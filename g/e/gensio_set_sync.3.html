gensio_set_sync(3) Manuel des fonctions de bibliothèque gensio_set_sync(3)

NOM

gensio_set_sync, gensio_clear_sync, gensio_read_s, gensio_write_s - Opérations d'E/S synchrones sur un gensio

SYNTAXE

#include <gensio/gensio.h>

int gensio_set_sync(struct gensio *io);
int gensio_clear_sync(struct gensio *io);
int gensio_read_s(struct gensio *io, gensiods *count,

void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_read_s_intr(struct gensio *io, gensiods *count,

void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_write_s(struct gensio *io, gensiods *count,

const void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_write_s_intr(struct gensio *io, gensiods *count,

const void *data, gensiods datalen,
struct gensio_time *timeout);

DESCRIPTION

Le fonctionnement normal de gensio est basé sur des rappels asynchrones. Cela convient à la plupart des programmes, surtout s'ils gèrent plusieurs connexions simultanément. Vous ne voudriez pas écrire un compilateur de cette manière, mais si vous développez quelque chose piloté par des événements externes, ce type de programmation événementielle fonctionne bien. Si vous y pensez, si vous utilisez des outils comme poll, select, etc., vous finissez presque toujours par avoir quelque chose comme :

poll(fds...)
if (fd1 read is set)
call fd1_read_handler()
if (fd1 write is set)
call fd1_write_handler()
if (fd2 read is set)
...

La gestion de gensio fait tout cela pour vous. Il suffit d'enregistrer un gestionnaire auprès du gensio pour recevoir les appels de lecture et d'écriture. C'est plus efficace, plus propre, et vous obtenez moins de code.

Mais il arrive occasionnellement que vous ayez besoin de faire quelque chose de synchrone avec l'exécution du programme. Par exemple, dans gtlsshd, si la vérification initiale du certificat et du mot de passe échoue, il utilise PAM pour gérer la lecture du mot de passe depuis le gensio distant. Cela nécessite des E/S synchrones, et il utilise cette capacité.

gensio_set_sync configure le gensio pour les E/S synchrones. Si vous faites cela, le rappel d'événement actuellement enregistré ne recevra plus les rappels de lecture et d'écriture. Il recevra d'autres rappels. Vous devez appeler cette fonction avant d'effectuer toute opération de lecture et d'écriture synchrone. Cette fonction sera bloquée (tout en gérant les événements gensio normaux) jusqu'à ce qu'aucun rappel ne soit actif.

gensio_clear_sync remet le gensio en mode E/S asynchrone. Le rappel sera restauré à celui qui était défini lorsque gensio_set_sync() a été appelé.

gensio_read_s attend des données du gensio, jusqu'à datalen octets. count (s'il n'est pas NULL) sera mis à jour avec le nombre d'octets effectivement lus. Cette fonction attendra n'importe quelle lecture et renverra ce que cette lecture a retourné, même si c'est moins que datalen. Elle attendra pendant la durée spécifiée dans timeout. timeout est mis à jour avec le temps restant à attendre. Si timeout est NULL, elle attendra indéfiniment.

gensio_write_s écrit des données dans le gensio. count (s'il n'est pas NULL) sera mis à jour avec le nombre d'octets effectivement écrits. Cette fonction attendra jusqu'à ce que le délai d'attente expire ou que toutes les données soient écrites. Elle attendra pendant la durée spécifiée dans timeout. timeout est mis à jour avec le temps restant à attendre. Si timeout est NULL, elle attendra indéfiniment.

gensio_read_s_intr et gensio_write_s_intr sont identiques à gensio_read_s et gensio_write_s, mais elles retournent immédiatement si une interruption de signal se produit. Sur les systèmes sans signaux, elles sont identiques à gensio_read_s et gensio_write_s.

VALEURS DE RETOUR

Zéro est retourné en cas de succès, ou une erreur gensio en cas d'échec.
