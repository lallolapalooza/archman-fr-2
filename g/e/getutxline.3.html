getutent(3) Manuel des fonctions de bibliothèque getutent(3)

NOM

getutent, getutid, getutline, pututline, setutent, endutent, utmpname - accéder aux entrées du fichier utmp

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPTION

Les nouvelles applications devraient utiliser les fonctions de la version "utmpx" spécifiée par POSIX.1 ; voir NORMES.

utmpname() définit le nom du fichier au format utmp auquel les autres fonctions utmp accéderont. Si utmpname() n'est pas utilisé pour définir le nom avant que les autres fonctions ne soient utilisées, elles supposent _PATH_UTMP, tel que défini dans <paths.h>.

setutent() rembobine le pointeur de fichier au début du fichier utmp. Il est généralement conseillé de l'appeler avant toute autre fonction.

endutent() ferme le fichier utmp. Il doit être appelé lorsque le code utilisateur a terminé d'accéder au fichier avec les autres fonctions.

getutent() lit une ligne depuis la position actuelle du fichier dans le fichier utmp. Il renvoie un pointeur vers une structure contenant les champs de la ligne. La définition de cette structure est montrée dans utmp(5).

getutid() recherche vers l'avant depuis la position actuelle du fichier dans le fichier utmp en se basant sur ut. Si ut->ut_type est l'un de RUN_LVL, BOOT_TIME, NEW_TIME, ou OLD_TIME, getutid() trouvera la première entrée dont le champ ut_type correspond à ut->ut_type. Si ut->ut_type est l'un de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, ou DEAD_PROCESS, getutid() trouvera la première entrée dont le champ ut_id correspond à ut->ut_id.

getutline() recherche vers l'avant depuis la position actuelle du fichier dans le fichier utmp. Il parcourt les entrées dont ut_type est USER_PROCESS ou LOGIN_PROCESS et renvoie la première dont le champ ut_line correspond à ut->ut_line.

pututline() écrit la structure utmp ut dans le fichier utmp. Il utilise getutid() pour rechercher l'emplacement correct dans le fichier pour insérer la nouvelle entrée. S'il ne trouve pas d'emplacement approprié pour ut, pututline() ajoutera la nouvelle entrée à la fin du fichier.

VALEUR DE RETOUR

getutent(), getutid(), et getutline() renvoient un pointeur vers une struct utmp en cas de succès, et NULL en cas d'échec (ce qui inclut le cas de "enregistrement introuvable"). Cette struct utmp est allouée dans un stockage statique et peut être écrasée par des appels ultérieurs.

En cas de succès, pututline() renvoie ut ; en cas d'échec, il renvoie NULL.

utmpname() renvoie 0 si le nouveau nom a été stocké avec succès, ou -1 en cas d'échec.

En cas d'échec, ces fonctions définissent errno pour indiquer l'erreur.

ERREURS

ENOMEM
Mémoire insuffisante.
ESRCH
Enregistrement introuvable.

setutent(), pututline(), et les fonctions getut*() peuvent également échouer pour les raisons décrites dans open(2).

FICHIERS

/var/run/utmp
base de données des utilisateurs actuellement connectés
/var/log/wtmp
base de données des connexions d'utilisateurs passées

Interface Attribut Valeur

Dans le tableau ci-dessus, utent dans race:utent signifie que si l'une des fonctions setutent(), getutent(), getutid(), getutline(), pututline(), utmpname(), ou endutent() est utilisée en parallèle dans différents threads d'un programme, des conflits de données (data races) peuvent survenir.

NORMES

Aucune.

HISTORIQUE

XPG2, SVr4.

Dans XPG2 et SVID 2, la fonction pututline() est documentée pour retourner void, et c'est ce qu'elle fait sur de nombreux systèmes (AIX, HP-UX). HP-UX introduit une nouvelle fonction _pututline() avec le prototype indiqué ci-dessus pour pututline().

Toutes ces fonctions sont désormais obsolètes sur les systèmes non Linux. POSIX.1-2001 et POSIX.1-2008, suivant SUSv1, n'ont aucune de ces fonctions, mais utilisent à la place

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Ces fonctions sont fournies par glibc, et effectuent la même tâche que leurs équivalents sans le "x", mais utilisent struct utmpx, définie sous Linux pour être identique à struct utmp. Par souci de complétude, glibc fournit également utmpxname(), bien que cette fonction ne soit pas spécifiée par POSIX.1.

Sur certains autres systèmes, la structure utmpx est un superset de la structure utmp, avec des champs supplémentaires, et des versions plus grandes des champs existants, et des fichiers parallèles sont maintenus, souvent /var/*/utmpx et /var/*/wtmpx.

Linux glibc, en revanche, n'utilise pas de fichier utmpx parallèle car sa structure utmp est déjà suffisamment grande. Les fonctions "x" listées ci-dessus ne sont que des alias pour leurs homologues sans "x" (par exemple, getutxent() est un alias pour getutent()).

NOTES

notes glibc

Les fonctions ci-dessus ne sont pas thread-safe. glibc ajoute des versions réentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Exigences de la macro de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getutent_r(), getutid_r(), getutline_r() :

    _GNU_SOURCE
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */    _SVID_SOURCE || _BSD_SOURCE

Ce sont des extensions GNU, analogues aux fonctions du même nom sans le suffixe _r. L'argument ubuf fournit à ces fonctions un endroit pour stocker leur résultat. En cas de succès, elles renvoient 0, et un pointeur vers le résultat est écrit dans *ubufp. En cas d'erreur, ces fonctions renvoient -1. Il n'existe pas d'équivalents utmpx des fonctions ci-dessus. (POSIX.1 ne spécifie pas de telles fonctions.)

EXEMPLES

L'exemple suivant ajoute et supprime un enregistrement utmp, en supposant qu'il est exécuté depuis un terminal pseudo. Pour une utilisation dans une application réelle, vous devriez vérifier les valeurs de retour de getpwuid(3) et ttyname

(3). 
#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
