DESCRIPTIO

N

Cette commande fusionne la liste des fichiers de l'index avec la liste réelle du répertoire de travail et affiche différentes combinaisons des

deux.

Plusieurs drapeaux peuvent être utilisés pour déterminer quels fichiers sont affichés, et ch

aque fichier peut être imprimé plusieurs fois s'il existe plusieurs entrées dans l'index ou
si plusieurs statuts sont applicables pour les options de sélection de fichiers concernées.

OPTION

S

-c,

--cached
Affiche tous les fichiers mis en cache dans l'index de Git, c'est-à-dire tous les fichiers suivis. (C'est le comportement par défaut si aucune option -c/-s/-d/-o/-u/-k/-m/--resolve-undo n'est spécifiée.
)

-d,

--deleted
Affiche les fichiers ayant une suppression non
indexée

-m,

--modified
Affiche les fichiers ayant une modification non indexée (notez qu'une suppression non indexée compte également comme une modification non
indexée)

-o,

--others
Affiche les autres fichiers (c'est-à-dire non suivis) dans la
sortie

-i,

--ignored
Affiche uniquement les fichiers ignorés dans la sortie. Doit être utilisé soit avec un -c explicite ou -o. Lors de l'affichage des fichiers de l'index (c'est-à-dire lorsqu'il est utilisé avec -c), n'imprime que les fichiers correspondant à un motif d'exclusion. Lors de l'affichage des fichiers « autres » (c'est-à-dire lorsqu'il est utilisé avec -o), n'affiche que ceux correspondant à un motif d'exclusion. Les règles d'ignorance standard ne sont pas activées automatiquement ; par conséquent, au moins une des options --exclude* est
requise.

-s,

--stage
Affiche les bits de mode, le nom d'objet et le numéro d'étape du contenu indexé dans la
sortie.

--director

y
Si un répertoire entier est classé comme « autre », affiche seulement son nom (avec un slash final) et non son contenu entier. N'a aucun effet sans
-o/--others.

--no-empty-director

y
Ne liste pas les répertoires vides. N'a aucun effet sans
--directory.

-u,

--unmerged
Affiche des informations sur les fichiers non fusionnés dans la sortie, mais n'affiche aucun autre fichier suivi (force --stage, remplace --cached)
.

-k,

--killed
Affiche les fichiers non suivis sur le système de fichiers qui doivent être supprimés en raison de conflits fichier/répertoire afin que les fichiers suivis puissent être écrits sur le système de
fichiers.

--resolve-und

o
Affiche les fichiers ayant des informations de resolve-undo dans l'index ainsi que leurs informations de resolve-undo. (Les informations de resolve-undo sont ce qui est utilisé pour implémenter « git checkout -m $PATH », c'est-à-dire pour recréer des conflits de fusion accidentellement
résolus)

-

z
Utilise \0 comme terminaison de ligne en sortie et ne met pas les noms de fichiers entre guillemets. Voir OUTPUT ci-dessous pour plus
d'informations.

--deduplicat

e
Lorsque seuls les noms de fichiers sont affichés, supprime les doublons pouvant provenir de la présence de plusieurs étapes lors d'une fusion, ou de l'utilisation simultanée des options --deleted et --modified. Lorsque l'une des options -t, --unmerged ou --stage est utilisée, cette option n'a aucun
effet.

-x <pattern>, --exclude=<pattern

>
Ignore les fichiers non suivis correspondant au motif. Notez que le motif est un motif générique de shell. Voir EXCLUDE PATTERNS ci-dessous pour plus
d'informations.

-X <file>, --exclude-from=<file

>
Lit les motifs d'exclusion depuis <file> ; 1 par
ligne.

--exclude-per-directory=<file

>
Lit des motifs d'exclusion supplémentaires qui ne s'appliquent qu'au répertoire et à ses sous-répertoires dans <file>. Si vous essayez d'émuler le fonctionnement des commandes Porcelain, l'utilisation de l'option --exclude-standard est plus simple et plus
complète.

--exclude-standar

d
Ajoute les exclusions standard de Git : .git/info/exclude, .gitignore dans chaque répertoire, et le fichier d'exclusion global de
l'utilisateur.

--error-unmatc

h
Si un <file> ne figure pas dans l'index, considère cela comme une erreur (retourne 1)
.

--with-tree=<tree-ish

>
Lors de l'utilisation de --error-unmatch pour développer les arguments <file> (c'est-à-dire motif de chemin) fournis par l'utilisateur en chemins, fait semblant que les chemins supprimés de l'index depuis le <tree-ish> nommé sont toujours présents. L'utilisation de cette option avec -s ou -u n'a aucun
sens.

-

t
Affiche les étiquettes de statut avec les noms de fichiers. Notez que pour des besoins de script, git-status(1) --porcelain et git-diff-files(1) --name-status sont presque toujours des alternatives supérieures ; les utilisateurs devraient consulter git-status(1) --short ou git-diff(1) --name-status pour des alternatives plus conviviales.

Cette option fournit une raison pour l'affichage de chaque nom de fichier, sous la forme d'une étiquette de statut (suivie d'un espace puis du nom de fichier). Les étiquettes de statut sont toutes des caractères uniques de la liste suivante

:

skip-worktree

indexée

C
fichier suivi avec modification/changement non

suivis

?

-

v
Similaire à -t, mais utilise des lettres minuscules pour les fichiers marqués comme assume unchanged (voir git-update-index(1))
.

-

f
Similaire à -t, mais utilise des lettres minuscules pour les fichiers marqués comme fsmonitor valid (voir git-update-index(1))
.

--full-nam

e
Lorsqu'il est exécuté depuis un sous-répertoire, la commande affiche généralement des chemins relatifs au répertoire courant. Cette option force l'affichage des chemins relatifs au répertoire racine du
projet.

--recurse-submodule

s
Appelle récursivement ls-files sur chaque sous-module actif du dépôt. Actuellement, seul le support des modes --cached et --stage est
disponible.

--abbrev[=<n>

]
Au lieu d'afficher les lignes d'objets hexadécimaux complets de 40 octets, affiche le préfixe le plus court d'au moins <n> chiffres hexadécimaux qui désigne l'objet de manière unique. Un nombre de chiffres non par défaut peut être spécifié avec --abbrev=<n>
.

--debu

g
Après chaque ligne décrivant un fichier, ajoute plus de données sur son entrée de cache. Cela vise à afficher autant d'informations que possible pour l'inspection manuelle ; le format exact peut changer à tout
moment.

--eo

l
Affiche <eolinfo> et <eolattr> des fichiers. <eolinfo> est l'identification du contenu du fichier utilisée par Git lorsque l'attribut « text » est « auto » (ou non défini et core.autocrlf n'est pas false). <eolinfo> est soit « -text », « none », « lf », « crlf », « mixed » ou « ».

« » signifie que le fichier n'est pas un fichier régulier, qu'il n'est pas dans l'index ou pas accessible dans l'arbre de

travail.

<eolattr> est l'attribut utilisé lors de l'extraction ou du commit, il est soit « », « -text », « text », « text=auto », « text eol=lf », « text eol=crlf ». Depuis Git 2.10, « text=auto eol=lf » et « text=auto eol=crlf » sont pris en charged

.

Le <eolinfo> dans l'index ("i/<eolinfo>") et dans l'arbre de travail ("w/<eolinfo>") sont affichés pour les fichiers réguliers, suivis du ("attr/<eolattr>

")
.

--spars

e
Si l'index est clairsemé, affiche les répertoires clairsemés sans les étendre vers les fichiers qu'ils contiennent. Les répertoires clairsemés seront affichés avec une barre oblique finale, comme "x/" pour un répertoire clairsemé
"x".

--format=<format

>
Une chaîne qui interpole %(nom-de-champ) depuis le résultat affiché. Elle interpole aussi %% en %, et %xXX où XX sont des chiffres hexadécimaux interpole vers le caractère dont le code hex est XX ; par exemple %x00 interpole vers \0 (NUL), %x09 vers \t (TAB) et %x0a vers \n (LF). --format ne peut pas être combiné avec -s, -o, -k, -t, --resolve-undo et --eol
.

SORTI

E

git ls-files ne produit que les noms de fichiers, sauf si --stage est spécifié, auquel cas il produit

: 
[<tag> ]<mode
> <object> <
stage> <file>

git ls-files --eol affichera i/<eolinfo><ESPACES>w/<eolinfo><ESPACES>attr/<eolattr><ESPACES*><TAB>

<file>

git ls-files --unmerged et git ls-files --stage peuvent être utilisés pour examiner des informations détaillées sur les chemins non

fusionnés.

Pour un chemin non fusionné, au lieu d'enregistrer une seule paire mode/SHA-1, l'index enregistre jusqu'à trois de ces paires ; une de l'arbre O à l'étape 1, A à l'étape 2, et B à l'étape 3. Ces informations peuvent être utilisées par l'utilisateur (ou le porcelain) pour voir ce qui devrait finalement être enregistré au chemin. (voir git-read-tree(1) pour plus d'informations sur

l'état)

Sans l'option -z, les chemins avec des caractères "inhabituels" sont mis entre guillemets comme expliqué pour la variable de configuration core.quotePath (voir git-config(1)). En utilisant -z, le nom de fichier est produit tel quel et la ligne est terminée par un octet

NUL.

Il est possible d'imprimer dans un format personnalisé en utilisant l'option --format, qui est capable d'interpoler différents champs en utilisant la notation %(nom-de-champ). Par exemple, si vous ne vous souciez que des champs "objectname" et "path", vous pouvez exécuter avec un "--format" spécifique

comme 
git ls-file
s --format=
'%(objectnam
e) %(path)'

MOTIFS

D'EXCLUSION

git ls-files peut utiliser une liste de "motifs d'exclusion" lors de la traversée de l'arborescence de répertoires et de la recherche de fichiers à afficher lorsque les drapeaux --others ou --ignored sont spécifiés. gitignore(5) spécifie le format des motifs

d'exclusion.

Ces motifs d'exclusion peuvent être spécifiés depuis les endroits suivants, dans l'ordre

:
1.Le drapeau de ligne de commande --exclude=<motif> spécifie un motif unique. Les motifs sont ordonnés dans le même ordre qu'ils apparaissent dans la ligne de
commande.
2.Le drapeau de ligne de commande --exclude-from=<fichier> spécifie un fichier contenant une liste de motifs. Les motifs sont ordonnés dans le même ordre qu'ils apparaissent dans le
fichier.
3.Le drapeau de ligne de commande --exclude-per-directory=<nom> spécifie un nom de fichier dans chaque répertoire que git ls-files examine, normalement .gitignore. Les fichiers dans les répertoires plus profonds ont la priorité. Les motifs sont ordonnés dans le même ordre qu'ils apparaissent dans les
fichiers.

Un motif spécifié sur la ligne de commande avec --exclude ou lu depuis le fichier spécifié avec --exclude-from est relatif au sommet de l'arborescence de répertoires. Un motif lu depuis un fichier spécifié par --exclude-per-directory est relatif au répertoire dans lequel le fichier de motifs

apparaît.

Généralement, vous devriez pouvoir utiliser --exclude-standard lorsque vous voulez que les règles d'exclusion soient appliquées de la même manière que ce que font les commandes Porcelain. Pour émuler ce que --exclude-standard spécifie, vous pouvez donner --exclude-per-directory=.gitignore, et puis spécifier

:
1.Le fichier spécifié par la variable de configuration core.excludesfile, si elle existe, ou le fichier $XDG_CONFIG_HOME/git/ignore
.
2.Le fichier $GIT_DIR/info/exclude
.

via l'option --exclud
