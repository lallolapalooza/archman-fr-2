git-archive - Créer une

archive de fichiers à

              [-o <file> | --output=<file>] [--worktree-attributes]
              [--remote=<repo> [--exec=<git-upload-archive>]] <tree-ish>
              [<path>..
.

DESCRIPTIO

N

Crée une archive au format spécifié contenant la structure d'arborescence de l'arbre nommé, et l'écrit sur la sortie standard. Si <prefix> est spécifié, il est ajouté devant les noms de fichiers dans

l'archive.

git archive se comporte différemment lorsqu'on lui donne un identifiant d'arbre par rapport à un identifiant de commit ou de tag. Quand un identifiant d'arbre est fourni, l'heure actuelle est utilisée comme heure de modification de chaque fichier dans l'archive. D'autre part, quand un identifiant de commit ou de tag est fourni, l'heure du commit telle qu'enregistrée dans l'objet commit référencé est utilisée à la place. De plus, l'identifiant de commit est stocké dans un en-tête pax étendu global si le format tar est utilisé ; il peut être extrait avec git get-tar-commit-id. Dans les fichiers ZIP

, il est stocké comme c
ommentaire de fichier.

OPTION

S

--format=<fmt

>
Format de l'archive résultante. Les valeurs possibles sont tar, zip, tar.gz, tgz, et tout format défini à l'aide de l'option de configuration tar.<format>.Si --format n'est pas donné, et que le fichier de sortie est spécifié, le format est déduit du nom de fichier si possible (par exemple, écrire dans foo.zip fait que la sortie sera au format zip). Sinon, le format de sortie est tar
.

-l,

--list
Afficher tous les formats
disponibles.

-v,

--verbose
Signaler la progression sur
stderr.

--prefix=<prefix>

/
Ajouter <prefix>/ devant les chemins dans l'archive. Peut être répété ; sa valeur la plus à droite est utilisée pour tous les fichiers suivis. Voir ci-dessous quelle valeur est utilisée par --add-file
.

-o <file>,

--output=<file>
Écrire l'archive dans <file> au lieu de
stdout.

--add-file=<file

>
Ajouter un fichier non suivi à l'archive. Peut être répété pour ajouter plusieurs fichiers. Le chemin du fichier dans l'archive est construit en concaténant la valeur de la dernière option --prefix (le cas échéant) avant ce --add-file et le nom de base de <file>
.

--add-virtual-file=<path>:

<content>
Ajouter le contenu spécifié à l'archive. Peut être répété pour ajouter plusieurs fichiers.

L'argument <path> peut commencer et se terminer par un caractère double-quote littéral ; le nom de fichier qu'il contient est interprété comme une chaîne de caractères de style C, c'est-à-dire que la barre oblique inverse est interprétée comme caractère d'échappement. Le chemin doit être entre guillemets s'il contient un deux-points, pour éviter que le deux-points soit mal interprété comme séparateur entre le chemin et le contenu, ou si le chemin commence ou se termine par un caractère

double-quote.

Le mode du fichier est limité à un fichier régulier, et l'option peut être soumise à des limites de ligne de commande dépendantes de la plateforme. Pour les cas non triviaux, écrivez un fichier non suivi et utilisez --add-file à la

place.

Notez que contrairement à --add-file, le chemin créé dans l'archive n'est pas affecté par l' option --prefix, car un <path> complet peut être d

onné comme vale
ur de l'option.

--worktree-attribute

s
Chercher également les attributs dans les fichiers .gitattributes dans l'arbre de travail (voir la section intitulée « ATTRIBUTS »)
.

--mtime=<time

>
Définir l'heure de modification des entrées de l'archive. Sans cette option, l'heure du commit est utilisée si <tree-ish> est un commit ou un tag, et l'heure actuelle si c'est un
arbre.

<extra

>
Il peut s'agir de n'importe quelles options comprises par le backend d'archivage. Voir la section
suivante.

--remote=<repo

>
Au lieu de créer une archive tar à partir du dépôt local, récupérer une archive tar depuis un dépôt distant. Notez que le dépôt distant peut imposer des restrictions sur les expressions sha1 qui peuvent être autorisées dans <tree-ish>. Voir git-upload-archive(1) pour les
détails.

--exec=<git-upload-archive

>
Utilisé avec --remote pour spécifier le chemin vers le git-upload-archive côté
distant.

<tree-ish

>
L'arbre ou le commit pour lequel produire une
archive.

<path

>
Sans paramètre de chemin optionnel, tous les fichiers et sous-réper
toires du répertoire de travail actuel sont inclus dans l'archive.
Si un ou plusieurs chemins sont spécifiés, seuls ceux-ci sont inclus.

CONFIGURATIO

N

tar.

umask
Cette variable peut être utilisée pour restreindre les bits de permission des entrées de l'archive tar. La valeur par défaut est 0002, ce qui désactive le bit d'écriture pour tous. La valeur spéciale « user » indique que l'umask de l'utilisateur qui crée l'archive sera utilisée à la place. Voir umask(2) pour les détails. Si --remote est utilisé, seule la configuration du dépôt distant prend
effet.

tar.<format>.

command
Cette variable spécifie une commande shell à travers laquelle la sortie tar générée par git archive devrait être acheminée. La commande est exécutée avec le shell, le fichier tar généré sur son entrée standard, et devrait produire la sortie finale sur sa sortie standard. Toutes les options de niveau de compression seront passées à la commande (par exemple, -9).

Les formats tar.gz et tgz sont définis automatiquement et utilisent la commande magique git archive gzip par défaut, qui invoque u

ne implémentation
interne de gzip.

tar.<format>.

remote
Si vrai, active le format pour une utilisation par les clients distants via git-upload-archive(1). La valeur par défaut est faux pour les formats définis par l'utilisateur, mais vrai pour les formats tar.gz et tg
z
.

ATTRIBUT

S

export-ignor

e
Les fichiers et répertoires avec l'attribut export-ignore ne seront pas ajoutés aux fichiers d'archive. Voir gitattributes(5) pour les
détails.

export-subs

t
Si l'attribut export-subst est défini pour un fichier, Git développera plusieurs emplacements réservés lors de l'ajout de ce fichier à une archive. Voir gitattributes(5) pour les
détails.

Notez que les attributs sont par défaut pris depuis les fichiers .gitattributes de l'arbre qui est archivé. Si vous voulez ajuster la manière dont la sortie est générée après coup (par exemple, vous avez commité sans ajouter un export-ignore approprié dans son .gitattributes), ajustez le fichier .gitattributes extrait selon vos besoins et utilisez l'option --worktree-attributes. Alternativement, vous pouvez conserver les attributs nécessaires qui devraient s'appliquer lors de l'archivage de n'importe quel arbre dans votre fichier $GIT_DIR/info/attribute

s
.
