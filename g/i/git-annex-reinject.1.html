NOM

git-annex-reinject - réinjecter le contenu d'un fichier dans l'annexe

SYNTAXE

git annex reinject [src dest]

git annex reinject --known [src]

DESCRIPTION

Déplace le contenu du ou des fichiers source dans l'annexe. Seuls les contenus de fichiers connus seront réinjectés. Les fichiers sources inconnus ne seront pas modifiés.

Ceci peut être utile si vous avez obtenu le contenu d'un fichier d'ailleurs et que vous souhaitez le placer dans l'annexe locale. Par exemple, si le contenu d'un fichier a été perdu et que vous avez une sauvegarde, vous pouvez restaurer la sauvegarde et la réinjecter dans votre dépôt local.

Il existe deux façons d'utiliser cette commande. Spécifier un fichier source et le nom d'un fichier de destination (situé à l'intérieur de l'arbre de travail du dépôt) injecte le fichier source comme contenu du fichier de destination.


git annex reinject /tmp/foo.iso foo.iso

Ou l'option --known peut être utilisée pour réinjecter tous les fichiers sources connus, sans avoir besoin de spécifier le fichier de destination.


git annex reinject --known /tmp/*.iso

OPTIONS

--known
Avec cette option, chaque fichier source spécifié est haché en utilisant le backend clé-valeur par défaut (ou celui spécifié avec --backend), et si git-annex a un enregistrement qu'une clé résultante a déjà été dans l'annexe, le contenu est réinjecté.
Notez que, lors de l'utilisation d'un backend clé-valeur qui inclut l'extension du nom de fichier dans la clé, cela ne fonctionnera que si les fichiers sources ont les mêmes extensions que les fichiers avec le même contenu qui ont été initialement ajoutés à git-annex.
Notez que cela réinjectera les anciennes versions de fichiers qui ont été modifiées ou supprimées de la branche git actuelle. Utilisez git-annex-unused(1) pour détecter quand de tels fichiers anciens et potentiellement inutilisés ont été réinjectés.
--backend
Spécifiez le backend clé-valeur à utiliser lors de la vérification si un fichier est connu avec l'option --known.
--guesskeys
Avec cette option, chaque fichier source spécifié est vérifié pour voir s'il a le nom d'une clé git-annex, et si c'est le cas, il est importé comme le contenu de cette clé.
Ceci peut être utilisé pour extraire des objets git-annex de lost+found, tant que le nom de fichier original n'a pas été perdu, et est particulièrement utile lorsque l'on utilise des backends clé-valeur qui ne hachent pas le contenu d'un fichier.
Lorsque le backend clé-valeur prend en charge le hachage, le contenu du fichier est vérifié avant son importation.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement écrits sur la sortie d'erreur standard sont inclus dans le JSON à la place.
Les options communes de git-annex (git-annex-common-options(1)) peuvent également être utilisées.
