NOM

git-symbolic-ref - Lire, modifier et supprimer des références symboliques

SYNTAXE

git symbolic-ref [-m <raison>] <nom> <réf>
git symbolic-ref [-q] [--short] [--no-recurse] <nom>
git symbolic-ref --delete [-q] <nom>

DESCRIPTION

Avec un seul argument, lit la tête de branche à laquelle la référence symbolique donnée fait référence et affiche son chemin, relatif au répertoire .git/. Typiquement, vous donneriez HEAD comme argument <nom> pour voir à quelle branche votre arborescence de travail est attachée.

Avec deux arguments, crée ou met à jour une référence symbolique <nom> pour qu'elle pointe vers la branche <réf> donnée.

Avec --delete et un argument supplémentaire, supprime la référence symbolique donnée.

Une référence symbolique est un fichier régulier qui stocke une chaîne commençant par ref: refs/. Par exemple, votre fichier .git/HEAD est un fichier régulier dont le contenu est ref: refs/heads/master.

OPTIONS

-d, --delete

Supprime la référence symbolique <nom>.

-q, --quiet

Ne pas émettre de message d'erreur si <nom> n'est pas une référence symbolique mais un HEAD détaché ; quitter avec un statut non nul silencieusement.

--short

Lors de l'affichage de la valeur de <nom> en tant que référence symbolique, tente de raccourcir la valeur, par exemple de refs/heads/master à master.

--recurse, --no-recurse

Lors de l'affichage de la valeur de <nom> en tant que référence symbolique, si <nom> fait référence à une autre référence symbolique, suit cette chaîne de références symboliques jusqu'à ce que le résultat ne pointe plus vers une référence symbolique (--recurse, qui est le comportement par défaut). --no-recurse s'arrête après avoir déréférencé un seul niveau de référence symbolique.

-m

Met à jour le reflog pour <nom> avec <raison>. Ceci n'est valide que lors de la création ou de la mise à jour d'une référence symbolique.

NOTES

Dans le passé, .git/HEAD était un lien symbolique pointant vers refs/heads/master. Lorsque nous voulions basculer vers une autre branche, nous faisions ln -sf refs/heads/nouvelle_branche .git/HEAD, et lorsque nous voulions savoir sur quelle branche nous étions, nous faisions readlink .git/HEAD. Mais les liens symboliques ne sont pas entièrement portables, ils sont donc désormais dépréciés et les références symboliques (comme décrit ci-dessus) sont utilisées par défaut.

git symbolic-ref quittera avec le statut 0 si le contenu de la référence symbolique a été imprimé correctement, avec le statut 1 si le nom demandé n'est pas une référence symbolique, ou 128 si une autre erreur se produit.
