NOM

git-annex-migrate - basculer les données vers un backend différent

SYNTAXE

git annex migrate [chemin ...]

git annex migrate --update

DESCRIPTION

Modifie les fichiers annexés spécifiés pour utiliser le backend clé-valeur par défaut (ou celui spécifié avec --backend). Seuls les fichiers dont le contenu est actuellement présent sont migrés.

Notez que le contenu est également toujours stocké en utilisant les anciennes clés après la migration. Lorsque c'est possible, des liens physiques sont utilisés pour éviter de prendre de l'espace disque supplémentaire. Utilisez git annex unused pour trouver et supprimer les anciennes clés.

Normalement, rien ne sera fait aux fichiers spécifiés qui utilisent déjà le nouveau backend. Cependant, si un backend modifie les informations qu'il utilise pour construire une clé, ceci peut également être utilisé pour migrer les fichiers afin qu'ils utilisent le nouveau format de clé.

OPTIONS

--update
Ceci met à jour le dépôt local pour les migrations qui ont été effectuées ailleurs. Seules les nouvelles migrations depuis la dernière fois que ceci a été exécuté seront effectuées.
Ceci ne modifie pas l'arbre de travail, mais seulement les liens physiques (ou dans certains cas les copies) des objets annexés vers leurs nouvelles clés.
git-annex pull et git-annex sync --content font automatiquement cela, à moins que la configuration annex.syncmigrations ne soit définie à false.
Notez que les versions plus anciennes de git-annex n'enregistraient pas les migrations d'une manière que ceci peut utiliser. Les migrations effectuées avec ces versions plus anciennes devaient être exécutées manuellement dans chaque clone du dépôt.
--apply
Ceci applique toutes les migrations enregistrées au dépôt local. C'est la forme non incrémentale de --update.
Une situation où ceci peut être utile est lorsque git-annex migrate --update a été exécuté, mais depuis lors, des objets non migrés sont entrés dans le dépôt. L'utilisation de cette option garantit que de tels objets sont migrés.
Notez que les versions plus anciennes de git-annex n'enregistraient pas les migrations d'une manière que ceci peut utiliser. Les migrations effectuées avec ces versions plus anciennes devaient être exécutées manuellement dans chaque clone du dépôt.
--backend
Spécifie le nouveau backend clé-valeur à utiliser pour les données migrées.
--force
Force la migration des clés qui utilisent déjà le nouveau backend.
options de correspondance de fichiers
Les git-annex-matching-options(1) peuvent être utilisées pour spécifier les fichiers à migrer.
Les git-annex-common-options(1) peuvent également être utilisés.
--remove-size
Les clés incluent souvent la taille de leur contenu, ce qui est généralement une chose utile. En fait, cette commande ajoute par défaut les informations de taille manquantes aux clés dans la plupart des migrations. Avec cette option, les informations de taille sont supprimées à la place.
Une utilisation de cette option est de convertir les clés URL qui ont été ajoutées par git-annex addurl --fast en celles qui auraient été ajoutées si cette commande avait été exécutée avec l'option --relaxed. Par exemple :

git-annex migrate --remove-size --backend=URL certainfichier
Pour ajouter à nouveau la taille à une clé URL, utilisez ceci :
git-annex migrate --backend=URL certainfichier
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard d'erreur sont inclus dans le JSON à la place.
