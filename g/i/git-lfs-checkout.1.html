NOM

git-lfs-checkout - Met à jour la copie de travail avec le contenu des fichiers si disponible

SYNOPSIS

git lfs checkout [<motif-glob>...]
git lfs checkout --to <fichier> {--base|--ours|--theirs} <chemin-objet-conflit>

DESCRIPTION

Essaye de s'assurer que la copie de travail contient le contenu des fichiers pour les objets Git LFS du ref courant, si les données de l'objet sont disponibles. Ne télécharge aucun contenu ; voir git-lfs-fetch(1) pour cela.

Checkout scanne le ref courant pour tous les objets LFS qui seraient nécessaires, puis lorsque un fichier est soit manquant dans la copie de travail, soit contient du contenu de pointeur placeholder avec le même SHA, le vrai contenu du fichier est écrit, à condition que nous l'ayons dans le stock local. Les fichiers modifiés ne sont jamais écrasés.

Un ou plusieurs s peuvent être fournis comme arguments pour restreindre l'ensemble des fichiers qui sont mis à jour. Les motifs glob sont comparés conformément au format décrit dans gitignore(5).

Lorsqu'utilisé avec --to et que l'arbre de travail est dans un état de conflit suite à une fusion, cette option extrait l'une des trois étapes d'un objet Git LFS conflictuel dans un fichier séparé (qui peut être en dehors de l'arbre de travail). Cela peut faciliter l'utilisation d'outils de diff pour inspecter et résoudre les fusions. Le chemin d'un fichier d'objet Git LFS unique doit être fourni dans <chemin-objet-conflit>. Si <fichier> existe déjà, qu'il s'agisse d'un fichier régulier, d'un lien symbolique ou d'un répertoire, il sera supprimé et remplacé, sauf s'il s'agit d'un répertoire non vide ou s'il ne peut être supprimé pour une autre raison.

Si la version de Git installée est au moins 2.42.0, cette commande extraira par défaut les objets Git LFS pour les fichiers uniquement s'ils sont présents dans l'index Git et s'ils correspondent à un attribut de filtre Git LFS d'un fichier .gitattributes présent dans l'index ou l'arbre de travail courant (ou, comme c'est toujours le cas, s'ils correspondent à un attribut de filtre Git LFS dans un fichier gitattributes local tel que $GIT_DIR/info/attributes). Ces contraintes ne s'appliquent pas avec les versions antérieures de Git.

Dans un dépôt avec un clonage partiel ou un checkout épars, il est donc conseillé d'extraire tous les fichiers .gitattributes depuis HEAD avant d'utiliser cette commande, si Git v2.42.0 ou ultérieur est installé. Alternativement, la variable d'environnement GIT_ATTR_SOURCE peut être définie à HEAD, ce qui amènera Git à ne lire les attributs que depuis les fichiers .gitattributes dans HEAD et à ignorer ceux de l'index ou de l'arbre de travail.

Dans un dépôt nu, cette commande n'a aucun effet. Dans une version future, cette commande peut se terminer avec une erreur si elle est exécutée dans un dépôt nu.

OPTIONS

--base

Extrait la base de fusion du fichier spécifié.

--ours

Extrait notre côté (celui de la branche courante) du conflit pour le fichier spécifié.

--theirs


Extrait leur côté (celui de l'autre branche) du conflit pour le fichier spécifié.

--to <chemin>

Si l'arbre de travail est dans un état de conflit, extrait la partie du conflit spécifiée par --base, --ours, ou --theirs vers le chemin donné.

EXEMPLES

• Extraire tous les fichiers manquants ou placeholders :
$ git lfs checkout
• Extraire un couple de fichiers spécifiques :
$ git lfs checkout chemin/vers/fichier1.png chemin/vers.fichier2.png
• Extraire un chemin avec un conflit de fusion dans des fichiers séparés :
# Tenter une fusion avec une branche qui a un conflit de fusion
$ git merge branche-conflictuelle
CONFLICT (content): Merge conflict in chemin/vers/fichier/conflictuelles/file.dat
# Extraire les versions du fichier conflictuel dans des fichiers temporaires
$ git lfs checkout --to ours.dat --ours chemin/vers/fichier/conflictuelles/file.dat
$ git lfs checkout --to theirs.dat --theirs chemin/vers/fichier/conflictuelles/file.dat
# Comparer les versions conflictuelles dans ours.dat et theirs.dat,
# puis résoudre le conflit (par exemple, en choisissant une version plutôt
# qu'une autre, ou en créant une nouvelle version)
# Nettoyer et continuer la fusion
$ rm ours.dat theirs.dat
$ git add chemin/vers/fichier/conflictuelles/file.dat
$ git merge --continue
