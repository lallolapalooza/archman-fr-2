DESCRIPTIO

N

git-annex-shell est un shell restreint, similaire à git-shell, qui peut être utilisé comme shell de connexion pour les comptes

SSH.

Étant donné que sa syntaxe est identique à celle de git-shell, il peut être

utilisé comme substitut direct partout où git-shell est utilisé. Par exempl
e, il peut être utilisé comme shell de connexion restreint d'un utilisateur.

COMMANDE

S

Toute commande non listée ci-dessous est transmise à

git-shell.

Notez que le paramètre répertoire doit être un chemin absolu, sinon il est supposé être relatif au répertoire personnel de l'utilisateur. De plus, le premier "/~/" ou "/~user/" est développé vers le répertoire personnel

spécifié.

répertoire
Cela affiche un sous-ensemble de la configuration git, sous la même forme que git config --list. Cela est utilisé pour obtenir l'annex.uuid du dépôt
distant.
Lorsqu'il est exécuté dans un dépôt qui n'a pas encore d'annex.uuid, celui-ci sera créé, à condition qu'une branche git-annex ait déjà été poussée vers le dépôt, ou si l'indicateur autoinit=1 est utilisé pour indiquer que l'initialisation est
souhaitée.

EXEMPLE

S

Pour créer un fichier ~/.ssh/authorized_keys qui n'autorise que l'exécution de git-annex-shell, et pas d'autres commandes, passez la commande originale à l'option -c

:


command="git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",no-agent-forwarding,no-port-forwarding,no-X11-forwarding ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Pour restreindre davantage git-annex-shell à un dépôt particulier, et le verrouiller complètement en mode lecture seule

:


command="GIT_ANNEX_SHELL_DIRECTORY=/srv/annex GIT_ANNEX_SHELL_LIMITED=true GIT_ANNEX_SHELL_READONLY=true git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",restrict ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Évidemment, ssh-rsa AAAAB3NzaC1y[...] user@example.com doit être remplacé par votre clé SSH. Ce qui précède suppose aussi git-annex-shell est disponible dans votre $PATH, utilisez un chemin absolu si ce n'est pas le cas. Notez aussi comment ce qui précède utilise l'option restrict au lieu d'une liste explicite de fonctionnalités à interdire. Cela ne fonctionne que dans certaines versions d'OpenSSH, à partir de 7.

1p2.

Pour n'autoriser que l'ajout de nouveaux objets au dépôt, la variable GIT_ANNEX_SHELL_APPENDONLY peut aussi être utilisée

:

command="GIT_ANNEX_SHELL_DIRECTORY=/srv/annex GIT_ANNEX_SHELL_APPENDONLY=true git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",restrict ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Cela n'empêchera pas un attaquant de détruire l'historique git, comme expliqué ci-dessus. Pour cela, vous pourriez vouloir interdire certaines opérations, comme la suppression de branche et le push forcé, avec des options de git-config(1). Par exemple

:

git config receive.denyDeletes true git config receive.denyNonFastForwards

true

Avec cette configuration, les commits git peuvent toujours supprimer des fichiers, mais ils seront toujours disponibles dans l'historique git et git-annex conservera leur contenu. Les modifications de la branche git-annex, cependant, peuvent nuire aux informations de suivi de localisation de git-annex et pourraient causer une perte de données. Pour contourner ce problème, des hooks plus complexes sont nécessaires, voir par exemple le hook update-paranoid dans la di

stribution s
ource de git.
