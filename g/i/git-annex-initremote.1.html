SYNOPSI

S

git annex initremote nom type=valeur [param=valeur ..

.
]

DESCRIPTIO

N

Crée un nouveau distant spécial et l'ajoute à .git/con

fig.

Exemple de distant Amazon S3

:


git annex initremote mys3 type=S3 encryption=hybrid keyid=me@example.com

datacenter=EU

git-annex prend en charge de nombreux types de distants spéciaux. Pour une liste et plus de détails, voir https://git-annex.branchable.com/special_remotes

/

La configuration du distant est spécifiée par les paramètres passés à cette commande. Les différents types de distants spéciaux nécessitent des valeurs de configuration différentes ; consultez donc la documentation d'un distant spécial pour plus de détails. La commande vous demandera les paramètres requis que vous avez omis ; vous pouvez également passer --whatelse pour voir les paramètres supplémentaires

.

Quelques paramètres pris en charge par tous les distants spéciaux sont documentés dans la section suivante

ci-dessous.

Une fois qu'un distant spécial a été initialisé avec cette commande, d'autres clones du dépôt peuvent également être configurés pour y accéder en utilisant git annex enab

leremote.

Le nom que vous fournissez pour le distant ne peut pas être un nom déjà utilisé pour un autre distant spécial, car git-annex enableremote utilise le nom pour identifier quel distant spécial activer. Si un ancien distant spécial qui n'est plus utilisé a pris le nom que vous souhaitez réutiliser, vous pouvez utiliser git annex re

namer
emote.

OPTION

S
--with-u
rl
Cela configure le distant avec une url « annex:: », ce qui permet à git de pousser et tirer depuis lui, en utilisant
git-remote-annex.
--whatelse / -
w
Décrit les paramètres de configuration supplémentaires que vous pourriez
spécifier.
Par exemple, si vous savez que vous voulez un distant S3, mais que vous avez oublié comment le configurer
:

git annex initremote mys3 type=S3
--whatelse
Pour obtenir une liste des paramètres lisible par une machine, utilisez ceci avec --jso
n.
--fa
st
Lors de l'initialisation d'un distant utilisant le chiffrement, une clé cryptographique est créée. Cela nécessite une entropie suffisante. Si initremote semble se bloquer ou prendre beaucoup de temps lors de la génération de la clé, vous pouvez interrompre avec Ctrl-c et relancer avec --fast, ce qui lui fait utiliser une source de hasard de qualité inférieure. (C'est-à-dire /dev/urandom au lieu de
/dev/random)
--sameas=dist
ant
Utilisez ceci lorsque le nouveau distant spécial utilise le même stockage sous-jacent que un autre distant. Le nouveau distant spécial aura alors le même uuid que le distant spécifié, et l'un ou l'autre peut être utilisé pour accéder au même
contenu.
Le distant peut être le nom d'un distant git, ou la description ou l'uuid de n'importe quel dépôt
git-annex.
Lorsque vous utilisez cette option, le nouveau distant hérite des paramètres de chiffrement du distant existant ; vous ne devez donc spécifier aucun paramètre de chiffrement. Aucune autre configuration n'est héritée du distant
existant.
Cela ne fonctionnera que si les deux distants utilisent le stockage sous-jacent de manière compatible. Voir cette page pour des informations sur les compatibilités connues. http://git-annex.branchable.com/tips/multiple_remotes_accessing_the_same_data_sto
re/
--priva
te
Évite d'enregistrer des informations sur le distant spécial dans la branche git-annex. Le distant spécial ne sera utilisable que depuis le dépôt où il a été
créé.
--js
on
Active la sortie JSON. Celle-ci est destinée à être analysée par des programmes utilisant
git-annex.
--json-error-messa
ges
Les messages qui seraient normalement envoyés sur la sortie d'erreur standard sont inclus dans le JSON à la
place.
Aussi, les git-annex-common-options(1) peuvent être
utilisés.

PARAMÈTRES DE CONFIGURATION

COMMUNS
encrypti
on
Presque tous les distants spéciaux prennent en charge le chiffrement. Vous devrez spécifier quel chiffrement, le cas échéant,
utiliser.
Si vous ne voulez aucun chiffrement, utilisez encryption=n
one
Pour chiffrer vers une clé GPG, utilisez encryption=hybrid keyid=$keyid ... et remplissez l'id de clé GPG (ou une adresse e-mail associée à une clé
GPG).
Pour plus de détails à ce sujet et sur les autres paramètres de chiffrement, voir https://git-annex.branchable.com/encryption/ ou
--whatelse
autoenab
le
Pour éviter que git annex enableremote doive être exécuté, vous pouvez passer « autoenable=true ». Ensuite, lorsque git-annex est exécuté dans un nouveau clone, il essaiera d'activer le distant spécial. Bien sûr, cela fonctionne mieux lorsque le distant spécial n'a besoin de rien de spécial pour être
activé.
co
st
Spécifiez ceci pour remplacer le coût par défaut du distant spécial. Cette configuration peut être remplacée par la configuration git locale, par ex. remote.name.
annex-cost.
uu
id
Normalement, git-annex initremote génère un nouvel UUID pour le nouveau distant
spécial. Si vous le souhaitez, vous pouvez spécifier un UUID pour lui, en
passant un paramètre uuid=quoi-que-ce-soit. Cela peut être utile dans cer
taines situations inhabituelles. Mais en cas de doute, ne faites pas cela.
