NOM

git-remote-ext - Pont entre un transport intelligent et une commande externe.

SYNOPSIS

git remote add <nick> "ext::<commande>[ <arguments>...]"

DESCRIPTION

Ce gestionnaire de télécommande utilise la <commande> spécifiée pour se connecter à un serveur Git distant.

Les données écrites sur l'entrée standard de la <commande> spécifiée sont supposées être envoyées à un serveur git://, git-upload-pack, git-receive-pack ou git-upload-archive (selon la situation), et les données lues depuis la sortie standard de <commande> sont supposées provenir du même service.

La commande et ses arguments sont séparés par un espace non échappé.

Les séquences suivantes ont une signification spéciale :

'% '

Espace littéral dans la commande ou l'argument.

%%

Signe pour cent littéral.

%s

Remplacé par le nom (receive-pack, upload-pack, ou upload-archive) du service que Git souhaite invoquer.

%S

Remplacé par le nom long (git-receive-pack, git-upload-pack, ou git-upload-archive) du service que Git souhaite invoquer.

%G (doit être les premiers caractères d'un argument)

Cet argument ne sera pas passé à <commande>. Au lieu de cela, il amènera le gestionnaire à commencer par envoyer des requêtes de service git:// au côté distant avec le champ de service défini sur une valeur appropriée et le champ dépôt défini sur le reste de l'argument. La valeur par défaut est de ne pas envoyer une telle requête.

Ceci est utile si le côté distant est un serveur git:// accédé via un tunnel.

%V (doit être les premiers caractères d'un argument)

Cet argument ne sera pas passé à <commande>. Au lieu de cela, il définit le champ vhost dans la requête de service git:// (vers le reste de l'argument). La valeur par défaut est de ne pas envoyer de vhost dans une telle requête (si elle est envoyée).

VARIABLES D'ENVIRONNEMENT

GIT_TRANSLOOP_DEBUG

Si définie, imprime des informations de débogage sur diverses lectures/écritures.

VARIABLES D'ENVIRONNEMENT TRANSMISES À LA COMMANDE

GIT_EXT_SERVICE

Défini sur le nom long (git-upload-pack, etc.) du service que le gestionnaire doit invoquer.

GIT_EXT_SERVICE_NOPREFIX

Défini sur le nom long (upload-pack, etc.) du service que le gestionnaire doit invoquer.

EXEMPLES

Ce gestionnaire de télécommande est utilisé de manière transparente par Git lorsque vous utilisez des commandes telles que « git fetch <URL> », « git clone <URL> », « git push <URL> » ou « git remote add <nick> <URL> », où <URL> commence par ext::. Exemples :

"ext::ssh -i /home/foo/.ssh/somekey user@host.example %S foo/repo"

Similaire à host.example:foo/repo, mais utilise /home/foo/.ssh/somekey comme paire de clés et user comme utilisateur côté distant. Cela évite d'avoir à éditer .ssh/config.

"ext::socat -t3600 - ABSTRACT-CONNECT:/git-server %G/somerepo"

Représente un dépôt avec le chemin /somerepo accessible via le protocole git à l'adresse du namespace abstrait /git-server.

"ext::git-server-alias foo %G/repo"

Représente un dépôt avec le chemin /repo accédé à l'aide du programme gestionnaire « git-server-alias foo ». Le chemin vers le dépôt et le type de requête ne sont pas passés sur la ligne de commande mais font partie du flux de protocole, comme d'habitude avec le protocole git://.

"ext::git-server-alias foo %G/repo %Vfoo"

Représente un dépôt avec le chemin /repo accédé à l'aide du programme gestionnaire « git-server-alias foo ». Le nom d'hôte du serveur distant passé dans le flux de protocole sera « foo » (cela permet à plusieurs serveurs Git virtuels de partager une adresse au niveau de la liaison).

"ext::git-server-alias foo %G/repo% avec% des% espaces %Vfoo"

Représente un dépôt avec le chemin /repo avec des espaces accédé à l'aide du programme gestionnaire « git-server-alias foo ». Le nom d'hôte du serveur distant passé dans le flux de protocole sera « foo » (cela permet à plusieurs serveurs Git virtuels de partager une adresse au niveau de la liaison).

"ext::git-ssl foo.example /bar"

Représente un dépôt accédé à l'aide du programme gestionnaire « git-ssl foo.example /bar ». Le type de requête peut être déterminé par le gestionnaire à l'aide de variables d'environnement (voir ci-dessus).
