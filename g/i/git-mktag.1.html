NOM

git-mktag - Crée un objet étiquette avec une validation supplémentaire

SYNOPIS

git mktag

DESCRIPTION

Lit le contenu d'une étiquette depuis l'entrée standard et crée un objet étiquette. La sortie est l'identifiant de l'<objet> de la nouvelle étiquette.

Cette commande est globalement équivalente à git-hash-object(1) invoquée avec -t tag -w --stdin. C'est-à-dire que les deux commandes créeront et écriront une étiquette trouvée dans my-tag:

git mktag <my-tag
git hash-object -t tag -w --stdin <my-tag

La différence est que mktag échouera avant d'écrire l'étiquette si celle-ci ne passe pas une vérification git-fsck(1).

La vérification "fsck" effectuée par mktag est plus stricte que celle que git-fsck(1) exécuterait par défaut, en ce sens que tous les messages fsck.<msg-id> sont promus de avertissements à erreurs (ainsi, par exemple, une ligne "tagger" manquante est une erreur).

Les en-têtes supplémentaires dans l'objet sont également une erreur sous mktag, mais ignorés par git-fsck(1). Cette vérification supplémentaire peut être désactivée en définissant la variable fsck.<msg-id> appropriée :

git -c fsck.extraHeaderEntry=ignore mktag <my-tag-with-headers

OPTIONS

--strict

Par défaut, mktag active l'équivalent du mode --strict de git-fsck(1). Utilisez --no-strict pour le désactiver.

FORMAT DE L'ÉTiquette

Un fichier de signature d'étiquette, à alimenter dans l'entrée standard de cette commande, a un format fixe très simple : quatre lignes de

object <hash>
type <typename>
tag <tagname>
tagger <tagger>

suivies d'un message optionnel libre (certaines étiquettes créées par d'anciennes versions de Git peuvent ne pas avoir de ligne tagger). Le message, lorsqu'il existe, est séparé par une ligne vide de l'en-tête. La partie message peut contenir une signature que Git lui-même ignore, mais qui peut être vérifiée avec gpg.
