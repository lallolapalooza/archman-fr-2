NOM

git-merge-index - Exécuter une fusion pour les fichiers nécessitant une fusion

SYNOPSIS

git merge-index [-o] [-q] <programme-de-fusion> (-a | ( [--] <fichier>...) )

DESCRIPTION

Ceci recherche le(s) <fichier>(s) dans l'index et, s'il y a des entrées de fusion, passe les hachages SHA-1 pour ces fichiers comme arguments 1, 2, 3 (argument vide s'il n'y a pas de fichier), et <fichier> comme argument 4. Les modes de fichier pour les trois fichiers sont passés comme arguments 5, 6 et 7.

OPTIONS

--

N'interprète aucun des arguments suivants comme des options.

-a

Exécute la fusion pour tous les fichiers dans l'index qui nécessitent une fusion.

-o

Au lieu de s'arrêter à la première fusion échouée, les fait toutes en une seule fois - continue la fusion même lorsque les fusions précédentes ont renvoyé des erreurs, et ne renvoie le code d'erreur qu'après toutes les fusions.

-q

Ne se plaint pas d'un programme de fusion échoué (un échec de programme de fusion indique généralement des conflits pendant la fusion). Ceci est destiné aux porcelains qui pourraient vouloir émettre des messages personnalisés.

Si git merge-index est appelé avec plusieurs <fichier>s (ou -a) alors il les traite à tour de rôle, s'arrêtant uniquement si la fusion renvoie un code de sortie non nul.

Typiquement, ceci est exécuté avec un script appelant l'imitation par Git de la commande merge du paquet RCS.

Un script d'exemple appelé git merge-one-file est inclus dans la distribution.

ALERTE ALERTE ALERTE ! L'ordre des objets de fusion de Git est différent de l'ordre des objets de fusion du programme merge de RCS. Dans l'ordre ci-dessus, l'original est le premier. Mais l'ordre des arguments du programme de fusion à 3 voies merge consiste à placer l'original au milieu. Ne me demandez pas pourquoi.

Exemples:

torvalds@ppc970:~/merge-test> git merge-index cat MM
This is MM from the original tree.              # original
This is modified MM in the branch A.            # merge1
This is modified MM in the branch B.            # merge2
This is modified MM in the branch B.            # current contents

ou

torvalds@ppc970:~/merge-test> git merge-index cat AA MM
cat: : No such file or directory
This is added AA in the branch A.
This is added AA in the branch B.
This is added AA in the branch B.
fatal: merge program failed

où le dernier exemple montre comment git merge-index arrêtera d'essayer de fusionner dès que quelque chose aura renvoyé une erreur (c'est-à-dire que cat a renvoyé une erreur pour le fichier AA, car il n'existait pas dans l'original, et donc git merge-index n'a même pas essayé de fusionner le fichier MM).
