NOM

gigdump - Lister les informations d'un fichier Gigasampler (.gig).

SYNTAXE

gigdump [OPTIONS] FICHIER_GIG

DESCRIPTION

Par défaut, il affiche une liste de tous les échantillons disponibles, les scripts d'instruments en temps réel et les instruments contenus dans un fichier Gigasampler (.gig), ainsi que des informations détaillées sur leurs propriétés et paramètres.

OPTIONS

 FICHIER_GIG
nom du fichier Gigasampler
 --instrument-names
Lister uniquement les noms d'instruments et leur numéro d'index.
 --rebuild-checksums
Reconstruire la table de sommes de contrôle pour tous les échantillons. Lire la description de l'option  --verify pour plus de détails sur les sommes de contrôle d'échantillons en général. Vous n'avez généralement besoin d'utiliser  --rebuild-checksums que si la table des sommes de contrôle CRC elle-même a été endommagée. L'option  --verify vous indiquera si c'est bien le cas et vous suggérera d'utiliser  --rebuild-checksums pour réparer la table dans de tels cas. Si seuls des échantillons individuels ont été endommagés, vous pourriez plutôt vouloir remplacer uniquement ces échantillons endommagés avec gigedit(1) par exemple. Lisez la description de  --verify pour connaître les raisons de le faire. Lorsque vous utilisez  --rebuild-checksums, toutes les sommes de contrôle de tous les échantillons seront régénérées. Par conséquent, vous devriez vérifier manuellement tous les échantillons une fois après avoir utilisé cette option. C'est-à-dire avec vos oreilles, ou en exportant les échantillons, mais pas en utilisant l'option  --verify. Parce que cette dernière ne peut pas identifier les échantillons endommagés qui l'ont été avant que la table des sommes de contrôle entière ne soit régénérée.
 -v
Afficher la version et quitter.
 --verify
Vérifier l'intégrité des données brutes des ondes de tous les échantillons et afficher le résultat de cette vérification. Pour tous les échantillons d'un fichier gig, une somme de contrôle CRC32 correspondante est stockée avec ses données brutes d'onde chaque fois qu'un changement conscient des données d'onde a été effectué. En appelant gigdump avec cette option, tous les échantillons sont analysés et comparés à leurs sommes de contrôle existantes pour détecter tout dommage aux échantillons individuels. Les échantillons endommagés individuels sont listés par gigdump dans ce cas. Étant donné que le fichier entier doit être lu, cela peut prendre un certain temps et cette vérification n'est donc pas effectuée par défaut, c'est-à-dire chaque fois qu'un fichier gig est chargé pour une utilisation régulière par exemple. Par conséquent, vous pouvez utiliser  --verify de temps en temps pour vérifier explicitement si vos fichiers gig ont été endommagés pour une raison quelconque, c'est-à-dire après les avoir modifiés avec un éditeur d'instruments comme gigedit(1). Si des échantillons endommagés ont été trouvés, vous pouvez remplacer ces échantillons endommagés avec gigedit(1). En faisant cela, seules les sommes de contrôle des échantillons remplacés seront mises à jour. Toutes les autres sommes de contrôle resteront intactes. C'est pourquoi cette approche est recommandée plutôt que d'utiliser  --rebuild-checksums dans de tels cas.
