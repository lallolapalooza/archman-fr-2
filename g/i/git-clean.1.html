NOM

git-clean - Supprime les fichiers non suivis de l'arbre de travail

SYNTAXE

git clean [-d] [-f] [-i] [-n] [-q] [-e <modèle>] [-x | -X] [--] [<spécification_chemin>...]

DESCRIPTION

Nettoie l'arbre de travail en supprimant récursivement les fichiers qui ne sont pas sous contrôle de version, en commençant par le répertoire courant.

Normalement, seuls les fichiers inconnus de Git sont supprimés, mais si l'option -x est spécifiée, les fichiers ignorés sont également supprimés. Cela peut, par exemple, être utile pour supprimer tous les produits de compilation.

Si des arguments facultatifs <spécification_chemin>... sont fournis, seuls les chemins qui correspondent à la spécification de chemin sont affectés.

OPTIONS

-d

Normalement, lorsqu'aucune <spécification_chemin> n'est spécifiée, git clean ne récursive pas dans les répertoires non suivis pour éviter de supprimer trop. Spécifiez -d pour qu'il récursive également dans de tels répertoires. Si une <spécification_chemin> est spécifiée, -d est sans objet ; tous les fichiers non suivis correspondant aux chemins spécifiés (à l'exception des dépôts git imbriqués mentionnés sous --force) seront supprimés.

-f, --force

Si la variable de configuration Git clean.requireForce n'est pas définie à false, git clean refusera de supprimer des fichiers ou des répertoires à moins d'être donné -f. Git refusera de modifier des dépôts git imbriqués non suivis (répertoires avec un sous-répertoire .git) à moins qu'un deuxième -f ne soit donné.

-i, --interactive

Affiche ce qui serait fait et nettoie les fichiers de manière interactive. Voir « Mode interactif » pour plus de détails. La variable de configuration clean.requireForce est ignorée, car ce mode fournit sa propre protection en passant en mode interactif.

-n, --dry-run

Ne supprime réellement rien, affiche seulement ce qui serait fait. La variable de configuration clean.requireForce est ignorée, car rien ne sera supprimé de toute façon.

-q, --quiet

Soit discret, signale seulement les erreurs, mais pas les fichiers qui sont supprimés avec succès.

-e <modèle>, --exclude=<modèle>

Utilise le modèle d'exclusion donné en plus des règles d'ignorance standard (voir gitignore(5)).

-x

N'utilise pas les règles d'ignorance standard (voir gitignore(5)), mais utilise toujours les règles d'ignorance données avec les options -e de la ligne de commande. Cela permet de supprimer tous les fichiers non suivis, y compris les produits de compilation. Cela peut être utilisé (éventuellement en conjonction avec git restore ou git reset) pour créer un arbre de travail vierge afin de tester une compilation propre.

-X

Supprime uniquement les fichiers ignorés par Git. Cela peut être utile pour reconstruire tout à partir de zéro, mais conserver les fichiers créés manuellement.

MODE INTERACTIF

Lorsque la commande entre en mode interactif, elle affiche les fichiers et répertoires à nettoyer et entre dans sa boucle de commande interactive.

La boucle de commande affiche la liste des sous-commandes disponibles et donne une invite "Quoi maintenant> ". En général, lorsque l'invite se termine par un seul >, vous ne pouvez choisir qu'une seule des options données et taper Entrée, comme ceci :

    *** Commandes ***
        1: clean                2: filtrer par modèle    3: sélectionner par numéros
        4: demander à chaque    5: quitter                 6: aide
    Quoi maintenant> 1

Vous pouvez également dire c ou clean ci-dessus tant que le choix est unique.

La boucle de commande principale a 6 sous-commandes.

clean

Commence à nettoyer les fichiers et répertoires, puis quitte.

filter by pattern

Cela affiche les fichiers et répertoires à supprimer et affiche une invite "Entrez les modèles d'ignorance>>". Vous pouvez entrer des modèles séparés par des espaces pour exclure des fichiers et des répertoires de la suppression. Par exemple, "*.c *.h" exclura les fichiers se terminant par ".c" et ".h" de la suppression. Lorsque vous êtes satisfait du résultat filtré, appuyez sur ENTRÉE (vide) pour revenir au menu principal.

select by numbers

Cela affiche les fichiers et répertoires à supprimer et affiche une invite "Sélectionnez les éléments à supprimer>>". Lorsque l'invite se termine par des doubles >> comme ceci, vous pouvez faire plusieurs sélections, concaténées par des espaces ou des virgules. Vous pouvez également indiquer des plages. Par exemple, "2-5 7,9" pour choisir 2,3,4,5,7,9 dans la liste. Si le deuxième nombre d'une plage est omis, tous les éléments restants sont sélectionnés. Par exemple, "7-" pour choisir 7,8,9 dans la liste. Vous pouvez dire * pour tout choisir. De plus, lorsque vous êtes satisfait du résultat filtré, appuyez sur ENTRÉE (vide) pour revenir au menu principal.

ask each

Cela commencera à nettoyer, et vous devrez confirmer un par un pour supprimer les éléments. Veuillez noter que cette action n'est pas aussi efficace que les deux actions ci-dessus.

quit

Cela vous permet de quitter sans effectuer de nettoyage.

help

Affiche une brève utilisation de git-clean interactif.

CONFIGURATION

Tout ce qui suit cette ligne dans cette section est inclus sélectivement à partir de la documentation de git-config(1) : Le contenu est le même que celui qui s'y trouve :

clean.requireForce

Un booléen pour faire en sorte que git-clean refuse de supprimer des fichiers à moins que -f ne soit donné. Par défaut, il est défini à true.
