Prend les patches donnés sur la ligne de commande et les envoie par courriel. Les patches peuvent être spécifiés sous forme de fichiers, de répertoires (qui enverront tous les fichiers du répertoire), ou directement comme une liste de révisions. Dans le dernier cas, tout format accepté par git-format-patch(1) peut être passé à git send-email, ainsi que les options comprises par git-format-pa

tch(1).

--smtp-encryption=<chiffrement>

Spécifie la manière dont le chiffrement commence pour la connexion SMTP. Les valeurs valides sont ssl et tls. Toute autre valeur revient à un SMTP en clair (non chiffré), qui utilise le port 25 par défaut. Malgré les noms, les deux valeurs utiliseront la même version plus récente de TLS, mais pour des raisons historiques portent ces noms. ssl fait référence au chiffrement « implicite » (parfois appelé SMTPS), qui utilise le port 465 par défaut. tls fait référence au chiffrement « explicite » (souvent connu sous le nom de STARTTLS), qui utilise le port 25 par défaut. D'autres ports peuvent être utilisés par le serveur SMTP, qui ne sont pas les ports par défaut. Un port alternatif couramment trouvé pour tls et non chiffré est le 587. Vous devez consulter la documentation de votre fournisseur ou la configuration de votre serveur pour vous assurer de votre propre cas. La valeur par défaut est celle de sendemail.smtpEncryption.

--smtp-domain=<FQDN>

Spécifie le Nom de Domaine Complet (FQDN) utilisé dans la commande HELO/EHLO au serveur SMTP. Certains serveurs exigent que le FQDN corresponde à votre adresse IP. S'il n'est pas défini, git send-email tente de déterminer votre FQDN automatiquement. La valeur par défaut est celle de sendemail.smtpDomain.

--smtp-auth=<mécanismes>

Liste des mécanismes SMTP-AUTH autorisés, séparés par des espaces. Ce paramètre force l'utilisation des seuls mécanismes listés. Exemple : 
$ git send-email --smtp-auth="PLAIN LOGIN GSSAPI" ...

Si au moins un des mécanismes spécifiés correspond à ceux annoncés par le serveur SMTP et s'il est pris en charge par la bibliothèque SASL utilisée, le mécanisme est utilisé pour l'authentification. Si ni sendemail.smtpAuth ni --smtp-auth n'est spécifié, tous les mécanismes pris en charge par la bibliothèque SASL peuvent être utilisés. La valeur spéciale none peut être spécifiée pour désactiver complètement l'authentification indépendamment de --smtp-user.

--smtp-pass[=<mot de passe>]

Mot de passe pour SMTP-AUTH. L'argument est facultatif : si aucun argument n'est spécifié, la chaîne vide est utilisée comme mot de passe. La valeur par défaut est celle de sendemail.smtpPass, cependant --smtp-pass remplace toujours cette valeur.

De plus, les mots de passe n'ont pas besoin d'être spécifiés dans les fichiers de configuration ou sur la ligne de commande. Si un nom d'utilisateur a été spécifié (avec --smtp-user ou sendemail.smtpUser), mais qu'aucun mot de passe n'a été spécifié (avec --smtp-pass ou sendemail.smtpPass), alors un mot de passe est obtenu à l'aide de git-credential(1).

--no-smtp-auth

Désactive l'authentification SMTP. Raccourci pour --smtp-auth=none.

--smtp-server=<hôte>

S'il est défini, spécifie le serveur SMTP sortant à utiliser (par exemple, smtp.example.com ou une adresse IP brute). S'il n'est pas spécifié, et si --sendmail-cmd n'est pas non plus spécifié, la valeur par défaut est de rechercher sendmail dans /usr/sbin, /usr/lib et $PATH si un tel programme est disponible, en se rabattant sur localhost sinon.

Pour des raisons de compatibilité, cette option peut également spécifier un chemin d'accès complet à un programme similaire à sendmail ; le programme doit prendre en charge l'option -i. Cette méthode ne prend pas en charge le passage d'arguments ou l'utilisation de noms de commandes simples. Pour ces cas d'utilisation, envisagez d'utiliser --sendmail-cmd à la place.

--smtp-server-port=<port>

Spécifie un port différent du port par défaut (les serveurs SMTP écoutent généralement sur le port smtp 25, mais peuvent également écouter sur le port de soumission 587, ou le port smtp SSL courant 465) ; les noms de ports symboliques (par exemple, submission au lieu de 587) sont également acceptés. Le port peut également être défini avec la variable de configuration sendemail.smtpServerPort.

--smtp-server-option=<option>

S'il est défini, spécifie l'option du serveur SMTP sortant à utiliser. La valeur par défaut peut être spécifiée par l'option de configuration sendemail.smtpServerOption.

L'option --smtp-server-option doit être répétée pour chaque option que vous souhaitez transmettre au serveur. De même, différentes lignes dans les fichiers de configuration doivent être utilisées pour chaque option.

--smtp-ssl

Alias obsolète pour --smtp-encryption ssl.

--smtp-ssl-cert-path

Chemin d'accès à un magasin de certificats d'autorité de certification de confiance pour la validation de certificat SSL/TLS SMTP (soit un répertoire qui a été traité par c_rehash, soit un seul fichier contenant un ou plusieurs certificats au format PEM concaténés ensemble : voir la description des options <file> -CAfile et <dir> -CApath de https://docs.openssl.org/master/man1/openssl-verify/ [la page de manuel de verify(1) d'OpenSSL] pour plus d'informations sur celles-ci). Définissez-le à une chaîne vide pour désactiver la vérification des certificats. La valeur par défaut est celle de la variable de configuration sendemail.smtpSSLCertPath, si elle est définie, ou celle intégrée à la bibliothèque SSL sous-jacente sinon (ce qui devrait être le meilleur choix sur la plupart des plateformes).

--smtp-user=<utilisateur>

Nom d'utilisateur pour SMTP-AUTH. La valeur par défaut est celle de sendemail.smtpUser ; si un nom d'utilisateur n'est pas spécifié (avec --smtp-user ou sendemail.smtpUser), alors aucune authentification n'est tentée.

--smtp-debug=(0|1)

Active (1) ou désactive (0) la sortie de débogage. Si activé, les commandes et les réponses SMTP seront affichées. Utile pour déboguer les problèmes de connexion TLS et d'authentification.

--imap-sent-folder=<dossier>

Certains fournisseurs de messagerie (par exemple, iCloud) n'envoient pas de copie des e-mails envoyés via SMTP au dossier Sent ou similaire dans votre boîte aux lettres. Utilisez cette option pour utiliser git imap-send pour envoyer une copie des e-mails au dossier spécifié par cette option. Vous pouvez exécuter git imap-send --list pour obtenir une liste des noms de dossiers valides, y compris le nom correct du dossier Sent dans votre boîte aux lettres. Vous pouvez également utiliser cette option pour envoyer des e-mails à un dossier IMAP dédié de votre choix.

Cette fonctionnalité nécessite la configuration de git imap-send. Voir git-imap-send(1) pour les instructions.

--use-imap-only, --no-use-imap-only

Si ceci est défini, tous les e-mails seront uniquement copiés dans le dossier IMAP spécifié avec --imap-sent-folder ou sendemail.imapSentFolder et ne seront pas envoyés aux destinataires. Utile si vous souhaitez simplement créer un brouillon des e-mails et utiliser un autre client de messagerie pour les envoyer. S'il est désactivé avec --no-use-imap-only, les e-mails seront envoyés comme d'habitude. Désactivé par défaut, mais la variable de configuration sendemail.useImapOnly peut être utilisée pour l'activer.

+ Cette fonctionnalité nécessite la configuration de git imap-send. Voir git-imap-send(1) pour les instructions.

--batch-size=<num>

Certains serveurs de messagerie (par exemple, smtp.163.com) limitent le nombre d'e-mails à envoyer par session (connexion), ce qui entraînera un échec lors de l'envoi de nombreux messages. Avec cette option, send-email se déconnectera après l'envoi de <num> messages et attendra quelques secondes (voir --relogin-delay) avant de se reconnecter, afin de contourner une telle limite. Vous pourriez vouloir utiliser une forme d'aide à l'identification (credential helper) pour éviter d'avoir à retaper votre mot de passe à chaque fois que cela se produit. La valeur par défaut est la variable de configuration sendemail.smtpBatchSize.

--relogin-delay=<int>

Attend <int> secondes avant de se reconnecter au serveur SMTP. Utilisé conjointement avec l'option --batch-size. La valeur par défaut est la variable de configuration sendemail.smtpReloginDelay.

Spécifie une commande à exécuter une fois par fichier de patch, qui doit générer des entrées To: spécifiques au fichier de patch. La sortie de cette commande doit être une adresse e-mail par ligne. La valeur par défaut est celle de la valeur de configuration sendemail.toCmd.

Spécifie une commande à exécuter une fois par fichier de patch, qui doit générer des entrées Cc: spécifiques au fichier de patch. La sortie de cette commande doit être une adresse e-mail par ligne. La valeur par défaut est celle de la valeur de configuration sendemail.ccCmd.

Spécifie une commande qui est exécutée une fois par message sortant et qui génère des lignes d'en-tête au format RFC 2822 à insérer dans ces messages. --chain-reply-to, --no-chain-reply-to

Si ceci est défini, chaque e-mail sera envoyé en réponse à l'e-mail précédent envoyé. S'il est désactivé avec --no-chain-reply-to, tous les e-mails après le premier seront envoyés en réponse au premier e-mail envoyé. Lors de l'utilisation de cette option, il est recommandé que le premier fichier fourni soit une vue d'ensemble de la série de patchs entière. Désactivé par défaut, mais la variable de configuration sendemail.chainReplyTo peut être utilisée pour l'activer.

--identity=<identité>

Une identité de configuration. Lorsqu'elle est donnée, elle fait en sorte que les valeurs de la sous-section sendemail.<identité> aient la priorité sur les valeurs de la section sendemail. L'identité par défaut est la valeur de sendemail.identity.

--signed-off-by-cc, --no-signed-off-by-cc

Si ceci est défini, ajoute les e-mails trouvés dans la remorque Signed-off-by ou dans les lignes Cc: à la liste cc. La valeur par défaut est celle de la valeur de configuration sendemail.signedOffByCc ; si elle n'est pas spécifiée, la valeur par défaut est --signed-off-by-cc.

--cc-cover, --no-cc-cover

Si ceci est défini, les e-mails trouvés dans les en-têtes Cc: du premier patch de la série (généralement la lettre de couverture) sont ajoutés à la liste cc pour chaque ensemble d'e-mails. La valeur par défaut est celle de la valeur de configuration sendemail.ccCover ; si elle n'est pas spécifiée, la valeur par défaut est --no-cc-cover.

--to-cover, --no-to-cover

Si ceci est défini, les e-mails trouvés dans les en-têtes To: du premier patch de la série (généralement la lettre de couverture) sont ajoutés à la liste to pour chaque ensemble d'e-mails. La valeur par défaut est celle de la valeur de configuration sendemail.toCover ; si elle n'est pas spécifiée, la valeur par défaut est --no-to-cover.

Utiliser Gmail comme serveur

SMTP

Pour utiliser git send-email afin d'envoyer vos patches via le serveur SMTP Gmail, modifiez le fichier ~/.gitconfig pour spécifier les paramètres de votre compte

: 
[sendemail]
        smtpEncryption = ssl
smtpServer = smtp.gmail.com smtpUser =
votre.nom@gmail.com smtpServerPort = 465

Gmail n'autorise pas l'utilisation de votre mot de passe habituel avec git send-email. Si vous avez configuré une authentification à plusieurs facteurs sur votre compte Gmail, vous pouvez générer un mot de passe spécifique à l'application pour l'utiliser avec git send-email. Visitez https://security.google.com/settings/security/apppasswords pour le

créer.

Alternativement, au lieu d'utiliser un mot de passe spécifique à l'application, vous pouvez utiliser l'authentification OAuth2.0 avec Gmail. OAuth2.0 est plus sécurisé que les mots de passe spécifiques aux applications et fonctionne que vous ayez ou non configuré une authentification à plusieurs facteurs. OAUTHBEARER et XOAUTH2 sont des mécanismes couramment utilisés pour ce type d'authentification. Gmail prend en charge les deux. Par exemple, si vous souhaitez utiliser OAUTHBEARER, modifiez votre fichier ~/.gitconfig et ajoutez smtpAuth = OAUTHBEARER à vos paramètres de compte

: 
[sendemail]
        smtpEncryption = ssl
        smtpServe
r = smtp.gmail.com smtpUser = votre.nom@gmail.com
smtpServerPort = 465 smtpAuth = OAUTHBEARER

Une autre alternative consiste à utiliser un outil développé par Google appelé sendgmail[1] pour envoyer des courriels en utilisant git send-emai

l
