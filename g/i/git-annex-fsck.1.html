NOM

git-annex-fsck - trouver et corriger les problèmes

SYNOPIS

git annex fsck [chemin ...]

DESCRIPTION

Cette commande vérifie les fichiers annexés pour la cohérence, et signale ou corrige les problèmes trouvés. C'est un bon complément à git fsck.

Par défaut, tous les fichiers annexés du répertoire courant et des sous-répertoires sont vérifiés. Avec des paramètres, seuls les fichiers spécifiés sont vérifiés.

Les problèmes que fsck trouve incluent des fichiers corrompus, des fichiers dont le contenu a été perdu de quelque manière que ce soit, des fichiers qui n'ont pas encore le nombre de copies configuré, et des clés qui peuvent être mises à niveau vers un meilleur format.

OPTIONS

--from=distant
Vérifie un dépôt distant, plutôt que le dépôt local.
Notez que par défaut, les fichiers seront copiés depuis le dépôt distant pour vérifier leur contenu. Pour éviter ce transfert coûteux, et uniquement vérifier que le dépôt distant contient toujours les fichiers attendus, ajoutez l'option --fast.
--fast
Évite les calculs de sommes de contrôle coûteux (et les transferts coûteux lors de la vérification d'un dépôt distant).
--incremental
Démarre un nouveau passage de fsck incrémentiel, effaçant les enregistrements de tous les fichiers qui ont été vérifiés lors du passage de fsck incrémentiel précédent.
--more
Ignore les fichiers qui ont été vérifiés depuis le dernier passage de fsck incrémentiel.
Notez qu'avant que --incremental ne soit utilisé pour démarrer un passage de fsck incrémentiel, les fichiers vérifiés sont toujours enregistrés, et l'utilisation de cette option ignorera la vérification de ces fichiers à nouveau.
La reprise peut vérifier de manière redondante certains fichiers qui ont été vérifiés auparavant. Tous les fichiers pour lesquels fsck a trouvé des problèmes seront re-vérifiés lors de la reprise. De plus, des points de contrôle sont effectués tous les 1000 fichiers ou toutes les 5 minutes pendant un fsck, et il reprend à partir du dernier point de contrôle. Ainsi, si un fsck incrémentiel est interrompu par exemple avec ctrl-c, il re-vérifiera les fichiers qui n'ont pas atteint le dernier point de contrôle.
--incremental-schedule=temps
Ceci démarre un nouveau fsck incrémentiel seulement un temps spécifié après le démarrage du dernier fsck incrémentiel.
Le temps est sous la forme "10d" (10 jours) ou "300h" (300 heures).
Peut-être aimeriez-vous exécuter un fsck pendant 5 heures la nuit, reprenant chaque nuit où il s'est arrêté. Vous aimeriez que cela continue jusqu'à ce que tous les fichiers aient été vérifiés. Et une fois que c'est fait, vous aimeriez qu'un nouveau passage de fsck démarre, mais pas plus souvent qu'une fois par mois. Alors, mettez ceci dans un cronjob nocturne :

git annex fsck --incremental-schedule 30d --time-limit 5h
--numcopies=N
Remplace le nombre de copies normalement configuré.
Pour vérifier uniquement l'intégrité des données en ignorant le nombre requis de copies, utilisez --numcopies=1.
--all -A
Normalement, seuls les fichiers de la branche actuellement vérifiée sont vérifiés. Cette option force la vérification de toutes les versions de tous les fichiers.
C'est le comportement par défaut lors de l'exécution de git-annex dans un dépôt nu.
--branch=ref
Opère sur les fichiers dans la branche ou l'arbre spécifié.
--unused
Opère sur les fichiers trouvés par la dernière exécution de git-annex unused.
--key=nomcle
Utilisez cette option pour vérifier une clé spécifiée.
options de correspondance
Les git-annex-matching-options(1) peuvent être utilisées pour contrôler ce qui est vérifié.
--jobs=N -JN
Exécute plusieurs tâches fsck en parallèle. Par exemple : -J4
Définir ceci sur "cpus" exécutera une tâche par cœur de processeur.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes utilisant git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard d'erreur sont inclus dans le JSON à la place.
--quiet
Comme toutes les commandes git-annex, cette option fait en sorte que seuls les messages d'erreur et d'avertissement soient affichés. Ceci est particulièrement utile avec fsck, qui affiche normalement tous les fichiers qu'il est en train de vérifier, même s'il n'y a aucun problème avec eux.
Les options communes de git-annex (git-annex-common-options(1)) peuvent également être utilisées.
