GIFBUILD(1) Documentation GIFLIB GIFBUILD(1)

NOM

gifbuild - décharger les données GIF dans un format textuel, ou les recharger pour obtenir un GIF

SYNTAXE

gifbuild [-v] [-a] [-d] [-t table-de-traduction] [-h] [fichier-gif]

OPTIONS

Un programme pour convertir une série de spécifications d'icônes GIF modifiables en texte et de fichiers GIF nommés en un GIF multi-images, utilisable comme fichier de ressources graphiques. Il peut également décharger des GIF existants dans ce format. Lors du déchargement d'un GIF, certaines vérifications de cohérence sont effectuées et peuvent entraîner l'émission d'un avertissement sur la sortie d'erreur standard.

Si aucun fichier GIF n'est fourni, gifbuild essaiera de lire une entrée texte depuis l'entrée standard.

SYNTAXE DE LA SPÉCIFICATION

Voici un résumé de la syntaxe en BNF informelle. Le jeton `NL' représente un saut de ligne obligatoire.

<spec-gif> ::= <bloc-entete> <bloc-image>...
<bloc-entete> ::= <declaration-entete>...
<declaration-entete> ::=
		| largeur ecran <chiffres> NL
		| hauteur ecran <chiffres> NL
		| couleurs ecran <chiffres> NL
		| arriere-plan ecran <chiffres> NL
		| octet ratio pixels <chiffres> NL
		| table ecran <table-couleurs> NL
<table-couleurs> ::= <declaration-couleur>... fin NL
<declaration-couleur> ::= rgb <chiffres> <chiffres> <chiffres> [ est <cle>] NL
                | drapeau tri {on|off} NL
<bloc-image> ::= inclure <nom-fichier> NL
		| image NL
			<declaration-image>...
			<image-raster>
			[ <extension> ]
<declarations-image> ::= image haut <chiffres> NL
			| image gauche <chiffres> NL
			| image entrelace NL
			| table image <table-couleurs> NL
			| bits image <chiffres> par <chiffres> [hex|ascii] NL <bloc-raster>
<extension> := <commentaire> NL <bloc-extension> NL fin NL
		| <texte-plat> NL <bloc-extension> NL fin NL
                | commande graphique NL <partie-GCB> NL fin NL
                | boucle netscape  <chiffres> NL
		| extension <chiffres-hex> NL <bloc-extension> NL fin NL
<partie-GCB> ::= mode suppression <chiffres> NL
                | drapeau entree utilisateur {on|off} NL
                | delai <chiffres> NL
                | index transparent <chiffres> NL

Si les types de données des déclarations « hauteur ecran », « largeur ecran », « arriere-plan ecran », « haut image », et « gauche image » ne vous sont pas évidents, que faites-vous avec ce logiciel ?

La déclaration « octet ratio pixels » définit un dénominateur entier pour une fraction exprimant le rapport d'aspect des pixels. Voir la norme GIF pour les détails ; ce champ est en réalité obsolète depuis longtemps.

Une table de couleurs déclare des indices de couleur (par ordre croissant à partir de 0) et peut les associer à des caractères clés (ces associations sont absentes lorsque la table compte plus de 94 couleurs et que les blocs raster l'utilisant doivent utiliser des paires hexadécimales). Ces caractères peuvent être utilisés plus tard dans les blocs raster. Comme ils doivent être imprimables et sans espace blanc, vous ne pouvez spécifier que 94 couleurs par icône. La vie est parfois comme ça.

Une déclaration de table de couleurs peut également définir le drapeau de tri de la table avec « drapeau tri on » ou « drapeau tri off » sur n'importe quelle ligne avant la fin.

Un bloc raster « ascii » est juste un bloc de caractères clés (utilisé pour une table de couleurs de 94 couleurs ou moins). Un bloc raster « hex » utilise des paires de chiffres hexadécimaux à la place (utilisé pour une table de couleurs avec plus de 94 couleurs). La valeur par défaut est ASCII. Il doit être dimensionné correctement pour la déclaration « bits image » qui le précède. Les blocs raster des GIF entrelacés sont déchargés avec les lignes dans un ordre non entrelacé.

Les mots-clés « commentaire », « texte-plat » ou « commande graphique » introduisent des données d'enregistrement d'extension GIF89 définies. Le dernier type GIF89, le bloc de commande graphique et le bloc d'application, ne sont pas encore pris en charge, mais le code reconnaît un bloc de boucle Netscape. Vous pouvez également dire « extension » suivi d'un type d'enregistrement hexadécimal. Toutes ces déclarations d'extension doivent être suivies d'un bloc d'extension, qui est terminé par le mot-clé « fin » sur sa propre ligne.

Un bloc d'extension est une série de lignes de texte, chacune interprétée comme une chaîne d'octets pour remplir un bloc d'extension (le saut de ligne terminant est supprimé). Le texte peut inclure des échappements octaux et hexadécimaux de style C standard précédés d'une barre oblique inverse.

Une déclaration de bloc de commande graphique crée un bloc d'extension de commande graphique ; pour la sémantique des champs, voir la norme GIF89, partie 23.

Une déclaration de boucle Netscape crée un bloc d'extension d'application contenant un contrôle de boucle d'animation NETSCAPE 2.0 avec un nombre de répétitions spécifié (un compte de répétition de 0 signifie une boucle infinie). Cela doit être immédiatement après la déclaration d'entête. Ces blocs de boucle sont interprétés par la ligne de navigateurs Netscape/Mozilla/Firefox.

Tous les jetons <chiffres> sont interprétés comme des nombres décimaux ; les jetons <chiffres-hex> sont interprétés comme deux chiffres hexadécimaux (un octet). Toutes les coordonnées sont à origine zéro avec le coin supérieur gauche (0,0). La vérification des plages est faible et la vérification de la valeur signée inexistante ; attention hacker !

En général, la quantité d'espace blanc et l'ordre des déclarations dans un bloc d'entête ou d'image ne sont pas significatifs, sauf qu'une image raster doit suivre immédiatement sa déclaration de bits « bits image ».

La déclaration « inclure » inclut un GIF nommé comme image suivante. Les tables de couleurs globales des GIF inclus sont fusionnées avec la table de base définie par toute déclaration « couleurs ecran ». Toutes les images d'un GIF multi-images inclus seront incluses dans l'ordre.

Les commentaires (précédés de « # ») seront ignorés.

OPTIONS

-v

Mode verbeux (afficher la progression). Active l'affichage des lignes scannées en cours.

-d

Décharger le ou les fichiers GIF d'entrée dans la forme texte décrite ci-dessus.

-t

Spécifier les caractères de nom à utiliser lors du déchargement des blocs raster. Valide uniquement avec l'option -d.

-h

Afficher une ligne d'aide en ligne de commande, similaire à l'Utilisation ci-dessus.

BOGUES

La vérification des erreurs est rudimentaire.

EXEMPLE :

Un fichier d'icône exemple appelé sample.ico est inclus dans le répertoire « pic » de la distribution source de GIFLIB.
