ment les modifications indexées
dans votre branche courante

DESCRIPTIO

N

Vous avez une branche de fonctionnalité avec quelques commits. Votre coéquipier a examiné la branche et a relevé quelques bugs. Vous avez des correctifs pour ces bugs, mais vous ne voulez pas tous les entasser dans un commit opaque qui dit « fixes », car vous croyez aux commits atomiques. Au lieu de chercher manuellement les SHA des commits pour git commit --fixup, ou d'exécuter un rebase interactif manuel, faites ceci

: 
$ git add $FICHIERS_QUE_VOUS_AVEZ_CORRIGÉ
S $ git absorb --and-rebase (ou) $ git a
bsorb $ git rebase -i --autosquash master

git absorb identifiera automatiquement quels commits peuvent être modifiés en toute sécurité, et quels changements indexés appartiennent à chac

un de ces commits. Il écrira alors des commits fixup! pour chacun de ces changements. Vous pouvez vérifier sa sortie manuellement si vous n
e lui faites pas confiance, puis intégrer les fixups dans votre branche de fonctionnalité avec la fonctionnalité autosquash intégrée à git.

UTILISATI

ON
1.git add pour tout changement que vous souhaitez absorber. Par conception, git absorb ne considérera que le contenu de l'index
git.
2.git absorb. Cela créera une séquence de commits sur HEAD. Chaque commit aura un message fixup! indiquant le message (s'il est unique) ou le SHA du commit dans lequel il doit être
écrasé.
3.Si vous êtes satisfait de la sortie, git rebase -i --autosquash pour écraser les commits fixup! dans leurs prédécesseurs. Vous pouvez définir la variable d'environnement GIT_SEQUENCE_EDITOR si vous n'avez pas besoin d'éditer le fichier TODO du
rebase.
4.Si vous n'êtes pas satisfait (ou si quelque chose de mauvais s'est produit), git reset --soft PRE_ABSORB_HEAD
pour revenir au commit d'avant l'absorption et récupérer votre ancien état. (Vous pouvez aussi trouver le com
mit en question avec git reflog.) Et si vous pensez que git absorb est en faute, veuillez soumettre un problème.

PILE

Lorsqu'il est exécuté sans --base, git-absorb ne cherchera que des commits candidats à fixup dans une certaine plage (10 par défaut). Si vous obtenez une erreur comme celle-ci

:

UN FIXUP PAR COMMIT

CORRIGIBLE

Par défaut, git-absorb générera des commits fixup séparés pour chaque fragment absorbable. Pour toujours ne générer qu'1 commit fixup pour tous les fragments absorbés dans le même commit, modifiez votre .gitconfig local ou global et ajoutez la section suivante

: 
[absorb]
oneFi
xupPerComm
it = true

INDEXER AUTOMATIQUEMENT TOUTES LES CHANGEMENTS SI RIEN N'EST

INDEXÉ

Par défaut, git-absorb ne considérera que les fichiers que vous avez indexés via git add. Cependant, on veut parfois essayer d'absorber tous les changements, ce qui nécessiterait de les indexer d'abord via git add .. Pour éviter cette étape supplémentaire,

définissez 
[absorb]
    au
toStageIfNothi
ngStaged = true

ce qui indique à git-absorb, lorsque rien n'est indexé, d'indexer

automatiquement tous les changements, de créer des commits fixup où c'e
st possible, et de désindexer les changements restants de l'index.

CIBLE FIXUP TOUJOURS

SHA

Par défaut, git-absorb créera des commits fixup dont les messages pointent vers le résumé du commit cible, et s'il y a des résumés en double, il pointera vers le SHA de la cible. À la place, on peut toujours pointer vers le SHA de la cible via

: 
[absorb]
fixupTa
rgetAlways
SHA = true

GÉNÉRER DES FIXUPS POUR DES COMMITS NON ÉCRITS PAR

VOUS

Par défaut, git-absorb ne générera des commits fixup que pour les commits que vous avez écrits. Pour toujours générer des fixups pour les commits de n'importe quel auteur, modifiez votre .gitconfig local ou global et ajoutez la section suivante

: 
[absorb]
for
ceAutho
r = true

GÉNÉRER DES FIXUPS SUR UN HEAD

DÉTACHÉ

Par défaut, git-absorb ne générera pas de commits fixup lorsque HEAD n'est pas une branche (« est détaché »). Pour toujours générer des fixups sur des HEAD détachés, modifiez votre .gitconfig local ou global et ajoutez la section suivante

: 
[absor
b]
forceD
etach
= true
