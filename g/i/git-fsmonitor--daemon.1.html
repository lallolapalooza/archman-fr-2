NOM

git-fsmonitor--daemon - Un moniteur de système de fichiers intégré

SYNTAXE

git fsmonitor--daemon start
git fsmonitor--daemon run
git fsmonitor--daemon stop
git fsmonitor--daemon status

DESCRIPTION

Un démon pour surveiller le répertoire de travail des changements de fichiers et de répertoires à l'aide des installations de notification du système de fichiers spécifiques à la plateforme.

Ce démon communique directement avec des commandes telles que git status en utilisant l'interface IPC simple[1] au lieu de l'interface plus lente de githooks(5).

Ce démon est intégré à Git de sorte qu'aucun outil tiers ne soit requis.

OPTIONS

start

Démarre un démon en arrière-plan.

run

Exécute un démon en premier plan.

stop

Arrête le démon exécuté dans le répertoire de travail actuel, s'il existe.

status

Se termine avec un statut zéro si un démon surveille le répertoire de travail actuel.

REMARQUES

Ce démon est un processus de longue durée utilisé pour surveiller un seul répertoire de travail et maintenir une liste des fichiers et répertoires récemment modifiés. Les performances de commandes telles que git status peuvent être améliorées s'elles demandent simplement un résumé des modifications apportées au répertoire de travail et peuvent éviter de scanner le disque.

Lorsque core.fsmonitor est défini sur true (voir git-config(1)), les commandes, telles que git status, demanderont au démon les modifications et le démarreront automatiquement (si nécessaire).

Pour plus d'informations, consultez la section « File System Monitor » dans git-update-index(1).

CAVEATS

Le démon fsmonitor ne connaît pas actuellement les sous-modules et ne sait pas filtrer les événements du système de fichiers qui se produisent dans un sous-module. Si le démon fsmonitor surveille un super dépôt et qu'un fichier est modifié dans le répertoire de travail d'un sous-module, il signalera la modification (comme étant appliquée au super dépôt). Cependant, le client ignorera correctement ces événements supplémentaires, de sorte que les performances peuvent être affectées mais cela ne provoquera pas de résultat incorrect.

Par défaut, le démon fsmonitor refuse de fonctionner avec les dépôts montés en réseau ; cela peut être annulé en définissant fsmonitor.allowRemote sur true. Notez cependant que le démon fsmonitor n'est pas garanti de fonctionner correctement avec tous les dépôts montés en réseau, donc une telle utilisation est considérée comme expérimentale.

Sur Mac OS, la communication inter-processus (IPC) entre diverses commandes Git et le démon fsmonitor se fait via un socket de domaine Unix (UDS) - un type spécial de fichier - qui est pris en charge par les systèmes de fichiers natifs de Mac OS, mais pas sur les systèmes de fichiers montés en réseau, NTFS ou FAT32. D'autres systèmes de fichiers peuvent ou non avoir le support nécessaire ; le démon fsmonitor n'est pas garanti de fonctionner avec ces systèmes de fichiers et une telle utilisation est considérée comme expérimentale.

Par défaut, le socket est créé dans le répertoire .git. Cependant, si le répertoire .git se trouve sur un système de fichiers monté en réseau, il sera créé à la place à $HOME/.git-fsmonitor-*, à moins que $HOME ne se trouve lui-même sur un système de fichiers monté en réseau, auquel cas vous devez définir la variable de configuration fsmonitor.socketDir sur le chemin d'un répertoire sur un système de fichiers natif de Mac OS dans lequel créer le fichier socket.

Si aucun des répertoires ci-dessus (.git, $HOME ou fsmonitor.socketDir) ne se trouve sur un système de fichiers natif Mac OS, le démon fsmonitor signalera une erreur qui entraînera la sortie du démon et de la commande en cours d'exécution.

CONFIGURATION

Tout ce qui suit cette ligne dans cette section est inclus sélectivement à partir de la documentation de git-config(1). Le contenu est le même que ce qui s'y trouve :

fsmonitor.allowRemote

Par défaut, le démon fsmonitor refuse de fonctionner avec les dépôts montés en réseau. Définir fsmonitor.allowRemote sur true annule ce comportement. Uniquement respecté lorsque core.fsmonitor est défini sur true.

fsmonitor.socketDir

Cette option spécifique à Mac OS, si elle est définie, spécifie le répertoire dans lequel créer le socket de domaine Unix utilisé pour la communication entre le démon fsmonitor et diverses commandes Git. Le répertoire doit résider sur un système de fichiers natif de Mac OS. Uniquement respecté lorsque core.fsmonitor est défini sur true.
