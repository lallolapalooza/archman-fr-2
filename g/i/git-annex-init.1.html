NOM

git-annex-init - initialiser git-annex

SYNTAXE

git annex init [description]

DESCRIPTION

Jusqu'à ce qu'un dépôt (ou l'une de ses copies distantes) ait été initialisé, git-annex refusera d'y opérer, afin d'éviter de l'utiliser accidentellement dans un dépôt qui n'était pas censé avoir d'annexe.

Il est utile, mais pas obligatoire, d'initialiser chaque nouvelle copie d'un dépôt avec sa propre description. Si vous n'en fournissez pas, une sera générée en utilisant le nom d'utilisateur, le nom d'hôte et le chemin.

Si des dépôts distants spéciaux ont été configurés avec autoenable=true, cela tentera également de les activer. Voir git-annex-initremote(1). Pour éviter cela, réactivez un dépôt distant avec "autoenable=false", ou marquez-le comme mort (voir git-annex-dead(1)).

Cette commande est totalement sûre, bien que généralement inutile, à exécuter dans un dépôt git-annex déjà initialisé.

Un fichier .noannex de haut niveau empêchera l'utilisation de git-annex init dans un dépôt. Ceci est utile pour les dépôts qui ont une raison politique de ne pas utiliser git-annex. Le contenu du fichier sera affiché à l'utilisateur qui tente d'exécuter git-annex init.

La configuration git annex.pre-init-command ou le hook pre-init-annex est exécuté avant l'initialisation et peut quitter avec un code non nul pour empêcher l'initialisation, ainsi que pour effectuer d'autres configurations.

EXEMPLES


# git annex add foo
git-annex: Premier lancement : git annex init
# git annex init
init ok
# git annex add foo
add foo ok

OPTIONS

--version=N
Force l'initialisation du dépôt en utilisant une annex.version différente de la valeur par défaut actuelle.
Lorsque la version donnée n'est pas prise en charge, mais peut être mise à niveau automatiquement vers une version plus récente, elle utilisera la version plus récente à la place.
--autoenable
Active uniquement les dépôts distants spéciaux configurés avec autoenable=true, n'initialise rien d'autre.
--no-autoenable
N'active pas les dépôts distants spéciaux configurés avec autoenable=true.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex.
--json-error-messages
Les messages qui seraient normalement envoyés vers la sortie d'erreur sont inclus dans la sortie JSON à la place.
Les git-annex-common-options(1) peuvent également être utilisés.
