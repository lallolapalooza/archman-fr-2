NOM

git-patch-id - Calculer un identifiant unique pour un patch

SYNOPSIS

git patch-id [--stable | --unstable | --verbatim]

DESCRIPTION

Lire un patch depuis l'entrée standard et calculer son identifiant de patch.

Un "identifiant de patch" n'est rien d'autre qu'une somme SHA-1 des différences de fichiers associées à un patch, sans tenir compte des numéros de ligne. En tant que tel, il est "raisonnablement stable", mais en même temps raisonnablement unique, c'est-à-dire que deux patches ayant le même "identifiant de patch" sont presque garantis d'être la même chose.

L'utilisation principale de cette commande est de rechercher des commits potentiellement dupliqués.

Lorsqu'il traite la sortie de git diff-tree, il profite du fait que le patch est préfixé par le nom de l'objet du commit et produit deux chaînes hexadécimales de 40 octets. La première chaîne est l'identifiant du patch, et la seconde chaîne est l'identifiant du commit. Ceci peut être utilisé pour créer une correspondance entre l'identifiant du patch et l'identifiant du commit.

OPTIONS

--verbatim

Calculer l'identifiant de patch de l'entrée telle qu'elle est donnée, sans supprimer d'espaces blancs.

Ceci est le comportement par défaut si patchid.verbatim est défini sur true.

--stable

Utiliser une somme de hachages "stable" comme identifiant de patch. Avec cette option :
•La réorganisation des différences de fichiers qui composent un patch n'affecte pas l'identifiant. En particulier, deux patches produits en comparant les mêmes deux arbres avec deux réglages différents pour -O<fichier-ordre> donnent la même signature d'identifiant de patch, permettant ainsi d'utiliser le résultat calculé comme clé pour indexer des métadonnées sur le changement entre les deux arbres ;
•Le résultat est différent de la valeur produite par git 1.9 et antérieur ou produite lorsqu'un hachage "instable" (voir --unstable ci-dessous) est configuré - même lorsqu'il est utilisé sur une sortie de diff prise sans aucune utilisation de -O<fichier-ordre>, rendant ainsi inutilisables les bases de données existantes stockant de tels identifiants de patch "instables" ou historiques.
•Tous les espaces blancs dans le patch sont ignorés et n'affectent pas l'identifiant.

Ceci est le comportement par défaut si patchid.stable est défini sur true.

--unstable

Utiliser un hachage "instable" comme identifiant de patch. Avec cette option, le résultat produit est compatible avec la valeur d'identifiant de patch produite par git 1.9 et antérieur, et les espaces blancs sont ignorés. Les utilisateurs ayant des bases de données préexistantes stockant des identifiants de patch produits par git 1.9 et antérieur (qui ne traitent pas de patches réordonnés) peuvent vouloir utiliser cette option.

C'est le comportement par défaut.
