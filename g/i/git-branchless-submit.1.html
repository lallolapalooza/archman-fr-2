git-branchless-submit(1) Manuel des commandes générales git-branchless-submit(1)

NOM

submit - Pousser des commits vers une source distante

SYNOPSIS

submit [--hidden] [-F|--forge] [-c|--create] [-d|--draft] [-m|--message] [-j|--jobs] [-s|--strategy] [-n|--dry-run] [-h|--help] [REVSETS]

DESCRIPTION

Pousse des commits vers une source distante

OPTIONS

--hidden
Inclure les commits cachés dans les résultats de l'évaluation des expressions revset
-F, --forge=TYPE_FORGE
Le fournisseur d'hébergement Git utilisé, appelé « forge ». S'il n'est pas fourni, une tentative sera faite pour détecter automatiquement la forge utilisée par le dépôt. Si aucune forge ne peut être détectée, le système utilisera la forge « branch » par défaut.

Valeurs possibles :

  • branch : Pousse en force les branches vers la source distante par défaut. Vous pouvez configurer la source distante de poussée par défaut avec `git config remote.pushDefault <remote>`
  • github : Pousse en force les branches vers la source distante et crée une demande d'extraction pour chaque branche en utilisant l'outil en ligne de commande `gh`. ATTENTION : probablement buggé !
  • phabricator : Soumet des revues de code à Phabricator en utilisant l'outil en ligne de commande `arc`
-c, --create
S'il n'y a pas de commit distant ou d'objet de revue de code associé pour un commit local donné, crée l'objet distant en poussant le commit local vers la forge.
-d, --draft
Si la forge le supporte, crée les revues de code en mode « brouillon ».
-m, --message=MESSAGE
Si la forge le supporte, un message optionnel à inclure avec l'opération de création ou de mise à jour.
-j, --jobs=NB_JOBS
Si la forge le supporte, combien de tâches exécuter en parallèle. La valeur `0` indique d'utiliser tous les cœurs CPU.
-s, --strategy=STRATEGIE_EXECUTION
Si la forge le supporte et utilise un outil qui nécessite un accès à la copie de travail, quel type de stratégie d'exécution utiliser.

Valeurs possibles :

  • working-copy : Par défaut. Exécute les tests dans la copie de travail. Cela nécessite une copie de travail propre. Ceci est utile si vous souhaitez réutiliser les artefacts de construction dans le répertoire courant.
  • worktree : Exécute les tests dans un worktree séparé (géré par git-branchless). Ceci est utile si vous souhaitez exécuter des tests en parallèle, ou si vous souhaitez exécuter des tests sur un commit différent sans invalider les artefacts de construction dans le répertoire courant, ou si vous souhaitez exécuter des tests pendant que votre copie de travail est sale.
-n, --dry-run
Ne pousse rien et ne crée rien. Au lieu de cela, indique ce qui serait poussé ou créé. (Cela peut encore déclencher la récupération d'informations de la forge.)
-h, --help
Affiche l'aide (voir un résumé avec '-h').
[REVSETS] [défaut: stack()]
Les commits à pousser vers la forge. Sauf si `--create` est passé, cela ne poussera que les commits qui ont déjà des objets distants associés sur la forge.
