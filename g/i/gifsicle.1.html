GIFSICLE(1) Manuel des commandes générales GIFSICLE(1)

NOM

gifsicle - manipule les images et animations GIF

SYNTAXE

gifsicle [options, trames et noms de fichiers]...

DESCRIPTION

gifsicle crée, édite, manipule et affiche des informations sur les images et animations GIF.

Gifsicle traite normalement les fichiers GIF d'entrée selon ses options de ligne de commande et écrit le résultat sur la sortie standard. L'option -i, par exemple, indique à gifsicle d'entrelacer ses entrées :

gifsicle -i < pic.gif > interlaced-pic.gif

Par défaut, gifsicle combine deux fichiers d'entrée ou plus en une animation de type « flipbook » :

gifsicle pic1.gif pic2.gif pic3.gif > animation.gif

Utilisez des options comme --delay, --loopcount et --optimize pour ajuster vos animations.

Pour modifier les fichiers GIF sur place, utilisez l'option --batch. Avec --batch, gifsicle modifiera les fichiers que vous spécifiez au lieu d'écrire un nouveau fichier sur la sortie standard. Pour entrelacer tous les GIFs du répertoire courant, vous pourriez taper :

gifsicle --batch -i *.gif

Les nouveaux utilisateurs voudront peut-être passer directement à la section Exemples à la fin.

LIGNE DE COMMANDE

La ligne de commande de gifsicle se compose de fichiers d'entrée GIF et d'options. La plupart des options commencent par un tiret (-) ou un plus (+); les sélections de trames, un type d'option, commencent par un dièse (#). Tout le reste est un fichier d'entrée GIF.

gifsicle lit et traite les fichiers d'entrée GIF dans l'ordre. Si aucun fichier d'entrée GIF n'est donné, ou si vous donnez le nom de fichier spécial ‘-’, il lit depuis l'entrée standard.

gifsicle se termine avec le statut 0 s'il n'y a pas eu d'erreurs et le statut 1 sinon.

OPTIONS

Chaque option a une forme longue, ‘--long-descriptive-name’. Vous n'avez pas besoin de taper toute la description longue, juste assez pour la rendre non ambiguë.

Certaines options ont également une forme courte, ‘-X’. Vous pouvez combiner des options courtes si elles ne prennent pas d'arguments : ‘-IIb’ est équivalent à ‘-I -I -b’. Mais faites attention avec les options qui prennent des arguments : ‘-cblah’ signifie ‘-c blah’, pas ‘-c -b -l -a -h’.

Beaucoup d'options ont également un inverse, ‘--no-option’, qui désactive l'option. Vous pouvez désactiver une option courte ‘-X’ en disant ‘+X’ à la place.

Options de mode

Les options de mode indiquent à gifsicle quel type de sortie générer. Il ne peut y en avoir qu'une, et elle doit précéder les entrées GIF.

--merge, -m
Combine toutes les entrées GIF en un seul fichier avec plusieurs trames et écrit ce fichier sur la sortie standard. C'est le mode par défaut.
--batch, -b
Modifie chaque entrée GIF sur place en lisant et écrivant sur le même nom de fichier. (Les GIFs lus depuis l'entrée standard sont écrits sur la sortie standard.)
--explode, -e
Crée un fichier GIF de sortie pour chaque trame de chaque fichier d'entrée. Les fichiers GIF de sortie sont nommés ‘xxx.000’, ‘xxx.001’, et ainsi de suite, où ‘xxx’ est le nom du fichier d'entrée (ou ce que vous avez spécifié avec ‘--output’) et l'extension numérique est le numéro de trame.
--explode-by-name, -E
Identique à --explode, mais écrit les trames nommées dans des fichiers ‘xxx.name’ au lieu de ‘xxx.frame-number’. Les trames sont nommées en utilisant l'option ‘--name’.

Options générales

Les options générales contrôlent les informations que gifsicle affiche et où il écrit sa sortie. Les options d'information et --verbose peuvent être désactivées avec ‘--no-X’.

--info, -I
Affiche une description lisible par l'homme de chaque GIF d'entrée sur la sortie standard, ou le fichier que vous spécifiez avec -o. Cette option supprime la sortie normale et ne peut pas être combinée avec des options de mode comme --batch. Si vous donnez deux options --info ou -I, cependant, les informations sont affichées sur l'erreur standard, et la sortie normale a lieu comme d'habitude.

--extension-info, --xinfo
Similaire à --info, mais affiche également toutes les extensions GIF non reconnues dans un format similaire à hexdump(1).
--size-info, --sinfo
Similaire à --info, mais affiche également des informations sur les tailles d'images compressées.
--help, -h

Image Transformation

Options

Les options de transformation d'image s'appliquent aux GIF entiers lorsqu'ils sont lus ou écrits. Elles peuvent être désactivées avec ‘--no-option’

.
--resize widthxheight
Redimensionne le GIF de sortie à la largeur et à la hauteur données. Si la largeur ou la hauteur est un souligné ‘_’, cette dimension est choisie de sorte que le rapport de forme reste inchangé. Le redimensionnement se produit après que tous les trames d'entrée ont été combinées et avant l'optimisation. Le redimensionnement utilise les dimensions de l'écran logique ; si le flux d'entrée a un écran logique inhabituel (beaucoup d'afficheurs GIF ignorent les écrans logiques), vous voudrez peut-être fournir --no-logical-screen (ou +S) pour le réinitialiser afin que gifsicle utilise les dimensions de l'image à la place. Voir aussi --resize-method.
--resize-width width
--resize-height height
Redimensionne à une largeur ou une hauteur donnée, en préservant le rapport de forme. Équivalent à --resize widthx_ ou --resize _xheight.
--resize-fit widthxheight
--resize-touch largeurxhauteur
Redimensionne le GIF de sortie pour qu'il tienne dans un rectangle de dimensions largeurxhauteur. Le rapport d'aspect reste inchangé. L'option --resize-fit ne fait que réduire l'image ; aucun redimensionnement n'est effectué si le GIF tient déjà dans le rectangle. Soit largeur, soit hauteur peut être un trait de soulignement « _ », ce qui laisse cette dimension non contrainte.
--resize-fit-width largeur
--resize-fit-height hauteur
--resize-touch-width largeur
--resize-touch-height hauteur
Similaire à --resize-fit et --resize-touch, mais contraint une seule dimension.
--scale FacteurX[xFacteurY]
Met à l'échelle la largeur et la hauteur du GIF de sortie par FacteurX et FacteurY. Si FacteurY n'est pas spécifié, il prend la valeur de FacteurX. La mise à l'échelle se produit après la combinaison de toutes les images d'entrée et avant l'optimisation.
--resize-method méthode
Définit la méthode utilisée pour redimensionner les images. La méthode « sample » s'exécute très rapidement, mais lorsqu'elle réduit les images, elle produit des résultats bruyants. La méthode « mix » est un peu plus lente, mais produit des résultats plus esthétiques. La méthode par défaut est actuellement « mix ».

Détails : Les méthodes de redimensionnement diffèrent le plus lors de la réduction des images. La méthode « sample » est un échantillonneur ponctuel : chaque position de pixel dans l'image de sortie correspond exactement à une position de pixel dans l'image d'entrée. Lors de la réduction, des lignes et des colonnes entières de l'entrée sont supprimées. Les autres méthodes utilisent tous les pixels d'entrée, ce qui produit généralement des images plus esthétiques. La méthode « box », un échantillonneur par boîte, est plus rapide que les filtres plus complexes et produit des résultats un peu plus nets, mais il y aura des anomalies lors de la réduction d'images d'une petite quantité dans une dimension. (Certains pixels de sortie correspondront à exactement 1 ligne ou colonne d'entrée, tandis que d'autres correspondront à exactement 2 lignes ou colonnes d'entrée.) La méthode « mix » est un interpolateur bilinéaire complet. C'est plus lent et produit des résultats un peu plus flous, mais évite les anomalies.

Gifsicle prend également en charge des ré-échantillonneurs plus complexes, y compris le ré-échantillonnage cubique de Catmull-Rom (« catrom »), le filtre de Mitchell-Netravali (« mitchell »), un filtre de Lanczos à 2 lobes (« lanczos2 »), et un filtre de Lanczos à 3 lobes (« lanczos3 »). Ces filtres sont encore plus lents, mais peuvent donner des résultats plus nets et meilleurs.

--resize-colors n
Permet à Gifsicle d'ajouter des couleurs intermédiaires lors du redimensionnement des images. Normalement, les algorithmes de redimensionnement de Gifsicle utilisent les palettes de couleurs des images d'entrée sans modifications. Lors de la réduction d'images avec très peu de couleurs (par exemple, des images en noir et blanc pur), l'ajout de couleurs intermédiaires peut améliorer les résultats. Exemple : --resize-colors 64 permet à Gifsicle d'ajouter des couleurs intermédiaires pour les images ayant moins de 64 couleurs d'entrée.

Options de couleur

Les options de couleur s'appliquent aux GIF entiers lors de leur lecture ou écriture. Elles peuvent être désactivées avec « --no-option ».

-k nombre
--colors nombre
Réduit le nombre de couleurs distinctes dans chaque GIF de sortie à nombre ou moins. Nombre doit être compris entre 2 et 256. Cela peut être utilisé pour réduire les GIF de sortie ou supprimer toutes les tables de couleurs locales.

Normalement, un groupe adaptatif de couleurs est choisi parmi la table de couleurs existante. Vous pouvez affecter ce processus avec l'option --color-method ou en fournissant votre propre palette avec --use-colormap. Gifsicle peut avoir besoin d'ajouter une couleur supplémentaire (faisant nombre+1 au total) s'il y a de la transparence dans l'image.

--color-method méthode
Détermine comment une palette de couleurs plus petite est choisie. « diversity », par défaut, est l'algorithme de diversité de xv(1), qui utilise un sous-ensemble strict des couleurs existantes et produit généralement de bons résultats. « blend-diversity » est une modification de celui-ci : certaines valeurs de couleur sont mélangées à partir de groupes de couleurs existantes. « median-cut » est l'algorithme de coupe médiane décrit par Heckbert. --method est un synonyme de --color-method.
-f
--dither[=méthode]
Lorsque --dither est activé et que la palette de couleurs est modifiée, des combinaisons de couleurs sont utilisées pour approximer les couleurs manquantes. Cela rend mieux, mais produit des fichiers plus volumineux et peut causer des artefacts d'animation, c'est pourquoi il est désactivé par défaut.

Spécifiez un algorithme de tramage avec l'argument facultatif méthode. Par défaut, « floyd-steinberg », utilise la diffusion d'erreur de Floyd-Steinberg. Cela rend généralement mieux, mais peut causer des artefacts d'animation, car les choix de tramage varieront d'une image à l'autre. Gifsicle prend également en charge les algorithmes de tramage ordonné qui évitent les artefacts d'animation. Le mode « ro64 » utilise un grand motif d'aspect aléatoire et produit généralement de bons résultats. Les modes « o3 », « o4 » et « o8 » utilisent des motifs plus petits et plus réguliers. Le mode « ordered » choisit un bon algorithme de tramage ordonné. Pour des effets spéciaux, essayez les modes demi-teintes « halftone », « squarehalftone » et « diagonal ». Certains modes acceptent des paramètres facultatifs à l'aide de virgules. Les modes demi-teintes acceptent une taille de cellule et une limite de couleur : « halftone,10,3 » crée des cellules demi-teintes de 10 pixels de large où chaque cellule utilise jusqu'à 3 couleurs.

--gamma gamma
Définit la correction gamma à gamma, qui peut être un nombre réel ou « srgb ». En gros, des nombres plus élevés exagèrent les ombres et des nombres plus bas exagèrent les hautes lumières. La valeur par défaut est la fonction définie par l'espace colorimétrique sRGB standard, qui fonctionne généralement bien. (Ses effets sont similaires à --gamma=2.2.) Gifsicle utilise la correction gamma lors du choix d'une palette de couleurs (--colors) et lors du tramage (--dither).
--lossy[=perte]
Modifie les couleurs de l'image pour réduire la taille du fichier de sortie au détriment d'artefacts et de bruit. Perte détermine le nombre d'artefacts autorisés ; des valeurs plus élevées peuvent entraîner des fichiers plus petits, mais causent plus d'artefacts. La valeur par défaut de perte est de 20.
--change-color couleur1 couleur2
Remplace couleur1 par couleur2 dans les GIF d'entrée suivants. (Les arguments couleur ont les mêmes formes que dans l'option -t.) Modifiez plusieurs couleurs en donnant l'option plusieurs fois. Les changements de couleur n'interfèrent pas les uns avec les autres, vous pouvez donc échanger en toute sécurité deux couleurs avec ‘--change-color couleur1 couleur2 --change-color couleur2 couleur1’. Ils prennent tous effet lors de la lecture d'un GIF d'entrée. --no-change-color annule tous les changements de couleur.
--transform-colormap commande
Commande doit être une commande shell qui lit depuis l'entrée standard et écrit vers la sortie standard. Chaque palette de couleurs du GIF de sortie est traduite au format de palette de couleurs texte (voir --use-colormap ci-dessous) et transmise à la commande. La sortie que la commande génère (qui doit également être au format de palette de couleurs texte) remplacera la palette de couleurs d'entrée. Le remplacement ne tient pas compte de la correspondance des couleurs, de sorte que les pixels qui utilisaient le slot de couleur n dans l'entrée utiliseront toujours le slot de couleur n dans la sortie.
--use-colormap palette
Modifie l'image pour utiliser la palette. Chaque pixel de l'image est modifié pour correspondre au plus proche dans la palette (ou, si --dither est activé, à une combinaison tramée de couleurs dans la palette). La palette peut être web pour la palette « Web-safe » de 216 couleurs ; gray pour les niveaux de gris ; bw pour le noir et blanc ; ou le nom d'un fichier. Ce fichier doit être un fichier texte (le format est décrit ci-dessous) ou un fichier GIF, dont la palette globale sera utilisée. Si --colors=N est également donné, un sous-ensemble de taille N de la palette sera utilisé.

Les fichiers de palette de couleurs texte utilisent ce format :

; chaque ligne non commentée représente une couleur, "rouge vert bleu"
; chaque composant doit être compris entre 0 et 255
0 0 0            ; comme ceci
255 255 255
; ou utiliser la notation hexadécimale web
#ffffff          ; comme ceci
