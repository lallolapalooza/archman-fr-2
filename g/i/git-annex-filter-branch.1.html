git-annex-filter-branch(1) Manuel des commandes générales git-annex-filter-branch(1)

NOM

git-annex-filter-branch - filtrer les informations de la branche git-annex

SYNOPSIS

git annex filter-branch [...]

DESCRIPTION

Cette commande copie des informations sélectionnées de la branche git-annex dans un objet commit git, et produit son hash. Le commit git peut être transféré vers un autre dépôt git, et recevoir un nom de branche tel que "foo/git-annex", et git-annex fusionnera automatiquement cette branche dans sa propre branche git-annex. Cela permet de publier certaines informations de votre branche git-annex, sans publier l'intégralité de celle-ci.

D'autres moyens d'éviter de publier des informations d'une branche git-annex, ou de supprimer des informations de celle-ci, incluent git-annex-forget(1), le annex.private configuration git, et l' --private option de git-annex-initremote(1). Ceux-ci sont beaucoup plus faciles à utiliser, mais cette commande offre un contrôle complet pour ceux qui en ont besoin.

Sans options, aucune information ne sera incluse de la branche git-annex. Utilisez des options pour spécifier ce qu'il faut inclure. Toutes les options peuvent être spécifiées plusieurs fois.

Lorsque le dépôt contient des informations sur un dépôt privé (en raison de annex.private défini, ou de l'utilisation de git-annex initremote --private), ces informations privées seront incluses lorsque les options le permettent, même si elles ne sont pas enregistrées sur la branche git-annex.

Lorsqu'un dépôt a été créé avec git annex initremote --sameas=foo, ses informations seront incluses lorsque les informations pour foo le sont, et exclues lorsque foo est exclu.

Lorsqu'un distant spécial est configuré avec importtree=yes ou exporttree=yes, normalement l'arbre git correspondant au dépôt est inclus dans la branche git-annex, pour s'assurer qu'il ne soit pas supprimé par le ramasse-miettes par git gc. Ces arbres ne sont *pas* inclus lors du filtrage de la branche git-annex. Habituellement, cela ne posera pas de problème, mais si un tel arbre est supprimé par le ramasse-miettes, cela empêchera l'accès aux fichiers sur le distant spécial, jusqu'à la prochaine fois qu'un arbre y sera importé ou exporté.

OPTIONS

chemin
Inclure les informations sur toutes les clés des fichiers annexés dans le chemin.
options de correspondance de fichiers
Les git-annex-matching-options(1) peuvent être utilisées pour spécifier quels fichiers dans un chemin inclure.
--branch=ref
Inclure les informations sur les clés référencées des fichiers annexés dans la branche ou l'arbre.
--key=clé
Inclure les informations sur une clé spécifique.
--all
Inclure les informations sur toutes les clés.
--include-key-information-for=dépôt
Lors de l'inclusion d'informations sur une clé, inclure les informations spécifiques à ce dépôt. Le dépôt peut être spécifié avec un uuid ou le nom d'un distant. Cette option peut être utilisée plusieurs fois pour inclure plusieurs dépôts.
--include-all-key-information
Inclure les informations de clés pour tous les dépôts, sauf ceux exclus avec l' --exclude-key-information-for option.
--exclude-key-information-for=dépôt
Lors de l'inclusion d'informations sur une clé, exclure les informations spécifiques à ce dépôt. Le dépôt peut être spécifié avec un uuid ou le nom d'un distant. Cette option peut être utilisée plusieurs fois pour exclure plusieurs dépôts.
--include-repo-config-for=dépôt
Inclure la configuration spécifique à ce dépôt. Le dépôt peut être spécifié avec un uuid ou le nom d'un distant.
Cela inclut la configuration des distants spéciaux, qui peut inclure des identifiants intégrés ou des paramètres de chiffrement. Cela inclut également les paramètres de confiance, le contenu préféré, etc. Cela n'inclut pas les informations sur les clés git-annex. Cette option peut être utilisée plusieurs fois pour inclure plusieurs dépôts.
--include-all-repo-config
Inclure la configuration de tous les dépôts, sauf ceux exclus avec l' --exclude-repo-config-for option.
--exclude-repo-config-for=dépôt
Exclure la configuration spécifique à ce dépôt. Le dépôt peut être spécifié avec un uuid ou le nom d'un distant. Cette option peut être utilisée plusieurs fois pour exclure plusieurs dépôts.
--include-global-config
Inclure la configuration globale, qui n'est spécifique à aucun dépôt.
Cela inclut les configurations stockées par git-annex-numcopies(1), git-annex-config(1), etc.

EXEMPLES

Vous avez un grand dépôt git-annex et vous extrayez le répertoire "foo" pour créer un dépôt plus petit. Vous voulez que la branche git-annex du dépôt plus petit contienne toutes les informations sur les distants et les autres configurations, mais seulement les informations sur les clés dans ce répertoire.


git-annex filter-branch foo --include-all-key-information \
--include-all-repo-config --include-global-config

Cela n'inclut que les informations sur les clés actuellement dans le répertoire "foo", pas les clés utilisées par les anciennes versions des fichiers. Pour inclure également les informations sur la version du sous-répertoire dans la balise "1.0", ajoutez l'option --branch=1.0:foo

Votre dépôt a un distant spécial "bar", et vous voulez partager des informations sur les fichiers annexés qui y sont stockés, mais sans partager quoi que ce soit sur la configuration du distant.


git-annex filter-branch --all --include-all-key-information \
--include-all-repo-config --exclude-repo-config-for=bar \
--include-global-config
