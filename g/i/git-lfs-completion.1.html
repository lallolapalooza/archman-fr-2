DESCRIPTIO

N

Produit un script qui, lorsqu'il est exécuté dans une session du shell donné, implémentera la complétion par tabulation de la ligne de commande des commandes Git

LFS.

Chaque shell nécessite un ensemble différent de commandes pour charger le script de complétion, soit pour une session individuelle, soit automatiquement à chaque démarrage d'une nouvelle session. Voir la section EXEMPLES pour plus de

détails.

Le script pour chaque shell fournit la complétion par tabulation des noms de commandes et des drapeaux de Git LFS, mais n'offre pas la complétion des termes Git tels que les noms des remotes, des branches ou des étiquettes de Git. (Cela pourrait changer dans une future version de Git LFS.

)

Par défaut, le script de chaque shell prend en charge la complétion des commandes Git LFS lorsqu'une tabulation est saisie après le nom du programme git-lfs. Par exemple, git-lfs [Tab] listera les commandes Git LFS disponibles telles que fetch, migrate et pull, et git-lfs pull --[Tab] listera les drapeaux possibles pour la commande git-lfs-pull(1)

.

Cependant, la plupart des utilisateurs seront habitués à utiliser Git LFS en tant que programme invoqué par Git, par ex., git lfs checkout ou git lfs pull. Pour activer la complétion par tabulation des commandes Git LFS dans ce cas, la complétion par tabulation des commandes Git normales doit également être active. En supposant que c'est le cas, les scripts générés par la commande git lfs completion devraient prendre en charge la complétion des commandes Git LFS lorsqu'une tabulation est saisie après git lfs, comme git lfs [Tab] pour lister toutes les commandes Git LFS disponibles ou git lfs pull --[Tab] pour lister les drapeaux possibles de cette commande. Voir la section SHELLS pour plus de détails concernant la complétion par tabulation de Git dans les shells pris en

charge.

Comme c'est courant pour la complétion par tabulation des shells, un espace doit être saisi après les noms de commande git-lfs ou git lfs avant que la tabulation ne déclenche l'exécution du script de complétion de Git LFS. Sans le caractère espace, toute complétion par tabulation active du shell cherchera plutôt des programmes dont les noms ont un préfixe

correspondant.

Les scripts de complétion utilisent des commandes Git LFS « cachées » pour demander des résultats de complétion au client Git LFS, spécifiquement les commandes git lfs __complete et git lfs __completeNoDesc. Ces commandes peuvent être supprimées à l'avenir, ou leur action peut être modifiée sans préavis, et les utilisateurs ne de

vraient donc pas les appeler directement ni les considérer comme faisant part
ie de l'interface en ligne de commande officiellement documentée de Git LFS.

SHELL

S

La commande git lfs completion prend en charge trois shells Unix : GNU Bash (Bourne Again SHell), fish et Zsh (Z shell). La complétion par tabulation est configurée différemment dans chacun, tant en général que spécifiquement pour Git et donc aussi pour Git

LFS.

Sur Windows, les utilisateurs qui ont Git LFS installé dans le cadre du projet Git for Windows ont accès à une émulation du shell Bash qui est empaquetée avec Git for

Windows.
•Bash :

Bien que Bash n'offre pas la complétion par tabulation pour Git par défaut, un script de complétion est disponible auprès du projet Git, comme décrit dans la documentation

:

https://git-scm.com/book/en/v2/Appendix-A%3A-Git-in-Other-Environments-Git-in-Bas

h

Le script renvoyé par la commande git lfs completion bash devrait être compatible avec ce script de complétion de Git et permettre la complétion par tabulation des commandes Git LFS saisies en utilisant soit le format git lfs soit le format git-lfs

.

Après avoir récupéré une copie du script de complétion de Git adaptée à votre version de Git, exécutez la commande suivante pour charger le script dans votre session actuelle

: 
$ source
git-comple

Pour charger le script dans toutes les futures sessions, ajoutez cette commande à vos fichiers de démarrage de Bash, ou placez le fichier dans l'un des emplacements recherchés par les utilitaires du paquet bash-completion

.

Le projet bash-completion, qui est distinct du shell GNU Bash lui-même, inclut un grand nombre de scripts de complétion de commandes et d'utilitaires pour les charger automatiquement lors du démarrage d'une nouvelle session

:

https://github.com/scop/bash-completio

n

Le script de complétion de Git LFS pour Bash dépend de plusieurs fonctions fournies par le paquet bash-completion, et ce paquet doit donc être installé pour utiliser la complétion par tabulation avec les commandes Git LFS. (Il n'est cependant pas requis par le script de complétion de Git pour Bash.

)

En supposant que le paquet bash-completion est installé, pour charger le script de complétion de Git dans toutes les futures sessions démarrées par l'utilisateur actuel (mais pas tous les utilisateurs), placez le script git-completion.bash dans le répertoire bash-completion/completions à l'intérieur de l'emplacement défini par la variable d'environnement XDG_DATA_HOME, ou, si cette variable n'est pas définie, le répertoire ~/.local/share. Par exemple

: 
$ cp git-completion.bash ~/.local/share/bash-completion/completions/g

Pour que les utilitaires bash-completion chargent le script de complétion de Git pour tous les utilisateurs, placez le script de complétion de Git dans le répertoire système approprié. Sur Linux, il peut s'agir de /usr/share/bash-completion/completions, et sur macOS, lorsque bash-completion est installé via Homebrew, il peut s'agir du répertoire share/bash-completion/completions à l'intérieur de l'emplacement renvoyé par la commande brew --prefix. •fish :

Le shell fish fournit sa propre implémentation de la complétion par tabulation des commandes Git, définie dans un fichier git.fish qui est probablement présent par défaut dans la liste des emplacements que le shell recherche pour les scripts de

complétion.

Le script renvoyé par la commande git lfs completion fish devrait être compatible avec cette implémentation et permettre la complétion par tabulation des commandes Git LFS saisies en utilisant soit le format git lfs soit le format git-

lf
s.
•Zsh :

Pour activer la complétion par tabulation dans Zsh pour n'importe quelles commandes, la fonction compinit doit d'abord être chargée avec une commande similaire à ce qui suit

: 
% autoload -
Uz compinit
&& compinit

Cela peut être fait individuellement pour chaque session, ou ajouté à un fichier de démarrage tel que ~/.zshrc ou /etc/zshrc afin qu'il s'applique à toutes les futures sessions, soit pour l'utilisateur actuel, soit pour tous les

utilisateurs.

Zsh lit les fonctions de complétion depuis les emplacements spécifiés dans la variable d'environnement FPATH, les chemins listés en premier ayant la priorité. Cette liste est également disponible en tant que tableau dans la variable fpath ; le shell synchronise automatiquement FPATH et fpath

.

Le shell Z fournit sa propre implémentation de la complétion par tabulation des commandes Git, définie dans un fichier _git qui est probablement présent dans l'un des emplacements spécifiés dans fpath

.

Le script renvoyé par la commande git lfs completion zsh devrait être compatible avec cette implémentation et permettre la complétion par tabulation des commandes Git LFS saisies en utilisant soit le format git lfs soit le format git-lfs

.

Le projet Git propose également des scripts de complétion pour Zsh, sous la forme du même script git-completion.bash utilisé pour le shell Bash, plus un script git-completion.zsh qui est destiné à être renommé en _git et placé dans un emplacement listé dans fpath. Ces scripts ne sont pas compatibles avec celui renvoyé par la lass="Li">git lfs completion zsh, et s'ils l'utilisent en conjonction avec ce script, la complétion par tabulation des commandes Git LFS ne fonctionnera pas correctement lorsqu'elle est initiée en utilisant le format de commande git

lfs.

Sur macOS, si Git est installé à l'aide de Homebrew, les scripts de complétion Zsh du projet Git peuvent être installés à un emplacement où ils prennent le dessus sur l'implémentation fournie par Zsh. Dans ce cas, pour faire pleinement usage du script renvoyé par git lfs completion zsh, le script de complétion _git installé par Homebrew pour Git doit être déplacé ou supprimé afin qu'il ne précède pas le script de complétion Git propre au Z shell dans l'ordre de chemin spécifié par fp

at
h

shell

Pour charger les complétions de commande Git LFS dans toutes les futures sessions shell, stockez le script généré par git lfs completion dans un emplacement où il sera lu par votre shell lors du démarrage de la

•Bash :

Comme mentionné dans la section SHELLS, le paquet bash-completion est requis par les scripts de complétion Git LFS pour Bash, et il fournit également des utilitaires pratiques qui recherchent des scripts de complétion dans un ensemble d'emplacements définis et les exécutent lors du démarrage de la

session.

Pour charger le script de complétion Git LFS dans toutes les futures sessions démarrées par l'utilisateur actuel (mais pas les autres utilisateurs), stockez le script dans le répertoire bash-completion/completions à l'intérieur de l'emplacement défini par la variable d'environnement XDG_DATA_HOME, ou, si cette variable n'est pas définie, le répertoire ~/.local/share. Par exemple

: 
$ mkdir -p ~/.local/share/bash-completion/completions
$ git lfs completion bash >~/.local/share/bash-completion/completions/git-l

Pour charger le script de complétion dans les futures sessions de tous les utilisateurs, stockez plutôt le script dans un répertoire système approprié, qui sur Linux peut être /usr/share/bash-completion/completions, ou sur macOS, si bash-completion a été installé à l'aide de Homebrew, peut être le répertoire share/bash-completion/completions à l'intérieur de l'emplacement renvoyé par la commande brew --prefix. Ces emplacements varieront cependant en fonction de la manière dont le paquet bash-completion a été inst

allé et configuré. Pour plus de détails, consultez la documenta
tion pertinente pour le paquet bash-completion de votre système.

Sur Linux, c'est généralement /etc/fish/completions.
