NOM

git-annex-updateproxy - mettre à jour les enregistrements avec la configuration du proxy

SYNOPIS

git annex updateproxy

DESCRIPTION

Un dépôt git-annex peut agir comme un proxy pour ses dépôts distants. Cela permet de stocker et de supprimer le contenu annexé des dépôts distants du proxy, par des dépôts qui n'ont pas de connexion directe avec les dépôts distants.

Par défaut, aucun proxy n'est utilisé. Pour configurer le dépôt local afin qu'il agisse comme proxy pour son dépôt distant nommé "foo", exécutez git config remote.foo.annex-proxy true.

Après avoir défini ou annulé la définition des configurations git remote.<nom>.annex-proxy, exécutez git-annex updateproxy pour enregistrer la configuration du proxy dans la branche git-annex. Cela informe les autres dépôts de la configuration du proxy.

Supposons, par exemple, que le dépôt distant "work" ait eu cette commande exécutée dedans. Ensuite, après avoir récupéré depuis "work", git-annex connaîtra un dépôt distant supplémentaire, "work-foo". Ce dépôt distant sera accessible en utilisant "work" comme proxy.

Les proxys ne peuvent être accédés que via ssh ou via une URL annex+http.

Pour configurer le proxy vers un dépôt distant spécial configuré avec exporttree=yes, il est nécessaire qu'il soit également configuré avec annexobjects=yes. De plus, "remote.<nom>.annex-tracking-branch" doit être configuré sur la branche qui sera exportée vers le dépôt distant spécial. Lorsque cette branche est poussée vers le proxy, elle mettra à jour l'arbre exporté vers le dépôt distant spécial. Lorsque des fichiers sont copiés vers le dépôt distant via le proxy, cela mettra également à jour l'arbre exporté.

Notez que le proxy pour un dépôt distant spécial peut utiliser temporairement de l'espace disque dans le dépôt, pour conserver temporairement le contenu des fichiers annexés.

OPTIONS

Les git-annex-common-options(1) peuvent être utilisés.
