git-remote - Gérer l'ensemble des dépôts

suivis

SYN

OP
SIS

--verbose]

Gérer l'ensemble des dépôts (« remotes ») dont les branches sont

suivies.

OP

TIO
NS

-v,

--verbose

Être un peu plus verbeux et afficher l'URL du dépôt distant après le nom. Pour les dépôts distants prometteurs, afficher également quels

filtres (
blob:none etc.) sont configurés. NOTE : Cela doit être placé entreremote et la sous-commande. COMM
AND
ES

Sans arguments, affiche une liste des dépôts distants existants. Plusieurs sous-commandes sont disponibles pour effectuer des opérations sur

les dépôts distants.

ad

d

Ajouter un dépôt distant nommé <nom> pour le dépôt situé à

<URL>. La commande
git fetch <nom> peut ensuite être utilisée pour créer et mettre à jour les branches de suivi à distance <nom>/<branche>. Avec

l'option -f, git fetch <nom> est exécutée immédiatement après la configuration des informations du dépôt distant. Ave

c

l'option --tags, git fetch <nom> importe chaque étiquette du dépôt distant. Ave

c

l'option --no-tags, git fetch <nom> n'importe pas les étiquettes du dépôt distant. Par défaut, seules les étiquettes sur les branches récupérées sont importées

(voir

git-fetch(1)). Ave

c

l'option -t <branche>, au lieu du refspec glob par défaut pour que le dépôt distant suive toutes les branches sous l'espace de noms refs/remotes/ <nom>/, un refspec pour suivre uniquement<branche> est créé. Vous pouvez donner plus d'un -t <branche> pour suivre plusieurs branches sans récupérer toutes les branches. Ave

c

l'option -m <master>, une ref symbolique refs/remotes/ <nom>/HEAD est configurée pour pointer vers la branche<master> du dépôt distant. Voir aussi la commande set-head. Lorsqu'un miroir de récupération est créé

avec

--mirror=fetch, les refs ne seront pas stockées dans l'espace de noms refs/remotes/, mais plutôt tout ce qui est dans refs/ sur le dépôt distant sera directement miroité dans refs/ du dépôt local. Cette option n'a de sens que dans les dépôts nus, car une récupération écraserait tous les commits locaux. Lorsqu'un miroir de push est créé

avec

--mirror=push, alors git push se comportera toujours comme si --mirror avait été passé. ren

a
me

Renommer le dépôt distant nommé <ancien> en <nouveau>. Toutes les branches de suivi à distance et les paramètres de configuration du dépôt

distant sont mis à jour.
Dans le cas où <ancien> et <nouveau> sont identiques, et où <ancien> est un fichier sous

$GIT_DIR/remotes ou $GIT_DIR/branches, le dépôt distant est converti au format de fichier de configuration. remo

v
e,

rm Supprimer le dépôt distant nommé <nom>. Toutes les branches de suivi à distance et les paramètres

de configuration du dépôt distant sont supprimés.
set-hea
d

Définir ou supprimer la branche par défaut (c'est-à-dire la cible de la ref

symbolique
refs/remotes/ <nom>/HEAD) pour le dépôt distant nommé. Avoir une branche par défaut pour un dépôt distant n'est pas requis, mais permet de spécifier le nom du dépôt distant au lieu d'une branche spécifique. Par exemple, si la branche par défaut pourorigin est définie sur master, alors origin peut être spécifié là où vous spécifieriez normalement origin/master. Avec

-d ou --delete, la ref symbolique refs/remotes/ <nom>/HEAD est supprimée.Ave

c

-a ou --auto, le dépôt distant est interrogé pour déterminer son HEAD, puis la ref symbolique refs/remotes/ <nom>/HEAD est définie sur la même branche. Par exemple, si leHEAD du dépôt distant est pointé vers next, git remote set-head origin -a définira la ref symbolique refs/remotes/origin/HEAD sur refs/remotes/origin/next. Cela ne fonctionnera que si refs/remotes/origin/next existe déjà ; sinon, elle doit d'abord être récupérée. Utilise

z

<branche> pour définir explicitement la ref symbolique refs/remotes/ <nom>/HEAD. Par exemple,git remote set-head origin master définira la ref symbolique refs/remotes/origin/HEAD sur refs/remotes/origin/master. Cela ne fonctionnera que si refs/remotes/origin/master existe déjà ; sinon, elle doit d'abord être récupérée. set-br

anc
hes

Modifier la liste des branches suivies par le dépôt distant nommé. Cela peut être utilisé pour suivre un sous-ensemble des branches distants disponibles après la configuration initiale d'un

dépôt distant.
Les branches nommées seront interprétées comme si elles étaient spécifiées avec l'

option -t sur la ligne de commande git remote add

.

Avec --add, au lieu de remplacer la liste des branches

actuellement suivies,
on ajoute à cette liste.

get-ur

l
Récupérer les URL d'un dépôt distant. Les configurations pour insteadOf et pushInsteadOf sont développées ici. Par défaut, seule la première URL est listée.

Avec --push, les URL de push sont interrogées plutôt que les URL de

récupération.

Avec --all, toutes les URL du dé

pôt distant s
eront listées.

set-ur

l
Modifier les URL du dépôt distant. Définir la première URL pour le dépôt distant <nom> qui correspond à l'expression régulière <ancienneurl> (première URL si aucune <ancienneurl> n'est donnée) sur <nouvelleurl>. Si <ancienneurl> ne correspond à aucune URL, une erreur se produit et rien n'est modifié.

Avec --push, les URL de push sont manipulées au lieu des URL de

récupération.

Avec --add, au lieu de modifier les URL existantes, une nouvelle URL est

ajoutée.

Avec --delete, au lieu de modifier les URL existantes, toutes les URL correspondant à l'expression régulière <URL> sont supprimées pour le dépôt distant <nom>. Tenter de supprimer toutes les URL non-push est une

erreur.

Notez que l'URL de push et l'URL de récupération, même si elles peuvent être définies différemment, doivent toujours référencer le même endroit. Ce que vou

s avez poussé vers l'URL de push devrait être ce que vous verriez si vous récupériez immédiatement depuis l'URL de récupération. Si vous essayez de réc
upérer depuis un endroit (par ex. votre amont) et de pousser vers un autre (par ex. votre dépôt de publication), utilisez deux dépôts distants séparés.

sho

w
Donne des informations sur le dépôt distant <nom>.

Avec l'option -n, les heads du dépôt distant ne sont pas interrogés d'abord avec git ls-remote <nom> ; les informations en cach

e sont utilisées
à la place.

prun

e
Supprimer les références obsolètes associées à <nom>. Par défaut, les branches de suivi à distance obsolètes sous <nom> sont supprimées, mais selon la configuration globale et la configuration du dépôt distant, nous pourrions même élaguer les étiquettes locales qui n'ont pas été poussées là-bas. Équivalent à git fetch --prune <nom>, sauf que aucune nouvelle référence ne sera récupérée.

Voir la section PRUNING de git-fetch(1) pour ce qui sera élagué selon différentes

configurations.

Avec l'option --dry-run, signaler quelles branches seraie

nt élaguées, mais ne p
as les élaguer réellement.

updat

e
Récupérer les mises à jour pour les dépôts distants ou les groupes de dépôts distants dans le dépôt tel que défini par remotes.<groupe>. Si ni le groupe ni le dépôt distant ne sont spécifiés sur la ligne de commande, le paramètre de configuration remotes.default sera utilisé ; si remotes.default n'est pas défini, tous les dépôts distants qui n'ont pas le paramètre de configuration remote.<nom>.skipDefaultUpdateb> défini sur true sera mis à jour. (Voir git-config(1)).

Avec l'option --prune, exécuter l'é

lagage pour tou
s les distants
mis à jour.

RETOUR

En cas de succès, le code de retour est 0

.

Lorsque des sous-commandes telles que add, rename et remove ne peuvent pas trouver le distant en question, le code de retour est 2. Lorsque le distant existe déjà, le code de retour est 3

.

Pour toute autre erreur, le c

ode de retour peut être tout
e autre valeur non nulle.
