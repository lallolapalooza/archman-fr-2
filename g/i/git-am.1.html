DISCUSSION

Le nom de l'auteur du commit est pris de la ligne "From: " du message, et la date de l'auteur du commit est prise de la ligne "Date: " du message. La ligne "Subject: " est utilisée comme titre du commit, après avoir supprimé le préfixe commun "[PATCH <quelque chose>]". La ligne "Subject: " est censée décrire de manière concise de quoi traite le commit en une seule ligne de texte.

"From: ", "Date: ", et "Subject: " les lignes commençant le corps remplacent les valeurs respectives du nom de l'auteur du commit et du titre prises des en-têtes.

Le message de commit est formé par le titre tiré du "Subject: ", une ligne vide et le corps du message jusqu'à l'endroit où le patch commence. Les espaces blancs excédentaires à la fin de chaque ligne sont automatiquement supprimés.

Le patch est attendu en ligne, directement après le message. Toute ligne de la forme :

•trois tirets et fin de ligne, ou
•une ligne commençant par "diff -", ou
•une ligne commençant par "Index: "

est considérée comme le début d'un patch, et le message de log du commit est terminé avant la première occurrence d'une telle ligne.

Lors de l'invocation initiale de git am, vous lui donnez les noms des boîtes aux lettres à traiter. En rencontrant le premier patch qui ne s'applique pas, il s'interrompt au milieu. Vous pouvez récupérer de cette situation de deux manières :

1.sauter le patch actuel en relançant la commande avec l'option --skip.
2.résoudre manuellement le conflit dans le répertoire de travail, et mettre à jour le fichier d'index pour le mettre dans un état que le patch aurait dû produire. Ensuite, relancez la commande avec l'option --continue.

La commande refuse de traiter de nouvelles boîtes aux lettres tant que l'opération actuelle n'est pas terminée. Ainsi, si vous décidez de recommencer à zéro, exécutez git am --abort avant de lancer la commande avec les noms de boîtes aux lettres.

Avant que tout patch ne soit appliqué, ORIG_HEAD est défini sur le sommet de la branche actuelle. C'est utile si vous rencontrez des problèmes avec plusieurs commits, comme lancer git am sur la mauvaise branche ou une erreur dans les commits qui est plus facilement corrigée en modifiant la boîte aux lettres (par exemple, des erreurs dans les lignes "From:").

HOOKS

Cette commande peut exécuter les hooks applypatch-msg, pre-applypatch, et post-applypatch. Voir githooks(5) pour plus d'informations.

CONFIGURATION

Tout ce qui suit dans cette section est inclus sélectivement de la documentation de git-config(1). Le contenu est le même que ce que l'on y trouve :

am.keepcr

Si vrai, git-am appellera git-mailsplit pour les patches au format mbox avec le paramètre --keep-cr. Dans ce cas, git-mailsplit ne supprimera pas les \r des lignes se terminant par \r\n. Peut être remplacé en donnant --no-keep-cr depuis la ligne de commande. Voir git-am(1), git-mailsplit(1).

am.threeWay

Par défaut, git am échouera si le patch ne s'applique pas proprement. Lorsque réglé sur vrai, ce paramètre indique à git am de recourir à une fusion à 3 voies si le patch enregistre l'identité des blobs sur lesquels il est censé s'appliquer et si nous avons ces blobs localement (équivalent à donner l'option --3way depuis la ligne de commande). Par défaut, c'est false. Voir git-am(1).
