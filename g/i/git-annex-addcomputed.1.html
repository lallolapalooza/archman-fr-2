NOM

git-annex-addcomputed - ajoute des fichiers calculés au dépôt

SYNOPIS

git annex addcomputed --vers=télédéportation -- ...

DESCRIPTION

Ajoute des fichiers à l'annexe qui sont calculés à partir de fichiers d'entrée dans le dépôt, en utilisant un téléport spécial de calcul.

Une fois qu'un fichier a été ajouté à un téléport de calcul, des commandes comme git-annex get l'utiliseront pour calculer le contenu du fichier.

La syntaxe de cette commande après le -- dépend du programme que le téléport spécial de calcul est configuré pour exécuter afin de réaliser le calcul.

Pour voir l'utilisation du programme, vous pouvez exécuter :

git-annex addcomputed --vers=foo

Généralement, vous fournirez un fichier d'entrée (ou plusieurs), et souvent aussi un nom de fichier de sortie, ainsi que des paramètres supplémentaires pour contrôler le calcul.

Il peut y avoir plus d'un fichier d'entrée combinés pour calculer un fichier de sortie. Et plusieurs fichiers de sortie peuvent être calculés en même temps.

Quelques exemples de ce à quoi cela pourrait ressembler :

git-annex addcomputed --vers=x -- convertir fichier.brut fichier.jpeg passes=10 git-annex addcomputed --vers=y -- compresser foo --niveau=9 git-annex addcomputed --vers=z -- couper foo 2:01-3:00 combiner avec bar pour baz

Notez que les paramètres passés à git-annex initremote lors de la configuration du téléport spécial de calcul seront ajoutés à la fin des paramètres fournis à git-annex addcomputed.

OPTIONS

--vers=télédéportation
Spécifiez quel téléport calculera les fichiers.
Cela doit être un téléport de calcul. Par exemple, on peut en initialiser un avec :
git-annex initremote photoconv type=compute \ program=git-annex-compute-photoconv
Pour plus de détails sur les téléports de calcul, et une liste de certains des programmes disponibles, voir https://git-annex.branchable.com/special_remotes/compute/
--rapide
Ajoute les fichiers calculés au dépôt, sans encore effectuer le travail pour calculer leur contenu.
Cela implique --non-reproductible, car même si le téléport de calcul produit une sortie reproductible, elle n'est pas disponible.
--non-reproductible, -u
Indique que le calcul n'est pas censé être entièrement reproductible. Il peut varier, de manière à produire des fichiers suffisamment équivalents pour être interchangeables, mais pas nécessairement identiques.
C'est le comportement par défaut, sauf si le téléport de calcul indique qu'il produit une sortie reproductible.
--reproductible, -r
Indique que le calcul est censé être entièrement reproductible.
C'est le comportement par défaut lorsque le téléport de calcul indique qu'il produit une sortie reproductible (sauf lors de l'utilisation de --rapide).
Si un calcul s'avère ne pas être entièrement reproductible, alors récupérer un fichier calculé depuis le téléport de calcul échouera plus tard avec une erreur de vérification de somme de contrôle. Une chose qui peut être faite alors est d'utiliser git-annex recompute --original --non-reproductible.
--backend
Spécifie quel backend clé-valeur utiliser.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
Aussi le git-annex-common-options(1) peut être utilisé.
