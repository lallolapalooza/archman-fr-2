SYNOPSI

S

.
]

DESCRIPTIO

N

Le contenu d'un fichier annexé peut avoir un nombre quelconque de champs de métadonnées attachés pour le décrire. Chaque champ de métadonnées peut à son tour avoir un nombre quelconque de

valeurs.

Cette commande peut être utilisée pour définir des métadonnées ou afficher les métadonnées actuellement

définies.

Lorsqu'elle est exécutée sans aucun paramètre -s ou -t, elle affiche les métadonnées

actuelles.

Chaque champ de métadonnées a ses propres métadonnées « champ-dernière-modification », qui contiennent la date à laquelle le champ a été modifié pour la dernière fois. Contrairement aux autres métadonnées, celles-ci ne peuvent pas être modifiées directement par cette commande. Elles sont mises à jour automatiquement

.

Notez que les métadonnées sont attachées à la clé git-annex correspondant au contenu d'un fichier, et non à un nom de fichier particulier sur une b

ranche git particulière. Tous les fichiers ayant la même clé partagent les mêmes métadonnées, qui sont stockées dans la branche git-annex. Si un
fichier est modifié, les métadonnées de la version précédente seront copiées vers la nouvelle clé lorsque git-annex ajoutera le fichier modifié.

OPTION

S
-g champ / --get
champ
Récupère la ou les valeurs d'un champ
unique.
Les valeurs seront affichées une par ligne, sans autre sortie, ce qui est adapté pour une utilisation dans un
script.
-s champ=valeur / --set
champ=valeur
Définit la valeur d'un champ, en supprimant les anciennes
valeurs.
-s champ+=valeur / --set
champ+=valeur
Ajoute une valeur supplémentaire, en conservant les anciennes
valeurs.
-s champ?=valeur / --set champ?
=valeur
Définit une valeur, mais seulement si le champ n'a pas déjà de valeur
définie.
-s champ-=valeur / --set
champ-=valeur
Supprime une valeur d'un champ, en laissant les autres valeurs que le champ a
définies.
-r champ / --remove
champ
Supprime toutes les valeurs actuelles du
champ.
-t étiquette / --tag
étiquette
Définit une étiquette. Notez qu'une étiquette est simplement une valeur du champ «
tag ».
-u étiquette / --unset
étiquette
Annule une
étiquette.
--remove-a
ll
Supprime toutes les métadonnées des fichiers
spécifiés.
Lorsqu'un fichier est modifié et que la nouvelle version est ajoutée, git-annex copiera les métadonnées de l'ancienne version du fichier. Dans les situations où vous ne souhaitez pas ces métadonnées copiées, vous pouvez utiliser cette option pour les
supprimer.
--for
ce
Par défaut, git annex metadata refuse de définir récursivement les métadonnées sur les fichiers d'un répertoire. Cette option active une telle définition
récursive.
options de
correspondance
Les git-annex-matching-options(1) peuvent être utilisées pour contrôler sur quoi
agir.
--all -
A
Spécifie, au lieu d'un fichier, de récupérer/définir les métadonnées sur toutes les clés
connues.
--branch=r
ef
Spécifie, au lieu d'un fichier, de récupérer/définir les métadonnées sur tous les fichiers de la branche ou de l'arbre
spécifié.
--unus
ed
Spécifie, au lieu d'un fichier, de récupérer/définir les métadonnées sur les fichiers trouvés lors de la dernière exécution de git-annex
unused.
--key=nomdela
cle
Spécifie, au lieu d'un fichier, de récupérer/définir les métadonnées de la clé
spécifiée.
--js
on
Active la sortie JSON (et l'entrée). Chaque ligne est un objet
JSON.
Le format des objets JSON a changé dans la version git-annex 6.
20160726.
Exemple du nouveau format
:

{"command":"metadata","file":"foo","key":"...","fields":{"author":["bar"],...},"note":"...","success":
true}
Exemple de l'ancien format, qui manque l'objet fields interne
:

{"command":"metadata","file":"foo","key":"...","author":["bar"],...,"note":"...","success":
true}
--json-error-messa
ges
Les messages qui seraient normalement affichés sur la sortie d'erreur standard sont inclus dans le JSON à la
place.
--bat
ch
Active le mode par lots, qui peut être utilisé pour à la fois récupérer, stocker et annuler les métadonnées de plusieurs fichiers ou
clés.
Le mode par lots ne prend actuellement en charge que l'entrée JSON. Vous devez donc activer --json avec --batc
h.
En mode par lots, git-annex lit des lignes depuis stdin, qui contiennent des objets JSON. Il répond à chaque fichier annexé en entrée avec un objet JSON de sortie. (Mais si le fichier n'est pas un fichier annexé, une ligne vide sera affichée.
)
Le format du JSON envoyé à git-annex peut être le même que le JSON qu'il produit. Ou une version simplifiée. Seul le champ « file » (ou « key ») est réellement
nécessaire.
Par exemple, pour récupérer les métadonnées actuelles du fichier
foo :

{"file":
"foo"}
Pour récupérer les métadonnées actuelles de la clé k :


{"ke

y":
"k"}
Tout champ de métadonnées inclus dans l'objet JSON sera stocké, remplaçant les valeurs que les champs avaient auparavant. Pour annuler un champ, incluez-le avec une liste vide de
valeurs.
Pour changer l'auteur du fichier foo en
bar :

{"file":"foo","fields":{"author":["bar"]
}}
Pour supprimer l'auteur du fichier
foo :

{"file":"foo","fields":{"author":[]
}}
Les git-annex-common-options(1) peuvent également être
utilisées.
