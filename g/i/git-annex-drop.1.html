NOM

git-annex-drop - supprime le contenu des fichiers du dépôt

SYNOPSIS

git annex drop [chemin ...]

DESCRIPTION

Supprime le contenu des fichiers annexés de ce dépôt, quand c'est possible.

git-annex refusera de supprimer du contenu s'il ne peut pas vérifier qu'il est sûr de le faire. Habituellement, cela implique de vérifier que le contenu est stocké dans un autre dépôt.

Le contenu qui doit être stocké dans le dépôt ne sera pas supprimé même si des copies suffisantes existent ailleurs. Voir git-annex-required(1).

Sans paramètres, essaie de supprimer tous les fichiers annexés dans le répertoire courant. Les chemins des fichiers ou des répertoires à supprimer peuvent être spécifiés.

EXEMPLES


# git annex drop *.jpeg
supprime photo1.jpg (vérification de l'origine...) ok
supprime photo2.jpg (dangereux)
Impossible de vérifier l'existence que de 0 des 1 copies nécessaires


Plutôt que de supprimer ce fichier, essayez d'utiliser : git annex move


(Utilisez --force pour ignorer cette vérification, ou ajustez numcopies.)
échec
supprime photo3.jpg (vérification de l'origine...) ok

OPTIONS

--from=remote
Plutôt que de supprimer le contenu des fichiers dans le dépôt local, cette option peut spécifier un dépôt distant duquel le contenu des fichiers devrait être supprimé.
--fast
Lors de la suppression depuis un dépôt distant, évite de faire quoi que ce soit lorsque le dépôt distant n'est pas censé contenir un fichier. Habituellement, chaque fichier est tenté d'être supprimé du dépôt distant. Cela peut être plus rapide, mais pourrait laisser certains fichiers sur le dépôt distant dans certains cas.
--auto
Plutôt que d'essayer de supprimer tous les fichiers spécifiés, supprime uniquement ceux qui ne sont pas du contenu préféré du dépôt, et évite d'essayer de supprimer des fichiers lorsqu'il n'y a pas assez d'autres copies pour que la suppression soit possible. Voir git-annex-preferred-content(1)
--force
Utilisez cette option avec prudence ! Elle contourne les vérifications de sécurité et force git-annex à supprimer le contenu des fichiers spécifiés, même du dernier dépôt qui stocke leur contenu. Une perte de données peut résulter de l'utilisation de cette option.
--all -A
Plutôt que de spécifier un nom de fichier ou un chemin à supprimer, cette option peut être utilisée pour supprimer toutes les versions disponibles de tous les fichiers.
C'est le comportement par défaut lors de l'exécution de git-annex drop dans un dépôt bare.
Notez que cela contourne la vérification du paramètre annex.numcopies de .gitattributes et les paramètres de contenu requis.
--branch=ref
Supprime les fichiers dans la branche ou l'arbre spécifié.
Notez que cela contourne la vérification du paramètre annex.numcopies de .gitattributes et les paramètres de contenu requis.
--unused
Supprime les fichiers trouvés par la dernière exécution de git-annex unused.
Notez que cela contourne la vérification du paramètre annex.numcopies de .gitattributes et les paramètres de contenu requis.
--key=keyname
Utilisez cette option pour supprimer une clé spécifiée.
Notez que cela contourne la vérification du paramètre annex.numcopies de .gitattributes et les paramètres de contenu requis.
options de correspondance
Les git-annex-matching-options(1) peuvent être utilisées pour spécifier ce qui doit être supprimé.
--jobs=N -JN
Exécute plusieurs tâches de suppression en parallèle. Ceci est particulièrement utile lorsque git-annex doit contacter des dépôts distants pour vérifier s'il peut supprimer des fichiers. Par exemple : -J4
Le réglage de cette option sur "cpus" exécutera une tâche par cœur de processeur.
--batch
Active le mode batch, dans lequel les lignes contenant les noms des fichiers à supprimer sont lues depuis l'entrée standard.
Au fur et à mesure que chaque fichier spécifié est traité, la sortie habituelle est affichée. Si le contenu d'un fichier n'est pas présent, ou s'il ne correspond pas aux options de correspondance spécifiées, ou s'il ne s'agit pas d'un fichier annexé, une ligne vide est générée en réponse à la place.
--batch-keys
Ceci est similaire à --batch mais les lignes lues depuis l'entrée standard sont analysées comme des clés.
Notez que cela contourne la vérification du paramètre annex.numcopies de .gitattributes et les paramètres de contenu requis.
-z
Fait en sorte que l'entrée batch soit délimitée par des nulls au lieu des retours à la ligne habituels.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement dirigés vers la sortie d'erreur standard sont inclus dans le JSON à la place.
Les git-annex-common-options(1) peuvent également être utilisés.
