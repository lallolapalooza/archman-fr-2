NOM

git-annex-unlock - déverrouiller des fichiers pour modification

SYNOPSIS

git annex unlock [chemin ...]

DESCRIPTION

Normalement, le contenu des fichiers annexés est protégé contre les modifications. Le déverrouillage d'un fichier annexé permet de le modifier. Lorsque aucun fichier n'est spécifié, tous les fichiers annexés dans le répertoire courant sont déverrouillés.

Le déverrouillage d'un fichier modifie la manière dont il est stocké dans le dépôt git (d'un lien symbolique à un fichier pointeur), cette commande provoquera donc une modification que vous pourrez commiter.

Le contenu d'un fichier déverrouillé est toujours stocké dans git-annex, et non dans git. Lorsque vous commitez des modifications au fichier, ces modifications seront également stockées dans git-annex, seul le fichier pointeur étant stocké dans git.

Si vous utilisez git add pour ajouter un fichier à l'annexe, il sera ajouté sous forme déverrouillée dès le départ. Ceci permet des flux de travail où un fichier commence déverrouillé, est modifié si nécessaire, et est verrouillé une fois qu'il atteint sa version finale.

Normalement, le déverrouillage d'un fichier nécessite une copie de son contenu, afin que son contenu original soit préservé, tandis que la copie peut être modifiée. Pour utiliser moins d'espace, annex.thin peut être défini à true; cela crée un lien physique vers le contenu au lieu d'une copie. (Uniquement lorsque le système de fichiers le supporte.) Bien que cela puisse économiser considérablement d'espace disque, toute modification apportée à un fichier entraînera la perte de l'ancienne version du fichier dans le dépôt local. Activez donc annex.thin avec précaution.

EXEMPLES


# git annex unlock image-disque
# git commit -m "déverrouillé pour permettre à la VM de faire des modifications pendant son exécution"


# git annex unlock photo.jpg
# gimp photo.jpg
# git commit photo.jpg -m "suppression des yeux rouges"
# gimp photo.jpg
# git commit photo.jpg -m "correction de la sur-saturation" # git annex lock photo.jpg

OPTIONS

options de correspondance de fichiers
Les options de correspondance git-annex-matching-options(1) peuvent être utilisées pour spécifier les fichiers à déverrouiller.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard d'erreur sont inclus dans le JSON à la place.
Aussi les options communes git-annex-common-options(1) peuvent être utilisées.
