NOM

git-annex-filter-process - processus de filtre de longue durée pour git-annex

SYNTAXE

git annex filter-process

DESCRIPTION

Lorsque cette option n'est pas activée, chaque fichier que git souhaite filtrer implique le démarrage d'un nouveau processus git-annex smudge. Le démarrage de nombreux processus de ce type pour de nombreux fichiers peut être lent, et peut ralentir des commandes telles que git checkout et git add lorsqu'elles opèrent sur un grand nombre de fichiers. (Un grand nombre de fichiers annexés verrouillés ne ralentit pas git checkout, mais les fichiers déverrouillés et les fichiers non annexés le ralentissent.)

En revanche, lorsque cette option est activée, git add d'un gros fichier effectue une lecture supplémentaire inutile du fichier et en transmet le contenu à git-annex. Donc, lorsque cette option est activée, il sera plus rapide d'utiliser git-annex add pour ajouter de gros fichiers à l'annexe, plutôt que git add. D'autres commandes qui ajoutent des fichiers, comme git commit -a, sont également affectées par ceci.

Ceci est utilisé par défaut dans les dépôts git-annex v9 et supérieurs, tandis que les dépôts v8 utilisent git-annex smudge pour la compatibilité descendante avec les anciennes versions de git-annex.

Pour activer ceci dans un dépôt v8, exécutez :


git config filter.annex.process 'git-annex filter-process'

Pour le désactiver, vous pouvez simplement annuler la configuration :


git config --unset filter.annex.process

Il n'y aura aucune différence visible de comportement entre l'activation de ceci et son absence, à part des changements de vitesse et d'utilisation de la mémoire lors de l'utilisation de git.

OPTIONS

Les options_communes_de_git-annex(1) peuvent être utilisées.
