NOM

git-annex-pull - récupérer le contenu des dépôts distants

SYNOPSIS

git annex pull [remote ...]

DESCRIPTION

Cette commande récupère le contenu des dépôts distants. Elle télécharge à la fois le contenu du dépôt git et le contenu des fichiers annexés. Comme git pull, elle fusionne les modifications dans la branche actuelle.

Vous pouvez utiliser git pull et git annex get manuellement pour faire la même chose que cette commande, mais cette commande gère plusieurs détails, notamment en s'assurant que la branche git-annex est récupérée du dépôt distant.

Certains dépôts spéciaux contiennent une arborescence de fichiers qui peuvent être importés, et cette commande peut être utilisée pour importer depuis ces dépôts spéciaux ainsi que depuis des dépôts git réguliers. Voir git-annex-import(1) pour plus de détails sur le fonctionnement de ces dépôts spéciaux. Pour que cette commande importe depuis un dépôt spécial, remote.<nom>.annex-tracking-branch doit également être configuré, et avoir la même valeur que la branche actuellement extraite.

Lorsque git-annex-adjust(1) a été utilisé pour extraire une branche ajustée, cette commande récupérera également les modifications de la branche parente.

Lorsque git-annex-view(1) a été utilisé pour extraire une branche de visualisation, cette commande mettra à jour la branche de visualisation pour refléter les changements apportés à la branche parente ou aux métadonnées.

Lorsque git-annex-migrate(1) a été utilisé dans d'autres dépôts, cela met également à jour le contenu du dépôt local pour ces migrations.

Normalement, cette commande tente de télécharger le contenu de chaque fichier annexé, depuis n'importe quel dépôt distant depuis lequel elle récupère des données et qui en possède une copie. Pour contrôler quels fichiers elle télécharge, configurez le contenu préféré du dépôt local. Elle supprimera également du dépôt distant les fichiers qui ne correspondent pas au contenu préféré du dépôt distant. Voir git-annex-preferred-content(1).

OPTIONS

[remote]
Par défaut, cette commande récupère les données de tous les dépôts distants disponibles, à l'exception de ceux pour lesquels remote.<nom>.annex-pull (ou remote.<nom>.annex-sync) est défini sur false.
En spécifiant les noms des dépôts distants (ou des groupes de dépôts), vous pouvez contrôler ceux depuis lesquels récupérer les données.
--fast
Ne récupérer que les données des dépôts distants ayant la valeur d'annexe-coût la plus faible configurée.
Lorsqu'une liste de dépôts distants (ou de groupes de dépôts) est fournie, elle choisit parmi ceux-ci, sinon elle choisit parmi tous les dépôts distants.
--only-annex -a, --not-only-annex
Ne récupérer que la branche git-annex et le contenu annexé des dépôts distants, pas les autres branches git.
La configuration annex.synconlyannex peut être définie sur true pour faire de ce comportement le comportement par défaut. Pour outrepasser un tel paramètre, utilisez --not-only-annex.
Lorsque ceci est combiné avec --no-content, seule la branche git-annex sera récupérée.
--no-content, -g, --content
Utilisez --no-content ou -g pour éviter de télécharger (et de supprimer) le contenu des fichiers annexés, et pour empêcher également toute migration de contenu.
Si vous utilisez fréquemment --no-content, vous pouvez définir la configuration annex.synccontent sur false pour empêcher le téléchargement de contenu par défaut. L'option --content remplace cette configuration.
Pour empêcher uniquement les migrations de contenu, vous pouvez définir la configuration annex.syncmigrations sur false. L'option --content remplace également cette configuration.
--content-of=chemin -C chemin
Ne télécharger (et supprimer) que les fichiers annexés présents dans le chemin spécifié.
Cette option peut être répétée plusieurs fois avec des chemins différents.
--all -A
Habituellement, cette commande opère sur les fichiers annexés de la branche actuelle. Cette option la fait opérer sur toutes les versions disponibles de tous les fichiers annexés (lorsque les paramètres de contenu préféré le permettent).
Notez que les paramètres de contenu préféré qui utilisent include= ou exclude= ne correspondront qu'à la version des fichiers actuellement dans l'arbre de travail, mais pas aux versions antérieures des fichiers.
--jobs=N -JN
Active la récupération parallèle avec jusqu'à N tâches exécutées simultanément. Par exemple : -J10
Définir cette valeur sur "cpus" exécutera une tâche par cœur de processeur.
(Notez que les récupérations git ne sont pas effectuées en parallèle car cela a tendance à être moins efficace.)
--allow-unrelated-histories, --no-allow-unrelated-histories
Transmis à git merge, pour contrôler si les historiques qui n'ont pas d'ancêtre commun doivent être fusionnés ou non.
--resolvemerge, --no-resolvemerge
Par défaut, les conflits de fusion sont automatiquement gérés par cette commande. Lorsque deux versions conflictuelles d'un fichier ont été validées, les deux seront ajoutées à l'arbre, sous des noms de fichiers différents. Par exemple, le fichier "foo" serait remplacé par "foo.variant-A" et "foo.variant-B". (Voir git-annex-resolvemerge(1) pour plus de détails.)
Utilisez --no-resolvemerge pour désactiver cette résolution automatique des conflits de fusion. Elle peut également être désactivée en définissant annex.resolvemerge sur false.
--backend
Spécifie le backend clé-valeur à utiliser lors de l'importation depuis un dépôt spécial.
Les options communes git-annex(1) peuvent également être utilisées.
