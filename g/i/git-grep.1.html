-m <num>, --max-count

<num>
Limite le nombre de correspondances par fichier. Lors de l'utilisation de l'option -v ou --invert-match, la recherche s'arrête après le nombre spécifié de non-correspondances. Une valeur de -1 renverra des résultats illimités (par défaut). Une valeur de 0 terminera immédiatement le programme avec un code de sortie non

--threads

<num>
Nombre de fils d'exécution de travail de grep à utiliser. Voir NOTES ON THREADS et grep.threads dans CONFIGURATION pour plus
d'informations.

-f

<file>
Lit les motifs dans <file>, un par ligne.

Passer le motif via <file> permet de fournir un motif de recherche contenant un

\0.

Tous les types de motifs ne prennent pas en charge les motifs contenant \0. Git échouera si un type de motif donné ne peut pas prendre en charge un tel motif. Le type de motif --perl-regexp, lorsqu'il est compilé avec le backend PCRE v2, offre la plus large prise en charge pour ces types de

motifs.

Dans les versions de Git antérieures à 2.23.0, les motifs contenant \0 étaient silencieusement considérés comme fixes. Cela n'a jamais été documenté, et il y avait également des interactions étranges et non documentées entre, par exemple, des motifs non ASCII contenant \0 et --ignore-case

.

Dans de futures versions, nous pourrions apprendre à prendre en charge les mo

tifs contenant \0 pour plus de backends de recherche ; d'ici là, nous éc
houerons lorsque le type de motif en question ne les prend pas en charge.

NOTES ON

THREADS

L'option --threads (et la configuration grep.threads ) sera ignorée lorsque --open-files-in-pager est utilisé, forçant une exécution

mono-thread.

Lors de la recherche dans le dépôt d'objets (avec --cached ou en donnant des objets tree), l'exécution avec plusieurs threads peut être plus lente que l'exécution mono-thread si --textconv est donné et qu'il y a trop de conversions de texte. Ainsi, si des performances faibles sont constatées dans ce cas, il peut être souhaitable d'utiliser --threads=

1
.
