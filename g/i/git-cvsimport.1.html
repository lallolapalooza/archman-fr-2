NOM

git-cvsimport - Récupérez vos données d'un autre SCM que les gens aiment détester

SYNOPSIS

git cvsimport [-o <branche-pour-HEAD>] [-h] [-v] [-d <CVSROOT>]
              [-A <fichier-conv-auteurs>] [-p <options-pour-cvsps>] [-P <fichier>]
              [-C <dépôt-git>] [-z <fuzz>] [-i] [-k] [-u] [-s <subst>]
              [-a] [-m] [-M <regex>] [-S <regex>] [-L <limite-commits>]
              [-r <dépôt-distant>] [-R] [<module-CVS>]

DESCRIPTION

ATTENTION : git cvsimport utilise cvsps version 2, qui est considéré comme obsolète ; il ne fonctionne pas avec cvsps version 3 et ultérieures. Si vous effectuez une importation ponctuelle d'un dépôt CVS, envisagez d'utiliser cvs2git[1] ou cvs-fast-export[2].

Importe un dépôt CVS dans Git. Il créera soit un nouveau dépôt, soit importera progressivement dans un dépôt existant.

La division du journal CVS en ensembles de correctifs est effectuée par cvsps. Une version au moins 2.1 est requise.

ATTENTION : dans certaines situations, l'importation entraîne des résultats incorrects. Veuillez consulter la section PROBLÈMES pour plus d'informations.

Vous ne devez jamais effectuer de travail personnel sur les branches créées par git cvsimport. Par défaut, l'importation initiale créera et remplira une branche "master" à partir de la branche principale du dépôt CVS que vous pourrez utiliser ; après cela, vous devrez vous-même git merge les importations incrémentielles, ou toutes les branches CVS. Il est conseillé de spécifier un dépôt distant nommé via -r pour séparer et protéger les branches entrantes.

Si vous avez l'intention de configurer un dépôt public partagé auquel tous les développeurs peuvent lire/écrire, ou si vous voulez utiliser git-cvsserver(1), alors vous voudrez probablement faire un clone nu du dépôt importé, et utiliser ce clone comme dépôt partagé. Voir gitcvs-migration(7).

OPTIONS

-v

Verbosité : laissez cvsimport indiquer ce qu'il fait.

-d <CVSROOT>

La racine de l'archive CVS. Peut être locale (un simple chemin) ou distante ; actuellement, seules les méthodes d'accès :local:, :ext: et :pserver: sont supportées. Si non spécifié, git cvsimport essaiera de le lire depuis CVS/Root. Si aucun fichier de ce type n'existe, il vérifie la variable d'environnement CVSROOT.

<module-CVS>

Le module CVS que vous souhaitez importer. Relatif à <CVSROOT>. Si non spécifié, git cvsimport essaiera de le lire depuis CVS/Repository.

-C <répertoire-cible>

Le dépôt Git à importer. Si le répertoire n'existe pas, il sera créé. Par défaut, c'est le répertoire courant.

-r <dépôt-distant>

Le dépôt distant Git dans lequel importer ce dépôt CVS. Déplace toutes les branches CVS vers remotes/<dépôt-distant>/<branche>, similaire à la façon dont git clone utilise origin par défaut.

-o <branche-pour-HEAD>

Lorsqu'aucun dépôt distant n'est spécifié (via -r), la branche HEAD de CVS est importée dans la branche origin du dépôt Git, car HEAD a déjà une signification spéciale pour Git. Lorsqu'un dépôt distant est spécifié, la branche HEAD est nommée remotes/<dépôt-distant>/master, reflétant le comportement de git clone. Utilisez cette option si vous souhaitez importer dans une branche différente.

Utilisez -o master pour continuer une importation qui a été initialement effectuée par l'ancien outil cvs2git.

-i

Importation seule : n'effectue pas de checkout après l'importation. Cette option garantit que le répertoire de travail et l'index restent inchangés et ne les créera pas s'ils n'existent pas.

-k

Tuer les mots-clés : extraira les fichiers avec -kk de l'archive CVS pour éviter des jeux de modifications bruyants. Fortement recommandé, mais désactivé par défaut pour préserver la compatibilité avec les arbres importés plus tôt.

-u

Convertit les traits de soulignement dans les noms de tags et de branches en points.

-s <subst>

Remplace le caractère "/" dans les noms de branches par <subst>

-p <options-pour-cvsps>

Options supplémentaires pour cvsps. Les options -u et -A sont implicites et ne doivent pas être utilisées ici.

Si vous devez passer plusieurs options, séparez-les par une virgule.

-z <fuzz>

Passe le facteur de tolérance des horodatages à cvsps, en secondes. Si non défini, cvsps utilise par défaut 300s.

-P <fichier-sortie-cvsps>

Au lieu d'appeler cvsps, lit le fichier de sortie cvsps fourni. Utile pour le débogage ou lorsque cvsps est géré en dehors de cvsimport.

-m

Tente de détecter les fusions basées sur le message de commit. Cette option activera des expressions régulières par défaut qui essaient de capturer le nom de la branche source à partir du message de commit.

-M <regex>

Tente de détecter les fusions basées sur le message de commit avec une expression régulière personnalisée. Elle peut être utilisée avec -m pour activer également les expressions régulières par défaut. Vous devez échapper les barres obliques.

L'expression régulière doit capturer le nom de la branche source dans $1.

Cette option peut être utilisée plusieurs fois pour fournir plusieurs expressions régulières de détection.

-S <regex>

Ignore les chemins correspondant à l'expression régulière.

-a

Importe tous les commits, y compris les commits récents. cvsimport, par défaut, ignore les commits dont l'horodatage est inférieur à 10 minutes.

-L <limite>

Limite le nombre de commits importés. Solution de contournement pour les cas où cvsimport consomme trop de mémoire.

-A <fichier-conv-auteurs>

CVS utilise par défaut le nom d'utilisateur Unix lors de la rédaction de ses journaux de commits. En utilisant cette option et un fichier de conversion d'auteurs, on mappe le nom enregistré dans CVS à un nom d'auteur, une adresse e-mail et éventuellement un fuseau horaire : 
        exon=Andreas Ericsson <ae@op5.se>
        spawn=Simon Pawn <spawn@frog-pond.org> America/Chicago

git cvsimport fera comme si ces auteurs avaient eu leur GIT_AUTHOR_NAME et GIT_AUTHOR_EMAIL correctement définis depuis le début. Si un fuseau horaire est spécifié, GIT_AUTHOR_DATE aura le décalage correspondant appliqué.

Par souci de commodité, ces données sont enregistrées dans $GIT_DIR/cvs-authors chaque fois que l'option -A est fournie et lues à partir de ce même fichier chaque fois que git cvsimport est exécuté.

Il n'est pas recommandé d'utiliser cette fonctionnalité si vous avez l'intention d'exporter à nouveau des changements vers CVS plus tard avec git cvsexportcommit.

-R

Génère un fichier $GIT_DIR/cvs-revisions contenant une correspondance entre les numéros de révision CVS et les nouveaux identifiants de commit Git. Le fichier généré contiendra une ligne pour chaque paire (nom de fichier, révision) importée ; chaque ligne ressemblera à : 
src/widget.c 1.1 1d862f173cdc7325b6fa6d2ae1cfd61fd1b512b7

Les données de révision sont ajoutées au fichier s'il existe déjà, pour être utilisées lors des importations incrémentielles.

Cette option peut être utile si vous avez des numéros de révision CVS stockés dans des messages de commit, des systèmes de suivi de bogues, des archives d'e-mails, etc.

-h

Affiche un court message d'utilisation et quitte.

SORTIE

Si -v est spécifié, le script indique ce qu'il fait.

Sinon, le succès est indiqué à la manière Unix, c'est-à-dire en quittant simplement avec un statut de sortie zéro.

PROBLÈMES

Problèmes liés aux horodatages :

•Si les horodatages des commits dans le dépôt CVS ne sont pas assez stables pour être utilisés pour ordonner les commits, les changements peuvent apparaître dans le mauvais ordre.
•Si des fichiers ont été "cvs import"és plus d'une fois (par exemple, importation de plus d'une version fournisseur), la branche HEAD contient le mauvais contenu.
•Si l'ordre des horodatages de différents fichiers croise l'ordre des révisions dans la fenêtre de temps de correspondance des commits, l'ordre des commits peut être erroné.

Problèmes liés aux branches :

•Les branches sur lesquelles aucun commit n'a été effectué ne sont pas importées.
•Tous les fichiers du point de branchement sont ajoutés à une branche même s'ils n'ont jamais été ajoutés dans CVS.
•Ceci s'applique aux fichiers ajoutés dans la branche source.
