NOM

git-annex-importfeed - importer des fichiers depuis des flux de podcasts

SYNTAXE

git annex importfeed [url ...]

DESCRIPTION

Importe le contenu des podcasts et autres flux rss et atom. Ne télécharge que les fichiers dont le contenu n'a pas déjà été ajouté au dépôt, vous pouvez donc supprimer, renommer, etc. les fichiers résultants et les exécutions répétées ne les dupliqueront pas.

Lorsque yt-dlp est installé, il peut être utilisé pour télécharger les liens dans le flux. Cela permet d'importer par exemple des playlists YouTube. (Cependant, ceci est désactivé par défaut car cela peut constituer un risque de sécurité. Voir la documentation de annex.security.allowed-ip-addresses dans git-annex(1) pour plus de détails.)

Pour que le processus d'importation ajoute des métadonnées aux fichiers importés du flux, utilisez git config annex.genmetadata true

Par défaut, les fichiers téléchargés sont placés dans un répertoire portant le titre du flux, et les fichiers sont nommés en fonction du titre de l'élément du flux. Cela peut être modifié en utilisant l'option --template.

Les fichiers existants ne sont pas écrasés par cette commande. Si "some feed/foo.mp3" existe déjà, il écrira plutôt dans "some feed/2_foo.mp3" (ou 3, 4, etc.). Parfois, un flux change l'URL d'un élément, ce qui entraîne le téléchargement de la nouvelle URL vers un tel nom de fichier.

OPTIONS

--force
Force le téléchargement des éléments déjà vus.
--fast, --relaxed, --verifiable, --raw, --raw-except
Ces options se comportent de la même manière qu'avec git-annex-addurl(1).
--fast
Évite le téléchargement immédiat des URLs. L'URL est toujours vérifiée (via HEAD) pour s'assurer qu'elle existe, et pour obtenir sa taille si possible.
--relaxed
Ne télécharge pas immédiatement les URLs, et évite de stocker la taille du contenu de l'URL. Cela fait que git-annex accepte n'importe quel contenu à un point ultérieur.
--raw
Empêche le traitement spécial des URLs par yt-dlp, bittorrent et autres dépôts spéciaux. Cela téléchargera, par exemple, un fichier .torrent et non les contenus qu'il pointe.
--no-raw
Exige que le contenu pointé par l'URL soit téléchargé en utilisant yt-dlp ou un dépôt spécial, plutôt que le contenu brut de l'URL. Si cela ne peut pas être fait, l'importation échouera, et la prochaine importation du flux réessayera.
--scrape
Plutôt que de télécharger l'URL et de l'analyser comme un flux rss/atom pour trouver des fichiers à importer, utilise yt-dlp pour gratter l'équivalent d'un flux, et importe ce qu'il a trouvé.
--template
Contrôle où les fichiers sont stockés.
Le modèle par défaut est '${feedtitle}/${itemtitle}${extension}'
Les variables disponibles dans le modèle incluent celles qui concernent les informations sur le flux : feedtitle, feedauthor, feedurl
Et celles qui concernent les éléments individuels du flux : itemtitle, itemauthor, itemsummary, itemdescription, itemrights, itemid.
De plus, title est itemtitle mais utilise feedtitle par défaut si l'élément n'a pas de titre, et author est itemauthor mais utilise feedauthor par défaut.
(Toutes les variables ci-dessus sont également ajoutées en tant que métadonnées lorsque annex.genmetadata est défini.)
La variable extension est l'extension du fichier dans le flux, ou parfois ".m" si aucune extension ne peut être déterminée.
Le modèle contient également des variables pour indiquer quand un élément a été publié.
itempubyear (YYYY), itempubmonth (MM), itempubday (DD), itempubhour (HH), itempubminute (MM), itempubsecond (SS), itempubdate (YYYY-MM-DD ou si la date du flux ne peut pas être analysée, la valeur brute du flux).
(Celles-ci utilisent le fuseau horaire UTC, pas le fuseau horaire local.)
--no-check-gitignore
Par défaut, les fichiers .gitignore sont respectés et la commande refusera de télécharger une URL vers un fichier qui serait ignoré. Ceci fait que ces fichiers sont ajoutés malgré les ignores.
--jobs=N -JN
Exécute plusieurs téléchargements en parallèle. Par exemple : -J4
Le réglage de cette option sur "cpus" exécutera un travail par cœur de processeur.
--backend
Spécifie le backend clé-valeur à utiliser.
--json
Active la sortie JSON. Ceci est destiné à être analysé par les programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut les objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement envoyés à la sortie d'erreur standard sont inclus dans le JSON à la place.
Les options git-annex-common-options(1) peuvent également être utilisées.
