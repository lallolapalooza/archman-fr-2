git-annex-unused(1) Manuel des commandes générales git-annex-unused(1)

NOM

git-annex-unused - recherche de contenu de fichier inutilisé

SYNTAXE

git annex unused

DESCRIPTION

Vérifie l'annexe pour des données qui ne correspondent à aucun fichier présent dans une balise ou une branche, ou dans l'index git, et affiche une liste numérotée des données.

Après avoir exécuté cette commande, vous pouvez utiliser l'option --unused avec de nombreuses autres commandes git-annex pour opérer sur toutes les données inutilisées qui ont été trouvées.

Par exemple, pour déplacer toutes les données inutilisées vers origin :


git annex unused ; git annex move --unused --to origin

OPTIONS

--fast
Affiche uniquement les fichiers temporaires et défectueux inutilisés.
--from=repository
Vérifie les données inutilisées situées dans un dépôt.
Le dépôt doit être spécifié en utilisant le nom d'une télécommande configurée, ou l'UUID ou la description d'un dépôt.
--used-refspec=+ref:-ref
Par défaut, toute donnée utilisée par l'index git, ou vers laquelle pointent des références dans le dépôt git, est considérée comme utilisée. Si vous ne voulez utiliser que certaines références, vous pouvez utiliser cette option pour spécifier celles à utiliser. Les données qui ne figurent pas dans les références spécifiées (et qui ne sont pas utilisées par l'index) seront alors considérées comme inutilisées.
Voir FORMAT REFSPEC ci-dessous pour les détails du format de ce paramètre.
La configuration git annex.used-refspec peut être utilisée pour configurer ceci de manière plus permanente.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes utilisant git-annex.
--json-error-messages
Les messages qui seraient normalement sortis sur la sortie standard d'erreur sont inclus dans le JSON à la place.
Aussi les options communes de git-annex(1) peuvent être utilisées.

FORMAT REFSPEC

Le format refspec pour --used-refspec et annex.used-refspec est une liste de séparateurs de deux-points d'ajouts et suppressions de refs. Un exemple quelque peu artificiel :


+refs/heads/*:+HEAD^:+refs/tags/*:-refs/tags/old-tag:reflog

Ceci ajoute toutes les refs refs/heads/, ainsi que la version précédente de HEAD. Il ajoute également toutes les balises, à l'exception de old-tag. Et il ajoute toutes les refs du reflog.

Le comportement par défaut est équivalent à --used-refspec=+refs/*:+HEAD

Le refspec est traité en commençant par un ensemble vide de refs, et en parcourant la liste dans l'ordre de gauche à droite.

Chaque + utilisant un glob est mis en correspondance avec toutes les refs pertinentes (un sous-ensemble de git show-ref) et toutes les refs correspondantes sont ajoutées à l'ensemble. Par exemple, "+refs/remotes/*" ajoute toutes les refs distantes.

Chaque + sans glob ajoute la valeur littérale à l'ensemble. Par exemple, "+HEAD^" ajoute "HEAD^".

Chaque - est mis en correspondance avec l'ensemble des refs accumulées jusqu'à présent. Toutes les refs dont les noms correspondent sont supprimées de l'ensemble.

"reflog" ajoute toutes les refs du reflog. Cela fera en sorte que les versions passées des fichiers ne soient pas considérées comme inutilisées tant que la ref n'aura pas expiré du reflog (par défaut pendant 90 jours). Notez que cela peut rendre git-annex unused plus long à terminer, s'il doit vérifier chaque ref du reflog.
