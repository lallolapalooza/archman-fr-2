NOM

git-mailinfo - Extrait des patchs et des informations d'auteur d'un seul message électronique

SYNOPSIS

git mailinfo [-k|-b] [-u | --encoding=<encodage> | -n]
               [--[no-]scissors] [--quoted-cr=<action>]
               <msg> <patch>

DESCRIPTION

Lit un seul message électronique depuis l'entrée standard, et écrit le message de commit dans le fichier <msg>, et les patchs dans le fichier <patch>. Le nom de l'auteur, son e-mail et le sujet de l'e-mail sont écrits sur la sortie standard pour être utilisés par git am afin de créer un commit. Il n'est généralement pas nécessaire d'utiliser cette commande directement. Voir plutôt git-am(1).

OPTIONS

-k

Habituellement, le programme supprime le « bruit » des e-mails de la ligne d'en-tête Subject: pour extraire la ligne de titre du message de commit. Cette option empêche cette modification, et est surtout utile lorsqu'elle est utilisée pour relire la sortie de git format-patch -k.

Plus spécifiquement, les éléments suivants sont supprimés jusqu'à ce qu'aucun ne reste :

• Espaces blancs en début et fin de ligne.
• Re:, re: et : en début de ligne.
• Chaînes de caractères entre crochets (entre [ et ], généralement [PATCH]) en début de ligne.

Enfin, les suites d'espaces blancs sont normalisées en un seul caractère espace ASCII.

-b

Lorsque -k n'est pas actif, toutes les chaînes commençant par des paires de crochets [ et ] sont supprimées. Cette option limite la suppression aux paires dont la chaîne entre crochets contient le mot "PATCH".

-u

Le message de commit, le nom de l'auteur et l'e-mail de l'auteur sont extraits de l'e-mail, et après un décodage minimal de l'encodage de transfert MIME, sont recodés dans le jeu de caractères spécifié par i18n.commitEncoding (par défaut UTF-8) en les translittérant. C'était autrefois optionnel mais c'est maintenant le comportement par défaut.

Notez que le patch est toujours utilisé tel quel, sans conversion de jeu de caractères, même avec ce drapeau.

--encoding=<encodage>

Similaire à -u. Mais lors du recodage, le jeu de caractères spécifié ici est utilisé à la place de celui spécifié par i18n.commitEncoding ou UTF-8.

-n

Désactive tout recodage de jeu de caractères des métadonnées.

-m, --message-id

Copie l'en-tête Message-ID à la fin du message de commit. Ceci est utile pour associer les commits aux discussions sur les listes de diffusion.

--scissors

Supprime tout le corps avant une ligne de ciseaux (par exemple "-- >8 --"). La ligne représente des ciseaux et des marques de perforation, et est utilisée pour demander au lecteur de couper le message à cette ligne. Si cette ligne apparaît dans le corps du message avant le patch, tout ce qui précède (y compris la ligne de ciseaux elle-même) est ignoré lorsque cette option est utilisée.

Ceci est utile si vous souhaitez commencer votre message dans un fil de discussion avec des commentaires et suggestions sur le message auquel vous répondez, et le conclure avec la soumission d'un patch, séparant la discussion et le début du message de commit proposé par une ligne de ciseaux.

Ceci peut être activé par défaut avec l'option de configuration mailinfo.scissors.

--no-scissors

Ignore les lignes de ciseaux. Utile pour remplacer les réglages de mailinfo.scissors.

--quoted-cr=<action>

Action lors du traitement des messages électroniques envoyés avec un encodage base64 ou quoted-printable, et lorsque les lignes décodées se terminent par un CRLF au lieu d'un simple LF.

Les actions valides sont :

•nowarn : Git ne fera rien lorsque ce type de CRLF sera trouvé.
•warn : Git émettra un avertissement pour chaque message si un tel CRLF est trouvé.
•strip : Git convertira ces CRLF en LF.

L'action par défaut peut être définie par l'option de configuration mailinfo.quotedCR. Si aucune option de configuration n'a été définie, warn sera utilisé.

<msg>

Le message de commit extrait de l'e-mail, généralement à l'exception de la ligne de titre qui provient de l'objet de l'e-mail.

<patch>

Le patch extrait de l'e-mail.

CONFIGURATION

Tout ce qui suit cette ligne dans cette section est inclus sélectivement de la documentation de git-config(1). Le contenu est le même que celui qui s'y trouve :

mailinfo.scissors

Si vrai, fait que git-mailinfo(1) (et par conséquent git-am(1)) agit par défaut comme si l'option --scissors avait été fournie en ligne de commande. Lorsqu'il est actif, cette fonctionnalité supprime tout du corps du message avant une ligne de ciseaux (c'est-à-dire principalement composée de ">8", "8<" et "-").
