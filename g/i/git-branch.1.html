DESCRIPTIO

N

Si --list est spécifié, ou s'il n'y a pas d'arguments non-option, les branches existantes sont listées ; la branche courante sera mise en évidence en vert et marquée d'un astérisque. Toute branche activée dans des arborescences de travail liées sera mise en évidence en cyan et marquée d'un signe plus. L'option -r fait lister les branches de suivi à distance, et l'option -a montre à la fois les branches locales et

distantes.

Si un <motif> est spécifié, il est utilisé comme joker de shell pour restreindre la sortie aux branches correspondantes. Si plusieurs motifs sont spécifiés, une branche est affichée si elle correspond à l'un des

motifs.

Notez que lors de la fourniture d'un <motif>, vous devez utiliser --list ; sinon la commande peut être interprétée comme une création de

branche.

Avec --contains, montre uniquement les branches qui contiennent le commit nommé (en d'autres termes, les branches dont les commits de tête sont des descendants du commit nommé), --no-contains l'inverse. Avec --merged, seules les branches fusionnées dans le commit nommé (c'est-à-dire les branches dont les commits de tête sont accessibles depuis le commit nommé) seront listées. Avec --no-merged, seules les branches non fusionnées dans le commit nommé seront listées. Si l'argument <commit> est absent, il vaut par défaut HEAD (c'est-à-dire la tête de la branche courante)

.

La deuxième forme de la commande crée une nouvelle tête de branche nommée <nom-de-branche> qui pointe vers le HEAD courant, ou <point-de-départ> si spécifié. Comme cas particulier, pour <point-de-départ>, vous pouvez utiliser <rév-A>...<rév-B> comme raccourci pour la base de fusion de <rév-A> et <rév-B> s'il y a exactement une base de fusion. Vous pouvez omettre au plus l'un de <rév-A> et <rév-B>, auquel cas il vaut par défaut HEAD

.

Notez que cela créera la nouvelle branche, mais ne basculera pas l'arborescence de travail dessus ; utilisez git switch <nouvelle-branche> pour basculer vers la nouvelle

branche.

Lorsqu'une branche locale est démarrée à partir d'une branche de suivi à distance, Git configure la branche (plus précisément les entrées de configuration branch.<nom>.remote et branch.<nom>.merge) de sorte que git pull fusionnera de manière appropriée depuis la branche de suivi à distance. Ce comportement peut être modifié via le drapeau de configuration global branch.autoSetupMerge. Ce réglage peut être surchargé en utilisant les options --track et --no-track, et modifié plus tard en utilisant git branch --set-upstream-to

.

Avec une option -m ou -M, <ancienne-branche> sera renommée en <nouvelle-branche>. Si <ancienne-branche> avait un journal de références correspondant, il est renommé pour correspondre à <nouvelle-branche>, et une entrée de journal de références est créée pour mémoriser le renommage de la branche. Si <nouvelle-branche> existe, -M doit être utilisé pour forcer le

renommage.

Les options -c et -C ont exactement la même sémantique que -m et -M, sauf qu'au lieu d'être renommée, la branche sera copiée vers un nouveau nom, avec sa configuration et son journal de

références.

Avec une option -d ou -D, <nom-de-branche> sera supprimée. Vous pouvez spécifier plus d'une branche pour la suppression. Si la branche a actuellement un journal de références, celui-ci sera également

supprimé.

Utilisez -r avec -d pour supprimer des branches de suivi à distance. Notez que cela n'a de sens que pour supprimer des branches de suivi à distance si elles n'existent plus dans le dépôt distant ou si git fetch a été configuré pour ne plus les récupérer. Voir aussi la sous-commande prune de git-remote(1) pour une façon de nettoyer toute

s les branches de suiv
i à distance obsolètes.

-r, --remotes

Liste ou supprime (si utilisé avec -d) les branches de suivi distantes. À combiner avec --list pour correspondre aux motifs optionnels.

-a, --all

Liste les branches de suivi distantes et les branches locales. À combiner avec --list pour correspondre aux motifs optionnels.

-l, --list

Liste les branches. Avec <motif>... optionnel, par exemple git branch --list 'maint-*', liste seulement les branches qui correspondent aux motifs.

--show-current

Affiche le nom de la branche courante. En état de HEAD détaché, rien n'est affiché.

-v, -vv, --verbose

Lorsqu'en mode liste, affiche le sha1 et la ligne de sujet du commit pour chaque tête, ainsi que la relation avec la branche amont (le cas échéant). Si donné deux fois, affiche également le chemin du worktree lié (le cas échéant) et le nom de la branche amont (voir aussi git remote show <remote>). Notez que le HEAD du worktree courant n'affichera pas son chemin (ce sera toujours votre répertoire courant).

-q, --quiet

Soit plus silencieux lors de la création ou de la suppression d'une branche, en supprimant les messages non-erreurs.

--abbrev=<n>

Dans la liste verbose qui montre le nom de l'objet commit, affiche le préfixe le plus court qui a au moins <n> chiffres hexadécimaux de long et qui fait référence de manière unique à l'objet. La valeur par défaut est 7 et peut être remplacée par l'option de configuration core.abbrev.

--no-abbrev

Affiche les sha1 complets dans la liste de sortie au lieu de les abréger.

-t, --track[=(direct|inherit)]

Lors de la création d'une nouvelle branche, configure les entrées de configuration branch.<nom>.remote et branch.<nom>.merge pour définir la configuration de suivi "amont" pour la nouvelle branche. Cette configuration indiquera à git de montrer la relation entre les deux branches dans git status et git branch -v. De plus, elle dirige git pull sans arguments pour tirer de l'amont lorsque la nouvelle branche est extraite.

La branche amont exacte est choisie en fonction de l'argument optionnel : -t, --track ou --track=direct signifie utiliser la branche de point de départ elle-même comme amont ; --track=inherit signifie copier la configuration amont de la branche de point de départ.

La variable de configuration branch.autoSetupMerge spécifie comment git switch, git checkout et git branch doivent se comporter lorsque ni --track ni --no-track ne sont spécifiés :

L'option par défaut, true, se comporte comme si --track=direct était donné chaque fois que le point de départ est une branche de suivi distante. false se comporte comme si --no-track était donné. always se comporte comme si --track=direct était donné. inherit se comporte comme si --track=inherit était donné. simple se comporte comme si --track=direct était donné uniquement lorsque le <point-de-départ> est une branche de suivi distante et que la nouvelle branche porte le même nom que la branche distante.

Voir git-pull(1) et git-config(1) pour une discussion supplémentaire sur la façon dont les options branch.<nom>.remote et branch.<nom>.merge sont utilisées.

--no-track

Ne pas configurer le suivi "amont", même si la variable de configuration branch.autoSetupMerge est définie.

--recurse-submodules

CETTE OPTION EST EXPÉRIMENTALE ! Fait récurer la commande courante dans les sous-modules si submodule.propagateBranches est activé. Voir submodule.propagateBranches dans git-config(1). Actuellement, seule la création de branche est prise en charge.

Lorsqu'utilisée pour la création de branche, une nouvelle branche <nom-de-branche> sera créée dans le superprojet et dans tous les sous-modules du <point-de-départ> du superprojet. Dans les sous-modules, la branche pointera vers le commit du sous-module dans le <point-de-départ> du superprojet, mais les informations de suivi de la branche seront configurées en fonction des branches et des dépôts distants du sous-module. Par exemple, git branch --recurse-submodules topic origin/main créera la branche de sous-module "topic" qui pointe vers le commit du sous-module dans "origin/main" du superprojet, mais suit le "origin/main" du sous-module.

--set-upstream

Comme cette option avait une syntaxe confuse, elle n'est plus prise en charge. Veuillez utiliser --track ou --set-upstream-to à la place.

-u <amont>, --set-upstream-to=<amont>

Configure les informations de suivi de <nom-de-branche> pour que <amont> soit considérée comme la branche amont de <nom-de-branche>. Si aucun <nom-de-branche> n'est spécifié, elle sera par défaut la branche courante.

--unset-upstream

Supprime les informations d'amont pour <nom-de-branche>. Si aucune branche n'est spécifiée, elle sera par défaut la branche courante.

--edit-description

Ouvre un éditeur et modifie le texte pour expliquer l'utilité de la branche, destiné à être utilisé par diverses autres commandes (par exemple, format-patch, request-pull et merge (si activé)). Des explications multilignes peuvent être utilisées.

--contains [<commit>]

Liste uniquement les branches qui contiennent <commit> (HEAD si non spécifié). Implique --list.

--no-contains [<commit>]

Liste uniquement les branches qui ne contiennent pas <commit> (HEAD si non spécifié). Implique --list.

--merged [<commit>]

Liste uniquement les branches dont les pointes sont atteignables depuis <commit> (HEAD si non spécifié). Implique --list.

--no-merged [<commit>]

Liste uniquement les branches dont les pointes ne sont pas atteignables depuis <commit> (HEAD si non spécifié). Implique --list.

--points-at <objet>

Liste uniquement les branches de <objet>.

--format <format>

Une chaîne qui interpole %(nom-de-champ) à partir d'une référence de branche affichée et de l'objet sur lequel elle pointe. <format> est le même que celui de git-for-each-ref(1).

<nom-de-branche>

Le nom de la branche à créer ou à supprimer. Le nouveau nom de branche doit passer tous les contrôles définis par git-check-ref-format(1). Certains de ces contrôles peuvent restreindre les caractères autorisés dans un nom de branche.

<point-de-départ>

La nouvelle tête de branche pointera vers ce commit. Il peut être donné sous forme de nom de branche, d'identifiant de commit ou de tag. Si cette option est omise, le HEAD courant sera utilisé à la place.

<ancienne-branche>

Le nom d'une branche existante. Si cette option est omise, le nom de la branche courante sera utilisé à la place.

<nouvelle-branche>

Le nouveau nom d'une branche existante. Les mêmes restrictions que pour <nom-de-branche> s'appliquent.

branch.autoSetupMerge

Indique à git branch, git switch et git checkout de configurer les nouvelles branches de manière à ce que git-pull(1) effectue une fusion appropriée à partir de la branche de départ. Notez que même si cette option n'est pas définie, ce comportement peut être choisi par branche à l'aide des options --track et --no-track. Cette option vaut par défaut true. Les valeurs valides sont :

false

aucune configuration automatique n'est effectuée

true

la configuration automatique est effectuée lorsque le point de départ est une branche de suivi distante

always

la configuration automatique est effectuée lorsque le point de départ est soit une branche locale, soit une branche de suivi distante

inherit

si le point de départ a une configuration de suivi, elle est copiée vers la nouvelle branche

simple

la configuration automatique est effectuée uniquement lorsque le point de départ est une branche de suivi distante et que la nouvelle branche porte le même nom que la branche distante.

branch.autoSetupRebase

Lorsqu'une nouvelle branche est créée avec git branch, git switch ou git checkout qui suit une autre branche, cette variable indique à Git de configurer le pull pour rebaser au lieu de fusionner (voir branch.<nom>.rebase). Les paramètres valides sont :

never

rebase n'est jamais défini automatiquement sur true.

local

rebase est défini sur true pour les branches suivies d'autres branches locales.

remote

rebase est défini sur true pour les branches suivies de branches de suivi distantes.

always

rebase sera défini sur true pour toutes les branches de suivi.

Voir branch.autoSetupMerge pour plus de détails sur la façon de configurer une branche pour suivre une autre branche. Cette option vaut par défaut never.

branch.sort
