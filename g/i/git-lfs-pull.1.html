NOM

git-lfs-pull - Télécharge tous les fichiers Git LFS pour la référence actuelle et le checkout

SYNTAXE

git lfs pull [options] [<remote>]

DESCRIPTION

Télécharge les objets Git LFS pour la référence actuellement sélectionnée et met à jour la copie de travail avec le contenu téléchargé si nécessaire.

Ceci est généralement équivalent à l'exécution des deux commandes suivantes :

$ git lfs fetch [options] [<remote>]
$ git lfs checkout

Si la version de Git installée est au moins 2.42.0, dans un dépôt non vide, cette commande télécharge et sélectionne par défaut les objets Git LFS pour les fichiers uniquement s'ils sont présents dans l'index Git et s'ils correspondent à un attribut de filtre Git LFS d'un fichier .gitattributes présent dans l'index ou dans l'arbre de travail actuel (ou, comme c'est toujours le cas, s'ils correspondent à un attribut de filtre Git LFS dans un fichier gitattributes local tel que $GIT_DIR/info/attributes). Ces contraintes ne s'appliquent pas aux versions antérieures de Git.

Dans un dépôt avec un clonage partiel ou un checkout dispersé, il est donc conseillé de sélectionner tous les fichiers .gitattributes depuis HEAD avant d'utiliser cette commande, si Git v2.42.0 ou une version ultérieure est installé. Alternativement, la variable d'environnement GIT_ATTR_SOURCE peut être définie sur HEAD, ce qui amènera Git à ne lire les attributs que des fichiers .gitattributes dans HEAD et à ignorer ceux de l'index ou de l'arbre de travail.

Dans un dépôt vide, si la version de Git installée est au moins 2.42.0, cette commande télécharge par défaut les objets Git LFS pour les fichiers uniquement s'ils sont présents dans l'index Git et s'ils correspondent à un attribut de filtre Git LFS d'un fichier gitattributes local tel que $GIT_DIR/info/attributes. Tous les fichiers HEAD seront ignorés, à moins que la variable d'environnement GIT_ATTR_SOURCE ne soit définie sur HEAD, et tous les fichiers .gitattributes dans l'index ou l'arbre de travail actuel seront toujours ignorés. Ces contraintes ne s'appliquent pas aux versions antérieures de Git.

OPTIONS

-I <chemins>, --include=<chemins>

Spécifie lfs.fetchinclude uniquement pour cette invocation ; voir INCLUDE ET EXCLUDE

-X <chemins>, --exclude=<chemins>

Spécifie lfs.fetchexclude uniquement pour cette invocation ; voir INCLUDE ET EXCLUDE

INCLURE ET EXCLURE

Vous pouvez configurer Git LFS pour ne télécharger les objets que pour satisfaire les références dans certains chemins du dépôt, et/ou pour exclure certains chemins du dépôt, afin de réduire le temps passé à télécharger des choses que vous n'utilisez pas.

Dans votre configuration Git ou dans un fichier .lfsconfig, vous pouvez définir l'un ou les deux de lfs.fetchinclude et lfs.fetchexclude avec des listes de chemins séparés par des virgules. Si lfs.fetchinclude est défini, les objets Git LFS ne seront téléchargés que si leur chemin correspond à l'un de ceux de cette liste, et si lfs.fetchexclude est défini, les objets Git LFS ne seront téléchargés que si leur chemin ne correspond pas à l'un de ceux de cette liste. Les chemins sont comparés à l'aide de la correspondance de caractères génériques comme spécifié dans gitignore(5).

Notez que l'utilisation des options de ligne de commande -I et -X remplace les paramètres de configuration respectifs. Définir l'une des options sur une chaîne vide efface la valeur.

REMOTE PAR DÉFAUT

Sans arguments, pull télécharge depuis le remote par défaut. Le remote par défaut est le même que pour git pull, c'est-à-dire basé sur la branche distante que vous suivez en premier lieu, ou origin sinon.

VOIR AUSSI

git-lfs-fetch(1), git-lfs-checkout(1), gitattributes(5), gitignore(5).

Fait partie de la suite git-lfs(1).
