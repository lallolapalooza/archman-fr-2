NOM

git-backfill - Télécharger les objets manquants dans un clone partiel

SYNOPSIS

git backfill [--min-batch-size=<n>] [--[no-]sparse]

DESCRIPTION

Les clones partiels sans blob (blobless) sont créés en utilisant git clone --filter=blob:none, puis le dépôt local est configuré de manière à ce que le client Git évite de télécharger les objets blob sauf s'ils sont requis pour une opération locale. Cela signifie initialement que le clone et les fetches ultérieurs téléchargent les commits et les arbres atteignables, mais aucun blob. Les opérations ultérieures qui modifient le pointeur HEAD, telles que git checkout ou git merge, peuvent nécessiter le téléchargement de blobs manquants pour compléter leur opération.

Dans le pire des cas, les commandes qui calculent les différences de blobs, comme git blame, deviennent très lentes car elles téléchargent les blobs manquants en requêtes d'un seul blob pour satisfaire l'objet manquant au fur et à mesure que la commande Git en a besoin. Cela entraîne de multiples requêtes de téléchargement et aucune capacité pour le serveur Git de fournir une compression delta entre ces objets.

La commande git backfill offre un moyen à l'utilisateur de demander à Git de télécharger les blobs manquants (avec des filtres optionnels) de sorte que les blobs manquants représentant des versions historiques des fichiers puissent être téléchargés par lots. La commande backfill tente d'optimiser la requête en regroupant les blobs qui apparaissent au même chemin, conduisant idéalement à une bonne compression delta dans le fichier pack envoyé par le serveur.

De cette manière, git backfill fournit un mécanisme pour diviser un gros clone en plus petits morceaux. En commençant par un clone partiel sans blob avec git clone --filter=blob:none, puis en exécutant git backfill dans le dépôt local, on obtient un moyen de télécharger tous les objets atteignables en plusieurs appels réseau plus petits que le téléchargement du dépôt entier au moment du clone.

Par défaut, git backfill télécharge tous les blobs atteignables depuis le commit HEAD. Cet ensemble peut être restreint ou élargi à l'aide de diverses options.

CETTE COMMANDE EST EXPÉRIMENTALE. SON COMPORTEMENT PEUT CHANGER À L'AVENIR.

OPTIONS

--min-batch-size=<n>

Spécifie une taille minimale pour un lot d'objets manquants à demander au serveur. Cette taille peut être dépassée par le dernier ensemble de blobs vus à un chemin donné. La taille minimale par défaut des lots est de 50 000.

--sparse, --no-sparse

Ne télécharge les objets que s'ils apparaissent à un chemin correspondant au sparse-checkout actuel. Si la fonctionnalité de sparse-checkout est activée, alors --sparse est supposé et peut être désactivé avec --no-sparse.
