DESCRIPTIO

N

Ce programme fait partie de Netpbm(1

)

Il s'agit d'un convertisseur de format graphique du format GIF vers le format PNM (c'est-à-dire PBM, PGM ou PPM)

.

Si l'image ne contient que du noir et du blanc de luminosité maximale, la sortie est PBM. Si l'image contient plus que ces deux couleurs, mais uniquement des gris, la sortie est PGM. Si l'image contient d'autres couleurs, la sortie est

PPM.


Une image GIF contient des pixels rectangulaires. Ils ont tous le même rapport d'aspect, mais peuvent ne pas être carrés (c'est en fait assez inhabituel qu'ils ne soient pas carrés, mais cela pourrait arriver). Les pixels d'une image Netpbm sont toujours carrés. En raison de la complexité technique pour faire autrement, giftopnm convertit une image GIF en image Netpbm pixel par pixel. Cela signifie que si les pixels GIF ne sont pas carrés, l'image de sortie Netpbm a le mauvais rapport d'aspect. Dans ce cas, giftopnm émet un message informatif vous indiquant d'exécuter pamscale pour co

rriger la
sortie.

--alphaout=nom-de-fichier-a

giftopnm crée un fichier PBM contenant les informations de transparence de l'image d'entrée. Cette « image alpha » a les mêmes dimensions que l'image d'entrée, et chaque pixel de l'image alpha indique si le pixel correspondant de l'image d'entrée est transparent. Noir signifie transparent ; blanc signifie opaque. Si vous ne spécifiez pas --alphaout, giftopnm ne génère pas de fichier alpha, et si l'image d'entrée a un canal alpha, giftopnm le supprime simplement.

Cette option identifie quelle image du flux GIF vous souhaitez. Vous pouvez sélectionner soit une image, soit toutes les images. Sélectionnez toutes les images avec all. Sélectionnez une image en spécifiant son numéro de séquence dans le flux : 1, 2, 3, etc.

Un flux GIF ne contient normalement qu'une seule image, donc vous n'avez pas besoin de cette option. Mais certains flux, y compris les GIF animés, ont plusieurs

images.

Lorsque vous sélectionnez plusieurs images GIF, la sortie est un flux PNM avec plusieurs

Si vous spécifiez une seule image, giftopnm doit lire et valider partiellement les images précédentes dans le flux. Il peut ou non faire de même pour les images suivantes ; voir -quitear

-repa
ir
Cette option fait giftopnm essayer de sauver ce qu'il peut d'une entrée GIF invalide.

En particulier, lorsque giftopnm détecte que l'entrée GIF est invalide de telle manière qu'il est impossible de déterminer ce que les pixels sont censés être, il produit une seule couleur arbitraire pour tous les pixels restants de l'image. giftopnm traite l'image de haut en bas, de gauche à droite, ce qui signifie que les pixels les plus bas seront ce

remplissage.

giftopnm émet des messages d'avertissement lorsqu'il sauve une image de cette

manière.

Sans cette option, giftopnm échoue lorsqu'il détecte une entrée GIF invalide. Toute sortie qu'il produit est arbitraire et n'est généralement pas une image PNM

valide.

Il est assez courant qu'une image soit corrompue de telle manière qu'elle ait commencé comme un GIF valide, mais que la fin du fichier ait été coupée. Un transfert réseau interrompu a tendance à faire cela. Dans ce cas, l'opération de récupération de giftopnm produira une image PNM valide des dimensions appropriées, mais avec une seule couleur arbitraire pour les pixels qui ont été omis du

fichier.

Cette option a été introduite dans Netpbm 10.38 (mars 2007). De 10.32 à 10.37, giftopnm échoue toujours s'il détecte une entrée GIF invalide. Avant 10.32, il réussissait dans le cas d'une image tronquée et remplaçait les pixels manquants par des couleurs arbitraires, pas nécessairement toutes identiques (Le comportement d'avant 10.32 n'était pas réellement prévu par la

conception)

Unisys demandait généralement 5000 $ pour une licence pour un usage trivial du brevet.
