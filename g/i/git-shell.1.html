NOM

git-shell - Shell de connexion restreint pour l'accès SSH Git uniquement

SYNOPSIS

chsh -s $(command -v git-shell) <utilisateur>
git clone <utilisateur>@localhost:/chemin/vers/repo.git
ssh <utilisateur>@localhost

DESCRIPTION

Ceci est un shell de connexion pour les comptes SSH afin de fournir un accès Git restreint. Il autorise l'exécution uniquement des commandes Git côté serveur qui implémentent la fonctionnalité de récupération/push, ainsi que des commandes personnalisées présentes dans un sous-répertoire nommé git-shell-commands dans le répertoire personnel de l'utilisateur.

COMMANDES

git shell accepte les commandes suivantes après l'option -c :

git receive-pack <argument>, git upload-pack <argument>, git upload-archive <argument>

Appelle la commande côté serveur correspondante pour prendre en charge la requête git push, git fetch, ou git archive --remote du client.

cvs server

Imite un serveur CVS. Voir git-cvsserver(1).

Si un répertoire ~/git-shell-commands est présent, git shell gérera également d'autres commandes personnalisées en exécutant "git-shell-commands/<commande> <arguments>" depuis le répertoire personnel de l'utilisateur.

UTILISATION INTERACTIVE

Par défaut, les commandes ci-dessus ne peuvent être exécutées qu'avec l'option -c ; le shell n'est pas interactif.

Si un répertoire ~/git-shell-commands est présent, git shell peut également être exécuté de manière interactive (sans arguments). Si une commande help est présente dans le répertoire git-shell-commands, elle est exécutée pour fournir à l'utilisateur un aperçu des actions autorisées. Ensuite, une invite "git> " est présentée où l'on peut entrer n'importe laquelle des commandes du répertoire git-shell-commands, ou exit pour fermer la connexion.

En général, ce mode est utilisé comme une interface administrative pour permettre aux utilisateurs de lister les dépôts auxquels ils ont accès, de créer, supprimer ou renommer des dépôts, ou de modifier les descriptions et les permissions des dépôts.

Si une commande no-interactive-login existe, elle est exécutée et le shell interactif est abandonné.

EXEMPLES

Pour désactiver les connexions interactives, affichant un message de bienvenue à la place :

$ chsh -s /usr/bin/git-shell
$ mkdir $HOME/git-shell-commands
$ cat >$HOME/git-shell-commands/no-interactive-login <<\EOF
#!/bin/sh
printf '%s\n' "Salut $USER ! Vous vous êtes authentifié avec succès, mais je ne"
printf '%s\n' "fournis pas d'accès interactif au shell."
exit 128
EOF
$ chmod +x $HOME/git-shell-commands/no-interactive-login

Pour activer l'accès à git-cvsserver (qui devrait généralement avoir l'exemple no-interactive-login ci-dessus comme prérequis, car la création du répertoire git-shell-commands autorise les connexions interactives) :

$ cat >$HOME/git-shell-commands/cvs <<\EOF
if ! test $# = 1 && test "$1" = "server"
then
        echo >&2 "git-cvsserver ne gère que \"server\""
        exit 1
fi
exec git cvsserver server
EOF
$ chmod +x $HOME/git-shell-commands/cvs
