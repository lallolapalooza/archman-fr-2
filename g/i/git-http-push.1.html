NOM

git-http-push - Pousse les objets via HTTP/DAV vers un autre dépôt

SYNOPIS

git http-push [--all] [--dry-run] [--force] [--verbose] <URL> <ref> [<ref>...]

DESCRIPTION

Envoie les objets manquants au dépôt distant, et met à jour la branche distante.

NOTE : Cette commande est temporairement désactivée si votre libcurl est plus ancienne que 7.16, car la combinaison a été rapportée comme ne fonctionnant pas et corrompant parfois le dépôt.

OPTIONS

--all

Ne suppose pas que le dépôt distant est complet dans son état actuel, et vérifie que tous les objets de l'historique de la référence locale existent dans le dépôt distant.

--force

Normalement, la commande refuse de mettre à jour une référence distante qui n'est pas un ancêtre de la référence locale utilisée pour la remplacer. Ce drapeau désactive la vérification. Cela signifie que le dépôt distant peut perdre des commits ; utilisez-le avec précaution.

--dry-run

Fait tout sauf envoyer réellement les mises à jour.

--verbose

Rapporte la liste des objets parcourus localement et la liste des objets envoyés avec succès au dépôt distant.

-d, -D

Supprime <ref> du dépôt distant. La branche spécifiée ne peut pas être le HEAD distant. Si -d est spécifié, les autres conditions suivantes doivent également être remplies :
•Le HEAD distant doit se résoudre en un objet qui existe localement
•La branche spécifiée doit se résoudre en un objet qui existe localement
•La branche spécifiée doit être un ancêtre du HEAD distant

<ref>...

Les références distantes à mettre à jour.

SPÉCIFICATION DES REFS

Une spécification de <ref> peut être soit un modèle unique, soit une paire de tels modèles séparés par deux-points ":" (ce qui signifie qu'un nom de référence ne peut pas contenir de deux-points). Un modèle unique <name> est simplement un raccourci pour <name>:<name>.

Chaque paire de modèles <src>:<dst> est composée du côté source (avant les deux-points) et du côté destination (après les deux-points). La référence à pousser est déterminée en trouvant une correspondance avec le côté source, et où elle est poussée est déterminée en utilisant le côté destination.

•C'est une erreur si <src> ne correspond exactement à aucune des références locales.
•Si <dst> ne correspond à aucune référence distante, soit
•il doit commencer par "refs/" ; <dst> est utilisé littéralement comme destination dans ce cas.
•<src> == <dst> et la référence qui correspond à <src> n'existe pas dans l'ensemble des références distantes ; la référence correspondant à <src> localement est utilisée comme nom de la destination.

Sans ‘--force`, la référence <src> est stockée à distance uniquement si <dst> n'existe pas, ou si <dst> est un sous-ensemble propre (c'est-à-dire un ancêtre) de <src>. Cette vérification, connue sous le nom de "vérification de fast-forward", est effectuée pour éviter d'écraser accidentellement la référence distante et de perdre les commits des autres utilisateurs.

Avec --force, la vérification de fast-forward est désactivée pour toutes les références.

Optionnellement, un paramètre <ref> peut être précédé d'un signe plus + pour désactiver la vérification de fast-forward uniquement sur cette référence.
