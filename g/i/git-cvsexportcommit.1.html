NOM

git-cvsexportcommit - Exporter un commit unique vers une copie de travail CVS

SYNTAXE

git cvsexportcommit [-h] [-u] [-v] [-c] [-P] [-p] [-a] [-d <cvsroot>]
        [-w <cvs-workdir>] [-W] [-f] [-m <msgprefix>] [<parent-commit>] <commit-id>

DESCRIPTION

Exporte un commit de Git vers une copie de travail CVS, facilitant ainsi la fusion de correctifs à partir d'un dépôt Git vers un dépôt CVS.

Spécifiez le nom d'une copie de travail CVS en utilisant l'option -w ou exécutez-le depuis la racine de la copie de travail CVS. Dans ce dernier cas, GIT_DIR doit être défini. Voir les exemples ci-dessous.

Il fait de son mieux pour agir prudemment, il vérifiera que les fichiers sont inchangés et à jour dans la copie de travail CVS, et il ne commitera pas automatiquement par défaut.

Prend en charge l'ajout, la suppression de fichiers et les commits qui affectent les fichiers binaires.

Si le commit est un commit de fusion, vous devez indiquer à git cvsexportcommit avec quel parent la modification doit être effectuée.

OPTIONS

-c

Commiter automatiquement si le correctif s'est appliqué proprement. Il ne committera pas si des blocs échouent à s'appliquer ou s'il y a eu d'autres problèmes.

-p

Être pédant (paranoïaque) lors de l'application des correctifs. Invoque patch avec --fuzz=0

-a

Ajouter les informations d'auteur. Ajoute la ligne Auteur et Commiteur (si différent de l'Auteur) au message.

-d

Définir un autre CVSROOT à utiliser. Ceci correspond au paramètre -d de CVS. Généralement, les utilisateurs ne voudront pas le définir, sauf s'ils utilisent CVS de manière asymétrique.

-f

Forcer la fusion même si les fichiers ne sont pas à jour.

-P

Forcer le commit parent, même s'il n'est pas un parent direct.

-m

Précéder le message de commit du préfixe fourni. Utile pour les séries de correctifs et similaires.

-u

Mettre à jour les fichiers affectés depuis le dépôt CVS avant de tenter l'exportation.

-k

Inverser l'expansion des mots-clés CVS (par exemple, $Revision: 1.2.3.4$ devient $Revision$) dans la copie de travail CVS avant d'appliquer le correctif.

-w

Spécifier l'emplacement de la copie de travail CVS à utiliser pour l'exportation. Cette option ne nécessite pas que GIT_DIR soit défini avant l'exécution si le répertoire courant se trouve dans un dépôt Git. La valeur par défaut est la valeur de cvsexportcommit.cvsdir.

-W

Indiquer à cvsexportcommit que le répertoire de travail courant n'est pas seulement un clone Git, mais aussi le clone CVS. Par conséquent, Git réinitialisera le répertoire de travail au commit parent avant de continuer.

-v

Verbeux.

CONFIGURATION

cvsexportcommit.cvsdir

L'emplacement par défaut de la copie de travail CVS à utiliser pour l'exportation.

EXEMPLES

Fusionner un correctif dans CVS

$ export GIT_DIR=~/projet/.git
$ cd ~/copie_travail_cvs
$ git cvsexportcommit -v <commit-sha1>
$ cvs commit -F .msg <fichiers>

Fusionner un correctif dans CVS (options -c et -w). Le répertoire de travail est dans le dépôt Git

        $ git cvsexportcommit -v -c -w ~/copie_travail_cvs <commit-sha1>

Fusionner les correctifs en attente dans CVS automatiquement — seulement si vous savez vraiment ce que vous faites

$ export GIT_DIR=~/projet/.git
$ cd ~/copie_travail_cvs
$ git cherry cvshead myhead | sed -n 's/^+ //p' | xargs -l1 git cvsexportcommit -c -p -v
