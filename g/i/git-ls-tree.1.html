NOM

git-ls-tree - Lister le contenu d'un objet arbre

SYNOPIS

git ls-tree [-d] [-r] [-t] [-l] [-z]
            [--name-only] [--name-status] [--object-only] [--full-name] [--full-tree] [--abbrev[=<n>]] [--format=<format>]
            <tree-ish> [<chemin>...]

DESCRIPTION

Liste le contenu d'un objet arbre donné, comme le fait "/bin/ls -a" dans le répertoire de travail courant. Notez que :

• le comportement est légèrement différent de celui de "/bin/ls" en ce que <chemin> désigne juste une liste de motifs à faire correspondre, par exemple spécifier un nom de répertoire (sans -r) aura un comportement différent, et l'ordre des arguments n'a pas d'importance.
• le comportement est similaire à celui de "/bin/ls" en ce que <chemin> est pris comme étant relatif au répertoire de travail courant. Par exemple, lorsque vous êtes dans un répertoire sous-rep qui contient un répertoire rep, vous pouvez exécuter git ls-tree -r HEAD rep pour lister le contenu de l'arbre (qui est sous-rep/rep dans HEAD). Vous ne voudrez pas donner un arbre qui n'est pas à la racine (par exemple, git ls-tree -r HEAD:sous-rep rep) dans ce cas, car cela reviendrait à demander sous-rep/sous-rep/rep dans le commit HEAD. Cependant, le répertoire de travail courant peut être ignoré en passant l'option --full-tree.

OPTIONS

<tree-ish>

Identifiant d'un objet arbre.

-d

N'afficher que l'entrée d'arbre nommée elle-même, pas ses enfants.

-r

Parcourir récursivement les sous-arbres.

-t

Afficher les entrées d'arbre même lorsqu'on les parcourt récursivement. N'a aucun effet si -r n'a pas été passé. -d implique -t.

-l, --long

Afficher la taille de l'objet des entrées blob (fichier).

-z

Terminer les lignes de sortie par un caractère NUL et ne pas guillemeter les noms de fichiers. Voir FORMAT DE SORTIE ci-dessous pour plus d'informations.

--name-only, --name-status

N'afficher que les noms de fichiers (au lieu de la sortie "longue"), un par ligne. Ne peut pas être combiné avec --object-only.

--object-only

N'afficher que les noms des objets, un par ligne. Ne peut pas être combiné avec --name-only ou --name-status. Ceci est équivalent à spécifier --format='%(objectname)', mais pour cette option et ce format exact, la commande utilise un chemin de code optimisé plutôt que le mécanisme de formatage générique.

--abbrev[=<n>]

Au lieu d'afficher les lignes complètes de 40 caractères hexadécimaux de l'objet, afficher le préfixe le plus court d'au moins <n> chiffres hexadécimaux qui identifie de manière unique l'objet. Un nombre de chiffres non par défaut peut être spécifié avec --abbrev=<n>.

--full-name

Au lieu d'afficher les noms de chemins relatifs au répertoire de travail courant, afficher les noms de chemins complets.

--full-tree

Ne pas limiter la liste au répertoire de travail courant. Implique --full-name.

--format=<format>

Une chaîne qui interpole %(nom-de-champ) à partir du résultat affiché. Elle interpole également %% en %, et %xNN où NN sont des chiffres hexadécimaux s'interpole en caractère avec le code hexadécimal NN ; par exemple %x00 s'interpole en \0 (NUL), %x09 en \t (TAB) et %x0a en \n (LF). Lorsqu'il est spécifié, --format ne peut pas être combiné avec d'autres options modifiant le format, y compris --long, --name-only et --object-only.

[<chemin>...]

Lorsque des chemins sont donnés, les afficher (notez que ce ne sont pas vraiment des noms de chemins bruts, mais plutôt une liste de motifs à faire correspondre). Sinon, utilise implicitement la racine de l'arbre comme unique argument de chemin.

FORMAT DE SORTIE

Le format de sortie de ls-tree est déterminé soit par l'option --format, soit par d'autres options modifiant le format comme --name-only etc. (voir --format ci-dessus).

L'utilisation de certaines directives --format est équivalente à l'utilisation de ces options, mais l'invocation de la machinerie de formatage complète peut être plus lente que l'utilisation d'une option de formatage appropriée.

Dans les cas où --format correspondrait exactement à une option existante, ls-tree utilisera un chemin plus rapide approprié. Ainsi, le format par défaut est équivalent à :

%(objectmode) %(objecttype) %(objectname)%x09%(path)

Ce format de sortie est compatible avec ce qu'attend --index-info --stdin de git update-index.

Lorsque l'option -l est utilisée, le format devient

%(objectmode) %(objecttype) %(objectname) %(objectsize:padded)%x09%(path)

La taille de l'objet identifiée par <objectname> est donnée en octets, et justifiée à droite avec une largeur minimale de 7 caractères. La taille de l'objet n'est donnée que pour les entrées blob (fichier) ; pour les autres entrées, le caractère - est utilisé à la place de la taille.

Sans l'option -z, les noms de chemins avec des caractères "inhabituels" sont mis entre guillemets comme expliqué pour la variable de configuration core.quotePath (voir git-config(1)). En utilisant -z, le nom de fichier est affiché tel quel et la ligne est terminée par un octet NUL.

Format personnalisé :

Il est possible d'afficher dans un format personnalisé en utilisant l'option --format, qui peut interpoler différents champs à l'aide d'une notation %(nom-de-champ). Par exemple, si vous ne vous souciez que des champs "objectname" et "path", vous pouvez exécuter avec un "--format" spécifique comme

git ls-tree --format='%(objectname) %(path)' <tree-ish>

NOMS DE CHAMPS

Diverses valeurs provenant de champs structurés peuvent être utilisées pour l'interpolation dans la sortie résultante. Pour chaque ligne de sortie, les noms suivants peuvent être utilisés :

objectmode

Le mode de l'objet.

objecttype

Le type de l'objet (commit, blob ou tree).

objectname

Le nom de l'objet.

objectsize[:padded]

La taille d'un objet blob ("-" si c'est un commit ou tree). Il supporte également un format de taille rembourrée avec "%(objectsize:padded)".

path

Le nom du chemin de l'objet.
