Paquet: git

GIT-SHOW-BRANCH(1) Manuel Git GIT-SHOW-BRANCH(1)

NOM

git-show-branch - Afficher les branches et leurs commits

SYNTAXE

git show-branch [-a | --all] [-r | --remotes] [--topo-order | --date-order]
                [--current] [--color[=<when>] | --no-color] [--sparse]
                [--more=<n> | --list | --independent | --merge-base]
                [--no-name | --sha1-name] [--topics]
                [(<rev> | <glob>)...]
git show-branch (-g | --reflog)[=<n>[,<base>]] [--list] [<ref>]

DESCRIPTION

Affiche le graphe d'ascendance des commits en partant des commits nommés avec <rev> ou <glob> (ou toutes les références sous refs/heads et/ou refs/tags) de manière semi-visuelle.

Il ne peut pas afficher plus de 26 branches et commits à la fois.

Il utilise les éléments de configuration multi-valeurs showbranch.default si aucun <rev> ou <glob> n'est donné en ligne de commande.

OPTIONS

<rev>

Expression SHA-1 étendue arbitraire (voir gitrevisions(7)) qui nomme généralement une tête de branche ou une étiquette.

<glob>

Un modèle de caractère générique qui correspond aux noms de branches ou d'étiquettes sous refs/. Par exemple, si vous avez de nombreuses branches thématiques sous refs/heads/topic, donner topic/* les affichera toutes.

-r, --remotes

Affiche les branches de suivi à distance.

-a, --all

Affiche à la fois les branches de suivi à distance et les branches locales.

--current

Avec cette option, la commande inclut la branche actuelle dans la liste des revues à afficher lorsqu'elle n'est pas donnée en ligne de commande.

--topo-order

Par défaut, les branches et leurs commits sont affichés dans un ordre chronologique inverse. Cette option les fait apparaître dans un ordre topologique (c'est-à-dire que les commits descendants sont affichés avant leurs parents).

--date-order

Cette option est similaire à --topo-order dans le sens où aucun parent ne vient avant tous ses enfants, mais sinon les commits sont ordonnés selon leur date de commit.

--sparse

Par défaut, la sortie omet les fusions qui ne sont accessibles que depuis une seule pointeur affichée. Cette option les rend visibles.

--more=<n>

Habituellement, la commande arrête la sortie en affichant le commit qui est l'ancêtre commun de toutes les branches. Ce drapeau indique à la commande d'aller <n> commits communs supplémentaires au-delà de celui-ci. Lorsque <n> est négatif, n'affiche que les <ref> données, sans afficher l'arbre d'ascendance des commits.

--list

Synonyme de --more=-1

--merge-base

Au lieu d'afficher la liste des commits, détermine les bases de fusion possibles pour les commits spécifiés. Toutes les bases de fusion seront contenues dans tous les commits spécifiés. Ceci est différent de la façon dont git-merge-base(1) gère le cas de trois commits ou plus.

--independent

Parmi les <ref> données, affiche seulement celles qui ne sont accessibles depuis aucune autre <ref>.

--no-name

N'affiche pas les chaînes de noms pour chaque commit.

--sha1-name

Au lieu de nommer les commits en utilisant le chemin pour les atteindre depuis les têtes (par exemple, "master~2" pour signifier le grand-parent de "master"), les nomme avec le préfixe unique de leurs identifiants d'objet.

--topics

N'affiche que les commits qui ne sont PAS sur la première branche donnée. Ceci aide à suivre les branches thématiques en masquant tout commit qui est déjà dans la ligne principale de développement. Lorsqu'il est donné "git show-branch --topics master topic1 topic2", cela affichera les révisions données par "git rev-list ^master topic1 topic2"

-g, --reflog[=<n>[,<base>]] [<ref>]

Affiche les <n> entrées les plus récentes du reflog pour la référence donnée. Si <base> est donné, <n> entrées remontant à partir de cette entrée. <base> peut être spécifié comme un compte ou une date. Lorsqu'aucun paramètre explicite <ref> n'est donné, il prend par défaut la branche actuelle (ou HEAD si elle est détachée).

--color[=<when>]

Colore le signe de statut (l'un de ceux-ci : * ! + -) de chaque commit correspondant à la branche dont il fait partie. La valeur doit être always (par défaut), never, ou auto.

--no-color

Désactive la sortie colorée, même lorsque le fichier de configuration donne la couleur par défaut. Identique à --color=never.

Notez que les options --more, --list, --independent et --merge-base sont mutuellement exclusives.

SORTIE

Étant donné N <ref>, les N premières lignes sont la description en une ligne de leur message de commit. La tête de branche pointée par $GIT_DIR/HEAD est précédée d'un astérisque *, tandis que les autres têtes sont précédées d'un signe !.

Suite à ces N lignes, un journal en une ligne pour chaque commit est affiché, indenté de N espaces. Si un commit est sur la I-ème branche, le I-ème caractère d'indentation affiche un signe + ; sinon, il affiche un espace. Les commits de fusion sont indiqués par un signe -. Chaque commit affiche un nom court qui peut être utilisé comme un SHA-1 étendu pour nommer ce commit.

L'exemple suivant montre trois branches, "master", "fixes" et "mhf" :

$ git show-branch master fixes mhf
* [master] Add 'git show-branch'.
 ! [fixes] Introduce "reset type" flag to "git reset"
  ! [mhf] Allow "+remote:local" refspec to cause --force when fetching.
---
  + [mhf] Allow "+remote:local" refspec to cause --force when fetching.
  + [mhf~1] Use git-octopus when pulling more than one head.
 +  [fixes] Introduce "reset type" flag to "git reset"
  + [mhf~2] "git fetch --force".
  + [mhf~3] Use .git/remote/origin, not .git/branches/origin.
  + [mhf~4] Make "git pull" and "git fetch" default to origin
  + [mhf~5] Infamous 'octopus merge'
  + [mhf~6] Retire git-parse-remote.
  + [mhf~7] Multi-head fetch.
  + [mhf~8] Start adding the $GIT_DIR/remotes/ support.
*++ [master] Add 'git show-branch'.

Ces trois branches ont toutes divergé d'un commit commun, [master], dont le message de commit est "Add 'git show-branch'". La branche "fixes" ajoute un commit "Introduce "reset type" flag to "git reset"". La branche "mhf" ajoute de nombreux autres commits. La branche actuelle est "master".

EXEMPLES

Si vous conservez vos branches principales directement sous refs/heads, et les branches thématiques dans des sous-répertoires de celui-ci, avoir ce qui suit dans le fichier de configuration peut aider :

[showbranch]
        default = --topo-order
        default = heads/*

Avec cela, git show-branch sans paramètres supplémentaires afficherait uniquement les branches principales. De plus, si vous vous trouvez sur votre branche thématique, elle est également affichée.

$ git show-branch --reflog="10,1 hour ago" --list master

affiche 10 entrées du reflog remontant à partir de la pointe d'il y a 1 heure. Sans --list, la sortie montre également comment ces pointes sont liées topologiquement entre elles.

CONFIGURATION

Tout ce qui suit cette ligne dans cette section est inclus sélectivement depuis la documentation de git-config(1). Le contenu est le même que ce qui s'y trouve :

showBranch.default

L'ensemble par défaut de branches pour git-show-branch(1). Voir git-show-branch(1).
