git-annex-import - imp

uis un distant spécial

SYNOPSI

S

git annex import --from distant branche[:sous-répertoire] | [chemin ..

.
]

DESCRIPTIO

N

Cette commande est un moyen d'importer une arborescence de fichiers

d'un autre endroit vers votre dépôt git-annex. Elle peut importer des fi
chiers depuis un distant spécial git-annex, ou depuis un répertoire.

IMPORTATION DEPUIS UN DISTANT

SPÉCIAL

L'importation depuis un distant spécial télécharge d'abord ou hache tout le nouveau contenu, puis construit un commit git qui reflète les fichiers ayant changé sur le distant spécial depuis la dernière fois où git-annex l'a consulté. Fusionner ce commit dans votre dépôt le mettra à jour pour refléter les changements effectués sur le distant

spécial.

De cette façon, quelque chose peut utiliser le distant spécial pour le stockage de fichiers, en ajoutant des fichiers, en modifiant des fichiers et en supprimant des fichiers, et vous pouvez suivre ces changements à l'aide de

git-annex.

Vous pouvez combiner l'utilisation de git annex import pour récupérer les changements depuis un distant spécial avec git annex export pour envoyer vos changements locaux vers le distant

spécial.

Vous ne pouvez importer que depuis des distants spéciaux qui ont été configurés avec importtree=yes lors de leur configuration avec git-annex-initremote(1). Seuls certains types de distants spéciaux vous permettent de les configurer de cette manière. Une liste peut-être non exhaustive est les distants spéciaux directory, s3 et

adb.

Pour importer depuis un distant spécial, vous devez spécifier le nom d'une branche. Une branche de suivi de distant correspondante sera mise à jour par git annex import. Après cela, c'est comme si vous aviez exécuté un git fetch depuis un distant git régulier ; vous pouvez fusionner les changements dans votre branche actuellement

cochée.

Par exemple

:


git annex import master --from myremote
git annex merge --allow-unrelated-histories

myremote/master

Vous pourriez tout aussi bien utiliser git merge --allow-unrelated-histories myremote/master comme deuxième étape, mais l'utilisation de git-annex merge évite quelques pièges. Lors de l'utilisation de branches ajustées, il ajuste la branche avant de fusionner depuis

celle-ci.

L'option --allow-unrelated-histories est nécessaire pour au moins la première fusion d'une branche de suivi de distant importée, car l'historique de la branche n'est pas connecté. Considérez cela comme si le distant était un dépôt git séparé avec ses propres fichiers. Si vous d'abord git annex export des fichiers vers un distant, puis git annex import depuis celui-ci, vous n'aurez pas besoin de cette

option.

Vous pouvez importer dans un sous-répertoire, en utilisant la syntaxe "branche:sous-répertoire". Par exemple, si "camera" est un distant spécial qui accède à un appareil photo, et que vous voulez importer ceux-ci dans le répertoire photos, plutôt qu'à la racine de votre dépôt

:


git annex import master:photos --from camera
git merge

camera/master

La commande git annex sync --content (et l'assistant git-annex) peut aussi être utilisée pour importer depuis un distant spécial. Pour cela, vous devez configurer "remote.<nom>.annex-tracking-branch" pour lui indiquer quelle branche suivre. Par exemple

:


git config remote.myremote.annex-tracking-branch master
git annex sync

--content

Tout fichier ignoré par git ne sera pas inclus dans l'importation, mais restera sur le

distant.

Lorsque le distant spécial a une expression de contenu préféré définie par git-annex-wanted(1), celle-ci est utilisée pour choisir quels fichiers importer depuis celui-ci. Les fichiers qui ne sont pas le contenu préféré du distant ne seront pas importés depuis celui-ci, mais resteront sur le

distant.

Ainsi, par exemple, une expression de contenu préféré comme "include=*.jpeg or largerthan=100mb" ne fera importer que les jpegs et les gros

fichiers.

Les parties d'une expression de contenu préféré qui se rapportent à la clé, comme "copies=", sont ignorées lors de l'importation, car la clé n'est pas connue avant

l'importation.

Les éléments de l'expression comme "include=" correspondent par rapport à la racine de l'arborescence de fichiers sur le distant, même lors de l'importation dans un

sous-répertoire
.

IMPORTATION DEPUIS UN

RÉPERTOIRE

Lorsqu'elle est exécutée avec un chemin, git annex import **déplace** les fichiers depuis un endroit en dehors de la copie de travail git, et les ajoute à l'annexe. Contrairement à l'importation depuis un distant spécial directory, les fichiers importés sont **supprimés du chemin

donné**.

Ceci est une interface héritée. Elle est toujours prise en charge, mais veuillez envisager de passer à l'importation depuis un distant spécial directory à la place, en utilisant l'interface documentée

ci-dessus.

Les fichiers individuels à importer peuvent être spécifiés. Si un répertoire est spécifié, l'ensemble du répertoire est importé. Veuillez noter que l'instruction suivante **supprimera tous les fichiers du répertoire

source**.


git annex import /media/camera/DCIM/

*

Lors de l'importation de fichiers, il y a une possibilité d'importer un doublon d'un fichier déjà connu de git-annex -- son contenu est soit déjà présent dans le dépôt local, soit git-annex connaît un autre dépôt qui le contient, soit il était présent dans l'annexe avant mais a été supprimé

maintenant.

Par défaut, l'importation d'un doublon d'un fichier connu entraînera l'ajout d'un nouveau nom de fichier au dépôt, de sorte que le fichier en double est présent dans le dépôt deux fois. (Avec tous les backends de somme de contrôle, y compris le SHA256E par défaut, une seule copie des données sera stockée.

)

Plusieurs options peuvent être utilisées pour ajuster le traitement des fichiers en double, voir --duplicate, --deduplicate, --skip-duplicates, --clean-duplicates et --reinject-duplicates documentation

ci-dessous.

les liens symboliques dans le répertoire importé sont ignorés pour éviter d'importer accidentellement de

s choses en dehors du répertoire sur lequel l'importation a été exécutée. Le répertoire sur lequel l'imp
ortation est exécutée peut cependant être lui-même un lien symbolique, et ce lien symbolique sera suivi.
