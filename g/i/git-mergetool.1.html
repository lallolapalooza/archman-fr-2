e résolution de conflits de fusion
pour résoudre les conflits de fusion

SYNOPSI

S 
git mergetool [--tool=<tool>] [-y | --[no-]prompt] [<file>..
.
]

DESCRIPTIO

N

Utilisez git mergetool pour exécuter l'un des plusieurs utilitaires de fusion afin de résoudre les conflits de fusion. Il est généralement exécuté après git merge

.

Si un ou plusieurs paramètres <file> sont fournis, le programme de fusion sera exécuté pour résoudre les différences dans chaque fichier (en ignorant ceux sans conflit). Spécifier un répertoire inclura tous les fichiers non résolus dans ce chemin. Si aucun nom de <file> n'est spécifié, git mergetool exécutera le programme de fusion sur

chaque fichier ayant
des conflits de fusion.

OPTION

S

-t <tool>, --tool=<tool

>
Utilise le programme de résolution de fusion spécifié par <tool>. Les valeurs valides incluent emerge, gvimdiff, kdiff3, meld, vimdiff, et tortoisemerge. Exécutez git mergetool --tool-help pour obtenir la liste des paramètres <tool> valides.

Si aucun programme de résolution de fusion n'est spécifié, git mergetool utilisera la variable de configuration merge.tool. Si la variable de configuration merge.tool n'est pas définie, git mergetool choisira une valeur par défaut

appropriée.

Vous pouvez fournir explicitement un chemin complet vers l'outil en définissant la variable de configuration mergetool.<tool>.path. Par exemple, vous pouvez configurer le chemin absolu vers kdiff3 en définissant mergetool.kdiff3.path. Sinon, git mergetool suppose que l'outil est disponible dans $PATH

.

Au lieu d'exécuter l'un des programmes de fusion connus, git mergetool peut être personnalisé pour exécuter un programme alternatif en spécifiant la ligne de commande à invoquer dans une variable de configuration mergetool.<tool>.cm

d.

Lorsque git mergetool est invoqué avec cet outil (soit par l'option -t ou --tool, soit par la variable de configuration merge.tool), la ligne de commande configurée sera invoquée avec BASE défini sur le nom d'un fichier temporaire contenant la base commune pour la fusion, si disponible ; LOCAL défini sur le nom d'un fichier temporaire contenant le contenu du fichier sur la branche courante ; REMOTE défini sur le nom d'un fichier temporaire contenant le contenu du fichier à fusionner, et MERGED défini sur le nom du fichier dans lequel l'outil de fusion doit écrire le résultat de la résolution de

fusion.

Si l'outil de fusion personnalisé indique correctement le succès d'une résolution de fusion par son code de sortie, alors la variable de configuration mergetool.<tool>.trustExitCode peut être définie à true. Sinon, git mergetool demandera à l'utilisateur d'indiquer le succès

de la résolution après la sor
tie de l'outil personnalisé.

--tool-hel

p
Affiche la liste des outils de fusion pouvant être utilisés avec --tool
.

-y, --no-promp

t
Ne demande pas de confirmation avant chaque invocation du programme de résolution de fusion. C'est le comportement par défaut si le programme de résolution de fusion est explicitement spécifié avec l'option --tool ou avec la variable de configuration merge.t
ool.

--promp

t
Demande une confirmation avant chaque invocation du programme de résolution de fusion pour donner à l'utilisateur la possibilité de passer le
chemin.

-g, --gu

i
Lorsque git-mergetool est invoqué avec l'option -g ou --gui, l'outil de fusion par défaut sera lu depuis la variable configurée merge.guitool au lieu de merge.tool. Si merge.guitool n'est pas définie, nous utiliserons l'outil configuré sous merge.tool. Cela peut être auto-sélectionné en utilisant la variable de configuration mergetool.guiD
efault.

--no-gu

i
Cela annule un paramètre -g ou --gui précédent ou la configuration mergetool.guiDefault et lit l'outil de fusion par défaut depuis la variable configurée merge.t
ool.

-O<orderfile

>
Traite les fichiers dans l'ordre spécifié dans le <orderfile>, qui contient un motif de glob shell par ligne. Cela annule la variable de configuration diff.orderFile (voir git-config(1)). Pour annuler diff.orderFile, utilisez -O/dev/nul
l
.

CONFIGURATIO

N

Tout ce qui suit cette ligne dans cette section est inclus sélectivement depuis la documentation git-config(1). Le contenu est identique à celui qui s'y trouve

:

mergetool.<tool>.

path
Remplace le chemin pour l'outil donné. C'est utile si votre outil n'est pas dans le $PATH
.

mergetool.<tool>.

cmd
Spécifie la commande pour invoquer l'outil de fusion spécifié. La commande spécifiée est évaluée dans le shell avec les variables suivantes disponibles : BASE est le nom d'un fichier temporaire contenant la base commune des fichiers à fusionner, si disponible ; LOCAL est le nom d'un fichier temporaire contenant le contenu du fichier sur la branche courante ; REMOTE est le nom d'un fichier temporaire contenant le contenu du fichier de la branche en cours de fusion ; MERGED contient le nom du fichier dans lequel l'outil de fusion doit écrire les résultats d'une fusion
réussie.

mergetool.<tool>.

hideResolved
Permet à l'utilisateur de remplacer la valeur globale mergetool.hideResolved pour un outil spécifique. Voir mergetool.hideResolved pour la description
complète.

mergetool.<tool>.

trustExitCode
Pour une commande de fusion personnalisée, spécifie si le code de sortie de la commande de fusion peut être utilisé pour déterminer si la fusion a réussi. Si ce n'est pas défini à true, l'horodatage du fichier cible de fusion est vérifié, et la fusion est supposée avoir réussi si le fichier a été mis à jour ; sinon, l'utilisateur est invité à indiquer le succès de la
fusion.

mergetool.meld.

hasOutput
Les anciennes versions de meld ne prennent pas en charge l'option --output. Git essaiera de détecter si meld prend en charge --output en inspectant la sortie de meld --help. Configurer mergetool.meld.hasOutput fera que Git sautera ces vérifications et utilisera la valeur configurée à la place. Définir mergetool.meld.hasOutput à true indique à Git d'utiliser inconditionnellement l'option --output, et false évite d'utiliser --output
.

mergetool.meld.

useAutoMerge
Lorsque --auto-merge est donné, meld fusionnera automatiquement toutes les parties non conflictuelles, mettra en évidence les parties conflictuelles et attendra la décision de l'utilisateur. Définir mergetool.meld.useAutoMerge à true indique à Git d'utiliser inconditionnellement l'option --auto-merge avec meld. Définir cette valeur à auto fait que git détecte si --auto-merge est pris en charge et n'utilisera --auto-merge que si disponible. Une valeur de false évite d'utiliser --auto-merge du tout, et est la valeur par
défaut.

mergetool.<variant>.

layout
Configure la disposition de la fenêtre divisée pour la <variant> de vimdiff, qui est l'une de vimdiff, nvimdiff, gvimdiff. Lors du lancement de git mergetool avec --tool=<variant> (ou sans --tool si merge.tool est configuré comme <variant>), Git consultera mergetool.<variant>.layout pour déterminer la disposition de l'outil. Si la configuration spécifique à la variante n'est pas disponible, celle de vimdiff est utilisée comme solution de repli. Si celle-ci n'est pas non plus disponible, une disposition par défaut avec 4 fenêtres sera utilisée. Pour configurer la disposition, voir la section INDICATIONS SPÉCIFIQUES AU
BACKEND.

mergetool.

hideResolved
Lors d'une fusion, Git résoudra automatiquement autant de conflits que possible et écrira le fichier $MERGED contenant les marqueurs de conflit autour de tout conflit qu'il ne peut pas résoudre ; $LOCAL et $REMOTE sont normalement les versions du fichier d'avant la résolution de conflit de Git. Ce drapeau fait que $LOCAL et $REMOTE sont écris de sorte que seuls les conflits non résolus soient présentés à l'outil de fusion outil. Peut être configuré par outil via la mergetool.<outil>.hideResolved variable de configuration. Par défaut false
.

mergetool.

keepBackup
Après avoir effectué une fusion, le fichier original avec les marqueurs de conflit peut être sauvegardé sous la forme d'un fichier avec une extension .orig. Si cette variable est définie à false, ce fichier n'est pas conservé. Par défaut true (c'est-à-dire conserver les fichiers de sauvegarde)
.

mergetool.

keepTemporaries
Lors de l'invocation d'un outil de fusion personnalisé, Git utilise un ensemble de fichiers temporaires à transmettre à l'outil. Si l'outil renvoie une erreur et que cette variable est définie à true, ces fichiers temporaires seront conservés ; sinon, ils seront supprimés après la sortie de l'outil. Par défaut false
.

mergetool.

writeToTemp
Git écrit par défaut les versions temporaires BASE, LOCAL et REMOTE des fichiers en conflit dans l'arbre de travail. Git tentera d'utiliser un répertoire temporaire pour ces fichiers lorsque défini à true. Par défaut false
.

mergetool.

prompt
Demander confirmation avant chaque invocation du programme de résolution de
fusion.

mergetool.

guiDefault
Définir à true pour utiliser merge.guitool par défaut (équivalent à spécifier l'argument --gui), ou auto pour sélectionner merge.guitool ou merge.tool selon la présence d'une valeur de variable d'environnement DISPLAY. La valeur par défaut est false, où l'argument --gui doit être fourni explicitement pour que merge.guitool
soit u
tilisé.

FICHIERS

TEMPORAIRES

git mergetool crée des fichiers de sauvegarde *.orig lors de la résolution des fusions. Il est sûr de les supprimer une fois qu'un fichier a été fusionné et que sa session git mergetool est

terminée.

Définir la variable de configuration mergetool.keepBackup à false fait que git mergetool supprime automatiquement les fichiers de sauve

garde à mesure que les fichie
rs sont fusionnés avec succès.

INDICATIONS SPÉFIQUES AU

MOTEUR

vimdif

f

Description

Lorsque vous spécifiez --tool=vimdiff dans git mergetool, Git ouvrira Vim avec une disposition de 4 fenêtres réparties de la manière suivante

: 
------------------------------------------
|             |           |              |
|   LOCAL     |   BASE    |   REMOTE     |
|             |           |              |
------------------------------------------
|                                        |
|                MERGED                  |
|                                        |
----------------------------------------
-
-

LOCAL, BASE et REMOTE sont des tampons en lecture seule affichant le contenu du fichier en conflit dans des commits spécifiques (« commit vers lequel vous fusionnez », « commit ancêtre commun » et « commit depuis lequel vous fusionnez »

respectivement)

MERGED est un tampon en écriture où vous devez résoudre les conflits (en utilisant les autres tampons en lecture seule comme référence). Une fois que vous avez terminé, enregistrez et quittez Vim comme d'habitude (:wq) ou, si vous souhaitez annuler, quittez avec :c

q
.

Configuration de la disposition

Vous pouvez modifier la disposition des fenêtres utilisée par Vim en définissant la variable de configuration mergetool.vimdiff.layout qui accepte une chaîne où les séparateurs suivants ont une signification spéciale

:
•+ est utilisé pour « ouvrir un nouvel onglet
»
•, est utilisé pour « ouvrir une nouvelle division verticale
»
•/ est utilisé pour « ouvrir une nouvelle division horizontale
»
•@ est utilisé pour indiquer le fichier contenant la version finale après la résolution des conflits. S'il n'est pas présent, MERGED sera utilisé par
défaut.

La priorité des opérateurs est la suivante (vous pouvez utiliser des parenthèses pour la modifier)

: 
`@` > `+` > `/` >
`,
`

Variantes

Au lieu de --tool=vimdiff, vous pouvez également utiliser l'une de ces autres variantes

:
•--tool=gvimdiff, pour ouvrir gVim au lieu de
Vim.
•--tool=nvimdiff, pour ouvrir Neovim au lieu de
Vim.

Lors de l'utilisation de ces variantes, afin de spécifier une disposition personnalisée, vous devrez définir les variables de configuration mergetool.gvimdiff.layout et mergetool.nvimdiff.layout au lieu de mergetool.vimdiff.layout (bien que cette dernière soit utilisée comme solution de repli si la variable spécifique à la variante n'est pas définie)

.
