NOM

git-mv - Déplacer ou renommer un fichier, un répertoire ou un lien symbolique

SYNOPSIS

git mv [-v] [-f] [-n] [-k] <source> <destination>
git mv [-v] [-f] [-n] [-k] <source>... <répertoire-destination>

DESCRIPTION

Déplacer ou renommer un fichier, un répertoire ou un lien symbolique.

Dans la première forme, elle renomme <source>, qui doit exister et être un fichier, un lien symbolique ou un répertoire, en <destination>. Dans la seconde forme, <répertoire-destination> doit être un répertoire existant ; les sources données seront déplacées dans ce répertoire.

L'index est mis à jour après une exécution réussie, mais le changement doit toujours être commité.

OPTIONS

-f, --force

Forcer le renommage ou le déplacement d'un fichier même si la destination existe.

-k

Ignorer les actions de déplacement ou de renommage qui mèneraient à une condition d'erreur. Une erreur se produit lorsqu'une source n'existe pas et n'est pas contrôlée par Git, ou lorsqu'elle écraserait un fichier existant sauf si -f est donné.

-n, --dry-run

Ne rien faire ; montrer seulement ce qui se passerait.

-v, --verbose

Rapporter les noms des fichiers lors de leur déplacement.

SOUS-MODULES

Déplacer un sous-module à l'aide d'un fichier git (ce qui signifie qu'il a été cloné avec une version de Git 1.7.8 ou plus récente) mettra à jour le fichier git et le paramètre core.worktree pour que le sous-module fonctionne au nouvel emplacement. Il tentera également de mettre à jour le paramètre submodule.<nom>.path dans le fichier gitmodules(5) et mettra ce fichier en attente (sauf si -n est utilisé).

BOGUES

Chaque fois qu'une mise à jour de superprojet déplace un sous-module déjà rempli (par exemple, lors du passage entre des commits avant et après le déplacement), une ancienne copie du sous-module restera à l'ancien emplacement et un répertoire vide apparaîtra au nouvel emplacement. Pour remplir à nouveau le sous-module au nouvel emplacement, l'utilisateur devra exécuter "git submodule update" par la suite. La suppression de l'ancien répertoire n'est sûre que s'il utilise un fichier git, car sinon l'historique du sous-module sera également supprimé. Ces deux étapes seront obsolètes lorsque la mise à jour récursive des sous-modules aura été implémentée.
