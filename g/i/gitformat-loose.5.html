NOM

gitformat-loose - Format d'objet Git lâche

SYNOPSIS

$GIT_DIR/objects/[0-9a-f][0-9a-f]/*

DESCRIPTION

Les objets lâches sont la manière dont Git stocke des objets individuels, où chaque objet est écrit sous forme de fichier distinct.

Au fil de la durée de vie d'un dépôt, les objets sont généralement écrits initialement sous forme d'objets lâches. Finalement, ces objets lâches seront compactés dans des fichiers de paquets via la maintenance du dépôt pour améliorer l'utilisation de l'espace disque et accélérer la recherche de ces objets.

OBJETS LÂCHES

Chaque objet lâche contient un préfixe, suivi immédiatement par les données de l'objet. Le préfixe contient <type> <taille>\0. <type> est l'un de blob, tree, commit ou tag et taille est la taille des données (sans le préfixe) sous forme d'entier décimal exprimé en ASCII.

L'ensemble du contenu, préfixe et données concaténés, est ensuite compressé avec zlib et les données compressées sont stockées dans le fichier. L'identifiant de l'objet est le hachage SHA-1 ou SHA-256 (selon le cas) des données non compressées.

Le fichier pour l'objet lâche est stocké sous le répertoire objects, les deux premiers caractères hexadécimaux de l'identifiant de l'objet étant le répertoire et les caractères restants étant le nom de fichier. Ceci est fait pour fragmenter les données et éviter d'avoir trop de fichiers dans un seul répertoire, car certains systèmes de fichiers fonctionnent mal avec de nombreux éléments dans un répertoire.

Par exemple, l'arbre vide contient les données (non compressées) tree 0\0 et, dans un dépôt SHA-256, aurait l'identifiant d'objet 6ef19b41225c5369f1c104d45d8d85efa9b057b53b14b4b9b939dd74decc5321 et serait stocké sous $GIT_DIR/objects/6e/f19b41225c5369f1c104d45d8d85efa9b057b53b14b4b9b939dd74decc5321.

De même, un blob contenant le contenu abc aurait les données non compressées de blob 3\0abc.
