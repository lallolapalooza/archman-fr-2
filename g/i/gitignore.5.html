DESCRIPTIO

N

Un fichier gitignore spécifie les fichiers intentionnellement non suivis que Git doit ignorer. Les fichiers déjà suivis par Git ne sont pas affectés ; voir les REMARQUES ci-dessous pour plus de

détails.

Chaque ligne dans un fichier gitignore spécifie un motif. Lors de la décision d'ignorer un chemin, Git vérifie normalement les motifs gitignore provenant de plusieurs sources, avec l'ordre de priorité suivant, du plus élevé au plus bas (au sein d'un même niveau de priorité, le dernier motif correspondant décide du résultat)

:
•Motifs lus depuis la ligne de commande pour les commandes qui les prennent en
charge.
•Motifs lus depuis un fichier .gitignore situé dans le même répertoire que le chemin, ou dans n'importe quel répertoire parent (jusqu'au niveau supérieur de l'arbre de travail), les motifs des fichiers de niveau supérieur étant remplacés par ceux des fichiers de niveau inférieur jusqu'au répertoire contenant le fichier. Ces motifs correspondent par rapport à l'emplacement du fichier .gitignore. Un projet inclut normalement de tels fichiers .gitignore dans son dépôt, contenant des motifs pour les fichiers générés lors de la construction du
projet.
•Motifs lus depuis $GIT_DIR/info/exclude
.
•Motifs lus depuis le fichier spécifié par la variable de configuration core.exclude
sFile.

Le fichier dans lequel placer un motif dépend de la manière dont le motif est censé être

utilisé.
•Les motifs qui doivent être versionnés et distribués à d'autres dépôts via clone (c'est-à-dire les fichiers que tous les développeurs voudront ignorer) doivent aller dans un fichier .giti
gnore.
•Les motifs qui sont spécifiques à un dépôt particulier mais qui n'ont pas besoin d'être partagés avec d'autres dépôts liés (par exemple, des fichiers auxiliaires qui se trouvent dans le dépôt mais qui sont spécifiques au flux de travail d'un utilisateur) doivent aller dans le fichier $GIT_DIR/info/exclude
.
•Les motifs qu'un utilisateur veut que Git ignore dans toutes les situations (par exemple, des fichiers de sauvegarde ou temporaires générés par l'éditeur de son choix) vont généralement dans un fichier spécifié par core.excludesFile dans le ~/.gitconfig de l'utilisateur. Sa valeur par défaut est $XDG_CONFIG_HOME/git/ignore. Si $XDG_CONFIG_HOME n'est pas défini ou est vide, $HOME/.config/git/ignore est utilisé à la
place.

Les outils de plomberie Git sous-jacents, tels que git ls-files et git read-tree, lisent les motifs gitignore spécifiés par des options de ligne de commande, ou depuis des fichiers spécifiés par des options de ligne de commande. Les outils Git de niveau supérieur, tels que git status et git add, utilisent les motifs

des sources spéc
ifiées ci-dessus.

FORMAT DES

MOTIFS
•Une ligne vide ne correspond à aucun fichier, elle peut donc servir de séparateur pour la
lisibilité.
•Une ligne commençant par # sert de commentaire. Mettez une barre oblique inverse ("\") devant le premier dièse pour les motifs qui commencent par un
dièse.
•Les espaces en fin de ligne sont ignorés sauf s'ils sont entourés de barres obliques inverses ("\")
.
•Un préfixe optionnel "!" qui nie le motif ; tout fichier correspondant exclu par un motif précédent sera de nouveau inclus. Il n'est pas possible de réinclure un fichier si un répertoire parent de ce fichier est exclu. Git ne liste pas les répertoires exclus pour des raisons de performance, donc tout motif sur les fichiers contenus n'a aucun effet, peu importe où il est défini. Mettez une barre oblique inverse ("\") devant le premier "!" pour les motifs qui commencent par un "!" littéral, par exemple, "\!important!.
txt".
•La barre oblique "/" est utilisée comme séparateur de répertoire. Les séparateurs peuvent apparaître au début, au milieu ou à la fin du motif de recherche .
gitignore.
•S'il y a un séparateur au début ou au milieu (ou aux deux) du motif, alors le motif est relatif au niveau de répertoire du fichier .gitignore lui-même. Sinon le motif peut aussi correspondre à n'importe quel niveau en dessous du niveau .giti
gnore.
•S'il y a un séparateur à la fin du motif alors le motif ne correspondra qu'aux répertoires, sinon le motif peut correspondre à la fois aux fichiers et aux
répertoires.
•Par exemple, un motif doc/frotz/ correspond au répertoire doc/frotz, mais pas au répertoire a/doc/frotz ; cependant frotz/ correspond à frotz et à a/frotz qui est un répertoire (tous les chemins sont relatifs depuis le fichier .gitignore)
.
•Un astérisque "*" correspond à tout sauf une barre oblique. Le caractère "?" correspond à n'importe quel caractère sauf "/". La notation de plage, par exemple [a-zA-Z], peut être utilisée pour correspondre à l'un des caractères d'une plage. Voir fnmatch(3) et l'indicateur FNM_PATHNAME pour une description plus
détaillée.
•Une barre oblique inverse ("\") peut être utilisée pour échapper n'importe quel caractère. Par exemple, "\*" correspond à un astérisque littéral (et "\a" correspond à "a", même s'il n'y a pas besoin d'échappement là). Comme avec fnmatch(3), une barre oblique inverse à la fin d'un motif est un motif invalide qui ne correspond
jamais.

Deux astérisques consécutifs ("**") dans les motifs correspondant à un chemin complet peuvent avoir une signification spéciale

:
•Un "**" initial suivi d'une barre oblique signifie correspondre dans tous les répertoires. Par exemple, "**/foo" correspond au fichier ou répertoire "foo" n'importe où, comme le motiffoo". "**/foo/bar" correspond au fichier ou répertoire "bar" n'importe où directement sous le répertoirefoo"
.
•Un "/**" final correspond à tout ce qui est à l'intérieur. Par exemple, "abc/**" correspond à tous les fichiers à l'intérieur du répertoire "abc", par rapport à l'emplacement du fichier .gitignore, avec une profondeur
infinie.
•Une barre oblique suivie de deux astérisques consécutifs puis d'une barre oblique correspond à zéro ou plusieurs répertoires. Par exemple, "a/**/b" correspond à "a/b", "a/x/b", "a/x/y/b" et ainsi de
suite.
•Les autres astérisques consécutifs sont con
sidérés comme des astérisques réguliers et
correspondront selon les règles précédentes.

CONFIGURATIO

N

La variable de configuration optionnelle core.excludesFile indique un chemin vers un fichier contenant des motifs de noms de fichiers à exclure, similaire à $GIT_DIR/info/exclude. Les motifs du fichier d'exclusion sont utilisés en plus de ceux de $GIT_DIR/info/exclud

e
.

REMARQUE

S

Le but des fichiers gitignore est de s'assurer que certains fichiers non suivis par Git restent non

suivis.

Pour arrêter de suivre un fichier actuellement suivi, utilisez git rm --cached pour retirer le fichier de l'index. Le nom du fichier peut ensuite être ajouté au fichier .gitignore pour empêcher le fichier d'être réintroduit dans les commits

ultérieurs.

Git ne suit pas les liens symboliques lors de l'accès à un fichier .gitignore dans l'arbre de travail. Cela maintient un comportement cohérent lorsque le f

ichier est accédé depuis l'index ou un arbre par ra
pport à l'accès depuis le système de fichiers.

EXEMPLE

S
•Le motif hello.* correspond à tout fichier ou répertoire dont le nom commence par hello.. Si l'on veut restreindre cela uniquement au répertoire et pas à ses sous-répertoires, on peut préfixer le motif d'une barre oblique, c'est-à-dire /hello.* ; le motif correspond maintenant à hello.txt, hello.c mais pas à a/hello.j
ava.
•Le motif foo/ correspondra à un répertoire foo et aux chemins en dessous, mais ne correspondra pas à un fichier régulier ou à un lien symbolique foo (cela est cohérent avec la manière dont pathspec fonctionne en général dans
Git)
•Le motif doc/frotz et /doc/frotz ont le même effet dans n'importe quel fichier .gitignore. En d'autres termes, une barre oblique initiale n'est pas pertinente s'il y a déjà une barre oblique au milieu du
motif.
•Le motif foo/*, correspond à foo/test.json (un fichier régulier), foo/bar (un répertoire), mais ne correspond pas à foo/bar/hello.c (un fichier régulier), car l'astérisque dans le motif ne correspond pas bar/hello.c qui contient une barre
oblique. 
    $ git status
    [...]
    # Fichiers non suivis :
    [...]
    #       Documentation/foo.html
    #       Documentation/gitignore.html
    #       file.o
    #       lib.a
    #       src/internal.o
    [...]
    $ cat .git/info/exclude
    # ignorer les objets et archives, n'importe où dans l'arbre.
    *.[oa]
    $ cat Documentation/.gitignore
    # ignorer les fichiers html générés,
    *.html
    # sauf foo.html qui est maintenu à la main
    !foo.html
    $ git status
    [...]
    # Fichiers non suivis :
    [...]
    #       Documentation/foo.html
    [..
.
]

Un autre exemple

: 
    $ cat .gitignore
    vmlinux*
    $ ls arch/foo/
kernel/vm* arch/foo/kernel/vmlinux.lds.S
$ echo '!/vmlinux*' >arch/foo/kernel/.gitignore

Le second .gitignore empêche Git d'ignorer arch/foo/kernel/vmli

nux.lds.S.

Exemple pour exclure tout sauf un répertoire spécifique foo/bar (notez le /* - sans la barre oblique, le joker exclurait également tout ce qui se trouve dans foo/bar)

: 
    $ cat .gitignore
    # exc
lure tout sauf le répertoi
re foo/bar /* !/fo
o /foo/* !/foo/bar
