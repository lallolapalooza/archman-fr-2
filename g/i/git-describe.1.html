NOM

git-describe - Donne à un objet un nom lisible par l'humain basé sur une référence disponible

SYNOPSIS

git describe [--all] [--tags] [--contains] [--abbrev=<n>] [<commit-ish>...]
git describe [--all] [--tags] [--contains] [--abbrev=<n>] --dirty[=<mark>]
git describe <blob>

DESCRIPTION

La commande trouve l'étiquette (tag) la plus récente accessible depuis un commit. Si l'étiquette pointe vers le commit, alors seule l'étiquette est affichée. Sinon, elle suffixe le nom de l'étiquette avec le nombre de commits supplémentaires au-dessus de l'objet étiqueté et le nom abrégé de l'objet du commit le plus récent. Le résultat est un nom d'objet « lisible par l'humain » qui peut également être utilisé pour identifier le commit à d'autres commandes git.

Par défaut (sans --all ou --tags) git describe n'affiche que les étiquettes annotées. Pour plus d'informations sur la création d'étiquettes annotées, voir les options -a et -s de git-tag(1).

Si l'objet donné fait référence à un blob, il sera décrit comme <commit-ish>:<path>, de sorte que le blob puisse être trouvé à <path> dans le <commit-ish>, qui décrit lui-même le premier commit dans lequel ce blob apparaît lors d'un parcours de révision inverse depuis HEAD.

OPTIONS

<commit-ish>...

Noms d'objets commit-ish à décrire. Par défaut HEAD si omis.

--dirty[=<mark>], --broken[=<mark>]

Décrire l'état de l'arbre de travail. Lorsque l'arbre de travail correspond à HEAD, la sortie est la même que "git describe HEAD". Si l'arbre de travail a des modifications locales, "-dirty" est ajouté à la fin. Si un dépôt est corrompu et que Git ne peut pas déterminer s'il y a des modifications locales, Git échouera, sauf si ‘--broken’ est donné, ce qui ajoute le suffixe "-broken" à la place.

--all

Au lieu d'utiliser uniquement les étiquettes annotées, utiliser toute référence trouvée dans l'espace de noms refs/ . Cette option permet de faire correspondre n'importe quelle branche connue, branche de suivi à distance ou étiquette légère.

--tags

Au lieu d'utiliser uniquement les étiquettes annotées, utiliser toute étiquette trouvée dans l'espace de noms refs/tags . Cette option permet de faire correspondre une étiquette légère (non annotée).

--contains

Au lieu de trouver l'étiquette qui précède le commit, trouver l'étiquette qui vient après le commit, et qui le contient donc. Implique automatiquement --tags.

--abbrev=<n>

Au lieu d'utiliser le nombre par défaut de chiffres hexadécimaux (qui variera en fonction du nombre d'objets dans le dépôt, avec un défaut de 7) du nom d'objet abrégé, utiliser <n> chiffres, ou autant de chiffres que nécessaire pour former un nom d'objet unique. Un <n> de 0 supprimera le format long, n'affichant que l'étiquette la plus proche.

--candidates=<n>

Au lieu de considérer uniquement les 10 étiquettes les plus récentes comme candidats pour décrire le commit-ish d'entrée, considérer jusqu'à <n> candidats. Augmenter <n> au-delà de 10 prendra légèrement plus de temps mais peut produire un résultat plus précis. Un <n> de 0 ne fera afficher que les correspondances exactes.

--exact-match

N'afficher que les correspondances exactes (une étiquette fait directement référence au commit fourni). C'est un synonyme pour --candidates=0.

--debug

Afficher verbeusement des informations sur la stratégie de recherche utilisée sur la sortie d'erreur standard. Le nom de l'étiquette sera toujours imprimé sur la sortie standard.

--long

Toujours afficher le format long (l'étiquette, le nombre de commits et le nom abrégé du commit) même lorsqu'il correspond à une étiquette. C'est utile lorsque vous voulez voir des parties du nom d'objet du commit dans la sortie de "describe", même lorsque le commit en question s'avère être une version étiquetée. Au lieu d'émettre simplement le nom de l'étiquette, elle décrira un tel commit comme v1.2-0-gdeadbee (0e commit depuis l'étiquette v1.2 qui pointe vers l'objet deadbee....).

--match <pattern>

Ne considérer que les étiquettes correspondant au motif glob(7) donné, en excluant le préfixe "refs/tags/". S'il est utilisé avec --all, il considère également les branches locales et les références de suivi à distance correspondant au motif, en excluant respectivement les préfixes "refs/heads/" et "refs/remotes/" ; les références de autres types ne sont jamais considérées. S'il est donné plusieurs fois, une liste de motifs sera accumulée, et les étiquettes correspondant à l'un des motifs seront considérées. Utilisez --no-match pour effacer et réinitialiser la liste de motifs.

--exclude <pattern>

Ne pas considérer les étiquettes correspondant au motif glob(7) donné, en excluant le préfixe "refs/tags/". S'il est utilisé avec --all, il ne considère pas non plus les branches locales et les références de suivi à distance correspondant au motif, en excluant respectivement les préfixes "refs/heads/" et "refs/remotes/" ; les références de autres types ne sont jamais considérées. S'il est donné plusieurs fois, une liste de motifs sera accumulée et les étiquettes correspondant à l'un des motifs seront exclues. Lorsqu'il est combiné avec --match, une étiquette sera considérée lorsqu'elle correspond à au moins un motif --match et ne correspond à aucun des motifs --exclude. Utilisez --no-exclude pour effacer et réinitialiser la liste de motifs.

--always

Afficher l'objet commit abrégé de manière unique comme solution de repli.

--first-parent

Suivre uniquement le premier commit parent lorsqu'on rencontre un commit de fusion. C'est utile lorsque vous ne voulez pas faire correspondre les étiquettes sur les branches fusionnées dans l'historique du commit cible.

EXEMPLES

Avec quelque chose comme l'arbre courant de git.git, j'obtiens :

[torvalds@g5 git]$ git describe parent
v1.0.4-14-g2414721

c'est-à-dire que la tête actuelle de ma branche "parent" est basée sur v1.0.4, mais comme elle a quelques commits au-dessus de cela, describe a ajouté le nombre de commits supplémentaires ("14") et un nom d'objet abrégé pour le commit lui-même ("2414721") à la fin.

Le nombre de commits supplémentaires est le nombre de commits qui seraient affichés par "git log v1.0.4..parent". Le suffixe de hachage est "-g" + une abréviation non ambiguë pour le commit de tête de parent (qui était 2414721b194453f058079d897d13c4e377f92dc6). La longueur de l'abréviation s'adapte à la croissance du dépôt, utilisant le nombre approximatif d'objets dans le dépôt et un peu de mathématiques autour du paradoxe des anniversaires, et est par défaut à un minimum de 7. Le préfixe "g" signifie "git" et est utilisé pour permettre de décrire la version d'un logiciel en fonction du SCM avec lequel le logiciel est géré. C'est utile dans un environnement où les gens peuvent utiliser différents SCM.

Faire un git describe sur un nom d'étiquette affichera simplement le nom de l'étiquette :

[torvalds@g5 git]$ git describe v1.0.4
v1.0.4

Avec --all, la commande peut utiliser les têtes de branche comme références, de sorte que la sortie affiche également le chemin de la référence :

[torvalds@g5 git]$ git describe --all --abbrev=4 v1.0.5^2
tags/v1.0.0-21-g975b
[torvalds@g5 git]$ git describe --all --abbrev=4 HEAD^
heads/lt/describe-7-g975b

Avec --abbrev défini à 0, la commande peut être utilisée pour trouver le nom d'étiquette le plus proche sans aucun suffixe :

[torvalds@g5 git]$ git describe --abbrev=0 v1.0.5^2
tags/v1.0.0

Notez que le suffixe que vous obtenez si vous tapez ces commandes aujourd'hui peut être plus long que ce que Linus a vu ci-dessus lorsqu'il a exécuté ces commandes, car votre dépôt Git peut avoir de nouveaux commits dont les noms d'objets commencent par 975b qui n'existaient pas à l'époque, et le suffixe "-g975b" seul peut ne pas être suffisant pour désambiguïser ces commits.

STRATÉGIE DE RECHERCHE

Pour chaque commit-ish fourni, git describe cherchera d'abord une étiquette qui étiquette exactement ce commit. Les étiquettes annotées seront toujours préférées aux étiquettes légères, et les étiquettes avec des dates plus récentes seront toujours préférées aux étiquettes avec des dates plus anciennes. Si une correspondance exacte est trouvée, son nom sera affiché et la recherche s'arrêtera.

Si aucune correspondance exacte n'a été trouvée, git describe remontera l'historique des commits pour localiser un commit ancêtre qui a été étiqueté. L'étiquette de l'ancêtre sera affichée avec une abréviation du SHA-1 du commit-ish d'entrée. Si --first-parent a été spécifié, alors lealk ne prendra en compte que le premier parent de chaque commit.

Si plusieurs étiquettes ont été trouvées lors du parcours, l'étiquette qui a le moins de commits différents du commit-ish d'entrée sera sélectionnée et affichée. Ici, le moins de commits différents est défini comme le nombre de commits qui seraient affichés par git log tag..input sera le plus petit nombre de commits possible.

BUGS

Les objets arbre ainsi que les objets d'étiquette ne pointant pas vers des commits ne peuvent pas être décrits. Lors de la description de blobs, les étiquettes légères pointant vers des blobs sont ignorées, mais le blob est toujours décrit comme <commit-ish>:<path> malgré l'étiquette légère étant préférable.
