NOM

git-annex-add - ajoute des fichiers à l'annexe git

SYNOPSIS

git annex add [chemin ...]

DESCRIPTION

Ajoute les fichiers spécifiés à l'annexe. Si un répertoire est spécifié, agit sur tous les fichiers à l'intérieur du répertoire et de ses sous-répertoires. Si aucun chemin n'est spécifié, ajoute les fichiers du répertoire courant et de ses sous-répertoires.

Les fichiers qui sont déjà enregistrés dans git et qui n'ont pas été modifiés, ou que git a été configuré pour ignorer, seront silencieusement ignorés.

Si annex.largefiles est configuré (dans git config, gitattributes, ou git-annex config), et qu'il ne correspond pas à un fichier, git annex add se comportera de la même manière que git add et ajoutera le fichier non volumineux directement dans le dépôt git, au lieu de l'annexe. (Par défaut, les fichiers dotfiles et le contenu des dotdirs sont considérés comme non volumineux et sont ajoutés directement à git, mais annex.dotfiles peut être configuré pour les annexer également.) Voir la page de manuel de git-annex pour la documentation de ces paramètres de configuration et d'autres.

Par défaut, les fichiers volumineux sont ajoutés à l'annexe sous forme verrouillée, ce qui empêche toute modification ultérieure de leur contenu jusqu'à ce qu'ils soient déverrouillés par git-annex-unlock(1). (Cela n'est cependant pas le cas lorsqu'un dépôt se trouve sur un système de fichiers qui ne prend pas en charge les liens symboliques.) La configuration git annex.addunlocked (et la configuration git-annex) peut être utilisée pour modifier ce comportement.

Cette commande peut également être utilisée pour ajouter des liens symboliques, qu'ils pointent vers du contenu annexé ou non.

EXEMPLES


# git annex add foo bar
add foo ok
add bar ok
# git commit -m added

OPTIONS

--no-check-gitignore
Ajoute les fichiers ignorés par git.
--force-large
Traite tous les fichiers comme des fichiers volumineux, ignore la configuration annex.largefiles et annex.dotfiles, et les ajoute à l'annexe.
--force-small
Traite tous les fichiers comme des fichiers non volumineux, ignore la configuration annex.largefiles, annex.dotfiles et annex.addsmallfiles, et les ajoute à git.
--backend
Spécifie quel backend clé-valeur utiliser.
options de correspondance de fichiers
Plusieurs des git-annex-matching-options(1) peuvent être utilisées pour spécifier les fichiers à ajouter.
Par exemple : --largerthan=1GB
--jobs=N -JN
Ajoute plusieurs fichiers en parallèle. Cela peut être plus rapide. Par exemple : -J4
Le réglage de cette option sur "cpus" lancera un travail par cœur de processeur.
--update -u
Similaire à git add --update, cela n'ajoute pas de nouveaux fichiers, mais les mises à jour des fichiers suivis seront ajoutées à l'index.
--dry-run
Affiche ce qui serait fait pour chaque fichier, mais évite de faire des changements.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut des objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard d'erreur sont inclus dans le JSON à la place.
--batch
Active le mode batch, dans lequel un fichier à ajouter est lu ligne par ligne depuis stdin, le fichier est ajouté, et ainsi de suite.
Notez que si un fichier est ignoré (parce qu'il n'existe pas, est ignoré par git, est déjà dans git, ou ne répond pas aux options de correspondance), une ligne vide sera affichée au lieu de la sortie normale produite lors de l'ajout d'un fichier.
-z
Fait en sorte que l'entrée --batch soit délimitée par des zéros (null) au lieu des sauts de ligne habituels.
Les git-annex-common-options(1) peuvent également être utilisés.
