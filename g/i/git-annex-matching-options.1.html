DESCRIPTIO

N

De nombreuses commandes git-annex prennent en charge l'utilisation de ces options pour spécifier sur quels fichiers elles agissent. Certaines de ces options peuvent également être utilisées par des commandes pour spécifier sur quelles clés elles

agissent.

Des expressions arbitrairement complexes peuvent être construites à l'aide de ces options. Par exemple

:


--include='*.mp3' --and -( --in=usbdrive --or --in=archive

-)

L'exemple ci-dessus fait en sorte que git-annex

ne travaille que sur les fichiers mp3 qui sont
présents dans l'un ou l'autre des deux dépôts.

OPTION

S
--exclude=gl
ob
Ignore les fichiers correspondant au motif glob. Le glob est comparé par rapport au répertoire courant. Par exemple
:

git annex get --exclude='*.mp3' --exclude='subdir
/*'
Notez que cela ne correspondra à rien lorsque vous utilisez --all ou
--unused.
--include=gl
ob
Ignore les fichiers ne correspondant pas au motif glob. (Équivalent à --not --exclude.) Par exemple, pour n'inclure que les fichiers mp3 et
ogg :

git annex get --include='*.mp3' --or --include='*.
ogg'
Notez que cela n'ignorera rien lorsque vous utilisez --all ou
--unused.
--excludesamecontent=g
lob
Ignore un fichier lorsqu'il existe un autre fichier avec le même contenu, dont le nom correspond au glob. Le glob est comparé par rapport au répertoire
courant.
Par exemple, pour supprimer les fichiers du répertoire archive, mais pas lorsque le même contenu est utilisé par un fichier du répertoire work
:

git annex drop archive/ --excludesamecontent='work
/*'
--includesamecontent=g
lob
Ignore les fichiers lorsqu'il n'y a pas d'autre fichier avec le même contenu dont le nom correspond au glob. (Équivalent à --not --excludesameconte
nt)
Par exemple, si vous avez les répertoires inbox et outbox, et que vous voulez trouver tout ce qui est dans inbox et qui a le même contenu que quelque chose dans outbox
:

git annex find inbox --includesamecontent='outbox
/*'
--in=reposit
ory
Ne correspond que lorsque git-annex estime que le contenu est présent dans un
dépôt.
Le dépôt doit être spécifié en utilisant le nom d'un distant configuré, ou l'UUID ou la description d'un dépôt. Pour le dépôt courant, utilisez --in=he
re
Notez que cela ne vérifie pas les dépôts distants pour confirmer que le contenu y est toujours présent. Cependant, lors de la vérification du dépôt courant, il vérifie bien que le contenu y est
présent.
--in=repository@{da
te}
Ne correspond que lorsque le contenu était présent dans un dépôt à la date
donnée.
La date est spécifiée avec la même syntaxe que celle documentée dans gitrevisions(7). Notez que cela utilise le reflog, donc les dates très anciennes ne peuvent pas être
interrogées.
Par exemple, vous pourriez avoir besoin d'exécuter git annex drop . pour libérer temporairement de l'espace disque. Le lendemain, vous pouvez récupérer les fichiers que vous avez supprimés en utilisant git annex get . --in=here@{yesterd
ay}
--expected-pres
ent
Ne correspond que lorsque git-annex estime que le contenu est présent dans le dépôt
local.
C'est comme --in=here, sauf qu'il ne vérifie pas que le contenu est réellement présent. Il peut donc être utilisé dans des situations où les informations de suivi de localisation sont connues pour être
obsolètes.
Par exemple, si un dépôt est en cours de restauration à partir d'une sauvegarde qui n'incluait pas les objets git-annex, cela pourrait être utilisé pour récupérer tous les fichiers qui étaient censés y être : git-annex get --expected-pres
ent
--copies=num
ber
Ne correspond que lorsque git-annex estime qu'il y a le nombre de copies spécifié, ou plus. Notez qu'il ne vérifie pas les distants pour confirmer que les copies existent
toujours.
--copies=trustlevel:
number
Ne correspond que lorsque git-annex estime qu'il y a le nombre de copies spécifié, sur les distants avec le niveau de confiance spécifié. Par exemple, --copies=trusted:
2
Pour correspondre à n'importe quel niveau de confiance égal ou supérieur à un niveau donné, utilisez 'trustlevel+'. Par exemple, --copies=semitrusted+:
2
--copies=groupname:
number
Ne correspond que lorsque git-annex estime qu'il y a le nombre de copies spécifié, sur les distants du groupe spécifié. Par exemple, --copies=archive:
2
--lackingcopies=num
ber
Ne correspond que lorsque git-annex estime que le nombre spécifié de copies ou plus doivent être créées afin de satisfaire les paramètres
numcopies.
--approxlackingcopies=num
ber
Comme lackingcopies, mais ne consulte pas les paramètres annex.numcopies de .gitattributes. Cela le rend nettement plus
rapide.
--inbackend=n
ame
Ne correspond que lorsque le contenu est stocké à l'aide du backend clé-valeur
spécifié.
--secureha
sh
Ne correspond que lorsque le contenu est haché à l'aide d'une fonction cryptographiquement
sécurisée.
--inallgroup=groupn
ame
Ne correspond que lorsque git-annex estime que le contenu est présent dans tous les dépôts du groupe
spécifié.
--onlyingroup=groupn
ame
Ne correspond que lorsque git-annex estime que le contenu est présent dans au moins un dépôt qui est dans le groupe spécifié, et n'est présent dans aucun dépôt qui n'est pas dans le groupe
spécifié.
--smallerthan=s
ize
--largerthan=s
ize
Ne correspond que lorsque le contenu est plus petit que, ou plus grand que la taille
spécifiée.
La taille peut être spécifiée avec n'importe lesquelles des unités couramment utilisées, par exemple, "0.5 gb" ou "100
KiloBytes"
--metadata
field=glob
Ne correspond que lorsqu'un champ de métadonnées est attaché avec une valeur qui correspond au glob. Les valeurs des champs de métadonnées sont comparées sans tenir compte de la
casse.
--metadata field<value / --metadata field>
value
--metadata field<=value / --metadata field>
=value
Ne correspond que lorsqu'un champ de métadonnées est attaché avec une valeur qui est inférieure ou supérieure à la valeur spécifiée,
respectivement.
Lorsque les deux valeurs sont des nombres, la comparaison est effectuée numériquement. Lorsqu'une valeur n'est pas un nombre, les valeurs sont plutôt comparées lexicographiquem
ent.
(Notez que vous devrez mettre le second paramètre entre guillemets pour éviter que le shell n'effectue une redirection.
)
--url=gl
ob
Correspond lorsque le contenu est enregistré comme étant présent dans une url qui correspond au
glob.
--want-g
et
Ne correspond que lorsque les paramètres de contenu préféré pour le dépôt local le font vouloir récupérer du contenu. Notez que cela correspondra même lorsque le contenu est déjà présent, sauf si limité par ex. avec, --not
--in=here
--want-dr
op
Ne correspond que lorsque les paramètres de contenu préféré pour le dépôt local le font vouloir supprimer du contenu. Notez que cela correspondra même lorsque le contenu n'est pas présent, sauf si limité par ex. avec, --not
--in=here
Les choses auxquelles cela correspond ne seront pas nécessairement supprimé par git-annex drop --auto. Cela ne vérifie pas qu'il y a suffisamment de copies pour supprimer. De plus, le même contenu peut être utilisé par un fichier qui n'est pas destiné à être
supprimé.
--want-get-by=dép
ôt
Correspond uniquement lorsque les paramètres de contenu préféré pour le dépôt spécifié indiquent qu'il souhaite récupérer du contenu. Notez que cela correspondra même lorsque le contenu est déjà présent dans ce dépôt, sauf si limité avec par ex., --not
--in=dépôt
Le dépôt doit être spécifié en utilisant le nom d'un distant configuré, ou l'UUID ou la description d'un dépôt. --want-get-by=here est équivalent à --want-ge
t.
--want-drop-by=dép
ôt
Correspond uniquement lorsque les paramètres de contenu préféré pour le dépôt spécifié indiquent qu'il souhaite supprimer du contenu. Notez que cela correspondra même lorsque le contenu n'est pas présent, sauf si limité avec par ex., --not
--in=dépôt
Le dépôt doit être spécifié en utilisant le nom d'un distant configuré, ou l'UUID ou la description d'un dépôt. --want-drop-by=here est équivalent à --want-dro
p.
--accessedwithin=interva
lle
Correspond lorsque le contenu a été accédé récemment, dans l'intervalle de temps
spécifié.
L'intervalle peut être sous la forme "5m" ou "1h" ou "2d" ou "1y", ou une combinaison telle que
"1h5m".
Ainsi, par exemple, --accessedwithin=1d correspond lorsque le contenu a été accédé au cours de la dernière
journée.
Si le système d'exploitation ou le système de fichiers ne prend pas en charge les temps d'accès, cela ne correspondra à
rien.
--unlock
ed
Correspond aux fichiers annexés qui sont
déverrouillés.
--lock
ed
Correspond aux fichiers annexés qui sont
verrouillés.
--mimetype=g
lob
Recherche le type MIME d'un fichier et vérifie si le glob
correspond.
Par exemple, --mimetype="text/*" correspondra à de nombreuses variétés de fichiers texte, y compris "text/plain", mais aussi "text/x-shellscript", "text/x-makefile",
etc.
Les types MIME sont les mêmes que ceux affichés en exécutant file
--mime-type
Si le contenu annexé du fichier n'est pas présent, le fichier ne correspondra
pas.
Ceci n'est disponible que lorsque git-annex a été compilé avec l'indicateur de compilation
MagicMime.
--mimeencoding=g
lob
Recherche l'encodage MIME d'un fichier et vérifie si le glob
correspond.
Par exemple, --mimeencoding=binary correspondra à de nombreux types de fichiers
binaires.
Les encodages MIME sont les mêmes que ceux affichés en exécutant file
--mime-encoding
Si le contenu annexé du fichier n'est pas présent, le fichier ne correspondra
pas.
Ceci n'est disponible que lorsque git-annex a été compilé avec l'indicateur de compilation
MagicMime.
--anythi
ng
Correspond toujours. Une façon dont cela peut être utile est git-annex find --anything listera tous les fichiers annexés, que leur contenu soit présent ou
non.
--nothi
ng
Ne correspond jamais. (Équivalent à --not --any
thing)
--n
ot
Inverse l'option de correspondance suivante. Par exemple, pour correspondre lorsqu'il y a moins de 3 copies, utilisez --not
--copies=3
--a
nd
Exige que l'option de correspondance précédente et la suivante correspondent toutes les deux. C'est le comportement par
défaut.
--
or
Exige que l'option de correspondance précédente ou la suivante
corresponde.
