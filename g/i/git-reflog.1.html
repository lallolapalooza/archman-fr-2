DESCRIPTIO

N

Cette commande gère les informations enregistrées dans les journaux des

références.

Les journaux de référence, ou « reflogs », enregistrent quand les extrémités des branches et des autres références ont été mises à jour dans le dépôt local. Les reflogs sont utiles dans diverses commandes Git pour spécifier l'ancienne valeur d'une référence. Par exemple, HEAD@{2} signifie « où HEAD se trouvait il y a deux déplacements », master@{one.week.ago} signifie « où master pointait il y a une semaine dans ce dépôt local », et ainsi de suite. Voir gitrevisions(7) pour plus de

détails.

La commande accepte diverses sous-commandes et différentes options selon la sous-commande

:

La sous-commande « show » (qui est aussi la par défaut, en l'absence de toute sous-commande) affiche le journal de la référence fournie dans la ligne de commande (ou HEAD, par défaut). Le reflog couvre toutes les actions récentes, et en plus le reflog de HEAD enregistre les changements de branche. git reflog show est un alias pour git log -g --abbrev-commit --pretty=oneline ; voir git-log(1) pour plus

d'informations.

La sous-commande « list » liste toutes les références ayant un reflog

correspondant.

La sous-commande « exists » vérifie si une référence a un reflog. Elle se termine avec un code de statut zéro si le reflog existe, et un code de statut non nul s'il n'existe

pas.

La sous-commande « write » écrit une seule entrée dans le reflog d'une référence donnée. Cette nouvelle entrée est ajoutée au reflog et deviendra donc l'entrée la plus récente. Le nom de la référence doit être entièrement qualifié. Les identifiants d'objet ancien et nouveau ne doivent pas être abrégés et doivent pointer vers des objets existants. Le message du reflog est

normalisé.

La sous-commande « delete » supprime des entrées individuelles du reflog, mais pas le reflog lui-même. Son argument doit être une entrée exacte (par exemple «git reflog delete master@{2} »). Cette sous-commande n'est généralement pas utilisée directement par les utilisateurs

finaux.

La sous-commande « drop » supprime complètement le reflog des références spécifiées. Cela contraste avec « expire » et « delete », qui peuvent toutes deux être utilisées pour supprimer des entrées de reflog, mais pas le reflog

lui-même.

La sous-commande « expire » élagque les entrées de reflog plus anciennes. Les entrées plus anciennes que le temps d'expiration, ou les entrées plus anciennes que le temps d'expiration des objets inaccessibles et non accessibles depuis l'extrémité actuelle, sont supprimées du reflog. Cela n'est généralement pas utilisé directement par les utilisateurs finaux — voir plutôt git-g

c(1
).

Options pour expir

e

--al

l
Traite les reflogs de toutes les
références.

--single-worktre

e
Par défaut, lorsque --all est spécifié, les reflogs de tous les arborescences de travail sont traités. Cette option limite le traitement aux reflogs de l'arborescence de travail actuelle
uniquement.

--expire=<time

>
Élagque les entrées plus anciennes que le temps spécifié. Si cette option n'est pas spécifiée, le temps d'expiration est pris à partir du paramètre de configuration gc.reflogExpire, qui vaut par défaut 90 jours. --expire=all élagque les entrées quel que soit leur âge ; --expire=never désactive l'élagage des entrées accessibles (mais voir --expire-unreac
hable).

--expire-unreachable=<time

>
Élagque les entrées plus anciennes que <time> qui ne sont pas accessibles depuis l'extrémité actuelle de la branche. Si cette option n'est pas spécifiée, le temps d'expiration est pris à partir du paramètre de configuration gc.reflogExpireUnreachable, qui vaut par défaut 30 jours. --expire-unreachable=all élagque les entrées inaccessibles quel que soit leur âge ; --expire-unreachable=never désactive l'élagage précoce des entrées inaccessibles (mais voir --expir
e).

--updatere

f
Met à jour la référence à la valeur de l'entrée supérieure du reflog (c'est-à-dire <ref>@{0}) si l'entrée supérieure précédente a été élaguée. (Cette option est ignorée pour les références symboliques.
)

--rewrit

e
Si le prédécesseur d'une entrée de reflog est élagué, ajuste son SHA-1 « ancien » pour qu'il soit égal au champ SHA-1 « nouveau » de l'entrée qui le précède
maintenant.

--stale-fi

x
Élagque toute entrée de reflog pointant vers des « commits cassés ». Un commit cassé est un commit qui n'est accessible depuis aucune des extrémités de référence et qui référence, directement ou indirectement, un commit, un arbre ou un objet blob manquant.

Ce calcul implique de parcourir tous les objets accessibles, c'est-à-dire qu'il a le même coût que git prune. Il est principalement destiné à corriger la corruption causée par la collecte de déchets av

ec des versions plus anciennes de Git, qui ne prot
égeaient pas les objets référencés par les reflogs.

-n, --dry-ru

n
Ne pas réellement élaguer les entrées ; afficher simplement ce qui aurait été
élagué.
