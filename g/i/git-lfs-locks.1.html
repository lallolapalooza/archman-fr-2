NOM

git-lfs-locks - Liste les fichiers actuellement verrouillés depuis le serveur Git LFS.

SYNTAXE

git lfs locks [options]

DESCRIPTION

Liste les verrous actuels du serveur Git LFS.

OPTIONS

-r <nom>, --remote=<nom>

Spécifie le serveur Git LFS à utiliser. Ignoré si la clé de configuration lfs.url est définie.

-i <id>, --id=<id>

Spécifie un verrou par son ID. Retourne un seul résultat.

-p <chemin>, --path=<chemin>

Spécifie un verrou par son chemin. Retourne un seul résultat.

--local

Liste uniquement nos propres verrous qui sont mis en cache localement. Saute un appel distant.

--cached


Liste les verrous mis en cache du dernier appel distant. Contrairement à --local, cela inclura également les verrous d'autres utilisateurs. Cette option est destinée à afficher les derniers verrous connus au cas où vous seriez hors ligne. Il n'y a aucune garantie que les verrous sur le serveur n'aient pas changé entre-temps.

--verify

Vérifie le propriétaire du verrou sur le serveur et marque nos propres verrous par 'O'. Les verrous propres sont réellement détenus par nous et les fichiers correspondants peuvent être mis à jour pour le prochain push. Tous les autres verrous sont détenus par quelqu'un d'autre. Contrairement à --local, cette option détectera également les verrous que nous détenons bien qu'aucune information de verrouillage locale ne soit disponible (par exemple, parce que le fichier avait été verrouillé depuis un autre clone) ; elle détectera également les verrous "cassés" (par exemple, si quelqu'un d'autre a déverrouillé nos fichiers de force).

-l <num>, --limit=<num>

Spécifie le nombre de résultats à retourner.

-j, --json

Écrit les informations de verrouillage au format JSON sur STDOUT si la commande se termine avec succès. Destiné à l'interopérabilité avec des outils externes. Si la commande se termine avec un code de sortie non nul, des messages en texte brut seront envoyés à STDERR.

VOIR AUSSI

git-lfs-lock(1), git-lfs-unlock(1).

Fait partie de la suite git-lfs(1).
