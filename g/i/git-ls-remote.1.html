NOM

git-ls-remote - Lister les références dans un dépôt distant

SYNOPSIS

git ls-remote [--branches] [--tags] [--refs] [--upload-pack=<exécutable>]
              [-q | --quiet] [--exit-code] [--get-url] [--sort=<clé>]
              [--symref] [<dépôt> [<motifs>...]]

DESCRIPTION

Affiche les références disponibles dans un dépôt distant ainsi que les identifiants de commit associés.

OPTIONS

-b, --branches, -t, --tags

Limite aux branches locales et aux tags locaux, respectivement. Ces options ne sont *pas* mutuellement exclusives ; lorsqu'elles sont toutes deux fournies, les références stockées dans refs/heads et refs/tags sont affichées. Notez que --heads et -h sont des synonymes dépréciés pour --branches et -b et pourraient être supprimés à l'avenir. Notez également que git ls-remote -h utilisé sans rien d'autre sur la ligne de commande affiche l'aide, comme les autres sous-commandes git.

--refs

Ne pas montrer les tags pelés ou les pseudoréfs comme HEAD dans la sortie.

-q, --quiet

N'imprime pas l'URL distante sur stderr.

--upload-pack=<exécutable>

Spécifie le chemin complet de git-upload-pack sur l'hôte distant. Cela permet de lister les références des dépôts accessibles via SSH et où le démon SSH n'utilise pas le PATH configuré par l'utilisateur.

--exit-code

Se termine avec le statut "2" lorsqu'aucune référence correspondante n'est trouvée dans le dépôt distant. Habituellement, la commande se termine avec le statut "0" pour indiquer qu'elle a réussi à communiquer avec le dépôt distant, qu'elle ait trouvé ou non des références correspondantes.

--get-url

Développe l'URL du dépôt distant donné en tenant compte de tout paramètre de configuration "url.<base>.insteadOf" (Voir git-config(1)) et se termine sans parler au dépôt distant.

--symref

En plus de l'objet pointé par celui-ci, affiche la référence sous-jacente pointée par celui-ci lors de l'affichage d'une référence symbolique. Actuellement, upload-pack n'affiche que la référence symbolique HEAD, donc ce sera la seule affichée par ls-remote.

--sort=<clé>

Trie en fonction de la clé donnée. Préfixez avec - pour trier dans l'ordre descendant de la valeur. Prend en charge "version:refname" ou "v:refname" (les noms de tags sont traités comme des versions). L'ordre de tri "version:refname" peut également être affecté par la variable de configuration "versionsort.suffix". Voir git-for-each-ref(1) pour plus d'options de tri, mais sachez que les clés comme committerdate qui nécessitent l'accès aux objets eux-mêmes ne fonctionneront pas pour les références dont les objets n'ont pas encore été récupérés du dépôt distant, et produiront une erreur objet manquant.

-o <option>, --server-option=<option>

Transmet la chaîne donnée au serveur lors de la communication en utilisant le protocole version 2. La chaîne donnée ne doit pas contenir de caractère NUL ou LF. Lorsque plusieurs options --server-option=<option> sont données, elles sont toutes envoyées à l'autre partie dans l'ordre où elles sont listées sur la ligne de commande. Lorsqu'aucune option --server-option=<option> n'est donnée sur la ligne de commande, les valeurs de la variable de configuration remote.<nom>.serverOption sont utilisées à la place.

<dépôt>

Le dépôt "distant" à interroger. Ce paramètre peut être une URL ou le nom d'une référence distante (voir les sections URL GIT et RÉFÉRENCES DISTANTES de git-fetch(1)).

<motifs>...

Lorsqu'ils ne sont pas spécifiés, toutes les références, après filtrage effectué avec --heads et --tags, sont affichées. Lorsque <motifs>... sont spécifiés, seules les références correspondant à un ou plusieurs des motifs donnés sont affichées. Chaque motif est interprété comme un glob (voir glob dans gitglossary(7)) qui est comparé à la "partie finale" d'une référence, soit à partir du début de la référence (donc un nom complet comme refs/heads/foo correspond), soit à partir d'un séparateur slash (donc bar correspond à refs/heads/bar mais pas à refs/heads/foobar).

SORTIE

La sortie est au format :

<oid> TAB <ref> LF

Lors de l'affichage d'un tag annoté, sauf si --refs est fourni, deux lignes de ce type sont affichées : une avec le nom de la référence pour le tag lui-même comme <ref>, et une autre avec <ref> suivi de ^{}. Le <oid> sur cette dernière ligne montre le nom de l'objet vers lequel le tag pointe.

EXEMPLES

•Lister toutes les références (y compris symboliques et pseudoréfs), en pelant les tags : 
$ git ls-remote
27d43aaaf50ef0ae014b88bba294f93658016a2e        HEAD
950264636c68591989456e3ba0a5442f93152c1a        refs/heads/main
d9ab777d41f92a8c1684c91cfb02053d7dd1046b        refs/heads/next
d4ca2e3147b409459955613c152220f4db848ee1        refs/tags/v2.40.0
73876f4861cd3d187a4682290ab75c9dccadbc56        refs/tags/v2.40.0^{}
•Lister toutes les références correspondant aux motifs donnés : 
$ git ls-remote http://www.kernel.org/pub/scm/git/git.git master seen rc
5fe978a5381f1fbad26a80e682ddd2a401966740        refs/heads/master
c781a84b5204fb294c9ccc79f8b3baceeb32c061        refs/heads/seen
•Lister uniquement les tags correspondant à un motif joker donné : 
$ git ls-remote --tags http://www.kernel.org/pub/scm/git/git.git v\*
485a869c64a68cc5795dd99689797c5900f4716d        refs/tags/v2.39.2
cbf04937d5b9fcf0a76c28f69e6294e9e3ecd7e6        refs/tags/v2.39.2^{}
d4ca2e3147b409459955613c152220f4db848ee1        refs/tags/v2.40.0
73876f4861cd3d187a4682290ab75c9dccadbc56        refs/tags/v2.40.0^{}
