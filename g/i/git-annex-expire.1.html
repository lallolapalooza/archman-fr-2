git-annex-expire(1) Manuel des commandes générales git-annex-expire(1)

NOM

git-annex-expire - périmer les dépôts inactifs

SYNTAXE

git annex expire [dépôt:]temps ...

DESCRIPTION

Cette commande périme les dépôts qui n'ont pas effectué d'activité spécifiée dans une période donnée. Un dépôt est périmé en le marquant comme mort. La dépérimation est également possible ; si un dépôt mort a récemment effectué une activité, il est marqué comme semi-fiable à nouveau.

Cela peut être utile lorsqu'il n'est pas possible de suivre manuellement l'état des dépôts. Par exemple, un réseau distribué de dépôts où personne ne peut accéder directement à tous les dépôts pour vérifier leur état.

Le dépôt peut être spécifié en utilisant le nom d'une télécommande, ou la description ou l'uuid du dépôt.

Le temps est sous la forme "60d" ou "1y". Un temps de "never" désactivera la périmation.

Si un temps est spécifié sans dépôt, il est utilisé comme valeur par défaut pour tous les dépôts. Notez que le dépôt actuel n'est jamais périmé.

OPTIONS

--no-act
Affiche ce qui serait fait, mais ne périme ni ne dépérime réellement aucun dépôt.
--activity=Nom
Spécifie l'activité qu'un dépôt doit avoir effectuée pour éviter d'être périmé. La valeur par défaut est toute activité.
Actuellement, la seule activité pouvant être effectuée pour éviter la périmation est --activity=Fsck, qui correspond à git annex fsck. Notez que l'exécution de fsck sur une télécommande met à jour la périmation du dépôt distant, pas du dépôt local.
La première version de git-annex qui enregistrait l'activité fsck était 5.20150405.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement envoyés à la sortie d'erreur standard sont inclus dans le JSON à la place.
Les options communes de git-annex-common-options(1) peuvent également être utilisées.
