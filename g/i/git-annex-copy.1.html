NOM

git-annex-copy - copier le contenu de fichiers vers/depuis un autre dépôt

SYNTAXE

git annex copy [chemin ...] [--from=dépôt|--to=dépôt]

DESCRIPTION

Copie le contenu des fichiers depuis ou vers un autre dépôt distant.

Sans paramètres, opère sur tous les fichiers annexés dans le répertoire courant. Les chemins de fichiers ou de répertoires sur lesquels opérer peuvent être spécifiés.

OPTIONS

--from=dépôt
Copie le contenu des fichiers du dépôt distant spécifié vers le dépôt local.
Tous les fichiers qui ne sont pas disponibles sur le dépôt distant seront silencieusement ignorés.
--to=dépôt
Copie le contenu des fichiers du dépôt local vers le dépôt distant spécifié.
--to=ici
Copie le contenu des fichiers de tous les dépôts distants accessibles vers le dépôt local.
--from=dépôt1 --to=dépôt2
Copie le contenu des fichiers qui se trouvent dans dépôt1 vers dépôt2.
Ceci est implémenté en téléchargeant d'abord le contenu depuis dépôt1 vers le dépôt local (s'il n'est pas déjà présent), puis en l'envoyant à dépôt2, et enfin en supprimant le contenu du dépôt local (s'il n'était pas présent à l'origine).
--from-anywhere --to=dépôt
Copie vers le dépôt distant les fichiers depuis le dépôt local ainsi que depuis tous les dépôts distants accessibles.
--jobs=N -JN
Active les transferts parallèles avec jusqu'à N jobs exécutés simultanément. Par exemple : -J10
Définir ceci sur "cpus" exécutera un job par cœur de CPU.
Notez qu'en utilisant --from avec --to, deux fois ce nombre de jobs s'exécuteront simultanément, répartis équitablement entre les deux dépôts.
--auto
Plutôt que de copier tous les fichiers spécifiés, copie uniquement ceux qui n'ont pas encore le nombre souhaité de copies, ou qui sont du contenu préféré du dépôt de destination. Voir git-annex-preferred-content(1)
--fast
Lors de la copie de contenu vers un dépôt distant, évite un aller-retour pour vérifier si le dépôt distant possède déjà le contenu. Cela peut être plus rapide, mais peut dans certains cas sauter la copie de contenu vers le dépôt distant.
--all -A
Plutôt que de spécifier un nom de fichier ou un chemin à copier, cette option peut être utilisée pour copier toutes les versions disponibles de tous les fichiers.
C'est le comportement par défaut lors de l'exécution de git-annex dans un dépôt nu (bare).
--branch=ref
Opère sur les fichiers de la branche ou de l'arbre spécifié.
--unused
Opère sur les fichiers trouvés par la dernière exécution de git-annex unused.
--failed
Opère sur les fichiers dont le transfert a récemment échoué.
--key=nomclé
Utilisez cette option pour copier une clé spécifiée.
options de correspondance
Les options de correspondance de git-annex(1) peuvent être utilisées pour spécifier quoi copier.
--batch
Active le mode batch, dans lequel les lignes contenant les noms de fichiers à copier sont lues depuis stdin.
Au fur et à mesure que chaque fichier spécifié est traité, la sortie de progression habituelle est affichée. Si le contenu d'un fichier n'a pas besoin d'être copié, ou s'il ne correspond pas aux options de correspondance spécifiées, ou s'il ne s'agit pas d'un fichier annexé, une ligne vide est renvoyée en réponse.
Étant donné que la sortie habituelle lors de la copie d'un fichier est verbeuse et non analysable par machine, vous pourriez vouloir utiliser --json en combinaison avec --batch.
--batch-keys
Ceci est similaire à --batch mais les lignes lues depuis stdin sont analysées comme des clés.
-z
Fait en sorte que l'entrée batch soit délimitée par des nulls au lieu des sauts de ligne habituels.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut les objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie d'erreur standard sont inclus dans le JSON à la place.
Les git-annex-common-options(1) peuvent également être utilisés.
