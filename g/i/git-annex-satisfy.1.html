git-annex-satisfy(1) Manuel des commandes générales git-annex-satisfy(1)

NOM

git-annex-satisfy - transfert et suppression de contenu selon la configuration

SYNTAXE

git annex satisfy [distant ...]

DESCRIPTION

Ceci transfère et supprime le contenu des fichiers annexés pour travailler à satisfaire les réglages de contenu préféré du dépôt local et des dépôts distants.

Cela fait la même chose que git-annex sync --content sans le téléchargement et le téléversement des dépôts git, et sans modifier les arbres qui sont importés depuis ou exportés vers des dépôts spéciaux.

Notez que cela (comme git-annex-sync ou git-annex-assist) ne travaille pas spécifiquement à satisfaire le réglage git-annex-numcopies, à moins que le réglage de contenu préféré du dépôt local ne soit écrit pour le faire en utilisant par exemple approxlackingcopies=1.

OPTIONS

[distant]
Par défaut, cette commande opère sur tous les dépôts distants, sauf ceux pour lesquels remote.<nom>.annex-sync est défini à false.
En spécifiant les noms des dépôts distants (ou des groupes de dépôts distants), vous pouvez contrôler ceux sur lesquels opérer.
--content-of=chemin -C chemin
Opère uniquement sur les fichiers dans le chemin spécifié. Par défaut, opère sur tous les fichiers dans l'arbre de travail.
Cette option peut être répétée plusieurs fois avec des chemins différents.
Notez que cette option n'empêche pas l'exportation d'autres fichiers vers un dépôt avec "exporttree=yes".
--jobs=N -JN
Active le traitement parallèle avec jusqu'à N travaux exécutés simultanément. Par exemple : -J10
Définir ceci sur "cpus" exécutera un travail par cœur de CPU.
--all -A
Normalement, cette commande opère sur les fichiers annexés de la branche actuelle. Cette option la fait opérer sur toutes les versions disponibles de tous les fichiers annexés (lorsque les réglages de contenu préféré le permettent).
Notez que les réglages de contenu préféré qui utilisent include= ou exclude= ne correspondront qu'à la version des fichiers actuellement dans l'arbre de travail, mais pas aux versions passées des fichiers.
également les options git-annex-common-options(1) peuvent être utilisées.
