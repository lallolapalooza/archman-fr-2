NOM

git-remote-annex - programme d'aide pour les dépôts distants afin de stocker un dépôt git dans un dépôt distant spécial git-annex

SYNTAXE

git fetch annex::uuid?param=valeur&param=valeur...

DESCRIPTION

Il s'agit d'un programme d'aide pour les dépôts distants git qui permet à git de cloner, de récupérer (pull) et de pousser (push) depuis un dépôt git stocké dans un dépôt distant spécial git-annex avec une URL commençant par "annex::"

Le dépôt distant spécial doit avoir une configuration remote.<nom>.url pour l'utiliser. Ceci est configuré automatiquement lors du clonage git depuis un dépôt distant spécial.

Pour faire en sorte que git-annex-initremote(1) et git-annex-enableremote(1) configurent l'URL, passez-leur l'option --with-url.

Ou, pour configurer un dépôt distant spécial existant avec une URL abrégée, exécutez :

git config remote.nom.url annex::

Une fois l'URL configurée, vous pouvez utiliser git pull, git push, etc. avec le dépôt distant spécial comme avec n'importe quel autre dépôt distant git. Mais consultez la section PUSH CONFLICTUELS ci-dessous pour certaines situations où il se comporte légèrement différemment.

FORMAT URL

Ceci utilise une URL commençant par "annex::". Il existe trois formes d'URL de ce type :

URL complète
Elle contient l'UUID et tous les paramètres de configuration du dépôt distant spécial qui ont été passés lors de l'utilisation de git-annex initremote.
Par exemple, pour cloner depuis un dépôt distant spécial de type répertoire :
git clone annex::358ff77e-0bc3-11ef-bc49-872e6695c0e3?type=directory&encryption=none&directory=/mnt/foo/
URL abrégée
Cela permet de configurer facilement un dépôt distant spécial existant avec une URL sans avoir à trouver l'URL complète.
annex::
Lorsque vous utilisez cette URL abrégée, l'URL complète sera affichée à chaque fois que vous effectuerez un git pull ou push, lorsque git-annex pourra la déterminer. (Bien que dans certains cas, comme pour le dépôt distant spécial de type répertoire, certains paramètres puissent être omis de l'URL affichée.)
URL Web
Cette URL pointe vers un fichier sur le web, qui contient l'URL annex:: complète.
annex::https://example.com/foo-repo
Tous les dépôts distants spéciaux ne peuvent pas être accédés par une telle URL, pour des raisons de sécurité. Actuellement, cela est limité aux dépôts distants spéciaux http.

PUSH CONFLICTUELS

Comme tout dépôt git, un dépôt git stocké sur un dépôt distant spécial peut avoir des conflits lors de pushes effectués depuis différents endroits. Cela fonctionne principalement de la même manière que pour tout autre dépôt git, par exemple, un push qui écrase un autre travail sera empêché à moins d'être forcé.

Cependant, il est possible, lorsque des pushes conflictuels sont effectués simultanément, que l'un des pushes soit écrasé par l'autre. Dans cette situation, le push écrasé semblera avoir réussi, mais un pull ultérieur montrera la situation réelle.

FORMAT DEPOT

Le dépôt git est stocké dans le dépôt distant spécial en utilisant des objets annex spéciaux dont les noms commencent par "GITMANIFEST" et "GITBUNDLE". Pour plus de détails, voir : https://git-annex.branchable.com/internals/git-remote-annex/

Les pushes vers un dépôt distant spécial sont généralement effectués de manière incrémentielle. Cependant, parfois, l'ensemble du dépôt git est re-téléversé. Cela est fait lors du forçage d'un ref, ou de la suppression d'un ref du dépôt distant. C'est également fait lorsque trop de git bundles s'accumulent dans le dépôt distant spécial, comme configuré par le fichier de configuration git remote.<nom>.annex-max-git-bundles.

Notez qu'une re-téléversement du dépôt ne supprime pas les anciens objets GITBUNDLE. Cela signifie que les refs poussés vers le dépôt distant spécial peuvent toujours être accédés même après les avoir supprimés ou écrasés.

Un push qui supprime tous les refs du dépôt distant spécial supprimera tous les objets GITBUNDLE accumulés. Mais bien sûr, effectuer un tel push signifie que quelqu'un qui clone depuis le dépôt distant spécial à ce moment-là verra un dépôt distant vide.
