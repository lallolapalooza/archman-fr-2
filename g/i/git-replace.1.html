SYNOPSI

S 
git replace [-f] <objet> <remplacement>
git replace [-f] --edit <objet>
git replace [-f] --graft <commit> [<parent>...]
git replace [-f] --convert-graft-file
git replace -d <objet>...
git replace [--format=<format>] [-l [<motif>
]
]

DESCRIPTIO

N

Ajoute une référence de remplacement dans refs/replace/

namespace.

Le nom de la référence de remplacement est le SHA-1 de l'objet qui est remplacé. Le contenu de la référence de remplacement est le SHA-1 de l'objet de

remplacement.

L'objet remplacé et l'objet de remplacement doivent être de même type. Cette restriction peut être contournée en utilisant -f

.

Sauf si -f est spécifié, la référence de remplacement ne doit pas encore

exister.

Il n'y a aucune autre restriction sur les objets remplacés et de remplacement. Les commits de fusion peuvent être remplacés par des commits non-fusion et vice

versa.

Les références de remplacement seront utilisées par défaut par toutes les commandes Git, sauf celles effectuant une traversée de joignabilité (prune, transfert de pack et fsck)

.

Il est possible de désactiver l'utilisation des références de remplacement pour n'importe quelle commande en utilisant l'option --no-replace-objects juste après git

.

Par exemple, si le commit foo a été remplacé par le commit bar

: 
$ git --no-repl
ace-objects cat-
file commit foo

affiche des informations sur le commit foo, tandis que

: 
$ git ca
t-file co
mmit foo

affiche des informations sur le commit bar

.

La variable d'environnement GIT_NO_REPLACE_OBJECTS peut être définie pour obtenir le même effet que l'option --no-repla

ce-obj
ects.

OPTION

S

-f,

--force
Si une référence de remplacement existante pour le même objet existe, elle sera écrasée (au lieu de provoquer une erreur)
.

-d,

--delete
Supprime les références de remplacement existantes pour les objets
donnés.

--edit

<objet>
Modifie le contenu d'un objet de manière interactive. Le contenu existant de <objet> est mis en forme dans un fichier temporaire, un éditeur est lancé sur le fichier, et le résultat est analysé pour créer un nouvel objet du même type que <objet>. Une référence de remplacement est ensuite créée pour remplacer <objet> par l'objet nouvellement créé. Voir git-var(1) pour des détails sur la manière dont l'éditeur sera
choisi.

--ra

w
Lors de la modification, fournit le contenu brut de l'objet plutôt que sa mise en forme. Actuellement, cela n'affecte que les arbres (trees), qui seront affichés sous leur forme binaire. Cela est plus difficile à manipuler, mais peut aider lors de la réparation d'un arbre tellement corrompu qu'il ne peut pas être mis en forme. Notez que vous devrez peut-être configurer votre éditeur pour lire et écrire proprement les données
binaires.

--graft <commit> [<parent>...

]
Crée un commit de greffe. Un nouveau commit est créé avec le même contenu que <commit> sauf que ses parents seront [<parent>...] au lieu des parents de <commit>. Une référence de remplacement est ensuite créée pour remplacer <commit> par le commit nouvellement créé. Utilisez --convert-graft-file pour convertir un fichier $GIT_DIR/info/grafts et utiliser les références de remplacement à la
place.

--convert-graft-fil

e
Crée des commits de greffe pour toutes les entrées de $GIT_DIR/info/grafts et supprime ce fichier en cas de succès. Le but est d'aider les utilisateurs à migrer depuis le fichier de greffe désormais
déprécié.

-l <motif>, --list

<motif>
Liste les références de remplacement pour les objets correspondant au motif donné (ou toutes si aucun motif n'est donné). Taper "git replace" sans arguments liste également toutes les références de
remplacement.

--format=<format

>
Lors de la liste, utilise le <format> spécifié, qui peut être l'un des suivants : short, medium et long. Lorsqu'il est omis, le format par défaut est sho
r
t.

S

:
•short :
<sha1-remplacé>
•medium : <sha1-remplacé> → <sha1-remplacement
>
•long : <sha1-remplacé> (<type-remplacé>) →
<sha1-remplacement>

CRÉATION D'OBJETS DE

REMPLACEMENT

git-hash-object(1), git-rebase(1) et git-filter-repo[1], parmi d'autres commandes git, peuvent être utilisés pour créer des objets de remplacement à partir d'objets existants. L'option --edit peut également être utilisée avec git replace pour créer un objet de remplacement en modifiant un objet

existant.

Si vous souhaitez remplacer de nombreux blobs, arbres ou commits faisant partie d'une chaîne de commits, vou

s pouvez simplement créer une chaîne de commits de remplacement puis remplacer uniquement le commit à l'extr
émité de la chaîne cible de commits par le commit à l'extrémité de la chaîne de commits de remplacement.

BOGUE

S

Comparer des blobs ou des arbres qui ont été remplacés avec ceux qui les remplacent ne fonctionnera pas correctement. Et utiliser git reset --hard pour revenir à un commit remplacé déplacera la branche vers le commit de remplacement au lieu du commit

remplacé.

Il peut y avoir d'autres problèmes lors de l'utilisation de git rev-list liés

aux objets
en attente.
