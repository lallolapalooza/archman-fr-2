NOM

git-annex-adjust - entrer dans une branche ajustée

SYNTAXE

git annex adjust --unlock|--lock|--fix|--hide-missing [--unlock|--lock|--fix]|--unlock-present

DESCRIPTION

Entre dans une forme ajustée de la branche courante. Les fichiers annexés seront traités différemment. Par exemple, avec --unlock, tous les fichiers annexés seront déverrouillés.

La branche ajustée aura un nom comme "ajusté/master(déverrouillé)". Puisqu'il s'agit d'une branche git normale, vous pouvez utiliser git checkout pour revenir à la branche originale à tout moment.

Cela permet de modifier la manière dont les fichiers annexés sont gérés, sans apporter de modifications à une branche publique avec des commandes comme git-annex unlock.

Lorsque vous êtes dans la branche ajustée, vous pouvez utiliser les commandes git-annex et git comme d'habitude. Tous les commits que vous effectuez seront initialement effectués uniquement sur la branche ajustée.

Pour propager les commits de la branche ajustée vers la branche originale, et vers d'autres dépôts, ainsi que pour fusionner les changements provenant d'autres dépôts, exécutez git annex sync. Cela propagera les modifications que vous avez apportées, telles que l'ajout/suppression de fichiers, mais ne propagera pas les ajustements effectués par cette commande.

Lorsque vous êtes dans une branche ajustée, utiliser git merge autrebranche n'est souvent pas idéal, car la fusion d'une branche non ajustée peut entraîner des conflits de fusion inutiles, ou ajouter des fichiers sous une forme non ajustée. De plus, ces fusions ne peuvent pas être propagées de la branche ajustée vers la branche originale. Pour éviter ces problèmes, utilisez git annex merge autrebranche.

Réexécuter cette commande avec les mêmes options tout en étant dans la branche ajustée mettra à jour la branche ajustée si nécessaire (par exemple pour --hide-missing et --unlock-present), et propagera également les commits vers la branche originale.

OPTIONS

--unlock
Déverrouille tous les fichiers annexés dans la branche ajustée. Cela permet de modifier les fichiers annexés.
Normalement, le déverrouillage d'un fichier nécessite de faire une copie de son contenu, afin que son contenu original soit préservé, pendant que la copie peut être modifiée. Pour utiliser moins d'espace, annex.thin peut être défini à true avant d'exécuter cette commande ; cela crée un lien physique vers le contenu au lieu d'une copie. (Lorsque pris en charge par le système de fichiers.) Bien que cela puisse économiser considérablement d'espace disque, toute modification apportée à un fichier entraînera la perte de l'ancienne version du fichier du dépôt local. Donc, activez annex.thin avec précaution.
Lorsque vous êtes dans une branche ajustée déverrouillée, git annex add ajoutera les fichiers déverrouillés au lieu du comportement par défaut qui est de les ajouter verrouillés.
--lock
Verrouille tous les fichiers annexés dans la branche ajustée. Ceci peut être préféré par ceux qui aiment voir des liens symboliques brisés lorsque le contenu d'un fichier annexé n'est pas présent.
Lorsque vous êtes dans une branche ajustée verrouillée, git annex add ajoutera les fichiers verrouillés, comme d'habitude. Cependant, git add (et git commit -a etc) ajouteront toujours les fichiers déverrouillés. C'est parce qu'il n'est pas possible pour ces commandes git d'ajouter des fichiers verrouillés.
--fix
Corrige les liens symboliques vers les fichiers annexés pour qu'ils pointent vers le répertoire d'objets annexés de git local. Ceci peut être utile si un dépôt est extrait d'une manière inhabituelle qui empêche les liens symboliques committés dans git de pointer vers les objets annexés.
--hide-missing
N'inclut que les fichiers annexés dans la branche ajustée lorsque leur contenu est présent.
La branche ajustée n'est pas immédiatement modifiée lorsque la disponibilité du contenu change. Ainsi, si vous git annex drop des fichiers, ils deviendront des liens brisés de la manière habituelle. Et lorsque des fichiers qui étaient manquants sont copiés dans le dépôt depuis ailleurs, ils ne deviendront pas immédiatement visibles dans la branche.
Pour mettre à jour la branche ajustée afin de refléter les changements de disponibilité du contenu, exécutez à nouveau git annex adjust --hide-missing. Ou, pour automatiser les mises à jour, définissez la configuration annex.adjustedbranchrefresh.
Malgré le fait que les fichiers manquants soient masqués, git annex sync --content continuera à les traiter, et pourra être utilisé pour télécharger les fichiers manquants depuis des dépôts distants. Il met également à jour la branche ajustée après le transfert de contenu.
Cette option peut être combinée avec --unlock, --lock, ou --fix.
--unlock-present
Déverrouille les fichiers dont le contenu est présent, et verrouille les fichiers dont le contenu est manquant. Ceci offre les avantages de travailler avec des fichiers déverrouillés, mais rend plus facile de voir quand le contenu d'un fichier est manquant, puisqu'il s'agira d'un lien symbolique brisé.
La branche ajustée n'est pas immédiatement modifiée lorsque la disponibilité du contenu change. Ainsi, lorsque vous git annex get des fichiers, ils resteront verrouillés. Et lorsque vous git annex drop des fichiers, ils resteront verrouillés et ne seront donc pas des liens symboliques brisés.
Pour mettre à jour la branche ajustée afin de refléter les changements de disponibilité du contenu, exécutez à nouveau git annex adjust --unlock-present. Ou, pour automatiser les mises à jour, définissez la configuration annex.adjustedbranchrefresh. Ou utilisez git-annex sync --content, qui met à jour la branche après le transfert de contenu.
Les git-annex-common-options(1) peuvent également être utilisés.
