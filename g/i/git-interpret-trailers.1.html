NOM

git-interpret-trailers - Ajouter ou analyser des informations structurées dans les messages de commit

SYNOPSIS

git interpret-trailers [--in-place] [--trim-empty]
                        [(--trailer (<key>|<key-alias>)[(=|:)<value>])...]
                        [--parse] [<file>...]

DESCRIPTION

Ajouter ou analyser des lignes trailer qui ressemblent aux en-têtes d'e-mail RFC 822, à la fin de la partie autrement libre du message de commit. Par exemple, dans le message de commit suivant

sujet
Lorem ipsum dolor sit amet, consectetur adipiscing elit.
Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>

les deux dernières lignes commençant par "Signed-off-by" sont des trailers.

Cette commande lit les messages de commit depuis les arguments <file> ou depuis l'entrée standard si aucun <file> n'est spécifié. Si --parse est spécifié, la sortie se compose des trailers analysés provenant de l'entrée, sans les influencer par des options de ligne de commande ou des variables de configuration.

Sinon, cette commande applique les variables de configuration trailer.* (qui pourraient potentiellement ajouter de nouveaux trailers, ainsi que les repositionner), ainsi que tous les arguments de ligne de commande qui peuvent écraser les variables de configuration (comme --trailer=... qui pourraient aussi ajouter de nouveaux trailers), à chaque fichier d'entrée. Le résultat est émis sur la sortie standard.

Cette commande peut aussi fonctionner sur la sortie de git-format-patch(1), qui est plus élaborée qu'un simple message de commit. Plus précisément, une telle sortie inclut un message de commit (comme ci-dessus), une ligne de séparation "---", et une partie patch. Pour ces entrées, les parties séparation et patch ne sont pas modifiées par cette commande et sont émises telles quelles dans la sortie, sauf si --no-divider est spécifié.

Certaines variables de configuration contrôlent la manière dont les arguments --trailer sont appliqués à chaque entrée et la manière dont tout trailer existant dans l'entrée est modifié. Elles rendent aussi possible l'ajout automatique de certains trailers.

Par défaut, un argument <key>=<value> ou <key>:<value> donné en utilisant --trailer sera ajouté après les trailers existants seulement si le dernier trailer a une paire (<key>, <value>) différente (ou s'il n'y a pas de trailer existant). Les parties <key> et <value> seront nettoyées pour supprimer les espaces de début et de fin, et le <key> et <value> résultants apparaîtront dans la sortie comme ceci :

key: value

Cela signifie que le <key> et <value> nettoyés seront séparés par ': ' (un deux-points suivi d'une espace).

Par commodité, un <key-alias> peut être configuré pour rendre l'utilisation de --trailer plus courte à taper sur la ligne de commande. Cela peut être configuré en utilisant la variable de configuration trailer.<key-alias>.key . Le <keyAlias> doit être un préfixe de la chaîne complète <key>, bien que la sensibilité à la casse n'ait pas d'importance. Par exemple, si vous avez

trailer.sign.key "Signed-off-by: "

dans votre configuration, vous n'avez besoin que de spécifier --trailer="sign: foo" sur la ligne de commande au lieu de --trailer="Signed-off-by: foo".

Par défaut, le nouveau trailer apparaîtra à la fin de tous les trailers existants. S'il n'y a pas de trailer existant, le nouveau trailer apparaîtra à la fin de l'entrée. Une ligne vide sera ajoutée avant le nouveau trailer s'il n'y en a pas déjà une.

Les trailers existants sont extraits de l'entrée en cherchant un groupe d'une ou plusieurs lignes qui (i) est entièrement composé de trailers, ou (ii) contient au moins un trailer généré par Git ou configuré par l'utilisateur et se compose d'au moins 25% de trailers. Le groupe doit être précédé d'une ou plusieurs lignes vides (ou composées uniquement d'espaces). Le groupe doit soit être à la fin de l'entrée, soit être les dernières lignes non-blanches avant une ligne qui commence par --- (suivi d'une espace ou de la fin de la ligne).

Lors de la lecture des trailers, il ne peut pas y avoir d'espaces avant ou à l'intérieur du <key>, mais un nombre quelconque d'espaces et de tabulations est autorisé entre le <key> et le séparateur. Il peut y avoir des espaces avant, à l'intérieur ou après le <value>. Le <value> peut être réparti sur plusieurs lignes, chaque ligne suivante commençant par au moins un espace, comme le "pliage" dans RFC 822. Exemple :

key: This is a very long value, with spaces and
  newlines in it.

Notez que les trailers ne suivent pas (et ne sont pas destinés à suivre) beaucoup des règles des en-têtes RFC 822. Par exemple, ils ne suivent pas la règle d'encodage.

OPTIONS

--in-place

Modifier les fichiers sur place.

--trim-empty

Si la partie <value> d'un trailer contient uniquement des espaces, le trailer entier sera supprimé de la sortie. Cela s'applique aux trailers existants ainsi qu'aux nouveaux trailers.

--trailer <key>[(=|:)<value>]

Spécifier une paire (<key>, <value>) qui doit être appliquée comme trailer aux entrées. Voir la description de cette commande.

--where <placement>, --no-where

Spécifier où tous les nouveaux trailers seront ajoutés. Un réglage fourni avec --where écrase trailer.where et toute variable de configuration trailer.<keyAlias>.where applicable et s'applique à toutes les options --trailer jusqu'à la prochaine occurrence de --where ou --no-where. Lors de la rencontre de --no-where, effacer l'effet de toute utilisation précédente de --where, de sorte que les variables de configuration pertinentes ne soient plus écrasées. Les emplacements possibles sontafter ,before , end oustart

.

--if-exists <action>, --no-if-exists Spécifier quelle action sera effectuée quand il y a déjà au moins un trailer avec le même <key> dans l'entrée. Un réglage fourni avec --if-exists écrase trailer.ifExists et toute variable de configurationtrailer.<keyAlias> .ifExists applicable et s'applique à toutes les options --trailer jusqu'à la prochaine occurrence de --if-exists ou--no-if-exists . Lors de la rencontre de--no-if-exists , effacer l'effet de toute utilisation précédente de--if-exists , de sorte que les variables de configuration pertinentes ne soient plus écrasées. Les actions possibles sontaddIfDifferent ,addIfDifferentNeighbor ,add , replace etdoNothing

.

--if-missing <action>, --no-if-missing Spécifier quelle action sera effectuée quand il n'y a pas d'autre trailer avec le même <key> dans l'entrée. Un réglage fourni avec --if-missing écrase trailer.ifMissing et toute variable de configurationtrailer.<keyAlias> .ifMissing applicable et s'applique à toutes les options --trailer jusqu'à la prochaine occurrence de --if-missing ou--no-if-missing . Lors de la rencontre de--no-if-missing , effacer l'effet de toute utilisation précédente de--if-missing , de sorte que les variables de configuration pertinentes ne soient plus écrasées. Les actions possibles sont doNothing ouadd

.

--only-trailers

Afficher uniquement les trailers, et non les autres parties de l'entrée.

--only-input Afficher uniquement les trailers qui existent dans l'entrée ; ne pas en ajouter depuis la ligne de commande ou en appliquant les variables de configuration trailer.*

.

--unfold

Si un trailer a une valeur qui s'étend sur plusieurs lignes (aussi appelée "pliée"), reformatage de la valeur en une seule ligne.

--parse Un alias pratique pour --only-trailers --only-input--unfold

. Cela facilite la visualisation des seuls trailers provenant de l'entrée sans les influencer par des options de ligne de commande ou des variables de configuration, tout en rendant la sortie compatible avec les machines grâce à --unfold.

--no-divider Ne pas traiter --- comme la fin du message de commit. Utilisez cette option quand vous savez que votre entrée contient uniquement le message de commit lui-même (et non un e-mail ou la sortie de gitformat-patch

).

VARIABLES DE CONFIGURATION Tout ce qui se trouve sous cette ligne dans cette section est inclus sélectivement à partir de la ig.1.fr'>documentation de git-config(1). Le contenu est identique à celui qui s’y trouve :

trailer.separators

Cette option indique quels caractères sont reconnus comme séparateurs de remorques (trailers). Par défaut, seul : est reconnu comme séparateur de remorque, à l'exception du fait que = est toujours accepté en ligne de commande pour la compatibilité avec d'autres commandes git.

Le premier caractère spécifié par cette option sera le caractère par défaut utilisé lorsqu'un autre séparateur n'est pas spécifié dans la configuration pour cette remorque.

Par exemple, si la valeur de cette option est "%=$", alors seules les lignes utilisant le format <clé><sep><valeur> avec <sep> contenant %, = ou $ puis des espaces seront considérées comme des remorques. Et % sera le séparateur par défaut utilisé, donc par défaut les remorques apparaîtront comme ceci : <clé>% <valeur> (un signe de pourcentage et un espace apparaîtront entre la clé et la valeur).

trailer.where

Cette option indique où une nouvelle remorque sera ajoutée.

Cela peut être end, ce qui est la valeur par défaut, start, after ou before.

Si c'est end, alors chaque nouvelle remorque apparaîtra à la fin des remorques existantes.

Si c'est start, alors chaque nouvelle remorque apparaîtra au début, au lieu de la fin, des remorques existantes.

Si c'est after, alors chaque nouvelle remorque apparaîtra juste après la dernière remorque avec la même <clé>.

Si c'est before, alors chaque nouvelle remorque apparaîtra juste avant la première remorque avec la même <clé>.

trailer.ifexists

Cette option permet de choisir quelle action sera effectuée lorsqu'il existe déjà au moins une remorque avec la même <clé> dans l'entrée.

Les valeurs valides pour cette option sont : addIfDifferentNeighbor (valeur par défaut), addIfDifferent, add, replace ou doNothing.

Avec addIfDifferentNeighbor, une nouvelle remorque sera ajoutée uniquement s'il n'y a pas de remorque avec la même paire (<clé>, <valeur>) au-dessus ou en dessous de la ligne où la nouvelle remorque sera ajoutée.

Avec addIfDifferent, une nouvelle remorque sera ajoutée uniquement s'il n'y a pas de remorque avec la même paire (<clé>, <valeur>) déjà présente dans l'entrée.

Avec add, une nouvelle remorque sera ajoutée, même si des remorques avec la même paire (<clé>, <valeur>) sont déjà présentes dans l'entrée.

Avec replace, une remorque existante avec la même <clé> sera supprimée et la nouvelle remorque sera ajoutée. La remorque supprimée sera celle qui est la plus proche (avec la même <clé>) de l'endroit où la nouvelle sera ajoutée.

Avec doNothing, rien ne sera fait ; c'est-à-dire qu'aucune nouvelle remorque ne sera ajoutée s'il en existe déjà une avec la même <clé> dans l'entrée.

trailer.ifmissing

Cette option permet de choisir quelle action sera effectuée lorsqu'il n'y a pas encore de remorque avec la même <clé> dans l'entrée.

Les valeurs valides pour cette option sont : add (valeur par défaut) et doNothing.

Avec add, une nouvelle remorque sera ajoutée.

Avec doNothing, rien ne sera fait.

trailer.<keyAlias>.key

Définit un <keyAlias> pour la <key>. La <keyAlias> doit être un préfixe (insensible à la casse) de la <key>. Par exemple, dans git config trailer.ack.key "Acked-by", "Acked-by" est la <key> et "ack" est la <keyAlias>. Cette configuration permet l'invocation plus courte --trailer "ack:..." en ligne de commande en utilisant la <keyAlias> "ack" au lieu de la plus longue --trailer "Acked-by:...".

À la fin de la <key>, un séparateur peut apparaître suivi de quelques espaces. Par défaut, le seul séparateur valide est :, mais cela peut être modifié en utilisant la variable de configuration trailer.separators.

S'il y a un séparateur dans la clé, il remplace le séparateur par défaut lors de l'ajout de la remorque.

trailer.<keyAlias>.where

Cette option prend les mêmes valeurs que la variable de configuration trailer.where et elle remplace ce qui est spécifié par cette option pour les remorques avec la <keyAlias> spécifiée.

trailer.<keyAlias>.ifexists

Cette option prend les mêmes valeurs que la variable de configuration trailer.ifexists et elle remplace ce qui est spécifié par cette option pour les remorques avec la <keyAlias> spécifiée.

trailer.<keyAlias>.ifmissing

Cette option prend les mêmes valeurs que la variable de configuration trailer.ifmissing et elle remplace ce qui est spécifié par cette option pour les remorques avec la <keyAlias> spécifiée.

trailer.<keyAlias>.command

Obsolète au profit de trailer.<keyAlias>.cmd. Cette option se comporte de la même manière que trailer.<keyAlias>.cmd, à l'exception qu'elle ne passe rien comme argument à la commande spécifiée. Au lieu de cela, la première occurrence de la sous-chaîne $ARG est remplacée par la <valeur> qui serait passée comme argument.

Notez que $ARG dans la commande de l'utilisateur n'est remplacé qu'une seule fois et que l'ancienne méthode de remplacement de $ARG n'est pas sûre.

Lorsque trailer.<keyAlias>.cmd et trailer.<keyAlias>.command sont tous deux donnés pour la même <keyAlias>, trailer.<keyAlias>.cmd est utilisé et trailer.<keyAlias>.command est ignoré.

trailer.<keyAlias>.cmd

Cette option peut être utilisée pour spécifier une commande shell qui sera appelée une fois pour ajouter automatiquement une remorque avec la <keyAlias> spécifiée, puis appelée chaque fois qu'un argument --trailer <keyAlias>=<valeur> est spécifié pour modifier la <valeur> de la remorque que cette option produirait.

Lorsque la commande spécifiée est appelée pour la première fois pour ajouter une remorque avec la <keyAlias> spécifiée, le comportement est comme si un argument spécial --trailer <keyAlias>=<valeur> avait été ajouté au début de la commande "git interpret-trailers", où <valeur> est prise comme sortie standard de la commande, avec les espaces blancs en début et fin supprimés.

Si des arguments --trailer <keyAlias>=<valeur> sont également passés en ligne de commande, la commande est appelée à nouveau une fois pour chacun de ces arguments avec la même <keyAlias>. Et la partie <valeur> de ces arguments, s'il y en a, sera passée à la commande comme son premier argument. De cette façon, la commande peut produire une <valeur> calculée à partir de la <valeur> passée dans l'argument --trailer <keyAlias>=<valeur>.

EXEMPLES

•Configurer une remorque sign avec une clé Signed-off-by, puis ajouter deux de ces remorques à un fichier de message de commit : 
$ git config trailer.sign.key "Signed-off-by"
$ cat msg.txt
subject
body text
$ git interpret-trailers --trailer 'sign: Alice <alice@example.com>' --trailer 'sign: Bob <bob@example.com>' <msg.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>
•Utiliser l'option --in-place pour modifier un fichier de message de commit sur place : 
$ cat msg.txt
subject
body text
Signed-off-by: Bob <bob@example.com>
$ git interpret-trailers --trailer 'Acked-by: Alice <alice@example.com>' --in-place msg.txt
$ cat msg.txt
subject
body text
Signed-off-by: Bob <bob@example.com>
Acked-by: Alice <alice@example.com>
•Extraire le dernier commit sous forme de patch, et y ajouter une remorque Cc et une remorque Reviewed-by : 
$ git format-patch -1
0001-foo.patch
$ git interpret-trailers --trailer 'Cc: Alice <alice@example.com>' --trailer 'Reviewed-by: Bob <bob@example.com>' 0001-foo.patch >0001-bar.patch
•Configurer une remorque sign avec une commande pour ajouter automatiquement un 'Signed-off-by: ' avec uniquement les informations de l'auteur si aucun 'Signed-off-by: ' n'est déjà présent, et montrer comment cela fonctionne : 
$ cat msg1.txt
subject
body text
$ git config trailer.sign.key "Signed-off-by: "
$ git config trailer.sign.ifmissing add
$ git config trailer.sign.ifexists doNothing
$ git config trailer.sign.cmd 'echo "$(git config user.name) <$(git config user.email)>"'
$ git interpret-trailers --trailer sign <msg1.txt

$ cat msg2.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
$ git interpret-trailers --trailer sign <msg2.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
•Configurer une remorque fix avec une clé contenant un # et aucun espace après ce caractère, et montrer comment cela fonctionne : 
$ git config trailer.separators ":#"
$ git config trailer.fix.key "Fix #"
$ echo "subject" | git interpret-trailers --trailer fix=42
subject
Fix #42
•Configurer une remorque help avec une commande utilisant un script glog-find-author qui recherche l'identité d'un auteur spécifié dans le log git du dépôt git et montrer comment cela fonctionne : 
$ cat ~/bin/glog-find-author

test -n "$1" && git log --author="$1" --pretty="%an <%ae>" -1 || true
$ cat msg.txt

body text
$ git config trailer.help.key "Helped-by: "
$ git config trailer.help.ifExists "addIfDifferentNeighbor"
$ git config trailer.help.cmd "~/bin/glog-find-author"
$ git interpret-trailers --trailer="help:Junio" --trailer="help:Couder" <msg.txt
subject
body text
Helped-by: Junio C Hamano <gitster@pobox.com>
Helped-by: Christian Couder <christian.couder@gmail.com>

$ git config trailer.ref.ifExists "replace"

body text
