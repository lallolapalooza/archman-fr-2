NOM

git-name-rev - Trouver des noms symboliques pour des révisions données

SYNTAXE

git name-rev [--tags] [--refs=<modèle>]
               ( --all | --annotate-stdin | <commit-ish>... )

DESCRIPTION

Trouve des noms symboliques appropriés pour être lus par des humains pour des révisions données dans un format quelconque reconnaissable par git rev-parse.

OPTIONS

--tags

Ne pas utiliser les noms de branches, mais uniquement les étiquettes (tags) pour nommer les commits.

--refs=<modèle>

Utiliser uniquement les refs dont les noms correspondent au modèle shell donné. Le modèle peut être un nom de branche, un nom d'étiquette, ou un nom de ref entièrement qualifié. Si donné plusieurs fois, utiliser les refs dont les noms correspondent à n'importe lequel des modèles shell donnés. Utiliser --no-refs pour effacer tout modèle de ref précédemment donné.

--exclude=<modèle>

Ne pas utiliser de ref dont le nom correspond au modèle shell donné. Le modèle peut être un nom de branche, un nom d'étiquette ou un nom de ref entièrement qualifié. S'il est donné plusieurs fois, une ref sera exclue lorsqu'elle correspondra à n'importe lequel des modèles donnés. Utilisé conjointement avec --refs, une ref sera utilisée comme correspondance uniquement si elle correspond à au moins un modèle --refs et ne correspond à aucun modèle --exclude. Utiliser --no-exclude pour effacer la liste des modèles d'exclusion.

--all

Lister tous les commits accessibles depuis toutes les refs.

--annotate-stdin

Transformer stdin en substituant tous les SHA-1 hexadécimaux de 40 caractères (disons $hex) par "$hex ($nom_rev)". Utilisé avec --name-only, substituer par "$nom_rev", omettant $hex complètement. Cette option était appelée --stdin dans les anciennes versions de Git.

Par exemple :

$ cat sample.txt
Une révision abrégée 2ae0a9cb82 ne sera pas substituée.
Le nom complet après substitution est 2ae0a9cb8298185a94e5998086f380a355dd8907,
tandis que son objet arbre est 70d105cc79e63b81cfdcb08a15297c23e60b07ad
$ git name-rev --annotate-stdin <sample.txt
Une révision abrégée 2ae0a9cb82 ne sera pas substituée.
Le nom complet après substitution est 2ae0a9cb8298185a94e5998086f380a355dd8907 (master),
tandis que son objet arbre est 70d105cc79e63b81cfdcb08a15297c23e60b07ad
$ git name-rev --name-only --annotate-stdin <sample.txt
Une révision abrégée 2ae0a9cb82 ne sera pas substituée.
Le nom complet après substitution est master,
tandis que son objet arbre est 70d105cc79e63b81cfdcb08a15297c23e60b07ad

--name-only

Au lieu d'imprimer à la fois le SHA-1 et le nom, n'imprimer que le nom. Si donné avec --tags, le préfixe habituel des tags de "tags/" est également omis du nom, ce qui correspond plus étroitement à la sortie de git-describe.

--no-undefined

Mourir avec un code d'erreur != 0 lorsqu'une référence est indéfinie, au lieu d'imprimer undefined.

--always

Afficher un commit unique abrégé comme solution de repli.

EXEMPLES

Étant donné un commit, découvrir où il se situe par rapport aux refs locales. Disons que quelqu'un vous a parlé de ce commit fantastique 33db5f4d9027a10e477ccf054b2c1ab94f74c85a. Bien sûr, vous regardez le commit, mais cela ne vous dit que ce qui s'est passé, pas le contexte.

Entrez git name-rev :

% git name-rev 33db5f4d9027a10e477ccf054b2c1ab94f74c85a
33db5f4d9027a10e477ccf054b2c1ab94f74c85a tags/v0.99~940

Maintenant, vous êtes plus sage, car vous savez qu'il s'est produit 940 révisions avant v0.99.

Une autre chose agréable que vous pouvez faire est :

% git log | git name-rev --annotate-stdin
