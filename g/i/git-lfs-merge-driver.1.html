NOM

git-lfs-merge-driver - Fusionne les fichiers LFS textuels

SYNTAXE

git lfs merge-driver [options]

DESCRIPTION

Fusionne les fichiers textuels stockés dans Git LFS en utilisant le mécanisme de fusion par défaut de Git, ou un pilote de fusion personnalisé si spécifié. Notez que cela, en général, ne prend pas en charge les renommages ou copies partiels car Git ne les prend pas en charge dans ce cas.

Ce programme est destiné à être appelé automatiquement par Git et non manuellement par les utilisateurs. Voir CONFIGURATION pour les détails sur la configuration requise à cet effet.

OPTIONS

--ancestor <chemin>

Spécifie le fichier contenant la révision ancestrale.

--current <chemin>

Spécifie le fichier contenant la révision courante.

--marker-size <nombre>

Spécifie la taille des marqueurs de conflit sous forme d'entier.

--other <chemin>

Spécifie le fichier contenant l'autre révision.

--program <programme>

Spécifie une commande, qui est passée au shell après substitution, qui effectue la fusion réelle. Si elle n'est pas spécifiée, git merge-file est appelé avec les arguments appropriés pour effectuer la fusion du fichier.

Voir CONFIGURATION pour les séquences qui sont substituées ici.

CONFIGURATION

Git autorise l'utilisation d'un pilote de fusion personnalisé pour les fichiers basé sur l'attribut merge défini dans .gitattributes. Par défaut, lors de l'utilisation de git lfs track, cette valeur est définie sur lfs.

Étant donné que Git LFS peut être utilisé pour stocker des fichiers textuels et binaires et qu'il n'est pas toujours clair quel comportement devrait être utilisé, Git LFS n'active pas ce pilote de fusion par défaut. Cependant, si vous savez que certains ou tous vos fichiers sont des fichiers textuels, vous pouvez définir l'attribut merge pour ces fichiers sur lfs-text et utiliser git config pour définir le pilote de fusion comme suit :

$ git config merge.lfs-text.driver 'git lfs merge-driver --ancestor %O --current %A --other %B --marker-size %L --output %A'

Cela indique à Git d'appeler le pilote de fusion personnalisé Git LFS, qui à son tour utilise le mécanisme de fusion de Git, pour fusionner les fichiers où l'attribut merge est défini sur lfs-text. Notez que lfs-text est ici un exemple et toute valeur syntaxiquement valide peut être utilisée.

Si vous utilisez un type de fichier spécial nécessitant des règles différentes du mécanisme de fusion standard de Git, vous pouvez également spécifier l'option --program, qui est passée à sh après la substitution de ses propres échappements encodés en pourcentage :

•%A: la version courante
•%B: l'autre version
•%D: la version de destination
•%O: la version ancestrale
•%L: la taille du marqueur de conflit

Notez que le signe pourcentage doit généralement être doublé pour éviter que Git ne substitue ses propres valeurs ici. Par conséquent, spécifier le comportement par défaut explicitement ressemble à ceci :

$ git config merge.lfs-text.driver \
  'git lfs merge-driver --ancestor %O --current %A --other %B --marker-size %L --output %A --program '\''git merge-file --stdout --marker-size=%%L %%A %%O %%B >%%D'\'''

Le code de sortie de la commande personnalisée doit être zéro en cas de succès ou non nul en cas de conflits ou d'autres échecs.

Notez que si aucun pilote de fusion n'est spécifié pour la valeur de l'attribut merge (comme c'est le cas par défaut avec merge=lfs), alors la stratégie de fusion par défaut de Git est utilisée. Pour les fichiers LFS, cela signifie que Git tentera de fusionner les fichiers pointeurs, ce qui n'est généralement pas utile.
