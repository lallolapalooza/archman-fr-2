NOM

git-annex-find - liste les fichiers disponibles

SYNOPSIS

git annex find [chemin ...]

DESCRIPTION

Affiche une liste des fichiers annexés dans le chemin spécifié. Sans chemin, recherche les fichiers dans le répertoire courant et ses sous-répertoires.

OPTIONS

options de correspondance
Les git-annex-matching-options(1) peuvent être utilisées pour spécifier les fichiers à lister.
Par défaut, la commande find ne liste que les fichiers annexés dont le contenu est actuellement présent. La spécification de l'une des options de correspondance annulera ce comportement par défaut.
Pour lister tous les fichiers annexés, présents ou non, spécifiez --anything.
Pour lister les fichiers annexés dont le contenu n'est pas présent, spécifiez --not --in=here
--branch=ref
Liste les fichiers dans la branche ou l'arbre spécifié.
--print0
Affiche les noms de fichiers terminés par des nulls, pour utilisation avec xargs -0
--format=valeur
Utilise un formatage de sortie personnalisé.
La valeur est une chaîne de format, dans laquelle '${var}' est développé en la valeur d'une variable. Pour justifier à droite une variable avec des espaces, utilisez '${var;largeur}' ; pour justifier à gauche une variable, utilisez '${var;-largeur}' ; pour échapper les caractères inhabituels (y compris les caractères de contrôle) dans une variable, utilisez '${var_echappee}'
Ces variables sont disponibles pour utilisation dans les formats : file, key, backend, bytesize, humansize, keyname, hashdirlower, hashdirmixed, mtime (pour le champ mtime d'une clé WORM).
De plus, '\n' est un saut de ligne, '\000' est un NULL, etc.
Le format de sortie par défaut est le même que --format='${file}\n', sauf lors de l'affichage sur un terminal, où les caractères de contrôle seront échappés.
--json
Affiche la liste des fichiers au format JSON.
Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie d'erreur standard sont inclus dans le JSON à la place.
--batch
Active le mode lot, dans lequel un fichier est lu ligne par ligne depuis l'entrée standard, ses informations sont affichées, et le processus se répète.
Notez que si le fichier n'est pas un fichier annexé, ou n'est pas présent, ou ne satisfait pas autrement aux options de correspondance, une ligne vide sera affichée à la place.
-z
Fait en sorte que l'entrée --batch soit délimitée par des nulls au lieu des sauts de ligne habituels.
Les git-annex-common-options(1) peuvent également être utilisés.
