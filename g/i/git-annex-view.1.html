NOM

git-annex-view - entrer dans une branche de visualisation

SYNTAXE

git annex view [tag ...] [champ=valeur ...] [champ=glob ...] [?tag ...] [champ?=glob] [!tag ...] [champ!=valeur ...]

DESCRIPTION

Utilise les métadonnées pour construire une branche de visualisation des fichiers de la branche actuelle, et valide la branche de visualisation. Seuls les fichiers de la branche actuelle dont les métadonnées correspondent à toutes les valeurs de champ et tags spécifiés seront affichés dans la visualisation.

Plusieurs valeurs pour un champ de métadonnées peuvent être spécifiées, soit en utilisant un glob (champ="*") soit en listant chaque valeur souhaitée. La visualisation résultante placera les fichiers dans des sous-répertoires en fonction de la valeur de leurs champs.

Une fois dans une telle visualisation, vous pouvez créer des répertoires supplémentaires, et y copier ou déplacer des fichiers. Lorsque vous validez, les métadonnées seront mises à jour pour correspondre à vos modifications. La suppression de fichiers et la validation mettent également à jour les métadonnées.

Outre les métadonnées habituelles, il existe des champs disponibles correspondant au chemin du fichier. Ainsi, un fichier "foo/bar/baz/fichier" a les champs "/=foo", "foo/=bar" et "foo/bar/=baz". Ces champs de localisation peuvent être utilisés de la même manière que d'autres métadonnées pour construire la visualisation.

Par exemple, /=foo n'inclura que les fichiers du répertoire foo dans la visualisation, tandis que foo/=* conservera les sous-répertoires du répertoire foo dans la visualisation.

Pour entrer dans une visualisation ne contenant que des fichiers qui manquent une valeur de métadonnée ou un tag donné, spécifiez champ!=valeur ou !tag. (Les globs ne peuvent pas être utilisés ici.)

champ?=* est comme champ=* mais ajoute un répertoire supplémentaire nommé _ (par défaut) qui contient les fichiers qui ne possèdent pas le champ défini sur aucune valeur. De même, ?tag ajoute un répertoire supplémentaire nommé _ qui contient les fichiers qui n'ont aucun tag défini. Le déplacement de fichiers du répertoire _ vers un autre répertoire et la validation définiront les métadonnées. Le déplacement de fichiers vers le répertoire _ et la validation effaceront les métadonnées.

Le nom du répertoire _ peut être modifié à l'aide de la configuration git annex.viewunsetdirectory.

Les noms de fichiers dans la branche de visualisation incluent leur chemin dans la branche d'origine, pour garantir qu'ils sont uniques. Le chemin vient après le nom de fichier principal, et avant toute extension. Par exemple, "foo/bar.baz" aura un nom comme "bar_%foo%.baz". annex.maxextensionlength peut être utilisé pour configurer ce qui est traité comme une extension.

OPTIONS

Les git-annex-common-options(1) peuvent être utilisés.
