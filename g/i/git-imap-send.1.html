NOM

git-imap-send - Envoie une collection de patches depuis stdin vers un dossier IMAP

SYNOPSIS

git imap-send [-v] [-q] [--[no-]curl] [(--folder|-f) <dossier>]
git imap-send --list

DESCRIPTION

Cette commande télécharge une boîte aux lettres générée avec git format-patch vers un dossier de brouillons IMAP. Cela permet d'envoyer des patches comme n'importe quel autre courriel lors de l'utilisation de clients de messagerie qui ne peuvent pas lire directement les fichiers de boîte aux lettres. La commande fonctionne également avec n'importe quelle boîte aux lettres générale dans laquelle les courriels ont les champs From, Dateet Subject dans cet ordre.

L'utilisation typique est quelque chose comme :

$ git format-patch --signoff --stdout --attach origin | git imap-send

OPTIONS

-v, --verbose

Être bavard.

-q, --quiet

Être silencieux.

-f <dossier>, --folder=<dossier>

Spécifier le dossier dans lequel les courriels doivent être enregistrés. Par exemple : --folder=[Gmail]/Drafts ou -f INBOX/Drafts.

--curl

Utiliser libcurl pour communiquer avec le serveur IMAP, sauf en cas de tunnel vers celui-ci. Ignoré si Git a été compilé sans l'option USE_CURL_FOR_IMAP_SEND.

--no-curl

Communiquer avec le serveur IMAP en utilisant les routines IMAP propres à git au lieu d'utiliser libcurl. Ignoré si Git a été compilé avec l'option NO_OPENSSL.

--list

Exécuter la commande IMAP LIST pour afficher une liste de tous les dossiers présents.

CONFIGURATION

Pour utiliser l'outil, imap.folder et soit imap.tunnel soit imap.host doivent être définis avec des valeurs appropriées.

Tout ce qui se trouve au-dessus de cette ligne dans cette section n'est pas inclus depuis la git-config(1) documentation. Le contenu qui suit est identique à celui qui s'y trouve :

imap.folder

Le dossier dans lequel déposer les courriels, qui est généralement le dossier Drafts. Par exemple : INBOX.Drafts, INBOX/Drafts ou [Gmail]/Drafts. Le dossier IMAP avec lequel interagir DOIT être spécifié ; la valeur de cette variable de configuration est utilisée comme valeur par défaut de secours lorsque l'option --folder n'est pas donnée.

imap.tunnel

Commande utilisée pour établir un tunnel vers le serveur IMAP à travers lequel les commandes seront acheminées au lieu d'utiliser une connexion réseau directe au serveur. Requis lorsque imap.host n'est pas défini.

imap.host

Une URL identifiant le serveur. Utilisez un préfixe imap:// pour les connexions non sécurisées et un préfixe imaps:// pour les connexions sécurisées. Ignoré lorsque imap.tunnel est défini, mais requis dans le cas contraire.

imap.user

Le nom d'utilisateur à utiliser lors de la connexion au serveur.

imap.pass

Le mot de passe à utiliser lors de la connexion au serveur.

imap.port

Un numéro de port entier sur lequel se connecter sur le serveur. Par défaut 143 pour les hôtes imap:// et 993 pour les hôtes imaps://. Ignoré lorsque imap.tunnel est défini.

imap.sslverify

Un booléen pour activer/désactiver la vérification du certificat du serveur utilisé par la connexion SSL/TLS. La valeur par défaut est true. Ignoré lorsque imap.tunnel est défini.

imap.preformattedHTML

Un booléen pour activer/désactiver l'utilisation de l'encodage HTML lors de l'envoi d'un patch. Un patch encodé en HTML sera entouré de <pre> et aura un type de contenu text/html. Ironiquement, activer cette option fait que Thunderbird envoie le patch en tant que courriel plain/text, format=fixed. La valeur par défaut est false.

imap.authMethod

Spécifier la méthode d'authentification pour s'authentifier auprès du serveur IMAP. Si Git a été compilé avec l'option NO_CURL, ou si votre version de curl est antérieure à 7.34.0, ou si vous exécutez git-imap-send avec l'option --no-curl , les seules méthodes prises en charge sont PLAIN, CRAM-MD5, OAUTHBEARER et XOAUTH2. Si cela n'est pas défini, alors git imap-send utilise la commande IMAP de base en texte clair LOGIN .

OBTENIR UNE LISTE DES DOSSIERS DISPONIBLES

Afin d'envoyer un courriel vers un dossier spécifique, vous devez connaître le nom correct du dossier souhaité dans votre boîte aux lettres. Les noms comme "Junk", "Trash" etc. affichés par divers clients de messagerie ne sont pas nécessairement les noms réels des dossiers stockés sur le serveur de messagerie de votre fournisseur.

Afin d'obtenir le nom de dossier correct à utiliser avec git imap-send, vous pouvez exécuter git imap-send --list. Cela affichera une liste de noms de dossiers valides. Un exemple de tel résultat lors de l'exécution sur un compte Gmail est :

* LIST (\HasNoChildren) "/" "INBOX"
* LIST (\HasChildren \Noselect) "/" "[Gmail]"
* LIST (\All \HasNoChildren) "/" "[Gmail]/All Mail"
* LIST (\Drafts \HasNoChildren) "/" "[Gmail]/Drafts"
* LIST (\HasNoChildren \Important) "/" "[Gmail]/Important"
* LIST (\HasNoChildren \Sent) "/" "[Gmail]/Sent Mail"
* LIST (\HasNoChildren \Junk) "/" "[Gmail]/Spam"
* LIST (\Flagged \HasNoChildren) "/" "[Gmail]/Starred"
* LIST (\HasNoChildren \Trash) "/" "[Gmail]/Trash"

Ici, vous pouvez observer que le nom correct pour le dossier "Junk" est [Gmail]/Spam et pour le dossier "Trash" est [Gmail]/Trash. Une logique similaire peut être utilisée pour déterminer les autres dossiers également.

EXEMPLES

Utilisation du mode tunnel :

[imap]
    folder = "INBOX.Drafts"
    tunnel = "ssh -q -C user@example.com /usr/bin/imapd ./Maildir 2> /dev/null"

Utilisation du mode direct :

[imap]
    folder = "INBOX.Drafts"
    host = imap://imap.example.com
    user = bob
    pass = p4ssw0rd

Utilisation du mode direct avec SSL :

[imap]
    folder = "INBOX.Drafts"
    host = imaps://imap.example.com
    user = bob
    pass = p4ssw0rd
    port = 123
    ; sslVerify = false

Note

Vous voudrez peut-être utiliser sslVerify=false pendant le dépannage, si vous soupçonnez que la raison pour laquelle vous rencontrez des difficultés à vous connecter est que le certificat que vous utilisez sur le serveur privé example.com que vous essayez de configurer (ou que vous avez configuré) n'est peut-être pas correctement vérifié.

Utilisation de l'interface IMAP de Gmail :

[imap]
    folder = "[Gmail]/Drafts"
    host = imaps://imap.gmail.com
    user = user@gmail.com
    port = 993

Gmail ne permet pas d'utiliser votre mot de passe habituel pour git imap-send. Si vous avez configuré une authentification à plusieurs facteurs sur votre compte Gmail, vous pouvez générer un mot de passe spécifique à l'application pour une utilisation avec git imap-send. Visitez https://security.google.com/settings/security/apppasswords pour le créer. Alternativement, utilisez l'authentification OAuth2.0 comme décrit ci-dessous.


Note

Vous devrez peut-être utiliser à la place : folder = "[Google Mail]/Drafts" si vous obtenez une erreur indiquant que le "Folder doesn’t exist". Vous pouvez également exécuter git imap-send --list pour obtenir une liste des dossiers disponibles.


Note

Si votre compte Gmail est défini sur une autre langue que l'anglais, le nom du dossier "Drafts" sera localisé.

Si vous souhaitez utiliser une authentification basée sur OAuth2.0, vous pouvez spécifier le mécanisme OAUTHBEARER ou XOAUTH2 dans votre configuration. C'est plus sécurisé que d'utiliser des mots de passe spécifiques à l'application, et cela n'impose pas non plus la nécessité d'avoir une authentification à plusieurs facteurs. Vous devrez utiliser un jeton d'accès OAuth2.0 à la place de votre mot de passe lorsque vous utilisez cette authentification.

[imap]
    folder = "[Gmail]/Drafts"
    host = imaps://imap.gmail.com
    user = user@gmail.com
    port = 993
    authmethod = OAUTHBEARER

Utilisation d'Outlook19;s IMAP interface:

Contrairement à Gmail, Outlook ne prend en charge que l'authentification basée sur OAuth2.0. De plus, il ne prend en charge que XOAUTH2 comme mécanisme.

[imap]
    folder = "Drafts"
    host = imaps://outlook.office365.com
    user = user@outlook.com
    port = 993
    authmethod = XOAUTH2

Une fois les commits prêts à être envoyés, exécutez la commande suivante :

$ git format-patch --cover-letter -M --stdout origin/master | git imap-send

Assurez-vous simplement de désactiver le retour à la ligne dans le client de messagerie (l'interface web de Gmail effectuera un retour à la ligne quoi qu'il arrive, vous devez donc utiliser un véritable client IMAP).

Si vous utilisez l'authentification OAuth2.0, il est plus facile d'utiliser les helpers d'identification pour générer des jetons. Les helpers d'identification suggérés dans git-send-email(1) peuvent être utilisés pour git imap-send également.

ATTENTION

Il reste de votre responsabilité de vous assurer que le message électronique envoyé par votre programme de messagerie respecte les standards de votre projet. Beaucoup de projets n'aiment pas que les patches soient joints. Certains agents de messagerie transformeront les patches (par exemple en effectuant des retours à la ligne ou en les envoyant au format format=flowed) de manière à les rendre invalides. Vous recevrez des flammes enflammées vous ridiculisant si vous ne vérifiez pas cela.

Thunderbird est en particulier connu pour être problématique. Les utilisateurs de Thunderbird pourraient souhaiter visiter cette page web pour plus d'informations : https://kb.mozillazine.org/Plain_text_e-mail_-_Thunderbird#Completely_plain_email
