DESCRIPTIO

N

Ajoute le contenu de fichiers nouveaux ou modifiés à l'index. L'« index » (également connu sous le nom de « zone de préparation ») est ce que vous utilisez pour préparer le contenu du prochain

commit.

Lorsque vous exécutez git commit sans aucun autre argument, seuls les changements préparés seront commités. Par exemple, si vous avez modifié file.c et souhaitez commiter vos modifications de ce fichier, vous pouvez exécuter

: 
git add
file.c gi
t commit

Vous pouvez également n'ajouter qu'une partie de vos modifications à un fichier avec git add -p

.

Cette commande peut être exécutée plusieurs fois avant un commit. Elle n'ajoute que le contenu des fichiers spécifiés au moment où la commande add est exécutée ; si vous souhaitez que les modifications ultérieures soient incluses dans le prochain commit, vous devez exécuter git add à nouveau pour ajouter le nouveau contenu à

l'index.

La commande git status peut être utilisée pour obtenir un résumé des fichiers dont les modifications sont préparées pour le prochain

commit.

La commande git add n'ajoute pas les fichiers ignorés par défaut. Vous pouvez utiliser l'option --force pour ajouter des fichiers ignorés. Si vous spécifiez le nom de fichier exact d'un fichier ignoré, git add échouera avec une liste des fichiers ignorés. Sinon, le fichier sera ignoré silencieusement

.

Veuillez consulter git-commit(1) pour connaître les autres

façons d'ajouter du
contenu à un commit.

OPTION

S

<pathspec>..

.
Fichiers à partir desquels ajouter du contenu. Des motifs de fichiers (par exemple *.c) peuvent être donnés pour ajouter tous les fichiers correspondants. Un nom de répertoire de tête (par exemple dir pour ajouter dir/file1 et dir/file2) peut également être donné pour mettre à jour l'index afin qu'il corresponde à l'état actuel du répertoire dans son ensemble (par exemple, la spécification de dir enregistrera non seulement un fichier dir/file1 modifié dans l'arbre de travail, un fichier dir/file2 ajouté à l'arbre de travail, mais aussi un fichier dir/file3 supprimé de l'arbre de travail). Notez que les anciennes versions de Git ignoraient les fichiers supprimés ; utilisez l'option --no-all si vous souhaitez ajouter les fichiers modifiés ou nouveaux mais ignorer les fichiers supprimés.

Pour plus de détails sur la syntaxe <pathspec>, consultez l'entrée pathspec dans gitgloss

ary
(7).

-n, --dry-ru

n
N'ajoute pas réellement le(s) fichier(s), montre seulement s'ils existent et/ou s'ils seront
ignorés.

-v, --verbos

e
Être
verbeux.

-f, --forc

e
Permettre l'ajout de fichiers autrement
ignorés.

--spars

e
Permettre la mise à jour des entrées d'index en dehors du cône de sparse-checkout. Normalement, git add refuse de mettre à jour les entrées d'index dont les chemins ne s'inscrivent pas dans le cône de sparse-checkout, car ces fichiers pourraient être supprimés de l'arbre de travail sans avertissement. Consultez git-sparse-checkout(1) pour plus de
détails.

-i, --interactiv

e
Ajouter de manière interactive les contenus modifiés dans l'arbre de travail à l'index. Des arguments de chemin optionnels peuvent être fournis pour limiter l'opération à un sous-ensemble de l'arbre de travail. Consultez « Mode interactif » pour plus de
détails.

-p, --patc

h
Choisir de manière interactive les blocs de patch entre l'index et l'arbre de travail et les ajouter à l'index. Cela donne à l'utilisateur la possibilité de vérifier la différence avant d'ajouter les contenus modifiés à l'index.

Cela exécute en fait add --interactive, mais contourne le menu de commandes initial et passe directement à la sous-commande patch. Consultez « Mode inter

actif » pour pl
us de détails.

-U<n>, --unified=<n

>
Générer des diffs avec <n> lignes de contexte. Par défaut, diff.context ou 3 si l'option de configuration n'est pas
définie.

--inter-hunk-context=<n

>
Afficher le contexte entre les blocs de diff, jusqu'au nombre spécifié de <number> lignes, fusionnant ainsi les blocs qui sont proches les uns des autres. Par défaut, diff.interHunkContext ou 0 si l'option de configuration n'est pas
définie.

-e, --edi

t
Ouvrir le diff par rapport à l'index dans un éditeur et permettre à l'utilisateur de le modifier. Après la fermeture de l'éditeur, ajuster les en-têtes des blocs et appliquer le patch à l'index.

L'intention de cette option est de sélectionner les lignes du patch à appliquer, voire de modifier le contenu des lignes

à préparer. Cela peut être plus rapide et plus flexible que d'utiliser le sélecteur de blocs interactif. Cependant, il est
facile de se tromper et de créer un patch qui ne s'applique pas à l'index. Consultez MODIFICATION DES PATCHS ci-dessous.

-u, --updat

e
Mettre à jour l'index uniquement là où il a déjà une entrée correspondant à <pathspec>. Cela supprime ainsi que modifie les entrées d'index pour qu'elles correspondent à l'arbre de travail, mais n'ajoute aucun nouveau fichier.

Si aucun <pathspec> n'est donné lorsque l'option -u est utilisée, tous les fichiers suivis de l'ensemble de l'arbre de travail sont mis à jour (les a

nciennes versions de Git limitaient la mise à jour
au répertoire courant et à ses sous-répertoires).

-A, --all, --no-ignore-remova

l
Mettre à jour l'index non seulement là où l'arbre de travail a un fichier correspondant à <pathspec> mais aussi là où l'index a déjà une entrée. Cela ajoute, modifie et supprime des entrées d'index pour qu'elles correspondent à l'arbre de travail.

Si aucun <pathspec> n'est donné lorsque l'option -A est utilisée, tous les fichiers de l'ensemble de l'arbre de travail sont mis à jour (les anci

ennes versions de Git limitaient la mise à jour a
u répertoire courant et à ses sous-répertoires).

--no-all, --ignore-remova

l
Mettre à jour l'index en ajoutant les nouveaux fichiers inconnus de l'index et les fichiers modifiés dans l'arbre de travail, mais ignorer les fichiers qui ont été supprimés de l'arbre de travail. Cette option est sans effet lorsqu'aucun <pathspec> n'est utilisé.

Cette option sert principalement à aider les utilisateurs habitués aux anciennes versions de Git, dont la commande git add <pathspec>... était un synonyme de git add --no-all <pathspec>..., c'est-à-dire qu'ell

e ignorait les fi
chiers supprimés.

-N, --intent-to-ad

d
Enregistrer uniquement le fait que le chemin sera ajouté plus tard. Une entrée pour le chemin est placée dans l'index sans contenu. Cela est utile, entre autres, pour afficher le contenu non préparé de ces fichiers avec git diff et pour les commiter avec git commit -a
.

--refres

h
Ne pas ajouter le(s) fichier(s), mais seulement actualiser leurs informations stat() dans
l'index.

--ignore-error

s
Si certains fichiers n'ont pas pu être ajoutés en raison d'erreurs lors de leur indexation, ne pas interrompre l'opération, mais continuer à ajouter les autres. La commande doit toujours se terminer avec un statut non nul. La variable de configuration add.ignoreErrors peut être définie à true pour en faire le comportement par
défaut.

--ignore-missin

g
Cette option ne peut être utilisée qu'avec --dry-run. En utilisant cette option, l'utilisateur peut vérifier si l'un des fichiers donnés serait ignoré, qu'ils soient déjà présents dans l'arbre de travail ou
non.

--no-warn-embedded-rep

o
Par défaut, git add émettra un avertissement lors de l'ajout d'un dépôt embarqué à l'index sans utiliser git submodule add pour créer une entrée dans .gitmodules. Cette option supprimera l'avertissement (par exemple, si vous effectuez manuellement des opérations sur les sous-modules)
.

--renormaliz

e
Appliquer le processus « clean » à nouveau à tous les fichiers suivis pour forcer leur réajout à l'index. C'est utile après avoir changé la configuration core.autocrlf ou l'attribut text afin de corriger les fichiers ajoutés avec desong fin de ligne CRLF/LF. Cette option implique -u. Les caractères CR isolés ne sont pas modifiés, ainsi, alors qu'un CRLF est nettoyé en LF, une séquence CRCRLF n'est nettoyée que partiellement en CRLF
.

--chmod=(+|-)

x
Remplace le bit exécutable des fichiers ajoutés. Le bit exécutable n'est modifié que dans l'index, les fichiers sur le disque sont laissés
inchangés.

--pathspec-from-file=<file

>
Le pathspec est passé dans <file> au lieu des arguments de la ligne de commande. Si <file> est exactement -, l'entrée standard est utilisée. Les éléments du pathspec sont séparés par LF ou CR/LF. Les éléments du pathspec peuvent être entre guillemets comme expliqué pour la variable de configuration core.quotePath (voir git-config(1)). Voir aussi --pathspec-file-nul et l'option globale --literal-pathspecs
.

--pathspec-file-nu

l
N'a de sens qu'avec --pathspec-from-file. Les éléments du pathspec sont séparés par le caractère NUL et tous les autres caractères sont pris littéralement (y compris les sauts de ligne et les guillemets)
.

-

-
Cette option peut être utilisée pour séparer les options de la ligne de
commande de la liste des fichiers, (utile lorsque les noms de fichier
s pourraient être confondus avec des options de la ligne de commande).

MODE

INTERACTIF

Lorsque la commande entre en mode interactif, elle affiche la sortie de la sous-commande status, puis entre dans sa boucle de commandes

interactive.

La boucle de commandes affiche la liste des sous-commandes disponibles et affiche l'invite "What now> ". En général, lorsque l'invite se termine par un seul >, vous ne pouvez choisir qu'une seule des options données et taper Entrée, comme ceci

: 
    *** Commands ***
      1: status       2: update       3: revert       4: add untracked
      5: patch        6: diff         7: quit         8: help
    What now>
1

Vous pouvez aussi dire s ou sta ou status ci-dessus tant que le choix est

unique.

La boucle de commandes principale a 6 sous-commandes (plus help et quit)

.

statu

s
Cela montre le changement entre HEAD et l'index (c'est-à-dire ce qui sera committé si vous dites git commit), et entre l'index et les fichiers de l'arbre de travail (c'est-à-dire ce que vous pourriez mettre en index plus tard avant git commit en utilisant git add) pour chaque chemin. Un exemple de sortie ressemble à ceci : 
              staged     unstaged path
     1:
binary nothing foo.png 2:
+403/-35 +1/-1 add-interactive.c

Cela montre que foo.png a des différences par rapport à HEAD (mais c'est binaire donc le nombre de lignes ne peut pas être affiché) et qu'il n'y a pas de différence entre la copie indexée et la version de l'arbre de travail (si la version de l'arbre de travail était aussi différente, binary aurait été affiché à la place de nothing). L'autre fichier, add-interactive.c, a 403 lignes ajoutées et 35 lignes supprimées si vous commitez ce qui est dans l'index, m

ais le fichier de l'arbre de travail a des modifica
tions supplémentaires (une addition et une suppression).

Lorsque l'invite se termine par un double >>, vous pouvez faire plus d'une sélection, concaténées avec des espaces ou des virgules. Vous pouvez aussi indiquer des plages. Par exemple "2-5 7,9" pour choisir 2,3,4,5,7,9 dans la liste. Si le second nombre d'une plage est omis, tous les correctifs restants sont pris. Par exemple "7-" pour choisir 7,8,9 dans la liste. ÉDITION DES

CORRECTIFS

Appeler git add -e ou sélectionner e depuis le sélecteur de hunks interactif ouvrira un correctif dans votre éditeur ; après la sortie de l'éditeur, le résultat est appliqué à l'index. Vous êtes libre d'apporter des modifications arbitraires au correctif, mais notez que certaines modifications peuvent avoir des résultats déroutants, ou même résulter en un correctif qui ne peut pas être appliqué. Si vous voulez annuler complètement l'opération (c'est-à-dire, ne rien mettre de nouveau en index), supprimez simplement toutes les lignes du correctif. La liste ci-dessous décrit certaines choses courantes que vous pourriez voir dans un correctif, et quelles opérations d'édition ont du sens sur

celles-ci.

contenu

ajouté
Le contenu ajouté est représenté par des lignes commençant par "+". Vous pouvez empêcher la mise en index de toute ligne d'addition en les
supprimant.

contenu

supprimé
Le contenu supprimé est représenté par des lignes commençant par "-". Vous pouvez empêcher la mise en index de leur suppression en convertissant le "-" en " " (espace)
.

contenu

modifié
Le contenu modifié est représenté par des lignes "-" (supprimant l'ancien contenu) suivies de lignes "+" (ajoutant le contenu de remplacement). Vous pouvez empêcher la mise en index de la modification en convertissant les lignes "-" en " ", et en supprimant les lignes "+". Attention, modifier seulement la moitié de la paire est susceptible d'introduire des changements déroutants dans
l'index.

Il existe également des opérations plus complexes qui peuvent être effectuées. Mais attention, parce que le correctif n'est appliqué qu'à l'index et non à l'arbre de travail, l'arbre de travail semblera "annuler" le changement dans l'index. Par exemple, introduire une nouvelle ligne dans l'index qui n'est ni dans HEAD ni dans l'arbre de travail mettra la nouvelle ligne en index pour le commit, mais la ligne semblera révertie dans l'arbre de

travail.

Évitez d'utiliser ces constructions, ou faites-le avec une extrême

prudence.

suppression de contenu non

touché
Le contenu qui ne diffère pas entre l'index et l'arbre de travail peut être affiché sur des lignes de contexte, commençant par un " " (espace). Vous pouvez mettre en index des lignes de contexte pour suppression en convertissant l'espace en un "-". Le fichier de l'arbre de travail résultant semblera réajouter le
contenu.

modification de contenu

existant
On peut aussi modifier des lignes de contexte en les mettant en index pour suppression (en convertissant " " en "-") et en ajoutant une ligne "+" avec le nouveau contenu. De même, on peut modifier des lignes "+" pour des additions ou modifications existantes. Dans tous les cas, la nouvelle modification semblera révertie dans l'arbre de
travail.

nouveau

contenu
Vous pouvez aussi ajouter du nouveau contenu qui n'existe pas dans le correctif ; ajoutez simplement de nouvelles lignes, chacune commençant par "+". L'addition semblera révertie dans l'arbre de
travail.

Il existe également plusieurs opérations qui devraient être évitées complètement, car elles rendraient le correctif impossible à appliquer

:
•ajouter des lignes de contexte (" ") ou de suppression
("-")
•supprimer des lignes de contexte ou de
suppression
•modifier le contenu
des lignes de contex
te ou de suppression
