NOM

git-annex-get - Rendre le contenu des fichiers annexés disponible

SYNOPSIS

git annex get [chemin ...]

DESCRIPTION

Rend le contenu des fichiers annexés disponible dans ce dépôt. Cela impliquera de les copier depuis un dépôt distant, de les télécharger, ou de les transférer depuis une sorte de magasin clé-valeur.

Sans aucun paramètre, récupère tous les fichiers annexés du répertoire courant dont le contenu n'était pas déjà présent. Des chemins de fichiers ou de répertoires à récupérer peuvent être spécifiés.

EXEMPLES


# evince foo.pdf
error: Unable to open document foo.pdf: No such file or directory
# ls foo.pdf
foo.pdf@
# git annex get foo.pdf
get foo.pdf (from origin..) ok
# evince foo.pdf

OPTIONS

--auto
Plutôt que de récupérer tous les fichiers spécifiés, récupère seulement ceux qui n'ont pas encore le nombre souhaité de copies, ou qui sont du contenu préféré du dépôt. Voir git-annex-preferred-content(1)
--from=distant
Normalement, git-annex choisira les dépôts distants depuis lesquels récupérer le contenu, préférant les dépôts avec des coûts inférieurs. Utiliser cette option pour spécifier le dépôt distant à utiliser.
Tous les fichiers qui ne sont pas disponibles sur le dépôt distant seront silencieusement ignorés.
--jobs=N -JN
Active le téléchargement parallèle avec jusqu'à N jobs s'exécutant en même temps. Par exemple : -J10
Définir ceci à "cpus" exécutera un job par cœur de processeur.
Lorsque les fichiers peuvent être téléchargés depuis plusieurs dépôts distants, l'activation des téléchargements parallèles répartira la charge entre les dépôts distants. Par exemple, si les fichiers sont disponibles sur les dépôts distants A et B, alors un fichier sera téléchargé depuis A, et un autre fichier sera téléchargé depuis B en parallèle. (Les dépôts avec des coûts inférieurs sont toujours préférés aux dépôts avec des coûts supérieurs.)
options de filtrage
Les options de filtrage git-annex-matching-options(1) peuvent être utilisées pour contrôler ce qu'il faut récupérer.
--incomplete
Reprend les téléchargements incomplets de fichiers qui ont été commencés et interrompus à un moment donné auparavant. Utile pour reprendre là où vous en étiez... quand vous ne vous en souvenez plus tout à fait.
Ces fichiers incomplets sont les mêmes que ceux listés comme fichiers temporaires non utilisés par git-annex-unused(1).
Notez que la clé git-annex sera affichée lors du téléchargement, car git-annex ne connaît pas le fichier associé et le fichier associé n'est peut-être même pas dans le répertoire de travail git courant.
--all -A
Plutôt que de spécifier un nom de fichier ou un chemin à récupérer, cette option peut être utilisée pour récupérer toutes les versions disponibles de tous les fichiers.
C'est le comportement par défaut lors de l'exécution de git-annex dans un dépôt nu.
--branch=ref
Opérer sur les fichiers de la branche ou de l'arbre spécifié.
--unused
Opérer sur les fichiers trouvés par la dernière exécution de git-annex unused.
--failed
Opérer sur les fichiers dont le transfert a récemment échoué.
À ne pas confondre avec --incomplete qui reprend uniquement les téléchargements qui ont réussi à transférer une partie du contenu d'un fichier.
--key=nomdelaclé
Utiliser cette option pour récupérer une clé spécifiée.
--batch
Active le mode batch, dans lequel les lignes contenant les noms des fichiers à récupérer sont lues depuis l'entrée standard.
Au fur et à mesure que chaque fichier spécifié est traité, la sortie de progression habituelle est affichée. Si le contenu du fichier spécifié est déjà présent, ou s'il ne correspond pas aux options de filtrage spécifiées, ou s'il ne s'agit pas d'un fichier annexé, une ligne vide est produite en réponse.
Comme la sortie habituelle lors de la récupération d'un fichier est verbeuse et non analysable par machine, vous voudrez peut-être utiliser --json en combinaison avec --batch.
--batch-keys
Ceci est similaire à --batch mais les lignes lues depuis l'entrée standard sont analysées comme des clés.
-z
Fait en sorte que l'entrée batch soit délimitée par des nulls au lieu des retours à la ligne habituels.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut les objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement envoyés sur la sortie d'erreur standard sont inclus dans le JSON à la place.
Les options git-annex-common-options(1) peuvent également être utilisées.
