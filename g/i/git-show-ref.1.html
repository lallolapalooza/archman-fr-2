NOM

git-show-ref - Liste les références dans un dépôt local

SYNOPSIS

git show-ref [--head] [-d | --dereference]
             [-s | --hash[=<n>]] [--abbrev[=<n>]] [--branches] [--tags]
             [--] [<pattern>...]
git show-ref --verify [-q | --quiet] [-d | --dereference]
             [-s | --hash[=<n>]] [--abbrev[=<n>]]
             [--] [<ref>...]
git show-ref --exclude-existing[=<pattern>]
git show-ref --exists <ref>

DESCRIPTION

Affiche les références disponibles dans un dépôt local avec les identifiants de commit associés. Les résultats peuvent être filtrés à l'aide d'un motif et les tags peuvent être déréférencés en identifiants d'objet. De plus, il peut être utilisé pour tester l'existence d'une référence particulière.

Par défaut, affiche les tags, les branches et les références distantes.

La --exclude-existing forme est un filtre qui fait l'inverse. Il lit les références depuis stdin, une référence par ligne, et affiche celles qui n'existent pas dans le dépôt local.

La --exists forme peut être utilisée pour vérifier l'existence d'une seule référence. Cette forme ne vérifie pas si la référence résout vers un objet réel.

L'utilisation de cet utilitaire est encouragée plutôt que d'accéder directement aux fichiers sous le .git répertoire.

OPTIONS

--head

Affiche la référence HEAD, même si elle serait normalement filtrée.

--branches, --tags

Limite respectivement aux branches locales et aux tags locaux. Ces options ne sont pas mutuellement exclusives ; lorsqu'elles sont données toutes les deux, les références stockées dans "refs/heads" et "refs/tags" sont affichées. Notez que --heads est un synonyme déprécié pour --branches et peut être supprimé dans le futur.

-d, --dereference

Déréférence également les tags en identifiants d'objet. Ils seront affichés avec ^{} ajouté.

-s, --hash[=<n>]

Affiche uniquement l'OID, pas le nom de la référence. Lorsqu'il est combiné avec --dereference, le tag déréférencé sera toujours affiché après l' OID.

--verify

Active une vérification plus stricte des références en exigeant un chemin de référence exact. En plus de retourner un code d'erreur de 1, il affichera également un message d'erreur si --quiet n'a pas été spécifié.

--exists

Vérifie si la référence donnée existe. Retourne un code de sortie de 0 si elle existe, 2 si elle est manquante, et 1 si la recherche de la référence a échoué avec une erreur autre que l'absence de la référence.

--abbrev[=<n>]

Abrège le nom de l'objet. Lors de l'utilisation de --hash, vous n'avez pas besoin de spécifier --hash --abbrev; --hash=n suffirait.

-q, --quiet

N'affiche aucun résultat sur stdout. Peut être utilisé avec --verify pour vérifier silencieusement si une référence existe.

--exclude-existing[=<pattern>]

Fait git show-ref agir comme un filtre qui lit les références depuis stdin sous la forme ^(?:<anything>\s)?<refname>(?:\^{})?$ et effectue les actions suivantes sur chacune : (1) supprime ^{} à la fin de la ligne s'il y en a un ; (2) ignore si un motif est fourni et ne correspond pas au début de refname ; (3) avertit si refname n'est pas un nom de référence bien formé et passe au suivant ; (4) ignore si refname est une référence qui existe dans le dépôt local ; (5) sinon, affiche la ligne.

<pattern>...

Affiche les références correspondant à un ou plusieurs motifs. Les motifs sont comparés depuis la fin du nom complet, et seules des parties complètes sont comparées, par exemple. master correspond à refs/heads/master, refs/remotes/origin/master, refs/tags/jedi/master mais pas à refs/heads/mymaster ou refs/remotes/master/jedi.

SORTIE

La sortie est au format :

<oid> SP <ref> LF

Par exemple,

$ git show-ref --head --dereference
832e76a9899f560a90ffd62ae2ce83bbeff58f54 HEAD
832e76a9899f560a90ffd62ae2ce83bbeff58f54 refs/heads/master
832e76a9899f560a90ffd62ae2ce83bbeff58f54 refs/heads/origin
3521017556c5de4159da4615a39fa4d5d2c279b5 refs/tags/v0.99.9c
6ddc0964034342519a87fe013781abf31c6db6ad refs/tags/v0.99.9c^{}
055e4ae3ae6eb344cbabf2a5256a49ea66040131 refs/tags/v1.0rc4
423325a2d24638ddcc82ce47be5e40be550f4507 refs/tags/v1.0rc4^{}
...

Lors de l'utilisation de --hash (et pas --dereference), la sortie est au format :

<oid> LF

Par exemple,

$ git show-ref --branches --hash
2e3ba0114a1f52b47df29743d6915d056be13278
185008ae97960c8d551adcd9e23565194651b5d1
03adf42c988195b50e1a1935ba5fcbc39b2b029b
...

EXEMPLES

Pour afficher toutes les références appelées "master", qu'il s'agisse de tags ou de branches ou de n'importe quoi d'autre, et quelle que soit la profondeur dans la hiérarchie de nommage des références, utilisez :

        git show-ref master

Cela affichera "refs/heads/master" mais aussi "refs/remote/other-repo/master", si de telles références existent.

Lors de l'utilisation de l'option --verify , la commande exige un chemin exact :

        git show-ref --verify refs/heads/master

ne correspondra qu'à la branche exacte appelée "master".

Si rien ne correspond, git show-ref retournera un code d'erreur de 1, et dans le cas de la vérification, il affichera un message d'erreur.

Pour les scripts, vous pouvez le demander à être silencieux avec l'option --quiet , ce qui vous permet de faire des choses comme

        git show-ref --quiet --verify -- "refs/heads/$headname" ||
                echo "$headname is not a valid branch"

pour vérifier si une branche particulière existe ou non (remarquez comment nous ne voulons en fait afficher aucun résultat, et nous voulons utiliser le nom de référence complet pour cela afin de ne pas déclencher le problème avec les correspondances partielles ambiguës).

Pour afficher uniquement les tags, ou uniquement les têtes de branches propres, utilisez --tags et/ou --branches respectivement (utiliser les deux signifie qu'il affiche les tags et les branches, mais pas les autres références aléatoires sous le sous-répertoire refs/).

Pour faire le déréférencement automatique des objets tag, utilisez l'option -d ou --dereference , afin que vous puissiez faire

        git show-ref --tags --dereference

pour obtenir une liste de tous les tags avec ce vers quoi ils se déréférencent.
