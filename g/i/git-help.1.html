DESCRIPTIO

N

Sans options et sans <commande> ni <doc>, la synopsis de la commande git et une liste des commandes Git les plus couramment utilisées sont affichées sur la sortie

standard.

Si l'option --all ou -a est fournie, toutes les commandes disponibles sont affichées sur la sortie

standard.

Si l'option --guides ou -g est fournie, une liste des guides de concepts Git est également affichée sur la sortie

standard.

Si une commande ou une autre documentation est fournie, la page de manuel correspondante sera affichée. Le programme man est utilisé à cette fin par défaut, mais cela peut être remplacé par d'autres options ou variables de

configuration.

Si un alias est fourni, git affiche la définition de l'alias sur la sortie standard. Pour obtenir la page de manuel de la commande aliasée, utilisez git <commande> --help

.

Notez que git --help ... est identique à git help ... car le premier est interne­ment converti en le

second.

Pour afficher la page de manuel git(1), utilisez git help git

.

Cette page peut être affichée avec git help help ou git help --he

l
p.

OPTION

S

-a,

--all
Affiche toutes les commandes disponibles sur la sortie
standard.

--no-external-command

s
Lorsqu'il est utilisé avec --all, exclut la liste des commandes externes « git-* » trouvées dans le $PATH
.

--no-aliase

s
Lorsqu'il est utilisé avec --all, exclut la liste des alias
configurés.

--verbos

e
Lorsqu'il est utilisé avec --all, affiche la description de toutes les commandes reconnues. C'est le comportement par
défaut.

-c,

--config
Liste toutes les variables de configuration disponibles. Il s'agit d'un résumé de la liste dans git-confi
g(1).

-g,

--guides
Affiche une liste des guides de concepts Git sur la sortie
standard.

--user-interface

s
Affiche une liste de la documentation des interfaces de dépôt, de commande et de fichier sur la sortie standard.

Les interfaces de fichier dans le dépôt telles que .git/info/exclude sont documentées ici (voir gitrepository-layout(5)), ainsi que la configuration dans l'arbre telles que .mailmap (voir gitmailmap(5))

.

Cette section de la documentation couvre également les conventions d'interface utilisateur générales ou répandues (par exemple gitcli(7)), ainsi que la pseudo-configuration telle que l'interface basée sur les fichiers .git/hooks/* décrite dans githoo

ks(
5).

--developer-interface

s
Affiche une liste de la documentation des formats de fichier, des protocoles et des autres interfaces de développeur sur la sortie
standard.

-i,

--info
Affiche la page de manuel de la commande dans le format info. Le programme info sera utilisé à cette
fin.

-m,

--man
Affiche la page de manuel de la commande dans le format man. Cette option peut être utilisée pour remplacer une valeur définie dans la variable de configuration help.format.

Par défaut, le programme man sera utilisé pour afficher la page de manuel, mais la variable de configuration man.viewer peut être utilisée pour choisir d'a

utres programmes d'affic
hage (voir ci-dessous).

-w,

--web
Affiche la page de manuel de la commande dans le format web (HTML). Un navigateur web sera utilisé à cette fin.

Le navigateur web peut être spécifié à l'aide de la variable de configuration help.browser, ou web.browser si la première n'est pas définie. Si aucune de ces variables de configuration n'est définie, le script auxiliaire git web--browse (appelé par git help) choisira une valeur par défaut appropriée. Voir git-web--browse(1) pou

r plus d'in
formations
à ce sujet.

VARIABLES DE

CONFIGURATION

help.

format

Si aucune option de ligne de commande n'est passée, la variable de configuration help.format sera vérifiée. Les valeurs suivantes sont prises en charge pour cette variable ; elles font que git help se comporte comme l'option de ligne de commande correspondante

:
•« man » correspond à -m|--man
,
•« info » correspond à -i|--info
,
•« web » ou « html » correspondent à -w|-
-we
b.

help.browser, web.browser et browser.<tool>.

path

Les variables help.browser, web.browser et browser.<tool>.path seront également vérifiées si le format web est choisi (soit par option de ligne de commande, soit par variable de configuration). Voir -w|--web dans la section OPTIONS ci-dessus et git-web--b

rows
e(1).

man.

viewer

La variable de configuration man.viewer sera vérifiée si le format man est choisi. Les valeurs suivantes sont actuellement prises en charge

:
•« man » : utiliser le programme man comme
d'habitude,
•« woman » : utiliser emacsclient pour lancer le mode « woman » dans emacs (cela ne fonctionne qu'à partir des versions 22 d'emacsclient)
,
•« konqueror » : utiliser kfmclient pour ouvrir la page de manuel dans un nouvel onglet konqueror (voir Note à propos de
konqueror

ci-dessous). Des valeurs pour d'autres outils peuvent être utilisées s'il existe une entrée de configurationman.<tool

>

.cmd correspondante (voir ci-dessous). Plusieurs valeurs peuvent être données à la variable de

configuration

man.viewer. Les programmes correspondants seront essayés dans l'ordre listé dans le fichier de

configuration. 
        Par exemple, cette configuration :
[man] viewer = konqu
eror viewer = woman

essaiera d'utiliser konqueror en premier. Mais cela peut échouer (par exemple, si DISPLAY n'est pas défini) et dans ce cas le mode woman d'emacs sera

essayé.

Si tout échoue, ou si aucun visualiseur n'est configuré, le visualiseur spécifié dans la variable d'environnement GIT_MAN_VIEWER sera essayé. Si cela échoue également, le programme man sera

essayé qu
and même.

man.<tool>.

path

Vous pouvez fournir explicitement un chemin complet vers votre visualiseur man préféré en définissant la variable de configuration man.<tool>.path. Par exemple, vous pouvez configurer le chemin absolu vers konqueror en définissant man.konqueror.path. Sinon, git help suppose que l'outi

l est disponi
ble dans PATH.

man.<tool>.

cmd

Lorsque le visualiseur man, spécifié par les variables de configuration man.viewer, n'est pas parmi ceux pris en charge, la variable de configuration correspondante man.<tool>.cmd sera recherchée. Si cette variable existe, l'outil spécifié sera traité comme une commande personnali

sée et un eval de shell sera utilisé pour exécuter la
commande avec la page de manuel passée en arguments.

Note à propos de

konqueror

Lorsque konqueror est spécifié dans la variable de configuration man.viewer, nous lançons kfmclient pour essayer d'ouvrir la page de manuel sur un konqueror déjà ouvert dans un nouvel onglet si

possible.

Par cohérence, nous essayons également cette astuce si man.konqueror.path est défini sur quelque chose comme A_PATH_TO/konqueror. Cela signifie que nous essayerons de lancer A_PATH_TO/kfmclient à la

place.

Si vous voulez vraiment utiliser konqueror, vous pouvez utiliser quelque chose comme ceci

: 
        [man]
                viewer = konq
        [man "konq"]
                cmd = CHEMIN_VERS/konque
