NOM

git-annex-repair - récupérer un dépôt git corrompu

SYNTAXE

git annex repair

DESCRIPTION

Ceci peut réparer de nombreux problèmes des dépôts git que git fsck détecte, mais ne corrige pas. C'est utile si un dépôt est gravement endommagé. Une façon dont cela peut se produire est si un dépôt utilisé par git-annex se trouve sur un lecteur amovible qui est débranché au mauvais moment.

Cette commande peut en fait être utilisée à l'intérieur de dépôts git qui n'utilisent pas du tout git-annex ; lorsqu'elle est utilisée dans un dépôt utilisant git-annex, elle effectue des réparations supplémentaires de la branche git-annex.

Elle fonctionne en supprimant tous les objets corrompus du dépôt git et en récupérant tous les objets manquants qu'elle peut des dépôts distants du dépôt.

Si cela ne suffit pas à récupérer entièrement le dépôt, elle peut également réinitialiser les branches aux commits précédents la corruption, supprimer les branches qui ne sont plus disponibles en raison des données perdues, et supprimer tous les fichiers manquants de l'index. Elle ne le fera que si elle est exécutée avec l'option --force, car cela réécrit l'historique et supprime les données perdues. Notez que l'option --force ne touche jamais les étiquettes (tags), même si elles ne sont plus utilisables en raison de données manquantes.

Après avoir exécuté cette commande, vous voudrez probablement exécuter git fsck pour vérifier qu'elle a réparé le dépôt. Notez que fsck peut toujours se plaindre d'objets référencés par le reflog, ou le stash, s'ils n'ont pas pu être récupérés. Cette commande ne tente pas de nettoyer ni le reflog ni le stash.

Il est également conseillé d'exécuter git annex fsck --fast après cette commande, pour s'assurer que la branche git-annex reflète la réalité.

OPTIONS

--force
Active les actions de réparation qui impliquent la suppression de données perdues en raison de la corruption du dépôt git.
Les git-annex-common-options(1) peuvent également être utilisés.
