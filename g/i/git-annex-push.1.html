git-annex-push(1) Manuel des commandes générales git-annex-push(1)

NOM

git-annex-push - pousser le contenu vers des dépôts distants

SYNTAXE

git annex push [remote ...]

DESCRIPTION

Cette commande pousse le contenu vers des dépôts distants. Elle télécharge à la fois le contenu du dépôt git et le contenu des fichiers annexés.

Vous pouvez utiliser git push et git-annex copy manuellement pour faire la même chose que cette commande, mais celle-ci gère plusieurs détails, notamment en s'assurant que la branche git-annex est poussée vers le dépôt distant.

Lors de l'utilisation de git-annex, les dépôts distants ne sont souvent pas des dépôts nus (bare), car il est utile d'ajouter des dépôts distants pour les machines à proximité auxquelles vous souhaitez accéder au même contenu annexé. Pousser vers un dépôt distant non nu ne mettra normalement pas à jour la branche actuelle du dépôt distant avec les modifications du dépôt local. (À moins que le dépôt distant ne soit configuré avec receive.denyCurrentBranch=updateInstead.)

Pour faciliter le travail avec de tels dépôts distants non nus, cette commande pousse non seulement master local vers master distant, mais aussi vers synced/master distant (et de manière similaire avec d'autres branches). Lorsque git-annex pull (ou git-annex sync) sera exécuté ultérieurement sur le dépôt distant, il fusionnera les branches synced/ qui y ont été poussées.

Certains dépôts distants spéciaux permettent d'exporter un arbre de fichiers vers eux (exporttree=yes), et cette commande peut être utilisée pour pousser vers ces dépôts distants ainsi que vers des dépôts git réguliers. Voir git-annex-export(1) pour plus de détails sur le fonctionnement de ces dépôts distants spéciaux. Pour que cette commande puisse exporter vers un dépôt distant spécial, remote.<nom>.annex-tracking-branch doit également être configuré et avoir la même valeur que la branche actuellement extraite.

Lorsque git-annex-adjust(1) a été utilisé pour extraire une branche ajustée, cette commande propagera les modifications apportées à la branche parente, sans propager les ajustements.

Normalement, cette commande tente de télécharger le contenu de chaque fichier annexé qui se trouve dans l'arborescence de travail, vers tout dépôt distant vers lequel elle pousse et qui ne possède pas de copie. Pour contrôler quels fichiers sont téléchargés vers un dépôt distant, configurez le contenu préféré du dépôt distant. Lorsqu'un fichier n'est pas le contenu préféré d'un dépôt distant, ou du dépôt local, cette commande tentera de supprimer le contenu du fichier. Voir git-annex-preferred-content(1).

OPTIONS

[remote]
Par défaut, cette commande pousse vers tous les dépôts distants disponibles, à l'exception des dépôts pour lesquels remote.<nom>.annex-push (ou remote.<nom>.annex-sync) est défini sur false ou remote.<nom>.annex-readonly est défini sur true.
En spécifiant les noms des dépôts distants (ou des groupes de dépôts distants), vous pouvez contrôler ceux vers lesquels pousser.
--rapide
Ne pousser que vers les dépôts distants avec la plus faible valeur annex-cost configurée.
Lorsqu'une liste de dépôts distants (ou de groupes de dépôts distants) est fournie, elle est choisie parmi ceux-ci, sinon elle est choisie parmi tous les dépôts distants.
--seulement-annexe -a, --pas-seulement-annexe
Pousser uniquement la branche git-annex et le contenu annexé vers les dépôts distants, pas les autres branches git.
La configuration annex.synconlyannex peut être définie sur true pour que ce soit le comportement par défaut. Pour outrepasser un tel réglage, utilisez --pas-seulement-annexe.
Lorsque ceci est combiné avec --pas-contenu, seule la branche git-annex sera poussée.
--pas-contenu, -g, --contenu
Utilisez --pas-contenu ou -g pour éviter de télécharger (et de supprimer) le contenu des fichiers annexés.
Si vous utilisez souvent --pas-contenu, vous pouvez définir la configuration annex.synccontent sur false pour éviter de télécharger le contenu par défaut. L'option --contenu outrepasse cette configuration.
--contenu-de=chemin -C chemin
Télécharger (ou supprimer) uniquement les fichiers annexés dans le chemin donné.
Cette option peut être répétée plusieurs fois avec différents chemins.
Notez que cette option n'empêche pas l'exportation d'autres fichiers vers un dépôt distant "exporttree=yes".
--tous -A
Habituellement, cette commande opère sur les fichiers annexés de la branche actuelle. Cette option la fait opérer sur toutes les versions disponibles de tous les fichiers annexés (lorsque les paramètres de contenu préféré le permettent).
Notez que les paramètres de contenu préféré qui utilisent include= ou exclude= ne correspondront qu'à la version des fichiers actuellement dans l'arborescence de travail, mais pas aux versions passées des fichiers.
--emplois=N -JN
Active la poussée parallèle avec jusqu'à N emplois exécutés simultanément. Par exemple : -J10
Définir ceci sur "cpus" exécutera un emploi par cœur de processeur.
--nettoyage
Supprime les branches synced/ locales et distantes, qui ont été créées et poussées par git-annex push ou git-annex sync. Cette option empêche toute autre activité.
Cela peut être utile lorsque vous avez poussé un changement vers des dépôts distants et que vous souhaitez maintenant réinitialiser votre branche principale avant ce changement. Vous exécutez donc git reset et forcez la poussée de la branche principale vers les dépôts distants, pour découvrir que le prochain git annex merge ou git annex pull ramène les changements. Pourquoi ? Parce que la branche synced/master traîne toujours et contient le changement. Nettoyer les branches synced/ empêche ce problème.
Les git-annex-common-options(1) peuvent également être utilisés.
