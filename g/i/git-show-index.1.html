NOM

git-show-index - Afficher l'index du fichier archive

SYNOPSIS

git show-index [--object-format=<algorithme-hachage>] < <fichier-pack-idx>

DESCRIPTION

Lire le fichier .idx d'un fichier pack Git (créé avec git-pack-objects(1) ou git-index-pack(1)) depuis l'entrée standard, et afficher son contenu. La sortie se compose d'un objet par ligne, chaque ligne contenant deux ou trois colonnes séparées par des espaces :

•la première colonne est le décalage en octets de l'objet dans le fichier pack correspondant
•la deuxième colonne est l'identifiant de l'objet
•si la version de l'index est 2 ou supérieure, la troisième colonne contient le CRC32 des données de l'objet

Les objets sont affichés dans l'ordre où ils sont trouvés dans le fichier d'index, qui doit être (dans un fichier correctement construit) trié par identifiant d'objet.

Notez que vous pouvez obtenir plus d'informations sur un fichier pack en appelant git-verify-pack(1). Cependant, comme cette commande ne considère que le fichier d'index lui-même, elle est à la fois plus rapide et plus flexible.

OPTIONS

--object-format=<algorithme-hachage>

Spécifie le format d'objet (algorithme de hachage) donné pour le fichier d'index. Les valeurs valides sont sha1 et (si activé) sha256. La valeur par défaut est l'algorithme du dépôt courant (défini par extensions.objectFormat), ou sha1 si aucune valeur n'est définie ou en dehors d'un dépôt.

Note : Actuellement, il n'y a pas d'interopérabilité entre les dépôts SHA-256 et les dépôts SHA-1.

Historiquement, nous avons averti que les dépôts SHA-256 pourraient plus tard nécessiter des modifications incompatibles avec les versions antérieures lorsque nous introduirions de telles fonctionnalités d'interopérabilité. Aujourd'hui, nous ne prévoyons que des changements compatibles. De plus, si de tels changements s'avèrent nécessaires, on peut s'attendre à ce que les dépôts SHA-256 créés avec la version actuelle de Git soient utilisables par les futures versions de Git sans perte de données.
