NOM

git-annex-move - déplace le contenu de fichiers vers/depuis un autre dépôt

SYNOPSIS

git annex move [chemin ...] [--from=remote|--to=remote|--to=here]

DESCRIPTION

Déplace le contenu des fichiers depuis ou vers un autre dépôt distant.

Sans aucun paramètre, opère sur tous les fichiers annexés dans le répertoire courant. Les chemins de fichiers ou de répertoires à traiter peuvent être spécifiés.

OPTIONS

--from=remote
Déplace le contenu des fichiers depuis le dépôt distant spécifié vers le dépôt local.
--to=remote
Déplace le contenu des fichiers depuis le dépôt local vers le dépôt distant spécifié.
--to=here
Déplace le contenu des fichiers depuis tous les dépôts distants accessibles vers le dépôt local.
--from=remote1 --to=remote2
Déplace le contenu des fichiers qui se trouvent dans remote1 vers remote2. Ne modifie pas ce qui est stocké dans le dépôt local.
Ceci est implémenté en téléchargeant d'abord le contenu depuis remote1 vers le dépôt local (s'il n'est pas déjà présent), puis en l'envoyant vers remote2, et enfin en supprimant le contenu du dépôt local (s'il n'y était pas initialement).
--from-anywhere --to=remote
Déplace vers le dépôt distant les fichiers du dépôt local et de tous les dépôts distants accessibles.
--force
Ignore les vérifications numcopies et de contenu requis, et supprime toujours les fichiers du dépôt source une fois que le dépôt de destination en a une copie.
Notez que, même sans cette option, vous pouvez déplacer le contenu d'un fichier d'un dépôt à un autre lorsque numcopies n'est pas satisfaite, tant que le déplacement n'entraîne pas moins de copies.
--jobs=N -JN
Active les transferts parallèles avec jusqu'à N jobs exécutés simultanément. Par exemple : -J10
Le réglage sur "cpus" exécutera un job par cœur de CPU.
Notez que lorsque vous utilisez --from avec --to, deux fois ce nombre de jobs seront exécutés simultanément, répartis équitablement entre les deux dépôts distants.
--all -A
Au lieu de spécifier un nom de fichier ou un chemin à déplacer, cette option peut être utilisée pour déplacer toutes les versions disponibles de tous les fichiers.
C'est le comportement par défaut lors de l'exécution de git-annex dans un dépôt nu.
--branch=ref
Opère sur les fichiers dans la branche ou l'arbre spécifié.
--unused
Opère sur les fichiers trouvés par la dernière exécution de git-annex unused.
--failed
Opère sur les fichiers dont le transfert a récemment échoué.
--key=keyname
Utilisez cette option pour déplacer une clé spécifiée.
options de correspondance
Les options de correspondance git-annex-matching-options(1) peuvent être utilisées pour contrôler ce qui doit être déplacé.
--batch
Active le mode batch, dans lequel les lignes contenant les noms de fichiers à déplacer sont lues depuis l'entrée standard.
Au fur et à mesure que chaque fichier spécifié est traité, la sortie de progression habituelle est affichée. Si le contenu d'un fichier n'a pas besoin d'être déplacé, ou s'il ne correspond pas aux options de correspondance spécifiées, ou s'il ne s'agit pas d'un fichier annexé, une ligne vide est affichée en réponse.
Étant donné que la sortie habituelle lors du déplacement d'un fichier est verbeuse et non analysable par une machine, vous pourriez vouloir utiliser --json en combinaison avec --batch.
--batch-keys
Ceci est similaire à --batch mais les lignes lues depuis l'entrée standard sont analysées comme des clés.
-z
Fait en sorte que l'entrée batch soit délimitée par des nulls au lieu des nouvelles lignes habituelles.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut les objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie d'erreur standard sont inclus dans le JSON à la place.
Aussi les options communes git-annex-common-options(1) peuvent être utilisées.
