git-annex-examinekey(1) Manuel des commandes générales git-annex-examinekey(1)

NOM

git-annex-examinekey - affiche des informations à partir d'une clé

SYNTAXE

git annex examinekey [clé ...]

DESCRIPTION

Cette commande de bas niveau (plumbing) reçoit une clé et affiche les informations qui peuvent être déterminées en examinant uniquement la clé.

OPTIONS

--format=valeur
Utilise un format de sortie personnalisé.
La valeur est une chaîne de format, dans laquelle '${variable}' est développée en la valeur d'une variable. Pour justifier à droite une variable avec des espaces, utilisez '${variable;largeur}' ; pour justifier à gauche une variable, utilisez '${variable;-largeur}' ; pour échapper des caractères inhabituels (y compris les caractères de contrôle) dans une variable, utilisez '${variable_échappée}'.
Pour générer un chemin depuis le haut du dépôt vers l'objet git-annex d'une clé, utilisez ${cheminobjet}. Pour générer la valeur d'un fichier pointeur git-annex pour une clé, utilisez ${pointeurobjet}.
Ces variables sont également disponibles pour être utilisées dans les formats: ${clé}, ${backend}, ${taille_en_octets}, ${taille_lisible}, ${nom_clé}, ${hashdirlower}, ${hashdirmixed}, ${mtime} (pour le champ mtime d'une clé WORM), ${fichier} (lorsqu'un nom de fichier est fourni à examinekey).
De plus, '\n' est une nouvelle ligne, '\000' est un NULL, etc.
Le format de sortie par défaut est identique à --format='${clé_échappée}\n', sauf que lorsqu'il est affiché sur un terminal, les caractères de contrôle seront échappés.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard d'erreur sont inclus dans le JSON à la place.
--migrate-to-backend=backend
Tente de migrer la clé d'entrée vers le nouveau backend spécifié. Si cela réussit, affiche des informations sur la clé migrée. Sinon, affiche des informations sur la clé d'entrée.
Ceci ne fait que des migrations rapides ; il ne ré-hashera pas le contenu d'une clé ou une opération similaire coûteuse.
Une façon de l'utiliser est d'ajouter une extension à une clé.

git annex examinekey SHA256--xxx --migrate-to-backend=SHA256E --filename=foo.tar.gz
Ou pour supprimer l'extension d'une clé :

git annex examinekey SHA256E--xxx.tar.gz --migrate-to-backend=SHA256
--filename=nom
Le nom d'un fichier associé à la clé, par exemple un fichier de l'arbre de travail. Il n'a pas besoin d'exister. Ceci est nécessaire lors de l'utilisation de --migrate-to-backend pour ajouter une extension à la clé.
--batch
Active le mode batch, dans lequel une ligne contenant une clé est lue depuis stdin, les informations la concernant sont affichées sur stdout, et cela se répète.
Afin de fournir également le nom d'un fichier associé à la clé, la ligne peut être au format "$clé $fichier"
Les options_communes_git_annex(1) peuvent aussi être utilisées.
