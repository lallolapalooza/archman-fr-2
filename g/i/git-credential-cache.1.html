NOM

git-credential-cache - Aide pour stocker temporairement les mots de passe en mémoire

SYNTAXE

git config credential.helper 'cache [<options>]'

DESCRIPTION

Cette commande met en cache les informations d'identification pour une utilisation par les futurs programmes Git. Les informations d'identification stockées sont conservées en mémoire du processus cache-daemon (au lieu d'être écrites dans un fichier) et sont oubliées après un délai configurable. Les informations d'identification sont oubliées plus tôt si le cache-daemon meurt, par exemple si le système redémarre. Le cache est accessible via une prise de socket de domaine Unix, restreinte à l'utilisateur actuel par les permissions du système de fichiers.

Vous ne voudrez probablement pas invoquer cette commande directement ; elle est destinée à être utilisée comme une aide pour les identifiants par d'autres parties de Git. Voir gitcredentials(7) ou EXEMPLES ci-dessous.

OPTIONS

--timeout <secondes>

Nombre de secondes pour mettre en cache les informations d'identification (par défaut : 900).

--socket <chemin>

Utilisez <chemin> pour contacter un daemon de cache en cours d'exécution (ou démarrer un nouveau daemon de cache s'il n'est pas démarré). Par défaut, $XDG_CACHE_HOME/git/credential/socket, à moins que ~/.git-credential-cache/ n'existe, auquel cas ~/.git-credential-cache/socket est utilisé à la place. Si votre répertoire personnel se trouve sur un système de fichiers monté sur réseau, vous devrez peut-être le changer pour un système de fichiers local. Vous devez spécifier un chemin absolu.

CONTRÔLER LE DAEMON

Si vous souhaitez que le daemon se termine plus tôt, oubliant toutes les informations d'identification mises en cache avant leur expiration, vous pouvez émettre une action exit :

git credential-cache exit

EXEMPLES

L'intérêt de cette aide est de réduire le nombre de fois où vous devez taper votre nom d'utilisateur ou votre mot de passe. Par exemple :

$ git config credential.helper cache
$ git push http://example.com/repo.git
Username: <tapez votre nom d'utilisateur>
Password: <tapez votre mot de passe>
[travaille pendant 5 minutes supplémentaires]
$ git push http://example.com/repo.git
[vos identifiants sont utilisés automatiquement]

Vous pouvez fournir des options via la variable de configuration credential.helper (cet exemple augmente le temps de cache à 1 heure) :

$ git config credential.helper 'cache --timeout=3600'

JETONS D'ACCÈS PERSONNELS

Certains dépôts distants acceptent les jetons d'accès personnels, qui sont générés aléatoirement et difficiles à mémoriser. Ils ont généralement une durée de vie de semaines ou de mois.

git-credential-cache ne convient intrinsèquement pas au stockage persistant des jetons d'accès personnels. Les informations d'identification seront oubliées après le délai d'expiration du cache. Même si vous configurez un délai d'expiration long, les informations d'identification seront oubliées si le daemon meurt.

Pour éviter de régénérer fréquemment les jetons d'accès personnels, configurez une aide d'identifiants avec stockage persistant. Sinon, configurez une aide d'identifiants OAuth pour générer automatiquement les identifiants. Voir gitcredentials(7), sections « Aide disponibles » et « OAuth ».
