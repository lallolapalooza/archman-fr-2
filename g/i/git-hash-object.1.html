NOM

git-hash-object - Calculer l'ID d'objet et créer éventuellement un objet à partir d'un fichier

SYNTAXE

git hash-object [-t <type>] [-w] [--path=<fichier> | --no-filters]
                [--stdin [--literally]] [--] <fichier>...
git hash-object [-t <type>] [-w] --stdin-paths [--no-filters]

DESCRIPTION

Calcule la valeur de l'ID d'objet pour un objet de type spécifié avec le contenu du fichier nommé (qui peut être extérieur à l'arbre de travail), et écrit éventuellement l'objet résultant dans la base de données d'objets. Rapporte son ID d'objet à sa sortie standard. Lorsque <type> n'est pas spécifié, il prend par défaut la valeur "blob".

OPTIONS

-t <type>

Spécifie le type d'objet à créer (par défaut : "blob"). Les valeurs possibles sont commit, tree, blob et tag.

-w

Écrit effectivement l'objet dans la base de données d'objets.

--stdin

Lit l'objet depuis l'entrée standard au lieu d'un fichier.

--stdin-paths

Lit les noms de fichiers depuis l'entrée standard, un par ligne, au lieu de la ligne de commande.

--path

Calcule l'objet comme s'il était situé au chemin donné. L'emplacement du fichier n'influence pas directement la valeur de hachage, mais le chemin est utilisé pour déterminer quels filtres Git appliquer à l'objet avant qu'il ne puisse être placé dans la base de données d'objets. En raison de l'application des filtres, le blob réel placé dans la base de données d'objets peut différer du fichier donné. Cette option est principalement utile pour calculer les objets de fichiers temporaires situés en dehors du répertoire de travail ou pour les fichiers lus depuis stdin.

--no-filters

Calcule le contenu tel quel, en ignorant tout filtre d'entrée qui aurait été choisi par le mécanisme d'attributs, y compris la conversion de fin de ligne. Si le fichier est lu depuis l'entrée standard, cette option est toujours implicite, à moins que l'option --path ne soit donnée.

--literally

Permet à --stdin de calculer des données quelconques dans un objet lâche qui pourrait ne pas passer les vérifications standards d'analyse d'objets ou de git-fsck. Utile pour tester les limites de Git lui-même ou pour reproduire les caractéristiques d'objets corrompus ou bidons rencontrés dans la nature.
