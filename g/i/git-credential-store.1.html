NOM

git-credential-store - Assistant pour stocker les identifiants sur disque

SYNOPSIS

git config credential.helper 'store [<options>]'

DESCRIPTION


Note

L'utilisation de cet assistant stockera vos mots de passe non chiffrés sur disque, protégés uniquement par les permissions du système de fichiers. Si ce n'est pas un compromis de sécurité acceptable, essayez git-credential-cache(1), ou cherchez un assistant qui s'intègre au stockage sécurisé fourni par votre système d'exploitation.

Cette commande stocke les identifiants indéfiniment sur disque pour être utilisés par les futurs programmes Git.

Vous ne voudrez probablement pas invoquer cette commande directement ; elle est destinée à être utilisée comme assistant d'identifiants par d'autres parties de Git. Voir gitcredentials(7) ou EXEMPLES ci-dessous.

OPTIONS

--file=<chemin>

Utilisez <chemin> pour rechercher et stocker les identifiants. Le fichier aura ses permissions du système de fichiers définies pour empêcher d'autres utilisateurs du système de le lire, mais il ne sera ni chiffré ni autrement protégé. S'il n'est pas spécifié, les identifiants seront recherchés à partir de ~/.git-credentials et $XDG_CONFIG_HOME/git/credentials, et les identifiants seront écrits dans ~/.git-credentials s'il existe, ou $XDG_CONFIG_HOME/git/credentials s'il existe et que le premier n'existe pas. Voir aussi la section « FICHIERS » ci-dessous.

FICHIERS

S'il n'est pas défini explicitement avec --file, il existe deux fichiers où git-credential-store recherchera les identifiants, par ordre de priorité :

~/.git-credentials

Fichier d'identifiants spécifique à l'utilisateur.

$XDG_CONFIG_HOME/git/credentials

Deuxième fichier d'identifiants spécifique à l'utilisateur. Si $XDG_CONFIG_HOME n'est pas défini ou est vide, $HOME/.config/git/credentials sera utilisé. Tout identifiant stocké dans ce fichier ne sera pas utilisé si ~/.git-credentials contient également un identifiant correspondant. Il est conseillé de ne pas créer ce fichier si vous utilisez parfois des versions plus anciennes de Git qui ne le prennent pas en charge.

Pour la recherche d'identifiants, les fichiers sont lus dans l'ordre indiqué ci-dessus, le premier identifiant correspondant trouvé ayant la priorité sur les identifiants trouvés dans les fichiers plus bas dans la liste.

Le stockage des identifiants écrira par défaut dans le premier fichier existant de la liste. Si aucun de ces fichiers n'existe, ~/.git-credentials sera créé et utilisé pour l'écriture.

Lors de la suppression d'identifiants, les identifiants correspondants seront supprimés de tous les fichiers.

EXEMPLES

L'objectif de cet assistant est de réduire le nombre de fois où vous devez taper votre nom d'utilisateur ou votre mot de passe. Par exemple :

$ git config credential.helper store
$ git push http://example.com/repo.git
Nom d'utilisateur: <tapez votre nom d'utilisateur>
Mot de passe: <tapez votre mot de passe>
[plusieurs jours plus tard]
$ git push http://example.com/repo.git
[vos identifiants sont utilisés automatiquement]

FORMAT DE STOCKAGE

Le fichier .git-credentials est stocké en texte brut. Chaque identifiant est stocké sur sa propre ligne sous la forme d'une URL comme :

https://user:pass@example.com

Aucun autre type de ligne (par exemple, lignes vides ou lignes de commentaire) n'est autorisé dans le fichier, même si certains peuvent être silencieusement ignorés. Ne visualisez ou n'éditez pas le fichier avec des éditeurs.

Lorsque Git a besoin d'authentification pour un contexte d'URL particulier, credential-store considérera ce contexte comme un modèle à faire correspondre avec chaque entrée du fichier d'identifiants. Si le protocole, le nom d'hôte et le nom d'utilisateur (si nous en avons déjà un) correspondent, alors le mot de passe est renvoyé à Git. Voir la discussion sur la configuration dans gitcredentials(7) pour plus d'informations.
