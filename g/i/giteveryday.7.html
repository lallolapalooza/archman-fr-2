DESCRIPTIO

N

Les utilisateurs de Git peuvent être largement regroupés en quatre catégories afin de décrire ici un petit ensemble d'utilisations utiles pour Git au

quotidien.
•Les commandes pour Développeur Individuel (Autonome) sont essentielles pour toute personne qui fait un commit, même pour quelqu'un qui travaille
seul.
•Si vous travaillez avec d'autres personnes, vous aurez besoin des commandes listées dans la section Développeur Individuel (Participant)
également.
•Les personnes qui jouent le rôle d'Intégrateur doivent apprendre quelques commandes supplémentaires en plus des
précédentes.

DÉVELOPPEUR INDIVIDUEL

(AUTONOME)

Un développeur individuel autonome n'échange pas de correctifs avec d'autres personnes et travaille seul dans un dépôt unique, en utilisant les commandes

suivantes.
•git-init(1) pour créer un nouveau
dépôt.
•git-log(1) pour voir ce qui s'est
passé.
•git-switch(1) et git-branch(1) pour changer de
branche.
•git-add(1) pour gérer le fichier
d'index.
•git-diff(1) et git-status(1) pour voir ce que vous êtes en train de
faire.
•git-commit(1) pour faire avancer la branche
courante.
•git-restore(1) pour annuler des
changements.
•git-merge(1) pour fusionner entre des branches
locales.
•git-rebase(1) pour maintenir des branches
thématiques.
•git-tag(1) pour marquer un point
connu.

DÉVELOPPEUR INDIVIDUEL

(PARTICIPANT)

Un développeur travaillant comme participant dans un projet de groupe doit apprendre à communiquer avec les autres et utilise ces commandes en plus de celles nécessaires à un développeur

autonome.
•git-clone(1) depuis l'amont pour initialiser votre dépôt
local.
•git-pull(1) et git-fetch(1) depuis "origin" pour rester à jour avec
l'amont.
•git-push(1) vers un dépôt partagé, si vous adoptez le flux de travail de dépôt partagé de style
CVS.
•git-format-patch(1) pour préparer une soumission par e-mail, si vous adoptez le flux de travail de forum public de style noyau
Linux.
•git-send-email(1) pour envoyer votre soumission par e-mail sans corruption par votre
MUA.
•git-request-pull(1) pour créer un résumé des changements pour que votre amont les
tire.

INTÉGRATEU

R

Une personne relativement centrale agissant comme intégrateur dans un projet de groupe reçoit les modifications faites par d'autres, les révise et les intègre, et publie le résultat pour que d'autres puissent l'utiliser, en utilisant ces commandes en plus de celles nécessaires aux

participants.

Cette section peut aussi être utilisée par ceux qui répondent à git request-pull ou pull-request sur GitHub (www.github.com) pour intégrer le travail des autres dans leur historique. Un lieutenant de sous-domaine d'un dépôt agira à la fois comme participant et comme

intégrateur.
•git-am(1) pour appliquer les patches envoyés par courriel de vos
contributeurs.
•git-pull(1) pour fusionner depuis vos lieutenants de
confiance.
•git-format-patch(1) pour préparer et envoyer des suggestions alternatives aux
contributeurs.
•git-revert(1) pour annuler des commits
ratés.
•git-push(1) pour publier la version la plus
récente.

ADMINISTRATION DE

DÉPÔT

Un administrateur de dépôt utilise les outils suivants pour configurer et maintenir l'accès au dépôt par les

développeurs.
•git-daemon(1) pour permettre le téléchargement anonyme depuis le
dépôt.
•git-shell(1) peut être utilisé comme un shell de connexion restreint pour les utilisateurs d'un dépôt central
partagé.
•git-http-backend(1) fournit une implémentation côté serveur de Git-sur-HTTP (« Smart http ») permettant à la fois les services de récupération et de
poussée.
•gitweb(1) fournit une interface web pour les dépôts Git, qui peut être configurée à l'aide du script git-instawe
b(1).

update hook howto[1] contient un bon exemple de gestion d'un dépôt central

partagé.

De plus, il existe un certain nombre d'autres solutions d'hébergage, de navigation et de révision largement déployées, telles que 

:
•gitolite, gerrit code review, cgit et
d'autres.
