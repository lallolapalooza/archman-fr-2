NOM

git-archimport - Importer un dépôt GNU Arch dans Git

SYNOPSIS

git archimport [-h] [-v] [-o] [-a] [-f] [-T] [-D <profondeur>] [-t <rep_temp>]
               <archive>/<branche>[:<branche-git>]...

DESCRIPTION

Importe un projet depuis un ou plusieurs dépôts GNU Arch. Il suivra les branches et les dépôts dans les espaces de noms définis par les paramètres <archive>/<branche> fournis. S'il ne trouve pas la branche distante d'où provient une fusion, il l'importera simplement comme une validation normale. S'il la trouve, il la marquera comme une fusion lorsque cela est possible (voir la discussion ci-dessous).

Le script s'attend à ce que vous fournissiez les racines clés à partir desquelles il peut démarrer l'importation à partir d'une validation de type importation initiale ou tag d'Arch. Il suivra et importera de nouvelles branches dans les racines fournies.

Il s'attend à traiter un seul projet. S'il voit des branches qui ont des racines différentes, il refusera de s'exécuter. Dans ce cas, modifiez vos paramètres <archive>/<branche> pour définir clairement la portée de l'importation.

git archimport utilise intensivement tla en arrière-plan pour accéder au dépôt Arch. Assurez-vous d'avoir une version récente de tla disponible dans le chemin. tla doit connaître les dépôts que vous passez à git archimport.

Pour l'importation initiale, git archimport s'attend à se trouver dans un répertoire vide. Pour suivre le développement d'un projet qui utilise Arch, réexécutez git archimport avec les mêmes paramètres que l'importation initiale pour effectuer des importations incrémentielles.

Bien que git archimport essaie de créer des noms de branches sensés pour les archives qu'il importe, il est également possible de spécifier manuellement des noms de branches Git. Pour ce faire, écrivez un nom de branche Git après chaque paramètre <archive>/<branche>, séparé par un deux-points. De cette façon, vous pouvez raccourcir les noms de branches Arch et convertir le jargon Arch en jargon Git, par exemple en mappant une branche "PROJET--devo--VERSION" à "master".

L'association de plusieurs branches Arch à une seule branche Git est possible ; le résultat sera le plus pertinent uniquement si aucune validation n'est effectuée sur la première branche après la création de la seconde. Néanmoins, cela est utile pour convertir des dépôts Arch qui avaient été régulièrement rotés.

FUSIONS

Les données de fusion de correctifs d'Arch sont également utilisées pour marquer les fusions dans Git. Git ne se soucie pas beaucoup du suivi des correctifs et ne considère une fusion que lorsqu'une branche incorpore toutes les validations depuis le point où elles se sont séparées. Le résultat final est que Git aura une bonne idée de la divergence des branches. Le processus d'importation perd donc certaines métadonnées d'échange de correctifs.

Heureusement, lorsque vous essayez de fusionner des branches importées d'Arch, Git trouvera une bonne base de fusion, et il y a de bonnes chances qu'il identifie les correctifs qui ont été échangés hors séquence entre les branches.

OPTIONS

-h

Afficher l'aide.

-v

Sortie verbeuse.

-T

Beaucoup de tags. Créera un tag pour chaque validation, reflétant le nom de la validation dans le dépôt Arch.

-f

Utiliser la stratégie d'importation rapide de jeux de correctifs. Cela peut être significativement plus rapide pour les arbres larges, mais ne peut pas gérer les renommages de répertoire ou les changements de permissions. La stratégie par défaut est lente et sûre.

-o

Utiliser ceci pour la compatibilité avec les noms de branche anciens utilisés par les versions antérieures de git archimport. Les noms de branche anciens étaient category--branch, tandis que les noms de branche nouveaux sont archive,category--branch--version. Dans les deux cas, les noms donnés sur la ligne de commande remplaceront ceux générés automatiquement.

-D <profondeur>

Suivre l'ascendance des fusions et tenter d'importer les arbres qui ont été fusionnés. Spécifiez une profondeur supérieure à 1 si les logs de correctifs ont été élagués.

-a

Tenter d'enregistrer automatiquement les archives à http://mirrors.sourcecontrol.net Ceci est particulièrement utile avec l'option -D.

-t <rep_temp>

Ignorer le répertoire temporaire par défaut.

<archive>/<branche>

Identificateur <archive>/<branche> dans un format que tla log comprend.
