NOM

gitformat-bundle - Le format de fichier bundle

SYNOPSIS

*.bundle
*.bdl

DESCRIPTION

Le format de bundle Git est un format qui représente à la fois des références (refs) et des objets Git. Un bundle est un en-tête dans un format similaire à git-show-ref(1) suivi d'un pack au format *.pack.

Le format est créé et lu par la commande git-bundle(1), et supporté par par exemple git-fetch(1) et git-clone(1).

FORMAT

Nous utiliserons la notation ABNF pour définir le format de bundle Git. Voir gitprotocol-common(5) pour les détails.

Un bundle v2 ressemble à ceci :

bundle    = signature *prerequisite *reference LF pack
signature = "# v2 git bundle" LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
pack         = ... ; packfile

Un bundle v3 ressemble à ceci :

bundle    = signature *capability *prerequisite *reference LF pack
signature = "# v3 git bundle" LF
capability   = "@" key ["=" value] LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
key          = 1*(ALPHA / DIGIT / "-")
value        = *(%01-09 / %0b-FF)
pack         = ... ; packfile

SEMANTIQUE

Un bundle Git se compose de plusieurs parties.

•"Capabilities", qui ne sont que dans le format v3, indiquent des fonctionnalités qui nécessitent que le bundle soit lu correctement.
•"Prerequisites" listent les objets qui ne sont PAS inclus dans le bundle et que le lecteur du bundle DOIT déjà posséder pour utiliser les données du bundle. Les objets stockés dans le bundle peuvent faire référence à des objets prérequis et à tout ce qui est accessible depuis ceux-ci (par exemple, un objet arbre dans le bundle peut faire référence à un blob qui est accessible depuis un prérequis) et/ou être exprimé comme un delta par rapport aux objets prérequis.
•"References" enregistrent les pointes du graphe d'historique, c'est-à-dire ce que le lecteur du bundle PEUT "git fetch" depuis celui-ci.
•"Pack" est le flux de données de pack que "git fetch" enverrait, si vous faisiez un fetch depuis un dépôt qui a les références enregistrées dans les "References" ci-dessus vers un dépôt qui a des références pointant vers les objets listés dans les "Prerequisites" ci-dessus.

Dans le format de bundle, il peut y avoir un commentaire suivant un obj-id prérequis. C'est un commentaire et il n'a pas de signification particulière. L'auteur du bundle PEUT y mettre n'importe quelle chaîne de caractères. Le lecteur du bundle DOIT ignorer le commentaire.

Note sur les clones superficiels et les bundles Git

Notez que les prérequis ne représentent pas une limite de clone superficiel. Les sémantiques des prérequis et des limites de clone superficiel sont différentes, et le format de bundle Git v2 ne peut pas représenter un dépôt de clone superficiel.

CAPACITÉS

Comme il n'y a pas d'opportunité de négociation, les capacités inconnues font que git bundle s'arrête.

•object-format spécifie l'algorithme de hachage utilisé, et peut prendre les mêmes valeurs que la valeur de configuration extensions.objectFormat.
•filter spécifie un filtre d'objet comme dans l'option --filter de git-rev-list(1). Le fichier de pack résultant doit être marqué comme un fichier de pack .promisor après son dépaquetage.
