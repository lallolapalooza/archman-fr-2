NOM

git-upload-archive - Envoie une archive à git-archive

SYNOPIS

git upload-archive <repository>

DESCRIPTION

Invoqué par git archive --remote et envoie une archive générée à l'autre extrémité via le protocole Git.

Cette commande n'est généralement pas invoquée directement par l'utilisateur final. L'interface utilisateur pour le protocole se trouve du côté de git archive, et la paire de programmes est destinée à être utilisée pour obtenir une archive à partir d'un dépôt distant.

SÉCURITÉ

Afin de protéger la confidentialité des objets qui ont été retirés de l'historique mais qui n'ont pas encore été élagués, git-upload-archive évite de servir des archives pour des commits et des arbres qui ne sont pas accessibles à partir des références du dépôt. Cependant, comme le calcul de l'accessibilité des objets est coûteux en termes de calcul, git-upload-archive implémente un ensemble de règles plus strictes mais plus faciles à vérifier :

1. Les clients peuvent demander un commit ou un arbre qui est pointé directement par une référence. Par exemple, git archive --remote=origin v1.0.
2. Les clients peuvent demander un sous-arbre dans un commit ou un arbre en utilisant la syntaxe ref:path. Par exemple, git archive --remote=origin v1.0:Documentation.
3. Les clients ne peuvent pas utiliser d'autres expressions sha1, même si le résultat final est accessible. Par exemple, ni un commit relatif comme master^ ni un sha1 littéral comme abcd1234 ne sont autorisés, même si le résultat est accessible depuis les références.

Notez que la règle 3 interdit de nombreux cas qui n'ont aucune implication sur la confidentialité. Ces règles sont sujettes à modification dans les futures versions de git, et le serveur accédé par git archive --remote peut ou non suivre ces règles exactes.

Si l'option de configuration uploadArchive.allowUnreachable est vraie, ces règles sont ignorées, et les clients peuvent utiliser des expressions sha1 arbitraires. Ceci est utile si vous ne vous souciez pas de la confidentialité des objets inaccessibles, ou si votre base de données d'objets est déjà publiquement disponible pour un accès via http non-smart.

OPTIONS

<repository>

Le dépôt à partir duquel obtenir une archive tar.
