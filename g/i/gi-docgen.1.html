GI-DOCGEN(1) Commandes utilisateur GI-DOCGEN(1)

NOM

gi-docgen - générateur de documentation utilisant gobject-introspection

SYNTAXE

gi-docgen COMMANDE [OPTION...] FICHIER_GIR

DESCRIPTION

GI-DocGen est un générateur de documentation pour les bibliothèques basées sur GObject. GObject est le système de types de base du projet GNOME. GI-DocGen utilise les données d'introspection lisibles par machine fournies par les bibliothèques basées sur GObject afin de générer la référence de l'API de ces bibliothèques, ainsi que d'autres documentations annexes.

L'exécutable principal gi-docgen fournit diverses sous-commandes pour accéder à toutes ses fonctionnalités.

Options communes

Toutes les commandes ont les options suivantes :

--quiet
ne pas afficher les détails de l'opération en cours
--fatal-warnings
transformer les avertissements en erreurs fatales
--help
afficher l'aide de la ligne de commande

La commande generate

La commande generate fournit la fonctionnalité principale de gi-docgen.

gi-docgen generate [ OPTIONS ] [ FICHIER_GIR ]

La commande generate analysera le fichier GIR donné, ainsi que ses dépendances, et construira une référence d'API pour l'espace de noms qu'elle trouve dans les données d'introspection. Les projets peuvent utiliser un fichier de configuration pour contrôler certains aspects de la sortie, ainsi que pour fournir du contenu supplémentaire qui doit être inclus dans la documentation.

options :

--config=FICHIER
utiliser le fichier de configuration de projet donné
--content-dir=CHEMIN
spécifier le répertoire où les fichiers de contenu listés dans le fichier de configuration du projet peuvent être trouvés
--templates-dir=CHEMIN
spécifier le répertoire où les modèles utilisés pour générer la documentation peuvent être trouvés
--theme-name=NOM
spécifier le nom du modèle à utiliser lors de la génération de la documentation, en remplaçant la configuration du projet
--output-dir=CHEMIN
créer la documentation sous le répertoire donné
--no-namespace-dir
générer tous les fichiers de documentation directement sous le répertoire de sortie, au lieu de créer un répertoire utilisant le nom de l'espace de noms et la version
--add-include-path=CHEMIN
ajouter un répertoire au chemin que le scanner utilise pour trouver les fichiers GIR. Peut être utilisé plusieurs fois pour spécifier plusieurs répertoires
--section=NOM
générer la documentation uniquement pour la section donnée. Peut être utilisé plusieurs fois pour spécifier plusieurs sections. Les sections supportées sont aliases, bitfields, classes, domains, enums, interfaces, structs et unions. Les valeurs spéciales sont all, signifiant toutes les sections (par défaut) ; et none, signifiant aucune section
--dry-run
analyser le FICHIER_GIR sans générer la documentation

La commande gen-index

La commande gen-index génère un index des symboles et des termes qui peut être utilisé pour rechercher dans la documentation générée par gi-docgen.

gi-docgen gen-index [ OPTIONS ] [ FICHIER_GIR ]

L'index généré est un fichier au format JSON appelé index.json.

options :

--config=FICHIER
utiliser le fichier de configuration de projet donné
--content-dir=CHEMIN
spécifier le répertoire où les fichiers de contenu listés dans le fichier de configuration du projet peuvent être trouvés
--output-dir=CHEMIN
créer l'index sous le répertoire donné
--add-include-path=CHEMIN
ajouter un répertoire au chemin que le scanner utilise pour trouver les fichiers GIR. Peut être utilisé plusieurs fois pour spécifier plusieurs répertoires
--dry-run
analyser le FICHIER_GIR sans générer la documentation

La commande check

La commande check exécute une série de vérifications sur le fichier d'introspection, pour s'assurer que l'API publique est correctement documentée. Elle peut être utilisée dans le cadre d'une suite de tests.

gi-docgen check [ OPTIONS ] [ FICHIER_GIR ]

options :

--config=FICHIER
utiliser le fichier de configuration de projet donné
--add-include-path=CHEMIN
ajouter un répertoire au chemin que le scanner utilise pour trouver les fichiers GIR. Peut être utilisé plusieurs fois pour spécifier plusieurs répertoires

La commande serve

La commande serve génère une référence d'API et la sert à l'aide d'un serveur HTTP local.

gi-docgen serve [ OPTIONS ] [ FICHIER_GIR ]

La commande serve analysera le fichier GIR donné, ainsi que ses dépendances, et construira une référence d'API pour l'espace de noms qu'elle trouve dans les données d'introspection. Une fois la référence construite avec succès, gi-docgen démarrera un serveur HTTP local pointant vers le répertoire de sortie.

options :

--bind=ADRESSE
utiliser l'adresse donnée pour le serveur HTTP ; la valeur par défaut est 127.0.0.1
--port=PORT
utiliser le port donné pour le serveur HTTP ; la valeur par défaut est 8080

La commande help

La commande help affiche l'aide de la ligne de commande. Si vous ne spécifiez aucune commande ou option lors de l'invocation de gi-docgen, la commande help sera implicite.

gi-docgen help [ OPTIONS ] [ COMMANDE ]

Si aucune commande n'est spécifiée, help affichera la liste des commandes.

Si une commande est spécifiée, help affichera l'aide de la ligne de commande pour ce programme.

options :

--version
afficher la version de gi-docgen

STATUT DE SORTIE

0
La commande s'est terminée avec succès.
1
Une erreur ou un avertissement a été généré.

VARIABLES D'ENVIRONNEMENT

L'exécutable gi-docgen utilise les variables d'environnement XDG_DATA_DIRS et XDG_DATA_HOME pour rechercher

pour les données d'introspection incluses dans le fichier GIR.

Si la GIDOCGEN_DEBUG variable d'environnement est définie, gi-docgen affichera des messages supplémentaires, ce qui peut être utile pour déboguer des problèmes.
