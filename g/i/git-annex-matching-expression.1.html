git-annex-matching-expression(1) Manuel des commandes générales git-annex-matching-expression(1)

NOM

git-annex-matching-expression - spécifier un ensemble de fichiers

DESCRIPTION

Les configurations annex.largefiles et annex.addunlocked utilisent toutes deux des expressions qui correspondent à certains fichiers dans l'arbre de travail.

SYNTAXE

Le format de ces expressions est similaire aux expressions de git-annex-preferred-content(1).

Par exemple :


plusgrandque=100ko et non (inclure=*.c ou inclure=*.h)

Ceci correspond aux gros fichiers, mais exclut les fichiers source C.

Les termes suivants peuvent être utilisés :

inclure=glob / exclure=glob
Spécifie les fichiers à inclure ou exclure.
Le glob peut contenir * et ? pour correspondre à des caractères arbitraires.
Notez que cela correspond au nom de fichier entier, relatif au répertoire git racine. Ainsi, inclure=foo inclura un fichier foo à la racine, mais pas subdir/foo. Pour inclure les deux, utilisez inclure=foo ou inclure=*/foo
pluspetitque=taille / plusgrandque=taille
Correspond uniquement aux fichiers plus petits que, ou plus grands que la taille spécifiée.
La taille peut être spécifiée avec des unités couramment utilisées, par exemple, "0.5 Go" ou "100 KiloBytes"
mimetype=glob
Recherche le type MIME d'un fichier et vérifie si le glob correspond.
Par exemple, "mimetype=text/*" correspondra à de nombreuses variétés de fichiers texte, y compris "text/plain", mais aussi "text/x-shellscript", "text/x-makefile", etc.
Les types MIME sont les mêmes que ceux affichés en exécutant file --mime-type
Ceci ne correspond que lorsque le contenu du fichier est présent dans le dépôt local. C'est généralement le cas, mais par exemple, lors de l'importation depuis un dépôt spécial avec --no-content, le contenu n'est généralement pas présent.
Ceci n'est disponible que lorsque git-annex a été compilé avec l'indicateur de compilation MagicMime.
mimeencoding=glob
Recherche l'encodage MIME d'un fichier et vérifie si le glob correspond.
Par exemple, "mimeencoding=binary" correspondra à de nombreux types de fichiers binaires.
Les encodages MIME sont les mêmes que ceux affichés en exécutant file --mime-encoding
Ceci ne correspond que lorsque le contenu du fichier est présent dans le dépôt local. C'est généralement le cas, mais par exemple, lors de l'importation depuis un dépôt spécial avec --no-content, le contenu n'est généralement pas présent.
Ceci n'est disponible que lorsque git-annex a été compilé avec l'indicateur de compilation MagicMime.
quelconque
Correspond à n'importe quel fichier.
rien
Ne correspond à aucun fichier. (Identique à "non quelconque")
non expression
Inverse ce à quoi l'expression correspond.
et / ou / ( expression )
Ceux-ci peuvent être utilisés pour construire des expressions plus compliquées.
