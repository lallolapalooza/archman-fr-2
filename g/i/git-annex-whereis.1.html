NOM

git-annex-whereis - liste les dépôts qui contiennent le contenu de fichiers

SYNTAXE

git annex whereis [chemin ...]

DESCRIPTION

Affiche des informations sur l'emplacement du contenu des fichiers.

Par exemple :


# git annex whereis
où est mon_gros_fichier_cool (1 copie)
0c443de8-e644-11df-acbf-f7cd7ca6210d -- ordinateur portable
où est autre_fichier (3 copies)
0c443de8-e644-11df-acbf-f7cd7ca6210d -- ordinateur portable
62b39bbe-4149-11e0-af01-bb89245a1e61 -- disque USB [ici]
7570b02e-15e9-11e0-adf0-9f3f94cb2eaa -- disque de sauvegarde

Notez que cette commande ne contacte pas les dépôts distants pour vérifier s'ils contiennent toujours le contenu des fichiers. Elle ne fait que rapporter les dernières informations reçues des dépôts distants.

OPTIONS

Options de correspondance
Les options de correspondance git-annex (`git-annex-matching-options(1)`) peuvent être utilisées pour contrôler sur quoi agir.
--key=nomdecl
Affiche où se trouve une clé git-annex particulière.
--all -A
Affiche les informations de où est pour toutes les clés connues.
(Sauf pour les clés marquées comme mortes, voir `git-annex-dead(1)`.)
--branch=ref
Affiche les informations de où est pour les fichiers de la branche ou de l'arbre spécifié.
--unused
Affiche les informations de où est pour les fichiers trouvés par la dernière exécution de `git-annex unused`.
--batch
Active le mode batch, dans lequel un fichier est lu ligne par ligne depuis l'entrée standard, ses informations sont affichées, et ainsi de suite.
Notez que si le fichier n'est pas un fichier annexé, ou ne correspond pas aux options de correspondance spécifiées, une ligne vide sera produite à la place.
--batch-keys
Ceci est similaire à --batch mais les lignes lues depuis l'entrée standard sont analysées comme des clés.
-z
Fait en sorte que l'entrée batch soit délimitée par des nuls au lieu des sauts de ligne habituels.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-error-messages
Les messages qui seraient normalement envoyés à la sortie d'erreur standard sont inclus dans le JSON à la place.
--format=valeur
Utilise un formatage de sortie personnalisé.
La valeur est une chaîne de format, dans laquelle '${var}' est développée en la valeur d'une variable. Pour justifier à droite une variable avec des espaces, utilisez '${var;largeur}' ; pour justifier à gauche une variable, utilisez '${var;-largeur}' ; pour échapper les caractères inhabituels (y compris les caractères de contrôle) dans une variable, utilisez '${var_echappee}'
Ces variables sont disponibles pour être utilisées dans les formats : fichier, clé, uuid, url, backend, octets, octets-lisibles, nomdecl, hashdirlower, hashdirmixed, mtime (pour le champ mtime d'une clé WORM).
De plus, '\n' est un saut de ligne, '\000' est un NUL, etc.
Lorsque le format contient la variable uuid, elle sera développée tour à tour pour chaque dépôt qui contient le contenu du fichier. Par exemple, avec --format='${fichier} ${uuid}\n', la sortie ressemblera à :

foo 00000000-0000-0000-0000-000000000001
foo a7f7ddd0-9a08-11ea-ab66-8358e4209d30
bar a7f7ddd0-9a08-11ea-ab66-8358e4209d30
La même chose s'applique lorsque la variable url est utilisée et qu'un fichier a plusieurs URLs enregistrées.
Les options générales de git-annex (`git-annex-common-options(1)`) peuvent également être utilisées.
