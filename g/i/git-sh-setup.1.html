NOM

git-sh-setup - Configuration commune des scripts shell Git

SYNTAXE

. "$(git --exec-path)/git-sh-setup"

DESCRIPTION

Ce n'est pas une commande que l'utilisateur final voudrait exécuter. Jamais. Cette documentation s'adresse aux personnes qui étudient les scripts de type « Porcelain » et/ou qui en écrivent de nouveaux.

Le scriptlet git sh-setup est conçu pour être sourcé (en utilisant .) par d'autres scripts shell afin de définir quelques variables pointant vers les répertoires Git normaux et quelques fonctions shell d'assistance.

Avant de le sourcer, votre script doit définir quelques variables ; USAGE (et LONG_USAGE, le cas échéant) est utilisé pour définir le message donné par la fonction shell usage(). SUBDIRECTORY_OK peut être défini si le script peut être exécuté à partir d'un sous-répertoire de l'arbre de travail (certaines commandes ne le peuvent pas).

Le scriptlet définit les variables shell GIT_DIR et GIT_OBJECT_DIRECTORY, mais ne les exporte pas dans l'environnement.

FONCTIONS

die

termine après avoir émis le message d'erreur fourni sur le flux d'erreur standard.

usage

termine avec le message d'utilisation.

set_reflog_action

définit la variable d'environnement GIT_REFLOG_ACTION à une chaîne donnée (typiquement le nom du programme) sauf si elle est déjà définie. Chaque fois que le script exécute une commande git qui met à jour des références, une entrée de reflog est créée en utilisant la valeur de cette chaîne pour laisser une trace de la commande qui a mis à jour la référence.

git_editor

exécute un éditeur au choix de l'utilisateur (GIT_EDITOR, core.editor, VISUAL ou EDITOR) sur un fichier donné, mais échoue si aucun éditeur n'est spécifié et que le terminal est basique.

is_bare_repository

affiche true ou false sur le flux de sortie standard pour indiquer si le dépôt est un dépôt nu (c'est-à-dire sans arbre de travail associé).

cd_to_toplevel

exécute chdir vers le niveau supérieur de l'arbre de travail.

require_work_tree

vérifie si le répertoire courant se trouve dans l'arbre de travail du dépôt, et sinon, termine.

require_work_tree_exists

vérifie si l'arbre de travail associé au dépôt existe, et sinon, termine. Souvent fait avant d'appeler cd_to_toplevel, ce qui est impossible à faire s'il n'y a pas d'arbre de travail.

require_clean_work_tree <action> [<hint>]

vérifie que l'arbre de travail et l'index associés au dépôt n'ont pas de modifications non commitées sur les fichiers suivis. Sinon, il émet un message d'erreur de la forme Cannot <action>: <reason>. <hint>, et termine. Par exemple : 
require_clean_work_tree rebase "Veuillez les commiter ou les stasher."

get_author_ident_from_commit

affiche du code à utiliser avec eval pour définir les variables GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL et GIT_AUTHOR_DATE pour un commit donné.

create_virtual_base

modifie le premier fichier pour qu'il ne reste que les lignes communes avec le second fichier. S'il y a peu de matière commune, le premier fichier est laissé vide. Le résultat est adapté comme entrée de base virtuelle pour une fusion à 3 voies.
