NOM

git-annex-sync - synchronise le dépôt local avec les dépôts distants

SYNOPSIS

git annex sync [dépôt ...]

DESCRIPTION

Cette commande synchronise le dépôt local avec ses dépôts distants.

Cette commande valide d'abord les modifications locales apportées aux fichiers qui ont été précédemment ajoutés au dépôt. Ensuite, elle effectue l'équivalent de git-annex-pull(1) suivi de git-annex-push(1).

Cependant, contrairement à ces commandes, cette commande ne transfère pas le contenu annexé par défaut. Cela changera dans une future version de git-annex, lors de la synchronisation avec des dépôts configurés avec du contenu préféré.

OPTIONS

--content, --no-content, -g
L'option --content provoque le téléchargement et le transfert du contenu des fichiers annexés.
Les options --no-content et -g empêchent le téléchargement et le transfert du contenu des fichiers annexés.
La configuration annex.synccontent peut être définie sur true pour que --content soit activé par défaut.
--content-of=chemin -C chemin
Cette option provoque le téléchargement et le transfert du contenu des fichiers annexés dans le chemin spécifié.
Cette option peut être répétée plusieurs fois avec des chemins différents.
Notez que cette option n'empêche pas l'exportation d'autres fichiers vers un dépôt "exporttree=yes".
--commit, --no-commit
Une validation est effectuée par défaut (sauf si annex.autocommit est défini sur false).
Utilisez --no-commit pour éviter de valider les modifications locales.
--message=msg -m msg
Utilisez cette option pour spécifier un message de validation.
Si plusieurs options -m sont données, leurs valeurs sont concaténées comme des paragraphes séparés.
--pull, --no-pull
Utilisez cette option pour désactiver le téléchargement.
Lorsque remote.<nom>.annex-sync est défini sur false, le téléchargement est désactivé pour ce dépôt distant, et l'utilisation de --pull ne l'activera pas.
--push, --no-push
Utilisez cette option pour désactiver le transfert.
Lorsque remote.<nom>.annex-sync est défini sur false, le transfert est désactivé pour ce dépôt distant, et l'utilisation de --push ne l'activera pas.
Également toutes les options supportées par
git-annex-pull(1) et git-annex-push(1) peuvent être utilisées.
Également les git-annex-common-options(1) peuvent être utilisées.
