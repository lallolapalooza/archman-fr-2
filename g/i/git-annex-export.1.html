git-annex-export(1) Manuel des commandes générales git-annex-export(1)

NOM

git-annex-export - exporter un arbre de fichiers vers un dépôt distant spécial

SYNTAXE

git annex export arbre --vers dépôt

DESCRIPTION

Utilisez cette commande pour exporter un arbre de fichiers depuis un dépôt git-annex.

Normalement, les fichiers sont stockés sur un dépôt distant spécial git-annex nommé par leurs clés. C'est idéal pour un stockage de données fiable, mais vos noms de fichiers sont alors masqués. L'exportation réplique l'arbre tel quel vers le dépôt distant spécial.

Pour l'utiliser, vous devez configurer un dépôt distant spécial avec exporttree=yes lors de sa configuration initiale avec git-annex-initremote(1).

L'arbre à exporter peut être le nom d'une branche git, ou une étiquette (tag), ou tout autre objet d'arbre accepté par git, y compris par exemple master:subdir pour n'exporter qu'un sous-répertoire d'une branche.

Lorsque le dépôt distant a une expression de contenu préférée définie par git-annex-wanted(1), l'arbre est filtré par celle-ci, excluant les fichiers annexés qu'il ne veut pas voir exportés. (Notez que les éléments de l'expression comme "include=" correspondent par rapport au sommet de l'arbre exporté.)

Tous les fichiers dans l'arbre qui sont stockés dans git seront également exportés vers le dépôt distant spécial.

Les exportations répétées sont effectuées efficacement, en comparant l'ancien et le nouvel arbre, et en ne transférant que les fichiers modifiés, et en renommant les fichiers si nécessaire.

Les exportations peuvent être interrompues et reprises. Cependant, les fichiers partiellement téléchargés seront redémarrés depuis le début dans la plupart des cas.

Une fois que le contenu a été exporté vers un dépôt, des commandes comme git annex get peuvent télécharger le contenu depuis celui-ci, comme depuis d'autres dépôts. Cependant, comme une exportation n'est pas un magasin clé/valeur, git-annex doit effectuer plus de vérifications sur le contenu téléchargé depuis une exportation. Certains types de clés, qui ne sont pas basés sur des sommes de contrôle, ne peuvent pas être téléchargés depuis une exportation. Et, git-annex ne fera jamais confiance à une exportation pour conserver le contenu d'une clé.

Cependant, certains dépôts distants spéciaux, notamment S3, prennent en charge le suivi des anciennes versions des fichiers qui y sont stockés. Si un dépôt distant spécial est configuré pour faire cela, il peut être utilisé comme magasin clé/valeur et les limitations du paragraphe précédent ne s'appliquent pas. Notez que la suppression de contenu d'un tel dépôt n'est pas prise en charge. Voir la documentation de chaque dépôt distant spécial pour plus de détails sur la façon d'activer cette gestion des versions.

Des commandes comme git-annex push peuvent également être utilisées pour exporter une branche vers un dépôt distant spécial, en mettant à jour le dépôt distant spécial chaque fois que la branche est modifiée. Pour ce faire, vous devez configurer "remote.<nom>.annex-tracking-branch" pour lui indiquer quelle branche suivre. Par exemple :


git config remote.mondépôt.annex-tracking-branch master
git annex push mondépôt

Vous pouvez combiner l'utilisation de git annex export pour envoyer les modifications à un dépôt distant spécial avec git annex import pour récupérer les modifications d'un dépôt distant spécial. Lorsqu'un fichier sur un dépôt distant spécial a été modifié par un logiciel autre que git-annex, l'exporter ne remplacera pas le fichier modifié, et l'exportation ne réussira pas. Vous pouvez résoudre ce conflit en utilisant git annex import.

(Certains types de dépôts distants spéciaux tels que S3 avec gestion des versions peuvent au contraire permettre à une exportation de remplacer le fichier modifié ; alors git annex import créera une séquence de commits qui inclut le fichier modifié, de sorte que la modification écrasée ne soit pas perdue.)

OPTIONS

--vers=dépôt
Spécifie le dépôt distant spécial vers lequel exporter.
--depuis=dépôt
Lorsque le contenu d'un fichier n'est pas disponible dans le dépôt local, cette option permet de le télécharger depuis un autre dépôt distant, et de l'envoyer vers le dépôt de destination. Le fichier sera stocké temporairement sur le disque local, mais n'entrera jamais dans le dépôt local.
Cette option peut être répétée plusieurs fois.
Il est possible d'utiliser --depuis avec le même dépôt distant que --vers. Si l'arbre contient plusieurs fichiers avec le même contenu, et que le dépôt distant vers lequel on exporte contient déjà une copie du contenu, cela permet de faire une copie en téléchargeant le contenu depuis celui-ci.
--suivi
Ceci est une façon obsolète de définir "remote.<nom>.annex-tracking-branch". Au lieu d'utiliser cette option, vous devriez configurer vous-même la configuration git.
--rapide
Ceci met en place une exportation d'un arbre, mais évite tout téléchargement coûteux de fichiers vers le dépôt distant. Vous pourrez ensuite exécuter git annex push pour télécharger les fichiers vers l'exportation.
--emplois=N -JN
Exporte plusieurs fichiers en parallèle. Cela peut être plus rapide. Par exemple : -J4
Définir ceci sur "cpus" exécutera un emploi par cœur de processeur.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
--json-progress
Inclut des objets de progression dans la sortie JSON.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie d'erreur standard sont inclus dans le JSON à la place.
Les git-annex-common-options(1) peuvent également être utilisés.

EXEMPLE


git annex initremote mondépôt type=directory directory=/mnt/mondépôt \
exporttree=yes encryption=none
git annex export master --vers mondépôt

Après cela, /mnt/mondépôt contiendra le même arbre de fichiers que la branche master.


git mv monfichier sousdossier/monfichier
git commit -m renommé
git annex export master --vers mondépôt

Cela met à jour /mnt/mondépôt pour refléter le fichier renommé.


git annex export master:sousdossier --vers mondépôt

Cela met à jour /mnt/mondépôt, pour qu'il ne contienne que les fichiers du répertoire "sousdossier" de la branche master.

CONFLITS D'EXPORTATION

Si deux dépôts git-annex différents exportent des arbres différents vers le même dépôt distant spécial, un conflit d'exportation peut survenir. Cela laisse le dépôt distant spécial avec certains fichiers d'un arbre, et certains fichiers de l'autre. Les fichiers dans le dépôt distant spécial peuvent aussi avoir un contenu totalement incorrect.

Il n'est pas possible pour git-annex de détecter quand une exportation provoquera un conflit d'exportation. La meilleure façon d'éviter les conflits d'exportation est soit d'exporter toujours vers un dépôt distant spécial depuis un seul dépôt, soit d'avoir une règle concernant l'arbre que vous exportez vers le dépôt distant spécial. Par exemple, si vous exportez toujours origin/master après avoir poussé vers origin, alors un conflit d'exportation ne peut pas se produire.

Un conflit d'exportation ne peut être détecté qu'après que les deux dépôts git qui l'ont produit se soient resynchronisés. Alors, la prochaine fois que vous exécuterez git annex export, il détectera le conflit d'exportation et le résoudra.

git-annex-export(1)

NAME

git-annex-export - export files to a location

SYNOPSIS

git annex export [remote] [directory]

git annex export --all --jobs=N

DESCRIPTION

Exports files from the current annex to a remote repository. This is useful for exporting the annexed files to a location that git-annex is not managing directly. When exporting to a remote, git-annex copies the annexed files to that remote. If the remote is also a git-annex repository, the files will be added to its annex as well. If no remote is specified, git-annex will export to the default remote (usually 'origin'). If no directory is specified, git-annex will export to the root of the remote repository.

OPTIONS

--all:: Export all annexed files. --jobs=N:: Use N parallel jobs to export files.

EXAMPLE

Export all annexed files to the 'backup' remote repository: git annex export backup Export all annexed files to the 'backup' remote repository and its 'archive' subdirectory: git annex export backup archive

EXPORT CONFLICTS

When exporting files, git-annex may encounter conflicts if a file with the same name already exists in the destination. In such cases, git-annex will rename the conflicting file by appending a number to its name (e.g., `file.txt.1`, `file.txt.2`).
