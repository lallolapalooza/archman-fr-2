git-annex-multicast(1) Manuel des commandes générales git-annex-multicast(1)

NOM

git-annex-multicast - distribution de fichiers par multidiffusion

SYNTAXE

git annex multicast [options]

DESCRIPTION

La multidiffusion (multicast) permet de diffuser des fichiers à plusieurs récepteurs, généralement sur un réseau local unique.

Le programme uftp est utilisé pour la multidiffusion. http://uftp-multicast.sourceforge.net/

OPTIONS

--gen-address
Génère une clé de chiffrement pour la multidiffusion et stocke une adresse de multidiffusion correspondante dans la branche git-annex.
--send [fichier]
Envoie les fichiers spécifiés aux récepteurs dont les adresses de multidiffusion sont stockées dans la branche git-annex.
Lorsqu'aucun fichier n'est spécifié, tous les fichiers annexés dans le répertoire courant et ses sous-répertoires sont envoyés.
Les options de correspondance git-annex (git-annex-matching-options(1)) peuvent être utilisées pour contrôler les fichiers à envoyer. Par exemple :

git annex multicast send . --not --copies 2
--receive
Reçoit les fichiers des expéditeurs dont les adresses de multidiffusion sont stockées dans la branche git-annex.
Au fur et à mesure que chaque fichier est reçu, son nom de fichier est affiché. C'est le nom de fichier utilisé par l'expéditeur ; l'arbre de travail local peut utiliser un nom différent pour le fichier, ou ne pas contenir de lien vers le fichier.
Cette commande continue de s'exécuter jusqu'à ce qu'elle soit interrompue par vous en appuyant sur Ctrl-c.
Notez que la réserve de disque configurée annex.diskreserve n'est pas respectée par cette commande, car uftpd reçoit les fichiers réels et peut recevoir des fichiers de n'importe quelle taille.
--uftp-opt=option -Uoption
Passe une option à la commande uftp/uftpd. Peut être spécifié plusieurs fois.
Par exemple, pour diffuser à 50 Mbps :

git annex multicast send -U-R -U50000
Les options communes de git-annex (git-annex-common-options(1)) peuvent également être utilisées.

EXEMPLE

Supposons qu'un professeur veuille diffuser des fichiers aux élèves d'une salle de classe.

Cela suppose que le professeur et les élèves ont cloné un dépôt git-annex, et que tous deux peuvent pousser des modifications vers sa branche git-annex, ou sinon se pousser mutuellement des modifications.

Premièrement, le professeur exécute git annex multicast --gen-address; git annex sync

Ensuite, chaque élève exécute git annex multicast --gen-address; git annex sync

Une fois que tous les élèves ont généré des adresses, le professeur exécute git annex sync une fois de plus. (Maintenant, tous les élèves ont reçu l'adresse du professeur, et le professeur a reçu toutes les adresses des élèves.)

Ensuite, chaque élève exécute git annex multicast --receive

Enfin, une fois que tous les élèves sont à l'écoute (ahem), le professeur exécute git annex multicast --send
