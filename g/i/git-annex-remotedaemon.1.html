NOM

git-annex-remotedaemon - communication persistante avec les dépôts distants

SYNTAXE

git annex remotedaemon

DESCRIPTION

Le remotedaemon assure une communication persistante avec les dépôts distants.

Plusieurs types de dépôts distants sont supportés :

Pour les dépôts distants ssh, le remotedaemon essaie de maintenir une connexion au dépôt distant, et utilise git-annex-shell notifychanges pour détecter quand le dépôt distant a changé, et en récupère les modifications. Pour que cela fonctionne, le dépôt distant doit avoir git-annex-shell(1) installé, avec le support de notifychanges. La première version de git-annex-shell qui le supporte est la 5.20140405.

Pour les dépôts distants tor-annex, le remotedaemon exécute un service caché tor, acceptant des connexions d'autres nœuds et servant le contenu du dépôt. Ceci n'est fait que si vous exécutez d'abord git annex enable-tor. Utilisez git annex p2p pour configurer l'accès aux dépôts distants tor-annex.

Pour les dépôts distants p2p-annex, le remotedaemon exécute la commande git-annex-p2p-<nomréseau> pour obtenir un fichier socket, écoute sur ce fichier socket les connexions d'autres pairs, et sert le contenu du dépôt. Ceci n'est fait que si vous exécutez d'abord git annex p2p --enable <nomréseau>.

Notez que lorsque remote.<nom>.annex-pull est défini sur false, le remotedaemon évitera de récupérer les modifications de ce dépôt distant.

OPTIONS

--foreground
Ne pas se détacher en arrière-plan, et communiquer sur stdin/stdout en utilisant un protocole textuel simple. L'assistant exécute le remotedaemon de cette manière.
Les commandes du protocole incluent LOSTNET, qui indique au remotedaemon que la connexion réseau a été perdue, et le fait cesser toute connexion TCP. Ceci peut être suivi de RESUME lorsque la connexion réseau est rétablie.
Les options communes de git-annex (git-annex-common-options(1)) peuvent également être utilisées.
