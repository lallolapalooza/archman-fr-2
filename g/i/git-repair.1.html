NOM

git-repair - Réparer un dépôt git corrompu

SYNTAXE

git-repair [--force]

DESCRIPTION

Ceci peut réparer un dépôt git corrompu ou cassé, pour lequel git fsck n'aurait fait que signaler des problèmes.

Il le fait en supprimant tous les objets corrompus et en récupérant tous les objets manquants qu'il peut auprès des dépôts distants.

Si cela ne suffit pas à récupérer entièrement le dépôt, il peut également réinitialiser les branches aux commits antérieurs à la corruption, supprimer les branches qui ne sont plus disponibles en raison des données perdues, et supprimer tout fichier manquant de l'index. Il ne fera cela que s'il est exécuté avec l'option --force, car cela réécrit l'historique et jette les données manquantes. Notez que l'option --force ne touche jamais les tags, même s'ils ne sont plus utilisables en raison de données manquantes.

Après avoir exécuté cette commande, vous voudrez probablement exécuter git fsck pour vérifier si le dépôt a été réparé. Notez que fsck peut encore se plaindre d'objets référencés par le reflog ou le stash, s'ils n'ont pas pu être récupérés. Cette commande n'essaie pas de nettoyer ni le reflog ni le stash.

Étant donné que cette commande décompresse tous les packs du dépôt, vous voudrez peut-être exécuter git gc par la suite.

TESTING

git-repair est capable de se tester lui-même, en faisant une copie temporaire du dépôt git dans lequel il est exécuté, en le corrompant de manière aléatoire, et en vérifiant qu'il peut le réparer de sorte que git fsck ne signale aucun problème.

Cela se fait à l'aide du paramètre --test et des paramètres associés --numtests et --retry.

Notez que les tests trouvent parfois des dépôts qui ne peuvent être réparés qu'avec --force ; c'est attendu. D'un autre côté, s'il échoue à récupérer un dépôt avec --force, alors les tests ont trouvé un bug !
