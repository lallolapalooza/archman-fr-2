OPTION

-I <paths>, --include=<paths

Spécifie lfs.fetchinclude uniquement pour cette invocation ; voir INCLURE ET

-X <paths>, --exclude=<paths

Spécifie lfs.fetchexclude uniquement pour cette invocation ; voir INCLURE ET

--recen

t
Télécharge les objets référencés par les branches et commits récents en plus de ceux qui seraient autrement téléchargés. Voir MODIFICATIONS

--al

l
Télécharge tous les objets référencés par un commit accessible depuis les références fournies en arguments. Si aucune référence n'est fournie, toutes les références sont récupérées. C'est principalement destiné à la sauvegarde et à la migration. Ne peut pas être combiné avec --recent ou --include/--exclude. Ignore les chemins d'inclusion et d'exclusion configurés globalement pour s'assurer que tous les objets sont
téléchargés.

p

INCLURE ET

EXCLURE

Vous pouvez configurer Git LFS pour ne récupérer les objets que pour satisfaire les références dans certains chemins du dépôt, et/ou pour exclure certains chemins du dépôt, afin de réduire le temps que vous passez à télécharger des choses que vous n'utilisez

pas.

Dans votre configuration Git ou dans un fichier .lfsconfig, vous pouvez définir l'un ou l'autre ou les deux de lfs.fetchinclude et lfs.fetchexclude à des listes de chemins séparés par des virgules. Si lfs.fetchinclude est défini, les objets Git LFS ne seront récupérés que si leur chemin correspond à un élément de cette liste, et si lfs.fetchexclude est défini, les objets Git LFS ne seront récupérés que si leur chemin ne correspond à aucun élément de cette liste. Les chemins sont comparés en utilisant la correspondance par motifs génériques comme défini dans gitignore(5)

.

Notez que l'utilisation des options en ligne de commande -I et -X remplace les paramètres de configuration respectifs. Définir l'une ou l'autre option à une chaîne vide efface la

valeur.

DISTANT PAR

DÉFAUT

Sans arguments, fetch télécharge depuis le distant par défaut. Le distant par défaut est le même que pour git fetch, c'est-à-dire basé sur la branche dist

ante que vous suivez en p
remier, ou origin sinon.

RÉFÉRENCES PAR

DÉFAUT

Si aucune référence n'est donnée en argument, la référence actuellement extr

aite est utilisée. De plus, si activé, les références et commits récemment m
odifiés sont également inclus. Voir MODIFICATIONS RÉCENTES pour les détails.

MODIFICATIONS

RÉCENTES

Si l'option --recent est spécifiée, ou si l'option gitconfig lfs.fetchrecentalways est vraie, alors après que la référence actuelle (ou celles des arguments) a été récupérée, nous recherchons également les modifications 'récentes' pour récupérer leurs objets, afin qu'il soit plus pratique de faire un checkout ou un diff de ces commits sans entraîner d'autres téléchargements

.

Ce qui est considéré comme 'récent' est basé sur un certain nombre d'options gitconfig

:

lfs.fetchrecentrefsday

s
Si non nul, inclut les branches qui ont des commits dans les N jours précédant la date actuelle. Seules les références locales sont incluses sauf si lfs.fetchrecentremoterefs est vrai. La valeur par défaut est 7
jours.

lfs.fetchrecentremoteref

s
Si vrai, récupère les références distantes (pour le distant que vous récupérez) ainsi que les références locales dans la fenêtre récente. C'est utile pour récupérer les objets pour les branches distantes que vous pourriez vouloir extraire plus tard. La valeur par défaut est vrai ; si vous définissez ceci à faux, la récupération pour ces branches n'aura lieu que lorsque vous les extrayez (perdant l'avantage de fetch --recent), ou que vous créez une branche locale de suivi séparément puis récupérez à
nouveau.

lfs.fetchrecentcommitsday

s
En plus de récupérer aux branches, récupère également les modifications effectuées dans les N jours précédant le dernier commit de la branche. C'est utile si vous examinez souvent les modifications récentes. La valeur par défaut est 0 (aucune modification précédente)
.

lfs.fetchrecentalway

s
Opère toujours comme si
--recent était fourni s
ur la ligne de commande.
