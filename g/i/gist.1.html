GIST(1) Manuel de Gist GIST(1)

NOM

gist - téléverser du code sur https://gist.github.com

SYNOPIS

La gemme ruby gist fournit une commande gist que vous pouvez utiliser depuis votre terminal pour téléverser du contenu sur https://gist.github.com/.

INSTALLATION

○
Si vous avez ruby installé :
gem install gist
○
Si vous utilisez Bundler :
source :rubygems gem ´gist´
○
Pour OS X, gist se trouve dans Homebrew
brew install gist
○
Pour FreeBSD, gist se trouve dans les ports
pkg install gist

COMMANDE

○
Pour téléverser le contenu de a.rb simplement :
gist a.rb
○
Téléverser plusieurs fichiers :
gist a b c gist *.rb
○
Par défaut, il lit depuis STDIN, et vous pouvez définir un nom de fichier avec -f.
gist -f test.rb <a.rb
○
Alternativement, vous pouvez simplement coller depuis le presse-papiers :
gist -P
○
Utilisez -p pour rendre le gist privé :
gist -p a.rb
○
Utilisez -d pour ajouter une description :
gist -d "Bug aléatoire de rbx" a.rb
○
Vous pouvez mettre à jour des gists existants avec -u :
gist -u ID_DU_GIST NOM_DU_FICHIER gist -u 42f2c239d2eb57299408 test.txt
○
Si vous souhaitez copier l'URL résultante dans votre presse-papiers, utilisez -c.
gist -c <a.rb
○
Si vous souhaitez copier l'URL intégrable résultante dans votre presse-papiers, utilisez -e.
gist -e <a.rb
○
Et vous pouvez simplement demander à gist d'ouvrir une fenêtre de navigateur directement avec -o.
gist -o <a.rb
○
Pour lister (gists publics ou tous les gists pour l'utilisateur authentifié) les gists d'un utilisateur
gist -l : tous les gists pour l'utilisateur authentifié gist -l defunkt : liste les gists publics de defunkt

Pour lire un gist et l'afficher sur STDOUT

gist -r ID_DU_GIST
gist -r 374130
○
Voir gist --help pour plus de détails.

CONNEXION

Avant d'utiliser gist pour la première fois, vous devrez vous connecter. Deux flux de connexion sont pris en charge :

1.
Le flux Oauth de code d'appareil GitHub. C'est le flux par défaut pour s'authentifier auprès de github.com, et il peut être activé pour GitHub Enterprise en créant une application Oauth, et en exportant la variable d'environnement GIST_CLIENT_ID avec l'ID client de l'application Oauth.
2.
Le flux (déprécié) d'échange de nom d'utilisateur et de mot de passe contre un jeton. C'est le flux par défaut pour GitHub Enterprise, et il peut être utilisé pour se connecter à github.com en exportant la variable d'environnement GIST_USE_USERNAME_AND_PASSWORD.

Le flux de code d'appareil

Ce flux vous permet d'obtenir un jeton en vous connectant à GitHub dans votre navigateur et en saisissant un code de vérification. C'est le mécanisme préféré.

gist --login
Demande des paramètres de connexion...
Veuillez vous connecter sur https://github.com/login/device
  et entrer le code : XXXX-XXXX
Succès ! https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e

Le access_token retourné est stocké dans ~/.gist et utilisé pour tous les futurs gists. Si nécessaire, vous pouvez révoquer l'accès depuis https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e.

Le flux nom d'utilisateur-mot de passe

Ce flux demande votre nom d'utilisateur et votre mot de passe GitHub (et le code 2FA), et les échange contre un jeton avec la permission "gist" (votre nom d'utilisateur et votre mot de passe ne sont pas stockés). Ce mécanisme est déprécié par GitHub, mais peut encore fonctionner avec GitHub Enterprise.

gist --login
Obtention du jeton d'accès OAuth2 depuis GitHub.
Nom d'utilisateur GitHub : ConradIrwin
Mot de passe GitHub :
Code d'authentification 2 facteurs :
Succès ! https://github.com/settings/tokens

Ce jeton est stocké dans ~/.gist et utilisé pour tous les futurs gists. Si nécessaire, vous pouvez le révoquer depuis https://github.com/settings/tokens, ou simplement supprimer le fichier.

Si vous avez des exigences d'autorisation complexes, vous pouvez créer manuellement un fichier de jeton en collant un jeton GitHub avec la portée gist (et éventuellement la portée user:email pour GitHub Enterprise) dans un fichier appelé ~/.gist. Vous pouvez en créer un depuis https://github.com/settings/tokens

Ce fichier ne doit contenir que le jeton (~40 caractères hexadécimaux), et pour faciliter son édition, il peut éventuellement avoir une nouvelle ligne finale (\n ou \r\n).

Par exemple, une façon de créer ce fichier serait d'exécuter :

(umask 0077 && echo MON_JETON_SECRET > ~/.gist)

L'utilitaire umask garantit que le fichier n'est accessible qu'à partir de votre compte utilisateur.

GitHub Enterprise

Si vous souhaitez que gist utilise votre GitHub Enterprise installé localement https://enterprise.github.com/, vous devez exporter la variable d'environnement GITHUB_URL (généralement fait dans votre ~/.bashrc).

export GITHUB_URL=http://github.internal.example.com/

Une fois que vous avez fait cela et redémarré votre terminal (ou exécuté source ~/.bashrc), gist utilisera automatiquement GitHub Enterprise au lieu du github.com public.

Votre jeton pour GitHub Enterprise sera stocké dans .gist.<protocole>.<nom_serveur>[.<port>] (par exemple, ~/.gist.http.github.internal.example.com pour l'exemple GITHUB_URL ci-dessus) au lieu de ~/.gist.

Si vous avez plusieurs serveurs ou si vous utilisez fréquemment Enterprise et GitHub public, vous pouvez contourner ce problème en créant des scripts qui définissent la variable d'environnement et exécutent ensuite gist. Gardez à l'esprit que pour utiliser GitHub public, vous devez désactiver la variable d'environnement. La définir simplement sur l'URL publique ne fonctionnera pas. Utilisez unset GITHUB_URL

Format du fichier de jeton

Si vous ne pouvez pas utiliser de mots de passe, comme c'est le cas pour la plupart des installations Enterprise, vous pouvez générer le jeton via l'interface web, puis simplement enregistrer la chaîne dans le bon fichier. Évitez les sauts de ligne, sinon vous pourriez voir : $ gist -l Erreur : Identifiants invalides

Vous pouvez également utiliser Gist comme bibliothèque depuis votre code ruby :

Si vous avez besoin de fonctionnalités plus avancées, vous pouvez également passer :

○
:access_token pour vous authentifier en utilisant OAuth2 (la valeur par défaut est `File.read("~/.gist")`).
○
:filename pour changer la coloration syntaxique (la valeur par défaut est a.rb).
○
:public si vous voulez que votre gist ait une URL devinable.
○
:description pour ajouter une description à votre gist.
○
:update pour mettre à jour un gist existant (peut être une URL ou un ID).
○
:copy pour copier l'URL résultante dans le presse-papiers (la valeur par défaut est false).
○
:open pour ouvrir l'URL résultante dans un navigateur (la valeur par défaut est false).

NOTE : Le access_token doit avoir la portée gist et peut également nécessiter la portée user:email.
