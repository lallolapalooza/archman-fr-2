NOM

git-annex-reinit - initialiser le dépôt, en réutilisant un UUID ancien

SYNOPIS

git annex reinit uuid|description

DESCRIPTION

Normalement, l'initialisation d'un dépôt génère un identifiant unique (UUID) pour ce dépôt. Il peut être utile occasionnellement de réutiliser un UUID – par exemple, si un dépôt a été supprimé et que vous le remettez en place.

Utilisez ceci avec prudence ; avoir deux dépôts existants avec le même UUID peut être source de confusion.

Assurez-vous d'exécuter git annex fsck après avoir changé l'UUID d'un dépôt pour vous assurer que les informations de suivi de localisation sont correctement enregistrées.

Comme git annex init, ceci tente d'activer tous les dépôts distants spéciaux qui sont configurés avec autoenable=true.

OPTIONS

--json
Active la sortie JSON. Ceci est destiné à être analysé par les programmes qui utilisent git-annex.
--json-error-messages
Les messages qui seraient normalement affichés sur la sortie standard sont inclus dans le JSON à la place.
Aussi, les git-annex-common-options(1) peuvent être utilisés.
