NOM

git-diagnose - Génère une archive zip d'informations de diagnostic

SYNTAXE

git diagnose [(-o | --output-directory) <chemin>] [(-s | --suffix) <format>]
               [--mode=<mode>]

DESCRIPTION

Collecte des informations détaillées sur la machine de l'utilisateur, le client Git et l'état du dépôt, puis emballe ces informations dans une archive zip. L'archive générée peut ensuite être partagée, par exemple, avec la liste de diffusion Git pour aider à déboguer un problème ou servir de référence pour un débogage indépendant.

Par défaut, les informations suivantes sont capturées dans l'archive :

•git version --build-options
•Le chemin vers la racine du dépôt
•L'espace disque disponible sur le système de fichiers
•Le nom et la taille de chaque fichier de paquet, y compris ceux dans les stockages d'objets alternatifs
•Le nombre total d'objets lâches, ainsi que les décomptes répartis par sous-répertoire de .git/objects

Des informations supplémentaires peuvent être collectées en sélectionnant un mode de diagnostic différent à l'aide de l'option --mode.

Cet outil diffère de git-bugreport(1) en ce qu'il collecte des informations beaucoup plus détaillées avec un plus grand accent sur le signalement de la taille et de la forme des données du contenu du dépôt.

OPTIONS

-o <chemin>, --output-directory <chemin>

Place l'archive de diagnostic résultante dans <chemin> au lieu du répertoire courant.

-s <format>, --suffix <format>

Spécifie un suffixe alternatif pour le nom de l'archive de diagnostic, afin de créer un fichier nommé git-diagnostics-<suffix-formaté>. Ceci doit prendre la forme d'une chaîne de format strftime(3) ; l'heure locale actuelle sera utilisée.

--mode=(stats|all)

Spécifie le type de diagnostics qui doivent être collectés. Le comportement par défaut de git diagnose est équivalent à --mode=stats.

L'option --mode=all collecte tout ce qui est inclus dans --mode=stats, ainsi que des copies des répertoires .git, .git/hooks, .git/info, .git/logs, et .git/objects/info. Ces informations supplémentaires peuvent être sensibles, car elles peuvent être utilisées pour reconstruire le contenu complet du dépôt diagnostiqué. Les utilisateurs doivent faire preuve de prudence lors du partage d'une archive générée avec --mode=all.
