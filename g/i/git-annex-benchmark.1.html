NOM

git-annex-benchmark - benchmark des commandes git-annex

SYNTAXE

git annex benchmark [options-criterion] ( -- commande [; commande] | --databases=N )

DESCRIPTION

Lorsque git-annex est compilé avec le support du benchmarking, cette commande peut être utilisée pour benchmarker toute autre commande git-annex. Par exemple, "git annex benchmark -- get ." benchmarkera "git annex get".

La commande benchmarkée est exécutée dans le dépôt git-annex actuel. Elle n'est pas exécutée une seule fois ; le processus de benchmarking l'exécutera plusieurs fois pour obtenir un résultat statistiquement significatif.

Lorsqu'on benchmarke une action comme "git annex get", la première exécution fera souvent beaucoup plus que les exécutions suivantes. Pour que le benchmark répète une action comme récupérer un fichier à chaque fois, des commandes supplémentaires peuvent être listées, séparées par ';'. (Notez que ';' doit être échappé du shell.) Le script combiné sera exécuté de manière répétée par le benchmark. Un exemple d'utilisation :


git annex benchmark -- get . ';' drop .

Notez que git-annex benchmark ne crée pas de nouveaux processus git-annex lorsqu'il benchmarke ; il appelle la commande à benchmarker en interne, et évite ainsi la surcharge de démarrage de git-annex. (N'essayez donc pas de l'utiliser pour optimiser le démarrage de git-annex.)

OPTIONS

Avant le "--", toute option de ligne de commande de la bibliothèque criterion peut être utilisée.

Toute option que git-annex accepte habituellement peut être incluse après la commande à benchmarker.

L'option --databases=N benchmarke l'utilisation des bases de données sqlite par git-annex, au lieu d'une commande. N est le nombre d'éléments à benchmarker.

SORTIE

La sortie des commandes benchmarkées va vers la sortie standard et l'erreur standard comme d'habitude. Il est souvent conseillé d'utiliser --quiet pour éviter une sortie inutile, à moins que la génération de cette sortie ne fasse partie de ce que vous voulez benchmarker.

Le rapport de benchmark est envoyé à la sortie standard par défaut, bien que les options de criterion puissent être utilisées pour le rediriger vers un fichier. Par exemple :


git annex benchmark -o bench -- find >/dev/null
