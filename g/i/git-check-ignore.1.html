NOM

git-check-ignore - Déboguer les fichiers gitignore / exclus

SYNTAXE

git check-ignore [<options>] <chemin>...
git check-ignore [<options>] --stdin

DESCRIPTION

Pour chaque chemin donné en ligne de commande ou à partir d'un fichier via --stdin, vérifie si le fichier est exclu par .gitignore (ou d'autres fichiers d'entrée du mécanisme d'exclusion) et affiche le chemin s'il est exclu.

Par défaut, les fichiers suivis ne sont pas affichés du tout car ils ne sont pas soumis aux règles d'exclusion ; mais voir ‘--no-index’.

OPTIONS

-q, --quiet

Ne rien afficher, juste définir le statut de sortie. Ceci n'est valide qu'avec un seul chemin.

-v, --verbose

Au lieu d'afficher les chemins qui sont exclus, pour chaque chemin qui correspond à un modèle d'exclusion, affiche le modèle d'exclusion ainsi que le chemin. (Correspondre à un modèle d'exclusion signifie généralement que le chemin est exclu, mais si le modèle commence par "!", alors c'est un modèle négatif et le faire correspondre signifie que le chemin N'EST PAS exclu.)

Pour les règles de priorité au sein et entre les sources d'exclusion, voir gitignore(5).

--stdin

Lit les noms de chemins depuis l'entrée standard, un par ligne, au lieu de la ligne de commande.

-z

Le format de sortie est modifié pour être analysable par machine (voir ci-dessous). Si --stdin est également donné, les chemins d'entrée sont séparés par un caractère NUL au lieu d'un caractère de fin de ligne.

-n, --non-matching

Affiche les chemins donnés qui ne correspondent à aucun modèle. Cela n'a de sens que lorsque --verbose est activé, sinon il serait impossible de distinguer les chemins qui correspondent à un modèle de ceux qui n'en correspondent pas.

--no-index

Ne cherche pas dans l'index lors des vérifications. Ceci peut être utilisé pour déboguer pourquoi un chemin est devenu suivi par ex. git add . et n'a pas été ignoré par les règles comme prévu par l'utilisateur ou lors du développement de modèles incluant la négation pour faire correspondre un chemin précédemment ajouté avec git add -f.

SORTIE

Par défaut, tout nom de chemin fourni qui correspond à un modèle d'exclusion sera affiché, un par ligne. Si aucun modèle ne correspond à un chemin donné, rien ne sera affiché pour ce chemin ; cela signifie que ce chemin ne sera pas ignoré.

Si --verbose est spécifié, la sortie est une série de lignes de la forme :

<source> <DEUX-POINTS> <numéro_ligne> <DEUX-POINTS> <modèle> <TAB> <chemin>

<chemin> est le chemin d'un fichier interrogé, <modèle> est le modèle correspondant, <source> est le fichier source du modèle, et <numéro_ligne> est le numéro de ligne du modèle dans cette source. Si le modèle contenait un préfixe "!" ou un suffixe "/", il sera préservé dans la sortie. <source> sera un chemin absolu lorsqu'il fait référence au fichier configuré par core.excludesFile, ou relatif à la racine du dépôt lorsqu'il fait référence à .git/info/exclude ou à un fichier d'exclusion par répertoire.

Si -z est spécifié, les noms de chemins dans la sortie sont délimités par le caractère nul ; si --verbose est également spécifié, alors les caractères nuls sont également utilisés à la place des deux-points et des tabulations :

<source> <NUL> <numéro_ligne> <NUL> <modèle> <NUL> <chemin> <NUL>

Si -n ou --non-matching sont spécifiés, les chemins ne correspondant pas seront également affichés, auquel cas tous les champs de chaque enregistrement de sortie, à l'exception de <chemin>, seront vides. Cela peut être utile lors de l'exécution non interactive, de sorte que les fichiers puissent être diffusés de manière incrémentielle vers STDIN d'un processus check-ignore en cours d'exécution, et pour chacun de ces fichiers, STDOUT indiquera si ce fichier correspondait à un modèle ou non. (Sans cette option, il serait impossible de dire si l'absence de sortie pour un fichier donné signifiait qu'il ne correspondait à aucun modèle, ou que la sortie n'avait pas encore été générée.)

La mise en tampon se fait comme documenté sous l'option GIT_FLUSH dans git(1). L'appelant est responsable d'éviter les blocages causés par le remplissage excessif d'un tampon d'entrée ou la lecture à partir d'un tampon de sortie vide.

STATUT DE SORTIE

0

Un ou plusieurs des chemins fournis sont ignorés.

1

Aucun des chemins fournis n'est ignoré.

128

Une erreur fatale a été rencontrée.
