NOM

git-merge-file - Exécuter une fusion de fichiers à trois voies

SYNOPSIS

git merge-file [-L <nom-courant> [-L <nom-base> [-L <autre-nom>]]]
        [--ours|--theirs|--union] [-p|--stdout] [-q|--quiet] [--marker-size=<n>]
        [--[no-]diff3] [--object-id] <courant> <base> <autre>

DESCRIPTION

Étant donné trois fichiers <courant>, <base> et <autre>, git merge-file incorpore tous les changements qui mènent de <base> à <autre> dans <courant>. Le résultat va normalement dans <courant>. git merge-file est utile pour combiner des changements séparés d'un original. Supposons que <base> est l'original, et que <courant> et <autre> sont des modifications de <base>, alors git merge-file combine les deux changements.

Un conflit se produit si <courant> et <autre> ont tous deux des changements dans un segment commun de lignes. Si un conflit est trouvé, git merge-file affiche normalement un avertissement et encadre le conflit avec des lignes contenant les marqueurs <<<<<<< et >>>>>>>. Un conflit typique ressemblera à ceci :

<<<<<<< A
lignes dans le fichier A
=======
lignes dans le fichier B
>>>>>>> B

Si des conflits surviennent, l'utilisateur doit éditer le résultat et supprimer l'une des alternatives. Lorsque l'option --ours, --theirs ou --union est active, ces conflits sont cependant résolus en privilégiant les lignes de <courant>, les lignes de <autre>, ou les lignes des deux respectivement. La longueur des marqueurs de conflit peut être spécifiée avec l'option --marker-size.

Si --object-id est spécifié, exactement le même comportement se produit, sauf qu'au lieu de spécifier quoi fusionner comme fichiers, c'est spécifié comme une liste d'ID d'objet faisant référence à des blobs.

La valeur de sortie de ce programme est négative en cas d'erreur, et le nombre de conflits sinon (tronqué à 127 s'il y en a plus que cela). Si la fusion s'est déroulée sans heurts, la valeur de sortie est 0.

git merge-file est conçu pour être un clone minimal de l'utilitaire merge de RCS ; c'est-à-dire qu'il implémente toutes les fonctionnalités de merge de RCS qui sont nécessaires à git(1).

OPTIONS

--object-id

Spécifiez le contenu à fusionner comme blobs dans le dépôt courant au lieu de fichiers. Dans ce cas, l'opération doit avoir lieu dans un dépôt valide.

Si l'option -p est spécifiée, le fichier fusionné (y compris les conflits, le cas échéant) va vers la sortie standard comme d'habitude ; sinon, le fichier fusionné est écrit dans le magasin d'objets et l'ID de l'objet de son blob est écrit vers la sortie standard.

-L <étiquette>

Cette option peut être donnée jusqu'à trois fois, et spécifie les étiquettes à utiliser à la place des noms de fichiers correspondants dans les rapports de conflit. C'est-à-dire, git merge-file -L x -L y -L z a b c génère une sortie qui semble provenir des fichiers x, y et z au lieu des fichiers a, b et c.

-p

Envoyer les résultats vers la sortie standard au lieu d'écraser <courant>.

-q

Silencieux ; ne pas avertir des conflits.

--diff3

Afficher les conflits dans le style "diff3".

--zdiff3

Afficher les conflits dans le style "zdiff3".

--ours, --theirs, --union

Au lieu de laisser les conflits dans le fichier, résoudre les conflits en privilégiant notre côté (ou leur côté ou les deux) des lignes.

--diff-algorithm={patience|minimal|histogram|myers}

Utiliser un algorithme de diff différent lors de la fusion. L'algorithme par défaut actuel est "myers", mais sélectionner un algorithme plus récent tel que "histogram" peut aider à éviter les mauvaises fusions qui surviennent en raison de lignes correspondantes sans importance (comme des accolades de fonctions distinctes). Voir aussi git-diff(1) --diff-algorithm.

EXEMPLES

git merge-file README.my README README.upstream

combine les changements de README.my et README.upstream depuis README, essaie de les fusionner et écrit le résultat dans README.my.

git merge-file -L a -L b -L c tmp/a123 tmp/b234 tmp/c345

fusionne tmp/a123 et tmp/c345 avec la base tmp/b234, mais utilise les étiquettes a et c au lieu de tmp/a123 et tmp/c345.

git merge-file -p --object-id abc1234 def567 890abcd

combine les changements du blob abc1234 et 890abcd depuis def567, essaie de les fusionner et écrit le résultat vers la sortie standard
