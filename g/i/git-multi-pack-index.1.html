NOM

git-multi-pack-index - Écrit et vérifie les index multi-packs

SYNOPSIS

git multi-pack-index [--object-dir=<dir>] [--[no-]bitmap] <sous-commande>

DESCRIPTION

Écrit ou vérifie un fichier d'index multi-packs (MIDX).

OPTIONS

--object-dir=<dir>

Utilise le répertoire donné pour l'emplacement des objets Git. Nous vérifions <dir>/packs/multi-pack-index pour le fichier MIDX actuel, et <dir>/packs pour les fichiers pack à indexer.

<dir> doit être une alternative au dépôt actuel.

--progress, --no-progress

Active/désactive explicitement la progression. Si aucun des deux n'est spécifié, la progression est affichée si la sortie d'erreur standard est connectée à un terminal. Pris en charge par les sous-commandes write, verify, expire et repack.

Les sous-commandes suivantes sont disponibles :

write

Écrit un nouveau fichier MIDX. Les options suivantes sont disponibles pour la sous-commande write :

--preferred-pack=<pack>

Lorsqu'elle est spécifiée, départage en faveur de ce pack lorsqu'il existe des copies supplémentaires de ses objets dans d'autres packs. Les égalités pour les objets non trouvés dans le pack préféré sont toujours résolues en faveur de la copie dans le pack ayant la mtime la plus élevée. Si non spécifié, le pack avec la mtime la plus basse est utilisé par défaut. Le pack préféré doit contenir au moins un objet.

--[no-]bitmap

Contrôle si un bitmap multi-pack est écrit ou non.

--stdin-packs

Écrit un index multi-pack contenant uniquement l'ensemble des noms de base d'index de pack délimités par des sauts de ligne fournis via l'entrée standard.

--refs-snapshot=<path>

Avec --bitmap, spécifiez éventuellement un fichier contenant un "instantané des refs" pris avant le reconditionnement.

Un instantané de référence est composé d'OID délimités par des sauts de ligne correspondant aux sommets des références, généralement pris par git repack avant la génération d'un nouveau pack. Une ligne peut éventuellement commencer par un caractère + pour indiquer que la référence correspondant à cet OID est "préférée" (voir pack.preferBitmapTips dans git-config(1)).

Le fichier donné à <path> est supposé être lisible et peut contenir des doublons. (Si un OID donné est donné plus d'une fois, il est marqué comme préféré si au moins une instance commence par le marqueur spécial +).

--incremental

Écrit un fichier MIDX incrémental contenant uniquement les objets et les packs qui ne sont pas présents dans une couche MIDX existante. Migre les MIDX non incrémentaux vers des MIDX incrémentaux si nécessaire. Incompatible avec --bitmap.

verify

Vérifie le contenu du fichier MIDX.

expire

Supprime les fichiers pack qui sont suivis par le fichier MIDX, mais qui n'ont aucun objet référencé par le MIDX (à l'exception des packs .keep et des packs de détritus). Réécrit le fichier MIDX par la suite pour supprimer toutes les références à ces fichiers pack.

Note
ce mode est incompatible avec les fichiers MIDX incrémentaux.

repack

Crée un nouveau fichier pack contenant les objets des petits fichiers pack référencés par l'index multi-pack. Si la taille donnée par l'argument --batch-size=<taille> est zéro, alors crée un pack contenant tous les objets référencés par l'index multi-pack. Pour une taille de lot non nulle, sélectionne les fichiers pack en examinant les packs du plus ancien au plus récent, en calculant la "taille attendue" en comptant le nombre d'objets dans le pack référencé par l'index multi-pack, puis en divisant par le nombre total d'objets dans le pack et en multipliant par la taille du pack. Nous sélectionnons les packs dont la taille attendue est inférieure à la taille du lot jusqu'à ce que l'ensemble des packs ait une taille attendue totale d'au moins la taille du lot, ou que tous les fichiers pack soient considérés. Si un seul fichier pack est sélectionné, alors ne rien faire. Si un nouveau fichier pack est créé, réécrit l'index multi-pack pour référencer le nouveau fichier pack. Une exécution ultérieure de git multi-pack-index expire supprimera les fichiers pack qui faisaient partie de ce lot.

Si repack.packKeptObjects est false, alors les fichiers pack associés à un fichier .keep ne seront pas sélectionnés pour le lot à reconditionner.


Note
ce mode est incompatible avec les fichiers MIDX incrémentaux.

EXEMPLES

•Écrit un fichier MIDX pour les fichiers pack du répertoire .git actuel. 
$ git multi-pack-index write
•Écrit un fichier MIDX pour les fichiers pack du répertoire .git actuel avec un bitmap correspondant. 
$ git multi-pack-index write --preferred-pack=<pack> --bitmap
•Écrit un fichier MIDX pour les fichiers pack d'un magasin d'objets alternatif. 
$ git multi-pack-index --object-dir <alt> write
•Vérifie le fichier MIDX pour les fichiers pack du répertoire .git actuel. 
$ git multi-pack-index verify

Voir Le document de conception de l'index multi-pack[1] et gitformat-pack(5) pour plus d'informations sur la fonctionnalité d'index multi-pack et son format de fichier.
