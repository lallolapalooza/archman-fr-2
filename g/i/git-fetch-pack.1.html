NOM

git-fetch-pack - Réceptionner les objets manquants d'un autre dépôt

SYNOPSIS

git fetch-pack [--all] [--quiet|-q] [--keep|-k] [--thin] [--include-tag]
        [--upload-pack=<git-upload-pack>]
        [--depth=<n>] [--no-progress]
        [-v] <dépôt> [<refs>...]

DESCRIPTION

Habituellement, vous devriez utiliser git fetch, qui est une interface de niveau supérieur de cette commande, à la place.

Invoque git-upload-pack sur un dépôt potentiellement distant et lui demande d'envoyer les objets manquants dans ce dépôt, pour mettre à jour les têtes nommées. La liste des commits disponibles localement est découverte en parcourant la hiérarchie locale de refs/ et envoyée à git-upload-pack s'exécutant à l'autre bout.

Cette commande dégénère en téléchargement complet pour finaliser les refs demandées du côté distant lorsque le côté local ne possède pas de commit ancêtre commun.

OPTIONS

--all

Récupérer toutes les refs distantes.

--stdin

Prendre la liste des refs depuis stdin, une par ligne. S'il y a des refs spécifiées sur la ligne de commande en plus de cette option, les refs provenant de stdin sont traitées après celles de la ligne de commande.

Si --stateless-rpc est spécifié avec cette option, alors la liste des refs doit être au format paquet (pkt-line). Chaque ref doit être dans un paquet séparé, et la liste doit se terminer par un paquet de fin.

-q, --quiet

Passe le drapeau -q à git unpack-objects ; cela rend le processus de clonage moins verbeux.

-k, --keep

N'invoque pas git unpack-objects sur les données reçues, mais crée un seul fichier paquet à partir de celles-ci, et le stocke dans la base de données d'objets. Si fourni deux fois, le paquet est verrouillé contre le re-pâquetage.

--thin

Récupère un paquet "thin", qui enregistre les objets sous forme de delta basé sur des objets non inclus dans le paquet pour réduire le trafic réseau.

--include-tag

Si le côté distant le prend en charge, les objets de type tag annoté seront téléchargés sur la même connexion que les autres objets si l'objet référencé par le tag est téléchargé. L'appelant doit sinon déterminer les tags rendus disponibles par cette option.

--upload-pack=<git-upload-pack>

Utilisez ceci pour spécifier le chemin vers git-upload-pack sur le côté distant, s'il n'est pas trouvé dans votre $PATH. Les installations de sshd ignorent les scripts de configuration d'environnement de l'utilisateur pour les shells de connexion (par ex. .bash_profile) et votre git privé peut ne pas être trouvé dans le $PATH par défaut du système. Une autre solution suggérée est de configurer votre $PATH dans ".bashrc", mais ce flag est destiné aux personnes qui ne veulent pas payer la surcharge pour les shells non interactifs en ayant un .bashrc épuré (elles configurent la plupart des choses dans .bash_profile).

--exec=<git-upload-pack>

Identique à --upload-pack=<git-upload-pack>.

--depth=<n>

Limite la récupération aux chaînes d'ancêtres n'excédant pas n. git-upload-pack traite la profondeur spéciale 2147483647 comme infinie, même s'il existe une chaîne d'ancêtres de cette longueur.

--shallow-since=<date>

Approfondit ou raccourcit l'historique d'un dépôt peu profond pour inclure tous les commits atteignables après <date>.

--shallow-exclude=<ref>

Approfondit ou raccourcit l'historique d'un dépôt peu profond pour exclure les commits atteignables depuis une branche ou un tag distant spécifié. Cette option peut être spécifiée plusieurs fois.

--deepen-relative

L'argument --depth spécifie le nombre de commits depuis la limite peu profonde actuelle au lieu de la pointe de l'historique de chaque branche distante.

--refetch

Ignore la négociation des commits avec le serveur afin de récupérer tous les objets correspondants. À utiliser pour réappliquer un nouveau filtre de blob/arbre de clone partiel.

--no-progress

N'affiche pas la progression.

--check-self-contained-and-connected

Affiche "connectivity-ok" si le paquet reçu est autonome et connecté.

-v

Exécute en mode verbeux.

<dépôt>

L'URL du dépôt distant.

<refs>...

Les têtes distantes à mettre à jour depuis. Ceci est relatif à $GIT_DIR (par ex. "HEAD", "refs/heads/master"). Lorsqu'il n'est pas spécifié, met à jour depuis toutes les têtes que le côté distant possède.

Si le distant a activé les options uploadpack.allowTipSHA1InWant, uploadpack.allowReachableSHA1InWant, ou uploadpack.allowAnySHA1InWant, ils peuvent alternativement être des sha1s hexadécimaux de 40 caractères présents sur le distant.
