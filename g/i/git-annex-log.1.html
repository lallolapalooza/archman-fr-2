git-annex-log(1) Manuel des commandes générales git-annex-log(1)

NOM

git-annex-log - affiche des informations du journal d'emplacement

SYNOPIS

git annex log [chemin ...]

DESCRIPTION

Cette commande affiche des informations de l'historique de la branche git-annex.

Plusieurs éléments peuvent empêcher la disponibilité de ces informations pour l'affichage. Lorsque git-annex-forget est utilisé, les anciennes données historiques sont effacées de la branche. Lorsque annex.private ou remote.name.annex-private est configuré, git-annex n'écrit aucune information dans la branche. Et lorsque annex.alwayscommit est défini sur false, les informations peuvent ne pas encore avoir été validées dans la branche.

OPTIONS

[chemin ...]
Affiche le journal d'emplacement pour le(s) fichier(s) spécifié(s), montrant chaque dépôt auquel ils ont été ajoutés ("+") et dont ils ont été retirés ("-"). Notez qu'il affiche des informations sur le contenu du fichier actuellement à ces chemins, pas sur tout autre contenu qui s'y trouvait dans des commits antérieurs.
options de correspondance
Les options de correspondance git-annex(1) peuvent être utilisées pour contrôler ce sur quoi agir lors de l'affichage du journal d'emplacement pour les fichiers spécifiés.
--all -A
Affiche les changements du journal d'emplacement pour tout le contenu, avec les changements les plus récents en premier. Dans ce mode, les noms des fichiers ne sont pas disponibles et les clés sont affichées à la place.
--key=nomdeclé
Affiche le journal d'emplacement pour la clé spécifiée.
--branch=ref
Affiche le journal d'emplacement pour les fichiers dans la branche ou l'arbre spécifié.
--unused
Affiche le journal d'emplacement pour les fichiers trouvés par la dernière exécution de git-annex unused.
--sizesof=dépôt
Affiche un historique de la taille totale des fichiers annexés dans un dépôt au fil du temps, de la création du dépôt à nos jours.
Le dépôt peut être "ici" pour le dépôt actuel, ou le nom d'une origine distante, ou une description de dépôt ou un UUID.
Notez que les clés dont la taille n'est pas connue ne sont pas incluses dans le total.
--sizes
Ceci est similaire à --sizesof, mais au lieu d'afficher la taille d'un seul dépôt, il affiche les tailles de tous les dépôts connus.
La sortie est un tableau formaté en CSV.
--totalsizes
Ceci est similaire à --sizesof, mais il affiche la taille totale de tous les dépôts connus.
--interval=temps
Lors de l'utilisation de --sizesof, --sizes et --totalsizes, cela contrôle l'intervalle minimum entre les affichages de la taille. La valeur par défaut est d'afficher chaque nouvelle taille enregistrée.
Le temps est de la forme "30j" ou "1a".
--received
Combinez cette option avec --sizesof ou --sizes pour afficher la quantité de données reçues dans les dépôts depuis la dernière ligne affichée.
--gnuplot
Combinez cette option avec --sizesof ou --sizes ou --totalsizes pour utiliser gnuplot(1) pour tracer les données. Le fichier gnuplot sera laissé sur le disque pour que vous puissiez le réutiliser.
Par exemple, pour tracer les tailles de tous les dépôts :
git annex log --sizes --interval=1d --gnuplot
Pour tracer la quantité de nouvelles données reçues dans chaque dépôt tous les 30 jours :
git annex log --sizes --interval=30d --gnuplot --recieved
--bytes
Affiche les tailles en octets, désactivant les unités plus agréables par défaut.
--raw-date
Plutôt que l'affichage normal d'une date dans le fuseau horaire local, affiche les secondes depuis l'époque Unix.
--since=date, --after=date, --until=date, --before=date, --max-count=N
Ces options sont transmises à git log et peuvent être utilisées pour limiter la profondeur de la recherche des changements du journal d'emplacement.
Par exemple : --since "1 mois"
Ces options n'ont aucun effet lors de l'utilisation de --sizesof, --sizes et --totalsizes.
--gource
Génère une sortie adaptée au programme de visualisation gource.
Cette option n'a aucun effet lors de l'utilisation de --sizesof, --sizes et --totalsizes.
--json
Active la sortie JSON. Ceci est destiné à être analysé par des programmes qui utilisent git-annex. Chaque ligne de sortie est un objet JSON.
Cette option n'a aucun effet lors de l'utilisation de --sizesof, --sizes et --totalsizes.
--json-error-messages
Les messages qui seraient normalement envoyés à la sortie d'erreur standard sont inclus dans le JSON.
Cette option n'a aucun effet lors de l'utilisation de --sizesof, --sizes et --totalsizes.
Les options communes git-annex(1) peuvent également être utilisées.
