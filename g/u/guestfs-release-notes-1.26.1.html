guestfs-release-notes - Notes de version de libguestfs

NOTES DE VERSION POUR LIBGUESTFS 1.26

Ces notes de version couvrent uniquement les différences par rapport à la division précédente entre les branches stable/dev (1.24.0). Pour des journaux de modifications détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive tar.

Nouvelles fonctionnalités

Outils

virt-customize(1) est un nouvel outil pour personnaliser les images de disque de machines virtuelles. Il permet d'installer des paquets, de modifier des fichiers de configuration, d'exécuter des scripts, de définir des mots de passe, etc. virt-builder(1) et virt-sysprep(1) utilisent virt-customize, et les options de ligne de commande de tous ces outils sont désormais identiques.

virt-diff(1) est un nouvel outil pour afficher les différences entre les systèmes de fichiers de deux machines virtuelles. Il est principalement utile pour montrer les fichiers modifiés entre les instantanés.

virt-builder(1) a été grandement amélioré. Il existe de nombreuses autres façons de personnaliser la machine virtuelle. Il peut récupérer des modèles de plusieurs dépôts. Une implémentation interne parallélisée de xzcat accélère la décompression des modèles. Virt-builder utilise un planificateur optimisé pour choisir la manière la plus rapide de construire la VM. Il est maintenant plus facile d'utiliser virt-builder depuis d'autres programmes. Le support de l'internationalisation a été ajouté aux métadonnées. Re-étiquetage SELinux plus efficace des fichiers. Peut construire des invités pour plusieurs architectures. Les messages d'erreur ont été améliorés. (Pino Toscano)

virt-sparsify(1) a une nouvelle option --in-place. Cela rend une image plus éparse sur place (sans la copier) et est également beaucoup plus rapide. (Beaucoup d'aide fournie par Paolo Bonzini)

virt-sysprep(1) peut supprimer et effacer des fichiers sous contrôle utilisateur. Vous pouvez verrouiller les comptes utilisateur ou définir des mots de passe aléatoires sur les comptes. Peut supprimer plus de fichiers journaux. Peut désabonner un invité du gestionnaire d'abonnements Red Hat. Nouvelle manière flexible d'activer et de désactiver les opérations. (Wanlong Gao, Pino Toscano)

virt-win-reg(1) vous permet d'utiliser des URI pour spécifier des images de disque distantes.

virt-format(1) peut maintenant renvoyer l'espace supplémentaire qu'il récupère à l'hôte.

guestfish(1) dispose de variables d'environnement supplémentaires pour un contrôle précis de l'invite "><fs>". Guestfish lit son fichier de configuration (rarement utilisé) dans un ordre différent maintenant, de sorte que les paramètres locaux remplacent les paramètres globaux. (Pino Toscano)

virt-make-fs(1) a été réécrit en C, mais reste inchangé en termes de fonctionnalités et d'utilisation de la ligne de commande.

Bindings de langage

Les bindings OCaml ont un nouveau module "Guestfs.Errno", utilisé pour vérifier le numéro d'erreur renvoyé par "Guestfs.last_errno".

Les tests PHP fonctionnent maintenant. (Pino Toscano)

Inspection

L'inspection peut reconnaître les images live Debian.

Architectures

ARMv7 (32 bits) prend désormais en charge l'accélération KVM.

Aarch64 (ARM 64 bits) est pris en charge, mais la partie appliance ne fonctionne pas encore.

Le support PPC64 a été corrigé et amélioré.

Sécurité

Déni de service lors de l'inspection d'images disque avec des volumes btrfs corrompus
Il était possible de faire planter libguestfs (et les programmes qui utilisent libguestfs comme bibliothèque) en présentant une image disque contenant un volume btrfs corrompu.

Ceci était causé par une déréférencement de pointeur NULL entraînant un déni de service, et on ne pense pas que cela puisse être exploité davantage.

Voir le commit d70ceb4cbea165c960710576efac5a5716055486 pour la correction. Cette correction est incluse dans les branches stables de libguestfs ≥ 1.26.0, ≥ 1.24.6 et ≥ 1.22.8, ainsi que dans RHEL ≥ 7.0. Les versions antérieures de libguestfs ne sont pas vulnérables.

Meilleure génération de mots de passe root et de graines aléatoires
Lors de la génération de mots de passe root et de graines aléatoires, deux bogues potentiellement liés à la sécurité ont été corrigés. Premièrement, nous ne lisons plus de manière excessive des octets de /dev/urandom (la plupart étant simplement jetés). Deuxièmement, nous avons modifié le code pour éviter le biais de modulo. On ne pense pas que ces problèmes aient pu être exploités. (Les deux modifications suggérées par Edwin Török)

API

Les paramètres GUID sont maintenant validés lorsqu'ils sont passés aux appels d'API, alors qu'auparavant, n'importe quelle chaîne de caractères pouvait être passée. (Pino Toscano)

Nouvelles APIs

"guestfs_add_drive_opts" : nouveau paramètre "discard"
Le nouveau paramètre "discard" permet un contrôle granulaire du support discard/trim pour un disque particulier. Cela permet au fichier hôte de devenir plus éparse (ou provisionné en capacité) lorsque vous supprimez des fichiers ou émettez l'appel d'API "guestfs_fstrim".
"guestfs_add_domain" : nouveaux paramètres : "cachemode", "discard"
Ces paramètres sont transmis lors de l'ajout des disques du domaine.
"guestfs_blkdiscard"
Supprime tous les blocs d'un périphérique guestfs. Combiné avec le paramètre "discard" ci-dessus, cela rend le fichier hôte éparse.
"guestfs_blkdiscardzeroes"
Teste si les blocs supprimés sont lus comme des zéros.
"guestfs_compare_*"
"guestfs_copy_*"
Pour chaque structure renvoyée via l'API, libguestfs génère maintenant des fonctions "guestfs_compare_*" et "guestfs_copy_*" pour vous permettre de comparer et copier des structures.
"guestfs_copy_attributes"
Copie les attributs (tels que les permissions, xattrs, propriété) d'un fichier à un autre. (Pino Toscano)
"guestfs_disk_create"
Une API flexible pour créer des images disque vides à partir de zéro. Cela évite d'avoir à appeler des programmes externes comme qemu-img(1).
"guestfs_get_backend_settings"
"guestfs_set_backend_settings"
Paramètres par backend (peuvent également être définis via la variable d'environnement "LIBGUESTFS_BACKEND_SETTINGS"). L'utilisation principale est de forcer le mode TCG dans les backends basés sur qemu, par exemple : 
export LIBGUESTFS_BACKEND=direct
export LIBGUESTFS_BACKEND_SETTINGS=force_tcg
"guestfs_part_get_name"
Obtient l'étiquette ou le nom d'une partition (pour les images disque GPT).

Changements de compilation

Les paquets supplémentaires suivants sont requis pour compiler libguestfs 1.26 :

supermin ≥ 5
La version 5 de Supermin est requise pour compiler cette version de libguestfs.
flex, bison
Virt-builder utilise maintenant un véritable analyseur pour analyser son fichier de métadonnées, donc ces outils sont requis.
xz
C'est maintenant une dépendance de compilation requise, alors qu'auparavant elle était (en théorie) optionnelle.

Internes

L'extraction des messages PO a été réécrite pour être plus robuste. (Pino Toscano)

"podwrapper" génère une erreur si le motif de l'argument --insert ou --verbatim n'est pas trouvé.

Libguestfs passe maintenant l'option qemu -enable-fips pour activer FIPS, si qemu le prend en charge.

"./configure --without-qemu" peut être utilisé si vous ne souhaitez pas spécifier d'hyperviseur par défaut.

Les superpositions en copie sur écriture [COW], utilisées par exemple pour les disques en lecture seule, sont maintenant créées via une API de backend interne (".create_cow_overlay").

Le backend Libvirt utilise des macros C quelque peu particulières pour générer du XML. Celles-ci sont

sûr.

Le format du fichier ChangeLog a changé. Il est maintenant identique à celui de "git log" , au lieu d'utiliser un format personnalisé.
