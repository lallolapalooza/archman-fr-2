30

Ces notes de version ne couvrent que les différences par rapport à la précédente séparation stable/dev (1.28.0). Pour les journaux de modifications détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive

virt-dib(1) est une alternative sûre et sécurisée à l'outil OpenStack « diskimage-builder ». Il est compatible avec les éléments de diskimage-builder. (Pino

Toscano)

Sécurit

é
CVE-2014-84
84
CVE-2014-84
85
Libguestfs exécutait auparavant l'utilitaire strings(1) sur des fichiers non fiables. Strings pouvait analyser les en-têtes BFD de manière non sécurisée, menant à une possible exécution de code arbitraire. Libguestfs exécute désormais strings avec un drapeau pour s'assurer qu'il n'essaie pas d'analyser les en-têtes BFD. Cela aurait pu mener à une exploitation de l'appliance libguestfs, mais comme libguestfs contraint davantage l'appliance via la virtualisation, SELinux et d'autres techniques, il était peu probable que cela ait causé une élévation de privilèges sur
l'hôte.
Injection XPath dans
virt-v2v
Une possible vulnérabilité d'injection XPath a été corrigée dans virt-v2v. Cela aurait pu permettre à un invité malveillant en cours de conversion par virt-v2v de construire une expression XPath arbitraire qui aurait été évaluée sur l'hôte (par la bibliothèque libxml2 liée au binaire virt-v2v). Il n'est pas clair quels auraient pu être les effets de cela.

Pour plus d'informations, voir le commit amont https://github.com/libguestfs/libguestfs/commit/6c6ce85f94c36803fe2db35a98db436bff

Problèmes de déni de service lors de l'utilisation de « qemu-img

Lors de l'utilisation du fuzzer American Fuzzy Lop (« afl-fuzz ») sur la commande « qemu-img info », Richard W.M. Jones a découvert que certains fichiers peuvent causer la s="Li">"qemu-img" peut utiliser beaucoup de mémoire et de temps (par exemple 6 Go de tas et 14 secondes de temps CPU sur un processeur Intel rapide), et dans certains cas provoquer un plantage. Comme libguestfs peut exécuter "qemu-img info" sur des images de disque pour découvrir ce qu'elles contiennent, cela pourrait transitoirement provoquer un blocage de libguestfs ou une consommation importante de mémoire.

Libguestfs a été modifié afin qu'il utilise des limites de ressources pour limiter l'espace et le temps utilisés par "qemu-img info", afin d'éviter ce problème. Si un utilisateur malveillant essaie de passer l'une de ces images de disque à libguestfs, "qemu-img" plantera et le plantage ser

Changements de

construction

Le démon n'utilise plus sa propre copie distincte de gnulib. Au lieu de cela, il partage une seule copie avec la

bibliothèque.

OCaml Les fichiers .annot sont maintenant créés, de sorte que les IDE et les éditeurs comme emacs et vi peuvent parcourir les types OCaml dans le code

source.

Divers correctifs pour permettre la construction avec différentes architectures hôte/appliance (Pino Toscano)

.

Automake est maintenant utilisé directement pour construire tous les programmes OCaml, au lieu de règles Makefile ad hoc. Un effet secondaire de cela est d'activer les avertissements dans tout le code C utilisé par les programmes

OCaml.

"-fno-strict-overflow" est utilisé tout au long de la construction pour éviter des optimisations GCC

douteuses.

Nettoyages multiples pour prendre en charge GCC

5.

OCaml OUnit2 est nécessaire pour exécuter certains tests

OCaml.

La création d'un libguestfs.a lié statiquement devrait à nouveau

fonctionner.

Le sous-répertoire src/api-support et ses scripts ne sont plus utilisés. Au lieu de cela, nous stockons dans le generator/actions.ml quand l'API

a été ajout
ée à libguestfs.

Interne

s

Dans tous les outils OCaml, il y a maintenant des fonctions communes "error", "warning", "info", et un moyen commun de définir et d'obtenir les drapeaux --quiet, -x (trace) et -v (verbose), et la mise en évidence des couleurs utilisée de manière

cohérente.

Les macros "COMPILE_REGEXP" sont utilisées pour simplifier les constructeurs et destructeurs

PCRE.

Dans le générateur, les arguments "Pointer" ont finalement été

implémentés.

Les identifiants internes n'utilisent plus de doubles et triples tirets bas (par ex. "guestfs___program_name"). Ces identifiants sont invalides pour les programmes C99 et C++, bien que les compilateurs les

accepteraient.

Le démon n'analyse plus les options "guestfs_*" à partir de /proc/cmdline. Au lieu de cela, il ne prend que des options de ligne de commande ordinaires. Le script d'init de l'appliance transforme /proc/cmdline en options de ligne de commande du

démon.

Les tests peuvent maintenant exécuter le démon comme un « processus captif », ce

qui permet de l'exécuter directement sur l'hôte. Le principal avantage est q
ue nous pouvons exécuter valgrind directement sur le démon pendant les tests.
