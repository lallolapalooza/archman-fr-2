guestfs-release-notes - Notes de publication de libguestfs

NOTES DE PUBLICATION POUR LIBGUESTFS 1.20

Ces notes de publication couvrent uniquement les différences par rapport à la division précédente stable/dev (1.18.0). Pour des journaux de modification détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive tar.

Nouvelles fonctionnalités

libvirt et sVirt (confinement SELinux)

Vous pouvez *optionnellement* utiliser libvirt pour lancer et gérer l'appliance backend en :

  • définissant "LIBGUESTFS_ATTACH_METHOD=libvirt[:URI]"
  • utilisant "./configure --with-default-attach-method=libvirt[:URI]"
  • ou en appelant la méthode API "guestfs_set_attach_method"

SVirt (confinement SELinux) est utilisé pour sécuriser l'appliance libguestfs, si le backend libvirt est sélectionné.

virtio-scsi, nombre de disques plus important, hotplugging

Virtio-scsi est maintenant utilisé par défaut, s'il est disponible. Cela augmente considérablement le nombre de disques pouvant être ajoutés à un seul descripteur libguestfs (jusqu'à 255).

Vous pouvez maintenant ajouter/retirer des disques à chaud (hotplugging) après le lancement.

Libguestfs peut maintenant gérer plus de 25 disques, dans toutes les API, outils et tests.

Vous pouvez étiqueter les disques lors de leur ajout, puis y faire référence par leur étiquette (/dev/disk/guestfs/LABEL) au lieu d'avoir à utiliser des noms de périphériques (/dev/sda).

nouvelles fonctionnalités de la bibliothèque

Les listes de contrôle d'accès POSIX (ACL) et les capacités de système de fichiers Linux peuvent maintenant être lues et écrites via l'API.

Les disques dynamiques Windows sont maintenant pris en charge. Les métadonnées ne peuvent être lues (les volumes ne peuvent pas être modifiés ou créés). Cependant, les données/systèmes de fichiers dans les volumes eux-mêmes peuvent être montés, lus et écrits (Matthew Booth).

Hivex (édition du registre Windows) est maintenant directement pris en charge via l'API, rendant la lecture ou l'édition du registre Windows beaucoup plus efficace.

Plusieurs API libguestfs ont été réimplémentées afin qu'elles n'aient plus de limites de sortie. Les API réimplémentées sont : "guestfs_cat", "guestfs_find", "guestfs_read_file", "guestfs_read_lines", "guestfs_write", "guestfs_write_append", "guestfs_lstatlist", "guestfs_lxattrlist", "guestfs_readlinklist", "guestfs_ls".

outils virt

"guestfish touch 'win:c:\new_file'" fonctionne maintenant comme prévu.

"guestfish" a une nouvelle option --network, qui active le réseau utilisateur dans libguestfs.

Vous pouvez définir "GUESTFISH_PS1" pour utiliser des invites fantaisistes dans "guestfish".

"rsync", "ssh", "less" et "lrzip" sont maintenant disponibles dans virt-rescue. De plus, "rsync" peut être utilisé via l'API pour effectuer des copies incrémentielles.

"virt-sparsify" utilise qcow2 v3 pour une efficacité accrue.

Améliorations de "virt-sysprep" :

  • générer de nouveaux UUID pour les PV et les VG
  • supprimer l'ID de la machine locale (Wanlong Gao)
  • supprimer les données ABRT (Wanlong Gao)
  • supprimer les clés et fichiers journaux de puppet (Wanlong Gao)
  • supprimer les fichiers de comptabilité des processus (Wanlong Gao)
  • nouveau paramètre --firstboot permettant des scripts de premier démarrage pour personnaliser les invités
  • supprimer le champ HOSTNAME des fichiers "ifcfg-eth*" (Wanlong Gao)
  • améliorations diverses pour SuSE (Olaf Hering)
  • supprimer le cache des pages de manuel (Wanlong Gao)
  • supprimer les données de crash générées par kexec-tools (Wanlong Gao)

"virt-make-fs" peut maintenant créer des disquettes virtuelles (VFD).

"guestmount" a une option --pid-file, qui peut être utilisée pour éviter une condition de concurrence entre le démontage du système de fichiers et l'utilisation de l'image disque sous-jacente.

liaisons de langage

Des liaisons Lua complètes ont été ajoutées dans cette version (grâce à Jérôme Vuarand pour de nombreuses suggestions).

En Ruby, le hachage des arguments optionnels est optionnel.

En Python, les arguments optionnels n'utilisent plus de valeurs "sentinelles" spéciales, de sorte que tout entier peut être passé comme argument optionnel.

Les liaisons Erlang sont maintenant livrées avec des exemples et des tests.

Les liaisons Erlang gèrent maintenant correctement les paramètres d'entiers 64 bits.

Les 'bindtests' automatisés testent maintenant la propreté 64 bits dans le passage des paramètres. Plusieurs bugs dans les liaisons ont été trouvés et corrigés en conséquence.

Une meilleure gestion des fonctions bloquantes et non bloquantes devrait rendre les appels libguestfs plus efficaces.

inspection

Les invités Windows avec des registres de taille illimitée sont maintenant pris en charge. En ajoutant l'API hivex à l'API libguestfs, il est beaucoup plus efficace et plus facile d'inspecter et de modifier le registre Windows dans les invités.

Meilleur support pour les invités SuSE (Olaf Hering).

Retourne l'architecture des applications installées (John Eckersberg).

Windows 8 est maintenant pris en charge.

Fedora 18 est maintenant prise en charge.

L'inspection des ISO/CD/DVD peut maintenant utiliser la base de données libosinfo.

ports

Libguestfs sans l'appliance peut être compilé sur Mac OS X (Masami HIRATA).

RHEL 5 est maintenant explicitement pris en charge via la branche 'oldlinux' dans le dépôt git principal.

PowerPC 64 bits est maintenant pris en charge. De plus, libguestfs a été examiné pour détecter les bugs d'endianness et ceux-ci ont été corrigés.

daemon

Une page de manuel pour le démon (guestfsd(8)) est incluse.

Sécurité

fichier d'historique guestfish

Le fichier d'historique $HOME/.guestfish est maintenant créé avec les permissions 0600 (au lieu de 0644 avant) de sorte qu'il n'est plus lisible par tous.

CVE-2012-2690

Les anciennes versions de "virt-edit" et de la commande "edit" de "guestfish" créaient un nouveau fichier contenant les modifications mais ne définissaient pas les permissions, etc. du nouveau fichier pour qu'elles correspondent à l'ancien. Le résultat était que si vous éditiez un fichier sensible à la sécurité comme /etc/shadow, il serait laissé lisible par tous après l'édition.

Ce problème s'est vu attribuer le CVE-2012-2690 et est corrigé dans libguestfs >= 1.16.

Pour plus d'informations, voir https://bugzilla.redhat.com/show_bug.cgi?id=788642

Internes

qemu ≥ 1.1 est requis (≥ 1.2 de préférence).

febootstrap ≥ 3.20 est requis.

libvirt est facultatif, mais si vous souhaitez utiliser le nouveau backend libvirt pour lancer l'appliance, alors libvirt ≥ 0.10.2 serait requis.

Coverity a été exécuté sur l'ensemble de la base de code, et de nombreux problèmes ont été corrigés (merci Ondrej Vasik, Kamil Dudka).

Les fonctions qui n'avaient auparavant pas d'arguments optionnels peuvent maintenant être converties en fonctions avec arguments optionnels, rendant l'extension de l'API beaucoup plus flexible. La compatibilité ascendante source et binaire est préservée pour les utilisateurs de l'API.

La manière dont les API et les structures libguestfs sont représentées dans le générateur a changé pour utiliser une structure OCaml au lieu d'un tuple. Cela rend les descriptions du générateur plus flexibles et plus faciles à comprendre. Pour plus de détails, voir les commits 39d1a7db et eb185eef.

Séparation du code de la bibliothèque en plus de fichiers :

  • Les backends de lancement sont maintenant situés dans des fichiers séparés, par exemple src/launch-appliance.c, "src/launch-libvirt.c".
  • Le code d'action généré est maintenant réparti sur plusieurs fichiers src/action*.c, pour une compilation plus rapide.
  • L'énorme fichier src/guestfs.c est maintenant divisé en unités logiques plus petites.

POD (documentation) est maintenant généré à l'aide d'un programme Perl réécrit au lieu de pod2* + scripts shell.

Les pages de manuel contiennent maintenant des dates stables (Hilko Bengen).

Les tests ignorés se terminent maintenant avec le code 77, de sorte qu'ils apparaissent comme "SKIP:" dans la sortie de "make check".

Le test parallèle de montage local a été réécrit en C (RHBZ#838081).

Ruby 1.8.5 est maintenant pris en charge (bien que Ruby ≥ 1.9 soit préféré).

Les bindings Perl peuvent être désactivés via "./configure --disable-perl" (Wulf C. Krueger). Notez que Perl est toujours requis pour construire libguestfs.

Les bindings Java sont maintenant activés/désactivés en utilisant "./configure --with-java" ou "./configure --without-java" (Wulf C. Krueger).

Nouvelles options de configuration "./configure --enable-code-profiling" et "./configure --enable-code-coverage".

Plusieurs corrections dans l'utilisation des entiers 64 bits dans les bindings de langage.

Le backend appliance utilise maintenant sgabios au lieu de vgabios (Dan Berrange).

Le script "./run" définit maintenant suffisamment de variables d'environnement pour que vous puissiez exécuter des programmes OCaml, Python, Ruby, Java, GJS, Erlang, Lua.

"./run --test" est un indicateur pour exécuter les tests avec une sortie minimale. Il affiche également le temps nécessaire pour exécuter chaque test.

Le script "./run" construit maintenant les chemins de manière cumulative, ce qui signifie que vous pouvez utiliser "./run" deux fois, ou utiliser les scripts "./run" de libguestfs et libvirt ensemble.

Vous pouvez extraire une liste des commandes externes requises par le démon, ce qui facilite la construction de l'appliance sur certaines distributions (Olaf Hering).

La commande "virt-rescue" est maintenant testée pendant "make check".

Le générateur supprime maintenant les fichiers générés inutilisés. Cela aide lors des allers-retours avec git rebase, git bisect, etc.

Les tests s'exécutent maintenant dans un répertoire "tmp/" de haut niveau séparé dans la source. Cela permet de labelliser le répertoire pour SELinux (sVirt), et rend également le nettoyage plus facile.

"make syntax-check" fonctionne maintenant dans une plus grande mesure, et de nombreux problèmes dans le code principal détectés par syntax-check ont été corrigés (merci Jim Meyering).

Le mode Emacs (-*- foo -*-) a été ajouté aux fichiers générés.

La sortie de la barre de progression est maintenant envoyée à /dev/tty afin qu'elle ne se retrouve pas dans la sortie normale du programme. virt-resize et virt-sparsify suppriment maintenant les barres de progression si stdout n'est pas un tty.

Il existe maintenant une option "./configure --without-libvirt". Ceci est utile pour tester que le code compile toujours sans libvirt.

Il existe maintenant une mini-bibliothèque interne pour exécuter des commandes. Cela nous permet de rediriger les erreurs des commandes externes dans des événements.

Le code de gestion des répertoires temporaires et du cache de l'appliance a été complètement revu.

Le code pour ignorer/désactiver temporairement les erreurs ressemble maintenant à ceci :

guestfs_push_error_handler (g, NULL, NULL);
guestfs_mkdir (g, "/foo"); /* Nous nous soucions peu si cela échoue. */
guestfs_pop_error_handler (g);

Le répertoire "tests/extra" a disparu. Les "tests supplémentaires" sont maintenant répartis en cibles exécutables séparément, telles que "make check-valgrind". Utilisez "make help" pour obtenir un résumé des cibles.

L'option "lpj" est passée au noyau de l'appliance lors de l'utilisation de TCG. Cela devrait améliorer la stabilité de l'horloge (merci Marcelo Tosatti, Olaf Hering).
