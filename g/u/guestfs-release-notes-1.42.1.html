NOTES DE VERSION DE LIBGUESTFS 1.

42

Veuillez noter que virt-v2v, virt-p2v et les outils d'analyse de démarrage ont été déplacés hors du paquet / dépôt libguestfs vers des projets séparés. Voir

:
  • https://github.com/libguestfs/virt-
    • v2v
  • https://github.com/libguestfs/virt-
    • p2v
  • https://github.com/libguestfs/libguestfs-analysis-too
    • l
s

Ces projets suivent désormais un cycle de version indépendant. Les notes de version sont publiées

séparément.

Nouvelles

fonctionnalités

Ajout du support du langage Vala (Corentin Noël)

.

Ajout du support du langage Rust (Hiroyuki Katsura, sponsorisé par Google Summer of Code)

.

Générations reproductibles (Chris Lamb)

.

Les disques Advanced Format (qui utilisent des secteurs de 4K) peuvent désormais être traités par libguestfs. Utilisez le nouveau paramètre facultatif "blocksize" de "guestfs_add_drive_opts", ainsi que l'option --blocksize ajoutée à plusieurs outils (Nikolay Ivanets)

.

Windows CompactOS (compression de fichiers NTFS) est désormais pris en

charge.

Nouvelles fonctionnalités dans les outils

existants

La sortie avancée lisible par machine dans divers outils virt prend désormais en charge la sortie JSON et l'écriture des journaux dans un descripteur de fichier numéroté (Pino Toscano)

.

L'outil virt-filesystems signale désormais la taille totale du système de fichiers de manière plus précise, par exemple lorsque le système de fichiers n'occupe pas l'intégralité de son périphérique conteneur (Pino Toscano)

.

Liaisons de

langages

Python ≥ 2.7 est

requis.

Les liaisons Python sont désormais testées plus en profondeur (Hiroyuki Katsura)

.

Les liaisons Python devraient désormais fonctionner avec Python ≥ 3.

8.

Corrections multiples pour éviter les plantages dans les liaisons Python (Sam Eiderman)

.

Les liaisons OCaml sont compilées avec "-DCAML_NAME_SPACE" pour garantir qu'aucun symbole hors de l'espace de noms caml_ n'est utilisé (Pino Toscano)

.

Les liaisons OCaml devraient désormais fonctionner avec OCaml 4.09 et 4.

10.

Erlang a déprécié l'ancienne bibliothèque "erl_interface" que nous utilisons pour les liaisons Erlang. Elle sera supprimée dans OTP 22, ce qui cassera définitivement le support d'Erlang à moins que quelqu'un ne se propose pour mettre à jour les liaisons Erlang dans

libguestfs.

Correction de la compatibilité avec les versions plus récentes de cgo pour les liaisons Go (Tomáš Golembiovský)

.

La gestion des erreurs de l'API Go est désormais plus idiomatique (Csaba Henk)

.

Mise à jour de la documentation sur la manière de gérer les paramètres booléens dans les liaisons Ruby (Csaba Henk)

.

Inspectio

n

Libguestfs peut désormais extraire les icônes pour les invités Gentoo, SUSE plus récents et OpenMandriva. Extraction améliorée des icônes RHEL (Pino Toscano)

.

L'inspection renvoie les identifiants osinfo des versions plus récentes de Windows et des distributions Linux en développement continu (Pino Toscano)

.

OpenMandriva est désormais détecté (Bernhard Rosenkränzer)

.

Améliorations de la détection d'Arch Linux (Pino Toscano)

.

Architectures et

plateformes

Libguestfs peut désormais être compilé sur OpenMandriva (Bernhard Rosenkränzer)

.

Correction sous Ubuntu pour activer le support réseau (Ioanna Alifieraki)

.

Autre

s

L'utilisation des API libguestfs dépréciées déclenchera désormais par défaut des avertissements de dépréciation du compilateur, alors qu'auparavant vous deviez activer ces avertissements. Pour désactiver ces avertissements, utilisez "-DGUESTFS_NO_WARN_DEPRECATED=1". Une nouvelle fonctionnalité permet désormais de désactiver complètement les API dépréciées si vous le souhaitez, en utilisant "-DGUESTFS_NO_DEPRECATED=1" (Pino Toscano)

.

Correction du nom d'hôte dans les modèles virt-builder (Pino Toscano)

.

Le fichier unique de notes de version est désormais divisé en plusieurs documents organisés par

version.

L'option "--key" de plusieurs outils était cassée, surtout si vous essayiez de l'utiliser pour passer plusieurs clés. Cela a été corrigé et un test de non-régression a été

ajouté.

Changements de

La version minimale d'Augeas requise est 1.2.0 (Pino Toscano)

Le sous-répertoire "common/" est désormais un sous-module git partagé avec le projet

Supermin ≥ 5.1.18 est

Il y avait plusieurs bogues dans libvirt 5.10.0 et 6.0 qui affectaient libguestfs. Il est fortement conseillé d'utiliser libvirt 6.1 où ces bogues sont corrigés (les versions de libvirt < 5.10.0 conviennent également)

De nombreux modules gnulib que nous n'utilisions pas ou que nous utilisions en quelques endroits seulement ont été supprimés (Pino Toscano)

.

Corrections multiples pour les constructions où builddir != sourcedir (Pino Toscano)

Un nouveau sous-répertoire "bundled/" contient une bibliothèque groupée que nous utilisons actuellement, "ocaml-augeas" (Pino Toscano)

Détails

internes

Lors de l'édition de liens des programmes OCaml, les règles silencieuses d'automake et l'indicateur "V=1" sont désormais tous deux respectés (Pino Toscano)

.

L'API "guestfs_device_index" a été réimplémentée dans le code de la bibliothèque au lieu du démon. Il ne devrait y avoir aucun effet observable de ce

changement.

Depuis que Linux 5.6 énumère les périphériques "/dev/sdX" en parallèle, libguestfs a été modifié pour associer les noms de périphériques de l'API aux noms de périphériques de l'appliance, puis effectuer l'association inverse lors du retour des noms depuis l'appliance. On espère que cela n'aura aucun effet observable, mais cela peut produire des messages de débogagement quelque peu déroutants car les noms de périphériques dans le débogage peuvent ne pas correspondre aux noms de périphériques passés aux API. De plus, l'option "root=UUID=..." est toujours passée à l'appliance (au lieu de nommer le périphérique contenant le système de fichiers racine)

.

Nous prévoyons de passer du service Zanata au service Weblate pour les chaînes traduites. Pour plus d'informations, voir https://bugz

illa.redhat
.com/1787301
