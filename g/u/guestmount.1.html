guestmount(1) Support de la virtualisation guestmount(1)

NOM

guestmount - Monter un système de fichiers invité sur l'hôte en utilisant FUSE et libguestfs

SYNOPSIS

guestmount [--options] -a disque.img -m périphérique [--ro] point_de_montage
guestmount [--options] -a disque.img -i [--ro] point_de_montage
guestmount [--options] -d Invité -i [--ro] point_de_montage

ATTENTION

Utiliser "guestmount" en mode écriture sur des machines virtuelles actives, ou simultanément avec d'autres outils de modification de disque, peut être dangereux et potentiellement entraîner une corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées simultanément.

Utilisez l'option --ro (lecture seule) pour utiliser "guestmount" en toute sécurité si l'image disque ou la machine virtuelle peut être active. Vous pourriez voir des résultats étranges ou incohérents si l'utilisation est simultanée avec d'autres modifications, mais avec cette option, vous ne risquez pas la corruption du disque.

DESCRIPTION

Le programme guestmount peut être utilisé pour monter des systèmes de fichiers de machines virtuelles et d'autres images disque sur l'hôte. Il utilise libguestfs pour accéder au système de fichiers invité, et FUSE (le « système de fichiers dans l'espace utilisateur ») pour le faire apparaître comme un périphérique montable.

Avec d'autres options, vous devez fournir au moins un périphérique (option -a) ou un domaine libvirt (option -d), et au moins un point de montage (option -m) ou utiliser l'option d'inspection -i. Comment cela fonctionne est mieux expliqué dans la page de manuel de guestfish(1), ou en regardant les exemples ci-dessous.

FUSE permet de monter des systèmes de fichiers en tant qu'utilisateur non-root. Le point de montage doit vous appartenir. Le système de fichiers ne sera visible par aucun autre utilisateur à moins que vous ne modifiiez la configuration, voir "NOTES" ci-dessous.

Pour démonter le système de fichiers, utilisez la commande guestunmount(1).

EXEMPLES

Pour un invité Windows typique dont le système de fichiers principal se trouve sur la première partition :

guestmount -a windows.img -m /dev/sda1 --ro /mnt

Pour un invité Linux typique qui a un système de fichiers /boot sur la première partition, et le système de fichiers racine sur un volume logique :

guestmount -a linux.img -m /dev/VG/LV -m /dev/sda1:/boot --ro /mnt

Pour que libguestfs détecte les points de montage invités pour vous :

guestmount -a guest.img -i --ro /mnt

Pour un invité libvirt nommé « Invité », vous pourriez faire : 

guestmount -d Invité -i --ro /mnt

Si vous ne savez pas quels systèmes de fichiers sont contenus dans un invité ou une image disque, utilisez d'abord virt-filesystems(1) : 

virt-filesystems -d MonInvité

Si vous voulez tracer les appels libguestfs mais sans informations de débogage excessives, nous recommandons :

guestmount [...] --trace /mnt

Si vous voulez déboguer le programme, nous recommandons :

guestmount [...] --trace --verbose /mnt

Pour démonter le système de fichiers après l'avoir utilisé :

guestunmount /mnt

NOTES

Les autres utilisateurs ne voient pas le système de fichiers par défaut

Si vous montez un système de fichiers en tant qu'utilisateur (par exemple, root), alors les autres utilisateurs ne pourront pas le voir par défaut. La solution est d'ajouter l'option FUSE "allow_other" lors du montage :

sudo guestmount [...] -o allow_other /mnt

et d'activer cette option dans /etc/fuse.conf.

Activation de FUSE

Sur certaines distributions, vous devrez peut-être vous ajouter à un groupe spécial (par exemple, "fuse") avant de pouvoir utiliser un système de fichiers FUSE. Ceci est nécessaire sur Debian et ses dérivés.

Sur d'autres distributions, aucun groupe spécial n'est requis. Ce n'est pas nécessaire sur Fedora ou Red Hat Enterprise Linux.

fusermount erreur : "Périphérique ou ressource indisponible"

Vous pouvez voir cette erreur lorsqu'un autre processus sur le système s'introduit dans le point de montage que vous venez de créer, le gardant ouvert et vous empêchant de le démonter. Les coupables habituels sont divers programmes d'« indexation » graphiques.

La solution populaire à ce problème est de réessayer la commande "fusermount -u" plusieurs fois jusqu'à ce qu'elle fonctionne (guestunmount(1) le fait pour vous). Malheureusement, ce n'est pas une solution fiable si (par exemple) le système de fichiers monté est particulièrement grand et que le programme intrus est particulièrement persistant.

Une solution appropriée consiste à utiliser un point de montage privé en créant un nouvel espace de noms de montage à l'aide du drapeau Linux-spécifique clone(2)/unshare(2) "CLONE_NEWNS". Malheureusement, pour le moment, cela nécessite root et nous devrions probablement également l'ajouter comme fonctionnalité à guestmount.

Conditions de course possibles lors de l’arrêt de la connexion

Lorsque guestunmount(1)/fusermount(1) se termine, guestmount peut encore s'exécuter et nettoyer le point de montage. L'image disque ne sera pas entièrement finalisée.

Cela signifie que les scripts comme celui-ci ont une méchante condition de course :

guestmount -a disque.img -i /mnt
# copier des choses dans /mnt
guestunmount /mnt
# essayer immédiatement d'utiliser 'disque.img' ** NON SÉCURISÉ **

La solution est d'utiliser l'option --pid-file pour écrire le PID de guestmount dans un fichier, puis après guestunmount, attendre que ce PID se termine.

guestmount -a disque.img -i --pid-file guestmount.pid /mnt

# ...
# ...

# Sauvegarder le PID de guestmount *avant* d'appeler guestunmount.
pid="$(cat guestmount.pid)"

# Démonter le système de fichiers.
guestunmount /mnt

timeout=10

count=$timeout
while kill -0 "$pid" 2>/dev/null && [ $count -gt 0 ]; do
    sleep 1
    ((count--))
done
if [ $count -eq 0 ]; then
    echo "$0: attente de la sortie de guestmount échouée après $timeout secondes"
    exit 1
fi

# Il est maintenant sûr d'utiliser l'image disque.

Notez que si vous utilisez directement l'API "guestfs_mount_local" (voir « MOUNT LOCAL » dans guestfs(3)), il est beaucoup plus facile d'écrire un programme sûr et sans conditions de course.

OPTIONS

-a IMAGE
--add IMAGE
Ajouter un périphérique bloc ou une image de machine virtuelle.

Le format de l'image disque est détecté automatiquement. Pour l'ignorer et forcer un format particulier, utilisez l'option --format=...

-a URI
--add URI
Ajouter un stockage distant. Voir « AJOUT DE STOCKAGE DISTANT » dans guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille du secteur de l'image disque. Il affecte tous les disques ajoutés explicitement par la suite après ce paramètre. Utiliser --blocksize sans argument fait passer la taille du secteur du disque à la valeur par défaut, qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Lorsqu'il est utilisé conjointement avec l'option -d, cela spécifie l'URI libvirt à utiliser. Par défaut, il utilise la connexion libvirt par défaut.
-d DOMAINE-LIBVIRT

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

d>
--domain LIBVIRT-DOMAIN
Ajoute des disques du domaine libvirt nommé. Si l'option --ro est également utilisée, alors tout domaine libvirt peut être utilisé. Cependant, en mode écriture, seuls les domaines libvirt arrêtés peuvent être nommés ici.

Les UUID de domaine peuvent être utilisés à la place des noms.

--dir-cache-timeout N
Définit le délai de mise en cache de readdir à N secondes, la valeur par défaut étant de 60 secondes. Le cache de readdir [en fait, il existe plusieurs caches semi-indépendants] est rempli après un appel à readdir(2) avec les statistiques et les attributs étendus des fichiers du répertoire, en prévision de leur demande imminente.

Il existe également un cache d'attributs différent implémenté par FUSE (voir l'option FUSE -o attr_timeout), mais le cache FUSE n'anticipe pas les requêtes futures, il ne met en cache que les requêtes existantes.

--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, guestfish désactive normalement l'écho afin que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--fd=FD
Spécifie un descripteur de fichier pipe ou eventfd. Lorsque le point de montage est prêt à être utilisé, guestmount écrit un seul octet dans ce descripteur de fichier. Ceci peut être utilisé conjointement avec --no-fork afin d'exécuter guestmount en mode captif sous un autre processus.
--format=raw|qcow2|..
--format
La valeur par défaut de l'option -a est de détecter automatiquement le format de l'image disque. L'utilisation de cette option force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format sans argument revient à la détection automatique pour les options -a suivantes.

Si vous avez des images de disque invité non fiables au format raw, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851). Voir également "guestfs_add_drive_opts" dans guestfs(3).

--fuse-help
Affiche l'aide sur les options spéciales FUSE (voir -o ci-dessous).
--help
Affiche une aide brève et quitte.
-i
--inspector
En utilisant le code de virt-inspector(1), inspecte les disques à la recherche d'un système d'exploitation et monte les systèmes de fichiers tels qu'ils seraient montés sur la machine virtuelle réelle.
--key SELECTOR
Spécifie une clé pour LUKS, pour ouvrir automatiquement un périphérique LUKS lors de l'inspection.
--key NAME:key:KEY_STRING
--key UUID:key:KEY_STRING
--key all:key:KEY_STRING
"NAME" est le nom du périphérique libguestfs (par exemple, "/dev/sda1"). "UUID" est l'UUID du périphérique. "all" signifie essayer la clé contre tout périphérique chiffré.

Utilisez la "KEY_STRING" spécifiée comme phrase secrète.

--key NAME:file:FILENAME
--key UUID:file:FILENAME
--key all:file:FILENAME
Lit la phrase secrète depuis FILENAME.
--key NAME:clevis
--key UUID:clevis
--key all:clevis
Tente un déverrouillage sans phrase secrète pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente dans la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lit les paramètres de clé ou de phrase secrète depuis stdin. La valeur par défaut est d'essayer de lire les phrases secrètes de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous devrez peut-être fournir plusieurs clés sur stdin, une par ligne.

-m dev[:mountpoint[:options[:fstype]]
--mount dev[:mountpoint[:options[:fstype]]]
Monte la partition ou le volume logique nommé au point de montage donné dans l'invité (cela n'a rien à voir avec les points de montage sur l'hôte).

Si le point de montage est omis, il vaut par défaut /. Vous devez monter quelque chose sur /.

La troisième partie (rarement utilisée) du paramètre de montage est la liste des options de montage utilisées pour monter le système de fichiers sous-jacent. Si elle n'est pas fournie, les options de montage sont soit la chaîne vide, soit "ro" (ce dernier si le drapeau --ro est utilisé). En spécifiant les options de montage, vous remplacez ce choix par défaut. La seule fois où vous utiliserez probablement cela est pour activer les ACL et/ou les attributs étendus si le système de fichiers peut les supporter :

-m /dev/sda1:/:acl,user_xattr

La quatrième partie du paramètre est le pilote de système de fichiers à utiliser, tel que "ext3" ou "ntfs". Ceci est rarement nécessaire, mais peut être utile si plusieurs pilotes sont valides pour un système de fichiers (par exemple : "ext2" et "ext3"), ou si libguestfs identifie mal un système de fichiers.

--no-fork
Ne pas démoniser (ou ne pas se détacher en arrière-plan).
-n
--no-sync
Par défaut, nous tentons de synchroniser le disque de l'invité lorsque le point de montage FUSE est démonté. Si vous spécifiez cette option, alors nous n'essayons pas de synchroniser le disque. Voir la discussion sur l'autosync dans la page de manuel de guestfs(3).
-o OPTION
--option OPTION
Passe des options supplémentaires à FUSE.

Pour obtenir une liste de toutes les options supplémentaires supportées par FUSE, utilisez la commande ci-dessous. Notez que seules les options FUSE -o peuvent être passées, et seulement certaines d'entre elles sont judicieuses.

guestmount --fuse-help

Quelques options FUSE potentiellement utiles :

-o allow_other
Permet à d'autres utilisateurs de voir le système de fichiers. Cette option n'a aucun effet à moins que vous ne l'activiez globalement dans /etc/fuse.conf.
-o attr_timeout=N
Active la mise en cache des attributs par FUSE et définit le délai d'attente à N secondes.
-o kernel_cache
Permet au noyau de mettre en cache les fichiers (réduit le nombre de lectures qui doivent passer par l'API guestfs(3)). C'est généralement une bonne idée si vous pouvez vous permettre l'utilisation supplémentaire de mémoire.
-o uid=N -o gid=N
Utilisez ces options pour mapper tous les UID et GID à l'intérieur du système de fichiers invité aux valeurs choisies.
-o use_ino
Conserve les numéros d'inode du système de fichiers sous-jacent.

Sans cette option, FUSE crée ses propres numéros d'inode. Les numéros d'inode que vous voyez dans stat(2), "ls -i" etc. ne sont pas les numéros d'inode du système de fichiers sous-jacent.

Note : cette option est potentiellement dangereuse si le système de fichiers sous-jacent est composé de plusieurs points de montage, car vous pourriez voir des numéros d'inode dupliqués apparaître via FUSE. L'utilisation de cette option peut confondre certains logiciels.

--pid-file FILENAME
Écrit le PID du processus travailleur de guestmount dans "filename".
-r
--ro
Ajoute les périphériques et monte tout en lecture seule. Interdit également les écritures et rend le disque accessible en lecture seule à FUSE.

Ceci est fortement recommandé si vous n'allez pas modifier le disque de l'invité. Si l'invité est en cours d'exécution et que cette option n'est *pas* fournie, il y a un risque élevé de corruption du disque dans l'invité. Nous essayons d'empêcher cela, mais ce n'est pas toujours possible.

Voir également "OUVERTURE DES DISQUES EN LECTURE ET ÉCRITURE" dans guestfish(1).

--selinux
Cette option est fournie pour des raisons de compatibilité ascendante et ne fait rien.
-v
--verbose
Active les messages détaillés des libguestfs sous-jacentes.
-V
--version
Affiche la version du programme et quitte.
-w
--rw
Ceci modifie les options -a, -d et -m de sorte que les disques soient ajoutés et les montages effectués en lecture-écriture.

Voir "OUVERTURE DES DISQUES EN LECTURE ET ÉC

RITE" dans guestfish(1).

-x
--trace
Trace les appels libguestfs et l'entrée dans chaque fonction FUSE. Cela empêche également le démon de se détacher en arrière-plan (voir

--no-fork )..

CODE DE RETOUR

Ce programme renvoie 0 en cas de succès, ou une valeur non nulle en cas d'erreur.
