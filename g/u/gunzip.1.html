DESCRIPTIO

N

La commande gzip réduit la taille des fichiers nommés en utilisant le codage Lempel-Ziv (LZ77). Chaque fois que c'est possible, chaque fichier est remplacé par un fichier avec l'extension .gz, tout en conservant les mêmes modes de propriété, les temps d'accès et de modification. (L'extension par défaut est z pour MSDOS, OS/2 FAT, Windows NT FAT et Atari.) Si aucun fichier n'est spécifié, ou si un nom de fichier est « - », l'entrée standard est compressée vers la sortie standard. La commande gzip essaiera uniquement de compresser des fichiers réguliers. En particulier, elle ignorera les liens

symboliques.

Si le nom du fichier compressé est trop long pour son système de fichiers, gzip le tronque. La commande gzip essaie de tronquer uniquement les parties du nom de fichier plus longues que 3 caractères. (Une partie est délimitée par des points.) Si le nom ne consiste qu'en de petites parties, les parties les plus longues sont tronquées. Par exemple, si les noms de fichiers sont limités à 14 caractères, gzip.msdos.exe est compressé en gzi.msd.exe.gz. Les ne sont pas tronqués sur les systèmes qui n'ont pas de limite sur la longueur des noms de

fichiers.

Par défaut, gzip conserve le nom de fichier original et l'horodatage dans le fichier compressé. Ceux-ci sont utilisés lors de la décompression du fichier avec l'option -N. C'est utile lorsque le nom du fichier compressé a été tronqué ou lorsque l'horodatage n'a pas été préservé après un transfert de

fichier.

Les fichiers compressés peuvent être restaurés à leur forme originale en utilisant gzip -d ou gunzip ou zcat. Si le nom original enregistré dans le fichier compressé n'est pas adapté à son système de fichiers, un nouveau nom est construit à partir de l'original pour le rendre

valide.

gunzip prend une liste de fichiers sur sa ligne de commande et remplace chaque fichier dont le nom se termine par .gz, -gz, .z, -z, ou _z (en ignorant la casse) et qui commence par le bon nombre magique par un fichier non compressé sans l'extension originale. gunzip reconnaît également les extensions spéciales .tgz et .taz comme raccourcis pour .tar.gz et .tar.Z respectivement. Lors de la compression, gzip utilise l'extension .tgz si nécessaire au lieu de tronquer un fichier avec une extension .ta

r.

gunzip peut actuellement décompresser les fichiers créés par gzip, zip, compress, compress -H ou pack. La détection du format d'entrée est automatique. Lors de l'utilisation des deux premiers formats, gunzip vérifie un CRC de 32 bits. Pour pack et gunzip vérifie la longueur non compressée. Le format standard compress n'a pas été conçu pour permettre des vérifications de cohérence. Cependant gunzip est parfois capable de détecter un mauvais fichier .Z. Si vous obtenez une erreur lors de la décompression d'un fichier .Z, ne supposez pas que le fichier .Z est correct simplement parce que la commande uncompress standard ne se plaint pas. Cela signifie généralement que la commande uncompress standard ne vérifie pas son entrée et génère gaiement une sortie inutile. Le format SCO compress -H (méthode de compression lzh) n'inclut pas de CRC mais permet également certaines vérifications de

cohérence.

Les fichiers créés par zip peuvent être décompressés par gzip uniquement s'ils ont un seul membre compressé avec la méthode « deflate ». Cette fonctionnalité est uniquement destinée à aider à la conversion des fichiers tar.zip au format tar.gz. Pour extraire un fichier zip avec un seul membre, utilisez une commande comme «gunzip <foo.zip » ou «gunzip -S .zip foo.zip ». Pour extraire des fichiers zip avec plusieurs membres, utilisez unzip au lieu de gunzip

.

La commande zcat est identique à gunzip -c. (Sur certains systèmes, zcat peut être installé en tant que gzcat pour préserver le lien original vers compress.) zcat décompresse soit une liste de fichiers sur la ligne de commande, soit son entrée standard, et écrit les données non compressées sur la sortie standard. zcat décompressera les fichiers qui ont le bon nombre magique, qu'ils aient ou non un suffixe .gz

.

La commande gzip utilise l'algorithme Lempel-Ziv utilisé dans zip et PKZIP. La quantité de compression obtenue dépend de la taille de l'entrée et de la distribution des sous-chaînes communes. Typiquement, un texte tel que du code source ou de l'anglais est réduit de 60 à 70 %. La compression est généralement bien meilleure que celle obtenue par LZW (comme utilisé dans compress), le codage de Huffman (comme utilisé dans pack), ou le codage de Huffman adaptatif (compac

t).

La compression est toujours effectuée, même si le fichier compressé est légèrement plus grand que l'original. L'expansion dans le pire des cas est de quelques octets pour l'en-tête du fichier gzip, plus 5 octets par bloc de 32 KiB, soit un taux d'expansion de 0,015 % pour les grands fichiers. Le nombre réel de blocs de disque utilisés n'augmente presque

jamais.

gzip préserve normalement le mode et l'horodatage de modification d'un fichier lors de la compression ou de la déc

ompression. Si vous avez les privilèges appropriés, il
préserve également le propriétaire et le groupe du fichier.

List information about the compressed file. The information displayed is: Uncompressed size, compressed size, percentage of compression, uncompressed name, timestamp, and CRC. A short listing is produced by default. Use -v to get the full listing.

When decompressing, do not restore the original file name. The restored file name is empty. When decompressing, do not restore the original timestamp. The restored timestamp is the current time. -N --name
When compressing, always save the original file name, and save the seconds part of the original modification timestamp if the original is a regular file and its timestamp is at least 1 (1970-01-01 00:00:01 UTC) and is less than 2**32 (2106-02-07 06:28:16 UTC, assuming leap seconds are not counted); this is the default. When decompressing, restore from the saved file name and timestamp if present. --rsyncable
When you synchronize a compressed file between two computers, this option allows rsync to transfer only files that were changed in the archive instead of the entire archive. Normally, after a change is made to any file in the archive, the compression algorithm can generate a new version of the archive that does not match the previous version of the archive. In this case, rsync transfers the entire new version of the archive to the remote computer. With this option, rsync can transfer only the changed files as well as a small amount of metadata that is required to update the archive structure in the area that was changed.

UTILISATION AVANCÉE

Plusieurs fichiers compressés peuvent être concaténés. Dans ce cas, gunzip extraira tous les membres à la fois. Par exemple :


gzip -c file1 > foo.gz
gzip -c file2 >> foo.gz

Ensuite


gunzip -c foo

est équivalent à


cat file1 file2

En cas de corruption d'un membre d'un fichier .gz, d'autres membres peuvent toujours être récupérés (si le membre corrompu est supprimé). Cependant, vous obtiendrez une meilleure compression en compressant tous les membres à la fois :


cat file1 file2 | gzip > foo.gz

compresse mieux que


gzip -c file1 file2 > foo.gz

Si vous souhaitez recompresser des fichiers concaténés pour obtenir une meilleure compression, faites :


gzip -cd old.gz | gzip > new.gz

Si un fichier compressé se compose de plusieurs membres, la taille décompressée et le CRC rapportés par l'option --list s'appliquent au dernier membre uniquement. Si vous avez besoin de la taille décompressée pour tous les membres, vous pouvez utiliser :


gzip -cd file.gz | wc -c

Si vous souhaitez créer un fichier archive unique avec plusieurs membres afin que les membres puissent être extraits indépendamment plus tard, utilisez un archiveur tel que tar ou zip. GNU tar prend en charge l'option -z pour invoquer gzip de manière transparente. gzip est conçu comme un complément à tar, et non comme un remplacement.

ENVIRONNEMENT

La variable d'environnement GZIP peut contenir un ensemble d'options par défaut pour gzip. Ces options sont interprétées en premier et peuvent être remplacées par des paramètres de ligne de commande explicites. Comme cela peut poser des problèmes lors de l'utilisation de scripts, cette fonctionnalité n'est prise en charge que pour --rsyncable, --synchronous et les options telles que -9 qui définissent le niveau de compression ; toute autre option ou opérande dans GZIP est ignoré silencieusement.

Vous pouvez utiliser un alias ou un script à la place. Par exemple, au lieu de définir GZIP="-9" dans l'environnement, si gzip se trouve dans le répertoire /usr/bin, vous pouvez préfixer $HOME/bin à votre PATH et créer un script exécutable $HOME/bin/gzip contenant ce qui suit :


#! /bin/sh
export PATH=/usr/bin
exec gzip -9 "$@"

DIAGNOSTICS

Le code de sortie est normalement 0 ; en cas d'erreur, le code de sortie est 1. En cas d'avertissement, le code de sortie est 2.

Usage: gzip [-cdfhklLnNrtvV19] [-S suffix] [file ...]
Des options invalides ont été spécifiées sur la ligne de commande.
file: not in gzip format
Le fichier spécifié à gunzip n'a pas été compressé.
file: Corrupt input.
Utilisez zcat pour récupérer des données. Le fichier compressé a été endommagé. Les données jusqu'au point de défaillance peuvent être récupérées à l'aide de


zcat file > recover

file: compressed with xx bits, can only handle yy bits
File a été compressé (en utilisant LZW) par un programme qui pouvait gérer plus de bits que le code de décompression sur cette machine. Recompressez le fichier avec gzip, qui compresse mieux et utilise moins de mémoire.
file: already has .gz suffix -- unchanged
Le fichier est supposé être déjà compressé. Renommez le fichier et réessayez.
file already exists; do you wish to overwrite (y or n)?
Répondez "y" si vous souhaitez que le fichier de sortie soit remplacé ; "n" sinon.
gunzip: corrupt input
Une violation SIGSEGV a été détectée, ce qui signifie généralement que le fichier d'entrée a été corrompu.
xx.x% Pourcentage de l'entrée sauvegardé par la compression.
(Pertinent uniquement pour -v et -l.)
-- not a regular file or directory: ignored
Lorsque le fichier d'entrée n'est pas un fichier ordinaire ou un répertoire (par exemple, un lien symbolique, un socket, un FIFO, un fichier de périphérique), il est laissé intact.
-- has xx other links: unchanged
Le fichier d'entrée a des liens ; il est laissé inchangé. Voir ln(1) pour plus d'informations. Utilisez l'option -f pour forcer la compression des fichiers à liens multiples.

MISES EN GARDE

Lors de l'écriture de données compressées sur une bande, il est généralement nécessaire de compléter la sortie avec des zéros jusqu'à une limite de bloc. Lorsque les données sont lues et que le bloc entier est passé à gunzip pour décompression, gunzip détecte qu'il y a des déchets supplémentaires après les données compressées et émet un avertissement par défaut. Vous pouvez utiliser l'option --quiet pour supprimer l'avertissement.

BOGUES

Dans de rares cas, l'option --best donne une compression pire que le niveau de compression par défaut (-6). Sur certains fichiers très redondants, compress compresse mieux que gzip.
