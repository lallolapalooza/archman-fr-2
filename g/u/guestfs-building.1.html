NOM

guestfs-building - Comment compiler libguestfs à partir des sources

DESCRIPTION

Cette page de manuel décrit comment compiler libguestfs à partir des sources.

Les étapes principales sont :

  • Installer les prérequis.
  • Compiler, soit depuis le dépôt git, soit depuis une archive tar.
  • Exécuter les tests.
  • Exécuter les outils depuis le répertoire source, ou les installer.

PRÉREQUIS

Raccourci pour les utilisateurs de Fedora ou Red Hat Enterprise Linux (RHEL)

Sur Fedora, utilisez dnf(8) pour installer tous les prérequis :

dnf builddep libguestfs
dnf install autoconf automake libtool gettext-devel

Sur les systèmes utilisant encore yum(8), faites :

yum-builddep libguestfs
yum install autoconf automake libtool gettext-devel

Raccourci pour les utilisateurs de Debian ou Ubuntu

Utilisez APT pour installer tous les prérequis :

apt-get build-dep libguestfs
apt-get install autoconf automake libtool-bin gettext

Si cette commande ne fonctionne pas, jetez un œil au paquet source Debian http://packages.debian.org/source/libguestfs, à la liste des "build-depends" et "build-depends-indep", et installez tout ce qui y est listé.

COMPILATION DEPUIS GIT

Vous devrez installer des dépendances supplémentaires "autoconf", "automake", "gettext", OCaml findlib et po4a lors d'une compilation depuis git.

git clone https://github.com/libguestfs/libguestfs
cd libguestfs
git submodule update --init
autoreconf -i
./configure CFLAGS=-fPIC
make

COMPILATION DEPUIS LES FICHIERS TAR

Les fichiers tar sont téléchargés depuis http://download.libguestfs.org/. Les fichiers tar stables sont signés avec la clé GnuPG pour "rich@annexia.org", voir https://pgp.mit.edu/pks/lookup?op=vindex&search=0x91738F73E1B768A0. L'empreinte est "F777 4FB1 AD07 4A7E 8C87 67EA 9173 8F73 E1B7 68A0".

Téléchargez et décompressez le fichier tar.

cd libguestfs-1.xx.yy
./configure
make

EXÉCUTION DES TESTS

N'EXÉCUTEZ PAS les tests en tant que root ! Libguestfs peut être compilé et testé en tant qu'utilisateur non-root. Exécuter les tests en tant que root pourrait même être dangereux, ne le faites pas.

Pour vérifier rapidement que la compilation a fonctionné, faites :

make quickcheck

Pour exécuter les tests de base, faites :

make check

Il existe de nombreux autres tests que vous pouvez exécuter. Voir guestfs-hacking(1) pour plus de détails.

INSTALLATION

N'UTILISEZ PAS "make install"! Vous vous retrouverez avec des versions conflictuelles de libguestfs installées, et cela cause des maux de tête constants aux utilisateurs. Voir la section suivante pour savoir comment utiliser le ./run script à la place.

Les empaqueteurs de distributions peuvent utiliser :

make INSTALLDIRS=vendor DESTDIR=[temp-build-dir] install

LE SCRIPT ./run

Vous pouvez exécuter guestfish(1), guestmount(1) et les outils virt sans avoir besoin de les installer en utilisant le ./run script dans le répertoire principal. Ce script fonctionne en définissant plusieurs variables d'environnement.

Par exemple :

./run guestfish [arguments habituels de guestfish ...]
./run virt-inspector [arguments habituels de virt-inspector ...]

Le ./run script ajoute chaque binaire libguestfs au $PATH, donc les exemples ci-dessus exécutent guestfish et virt-inspector depuis le répertoire de compilation (et non le guestfish installé globalement s'il y en a un).

Vous pouvez utiliser le script depuis n'importe quel répertoire. Si vous vouliez exécuter votre propre programme utilisant libguestfs, alors la commande suivante fonctionnera aussi :

/chemin/vers/libguestfs/run ./mon_programme [...]

Vous pouvez aussi exécuter les programmes C sous valgrind comme ceci :

./run valgrind [options de valgrind...] virt-cat [options de virt-cat...]

ou sous gdb :

./run gdb --args virt-cat [options de virt-cat...]

Cela fonctionne aussi avec sudo (par ex. si vous avez besoin d'un accès root pour libvirt ou pour accéder à un périphérique bloc) :

sudo ./run virt-cat -d LinuxGuest /etc/passwd

Pour définir des variables d'environnement, vous pouvez soit faire :

LIBGUESTFS_HV=/mon/qemu ./run guestfish

soit :

./run env LIBGUESTFS_HV=/mon/qemu guestfish

local* FICHIERS

Les fichiers dans le répertoire source principal qui commencent par le préfixe local* sont ignorés par git. Ces fichiers peuvent contenir une configuration locale ou des scripts dont vous avez besoin pour compiler libguestfs.

J'ai un fichier appelé localconfigure qui est un simple enveloppeur autour de configure contenant des personnalisations de configure locales dont j'ai besoin. Il ressemble à ceci :

. localenv
./configure.sh \
    -C \
    --enable-werror \
    "$@"

Ainsi je peux l'utiliser pour compiler libguestfs :

./localconfigure && make

S'il y a un fichier dans le répertoire de compilation principal appelé localenv, alors il sera chargé par "make". Ce fichier peut contenir toutes les variables d'environnement locales nécessaires, par ex. pour sauter des tests :

# Sauter ce test, il est cassé.
export SKIP_TEST_BTRFS_FSCK=1

Notez que localenv est inclus par le Makefile principal (c'est donc un fragment de Makefile). Mais s'il est aussi chargé par votre localconfigure script alors il est utilisé comme un script shell.

--disable-ruby
Désactiver des liaisons de langage spécifiques, même si "./configure" trouve toutes les bibliothèques nécessaires installées pour qu'elles puissent être compilées.

Notez que la désactivation d'OCaml (les liaisons) ou de Perl aura comme effet secondaire la désactivation de parties de la suite de tests et de certains outils.

OCaml est requis pour compiler libguestfs et cette exigence ne peut pas être supprimée. Utiliser --disable-ocaml ne désactive que les liaisons.

--disable-fuse
Désactiver la prise en charge de FUSE dans l'API et l'outil guestmount(1) .
--disable-static
Ne pas compiler une version statiquement liée de la bibliothèque libguestfs.
--enable-install-daemon
Normalement guestfsd(8) n'est pas installé par "make install", car cela ne serait pas utile (à la place, il est « installé » à l'intérieur de l'appliance supermin). Cependant, si les empaqueteurs compilent « libguestfs live » alors ils devraient utiliser cette option.
--enable-werror
Cela transforme les avertissements du compilateur en erreurs (c'est-à-dire "-Werror"). Utilisez ceci pour le développement, en particulier lors de la soumission de correctifs. Cela ne devrait généralement pas être utilisé pour la production ou les compilations de distribution.
--with-default-backend=libvirt
Cela contrôle la méthode par défaut que libguestfs utilise pour exécuter qemu (voir « BACKEND » dans guestfs(3)). Si non spécifié, le backend par défaut est "direct" , ce qui signifie que libguestfs exécute qemu directement. Fedora et Red Hat Enterprise Linux (RHEL) ≥ 7 utilisent cette option pour changer le backend par défaut en "libvirt" , car (surtout dans RHEL) la politique est de ne permettre à aucun programme d'exécuter qemu autrement que via libvirt. Notez que malgré ce paramètre, tous les backends sont intégrés dans libguestfs, et vous pouvez remplacer le backend à l'exécution en définissant la variable d'environnement

$LIBGUESTFS_BACKEND (ou en utilisant les méthodes de l'API). --with-distro=REDHAT|DEBIAN|.
