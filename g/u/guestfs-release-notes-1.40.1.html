guestfs-release-notes - Notes de version de libguestfs

NOTES DE VERSION POUR LIBGUESTFS 1.40

Ces notes de version ne couvrent que les différences par rapport à la précédente séparation stable/dev (1.38.0). Pour les journaux de modifications détaillés, veuillez consulter le dépôt git ou le fichier ChangeLog distribué dans l'archive tar.

Nouvelles fonctionnalités

Nouvelles fonctionnalités dans les outils existants

Virt-inspector affiche désormais le court identifiant libosinfo pour les invités (Pino Toscano).

Guestfish -N générera désormais des disques de 1G au lieu de disques de 100M par défaut.

Virt-resize prend en charge les systèmes de fichiers f2fs (Pino Toscano).

libguestfs-test-tool prend désormais en charge la complétion de commandes par tabulation avec bash (Pino Toscano).

L'option --machine-readable prend désormais en charge l'envoi de la sortie vers des fichiers ou stdout/stderr. Cela fonctionne de manière uniforme pour la plupart des outils virt basés sur OCaml, notamment : virt-builder, virt-builder-repository, virt-dib, virt-get-kernel, virt-resize, virt-sparsify et virt-v2v (Pino Toscano).

Virt-builder --uninstall fonctionne désormais sur SUSE (Sebastian Meyer).

Virt-builder prend désormais en charge Windows. Nous ne sommes pas en mesure de fournir des modèles Windows dans le dépôt public pour des raisons de licence évidentes, mais si vous êtes abonné à MSDN, vous pouvez construire les vôtres. Voir https://rwmj.wordpress.com/2018/09/13/creating-windows-templates-for-virt-builder/

De nombreux outils prennent désormais en charge une option --key vous permettant de passer des clés de déchiffrement pour les systèmes de fichiers stockés dans des fichiers locaux sur l'hôte au lieu de devoir les fournir via stdin (Pino Toscano).

virt-v2v et virt-p2v

Nouveau mode -o rhv-upload pour téléverser directement des images vers RHV, en contournant le domaine de stockage d'exportation (Tomáš Golembiovský, Nir Soffer, Daniel Erez, Pino Toscano).

Nouveau mode -o openstack pour téléverser directement des images vers OpenStack et Cinder en utilisant les API OpenStack.

Virt-v2v dispose désormais d'un mécanisme général pour les options d'entrée et de sortie : -io et -oo.

Virt-v2v peut désormais installer les outils RHV ou QEMU GA dans les invités (Tomáš Golembiovský).

Le manuel volumineux a désormais été divisé en plusieurs documents plus petits et se concentre davantage sur l'aide aux utilisateurs pour accomplir des tâches v2v spécifiques.

Améliorations multiples des métadonnées OVF lors de la conversion vers RHV (Tomáš Golembiovský, Pino Toscano, Arik Hadas).

Virt-v2v peut désormais convertir des invités Linux avec des paquets de noyau séparés, en particulier Ubuntu 18.04 (Pino Toscano).

L'ancienne option --password-file de virt-v2v a été remplacée par -ip (l'ancienne option reste pour la compatibilité ascendante).

Virt-v2v préserve désormais le VM Generation ID.

Virt-v2v a une nouvelle option --mac permettant de faire correspondre précisément des cartes réseau spécifiques à des réseaux ou ponts sur la cible.

Nouvelle option virt-v2v --print-estimate pour estimer la taille des données que virt-v2v copiera.

Virt-v2v est désormais généralement capable de supprimer open-vm-tools et VMware Tools de l'invité Linux pendant la conversion (Pino Toscano).

Virt-v2v peut désormais prendre en charge les conversions UEFI vers RHV (Tomáš Golembiovský).

Virt-p2v préfère désormais que vous éteigniez la machine au lieu de la redémarrer après la fin de la conversion (Pino Toscano).

Virt-v2v écrit désormais le court identifiant libosinfo dans les métadonnées libvirt lors de l'utilisation des modes de sortie -o local et -o libvirt (Martin Kletzander).

Liaisons de langage

OpenJDK 10+ est pris en charge (Pino Toscano).

Liaisons Java corrigées pour l'hôte Gentoo (Martin Kletzander).

Inspection

Prise en charge de Kali Linux (Pino Toscano).

Lors de l'inspection des points de montage, recherchez également /etc/mdadm/mdadm.conf ainsi que /etc/mdadm.conf (Nikolay Ivanets).

Amélioration de la prise en charge d'OpenSUSE Tumbleweed (Pino Toscano).

Architectures et plateformes

Corrections diverses de compilation pour macOS (Adam Robinson).

Autres

Corrections de plusieurs fautes de frappe dans la documentation (Yuri Chornoivan).

Sécurité

Voir aussi guestfs-security(1).

CVE-2018-11806

Le slirp de Qemu (réseau en espace utilisateur) présentait plusieurs débordements de tampon qui pouvaient être déclenchés depuis l'invité ou le côté réseau.

API

Nouvelles API

"f2fs_expand"
Étend un système de fichiers f2fs (Pino Toscano).
"inspect_get_osinfo"
Obtient le court identifiant libosinfo pour l'invité inspecté (Pino Toscano).
"lvm_scan"
Rescanne tous les PV, VG et LV, en les activant éventuellement.

Autres changements d'API

"part_get_mbr_part_type" a été réimplémenté en OCaml (Nikolay Ivanets).

"list_filesystems" filtre désormais les partitions étendues MBR (Nikolay Ivanets).

"vgscan" a été déprécié. Utilisez de préférence la nouvelle API "lvm_scan" .

Changements de compilation

La bibliothèque JSON est passée de yajl à Jansson ≥ 2.7 (Pino Toscano).

Prise en charge de The Sleuth Kit 4.5 (Pino Toscano).

Améliorations multiples dans le script "./configure" (Lin Ma).

Plus de corrections pour les compilations hors arbre (Hilko Bengen).

Travail sur les compilations reproductibles (Bernhard M. Wiedemann).

Internes

lvmetad est désormais utilisé inconditionnellement et est démarré beaucoup plus tôt dans le processus d'amorçage de l'appareil. Cela corrige la prise en charge de certains types de PV.

Sur Debian, dash est installé à l'intérieur de l'appareil et dans virt-rescue (Pino Toscano).

La quantité de RAM attribuée à l'appareil a été augmentée de 500M à 768M (sur x86_64, les autres architectures ont des limites différentes). Cela permet l'utilisation de jusqu'à 255 disques avec les noyaux Linux récents.

Virt-v2v modélise désormais le type de machine source (par ex. i440FX, Q35 ou virt).

Virt-p2v génère désormais automatiquement du code de configuration, y compris du code pour analyser la ligne de commande du noyau.

Utilisez "LT_INIT" au lieu de "AC_PROG_LIBTOOL".

Le code "JSON" OCaml pour l'analyse et la sérialisation a été unifié en un seul type de données abstrait.

La plupart des outils OCaml sont désormais compilés avec le runtime PIC. Cela a un impact sur les performances sur i686, mais est relativement gratuit sur les autres architectures et présente des avantages en matière de sécurité.

Le backend direct interroge désormais le binaire qemu pour la disponibilité de KVM, au lieu d'utiliser une heuristique basée sur /dev/kvm (Andrea Bolognani).

Nos macros d'écriture libxml2 « intelligentes » sont désormais utilisées de manière cohérente dans toutes les parties de la base de code.

Qemu a supprimé -nodefconfig sans nous le dire. L'option équivalente -no-user-config est désormais utilisée à la place. Qemu a également déplacé l'option "serial" de -drive vers -device, là encore sans aucun avertissement, et cela est également corrigé.
