NOTES DE VERSION DE LIBGUESTFS 1.

22

Ces notes de version ne couvrent que les différences par rapport à la précédente séparation stable/dev (1.20.0). Pour les journaux de modifications détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive

tarball.

Les chargeurs de démarrage SYSLINUX et EXTLINUX peuvent désormais être installés dans des images de disque à l'aide de

l'API.

L'inspection peut désormais gérer des systèmes de fichiers tels que btrfs où les sous-volumes peuvent être montés séparément (Matthew Booth)

.

Les « attach methods » sont désormais connus sous le nom de « backends ». La compatibilité avec le code existant est

préservée.

Les noms de fichiers peuvent contenir ':', à condition d'utiliser une version plus récente de

QEMU.

Outil

s

Virt-alignment-scan et virt-df analysent plusieurs invités en

parallèle.

Guestmount transmet désormais errno de manière précise à l'espace utilisateur dans presque tous les

cas.

Guestfish et d'autres outils peuvent désormais utiliser une syntaxe semblable à une URI pour accéder aux disques distants, par exemple

: 
guestfish -a ssh://example.com/path/to/disk.
img

Guestfish et guestmount vous permettent désormais de spécifier le type de système de fichiers lors du montage, ce qui est plus sûr (Dave Vasilevsky)

.

Guestfish est désormais le « guest filesystem shell »

.

Guestfish n'accepte que 1 "true" "t" "yes" "y" "on" 0 "false" "f" "no" "n" "off" pour les valeurs booléennes (insensible à la casse), et renvoie une erreur pour toutes les autres

chaînes.

Nouvel outil "guestunmount" pour démonter les systèmes de fichiers FUSE en toute

sécurité.

L'option "guestmount --no-fork" empêche guestmount de se transformer en

démon.

Virt-resize utilise désormais des copies creuses par défaut, économisant un espace considérable pour les invités principalement

vides.

L'achèvement par tabulation de Bash a été réécrit et peut désormais gérer la plupart des outils, et compléter correctement par tabulation les options "--long". De plus, les scripts d'achèvement de bash sont chargés à la

demande.

langage

L'API Java prend désormais en charge les

événements.

L'objet Python hérite désormais de la classe de base

"object".

Les méthodes Python qui renvoyaient auparavant des listes de tuples peuvent désormais renvoyer un dict Python. Pour la compatibilité ascendante, vous devez activer cela en utilisant l'option de constructeur "guestfs.GuestFS (python_retu

rn_dict=True)".

Les liaisons PHP sont désormais correctement testées et ont reçu de multiples

corrections.

La bibliothèque Perl "Sys::Guestfs::Lib", obsolète depuis longtemps, a été supprimée. https://www.redhat.com/archives/libguestfs/2013-April/msg00001.

Interne

s

L'outil febootstrap a désormais été renommé "supermin". Libguestfs peut utiliser l'un ou l'autre, mais préfère désormais "supermin". http://people.redhat.com/~rjones/supermin

/

libxml2 est requis pour compiler

libguestfs.

Le programme hivexregedit (de hivex) est requis pour compiler à partir de

git.

Les fonctions internes ne peuvent plus être utilisées à moins que l'appelant ne définisse "-DGUESTFS_PRIVATE=1"

.

Activer les avertissements du compilateur C dans les liaisons Python et

Ruby.

Échouer tôt et clairement si libvirt ne prend pas en charge qemu/KVM (par ex. si la connexion libvirt par défaut est vers Xen)

.

Règle "make print-subdirs", utile pour exécuter sélectivement des

tests.

Corrections multiples pour permettre des compilations séparées (sourcedir != builddir)

.

Corrections multiples pour les liaisons

Haskell.

Les API "ln" et "ln-f" capturent désormais "errno" correc

tement.

Les tests de liaison de langage utilisent (pour la plupart) un schéma de numérotation standard et visent à tester la même gamme de fonctionnalités dans chaque langage. De plus, le nombre de lancements requis a été réduit, ces tests devraient donc s'exécuter beaucoup plus

rapidement.

Le code de la bibliothèque utilise en interne GCC "__attribute__((cleanup))" (si disponible) pour simplifier l'allocation de

mémoire.

Les fichiers d'en-tête internes ont été réorganisés. Voir les commentaires dans src/guestfs-internal*.

h

Le code interne partagé entre la bibliothèque et certains outils se trouve désormais dans une bibliothèque statique "libutils"

.

Presque tous les sous-répertoires peuvent désormais utiliser des compilations parallèles, bien que les répertoires de premier niveau se compilent toujours en

série.

L'utilisation de "PATH_MAX" et "NAME_MAX" a été éliminée du

code.

L'API Java requiert désormais une JVM ≥ 1.

6.

Forcer l'utilisation de "serial-tests" avec automake ≥ 1.

12.

L'utilisation des sockets dans la couche de protocole de la bibliothèque est abstraite, permettant d'ajouter d'autres couches non-POSIX à l'avenir (voir src/conn-socket.c)

.

"qemu-img info --output json" est utilisé si disponible, pour un analyse plus sécurisée de la sortie de cette

commande.

Les distributions peuvent désormais utiliser "make INSTALLDIRS=vendor install" pour placer les liaisons Ruby dans vendordir. Cela élimine un patch non amont porté à la fois par Fedora et

Debian.

Les fichiers de journal Valgrind sont désormais écrits dans tmp/valgrind-DATE-PID.

log

"make clean" nettoie le répertoire local "tmp/"

.

Les tests de l'API C ont été réécrits à l'aide d'un

langage de génération plus flexible permettant
d'exécuter du code C arbitraire pendant les tests.
