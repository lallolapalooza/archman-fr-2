Calculer la somme de contrôle d'un fichier ou d'un périphérique dans une image de

disque

Pour calculer la somme de contrôle d'un périphérique entier, d'une partition, d'un LV, etc. dans une image de disque 

: 
guestfish --ro -a disk.img run : checksum-device md5
/dev/sda1

Remplacez « md5 » par le type de somme de contrôle que vous voulez. Voir « guestfs_checksum_device » dans guestfs(3) pour une liste des types pris en

charge.

/dev/sda1 signifie « la première partition ». Vous pouvez utiliser /dev/sda pour calculer la somme de contrôle de l'image de disque entière, ou le nom d'un volume logique ou d'un périphérique

RAID.

Pour calculer la somme de contrôle d'un seul fichier 

: 
guestfish --ro -a disk.img -i checksum sha256
/etc/passwd

ou pour un invité Windows 

: 
guestfish --ro -a disk.img -i \
  checksum sha256 'win:\windows\system32\config\SOFTWAR

Convertir d'un format/système de fichiers à un

autre

Si vous avez un disque de données dans un format / système de fichiers / partition / gestionnaire de volumes, vous pouvez le convertir en un autre en utilisant cette

technique.

Dans cet exemple, nous partons d'un disque de données qui a une seule partition contenant un système de fichiers, et nous voulons créer un autre disque qui contient les mêmes fichiers mais sur un système de fichiers ext3 intégré dans un volume logique sur un disque raw

sparse.

D'abord, créer le disque cible formaté mais vide 

: 
truncate -s 10G target.img
virt-format -a target.img --partition=mbr --lvm --filesystem=ext
3

Maintenant, connectez deux instances de guestfish ensemble pour transférer les anciennes données vers le nouveau disque 

: 
guestfish --ro -a source.img -m /dev/sda1  -- tar-out / - | \
guestfish --rw -a target.img -m /dev/VG/LV -- tar-in -
/

Pour parcourir l'image de disque finale, faire 

: 
guestfish --ro -a target.img -m /dev/VG/LV
><fs> ll
/

Cette technique est assez puissante, vous permettant par exemple de répartir les répertoires sources sur les systèmes de fichiers

cibles.

Notez que cela ne fonctionnera pas (au moins, pas direc

tement) pour les disques de machines virtuelles bo
otables car cela ne copie pas le chargeur de démarrage.

Convertir une image sans partition de style Xen en image de disque

partitionnée

Les images de disque Xen sont souvent sans partition, ce qui signifie que le système de fichiers commence directement au début du disque sans table de partition. Vous pouvez en fait les utiliser directement dans KVM (à condition que l'invité ne soit pas Windows), mais certaines personnes aiment les convertir en images de disque partitionnées régulières, et cela est requis pour les invités Windows. Voici comment utiliser guestfish pour faire cela 

: 
guestfish
><fs> add-ro input.img
><fs> sparse output.img 10G     # ajuster la taille de sortie
><fs> run
# Créer une table de partition sur le disque de sortie :
><fs> part-init /dev/sdb mbr
><fs> part-add /dev/sdb p 2048 -2048
# Copier les données vers la partition cible :
><fs> copy-device-to-device /dev/sda /dev/sdb1 sparse:true
# Redimensionner optionnellement le système de fichiers cible. Utiliser ntfsresize
# pour les invités Windows :
><fs> resize2fs
/dev/sdb1

Une telle image de disque ne sera pas directement bootable. Vous devrez peut-être la démarrer avec un noyau et un initramfs externes (voir ci-dessous). Ou vous pouvez utiliser les commandes guestfish « syslinux » ou « extlinux » pour installer un ch

argeur de démarra
ge SYSLINUX.

Lettres de lecteur via

FUSE

Vous avez un invité Windows et vous souhaitez exposer les lettres de lecteur en tant que points de montage FUSE (/C/..., /D/... etc). Au lieu de guestmount(1), utilisez ce script Perl

: 
#!/usr/bin/perl -w
use strict;
use Sys::Guestfs;
$| = 1;
die "usage: $0 mountpoint disk.img" if @ARGV < 2;
my $mp = shift @ARGV;
my $g = new Sys::Guestfs;
$g->add_drive_opts ($_) foreach @ARGV;
$g->launch;
my @roots = $g->inspect_os;
die "$0: no operating system found" if @roots != 1;
my $root = $roots[0];
die "$0: not Windows" if $g->inspect_get_type ($root) ne "windows";
my %map = $g->inspect_get_drive_mappings ($root);
foreach (keys %map) {
    $g->mkmountpoint ("/$_");
    eval { $g->mount ($map{$_}, "/$_") };
    warn "$@ (ignored)\n" if $@;
}
$g->mount_local ($mp);
print "filesystem ready on $mp\n";
$g->mount_local_run;
$g->
shutdown;

Exporter un noyau externe et un initramfs

Installation du chargeur de démarrage SYSLINUX dans un

invité

SYSLINUX est un petit chargeur de démarrage facile à configurer pour les invités Linux et Windows. Si votre invité n'est pas amorçable, vous pouvez installer le chargeur de démarrage SYSLINUX en utilisant les commandes guestfish "syslinux" (pour les invités basés sur FAT) ou "extlinux" (pour les invités basés sur ext2/3/4 et btrfs)

.

Ce guide suppose un invité Linux où /dev/sda1 est /boot, /boot/vmlinuz est le noyau de l'invité, et /dev/sda3 est la partition racine. Pour un invité Windows, vous auriez besoin d'une partition de démarrage formatée en FAT et vous devriez utiliser la commande "syslinux" à la

place.

Créez un fichier de configuration syslinux.cfg. Vous devriez consulter la documentation de SYSLINUX à l'adresse http://www.syslinux.org mais cela pourrait ressembler à quelque chose comme ceci

: 
DEFAULT linux
LABEL linux
  SAY Booting the kernel
  KERNEL vmlinuz
  INITRD initrd
  APPEND ro
root=/dev/sda3

Localisez le master boot record de syslinux (un fichier nommé quelque chose comme /usr/share/syslinux/mbr.bin)

. 
guestfish -a disk.img -i
# Upload the master boot record and configuration file:
><fs> upload ..../mbr.bin /boot/mbr.bin
><fs> upload ..../syslinux.cfg /boot/syslinux.cfg
# Put the MBR into the boot sector:
><fs> copy-file-to-device /boot/mbr.bin /dev/sda size:440
# Install syslinux on the first partition:
><fs> extlinux /boot
# Set the first partition as bootable:
><fs> part-set-bootable /dev/sda 1
true

Voir aussi : http://rwmj.wordpress.com/2013/04/04/new-in-libguestfs-use-syslinux-or-extlinux-to-make-bootable-guests/#conte

Téléversement de contenu de système de fichiers

brut s="Pp">Vous pouvez utiliser guestfish(1) pour téléverser des systèmes de fichiers entiers dans une VM, même dans un système de fichiers chiffré ou caché à l'intérieur d'un périphérique LV ou RAID

: 
guestfish --rw -a disk.img run : upload sda1.img /dev/sda1
guestfish --rw -d Guest run : upload lv.img /dev/vg_guest/lv_roo
t

Un problème courant est que le système de fichiers n'a pas la bonne taille pour la cible. S'il est trop grand, vous ne pouvez pas faire grand-chose avec libguestfs - vous devez préparer le système de fichiers différemment. Mais si le système de fichiers doit s'étendre vers la cible, vous pouvez utiliser guestfish pour le redimensionner à la bonne taille

: 
guestfish --rw -d Guest run : \
  upload lv.img /dev/vg_guest/lv_root : \
  resize2fs /dev/vg_guest/lv_roo
t

(ou utilisez "ntfsresize" si le sys

tème de fichie
rs est NTFS).
