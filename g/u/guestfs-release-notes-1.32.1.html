NOTES DE VERSION POUR LIBGUESTFS 1.

32

Ces notes de version ne couvrent que les différences par rapport à la précédente séparation des branches stable/dev (1.30.0). Pour les journaux de modifications détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive

tar.

Nouvelles

fonctionnalités

Nouveaux

outils

Le nouvel outil virt-v2v-copy-to-local(1) est un outil auxiliaire pour virt-v2v(1) vous permettant de convertir des invités sources auxquels virt-v2v ne peut pas accéder

directement.

Nouvelles fonctionnalités dans les outils

existants

Virt-customize sait écrire une graine aléatoire dans CirrOS (Pino Toscano)

.

Sur Fedora, virt-customize exécute dnf(8) avec l'indicateur --best, garantissant qu'il met toujours à jour vers les paquets les plus récents

disponibles.

Virt-builder fournit désormais des modèles Fedora 32

bits.

L'option --install de virt-builder et virt-customize fonctionne désormais sur les invités Fedora 32 bits. Auparavant, il essayait d'installer des paquets 64 bits (Jan Sedlák)

.

Virt-builder peut désormais récupérer des images cloud en utilisant les métadonnées Simple Streams v1.0 (Pino Toscano)

.

Virt-builder peut désormais récupérer des images cloud openSUSE directement (Cédric Bosdonnat)

.

Virt-customize utilisera désormais par défaut des mots de passe chiffrés plus forts (SHA-512) sur openSUSE ≥ 11 (Pino Toscano)

.

Virt-builder gérera désormais correctement les noms de fichiers de sortie contenant des deux-points (":"), et créera des fichiers temporaires dans le répertoire de cache de libguestfs au lieu d'utiliser par défaut /tmp (Pino Toscano)

.

Virt-resize a une nouvelle option --unknown-filesystems pour contrôler quoi faire lorsqu'on lui demande de redimensionner un système de fichiers que libguestfs ne sait pas

redimensionner.

Virt-v2v a désormais un indicateur/mode --in-place, permettant la conversion sur place des invités (Roman Kagan)

.

Virt-v2v a une option --compressed pour créer des fichiers de sortie qcow2

compressés.

Virt-v2v peut désormais obtenir correctement le chemin du centre de données VMware (dcPath) depuis libvirt, au lieu de devoir le calculer en utilisant un algorithme qui obtenait parfois la mauvaise réponse (Matthias Bolte, Tingting Zheng)

.

Virt-v2v traite désormais correctement les tailles de RAM pour les invités 64 bits lorsqu'il s'exécute sur un hôte 32

bits.

Liaisons de

langage

Dans les programmes Perl et Python, l'API "get_program_name" renvoie désormais le vrai nom du programme, au lieu de la chaîne incorrecte "perl" ou "python"

.

Les liaisons Python peuvent désormais être compilées contre une version différente de libguestfs, permettant au module pip d'être construit contre n'importe quelle version de libguestfs (au lieu d'exiger que le module pip et libguestfs aient exactement la même version)

.

La qualité de la rdoc Ruby (documentation) a été améliorée (Pino Toscano)

.

Les scripts Perl ne codent plus en dur l'emplacement de perl dans la ligne shebang, mais utilisent env(1) pour le localiser à la place (Pino Toscano)

.

Dans les programmes OCaml, le handle guestfs était incorrectement transformé en racine globale, signifiant qu'il ne pouvait jamais être collecté par le ramasse-miettes. Si vous n'appeliez pas explicitement la fonction "close", le handle n'était pas fermé jusqu'à ce que tout le programme se termine. Cela a désormais été corrigé afin que les handles soient collectés par le ramasse-miettes de la manière habituelle. Cela change l'API de la fonction OCaml "Guestfs.event_callback". Notez que les liaisons de langage non C ne sont pas couvertes par la garantie API/ABI de libguestfs, bien que nous essayions de ne pas les changer, mais dans ce cas c'était essentiel afin de corriger ce bogue très

sérieux.

n

Alpine Linux et le gestionnaire de paquets APK, ALT Linux, Frugalware, et PLD Linux sont désormais reconnus (Pino Toscano)

.

S'il existe, /etc/os-release sera préféré pour inspecter les invités Linux (Pino Toscano)

.

La version correcte du noyau est renvoyée pour les invités Windows ≥

10.

New features

The "--enable-valgrind-daemon" option has been removed.

You can no longer build libguestfs on RHEL 5-era (c.2007) machines. See the "oldlinux" branch if you need (limited) RHEL 5 support.

Virt-p2v can now be built on RHEL 6-era (c.2010) Linux distros.

OCaml ≥ 3.11 (released in 2008) is now required to build from git.

Building the Perl bindings now requires "Module::Build" (instead of "ExtUtils::MakeMaker").

Builds should be faster (especially when incrementally rebuilding), because work was done to reduce build times.

Both OCaml and the OCaml findlib module are required if you need to run the generator at build time. Previously the build would have failed if findlib was not installed.

"make check" tests now run in parallel (within each test directory).

"make install" no longer installs OCaml bindtests.* files incorrectly.

"make install" can now be run twice. Previously it would fail on the second run.

"make clean" should now remove nearly every file that "make" creates.

A new "make installcheck" rule has been added, allowing the installed copy of libguestfs to be tested.

Internals

Some effort was put into minimizing the size of the appliance, which reduces temporary disk space and time needed by libguestfs handles.

The appliance now passes the NIC name to dhcpd, fixing hangs when running the appliance on some distros (Cédric Bosdonnat).

OCaml "Guestfs.Errno" is now generated (Pino Toscano).

In OCaml tools, common code now handles --debug-gc, --verbose and other common options (Roman Kagan, Pino Toscano).

The virt-v2v test harness allows us to boot the test guests at fixed dates in the past, ensuring that Windows reactivation doesn't kick in.

There is a new internal API for reading/writing a subprocess via a pipe from library code.

Used "deheader" program to remove unused "#include" directives.

In OCaml tools, the "Char" and "String" modules now implicitly reference the "Common_utils.Char" and "Common_utils.String" modules (instead of the ones from stdlib). The "Common_utils" modules contain a number of extra char/string utility functions, and also hide some unsafe functions in stdlib.

Many more virt-v2v tests will now be run even if you don't have rhsrvany and virtio-win installed (Roman Kagan).

The huge configure.ac file has been split into several smaller files called m4/guestfs_*.m4.

The old tests/data and tests/guests directories have been moved to test-data/. This new top level directory carries all test data which is common, large and/or shared between multiple tests.

There is a new top level website/ directory containing the public http://libguestfs.org website (or most of it).

The fuzz testing of inspection (tests/fuzz) has been removed.

Virt-p2v now saves the source physical machine dmesg output into the conversion server debug directory, making it simpler to debug cases of missing drivers, firmware etc.
