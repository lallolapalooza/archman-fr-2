guestfs-testing(1) Support de la virtualisation guestfs-testing(1)

NOM

guestfs-testing - tests manuels de libguestfs, vous pouvez aider !

DESCRIPTION

Cette page contient des tests manuels que vous pouvez essayer sur libguestfs. Chacun a une combinaison légèrement différente de plateforme, de matériel et d'invités, ce qui rend ce test très utile. Merci de votre aide !

Les tests marqués d'un * (astérisque) peuvent détruire des données si vous n'êtes pas prudent. Les autres sont sûrs et ne modifieront rien.

Ces tests nécessitent libguestfs ≥ 1.22.

Vous pouvez signaler les bogues que vous trouvez via ce lien :

https://bugzilla.redhat.com/enter_bug.cgi?component=libguestfs&product=Virtualization+Tools

ou publier sur la liste de diffusion (l'inscription n'est pas pas requise, mais si vous n'êtes pas inscrit, vous devrez attendre qu'un modérateur approuve manuellement votre message) :

https://lists.libguestfs.org

TESTS

Exécutez libguestfs-test-tool

Exécutez :

libguestfs-test-tool

Cette commande effectue un test très simple et non destructif pour vérifier que libguestfs fonctionne de base. Vous n'avez pas besoin de l'exécuter en tant que root.

S'il ne n'affiche pas "===== TEST FINISHED OK =====", signalez-le comme un bogue. Il est très important que vous incluiez la sortie complète et non modifiée de "libguestfs-test-tool" dans votre rapport de bogue. Voir la section « BUGS » à la fin de cette page.

Vérifiez que l'accélération KVM est utilisée.

Si votre hôte dispose d'une accélération de virtualisation matérielle, alors avec un cache chaud, libguestfs devrait pouvoir démarrer en quelques secondes. Exécutez la commande suivante plusieurs fois :

time guestfish -a /dev/null run

Après quelques exécutions, le temps devrait se stabiliser à quelques secondes (moins de 3 secondes sur du matériel 64 bits rapide).

Si la commande ci-dessus ne fonctionne pas du tout, utilisez libguestfs-test-tool(1).

Vérifiez quelle version de libguestfs, qemu, libvirt, etc. est utilisée.

Regardez la sortie de "libguestfs-test-tool" et vérifiez :

  • Quelle version de libguestfs est utilisée ? Près du début de la sortie, vous verrez une ligne comme : 
    library version: 1.22.0fedora=19,release=1.fc19,libvirt
  • libvirt est-il utilisé ? Vous pouvez le savoir en cherchant le backend : 
    guestfs_get_backend: direct

    ou :

    guestfs_get_backend: libvirt
  • Quelle version de qemu est utilisée ? Elle peut être affichée : 
    libguestfs: qemu version 1.5
  • Quel noyau est utilisé ? supermin(1) essaiera de choisir le dernier noyau installé sur votre machine. Vous pouvez voir la version dans la sortie de l'appliance, par exemple : 
    [    0.000000] Linux version 3.9.2-200.fc18.x86_64 [...]

Essayez d'ouvrir une image d'invité locale avec guestfish.

Vous pouvez utiliser n'importe quelle image de disque d'invité pour ce test. Assurez-vous d'utiliser l'option "--ro" afin que guestfish(1) ouvre l'image de disque en lecture seule.

guestfish --ro -a /path/to/disk.img -i

Si la commande réussit, elle devrait afficher le nom du système d'exploitation de l'invité et vous placer à l'invite "><fs>" de guestfish. Vous pouvez utiliser des commandes guestfish comme "ll /" pour regarder à l'intérieur de l'image de disque. Pour quitter, tapez "exit".

Si vous obtenez une erreur, essayez d'activer le débogage (ajoutez "-v" à la ligne de commande). Assurez-vous également que libguestfs-test-tool(1) réussit.

Essayez d'ouvrir une image d'invité distante avec guestfish.

Vous devrez peut-être aussi désactiver libvirt en définissant ceci :

export LIBGUESTFS_BACKEND=direct

Si vous avez une image de disque disponible via HTTP/FTP, essayez de l'ouvrir.

guestfish --ro -i --format=raw -a http://www.example.com/disk.img

Pour SSH, vous devrez vous assurer que ssh-agent est configuré afin que vous n'ayez pas besoin de mot de passe pour vous connecter à la machine distante. Ensuite, une commande similaire à celle-ci devrait fonctionner :

guestfish --ro -i --format=raw \
  -a ssh://remote.example.com/path/to/disk.img

Si vous obtenez une erreur, essayez d'activer le débogage (ajoutez "-v" à la ligne de commande). Assurez-vous également que libguestfs-test-tool(1) réussit.

Exécutez virt-alignment-scan sur tous vos invités.

Exécutez virt-alignment-scan(1) sur des invités ou des images de disque :

virt-alignment-scan -a /path/to/disk.img

ou :

virt-alignment-scan -d Guest

Le rapport d'alignement correspond-il à la façon dont les partitions de l'invité sont alignées ?

Exécutez virt-cat sur des fichiers dans les invités.

virt-cat(1) peut afficher des fichiers depuis des invités. Pour un invité Linux, essayez :

virt-cat LinuxGuest /etc/passwd

Une fonctionnalité récente est la prise en charge des chemins Windows, par exemple :

virt-cat WindowsGuest 'c:\windows\win.ini'

Un test encore meilleur est si vous avez un invité Windows avec plusieurs lecteurs. Les chemins "D:", "E:" etc. fonctionnent-ils correctement ?

* Copiez quelques fichiers dans un invité éteint .

virt-copy-in(1) peut copier récursivement des fichiers et des répertoires dans un invité ou une image de disque.

virt-copy-in -d Guest /etc /tmp

Cela devrait copier le répertoire local /etc vers /tmp/etc dans l'invité (récursivement). Si vous démarrez l'invité, pouvez-vous voir tous les fichiers et répertoires copiés ?

Éteignez l'invité et essayez de copier plusieurs fichiers et répertoires :

virt-copy-in -d Guest /home /etc/issue /tmp

Copiez quelques fichiers depuis un invité.

virt-copy-out(1) peut copier récursivement des fichiers et des répertoires depuis un invité ou une image de disque.

virt-copy-out -d Guest /home .

Remarquez que l'espace et le point finaux dans la commande ne sont pas une faute de frappe.

Cela devrait copier /home depuis l'invité vers le répertoire courant.

Exécutez virt-df.

virt-df(1) liste l'espace disque. Exécutez :

virt-df

Vous pouvez essayer de comparer cela aux résultats de df(1) à l'intérieur de l'invité, mais il y a quelques réserves :

  • L'invité doit être inactif.
  • Les disques de l'invité doivent être synchronisés en utilisant sync(1).
  • Toute action comme le démarrage de l'invité écrira des fichiers journaux, ce qui fera changer les chiffres.

Nous ne garantissons pas que les chiffres seront identiques même dans ces circonstances. Ils devraient être similaires. Cela indiquerait un bogue si vous voyez des chiffres très différents.

Essayez d'importer la sortie CSV de virt-df dans un tableur ou une base de données.

Exécutez :

virt-df --csv > /tmp/report.csv

Essayez maintenant de charger cela dans votre tableur ou base de données préférée. Les résultats sont-ils fidèlement reproduits dans le tableur/la base de données ?

http://www.postgresql.org/docs/8.1/static/sql-copy.html http://dev.mysql.com/doc/refman/5.1/en/load-data.html

* Modifier un fichier dans un invité arrêté.

virt-edit(1) peut modifier des fichiers dans les invités. Essayez cette commande sur un invité RHEL ou Fedora :

virt-edit LinuxGuest /etc/sysconfig/network

Sur d'autres invités Linux, essayez de modifier d'autres fichiers tels que :

virt-edit LinuxGuest /etc/motd

Les modifications sont-elles visibles dans l'invité lorsqu'il est démarré ?

Afficher les systèmes de fichiers / partitions / LV dans un invité.

virt-filesystems(1) peut être utilisé pour afficher les systèmes de fichiers dans un invité. Essayez cette commande sur n'importe quelle image de disque ou invité :

virt-filesystems -a /path/to/disk.img --all --long -h

ou :

virt-filesystems -d Guest --all --long -h

Les résultats correspondent-ils à ce qui est vu dans l'invité ?

Exécutez virt-inspector sur tous vos invités.

Utilisez virt-inspector(1) pour obtenir un rapport sur tous vos invités ou images de disque :

virt-inspector -a /path/to/disk.img | less

ou :

virt-inspector -d Guest | less

Les résultats correspondent-ils à ce qui se trouve réellement dans l'invité ?

Si vous avez un invité inhabituel (une distribution Linux rare, une version très récente de Windows), virt-inspector le reconnaît-il ? Si non, c'est probablement un bogue.

Essayez les fonctionnalités d'audit de virt-ls sur tous vos invités.

Listez tous les programmes setuid ou setgid dans une machine virtuelle Linux :

virt-ls -lR -d Guest / | grep '^- [42]'

Listez tous les répertoires accessibles en écriture publique dans une machine virtuelle Linux :

virt-ls -lR -d Guest / | grep '^d ...7'

Listez tous les sockets de domaine Unix dans une machine virtuelle Linux :

virt-ls -lR -d Guest / | grep '^s'

Listez tous les fichiers réguliers dont les noms se terminent par « .png » :

virt-ls -lR -d Guest / | grep -i '^-.*\.png$'

Affichez les fichiers de plus de 10 Mo dans les répertoires personnels :

virt-ls -lR -d Guest /home | awk '$3 > 10*1024*1024'

Trouvez tout ce qui a été modifié au cours des 7 derniers jours :

virt-ls -lR -d Guest --time-days / | awk '$6 <= 7'

Trouvez les fichiers réguliers modifiés au cours des 24 dernières heures :

virt-ls -lR -d Guest --time-days / | grep '^-' | awk '$6 < 1'

Les résultats correspondent-ils à ce qui se trouve dans l'invité ?

Créer une image de disque à partir d'une archive tar.

Utilisez virt-make-fs(1) pour créer une image de disque à partir de n'importe quelle archive tar que vous avez sous la main :

virt-make-fs --partition=mbr --type=vfat /any/tarball.tar.gz output.img

Ajoutez « output.img » comme disque brut à un invité existant. Vérifiez que l'invité peut voir les fichiers. Ce test est particulièrement utile si vous l'essayez avec un invité Windows.

Essayez d'autres schémas de partitionnement, par ex. --partition=gpt.

Essayez d'autres formats de système de fichiers, par ex. --type=ntfs, --type=ext2.

* Exécutez virt-rescue sur une image de disque ou un invité arrêté.

Utilisez virt-rescue(1) pour examiner, sauvegarder ou réparer un invité arrêté ou une image de disque :

virt-rescue -a /path/to/disk.img

ou :

virt-rescue -d Guest

Pouvez-vous utiliser des commandes shell ordinaires pour examiner l'invité ?

* Redimensionnez vos invités.

Utilisez virt-resize(1) pour donner à un invité un peu plus d'espace disque. Par exemple, si vous avez une image de disque de moins de 30 Go, augmentez-la à 30 Go en faisant :

truncate -s 30G newdisk.img
virt-filesystems -a /path/to/olddisk.img --all --long -h
virt-resize /path/to/olddisk.img newdisk.img --expand /dev/sda1
qemu-kvm -m 1024 -hda newdisk.img

L'invité démarre-t-il toujours ? Essayez d'étendre d'autres partitions.

* Rendez le disque d'un invité clairsemé (sparse).

En utilisant virt-sparsify(1), rendez une image de disque plus clairsemée :

virt-sparsify /path/to/olddisk.img newdisk.img

Le fichier newdisk.img est-il toujours amorçable après avoir été rendu clairsemé ? L'image de disque résultante est-elle plus petite (utilisez "du" pour vérifier) ?

Construisez et démarrez un invité

En utilisant virt-builder(1), choisissez un invité dans la liste :

virt-builder -l

construisez-le :

virt-builder -o disk.img [os-version from list above]

et démarrez-le :

qemu-kvm -cpu host -m 2048 -drive file=disk.img,format=raw

Démarre-t-il ?

* Effectuez un « Sysprep » sur un invité Linux arrêté.

Notez que cela va vraiment désorganiser un invité existant, il est donc préférable de cloner l'invité avant d'essayer cela.

virt-sysprep --hostname newhost.example.com -a /path/to/disk.img

Le sysprep a-t-il réussi ? Après le démarrage, quelles modifications ont été apportées et ont-elles été réussies ?

Exportez le Registre Windows depuis vos invités Windows.

Utilisez virt-win-reg(1) pour exporter le Registre Windows depuis tous les invités Windows que vous avez.

virt-win-reg --unsafe-printable-strings WindowsGuest 'HKLM\Software' |
  less
virt-win-reg --unsafe-printable-strings WindowsGuest 'HKLM\System' |
  less

La sortie correspond-elle à l'exécution de "regedit" dans l'invité ?

Une fonctionnalité récente permet d'exporter les registres utilisateur, essayez donc cela, en remplaçant username par le nom d'un utilisateur local dans l'invité :

virt-win-reg --unsafe-printable-strings WindowsGuest 'HKEY_USERS\username' |
  less
