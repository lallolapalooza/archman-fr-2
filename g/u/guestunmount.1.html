NOM

guestunmount - Démonter un système de fichiers monté par guestmount

SYNOPSIS

guestunmount point_de_montage
guestunmount --fd=<FD> point_de_montage

DESCRIPTION

guestunmount est un utilitaire pour nettoyer automatiquement les systèmes de fichiers montés. guestmount(1) monte les systèmes de fichiers en utilisant libguestfs. Ce programme démonte le système de fichiers lorsqu'un programme ou un script a fini de l'utiliser.

guestunmount est un wrapper autour du programme FUSE fusermount(1), qui doit exister dans le "PATH" courant.

Il existe deux façons d'utiliser guestunmount. Lorsqu'il est appelé comme ceci :

guestunmount point_de_montage

il démonte immédiatement "point_de_montage".

Lorsqu'il est appelé comme ceci :

guestunmount --fd=FD point_de_montage

il attend que le pipe "FD" soit fermé. Ceci peut être utilisé pour surveiller un autre processus et nettoyer son point de montage lorsque ce processus se termine, comme décrit ci-dessous.

DEPUIS DES PROGRAMMES

Vous pouvez simplement appeler "guestunmount point_de_montage" depuis le programme, mais une façon plus sophistiquée d'utiliser guestunmount est de lui faire surveiller votre programme afin qu'il puisse nettoyer le point de montage si votre programme se termine de manière inattendue.

Dans le programme, créez un pipe (par exemple, en appelant pipe(2)). Soit "FD" le numéro du descripteur de fichier du côté lecture du pipe (c'est-à-dire "pipefd[0]").

Après avoir monté le système de fichiers avec guestmount(1) (sur "point_de_montage"), effectuez un fork et lancez guestunmount comme ceci :

guestunmount --fd=FD point_de_montage

Fermez le côté lecture du pipe dans le processus parent.

Maintenant, lorsque le côté écriture du pipe (c'est-à-dire "pipefd[1]") est fermé pour une raison quelconque, que ce soit explicitement ou parce que le processus parent se termine, guestunmount le remarque et démonte le point de montage.

Si votre système d'exploitation le prend en charge, vous devriez définir le drapeau "FD_CLOEXEC" sur le côté écriture du pipe. Ceci afin que d'autres processus enfants n'héritent pas du descripteur de fichier et le gardent ouvert.

Guestunmount ne se daemonise jamais lui-même.

DEPUIS DES SCRIPTS SHELL

Comme bash ne fournit pas de moyen de créer un pipe sans nom, utilisez un piège pour appeler guestunmount à la sortie comme ceci :

trap "guestunmount point_de_montage" EXIT INT QUIT TERM

OPTIONS

--fd=FD
Spécifie le descripteur de fichier du pipe à surveiller, et retarde le nettoyage jusqu'à ce que ce pipe soit fermé.
--help
Affiche une aide brève et quitte.
-q
--quiet
Ne pas afficher les messages d'erreur de fusermount. Le statut de retour est toujours défini (voir "STATUT DE SORTIE" ci-dessous).
--no-retry
--retry=N
Par défaut, guestunmount essaiera l'opération fusermount jusqu'à 5 fois (c'est-à-dire qu'il l'exécutera jusqu'à 6 fois = 1 essai + 5 réessais).

Utilisez --no-retry pour que guestunmount n'exécute fusermount qu'une seule fois.

Utilisez --retry=N pour que guestunmount réessaie "N" fois au lieu de 5.

guestunmount effectue un recul exponentiel entre les réessais, attendant 1 seconde, 2 secondes, 4 secondes, etc. avant chaque réessai.

-V
--version
Affiche la version du programme et quitte.

VARIABLES D'ENVIRONNEMENT

"PATH"
Le programme fusermount(1) (fourni par FUSE) doit être disponible dans le "PATH" courant.

STATUT DE SORTIE

Ce programme retourne 0 en cas de succès, ou l'un des codes d'erreur suivants :

1
Erreur de programme, par exemple, impossible d'allouer de la mémoire, impossible d'exécuter fusermount. Voir le message d'erreur affiché pour plus d'informations.
2
Le point de montage n'a pas pu être démonté même après réessais. Voir le message d'erreur affiché pour l'erreur fusermount sous-jacente.
3
Le point de montage n'est pas monté.
