guestfs-release-notes - Notes de version de libguestfs

NOTES DE VERSION POUR LIBGUESTFS 1.38

Ces notes de version ne couvrent que les différences par rapport à la précédente séparation stable/dev (1.36.0). Pour les journaux de modifications détaillés, veuillez consulter le dépôt git, ou le fichier ChangeLog distribué dans l'archive tar.

Nouvelles fonctionnalités

Nouveaux outils

Virt-builder-repository est un nouvel outil permettant aux utilisateurs finaux de créer et mettre à jour des dépôts virt-builder (Cédric Bosdonnat).

Virt-rescue (bien que ce ne soit pas un nouvel outil) a été substantiellement réécrit, implémentant le contrôle des travaux, -m et -i les options, les touches d'échappement, etc.

Nouvelles fonctionnalités dans les outils existants

Le planificateur de virt-builder a été amélioré afin que des plans de construction plus rapides et plus efficaces soient choisis pour les cas complexes, en particulier lorsque le répertoire temporaire ou la sortie se trouve sur un stockage en réseau.

Les nouveaux modèles Fedora de virt-builder (à partir de Fedora 26) auront une disposition de partition simple et utiliseront GPT pour les partitions.

Les scripts « firstboot » de virt-customize dans les invités utilisant systemd sont maintenant installés sous "multi-user.target" au lieu de "default.target" afin qu'ils ne s'exécutent que lorsque le système est démarré normalement.

Virt-customize définit maintenant un /etc/machine-id aléatoire pour les invités Linux, s'il n'est pas déjà défini.

Virt-df fonctionne maintenant correctement sur les systèmes de fichiers avec des tailles de bloc inférieures à 1K (Nikolay Ivanets).

Virt-dib a de nouvelles améliorations de compatibilité avec diskimage-builder (Pino Toscano).

Virt-sysprep supprime "DHCP_HOSTNAME" à partir des fichiers ifcfg-*.

Virt-sysprep fonctionne maintenant sur Oracle Linux (Jamie Iles).

Virt-resize copie maintenant correctement les attributs de partition GPT de la source vers la destination (Cédric Bosdonnat).

La complétion de tabulation Bash a été implémentée ou améliorée pour : virt-win-reg, virt-v2v-copy-to-local.

virt-v2v et virt-p2v

Virt-v2v peut maintenant lire directement les fichiers VMX de VMware, soit depuis un disque local, un stockage NFS, ou via SSH depuis un hyperviseur ESXi.

Virt-v2v peut maintenant utiliser VDDK comme source d'entrée.

virt-v2v et virt-p2v sont maintenant capables de transmettre le fournisseur, le modèle et la topologie du CPU source. Cependant, malheureusement, tous les hyperviseurs sources et cibles ne sont pas capables de fournir ou consommer ces données actuellement (Tomáš Golembiovský).

Virt-v2v prend maintenant en charge les invités chiffrés (Pino Toscano).

Virt-v2v peut maintenant gérer les instantanés VMware. Notez que les instantanés sont aplatis — cela ne convertit pas la chaîne d'instantanés en une chaîne d'instantanés.

Virt-v2v installe maintenant correctement les pilotes de bloc virtio pour Windows 10 / Windows Server 2016 (Pavel Butsykin, Kun Wei).

Virt-v2v installe maintenant les pilotes virtio-rng, balloon et pvpanic, et définit correctement cela dans les métadonnées de l'hyperviseur cible pour les hyperviseurs qui le prennent en charge (Tomáš Golembiovský).

Virt-v2v installe maintenant à la fois les clés virtio anciennes et modernes dans le registre Windows (Ladi Prosek).

Virt-p2v peut maintenant préserver (dans certains cas) le décalage de l'horloge temps réel par rapport à l'UTC.

Virt-p2v combine maintenant plusieurs commandes scp vers le serveur de conversion en une seule commande, améliorant les temps de conversion.

Virt-v2v détecte maintenant correctement les noyaux Xen PV-only spéciaux de Linux (Laszlo Ersek).

Virt-v2v -o glance génère maintenant les bonnes propriétés pour les invités UEFI (Pino Toscano).

Virt-v2v -o null évite maintenant de mettre l'invité en tampon dans un fichier temporaire, il écrit plutôt dans le « null block device » de qemu. Cela le rend plus rapide et utilise presque pas d'espace disque.

Virt-v2v -o rhv prend maintenant en charge le type d'invité Windows 2016 Server.

Virt-v2v -i libvirtxml peut maintenant ouvrir des disques réseau via http ou https.

Virt-v2v émettra désormais un avertissement concernant les périphériques de pass-through hôte (Pino Toscano).

La sortie --machine-readable de virt-v2v a été améliorée afin qu'elle inclue les faits "vcenter-https", "xen-ssh" et "in-place" (Pino Toscano).

Liaisons de langage

Correction de plusieurs fuites de mémoire et d'autres problèmes de corruption de données dans les liaisons Java (Pino Toscano).

Perl %guestfs_introspection a été abandonné.

Inspection

La prise en charge de l'inspection a été réécrite en OCaml et incluse dans le démon. Cela rend l'inspection considérablement plus rapide, plus robuste et plus facilement extensible à l'avenir.

Meilleure prise en charge des icônes pour les invités ALT Linux (Pino Toscano).

Meilleure prise en charge de NeoKylin (Qingzheng Zhang).

Peut gérer des OS comme Void Linux qui n'incluent pas "VERSION_ID" dans /etc/os-release (Pino Toscano).

Ajout de la prise en charge de Microsoft MS-DOS (Daniel Berrangé).

Architectures et plateformes

Corrections multiples pour l'architecture S/390. Libguestfs et tous les outils devraient maintenant compiler et fonctionner sur cette architecture.

Autres

L'API libguestfs est maintenant sûre pour les threads (bien que non parallèle). Vous pouvez appeler des API sur le même handle depuis plusieurs threads sans avoir besoin de prendre un verrou.

Sécurité

Il y avait plusieurs vulnérabilités dans le programme icoutils "wrestool" qui est exécuté par libguestfs pour créer des icônes pour les invités Windows. Il est recommandé d'utiliser la dernière version de "wrestool".

API

Nouvelles API

"hivex_value_string"
Cela remplace l'API déconseillée "hivex_value_utf8" mais fait la même chose.
"part_get_gpt_attributes"
"part_set_gpt_attributes"
Lire et écrire les drapeaux d'attributs de partition GPT (Cédric Bosdonnat).
"part_resize"
Agrandir ou réduire une partition existante (Nikos Skalkotos).
"yara_destroy"
"yara_load"
"yara_scan"
Prise en charge du moteur de scan de malwares Yara (Matteo Cafasso).

Autres changements d'API

Les API implémentées dans le démon peuvent maintenant être écrites en C ou en OCaml. Plusieurs API ont été réécrites en OCaml, bien que nous ne prévoyions pas de toutes les réécrire.

Vous obtiendrez maintenant un message d'erreur clair si vous essayez d'ajouter trop de disques à l'appliance, au lieu d'obtenir un échec étrange de la part de qemu.

Certaines API permettaient accidentellement d'utiliser "/dev/urandom" comme « device » d'entrée, ex. "g.copy_device_to_device("/dev/urandom", "/dev/sda")". Le code a été modifié pour interdire cet usage.

Toutes les API pour inspecter les CD d'installation ont été déconseillées. Utilisez libosinfo pour cette tâche.

Changements de construction

Un compilateur OCaml fonctionnel ≥ 4.01 est maintenant requis pour construire libguestfs. L'option "./configure --disable-ocaml" reste mais n'est utilisée que pour désactiver les liaisons de langage OCaml.

Ajout du fichier "RELEASES" qui liste les dates de publication de chaque version de libguestfs. Vous devez mettre à jour ce fichier lors de la création d'une nouvelle version.

La documentation générée par "gtk-doc" a été supprimée. "./configure --enable-gtk-doc" ne fait maintenant rien.

Libtirpc est maintenant utilisé pour les fonctions XDR et rpcgen. Notez que glibc a déconseillé et dans la plupart des distributions Linux supprimé ceux-ci, donc pour la plupart des gens ce sera une dépendance supplémentaire (Martin Kletzander).

Libxcrypt est maintenant utilisé pour crypt(3). C'est requis si vous utilisez glibc ≥ 2.27.

"ocaml-hivex" est maintenant requis.

Libvirt ≥ 1.2.20 est maintenant requis.

Il y a maintenant une cible "make check-ro

VERSION HISTORY

libguestfs 1.38.1

This is a bugfix release.

New features

"virt-sysprep" now supports deleting users and groups.

The "virt-resize" command now supports extending the filesystem after resizing the partition. Previously, it would just resize the partition, leaving the filesystem intact.

"virt-builder --list-builders" lists available builders.

Added an option to "virt-builder" to explicitly specify the Linux distribution ID to use, overriding automatic detection. Use "./configure --with-distro=ID" (Pino Toscano).

Added a new "make check-root" target for tests which need to be run as root (analogous to "make check-slow").

"./configure"-time check for "__attribute__((cleanup))" now works in the cross-compilation case (Yann E. Morin).

The "AUTHORS" and "p2v/about-authors.c" files are now generated from a single place.

Either GnuPG v1 or v2 can be used.

"./configure --with-guestfs-path" may be used to set the default "LIBGUESTFS_PATH". In addition the way that the path is searched has changed slightly so that all types of appliances are searched in each path element separately (Pavel Butsykin).

"GUESTFSD_EXT_CMD" which was used to mark external commands in the daemon has been removed. It was originally used by SUSE builds, but they have not been using it for a while.

The output from "./configure" is now visually grouped under headings related to what it is doing, making it much easier to scan (Pino Toscano).

OCaml dependencies are now generated from a single script instead of multiple not-quite-the-same Makefile fragments.

"./configure --with-distro=ID" can be used to override automatic Linux distro detection at build time (Pino Toscano).

qemu ≥ 2.10 is supported (but not required). This adds mandatory locking to disks and libguestfs turns this off in certain circumstances when it is known to be safe (Lars Seipel, Peter Krempa, Daniel Berrangé, Pino Toscano, Fam Zheng, Yongkui Guo, Václav Kadlčík).

Internals

Most common code has been moved to the common/ subdirectory, with OCaml common code being in common/ml* directories (eg. common/visit and common/mlvisit contain the visitor library in C and OCaml respectively). The mllib directory has been deleted and replaced by common/mltools.

There is now a lightweight OCaml binding for PCRE, see common/mlpcre. Use of OCaml "Str" library has been mostly replaced with PCRE.

Add more calls to "udev_settle" to improve stability of partition code (Dawid Zamirski).

Run "udev_settle" with --exit-if-exists option, which improves the speed of this command (Pavel Butsykin).

Detect new locations of major(3), minor(3), makedev(3).

Actions can now be deprecated with no suggested replacement, for APIs such as "guestfs_wait_ready" that should simply be removed from client code.

Use gnulib "set_nonblocking_flag" wrapper instead of calling fcntl(2) with "O_NONBLOCK" (Eric Blake). Similarly "set_cloexec_flag".

Fix memory leak in XFS version of "guestfs_vfs_minimum_size" (Pino Toscano).

Valgrind checks now run on the virt-p2v binary.

Unicode single quotes ("‘’") and now used in place of '' or `' throughout the code and documentation. Similarly for "’s" instead of "'s".

The "is_zero" function has been reimplemented for greater speed (Eric Blake).

In the direct backend, virtio-blk support has been removed. Virtio-scsi is now the only supported way to add disks.

Generator string parameter and return types have been rationalised so there are only two types ("String", "StringList") with many subtypes eg. "FileIn" becomes "String (FileIn, ...)".

The appliance disk image can now be in formats other than raw (Pavel Butsykin).

Multiple improvements to how we automatically build Debian templates for virt-builder (Pino Toscano). Enable serial console for these templates (Florian Klink).

In the daemon, instead of making a private copy of lvm.conf and modifying it (eg for filters), start with an empty file since LVM understands that to mean "all defaults" (Alasdair Kergon, Zdenek Kabelac).

The "direct" backend can now run QMP queries against the QEMU binary, enhancing the kinds of information we can detect. In addition the code to query QEMU has been made more robust for handling multiple parallel queries of different versions of QEMU.

OCaml Augeas bindings are bundled under common/mlaugeas. The long term plan is to remove this and use system ocaml-augeas when it is more widely available in distros (Pino Toscano).

All OCaml modules ("*.ml" files) are now required to have an interface file ("*.mli"). If they don’t export anything then the interface will be empty except for comments.

Certain OCaml features in OCaml ≥ 4.01 are used throughout the code, including replacing ‘{ field = field }’ with ‘{ field }’.

Virt-builder "make-template" utility now uses the "virt-install --transient" option so that we should never need to clean up left over domains after a crash. It also saves kickstarts and virt-install commands, which are committed to git for future reference.

/dev/shm is now created in the appliance (Nicolas Hicher).

In verbose mode on Fedora guests, virt-customize will now use "dnf --verbose" enabling better debugging output.

Virt-v2v input and output classes now contain a "#precheck" method which is used to perform environmental checks before conversion starts.

Virt-p2v enables miniexpect debugging. It is written to stderr (of virt-p2v).

Virt-v2v free space checks are more liberal especially for smaller guests (Pino Toscano).
