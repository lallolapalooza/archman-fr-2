Pour un fichier d'entrée donné, le suffixe du nom de fichier détermine le type de compilation effectué. Les types de noms de fichiers d'entrée suivants sont pris en charge

:
fichier.
mod
Fichiers source de programme ou d'implémentation Modula-2. Voir l'option -fmod= si vous souhaitez compiler un projet qui utilise une extension de fichier source
différente.
fichier.
def
Fichiers source de module de définition Modula-2. Les modules de définition ne sont pas compilés séparément ; en GNU Modula-2, les modules de définition sont analysés au besoin lorsque les modules de programme ou d'implémentation sont compilés. Voir l'option -fdef= si vous souhaitez compiler un projet qui ut
ilise une extension de f
ichier source différente.

Vous pouvez spécifier plus d'un fichier d'entrée sur la ligne de commande

gm2,
"-
g"
crée des informations de débogage afin que des débogueurs tels que gdb puissent inspecter et contrôler
l'exécutable.
"-
I"
utilisé pour spécifier le chemin de recherche des modules de définition et d'implémentation. Un exemple est : "gm2-g -c -I.:../../libs foo.mod". Si cette option n'est pas spécifiée, le chemin par défaut est ajouté, qui se compose du répertoire courant suivi des répertoires de bibliothèques de dialecte de langage
appropriés.
"-fauto-ini
t"
active l'initialisation automatique des pointeurs à NIL. Chaque fois qu'un bloc est créé, tous les pointeurs déclarés dans cette portée verront leur adresse assignée à
NIL.
"-fbound
s"
active la vérification à l'exécution des sous-plages, des index de tableau et de l'indirection via un pointeur
"NIL".
"-fcas
e"
active la vérification à la compilation pour vérifier si une instruction "CASE" nécessite une clause "ELSE" alors qu'aucune n'a été
spécifiée.
"-fcp
p"
prétraite le source avec cpp -lang-asm -traditional-cpp Pour plus de détails sur ces options, si -fcpp est fourni, alors tous les modules de définition et modules d'implémentation qui sont analysés seront prétraités par cpp
.
"-fdebug-builti
ns"
appelle une fonction réelle plutôt que l'équivalent intégré. Cela peut être utile pour déboguer les valeurs de paramètres d'une fonction intégrée, car cela permet aux utilisateurs de faire du pas à pas dans une fonction
intrinsèque.
"-fdef
="
reconnaît le suffixe spécifié comme nom de fichier de module de définition. Le suffixe de nom de fichier d'implémentation et de module par défaut est .def. Si cette option est utilisée, GNU Modula-2 reviendra toujours à cette valeur par défaut si un module de définition demandé est
introuvable.
"-fdump-system-expor
ts"
affiche tous les éléments système intégrés. C'est une option interne de ligne de
commande.
"-fexception
s"
active le code de gestion des exceptions. Par défaut, cette option est activée. La gestion des exceptions peut être désactivée par -fno-exceptions et aucune référence n'est faite aux bibliothèques d'exceptions
d'exécution.
"-fextended-opaq
ue"
permet aux types opaques d'être implémentés comme n'importe quel type. C'est une extension GNU Modula-2 et elle nécessite que le module d'implémentation définissant le type opaque soit disponible afin qu'il puisse être résolu lors de la compilation du module qui importe le type
opaque.
"-ffloatvalu
e"
active la vérification à l'exécution pour vérifier si un nombre en virgule flottante est sur le point de dépasser sa
plage.
"-fgen-module-list=nomdefichi
er"
tente de trouver tous les modules lors de l'édition de liens et génère une liste de modules. Si le nomdefichier est - alors le contenu n'est pas écrit et est seulement utilisé pour forter l'édition de liens de tous les constructeurs de modules. Cette option ne peut pas être utilisée si -fuse-list= est
activé.
"-finde
x"
génère du code pour vérifier si les valeurs d'index de tableau sont hors limites. La vérification des index de tableau peut être désactivée via -fno-inde
x.
"-fis
o"
active les fonctionnalités de la norme ISO. Actuellement, cela active le module ISO "SYSTEM" et modifie le chemin de recherche des bibliothèques par défaut afin que les bibliothèques ISO soient recherchées avant les bibliothèques PIM. Cela affecte également le comportement des opérateurs "DIV" et "MOD"
.
"-flibs
="
modifie le chemin de recherche des bibliothèques par défaut. Les bibliothèques fournies sont : m2pim, m2iso, m2min, m2log et m2cor. Celles-ci correspondent aux bibliothèques de base Programming in Modula-2, aux bibliothèques standard ISO, au support de bibliothèque minimal, à la bibliothèque compatible Logitech et à Programming in Modula-2 avec coroutines. Plusieurs bibliothèques peuvent être spécifiées et sont séparées par des virgules, la priorité allant à la première de la liste. Il n'est pas nécessaire d'utiliser -flibs=m2pim ou -flibs=m2iso si vous spécifiez également -fpim, -fpim2, -fpim3, -fpim4 ou -fiso. À moins que vous n'utilisiez -flibs=m2min, vous devriez inclure m2pim car elles fournissent les modules de base que tous les autres dialectes utilisent. L'option -fno-libs=- désactive le pilote gm2 de modifier les chemins de recherche et de
bibliothèques.
"-static-libg
m2"
Sur les systèmes qui fournissent les runtimes m2 à la fois comme bibliothèques partagées et statiques, cette option force l'utilisation de la version
statique.
"-fm2-debug-trac
e="
active le débogage de traçage à l'aide d'une liste séparée par des virgules : line,token,quad,all. C'est une option interne de ligne de
commande.
"-fm2-dump
="
permet le vidage de la représentation interne des structures de données de Modula-2 à l'aide d'une liste séparée par des virgules. La liste peut contenir : quad,gimple,de
cl,all.
"-fm2-dump-decl=nomdefichi
er"
vide la représentation Modula-2 d'un symbole vers le nomdefichier spécifié. Cette option n'a d'effet que si -fm2-dump-filter est
spécifié.
"-fm2-dump-gimple=nomdefichi
er"
vide la représentation gimple de Modula-2 vers le nomdefichier sp
écifié.
"-fm2-dump-quad=nomdefichi
er"
vide la représentation quadruple vers le nomdefichier sp
écifié.
"-fm2-dump-filter=règle
s"
filtre les vidages de langage -fdump-lang-decl, -fdump-lang-gimple et-fdump-lang-quad selon les règles. règles doit être une liste séparée par des virgules qui peut prendre trois formes : le nom textuel complet de déclaration d'une procédure, [libname.]module.ident ou [filename:]module.ident. C'est une option interne de ligne de commande. Actuellement, elle ne filtre que sur les noms de procédures et la correspondance par expressions régulières n'est pas implémentée. Trois exemples d'utilisation suivant les formes précédentes pourraient être : "-fm2-dump-filter=_M2_hello_init", "-fm2-dump-filter=m2pim.StrIO.WriteString" et "-fm2-dump-filter=StrLib.mod:Str
IO.WriteString".
"-fm2-file-offset-bit
s="
force le type "SYSTEM.COFF_T" à être construit en utilisant le nombre de bits spécifié. Si cette option n'est pas utilisée, la valeur par défaut est "CSSIZE_T"
bits.
"-fm2-
g"
améliore l'expérience de débogage pour les nouveaux programmeurs au prix de la génération d'instructions "nop" si nécessaire pour assurer la précision du pas à pas sur tous les mots-clés liés au code. Un exemple de cela est la terminaison d'une liste d'instructions "IF" imbriquées où plusieurs mots-clés "END" sont mappés sur une séquence d'instructions "nop"
.
"-fm2-lower-ca
se"
rend les mots-clés dans les messages d'erreur en
minuscules.
"-fm2-pathnam
e="
spécifie le nom de préfixe mangé du module pour tous les modules dans les chemins d'inclusion
suivants.
"-fm2-pathnam
eI"
pour usage interne uniquement : utilisé par le pilote pour copier l'option -I destinée à
l'utilisateur.
"-fm2-plugi
n"
insère un plugin pour identifier les erreurs d'exécution à la compilation (activé par défaut)
.
"-fm2-prefix
="
spécifie le nom de préfixe mangé du module. Tous les symboles exportés d'un module de définition auront le nom de
préfixe.
"-fm2-statisti
cs"
génère des informations quadruples : nombre de quadruples générés, nombre de quadruples restants après optimisation et nombre de lignes de source
compilées.
"-fm2-strict-ty
pe"
indicateur expérimental pour activer le nouveau vérificateur de types
strict. t>"-fm2-whole-program"
compile tous les modules d'implémentation et le module programme en une seule fois. Notez que vous devez faire attention si vous compilez des modules de dialectes différents (en particulier avec les opérandes négatifs pour modulus). Mais cette option, lorsqu'elle est combinée avec "-O3", peut apporter d'énormes améliorations de
performance.
"-fmod
="
reconnaît le suffixe spécifié comme noms de fichiers d'implémentation et de module. Le suffixe par défaut des noms de fichiers d'implémentation et de module est .mod. Si cette option est utilisée, GNU Modula-2 reviendra quand même à cette valeur par défaut s'il doit lire un module d'implémentation et que le nom de fichier avec le suffixe spécifié n'existe
pas.
"-fni
l"
génère du code pour détecter l'accès aux données via un pointeur de valeur "NIL". La vérification du déréférencement à travers un pointeur "NIL" peut être désactivée par -fno-ni
l.
"-fpi
m"
active les fonctionnalités standard PIM. Actuellement, cela active le module "SYSTEM" PIM et détermine quels identifiants sont pervasifs (déclarés dans le module de base). Si aucun autre commutateur -fpim[234] n'est utilisé, alors les opérateurs de division et de modulus se comportent comme défini dans
PIM4.
"-fpim
2"
active les fonctionnalités standard PIM-2. Actuellement, cela retire "SIZE" des identifiants pervasifs (déclarés dans le module de base). Il place "SIZE" dans le module "SYSTEM". Cela affecte aussi le comportement des opérateurs "DIV" et "MOD"
.
"-fpim
3"
active les fonctionnalités standard PIM-3. Actuellement, cela n'affecte que le comportement des opérateurs "DIV" et "MOD"
.
"-fpim
4"
active les fonctionnalités standard PIM-4. Actuellement, cela n'affecte que le comportement des opérateurs "DIV" et "MOD"
.
"-fpositive-mod-floor-d
iv"
force les opérateurs "DIV" et "MOD" à se comporter comme défini par PIM4. Tous les résultats de modulus sont positifs et les résultats de la division sont arrondis vers le bas (floor)
.
"-fpthrea
d"
lie avec la bibliothèque pthread. Par défaut, cette option est activée. Elle peut être désactivée par -fno-pthread. GNU Modula-2 utilise les bibliothèques pthread de GCC pour implémenter les coroutines (voir le module d'implémentation SYSTEM)
.
"-frang
e"
génère du code pour vérifier la plage d'affectation, la plage de valeur de retour, la plage de définition et la plage du constructeur. La vérification des plages peut être désactivée via -fno-rang
e.
"-fretur
n"
génère du code pour vérifier que les fonctions se terminent toujours par un "RETURN" et ne sortent pas à la fin. La vérification des retours peut être désactivée via -fno-retur
n.
"-fruntime-module
s="
spécifie, à l'aide d'une liste séparée par des virgules, les modules d'exécution et leur ordre. Ces modules seront initialisés en premier avant tout autre module dans la dépendance de l'application. Par défaut, la liste des modules d'exécution est définie à "m2iso:RTentity,m2iso:Storage,m2iso:SYSTEM," "m2iso:M2RTS,m2iso:RTExceptions,m2iso:IOLink". Notez que ces modules ne seront liés dans votre exécutable que s'ils sont requis. Ajouter une longue liste de modules dépendants n'affectera pas la taille de l'exécutable, cela indique simplement l'ordre d'initialisation au cas où ils seraient
requis.
"-fscaffold-dynam
ic"
l'option garantit que gm2 générera une infrastructure d'échafaudage dynamique lors de la compilation des modules d'implémentation et de programme. Par défaut, cette option est activée. Utilisez -fno-scaffold-dynamic pour la désactiver ou sélectionnez -fno-scaffold-
static.
"-fscaffold-
c"
génère un échafaudage source C pour le module en cours de
compilation.
"-fscaffold-c
++"
génère un échafaudage source C++ pour le module en cours de
compilation.
"-fscaffold-ma
in"
force la génération de la fonction main. Cela n'est pas nécessaire si l'option -c est
omise.
"-fscaffold-stat
ic"
l'option garantit que gm2 générera un échafaudage statique à l'intérieur du module programme. L'échafaudage statique consiste en des séquences d'appels à toutes les procédures d'initialisation et de finalisation des modules dépendants. L' échafaudage statique est utile pour le débogage et le pas-à-pas des blocs d'initialisation des modules
d'implémentation.
"-fshare
d"
génère une bibliothèque partagée à partir du
module.
"-fsoft-check-a
ll"
active toutes les vérifications à l'exécution. Cela revient à invoquer GNU Modula-2 avec les options de commande "-fnil" "-frange" "-findex" "-fwholevalue" "-fwholediv" "-fcase" "-freturn
".
"-fsource
s"
affiche le chemin vers la source de chaque module. Cette option peut être utilisée au moment de la compilation pour vérifier que le bon module de définition est
utilisé.
"-fswi
g"
génère un fichier d'interface
swig.
"-funbounded-by-referen
ce"
active l'optimisation des paramètres non bornés en essayant de passer les paramètres non "VAR" non bornés par référence. Cette optimisation évite la copie implicite à l'intérieur de la procédure appelée. GNU Modula-2 n'autorisera le passage des paramètres non bornés par référence que si, à l'intérieur de la procédure appelée, ils ne sont pas écrits, aucune adresse n'est calculée sur le tableau et il n'est pas passé comme un paramètre "VAR". Notez qu'il est possible d'écrire du code pour contourner cette optimisation, par conséquent cette option doit être utilisée avec prudence. Par exemple, il serait possible de prendre l'adresse d'un tableau, de passer l'adresse et le tableau à une procédure, de lire depuis le tableau dans la procédure et d'écrire à l'emplacement en utilisant le paramètre d'adresse.

En raison de la nature dangereuse de cette option, elle n'est pas activée lorsque l'option -O est s

pécif
iée.
"-fuse-list=filenam
e"
si -fscaffold-static est activé, alors utilisez le fichier filename pour l'ordre d'initialisation des modules. Alors que si -fscaffold-dynamic est activé, alors utilisez ce fichier pour forcer le lien de tous les ctors de modules. Cette option ne peut pas être utilisée si -fgen-module-list= est
activé.
"-fwholedi
v"
génère du code pour détecter la division d'un nombre entier par zéro ou le modulus par
zéro.
"-fwholevalu
e"
génère du code pour détecter le débordement et le sous-débordement des nombres
entiers.
"-Wcase-enu
m"
génère un avertissement si une instruction "CASE" sélectionne sur une expression de type énuméré et que l'instruction est manquante un ou plusieurs libellés "CASE". Aucun avertissement n'est émis si l' instruction "CASE" a une clause "ELSE" par défaut. L'option -Wall activera ce
drapeau.
"-Wuninit-variable-checki
ng"
émet un avertissement si une variable est utilisée avant d'être initialisée. La vérification n'a lieu que dans le premier bloc de base de chaque procédure. Elle ne vérifie pas les paramètres, les types de tableau ou les types
d'ensemble.
"-Wuninit-variable-checking=all,known,
cond"
émet un avertissement si une variable est utilisée avant d'être initialisée. La vérification n'aura lieu que dans le premier bloc de base de chaque procédure si known est spécifié. Si cond ou all est spécifié, alors la vérification continue dans les branches conditionnelles du graphe de flux. Toute vérification s'arrêtera lorsqu'un appel de procédure est invoqué ou qu'on atteint le haut d'une boucle. L'option -Wall activera ce drapeau avec -Wuninit-variable-checking=known. L'option -Wuninit-variable-checking
=all augmenter
a le temps de
compilation.
