NOM

gmap, gpart - calculer des mappings et des partitions statiques séquentiellement

SYNOPSIS

gmap [options] [gfile] [tfile] [mfile] [lfile]
gpart [options] [nparts/pwght] [gfile] [mfile] [lfile]

DESCRIPTION

Le programme gmap calcule, de manière séquentielle, un mapping statique d'un graphe source vers un graphe cible.

Le programme gpart est une interface simplifiée à gmap, qui effectue un partitionnement de graphe au lieu d'un mapping statique. Par conséquent, le nombre désiré de parties doit être fourni, à la place de l'architecture cible.

Les options -b et -c permettent à l'utilisateur de définir des préférences sur le comportement de la stratégie de mapping qui est utilisée par défaut. L'option -m permet à l'utilisateur de définir une stratégie de mapping personnalisée.

L'option -q transforme les programmes en outils de clustering de graphes. Dans ce cas, gmap n'accepte que des architectures cibles de taille variable.

Le fichier de graphe source gfile ne peut être qu'un fichier de graphe centralisé. Pour gmap, le fichier d'architecture cible tfile décrit soit des topologies codées algorithmiquement telles que les maillages et les hypercubes, soit des architectures définies par décomposition créées à l'aide du programme amk_grf(1). Le mapping résultant est stocké dans le fichier mfile. Les informations de journalisation éventuelles (telles que celles produites par l'option -v) sont envoyées au fichier lfile. Lorsque les noms de fichiers ne sont pas spécifiés, les données sont lues depuis l'entrée standard et écrites vers la sortie standard. Les flux standards peuvent également être représentés explicitement par un tiret '-'.

Lorsque les bibliothèques appropriées ont été incluses lors de la compilation, gmap et gpart peuvent gérer directement les graphes compressés, tant en entrée qu'en sortie. Un flux est traité comme compressé dès lors que son nom est postfixé d'une extension de fichier compressé, comme dans 'brol.grf.bz2' ou '-.gz'. Les formats de compression qui peuvent être supportés sont les formats bzip2 ('.bz2'), gzip ('.gz') et lzma ('.lzma').

OPTIONS

-b?val
Définit le ratio maximum de déséquilibre de charge pour le partitionnement de graphe ou le mapping statique. Lorsque les programmes sont utilisés comme outils de clustering, ce paramètre définit le ratio maximum de déséquilibre de charge pour les bipartitions récursives. Exclusif avec l'option -m.
-c?opt
Choisit la stratégie de mapping par défaut selon une ou plusieurs options parmi :
b
force autant que possible l'équilibre de charge.
q
privilégie la qualité sur la vitesse (par défaut).
s
privilégie la vitesse sur la qualité.
t
force la sécurité.

C'est exclusif avec l'option -m.

-h
Affiche une aide.
-m?strat
Utilise la stratégie de mapping séquentielle strat (voir le manuel utilisateur Scotch pour plus d'informations).
-q
(pour gpart)
-q?pwght
(pour gmap) Utilise les programmes comme outils de clustering de graphes au lieu d'outils de mapping statique ou de partitionnement de graphes. Pour gpart, le nombre de parties devient le poids maximum du cluster. Pour gmap, ce nombre pwght doit être passé après l'option.
-V
Affiche la version du programme et le copyright.
-v?verb
Définit le mode verbeux à verb. C'est un ensemble d'un ou plusieurs caractères qui peuvent être :
m
informations de mapping.
s
informations de stratégie.
t
informations de temps.

ARCHITECTURES CIBLES

Les architectures cibles représentent les graphes sur lesquels les graphes sources sont mappés. Afin d'accélérer l'obtention des propriétés topologiques des architectures cibles lors du calcul des mappings, certaines topologies classiques sont codées algorithmiquement dans le programme de mapping lui-même. Ces topologies sont par conséquent simplement définies par leur nom de code, suivi de leurs paramètres dimensionnels :

cmplt dim
graphe complet non pondéré de taille dim.
cmpltw dim w0 w1 ... wdim-1
graphe complet pondéré de taille dim et de charges respectives w0, w1, ..., wdim-1.
hcub dim
hypercube de dimension dim.
leaf hgt n0 w0 ... nhgt-1 whgt-1
graphe arbre-feuilles de hauteur hgt avec (n0 fois n1 fois ... nhgt-1) sommets, avec des poids de liens inter-clusters de w0, w1, ... whgt-1.
mesh2D dimX dimY
maillage 2D de dimX fois dimY nœuds.
mesh3D dimX dimY dimZ
maillage 3D de dimX fois dimY fois dimZ nœuds.
torus2D dimX dimY
tore 2D de dimX fois dimY nœuds.
torus3D dimX dimY dimZ
tore 3D de dimX fois dimY fois dimZ nœuds.

D'autres topologies cibles peuvent être créées à partir de leur description de graphe source en utilisant la commande amk_grf(1). Dans ce cas, la description cible commencera par le nom de code deco.

MAPPINGS

Les mappings sont représentés par autant de lignes qu'il y a de sommets dans le graphe source. Chacune de ces lignes est composée de deux chiffres : le numéro du sommet (ou son étiquette si les sommets du graphe source sont étiquetés) et l'indice du sommet cible auquel il a été assigné. Les indices des sommets cibles vont de 0 au nombre de sommets dans l'architecture cible (c'est-à-dire le nombre de parties) moins un.

Ce bloc de lignes est toujours précédé par le nombre de telles lignes. Dans la plupart des cas, puisque des mappings complets sont demandés, le nombre de lignes est égal au nombre de sommets dans le graphe source.

EXEMPLES

Exécute gpart pour calculer une partition en 7 parties du graphe 'brol.grf' et sauvegarde l'ordre résultant dans le fichier 'brol.map'.

    $ gpart 7 brol.grf brol.map
Exécute gmap pour calculer une partition, en 3 parties de poids respectifs 1, 2 et 4, du graphe 'brol.grf' et sauvegarde le mapping résultant dans le fichier 'brol.map'. Le nom de fichier standard tiret '-' est utilisé afin que la description de l'architecture cible soit lue depuis l'entrée standard, via le pipe, telle que fournie par la commande shell 'echo'. 
    $ echo "cmpltw 3 1 2 4" | gmap brol.grf - brol.map
