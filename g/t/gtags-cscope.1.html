GTAGS-CSCOPE(1) Manuel des commandes générales GTAGS-CSCOPE(1)

NOM

gtags-cscope - examiner interactivement un programme C

SYNOPSIS

gtags-cscope [-abCdehilLvV][-F fichier ][-012345678 motif][-p n]

DESCRIPTION

gtags-cscope est un outil interactif orienté écran qui permet à l'utilisateur de parcourir les fichiers sources pour des éléments de code spécifiés.

gtags-cscope construit la référence croisée des symboles la première fois qu'il est utilisé sur les fichiers sources du programme en cours de navigation. Lors d'une invocation suivante, gtags-cscope reconstruit la référence croisée uniquement si un fichier source a changé ou si la liste des fichiers sources est différente. Lorsque la référence croisée est reconstruite, elle est mise à jour de manière incrémentielle, ce qui rend la reconstruction plus rapide que la construction initiale.

gtags-cscope est un outil qui emprunte simplement l'interface utilisateur de cscope ; c'est Global lui-même pour le fond.

OPTIONS

Certains arguments de ligne de commande ne peuvent apparaître qu'en tant qu'unique argument lors de l'exécution de gtags-cscope. Ils font que le programme se contente d'afficher une sortie et se termine immédiatement :

-h
Afficher l'aide détaillée sur l'utilisation.
-V
Afficher le numéro de version de gtags-cscope.
--help
Identique à -h
--version
Identique à -V

Les options suivantes peuvent apparaître dans n'importe quelle combinaison :

-a
Afficher les chemins absolus.
-b
Construire uniquement la référence croisée.
-C
Ignorer la casse des lettres lors de la recherche.
-d
Ne pas mettre à jour la référence croisée.
-e
Supprimer l'invite de commande ´^e´ entre les fichiers.
-F fichier
Lire les lignes de référence aux symboles à partir du fichier. (Un fichier de référence aux symboles est créé par > et >>, et peut aussi être lu à l'aide de la commande <, décrite dans « Émission des requêtes suivantes », ci-dessous.)
-i
Ignorer le signal SIGINT en mode orienté ligne.
-L
Effectuer une recherche unique avec une sortie orientée ligne lorsqu'il est utilisé avec l'option -num motif.
-l
Interface orientée ligne. Cette option implique l'option -d .
-[0-9] motif
Aller au champ de saisie num (en comptant à partir de 0) et trouver le motif.
-p n
Afficher les derniers n composants du chemin du fichier au lieu de la valeur par défaut (1). Utiliser ´0´ pour ne pas afficher le nom du fichier du tout.
-v
Être plus verbeux en mode orienté ligne.

Demande de la recherche initiale

Une fois la référence croisée prête, gtags-cscope affichera ce menu :

Trouver ce symbole :
Trouver cette définition globale :
Trouver les fonctions appelées par cette fonction (N/A) :
Trouver les références de cette fonction :
Trouver cette chaîne de texte :
Modifier cette chaîne de texte :
Trouver ce motif egrep :
Trouver ce fichier :
Trouver les fichiers incluant ce fichier :
Trouver les affectations à ce symbole :

Appuyez à plusieurs reprises sur les touches <Up> ou <Down> pour vous déplacer vers le champ de saisie souhaité, tapez le texte à rechercher, puis appuyez sur la touche <Return>.

Émission des requêtes suivantes

Si la recherche est réussie, l'une de ces commandes à un seul caractère peut être utilisée :

0-9a-zA-Z
Modifier le fichier référencé par le numéro de ligne donné.
<Space>
Afficher l'ensemble suivant de lignes correspondantes.
<Tab>
Alterner entre le menu et la liste des lignes correspondantes.
<Up>
Se déplacer vers l'élément précédent du menu (si le curseur est dans le menu) ou vers la ligne correspondante précédente (si le curseur est dans la liste des lignes correspondantes).
<Down>
Se déplacer vers l'élément suivant du menu (si le curseur est dans le menu) ou vers la ligne correspondante suivante (si le curseur est dans la liste des lignes correspondantes).
+
Afficher l'ensemble suivant de lignes correspondantes.
-
Afficher l'ensemble précédent de lignes correspondantes.
^e
Modifier les fichiers affichés dans l'ordre.
>
Écrire la liste de lignes affichées dans un fichier.
>>
Ajouter la liste de lignes affichées à un fichier.
<
Lire les lignes depuis un fichier au format de référence aux symboles (créé par ´>´ ou ´>>´), tout comme l'option -F .
^
Filtrer toutes les lignes à travers une commande shell et afficher les lignes résultantes, en remplaçant les lignes qui étaient déjà là.
|
Envoyer toutes les lignes à une commande shell et les afficher sans les modifier.
^g
Lire les lignes à partir du résultat de l'exécution de global(1).

À tout moment, ces commandes à un seul caractère peuvent aussi être utilisées :

<Return>
Se déplacer vers le champ de saisie suivant.
^n
Se déplacer vers le champ de saisie suivant.
^p
Se déplacer vers le champ de saisie précédent.
^y
Rechercher avec le dernier texte tapé.
^b
Se déplacer vers le champ de saisie et le motif de recherche précédents.
^f
Se déplacer vers le champ de saisie et le motif de recherche suivants.
^c
Basculer entre ignorer/utiliser la casse des lettres lors de la recherche. (Lorsque la casse est ignorée, une recherche de ´FILE´ correspondra à ´File´ et ´file´.)
^r
Reconstruire la référence croisée.
!
Démarrer un shell interactif (tapez ´^d´ pour revenir à gtags-cscope).
^l
Redessiner l'écran.
?
Afficher les informations d'aide sur les commandes gtags-cscope .
^d
Quitter gtags-cscope.

REMARQUE : Si le premier caractère du texte à rechercher correspond à l'une des commandes ci-dessus, échappez-le en tapant d'abord un ´\' (antislash).

Substitution d'un nouveau texte pour un ancien texte

Une fois le texte à modifier tapé, gtags-cscope demandera le nouveau texte, puis affichera les lignes contenant l'ancien texte. Sélectionnez les lignes à modifier avec ces commandes à un seul caractère :

0-9a-zA-Z
Marquer ou démarquer la ligne à modifier.
*
Marquer ou démarquer toutes les lignes affichées à modifier.
<Space>
Afficher l'ensemble suivant de lignes.
+
Afficher l'ensemble suivant de lignes.
-
Afficher l'ensemble précédent de lignes.
^a
Marquer ou démarquer toutes les lignes à modifier.
^d
Modifier les lignes marquées et quitter.
<Esc>
Quitter sans modifier les lignes marquées.
!
Démarrer un shell interactif (tapez ´^d´ pour revenir à gtags-cscope).
^l
Redessiner l'écran.
?
Afficher les informations d'aide sur les commandes gtags-cscope .
Touches spéciales
Si votre terminal a des touches de flèches qui fonctionnent dans vi, vous pouvez les utiliser pour vous déplacer entre les champs de saisie. La touche flèche vers le haut est utile pour se déplacer vers le champ de saisie précédent au lieu d'utiliser la touche <Tab> à plusieurs reprises. Si vous avez les touches <CLEAR>, <NEXT> ou <PREV>, elles agiront comme les commandes ´^l´, ´+´ et ´-´, respectivement.

Interface orientée ligne

L'option -l vous permet d'utiliser gtags-cscope là où une interface orientée écran ne serait pas utile, par exemple depuis un autre programme orienté écran.

gtags-cscope affichera ´>>´ lorsqu'il est prêt pour une ligne de saisie, qui commence par le numéro du champ (en comptant à partir de 0), immédiatement suivi du motif de recherche. Par exemple, ´`main´ trouve la définition de la fonction `main´.

Si vous voulez simplement une recherche unique, au lieu de l' -l option utilisez les -L et -num pattern options, et vous n'aurez pas l'invite `>>´.

Pour -l, gtags-cscope produit le nombre de lignes de référence :
cscope: 2 lines

Pour chaque référence trouvée, gtags-cscope produit une ligne composée du nom du fichier, du nom de la fonction, du numéro de ligne et du texte de la ligne, séparés par des espaces. Par exemple :
main.c main 161 main(argc, argv)

Notez que l'éditeur n'est pas appelé pour afficher une référence unique, contrairement à l'interface orientée écran.

Vous pouvez utiliser la commande `c´ pour basculer l'ignorance/utilisation de la casse lors d'une recherche. (Lorsque la casse est ignorée, une recherche pour `FILE´ correspondra à `File´ et `file´.)

Vous pouvez utiliser la commande `r´ pour reconstruire la base de données.

gtags-cscope quittera lorsqu'il détectera une fin de fichier, ou lorsque le premier caractère d'une ligne d'entrée est `^d´ ou `q´.

ENVIRONNEMENT

Les variables d'environnement suivantes proviennent de cscope .

CSCOPE_EDITOR
Remplace les EDITOR et VIEWER variables. Utilisez ceci si vous souhaitez utiliser un éditeur différent avec cscope que celui spécifié par vos EDITOR/VIEWER variables.
CSCOPE_LINEFLAG
Format de l'indicateur de numéro de ligne pour votre éditeur. Par défaut, cscope invoque votre éditeur via l'équivalent de `editor +N file´, où N est le numéro de ligne auquel l'éditeur doit sauter. Ce format est utilisé à la fois par emacs et vi. Si votre éditeur a besoin de quelque chose de différent, spécifiez-le dans cette variable, avec `%s´ comme espace réservé pour le numéro de ligne. Ex : si votre éditeur doit être invoqué comme `editor -#103 file´ pour aller à la ligne 103, définissez cette variable à `-#%s´.
CSCOPE_LINEFLAG_AFTER_FILE
Définissez cette variable à `yes´ si votre éditeur doit être invoqué avec l'option de numéro de ligne après le nom du fichier à éditer. Pour continuer l'exemple de CSCOPE_LINEFLAG, ci-dessus : si votre éditeur a besoin de voir `editor file -#number´, définissez cette variable d'environnement. Les utilisateurs de la plupart des éditeurs standard (vi, emacs) n'ont pas besoin de définir cette variable.
EDITOR
Éditeur préféré, qui est par défaut vi.
HOME
Répertoire personnel, qui est automatiquement défini à la connexion.
SHELL
Shell préféré, qui est par défaut sh.
TERM
Type de terminal, qui doit être un terminal écran.
TERMINFO
Chemin complet du répertoire d'informations du terminal. Si votre terminal n'est pas dans le répertoire terminfo standard, voir curses et terminfo pour savoir comment créer votre propre description de terminal.
TMPDIR
Répertoire des fichiers temporaires, qui est par défaut `/tmp´.
VIEWER
Programme d'affichage de fichiers préféré (comme less), qui remplace EDITOR (voir ci-dessus).

Les variables d'environnement suivantes proviennent de Global .

GTAGSCONF
Fichier de configuration.
GTAGSGLOBAL
Si cette variable est définie, `´$GTAGSGLOBAL´ est utilisé comme nom de global(1). La valeur par défaut est global.
GTAGSGTAGS
Si cette variable est définie, `´$GTAGSGTAGS´ est utilisé comme nom de gtags(1). La valeur par défaut est gtags.
GTAGSDBPATH
Le répertoire dans lequel les fichiers de tags existent. Cette valeur est ignorée lorsque GTAGSROOT n'est pas défini.
GTAGSLABEL
Étiquette de configuration. La valeur par défaut est `default´.
GTAGSLIBPATH
Si cette variable est définie, elle est utilisée comme chemin de recherche pour les fonctions de bibliothèque. Si les tags spécifiés ne sont pas trouvés dans le projet, global recherche également dans ces chemins. Comme seule `GTAGS´ est ciblée lors de la récupération, cette variable est ignorée lorsque -r ou -s est spécifié.
GTAGSROOT
Le répertoire racine du projet.
MAKEOBJDIR
Si cette variable est définie, `´$MAKEOBJDIR´ est utilisé comme nom du répertoire obj de style BSD. La valeur par défaut est `obj´.
MAKEOBJDIRPREFIX
Si cette variable est définie, `´$MAKEOBJDIRPREFIX´ est utilisé comme préfixe du répertoire obj de style BSD. La valeur par défaut est `/usr/obj´.

FICHIERS

`GTAGS´
Fichier de tags pour les définitions.
`GRTAGS´
Fichier de tags pour les références.
`GPATH´
Fichier de tags pour les fichiers source.
`GTAGSROOT´
Si la variable d'environnement GTAGSROOT n'est pas définie et que le fichier `GTAGSROOT´ existe dans le même répertoire que `GTAGS´ alors global définit GTAGSROOT au contenu du fichier.
`gtags.conf´, `´$HOME/.globalrc´
Données de configuration pour GNU Global. Voir gtags.conf(5).

ANOMALIE

Le champ fonction de l'affichage est presque <unknown> puisque Global ne le reconnaît pas.

`Find functions called by this function´ n'est pas implémenté.

HISTORIQUE

Cscope a été développé à l'origine au Bell Labs au début des années 1980, et a été publié en tant que logiciel libre sous la licence BSD en avril 2000. Gtags-cscope est un dérivé de cscope pour utiliser Global comme back-end. Son interface orientée ligne a été écrite à l'origine en 2006, et a été réimplémentée en 2011 en utilisant cscope lui-même.
