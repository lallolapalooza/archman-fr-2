NAME

gtkwave

GTKWave waveform viewer

SYNTAX

gtkwave [options] [dumpfile] [savefile]

DESCRIPTION

gtkwave is a waveform viewer for simulation traces. It can display traces from Verilog VCD, VZT, LXT, LXT2, FST, and Value Change Dump (VCD) files. It can display traces from Verilog simulation, Synopsys VCS, Cadence Xcelium, Mentor Graphics Questa/ModelSim, Aldec Active-HDL, and other EDA tools. It can also display traces from logic analyzers and other hardware debug tools.

The waveform viewer can display a virtually unlimited number of signals. It can display signals of any type (integers, enumerated types, bitvectors, etc.). It can display signals in various formats (binary, hexadecimal, unsigned, signed, enumerated types). It can display signals in various representations (waves, values, lists).

The waveform viewer can display multiple traces at once. It can display traces from different simulation runs at the same time. It can display traces from different simulation tools at the same time.

The waveform viewer can display traces from different formats at the same time. It can display traces from VCD, VZT, LXT, LXT2, FST, and other formats at the same time.

OPTIONS

-I,--interactive
Spécifie que le mode VCD "interactif" doit être utilisé, ce qui permet à un spectateur de naviguer dans une trace VCD pendant que GTKWave traite le fichier VCD. Lorsque cette option est utilisée, le nom de fichier est surchargé de telle sorte qu'il s'agit de la valeur hexadécimale de l'ID de mémoire partagée d'un écrivain. Notez que l'ID de mémoire partagée peut être transmis directement depuis stdin en utilisant l'option --vcd ; voir la page de manuel de shmidcat(1) pour plus de détails.
-L,--legacy
Spécifie que le spectateur doit utiliser le mode VCD hérité plutôt que le recoder VCD. Notez que l'utilisation du mode hérité nécessitera considérablement plus de mémoire que le recoder et son utilisation est déconseillée pour les traces très volumineuses.
-g,--giga
Spécifie que le spectateur doit utiliser le mempacking gigaoctet lors du recodage (potentiellement plus lent). Ceci équivaut à définir les indicateurs vlist_spill et vlist_prepack dans le fichier rc.
-C,--comphier
Spécifie que le spectateur doit utiliser des noms de hiérarchie compressés lors du chargement du dumpfile (disponible pour le recoder VCD, LXT, LXT2 et VZT). Cela utilisera moins de mémoire au détriment d'un délai de compression / décompression.
-v,--vcd
Utiliser stdin comme dumpfile VCD.
-O,--output <nom_fichier>
Spécifie le nom de fichier pour la redirection stdout/stderr. Pour désactiver les messages vers la console, utilisez /dev/null comme nom de fichier.
-z,--slider-zoom
Active le zoom étirable par curseur pour le curseur temporel horizontal. Cliquer puis faire glisser le bord gauche ou droit du curseur peut être utilisé pour un zoom précis en temps réel.
-V,--version
Affiche la bannière de version puis quitte.
-h,--help
Affiche l'aide puis quitte.
-x,--exit
Quitte après le chargement de la trace (pour le benchmark du chargeur).

FILES

~/.gtkwaverc (voir la page de manuel gtkwaverc(5))

EXAMPLES

Pour exécuter ce programme de la manière standard, tapez :
gtkwave dumpfile.vcd
Alternativement, vous pouvez l'exécuter avec un fichier de sauvegarde comme :
gtkwave dumpfile.vcd dumpfile.gtkw
Pour exécuter interactivement en utilisant le descripteur de mémoire partagée 0x00050003 :
gtkwave -I 00050003 dumpfile.gtkw
Pour récupérer automatiquement un dumpfile à partir d'un fichier de sauvegarde (par exemple, lors du lancement à partir d'une icône) :
gtkwave --save dumpfile.gtkw
Pour exécuter à partir du bundle d'applications gtkwave.app sur OSX en utilisant /bin/sh :
GTKWAVE_CHDIR=`pwd`;export GTKWAVE_CHDIR;open -n -W -a gtkwave --args --chdir dummy --dump des.vzt --save des.gtkw
Alternativement, exécutez le script Perl suivant gtkwave.app/Contents/Resources/bin/gtkwave pour traiter les arguments de la ligne de commande à partir des scripts shell OSX.
Notez que pour passer des éléments qui ne sont pas des options et qui commencent par un tiret, il est nécessaire de spécifier -- afin de désactiver l'analyse des options. Un second -- désactivera l'analyse de tous les arguments suivants, leur permettant d'être transmis aux scripts Tcl et récupérés via gtkwave::getArgv.

Les options de ligne de commande ne sont pas nécessaires pour représenter les noms des dumpfiles, savefiles et rcfiles. Elles sont simplement fournies pour permettre de les spécifier dans un ordre différent.

BUGS

AIX nécessite -bmaxdata:0x80000000 (-bmaxdata:0xd0000000/dsa pour AIX 5.3) à ajouter à votre liste d'indicateurs de compilateur pour xlc si vous souhaitez que GTKWave puisse accéder à plus de 256 Mo de mémoire virtuelle. La valeur indiquée permet au VMM d'utiliser jusqu'à 2 Go (3,25 Go AIX5.3). Cela peut être nécessaire pour les traces très volumineuses.
Les opérations Shift et Page utilisant la barre de défilement de la fenêtre de forme d'onde peuvent être non fonctionnelles lorsque vous vous éloignez du début du dump pour des traces très volumineuses. Une trace qui va jusqu'à 45 milliards de ticks est connue pour présenter ce problème. Cela provient de l'utilisation de l'élément gfloat du curseur horizontal pour encoder la valeur temporelle de la marge gauche. Le résultat est une perte de précision pour les valeurs très volumineuses. Utilisez les raccourcis clavier ou les boutons en haut de l'écran si cela pose problème.
Lors de l'exécution sous Cygwin, il est nécessaire d'activer Cygserver si l'IPC par mémoire partagée est utilisé. Plus précisément, cela se produit lorsque rtlbrowse(1) est lancé comme processus auxiliaire. Voir la documentation Cygwin pour plus d'informations sur la manière d'activer Cygserver.
