GTAGS(1) Manuel des commandes générales GTAGS(1)

NOM

gtags - créer des fichiers de tags pour global

SYNOPSIS

gtags [-ciIOqvw][-C dir][-d fichier-tag][-f fichier][chemin-db]

DESCRIPTION

Gtags est utilisé pour créer des fichiers de tags pour global(1).

Gtags collecte récursivement les fichiers source sous le répertoire courant, extrait les symboles et écrit les données de référence croisée dans les fichiers de tags (´GTAGS´, ´GRTAGS´ et ´GPATH´).

Par défaut, gtags collecte les fichiers source C, Yacc, assembleur, Java, C++ et PHP. Les fichiers dont le nom se termine par ´.c´, ´.h´ sont supposés être des fichiers source C. Les fichiers dont le nom se termine par ´.y´ sont supposés être des fichiers source Yacc. Les fichiers dont le nom se termine par ´.s´, ´.S´ sont supposés être des fichiers source assembleur. Les fichiers dont le nom se termine par ´.java´ sont supposés être des fichiers source Java. Les fichiers dont le nom se termine par ´.c++´, ´.cc´, ´.hh´, ´.cpp´, ´.cxx´, ´.hxx´, ´.hpp´, ´.C´, ´.H´ sont supposés être des fichiers source C++. Les fichiers dont le nom se termine par ´.php´, ´.php3´, ´.phtml´ sont supposés être des fichiers source PHP. Les autres fichiers sont supposés être des fichiers texte. Gtags ne traite pas les fichiers binaires.

Si ´gtags.files´ existe dans le répertoire courant ou si un fichier est spécifié par l'option -f, les fichiers cibles sont limités par celui-ci. Les lignes commençant par ´. ´ sont des commentaires.

OPTIONS

Les options suivantes sont disponibles :

--accept-dotfiles
Accepte les fichiers et répertoires dont le nom commence par un point. Par défaut, gtags les ignore.
-c, --compact
Crée ´GTAGS´ au format compact. Cette option n'influence pas ´GRTAGS´, car il est toujours créé au format compact.
-C, --directory dir
Change de répertoire avant d'effectuer tout le travail, y compris l'analyse des paramètres. Cette option est ignorée dans GTAGS_OPTIONS. Veuillez la spécifier directement sur la ligne de commande.
--config[=nom]
Affiche la valeur de la variable de configuration nom. Si nom n'est pas spécifié, affiche tous les noms et valeurs. De plus, vous pouvez vous référer au nom du répertoire où le système est installé comme variables en lecture seule : bindir, libdir, datadir, localstatedir et sysconfdir.
-d, --dump fichier-tag
Affiche un fichier de tags sous forme de texte sur la sortie standard. Le format de sortie est 'clé<tab>données'. Ceci est pour le débogage.
--explain
Explique la gestion des fichiers.
-f, --file fichier
Donne une liste de candidats pour les fichiers cibles. Les fichiers qui ne sont pas dans la liste sont ignorés. L'argument fichier peut être défini à ´-´ pour accepter une liste de fichiers depuis l'entrée standard. Les noms de fichiers doivent être séparés par un saut de ligne. Pour créer la liste, vous pouvez utiliser find(1), qui dispose d'options riches pour sélectionner les fichiers.
--gtagsconf fichier
Définit la variable d'environnement GTAGSCONF à fichier.
--gtagslabel label
Définit la variable d'environnement GTAGSLABEL à label.
--help
Affiche un message d'utilisation.
-I, --idutils
En plus des fichiers de tags, crée une base de données d'IDs pour idutils(1).
-i, --incremental
Met à jour les fichiers de tags de manière incrémentielle. Il est préférable d'utiliser global(1) avec la commande -u.
-O, --objdir
Utilise le répertoire d'objets de style BSD comme emplacement des fichiers de tags. Si GTAGSOBJDIRPREFIX est défini et que le répertoire ´$GTAGSOBJDIRPREFIX´ existe, gtags crée le répertoire ´$GTAGSOBJDIRPREFIX/<répertoire courant>´ et y crée les fichiers de tags. Bien que vous puissiez utiliser MAKEOBJDIRPREFIX à la place de GTAGSOBJDIRPREFIX, celui-ci est obsolète. Si chemin-db est spécifié, cette option est ignorée.
--single-update fichier
Met à jour les fichiers de tags pour un seul fichier. Il est considéré que fichier a été ajouté, mis à jour ou supprimé, et qu'il n'y a aucun changement dans les autres fichiers. Cette option implique l'option -i.
--skip-unreadable
Ignore les fichiers illisibles.
--skip-symlink [=type]
Ignore les liens symboliques. Si type est 'f', ignore seulement les liens symboliques de fichiers, sinon si 'd', ignore seulement les liens symboliques de répertoires. La valeur par défaut de type est 'a' (tous les liens symboliques).
--sqlite3
Utilise l'API Sqlite 3 pour créer les fichiers de tags. Par défaut, l'API BSD/DB 1.85 est utilisée. Pour utiliser cette option, vous devez invoquer le script configure avec --with-sqlite3 pendant la phase de compilation.
--statistics
Affiche des informations statistiques.
-q, --quiet
Mode silencieux.
-v, --verbose
Mode verbeux.
--version
Affiche le numéro de version.
-w, --warning
Affiche les messages d'avertissement.
chemin-db
Le répertoire dans lequel les fichiers de tags sont générés. La valeur par défaut est le répertoire courant.

EXEMPLES

$ ls -F
Makefile      src/    lib/
$ gtags -v
$ global -x main
main              10 src/main.c  main (argc, argv) {

FICHIERS

´GTAGS´
Fichier de tags pour les définitions.
´GRTAGS´
Fichier de tags pour les références.
´GPATH´
Fichier de tags pour les fichiers source.
´gtags.conf´, ´$HOME/.globalrc´
Données de configuration pour GNU Global. Voir gtags.conf(5).
´gtags.files´
La liste des candidats pour les fichiers cibles.
´.notfunction´
La liste des symboles qui ne sont pas une définition. Si ce fichier existe dans le répertoire racine du projet, gtags ne considère pas les symboles listés dans ce fichier comme des définitions. Les lignes commençant par ';' sont des lignes de commentaire.

ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de gtags :

GTAGSCACHE
La taille du cache de l'arbre B. La valeur par défaut est 50000000 (octets).
GTAGSCONF
Fichier de configuration.
GTAGSFORCECPP
Si cette variable est définie, chaque fichier dont le suffixe est ´.h´ est analysé de force par l'analyseur C++ intégré. Ne définissez pas cette variable si vous utilisez des analyseurs externes. Cette variable et l'analyseur C++ intégré sont obsolètes.
GTAGSFORCEENDBLOCK
Si cette variable est définie, chaque } à la première colonne marque la fin d'un bloc de niveau 0.
GTAGSLABEL
Étiquette de configuration. La valeur par défaut est &

ENVIRONNEMENT

Les variables suivantes peuvent affecter le comportement de gtags.

GTAGSLOGGING
Si cette variable est définie, ´$GTAGSLOGGING´ est utilisée comme nom de chemin d'un fichier journal. Il n'y a pas de valeur par défaut.
GTAGS_COMMANDLINE
Cette variable ne peut être référencée qu'à partir du hook (voir gtags_hook). Gtags définit sa propre ligne de commande effective dans cette variable avant d'appeler le hook. Chaque argument est séparé par des espaces blancs, et les espaces blancs réels sont représentés par '%20'. Ceci est en lecture seule.
GTAGS_OPTIONS
La valeur de cette variable est insérée dans l'en-tête des arguments.
GTAGSOBJDIR
Si cette variable est définie, elle est utilisée comme nom pour l'objdir de style BSD. La valeur par défaut est ´obj´. Bien que vous puissiez utiliser MAKEOBJDIR à la place de GTAGSOBJDIR, cette dernière est dépréciée.
GTAGSOBJDIRPREFIX
Si cette variable est définie, elle est utilisée comme préfixe pour l'objdir de style BSD. La valeur par défaut est ´/usr/obj´. Bien que vous puissiez utiliser MAKEOBJDIRPREFIX à la place de GTAGSOBJDIRPREFIX, cette dernière est dépréciée.
TMPDIR
L'emplacement utilisé pour stocker les fichiers temporaires. La valeur par défaut est ´/tmp´.

CONFIGURATION

Les variables de configuration suivantes affectent l'exécution de gtags. Vous pouvez voir la valeur par défaut pour chaque variable avec l'option --config.

gtags_parser (liste séparée par des virgules)
Spécifie le mappage entre les noms de langages et les analyseurs (parsers) plug-ins. Chaque partie délimitée par la virgule se compose d'un nom de langage, d'un deux-points, du chemin de l'objet partagé, d'un deux-points optionnel suivi d'un nom de fonction. Si le nom de la fonction n'est pas spécifié, 'parser' est supposé. À titre d'exception spéciale, gtags collecte les valeurs de plusieurs variables gtags_parser. Pour ces mappages, la première correspondance est adoptée.
gtags_hook (ligne de commande)
Spécifie une ligne de commande qui doit être exécutée au début de gtags après le chargement du fichier de configuration. Vous pouvez utiliser ce hook pour mettre à jour ´gtags.files´ dynamiquement. Le préfixe "./" signifie toujours le répertoire racine du projet, car gtags est toujours invoqué à cet endroit.

Ce hook est ignoré lorsque les options suivantes sont spécifiées : --version, --help, --config, --dump.

icase_path (booléen)
Ignore les distinctions de casse dans le chemin. La vérification des suffixes est affectée par cette capacité.
langmap (liste séparée par des virgules)
Mappage des langages. Chaque mappage séparé par des virgules se compose d'un nom de langage, d'un deux-points et d'une liste d'extensions de fichiers. Vous pouvez spécifier un motif glob entouré de parenthèses au lieu d'une extension pour les fichiers sans extensions (par exemple, Make:([Mm]akefile).mak.mk). À titre d'exception spéciale, gtags collecte les valeurs de plusieurs variables langmap. Pour ces mappages, la première correspondance est adoptée. Le mappage par défaut est :
´c:.c.h,yacc:.y,asm:.s.S,java:.java,cpp:.c++.cc.hh.cpp.cxx.hxx.hpp.C.H,php:.php.php3.phtml´.
skip (liste séparée par des virgules)
Gtags ignore les fichiers et les répertoires qui sont indiqués dans cette liste. À titre d'exception spéciale, gtags collecte les valeurs de plusieurs variables skip. Si la valeur se termine par ´/´, elle est considérée comme un répertoire et gtags ignore tous les fichiers qui s'y trouvent. La valeur peut inclure des motifs glob (*, ?, [...], [!...], [^...]).

Si la valeur commence par ´/´, elle est considérée comme un nom de chemin relatif par rapport au répertoire racine du projet. Vous ne pouvez pas utiliser de motifs glob pour un nom de chemin. Cependant, cette directive est obsolète et n'est pas recommandée. À la place, vous pouvez utiliser l'option -f qui peut être combinée avec find(1). Comme find(1) dispose d'options riches pour sélectionner des fichiers, vous pouvez tout faire. De plus, cette technique peut également être appliquée à tout autre système d'indexation comme ctags(1), cscope(1), etc.

La liste de mise à l'écart est également effective lorsque vous utilisez l'option -f ou le fichier ´gtags.files´.

EXEMPLES

#
# Il existe plusieurs façons d'utiliser l'analyseur (parser) plug-in Universal Ctags.
#
$ gtags --gtagsconf=/usr/local/share/gtags/gtags.conf --gtagslabel=universal-ctags
$ gtags --explain
ou
$ export GTAGSCONF=/usr/local/share/gtags/gtags.conf
$ export GTAGSLABEL=universal-ctags
$ gtags --explain
ou
# Dans votre projet
$ cp /usr/local/share/gtags/gtags.conf .
$ vi gtags.conf		# par défaut : tc=native => par défaut : tc=universal-ctags
$ gtags --explain

DIAGNOSTICS

Gtags se termine avec une valeur non nulle si une erreur s'est produite, 0 sinon.

Notez que les fichiers créés par gtags avec un code de sortie non nul doivent être considérés comme corrompus.

BOGUE

´GTAGS´ et ´GRTAGS´ sont très volumineux. Avant d'utiliser cette commande, vérifiez l'espace de votre disque.

Le support du langage assembleur est loin d'être complet. Il extrait seulement ENTRY() et ALTENTRY() du fichier source. Probablement valide uniquement pour les sources des noyaux FreeBSD et Linux.

Le support C++ est déprécié.

Il n'y a pas de contrôle de concurrence pour les fichiers d'index.
