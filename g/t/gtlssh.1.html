DESCRIPTIO

N

Le programme gtlssh se connecte à un serveur distant, authentifie le serveur distant à l'aide de SSL, puis s'authentifie auprès du

serveur.

gtlsshd tentera d'abord une connexion SCTP et

retombera sur TCP si
cela ne fonctionne pas.

AUTHENTIFICATION DE

L'HÔTE

Après la connexion, l'hôte est d'abord validé à l'aide de SSL standard. Les clés utilisées pour la validation se trouvent par défaut dans $HOME/.gtlssh/server_certs. Si la clé donnée n'est pas reconnue, l'utilisateur est invité avec l'empreinte du certificat lui demandant s'il souhaite accepter le

certificat.

Si l'utilisateur accepte le certificat, il est alors ajouté dans le répertoire par défaut. Sinon, la connexion est

terminée.

Les certificats sont stockés sous la forme « <nom d'hôte>,<port>.crt » et « <adresse ip>,<port>.crt ». Les deux sont créés pour une

connexion (sauf si la connexion se fait avec une adresse IP). Une connexion est vérifiée comme correspondant aux deux entrées ; si le c
ertificat du fichier ne correspond pas au certificat de l'extrémité distante, la connexion est terminée et l'utilisateur est informé.

AUTHENTIFICATION DE

L'UTILISATEUR

Si l'authentification de l'hôte réussit, gtlssh s'authentifie avec une clé et un certificat. Ces fichiers sont récupérés par défaut depuis $HOME/.gtlssh/keycerts sous la forme <hôte>[,<port>].key et <hôte>[,<port>].crt. Si la forme avec l'hôte et le port existe, elle est utilisée. Sinon, si la forme avec seulement l'hôte existe, elle est utilisée. Sinon, elle utilise par défaut $HOME/.gtlssh/default.key et $HOME/.gttlssh/default.

crt.

L'extrémité distante cherche le certificat dans $HOME/.gtlssh/all

owed_certs. Si l'extrémité distante ne possède pas le certifi
cat présenté, l'authentification par mot de passe est tentée.

MODE

INTERACTIF

Si stdin pour gtlssh est un tty et qu'aucun programme n'est donné à exécuter, alors la connexion est une connexion interactive. Tout type de délai dans le traitement d'E/S est désactivé, et le terminal local est utilisé pour les E/S et est mis en mode

brut

En mode non interactif, le côté local utilise stdio pour les E/S locales

et le délai de traitement des E/S sur le côté réseau n'est pas désactivé. Cel
a est utile pour les programmes transférant des données sur la connexion.

ÉCHAPPEMEN

TS

Si le caractère d'échappement est reçu de l'utilisateur, le caractère n'est pas transféré et le programme attend un autre caractère. Si l'autre caractère est également le caractère d'échappement, un seul caractère d'échappement est envoyé. Si l'autre caractère n'est pas reconnu comme un échappement valide, il est ignoré et non transféré. Les majuscules et minuscules sont

équivalentes.

Les caractères d'échappement sont

:
q
Quitter le
programme.
b
Envoyer une interruption à io2. Ignoré si io2 ne supporte pas
l'interruption.
d
Vider les données série pour io2. Ignoré si io2 n'est pas compatible
RFC2217.
s
Définir le débit (baud) du port série pour io2. Ignoré si io2 n'est pas compatible RFC2177. Après cela, la vitesse du port série doit être saisie, terminée par un retour à la ligne. Les vitesses invalides sont ignorées, utilisez escchar-d pour savoir si vous l'avez défini
correctement.
n, o,
e
Définir la parité sur io2 à none (aucune), odd (impaire) ou even (paire). Ignoré si io2 n'est pas compatible
RFC2217.
7,

RFC2217.
