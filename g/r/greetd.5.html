NOM

greetd - fichier de configuration

DESCRIPTION

greetd utilise un fichier de configuration TOML simple pour définir son comportement.

CONFIGURATION

La configuration est divisée en sections. Les sections sont délimitées comme suit :

[nom_section]
cle_config = valeur

Les clés de configuration peuvent être des littéraux entiers ou des chaînes délimitées par des guillemets. Les sections de configuration sont décrites ci-dessous.

terminal

Cette section contient la configuration du terminal.

vt = num|"next"|"current"

Le VT sur lequel s'exécuter. Peut être le numéro d'un VT spécifique, "next" pour sélectionner le prochain VT disponible, ou "current" pour rester là où greetd a été démarré. Le VT spécifique est évalué au démarrage et ne change pas pendant l'exécution de greetd.

Si vous utilisez le VT actuel ou un VT spécifique, vous devez vous assurer qu'il n'y a pas d'autres utilisateurs de ce VT. Si vous utilisez systemd avec autovt et getty, l'évitement des conflits peut être géré dans l'unité de service avec "Conflicts=getty@ttyN.service", où N est le numéro du VT.

L'utilisation d'un VT spécifique avec une évitement des conflits approprié est recommandée.

switch = true|false

Indique s'il faut basculer vers vt ou non.

Si défini sur false et que vt n'est pas le VT actif actuel, greetd attendra que vt devienne actif avant de faire quoi que ce soit, y compris le lancement du greeter.

Si défini sur true, greetd basculera le VT actuel vers vt.

La valeur par défaut est true.

general

Cette section contient la configuration générale qui ne rentre pas dans d'autres sections et ne mérite pas sa propre section.

source_profile = true|false

Indique s'il faut sourcer ~/.profile et /etc/profile s'ils sont présents lors de l'exécution de commandes. La valeur par défaut est true.

runfile = chemin-vers-runfile

Emplacement du fichier de lancement (runfile) de greetd qui est créé lors de la première exécution pour empêcher la session initiale d'être relancée à la fin de la session ou lors du redémarrage de greetd.

Ce fichier doit se trouver dans un emplacement qui est effacé lors d'un redémarrage.

default_session

Cette section décrit la session par défaut, également appelée le greeter.

command = ligne-de-commande

La ligne de commande que greetd exécutera pour démarrer la session par défaut, par exemple "agreety -c sway". La session par défaut est automatiquement lancée lorsqu'aucune autre session n'est en cours d'exécution, par exemple lorsqu'une session utilisateur se termine ou lorsque greetd est lancé initialement sans session initiale configurée.

La ligne de commande est exécutée par sh(1), et accepte donc la syntaxe standard du shell POSIX.

Consultez greetd-ipc(7) pour savoir comment un greeter peut créer des sessions.

user = utilisateur

L'utilisateur à utiliser pour exécuter le greeter. La valeur par défaut est "greeter".

initial_session

Cette section facultative décrit la session initiale, communément appelée "auto-login".

La session initiale ne sera exécutée qu'à la première exécution de greetd depuis le démarrage, afin de garantir que la déconnexion fonctionne correctement et d'éviter les problèmes de sécurité lorsque greetd ou le greeter se terminent. Ceci est vérifié par la présence du fichier de lancement.

command = ligne-de-commande

La ligne de commande que greetd exécutera pour démarrer la session initiale, par exemple "sway". La session initiale sera lancée exactement une fois lorsque greetd sera lancé initialement.

La ligne de commande est exécutée par sh(1), et accepte donc la syntaxe standard du shell POSIX.

user = utilisateur

L'utilisateur à utiliser pour exécuter la session initiale.

EXEMPLES

Configuration normale avec agreety et sway

[terminal]
vt = 1
[default_session]
command = "agreety -c sway"

Auto-connexion

[terminal]
vt = 1
[default_session]
command = "agreety -c sway"
[initial_session]
command = "sway"
user = "john"
