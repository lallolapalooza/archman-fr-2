DESCRIPTIO

N

L'utilitaire grep recherche dans les fichiers d'entrée, en sélectionnant les lignes correspondant à un ou plusieurs motifs ; les types de motifs sont contrôlés par les options spécifiées. Les motifs sont spécifiés par l'option -e, l'option -f, ou l'opérande liste_de_motifs. La valeur de la liste_de_motifs doit se composer d'un ou plusieurs motifs séparés par des caractères <newline> ; le contenu du fichier_de_motifs doit se composer d'un ou plusieurs motifs terminés par un caractère <newline>. Par défaut, une ligne d'entrée est sélectionnée si un motif, traité comme une expression rationnelle de base (BRE) complète telle que décrite dans le volume des Définitions de base de POSIX.1‐2017, Section 9.3, Expressions rationnelles de base, correspond à une partie de la ligne à l'exclusion du <newline> terminal ; une BRE nulle correspond à chaque ligne. Par défaut, chaque ligne d'entrée sélectionnée est écrite sur la sortie

standard.

La correspondance des expressions rationnelles est basée sur des lignes de texte. Puisqu'un <newline> sépare ou termine des motifs (voir les options -e et -f ci-dessous), les expressions rationnelles ne peuvent pas contenir un <newline>. De même, puisque les motifs sont comparés à des lignes indiv

iduelles (à l'exclusion des caractères <newline> terminaux) de l'entrée
, un motif ne peut pas correspondre à un <newline> trouvé dans l'entrée.

OPTION

S

L'utilitaire grep doit se conformer au volume des Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des

utilitaires.

APERÇU

Le grep utility recherche dans la liste des fichiers spécifiés des lignes contenant une correspondance avec une expression rationnelle donnée.

SYNTAXE

grep [options] motif_liste [fichier...]

grep [options] -e motif_liste [-e motif_liste...] [fichier...]

grep [options] -f motif_fichier [-f motif_fichier...] [fichier...]

DESCRIPTION

Le grep utility lit les lignes de l'entrée standard ou des fichiers spécifiés, en sélectionnant les lignes qui correspondent à un modèle spécifié et en écrivant les lignes sélectionnées sur la sortie standard. Les lignes sont sélectionnées si elles contiennent des correspondances pour toutes les expressions rationnelles spécifiées.

Les expressions rationnelles sont décrites dans Regular Expressions. Les options suivantes sont disponibles :

-A nombre
Imprimer également nombre lignes après chaque ligne correspondante. Sauf si nombre est négatif, auquel cas il n'imprime aucune ligne après chaque ligne correspondante. Cette option est incompatible avec l'option -B ou -C.
-B nombre
Imprimer également nombre lignes avant chaque ligne correspondante. Sauf si nombre est négatif, auquel cas il n'imprime aucune ligne avant chaque ligne correspondante. Cette option est incompatible avec l'option -A ou -C.
-C nombre
Imprimer également nombre lignes avant et après chaque ligne correspondante. Sauf si nombre est négatif, auquel cas il n'imprime aucune ligne avant ou après chaque ligne correspondante. Cette option est incompatible avec l'option -A ou -B.
-c
Ne pas imprimer les lignes sélectionnées ; au lieu de cela, imprimer un résumé de la forme suivante :
"%s\n", <nombre d'occurrences>
-e motif_liste
Spécifier le modèle à utiliser dans la recherche. Cette option est utile pour spécifier plusieurs modèles ou lorsque le modèle commence par un tiret. L'argument motif_liste est une ou plusieurs expressions rationnelles séparées par des caractères de saut de ligne. Le comportement est indéfini si motif_liste contient un caractère de saut de ligne nul.
-F
Interpréter motif_liste comme une liste de chaînes fixes et non comme une expression rationnelle. Chaque chaîne est séparée dans motif_liste par un caractère de saut de ligne. Le comportement est indéfini si motif_liste contient un caractère de saut de ligne nul.
-f motif_fichier
Lire les expressions rationnelles à partir du fichier spécifié, une par ligne. Le comportement est indéfini si l'un des motifs lus à partir du fichier contient un caractère de saut de ligne nul. Si motif_fichier est spécifié comme -, lire les motifs à partir de l'entrée standard.
-H
Imprimer le nom du fichier d'origine avant chaque ligne sélectionnée. Cela est le comportement par défaut lorsque plusieurs fichiers sont spécifiés.
-h
Supprimer le préfixe du nom de fichier des lignes de sortie. C'est le comportement par défaut lorsque seulement un fichier est spécifié.
-i
Ignorer la casse lors de la comparaison des expressions rationnelles et des lignes d'entrée.
-l
Imprimer uniquement les noms des fichiers qui contiennent des correspondances. Sauf si une erreur est rencontrée, le statut de sortie sera 0, même si aucun fichier n'a été trouvé.
-n
Préfixer chaque ligne de sortie par son numéro de ligne dans le fichier d'origine.
-q
Mode silencieux. Ne pas écrire sur la sortie standard. Quitter dès qu'une correspondance est trouvée. Le statut de sortie est 0 si une ligne est trouvée, même si des erreurs sont rencontrées.
-R
Rechercher de manière récursive dans les sous-répertoires. Par défaut, les liens symboliques sont suivis, mais pas les répertoires référencés par les liens symboliques. Si l'option -L est également spécifiée, tous les liens symboliques seront suivis.
-s
Supprimer les messages d'erreur concernant l'existence ou la lisibilité des fichiers. Cette option est fournie pour la compatibilité avec les versions précédentes.
-v
Inverser la correspondance ; sélectionner les lignes qui ne correspondent pas au modèle.
-w
Sélectionner uniquement les lignes dans lesquelles le motif forme des mots entiers. Un mot entier est défini comme une séquence de caractères de lettres, de chiffres et de trait de soulignement, délimitée par des caractères non mots ou par le début ou la fin de la ligne.
-x
Sélectionner uniquement les lignes qui correspondent exactement au modèle.

L'une des options suivantes est requise :

--
Indique la fin des options. Le motif peut commencer par un tiret.

LC_COLLATE

Déterminer la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

EVENEMENTS ASYNCHRONES

Par défaut.

STDOUT

Si l'option -l est activée, ce qui suit sera écrit pour chaque fichier contenant au moins une ligne d'entrée sélectionnée :

"%s\n", <fichier>

Sinon, si plus d'un argument fichier apparaît, et que -q n'est pas spécifié, l'utilitaire grep préfixera chaque ligne de sortie par :

"%s:", <fichier>

Le reste de chaque ligne de sortie dépendra des autres options spécifiées :

*
Si l'option -c est activée, le reste de chaque ligne de sortie contiendra :
"%d\n", <compteur>
*
Sinon, si -c n'est pas activé et que l'option -n est activée, ce qui suit sera écrit sur la sortie standard :
"%d:", <numéro de ligne>
*
Enfin, ce qui suit sera écrit sur la sortie standard :
"%s", <contenu de la ligne sélectionnée>

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

CONSEQUENCES DES ERREURS

Si l'option -q est spécifiée, le statut de sortie sera zéro si une ligne d'entrée est sélectionnée, même si une erreur a été détectée. Sinon, les actions par défaut seront effectuées.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Il faut faire attention lors de l'utilisation de caractères dans motif_liste qui peuvent également avoir une signification pour l'interpréteur de commandes. Il est plus sûr d'encapsuler tout l'argument motif_liste entre guillemets simples :

'...'

L'option -e motif_liste a le même effet que l'opérande motif_liste, mais est utile lorsque motif_liste commence par le délimiteur <tiret-moins>. Elle est également utile lorsqu'il est plus pratique de fournir plusieurs motifs comme arguments séparés.

Plusieurs options -e et -f sont acceptées et grep utilise tous les motifs qui lui sont donnés lors de la mise en correspondance des lignes de texte d'entrée. (Notez que l'ordre d'évaluation n'est pas spécifié. Si une implémentation trouve une chaîne nulle comme motif, elle est autorisée à utiliser ce motif en premier, en faisant correspondre toutes les lignes, et à ignorer effectivement tout autre motif.)

L'option -q fournit un moyen facile de déterminer si un motif (ou une chaîne) existe ou non dans un groupe de fichiers. Lors de la recherche de plusieurs fichiers, elle offre une amélioration des performances (car elle peut s'arrêter dès qu'elle trouve la première correspondance) et nécessite moins de précautions de la part de l'utilisateur pour choisir l'ensemble de fichiers à fournir en tant qu'arguments (car elle sort zéro si elle trouve une correspondance même si grep a détecté une erreur d'accès ou de lecture sur les opérandes de fichier précédents).

Lors de l'utilisation de grep pour traiter des noms de chemin, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les noms de chemin peuvent contenir des séquences d'octets qui ne forment pas des caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire serait indéfini. Dans la locale POSIX, chaque octet est un caractère valide mono-octet, et donc ce problème est évité.

EXEMPLES

1.
Pour trouver toutes les occurrences du mot "Posix" (en ignorant la casse) dans le fichier text.mm et écrire avec les numéros de ligne :
grep -i -n posix text.mm
2.
Pour trouver toutes les lignes vides dans l'entrée standard :
grep ^$

ou :

grep -v .
3.
Les deux commandes suivantes impriment toutes les lignes contenant les chaînes "abc" ou "def" ou les deux :
grep -E 'abc|def'
grep -F 'abc
def'
4.
Les deux commandes suivantes impriment toutes les lignes correspondant exactement à "abc" ou "def" :
grep -E '^abc$|^def$'
grep -F -x 'abc
def'

RATIONALE

Ce grep a été amélioré d'une manière compatible ascendante pour fournir la fonctionnalité exacte des commandes historiques egrep et fgrep également. C'était l'intention claire des développeurs du standard de consolider les trois grep en une seule commande.

Les anciennes commandes egrep et fgrep sont susceptibles d'être prises en charge pendant de nombreuses années à venir en tant qu'extensions d'implémentation, permettant aux applications historiques de fonctionner sans modification.

Les implémentations historiques ignoraient généralement silencieusement toutes les options -e et -f spécifiées plusieurs fois, sauf une, mais n'étaient pas cohérentes quant à la spécification effectivement utilisée.

L'option -b a été omise de la section OPTIONS car les numéros de bloc sont définis par l'implémentation.

La restriction System V sur l'utilisation de - pour signifier l'entrée standard a été omise.

Une définition de l'action entreprise lorsqu'on reçoit une BRE ou une ERE nulle est spécifiée. C'est une condition d'erreur dans certaines implémentations historiques.

L'option -l indiquait précédemment que son utilisation était indéfinie lorsqu'aucun fichier n'était explicitement nommé. Ce comportement était historique et imposait une restriction inutile aux implémentations futures. Il a été supprimé.

La pratique historique de l'option -s de grep BSD est facilement reproduite en redirigeant la sortie standard vers /dev/null. L'option -s requise ici provient de System V.

L'option -x, historiquement disponible uniquement avec fgrep, est disponible ici pour toutes les versions non obsolètes.
