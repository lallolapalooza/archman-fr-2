GREPHISTORY(1) Documentation InterNetNews GREPHISTORY(1)

NOM

grephistory - Interroger la base de données d'historique INN

SYNTAXE

grephistory [-eilnqsv] [-f db] [message-id]

DESCRIPTION

grephistory interroge la base de données d'historique INN pour des informations sur le message-id spécifié. Si aucune option n'est donnée, le programme imprime le jeton de l'API de stockage de l'article correspondant, ou "/dev/null" si l'article est listé dans la base de données d'historique mais n'est pas stocké sur le serveur. Si le message-id ne peut pas être trouvé dans la base de données, grephistory imprimera "grephistory: not found" et quittera avec un statut non nul.

Assurez-vous d'échapper tout caractère spécial du message-id par rapport au shell. Les guillemets simples sont recommandés à cet effet, car de nombreux message-id contiennent des signes dollar.

OPTIONS

-e
Imprimer uniquement le jeton de stockage si l'article est stocké sur le système. (Autrement dit, supprimer la sortie "/dev/null" ou "not found" pour les articles manquants ou mémorisés.)
-f db
Interroger la base de données d'historique db plutôt que la base de données d'historique par défaut.
-i
Au lieu d'attendre un message-id sur la ligne de commande, grephistory lira une liste de message-id sur l'entrée standard, un par ligne. Les espaces blancs en début et fin de ligne sont ignorés, tout comme les lignes malformées. Il imprimera sur la sortie standard les message-id qui ne sont pas trouvés dans la base de données d'historique. Ceci est utilisé lors du traitement des messages de contrôle "ihave".
-l
Afficher la ligne entière de la base de données d'historique, plutôt que juste le jeton de l'API de stockage. Si le message-id est présent dans la base de données d'historique mais n'a pas de jeton d'API de stockage, grephistory n'imprime rien.
-n
Si le message-id est présent dans la base de données d'historique mais n'a pas de jeton d'API de stockage, imprimer "/dev/null" et quitter avec succès. Cela peut se produire si un article a été annulé ou a expiré, mais que les informations d'historique ont été conservées. C'est le comportement par défaut.
-q
Ne pas imprimer de message, mais quitter avec le statut approprié.
-s
Au lieu d'attendre un message-id sur la ligne de commande, grephistory lira une liste de message-id sur l'entrée standard, un par ligne. Les espaces blancs en début et fin de ligne sont ignorés, tout comme les lignes malformées. Il imprimera sur la sortie standard les jetons d'API de stockage pour tous les articles toujours disponibles, un par ligne. Cette option est utilisée lors du traitement des messages de contrôle "sendme".
-v
Imprimer le hachage du message-id à des fins de diagnostic, ainsi que toute autre information demandée. Cette option n'est pas utile avec -i ou -s.

EXEMPLES

Dans le cas où l'article demandé n'est pas listé dans la base de données d'historique :

% grephistory '<unknown.article@news.example.com>'
grephistory: not found
% grephistory -v '<unknown.article@news.example.com>'
grephistory: not found (hash is 501C66C22932BA91131186D7218201EB)

Dans le cas où l'article demandé est listé dans la base de données d'historique mais n'est pas stocké sur le serveur :

% grephistory '<remembered.article@news.example.com>'
/dev/null

Dans le cas où l'article demandé est stocké sur le serveur :

% grephistory '<87fxeaay1z.fsf@windlord.stanford.edu>'
@02014A2DD6231FCC00000000000000000000@
% grephistory -l '<87fxeaay1z.fsf@windlord.stanford.edu>'
[B6DDF69376E3CC199246CEC949B3ACAC]  1244517923~-~1244517912
  @02014A2DD6231FCC00000000000000000000@

Avec sm, nous pouvons récupérer l'article et obtenir sa date de publication :

% grephistory '<87fxeaay1z.fsf@windlord.stanford.edu>' \
    | sm | grep Date
Date: Mon, 08 Jun 2009 20:25:12 -0700
% convdate -dc 1244517912
Tue, 9 Jun 2009 03:25:12 -0000 (UTC)

Cela correspond au nombre enregistré dans l'historique comme date de publication.
