L'entrée de grops doit être au format produit par troff(1), décrit dans groff_out(5). De plus, les fichiers de description du périphérique et des polices pour le périphérique utilisé doivent satisfaire certaines exigences. La résolution du périphérique doit être un multiple entier de 72 fois le sizescale. Le fichier de description du périphérique doit contenir un format de papier valide ; voir groff_font(5). Chaque fichier de description de police

doit 
contenir unedirective
internalname
psname qui indique que
le nom PostScript de la police est

psname. Un fichier de description de police peut

aussi 
contenir unedirective

qui indi

forme
p

Les lignes commençant par # et les lignes vides sont ignorées. Le code de chaque caractère donné dans le fichier de description de police doit correspondre au code du caractère dans le fichier d'encodage, ou au code dans l'encodage par défaut de la police si la police PostScript n'est pas à réencoder. Ce code peut être utilisé avec la séquence d'échappement \N dans troff pour sélectionner le caractère, même s'il n'a pas de nom de glyphe groff. Chaque caractère dans le fichier de description de police doit exister dans la police PostScript, et les largeurs données dans le fichier de description de police doivent correspondre aux largeurs utilisées dans la police PostScript. grops suppose qu'un caractère avec un nom groff de space est blanc (ne fait aucune marque sur la page) ; il peut utiliser un tel caractère pour générer une sortie PostScript plus efficace et compacte. grops est

capable d'afficher tous les glyphes d'une police PostScript ; il n'est pas limité à 256 d'entre eux. enc-file (ou l'encodage par défaut si aucun fichier d'encodage n'est spécifié) définit simplement l'ordre des glyphes pour les 256 premiers caractères ; tous les autres glyphes sont accessibles avec des vecteurs d'encodage supplémentaires que grops produit à

la

volée. grops peut intégrer dans un document les polices nécessaires à son rendu ; ceci est cappelés « téléchargeables ». Ces polices doivent être au format PFA. Utilisez pfbtops(1) pour convertir une police de type 1 au format PFB. Les polices téléchargeables doivent être listées dans un fichier download contenant des lignes de la

forme 
psname
fichi
er où psname est le nom PostScript de la police, et fichier est le nom du fichier la contenant ; les lignes commençant par # et les lignes vides sont ignorées ; les champs peuvent être séparés par des tabulations ou des espaces. fichier est recherché en utilisant le même mécanisme que celui pour les fichiers de description de polices de groff. Le fichier download lui-même est également recherché en utilisant ce mécanisme ; actuellement, seul le premier fichier correspondant trouvé dans le chemin de recherche des descriptions de périphérique et de polices est utilisé.

Si le fichier contenant une police téléchargeable ou un document importé est conforme aux Conventions de Structuration de Documents d'Adobe, alors grops interprète les commentaires des fichiers de manière suffisante pour garantir que sa propre sortie est conforme. Il fournit également toutes les ressources de police nécessaires qui sont listées dans le fichier download ainsi que toutes les ressources de fichier nécessaires. Il est également capable de gérer les dépendances entre ressources. Par exemple, supposez que vous ayez une police téléchargeable appelée Garamond, et aussi une police téléchargeable appelée Garamond-Outline qui dépend de Garamond (typiquement elle serait définie pour copier le dictionnaire de police de Garamond et changer le PaintType), alors il est nécessaire que Garamond apparaisse avant Garamond-Outline dans le document PostScript. grops gère cela automatiquement à condition que le fichier de police téléchargeable pour Garamond-Outline indique sa dépendance sur Garamond par le biais des Conventions de Structuration de Documents, par exemple en commençant par les lignes

suivantes. 
%!PS-Adobe-3.0 Resource-Font
%%DocumentNeededResources: font Garam
ond %%EndComments %%IncludeResource: font Garamond Dans ce cas, à
la fois Garamond et Garamond-Outline devraient être listés dans le fichier download. Une police téléchargeable ne devrait pas inclure son propre nom dans un commentaire %%DocumentSuppliedResources.

grops n'interprète pas les commentaires %%DocumentFonts. Les commentaires %%DocumentNeededResources, %%DocumentSuppliedResources, %%IncludeResource, %%BeginResource, et %%EndResource (ou peut-être les anciens commentaires %%DocumentNeededFonts, %%DocumentSuppliedFonts, %%IncludeFont, %%BeginFont, et %%EndFont) devraient être

utilisés.

La couleur de trait et de remplissage par défaut est le noir. Pour les couleurs définies dans l'espace de couleur « rgb », setrgbcolor est utilisé ; pour « cmy » et « cmyk », setcmykcolor ; et pour « gray », setgray. setcmykcolor est une commande PostScript LanguageLevel 2 et n'est donc pas disponible sur certaines imprimantes plus

anciennes.

Commandes de contrôle du

périphérique

grops reconnaît les commandes de contrôle du périphérique produites par la séquence d'échappement \X, mais n'interprète que celles qui commencent par une étiquette «ps: »

.
\X'ps: execcode
'
Exécute les commandes PostScript arbitraires code. Le currentpoint PostScript est défini à la position de dessin de groff lorsque la séquence d'échappement \X est interprétée avant d'exécuter code. L'origine est au coin supérieur gauche de la page ; les coordonnées x augmentent vers la droite, et les coordonnées y vers le bas de la page. Une procédureu est définie qui convertit les unités de base de groff vers le système de coordonnées en vigueur (à condition que l'utilisateur ne change pas l'échelle). Par exemple, 
.nr x 1i
\X'ps: exec \nx u 0 rli
neto stroke' dessine une ligne
horizontale d'un pouce de long. code peut apporter des changements à l'état graphique, mais tout changement ne persiste qu'à la fin de la page. Un dictionnaire contenant les définitions spécifiées par les commandes def et mdef est au sommet de la pile de dictionnaires. Si votre code ajoute des définitions à ce dictionnaire, vous devriez allouer de l'espace pour elles en utilisant «\X'ps: mdef n». Toute définition ne persiste qu'à la fin de la page. Si vous utilisez la séquence d'échappement \Y avec un argument nommant une macro, code peut s'étendre sur plusieurs lignes. Par exemple, 
.nr x 1i
.de y
ps: exec
\nx u 0 rlineto
stroke
..
\Yy
est une autre façon de dessiner une ligne horizont
ale d'un pouce de long. Le simple antislash avant «nx »—la seule raison d'utiliser un registre lors de la définition de la macro «y »—est de convertir une dimension spécifiée par l'utilisateur «1i » en unités de base de groff qui sont à leur tour converties en unités PostScript avec la procédure u.

grops enveloppe le code PostScript spécifié par l'utilisateur dans un dictionnaire, rien de plus. En particulier, il ne commence et ne termine pas le code inséré avec save et restore respectivement. Cela doit être

fourni par l'utilis
ateur, si nécessaire.
\X'ps: filenom
'
C'est la même chose que la commande exec sauf que le code PostScript est lu depuis le fichier nom
.
\X'ps: defcode
'
Place une définition PostScript contenue dans code dans le prologue. Il devrait y avoir au plus une définition par commande \X. Les définitions longues peuvent être divisées sur plusieurs commandes \X ; tous les arguments code sont simplement joints ensemble séparés par des sauts de ligne. Les définitions sont placées dans un dictionnaire qui est automatiquement poussé sur la pile de dictionnaires lorsqu'une commande exec est exécutée. Si vous utilisez la séquence d'échappement \Y avec un argument nommant une macro, code peut s'étendre sur plusieurs
lignes.
\X'ps: mdefn code
'
Comme def, sauf que code peut contenir jusqu'à n définitions. grops a besoin de savoir combien de définitions code contient pour pouvoir créer un dictionnaire PostScript de taille appropriée pour les
contenir.
\X'ps: importfichier llx lly urx ury largeur[hauteur]
'
Importe un graphique PostScript depuis le fichier. Les arguments llx, lly, urx, et ury donnent la boîte englobante du graphique dans le système de coordonnées PostScript par défaut. Ils devraient tous être des entiers : llx et lly sont les coordonnées x et y du coin inférieur gauche du graphique ; urx et ury sont les coordonnées x et y du coin supérieur droit du graphique ; width et height sont des entiers donnant la largeur et la hauteur désirées en unités de base de grof
f du
graphique.
Le graphique est mis à l'échelle pour qu'il ait cette largeur et cette hauteur et translaté de sorte que le coin inférieur gauche du graphique est situé à la position associée à la commande \X. Si l'argument de hauteur est omis, il est mis à l'échelle uniformément le long des axes x et y de sorte qu'il ait la largeur
spécifiée.
Le contenu de la commande \X n'est pas interprété par troff, donc l'espace vertical pour l'image n'est pas automatiquement ajouté, et les arguments de largeur et de hauteur ne peuvent pas avoir d'indicateurs d'échelle
attachés.
Si le fichier PostScript respecte les Conventions de Structuration de Documents Adobe et contient un commentaire %%BoundingBox, alors la boîte englobante peut être extraite automatiquement à partir de l'entrée groff en utilisant la requête psbb
.
Voir groff_tmac(5) pour une description de la macro PSPIC qui fournit une interface de haut nive
au pratique pour l'inclu
sion d'images PostScript.

TrueType et autres formats de

police

Les polices TrueType peuvent être utilisées avec grops si elles sont d'abord converties au format Type 42, un enveloppement PostScript équivalent au format PFA décrit dans pfbtops(1). Plusieurs méthodes existent pour générer un enveloppement Type 42 ; certaines impliquent l'utilisation d'un interpréteur PostScript tel que Ghostscript — voir gs(1

).

Une approche consiste à utiliser FontForge, un éditeur de polices qui peut convertir la plupart des formats de polices vectorielles. Voici un exemple d'utilisation de la police Roboto Slab Serif avec groff. Plusieurs variables sont utilisées afin que vous puissiez plus facilement l'adapter à votre propre

script. 
MAP=/usr/share/groff/1.23.0/font/devps/generate/text.map
TTF=/usr/share/fonts/truetype/roboto/slab/RobotoSlab-Regular.ttf
BASE=$(basename "$TTF")
INT=${BASE%.ttf}
PFA=$INT.pfa
AFM=$INT.afm
GFN=RSR
DIR=$HOME/.local/groff/font
mkdir -p "$DIR"/devps
fontforge -lang=ff -c "Open(\"$TTF\");\
Generate(\"$DIR/devps/$PFA\");"
afmtodit "$DIR/devps/$AFM" "$MAP" "$DIR/devps/$GFN"
printf "$BASE\t$PFA\n" >> "$DIR/devps/downloa
d
"

fontforge et afmtodit peuvent générer des avertissements en fonction des attributs de la police. La procédure de test est

simple. 
printf ".ft RSR\nHell
o, world!\n" | groff
-F "$DIR" > hello.ps

Une fois que vous êtes satisfait que la police fonctionne, vous voudrez peut-être générer les styles apparentés disponibles (par exemple, Roboto Slab a aussi les styles « Bold », « Light » et « Thin ») et configurer GROFF_FONT_PATH dans votre environnement pour inclure le répertoire où vous conservez les polices générées afin que vous n'ayez pas à utiliser l'option -

F
.

Installation des

polices

Ce qui suit est un guide d'installation des polices étape par étape pour grops

.
•
Convertissez votre police en quelque chose que groff comprend. Il s'agit d'une police PostScript Type 1 au format PFA ou d'une police
PostScript Type 42, accompagnée d'un fi
chier AFM. Un fichier PFA commence comme suit. 
%!PS-AdobeFont-1.0:

Un fichier PFB contient également cett
e chaîne, précédée par quelques octets non imprimables. Si
votre police est au format PFB, utilisez le programme pfbtops(1) de groff pour la convertir en PFA. Pour les polices TrueType et autres formats de polices, nous recommandons fontforge, qui peut convertir la plupart des formats de polices vectorielles. Un fichier de police Type 42 commence comme suit. 
%!PS-TrueTypeFont

Ceci est un format d'enveloppement pour les polices TrueType. Les anciennes imprimantes P
ostScript pourraient ne pas les prendre en charge (c'est-à-dire qu'elles pourraient ne pas avoir d'interpr
éteur de polices TrueType intégré). Dans les étapes suivantes, nous considérerons l'utilisation de la police BrushScriptX-Italic de CTAN au format
PFA.
•
Convertissez le fichier AFM en un fichier de description de police groff avec le programme afmtodit
(1). Par
exemple, 
$ 
afmtodit BrushScriptX-Italic.afm text.map BSI
convertit le fichier Adobe Font Metric BrushScriptX-Italic.afm en le fichier de description de police groff BSI
.
Si vous avez une famille de polices qui fournit des styles régulier droit (romain), gras, italique et gras-italique (où « italique » peut être « oblique » ou « incliné »), nous recommandons d'utiliser les lettres R, B, I et BI, respectivement, comme suffixes au nom de famille de polices groff pour activer les fonctionnalités de sélection de famille et de style de groff. Un exemple est le support intégré de groff pour Times : le nom de la famille de polices est abrégé en T, et les noms de polices groff sont donc TR, TB, TI et TBI. Dans notre exemple, cependant, la police BrushScriptX n'est disponible qu'en un seul style,
italique.
•
Installez le(s) fichier(s) de description de police groff dans un sous-répertoire devps du chemin de recherche que groff utilise pour les descriptions de fichiers de périphériques et de polices. Voir l'entrée GROFF_FONT_PATH dans la section « Environnement » de troff(1) pour la valeur actuelle du chemin de recherche des polices. Bien que groff n'utilise pas directement les fichiers AFM, c'est une bonne idée de les stocker à côté de ses fichiers de description de

Anciennes

polices

Les versions de groff 1.19.2 et antérieures contenaient des descriptions d'un ensemble légèrement différent des 35 polices de base PostScript niveau 2 définies par Adobe. L'ancien ensemble a 229 glyphes et un plus grand ensemble de paires de crénage ; le plus récent en a 314 et inclut le glyphe Euro. Pour la rétrocompatibilité, ces anciennes descriptions de polices sont également installées dans le répertoire /usr/share/groff/1.23.0/oldfont/devps
