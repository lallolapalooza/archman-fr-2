Descriptio

n

Ce pilote de sortie GNU roff traduit la sortie de troff(1) en un format PCL5 adapté à une imprimante HP LaserJet 4. Normalement, grolj4 est invoqué par groff(1) lorsque ce dernier reçoit l'option «-T lj4 ». (Dans cette installation, ps est le périphérique de sortie par défaut.) Utilisez l'option -P de groff pour transmettre les options ci-dessus à grolj4. Si aucun argument fichier n'est donné, ou si fichier vaut « - », grolj4 lit le flux d'entrée standard. La sortie est écrite dans le flux de sortie

standard.

Police

s

Nominativement, toutes les imprimantes Hewlett-Packard LaserJet de série 4 et plus récentes possèdent les mêmes polices internes : 45 polices vectorielles et une police matricielle Lineprinter. Les polices vectorielles sont disponibles en tailles allant de 0,25 point à 999,75 points, par incréments de 0,25 point ; la police Lineprinter n'est disponible qu'en taille de 8,5

points.

Les fichiers de polices LaserJet inclus avec groff supposent que toutes les imprimantes depuis la LaserJet 4 sont identiques. Il existe cependant quelques différences entre les polices des imprimantes anciennes et plus récentes. L'imprimante LaserJet 4 utilisait la technologie Agfa Intellifont pour 35 de ses polices vectorielles internes ; les 10 autres polices vectorielles étaient de type TrueType. À partir des imprimantes LaserJet de série 4000 introduites en 1997, toutes les polices vectorielles internes sont de type TrueType. Le nombre de glyphes imprimables diffère légèrement entre les polices Intellifont et TrueType (généralement, les polices TrueType incluent plus de glyphes), et il existe de légères différences dans les métriques des glyphes. Les différences entre les modèles d'imprimantes sont décrites dans le PCL 5 Comparison Guide et le PCL 5 Comparison Guide Addendum (pour les imprimantes introduites depuis approximativement 2001)

.

Les imprimantes LaserJet référencent un glyphe par une combinaison d'un jeu de symboles de 256 glyphes et d'un index au sein de ce jeu de symboles. Beaucoup de glyphes apparaissent dans plus d'un jeu de symboles ; toutes les combinaisons de jeu de symboles et d'index qui référencent le même glyphe sont équivalentes. Pour chaque glyphe, hpftodit(1) parcourt une liste de jeux de symboles et sélectionne le premier jeu qui contient le glyphe. Le code d'impression généré par hpftodit est un entier qui encode une valeur numérique pour le jeu de symboles dans le(s) octet(s) de poids fort, et l'index dans l'octet de poids faible. Voir groff_font(5) pour une description complète du format de fichier de police ; les jeux de symboles sont décrits plus en détail dans le PCL 5 Printer Language Technical

Reference Manual.

Deux des polices vectorielles, Symbol et Wingdings, sont liées à des jeux de symboles de 256 glyphes ; les autres polices vectorielles, ainsi que la police Lineprinter, prennent en charge de nombreux jeux de symboles, suffisants pour permettre l'impression de plus de 600

glyphes.

Les métriques générées par hpftodit supposent que le fichier DESC contient les valeurs 1200 pour res et 6350 pour unitwidth, ou toute combinaison (p. ex., 2400 et 3175) pour laquelle res ×unitwidth = 7620000. Bien que les imprimantes HP PCL 5 LaserJet prennent en charge une résolution interne de 7200 unités par pouce, elles utilisent un entier signé sur 16 bits pour le positionnement ; si devlj4 doit prendre en charge le papier grand format américain (11 in × 17 in ; in = pouce), la résolution utilisable maximale est 32767 ÷ 17, soit 1927 unités par pouce, ce qui est arrondi à 1200 unités par pouce. Si la plus grande dimension de papier requise est plus petite (p. ex., 8,5 in × 11 in, ou A5), une res (et une unitwidth) plus grande peut être

spécifiée.

Les métriques de polices pour les polices Intellifont étaient fournies par des fichiers Tagged Font Metric (TFM) initialement développés par Agfa/Compugraphic. Les fichiers TFM fournis pour ces polices prenaient en charge plus de 600 glyphes et contenaient d'importantes listes de paires de

crénage.

Pour accommoder les développeurs qui s'étaient habitués aux fichiers TFM, HP a également fourni des fichiers TFM pour les 10 polices TrueType incluses dans la LaserJet 4. Les fichiers TFM pour les polices TrueType incluaient généralement moins d'informations que les TFM Intellifont, prenaient en charge moins de glyphes et, dans la plupart des cas, ne fournissaient aucune information de crénage. Au moment où l'imprimante LaserJet 4000 a été introduite, la plupart des développeurs avaient migré vers d'autres moyens d'obtenir les métriques de polices, et la prise en charge de nouveaux fichiers TFM était très limitée. Les fichiers TFM fournis pour les polices TrueType dans la LaserJet 4000 ne prennent en charge que le jeu de symboles Latin 2 (ISO 8859-2) et n'incluent aucune information de crénage ; par conséquent, ils ont peu de valeur pour tout autre document que les plus

rudimentaires.

Parce que les fichiers TFM Intellifont contiennent considérablement plus d'informations, ils sont généralement préférables aux fichiers TFM TrueType, même pour une utilisation avec les polices TrueType des imprimantes plus récentes. Les métriques des polices TrueType sont très proches, bien qu'identiques, de celles des anciennes polices Intellifont portant les mêmes noms. Bien que la plupart des sorties utilisant les métriques Intellifont avec les imprimantes plus récentes soient tout à fait acceptables, quelques glyphes peuvent ne pas s'imprimer comme prévu. Les différences dans les métriques des glyphes peuvent être particulièrement visibles avec les parenthèses, crochets et accolades composites utilisés par eqn(1). Un script, situé dans /usr/share/groff/1.23.0/font/devlj4/generate, peut être utilisé pour ajuster les métriques de ces glyphes dans la police spéciale « S » pour une utilisation avec les imprimantes qui ont toutes des polices

TrueType.

Au moment où HP a cessé de prendre en charge les fichiers TFM, seule la version 1.0 du standard Unicode était disponible. Par conséquent, de nombreux glyphes sans point de code assigné ont été a

ssignés par HP à la Zone d'utilisation privée (PUA). Les versions ultérieures du standard Unicode ont inclus des points de code en dehors de la PUA pour beaucoup de ces glyphes. Les fichiers
TFM TrueType fournis par HP utilisent les assignations PUA ; les fichiers TFM générés à partir de fichiers de polices TrueType plus récents nécessitent les valeurs Unicode ultérieures pour a
ccéder aux mêmes glyphes. Par conséquent, deux fichiers de correspondance différents peuvent être nécessaires : un pour les fichiers TFM fournis par HP, et un pour les fichiers TFM plus récents.
