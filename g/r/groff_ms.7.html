Titre

s

Utilisez les titres pour créer une structure hiérarchique pour votre document. The ms macros print headings in bold using the same font family and, by default, type size as the body text. Headings are available with and without automatic numbering. Text on input lines following the macro call becomes the heading's title. Call a paragraphing macro to end the heading text and start the section's content.

.NH[depth]
Set an automatically numbered heading. ms produces a numbered heading in the form a.b.c..., to any level desired, with the numbering of each depth increasing automatically and being reset to zero when a more significant depth is increased. «1» est la division la plus significative ou la plus grossière du document. Seules les valeurs non nulles sont produites. Si depth est omis, il est considéré comme 1. Si vous spécifiez depth de telle sorte qu'un écart ascendant se produise par rapport à l'appel NH précédent—c'est-à-dire que vous « sautez un niveau », comme avec «.NH 1» puis «.NH 3», groff ms émet un avertissement sur le flux d'erreur standard.
.NH Sheading-depth-index...
Alternativement, vous pouvez donner à NH un premier argument de «S», suivi d'entiers pour numéroter explicitement les niveaux de titre. La numérotation automatique ultérieure, si elle est utilisée, reprend en utilisant les indices spécifiés comme leurs prédécesseurs. Cette fonctionnalité est une extension de Berkeley.

After .NH is called, the assigned number is made available in the strings SN-DOT (as it appears in a printed heading with default formatting, followed by a terminating period) and SN-NO-DOT (with the terminating period omitted). These are GNU extensions.

You can control the style used to print numbered headings by defining an appropriate alias for the string SN-STYLE. By default, \*[SN-STYLE] is aliased to \*[SN-DOT]. If you prefer to omit the terminating period from numbers appearing in numbered headings, you may alias it to \*[SN-NO-DOT]. Any such change in numbering style becomes effective from the next use of .NH following redefinition of the alias for \*[SN-STYLE]. The formatted number of the current heading is available in \*[SN] (a feature first documented by Berkeley); this string facilitates its inclusion in, for example, table captions, equation labels, and .XS/.XA/.XE table of contents entries.

.SH[depth]
Set an unnumbered heading. The optional depth argument is a GNU extension indicating the heading depth corresponding to the depth argument of .NH. It matches the type size at which the heading is set to that of a numbered heading at the same depth when the \n[GROWPS] and \n[PSINCR] heading size adjustment mechanism is in effect.

The PSINCR register defines an increment in type size to be applied to a heading at a lesser depth than that specified in \n[GROWPS]. The value of \n[PSINCR] should be specified in points with the “p” scaling unit and may include a fractional component.

The GROWPS register defines the heading depth above which the type size increment set by \n[PSINCR] becomes effective. For each heading depth less than the value of \n[GROWPS], the type size is increased by \n[PSINCR]. Setting \n[GROWPS] to a value less than 2 disables the incremental heading size feature.

In other words, if the value of GROWPS register is greater than the depth argument to a .NH or .SH call, the type size of a heading produced by these macros increases by \n[PSINCR] units over \n[PS] multiplied by the difference of \n[GROWPS] and depth.

The \n[HORPHANS] register operates in conjunction with the NH and SH macros to inhibit the printing of isolated headings at the bottom of a page; it specifies the minimum number of lines of the subsequent paragraph that must be kept on the same page as the heading. If insufficient space remains on the current page to accommodate the heading and this number of lines of paragraph text, a page break is forced before the heading is printed. Any display macro call or tbl, pic, or eqn region between the heading and the subsequent paragraph suppresses this grouping.

Typeface and decoration

The ms macros provide a variety of ways to style text. Attend closely to the ordering of arguments labeled pre and post, which is not intuitive. Support for pre arguments is a GNU extension.

.B[text[post[pre]]]
Style text in bold, followed by post in the previous font style without intervening space, and preceded by pre similarly. Without arguments, ms styles subsequent text in bold until the next paragraphing, heading, or no-argument typeface macro call.
.R[text[post[pre]]]
As .B, but use the roman style (upright text of normal weight) instead of bold. Argument recognition is a GNU extension.
.I[text[post[pre]]]
As .B, but use an italic or oblique style instead of bold.
.BI[text[post[pre]]]
As .B, but use a bold italic or bold oblique style instead of upright bold. This is a Tenth Edition Research Unix extension.
.CW[text[post[pre]]]
As .B, but use a constant-width (monospaced) roman typeface instead of bold. This is a Tenth Edition Research Unix extension.
.BX[text]
Typeset text and draw a box around it. On terminal devices, reverse video is used instead. If you want text to contain space, use unbreakable space or horizontal motion escape sequences (\~, \space, \^, \|, \0, or \h).
.UL[text[post]]
Typeset text with an underline. post, if present, is set after text with no intervening space.
.LG
Set subsequent text in larger type (2 points larger than the current size) until the next type size, paragraphing, or heading macro call. You can specify this macro multiple times to enlarge the type size as needed.
.SM
Set subsequent text in smaller type (2 points smaller than the current size) until the next type size, paragraphing, or heading macro call. You can specify this macro multiple times to reduce the type size as needed.
.NL
Set subsequent text at the normal type size (\n[PS]).

When pre is used, a hyphenation control escape sequence \% that would ordinarily start text must start pre instead.

Indented regions

You may need to indent a region of text while otherwise formatting it normally. Indented regions can be nested.

.RS
Begin a region where headings, paragraphs, and displays are indented (further) by \n[PI].
.RE

Keeps, boxed keeps, and displays

On occasion, you may want to keep several lines of text, or a region of a document, together on a single page, preventing an automatic page break within certain boundaries. This can cause a page break to occur earlier than it normally would.

You can alternatively specify a floating keep: if a keep cannot fit on the current page, ms holds its contents and allows text following the keep (in the source document) to fill in the remainder of the current page. When the page breaks, whether by reaching the end or bp request, ms puts the floating keep at the beginning of the next page.

.KS
Begin a keep.
.KF
Begin a floating keep.
.KE
End (floating) keep.

As an alternative to the keep mechanism, the ne request forces a page break if there is not at least the amount of vertical space specified in its argument remaining on the page.

A boxed keep has a frame drawn around it.

.B1
Begin a keep with a box drawn around it.
.B2
End boxed keep.

Boxed keep macros cause breaks; if you need to box a word or phrase within a line, see the BX macro in section “Highlighting” above. Box lines are drawn as close as possible to the text they enclose so that they are usable within paragraphs. If you wish to place one or more paragraphs in a boxed keep, you may improve their appearance by calling .B1 after the first paragraphing macro, and by adding a small amount of vertical space before calling .B2.

If you want a boxed keep to float, you will need to enclose the .B1 and .B2 calls within a pair of .KF and .KE calls.

Displays turn off filling; lines of verse or program code are shown with their lines broken as in the source document without requiring br requests between lines. Displays can be kept on a single page or allowed to break across pages. The DS macro begins a kept display of the layout specified in its first argument; non-kept displays are begun with dedicated macros corresponding to their layout.

Begin (DS: kept) display indented by indent if specified, \n[DI] otherwise.

Fin de tout affichage.

La distance stockée dans \n[DD] est insérée avant et après chaque paire de macros d'affichage ; il s'agit d'une extension Berkeley. Dans groff ms, cette distance remplace toute distance inter-paragraphe adjacente ou tout espacement ultérieur avant un titre de section. Le registre DI est une extension GNU ; sa valeur est un retrait appliqué aux affichages créés avec .DS et .ID sans arguments, à “.DS I” sans argument de retrait, et aux équations définies avec “.EQ I”. Les modifications apportées à l'un ou l'autre registre prennent effet à la prochaine limite d'affichage.

Notes de bas de page

Une note de bas de page est généralement ancrée à un endroit du texte avec un marqueur, qui est un petit entier, un symbole ou un texte arbitraire spécifié par l'utilisateur.

\**
Placez un numéro automatique, un marqueur numérique de note de bas de page généré automatiquement, dans le texte. Chaque fois que cette chaîne est interpolée, le numéro qu'elle produit s'incrémente d'une unité. Les numéros automatiques commencent à 1. Il s'agit d'une extension Berkeley.

Entourez le texte de la note de bas de page avec les appels de macros FS et FE pour le placer au "pied" le plus proche disponible, ou en bas, d'une colonne de texte ou d'une page.

.FS [marker]
Début d'une note de bas de page. Le hook .FS-MARK (voir ci-dessous) est appelé avec l'argument marker fourni, qui est ensuite également placé au début du texte de la note de bas de page. Si marker est omis, le prochain numéro automatique en attente, mis en attente par l'interpolation de la chaîne *, est utilisé, et s'il n'y en a pas, rien n'est précédé.
.FE
Fin du texte de la note de bas de page.

groff ms fournit une macro hook, FS-MARK, pour les opérations déterminées par l'utilisateur à effectuer lorsque la macro FS est appelée. Elle reçoit les mêmes arguments que .FS elle-même. Par défaut, cette macro a une définition vide. .FS-MARK est une extension GNU.

Le texte des notes de bas de page est formaté comme les paragraphes, en utilisant des paramètres analogues. Les registres FI, FPD, FPS et FVS correspondent à PI, PD, PS et VS, respectivement ; FPD, FPS et FVS sont des extensions GNU.

Le registre FF contrôle le formatage des paragraphes de notes de bas de page numérotés automatiquement, et ceux pour lesquels .FS reçoit un argument marker, en bas d'une colonne ou d'une page comme suit.

0
Définit un numéro automatique, ou un argument marker FS spécifié, comme exposant (sur les périphériques de composition) ou entouré de crochets (sur les terminaux). Le paragraphe de note de bas de page est indenté comme avec .PP s'il y a un argument .FS ou un numéro automatique, et comme avec .LP sinon. C'est la valeur par défaut.
1
Comme 0, mais définit le marqueur comme du texte normal, et fait suivre un numéro automatique d'un point.
2
Comme 1, mais sans indentation (comme .LP).
3
Comme 1, mais définit le paragraphe de note de bas de page avec le marqueur suspendu (comme .IP).

En-têtes et pieds de page

Il existe plusieurs façons de produire des en-têtes et des pieds de page. L'une d'elles consiste à définir les chaînes LH, CH et RH pour définir les en-têtes gauche, central et droit, respectivement ; et LF, CF et RF pour définir les pieds de page gauche, central et droit. Cette approche suffit pour les documents qui ne distinguent pas les pages impaires et paires.

Une autre méthode consiste à appeler des macros qui définissent les en-têtes ou les pieds de page pour les pages impaires ou paires. Chaque macro de ce type prend un argument délimité séparant les textes d'en-tête ou de pied de page gauche, central et droit. Vous pouvez remplacer les apostrophes neutres (') montrées ci-dessous par n'importe quel caractère n'apparaissant pas dans le texte de l'en-tête ou du pied de page. Ces macros sont des extensions Berkeley.

.OH 'left'center'right'
.OF 'left'center'right'
.EH 'left'center'right'
.EF 'left'center'right'
Les macros OH et EH définissent les en-têtes pour les pages impaires (recto) et paires (verso), respectivement ; les macros OF et EF définissent les pieds de page pour celles-ci.

Avec l'une ou l'autre méthode, un signe de pourcentage % dans le texte de l'en-tête ou du pied de page est remplacé par le numéro de page actuel. Par défaut, ms ne place pas d'en-tête sur une page numérotée “1” (quel que soit son format de numéro).

.P1
Compose l'en-tête même sur la page 1. Pour être efficace, cette macro doit être appelée avant que le piège d'en-tête ne soit déclenché sur une page numérotée “1”. Il s'agit d'une extension Berkeley.

Pour une flexibilité encore plus grande, ms permet de redéfinir les macros appelées lorsque les pièges d'en-tête et de pied de page sont déclenchés. PT ("page trap") est appelé par ms lorsque l'en-tête doit être écrit, et BT ("bottom trap") lorsque le pied de page doit l'être. Le piège de position de page de groff que ms configure pour formater l'en-tête appelle également la macro HD (normalement indéfinie) après .PT ; vous pouvez définir .HD si vous avez besoin d'un traitement supplémentaire après la définition de l'en-tête. Le hook HD est une extension Berkeley. Toutes macros de ce type que vous redéfinissez (ou définissez) doivent implémenter toute spécialisation souhaitée pour les pages impaires, paires ou la première page numérotée.
