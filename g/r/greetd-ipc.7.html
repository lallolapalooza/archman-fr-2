NOM

greetd-ipc - Protocole IPC pour greetd

DESCRIPTION

Ceci détaille le protocole de communication interprocessus (IPC) pour greetd(1). Ce protocole IPC peut être utilisé pour créer et gérer des sessions sous greetd.

Le protocole IPC utilise un socket UNIX comme méthode de communication. Le chemin vers le socket est stocké dans la variable d'environnement GREETD_SOCK.

FORMAT DES MESSAGES ET DES RÉPONSES

Le format des messages et des réponses est le suivant :

<longueur-payload> <payload>
Où 
<longueur-payload> est un entier de 32 bits dans l'ordre des octets natif
<payload> est une chaîne JSON encodée en UTF-8.

Par exemple, l'envoi de la commande "create_session" ressemblerait au dump hexadécimal suivant :

00000000  2c 00 00 00 7b 22 74 79  70 65 22 3a 20 22 63 72  |,...{"type": "cr|
00000010  65 61 74 65 5f 73 65 73  73 69 6f 6e 22 2c 20 22  |eate_session", "|
00000020  75 73 65 72 6e 61 6d 65  22 3a 20 22 6d 65 22 7d  |username": "me"}|

MESSAGES

Requêtes

TYPE DE MESSAGE CHAMPS BUT
create_session username (string) Crée une session et initie une tentative de connexion pour l'utilisateur donné. La session est prête à être démarrée si une réponse de succès est retournée.
post_auth_message_response response (string, optionnel) Répond à un message d'authentification. Si le message était informatif (info, erreur), alors une réponse ne doit pas être définie dans ce message. La session est prête à être démarrée si une réponse de succès est retournée.
start_session cmd (tableau de chaînes), env (tableau de chaînes) Demande que la session soit démarrée en utilisant la ligne de commande fournie, ajoutant l'environnement fourni à celui créé par PAM. La session sera démarrée après la terminaison du processus greeter.
cancel_session Annule la session en cours de configuration.

Réponses

TYPE DE MESSAGE CHAMPS BUT
success Indique que la requête a réussi.
error error_type (enum sous forme de chaîne), description (string) Indique que la requête a échoué.
auth_message auth_message_type (enum sous forme de chaîne), auth_message (string) Indique qu'un message d'authentification doit être répondu pour continuer le flux d'authentification. Il n'y a pas de limites sur le nombre et le type de messages qui peuvent être requis pour que l'authentification réussisse, et un greeter ne doit faire aucune supposition sur ces messages. Doit être répondu avec soit post_auth_message_response, soit cancel_session.

Énumérations des types de messages d'authentification

TYPE DE MESSAGE D'AUTH BUT
visible Indique que l'entrée de l'utilisateur doit être visible lorsqu'il répond à cette question.
secret Indique que l'entrée de l'utilisateur doit être considérée comme secrète lorsqu'il répond à cette question.
info Indique que ce message est informatif, pas une question.
error Indique que ce message est une erreur, pas une question.

Énumérations des erreurs

TYPE D'ERREUR BUT
auth_error Indique que l'authentification a échoué. Ce n'est pas une erreur fatale, et est probablement causée par des identifiants incorrects. Gérer comme il convient.
error Une erreur générale. Voir la description de l'erreur pour plus d'informations.
