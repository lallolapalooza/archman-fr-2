Cela tendra à améliorer la performance des travaux, mais retardera l'allocation des ressources à ceux-ci. Si spécifié et qu'un travail n'est pas soumis avec l'option --gres-flags=enforce-binding, les cœurs identifiés seront préférés pour la planification avec chaque ressource générique. Si vous utilisez une carte avec la fonctionnalité Multi-Instance GPU, utilisez MultipleFiles à la place. File et MultipleFiles sont mutuellement exclusifs.

NOTE : File est requis pour tous les GRES de type gpu.

NOTE : Si vous spécifiez le paramètre File pour une ressource sur un nœud donné, l'option doit être spécifiée sur tous les nœuds et Slurm suivra l'attribution de chaque ressource spécifique sur chaque nœud. Sinon, Slurm suivra uniquement un décompte des ressources allouées plutôt que l'état de chaque fichier de périphérique individuel.

NOTE : Arrêtez un nœud avant de modifier le nombre d'enregistrements avec des paramètres File (par exemple, si vous souhaitez ajouter ou supprimer des GPU de la configuration d'un nœud). À défaut, tout job utilisant ces GRES sera interrompu.

NOTE : Lors de la spécification de File, Count est limité en taille (actuellement 1024) pour chaque nœud.

Flags
Indicateurs optionnels qui peuvent être spécifiés pour modifier le comportement configuré du GRES.

Les valeurs autorisées à l'heure actuelle sont :

CountOnly
N'essayez pas de charger un plugin du type GRES car ce GRES sera uniquement utilisé pour suivre les décomptes de GRES utilisés. Cela évite de tenter de charger un plugin inexistant qui pourrait affecter les systèmes de fichiers avec des opérations de métadonnées à latence élevée pour les fichiers inexistants.

NOTE : Si un gres a ce drapeau configuré, il est global, donc tous les autres nœuds avec ce gres auront ce drapeau implicite.

explicit
Si l'indicateur est défini, le GRES n'est pas alloué au job dans le cadre d'une allocation de nœud entier (--exclusive ou OverSubscribe=EXCLUSIVE défini sur la partition) sauf s'il a été explicitement demandé par le job.

NOTE : Si un gres a ce drapeau configuré, il est global, donc tous les autres nœuds avec ce gres auront ce drapeau implicite.

one_sharing
À utiliser sur un gres partagé. Si vous utilisez un gres partagé (mps) en plus d'un gres partageant (gpu), n'autorisez qu'un seul des gres partageant à être utilisé par le gres partagé. C'est le comportement par défaut pour MPS.

NOTE : Si un gres a ce drapeau configuré, il est global, donc tous les autres nœuds avec ce gres auront ce drapeau implicite. Ce drapeau n'est pas compatible avec all_sharing pour un gres spécifique.

all_sharing
À utiliser sur un gres partagé. C'est l'inverse de one_sharing et peut être utilisé pour permettre à tous les gres partageant (gpu) sur un nœud d'être utilisés pour un gres partagé (mps).

NOTE : Si un gres a ce drapeau configuré, il est global, donc tous les autres nœuds avec ce gres auront ce drapeau implicite. Ce drapeau n'est pas compatible avec one_sharing pour un gres spécifique.

nvidia_gpu_env
Définit la variable d'environnement CUDA_VISIBLE_DEVICES pour tous les GPU sur le(s) nœud(s) spécifié(s).
amd_gpu_env
Définit la variable d'environnement ROCR_VISIBLE_DEVICES pour tous les GPU sur le(s) nœud(s) spécifié(s).
intel_gpu_env
Définit la variable d'environnement ZE_AFFINITY_MASK pour tous les GPU sur le(s) nœud(s) spécifié(s).
opencl_env
Définit la variable d'environnement GPU_DEVICE_ORDINAL pour tous les GPU sur le(s) nœud(s) spécifié(s).
no_gpu_env
Ne définit aucune variable d'environnement spécifique aux GPU. Ceci est mutuellement exclusif avec tous les autres indicateurs liés à l'environnement.
Si aucun indicateur lié à l'environnement n'est spécifié, alors nvidia_gpu_env, amd_gpu_env, intel_gpu_env et opencl_env seront implicitement définis par défaut. Si AutoDetect est utilisé et que les indicateurs liés à l'environnement ne sont pas spécifiés, alors AutoDetect=nvml ou AutoDetect=nvidia définira nvidia_gpu_env, AutoDetect=rsmi définira amd_gpu_env, et AutoDetect=oneapi définira intel_gpu_env. Inversement, les indicateurs liés à l'environnement spécifiés remplaceront toujours AutoDetect.

Les indicateurs liés à l'environnement définis sur une ligne GRES seront hérités par la ligne GRES directement en dessous si aucun indicateur lié à l'environnement n'est spécifié sur cette ligne et si elle concerne le même nœud, le même nom et le même type. Les indicateurs liés à l'environnement doivent être identiques pour les GRES du même nœud, nom et type.

Notez qu'il existe un problème connu avec le runtime AMD ROCm où ROCR_VISIBLE_DEVICES est traité en premier, puis CUDA_VISIBLE_DEVICES est traité. Pour éviter les problèmes causés par cela, définissez Flags=amd_gpu_env pour les GPU AMD afin que seul ROCR_VISIBLE_DEVICES soit défini.

Links
Une liste séparée par des virgules de nombres identifiant le nombre de connexions entre cet appareil et d'autres appareils pour permettre le coscheduling des appareils mieux connectés. Il s'agit d'une liste ordonnée dans laquelle le nombre de connexions que cet appareil spécifique a avec l'appareil numéro 0 serait dans la première position, le nombre de connexions qu'il a avec l'appareil numéro 1 dans la deuxième position, etc. Un -1 indique l'appareil lui-même et un 0 indique aucune connexion. Si spécifié, alors cette ligne ne peut contenir qu'un seul appareil GRES (c'est-à-dire qu'elle ne peut contenir qu'un seul fichier via File).

Ceci est une valeur optionnelle et est généralement déterminée automatiquement si AutoDetect est activé. Un cas d'utilisation typique serait d'identifier les GPU ayant une connectivité NVLink. Notez que pour les GPU, le numéro mineur assigné par le système d'exploitation et utilisé dans le fichier de périphérique (c'est-à-dire le X dans /dev/nvidiaX) n'est pas nécessairement le même que le numéro/indice de périphérique. Le numéro de périphérique est créé en triant les GPU par ID de bus PCI, puis en les numérotant à partir du plus petit ID de bus. Voir https://slurm.schedmd.com/gres.html#GPU_Management

MultipleFiles
Chemin d'accès complet des fichiers de périphérique associés à une ressource. Les cartes graphiques utilisant la technologie Multi-Instance GPU (MIG) présenteront plusieurs fichiers de périphérique qui devraient être gérés comme une seule ressource générique. Les noms de fichiers peuvent être une liste séparée par des virgules ou peuvent inclure un suffixe de plage numérique (par exemple, MultipleFiles=/dev/nvidia[0-3]).

Arrêtez un nœud avant de modifier le nombre d'enregistrements avec le paramètre MultipleFiles, par exemple lors de l'ajout ou de la suppression de GPU de la configuration d'un nœud. À défaut, tout job utilisant ces GRES sera interrompu.

Lorsque vous n'utilisez pas de GPU avec la fonctionnalité MIG, utilisez File à la place. MultipleFiles et File sont mutuellement exclusifs.

Name
Nom de la ressource générique. Tout nom souhaité peut être utilisé. Le nom doit correspondre à une valeur dans GresTypes dans slurm.conf. Chaque ressource générique a un plugin optionnel qui peut fournir des fonctionnalités spécifiques à la ressource. Les ressources génériques qui incluent actuellement un plugin optionnel sont :
gpu
Processeur graphique
mps
Service Multi-Processus CUDA (MPS)
nic
Carte d'interface réseau
shard
Parties d'un gpu
NodeName
Une spécification optionnelle de NodeName peut être utilisée pour permettre l'utilisation d'un seul fichier gres.conf pour tous les nœuds de calcul d'un cluster en spécifiant le(s) nœud(s) auquel (auxquels) chaque ligne doit s'appliquer. La spécification NodeName peut utiliser une spécification de liste d'hôtes Slurm comme montré dans l'exemple ci-dessous.
Type
Une chaîne de caractères arbitraire optionnelle identifiant le type de ressource générique. Par exemple, cela pourrait être utilisé pour identifier un modèle spécifique de GPU, que les utilisateurs peuvent ensuite spécifier dans une demande de job. Pour que les modifications de l'option Type prennent effet avec un scontrol reconfig, tous les démons slurmd affectés doivent répondre au slurmctld. Sinon, un redémarrage de ces démons sera nécessaire.
estart of les démons slurmctld et slurmd est requis.

NOTE : Si vous utilisez la fonctionnalité d'auto-détection et que vous définissez le Type dans votre fichier gres.conf, le Type spécifié doit correspondre ou être une sous-chaîne de la valeur détectée, en utilisant un trait de soulignement à la place des espaces.

EXEMPLES

##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Définition des périphériques GPU avec support MPS, avec vérification de l'auto-détection
##################################################################
AutoDetect=nvml
Name=gpu Type=gtx560 File=/dev/nvidia0 COREs=0,1
Name=gpu Type=tesla  File=/dev/nvidia1 COREs=2,3
Name=mps Count=100 File=/dev/nvidia0 COREs=0,1
Name=mps Count=100  File=/dev/nvidia1 COREs=2,3
##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Remplace les valeurs par défaut du système et configure explicitement trois GPU
##################################################################
Name=gpu Type=tesla File=/dev/nvidia[0-1] COREs=0,1
# Name=gpu Type=tesla  File=/dev/nvidia[2-3] COREs=2,3
# NOTE : le périphérique nvidia2 est hors service
Name=gpu Type=tesla  File=/dev/nvidia3 COREs=2,3
##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Utilisation d'un seul fichier gres.conf pour tous les nœuds de calcul - méthode positive
##################################################################
## Spécification explicite des périphériques sur les nœuds tux0-tux15
# NodeName=tux[0-15]  Name=gpu File=/dev/nvidia[0-3]
# NOTE : le périphérique tux3 nvidia1 est hors service
NodeName=tux[0-2]  Name=gpu File=/dev/nvidia[0-3]
NodeName=tux3  Name=gpu File=/dev/nvidia[0,2-3]
NodeName=tux[4-15]  Name=gpu File=/dev/nvidia[0-3]
##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Utilisation de NVML pour collecter les informations de configuration des GPU
# pour tous les nœuds sauf un
##################################################################
AutoDetect=nvml
NodeName=tux3 AutoDetect=off Name=gpu File=/dev/nvidia[0-3]
##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Spécification de certains nœuds avec NVML, d'autres avec RSMI, et d'autres sans AutoDetect
##################################################################
NodeName=tux[0-7] AutoDetect=nvml
NodeName=tux[8-11] AutoDetect=rsmi
NodeName=tux[12-15] Name=gpu File=/dev/nvidia[0-3]
##################################################################
# Fichier de configuration des ressources génériques (GRES) de Slurm
# Définition de la GRES 'bandwidth' à utiliser pour limiter
# l'utilisation des ressources sur ces nœuds à des fins de flux de travail
##################################################################
NodeName=tux[0-7] Name=bandwidth Type=lustre Count=4G Flags=CountOnly
