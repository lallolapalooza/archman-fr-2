NOM

grmlzshrc - Configuration zsh de Grml

SYNTAXE

zsh [options]...

DESCRIPTION

Le projet Grml fournit une configuration interactive assez complète (désignée sous le nom de grmlzshrc dans ce document) pour l'étonnant shell Unix zsh http://zsh.sourceforge.net. Ceci est le manuel de référence pour cette configuration.

Pour utiliser grmlzshrc, vous avez besoin au minimum de la version 5.1 de zsh.

grmlzshrc se comporte différemment en fonction de l'utilisateur qui le charge. Pour l'utilisateur root (EUID == 0), seul un sous-ensemble de fonctionnalités est chargé par défaut. Ce comportement peut être modifié en définissant la VARIABLE DE DÉMARRAGE GRML_ALWAYS_LOAD_ALL (voir ci-dessous).

Les utilisateurs peuvent vouloir conserver une version à jour de la configuration (éventuellement à partir des sources git) dans ~/.zshrc. Si cela se produit sur un système où le zshrc global est également un grmlzshrc (mais éventuellement une version plus ancienne), vous pouvez empêcher le chargement de la version globale en faisant :

echo setopt no_global_rcs >> ~/.zshenv

Notez que cela désactivera *TOUS* les fichiers globaux, à l'exception du fichier zshenv global.

VARIABLES DE DÉMARRAGE

Certains comportements de grmlzshrc peuvent être modifiés en définissant certaines variables shell. Celles-ci peuvent être définies temporairement au démarrage de zsh comme ceci :

% GRML_DISPLAY_BATTERY=1 zsh

Ou en les définissant de manière permanente dans zshrc.pre (voir FICHIERS AUXILIAIRES ci-dessous).

BATTERY

Obsolète. Utilisez GRML_DISPLAY_BATTERY à la place.

COMMAND_NOT_FOUND

Une valeur non nulle active un gestionnaire, qui est appelé lorsqu'une commande est introuvable. Le gestionnaire est défini par GRML_ZSH_CNF_HANDLER (voir ci-dessous).

GRML_COMP_CACHING

Si défini sur yes (par défaut), la configuration activera le mécanisme de mise en cache des complétions de zsh, les données de mise en cache étant placées dans $GRML_COMP_CACHE_DIR.

GRML_COMP_CACHE_DIR

Définit l'emplacement où les données de mise en cache des complétions de zsh seront placées, si $GRML_COMP_CACHING est actif. La valeur par défaut est ${ZDOTDIR:-$HOME}/.cache. La configuration s'assurera que le répertoire existe avant d'essayer de l'utiliser.

GRML_DISPLAY_BATTERY

Si défini sur une valeur supérieure à zéro, grmlzshrc placera l'état de la batterie dans l'invite interactive de droite. Les OS supportés sont GNU/Linux, FreeBSD, OpenBSD et Darwin.

GRML_ZSH_CNF_HANDLER

Cette variable contient le gestionnaire à utiliser par COMMAND_NOT_FOUND (voir ci-dessus) et vaut par défaut "/usr/share/command-not-found/command-not-found".

GRML_NO_APT_ALIASES

Une valeur non vide empêche la définition d'alias courts spécifiques à apt, tels que ag, agi, ati, etc.

GRML_NO_SMALL_ALIASES

Une valeur non vide empêche la définition d'alias de 2 lettres telles que da. Les alias ls, ll, la et autres alias courants liés à ls sont exemptés de cette règle, tout comme les alias inhibés par GRML_NO_APT_ALIASES.

GRMLSMALL_SPECIFIC

Définissez cette valeur sur zéro pour supprimer les éléments de la configuration zsh qui ne fonctionnent pas dans grml-small.

HISTFILE

Où zsh enregistre l'historique. Par défaut : ${HOME}/.zsh_history.

HISTSIZE

Nombre de commandes à conserver dans l'historique. Par défaut : 5000

MAILCHECK

Définit la fréquence en secondes à laquelle zsh vérifie les nouveaux e-mails. La valeur par défaut est 30. Une valeur de zéro désactive la vérification.

NOCOR

Des valeurs non nulles désactivent la correction automatique des commandes.

NOETCHOSTS

Des valeurs non nulles désactivent l'analyse de "/etc/hosts", désactivant ainsi la complétion des hôtes en utilisant le contenu du fichier.

NOMENU

Si défini sur zéro (par défaut), permet la sélection à partir d'un menu, s'il y a au moins cinq options de complétion possibles.

NOPRECMD

Une valeur non nulle désactive les commandes precmd et preexec. Ce sont des fonctions qui sont exécutées avant chaque commande (définition des titres xterm/screen, etc.).

REPORTTIME

Affiche le temps (utilisateur, système et CPU) utilisé par les commandes externes, si elles s'exécutent plus longtemps que le nombre de secondes défini (par défaut : 5).

SAVEHIST

Nombre de commandes à stocker dans ${HISTFILE}. Par défaut : 10000

watch

Comme dans tcsh(1), un tableau d'événements de connexion/déconnexion à signaler par l'interne du shell "log". Pour plus de détails, voir zshparam(1). La valeur par défaut est (notme root).

ZSH_NO_DEFAULT_LOCALE

Importe "/etc/default/locale", si défini sur zéro (par défaut).

ZSH_PROFILE_RC

Une valeur non nulle provoque le profilage des fonctions shell. Les résultats peuvent être obtenus avec la commande interne zprof (voir zshmodules(1) pour les détails).

COMPDUMPFILE

Spécifie l'emplacement du fichier de vidage des complétions. Par défaut : $HOME/.zcompdump.

STYLES SPÉCIFIQUES À GRML-ZSHRC

Les styles sont un mécanisme de configuration sensible au contexte inclus avec zsh. Le shell l'utilise intensivement dans des sous-systèmes tels que le système d'information de complétion et de VCS. Il vit en dehors de l'espace de noms des variables shell classiques, évitant ainsi de le polluer. Les nouvelles fonctionnalités du zshrc de grml utiliseront probablement des styles plutôt que des variables. Certains aspects de la configuration (comme la gestion de la pile de répertoires) utilisent déjà des styles. Ces styles sont documentés avec les fonctionnalités spécifiques. Cette section documente des styles plus généraux.

Contexte : :grml:completion:compinit

Ce contexte tourne autour de l'appel de la fonction compinit du zshrc, qui initialise le système de complétion basé sur les fonctions de zsh.

arguments

Ce style permet l'injection d'arguments dans la ligne de commande utilisée pour exécuter compinit. C'est un style de liste et sa valeur par défaut est la liste vide. En utilisant ce style, il est possible d'ajouter -i à compinit afin de désactiver compaudit.
zstyle ':grml:completion:compinit' arguments -i

Ne faites cela que si vous savez quelles vérifications de sécurité sont désactivées lorsque compaudit n'est pas actif et si cela est acceptable dans votre configuration spécifique.

Ce style doit être défini au moment où le zshrc de Grml exécute compinit. Une façon possible d'y parvenir est de le définir dans ~/.zshrc.pre (voir FICHIERS AUXILIAIRES ci-dessous pour les détails).

DESCRIPTION DES FONCTIONNALITÉS

Ceci est une description approfondie des fonctionnalités non standard implémentées par grmlzshrc.

gestion de la pile de répertoires

La pile de répertoires dans grmlzshrc a une nature persistante. Elle est enregistrée dans un fichier chaque fois que le répertoire de travail de zsh est modifié. Ce fichier peut être configuré via la variable DIRSTACKFILE et vaut par défaut ~/.zdirs. La variable DIRSTACKSIZE vaut par défaut 20 dans cette configuration.

Le fichier DIRSTACKFILE est chargé chaque fois que zsh démarre, donc les zsh fraîchement démarrés héritent de la pile de répertoires du zsh qui a le plus récemment mis à jour DIRSTACKFILE.

Si vous souhaitez désactiver complètement la fonctionnalité de pile de répertoires persistante, vous pouvez le faire en définissant le style booléen enable sur false dans le bon contexte (la valeur par défaut est true) :

zstyle ':grml:chpwd:dirstack' enable false

Il est possible d'appliquer un filtre aux noms des répertoires qui seront enregistrés dans le fichier de pile de répertoires persistante. Il existe deux façons de configurer ce filtre : un filtre général basé sur une fonction et un filtre basé sur un motif. Les deux sont configurés via des styles dans le contexte ':grml:chpwd:dirstack'.

Pour utiliser un filtre basé sur une fonction, définissez le style filter à fo

Initialisatio

n

To initialise the system, you need to call the function `chpwd_profiles' at some point in your `zshrc.local'; preferably after you configured the system. The configuration of the system is described further

below.

If you need to do initialisations the first time `chpwd_profiles' is called (which should be in your configuration file), you can do that in a function called "chpwd_profiles_init". That function needs to be defined before `chpwd_profiles' is called for this to

work.

During the first call of `chpwd_profiles' (and therefore all its profile functions) the parameter `$CHPWD_P

ROFILES_INIT' exists and is set to `1'. In all
other cases, the parameter does not exist at all.

Styles et noms de

profils

To store its configuration, the system uses functions and styles (zsh’s context sensitive configuration system), such as

this: 
zstyle ':chpwd:profiles:/usr/src/grml(|/|
/*)' profile grml zstyle ':chpwd:profil
es:/usr/src/debian(|/|/*)' profile debian

When that’s done and you enter a directory that matches the pattern in the third part of the context, a function called chpwd_profile_grml, for example, is called (if it exists)

.

If no pattern matches (read: no profile is detected) the profile is set to 'default', which means chpwd_profile_default is attempted to be

called.

A word about the context (the ':chpwd:profiles:*' stuff in the zstyle command) which is used: The third part in the context is matched against ${PWD}. That’s why using a pattern such as /foo/bar(|/|/*) makes sense. Because that way the profile is detected for all these values of ${PWD}

: 
/foo/bar
/
foo/bar/ /f
oo/bar/baz

So, if you want to make double damn sure a profile works in /foo/bar and everywhere deeper in that tree, just use (|/|/*) and be

happy.

The name of the detected profile will be available in

a variable called 'profile' in your functions. Yo
u don’t need to do anything, it’ll just be there.

Contrôle de l'exécution des

profils

During its initialisation run, the system creates a parameter $CHPWD_PROFILE, which is set to the profile that was is currently active (the default value is "default"). That way you can avoid running code for a profile that is already active, by running code such as the following at the start of your

function: 
function chpwd_profile_grml() {
    [[ ${profile} == ${CHPWD_PROFILE} ]] && return 1
  ...
}

If you know you are going to do that all the time for each and every directory-profile function you are ever going to write, you may also set the `re-execute' style to `false' (which only defaults to `true' for backwards compatibility), like

this: 
zstyle ':ch
pwd:profile
s:*' re-ex
ecute false

Invite de

commande

The grmlzshrc now supplies three prompt themes compatible with zsh’s promptinit system. The three themes are called grml, grml-large and grml-chroot

.

By default, grml is used, unless $GRMLPROMPT is set to a value larger than zero, in which case grml-large is used. Lastly, if $GRML_CHROOT is non-empty, grml-chroot is

used.

As usual, with promptinit themes, the user may switch to a different theme using the prompt uti

lity: 
prompt
grml
-large

That will use the grml-large prompt

theme.

The themes are highly customisable. La principale source de documentation concernant la personnalisation est la doc-string du thème principal grml, qui est disponible via la commande suivante

: 
promp
t -h
grml

Les autres thèmes sont également accompagnés de doc-strings, mais celle du thème principal fait référence canonique pour tous les

autres.

Cette fonctionnalité nécessite la version 4.3.7 du shell. Les versions antérieures utiliseront le prompt grml classique en

repli.

Une note pour les amateurs de personnalisation : si vous n'utilisez pas de thème de prompt pour votre personnalisation, mais que vous définissez statiquement $PS1 (ou $PROMPT) ou que vous construisez l'une de ces variables dans la fonction `precmd()' de zsh, assurez-vous de désactiver le système de thèmes de prompt de zsh avant de le faire. Un exemple correct de personnalisation pourrait ressembler à ceci

: 
# Désactiver le système de promp
t : prompt off # Personnaliser le
prompt vous-même : PS1='%~ %# '

Vous pouvez également ajouter vos propres jetons en utilisant la

fonction `grml_theme_add_token()`. Appelez la fonction sans argume
nts pour obtenir une documentation détaillée sur cette procédure.

agi (apt install)

Télécharge et installe ou met à niveau les paquets donnés en ligne de commande. Si un tiret est ajouté au nom du paquet, le paquet identifié sera supprimé s'il est installé. Une version spécifique d'un paquet peut être sélectionnée pour l'installation en ajoutant un signe égal suivi de la version du paquet à sélectionner. Cela entraînera la localisation et la sélection de cette version pour l'installation. Alternativement, une distribution spécifique peut être sélectionnée en ajoutant un slash suivi de la version de la distribution ou du nom de l'archive (stable, testing, unstable) au nom du paquet. Est invoqué par sudo, si l'identifiant utilisateur n'est pas 0.

ÉTIQUETTES DE LA CARTE DE RÉFÉRENCE

ZSH

Si vous lisez le code de grmlzshrc, vous pouvez remarquer des commentaires d'apparence étrange. Ils sont là pour une raison. La carte de référence zsh de grml est générée automatiquement à partir du contenu du fichier de configuration réel. Cependant, nous avons besoin d'un peu d'informations supplémentaires sur quels commentaires et quelles lignes de code prendre en compte (et pour quel but)

.

Voici ce qu'ils signifient

:

Liste des étiquettes (types de commentaires) utilisées

:

#a# La ligne suivante contient un alias important, qui devrait être inclus dans la carte de référence grml-zsh. (étiquette de placement : @@INSERT-aliases@@

)

#f# La ligne suivante contient le début d'une fonction importante. (étiquette de placement : @@INSERT-functions@@

)

#v# La ligne suivante contient une variable importante. (étiquette de placement : @@INSERT-variables@@

)

#k# La ligne suivante contient un raccourci clavier important. (étiquette de placement : @@INSERT-keybindings@@

)

#d# Génération de la liste des répertoires hachés : start: dénote le début d'une liste de définitions 'hash -d'. end: dénote sa fin. (étiquette de placement : @@INSERT-hasheddirs@@

)

#A# Génération de la liste des développements d'abréviations : start: dénote le début des abréviations. end: dénote leur

fin.

Les lignes dans cette section qui se terminent par '#d .*' fournissent une documentation supplémentaire à inclure dans la carte de référence. (étiquette de placement : @@INSERT-abbrev@@

)

#m# Cette étiquette vous permet de générer manuellement des entrées de carte de référence pour des lignes de code qui sont difficiles/impossibles à

analyser.

Exemple

: 
#m# k ESC-h C
all the run-
help function

Cela ajouterait une entrée de carte de référence dans le tableau des raccourcis clavier pour 'ESC-h' avec le commentaire

donné.

Donc la syntaxe est

: 
#m# <sectio
n> <argument
> <comment>

#o# Cette étiquette vous permet d'insérer des entrées dans le hachage 'other'. Généralement, cela ne devrait pas être utilisé. Elle est là pour des choses qui ne peuvent pas être faites facilement d'une autre manière. (étiquette de placement : @@INSERT-other-foobar@@

)

Toutes ces étiquettes (sauf m et o) prennent deux arguments, le premier dans l'étiquette, l'autre après l'étiquette

: 
#<tag><se
ction>#
<comment>

Où <section> est en fait juste un nombre, qui est défini par le tableau @secmap en haut de 'genrefcard.pl'. La raison pour laquelle on utilise des nombres plutôt que des noms est que, pour le lecteur, l'étiquette ne devrait pas beaucoup différer d'un commentaire régulier. Pour zsh, c'est en effet un commentaire régulier. Les nombres ont les significations suivantes

:

0 par

défaut

1 systèm

e

2 utilisate

ur

3 debia

n

4 recherch

e

5 raccourci

s

6 service

s

Ainsi, ce qui suit ajoutera une entrée dans la table 'functions' dans la section 'system', avec un commentaire (espérons-le) descriptif

: 
#f1# Éditer un alias via zle
edalias()
{

Elle apparaîtra ensuite dans la balise de remplacement @@INSERT-aliases-system@@ que l'on trouve dans 'grml-zsh-refcard.tex.in'. Si le numéro de section est omis, la section 'default' est supposée. De plus, dans 'grml-zsh-refcard.tex.in', @@INSERT-aliases@@ est exactement la même que @@INSERT-aliases-default@@. Si vous voulez une liste de tous les aliases, par exemple, utilisez @@INSERT-aliases-all@

@
.
