greetd(1) Manuel des commandes générales greetd(1)

NOM

greetd - Démon gestionnaire de connexion

SYNTAXE

greetd [options]

OPTIONS

-h, --help

Affiche le message d'aide et quitte.

-c, --config <config>

Spécifie le fichier de configuration à utiliser.

--vt <vt>

La VT à utiliser, écrasant la valeur du fichier de configuration. Ceci peut être utile lors du lancement d'une instance par VT si greetd ne parvient pas à déduire la VT prévue à partir d'un terminal de contrôle associé.

DESCRIPTION

greetd a été créé pour répondre au besoin d'un gestionnaire de connexion simple qui ne fait aucune hypothèse sur les applications qu'il démarre, le rendant ainsi également adapté au démarrage de sessions console, de sessions Wayland ou de toute autre chose.

greetd n'interagit pas lui-même avec l'utilisateur, mais s'appuie sur un processus de "greeter" externe comme agreety(1) pour gérer cet aspect.

FONCTIONNEMENT

greetd opère sur des sessions. Un greeter crée une session, tente d'authentifier un utilisateur dans celle-ci, et enfin, l'utilise pour démarrer une application arbitraire.

Il existe deux types de sessions préconfigurées : La session par défaut, également connue sous le nom de greeter, et la session initiale optionnelle, servant de fonction "auto-connexion". La session initiale, si elle est configurée, est lancée une fois au démarrage de greetd. La session par défaut est lancée au démarrage si aucune session initiale n'est configurée, et relancée à chaque fois qu'aucune session n'est active, comme lors de la déconnexion d'un utilisateur.

Un socket IPC est exposé à ce greeter, comme indiqué par GREETD_SOCK. Le greeter peut l'utiliser pour créer, authentifier et enfin lancer une session. Pour plus d'informations sur la couche IPC, voir greetd-ipc(7).

Une fois que le greeter a demandé le démarrage d'une session et s'est terminé lui-même, greetd démarrera la nouvelle session. Une fois cette session terminée, le processus recommence.

greetd ne fait aucune hypothèse sur les sessions, y compris le greeter. Celles-ci peuvent être textuelles, s'exécutant dans la console active, ou des environnements graphiques complets.

CONFIGURATION

greetd recherche un fichier de configuration dans /etc/greetd/config.toml par défaut. Ceci peut être outrepassé avec un argument de ligne de commande.

Pour plus d'informations sur le format du fichier de configuration, voir greetd(5).
