Macros de structure de

document

Les macros de structure de document organisent le contenu d'une page manuelle. Toutes cassent la ligne de sortie. .TH (titre principal) identifie le document comme une page manuelle et configure les en-têtes et pieds de page. Les titres de section (.SH), dont un est obligatoire et dont beaucoup sont conventionnellement attendus, facilitent la localisation du contenu par le lecteur et aident l'auteur de la page manuelle à discuter de tous les aspects essentiels du sujet. Les titres de sous-section (.SS) sont facultatifs et permettent aux sections qui deviennent longues de se développer de manière contrôlée. De nombreuses discussions techniques bénéficient d'exemples ; les exemples longs, en particulier ceux qui reflètent plusieurs lignes d'entrée ou de sortie du système, sont utilement encadrés par .EX et .EE. Quand aucun des éléments ci-dessus ne répond à une exigence structurelle, utilisez .RS/.RE pour indenter une région à l'intérieur d'une (sous-)

section.

Macros de

paragraphe

Un paragraphe ordinaire (.P) est composé sans indentation de première ligne à la marge gauche courante. Dans les pages de manuel et d'autres documents techniques, on rencontre fréquemment des listes de définitions ; celles-ci peuvent être composées en « paragraphes étiquetés », qui ont une (.TP) ou plusieurs (.TQ) étiquettes initiales suivies d'un paragraphe ayant une indentation supplémentaire. La macro de paragraphe indenté (.IP) est utile pour continuer le contenu indenté d'un récit commencé avec .TP, ou pour présenter une liste à puces ou numérotée. Toutes ces macros interrompent la ligne de sortie. Si une autre macro de paragraphe est survenue depuis le dernier .SH ou .SS, elles (sauf .TQ) suivent l'interruption d'une quantité d'espace vertical par défaut, qui peut être modifiée par la macro dépréciée .PD ; voir la sous-section « Espacement horizontal et vertical » ci-dessous. Elles réinitialisent également la taille de corps et le style de police aux valeurs par défaut (.TQ à l'exception près) ; voir la sous-section « Macros de style de police » ci-dessous.

Macros de style de

police

Le paquet de macros man est limité dans ses options de style de police, n'offrant que gras (.B), italique (.I), et romain. Le texte italique est généralement composé souligné à la place sur les terminaux. Les macros .SM et .SB composent le texte en romain ou en gras, respectivement, à une taille de corps plus petite ; celles-ci ne diffèrent visuellement du texte romain ou gras de taille normale que sur les périphériques de composition. Il est souvent nécessaire de composer du texte dans différents styles sans espace intercalaire. Les macros .BI, .BR, .IB, .IR, .RB, et .RI, où « B », « I », et « R » indi

Font styles

The groff package supports a number of macros for changing font styles. The simplest macros change the font style of their arguments. Some macros, when given no arguments, plant a one-line input trap; text typed on the next line, which can be further formatted with a macro, is set in the specified font style. This is useful for setting the first word of a sentence or phrase in a different font style.

The macros described below are described as if they accept arguments. If no argument is given, then a one-line input trap is planted; text on the next line, which can be further formatted with a macro, is set in the indicated font style.

The default type size and family for typesetting devices is 10-point Times, except on the X75-12 and X100-12 devices where the type size is 12 points. The default style is roman.

.B [texte]
Met en texte en gras. Si aucun argument n'est donné, un piège d'entrée d'une ligne est placé; le texte de la ligne suivante, qui peut être davantage formaté avec une macro, est mis en gras.
.I [texte]
Met en texte dans une graisse italique ou oblique. Si aucun argument n'est donné, un piège d'entrée d'une ligne est placé; le texte de la ligne suivante, qui peut être davantage formaté avec une macro, est mis en italique ou oblique.
.SM [texte]
Met en texte un point plus petit que la taille de police par défaut sur les périphériques de composition. Si aucun argument n'est donné, un piège d'entrée d'une ligne est placé; le texte de la ligne suivante, qui peut être davantage formaté avec une macro, est mis plus petit.
.SB [texte]
Met en texte en gras et (sur les périphériques de composition) un point plus petit que la taille de police par défaut. Si aucun argument n'est donné, un piège d'entrée d'une ligne est placé; le texte de la ligne suivante, qui peut être davantage formaté avec une macro, est mis plus petit et en gras. Cette macro est une extension introduite dans SunOS 4.0.

Espacement horizontal et vertical

L'argument d'indentation accepté par .IP, .TP, et le déprécié .HP est un nombre plus une unité de mise à l'échelle optionnelle, tout comme montant-retrait de .RS. Si aucune unité de mise à l'échelle n'est donnée, le package man suppose «n». Une indentation spécifiée dans un appel à .IP, .TP, ou le déprécié .HP persiste jusqu'à ce que (1) un autre de ces macros soit appelé avec un argument d'indentation, ou (2) .SH, .SS, ou .P ou ses synonymes soient appelés; ceux-ci effacent complètement l'indentation.

La marge gauche utilisée par les paragraphes ordinaires définis avec .P (et ses synonymes) qui ne sont pas dans un retrait relatif .RS/.RE est de 7.2n pour les périphériques de composition et de 7n pour les périphériques terminaux (mais voir l'option -rIN). Les en-têtes, les pieds de page (tous deux définis avec .TH), et les titres de section (.SH) sont définis au décalage de page (voir groff(7)) et les titres de sous-section (.SS) sont indiqués à partir de celui-ci par 3n (mais voir l'option -rSN).

Plusieurs macros insèrent un espace vertical: .SH, .SS, .TP, .P (et ses synonymes), .IP, et le déprécié .HP. L'espacement par défaut entre les sections et entre les paragraphes est de 1v pour les périphériques terminaux et de 0.4v pour les périphériques de composition. (La macro dépréciée .PD peut changer cet espacement vertical, mais son utilisation est déconseillée.) Entre les appels .EX et .EE, l'espacement entre les paragraphes est de 1v, quel que soit le périphérique de sortie.

Crochets

Deux macros, toutes deux extensions GNU, sont appelées en interne par le package groff man pour formater les en-têtes et pieds de page et peuvent être redéfinies par l'administrateur dans le fichier local man.local (voir la section « Fichiers » ci-dessous). La présentation de .TH ci-dessus décrit les en-têtes et pieds de page par défaut. Étant donné que ces macros sont des crochets pour les internes de groff man, les pages de manuel n'ont aucune raison de les appeler. De telles définitions de crochets consisteront probablement en des requêtes « .sp » et « .tl ». Elles doivent également augmenter la longueur de la page avec des requêtes « .pl » en mode de rendu continu; .PT a en outre la responsabilité d'émettre un signet PDF après avoir écrit le premier en-tête de page dans un document. Consultez les implémentations existantes dans an.tmac lors de la rédaction de remplacements.

.BT
Définit le texte du pied de page (« piège inférieur »).
.PT
Définit le texte de l'en-tête de page (« piège de page »).

Pour supprimer complètement un en-tête ou un pied de page, définissez la macro appropriée comme vide plutôt que de la supprimer.

Si vous vous sentez tenté de modifier les tabulations de telle sorte qu'appeler cette macro plus tard soit souhaitable pour les restaurer, vous devriez probablement composer un tableau en utilisant tbl(1) à la place.
.HP [indentation]
Configure un paragraphe avec une indentation à gauche suspendue. L'argument indentation, s'il est présent, est géré comme avec .TP.
L'utilisation de cette macro axée sur la présentation est dépréciée. Une indentation suspendue ne peut pas être exprimée naturellement sous HTML, et les interpréteurs de pages de manuel non basés sur roff peuvent traiter .HP comme un paragraphe ordinaire. Ainsi, les informations ou les distinctions que vous avez l'intention d'exprimer par indentation peuvent être perdues.
.OP nom-option [argument-option]
Indique un paramètre de commande optionnel appelé nom-option, qui est mis en gras. Si l'option prend un argument, spécifiez argument-option en utilisant un nom, une abréviation, ou une phrase nominale avec trait d'union. S'il est présent, argument-option est précédé d'un espace et mis en italique. Les crochets en romain entourent les deux arguments.
L'utilisation de cette macro quasi-sémantique, une extension provenant de l'implémentation troff de Documenter's Workbench, est dépréciée. Elle ne peut pas être facilement utilisée pour annoter des options qui prennent des arguments optionnels ou des options dont les arguments ont une structure interne (comme un mélange de composantes littérales et variables). On pourrait contourner ces limitations avec des séquences d'échappement de sélection de police, mais il est préférable d'utiliser les macros d'alternance de style de police, qui offrent une plus grande flexibilité.
.PD [espace-vertical]
Définit l'espace vertical entre les paragraphes ou les (sous)sections. L'argument optionnel espace-vertical spécifie la quantité; l'unité de mise à l'échelle par défaut est « v ». Sans argument, l'espacement est réinitialisé à sa valeur par défaut; voir la sous-section « Espacement horizontal et vertical » ci-dessus.
L'utilisation de cette macro axée sur la présentation est dépréciée. Elle se traduit mal en HTML, où le contrôle exact de l'espacement entre les paragraphes n'est pas facilement disponible. Ainsi, les informations ou les distinctions que vous utilisez .PD pour exprimer risquent d'être perdues.

-rC1
Number output pages consecutively, in strictly increasing sequence, rather than resetting the page number to 1 (or the value of register P) with each new man document.
-rCS=1
Set section headings (the argument(s) to .SH) in full capitals. This transformation is off by default because it discards case distinction information.
-rCT=1
Set the man page topic (the first argument to .TH) in full capitals in headers and footers. This transformation is off by default because it discards case distinction information.
-rD1
Enable double-sided layout, formatting footers for even and odd pages differently; see the description of .TH in subsection “Document structure macros” above.
-rFT=footer-distance
Set distance of the footer relative to the bottom of the page to footer-distance; this amount is always negative. At one half-inch above this location, the page text is broken before writing the footer. Ignored if continuous rendering is enabled. The default is -0.5i.
-dHF=heading-font
Set the font used for section and subsection headings; the default is “B” (bold style of the default family). Any valid argument to groff's “.ft” request may be used. See groff(7).
-rHY=0
Disable automatic hyphenation. Normally, it is enabled (1). The hyphenation mode is determined by the groff locale; see section “Localization“ of groff(7).
-rIN=standard-indentation
Set the amount of indentation used for ordinary paragraphs (.P and its synonyms) and the default indentation amount used by .IP, .RS, .TP, and the deprecated .HP. See subsection “Horizontal and vertical spacing” above for the default. For terminal devices, standard-indentation should always be an integer multiple of unit “n” to get consistent indentation.
-rLL=line-length
Set line length; the default is 78n for terminal devices and 6.5i for typesetting devices.
-rLT=title-length
Set the line length for titles. By default, it is set to the line length (see -rLL above).
-dMF=man-page-topic-font
Set the font used for man page topics named in .TH and .MR calls; the default is “I” (italic style of the default family). Any valid argument to groff's “.ft” request may be used. If the MF string ends in “I”, it is assumed to be an oblique typeface, and italic corrections are applied before and after man page topics.
-rPn
Start enumeration of pages at n. The default is 1.
-rStype-size
Use type-size for the document's body text; acceptable values are 10, 11, or 12 points. See subsection “Font style macros” above for the default.

Enable generation of URI hyperlinks in the grohtml and grotty output drivers. grohtml enables them by default; grotty does not, pending more widespread pager support for OSC 8 escape sequences. Number successors of page p as pa, pb, pc, and so forth. The register tracking the suffixed page letter uses format “a” (see the “.af” request in groff(7)).

Files

/usr/share/groff/1.23.0/tmac/an.tmac
Most man macros are defined in this file. It also loads extensions from an-ext.tmac (see below).
/usr/share/groff/1.23.0/tmac/andoc.tmac
This brief groff program detects whether the man or mdoc macro package is being used by a document and loads the correct macro definitions, taking advantage of the fact that pages using them must call .TH or .Dd, respectively, before any other macros. A man program or user typing, for example, “groff -mandoc page.1”, need not know which package the file page.1 uses. Multiple man pages, in either format, can be handled; andoc reloads each macro package as necessary.
/usr/share/groff/1.23.0/tmac/an-ext.tmac
Except for .SB, definitions of macros described above as extensions are contained in this file; in some cases, they are simpler versions of definitions appearing in an.tmac, and are ignored if the formatter is GNU troff. They are written to be compatible with AT&T troff and permissively licensed—not copylefted. To reduce the risk of name space collisions, string and register names begin only with “m”. We encourage man page authors who are concerned about portability to legacy Unix systems to copy these definitions into their pages, and maintainers of troff implementations or work-alike systems that format man pages to re-use them.
The definitions for these macros are read after a page calls .TH, so they will replace any macros of the same names preceding it in your file. If you use your own implementations of these macros, they must be defined after .TH is called to have any effect. Furthermore, it is wise to define such page-local macros (if at all) after the “Name” section to accommodate timid makewhatis or mandb implementations that may give up their scan for indexing material early.
