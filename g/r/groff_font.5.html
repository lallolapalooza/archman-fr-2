Contrairement à l'implémentation d'AT&T, groff ne possède pas de format binaire ; tous les fichiers sont des fichiers texte. (Le troff de Plan 9 a également abandonné le format binaire.) Les fichiers de description des périphériques et des polices pour un périphérique nommé sont stockés dans un répertoire devname. Le fichier de description du périphérique est appelé DESC, et, pour chaque police prise en charge par le périphérique, un fichier de description depolice est appelé f, où f est généralement une abréviation du nom et/ou du style d'une police. Par exemple, le périphérique ps (PostScript) possède des fichiers de description de polices groffpour Times roman ( TR) et Zapf Chancery Mediumitalic ( ZCMI), entre beaucoup d'autres, tandis que le périphérique utf8 (pour les émulateurs de terminal) ne possède que des descriptions de polices pour les styles roman, italic, bold,R, I, et bold-italic ( R, I, B, et

Format des fichiers de description des polices Sur les périphériques de composition typographique, chaque police est généralement disponible en plusieurs tailles. Bien que les mesures sur papier dans le fichier de description du périphérique soient en unités absolues, les mesures applicables aux polices doivent être proportionnelles à la corps de caractères. groff réalise cela en utilisant le précédent établi par le troff indépendant du

périphéri
que d'

AT&T : une taille de police est choisie comme norme, et toutes les autres sont mises à l'échelle linéairement par rapport à cette base. La « largeur d'unité » est le nombre d'unités de base par point lorsque la police est rendue à cette taille

nominale.

Par exemple, le périphérique lbp

de

Sa police Times roman (« TR ») a un spacewidth de 833 ; c'est aussi la largeur de sa virgule, de son point, de son point centré et de son astérisque mathématique, tandis que son « M » fait 2 963 unités de base. Ainsi, un « M » sur lepériphérique lbp a une largeur de 2 963 unités de base pour un corps de caractères notionnel de 800 points. (Un corps de 800 points n'est pas pratique pour la plupart des usages, mais son utilisation permet d'exprimer les quantités dans les fichiers de description de police sous forme d'entiers.) Le sous-champ width donne la largeur du glyphe. Le sous-champ height donne la hauteur du glyphe (le haut est positif) ; si un glyphe ne s'étend pas au-dessus de la ligne de base, il devrait recevoir une hauteur de zéro, plutôt qu'une hauteur négative. Le sous-champ depth donne la profondeur du glyphe, c'est-à-dire la distance sous la ligne de base à laquelle le glyphe s'étend (le bas est positif) ; si un glyphe ne s'étend pas sous la ligne de base, il devrait recevoir une profondeur de zéro, plutôt qu'une profondeur négative. Les corrections italiques sont pertinentes pour les glyphes en style italique ou oblique. La italic-correction est la quantité d'espace qui devrait être ajoutée après un glyphe oblique suivi immédiatement d'un glyphe droit. La left-italic-correction est la quantité d'espace qui devrait être ajoutée avant un glyphe oblique précédé immédiatement d'un glyphe droit. La subscript-correction est la quantité d'espace qui devrait être ajoutée après un glyphe oblique suivi d'un indice ; elle devrait être inférieure à la correction

italique.

Pour les polices utilisées avec les périphériques de composition, le champ type donne une description fonctionnelle du glyphe : c'est un masque de bits enregistrant si le glyphe est un ascendant, un descendant, les deux, ou aucun des deux. Lorsqu'une séquence d'échappement \w est interpolée, ces valeurs sont combinées par ou binaire pour chaque glyphe et stockées dans le registre ct. Dans les descriptions de polices pour les périphériques de terminal, tous les glyphes peuvent avoir un type de zéro, quelle que soit leur
