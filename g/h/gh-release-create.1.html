NOM

gh-release-create - Créer une nouvelle version

SYNTAXE

gh release create [<tag>] [<nom_fichier>... | <motif>...]

DESCRIPTION

Crée une nouvelle version GitHub pour un dépôt.

Une liste de fichiers d'actifs peut être fournie pour les téléverser dans la nouvelle version. Pour définir une étiquette d'affichage pour un actif, ajoutez du texte commençant par # après le nom du fichier.

Si une balise git correspondante n'existe pas encore, une sera automatiquement créée à partir du dernier état de la branche par défaut. Utilisez --target pour pointer vers une branche ou un commit différent pour la création automatique de la balise. Utilisez --verify-tag pour annuler la version si la balise n'existe pas déjà. Pour récupérer la nouvelle balise localement après la version, exécutez git fetch --tags origin.

Pour créer une version à partir d'une balise git annotée, créez-la d'abord localement avec git, téléversez la balise sur GitHub, puis exécutez cette commande. Utilisez --notes-from-tag pour obtenir les notes de version à partir de la balise git annotée. Si la balise n'est pas annotée, le message de commit sera utilisé à la place.

Utilisez --generate-notes pour générer automatiquement les notes en utilisant l'API GitHub Release Notes. Lorsque vous utilisez des notes de version générées automatiquement, un titre de version sera également généré automatiquement, sauf si un titre a été explicitement passé. Des notes de version supplémentaires peuvent être ajoutées avant les notes générées automatiquement en utilisant le drapeau --notes.

Par défaut, la version est créée même s'il n'y a pas de nouveaux commits depuis la dernière version. Cela peut entraîner une version identique ou dupliquée, ce qui peut ne pas être souhaitable dans certains cas. Utilisez --fail-on-no-commits pour échouer s'il n'y a pas de nouveaux commits disponibles. Ce drapeau n'a aucun effet s'il n'y a pas de versions existantes ou si c'est la toute première version.

Versions Immuables

Lorsque l'immuabilité des versions est activée pour un dépôt, les protections suivantes sont appliquées : - Les balises Git associées à une version ne peuvent pas être modifiées ou supprimées. - Les actifs de version ne peuvent pas être modifiés ou supprimés.

L'immuabilité est appliquée uniquement après la publication d'une version. Les versions brouillons peuvent être modifiées ou supprimées, et les balises Git associées peuvent également être modifiées ou supprimées.

Lors de l'utilisation de la commande create pour attacher des actifs à une version, des appels API séparés sont effectués pour créer la version en tant que brouillon, téléverser les actifs, puis publier la version. Les protections d'immuabilité ne seront appliquées QU'APRÈS la publication de la version.

OPTIONS

--discussion-category <chaîne>
Démarrer une discussion dans la catégorie spécifiée
-b, --draft
Enregistrer la version en tant que brouillon au lieu de la publier
--fail-on-no-commits
Échouer s'il n'y a pas de commits depuis la dernière version (aucun impact sur la première version)
--generate-notes
Générer automatiquement le titre et les notes pour la version via l'API GitHub Release Notes
--latest
Marquer cette version comme "Dernière" (par défaut [automatique basé sur la date et la version]). --latest=false pour explicitement NE PAS définir comme dernière
-N, --notes <chaîne>
Notes de version
-F, --notes-file <fichier>
Lire les notes de version depuis un fichier (utiliser "-" pour lire depuis l'entrée standard)
--notes-from-tag
Récupérer les notes depuis l'annotation de la balise ou le message du commit associé à la balise
--notes-start-tag <chaîne>
Balise à utiliser comme point de départ pour la génération des notes de version
-p, --prerelease
Marquer la version comme une pré-version
--target <branche>
Branche cible ou SHA de commit complet (par défaut [branche principale])
-t, --title <chaîne>
Titre de la version
--verify-tag
Annuler si la balise git n'existe pas déjà dans le dépôt distant

OPTIONS HÉRITÉES DES COMMANDES PARENTES

-R, --repo <[HÔTE/]PROPRIÉTAIRE/DÉPÔT>
Sélectionner un autre dépôt en utilisant le format [HÔTE/]PROPRIÉTAIRE/DÉPÔT

ALIAS

gh release new

CODES DE SORTIE

0 : Exécution réussie

1 : Erreur

2 : Commande annulée

4 : Authentification requise

NOTE : Les commandes spécifiques peuvent avoir des codes de sortie supplémentaires. Référez-vous à l'aide de la commande pour plus d'informations.

EXEMPLE

# Créer une version interactivement
$ gh release create
# Créer une version interactivement à partir d'une balise spécifique
$ gh release create v1.2.3
# Créer une version non interactivement
$ gh release create v1.2.3 --notes "version de correction de bugs"
# Utiliser les notes de version générées automatiquement via l'API GitHub Release Notes
$ gh release create v1.2.3 --generate-notes
# Utiliser les notes de version à partir d'un fichier
$ gh release create v1.2.3 -F release-notes.md
# Utiliser l'annotation de balise ou le message de commit associé comme notes
$ gh release create v1.2.3 --notes-from-tag
# Ne pas marquer la version comme dernière
$ gh release create v1.2.3 --latest=false
# Téléverser tous les fichiers tarballs d'un répertoire comme actifs de version
$ gh release create v1.2.3 ./dist/*.tgz
# Téléverser un actif de version avec une étiquette d'affichage
$ gh release create v1.2.3 '/chemin/vers/asset.zip#Mon étiquette d'affichage'
# Créer une version et démarrer une discussion
$ gh release create v1.2.3 --discussion-category "Général"
# Créer une version seulement s'il y a de nouveaux commits disponibles depuis la dernière version
$ gh release create v1.2.3 --fail-on-no-commits
