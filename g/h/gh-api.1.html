NAME


gh-api - Appel de l'API REST de GitHub






SYNOPSIS


gh api <request> [-X <method>] [-F <name>=<value>] [-f <name>=<value>] [-H <header>] [-i <input>] [-q <jq_filter>] [--paginate]






DESCRIPTION


Appelle l'API REST de GitHub. La requête est le chemin de l'API (par exemple, /users/octocat). Les requêtes à l'API REST de GitHub sont documentées sur api.github.com.


Les options suivantes permettent de modifier la requête :




-X, --method <method>


La méthode HTTP à utiliser pour la requête (par défaut : GET).


-F, --form <name>=<value>


Utilise un champ de formulaire dans la requête. Peut être spécifié plusieurs fois.


-f, --field <name>=<value>


Utilise un champ de formulaire dans la requête. Différent de -F en ce sens que la valeur est transmise en tant que chaîne de caractères et non en tant que fichier. Peut être spécifié plusieurs fois.


-H, --header <header>


Ajoute un en-tête HTTP personnalisé à la requête. Par exemple : -H "Accept: application/vnd.github.v3.raw".


-i, --input <input>


Lit le corps de la requête à partir du fichier spécifié.


-q, --jq <jq_filter>


Filtre la sortie JSON à l'aide d'un filtre jq. Voir https://stedolan.github.io/jq/ pour la syntaxe.


--paginate


Effectue des requêtes paginées pour obtenir toutes les ressources.








EXIT CODES


Les codes de sortie sont les mêmes que ceux de la commande gh(1).






EXAMPLE


Obtenir des informations sur l'utilisateur octocat :


$ gh api users/octocat
{
  "login": "octocat",
  "id": 583231,
  "node_id": "MDQ6VXNlcjU4MzIzMQ==",
  // ...
}



Créer une nouvelle issue pour le dépôt cli/cli :


$ gh api repos/cli/cli/issues -f title='Bug report' -f body='This is a bug.' -X POST
{
  "url": "https://api.github.com/repos/cli/cli/issues/1",
  "repository_url": "https://api.github.com/repos/cli/cli",
  // ...
}



Obtenir le contenu d'un fichier, en filtrant la sortie avec jq :


$ gh api --jq '.[0].download_url' repos/cli/cli/contents/README.md
https://raw.githubusercontent.com/cli/cli/trunk/README.md



Lister toutes les dépôts de l'utilisateur, puis compter ceux qui sont des forks :


$ gh api --jq 'map(.isFork) | map(select(.) | length) | length / length' repos/octocat/repos
0.1234



Le filtre jq ci-dessus est une décomposition de :


'map(select(.isFork)) | length' # Compte le nombre de forks
'map(length)' # Compte le nombre total de dépôts



Voici une version plus courte qui utilise les options de gh :


$ gh api repos/octocat/repos --jq 'map(.isFork) | (. | length) as $total | (map(select(.) | length) | length) / $total'
