GH-AUTH-LOGIN(1) Manuel de la CLI GitHub GH-AUTH-LOGIN(1)

NOM

gh-auth-login - Se connecter à un compte GitHub

SYNTAXE

gh auth login [options]

DESCRIPTION

S'authentifier auprès d'un hôte GitHub.

Le nom d'hôte par défaut est github.com. Ceci peut être remplacé en utilisant l'option --hostname.

Le mode d'authentification par défaut est un flux via navigateur web. Après achèvement, un jeton d'authentification sera stocké de manière sécurisée dans le gestionnaire d'identifiants du système. Si un gestionnaire d'identifiants n'est pas trouvé ou s'il y a un problème lors de son utilisation, gh utilisera en secours l'écriture du jeton dans un fichier texte brut. Voir gh auth status pour connaître son emplacement de stockage.

Alternativement, utilisez --with-token pour passer un jeton d'accès personnel (classique) sur l'entrée standard. Les scopes minimum requis pour le jeton sont : repo, read:org et gist. Soyez prudent en passant un jeton d'accès personnel affiné à --with-token, car le filtrage inhérent à certaines ressources peut causer un comportement confus lors de l'interaction avec d'autres ressources. Privilégiez la définition de GH_TOKEN pour l'utilisation de jetons d'accès personnels affinés.

Alternativement, gh utilisera le jeton d'authentification trouvé dans les variables d'environnement. Cette méthode est la plus adaptée pour une utilisation de gh « sans tête », par exemple dans l'automatisation. Voir gh help environment pour plus d'informations.

Pour utiliser gh dans GitHub Actions, ajoutez GH_TOKEN: ${{ github.token }} à env.

Le protocole git à utiliser pour les opérations git sur cet hôte peut être défini avec --git-protocol, ou lors de la demande interactive. Bien que la connexion soit pour un seul compte sur un hôte, la définition du protocole git prendra effet pour tous les utilisateurs sur l'hôte.

Spécifier ssh pour le protocole git détectera les clés SSH existantes à téléverser, demandant de créer et téléverser une nouvelle clé si aucune n'est trouvée. Ceci peut être ignoré avec l'option --skip-ssh-key.

Pour plus d'informations sur les scopes OAuth, voir

⟨https://docs.github.com/en/developers/apps/building-oauth-apps/scopes-for-oauth-apps/⟩.

OPTIONS

-c, --clipboard
Copier le code d'appareil OAuth à usage unique dans le presse-papiers
-p, --git-protocol <chaîne>
Le protocole à utiliser pour les opérations git sur cet hôte : {ssh|https}
-h, --hostname <chaîne>
Le nom d'hôte de l'instance GitHub pour laquelle s'authentifier
--insecure-storage
Enregistrer les identifiants d'authentification en texte brut au lieu du gestionnaire d'identifiants
-s, --scopes <chaînes>
Scopes d'authentification supplémentaires à demander
--skip-ssh-key
Ignorer la demande de génération/téléversement de clé SSH
-w, --web
Ouvrir un navigateur pour s'authentifier
--with-token
Lire le jeton depuis l'entrée standard

CODES DE SORTIE

0 : Exécution réussie

1 : Erreur

2 : Commande annulée

4 : Authentification requise

NOTE : Des commandes spécifiques peuvent avoir des codes de sortie supplémentaires. Référez-vous à l'aide de la commande pour plus d'informations.

EXEMPLE

# Démarrer la configuration interactive
$ gh auth login
# Ouvrir un navigateur pour s'authentifier et copier le code d'authentification unique dans le presse-papiers
$ gh auth login --web --clipboard
# S'authentifier auprès de github.com en lisant le jeton depuis un fichier
$ gh auth login --with-token < monjeton.txt
# S'authentifier avec un hôte spécifique
$ gh auth login --hostname entreprise.interne
