NOM

gh-release-edit - Modifier une release

SYNTAXE

gh release edit <tag>

OPTIONS

--discussion-category <chaîne>
Lancer une discussion dans la catégorie spécifiée lors de la publication d'un brouillon
--draft
Sauvegarder la release comme brouillon au lieu de la publier
--latest
Marquer explicitement la release comme « Dernière »
-n, --notes <chaîne>
Notes de release
-F, --notes-file <fichier>
Lire les notes de release depuis un fichier (utiliser « - » pour lire depuis l'entrée standard
--prerelease
Marquer la release comme une pré-release
--tag <chaîne>
Le nom du tag
--target <branche>
Branche cible ou SHA de commit complet (par défaut [branche principale])
-t, --title <chaîne>
Titre de la release
--verify-tag
Annuler si le tag git n'existe pas déjà dans le dépôt distant

OPTIONS HÉRITÉES DES COMMANDES PARENTES

-R, --repo <[HÔTE/]PROPRIÉTAIRE/DÉPÔT>
Sélectionner un autre dépôt en utilisant le format [HÔTE/]PROPRIÉTAIRE/DÉPÔT

CODES DE SORTIE

0 : Exécution réussie

1 : Erreur

2 : Commande annulée

4 : Authentification requise

NOTE : Des commandes spécifiques peuvent avoir des codes de sortie supplémentaires. Se référer à l'aide de la commande pour plus d'informations.

EXEMPLE

# Publier une release qui était auparavant un brouillon
$ gh release edit v1.0 --draft=false
# Mettre à jour les notes de release à partir du contenu d'un fichier
$ gh release edit v1.0 --notes-file /chemin/vers/release_notes.md
