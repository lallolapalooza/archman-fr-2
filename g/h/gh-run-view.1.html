NOM

gh-run-view - Afficher un résumé d'une exécution de workflow

SYNTAXE

gh run view [<id-run>] [options]

DESCRIPTION

Afficher un résumé d'une exécution de workflow.

En raison des limitations de la plateforme, gh peut ne pas toujours être en mesure d'associer les jobs à leurs journaux correspondants lorsqu'il utilise la méthode principale de récupération des journaux au format zip.

Dans de tels cas, gh tentera de récupérer les journaux pour chaque job individuellement via l'API. Ce mécanisme de repli est plus lent et plus gourmand en ressources. Si plus de 25 journaux de jobs sont manquants, l'opération échouera avec une erreur.

De plus, en raison de contraintes similaires de la plateforme, certaines lignes de journal peuvent ne pas être associées à une étape spécifique au sein d'un job. Dans ces cas, le nom de l'étape apparaîtra comme ÉTAPE INCONNUE dans la sortie du journal.

OPTIONS

-a, --attempt <uint> (par défaut 0)
Le numéro de tentative de l'exécution du workflow
--exit-status
Sortir avec un statut non nul si l'exécution a échoué
-j, --job <chaîne>
Afficher un ID de job spécifique d'une exécution
-q, --jq <expression>
Filtrer la sortie JSON à l'aide d'une expression jq
--json <champs>
Afficher JSON avec les champs spécifiés
--log
Afficher le journal complet pour une exécution ou un job spécifique
--log-failed
Afficher le journal des étapes échouées dans une exécution ou un job spécifique
-t, --template <chaîne>
Formater la sortie JSON à l'aide d'un modèle Go ; voir « gh help formatting »
-v, --verbose
Afficher les étapes du job
-w, --web
Ouvrir l'exécution dans le navigateur

OPTIONS HERITEES DES COMMANDES PARENT

-R, --repo <[HOTE/]PROPRIETAIRE/REPO>
Sélectionner un autre dépôt en utilisant le format [HOTE/]PROPRIETAIRE/REPO

CHAMPS JSON

attempt, conclusion, createdAt, databaseId, displayTitle, event, headBranch, headSha, jobs, name, number, startedAt, status, updatedAt, url, workflowDatabaseId, workflowName

CODES DE SORTIE

0 : Exécution réussie

1 : Erreur

2 : Commande annulée

4 : Authentification requise

NOTE : Les commandes spécifiques peuvent avoir des codes de sortie supplémentaires. Référez-vous à l'aide de la commande pour plus d'informations.

EXEMPLE

# Sélectionner interactivement une exécution à afficher, en sélectionnant éventuellement un job unique
$ gh run view
# Afficher une exécution spécifique
$ gh run view 12345
# Afficher une exécution spécifique avec un numéro de tentative spécifique
$ gh run view 12345 --attempt 3
# Afficher un job spécifique dans une exécution
$ gh run view --job 456789
# Afficher le journal complet pour un job spécifique
$ gh run view --log --job 456789
# Sortir non nul si une exécution a échoué
$ gh run view 0451 --exit-status && echo "run pending or passed"
