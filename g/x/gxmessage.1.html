DESCRIPTIO

N

gxmessage ouvre une fenêtre pour afficher un message obtenu depuis la ligne de commande, depuis un fichier, ou depuis stdin. La fenêtre contient une rangée de boutons, chacun faisant quitter le programme avec un code de retour

différent.

L'entrée Info GNU de gxmessag

e contient des informations dé
taillées et des exemples.

OPTION

S

gxmessage accepte toute option que xmessage accepterait, bien que certaines (comme -bw et -xrm) soient ignorées silencieusement

.
-bg COUL
EUR

Définit la couleur d'arrière-plan du message à COULEUR. Exemples : red, "#c90",
"#446a7e".
-buttons LISTE_BOUT
ONS

Définit les boutons à créer. LISTE_BOUTONS est une liste d'éléments séparés par des virgules de paires ÉTIQUETTE:VALEUR, une pour chaque bouton. L' ÉTIQUETTE est le texte qui apparaît sur le bouton. La VALEUR (0..255) est le code avec lequel le programme quittera si ce bouton est pressé. Les virgules et les deux-points peuvent être échappés en utilisant des barres obliques inverses (\). En plus du texte ordinaire, l' ÉTIQUETTE peut spécifier un bouton « stock » GTK, comme "GTK_STOCK_CANCEL", ou elle peut incluer un souligné (_) pour spécifier un accélérateur clavier. Si les VALEURS sont omises, elles valent par défaut 101, 102, 103, etc., dans l'ordre. Si aucune option -buttons n'est donnée, LISTE_BOUTONS vaut par défaut "okay:0". 
gxmessage -buttons "Foo:42,Bar:63" "Exemple"
echo $?
gxmessage -buttons "_Foo,_Bar" "Exemple"
echo $?
gxmessage "Exemple"
echo $?
gxmessage -buttons "GTK_STOCK_OK:0" "Exemple"
echo $?
gxmessage -buttons "Hello\, world"
"Exemple"

er

l'écran.

Ouvre la fenêtre gxmessage avec le focus sur le bouton spécifié. ÉTIQUETTE est l'une des ÉTIQUETTEs de la LISTE_BOUTONS (voir -buttons, ci-dessus)

Spécifie la police du message, en utilisant le système de spécification de polices de GTK. Par exemple, -font "serif italic 14". (Le système de polices de GTK n'est pas compatible avec xmessage. Voir la section Compatibilité, ci-dessous, pour une solution de contournement.

DÉFAUTS

GTK

L'apparence par défaut du programme peut être ajustée en utilisant des fichiers de ressources GTK. Le widget principal d'affichage du texte est nommé gxmessage-textview. Le widget de saisie de texte est nommé gxmessage-entry

. 
# Exemple : ~/.gtkrc-2.0
style "gxmsg" {
    text[NORMAL]   = "#cc9900"
    base[NORMAL]   = "#6
60000" text[SELECTED] = "#660000" base[SELECTED] = "#cc9900" font_name = "monosp
ace" } widget "*.gxmessage-textview" style "gxmsg" widget "*.gxmessage-entry" style "gxmsg"

CODE DE

SORTIE

Si un bouton est pressé, le programme retourne la valeur assignée à ce bouton. Le bouton par défaut "okay" retourne

0.

Si un événement de délai d'attente se produit, le programme retourne

0.

Si une erreur se produit, ou si la fenêtre est fermée sans événement de p

ression de bouton ou de délai d'attente, le programme quitte avec le code 1.
Appuyer sur la touche ESC fait aussi quitter le programme avec le code 1.

COMPATIBILITÉ AVEC

XMESSAGE

Revenir à xmessage si gxmessage n'est pas disponible

: 
#! /bin/sh
XMESSAGE=$(which gxmessage) || XMESSAGE=xmessage
$XMESSAGE "hello,
world"

Si vousecifier les polices, vérifiez quel programme vous utilisez

: 
font="monospace 14"
[ "$XMESSAGE" = xmessage ] && font="fixed"
$XMESSAGE ${font:+-fn "$font"} "hello,
world"

N'utilisez pas d'options de ligne de commande avec double tiret

: 
$XMESSAGE "hello, world" -buttons good
$XMESSAGE "hello, world" --buttons
bad

N'utilisez pas les options spécifiques à gxmessage

: 
-entry, -entrytext, -borderless, -wrap,
-encoding, -nofocus, -noescape, -ontop,
-sticky, -version, -h, -
?
