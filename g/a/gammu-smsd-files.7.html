GAMMU-SMSD-FILES(7) Gammu GAMMU-SMSD-FILES(7)

NOM

gammu-smsd-files - backend de gammu-smsd(1) utilisant le système de fichiers comme stockage de messages

DESCRIPTION

Le backend FILES stocke toutes les données sur un système de fichiers dans des dossiers définis par la configuration (voir gammu-smsdrc pour la description des options de configuration).

RÉCEPTION DES MESSAGES

Les messages reçus sont stockés dans un dossier défini par la configuration. Le nom du fichier sera IN<date>_<heure>_<série>_<expéditeur>_<séquence>.<ext>, par exemple IN20021130_021531_00_+45409000931640979_00.txt.

Explication des champs :

<date>
date au format AAAAJJMM
<heure>
heure au format HHMMSS
<expéditeur>
numéro de l'expéditeur
<série>
ordre d'un message (en cas de réception de plusieurs messages à la même heure), au format NN
<séquence>
partie du message pour les messages multiparties, au format NN
<ext>
txt pour un message texte, les messages 8 bits sont stockés avec l'extension bin, smsbackup pour gammu-smsbackup

Le contenu du fichier est le contenu du message et le format est défini par la directive de configuration InboxFormat (voir gammu-smsdrc).

TRANSMISSION DES MESSAGES

Les messages transmis sont lus à partir d'un dossier défini par la configuration. Le nom du fichier doit être l'un des formats suivants :

  • OUT<destinataire>.<ext>
  • OUT<priorité>_<destinataire>_<série>.<ext>
  • OUT<priorité><date>_<heure>_<série>_<destinataire>_<note>.<ext>

Explication des champs :

<destinataire>
numéro du destinataire auquel envoyer le message
<priorité>
un caractère alphabétique (A-Z) A = priorité la plus élevée
<ext>
txt pour un SMS texte normal, smsbackup pour gammu-smsbackup
<note>
texte arbitraire qui est ignoré

Pour les messages texte, vous pouvez en plus ajouter des indicateurs à l'extension :

d
rapport de livraison demandé
f
SMS flash
b
signet WAP sous la forme Nom,URL

Les autres champs sont identiques à ceux des messages reçus.

Par exemple, OUTG20040620_193810_123_+4512345678_xpq.txtdf est un SMS texte flash demandant des rapports de livraison.

Les SMS seront transmis séquentiellement en fonction du nom du fichier. Le contenu du fichier est le SMS à transmettre (en Unicode ou en jeu de caractères standard).

Le contenu du fichier est le SMS à transmettre (en Unicode ou en jeu de caractères standard), pour les signets WAP, il est divisé en Nom, URL ; pour les messages texte, le contenu entier du fichier est utilisé.

Veuillez noter que si le fichier n'est pas en Unicode, l'encodage est détecté en fonction des locales, qui ne doivent pas nécessairement être configurées si SMSD est exécuté à partir d'un script d'initialisation. Si c'est votre cas, veuillez ajouter la définition des locales au script d'initialisation.
