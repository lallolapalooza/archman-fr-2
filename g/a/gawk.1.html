EXÉCUTION DU PROGRAMME AWK

Un programme AWK se compose d'une séquence de directives facultatives, d'instructions motif-action et de définitions de fonctions facultatives.

@include "filename"
@load "filename"
@namespace "name"
pattern { action statements }
function name(parameter list) { statements }

Gawk lit d'abord le source du programme à partir des program-file(s) si spécifié, à partir des arguments de --source, ou à partir du premier argument non-option sur la ligne de commande. Les options -f et --source peuvent être utilisées plusieurs fois sur la ligne de commande. Gawk lit le texte du programme comme si tous les program-files et les textes source de la ligne de commande avaient été concaténés ensemble.

De plus, les lignes commençant par @include peuvent être utilisées pour inclure d'autres fichiers source dans votre programme. Cela équivaut à utiliser l'option --include .

Les lignes commençant par @load peuvent être utilisées pour charger des fonctions d'extension dans votre programme. Cela équivaut à utiliser l'option --load .

La variable d'environnement AWKPATH spécifie un chemin de recherche à utiliser lors de la recherche de fichiers source nommés avec les options -f et --include . Si cette variable n'existe pas, le chemin par défaut est ".:/usr/local/share/awk". (Le répertoire réel peut varier, selon la manière dont gawk a été construit et installé.) Si un nom de fichier donné à l'option -f contient le caractère « / », aucune recherche de chemin n'est effectuée.

La variable d'environnement AWKLIBPATH spécifie un chemin de recherche à utiliser lors de la recherche de fichiers source nommés avec l'option --load . Si cette variable n'existe pas, le chemin par défaut est "/usr/local/lib/gawk". (Le répertoire réel peut varier, selon la manière dont gawk a été construit et installé.)

Gawk exécute les programmes AWK dans l'ordre suivant. D'abord, toutes les affectations de variables spécifiées via l'option -v sont effectuées. Ensuite, gawk compile le programme en une forme interne. Puis, gawk exécute le code dans la(s) règle(s) BEGIN (s'il y en a), puis procède à la lecture de chaque fichier nommé dans le ARGV tableau (jusqu'à ARGV[ARGC-1]). S'il n'y a pas de fichiers nommés sur la ligne de commande, gawk lit l'entrée standard.

Si un nom de fichier sur la ligne de commande a la forme var=val il est traité comme une affectation de variable. La variable var se verra assigner la valeur val. (Cela se produit après l'exécution de toute(s) règle(s) BEGIN .)

Si la valeur d'un élément particulier de ARGV est vide (""), gawk le saute.

Pour chaque fichier d'entrée, si une règle BEGINFILE existe, gawk exécute le code associé avant de traiter le contenu du fichier. De même, gawk exécute le code associé aux règles ENDFILE après le traitement du fichier.

Pour chaque enregistrement dans l'entrée, gawk teste pour voir s'il correspond à un pattern quelconque dans le programme AWK. Pour chaque motif auquel l'enregistrement correspond, gawk exécute l' actionassociée. Les motifs sont testés dans l'ordre où ils apparaissent dans le programme.

Enfin, après que toute l'entrée a été épuisée, gawk exécute le code dans la(s) règle(s) END (s'il y en a).

RÉPERTOIRES DE LA LIGNE DE COMMANDE

Selon POSIX, les fichiers nommés sur la ligne de commande d' awk doivent être des fichiers texte. Le comportement est « indéfini » s'ils ne le sont pas. La plupart des versions de awk traitent un répertoire sur la ligne de commande comme une erreur fatale.

Pour gawk, un répertoire sur la ligne de commande produit un avertissement, mais est autrement ignoré. Si l'une ou l'autre des options --posix ou --traditional est donnée, alors gawk revient à traiter les répertoires sur la ligne de commande comme une erreur fatale.

VARIABLES, ENREGISTREMENTS ET CHAMPS

Les variables AWK sont dynamiques ; elles viennent à l'existence lorsqu'elles sont utilisées pour la première fois. Leurs valeurs sont soit des nombres en virgule flottante, soit des chaînes, ou les deux, selon la manière dont elles sont utilisées. De plus, gawk permet aux variables d'avoir un type expression rationnelle. AWK a également des tableaux unidimensionnels ; les tableaux à plusieurs dimensions peuvent être simulés. Cependant, gawk fournit de véritables tableaux de tableaux. Plusieurs variables prédéfinies sont définies à l'exécution d'un programme ; celles-ci sont décrites au besoin et résumées ci-dessous.

Enregistrements

Normalement, les enregistrements sont séparés par des caractères de nouvelle ligne. Vous pouvez contrôler la manière dont les enregistrements sont séparés en assignant des valeurs à la variable intégrée RS. Voir https://www.gnu.org/software/gawk/manual/html_node/Records.html pour les détails.

Champs

À mesure que chaque enregistrement d'entrée est lu, gawk divise l'enregistrement en champs, en utilisant la valeur de la variable FS comme séparateur de champs. De plus, FIELDWIDTHS et FPAT peuvent être utilisés pour contrôler la division des champs d'entrée. Voir les détails, en commençant à https://www.gnu.org/software/gawk/manual/html_node/Fields.html.

Chaque champ dans l'enregistrement d'entrée peut être référencé par sa position : $1, $2, et ainsi de suite. $0 est l'enregistrement entier, y compris les espaces blancs de début et de fin.

La variable NF est définie au nombre total de champs dans l'enregistrement d'entrée.

Les références à des champs inexistants (c'est-à-dire les champs après $NF) produisent la chaîne nulle. Cependant, l'affectation à un champ inexistant (par exemple, $(NF+2) = 5) augmente la valeur de NF, crée tous les champs intermédiaires avec la chaîne nulle comme valeur, et provoque le recalcul de la valeur de $0 , les champs étant séparés par la valeur de OFS. Les références à des champs numérotés négativement provoquent une erreur fatale. La décrémentation de NF provoque la perte des valeurs des champs au-delà de la nouvelle valeur, et le recalcul de la valeur de $0 , les champs étant séparés par la valeur de OFS.

L'affectation d'une valeur à un champ existant provoque la reconstruction de l'enregistrement entier lorsque $0 est référencé. De même, l'affectation d'une valeur à $0 provoque la redivision de l'enregistrement, créant de nouvelles valeurs pour les champs.

Valeurs Séparées par des Virgules

Lorsqu'il est invoqué avec l'option -k ou l'option --csv , gawk n'utilise pas la détermination des enregistrements et la séparation des champs régulières décrites ci-dessus. À la place, les enregistrements sont terminés par des sauts de ligne non protégés, et les champs sont séparés par des virgules. Les guillemets doubles peuvent être utilisés pour englober des champs contenant des virgules, des sauts de ligne, ou des guillemets doubles doublés. Voir https://www.gnu.org/software/gawk/manual/html_node/Comma-Separated-Fields.html pour plus de détails.

Tableaux

Les tableaux sont indexés avec une expression entre crochets ([ et ]). Si l'expression est une liste d'expressions (expr, expr ...) alors le sous-script du tableau est une chaîne constituée de la concaténation de la valeur (chaîne) de chaque expression, séparée par la valeur de la variable SUBSEP . Cette fonctionnalité est utilisée pour simuler des tableaux multidimensionnels. Par exemple :

i = "A"; j = "B"; k = "C"
x[i, j, k] = "hello, world\n"

assigne la chaîne "hello, world\n" à l'élément du tableau x qui est indexé par la chaîne "A\034B\034C". Tous les tableaux en AWK sont associatifs, c'est-à-dire indexés par des valeurs de chaînes.

L'opérateur spécial in peut être utilisé pour tester si un tableau a un index correspondant à une valeur particulière :

if (val in array)
	print array[val]

Si le tableau a plusieurs sous-scripts, utilisez (i, j) in array.

La construction in peut aussi être utilisée dans une boucle for pour itérer sur tous les éléments d'un tableau. Cependant, la construction (i, j) in array ne fonctionne que dans les tests, pas dans les boucles for .

Un élément peut être supprimé d'un tableau en utilisant l'instruction delete . L'instruction delete peut aussi être utilisée pour supprimer le contenu entier d'un tableau, simplement en spécifiant le nom du tableau sans sous-script.

gawk supporte les vrais tableaux multidimensionnels. Il ne requiert pas que de tels tableaux soient « rectangulaires » comme en C ou C++. Voir https://www.gnu.org/software/gawk/manual/html_node/Arrays pour les détails.

Espaces de noms

Gawk fournit une fonctionnalité simple d' espace de noms pour aider à contourner le fait que toutes les variables en AWK sont globales.

Un nom qualifié est constitué de deux identifiants simples joints par deux-points (::). L'identifiant de gauche représente l'espace de noms et l'identifiant de droite est la variable à l'intérieur. Tous les noms simples (non qualifiés) sont considérés comme étant dans l'espace de noms « courant » ; l'espace de noms par défaut est awk. Cependant, les identifiants simples constitués uniquement de lettres majuscules sont forcés dans l'espace de noms awk , même si l'espace de noms courant est différent.

Vous changez l'espace de noms courant avec la directive @namespace "name" .

Les noms des fonctions intégrées prédéfinies standard ne peuvent pas être utilisés comme noms d'espace de noms. Les noms des fonctions supplémentaires fournies par gawk peuvent être utilisés comme noms d'espace de noms ou comme identifiants simples dans d'autres espaces de noms. Pour plus de détails, voir https://www.gnu.org/software/gawk/manual/html_node/Namespaces.html#Namespaces.

Typage et Conversion des Variables

Les variables et les champs peuvent être des nombres (en virgule flottante), ou des chaînes, ou les deux. Ils peuvent aussi être des expressions régulières. La manière dont la valeur d'une variable estnterprétée dépend de son contexte. Si elle est utilisée dans une expression numérique, elle sera traitée comme un nombre ; si elle est utilisée comme une chaîne, elle sera traitée comme une chaîne.

Pour forcer une variable à être traitée comme un nombre, ajoutez-y zéro ; pour la forcer à être traitée comme une chaîne, concaténez-la avec la chaîne nulle.

Les variables non initialisées ont la valeur numérique zéro et la valeur de chaîne "" (la chaîne nulle ou vide).

Lorsqu'une chaîne doit être convertie en nombre, la conversion est effectuée à l'aide de strtod(3). Un nombre est converti en chaîne en utilisant la valeur de CONVFMT comme chaîne de format pour sprintf(3), avec la valeur numérique de la variable comme argument. Cependant, bien que tous les nombres dans AWK soient en virgule flottante, les valeurs entières sont toujours converties comme des entiers.

Gawk effectue les comparaisons comme suit : Si deux variables sont numériques, elles sont comparées numériquement. Si une valeur est numérique et que l'autre a une valeur de chaîne qui est une « chaîne numérique », les comparaisons sont également effectuées numériquement. Sinon, la valeur numérique est convertie en chaîne et une comparaison de chaînes est effectuée. Deux chaînes sont comparées, bien sûr, comme des chaînes.

Notez que les constantes de chaîne, telles que "57", ne sont pas des chaînes numériques, ce sont des constantes de chaîne. L'idée de « chaîne numérique » ne s'applique qu'aux champs, getline d'entrée, FILENAME, ARGV éléments, ENVIRON éléments et les éléments d'un tableau créé par split() ou patsplit() qui sont des chaînes numériques. L'idée de base est que l'entrée utilisateur, et seulement l'entrée utilisateur, qui semble numérique, doit être traitée de cette manière.

Constantes octales et hexadécimales

Vous pouvez utiliser des constantes octales et hexadécimales de style C dans le code source de votre programme AWK. Par exemple, la valeur octale 011 est égale au décimal 9, et la valeur hexadécimale 0x11 est égale au décimal 17.

Constantes de chaîne

Les constantes de chaîne dans AWK sont des séquences de caractères encadrées par des guillemets doubles (comme "value"). Dans les chaînes, certaines séquences d'échappement sont reconnues, comme en C. Voir https://www.gnu.org/software/gawk/manual/html_node/Escape-Sequences pour les détails.

Constantes d'expression rationnelle

Une constante d'expression rationnelle est une séquence de caractères encadrée par des barres obliques (comme /value/).

Les séquences d'échappement décrites dans le manuel peuvent également être utilisées à l'intérieur des expressions rationnelles constantes (par exemple, /[ \t\f\n\r\v]/ correspond aux caractères d'espacement).

Gawk fournit des constantes d' expression rationnelle fortement typées. Celles-ci sont écrites avec un symbole @ en tête (comme ceci : @/value/ ). De telles constantes peuvent être assignées à des scalaires (variables, éléments de tableau) et passées à des fonctions définies par l'utilisateur. Les variables qui ont été assignées de cette manière ont un type d'expression rationnelle.PATTERNS ET ACTIONS

AWK est un langage orienté ligne. Le motif vient en premier, puis l'action. Les instructions d'action sont encadrées par

{ et } . Soit le motif peut être manquant, soit l'action peut être manquante, mais pas les deux, bien sûr. Si le motif est manquant, l'action s'exécute pour chaque enregistrement d'entrée. Une action manquante est équivalente à{ print }

qui imprime l'enregistrement entier.

Les commentaires commencent par le caractère

# et continuent jusqu'à la fin de la ligne. Des lignes vides peuvent être utilisées pour séparer les instructions. Normalement, une instruction se termine par une nouvelle ligne, cependant, ce n'est pas le cas pour les lignes se terminant par une virgule, { ,? ,: ,&& , ou|| . Les lignes se terminant pardo ou else ont également leurs instructions automatiquement continuées sur la ligne suivante. Dans les autres cas, une ligne peut être continuée en la terminant par un « \ », auquel cas la nouvelle ligne est ignorée. Cependant, un « \ » après un # n'est pas spécial. Plusieurs instructions peuvent être placées sur une ligne en les séparant par un « ; ». Cela s'applique à la fois aux instructions à l'intérieur de la partie action d'une paire motif-action (le cas habituel), et aux instructions motif-action elles-mêmes.

Instructions d'E/S

Les instructions d'entrée/sortie sont les suivantes :

Fonctions E/S

close(fichier [, how])
Ferme un fichier, un tuyau ou un coprocessus ouvert. L'argument optionnel how ne doit être utilisé que lors de la fermeture d'une extrémité d'un tuyau bidirectionnel vers un coprocessus. Il doit s'agir d'une valeur chaîne, soit "to", soit "from".
getline
Définit $0 à partir de l'enregistrement d'entrée suivant ; définit NF, NR, FNR, RT.
getline <fichier
Définit $0 à partir de l'enregistrement suivant de fichier ; définit NF, RT.
getline variable
Définit variable à partir de l'enregistrement d'entrée suivant ; définit NR, FNR, RT.
getline variable <fichier
Définit variable à partir de l'enregistrement suivant de fichier ; définit RT.
commande | getline [variable]
Exécute commande, en redirigeant la sortie soit vers $0, soit vers variable, comme ci-dessus, et RT.
commande |& getline [variable]
Exécute commande en tant que coprocessus, en redirigeant la sortie soit vers $0 soit vers variable, comme ci-dessus, et RT. (La commande peut aussi être une socket. Voir la sous-section Noms de Fichiers Spéciaux, ci-dessous.)
fflush([fichier])
Vide tous les tampons associés au fichier de sortie ouvert ou au tuyau fichier. Si fichier est manquant ou s'il s'agit d'une chaîne nulle, alors tous les fichiers de sortie et tuyaux ouverts sont vidés.
next
Arrête le traitement de l'enregistrement d'entrée courant. Lit l'enregistrement d'entrée suivant et recommence le traitement avec le premier motif du programme AWK. À la fin des données d'entrée, exécute les règles END.
nextfile
Arrête le traitement du fichier d'entrée courant. Le prochain enregistrement d'entrée lu provient du fichier d'entrée suivant. Met à jour FILENAME et ARGIND, réinitialise FNR à 1 et recommence le traitement avec le premier motif du programme AWK. À la fin des données d'entrée, exécute les règles ENDFILE et END.
print
Imprime l'enregistrement courant. L'enregistrement de sortie est terminé par la valeur de ORS.
print liste-expressions
Imprime des expressions. Chaque expression est séparée par la valeur de OFS. L'enregistrement de sortie est terminé par la valeur de ORS.
print liste-expressions >fichier
Imprime des expressions dans fichier. Chaque expression est séparée par la valeur de OFS. L'enregistrement de sortie est terminé par la valeur de ORS.
printf fmt, liste-expressions
Formate et imprime.
printf fmt, liste-expressions >fichier
Formate et imprime dans fichier.
system(ligne-commande)
Exécute la commande ligne-commande et retourne son code de sortie. (Ceci peut ne pas être disponible sur les systèmes non-POSIX.) Voir https://www.gnu.org/software/gawk/manual/html_node/I_002fO-Functions.html#I_002fO-Functions pour tous les détails sur le code de sortie.

Des redirections de sortie supplémentaires sont autorisées pour print et printf.

print ... >> fichier
Ajoute la sortie à fichier.
print ... | commande
Écrit dans un tuyau.
print ... |& commande
Envoie des données à un coprocessus ou à une socket. (Voir aussi la sous-section Noms de Fichiers Spéciaux, ci-dessous.)

La fonction getline renvoie 1 en cas de succès, zéro en fin de fichier, et -1 en cas d'erreur. Si la valeur de errno(3) indique que l'opération d'E/S peut être réessayée, et que PROCINFO["input", "RETRY"] est définie, alors -2 est renvoyé au lieu de -1, et des appels ultérieurs à getline peuvent être tentés. En cas d'erreur, ERRNO est défini à une chaîne décrivant le problème.

NOTE : L'échec de l'ouverture d'une socket bidirectionnelle renvoie une erreur non fatale à la fonction appelante. Si vous utilisez un tuyau, un coprocessus ou une socket pour getline, ou depuis print ou printf dans une boucle, vous devez utiliser close() pour créer de nouvelles instances de la commande ou de la socket. AWK ne ferme pas automatiquement les tuyaux, les sockets ou les coprocessus lorsqu'ils retournent EOF.

Les versions AWK de l'instruction printf et de la fonction sprintf() sont similaires à celles de C. Pour plus de détails, voir https://www.gnu.org/software/gawk/manual/html_node/Printf.html.

Fonctions de Chaîne

Gawk possède les fonctions de chaîne intégrées suivantes ; les détails sont fournis dans https://www.gnu.org/software/gawk/manual/html_node/String-Functions.

asort(s [, d [, how] ])
Retourne le nombre d'éléments dans le tableau source s. Trie le contenu de s en utilisant les règles normales de gawk pour comparer les valeurs, et remplace les indices des valeurs triées de s par des entiers séquentiels commençant à 1. Si le tableau destination optionnel d est spécifié, duplique d'abord s dans d, puis trie d, laissant les indices du tableau source s inchangés. La chaîne optionnelle how contrôle la direction et le mode de comparaison. Les valeurs valides pour how sont décrites dans https://www.gnu.org/software/gawk/manual/html_node/String-Functions.html#String-Functions. s et d sont autorisés à être le même tableau ; ceci n'a de sens que lorsque le troisième argument est également fourni.
asorti(s [, d [, how] ])
Retourne le nombre d'éléments dans le tableau source s. Le comportement est le même que celui de asort(), sauf que les indices du tableau sont utilisés pour le tri, pas les valeurs du tableau. Une fois terminé, le tableau est indexé numériquement, et les valeurs sont celles des indices d'origine. Les valeurs originales sont perdues ; fournissez donc un deuxième tableau si vous souhaitez conserver l'original. Le but de la chaîne optionnelle how est le même que pour asort(). Ici aussi, s et d sont autorisés à être le même tableau ; ceci n'a de sens que lorsque le troisième argument est également fourni.
gensub(r, s, h [, t])
Recherche la chaîne cible t à la recherche de correspondances de l'expression régulière r. Si h est une chaîne commençant par g ou G, alors toutes les correspondances de r sont remplacées par s. Sinon, h est un nombre indiquant quelle correspondance de r remplacer. Si t n'est pas fourni, utilisez $0 à la place. Dans la chaîne de remplacement s, la séquence \n, où n est un chiffre de 1 à 9, peut être utilisée pour indiquer seulement le texte qui a correspondu à la sous-expression parenthesée n. La séquence \0 représente tout le texte correspondant, tout comme le caractère &. Contrairement à sub() et gsub(), la chaîne modifiée est retournée comme résultat de la fonction, et la chaîne cible originale n'est pas modifiée.
gsub(r, s [, t])
Pour chaque sous-chaîne correspondant à l'expression régulière r dans la chaîne t, substituer la chaîne s, et retourner le nombre de substitutions. Si t n'est pas fourni, utilisez $0. Un & dans la chaîne de remplacement est remplacé par le texte qui a réellement été correspondant. Utilisez \& pour obtenir un & littéral. (Ceci doit être tapé comme "\\&" ; voir https://www.gnu.org/software/gawk/manual/html_node/Gory-Details.html#Gory-Details pour une discussion plus complète des règles concernant les ampersands et les antislashs dans le texte de remplacement de sub(), gsub() et gensub().)
index(s, t)
Retourne l'indice de la chaîne t dans la chaîne s, ou zéro si t n'est pas présente. (Ceci implique que les indices de caractères commencent à un.)
length([s])
Retourne la longueur de la chaîne s, ou la longueur de $0 si s n'est pas fournie. Avec un argument de tableau, length() retourne le nombre d'éléments dans le tableau.
match(s, r [, a])
Retourne la position dans s où l'expression régulière r se produit, ou zéro si r n'est pas présente, et définit les valeurs de RSTART et RLENGTH. Notez que l'ordre des arguments est le même que pour l'opérateur ~ : str ~ re. Voir https://www.gnu.org/software/gawk/manual/html_node/String-Functions.html#String-Functions pour une description de la manière dont le tableau a est rempli s'il est fourni.
patsplit(s, a [, r [, seps] ])
Divise la chaîne s dans le tableau a et le tableau des séparateurs seps selon l'expression régulière r, et retourne le nombre de champs. Les valeurs des éléments sont les parties de s qui correspondaient à r. La valeur de seps[i] est le séparateur potentiellement vide qui est apparu après a[i]. La valeur de seps[0] est le séparateur initial potentiellement vide. Si r est omis, FPAT est utilisé à la place. Les tableaux a et seps sont d'abord effacés. La division se comporte de manière identique à la division en champs avec FPAT.
split(s, a [, r [, seps] ])
Divise la chaîne s dans le tableau a et le tableau des séparateurs seps selon l'expression régulière r, et retourne le nombre de champs. Si r est omis, FS est utilisé à la place. Les tableaux a et seps sont d'abord effacés. seps[i] est le séparateur de champ correspondant à r entre a[i] et a[i+1]. La division se comporte de manière identique à la division en champs.
sprintf(fmt, expr-list)
Imprime expr-list selon fmt, et retourne la chaîne résultante.
strtonum(str)
Examine str, et retourne sa valeur numérique. Si str commence par un 0 en tête, elle est traitée comme un nombre octal. Si str commence par 0x ou 0X en tête, elle est traitée comme un nombre hexadécimal. Sinon, elle est supposée être un nombre décimal.
sub(r, s [, t])
Identique à gsub(), mais remplace seulement la première sous-chaîne correspondante. Retourne zéro ou un.
substr(s, i [, n])
Retourne la sous-chaîne de s d'au plus n caractères commençant à i. Si n est omis, utilise le reste de s.
tolower(str)
Retourne une copie de la chaîne str, avec tous les caractères majuscules de str traduits en leurs homologues minuscules correspondants. Les caractères non alphabétiques ne sont pas modifiés.
toupper(str)
Retourne une copie de la chaîne str, avec tous les caractères minuscules de str traduits en leurs homologues majuscules correspondants. Les caractères non alphabétiques ne sont pas modifiés.

Gawk est conscient des multi-octets. Cela signifie que index(), length(), substr() et match() fonctionnent tous en termes de caractères, et non d'octets.

mktime(datespec [, utc-flag])
Convertit datespec en un horodatage de la même forme que celle retournée par systime(), et retourne le résultat. Voir la spécification de la fonction strftime() dans ISO C pour les conversions de format garanties d'être disponibles.

EXEMPLES

Imprimer et trier les noms de connexion de tous les utilisateurs :
	BEGIN	{ FS = ":" }
		{ print $1 | "sort" }
Compter les lignes dans un fichier :
		{ nlines++ }
	END	{ print nlines }
Précéder chaque ligne de son numéro dans le fichier :
	{ print FNR, $0 }
Concaténer et numéroter les lignes (une variante sur le même thème) :
	{ print NR, $0 }
Exécuter une commande externe pour des lignes de données particulières :
	tail -f access_log |
	awk '/myhome.html/ { system("nmap " $1 ">> logdir/myhome.html") }'
