; Le gouverneur souhaité est utilisé lors de l'entrée dans GameMode au lieu de "performance"

; GameMode peut changer la politique de l'ordonnanceur en SCHED_ISO sur les noyaux qui le supportent (actuellement
; non supporté par les noyaux amont). Peut être défini à "auto", "on" ou "off". "auto" activera

softrealtime=off
; GameMode peut renicer les processus de jeu. Vous pouvez mettre n'importe quelle valeur entre 0 et 20 ici, la valeur
; sera négativée et appliquée comme valeur de nice (0 signifie aucun changement). Par défaut à 0.
; Pour utiliser cette fonctionnalité, l'utilisateur doit être ajouté au groupe gamemode (puis redémarré) :
; sudo usermod -aG gamemode $(whoami)

; Par défaut, GameMode ajuste l'iopriority des clients à BE/0, vous pouvez mettre n'importe quelle valeur

; Ici, il y a des dragons !
; Avertissement : Utilisez ces paramètres à vos propres risques
; Tout dommage matériel causé par cette fonctionnalité est de votre responsabilité et de la vôtre uniquement
; Il est également fortement recommandé d'essayer ces paramètres d'abord manuellement pour trouver les points optimaux
; Définir ceci à la phrase-clé "accept-responsibility" permettra à gamemode d'appliquer des optimisations GPU telles que des overclocks
;apply_gpu_optimisations=0
; Le numéro de périphérique DRM sur le système (généralement 0), c.-à-d. le numéro dans /sys/class/drm/card0/
;gpu_device=0
; Paramètres spécifiques à Nvidia
; Nécessite l'extension coolbits activée dans nvidia-xconfig
; Cela correspond au GPUPowerMizerMode souhaité
; "Adaptive"=0 "Prefer Maximum Performance"=1 et "Auto"=2
; Voir NV_CTRL_GPU_POWER_MIZER_MODE et compagnie dans https://github.com/NVIDIA/nvidia-settings/blob/master/src/libXNVCtrl/NVCtrl.h
;nv_powermizer_mode=1
; Celles-ci modifieront les horloges du cœur et de la mémoire de l'état de performance le plus élevé dans le PowerMizer Nvidia
; Elles sont mesurées comme des décalages en Mhz à partir de la ligne de base, 0 réinitialisera les valeurs par défaut, -1 ou non défini ne modifiera pas les valeurs
;nv_core_clock_mhz_offset=0
;nv_mem_clock_mhz_offset=0
; Paramètres spécifiques à AMD
; Nécessite un module de noyau AMDGPU relativement à jour
; Voir : https://dri.freedesktop.org/docs/drm/gpu/amdgpu.html#gpu-power-thermal-controls-and-monitoring
; Il est également fortement recommandé d'utiliser lm-sensors (ou d'autres outils disponibles) pour vérifier les températures de la carte
; Cela correspond à power_dpm_force_performance_level, "manual" n'est pas supporté pour l'instant
;amd_performance_level=high
[cpu]
; Le parking ou le pinning peut être activé avec soit "yes", "true" ou "1" et désactivé avec "no", "false" ou "0".
; L'un ou l'autre peut également être défini sur une liste spécifique de cœurs à garer ou à épingler, liste séparée par des virgules où "-" dénote
; une plage. Par ex. "park_cores=1,8-15" garerait les cœurs 1 et 8 à 15.
; La valeur par défaut non commentée est de désactiver le parking mais d'activer le pinning. Si l'un ou l'autre est activé, le code
; actuellement ne détectera automatiquement que les Ryzen 7900x3d, 7950x3d et les CPU Intel avec des cœurs E et P.
; Pour le Core Parking, l'utilisateur doit être ajouté au groupe gamemode (non requis pour le Core Pinning) :
; sudo usermod -aG gamemode $(whoami)
;park_cores=no
;pin_cores=yes
