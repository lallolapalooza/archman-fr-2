SMBTORTURE(1) Suite de tests SMBTORTURE(1)

NOM

smbtorture - Exécute une série de tests contre un serveur SMB

SYNTAXE

smbtorture {//serveur/partage} [-d niveau_débogage] [-U utilisateur%mot_de_passe] [-k] [-N nb_processus] [-n nom_netbios] [-W groupe_travail] [-e nb fichiers(entrées)] [-O options_socket] [-m protocole_maximum] [-L] [-c CLIENT.TXT] [-t limite_temps] [-C nom_fichier] [-A] [-p port] [-s graine] [-f échecs_max] [-X] {CHAÎNE_LIAISON|UNC} {TEST1} [TEST2] [...]

DESCRIPTION

smbtorture est une suite de tests qui exécute plusieurs tests contre un serveur SMB. Tous les tests réussissent contre un serveur Windows 2003 (?). L'objectif principal de Smbtorture est de trouver des différences dans les implémentations du protocole SMB et de tester les serveurs SMB.

Un nombre quelconque de tests peut être spécifié sur la ligne de commande. Si aucun test n'est spécifié, tous les tests sont exécutés.

Si aucun argument n'est spécifié du tout, toutes les options et tous les tests disponibles sont listés.

Format de la chaîne de liaison

Le format de la chaîne de liaison est :

TRANSPORT:hôte[indicateurs]

Où TRANSPORT est soit ncacn_np pour SMB, ncacn_ip_tcp pour RPC/TCP, soit ncalrpc pour les connexions locales.

'hôte' est une adresse IP, un nom d'hôte ou un nom NetBIOS. Si la chaîne de liaison identifie le côté serveur d'un point de terminaison, 'hôte' peut être une chaîne vide.

'indicateurs' peuvent inclure un nom de pipe SMB si vous utilisez le transport ncacn_np, ou un numéro de port TCP si vous utilisez le transport ncacn_ip_tcp, sinon ils seront déterminés automatiquement.

Autres indicateurs reconnus :

sign

active la signature ntlmssp

seal

active le chiffrement ntlmssp

connect

active l'authentification de niveau rpc connect (authentification, mais pas de signature ou de chiffrement)

validate

active le validateur NDR

print

active le débogage des paquets

bigendian

utilise RPC bigendian

padcheck

vérifie que les données de réponse ne contiennent pas d'octets de remplissage non nuls

Par exemple, ces commandes se connectent toutes au pipe samr :

•ncacn_np:myserver
•ncacn_np:myserver[samr]
•ncacn_np:myserver[\\pipe\\samr]
•ncacn_np:myserver[/pipe/samr]
•ncacn_np:myserver[samr,sign,print]
•ncacn_np:myserver[\\pipe\\samr,sign,seal,bigendian]
•ncacn_np:myserver[/pipe/samr,seal,validate]
•ncacn_np:
•ncacn_np:[/pipe/samr]
•ncacn_ip_tcp:myserver
•ncacn_ip_tcp:myserver[1024]
•ncacn_ip_tcp:myserver[1024,sign,seal]
•ncalrpc:

Format UNC

Le format UNC est :

//serveur/partage

OPTIONS

-d niveau_débogage

Utilise le niveau de débogage Samba spécifié. Un niveau de débogage plus élevé signifie plus de sortie.

-U utilisateur%mot_de_passe

Utilise la combinaison nom d'utilisateur/mot de passe spécifiée lors de la connexion à un serveur distant.

-k

Utilise Kerberos lors de l'authentification.

-W groupe_travail

Utilise le nom spécifié comme nom de notre groupe de travail.

-n nom_netbios

Utilise le nom spécifié comme nom NetBIOS de notre machine.

-O options_socket

Utilise les options socket spécifiées, équivalent de l'option smb.conf « socket options ». Voir la page man smb.conf(5) pour plus de détails.

-m protocole_maximum

Spécifie le dialecte SMB maximum qui doit être utilisé. Les valeurs possibles sont : CORE, COREPLUS, LANMAN1, LANMAN2, NT1

-s graine

Initialise le générateur de nombres aléatoires en utilisant graine comme graine.

-L

Utilise les oplocks.

-X

Active les tests dangereux. À utiliser avec prudence ! Cela pourrait faire planter votre serveur...

-t limite_temps

Spécifie la limite de temps NBENCH en secondes. La valeur par défaut est 600.

-p ports

Spécifie les ports de connexion.

-c fichier

Lit les commandes NBENCH depuis fichier au lieu de CLIENT.TXT.

-A

Affiche non seulement OK ou ÉCHEC, mais une sortie plus détaillée. Utilisé uniquement par le test DENY pour le moment.

-C nom_fichier

Charge une liste de noms UNC depuis le fichier spécifié. Les instances de Smbtorture se connecteront à un hôte aléatoire de cette liste.

-N nb_processus

Spécifie le nombre de processus smbtorture à lancer.

-e nb_fichiers

Nombre d'entrées à utiliser dans certains tests (comme la création de X fichiers) (défaut : 1000).

-f échecs_max

Nombre d'échecs avant d'interrompre un test (défaut : 1).
