smpquery(8) Diagnostic InfiniBand smpquery(8)

Nom

smpquery - interroger les attributs de gestion du sous-réseau InfiniBand

Syntaxe

smpquery [options] <opération> <chemin_dr_destination|lid|guid> [paramètres_opération]

Description

smpquery permet un sous-ensemble basique de requêtes SMP standard, y compris les suivantes : informations sur le nœud, description du nœud, informations sur le commutateur, informations sur le port. Les champs sont affichés dans un format lisible par l'homme.

Options

Opérations actuellement supportées (insensible à la casse) et leurs paramètres :

Nodeinfo (NI) <adresse>
Nodedesc (ND) <adresse>
Portinfo (PI) <adresse> [<numéro_port>]     # le port par défaut est zéro
PortInfoExtended (PIE) <adresse> [<numéro_port>]
Switchinfo (SI) <adresse>
PKeyTable (PKeys) <adresse> [<numéro_port>]
SL2VLTable (SL2VL) <adresse> [<numéro_port>]
VLArbitration (VLArb) <adresse> [<numéro_port>]
GUIDInfo (GI) <adresse>
MlnxExtPortInfo (MEPI) <adresse> [<numéro_port>]  # le port par défaut est zéro
-c, --combined
Utiliser l'adresse de route combinée <lid> <DR_Path>
-x, --extended
Définir le bit 31 de SMSupportsExtendedSpeeds dans AttributeModifier (n'affecte que les requêtes PortInfo).
-K, --show_keys
afficher les clés de sécurité (mkey, smkey, etc.) associées à la requête.

Drapeaux d'adressage

-D, --Direct L'adresse spécifiée est une route dirigée

Exemples :
   [options] -D [options] "0"          # port auto
   [options] -D [options] "0,1,2,1,4"  # sortie via le port 1, puis 2, ...
   (Notez que le deuxième numéro dans le chemin spécifié doit correspondre au port utilisé.
   Ceci peut être spécifié à l'aide du drapeau de sélection de port '-P' ou du
   port trouvé via le processus de sélection automatique.)

-G, --Guid L'adresse spécifiée est un GUID de port

-L, --Lid L'adresse spécifiée est un LID

-s, --sm_port <smlid> utiliser 'smlid' comme lid cible pour les requêtes SA.

Drapeaux de sélection de port

-C, --Ca <nom_ca> utiliser le nom_ca spécifié.

-P, --Port <ca_port> utiliser le ca_port spécifié.

Sélection du port local

Support multi-ports/multi-CA : lorsqu'aucun périphérique ou port IB n'est spécifié (voir les "paramètres umad locaux" ci-dessous), la bibliothèque libibumad sélectionne le port à utiliser selon les critères suivants :

1.
le premier port ACTIF.
2.
si non trouvé, le premier port CONNECTÉ (lien physique actif).

Si un nom de port et/ou de CA est spécifié, la bibliothèque libibumad tente de répondre à la demande de l'utilisateur, et échouera si ce n'est pas possible.

Par exemple :

ibaddr                 # utilise le premier port (critère #1 ci-dessus)
ibaddr -C mthca1       # choisit le meilleur port uniquement depuis "mthca1".
ibaddr -P 2            # utilise le deuxième port (actif/connecté) du premier périphérique IB disponible.
ibaddr -C mthca0 -P 2  # utilise uniquement le port spécifié.

Drapeaux de débogage

-d
augmente le niveau de débogage IB. Peut être utilisé plusieurs fois (-ddd ou -d -d -d).
-e
affiche les erreurs d'envoi et de réception (timeouts et autres)

-h, --help affiche le message d'utilisation

-v, --verbose
augmente le niveau de verbosité de l'application. Peut être utilisé plusieurs fois (-vv ou -v -v -v)

-V, --version affiche les informations de version.

Drapeaux de configuration

-t, --timeout <timeout_ms> remplace le timeout par défaut pour les mads sollicités.

--node-name-map <node-name-map> Spécifie une table de noms de nœuds.

Ce fichier mappe les GUIDs à des noms plus conviviaux. Voir la section FICHIERS.
-y, --m_key <clé>
utilise la M_key spécifiée pour les requêtes. Si une valeur non numérique (comme 'x') est spécifiée, une valeur sera demandée.

--config, -z <fichier_config> Spécifie un fichier de configuration alternatif.

Par défaut : /etc/infiniband-diags/ibdiag.conf

Fichiers

FICHIER DE CONFIGURATION

/etc/infiniband-diags/ibdiag.conf

Un fichier de configuration global est fourni pour définir certaines des options courantes pour tous les outils. Voir le fichier de configuration fourni pour les détails.

FORMAT DU FICHIER DE NOM DE NŒUD

Le fichier de nom de nœud est utilisé pour spécifier des noms conviviaux pour les nœuds dans la sortie. Les GUIDs sont utilisés pour effectuer la recherche.

Cette fonctionnalité est fournie par le paquet opensm-libs. Voir opensm(8) pour l'emplacement du fichier pour votre installation.

Généralement :

# commentaire
<guid> "<nom>"

Exemple :

# IB1
# Cartes de ligne
0x0008f104003f125c "IB1 (Rack 11 slot 1   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f125d "IB1 (Rack 11 slot 1   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10d2 "IB1 (Rack 11 slot 2   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10d3 "IB1 (Rack 11 slot 2   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10bf "IB1 (Rack 11 slot 12  ) ISR9288/ISR9096 Voltaire sLB-24D"
# Dorsales
0x0008f10400400e2d "IB1 (Rack 11 spine 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e2e "IB1 (Rack 11 spine 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e2f "IB1 (Rack 11 spine 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e31 "IB1 (Rack 11 spine 2   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e32 "IB1 (Rack 11 spine 2   ) ISR9288 Voltaire sFB-12D"
# GUID   Nom du nœud
0x0008f10400411a08 "SW1  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f10400411a28 "SW2  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f10400411a34 "SW3  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f104004119d0 "SW4  (Rack  3) ISR9024 Voltaire 9024D"

Exemples

smpquery portinfo 3 1                     # portinfo par lid, avec modificateur de port
smpquery -G switchinfo 0x2C9000100D051 1  # switchinfo par guid
smpquery -D nodeinfo 0                    # nodeinfo par route directe
smpquery -c nodeinfo 6 0,12               # nodeinfo par route combinée
