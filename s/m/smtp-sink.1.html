SMTP-SINK(1) Manuel des commandes générales SMTP-SINK(1)

NOM

smtp-sink - serveur de test SMTP/LMTP parallélisé

SYNTAXE

smtp-sink [options] [inet:][hôte]:port file_attente

smtp-sink [options] unix:chemin_d_acces file_attente

DESCRIPTION


smtp-sink écoute sur l'hôte (ou l'adresse) et le port nommés. Il reçoit des messages SMTP du réseau et les ignore. Le but est de mesurer les performances du client, pas la conformité du protocole.

smtp-sink peut également être configuré pour capturer chaque transaction de livraison de courrier dans un fichier. Les latences disque étant importantes comparées aux délais réseau, ce mode de fonctionnement peut réduire les performances maximales de plusieurs ordres de grandeur.

Les connexions peuvent être acceptées sur des points d'extrémité IPv4 ou IPv6, ou sur des sockets de domaine UNIX. IPv4 et IPv6 sont les valeurs par défaut. Ce programme est le complément du programme smtp-source(1).

Note : ceci est un programme de test non pris en charge. Aucune tentative n'est faite pour maintenir la compatibilité entre les versions successives.

Arguments :

-4
Prend en charge uniquement IPv4. Cette option n'a aucun effet lorsque Postfix est compilé sans prise en charge IPv6.
-6
Prend en charge uniquement IPv6. Cette option n'est pas disponible lorsque Postfix est compilé sans prise en charge IPv6.
-8
N'annonce pas la prise en charge de 8BITMIME.
-a
N'annonce pas la prise en charge de l'authentification SASL.
-A delai
Attend delai secondes après avoir répondu à DATA, puis abandonne prématurément avec un statut de réponse 550. Ne lit pas davantage d'entrées du client ; ceci est une tentative de bloquer le client avant qu'il n'envoie « . ». Spécifiez une valeur de délai nulle pour abandonner immédiatement.
-b reponse-rebond-souple
Utilise reponse-rebond-souple pour les réponses de rejet souples. La réponse par défaut est « 450 4.3.0 Erreur : commande échouée ».
-B reponse-rebond-dur
Utilise reponse-rebond-dur pour les réponses de rejet dures. La réponse par défaut est « 500 5.3.0 Erreur : commande échouée ».
-c
Affiche les compteurs actifs qui sont mis à jour chaque fois qu'une session SMTP se termine, qu'une commande QUIT est exécutée, ou lorsque « . » est reçu.
-C
Désactive la prise en charge de XCLIENT.
-d modele-extraction
Extrait chaque transaction de courrier dans un fichier de message unique dont le nom est créé en développant le modele-extraction via strftime(3) et en ajoutant un nombre hexadécimal pseudo-aléatoire (exemple : « %Y%m%d%H/%M. » se développe en « 2006081203/05.809a62e3 »). Si le modèle contient des caractères « / », les répertoires manquants sont créés automatiquement. Le format d'extraction du message est décrit ci-dessous.

Note : cette option maintient un fichier de capture ouvert pour chaque transaction de courrier en cours.

-D modele-extraction
Ajoute les transactions de courrier à un fichier d'extraction multi-messages dont le nom est créé en développant le modele-extraction via strftime(3). Si le modèle contient des caractères « / », les répertoires manquants sont créés automatiquement. Le format d'extraction du message est décrit ci-dessous.

Note : cette option maintient un fichier de capture ouvert pour chaque transaction de courrier en cours.

-e
N'annonce pas la prise en charge d'ESMTP.
-E
N'annonce pas la prise en charge de ENHANCEDSTATUSCODES.
-f commande,commande,...
Rejette les commandes spécifiées avec un code d'erreur dur (5xx). Cette option implique -p.

Les exemples de commandes sont CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP et QUIT. Séparez les noms de commande par des espaces blancs ou des virgules, et utilisez des guillemets pour protéger les espaces blancs du shell. Les noms de commande ne sont pas sensibles à la casse.

-F
Désactive la prise en charge de XFORWARD.
-h nom_hote
Utilise nom_hote dans le message d'accueil SMTP, la réponse HELO et la réponse EHLO. Le nom d'hôte par défaut est « smtp-sink ».
-H delai
Retarde la première opération de lecture après réception de DATA (délai en secondes). Combinez avec un gros message de test et une petite taille de fenêtre TCP (voir l'option -T) pour tester l'implémentation write_wait() du client Postfix.
-L
Active LMTP au lieu de SMTP.
-m nombre (défaut : 256)
Une limite supérieure sur le nombre maximal de connexions simultanées que smtp-sink gérera. Cela empêche le processus de manquer de descripteurs de fichiers. Les connexions excédentaires resteront mises en file d'attente dans la pile TCP/IP.
-M nombre
Termine après avoir reçu nombre messages.
-n nombre
Termine après nombre sessions.
-N
N'annonce pas la prise en charge de DSN.
-p
N'annonce pas la prise en charge du pipelining des commandes ESMTP.
-P
Modifie le message d'accueil du serveur pour qu'il semble provenir d'un système CISCO PIX. Implique -e.
-q commande,commande,...
Déconnecte (sans répondre) après avoir reçu l'une des commandes spécifiées.

Les exemples de commandes sont CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP et QUIT. Séparez les noms de commande par des espaces blancs ou des virgules, et utilisez des guillemets pour protéger les espaces blancs du shell. Les noms de commande ne sont pas sensibles à la casse.

-Q commande,commande,...
Envoie une réponse 421 et déconnecte après avoir reçu l'une des commandes spécifiées.

Les exemples de commandes sont CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP et QUIT. Séparez les noms de commande par des espaces blancs ou des virgules, et utilisez des guillemets pour protéger les espaces blancs du shell. Les noms de commande ne sont pas sensibles à la casse.

-r commande,commande,...
Rejette les commandes spécifiées avec un code d'erreur souple (4xx). Cette option implique -p.

Les exemples de commandes sont CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP et QUIT. Séparez les noms de commande par des espaces blancs ou des virgules, et utilisez des guillemets pour protéger les espaces blancs du shell. Les noms de commande ne sont pas sensibles à la casse.

-R repertoire-racine
Change le répertoire racine du processus à l'emplacement spécifié. Cette option nécessite des privilèges de super-utilisateur. Voir également l'option -u.
-s commande,commande,...
Journalise les commandes nommées dans syslogd.

Les exemples de commandes sont CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP et QUIT. Séparez les noms de commande par des espaces blancs ou des virgules, et utilisez des guillemets pour protéger les espaces blancs du shell. Les noms de commande ne sont pas sensibles à la casse.

-S chaine-debut
Une chaîne facultative qui est préfixée à chaque message écrit dans un fichier d'extraction (voir la description du format du fichier d'extraction ci-dessous). Les séquences d'échappement C suivantes sont prises en charge : \a (sonnerie), \b (retour arrière), \f (saut de page), \n (nouvelle ligne), \r (retour chariot), \t (tabulation horizontale), \v (tabulation verticale), \ddd (jusqu'à trois chiffres octaux) et \\ (le caractère antislash).
-t delai-expiration (défaut : 100)
Limite le temps de réception d'une commande ou d'envoi d'une réponse. Le délai d'expiration est spécifié en secondes.
-T taille-fenetre
Remplace la taille de fenêtre TCP par défaut. Pour contourner des implémentations de mise à l'échelle de fenêtre TCP défectueuses, spécifiez une valeur > 0 et < 65536.
-u

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

nomdutilisateur
Passe aux privilèges d'utilisateur spécifiés après l'ouverture du socket réseau et éventuellement le changement du répertoire racine du processus. Cette option est requise lorsque le processus s'exécute avec des privilèges de super-utilisateur. Voir aussi l'option -R.
-v
Affiche les conversations SMTP.
-w délai
Attend délai secondes avant de répondre à une commande DATA.
-W commande:délai[:probabilité]
Attend délai secondes avant de répondre à commande. Si probabilité est également spécifiée (un nombre compris entre 1 et 99 inclus), attend un multiple aléatoire de délai. Le multiplicateur aléatoire est égal au nombre de fois où le programme doit lancer un dé avec une plage de 0 à 99 inclus, avant que le dé ne produise un résultat supérieur ou égal à probabilité.
[inet:][hôte]:port
Écoute sur l'interface réseau hôte (par défaut : toute interface) du port TCP port. L'hôte et le port peuvent être spécifiés sous forme numérique ou symbolique.
unix:chemin
Écoute sur le socket de domaine UNIX au chemin.
backlog
La longueur maximale de la file d'attente des connexions en attente, telle que définie par l'appel système listen(2).

FORMAT DU FICHIER DE SAUVEGARDE

Chaque message sauvegardé contient une séquence de lignes de texte, terminées par le caractère de nouvelle ligne. La séquence d'informations est la suivante :

  • La chaîne optionnelle spécifiée avec l'option -S.
  • Les en-têtes générés par smtp-sink, tels que décrits ci-dessous.
  • L'en-tête et le corps du message tels que reçus du client SMTP.
  • Une ligne vide.

Le format des en-têtes générés par smtp-sink est le suivant :

X-Client-Addr: texte
L'adresse IP du client sans les crochets environnants. Une adresse IPv6 est préfixée par "ipv6:". Cet enregistrement est toujours présent.
X-Client-Proto: texte
Le protocole client : SMTP, ESMTP ou LMTP. Cet enregistrement est toujours présent.
X-Helo-Args: texte
Les arguments de la dernière commande HELO ou EHLO avant cette transaction de livraison de courrier. Cet enregistrement est présent uniquement si le client a envoyé une commande HELO ou EHLO reconnaissable avant la commande DATA.
X-Mail-Args: texte
Les arguments de la commande MAIL qui a démarré cette transaction de livraison de courrier. Cet enregistrement est présent exactement une fois.
X-Rcpt-Args: texte
Les arguments d'une commande RCPT dans cette transaction de livraison de courrier. Il y a un enregistrement pour chaque commande RCPT, et ils sont dans l'ordre où ils ont été envoyés par le client.
Received: texte
Un en-tête de message pour la compatibilité avec les logiciels de traitement de courrier. Cet en-tête de trois lignes marque la fin des en-têtes fournis par smtp-sink, et est formaté comme suit :
from helo ([addr])
L'argument de la commande HELO ou EHLO et l'adresse IP du client. Si le client n'a pas envoyé HELO ou EHLO, l'adresse IP du client est utilisée à la place.
by hôte (smtp-sink) with proto id aléatoire;
Le nom d'hôte spécifié avec l'option -h, le protocole client (voir X-Client-Proto ci-dessus), et la partie pseudo-aléatoire du nom de fichier de capture par message.
horodatage
Un horodatage tel que défini dans la RFC 2822.
