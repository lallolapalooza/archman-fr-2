NOM

smokeping_examples - Exemples de fichiers de configuration de Smokeping

APERÇU

Ce document fournit quelques exemples de fichiers de configuration de Smokeping. Tous les exemples se trouvent dans le répertoire "examples" de la documentation de Smokeping. Notez que les noms DNS dans les exemples ne sont pas fonctionnels.

Les détails de la syntaxe et toutes les variables se trouvent dans smokeping_config et dans la documentation de la sonde correspondante, le cas échéant.

Ce manuel est généré automatiquement à partir du code source de Smokeping, spécifiquement du module Smokeping::Examples.

DESCRIPTION

Actuellement, les exemples ne diffèrent que dans les sections "Probes" et "Targets". Les autres sections sont tirées du modèle de configuration "etc/config.dist" de la distribution Smokeping afin que les fichiers d'exemple soient complets.

Si vous souhaitez fournir plus d'exemples, documenter les autres sections ou améliorer les exemples existants, veuillez le faire, de préférence en envoyant les modifications proposées à la liste de diffusion smokeping-users.

Exemple 1: config.simple

Configuration de la sonde
*** Probes ***
+FPing
binary = /usr/bin/fping
Explication de la sonde

Ici, nous avons une seule sonde, fping, pingant quatre hôtes. La sonde fping utilise les paramètres par défaut, certains étant fournis par la section Database ("step" et "pings"), et d'autres par le module de sonde.

Configuration de la cible
*** Targets ***
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ mysite1
menu = Site 1
title = Hosts in Site 1

++ myhost1
host = myhost1.mysite1.example
++ myhost2
host = myhost2.mysite1.example

+ mysite2
menu = Site 2
title = Hosts in Site 2

++ myhost3
host = myhost3.mysite2.example
++ myhost4
host = myhost4.mysite2.example
Explication de la cible
Les hôtes sont situés dans deux sites de deux hôtes chacun, et la configuration a été divisée en sections de site ('+') et sous-sections d'hôte ('++') en conséquence.

Exemple 2: config.multiple-probes

Configuration de la sonde
*** Probes ***
+ FPing
binary = /usr/bin/fping
packetsize = 1000

+ DNS
binary = /usr/bin/dig
lookup = name.example
pings = 5
step = 180

+ EchoPingHttp
pings = 5
url = /test-url
Explication de la sonde

Ici, nous avons trois sondes : FPing pour les pings ICMP réguliers, DNS pour la mesure de latence du serveur de noms et EchoPingHttp pour les serveurs Web.

La sonde FPing fonctionne avec les paramètres par défaut, à l'exception que la taille du paquet ICMP est de 1000 octets au lieu des 56 octets par défaut.

Les sondes DNS et EchoPingHttp ont été configurées pour être un peu plus douces avec les serveurs, car elles n'effectuent que 5 requêtes (pings) au lieu des 20 par défaut (ou quelle que soit la valeur spécifiée dans la section Database). Cependant, les requêtes DNS sont effectuées plus fréquemment : 5 requêtes toutes les 3 minutes au lieu de toutes les 5 minutes.

Configuration de la cible
*** Targets ***
probe = FPing
menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ network
menu = Net latency
title = Network latency (ICMP pings)

++ myhost1
host = myhost1.example
++ myhost2
host = myhost2.example

+ services
menu = Service latency
title = Service latency (DNS, HTTP)

++ DNS
probe = DNS
menu = DNS latency
title = Service latency (DNS)

+++ dns1
host = dns1.example

+++ dns2
host = dns2.example

++ HTTP
menu = HTTP latency
title = Service latency (HTTP)

+++ www1
host = www1.example

+++ www2
host = www2.example
Explication de la cible
L'arbre des cibles a été divisé par la sonde utilisée. Cela n'a pas à être le cas : chaque cible (sous)section peut utiliser une sonde différente, et la même sonde peut être utilisée dans différentes parties de l'arbre de configuration.

Exemple 3: config.fping-instances

Configuration de la sonde
*** Probes ***
+ FPing
binary = /usr/bin/fping

++ FPingNormal
offset = 0%

++ FPingLarge
packetsize = 5000
offset = 50%
Explication de la sonde

Cet exemple démontre le concept d'instances de sonde. Les sondes FPingLarge et FPingNormal sont indépendantes l'une de l'autre, elles utilisent simplement le même module, FPing. FPingNormal utilise les paramètres par défaut, tout comme FPingLarge à l'exception de la taille de paquet de 5 kilooctets. Les deux utilisent le même binaire fping, et son chemin est configuré dans la section supérieure FPing.

Les paramètres 'offset' garantissent que les sondes ne s'exécutent pas en même temps - FPingNormal s'exécute toutes les 5 minutes 'pleines' (par exemple, 8:00, 8:05, 8:10, etc., en temps universel) tandis que FPingLarge s'exécute à mi-chemin de ces intervalles (par exemple, 8:02:30, 8:07:30, etc.)

La section supérieure FPing ne définit pas une sonde en soi car elle a des sous-sections. Si nous voulions vraiment avoir une sonde nommée "FPing", nous pourrions le faire en créant une sous-section de ce nom.

Configuration de la cible
*** Targets ***
probe = FPingNormal
menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ network
menu = Net latency
title = Network latency (ICMP pings)

++ myhost1
menu = myhost1
title = ICMP latency for myhost1

+++ normal
title = Normal packetsize (56 bytes)
probe = FPingNormal
host = myhost1.example

+++ large
title = Large packetsize (5000 bytes)
probe = FPingLarge
host = myhost1.example

++ myhost2
menu = myhost2
title = ICMP latency for myhost2

+++ normal
title = Normal packetsize (56 bytes)
probe = FPingNormal
host = myhost2.example

+++ large
title = Large packetsize (5000 bytes)
probe = FPingLarge
host = myhost2.example
Explication de la cible
La section cible montre deux hôtes, myhost1.example et myhost2.example, étant pingés avec deux paquets ICMP de tailles différentes. Cette fois, l'arbre est divisé par l'hôte cible plutôt que par la sonde.

Exemple 4: config.targetvars-with-Curl

Configuration de la sonde
*** Probes ***
+ Curl
# probe-specific variables
binary = /usr/bin/curl
step = 60

# a default for this target-specific variable
urlformat = http://%host%/
Explication de la sonde

Cet exemple explique la différence entre les variables spécifiques à la sonde et spécifiques à la cible. Nous utilisons la sonde Curl pour cela.

Chaque sonde prend en charge au moins quelques variables spécifiques à la sonde. Les valeurs de ces variables sont communes à toutes les cibles de la sonde, et elles ne peuvent être configurées que dans la section Probes. Dans ce cas, les variables spécifiques à la sonde sont "binary" et "step".

Les variables spécifiques aux cibles sont prises en charge par la plupart des sondes, la seule exception notable étant la sonde FPing et ses dérivés. Les variables spécifiques aux cibles peuvent avoir des valeurs différentes pour différentes cibles. Elles peuvent être configurées dans les sections Probes et Targets. Les valeurs attribuées dans les sections Probes deviennent des valeurs par défaut qui peuvent être remplacées dans la section Targets.

La documentation de chaque sonde indique quelles sont ses variables spécifiques à la sonde et lesquelles sont spécifiques à la cible.

smokeping_examples(5) — smokeping — Extra

NAME

smokeping_examples - configuration file examples for smokeping

OVERVIEW

This document shows some example configuration files for the smokeping(1) daemon.

DESCRIPTION

This document contains sample configuration files for smokeping(1). You will likely want to start by copying the config.dist file to config and then customizing it.

Example 1: config.dist

This is the default configuration file shipped with Smokeping. It is heavily commented and explains all the available options.

Example 2: config.simple

Probe configuration
*** Probes ***
+ FPing
binary = /usr/bin/fping
Probe explanation
This is a very simple configuration which only uses the FPing probe.
Target configuration
*** Targets ***
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ example.com
menu = example.com
title = example.com
host = example.com
Target explanation
This configuration probes a single host: example.com.

Example 3: config.customprobe

Probe configuration
*** Probes ***
+ FPing
binary = /usr/bin/fping

+ MyProbe
program = /usr/local/bin/myprobe
 
    # probes can be given arguments like this:
    arguments = pps=10, timeout=100
Probe explanation
This configuration defines a custom probe named MyProbe. It expects an executable named myprobe to be present in /usr/local/bin. The probe is called with the arguments pps=10 and timeout=100.
Target configuration
*** Targets ***
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ MyHost
menu = MyHost
title = My Host
host = myhost.example

++ MyHost/Custom
menu = Custom
title = My Host (Custom Probe)
probe = MyProbe
host = myhost.example
Target explanation
This configuration probes myhost.example using the default FPing probe and also using the custom MyProbe probe.

Example 4: config.urlformat

Probe configuration
*** Probes ***
+ Curl
binary = /usr/bin/curl
# Note that Curl probe does not support target specific variables
# The host variable is still required, though.
Probe explanation
This configuration uses the Curl probe. Note that the Curl probe does not support target specific variables.
Target configuration
*** Targets ***
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ HTTP
menu = http
title = HTTP latency 

++ myhost1
menu = myhost1
title = HTTP latency for myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = HTTP latency for myhost2
host = myhost2.example

++ myhost3
menu = myhost3
title = HTTP latency for myhost3 (port 8080!)
host = myhost3.example
urlformat = http://%host%:8080/

+ FTP
menu = ftp
title = FTP latency
urlformat = ftp://%host%/

++ myhost1
menu = myhost1
title = FTP latency for myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = FTP latency for myhost2
host = myhost2.example
Target explanation

In this example, the urlformat variable is used to specify the URL format for the probes. The %host% placeholder is used to insert the target host name into the URL. The Curl probe does not support target-specific variables, but the host variable is still required as a placeholder for the %host% escape.

(The reason why the FPing probe does not support target-specific variables is simply the fact that the fping program measures all its targets in one go, so they all have the same parameters. The other probes ping their targets one at a time.)

Target configuration
*** Targets ***
probe = Curl
menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ HTTP
menu = http
title = HTTP latency 

++ myhost1
menu = myhost1
title = HTTP latency for myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = HTTP latency for myhost2
host = myhost2.example

++ myhost3
menu = myhost3
title = HTTP latency for myhost3 (port 8080!)
host = myhost3.example
urlformat = http://%host%:8080/

+ FTP
menu = ftp
title = FTP latency
urlformat = ftp://%host%/

++ myhost1
menu = myhost1
title = FTP latency for myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = FTP latency for myhost2
host = myhost2.example
Target explanation
The target tree is divided into an HTTP branch and an FTP one. The servers "myhost1.example" and "myhost2.example" are probed in both. The third server, "myhost3.example", only has an HTTP server, and it's in a non-standard port (8080).

The "urlformat" variable is specified for the whole FTP branch as "ftp://%host%/". For the HTTP branch, the default from the Probes section is used, except for myhost3, which overrides it to tag the port number into the URL.

The myhost3 assignment could just as well have included the hostname verbatim (ie. urlformat = http://myhost3.example:8080/) instead of using the %host% placeholder, but the host variable would still have been required (even though it wouldn't have been used for anything).

Example 5: config.echoping

Probe configuration
*** Probes ***
+ FPing
binary = /usr/bin/fping

# these expect to find echoping in /usr/bin
# if not, you'll have to specify the location separately for each probe
# + EchoPing         # uses TCP or UDP echo (port 7)
# + EchoPingDiscard  # uses TCP or UDP discard (port 9)
# + EchoPingChargen  # uses TCP chargen (port 19)
+ EchoPingSmtp       # SMTP (25/tcp) for mail servers
+ EchoPingHttps      # HTTPS (443/tcp) for web servers
+ EchoPingHttp       # HTTP (80/tcp) for web servers and caches
+ EchoPingIcp        # ICP (3130/udp) for caches
# these need at least echoping 6 with the corresponding plugins
+ EchoPingDNS        # DNS (53/udp or tcp) servers
+ EchoPingLDAP       # LDAP (389/tcp) servers
+ EchoPingWhois      # Whois (43/tcp) servers
Probe explanation
This example shows most of the echoping-derived probes in action.
Target configuration
*** Targets ***
# default probe
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ MyServers

menu = My Servers
title = My Servers 

++ www-server
menu = www-server
title = Web Server (www-server) / ICMP
# probe = FPing propagated from top
host = www-server.example

+++ http
menu = http
title = Web Server (www-server) / HTTP
probe = EchoPingHttp
host = www-server.example 
# default url is /

+++ https
menu = https
title = Web Server (www-server) / HTTPS
probe = EchoPingHttps
host = www-server.example

++ cache
menu = www-cache
title = Web Cache (www-cache) / ICMP
host = www-cache.example

+++ http
menu = http
title = www-cache / HTTP
probe = EchoPingHttp
host = www-cache.example
port = 8080 # use the squid port
url = http://www.somehost.example/

+++ icp
menu = icp
title = www-cache / ICP
probe = EchoPingIcp
host = www-cache.example
url = http://www.somehost.example/

++ mail
menu = mail-server
title = Mail Server (mail-server) / ICMP
host = mail-server.example

+++ smtp
menu = mail-server / SMTP
title = Mail Server (mail-server) / SMTP
probe = EchoPingSmtp
host = mail-server.example

++ ldap-server
menu = ldap-server
title = ldap-server / ICMP
host = ldap-server.example

+++ ldap
menu = ldap-server / LDAP
title = LDAP Server (ldap-server) / LDAP
probe = EchoPingLDAP
ldap_request = (objectclass=*)
host = ldap-server.example

++ name-server
menu = name-server
title = name-server / ICMP
host = name-server.example

+++ DNS
menu = name-server / DNS
title = DNS Server (name-server) / DNS
probe = EchoPingDNS
dns_request = name.example
host = name-server.example

++ whois-server
menu = whois-server
title = whois-server / ICMP
host = whois-server.example

+++ Whois
menu = whois-server / Whois
title = Whois Server (whois-server) / Whois
probe = EchoPingWhois
whois_request = domain.example
host = whois-server.example
Target explanation
All the servers are pinged both with ICMP (the FPing probe) and their respective echoping probe. The proxy server, www-cache, is probed with both HTTP requests and ICP requests for the same URL.

Example 6: config.template

Probe configuration
*** Probes ***

+ FPing

binary = /usr/sbin/fping

*** Slaves ***
secrets=/usr/etc/smokeping_secrets.dist
+boomer
display_name=boomer
color=0000ff

+slave2
