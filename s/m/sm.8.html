NOM

sm - Interface en ligne de commande pour le gestionnaire de stockage INN

SYNTAXE

sm [-cdHiqRrSs] [jeton ...]

DESCRIPTION

Le gestionnaire de stockage INN est le sous-système qui stocke et suit tous les articles et le backend de stockage dans lequel ils se trouvent. Tous les articles stockés se voient attribuer un jeton d'API de stockage. sm est une interface en ligne de commande pour ce gestionnaire de stockage, principalement utilisée pour récupérer des articles par ces jetons, mais aussi pour effectuer d'autres opérations sur le sous-système de stockage.

jeton est le jeton d'un article (la même chose qui est retournée par grephistory ou stockée dans le fichier history). Il ressemble à ceci :

@0502000005A4000000010000000000000000@

N'importe quel nombre de jetons peut être donné sur la ligne de commande pour toute fonction autre que -s. Si aucun n'est donné, sm lit normalement les jetons depuis l'entrée standard, un par ligne. L'opération par défaut consiste à récupérer et à écrire sur la sortie standard l'article correspondant pour chaque jeton donné.

Si -s est donné, sm stocke plutôt l'article donné sur l'entrée standard (au format natif, sauf si -R est donné, auquel cas le format filaire est attendu) en utilisant les règles normales du sous-système de stockage. Si l'article est stocké avec succès, le jeton de l'article est imprimé sur la sortie standard. Veuillez noter que cela ne fait aucune tentative d'écrire une entrée d'historique ou des données d'aperçu, et est donc utile uniquement dans des circonstances très spécifiques.

OPTIONS

-c
Affiche une forme claire et décodée du jeton d'API de stockage. Chaque partie du jeton est expliquée, dans une chaîne lisible par l'homme. Entre autres éléments, cette commande donne le chemin où l'article correspondant est censé être stocké.
-d, -r
Plutôt que de récupérer l'article spécifié, supprimez l'article. Cela supprimera l'article de la file d'attente des nouvelles et il ne sera plus récupérable par aucune partie d'INN. C'est équivalent à "ctlinnd cancel" sauf que cela prend un jeton d'API de stockage au lieu d'un identifiant de message.
-H
Récupère uniquement les en-têtes de l'article plutôt que l'article entier. Cette option ne peut pas être utilisée avec -d, -r, -i, ou -S.
-i
Affiche le nom du groupe de nouvelles et le numéro d'article associés au jeton plutôt que l'article lui-même. Notez que pour les articles cross-postés, seul le premier groupe de nouvelles et le numéro d'article auxquels l'article est associé seront retournés.
-q
Supprime tous les messages d'erreur sauf les erreurs d'utilisation.
-R
Affiche l'article brut. Cela signifie que les fins de ligne ne seront pas converties en fins de ligne natives et resteront des séquences CRLF ; les points de début seront toujours échappés pour l'envoi via NNTP, et l'article se terminera par une séquence CRLF.CRLF.

Lorsqu'elle est utilisée avec -s, lit les articles au format filaire.

-S
Écrit l'article sur la sortie standard dans le format utilisé par les fichiers de spool de rnews. Plusieurs articles peuvent être écrits dans ce format, et la sortie résultante peut être fournie à rnews (sur un autre système, par exemple) pour injecter ces articles dans INN. Cette option ne peut pas être utilisée avec -d, -r, -H, -i, ou -R.
-s
Stocke l'article donné sur l'entrée standard en utilisant les règles de stockage normales pour les articles telles que configurées dans storage.conf(5). Imprime le nouveau jeton pour le message sur la sortie standard s'il est stocké avec succès. Si cette option est donnée, aucune autre option sauf -R et éventuellement -q ne devrait être donnée. Lorsque -R est donné, n'importe quel nombre d'articles au format filaire est lu sur l'entrée standard et stocké.

STATUT DE SORTIE

Si toutes les opérations ont réussi, sm se termine avec le statut 0. Si une opération sur l'un des jetons fournis échoue, sm se terminera avec le statut 1, même si les opérations sur d'autres jetons ont réussi. En d'autres termes, si vingt jetons sont fournis à "sm -r" sur stdin, 19 articles ont été supprimés avec succès, mais le sixième article n'a pas pu être trouvé, sm se terminera toujours avec le statut 1.

Cela signifie que si vous devez être sûr qu'une opération particulière a réussi, vous devriez exécuter sm sur un jeton à la fois.
