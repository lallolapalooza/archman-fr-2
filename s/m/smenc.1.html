NOM

smenc - Programme pour encoder un fichier wav dans un modèle SpectMorph

SYNTAXE

smenc [OPTIONS] Fichier-WAV [Fichier-SM]

DESCRIPTION

smenc est un outil en ligne de commande pour créer des modèles SpectMorph à partir de fichiers audio. Habituellement, le fichier d'entrée doit contenir une seule note d'un instrument, comme une seule note Do4. Comme les notes graves nécessitent des paramètres d'analyse différents des notes aiguës, il est généralement judicieux d'utiliser l'option -m pour informer l'algorithme d'encodage de la note encodée.

Il y a également un compromis qualité/temps, ce qui signifie que vous pouvez utiliser l'option -O0, -O1 ou -O2 pour spécifier la précision de l'analyse, les nombres plus élevés signifiant une meilleure qualité, mais un temps d'analyse plus long.

Pour les entrées multi-canaux, chaque canal est encodé séparément. Si vous ne spécifiez pas le nom du fichier de sortie, l'encodeur créera par exemple piano-ch0.sm et piano-ch1.sm à partir du fichier stéréo piano.wav. Si vous spécifiez un nom de fichier de sortie, vous devez y inclure un %c, comme piano-ch%c.sm, qui sera substitué par le numéro du canal.

OPTIONS

smenc suit la syntaxe habituelle des lignes de commande GNU, avec des options longues commençant par deux tirets ('-').

-h, --help
Affiche un bref message d'aide.
-v, --version
Affiche la version de smenc.
-f <fréquence>
Spécifie la fréquence fondamentale en Hz - cette information est facultative, mais doit être fournie lorsqu'elle est connue, afin d'augmenter la précision du modèle. Elle est équivalente à spécifier la note midi ; une seule des options -m et -f doit être utilisée.
-m <note-midi>
Spécifie la note midi de l'entrée ; elle sera utilisée pour définir la fréquence fondamentale en Hz. Cette information n'est pas obligatoire, mais augmente la précision de l'algorithme d'analyse. Une seule des options -m et -f doit être utilisée.
-O <niveau>
Pour toutes les trames du fichier d'entrée, une fois que smenc a déterminé quelles ondes sinusoïdales peuvent être utilisées pour décrire la trame, il doit estimer l'amplitude et la phase de chaque onde sinusoïdale pour cette trame. Le niveau d'optimisation choisit l'algorithme utilisé pour trouver l'amplitude et la phase ; plus le niveau est élevé, plus le résultat sera précis. Cependant, il est réglé par défaut sur -O0, car c'est l'algorithme le plus rapide : estimation de l'amplitude/phase à partir du résultat FFT. Un bon choix est -O1, qui est un peu plus lent, mais aussi un peu meilleur.
-s
Actuellement, smenc inclut par défaut beaucoup d'informations pour rejouer le fichier. Par conséquent, les fichiers créés par smenc sont très volumineux par défaut. Pour limiter la taille du fichier, l'utilisation de l'option -s indique à smenc de créer un modèle "déshabillé", qui ne contient que les informations nécessaires pour le jouer. Ces modèles déshabillés sont généralement beaucoup plus petits que les modèles non déshabillés.
--no-attack
Par défaut, smenc essaie de trouver une enveloppe d'attaque au début de l'entrée, qui décrit à quel moment l'attaque se produit et sa vitesse. Cette option désactive cette étape (qui consomme beaucoup de temps CPU).
--no-sines
Ignore l'analyse de la partie sinusoïdale du signal (suivi de partiels).
--loop-start
Définit le point de début de boucle (en échantillons) - le type de boucle est défini sur timeloop.
--loop-end
Définit le point de fin de boucle (en échantillons) - le type de boucle est défini sur timeloop.
