NOM

smartpqi - Pilote SCSI pour Microchip Smart Storage

SYNTAXE

modprobe smartpqi [disable_device_id_wildcards={0|1}] [disable_heartbeat={0|1}] [disable_ctrl_shutdown={0|1}] [lockup_action={none|reboot|panic}] [expose_ld_first={0|1}] [hide_vsep={0|1}] [disable_managed_interrupts={0|1}] [ctrl_ready_timeout={0|[30,1800]}]

DESCRIPTION

smartpqi est un pilote SCSI pour les contrôleurs Microchip Smart Storage.

Opérations ioctl() supportées

Pour la compatibilité avec les applications écrites pour les pilotes cciss(4) et hpsa(4), plusieurs, mais pas toutes les opérations ioctl(2) supportées par le pilote hpsa sont également supportées par le pilote smartpqi. Les structures de données utilisées par ces opérations sont décrites dans le fichier source du noyau Linux include/linux/cciss_ioctl.h.

CCISS_DEREGDISK
CCISS_REGNEWDISK
CCISS_REGNEWD
Ces opérations font exactement la même chose, c'est-à-dire provoquer une nouvelle analyse des périphériques par le pilote. Cela fait exactement la même chose qu'écrire dans l'attribut rescan spécifique au contrôleur smartpqi.
CCISS_GETPCIINFO
Cette opération renvoie le domaine PCI, le bus, le périphérique, la fonction et l'"ID de la carte" (ID du sous-système PCI).
CCISS_GETDRIVVER
Cette opération renvoie la version du pilote en quatre octets, encodée comme suit :

(major_version << 28) | (minor_version << 24) |
        (release << 16) | revision

CCISS_PASSTHRU
Permet de transmettre des commandes BMIC et CISS au contrôleur.

Options de démarrage

disable_device_id_wildcards={0|1}
Désactive la prise en charge des caractères génériques pour les ID de périphérique. La valeur par défaut est 0 (les caractères génériques sont activés).
disable_heartbeat={0|1}
Désactive la prise en charge de la vérification du battement de cœur du contrôleur. Ce paramètre est utilisé à des fins de débogage. La valeur par défaut est 0 (la vérification du battement de cœur du contrôleur est activée).
disable_ctrl_shutdown={0|1}
Désactive la prise en charge de l'arrêt du contrôleur en cas de blocage du contrôleur. La valeur par défaut est 0 (le contrôleur sera arrêté).
lockup_action={none|reboot|panic}
Spécifie l'action entreprise par le pilote lorsqu'un blocage du contrôleur est détecté. L'action par défaut est none.
paramètre action
none mettre le contrôleur hors ligne uniquement
reboot redémarrer le système
panic faire paniquer le système
expose_ld_first={0|1}
Cette option expose les périphériques logiques au système d'exploitation avant les périphériques physiques. La valeur par défaut est 0 (les périphériques physiques sont exposés en premier).
hide_vsep={0|1}
Cette option désactive l'exposition du SEP virtuel au système d'exploitation. La valeur par défaut est 0 (le SEP virtuel est exposé).
disable_managed_interrupts={0|1}
Désactive l'utilisation par le pilote des interruptions gérées par le noyau Linux pour les contrôleurs. La fonctionnalité d'interruptions gérées distribue automatiquement les interruptions à tous les CPU disponibles et attribue l'affinité SMP. La valeur par défaut est 0 (interruptions gérées activées).
ctrl_ready_timeout={0|[30,1800]}
Cette option spécifie le délai d'attente en secondes pendant lequel le pilote attend que le contrôleur soit prêt. La plage valide est 0 ou [30, 1800]. La valeur par défaut est 0, ce qui entraîne un délai d'attente de 180 secondes pour le pilote.

FICHIERS

Nœuds de périphériques

Les lecteurs de disques sont accessibles via le pilote de disque SCSI (sd), les lecteurs de bandes via le pilote de bande SCSI (st), et le contrôleur RAID via le pilote générique SCSI (sg), avec des noms de nœuds de périphérique respectivement /dev/sd*, /dev/st* et /dev/sg*.

Fichiers d'attributs spécifiques à SmartPQI dans /sys

/sys/class/scsi_host/host*/rescan
L'attribut rescan de l'hôte est un attribut en écriture seule. L'écriture dans cet attribut amène le pilote à rechercher les périphériques nouveaux, modifiés ou supprimés (par exemple, lecteurs de bandes enfichables à chaud, ou volumes logiques nouvellement configurés ou supprimés) et à notifier la couche intermédiaire SCSI de tout changement détecté. Généralement, cette action est déclenchée automatiquement par des modifications de configuration, l'utilisateur ne devrait donc normalement pas avoir à écrire dans ce fichier. Cela peut être utile lors de l'enfichage à chaud de périphériques tels que des lecteurs de bandes ou des boîtes de stockage entières contenant des volumes logiques préconfigurés.
/sys/class/scsi_host/host*/lockup_action
L'attribut lockup_action de l'hôte est un attribut en lecture/écriture. Cet attribut amène le pilote à effectuer une action dans le cas peu probable où un blocage du contrôleur serait détecté. Voir OPTIONS ci-dessus pour une explication des valeurs de lockup_action.
/sys/class/scsi_host/host*/driver_version
L'attribut driver_version est en lecture seule. Cet attribut contient la version du pilote smartpqi.
Par exemple :

$ 
cat /sys/class/scsi_host/host1/driver_version
1.1.2-126

/sys/class/scsi_host/host*/firmware_version
L'attribut firmware_version est en lecture seule. Cet attribut contient la version du firmware du contrôleur.
Par exemple :

$ 
cat /sys/class/scsi_host/host1/firmware_version
1.29-112

/sys/class/scsi_host/host*/model
L'attribut model est en lecture seule. Cet attribut contient la chaîne d'identification du produit du contrôleur.
Par exemple :

$ 
cat /sys/class/scsi_host/host1/model
1100-16i

NAME


smartpqi - Microchip SmartPQI RAID controller driver






SYNOPSIS


smartpqi







DESCRIPTION


The smartpqi driver provides support for
    Microchip SmartPQI RAID controllers.


This driver uses the sysfs interface to provide information about
    the controller and its associated disks. The sysfs filesystem provides a way
    to inspect and configure kernel parameters and devices.


The sysfs files used by this driver are organized under
    /sys/class/scsi_host/host* and /sys/class/scsi_disk/*.




Controller attribute files in /sys


In the file specifications below, * stands for the controller
    number.



  
/sys/class/scsi_host/host*/version

  
The version attribute is read-only. This attribute contains the
      driver version string.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_host/host1/version
smartpqi 1.1.14-1.0.1-RH


    

  





  
/sys/class/scsi_host/host*/firmware_version

  
The firmware_version attribute is read-only. This attribute
      contains the firmware version string.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_host/host1/firmware_version
3.45.00.1


    

  





  
/sys/class/scsi_host/host*/driver_version

  
The driver_version attribute is read-only. This attribute contains
      the driver version string.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_host/host1/driver_version
smartpqi 1.1.14-1.0.1-RH


    

  





  
/sys/class/scsi_host/host*/serial_number

  
The serial_number attribute is read-only. This attribute contains
      the serial number of the controller.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_host/host1/serial_number
6A316373777


    

  





  
/sys/class/scsi_host/host*/vendor

  
The vendor attribute is read-only. This attribute contains the
      vendor identification string of the controller.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_host/host1/vendor
Adaptec


    

  





  
/sys/class/scsi_host/host*/enable_stream_detection

  
The enable_stream_detection attribute is read-write. This attribute
      enables/disables stream detection in the driver. Enabling stream detection
      can improve sequential write performance for ioaccel-enabled volumes. See
      the ssd_smart_path_enabled disk attribute section for details on
      ioaccel-enabled volumes. The default value is 1 (stream detection
      enabled).





  

  
Enable example:

  

  

    

    
$ 
echo 1 > /sys/class/scsi_host/host1/enable_stream_detection


    

  





  
/sys/class/scsi_host/host*/enable_r5_writes

  
The enable_r5_writes attribute is read-write. This attribute
      enables/disables RAID 5 write operations for ioaccel-enabled volumes.
      Enabling can improve sequential write performance. See the
      ssd_smart_path_enabled disk attribute section for details on
      ioaccel-enabled volumes. The default value is 1 (RAID 5 writes
    enabled).





  

  
Enable example:

  

  

    

    
$ 
echo 1 > /sys/class/scsi_host/host1/enable_r5_writes


    

  





  
/sys/class/scsi_host/host*/enable_r6_writes

  
The enable_r6_writes attribute is read-write. This attribute
      enables/disables RAID 6 write operations for ioaccel-enabled volumes.
      Enabling can improve sequential write performance. See the
      ssd_smart_path_enabled disk attribute section for details on
      ioaccel-enabled volumes. The default value is 1 (RAID 6 writes
    enabled).





  

  
Enable example:

  

  

    

    
$ 
echo 1 > /sys/class/scsi_host/host1/enable_r6_writes


    

  








SmartPQI-specific   disk attribute files in /sys


In the file specifications below, c stands for the number
    of the appropriate SCSI controller, b is the bus number, t the
    target number, and l is the logical unit number (LUN).



  
/sys/class/scsi_disk/c:b:t:l/device/raid_level

  
The raid_level attribute is read-only. This attribute contains the
      RAID level of the logical volume.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/4:0:0:0/device/raid_level
RAID 0


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/sas_address

  
The sas_address attribute is read-only. This attribute contains the
      SAS address of the device.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/1:0:3:0/device/sas_address
0x5001173d028543a2


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/ssd_smart_path_enabled

  
The ssd_smart_path_enabled attribute is read-only. This attribute
      is for ioaccel-enabled volumes. (Ioaccel is an alternative driver
      submission path that allows the driver to send I/O requests directly to
      backend SCSI devices, bypassing the controller firmware. This results in
      an increase in performance. This method is used for HBA disks and for
      logical volumes comprised of SSDs.) Contains 1 if ioaccel is enabled for
      the volume and 0 otherwise.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/1:0:3:0/device/ssd_smart_path_enabled
0


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/lunid

  
The lunid attribute is read-only. This attribute contains the SCSI
      LUN ID for the device.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/13:1:0:3/device/lunid
0x0300004000000000


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/unique_id

  
The unique_id attribute is read-only. This attribute contains a
      16-byte ID that uniquely identifies the device within the controller.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/13:1:0:3/device/unique_id
600508B1001C6D4723A8E98D704FDB94


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/path_info

  
The path_info attribute is read-only. This attribute contains the
      c:b:t:l of the device along with the device
      type and whether the device is Active or Inactive. If the device is an HBA
      device, path_info will also display the PORT, BOX, and BAY the
      device is plugged into.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/13:1:0:3/device/path_info
[13:1:0:3]    Direct-Access     Active
$ 
cat /sys/class/scsi_disk/12:0:9:0/device/path_info
[12:0:9:0]  Direct-Access   PORT: C1 BOX: 1 BAY: 14 Inactive
[12:0:9:0]  Direct-Access   PORT: C0 BOX: 1 BAY: 14 Active


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/raid_bypass_cnt

  
The raid_bypass_cnt attribute is read-only. This attribute contains
      the number of I/O requests that have gone through the ioaccel path for
      ioaccel-enabled volumes. See the ssd_smart_path_enabled disk
      attribute section for details on ioaccel-enabled volumes.





  

  
For example:

  

  

    

    
$ 
cat /sys/class/scsi_disk/13:1:0:3/device/raid_bypass_cnt
0x300


    

  





  
/sys/class/scsi_disk/c:b:t:l/device/sas_ncq_prio_enable

  
The sas_ncq_prio_enable attribute is read/write. This attribute
      enables SATA NCQ priority support. This attribute works only when device
      has NCQ support and controller firmware can handle IO with NCQ priority
      attribute.





  

  
For example:

  

  

    

    
$ 
echo 1 > /sys/class/scsi_disk/13:1:0:3/device/sas_ncq_prio_enable


    

  










VERSIONS


The smartpqi driver was added in Linux 4.9.






NOTES




Configuration


To configure a Microchip Smart Storage controller, refer to the
    User Guide for the controller, which can be found by searching for the
    specific controller at
    https://www.microchip.com/design-centers/storage.

NOM

smartpqi - Pilote de contrôleur RAID Microchip SmartPQI

SYNOPSIS

smartpqi

DESCRIPTION

Le pilote smartpqi fournit une prise en charge des contrôleurs RAID Microchip SmartPQI.

Ce pilote utilise l'interface sysfs pour fournir des informations sur le contrôleur et ses disques associés. Le système de fichiers sysfs fournit un moyen d'inspecter et de configurer les paramètres et les périphériques du noyau.

Les fichiers sysfs utilisés par ce pilote sont organisés sous /sys/class/scsi_host/host* et /sys/class/scsi_disk/*.
