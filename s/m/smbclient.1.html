SMBCLIENT(1) Commandes Utilisateur SMBCLIENT(1)

NOM

smbclient - client de type ftp pour accéder aux ressources SMB/CIFS sur les serveurs

SYNTAXE

smbclient [-M|--message=HOTE] [-I|--ip-address=IP] [-E|--stderr] [-L|--list=HOTE] [-T|--tar=<c|x>IXFvgbNan] [-D|--directory=DIR] [-b|--send-buffer=OCTETS] [-t|--timeout=SECONDES] [-p|--port=PORT] [-g|--grepable] [-q|--quiet] [-B|--browse] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [-s|--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=BASE_NOM_FICHIER_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOLUTION_NOMS] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=PROTOCOLE_MAX] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=PORTEE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR%[MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=voulu|requis|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] [-c|--command=CHAINE]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

smbclient est un client qui peut "parler" à un serveur SMB/CIFS. Il offre une interface similaire à celle du programme ftp (voir ftp(1)). Les opérations incluent des actions telles que récupérer des fichiers du serveur vers la machine locale, envoyer des fichiers de la machine locale vers le serveur, récupérer des informations de répertoire depuis le serveur, etc.

OPTIONS

nom_service

nom_service est le nom du service que vous souhaitez utiliser sur le serveur. Un nom de service prend la forme //serveur/service où serveur est le nom NetBIOS du serveur SMB/CIFS offrant le service désiré et service est le nom du service offert. Ainsi, pour vous connecter au service "printer" sur le serveur SMB/CIFS "smbserver", vous utiliseriez le nom_service //smbserver/printer

Notez que le nom du serveur requis N'EST PAS nécessairement le nom d'hôte IP (DNS) du serveur ! Le nom requis est un nom de serveur NetBIOS, qui peut ou non être identique au nom d'hôte IP de la machine exécutant le serveur.

Le nom du serveur est recherché soit selon le paramètre -R|--name-resolve de smbclient, soit en utilisant l'ordre de résolution des noms dans le fichier smb.conf(5), permettant à un administrateur de modifier l'ordre et les méthodes de recherche des noms de serveurs.

mot_de_passe

Le mot de passe requis pour accéder au service spécifié sur le serveur spécifié. Si ce paramètre est fourni, l'option -N (supprimer la demande de mot de passe) est supposée.

Il n'y a pas de mot de passe par défaut. Si aucun mot de passe n'est fourni sur la ligne de commande (soit en utilisant ce paramètre, soit en ajoutant un mot de passe à l'option -U (voir ci-dessous)) et que l'option -N n'est pas spécifiée, le client demandera un mot de passe, même si le service désiré n'en requiert pas. (Si aucun mot de passe n'est requis, appuyez simplement sur ENTREE pour fournir un mot de passe nul.)

Remarque : Certains serveurs (y compris OS/2 et Windows for Workgroups) insistent sur un mot de passe en majuscules. Les mots de passe en minuscules ou mixtes peuvent être rejetés par ces serveurs.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts.

-M|--message nom_netbios

Cette option vous permet d'envoyer des messages, en utilisant le protocole "WinPopup", à un autre ordinateur. Une fois la connexion établie, vous tapez votre message, puis appuyez sur ^D (contrôle-D) pour terminer.

Si l'ordinateur récepteur exécute WinPopup, l'utilisateur recevra le message et probablement un bip sonore. S'il n'exécute pas WinPopup, le message sera perdu et aucun message d'erreur ne sera généré.

Le message est également automatiquement tronqué si sa taille dépasse 1600 octets, car c'est la limite du protocole.

Une astuce utile est de faire passer le message par smbclient. Par exemple : smbclient -M FRED < monmessage.txt enverra le message contenu dans le fichier monmessage.txt à la machine FRED.

Vous pourriez également trouver utiles les options -U et -I, car elles vous permettent de contrôler les parties DE et À du message.

Voir le paramètre message command dans smb.conf(5) pour une description de la manière de gérer les messages WinPopup entrants dans Samba.

Remarque : Copiez WinPopup dans le groupe de démarrage sur vos PC WfWg si vous souhaitez qu'ils soient toujours capables de recevoir des messages.

-p|--port port

Ce numéro est le numéro de port TCP qui sera utilisé lors de la connexion au serveur. Le numéro de port TCP standard (bien connu) pour un serveur SMB/CIFS est 139, ce qui est le défaut.

-g|--grepable

Ce paramètre, combiné avec -L, fournit une sortie facile à analyser qui permet le traitement avec des utilitaires tels que grep et cut.

-m|--max-protocol protocole

Cela permet à l'utilisateur de sélectionner le niveau de protocole SMB le plus élevé que smbclient utilisera pour se connecter au serveur. Par défaut, il est défini à la version la plus élevée du protocole SMB3 disponible. Pour se connecter en utilisant le protocole SMB2 ou SMB1, utilisez respectivement les chaînes SMB2 ou NT1. Notez que pour se connecter à un serveur Windows 2012 avec transport chiffré, la sélection d'un protocole maximal de SMB3 est requise.

-P|--machine-pass

Effectue des requêtes au serveur externe en utilisant le compte machine du serveur local.

-I|--ip-address IP-address

Adresse IP est l'adresse du serveur auquel se connecter. Elle doit être spécifiée dans la notation standard "a.b.c.d".

Normalement, le client tenterait de localiser un serveur SMB/CIFS nommé en le recherchant via le mécanisme de résolution de noms NetBIOS décrit ci-dessus dans le paramètre ordre de résolution des noms ci-dessus. L'utilisation de ce paramètre forcera le client à supposer que le serveur se trouve sur la machine avec l'adresse IP spécifiée et que le composant nom NetBIOS de la ressource à laquelle on se connecte sera ignoré.

Il n'y a pas de valeur par défaut pour ce paramètre. S'il n'est pas fourni, il sera déterminé automatiquement par le client comme décrit ci-dessus.

-E|--stderr

Ce paramètre fait que le client écrit les messages sur le flux d'erreur standard (stderr) plutôt que sur le flux de sortie standard.

Par défaut, le client écrit les messages sur la sortie standard - typiquement le tty de l'utilisateur.

-L|--list

Cette option vous permet de voir quels services sont disponibles sur un serveur. Vous l'utilisez comme smbclient -L hôte et une liste devrait apparaître. L'option -I peut être utile si vos noms NetBIOS ne correspondent pas à vos noms d'hôte DNS TCP/IP ou si vous essayez d'atteindre un hôte sur un autre réseau.

-b|--send-buffer taille_buffer

Lors de l'envoi ou de la réception de fichiers, smbclient utilise un tampon interne dont la taille est déterminée par le nombre maximum de requêtes autorisées au serveur connecté. Cette commande permet de régler cette taille dans une plage comprise entre 0 (ce qui signifie utiliser la taille par défaut contrôlée par le serveur) octets et 16776960 (0xFFFF00) octets. L'utilisation de la taille contrôlée par le serveur est la plus efficace, car smbclient mettra en pipeline autant de lectures ou d'écritures simultanées que nécessaire pour maintenir le serveur aussi occupé que possible. Le réglage sur toute autre taille ralentira le transfert. Ceci peut également être réglé en utilisant la commande iosize à l'intérieur de smbclient.

-B|--browse

Parcourir les serveurs SMB en utilisant DNS.

-t|--timeout <secondes_timeout>

Cela permet à l'utilisateur de régler le délai d'attente par défaut utilisé pour chaque requête SMB. Le réglage par défaut est de 20 secondes. Augmentez-le si les requêtes au serveur expirent parfois. Cela peut se produire lorsque le chiffrement SMB3 est sélectionné et que smbclient submerge le serveur de requêtes. Cela peut également être réglé en utilisant la commande timeout à l'intérieur de smbclient.

-T|--tar options_tar

smbclient peut être utilisé pour créer des sauvegardes compatibles avec tar(1) de tous les fichiers sur un partage SMB/CIFS. Les options tar secondaires qui peuvent être données à cette option sont :
•c - Créer une archive de sauvegarde tar sur le système local. Doit être suivi du nom d'un fichier tar, d'un périphérique de bande ou de "-" pour la sortie standard. Si vous utilisez la sortie standard, vous devez régler le niveau de journalisation à sa valeur la plus basse -d0 pour éviter de corrompre votre fichier tar. Ce drapeau est mutuellement exclusif avec le drapeau x.
•n - En combinaison avec le drapeau c, ne pas
en fait, créez l'archive, au lieu de cela effectuez un essai à blanc qui tente tout ce qui est impliqué dans la création autre que l'écriture du fichier.
•x - Extraire (restaurer) un fichier tar local vers un partage. Sauf si l'option -D est donnée, les fichiers tar seront restaurés depuis le niveau supérieur du partage. Doit être suivi du nom du fichier tar, périphérique ou "-" pour l'entrée standard. Mutuellement exclusif avec le flag c. Les fichiers restaurés ont leurs temps de création (mtime) définis à la date enregistrée dans le fichier tar. Les répertoires ne voient actuellement pas leurs dates de création restaurées correctement.
•I - Inclure les fichiers et répertoires. Est le comportement par défaut lorsque des noms de fichiers sont spécifiés ci-dessus. Provoque l'inclusion des fichiers dans une extraction ou une création (et donc l'exclusion de tout le reste). Voir l'exemple ci-dessous. La recherche de noms de fichiers fonctionne de l'une des deux manières. Voir r ci-dessous.
•X - Exclure les fichiers et répertoires. Provoque l'exclusion des fichiers d'une extraction ou d'une création. Voir l'exemple ci-dessous. La recherche de noms de fichiers fonctionne de l'une des deux manières. Voir r ci-dessous.
•F - Fichier contenant une liste de fichiers et répertoires. Le F fait que le nom suivant le fichier tar à créer soit lu comme un nom de fichier contenant une liste de fichiers et répertoires à inclure dans une extraction ou une création (et donc tout le reste à exclure). Voir l'exemple ci-dessous. La recherche de noms de fichiers fonctionne de l'une des deux manières. Voir r ci-dessous.
•b - Taille de bloc. Doit être suivi d'une taille de bloc valide (supérieure à zéro). Provoque l'écriture du fichier tar en blocs de taille de bloc * TBLOCK (512 octets).
•g - Incrémental. Sauvegarde uniquement les fichiers dont le bit d'archive est défini. Utile uniquement avec le flag c.
•v - Verbeux. Fait imprimer par tar les fichiers en cours de traitement. Par défaut, tar n'est pas verbeux. Ceci est identique à verbose en mode tar.
•r - Utiliser la mise en correspondance de caractères génériques pour inclure ou exclure. Obsolète.
•N - Plus récent que. Doit être suivi du nom d'un fichier dont la date est comparée aux fichiers trouvés sur le partage lors d'une création. Seuls les fichiers plus récents que le fichier spécifié sont sauvegardés dans le fichier tar. Utile uniquement avec le flag c.
•a - Définir le bit d'archive. Provoque la réinitialisation du bit d'archive lorsqu'un fichier est sauvegardé. Utile avec les flags g et c.
Noms de fichiers longs dans Tar

L'option tar de smbclient prend désormais en charge les noms de fichiers longs en sauvegarde comme en restauration. Cependant, le chemin complet du fichier doit être inférieur à 1024 octets. De plus, lorsqu'une archive tar est créée, l'option tar de smbclient place tous les fichiers de l'archive avec des noms relatifs, et non des noms absolus.

Noms de fichiers Tar

Tous les noms de fichiers peuvent être donnés en noms de chemins DOS (avec '\\' comme séparateur de composant) ou en noms de chemins UNIX (avec '/' comme séparateur de composant).

Exemples

Restauration à partir du fichier tar backup.tar dans myshare sur mypc (pas de mot de passe sur le partage).

smbclient //mypc/myshare "" -N -Tx backup.tar

Restauration de tout sauf de users/docs

smbclient //mypc/myshare "" -N -TXx backup.tar users/docs

Création d'un fichier tar des fichiers sous users/docs.

smbclient //mypc/myshare "" -N -Tc backup.tar users/docs

Création du même fichier tar qu'auparavant, mais en utilisant maintenant un nom de chemin DOS.

smbclient //mypc/myshare "" -N -Tc backup.tar users\edocs

Création d'un fichier tar des fichiers listés dans le fichier tarlist.

smbclient //mypc/myshare "" -N -TcF backup.tar tarlist

Création d'un fichier tar de tous les fichiers et répertoires du partage.

smbclient //mypc/myshare "" -N -Tc backup.tar *

-D|--directory répertoire initial

Changez de répertoire avant de commencer. Probablement utile uniquement avec l'option tar -T.

-c|--command chaîne de commande

la chaîne de commande est une liste de commandes séparées par des points-virgules à exécuter au lieu de demander depuis stdin. -N est implicite par -c.

Ceci est particulièrement utile dans les scripts et pour imprimer stdin sur le serveur, par exemple -c 'print -'.

-?|--help

Imprimer un résumé des options de la ligne de commande.

--usage

Afficher un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications clientes.

Plus cette valeur est élevée, plus les informations détaillées seront enregistrées dans les fichiers journaux sur les activités du serveur. Au niveau 0, seules les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre remplacera le paramètre niveau de journal dans le fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients journalisent vers STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations contenues dans ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Cela remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur contient un espace, entourez --option=name=value de guillemets.

-l|--log-basename=répertoire de journalisation

Nom de base du répertoire pour les fichiers de journalisation/débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc.). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le reporting de fuite talloc à la sortie.

--leak-report-full

Active le reporting complet de fuite talloc à la sortie.

-V|--version

Imprime le numéro de version du programme.

-R|--name-resolve=RÉSOLUTION-NOM

Cette option est utilisée pour déterminer quels services de noms et dans quel ordre résoudre les noms d'hôtes en adresses IP. L'option prend une chaîne d'options de résolution de noms séparées par des espaces. Il est préférable d'encadrer l'ensemble --name-resolve=NAME-RESOLVE-ORDER avec des guillemets.

Les options sont : "lmhosts", "host", "wins" et "bcast". Elles provoquent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir lmhosts(5) pour les détails), alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution de nom d'hôte en adresse IP standard, en utilisant les recherches /etc/hosts, NIS ou DNS du système. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, cela peut être contrôlé par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP listée dans le paramètre serveur wins. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Diffuse sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend de l'hôte cible étant sur un sous-réseau connecté localement.
Si ce paramètre n'est pas défini, l'ordre de résolution de noms défini dans le paramètre du fichier /etc/samba/smb.conf (ordre de résolution de noms) sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ni aucune entrée dans le paramètre ordre de résolution de noms du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=OPTIONS SOCKET

Options de socket TCP à définir sur le socket client. Voir le paramètre options de socket dans la page de manuel de /etc/samba/smb.conf pour la liste des options valides.

-m|--max-protocol=MAXPROTOCOLE

La valeur du paramètre (une chaîne) est le niveau de protocole le plus élevé qui sera pris en charge par le client.

Notez que la spécification de ce paramètre remplacera le paramètre client max protocol dans le fichier /etc/samba/smb.conf.

-n|--netbiosname=NOM NETBIOS

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage sur la ligne de commande aura la priorité sur les réglages dans /etc/samba/smb.conf.

--netbios-scope=PORTEE

Ceci spécifie une portée NetBIOS avec laquelle nmblookup communiquera lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont *très* rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système en charge de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=GROUPE DE TRAVAIL

Définit le domaine SMB de l'utilisateur. Ceci remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est le même que le nom NetBIOS du serveur, cela amène le client à se connecter en utilisant le SAM local du serveur (par opposition au SAM du Domaine).

Notez que la spécification de ce paramètre remplacera le paramètre workgroup dans le fichier /etc/samba/smb.conf.

-r|--realm=DOMAINE

Définit le domaine pour le domaine.

Notez que la spécification de ce paramètre remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

-U|--user=[DOMAINE\]NOMUTILISATEUR[%MOTDEPASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOTDEPASSE n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas permi

tent à contenir un mot de passe) et si l'un d'eux existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'identifiants Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'identifiants qui contient le texte brut du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les identifiants en ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés. Voir le paramètre -A pour plus de détails.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts ou au passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre de processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une course.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite normale de mot de passe du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

Sauf si un mot de passe est spécifié sur la ligne de commande ou si ce paramètre est spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts ou au passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censée contenir un descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne devrait contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés !

Bien que Samba tente de supprimer le mot de passe du titre de processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une course.

--pw-nt-hash

Le mot de passe fourni est le hachage NT.

-A|--authentication-file=nom_fichier

Cette option permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est le suivant : 
username = <valeur>
password = <valeur>
domain   = <valeur>

Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés !

-P|--machine-pass

Utilise le mot de passe du compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils clients Samba tenteront de s'authentifier via Kerberos. Pour l'authentification Kerberos, vous devez utiliser des noms DNS au lieu d'adresses IP lors de la connexion à un service. Par défaut, les outils clients Samba tenteront d'utiliser le cache d'identifiants Kerberos (ccache) par défaut. Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'identifiants Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'identifiants pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Tente d'utiliser le cache d'identifiants de winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection dans le fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus précis, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

OPÉRATIONS

Une fois le client en cours d'exécution, l'utilisateur se voit présenter une invite :

smb:\>

La barre oblique inverse ("\\") indique le répertoire de travail actuel sur le serveur, et changera si le répertoire de travail actuel est modifié.

L'invite indique que le client est prêt et attend d'exécuter une commande utilisateur. Chaque commande est un mot unique, éventuellement suivi de paramètres spécifiques à cette commande. Les commandes et les paramètres sont séparés par des espaces, sauf indication contraire dans ces notes. Toutes les commandes sont insensibles à la casse. Les paramètres des commandes peuvent être sensibles ou non à la casse, selon la commande.

Vous pouvez spécifier des noms de fichiers contenant des espaces en les entourant de guillemets doubles, par exemple "un nom de fichier long".

Les paramètres indiqués entre crochets (par exemple, "[paramètre]") sont facultatifs. S'ils ne sont pas fournis, la commande utilisera des valeurs par défaut appropriées. Les paramètres indiqués entre chevrons (par exemple, "") sont requis.

Notez que toutes les commandes opérant sur le serveur sont en fait effectuées en envoyant une requête au serveur. Ainsi, le comportement peut varier d'un serveur à l'autre, en fonction de la manière dont le serveur a été implémenté.

Les commandes disponibles sont présentées ici par ordre alphabétique.

? [commande]

Si commande est spécifiée, la commande ? affichera un bref message informatif sur la commande spécifiée. Si aucune commande n'est spécifiée, une liste des commandes disponibles sera affichée.

! [commande_shell]

Si commande_shell est spécifiée, la commande ! exécutera un shell localement et exécutera la commande shell spécifiée. Si aucune commande n'est spécifiée, un shell local sera exécuté.

allinfo fichier

Le client demandera au serveur de renvoyer toutes les informations connues sur un fichier ou un répertoire (y compris les flux).

altname fichier

Le client demandera au serveur de renvoyer le nom "alternatif" (le nom 8.3) d'un fichier ou d'un répertoire.

archive <nombre>

Définit le niveau d'archive lors de l'opération sur les fichiers. 0 signifie ignorer le bit d'archive, 1 signifie opérer uniquement sur les fichiers avec ce bit défini, 2 signifie opérer uniquement sur les fichiers avec ce bit défini et le réinitialiser après l'opération, 3 signifie opérer sur tous les fichiers et le réinitialiser après l'opération. La valeur par défaut est 0.

backup

Active/désactive l'état du drapeau "intention de sauvegarde" envoyé au serveur lors des listages de répertoires et des ouvertures de fichiers. Si le drapeau "intention de sauvegarde" est vrai, le serveur tentera de contourner certaines vérifications du système de fichiers si l'utilisateur a reçu les privilèges SE_BACKUP ou SE_RESTORE. Cet état est utile lors de l'exécution d'une opération de sauvegarde ou de restauration.

blocksize <nombre>

Définit le paramètre blocksize pour une opération tar. La valeur par défaut est 20. Permet d'écrire le fichier tar par unités de blocksize * TBLOCK (normalement 512 octets).

cancel jobid0 [jobid1] ... [jobidN]

Le client demandera au serveur d'annuler les travaux d'impression identifiés par les identifiants numériques de travaux d'impression donnés.

case_sensitive

Active/désactive le drapeau dans les paquets SMB qui indique au serveur de traiter les noms de fichiers comme sensibles à la casse. Désactivé par défaut (indique au serveur de fichiers de traiter les noms de fichiers comme insensibles à la casse). N'affecte actuellement que les serveurs de fichiers Samba 3.0.5 et supérieurs avec le paramètre case sensitive défini sur auto dans smb.conf.

cd <nom_répertoire>

Si "nom_répertoire" est spécifié, le répertoire de travail actuel sur le serveur sera changé pour le répertoire spécifié. Cette opération échouera si, pour une raison quelconque, le répertoire spécifié est inaccessible.

Si aucun nom de répertoire n'est spécifié, le répertoire de travail actuel sur le serveur sera rapporté.

chmod fichier mode_en_octal

Cette commande dépend du support des extensions UNIX CIFS par le serveur et échouera si le serveur ne les supporte pas. Le client demande au serveur de modifier les permissions UNIX au mode octal donné, au format UNIX standard.

chown fichier uid gid

Cette commande dépend du support des extensions UNIX CIFS par le serveur et échouera si le serveur ne les supporte pas. Le client demande au serveur de modifier la propriété utilisateur et groupe UNIX aux valeurs décimales données. Notez qu'il n'y a actuellement aucun moyen de rechercher à distance les valeurs uid et gid UNIX pour un nom donné. Cela pourra être corrigé dans les futures versions des extensions UNIX CIFS.

close <fileid>

Ferme un fichier explicitement ouvert par la commande open. Utilisé à des fins de test interne Samba.

del <masque>

Le client demandera au serveur de tenter de supprimer tous les fichiers correspondant à masque du répertoire de travail actuel sur le serveur.

deltree <masque>

Le client demandera au serveur de tenter de supprimer tous les fichiers et répertoires correspondant à masque du répertoire de travail actuel sur le serveur. Notez que cela supprimera récursivement les fichiers et les répertoires dans les répertoires sélectionnés même sans que la commande recurse ne soit définie. Si l'une des demandes de suppression échoue, la commande cessera le traitement à ce stade, laissant les fichiers et répertoires non encore traités intacts. Ceci est par conception.

dir <masque>

Une liste des fichiers correspondant à masque dans le répertoire de travail actuel sur le serveur sera récupérée du serveur et affichée.

du <nom_fichier>

Effectue un listage de répertoire puis imprime l'utilisation actuelle du disque et l'espace libre sur un partage.

echo <nombre> <données>

Effectue une requête SMBecho pour pinger le serveur. Utilisé à des fins de test interne Samba.

exit

Termine la connexion avec le serveur et quitte le programme.

get <nom_fichier_distant> [nom_fichier_local]

Copie le fichier nommé nom_fichier_distant du serveur vers la machine exécutant le client. Si spécifié, nomme la copie locale nom_fichier_local. Notez que tous les transferts dans smbclient sont binaires. Voir aussi la commande lowercase.

getfacl <nom_fichier>

Nécessite que le serveur supporte les extensions UNIX. Demande
et imprime les ACL POSIX sur un fichier.

hardlink <src> <dest>

Crée un lien physique sur le serveur en utilisant la sémantique CIFS de Windows.

help [commande]

Voir la commande ? ci-dessus.

history

Affiche l'historique des commandes.

iosize <octets>

Lors de l'envoi ou de la réception de fichiers, smbclient utilise un tampon interne dont la taille est déterminée par le nombre maximal de requêtes autorisées vers le serveur connecté. Cette commande permet de définir cette taille dans une plage comprise entre 0 (ce qui signifie utiliser la taille contrôlée par le serveur par défaut) et 16776960 (0xFFFF00) octets. L'utilisation de la taille contrôlée par le serveur est la plus efficace, car smbclient mettra en pipeline autant de lectures ou écritures simultanées que nécessaire pour maintenir le serveur aussi occupé que possible. La définition d'une autre taille ralentira le transfert.

lcd [nom du répertoire]

Si nom du répertoire est spécifié, le répertoire de travail actuel sur la machine locale sera changé pour le répertoire spécifié. Cette opération échouera si, pour une raison quelconque, le répertoire spécifié est inaccessible.

Si aucun nom de répertoire n'est spécifié, le nom du répertoire de travail actuel sur la machine locale sera affiché.

link cible nom_lien

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Le client demande au serveur de créer un lien physique entre les fichiers nom_lien et cible. Le fichier nom_lien ne doit pas exister.

listconnect

Affiche les connexions actuelles détenues à des fins DFS.

lock <num_fichier> <r|w> <début_hex> <longueur_hex>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Tente de définir un verrou fcntl POSIX du type donné sur la plage donnée. Utilisé à des fins de test interne de Samba.

logon <nom_utilisateur> <mot_de_passe>

Établit un nouveau vuid pour cette session en se connectant à nouveau. Remplace le vuid actuel. Affiche le nouveau vuid. Utilisé à des fins de test interne de Samba.

logoff

Déconnecte l'utilisateur du serveur, fermant la session. Utilisé à des fins de test interne de Samba.

lowercase

Active/désactive la mise en minuscules des noms de fichiers pour les commandes get et mget.

Lorsque la mise en minuscules est activée, les noms de fichiers locaux sont convertis en minuscules lors de l'utilisation des commandes get et mget. Ceci est souvent utile lors de la copie (par exemple) de fichiers MSDOS depuis un serveur, car les noms de fichiers en minuscules sont la norme sur les systèmes UNIX.

ls <masque>

Voir la commande dir ci-dessus.

mask <masque>

Cette commande permet à l'utilisateur de définir un masque qui sera utilisé lors des opérations récursives des commandes mget et mput.

Les masques spécifiés aux commandes mget et mput agissent comme des filtres pour les répertoires plutôt que pour les fichiers lorsque la récursion est activée.

Le masque spécifié avec la commande mask est nécessaire pour filtrer les fichiers dans ces répertoires. Par exemple, si le masque spécifié dans une commande mget est "source*" et le masque spécifié avec la commande mask est "*.c", et que la récursion est activée, la commande mget récupérera tous les fichiers correspondant à "*.c" dans tous les répertoires en dessous et y compris tous les répertoires correspondant à "source*" dans le répertoire de travail actuel.

Notez que la valeur par défaut du masque est vide (équivalent à "*") et le reste jusqu'à ce que la commande mask soit utilisée pour la modifier. Elle conserve la dernière valeur spécifiée indéfiniment. Pour éviter des résultats inattendus, il serait judicieux de rétablir la valeur du masque à "*" après avoir utilisé les commandes mget ou mput.

md <nom du répertoire>

Voir la commande mkdir.

mget <masque>

Copie tous les fichiers correspondant au masque depuis le serveur vers la machine exécutant le client.

Notez que masque est interprété différemment lors des opérations récursives et non récursives - reportez-vous aux commandes recurse et mask pour plus d'informations. Notez que tous les transferts dans smbclient sont binaires. Voir également la commande lowercase.

mkdir <nom du répertoire>

Crée un nouveau répertoire sur le serveur (si les privilèges d'accès de l'utilisateur le permettent) avec le nom spécifié.

more <nom du fichier>

Récupère un fichier distant et l'affiche avec le contenu de votre variable d'environnement PAGER.

mput <masque>

Copie tous les fichiers correspondant au masque dans le répertoire de travail actuel sur la machine locale vers le répertoire de travail actuel sur le serveur.

Notez que masque est interprété différemment lors des opérations récursives et non récursives - reportez-vous aux commandes recurse et mask pour plus d'informations. Notez que tous les transferts dans smbclient sont binaires.

notify <nom du répertoire>

Interroge un répertoire pour les notifications de changement. Cette commande émet un appel recursive filechangenotify pour tous les changements possibles. Au fur et à mesure que les changements arrivent, elle affichera une ligne par changement. Voir https://msdn.microsoft.com/en-us/library/dn392331.aspx pour une description des numéros d'action que cette commande affiche.

Cette commande ne se termine jamais, elle attend les événements indéfiniment.

posix

Interroge le serveur distant pour voir s'il prend en charge les extensions UNIX CIFS et affiche la liste des capacités prises en charge. Si c'est le cas, active le traitement des chemins POSIX et les lectures/écritures de gros fichiers (si disponibles).

posix_encrypt <domaine> <nom_utilisateur> <mot_de_passe>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Tente de négocier le chiffrement SMB sur cette connexion. Si smbclient s'est connecté avec des identifiants kerberos (-k), les arguments de cette commande sont ignorés et les identifiants kerberos sont utilisés pour négocier la signature et le scellement GSSAPI à la place. Voir également l'option -e de smbclient pour forcer le chiffrement lors de la connexion initiale. Cette commande est nouvelle avec Samba 3.2.

posix_open <nom_fichier> <mode_octal>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Ouvre un fichier distant en utilisant les extensions UNIX CIFS et affiche un identifiant de fichier. Utilisé à des fins de test interne de Samba.

posix_mkdir <nom_répertoire> <mode_octal>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Crée un répertoire distant en utilisant les extensions UNIX CIFS avec le mode donné.

posix_rmdir <nom_répertoire>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Supprime un répertoire distant en utilisant les extensions UNIX CIFS.

posix_unlink <nom_fichier>

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Supprime un fichier distant en utilisant les extensions UNIX CIFS.

posix_whoami

Interroge le serveur distant pour obtenir le jeton utilisateur à l'aide de l'appel WHOAMI des extensions UNIX CIFS. Affiche le statut invité, l'utilisateur, le groupe, la liste des groupes et la liste des SID que le serveur distant utilise pour le compte de l'utilisateur connecté.

print <nom du fichier>

Imprime le fichier spécifié depuis la machine locale via un service imprimable sur le serveur.

prompt

Active/désactive la demande de confirmation pour les noms de fichiers lors de l'opération des commandes mget et mput.

Lorsqu'il est activé, l'utilisateur sera invité à confirmer le transfert de chaque fichier lors de ces commandes. Lorsqu'il est désactivé, tous les fichiers spécifiés seront transférés sans confirmation.

put <nom du fichier local> [nom du fichier distant]

Copie le fichier nommé nom du fichier local depuis la machine exécutant le client vers le serveur. Si spécifié, nommez la copie distante nom du fichier distant. Notez que tous les transferts dans smbclient sont binaires. Voir également la commande lowercase.

queue

Affiche la file d'attente d'impression, montrant l'ID du travail, le nom, la taille et l'état actuel.

quit

Voir la commande exit.

readlink nom_lien_symbolique

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Affiche la valeur du lien symbolique "nom_lien_symbolique".

rd <nom du répertoire>

Voir la commande rmdir.

recurse

Active/désactive la récursion de répertoire pour les commandes mget et mput.

Lorsqu'elle est activée, ces commandes traiteront tous les répertoires du répertoire source (c'est-à-dire le répertoire à partir duquel elles copient) et parcourront récursivement ceux qui correspondent au masque spécifié dans la commande. Seuls les fichiers correspondant au masque spécifié à l'aide de la commande mask seront récupérés. Voir également la commande mask.

Lorsque la récursion est désactivée, seuls les fichiers du répertoire de travail actuel sur la machine source qui correspondent au masque spécifié dans les commandes mget ou mput seront copiés, et tout masque spécifié à l'aide de la commande mask sera ignoré.

rename <ancien nom de fichier> <nouveau nom de fichier> [-f]

Renomme les fichiers dans le répertoire de travail actuel sur le serveur de ancien nom de fichier à nouveau nom de fichier. Le commutateur optionnel -f permet de remplacer le fichier de destination s'il existe. Ceci est pris en charge par le dialecte de protocole NT1 et la famille de protocoles SMB2.

rm <masque>

Supprime tous les fichiers correspondant au masque du répertoire de travail actuel sur le serveur.

rmdir <nom du répertoire>

Supprime le répertoire spécifié (si les privilèges d'accès de l'utilisateur le permettent) du serveur.

scopy <nom du fichier source> <nom du fichier destination>

Tente de copier un fichier sur le serveur en utilisant les appels de copie côté serveur les plus efficaces. En cas d'échec, utilise une lecture puis une écriture si le serveur ne prend pas en charge la copie côté serveur.

setmode <nom du fichier> <perm=[+|\-]rsha>

Une version de la commande DOS attrib pour définir les permissions de fichiers. Par exemple :

setmode monfichier +r

rendra monfichier en lecture seule.

showconnect

Affiche la connexion active actuellement détenue à des fins DFS.

stat fichier

Cette commande dépend de la prise en charge des extensions UNIX CIFS par le serveur et échouera si ce n'est pas le cas. Le client demande le niveau d'informations de base UNIX et affiche les mêmes informations que la commande stat de Linux concernant le fichier. Cela inclut la taille, les blocs utilisés o
n disque, type de fichier, permissions, numéro d'inode, nombre de liens et enfin les trois horodatages (accès, modification et changement). Si le fichier est un fichier spécial (lien symbolique, caractère ou périphérique bloc, fifo ou socket), des informations supplémentaires peuvent également être imprimées.

cible de lien symbolique nom_lien

Cette commande dépend du serveur prenant en charge les extensions CIFS UNIX et échouera si le serveur ne le fait pas. Le client demande au serveur de créer un lien symbolique dur entre les fichiers cible et nom_lien. Le fichier nom_lien ne doit pas exister. Notez que le serveur ne créera pas de lien vers un chemin situé en dehors du partage actuellement connecté. Ceci est appliqué par le serveur Samba.

tar <c|x>[IXbgNa]

Effectue une opération tar - voir l'option de ligne de commande -T ci-dessus. Le comportement peut être affecté par la commande tarmode (voir ci-dessous). L'utilisation de g (incrémental) et N (plus récent) affectera les paramètres de tarmode. Notez que l'utilisation de l'option "-" avec tar x peut ne pas fonctionner - utilisez plutôt l'option de ligne de commande.

blocksize <blocksize>

Taille de bloc. Doit être suivi d'une taille de bloc valide (supérieure à zéro). Fait que le fichier tar soit écrit par blocs de blocksize*TBLOCK (512 octets).

tarmode <full|inc|reset|noreset|system|nosystem|hidden|nohidden|verbose|noverbose>

Modifie le comportement de tar concernant les attributs DOS. Il existe 4 modes qui peuvent être activés ou désactivés.

Mode incrémental (désactivé par défaut). Lorsqu'il est désactivé (en utilisant full), tar sauvegardera tout, quel que soit le paramètre du bit archive. Lorsqu'il est activé (en utilisant inc), tar ne sauvegardera que les fichiers avec le bit archive défini.

Mode reset (désactivé par défaut). Lorsqu'il est activé (en utilisant reset), tar supprimera le bit archive sur tous les fichiers qu'il sauvegarde (implique un partage en lecture/écriture). Utilisez noreset pour désactiver.

Mode système (activé par défaut). Lorsqu'il est désactivé, tar ne sauvegardera pas les fichiers système. Utilisez nosystem pour désactiver.

Mode caché (activé par défaut). Lorsqu'il est désactivé, tar ne sauvegardera pas les fichiers cachés. Utilisez nohidden pour désactiver.

timeout <délai d'attente par opération en secondes>

Cela permet à l'utilisateur d'ajuster le délai d'attente par défaut utilisé pour chaque requête SMB. Le réglage par défaut est de 20 secondes. Augmentez-le si les requêtes vers le serveur parfois expirent. Cela peut se produire lorsque le chiffrement SMB3 est sélectionné et que smbclient submerge le serveur de requêtes.

unlock <num_fichier> <start_hex> <len_hex>

Cette commande dépend du serveur prenant en charge les extensions CIFS UNIX et échouera si le serveur ne le fait pas. Tente de déverrouiller un verrou POSIX fcntl sur la plage donnée. Utilisé à des fins de test interne Samba.

volume

Imprime le nom du volume actuel du partage.

vuid <nombre>

Change le vuid actuellement utilisé dans le protocole pour le nombre arbitraire donné. Sans argument, imprime le vuid actuel utilisé. Utilisé à des fins de test interne Samba.

tcon <nom_partage>

Établit une nouvelle connexion d'arborescence (connexion à un partage). Remplace la connexion d'arborescence actuelle. Imprime le nouveau tid (identifiant d'arborescence). Utilisé à des fins de test interne Samba.

tdis

Ferme la connexion de partage actuelle (déconnexion d'arborescence). Utilisé à des fins de test interne Samba.

tid <nombre>

Change le tid (tree id) actuel dans le protocole pour un nouveau nombre arbitraire. Sans argument, il imprime le tid actuellement utilisé. Utilisé à des fins de test interne Samba.

utimes <nom_fichier> <heure_création> <heure_accès> <heure_écriture> <heure_changement>

Modifie les horodatages d'un fichier par son nom. Les heures doivent être spécifiées au format [AA]AA:MM:DD-HH:MM:SS ou -1 pour aucune modification.

NOTES

Certains serveurs sont pointilleux sur la casse des noms d'utilisateur, mots de passe, noms de partage (également appelés noms de service) et noms de machine fournis. Si vous ne parvenez pas à vous connecter, essayez de fournir tous les paramètres en majuscules.

Il est souvent nécessaire d'utiliser l'option -n lors de la connexion à certains types de serveurs. Par exemple, OS/2 LanManager insiste sur l'utilisation d'un nom NetBIOS valide, vous devez donc fournir un nom valide qui serait connu du serveur.

smbclient prend en charge les noms de fichiers longs lorsque le serveur prend en charge le protocole LANMAN2 ou supérieur.

VARIABLES D'ENVIRONNEMENT

Consultez les options --user et --password pour plus de détails sur les moyens de spécifier un nom d'utilisateur et un mot de passe via une variable d'environnement.

INSTALLATION

L'emplacement du programme client est une affaire d'administrateurs système individuels. Les éléments suivants ne sont donc que des suggestions.

Il est recommandé que le logiciel smbclient soit installé dans le répertoire /usr/local/samba/bin/ ou /usr/samba/bin/, ce répertoire étant lisible par tous, inscriptible uniquement par root. Le programme client lui-même doit être exécutable par tous. Le client ne doit PAS être setuid ou setgid !

Les fichiers journaux du client doivent être placés dans un répertoire lisible et inscriptible uniquement par l'utilisateur.

Pour tester le client, vous devrez connaître le nom d'un serveur SMB/CIFS en cours d'exécution. Il est possible d'exécuter smbd(8) en tant qu'utilisateur ordinaire - exécuter ce serveur en tant que démon sur un port accessible par l'utilisateur (typiquement tout port supérieur à 1024) fournirait un serveur de test approprié.

DIAGNOSTICS

La plupart des diagnostics émis par le client sont enregistrés dans un fichier journal spécifié. Le nom du fichier journal est spécifié lors de la compilation, mais peut être remplacé sur la ligne de commande.

Le nombre et la nature des diagnostics disponibles dépendent du niveau de débogage utilisé par le client. En cas de problèmes, définissez le niveau de débogage sur 3 et examinez les fichiers journaux.
