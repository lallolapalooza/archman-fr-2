SMBPASSWD(8) Outils d'administration système SMBPASSWD(8)

NOM

smbpasswd - changer le mot de passe SMB d'un utilisateur

SYNTAXE

smbpasswd [-a] [-c <fichier de config>] [-x] [-d] [-e] [-D niveau debug] [-n] [-r <machine>] [-R <ordre>] [-m] [-U nomutilisateur[%motdepasse]] [-h] [-s] [-w motdepasse] [-W] [-i] [-L] [nomutilisateur]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

Le programme smbpasswd a plusieurs fonctions différentes, selon qu'il est exécuté par l'utilisateur root ou non. Lorsqu'il est exécuté en tant qu'utilisateur normal, il permet à l'utilisateur de changer le mot de passe utilisé pour ses sessions SMB sur toutes les machines qui stockent les mots de passe SMB. C'est une alternative aux mots de passe du système d'exploitation UNIX.

Par défaut (lorsqu'il est exécuté sans arguments), il tentera de changer le mot de passe SMB de l'utilisateur courant sur la machine locale. Ceci est similaire à la façon dont fonctionne le programme passwd(1). smbpasswd diffère cependant de la façon dont fonctionne le programme passwd en ce qu'il n'est pas setuid root mais fonctionne en mode client-serveur et communique avec un démon smbd(8) exécuté localement. Par conséquent, pour que cela réussisse, le démon smbd doit être en cours d'exécution sur la machine locale. Sur une machine UNIX, les mots de passe SMB cryptés sont généralement stockés dans le backend passdb par défaut.

Lorsqu'il est exécuté par un utilisateur ordinaire sans aucune option, smbpasswd lui demandera son ancien mot de passe SMB, puis lui demandera son nouveau mot de passe deux fois, pour s'assurer que le nouveau mot de passe a été tapé correctement. Aucun mot de passe ne sera affiché à l'écran lors de la saisie. Si vous avez un mot de passe SMB vide (spécifié par la chaîne "NO PASSWORD" dans le fichier smbpasswd), appuyez simplement sur la touche <Entrée> lorsqu'on vous demande votre ancien mot de passe.

smbpasswd peut également être utilisé par un utilisateur normal pour changer son mot de passe SMB sur des machines distantes, telles que les contrôleurs de domaine primaires Windows NT. Voir les options (-r) et -U ci-dessous.

Lorsqu'il est exécuté par root, smbpasswd permet d'ajouter et de supprimer de nouveaux utilisateurs dans le fichier smbpasswd, ainsi que de modifier les attributs de l'utilisateur dans ce fichier. Lorsqu'il est exécuté par root, smbpasswd accède directement au fichier smbpasswd local, permettant ainsi d'effectuer des modifications même si smbd n'est pas en cours d'exécution.

OPTIONS

-a

Cette option spécifie que le nom d'utilisateur suivant doit être ajouté au fichier smbpasswd local, avec le nouveau mot de passe tapé (tapez <Entrée> pour l'ancien mot de passe). Cette option est ignorée si le nom d'utilisateur suivant existe déjà dans le fichier smbpasswd et est traitée comme une commande normale de changement de mot de passe. Notez que les backends passdb par défaut exigent que l'utilisateur existe déjà dans le fichier de mots de passe du système (généralement /etc/passwd), sinon la demande d'ajout de l'utilisateur échouera.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-c

Cette option peut être utilisée pour spécifier le chemin et le nom de fichier du fichier de configuration /etc/samba/smb.conf lorsqu'il est important d'utiliser un fichier autre que celui par défaut et/ou un emplacement différent.

-x

Cette option spécifie que le nom d'utilisateur suivant doit être supprimé du fichier smbpasswd local.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-d

Cette option spécifie que le nom d'utilisateur suivant doit être désactivé dans le fichier smbpasswd local. Ceci est fait en écrivant un drapeau 'D' dans l'espace de contrôle du compte dans le fichier smbpasswd. Une fois cela fait, toutes les tentatives d'authentification via SMB en utilisant ce nom d'utilisateur échoueront.

Si le fichier smbpasswd est au format 'ancien' (format pré-Samba 2.0), il n'y a pas d'espace dans l'entrée du mot de passe de l'utilisateur pour écrire ces informations et la commande ÉCHOUERA. Voir smbpasswd(5) pour les détails sur les formats de fichiers de mots de passe 'ancien' et nouveau.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-e

Cette option spécifie que le nom d'utilisateur suivant doit être activé dans le fichier smbpasswd local, si le compte était précédemment désactivé. Si le compte n'était pas désactivé, cette option n'a aucun effet. Une fois le compte activé, l'utilisateur pourra s'authentifier via SMB à nouveau.

Si le fichier smbpasswd est au format 'ancien', smbpasswd ÉCHOUERA à activer le compte. Voir smbpasswd(5) pour les détails sur les formats de fichiers de mots de passe 'ancien' et nouveau.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-D niveau_debug

niveau_debug est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est zéro.

Plus cette valeur est élevée, plus les détails seront enregistrés dans les fichiers journaux sur les activités de smbpasswd. Au niveau 0, seules les erreurs critiques et les avertissements sérieux seront enregistrés.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation, et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'ÉNORMES quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

-n

Cette option spécifie que le nom d'utilisateur suivant doit avoir son mot de passe défini sur nul (c'est-à-dire un mot de passe vide) dans le fichier smbpasswd local. Ceci est fait en écrivant la chaîne "NO PASSWORD" comme première partie du premier mot de passe stocké dans le fichier smbpasswd.

Notez que pour permettre aux utilisateurs de se connecter à un serveur Samba une fois le mot de passe défini sur "NO PASSWORD" dans le fichier smbpasswd, l'administrateur doit définir le paramètre suivant dans la section [global] du fichier smb.conf :

null passwords = yes

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-r nom_machine_distante

Cette option permet à un utilisateur de spécifier sur quelle machine il souhaite changer son mot de passe. Sans ce paramètre, smbpasswd utilise par défaut l'hôte local. Le nom_machine_distante est le nom NetBIOS du serveur SMB/CIFS à contacter pour tenter le changement de mot de passe. Ce nom est résolu en une adresse IP en utilisant le mécanisme de résolution de noms standard dans tous les programmes de la suite Samba. Voir le paramètre -R ordre_de_résolution_de_nom pour les détails sur la modification de ce mécanisme de résolution.

Le nom d'utilisateur dont le mot de passe est changé est celui de l'utilisateur UNIX actuellement connecté. Voir le paramètre -U nomutilisateur pour les détails sur le changement de mot de passe pour un autre nom d'utilisateur.

Notez que si vous changez un mot de passe de domaine Windows NT, la machine distante spécifiée doit être le contrôleur de domaine principal du domaine (les contrôleurs de domaine secondaires n'ont qu'une copie en lecture seule de la base de données des comptes utilisateurs et n'autoriseront pas le changement de mot de passe).

Note : Windows 95/98 ne dispose pas d'une véritable base de données de mots de passe, il n'est donc pas possible de changer les mots de passe en spécifiant une machine Win95/98 comme cible distante.

-R ordre_résolution_de_nom

Cette option permet à l'utilisateur de smbpasswd de déterminer quels services de résolution de noms utiliser lors de la recherche du nom NetBIOS de l'hôte cible.

Les options sont : "lmhosts", "host", "wins" et "bcast". Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir le fichier lmhosts(5) pour les détails) alors n'importe quel type de nom correspond pour la recherche.
•host : Effectue une résolution de nom d'hôte vers adresse IP standard, en utilisant les recherches DNS, NIS ou le fichier /etc/hosts du système. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, cela peut être contrôlé par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP listée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la moins fiable des méthodes de résolution de noms car elle dépend de l'hôte cible se trouvant sur un sous-réseau connecté localement.
L'ordre par défaut est lmhosts, host, wins, bcast et sans ce paramètre ou toute entrée dans le fichier smb.conf(5) le nom

-m

Cette option spécifie que le nom d'utilisateur suivant doit avoir son mot de passe stocké sous forme cryptée LM (LAN Manager).

Cette option est uniquement disponible lorsque smbpasswd est exécuté en tant que root.

-U nomutilisateur[%motdepasse]

Cette option permet à l'utilisateur d'essayer de changer le mot de passe d'un autre utilisateur. Le nomutilisateur spécifié sera le nom d'utilisateur Samba. Si le nom d'utilisateur est suivi d'un "%" et d'un mot de passe, ce mot de passe sera utilisé pour l'authentification du nom d'utilisateur auprès du serveur distant. Ceci est utile lorsque vous n'avez pas d'authentification NT ou si le nom d'utilisateur et le mot de passe NT sont différents.

Notez que l'utilisation de "%motdepasse" est une faille de sécurité, car le mot de passe sera visible dans l'historique des commandes ou dans la liste des processus.

Cette option est uniquement disponible lorsque smbpasswd est exécuté en tant que root.

-h

Affiche un message d'aide.

-s

Cette option spécifie que les mots de passe seront lus depuis l'entrée standard, et non demandés interactivement. Ceci est utile pour les scripts.

Notez que l'utilisation de cette option est une faille de sécurité, car le mot de passe sera visible dans l'historique des commandes ou dans la liste des processus.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-w motdepasse

Utilise le motdepasse fourni comme mot de passe SMB pour l'utilisateur spécifié. Ceci est utile dans les scripts.

Notez que l'utilisation de cette option est une faille de sécurité, car le mot de passe sera visible dans l'historique des commandes ou dans la liste des processus.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-W

Cette option indique à smbpasswd d'utiliser des caractères Unicode pour les mots de passe. Par défaut, les mots de passe sont traités comme des chaînes de caractères à 8 bits.

-i

Cette option est utilisée pour initialiser le backend passdb. C'est-à-dire qu'elle est utilisée pour construire le fichier smbpasswd à partir du fichier de mots de passe système. Cela ne peut être fait que si le backend passdb est basé sur des fichiers (comme smbpasswd ou tdbsam). Ceci ne peut être fait que par root.

-L

Cette option indique à smbpasswd d'utiliser des méthodes de cryptage locales uniquement. Ceci est souvent utilisé pour permettre à Samba de fonctionner sans avoir besoin d'un serveur WINS.

nomutilisateur

Le nom d'utilisateur pour lequel le mot de passe doit être changé. Si ce paramètre est omis, le nom d'utilisateur courant sera utilisé.

EXEMPLES

Changer le mot de passe de l'utilisateur courant :

   smbpasswd

Ajouter un nouvel utilisateur 'john' et définir son mot de passe (requiert les privilèges root) :

   smbpasswd -a john

Désactiver l'utilisateur 'jane' (requiert les privilèges root) :

   smbpasswd -d jane

Activer l'utilisateur 'jane' (requiert les privilèges root) :

   smbpasswd -e jane

Supprimer l'utilisateur 'john' du fichier smbpasswd (requiert les privilèges root) :

   smbpasswd -x john

Changer le mot de passe de l'utilisateur 'fred' sur la machine 'winserver' (requiert les privilèges root) :

   smbpasswd -r winserver -U fred

VOIR AUSSI

smbd(8), smbpasswd(5), samba(7), lmhosts(5), smb.conf(5)

Cette option indique à smbpasswd que le compte modifié est un compte MACHINE. Actuellement, cela est utilisé lorsque Samba est utilisé comme contrôleur de domaine principal NT.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

Cette option ne peut être utilisée qu'en conjonction avec l'option -r. Lors de la modification d'un mot de passe sur une machine distante, elle permet à l'utilisateur de spécifier le nom d'utilisateur sur cette machine dont le mot de passe sera modifié. Elle est présente pour permettre aux utilisateurs qui ont des noms d'utilisateur différents sur différents systèmes de modifier ces mots de passe.

-h

Cette option affiche la chaîne d'aide pour smbpasswd, en sélectionnant celle qui convient pour une exécution en tant que root ou en tant qu'utilisateur ordinaire.

-s

Cette option fait en sorte que smbpasswd soit silencieux (c'est-à-dire qu'il ne demande rien) et qu'il lise ses anciens et nouveaux mots de passe depuis l'entrée standard, plutôt que depuis /dev/tty (comme le fait le programme passwd(1)). Cette option est destinée à aider les personnes qui écrivent des scripts pour piloter smbpasswd.

-w mot_de_passe

Notez que le mot de passe est stocké dans secrets.tdb et est indexé par le DN de l'administrateur. Cela signifie que si la valeur de dn d'administrateur ldap change jamais, le mot de passe devra également être mis à jour manuellement.

NOTE : Cette option est identique à "-w" sauf que le mot de passe doit être saisi via stdin.

Ce paramètre n'est disponible que si Samba a été compilé avec le support LDAP. Le commutateur -W est utilisé pour spécifier le mot de passe à utiliser avec le dn d'administrateur ldap. Cela signifie que si la valeur de dn d'administrateur ldap change jamais, le mot de passe devra également être mis à jour manuellement.

Cette option indique à smbpasswd que le compte modifié est un compte de confiance inter-domaines. Actuellement, cela est utilisé lorsque Samba est utilisé comme contrôleur de domaine principal NT. Le compte contient les informations sur un autre domaine de confiance.

Cette option n'est disponible que lorsque smbpasswd est exécuté en tant que root.

-L

Exécuter en mode local.

nom_utilisateur

Ceci spécifie le nom d'utilisateur sur lequel toutes les options réservées à root doivent opérer. Seul root peut spécifier ce paramètre car seul root possède les permissions nécessaires pour modifier directement les attributs dans le fichier smbpasswd local.

NOTES

Comme smbpasswd fonctionne en mode client-serveur en communiquant avec un smbd local pour un utilisateur non root, le démon smbd doit être en cours d'exécution pour que cela fonctionne. Un problème courant est d'ajouter une restriction aux hôtes qui peuvent accéder au smbd s'exécutant sur la machine locale en spécifiant une entrée allow hosts ou deny hosts dans le fichier smb.conf(5) et en négligeant d'autoriser l'accès "localhost" à smbd.

De plus, la commande smbpasswd n'est utile que si Samba a été configuré pour utiliser des mots de passe cryptés.
