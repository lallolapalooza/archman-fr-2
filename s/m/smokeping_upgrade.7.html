NOM

smokeping_upgrade - Notes sur la mise à niveau de Smokeping

APERÇU

Ce document tente de lister les changements incompatibles ou autrement visibles par l'utilisateur dans les versions de Smokeping, avec des instructions sur la façon de résoudre les problèmes éventuels. Il mentionne également sporadiquement de nouvelles fonctionnalités, etc.

Le document commence actuellement par les changements de 1.34 à 1.37. Si vous rencontrez des problèmes lors de la mise à niveau à partir de versions antérieures, veuillez envoyer une description des problèmes, de préférence avec des notes sur la façon de les résoudre, à la liste de diffusion "smokeping-users", afin qu'ils puissent être ajoutés à ce document. Il en va de même pour les problèmes que vous trouvez dans les versions actuelles qui ne sont pas documentés ici, bien sûr. Les soumissions de correctifs contre la source POD de ce fichier sont très appréciées.

Si une version n'est pas listée, il n'y a pas de problèmes connus pour la mise à niveau à partir de la version précédente.

Une liste officielle des changements pour chaque version peut être trouvée dans le fichier CHANGES de la distribution Smokeping. Ce document tente de compléter cela avec des instructions de mise à niveau, etc.

2.4.2 à 2.4.3

Pour corriger le zoom pour FF3.5, prototype et scriptaculous ont été mis à jour. Pour compléter la correction, vous devez également mettre à jour votre fichier basepage.html et inclure effects dans la ligne de chargement de scriptaculous

cropper/lib/scriptaculous.js?load=builder,effects,dragdrop

2.3.6 à 2.4.0

Le nouvel outil SmokeTrace a été ajouté à SmokePing. Pour les instructions de configuration, lisez la page de manuel smoketrace.

2.3.3 à 2.3.4

Le protocole de communication entre le maître et l'esclave a été rendu plus sécurisé. Cela nécessite que le maître ET l'esclave soient mis à niveau pour continuer à fonctionner.

2.2.x à 2.3.x

2.3.0 concerne principalement de nouvelles fonctionnalités. Consultez la documentation de référence sur les hiérarchies et les propriétés de cible parents, hidden et nomasterpoll.

La seule chose à vérifier est le fichier basepage.html.dist qui a reçu de nouvelles propriétés css. Sans elles, les résultats de la nouvelle fonction de filtrage auront un très mauvais rendu.

2.1.x à 2.2.0

Dépendance LWP

La nouvelle fonctionnalité maître/esclave nécessite le module LWP::UserAgent de CPAN. Actuellement, la dépendance n'est pas optionnelle ; vous aurez besoin du module même si vous n'exécutez qu'une seule instance de Smokeping.

2.0.9 à 2.1.0

Support Echoping 6

Ceci est la première version de Smokeping qui supporte pleinement echoping 6. Les versions antérieures des sondes EchoPingHttp ne fonctionnent pas avec echoping 6 en raison d'une incompatibilité de ligne de commande. (Echoping 5 est toujours supporté, bien sûr.)

Cette version introduit également trois nouvelles sondes utilisant la nouvelle interface de plugin echoping introduite dans la version 6 :

  • EchoPingDNS
  • EchoPingLDAP
  • EchoPingWhois

Voir le document smokeping_examples pour des exemples simples d'utilisation de ces sondes.

Nouvelle méthode dans base.pm (si vous écrivez vos propres sondes)

Le module base.pm définit la méthode ProbeUnit. Remplacez-la si votre sonde ne renvoie pas 'Seconds'. Voir FTPtransfer.pm pour vous en inspirer.

2.0.8 à 2.0.9

FPing

La variable 'timeout' supprimée dans 2.0.5 a été réintroduite. Elle est utilisée pour donner à la commande "fping" le paramètre "-t", qui affecte apparemment le timeout du dernier ping en mode comptage ("-C") utilisé par Smokeping.

2.0.5 à 2.0.6

Liens auto-référents CGI (encore)

La manière dont Smokeping crée les liens auto-référents a été modifiée une fois de plus. Voir la section sous '2.0.4 à 2.0.5' pour une description du changement précédent.

Le comportement est maintenant personnalisable via la variable "linkstyle" dans la section "General" du fichier de configuration. La valeur par défaut est maintenant "relative", créant des liens tels que <a href="?foo=bar">. J'espère que cela fonctionnera pour tout le monde, mais si ce n'est pas le cas, consultez smokeping_config pour les alternatives.

2.0.4 à 2.0.5

FPing

La variable 'timeout' a été supprimée. Elle était utilisée pour donner à la commande "fping" le paramètre "-t", mais comme ce paramètre n'est efficace que dans le mode par défaut de "fping", alors que Smokeping utilise le mode comptage ("-c"), il n'a jamais rien fait.

Liens auto-référents CGI

La manière dont Smokeping crée les liens auto-référents a été modifiée. L'ancien comportement utilisait le nom du script mais pas la partie hôte, résultant en des liens tels que <a href="/chemin/smokeping.cgi?foo=bar">. Le nouveau comportement utilise la variable "cgiurl" : les liens sont toujours absolus tels que <a href="http://some.host/path/smokeping.cgi?foo=bar">.

2.0.1 à 2.0.2

Alertes déclenchées à chaque changement

Les notifications d'alerte peuvent désormais être envoyées optionnellement uniquement lorsque l'état de l'alerte change. Cela signifie que seule la première correspondance de l'alerte génère une notification, les correspondances ultérieures ne le font pas. Lorsque l'alerte est résolue, c'est-à-dire qu'il n'y a plus de correspondance, une autre notification est envoyée.

Ce comportement est activé par la variable "edgetrigger" dans la section "Alerts". L'ancien comportement (qui envoie une notification à chaque correspondance) est le comportement par défaut.

1.40 à 2.0

Le plus grand changement avec la sortie de la version 2.0 est que le fichier de configuration est maintenant analysé de manière beaucoup plus stricte. Cela devrait se traduire par des messages d'erreur (espérons-le compréhensibles) rendant la configuration moins basée sur l'essai-erreur qu'auparavant. Cela automatise également la génération de la documentation de configuration à partir du code source, de sorte que les documents sont maintenant plus précis.

Un changement mineur méritant d'être mentionné est l'inclusion du script tSmoke (contribué par Dan McGinn-Combs) pour l'envoi d'e-mails de résumé sur l'état quotidien et hebdomadaire du système. Notez qu'il nécessite la nouvelle variable 'tmail' pour être définie dans le fichier de configuration.

CONFIGURATION

La syntaxe de configuration est restée globalement la même, à l'exception des problèmes ci-dessous.

PROBE_CONF
Les sous-sections PROBE_CONF ont été dépréciées. Toutes les variables spécifiques à la cible sont maintenant configurées dans la même section que la cible elle-même. Il suffit de supprimer la

++ PRO

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

BE_CONF

les lignes devraient résoudre ce problème (pour n'importe quel nombre de '+', évidemment.)

L'existence d'une section PROBE_CONF fait que smokeping s'arrête avec un message d'erreur lors de l'analyse.

Note pour les distributeurs : ces lignes pourraient facilement être supprimées automatiquement lors de la mise à niveau.

Ordre des variables
La variable "probe" doit maintenant être définie avant toute variable dépendant de la sonde sélectionnée. Ceci est dû au fait que la définition de "probe" modifie la grammaire du reste de la section dynamiquement lors de l'analyse.

De plus, "probe" doit maintenant précéder "host", pour des raisons liées à l'implémentation actuelle de la vérification des variables obligatoires.

Ces deux erreurs sont reconnues lors de l'analyse et produisent des messages d'erreur en conséquence.

Note pour les distributeurs : la commande "smokeping" dispose désormais d'une nouvelle option '--check' qui peut être utilisée pour vérifier la syntaxe du fichier de configuration. Il pourrait être judicieux de l'utiliser lors de la mise à niveau et de fournir une note explicative à l'utilisateur si la vérification échoue.

Variables spécifiques à la cible dans la section Probes
Ce n'est pas un changement incompatible, mais il est mentionné ici néanmoins. Les variables spécifiques à la cible peuvent désormais être spécifiées dans la section Probes également, et les valeurs fournies deviennent les valeurs par défaut pour toutes les cibles.
Temps d'attente
La variable "timeout" dans la section Probes est maintenant le temps maximum attendu pour **un** ping. Précédemment, c'était le temps maximum autorisé pour tous les pings vers une cible. C'est un changement incompatible, mais le code fonctionne maintenant de la manière dont il était documenté pour fonctionner même dans la version 1.38.

Les sondes offrant une variable "timeout" spécifique à la cible obtiendront une valeur par défaut à partir de la section Probes, comme noté dans l'élément précédent. Cela devrait garantir que les sondes qui appliquent elles-mêmes le temps d'attente du ping (la plupart le font) ne seront pas tuées en raison d'un délai d'attente avant qu'elles n'aient la possibilité de le faire.

Correspondances
Les modules de correspondance ont été renommés pour commencer par une lettre majuscule, afin de différencier les modules réels des classes de base. Vous devez mettre en majuscule le nom de la correspondance dans la définition du modèle en conséquence.
Nombre minimum de pings
La variable "pings" a maintenant une valeur minimale forcée de 3, car la conception entière de Smokeping est basée sur l'idée d'envoyer plusieurs sondes et de mesurer et visualiser la variation entre elles.
Vérification des paramètres RRD
Smokeping vérifie maintenant au démarrage que les paramètres de tous les fichiers RRD existants correspondent à ceux spécifiés dans le fichier de configuration. En cas de divergence, il tentera de corriger la situation et refusera de démarrer s'il ne le peut pas.

Cette situation est très susceptible de se produire si vous avez modifié la variable "pings" dans votre fichier de configuration. Vous devrez alors supprimer l'ancien fichier RRD ou le convertir d'une manière ou d'une autre pour utiliser les nouveaux paramètres. La commande "rrdtune" pourrait être utile ici.

Emplacement configurable pour les fichiers liés à DYNAMIC
Il existe maintenant une nouvelle variable de configuration, "dyndir", qui peut être utilisée pour spécifier l'emplacement des fichiers liés à DYNAMIC (.adr et .snmp). Ces fichiers étaient auparavant conservés sous "datadir" avec les fichiers RRD, mais comme ils doivent être inscriptibles par le serveur web, il peut être utile de les séparer.

Si "dyndir" n'est pas spécifié, Smokeping utilisera la valeur de "datadir" par défaut. Cela devrait garantir qu'aucune configuration existante ne sera rompue.

En plus de cela, certaines sondes ont subi des changements mineurs incompatibles dans leur configuration.

RemoteFPing
La variable "rbinary" est maintenant obligatoire. C'est un effet secondaire d'un changement plus important : la sonde est maintenant dérivée de la sonde FPing et prend en charge toutes les variables que FPing prend en charge.
FPing6
Cette sonde est également maintenant dérivée de FPing et prend en charge toutes les variables que FPing prend en charge.
Curl
L'URL qui sera utilisée est maintenant spécifiée avec la variable "urlformat" au lieu de "url". La nouvelle variable peut (et devrait généralement) inclure un espace réservé pour la variable "host" de chaque cible sous la forme "%host%", par exemple "urlformat = http://%host%/". La nouvelle variable est obligatoire.

Ce changement a été apporté pour résoudre la situation confuse où la variable "host" était requise pour chaque cible réelle, mais n'avait en fait aucun effet (car le serveur à sonder provenait de la variable "url".)

Les délais d'attente sont maintenant reconnus correctement en examinant le code de sortie de curl. Le délai d'attente par défaut de cette sonde a été augmenté à 10 secondes.

La ligne de commande est maintenant exécutée sans /bin/sh intermédiaire, et donc les guillemets ne sont plus nécessaires autour de la chaîne User-Agent (le paramètre "agent"). Smokeping se plaindra s'il remarque des guillemets autour de la chaîne.

Tous les arguments supplémentaires pour "curl" peuvent maintenant être spécifiés dans la variable "extraargs".

EchoPingHttp
Le délai d'attente par défaut de cette sonde a été augmenté à 10 secondes.
EchoPingHttps
Le délai d'attente par défaut de cette sonde a été augmenté à 10 secondes.
EchoPingIcp
La variable "url" est maintenant obligatoire, car la valeur par défaut précédente "/" n'avait pas de sens car elle est relative plutôt qu'absolue.
LDAP
La variable "filter" est maintenant obligatoire, car Net::LDAP échoue sans elle.

La variable "sleeptime" a été renommée en "mininterval" et ses sémantiques ont été modifiées en conséquence (il s'agit maintenant du temps minimum entre deux requêtes plutôt que du temps de pause entre la fin d'une et le début de l'autre.)

Radius
La variable "sleeptime" a été renommée en "mininterval" et ses sémantiques ont été modifiées en conséquence. Voir l'explication LDAP ci-dessus.
AnotherDNS
La variable "sleeptime" a été renommée en "mininterval" et ses sémantiques ont été modifiées en conséquence. Voir l'explication LDAP ci-dessus. De plus, le temps est maintenant spécifié en secondes plutôt qu'en microsecondes.
AnotherSSH
La variable "sleeptime" a été renommée en "mininterval" et ses sémantiques ont été modifiées en conséquence. Voir l'explication LDAP ci-dessus. De plus, le temps est maintenant spécifié en secondes plutôt qu'en microsecondes.
TelnetIOSPing
Le nom de cette sonde a été modifié : il commence maintenant par une lettre majuscule comme toutes les autres.

La variable "target" a été supprimée. La cible doit maintenant être spécifiée dans la variable "host", comme c'est le cas pour toutes les autres sondes.

Version du module CGI::Carp

La version recommandée pour CGI::Carp est maintenant au moins 1.24, incluse dans CGI.pm-2.82 et la distribution standard de Perl à partir de 5.8.1. Voir le document smokeping_install.

1.38 à 1.40

La nouvelle fonctionnalité de navigation
La grande différence visible entre 1.38 et 1.40 est la nouvelle fonctionnalité de navigation dans le navigateur : en cliquant sur les graphiques en vue détaillée, vous pouvez sélectionner différentes plages de temps pour le graphique. La création de cette fonctionnalité a été sponsorisée par BeverlyCorp.com.

1.34 à 1.37

La sonde RemoteFPing
La configuration de cette sonde a été déplacée de la section Targets vers la section Probes, car toutes les variables sont réellement spécifiques à la sonde. Les variables déplacées étaient "rhost", "rbinary" et "rhost".
Changements dans la journalisation
Le démon "smokeping" affiche maintenant un avertissement au démarrage si le support syslog n'est pas activé dans le fichier de configuration. Ceci est dû au fait que de nombreux messages de diagnostic seraient autrement perdus.
Sondes concurrentes
Chaque sonde s'exécute maintenant dans son propre processus, au lieu de s'exécuter séquentiellement dans un seul processus. Cela permet de spécifier différentes longueurs d'étape pour différentes sondes. Vous pouvez retrouver le comportement précédent en définissant 'concurrentprobes = no'.

NAME

smokeping_upgrade - upgrade notes for Smokeping

OVERVIEW

This document describes the changes between Smokeping versions and what you need to do to upgrade.

No changes to configuration or data formats.

2.3.6 to 2.4.0

No changes to configuration or data formats.

2.3.3 to 2.3.4

No changes to configuration or data formats.

2.2.x to 2.3.x

No changes to configuration or data formats.

2.1.x to 2.2.0

No changes to configuration or data formats.

2.0.9 to 2.1.0

No changes to configuration or data formats.

2.0.8 to 2.0.9

No changes to configuration or data formats.

2.0.5 to 2.0.6

No changes to configuration or data formats.

2.0.4 to 2.0.5

No changes to configuration or data formats.

2.0.1 to 2.0.2

No changes to configuration or data formats.

1.40 to 2.0

The configuration file format has been changed significantly. Please see smokeping_config(5) for details.

1.38 to 1.40

The configuration file format has been changed. Please see smokeping_config(5) for details.

The configuration file format has been changed. Please see smokeping_config(5) for details.
