NOM

smbd - serveur pour fournir des services SMB/CIFS aux clients

SYNTAXE

smbd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-b|--build-options] [-p <numéro(s)> de port] [-P <niveau> de profilage] [-d <niveau> de débogage] [--debug-stdout] [--configfile=<fichier> de configuration] [--option=<nom>=<valeur>] [-l|--log-basename <répertoire> de logs] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPTION

Ce programme fait partie de la suite samba(7).

smbd est le démon serveur qui fournit les services de partage de fichiers et d'impression aux clients Windows. Le serveur fournit des services d'espace de fichiers et d'imprimantes aux clients utilisant le protocole SMB (ou CIFS). Ceci est compatible avec le protocole LanManager et peut servir des clients LanManager. Ceux-ci incluent MSCLIENT 3.0 pour DOS, Windows for Workgroups, Windows 95/98/ME, Windows NT, Windows 2000, OS/2, DAVE pour Macintosh, et smbfs pour Linux.

Une description exhaustive des services que le serveur peut fournir est donnée dans la page de manuel du fichier de configuration contrôlant les attributs de ces services (voir smb.conf(5). Cette page de manuel ne décrit pas les services, mais se concentrera sur les aspects administratifs de l'exécution du serveur.

Veuillez noter qu'il y a des implications de sécurité significatives à exécuter ce serveur, et la page de manuel smb.conf(5) doit être considérée comme une lecture obligatoire avant de procéder à l'installation.

Une session est créée chaque fois qu'un client en demande une. Chaque client obtient une copie du serveur pour chaque session. Cette copie sert ensuite toutes les connexions effectuées par le client pendant cette session. Lorsque toutes les connexions du client sont fermées, la copie du serveur pour ce client se termine.

Le fichier de configuration, et tous les fichiers qu'il inclut, sont rechargés automatiquement toutes les trois minutes, s'ils changent. On peut forcer un rechargement en envoyant un SIGHUP au serveur. Le rechargement du fichier de configuration n'affectera pas les connexions à un service déjà établi. L'utilisateur devra soit se déconnecter du service, soit smbd sera tué et redémarré.

Au lieu d'envoyer un signal SIGHUP, une requête pour recharger le fichier de configuration peut être envoyée en utilisant le programme smbcontrol(1).

OPTIONS

-D|--daemon

Si spécifié, ce paramètre amène le serveur à fonctionner comme un démon. C'est-à-dire qu'il se détache et s'exécute en arrière-plan, répondant aux requêtes sur le port approprié. L'exploitation du serveur comme un démon est la manière recommandée d'exécuter smbd pour les serveurs qui fournissent des services de fichiers et d'impression plus qu'un usage occasionnel. Ce commutateur est supposé si smbd est exécuté sur la ligne de commande d'un shell.

-i|--interactive

Si ce paramètre est spécifié, il amène le serveur à fonctionner "interactivement", pas comme un démon, même si le serveur est exécuté sur la ligne de commande d'un shell. La définition de ce paramètre annule le mode démon implicite lorsqu'il est exécuté depuis la ligne de commande. smbd n'acceptera qu'une seule connexion et se terminera. Il enregistrera également dans la sortie standard, comme si le paramètre -S avait été donné.

-F|--foreground

Si spécifié, ce paramètre amène le processus principal smbd à ne pas se démoniaquer, c'est-à-dire à ne pas faire de double fork et à ne pas se détacher du terminal. Des processus enfants sont toujours créés normalement pour servir chaque demande de connexion, mais le processus principal ne se termine pas. Ce mode de fonctionnement convient à l'exécution de smbd sous des superviseurs de processus tels que supervise et svscan du package daemontools de Daniel J. Bernstein, ou le moniteur de processus AIX.

--no-process-group

Ne pas créer de nouveau groupe de processus pour smbd.

-b|--build-options

Affiche des informations sur la façon dont Samba a été construit.

-p|--port<numéro(s) de port>

numéro(s) de port est une liste de ports TCP, séparée par des espaces ou des virgules, sur lesquels smbd doit écouter. La valeur par défaut est prise du paramètre ports dans /etc/samba/smb.conf.

Les ports par défaut sont 139 (utilisé pour SMB sur NetBIOS sur TCP) et le port 445 (utilisé pour le SMB simple sur TCP).

-P|--profiling-level<niveau de profilage>

niveau de profilage est un nombre spécifiant le niveau de données de profilage à collecter. 0 désactive le profilage, 1 active uniquement le profilage de compteurs, 2 active le profilage complet, et 3 réinitialise toutes les données de profilage.

-d|--debuglevel=level

level est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 0.

Plus cette valeur est élevée, plus les informations enregistrées dans les fichiers journaux concernant les activités du serveur seront détaillées. Au niveau 0, seules les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journal, et ne devraient être utilisés que lors de la résolution d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent une quantité ÉNORME de données de journal, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level dans le fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, les démons serveur enregistrent dans un fichier journal.

--configfile=FICHIERCONFIG

Le fichier spécifié contient les détails de configuration requis par le serveur. Les informations de ce fichier incluent des détails spécifiques au serveur tels que quel fichier printcap utiliser, ainsi que des descriptions de tous les services que le serveur doit fournir. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues depuis le fichier de configuration. Si un nom ou une valeur contient un espace, entourez l'ensemble --option=nom=valeur par des guillemets.

-l|--log-basename=repertoirelog

Nom de base du répertoire pour les fichiers journaux/de débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-?|--help

Affiche un résumé des options de ligne de commande.

--usage

Affiche un bref message d'utilisation.

FICHIERS

/etc/inetd.conf

Si le serveur doit être exécuté par le méta-démon inetd, ce fichier doit contenir les informations de démarrage appropriées pour le méta-démon.

/etc/rc

ou tout script d'initialisation que votre système utilise).

Si le serveur est exécuté comme un démon au démarrage, ce fichier devra contenir une séquence de démarrage appropriée pour le serveur.

/etc/services

Si le serveur est exécuté via le méta-démon inetd, ce fichier doit contenir un mappage du nom du service (par exemple, netbios-ssn) au port du service (par exemple, 139) et au type de protocole (par exemple, tcp).

/usr/local/samba/lib/smb.conf

C'est l'emplacement par défaut du fichier de configuration du serveur smb.conf(5). D'autres emplacements courants où les systèmes installent ce fichier sont /usr/samba/lib/smb.conf et /etc/samba/smb.conf.

Ce fichier décrit tous les services que le serveur doit rendre disponibles aux clients. Voir smb.conf(5) pour plus d'informations.

LIMITATIONS

Sur certains systèmes, smbd ne peut pas revenir à l'utilisateur root après un appel setuid(). De tels systèmes sont appelés systèmes avec uid "trapdoor". Si vous avez un tel système, vous ne pourrez pas vous connecter depuis un client (tel qu'un PC) en tant que deux utilisateurs différents

LIMITATIONS

Only one user can connect to the server at a time. Attempts to connect the second user will result in access denied or similar.

VARIABLES D'ENVIRONNEMENT

PRINTER

Si aucun nom d'imprimante n'est spécifié aux services imprimables, la plupart des systèmes utiliseront la valeur de cette variable (ou lp si cette variable n'est pas définie) comme nom de l'imprimante à utiliser. Ceci n'est cependant pas spécifique au serveur.

INTERACTION PAM

Samba utilise PAM pour l'authentification (lorsqu'un mot de passe en clair est présenté), pour la vérification des comptes (le compte est-il désactivé ?) et pour la gestion des sessions. Le degré de prise en charge de PAM par Samba est limité par les contraintes du protocole SMB et le paramètre obey pam restrictions de smb.conf(5). Lorsque ce paramètre est activé, les restrictions suivantes s'appliquent :

•Validation du compte : Tous les accès à un serveur Samba sont vérifiés par PAM pour s'assurer que le compte est valide, non désactivé et autorisé à se connecter à ce moment-là. Cela s'applique également aux connexions chiffrées.
•Gestion des sessions : En l'absence de sécurité au niveau du partage, les utilisateurs doivent passer les vérifications de session PAM avant que l'accès ne soit accordé. Notez cependant que cela est ignoré en cas de sécurité au niveau du partage. Notez également que certains anciens fichiers de configuration PAM peuvent nécessiter l'ajout d'une ligne pour le support des sessions.

DIAGNOSTICS

La plupart des diagnostics émis par le serveur sont enregistrés dans un fichier journal spécifié. Le nom du fichier journal est spécifié à la compilation, mais peut être remplacé en ligne de commande.

Le nombre et la nature des diagnostics disponibles dépendent du niveau de débogage utilisé par le serveur. En cas de problèmes, définissez le niveau de débogage à 3 et parcourez les fichiers journaux.

La plupart des messages sont raisonnablement explicites. Malheureusement, à l'époque où cette page de manuel a été créée, il y avait trop de diagnostics disponibles dans le code source pour justifier la description de chacun d'entre eux. À ce stade, votre meilleure option reste de rechercher dans le code source et d'inspecter les conditions qui ont conduit aux diagnostics que vous observez.

SIGNaux

L'envoi d'un signal SIGHUP à smbd provoquera le rechargement de son fichier de configuration smb.conf dans un court délai.

Pour arrêter un processus smbd utilisateur, il est recommandé de ne PAS utiliser SIGKILL (-9), sauf en dernier recours, car cela pourrait laisser la zone de mémoire partagée dans un état incohérent. La manière sûre de terminer un smbd est de lui envoyer un signal SIGTERM (-15) et d'attendre qu'il s'arrête de lui-même.

Le niveau de journalisation de débogage de smbd peut être augmenté ou diminué à l'aide du programme smbcontrol(1) (les signaux SIGUSR[1|2] ne sont plus utilisés depuis Samba 2.2). Ceci afin de permettre le diagnostic de problèmes transitoires tout en fonctionnant à un niveau de journalisation normalement bas.

Notez que comme les gestionnaires de signaux envoient une écriture de débogage, ils ne sont pas réentrables dans smbd. Vous devriez donc attendre que smbd soit en état d'attente d'un SMB entrant avant de les déclencher. Il est possible de rendre les gestionnaires de signaux sûrs en débloquant les signaux avant l'appel select et en les rebloquant après, mais cela affecterait les performances.
