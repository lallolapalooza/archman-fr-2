NOM

smokeping_master_slave - Comment exécuter plusieurs instances distribuées de SmokePing

APERÇU

Normalement, les sondes smokeping exécutent leurs tests depuis l'hôte où smokeping est exécuté vers un hôte cible et surveillent la latence de la connexion entre les deux.

Le concept Maître/Esclave permet à toutes les sondes smokeping de s'exécuter à distance. Le cas d'utilisation pour cela est de mesurer la connectivité globale dans un réseau. Si vous souhaitez vérifier que votre serveur DNS central ou votre serveur de fichiers fonctionne pour tout le monde, vous pourriez configurer plusieurs instances smokeping pour surveiller ces deux serveurs à partir de plusieurs emplacements dans votre réseau. Avec la configuration Maître/Esclave de smokeping, ce processus devient beaucoup plus simple, car un serveur maître smokeping peut contrôler plusieurs esclaves.

Toutes les données de surveillance sont stockées et présentées sur le serveur, mais collectées par les esclaves. Les esclaves recevront également leurs informations de configuration du maître, de sorte que vous n'ayez qu'à maintenir le fichier de configuration du serveur maître et que le reste soit géré automatiquement.

DESCRIPTION

Architecture

Les esclaves communiquent avec le serveur maître smokeping via l'interface web normale de smokeping. Au démarrage, chaque esclave se connecte au serveur maître et demande ses affectations. Lorsque l'esclave a effectué une série de sondages, il se reconnecte au maître pour livrer les résultats.

Si l'affectation d'un esclave change, le maître le dira à l'esclave après que celui-ci ait livré ses résultats.

Le maître et les esclaves signent leurs messages en fournissant un code HMAC-MD5 (RFC 2104) du message et un secret partagé. La communication entière peut éventuellement s'exécuter sur SSL.

[esclave 1]     [esclave 2]      [esclave 3]
    |             |              |
    +-------+     |     +--------+
            |     |     |
            v     v     v
          +---------------+
          |     maître     |
          +---------------+

L'esclave est une instance smokeping normale configurée où la configuration provient du maître plutôt que d'un fichier de configuration local. L'esclave essaie de contacter le serveur maître après chaque série de sondages, en fournissant ses résultats. Si le serveur maître ne peut pas être atteint, les résultats seront envoyés au serveur avec la prochaine série de résultats. Les résultats seront stockés dans un fichier sous forme stockable par Perl, de sorte qu'ils survivent à un redémarrage de l'instance smokeping.

Configuration du maître

Pour configurer une configuration maître/esclave, ajoutez une section slaves à votre fichier de configuration smokeping. Chaque esclave a une section dans la partie slaves du fichier de configuration maître. Le nom de la section doit correspondre au nom d'hôte de l'esclave. Si un paramètre de configuration doit être défini sur une valeur spéciale pour l'esclave, utilisez une section d'override pour cela.

Les noms d'esclaves doivent être les noms que les hôtes pensent avoir, pas leurs noms d'hôtes externes, leurs adresses IP ou quoi que ce soit d'autre. Lorsque l'esclave appelle le maître pour obtenir sa configuration ou rapporter ses mesures, il indique au maître son 'hostname'. Ceci, avec le secret partagé, est utilisé pour authentifier et identifier qui est qui.

*** Slaves ***
secrets=/etc/smokeping/slavesecrets.conf 
+esclave1
display_name=erul22
location=Inde
color=ff0000
++override
Probes.FPing.binary = /usr/bin/fping
...

Ensuite, dans la section targets, vous pouvez définir des esclaves à tous les niveaux. Encore une fois, les paramètres sont hérités par les cibles de niveau inférieur et peuvent être remplacés n'importe où dans l'arborescence.

Un esclave recevra alors la configuration appropriée attribuée par le serveur.

*** Targets ***
slaves = esclave1 esclave2
...
+dest1
slaves =
...
+dest2
slaves = esclave1
...
+dest3
...

Les données des esclaves seront stockées dans NomCible~NomEsclave.rrd. Ainsi, l'exemple ci-dessus créerait les fichiers suivants :

dest1.rrd
dest2.rrd
dest2~esclave1.rrd
dest3.rrd
dest3~esclave1.rrd
dest3~esclave2.rrd

Le fichier slavesecrets.conf contient une liste séparée par des deux-points de noms d'hôtes et de secrets.

host1:secret1
host2:secret2

Configuration de l'esclave

Une configuration d'esclave smokeping n'a pas de fichier de configuration. Elle a juste besoin de savoir qu'elle fonctionne en mode esclave et connaître son secret. Le secret est stocké dans un fichier pour une protection optimale. Par défaut, le cache de données persistant sera situé dans /tmp/smokeping.$USER.cache.

./smokeping --master-url=http://smokeping/smokeping.cgi \
            --cache-dir=/var/smokeping/ \
            --shared-secret=/var/smokeping/secret.txt

Le fichier secret.txt contient un seul mot, le secret de cet esclave. Ce n'est PAS le même que le fichier slavesecrets.conf utilisé par le maître.

CONSIDÉRATIONS DE SÉCURITÉ

Le maître a effectivement un accès complet aux hôtes esclaves en tant qu'utilisateur exécutant l'instance smokeping esclave. La configuration est transférée sous forme de code Perl qui est évalué sur l'esclave. Bien que cela soit fait à l'intérieur d'un compartiment restreint "Safe", il existe diverses façons pour un maître malveillant d'intégrer des commandes arbitraires dans la configuration et de les faire exécuter lorsque l'esclave sonde ses cibles.

La robustesse du secret partagé est donc d'une importance capitale. Le craquage du secret permettrait à un attaquant de s'interposer pour injecter une nouvelle configuration malveillante et compromettre l'esclave.
