SMBGET(1) Commandes utilisateur SMBGET(1)

NOM

smbget — utilitaire de type wget pour télécharger des fichiers via SMB

SYNOPIS

smbget [-a, --guest] [-r, --resume] [--recursive] [-D, --dots] [-o, --outputfile] [-q, --quiet] [-v, --verbose] [-b, --blocksize] [-O, --stdout] [-u, --update] [-e, --encrypt] [--limit-rate=INT] [-?|--help] [--usage] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] [-s|--configfile=CONFIGFILE] [--option=name=value] [-l|--log-basename=LOGFILEBASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=NAME-RESOLVE-ORDER] [-O|--socket-options=SOCKETOPTIONS] [-m|--max-protocol=MAXPROTOCOL] [-n|--netbiosname=NETBIOSNAME] [--netbios-scope=SCOPE] [-W|--workgroup=WORKGROUP] [--realm=REALM] [-U|--user=[DOMAIN/]USERNAME%[PASSWORD]] [-N|--no-pass] [--password=STRING] [--pw-nt-hash] [-A|--authentication-file=FILE] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] {smb://hôte/partage/chemin/vers/fichier} [smb://url2/] [...]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

smbget est un utilitaire simple avec la sémantique de wget, qui peut télécharger des fichiers depuis des serveurs SMB. Vous pouvez spécifier les fichiers que vous souhaitez télécharger sur la ligne de commande.

Les fichiers doivent suivre le standard des URL SMB, par ex. utilisez smb://hôte/partage/fichier pour le chemin UNC \\\\HÔTE\\PARTAGE\\fichier.

OPTIONS

-a, --guest

Fonctionner en tant qu'utilisateur invité

-r, --resume

Reprendre automatiquement les fichiers interrompus

--recursive

Télécharger les fichiers de manière récursive

-D, --dots

Afficher des points comme indicateur de progression

-o, --outputfile

Écrire le fichier en cours de téléchargement dans le fichier spécifié. Ne peut pas être utilisé avec -R.

--stdout

Écrire le fichier en cours de téléchargement sur la sortie standard.

-q, --quiet

Être silencieux

-v, --verbose

Être verbeux

-b, --blocksize

Nombre d'octets à télécharger par bloc. Par défaut 64000.

-u, --update

Télécharger uniquement si le fichier distant est plus récent que le fichier local ou si le fichier local est manquant.

-e, --encrypt

Activer le chiffrement SMB.

--limit-rate=INT

Limiter le taux de téléchargement à ce nombre de Ko/s.

-?|--help

Afficher un résumé des options de la ligne de commande.

--usage

Afficher un bref message d'utilisation.

-d|--debuglevel=level

level est un entier allant de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications clientes.

Plus cette valeur est élevée, plus les journaux contiendront de détails sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour un usage quotidien — il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients écrivent dans STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations contenues dans ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client, telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues depuis le fichier de configuration. Si un nom ou une valeur contient un espace, entourez tout le `--option=nom=valeur` avec des guillemets.

-l|--log-basename=répertoires de journaux

Nom de base du répertoire pour les fichiers de journal/débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Activer le rapport de fuites talloc à la sortie.

--leak-report-full

Activer le rapport complet de fuites talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-R|--name-resolve=ORDRE-RÉSOLUTION-NOM

Cette option est utilisée pour déterminer quels services de noms et dans quel ordre résoudre les noms d'hôtes en adresses IP. L'option prend une chaîne d'options de résolution de noms séparées par des espaces. Le mieux est d'entourer tout le `--name-resolve=ORDRE-RÉSOLUTION-NOM` avec des guillemets.

Les options sont : « lmhosts », « host », « wins » et « bcast ». Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir /man/lmhosts.5.en'>lmhosts(5) pour les détails) alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution de nom d'hôte en adresse IP standard, en utilisant les recherches du système sur /etc/hosts, NIS ou DNS. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, cela peut être contrôlé par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP listée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la moins fiable des méthodes de résolution de noms car elle dépend de l'hôte cible étant sur un sous-réseau connecté localement.
Si ce paramètre n'est pas défini, l'ordre de résolution de noms défini dans le paramètre name resolve order du fichier /etc/samba/smb.conf sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ni aucune entrée dans le paramètre name resolve order du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=OPTIONS-SOCKET

Options de socket TCP à définir sur le socket client. Voir le paramètre des options de socket dans la page de manuel de /etc/samba/smb.conf pour la liste des options valides.

-m|--max-protocol=MAXPROTOCOL

La valeur du paramètre (une chaîne de caractères) est le niveau de protocole le plus élevé qui sera supporté par le client.

Notez que la spécification de ce paramètre ici remplacera le paramètre client max protocol du fichier /etc/samba/smb.conf.

-n|--netbiosname=NOM-NETBIOS

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage en ligne de commande aura la priorité sur les réglages dans smb.conf.

--netbios-scope=SCOPE

Ceci spécifie une portée NetBIOS que nmblookup utilisera pour communiquer lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont très rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système en charge de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=GROUPE-TRAVAIL

Définit le domaine SMB de l'utilisateur. Ceci remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est le même que le nom NetBIOS du serveur, cela amène le client à se connecter en utilisant le SAM local du serveur (par opposition au SAM du domaine).

-r|--realm=REALM

Définit le royaume pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

-U|--user=[DOMAIN\]USERNAME[%PASSWORD]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %PASSWORD n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir un mot de passe) et si l'une existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'informations d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'informations d'identification contenant le texte en clair du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas transmettre les informations d'identification sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les autorisations sur le fichier restreignent l'accès aux utilisateurs indésirables. Voir le -A pour plus de détails.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié sur la ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censé contenir un numéro de descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les autorisations sur le fichier restreignent l'accès aux utilisateurs indésirables !

Bien que Samba tente de supprimer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

--pw-nt-hash

Le mot de passe fourni est le hachage NT.

-A|--authentication-file=filename

Cette option vous permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est : 
username = <value>
password = <value>
domain   = <value>

Assurez-vous que les autorisations sur le fichier restreignent l'accès aux utilisateurs indésirables !

-P|--machine-pass

Utilise le mot de passe de compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils client Samba tenteront de s'authentifier à l'aide de Kerberos. Pour l'authentification Kerberos, vous devez utiliser des noms DNS au lieu d'adresses IP lors de la connexion à un service. Par défaut, les outils client Samba tenteront d'utiliser le cache d'informations d'identification Kerberos par défaut (ccache). Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont de saisir un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'informations d'identification Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'informations d'identification pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Tente d'utiliser le cache d'informations d'identification par winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection dans le fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus précis, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

URLS SMB

Les URL SMB doivent être spécifiées dans le format suivant :

smb://[[[domaine;]utilisateur[:motdepasse@]]serveur[/partage[/chemin[/fichier]]]]
smb:// signifie tous les groupes de travail
smb://nom/ signifie, si nom est un groupe de travail, tous les serveurs de ce groupe de travail, ou si nom est un serveur, tous les partages sur ce serveur.

EXEMPLES

# Télécharger récursivement le répertoire 'src'
smbget --recursive smb://rhonwyn/jelmer/src
# Télécharger l'ISO FreeBSD et activer la reprise
smbget --resume smb://rhonwyn/isos/FreeBSD5.1.iso
# Télécharger récursivement toutes les ISO
smbget --recursive --resume smb://rhonwyn/isos
# Sauvegarder mes données sur rhonwyn
smbget --recursive -resume smb://rhonwyn/

BUGS

L'autorisation est refusée est retournée dans certains cas où la cause de l'erreur est inconnue (telle qu'une URL smb:// mal formatée ou une tentative de récupération d'un répertoire sans --resursive activé).
