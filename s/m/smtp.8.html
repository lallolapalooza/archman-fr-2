SMTP(8) Manuel de l'administrateur système SMTP(8)

NOM

smtp, lmtp - Client SMTP+LMTP de Postfix

SYNTAXE

smtp [options générales du démon Postfix] [flags=DORX]
lmtp [options générales du démon Postfix] [flags=DORX]

DESCRIPTION


Le client SMTP+LMTP de Postfix implémente les protocoles de livraison de courrier SMTP et LMTP. Il traite les requêtes de livraison de messages du gestionnaire de files d'attente. Chaque requête spécifie un fichier de file d'attente, une adresse d'expéditeur, un domaine ou un hôte de destination, et des informations sur le destinataire. Ce programme est destiné à être exécuté par le gestionnaire de processus master(8). Le nom du processus, smtp ou lmtp, contrôle le protocole et les noms des paramètres de configuration qui seront utilisés.

Le client SMTP+LMTP met à jour le fichier de file d'attente et marque les destinataires comme terminés, ou il informe le gestionnaire de files d'attente que la livraison doit être réessayée ultérieurement. Les rapports de statut de livraison sont envoyés au démon bounce(8), defer(8) ou trace(8), selon le cas.

La stratégie de recherche de serveur est différente pour SMTP et LMTP, comme décrit dans les sections "RECHERCHE DE SERVEUR SMTP" et "RECHERCHE DE SERVEUR LMTP".

Après une transaction de courrier réussie, une connexion peut être sauvegardée dans le serveur de cache de connexion scache(8), afin qu'elle puisse être utilisée par tout client SMTP+LMTP pour une transaction ultérieure.

Par défaut, la mise en cache des connexions est activée temporairement pour les destinations qui ont un volume élevé de courrier dans la file d'attente active. La mise en cache des connexions peut être activée de manière permanente pour des destinations spécifiques.

RECHERCHE DE SERVEUR SMTP

Le client SMTP de Postfix prend en charge plusieurs destinations séparées par une virgule ou un espace blanc (Postfix 3.5 et versions ultérieures). Chaque destination est essayée dans l'ordre spécifié.

Les destinations SMTP ont le format suivant :

nomdedomaine
nomdedomaine:service
Recherche les échangeurs de courrier pour le domaine spécifié et se connecte au service spécifié (par défaut : smtp). Optionnellement, les échangeurs de courrier peuvent être recherchés avec des requêtes SRV au lieu de MX ; cela nécessite que service soit donné sous forme symbolique.
[nomhote]
[nomhote]:service
Recherche les adresses de l'hôte spécifié et se connecte au service spécifié (par défaut : smtp).
[adresse]
[adresse]:service
Se connecte à l'hôte à l'adresse spécifiée et se connecte au service spécifié (par défaut : smtp). Une adresse IPv6 doit être formatée comme [ipv6:adresse].

RECHERCHE DE SERVEUR LMTP

Le client LMTP de Postfix prend en charge plusieurs destinations séparées par une virgule ou un espace blanc (Postfix 3.5 et versions ultérieures). Chaque destination est essayée dans l'ordre spécifié.

Les destinations LMTP ont le format suivant :

unix:chemin
Se connecte au serveur local de domaine UNIX lié au chemin spécifié. Si le processus s'exécute en chroot, un chemin absolu est interprété par rapport au répertoire de files d'attente de Postfix.
inet:nomdedomaine
inet:nomdedomaine:service
Recherche les serveurs LMTP pour le domaine et le service spécifiés (par défaut : lmtp). Cette forme est prise en charge lorsque les recherches SRV sont activées et nécessite que service soit sous forme symbolique.
inet:nomhote
inet:nomhote:service
Recherche les adresses du nom d'hôte spécifié et se connecte au service spécifié (par défaut : lmtp). Lorsque les recherches SRV sont activées, utilisez la forme [nomhote] pour forcer les recherches d'adresses.
inet:[adresse]
inet:[adresse]:service
Se connecte à l'hôte local ou distant et au service spécifiés (par défaut : lmtp). Une adresse IPv6 doit être formatée comme [ipv6:adresse].

LIVRAISON À UN SEUL DESTINATAIRE

Par défaut, le client SMTP+LMTP de Postfix livre le courrier à plusieurs destinataires par requête de livraison. Ceci est indésirable lors de l'ajout d'un en-tête de message Delivered-to: ou X-Original-To:. Pour empêcher Postfix d'envoyer plusieurs destinataires par requête de livraison, spécifiez

    transport_destination_recipient_limit = 1

dans le fichier main.cf de Postfix, où transport est le nom dans la première colonne de l'entrée master.cf de Postfix pour ce service de livraison de courrier.

SYNTAXE DES ATTRIBUTS DE COMMANDE

flags=DORX (facultatif)
Indicateurs optionnels de traitement des messages.
D
Ajoute un en-tête de message "Delivered-To: destinataire" avec l'adresse du destinataire de l'enveloppe. Note : pour que cela fonctionne, transport_destination_recipient_limit doit être égal à 1 (voir LIVRAISON À UN SEUL DESTINATAIRE ci-dessus pour plus de détails).

L'indicateur D applique également la détection de boucles : si un message contient déjà un en-tête Delivered-To: avec la même adresse de destinataire, le message est retourné comme non livrable. La comparaison des adresses est insensible à la casse.

Cette fonctionnalité est disponible depuis Postfix 3.5.

O
Ajoute un en-tête de message "X-Original-To: destinataire" avec l'adresse du destinataire telle qu'elle a été fournie à Postfix. Note : pour que cela fonctionne, transport_destination_recipient_limit doit être égal à 1 (voir LIVRAISON À UN SEUL DESTINATAIRE ci-dessus pour plus de détails).

Cette fonctionnalité est disponible depuis Postfix 3.5.

R
Ajoute un en-tête de message "Return-Path: <expéditeur>" avec l'adresse de l'expéditeur de l'enveloppe.

Cette fonctionnalité est disponible depuis Postfix 3.5.

X
Indique que la livraison est finale. Cet indicateur affecte le statut rapporté dans les DSN (notifications d'état de livraison) de succès, et le change de "relais" à "livré".

Cette fonctionnalité est disponible depuis Postfix 3.5.

SÉCURITÉ

Le client SMTP+LMTP est modérément sensible à la sécurité. Il communique avec les serveurs SMTP ou LMTP et les serveurs DNS sur le réseau. Le client SMTP+LMTP peut être exécuté en chroot avec des privilèges bas et fixes.

smtp(8) - Manuel Postfix

DESCRIPTION

Le programme smtp(8) est le client SMTP de Postfix. Il est utilisé pour livrer des messages vers des destinations distantes, ou pour livrer des messages vers des destinations locales qui nécessitent une livraison via SMTP (par exemple, via local(8)).

Il peut être utilisé par le démon smtpd(8), ou par d'autres programmes de Postfix, tels que pickup(8) ou qmgr(8).

Le programme smtp(8) peut être configuré pour envoyer des messages à un serveur SMTP de transfert (relay), ou directement au serveur de destination. Il supporte l'authentification SASL et le chiffrement TLS.

Le programme smtp(8) écrit des informations dans le journal des messages, notamment le succès ou l'échec de la livraison, les erreurs de connexion, et les problèmes de protocole. Ces informations sont utilisées par le démon smtpd(8) pour déplacer les messages vers la file d'attente corrupt pour une inspection plus approfondie.

En fonction du réglage du paramètre notify_classes, le postmaster est notifié des retours, des problèmes de protocole et d'autres soucis.

BOGUES


La réutilisation des connexions SMTP et LMTP pour TLS (sans fermer la connexion SMTP ou LMTP) n'est pas supportée avant Postfix 3.4.

La réutilisation des connexions SMTP et LMTP suppose que les identifiants SASL sont valides pour toutes les destinations qui correspondent à la même adresse IP et au même port TCP.

PARAMÈTRES DE CONFIGURATION

Les versions de Postfix 2.3 et ultérieures implémentent le client SMTP et LMTP avec le même programme, et choisissent le protocole et les paramètres de configuration en fonction du nom du processus, smtp ou lmtp.

La plupart des paramètres de configuration smtp_xxx ont un paramètre "miroir" lmtp_xxx pour la fonctionnalité LMTP équivalente. Ce document ne décrit que les paramètres liés à LMTP qui ne sont pas simplement des paramètres "miroir".

Les modifications apportées à main.cf sont prises en compte automatiquement, car les processus smtp(8) ne s'exécutent que pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer un changement.

Le texte ci-dessous fournit uniquement un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

CONTROLES STARTTLS OBSOLÈTES

Les paramètres de configuration suivants existent pour assurer la compatibilité avec les versions de Postfix antérieures à la 2.3. La prise en charge de ces paramètres sera supprimée dans une version future.

smtp_use_tls (non)
Mode opportuniste : utilise le TLS si un serveur SMTP distant annonce la prise en charge de STARTTLS, sinon envoie le courrier en clair.
smtp_enforce_tls (non)
Mode d'application : exige que les serveurs SMTP distants utilisent le chiffrement TLS, et n'envoie jamais de courrier en clair.
smtp_tls_enforce_peername (oui)
Avec le chiffrement TLS obligatoire, exige que le nom d'hôte du serveur SMTP distant corresponde aux informations contenues dans le certificat du serveur SMTP distant.
smtp_tls_per_site (vide)
Tables de recherche optionnelles avec la politique d'utilisation TLS du client SMTP Postfix par destination suivante et par nom d'hôte de serveur SMTP distant.
smtp_tls_cipherlist (vide)
Contrôle obsolète de Postfix < 2.3 pour la liste des chiffrements TLS du client SMTP Postfix.
