SMTPD.CONF(5) Manuel des formats de fichiers SMTPD.CONF(5)

NOM

smtpd.conf — Fichier de configuration du démon SMTP

DESCRIPTION

smtpd.conf est le fichier de configuration du démon de messagerie smtpd(8).

Lorsque les e-mails arrivent, chaque commande “RCPT TO:” génère une enveloppe de messagerie. Si une enveloppe correspond à certains critères prédéfinis (en utilisant la directive match), le message est accepté pour livraison. Une copie du message, ainsi que ses enveloppes associées, est sauvegardée dans la file d'attente des messages et expédiée ultérieurement conformément à un ensemble d'actions associées (en utilisant la directive action). Si une enveloppe ne correspond à aucune option, elle est rejetée. Les règles de correspondance sont évaluées séquentiellement, la première correspondance étant la gagnante.

Le format du fichier de configuration est assez flexible. La ligne actuelle peut être étendue sur plusieurs lignes en utilisant une barre oblique inversée (‘\’). Les commentaires peuvent être placés n'importe où dans le fichier en utilisant une dièse (‘#’) et s'étendent jusqu'à la fin de la ligne actuelle. Il faut être prudent lors de la mise en commentaire de texte multi-lignes : le commentaire est effectif jusqu'à la fin du bloc entier. Les noms d'arguments ne commençant pas par une lettre, un chiffre ou un tiret bas, ainsi que les mots réservés (tels que listen, match et port), doivent être mis entre guillemets. Les arguments contenant des espaces doivent être entourés de guillemets doubles (").

Une macro est définie avec une commande de la forme nom=valeur. Le nom de la macro nom peut contenir des lettres, des chiffres et des tirets bas et ne peut pas être un mot réservé. Dans les arguments non cités, la chaîne $nom est ultérieurement étendue à valeur.

Par exemple :

lan_addr = "192.168.0.1"
listen on $lan_addr
listen on $lan_addr tls auth

La syntaxe de smtpd.conf est décrite ci-dessous.

action nom méthode [options]
Lorsque le processus de la file d'attente traite une enveloppe de la file d'attente de messages, il exécute l'action nom, sélectionnée par la directive match ... action lors de la réception du message. La directive action fournit des données de configuration pour les tentatives de livraison. Les recherches requises sont effectuées au moment de chaque tentative de livraison. Par conséquent, modifier une directive action ou les fichiers qu'elle référence et redémarrer le démon smtpd(8) fait prendre effet aux modifications pour les tentatives de livraison ultérieures pour le distributeur nom respectif, même pour les messages qui étaient déjà bloqués dans la file d'attente avant les modifications de configuration.

Le paramètre de méthode de livraison peut être l'un des suivants :

expand-only
N'accepter le message que si une méthode de livraison a été spécifiée dans un fichier aliases ou .forward.
forward-only
N'accepter le message que si le destinataire résulte en une adresse distante après le traitement des aliases ou du fichier forward.
lmtp destination [rcpt-to]
Livrer le message à un serveur LMTP à destination. L'emplacement peut être exprimé comme hôte:port ou comme socket UNIX.

Optionnellement, rcpt-to peut être spécifié pour utiliser l'adresse e-mail du destinataire (après expansion) au lieu de l'utilisateur local dans la session LMTP en tant que RCPT TO.

maildir [chemin] [junk]
Livrer le message au maildir dans chemin si spécifié, ou par défaut à ~/Maildir.

Le chemin peut contenir des spécificateurs de format qui sont développés avant utilisation (voir SPECIFICATEURS DE FORMAT).

Si l'argument junk est fourni, le message sera déplacé dans le dossier ‘Junk’ s'il contient un en-tête ‘X-Spam’ positif. Ce dossier sera créé sous chemin s'il n'existe pas encore.

mbox
Livrer le message au mbox de l'utilisateur avec mail.local(8).
mda commande
Déléguer la livraison à une commande qui reçoit le message sur son entrée standard (voir COMMANDES MDA).

La commande peut contenir des spécificateurs de format qui sont développés avant utilisation (voir SPECIFICATEURS DE FORMAT).

relay
Relayer le message vers un autre serveur SMTP.

Les méthodes de livraison locale prennent en charge des options supplémentaires :

alias <table>
Utiliser le mappage table pour l'expansion des aliases(5).
ttl n{s|m|h|d}
Spécifier combien de temps un message peut rester dans la file d'attente.
user nomutilisateur
Spécifier le nomutilisateur pour effectuer la livraison, à rechercher avec getpwnam(3).

Ceci est utilisé pour l'hébergement virtuel où un nom d'utilisateur unique est chargé de gérer la livraison pour tous les utilisateurs virtuels.

Cette option n'est pas utilisable avec la méthode de livraison mbox.

Seul le fichier .forward de l'utilisateur de livraison sera traité.

userbase <table>
Utiliser le mappage table pour les recherches d'utilisateurs au lieu de la fonction getpwnam(3).

Le userbase ne s'applique pas à l'option user.

virtual <table>
Utiliser le mappage table pour l'expansion virtuelle. Le format de la table d'alias est décrit dans table(5).
wrapper nom
Utiliser le wrapper spécifié dans mda wrapper.

Les méthodes de livraison par relais prennent également en charge des options supplémentaires :

backup
Fonctionner comme un échangeur de messagerie de secours livrant les messages à tout échangeur de messagerie avec une priorité plus élevée.
backup mx nom
Fonctionner comme un échangeur de messagerie de secours livrant les messages à tout échangeur de messagerie avec une priorité plus élevée que l'échangeur de messagerie identifié comme nom.

helo heloname
Annoncez heloname comme nom d'hôte aux autres expéditeurs de courrier pendant la phase HELO.
helo-src <table>
Utilisez le mappage table pour rechercher un nom d'hôte correspondant à l'adresse source, à annoncer pendant la phase HELO.
domain <domains>
Ne pas effectuer de recherches MX, mais rechercher le domaine de destination dans domains et utiliser l'URL de relais correspondante comme hôte de relais.
host relay-url
Ne pas effectuer de recherches MX, mais relayer les messages vers l'hôte de relais décrit par relay-url. Le format de relay-url est [proto://[label@]]host[:port]. Les protocoles suivants sont disponibles:
smtp
Session SMTP normale avec STARTTLS opportuniste (par défaut).
smtp+tls
Session SMTP normale avec STARTTLS obligatoire.
smtp+notls
Session SMTP en texte clair sans TLS.
lmtp
Session LMTP. Le port est requis.
smtps
Session SMTP avec TLS forcé à la connexion. Le port par défaut est 465.

Sauf indication contraire, le port par défaut est 25.

Le label correspond à une entrée dans une table d'identifiants, comme documenté dans table(5). Il est utilisé avec les protocoles “smtp+tls” et “smtps” pour l'authentification. Les certificats serveur pour ces protocoles sont vérifiés par défaut.

pki pkiname
Pour les connexions sécurisées, utilisez le certificat associé à pkiname (déclaré dans une directive pki) pour prouver l'identité du client au serveur de messagerie distant.
srs
Lors du relais d'un courrier résultant d'un transfert, utilisez le Sender Rewriting Scheme pour réécrire l'adresse de l'expéditeur.
tls [no-verify]
Exiger l'utilisation de TLS lors du relais, avec STARTTLS obligatoire par défaut. Lorsqu'il est utilisé avec un smarthost, le protocole ne doit pas être “smtp+notls://”. Si no-verify est spécifié, ne pas exiger de certificat valide.
protocols protostr
Définir les versions de protocole à utiliser pour les sessions TLS. Reportez-vous à la page de manuel tls_config_parse_protocols(3) pour le format de protostr.
ciphers cipherstr
Définir la liste des chiffrements qui peuvent être utilisés pour les sessions TLS. Reportez-vous à la page de manuel tls_config_set_ciphers(3) pour le format de cipherstr.
auth <table>
Utiliser le mappage table pour se connecter à relay-url en utilisant des identifiants. Cette option n'est utilisable qu'avec l'option host. Le format de la table d'identifiants est décrit dans table(5).
mail-from mailaddr
Utiliser mailaddr comme adresse MAIL FROM dans la transaction SMTP.
src sourceaddr | <sourceaddr>
Utiliser la chaîne ou la table de listes sourceaddr pour l'adresse IP source, ce qui est utile sur les machines ayant plusieurs interfaces. Si la liste contient plus d'une adresse, elles sont toutes utilisées de telle sorte que le trafic soit acheminé aussi efficacement que possible.
admd authservid
Le domaine de gestion administrative auquel appartient ce serveur de messagerie. L'authservid sera transmis aux filtres qui l'utiliseront pour identifier ou marquer les en-têtes authentication-results. S'il est omis, il prendra par défaut le nom du serveur.
bounce warn-interval delay [, delay ...]
Envoyer des messages d'avertissement à l'expéditeur enveloppe lorsque des échecs temporaires de livraison font que le message reste dans la file d'attente plus longtemps que delay. Chaque paramètre delay consiste en un entier décimal positif et une unité s, m, h, ou d. Au plus quatre paramètres delay peuvent être spécifiés. Par défaut, il s'agit de “bounce warn-interval 4h”, envoyant un seul avertissement après quatre heures.
ca caname cert cafile
Associer le fichier certificat de l'autorité de certification (AC) cafile à l'entrée d'AC caname. L'entrée d'AC peut être référencée dans les règles de listen on et action ... relay.
filter chain-name chain {filter-name [, ...]}
Enregistrer une chaîne de filtres chain-name, composée des filtres listés dans filter-name. Les filtres dans une chaîne de filtres sont exécutés dans l'ordre de déclaration pour chaque phase pour laquelle ils sont enregistrés. Une chaîne de filtres peut être utilisée à la place d'un filtre pour toute directive, à l'exception des chaînes de filtres elles-mêmes.
filter filter-name phase phase-name match conditions decision
Enregistrer un filtre filter-name. Une decision sur quoi faire du courrier est prise à la phase phase-name lors de la correspondance des conditions. Les phases, les conditions de correspondance et les décisions sont décrites dans MAIL FILTERING, ci-dessous.
filter filter-name proc proc-name
Enregistrer un filtre "proc" filter-name soutenu par le processus proc-name.
filter filter-name proc-exec command
Enregistrer et exécuter un filtre "proc" filter-name à partir de la command, conformément à l'API smtpd-filters(7). Si command commence par un slash, il est exécuté avec un chemin absolu, sinon il sera exécuté depuis “/usr/lib/smtpd/opensmtpd”.
include "pathname"
Remplacer cette directive par le contenu du fichier de configuration supplémentaire situé au pathname absolu.
listen on interface [family] [options]
Écouter sur l'interface pour les connexions entrantes, en utilisant la même syntaxe que ifconfig(8). Le paramètre interface peut également être un groupe d'interfaces, une adresse IP ou un nom de domaine. L'écoute peut éventuellement être restreinte à une famille d'adresses spécifique family, qui peut être inet4 ou inet6.

Les options sont les suivantes:

auth [<authtable>]
Support SMTPAUTH: les clients ne peuvent démarrer des transactions SMTP qu'après une authentification réussie. Les utilisateurs sont authentifiés soit par leurs propres identifiants de connexion normaux, soit par une table d'identifiants authtable, dont le format est décrit dans table(5).
auth-optional [<authtable>]
Support SMTPAUTH optionnel: les clients n'ont pas besoin de s'authentifier, mais peuvent le faire. Cela permet à une directive listen on d'accepter à la fois le courrier entrant des expéditeurs non fiables et de permettre le courrier sortant des utilisateurs authentifiés (en utilisant match auth). Elle peut être utilisée dans des situations où il n'est pas possible d'écouter sur un port séparé (généralement le port de soumission, 587) pour que les utilisateurs s'authentifient.
ca caname
Pour
secure connections, utilisez le certificat d'autorité de certification associé à caname (déclaré dans une directive ca) comme certificat d'autorité de certification lors de la vérification des certificats clients.
filter nom
Appliquer le filtre nom aux connexions gérées par cet écouteur.
hostname hostname
Utiliser hostname dans la bannière de salutation au lieu du nom de serveur par défaut.
hostnames <noms>
Remplacer le nom du serveur pour des adresses spécifiques. La table noms contient une correspondance entre les adresses IP et les noms d'hôte. Si l'adresse sur laquelle arrive la connexion apparaît dans la correspondance, le nom d'hôte associé est utilisé.
mask-src
Omettre la partie from lors de la préposition des en-têtes "Received".
no-dsn
Désactiver l'extension DSN (Delivery Status Notification).
pki pkiname
Pour les connexions sécurisées, utiliser le certificat associé à pkiname (déclaré dans une directive pki) pour prouver l'identité d'un serveur de messagerie. Cette option peut être utilisée plusieurs fois pour fournir des certificats alternatifs pour SNI.
port [port]
Écouter sur le port donné au lieu du port par défaut 25.
proxy-v2
Prendre en charge le protocole PROXYv2, en réécrivant de manière appropriée l'adresse source reçue du proxy.
received-auth
Dans les en-têtes "Received", indiquer si la session était authentifiée et par quel utilisateur local.
senders <utilisateurs> [masquerade]
Rechercher l'utilisateur authentifié dans la table de correspondance utilisateurs pour trouver les adresses e-mail que cet utilisateur est autorisé à utiliser pour envoyer des e-mails. De plus, si l'option masquerade est fournie, l'en-tête From est réécrit pour correspondre à l'expéditeur fourni dans la session SMTP.
smtps [verify]
Prendre en charge SMTPS, par défaut sur le port 465. Mutuellement exclusif avec tls. Avec l'option verify, les clients doivent également fournir un certificat valide pour établir une session SMTP.
tag tag
Les clients se connectant à l'écouteur sont marqués avec le tag donné.
tls
Prendre en charge STARTTLS, par défaut sur le port 25. Mutuellement exclusif avec smtps.
tls-require [verify]
Similaire à tls, mais force les clients à établir une connexion sécurisée avant d'être autorisés à démarrer une transaction SMTP. Avec l'option verify, les clients doivent également fournir un certificat valide pour établir une session SMTP.
protocols protostr
Définir les versions de protocole à utiliser pour les sessions TLS. Se référer à la page de manuel tls_config_parse_protocols(3) pour le format de protostr.
ciphers cipherstr
Définir la liste des chiffrements qui peuvent être utilisés pour les sessions TLS. Se référer à la page de manuel tls_config_set_ciphers(3) pour le format de cipherstr.
listen on socket [options]
Écouter les connexions SMTP entrantes sur le socket de domaine Unix /run/smtpd.sock. Ceci est fait par défaut, même si la directive est absente.

Les options sont les suivantes :

filter nom
Appliquer le filtre nom aux connexions gérées par cet écouteur.
mask-src
Omettre la partie from lors de la préposition des en-têtes "Received".
no-dsn
Désactiver l'extension DSN (Delivery Status Notification).
tag tag
Les clients se connectant à l'écouteur sont marqués avec le tag donné.
match options action name
Si au moins une enveloppe de courrier correspond aux options d'une directive match action, recevoir le message entrant, placer une copie dans chaque enveloppe correspondante, et enregistrer atomiquement les enveloppes dans la file d'attente de courrier pour un traitement ultérieur par le répartiteur name respectif qui doit être déclaré au préalable avec la directive action.

Les options de correspondance suivantes sont prises en charge et peuvent toutes être niées :

[!] for any
Spécifier que la session peut s'adresser à n'importe quelle destination.
[!] for local
Spécifier que la session peut s'adresser à n'importe quel domaine local. C'est la valeur par défaut et peut être omise.
[!] for domain [regex] domain | <domain>
Spécifier que la session peut s'adresser à la chaîne ou à la table de listes domain. Le mot-clé regex est requis si domain est une expression régulière ou une table d'expressions régulières.
[!] for rcpt-to [regex] recipient | <recipient>
Spécifier que la session peut s'adresser à la chaîne ou à la table de listes recipient. Le mot-clé regex est requis si recipient est une expression régulière ou une table d'expressions régulières.
[!] from any
Spécifier que la session peut provenir de n'importe quelle source.
[!] from auth
Spécifier que la session peut provenir de n'importe quel utilisateur authentifié, quelle que soit l'adresse IP source.
[!] from auth [regex] user | <user>
Spécifier que la session peut provenir de l'utilisateur authentifié ou de la liste d'utilisateurs user, quelle que soit l'adresse IP source. Le mot-clé regex est requis si user est une expression régulière ou une table d'expressions régulières.
[!] from local
Spécifier que la session ne peut provenir que d'une adresse IP locale, ou de l'enfileur local. C'est la valeur par défaut et peut être omise.
[!] from mail-from [regex] sender | <sender>
Spécifier que la session peut provenir de l'expéditeur ou de la liste d'expéditeurs sender, quelle que soit l'adresse IP source. Le mot-clé regex est requis si sender est une expression régulière ou une table d'expressions régulières.
[!] from rdns
Spécifier que la session ne peut provenir que d'une adresse IP qui se résout en un DNS inversé.
[!] from rdns [regex] hostname | <hostname>
Spécifier que la session ne peut provenir que d'une adresse IP qui se résout en un DNS inversé correspondant à la chaîne ou à la chaîne de liste hostname. Le mot-clé regex est requis si hostname est une expression régulière ou une table d'expressions régulières.
[!] from socket
Spécifier que la session ne peut provenir que de l'enfileur local.
[!] from src [regex] address | <address>
Spécifier que la session ne peut provenir que de la chaîne ou de la table de listes address, qui peut être une adresse spécifique ou un sous-réseau exprimé en notation CIDR. Le mot-clé regex est requis si address est une expression régulière ou une table d'expressions régulières.

De plus, les options de transaction suivantes peuvent être mises en correspondance :

[!] auth
Correspond aux transactions qui ont été authentifiées.
[!] auth [regex] nomutilisateur | <nomutilisateur>
Correspond aux transactions qui ont été authentifiées pour l'utilisateur ou la liste d'utilisateurs nomutilisateur. Le mot-clé regex est requis si nomutilisateur est une expression régulière ou une table d'expressions régulières.
[!] helo [regex] nomhelo | <nomhelo>
Spécifie que le HELO / EHLO de la session doit correspondre à la chaîne ou à la table de chaînes nomhelo. Le mot-clé regex est requis si nomhelo est une expression régulière ou une table d'expressions régulières.
[!] mail-from [regex] expediteur | <expediteur>
Spécifie que le MAIL FROM de la transaction doit correspondre à la chaîne ou à la table de chaînes expediteur. Le mot-clé regex est requis si expediteur est une expression régulière ou une table d'expressions régulières.
[!] rcpt-to [regex] destinataire | <destinataire>
Spécifie que le RCPT TO de la transaction doit correspondre à la chaîne ou à la table de chaînes destinataire. Le mot-clé regex est requis si destinataire est une expression régulière ou une table d'expressions régulières.
[!] tag [regex] tag
Correspond aux transactions étiquetées avec le tag donné. Le mot-clé regex est requis si tag est une expression régulière.
[!] tls
Spécifie que la transaction doit avoir lieu dans un canal TLS.
match options reject
Rejette le message entrant pendant le dialogue SMTP. Les mêmes options sont supportées que pour la directive match action.
mda wrapper nom commande
Associe la commande avec le wrapper de l'agent de livraison de courrier nommé nom. Lorsqu'une livraison locale spécifie un wrapper, la commande associée au wrapper sera exécutée à la place. La commande peut contenir des spécificateurs de format (voir FORMAT SPECIFIERS).
mta max-deferred nombre
Lorsque la livraison à un hôte donné est suspendue en raison d'échecs temporaires, met en cache au maximum nombre enveloppes pour cet hôte afin qu'elles puissent être livrées dès qu'une autre livraison réussit à cet hôte. La valeur par défaut est 100.
pki nompki cert fichiercert
Associe le fichier de certificat fichiercert à l'entrée pki nompki. L'entrée pki définit une configuration de paire de clés qui peut être référencée dans les règles d'écoute et les actions de relais.

Une chaîne de certificats peut être créée en ajoutant un ou plusieurs certificats, y compris un certificat d'autorité de certification, à fichiercert. La création de certificats est documentée dans starttls(8).

pki nompki key fichiercle
Associe la clé située dans fichiercle à l'entrée pki nompki.
pki nompki dhe param
Spécifie les paramètres DHE à utiliser pour les suites de chiffrement DHE avec l'entrée pki nompki. Les valeurs de paramètre valides sont none, legacy, et auto. Pour legacy, une longueur de clé fixe de 1024 bits est utilisée, tandis que pour auto, la longueur de clé est déterminée automatiquement. La valeur par défaut est none, ce qui désactive les suites de chiffrement DHE.
proc nomproc commande
Enregistre un processus externe nommé nomproc à partir de la commande, conformément à l'API smtpd-filters(7). De tels processus peuvent être utilisés pour partager la même instance entre plusieurs filtres. Si commande commence par un slash, elle est exécutée avec un chemin absolu, sinon elle sera exécutée depuis “/usr/lib/smtpd/opensmtpd”.
queue compression
Stocke les fichiers de la file d'attente au format compressé. Cela peut être utile pour économiser de l'espace disque.
queue encryption [cle]
Chiffre les fichiers de la file d'attente avec EVP_aes_256_gcm(3). Si aucune cle n'est spécifiée, elle est lue avec getpass(3). Si la chaîne stdin ou un seul tiret (‘-’) est donnée au lieu d'une cle, la clé est lue depuis l'entrée standard.
queue ttl delai
Définit le temps d'expiration par défaut pour les messages temporairement non livrables, donné comme un entier décimal positif suivi d'une unité s, m, h, ou d. La valeur par défaut est quatre jours (4d).
smtp ciphers controle
Définit la chaîne de controle pour SSL_CTX_set_cipher_list(3). La valeur par défaut est "HIGH:!aNULL:!MD5".
smtp limit max-mails compte
Limite le nombre de messages à compte pour chaque session. La valeur par défaut est 100.
smtp limit max-rcpt compte
Limite le nombre de destinataires à compte pour chaque transaction. La valeur par défaut est 1000.
smtp max-message-size taille
Rejette les messages dont la taille dépasse taille, donnée comme un nombre positif d'octets ou comme une chaîne à analyser avec scan_scaled(3). La valeur par défaut est "35M".
smtp sub-addr-delim caractere
Lors de la résolution de la partie locale d'une adresse e-mail locale, ignore le caractère ASCII caractere et tous les caractères qui le suivent. La valeur par défaut est ‘+’.
srs key [backup] secret
Définit la clé secrète à utiliser pour SRS, le Sender Rewriting Scheme. L'option backup peut être spécifiée pour définir une clé secrète à utiliser comme solution de repli pour SRS ; cela peut être utilisé pour implémenter la rotation des clés SRS.
srs ttl delai
Définit le délai de temps de vie (TTL) pour les enveloppes SRS. Après ce délai, une réponse de rebond à l'adresse SRS sera écartée pour limiter les risques d'adresses falsifiées. La valeur par défaut est quatre jours (4d).
table nom [type:]chemin
Les tables fournissent des informations de configuration supplémentaires pour smtpd(8) sous forme de listes ou de correspondances clé-valeur. Le format des entrées dépend de l'utilisation de la table. Référez-vous à table(5) pour la documentation exhaustive.

Chaque table est identifiée par un nom arbitraire et unique.

Si le type est db, les informations sont stockées dans un fichier créé avec makemap(8) ; si c'est file ou omis, les informations sont stockées dans un fichier texte brut utilisant le format décrit dans table(5). Le chemin du fichier doit être absolu.

table nom {valeur [, ...]}
Au lieu d'utiliser un fichier séparé, déclare une table de liste contenant les valeurs statiques données. La table doit contenir au moins une valeur et peut déclarer plusieurs valeurs sous forme de liste séparée par des virgules (espaces blancs facultatifs).
table nom {cle=valeur [, ...]}
Au lieu d'utiliser un fichier séparé, déclare une table de correspondance contenant les paires statiques données cle-valeur. La table doit contenir au moins une paire clé-valeur et peut déclarer plusieurs paires sous forme de liste séparée par des virgules (espaces blancs facultatifs).

FILTRAGE DU COURRIER

Dans un flux de travail régulier, smtpd(8) peut accepter ou rejeter un message en se basant uniquement sur le contenu des enveloppes. Ses décisions portent sur la gestion du message, et non sur la gestion d'une session active.

Le filtrage étend le processus de prise de décision en permettant à smtpd(8) de s'arrêter à chaque phase d'une session SMTP, de vérifier que les conditions sont remplies, puis de décider si une session est autorisée à avancer.

Avec le filtrage, une session peut être interrompue à n'importe quelle phase avant qu'une enveloppe ne soit complète. Un message peut également être rejeté après sa soumission, qu'il ait été accepté ou non.

Les phases suivantes sont actuellement prises en charge :

connect lors de la connexion, avant que la bannière ne soit affichée
helo après la soumission de la commande HELO
ehlo après la soumission de la commande EHLO
mail-from après la soumission de la commande MAIL FROM
rcpt-to après la soumission de la commande RCPT TO
data après la soumission de la commande DATA
commit après la soumission complète du message

À chaque phase, diverses conditions peuvent être mises en correspondance. Les données fcrdns, rdns et src sont disponibles dans toutes les phases, mais d'autres données doivent avoir été soumises auparavant pour être disponibles.

fcrdns le DNS inversé confirmé par DNS direct est valide
rdns la session a un DNS inversé
rdns <table> la session a un DNS inversé dans la table
src <table> l'adresse source est dans la table
helo <table> le nom HELO est dans la table
auth la session est authentifiée
auth <table> le nom d'utilisateur de la session est dans la table
mail-from <table> l'adresse de l'expéditeur est dans la table
rcpt-to <table> l'adresse du destinataire est dans la table

Toutes ces conditions peuvent être niées en les faisant précéder d'un point d'exclamation :

!fcrdns le DNS inversé confirmé par DNS direct est invalide

Toutes les conditions utilisant une table peuvent indiquer que la table contient des expressions régulières en faisant précéder le nom de la table par le mot-clé regex.

helo regex <table> le nom HELO correspond à une regex dans la table

Enfin, un certain nombre de décisions peuvent être prises :

bypass la session ou la transaction contourne les filtres
disconnect message la session est déconnectée avec le message
junk la session ou la transaction est marquée comme indésirable, c'est-à-dire qu'un en-tête ‘X-Spam: yes’ est ajouté à tous les messages
reject message la commande est rejetée avec le message
rewrite value le paramètre de la commande est réécrit avec la valeur

Les décisions impliquant un message nécessitent que le message soit valide selon la RFC, c'est-à-dire qu'elles doivent commencer par un code d'état 4xx ou 5xx. Les décisions peuvent être prises à n'importe quelle phase, bien que le marquage comme indésirable ne puisse se produire qu'avant qu'un message ne soit validé.

SPÉCIFICATEURS DE FORMAT

Certaines directives de configuration prennent en charge l'expansion de leurs paramètres à l'exécution. Ces directives (par exemple action maildir, action mda) peuvent utiliser des spécificateurs de format qui sont développés avant la livraison ou le relais. Les formats suivants sont actuellement pris en charge :

%{sender} adresse e-mail de l'expéditeur, peut être une chaîne vide
%{sender.user} partie utilisateur de l'adresse e-mail de l'expéditeur, peut être vide
%{sender.domain} partie domaine de l'adresse e-mail de l'expéditeur, peut être vide
%{rcpt} adresse e-mail du destinataire
%{rcpt.user} partie utilisateur de l'adresse e-mail du destinataire
%{rcpt.domain} partie domaine de l'adresse e-mail du destinataire
%{dest} adresse e-mail du destinataire après expansion
%{dest.user} partie utilisateur après expansion
%{dest.domain} partie domaine après expansion
%{user.username} utilisateur local
%{user.directory} répertoire personnel de l'utilisateur local
%{mbox.from} nom utilisé dans les lignes de séparation mbox From
%{mda} commande mda, disponible uniquement pour les wrappers mda

Les formats d'expansion prennent également en charge l'expansion partielle à l'aide de notations entre crochets optionnelles avec un décalage de sous-chaîne. Par exemple, avec le domaine du destinataire “example.org” :

%{rcpt.domain[0]} s'étend à “e”
%{rcpt.domain[1]} s'étend à “x”
%{rcpt.domain[8:]} s'étend à “org”
%{rcpt.domain[-3:]} s'étend à “org”
%{rcpt.domain[0:6]} s'étend à “example”
%{rcpt.domain[0:-4]} s'étend à “example”

De plus, des modificateurs peuvent être appliqués au jeton. Par exemple, avec le destinataire “User+Tag@Example.org” :

%{rcpt:lowercase} s'étend à “user+tag@example.org”
%{rcpt:uppercase} s'étend à “USER+TAG@EXAMPLE.ORG”
%{rcpt:strip} s'étend à “User@Example.org”
%{rcpt:lowercase|strip} s'étend à “user@example.org”

Pour des raisons de sécurité, les valeurs développées sont assainies et les caractères potentiellement dangereux sont remplacés par des ‘:’. Dans les situations où ils sont souhaitables, le modificateur “raw” peut être appliqué. Par exemple, avec le destinataire “user+t?g@example.org” :

%{rcpt} s'étend à “user+t:g@example.org”
%{rcpt:raw} s'étend à “user+t?g@example.org”

COMMANDES MDA

Lorsque la méthode de livraison d'une action est mda, smtpd(8) exécute la commande associée pour la livraison avec le contenu du courrier fourni via l'entrée standard. La commande est censée lire tout le contenu du courrier.

Le code de sortie de la commande signale le résultat de la livraison : le statut 0 (EX_OK) indique une livraison réussie ; les statuts 71 (EX_OSERR) et 75 (EX_TEMPFAIL) indiquent des échecs temporaires ; et tous les autres codes de sortie sont considérés comme des échecs permanents.

Les variables d'environnement suivantes sont définies :

DOMAIN
Le domaine du destinataire.
EXTENSION
La sous-adresse du destinataire (peut être non définie).
HOME
Le répertoire de connexion de l'utilisateur de livraison.
LOCAL
La partie locale de l'adresse de l'utilisateur destinataire.
LOGNAME
Le nom de connexion de l'utilisateur.
ORIGINAL_RECIPIENT
L'adresse du destinataire original.
PATH
Défini sur _PATH_DEFPATH. Traditionnellement /usr/bin:/bin, mais développé pour inclure /usr/sbin, /sbin, /usr/X11R6/bin, /usr/local/bin, et /usr/local/sbin dans OpenBSD.
RECIPIENT
L'adresse du destinataire final.
SENDER
L'adresse de l'expéditeur (peut être vide).
SHELL
Défini sur /bin/sh.
USER
Synonyme de LOGNAME pour la compatibilité descendante.

FICHIERS

/etc/smtpd/smtpd.conf
Fichier de configuration par défaut de smtpd(8).
/etc/smtpd/mailname
Si ce fichier existe, la première ligne est utilisée comme nom du serveur. Sinon, le nom du serveur est dérivé du nom d'hôte local retourné par gethostname(3), soit directement s'il s'agit d'un nom de domaine pleinement qualifié, soit en récupérant le nom canonique associé via getaddrinfo(3).
/run/smtpd.sock
Socket de domaine Unix pour les connexions SMTP entrantes.
/var/spool/smtpd/
Répertoires de spool pour le courrier pendant le traitement.

EXEMPLES

Le fichier smtpd.conf par défaut qui est livré avec OpenBSD écoute sur l'interface réseau de bouclage (lo0) et autorise le courrier des utilisateurs et des démons sur la machine locale, tout en autorisant l'envoi de courrier vers des serveurs SMTP distants. Des configurations plus complexes sont présentées ci-dessous.

Ce premier exemple est similaire à la configuration par défaut, mais tout le courrier sortant est transféré vers un serveur SMTP distant. Un fichier de secrets est nécessaire pour spécifier un nom d'utilisateur et un mot de passe :

# touch /etc/smtpd/secrets
# chmod 640 /etc/smtpd/secrets
# chown root:smtpd /etc/smtpd/secrets
# echo "bob nom_utilisateur:mot_de_passe" > /etc/smtpd/secrets

smtpd.conf ressemblerait à ceci :

table aliases file:/etc/smtpd/aliases
table secrets file:/etc/smtpd/secrets

listen on lo0

action "local_mail" mbox alias <aliases>
action "outbound" relay host smtp+tls://bob@smtp.example.com \
	auth <secrets>

match from local for local action "local_mail"
match from local for any action "outbound"

Dans ce deuxième exemple, l'objectif est de permettre la livraison et le transfert de courrier uniquement pour les utilisateurs qui peuvent s'authentifier (en utilisant leurs identifiants de connexion normaux). Un certificat RSA doit être fourni pour prouver l'identité du serveur. Le serveur de messagerie écoute sur toutes les interfaces pointées par les routes par défaut. Le courrier destiné à une destination locale est envoyé à un MDA externe. Tout d'abord, le certificat RSA est créé :

# openssl genrsa -out /etc/ssl/private/mail.example.com.key 4096
# openssl req -new -x509 -key /etc/ssl/private/mail.example.com.key \
	-out /etc/ssl/mail.example.com.crt -days 365
# chmod 600 /etc/ssl/mail.example.com.crt
# chmod 600 /etc/ssl/private/mail.example.com.key

Dans l'exemple ci-dessus, un certificat valide pendant un an a été créé. Le fichier de configuration ressemblerait à ceci :

pki mail.example.com cert "/etc/ssl/mail.example.com.crt"
pki mail.example.com key "/etc/ssl/private/mail.example.com.key"

table aliases file:/etc/smtpd/aliases

listen on lo0
listen on egress tls pki mail.example.com auth

action mda_with_aliases mda "/path/to/mda -f -" alias <aliases>
action mda_without_aliases mda "/path/to/mda -f -"
action "outbound" relay

match for local action mda_with_aliases
match from any for domain example.com action mda_without_aliases
match for any action "outbound"
match auth from any for any action "outbound"

Pour les sites qui souhaitent signer les messages en utilisant DKIM, l'exemple suivant utilise opensmtpd-filter-dkimsign pour la signature DKIM :

table aliases file:/etc/smtpd/aliases

filter "dkimsign" proc-exec "filter-dkimsign -d <domaine> -s <sélecteur> \
	-k /etc/smtpd/dkim/private.key" user _dkimsign group _dkimsign

listen on socket filter "dkimsign"
listen on lo0 filter "dkimsign"

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"

Alternativement, le paquet opensmtpd-filter-rspamd peut être utilisé pour fournir une intégration avec rspamd, un démon tiers qui fournit plusieurs fonctionnalités antispam ainsi que la signature DKIM. En plus de la configuration de rspamd lui-même, cela nécessite l'utilisation du mot-clé proc-exec :

filter "rspamd" proc-exec "filter-rspamd"

Les sites qui acceptent les messages non locaux peuvent réduire le volume de spam reçu en rejetant les messages forgés qui prétendent provenir du domaine local. L'exemple suivant utilise une table de liste other-relays pour spécifier les adresses IP des relais qui peuvent légitimement être à l'origine de courriers avec le domaine du propriétaire comme expéditeur.

table aliases file:/etc/smtpd/aliases
table other-relays file:/etc/smtpd/other-relays

listen on lo0
listen on egress

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"
match !from src <other-relays> mail-from "@example.com" for any \
      reject
match from any for domain example.com action "local_mail"
