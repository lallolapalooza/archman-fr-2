SMBCQUOTAS(1) Commandes utilisateur SMBCQUOTAS(1)

NOM

smbcquotas - Définir ou obtenir les QUOTAS des partages NTFS 5

SYNTAXE

smbcquotas {//serveur/partage} [-u|--quota-user=UTILISATEUR] [-L|--list] [-F|--fs] [-S|--set=CHAINE_DEFINITION] [-n|--numeric] [-v|--verbose] [-t|--test-args] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=FICHIER_JOURNAL_BASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOLUTION_NOM] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=PROTOCOLE_MAX] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=SCOPE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR[%MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

Le programme smbcquotas manipule les quotas NT sur les partages de fichiers SMB.

OPTIONS

Les options suivantes sont disponibles pour le programme smbcquotas.

-u|--quota-user utilisateur

Spécifie l'utilisateur dont les quotas sont obtenus ou définis. Par défaut, le nom d'utilisateur de l'utilisateur courant est utilisé.

-L|--list

Liste tous les enregistrements de quotas du partage.

-F|--fs

Affiche l'état du quota du partage et les limites par défaut.

-S|--set COMMANDE_DEFINITION_QUOTA

Cette commande définit/modifie les quotas pour un utilisateur ou sur le partage, en fonction du paramètre COMMANDE_DEFINITION_QUOTA qui est décrit plus loin.

-n|--numeric

Cette option affiche toutes les informations de QUOTA sous forme numérique. La valeur par défaut est de convertir les SID en noms et les limites de QUOTA en un format de chaîne lisible.

-t|--test-args

Ne fait rien en réalité, valide uniquement la correction des arguments.

-v|--verbose

Verbeux.

-?|--help

Imprime un résumé des options de ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus les journaux contiendront de détails sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de la résolution d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirige la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou ne fournir que des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Cela remplace les valeurs par défaut compilées et les options lues depuis le fichier de configuration. Si un nom ou une valeur inclut un espace, entourez toute l'option --option=nom=valeur avec des guillemets.

-l|--log-basename=répertoire_journal

Nom de base du répertoire pour les fichiers de journal/débogage. L'extension ".nomprog" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuites talloc à la sortie.

--leak-report-full

Active le rapport complet de fuites talloc à la sortie.

-V|--version

Imprime le numéro de version du programme.

-R|--name-resolve=ORDRE_RESOLUTION_NOM

Cette option est utilisée pour déterminer quels services de nommage et dans quel ordre résoudre les noms d'hôte en adresses IP. L'option prend une chaîne séparée par des espaces de différentes options de résolution de noms. Il est préférable d'entourer tout l'argument --name-resolve=ORDRE_RESOLUTION_NOM avec des guillemets.

Les options sont : "lmhosts", "host", "wins" et "bcast". Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir le fichier lmhosts(5) pour les détails) alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution standard de nom d'hôte en adresse IP, en utilisant les recherches du système dans /etc/hosts, NIS ou DNS. Cette méthode de résolution de noms dépend du système d'exploitation ; par exemple, sur IRIX ou Solaris, elle peut être contrôlée par le fichier /etc/nsswitch.conf. Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP listée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend du fait que l'hôte cible soit sur un sous-réseau localement connecté.
Si ce paramètre n'est pas défini, alors l'ordre de résolution des noms défini dans le paramètre (name resolve order) du fichier /etc/samba/smb.conf sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ni aucune entrée dans le paramètre name resolve order du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=OPTIONS_SOCKET

Options de socket TCP à définir sur le socket client. Voir le paramètre des options de socket dans la page de manuel de /etc/samba/smb.conf pour la liste des options valides.

-m|--max-protocol=PROTOCOLE_MAX

La valeur du paramètre (une chaîne) est le niveau de protocole le plus élevé qui sera supporté par le client.

Notez que la spécification de ce paramètre ici remplacera le paramètre client max protocol du fichier /etc/samba/smb.conf.

-n|--netbiosname=NOM_NETBIOS

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage en ligne de commande aura la priorité sur les réglages dans /etc/samba/smb.conf.

--netbios-scope=SCOPE

Spécifie une portée NetBIOS que nmblookup utilisera pour communiquer lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont *très* rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système en charge de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=GROUPE_TRAVAIL

Définit le domaine SMB du nom d'utilisateur. Cela remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est identique au nom NetBIOS du serveur, cela amène le client à se connecter en utilisant le SAM local du serveur (par opposition au SAM du domaine).

Notez que la spécification de ce paramètre ici remplacera le paramètre workgroup du fichier /etc/samba/smb.conf.

-r|--realm=DOMAINE

Définit le domaine (realm) pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm du fichier /etc/samba/smb.conf.

-U|--user=[DOMAINE\]NOM_UTILISATEUR[%MOT_DE_PASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOT_DE_PASSE n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contient le mot de passe séparé par un %), puis la variable LOGNAME (qui ne doit pas contenir de mot de passe) et si l'un ou l'autre existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache de credentials Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier de credentials qui contient le texte brut du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les credentials en ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés. Voir -A pour plus de détails.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts ou au passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour la sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre du processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une concurrence.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié en ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié en ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera ignoré silencieusement et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts ou au passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour la sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, puis PASSWD_FD qui est censée contenir un descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne devrait contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

Bien que Samba tente de supprimer le mot de passe du titre du processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une concurrence.

--pw-nt-hash

Le mot de passe fourni est le hash NT.

-A|--authentication-file=filename

Cette option permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est : 
username = <valeur>
password = <valeur>
domain   = <valeur>

Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

-P|--machine-pass

Utilise le mot de passe de compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils clients Samba tenteront de s'authentifier en utilisant Kerberos. Pour l'authentification Kerberos, vous devez utiliser des noms DNS au lieu d'adresses IP lors de la connexion à un service. Par défaut, les outils clients Samba essaieront d'utiliser le cache de credentials Kerberos (ccache) par défaut. Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache de credentials Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos du fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache de credentials pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Essayer d'utiliser le cache de credentials par winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection du fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus fin, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

QUOTA_SET_COMMAND

Le format d'une QUOTA_SET_COMMAND est un nom d'opération suivi d'un ensemble de paramètres spécifiques à cette opération.

Pour définir les quotas utilisateur pour l'utilisateur spécifié par -u ou pour le nom d'utilisateur actuel :

UQLIM:<username>:<softlimit>/<hardlimit>

Pour définir les quotas par défaut pour un partage :

FSQLIM:<softlimit>/<hardlimit>

Pour modifier les paramètres de quota du partage :

FSQFLAGS:QUOTA_ENABLED/DENY_DISK/LOG_SOFTLIMIT/LOG_HARD_LIMIT

Toutes les limites sont spécifiées en nombre d'octets.

STATUT DE SORTIE

Le programme smbcquotas définit le statut de sortie en fonction du succès ou non des opérations effectuées. Le statut de sortie peut être l'une des valeurs suivantes.

Si l'opération a réussi, smbcquotas renvoie un statut de sortie de 0. Si smbcquotas n'a pas pu se connecter au serveur spécifié, ou s'il y a eu une erreur lors de l'obtention ou de la définition du ou des quotas, un statut de sortie de 1 est retourné. S'il y a eu une erreur lors de l'analyse des arguments de la ligne de commande, un statut de sortie de 2 est retourné.
