NOM

smartd.conf - Fichier de configuration du démon de surveillance SMART

DESCRIPTION

[Cette page de manuel est générée pour la version Linux de smartmontools. Elle ne contient pas d'informations spécifiques à d'autres plateformes.]

/etc/smartd.conf est le fichier de configuration du démon smartd.

Si le fichier de configuration /etc/smartd.conf est présent, smartd le lit au démarrage. Si smartd reçoit ensuite un signal HUP, il relira le fichier de configuration. Si smartd fonctionne en mode debug, un signal INT le fera également relire le fichier de configuration. Ce signal peut être généré en tapant <CONTROL-C> dans la fenêtre du terminal où smartd est en cours d'exécution.

En l'absence de fichier de configuration, smartd essaiera d'ouvrir tous les périphériques disponibles (voir la page de manuel de smartd(8)). Un fichier de configuration avec une seule ligne 'DEVICESCAN -a' aurait le même effet.

Cela peut être gênant si vous avez un périphérique ATA ou SCSI qui se bloque ou se comporte mal lors de la réception de commandes SMART. Même si cela ne cause aucun problème, vous pourriez être dérangé par la série de messages d'erreur concernant les périphériques qui ne peuvent pas être ouverts.

On peut éviter ce problème, et gagner plus de contrôle sur les types d'événements surveillés par smartd, en utilisant le fichier de configuration /etc/smartd.conf. Ce fichier contient une liste de périphériques à surveiller, un périphérique par ligne. Un exemple de fichier est inclus avec la distribution smartmontools. Vous trouverez ce fichier de configuration d'exemple dans /usr/share/doc/smartmontools/. Par mesure de sécurité, le fichier de configuration ne devrait être inscriptible que par root. La syntaxe du fichier est la suivante :

  • Il devrait y avoir un périphérique listé par ligne, bien que vous puissiez avoir des lignes qui sont entièrement des commentaires ou des espaces blancs.
  • Tout texte suivant un signe dièse '#' et jusqu'à la fin de la ligne est considéré comme un commentaire et ignoré.
  • Les lignes peuvent être continuées en utilisant une barre oblique inverse '\' comme dernier élément non blanc ou non commenté sur une ligne.
  • Note : une ligne dont le premier caractère est un signe dièse '#' est traitée comme une ligne blanche, pas comme une ligne inexistante, et mettra fin à une ligne de continuation.

Voici un exemple de fichier de configuration. Il est uniquement à titre illustratif ; ne le copiez pas sur votre système sans lire jusqu'à la fin de la section DIRECTIVES ci-dessous !

################################################
# Ceci est un fichier de configuration exemple pour smartd
# /etc/smartd.conf
#
# Sur le second disque, lance un auto-test long chaque
# dimanche entre 3h et 4h du matin.
#
/dev/sda -a -m admin@example.com,root@localhost
/dev/sdb -a -I 194 -I 5 -i 12 -s L/../../7/03
#
# Envoie un email de test à admin au démarrage.
#
/dev/sdc -m admin@example.com -M test
#
# Un disque ATA peut apparaître comme un périphérique SCSI pour le
# système d'exploitation. Si une couche de traduction SCSI vers ATA (SAT)
# est présente entre le système d'exploitation et le périphérique, cela peut
# être indiqué avec l'option '-d sat'.
/dev/sda -a -d sat
#
# Disques connectés à un contrôleur MegaRAID
# Lance des auto-tests courts quotidiennement entre 1h-2h, 2h-3h, et
# 3h-4h du matin.
# Linux :
/dev/sda -d megaraid,0 -a -s S/../.././01
/dev/sda -d megaraid,1 -a -s S/../.././02
/dev/sda -d megaraid,2 -a -s S/../.././03
/dev/bus/0 -d megaraid,2 -a -s S/../.././03
#
# Trois disques connectés à un contrôleur AacRaid
# Lance des auto-tests courts quotidiennement entre 1h-2h, 2h-3h, et
# 3h-4h du matin.
/dev/sda -d aacraid,0,0,66 -a -s S/../.././01
/dev/sda -d aacraid,0,0,67 -a -s S/../.././02
/dev/sda -d aacraid,0,0,68 -a -s S/../.././03
#
# Deux disques SATA (pas SAS) sur un contrôleur 3ware 9750.
# Lance des auto-tests longs les dimanches entre minuit et
# 1h du matin et 2h-3h du matin.
# sous Linux
/dev/twl0 -d 3ware,0 -a -s L/../../7/00
/dev/twl0 -d 3ware,1 -a -s L/../../7/02
#
# Deux disques connectés au premier contrôleur HP SmartArray
# qui utilise le pilote Linux cciss. Lance des auto-tests longs
# les dimanches soirs et des auto-tests courts tous les soirs et envoie
# les erreurs à root.
/dev/sda -d cciss,0 -a -s (L/../../7/02|S/../.././02) -m root
/dev/sda -d cciss,1 -a -s (L/../../7/03|S/../.././03) -m root
#
# Trois disques SATA sur un contrôleur HighPoint RocketRAID.
# Lance des auto-tests courts quotidiennement entre 1h-2h, 2h-3h, et
# 3h-4h du matin.
# sous Linux
/dev/sde -d hpt,1/1 -a -s S/../.././01
/dev/sde -d hpt,1/2 -a -s S/../.././02
/dev/sde -d hpt,1/3 -a -s S/../.././03
#
# Deux disques SATA connectés à un HighPoint RocketRAID
# via un périphérique pmport. Lance des auto-tests longs les dimanches
# entre minuit et 1h du matin et 2h-3h du matin.
# sous Linux
/dev/sde -d hpt,1/4/1 -a -s L/../../7/00
/dev/sde -d hpt,1/4/2 -a -s L/../../7/02
#
# Trois disques SATA connectés à un contrôleur RAID Areca.
# Lance des auto-tests longs les dimanches
# entre minuit et 3h du matin.
# sous Linux
/dev/sg2 -d areca,1 -a -s L/../../7/00
/dev/sg2 -d areca,2 -a -s L/../../7/01
/dev/sg2 -d areca,3 -a -s L/../../7/02
#
# La ligne suivante active la surveillance du
# journal d'erreurs ATA et du journal d'erreurs d'auto-test.
# Elle suit également les changements dans les attributs de pré-défaillance
# et d'utilisation, à l'exception des attributs
# 9, 194 et 231, et affiche des lignes continuées :
#
/dev/sdd -l error \
     -l selftest \
     -t \         # Attributs non suivis :
     -I 194 \    # température
     -I 231 \    # également température
     -I 9         # heures de mise sous tension
#
################################################

DEVICESCAN

Si une entrée non commentée dans le fichier de configuration est la chaîne de caractères DEVICESCAN en majuscules, alors smartd ignorera toutes les lignes restantes dans le fichier de configuration et analysera les périphériques. Si DEVICESCAN n'est suivi d'aucune directive, alors '-a' s'appliquera à tous les périphériques.

DEVICESCAN peut éventuellement être suivi de directives qui s'appliqueront à tous les périphériques trouvés lors de l'analyse. Par exemple :

  DEVICESCAN -m root@example.com

analysera tous les périphériques, puis les surveillera. Il enverra un e-mail d'avertissement par périphérique pour tout problème détecté.

  DEVICESCAN -H -m root@example.com

fera la même chose, mais ne surveillera que l'état de santé SMART des périphériques, plutôt que le '-a' par défaut.

Plusieurs options '-d TYPE' peuvent être spécifiées avec DEVICESCAN pour combiner les résultats d'analyse de plusieurs TYPE.

Les entrées de configuration pour des périphériques spécifiques peuvent précéder l'entrée DEVICESCAN. Par exemple :

  DEFAULT -m root@example.com
  /dev/sda -s S/../.././02
  /dev/sdc -d ignore
  DEVICESCAN -s L/../.././02

analysera tous les périphériques sauf /dev/sda et /dev/sdc, les surveillera et lancera un test long entre 2h et 3h du matin chaque matin. Le périphérique /dev/sda sera également surveillé, mais seul un test court sera lancé. Le périphérique /dev/sdc sera ignoré. Des e-mails d'avertissement seront envoyés pour tous les périphériques surveillés.

Un périphérique est ignoré par DEVICESCAN si une ligne de configuration avec le même nom de périphérique existe. Les liens symboliques sont résolus avant cette vérification. Un nom de périphérique est également ignoré si un autre périphérique avec les mêmes informations d'identification (fabricant, modèle, version du firmware, numéro de série, WWN) existe déjà.

[NVMe : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.5] Si un périphérique ne prend en charge qu'un seul espace de noms et qu'une ligne de configuration adressant son ID d'espace de noms existe déjà, un résultat DEVICESCAN qui n'adresse pas d'espace de noms est également ignoré (et inversement).

PARAMETRES PAR DEFAUT

Si une entrée dans le fichier de configuration commence par DEFAULT au lieu d'un nom de périphérique, alors toutes les directives de cette entrée sont définies par défaut pour les entrées de périphérique suivantes.

Cette configuration :

  DEFAULT -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sda
  /dev/sdb
  /dev/sdc
  DEFAULT -H -m admin@example.com
  /dev/sdd
  /dev/sde -d removable

a le même effet que :

  /dev/sda -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdb -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdc -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdd -H -m admin@example.com
  /dev/sde -d removable -H -m admin@example.com

DIRECTIVES DU FICHIER DE CONFIGURATION

Les directives suivantes peuvent apparaître après le nom de périphérique, ou DEVICESCAN ou DEFAULT sur n'importe quelle ligne du fichier de configuration /etc/smartd.conf. Notez qu'il ne s'agit **PAS d'options de ligne de commande pour** smartd. Les directives ci-dessous peuvent apparaître dans n'importe quel ordre, après le nom du périphérique.

Si aucune directive n'apparaît, le périphérique sera surveillé comme si la directive '-a' avait été donnée.

-d TYPE
Spécifie le type de périphérique. Les arguments valides pour cette directive sont :

auto - Tente de deviner le type de périphérique à partir du nom du périphérique ou des informations de type de contrôleur fournies par le système d'exploitation ou à partir d'une entrée d'identifiant USB correspondante dans la base de données des disques. C'est la valeur par défaut.

ata - Le type de périphérique est ATA. Cela empêche smartd d'émettre des commandes SCSI vers un périphérique ATA.

scsi - Le type de périphérique est SCSI. Cela empêche smartd d'émettre des commandes ATA vers un périphérique SCSI.

nvme[,NSID] - Le type de périphérique est NVM Express (NVMe). Le paramètre optionnel NSID spécifie l'identifiant d'espace de noms (en hexadécimal) transmis au pilote. Utilisez 0xffffffff pour l'identifiant d'espace de noms de diffusion. La valeur par défaut pour NSID est l'identifiant d'espace de noms adressé par le nom du périphérique.

sat[,auto][,N] - Le type de périphérique est SCSI to ATA Translation (SAT). Ceci est pour les disques ATA qui ont une couche de traduction SCSI vers ATA (SATL) entre le disque et le système d'exploitation. SAT définit deux commandes SCSI de passage ATA, l'une de 12 octets et l'autre de 16 octets. La valeur par défaut est la variante de 16 octets qui peut être remplacée par '-d sat,12' ou '-d sat,16'.

Si '-d sat,auto' est spécifié, le type de périphérique SAT (pour les disques ATA/SATA) n'est utilisé que si les données d'INQUIRY SCSI rapportent un SATL (VENDOR: "ATA "). Sinon, le type de périphérique SCSI (pour les disques SCSI/SAS) est utilisé.

usbasm1352r,PORT - [NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.4] ce type de périphérique est pour un ou deux disques SATA qui sont derrière un pont USB vers SATA (RAID) ASMedia ASM1352R. Le paramètre PORT (0 ou 1) sélectionne le disque à surveiller.
Note : Ce pont USB prend également en charge '-d sat'. Cela surveille soit le premier disque, soit le second disque si aucun disque n'est connecté au premier port.

usbcypress - Ce type de périphérique est pour les disques ATA qui sont derrière un pont USB vers PATA Cypress. Ceci utilisera la commande propriétaire de passage SCSI ATACB. Le code d'opération SCSI par défaut est 0x24, mais bien qu'il puisse être remplacé par '-d usbcypress,0xN', où N est le code d'opération SCSI, vous risquez d'endommager le périphérique ou les systèmes de fichiers qui y résident.

usbjmicron[,p][,x][,PORT] - Ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers PATA/SATA JMicron. Les commandes ATA sur 48 bits (requises par exemple pour '-l xerror', voir ci-dessous) ne fonctionnent pas avec tous ces ponts et sont donc désactivées par défaut. Ces commandes peuvent être activées avec '-d usbjmicron,x'. Si deux disques sont connectés à un pont avec deux ports, un message d'erreur est imprimé si aucun PORT (0 ou 1) n'est spécifié.
Le paramètre PORT n'est pas nécessaire si le périphérique utilise un multiplicateur de port pour connecter plusieurs disques à un port. Les disques apparaissent alors sous des noms de glace distincts.
ATTENTION : Spécifier ',x' pour un périphérique qui ne le prend pas en charge entraîne des erreurs d'E/S et peut déconnecter le disque. Il en va de même si le PORT spécifié n'existe pas ou n'est pas connecté à un disque.

Les ponts USB Prolific PL2507/3507 avec un ancien firmware prennent en charge une commande de passage similaire à JMicron et fonctionnent avec '-d usbjmicron,0'. Les firmwares Prolific plus récents nécessitent une commande modifiée qui peut être sélectionnée avec '-d usbjmicron,p'. Notez que cela ne prend pas encore en charge la commande d'état SMART.

usbprolific - Ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers SATA Prolific PL2571/2771/2773/2775.

usbsunplus - Ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers SATA SunplusIT.

sntasmedia[/sat] - Ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe ASMedia.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.5] Si le suffixe '/sat' est spécifié et que la commande NVMe Identify Controller échoue, le type de périphérique est changé en '-d sat'. Ceci est utile pour les adaptateurs M.2 USB qui prennent en charge les périphériques NVMe et SATA.

sntjmicron[,NSID][/sat] - Ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe JMicron. Le paramètre optionnel NSID spécifie l'identifiant d'espace de noms (en hexadécimal) transmis au pilote. L'identifiant d'espace de noms par défaut est l'identifiant d'espace de noms de diffusion (0xffffffff). Voir également '-d sntasmedia' pour le suffixe '/sat'.

sntrealtek[/sat] - Ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe Realtek. Voir également '-d sntasmedia' pour le suffixe '/sat'.

marvell - [Linux uniquement] (obsolète et susceptible d'être supprimé).

megaraid,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS connectés à un contrôleur MegaRAID. L'entier positif N (dans la plage de 0 à 127 inclus) désigne quel disque du contrôleur est surveillé. Cette interface fonctionnera également pour les contrôleurs Dell PERC. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme megaraid_disk_XXX avec XXX dans la plage de 000 à 127 inclus. Veuillez consulter la page man smartctl(8) pour plus de détails.

aacraid,H,L,ID - [Linux, Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur AacRaid. Les entiers positifs H, L, ID (Numéro d'hôte, Lun, ID) désignent quel disque du contrôleur est surveillé. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme aacraid_disk_HH_LL_ID. Veuillez consulter la page man smartctl(8) pour plus de détails.

3ware,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques ATA connectés à un contrôleur RAID 3ware. L'entier positif N (dans la plage de 0 à 127 inclus) désigne quel disque du contrôleur est surveillé. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme 3ware_disk_XXX avec XXX dans la plage de 000 à 127 inclus.

Notez que bien que vous puissiez utiliser **n'importe lequel** des périphériques logiques SCSI 3ware /dev/tw* pour adresser **n'importe lequel** des disques physiques (ports 3ware), les messages d'erreur et les journaux auront plus de sens si vous listez toujours le périphérique logique SCSI 3ware correspondant aux disques physiques particuliers. Veuillez consulter la page man smartctl(8) pour plus de détails.

areca,N - [FreeBSD, Linux, Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SATA connectés à un contrôleur RAID SATA Areca. L'entier positif N (dans la plage de 1 à 24 inclus) désigne quel disque du contrôleur est surveillé. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme areca_disk_XX avec XX dans la plage de 01 à 24 inclus. Veuillez consulter la page man smartctl(8) pour plus de détails.

areca,N/E - [FreeBSD, Linux, Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SATA ou SAS connectés à un contrôleur RAID SAS Areca. L'entier N (plage 1 à 128) désigne le canal (logement) et E (plage 1 à 8) désigne le boîtier. Important : Ceci nécessite la version 1.51 ou ultérieure du firmware du contrôleur SAS Areca.

cciss,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur RAID cciss. L'entier positif N (dans la plage de 0 à 127 inclus) désigne quel disque du contrôleur est surveillé. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme cciss_disk_XX avec XX dans la plage de 00 à 127 inclus. Veuillez consulter la page man smartctl(8) pour plus de détails.

hpt,L/M/N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques ATA connectés à un contrôleur HighPoint RocketRAID. L'entier L est l'identifiant du contrôleur, l'entier M est le numéro de canal, et l'entier N est le numéro de port PM s'il est disponible. Les valeurs autorisées pour L sont de 1 à 4 inclus, M de 1 à 128 inclus et N de 1 à 4 si le port PM est disponible. Et aussi ces valeurs sont limitées par le modèle du contrôleur HighPoint RocketRAID. Dans les fichiers journal et les messages électroniques, ce disque sera identifié comme hpt_X/X/X et X/X/X est identique à L/M/N, notez que si N n'est pas indiqué, N est défini sur la valeur par défaut 1. Veuillez consulter la page man smartctl(8) pour plus de détails.

sssraid,E,S - [Linux uniquement : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.4] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur SSSRAID. L'entier positif E (dans la plage de 0 à 8) désigne le boîtier et S (plage 0 à 128) désigne le logement. Veuillez consulter la page man smartctl(8) pour plus de détails.

intelliprop,N[+TYPE] - (obsolète et susceptible d'être supprimé).

jmb39x[-q[2]],N[,sLBA][,force][+TYPE] - le périphérique se compose de plusieurs disques SATA connectés à un multiplicateur de port RAID JMicron JMB39x. Le suffixe '-q' sélectionne une variante de commande légèrement différente utilisée par les appareils NAS QNAP TR-004. L'entier N est le numéro de port de 0 à 4.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.5] Le suffixe '-q2' sélectionne une autre variante de commande utilisée par les appareils NAS QNAP TR-002. Veuillez consulter la page man smartctl(8) pour plus de détails.

jms56x,N[,sLBA][,force][+TYPE] - le périphérique se compose de plusieurs disques SATA connectés à un pont RAID USB vers SATA JMicron JMS56x. Voir 'jmb39x...' ci-dessus pour les arguments valides.

ignore - le périphérique spécifié par cette entrée de configuration doit être ignoré. Cela permet d'ignorer des périphériques spécifiques qui sont détectés par une ligne de configuration DEVICESCAN suivante. Il peut également être utilisé pour désactiver temporairement des entrées de configuration multi-lignes plus longues. Cette directive peut être utilisée conjointement avec les autres directives '-d'.

removable - le périphérique ou son support est amovible. Ceci indique à smartd qu'il doit continuer (au lieu de s'arrêter, ce qui est le comportement par défaut) si le périphérique ne semble pas être présent lorsque smartd est démarré. Cette directive également s

uppresses e-mails d'avertissement et messages de journal répétés si le périphérique est retiré après le démarrage. Cette directive peut être utilisée en conjonction avec les autres directives '-d'.
AVERTISSEMENT : Retirer un périphérique et en connecter un autre sur la même interface n'est pas pris en charge et peut entraîner des avertissements erronés jusqu'à ce que smartd soit redémarré.

-n POWERMODE[,N][,q]
[ATA uniquement] Cette directive 'nocheck' est utilisée pour empêcher un disque d'être lancé lorsqu'il est interrogé périodiquement par smartd.

Les disques ATA ont cinq états d'alimentation différents. Par ordre de consommation d'énergie croissante, ce sont : 'OFF', 'SLEEP', 'STANDBY', 'IDLE' et 'ACTIVE'. Généralement, en mode OFF, SLEEP et STANDBY, les plateaux du disque ne tournent pas. Mais généralement, en réponse aux commandes SMART émises par smartd, les plateaux du disque sont lancés. Donc, si cette option n'est pas utilisée, un disque qui est en mode basse consommation peut être lancé et passer à un mode de consommation plus élevée lorsqu'il est interrogé périodiquement par smartd.

Notez que si le disque est en mode SLEEP au démarrage de smartd, il ne répondra pas aux commandes de smartd, et le disque ne sera donc pas enregistré comme un périphérique à surveiller par smartd. Si un disque est dans tout autre mode basse consommation, les commandes émises par smartd pour enregistrer le disque le feront probablement tourner.

La directive '-n' (nocheck) spécifie si les vérifications périodiques de smartd doivent toujours être effectuées lorsque le périphérique est en mode basse consommation. Elle peut être utilisée pour empêcher un disque d'être lancé par l'interrogation périodique de smartd. Les valeurs autorisées de POWERMODE sont :

never - smartd interrogera (vérifiera) le périphérique quel que soit son mode d'alimentation. Cela peut amener un disque arrêté à être lancé lorsque smartd le vérifie. C'est le comportement par défaut si la directive '-n' n'est pas fournie.

sleep - vérifie le périphérique sauf s'il est en mode SLEEP.

standby - vérifie le périphérique sauf s'il est en mode SLEEP ou STANDBY. Dans ces modes, la plupart des disques ne tournent pas, donc si vous voulez empêcher un disque d'ordinateur portable de démarrer à chaque interrogation de smartd, c'est probablement ce que vous voulez.

idle - vérifie le périphérique sauf s'il est en mode SLEEP, STANDBY ou IDLE. En état IDLE, la plupart des disques tournent encore, donc ce n'est probablement pas ce que vous voulez.

Le nombre maximum de vérifications ignorées (consécutives) peut être spécifié en ajoutant un nombre positif ',N' à POWERMODE (comme '-n standby,15'). Après N vérifications ignorées consécutivement, powermode est ignoré et la vérification est effectuée de toute façon.

Lorsqu'un test périodique est ignoré, smartd écrit normalement un message de journal informel. Le message peut être supprimé en ajoutant l'option ',q' à POWERMODE (comme '-n standby,q'). Cela empêche un disque d'ordinateur portable de démarrer en raison de ce message.

Les deux ',N' et ',q' peuvent être spécifiés ensemble.

-T TYPE
Spécifie la tolérance de smartd aux échecs des commandes SMART. Les arguments valides pour cette directive sont :

Rapporte les augmentations du nombre d'erreurs dans l'un des trois journaux SMART. Les arguments valides pour cette directive sont :

error - [ATA] rapporte si le nombre d'erreurs ATA signalées dans le journal des erreurs SMART de résumé a augmenté depuis la dernière vérification.

xerror - [ATA] rapporte si le nombre d'erreurs ATA signalées dans le journal des erreurs SMART complet étendu a augmenté depuis la dernière vérification.

-s REGEXP
Exécute des auto-tests ou des tests immédiats hors ligne, à des heures programmées. Un auto-test ou un test immédiat hors ligne sera exécuté à la fin de l'interrogation périodique du périphérique, si les 12 caractères de la chaîne T/MM/DD/d/HH correspondent à l'expression régulière étendue REGEXP. Ici :
T
est le type de test. Les valeurs que smartd essaiera de faire correspondre (tour à tour) sont : 'L' pour un auto-test Long, 'S' pour un auto-test Short, 'C' pour un auto-test de Conveyance (ATA seulement), et 'O' pour un test immédiat hors ligne (ATA seulement). Dès qu'une correspondance est trouvée, le test sera démarré et aucune correspondance supplémentaire ne sera recherchée pour ce périphérique et ce cycle d'interrogation.

[NVMe : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.5] Pour les périphériques NVMe prenant en charge l'auto-test, utilisez 'L' pour démarrer un auto-test NVMe "étendu" et 'S' pour un auto-test NVMe Short. Si le nom du périphérique s'adresse à un espace de noms individuel, le test sera démarré en utilisant cet identifiant d'espace de noms, sinon en utilisant l'identifiant d'espace de noms diffusé.

[ATA seulement] Pour exécuter des auto-tests sélectifs programmés, utilisez 'n' pour le prochain niveau, 'r' pour répéter le dernier niveau, ou 'c' pour continuer avec le niveau suivant ou répéter le dernier niveau en fonction de l'état du dernier test. La plage LBA est basée sur le premier niveau du dernier test. Voir les options smartctl -t select,[next|redo|cont] pour plus d'informations.

Certains disques (par exemple, WD) ne conservent pas le journal des auto-tests sélectifs après les cycles d'alimentation. Si la persistance d'état ('-s' option) est activée, le dernier niveau de test est conservé par smartd et utilisé si (et seulement si) le journal des auto-tests sélectifs est vide.

MM
est le mois de l'année, exprimé avec deux chiffres décimaux. La plage va de 01 (janvier) à 12 (décembre) inclus. N'utilisez pas un seul chiffre décimal ou la correspondance échouera toujours !
DD
est le jour du mois, exprimé avec deux chiffres décimaux. La plage va de 01 à 31 inclus. N'utilisez pas un seul chiffre décimal ou la correspondance échouera toujours !
d
est le jour de la semaine, exprimé avec un chiffre décimal. La plage va de 1 (lundi) à 7 (dimanche) inclus.
HH
est l'heure de la journée, écrite avec deux chiffres décimaux, et donnée en heures après minuit. La plage est de 00 (minuit à juste avant 1h du matin) à 23 (23h à juste avant minuit) inclus. N'utilisez pas un seul chiffre décimal ou la correspondance échouera toujours !
Si l'expression régulière contient des sous-chaînes de la forme :NNN ou :NNN-LLL, où NNN et LLL sont trois chiffres décimaux, les tests décalés sont activés. Alors un test sera également exécuté si les 16 (ou 20) caractères de la chaîne T/MM/DD/d/HH:NNN (ou T/MM/DD/d/HH:NNN-LLL) correspondent à l'expression régulière. Cette vérification est effectuée pour un maximum de sept :NNN ou :NNN-LLL trouvés dans l'expression régulière. L'heure utilisée pour la vérification est ajustée dans le passé de manière à ce que les tests du premier disque ne soient pas retardés, les tests du deuxième disque soient retardés de NNN heures, les tests du troisième disque soient retardés de 2*NNN heures, et ainsi de suite.
Si LLL est également spécifié, les retards sont limités à LLL heures en calculant chaque retard individuel comme suit :
'((INDEX_DISQUE * NNN) mod (LLL + 1))'.

Quelques exemples suivent. En les lisant, gardez à l'esprit qu'en expressions régulières étendues, un point '.' correspond à n'importe quel caractère unique, et une expression entre parenthèses comme '(A|B|C)' représente l'une des trois possibilités A, B ou C.

Pour programmer un auto-test court entre 2h et 3h du matin chaque jour, utilisez :
-s S/../.././02
Pour programmer un auto-test long entre 4h et 5h du matin chaque dimanche matin, utilisez :
-s L/../../7/04
Pour activer les tests décalés avec des retards par pas de trois heures, utilisez :
-s L/../../7/04:003
Pour activer les tests décalés avec des retards de 0, 3, 6, 9, 1, 4, 7, 10, 2, 5, 8, 0, ... heures, utilisez :
-s L/../../7/04:003-010
Pour activer les tests décalés avec des retards de 0, 1, 2, ..., 9, 10, 0, ... heures, utilisez :
-s L/../../7/04:001-010
Pour programmer un auto-test long entre 22h et 23h le premier et le quinzième jour de chaque mois, utilisez :
-s L/../(01|15)/./22
Pour programmer un test immédiat hors ligne après chaque minuit, 6h, midi et 18h, plus un auto-test court quotidiennement entre 1h et 2h du matin et un auto-test long chaque samedi entre 3h et 4h du matin, utilisez :
-s (O/../.././(00|06|12|18)|S/../.././01|L/../../6/03)
Pour activer des auto-tests longs décalés avec des retards par pas de trois heures, utilisez :
-s (O/../.././(00|06|12|18)|S/../.././01|L/../../6/03:003)
Si les auto-tests longs de gros disques prennent plus de temps que la durée de fonctionnement du système, un test complet du disque peut être effectué par plusieurs auto-tests sélectifs. Pour configurer un test complet d'un disque de 1 To en 20 jours (une plage de 50 Go par jour), exécutez cette commande une fois :

  smartctl -t select,0-99999999 /dev/sda
Pour exécuter les prochains niveaux de test le lundi-vendredi entre 12h et 13h, exécutez smartd avec cette directive :
-s n/../../[1-5]/12

Les tests programmés sont exécutés immédiatement après l'interrogation régulière des périphériques, si la date, l'heure locale actuelles et le type de test correspondent à REGEXP. Par défaut, l'interrogation régulière des périphériques se produit toutes les trente minutes après le démarrage de smartd. Soyez prudent si vous utilisez l'option '-i' pour que cet intervalle d'interrogation soit supérieur à soixante minutes : les heures d'interrogation peuvent ne pas coïncider avec les heures de test que vous avez spécifiées avec REGEXP. Dans ce cas, le test sera exécuté après la prochaine interrogation du périphérique.

Avant d'exécuter un test hors ligne ou un auto-test, smartd vérifie qu'un auto-test n'est pas déjà en cours. Si un auto-test est déjà en cours, ce test en cours ne sera pas interrompu pour démarrer un autre test.

smartd n'essaiera pas d'exécuter quelque type de test que ce soit si un autre test a déjà été démarré ou exécuté dans la même heure.

Pour éviter les problèmes de performance lors du démarrage du système, smartd n'essaiera pas d'exécuter de tests programmés après la toute première interrogation du périphérique (sauf si '-q onecheck' est spécifié).

Chaque fois qu'un test est exécuté, smartd enregistrera une entrée dans SYSLOG. Vous pouvez utiliser celles-ci ou l'option de ligne de commande '-q showtests' pour vérifier que vous avez correctement construit REGEXP. L'ordre de correspondance (L avant S avant C avant O) garantit que si plusieurs types de tests sont programmés pour la même heure, le type de test le plus long a la priorité. C'est généralement le comportement souhaité.

Si les tests programmés sont utilisés conjointement avec la persistance d'état ('-s' option), smartd essaiera également de faire correspondre les heures depuis le dernier arrêt (ou au maximum 90 jours). Si un test aurait dû être démarré pendant l'indisponibilité, le plus long (voir ci-dessus) de ces tests est exécuté après la deuxième interrogation du périphérique.

Si la directive '-n' est utilisée et qu'un test aurait dû être démarré pendant la mise en veille du disque, le plus long de ces tests est exécuté lorsque le disque est de nouveau actif.

Utilisateurs Unix : veuillez noter que les règles pour les expressions régulières étendues [regex(7)] ne sont pas les mêmes que les règles pour la mise en correspondance des noms de fichiers par le shell [glob(7)]. smartd émettra des messages d'avertissement informatifs inoffensifs s'il détecte des caractères dans REGEXP qui semblent indiquer que vous avez commis cette erreur.

-m ADD
Envoie un e-mail d'avertissement à l'adresse e-mail ADD si les directives '-H', '-l error', '-l xerror', '-l selftest', '-f', '-C', '-U' ou '-W' détectent une défaillance ou une nouvelle erreur, ou si une commande SMART du disque échoue. Cette directive ne fonctionne qu'en conjonction avec ces autres directives (ou avec la directive par défaut '-a').

Pour éviter que votre boîte de réception ne soit remplie de messages d'avertissement, par défaut, un seul avertissement et (en fonction de l'option '-s') des rappels quotidiens seront envoyés pour chaque type d'alerte activé. Voir la directive '-M' ci-dessous pour plus de détails.

Pour envoyer des e-mails à plusieurs utilisateurs, veuillez utiliser la forme "séparée par des virgules" suivante pour l'adresse : user1@add1,user2@add2,...,userN@addN (sans espaces).

Pour tester l'envoi correct des e-mails, utilisez la directive '-M test' décrite ci-dessous pour envoyer un message d'e-mail de test au démarrage de smartd.

Par défaut, les e-mails sont envoyés en utilisant la commande système mail(1). Afin que smartd trouve cette commande (normalement /usr/bin/mail), l'exécutable doit être dans le chemin du shell ou de l'environnement à partir duquel smartd a été démarré. Si vous souhaitez spécifier un chemin explicite vers l'exécutable de messagerie (par exemple /usr/local/bin/mail) ou un script personnalisé à exécuter, veuillez utiliser la directive '-M exec' ci-dessous.

Notez également qu'il existe un argument spécial <nomailer> qui peut être donné à la directive '-m' en conjonction avec la directive '-M exec'. Veuillez voir ci-dessous pour une explication de son effet.

Si le programme de messagerie ou le shell qui l'exécute produit une sortie STDERR/STDOUT, un extrait de cette sortie sera copié dans SYSLOG. Le reste de la sortie est ignoré. Si des problèmes surviennent dans l'envoi d'e-mails, cela devrait vous aider à les comprendre et à les résoudre. Si vous rencontrez des problèmes de messagerie, nous vous recommandons d'exécuter smartd en mode débogage avec l'option '-d', en utilisant la directive '-M test' décrite ci-dessous.

Si un mot de la liste séparée par des virgules a la forme '@plugin', un script personnalisé /usr/share/smartmontools/smartd_warning.d/plugin est exécuté et le mot est supprimé de la liste avant d'envoyer l'e-mail. La chaîne 'plugin' peut être n'importe quel nom valide sauf 'ALL'. Si '@ALL' est spécifié, tous les scripts dans /usr/share/smartmontools/smartd_warning.d/* sont exécutés à la place. Ceci est géré par le script /usr/share/smartmontools/smartd_warning.sh (voir aussi '-M exec' ci-dessous). Les scripts de plugins sans permission d'exécution sont silencieusement ignorés. Si un script de plugin est manquant ou échoue avec un statut de sortie différent de zéro, le script d'avertissement se termine immédiatement sans envoyer de courrier.

-M TYPE
Ces directives modifient le comportement des avertissements par courrier de smartd activés avec la directive de courrier '-m' décrite ci-dessus. Ces directives '-M' ne fonctionnent qu'en conjonction avec la directive '-m' et ne peuvent pas être utilisées sans elle.

Plusieurs directives -M peuvent être données. Si plus d'une des trois directives -M suivantes sont données (exemple : -M once -M daily) alors la dernière (dans l'exemple, -M daily) est utilisée.

Les arguments valides pour la directive -M sont (l'un des trois suivants) :

once - envoyer un seul courrier d'avertissement pour chaque type de problème de disque détecté. C'est la valeur par défaut sauf si la persistance d'état (option '-s') est activée.

always - [NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.4] envoyer des courriers de rappel d'avertissement supplémentaires, à chaque vérification, pour chaque type de problème de disque détecté.

daily - envoyer des courriers de rappel d'avertissement supplémentaires, une fois par jour, pour chaque type de problème de disque détecté. C'est la valeur par défaut si la persistance d'état ('-s' option) est activée.

diminishing - envoyer des courriers de rappel d'avertissement supplémentaires, après un intervalle d'un jour, puis de deux jours, puis de quatre jours, et ainsi de suite pour chaque type de problème de disque détecté. Chaque intervalle est deux fois plus long que l'intervalle précédent.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTD 7.4] La durée de l'intervalle restera de 32 jours après 5 courriers de rappel d'avertissement.

Si un problème de disque n'est plus détecté, le compteur de courrier interne est réinitialisé. Si le problème réapparaît, un nouveau courrier d'avertissement est envoyé immédiatement.

En outre, on peut ajouter zéro ou plusieurs des directives suivantes :

test - envoyer un seul courrier de test immédiatement au démarrage de smartd. Cela permet de vérifier que le courrier est correctement délivré. Notez que si cette directive est utilisée, smartd enverra également les avertissements normaux par courrier activés avec la directive '-m', en plus du seul courrier de test !

exec PATH - exécuter l'exécutable PATH à la place de la commande de courrier par défaut, lorsque smartd doit envoyer un courrier. PATH doit pointer vers un fichier binaire exécutable ou un script.

En réglant PATH pour pointer vers un script personnalisé, vous pouvez faire exécuter à smartd des astuces utiles lorsqu'un problème de disque est détecté (émettre un bip sur la console, arrêter la machine, diffuser des avertissements à tous les utilisateurs connectés, etc.) Mais s'il vous plaît, soyez prudent. smartd **bloquera** jusqu'à ce que l'exécutable PATH retourne, donc si votre exécutable se bloque, alors smartd se bloquera également. Des exemples de scripts sont inclus dans /usr/share/doc/smartmontools/examplescripts/.

Le statut de sortie de l'exécutable est enregistré par smartd dans SYSLOG. L'exécutable n'est pas censé écrire dans STDOUT ou STDERR. S'il le fait, cela est interprété comme une indication que quelque chose ne va pas avec votre exécutable, et un fragment de cette sortie est consigné dans SYSLOG pour vous aider à comprendre le problème. Normalement, si vous souhaitez laisser une trace, l'exécutable devrait envoyer un courrier ou écrire dans un fichier ou un périphérique.

Avant d'exécuter l'exécutable, smartd définit un certain nombre de variables d'environnement. Ces variables d'environnement peuvent être utilisées pour contrôler le comportement de l'exécutable. Les variables d'environnement exportées par smartd sont :

SMARTD_MAILER
est réglé sur l'argument de -M exec, si présent, sinon sur 'mail' (exemples : /usr/local/bin/mail, mail).
SMARTD_DEVICE
est réglé sur le chemin du périphérique (exemple : /dev/sda).
SMARTD_DEVICETYPE
est réglé sur le type de périphérique spécifié par la directive '-d' ou 'auto' si aucun.
SMARTD_DEVICESTRING
est réglé sur la description du périphérique. Il commence par SMARTD_DEVICE et peut être suivi d'une identification optionnelle du contrôleur (exemple : /dev/sda [SAT]). La chaîne peut contenir un espace et n'est PAS mise entre guillemets.
SMARTD_DEVICEINFO
est réglé sur les informations d'identification du périphérique. Il comprend la plupart des informations imprimées par smartctl -i mais utilise un format concis sur une seule ligne. Ces informations de périphérique sont également consignées au démarrage de smartd. La chaîne contient des espaces et n'est PAS mise entre guillemets.
SMARTD_FAILTYPE
indique la raison de l'e-mail d'avertissement ou de message. Les valeurs possibles qu'il prend et leurs significations sont :
EmailTest : il s'agit d'un message de test par courrier électronique.
Health : l'état de santé SMART indique une défaillance imminente.
Usage : un attribut d'utilisation a échoué.
SelfTest : le nombre d'échecs d'auto-test a augmenté.
ErrorCount : le nombre d'erreurs dans le journal d'erreurs ATA a augmenté.
CurrentPendingSector : un ou plusieurs secteurs du disque n'ont pas pu être lus et sont marqués pour être réalloués (remplacés par des secteurs de secours).
OfflineUncorrectableSector : lors d'un test hors ligne, ou d'un auto-test, un ou plusieurs secteurs du disque n'ont pas pu être lus.
Temperature : la température a atteint la limite critique (voir la directive -W).
FailedHealthCheck : la commande d'état de santé SMART a échoué.
FailedReadSmartData : la commande de lecture des données d'attribut SMART a échoué.
FailedReadSmartErrorLog : la commande de lecture du journal d'erreurs SMART a échoué.
FailedReadSmartSelfTestLog : la commande de lecture du journal d'auto-test SMART a échoué.
FailedOpenDevice : la commande open() du périphérique a échoué.
SMARTD_ADDRESS
est déterminé par l'argument d'adresse ADD de la directive '-m'. Si ADD est <nomailer>, alors SMARTD_ADDRESS n'est pas défini. Sinon, il est réglé sur la liste d'adresses électroniques séparées par des virgules donnée par l'argument ADD, avec les virgules remplacées par des espaces (exemple : admin@example.com root). S'il y a plus d'une adresse électronique, alors cette chaîne contiendra des espaces et ne sera PAS mise entre guillemets, donc pour l'utiliser dans un script shell, vous pourriez vouloir l'entourer de guillemets doubles.
SMARTD_ADDRESS_ORIG
est réglé sur la valeur d'origine de SMARTD_ADDRESS avec les chaînes '@plugin' toujours présentes. S'il n'y a pas de telles chaînes dans la directive '-m', cette variable n'est PAS définie.
SMARTD_MESSAGE
est réglé sur la chaîne de message d'avertissement d'une phrase de smartd. Cette chaîne de message contient des espaces et n'est PAS mise entre guillemets. Donc pour utiliser $SMARTD_MESSAGE dans un script shell, vous devriez probablement l'entourer de guillemets doubles.
SMARTD_FULLMESSAGE
est réglé sur le contenu de la chaîne de message d'avertissement complet de smartd. Cette chaîne de message contient des espaces et des caractères de retour et n'est PAS mise entre guillemets. Donc pour utiliser $SMARTD_FULLMESSAGE dans un script shell, vous devriez probablement l'entourer de guillemets doubles.
SMARTD_TFIRST
est une chaîne de texte donnant l'heure et la date auxquelles le premier problème de ce type a été signalé. Cette chaîne de texte contient des espaces et pas de sauts de ligne, et n'est PAS mise entre guillemets. Par exemple :
dim. 9 fév. 14:58:19 2003 CST
SMARTD_TFIRSTEPOCH
est un entier, qui est l'époque Unix (nombre de secondes depuis le 1er janvier 1970) pour SMARTD_TFIRST.
SMARTD_PREVCNT
est un entier spécifiant le nombre de messages précédents envoyés. Il est réglé sur '0' pour le premier message.
SMARTD_NEXTDAYS
est un entier spécifiant le nombre de jours avant l'envoi du prochain message. Il est réglé sur vide pour '-M once', réglé sur '0' pour '-M always' et réglé sur '1' pour '-M daily'.
Si la directive '-m ADD' est donnée avec un argument d'adresse normal, alors l'exécutable pointé par PATH sera exécuté dans un shell avec STDIN recevant le corps du message électronique, et avec les mêmes arguments de ligne de commande : 
  -s "$SMARTD_SUBJECT" $SMARTD_ADDRESS
qui seraient normalement fournis à 'mail'. Les exemples incluent :
-m user@home -M exec /usr/bin/mail
-m admin@work -M exec /usr/local/bin/mailto
-m root -M exec /Example_1/shell/script/below

Si la directive '-m ADD' est donnée avec l'argument d'adresse spécial <nomailer>, alors l'exécutable pointé par PATH est exécuté dans un shell sans STDIN et sans arguments de ligne de commande, par exemple :

  -m <nomailer> -M exec /Example_2/shell/script/below

Si l'exécutable produit une sortie STDERR/STDOUT, alors smartd suppose que quelque chose ne va pas, et un extrait de cette sortie sera copié dans SYSLOG. Le reste de la sortie est ensuite discardé.

Ceci est utile, par exemple, si l'un des attributs du périphérique est la température du disque (généralement l'attribut 194 ou 231). [ATA uniquement] Lors du suivi, signaler la valeur brute de l'attribut ID en plus de sa valeur normalisée (normalement signalée). ID doit être un entier décimal compris entre 1 et 255. Une utilisation courante de cette directive est de suivre la température du périphérique (souvent ID=194 ou 231).

Si l'indicateur optionnel '!' est ajouté, un changement de la valeur normalisée est considéré comme critique. Le rapport sera enregistré sous LOG_CRIT et un e-mail d'avertissement sera envoyé si '-m' est spécifié.

-R ID[!]
[ATA uniquement] Lors du suivi, signaler chaque fois que la valeur brute de l'attribut ID change. (Normalement, smartd ne suit/signale que les changements des valeurs d'attributs normalisées.) ID doit être un entier décimal compris entre 1 et 255. Cette directive modifie le comportement des directives de suivi '-p', '-u' et '-t' et n'a aucun effet sans l'une d'entre elles. Cette directive peut être donnée plusieurs fois.

Une utilisation courante de cette directive est de suivre la température du périphérique (souvent ID=194 ou 231). Elle est également utile pour comprendre comment différents types de comportements système affectent les valeurs de certains attributs.

Si l'indicateur optionnel '!' est ajouté, un changement de la valeur brute est considéré comme critique. Le rapport sera enregistré sous LOG_CRIT et un e-mail d'avertissement sera envoyé si '-m' est spécifié. Un exemple est '-R 5!' pour avertir lors de la réallocation de nouveaux secteurs.

-C ID[+]
[ATA uniquement] Signaler si le nombre actuel de secteurs en attente est différent de zéro. Ici, ID est le numéro d'identifiant de l'attribut dont la valeur brute est le nombre de secteurs en attente actuels. La plage autorisée pour ID est de 0 à 255 inclusivement. Pour désactiver ce rapport, utilisez ID = 0. Si l'option -C ID n'est pas donnée, elle prend par défaut la valeur -C 197 (car l'attribut 197 est généralement utilisé pour surveiller les secteurs en attente). Si le nom de cet attribut est modifié par une directive '-v 197,FORMAT,NOM', la valeur par défaut est changée en -C 0.

Si '+' est spécifié, un rapport n'est imprimé que si le nombre de secteurs a augmenté entre deux cycles de vérification. Certains disques ne réinitialisent pas cet attribut lorsque qu'un secteur défectueux est réalloué. Voir également '-v 197,croissant' ci-dessous.

Le compteur d'e-mails d'avertissement est réinitialisé si le nombre de secteurs en attente est tombé à 0. Cela se produit généralement lorsque tous les secteurs en attente ont été réalloués ou ont pu être relus.

Un secteur en attente est un secteur de disque (contenant 512 octets de vos données) que le périphérique aimerait marquer comme "mauvais" et réallouer. Généralement, c'est parce que votre ordinateur a essayé de lire ce secteur, et la lecture a échoué parce que les données qu'il contient sont corrompues et ont des codes de contrôle d'erreur (ECC) incohérents. Il est important de le savoir, car cela signifie qu'il y a des données illisibles sur le disque. Le problème de savoir à quel fichier ces données appartiennent est spécifique au système d'exploitation et au système de fichiers. Vous pouvez généralement forcer la réallocation du secteur en y écrivant (traduction : faire en sorte que le périphérique remplace un secteur défectueux par un bon secteur de rechange), mais au prix de la perte des 512 octets de données stockées là.

-U ID[+]
[ATA uniquement] Signaler si le nombre de secteurs non corrigeables hors ligne est différent de zéro. Ici, ID est le numéro d'identifiant de l'attribut dont la valeur brute est le nombre de secteurs non corrigeables hors ligne. La plage autorisée pour ID est de 0 à 255 inclusivement. Pour désactiver ce rapport, utilisez ID = 0. Si l'option -U ID n'est pas donnée, elle prend par défaut la valeur -U 198 (car l'attribut 198 est généralement utilisé pour surveiller les secteurs non corrigeables hors ligne). Si le nom de cet attribut est modifié par une directive '-v 198,FORMAT,NOM' (sauf '-v 198,FORMAT,Offline_Scan_UNC_SectCt'), la valeur par défaut est changée en -U 0.

Si '+' est spécifié, un rapport n'est imprimé que si le nombre de secteurs a augmenté depuis le dernier cycle de vérification. Certains disques ne réinitialisent pas cet attribut lorsque qu'un secteur défectueux est réalloué. Voir également '-v 198,croissant' ci-dessous.

Le compteur d'e-mails d'avertissement est réinitialisé si le nombre de secteurs non corrigeables hors ligne est tombé à 0. Cela se produit généralement lorsque tous les secteurs non corrigeables hors ligne ont été réalloués ou ont pu être relus.

Un secteur non corrigeable hors ligne est un secteur de disque qui n'a pas pu être lu lors d'un scan hors ligne ou d'un auto-test. Il est important de le savoir, car si vous avez des données stockées dans ce secteur du disque et que vous devez les lire, la lecture échouera. Veuillez consulter l'option '-C' précédente pour plus de détails.

-W DIFF[,INFO[,CRIT]]
Signaler si la température actuelle a changé d'au moins DIFF degrés depuis le dernier rapport, ou si une nouvelle température minimale ou maximale est détectée. Signaler ou avertir si la température est supérieure ou égale à l'un des seuils INFO ou CRIT en degrés Celsius. EXEMPLES DE SCRIPTS SHELL POUR '-M exec'
Voici deux exemples de scripts shell qui peuvent être utilisés avec la directive '-M exec PATH' décrite précédemment. Les chemins vers ces scripts et exécutables similaires constituent l'argument PATH de la directive '-M exec PATH'.

Exemple 1 : Ce script est destiné à être utilisé avec '-m ADRESSE -M exec PATH'. Il ajoute la sortie de smartctl -a à la sortie du message d'avertissement par e-mail de smartd et l'envoie à ADRESSE.

#! /bin/sh
# Sauvegarde du message e-mail (STDIN) dans un fichier :
cat > /root/msg
# Ajout de la sortie de smartctl -a au message :
/usr/bin/smartctl -a -d $SMART_DEVICETYPE \
  $SMARTD_DEVICE >> /root/msg
# Envoi maintenant du message par e-mail à l'utilisateur à l'adresse ADD :
/usr/bin/mail -s "$SMARTD_SUBJECT" $SMARTD_ADDRESS \
  < /root/msg

Exemple 2 : Ce script est destiné à être utilisé avec '-m <nomailer> -M exec PATH'. Il avertit tous les utilisateurs d'un problème de disque, attend 30 secondes, puis éteint la machine.

#! /bin/sh
# Avertir tous les utilisateurs d'un problème
wall <<EOF
Problème détecté avec le disque : $SMARTD_DEVICESTRING
Message d'avertissement de smartd : $SMARTD_MESSAGE
Arrêt de la machine dans 30 secondes...
EOF
# Attendre une demi-minute
sleep 30
# Éteindre la machine
/sbin/shutdown -hf now

Certains exemples de scripts sont distribués avec le paquet smartmontools , dans /usr/share/doc/smartmontools/examplescripts/.

Veuillez noter que ces scripts s'exécutent généralement en tant que root, donc tout fichier qu'ils lisent/écrivent ne doit pas être accessible en écriture par les utilisateurs ordinaires ou résider dans des répertoires comme /tmp qui sont accessibles en écriture par les utilisateurs ordinaires et peuvent exposer votre système à des attaques par lien symbolique.

Comme décrit précédemment, si les scripts écrivent sur STDOUT ou STDERR, cela est interprété comme une indication d'une erreur interne dans le script, et un extrait de STDOUT/STDERR est enregistré dans SYSLOG. Le reste est vidé.
