SMARTCTL(8) Outils de surveillance SMART SMARTCTL(8)

NOM

smartctl - Utilitaire de contrôle et de surveillance des disques SMART

SYNTAXE

smartctl [options] appareil

DESCRIPTION

[Cette page de manuel est générée pour la version Linux de smartmontools. Elle ne contient pas d'informations spécifiques aux autres plateformes.]

smartctl contrôle le système Self-Monitoring, Analysis and Reporting Technology (SMART) intégré à la plupart des disques durs et SSD ATA/SATA et SCSI/SAS. Le but de SMART est de surveiller la fiabilité du disque dur et de prédire les défaillances, ainsi que d'effectuer différents types d'autotests du disque. smartctl prend également en charge certaines fonctionnalités non liées à SMART. Cette version de smartctl est compatible avec les normes ACS-3, ACS-2, ATA8-ACS, ATA/ATAPI-7 et antérieures (voir REFERENCES ci-dessous).

smartctl prend également en charge les lecteurs de bandes SCSI et les changeurs (voir LECTEURS DE BANDE ci-dessous).

L'utilisateur doit spécifier l'appareil à contrôler ou interroger comme dernier argument de smartctl. L'ensemble de commandes utilisé par l'appareil est souvent dérivé du chemin de l'appareil mais peut nécessiter de l'aide avec l'option '-d' (pour plus d'informations, voir la section sur "les ensembles de commandes ATA, SCSI et SAT" ci-dessous). Les chemins des appareils sont les suivants :

LINUX:
Utilisez les formats "/dev/sd[a-z]" pour les appareils ATA/SATA et SCSI/SAS. Pour les lecteurs de bandes et changeurs SCSI, utilisez les appareils "/dev/nst*" et "/dev/sg*". Pour les disques derrière les contrôleurs 3ware, vous pourriez avoir besoin de "/dev/sd[a-z]" ou "/dev/twe[0-9]", "/dev/twa[0-9]" ou "/dev/twl[0-9]" : voir les détails ci-dessous. Pour les disques derrière les contrôleurs HighPoint RocketRAID, vous pourriez avoir besoin de "/dev/sd[a-z]". Pour les disques derrière les contrôleurs Areca SATA RAID, vous avez besoin de "/dev/sg[2-9]" (notez que smartmontools interagit avec les contrôleurs Areca via un périphérique générique SCSI différent du périphérique SCSI utilisé pour lire et écrire des données) ! Pour les contrôleurs RAID HP Smart Array, il existe trois pilotes actuellement pris en charge : cciss, hpsa et hpahcisr. Pour les disques accédés via le pilote cciss, les nœuds de périphérique sont de la forme "/dev/cciss/c[0-9]d0". Pour les disques accédés via les pilotes hpahcisr et hpsa, les nœuds de périphérique dont vous avez besoin sont "/dev/sg[0-9]*". ("lsscsi -g" est utile pour déterminer quel nœud de périphérique générique scsi correspond à quel appareil.) Utilisez les nœuds correspondant aux contrôleurs RAID, pas aux disques logiques. Voir l'option -d ci-dessous également. Utilisez les formats "/dev/nvme[0-9]" (espace de noms de diffusion) ou "/dev/nvme[0-9]n[1-9]" (espace de noms spécifique 1-9) pour les appareils NVMe.

Si '-' est spécifié comme chemin de l'appareil, smartctl lit et interprète sa propre sortie de débogage à partir de l'entrée standard. Voir '-r ataioctl' ci-dessous pour les détails.

smartctl devine le type de l'appareil si possible. Si nécessaire, l'option '-d' peut être utilisée pour remplacer cette supposition.

Notez que la sortie affichée par smartctl présente la plupart des valeurs numériques en base 10 (décimal), mais certaines valeurs sont affichées en base 16 (hexadécimal). Pour les distinguer, les valeurs en base 16 sont toujours affichées avec un préfixe "0x", par exemple : "0xff". Cette page de manuel suit la même convention.

OPTIONS

Les options sont regroupées ci-dessous en plusieurs catégories. smartctl exécutera les commandes correspondantes dans l'ordre : INFORMATIONS, ACTIVATION/DÉSACTIVATION, AFFICHAGE DES DONNÉES, EXÉCUTION/ANNULATION DES TESTS.

OPTIONS D'AFFICHAGE DES INFORMATIONS :
-h, --help, --usage
Imprime un message d'utilisation sur STDOUT et quitte.
-V, --version, --copyright, --license
Imprime la version, les informations de copyright, de licence, la page d'accueil et la révision SVN de votre copie de smartctl sur STDOUT, puis quitte.
-i, --info
Imprime le numéro de modèle de l'appareil, le numéro de série, la version du firmware et les informations sur la version/révision de la norme ATA. Indique si l'appareil prend en charge SMART et, si c'est le cas, si la prise en charge SMART est actuellement activée ou désactivée. Si l'appareil prend en charge le mode Logical Block Address (mode LBA), affiche la capacité actuelle du disque utilisateur en octets. (Si le disque a une zone protégée par l'utilisateur réservée, ou est "tronqué", cela peut être inférieur à la capacité maximale potentielle du disque.) Indique si le disque est dans la base de données smartmontools (voir les options '-v' ci-dessous). Si c'est le cas, la famille de modèles du disque peut également être imprimée. Si '-n' (voir ci-dessous) est spécifié, le mode d'alimentation du disque est imprimé.

[NVMe] Pour les appareils NVMe, les informations sont obtenues à partir de la structure de données Identify Controller et Identify Namespace.

--identify[=[w][nvb]]
[ATA uniquement] Imprime un tableau annoté des données IDENTIFY DEVICE. Par défaut, seuls les mots valides (mots différents de 0x0000 ou 0xffff) et les bits et champs de bits non nuls sont imprimés. Ceci peut être modifié par l'argument optionnel composé d'un ou deux caractères de l'ensemble 'wnvb'. Le caractère 'w' active l'impression de tous les 256 mots. Le caractère 'n' supprime l'impression des bits, 'v' active l'impression de tous les bits des mots valides, 'b' active l'impression de tous les bits. Par exemple, '--identify=n' (mots valides, pas de bits) produit la sortie la plus courte et '--identify=wb' (tous les mots, tous les bits) produit la sortie la plus longue.
-a, --all
Imprime toutes les informations SMART sur l'appareil.

Pour ATA, cela équivaut à
'-H -i -c -A -l error -l selftest -l selective'.
Cette option n'est plus recommandée pour les disques ATA car elle n'active pas les options SMART qui nécessitent la prise en charge des commandes ATA 48 bits (voir '-x' ci-dessous).

Pour SCSI, cela équivaut à
'-H -i -A -l error -l selftest'.

Pour NVMe, cela équivaut à
'-H -i -c -A -l error -l selftest'.

-x, --xall
Imprime toutes les informations SMART et non-SMART sur l'appareil.

Pour ATA, cela équivaut à
'-H -i -g all -c -A -f brief -l xerror,error -l xselftest,selftest -l selective -l directory -l scttemp -l scterc -l devstat -l defects -l sataphy'.
Si '-a' est également spécifié, ajoutez '-l error -l selftest'.
[NOUVEAU SMARTCTL EXPÉRIMENTAL 7.5 FIX] '-g wcreorder' n'est plus inclus car il n'est pas possible de vérifier si cette fonctionnalité est prise en charge par le disque.

Pour les disques SCSI, cela équivaut à
'-H -i -g all -A -l error -l selftest -l background -l sasphy -l defects -l envrep -l genstats -l ssd -l zdevstat'
et pour les lecteurs de bandes et changeurs SCSI, ajoutez '-l tapedevstat'.

Pour NVMe, cela équivaut à
'-H -i -c -A -l error -l selftest'.

--scan
Analyse les appareils et imprime le nom de chaque appareil, le type d'appareil et les informations de protocole ([ATA] ou [SCSI]). Peut être utilisé en conjonction avec '-d TYPE' pour restreindre l'analyse à un TYPE spécifique. Voir aussi les informations sur l'analyse d'appareils spécifique à la plateforme et la directive DEVICESCAN dans la page de manuel smartd(8).
--scan-open
Identique à --scan, mais essaie également d'ouvrir chaque appareil avant d'imprimer les informations de l'appareil. L'ouverture de l'appareil peut changer le type de l'appareil en raison de la détection automatique (voir aussi '-d test').

Cette option peut être utilisée pour créer un fichier smartd.conf brouillon. Toutes les options après '--' sont ajoutées à chaque ligne de sortie. Par exemple :

smartctl --scan-open -- -a -W 4,45,50 -m admin@work > smartd.conf

Plusieurs options '-d TYPE' peuvent être spécifiées avec '--scan[-open]' pour combiner les résultats d'analyse de plus d'un TYPE.

-g NOM, --get=NOM
Obtient les paramètres non-SMART de l'appareil. Voir '-s, --set' ci-dessous pour plus d'informations.
OPTIONS DE COMPORTEMENT EN COURS D'EXÉCUTION :
-j, --json[=cgiosuvy]
Active le mode de sortie JSON ou YAML.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Les sorties peuvent être modifiées ou améliorées par l'argument facultatif qui se compose d'un ou plusieurs caractères de l'ensemble 'cgiosuvy' :
'c' : Sorties au format compact sans espaces supplémentaires ni sauts de ligne. Par défaut, la sortie est formatée joliment. Si utilisé avec le format YAML, l' indentation des tableaux est réduite.
'g' : Sorties de la structure JSON sous forme d'affectations uniques pour permettre l'utilisation de grep. Chaque affectation reflète le chemin absolu d'une valeur. La syntaxe est compatible avec gron :
'json.CLEF1[INDEX2].CLEF3 = VALEUR ;'.
'o' : Inclut la sortie texte brute complète de smartctl sous forme de tableau JSON 'smartctl.output[]'.
's' : Sorties des éléments d'objet JSON triés par clé. Par défaut, les éléments d'objet sont ordonnés tels qu'ils sont générés en interne.
'v' : Active la sortie verbose des entiers potentiellement non sûrs. Si spécifié, les valeurs qui peuvent dépasser l'entier sûr JSON (53 bits) sont toujours affichées sous forme de nombre (avec une clé 'KEY') et d'une chaîne ('KEY_s'), quelle que soit la valeur réelle. Les valeurs qui peuvent dépasser la plage 64 bits sont également affichées sous forme de tableau d'octets little-endian ('KEY_le'). Par défaut, les éléments supplémentaires ne sont affichés que si la valeur dépasse réellement la plage.
'y' : Sorties au format YAML.

Les deux arguments suivants sont principalement destinés au développement :
'i' : Inclut les lignes de la sortie texte qui affichent des informations déjà implémentées pour la sortie JSON. Les lignes apparaissent sous forme de chaînes avec la clé 'smartctl_NNNN_i'.
'u' : Inclut les lignes de la sortie texte qui affichent des informations toujours non implémentées pour la sortie JSON. Les lignes apparaissent sous forme de chaînes avec la clé 'smartctl_NNNN_u'.

-q TYPE, --quietmode=TYPE
Spécifie que smartctl doit s'exécuter dans l'un des modes silencieux décrits ici. Les arguments valides pour cette option sont :

errorsonly - imprimer uniquement : Pour l'option '-l error', si non nul, le nombre d'erreurs enregistrées dans le journal d'erreurs SMART et le temps de mise sous tension pendant leur occurrence ; Pour l'option '-l selftest', les erreurs enregistrées dans le journal d'auto-test du périphérique ; Pour l'option '-H', l'état SMART de "disque défaillant" ou les attributs du périphérique (pré-défaillance ou utilisation) qui ont échoué maintenant ou dans le passé ; Pour l'option '-A', les attributs du périphérique (pré-défaillance ou utilisation) qui ont échoué maintenant ou dans le passé.

silent - ne pas afficher de sortie. La seule façon de connaître ce qui a été trouvé est d'utiliser le code de sortie de smartctl (voir CODE DE SORTIE ci-dessous).

noserial - Ne pas imprimer le numéro de série du périphérique. Ceci supprime également l'ID de périphérique LU WWN (ATA) et les adresses SAS (SCSI). Les champs associés sont également invalidés dans les sorties de débogage ATA et NVMe.
Note : Ce n'est pas le cas dans la sortie de débogage SCSI.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.4] Le Namespace IEEE EUI-64 (NVMe) est également supprimé.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.5] Le numéro de série et le World Wide Name du journal FARM (voir '-l farm' ci-dessous) sont également supprimés, à l'exception de la sortie de débogage.

-d TYPE, --device=TYPE
Spécifie le type du périphérique. Les arguments valides pour cette option sont :

auto - tenter de deviner le type de périphérique à partir du nom du périphérique ou des informations de type de contrôleur fournies par le système d'exploitation ou à partir d'une entrée d'ID USB correspondante dans la base de données des disques. C'est le défaut.

test - imprime le TYPE deviné, puis ouvre le périphérique et imprime le nom du TYPE (éventuellement modifié) puis quitte sans effectuer d'autres commandes.

ata - le type de périphérique est ATA. Ceci empêche smartctl d'émettre des commandes SCSI vers un périphérique ATA.

scsi - le type de périphérique est SCSI. Ceci empêche smartctl d'émettre des commandes ATA vers un périphérique SCSI.

nvme[,NSID] - le type de périphérique est NVM Express (NVMe). Le paramètre facultatif NSID spécifie l'ID de namespace (en hexadécimal) passé au pilote. Utilisez 0xffffffff pour l'ID de namespace broadcast. La valeur par défaut pour NSID est l'ID de namespace adressé par le nom du périphérique.

sat[,auto][,N] - le type de périphérique est SCSI vers ATA Translation (SAT). Ceci est pour les disques ATA qui ont une couche de traduction SCSI vers ATA (SATL) entre le disque et le système d'exploitation. SAT définit deux commandes SCSI de passage ATA, l'une de 12 octets et l'autre de 16 octets. La valeur par défaut est la variante de 16 octets qui peut être remplacée par '-d sat,12' ou '-d sat,16'.

Si '-d sat,auto' est spécifié, le type de périphérique SAT (pour les disques ATA/SATA ) n'est utilisé que si les données d'interrogation SCSI rapportent une SATL (VENDOR: "ATA "). Sinon, le type de périphérique SCSI (pour les disques SCSI/SAS) est utilisé.

usbasm1352r,PORT - [NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.4 ] ce type de périphérique est pour un ou deux disques SATA qui sont derrière un pont USB vers SATA (RAID) ASMedia ASM1352R. Le paramètre PORT (0 ou 1) sélectionne le disque à surveiller.
Note : Ce pont USB prend également en charge '-d sat'. Ceci surveille soit le premier disque, soit le second disque s'il n'y a pas de disque connecté au premier port.

usbcypress - ce type de périphérique est pour les disques ATA qui sont derrière un pont USB vers PATA Cypress. Ceci utilisera la commande de passage scsi propriétaire ATACB. Le code d'opération SCSI par défaut est 0x24, mais bien qu'il puisse être remplacé par '-d usbcypress,0xN', où N est le code d'opération scsi, vous risquez de causer des dommages au périphérique ou aux systèmes de fichiers qu'il contient.

usbjmicron[,p][,x][,PORT] - ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers PATA/SATA JMicron. Les commandes ATA sur 48 bits (requises par exemple pour '-l xerror', voir ci-dessous) ne fonctionnent pas avec tous ces ponts et sont donc désactivées par défaut. Ces commandes peuvent être activées par '-d usbjmicron,x'. Si deux disques sont connectés à un pont à deux ports, un message d'erreur est affiché si aucun PORT (0 ou 1) n'est spécifié.
Le paramètre PORT n'est pas nécessaire si le périphérique utilise un multiplicateur de ports pour connecter plusieurs disques à un port. Les disques apparaissent alors sous des noms /dev/ice séparés.
ATTENTION : Spécifier ',x' pour un périphérique qui ne le prend pas en charge entraîne des erreurs d'E/S et peut déconnecter le disque. Il en va de même si le PORT spécifié n'existe pas ou n'est pas connecté à un disque.

Les ponts USB Prolific PL2507/3507 avec un firmware plus ancien prennent en charge une commande de passage similaire à JMicron et fonctionnent avec '-d usbjmicron,0'. Les firmwares Prolific plus récents nécessitent une commande modifiée qui peut être sélectionnée par '-d usbjmicron,p'. Notez que cela ne prend pas encore en charge la commande d'état SMART.

usbprolific - ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers SATA Prolific PL2571/2771/2773/2775.

usbsunplus - ce type de périphérique est pour les disques SATA qui sont derrière un pont USB vers SATA SunplusIT.

sntasmedia[/sat] - ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe ASMedia.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.5] Si le suffixe '/sat' est spécifié et que la commande NVMe Identify Controller échoue, le type de périphérique est changé en '-d sat'. Ceci est utile pour les adaptateurs M.2 USB qui prennent en charge les périphériques NVMe et SATA.

sntjmicron[,NSID][/sat] - ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe JMicron. Le paramètre facultatif NSID spécifie l'ID de namespace (en hexadécimal) passé au pilote. La valeur par défaut de l'ID de namespace est l'ID de namespace broadcast (0xffffffff). Voir également '-d sntasmedia' pour le suffixe '/sat'.

sntrealtek[/sat] - ce type de périphérique est pour les disques NVMe qui sont derrière un pont USB vers NVMe Realtek. Voir également '-d sntasmedia' pour le suffixe '/sat'.

marvell - [Linux uniquement] (obsolète et susceptible d'être supprimé).

megaraid,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS connectés à un contrôleur MegaRAID . L'entier non négatif N (dans la plage de 0 à 127 inclus) désigne le disque surveillé sur le contrôleur. Cette interface fonctionnera également pour les contrôleurs Dell PERC. Utilisez la syntaxe telle que :
smartctl -a -d megaraid,2 /dev/sda
smartctl -a -d megaraid,0 /dev/sdb
smartctl -a -d megaraid,0 /dev/bus/0
Il est possible de définir le nom du périphérique RAID comme /dev/bus/N, où N est un numéro de bus SCSI.

L'entrée suivante dans /proc/devices doit exister :
Pour les contrôleurs PERC2/3/4 : megadevN
Pour les contrôleurs PERC5/6 : megaraid_sas_ioctlN

aacraid,H,L,ID - [Linux, Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur AacRaid . Les entiers non négatifs H, L, ID (numéro d'hôte, Lun, ID) désignent le disque surveillé sur le contrôleur. Utilisez la syntaxe telle que :
smartctl -a -d aacraid,0,0,2 /dev/sda
smartctl -a -d aacraid,1,0,4 /dev/sdb

L'option '-d sat,auto+...' est implicitement activée pour détecter les disques SATA. Utilisez '-d scsi+aacraid,H,L,ID' pour la désactiver.

Sous Linux, l'entrée suivante dans /proc/devices doit exister : aac. Des nœuds de périphérique caractères /dev/aacH (H=Numéro d'hôte) sont créés si nécessaire.

3ware,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques ATA connectés à un contrôleur RAID 3ware . L'entier non négatif N (dans la plage de 0 à 127 inclus) désigne le disque surveillé sur le contrôleur. Utilisez la syntaxe telle que :
smartctl -a -d 3ware,2 /dev/sda [Linux uniquement]
smartctl -a -d 3ware,0 /dev/twe0
smartctl -a -d 3ware,1 /dev/twa0
smartctl -a -d 3ware,1 /dev/twl0 [Linux uniquement]
smartctl -a -d 3ware,1 /dev/tws0 [FreeBSD uniquement]
Les deux premières formes, qui font référence aux périphériques /dev/sda-z (obsolète) et /dev/twe0-15, peuvent être utilisées avec les contrôleurs 3ware séries 6000, 7000 et 8000 qui utilisent le pilote 3x-xxxx. Les périphériques /dev/twa0-15, doivent être utilisés avec les contrôleurs 3ware série 9000, qui utilisent le pilote 3w-9xxx . Les périphériques /dev/twl0-15 [Linux] ou /dev/tws0-15 [FreeBSD] doivent être utilisés avec les contrôleurs 3ware/LSI série 9750 qui utilisent le pilote 3w-sas.

Notez que si les nœuds de périphérique caractères spéciaux /dev/tw[ls]?, /dev/twa? et /dev/twe? n'existent pas, ou existent avec des numéros majeurs ou mineurs incorrects, smartctl les recréera à la volée.

areca,N - [FreeBSD, Linux et Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SATA connectés à un contrôleur RAID SATA Areca. L'entier positif N (dans la plage de 1 à 24 inclus) désigne le disque du contrôleur surveillé. Sous Linux, utilisez la syntaxe suivante :
smartctl -a -d areca,2 /dev/sg2
smartctl -a -d areca,3 /dev/sg3
La première ligne ci-dessus s'adresse au deuxième disque du premier contrôleur RAID Areca. La deuxième ligne s'adresse au troisième disque du deuxième contrôleur RAID Areca. Pour aider à identifier le périphérique correct sous Linux, utilisez la commande :
cat /proc/scsi/sg/device_hdr /proc/scsi/sg/devices
pour afficher les périphériques génériques SCSI (un par ligne, commençant par /dev/sg0). Les périphériques génériques SCSI corrects à adresser pour smartmontools sont ceux dont le champ type est égal à 3. Si le périphérique incorrect est adressé, veuillez lire attentivement les messages d'avertissement/erreur. Ils devraient fournir des indices sur les périphériques à utiliser.

Important : le contrôleur Areca doit avoir la version du micrologiciel 1.46 ou ultérieure. Les versions de micrologiciel inférieures donneront des messages d'erreur SCSI (inoffensifs) et aucune information SMART.

areca,N/E - [FreeBSD, Linux et Windows et Cygwin uniquement] le périphérique se compose d'un ou plusieurs disques SATA ou SAS connectés à un contrôleur RAID SAS Areca. L'entier N (plage 1 à 128) désigne le canal (emplacement) et E (plage 1 à 8) désigne le boîtier. Important : Cela nécessite la version du micrologiciel du contrôleur SAS Areca 1.51 ou ultérieure.

cciss,N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur RAID cciss. L'entier N (plage 0 à 127 inclus) désigne le disque du contrôleur surveillé.

L'option '-d sat,auto+...' est implicitement activée pour détecter les disques SATA. Utilisez '-d scsi+cciss,N' pour la désactiver.

Pour examiner les disques derrière les contrôleurs HP Smart Array, utilisez la syntaxe suivante :
smartctl -a -d cciss,0 /dev/cciss/c0d0 (pilote cciss sous Linux)
smartctl -a -d cciss,0 /dev/sg2 (pilotes hpsa ou hpahcisr sous Linux)

hpt,L/M/N - [FreeBSD et Linux uniquement] le périphérique se compose d'un ou plusieurs disques ATA connectés à un contrôleur HighPoint RocketRAID. L'entier L est l'ID du contrôleur, l'entier M est le numéro de canal, et l'entier N est le numéro de port PMPort s'il est disponible. Les valeurs autorisées de L sont de 1 à 4 inclus, M de 1 à 128 inclus et N de 1 à 4 si le port PMPort est disponible. De plus, ces valeurs sont limitées par le modèle du contrôleur HighPoint RocketRAID. Utilisez la syntaxe suivante :
smartctl -a -d hpt,1/3 /dev/sda (sous Linux)
smartctl -a -d hpt,1/2/3 /dev/sda (sous Linux)
Notez que la forme /dev/sda-z doit être le nœud de périphérique qui représente les disques dérivés des contrôleurs HighPoint RocketRAID sous Linux et sous FreeBSD, c'est le périphérique caractère que le pilote a enregistré (par exemple, /dev/hptrr, /dev/hptmv6).

sssraid,E,S - [Linux uniquement : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE DE SMARTCTL 7.4] le périphérique se compose d'un ou plusieurs disques SCSI/SAS ou SATA connectés à un contrôleur SSSRAID. L'entier non négatif E (dans la plage de 0 à 8) désigne le boîtier et S (plage 0 à 128) désigne l'emplacement. Utilisez la syntaxe suivante :
smartctl -a -d sssraid,0,1 /dev/bsg/sssraid0
Il est possible de définir le nom du périphérique RAID sur /dev/bsg/sssraidN, où N est un numéro de bus SCSI.

intelliprop,N[+TYPE] - (obsolète et susceptible d'être supprimé).

jmb39x[-q[2]],N[,sLBA][,force][+TYPE] - le périphérique se compose de plusieurs disques SATA connectés à un multiplicateur de ports RAID JMicron JMB39x. Le suffixe '-q' sélectionne une variante de commande légèrement différente utilisée par les périphériques NAS QNAP TR-004. L'entier N est le numéro de port de 0 à 4.
[NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE DE SMARTCTL 7.5] Le suffixe '-q2' sélectionne une autre variante de commande utilisée par les périphériques NAS QNAP TR-002.
AVERTISSEMENT : les commandes de passage ATA sont émises via les commandes READ/WRITE vers un LBA du volume RAID. L'utilisation de cette option avec d'autres périphériques peut écraser ce secteur.
Le LBA par défaut est 33. Le LBA peut être sélectionné dans la plage de 1 à 255 inclus.
Si une table de partition GPT est utilisée, le LBA 33 contient les 4 dernières (sur 128) entrées de la table de partition. Ces entrées sont remplies de zéros dans la plupart des cas. Si une table de partition MBR est utilisée, le LBA 33 peut être rempli de zéros ou contenir du code d'un chargeur de démarrage.
Par défaut, l'accès au périphérique est refusé si le secteur sélectionné n'est pas rempli de zéros. Le drapeau 'force' désactive cette vérification.
AVERTISSEMENT : les données du secteur d'origine ne sont pas réécrites si smartctl est interrompu par un signal.

jms56x,N[,sLBA][,force][+TYPE] - le périphérique se compose de plusieurs disques SATA connectés à un pont RAID USB vers SATA JMicron JMS56x. Voir 'jmb39x...' ci-dessus pour les arguments valides.

-T TYPE, --tolerance=TYPE
[ATA uniquement] Spécifie à quel point smartctl doit être tolérant aux échecs des commandes ATA et SMART.

Le comportement de smartctl dépend du fait que la commande soit "optionnelle" ou "obligatoire". Ici, "obligatoire" signifie "requis par la spécification ATA si l'appareil implémente l'ensemble de commandes SMART" et "optionnelle" signifie "non requis par la spécification ATA même si l'appareil implémente l'ensemble de commandes SMART". Les commandes ATA et SMART "obligatoires" sont : (1) ATA IDENTIFY DEVICE, (2) SMART ENABLE/DISABLE ATTRIBUTE AUTOSAVE, (3) SMART ENABLE/DISABLE, et (4) SMART RETURN STATUS.

Les arguments valides pour cette option sont :

normal - sortie en cas d'échec de toute commande SMART obligatoire, et ignore tous les échecs des commandes SMART optionnelles. C'est le comportement par défaut. Notez que sur certains appareils, l'émission de commandes optionnelles non implémentées ne provoque pas d'erreur. Cela peut entraîner des messages smartctl trompeurs tels que "La fonctionnalité X n'est pas implémentée", suivis peu après de "La fonctionnalité X : activée". Dans la plupart de ces cas, contrairement au message final, la fonctionnalité X n'est pas activée.

conservative - sortie en cas d'échec de toute commande SMART optionnelle.

permissive - ignore les échecs des commandes SMART obligatoires. Cette option peut être utilisée plusieurs fois. Chaque utilisation supplémentaire de cette option entraînera l'ignorance d'un échec supplémentaire. Notez que l'utilisation de cette option peut entraîner des messages tels que "La fonctionnalité X n'est pas prise en charge", suivis peu après de "L'activation de la fonctionnalité X a échoué". Dans quelques cas, contrairement au message final, la fonctionnalité X est activée.

verypermissive - équivalent à donner un grand nombre d'options '-T permissive' : ignore les échecs d'un nombre quelconque de commandes SMART obligatoires. Veuillez consulter la note ci-dessus.

-b TYPE, --badsum=TYPE
[ATA uniquement] Spécifie l'action que smartctl doit entreprendre si une erreur de somme de contrôle est détectée dans : (1) la structure d'identification du périphérique, (2) la structure du journal d'auto-test SMART, (3) la structure de valeur des attributs SMART, (4) la structure des seuils des attributs SMART, ou (5) la structure du journal d'erreurs ATA.

Les arguments valides pour cette option sont :

warn - signaler la somme de contrôle incorrecte mais continuer malgré cela. C'est le comportement par défaut.

exit - quitter smartctl.

ignore - continuer silencieusement sans émettre d'avertissement.

-r TYPE, --report=TYPE
Destiné principalement à aider les développeurs de smartmontools à comprendre le comportement de smartmontools sur du matériel non conforme ou mal conforme. Cette option signale les détails des transactions de smartctl avec le périphérique. L'option peut être utilisée plusieurs fois. Lorsqu'elle est utilisée une seule fois, elle affiche un enregistrement des transactions ioctl() avec le périphérique. Lorsqu'elle est utilisée plus d'une fois, le détail de ces transactions ioctl() est rapporté de manière plus détaillée. Les arguments valides pour cette option sont :

ioctl - signaler toutes les transactions ioctl().

ataioctl - signaler uniquement les transactions ioctl() avec des périphériques ATA.

scsiioctl - signaler uniquement les transactions ioctl() avec des périphériques SCSI. L'invocation une fois affiche les commandes SCSI en hexadécimal et le statut correspondant. L'invocation une deuxième fois ajoute une liste hexadécimale des 64 premiers octets de données envoyés à, ou reçus du périphérique.

nvmeioctl - signaler uniquement les transactions ioctl() avec des périphériques NVMe.

Tout argument peut inclure un entier positif pour spécifier le niveau de détail qui doit être signalé. L'argument doit être suivi d'une virgule puis de l'entier sans espaces. Par exemple, ataioctl,2 Le niveau par défaut est 1, donc '-r ataioctl,1' et '-r ataioctl' sont équivalents.

À des fins de test, la sortie de '-r ataioctl,2' peut plus tard être analysée par smartctl lui-même si '-' est utilisé comme chemin de périphérique. Les paramètres d'entrée de la commande ATA, les données du secteur et les valeurs de retour sont reconstruits à partir du rapport de débogage lu depuis l'entrée standard. Ensuite, smartctl simule en interne un périphérique ATA avec le même comportement. Cela ne fonctionne pas encore pour les périphériques SCSI.

-n POWERMODE[,STATUS[,STATUS2]], --nocheck=POWERMODE[,STATUS[,STATUS2]]
[ATA, SCSI] Spécifie si smartctl doit s'arrêter avant d'effectuer des vérifications lorsque le périphérique est en mode basse consommation. Il peut être utilisé pour empêcher un disque d'être mis sous tension par smartctl. Le mode d'alimentation est ignoré par défaut.

Note : Si cette option est utilisée, il peut également être nécessaire de spécifier le type de périphérique avec l'option '-d'. Sinon, le périphérique peut être mis sous tension en raison de commandes émises lors de la détection automatique du type de périphérique.

Par défaut, le code de sortie 2 est renvoyé si le périphérique est dans l'un des modes basse consommation spécifiés. Ce statut est également renvoyé si l'ouverture du périphérique ou l'identification échoue (voir STATUT DE SORTIE ci-dessous). Le paramètre STATUS optionnel permet de remplacer ce comportement par défaut. STATUS est un entier dans la plage de 0 à 255 inclus. Par exemple, utilisez '-n standby,0' pour renvoyer un succès si un périphérique est en mode SLEEP ou STANDBY. Utilisez '-n standby,3' pour renvoyer un code de sortie unique dans ce cas.

Les arguments valides pour cette option sont :

never - vérifier

sur le périphérique, mais imprime le mode d'alimentation si '-i' est spécifié.

sleep[,STATUT[,STATUT2]] - vérifie le périphérique sauf s'il est en mode SLEEP.

standby[,STATUT[,STATUT2]] - vérifie le périphérique sauf s'il est en mode SLEEP ou STANDBY. Dans ces modes, la plupart des disques ne tournent pas, donc si vous voulez empêcher un disque de démarrer, c'est probablement ce que vous voulez.

idle[,STATUT[,STATUT2]] - vérifie le périphérique sauf s'il est en mode SLEEP, STANDBY ou IDLE. Dans l'état IDLE, la plupart des disques tournent encore, donc ce n'est probablement pas ce que vous voulez.

L'option '-n' est ignorée si la vérification du mode d'alimentation n'est pas prise en charge ou renvoie une valeur inconnue.
[ATA uniquement] Si le paramètre optionnel STATUT2 est spécifié, smartctl se termine immédiatement avec STATUT2 dans ce cas. Par exemple, utilisez '-n standby,3,5' pour renvoyer des statuts de sortie uniques dans les cas STANDBY et UNSUPPORTED.

COMMANDES D'ACTIVATION/DÉSACTIVATION DES FONCTIONNALITÉS SMART :
Remarque : si plusieurs options sont utilisées pour activer et désactiver une fonctionnalité, les deux commandes d'activation et de désactivation seront émises. La commande d'activation sera toujours émise avant la commande de désactivation correspondante.
-s VALEUR, --smart=VALEUR
Active ou désactive SMART sur le périphérique. Les arguments valides pour cette option sont on et off.

[ATA] Notez que les commandes ATA SMART ENABLE/DISABLE OPERATIONS ont été déclarées obsolètes dans ATA ACS-4 Revision 10 (nov 2015).

[Lecteur de bande ou changeur SCSI] Il n'est pas nécessaire (ou utile) d'activer SMART pour voir les messages TapeAlert.

-o VALEUR, --offlineauto=VALEUR
[ATA uniquement] Active ou désactive le test automatique hors ligne SMART, qui analyse le lecteur toutes les quatre heures pour détecter les défauts du disque. Cette commande peut être donnée pendant le fonctionnement normal du système. Les arguments valides pour cette option sont on et off.

Notez que la commande de test automatique hors ligne SMART est répertoriée comme "Obsolète" dans toutes les versions des spécifications ATA et ATA/ATAPI. Elle faisait initialement partie de la spécification SFF-8035i Révision 2.0, mais n'a jamais fait partie d'aucune spécification ATA. Cependant, elle est implémentée et utilisée par de nombreux fabricants. Vous pouvez savoir si les tests automatiques hors ligne sont pris en charge en vérifiant si cette commande les active et les désactive, comme indiqué dans la partie "Auto Offline Data Collection" du rapport des capacités SMART (affiché avec '-c').

SMART fournit trois catégories de base de tests. La première catégorie, appelée test "en ligne", n'a aucun effet sur les performances du périphérique. Elle est activée par l'option '-s on'.

La deuxième catégorie de tests est appelée test "hors ligne". Ce type de test peut, en principe, dégrader les performances du périphérique. L'option '-o on' fait que ce test hors ligne est effectué, automatiquement, à intervalles réguliers. Normalement, le disque suspend les tests hors ligne pendant les accès au disque, puis les reprend automatiquement lorsque le disque serait autrement inactif, donc en pratique, cela a peu d'effet. Notez qu'un test hors ligne unique peut également être effectué immédiatement après réception d'une commande utilisateur. Voir l'option '-t offline' ci-dessous, qui effectue un test hors ligne unique immédiatement.

Le choix (fait par les auteurs des spécifications SFF-8035i et ATA) du mot testing pour ces deux premières catégories est malheureux et conduit souvent à la confusion. En fait, ces deux premières catégories de tests en ligne et hors ligne auraient pu être décrites plus précisément comme une collecte de données en ligne et hors ligne.

Les résultats de ces tests hors ligne automatiques ou immédiats (collecte de données) se reflètent dans les valeurs des attributs SMART. Ainsi, si des problèmes ou des erreurs sont détectés, les valeurs de ces attributs descendront sous leurs seuils de défaillance ; certains types d'erreurs peuvent également apparaître dans le journal d'erreurs SMART. Ceux-ci sont visibles avec les options '-A' et '-l error' respectivement.

Certaines valeurs d'attributs SMART sont mises à jour uniquement pendant les activités de collecte de données hors ligne ; les autres sont mises à jour pendant le fonctionnement normal du périphérique ou pendant le fonctionnement normal et les tests hors ligne. Le tableau des valeurs d'attributs produit par l'option '-A' l'indique dans la colonne UPDATED. Les attributs du premier type sont marqués "Offline" et les attributs du second type sont marqués "Always".

La troisième catégorie de tests (et la seule catégorie pour laquelle le mot 'testing' est vraiment approprié) est le test "self" (auto-test). Ce troisième type de test n'est effectué (immédiatement) que lorsqu'une commande pour l'exécuter est émise. Les options '-t' et '-X' peuvent être utilisées pour effectuer et annuler de tels auto-tests ; veuillez consulter ci-dessous pour plus de détails.

Toutes les erreurs détectées dans les auto-tests seront affichées dans le journal d'auto-tests SMART, qui peut être consulté en utilisant l'option '-l selftest'.

Remarque : dans cette page de manuel, le mot "Test" est utilisé en relation avec la deuxième catégorie décrite, par exemple pour le "test" hors ligne. Les mots "Self-test" (auto-test) sont utilisés en relation avec la troisième catégorie.

-S VALEUR, --saveauto=VALEUR
[ATA] Active ou désactive la sauvegarde automatique SMART des attributs spécifiques au vendeur du périphérique. Les arguments valides pour cette option sont on et off. Notez que cette fonctionnalité est préservée après les cycles d'alimentation du disque, vous ne devriez donc avoir besoin de l'émettre qu'une seule fois.

La norme ATA ne spécifie pas de méthode pour vérifier si la sauvegarde automatique SMART est activée. Contrairement à SCSI (ci-dessous), smartctl ne peut pas afficher d'avertissement si la sauvegarde est désactivée.

Notez que les commandes ATA SMART ENABLE/DISABLE AUTOSAVE ont été déclarées obsolètes dans ATA ACS-4 Revision 10 (nov 2015).

[SCSI] Pour les périphériques SCSI, cela bascule la valeur du bit Global Logging Target Save Disabled (GLTSD) dans la Page de Contrôle. Certains fabricants de disques définissent ce bit par défaut. Cela empêche les compteurs d'erreurs, les heures de mise sous tension et d'autres données utiles d'être stockées en mémoire non volatile, donc ces valeurs peuvent être remises à zéro lors du prochain cycle d'alimentation du périphérique. Si le bit GLTSD est défini, 'smartctl -a' émettra un avertissement. Utilisez on pour effacer le bit GLTSD et ainsi permettre la sauvegarde des compteurs dans le stockage non volatile. Pour des applications extrêmes de type streaming vidéo, vous pourriez envisager d'utiliser off pour définir le bit GLTSD.

-g NOM, --get=NOM, -s NOM[,VALEUR], --set=NOM[,VALEUR]
Récupère/définit les paramètres du périphérique non-SMART. Notez que l'option '--set' partage son option courte '-s' avec '--smart'. Les arguments valides sont :

all - Récupère toutes les valeurs. Ceci est équivalent à
'-g aam -g apm -g lookahead -g security -g wcache -g rcache -g dsn'

aam[,N|off] - [ATA uniquement] Récupère/définit la fonctionnalité Automatic Acoustic Management (AAM) (si prise en charge). Une valeur de 128 définit le mode le plus silencieux (le plus lent) et 254 le mode le plus rapide (le plus bruyant), 'off' désactive l'AAM. Les périphériques peuvent prendre en charge des niveaux intermédiaires. Les valeurs inférieures à 128 sont définies comme spécifiques au vendeur (0) ou retirées (1 à 127). Notez que la fonctionnalité AAM a été déclarée obsolète dans ATA ACS-2 Révision 4a (déc. 2010).

apm[,N|off] - [ATA uniquement] Récupère/définit la fonctionnalité Advanced Power Management (APM) sur le périphérique (si prise en charge). Si une valeur entre 1 et 254 est fournie, elle tentera d'activer l'APM et de définir la valeur spécifiée, 'off' désactive l'APM. Notez que le comportement réel dépend du disque, par exemple, certains disques désactivent l'APM si leur valeur est définie au-dessus de 128. Les valeurs inférieures à 128 sont censées permettre l'arrêt du disque, les valeurs 128 et supérieures ajustent uniquement la fréquence de parking des têtes, bien que le comportement réel défini soit également spécifique au vendeur.

lookahead[,on|off] - [ATA uniquement] Récupère/définit la fonctionnalité de pré-lecture (read look-ahead) (si prise en charge). La pré-lecture est généralement activée par défaut.

security - [ATA uniquement] Récupère l'état de la fonctionnalité de sécurité ATA (si prise en charge). Si la sécurité ATA est activée, un mot de passe utilisateur ATA est défini. Le lecteur sera verrouillé lors du prochain redémarrage.

security-freeze - [ATA uniquement] Définit la fonctionnalité de sécurité ATA en mode figé. Cela empêche le lecteur d'accepter des commandes de sécurité jusqu'au prochain redémarrage. Notez que le mode figé peut déjà être défini par le BIOS ou le système d'exploitation.

standby,[N|off] - [ATA] Définit le minuteur de veille (arrêt) et place le lecteur en mode IDLE. Une valeur de 0 ou 'off' désactive le minuteur de veille. Les valeurs de 1 à 240 spécifient des délais de 5 secondes à 20 minutes par incréments de 5 secondes. Les valeurs de 241 à 251 spécifient des délais de 30 minutes à 330 minutes par incréments de 30 minutes. La valeur 252 spécifie 21 minutes. La valeur 253 spécifie un temps spécifique au vendeur entre 8 et 12 heures. La valeur 255 spécifie 21 minutes et 15 secondes. Certains disques peuvent utiliser une interprétation spécifique au vendeur pour les valeurs. Notez qu'il n'y a pas d'option de récupération car les normes ATA ne spécifient pas de méthode pour lire le minuteur de veille. Si '-s standby,now' est également spécifié, le lecteur est immédiatement placé en mode STANDBY sans le placer temporairement en mode IDLE. Notez que les normes ATA ne spécifient pas de commande pour régler le minuteur de veille sans affecter le mode d'alimentation.
[SCSI] Seule l'option de définition avec 'standby,off' ou 'standby,0' est acceptée et placera le disque SCSI dans la condition d'alimentation "ACTIVE".

standby,now - [ATA] Place le lecteur en mode STANDBY. Cela arrête généralement le disque. Le réglage du minuteur de veille n'est pas affecté, sauf si '-s standby,[N|off]' est également spécifié.
[SCSI] Seule l'option de définition est acceptée et placera le disque SCSI dans la condition d'alimentation "STANDBY_Z".

wcache[,on|off] - [ATA] Récupère/définit la fonctionnalité de cache d'écriture volatile (si prise en charge). Le cache d'écriture est généralement activé par défaut.

wcache[,on|off] - [SCSI] Récupère/définit le bit 'Write Cache Enable' (WCE) (si pris en charge). Le cache d'écriture est généralement activé par défaut.

wcache-sct[,ata|on|off[,p]] - [ATA uniquement] Récupère/définit la fonctionnalité de cache d'écriture via SCT Feature Control (si prise en charge). L'état du cache d'écriture dans SCT Feature Control peut être "Controlled by ATA", "Force Enabled", ou "Force Disabled". SCT

Le contrôle des fonctionnalités remplace le paramètre par la commande ATA Set Features (option wcache[,on|off]). Si le contrôle des fonctionnalités SCT définit le cache d'écriture comme « Forcer activé » ou « Forcer désactivé », le paramètre de wcache[,on|off] est ignoré par le lecteur. wcreorder[,on|off[,p]] - [ATA uniquement] Obtient/définit le réordonnancement du cache d'écriture. OPTIONS DE LECTURE ET D'AFFICHAGE DES DONNÉES SMART :
-H, --health
Affiche l'état de santé du périphérique.

Si le périphérique signale un état de santé défaillant, cela signifie soit que le périphérique a déjà échoué, soit qu'il prévoit sa propre défaillance dans les prochaines 24 heures. Si cela se produit, utilisez l'option '-x' pour obtenir plus d'informations et récupérez vos données du disque et mettez-les en lieu sûr dès que possible.

[ATA] L'état de santé est obtenu en vérifiant le résultat (booléen) renvoyé par la commande SMART RETURN STATUS. La valeur de retour de cette commande ATA peut être inconnue en raison de limitations ou de bogues dans une couche (par exemple, contrôleur RAID ou micrologiciel de pont USB) entre le disque et le système d'exploitation. Dans ce cas, smartctl affiche un avertissement et vérifie si la valeur d'un attribut SMART de pré-défaut est inférieure ou égale à son seuil (voir '-A' ci-dessous).

[SCSI] L'état de santé est obtenu en vérifiant le code de détection supplémentaire (ASC) et le qualificateur de code de détection supplémentaire (ASCQ) de la page de journal des exceptions informelles (IE) (si prise en charge) et/ou des données de détection SCSI.

[Lecteur de bande ou changeur SCSI] L'état TapeAlert est obtenu en lisant la page de journal TapeAlert, mais uniquement si cette option est donnée deux fois (voir LECTEURS DE BANDE pour la justification).

[NVMe] L'état NVMe est obtenu en lisant l'octet « Critical Warning » du journal SMART/Health Information.

-c, --capabilities
[ATA] Affiche uniquement les capacités SMART génériques. Celles-ci montrent quelles fonctionnalités SMART sont implémentées et comment le périphérique répondra à certaines des différentes commandes SMART. Par exemple, elles indiquent si le périphérique enregistre des erreurs, s'il prend en charge l'analyse de surface hors ligne, etc. Si le périphérique peut effectuer des auto-tests, cette option affiche également le temps estimé nécessaire pour exécuter ces tests.

[NVMe] Affiche diverses capacités du périphérique NVMe obtenues à partir des structures de données Identify Controller et Identify Namespace.

-A, --attributes
[ATA] Affiche uniquement les attributs SMART spécifiques au fournisseur. Les attributs sont numérotés de 1 à 253 et portent des noms et des numéros d'identification spécifiques. Par exemple, l'attribut 12 est le « nombre de cycles d'alimentation » : combien de fois le disque a été alimenté.

Chaque attribut a une valeur « Raw » (brute), affichée sous l'en-tête « RAW_VALUE », et une valeur « Normalized » (normalisée) affichée sous l'en-tête « VALUE ». [Remarque : smartctl affiche ces valeurs en base 10.] Dans l'exemple donné, la « Raw Value » de l'attribut 12 serait le nombre réel de fois où le disque a été mis sous tension, par exemple 365 si le disque a été allumé une fois par jour pendant exactement un an. Chaque fournisseur utilise son propre algorithme pour convertir cette valeur « Raw » en une valeur « Normalized » comprise entre 1 et 254. Veuillez garder à l'esprit que smartctl ne fait que rapporter les différents types d'attributs, les valeurs et les seuils tels qu'ils sont lus depuis le périphérique. Il n'effectue pas la conversion entre les valeurs « Raw » et « Normalized » : celle-ci est effectuée par le micrologiciel du disque.

La conversion de la valeur brute en une quantité avec des unités physiques n'est pas spécifiée par la norme SMART. Dans la plupart des cas, les valeurs affichées par smartctl sont raisonnables. Par exemple, l'attribut de température a généralement sa valeur brute égale à la température en Celsius. Cependant, dans certains cas, les fournisseurs utilisent des conventions inhabituelles. Par exemple, le disque Hitachi de mon ordinateur portable affiche ses heures de mise sous tension en minutes, pas en heures. Certains disques IBM suivent trois températures plutôt qu'une dans leurs valeurs brutes. Et ainsi de suite.

Chaque attribut a également une valeur de seuil (variant de 0 à 255) qui est affichée sous l'en-tête « THRESH ». Si la valeur normalisée est inférieure ou égale à la valeur du seuil, alors l'attribut est considéré comme défaillant. Si l'attribut est un attribut de pré-défaut, alors la défaillance du disque est imminente.

Chaque attribut a également une valeur « Worst » (la pire), affichée sous l'en-tête « WORST ». C'est la plus petite valeur (la plus proche de la défaillance) que le disque a enregistrée à tout moment de sa durée de vie lorsque SMART était activé. [Notez cependant que le micrologiciel de certains fournisseurs peut en fait augmenter la valeur « Worst » pour certains attributs de « type taux ».]

Le tableau d'attributs affiché par smartctl indique également le « TYPE » de l'attribut. Les attributs sont de l'un des deux types possibles : Pré-défaut ou Vieillesse. Les attributs de pré-défaut sont ceux qui, s'ils sont inférieurs ou égaux à leurs valeurs de seuil, indiquent une défaillance imminente du disque. Les attributs de vieillesse, ou d'utilisation, sont ceux qui indiquent la fin de la vie du produit due à la vieillesse ou à l'usure normale, si la valeur de l'attribut est inférieure ou égale au seuil. Veuillez noter : le fait qu'un attribut soit de type 'Pre-fail' ne signifie pas que votre disque est sur le point de tomber en panne ! Cela n'a de sens que si la valeur normalisée actuelle de l'attribut est inférieure ou égale à la valeur du seuil.

Si la valeur normalisée actuelle de l'attribut est inférieure ou égale à la valeur du seuil, la colonne « WHEN_FAILED » affichera « FAILING_NOW ». Sinon, mais si la pire valeur enregistrée est inférieure ou égale à la valeur du seuil, cette colonne affichera « In_the_past ». Si la colonne « WHEN_FAILED » n'a aucune entrée (indiquée par un tiret : '-') alors cet attribut est OK maintenant (pas défaillant) et n'a jamais échoué dans le passé.

Le tableau dont la colonne est intitulée « UPDATED » indique si les valeurs des attributs SMART sont mises à jour pendant le fonctionnement normal et les tests hors ligne, ou uniquement pendant les tests hors ligne. Les premiers sont étiquetés « Always » et les seconds « Offline ».

Pour résumer : les valeurs brutes des attributs sont celles qui peuvent avoir une interprétation physique réelle, telles que « Température Celsius », « Heures » ou « Cycles de démarrage-arrêt ». Chaque fabricant convertit ces valeurs, en utilisant sa connaissance détaillée des opérations et des modes de défaillance du disque, en valeurs d'attributs normalisées dans la plage de 1 à 254. Les valeurs normalisées actuelles et les pires (les plus basses mesurées) de ces attributs sont stockées sur le disque, ainsi qu'une valeur de seuil que le fabricant a déterminée comme indiquant que le disque va tomber en panne, ou qu'il a dépassé son âge de conception ou sa limite de vieillissement. smartctl ne calcule pas les valeurs, les seuils ou les types des attributs, il se contente de les rapporter à partir des données SMART du périphérique.

Notez qu'à partir d'ATA/ATAPI-4, révision 4, la signification de ces champs d'attributs est devenue entièrement spécifique au fournisseur. Cependant, la plupart des disques ATA/SATA plus récents semblent respecter leur signification, nous avons donc conservé l'option d'afficher les valeurs des attributs.

Les lecteurs à état solide utilisent des significations différentes pour certains des attributs. Dans ce cas, le nom de l'attribut imprimé par smartctl est incorrect, sauf si le lecteur est déjà dans la base de données des lecteurs smartmontools.

Notez que la commande ATA SMART READ DATA a été déclarée obsolète dans ATA ACS-4 Revision 10 (nov. 2015).

Certains attributs spécifiques au fournisseur sont répertoriés s'ils sont reconnus. Les attributs sont affichés dans un format relativement libre (comparé aux attributs de disque ATA).

Affiche divers journaux de périphériques. Les arguments valides pour cette option sont :

error - [ATA] Affiche le journal des erreurs SMART de résumé. Les disques SMART conservent un journal des cinq erreurs non triviales les plus récentes. Pour chacune de ces erreurs, la durée de vie du disque au moment où l'erreur s'est produite est enregistrée, ainsi que l'état du périphérique (veille, veille prolongée, etc.) au moment de l'erreur. Pour certains types d'erreurs courants, les valeurs des registres d'erreur (ER) et d'état (SR) sont décodées et affichées sous forme de texte. Les significations sont les suivantes :

   ABRT : Commande ABoRTée
d AMNF: Address Mark Not Found (Marque d'adresse non trouvée) CCTO: Command Completion Timed Out (Expiration du délai d'achèvement de la commande) EOM: End Of Media (Fin du média) ICRC: Interface Cyclic Redundancy Code (CRC) error (Erreur de code de redondance cyclique de l'interface) IDNF: IDentity Not Found (Identité non trouvée) ILI: (spécifique à l'ensemble de commandes du paquet) MC: Media Changed (Média changé) MCR: Media Change Request (Demande de changement de média) NM: No Media (Pas de média) obs: obsolète TK0NF: TracK 0 Not Found (Piste 0 non trouvée) UNC: UNCorrectable Error in Data (Erreur de données non corrigeable) WP: Media is Write Protected (Le média est protégé en écriture) De plus, jusqu'aux cinq dernières commandes ayant précédé l'erreur sont listées, avec un horodatage mesuré depuis le début du cycle d'alimentation correspondant. Ceci est affiché sous la forme Dd+HH:MM:SS.msec où D représente le nombre de jours, HH les heures, MM les minutes, SS les secondes et msec les millisecondes. [Note : cet horodatage se réinitialise après 2^32 millisecondes, soit 49 jours, 17 heures, 2 minutes et 47,296 secondes.] Les registres clés du disque ATA sont également enregistrés dans le journal. La dernière colonne du journal d'erreurs est une description textuelle de la commande ATA définie par les valeurs du registre de commande (CR) et du registre de fonctionnalité (FR). Les commandes obsolètes dans la spécification la plus récente sont listées comme ceci : READ LONG (w/ retry) [OBS-4], indiquant que la commande est devenue obsolète avec ou dans la spécification ATA-4. De même, la notation [RET-N] est utilisée pour indiquer qu'une commande a été retirée dans la spécification ATA-N. Certaines commandes ne sont définies dans aucune version de la spécification ATA mais sont néanmoins couramment utilisées ; celles-ci sont marquées [NS], signifiant non standard.

La spécification ATA (ATA ACS-2 Révision 7, Section A.7.1) dit : « Les structures de données du journal d'erreurs doivent inclure, sans s'y limiter, les erreurs non corrigeables, les erreurs d'ID non trouvé pour lesquelles le LBA demandé était valide, les erreurs de servo et les erreurs de faute d'écriture. Les structures de données du journal d'erreurs ne doivent pas inclure les erreurs attribuées à la réception de commandes défectueuses. » Les définitions de ces termes sont :
UNC (UNCorrectable - Non corrigeable) : les données ne sont pas corrigeables. Ceci fait référence aux données qui ont été lues du disque, mais pour lesquelles les codes de contrôle et de correction d'erreurs (ECC) sont incohérents. En effet, cela signifie que les données ne peuvent pas être lues.
IDNF (ID Not Found - ID non trouvé) : l'adresse accessible par l'utilisateur n'a pas pu être trouvée. Pour les commandes de type READ LOG, IDNF peut également indiquer qu'un checksum de la structure de journal de données du périphérique était incorrect.

Si la commande qui a causé l'erreur était une commande de lecture (READ) ou d'écriture (WRITE), alors l'adresse logique de bloc (LBA) à laquelle l'erreur s'est produite sera affichée en base 10 et en base 16. Le LBA est une adresse linéaire qui compte les secteurs de 512 octets sur le disque, à partir de zéro. (En raison des limitations du journal d'erreurs SMART, si le LBA est supérieur à 0xfffffff, alors soit aucune entrée de journal d'erreurs ne sera faite, soit l'entrée de journal d'erreurs aura un LBA incorrect. Cela peut se produire pour les disques d'une capacité supérieure à 128 Gio ou 137 Go.) Sur les systèmes Linux, la page Web de smartmontools contient des instructions sur la façon de convertir l'adresse LBA en nom du fichier disque contenant le secteur du disque erroné.

Veuillez noter que certains fabricants ignorent les spécifications ATA et créent des entrées dans le journal d'erreurs si le périphérique reçoit une commande qui n'est pas implémentée ou qui n'est pas valide.

-v ID,FORMAT[:BYTEORDER][,NAME], --vendorattribute=ID,FORMAT...
[ATA uniquement] Définit un format d'affichage de valeur brute spécifique au fournisseur, un ordre d'octets BYTEORDER optionnel et un nom NAME optionnel pour l'ID d'attribut. Cette option peut être utilisée plusieurs fois.

L'ID d'attribut peut être dans la plage de 1 à 255. Si 'N' est spécifié comme ID, les paramètres de tous les attributs sont modifiés.

L'ordre des octets BYTEORDER optionnel se compose de 1 à 8 caractères de l'ensemble '012345rvwz'. Les caractères '0' à '5' sélectionnent l'octet 0 à 5 de la valeur brute de 48 bits, 'r' sélectionne l'octet réservé du bloc de données d'attribut, 'v' sélectionne la valeur normalisée, 'w' sélectionne la valeur la plus basse et 'z' insère un octet zéro. L'ordre des octets BYTEORDER par défaut est '543210' pour tous les formats de 48 bits, 'r543210' pour les formats de 54 bits, et '543210wv' pour les formats de 64 bits. Par exemple, '-v 5,raw48:012345' affiche la valeur brute de l'attribut 5 avec un ordre d'octets big-endian au lieu de little-endian.

OPTIONS DE LANCEMENT/ANNULATION DE TEST HORS LIGNE ET D'AUTO-TEST SMART :
-t TEST, --test=TEST
Exécute TEST immédiatement. L'option '-C' peut être utilisée conjointement avec cette option pour exécuter les auto-tests courts ou longs (et aussi pour les périphériques ATA, sélectifs ou de convoyage) en mode captif (connu sous le nom de "mode avant" pour les périphériques SCSI). Notez qu'un seul type de test peut être exécuté à la fois, donc un seul type de test doit être spécifié par ligne de commande. Notez également que si un ordinateur est arrêté ou subit un cycle de mise sous tension pendant un auto-test, aucun dommage ne devrait en résulter. L'auto-test sera soit annulé, soit repris automatiquement.

Toutes les commandes '-t TEST' peuvent être données pendant le fonctionnement normal du système, sauf si le mode captif (option '-C') est utilisé. Un auto-test en cours d'exécution peut cependant dégrader les performances du disque. Les requêtes d'E/S fréquentes du système d'exploitation augmentent la durée d'un test. Ces impacts peuvent varier d'un appareil à l'autre.

Si une erreur de test se produit, le périphérique peut interrompre le test et signaler le résultat immédiatement.

[ATA] Notez que la commande ATA SMART EXECUTE OFF-LINE IMMEDIATE (la commande pour démarrer un test) a été déclarée obsolète dans ATA ACS-4 Révision 10 (novembre 2015).

Les arguments valides pour cette option sont :

offline - [ATA] exécute le test immédiat hors ligne SMART. Cela démarre immédiatement le test décrit ci-dessus. Cette commande peut être donnée pendant le fonctionnement normal du système. Les effets de ce test ne sont visibles que dans la mesure où il met à jour les valeurs des attributs SMART, et si des erreurs sont trouvées, elles apparaîtront dans le journal des erreurs SMART, visibles avec l'option '-l error'.

Si l'option '-c' pour

smartctl indique que le périphérique possède la capacité « Suspend Offline collection upon new command » (Suspendre la collecte hors ligne sur nouvelle commande), vous pouvez alors suivre la progression du test de détection hors ligne immédiat en utilisant l'option '-c' de smartctl. Si l'option '-c' indique que le périphérique possède la capacité « Abort Offline collection upon new command » (Abandonner la collecte hors ligne sur nouvelle commande), la plupart des commandes abandonneront le test de détection hors ligne immédiat, vous ne devez donc pas essayer de suivre la progression du test avec '-c', car cela abandonnera le test.

offline - [SCSI] exécute le test d'auto-diagnostic par défaut en premier plan. Aucune entrée n'est placée dans le journal des tests d'auto-diagnostic.

short - [ATA] exécute le test d'auto-diagnostic court SMART (généralement moins de dix minutes). Cette commande peut être passée pendant le fonctionnement normal du système (sauf si elle est exécutée en mode captif - voir l'option '-C' ci-dessous). C'est un test appartenant à une catégorie différente des tests hors ligne immédiats ou automatiques. Les tests "Self" vérifient les performances électriques et mécaniques ainsi que les performances de lecture du disque. Leurs résultats sont rapportés dans le journal des erreurs d'auto-diagnostic, lisible avec l'option '-l selftest'. Notez que sur certains disques, la progression du test d'auto-diagnostic peut être surveillée en consultant ce journal pendant le test ; sur d'autres disques, utilisez l'option '-c' pour surveiller la progression.

short - [SCSI] exécute le test d'auto-diagnostic "Background short" (court arrière-plan).

short - [NVMe : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.4] exécute le test d'auto-diagnostic "Short" (court) pour l'espace de noms actuel.

long - [ATA] exécute le test d'auto-diagnostic étendu SMART (de quelques dizaines de minutes à plusieurs heures). C'est une version plus longue et plus approfondie du test d'auto-diagnostic court décrit ci-dessus. Notez que cette commande peut être passée pendant le fonctionnement normal du système (sauf si elle est exécutée en mode captif - voir l'option '-C' ci-dessous).

long - [SCSI] exécute le test d'auto-diagnostic "Background long" (long arrière-plan).

long - [NVMe : NOUVELLE FONCTIONNALITÉ EXPÉRIMENTALE SMARTCTL 7.4] exécute le test d'auto-diagnostic "Extended" (étendu) pour l'espace de noms actuel.

conveyance - [ATA uniquement] exécute un test d'auto-diagnostic SMART "Conveyance" (transport) (quelques minutes). Cette routine de test d'auto-diagnostic est conçue pour identifier les dommages subis pendant le transport du périphérique. Cette routine de test d'auto-diagnostic devrait prendre de l'ordre de quelques minutes pour se terminer. Notez que cette commande peut être passée pendant le fonctionnement normal du système (sauf si elle est exécutée en mode captif - voir l'option '-C' ci-dessous).

select,N-M, select,N+SIZE - [ATA uniquement] exécute un test d'auto-diagnostic sélectif SMART, pour tester une plage d'adresses de blocs logiques (LBA) du disque, plutôt que le disque entier. Chaque plage de LBA testée est appelée un "span" (segment) et est spécifiée par une LBA de départ (N) et une LBA de fin (M) avec N inférieur ou égal à M. La plage peut également être spécifiée sous la forme N+TAILLE. Un segment à la fin d'un disque peut être spécifié par N-max.

Par exemple, les commandes :

  smartctl -t select,10-20 /dev/sda
  smartctl -t select,10+11 /dev/sda
exécutent toutes deux un test d'auto-diagnostic sur un segment composé des LBA dix à vingt (inclus). La commande : 
  smartctl -t select,100000000-max /dev/sda
exécute un test d'auto-diagnostic de la LBA 100000000 jusqu'à la fin du disque. L'option '-t' peut être passée jusqu'à cinq fois, pour tester jusqu'à cinq segments. Par exemple, la commande : 
  smartctl -t select,0-100 -t select,1000-2000 /dev/sda
exécute un test d'auto-diagnostic sur deux segments. Le premier segment est composé de 101 LBA et le second segment est composé de 1001 LBA. Notez que les segments peuvent se chevaucher partiellement ou complètement, par exemple : 
  smartctl -t select,0-10 -t select,5-15 -t select,10-20 /dev/sda
Les résultats du test d'auto-diagnostic sélectif peuvent être obtenus (pendant et après le test) en affichant le journal des tests d'auto-diagnostic SMART, en utilisant l'option '-l selftest' de smartctl.

Les tests d'auto-diagnostic sélectifs sont particulièrement utiles à mesure que les capacités des disques augmentent : un test d'auto-diagnostic étendu (smartctl -t long) peut prendre plusieurs heures. Les tests d'auto-diagnostic sélectifs sont utiles si (sur la base des messages d'erreur SYSLOG, des échecs de tests d'auto-diagnostic précédents ou des entrées du journal d'erreurs SMART) vous suspectez qu'un disque rencontre des problèmes sur une plage particulière d'adresses de blocs logiques (LBA).

Les tests d'auto-diagnostic sélectifs peuvent être exécutés pendant le fonctionnement normal du système (sauf s'ils sont effectués en mode captif - voir l'option '-C' ci-dessous).

Les variantes suivantes de la commande de test d'auto-diagnostic sélectif utilisent des segments basés sur les plages des tests précédents déjà stockées sur le disque :

select,redo[+SIZE] - [ATA uniquement] refait le dernier test d'auto-diagnostic sélectif SMART en utilisant la même plage de LBA. La LBA de départ est identique à la LBA utilisée par le dernier test, de même pour la LBA de fin sauf si une nouvelle taille de segment est spécifiée par l'argument optionnel +TAILLE.

Par exemple, les commandes :

  smartctl -t select,10-20 /dev/sda
  smartctl -t select,redo /dev/sda
  smartctl -t select,redo+20 /dev/sda
ont le même effet que : 
  smartctl -t select,10-20 /dev/sda
  smartctl -t select,10-20 /dev/sda
  smartctl -t select,10-29 /dev/sda

select,next[+SIZE] - [ATA uniquement] exécute un test d'auto-diagnostic sélectif SMART sur la plage de LBA qui suit la plage du dernier test. La LBA de départ est définie sur (LBA de fin +1) du dernier test. Une nouvelle taille de segment peut être spécifiée par l'argument optionnel +TAILLE.

Par exemple, les commandes :

  smartctl -t select,0-999 /dev/sda
  smartctl -t select,next /dev/sda
  smartctl -t select,next+2000 /dev/sda
ont le même effet que : 
  smartctl -t select,0-999 /dev/sda
  smartctl -t select,1000-1999 /dev/sda
  smartctl -t select,2000-3999 /dev/sda

Si le dernier test s'est terminé à la dernière LBA du disque, la nouvelle plage commence à la LBA 0. La taille du segment du dernier segment d'un disque est ajustée de sorte que le nombre total de segments pour tester le disque complet ne soit pas modifié par les utilisations futures de '-t select,next'.

select,cont[+SIZE] - [ATA uniquement] effectue un 'redo' (ci-dessus) si le statut du test d'auto-diagnostic indique que le dernier test a été abandonné par l'hôte. Sinon, il exécute le test 'next' (ci-dessus).

afterselect,on - [ATA uniquement] effectue un scan de lecture hors ligne après la fin d'un test d'auto-diagnostic sélectif. Cette option doit être utilisée conjointement avec une ou plusieurs des options select,N-M ci-dessus. Si les LBA spécifiées dans le test d'auto-diagnostic sélectif réussissent le test sans aucune erreur détectée, alors le reste du disque est scanné en lecture. Si le périphérique est mis hors tension pendant ce scan de lecture, le scan de lecture sera automatiquement repris après un délai spécifié par le minuteur en attente (voir ci-dessous). La valeur de cette option est conservée entre les tests d'auto-diagnostic sélectifs.

afterselect,off - [ATA uniquement] ne scanne pas le reste du disque en lecture après la fin d'un test d'auto-diagnostic sélectif. Cette option doit être utilisée conjointement avec une ou plusieurs des options select,N-M ci-dessus. La valeur de cette option est conservée entre les tests d'auto-diagnostic sélectifs.

pending,N - [ATA uniquement] définit le minuteur de scan de lecture hors ligne en attente à N minutes. Ici, N est un entier compris entre 0 et 65535 inclus. Si le périphérique est mis hors tension pendant un scan de lecture après un test d'auto-diagnostic sélectif, le test reprendra automatiquement N minutes après le démarrage. Cette option doit être utilisée conjointement avec une ou plusieurs des options select,N-M ci-dessus. La valeur de cette option est conservée entre les tests d'auto-diagnostic sélectifs.

vendor,N - [ATA uniquement] émet la commande ATA SMART EXECUTE OFF-LINE IMMEDIATE avec la sous-commande N dans le registre LBA LOW. La sous-commande est spécifiée sous forme de valeur hexadécimale dans la plage 0x00 à 0xff. Les sous-commandes 0x40-0x7e et 0x90-0xff sont réservées à un usage spécifique au vendeur, voir la table 61 de T13/1699-D Revision 6a (ATA8-ACS). Notez que les sous-commandes 0x00-0x04, 0x7f, 0x81-0x84 sont prises en charge par d'autres options de smartctl (par exemple, 0x01 : '-t short', 0x7f : '-X', 0x82 : '-C -t long').

ATTENTION : N'exécutez que les sous-commandes documentées par le vendeur du périphérique.

Exemple pour certains SSD Intel uniquement : La sous-commande 0x40 ('-t vendor,0x40') efface les attributs SMART liés à la charge de travail chronométrée (226, 227, 228). Notez que les valeurs brutes de ces attributs sont maintenues à 65535 (0xffff) jusqu'à ce que le minuteur de charge de travail atteigne 60 minutes.

force - démarre un nouveau test d'auto-diagnostic même si un autre test est déjà en cours. Par défaut, un test d'auto-diagnostic en cours ne sera pas interrompu pour en démarrer un autre.

-C, --captive
[ATA] Exécute les tests d'auto-diagnostic en mode captif. Cela n'a aucun effet avec '-t offline' ou si l'option '-t' n'est pas utilisée.

ATTENTION : Les tests exécutés en mode captif peuvent rendre le disque indisponible pendant la durée du test. N'exécutez les tests captifs que sur des disques sans aucune partition montée !

[SCSI] Exécute le test d'auto-diagnostic en mode "Foreground" (premier plan).

-X, --abort
Abandonne les tests d'auto-diagnostic SMART non captifs. Notez que cette commande abandonnera la routine de test hors ligne immédiat uniquement si votre disque possède la capacité "Abort Offline collection upon new command".

Ensembles de commandes ATA, SCSI et SAT

Par le passé, il existait une distinction claire entre les périphériques de stockage qui utilisaient les ensembles de commandes ATA et SCSI. Cette distinction se reflétait souvent dans leur dénomination et leur matériel. Désormais, divers transports SCSI (par exemple, SAS, FC et iSCSI) peuvent s'interconnecter avec des disques SCSI (par exemple, FC et SAS) et des disques ATA (en particulier SATA). Les périphériques de stockage USB et IEEE 1394 utilisent l'ensemble de commandes SCSI en externe mais contiennent presque toujours des disques ATA ou SATA (ou flash). Les sous-systèmes de stockage de certains systèmes d'exploitation ont commencé à supprimer la distinction entre ATA et SCSI dans leurs politiques de dénomination des périphériques.

99% des opérations qu'un système d'exploitation effectue sur un disque impliquent les commandes SCSI INQUIRY, READ CAPACITY, READ et WRITE, ou leurs équivalents ATA. Étant donné que les commandes SCSI sont légèrement plus générales que leurs équivalents ATA, de nombreux systèmes d'exploitation génèrent des commandes SCSI (principalement READ et WRITE) et laissent une couche inférieure les traduire en leurs équivalents ATA lorsque le besoin se fait sentir. Une note importante ici est que la "couche inférieure" peut se trouver dans un équipement externe et donc hors du contrôle d'un système d'exploitation.

La traduction SCSI vers ATA (SAT) est une norme (ANSI INCITS 431-2007) qui spécifie comment cette traduction est effectuée. Pour les 1% restants des opérations qu'un système d'exploitation effectue sur un disque, SAT offre deux options. La première est une commande SCSI ATA PASS-THROUGH facultative (il existe deux variantes). La seconde est une traduction à partir de la commande SCSI la plus proche. L'intérêt actuel porte principalement sur l'option "pass-through".

La pertinence

ance à smartmontools (et donc à smartctl) est que ses interactions avec les disques tombent solidement dans la catégorie des « 1 % ». Ainsi, même si le système d'exploitation peut traiter (et nommer) un disque comme « SCSI » sans problème, smartmontools doit détecter le jeu de commandes natif et agir en conséquence. À mesure que davantage de fabricants de stockage (y compris les disques SATA externes) se conforment à SAT, smartmontools est capable de distinguer automatiquement le jeu de commandes natif de l'appareil. Dans certains cas, l'option « -d sat » est nécessaire sur la ligne de commande.

Il existe également des disques virtuels qui n'ont généralement aucune information utile à transmettre à smartmontools, mais qui pourraient éventuellement en avoir à l'avenir. Un exemple de disque virtuel est la vue du système d'exploitation sur une boîte RAID 1. Il y a très probablement deux disques SATA à l'intérieur d'une boîte RAID 1. S'adresser à ces disques SATA depuis un système d'exploitation distant est un défi pour smartmontools. Une autre approche consiste à exécuter un outil comme smartmontools à l'intérieur de la boîte RAID 1 (par exemple, un boîtier de stockage en réseau - NAS) et à récupérer les journaux via un navigateur.

LECTEURS DE BANDES

Commandes pour les lecteurs de bandes SCSI telles que définies dans la norme SSC-4 (ANSI INCITS 516-2013). SSC signifie « SCSI Streaming Commands » (Commandes de flux SCSI). Les projets de normes peuvent être trouvés sur https://www.t10.org/.

De nombreuses fonctionnalités liées au SMART des disques SCSI sont partagées par les lecteurs de bandes SCSI. Une page de journal importante spécifique aux bandes est appelée « TapeAlert », qui est utilisée pour signaler des conditions anormales. Contrairement à la plupart des autres pages de journal, la page de journal TapeAlert **efface** les alertes en attente après la récupération de cette page (c'est-à-dire sa lecture à partir du lecteur de bande). Pour être plus précis, la page de journal TapeAlert est effacée pour le nexus I_T (paire initiateur-cible) qui a envoyé la commande (SCSI LOG SENSE) ; ainsi, un autre initiateur (par exemple, une carte HBA sur une autre machine) continuera à avoir des alertes en attente signalées. [Cette action d'effacement peut être contrôlée par le bit TAPLSD dans la page de mode d'extension de configuration de périphérique [SSC], mais l'action d'origine et par défaut reste : effacer toutes les alertes TapeAlert en attente. L'utilitaire sdparm peut être utilisé pour accéder et modifier TAPLSD.]

Les versions précédentes de smartctl prenaient en charge l'interrogation de la page de journal TapeAlert lorsque l'option --health était donnée. Cet effacement des alertes en attente a créé des problèmes pour d'autres outils spécifiques aux bandes. Cette version de smartctl ne récupérera la page de journal TapeAlert que si l'option --health est donnée **deux fois** lors de l'invocation de la commande (ou si l'option --log=tapealert est donnée).

Il existe d'autres pages de journal spécifiques aux bandes telles que --log=tapedevstat qui se comportent normalement (c'est-à-dire qu'elles ne modifient aucune information d'état dans le lecteur de bande).

EXEMPLES

smartctl -a /dev/sda
Affiche une grande quantité d'informations SMART pour le lecteur /dev/sda.

smartctl -s off /dev/sdd
Désactive la surveillance SMART et la collecte de journaux de données sur le lecteur /dev/sdd.

smartctl --smart=on --offlineauto=on --saveauto=on /dev/sda
Active le SMART sur le lecteur /dev/sda, active les tests hors ligne automatiques toutes les quatre heures, et active la sauvegarde automatique des attributs SMART. C'est une bonne ligne de démarrage pour les fichiers d'initialisation de votre système. Vous pouvez exécuter cette commande sur un système en cours d'exécution.

smartctl -t long /dev/sdc
Démarre un auto-test étendu du lecteur /dev/sdc. Vous pouvez exécuter cette commande sur un système en cours d'exécution. Les résultats peuvent être consultés dans le journal d'auto-tests visible avec l'option '-l selftest' après son achèvement.

smartctl -s on -t offline /dev/sda
Active le SMART sur le disque et démarre un test hors ligne immédiat du lecteur /dev/sda. Vous pouvez exécuter cette commande sur un système en cours d'exécution. Les résultats sont uniquement utilisés pour mettre à jour les attributs SMART, visibles avec l'option '-A'. Si des erreurs de périphérique surviennent, elles sont enregistrées dans le journal d'erreurs SMART, qui peut être consulté avec l'option '-l error'.

smartctl -A -v 9,minutes /dev/sda
Affiche les attributs du fournisseur, lorsque le disque stocke son temps de mise sous tension en interne en minutes plutôt qu'en heures.

smartctl -q errorsonly -H -l selftest /dev/sda
Produit une sortie uniquement si l'appareil renvoie un statut SMART défaillant, ou si certains des auto-tests enregistrés se sont terminés par des erreurs.

smartctl -q silent -a /dev/sda
Examine toutes les données SMART pour l'appareil /dev/sda, mais ne produit aucune sortie imprimée. Vous devez utiliser le code de sortie (la variable shell $?) pour savoir si des attributs sont hors limites, si le statut SMART est défaillant, s'il y a des erreurs enregistrées dans le journal d'auto-tests, ou s'il y a des erreurs enregistrées dans le journal d'erreurs du disque.

smartctl -a -d 3ware,0 /dev/twl0
Examine toutes les données SMART pour le premier disque SATA (pas SAS) connecté à une carte contrôleur RAID 3ware 9750.

smartctl -t long -d areca,4 /dev/sg2
Démarre un auto-test long sur le quatrième disque SATA connecté à un contrôleur RAID Areca adressé par /dev/sg2.

smartctl -a -d hpt,1/3 /dev/sda (sous Linux)
smartctl -a -d hpt,1/3 /dev/hptrr (sous FreeBSD)
Examine toutes les données SMART pour le disque (S)ATA directement connecté au troisième canal de la première carte contrôleur HighPoint RocketRAID.

smartctl -t short -d hpt,1/1/2 /dev/sda (sous Linux)
smartctl -t short -d hpt,1/1/2 /dev/hptrr (sous FreeBSD)
Démarre un auto-test court sur le disque (S)ATA connecté au deuxième port pm sur le premier canal de la première carte contrôleur HighPoint RocketRAID.

smartctl -t select,10-100 -t select,30-300 -t afterselect,on -t pending,45 /dev/sda
Exécute un auto-test sélectif sur les LBA 10 à 100 et 30 à 300. Après que ces LBA aient été testés, analyse en lecture le reste du disque. Si le disque est mis sous tension pendant l'analyse en lecture, reprend l'analyse 45 minutes après que l'alimentation de l'appareil soit rétablie.

smartctl -a -d cciss,0 /dev/cciss/c0d0
Examine toutes les données SMART pour le premier disque SCSI connecté à une carte contrôleur RAID cciss.

STATUT DE SORTIE

Les codes de sortie de smartctl sont définis par un masque de bits. Si tout va bien avec le disque, le code de sortie (valeur de retour) de smartctl est 0 (tous les bits désactivés). Si un problème survient, ou une erreur, une erreur potentielle ou une faute est détectée, alors un statut non nul est renvoyé. Dans ce cas, les huit bits différents du code de sortie ont les significations suivantes pour les disques ATA ; certaines de ces valeurs peuvent également être renvoyées pour les disques SCSI.

Bit 0 :
La ligne de commande n'a pas pu être analysée.
Bit 1 :
L'ouverture du périphérique a échoué, le périphérique n'a pas renvoyé une structure IDENTIFY DEVICE, ou le périphérique est en mode basse consommation (voir l'option '-n' ci-dessus).
Bit 2 :
Une commande SMART ou une autre commande ATA vers le disque a échoué, ou il y a eu une erreur de somme de contrôle dans une structure de données SMART (voir l'option '-b' ci-dessus).
Bit 3 :
La vérification du statut SMART a renvoyé « DISK FAILING » (Disque défaillant).
Bit 4 :
Nous avons trouvé des attributs pré-défaillants <= au seuil.
Bit 5 :
La vérification du statut SMART a renvoyé « DISK OK » (Disque OK) mais nous avons constaté que certains attributs (d'utilisation ou pré-défaillants) ont été <= au seuil à un moment donné dans le passé.
Bit 6 :
Le journal d'erreurs du périphérique contient des enregistrements d'erreurs.
Bit 7 :
Le journal d'auto-tests du périphérique contient des enregistrements d'erreurs. [ATA uniquement] Les auto-tests échoués rendus obsolètes par un auto-test étendu plus récent et réussi sont ignorés.

Pour tester dans le shell si les différents bits sont activés ou désactivés, vous pouvez utiliser le type de construction suivant (qui devrait fonctionner avec tout shell compatible POSIX) :
smartstat=$(($? & 8))
Ceci ne regarde que le bit 3 du code de sortie $? (puisque 8=2^3). La variable shell $smartstat sera non nulle si la vérification du statut SMART a renvoyé « disque défaillant » et zéro sinon.

Ce script shell imprime tous les bits de statut :

val=$?; mask=1
for i in 0 1 2 3 4 5 6 7; do
  echo "Bit $i: $(((val & mask) && 1))"
  mask=$((mask << 1))
done
