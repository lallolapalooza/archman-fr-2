SMBPASSWD(5) Formats de fichiers et conventions SMBPASSWD(5)

NOM

smbpasswd - Le fichier de mots de passe chiffrés Samba

SYNTAXE

smbpasswd

DESCRIPTION

Cet outil fait partie de la suite samba(7).

smbpasswd est le fichier de mots de passe chiffrés de Samba. Il contient le nom d'utilisateur, l'identifiant utilisateur Unix et les mots de passe hachés SMB de l'utilisateur, ainsi que des informations sur les indicateurs de compte et l'heure de la dernière modification du mot de passe. Le format de ce fichier a évolué avec Samba et a eu plusieurs formats différents par le passé.

FORMAT DU FICHIER

Le format du fichier smbpasswd utilisé par Samba 2.2 est très similaire au fichier passwd(5) familier de Unix. C'est un fichier ASCII contenant une ligne par utilisateur. Chaque champ dans chaque ligne est séparé du suivant par un deux-points. Toute entrée commençant par '#' est ignorée. Le fichier smbpasswd contient les informations suivantes pour chaque utilisateur :

nom

C'est le nom d'utilisateur. Il doit s'agir d'un nom qui existe déjà dans le fichier passwd standard de UNIX.

uid

C'est l'uid UNIX. Il doit correspondre au champ uid pour la même entrée utilisateur dans le fichier passwd standard de UNIX. Si cela ne correspond pas, Samba refusera de reconnaître cette entrée du fichier smbpasswd comme valide pour un utilisateur.

Hash du mot de passe Lanman

C'est le hachage LANMAN du mot de passe de l'utilisateur, encodé en 32 chiffres hexadécimaux. Le hachage LANMAN est créé en chiffrant DES une chaîne bien connue avec le mot de passe de l'utilisateur comme clé DES. C'est le même mot de passe utilisé par les machines Windows 95/98. Notez que ce hachage de mot de passe est considéré comme faible car il est vulnérable aux attaques par dictionnaire et si deux utilisateurs choisissent le même mot de passe, cette entrée sera identique (c'est-à-dire que le mot de passe n'est pas "salé" comme le mot de passe UNIX). Si l'utilisateur a un mot de passe nul, ce champ contiendra les caractères "NO PASSWORD" au début de la chaîne hexadécimale. Si la chaîne hexadécimale est égale à 32 caractères 'X', le compte de l'utilisateur est marqué comme désactivé et l'utilisateur ne pourra pas se connecter au serveur Samba.

ATTENTION !! Notez qu'en raison de la nature défi/réponse du protocole d'authentification SMB/CIFS, toute personne connaissant ce hachage de mot de passe pourra usurper l'identité de l'utilisateur sur le réseau. Pour cette raison, ces hachages sont connus sous le nom d'équivalents de texte clair et ne doivent PAS être mis à la disposition de quiconque, sauf de l'utilisateur root. Pour protéger ces mots de passe, le fichier smbpasswd est placé dans un répertoire dont l'accès en lecture et parcours est réservé à l'utilisateur root, et le fichier smbpasswd lui-même doit être configuré en lecture/écriture uniquement pour root, sans aucun autre accès.

Hash du mot de passe NT

C'est le hachage Windows NT du mot de passe de l'utilisateur, encodé en 32 chiffres hexadécimaux. Le hachage Windows NT est créé en prenant le mot de passe de l'utilisateur tel que représenté en UNICODE 16 bits, little-endian, puis en lui appliquant l'algorithme de hachage MD4 (Internet RFC1321).

Ce hachage de mot de passe est considéré comme plus sûr que le hachage de mot de passe LANMAN car il préserve la casse du mot de passe et utilise un algorithme de hachage de bien meilleure qualité. Cependant, il est toujours vrai que si deux utilisateurs choisissent le même mot de passe, cette entrée sera identique (c'est-à-dire que le mot de passe n'est pas "salé" comme le mot de passe UNIX).

ATTENTION !!. Notez qu'en raison de la nature défi/réponse du protocole d'authentification SMB/CIFS, toute personne connaissant ce hachage de mot de passe pourra usurper l'identité de l'utilisateur sur le réseau. Pour cette raison, ces hachages sont connus sous le nom d'équivalents de texte clair et ne doivent PAS être mis à la disposition de quiconque, sauf de l'utilisateur root. Pour protéger ces mots de passe, le fichier smbpasswd est placé dans un répertoire dont l'accès en lecture et parcours est réservé à l'utilisateur root, et le fichier smbpasswd lui-même doit être configuré en lecture/écriture uniquement pour root, sans aucun autre accès.

Indicateurs de compte

Cette section contient des indicateurs qui décrivent les attributs du compte utilisateur. Ce champ est encadré par des crochets '[' et ']' et fait toujours 13 caractères de long (y compris les caractères '[' et ']'). Le contenu de ce champ peut être l'un des caractères suivants :
•U - Ceci signifie qu'il s'agit d'un compte "Utilisateur", c'est-à-dire un utilisateur ordinaire.
•N - Ceci signifie que le compte n'a pas de mot de passe (les mots de passe dans les champs Hash du mot de passe LANMAN et Hash du mot de passe NT sont ignorés). Notez que cela ne permettra aux utilisateurs de se connecter qu'avec un mot de passe nul si le paramètre mots de passe nuls est défini dans le fichier de configuration smb.conf(5).
•D - Ceci signifie que le compte est désactivé et qu'aucune connexion SMB/CIFS ne sera autorisée pour cet utilisateur.
•X - Ceci signifie que le mot de passe n'expire pas.
•W - Ceci signifie qu'il s'agit d'un compte "Confiance poste de travail". Ce type de compte est utilisé dans le flux de code PDC Samba pour permettre aux postes de travail et serveurs Windows NT de rejoindre un Domaine hébergé par un PDC Samba.
D'autres indicateurs peuvent être ajoutés à mesure que le code est étendu dans le futur. Le reste de l'espace de ce champ est rempli d'espaces. Pour plus d'informations sur les indicateurs pris en charge, veuillez vous référer à la page de manuel de la commande pdbedit.

Heure de la dernière modification

Ce champ représente l'heure de la dernière modification du compte. Il se compose des caractères 'LCT-' (pour "Last Change Time", Heure de la dernière modification) suivis d'un encodage numérique du temps UNIX en secondes depuis l'époque (1970) de la dernière modification.

Tous les autres champs séparés par des deux-points sont ignorés à l'heure actuelle.
