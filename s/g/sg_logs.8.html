NOM

sg_logs - accède aux pages de log avec la commande SCSI LOG SENSE

SYNOPSIS

sg_logs [--ALL] [--all] [--brief] [--exclude] [--filter=FL] [--full] [--hex] [--json[=JO]] [--js-file=JFN] [--list] [--maxlen=LEN] [--name] [--no_inq] [--page=PG] [--paramp=PP] [--pcb] [--ppc] [--pdt=DT] [--raw] [--readonly] [--sp] [--temperature] [--transport] [--undefined] [--vendor=VP] [--verbose] PÉRIPHÉRIQUE

sg_logs --inhex=FN [--ALL] [--all] [--brief] [--exclude] [--filter=FL] [--full] [--hex] [--json[=JO]] [--js-file=JFN] [--list] [--name] [--page=PG] [--pdt=DT] [--raw] [--undefined] [--vendor=VP]

sg_logs --select [--control=PC] [--page=PG] [--raw] [--reset] [--sp] [--verbose] PÉRIPHÉRIQUE

sg_logs --enumerate [--filter=FL] [--help] [--vendor=VP] [--version]

sg_logs [-a] [-A] [-b] [-c=PC] [-D=DT] [-e] [-E] [-f=FL] [-F] [-h] [-H] [-i=FN] [-l] [-L] [-m=LEN] [-M=VP] [-n] [-p=PG] [-paramp=PP] [-pcb] [-ppc] [-r] [-R] [-select] [-sp] [-t] [-T] [-u] [-v] [-V] [-?] [-x] PÉRIPHÉRIQUE

DESCRIPTION

Cet utilitaire envoie une commande SCSI LOG SENSE au PÉRIPHÉRIQUE puis affiche la réponse. La commande LOG SENSE est utilisée pour récupérer des pages de log qui, si elles sont connues, sont décodées par défaut. Lorsque l'option --reset et/ou --select est donnée, une commande SCSI LOG SELECT est émise vers le PÉRIPHÉRIQUE. Alternativement, une ou plusieurs réponses de page de log peuvent se trouver dans un fichier lu en utilisant l'option --inhex=FN ; dans ce cas, ces réponses sont décodées et l'argument PÉRIPHÉRIQUE, s'il est donné, est ignoré.

Dans la révision 5 de SPC-4, le code de sous-page a été introduit à la fois pour la commande LOG SENSE et LOG SELECT. Dans le même temps, un champ de code de page a été introduit dans la commande LOG SELECT. Le code de sous-page peut varier de 0 à 255 (0xff) inclus. La valeur 255 du code de sous-page peut être considérée comme un caractère générique.

La section SYNOPSIS ci-dessus est divisée en cinq formes. La première forme montre les options qui peuvent être utilisées pour envoyer une commande LOG SENSE au PÉRIPHÉRIQUE et décoder sa réponse. La deuxième forme récupère les données d'un fichier (nommé FN) et les décode comme si c'était une réponse d'une commande LOG SENSE. La troisième forme montre les options qui peuvent être utilisées pour envoyer une commande LOG SELECT. La quatrième forme regroupe diverses options de gestion. La dernière forme montre l'interface de ligne de commande plus ancienne et dépréciée, maintenue pour des raisons de compatibilité ascendante.

Lorsque aucune option n'est donnée, juste un PÉRIPHÉRIQUE, cela équivaut à appeler cet utilitaire avec l'option --list. Dans ce cas, les noms des pages de log supportées (mais pas les sous-pages) sont listés.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont disposées par ordre alphabétique basé sur le nom de l'option longue.

-A, --ALL
récupère et décode toutes les pages et sous-pages de log supportées par le PÉRIPHÉRIQUE. Ceci nécessite un processus en deux étapes : d'abord la page de log "pages et sous-pages de log supportées" est récupérée, puis pour chaque entrée dans sa réponse, la page (ou sous-page) de log correspondante est récupérée et affichée. Notez qu'il existe de nombreux périphériques SCSI qui ne supportent pas les sous-pages LOG SENSE et répondent à cette option avec une clé de sense illégale. Dans ce cas, cet utilitaire continue en récupérant plutôt la page de log des pages de log supportées. En d'autres termes, si l'option --ALL échoue, alors l'option --all est utilisée à la place. La raison est que le PÉRIPHÉRIQUE n'a très probablement aucune sous-page de log à signaler.
Pour forcer une erreur si la récupération de la page de log "pages et sous-pages de log supportées" échoue, utilisez les deux options --ALL et --full.
Comme certains fournisseurs ne listent pas toutes les pages de log dans la page "pages et sous-pages de log supportées", l'option '-lll' peut être donnée en plus. Cela fusionnera les deux pages de log "supportées ...", puis, à partir de cette liste fusionnée résultante, récupérera le contenu des pages.
Cette option remplace --page=PG si cette dernière est également donnée.
-a, --all
affiche toutes les pages de log supportées par le PÉRIPHÉRIQUE. Ceci nécessite un processus en deux étapes : d'abord la page de log "pages de log supportées" est récupérée, puis pour chaque entrée dans sa réponse, la page de log correspondante est récupérée et affichée. Lorsqu'elle est utilisée deux fois (par exemple, '-aa'), toutes les pages et sous-pages de log sont récupérées.
Cette option remplace --page=PG si cette dernière est également donnée.
-b, --brief
réduit la quantité de sortie pour certaines pages de log. Par exemple, la page de log Tape Alert n'affiche que les paramètres dont les indicateurs sont définis lorsque --brief est donné.
-c, --control=PC
accepte 0, 1, 2 ou 3 pour l'argument PC :
0 : valeurs seuils actuelles
1 : valeurs cumulatives actuelles
2 : valeurs seuils par défaut
3 : valeurs cumulatives par défaut
La valeur par défaut est 1 (c'est-à-dire valeurs cumulatives actuelles).
-e, --enumerate
cette option est utilisée pour afficher les informations contenues dans les tables internes de cet utilitaire concernant les pages de log connues, y compris leur nom, acronyme et champs. Si elle est donnée, l'argument PÉRIPHÉRIQUE est ignoré. Lorsqu'elle est donnée une fois (par exemple, '-e'), toutes les pages connues sont listées, triées par ordre alphabétique ascendant de l'acronyme.
Lorsqu'elle est donnée deux fois, les pages spécifiques au vendeur sont exclues. Lorsqu'elle est donnée trois fois, toutes les pages connues sont listées, triées par ordre numérique ascendant ; lorsqu'elle est donnée quatre fois, les pages spécifiques au vendeur sont exclues de l'ordre numérique.
Les options --filter=FL et --verbose réduisent la sortie de l'énumération.
-E, --exclude
cette option exclut les pages et paramètres spécifiques aux vendeurs de la sortie. Essayer de décoder des pages et paramètres spécifiques aux vendeurs ne fonctionne pas nécessairement bien pour de nombreuses raisons. Cette option limite la sortie aux pages et paramètres définis par T10.
Seuls les champs de paramètres identifiés dans les brouillons comme 'spécifiques au vendeur' sont exclus. Ainsi, les codes de paramètres identifiés comme 'réservés' sont affichés.
-f, --filter=FL
FL est soit un code de paramètre lorsque PÉRIPHÉRIQUE est donné, soit un type de périphérique (pdt) (ou autre) si --enumerate est donné.
Dans le cas du code de paramètre, FL est une valeur comprise entre 0 et 65535 (0xffff) et seule la section de paramètre correspondant à ce code est affichée. Si l'option --hex est donnée, le paramètre de log est affiché en hexadécimal plutôt que décodé. Si l'option --hex est utilisée deux fois, l'adresse de début sur chaque ligne hexadécimale est supprimée. Si l'option --raw est donnée, le paramètre de log est affiché en binaire. La plupart des pages de log contiennent un ou plusieurs paramètres de log. Les exemples de celles qui ne suivent pas cette convention sont les pages qui listent les pages (et sous-pages) de log supportées.
Dans le cas de --enumerate, lorsque FL >= zéro, il est considéré comme une valeur pdt et seules les pages de log associées à ce pdt plus les pages génériques listées dans SPC sont énumérées. Si FL est -1, le filtre ne fait rien, ce qui est identique à ne pas donner cette option ; lorsque FL est -2, seules les pages génériques listées dans SPC sont énumérées. Si FL est -10, seules les pages génériques d'accès direct (par exemple, disque) sont énumérées. Si FL est -11, seules les pages génériques de bande (par exemple, y compris ADC) sont énumérées.
-F, --full
cette option est utilisée uniquement dans deux situations : avec la page de log du client d'application (AC) et avec l'option --ALL. Généralement, la page de log AC contient plus de 16 000 octets de données fournies par l'utilisateur. Plutôt que de tout afficher, la valeur par défaut est d'afficher les 64 premiers octets de données. Lorsque cette
L’option est donnée, les pages de journal du client de l’application sont entièrement décodées.
Lorsque ces deux options et l’option --ALL sont fournies, cet utilitaire se terminera avec une erreur si la page de journal des pages et sous-pages de journal prises en charge n’est pas disponible.
-h, --help
affiche le message d’utilisation puis quitte.
-H, --hex
L’action par défaut consiste à décoder les numéros de page de journal (et de sous-page) connus en texte. Lorsque cette option est utilisée une fois, la réponse est affichée en hexadécimal. Lorsqu’elle est utilisée deux fois, chaque ligne hexadécimale affiche son équivalent ASCII à droite. Lorsqu’elle est utilisée trois fois, l’hexadécimal n’a ni adresse de début ni ASCII de fin, ce qui le rend approprié pour être placé dans un fichier (ou redirigé). Ce fichier pourrait plus tard être utilisé par une autre invocation utilisant l’option --inhex=FN.
Une forme plus faible de cette option, appelée --undefined, gère le formatage de la sortie hexadécimale pour les champs que cet utilitaire ne peut pas décoder.
-i, --in=FN
Identique à l’option --inhex=FN. Conservé pour la compatibilité ascendante.
-i, --inhex=FN
Cette option peut être utilisée dans deux contextes différents. L’un est avec --select pour envoyer une commande LOG SELECT au DEVICE donné ; voir la section LOG SELECT ci-dessous.
L’autre contexte est lorsqu’aucun argument DEVICE n’est donné, auquel cas le contenu de FN est décodé comme s’il s’agissait de la réponse d’une commande LOG SENSE (c’est-à-dire une ou plusieurs pages de journal). Pour le décodage, les numéros de page et de sous-page sont pris de FN tandis que le type de périphérique périphérique est soit générique (c’est-à-dire de SPC), soit la valeur donnée par --pdt=DT.
FN est traité comme un nom de fichier (ou '-' pour stdin) contenant de l’hexadécimal ASCII ou binaire représentant une page de journal. L’hexadécimal doit être organisé en 1 ou 2 chiffres représentant un octet, chacun étant séparé par des espaces blancs ou des virgules. Tout à partir d’un signe dièse jusqu’à la fin de la ligne est ignoré. Si l’option --raw est également donnée, alors FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du texte brut. Notez que les arguments de la forme courte et longue sont facultatifs et, s’ils sont présents, commencent par « = » et aucun espace n’est autorisé autour de ce « = ».
Consultez le manuel sg3_utils_json ou utilisez « ? » pour JO afin d’obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l’option --json[=JO] est implicite et n’a pas besoin d’être donnée. L’option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO sur des valeurs non par défaut.
-l, --list
liste les noms des pages de journalisation prises en charge par ce périphérique. Cela est fait en lisant la page de journal « pages de journal prises en charge ». Lorsqu’elle est utilisée une fois, seules les pages de journal, mais pas les sous-pages, sont listées. Lorsqu’elle est utilisée deux fois, la page de journal « pages et sous-pages de journal prises en charge » est générée. Certains fournisseurs ne listent pas certaines pages de journal (par exemple, celles sans sous-pages) dans la page de journal « pages et sous-pages de journal prises en charge ». Pour obtenir un inventaire complet, cette option peut être utilisée trois fois (par exemple, « -lll ») et la sortie des deux pages de journal est fusionnée. Même si la page de journal « pages et sous-pages de journal prises en charge » n’est pas prise en charge, l’utilisation de cette option trois fois produira une liste à partir de la page de journal « pages de journal prises en charge ». En l’absence d’autres options, les noms des pages/sous-pages, mais pas leur contenu, sont affichés lorsque cette option est donnée.
La forme « -lll » peut être utile avec l’option --ALL pour afficher le contenu de toutes les pages référencées dans la page de journal « page de journal prise en charge » ou « pages et sous-pages de journal prises en charge ». pages.
-m, --maxlen=LEN
définit le champ « longueur d’allocation » dans le cdb LOG SENSE. Il s’agit de la longueur maximale en octets de la réponse. Sans cette option (ou avec LEN égal à 0), cet utilitaire récupère d’abord la réponse de 4 octets, puis effectue un deuxième accès avec la longueur indiquée dans la première réponse (de 4 octets). Les valeurs négatives et 1 pour LEN ne sont pas acceptées. Les réponses peuvent être assez volumineuses (par exemple, la page de journal des résultats de balayage en arrière-plan) et cette option peut être utilisée pour limiter la quantité d’informations retournées.
La valeur par défaut de LEN est 65532, sauf si l’option --in=FN est donnée ; dans ce cas, la valeur par défaut est 262144.
-n, --name
décode certaines pages de journal en entrées « nom=valeur », une par ligne. Le nom ne contient pas d’espace et peut être abrégé, et la valeur est décimale sauf si elle est précédée de « 0x ». L’imbrication est indiquée par des espaces en retrait. Cette forme est censée être relativement facile à analyser.
Cette option est remplacée par l’option --json[=JO]. Si les deux sont données, cette option est ignorée.
-x, --no_inq
supprime la sortie des informations obtenues à partir d’un appel initial à la commande INQUIRY pour la réponse standard. Par défaut (en supposant que certaines autres options qui suppriment cette sortie ne sont pas non plus données), plusieurs chaînes d’identification de périphérique sont générées.
Si cette option est donnée deux fois (ou plus), aucune commande INQUIRY n’est envoyée, il n’y aura donc pas non plus de sortie de chaîne d’identification de périphérique. De plus, le champ type de périphérique périphérique (PDT) ne sera pas obtenu, cet utilitaire ne pourra donc pas différencier certaines pages de journal qui dépendent du périphérique. L’utilitaire supposera un PDT de 0 (c’est-à-dire un disque) à moins que l’option --pdt=DT ne soit donnée.
-O, --old
Commute vers les options de style ancien. Veuillez l’utiliser comme première option.
-p, --page=PG
nom/numéro de page de journal à accéder. PG est soit un acronyme, un numéro de page, soit une paire de numéros de page et de sous-page. Les acronymes disponibles peuvent être listés avec l’option --enumerate. Les numéros de page (0 à 63) et de sous-page (0 à 255) sont séparés par des virgules. Ils sont décimaux sauf indication hexadécimale. Un nombre hexadécimal peut être spécifié par un « 0x » initial ou un « h » final.
Quelques acronymes spécifient une plage de valeurs de sous-pages, auquel cas l’acronyme peut être suivi d’une virgule puis d’un numéro de sous-page. Cette méthode peut également être utilisée pour récupérer la page de journal des sous-pages prises en charge (par exemple, --page=temp,0xff).
-P, --paramp=PP
PP est le pointeur de paramètre à placer dans un champ du même nom dans le cdb LOG SENSE. Un nombre dans la plage 0 à 65535 (0x0 à 0xffff) est attendu. Lorsqu’une valeur supérieure à 0 est donnée, l’option --ppc doit être sélectionnée. La valeur par défaut est 0.
Pour les pages de journal qui ont des codes de paramètre, le DEVICE doit renvoyer uniquement des codes de paramètre égaux à PP ou supérieurs dans sa réponse.
-q, --pcb
affiche les paramètres du Byte de contrôle des paramètres (uniquement pertinents lorsque les paramètres du journal sont générés en ASCII). Ce byte inclut les bits DU et TSD ainsi que le champ « Format et liaison » (large de 2 bits).
-D, --pdt=DT
DT est le type de périphérique périphérique (PDT) utilisé lorsqu’il n’est pas disponible à partir du DEVICE. Il existe plusieurs cas : lorsque le DEVICE n’est pas donné (par exemple, lorsque l’option --inhex=FN ou --enumerate est donnée) et lorsque DEVICE est donné et associé à l’option --no_inq. Cela empêche cet utilitaire d’envoyer la commande SCSI INQUIRY, d’où cet utilitaire trouve généralement les pages de journal associées au PDT pour le décodage.
Des valeurs numériques comprises entre -1 et 31 (inclus) peuvent être utilisées, où -1 implique ce qui est dans SPC. Les commandes primaires SCSI (SPC) sont communes à tous les périphériques SCSI. Des noms tels que « tape », « disk » et « processor » peuvent également être donnés pour DT. La valeur par défaut est 0 ou « disk » pour SBC (et l’acronyme standard associé peut également être donné, qui est « sbc » dans ce cas).
-Q, --ppc
définit le bit Parameter Pointer Control (PPC) dans le cdb LOG SENSE. La valeur par défaut est 0 (c’est-à-dire effacé). Ce bit a été rendu obsolète dans la révision 18 de SPC-4.
-r, --raw
génère la réponse en binaire vers stdout. Les messages d’erreur et les avertissements sont générés vers stderr.
Cette option peut également être donnée avec --in=FN, auquel cas le contenu de FN est interprété comme des données binaires (et la réponse est décodée normalement, pas affichée en binaire).
-R, --readonly
ouvre le DEVICE en lecture seule (par exemple, sous Unix avec le drapeau O_RDONLY). L’action par défaut consiste à essayer d’ouvrir DEVICE en lecture-écriture, puis, si cela échoue, à réessayer en lecture seule. Cependant, lorsqu’une ouverture en lecture-écriture réussit, il peut toujours y avoir des actions indésirables lors de la fermeture (par exemple, certains systèmes d’exploitation essaient d’exécuter une commande SYNCHRONIZE CACHE). Cette option force donc une ouverture en lecture seule sur DEVICE et, si elle échoue, cet utilitaire se terminera. Notez que les options telles que --select nécessitent très probablement une ouverture en lecture-écriture.
-R, --reset
utilise la commande SCSI LOG SELECT (avec le bit PCR défini) pour réinitialiser toutes les pages de journal (ou la page donnée). Ce qui est exactement réinitialisé dépend du bit SP accompagnant (c’est-à-dire l’option --sp qui est par défaut à 0) et de la valeur PC (« contrôle de page ») (qui est par défaut à 1). Fournir cette option implique également l’option --select. Cette option semble effacer les pages de journal des compteurs d’erreurs mais laisse les pages telles que les résultats d’auto-test, le compteur de cycles de démarrage-arrêt et les pages de journal de température inchangées. Cette option peut être nécessaire pour effacer les pages de journal si un compteur atteint sa valeur maximale, car la page de journal dans laquelle se trouve le compteur restera « bloquée » à sa valeur maximale jusqu’à une interaction utilisateur (par exemple, appeler sg_logs avec cette option).
-S, --select
utilise une commande LOG SELECT. L’action par défaut (c’est-à-dire lorsque ni cette option ni --reset ne sont données) est d’exécuter une commande LOG SENSE. Voir la section LOG SELECT.
-s, --sp
définit le bit Saving Parameters (SP). La valeur par défaut est 0 (c’est-à-dire effacé). Lorsqu’il est défini, il demande au périphérique de s

NEW COMMAND LINE OPTIONS

These new command line options were introduced in sg3_utils version 1.23.

-a, --all
outputs all the log pages supported by the DEVICE. This option can be given more than once, in which case it means dump all pages and subpages. If this option is used with --inhex=FN and there is no DEVICE argument, it lists all log pages (and subpages if used twice or more) found in FN.
-b, --byte
outputs log parameters in blocks of 16 bytes, with hex bytes and ASCII to the right. This is the default if the log page decode logic does not produce a more structured output.
-c, --control=PC
where PC is the 1-byte 'Parameter Code' for the LOG PARAMETER FIELD. It defaults to 0x00. This is the Parameter Code (PC) field in the LOG PARAMETER header (see sbí 1.1). Note that this is only active for the LOG SELECT command.
-d, --dump
outputs the entire log page (in hex) without any decoding. Useful if you want to see the raw data. If used with --inhex=FN, it just dumps the contents of FN.
-e, --enumerate
enumerate internal tables to show information about known log pages. Defaults to listing pages only. If used with --verbose, then subpages are also listed, and pages that have no associated decode logic are marked.
-E, --exclude
exclude vendor specific log pages. Usually only relevant when dumping all log pages.
-f, --filter=FP
filters the output of log pages based on the given parameter code FP. The parameter code FP is treated as a hex number. This option is only active when reading log pages (i.e. not used with LOG SELECT). Multiple uses of this option filter on multiple parameter codes.
-F, --filter_log=FP
similar to --filter but operates on the 'Log Filter' field in the log page sense data. The value FP is treated as a hex number.
-h, --hex
outputs the response in hex. This option cannot be used with the --undefined option. This option is active for both LOG SENSE and LOG SELECT commands.
-H, --help
print the usage summary then exit.
-i, --in=FN
reads the log page contents from file FN (or stdin if FN is '-'). This is used for the LOG SELECT command. The data read from FN is placed in the data-out buffer and the length of the data is placed in the Parameter list length field.
-I, --inhex=FN
reads the log page contents from file FN (or stdin if FN is '-'). This is used for the LOG SENSE command. The data read from FN is placed in the data-in buffer and the length of the data is placed in the Allocation length field.
-l, --list
lists the names of all log pages supported by this DEVICE. Defaults to listing pages only. If used twice, lists pages and subpages.
-m, --maxlen=LEN
request only LEN bytes of response data. Default is 0 which is interpreted as all that is available. LEN is decimal unless it has a leading '0x' or trailing 'h'.
-n, --name
outputs the name of the log page in addition to the decoded output. This option is ignored if the log page name is not known to this utility.
-O, --old
use the older command line options (from sg3_utils version 1.22 and earlier). This option must be the first one on the command line.
-p, --page=PG
where PG is the log page number. It defaults to 0x00. It can be given as a decimal number or a hex number (prefixed with '0x' or suffixed with 'h').
-P, --pdt=PDT
where PDT is the 'Primary Device Type' (e.g. 0 for disk). This option is mainly for use with the --enumerate option.
-r, --reset
sets the PCR (Parameter Code Reset) bit in the CDB. This causes the parameters to be reset to their vendor specific defaults. This option is only active for the LOG SELECT command.
-s, --select
issue a LOG SELECT command instead of the default LOG SENSE command. This option is required to issue a LOG SELECT command.
-S, --sp
sets the SP (Save Pointers) bit in the CDB. This causes the LOG SELECT command to save the current log page parameters (as indicated by the DS and TSD parameter codes) in some non-volatile location. Hence the log parameters will be preserved across power cycles. This option is typically not needed, especially if the GLTSD flag is clear in the control mode page which causes the DEVICE to periodically save all saveable log parameters to non-volatile storage.
-t, --temperature
outputs the temperature. First looks in the temperature log page and if that is not available tries the Informational Exceptions log page which may also have the current temperature (especially on older disks).
-T, --transport
outputs the transport ('Protocol specific port') log page. Equivalent to setting '--page=18h'.
-u, --undefined
to see fields decoded, the --hex option cannot be used. However some fields are not defined in the T10 documents and in that case they are output in hex. This option controls the format of 'undefined' fields when they output in hex. Multiple uses of this option has the same sense as the --hex option. For example '-uu' will output undefined fields in hexadecimal with an ASCII rendering to the right of each line.
-M, --vendor=VP
where VP is a vendor/manufacturer (e.g. "sea" for Seagate) or product (group) acronym (e.g. "lto5" for the 5th generation LTO (tape) consortium). Either the whole log page is vendor specific (e.g. page numbers 0x30 to 0x3f) or part of a T10 defined log page is vendor specific. For example SPC-5 defines parameter code 0x0 of page 0x2f (the Informational Exceptions log page) and states that the remaining parameter codes (i.e. 0x1 to 0xffff) are vendor specific. Using a VP of "xxx" will list the available acronyms.
If this option is used with --page=PG and PG is an acronym then this option is ignored. If PG is a number (e.g. 0xc0) then VP is used to choose the which vendor specific page (e.g. sharing page number 0xc0) to decode.
-v, --verbose
increase level of verbosity. When used with --enumerate, in the list of known log page names, those that have no associated decode logic are followed by "[hex only]".
-V, --version
print out version string then exit.

SÉLECTION DU JOURNAL

La commande SCSI LOG SELECT peut être utilisée pour réinitialiser certains paramètres aux valeurs par défaut spécifiques au fournisseur, les enregistrer dans un stockage non volatile (c'est-à-dire le média), ou fournir un nouveau contenu de page. Cette commande a été modifiée entre SPC-3 et SPC-4 avec l'ajout des champs Code de page et Sous-page qui ne peuvent être que non nuls lorsque la longueur de la liste de paramètres est nulle.

L'option --select (ou --reset) est requise pour émettre une commande LOG SELECT. Si l'option --in=FN n'est pas donnée (ou si FN est effectivement vide), la longueur de la liste de paramètres est définie à zéro. Si l'option --in=FN est donnée, ses données décodées sont placées dans le tampon de sortie de données et sa longueur en octets est placée dans le champ Longueur de la liste de paramètres.

Les autres options actives avec la commande LOG SELECT sont --control=PC, --reset (qui définit le bit PCR) et --sp.

CLIENT APPLICATION

C'est le nom d'une page de journal qui sert de conteneur pour les données fournies par l'utilisateur. Un client d'application est un terme SCSI pour le programme qui émet des commandes à un initiateur SCSI (souvent connu sous le nom de carte hôte (HBA)). Ainsi, par exemple, cet utilitaire est un client d'application SCSI.

La page de journal du client d'application a 64 paramètres de journal avec des codes de paramètres 0 à 63. Chacun peut contenir 252 octets de données binaires utilisateur. Ces 252 octets (ou moins) de données utilisateur, avec un préfixe de 4 octets (pour un total de 256 octets), peuvent être fournis avec l'option --in=FN. Un préfixe typique serait '0,n,83,fc'. Le "n" est le code du paramètre en hexadécimal, donc le dernier paramètre de journal serait '0,3f,83,fc'. Ce paramètre de journal pourrait être lu à nouveau plus tard avec '--page=0xf --filter=0x<n>' .

EN HEXADÉCIMAL AU LIEU DE L'APPAREIL

Cette section s'applique lorsque l'option --inhex=FN est utilisée et qu'il n'y a pas d'argument DEVICE. Ceci peut être considéré comme une fonction de relecture où le fichier FN a été créé par une invocation antérieure de cet utilitaire, très probablement avec l'option '-HHHHH', la redirection de la sortie de la ligne de commande étant utilisée pour créer FN.

Si l'option --all est donnée une fois, toutes les pages (mais pas les sous-pages) trouvées dans FN seront décodées, ou affichées en hexadécimal si cet utilitaire ne peut pas en décoder certaines. Si l'option --all est donnée deux fois ou plus, toutes les pages et sous-pages trouvées dans FN seront décodées. Dans les deux cas, les pages sont décodées dans l'ordre où elles sont trouvées dans FN.

Ensuite, si l'option --page=PG est donnée, alors FN est recherché pour une correspondance avec PG et, si trouvée, cette page de journal (sous-page) est décodée. Si l'option --list est donnée une fois, la page de journal "Supported log pages" [0x0,0x0] est décodée, si elle est présente. Si l'option --list est donnée deux fois ou plus, la page "Supported Log Pages and Subpages" [0x0,0xff] est décodée, si elle est présente.

Si aucune des options de sélection ci-dessus n'est donnée, cet utilitaire tentera de décoder la première page de journal trouvée dans FN. S'il y a d'autres pages de journal après la première dans FN, elles sont ignorées.

NOTES

Cet utilitaire effectuera généralement une double lecture des pages de journal avec la commande SCSI LOG SENSE. La première lecture demande une réponse de 4 octets (c'est-à-dire placer 4 dans le champ "longueur d'allocation" dans le cdb). À partir de cette réponse, il peut calculer la longueur réelle de la réponse, ce qu'il demande lors de la deuxième lecture. C'est une pratique typique en SCSI et garantie de fonctionner dans les normes. Cependant, certains anciens appareils ne sont pas conformes. Pour ces appareils, l'utilisation de l'option --maxlen=LEN effectuera une seule lecture. Une valeur de 252 devrait être un point de départ sûr.

Diverses pages de journal contiennent des informations sur les taux d'erreur, la température de l'appareil, les cycles de démarrage/arrêt depuis la production de l'appareil et les résultats des 20 derniers auto-tests. Les auto-tests peuvent être initiés par l'utilitaire sg_senddiag(8). Le paquet smartmontools fournit une grande partie des informations trouvées avec sg_logs sous une forme adaptée à la surveillance de la santé des disques et lecteurs de bandes SCSI.

La manière la plus simple de trouver quelles pages de journal peuvent être décodées par cet utilitaire est d'utiliser l'option --enumerate. Certains noms de page sont connus mais il n'y a pas de logique de décodage ; ces cas ont "[hex only]" après le nom de la page de journal lorsque l'option --verbose est utilisée avec --enumerate.

Les fournisseurs sont spécifiquement autorisés par SPC-6 à ne *pas* rapporter toutes les pages et sous-pages prises en charge par un appareil. Cela affaiblit l'utilité des pages qui rapportent une liste des pages et sous-pages prises en charge. Une garantie est donnée que les pages rapportées seront dans l'ordre croissant.

STATUT DE SORTIE

Le statut de sortie de sg_logs est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE ANTÉRIEURES

NAME

sg_logs - read log pages from a SCSI device

SYNOPSIS

sg_logs [-a] [-N] [-p=PG] [-paramp=PP] [-pcb] [-ppc] [-r] [-R] [-select] [-sp] [-t] [-T] [-v] [-V] [-x] [-?] DEVICE

DESCRIPTION

This utility, for SCSI devices, reads one or more log pages (using the LOG SENSE command) and outputs them. By default it reads all log pages and prints them out in a hex dump format. It can also be instructed to interpret and print certain log pages in a more human readable format.

The DEVICE is typically a block device name such as /dev/sda or /dev/sg0.

OPTIONS

Attempt to interpret the supplied LOG SENSE response. Supported interpretations are for the pages: 0, 1, 3, 8, b, c, 10h, 11h and depending on the device, others.

-a
Output all known log pages. By default, only the first 128 log pages are requested. Some devices might not implement all of these.
-N, --new
Switch to the newer style options.
-p=PG
log page code to access. PG is either an acronym, a page number, or a page, subpage pair. Available acronyms can be listed with the --enumerate option. Page (0 to 3f) and subpage (0 to ff) numbers are comma separated. The numbers are assumed to be hexadecimal.
-paramp=PP
PP is the parameter pointer value (in hex) to place in command. Should be a number between 0 and ffff inclusive.
-pcb
show Parameter Control Byte settings (only relevant when log parameters being output in ASCII).
-ppc
sets the Parameter Pointer Control (PPC) bit. Default is 0 (i.e. cleared).
-r
use SCSI LOG SELECT command (PCR bit set) to reset the all log pages (or the given page). Equivalent to --reset in the main description.
-R
Equivalent to --readonly in the main description.
-select
use a LOG SELECT command. Equivalent to --select in the main description.
-sp
sets the Saving Parameters (SP) bit. Default is 0 (i.e. cleared). Equivalent to --sp in the main description.
-t
outputs the temperature. Equivalent to --temperature in the main description.
-T
outputs the transport ('Protocol specific port') log page. Equivalent to --transport in the main description.
-v
increase level of verbosity.
-V
print out version string then exit.
-x
suppress the INQUIRY command. Equivalent to --no_inq in the main description.
-?
output usage message then exit.

LOG SELECT

The LOG SELECT command is used to modify settings within log pages. The -select option causes the LOG SELECT command to be used instead of the LOG SENSE command. The -sp and -ppc options set bits within the command. The -paramp option provides a value (pointer) that will be placed in the command.

APPLICATION CLIENT

Some SCSI devices have an "Application Client" log page (page code 0x0) which is used to control application specific clients. The default output for this page lists the clients currently active. The -pcb option can be used to see the Parameter Control Byte settings. The -paramp option can be used to set a parameter pointer, and the -sp option can be used to set the Saving Parameters bit.

INHEX INSTEAD OF DEVICE

Since sg3_utils version 1.27, an alternative to specifying a DEVICE is to specify a hexadecimal number in the range 0 to 65535. This implies that the command should be sent via the sg_simple_send_scsi_cmd utility (which has its own set of options and is usually run as root). This is useful for scripting when the specific device name might change between runs.

NOTES

Some log pages are very verbose and may scroll off the screen. Using a pager like less is recommended.

Some log pages, especially those related to temperature, may not be implemented on all devices.

EXIT STATUS

Exits with 0 on success, non-zero on failure. See the sg3_utils(8) man page for a list of exit codes.

OLDER COMMAND LINE OPTIONS

The options -a, -p, -r, -R, -t, -T, -x, and -? are the older style options (pre sg3_utils version 1.27). They are still supported but the newer style options like --all, --page, --reset, --readonly, --temperature, --transport, --no_inq and --help are preferred. The -N option switches to the newer style options.

-N, --new
Switch to the newer style options.
-p=PG
log page code to access. PG is either an acronym, a page number, or a page, subpage pair. Available acronyms can be listed with the --enumerate option. Page (0 to 3f) and subpage (0 to ff) numbers are comma separated. The numbers are assumed to be hexadecimal.
-paramp=PP

-pcb

-ppc

-R

-select
use a LOG SELECT command. Equivalent to --select in the main description.
-sp

-t
outputs the temperature. Equivalent to --temperature in the main description.
-T
outputs the transport ('Protocol specific port') log page. Equivalent to --transport in the main description.
-v
increase level of verbosity.
-V

-x

-?

ENVIRONMENT VARIABLES

Since sg3_utils version 1.23 the environment variable SG3_UTILS_OLD_OPTS can be given. When it is present this utility will expect the older command line options. So the presence of this environment variable is equivalent to using --old (or -O) as the first command line option.
