sg_get_disk_io_stats(3) sg_get_disk_io_stats(3)

NOM

sg_get_disk_io_stats, sg_get_disk_io_stats_r, sg_get_disk_io_stats_diff, sg_get_disk_io_stats_diff_between, sg_free_disk_io_stats, sg_disk_io_compare_name, sg_disk_io_compare_traffic - obtenir les statistiques d'E/S disque

SYNTAXE

#include <statgrab.h>


sg_disk_io_stats *sg_get_disk_io_stats
(size_t *entries);


sg_disk_io_stats *sg_get_disk_io_stats_r
(size_t *entries);


sg_disk_io_stats *sg_get_disk_io_stats_diff
(size_t *entries);


sg_disk_io_stats *sg_get_disk_io_stats_diff_between
(const sg_disk_io_stats *cur, const sg_disk_io_stats *last, size_t *entries);


sg_error sg_free_disk_io_stats
(sg_disk_io_stats *data);


int sg_disk_io_compare_name
(const void *va, const void *vb);


int sg_disk_io_compare_traffic
(const void *va, const void *vb);

DESCRIPTION

Les fonctions sg_get_disk_io_stats fournissent des statistiques d'E/S disque par disque. Toutes les fonctions get et diff prennent un paramètre entries optionnel, qui pointe (lorsqu'il est fourni) vers une variable de type size_t pour recevoir le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_disk_io_stats() et sg_get_disk_io_stats_r() fournissent les statistiques d'E/S depuis que le disque a été connecté au système. Les fonctions sg_get_disk_io_stats_diff() et sg_get_disk_io_stats_diff_between() fournissent la différence entre deux appels à sg_get_disk_io_stats() ou sg_get_disk_io_stats_r(), respectivement.

Raccourci API

fonction retourne propriétaire des données
sg_get_disk_io_stats sg_disk_io_stats * libstatgrab (local au thread)
sg_get_disk_io_stats_r sg_disk_io_stats * l'appelant
sg_get_disk_io_stats_diff sg_disk_io_stats * libstatgrab (local au thread)
sg_get_disk_io_stats_diff_between sg_disk_io_stats * l'appelant

Les vecteurs sg_disk_io_stats obtenus de sg_get_disk_io_stats_r() ou sg_get_disk_io_stats_diff_between() doivent être libérés avec sg_free_disk_io_stats() lorsqu'ils ne sont plus nécessaires. L'appelant en est responsable.

De plus, deux fonctions d'assistance pour qsort(3) sont disponibles : sg_disk_io_compare_name() et sg_disk_io_compare_traffic().

Exemple

size_t entries;
sg_disk_io_stats *io_stats = NULL;
while( NULL != ( io_stats = sg_get_disk_io_stats_diff(&entries) ) ) {
    /* afficher les disques avec le plus de trafic en premier */
    qsort( io_stats, entries, sizeof(io_stats[0]), &sg_disk_io_compare_traffic );
    show_disk_io_stats( io_stats );
}

Sur certaines plateformes, comme Solaris 7, la valeur du noyau est stockée dans un entier 32 bits, donc elle se réinitialise lorsqu'elle atteint 4 Go. D'autres plateformes, comme Solaris 8 (et la plupart des autres systèmes modernes), stockent la valeur dans un entier 64 bits, qui se réinitialise autour de 17 millions de téraoctets. Les fonctions sg_get_disk_io_stats_diff() et sg_get_disk_io_stats_diff_between() tiennent compte de ces dépassements et tentent de les détecter lors du calcul de la différence.

Sur Solaris, libstatgrab tentera d'obtenir la représentation cXtXdXsX pour la chaîne disk_name. Si cela échoue, il utilisera un nom tel que sd0. Sur certains systèmes, les programmes appelant libstatgrab auront besoin de privilèges élevés pour rechercher certains noms. Les correspondances sont construites lorsque sg_init() est appelé pour la première fois.

VALEURS DE RETOUR

Toutes les statistiques d'E/S disque retournent un pointeur vers une structure de type sg_disk_io_stats.

typedef struct {
        char *disk_name;
        unsigned long long read_bytes;
        unsigned long long write_bytes;
        time_t systime;
} sg_disk_io_stats;
disk_name
Le nom connu du système d'exploitation. (par exemple, sous linux, il pourrait s'agir de hda)
read_bytes
Le nombre d'octets lus par le disque.
write_bytes
Le nombre d'octets écrits par le disque.
systime
La période pendant laquelle read_bytes et write_bytes ont été transférés.

BOGUES

sg_get_disk_io_stats_diff et sg_get_disk_io_stats_diff_between comparent deux listes de statistiques d'E/S relatives aux disques (périphériques de bloc). Chaque entrée n'apparaissant que dans la seconde liste est transmise à la liste résultante comme si elle avait été comparée à une entrée avec toutes les valeurs de statistiques mises à 0. Cela implique que lors du tout premier appel, sg_get_disk_io_stats_diff retournera la même chose que sg_get_disk_io_stats.

Sur les systèmes d'exploitation qui ne disposent que de 32 bits de données, il y a un problème si les valeurs dépassent deux fois. Par exemple, sur Solaris 7, si 9 Go sont transférés et que le système d'exploitation se réinitialise à 4 Go, la fonction sg_get_disk_io_stats_diff() retournera 5 Go.

Les fonctions de comparaison existent plutôt pour la compatibilité ascendante que pour l'amélioration des fonctionnalités. La flexibilité limitée (par exemple, ordre inversé) et le manque d'opportunités d'optimisation pour le compilateur conduisent à recommander d'implémenter les routines de comparaison requises localement.
