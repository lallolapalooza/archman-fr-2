NOM

sg_rbuf - lit des données avec la commande SCSI READ BUFFER

SYNTAXE

sg_rbuf [--buffer=EACH] [--dio] [--help] [--mmap] [--quick] [--size=OVERALL] [--verbose] [--version] PÉRIPHÉRIQUE

sg_rbuf [-b=EACH_KIB] [-d] [-m] [-q] [-s=OVERALL_MIB] [-t] [-v] [-V] PÉRIPHÉRIQUE

DESCRIPTION

Cette commande lit des données avec la commande SCSI READ BUFFER puis les ignore. Généralement, les données lues proviennent du cache mémoire d'un disque. On suppose que les données sont sourcées rapidement (bien que cela ne soit pas garanti par les normes SCSI) de sorte qu'elles soient plus rapides que la lecture des données depuis le support physique. Cette commande est conçue pour chronométrer les vitesses de transfert sur un transport SCSI.

Pour récupérer les données avec une commande SCSI READ BUFFER et les décoder éventuellement, consultez l'utilitaire sg_read_buffer. Il existe également un utilitaire sg_write_buffer utile pour télécharger le firmware, entre autres choses.

Cet utilitaire ne fonctionne que sous Linux et uniquement lorsque PÉRIPHÉRIQUE est un périphérique sg (par exemple, "/dev/sg1"). L'utilitaire sg_read_buffer a une fonctionnalité similaire et est porté sur d'autres systèmes d'exploitation, et sous Linux peut utiliser des noms de périphériques bsg et normaux (par exemple, "/dev/sdc").

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-b, --buffer=EACH
où EACH est le nombre d'octets à transférer par chaque commande READ BUFFER. La valeur par défaut est la taille réelle du tampon disponible retournée par la commande READ BUFFER (descriptor). Le maximum est le même que la valeur par défaut, donc cet argument ne peut être utilisé que pour réduire la taille de chaque transfert à moins de la taille réelle du tampon disponible du périphérique.
-d, --dio
utilise l'IO directe si disponible. Cette option n'est disponible que si PÉRIPHÉRIQUE est un nœud de périphérique du pilote sg (par exemple /dev/sg1). Dans ce cas, le pilote sg tentera de configurer le DMA depuis la carte adaptateur SCSI pour transférer directement dans la mémoire utilisateur. Cela éliminera la copie via les tampons du noyau. Si ce n'est pas disponible, cela sera signalé et une IO indirecte sera effectuée à la place.
-h, --help
affiche le message d'utilisation puis quitte.
-m, --mmap
utilise l'IO mappée en mémoire si disponible. Cette option n'est disponible que si PÉRIPHÉRIQUE est un nœud de périphérique du pilote sg (par exemple /dev/sg1). Dans ce cas, le pilote sg tentera de configurer le DMA depuis la carte adaptateur SCSI pour transférer directement dans la mémoire utilisateur. Cela éliminera la copie via les tampons du noyau.
-O, --old
Passe aux options de style plus ancien. Veuillez l'utiliser comme première option.
-q, --quick
ne transfère les données que dans les tampons du noyau (généralement par DMA depuis la carte adaptateur SCSI) et ne les déplace pas dans l'espace utilisateur. Cette option n'est disponible que si PÉRIPHÉRIQUE est un nœud de périphérique du pilote sg (par exemple /dev/sg1).
-s, --size=OVERALL
où OVERALL est la taille du transfert total en octets. La valeur par défaut est 200 MiB (200*1024*1024 octets). Le nombre réel d'octets transférés peut être légèrement inférieur à ce qui est demandé car tous les transferts ont la même taille (et une division entière est impliquée, arrondie vers zéro).
-t, --time
chronomètre la composante de transfert de données en bloc de cette commande. Le temps écoulé est affiché ainsi qu'un calcul en Mo/sec. Dans ce cas, "Mo" représente 1 000 000 d'octets. L'appel système gettimeofday() est utilisé en interne pour le calcul du temps.
-v, --verbose
augmente le niveau de verbosité. Peut être utilisé plusieurs fois.
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Cette commande est généralement utilisée sur les disques SCSI modernes qui disposent d'un cache RAM dans leur électronique de lecteur. Si aucune IO vers le support magnétique, ou des périphériques plus lents comme la mémoire flash, n'est impliquée, alors le disque peut être capable de fournir des données assez rapidement pour saturer la bande passante du transport SCSI. Le goulot d'étranglement peut alors être l'élément DMA de la carte HBA, les pilotes Linux ou le matériel de la machine hôte (par exemple, la vitesse de la RAM).

Divers arguments numériques (par exemple, OVERALL) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section "ARGUMENTS NUMÉRIQUES" dans la page de manuel sg3_utils(8).

EXEMPLES

Sur le système de test, /dev/sg0 correspond à un disque rapide sur un bus SCSI U2W (max 80 Mo/sec). Les spécifications du disque indiquent que son cache est de 4 Mo.
$ time ./sg_rbuf /dev/sg0
READ BUFFER reports: buffer capacity=3434944,
offset boundary=6
Read 200 MiB (actual 199 MiB, 209531584 bytes),
buffer size=3354 KiB
real 0m5.072s, user 0m0.000s, sys 0m2.280s

Soit environ 40 Mo/sec avec une utilisation de 40 %. Maintenant, avec l'ajout de l'option "-q", ce débit s'améliore et l'utilisation tombe à 0 %.
$ time ./sg_rbuf -q /dev/sg0
READ BUFFER reports: buffer capacity=3434944,
offset boundary=6
Read 200 MiB (actual 199 MiB, 209531584 bytes),
buffer size=3354 KiB
real 0m2.784s, user 0m0.000s, sys 0m0.000s

STATUT DE SORTIE

Le statut de sortie de sg_rbuf est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE PLUS ANCIENNES

Les options de cette section étaient les seules disponibles avant la version 1.23 de sg3_utils. Depuis, cet utilitaire utilise par défaut les options de ligne de commande plus récentes qui peuvent être remplacées en utilisant --old (ou -O) comme première option. Voir la section VARIABLES D'ENVIRONNEMENT pour une autre façon de forcer l'utilisation de ces anciennes options de ligne de commande.

-b=EACH_KIB
où EACH_KIB est le nombre de Kilooctets (c'est-à-dire des unités de 1024 octets) à transférer par chaque commande READ BUFFER. Similaire à l'option --buffer=EACH dans la description principale, mais les unités sont différentes.
-d
utilise l'IO directe si disponible. Équivalent à l'option --dio dans la description principale.
-m
utilise l'IO mappée en mémoire si disponible. Équivalent à l'option --mmap dans la description principale.
-N, --new
Passe aux options de style plus récent.
-q
ne transfère les données que dans les tampons du noyau (généralement par DMA depuis la carte adaptateur SCSI) et ne les déplace pas dans l'espace utilisateur. Équivalent à l'option --quick dans la description principale.
-s=OVERALL_MIB
où OVERALL_MIB est la taille du transfert total en Mégaoctets (1048576 octets). Similaire à l'option --size=OVERALL dans la description principale, mais les unités sont différentes.
-t
chronomètre la composante de transfert de données en bloc de cette commande. Équivalent à l'option --time dans la description principale.
-v
augmente le niveau de verbosité. Peut être utilisé plusieurs fois.
-V
affiche la chaîne de version puis quitte.

VARIABLES D'ENVIRONNEMENT

Depuis la version 1.23 de sg3_utils, la variable d'environnement SG3_UTILS

_OLD_OPTS peut être donné. Lorsqu'il est présent, cet utilitaire s'attendra aux anciennes options de ligne de commande. Ainsi, la présence de cette variable d'environnement équivaut à utiliser --old (ou -O) comme première option de ligne de commande.
