NOM

sg_vpd - récupérer une page VPD et/ou décoder sa réponse

SYNTAXE

sg_vpd [--all] [--enumerate] [--examine] [--force] [--help] [--hex] [--ident] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--long] [--maxlen=LEN] [--page=PG] [--quiet] [--raw] [--sinq_inraw=RFN] [--vendor=VP] [--verbose] [--version] [PÉRIPHÉRIQUE]

DESCRIPTION

Cet utilitaire, lorsqu'un PÉRIPHÉRIQUE est spécifié, récupère une page de données produit vitales (VPD) et la décode, ou l'affiche en hexadécimal ASCII ou en binaire. Les pages VPD sont récupérées avec une commande SCSI INQUIRY.

Alternativement, l'option --inhex=FN peut être spécifiée. Dans ce cas, FN est présumé être un nom de fichier ('-' pour stdin) contenant de l'hexadécimal ASCII représentant une réponse de page VPD. Si l'option --raw est également spécifiée, l'entrée binaire est présumée (plutôt que l'hexadécimal ASCII).

La page la plus importante est probablement la page de données d'identification du périphérique VPD (numéro de page : 0x83). Depuis SPC-3, le support de cette page est obligatoire. Cette page peut être récupérée en utilisant l'option --ident.

Le document de référence utilisé pour interpréter les pages VPD (et la réponse standard INQUIRY) est T10/BSR INCITS 566 Révision 6 qui est un brouillon SPC-6 daté du 22 octobre 2021. Il peut être trouvé sur https://www.t10.org .

Lorsqu'aucune option n'est donnée, autre qu'un PÉRIPHÉRIQUE, alors la page VPD « Supported VPD pages » (0x0) est récupérée et décodée.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont arrangées par ordre alphabétique basé sur le nom de l'option longue.

-a, --all
décode toutes les pages VPD. Lorsqu'il est utilisé avec un PÉRIPHÉRIQUE, les pages à décoder se trouvent dans la page VPD « Supported VPD pages ». Les pages qui ne peuvent pas être décodées sont affichées en hexadécimal ; ajoutez l'option --long pour afficher du texte ASCII à droite de chaque ligne hexadécimale.
Si cette option est utilisée avec l'option --inhex=FN, alors le fichier FN est présumé contenir une ou plusieurs pages VPD (en hexadécimal ASCII ou binaire). Le décodage se poursuit jusqu'à l'épuisement du fichier (ou une erreur). Des vérifications de cohérence sont appliquées sur la longueur de chaque page VPD et sur l'ordre croissant des numéros de page VPD (requis par SPC-4), donc des données incorrectes peuvent être détectées.
Si l'option --page=PG est également donnée, alors aucune page VPD dont le numéro de page est supérieur à PG (ou son équivalent numérique) n'est décodée.
-e, --enumerate
liste les noms des pages VPD connues, d'abord les pages standard (c'est-à-dire celles définies par T10), puis les pages spécifiques au fournisseur. Chaque groupe est trié par ordre d'abréviation. Le PÉRIPHÉRIQUE et la plupart des autres options sont ignorés et cet utilitaire se termine après la liste des noms de pages VPD. Peut être utilisé conjointement avec --page=PG où PG est numérique. Si c'est le cas, il recherche les lignes récapitulatives de toutes les pages VPD dont le numéro correspond à PG. Peut être utilisé avec --vendor=VP pour limiter la sortie aux pages spécifiques connues du fournisseur pour le fournisseur/produit VP.
-E, --examine
balaye une partie ou tout l'espace VPD (numéros de page 0x0 à 0xff) et affiche toutes les pages trouvées. Si cette option est donnée une fois, le balayage commence à la page 0x80 ; si elle est donnée deux fois, le balayage commence à 0x0 ; et si elle est donnée trois fois, le balayage commence à 0xc0. Cette option ne tient pas compte du contenu de la page VPD 0x0 qui devrait contenir une liste de toutes les pages VPD supportées. Certains fournisseurs oublient soit de lister certaines pages standard, soit ne listent pas volontairement les pages spécifiques au fournisseur qui se trouvent dans la plage 0xc0 à 0xff.
Si l'option --page=PG n'est pas donnée, le balayage se termine à la page 0xff. Si l'option --page=PG est donnée, le balayage se termine à la page PG. Une vérification est effectuée avant le balayage pour s'assurer que la page de début est inférieure ou égale à la page de fin ; sinon, les numéros de page de début et de fin sont échangés.
L'utilitaire sdparm, qui liste les pages de mode et VPD, a également une option --examine avec une fonctionnalité similaire. Notez que T10 a modifié la plupart des pages qui listent les pages supportées (par exemple, les pages VPD, de mode et de journal ; les commandes supportées) pour ajouter les mots prudents « peuvent ou peuvent ne pas lister toutes... ».
-f, --force
En tant que vérification de cohérence, l'action normale lors de la récupération des pages VPD autres que la page 0x0 (la page VPD « Supported VPD pages ») est de récupérer d'abord la page 0x0 et seulement si la page demandée est parmi les pages supportées, alors de récupérer la page demandée.
Lorsque cette option est donnée, saute la vérification de la page VPD 0x0 avant d'accéder à la page VPD demandée. La vérification préalable de la page VPD 0x0 est connue pour planter certains périphériques USB, donc à utiliser avec précaution.
-h, --help
affiche le message d'aide résumant les options de la ligne de commande, puis se termine. Ignore PÉRIPHÉRIQUE si donné.
-H, --hex
affiche la page VPD demandée en hexadécimal ASCII. Peut être utilisé plusieurs fois, voir la section sur la page d'informations ATA vpd.
Pour générer une sortie adaptée pour être placée dans un fichier qui peut être utilisé par une invocation ultérieure avec l'option --inhex=FN, utilisez l'option '-HHHH' (par exemple, 'sg_vpd -p di -HHHH /dev/sg3 > dev_id.hex'). La raison pour laquelle '-HHHH' est utilisé est de signaler que de l'hexadécimal pur (sans autre texte ni décalages d'adresse) est envoyé à stdout.
-i, --ident
décode la page VPD d'identification du périphérique (0x83). Lorsqu'elle est utilisée une fois, cette option a le même effet que '--page=di'. Lorsqu'elle est utilisée deux fois, la forme courte du descripteur d'unité logique de la page VPD d'identification du périphérique est décodée. Dans ce dernier cas, cette option a le même effet que '--quiet --page=di_lu'.
-I, --inhex=FN
FN est attendu comme un nom de fichier (ou '-' pour stdin) contenant de l'hexadécimal ASCII ou du binaire représentant une réponse de page VPD (ou une INQUIRY standard). Cet utilitaire décodera alors cette réponse. Il est préférable de fournir également l'option --page=PG, sinon cet utilitaire tentera de deviner à quelle page VPD (ou INQUIRY standard) la réponse est associée. L'hexadécimal doit être disposé en 1 ou 2 chiffres représentant un octet chacun, séparés par des espaces blancs ou des virgules. Tout à partir d'un signe dièse (#) jusqu'à la fin de la ligne est ignoré. Si l'option --raw est également donnée, alors FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du format texte brut. Notez que les arguments de la forme courte et longue sont eux-mêmes optionnels et, s'ils sont présents, commencent par '=' sans espace blanc autorisé autour de ce '='.
Voir la page man sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO sur des valeurs non défaut.
-l, --long
lors du décodage de certaines pages VPD, donne un peu plus de sortie. Par exemple, la page d'informations ATA ne montre que la signature (en hexadécimal) et l'IDENTIFY (PACKET) DEVICE (en hexadécimal) lorsque cette option est donnée.
-m, --maxlen=LEN
où LEN est la longueur de réponse (maximale) en octets. Elle est placée dans le champ « allocation length » du cdb. Si elle n'est pas donnée (ou si LEN est zéro), 252 est utilisé (sauf pour la page d'informations ATA qui utilise par défaut 572) et, si la réponse indique que cette valeur est insuffisante, une autre commande INQUIRY est envoyée avec une valeur plus grande dans le champ « allocation length » du cdb. Si cette option est donnée et que LEN est supérieur à 0, alors une seule commande INQUIRY est envoyée. Comme de nombreux périphériques simples implémentent mal la commande INQUIRY (et ne supportent pas les pages VPD), la valeur la plus sûre est

OPTIONS

-p, --page=PG
où PG est la page VPD à décoder ou à afficher. L'argument PG peut être une abréviation, un nombre ou une paire de nombres/abréviations séparés par une virgule. Les abréviations de pages VPD peuvent être consultées en utilisant l'option --enumerate. Si un nombre est donné, il est supposé être décimal sauf s'il a un indicateur hexadécimal qui est soit un '0x' préfixé soit un 'h' suffixé. Si un seul nombre est donné, il est supposé être un numéro de page VPD. Si deux nombres (ou abréviations) sont donnés, le second est identique à VP (voir l'option --vendor=VP). Si cette option n'est pas donnée (ni '-i', '-l' ni '-V') alors la page VPD « Supported VPD pages » (0x0) est récupérée et décodée. Si PG est '-1' ou 'sinq', alors la réponse standard INQUIRY est affichée. Cette option peut également être utilisée avec l'option --enumerate (voir sa description).
Si PG n'est pas trouvé dans la page VPD 'Supported VPD pages' (0x0), alors EDOM est renvoyé. Pour contourner cette vérification, utilisez l'option --force.
-q, --quiet
supprime la quantité de décodage et de sorties d'erreur.
-r, --raw
si non utilisé avec --inhex=FN, affiche la page VPD demandée en binaire. La sortie doit être redirigée vers un fichier ou un autre utilitaire lorsque cette option est utilisée. Le binaire est envoyé à stdout et les erreurs à stderr.
si utilisé avec --inhex=FN, le contenu de FN est traité comme binaire.
-Q, --sinq_inraw=RFN
où RFN est un nom de fichier contenant des données binaires de réponse standard INQUIRY qui correspondent soit à DEVICE soit à FN. Linux place cette réponse standard INQUIRY dans son système de fichiers pseudo sysfs. Un emplacement typique est /sys/class/scsi_device/<hctl>/device/inquiry où <hctl> est un tuple numérique à quatre parties séparé par des deux-points. Ce tuple distingue le périphérique des autres sur le système. Linux place également certaines réponses de pages VPD en binaire dans le même répertoire avec des noms comme « vpd_pg83 » où les deux derniers chiffres forment le numéro hexadécimal de la page VPD dont le contenu binaire s'y trouve.
Certaines pages VPD (par exemple, la page VPD Extended Inquiry) dépendent de la connaissance des paramètres de la réponse standard INQUIRY pour interpréter les champs de cette page VPD. Cette option, conjointement avec --all, --examine ou --page=PG, permet à cet utilitaire de traiter à la fois la réponse standard INQUIRY et les pages VPD dans la même invocation.
L'option --raw n'a aucun effet sur cette option. L'argument DEVICE peut être fourni avec cette option.
-M, --vendor=VP
où VP est un acronyme de vendeur (par exemple, « sea » pour Seagate) ou de vendeur/produit (par exemple, « hp3par » pour le réseau 3PAR de HP). De nombreux vendeurs ont réutilisé les numéros au début de la plage des pages VPD spécifiques au vendeur (par exemple, page 0xc0) et cette option est un moyen de sélectionner uniquement ceux qui sont d'intérêt. L'utilisation d'un VP de « xxx » listera les acronymes disponibles.
Si cette option est utilisée avec --page=PG et que PG est une abréviation, cette option est ignorée. Si PG est un nombre (par exemple, 0xc0), alors VP est utilisé pour choisir quelle page spécifique au vendeur (par exemple, partageant le numéro de page 0xc0) décoder.
-v, --verbose
augmente le niveau de verbosité.
-V, --version
affiche la chaîne de version puis quitte.

PAGE VPD ATA INFORMATION

Cette page VPD (0x89 ou 'ai') est définie par la norme SCSI to ATA Translation. Elle contient des informations sur la couche SAT, la « signature » du périphérique ATA et la réponse à la commande ATA IDENTIFY (PACKET) DEVICE. Cette dernière partie contient 512 octets de données d'identité, de capacité et de configuration que l'utilitaire hdparm est capable de décoder (donc cet utilitaire ne les décode pas).

Pour désencombrer la sortie de cette page, la signature et la réponse IDENTIFY (PACKET) DEVICE ne sont pas affichées à moins que l'option --long (ou --hex ou --raw) ne soit donnée. Lorsque l'option --long est donnée, la réponse IDENTIFY (PACKET) DEVICE est affichée sous forme de 256 mots (16 bits) comme il est d'usage pour les périphériques ATA. Pour voir cette réponse sous forme d'une chaîne d'octets, utilisez l'option '-HH'. Pour formater la sortie de manière adaptée au décodage par hdparm, utilisez l'option '-HHH' ou '-rr'. Par exemple, si 'dev/sdb' est un disque SATA derrière une couche SAT, alors la commande : 'sg_vpd -p ai -HHH /dev/sdb | hdparm --Istdin' devrait décoder la réponse ATA IDENTIFY (PACKET) DEVICE.

NOTES

Comme certaines pages VPD (par exemple, la page Extended INQUIRY) dépendent des paramètres de la réponse standard INQUIRY, la réponse standard INQUIRY est affichée comme une pseudo page VPD lorsque PG est défini sur '-1' ou 'sinq'. De plus, le décodage de certains champs (par exemple, le champ SPT de la page Extended INQUIRY) est élargi lorsque l'option '--long' est donnée en utilisant les informations de la réponse standard INQUIRY (par exemple, les champs PDT et PROTECT).

Le DEVICE est ouvert avec un indicateur de lecture seule (par exemple, sous Unix avec l'indicateur O_RDONLY).

STATUT DE SORTIE

Le statut de sortie de sg_vpd est 0 en cas de succès. Sinon, voir la page man sg3_utils(8).

EXEMPLES

Les exemples de cette page utilisent des noms de périphériques Linux. Pour des noms de périphériques appropriés dans d'autres systèmes d'exploitation pris en charge, voir la page man sg3_utils(8).

Pour voir les pages VPD qu'un périphérique prend en charge, utilisez sans options. L'invocation de ligne de commande est indiquée d'abord, suivie d'une réponse typique :


# sg_vpd /dev/sdb
Supported VPD pages VPD page:
Supported VPD pages [sv]
Unit serial number [sn]
Device identification [di]
Extended inquiry data [ei]
Block limits (SBC) [bl]

Pour voir les numéros de page VPD associés à chaque page prise en charge, ajoutez l'option '--long' à la ligne de commande ci-dessus. Pour afficher une page VPD, son numéro ou son abréviation peuvent être donnés à l'option '--page='. Les abréviations de noms de page sont indiquées entre crochets ci-dessus. Dans l'exemple suivant, la page VPD Extended inquiry data est listée :


# sg_vpd --page=ei /dev/sdb
extended INQUIRY data VPD page:
ACTIVATE_MICROCODE=0 SPT=0 GRD_CHK=0 APP_CHK=0 REF_CHK=0
UASK_SUP=0 GROUP_SUP=0 PRIOR_SUP=0 HEADSUP=1 ORDSUP=1 SIMPSUP=1
WU_SUP=0 CRD_SUP=0 NV_SUP=0 V_SUP=0
P_I_I_SUP=0 LUICLR=0 R_SUP=0 CBCS=0
Multi I_T nexus microcode download=0
Extended self-test completion minutes=0
POA_SUP=0 HRA_SUP=0 VSA_SUP=0

Pour vérifier si des types de protection sont pris en charge par un disque, utilisez l'option '--long' sur la page VPD Extended inquiry data :


# sg_vpd --page=ei --long /dev/sdb
extended INQUIRY data VPD page:
ACTIVATE_MICROCODE=0
SPT=1 [protection types 1 and 2 supported]
GRD_CHK=1
....

Rechercher le nom (et l'acronyme) de toutes les pages qui partagent le numéro de page VPD 0xb0.


# sg_vpd --page=0xb0 --enumerate
Matching standard VPD pages:
bl 0xb0 Block limits (SBC)
oi 0xb0 OSD information
sad 0xb0 Sequential access device capabilities (SSC)

Quelques exemples suivent en utilisant l'option « --all ». Envoyer une représentation hexadécimale ASCII de toutes les pages VPD dans un fichier :


# sg_vpd --all -HHHH /dev/sg3 > all_vpds.hex

Plus tard, ce fichier pourrait être décodé avec :


# sg_vpd --all --inhex=all_vpds.hex

Pour faire l'équivalent de l'exemple précédent mais en utilisant un fichier contenant du binaire :


# sg_vpd --all --raw /dev/sg3 > all_vpds.bin
# sg_vpd --all --raw --inhex=all_vpds.bin

Notez que « --raw » doit être donné avec la seconde invocation (--inhex) pour avertir l'utilitaire que all_vpds.bin contient du binaire, car il suppose par défaut de l'hexadécimal ASCII. Ensuite, nous décodons uniquement les pages VPD spécifiées par T10 en excluant les pages VPD spécifiques au vendeur qui commencent à la page numéro 0xc0 :


# sg_vpd --all --page=0xbf --raw --inhex=all_vpds.bin

Sous Linux, des images binaires de certaines réponses de pages VPD importantes (par exemple, 0, 80h et 83h) sont mises en cache dans des fichiers au sein du système de fichiers pseudo sysfs. Étant donné que les pages VPD changent rarement de contenu, le décodage de ces fichiers donnera le même résultat que la sonde du périphérique avec l'avantage supplémentaire que le décodage de ces fichiers ne nécessite pas de permissions root. Les formes longues et courtes sont indiquées :


sg_vpd --raw --inhex=/sys/class/scsi_generic/sg3/device/vpd_pg83


sg_vpd -rI /sys/class/scsi_generic/sg3/device/vpd_pg83

Si /dev/sg3 est un disque à 2:0:0:0, alors cette invocation donnera une sortie plus détaillée mais essentiellement la même que les deux exemples précédents.


sg_vpd -v -r -I /sys/class/scsi_disk/2:0:0:0/device/vpd_pg83

D'autres exemples peuvent être trouvés sur la page web https://sg.danny.cz/sg/sg3_utils.html.
