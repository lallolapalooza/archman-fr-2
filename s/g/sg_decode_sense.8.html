NOM

sg_decode_sense - décode les données de sens SCSI et connexes

SYNTAXE

sg_decode_sense [--binaire=BFN] [--cdb] [--err=ES] [--fichier=HFN] [--aide] [--hex] [--inhex=HFN] [--ignorer-premier] [--json[=JO]] [--js-fichier=JFN] [--nodecode] [--nospace] [--statut=SS] [--verbeux] [--version] [--ecrire=WFN] [H1 H2 H3 ...]

DESCRIPTION

Cet utilitaire prend les données de sens SCSI en binaire ou sous forme d'une séquence d'octets hexadécimaux ASCII et les décode. La référence principale pour le décodage est SPC-5 ANSI INCITS 502-2020 et la dernière révision SPC-6, qui peuvent être trouvées sur https://www.t10.org et d'autres emplacements sur Internet.

Les données de sens SCSI se trouvent souvent dans les fichiers journaux du noyau à la suite d'un problème ou peuvent être un avertissement informatif. Elles sont souvent présentées sous forme d'une séquence d'octets hexadécimaux, commençant par 70, 71, 72, 73, f0 ou f1. Les données de sens peuvent avoir jusqu'à 252 octets de long, mais sont généralement beaucoup plus courtes, 18 octets étant fréquents et généralement associés au format plus ancien de données de sens « fixes ».

Les données de sens peuvent être fournies sur la ligne de commande ou dans un fichier. Si elles sont données sur la ligne de commande, les données de sens doivent être une séquence d'octets hexadécimaux séparés par des espaces. Alternativement, un fichier peut être fourni avec son contenu en octets binaires ou hexadécimaux ASCII. Ce dernier format peut contenir plusieurs lignes, chacune avec aucun, un ou plusieurs octets hexadécimaux ASCII séparés par des espaces (virgules ou tabulations). Le symbole dièse (#) peut apparaître et il, ainsi que le reste de la ligne, est ignoré, ce qui le rend utile pour les commentaires.

Si l'option --cdb est donnée, alors au lieu de considérer les arguments hexadécimaux donnés comme des données de sens, ils sont considérés comme un bloc de descripteur de commande SCSI (CDB). Dans ce cas, le nom de la commande est imprimé. Ce nom est basé sur le premier octet hexadécimal donné (connu sous le nom d'opcode) et éventuellement sur un autre champ appelé « service action ».

Une autre action alternative est lorsque l'option --err=ES est donnée. ES est supposé être une « valeur de statut de sortie » entre 0 et 255 provenant de l'une des utilitaires de ce paquet. Une chaîne descriptive est imprimée. Les autres options sont ignorées sauf --verbeux.

Lorsque l'option --nodecode est donnée, cet utilitaire peut être utilisé pour convertir un fichier binaire en hexadécimal ou vice versa. Les données converties n'ont pas besoin d'être liées aux données de sens SCSI ni aux CDB.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-b, --binaire=BFN
les données sont lues en binaire à partir d'un fichier appelé BFN. L'option ne peut pas être donnée avec --fichier=HFN ou --inhex=HFN car elles sont contradictoires. Les données sont supposées être des données de sens, sauf si l'option --nodecode est donnée.
-c, --cdb
traiter la chaîne d'arguments hexadécimaux donnée comme des octets dans un CDB SCSI et décoder le nom de la commande.
-e, --err=ES
ES doit être une « valeur de statut de sortie » entre 0 et 255 disponible depuis le shell (c'est-à-dire le contexte d'exécution de l'utilitaire) après la fin de l'exécution de l'utilitaire. Par défaut, un message d'erreur indicatif est imprimé sur stdout ; et si l'option --verbeux est donnée une fois (ou un nombre impair de fois), le message est imprimé sur stderr. Si --verbeux est donné deux fois ou plus, une forme plus longue du message est affichée. Dans tous les cas, le message a moins de 128 caractères avec un retour à la ligne final. Toutes les autres options et arguments de la ligne de commande sont ignorés.
-f, --fichier=HFN
les données de sens sont lues en hexadécimal ASCII à partir d'un fichier appelé HFN. Les données de sens doivent apparaître comme une séquence d'octets séparés par des espaces, des virgules, des tabulations, des tirets ou des retours à la ligne. Tout à partir du symbole dièse (#) et jusqu'à la fin de cette ligne est ignoré. Si --nospace est activé, aucun séparateur n'est requis entre les chiffres hexadécimaux ASCII dans HFN, les octets étant décodés à partir de paires de chiffres hexadécimaux ASCII.
-h, --aide
afficher le message d'utilisation puis quitter.
-H, --hex
cette option est utilisée une fois conjointement avec --ecrire=WFN afin de modifier la sortie écrite dans WFN en lignes d'octets hex ASCII appropriées pour un compilateur C. Chaque ligne contient jusqu'à 16 octets (par exemple, une ligne commençant par "0x3b,0x07,0x00,0xff").
Dans d'autres cas (c'est-à-dire lorsque --ecrire=WFN n'est pas donnée, ou que cette option est donnée plus d'une fois), la sortie est telle que décrite dans la page de manuel de sg3_utils(8).
La combinaison de --inhex=HFN et de cette option utilisée trois fois peut être utile pour convertir des octets hexadécimaux (par exemple, séparés par des tirets) dans une forme plus régulière. La forme courte de l'option est plus pratique pour invoquer cette option trois fois (par exemple, '-HHH').
-i, --inhex=HFN
même action que --fichier=HFN. Cette option a été ajoutée pour la compatibilité avec d'autres utilitaires de ce paquet qui ont une option --inhex=.
-I, --ignorer-premier
de nombreux programmes qui affichent des octets hexadécimaux (par exemple, 'hexdump -C') ont un compteur courant (ou index) dans la première colonne de chaque ligne. Cette option ignore la première valeur hexadécimale de chaque ligne. Cette option n'a aucun effet si --binaire=BFN ou --nospace sont donnés. Les lignes vides et tout caractère à partir de "#" et après sur une ligne sont ignorés. Utile avec les options --fichier=HFN et --nodecode.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du format texte brut. Notez que les arguments des formes courte et longue sont eux-mêmes optionnels et s'ils sont présents commencent par "=" et aucun espace n'est permis autour de ce "=".
Voir la page de manuel sg3_utils_json ou utiliser '?' pour JO pour obtenir un résumé.
-J, --js-fichier=JFN
la sortie est au format JSON et elle est envoyée dans un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée sur stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non défaut.
-N, --nodecode
Ne pas décoder les données fournies comme sens ou cdb. Utile lorsque des données arbitraires sont fournies (par exemple, lors de la conversion de hex en binaire ou vice versa).
-n, --nospace
attendre des octets hexadécimaux ASCII sous forme d'une chaîne de chiffres hexadécimaux sans espaces entre eux. Les octets sont décodés en prenant deux chiffres hexadécimaux à la fois, donc un nombre pair de chiffres est attendu. La chaîne de chiffres hexadécimaux peut être sur la ligne de commande (en remplacement de "H1 H2 H3") ou répartie sur plusieurs lignes dans le fichier HFN donné à --fichier=. Sur la ligne de commande, les espaces (ou autres caractères d'espacement) entre les séquences de chiffres hexadécimaux sont ignorés ; la longueur maximale de la chaîne hex sur la ligne de commande est de 1023 caractères.
-s, --statut=SS
où SS est une valeur d'octet de statut SCSI, donnée en hexadécimal. L'octet de statut SCSI est lié, mais distinct, des données de sens.
-v, --verbeux
augmenter le degré de verbosité (messages de débogage).
-V, --version
afficher la chaîne de version puis quitter.
-w, --ecrire=WFN
écrit les données de sens dans un fichier appelé WFN. Si nécessaire, WFN est créé. Si WFN existe, il est tronqué avant que les données de sens n'y soient écrites. Si l'option --hex est également donnée, alors de l'hex ASCII est écrit dans WFN (voir la description de l'option --hex) ; sinon, du binaire est écrit dans WFN. Cette option est une commodité et peut être utile pour convertir la représentation hexadécimale ASCII des données de sens (ou de tout autre chose) en l'équivalent binaire ou en une forme hexadécimale ASCII compilable.

EXEMPLES

Pour décoder les données de sens suivantes qui ont été trouvées dans un journal du noyau:

    Sense data: f0 00 01 00 00 00 00 0a 00 00 00 00 24 00 00 00 00 00

entrer:

    sg_decode_sense f0 00 01 00 00 00 00 0a 00 00 00 00 24 00 00 00 00 00

ce qui donnera une sortie similaire à:

    Inquiry data - not sense data

Ce qui montre que l'utilitaire a reconnu les données comme une réponse d'Inquiry plutôt que des données de sens. Pour forcer la sortie en tant que données de sens, il faut utiliser l'option --nodecode.

Pour décoder une réponse d'Inquiry hexadécimale de 36 octets à partir d'un fichier appelé inq.txt:

    sg_decode_sense --file=inq.txt --nodecode

Pour décoder la même réponse d'Inquiry en utilisant des octets hexadécimaux ASCII dans le fichier (par exemple, des lignes comme 0x00 0x01 0x00 0x00):

    sg_decode_sense --file=inq.txt --nodecode

Pour afficher le nom d'une commande SCSI (CDB) à partir de ses octets hexadécimaux ASCII:

    sg_decode_sense --cdb 0x28 0x00 0x01 0x58 0x00 0x00 0x00 0x00 0x08 0x00

ce qui donne une sortie similaire à:

    SCSI READ (10) command CDB, length 10 bytes

SORTIE

La sortie peut être envoyée sur stdout ou sur un fichier spécifié par l'option --js-fichier=JFN. Par défaut, la sortie est au format texte lisible par l'homme. Si l'option --json est utilisée, la sortie est au format JSON.

EFFETS DE BORD

L'option --err=ES fait que l'utilitaire imprime un message sur stdout (ou stderr si --verbeux est utilisé) et se termine avec le statut spécifié. Toutes les autres options et arguments sont ignorés.

sg_decode_sense(8) — sg3_utils — Légendes du système Arch Linux

NOM

sg_decode_sense — décode les données de sens SCSI et détaille les champs.

SYNOPSIS

sg_decode_sense [OPTION]… [SENSE_DATA…]

DESCRIPTION

Décode et affiche le contenu détaillé de données de sens SCSI. Les données de sens peuvent être fournies sous forme de chaîne hexadécimale sur la ligne de commande ou dans un fichier binaire ou hexadécimal.

Si aucun argument de données de sens n'est fourni, sg_decode_sense tente de les lire à partir de l'entrée standard.

Les données de sens sont généralement obtenues en envoyant une commande `SCSI INQUIRY` ou `TEST UNIT READY`, ou lorsqu'une commande échoue et que le système d'exploitation enregistre les données de sens.

OPTIONS

-b, --binary=BFN
Lit les données de sens sous forme binaire à partir du fichier BFN. Peut être utilisé plusieurs fois.
-e, --error
Décode uniquement les informations d'erreur (par exemple, le code détaillé de sens SCSI et la clé de sens).
-H, --hex
Sortie sous forme hexadécimale.
-h, --help
Affiche le message d'aide puis quitte.
-HHH, --hexHH
Sortie hexadécimale brute (sans encadrement par des délimiteurs).
-i, --inhex=HFN
Lit les données de sens sous forme hexadécimale à partir du fichier HFN. Peut être utilisé plusieurs fois.
-k, --key
Affiche uniquement la clé de sens.
-m, --mask=MASK
Champs de masquage utilisés pour l'affichage dans des formats spécifiques (par exemple, page de code des fonctionnalités).
-n, --nodecode
Ne décode pas les données de sens. Utile pour convertir hexadécimal en binaire.
-p, --page=PAGE_CODE
Spécifie une page de code de fonctionnalités (Vital Product Data - VPD).
-q, --quiet
Désactive les messages d'avertissement lors de la gestion des erreurs.
-r, --raw
Ne pas décoder le texte. La sortie est une séquence brute d'octets.
-s, --sense
Décode les données de sens. C'est le comportement par défaut.
-S, --summary
Fournit un résumé plus court, en se concentrant sur la clé de sens et le code détaillé de sens.
-t, --transport
Affiche des informations supplémentaires sur le transport (par exemple, les données de statut de transport).
-v, --verbose
Augmente la verbosité. Peut être utilisé plusieurs fois.
-V, --version
Affiche les informations de version puis quitte.
-w, --write=WFN
Ecrit les données de sens (potentiellement converties) dans le fichier WFN. Par défaut, écrit au format hexadécimal. Utilisez --nodecode pour écrire des données binaires brutes.

NOTES

Contrairement à la plupart des utilitaires de ce paquet, cet utilitaire n'accède pas à un périphérique SCSI (unité logique). Cet utilitaire accède à une bibliothèque associée à ce paquet. Entre autres choses, la bibliothèque décode les données de sens SCSI.

L'utilitaire sg_raw prend une séquence hexadécimale ASCII représentant un CDB SCSI. Lorsque sg_raw reçoit l'option '-vvv', il tente de décoder le nom du CDB.

L'utilisation de la combinaison d'options : "--inhex=HFN --nodecode --write=WFN" peut être utilisée pour convertir l'hexadécimal (tel que produit par cet utilitaire et d'autres de ce paquet) en binaire, où le fichier de sortie est WFN.

Contrairement à de nombreux autres utilitaires, il n'y a pas d'option --raw. Cependant, les données binaires peuvent être entrées en utilisant l'option --binary=BFN, tandis que les données binaires peuvent être sorties en utilisant l'option --write=WFN (en l'absence de l'option --hex).

EXEMPLES

Les données de sens sont souvent imprimées dans les journaux du noyau et parfois sur la ligne de commande lorsque des indicateurs verbeux ou de débogage sont donnés. Elles auront au moins 8 octets, souvent 18 octets, mais peuvent être plus longues. Une chaîne de données de sens pourrait ressembler à ceci :

f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00
00 00

Copiez-collez-la après la commande sg_decode_sense :


sg_decode_sense f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00 00 00

et pour ces données de sens, la sortie devrait ressembler à ceci :


Fixed format, current; Sense key: Medium Error
Additional sense: Unrecovered read error
Info fld=0x1234 [4660]

Pour une erreur média, le champ Info est l'adresse de bloc logique (LBA) du bloc numéroté le plus bas que la commande SCSI associée n'a pas pu lire (vérifier ou écrire).

Pour convertir des données binaires arbitraires en hexadécimal, adaptées à être analysées par d'autres utilitaires sg3_utils. L'option --nodecode est utilisée dans ce cas :


sg_decode_sense -N -i vpd_zbdc.hex -w vpd_zbdc.bin

Le '-HHH' affichera en hexadécimal sur la console (stdout) sous une forme appropriée pour que d'autres utilitaires de ce paquet puissent l'analyser en entrée. Et sg_decode_sense peut également être utilisé pour convertir de l'hexadécimal arbitraire en binaire avec :


sg_decode_sense -N -b vpd_zbdc.raw -HHH

Notez que des outils comme hexdump et od placent un compteur (c'est-à-dire un index commençant à 0) au début de chaque ligne, ce qui est gênant lors de l'analyse de l'hexadécimal. Les options '/-HHH' n'affichent pas ce compteur de début sur chaque ligne.

STATUT DE SORTIE

Le statut de sortie de sg_decode_sense est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).
