SGEDMDQ calcule la Décomposition de Mode Dynamique (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    SGEDMDQ calcule la Décomposition de Mode Dynamique (DMD) pour
!>    une paire de matrices d'instantanés de données, en utilisant
!>    une compression basée sur la factorisation QR des données.
!>    Pour les matrices d'entrée X et Y telles que Y = A*X avec
!>    une matrice A inaccessible, SGEDMDQ calcule un certain nombre
!>    de paires de Ritz de A en utilisant l'extraction standard de
!>    Ritz-Rayleigh à partir d'un sous-espace de range(X) qui est
!>    déterminé à l'aide des vecteurs singuliers gauches principaux de X.
!>    Optionnellement, SGEDMDQ retourne les résidus des paires de
!>    Ritz calculées, les informations nécessaires pour un raffinement
!>    des vecteurs de Ritz, ou les vecteurs propres de la DMD exacte.
!>    Pour plus de détails, voir les références ci-dessous.
!>    Pour plus de détails sur l'implémentation, voir [3].
!>

Références :

!>        and experimental data,
!>        Journal of Fluid Mechanics 656, 5-28, 2010.

!>        decompositions: analysis and enhancements,
!>        SIAM J. on Sci. Comp. 40 (4), A2253-A2285, 2018.

Paramètres

JOBS 
!>    JOBS (entrée) CARACTÈRE*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 colonnes de tête de F sont désignées par X et les
!>    N-1 colonnes de queue par Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D telle que X*D ait des colonnes
!>           non nulles unitaires (dans la norme Euclidienne 2).
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il s'avère qu'une i-ème colonne de X est un vecteur
!>           nul et que la i-ème colonne correspondante de Y est
!>           non nulle, alors la i-ème colonne de Y est mise à
!>           zéro et un indicateur d'avertissement est déclenché.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D telle que Y*D ait des colonnes
!>           non nulles unitaires (dans la norme Euclidienne 2).
!>    'N' :: Aucune mise à l'échelle des données.
!>

JOBZ

!>    JOBZ (entrée) CARACTÈRE*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et retournés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormée et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur sous-jacent discret sur l'enveloppe
!>           des instantanés de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CARACTÈRE*1
!>    Détermine si les résidus doivent être calculés.
!>    'R' :: Les résidus pour les paires propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit valide, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!>

JOBQ

!> JOBQ (entrée) CHARACTER*1 !> Spécifie si la matrice orthogonale issue de la factorisation QR doit être calculée explicitement et retournée. !> 'Q' :: La matrice Q de la factorisation QR de la matrice des snapshots de données est calculée et stockée dans le tableau F. Voir la description de F. !> 'N' :: La matrice Q n'est pas calculée explicitement. !>

JOBT

!>    JOBT (entrée) CHARACTER*1
!>    Spécifie si le facteur triangulaire supérieur issu de la factorisation QR doit être retourné.
!>    'R' :: La matrice R de la factorisation QR de la matrice des snapshots de données F est retournée dans le tableau Y. Voir la description de Y et les Détails supplémentaires.
!>    'N' :: La matrice R n'est pas retournée.
!>

JOBF

!>    JOBF (entrée) CHARACTER*1
!>    Spécifie si des informations nécessaires au post-traitement (par exemple, le calcul des vecteurs de Ritz raffinés) doivent être stockées.
!>    'R' :: La matrice nécessaire au raffinement des vecteurs de Ritz est calculée et stockée dans le tableau B. Voir la description de B.
!>    'E' :: Les vecteurs propres non normalisés du DMD exact sont calculés et retournés dans le tableau B. Voir la description de B.
!>    'N' :: Aucune donnée de raffinement de vecteur propre n'est calculée.
!>    Pour être utile en sortie, cette option nécessite JOBQ='Q'.
!>

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet de sélectionner l'algorithme SVD de la bibliothèque LAPACK.
!>    1 :: SGESVD (l'algorithme SVD QR)
!>    2 :: SGESDD (l'algorithme Divide and Conquer ; si suffisamment d'espace de travail est disponible, c'est l'option la plus rapide)
!>    3 :: SGESVDQ (le SVD QR préconditionné ; ceci et 4 sont les options les plus précises)
!>    4 :: SGEJSV (le SVD de Jacobi préconditionné ; ceci et 3 sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative dans la précision des petites valeurs singulières est possible si les snapshots varient en norme de telle sorte que X soit sévèrement mal conditionnée. Si des petites valeurs singulières (inférieures à EPS*||X||) sont d'intérêt et que JOBS=='N', alors les options (3, 4) donnent les résultats les plus précis, où l'option 4 est légèrement meilleure et avec un fondement théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire que les colonnes de X seront normalisées, alors toutes les méthodes donnent des résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M >= 0
!>    La dimension de l'espace d'états (le nombre de lignes de F)
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de snapshots de données d'une seule trajectoire, pris à des temps discrets équidistants. C'est le nombre de colonnes de F.
!>

F

!>    F (entrée/sortie) REAL(KIND=WP) tableau M-par-N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence des snapshots de données d'une seule trajectoire, pris à des temps discrets équidistants. Il est supposé que les normes des colonnes de F sont dans la plage des nombres flottants normalisés.
!>    < À la sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice/le facteur orthogonal de la factorisation QR de la matrice initiale des snapshots de données F. Voir la description de JOBQ.
!>    Si JOBQ == 'N', les entrées de F strictement sous la diagonale principale contiennent, colonne par colonne, les informations sur les vecteurs de Householder, tels que retournés par SGEQRF. Les informations restantes pour restaurer la matrice orthogonale de la factorisation QR initiale sont stockées dans WORK(1:N). Voir la description de WORK.
!>

LDF

!>    LDF (entrée) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N)-par-(N-1)
!>    X est utilisé comme espace de travail pour contenir des représentations des N-1 premiers snapshots dans la base orthonormée calculée lors de la factorisation QR de F.
!>    À la sortie, les K premières colonnes de X contiennent les K premiers vecteurs singuliers gauches du contenu décrit ci-dessus de X. Pour les remonter dans l'espace des vecteurs singuliers gauches U(:,1:K) des données d'entrée, pré-multiplier par le facteur Q de la factorisation QR initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= N
!>    La dimension principale du tableau X
!>

Y

!>    Y (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N)-par-(N-1)
!>    Y est utilisé comme espace de travail pour contenir des représentations des N-1 derniers snapshots dans la base orthonormée calculée lors de la factorisation QR de F.
!>    À la sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire supérieur MIN(M,N)-par-N de la factorisation QR de la matrice des snapshots de données F.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= N
!>    La dimension principale du tableau Y
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique, c'est-à-dire comment tronquer les petites valeurs singulières de la matrice d'entrée X. À l'entrée, si
!>    NRNK = -1 :: i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite une SVD de haute précision, ce qui
!>                 peut ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur positive de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles calculées est inférieur à NRNK, alors seules ces
!>    valeurs non nulles seront utilisées et la dimension réellement utilisée sera inférieure à NRNK. Le nombre réel de
!>    valeurs singulières non nulles est retourné dans la variable
!>    K. Voir la description de K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour la troncature des petites valeurs singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER, 0 <= K <= N
!>    La dimension de la base SVD/POD pour les N-1 premiers
!>    snapshots de données (colonnes de F) et le nombre de paires de Ritz calculées. La valeur de K est déterminée
!>    conformément à la règle définie par les paramètres NRNK et
!>    TOL. Voir les descriptions de NRNK et TOL.
!>

REIG

!>    REIG (sortie) REAL(KIND=WP) tableau (N-1)-par-1
!>    Les K premières entrées (K<=N) de REIG contiennent
!>    les parties réelles des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Voir les descriptions de K, IMEIG, Z.
!>

IMEIG

!>    IMEIG (sortie) REAL(KIND=WP) tableau (N-1)-par-1
!>    Les K premières entrées (K<N) de REIG contiennent
!>    les parties imaginaires des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Les valeurs propres sont déterminées comme suit :
!>    Si IMEIG(i) == 0, alors la valeur propre correspondante est
!>    réelle, LAMBDA(i) = REIG(i).
!>    Si IMEIG(i)>0, alors la paire de valeurs propres complexes
!>    conjuguées correspondante se lit
!>    LAMBDA(i)   = REIG(i) + sqrt(-1)*IMAG(i)
!>    LAMBDA(i+1) = REIG(i) - sqrt(-1)*IMAG(i)
!>    C'est-à-dire que les paires de conjugués complexes ont des
!>    indices consécutifs (i,i+1), avec la partie imaginaire positive
!>    listée en premier.
!>    Voir les descriptions de K, REIG, Z.
!>

Z

!>    Z (espace de travail/sortie) REAL(KIND=WP) tableau M-par-(N-1)
!>    Si JOBZ =='V' alors
!>       Z contient les vecteurs de Ritz réels comme suit :
!>       Si IMEIG(i)=0, alors Z(:,i) est un vecteur propre de
!>       la i-ème valeur de Ritz.
!>       Si IMEIG(i) > 0 (et IMEIG(i+1) < 0) alors
!>       [Z(:,i) Z(:,i+1)] engendrent un sous-espace invariant et
!>       les valeurs de Ritz extraites de ce sous-espace sont
!>       REIG(i) + sqrt(-1)*IMEIG(i) et
!>       REIG(i) - sqrt(-1)*IMEIG(i).
!>       Les vecteurs propres correspondants sont
!>       Z(:,i) + sqrt(-1)*Z(:,i+1) et
!>       Z(:,i) - sqrt(-1)*Z(:,i+1), respectivement.
!>    Si JOBZ == 'F', alors les descriptions ci-dessus s'appliquent
!>    aux colonnes de Z*V, où les colonnes de V sont les
!>    vecteurs propres du quotient de Rayleigh K-par-K, et Z est
!>    orthonormée. Les colonnes de V sont structurées de manière similaire :
!>    Si IMEIG(i) == 0 alors Z*V(:,i) est un vecteur propre, et si
!>    IMEIG(i) > 0 alors Z*V(:,i)+sqrt(-1)*Z*V(:,i+1) et
!>                      Z*V(:,i)-sqrt(-1)*Z*V(:,i+1)
!>    sont les vecteurs propres de LAMBDA(i), LAMBDA(i+1).
!>    Voir les descriptions de REIG, IMEIG, X et V.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau (N-1)-par-1
!>    RES(1:K) contient les résidus pour les K paires de Ritz calculées.
!>    Si LAMBDA(i) est réelle, alors
!>       RES(i) = || A * Z(:,i) - LAMBDA(i)*Z(:,i))||_2.
!>    Si [LAMBDA(i), LAMBDA(i+1)] est une paire complexe conjuguée
!>    alors
!>    RES(i)=RES(i+1) = || A * Z(:,i:i+1) - Z(:,i:i+1) *B||_F
!>    où B = [ real(LAMBDA(i)) imag(LAMBDA(i)) ]
!>              [-imag(LAMBDA(i)) real(LAMBDA(i)) ].
!>    Il est vrai que
!>    RES(i)   = || A*ZC(:,i)   - LAMBDA(i)  *ZC(:,i)   ||_2
!>    RES(i+1) = || A*ZC(:,i+1) - LAMBDA(i+1)*ZC(:,i+1) ||_2
!>    où ZC(:,i)   =  Z(:,i) + sqrt(-1)*Z(:,i+1)
!>          ZC(:,i+1) =  Z(:,i) - sqrt(-1)*Z(:,i+1)
!>    Voir la description de Z.
!>

B

!>    B (sortie) REAL(KIND=WP) tableau MIN(M,N)-par-(N-1).
!>    SI JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs raffinés ; voir les détails supplémentaires dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD exact, à une mise à l'échelle par l'inverse des valeurs propres près.
!>    Dans les deux cas, le contenu de B peut être remonté à la
!>    dimension d'origine des données d'entrée en pré-multipliant
!>    par le facteur Q de la factorisation QR initiale.
!>    Ici, A dénote une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= MIN(M,N)
!>    La dimension principale du tableau B.
!>

V

!>    V (espace de travail/sortie) REAL(KIND=WP) tableau (N-1)-par-(N-1)
!>    À la sortie, V(1:K,1:K) contient les K vecteurs propres
!!>    du quotient de Rayleigh. Les vecteurs propres d'une paire complexe conjuguée de valeurs propres sont retournés sous forme réelle
!>    comme expliqué dans la description de Z. Les vecteurs de Ritz
!>    (retournés dans Z) sont le produit de X et V ; voir
!>    les descriptions de X et Z.
!>

Documentation de la fonction/sous-routine

Le sous-programme SGEDMDQ calcule une décomposition tronquée en valeurs singulières (SVD) de la matrice M-par-N F(1:M,1:N).

Le sous-programme SGEDMDQ calcule les k valeurs singulières les plus petites (si WHTSVD=2,3,4) ou les k valeurs singulières les plus grandes (si WHTSVD=1) de la matrice de covariance tronquée.

Il est utilisé pour obtenir le modèle d'état de Hankel des systèmes linéaires discrets.

Le sous-programme est basé sur le sous-programme LAPACK SGGESV.

Paramètres

JOBZ

!>    JOBZ (input) CHARACTER*1
!>    Specifies whether to compute the eigenvectors of S.
!>    = 'N': Do not compute the eigenvectors.
!>    = 'V': Compute the eigenvectors of the matrix S.
!>    = 'F': Compute the eigenvectors of the matrix S and
!>           the generalized eigenvectors of (A,B) if it is
!>           possible.
!>

JOBQ

!>    JOBQ (input) CHARACTER*1
!>    Specifies whether to compute the right singular vectors.
!>    = 'N': Do not compute the right singular vectors.
!>    = 'Q': Compute the right singular vectors.
!>

WHTSVD

!>    WHTSVD (input) INTEGER
!>    Specifies the variant of the SVD computation.
!>    = 1: Compute the k largest singular values. (k is output
!>         singular values.)
!>    = 2: Compute the k smallest singular values. (k is output
!>         singular values.)
!>    = 3: Compute the k smallest singular values using the
!>         generalized SVD of (A,B) where A = F(1:M, 1:N-1)
!>         and B = F(1:M, N).
!>    = 4: Compute the k smallest singular values using the
!>         generalized SVD of (A,B) where A = F(1:M, N)
!>         and B = F(1:M, 1:N-1).
!>

M

!>    M (input) INTEGER
!>    The number of rows of the matrix F. M >= 0.
!>

N

!>    N (input) INTEGER
!>    The number of columns of the matrix F. N >= 0.
!>

F

!>    F (input/output) REAL(KIND=WP) M-by-N array
!>    On entry, F contains the M-by-N matrix for which the
!>    truncated SVD is to be computed.
!>    On exit, F is overwritten by the decomposition.
!>

LDF

!>    LDF (input) INTEGER
!>    The leading dimension of the array F. LDF >= max(1,M).
!>

V

!>    V (output) REAL(KIND=WP) (N-1)-by-(N-1) array
!>    If JOBZ = 'V' or 'F', V contains the matrix S.
!>    The content of V is overwritten during the eigenvalue
!>    decomposition by SGEEV.
!>

LDV

!>    LDV (input) INTEGER, LDV >= N-1
