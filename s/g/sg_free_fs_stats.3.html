DESCRIPTION

Les fonctions sg_get_fs_stats fournissent des statistiques des systèmes de fichiers montés. Les deux fonctions prennent un paramètre d'entrées optionnel, qui pointe (lorsqu'il est fourni) vers une variable de type size_t pour compter le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_fs_stats() et sg_get_fs_stats_r() retournent les statistiques des systèmes de fichiers au moment de l'appel de la fonction. Les fonctions sg_get_fs_stats_diff() et sg_get_fs_stats_diff_between() retournent la différence entre deux appels de sg_get_fs_stats() ou sg_get_fs_stats_r(), respectivement.

Raccourcis API

fonction retourne propriétaire des données
sg_get_fs_stats sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_r sg_fs_stats * l'appelant
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_diff_between sg_fs_stats * l'appelant
sg_get_valid_filesystems char ** libstatgrab (global)

Les vecteurs sg_fs_stats reçus de sg_get_fs_stats_r() ou sg_get_fs_stats_diff_between() doivent être libérés avec sg_free_fs_stats() lorsqu'ils ne sont plus nécessaires. L'appelant est responsable de le faire.

La bibliothèque statgrab est livrée avec une liste intégrée de types de systèmes de fichiers valides en fonction du système d'exploitation pour lequel elle a été compilée. Certains systèmes d'exploitation fournissent en outre une API pour connaître les types de systèmes de fichiers connus ou valides pour l'instance OS en cours d'exécution, ce qui est utilisé lorsqu'il est détecté. Néanmoins, il existe des problèmes connus lors de la collecte des statistiques des systèmes de fichiers : les systèmes de fichiers réseau sont montés depuis des serveurs lancés à distance, les développeurs de systèmes de fichiers exécutent un pilote expérimental, etc.

Pour éviter que les processus ne se bloquent en collectant les statistiques des systèmes de fichiers ou pour permettre aux développeurs de tester leurs pilotes, les processus peuvent modifier la liste des systèmes de fichiers valides en utilisant sg_get_valid_filesystems() et sg_set_valid_filesystems(). La liste des paramètres char * avec lesquels les deux fonctions travaillent se termine toujours par un élément pointant vers NULL.

La liste retournée par sg_get_valid_filesystems() ne doit pas être modifiée. Copiez toujours la liste dans votre propre structure si vous envisagez d'étendre ou de réduire la liste :

Exemple de suppression des systèmes de fichiers réseau

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* noms connus des systèmes de fichiers réseau sur différentes plateformes */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* dupliquer dans une mémoire propre pour modifier la liste */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copier y compris le pointeur NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Notez qu'il n'est pas nécessaire de dupliquer les chaînes contenues dans la liste des systèmes de fichiers valides dans l'exemple ci-dessus ; elles ne sont pas modifiées.

La liste retournée par sg_get_valid_filesystems() peut devenir invalide lorsqu'elle est utilisée pendant que le processus effectue des appels à sg_set_valid_filesystems(). Aucune des fonctions sg_fs_stats ne protège l'accès au stockage globalement utilisé où la copie propre de la liste des systèmes de fichiers valides est conservée. Il incombe à l'appelant de ne pas mélanger les appels de configuration avec les appels pour récupérer les statistiques.

De plus, deux fonctions de support pour qsort(3) sont disponibles : sg_fs_compare_device_name() et sg_fs_compare_mnt_point().

Exemple de tri

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* trier les entrées par ordre alphabétique en utilisant le point de montage */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALEURS DE RETOUR

sg_get_fs_stats retourne un pointeur vers une structure de type sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
device_name
Le nom connu du système d'exploitation. (par ex. sous linux, cela pourrait être hda)
fs_type
Le type de système de fichiers (par ex. hpfs ou ufs).
mnt_point
Le point de montage où le système de fichiers est monté.
device_type
Le type de périphérique du système de fichiers, actuellement non rempli et toujours sg_fs_unknown.
size
La taille totale, en octets, du système de fichiers.

size = used + free

used
La quantité d'espace, en octets, utilisée sur le système de fichiers.
avail
La quantité d'espace, en octets, disponible sur le système de fichiers pour les processus non-root.
sg_free_fs_stats(3) — libstatgrab — Arch manual pages

NAME

sg_free_fs_stats — Get statistics for free file systems

SYNOPSIS

#include <statgrab.h>

sg_fs_stats_t *
sg_free_fs_stats(int *n_structures);

DESCRIPTION

The sg_free_fs_stats function returns a list of sg_fs_stats_t structures detailing the statistics for free file systems mounted on the system.

The file systems are identified by the fs_mount_point field.

If the value of n_structures is greater than 0 then the pointer it points to will be set to the number of structures returned.

The memory for the returned structures is allocated by libstatgrab and should be freed using sg_fs_stats_free.

sg_fs_stats_t
Structure containing file system statistics.
fs_mount_point
The mount point for the file system.
fs_type
The type of the file system (e.g. "ext4", "nfs").
fs_device
The device the file system is mounted on.
fs_total_bytes
The total number of bytes in the file system.
fs_total_files
The total number of files in the file system.
fs_used_bytes
The number of bytes used in the file system.
fs_used_files
The number of files used in the file system.
fs_reserved_bytes
The number of bytes reserved for privileged users/processes.
fs_reserved_files
The number of inodes reserved for privileged users/processes.
fs_available_bytes
The number of bytes available to unprivileged users/processes (free space less reserved space).
avail = free - reserved
free
The amount of space, in bytes, free on the file system.
total_inodes
The total number of inodes in the file system.
used_inodes
The number of used inodes in the file system.
free_inodes
The number of free inodes in the file system.
avail_inodes
The number of free inodes available to non-privileged processes.
io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
block_size
The size in bytes of the minimum unit of allocation on this file system.
total_blocks
The total number of blocks in the file system.
free_blocks
The number of free blocks in the file system.
used_blocks
The number of used blocks in the file system.
avail_blocks
The number of free blocks available to non-privileged processes.
systime
The time in seconds since epoch when the statistic was retrieved from kernel.

RETURN VALUES

On success, a pointer to an array of sg_fs_stats_t structures is returned. The pointer is NULL on failure, and errno is set to indicate the error.

If the value of n_structures is greater than 0 then the pointer it points to will be set to the number of structures returned.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
