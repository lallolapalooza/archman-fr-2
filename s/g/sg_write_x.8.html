sg_write_x - Commandes SCSI WRITE normales/ATOMIC/SAME/SCATTERED/STREAM, ORWRITE

DESCRIPTION

Cet utilitaire envoie l'une des six commandes SCSI, toutes associées à l'écriture de données sur le PÉRIPH donné. Ce sont les commandes WRITE "normales", ORWRITE, WRITE ATOMIC, WRITE SAME, WRITE SCATTERED ou WRITE STREAM. Cet utilitaire supporte les variantes de 16 et 32 octets de ces six commandes. Par conséquent, certaines commandes étroitement liées ne sont pas supportées (par exemple, WRITE(10)). Toutes les variantes de 32 octets, à l'exception de ORWRITE(32), nécessitent que le PÉRIPH soit formaté avec des informations de protection (PI) de type 1, 2 ou 3, rendant tous les blocs logiques 8 octets (ou un multiple de 8 octets) plus longs sur le support.

L'interface en ligne de commande est un peu chargée avec plus de trente options. C'est pourquoi la SYNTAXE, après avoir listé toutes les options (longues), liste celles applicables à chaque commande supportée. Pour chaque syntaxe de commande, l'option qui sélectionne la commande SCSI est affichée en premier, suivie des options requises. Si aucune option de commande n'est donnée, une commande WRITE "normale" est supposée. Même si l'option --scat-file=SF peut être donnée pour chaque commande, elle n'est affichée que pour WRITE SCATTERED où elle est la plus utile. Si l'option --scat-file=SF est donnée, alors ni les options --lba=LBA[,LBA...] ni --num=NUM[,NUM...] ne doivent être données. Seul le premier élément des options --lba=LBA[,LBA...] et --num=NUM[,NUM...] (ou la première paire (ou quintet) de l'option --scat-file=SF) est utilisé pour toutes les commandes sauf WRITE SCATTERED. Toutes les commandes peuvent accepter --dry-run et --verbose en plus de celles affichées dans la SYNTAXE.

La taille du bloc logique en octets peut être donnée explicitement avec l'option --bs=BS, tant que BS est supérieur à zéro. C'est typiquement une puissance de deux, 512 ou plus. Si l'option --bs=BS n'est pas donnée ou si BS est zéro, alors la commande SCSI READ CAPACITY est utilisée pour trouver la taille du bloc logique. D'abord, la commande READ CAPACITY(16) est essayée et si elle réussit, la taille du bloc logique dans la réponse est généralement utilisée comme la taille de bloc réelle pour cet utilitaire. L'exception est lorsque PROT_EN est défini dans la réponse et que l'option --wrprotect=WPR est donnée et non nulle ; dans ce cas, 8 (octets) sont ajoutés à la taille du bloc logique pour obtenir la taille de bloc réelle utilisée par cet utilitaire. Si READ CAPACITY(16) échoue, alors READ CAPACITY(10) est essayée et si cela fonctionne, la taille du bloc logique dans la réponse est utilisée comme la taille de bloc réelle.

Le nombre d'octets que cet utilitaire tentera de lire à partir du fichier nommé par IF est le produit de la taille de bloc réelle et du nombre_de_blocs (NUM ou la somme des arguments NUM). Si moins d'octets sont lus depuis le fichier IF et que l'option --strict est donnée, alors cet utilitaire se termine avec un code de sortie SG_LIB_FILE_ERROR. Si moins d'octets sont lus depuis le fichier IF et que l'option --strict n'est pas donnée, alors des octets nuls sont substitués aux octets "manquants" et cet utilitaire continue.

Les tentatives d'écriture de données de plusieurs mégaoctets avec une seule commande sont susceptibles d'échouer pour plusieurs raisons. Premièrement, le système d'exploitation peut refuser d'allouer un tampon aussi grand. Ensuite, le passage SCSI limite généralement les blocs de données à quelques mégaoctets ou moins. Enfin, le périphérique de stockage peut avoir une quantité limitée de RAM pour supporter une opération d'écriture comme ATOMIC (car elle pourrait nécessiter une annulation). Le périphérique de stockage peut informer le client applicatif de ses limitations via la page VPD des limites de bloc (0xb0), avec le champ de longueur de transfert atomique maximale entre autres.

Un descripteur de plage d'adresses de blocs logiques (LBA) dégénéré sans PI a un LBA et un NUM de zéro. Un descripteur de plage LBA dégénéré avec PI a en outre ses champs RT, AT et TM mis à zéro (note : ce ne sont pas les valeurs par défaut pour RT, AT et TM). Ils sont dégénérés dans le sens où ils sont indiscernables d'un remplissage de zéros qui suit la liste de dispersion dans le tampon de données en sortie. SBC-4 précise qu'un descripteur de plage LBA dégénéré est valide. Cela peut devenir un problème si RD donné dans l'option --scattered=RD a la valeur 0. Dans ce cas, la logique peut avoir besoin de parcourir les données fournies par l'utilisateur pour calculer le nombre de descripteurs de plage LBA requis par la commande WRITE SCATTERED cdb. En l'absence d'autres informations, la logique considérera un descripteur de plage LBA dégénéré comme un terminateur de la liste de dispersion.

La référence pour ces commandes est SBC-4 (T10/BSR INCITS 506-2021) et le projet SBC-5 INCITS 571 révision 1 daté du 21 mai 2021. Les six commandes SCSI sont décrites dans ces documents. WRITE ATOMIC a été ajoutée dans la révision 3 de SBC-4 ; WRITE STREAM a été ajoutée dans la révision 7 de SBC-4 ; WRITE SCATTERED a été ajoutée dans la révision 11 de SBC-4 tandis que les autres sont dans la norme SBC-3 précédente.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont classées par ordre alphabétique basé sur le nom de l'option longue.

-6, --16
envoie la variante cdb de 16 octets de la commande SCSI sélectionnée. Si aucune commande n'est sélectionnée, la commande SCSI WRITE(16) "normale" est envoyée. Si ni cette option ni l'option --32 n'est donnée, cette option est supposée.
-3, --32
envoie la variante cdb de 32 octets de la commande SCSI sélectionnée. Si aucune commande n'est sélectionnée, la commande SCSI WRITE(32) "normale" est envoyée. Si ni cette option ni l'option --16 n'est donnée, alors l'option --16 est supposée. Si cette option et l'option --16 sont toutes deux données, alors cette option a la priorité. Notez qu'à l'exception de ORWRITE(32), toutes les autres variantes cdb de 32 octets nécessitent un PÉRIPH formaté avec t
type 1, 2 ou 3 informations de protection.
-a, --app-tag=AT
où AT est le champ « étiquette logique de bloc attendue » (expected logical block application tag) trouvé dans la plupart des variantes de cdb de 32 octets (l'exception est ORWRITE(32)). AT est un champ de 16 bits, donc la valeur maximale est 0xffff. La valeur par défaut est 0xffff.
-A, --atomic=AB
sélectionne la commande WRITE ATOMIC et AB est placé dans le champ Atomic Boundary de son cdb. C'est un champ de 16 bits, donc la valeur maximale est 0xffff. En cas de doute sur la valeur à définir, essayez 0, ce qui tentera d'écrire tout le tampon de sortie de données en une seule opération atomique.
-B, --bmop=OP,PGP
où OP et PGP sont les valeurs à placer respectivement dans les champs BMOP et 'Previous Generation Processing' de ORWRITE(32). BMOP est un champ de 3 bits (valeur de 0 à 7) et PGP est un champ de 4 bits (valeur de 0 à 15). Les deux champs valent 0 par défaut.
-b, --bs=BS
où BS est la taille logique du bloc ou la taille réelle du bloc qui sera légèrement plus grande. La valeur par défaut est zéro. Si cette option n'est pas fournie ou est fournie avec une valeur BS de zéro, alors la commande SCSI READ CAPACITY(16) est envoyée à DEVICE. Si cela échoue, la commande READ CAPACITY(10) est envoyée. La taille logique et la taille réelle du bloc seront dérivées de la réponse de la commande READ CAPACITY.
Cette section suppose que BS est supérieur à zéro. Si BS est inférieur à 512 (octets) ou n'est pas un multiple de 8, un avertissement est émis et l'utilitaire continue, sauf si l'option --strict est également fournie. Si BS est une puissance de deux (par exemple, 512), alors la taille logique et la taille réelle du bloc sont définies sur BS (par exemple, 512). Si BS n'est pas une puissance de deux (par exemple, 520), alors la taille logique du bloc est définie sur la puissance de deux la plus proche inférieure à BS (par exemple, 512) et la taille réelle du bloc est définie sur BS (par exemple, 520).
Si la taille logique et la taille réelle du bloc sont différentes, une vérification ultérieure réduira la taille réelle du bloc à la taille logique du bloc, sauf si --wrprotect=WPR est supérieur à zéro.
-c, --combined=DOF
Cette option s'applique uniquement à WRITE SCATTERED et suppose que l'ensemble du tampon de sortie de données peut être lu à partir de IF fourni par l'option --in=IF. L'ensemble du tampon de sortie de données est l'en-tête de la liste de paramètres, suivi de zéro ou plusieurs descripteurs de plage LBA, éventuellement suivis de quelques octets de remplissage et ensuite des données à écrire sur le média. Si les options --lba=LBA[,LBA...], --num=NUM[,NUM...] ou --scat-file=SF sont également fournies, une erreur est générée. L'argument DOF doit être la valeur appropriée pour le champ 'Logical Block Data Offset' dans le cdb de WRITE SCATTERED. C'est le décalage dans le tampon de sortie de données où commencent les données à écrire sur le média. L'unité de ce champ est la taille réelle du bloc, qui est la taille logique du bloc plus un multiple de 8, si des informations de protection (PI) sont envoyées. Lorsque WPR (de --wrprotect=WPR) est supérieur à zéro, des PI sont attendues. La révision 15 de SBC-4 ne le stipule pas, mais il semble qu'une valeur DOF de 0 soit invalide. Il est suggéré d'utiliser cette option avec l'option --strict lors des expérimentations, car des données aléatoires ou incorrectes fournies via l'option --in=IF pourraient écrire beaucoup de données « intéressantes » partout sur le DEVICE. Si DOF est donné comme 0, l'utilitaire recherchera dans les données de IF jusqu'à ce que RD descripteurs de plage LBA soient trouvés ; ou si RD est également 0, jusqu'à ce qu'un descripteur de plage LBA dégénéré soit trouvé.
-D, --dld=DLD
où DLD est le descripteur de limites de durée réparti sur 3 bits dans les commandes SCSI WRITE(16) et WRITE SCATTERED(16). DLD est compris entre 0 et 7 inclus, avec une valeur par défaut de zéro. Le champ DLD0 dans WRITE(16) et WRITE SCATTERED(16) est défini si (0x1 & DLD) est non nul. Le champ DLD1 dans les deux cdb est défini si (0x2 & DLD) est non nul. Le champ DLD2 dans les deux cdb est défini si (0x4 & DLD) est non nul.
-d, --dpo
si cette option est fournie, le champ de bits DPO (disable page out) dans le cdb est défini. Par défaut, ce champ de bits est effacé. S'applique à toutes les commandes prises en charge par cet utilitaire, sauf WRITE SAME.
-x, --dry-run
cette option se termine (avec un statut de 0) juste avant d'envoyer la commande d'écriture SCSI sélectionnée. Elle peut toujours envoyer une commande SCSI READ CAPACITY (variante 16 octets et peut-être aussi variante 10 octets), donc le DEVICE est toujours requis. Elle lit les données et les traite si les options --in=IF et/ou --scat-file=SF sont fournies. Tout le traitement de la ligne de commande et les vérifications de cohérence (par exemple, si l'option --strict est fournie) seront effectués et en cas d'erreur, il y aura un statut de sortie non nul.
Si cette option est donnée deux fois (par exemple, -xx), au lieu d'exécuter la commande d'écriture SCSI sélectionnée, le tampon de sortie de données est écrit dans un fichier nommé sg_write_x.bin. S'il n'existe pas, ce fichier est créé dans le répertoire courant et est tronqué s'il existait précédemment avec un contenu plus long. Le tampon de sortie de données est écrit en binaire avec des informations à son sujet écrites sur stdout. Pour les écritures autres que dispersées, le nom du fichier et sa longueur en octets sont affichés sur stdout. Pour les écritures dispersées, en plus, le nombre de descripteurs de plage LBA et le décalage du bloc logique de données sont affichés sur stdout.
-f, --fua
si cette option est fournie, le champ de bits FUA (force unit access) dans le cdb est défini. Par défaut, ce champ de bits est effacé. S'applique à toutes les commandes prises en charge par cet utilitaire, sauf WRITE SAME.
-G, --generation=EOG,NOG
les arguments de cette option sont utilisés uniquement par la commande ORWITE(32). EOG est placé dans le champ "Expected ORWgeneration" tandis que NOG est placé dans le champ "New ORWgeneration". Les deux sont sur 32 bits et valent zéro par défaut.
-g, --grpnum=GN
définit le champ 'Group number' sur GN. La valeur par défaut est zéro. GN doit être une valeur comprise entre 0 et 63.
-h, --help
affiche le message d'utilisation puis quitte. Utiliser plusieurs fois pour plus d'aide. Actuellement, '-h' à '-hhhh' fournissent des sorties différentes.
-i, --in=IF
lit les données (en binaire) à partir d'un fichier nommé IF en un seul appel système OS (en Unix : read(2)). Ces données sont placées dans un tampon continu et utilisées comme tampon de sortie de données pour toutes les commandes d'écriture SCSI, à l'exception de WRITE SCATTERED(16 ou 32) qui peut inclure d'autres données dans le tampon de sortie de données. Pour WRITE SCATTERED (16 ou 32), le tampon de sortie de données est composé de 3 ou 4 composants dans cet ordre : un en-tête de liste de paramètres (32 octets nuls) ; zéro ou plusieurs descripteurs de plage LBA, éventuellement quelques octets de remplissage (zéros) et ensuite les données à écrire sur le média. Pour WRITE SCATTERED, IF fournit uniquement les données à écrire sur le média, sauf si l'option --combined=DOF est fournie. Lorsque l'option --combined=DOF est fournie, IF contient tous les composants du tampon de sortie de données de WRITE SCATTERED en binaire. Les données lues à partir de IF commencent à l'offset de OFF octets, qui vaut zéro par défaut, et pas plus de DLEN octets sont lus à partir de ce point (c'est-à-dire à partir de l'offset de fichier de OFF octets). Si DLEN est zéro ou non fourni, le reste du fichier IF est lu. Cette option est obligatoire, sauf lorsque --same=1 est fourni (ce qui définit le bit NDOB, signifiant "No Data Out Buffer"). Dans les systèmes d'exploitation basés sur Unix, n'importe quel nombre de zéros peut être produit en utilisant le fichier spécial /dev/zero.
IF peut être "-" ce qui est interprété comme stdin. Dans ce cas, --offset=OFF,DLEN peut être fourni avec OFF réglé à 0 et LEN réglé à une valeur non nulle, de préférence un multiple de la taille réelle du bloc. L'utilitaire peut également déduire la longueur de IF à partir de NUM (ou la somme d'entre eux dans le cas d'une liste dispersée).
-l, --lba=LBA[,LBA...]
où l'argument est une seule adresse logique de bloc (LBA) ou une liste séparée par des virgules de LBA, chacune étant l'adresse du premier bloc écrit par la commande d'écriture sélectionnée. Seule la commande WRITE SCATTERED peut utiliser plus d'un LBA de manière utile. Quel que soit le nombre de LBA fournis, il doit y avoir un nombre égal de NUM fournis à l'option --num=NUM[,NUM...]. Le premier LBA fourni s'associe au premier NUM fourni pour former le premier descripteur de plage LBA (qui, selon le numéro T10, commence à zéro dans SBC-4). Le deuxième LBA s'associe au deuxième NUM pour former le deuxième descripteur de plage LBA, etc. Un moyen plus pratique de définir un grand nombre de descripteurs de plage LBA est d'utiliser l'option --scat-file=SF. Par défaut, le bloc logique 0 (ce qui peut être dangereux) tandis que NUM vaut 0 par défaut, ce qui rend la combinaison inoffensive. LBA est supposé être en décimal, sauf s'il est précédé de '0x' ou a un 'h' final.
-N, --normal
le choix d'une commande WRITE "normale" (16 ou 32) peut être rendu explicite avec cette option. En l'absence de sélection d'une autre commande (par exemple, --atomic=AB), le choix d'une commande WRITE "normale" est le défaut.
-n, --num=NUM[,NUM...]
où l'argument est un seul NOMBRE de blocs (NUM) ou une liste séparée par des virgules de NUM qui correspondent aux entrées correspondantes de l'option --lba=LBA[,LBA...]. Si un NUM est fourni et n'est pas obtenu par un autre moyen (par exemple, en utilisant l'option --scat-file=SF), il prend par défaut le nombre de blocs dérivé de la taille du fichier nommé par IF (en commençant à l'offset de OFF octets jusqu'à la fin du fichier ou DLEN). En dehors de l'option --combined=DOF, un LBA doit être explicitement donné (soit avec --lba=LBA, soit via --scat-file=SF), sinon NUM vaut 0 par défaut par mesure de sécurité.
-o, --offset=OFF[,DLEN]
où OFF est le décalage en octets dans le fichier nommé IF à partir duquel commencer la lecture. La valeur par défaut de OFF est zéro, ce qui correspond au début du fichier nommé IF. DLEN est le nombre maximum d'octets à lire, en commençant à l'offset OFF en octets
t OFF, à partir du fichier nommé IF. Moins d'octets seront lus si une fin de fichier se produit avant que DLEN soit épuisé. Si DLEN est zéro ou n'est pas donné, alors la lecture à partir du décalage d'octet OFF jusqu'à la fin du fichier nommé IF est supposée.
-O, --or
sélectionne la commande ORWRITE. ORWRITE(16) a des champs similaires à WRITE(16) à part le champ WRPROTECT qui est nommé ORPROTECT avec des sémantiques légèrement différentes et l'absence des 3 champs de bits DLD. ORWRITE(32) a quatre champs supplémentaires qui sont définis avec les options --bmop=OP,PGP et --generation=EOG,NOG. ORWRITE(32) est la seule commande cdb de 32 octets de cet utilitaire qui ne nécessite pas un DEVICE formaté avec le type 1, 2 ou 3 PI (bien qu'il fonctionne toujours s'il est formaté avec PI).
-Q, --quiet
supprime certains messages d'information tels que ceux associés aux erreurs détectées lorsque cet utilitaire est sur le point de se terminer. La valeur du statut de sortie est toujours retournée au système d'exploitation lorsque cet utilitaire se termine.
-r, --ref-tag=RT
où RT est le champ "étiquette logique de référence de bloc initiale attendue" trouvé dans les variantes cdb de 32 octets de WRITE, WRITE ATOMIC, WRITE SAME et WRITE STREAM. Le champ est également trouvé dans les descripteurs de plage LBA de WRITE SCATTERED(32). C'est un champ de 32 bits, ce qui signifie que la valeur maximale est de 0xffffffff. La valeur par défaut est de 0xffffffff.
-S, --same=NDOB
sélectionne la commande WRITE SAME avec le champ NDOB défini à NDOB qui signifie No Data-Out Buffer. NDOB peut prendre les valeurs 0 ou 1 (c'est-à-dire qu'il s'agit d'un champ d'un seul bit). Lorsque --same=1, toutes les options associées au tampon de données de sortie sont ignorées.
-q, --scat-file=SF
où SF est le nom d'un fichier auxiliaire contenant la liste de dispersion pour la commande WRITE SCATTERED. Si l'option --scat-raw est également donnée, alors SF est supposé contenir à la fois l'en-tête de la liste de paramètres (32 octets de zéros) suivi de zéro ou plusieurs descripteurs de plage LBA qui font également 32 octets chacun. Ces composants sont tels que définis par SBC-4 (c'est-à-dire en binaire avec des entiers au format big endian). Si l'option --scat-raw n'est pas donnée, alors un fichier au format hexadécimal ASCII est attendu, comme décrit dans la section SCATTERED FILE ASCII FORMAT ci-dessous.
Si cette option est donnée avec l'option --combined=DOF, alors cet utilitaire se terminera avec une erreur de syntaxe. SF ne doit pas être "-", un moyen d'empêcher l'utilisateur de rediriger stdin.
-R, --scat-raw
cette option affecte uniquement la manière dont le fichier nommé SF de l'option --scat-file=SF pour WRITE SCATTERED est interprété. Par défaut (c'est-à-dire sans cette option), SF est analysé comme de l'hexadécimal ASCII avec des lignes vides et le contenu des lignes depuis et y compris '#' jusqu'à la fin de la ligne ignoré. Il peut donc contenir des commentaires et d'autres indications. Lorsque cette option est donnée, le fichier nommé SF est interprété comme binaire. En tant que binaire, il est supposé contenir 32 octets de zéros (l'en-tête de la liste de paramètres de WRITE SCATTERED) suivi de zéro ou plusieurs descripteurs de plage LBA (qui font chacun 32 octets). Si l'option --strict est donnée, le champ réservé dans ces deux éléments est vérifié, tout octet non nul provoquant une erreur.
-S, --scattered=RD
sélectionne la commande WRITE SCATTERED avec RD étant le nombre de descripteurs de plage LBA qui seront placés dans le tampon de données de sortie. Si RD est zéro, alors la logique essaiera de déterminer le nombre de descripteurs de plage par d'autres moyens (par exemple, en analysant le fichier nommé par SF, s'il y en a un). Les descripteurs de plage LBA diffèrent entre les variantes cdb de 16 et 32 octets de WRITE SCATTERED. Dans la variante cdb de 16 octets, le descripteur de plage LBA de 32 octets est composé d'un LBA de 8 octets, suivi d'un nombre_de_blocs de 4 octets, puis de 20 octets de zéros. Dans la variante de 32 octets, le LBA et le nombre_de_blocs sont suivis d'un RT (4 octets), d'un AT (2 octets) et d'un TM (2 octets), puis de 12 octets de zéros.
Ce paragraphe s'applique lorsque RD est supérieur à zéro. Si RD est inférieur au nombre de descripteurs de plage LBA construits à partir des options de ligne de commande, à partir de l'option --scat-file=SF ou décodé de IF (lorsque l'option --combined=DOF est donnée), alors RD prend la priorité ; ainsi RD est placé dans le champ "Nombre de descripteurs de plage LBA" dans le cdb. Si RD est supérieur au nombre de descripteurs de plage LBA trouvés à partir des données et options fournies, alors une erreur est générée.
-T, --stream=ID
sélectionne la commande WRITE STREAM avec le champ STR_ID défini à ID. ID peut prendre des valeurs de 0 à 0xffff (c'est-à-dire qu'il s'agit d'un champ de 16 bits).
-s, --strict
lorsque cette option est présente, davantage de choses (par exemple, que les champs réservés contiennent des zéros) et toute irrégularité termineront l'utilitaire avec un message vers stderr et un statut de sortie indicatif. Lors de l'expérimentation avec ces commandes, en particulier WRITE SCATTERED, il est recommandé d'utiliser cette option.
-t, --tag-mask=TM
où TM est le champ "masque d'étiquette d'application de bloc logique" trouvé dans les variantes cdb de 32 octets de WRITE, WRITE ATOMIC, WRITE SAME et WRITE STREAM. Le champ est également trouvé dans les descripteurs de plage LBA de WRITE SCATTERED(32). C'est un champ de 16 bits, ce qui signifie que la valeur maximale est de 0xffff. La valeur par défaut est de 0xffff.
-I, --timeout=TO
où TO est la valeur de temporisation de la commande en secondes. La valeur par défaut est de 120 secondes. Si NUM est important sur des médias lents, ces commandes WRITE peuvent nécessiter considérablement plus de 120 secondes pour se terminer. Une forme alternative d'option longue est --tmo=TO.
-u, --unmap=U_A
où U_A est la valeur des bits OR-és utilisés pour définir les champs de bits UNMAP et ANCHOR dans le cdb WRITE SAME (16 ou 32). Si U_A est 1, alors le champ de bits UNMAP est défini ; si U_A est 2, alors le champ de bits ANCHOR est défini ; si U_A est 3, alors les champs de bits UNMAP et ANCHOR sont tous deux définis. La valeur par défaut pour les deux champs de bits est effacé (0) ; définir U_A à 0 effacera également les deux champs de bits.
-v, --verbose
augmente le degré de verbosité (messages de débogage). Ces messages sont généralement écrits sur stderr.
-V, --version
affiche la chaîne de version puis quitte.
-w, --wrprotect=WPR
définit le champ WRPROTECT (3 bits) dans toutes les commandes sg_write_x, à l'exception de ORWRITE qui a un champ ORPROTECT de 3 bits (et le synopsis montre OPR pour souligner la différence). Dans tous les cas, WPR est placé dans ce champ de 3 bits. La valeur par défaut est zéro, ce qui n'envoie aucun PI dans le tampon de données de sortie. WPR doit être une valeur comprise entre 0 et 7.

FORMAT ASCII DU FICHIER DE DISPERSION

Toutes les commandes de cet utilitaire peuvent accepter un fichier --scat-file=SF, et cette option peut être considérée comme un remplacement des options --lba=LBA[,LBA...] et --num=NUM[,NUM...]. Si les deux options --scat-file=SF et --scat-raw sont données, alors le fichier nommé SF est attendu comme binaire et doit contenir l'en-tête de la liste de paramètres (32 octets de zéros pour les variantes 16 et 32 octets) suivi de zéro ou plusieurs descripteurs de plage LBA, chacun de 32 octets. Cette section décrit ce qui est attendu dans SF lorsque l'option --scat-raw n'est pas donnée.

Le fichier de dispersion "hexadécimal ASCII" (nommé par SF) peut contenir des commentaires, des lignes vides et des nombres. Si plusieurs nombres apparaissent sur une seule ligne, ils peuvent être séparés par des espaces, des tabulations ou une seule virgule. Les nombres sont analysés comme décimaux, sauf s'ils sont précédés de "0x" (ou "0X") ou ont un suffixe "h". 0x est le préfixe des nombres hexadécimaux dans le langage C, tandis que T10 utilise le suffixe "h" pour le même objectif. Tout ce qui va de et incluant un caractère "#" jusqu'à la fin de la ligne est ignoré, donc des commentaires peuvent y être placés.

Pour la commande WRITE SCATTERED (16), ses descripteurs de plage LBA contiennent deux éléments par descripteur : un LBA de 8 octets suivi d'un nombre_de_blocs de 4 octets. Les 20 octets restants du descripteur sont des zéros. Le format accepté est relativement souple, chaque valeur décodée étant placée dans un LBA, puis un nombre_de_blocs jusqu'à la fin du fichier. Le modèle commence par un LBA et s'il ne se termine pas par un nombre_de_blocs (c'est-à-dire si un nombre impair de valeurs est analysé), une erreur se produit. Ainsi, le nombre de descripteurs de plage LBA générés sera la moitié du nombre de valeurs analysées dans SF.

Pour la commande WRITE SCATTERED (32), ses descripteurs de plage LBA contiennent cinq éléments par descripteur : un LBA de 8 octets suivi d'un nombre_de_blocs de 4 octets, puis un RT de 4 octets, un AT de 2 octets et un TM de 2 octets. Les trois derniers éléments sont associés aux informations de protection (PI). Le format accepté dans le fichier SF est plus contraint que la variante cdb de 16 octets. Les éléments de chaque descripteur de plage LBA doivent se trouver sur une seule ligne, les éléments adjacents étant séparés par des virgules. Les deux premiers éléments (LBA et nombre_de_blocs) doivent être fournis, et s'il n'y a plus d'éléments sur la ligne, RT, AT et TM reçoivent leurs valeurs par défaut (tous les octets "ff"). Des espaces et des tabulations peuvent apparaître entre les éléments, mais les virgules sont les séparateurs. Deux virgules sans valeur entre elles feront que l'élément "manquant" recevra sa valeur par défaut.

NOTES

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section "ARGUMENTS NUMÉRIQUES" dans la page de manuel sg3_utils(8).

Sous Linux, avant le noyau 3.17, le pilote sg ne supportait pas les tailles de cdb supérieures à 16 octets. Ainsi, un nœud de périphérique tel que /dev/sg1, associé au pilote sg, échouerait avec cet utilitaire si l'option --32 était donnée (ou implicite par d'autres options). Le pilote bsg avec des nœuds de périphérique tels que /dev/bsg/6:0:0:1 prend en charge les tailles de cdb supérieures à 16 octets depuis son introduction dans le noyau 2.6.28.

STATUT DE SORTIE

Le statut de sortie of sg_write_x est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).

EXEMPLES

Une utilisation simple consiste à écrire 4 blocs de zéros à partir (et en incluant) un LBA donné, conformément aux règles de WRITE ATOMIC avec une limite atomique de 0. Comme aucune option de taille de cdb n'est donnée, le cdb de 16 octets sera supposé (c'est-à-dire WRITE ATOMIC(16)) :


sg_write_x --atomic=0 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Comme --bs=BS n'a pas été donné, cet utilitaire appellera la commande READ CAPACITY(16) sur /dev/sdc pour déterminer le nombre d'octets dans un bloc logique. Si la commande READ CAPACITY(16) échoue, la commande READ CAPACITY(10) est essayée. Supposons que l'une d'elles fonctionne et que le nombre d'octets dans chaque bloc logique est de 512 octets. Donc, 4 blocs de zéros (chaque bloc contenant 512 octets) seront écrits à partir (et en incluant) LBA 0x1234. Maintenant, pour contourner la nécessité de la/des commande(s) READ CAPACITY, l'option --bs=BS peut être utilisée :


sg_write_x --atomic=0 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Comme --bs= est donné et que sa valeur (512) est une puissance de 2, la taille réelle du bloc est également de 512. Si, au lieu de cela, 520 était donné, la taille du bloc logique serait de 512 (la plus grande puissance de 2 inférieure à 520) et la taille réelle du bloc serait de 520 octets. Pour envoyer la variante de 32 octets, ajoutez --32, comme ceci :


sg_write_x --atomic=0 --32 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Pour des exemples utilisant 'sg_write_x --same=NDOB', consultez la page de manuel de sg_write_same(8). La syntaxe est légèrement différente mais la sémantique est la même.

Pour envoyer une commande WRITE STREAM(32) avec un STR_ID de 1, utilisez la commande suivante :


sg_write_x --stream=1 --32 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Voici une commande WRITE SCATTERED(16) avec la liste de dispersion, répartie entre les options --lba= et --num=, sur la ligne de commande :


sg_write_x --scattered=2 --lba=2,0x33 --num=4,1 -i /dev/zero /dev/sg1

Exemple de commande WRITE SCATTERED(16) avec un descripteur de plage LBA dégénéré (premier élément pour --lba= et --num=) :


sg_write_x --scattered=2 --lba=0,0x33 --num=0,1 -i /dev/zero /dev/sg1

Exemple de commande WRITE SCATTERED(16) avec la liste de dispersion dans scat_file.txt


sg_write_x --scattered=3 -q scat_file.txt -i /dev/zero /dev/sg1

Ensuite, une commande WRITE SCATTERED(16) avec sa liste de dispersion et ses données dans un seul fichier. Notez que l'argument de --scattered= est 0, donc le nombre de descripteurs de plage LBA est calculé en analysant les deux premiers blocs de scat_data.bin (car l'argument de --combined= est 2) :


sg_write_x --scattered=0 --combined=2 -i scat_data.bin /dev/sg1

Lorsque l'option -xx est utilisée, une commande WRITE SCATTERED n'est pas exécutée, mais le contenu du tampon de données sortantes est écrit dans un fichier nommé sg_write_x.bin. Dans le cas de WRITE SCATTERED, ce fichier binaire convient pour être fourni à une invocation ultérieure afin d'effectuer l'écriture réelle sur le média. Par exemple :


$ sg_write_x --scattered=3 -q scat_file.txt -xx -i /dev/zero /dev/sg1
Wrote 8192 bytes to sg_write_x.bin, LB data offset: 1
Number of LBA range descriptors: 3


sg_write_x --scattered=0 --combined=1 -i sg_write_x.bin /dev/sg1

Notez que lors de l'écriture de sg_write_x.bin (et rien n'est écrit sur le média), un résumé de ce qui s'est passé est envoyé à la sortie standard. La valeur affichée pour "LB data offset:" (1) doit être fournie à l'option --combined= lorsque l'écriture sur le média a lieu effectivement (c'est-à-dire la deuxième invocation montrée directement ci-dessus).
