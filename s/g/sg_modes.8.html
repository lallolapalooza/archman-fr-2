NOM

sg_modes - lit les pages de mode avec la commande SCSI MODE SENSE

SYNOPSIS

sg_modes [--all] [--ALL] [--control=PC] [--dbd] [--dbout] [--examine] [--flexible] [--help] [--hex] [--list] [--llbaa] [--maxlen=LEN] [--multiple] [--page=PG[,SPG]] [--raw] [-R] [--readwrite] [--six] [--verbose] [--version] [PÉRIPHÉRIQUE]

sg_modes [-6] [-a] [-A] [-c=PC] [-d] [-D] [-e] [-f] [-h] [-H] [-l] [-L] [-m=LEN] [-M] [-p=PG[,SPG]] [-r] [-subp=SPG] [-v] [-V] [-w] [-?] [PÉRIPHÉRIQUE]

DESCRIPTION

Cet utilitaire envoie une commande SCSI MODE SENSE au PÉRIPHÉRIQUE et affiche la réponse. Il existe une variante en 6 octets et une en 10 octets (cdb) pour la commande MODE SENSE, cet utilitaire utilise par défaut la variante 10 octets. La norme SPC-4 (et la norme SPC-5) stipule que les implémenteurs doivent abandonner les commandes SCSI MODE SELECT(6) et MODE SENSE(6) au profit des variantes 10 octets (par exemple, MODE SENSE(10)). Dans la version préliminaire SPC-6, révision 7, les commandes SCSI MODE SELECT(6) et MODE SENSE(6) ont été supprimées.

Cet utilitaire décode les en-têtes de pages de mode et les descripteurs de bloc mais affiche le contenu de chaque page de mode en hexadécimal. Il n'a pas non plus la capacité de modifier le contenu des pages de mode ou les données des descripteurs de bloc. Le contenu des pages de mode est décodé et peut être modifié avec l'utilitaire sdparm.

Cet utilitaire prend en charge deux syntaxes de ligne de commande, la syntaxe préférée est présentée en premier dans le synopsis et expliquée dans cette section. Une section ultérieure sur l'ancienne syntaxe de ligne de commande décrit le deuxième groupe d'options.

Si aucune page n'est spécifiée (et que --list n'est pas sélectionné) alors --all est supposé. L'option --all demande toutes les pages de mode (mais pas les sous-pages) dans une seule réponse.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-a, --all
affiche toutes les pages de mode signalées par le PÉRIPHÉRIQUE. C'est ce que la page code 63 (0x3f) est définie pour faire. Lorsqu'elle est utilisée une fois, les sous-pages de mode ne sont pas récupérées. Lorsqu'elle est utilisée deux fois (par exemple, '-aa'), toutes les pages de mode et sous-pages sont demandées, ce qui équivaut à '--page=63,255'.
-A, --ALL
même signification que l'utilisation de l'option --all deux fois. C'est-à-dire que toutes les pages de mode et sous-pages sont récupérées. Par défaut, toutes les pages de mode sont récupérées mais pas les sous-pages de mode.
-c, --control=PC
PC est la valeur de contrôle de page. Jusqu'à quatre versions différentes de chaque page sont conservées par le périphérique :
0 : valeurs actuelles (c'est-à-dire celles actives actuellement)
1 : valeurs modifiables
2 : valeurs par défaut (c'est-à-dire les paramètres du fabricant)
3 : valeurs sauvegardées
Les valeurs modifiables sont des masques de bits montrant quels champs pourraient être modifiés avec un MODE SELECT. Les valeurs sauvegardées seront rétablies la prochaine fois que le périphérique sera alimenté ou réinitialisé. Si cette option n'est pas donnée, les valeurs actuelles [0] sont supposées.
-d, --dbd
désactive les descripteurs de bloc. Par défaut, les descripteurs de bloc (généralement un (pour les disques) ou aucun) sont retournés dans une réponse MODE SENSE. Cette option définit le bit « disable block descriptors » (DBD) dans le cdb, ce qui indique au périphérique de ne pas retourner de descripteurs de bloc dans sa réponse. Les périphériques plus anciens peuvent ne pas prendre en charge ce paramètre et retourner une clé de diagnostic « illegal request » ; alternativement, ils peuvent l'ignorer. Curieusement, l'ensemble de commandes de blocs réduits (RBC) requiert que ce bit soit défini.
-D, --dbout
désactive l'affichage des descripteurs de bloc. Indépendamment de la présence ou non de descripteurs de bloc dans la réponse, ils ne sont pas affichés.
-e, --examine
si l'option --page=PG[,SPG] n'est pas donnée, examine chaque page de mode dans la plage de 0 à 62 (inclus). Si l'option --page=PG[,SPG] est donnée, alors toutes les sous-pages dont le code de page est PN sont examinées (sous-pages 0 à 254 (inclus)). Si une réponse est donnée, affichez le nom de la page de mode (sous-page) ou le numéro (en hexadécimal) si le nom n'est pas connu.
L'utilitaire sdparm, qui liste les pages de mode et VPD, a également une option --examine avec une fonctionnalité similaire.
-f, --flexible
Certains périphériques, ponts et/ou pilotes tentent des traductions rudimentaires entre les commandes MODE SENSE 6 et 10 octets sans corriger la réponse. Cela entraînera une mauvaise interprétation de la réponse (généralement avec une erreur indiquant que la réponse est mal formée). Avec cette option, la longueur de la réponse est vérifiée, et si elle semble erronée, la réponse est ensuite décodée comme si l'autre mode sense (longueur de cdb) avait été envoyée.
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
Puisque cet utilitaire montre la structure d'une réponse de commande MODE SENSE (c'est-à-dire son en-tête de paramètre, zéro ou plusieurs descripteurs de bloc suivis de zéro ou plusieurs pages de mode) mais affiche la plupart du contenu de la réponse en hexadécimal. Lorsque cette option est utilisée une fois, la seule différence est que le nom de la page de mode, s'il est connu, est suivi de son numéro de page (et numéro de sous-page) entre parenthèses en hexadécimal.
Lorsque cette option est donnée deux fois, alors chaque ligne de sortie hexadécimale a un rendu ASCII de ce hexadécimal à la fin de chaque ligne. Lorsque cette option est donnée trois fois, alors l'adresse hexadécimale, affichée au début de chaque ligne hexadécimale, est supprimée, il n'y a pas de rendu ASCII de l'hexadécimal, et toutes les lignes de texte sont supprimées. Il ne reste qu'un hexadécimal simple et analysable qui représente la réponse de la commande MODE SENSE. Les parties composantes de cette réponse sont mises sur des lignes séparées.
Lorsque l'option est donnée quatre fois ou plus (recommandé pour une forme analysable), les lignes d'informations ASCII sont de retour, mais elles commencent toutes par « # » que le parseur doit ignorer. La sortie est envoyée à stdout tandis que les messages d'erreur ou d'avertissement sont envoyés à stderr. Ainsi, une simple redirection de stdout vers un fichier depuis la ligne de commande Unix (faite avec '>' dans la plupart des shells Unix) devrait suffire à capturer la sortie. Comme mentionné ci-dessus, l'utilitaire sdparm peut être utilisé pour décoder ce fichier hexadécimal plus tard avec son option '--inhex=FN'.
-l, --list
liste tous les codes de page et sous-page courants et leurs noms qui se trouvent dans l'ensemble de commandes correspondant au type de périphérique du PÉRIPHÉRIQUE donné. Si aucun PÉRIPHÉRIQUE et aucune option --page=PG ne sont donnés, alors les codes de page et sous-page courants et leurs noms sont listés pour SBC (par exemple, un disque). Si aucun PÉRIPHÉRIQUE n'est donné et qu'une option --page=PG est donnée, alors les codes de page et sous-page courants et leurs noms sont listés pour l'ensemble de commandes dont le type de périphérique correspond à la valeur donnée à PG. Par exemple, 'sg_mode --list --page=1' liste les pages de mode et sous-pages de commandes pour les périphériques à bande. De plus, si un sous_page_code est donné, il est interprété comme un identifiant de transport et les codes de page spécifiques au transport de commande et leurs noms sont listés après la liste principale des pages de mode. Les autres options sont ignorées.
-L, --llbaa
définit le bit Long LBA Accepted (LLBAA) dans le cdb MODE SENSE (10). Ce bit n'est pas défini dans le cdb MODE SENSE (6), donc la définition des options '-L' et '--six' est signalée comme une erreur. Lorsqu'il est défini, le PÉRIPHÉRIQUE peut répondre avec des descripteurs de bloc de 16 octets comme indiqué par le champ 'LongLBA' dans la réponse. Dans la plupart des cas, la définition de cette option n'est pas nécessaire.
-m, --maxlen=LEN
L'argument LEN est la longueur de réponse maximale en octets. C'est le champ 'allocation length' dans le cdb. Lorsqu'il n'est pas donné (ou si LEN est zéro), le champ d'allocation de longueur est défini à 4096 pour MODE SENSE (10) ou 252 pour MODE SENSE (6). L'argument LEN doit être non négatif et ne pas dépasser 65535 pour MODE SENSE (10) et ne pas dépasser 255 pour MODE SENSE (6).
-M, --multiple
pour chaque page de mode (et sous-page de mode), récupère toutes les ...

available page controls. Il peut y avoir jusqu'à quatre contrôles de page, comme décrit dans l'option --control=PC. Les descripteurs d'en-tête et de bloc de mode sont produits de la même manière qu'en l'absence de cette option. Après le nom de la page de mode (et les numéros) sont affichés, il y a une ligne avec soit le contrôle de page actuel, modifiable, par défaut ou sauvegardé, suivie de ce contrôle de page en hexadécimal.
Si l'option --control=PC est donnée, elle est remplacée par cette option.
-O, --old
Basculer vers les options de style ancien. Veuillez l'utiliser comme première option.
-p, --page=PG
Code de page à récupérer. PG est supposé être une valeur décimale à moins qu'il ne soit préfixé par '0x' ou qu'il ait un 'h' final. Il doit s'agir d'une valeur comprise entre 0 et 63 (inclus). Lorsqu'elle n'est pas donnée et qu'un défaut est requis, une valeur de 63 (0x3f), qui récupère toutes les pages de mode, est utilisée.
Alternativement, un acronyme pour la page de mode peut être donné. Les acronymes disponibles peuvent être listés avec l'option --page=xxx. Ils sont presque identiques aux acronymes utilisés pour les pages de mode dans l'utilitaire sdparm.
-p, --page=PG,SPG
Codes de page et de sous-page à récupérer. Les deux arguments sont supposés être décimaux à moins qu'ils ne soient marqués comme hexadécimaux. Le code de page doit être compris entre 0 et 63 inclus. Le code de sous-page doit être compris entre 0 et 255 inclus. La valeur par défaut pour le code de sous-page est 0.
-r, --raw
Sortir la réponse en binaire vers stdout. Les messages d'erreur et les avertissements, le cas échéant, sont envoyés vers stderr. Lorsque cette option est utilisée deux fois (par exemple, '-rr'), elle a la même action que '-R'.
-R
Sortir la page de mode sélectionnée vers stdout, un octet par ligne. Chaque ligne contient deux chiffres hexadécimaux (par exemple, "3e"). Utile comme entrée (après édition) pour l'utilitaire sg_wr_mode(8).
-w, --readwrite
Ouvrir DEVICE en mode "lecture-écriture". Le défaut est de l'ouvrir en mode lecture seule.
-6, -s, --six
Par défaut, cet utilitaire envoie une commande MODE SENSE de 10 octets au DEVICE. Cependant, certains périphériques SCSI ne prennent en charge que les commandes MODE SENSE de 6 octets (par exemple, les lecteurs de bande SCSI-2). Ce paramètre force l'utilisation de commandes MODE SENSE de 6 octets.
-v, --verbose
Augmenter le niveau de verbosité. Peut être utilisé plusieurs fois.
-V, --version
Afficher la chaîne de version puis quitter.

NOTES

Si l'utilitaire sg_modes normal échoue avec "illegal command operation code", essayez l'option '--six' (ou '-6').

Cet utilitaire effectue une commande SCSI INQUIRY pour déterminer le type de périphérique du DEVICE (par exemple, 0 -> Direct Access Device (disque)) avant d'envoyer une commande MODE SENSE. Cela aide à décoder le descripteur de bloc et les pages de mode.

Cet utilitaire ouvre DEVICE en mode lecture seule (par exemple, sous Unix, avec le drapeau O_RDONLY) par défaut. Il ouvrira DEVICE en mode lecture-écriture si l'option --readwrite est donnée.

Dans la série 2.4 des noyaux Linux, le DEVICE doit être un périphérique générique SCSI (sg). Dans la série 2.6, les périphériques de bloc (par exemple, disques SCSI et lecteurs DVD) peuvent également être spécifiés. Par exemple, "sg_modes -a /dev/sda" fonctionnera dans les noyaux de la série 2.6.

Il n'y a pas de sortie JSON de cet utilitaire car sa sortie principale est constituée de pages de mode en hexadécimal. Ainsi, à part le nom de la page de mode et sa structure, rien n'est décodé. L'utilitaire sdparm décode le contenu des pages de mode et prend en charge la sortie JSON.

STATUT DE SORTIE

Le statut de sortie de sg_modes est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE PLUS ANCIENNES

Les options dans cette section étaient les seules disponibles avant la version 1.23 de sg3_utils. Depuis lors, cet utilitaire utilise par défaut les options de ligne de commande plus récentes qui peuvent être remplacées en utilisant --old (ou -O) comme première option. Voir la section VARIABLES D'ENVIRONNEMENT pour une autre façon de forcer l'utilisation de ces anciennes options de ligne de commande.

-6
Par défaut, cet utilitaire envoie une commande MODE SENSE de 10 octets au DEVICE. Ce paramètre force l'utilisation de commandes MODE SENSE de 6 octets. Voir --six dans la description principale.
-a
Voir --all dans la description principale.
-A
Sortir toutes les pages et sous-pages de mode prises en charge par le DEVICE. Identique à '--all --all' dans la nouvelle syntaxe.
-c=PC
PC est la valeur du contrôle de page. Voir --control=PC dans la description principale.
-d
Voir --dbd dans la description principale.
-D
Voir --dbout dans la description principale.
-e
Voir --examine dans la description principale.
-f
Voir --flexible dans la description principale.
-h
L'action par défaut est de décoder les numéros de page de mode connus (et les numéros de sous-page) en texte. Avec cette option, les numéros de page de mode (et les numéros de sous-page) sont affichés en hexadécimal.
-H
Même action que l'option '-h'.
-l
Voir --list dans la description principale.
-L
Voir --llbaa dans la description principale.
-N, --new
Basculer vers les options de style plus récent.
-m=LEN
Voir --maxlen=LEN dans la description principale.
-M
Voir --multiple dans la description principale.
-p=PG
PG est le code de page à récupérer. Doit être un nombre hexadécimal entre 0 et 3f inclus (0 à 63 décimal). La valeur par défaut lorsqu'elle est requise est 3f (récupérer toutes les pages de mode). Notez qu'un acronyme pour la page et/ou la sous-page n'est pas accepté dans ce format plus ancien (car tout acronyme commençant par les lettres 'a' à 'f' est ambigu ; il peut s'agir d'un nombre hexadécimal ou d'un acronyme).
-p=PG,SPG
Codes de page et de sous-page à récupérer. Le code de page doit être un nombre hexadécimal entre 0 et 3f inclus. Le code de sous-page doit être un nombre hexadécimal entre 0 et ff inclus. La valeur par défaut pour le code de sous-page est 0.
-r
Sortir la page de mode sélectionnée vers stdout, un octet par ligne. Chaque ligne contient deux chiffres hexadécimaux (par exemple, "3e"). Utile comme entrée (après édition) pour l'utilitaire sg_wr_mode(8).
-subp=SPG
Code de sous-page à récupérer. Doit être un nombre hexadécimal entre 0 et 0xff inclus. La valeur par défaut est 0.
-v
Augmenter la verbosité de la sortie.
-V
Afficher la chaîne de version puis quitter.
-w
Voir --readwrite dans la description principale.
-?
Afficher le message d'utilisation puis quitter. Ignorer tous les autres paramètres.

VARIABLES D'ENVIRONNEMENT

Depuis la version 1.23 de sg3_utils, la variable d'environnement SG3_UTILS_OLD_OPTS peut être définie. Lorsqu'elle est présente, cet utilitaire attendra les options de ligne de commande plus anciennes. Ainsi, la présence de cette variable d'environnement équivaut à utiliser --old (ou -O) comme première option de ligne de commande.

EXEMPLES

Toutes les pages de mode, mais pas les sous-pages de mode, peuvent être extraites en hexadécimal dans un fichier comme ceci :


# sg_modes -a -HHHH /dev/sdb > modes_sdeb.hex

S'il y a des erreurs, elles sont envoyées à stderr, elles apparaîtront donc sur la console et non dans le fichier modes_sdeb.hex. Néanmoins, le contenu de modes_sdeb.hex peut ne pas être utile si une erreur s'est produite.

L'option '-HHHH' produit une sortie hexadécimale avec des lignes de commentaires commençant par un caractère '#'. Chaque commentaire décrit le bloc suivant. Si tout va bien, le fichier modes_sdeb.hex sera adapté pour que l'utilitaire sdparm le décode :


# sdparm -a --inhex=modes_sdeb.hex

Voir la page de manuel sdparm(8) pour plus d'informations.
Pour extraire les pages de mode et les sous-pages, utilisez cette invocation :


# sg_modes -aa -HHHH /dev/sdb > modes_sdeb.hex

Aucun changement n'est nécessaire dans l'appel sdparm associé. Il y a des exemples de sortie dans le répertoire inhex du package sg3_utils, dans un fichier appelé : modes_sdeb.hex. Le fichier a été produit en utilisant cet utilitaire sur le pilote scsi_debug sous Linux.

Chaque page de mode (et sous-page) a jusqu'à quatre 'contrôles de page' : actuel, modifiable, par défaut et sauvegardé. Ces trois derniers peuvent ou non être pris en charge par le périphérique. Tous les contrôles de page disponibles pour toutes les pages et sous-pages de mode peuvent être placés dans un fichier hexadécimal avec cette invocation :


# sg_modes -aa -M -HHHH /dev/sdb > modes_mm_sdeb.hex

Encore une fois, aucun changement n'est nécessaire dans l'appel sdparm associé. Il y a des exemples de sortie dans le répertoire inhex du package sg3_utils, dans un fichier appelé : modes_mm_sdeb.hex.
