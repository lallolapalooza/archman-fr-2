NOM

sg_requests - envoie une ou plusieurs commandes SCSI REQUEST SENSE

SYNTAXE

sg_requests [--desc] [--error] [--help] [--hex] [--maxlen=LEN] [--num=NUM] [--number=NUM] [--progress] [--raw] [--status] [--time] [--timeout=SE] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Envoie une commande SCSI REQUEST SENSE au PÉRIPHÉRIQUE et affiche les données de paramètre de réponse attendues au format de données de détection (sense data). Les deux formats de données de détection, fixe et descripteur, sont pris en charge.

Plusieurs commandes REQUEST SENSE peuvent être envoyées avec l'option --num=NUM. Ceci peut être utilisé à des fins de chronométrage ou pour surveiller l'indication de progression.

OPTIONS

Les arguments des options longues sont obligatoires, tout comme pour les options courtes.

-d, --desc
définit le bit DESC dans le CDB de REQUEST SENSE. Le PÉRIPHÉRIQUE doit renvoyer les données de détection au format descripteur (plutôt que fixe). Cela ne se produira que si le PÉRIPHÉRIQUE reconnaît le format descripteur (SPC-3 et versions ultérieures). Si le périphérique est antérieur à SPC-3, la définition d'un bit dans un champ réservé peut provoquer un statut de condition de détection avec une clé de détection de requête illégale, mais sera très probablement ignorée.
-e, --error
lorsqu'il est utilisé une fois, il change l'opcode de REQUEST SENSE de 0x3 à 0xff, ce qui devrait être rejeté par le PÉRIPHÉRIQUE. Il y a une faible chance que le fournisseur du périphérique ait implémenté une commande spécifique au fournisseur à cet opcode (0xff). Lorsqu'il est utilisé deux fois, l'appel de passage pour envoyer la commande SCSI est contourné. L'idée ici est de mesurer la surcharge de l'espace utilisateur de cette bibliothèque pour configurer et traiter la réponse d'une commande SCSI. Cette option sera généralement utilisée avec les options --num=NUM et --time où NUM est un grand nombre (par exemple 1000000).
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse en hexadécimal ASCII.
-m, --maxlen=LEN
où LEN est la longueur de réponse (maximale) en octets. Elle est placée dans le champ « longueur d'allocation » du CDB. Si elle n'est pas fournie (ou si LEN est zéro), 252 est utilisé. La valeur maximale de LEN est 255 (mais SPC-4 recommande 252).
-n, --num=NUM
exécute NUM commandes SCSI REQUEST SENSE, en s'arrêtant lorsque NUM est atteint ou qu'une erreur se produit. La valeur par défaut pour NUM est 1.
--number=NUM
même action que --num=NUM. Ajouté pour la compatibilité avec sg_turs.
-p, --progress
affiche l'indication de progression (un pourcentage) si disponible. Si --num=NUM est donné, NUM est supérieur à 1 et une indication de progression initiale a été détectée, alors cet utilitaire attend 30 secondes avant les vérifications ultérieures. Se termine lorsque NUM est atteint ou qu'il n'y a plus d'indications de progression. Ignore les options --hex, --raw et --time. Voir la section NOTES ci-dessous.
-r, --raw
affiche la réponse en binaire (vers stdout).
-s, --status
si la commande REQUEST SENSE s'est terminée sans erreur (tel qu'indiqué par son statut SCSI), alors le contenu des données de paramètre est analysé comme des données de détection et le statut de sortie est défini en conséquence. L'action par défaut (c'est-à-dire lorsque cette option n'est pas donnée) est d'ignorer le contenu des données de paramètre aux fins de la définition du statut de sortie. Certains types d'erreurs définissent une clé de détection de « AUCUNE DÉTECTION » (NO SENSE) avec des informations non nulles dans le code de détection supplémentaire (par exemple, le groupe de codes de seuil de prédiction d'échec dépassé) ; cela entraîne un statut de sortie de 10. Si la clé de détection est « AUCUNE DÉTECTION » et que asc et ascq sont tous deux nuls, alors le statut de sortie est défini à 0. Voir la page de manuel sg3_utils(8) pour les valeurs de statut de sortie.
-t, --time
chronomètre la ou les commandes SCSI REQUEST SENSE et calcule le nombre moyen d'opérations par seconde.
-T, --timeout=SE
où SE est le délai d'attente de chaque commande TEST UNIT READY. L'unité de SE est la seconde et si 0 est donné, il est mappé à 60 secondes, ce qui est la valeur par défaut. Une forme alternative d'option longue est --tmo=SE.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage). De plus, la réponse (si reçue) est affichée en ASCII-HEX. Utilisez cette option plusieurs fois pour une plus grande verbosité.
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Dans SCSI 1 et 2, la commande REQUEST SENSE était très importante pour le traitement des erreurs et des avertissements en SCSI. La capacité d'autosense rendait cette commande presque superflue.

Cependant, les projets de normes SCSI récents (par exemple SPC-4 révision 14 et SBC-3 révision 14) augmentent l'utilité de la commande REQUEST SENSE. Les conditions d'alimentation au ralenti et en veille (faible) peuvent être détectées avec cette commande.

La commande REQUEST SENSE n'est pas marquée comme obligatoire dans SPC-3 (c'est-à-dire pour tous les périphériques SCSI) mais est marquée comme obligatoire dans SBC-2 (c'est-à-dire pour les disques), SSC-3 (c'est-à-dire pour les bandes) et MMC-4 (c'est-à-dire pour les lecteurs CD/DVD/HD-DVD/BD).

La commande SCSI FORMAT pour les disques utilisée avec le bit IMMED défini est un exemple d'opération qui prend un temps considérable et exclut d'autres accès au média pendant ce temps. Le bit IMMED défini indique à la commande FORMAT de renvoyer le contrôle au client de l'application une fois que le format a commencé (voir SBC-3). Plusieurs commandes SCSI de longue durée associées aux lecteurs de bandes utilisent également l'indication de progression (voir SSC-3).

Les premières normes suggéraient que la commande SCSI TEST UNIT READY soit utilisée pour interroger l'indication de progression (voir l'utilitaire sg_turs). Depuis SPC-3, les normes suggèrent que la commande SCSI REQUEST SENSE devrait être utilisée à la place.

Le PÉRIPHÉRIQUE est ouvert avec un indicateur de lecture seule (par exemple, sous Unix avec l'indicateur O_RDONLY).

STATUT DE SORTIE

Le statut de sortie de sg_requests est 0 lorsqu'il réussit. Sinon, voir la page de manuel sg3_utils(8).
