NOM

sg_read_long - envoie une commande SCSI READ LONG

SYNTAXE

sg_read_long [--16] [--correct] [--help] [--lba=LBA] [--out=OF] [--pblock] [--readonly] [--verbose] [--version] [--xfer_len=BTL] APPAREIL

DESCRIPTION

Envoie une commande SCSI READ LONG à APPAREIL. Le tampon de lecture est affiché en hexadécimal et ASCII sur la sortie standard ou placé dans un fichier. Notez que les données renvoyées incluent les données du bloc logique (typiquement 512 octets pour un disque) plus les informations ECC (dont le format est propriétaire) plus éventuellement d'autres données propriétaires. Notez que les données du bloc logique peuvent être encodées ou cryptées.

Dans la révision 7 de SBC-4, les commandes SCSI READ LONG (10 et 16 octets) ont été rendues obsolètes. Dans la même révision, toutes les utilisations des commandes SCSI WRITE LONG (10 et 16 octets) ont été rendues obsolètes, à l'exception du cas où le bit WR_UNCOR est défini.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-S, --16
utilise une commande SCSI READ LONG(16). L'action par défaut est d'utiliser une commande SCSI READ LONG(10). La commande READ LONG(10) a un champ de 32 bits pour le LBA, tandis que READ LONG(16) a un champ de 64 bits.
-c, --correct
définit le bit 'CORRCT' dans la commande SCSI READ LONG. Lorsqu'il est défini, les données sont corrigées par l'ECC avant d'être renvoyées à cet utilitaire. Par défaut, le bit 'CORRCT' est effacé, auquel cas les données ne sont pas corrigées.
-h, --help
affiche le message d'utilisation puis quitte.
-l, --lba=LBA
où LBA est l'adresse de bloc logique du secteur à lire. Supposé être en décimal, sauf s'il est préfixé par '0x' (ou a un 'h' final). Par défaut, le LBA est 0. Si le LBA est plus grand que ce qui peut tenir dans 32 bits, l'option --16 devrait être utilisée.
-o, --out=OF
au lieu de générer de l'hexadécimal ASCII sur la sortie standard, l'envoie en binaire dans le fichier nommé OF. Si '-' est donné pour OF, la sortie (binaire) est envoyée sur la sortie standard. Notez que toutes les informations et messages d'erreur sont envoyés sur la sortie d'erreur.
-p, --pblock
définit le bit 'PBLOCK' dans la commande SCSI READ LONG. Lorsqu'il est défini, le bloc physique (plus les données ECC) contenant l'adresse de bloc logique demandée est lu. Par défaut, le bit 'PBLOCK' est effacé, auquel cas le bloc logique (plus toute donnée ECC) est lu.
-r, --readonly
ouvre l'APPAREIL en lecture seule plutôt qu'en lecture-écriture, ce qui est le défaut. Le pilote sg Linux nécessite un accès en lecture-écriture pour la commande SCSI READ LONG, mais d'autres méthodes d'accès peuvent nécessiter un accès en lecture seule.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
imprime la chaîne de version puis quitte.
-x, --xfer_len=BTL
où BTL est la longueur de transfert en octets (par défaut 520). Si la valeur donnée (ou la valeur par défaut) ne correspond pas à la taille du bloc "long" de l'appareil, le BTL approprié est déduit de la réponse d'erreur et affiché (sur la sortie d'erreur). L'idée est que l'utilisateur réessayera avec cet utilitaire en utilisant la longueur de transfert correcte.

NOTES

Si un bloc défectueux est trouvé et que son contenu, le cas échéant, a été récupéré, "sg_reassign" pourrait être utilisé pour cartographier le bloc défectueux. Associé à une telle action, le nombre d'éléments dans la liste des défauts "croissants" pourrait être surveillé (avec "sg_reassign --grown") car le disque pourrait approcher de la fin de sa durée de vie utile.

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section "ARGUMENTS NUMÉRIQUES" dans la page de manuel sg3_utils(8).

À titre indicatif, Fujitsu utilise un ECC de 54 octets (par bloc) capable de corriger jusqu'à une seule erreur en rafale ou 216 bits "à la volée". [Informations obtenues du manuel du produit MAV20xxrc.]

STATUT DE SORTIE

Le statut de sortie de sg_read_long est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
