NOM

sg_compare_and_write - envoie la commande SCSI COMPARE AND WRITE

SYNTAXE

sg_compare_and_write [--dpo] [--fua] [--fua_nv] [--grpnum=GN] [--help] --in=IF [--inw=WF] --lba=LBA [--num=NUM] [--quiet] [--timeout=TO] [--verbose] [--version] [--wrprotect=WP] [--xferlen=LEN] PÉRIPHÉRIQUE

DESCRIPTION

Envoie la commande SCSI COMPARE AND WRITE au PÉRIPHÉRIQUE. Cet utilitaire récupère un tampon de comparaison et un tampon d'écriture depuis un ou deux fichiers. Si l'option --inw=WF est donnée, le tampon de comparaison est récupéré du fichier indiqué par --in=IF tandis que le tampon d'écriture est récupéré du fichier indiqué par --inw=WF. Si l'option --inw=WF n'est pas donnée, les tampons de comparaison et d'écriture concaténés sont récupérés du fichier indiqué par l'option --in=IF.

Ces tampons sont censés contenir chacun NUM blocs de données. La comparaison commence à l'adresse de bloc logique LBA sur le PÉRIPHÉRIQUE et si la comparaison échoue (c'est-à-dire si le tampon de comparaison fourni ne correspond pas aux données à LBA sur le PÉRIPHÉRIQUE), la commande COMPARE AND WRITE se termine avec une clé de sens MISCOMPARE. Dans ce cas, cet utilitaire se terminera et définira un statut de sortie de 14 (ce qui correspond à la valeur de la clé de sens MISCOMPARE).

Si la comparaison réussit, le tampon d'écriture fourni est stocké en commençant à LBA pour NUM blocs sur le PÉRIPHÉRIQUE.

Le nombre réel d'octets transférés dans le tampon data-out de la commande COMPARE AND WRITE peut devoir être spécifié par l'utilisateur avec l'option --xferlen=LEN. LEN est par défaut (2 * NUM * 512) ce qui fait 1024 pour NUM par défaut de 1. Si la taille du bloc est différente de 512, l'utilisateur devra utiliser l'option --xferlen=LEN. Si des informations de protection sont fournies (indiqué par une valeur de WP autre que 0 (par défaut)) alors pour un NUM de 1, LEN devrait être de 1040. Notez que la commande SCSI READ CAPACITY n'est pas exécutée par cet utilitaire (par exemple, pour trouver la taille du bloc).

La définition T10 de la commande SCSI COMPARE AND WRITE exige que le PÉRIPHÉRIQUE implémente la comparaison et l'écriture optionnelle comme une série d'actions ininterrompues. Selon d'autres paramètres du PÉRIPHÉRIQUE, une opération de vérification peut survenir avant la comparaison.

Lorsqu'une discordance survient entre le tampon de comparaison et les blocs commençant à LBA lus depuis le PÉRIPHÉRIQUE, le tampon de sens contenant la clé de sens MISCOMPARE provoque l'envoi de plusieurs messages vers stderr (y compris le décalage du premier octet de discordance). Pour supprimer ces messages, utilisez l'option --quiet. Avec ou sans l'option --quiet, le statut de sortie sera défini à 14.

Cette commande est définie dans SBC-3 dont la révision la plus récente est 36. SBC-3 et d'autres documents SCSI peuvent être trouvés sur https://www.t10.org .

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont arrangées par ordre alphabétique basé sur le nom de l'option longue.

-d, --dpo
Définit le bit DPO dans le CDB COMPARE AND WRITE
-f, --fua
Définit le bit FUA dans le CDB COMPARE AND WRITE
-F, --fua_nv
Définit le bit FUA_NV dans le CDB COMPARE AND WRITE. Ce bit a été supprimé dans la révision SBC-3 35d et sa position est marquée comme "réservée".
-g, --grpnum=GN
où GN est la valeur à placer dans le champ numéro de groupe du CDB COMPARE AND WRITE.
-h, --help
affiche le message d'utilisation puis quitte.
-i, --in=IF
lit les données (binaires) depuis le fichier nommé IF. Ce sera soit les tampons de comparaison et d'écriture combinés (lorsque l'option --inw=WF n'est pas donnée), soit uniquement le tampon de comparaison (lorsque l'option --inw=WF est donnée). Si IF est '-', alors stdin (par exemple un pipe) est lu.
-C, --inc=IF
Identique à l'option --in.
-D, --inw=WF
lit les données (binaires) depuis le fichier nommé WF. Ce sera le tampon d'écriture qui constituera la seconde moitié du tampon data-out envoyé au PÉRIPHÉRIQUE associé à la commande COMPARE AND WRITE. Notez que lorsque cette option est donnée, il est attendu que --in=IF contienne le tampon de comparaison associé.
-l, --lba=LBA
où LBA est l'adresse de bloc logique à partir de laquelle la commande COMPARE AND WRITE commencera. Est supposée être en décimal sauf si elle est précédée de '0x' ou a un suffixe 'h'.
-n, --num=NUM
où NUM est le nombre de blocs, à partir de LBA, à lire et comparer avec l'instance de vérification. Et si une correspondance est trouvée, le nombre de blocs à écrire commençant à LBA. La valeur par défaut pour NUM est 1.
-q, --quiet
supprime les messages du tampon de sens associés à une clé de sens MISCOMPARE qui seraient autrement envoyés à stderr. Définit toujours le statut de sortie à 14, qui est la valeur de la clé de sens indiquant un MISCOMPARE.
-t, --timeout=TO
où TO est la valeur du délai d'attente de la commande en secondes. La valeur par défaut est 60 secondes. Si NUM est grand (ou zéro), une commande WRITE SAME peut nécessiter considérablement plus de 60 secondes pour s'achever.
-v, --verbose
augmente le degré de verbosité (messages de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wrprotect=WP
définit le champ WRPROTECT dans le cdb à WP. La valeur par défaut est 0, ce qui implique qu'aucune information de protection n'est envoyée (avec les données utilisateur) par cet utilitaire.
-x, --xferlen=LEN
où LEN est la longueur du tampon data-out en octets. Elle est par défaut de (2 * NUM * 512) octets. Si la taille du bloc du PÉRIPHÉRIQUE est différente de 512 octets ou si WP est non nul (impliquant des informations de protection supplémentaires), alors cette valeur par défaut sera incorrecte ; l'utilisateur doit fournir la valeur correcte pour LEN.

NOTES

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section "ARGUMENTS NUMÉRIQUES" dans la page de manuel sg3_utils(8).

# sg_dd if=/dev/sg1 bs=512 of=backup01.bin count=2
2+0 enregistrements lus
2+0 enregistrements écrits

ATTENTION : si /dev/sg1 correspond à un disque de votre système contenant des systèmes de fichiers actuellement montés, ne continuez pas. Si possible, démontez tous les systèmes de fichiers de ce disque. Si cela n'est pas possible, utilisez un autre disque sans systèmes de fichiers montés. Sous Linux, le pilote scsi_debug est un bon candidat pour l'expérimentation.

1+0 enregistrements écrits

sg_compare_and_write(8)

NAME

sg_compare_and_write - performs SCSI COMPARE AND WRITE command

SYNOPSIS

sg_compare_and_write [OPTIONS] DEVICE

DESCRIPTION

This utility uses the SCSI COMPARE AND WRITE command (opcodes 0xc7, 0x02) to compare data from the input file with a block of data on the storage device and, if they are identical, write the data from the input file to that block. This is a combined operation that is usually atomic.

The command requires that the data on the device and the data in the input file are identical for the write to occur. If they are not identical, the write is inhibited and the command fails.

The data block on the storage device is identified by the Logical Block Address (LBA) and the number of blocks (which must be 1).

OPTIONS

--in=FILE
Read data from FILE. This file should contain the data to be written to the storage device. If FILE is given as "-" then standard input is used.
--lba=LLBA
The Logical Block Address (LBA) where the operation should start. Defaults to 0.
--num=N
The number of blocks to compare and write. This value must be 1 for the SCSI COMPARE AND WRITE command.
--verbose=N
Increase verbosity. 0 means no output, 1 means errors, 2 means informational messages, etc. Defaults to 1.
--help
Print out the usage message and exit.
--version
Print the version string and then exit.

NOTES

This command is most useful for security overwrites where you want to ensure that the data is truly gone. For example, you could fill a block with zeros, then use the compare and write command to overwrite it with random data.

The SCSI COMPARE AND WRITE command expects to compare and write a single block (i.e. --num=1). The size of the block is determined by the device's logical block size.

EXAMPLES

First, create a file with 512 bytes of 0xff:


# dd if=/dev/zero bs=512 count=1 | tr '\000' '\377' > ff00.bin
# echo $?
0

Now, write this file to LBA 0 of /dev/sg1, but first check if LBA 0 is all zeros. The command will fail because LBA 0 is not all zeros:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1
Miscompare at byte offset: 0 [0x0]
sg_compare_and_write failed: Miscompare

Now, overwrite LBA 0 with the contents of ff00.bin. This will succeed because the previous command failed and thus did not write anything. It will also overwrite the previous content of LBA 0 with the 0xff bytes:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1

Now, LBA 0 and ff00.bin are equal (they should be both full of 0xff bytes). Since the compare succeeds, it will write the second block in ff00.bin over LBA 0:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1

No news is good news. Now if we do that command again:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1
Miscompare at byte offset: 0 [0x0]
sg_compare_and_write failed: Miscompare

This is expected. The first sg_compare_and_write ended up writing 0x0 bytes over LBA 0x0. The second sg_compare_and_write command compares LBA 0x0 with 0xff bytes and fails immediately (i.e. at byte offset: 0). Now we will overwrite the first 3 bytes of ff00.bin with 0x0:


# sg_dd bs=1 iflag=00 of=ff00.bin count=3
3+0 records in
3+0 records out

Notice the 'bs=1' operand. The dd utility (and thus sg_dd) is very useful for doing small binary edits on a file. Now if we do that sg_compare_and_write again, it still fails but with a small difference:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1
Miscompare at byte offset: 3 [0x3]
sg_compare_and_write failed: Miscompare

So the bytes at offset 0, 1, and 2 compared equal but not the byte at offset 3. The SCSI COMPARE AND WRITE will stop on the first micompared byte.

EXIT STATUS

The exit status of sg_compare_and_write is 0 when it is successful. If the compare step fails then the exit status is 14. For other exit status values see the EXIT STATUS section in the sg3_utils(8) man page.

Earlier versions of this utility set an exit status of 98 when there was a MISCOMPARE.
