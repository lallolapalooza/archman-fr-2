NOM

sg_get_config - envoie une commande SCSI GET CONFIGURATION (MMC-4 +)

SYNTAXE

sg_get_config [--brief] [--current] [--help] [--hex] [--inner-hex] [--list] [--raw] [--readonly] [--rt=RT] [--starting=FC] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Envoie une commande SCSI GET CONFIGURATION au PÉRIPHÉRIQUE et décode la réponse. La réponse inclut les fonctionnalités et les profils du périphérique. Typiquement, ces périphériques sont des lecteurs CD, DVD, HD-DVD et BD qui peuvent (mais pas nécessairement) contenir un média. Ces périphériques peuvent être connectés via des transports ATAPI, USB ou IEEE 1394. Dans de tels cas, ils ne sont « SCSI » que dans le sens où ils utilisent l'ensemble de commandes « Multi-Media command » (MMC). MMC est un ensemble de commandes SCSI spécialisé dont la définition peut être trouvée sur https://www.t10.org.

Cet utilitaire est basé sur les brouillons des normes MMC-4 et suivantes. Voir la section 5 sur « Features and Profile for Multi_Media devices » pour plus d'informations sur les paramètres de fonctionnalités spécifiques et les profils. Le manuel du fabricant du produit peut également être utile.

Étant donné que les graveurs DVD et BD modernes prennent en charge de nombreuses fonctionnalités et profils, la sortie décodée de cet utilitaire peut être volumineuse. Il existe plusieurs façons de réduire la sortie. Si l'option --brief est utilisée, seuls les noms des fonctionnalités sont affichés et les paramètres des fonctionnalités ne sont pas décodés. Alternativement, si une seule fonctionnalité est d'intérêt, cette combinaison d'options est appropriée : « --rt=2 --starting=FC ». Une autre possibilité est de n'afficher que les fonctionnalités pertinentes pour le média dans le lecteur (c'est-à-dire « current ») avec l'option « --rt=1 ».

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-b, --brief
affiche les noms des fonctionnalités mais ne décode pas les paramètres de ces fonctionnalités. Lorsqu'elle est utilisée avec --list, elle affiche les noms des fonctionnalités connues mais pas les noms des profils connus.
-c, --current
affiche les fonctionnalités marquées comme « current ». Cette option est équivalente à « --rt=1 ».
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse en hexadécimal (ne décode pas la réponse).
-i, --inner-hex
décode jusqu'au niveau du nom de la fonctionnalité puis affiche les données de chaque fonctionnalité en hexadécimal.
-l, --list
liste tous les noms de fonctionnalités et de profils connus. Ignore le nom du périphérique (s'il est donné). Liste simplement les noms des fonctionnalités et des profils (suivis de leurs valeurs hexadécimales) que cet utilitaire connaît. Si --brief est également donné, seuls les noms des fonctionnalités sont listés.
-q, --readonly
ouvre le PÉRIPHÉRIQUE en lecture seule plutôt qu'en lecture-écriture, ce qui est le comportement par défaut. Le pilote sg de Linux a besoin d'un accès en lecture-écriture pour la commande SCSI GET CONFIGURATION, mais d'autres méthodes d'accès peuvent nécessiter un accès en lecture seule.
-r, --rt=RT
où RT est le champ de ce nom dans le CDB GET CONFIGURATION. Les valeurs autorisées sont 0, 1, 2 ou 3. L'action de la commande dépend également de la valeur donnée à l'option --starting=FC. La valeur par défaut est 0. Lorsque RT est 0, toutes les fonctionnalités, qu'elles soient actives ou non, sont retournées (dont le code de fonctionnalité est supérieur ou égal à FC donné à --starting=). Lorsque RT est 1, toutes les fonctionnalités actives sont retournées (dont le code de fonctionnalité est supérieur ou égal à FC). Lorsque RT est 2, la fonctionnalité dont le code de fonctionnalité est égal à FC, le cas échéant, est retournée. Lorsque RT est 3, la réponse est réservée (probablement une erreur « champ illégal dans le cdb »). Pour simplifier, les significations des valeurs RT sont :
0 : toutes les fonctionnalités, actives ou non
1 : uniquement les fonctionnalités actives
2 : uniquement la fonctionnalité dont le code est FC
3 : réservé
-R, --raw
affiche la réponse en binaire (vers la sortie standard). Notez que la forme courte est -R contrairement à la plupart des autres utilitaires de ce paquet qui utilisent -r pour cette action.
-s, --starting=FC
où FC est la valeur du code de fonctionnalité. Cette option fonctionne étroitement avec l'option --rt=RT. La valeur FC est dans la plage 0 à 65535 (0xffff) inclusive. Sa valeur par défaut est 0. Une valeur précédée de « 0x » (ou d'un « h » à la fin) est interprétée comme hexadécimale.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Il existe plusieurs versions des normes (brouillons) MMC : MMC [1997], MMC-2 [2000], MMC-3 [2002], MMC-4 et MMC-5. Les trois premières sont maintenant des normes ANSI INCITS avec l'année de leur standardisation entre crochets. Le brouillon immédiatement avant la standardisation peut être trouvé sur https://www.t10.org. Dans la norme MMC initiale, il n'y avait pas de commande GET CONFIGURATION et les informations pertinentes étaient obtenues à partir de la « page de mode des capacités CD et état mécanique » (page de mode 0x2a). Elle a ensuite été renommée « page de mode des capacités MM et état mécanique » et a été rendue obsolète dans MMC-4 et MMC-5. La commande GET CONFIGURATION a été introduite dans MMC-2 et est devenue un remplacement pour cette page de mode. De nouvelles fonctionnalités telles que la prise en charge du type de média « BD » (blue ray) ne peuvent être trouvées qu'en utilisant la commande GET CONFIGURATION. Par conséquent, les anciens lecteurs CD peuvent ne pas prendre en charge la commande GET CONFIGURATION, auquel cas la page de mode « MM capabilities ... » peut être vérifiée avec sdparm(8), sginfo(8) ou sg_modes(8).

Dans la série 2.4 des noyaux Linux, le PÉRIPHÉRIQUE doit être un périphérique générique SCSI (sg). Dans la série 2.6, les périphériques bloc peuvent également être spécifiés. Par exemple, « sg_get_config /dev/hdc » fonctionnera dans les noyaux de la série 2.6 tant que /dev/hdc est un périphérique ATAPI. Dans la série 2.6, les graveurs DVD externes connectés via USB pourraient être interrogés avec « sg_get_config /dev/scd1 », par exemple.

STATUT DE SORTIE

Le statut de sortie de sg_get_config est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
