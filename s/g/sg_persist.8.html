NOM

sg_persist - utilise la commande SCSI PERSISTENT RESERVE pour accéder aux enregistrements et réservations

SYNTAXE

sg_persist [OPTIONS] PÉRIPHÉRIQUE

sg_persist [OPTIONS] --périphérique=PÉRIPHÉRIQUE

sg_persist --aide | --version

DESCRIPTION

Cet utilitaire permet de consulter et de modifier les réservations et enregistrements persistants. Les réservations et enregistrements persistants sont interrogés par des sous-commandes (appelées « actions de service » dans SPC-4) de la commande SCSI PERSISTENT RESERVE IN (PRIN). Les réservations et enregistrements persistants sont modifiés par des sous-commandes de la commande SCSI PERSISTENT RESERVE OUT (PROUT).

Il existe un processus en deux étapes pour obtenir une réservation persistante. Tout d'abord, une application (un nexus I_T selon la terminologie de la norme) doit enregistrer une clé de réservation. Si cela est accepté (et cela devrait l'être, sauf si un autre nexus I_T a enregistré cette clé), l'application peut alors tenter de réserver le périphérique. L'opération de réservation doit spécifier la clé de réservation et un « type » (voir l'option --type-prout=TYPE).

Il est relativement sûr de consulter l'état des réservations et enregistrements persistants. Sans aucune option, cet utilitaire utilise par défaut la sous-commande READ KEYS de la commande PRIN. Les autres sous-commandes PRIN sont READ RESERVATION, REPORT CAPABILITIES et READ FULL STATUS.

Avant d'essayer de modifier les réservations et enregistrements persistants, les utilisateurs doivent être conscients de ce qu'ils font. Les sections pertinentes du document SCSI Primary Commands (c'est-à-dire SPC-5 ANSI INCITS 502-2020) sont les sections 8.14 (intitulée « Reservations »), 9.16 (pour la commande PRIN) et 9.17 (pour la commande PROUT). Pour se prémunir contre une utilisation accidentelle, l'option --out doit être fournie lorsqu'une sous-commande PROUT (par exemple, --register) est utilisée.

Les anciennes commandes SCSI RESERVE et RELEASE (variantes 6 et 10 octets) ne sont pas prises en charge par cet utilitaire. Dans SPC-3, RESERVE et RELEASE sont dépréciées et remplacées par les réservations persistantes. RESERVE et RELEASE ont été supprimées de SPC-4 et l'annexe B présente comment convertir vers les commandes de réservation persistante. Voir un utilitaire appelé 'scsires' pour la prise en charge des commandes SCSI RESERVE et RELEASE.

PÉRIPHÉRIQUE doit être spécifié pour toutes les variantes de cet utilitaire, à l'exception de --aide et --version. Le PÉRIPHÉRIQUE peut être fourni soit comme argument (généralement, mais pas nécessairement après les options), soit via l'option --périphérique=PÉRIPHÉRIQUE.

SPC-4 n'utilise pas le terme « sous-commande ». Il utilise le terme « action de service » pour cela et pour une partie du nom d'un champ dans le bloc de paramètres associé à la commande PROUT (c'est-à-dire « clé de réservation d'action de service »). Afin de réduire la confusion potentielle, le terme « sous-commande » a été introduit.

TRANSPORT IDs

Les TransportIDs sont utilisés dans les réservations persistantes pour identifier les initiateurs. Le format d'un TransportID dépend du type de transport utilisé. Leur format est décrit dans SPC-4 (dans la révision 37 du projet, voir la section 7.6.4).

Un TransportID est requis pour la sous-commande PROUT 'enregistrer et déplacer' et la sous-commande PROUT 'enregistrer' peut avoir zéro, un ou plusieurs TransportIDs.

Lorsque l'option --transport-id=TIDS est fournie, l'argument TIDS peut être une liste d'octets hexadécimaux ASCII séparés par des virgules (ou un espace unique) représentant un seul TransportID tel que défini dans SPC-4. Alternativement, l'argument TIDS peut être une chaîne spécifique au transport commençant par « fcp, », « spi, », « sbp, », « srp, », « iqn », « sas, » ou « sop, ». La forme « iqn » est un nom qualifié iSCSI. À l'exception de « iqn », les autres chaînes de préfixe spécifiques au transport peuvent être en majuscules (par exemple, « FCP, »).

La forme « fcp, » doit être suivie de 16 chiffres hexadécimaux ASCII représentant le N_PORT_NAME d'un initiateur (par exemple, « fcp,10000000C9F3A571 »). La forme « spi, » doit être suivie de « <scsi_address>,<relative_target_port_identifier> » (deux nombres décimaux). La forme « sbp, » doit être suivie de 16 chiffres hexadécimaux ASCII représentant le nom EUI-64 d'un initiateur. La forme « srp, » doit être suivie de 32 chiffres hexadécimaux ASCII représentant un identifiant de port d'initiateur. La forme « sas, » doit être suivie de 16 chiffres hexadécimaux ASCII représentant l'adresse SAS du port d'un initiateur (par exemple, « sas,5000c50005b32001 »). La forme « sop, » prend un nombre hexadécimal représentant un identifiant de routage.

Il existe deux formes de nom qualifié iSCSI. La forme la plus courte contient le nom iSCSI du port d'initiateur (par exemple, « iqn.5886.com.acme.diskarrays-sn-a8675309 »). La forme la plus longue ajoute l'identifiant de session d'initiateur (ISID en hexadécimal) séparé par « ,i,0x ». Par exemple « iqn.5886.com.acme.diskarrays-sn-a8675309,i,0x1234567890ab ». Sur la ligne de commande, pour empêcher la ponctuation dans un nom iSCSI d'être (mal) interprétée par le shell, il est conseillé de placer l'argument de l'option contenant le nom iSCSI entre guillemets doubles. Les noms iSCSI sont encodés en UTF-8, donc si des caractères non ASCII (7 bits) apparaissent dans le nom iSCSI sur la ligne de commande, il y aura des difficultés s'ils ne sont pas encodés en UTF-8. La locale peut être modifiée temporairement en préfixant l'invocation de ligne de commande de sg_persist avec « LANG=en_US.utf-8 », par exemple.

sg_persist(8) — sg3_utils — Arch Linux

NAME

sg_persist — SCSI persist reservation utility

SYNOPSIS

sg_persist [OPTIONS] DEVICE

DESCRIPTION

This utility sends SCSI Persist Reserve IN (PR-IN) and Persist Reserve OUT (PR-OUT) commands to the given SCSI device. These commands are used to manage reservations on SCSI devices, primarily for SCSI-2 and SCSI-3 persistent reservations. This utility is part of the sg3_utils package.

The PR-IN command is used to read information about existing reservations or key identifiers. The PR-OUT command is used to create, modify, or delete reservations.

The DEVICE is typically a SCSI disk device like /dev/sdb, or a SCSI generic device like /dev/sg0. For older Linux kernels (2.4 series) it must be a SCSI generic device. For newer kernels (2.6 and later) it can be any SCSI device.

OPTIONS

Common options for all sg_utils utilities are available. Use sg_persist --help for a full list.

Most options are grouped into those that control the PR-IN commands and those that control the PR-OUT commands. Only one group can be active at a time.

PR-IN related options:

--in, -i
Selects the PR-IN command group. This is the default if no options are specified.
--read-keys, -r
Performs a READ KEYS (PR-IN) operation. This retrieves all active reservations (TransportID, ServiceAction and key) for the specified device.
--read-reservation, -R
Performs a READ RESERVATION (PR-IN) operation. This retrieves the current reservation on the device, including the reservation holder's TransportID, ServiceAction, and key.
--command=CMD
Specifies the PR-IN service action. Default is 0x0 (reserved). See SPC-4 for details.
--param-spsp=HEX
Sets the Spare_SPS field in the CDB. Default is 0.
--param-tpi=HEX
Sets the Transport_Prot_Ident field in the CDB. Default is 0.

PR-OUT related options:

--out, -o
Selects the PR-OUT command group.
--register, -R
Performs a REGISTER SERVICE ACTION OUT (PR-OUT) operation. This registers a new reservation key.
--reserve, -r
Performs a RESERVE (PR-OUT) operation. This establishes a reservation on the device.
--release, -z
Performs a RELEASE (PR-OUT) operation. This releases an existing reservation.
--clear, -c
Performs a CLEAR (PR-OUT) operation. This clears all reservations and registrations on the device.
--abort, -a
Performs an ABORT (PR-OUT) operation. This aborts reservations held by a specific initiator.
--preempt, -p
Performs a PREEMPT (PR-OUT) operation. This preempts an existing reservation.
--service-action=SA
Sets the Service Action field for PR-OUT commands. Default is 0. Valid values are 0 (reserved), 1 (Write Exclusive), 2 (Exclusive Access), 3 (Write Exclusive and Exclusive Access), 4 (Write Exclusive Registrants Only), 5 (Exclusive Access Registrants Only), 6 (Write Exclusive and Exclusive Access Registrants Only).
--param-rk=HEX
Sets the Reservation Key field in the CDB for PR-OUT commands. This key must match the key of the reservation being modified or released.
--param-aptpl=HEX
Sets the APTPL (All Persistent Transport Protocol Limits) field for PR-OUT commands. This is used with reservations to control access.
--prout-type=TYPE
Specifies the scope of the reservation for PR-OUT commands. Valid values are 0 (RESERVED), 1 (LU_SCOPE), 2 (ELEMENT_SCOPE). Default is 1 (LU_SCOPE).
--transport-id=TIDS
Specifies the TransportID for the reservation. This can be a comma, space, or tab separated list of ASCII hex bytes, or a file containing such a list. See the TRANSPORT IDs section for details.
--failover
Performs a failover reservation. This is a form of preempt.
--grace-period=SEC
Sets the grace period in seconds for preempt or clear operations.

Other options:

--readonly, -w
Open the device in read-only mode. This is useful if you only need to perform PR-IN operations.
--verbose, -v
Increase verbosity of output.
--help
Print usage information and exit.
--version
Print version information and exit.

TRANSPORT IDs

TransportIDs are used to identify initiators. They are typically strings that represent the connection path to the initiator. The format of the TransportID depends on the transport protocol (e.g., Fibre Channel, SAS, iSCSI).

The sg_persist utility supports two ways of providing TransportIDs:

Directly on the command line
The TransportID can be provided as a string directly using the --transport-id option. The string can be a comma, space, or tab-separated list of ASCII hex bytes representing the TransportID.
From a file
The TransportID can be specified using the format --transport-id=file=<name>. This will read the TransportID from the specified file <name>. The file should contain a comma, space, or tab-separated list of ASCII hex bytes.

The utility parses the input and builds a valid SPC-4 TransportID. It ignores empty lines and comments (lines starting with '#'). Leading spaces and tabs are also ignored. If the provided TransportID is shorter than 24 bytes, it will be padded with zero bytes to meet the minimum length.

In SPC-3, the SPEC_I_PT bit allowed TransportIDs for the PROUT register and ignore existing key sub-command. In SPC-4, this is disallowed, resulting in a CHECK CONDITION status with an ILLEGAL REQUEST sense key and an additional sense code set to INVALID FIELD IN PARAMETER LIST.

NOTES

In the 2.4 series of Linux kernels, the DEVICE must be a SCSI generic (sg) device. In the 2.6 series, any SCSI device name (e.g., /dev/sdc, /dev/st1m, or /dev/sg3) can be specified. For example, "sg_persist --read-keys /dev/sdb" will work in 2.6 series kernels.

The only scope for PROUT commands supported in the current draft of SPC-4 is "LU_SCOPE". Therefore, there seems to be no point in offering an option to set the scope to another value.

Most errors with the PROUT sub-commands (e.g., missing or mismatched --prout-type=TYPE) will result in a RESERVATION CONFLICT status. This can be confusing when you know there is only one (active) initiator; the "conflict" is with the SPC standard, not another initiator.

Some recent disks accept some PRIN and PROUT sub-commands when the media is stopped. One exception was setting the APTPL flag (with the --param-aptpl option) during a key register operation; it complained if the disk was stopped. The error indicated it wanted the disk spun up, and when that happened, the registration was successful.

EXAMPLES

These examples use Linux device names. For suitable device names in other supported Operating Systems, see the sg3_utils(8) man page.

Due to the various option defaults, the simplest example executes the 'read keys' sub-command of the PRIN command:


sg_persist /dev/sdb

This is the same as the following (long-winded) command:


sg_persist --in --read-keys --device=/dev/sdb

To read the current reservation, either the '--read-reservation' form or the shorter '-R' can be used:


sg_persist -R /dev/sdb

To register the new reservation key 0x123abc, the following could be used:


sg_persist --out --register --param-rk=123abc /dev/sdb

Given the above registration succeeds, to reserve the DEVICE (with type 'Write Exclusive') the following could be used:


sg_persist --out --reserve --param-rk=123abc \
--prout-type=1 /dev/sdb

To release the reservation, the following can be given (note that the --param-rk and --prout-type arguments must match those of the reservation):


sg_persist --out --release --param-rk=123abc \
--prout-type=1 /dev/sdb

Finally, to unregister a reservation key (and not affect other registrations, which is what '--clear' would do), the command is a little surprising:


sg_persist --out --register --param-rk=123abc /dev/sdb

Now, have a close look at the difference between the register and unregister examples above.

An example file that is suitably formatted to pass TransportIDs via a '--transport-id=file=transport_ids.txt' option can be found in the examples sub-directory of the sg3_utils package. There is also a simple test script called sg_persist_tst.sh in the same directory.

The above sequence of commands was tested successfully on a Seagate Savvio 10K.3 disk and a 1200 SSD, both of which have SAS interfaces.

EXIT STATUS

The exit status of sg_persist is 0 when it is successful. Otherwise, see the sg3_utils(8) man page.

ENVIRONMENT VARIABLES

Currently, there is one recognized environment variable: SG_PERSIST_IN_RDONLY. If present and only if a PRIN command has been selected, then the given DEVICE is opened read-only (e.g., in Unix, this is with the O_RDONLY flag). See the --readonly option.
