NOM

sg3_utils_json - sortie JSON pour certains utilitaires sg3_utils

SYNOPIS

sg_* --json[=JO] [--js-file=JFN] [AUTRES_OPTIONS] [PÉRIPHÉRIQUE]

DESCRIPTION

sg3_utils est un ensemble d'utilitaires qui envoient des commandes SCSI au PÉRIPHÉRIQUE donné via une interface de passage de commandes SCSI fournie par le système d'exploitation hôte. Certains utilitaires, principalement ceux qui décodent des données structurées renvoyées par des commandes SCSI (par exemple, sg_vpd), peuvent facultativement fournir une sortie JSON, plutôt qu'une sortie texte simple. La sortie texte simple reste le comportement par défaut.

JavaScript Object Notation (JSON) est un format de fichier standard ouvert qui peut être utilisé pour l'échange de données entre programmes, y compris sur un réseau. Voir https://en.wikipedia.org/wiki/JSON . JSON existe sous de nombreuses formes et celle-ci utilise l'implémentation C json-builder trouvée sur https://github.com/json-parser/json-builder qui implémente quatre types de données JSON simples : chaîne, entier, booléen et nul. Ses autres types de données sont l'objet JSON et le tableau JSON.

Ce projet utilise la convention 'snake_case' pour les noms d'objets JSON : tout en minuscules ou en chiffres avec des mots individuels joints par un unique trait de soulignement (par exemple, "starting_lba"). Il ne doit y avoir aucun caractère de soulignement au début ou à la fin. La bibliothèque json-builder utilise le SPDX-License-Identifier: BSD-2-Clause qui est la même licence que la majeure partie des utilitaires du package sg3_utils.

La bibliothèque json-builder est relativement légère (700 lignes de code C) et est entièrement 'cachée' dans la bibliothèque sg3_utils de sorte que son interface de fonction et ses types de données ne soient pas disponibles (directement) pour les utilitaires du package sg3_utils. C'est pourquoi l'interface json-builder (un fichier nommé sg_json_builder.h) se trouve dans le répertoire lib et non dans le répertoire include. Tel que présenté sur github, json-builder partage certains fichiers d'en-tête avec son compagnon json-parser. L'auteur a modifié l'en-tête json-builder pour inclure ce qui est nécessaire de l'en-tête json-parser afin que seul le constructeur et non le parseur soient construits. Le parseur pourrait être ajouté plus tard, mais actuellement il ne semble pas y en avoir besoin.

L'interface utilisateur pour la fonctionnalité JSON dans le package sg3_utils est fortement basée sur ce qui a été fait par Christian Franke et d'autres dans smartctl, un utilitaire du package smartmontools pour obtenir des informations S.M.A.R.T. à partir des disques (et autres périphériques de stockage).

Cette page de manuel discute des options de ligne de commande --json[=JO] et --js-file=JFN. Notez que l'argument de --json est lui-même facultatif. Dans sa forme la plus courte, l'option --json peut être soit -j soit -J (minuscule préférée si elle n'est pas déjà utilisée). La forme la plus courte peut également prendre un argument, mais un "=" doit précéder l'argument JO sans espaces de part et d'autre du "=".

Un certain soin a été apporté aux guillemets dans cette page de manuel. Les guillemets doubles sont utilisés autour des noms d'objets JSON, les guillemets simples sont utilisés pour tous les autres usages.

VARIABLES D'ENVIRONNEMENT

La variable d'environnement SG3_UTILS_JSON_OPTS permet à l'utilisateur de remplacer les valeurs par défaut des paramètres JO. Ces paramètres peuvent à nouveau être remplacés par l'option de ligne de commande --json[=JO]. Si la chaîne associée à SG3_UTILS_JSON_OPTS ne peut pas être analysée, ce message d'erreur est envoyé vers stderr : 'error parsing SG3_UTILS_JSON_OPTS environment variable, ignore'.

OPTIONS

Puisque l'argument de --json[=JO] est facultatif, dans la forme la plus courte il peut n'y avoir aucun espace entre l'option et son argument.

-j[=JO], --json[=JO]
JO est une chaîne de zéro ou plusieurs caractères dont l'ordre n'est pas significatif à l'exception des caractères de négation ('-' est préféré). Le caractère de négation doit apparaître immédiatement avant la (fonctionnalité booléenne) qu'il est en train de basculer.
Dans la forme courte, la lettre de l'option peut être autre que -j si cette lettre a déjà été utilisée (-J est préférée ensuite). Par exemple, l'utilitaire sg_ses utilise -j pour son opération 'join'. De plus, comme l'argument de l'option courte est lui-même facultatif, il ne peut y avoir d'espaces entre l'option courte, le "=", et JO, s'il est donné. Quelques exemples de forme courte : '-jl' demande une sortie JSON (sans option d'argument) et tout ce que signifie l'option courte '-l' dans l'utilitaire appelé ; '-j=h' demande une sortie JSON avec certains entiers rendus en plus sous forme de chaînes JSON hexadécimales.
-J, --js-file=JFN
la sortie est au format JSON et elle est envoyée vers un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée vers stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non défaut.
L'option courte peut être autre que -J si cette option courte était déjà utilisée.

CARACTÈRES DE CONTRÔLE JSON

Chaque chaîne JO est composée de zéro ou plusieurs des caractères de contrôle JSON suivants.

0
Si sortie JSON formatée, utiliser 2 espaces pour la tabulation.
2
Si sortie JSON formatée, utiliser 2 espaces pour la tabulation.
4
Si sortie JSON formatée, utiliser 4 espaces pour la tabulation.
C'est le réglage de tabulation par défaut pour le formatage de sortie JSON.
8
Si sortie JSON formatée, utiliser 8 espaces pour la tabulation.
-
caractère de négation. Inverse le sens (booléen) du caractère de contrôle suivant.
e
c'est un caractère de contrôle booléen pour le "statut de sortie". S'il est actif, un champ "exit status" est placé à la fin de la sortie JSON. La valeur entière de ce champ est la valeur du statut de sortie Unix qui est retournée au système d'exploitation lorsque cet utilitaire se termine. La valeur 0 indique une bonne sortie (c'est-à-dire aucune erreur détectée).
Ce caractère de contrôle booléen est actif par défaut (vrai).
h
c'est un caractère de contrôle booléen pour 'hexadécimal'. De nombreuses valeurs associées à SCSI sont mieux (ou du moins historiquement) vues en hexadécimal, tandis que la sortie JSON préfère les entiers décimaux (supposés avoir une taille maximale de 64 bits, signés). La taille maximale de la plupart des champs SCSI est de 64 bits _non signés_. De plus, certains champs SCSI sont des masques qui sont mieux vus en hexadécimal. Lorsque ce caractère de contrôle est actif, la plupart des champs (non triviaux) qui ont une valeur entière reçoivent à la place un sous-objet contenant au moins un champ "i" avec la valeur entière et un champ "hex" avec la valeur hexadécimale correspondante dans une chaîne JSON. Cette chaîne hexadécimale n'a pas de décorations hexadécimales (c'est-à-dire pas de préfixe '0x' ni de suffixe 'h').
Ce caractère de contrôle booléen est inactif par défaut (faux).
k
c'est un caractère de contrôle booléen pour un contrôle plus fin de la sortie JSON non formatée. Si le caractère de contrôle 'p' est défini sur (vrai), alors cette option n'a aucun effet.
Si le caractère de contrôle 'p' est désactivé (faux) et que ce caractère de contrôle est désactivé (faux), alors la sortie JSON sur une seule ligne contient quelques espaces pour la lisibilité. Si le caractère de contrôle 'p' est désactivé (faux) et que ce caractère de contrôle est activé (vrai), alors la sortie JSON sur une seule ligne est 'empaquetée', supprimant tous les espaces inutiles.
Ce caractère de contrôle booléen est inactif par défaut (faux).
l
c'est un caractère de contrôle booléen pour contrôler si les champs d'introduction sont affichés. Les champs d'introduction se trouvent au début de la sortie JSON et incluent des sous-objets "json_format_version" et "utility_invoked". Le sous-objet "utility_invoked" inclut des champs de chaîne "name", "version_date" et un tableau JSON nommé "argv" avec une entrée pour chaque argument de ligne de commande. Si le caractère de contrôle o est également actif, alors si disponible, la sortie non-JSON (c'est-à-dire la forme originale, en 'texte brut') est placée dans un tableau appelé "plain_text_output" avec un élément par ligne de sortie 'normale'.

Various utilities for controlling SCSI devices.

DESCRIPTION

The sg3_utils package provides a number of utilities that allow users to send SCSI commands to SCSI devices (e.g. disk drives, CD/DVD drives, tape drives, RAID controllers, etc.) and to display the results in various forms. The primary purpose is to allow low-level inspection and control of SCSI devices, especially for diagnostics and low-level operations.

The utilities in this package are built around the libsgutil library which in turn uses the libsata library to communicate with SCSI devices via the operating system's SCSI generic (SG) device interface (e.g. Linux's /dev/sgX devices).

The primary tasks these utilities perform are:

  • Sending SCSI commands (CDBs) to the device.
  • Receiving data or status back from the device.
  • Interpreting the received data and status, and displaying it to the user.

Many of the utilities share common options for controlling the output format, verbosity, and device selection. The most prominent of these is the --json[=JO] option which causes the output to be in JSON format.

When the --json option is used, it can be followed by an optional argument string JO. This string is interpreted as a set of control characters, each typically a single letter, that modify the JSON output. See the JSON CONTROL CHARACTERS section below.

ENVIRONMENT VARIABLES

The following environment variables are recognized:

SG3_UTILS_OPTIONS
If set, its value is interpreted as a string of standard command line options and is prepended to the command line options given by the user. This provides a way to set default options for all utilities. This variable is ignored if it is empty or not set.
SG_IO_TIMEOUT
If set, its value is interpreted as a decimal integer and used as the default timeout (in seconds) for SCSI I/O operations. A value of 0 means use the OS default. If not set, the OS default is used.
SG_LOG_LEVEL
If set, its value is interpreted as a decimal integer and used as the default SCSI I/O logging level. If not set, logging is disabled.
SG_LOG_OPTIONS
If set, its value is interpreted as a string of options for SCSI I/O logging. If not set, no logging options are used.

OPTIONS

Most of the utilities in this package share a common set of options.

-b, --binary
Output data in binary form. This is usually used in conjunction with other options like --hex or --raw.
-c, --count=CT
Sets the number of Test Unit Ready (TURS) commands to send. Default is 1.
-e, --emulate=ER
Emulate a SCSI device of type ER. Currently, only none (no emulation) is supported.
-E, --export
Export VPD page data in a suitable format for import by other tools. Requires the device to support Vital Product Data (VPD).
-h, --help
Print out the usage information for the specified utility then exit. When given twice, also print help for common options.
-H, --hex=FN
Write the output data (decoded or raw) to the file FN in hexadecimal format. If FN is '-', stdout is used.
-i, --inhex=FN
Read input data from the file FN in hexadecimal format. If FN is '-', stdin is used. This is typically used to supply data for commands like sg_write_buffer.
-j, --json[=JO]
Output the results in JSON format. The optional JO argument is a string of control characters that modify the JSON output. See the JSON CONTROL CHARACTERS section below.
-l, --log
Enable SCSI I/O logging. The logging level and options are determined by the SG3_UTILS_LOG_LEVEL and SG3_UTILS_LOG_OPTIONS environment variables.
-p, --page=PG
Select a specific SCSI page number. Page numbers can be given as decimal or hexadecimal (prefixed with '0x').
-q, --quiet
Suppress the display of error messages. Warnings and other non-error output will still be shown.
-r, --raw
Output the raw SCSI command response data. This bypasses most of the decoding and formatting done by the utilities.
-s, --short
Produce shorter output, where applicable. For example, for VPD pages, this might mean printing only the page identifier and name.
-t, --size
Print the size of the requested data buffer.
-v, --verbose
Increase the level of verbosity. Can be given multiple times to increase the verbosity further.
-V, --version
Print the version string of the utility then exit.

JSON CONTROL CHARACTERS

The --json[=JO] option allows for fine-grained control over the JSON output using a set of single-letter control characters that can be combined in the JO string.

The following control characters are supported:

a
this is a boolean control character for "ascii_ Kabupaten". When true, then ASCII characters that are not printable are replaced by a '.' character in the JSON output. If false, these non-printable characters are output as is (which may cause issues if the terminal cannot display them).
d
this is a boolean control character for "descriptors". When true, then the output is formatted to show descriptor data (e.g. from VPD pages) in a more structured and readable way. If false, the output is more compact.
e
this is a boolean control character for "export". When true, then the output is formatted in a way suitable for exporting to other tools, typically for VPD pages. If false, the output is for human consumption.
i
this is a boolean control character for "indent". When true, the JSON output is pretty-printed with indentation. If false, the JSON output is compact.
k
this is a boolean control character for "packed". When true, the JSON output is presented in a compact, single-line format, suitable for machine parsing and efficient transmission. This is an alternative to pretty-printing (see control character 'p').
l
this is a boolean control character for "long". When true, then the output is formatted to show more detailed information, usually associated with longer output formats. If false, the output is more compact.
n
this is a boolean control character for "name_extra". It is used to provide additional information about the name it is a sub-object of. The most common usage is to spell out an abbreviated name (e.g. a T10 name like 'SKSV' to 'Sense Key Specific Valid'). Another use is to note that a T10 field is obsolete and in which T10 standard it first became obsolete. Also if the named field's value is a physical quantity where the unit is unclear (e.g. a timeout) then "name_extra" can state that (e.g. 'unit: millisecond'). Only some fields have associated "name_extra" data.
This boolean control character is default off (false).
o
this is a boolean control character to control whether normal (i.e. non-JSON) lines of output are placed in a JSON array (one element per line of normal output) within the utility_invoked subject (see control character l). The name of the array is "plain_text_output". This control character is active even if the lead-in fields control character (l) is negated.
This boolean control character is default off (false).
p
this boolean control character controls whether the JSON output is 'pretty printed' or sent in a relatively compact stream suitable for more efficient transmission over a communications channel.
The pretty printed form of output has one JSON name with its associated integer, string or boolean value per line; and one array element per line. JSON objects and arrays that have an associated JSON object as their value, have their name on a separate line. These lines are indented with the current tab setting to indicate the level of nesting. Basically the pretty printed form is for human consumption.
There are two forms of non-pretty printed output, see the 'packed' control character ['k'].
This boolean control character is default on (true).
s
this boolean control character controls whether T10 field values that have a defined meaning are broken out with an added JSON sub-object usually named "meaning". When active the field name has a sub-object that contains at least an "i" field with the integer value of the field and a JSON string object, usually named "meaning", with a string that corresponds to the T10 defined meaning of the value in the "i" field.
This boolean control character is default on (true).
v
this is an integer control character that controls the amount of debug output. It can be given multiple times to increase the level of JSON debug verbosity in the output.
Note that this verbose control character is JSON specific while the --verbose option (short form: fI-v often repeated: fI-vvv) that most utilities support is more general.
This integer control character is set to 0 by default.

OUTPUT PROCESSING

The default remains the same for all utilities that support the --json option, namely the decoded information is sent to stdout in plain text form. Errors are reported to stderr and may cause the early termination of a utility (e.g. command line option syntax error).

When the --json option is given and no errors are detected, then only JSON is normally sent to stdout. As the SCSI response is parsed, a JSON representation is built as a tree in memory. After all other actions (perhaps apart from the final exit status report) that JSON tree is 'dumped' to stdout. This means if there is any non-JSON output sent to stdout that it will appear _before_ the JSON output.

If the 'o' control character is in the JO argument to the --json option, then the former plain text output is placed in a JSON array named "plain_text_output" within a JSON object named "utility_invoked".
Each line of the former 'plain text' output is placed in its own element of the JSON array.

A JSON tree is built in memory as the utility parses the data returned from the SCSI device (e.g. sg_vpd parsing a VPD page returned from a SCSI INQUIRY command). SCSI 'list's become JSON named arrays (e.g. in the Device Identification VPD page there is a 'Designation descriptor list' that becomes a JSON array named "designation_descriptor_list").

At the completion of the utility that JSON tree is 'measured' taking into account the form of output (i.e. pretty-printed, single line or packed single line). For the pretty-printed JSON output, the size of each indentation in spaces is also given (i.e. the tab width). The JSON is then output to a single C string, then sent to stdout. If a NULL character (ASCII zero and C string terminator) somehow finds its way into a field that should (according to the spec) be space padded, then the JSON output may appear truncated.

Note that this JSON processing means that if a utility is aborted for whatever reason then no JSON output will appear. With the normal, plain text output processing, some output may appear before the utility aborts in such bad situations.

BOOLEAN OR 0/1

In general, the JSON generated by this package outputs 1 bit SCSI fields as the integer value 0 (for false) and 1 (for true). This follows the SCSI convention which predates the common use of boolean. Also SCSI reserved fields are output as the integer value 0. Extensions to SCSI commands and associated data descriptors typically use parts of commands or data descriptors that were previously reserved.

INTERACTION WITH OTHER OPTIONS

As stated above, the default output is in plain text form using 7 bit ASCII. The --json[=JO] option is designed to be an alternative to that plain text form. There are other alternative output formats such as the response output as a hexadecimal sequence of bytes or in 'raw' binary output; both of those take precedence over the --json[=JO] option. Other specialized output format (e.g. 'sg_inq --export') will usually take precedence over JSON output.

When the --raw option is used together with the --inhex=FN option only the data input to the utility is interpreted as binary. So the output format defaults to plain text form and thus can be changed to JSON if the --json[=JO] option is also used.

There is typically only one form of JSON output so options like --brief and --quiet are ignored in the JSON output. In some cases (i.e 'sg_inq --descriptors') the JSON output is expanded.

ERRORS

No attempts have been made to translate errors into JSON form, apart from the final "exit_status" JSON object where a value of 0 means 'no errors'. Exit status values indicating a problem range from 1 to 255.

The sg_decode_sense utility will parse SCSI sense data into JSON form if requested. So if another utility is failing with a sense data report (most often seen when the --verbose option is used). That sense data (in hex bytes) could be cut-and-pasted onto the command line following 'sg_decode_sense -j ' which should then render that sense data in JSON.

Otherwise, when a error is detected while JSON output is selected, the error message is sent to stderr in plain text form. Typically once an error is detected the utility will exit, first dumping the JSON in-memory tree as discussed above and a non-zero exit status will be set. The JSON output will be well formed but missing any fields or list elements following the point that the error was detected.

The summary is that when JSON output is selected and an error occurs each utility will process the error the same way as it would if JSON output had not been selected. In most cases error messages, in plain text form, are sent to stderr.
