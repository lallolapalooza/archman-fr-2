sg_readcap(8)

Paquet: sg3_utils

Licences: GPL, custom:BSD

SG_READCAP(8) SG3_UTILS SG_READCAP(8)

NOM

sg_readcap - envoyer une commande SCSI READ CAPACITY

SYNTAXE

sg_readcap [--10] [--16] [--brief] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--lba=LBA] [--long] [--pmi] [--raw] [--readonly] [--verbose] [--version] [--zbc] APPAREIL

sg_readcap [-16] [-b] [-h] [-H] [-lba=LBA] [-pmi] [-r] [-R] [-v] [-V] [-z] APPAREIL

DESCRIPTION

L'action normale de la commande SCSI READ CAPACITY est de récupérer le nombre de blocs (et la taille des blocs) de l'APPAREIL.

La commande SCSI READ CAPACITY (versions 10 et 16 octets de cdb) renvoie en fait l'adresse du dernier bloc et la taille du bloc. Le nombre de blocs est donc égal à un plus l'adresse du dernier bloc (les blocs étant comptés à partir de zéro). C'est la source de nombreuses erreurs d'un unité.

La réponse de READ CAPACITY(16) fournit des informations supplémentaires non présentes dans la réponse de READ CAPACITY(10). Cela inclut des informations sur la protection et le provisionnement logique des blocs, ainsi que le nombre de blocs logiques par bloc physique. Ainsi, même si la taille du média ne dépasse pas ce que READ CAPACITY(10) peut afficher, il peut être utile d'examiner la réponse à READ CAPACITY(16). Malheureusement, il existe des implémentations de jeux de commandes SCSI défectueuses qui plantent lorsque la commande READ CAPACITY(16) leur est envoyée.

La capacité d'un appareil est le produit du nombre de blocs par la taille des blocs. Cet utilitaire affiche ce chiffre en octets, MiB (1048576 octets par MiB), Go (1000000000 octets par Go) et, si suffisamment grand, To (1000 Go).

Si sg_readcap est appelé sans l'option --long, la version avec cdb de 10 octets (c'est-à-dire READ CAPACITY (10)) est envoyée à l'APPAREIL. Si le nombre de blocs dans la réponse est rapporté comme étant 0xffffffff (c'est-à-dire (2**32 - 1)) et que l'option --hex n'a pas été donnée, alors READ CAPACITY (16) est appelée et sa réponse est affichée.

Cet utilitaire prend en charge deux syntaxes de ligne de commande, la première étant celle affichée dans la syntaxe et expliquée dans cette section. Une section ultérieure sur la syntaxe des anciennes commandes décrit le deuxième groupe d'options.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont classées par ordre alphabétique selon le nom de l'option longue.

--10
Utilise la variante de commande READ CAPACITY avec cdb de 10 octets. C'est actuellement l'action par défaut de cet utilitaire. Ce comportement par défaut pourrait passer à la variante avec cdb de 16 octets, surtout si T10 déprécie la variante avec cdb de 10 octets.
--16
Utilise la variante de commande READ CAPACITY avec cdb de 16 octets. Voir l'option '--long'. -b, --brief affiche deux nombres hexadécimaux (précédés de '0x' et séparés par un espace) sur stdout. Le premier nombre est le nombre maximum de blocs sur l'appareil (qui est un plus le lba du dernier bloc accessible). Le second nombre est la taille en octets de chaque bloc. Si l'opération échoue, "0x0 0x0" est écrit sur stdout.
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse à la commande READ CAPACITY (variante avec cdb de 10 ou 16 octets) en hexadécimal ASCII sur stdout. Chaque ligne commence par une adresse ou un index hexadécimal, commençant à 0. Si cette option est donnée deux fois, et un rendu ASCII des 16 octets de chaque ligne est ajouté sur le côté droit de chaque ligne.
Si cette option est donnée trois fois, 16 octets d'hexadécimal ASCII sont affichés sur chaque ligne sans adresse initiale ni rendu ASCII à droite. Cette sortie est adaptée pour être importée dans une invocation ultérieure de cet utilitaire avec le fichier contenant l'hexadécimal donné à l'option --inhex=FN. Lorsque cette option est donnée quatre fois (ou plus), elle ajoute une ligne de commentaire (commençant par '#') décrivant la commande qui a généré la sortie.
-i, --inhex=FN
où FN est un nom de fichier dont le contenu est supposé être en hexadécimal ASCII. Si APPAREIL est également donné, alors APPAREIL est ignoré, un avertissement est émis et l'utilitaire continue, décodant le fichier nommé FN. Voir la section "FORMATS HEXADÉCIMAUX, BINAIRES ET JSON" dans la page de manuel sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors le contenu de FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du texte brut. Notez que les arguments des formes courte et longue sont eux-mêmes optionnels et s'ils sont présents, ils commencent par "=" sans espace permis autour de ce "=".
Voir la page de manuel sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et elle est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO sur des valeurs non défaut.
-L, --lba=LBA
utilisé conjointement avec l'option --pmi. Cette variante de READ CAPACITY renverra la dernière adresse de bloc après LBA avant un délai. Pour un disque, étant donné un LBA, il renvoie le bloc le plus numéroté sur le même cylindre (c'est-à-dire avant que les têtes ne doivent bouger). LBA est supposé être décimal sauf s'il est préfixé par "0x" ou s'il a un suffixe "h". Valeur par défaut : 0. Cette option a été rendue obsolète dans la révision 26 de SBC-3.
-l, --long
Utilise la variante de commande READ CAPACITY avec cdb de 16 octets. L'action par défaut est d'utiliser la variante avec cdb de 10 octets qui limite l'adresse de bloc maximale à (2**32 - 2). Lorsqu'une commande READ CAPACITY avec cdb de 10 octets est utilisée sur un appareil dont la taille est trop grande, une adresse de dernier bloc de 0xffffffff est retournée (si l'appareil est conforme à SBC-2 ou ultérieur).
-O, --old
Passe aux options de style ancien. À utiliser comme première option.
-p, --pmi
indicateur partiel du média : pour trouver la prochaine adresse de bloc avant un certain délai (par exemple, mouvement de tête). En l'absence de cette option, le nombre total de blocs et la taille des blocs de l'appareil sont affichés. Utilisé conjointement avec l'option --lba=LBA. Cette option a été rendue obsolète dans la révision 26 de SBC-3.
-r, --raw
envoie la réponse en binaire sur stdout.
-R, --readonly
ouvre l'APPAREIL en lecture seule (par exemple, sous Unix avec le flag O_RDONLY). La valeur par défaut pour READ CAPACITY(16) est de l'ouvrir en lecture-écriture. La valeur par défaut pour READ CAPACITY(10) est de l'ouvrir en lecture seule, donc cette option ne change rien dans ce cas.
-v, --verbose
augmente le niveau de verbosité. Peut être utilisé plusieurs fois.
-V, --version
affiche la chaîne de version puis quitte.
-z, --zbc
affiche en plus le champ ZBC supplémentaire (RC_BASIS) dans la réponse de READ CAPACITY. L'utilisation de cette option active implicitement l'option --16.

NOTES

La réponse à READ CAPACITY(16) contient un bit LBPRZ dans la norme SBC-3 (ANSI INCITS 514-2014). Il y avait aussi un bit LBPRZ avec la même signification dans la page VPD de provisionnement de bloc logique (0xb2). Puis, de manière quelque peu confuse, T10 a étendu le bit LBPRZ à un champ de 3 bits dans le projet SBC-4 révision 7, mais uniquement dans la page VPD de provisionnement de bloc logique. La raison de l'extension était de signaler un nouvel état de "modèle d'initialisation de provisionnement" (lorsqu'un bloc logique non mappé est lu). Le nouvel état a été assigné LBPRZ=2 dans la page VPD et il réutilise LBPRZ=0 dans la réponse de READ CAPACITY(16). STATUT DE SORTIE

Le statut de sortie de sg_readcap est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE OBSOLÈTES

Les options de cette section étaient les seules disponibles avant la version 1.23 de sg3_utils. Depuis lors, cet utilitaire utilise par défaut les options de ligne de commande plus récentes, qui peuvent être remplacées en utilisant --old (ou -O) comme première option. Voir la section VARIABLES D'ENVIRONNEMENT pour une autre façon de forcer l'utilisation de ces options de ligne de commande obsolètes.

-16
Utilise la variante 16 octets du CDB de la commande READ CAPACITY. Équivalent à --long dans la description principale.
-b
l'utilitaire affiche deux nombres hexadécimaux (précédés de '0x' et séparés par un espace) sur stdout. Le premier nombre est le nombre maximum de blocs sur le périphérique (qui est un plus le LBA du dernier bloc accessible). Le second nombre est la taille de chaque bloc. Si l'opération échoue, "0x0 0x0" est écrit sur stdout. Équivalent à --brief dans la description principale.
-h
affiche le message d'utilisation puis quitte. Donner l'option -? affiche également le message d'utilisation puis quitte.
-H
affiche la réponse à la commande READ CAPACITY (variante 10 ou 16 octets du CDB) en hexadécimal ASCII sur stdout.
-lba=LBA
utilisé en conjonction avec l'option -pmi. Cette variante de READ CAPACITY renverra le dernier bloc adresse après LBA avant un délai. Équivalent à --lba=LBA dans la description principale.
-N, --new
Passe aux options de style plus récent.
-pmi
indicateur de média partiel : pour trouver le bloc adresse suivant avant un certain délai (par exemple, mouvement de tête). En l'absence de cet interrupteur, le nombre total de blocs et la taille des blocs du périphérique sont affichés. Équivalent à --pmi dans la description principale.
-r
affiche la réponse en binaire (sur stdout).
-R
Équivalent à --readonly dans la description principale.
-v
verbeux : affiche le CDB des commandes émises avant leur exécution. '-vv' et '-vvv' sont également acceptés, produisant une verbosité accrue.
-V
affiche la chaîne de version puis quitte.
-z
Équivalent à --zbc dans la description principale.

VARIABLES D'ENVIRONNEMENT

Depuis la version 1.23 de sg3_utils, la variable d'environnement SG3_UTILS_OLD_OPTS peut être utilisée. Lorsqu'elle est présente, cet utilitaire attend les options de ligne de commande obsolètes. La présence de cette variable d'environnement est donc équivalente à l'utilisation de --old (ou -O) comme première option de ligne de commande.
