SG_GET_LBA_STATUS(8) SG3_UTILS SG_GET_LBA_STATUS(8)

NOM

sg_get_lba_status - envoie la commande SCSI GET LBA STATUS(16 ou 32)

SYNTAXE

sg_get_lba_status [--16] [--32] [--blockhex] [--brief] [--element-id=EI] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--lba=LBA] [--maxlen=LEN] [--raw] [--readonly] [--report-type=RT] [--scan-len=SL] [--verbose] [--version] PÉRIPH

DESCRIPTION

Envoie la commande SCSI GET LBA STATUS(16) ou GET LBA STATUS(32) au PÉRIPH et affiche la réponse. La variante de commande sur 16 octets a été introduite dans (draft) SBC-3 révision 20 et les périphériques qui supportent le provisionnement logique des blocs devraient supporter cette commande. La commande GET LBA STATUS(32) a été ajoutée dans (draft) SBC-4 révision 14.

L'action par défaut consiste à décoder la réponse en un descripteur de statut LBA par ligne, puis à afficher un en-tête et les descripteurs de statut sur stdout. Le LBA du descripteur est affiché en hexadécimal (précédé de '0x') et le nombre de blocs est affiché en décimal suivi du statut de provisionnement, de l'accessibilité du LBA et du statut additionnel en décimal. Le statut de provisionnement peut être compris entre 0 et 15, dont seuls 0 (mappé ou inconnu), 1 (non mappé), 2 (ancré), 3 (mappé) et 4 (inconnu) sont actuellement utilisés. La quantité de sortie peut être réduite par l'option --brief.

Plutôt que d'envoyer cette commande SCSI au PÉRIPH, si l'option --inhex=FN est donnée, alors le contenu du fichier nommé FN est décodé en hexadécimal ASCII puis traité comme s'il s'agissait de la réponse à cette commande.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-S, --16
envoie la commande SCSI GET LBA STATUS(16) qui est la variante sur 16 octets. En l'absence des options --16 ou --32, la commande SCSI GET LBA STATUS(16) est envoyée. Si les options --16 et --32 sont données, alors la commande GET LBA STATUS(16) est envoyée.
-T, --32
envoie la commande SCSI GET LBA STATUS(32) qui est la variante sur 32 octets. Lorsqu'elle est donnée avec l'option --16, cette option est ignorée (donc la commande GET LBA STATUS(16) est envoyée).
-b, --brief
lorsqu'elle est utilisée une fois, un descripteur de statut LBA par ligne est envoyé à stdout. Chaque ligne a ce format : "0x<descripteur_LBA> 0x<blocs> <statut_provisionnement> <statut_additionnel>". Ainsi, le LBA de départ du descripteur et le nombre de blocs sont affichés en hexadécimal tandis que le statut de provisionnement et le statut additionnel sont en décimal. Lorsqu'elle est utilisée deux fois (par ex. '-bb' ou '--brief --brief'), le statut de provisionnement du LBA donné (ou LBA 0 si l'option --lba n'est pas donnée) est envoyé à stdout. Une vérification est effectuée pour s'assurer que le LBA donné se trouve dans la plage du premier descripteur de statut LBA retourné (comme il devrait l'être selon la révision 20 de SBC-3) et des avertissements sont envoyés à stderr si ce n'est pas le cas.
-B, --blockhex
le nombre de blocs dans chaque descripteur de statut LBA est généralement affiché en décimal. Une exception est lorsque l'option --brief est donnée, auquel cas il est affiché en hexadécimal. Lorsque l'option est donnée une fois, les deux cas sont affichés en hexadécimal. Lorsque l'option est donnée deux fois, les deux cas sont affichés en décimal.
-e, --element-id=EI
où EI est l'identifiant de l'élément physique pour lequel les LBA doivent être rapportés en fonction de la valeur du champ type de rapport (c.-à-d. RT). Cette option n'est active qu'avec la commande SCSI GET LBA STATUS(32) (c.-à-d. elle est ignorée si la commande GET LBA STATUS(16) est envoyée).
Les identifiants d'éléments valides sont non nuls. La valeur par défaut de EI est 0, ce qui signifie dans ce contexte qu'aucun identifiant d'élément n'est spécifié.
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse à cette commande en hexadécimal ASCII. Pour produire une sortie hexadécimale adaptée à une invocation ultérieure pour la récupérer avec l'option --inhex=FN, utilisez cette option trois fois. L'option courte la rend plus pratique : '-HHH'.
-i, --inhex=FN
où FN est un nom de fichier dont le contenu est supposé être en hexadécimal ASCII. Voir la section "FORMATS HEX, BINARY ET JSON" dans la page man sg3_utils pour plus d'informations. Si PÉRIPH est également donné, il est ignoré. Si l'option --raw est également donnée, le contenu de FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du format texte brut. Notez que les arguments des formes courtes et longues sont facultatifs et, s'ils sont présents, commencent par "=" et aucun espace n'est autorisé autour de ce "=".
Voir la page man sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et elle est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et il n'est pas nécessaire de la donner. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non par défaut.
-l, --lba=LBA
où LBA est l'adresse logique de bloc (LBA) de départ pour laquelle vérifier le statut de provisionnement. Notez que le PÉRIPH choisit combien de blocs suivants pour lesquels il renverra le statut de provisionnement.
-m, --maxlen=LEN
où LEN est la longueur (maximale) de la réponse en octets. Elle est placée dans le champ "longueur d'allocation" du cdb. Si elle n'est pas donnée, 24 est utilisé. 24 est suffisant pour l'en-tête de réponse et un descripteur de statut LBA. LEN doit être 8 plus un multiple de 16 (par exemple, 24, 40 et 56 sont appropriés).
-r, --raw
envoie la réponse en binaire (vers stdout) à moins que l'option --inhex=FN ne soit également donnée. Dans ce cas, le nom du fichier d'entrée (FN) est décodé en binaire (et la sortie n'est *pas* en binaire).
-R, --readonly
ouvre le PÉRIPH en lecture seule (par ex. sous Unix avec le drapeau O_RDONLY). La valeur par défaut est d'ouvrir en lecture-écriture.
-t, --report-type=RT
où RT est 0 pour rapporter tous les LBA ; 1 pour rapporter les LBA avec un statut de provisionnement non nul ; 2 pour rapporter les LBA mappés ; 3 pour rapporter les LBA désalloués ; 4 pour rapporter les LBA ancrés ; 16 pour rapporter les LBA qui peuvent retourner une erreur non récupérée. Le champ REPORT TYPE a été ajouté au cdb GET LBA STATUS dans sbc4r12.
Étant donné que le champ REPORT TYPE est plus récent que la commande, la réponse contient le bit RTP pour indiquer si le PÉRIPH agit ou non sur le champ REPORT TYPE (défini lorsqu'il agit dessus, effacé sinon).
-s, --scan-len=SL
où SL est la longueur de balayage, qui est le nombre maximal de blocs logiques contigus à analyser pour les blocs logiques qui correspondent au type de rapport donné (c.-à-d. RT). Cette option n'est active qu'avec la commande SCSI GET LBA STATUS(32) (c.-à-d. elle est ignorée si la commande GET LBA STATUS(16) est envoyée).
La valeur par défaut de SL est 0, ce qui devrait être interprété par le PÉRIPH comme une absence de limite au nombre de LBA à analyser.
-v, --verbose
augmente le niveau de verbosité (c.-à-d. le débogage). Les sorties supplémentaires causées par cette option sont envoyées à stderr.
-V, --version
affiche la chaîne de version puis quitte.

sg_get_lba_status(8) — sg3_utils — Arch Linux

NAME

sg_get_lba_status — fetches LBA (logical block address) status from a SCSI device.

SYNOPSIS

sg_get_lba_status [OPTIONS] DEVICE

DESCRIPTION

This utility sends a SCSI ATA REPORT LBA STATUS command (SBC-4) to the given SCSI DEVICE and prints the LBA status information returned.

The primary purpose of this command is to discover which LBAs are deallocated (or unmapped in the context of the ATA TRIM command), which are allocated and accessible, and which are allocated but inaccessible.

OPTIONS

-b, --bytes
When printing LBA ranges, print the number of blocks instead of the number of bytes. The default is to print bytes.

-e, --extended
Perform an extended LBA status query. This involves sending multiple REPORT LBA STATUS commands, starting with the highest LBA and working downwards. This is useful for discovering sparse allocation patterns.

-f, --formatted
Prints LBA information in a slightly more human-readable format.

-h, --help
Print usage information and exit.

-H, --hex
Print the raw SCSI response in hex. This overrides other output options.

-i, --inhex=FILE
Read the SCSI response from FILE instead of sending a command to the device. Useful for testing and debugging.

-l, --lba=LBA
Set the starting LBA for the query. Defaults to 0.

-n, --num=NUM
Set the number of LBAs to query. Defaults to all available LBAs on the device.

-p, --p
Set the provisioning sense value. Defaults to 0.

-r, --r
Set the return type. Defaults to 0.

-t, --transport
Prints transport related information.

-v, --verbose
Increase verbosity.

-V, --version
Print version information and exit.

NOTES

The REPORT LBA STATUS command is defined in the SBC-4 revision 14 draft and later. In earlier drafts (e.g., SBC-3 revision 10), the equivalent command was REPORT WATERMARK.

The byte offset in the REPORT LBA STATUS command's response was 8 in SBC-3 revision 10 and in revision 25 it was changed to 4.

For a discussion of logical block provisioning see section 4.7 of sbc4r14.pdf at https://www.t10.org (or the corresponding section of a later draft).

EXAMPLES

This example uses a "canned" hex file rather than a real DEVICE.


# cd <folder at root of sg3_utils source package>
# sg_get_lba_status --inhex=inhex/get_lba_status.hex


Command completed due to meeting capacity of medium
RTP=0x0
[1] LBA: 0x0 blocks: 287453952 mapped (or unknown); LBA accessibility not reported
[2] LBA: 0x11223300 blocks: 68 deallocated; LBA access not reported [may contain unrecovered errors]
[3] LBA: 0x11223344 blocks: 51 deallocated; LBA extent inaccessible [may contain unrecovered errors]

EXIT STATUS

The exit status of sg_get_lba_status is 0 when it is successful. Otherwise see the sg3_utils(8) man page.
