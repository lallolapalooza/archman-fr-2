NOM

sg_reassign - envoyer une commande SCSI REASSIGN BLOCKS

SYNTAXE

sg_reassign [--address=A,A...] [--dummy] [--eight=0|1] [--grown] [--help] [--hex] [--longlist=0|1] [--primary] [--verbose] [--version] DEVICE

DESCRIPTION

Envoie une commande SCSI REASSIGN BLOCKS à DEVICE. Alternativement, cet utilitaire peut trouver le nombre d'éléments dans une liste de défauts "croissants" ou "primaires" avec une commande SCSI READ DEFECT DATA (10). Ces commandes SCSI sont définies dans SBC-2 pour les périphériques d'accès direct (par exemple, un disque). Reassign blocks est conçu pour modifier l'emplacement physique d'un bloc logique connu ou suspecté d'être défectueux vers une autre zone du média. Les disques sont typiquement formatés avec des blocs réservés à cette situation.

Si ni l'option --grown ni l'option --primary ne sont fournies, alors une ou plusieurs adresses doivent être données. Si l'adresse (ou toutes les adresses) tient dans 4 octets et que '--eight=1' n'est pas donné, alors le bloc de paramètres passé à DEVICE est constitué d'adresses de blocs logiques de 4 octets. Si une des adresses nécessite plus de 4 octets pour être représentée (c'est-à-dire >= 2**32) ou si '--eight=1' est donné, alors le bloc de paramètres passé à DEVICE est constitué d'adresses de blocs logiques de 8 octets.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont classées par ordre alphabétique basé sur le nom de l'option longue.

-a, --address=A,A...
où A,A... est une chaîne de nombres séparés par des virgules. Chaque nombre est interprété en décimal sauf s'il est précédé de '0x' ou '0X' (ou s'il a un suffixe 'h' ou 'H'). Si plusieurs adresses de blocs logiques sont données, elles doivent être séparées par une virgule ou un espace (unique). Une chaîne contenant des séparateurs d'espace doit être mise entre guillemets. Au moins une adresse doit être donnée.
-a, --address=-
lit une ou plusieurs adresses de blocs logiques depuis stdin. Celles-ci peuvent être séparées par des virgules, des espaces, des tabulations ou des sauts de ligne (nouvelle ligne). Si une ligne contient "#", alors les caractères restants sur cette ligne sont ignorés. Sinon, chaque séquence de caractères non séparateur doit être résolue en un nombre décimal sauf si elle est précédée de '0x' ou '0X' (ou a un suffixe 'h'). Au moins une adresse doit être donnée. Les lignes ne doivent pas dépasser 1023 octets.
-d, --dummy
prépare mais n'exécute pas la commande SCSI REASSIGN BLOCKS. Étant donné que la commande REASSIGN BLOCKS est essentiellement irréversible, les utilisateurs paranoïaques peuvent souhaiter vérifier l'invocation de cet utilitaire avant de réaffecter des blocs défectueux sur un disque. Utile avec '-vv' pour ceux qui souhaitent voir le bloc de paramètres qui accompagnera la commande.
-e, --eight=0 | 1
quand la valeur est 1, cela définit le drapeau 'LONGLBA' dans la commande, indiquant que les adresses dans le bloc de paramètres associé sont des quantités de 8 octets. Quand la valeur est 0, cela efface le drapeau 'LONGLBA' dans la commande, indiquant que les adresses dans le bloc de paramètres associé sont des quantités de 4 octets. Si cette option n'est pas donnée, des quantités de 4 octets sont supposées, sauf si une des adresses est trop grande.
-g, --grown
utilise la commande SCSI READ DEFECT DATA (10) pour déterminer le nombre d'éléments dans la "liste de défauts croissants". Lorsque cette option est donnée, il n'y a pas de réaffectation de blocs (c'est-à-dire que cet utilitaire est passif). Lorsque cette option est donnée, l'option --address= n'est pas autorisée. Voir la discussion ci-dessous concernant la relation entre les blocs réaffectés et la liste des défauts croissants. Cette liste est parfois appelée GLIST.
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse en hexadécimal (pour -g, --grown, -p ou --primary).
-l, --longlist=0 | 1
définit le champ cdb REASSIGN BLOCKS du même nom à la valeur donnée. Seulement 1000 adresses sont permises, donc il ne devrait y avoir aucun besoin de spécifier une valeur de 1. La variante de liste courte restreint la longueur du bloc de paramètres à 2 ** 16 octets (soit environ 16000 adresses de 4 octets ou 8000 adresses de 8 octets). Ajouté pour des raisons de complétude.
-p, --primary
utilise la commande SCSI READ DEFECT DATA (10) pour déterminer le nombre d'éléments dans la "liste de défauts primaires" qui est établie pendant le processus de fabrication. Lorsque cette option est donnée, il n'y a pas de réaffectation de blocs (c'est-à-dire que cet utilitaire est passif). Lorsque cette option est donnée, l'option --address= n'est pas autorisée. Cette liste est parfois appelée PLIST.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les messages de débogage).
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Notez que si les champs ARRE (pour les lectures) et/ou AWRE (pour les écritures) sont définis dans la page de mode "Read Write Error Recovery", alors les erreurs de lecture et/ou d'écriture récupérables provoquent la réaffectation automatique du bloc défectueux. Le bit PER dans la même page de mode contrôle si une clé d'état RECOVERED ERROR est rapportée ou non (PER=1 signifie qu'il faut rapporter). Indépendamment des paramètres des champs ARRE, AWRE ou PER, les pages de journaux des compteurs d'erreurs reflètent toutes les erreurs (récupérées ou autres). Chaque fois qu'un bloc est réaffecté, une nouvelle entrée est ajoutée à la liste des défauts "croissants". Outre l'exécution régulière de selftests (voir sg_senddiag ou smartmontools), la surveillance de la liste des défauts croissants d'un disque est une métrique raisonnable de sa santé. Si la liste croissante commence à croître rapidement, c'est un signe inquiétant. Les meilleures listes de défauts croissants sont celles qui sont vides. Le nombre d'éléments dans la liste des défauts croissants peut être consulté avec l'option --grown. Le contenu de la liste des défauts croissants peut être consulté avec l'utilitaire 'sginfo -G'.

Si une erreur irrécupérable est détectée à une adresse de bloc logique, REASSIGN BLOCKS est nécessaire pour réaffecter le bloc. De plus, si les champs ARRE et/ou AWRE sont effacés et qu'une erreur récupérable est détectée, le bloc logique en question peut être réaffecté avec cet utilitaire (sinon les pages de journaux des compteurs d'erreurs seront continuellement incrémentées pour chaque accès récupéré).

Le nombre de blocs réservés pour les REASSIGN BLOCKS est spécifique au vendeur et peut bien être limité à la zone du média où se trouvait le bloc d'origine (défectueux). Lorsque ce nombre est épuisé, les invocations ultérieures de cet utilitaire peuvent entraîner une clé d'état d'erreur matérielle et un état supplémentaire de 'Aucun emplacement de défaut de rechange disponible'. La prochaine étape serait de reformater le disque (ou d'en obtenir un remplacement).

Le projet de norme SBC-2 (révision 16) note que lorsque plusieurs adresses sont données à la commande SCSI REASSIGN BLOCKS et qu'il y a un échec à une des adresses ultérieures, toutes les adresses précédentes ont déjà été réaffectées. Il faut être prudent dans un tel cas. Réexécuter la commande avec les mêmes adresses entraînera la réaffectation des adresses précédentes. À un certain stade, le disque manquera d'emplacements réservés. Donc, à moins qu'un grand nombre d'adresses ne soit impliqué, il peut être plus sûr de les réaffecter une adresse à la fois.

STATUT DE SORTIE

Le statut de sortie de sg_reassign est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
