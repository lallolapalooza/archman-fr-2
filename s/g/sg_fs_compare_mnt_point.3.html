sg_get_fs_stats(3) sg_get_fs_stats(3)

DESCRIPTION

Les fonctions sg_get_fs_stats fournissent des statistiques sur les systèmes de fichiers montés. Les deux fonctions acceptent un paramètre facultatif `entries`, qui pointe (lorsqu'il est fourni) vers un `size_t` pour obtenir le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_fs_stats() et sg_get_fs_stats_r() fournissent les statistiques du système de fichiers au moment où la fonction est appelée. Les fonctions sg_get_fs_stats_diff() et sg_get_fs_stats_diff_between() fournissent la différence entre deux appels à sg_get_fs_stats() ou sg_get_fs_stats_r(), respectivement.

Raccourci API

fonction retourne propriétaire des données
sg_get_fs_stats sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_r sg_fs_stats * l'appelant
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_diff_between sg_fs_stats * l'appelant
sg_get_valid_filesystems char ** libstatgrab (global)

Les vecteurs sg_fs_stats reçus de sg_get_fs_stats_r() ou sg_get_fs_stats_diff_between() doivent être libérés en utilisant sg_free_fs_stats() lorsqu'ils ne sont plus nécessaires. L'appelant est responsable de le faire.

La bibliothèque statgrab est livrée avec une liste intégrée de types de systèmes de fichiers valides, en fonction du système d'exploitation pour lequel elle a été compilée. Certains systèmes d'exploitation fournissent également une API pour connaître les types de systèmes de fichiers connus ou valides pour l'instance d'OS en cours d'exécution, qui est utilisée lorsqu'elle est détectée. Néanmoins, il existe des problèmes connus lors de la collecte des statistiques des systèmes de fichiers : les systèmes de fichiers réseau sont montés depuis des serveurs défaillants, les développeurs de systèmes de fichiers exécutent un pilote expérimental, etc.

Pour éviter que les processus ne se bloquent lors de la collecte des statistiques des systèmes de fichiers ou pour permettre aux développeurs de tester leurs pilotes, les processus peuvent modifier la liste des systèmes de fichiers valides à l'aide de sg_get_valid_filesystems() et sg_set_valid_filesystems(). La liste des paramètres `char *` avec lesquels les deux fonctions travaillent est toujours terminée par un élément pointant vers NULL.

La liste retournée par sg_get_valid_filesystems() ne doit pas être modifiée. Copiez toujours la liste dans votre propre structure si vous prévoyez d'étendre ou de réduire la liste :

Exemple de suppression des systèmes de fichiers réseau

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* noms connus des systèmes de fichiers réseau sur différentes plateformes */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* dupliquer dans mémoire propre pour modifier la liste */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copier y compris le pointeur NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Notez qu'il n'est pas nécessaire de dupliquer les chaînes contenues dans la liste des systèmes de fichiers valides dans l'exemple ci-dessus - elles ne sont pas modifiées.

La liste retournée par sg_get_valid_filesystems() pourrait devenir invalide lorsqu'elle est utilisée pendant que le processus effectue des appels à sg_set_valid_filesystems(). Aucune des fonctions sg_fs_stats ne protège l'accès au stockage globalement utilisé où la copie de la liste des systèmes de fichiers valides est conservée. Il appartient à l'appelant de ne pas mélanger les appels de configuration avec les appels pour récupérer les statistiques.

De plus, deux fonctions d'aide pour qsort(3) sont disponibles : sg_fs_compare_device_name() et sg_fs_compare_mnt_point().

Exemple de tri

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ordonner les entrées alphabétiquement en utilisant le point de montage */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALEUR DE RETOUR

sg_get_fs_stats retourne un pointeur vers une structure de type sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
device_name
Le nom connu du système d'exploitation. (par ex. sous Linux, cela pourrait être hda)
fs_type
Le type du système de fichiers (par ex. hpfs ou ufs).
mnt_point
Le point de montage où le système de fichiers est monté.
device_type
Le type de périphérique du système de fichiers, actuellement non rempli et toujours sg_fs_unknown.
size
La taille totale, en octets, du système de fichiers.

size = used + free

used
La quantité d'espace, en octets, utilisée sur le système de fichiers.
avail
La quantité d'espace, en octets, disponible sur le système de fichiers pour l'utilisation par les utilisateurs ordinaires. Elle est inférieure à `free` car certains blocs sont réservés pour le superutilisateur.
free
La quantité d'espace, en octets, libre sur le système de fichiers.

DESCRIPTION

Ces fonctions sont destinées à être utilisées avec des fonctions telles que qsort(3) afin de trier des tableaux de structures sg_fs_stats. Elles comparent deux structures sg_fs_stats et retournent une valeur qui indique leur ordre relatif.

Le comportement de chaque fonction de comparaison est le suivant:

mnt_point
Compare les points de montage des deux structures.
size
La taille totale du système de fichiers en octets.
total_files
Le nombre total de fichiers dans le système de fichiers.
used_files
Le nombre de fichiers utilisés dans le système de fichiers.
free_files
Le nombre de fichiers libres dans le système de fichiers.
avail_files
Le nombre de fichiers libres disponibles pour les processus non privilégiés (espace libre moins espace réservé).

avail = free - reserved

free
La quantité d'espace, en octets, libre sur le système de fichiers.
total_inodes
Le nombre total d'inodes dans le système de fichiers.
used_inodes
Le nombre d'inodes utilisés dans le système de fichiers.
free_inodes
Le nombre d'inodes libres dans le système de fichiers.
avail_inodes
Le nombre d'inodes libres disponibles pour les processus non privilégiés.
io_size
Une taille de bloc optimale suggérée pour les opérations d'E/S — si vous lisez ou écrivez beaucoup de données, faites-le par blocs de cette taille.
block_size
La taille en octets de l'unité d'allocation minimale sur ce système de fichiers.
total_blocks
Le nombre total de blocs dans le système de fichiers.
free_blocks
Le nombre de blocs libres dans le système de fichiers.
used_blocks
Le nombre de blocs utilisés dans le système de fichiers.
avail_blocks
Le nombre de blocs libres disponibles pour les processus non privilégiés.
systime
Le temps en secondes depuis l'époque où la statistique a été récupérée du noyau.

ERREURS

Seuls les systèmes de fichiers montés sont reconnus.

Certains systèmes de fichiers peuvent être signalés deux fois s'ils sont montés sur différents points de montage.

Les fonctions de comparaison existent plutôt pour la compatibilité descendante que pour l'amélioration des fonctionnalités. Une flexibilité limitée (par exemple, ordre inverse) et le manque d'opportunités d'optimisation pour le compilateur conduisent à la recommandation d'implémenter les routines de comparaison requises localement.

Appeler sg_set_valid_filesystems avec une liste vide effacera la liste interne des systèmes de fichiers valides. Il n'y a actuellement aucun moyen de réinitialiser à la liste initiale.
