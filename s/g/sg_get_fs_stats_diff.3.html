DESCRIPTION

Les fonctions sg_get_fs_stats fournissent des statistiques des systèmes de fichiers montés. Les deux fonctions prennent un paramètre facultatif pour le nombre d'entrées, qui pointe (si fourni) vers une variable de type size_t pour obtenir le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_fs_stats() et sg_get_fs_stats_r() fournissent les statistiques du système de fichiers au moment de l'appel de la fonction. Les fonctions sg_get_fs_stats_diff() et sg_get_fs_stats_diff_between() fournissent la différence entre deux appels de sg_get_fs_stats() ou sg_get_fs_stats_r(), respectivement.

Raccourci API

fonction retourne propriétaire des données
sg_get_fs_stats sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_r sg_fs_stats * l'appelant
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_diff_between sg_fs_stats * l'appelant
sg_get_valid_filesystems char ** libstatgrab (global)

Les vecteurs sg_fs_stats reçus de sg_get_fs_stats_r() ou sg_get_fs_stats_diff_between() doivent être libérés avec sg_free_fs_stats() lorsqu'ils ne sont plus nécessaires. L'appelant est responsable de cette opération.

La bibliothèque statgrab est livrée avec une liste intégrée de types de systèmes de fichiers valides, en fonction du système d'exploitation pour lequel elle a été compilée. Certains systèmes d'exploitation fournissent en outre une API pour connaître les types de systèmes de fichiers connus ou valides pour l'instance du système d'exploitation en cours d'exécution, ce qui est utilisé lorsqu'il est détecté. Néanmoins, il existe des problèmes connus lors de la collecte de statistiques de systèmes de fichiers : les systèmes de fichiers réseau sont montés à partir de serveurs défaillants, les développeurs de systèmes de fichiers exécutent un pilote expérimental, etc.

Pour éviter que les processus ne se bloquent lors de la collecte des statistiques de systèmes de fichiers ou pour permettre aux développeurs de tester leurs pilotes, les processus peuvent modifier la liste des systèmes de fichiers valides à l'aide de sg_get_valid_filesystems() et sg_set_valid_filesystems(). La liste de paramètres char * avec lesquels les deux fonctions travaillent est toujours terminée par un élément pointant vers NULL.

La liste retournée par sg_get_valid_filesystems() ne doit pas être modifiée. Copiez toujours la liste dans votre propre structure si vous prévoyez d'étendre ou de réduire la liste :

Exemple de suppression des systèmes de fichiers réseau

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* noms connus des systèmes de fichiers réseau sur différentes plateformes */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* dupliquer dans une mémoire propre pour modifier la liste */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copier y compris le pointeur NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Notez qu'il n'est pas nécessaire de dupliquer les chaînes contenues dans la liste des systèmes de fichiers valides dans l'exemple ci-dessus - elles ne sont pas modifiées.

La liste retournée par sg_get_valid_filesystems() peut devenir invalide lorsqu'elle est utilisée pendant que le processus effectue des appels à sg_set_valid_filesystems(). Aucune des fonctions sg_fs_stats ne protège l'accès au stockage globalement utilisé où est conservée la copie propre de la liste des systèmes de fichiers valides. Il incombe à l'appelant de ne pas mélanger les appels de configuration avec les appels pour récupérer les statistiques.

De plus, deux fonctions d'aide pour qsort(3) sont disponibles : sg_fs_compare_device_name() et sg_fs_compare_mnt_point().

Exemple de tri

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* trier les entrées par ordre alphabétique en utilisant le point de montage */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALEURS DE RETOUR

sg_get_fs_stats renvoie un pointeur vers une structure de type sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
nom_du_périphérique
Le nom connu du système d'exploitation. (par exemple, sous Linux, il peut s'agir de hda)
type_de_système_de_fichiers
Le type de système de fichiers (par exemple, hpfs ou ufs).
point_de_montage
Le point de montage où le système de fichiers est monté.
type_de_périphérique
Le type de périphérique du système de fichiers, actuellement non rempli et toujours sg_fs_unknown.
taille
La taille totale, en octets, du système de fichiers.

taille = utilisé + libre

utilisé
La quantité d'espace, en octets, utilisée sur le système de fichiers.
disponible
La quantité d'espace, en octets, disponible sur le système de fichiers pour l'utilisateur.

sg_get_fs_stats_diff.3.en

NAME

sg_get_fs_stats_diff - Renvoie la différence entre deux ensembles de statistiques de système de fichiers

SYNOPSIS 

#include <statgrab.h>
int sg_get_fs_stats_diff(sg_fs_stats_diff *diff, size_t *num_fs_stats,
                         error_t *error);

DESCRIPTION

La fonction sg_get_fs_stats_diff récupère les statistiques des systèmes de fichiers montés et les compare aux statistiques récupérées précédemment. Elle renvoie un tableau de structures sg_fs_stats_diff qui contiennent la différence entre les nouvelles et les anciennes statistiques.

Les statistiques sont récupérées pour tous les systèmes de fichiers montés. La comparaison est effectuée sur la base du point de montage.

Les champs de la structure sg_fs_stats_diff sont les suivants :

avail
L'espace disponible pour les processus non privilégiés (espace libre - espace réservé).
avail = free - reserved
free
L'espace libre, en octets, sur le système de fichiers.
total_inodes
Le nombre total d'inodes dans le système de fichiers.
used_inodes
Le nombre d'inodes utilisés dans le système de fichiers.
free_inodes
Le nombre d'inodes libres dans le système de fichiers.
avail_inodes
Le nombre d'inodes libres disponibles pour les processus non privilégiés.
io_size
Une taille de bloc optimale suggérée pour les opérations d'E/S -- si vous lisez ou écrivez beaucoup de données, faites-le par blocs de cette taille.
block_size
La taille en octets de l'unité minimale d'allocation sur ce système de fichiers.
total_blocks
Le nombre total de blocs dans le système de fichiers.
free_blocks
Le nombre de blocs libres dans le système de fichiers.
used_blocks
Le nombre de blocs utilisés dans le système de fichiers.
avail_blocks
Le nombre de blocs libres disponibles pour les processus non privilégiés.
systime
Le temps en secondes depuis l'époque où la statistique a été récupérée du noyau.

BUGS

Seuls les systèmes de fichiers montés sont reconnus.

Certains systèmes de fichiers peuvent être signalés deux fois s'ils sont montés sur différents points de montage.

Les fonctions de comparaison existent pour des raisons de compatibilité ascendante plutôt que pour des améliorations de fonctionnalités. La flexibilité limitée (par exemple, l'ordre inverse) et le manque d'opportunités d'optimisation pour le compilateur conduisent à la recommandation d'implémenter les routines de comparaison requises localement.

Appeler sg_set_valid_fileystems avec une liste vide efface la liste interne des systèmes de fichiers valides. Il n'y a actuellement aucun moyen de réinitialiser la liste initiale.
