SG_START(8) SG3_UTILS SG_START(8)

NOM

sg_start - envoie la commande SCSI START STOP UNIT : démarrer, arrêter, charger ou éjecter un média

SYNTAXE

sg_start [0] [1] [--eject] [--help] [--fl=FL] [--immed] [--load] [--loej] [--mod=PC_MOD] [--noflush] [--pc=PC] [--readonly] [--start] [--stop] [--verbose] [--version] PÉRIPH

sg_start [--eject] [--fl=FL] [-i] [--imm=0|1] [--load] [--loej] [--mod=PC_MOD] [--noflush] [--pc=PC] [-r] [--start] [--stop] [-v] [-V] [0|1] PÉRIPH

DESCRIPTION

sg_start envoie une commande SCSI START STOP UNIT au PÉRIPH avec les options sélectionnées. Les options les plus couramment utilisées sont --stop pour arrêter un disque et --start pour le démarrer. Utiliser --start sur un disque déjà en rotation est sans danger. Il existe un contrôle plus fin avec la « condition d'alimentation » : active, idle ou standby. Ceci est défini avec l'option --pc=PC. Dans certains contextes, l'état « stop » peut être considéré comme une condition d'alimentation supplémentaire.

Les périphériques contenant des médias amovibles tels que les lecteurs CD/DVD peuvent utiliser l'option --loej pour charger le média lorsqu'elle est utilisée conjointement avec --start (c'est-à-dire charger le média puis démarrer). Alternativement, --loej peut être utilisé pour éjecter le média lorsqu'elle est utilisée conjointement avec --stop (c'est-à-dire arrêter puis éjecter le média). Plus simplement, le chargement ou l'éjection d'un média amovible peut être demandé avec l'option --load ou --eject.

Si aucune option ou argument n'est donné, une action --start est supposée ; comme le suggère le nom de l'utilitaire.

Cet utilitaire supporte deux syntaxes de ligne de commande, la préférentielle est montrée en premier dans la syntaxe et expliquée dans cette section. Une section ultérieure sur l'ancienne syntaxe de ligne de commande décrit le second groupe d'options.

Note Linux : il est préférable de ne pas utiliser un nom de périphérique bloc standard (par exemple /dev/sdc) avec l'option --stop. Utilisez plutôt un nœud de périphérique sg ou bsg (voir lsscsi(8)). La couche bloc peut parfois remarquer que le disque s'arrête et décider : « ce n'est pas normal » et le redémarrer !

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes aussi.

0
même action que --stop.
1
même action que --start.
-e, --eject
arrête le média et l'éjecte du lecteur. Uniquement approprié pour un périphérique avec média amovible. Peut être ignoré (empêché), voir ci-dessous. Notez qu'il s'agit d'une opération qui peut être effectuée sur un lecteur de bande ou un lecteur CD/DVD/BD, pas sur un disque dur ou un SSD !
-h, --help
affiche le message d'utilisation puis quitte.
-f, --fl=FL
définit le numéro de couche de formatage sur lequel le disque doit « sauter » (défini dans MMC-5). Les valeurs de FL peuvent être de 0 à 3. Lorsque cette option est choisie, les bits FL, LoEj et Start sont définis dans le cdb comme requis par MMC-5 ; ainsi, l'utilisateur n'a pas besoin de définir les options --start et/ou --load.
-i, --immed
définit le bit IMM sur la commande START STOP UNIT afin que cet utilitaire revienne immédiatement sans attendre que le média achève l'action demandée. Par défaut, il attend que le média achève l'action demandée avant de revenir.
-l, --load
charge le média dans le lecteur et le démarre. Uniquement approprié pour un média amovible.
-L, --loej
définit le bit LOEJ sur la commande START STOP UNIT. Cela charge le média lorsque l'unité démarre ou l'éjecte lorsque l'unité s'arrête (c'est-à-dire fonctionne en conjonction avec le bit START dans le cdb). Cette option est ignorée si 'pc > 0'. Par défaut, elle est désactivée (c'est-à-dire ne pas tenter de charger ou d'éjecter le média). Si une indication de démarrage/arrêt n'est pas donnée (c'est-à-dire ni --start ni --stop) et que cette option est donnée, alors une action de chargement et de démarrage est supposée.
-m, --mod=PC_MOD
où PC_MOD est la valeur du « modificateur de condition d'alimentation ». Les valeurs de 0 à 15 (inclus) sont valides et 0 est la valeur par défaut. Ce champ « modificateur de condition d'alimentation » dans le cdb a été ajouté après sbc3r13.
-n, --noflush
ne pas effectuer de vidage vers le média (par exemple, comme le fait SYNCHRONIZE CACHE) avant une variante de cet utilitaire qui limite l'accès au média. L'utilisation de l'option --stop est un exemple de quelque chose qui limite l'accès au média. Ce champ « noflush » dans le cdb a été ajouté après sbc3r13.
-O, --old
passe aux options de style ancien. Veuillez l'utiliser comme première option.
-p, --pc=PC
où PC est la valeur des « conditions d'alimentation ». Les valeurs de 0 à 15 (inclus) sont valides. La valeur par défaut est 0. Lorsque '--pc=0' alors --eject, --load, --loej, --start et --stop sont actifs. Certaines valeurs courantes sont 1 pour la condition d'alimentation « active » (SBC) ; 2 pour la condition d'alimentation idle ; 3 pour la condition d'alimentation standby ; 5 pour la condition d'alimentation sleep (MMC) ; 7 pour LU_CONTROL (SBC), 0xa (décimal 10) pour FORCE_IDLE_0 (SBC) et 0xb (décimal 11) pour FORCE_STANDBY_0 (SBC). Voir les récentes ébauches SBC-3, MMC-5 et SAS sur www.t10.org pour plus d'informations.
-r, --readonly
ouvre le PÉRIPH en mode lecture seule. Peut être nécessaire sous Linux pour arrêter un redémarrage intempestif si le PÉRIPH est un disque ATA. Le redémarrage intempestif peut se produire à la fin de cette commande, annulant l'effet de l'option --stop.
-s, --start
démarre (mise en rotation) le PÉRIPH. Ceci définit le bit START dans le cdb. Utiliser cette option sur un périphérique déjà démarré est sans danger. En l'absence d'autres options, cette option est par défaut (c'est-à-dire définit le bit START du cdb).
-S, --stop
arrête (désactivation de la rotation) le PÉRIPH. Ceci efface le bit START dans le cdb. Cette opération est généralement effectuée sur un disque dur ou un SSD. Dans le cas d'un SSD, il sera placé en mode basse consommation et pourra nécessiter une opération de démarrage ultérieure avant que les IO normales ne puissent reprendre.
-v, --verbose
augmente le niveau de verbosité. Peut être utilisé plusieurs fois.
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Pour éviter la confusion, une seule des options 0, 1, --eject, --load, --start et --stop doit être utilisée.

Il existe une page de mode associée « condition d'alimentation » (0x1a) dans laquelle les valeurs de temporisation peuvent être définies pour passer à l'état idle ou standby après une période d'inactivité. L'utilitaire sdparm peut être utilisé pour visualiser la page de mode de condition d'alimentation et, si nécessaire, la modifier. Si un PÉRIPH est dans un état de condition d'alimentation idle ou standby, alors une commande REQUEST SENSE (voir l'utilitaire sg_requests) devrait retourner une clé de sens de « pas de sens » et un code de sens supplémentaire de « Basse condition d'alimentation activée » sur les périphériques SCSI récents.

L'éjection de médias amovibles (par exemple 'sg_start --eject /dev/hdd' où le PÉRIPH est un lecteur CD/DVD ATAPI) peut être empêchée par une commande SCSI antérieure PREVENT ALLOW MEDIUM REMOVAL (voir sg_prevent). Dans ce cas, cet utilitaire devrait échouer avec une erreur générée par le périphérique : demande illégale / retrait du média empêché. Cela peut être outrepassé en utilisant sg_prevent ou, par exemple, 'sdparm --command=unlock /dev/hdd'.

La commande SCSI TEST UNIT READY peut être utilisée pour savoir si un PÉRIPH est prêt à transférer des données. Si les médias rotatifs sont à l'arrêt ou montent encore en vitesse, alors la commande TEST UNIT READY retournera une clé de sens « non prêt » et un code de sens supplémentaire plus informatif. Voir l'utilitaire sg_turs.

Dans la série 2.4 des noyaux Linux, le PÉRIPH doit être un périphérique générique SCSI (sg). Dans la série 2.6, les périphériques blocs (par exemple, disques SCSI et lecteurs DVD) peuvent également être spécifiés. Par exemple, « sg_start 0 /dev/sda » fonctionnera dans le noyau série 2.6

sg_start(8) — sg3_utils

NAME

sg_start – start, stop, load or eject medium in a SCSI or ATA device

SYNOPSIS

sg_start [OPTIONS] DEVICE ...

DESCRIPTION

This utility sends a SCSI START STOP UNIT command (SBC-2) or an ATA (ATAPI) SET FEATURES command to the given DEVICE(s) to start (spin up), stop (spin down), load or eject the medium. The DEVICE argument is typically a SCSI or ATA device name like /dev/sg0 or /dev/sda.

OPTIONS

-i, --imm=0|1
sets the IMM (immediate) bit. When 1, this utility returns immediately after the START STOP UNIT command is sent. When 0 (the default), this utility waits until the device has completed the requested action (e.g. spun down or spun up).
--load
load the medium in the drive and start it. Equivalent to the new interface "start" operation, but with the LOEJ bit also set.
--eject
stop the medium and eject it from the drive. Equivalent to the new interface "stop" operation, but with the LOEJ bit also set.
--start
start (spin up) the medium in the drive. This is the default action if no option is given.
--stop
stop (spin down) the medium in the drive. This is equivalent to the older interface "0" argument.
-N, --new
Switch to the newer command line options. This is the default.
-O, --old
Switch to the older command line options. See the "OLDER COMMAND LINE OPTIONS" section below.
-v, --verbose
increase the level of verbosity, and print debug information. Can be given multiple times.
-V, --version
print out the version string then exit.

NOTES

In the Linux 2.6 series, especially with ATA disks, using this utility to stop (spin down) a disk may not be sufficient and other mechanisms will start the disk again some time later. The user might additionally mark the disk as "offline" with 'echo offline > /sys/block/sda/device/state' where sda is the block name of the disk. To restart the disk "offline" can be replaced with "running". Note that once the 'state' is set to offline, no SCSI commands can be sent to the device until it is set back to running. Also stopping a disk via a pass-through interface (e.g. /dev/sg1 or /dev/bsg/1:0:0:0) may reduce unwanted side effects (such as restarting it again when this utility completes).

EXIT STATUS

The exit status of sg_start is 0 when it is successful. Otherwise see the sg3_utils(8) man page.

OLDER COMMAND LINE OPTIONS

The options in this section were the only ones available prior to sg3_utils version 1.23 . Since then this utility defaults to the newer command line options which can be overridden by using --old (or -O) as the first option. See the ENVIRONMENT VARIABLES section for another way to force the use of these older command line options.

Note that the action of --loej is slightly different in the older interface: when neither --start nor --stop (nor proxies for them) are given, --loej performs an eject operation. In the same situation the newer interface will perform a load operation.

Earlier versions of sg_start had a '-s' option to perform a SYNCHRONIZE CACHE command before the START STOP UNIT command was issued. According to recent SBC-2 drafts this is done implicitly if required. Hence the '-s' option has been dropped.

All options, other than '-v' and '-V', can be given with a single "-". For example: "sg_start -stop /dev/sda" and "sg_start --stop /dev/sda" are equivalent. The single "-" form is for backward compatibility.

0
stop (spin-down) DEVICE.
1
start (spin-up) DEVICE.
--eject
stop the medium and eject it from the drive.
--fl=FL
sets the format layer number for the disc to "jump" to (defined in MMC-5).
-i
sets the IMM bit on the START STOP UNIT command so this utility will return immediately and not wait for the media to spin down. Same effect as '--imm=1'. The default action (without this option or a '--imm=1' option) is to wait until the media spins down before returning.
--imm=0|1
when the immediate bit is 1 then this utility returns immediately after the DEVICE has received the command. When this option is 0 (the default) then the utility returns once the command has completed its action (i.e. it waits until the device is started or stopped).
--load
load the medium in the drive and start it.
--loej
sets the LOEJ bit in the START STOP UNIT cdb. When a "start" operation is indicated, then a load and start is performed. When a "stop" operation is indicated, then a stop and eject is performed. When neither a "start" or "stop" operation is indicated does a stop and eject. [Note that the last action differs from the new interface in which the option of this name defaults to load and start.]
-N, --new
Switch to the newer style options.
--mod=PC_MOD
where PC_MOD is the 'power condition modifier' value. 0 to 15 (inclusive) are valid and 0 is the default. This field was added after sbc3r13.
--noflush
do not perform a flush to media (e.g. like SYNCHRONIZE CACHE does) before a variant of this utility that limits access to the media. Using the --stop option is an example of something that limits access to the media. This field was added after sbc3r13.
--pc=PC
where PC is the 'power condition' value (in hex). 0 to f (inclusive) are valid. Default value is 0.
-r
see the --readonly option above. May be useful for ATA disks.
--start
start (spin-up) DEVICE.
--stop
stop (spin-down) DEVICE. Same meaning as "0" argument.
-v
verbose: outputs SCSI command in hex to console before with executing it. '-vv' and '-vvv' are also accepted yielding greater verbosity.
-V
print out version string then exit.

ENVIRONMENT VARIABLES

Since sg3_utils version 1.23 the environment variable SG3_UTILS_OLD_OPTS can be given. When it is present this utility will expect the older command line options. So the presence of this environment variable is equivalent to using --old (or -O) as the first command line option.
