NOM

sg_opcodes - rapporte les commandes SCSI prises en charge ou les fonctions de gestion de tâches

SYNTAXE

sg_opcodes [--alpha] [--compact] [--enumerate] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--mask] [--mlu] [--no-inquiry] [--opcode=OP[,SA]] [--pdt=DT] [--raw] [--rctd] [--repd] [--sa=SA] [--tmf] [--unsorted] [--verbose] [--version] DEVICE

sg_opcodes [-a] [-c] [-e] [-H] [-i=FN] [-j] [-m] [-M] [-n] [-o=OP] [-p=DT] [-q] [-R] [-s=SA] [-t] [-u] [-v] [-V] [-?] DEVICE

DESCRIPTION

Cet utilitaire envoie une commande SCSI REPORT SUPPORTED OPERATION CODES ou REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS au DEVICE et affiche ensuite la réponse. L'action par défaut est de rapporter les codes d'opération pris en charge. Dans ce mode, il listera toutes les commandes prises en charge ou fournira des informations détaillées sur une commande spécifique identifiée par l'option --opcode=OP (éventuellement avec des informations supplémentaires de l'option --sa=SA).

Le nom d'une commande SCSI dépend de son type de périphérique périphérique (par exemple, un disque). Les commandes REPORT SUPPORTED OPERATION CODES et REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS ne sont pas prises en charge dans l'ensemble de commandes MMC pour les périphériques CD et DVD. Cet utilitaire effectue une commande INQUIRY pour obtenir le type de périphérique périphérique et affiche les chaînes du fournisseur, du produit et de la révision.

Une installation similaire pour interroger les codes d'opération pris en charge était auparavant disponible via le bit CmdDt dans la commande SCSI INQUIRY (voir sg_inq(8)). Cependant, cette installation a été rendue obsolète et remplacée par la commande REPORT SUPPORTED OPERATION CODES dans SPC-3 (révision 4) en février 2002.

Cet utilitaire prend en charge deux syntaxes de ligne de commande, la préférentielle est montrée en premier dans la syntaxe et expliquée dans cette section. Une section ultérieure sur la syntaxe de commande ancienne décrit le deuxième groupe d'options.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-a, --alpha
lorsque toutes les commandes prises en charge sont listées, il n'y a aucune exigence pour le serveur de périphérique (c'est-à-dire le DEVICE) de trier la liste des commandes. Lorsque cette option est donnée, la liste des commandes prises en charge est triée par nom (alphabétiquement). Lorsque cette option et l'option --unsorted ne sont ni données, la liste des commandes prises en charge est triée numériquement (d'abord par code d'opération, puis par action de service).
-c, --compact
certains noms de commandes, en particulier ceux associés à certaines actions de service, sont de plus en plus longs. Cela peut provoquer un retour à la ligne dans le mode une ligne par commande sur certains terminaux. Lorsque cette option est donnée, les champs de code d'opération et d'action de service sont combinés en un seul champ avec l'action de service, préfixé par une virgule affichée directement après le code d'opération. S'il n'y a pas d'action de service associée à la commande, alors la virgule et l'action de service ne sont pas affichées après le code d'opération. Le champ de taille du CDB n'est pas affiché lorsque cette option est donnée.
-e, --enumerate
cette option affiche le nom de la commande SCSI basé sur le code d'opération donné, le type de périphérique périphérique et éventuellement l'action de service. Si donné, DEVICE est ignoré. Le code d'opération, le type de périphérique périphérique et l'action de service sont mis à zéro par défaut s'ils ne sont pas donnés. Ainsi, si cette option est la seule option donnée, "Test Unit ready" est affiché car son code d'opération est 0, il n'a pas d'action de service et il est commun à tous les types de périphériques périphériques car il est défini dans les normes SCSI Primary Commands (SPC).
-h, --help
affiche le message d'utilisation résumant les options de la ligne de commande, puis se termine. Ignore DEVICE s'il est donné.
-H, --hex
affiche la réponse en hexadécimal ASCII sur stdout. Lorsqu'utilisé une ou deux fois, chaque ligne commence par une adresse relative (hex) commençant à 0 sur la première ligne hexadécimale affichée. La différence est que lorsqu'il est utilisé deux fois, les octets hexadécimaux sont rendus en ASCII à droite de chaque ligne ; les caractères non imprimables sont remplacés par "." .
Lorsqu'il est utilisé trois fois ou plus, il n'y a pas d'adresse relative au début de chaque ligne. Cette sortie convient pour être redirigée vers un fichier qui peut plus tard être donné à l'option --inhex=FN.
-i, --inhex=FN
où FN est un nom de fichier dont le contenu est supposé être en hexadécimal ASCII. Si DEVICE est également donné, alors DEVICE est ignoré, un avertissement est émis et l'utilitaire continue, décodant le fichier nommé FN. Voir la section "FORMATS HEX, BINAIRE ET JSON" dans la page man sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors le contenu de FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du format texte brut. Notez que les arguments des formes courte et longue sont facultatifs et, s'ils sont présents, commencent par "=" et aucun espace n'est autorisé autour de ce "=" .
Voir la page man sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non défaut.
-m, --mask
affiche en plus le masque cdb en hexadécimal. Ainsi, un cdb de 12 octets aura un masque hexadécimal de 12 octets. Si l'hexadécimal est développé (mentalement) en binaire, alors un "1" signifie que la position correspondante dans le cdb peut être définie. Et "0" signifie que la position correspondante dans le cdb ne doit pas être définie. Pour les positions de masque "0" qu'un utilisateur essaie de définir dans un cdb, le périphérique peut soit l'ignorer, soit signaler une erreur, généralement avec une clé de détection de "requête illégale".
-M, --mlu
affiche en plus une indication (0 ou 1) si la commande affecte toutes les unités logiques de la cible contenante. MLU (Multiple Logical Units) est un bit dans la réponse REPORT SUPPORTED OPERATION CODES introduit par la proposition 18-045r1 (et potentiellement dans spc5r20). Sans l'option, le format de sortie par défaut qui liste tous les codes d'opération n'inclut pas d'indication MLU.
-n, --no-inquiry
avant d'appeler une commande SCSI REPORT SUPPORTED OPERATION CODES ou REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS, une commande SCSI INQUIRY est effectuée. La raison est de déterminer le type de périphérique périphérique (pdt) du DEVICE car cela est utile pour traduire les codes d'opération en noms de commandes. Par défaut, cet utilitaire affiche un résumé de la réponse de la commande INQUIRY sur stdout. Si cette option (ou l'option --raw) est donnée, alors ce résumé n'est pas affiché sur stdout.
-O, --old
Passer aux options de style plus ancien. Veuillez utiliser comme première option.
-o, --opcode=OP[,SA]
le DEVICE sera interrogé pour le code d'opération donné (c'est-à-dire la valeur OP) qui est le premier octet d'une commande SCSI. Optionnellement, si une valeur SA est donnée, elle sera utilisée comme action de service de cette commande SCSI. Notez que OP et OP,0 ne sont pas la même chose, car SCSI autorise l'action de service à être 0 (mais pas dans cette commande). OP et SA sont décimaux sauf s'ils sont préfixés par "0x" ou s'ils ont un "h" final. OP doit être dans la plage 0 à 255 (0xff) inclusivement. SA doit être dans la plage 0 à 65535 (0xffff) inclusivement. Lorsque cette option n'est pas donnée, toutes les commandes SCSI disponibles prises en charge par le DEVICE sont listées.

NAME

sg_opcodes - get SCSI operation codes and supported commands from a SCSI device or cd/dvd.

SYNOPSIS

sg_opcodes [OPTIONS] DEVICE

DESCRIPTION

This utility lists SCSI commands supported by a given SCSI device. It does this by sending a SCSI REPORT SUPPORTED OPERATION CODES command (in older versions, it might use a SCSI INQUIRY command).

-a, --alpha
sort command names alphabetically. When this option is not given the supported commands are sorted numerically (first by operation code and then by service action).
-c, --compact
output response in compact binary form. The output is suitable for piping to another utility like sg_decode_sense or sg_decode_command.
-e, --enumerate=DEVICE
query the given DEVICE for command information. This is done by sending a SCSI INQUIRY command to find the peripheral device type.
-h, --help
output the usage message and exit.
-H, --hex
output response in hexadecimal form.
-i, --inhex=FN
read command data from file FN. The data in FN is interpreted as hexadecimal. Used together with --raw to decode a previously saved binary output.
-m, --mask=MASK
only list supported commands where the operation code matches the given MASK. The MASK is a hexadecimal number where a '1' bit means that the corresponding bit in the operation code must match the bit in the mask. A '0' bit means that the corresponding bit in the operation code is ignored. The default mask is 0xff.
-O, --old
use older command line option style. See the EXAMPLES section for details.
--op=OP
the DEVICE will be queried for the given operation code (i.e. OP) which is the first byte of a SCSI command. OP is hexadecimal and expected to be in the range 0 to ff inclusive. When this option is not given then all available SCSI commands supported by the DEVICE are listed.
-p, --pdt=PDT
peripheral device type. This is used together with --enumerate to differentiate when a command opcode (and perhaps service action) is shared by multiple device types.
Numerical values between -1 and 31 (inclusive) may be used where -1 implies what is in SPC. Names like 'tape', 'disk' and 'processor' may also be given.
This option may also be used with the --no-inquiry option to suppress this utility doing an INQUIRY command since the main reason for doing that is to find the peripheral device type of the DEVICE.
-r, --raw
output response in binary (to stdout) unless the --inhex=FN option is also given. In that case the input file name (FN) is decoded as binary (and the output is _not_ in binary (but may be hex)).
-R, --rctd
set report command timeout descriptor (RCTD) bit in the cdb. The response may or may not contain command timeout descriptors. If available they are output. If supported there are two values: a nominal command timeout and a recommended command timeout. Both have units of seconds. A value of zero means that no timeout is indicated and this is shown in the corresponding decoded output as "-".
-q, --repd
set read extended parameter data (REPD) bit in the report task management functions cdb. 16 bytes rather than the default 4 bytes expected in the response. This was added in SPC-4 (revision 26).
-s, --sa=SA
the DEVICE will be queried for a command with the given service action (i.e. the SA value). Used in conjunction with the --opcode=OP option. If this option is not given, --opcode=OP is given and the command in question does have a service action then a value of 0 will be assumed. SA is decimal and expected to be in the range 0 to 65535 (0xffff) inclusive.
-t, --tmf
list supported task management functions. This is done with the SCSI REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS command. When this option is chosen the --alpha, --opcode=OP, --rctd, --sa=SA and --unsorted options are ignored.
-u, --unsorted
when all supported commands are being listed there is no requirement for the device server (i.e. the DEVICE) to sort the list of commands. When this option is given the list of supported commands is in the order given by the DEVICE. When this option is not given the supported commands are sorted numerically (first by operation code and then by service action).
-v, --verbose
increase level of verbosity. Can be used multiple times.
-V, --version
print out version string then exit.

NOTES

As of SPC-5 revision 8 the recognized task management functions are: abort set, abort task set, clear ACA, clear task set, logical unit reset, query task, query asynchronous event, query task set, and I_T nexus reset. In SPC-4 revision 26 target reset and wakeup task management functions were made obsolete.

In the 2.4 series of Linux kernels the DEVICE must be a SCSI generic (sg) device. In the 2.6 series block devices (e.g. SCSI disks and DVD drives) can also be specified. For example "sg_opcodes /dev/sda" will work in the 2.6 series kernels.

EXIT STATUS

The exit status of sg_opcodes is 0 when it is successful. Otherwise see the sg3_utils(8) man page.

EXAMPLES

The examples in this page use Linux device names. For suitable device names in other supported Operating Systems see the sg3_utils(8) man page.

To see the information about a specific command give its operation code to the '--op=' option. A command line invocation is shown first followed by a typical response:


# sg_opcodes --op=93h /dev/sdb


Opcode=0x93
Command_name: Write same(16)
Command supported [conforming to SCSI standard]
Usage data: 93 e2 00 00 00 00 ff ff ff ff 00 00 ff ff 00 00

The next example shows the supported task management functions:


# sg_opcodes --tmf -n /dev/sdb

Task Management Functions supported by device:
Abort task
Abort task set
Clear ACA
Clear task set
Logical unit reset
Query task

Enumerate can be used to look up a SCSI command name in the absence of a device that supports that command. The opcode and service action (if required) should be supplied:


# sg_opcodes --enumerate --op=0x9b,0xa


SCSI command:
Read buffer(16), read data from echo buffer

ENVIRONMENT VARIABLES

Since sg3_utils version 1.23 the environment variable SG3_UTILS_OLD_OPTS can be given. When it is present this utility will expect the older command line options. So the presence of this environment variable is equivalent to using --old (or -O) as the first command line option.

NOM

sg_opcodes - lister les codes d'opération SCSI et leurs descriptions

SYNTAXE

sg_opcodes [-a] [-H] [-h] [-v] [-V] [-d DEVICES] [-m MAJORS] [-n NUMBERS]

DESCRIPTION

Ce programme interroge un ou plusieurs périphériques SCSI pour obtenir la liste des codes d'opération SCSI qu'ils prennent en charge, puis affiche ces codes ainsi que leurs descriptions.

OPTIONS

  • -a, --all : Afficher tous les codes d'opération, y compris ceux qui ne sont pas pris en charge.
  • -H, --hex : Afficher les codes d'opération en hexadécimal.
  • -h, --help : Afficher un message d'aide et quitter.
  • -v, --verbose : Mode verbeux.
  • -V, --version : Afficher les informations de version et quitter.
  • -d, --devices=DEVICES : Spécifie les périphériques à interroger. Les valeurs possibles sont scsi (tous les périphériques SCSI), usb (périphériques USB SCSI), sata (périphériques SATA SCSI) ou sas (périphériques SAS SCSI). La valeur par défaut est scsi.
  • -m, --majors=MAJORS : Spécifie les numéros de majeure des périphériques à interroger.
  • -n, --numbers=NUMBERS : Spécifie les numéros de périphériques à interroger.

NOTES

Ce programme nécessite des privilèges root pour accéder aux périphériques SCSI.

STATUT DE SORTIE

Retourne 0 en cas de succès, une valeur non nulle en cas d'erreur.

OPTIONS DE LIGNE DE COMMANDE ANTÉRIEURES

Les options suivantes étaient prises en charge dans les versions antérieures mais sont maintenant obsolètes :

  • -e : Équivalent à -a.

EXEMPLES

Pour lister tous les codes d'opération SCSI pris en charge par le système :

# sg_opcodes

Pour lister tous les codes d'opération SCSI, y compris ceux non pris en charge :

# sg_opcodes -a

Pour lister les codes d'opération SCSI des périphériques USB :

# sg_opcodes -d usb
