NOM

sg_format - formater, formater avec préréglage, redimensionner un disque SCSI ; formater une bande

SYNOPIS

sg_format [--cappid] [--cmplst={0|1}] [--count=COUNT] [--dcrt] [--dry-run] [--early] [--ffmt=FFMT] [--fmtmaxlba [--format] [--help] [--ip-def] [--long] [--mode=MP] [--pfu=PFU] [--pie=PIE] [--pinfo] [--poll=PT] [--preset=ID] [--quick] [--resize] [--rto_req] [--security] [--six] [--size=LB_SZ] [--tape=FM] [--timeout=SECS] [--verbose] [--verify] [--version] [--wait] PÉRIPHÉRIQUE

DESCRIPTION

Tous les périphériques d'accès direct SCSI n'ont pas besoin d'être formatés, et certains disposent de procédures de formatage spécifiques au fabricant. Les disques SCSI avec support rotatif constituent probablement le plus grand groupe qui supporte une opération de formatage « standard ». Ils sont généralement formatés en usine avec une taille de bloc de 512 octets et le plus grand nombre de blocs que le fabricant recommande. La recommandation du fabricant laisse généralement de côté un certain nombre de pistes, réparties sur le support, pour la réaffectation de blocs aux adresses de blocs logiques pendant la durée de vie du disque.

Cet utilitaire émet l'une des trois commandes SCSI de formatage : FORMAT UNIT, FORMAT MEDIUM ou FORMAT WITH PRESET. Dans la description suivante, les sections non qualifiées feront généralement référence à la commande SCSI FORMAT UNIT. FORMAT UNIT et FORMAT WITH PRESET s'appliquent tous deux aux disques (ou périphériques de type disque). La commande FORMAT MEDIUM est destinée aux bandes. Une réponse SCSI INQUIRY catégorise le « Peripheral Device Type » (PDT) de chaque périphérique SCSI. Cet utilitaire utilise le PDT pour vérifier s'il y a un conflit entre le PÉRIPHÉRIQUE et l'option donnée (par exemple, donner l'option --tape=FM lorsque PÉRIPHÉRIQUE est un disque normal). En cas de conflit, cet utilitaire ne continuera pas.

Cet utilitaire peut formater les disques SCSI modernes et potentiellement changer leur taille de bloc (si autorisé) et le nombre de blocs (c'est-à-dire le nombre de blocs accessibles sur le support, également connu sous le nom de « redimensionnement »). Redimensionner un disque à un nombre de blocs inférieur à celui recommandé par le fabricant est parfois appelé « short stroking » (voir la section NOTES). Le redimensionnement du nombre de blocs sans changer la taille des blocs peut ne pas nécessiter d'opération de formatage. La norme SBC-2 (voir www.t10.org) a rendu obsolète la page de mode « format device ». Beaucoup de détails de bas niveau trouvés dans cette page de mode sont maintenant laissés à la discrétion du fabricant. Il existe une page de journal de statut de format qui rend compte des opérations de formatage réussies précédentes.

Lorsque cet utilitaire est utilisé sans options (c'est-à-dire qu'on lui donne uniquement un argument PÉRIPHÉRIQUE), il affiche la taille de bloc existante et le nombre de blocs dérivés de deux sources. Ces deux sources sont un descripteur de bloc dans la réponse à une commande MODE SENSE et la réponse à une commande READ CAPACITY. La raison de cette double vérification est de détecter un état de « format corrompu » (voir la section NOTES). Cette utilisation ne modifiera pas le disque.

Lorsque cet utilitaire est utilisé avec --format, --preset=ID ou --tape=FM, il tentera de formater le PÉRIPHÉRIQUE donné. En l'absence de l'option --quick, il y a une pause de 15 secondes pendant laquelle l'utilisateur est invité à trois reprises (toutes les 5 secondes) à abandonner sg_format. Cela se produit juste avant que la commande SCSI FORMAT UNIT, FORMAT WITH PRESET ou FORMAT MEDIUM ne soit émise. Voir la section NOTES pour plus d'informations.

Les informations de protection (PI) sont facultatives et sont composées d'un ou plusieurs intervalles de protection, chacun composé de 8 octets associés à un bloc logique. Lorsque PI est actif, chaque bloc logique aura 1, 2, 4, 8, etc. intervalles de protection (c'est-à-dire une puissance de deux), entrelacés avec (et suivant) les données utilisateur auxquelles ils se réfèrent. Quatre types de protection sont définis, le type de protection 0 n'ayant pas d'intervalles de protection. Voir la section INFORMATIONS DE PROTECTION ci-dessous pour plus d'informations.

Lorsque l'option --tape=FM est donnée, la commande SCSI FORMAT MEDIUM est envoyée au PÉRIPHÉRIQUE. FORMAT MEDIUM est défini dans les documents SSC de T10 et prépare un volume à l'utilisation. Cela peut inclure le partitionnement du support. Voir la section ci-dessous sur TAPE pour plus d'informations.

FORMAT WITH PRESET a été ajouté dans la version préliminaire SBC-4 révision 18. Un modèle prédéfini, sélectionné par le champ PRESET IDENTIFIER (--id=FWPID), est écrit sur le disque. Voir la page VPD de Format Presets (0xb8) pour une liste des identificateurs de préréglage de format disponibles et de leurs données associées.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont classées par ordre alphabétique basé sur le nom de l'option longue.

-a, --cappid
cette option définit le bit CAPPID dans l'en-tête MODE SELECT qui fait partie de la liste de paramètres de cette commande. Une commande MODE SELECT est nécessaire lorsque le COUNT (c'est-à-dire le nombre de blocs logiques) est modifié. La commande MODE SELECT doit réussir avant que la commande FORMAT UNIT ne soit exécutée. Le bit CAPPID (introduit dans SBC-5 révision 4) est étroitement lié à la page VPD de mappage de la capacité/identification du produit (0xba). Si cette page VPD n'est pas présente, alors le bit CAPPID n'est pas défini à moins que l'option ne soit donnée deux fois. Si le bit CAPPID n'est pas supporté, une clé de détection « illegal request » avec un sens additionnel « invalid field in parameter list » devrait être rapportée.
En cas de succès, cette option peut modifier le champ d'identification du produit de la réponse INQUIRY standard. Si c'est le cas, une condition d'attention d'unité est définie avec un sens additionnel « Inquiry data has changed ».
-C, --cmplst={0|1}
définit le bit CMPLST (« complete list ») dans le cdb FORMAT UNIT à 0 ou 1. Si la valeur est 0, la liste GLIST (liste étendue) existante est prise en compte. Si la valeur est 1, la GLIST existante est ignorée. CMPLST est par défaut à 1, sauf lorsque la valeur de l'option --ffmt=FFMT est non nulle, auquel cas CMPLST est par défaut à 0. Voir la section LISTS ci-dessous. Dans la plupart des cas, ce bit doit être laissé à sa valeur par défaut.
Si cette option est donnée deux fois, la certification est activée en effaçant le bit DCRT et en définissant le bit FOV.
-c, --count=COUNT
où COUNT est le nombre de blocs à formater ou le nombre de supports à redimensionner. Peut être utilisé avec --format ou --resize. Avec --format, cette option n'a pas besoin d'être donnée, auquel cas elle est supposée être zéro.
Avec --format, l'interprétation de COUNT est :
(COUNT > 0) : formater uniquement les COUNT premiers blocs et READ CAPACITY indiquera COUNT blocs après le formatage
(COUNT = 0) et taille de bloc inchangée : utiliser le nombre de blocs existant
(COUNT = 0) et taille de bloc modifiée : nombre maximal de blocs recommandé pour la nouvelle taille de bloc
(COUNT = -1) : utiliser le nombre maximal de blocs recommandé
(COUNT < -1) : illégal Avec --resize, cette option doit être donnée et COUNT a cette interprétation :
(COUNT > 0) : après le redimensionnement, READ CAPACITY indiquera COUNT blocs
(COUNT = 0) : après le redimensionnement, READ CAPACITY indiquera 0 blocs
(COUNT = -1) : après le redimensionnement, READ CAPACITY indiquera son nombre maximal de blocs
(COUNT < -1) : illégal
Dans les deux cas, si le COUNT donné dépasse le nombre maximal de blocs (pour la taille de bloc), le disque signale une erreur. Voir la section NOTES ci-dessous.
-D, --dcrt
cette option définit le bit DCRT dans l'en-tête de la liste de paramètres de la commande FORMAT UNIT. Elle « désactivera la certification ». La certification vérifie que les blocs sont utilisables pendant le processus de formatage. L'utilisation de cette option peut accélérer le formatage, mais --ffmt=FFMT, si disponible, serait probablement meilleure. L'action par défaut de cet utilitaire (c'est-à-dire lorsque cette option n'est pas donnée) est d'effacer le bit DCRT, demandant ainsi la « certification du support » (également, sauf si une autre option l'exige, le bit FOV sera effacé). Lorsque le bit DCRT est défini, le bit FOV doit également être défini, donc sg_format le fait.
Si cette option est donnée deux fois, la certification est activée en effaçant le bit DCRT et en définissant le bit FOV. Ces deux bits se trouvent dans la liste de paramètres associée au cdb FORMAT UNIT.
-d, --dry-run
cette option analysera la ligne de commande, effectuera toute la préparation mais sautera l'exécution réelle de la commande FORMAT UNIT, FORMAT WITH PRESET ou FORMAT MEDIUM.
-e, --early
cette option définit le bit EARLY dans le cdb FORMAT UNIT. Le bit EARLY est destiné à être utilisé avec les disques qui ont une « synchronisation de format » (format synchronization) via une commande SYNC CACHE.
-f, --ffmt=FFMT
cette option définit la valeur du champ FFMT (Fast Format) dans le cdb FORMAT UNIT. La valeur 0 est la valeur par défaut. Les valeurs de 1 à 7 sont autorisées. Si FFMT est différent de zéro, alors le bit CMPLST est défini sur 0 par défaut. Des valeurs plus élevées de FFMT peuvent indiquer un formatage plus rapide, potentiellement sans certification du support.
-F, --fmtmaxlba
cette option définit le bit FmTLBA (Format Media, Largest Logical Block Address) dans le cdb FORMAT UNIT. Cela indique que le COUNT (qui est le nombre de blocs logiques) dans le cdb spécifie la plus grande adresse de bloc logique à formater.
-F, --format
cette option indique à sg_format d'émettre une commande FORMAT UNIT. Ce sera le formatage standard du disque. Elle peut être utilisée avec --count pour spécifier un nombre de blocs cible. Si --count=0 est donné, le disque sera formaté au nombre maximal de blocs recommandé pour la taille de bloc donnée (ou la taille de bloc existante si elle n'est pas modifiée).
-h, --help
affiche le message d'aide et quitte.
-I, --ip-def
cette option définit le bit IP-DEF (Initialization Pattern - Default) dans le cdb FORMAT UNIT. Ce bit est utilisé pour formater le support avec un modèle d'initialisation par défaut.
-l, --long
augmente le niveau de verbosité. Peut être donné plusieurs fois.
-m, --mode=MP
spécifie la page de mode MP à afficher ou modifier. La valeur par défaut est la page de mode de format (page 3). Les valeurs des pages de mode doivent être comprises entre 0 et 62.
-p, --pfu=PFU
définit le bit PFU (Protect Information Full Utilization) dans le cdb FORMAT UNIT. Ce bit est lié à la manière dont les informations de protection sont utilisées. La valeur par défaut est 0.
-p, --pie=PIE
définit le champ PIE (Protection Information Enable) dans le cdb FORMAT UNIT. Ce champ contrôle l'activation des informations de protection. Les valeurs valides sont 0 à 3. La valeur par défaut est 0 (informations de protection désactivées).
-p, --pinfo
définit le bit PINFO (Protection Information) dans le cdb FORMAT UNIT. Lorsque ce bit est défini, cela indique que le support formaté inclura des informations de protection.
-p, --poll=PT
définit le temps d'attente (en secondes) pour l'interrogation de l'état du formatage. La valeur par défaut est 0, ce qui signifie que le formatage est effectué de manière non bloquante. Si une valeur de PT est donnée, l'utilitaire interrogera périodiquement le périphérique pour obtenir l'état jusqu'à ce que le formatage soit terminé ou qu'un délai d'attente soit atteint.
-P, --preset=ID
cette option indique à sg_format d'émettre une commande FORMAT WITH PRESET. L'argument ID est l'identificateur du préréglage à utiliser. Ce préréglage est appliqué au disque pendant le formatage.
-q, --quick
cette option définit le bit QUICK dans le cdb FORMAT UNIT. Cela accélère le processus de formatage en omettant certaines vérifications ou étapes. Ce bit est généralement utilisé avec des disques qui ont déjà été formatés ou qui n'ont pas besoin d'une certification complète du support.
-r, --resize
cette option indique à sg_format de redimensionner le support au nombre de blocs spécifié par l'option --count. Cela modifie la taille logique du périphérique sans nécessairement reformater physiquement le support.
-r, --rto_req
cette option définit le bit RTO_REQ (Return Target Online) dans le cdb FORMAT UNIT. Ce bit spécifie si le périphérique doit être ramené en ligne après une opération de formatage. Lorsque ce bit est défini, le périphérique peut être ramené en ligne automatiquement.
-s, --security
cette option définit le bit SECURITY dans le cdb FORMAT UNIT. Ceci est lié aux fonctions de sécurité du périphérique, telles que l'effacement sécurisé du support.
-s, --six
utilise le jeu de commandes SCSI-3 (pas SCSI-2). La plupart des périphériques modernes supportent SCSI-3. Ce n'est généralement pas nécessaire à spécifier.
-s, --size=LB_SZ
spécifie la nouvelle taille de bloc logique en octets. Par défaut, la taille de bloc existante est utilisée. Cette option ne peut être utilisée qu'avec les options --format ou --resize.
-t, --tape=FM
cette option indique à sg_format d'émettre une commande FORMAT MEDIUM (FM) au lieu d'une commande FORMAT UNIT. Elle est destinée aux périphériques de bande qui utilisent la commande FORMAT MEDIUM pour préparer le support à l'utilisation. FM peut être 0 (valeur par défaut) ou 1. La valeur 1 définit le bit ERT (Erase on Reformat) dans le cdb.
-t, --timeout=SECS
définit le délai d'attente (en secondes) pour l'opération de formatage. La valeur par défaut est 0, ce qui signifie qu'aucun délai d'attente n'est défini. Si une valeur de SECS est donnée, le périphérique signalera une erreur si l'opération de formatage ne se termine pas dans ce délai.
-v, --verbose
augmente le niveau de verbosité. Peut être donné plusieurs fois.
-v, --verify
définit le bit VERIFY dans le cdb FORMAT UNIT. Lorsque ce bit est défini, le périphérique effectuera une vérification après le formatage pour s'assurer que les blocs sont utilisables.
-V, --version
affiche les informations de version et quitte.
-w, --wait
attend que l'opération de formatage soit terminée. Sans cette option, la commande retourne immédiatement après avoir initié le formatage. L'interrogation de l'état du formatage peut être contrôlée par l'option --poll=PT.

NOTES

FORMAT CORRUPT

Un état de « format corrompu » se produit lorsqu'un disque est formaté, mais que les informations sur sa capacité (nombre de blocs et taille de bloc) ne correspondent pas entre les descripteurs de mode et la réponse READ CAPACITY. Cela peut arriver si une opération de formatage est interrompue, ou si le disque n'est pas complètement formaté.

L'utilisation de sg_format sans options permet de vérifier si un état de « format corrompu » est présent. Si tel est le cas, il est recommandé de formater à nouveau le disque en utilisant soit --format, soit --resize, en spécifiant un nombre de blocs cible.

SHORT STROKING

Le « short stroking » est une technique où un disque est formaté ou redimensionné pour n'exposer qu'une partie de sa capacité totale. Cela peut être fait pour améliorer les performances, en particulier sur les anciens disques durs rotatifs, en évitant les zones de faible performance situées vers la périphérie du disque. Cela peut également être utilisé pour des raisons de sécurité, en limitant l'espace disponible pour les données.

Pour effectuer un « short stroke », utilisez l'option --resize avec l'option --count spécifiant le nombre de blocs souhaité. Par exemple, pour redimensionner un disque à 10000 blocs, utilisez sg_format --resize --count=10000 /dev/sdX.

FORMATTING TAPE

Pour formater une bande, utilisez l'option --tape=FM. Cela émettra la commande SCSI FORMAT MEDIUM. Cette commande est utilisée pour préparer une bande à l'utilisation, ce qui peut inclure le partitionnement du support. L'option --poll=PT peut être utilisée pour suivre la progression du formatage, et l'option --wait pour attendre sa complétion.

PROTECTION INFORMATION (PI)

Les informations de protection (PI) sont une fonctionnalité des périphériques de stockage SCSI qui permet d'ajouter des données de contrôle d'intégrité à chaque bloc logique. Cela aide à détecter les erreurs de données qui pourraient survenir pendant le transfert ou le stockage.

Les options --pinfo, --pie=PIE et --pfu=PFU sont utilisées pour contrôler le comportement des informations de protection lors du formatage. Le type de protection 0 désactive les informations de protection, tandis que les types 1 à 3 les activent avec différentes configurations.

FORMAT PRESETS (SBC-4)

La commande FORMAT WITH PRESET, introduite dans la norme SBC-4, permet de formater un disque en utilisant un modèle prédéfini. Ces préréglages sont définis par le fabricant et peuvent être utilisés pour des opérations de formatage spécifiques. La page VPD 0xb8 (Format Presets) peut être interrogée pour obtenir la liste des identificateurs de préréglage disponibles.

Utilisez l'option --preset=ID pour spécifier le préréglage à utiliser, où ID est l'identificateur du préréglage.

FORMAT AVEC PRESET ou commande FORMAT MEDIUM. Également si les options devaient autrement modifier la taille du bloc logique, alors la commande MODE SELECT qui le ferait est également ignorée lorsque l'option de simulation à sec est donnée.
-e, --early
lors d'une opération de formatage, l'action par défaut de cet utilitaire est d'interroger le disque toutes les 60 secondes (ou toutes les 10 secondes si *FFMT* est non nul) pour déterminer la progression de l'opération de formatage jusqu'à ce qu'elle soit terminée. Lorsque cette option est donnée, cet utilitaire quittera "tôt", c'est-à-dire dès que l'opération de formatage aura commencé. L'utilisateur pourra alors surveiller la progression de l'opération de formatage en cours avec d'autres utilitaires (par exemple, sg_turs(8) ou sg_requests(8)). Cette option et *--wait* sont mutuellement exclusives.
-t, --ffmt=FFMT
*FFMT* (format rapide) est placé dans un champ du même nom dans la commande cdb FORMAT UNIT. Le champ a été introduit dans la révision 10 de SBC-4. La valeur par défaut est 0, ce qui implique l'action précédente qui consiste généralement à écraser tous les blocs sur le *DEVICE*. Cela peut prendre beaucoup de temps (par exemple, avec des disques durs de plus de 10 To, cela peut durer des jours). Avec *FFMT* réglé, ce temps peut être réduit à quelques minutes ou moins. Il vaut donc la peine d'essayer si c'est disponible.
*FFMT* a les valeurs 1 et 2 pour le formatage rapide, 3 étant actuellement réservé. Ces deux valeurs incluent cette description : "Le serveur de périphériques initialise le support... sans écraser le support (c'est-à-dire que les ressources pour gérer l'accès au support sont initialisées et que le support n'est pas écrit)". La différence entre 1 et 2 concerne les opérations de lecture sur les LBA sur lesquels aucune donnée n'a été écrite après le formatage rapide. Lorsque *FFMT* est 1, l'opération de lecture doit renvoyer des "données de bloc logique non spécifiées" et se terminer sans erreur. Lorsque *FFMT* est 2, l'opération de lecture peut générer un statut de vérification de condition avec une clé de détection définie sur erreur matérielle, erreur de support ou commande abandonnée. Voir la version préliminaire de SBC-4, révision 16, section 4.34 pour plus de détails.
-b, --fmtmaxlba
Cette option n'est active que si elle est donnée avec l'option *--preset=ID*. Si c'est le cas, elle définit le champ FMTMAXLBA dans la commande FORMAT WITH PRESET.
-f, --fmtpinfo=FPI
définit le champ FMTPINFO dans la commande cdb FORMAT UNIT à une valeur comprise entre 0 et 3. La valeur par défaut est 0. Le champ FMTPINFO de la révision 16 de SBC-3 est un champ de 2 bits (bits 7 et 6 de l'octet 1 dans le cdb). Avant cette révision, c'était un champ d'un seul bit (bit 7 de l'octet 1 dans le cdb) et il y avait un bit d'accompagnement appelé RTO_REQ (bit 6 de l'octet 1 dans le cdb). Les options obsolètes "--pinfo" et "--rto-req" représentent l'ancienne utilisation. Cette option doit être utilisée à leur place. Voir la section INFORMATIONS DE PROTECTION ci-dessous pour plus d'informations.
-F, --format
émet l'une des trois commandes SCSI "format". En l'absence des options *--preset=ID* et *--tape=FM*, la commande SCSI FORMAT UNIT est émise. **Ces commandes détruiront toutes les données contenues sur le support.** Cette option est nécessaire pour modifier la taille du bloc d'un disque. En l'absence de l'option *--quick*, l'utilisateur dispose d'un compte à rebours de 15 secondes pour réfléchir à la sagesse de le faire, pendant lequel le contrôle-C (entre autres commandes Unix) peut être utilisé pour tuer ce processus avant qu'il ne cause des dommages.
Lorsqu'elle est utilisée trois fois (ou plus), les commandes préliminaires MODE SENSE et SELECT sont ignorées, ne laissant que les commandes initiales INQUIRY et FORMAT UNIT. Ceci est pour une utilisation d'urgence (par exemple, lorsque les commandes MODE SENSE/SELECT ne fonctionnent pas) et ne peut pas modifier la taille du bloc logique.
Les périphériques zonés gérés par l'hôte (par exemple, de nombreux disques zonés) ont un PDT différent de celui des autres disques, mais peuvent toujours être formatés comme s'ils étaient des disques "normaux".
Voir la section NOTES pour les détails d'implémentation et la section EXEMPLES pour une utilisation typique.
-h, --help
imprime les informations d'utilisation puis quitte.
-I, --ip-def
définit le motif d'initialisation par défaut. Certains disques (SSD) l'utilisent pour indiquer qu'un formatage doit provisionner complètement (c'est-à-dire associer un bloc physique à chaque bloc logique). Les mêmes disques (SSD) peuvent provisionner finement si cette option n'est pas donnée. Si cette option est donnée, l'option *--security* ne peut pas être donnée. Accepte également *--ip_def* pour cette option.
-l, --long
l'action par défaut de cet utilitaire est de supposer des adresses de bloc logique de 32 bits. Avec une taille de bloc de 512 octets, cela permet plus de 2 téraoctets (presque 2 ** 41 octets) sur un seul disque. Cette option sélectionne des commandes et des paramètres qui permettent des adresses de bloc logique de 64 bits. Spécifiquement, cette option définit le drapeau "longlba" dans la commande MODE SENSE (10) et utilise READ CAPACITY (16) plutôt que READ CAPACITY (10). Si cette option n'est pas donnée et que READ CAPACITY (10) ou MODE SELECT détecte un disque qui a besoin de plus de 32 bits pour représenter ses blocs logiques, alors il est défini en interne. Cette option ne définit pas le bit LONGLIST dans la commande FORMAT UNIT. Le bit LONGLIST est défini si nécessaire en fonction d'autres paramètres (par exemple, lorsque '--pie=PIE' est supérieur à zéro).
-M, --mode=MP
*MP* est un numéro de page de mode (0 à 62 inclus) qui sera utilisé pour lire et éventuellement modifier la taille du bloc logique du périphérique. La valeur par défaut est 1, qui est la page de mode de récupération des erreurs de lecture-écriture.
De préférence, la page de mode choisie (ou par défaut) devrait être sauvegardable (c'est-à-dire accepter le bit SP défini dans la commande MODE SELECT utilisée lors de la modification de la taille du bloc logique). Les versions récentes de cet utilitaire retenteront une commande MODE SELECT si la variante SP=1 échoue avec une clé de détection de REQUÊTE ILLÉGALE. Cette nouvelle tentative utilisera la même commande MODE SELECT mais avec SP=0.
-P, --pfu=PFU
définit le champ "Protection Field Usage" dans le bloc de paramètres associé à une commande FORMAT UNIT à *PFU*. La valeur par défaut est 0, la seule autre valeur définie actuellement est 1. Voir la section INFORMATIONS DE PROTECTION ci-dessous pour plus d'informations.
-q, --pie=PIE
définit le champ "Protection Interval Exponent" dans le bloc de paramètres associé à une commande FORMAT UNIT à *PIE*. La valeur par défaut est 0. *PIE* ne peut être différent de zéro qu'avec les types de protection 2 et 3. La valeur 0 est typique pour les blocs de 512 octets ; avec des blocs de 4096 octets, une valeur de 3 peut être appropriée (c'est-à-dire 8 intervalles de protection entrelacés avec 4096 octets de données utilisateur). Un périphérique peut ne supporter aucune valeur non nulle. Ce champ est apparu pour la première fois dans la révision 18 de SBC-3.
-p, --pinfo
cette option est obsolète, utilisez plutôt l'option *--fmtpinfo=FPI*. Si elle est utilisée, elle définit le bit 7 de l'octet 1 dans le cdb FORMAT UNIT, ce qui équivaut à définir *--fmtpinfo=2*. [Donc, si *--pinfo* est utilisé (plus *--fmtpinfo=FPI* et *--pfu=PFU* ne sont pas donnés ou leurs arguments sont 0), alors le type de protection 1 est sélectionné.]
-x, --poll=PT
où *PT* est le type de sondage utilisé. Si *PT* est 0, une commande TEST UNIT READY est utilisée, sinon une commande REQUEST SENSE est utilisée. La valeur par défaut est actuellement 0, mais cela passera à 1 dans un avenir proche. Voir les sections NOTES ci-dessous.
-E, --preset=ID
cette option demande à cet utilitaire d'émettre une commande SCSI FORMAT WITH PRESET. Le champ PRESET IDENTIFIER dans ce cdb est défini sur *ID*. Le champ IMMED dans ce cdb est également défini, sauf si l'option *--wait* est également donnée, auquel cas il est effacé.
-Q, --quick
l'action par défaut (c'est-à-dire lorsque l'option n'est pas donnée) est de donner à l'utilisateur 15 secondes pour reconsidérer le formatage du *DEVICE*. Lorsque cette option est donnée, cette étape (c'est-à-dire la période d'avertissement de 15 secondes) est sautée.
-r, --resize
au lieu de formater le disque, il peut être redimensionné. Cela signifie modifier le nombre de blocs sur le périphérique signalé par la commande READ CAPACITY. Cette option doit être utilisée avec l'option *--count=COUNT*. Le contenu de tous les blocs logiques sur le support reste inchangé lorsque cette option est utilisée. Cela signifie que toute opération de redimensionnement peut être inversée. Cette option ne peut pas être utilisée conjointement avec *--format* ou une option *--size=LB_SZ* dont l'argument est différent de la taille de bloc existante.
-R, --rto_req
L'option est obsolète, utilisez plutôt l'option *--fmtpinfo=FPI*. Si elle est utilisée, elle définit le bit 6 de l'octet 1 dans le cdb FORMAT UNIT.
-S, --security
définit le bit "Security Initialization" (SI) dans le descripteur de motif d'initialisation de la commande FORMAT UNIT dans la liste de paramètres. Selon SBC-3, le motif d'initialisation par défaut "doit être écrit en utilisant une technique d'effacement sécurisé". Voir la section NOTES sur la commande SCSI SANITIZE. Si cette option est donnée, l'option *--ip_def* ne peut pas être donnée.
-6, --six
Utilise les variantes à 6 octets de MODE SENSE et MODE SELECT. L'action par défaut est d'utiliser les variantes à 10 octets. Certains lecteurs MO ont besoin que cette option soit définie lors d'un formatage.
-s, --size=LB_SZ
où *LB_SZ* est la taille du bloc logique (c'est-à-dire le nombre d'octets utilisateur dans chaque bloc) à laquelle le périphérique doit être formaté. La valeur par défaut est celle actuellement signalée par le descripteur de bloc dans une commande MODE SENSE. Si la taille du bloc donnée par cette option est différente de la valeur actuelle, une commande MODE SELECT est utilisée pour la modifier avant le démarrage de la commande FORMAT UNIT (comme recommandé dans les normes SBC). Certains disques SCSI ont des blocs logiques de 512 octets par défaut et autorisent une taille de bloc logique alternative de 4096 octets. Si la taille donnée est inacceptable pour le disque, un message du type "Champ invalide dans la liste des paramètres" apparaîtra probablement dans les données de détection (nécessite l'utilisation de '-v' pour décoder les données de détection).
Notez que le formatage d'un disque pour ajouter ou supprimer des informations de protection n'est pas considéré comme une modification de sa taille de bloc logique, cette option ne doit donc pas être utilisée.
-T, --tape=FM
enverra une commande FORMAT MEDIUM à DEVICE avec son champ FORMAT défini à FM. Cette option est utilisée pour préparer une bande (c'est-à-dire le "support") dans un lecteur de bande pour utilisation. Les valeurs pour FM incluent 0 pour effectuer le formatage "par défaut"; 1 pour partitionner un volume et 2 pour effectuer un formatage par défaut puis partitionner.
-m, --timeout=SECS
où SECS est le délai d'attente de la commande FORMAT UNIT, FORMAT WITH PRESET ou FORMAT MEDIUM en secondes. SECS ne sera utilisé que s'il dépasse le délai d'attente interne qui est de 20 secondes si le bit IMMED est défini et de 72000 secondes (20 heures) ou plus si le bit IMMED n'est pas défini. Si la taille du disque dépasse 4 To, la valeur du délai d'attente est augmentée à 144000 secondes (40 heures). Et si elle est supérieure à 8 To, la valeur du délai d'attente est augmentée à 288000 secondes (80 heures). Si le délai d'attente est dépassé, le système d'exploitation abandonnera généralement la commande. L'abandon d'une commande peut entraîner une réinitialisation du LUN (ou pire). Un délai d'attente peut également laisser l'opération de formatage du disque ou de la bande incomplète. Et cela peut laisser le disque ou la bande dans un état de "format corrompu", nécessitant un autre formatage pour remédier à la situation. Ainsi, pour diverses raisons, les délais d'attente de commande doivent être évités. Une forme alternative d'option longue est --tmo=SECS.
-v, --verbose
augmente le niveau de verbosité, (c'est-à-dire la sortie de débogage). "-vvv" donne beaucoup plus de sortie de débogage.
-y, --verify
définit le bit VERIFY dans le CDB FORMAT MEDIUM. Par défaut, le bit VERIFY est effacé. Cette option est uniquement appropriée pour les bandes.
-V, --version
affiche la chaîne de version puis quitte.
-w, --wait
l'action de formatage par défaut consiste à définir le bit "IMMED" dans l'en-tête de paramètre (court) de la commande FORMAT UNIT. Si cette option (c'est-à-dire --wait) est donnée, le bit "IMMED" n'est pas défini. Si --wait est donné, la commande FORMAT UNIT, FORMAT WITH PRESET ou FORMAT MEDIUM attend que l'opération de formatage soit terminée avant de retourner sa réponse. Cela peut prendre plusieurs heures sur de grands disques. Voir l'option --timeout=SECS.
Alternativement, cette option peut être utile lorsqu'elle est utilisée avec --ffmt=FFMT (et FFMT supérieur à 0) car le formatage rapide peut n'être qu'une question de secondes.

LISTES

La version préliminaire SBC-3 (révision 20) définit PLIST, CLIST, DLIST et GLIST dans la section 4.10 sur "les défauts du support". Brièvement, PLIST est la liste "primaire" des défauts détectés par le fabricant, CLIST ("liste de certification") contient ceux détectés pendant l'opération de formatage, DLIST est une liste de défauts qui peuvent être donnés à l'opération de formatage. GLIST est la liste croissante qui commence dans le processus de formatage comme CLIST+DLIST et peut "croître" plus tard en raison de la réallocation automatique (voir les bits ARRE et AWRE dans la page de mode de récupération d'erreurs de lecture-écriture (voir sdparm(8))) et de l'utilisation de la commande SCSI REASSIGN BLOCKS (voir sg_reassign(8)).

Selon la norme SBC-3 (suite à la révision 36), CLIST et DLIST ont été supprimés, ne laissant que PLIST et GLIST. Seuls PLIST et GLIST se trouvent dans les versions préliminaires SBC-4.

Le bit CMPLST (contrôlé par l'option --cmplst=0|1) détermine si la GLIST existante, lorsque l'opération de formatage est appelée, est prise en compte. L'utilitaire sg_format définit le bit FOV à zéro, ce qui provoque DPRY=0, de sorte que la PLIST est prise en compte, et DCRT=0, de sorte que la CLIST est générée et utilisée pendant le processus de formatage.

L'utilitaire sg_format ne permet pas à un utilisateur de fournir une liste de défauts (c'est-à-dire DLIST).

INFORMATIONS DE PROTECTION

Les informations de protection (PI) sont des informations supplémentaires conservées avec les blocs logiques afin qu'une application et/ou un adaptateur de bus hôte puisse vérifier l'exactitude de ces blocs logiques. Les PI sont placées dans un ou plusieurs intervalles de protection entrelacés dans chaque bloc logique. Chaque intervalle de protection suit les données utilisateur auxquelles il se réfère. Un intervalle de protection contient 8 octets composés d'un "garde de bloc logique" de 2 octets (CRC), d'un "garde d'application de bloc logique" de 2 octets et d'une "étiquette de référence de bloc logique" de 4 octets. Les périphériques avec une taille de bloc logique de 512 octets ont généralement un intervalle de protection ajouté, rendant leurs données de bloc logique de 520 octets. Les périphériques avec une taille de bloc logique de 4096 octets ont souvent 8 intervalles de protection répartis sur leurs données de bloc logique pour une taille totale de 4160 octets. Notez que pour toutes les autres fins, la taille du bloc logique est considérée comme étant respectivement de 512 et 4096 octets.

La norme SBC-3 a ajouté plusieurs "types de protection" aux PI introduits dans la norme SBC-2. SBC-3 définit 4 types de protection (types 0 à 3), le type de protection 0 signifiant qu'aucune PI n'est maintenue. Bien qu'un périphérique puisse prendre en charge un ou plusieurs types de protection, il ne peut être formaté qu'avec 1 des 4. Pour changer le type de protection d'un périphérique, il doit être reformaté. Pour plus d'informations, voir les Informations de protection dans la section 4.21 de la version préliminaire SBC-4 révision 16.

Un périphérique qui prend en charge les informations PI (c'est-à-dire qui prend en charge un ou plusieurs types de protection 1, 2 et 3) définit le bit "PROTECT" dans sa réponse INQUIRY standard. Il définit également le champ SPT dans la réponse de la page VPD d'INQUIRY ÉTENDUE pour indiquer les types de protection qu'il prend en charge. Étant donné PROTECT=1, SPT=0 implique que le périphérique prend en charge uniquement le type PI 1, SPT=1 implique que le périphérique prend en charge les types PI 1 et 2, et diverses autres correspondances non évidentes jusqu'à SPT=7, ce qui implique que les types de protection 1, 2 et 3 sont pris en charge. Le type de protection actuel d'un disque peut être trouvé dans les champs "P_TYPE" et "PROT_EN" dans la réponse d'une commande READ CAPACITY (16) (par exemple, avec l'utilitaire 'sg_readcap --long').

Étant donné qu'un périphérique prend en charge un type de protection particulier, un utilisateur peut alors choisir de formater ce disque avec ce type de protection en définissant les champs "FMTPINFO" et "Protection Field Usage" dans la commande FORMAT UNIT. Ces champs correspondent aux options --fmtpinfo=FPI et --pfu=PFU de cet utilitaire. La liste ci-dessous montre les quatre types de protection suivis des options de cet utilitaire nécessaires pour les sélectionner :
0 : --fmtpinfo=0 --pfu=0
1 : --fmtpinfo=2 --pfu=0
2 : --fmtpinfo=3 --pfu=0
3 : --fmtpinfo=3 --pfu=1
La valeur par défaut de FPI (dans --fmtpinfo=FPI) est 0 et la valeur par défaut de PFU (dans --pfu=PFU) est 0. Donc, si ni --fmtpinfo=FPI ni --pfu=PFU ne sont donnés, le type de protection 0 (c'est-à-dire aucune information de protection) est choisi.

NOTES

Après un formatage qui modifie la taille du bloc logique ou le nombre de blocs logiques sur un disque, le système d'exploitation peut avoir besoin d'être informé de la réinitialisation de ses paramètres pour ce disque. Sous Linux, cela peut être fait avec :
echo 1 > /sys/block/sd{lettre(s)}/device/rescan
où "lettre(s)" sera entre 'a' et 'zzz'. L'utilitaire lsscsi sous Linux peut être utilisé pour vérifier les différentes désignations d'un disque.

La norme SBC-2 stipule que la commande REQUEST SENSE doit être utilisée pour obtenir des indications de progression lorsque la commande de formatage est en cours. Cependant, des tests sur une sélection de disques montrent que les commandes TEST UNIT READY fournissent des indications de progression (mais pas les commandes REQUEST SENSE). Ainsi, la version actuelle de cet utilitaire utilise par défaut les commandes TEST UNIT READY pour interroger le disque afin de connaître la progression du formatage. L'option --poll=PT a été ajoutée pour contrôler cela.

Lorsque l'option --format, --preset=ID ou --tape=FM est donnée sans l'option --wait, la commande SCSI correspondante est émise avec le bit IMMED défini, ce qui fait que la commande SCSI retourne après avoir démarré l'opération de formatage. L'option --early fera alors quitter sg_format. Sinon, le DEVICE est interrogé toutes les 60 secondes ou toutes les 10 secondes si FFMT est non nul. L'interrogation se fait avec des commandes TEST UNIT READY ou REQUEST SENSE jusqu'à ce que l'une signale "tout est clair" (c'est-à-dire que l'opération de formatage est terminée). Normalement, ces commandes d'interrogation généreront un indicateur de progression (exprimé en pourcentage) affiché à l'écran. Si l'utilisateur se lasse de regarder le rapport de progression, le processus sg_format peut être terminé (par exemple avec Control-C) sans affecter l'opération de formatage qui continue. Cependant, une réinitialisation de la cible ou du périphérique (ou une mise hors tension) provoquera probablement l'arrêt du formatage et le passage du DEVICE à l'état "format corrompu".

Lorsque les options --format (--preset=ID ou --tape) et --wait sont toutes deux données, cet utilitaire peut prendre beaucoup de temps à retourner. Dans ce cas, il faut veiller à ne pas envoyer d'autres commandes SCSI au disque car il pourrait ne pas répondre, laissant ces commandes en file d'attente derrière la commande de formatage active. Cela pourrait entraîner un délai d'attente dans le pilote du système d'exploitation (dans une période beaucoup plus courte que les 20 heures applicables à certaines opérations de formatage). Cela pourrait entraîner la réinitialisation du disque par le système d'exploitation, laissant l'opération de formatage incomplète. Cela pourrait laisser le disque dans un état de "format corrompu", nécessitant un autre formatage pour remédier à la situation. Les périphériques SCSI modernes devraient générer une clé d'état "pas prêt" avec un sens supplémentaire indiquant qu'un formatage est en cours. Avec les périphériques plus anciens, l'utilisateur doit prendre des précautions pour que rien n'accède à un périphérique pendant son formatage. Le démontage des systèmes de fichiers montés sur un DEVICE avant d'appeler cet utilitaire est fortement conseillé.

Lorsque la taille du bloc (c'est-à-dire le nombre d'octets dans chaque bloc) est modifiée sur un disque, deux commandes SCSI doivent être envoyées : une MODE SELECT pour changer la taille du bloc, suivie d'une commande FORMAT. Si la commande MODE SELECT réussit et que la commande FORMAT échoue, le disque peut être dans un état que la norme appelle "format corrompu". Un descripteur de bloc dans une MODE SENSE ultérieure rapportera la nouvelle taille de bloc demandée, tandis qu'une commande READ CAPACITY rapportera la taille de bloc existante (c'est-à-dire la précédente). Alternativement, la commande READ CAPACITY peut échouer, rapportant que le périphérique n'est pas prêt, nécessitant potentiellement un formatage. La solution à cette situation est de refaire un formatage (et cette fois, la nouvelle taille de bloc n'a pas besoin d'être spécifiée) ou de revenir à la taille de bloc d'origine.

La norme SBC-2 stipule que le nombre de blocs peut être rétabli à la valeur recommandée maximale par le fabricant dans une opération de formatage ou de redimensionnement. Cela peut être fait en plaçant une adresse de 0xffffffff (ou son équivalent 64 bits) dans le champ approprié du descripteur de bloc d'une commande MODE SELECT. Je

NOTES ON FORMATTING SCSI DEVICES

This utility formats SCSI devices. It supports the FORMAT UNIT service action for disks and the FORMAT MEDIUM command for tape drives. A format operation can erase all existing data on a device, so care should be taken.

The main options are: --format, --format-start, --erase, --interval, --leap, --locate, --percent, --pillow, --pservice, --resize, --revalidate, --rfc, --rsv, --rwc, --security, --size, --slow, --spinup, --ssz, --t10-pic, --t10-pi, --transport, --verify, --vendor, --pblock, --pinfo, --psatype, --psctype, --psetype, --plist, --pmode, --pserv, --reassign, --retries, --save, --scsi-pt, --sense-len, --split, --tapespeed, --tape, --wait, --wbcardi, --wce, --werr, --wlba, --wp, --xps.

For details on these and other options, and for a full list of related commands, see the sg3_utils(8) man page.

The two main commands are FORMAT UNIT (for disks) and FORMAT MEDIUM (for tapes). They are invoked with the --format and --tape options respectively.

The --format option is a simple way to initiate a format operation on a disk. It sets defaults for various fields in the FORMAT UNIT command's CDB (Command Description block). The --wait option can be used to wait for the format to complete. If --wait is not given, the command exits immediately after issuing the FORMAT UNIT command.

Some disks support a "short stroke" or "resize" operation which allows the user to reduce the capacity of the disk. This is typically done to improve performance. The --resize option is used for this purpose. The --count option specifies the new capacity in blocks. A value of -1 for --count causes the disk to be resized back to its manufacturer's maximum recommended value.

The --security option invokes the security initialization mode of the FORMAT UNIT command. This can be used to erase all data on the disk. The --erase option is a shortcut for this.

The --verbose option (or -v) can be used to see the SCSI commands being sent. -vvv provides even more detail.

The FMTDATA field in the FORMAT UNIT CDB is not directly controlled by an option in this utility. It is set when an additional parameter list is sent to the device.

Short stroking is a technique used to trade capacity for performance on hard disk drives (HDDs). HDDs typically offer better performance on their outer tracks (lower logical block addresses). By reformatting a disk to a smaller capacity, the average performance can be improved.

Other utilities that may be useful include:

  • sg_inq(8): To fetch standard INQUIRY information (e.g., the PROTECT bit) and the EXTENDED INQUIRY VPD page (e.g., RTO and GRD_CHK bits).
  • sdparm(8): To access and modify mode pages, including the now obsolete format mode page.

Another utility for formatting SCSI disks on Linux is scsiformat. It is older and may be useful for disks with older firmware.

The COUNT numeric argument can include multiplicative suffixes (e.g., K, M, G) or be given in hexadecimal. See the "NUMERIC ARGUMENTS" section in the sg3_utils(8) man page.

The SCSI SANITIZE command (introduced in SBC-3 rev 27) is related to the ATA sanitize disk feature set and can be used to erase data. It is more likely to be implemented on modern disks (including SSDs) than the FORMAT UNIT's security initialization feature, and can be much faster.

SSDs that support thin provisioning often unmap all logical blocks during a format to improve endurance. Thin provisioned formats typically complete faster than fully provisioned ones. Formatting SSDs is generally much faster than formatting HDDs.

Host managed zoned devices (PDT=20 or 0x14) have a different Peripheral Device Type than normal disks. They can be formatted like other SCSI disks. They are governed by ZBC standards (INCITS 536-2016 and draft ZBC-2). "Host aware" zoned disk variants use PDT=0 and can be formatted as normal disks.

TAPE

Tape systems use a variant of the FORMAT UNIT command called FORMAT MEDIUM. This command is simpler, with typically only three fields in the CDB. The fields are VERIFY, IMMED, and FORMAT. The --verify option sets the VERIFY bit. The --wait option manipulates the IMMED bit similarly to disks, but defaults to polling every 1 second using REQUEST SENSE commands if --poll=PT is not specified.

The --tape=FM option sets the FORMAT field, which can range from -1 (default, no format) to 15. Values 8-15 are for vendor-specific formats. The --early option sets the IMMED bit and exits immediately, allowing the tape drive to continue formatting in the background. During this time, INQUIRY and REPORT LUNS commands should still respond, while other commands (like REQUEST SENSE) should indicate "not ready, format in progress" and provide progress information.

When FM is 1 or 2, the Medium Partition mode page controls partitioning. This page can be viewed and modified with sdparm(8).

Before invoking this utility, the tape may need to be positioned to the beginning of partition 0 using a utility like mt(mt-st) (e.g., 'mt -f /dev/st0 rewind').

EXAMPLES

These examples use Linux device names. For other operating systems, refer to the sg3_utils(8) man page.

To display the existing block count and size without making changes:


# sg_format /dev/sdm

To perform a simple format, keeping the existing block count and size, in IMMED mode, polling every 60 seconds:


# sg_format --format /dev/sdm

To format and wait passively for completion:


# sg_format --format --wait /dev/sdm

To format with a block size of 520 bytes and set the block count to the manufacturer's maximum (note: not all disks support changing block size):


# sg_format --format --size=520 /dev/sdm

To resize the disk, making only the first 0x10000 (65536) blocks accessible:


# sg_format --resize --count=0x10000 /dev/sdm

To resize the disk back to its normal maximum block count:


# sg_format --resize --count=-1 /dev/sdm

To format a SCSI disk and add protection information (type 1):

First, check supported protection types:


# sg_vpd -p ei -l /dev/sdb
extended INQUIRY data VPD page:
ACTIVATE_MICROCODE=0
SPT=1 [protection types 1 and 2 supported]
....

Then, format with type 1 protection:


# sg_format --format --fmtpinfo=2 /dev/sdm

After a successful format with type 1 protection, READ CAPACITY(16) should show:


# sg_readcap -l /dev/sdm
Read Capacity results:
Protection: prot_en=1, p_type=0, p_i_exponent=0 [type 1 protection]
Logical block provisioning: lbpme=0, lbprz=0
....

To format with type 3 protection (may fail if not supported):


# sg_format --format --fmtpinfo=3 --pfu=1 /dev/sdm

Examples using fast format (FFMT field) to switch between 512 and 4096 byte logical block sizes (assume disk starts with 4096 bytes and data is backed up):

Format to 512 byte logical block size:


# sg_format --format --ffmt=1 --size=512 /dev/sdd

Format back to 4096 byte logical block size:


# sg_format --format --ffmt=1 --size=4096 /dev/sdd

Fast formats can be very quick; using --wait is often appropriate.

To use the Format with Preset command:


# sg_format --preset=1 --fmtmaxlba /dev/sdd

Consult the FORMAT PRESETS VPD page (0xb8) using sg_vpd(8) to verify Preset identifier 0x1 and its format (e.g., "default host aware zoned block device model...").

EXIT STATUS

The exit status is 0 on success. Otherwise, refer to the sg3_utils(8) man page. The exit status may not reflect the success of the format operation if --wait is not used. Use sg_turs(8) and sg_readcap(8) after formatting for verification.

While "no news is good news" is a Unix convention, it can be unnerving after a format. Using --verbose once can provide reassurance.
