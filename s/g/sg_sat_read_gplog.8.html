NOM

sg_sat_read_gplog - utilise la commande ATA READ LOG EXT ou SMART READ LOG via une couche de traduction SCSI vers ATA (SAT)

SYNTAXE

sg_sat_read_gplog [--address=LA_L] [--ck_cond] [--count=CO] [--dma] [--help] [--hex] [--len=LONGUEUR_COMMANDE] [--log=LA_L] [--page=PN] [--ppt=PPT] [--readonly] [--smart] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Cet utilitaire envoie une commande ATA READ LOG EXT, ATA READ LOG DMA EXT, ou ATA SMART READ LOG au PÉRIPHÉRIQUE. Par défaut, il envoie l'une des deux premières commandes pour lire les pages de log "general purpose log". Seuls les périphériques (S)ATA (par exemple, disques) et non les périphériques ATAPI (par exemple, lecteurs DVD) prennent en charge les pages de log générales. Plutôt que d'envoyer la commande READ LOG (DMA) EXT directement au périphérique, elle est envoyée via un transport SCSI qui est supposé contenir une couche de traduction SCSI vers ATA (SATL). La SATL peut se trouver dans un pilote du système d'exploitation, dans le firmware d'un adaptateur hôte (HBA) ou dans un boîtier externe.

Cet utilitaire n'essaie pas actuellement de décoder la réponse du disque ATA, mais affiche la réponse en hexadécimal ASCII regroupée par octets de 8 bits ou par mots de 16 bits. Conformément aux conventions ATA, ces mots sont décodés en little endian (notez que les commandes SCSI utilisent une représentation big endian). L'adresse de log 0, page numéro 0 est la page de log "directory" et elle est décodée si l'option --hex n'est pas donnée. À l'avenir, cet utilitaire pourrait tenter de décoder d'autres pages de log. Peut-être que d'autres utilitaires ATA pourront décoder ces pages de log à partir de la sortie hexadécimale de cet utilitaire.

Récupérer toutes les pages de log semble aussi simple que de lire la page de log répertoire, puis d'accéder aux adresses de log qui ont plus de zéro numéro de page associé. Malheureusement, ce n'est pas si simple. Certaines adresses de log (en particulier 0xe1 "SCT Data transfer") nécessitent qu'une commande SCT soit exécutée avant de récupérer la page de log à cette adresse de log. D'autres adresses de log pourraient être problématiques (par exemple, il a été suggéré que les "Device vendor specific logs" 0xa0:0xdf) donc peut-être qu'elles devraient également être évitées. C'est pourquoi les options --address=LA_L et --log=LA_L sont conçues pour accepter une liste de plages.

La norme SAT-4 (SAT ANSI INCITS 491-201r7 brouillon antérieur : sat4r06.pdf sur www.t10.org) définit trois commandes SCSI "ATA PASS-THROUGH" : une utilisant un "cdb" de 12 octets, une autre utilisant un cdb de 16 octets, et la troisième un cdb de 32 octets. Cet utilitaire utilise par défaut la variante avec cdb de 16 octets.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-a, --address=LA_L
où LA_L est une seule "adresse de log", une plage d'adresses de log, ou une liste de (plages d') adresses de log. Une adresse de log est un nombre compris entre 0 et 255 (0xff) où l'adresse de log 0, numéro de page 0, est un répertoire. Une plage d'adresses de log a la forme "lo:hi" où l'adresse de log "hi" doit être supérieure ou égale à "lo". Une liste d'adresses de log est une liste séparée par des virgules d'adresses de log ou de plages d'adresses de log.
Chaque adresse de log contient jusqu'à 256 (log SMART) ou 65536 (log général) numéros de page, à partir du numéro de page 0. Le nombre de numéros de page disponibles pour chaque adresse de log est énuméré dans la page de log répertoire.
Résumé de la syntaxe de LA_L : lo:hi,lo2:hi2,lo3:hi3 ...
-C, --ck_cond
définit le bit CK_COND dans le cdb SCSI ATA PASS-THROUGH. Le réglage par défaut est effacé (c'est-à-dire 0). Lorsqu'il est défini, la SATL doit renvoyer un tampon de détection contenant un descripteur de résultat ATA, que la commande ATA ait réussi ou échoué. Lorsqu'il est effacé, la SATL ne doit renvoyer un tampon de détection contenant un descripteur de résultat ATA que si la commande ATA a échoué.
-c, --count=CO
le nombre CO est placé dans le champ "count" de la commande ATA READ LOG EXT. Il spécifie le nombre de pages de log de 512 octets à lire à partir de l'adresse de log spécifiée. La page d'adresse donnée commençant au numéro de page donné est lue. Le dernier numéro de page lu sera (PN + CO - 1) s'il existe.
La valeur maximale de CO est 0xffff (65 535) pour les pages de log générales et 0xff (255) pour les logs SMART.
Une erreur est généralement signalée si le --page=PN donné (par défaut 0) plus CO dépasse le nombre indiqué dans le répertoire de log (adresse de log 0) pour l'adresse de log donnée.
Notez que CO ne s'applique qu'à l'adresse de log actuelle ; en d'autres termes, il n'y a pas de retour au début de l'adresse de log suivante.
-d, --dma
utilise la commande ATA READ LOG DMA EXT au lieu de la commande ATA READ LOG EXT. Certains périphériques nécessitent cela pour renvoyer des données de log valides.
-h, --help
affiche le message d'utilisation résumant les options de ligne de commande, puis quitte. Ignore PÉRIPHÉRIQUE s'il est donné.
-H, --hex
lorsqu'il est donné une fois, la réponse est affichée en octets hexadécimaux ASCII. Lorsqu'il est donné deux fois, la réponse est regroupée en mots de 16 bits selon les conventions ATA (c'est-à-dire little endian) ; c'est la sortie par défaut (c'est-à-dire lorsque cette option n'est pas donnée). Lorsqu'il est donné trois fois (c'est-à-dire '-HHH'), la sortie est en hexadécimal, regroupée en mots de 16 bits (sans décalage initial et ASCII final sur chaque ligne), dans un format acceptable pour que 'hdparm --Istdin' puisse le traiter.

Si cette option est invoquée quatre fois (par exemple, '-HHHH'), les pages de log sont affichées sous forme d'octets hexadécimaux, sans adresse initiale au début de chaque ligne. Cela rend l'hexadécimal plus facile à décoder pour les ordinateurs (mais pas pour les humains). Si cette option est invoquée cinq fois, une ligne de commentaire, commençant par un caractère '#', est affichée avant chaque page de log de 512 octets. Le commentaire décrit la page de log suivante.

-l, --len=LONGUEUR_COMMANDE
où LONGUEUR_COMMANDE est la longueur de la commande (cdb) de la commande SCSI ATA PASS-THROUGH utilisée pour tunneler les commandes ATA. Trois valeurs sont autorisées : 12, 16 et 32 (octets). La variante de 12 octets a le plus de restrictions (par exemple, son champ 'count' est un seul octet), mais les anciens systèmes peuvent ne pas autoriser les commandes de 16 ou 32 octets.
-L, --log=LA_L
voir l'option --address=LA_L.
-p, --page=PN
le numéro PN est le numéro de page (dans l'adresse de log) et est placé dans les bits 32:16 du champ "lba" de la commande ATA READ LOG (DMA) EXT. La valeur par défaut placée dans le champ "lba" est 0.
La valeur maximale de PN est 0xffff (65 535) pour les pages de log générales et 0xff (255) pour les logs SMART. Dans ce dernier cas, PN doit être 0 et CO est 255.

Lorsque plusieurs adresses de log sont spécifiées (via l'argument LA_L), cette option est traitée différemment. Avec plusieurs adresses de log et si PN est supérieur à 0, cela agit comme une limite supérieure du nombre de numéros de page qui seront affichés pour chaque adresse de log. Le nombre réel de pages de log de 512 octets affichées dépendra également du nombre de numéros de page indiqués dans le répertoire de log pour l'adresse de log actuelle.

-P, --ppt=PPT
où PPT est le nombre de pages à transférer depuis le PÉRIPHÉRIQUE par invocation de commande ATA READ LOG EXT ou ATA READ LOG DMA EX. La valeur par défaut est 128 (ou 64 kibi-octets), choisie car la plupart des systèmes d'exploitation ont une limite supérieure sur la taille des transferts vers et depuis un périphérique avec une seule commande. Lorsque le nombre de pages de log donné avec l'option --count=CO est important, il peut dépasser ce que le système d'exploitation autorise dans une seule invocation de commande. D'où le besoin de cette option.
-l, --len={32|16|12}
c'est la longueur du cdb SCSI utilisé pour les commandes ATA PASS-THROUGH. L'argument peut être 32, 16 ou 12. La valeur par défaut est 16. Certains transports SCSI ne peuvent pas transmettre de commandes SCSI de plus de 12 octets.
-r, --readonly
ouvre le PÉRIPHÉRIQUE avec le drapeau lecture seule (O_RDONLY dans
Unix). L'action par défaut est d'ouvrir DEVICE avec le drapeau lecture-écriture (O_RDWR sous Unix). Dans certains cas, l'envoi de commandes de gestion d'alimentation aux disques ATA est empêché par les actions du système d'exploitation lors du close() si le DEVICE a été ouvert avec le drapeau lecture-écriture (par exemple, le système d'exploitation pourrait penser qu'il doit écrire quelque chose sur le disque).
-s, --smart
dans le jeu de fonctionnalités ATA SMART, les pages de journal "SMART" sont présentes depuis longtemps et précèdent l'ajout ultérieur des pages de journal "générales". Ainsi, cet utilitaire peut être facilement étendu pour lire les pages de journal "SMART" au lieu des pages de journal générales. C'est exactement ce que fait cette option.
La commande ATA SMART READ LOG n'a pas de champ de numéro de page, toutes les récupérations commencent à partir de la page numéro 0. De plus, le nombre de numéros de page (dans son adresse de journal) est limité à un seul octet (donc 255). La page du répertoire de journal général et la page du répertoire de journal SMART ont le même format (étant donné la restriction d'un seul octet sur le nombre de numéros de page dans chaque adresse de journal SMART).
-v, --verbose
augmente le niveau de verbosité.
-V, --version
affiche la chaîne de version

NOTES

Avant le noyau Linux 2.6.29, le stockage de masse USB limitait les données de détection à 18 octets, ce qui donnait des résultats étranges (tronqués) pour l'option --ck_cond.

Il existe de légères différences dans la gestion lorsqu'une seule adresse de journal est récupérée et lorsqu'un plusieurs pages de journal sont récupérées. Dans le cas d'une seule adresse de journal, l'adresse de journal, le numéro de page et le nombre entrent dans les champs correspondants de la commande ATA READ LOG EXT ou ATA SMART READ LOG. Lorsque plusieurs adresses de journal sont fournies, la page de journal "répertoire" (log_address=0, page_number=0) est d'abord chargée. Ensuite, seules les adresses de journal pour lesquelles le répertoire indique qu'il y a plus de zéro page de journal sont récupérées. Le nombre de pages de journal accédées peut être encore limité par l'option --page=PN si PN est supérieur à zéro.

EXEMPLES

Tout d'abord, voici un exemple évitant les adresses de journal problématiques mentionnées dans la section DESCRIPTION ci-dessus.


sg_sat_read_gplog -a 0:0xb,0xd:0x9f,0xe0,0xe2:255 /dev/sdc

Ce qui précède utilise la forme courte de l'option --address=LA_L avec une liste qui évite les adresses de journal 0xc, 0xa0 à 0xdf et 0xe1. La sortie inclura toutes les adresses de journal, à l'exception de celles exclues, pour lesquelles le répertoire indique qu'il y a plus de 0 page de journal.
L'invocation suivante utilise la commande SMART READ LOG au lieu de la commande READ LOG EXT :


sg_sat_read_gplog --smart -a 0:0xb,0xd:0x9f,0xe0,0xe2:255 /dev/sdc

STATUT DE SORTIE

Le statut de sortie de sg_sat_read_gplog est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
