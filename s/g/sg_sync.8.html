NOM

sg_sync - envoie la commande SCSI SYNCHRONIZE CACHE

SYNTAXE

sg_sync [--16] [--count=COUNT] [--group=GN] [--help] [--immed] [--lba=LBA] [--sync-nv] [--timeout=SECS] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Envoie la commande SYNCHRONIZE CACHE(10) ou SYNCHRONIZE CACHE(16) au PÉRIPHÉRIQUE. Ces commandes sont définies pour les périphériques bloc SCSI (voir SBC-3). En cas de succès, ces commandes garantissent que tous les blocs dont les dernières versions sont conservées en cache sont écrits sur le support (également appelé « synchronisés avec » le support).

Si les arguments LBA et COUNT sont tous deux à zéro (leurs valeurs par défaut), alors tous les blocs du cache sont synchronisés. Si LBA est supérieur à zéro tandis que COUNT est à zéro, alors les blocs du cache dont les adresses vont de LBA jusqu'à la dernière adresse de bloc du périphérique sont synchronisés. Si LBA et COUNT sont tous deux différents de zéro, alors les blocs du cache dont les adresses se situent dans l'intervalle LBA à LBA+COUNT-1 inclus sont synchronisés avec le support.

OPTIONS

Les arguments des options longues sont également obligatoires pour les options courtes.

-S, --16
exécute une commande SYNCHRONIZE CACHE(16). Par défaut, une commande SYNCHRONIZE CACHE(10) est exécutée.
-c, --count=COUNT
où COUNT est le nombre de blocs à synchroniser à partir de LBA inclus. La valeur par défaut est 0. Lorsque 0, tous les blocs du cache à partir de LBA inclus jusqu'au dernier bloc sont synchronisés.
-g, --group=GN
où GN est le numéro de groupe qui peut être compris entre 0 et 63 inclus. La valeur par défaut est 0. Les numéros de groupe sont utilisés pour ségréguer les données collectées au sein du périphérique. Il s'agit d'une nouvelle fonctionnalité dans SBC-2 et peut probablement être ignorée pour le moment.
-h, --help
affiche le message d'utilisation puis quitte.
-i, --immed
définit le bit IMMED dans la commande SYNCHRONIZE CACHE. Cela demande au périphérique, si le format de la commande est acceptable, de renvoyer un statut BON immédiatement plutôt que d'attendre que les blocs dans le cache soient synchronisés avec (c'est-à-dire écrits sur) le support.
-l, --lba=LBA
où LBA est la plus petite adresse de bloc logique dans le cache à synchroniser avec le support. La valeur par défaut est 0.
-s, --sync-nv
synchronise le cache (volatil) avec le cache non volatil. Sans cette option (ou s'il n'y a pas de cache non volatil dans le périphérique), la synchronisation se fait avec le support. Le bit SYNC_NV a été rendu obsolète dans la révision 35d de SBC-3.
-t, --timeout=SECS
où SECS est le nombre de secondes que le système d'exploitation accorde à la commande SYNCHRONIZE CACHE(16) pour se terminer avant d'essayer de l'annuler. L'annulation des commandes (généralement avec la fonction de gestion des tâches « abort task ») doit être évitée. Notez que cette option n'est active qu'avec l'option --16. Le délai d'attente par défaut est de 60 secondes pour SYNCHRONIZE CACHE(10) et SYNCHRONIZE CACHE(16). Notez que les problèmes de délai d'attente peuvent être évités avec l'option --immed.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les informations de débogage).
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Avec la commande SYNCHRONIZE CACHE(16), LBA peut avoir jusqu'à 64 bits de taille et COUNT jusqu'à 32 bits de taille. Avec la commande SYNCHRONIZE CACHE(10), LBA peut avoir jusqu'à 32 bits de taille et COUNT jusqu'à 16 bits de taille.

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section « ARGUMENTS NUMÉRIQUES » de la page de manuel sg3_utils(8).

STATUT DE SORTIE

Le statut de sortie de sg_sync est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
