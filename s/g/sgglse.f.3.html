sous-routine sgglse (integer m, integer n, integer p, real, dimension( lda, * ) a, integer lda, real, dimension( ldb, * ) b, integer ldb, real, dimension( * ) c, real, dimension( * ) d, real, dimension( * ) x, real, dimension( * ) work, integer lwork, integer info)

SGGLSE résout des systèmes surdéterminés ou sous-déterminés pour d'AUTRES matrices

Objectif :

!>
!> SGGLSE résout le problème des moindres carrés linéaires avec contraintes
!> d'égalité (LSE) :
!>
!>         minimiser || c - A*x ||_2   sous contrainte   B*x = d
!>
!> où A est une matrice M par N, B est une matrice P par N, c est un vecteur
!> donné de M éléments, et d est un vecteur donné de P éléments. On suppose
!> que
!> P <= N <= M+P, et
!>
!>          rang(B) = P et  rang( (A) ) = N.
!>                               ( (B) )
!>
!> Ces conditions garantissent que le problème LSE a une solution unique,
!> qui est obtenue en utilisant une factorisation généralisée RQ des
!> matrices (B, A) donnée par
!>
!>    B = (0 R)*Q,   A = Z*T*Q.
!>
!> Les appelants de cette sous-routine doivent noter que les vérifications
!> de singularité/dégénérescence de rang implémentées dans cette sous-routine
!> sont rudimentaires. La sous-routine STRTRS appelée par cette sous-routine
!> ne signale un échec dû à la singularité que si le problème est exactement
!> singulier.
!>
!> Il est concevable que l'un (ou plusieurs) des facteurs impliqués dans la
!> factorisation généralisée RQ de la paire (B, A) soit subnormalement proche
!> de la singularité sans que cette sous-routine ne signale une erreur.
!> Les solutions calculées pour de tels problèmes presque dégénérés en rang
!> peuvent être moins précises en raison d'une perte de précision numérique.
!> 
!>

Paramètres

M 
!>          M est INTEGER
!>          Le nombre de lignes de la matrice A.  M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes des matrices A et B. N >= 0.
!>

P

!>          P est INTEGER
!>          Le nombre de lignes de la matrice B. 0 <= P <= N <= M+P.
!>

A

!>          A est tableau de type REAL, dimension (LDA,N)
!>          En entrée, la matrice M par N, A.
!>          En sortie, les éléments sur et au-dessus de la diagonale du tableau
!>          contiennent la matrice trapézoïdale supérieure T de min(M,N) par N.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,M).
!>

B

!>          B est tableau de type REAL, dimension (LDB,N)
!>          En entrée, la matrice P par N, B.
!>          En sortie, le triangle supérieur du sous-tableau B(1:P,N-P+1:N)
!>          contient la matrice triangulaire supérieure R de P par P.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,P).
!>

C

!>          C est tableau de type REAL, dimension (M)
!>          En entrée, C contient le vecteur second membre pour la partie
!>          moindres carrés du problème LSE.
!>          En sortie, la somme des carrés des résidus pour la solution
!>          est donnée par la somme des carrés des éléments N-P+1 à M
!>          du vecteur C.
!>

D

!>          D est tableau de type REAL, dimension (P)
!>          En entrée, D contient le vecteur second membre pour l'équation
!>          contrainte.
!>          En sortie, D est détruit.
!>

X

!>          X est tableau de type REAL, dimension (N)
!>          En sortie, X est la solution du problème LSE.
!>

WORK

!>          WORK est tableau de type REAL, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la valeur optimale de
!>          LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,M+N+P).
!>          Pour une performance optimale LWORK >= P+min(M,N)+max(M,N)*NB,
!>          où NB est une borne supérieure pour les tailles de blocs optimales
!>          pour SGEQRF, SGERQF, SORMQR et SORMRQ.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ;
!>          la routine calcule uniquement la taille optimale du tableau WORK,
!>          renvoie cette valeur comme première entrée du tableau WORK, et aucun
!>          message d'erreur lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est INTEGER
!>          = 0:  terminaison réussie.
!>          < 0:  si INFO = -i, le i-ème argument avait une valeur illégale.
!>          = 1:  le facteur triangulaire supérieur R associé à B dans la
!>                factorisation généralisée RQ de la paire (B, A) est exactement
!>                singulier, donc rank(B) < P ; la solution des moindres carrés
!>                n'a pas pu être calculée.
!>          = 2:  la partie (N-P) par (N-P) du facteur trapézoïdal supérieur
!>                T associé à A dans la factorisation généralisée RQ
!>                de la paire (B, A) est exactement singulier, donc
!>                rank( (A) ) < N ; la solution des moindres carrés n'a pas
!>                    ( (B) )
!>                pu être calculée.
!>
