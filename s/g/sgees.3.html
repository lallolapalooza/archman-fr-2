SGEES calcule les valeurs propres, la forme de Schur, et optionnellement, la matrice des vecteurs de Schur pour les matrices GE

Documentation de la fonction/sous-programme

sous-programme sgees (caractere jobvs, caractere sort, externe select, entier n, reel, dimension( lda, * ) a, entier lda, entier sdim, reel, dimension( * ) wr, reel, dimension( * ) wi, reel, dimension( ldvs, * ) vs, entier ldvs, reel, dimension( * ) work, entier lwork, logique, dimension( * ) bwork, entier info)

SGEES calcule les valeurs propres, la forme de Schur, et optionnellement, la matrice des vecteurs de Schur pour les matrices GE

Objectif :

!>
!> SGEES calcule pour une matrice réelle non symétrique A de taille N*N,
!> les valeurs propres, la forme de Schur réelle T, et, optionnellement, la matrice des vecteurs de Schur Z. Cela donne la factorisation de Schur A = Z*T*(Z**T).
!>
!> Optionnellement, elle ordonne également les valeurs propres sur la diagonale de la forme de Schur réelle de sorte que les valeurs propres sélectionnées soient en haut à gauche.
!> Les colonnes de tête de Z forment alors une base orthonormée pour le sous-espace invariant correspondant aux valeurs propres sélectionnées.
!>
!> Une matrice est en forme de Schur réelle si elle est quasi-triangulaire supérieure avec des blocs de 1x1 et 2x2. Les blocs de 2x2 seront standardisés sous la forme
!>         [  a  b  ]
!>         [  c  a  ]
!>
!> où b*c < 0. Les valeurs propres d'un tel bloc sont a +- sqrt(bc).
!>

Paramètres

JOBVS 
!>          JOBVS est CHARACTER*1
!>          = 'N': les vecteurs de Schur ne sont pas calculés ;
!>          = 'V': les vecteurs de Schur sont calculés.
!>

SORT

!>          SORT est CHARACTER*1
!>          Spécifie si les valeurs propres doivent être ordonnées ou non
!>          sur la diagonale de la forme de Schur.
!>          = 'N': les valeurs propres ne sont pas ordonnées ;
!>          = 'S': les valeurs propres sont ordonnées (voir SELECT).
!>

SELECT

!>          SELECT est une FONCTION LOGIQUE de deux arguments REELS
!>          SELECT doit être déclarée EXTERNE dans le sous-programme appelant.
!>          Si SORT = 'S', SELECT est utilisée pour sélectionner les valeurs propres à trier
!>          en haut à gauche de la forme de Schur.
!>          Si SORT = 'N', SELECT n'est pas référencée.
!>          Une valeur propre WR(j)+sqrt(-1)*WI(j) est sélectionnée si
!>          SELECT(WR(j),WI(j)) est vraie ; c'est-à-dire si l'une des valeurs propres
!>          d'une paire conjuguée complexe est sélectionnée, alors les deux valeurs propres
!>          complexes sont sélectionnées.
!>          Notez qu'une valeur propre complexe sélectionnée peut ne plus
!>          satisfaire SELECT(WR(j),WI(j)) = .TRUE. après l'ordonnancement, car
!>          l'ordonnancement peut modifier la valeur des valeurs propres
!>          complexes (surtout si la valeur propre est mal conditionnée) ;
!>          dans ce cas, INFO est mis à N+2 (voir INFO ci-dessous).
!>

N

!>          N est ENTIER
!>          L'ordre de la matrice A. N >= 0.
!>

A

!>          A est un tableau REEL, dimension (LDA,N)
!>          En entrée, la matrice A de taille N*N.
!>          En sortie, A a été écrasée par sa forme de Schur réelle T.
!>

LDA

!>          LDA est ENTIER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

SDIM

!>          SDIM est ENTIER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = nombre de valeurs propres (après ordonnancement)
!>                         pour lesquelles SELECT est vraie. (Les paires conjuguées complexes
!>                         pour lesquelles SELECT est vraie pour l'une ou l'autre valeur propre comptent pour 2.)
!>

WR

!>          WR est un tableau REEL, dimension (N)
!>

WI

!>          WI est un tableau REEL, dimension (N)
!>          WR et WI contiennent les parties réelle et imaginaire,
!>          respectivement, des valeurs propres calculées dans le même ordre
!>          où elles apparaissent sur la diagonale de la forme de Schur de sortie T.
!>          Les paires de valeurs propres conjuguées complexes apparaîtront
!>          consecutivement avec la valeur propre ayant la partie imaginaire positive en premier.
!>

VS

!>          VS est un tableau REEL, dimension (LDVS,N)
!>          Si JOBVS = 'V', VS contient la matrice orthogonale Z des vecteurs de Schur.
!>          Si JOBVS = 'N', VS n'est pas référencé.
!>

LDVS

!>          LDVS est ENTIER
!>          La dimension principale du tableau VS. LDVS >= 1 ; si
!>          JOBVS = 'V', LDVS >= N.
!>

WORK

!>          WORK est un tableau REEL, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient le LWORK optimal.
!>

LWORK

!>          LWORK est ENTIER
!>          La dimension du tableau WORK. LWORK >= max(1,3*N).
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule seulement la taille optimale du tableau WORK, renvoie
!>          cette valeur comme première entrée du tableau WORK, et aucun message d'erreur
!>          lié à LWORK n'est émis par XERBLA.
!>

BWORK

!>          BWORK est un tableau LOGIQUE, dimension (N)
!>          Non référencé si SORT = 'N'.
!>

INFO

!>          INFO est ENTIER
!>          = 0: sortie réussie
!>          < 0: si INFO = -i, le i-ème argument avait une valeur illégale.
!>          > 0: si INFO = i, et i est
!>             <= N: l'algorithme QR n'a pas réussi à calculer toutes les
!>                   valeurs propres ; les éléments 1:ILO-1 et i+1:N de WR et WI
!>                   contiennent les valeurs propres qui ont convergé ; si
!>                   JOBVS = 'V', VS contient la matrice qui réduit A
!>                   à sa forme de Schur partiellement convergée.
!>             = N+1: les valeurs propres n'ont pas pu être réordonnées car certaines
!>                   valeurs propres étaient trop proches pour être séparées (le problème
!>                   est très mal conditionné) ;
!>             = N+2: après réordonnancement, des erreurs d'arrondi ont modifié les valeurs de certaines
!>                   valeurs propres complexes de telle sorte que les valeurs propres principales
!>                   de la forme de Schur ne satisfont plus SELECT=.TRUE. Ceci
!>                   pourrait aussi être causé par un sous-dépassement dû à la mise à l'échelle.
!>
