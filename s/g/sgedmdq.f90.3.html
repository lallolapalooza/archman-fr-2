SGEDMDQ calcule la Décomposition en Modes Dynamiques (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    SGEDMDQ calcule la Décomposition en Modes Dynamiques (DMD) pour
!>    une paire de matrices d'instantanés de données, en utilisant une
!>    compression basée sur la factorisation QR des données. Pour les
!>    matrices d'entrée X et Y telles que Y = A*X avec une matrice A
!>    inaccessible, SGEDMDQ calcule un certain nombre de paires de Ritz
!>    de A en utilisant l'extraction standard de Rayleigh-Ritz à partir
!>    d'un sous-espace de range(X) qui est déterminé à l'aide des vecteurs
!>    singuliers gauches principaux de X. Optionnellement, SGEDMDQ renvoie
!>    les résidus des paires de Ritz calculées, les informations nécessaires
!>    à un raffinement des vecteurs de Ritz, ou les vecteurs propres de la
!>    DMD exacte.
!>    Pour plus de détails, voir les références ci-dessous. Pour plus de
!>    détails sur l'implémentation, voir [3].
!>

Références :

!>        and experimental data,
!>        Journal of Fluid Mechanics 656, 28-5, 2010.
!>    [2] Z. Drmac, I. Mezic, R. Mohr : Data driven modal
!>        decompositions : analysis and enhancements,
!>        SIAM J. on Sci. Comp. 40 (4), A2253-A2285, 2018.
!>    [3] Z. Drmac : A LAPACK implementation of the Dynamic
!>        Mode Decomposition I. Rapport technique. AIMDyn Inc.

!>        Brunton, N. Kutz : On Dynamic Mode Decomposition :
!>        Theory and Applications, Journal of Computational
!>        Dynamics 1(2), 391 -421, 2014.
!>

Paramètres

JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 colonnes principales de F sont notées X et les
!>    N-1 colonnes suivantes sont notées Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           non nulles unitaires (dans la norme Euclidienne 2)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il est constaté qu'une i-ème colonne de X est un vecteur
!>           nul et que la i-ème colonne correspondante de Y est non nulle,
!>           alors la i-ème colonne de Y est mise à zéro et un indicateur
!>           d'avertissement est déclenché.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           non nulles unitaires (dans la norme Euclidienne 2)
!>    'N' :: Aucune mise à l'échelle des données.
!>

JOBZ

!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et renvoyés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormale et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur sous-jacent discrétisé sur l'espace
!>           des instantanés de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CHARACTER*1
!>    Détermine si les résidus doivent être calculés.
!>    'R' :: Les résidus des paires propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit légale, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!>

JOBQ

!>    JOBQ (entrée) CHARACTER*1
!>    Spécifie si la matrice orthogonale de la factorisation QR
!>    doit être calculée explicitement et retournée.
!>    'Q' :: La matrice Q de la factorisation QR de la matrice
!>           des snapshots de données est calculée et stockée
!>           dans le tableau F. Voir la description de F.
!>    'N' :: La matrice Q n'est pas calculée explicitement.
!>

JOBT

!>    JOBT (entrée) CHARACTER*1
!>    Spécifie si le facteur triangulaire supérieur de la
!>    factorisation QR doit être retourné.
!>    'R' :: La matrice R de la factorisation QR de la matrice
!>           des snapshots de données F est retournée dans le
!>           tableau Y. Voir la description de Y et Détails
!>           supplémentaires.
!>    'N' :: La matrice R n'est pas retournée.
!>

JOBF

!>    JOBF (entrée) CHARACTER*1
!>    Spécifie si les informations nécessaires au post-traitement
!>    (par exemple, le calcul des vecteurs de Ritz affinés)
!>    doivent être stockées.
!>    'R' :: La matrice nécessaire à l'affinage des vecteurs de
!>           Ritz est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non mis à l'échelle du DMD exact
!>           sont calculés et retournés dans le tableau B. Voir
!>           la description de B.
!>    'N' :: Aucune donnée d'affinage de vecteur propre n'est calculée.
!>    Pour être utile à la sortie, cette option nécessite JOBQ='Q'.
!>

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet de sélectionner l'algorithme SVD de la bibliothèque
!>    LAPACK.
!>    1 :: SGESVD (l'algorithme QR SVD)
!>    2 :: SGESDD (l'algorithme Divide and Conquer ; si suffisamment
!>         d'espace de travail est disponible, c'est l'option la
!>         plus rapide)
!>    3 :: SGESVDQ (le QR SVD préconditionné ; ces deux options et la 4
!>         sont les plus précises)
!>    4 :: SGEJSV (le Jacobi SVD préconditionné ; ces deux options et la 3
!>         sont les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative
!>    dans la précision des petites valeurs singulières est possible si
!>    les snapshots varient en norme de telle sorte que X soit fortement
!>    mal conditionné. Si les valeurs singulières petites (inférieures à
!>    EPS*||X||) sont d'intérêt et JOBS=='N', alors les options (3, 4)
!>    donnent les résultats les plus précis, l'option 4 étant légèrement
!>    meilleure et avec un fondement théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire que les colonnes de X seront normalisées,
!>    alors toutes les méthodes donnent des résultats presque aussi précis.
!>

M

!>    M (entrée) INTEGER, M >= 0
!>    La dimension de l'espace d'états (le nombre de lignes de F)
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de snapshots de données d'une seule trajectoire,
!>    pris à des instants discrets équidistants. C'est le nombre
!>    de colonnes de F.
!>

F

!>    F (entrée/sortie) REAL(KIND=WP) tableau M x N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence de snapshots de données
!>    provenant d'une seule trajectoire, pris à des instants discrets
!>    équidistants. Il est supposé que les normes des colonnes de F
!>    sont dans la plage des nombres flottants normalisés.
!>    < À la sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice/facteur orthogonale
!>    de la factorisation QR de la matrice initiale des snapshots de
!>    données F. Voir la description de JOBQ.
!>    Si JOBQ == 'N', les entrées de F strictement sous la diagonale
!>    principale contiennent, colonne par colonne, les informations sur
!>    les vecteurs de Householder, tels que retournés par SGEQRF. Les
!>    informations restantes pour restaurer la matrice orthogonale de la
!>    factorisation QR initiale sont stockées dans WORK(1:N).
!>    Voir la description de WORK.
!>

LDF

!>    LDF (entrée) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N) x (N-1)
!>    X est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 snapshots principaux dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie, les colonnes principales K de X contiennent les K
!>    premiers vecteurs singuliers gauches du contenu décrit ci-dessus
!>    de X. Pour les élever dans l'espace des vecteurs singuliers
!>    gauches U(:,1:K) des données d'entrée, multiplier par pré-
!>    multiplication avec le facteur Q de la factorisation QR initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= N
!>    La dimension principale du tableau X
!>

Y

!>    Y (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N) x (N-1)
!>    Y est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 snapshots finaux dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire supérieur
!>    MIN(M,N) x N de la factorisation QR de la matrice des snapshots
!>    de données F.
!>

LDY

!>    LDY (entrée) INTEGER, LDY >= N
!>    La dimension principale du tableau Y
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique, c'est-à-dire
!>    comment tronquer les petites valeurs singulières de la matrice
!>    d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite un SVD de haute précision, qui
!>                 peut ne pas être réalisable.
!>    Le rang numérique peut être forcé en utilisant une valeur positive
!>    de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles
!>    calculées est inférieur à NRNK, alors seules ces valeurs non
!>    nulles seront utilisées et la dimension réellement utilisée sera
!>    inférieure à NRNK. Le nombre réel de valeurs singulières non nulles
!>    est retourné dans la variable K. Voir la description de K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour tronquer les petites valeurs singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER, 0 <= K <= N
!>    La dimension de la base SVD/POD pour les N-1 premiers snapshots
!>    de données (colonnes de F) et le nombre de paires de Ritz calculées.
!>    La valeur de K est déterminée selon la règle définie par les paramètres
!>    NRNK et TOL. Voir les descriptions de NRNK et TOL.
!>

REIG

!>    REIG (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    Les K premières entrées (K<=N) de REIG contiennent les parties
!>    réelles des valeurs propres calculées REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Voir les descriptions de K, IMEIG, Z.
!>

IMEIG

!>    IMEIG (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    Les K premières entrées (K<N) de REIG contiennent les parties
!>    imaginaires des valeurs propres calculées REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Les valeurs propres sont déterminées comme suit :
!>    Si IMEIG(i) == 0, alors la valeur propre correspondante est réelle,
!>    LAMBDA(i) = REIG(i).
!>    Si IMEIG(i)>0, alors la paire de valeurs propres complexes conjuguées
!>    correspondante se lit comme suit :
!>    LAMBDA(i)   = REIG(i) + sqrt(-1)*IMAG(i)
!>    LAMBDA(i+1) = REIG(i) - sqrt(-1)*IMAG(i)
!>    C'est-à-dire que les paires de conjugués complexes ont des indices
!>    consécutifs (i,i+1), la partie imaginaire positive étant listée
!>    en premier.
!>    Voir les descriptions de K, REIG, Z.
!>

Z

!>    Z (espace de travail/sortie) REAL(KIND=WP) tableau M x (N-1)
!>    Si JOBZ =='V' alors
!>       Z contient les vecteurs de Ritz réels comme suit :
!>       Si IMEIG(i)=0, alors Z(:,i) est un vecteur propre de la i-ème
!>       valeur de Ritz.
!>       Si IMEIG(i) > 0 (et IMEIG(i+1) < 0) alors [Z(:,i) Z(:,i+1)]
!>       englobent un sous-espace invariant et les valeurs de Ritz
!>       extraites de ce sous-espace sont REIG(i) + sqrt(-1)*IMEIG(i)
!>       et REIG(i) - sqrt(-1)*IMEIG(i).
!>       Les vecteurs propres correspondants sont
!>       Z(:,i) + sqrt(-1)*Z(:,i+1) et
!>       Z(:,i) - sqrt(-1)*Z(:,i+1), respectivement.
!>    Si JOBZ == 'F', alors les descriptions ci-dessus s'appliquent aux
!>    colonnes de Z*V, où les colonnes de V sont les vecteurs propres du
!>    quotient de Rayleigh KxK, et Z est orthonormale. Les colonnes de V
!>    sont structurées de manière similaire :
!>    Si IMEIG(i) == 0 alors Z*V(:,i) est un vecteur propre, et si
!>    IMEIG(i) > 0 alors Z*V(:,i)+sqrt(-1)*Z*V(:,i+1) et
!>                      Z*V(:,i)-sqrt(-1)*Z*V(:,i+1)
!>    sont les vecteurs propres de LAMBDA(i), LAMBDA(i+1).
!>    Voir les descriptions de REIG, IMEIG, X et V.
!>

LDZ

!>    LDZ (entrée) INTEGER, LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    RES(1:K) contient les résidus pour les K paires de Ritz calculées.
!>    Si LAMBDA(i) est réelle, alors
!>       RES(i) = || A * Z(:,i) - LAMBDA(i)*Z(:,i))||_2.
!>    Si [LAMBDA(i), LAMBDA(i+1)] est une paire de conjugués complexes
!>    alors
!>    RES(i)=RES(i+1) = || A * Z(:,i:i+1) - Z(:,i:i+1) *B||_F
!>    où B = [ real(LAMBDA(i)) imag(LAMBDA(i)) ]
!>              [-imag(LAMBDA(i)) real(LAMBDA(i)) ].
!>    Il est vrai que
!>    RES(i)   = || A*ZC(:,i)   - LAMBDA(i)  *ZC(:,i)   ||_2
!>    RES(i+1) = || A*ZC(:,i+1) - LAMBDA(i+1)*ZC(:,i+1) ||_2
!>    où ZC(:,i)   =  Z(:,i) + sqrt(-1)*Z(:,i+1)
!>          ZC(:,i+1) =  Z(:,i) - sqrt(-1)*Z(:,i+1)
!>    Voir la description de Z.
!>

B

!>    B (sortie) REAL(KIND=WP) tableau MIN(M,N) x (N-1).
!>    SI JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs affinés ; voir les
!>    détails supplémentaires dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD exact,
!>    à l'échelle près par l'inverse des valeurs propres.
!>    Dans les deux cas, le contenu de B peut être élevé à la
!>    dimension originale des données d'entrée en multipliant par
!>    pré-multiplication avec le facteur Q de la factorisation QR
!>    initiale. Ici A dénote une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= MIN(M,N)
!>    La dimension principale du tableau B.
!>

V

!>    V (espace de travail/sortie) REAL(KIND=WP) tableau (N-1) x (N-1)
!>    À la sortie, V(1:K,1:K) contient les K vecteurs propres du quotient
!>    de Rayleigh. Les vecteurs propres d'une paire de valeurs propres
!>    complexes conjuguées sont retournés sous forme réelle comme expliqué
!>    dans la description de Z. Les vecteurs de Ritz (retournés dans Z)
!>    sont le produit de X et V ; voir les descriptions de X et Z.
!>
re>

LDV

!>    LDV (entrée) ENTIER, LDV >= N-1
!>    La dimension principale du tableau V.
!>

S

!>    S (sortie) RÉEL(KIND=WP) tableau de taille (N-1)-par-(N-1)
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de Rayleigh matriciel.
!>    Son contenu est écrasé pendant la décomposition en valeurs propres par SGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) ENTIER, LDS >= N-1
!>    La dimension principale du tableau S.
!>

WORK

!>    WORK (espace de travail/sortie) tableau RÉEL(KIND=WP) de taille LWORK-by-1
!>    À la sortie,
!>    WORK(1:MIN(M,N)) contient les facteurs scalaires des réflecteurs élémentaires
!>    tels que retournés par SGEQRF de la matrice d'entrée F de taille M-par-N.
!>    WORK(MIN(M,N)+1:MIN(M,N)+N-1) contient les valeurs singulières de la sous-matrice
!>    d'entrée F(1:M,1:N-1).
!>    Si l'appel à SGEDMDQ est uniquement une requête d'espace de travail, alors
!>    WORK(1) contient la longueur minimale de l'espace de travail et
!>    WORK(2) contient la longueur optimale de l'espace de travail. Par conséquent,
!>    la longueur de WORK est d'au moins 2.
!>    Voir la description de LWORK.
!>

LWORK

!>    LWORK (entrée) ENTIER
!>    La longueur minimale du vecteur d'espace de travail WORK.
!>    LWORK est calculé comme suit :
!>    Soit MLWQR  = N (espace de travail minimal pour SGEQRF[M,N])
!>        MLWDMD = espace de travail minimal pour SGEDMD (voir la
!>                 description de LWORK dans SGEDMD) pour
!>                 les snapshots de dimensions MIN(M,N)-by-(N-1)
!>        MLWMQR = N (espace de travail minimal pour
!>                   SORMQR['L','N',M,N,N])
!>        MLWGQR = N (espace de travail minimal pour SORGQR[M,N,N])
!>    Alors
!>    LWORK = MAX(N+MLWQR, N+MLWDMD)
!>    est mis à jour comme suit :
!>       si   JOBZ == 'V' ou JOBZ == 'F' ALORS
!>            LWORK = MAX( LWORK,MIN(M,N)+N-1 +MLWMQR )
!>       si   JOBQ == 'Q' ALORS
!>            LWORK = MAX( LWORK,MIN(M,N)+N-1+MLWGQR)
!>    Si à l'entrée LWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule uniquement les longueurs minimales
!>    et optimales de l'espace de travail pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!>

IWORK

!>    IWORK (espace de travail/sortie) tableau ENTIER de taille LIWORK-by-1
!>    Espace de travail requis uniquement si WHTSVD est égal à
!>    2, 3 ou 4. (Voir la description de WHTSVD).
