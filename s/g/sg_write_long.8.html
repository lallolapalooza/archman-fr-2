NOM

sg_write_long - envoie la commande SCSI WRITE LONG

SYNTAXE

sg_write_long [--16] [--cor_dis] [--help] [--in=IF] [--lba=LBA] [--pblock] [--verbose] [--version] [--wr_uncor] [--xfer_len=BTL] PÉRIPH

DESCRIPTION

Envoie la commande SCSI WRITE LONG (10 ou 16 octets) au PÉRIPH. Le tampon à écrire sur le PÉRIPH est rempli d'octets 0xff ou lu depuis le fichier IF. Ce tampon inclut les données logiques (par exemple, 512 octets) et les octets ECC.

Cet utilitaire peut être utilisé pour générer une ERREUR MÉDIUM à une adresse de bloc logique spécifique. Cela peut être utile pour tester la gestion des erreurs. Avant un tel test, l'utilitaire sg_dd pourrait être utilisé pour copier le contenu original de l'adresse de bloc logique vers un emplacement sûr. Après le test, l'utilitaire sg_dd pourrait être utilisé pour réécrire le contenu original de l'adresse de bloc logique. Une stratégie alternative serait de lire le contenu "long" de l'adresse de bloc logique avec l'utilitaire sg_read_long avant le test et de le restaurer avec cet utilitaire après le test.

Attention : Si des erreurs récupérables sont injectées (par exemple, un ou seulement quelques bits modifiés de telle sorte que l'ECC puisse corriger les données), il faut être prudent avec les paramètres de la page de mode "récupération d'erreurs de lecture/écriture". Plus précisément, si les bits ARRE (pour les lectures) et/ou AWRE (pour les écritures) sont activés, les erreurs récupérées entraîneront la réaffectation du LBA (et l'ajout de l'ancien emplacement à la liste des défauts générés (PLIST)). Ce n'est pas facilement réversible et utilise (un des N secteurs de spare réservés à cet effet) les N secteurs de spare réservés à cet effet. En cas de doute, il est probablement plus sûr de désactiver les bits ARRE et AWRE. Ces bits peuvent être vérifiés et modifiés avec l'utilitaire sdparm. Par exemple : "sdparm -c AWRE,ARRE /dev/sda" désactivera les bits jusqu'à ce que le disque soit hors tension.

Dans SBC-4 révision 7, toutes les utilisations des commandes SCSI WRITE LONG (10 et 16 octets) ont été rendues obsolètes, sauf dans le cas où le bit WR_UNCOR est activé. Les commandes SCSI READ LONG (10 et 16 octets) ont été rendues obsolètes dans la même révision.

OPTIONS

Les arguments des options longues sont obligatoires, même pour les options courtes.

-S, --16
envoie une commande SCSI WRITE LONG (16) au PÉRIPH. L'action par défaut (en l'absence de cette option) est d'envoyer une commande SCSI WRITE LONG (10).
-c, --cor_dis
active le bit de correction désactivée (c'est-à-dire 'COR_DIS'). Cela inhibe divers autres mécanismes tels que la réaffectation automatique de blocs, la récupération d'erreurs et le déclenchement de diverses conditions d'exception informationnelles. Ce bit est relativement nouveau dans SBC-3.
-h, --help
affiche le message d'utilisation puis quitte.
-i, --in=IF
lit les données (binaires) depuis le fichier nommé IF et les utilise pour la commande SCSI WRITE LONG. Si IF est "-", alors l'entrée standard est lue. Si cette option n'est pas donnée, des octets 0xff sont utilisés comme remplissage.
-l, --lba=LBA
où LBA est l'adresse de bloc logique du secteur à écraser. La valeur par défaut est lba 0, qui est un bloc dangereux à écraser sur un disque en cours d'utilisation. Supposé être en décimal sauf s'il est préfixé par '0x' ou a un suffixe 'h'. Si LBA est plus grand que ce qui peut tenir dans 32 bits, l'option --16 devrait être utilisée.
-p, --pblock
active le bit de bloc physique (c'est-à-dire 'PBLOCK'). Cela indique au PÉRIPH d'utiliser les données fournies (sauf si --wr_uncor est également donné) pour écrire sur le bloc physique spécifié par LBA. L'action par défaut est d'écrire sur le bloc logique correspondant au lba donné. Ce bit est relativement nouveau dans SBC-3.
-v, --verbose
augmente le niveau de verbosité (messages de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wr_uncor
active le bit "write uncorrected" (c'est-à-dire 'WR_UNCOR'). Cela indique au PÉRIPH de marquer le lba donné (ou le bloc physique qui le contient si --pblock est également donné) comme ayant une erreur irrécupérable associée. Note : aucune donnée n'est transférée au PÉRIPH, autre que la commande (c'est-à-dire le cdb). En l'absence de cette option, l'action par défaut consiste à utiliser les données fournies ou les octets 0xff (de longueur --xfer_len=BTL) et à les écrire sur le PÉRIPH. Ce bit est relativement nouveau dans SBC-3.
-x, --xfer_len=BTL
où BTL est la longueur de transfert en octets (par défaut 520). Si la valeur donnée (ou la valeur par défaut) ne correspond pas à la taille du bloc "long" du périphérique, rien n'est écrit sur le PÉRIPH et la valeur xfer_len appropriée peut être déduite de la réponse d'erreur qui est imprimée (sur stderr).

NOTES

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section "ARGUMENTS NUMÉRIQUES" de la page de manuel sg3_utils(8).

La commande SCSI WRITE LONG à 10 octets limite l'adresse de bloc logique à une quantité de 32 bits. Pour des LBA plus grands, utilisez l'option --16 pour la commande SCSI WRITE LONG (16).

EXEMPLES

Cette section décrit la configuration d'un bloc avec des données corrompues, la vérification de la condition d'erreur, puis la restauration du contenu utile dans ce secteur.

Premièrement, si les données d'un secteur sont importantes, enregistrez-les avec l'utilitaire sg_read_long :


sg_read_long --lba=0x1234 --out=0x1234_1.img -x BTL /dev/sda

Cet utilitaire peut devoir être exécuté plusieurs fois pour déterminer la valeur correcte de BTL. Ensuite, utilisez cet utilitaire pour "corrompre" ce secteur. Cela pourrait être fait avec :


sg_write_long --lba=0x1234 -x BTL /dev/sda

Cela écrira un secteur (et les données ECC) composé d'octets 0xff. Certains disques peuvent rejeter cela (au moins un des auteurs le fait). Une autre approche consiste à copier le fichier 0x1234_1.img (vers 0x1234_2.img dans cet exemple) et à modifier certaines valeurs avec un éditeur hexadécimal. Puis écrire l'image modifiée avec :


sg_write_long --lba=0x1234 --in=0x1234_2.img -x BTL /dev/sda

Encore une autre approche consiste à utiliser l'option --wr_uncor, si elle est supportée :


sg_write_long --lba=0x1234 --wr_uncor /dev/sda

Ensuite, nous utilisons l'utilitaire sg_dd pour vérifier que le secteur est corrompu. Voici un exemple :


sg_dd if=/dev/sda blk_sgio=1 skip=0x1234 of=. bs=512 count=1 verbose=4

Notez que l'option "blk_sgio=1" est donnée. Ceci est pour s'assurer que le secteur est lu (et aucun autre) et que l'erreur est entièrement signalée. L'option "blk_sgio=1" amène sg_dd à utiliser l'appel système SG_IO plutôt que le sous-système de blocs.

Enfin, nous devrions restaurer le secteur 0x1234 à un état non corrompu. Un secteur rempli de zéros pourrait être écrit avec :


sg_dd if=/dev/zero of=/dev/sda blk_sgio=1 seek=0x1234 bs=512 count=1

Cela se traduira par un secteur (bloc) avec 512 octets de 0x0 sans ERREUR MÉDIUM, car l'ECC et les données associées seront régénérées et donc bien formées. L'option 'blk_sgio=1' est encore plus importante dans ce cas, car elle peut empêcher le sous-système de blocs d'effectuer une lecture avant écriture (puisque la lecture échouera très probablement). Une autre approche consiste à réécrire le contenu original :


sg_write_long --lba=0x1234 --in=0x1234_1.img -x BTL /dev/sda

STATUT DE SORTIE

Le statut de sortie de sg_write_long est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).

NAME

sg_write_long - write data to a SCSI device's persistent reserve

SYNOPSIS

sg_write_long [OPTIONS] DEVICE

DESCRIPTION

Writes a 64-byte data buffer to the SCSI device's persistent reserve. This command is part of the SCSI commands that deal with the persistent reserve and is used to manage reservations on SCSI devices. The data is typically used for identifying the initiator holding the reservation. If the device does not support persistent reserve, an error will be reported.

OPTIONS

There are no specific options for this command as it's a direct interface to a SCSI command. The device name is the primary argument.

NOTES

This utility is part of the sg3_utils package, which provides tools for interacting with SCSI devices. The persistent reserve mechanism is primarily used in clustered environments to manage access to shared storage devices.

EXAMPLES

To write the default 64-byte data buffer to the persistent reserve of a SCSI device `/dev/sg0`:

sg_write_long /dev/sg0

EXIT STATUS

Returns 0 on success, non-zero on failure.
