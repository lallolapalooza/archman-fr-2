NOM

sg_sat_phy_event - utilise ATA READ LOG EXT via un passage SAT pour récupérer les compteurs d'événements phy SATA

SYNOPIS

sg_sat_phy_event [--ck_cond] [--extend] [--help] [--hex] [--ignore] [--len={16|12}] [--raw] [--reset] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Cet utilitaire envoie une commande ATA READ LOG EXT avec la page de journal ("adresse") définie sur 11h à PÉRIPHÉRIQUE et affiche la réponse. La page de journal 11h est définie dans la norme SATA 2.5 et contient les compteurs d'événements phy. Plutôt que d'envoyer cette commande directement au PÉRIPHÉRIQUE, elle est envoyée via un transport SCSI supposé contenir une couche de traduction SCSI vers ATA (SAT). La couche SAT peut se trouver dans un pilote du système d'exploitation, dans le firmware de l'adaptateur de bus hôte ou dans un boîtier externe.

La norme SAT (SAT ANSI INCITS 431-2007, brouillon précédent : sat-r09.pdf sur www.t10.org) définit deux commandes SCSI "ATA PASS-THROUGH" : une utilisant un "cdb" de 16 octets et l'autre avec un cdb de 12 octets. Cet utilitaire utilise par défaut la variante de cdb de 16 octets. SAT-2 est également une norme : SAT-2 ANSI INCITS 465-2010 et le brouillon précédent est sat2r09.pdf . Le projet SAT-3 a commencé et le brouillon le plus récent est sat3r01.pdf .

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-c, --ck_cond
définit le bit CK_COND dans le cdb SCSI ATA PASS-THROUGH. Le réglage par défaut est effacé (c'est-à-dire 0). Lorsqu'il est défini, la couche SAT doit renvoyer un tampon de détection contenant un descripteur de résultat ATA, indépendamment du succès ou de l'échec de la commande. Lorsqu'il est effacé, la couche SAT ne doit renvoyer un tampon de détection contenant un descripteur de résultat ATA que si la commande a échoué.
-e, --extend
définit le bit EXTEND dans le cdb SCSI ATA PASS-THROUGH. Le réglage par défaut est effacé (c'est-à-dire 0). Lorsqu'il est défini, une commande LBA de 48 bits est envoyée au périphérique. Cette option n'a aucun effet avec --len=12.
-h, --help
affiche le message d'utilisation résumant les options de la ligne de commande puis quitte. Ignore PÉRIPHÉRIQUE s'il est fourni.
-H, --hex
affiche la réponse ATA READ LOG EXT en hexadécimal. L'action par défaut (c'est-à-dire sans aucune option '-H') est d'afficher la réponse en hexadécimal, groupée par mots de 16 bits (c'est-à-dire la préférence de la norme ATA). Lorsqu'elle est donnée une fois, la réponse est affichée en octets hexadécimaux ASCII (c'est-à-dire la préférence de la norme SCSI). Lorsqu'elle est donnée deux fois (c'est-à-dire '-HH'), la sortie est en hexadécimal, groupée par mots de 16 bits, de la même manière que par défaut mais sans en-tête.
-i, --ignore
habituellement, les noms des identifiants des compteurs phy sont décodés. Lorsque cette option est donnée, la valeur numérique de l'identifiant, le drapeau du vendeur, la longueur des données (en octets) et la valeur correspondante sont affichés.
-l, --len={16|12}
c'est la longueur du cdb SCSI utilisée pour les commandes ATA PASS-THROUGH. L'argument peut être 16 ou 12. La valeur par défaut est 16. La taille de cdb plus grande est nécessaire pour l'adressage LBA 48 bits des périphériques ATA. D'autre part, certains transports SCSI ne peuvent pas véhiculer des commandes SCSI plus longues que 12 octets.
-r, --raw
affiche la réponse ATA READ LOG EXT en binaire. La sortie doit être redirigée vers un fichier ou un autre utilitaire lorsque cette option est utilisée. La sortie binaire est envoyée à stdout, et les erreurs sont envoyées à stderr.
-R, --reset
réinitialise les compteurs après que les valeurs actuelles ont été retournées, décodées et affichées.
-v, --verbose
augmente le niveau de verbosité.
-V, --version
affiche la chaîne de version

NOTES

La commande ATA PASS-THROUGH (12) SCSI a l'opcode 0xa1 et entre en conflit avec la commande BLANK du jeu MMC utilisée par les graveurs de CD/DVD. Ainsi, une couche SAT devant un périphérique ATAPI qui utilise MMC (c'est-à-dire qui a le type de périphérique 5) devrait probablement traiter l'opcode 0xa1 comme une commande BLANK et la transmettre au lecteur CD/DVD. La commande ATA PASS-THROUGH (16) a l'opcode (0x85) qui n'entre pas en conflit avec quoi que ce soit, c'est donc un meilleur choix.

Dans la série 2.4 des noyaux Linux, le PÉRIPHÉRIQUE doit être un périphérique générique SCSI (sg). Dans la série 2.6, les périphériques de bloc (par exemple, disques durs et lecteurs DVD ATAPI) peuvent également être spécifiés. Par exemple, "sg_inq /dev/sda" fonctionnera dans les noyaux de la série 2.6. À partir de lk 2.6.6, d'autres noms de périphériques "char" SCSI peuvent également être utilisés (par exemple, "/dev/st0m"). Avant lk 2.6.29, le stockage de masse USB limitait les données de détection à 18 octets, ce qui entraînait des résultats étranges (tronqués) pour l'option --ck_cond.

CODE DE SORTIE

Le code de sortie de sg_sat_identify est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).
