NOM

sg_inq - émettre une commande SCSI INQUIRY et/ou décoder sa réponse

SYNTAXE

sg_inq [--ata] [--block=0|1] [--cmddt] [--descriptors] [--export] [--extended] [--force] [--help] [--hex] [--id] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--len=LEN] [--long] [--maxlen=LEN] [--only] [--page=PG] [--quiet] [--raw] [--sinq_inraw=RFN] [--vendor] [--verbose] [--version] [--vpd] PÉRIPHÉRIQUE

sg_inq [-36] [-a] [-A] [-b] [--B=0|1] [-c] [-cl] [-d] [-e] [-f] [-h] [-H] [-i] [-I=FN] [-j[=JO]] [-l=LEN] [-L] [-m] [-M] [-o] [-p=VPD_PG] [-P] [-q] [-r] [-s] [-u] [-v] [-V] [-x] [-36] [-?] PÉRIPHÉRIQUE

DESCRIPTION

Cet utilitaire, lorsqu'on lui donne un PÉRIPHÉRIQUE, lui envoie une commande SCSI INQUIRY puis affiche la réponse. Tous les périphériques SCSI sont censés répondre à une commande INQUIRY "standard" avec au moins une réponse de 36 octets (en SCSI 2 et supérieur). Une commande INQUIRY est dite "standard" lorsque les bits EVPD et CmdDt (maintenant obsolète) sont tous deux effacés. Formellement (c'est-à-dire selon les normes SPC), le nom d'une réponse INQUIRY standard est le "format de données standard INQUIRY" mais ici la "réponse standard INQUIRY" est utilisée car elle est plus courte et plus descriptive.

Alternativement, l'option --inhex=FN peut être donnée. Dans ce cas, FN est supposé être un nom de fichier ('-' pour stdin) contenant des hexadécimaux ASCII représentant une réponse INQUIRY.

Cet utilitaire supporte deux syntaxes de ligne de commande. La plus préférée est montrée en premier dans la syntaxe et est décrite dans la section OPTIONS principales. Une section ultérieure intitulée OPTIONS DE LIGNE DE COMMANDE PLUS ANCIENNES décrit le second groupe d'options.

Une page INQUIRY "non standard" importante est la page de données de produit vital (VPD) d'identification du périphérique [0x83]. Depuis SPC-3, le support de cette page est obligatoire. L'option --id décode cette page. Les nouvelles informations sur les pages VPD ne sont plus ajoutées à cet utilitaire. L'utilitaire sg_vpd(8) est spécialisé dans le décodage des pages VPD et partage du code avec cet utilitaire à cette fin. L'utilitaire sdparm(8) qui se trouve dans un paquet du même nom décode également les pages VPD bien que son objectif principal soit d'accéder et de modifier les pages de mode SCSI.

Sous Linux, si le PÉRIPHÉRIQUE existe et que la commande SCSI INQUIRY échoue (par exemple parce que l'ioctl SG_IO n'est pas supporté) alors une commande ATA IDENTIFY (PACKET) DEVICE est tentée. Si elle réussit, des chaînes d'identification du périphérique sont affichées. Les options --raw et --hex peuvent être utilisées pour manipuler la sortie. Si l'option --ata est donnée, la commande SCSI INQUIRY n'est pas effectuée et le PÉRIPHÉRIQUE est supposé être ATA (ou ATAPI). Pour plus d'informations, voir la section PÉRIPHÉRIQUES ATA ci-dessous.

Dans certains systèmes d'exploitation, un périphérique NVMe (par exemple un SSD) peut être donné comme PÉRIPHÉRIQUE. Pour plus d'informations, voir la section PÉRIPHÉRIQUES NVME ci-dessous.

Le document de référence utilisé pour interpréter une commande INQUIRY est T10/BSR INCITS 566 Revision 6, qui est une ébauche de SPC-6 datée du 22 octobre 2021. Il peut être trouvé à https://www.t10.org . Les éléments obsolètes et réservés dans la sortie de la réponse standard INQUIRY sont affichés entre crochets.

OPTIONS

Les arguments des options longues sont obligatoires, de même que pour les options courtes. Les options sont classées par ordre alphabétique basé sur le nom de l'option longue.

-a, --ata
Suppose que le PÉRIPHÉRIQUE donné est un périphérique ATA ou ATAPI qui peut recevoir des commandes ATA du système d'exploitation hôte. Ignore la commande SCSI INQUIRY et utilise soit la commande ATA IDENTIFY DEVICE (pour les périphériques non-paquet) soit la commande ATA IDENTIFY PACKET DEVICE. Pour afficher la réponse en hexadécimal, ajoutez une option '--verbose'. Cette option n'est disponible que sous Linux.
-B, --block=0|1
cette option contrôle la manière dont le descripteur de fichier du PÉRIPHÉRIQUE est ouvert. Si cet argument est 0, l'ouverture est non bloquante. Sous Unix, une ouverture non bloquante est indiquée par un drapeau O_NONBLOCK tandis qu'une ouverture bloquante est indiquée par l'absence de ce drapeau. La valeur par défaut dépend du système d'exploitation et du type de nœud PÉRIPHÉRIQUE. Pour les pass-through Linux (c'est-à-dire les pilotes sg et bsg), la valeur par défaut est 0.
-c, --cmddt
définit le bit Command Support Data (CmdDt) (par défaut effacé(0)). Utilisé en conjonction avec l'option --page=PG où PG spécifie l'opcode de la commande SCSI à interroger. Lorsqu'il est utilisé deux fois (par exemple '-cc'), cet utilitaire forme une liste en bouclant sur tous les opcodes (0 à 255 inclus) n'affichant une ligne que pour les commandes qui sont trouvées. Le bit CmdDt est maintenant obsolète ; il a été remplacé par la commande REPORT SUPPORTED OPERATION CODES, voir l'utilitaire sg_opcodes(8).
-d, --descriptors
décode et affiche les descripteurs de version trouvés dans une réponse standard INQUIRY. Il y en a jusqu'à 8. Les descripteurs de version indiquent à quelles versions de normes et/ou d'ébauches le PÉRIPHÉRIQUE est conforme. Les composants normaux d'une commande INQUIRY standard sont affichés (typiquement à partir des 36 premiers octets de la réponse) suivis des descripteurs de version s'il y en a.
-e
voir l'entrée ci-dessous pour --vpd.
-f, --force
À titre de vérification de sécurité, l'action normale lors de la récupération des pages VPD autres que la page 0x0 (la page VPD "Supported VPD pages") est de récupérer d'abord la page 0x0 et seulement si la page demandée est l'une des pages supportées, de procéder à la récupération de la page demandée.
Lorsque cette option est donnée, sautez la vérification de la page VPD 0x0 avant d'accéder à la page VPD demandée. La vérification préalable de la page VPD 0x0 est connue pour planter certains périphériques USB, utilisez donc avec précaution.
-u, --export
affiche les informations obtenues du périphérique. La sortie peut être modifiée en sélectionnant une page VPD avec PG (depuis --page=PG). Si la page VPD d'identification du périphérique 0x83 est donnée, elle affiche les informations sous la forme : "SCSI_IDENT_<assoc>_<type>=<ident>" sur stdout. Si la page VPD du numéro de série du périphérique 0x80 est donnée, elle affiche les informations sous la forme : "SCSI_SERIAL=<ident>". Les autres pages VPD ne sont pas supportées. Si aucune page VPD n'est donnée, elle affiche les informations sous la forme : "SCSI_VENDOR=<vendor>", "SCSI_MODEL=<model>", et "SCSI_REVISION=<rev>", extraites de la requête standard. Ceci peut être utile pour des outils comme udev(7) sous Linux.
-E, -x, --extended
affiche la page VPD étendue INQUIRY [0x86]. Elle a le même effet que de donner l'option --page=ei.
-h, --help
affiche le message d'utilisation puis quitte. Lorsqu'il est utilisé deux fois, après le message d'utilisation, il y a une liste d'abréviations disponibles qui peuvent être données à l'option --page=PG.
-H, --hex
plutôt que de décoder une réponse standard INQUIRY, une page VPD ou des données de support de commande ; affiche la réponse en hexadécimal et envoie la sortie vers stdout. Les messages d'erreur et les avertissements sont généralement envoyés vers stderr. Lorsqu'il est utilisé deux fois avec la page VPD ATA Information [0x89], décode le début de la réponse puis affiche la réponse ATA IDENTIFY (PACKET) DEVICE en octets hexadécimaux (pas en mots de 16 bits). Lorsqu'il est utilisé trois fois avec la page VPD ATA Information [0x89] ou l'option --ata, cet utilitaire affiche la réponse ATA IDENTIFY (PACKET) DEVICE en mots hexadécimaux appropriés pour l'entrée de 'hdparm --Istdin'. Voir la note ci-dessous.
Pour générer une sortie appropriée pour être placée dans un fichier qui peut être utilisé par une invocation ultérieure avec l'option --inhex=FN, utilisez l'option '-HHHH' (par exemple 'sg_inq -p di -HHHH /dev/sg3 > dev_id.hex').
-i, --id
affiche la page VPD d'identification du périphérique [0x83]. Elle a le même effet que de donner l'option --page=di.
-I,

Arch manual pages | Hosted by Arch Linux

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

-i=FN, --inhex=FN

FN est censé être un nom de fichier (ou '-' pour stdin) qui contient des données hexadécimales ASCII ou binaires représentant une réponse INQUIRY (y compris une page VPD). Cet utilitaire décodera cette réponse. Il est préférable de fournir également l'option --page=PG, sinon cet utilitaire tentera de deviner à quelle page VPD (ou INQUIRY standard) la réponse est associée. Les données hexadécimales doivent être organisées en 1 ou 2 chiffres représentant chaque octet, séparés par des espaces blancs ou des virgules. Tout à partir d'un signe dièse (#) jusqu'à la fin de la ligne est ignoré. Si l'option --raw est également donnée, alors FN est traité comme binaire.

-j[=JO], --json[=JO]

La sortie est au format JSON au lieu du texte brut. Notez que les arguments des formes courte et longue sont facultatifs et, s'ils sont présents, commencent par "=" sans espace autour de ce "=".
Voir la page de manuel sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.

-J, --js-file=JFN

La sortie est au format JSON et est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non par défaut.

-l, --len=LEN

Le nombre LEN est le champ "allocation length" (longueur d'allocation) dans le CDB INQUIRY. C'est la longueur (maximale) de la réponse renvoyée par le périphérique. La valeur par défaut de LEN est 0, ce qui est interprété comme suit : la première requête porte sur 36 octets et, si nécessaire, une autre commande INQUIRY est exécutée si le champ "additional length" (longueur supplémentaire) dans la réponse indique que plus de 36 octets sont disponibles.
Si LEN est supérieur à 0, une seule commande INQUIRY est exécutée. Cela signifie que le numéro de série (obtenu à partir de la page VPD "Serial Number" (0x80)) n'est pas récupéré et donc pas affiché. Voir la section NOTES ci-dessous concernant les "INQUIRY de 36 octets".

-L, --long

Cette option provoque le décodage de plus d'informations à partir de la commande Identify envoyée à un DEVICE NVMe.

-m, --maxlen=LEN

Cette option a la même action que l'option --len=LEN ci-dessus. Elle a été ajoutée pour la compatibilité avec les utilitaires sg_vpd, sg_modes et sg_logs.

-O, --old

Basculer vers le style d'options plus ancien. Veuillez utiliser comme première option sur la ligne de commande.

-o, --only

N'essayez pas de récupérer en plus la page VPD du numéro de série (0x80) pour améliorer la sortie d'une INQUIRY standard. Ainsi, avec cette option activée et aucune autre, cet utilitaire enverra une commande SCSI INQUIRY standard et décodera sa réponse. Aucune autre commande SCSI ne sera envoyée au DEVICE. Sans cette option, une commande SCSI supplémentaire est envoyée : une commande INQUIRY SCSI (non standard) pour récupérer la page VPD du numéro de série. Cependant, la page VPD du numéro de série n'est pas obligatoire (alors que la page d'identification du périphérique est obligatoire mais un milliard de clés USB l'ignorent) et peut provoquer des rapports d'erreurs gênants. Dans la plupart des cas, si l'option --maxlen=LEN est donnée et que LEN est supérieur à 0, cette option n'est pas nécessaire.
Pour les périphériques NVMe, seule la commande Identify controller est exécutée, même si le DEVICE inclut un identifiant de namespace. Par exemple, sous FreeBSD, pour un DEVICE nommé /dev/nvme0ns1, une commande Identify controller est envoyée à /dev/nvme0 et rien n'est envoyé à son "ns1" (premier namespace).

-p, --page=PG

L'argument PG peut être un nombre ou une abréviation pour une page VPD. Pour énumérer les abréviations disponibles pour les pages VPD, utilisez '-hh' ou une abréviation incorrecte (par exemple, '--page=xxx'). Lorsque l'option --cmddt est donnée (une fois), PG est interprété comme un numéro d'opcode (donc les abréviations de page VPD ont peu de sens).
Si PG est un nombre négatif, une INQUIRY standard est effectuée. Cela peut être utilisé pour outrepasser une partie de la logique de devinage associée à l'option --inhex=FN.
Si PG n'est pas trouvé dans la page VPD "Supported VPD pages" (0x0), alors EDOM est renvoyé. Pour contourner cette vérification, utilisez l'option --force.

-q, --quiet

Supprime la quantité de décodage et de sortie d'erreur.

-r, --raw

En l'absence de --inhex=FN, la réponse de sortie est en binaire. La sortie doit être redirigée vers un fichier ou un autre utilitaire lorsque cette option est utilisée. Les données binaires sont envoyées à stdout, et les erreurs à stderr.
Si utilisé avec --inhex=FN, le contenu de FN est traité comme binaire.

-Q, --sinq_inraw=RFN

Où RFN est un nom de fichier contenant des données de réponse INQUIRY standard binaires qui correspondent soit au DEVICE, soit à FN. Linux place cette réponse INQUIRY standard dans son système de fichiers pseudo sysfs. Un emplacement typique est /sys/class/scsi_device/<hctl>/device/inquiry où <hctl> est un tuple numérique à quatre parties séparé par des deux-points. Ce tuple distingue le périphérique de tous les autres sur le système. Linux place également certaines réponses de page VPD en binaire dans le même répertoire avec des noms tels que "vpd_pg83", où les deux derniers chiffres forment le numéro de page VPD hexadécimal dont le contenu binaire s'y trouve.
Certaines pages VPD (par exemple, la page Extended Inquiry VPD) dépendent de la connaissance des paramètres de la réponse INQUIRY standard pour interpréter les champs de cette page VPD. Cette option, combinée avec --all, --examine ou --page=PG, permet à cet utilitaire de traiter à la fois la réponse INQUIRY standard et les pages VPD dans la même invocation.
L'option --raw n'a aucun effet sur cette option. L'argument DEVICE peut être fourni avec cette option.

-s, --vendor

Affiche les champs spécifiques au vendeur de la réponse INQUIRY standard, de l'offset 36 à 55 en ASCII. Lorsqu'elle est utilisée deux fois (par exemple, '-ss'), affiche également le champ spécifique au vendeur à partir de l'offset 96 en ASCII. Ceci n'est fait que si les données passent quelques vérifications de cohérence simples.

-v, --verbose

Augmente le niveau de verbosité. Peut être utilisé plusieurs fois.

-V, --version

Affiche la chaîne de version puis quitte.

-e, --vpd

Définit le bit Enable Vital Product Data (EVPD) (par défaut à effacé(0)). Utilisé en conjonction avec l'option --page=PG où PG spécifie le numéro de page VPD à interroger. Si l'option --page=PG n'est pas donnée, PG prend par défaut la valeur zéro, qui est la page VPD "Supported VPD pages".

NOTES

Certains périphériques avec des implémentations de jeux de commandes SCSI faibles se bloquent lorsqu'ils reçoivent des commandes qu'ils ne comprennent pas (et certains se bloquent s'ils reçoivent des longueurs de réponse inattendues). Ces périphériques doivent être traités avec soin, utilisez l'option '--len=36'. Sans cette option, cet utilitaire émettra une commande INQUIRY standard initiale demandant 36 octets de données de réponse. Si le périphérique indique qu'il aurait pu fournir plus de données, une deuxième commande INQUIRY est émise pour récupérer la réponse plus longue. Cette deuxième commande peut bloquer les périphériques défectueux.

Les périphériques ATA ou ATAPI qui utilisent une couche de traduction SCSI vers ATA (voir SAT sur www.t10.org ) peuvent prendre en charge la page VPD ATA INFORMATION. Celle-ci renvoie la réponse IDENTIFY (PACKET) DEVICE entre autres choses. La page VPD ATA Information peut être récupérée avec '--page=ai'.

Dans la réponse standard INQUIRY, il y a un indicateur "MultiP" qui est défini lorsque le périphérique a 2 ports ou plus. Certains fabricants utilisent le bit "vendor specific" (VS) précédent pour indiquer quel port est accédé par la commande INQUIRY (0 -> port relatif 1 (port "a"), 1 -> port relatif 2 (port "b")). Lorsque l'indicateur "MultiP" est défini, le bit spécifique au vendeur précédent est affiché entre parenthèses. Les périphériques conformes SPC-3 doivent utiliser la page VPD d'identification du périphérique (0x83) pour indiquer quel port est utilisé pour l'accès et la page VPD des ports SCSI (0x88) pour montrer tous les ports disponibles sur le périphérique.

Dans la série 2.4 des noyaux Linux, le DEVICE doit être un périphérique SCSI générique (sg). Dans la série 2.6 et ultérieures, les périphériques de bloc (par exemple, disques et lecteurs DVD ATAPI) peuvent également être spécifiés. Par exemple, "sg_inq /dev/sda" fonctionnera dans les noyaux de la série 2.6. À partir de lk 2.6.6, d'autres noms de périphériques "char" SCSI peuvent également être utilisés (par exemple, "/dev/st0m").

Le nombre d'octets affiché par --hex et --raw est de 36 octets ou le nombre donné à --len=LEN (ou --maxlen=LEN). Ce nombre est réduit si le "resid" renvoyé par le HBA indique moins d'octets ont été renvoyés par le DEVICE.

Le DEVICE est ouvert avec un indicateur de lecture seule (par exemple, sous Unix avec l'indicateur O_RDONLY).

PÉRIPHÉRIQUES ATA

Il existe deux types principaux de périphériques ATA : les périphériques non-paquets (par exemple, disques ATA) et les périphériques paquets (ATAPI). La majorité des périphériques ATAPI sont des lecteurs CD/DVD/BD dans lesquels le transport ATAPI transporte le jeu de commandes MMC (c'est-à-dire un jeu de commandes SCSI). De plus, les deux types de périphériques ATA peuvent être connectés à un ordinateur hôte via un transport "SCSI" (ou autre). Lorsqu'un disque ATA est contrôlé via un transport SCSI (ou non-ATA), deux approches sont couramment utilisées : le tunneling (par exemple, STP dans Serial Attached SCSI (SAS)) ou en émulant un périphérique SCSI (par exemple, avec une couche de traduction SCSI vers ATA, voir SAT sur www.t10.org ). Même lorsque le transport physique vers l'ordinateur hôte est ATA (surtout dans le cas du SATA), le système d'exploitation peut choisir de placer une couche SAT dans la "pile" du pilote (par exemple, libata sous Linux).

La commande d'identification principale pour tout périphérique SCSI est une INQUIRY. La commande correspondante pour un périphérique ATA non-paquet est IDENTIFY DEVICE, tandis que pour un périphérique ATA paquet, c'est IDENTIFY PACKET DEVICE.

Lorsque cet utilitaire est invoqué pour un périphérique ATAPI (par exemple, un lecteur CD/DVD/BD avec "sg_inq /dev/hdc"), une commande SCSI INQUIRY est envoyée au périphérique et s'il répond, la réponse est décodée et affichée, et cet utilitaire se termine. Pour voir la réponse à une commande ATA IDENTIFY PACKET DEVICE

COMMANDES ATA

L'option --ata a été ajoutée (par exemple, « sg_inq --ata /dev/hdc »).

Cet utilitaire ne décode pas la réponse à une commande ATA IDENTIFY (PACKET) DEVICE ; hdparm fait un bon travail pour cela. L'option '-HHH' a été ajoutée pour être utilisée avec l'option '--ata' ou '--page=ai' afin de produire un format acceptable pour « hdparm --Istdin ». Un exemple : « sg_inq --ata -HHH /dev/hdc | hdparm --Istdin ». Voir hdparm.

APPAREILS NVME

Actuellement, ces appareils sont généralement des SSD (Solid State Disks) connectés directement à un connecteur PCIe ou via un connecteur spécialisé tel qu'un connecteur M2. Linux et FreeBSD traitent les périphériques de stockage NVMe séparément du stockage SCSI, avec des noms de périphériques tels que /dev/nvme0n1 (sous Linux) et /dev/nvme0ns1 (sous FreeBSD). Le groupe NVM Express a un document intitulé « NVM Express: SCSI Translation Reference » qui définit une « couche de traduction SCSI vers NVMe » partielle, souvent connue sous son acronyme : SNTL.

Sur les systèmes d'exploitation où il est pris en charge par ce package, cet utilitaire détectera les périphériques de stockage NVMe connectés directement et enverra une commande NVMe Admin « Identify controller » et décodera sa réponse. Un contrôleur NVMe est architecturalement similaire à un périphérique cible SCSI. Si le périphérique NVMe indique un espace de noms, une commande NVMe Admin « Identify namespace » est envoyée à cet espace de noms et sa réponse est décodée. Les espaces de noms sont numérotés séquentiellement à partir de 1. Les espaces de noms sont similaires aux unités logiques SCSI et leurs identifiants (nsid_s) peuvent être considérés comme des LUN SCSI. Dans les noms de périphériques Linux et FreeBSD ci-dessus, les parties « n1 » et « ns1 » indiquent nsid 1. Si aucun espace de noms n'est donné dans le DEVICE, alors toutes les espaces de noms trouvées dans le contrôleur reçoivent des commandes « Identify namespace » et les réponses sont décodées.

Pour obtenir plus de détails dans la réponse, utilisez l'option --long. Pour obtenir uniquement le décodage de l'identifiant du contrôleur, utilisez l'option --only.

Il est possible que même si le DEVICE se présente comme un périphérique NVMe, il dispose d'un SNTL et accepte les commandes SCSI. Dans ce cas, pour envoyer une commande SCSI INQUIRY (et récupérer ses pages VPD), utilisez l'utilitaire sg_vpd(8).

SG_INQ et SG_VPD

Ces deux utilitaires ont beaucoup en commun puisque les pages VPD sont récupérées avec la commande SCSI INQUIRY. Au fur et à mesure que de nouvelles pages VPD ont été ajoutées (et que les pages existantes ont été étendues), les plus récentes n'ont été décodées qu'avec sg_vpd. Récemment, avec le travail optionnel sur la sortie JSON, il a été décidé de placer tout le décodage des pages VPD dans un fichier source appelé sg_vpd_common.c qui est lié par sg_inq et sg_vpd.

Cela signifie que les capacités de décodage des pages VPD de sg_inq et sg_vpd seront identiques. Leurs actions par défaut restent les mêmes, à savoir que lorsque sg_inq est utilisé sans options de ligne de commande, il décode la réponse « format de données d'enquête standard » (généralement appelée « réponse d'enquête standard »), tandis que lorsque sg_vpd est utilisé sans options, il décode la page VPD « Supported VPD pages ».

STATUT DE SORTIE

Le statut de sortie de sg_inq est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE PLUS ANCIENNES

Les options de cette section étaient les seules disponibles avant la version 1.23 de sg3_utils. Depuis lors, cet utilitaire utilise par défaut les options de ligne de commande plus récentes, qui peuvent être remplacées en utilisant --old (ou -O) comme première option. Voir la section VARIABLES D'ENVIRONNEMENT pour une autre façon de forcer l'utilisation de ces anciennes options de ligne de commande.

-36
demande uniquement 36 octets de données de réponse pour une INQUIRY. De plus, même si le périphérique indique dans sa réponse qu'il peut fournir plus de données, une deuxième INQUIRY (plus longue) n'est pas effectuée. C'est un paramètre de précaution. Équivalent à « --len=36 » dans la section OPTIONS.
-a
récupère la page VPD ATA Information [0x89]. Équivalent à « --page=ai » dans la section OPTIONS. Cette page est définie dans SAT (voir www.t10.org).
-A
suppose que le DEVICE donné est un périphérique ATA ou ATAPI. Équivalent à --ata dans la section OPTIONS.
-b
décode la page VPD Block Limits [0xb0]. Équivalent à « --page=bl » dans la section OPTIONS. Cette page est définie dans SBC-2 (voir www.t10.org) et les versions ultérieures.
-B=0|1
équivalent à --block=0|1 dans la section OPTIONS.
-c
définit le bit Command Support Data (CmdDt) (par défaut à effacé(0)). Utilisé conjointement avec l'option -p=VPD_PG pour spécifier l'opcode de commande SCSI à interroger. Équivalent à --cmddt dans la section OPTIONS.
-cl
liste les données de commande pour toutes les commandes prises en charge (suivies du nom de la commande) en parcourant tous les 256 opcodes. Cette option utilise le bit CmdDt qui est maintenant obsolète. Voir l'utilitaire sg_opcodes(8). Équivalent à « --cmddt --cmddt » dans la section OPTIONS.
-d
décode en fonction du contexte. Si l'option -e est donnée, ou toute option qui implique -e (par exemple, '-i' ou '-p=80'), alors cet utilitaire tente de décoder la page VPD indiquée. Sinon, les descripteurs de version (le cas échéant) sont listés après une réponse INQUIRY standard. Dans le contexte des descripteurs de version, équivalent à --descriptors dans la section OPTIONS.
-e
active (c'est-à-dire définit) le bit Vital Product Data (EVPD) (par défaut à effacé(0)). Utilisé conjointement avec l'option -p=VPD_PG pour spécifier la page VPD à récupérer. Si -p=VPD_PG n'est pas donné, la page VPD 0 (liste des pages VPD prises en charge) est supposée.
-f
équivalent à --force dans la section OPTIONS.
-h
affiche la réponse INQUIRY en hexadécimal au lieu d'essayer de la décoder. Équivalent à --hex dans la section OPTIONS.
-H
même action que -h. Équivalent à --hex dans la section OPTIONS.
-i
décode la page VPD Device Identification [0x83]. Équivalent à --id dans la section OPTIONS. Cette page est composée de plusieurs « descripteurs de désignation ». Si -h est donné, chaque en-tête de descripteur est décodé et l'identifiant lui-même est affiché en hexadécimal. Pour voir la réponse complète de la page VPD 0x83 en hexadécimal, utilisez '-p=83 -h'.
-I=FN
équivalent à --inhex=FN dans la section OPTIONS.
-j[=JO]
équivalent à --json[=JO] dans la section OPTIONS.
-l=LEN
équivalent à --len=LEN dans la section OPTIONS.
-L
équivalent à --long dans la section OPTIONS.
-m
décode la page VPD Management network addresses [0x85]. Équivalent à « --page=mna » dans la section OPTIONS.
-M
décode la page VPD Mode page policy [0x87]. Équivalent à « --page=mpp » dans la section OPTIONS.
-N, --new
passe aux options de style plus récent.
-o
équivalent à --only dans la section OPTIONS.
-p=VPD_PG
utilisé conjointement avec l'option -e ou -c. Si aucun n'est donné, l'option -e est supposée. Lorsque l'option -e est également donnée (ou supposée), l'argument de cette option est le numéro de page VPD. L'argument est interprété en hexadécimal et doit être compris entre 0 et ff inclus. Seule la page VPD 0 est décodée et elle liste les pages VPD prises en charge et leurs noms (si connus). Pour décoder la page d'identification obligatoire du périphérique (0x83), utilisez l'option -i. Une utilisation maintenant obsolète est lorsque l'option -c est donnée, auquel cas l'argument de cette option est supposé être un numéro d'opcode de commande. Les brouillons de normes SCSI récents ont déplacé cette fonctionnalité vers une commande distincte (voir sg_opcodes(8)). Par défaut à 0, donc si -e est donné sans cette option, la page VPD 0 est affichée.
-P
décode la page VPD Unit Path Report [0xc0] qui est spécifique à EMC. Équivalent à « --page=upr » dans la section OPTIONS.
-r
affiche la réponse en binaire sur stdout. Équivalent à --raw dans la section OPTIONS. Peut être utilisé deux fois (c'est-à-dire '-rr' (et '-HHH' a le même effet)) et s'il est utilisé avec l'option -A ou -a, produit une sortie avec le même format que « cat /proc/ide/hd<x>/identify » afin qu'elle puisse ensuite être redirigée vers « hdparm --Istdin ».
-s
décode la page VPD SCSI Ports [0x88]. Équivalent à « --page=sp » dans la section OPTIONS.
-u
équivalent à « --export » dans la section OPTIONS.
-v
augmente le niveau de verbosité. Peut être utilisé plusieurs fois.
-V
affiche la chaîne de version puis quitte.
-x
décode la page VPD Extended INQUIRY data [0x86]. Équivalent à « --page=ei » dans la section OPTIONS.
-?
affiche le message d'utilisation et quitte. Ignore tous les autres paramètres.

sg_inq(8) — sg3_utils — Arch Linux man pages

NAME

sg_inq — read SCSI vital product data (VPD) pages and related information

SYNOPSIS

sg_inq [OPTIONS] [DEVICE]

DESCRIPTION

This utility interrogates a SCSI device (or an NVMe device which emulates SCSI) and displays information obtained from the SCSI INQUIRY command. It is particularly useful for viewing Vital Product Data (VPD) pages.

OPTIONS

-a, --all
List all supported VPD pages. By default only a subset of the more common VPD pages are listed. Use sg_inq with no options to see the default list.
-A, -- ata-info
Print ATA Information VPD page (page code 85h). Requires sg_inq version 1.20 or later.
-b, --broad-cast-luns
Perform a broadcast Lightly Treatable LUN (LT LUN) inventory operation. This is an older mechanism for discovering LUNs and may not be supported. Use with extreme caution.
-c, --di-csv
Output the Device Identification VPD page (page code 83h) in CSV format. This is useful for scripting and piping to other utilities. Can be combined with -p 83h.
-d, --di-pgd
Output the Device Identification VPD page (page code 83h) in ASCII hexadecimal format. This is the default if page 83h is requested.
-e, --enumerate
Enumerate supported VPD pages. This command lists the page codes that the device claims to support. It does not fetch the content of the pages.
-f, --fcp-lu-id
Print FCP Target Port Identification VPD page (page code 95h). Requires sg_inq version 1.21 or later.
-h, --help
Print the usage message and exit.
-i, --ident
Print standard INQUIRY data. This is the default if no page codes are specified.
-I, --inhex=FN
Read the binary response for a VPD page from the file FN. This is useful when the device itself is not accessible, but its response has been saved to a file. See the example section on sysfs.
-l, --list-vpd
List VPD pages. This is a synonym for -e.
-m, --vendor-spc
Print Vendor Specific VPD page (page code 0). Requires sg_inq version 1.23 or later.
-O, --old
Use older command line interpretation. This is useful for backwards compatibility.
-p PG, ...
Page code(s) to request. The page codes can be given as decimal or hexadecimal (prefixed with 0x or enclosed in h). Multiple page codes can be given, separated by commas. If no page codes are given, then the standard INQUIRY data is printed.
-r, --raw
Output the data in binary form. This is the default for some pages like 83h, but can be explicitly requested. Useful when piping to other utilities.
-S, --scsi-name
Print Extended INQUIRY data (using the SCSI standard INQUIRY command with the EVPD bit set and page code 0). This is equivalent to -p 0.
-t, --t10-pi
Print T10 Protection Information VPD page (page code 01h). Requires sg_inq version 1.23 or later.
-v, --verbose
Increase verbosity.
-V, --version
Print version string and exit.
-x, --hex
Output the data in ASCII hexadecimal format. This is the default for most VPD pages.

NOTES

The SCSI INQUIRY command is a fundamental command used to query device characteristics. Vital Product Data (VPD) pages provide more detailed information about the device, such as its serial number, device identification, supported modes, etc. The standard INQUIRY command returns 36 bytes of data. VPD pages can extend this data significantly.

The sg_inq utility sends SCSI INQUIRY commands to the specified DEVICE. The DEVICE can be a SCSI device file (e.g., /dev/sg0, /dev/st0), a disk device file (e.g., /dev/sda), or an NVMe device file (e.g., /dev/nvme0n1).

If no DEVICE is given, sg_inq will attempt to open the first available generic SCSI device (e.g., /dev/sg0).

ATA DEVICES

For ATA devices, the SCSI INQUIRY command is often translated to ATA commands by the host bus adapter (HBA) or the kernel. The VPD pages returned may reflect ATA Identify Device information.

NVME DEVICES

NVMe devices use the SCSI translation layer to respond to SCSI commands. sg_inq can query NVMe devices, and certain VPD pages may be populated with NVMe-specific information.

SG_INQ and SG_VPD

The sg_vpd utility is specifically designed to query and display VPD pages. While sg_inq can display many VPD pages, sg_vpd offers more specialized functionality and formatting options for VPD data.

EXIT STATUS

Exits with 0 on success, and non-zero if an error occurs.

OLDER COMMAND LINE OPTIONS

For compatibility with older versions of sg3_utils, the -O or --old option can be used. This changes how the command line arguments are parsed. For example, if -O is present, then -p 80 is interpreted as requesting page 80h, whereas without -O, it might be interpreted as a file name.

EXAMPLES

To list the standard INQUIRY data:


sg_inq /dev/sda

To list all supported VPD pages (but not their contents):


sg_inq -e /dev/sda

To display the Device Identification VPD page (page code 83h):


sg_inq -p 83h /dev/sda

To display the Unit Serial Number VPD page (page code 02h):


sg_inq -p 02h /dev/sda

To display the ATA Information VPD page (page code 85h):


sg_inq -A /dev/sda

To display the T10 Protection Information VPD page (page code 01h):


sg_inq -t /dev/sda

The SCSI INQUIRY command returns Vital Product Data (VPD) pages which can be viewed with the SCSI INQUIRY command. To list the supported VPD pages (but not their contents) try:


sg_inq -e /dev/sda

In Linux, binary images of some important VPD page responses (e.g. 0, 80h and 83h) are cached in files within the sysfs pseudo file system. Since VPD pages hardly ever change their contents, decoding those files will give the same output as probing the device with the added benefit that decoding those files doesn't need root permissions. If /dev/sg3 is a disk at 2:0:0:0 , then these three invocations should result in the same output:


sg_inq --raw --inhex=/sys/class/scsi_generic/sg3/device/vpd_pg83


sg_inq -rI /sys/class/scsi_generic/sg3/device/vpd_pg83


sg_inq -r -I /sys/class/scsi_disk/2:0:0:0/device/vpd_pg83

Without the --raw option, the --inhex=FN option would expect the contents of those files to be hexadecimal. vpd_pg83 contains the response (in binary) to the Device Identification VPD page whose page number is 83h (i.e. hexadecimal).

Some VPD pages can be read with the sg_inq utility but a newer utility called sg_vpd specializes in showing their contents. The sdparm utility can also be used to show the contents of VPD pages.

Further examples of sg_inq together with some typical output can be found on https://sg.danny.cz/sg/sg3_utils.html web page.

ENVIRONMENT VARIABLES

Since sg3_utils version 1.23 the environment variable SG3_UTILS_OLD_OPTS can be given. When it is present this utility will expect the older command line options. So the presence of this environment variable is equivalent to using --old (or -O) as the first command line option.
