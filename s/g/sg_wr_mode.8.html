NOM

sg_wr_mode - écrire (modifier) une page de mode SCSI

SYNTAXE

sg_wr_mode [--cfile=CF] [--contents=H,H...] [--dbd] [--force] [--help] [--len=10|6] [--mask=M,M...] [--page=PG_H[,SPG_H]] [--raw] [--rtd] [--save] [--six] [--verbose] [--version] APPAREIL

DESCRIPTION

Écrit une page de mode modifiée sur APPAREIL. Utilise la commande SCSI MODE SENSE (variante 6 ou 10 octets) pour récupérer les données de mode existantes qui incluent une page de mode (ou sous-page). Elle combine ensuite cela avec le contenu, potentiellement masqué, et écrit la page de mode modifiée avec la commande SCSI MODE SELECT (variante 6 ou 10 octets). Cet utilitaire ne modifie pas les descripteurs de bloc ; si des descripteurs de bloc sont récupérés par la commande MODE SENSE, les mêmes descripteurs de bloc sont réécrits avec la commande MODE SELECT suivante.

Si l'option --rtd est donnée, la plupart des autres options à part --save, --len=10|6 et --six sont ignorées. Dans ce cas, seule une commande MODE SELECT est envoyée à APPAREIL avec le bit RTD (Revert To Defaults) activé. Ce bit a été ajouté à cette commande dans la révision 11 de SPC-5, donc les anciens appareils pourraient ne pas le supporter. La page VPD Extended Inquiry a le bit RTD_SUP pour indiquer si APPAREIL supporte le bit RTD dans les commandes MODE SELECT(6 et 10). Lorsque l'option --rtd est donnée, le reste de cette section peut être ignoré.

Si une option de contenu n'est pas donnée, alors les divers composants (c'est-à-dire l'en-tête, les descripteurs de bloc et la page de mode) des valeurs "actuelles" de la page de mode existante sont imprimés. Dans ce cas, la page de mode n'est pas modifiée sur l'appareil.

Si les contenus sont spécifiés, et qu'un masque n'est pas spécifié, alors les contenus doivent correspondre à la page de mode existante à divers égards, sauf si l'option --force est donnée. Cela inclut la longueur, le code de la page de mode et le code de la sous-page le cas échéant. Si tout va bien, alors la chaîne de contenu est écrite sur APPAREIL comme nouvelle page de mode.

Si les deux chaînes de contenu et de masque sont spécifiées, seuls les positions de bits dans les contenus correspondant aux bits définis dans le masque sont pris, tandis que la page de mode existante fournit les positions de bits correspondant aux bits effacés. Lorsqu'un masque est donné, le masque et/ou les contenus peuvent être plus courts que la page de mode existante. Si le masque est plus court que le contenu, les octets restants sont pris du contenu. Si les contenus sont plus courts que la page de mode existante, les octets restants sont pris de la page de mode existante.

L'option force permet que la chaîne de contenu soit prise comme nouvelle page de mode sans aucune vérification préalable sur la page de mode existante. Ceci ne devrait être requis que pour les pages de mode spécifiques au vendeur. Les données de mode existantes sont ignorées à part les descripteurs de bloc qui peuvent être supprimés avec l'option --dbd si nécessaire.

Changer des champs individuels dans une page de mode est probablement plus facile à faire avec l'utilitaire sdparm. Les champs peuvent être identifiés par un acronyme ou par un descripteur numérique.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-C, --cfile=CF
où CF est un nom de fichier contenant la page de mode. Voir la section "FORMATS HEXADÉCIMAL, BINAIRE ET JSON" dans la page de manuel sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors le contenu de FN est traité comme binaire.
-c, --contents=H,H...
où H,H... est une chaîne de nombres hexadécimaux séparés par des virgules, dont chacun doit se résoudre en une valeur d'octet (c'est-à-dire de 0 à ff inclus). Une chaîne de nombres hexadécimaux (simples) séparés par des espaces est également autorisée mais la liste doit être entre guillemets. C'est le nouveau contenu de la page de mode à écrire sur APPAREIL, potentiellement filtré par la chaîne de masque.
-c, --contents=-
lit la chaîne de contenu depuis l'entrée standard. Voir l'option --cfile=CF ci-dessus.
-d, --dbd
désactive les descripteurs de bloc (flag DBD dans le cdb). Certains types d'appareils incluent des descripteurs de bloc dans les données de mode retournées par une commande MODE SENSE. Si c'est le cas, les mêmes descripteurs de bloc sont écrits par la commande MODE SELECT. Cette option demande à la commande MODE SENSE de ne pas retourner de descripteurs de bloc. Ce serait un choix raisonnable par défaut pour cet utilitaire, mis à part le fait que tous les appareils SCSI ne supportent pas le bit DBD dans le cdb.
-f, --force
force la chaîne de contenu à être prise comme nouvelle page de mode, ou du moins n'effectue pas de vérifications sur la page de mode existante. Notez que APPAREIL peut toujours rejeter le nouveau contenu de la page de mode. Ne peut pas être utilisé avec l'option --mask=M,M....
-h, --help
affiche le message d'utilisation puis quitte.
-l, --len=10 | 6
longueur des commandes SCSI (cdb) envoyées à APPAREIL. La valeur par défaut est 10, donc des commandes MODE SENSE et MODE SELECT de 10 octets sont émises. Certains anciens appareils ne supportent pas les variantes de 10 octets, d'où cette option.
-m, --mask=M,M...
où M,M... est une chaîne de nombres hexadécimaux séparés par des virgules, dont chacun doit se résoudre en une valeur d'octet (c'est-à-dire de 0 à ff inclus). Une chaîne de nombres hexadécimaux (simples) séparés par des espaces est également autorisée mais la liste doit être entre guillemets. Le masque choisit (octet par octet) si la nouvelle page de mode provient du contenu (bit de masque défini) ou de la page de mode existante (bit de masque effacé). Si la chaîne de masque est plus courte que la chaîne de contenu, les octets restants sont pris de la chaîne de contenu. Si la chaîne de contenu est plus courte que la page de mode existante, les octets restants sont pris de la page de mode existante (c'est-à-dire qu'ils ne sont pas modifiés).
-p, --page=PG_H
où PG_H est la valeur du code de page à récupérer et modifier. Le code de page est en hexadécimal et doit être compris entre 0 et 3e inclus. Notez que le code de page 3f pour récupérer toutes les pages de mode est interdit.
-p, --page=PG_H,SPG_H
où PG_H est la valeur du code de page et SPG_H est la valeur du code de sous-page à récupérer et modifier. Les deux valeurs sont en hexadécimal. Le code de sous-page doit être compris entre 0 et fe inclus. Notez que le code de sous-page ff pour récupérer toutes les sous-pages de mode (pour une page de mode donnée ou toutes les pages de mode dans le cas de 3f,ff) est interdit.
-r, --raw
lorsque cette option est donnée, le fichier donné par l'option --cfile=CF est traité comme binaire (la valeur par défaut est de le traiter comme hexadécimal ASCII).
-R, --rtd
lorsque cette option est donnée, la plupart des autres actions sont contournées et une commande MODE SELECT(6 ou 10) est envoyée à APPAREIL avec le bit RTD activé. Cela fera que toutes les valeurs actuelles (et les valeurs sauvegardées si l'option --save est également donnée) de toutes les pages de mode seront rétablies à leurs valeurs par défaut.
-s, --save
modifie la page de mode "sauvegardée" lorsque MODE SELECT réussit. Par défaut (c'est-à-dire lorsque --save n'est pas utilisé), seules les valeurs "actuelles" de la page de mode sont modifiées lorsque MODE SELECT réussit. Dans ce cas, la nouvelle page de mode restera en vigueur jusqu'à ce que l'appareil soit réinitialisé (par exemple, redémarré électriquement). Lors du redémarrage, les valeurs "sauvegardées" de la page de mode seront réinstaurées. Donc, pour rendre les changements permanents, utilisez l'option --save.
Lorsqu'utilisé avec l'option --rtd, les valeurs actuelles et sauvegardées de chaque page de mode sont rétablies à leurs valeurs par défaut. En l'absence de l'option --save, seules les valeurs actuelles de chaque page de mode sont rétablies à leurs valeurs par défaut.
-6, --six
cette option fera utiliser les variantes de 6 octets des commandes MODE SENSE et MODE SELECT. La valeur par défaut est d'utiliser les variantes de 10 octets. Cette option est équivalente à utiliser l'option --len=6.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les sorties de débogage).
-V, --version
affiche la chaîne de version puis quitte.

EXEMPLES

Pour voir la page de mode 0x01 (fortement recommandée) de l'appareil `/dev/sg0` utilisez :

sg_wr_mode --page=0x01 /dev/sg0

Pour changer le bit 7 de l'octet 2 de la page de mode 0x01 de `/dev/sg1` de sa valeur actuelle à 1 (et sauvegarder ce changement) utilisez :
(l'octet 0 et 1 du masque et du contenu sont juste des placeholders)

sg_wr_mode --page=0x01 --contents=0x00,0x02,0x80 --mask=0xff,0xff,0x80 --save /dev/sg1

Pour rétablir tous les modes de `/dev/sg0` à leurs valeurs par défaut et les sauvegarder :

sg_wr_mode --rtd --save /dev/sg0

EN RAPPORT

NOM

sg_wr_mode

écrire des pages de mode sur un périphérique SCSI

SYNOPSIS

sg_wr_mode [OPTION ...] DEVICE

sg_wr_mode [OPTION ...] -c CONTENTS -m MASK DEVICE

DESCRIPTION

Ce programme de l'espace utilisateur écrit une page de mode sur un périphérique SCSI, soit en remplaçant complètement une page de mode existante, soit en modifiant une partie de celle-ci via un masque.

La plupart des périphériques SCSI ont des pages de mode qui contrôlent divers aspects de leur comportement. Par exemple, la page de mode 0x1a sur les périphériques MMC (CD/DVD) contrôle la gestion de l'alimentation.

Le processus typique pour modifier une page de mode consiste à utiliser d'abord sg_modes(8) pour lire la page actuelle, à modifier le contenu de la page, puis à utiliser sg_wr_mode pour écrire la nouvelle page de mode. Alternativement, pour des modifications plus fines, on peut lire la page, utiliser sg_wr_mode avec les options -c et -m pour spécifier les valeurs à écrire et les bits à modifier.

OPTIONS

-c, --contents=CONTENTS
Spécifie le contenu de la page de mode à écrire. La chaîne CONTENTS est une liste de nombres hexadécimaux séparés par des virgules. Si elle est précédée d'un tiret (`-`), le contenu est lu depuis l'entrée standard. Par défaut, si cette option n'est pas utilisée, la page de mode spécifiée par -p sera lue, modifiée si nécessaire par -m, puis écrite. Si -c est donné, cela remplace entièrement la page de mode.
-f, --force
Certains champs de la page de mode (comme le bit PS) ne doivent pas être modifiés par l'utilisateur. Sans cette option, le bit PS dans la chaîne CONTENTS est mis à zéro. Avec cette option, le bit PS est conservé tel qu'il est spécifié dans CONTENTS.
-h, --help
Affiche un message d'aide et quitte.
-H, --hex
Affiche la sortie en hexadécimal.
-I, --inhex
Utilise des chaînes hexadécimales pour les arguments des options -c et -m.
-k, --kbytes
Le paramètre de la page de mode est donné en kilooctets (KBytes).
-p, --page=PAGE
Page de mode à écrire. PAGE peut être un nombre hexadécimal ou décimal. Les numéros de page spéciaux comme `all` ne sont pas pris en charge par cette option.
-r, --read
Lit la page de mode spécifiée avant de la modifier et de l'écrire. Ceci est utile si vous voulez modifier seulement une partie de la page.
-s, --save
Écrit la page de mode dans la mémoire non volatile du périphérique, de sorte qu'elle persiste après un cycle d'alimentation.
-S, --subpage=SUBPAGE
Sous-page de mode à écrire. SUBPAGE peut être un nombre hexadécimal ou décimal.
-v, --verbose
Augmente le niveau de verbosité.
-?, --help
Affiche un message d'aide et quitte.

NOTES

Cet utilitaire ne vérifie pas si la chaîne de contenu tente de modifier des parties de la page de mode qui sont modifiables. Le périphérique devrait faire cela et si une partie n'est pas modifiable, il devrait signaler : "Invalid field in parameter list".

Certaines pages de mode ne sont pas sauvegardables. Si c'est le cas, une tentative d'utilisation de l'option --save devrait provoquer une erreur signalée par le périphérique : "Illegal field in cdb".

Le périphérique est requis pour effectuer diverses vérifications avant d'accepter une nouvelle page de mode. Si ces vérifications échouent, la page de mode n'est pas modifiée et une erreur de type "parameter list length error" ou "invalid field in parameter list" est retournée par le périphérique dans les données de sens.

La manière recommandée de modifier une page de mode est de la lire avec un MODE SENSE, de modifier une partie de celle-ci puis de la réécrire sur le périphérique avec une commande MODE SELECT. Par exemple, la lecture d'une page de mode existante peut être effectuée avec 'sg_modes -p=1a -r /dev/sdb > mp_1a.txt' (la page de mode de condition d'alimentation). Le fichier mp_1a.txt peut être édité puis utilisé comme chaîne de contenu pour cet utilitaire (par exemple, 'sg_wr_mode -p 1a -s -c - /dev/sdb < mp_1a.txt').

Deux champs diffèrent entre ce qui est lu du périphérique avec MODE SENSE et ce qui est écrit sur le périphérique avec MODE SELECT : la longueur des données de mode est réservée (c'est-à-dire nulle(s)) dans une commande MODE SELECT tandis que le bit PS (octet 0 bit 7 de la sous-page) dans chaque page (sous-)mode est réservé (zéro) dans une commande MODE SELECT. Le bit PS donné dans la chaîne de contenu est mis à zéro à moins que l'option --force ne soit sélectionnée.

EXEMPLES

Cet utilitaire peut être utilisé conjointement avec l'utilitaire sg_modes. Pour rétablir les valeurs par défaut de la page de mode (c'est-à-dire les valeurs de page de mode choisies par le fabricant du périphérique) en tant que valeurs de page de mode courantes et sauvegardées, la séquence suivante pourrait être utilisée :


$ sg_modes --control=2 --page=1a -r /dev/sda > t


$ sg_wr_mode --page=1a --contents=- --save /dev/sda < t

Ci-dessous un exemple d'utilisation d'un masque pour modifier le "compteur de condition de veille" de la page de mode "condition d'alimentation" (0x1a) de 0x28 à 0x37. Notez que le changement n'est pas sauvegardé, donc le "compteur de condition de veille" reviendra à 0x28 après le prochain cycle d'alimentation. La sortie de sg_modes est abrégée.


$ sg_modes --page=1a /dev/hdc
>> Condition d'alimentation (mmc), page_control: current
00 1a 0a 00 03 00 00 00 28 00 00 01 2c


$ sg_wr_mode -p 1a -c 0,0,0,0,0,0,0,37 -m 0,0,0,0,0,0,0,ff /dev/hdc


$ sg_modes -p 1a /dev/hdc
>> Condition d'alimentation (mmc), page_control: current
00 1a 0a 00 03 00 00 00 37 00 00 01 2c

STATUT DE SORTIE

Le statut de sortie de sg_wr_mode est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
