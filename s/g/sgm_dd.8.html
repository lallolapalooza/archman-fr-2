SGM_DD(8) SG3_UTILS SGM_DD(8)

NOM

sgm_dd - copie des données vers et depuis des fichiers et des périphériques, en particulier des périphériques SCSI

SYNTAXE

sgm_dd [bs=BS] [count=COUNT] [ibs=BS] [if=IFILE] [iflag=FLAGS] [obs=BS] [of=OFILE] [oflag=FLAGS] [seek=SEEK] [skip=SKIP] [--help] [--version]

[bpt=BPT] [cdbsz=6|10|12|16] [dio=0|1] [sync=0|1] [time=0|1] [verbose=VERB] [--dry-run] [--progress] [--verbose]

DESCRIPTION

Copie des données vers et depuis n'importe quels fichiers. Spécialisé pour les « fichiers » qui sont des périphériques génériques SCSI (sg) Linux et des périphériques bruts. Utilise des transferts mappés en mémoire sur les périphériques sg. Syntaxe et sémantique similaires à dd(1) mais n'effectue aucune conversion.

N'effectuera des transferts mappés en mémoire que lorsque IFILE ou OFILE sont des périphériques génériques SCSI (sg).

Si IFILE et OFILE sont tous deux des périphériques sg, alors des transferts mappés en mémoire sont effectués sur IFILE. Si aucun autre drapeau n'est spécifié, alors les E/S indirectes sont effectuées sur OFILE. Si 'oflag=dio' est donné, alors les E/S directes sont tentées sur OFILE. Si les E/S directes ne sont pas disponibles, alors cet utilitaire se rabat sur les E/S indirectes et le signale à la fin de la copie.

Le premier groupe dans la synopsis ci-dessus contient les opérandes « standard » Unix de dd(1). Le second groupe contient des options supplémentaires ajoutées par cet utilitaire. Les deux groupes sont définis ci-dessous.

OPTIONS

bpt=BPT
chaque transaction E/S sera effectuée en utilisant BPT blocs (ou moins si près de la fin de la copie). La valeur par défaut est 128 pour les tailles de bloc inférieures à 2048 octets, sinon la valeur par défaut est 32. Ainsi, pour bs=512, les lectures et écritures transmettront chacune 64 KiB de données par défaut (moins si près de la fin du transfert ou restrictions de mémoire). Lorsque des lecteurs cd/dvd sont accédés, la taille de bloc est typiquement de 2048 octets et bpt vaut par défaut 32, ce qui implique encore des transferts de 64 KiB.
bs=BS
où BS doit être la taille de bloc du périphérique physique. Notez que cela diffère de dd(1) qui autorise BS à être un multiple entier. La valeur par défaut est 512, ce qui est généralement correct pour les disques mais incorrect pour les lecteurs CD-ROM (qui ont normalement des blocs de 2048 octets). Pour cet utilitaire, la taille maximale de chaque opération d'E/S individuelle est BS * BPT octets.
cdbsz=6 | 10 | 12 | 16
taille des blocs de commande SCSI READ et/ou WRITE émis sur les noms de périphériques sg. La valeur par défaut est des blocs de commande SCSI de 10 octets (sauf si les calculs indiquent qu'un numéro de bloc de 4 octets peut être dépassé, auquel cas la valeur par défaut est des commandes SCSI de 16 octets).
count=COUNT
copie COUNT blocs de IFILE vers OFILE. La valeur par défaut est le nombre minimum (de IFILE et OFILE) de blocs que les périphériques sg rapportent des commandes SCSI READ CAPACITY ou que les périphériques de bloc (ou leurs partitions) rapportent. Les fichiers normaux ne sont pas interrogés pour leur taille. Si skip=SKIP ou seek=SEEK sont donnés et que le compte est dérivé (c'est-à-dire non explicitement donné), alors le compte dérivé est réduit afin que la copie ne dépasse pas le périphérique. Si le nom de fichier est une partition de périphérique de bloc et que COUNT n'est pas donné, alors la taille de la partition plutôt que la taille de l'ensemble du périphérique est utilisée. Si COUNT n'est pas donné et ne peut pas être dérivé, alors un message d'erreur est émis et aucune copie n'a lieu.
dio=0 | 1
permet la sélection des E/S directes sur le côté écriture (c'est-à-dire sur OFILE). N'est autorisé que lorsque le côté lecture (c'est-à-dire IFILE) est un périphérique sg. Lorsque 1, il peut y avoir une copie « sans copie » (c'est-à-dire un transfert mmap-ed de la lecture vers l'espace utilisateur et des E/S directes à partir de là en écriture, potentiellement deux DMA et aucune copie de données par le CPU). La valeur par défaut est 0. La même action que 'dio=1' est également disponible avec 'oflag=dio'.
ibs=BS
si donné, doit être le même que BS donné à l'option 'bs='.
if=IFILE
lit depuis IFILE au lieu de stdin. Si IFILE est '-', alors stdin est lu. Commence à lire au début de IFILE à moins que SKIP ne soit donné.
iflag=FLAGS
où FLAGS est une liste de drapeaux séparés par des virgules, un ou plusieurs des drapeaux décrits ci-dessous. Ces drapeaux sont associés à IFILE et sont ignorés lorsque IFILE est stdin.
obs=BS
si donné, doit être le même que BS donné à l'option 'bs='.
of=OFILE
écrit vers OFILE au lieu de stdout. Si OFILE est '-', alors écrit vers stdout. Si OFILE est /dev/null, alors aucune écriture réelle n'est effectuée. Si OFILE est '.', il est traité de la même manière que /dev/null (c'est une notation abrégée). Si OFILE existe, il n'est *pas* tronqué ; il est écrasé à partir du début de OFILE à moins que 'oflag=append' ou SEEK ne soit donné.
oflag=FLAGS
où FLAGS est une liste de drapeaux séparés par des virgules, un ou plusieurs des drapeaux décrits ci-dessous. Ces drapeaux sont associés à OFILE et sont ignorés lorsque OFILE est /dev/null, '.' (point), ou stdout.
seek=SEEK
commence à écrire SEEK blocs de taille bs depuis le début de OFILE. La valeur par défaut est le bloc 0 (c'est-à-dire le début du fichier).
skip=SKIP
commence à lire SKIP blocs de taille bs depuis le début de IFILE. La valeur par défaut est le bloc 0 (c'est-à-dire le début du fichier).
sync=0 | 1
lorsque 1, effectue une commande SYNCHRONIZE CACHE sur OFILE à la fin du transfert. Uniquement actif lorsque OFILE est un nom de fichier de périphérique sg.
time=0 | 1
lorsque 1, chronomètre le transfert et calcule le débit, affichant les résultats (sur stderr) à la fin. Lorsque 0 (par défaut), n'effectue pas de chronométrage.
verbose=VERB
à mesure que VERB augmente, la quantité de sortie de débogage envoyée à stderr augmente. La valeur par défaut est zéro, ce qui produit le minimum de sortie de débogage. Une valeur de 1 signale des informations supplémentaires qui ne sont pas répétitives. Une valeur de 2 signale les cdbs et les réponses pour les commandes SCSI qui ne sont pas répétitives (c'est-à-dire autres que READ et WRITE). Le traitement des erreurs n'est pas considéré comme répétitif. Les valeurs 3 et 4 produisent une sortie pour toutes les commandes SCSI (et les appels Unix read() et write()), il peut donc y avoir une grande quantité de sortie.
-d, --dry-run
effectue toute l'analyse et la préparation de la ligne de commande mais contourne la copie ou la lecture réelle. Cette préparation peut inclure l'ouverture de IFILE ou OFILE pour déterminer leurs longueurs. Cette option peut être utile pour tester la syntaxe d'invocations complexes de ligne de commande avant de les exécuter.
-h, --help
affiche le message d'utilisation et quitte.
-p, --progress
cette option provoque l'affichage d'un rapport de progression toutes les deux minutes jusqu'à ce que la copie soit terminée. Après la fin de la copie, une ligne avec « completed » est imprimée pour distinguer le rapport final des rapports de progression précédents. Lorsqu'elle est utilisée deux fois, le rapport de progression est toutes les minutes, lorsqu'elle est utilisée trois fois, le rapport de progression est toutes les 30 secondes.
Si cette option est donnée, alors l'option 'time=1' est implicitement définie.
-v, --verbose
lorsqu'il est utilisé une fois, équivaut à verbose=1. Lorsqu'il est utilisé deux fois (par exemple, "-vv"), équivaut à verbose=2, etc.
-V, --version
affiche les informations sur le numéro de version et quitte.

FLAGS

Voici une liste de drapeaux et leur signification :

append
cause l'ajout du drapeau O_APPEND

sgm_dd(8) — sg3_utils documentation

NAME

sgm_dd — copy data to/from storage devices using SCSI.

SYNOPSIS

sgm_dd [OPTIONS] IFILE=IFILE OFILE=OFILE

DESCRIPTION

The sgm_dd utility copies data from a source file (IFILE) to a destination file (OFILE). It is intended to be a simpler and more focused version of sg_dd. Many of the options mirror those found in the standard dd utility. This utility uses the SCSI generic (sg) interface to perform the copy operations. It is primarily designed for block devices, but can also be used with regular files.

The sgm_dd utility uses memory mapped IO (mmap) for its transfers by default, which is often faster than standard read/write operations for block devices. If this is not desired or not possible, the -direct=1 option can be used to disable it and force the use of standard IO. The -direct=0 option enables memory mapped IO. The default action is to use memory mapped IO.

Note that this utility is a simplified version of sg_dd and some features may be missing or behave differently.

OPTIONS

The options are split into two categories: flags (which are on/off switches) and keyword-argument pairs.

The keyword-argument pairs are: bs=N, count=N, ibs=N, obs=N, skip=N, seek=N, iseek=N, oseek=N, iflag=IFLAG,..., oflag=OFLAG,..., read=N, write=N.

The flags are: append, dio, direct, dpo, dsync, excl, fua, null.

The default action is to overwrite any existing data from the beginning of the file or, if seek is given, starting at block seek.

See the sg_dd man page for a detailed description of these options.

FLAGS

append
Causes the O_APPEND flag to be added to the open of OFILE. For normal files this will lead to data appended to the end of any existing data. Cannot be used together with the seek=SEEK option as they conflict. The default action of this utility is to overwrite any existing data from the beginning of the file or, if SEEK is given, starting at block SEEK. Note that attempting to 'append' to a device file (e.g. a disk) will usually be ignored or may cause an error to be reported.
dio
is only active with oflag (i.e. 'oflag=dio'). Its action is described in the 'dio=1' option description above.
direct
causes the O_DIRECT flag to be added to the open of IFILE and/or OFILE. This flag requires some memory alignment on IO. Hence user memory buffers are aligned to the page size. Has no effect on sg, normal or raw files.
dpo
set the DPO bit (disable page out) in SCSI READ and WRITE commands. Not supported for 6 byte cdb variants of READ and WRITE. Indicates that data is unlikely to be required to stay in device (e.g. disk) cache. May speed media copy and/or cause a media copy to have less impact on other device users.
dsync
causes the O_SYNC flag to be added to the open of IFILE and/or OFILE. The "d" is prepended to lower confusion with the 'sync=0|1' option which has another action (i.e. a synchronisation to media at the end of the transfer).
excl
causes the O_EXCL flag to be added to the open of IFILE and/or OFILE.
fua
causes the FUA (force unit access) bit to be set in SCSI READ and/or WRITE commands. This only has effect with sg devices. The 6 byte variants of the SCSI READ and WRITE commands do not support the FUA bit. Only active for sg device file names.
null
has no affect, just a placeholder.

RETIRED OPTIONS

Here are some retired options that are still present:

fua=0 | 1 | 2 | 3
force unit access bit. When 3, fua is set on both IFILE and OFILE; when 2, fua is set on IFILE; when 1, fua is set on OFILE; when 0 (default), fua is cleared on both. See the 'fua' flag.

NOTES

A raw device must be bound to a block device prior to using sgm_dd. See raw(8) for more information about binding raw devices. To be safe, the sg device mapping to SCSI block devices should be checked with the lsscsi utility before use.

Raw device partition information can often be found with fdisk(8) [the "-ul" argument is useful in this respect].

Various numeric arguments (e.g. SKIP) may include multiplicative suffixes or be given in hexadecimal. See the "NUMERIC ARGUMENTS" section in the sg3_utils(8) man page.

The count, skip and seek parameters can take 64 bit values (i.e. very big numbers). Other values are limited to what can fit in a signed 32 bit number.

Data usually gets to the user space in a 2 stage process: first the SCSI adapter DMAs into kernel buffers and then the sg driver copies this data into user memory (write operations reverse this sequence). With memory mapped transfers a kernel buffer reserved by sg is memory mapped (see the mmap(2) system call) into the user space. When this is done the second (redundant) copy from kernel buffers to user space is not needed. Hence the transfer is faster and requires less "grunt" from the CPU.

All informative, warning and error output is sent to stderr so that dd's output file can be stdout and remain unpolluted. If no options are given, then the usage message is output and nothing else happens.

For sg devices this utility issues SCSI READ and WRITE (SBC) commands which are appropriate for disks and reading from CD/DVD/BD drives. Those commands are not formatted correctly for tape devices so sgm_dd should not be used on tape devices.

This utility stops the copy if any error is encountered. For more advanced "copy on error" logic see the sg_dd utility (and its 'coe' flag).

EXAMPLES

See the examples given in the man page for sg_dd(8).

SIGNALS

The signal handling has been borrowed from dd: SIGINT, SIGQUIT and SIGPIPE output the number of remaining blocks to be transferred and the records in + out counts; then they have their default action. SIGUSR1 causes the same information to be output yet the copy continues. All output caused by signals is sent to stderr.

EXIT STATUS

The exit status of sgm_dd is 0 when it is successful. Otherwise see the sg3_utils(8) man page. Since this utility works at a higher level than individual commands, and there are 'coe' and 'retries' flags, individual SCSI command failures do not necessary cause the process to exit.
