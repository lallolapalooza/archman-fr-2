NOM

sg_unmap - envoie la commande SCSI UNMAP (connue sous le nom de 'trim' dans les spécifications ATA)

SYNTAXE

sg_unmap [--all=ST,RN[,LA]] [--anchor] [--dry-run] [--force] [--grpnum=GN] [--help] [--in=FICHIER] [--lba=LBA,LBA...] [--num=NB,NB...] [--timeout=TO] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Envoie une commande SCSI UNMAP au PÉRIPHÉRIQUE pour désallouer un ou plusieurs blocs logiques. Cette commande a été introduite dans la révision 18 de SBC-3 sous le titre général de "provisioning de blocs logiques". Les blocs logiques peuvent également être désalloués par la commande SCSI WRITE SAME ; voir l'utilitaire sg_write_same. La capacité de désallocation est étroitement liée à la commande ATA DATA SET MANAGEMENT avec le bit "Trim" défini.

Les blocs logiques à désallouer peuvent être spécifiés de trois manières à cet utilitaire. Une façon est de fournir les LBA de départ à l'option '--lba=' et le nombre correspondant à désallouer à l'option '--num='. Une autre façon est de placer des paires de LBA de départ et de nombre à désallouer dans un fichier dont le nom est donné à l'option '--in='. Alternativement, un grand segment ou l'ensemble d'un disque (SSD) peut être désalloué avec l'option --all=ST_RN[,LA]. Toutes les valeurs sont supposées être décimales sauf si elles sont préfixées par "0x" (ou "0X") ou ont un suffixe "h" (ou "H") auquel cas elles sont interprétées comme hexadécimales. Des multiplicateurs de suffixe sont autorisés sur les valeurs décimales (par exemple, '--num=1m').

Lorsque l'option '--lba=' est donnée, l'option '--num=' doit également être donnée. Si l'une a une liste séparée par des virgules comme argument, l'autre doit avoir le même nombre d'éléments dans sa liste. Les arguments peuvent utiliser un espace simple comme séparateur mais doivent être entre guillemets ou échappés pour ne pas être mal interprétés par le shell.

Avec l'option '--in=FICHIER', un nombre pair de valeurs sera trouvé et interprété comme des paires : la première valeur de chaque paire est un LBA de départ et la seconde valeur est le nombre à désallouer à partir de ce LBA. Tout ce qui commence par et inclut un "#" sur une ligne est ignoré, tout comme les lignes vides. Les valeurs peuvent être séparées par des virgules, des espaces et des tabulations ou apparaître sur des lignes séparées. Chaque ligne ne doit pas dépasser 1023 octets.

Étant donné que beaucoup de données peuvent être perdues avec cet utilitaire, une période de "refroidissement" de 15 secondes est donnée avant que toute commande UNMAP ne soit envoyée. Pendant cette période, l'utilisateur est rappelé ce qui va se passer, et sur quel périphérique, afin qu'il puisse utiliser control-C (ou une autre technique) pour terminer cet utilitaire avant que toute désallocation n'ait lieu. Cette période peut être contournée avec l'option --force.

OPTIONS

Les arguments des options longues sont obligatoires, même pour les options courtes.

-A, --all=ST,RN[,LA]
où ST est le LBA de départ, RN est le nombre de répétitions, qui est le nombre maximum de blocs dans chaque commande SCSI UNMAP, et LA, s'il est donné, est le dernier LBA à désallouer. Si LA n'est pas donné, le dernier LBA du PÉRIPHÉRIQUE est utilisé. Ceci est obtenu par la commande SCSI READ CAPACITY.
-a, --anchor
définit le bit 'Anchor' dans la commande (introduit dans sbc3r22).
-d, --dry-run
effectue toute la préparation, y compris l'ouverture du PÉRIPHÉRIQUE ainsi que l'envoi d'une commande SCSI INQUIRY 'standard' (et éventuellement une READ CAPACITY), mais sort avant d'effectuer toute commande SCSI UNMAP.
-f, --force
contourne la période d'avertissement de 15 secondes qui précède l'envoi de commandes UNMAP.
-g, --grpnum=GN
définit le champ 'Group number' à GN. La valeur par défaut est zéro. GN doit être une valeur comprise entre 0 et 63.
-h, --help
affiche le message d'utilisation puis quitte.
-I, --in=FICHIER
où FICHIER est un nom de fichier contenant des paires de valeurs. Le premier membre de chaque paire est un LBA de départ et le second membre de la paire est le nombre de blocs logiques à désallouer à partir de ce LBA de départ inclus. Les valeurs sont interprétées comme décimales sauf indication contraire. Cette option ne peut pas être présente avec l'option '--lba='.
-l, --lba=LBA,LBA...
où LBA,LBA... est une chaîne de valeurs séparées par des virgules (ou des espaces) qui sont interprétées comme des adresses de blocs logiques de départ. Chaque nombre est interprété comme décimal sauf s'il est préfixé par '0x' ou '0X' (ou s'il a un 'h' ou 'H' en suffixe). Un argument contenant des séparateurs d'espaces doit être mis entre guillemets (ou autrement échappé). Lorsque cette option est donnée, l'option '--num=' doit également être donnée et elles doivent contenir le même nombre d'éléments dans leurs arguments.
-n, --num=NB,NB...
où NB,NB... est une chaîne de valeurs séparées par des virgules (ou des espaces) qui sont interprétées comme un nombre de blocs logiques à désallouer. Chaque nombre est interprété comme décimal sauf s'il est préfixé par '0x' ou '0X' (ou s'il a un 'h' ou 'H' en suffixe). Notez que 0 bloc est acceptable. Un argument contenant des séparateurs d'espaces doit être mis entre guillemets (ou autrement échappé). Lorsque cette option est donnée, l'option '--lba=' doit également être donnée et elles doivent contenir le même nombre d'éléments dans leurs arguments.
-t, --timeout=TO
où TO est une valeur de délai d'attente (en secondes) pour la commande UNMAP. La valeur par défaut est de 60 secondes.
-v, --verbose
augmente le niveau de verbosité, (c'est-à-dire les sorties de débogage).
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Quelques limites : un LBA peut faire jusqu'à 64 bits, un NUM jusqu'à 32 bits (imposé par la structure des données de paramètres de la commande UNMAP SCSI). Le NUM est en outre contraint par le champ MAXIMUM UNMAP LBA COUNT de la page VPD BLOCK LIMITS (0xb0). Le nombre maximum de paires LBA,NUM est limité à 128 par cet utilitaire et peut être davantage contraint par le champ MAXIMUM UNMAP BLOCK DESCRIPTOR COUNT de la page VPD BLOCK LIMITS.

Comme il n'est pas clair combien de temps la commande UNMAP prendra pour s'exécuter, une option '--timeout=' a été fournie. La période de délai d'attente par défaut est de 60 secondes. Si tous les blocs logiques d'une unité logique (par exemple, un disque dur) doivent être désalloués, la commande FORMAT UNIT SCSI (voir l'utilitaire sg_format) peut être envisagée comme alternative.

Le support du provisionnement de blocs logiques est indiqué par le bit LBPME dans la réponse à la commande SCSI READ CAPACITY (16) (voir l'utilitaire sg_readcap).

Dans la révision 25 de SBC-3, les bits LBPU et ANC_SUP ont été ajoutés à la page VPD Logical Block Provisioning. Lorsque LBPU est défini, cela indique que le périphérique supporte la commande UNMAP. Lorsque le bit ANC_SUP est défini, cela indique que le périphérique supporte les LBA ancrés.

La commande SCSI UNMAP fait la "bonne chose" concernant la mise en file d'attente des commandes. Cependant, son homologue ATA : la commande DATA SET MANAGEMENT avec le bit "Trim" défini n'interagit pas bien avec la mise en file d'attente SATA connue sous le nom de NCQ. Pour résoudre ce problème, T13 a introduit une nouvelle commande appelée SFQ DATA SET MANAGEMENT qui a également un bit Trim.

EXEMPLES

Dans le répertoire examples du paquet sg3_utils, il y a un fichier sg_unmap_example.txt qui montre le format accepté par l'option '--in='.

Pour désallouer tous les blocs à partir du LBA 0x2000 inclus jusqu'à la fin du périphérique (par exemple, disque dur ou SSD), avec chaque commande SCSI UNMAP recevant 1024 blocs à désallouer :


sg_unmap --all=0x2000,1k /dev/sg2

Ajoutez '--force' pour contourner les 15 secondes d'avertissements. Donc '--force' est approprié pour les fichiers batch.

STATUT DE SORTIE

Le statut de sortie de sg_unmap est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8).
