NOM

sg_copy_results - envoie la commande SCSI RECEIVE COPY RESULTS (liée à XCOPY)

SYNTAXE

sg_copy_results [--failed|--params|--receive|--status] [--help] [--hex] [--list_id=ID] [--readonly] [--verbose] [--version] [--xfer_len=BTL] DEVICE

DESCRIPTION

Cet utilitaire est conçu pour interroger le statut de la facilité SCSI Extended Copy (XCOPY) (voir SPC-3 révision 23 sections 6.3 et 6.17), présente dans certains tableaux de stockage modernes. Cet utilitaire envoie une commande SCSI RECEIVE COPY RESULTS au DEVICE donné et affiche la réponse.

Pendant les phases de brouillon de SPC-4, le comité T10 a étendu la commande XCOPY de sorte qu'elle ait maintenant deux variantes : "LID1" (pour une longueur d'identifiant de liste de 1 octet) et "LID4" (pour une longueur d'identifiant de liste de 4 octets). Cet utilitaire supporte l'ancienne variante LID1, également trouvée dans SPC-3 et les versions antérieures. Bien que la variante LID1 dans SPC-4 soit compatible au niveau de la commande (binaire) avec XCOPY tel que défini dans SPC-3, certains noms de commandes ont changé. Cet utilitaire utilise les anciens noms XCOPY de SPC-3.

La commande a quatre modes de fonctionnement distincts, distingués par le champ d'action de service :

COPY STATUS [SPC-4: RECEIVE COPY STATUS(LID1)]
Affiche le statut actuel de la commande EXTENDED COPY identifiée par le champ d'identifiant de liste.
RECEIVE DATA [SPC-4: RECEIVE COPY DATA(LID1)]
Retourne les données conservées lues par la commande EXTENDED COPY identifiée par le champ d'identifiant de liste. Cette option n'est significative que si les descripteurs de segment respectifs sont supportés.
OPERATING PARAMETERS [SPC-4: RECEIVE COPY OPERATING PARAMETERS]
Retourne les paramètres de fonctionnement du gestionnaire de copie. Cette option est également utile pour déterminer si la facilité SCSI Extended Copy est supportée.
FAILED SEGMENT DETAILS [SPC-4: RECEIVE COPY FAILURE DETAILS(LID1)]
Retourne les données de sense du périphérique cible de copie et d'autres informations sur les segments échoués.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-f, --failed
définit le champ d'action de service à FAILED SEGMENT DETAILS [4].
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche le tampon de réponse en hexadécimal.
-l, --list_id=ID
définit le champ d'identifiant de liste à ID (par défaut : 0).
-p, --params
définit le champ d'action de service à OPERATING PARAMETERS [3]. C'est le défaut.
-R, --readonly
ouvre le DEVICE en lecture seule (par exemple, sous Unix avec le flag O_RDONLY). Le défaut est de l'ouvrir en lecture-écriture.
-r, --receive
définit le champ d'action de service à RECEIVE DATA [1].
-s, --status
définit le champ d'action de service à COPY STATUS [0].
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-x, --xfer_len=BTL
définit le champ de longueur d'allocation à BTL. C'est la longueur de transfert en octets et c'est la taille maximale (en octets) de la réponse. BTL doit être inférieur à 10000 et vaut par défaut 520.

NOTES

Le décodage de l'action de service RECEIVE DATA n'est pas implémenté.

De manière similaire, la fonctionnalité de sg_xcopy a été portée vers l'utilitaire plus général ddpt (et le paquet), la fonctionnalité de cet utilitaire a été portée vers l'utilitaire ddptctl.

EXEMPLES

Interroger les paramètres de fonctionnement d'un périphérique :

# sg_copy_results -p /dev/sdo

Maximum segment descriptor count: 1

Inline data not supported

Maximum stream device transfer size: 0 bytes
Total concurrent copies: 0

Inline data granularity: 1 bytes
Held data granularity: 1 bytes

Segment descriptor 0x02: Copy from block device to block device
Target descriptor 0xe4: Identification descriptor

STATUT DE SORTIE

Le statut de sortie de sg_copy_results est 0 en cas de succès. Sinon, voir la page man sg3_utils(8).
