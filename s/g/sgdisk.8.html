SGDISK(8) Manuel GPT fdisk SGDISK(8)

NOM

sgdisk - Manipulateur de table de partition GUID (GPT) en ligne de commande pour Linux et Unix

SYNTAXE

sgdisk [ options ] périphérique

DESCRIPTION

GPT fdisk est un ensemble de programmes en mode texte, à base de menus, pour la création et la manipulation des tables de partitions. Il se compose de deux programmes : gdisk en mode interactif et sgdisk en ligne de commande. L'un ou l'autre de ces programmes convertira automatiquement une table de partitions MBR (Master Boot Record) ancienne ou un label de disque BSD stocké sans partition porteuse MBR au nouveau format GPT (GUID Partition Table), ou chargera une table de partitions GUID. Cette page de manuel documente le programme en ligne de commande sgdisk.

Certaines options avancées de manipulation de données et de récupération nécessitent que vous compreniez les distinctions entre les données principales et de sauvegarde, ainsi qu'entre les en-têtes GPT et les tables de partitions. Pour des informations sur MBR vs GPT, ainsi que sur la terminologie et la structure GPT, consultez la documentation étendue de gdisk sur https://www.rodsbooks.com/gdisk/ ou consultez Wikipédia.

Le programme sgdisk utilise une interface utilisateur basée entièrement sur la ligne de commande, ce qui le rend adapté à une utilisation dans des scripts ou par des experts souhaitant apporter un ou deux changements rapides à un disque. (Le programme peut interroger l'utilisateur lors de certaines erreurs, cependant.) Le nom du programme est basé sur sfdisk, mais les options utilisateur des deux programmes sont entièrement différentes.

Normalement, sgdisk opère sur des fichiers de périphériques de disque, tels que /dev/sda ou /dev/hda sous Linux, /dev/disk0 sous Mac OS X, ou /dev/ad0 ou /dev/da0 sous FreeBSD. Le programme peut également opérer sur des fichiers image de disque, qui peuvent être soit des copies de disques entiers (créés avec dd, par exemple) soit des images de disque brutes utilisées par des émulateurs comme QEMU ou VMWare. Notez que seules les images de disque brutes sont supportées ; sgdisk ne peut pas travailler sur des formats d'images de disque compressés ou d'autres formats avancés.

Le système de partitionnement MBR utilise une combinaison d'adressage cylindre/tête/secteur (CHS) et d'adressage par blocs logiques (LBA). Le premier est maladroit et limitatif. GPT abandonne l'adressage CHS et utilise exclusivement le mode LBA 64 bits. Ainsi, les structures de données GPT, et donc sgdisk, n'ont pas besoin de traiter les géométries CHS et tous les problèmes qu'elles créent.

Pour de meilleurs résultats, vous devriez utiliser un programme de table de partition spécifique au système d'exploitation chaque fois que possible. Par exemple, vous devriez créer des partitions Mac OS X avec le programme Utilitaire de disque de Mac OS X et des partitions Linux avec les programmes gdisk, sgdisk ou GNU Parted de Linux.

Au démarrage, sgdisk tente d'identifier le type de partition utilisé sur le disque. S'il trouve des données GPT valides, sgdisk les utilise. S'il trouve un MBR ou un label de disque BSD valide mais aucune donnée GPT, il tente de convertir le MBR ou le label de disque en format GPT. (Les labels de disque BSD risquent d'avoir des partitions inutilisables au début et/ou à la fin car elles chevauchent les structures de données GPT, cependant.) GPT fdisk peut identifier, mais pas utiliser, les données des disques à carte de partition Apple (APM), utilisés sur les Macintosh basés sur 680x0 et PowerPC. Si vous spécifiez une option qui entraîne des modifications sur un MBR ou un label de disque BSD, sgdisk ignore ces modifications à moins que l'option -g (--mbrtogpt), -z (--zap), ou -Z (--zap-all) ne soit utilisée. Si vous utilisez l'option -g, sgdisk remplace le MBR ou le label de disque par une GPT. Cette action est potentiellement dangereuse ! Votre système peut devenir non amorçable, et les codes de type de partition peuvent être corrompus si le disque utilise des codes de type non reconnus. Des problèmes de démarrage sont particulièrement probables si vous utilisez le multi-amorçage avec un système d'exploitation qui n'est pas compatible GPT.

La conversion MBR vers GPT laissera au moins un espace dans la numérotation des partitions si le MBR d'origine utilisait des partitions logiques. Ces espaces sont inoffensifs, mais vous pouvez les éliminer en utilisant l'option -s (--sort), si vous le souhaitez. (Cela peut nécessiter la mise à jour de votre fichier /etc/fstab.)

Lors de la création d'une table de partitions vierge, certaines considérations peuvent être appropriées :

*
Pour les disques de données (non amorçables) et pour les disques d'amorçage utilisés sur les ordinateurs basés sur BIOS avec GRUB comme chargeur d'amorçage, les partitions peuvent être créées dans n'importe quel ordre et dans n'importe quelle taille souhaitée.
*
Les disques d'amorçage pour les systèmes basés sur EFI nécessitent une partition système EFI (code interne gdisk 0xEF00) formatée en FAT-32. Je recommande de créer cette partition de 550 Mio. (Des ESP plus petits sont courants, mais certains EFI ont des pilotes FAT capricieux qui nécessitent une partition plus grande pour un fonctionnement fiable.) Les fichiers liés à l'amorçage sont stockés ici. (Notez que GNU Parted identifie de telles partitions comme ayant le "flag d'amorçage" activé.)
*
Certains chargeurs d'amorçage pour systèmes basés sur BIOS utilisent une partition d'amorçage BIOS (code interne gdisk 0xEF02), dans laquelle le chargeur d'amorçage secondaire est stocké, potentiellement sans système de fichiers. (GRUB2 peut utiliser optionnellement une telle partition.) Cette partition peut généralement être assez petite (environ 32 à 200 Kio, bien que 1 Mio soit plus courant en pratique), mais vous devriez consulter la documentation de votre chargeur d'amorçage pour plus de détails.
*
Si Windows doit démarrer à partir d'un disque GPT, une partition de type Réservé Microsoft (code interne sgdisk 0x0C01) est recommandée. Cette partition devrait faire environ 128 Mio. Elle suit généralement la partition système EFI et précède immédiatement les partitions de données Windows. (Notez que GNU Parted crée toutes les partitions FAT avec ce type, ce qui rend effectivement la partition inutilisable pour le stockage de fichiers normal sous Windows et Mac OS X.)
*
Certains utilitaires GPT d'OS créent un espace vide (généralement 128 Mio) après chaque partition. L'intention est de permettre aux futures utilitaires de disque d'utiliser cet espace. Un tel espace libre n'est pas requis pour les disques GPT, mais sa création peut aider à la maintenance future du disque.

OPTIONS

Certaines options ne prennent pas d'arguments, d'autres prennent un argument (typiquement un numéro de partition), et d'autres prennent des arguments composés délimités par des deux-points. Par exemple, -n (--new) prend un numéro de partition, un secteur de début et un secteur de fin, comme dans sgdisk -n 2:2000:50000 /dev/sdc, qui crée une nouvelle partition, numérotée 2, commençant au secteur 2000 et se terminant au secteur 50 000, sur /dev/sdc.

Les options non liées peuvent être combinées ; cependant, certaines de ces combinaisons seront absurdes (comme supprimer une partition puis changer son code de type GUID). sgdisk interprète les options dans l'ordre où elles sont saisies, donc les effets peuvent varier en fonction de l'ordre. Par exemple, sgdisk -s -d 2 trie les entrées de la table de partitions puis supprime la partition 2 de la liste nouvellement triée ; mais sgdisk -d 2 -s supprime la partition 2 d'origine puis trie la table de partitions modifiée.

La vérification des erreurs et les opportunités de corriger les erreurs dans sgdisk sont minimales. Bien que le programme s'efforce de maintenir la légalité des structures de données GPT, il ne demande pas de vérification avant d'effectuer ses actions. À moins que vous n'ayez besoin d'un programme piloté par ligne de commande, vous devriez utiliser le programme interactif gdisk à la place de sgdisk, car gdisk vous permet de quitter sans sauvegarder vos modifications, si vous faites une erreur.

Bien que sgdisk soit basé sur le même code de manipulation de partitions que gdisk, sgdisk implémente moins de fonctionnalités que son frère interactif. Les options disponibles dans sgdisk sont :

-a, --set-alignment=valeur
Définit le multiple d'alignement des secteurs. GPT fdisk aligne le début des partitions sur des secteurs qui sont des multiples de cette valeur, qui par défaut est de 1 Mio (2048 sur les disques avec des secteurs de 512 octets) sur les disques fraîchement formatés. Cette valeur d'alignement est nécessaire pour obtenir des performances optimales avec les disques Western Digital Advanced Format et similaires ayant des secteurs physiques plus grands que les secteurs logiques, avec certains types de réseaux RAID et avec les périphériques SSD. Lorsque l'option -I est utilisée, cette même valeur d'alignement est utilisée pour déterminer les points de fin des partitions ; mais les partitions se terminent à un secteur moins qu'un multiple de cette valeur, afin de maintenir la longueur de la partition comme un multiple de cette valeur.
-A, --attributes=liste|[num_part:afficher|ou|etpas|ou=|definir|effacer|basculer|obtenir[:num_bit|masque_hexadécimal_bit]]
Affiche ou définit les attributs de partition. Utilisez liste pour voir les valeurs d'attribut définies (connues). Omettre le numéro de partition
lors de l'utilisation de cette option. Les autres nécessitent un numéro de partition. Les options show et get affichent les paramètres d'attributs actuels (tous les attributs ou pour un bit particulier, respectivement). Les options or, nand, xor, =, set, clear et toggle vous permettent de modifier la valeur du bit d'attribut. Les options set, clear, toggle et get fonctionnent sur un numéro de bit ; les autres fonctionnent sur un masque de bits hexadécimal. Par exemple, tapez sgdisk -A 4:set:2 /dev/sdc pour définir le bit d'attribut 2 (démarrable par BIOS hérité) sur la partition 4 de /dev/sdc.
-b, --backup=fichier
Enregistre les données de partition dans un fichier de sauvegarde. Vous pouvez sauvegarder votre table de partitions actuelle en mémoire dans un fichier disque en utilisant cette option. Le fichier résultant est un fichier binaire composé du MBR protecteur, de l'en-tête GPT principal, de l'en-tête GPT de sauvegarde et d'une copie de la table de partitions, dans cet ordre. Notez que la sauvegarde concerne les structures de données actuelles en mémoire, donc si vous lancez le programme, apportez des modifications, puis utilisez cette option, la sauvegarde reflétera vos modifications. Si les structures de données GPT sont endommagées, la sauvegarde peut ne pas refléter fidèlement l'état endommagé ; au lieu de cela, elles refléteront l'interprétation de GPT fdisk de la GPT lors de la première passe.
-B, --byte-swap-name=numpart
Inverse l'ordre des octets pour le nom de la partition spécifiée. Certains outils de partitionnement, y compris GPT fdisk 1.0.7 et versions antérieures, peuvent écrire le nom de la partition dans le mauvais ordre d'octets sur des ordinateurs big-endian, tels que les mainframes IBM s390 et les Mac basés sur PowerPC. Cette fonctionnalité corrige ce problème.
-c, --change-name=numpart:nom
Modifie le nom GPT d'une partition. Ce nom est codé sous forme de chaîne UTF-16, mais une entrée et un affichage corrects de tout ce qui va au-delà des valeurs ASCII de base nécessitent un locale et un support de police appropriés. Dans la plupart des cas, Linux ignore le nom de la partition, mais cela peut être important dans certains systèmes d'exploitation. Si vous souhaitez définir un nom contenant un espace, entourez-le de guillemets, comme dans sgdisk -c 1:"Nom d'exemple" /dev/sdb. Notez que le nom GPT d'une partition est distinct du nom du système de fichiers, qui est codé dans les structures de données du système de fichiers.
-C, --recompute-chs
Recalcule les valeurs CHS dans le MBR protecteur ou hybride. Cette option peut parfois aider si un utilitaire de disque, un système d'exploitation ou un BIOS n'aime pas les valeurs CHS utilisées par les partitions dans le MBR protecteur ou hybride. En particulier, la spécification GPT exige une valeur CHS de 0xFFFFFF pour les partitions de plus de 8 Gio, mais cette valeur est techniquement illégale selon les normes habituelles. Certains BIOS se bloquent lorsqu'ils rencontrent cette valeur. Cette option recalculera une valeur CHS plus normale -- 0xFEFFFF pour les partitions de plus de 8 Gio, permettant à ces BIOS de démarrer.
-d, --delete=numpart
Supprime une partition. Cette action supprime l'entrée de la table de partitions mais ne perturbe pas les données dans les secteurs initialement alloués à la partition sur le disque. Si une partition MBR hybride correspondante existe, gdisk la supprime également, et étend toute partition MBR protectrice 0xEE (EFI GPT) adjacente pour occuper le nouvel espace libre.
-D, --display-alignment
Affiche la valeur d'alignement de secteur actuelle. Les partitions seront créées sur des multiples de la valeur de secteur rapportée par cette option. Vous pouvez modifier la valeur d'alignement avec l'option -a.
-e, --move-second-header
Déplace les structures de données GPT de sauvegarde à la fin du disque. Utilisez cette option si vous avez ajouté des disques à un tableau RAID, créant ainsi un disque virtuel avec de l'espace qui suit les structures de données GPT de sauvegarde. Cette commande déplace les structures de données GPT de sauvegarde à la fin du disque, où elles doivent être.
-E, --end-of-largest
Affiche le numéro du secteur de fin du plus grand bloc de secteurs disponibles sur le disque. Un script peut stocker cette valeur et la renvoyer dans le cadre de l'option -n pour créer une partition. Si aucun secteur non alloué n'est disponible, cette fonction renvoie la valeur 0.
-f, --first-in-largest
Affiche le numéro du secteur de début du plus grand bloc de secteurs disponibles sur le disque. Un script peut stocker cette valeur et la renvoyer dans le cadre de l'option -n pour créer une partition. Si aucun secteur non alloué n'est disponible, cette fonction renvoie la valeur 0. Notez que ce paramètre ne tient pas compte de l'alignement des partitions ; lorsque vous créez effectivement une partition, son point de départ peut être modifié par rapport à cette valeur.
-F, --first-aligned-in-largest
Similaire à -f (--first-in-largest), sauf qu'il renvoie le numéro de secteur avec la correction d'alignement actuelle appliquée. Utilisez cette fonction si vous avez besoin de calculer le point de départ réel de la partition plutôt qu'un point de départ théorique ou le point de départ réel si vous avez défini la valeur d'alignement sur 1.
-g, --mbrtogpt
Convertit un disque MBR ou une étiquette de disque BSD en disque GPT. Par mesure de sécurité, l'utilisation de cette option est requise sur les disques MBR ou étiquettes de disque BSD si vous avez l'intention d'enregistrer vos modifications, afin d'éviter d'endommager accidentellement de tels disques.
-G, --randomize-guids
Randomise le GUID du disque et tous les GUID uniques des partitions (mais pas leurs GUID de code de type de partition). Cette fonction peut être utilisée après le clonage d'un disque afin de rendre tous les GUID à nouveau uniques.
-h, --hybrid
Crée un MBR hybride. Cette option prend un à trois numéros de partition, séparés par des deux-points, comme arguments. Vous pouvez éventuellement spécifier une partition finale "EE" pour indiquer que le GPT EFI (type 0xEE) doit être placé en dernier dans la table, sinon il sera placé en premier, suivi des partitions que vous spécifiez. Leurs codes de type sont basés sur les codes de type GPT fdisk divisés par 0x0100, ce qui est généralement correct pour les partitions Windows. Si le drapeau actif/démarrable doit être défini, vous devez le faire dans un autre programme, tel que fdisk. Le programme gdisk offre des options de création de MBR hybride supplémentaires.
-i, --info=numpart
Affiche des informations détaillées sur la partition. Les informations récapitulatives produites par la commande -p omettent nécessairement de nombreux détails, tels que le GUID unique de la partition et la traduction du code de type de partition interne de sgdisk en un nom de type simple. L'option -i affiche ces informations pour une seule partition.
-I, --align-end
Lorsque cela est possible, aligne les points de fin des partitions sur un multiple moins un de la valeur d'alignement. Lorsque les points de début et de fin sont alignés, les partitions doivent être des multiples de la valeur d'alignement en taille, ce qui est nécessaire pour que certains outils de chiffrement de partition fonctionnent correctement. Cette option s'applique à toutes les partitions créées après cette option sur la ligne de commande. Notez que cet alignement n'est pas toujours possible ; par exemple, si l'espace libre à la fin d'un disque est inférieur à la valeur d'alignement, avec la dernière partition actuelle alignée, et si sgdisk est invité à créer une partition dans cet espace, alors elle ne sera pas alignée en fin.
-j, --move-main-table=secteur
Définit le secteur de début de la table de partitions principale. Cette valeur est normalement 2, mais elle peut devoir être augmentée dans certains cas, par exemple lorsqu'un système sur puce (SoC) est codé en dur pour lire le code de démarrage à partir du secteur 2. Je déconseille de modifier cette valeur, sauf si cela est absolument nécessaire.
-k, --move-backup-table=secteur
Définit le secteur de début de la table de partitions secondaire/de sauvegarde. La table de sauvegarde est généralement placée juste avant le dernier secteur, qui contient l'en-tête de sauvegarde. La valeur par défaut est donc la taille du disque, moins un, moins la taille totale de la table de partitions (en secteurs, généralement 32). Il y a probablement très peu de raisons de changer cela, et bien que la norme EFI ne l'impose pas, la plupart des outils supposent que la table de sauvegarde se trouve tout à la fin du disque.
-l, --load-backup=fichier
Charge les données de partition à partir d'un fichier de sauvegarde. Cette option est l'inverse de l'option -b. Notez qu'il n'est pas recommandé de restaurer des données de partition à partir d'autre chose que du disque d'origine. Cette option fonctionnera même si la table de partitions d'origine du disque est corrompue ; cependant, la plupart des autres options sur la même ligne de commande seront ignorées.
-L, --list-types
Affiche un résumé des types de partitions. GPT utilise un GUID pour identifier les types de partitions pour des systèmes d'exploitation et des usages particuliers. Pour faciliter la saisie des données, sgdisk les compresse en valeurs sur deux octets (hexadécimal à quatre chiffres) qui sont liées à leurs codes MBR équivalents. Plus précisément, le code MBR est multiplié par 0x0100 hexadécimal. Par exemple, le code pour l'espace d'échange Linux en MBR est 0x82, et il est 0x8200 dans gdisk. Cependant, une correspondance univoque est impossible. Plus particulièrement, les codes de toutes les variétés de partitions FAT et NTFS correspondent à un seul code GPT (entré comme 0x0700 dans sgdisk). Certains systèmes d'exploitation utilisent un seul code MBR mais emploient beaucoup plus de codes dans GPT. Pour ceux-ci, sgdisk ajoute des numéros de code séquentiellement, tels que 0xa500 pour une étiquette de disque FreeBSD, 0xa501 pour le démarrage FreeBSD, 0xa502 pour l'échange FreeBSD, etc. Notez que ces codes sur deux octets sont propres à gdisk et sgdisk. Cette option ne nécessite pas de spécifier un nom de fichier de périphérique disque valide.
-m, --gpttombr
Convertit un disque de GPT en MBR. Cette option prend un à quatre numéros de partition, séparés par des deux-points, comme arguments. Leurs codes de type sont basés sur les codes de type GPT fdisk divisés par 0x0100. Si le drapeau actif/démarrable doit être défini, vous devez le faire dans un autre programme, tel que fdisk. Le programme gdisk offre des options de conversion MBR supplémentaires. Il n'est pas possible de convertir plus de quatre partitions de GPT en MBR ou de convertir des partitions qui commencent au-dessus de la marque des 2 Tio ou qui sont plus grandes que 2 Tio.
-n, --new=numpart:debut:fin
Crée une nouvelle partition. Vous entrez un numéro de partition, un secteur de début et un secteur de fin.
sector. Les deux secteurs de début et de fin peuvent être spécifiés en termes absolus comme numéros de secteur ou comme positions mesurées en kibioctets (K), mébioctets (M), gibioctets (G), tébioctets (T) ou pébioctets (P) ; par exemple, 40M spécifie une position à 40 Mio depuis le début du disque. Vous pouvez spécifier des emplacements relatifs au début ou à la fin de la plage par défaut spécifiée en faisant précéder le nombre d'un symbole '+' ou '-' , comme dans +2G pour spécifier un point 2 Gio après le secteur de départ par défaut, ou -200M pour spécifier un point 200 Mio avant le dernier secteur disponible. Une valeur de début ou de fin de 0 spécifie la valeur par défaut, qui est le début du plus grand bloc disponible pour le secteur de début et la fin du même bloc pour le secteur de fin. Une valeur partnum de 0 fait que le programme utilise le premier numéro de partition disponible. Les utilisations ultérieures des options -A (--attributes), -c (--change-name), -t (--typecode) et -u (--partition-guid) peuvent également utiliser 0 pour faire référence à la même partition.
-N, --largest-new=num
Crée une nouvelle partition qui remplit le plus grand bloc d'espace disponible sur le disque. Vous pouvez utiliser l'option -a (--set-alignment) pour ajuster l'alignement, si vous le souhaitez. Une valeur num de 0 fait que le programme utilise le premier numéro de partition disponible. Les utilisations ultérieures des options -A (--attributes), -c (--change-name), -t (--typecode) et -u (--partition-guid) peuvent également utiliser 0 pour faire référence à la même partition.
-o, --clear
Efface toutes les données de partition. Cela inclut les données d'en-tête GPT, toutes les définitions de partition et le MBR protecteur. Notez que cette opération échouera, comme la plupart des autres opérations, sur un disque endommagé. Si vous souhaitez préparer un disque que vous savez endommagé pour une utilisation GPT, vous devez d'abord le nettoyer avec -Z puis le partitionner normalement. Cette option fonctionnera même si la table de partitions d'origine du disque est corrompue ; cependant, la plupart des autres options sur la même ligne de commande seront ignorées.
-O, --print-mbr
Affiche des données récapitulatives basiques de partitions MBR. Cela inclut les numéros de partition, les numéros de secteur de début et de fin, les tailles de partition, les codes de type de partition MBR et les noms de partition. Cette option est utile principalement pour diagnostiquer des problèmes de table de partitions, en particulier sur les disques avec des MBR hybrides.
-p, --print
Affiche des données récapitulatives basiques de partitions GPT. Cela inclut les numéros de partition, les numéros de secteur de début et de fin, les tailles de partition, les codes de type de partition de sgdisk et les noms de partition. Pour des informations supplémentaires, utilisez l'option -i (--info).
-P, --pretend
Fait semblant d'apporter les modifications spécifiées. Les structures de données GPT en mémoire sont modifiées conformément aux autres paramètres, mais les modifications ne sont pas écrites sur le disque.
-r, --transpose
Échange les entrées de deux partitions dans la table de partitions. Une ou les deux partitions peuvent être vides, bien que l'échange de deux partitions vides soit inutile. Par exemple, si les partitions 1 à 4 sont définies, l'échange de 1 et 5 donne une table avec des partitions numérotées de 2 à 5. L'échange de partitions de cette manière n'a aucun effet sur leur allocation d'espace disque ; il modifie uniquement leur ordre dans la table de partitions.
-R, --replicate=second_device_filename
Réplique la table de partitions du périphérique principal sur le second périphérique spécifié. Notez que la table de partitions répliquée est une copie exacte, y compris tous les GUID ; si le périphérique doit avoir ses propres GUID uniques, vous devez utiliser l'option -G sur le nouveau disque.
-s, --sort
Trie les entrées de partition. Les numéros de partition GPT n'ont pas besoin de correspondre à l'ordre des partitions sur le disque. Si vous souhaitez qu'ils correspondent, vous pouvez utiliser cette option. Notez que certains utilitaires de partitionnement trient les partitions chaque fois qu'ils effectuent des modifications. Ces modifications seront reflétées dans vos noms de périphériques, vous devrez donc peut-être modifier /etc/fstab si vous utilisez cette option.
-t, --typecode=partnum:{hexcode|GUID}
Change le code de type d'une seule partition. Vous entrez le code de type en utilisant soit un nombre hexadécimal de deux octets, comme décrit précédemment, soit une valeur GUID entièrement spécifiée, telle que EBD0A0A2-B9E5-4433-87C0-68B6B72699C7.
-T, --transform-bsd=partnum
Transforme les partitions BSD en partitions GPT. Cette option fonctionne sur les disklabels BSD contenus dans des partitions GPT (ou MBR converties). Les codes de type des partitions converties devront probablement être ajustés manuellement. sgdisk tentera de convertir les disklabels BSD stockés sur le disque principal lors du lancement, mais cette conversion produira probablement des partitions première et/ou dernière inutilisables. Les nombreuses variantes BSD signifient que la probabilité que sgdisk ne parvienne pas à convertir un disklabe BSD est élevée par rapport à la probabilité de problèmes avec une conversion MBR.
-u, --partition-guid=partnum:guid
Définit le GUID unique de partition pour une partition individuelle. Le GUID peut être un GUID complet ou 'R' pour définir un GUID aléatoire.
-U, --disk-guid=guid
Définit le GUID du disque. Le GUID peut être un GUID complet ou 'R' pour définir un GUID aléatoire.
--usage
Affiche un bref résumé des options disponibles.
-v, --verify
Vérifie le disque. Cette option recherche une variété de problèmes, tels que des CRC incorrects et des données principales et de sauvegarde non concordantes. Cette option ne corrige pas automatiquement la plupart des problèmes ; pour cela, vous devez utiliser les options du menu de récupération et de transformation. Si aucun problème n'est trouvé, cette commande affiche un résumé de l'espace disque non alloué. Cette option fonctionnera même si la table de partitions d'origine du disque est corrompue ; cependant, la plupart des autres options sur la même ligne de commande seront ignorées.
-V, --version
Affiche les informations de version du programme. Cette option peut être utilisée sans spécifier de nom de fichier de périphérique.
-z, --zap
Supprime (détruit) les structures de données GPT puis quitte. Utilisez cette option si vous souhaitez repartitionner un disque GPT à l'aide de fdisk ou d'un autre programme ne connaissant pas GPT. Cette option détruit uniquement les structures de données GPT ; elle laisse le MBR intact. Ceci le rend utile pour effacer les structures de données GPT après qu'un disque a été repartitionné pour MBR à l'aide d'un utilitaire ne connaissant pas GPT ; cependant, il y a un risque qu'il endommage les chargeurs de démarrage ou même le début de la première ou la fin de la dernière partition MBR. Si vous l'utilisez sur un disque GPT valide, le MBR restera avec une définition de partition inappropriée EFI GPT (0xEE), que vous pourrez supprimer à l'aide d'un autre utilitaire.
-Z, --zap-all
Supprime (détruit) les structures de données GPT et MBR puis quitte. Cette option fonctionne de manière similaire à -z, mais comme elle efface le MBR ainsi que le GPT, elle est plus adaptée si vous souhaitez repartitionner un disque après avoir utilisé cette option, et totalement inadaptée si vous avez déjà repartitionné le disque.
-?, --help
Affiche un résumé des options.

BOGUES

Les bogues et limitations connus incluent :

*
Le programme ne compile correctement que sous Linux, FreeBSD et Mac OS X. Les versions Linux pour x86-64 (64 bits), x86 (32 bits) et PowerPC (32 bits) ont été testées, la version x86-64 ayant reçu le plus de tests.
*
La version FreeBSD du programme ne peut pas écrire les modifications de la table de partitions sur un disque lorsque des partitions existantes sur ce disque sont montées. (Le même problème existe avec de nombreux autres utilitaires FreeBSD, tels que gpt, fdisk et dd.) Cette limitation peut être contournée en tapant sysctl kern.geom.debugflags=16 à l'invite d'un shell.
*
Les champs utilisés pour afficher les numéros de secteur de début et de fin des partitions dans l'option -p ont une largeur de 14 caractères. Cela correspond à une limitation d'environ 45 PiB. Sur des disques plus grands, les colonnes affichées seront désalignées.
*
Le programme ne peut charger que jusqu'à 128 partitions (4 partitions primaires et 124 partitions logiques) lors de la conversion à partir du format MBR. Cette limite peut être augmentée en modifiant la ligne #define MAX_MBR_PARTS dans le fichier source basicmbr.h et en recompilant ; cependant, un tel changement nécessitera l'utilisation d'une table de partitions plus grande que la normale. (La limite de 128 partitions a été choisie car ce nombre est égal aux 128 partitions prises en charge par la taille de table de partitions la plus courante.)
*
La conversion à partir du format MBR échoue parfois en raison d'un espace insuffisant au début ou (plus couramment) à la fin du disque. Redimensionner la table de partitions (en utilisant l'option 's' dans le menu expert) peut parfois résoudre ce problème ; cependant, dans des cas extrêmes, il peut être nécessaire de redimensionner une partition à l'aide de GNU Parted ou d'un outil similaire avant la conversion avec gdisk.
*
Les conversions MBR ne fonctionnent que si le disque possède des descripteurs de partition LBA corrects. Ces descripteurs devraient être présents sur tout disque de plus de 8 Gio ou sur des disques plus petits partitionnés avec un logiciel autre que très ancien.
*
Le support des disklabels BSD peut créer des partitions première et/ou dernière qui chevauchent les structures de données GPT. Cela peut parfois être compensé en ajustant la taille de la table de partitions, mais dans des cas extrêmes, l'affectation

BUGS

*
Les partitions existantes sont conservées lors de la conversion d'un disque MBR ou BSD disklabel. Toutefois, il est possible que la table de partitions résultante ne contienne pas suffisamment d'espace libre pour toutes les partitions de l'ancien format. Dans ce cas, des partitions pourraient être supprimées.
*
En raison de la nature très variable des structures BSD disklabel, les conversions à partir de ce format peuvent être peu fiables -- les partitions peuvent être supprimées, converties de manière à créer des chevauchements avec d'autres partitions, ou converties avec des valeurs de début ou de fin incorrectes. Utilisez cette fonction avec prudence !
*
Le démarrage après la conversion d'un disque MBR ou BSD disklabel sera probablement perturbé. Parfois, la réinstallation d'un chargeur de démarrage peut résoudre le problème, mais d'autres fois, vous pourriez avoir besoin de changer de chargeur de démarrage. Sauf sur les plateformes basées sur EFI, Windows, au moins jusqu'à Windows 7 RC, ne prend pas en charge le démarrage à partir de disques GPT. La création d'un MBR hybride (en utilisant l'option 'h' du menu de récupération et de transformation) ou l'abandon du GPT en faveur du MBR pourraient être vos seules options dans ce cas.
