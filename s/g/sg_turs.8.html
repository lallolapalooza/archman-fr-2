NOM

sg_turs - envoie une ou plusieurs commandes SCSI TEST UNIT READY

SYNTAXE

sg_turs [--ascq=ASC[,ASQ]] [--delay=MS] [--help] [--low] [--num=NUM] [--number=NUM] [--progress] [--time] [--timeout=SE] [--verbose] [--version] PÉRIPH

sg_turs [-d=MS] [-n=NUM] [-p] [-t] [-v] [-V] PÉRIPH

DESCRIPTION

Cet utilitaire envoie une ou plusieurs commandes SCSI TEST UNIT READY au PÉRIPH. Cela peut être utile pour chronométrer le surcoût par commande. Notez que TEST UNIT READY n'a pas de données associées, juste une commande de 6 octets (chaque octet étant zéro) et une valeur de statut SCSI renvoyée.

Cet utilitaire prend en charge deux syntaxes de ligne de commande, la plus préférée est affichée en premier dans la syntaxe et expliquée dans cette section. Une section ultérieure sur la syntaxe de ligne de commande ancienne décrit le second groupe d'options.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-a, --ascq=ASC[,ASQ]
vérifie les données de sense associées à une clé de sense NOT READY. S'il y a une correspondance avec ASC et, si fourni, avec ASQ, cet utilitaire définit son statut de sortie à 36. C'est un code bon alternatif car un statut de sortie de 0 impliquerait que l'unité est prête.

La raison de l'ajout de cette option est que les lecteurs de cartes USB (par exemple, les lecteurs de cartes SD) renvoient souvent un code de sense additionnel de 0x3a,0x0 pour "aucun support présent" lorsqu'il n'y a pas de carte SD dans le lecteur. Il existe des variations du code de sense additionnel 0x3a, il est donc préférable de ne pas fournir la valeur ASQ afin que tout code ascq corresponde.

-d, --delay=MS
cette option provoque un délai de MS millisecondes avant l'envoi de chaque commande TEST UNIT READY.
-h, --help
affiche le message d'utilisation puis quitte.
-l, --low
lorsque [--progress] n'est pas utilisé, cet utilitaire essaie de terminer la ou les commandes SCSI TEST UNIT READY aussi rapidement que possible. Habituellement, il appelle une fonction de bibliothèque pour effectuer chaque TUR (sg_ll_test_unit_ready). Avec cette option, il utilise l'interface sg_pt de plus bas niveau (voir sg_pt.h) pour gagner un peu de temps sur chaque TUR.
-n, --num=NUM
effectue TEST UNIT READY NUM fois. Si non fourni, la valeur par défaut est 1. Ces multiplicateurs suffixés sont autorisés : c C *1 ; w W *2 ; b B *512 ; k K KiB *1,024 ; KB *1,000 ; m M MiB *1,048,576 ; MB *1,000,000 ; g G GiB *1,073,741,824 ; et GB *1,000,000,000. Un suffixe de la forme "x<n>" multiplie le nombre principal par <n>. Alternativement, un nombre hexadécimal peut être fourni, précédé de '0x' ou ayant un 'h' à la fin.
--number=NUM
identique à --num=NUM. Ajouté pour la compatibilité avec sg_requests et d'autres utilitaires de ce paquet. L'utilitaire sg_request a repris le rôle de sondage de l'indication de progression qui était initialement attribuée à la commande TEST UNIT READY. Ceci est un changement par T10.
-O, --old
Passe aux options de style ancien. Veuillez utiliser comme première option.
-p, --progress
affiche l'indication de progression (un pourcentage) si disponible. Si --num=NUM est fourni, NUM est supérieur à 1 et une indication de progression initiale a été détectée, cet utilitaire attend 30 secondes avant les vérifications ultérieures. Si l'option --delay=MS est fournie, il attendra ce nombre de millisecondes au lieu de 30 secondes. Se termine lorsque NUM est atteint ou qu'il n'y a plus d'indications de progression. Ignore l'option --time. Voir la section NOTES ci-dessous.
-t, --time
après avoir exécuté le nombre requis de commandes TEST UNIT READY, affiche la durée totale et le nombre moyen de commandes exécutées par seconde.
-T, --timeout=SE
où SE est le délai d'expiration de la commande pour chaque commande TEST UNIT READY. L'unité de SE est la seconde et si 0 est fourni, il est mappé à 60 secondes, ce qui est la valeur par défaut. Une forme d'option longue alternative est --tmo=SE.
-v, --verbose
augmente le niveau de verbosité.
-V, --version
affiche la chaîne de version puis quitte.

NOTES

L'indication de progression fait partie des données de sense, facultativement. Lorsqu'une commande précédente qui prend beaucoup de temps à s'exécuter (et qui empêche généralement d'autres commandes d'accès aux supports) est toujours en cours, l'indication de progression peut être utilisée pour déterminer combien de temps avant que le périphérique ne revienne à son état normal. Autour de SPC-3, T10 a changé la commande préférée pour sonder l'indication de progression, passant de TEST UNIT READY à REQUEST SENSE (voir l'utilitaire sg_requests).

La commande SCSI FORMAT pour les disques utilisés avec le bit IMMED défini est un exemple d'opération qui prend un temps considérable et empêche d'autres accès aux supports pendant ce temps. Le bit IMMED défini instruit la commande FORMAT de renvoyer le contrôle au client d'application une fois le format commencé (voir SBC-3). Plusieurs commandes SCSI de longue durée associées aux lecteurs de bandes utilisent également l'indication de progression (voir SSC-3).

Le PÉRIPH est ouvert avec un indicateur de lecture seule (par exemple, sous Unix avec l'indicateur O_RDONLY).

Les anciennes normes suggéraient que la commande SCSI TEST UNIT READY soit utilisée pour sonder l'indication de progression. Les normes plus récentes semblent suggérer que la commande SCSI REQUEST SENSE devrait être utilisée à la place.

STATUT DE SORTIE

Le statut de sortie de sg_turs est 0 lorsqu'il réussit (par exemple, dans le cas d'un disque mécanique, il est démarré et prêt à accepter des commandes d'E/S). Pour cet utilitaire, les autres valeurs de statut de sortie intéressantes sont 2, 12, 13 et 36. 12 correspond au cas où la clé de sense est "not ready" [0x2] et que le code de sense additionnel se termine par "Target port in standby state" [0x4, 0xb]. 13 correspond au cas où la clé de sense est "not ready" [0x2] et que le code de sense additionnel est "Target port in unavailable state" [0x4, 0xc]. Le statut de sortie de 36 est associé à l'option --ascq=ASC[,ASQ]. Tous les autres cas où la clé de sense est "not ready" [0x2] définiront le statut de sortie à 2. Pour les autres valeurs de statut de sortie, voir la page de manuel sg3_utils(8).

OPTIONS DE LIGNE DE COMMANDE PLUS ANCIENNES

Les options de cette section étaient les seules disponibles avant la version 1.23 de sg3_utils. Depuis lors, cet utilitaire utilise par défaut les options de ligne de commande plus récentes qui peuvent être remplacées en utilisant --old (ou -O) comme première option. Voir la section VARIABLES D'ENVIRONNEMENT pour une autre façon de forcer l'utilisation de ces anciennes options de ligne de commande.

-d, --delay=MS
cette option provoque un délai de MS millisecondes avant l'envoi de chaque commande TEST UNIT READY.
-n=NUM
effectue TEST UNIT READY NUM fois. Si non fourni, la valeur par défaut est 1. Équivalent à --num=NUM dans la description principale.
-N, --new
Passe aux options de style plus récent.
-p
affiche l'indication de progression (un pourcentage) si disponible. Équivalent à --progress dans la description principale.
-t
après avoir exécuté le nombre requis de commandes TEST UNIT READY, affiche la durée totale et le nombre moyen de commandes exécutées par seconde. Équivalent à --time dans la description principale.
-v
augmente le niveau de verbosité.
-V
affiche la chaîne de version puis quitte.

VARIABLES D'ENVIRONNEMENT

Depuis la version 1.23 de sg3_utils, la variable d'environnement SG3_UTILS_OLD_OPTS peut être spécifiée. Lorsqu'elle est présente, cet utilitaire attend les anciennes options de ligne de commande. La présence de cette variable d'environnement est donc équivalente à l'utilisation de --old (ou -O) comme première option de ligne de commande.
