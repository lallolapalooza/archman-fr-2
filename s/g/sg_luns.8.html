NOM

sg_luns - envoyer une commande SCSI REPORT LUNS ou décoder un LUN donné

SYNTAXE

sg_luns [--decode] [--help] [--hex] [--inhex=FN] [--inner-hex] [--json[=JO]] [--js-file=JFN] [--linux] [--lu_cong] [--maxlen=LEN] [--quiet] [--raw] [--readonly] [--select=SR] [--sinq_inraw=RFN] [--verbose] [--version] DEVICE

sg_luns --test=ALUN [--decode] [--hex] [--inner-hex] [--lu_cong] [--verbose]

DESCRIPTION

Dans la première forme de syntaxe présentée, cet utilitaire envoie la commande SCSI REPORT LUNS à DEVICE et affiche la réponse. La réponse devrait être une liste de LUNs ("inventaire des LUNs") pour le nexus I_T associé à DEVICE. Grossièrement, ce sont tous les LUNs qui partagent le périphérique cible via lequel la commande REPORT LUNS est envoyée. Cette commande est définie dans les normes SCSI SPC-3 et SPC-4 et son support est obligatoire. Le projet le plus récent est SPC-6 révision 1.

Lorsque l'option --test=ALUN est fournie (la seconde forme de syntaxe), la valeur ALUN est décodée comme décrit dans diverses normes SCSI Architecture Model (SAM) et leurs projets récents (par ex. SAM-6 révision 2, section 4.7).

Lorsque requis ci-dessous, la première forme de syntaxe est appelée "mode périphérique" et la seconde forme est appelée "mode test".

OPTIONS

Les arguments des options longues sont obligatoires, y compris pour les options courtes.

-d, --decode
décoder les LUNs en leurs composantes, comme décrit dans la section LUN de SAM-3, SAM-4 et SAM-5.
[mode test] ALUN est décodé indépendamment de la présence ou non de cette option. Si cette option est donnée une fois, le ALUN donné est affiché au format préféré T10 (soit 8 paires d'hexadécimaux, séparées par un espace). Si elle est donnée deux fois, le ALUN donné est affiché dans un format T10 alternatif composé de quatre groupes de chiffres hexadécimaux séparés par un trait d'union ("-") (par ex. C101-0000-0000-0000).
-h, --help
afficher le message d'utilisation puis quitter.
-H, --hex
[mode périphérique] lorsqu'il est donné une fois, cet utilitaire affichera la réponse SCSI (c'est-à-dire le buffer de sortie de données) à la commande REPORT LUNS en hexadécimal ASCII puis quittera. Lorsqu'il est donné deux fois, cela fait que --decode affiche les champs composantes en hexadécimal plutôt qu'en décimal. Notez que ceci (c'est-à-dire le traitement de '-HH') diffère de la description dans sg3_utils(8). L'option --inner-hex a la même action que '-HH'. Lorsque cette option est utilisée trois fois (ou plus), la sortie hexadécimale est adaptée pour être placée dans un fichier et utilisée lors d'une invocation ultérieure de sg_luns avec l'option --inhex=FN.
[mode test] lorsque cette option est donnée, les champs composantes décodés de ALUN sont affichés en hexadécimal.
Lorsqu'elle est donnée trois fois ou plus, les octets hexadécimaux ASCII sont affichés (jusqu'à 16 par ligne) sans adresse ou index de début. Cette sortie est adaptée pour être placée dans un fichier et utilisée lors d'une invocation ultérieure de cet utilitaire pour la décoder avec l'option --inhex=FN. Lorsque cette option est utilisée quatre fois, une ligne de commentaire (commençant par '#') est ajoutée avant l'hexadécimal décrivant ce que l'hexadécimal a été généré par. Un fichier contenant de tels commentaires est toujours analysable par l'option --inhex=FN.
-i, --inhex=FN
FN est attendu comme étant un nom de fichier (ou '-' pour stdin) qui contient de l'hexadécimal ASCII ou du binaire représentant une réponse de REPORT LUNS. Cet utilitaire décodera alors cette réponse. Voir la section "FORMATS HEXADÉCIMAL, BINAIRE ET JSON" dans la page man sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors FN est traité comme binaire.
-I, --inner-hex
utilisé conjointement avec l'option --decode afin que les valeurs décodées soient affichées en hexadécimal. L'action par défaut est d'afficher les valeurs décodées en décimal. Cette option a la même action que '-HH' mais l'intention est un peu plus claire avec cette option.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du texte brut. Notez que les arguments des formes courte et longue sont eux-mêmes optionnels et s'ils sont présents, ils commencent par "=" et aucun espace n'est autorisé autour de ce "=".
Voir la page man sg3_utils_json ou utiliser '?' pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et elle est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et n'a pas besoin d'être donnée. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non par défaut.
-l, --linux
cette option n'est disponible que sous Linux. Après la représentation T10 de chaque LUN de 64 bits (en 16 chiffres hexadécimaux), si cette option est donnée, alors à droite, entre crochets, se trouve l'entier LUN Linux en décimal. Si l'option --hex est donnée deux fois (par ex. -HH) en même temps, alors l'entier LUN Linux est affiché en hexadécimal.
-L, --lu_cong
cette option n'est considérée qu'avec --decode. Lorsqu'elle est donnée une fois, la liste des LUNs est décodée comme si le bit LU_CONG était défini dans la réponse INQUIRY correspondante de chaque LU. Lorsqu'elle est donnée deux fois, la liste des LUNs est décodée comme si le bit LU_CONG était effacé dans la réponse INQUIRY correspondante de chaque LU. Lorsque cette option n'est pas donnée et que --decode est donné, alors une commande INQUIRY est envoyée à DEVICE et le réglage de son bit LU_CONG est utilisé pour décoder la liste des LUNs.
[mode test] décoder ALUN comme si le bit LU_CONG était défini dans sa réponse standard INQUIRY correspondante. En d'autres termes, traiter ALUN comme s'il s'agissait d'un LUN composite. S'il n'est pas donné (ou donné deux fois), décoder ALUN comme si le bit LU_CONG était effacé.
-m, --maxlen=LEN
où LEN est la longueur (maximale) de la réponse en octets. Elle est placée dans le champ "allocation length" du cdb. Si elle n'est pas donnée (ou si LEN est zéro), 8192 est utilisé. La valeur maximale autorisée de LEN est 1048576.
-q, --quiet
afficher uniquement le rendu hexadécimal ASCII de chaque rapport LUN, un par ligne. Sans l'option --quiet, des informations d'en-tête sont imprimées avant la liste des LUNs.
-r, --raw
afficher la réponse SCSI (c'est-à-dire le buffer de sortie de données) en binaire (vers stdout).
-R, --readonly
ouvrir DEVICE en lecture seule (par ex. sous Unix avec le drapeau O_RDONLY). La valeur par défaut est d'ouvrir en lecture-écriture.
-s, --select=SR
SR est placé dans le champ SELECT REPORT de la commande SCSI REPORT LUNS. La valeur par défaut est 0. Les valeurs hexadécimales peuvent être données avec un préfixe "0x" ou un suffixe "h". Pour des informations détaillées, voir la commande REPORT LUNS dans SPC (la plus récente est SPC-4 révision 37 dans la section 6.33). Pour simplifier, pour le nexus I_T associé à DEVICE, les significations des valeurs SR définies à ce jour pour SPC-4 sont:
0 : la plupart des LUNs, à l'exclusion des numéros de logique bien connus
1 : numéros de logique bien connus
2 : tous les LUNs accessibles à ce nexus I_T
0x10 : seulement les LUNs administratifs accessibles
0x11 : LUNs administratifs plus LUNs non composites (voir SPC-4)
0x12 : si DEVICE est un LU administratif, alors rapporter son
LUN ainsi que ses LUNs subsidiaires
Pour les valeurs SR 0x10 et 0x11, DEVICE doit être soit le LUN 0, soit le logique de LUN bien connu de REPORT LUNS. Les valeurs entre 0xf8 et 0xff (inclus) sont spécifiques au vendeur, les autres valeurs sont réservées. Cet utilitaire acceptera toute valeur entre 0 et 255 (0xff) pour SR.
-Q, --sinq_inraw=RFN
cette option est prise en charge à partir de la version 3.1 des sg3-utils. Elle est uniquement utilisée dans le mode périphérique. Lorsque cette option est donnée, une commande PERSISTENT RESERVE IN est envoyée au périphérique, puis une commande REPORT LUNS est envoyée. Si la commande PERSISTENT RESERVE IN renvoie un succès et que son champ "external status" a une valeur de 2 (qui indique que la réserve est en conflit) et que son champ "Vendor specific error" est 1, alors le champ "additional descriptor length" est utilisé pour lire le nombre d'octets dans le buffer retourné par la commande REPORT LUNS. Le reste de la commande REPORT LUNS est alors lu à partir de ce nombre d'octets. Le nom de fichier pour les données supplémentaires de la commande REPORT LUNS est RFN (qui peut être '-' pour stdin). Cela est destiné à la prise en charge des périphériques qui ne renvoient pas la totalité de leur inventaire LUN avec une seule commande REPORT LUNS.
-v, --verbose
accroître la verbosité de la sortie (par ex. afficher les messages d'erreur des commandes SCSI).
-V, --version
afficher la version de ce programme puis quitter.

EXEMPLES

Voir sg3_utils(8) pour des exemples plus généraux. Les exemples ci-dessous sont spécifiques à sg_luns.

sg_luns /dev/sdb
Envoie une commande REPORT LUNS au périphérique /dev/sdb et affiche la réponse dans un format lisible.

sg_luns -HH -d /dev/sg0
Envoie une commande REPORT LUNS au périphérique /dev/sg0, puis décode la réponse en affichant les champs composantes en hexadécimal.

sg_luns -j -d /dev/sdc
Envoie une commande REPORT LUNS au périphérique /dev/sdc, puis affiche la réponse décodée au format JSON.

sg_luns -test=0x81 -d
Décode l'adresse LUN 0x81 comme décrit dans les normes SAM.

sg_luns -test=C101-0000-0000-0000 -d -I
Décode l'adresse LUN C101-0000-0000-0000 au format T10, affichant les composantes en hexadécimal.

NOTES

L'option --select=SR permet de spécifier quelles LUNs sont demandées. Les valeurs par défaut (SR=0) devraient convenir dans la plupart des cas.

Dans le mode test, la valeur ALUN peut être fournie sous forme hexadécimale (précédée de 0x ou suivie de h) ou sous forme décimale. Les deux types sont décomposés en leurs deux champs: "logical unit exponent" et "logical unit identity".

Pour une analyse plus approfondie des LUNs et de leurs structures, voir les normes SCSI pertinentes, notamment SPC-3, SPC-4, SAM-3, SAM-4 et SAM-5.

>=RFN
où RFN est un nom de fichier contenant des données de réponse d'interrogation (INQUIRY) binaires standard qui correspondent soit à DEVICE, soit à FN. Linux place cette réponse d'interrogation standard dans son système de fichiers pseudo sysfs. Un emplacement typique est /sys/class/scsi_device/<hctl>/device/inquiry où <hctl> est un tuple numérique en quatre parties séparées par des deux-points. Ce tuple distingue le périphérique de tous les autres sur le système.
Actuellement, le champ LU_CONG est lu à partir de la réponse d'interrogation standard lorsque cette option est donnée. L'option --raw n'a aucun effet sur cette option. L'argument DEVICE peut être donné avec cette option.
-t, --test=ALUN
ALUN est supposé être un nombre hexadécimal en hexadécimal ASCII ou la lettre 'L' suivie d'un nombre décimal (voir ci-dessous). Le nombre hexadécimal peut avoir jusqu'à 64 bits (c'est-à-dire 16 chiffres hexadécimaux) et est complété à droite s'il y a moins de 16 chiffres hexadécimaux (par exemple, --test=0122003a représente T10 LUN : 01 22 00 3a 00 00 00 00). ALUN peut être préfixé par '0x' ou '0X' (par exemple, l'exemple précédent aurait pu être --test=0x0122003a). ALUN peut également être donné avec des espaces, des tabulations ou un '-' entre chaque octet (ou autre regroupement (par exemple, c101-0000-0000-0000)). Cependant, dans le cas de séparateurs d'espace ou de tabulation, ALUN devrait être entouré de guillemets simples ou doubles.
Dans le cas du 'L' initial, le nombre décimal suivant (hexadécimal s'il est précédé de '0x') est supposé être un LUN "word flipped" de Linux qui est converti en une représentation T10 LUN et affiché. Dans les deux cas, le nombre est interprété comme un LUN et décodé comme si l'option --decode avait été donnée. De plus, lorsque ALUN est un nombre hexadécimal, il peut avoir un 'L' final, auquel cas la valeur LUN "word flipped" correspondante de Linux est affichée. Le LUN est décodé dans tous les cas.
L'action lorsqu'elle est utilisée avec --decode est expliquée sous cette option.
-v, --verbose
augmenter le niveau de verbosité, (c'est-à-dire la sortie de débogage).
-V, --version
afficher la chaîne de version puis quitter.

NOTES

La commande SCSI REPORT LUNS est importante pour la découverte des unités logiques (LU). Après qu'un périphérique cible a été découvert (généralement via un mécanisme spécifique au transport) et après l'envoi d'une commande INQUIRY (pour déterminer le réglage LU_CONG), une commande REPORT LUNS doit être envoyée soit à LUN 0 (qui est la méthode d'adressage de périphérique périphérique avec bus_id=0 et target/lun=0), soit au LUN bien connu de REPORT LUNS (c'est-à-dire 0xc101000000000000). SAM-5 exige que l'une de ces commandes réponde avec un inventaire des LUNs contenus dans ce périphérique cible.

En mode test, si l'option --hex est donnée une fois, alors dans la sortie décodée, certains des champs composants sont affichés en hexadécimal avec des zéros initiaux. Les zéros initiaux servent à indiquer la taille du champ composant. Par exemple : dans la méthode d'adressage de périphérique périphérique (16 bits au total), l'ID de bus a une largeur de 6 bits et le champ cible/LUN a une largeur de 8 bits ; ils sont donc tous deux affichés avec deux chiffres hexadécimaux (par exemple, bus_id=0x02, target=0x3a).

EXEMPLES

Généralement, au moment où les programmes de l'espace utilisateur s'exécutent, les LUNs SCSI ont déjà été découverts. Sous Linux, l'utilitaire lsscsi liste les LUNs actuellement présents. Le LUN d'un périphérique (LU) est le quatrième élément du tuple au début de chaque ligne. Ci-dessous, nous voyons qu'une cible (ou "I_T Nexus" : "6:0:0") a deux LUNs : 1 et 49409. Si 49409 est converti au format T10 LUN, il devient 0xc101000000000000, qui est le LUN bien connu de REPORT LUNS.


# lsscsi -g
[6:0:0:1] disk Linux scsi_debug 0004 /dev/sdb /dev/sg1
[6:0:0:2] disk Linux scsi_debug 0004 /dev/sdc /dev/sg2
[6:0:0:49409]wlun Linux scsi_debug 0004 - /dev/sg3

Nous pourrions envoyer une commande REPORT LUNS (avec SR 0x0, 0x1 ou 0x2) à n'importe lequel de ces nœuds de périphérique de fichier et obtenir le même résultat. Ci-dessous, nous utilisons /dev/sg1 :


# sg_luns /dev/sg1
Lun list length = 16 which implies 2 lun entries
Report luns [select_report=0x0]:
0001000000000000
0002000000000000

C'est un peu bruyant, alors réduisons le désordre avec --quiet :


# sg_luns -q /dev/sg1
0001000000000000
0002000000000000

Maintenant, décodons ce LUN en ses composants :


# sg_luns -d -q /dev/sg1
0001000000000000
Peripheral device addressing: lun=1
0002000000000000
Peripheral device addressing: lun=2

Utilisons maintenant --select=1 pour savoir s'il existe des LUNs bien connus :


# sg_luns -q -s 1 /dev/sg1
c101000000000000

Alors, combien de LUNs avons-nous au total (associés au Nexus I_T actuel) :


# sg_luns -q -s 2 /dev/sg1
0001000000000000
0002000000000000
c101000000000000


# sg_luns -q -s 2 -d /dev/sg1
0001000000000000
Peripheral device addressing: lun=1
0002000000000000
Peripheral device addressing: lun=1
c101000000000000
REPORT LUNS well known logical unit

L'exemple suivant utilise l'option --linux et n'est pas disponible sur d'autres systèmes d'exploitation. Le nombre supplémentaire entre crochets est la version Linux du T10 LUN montré au début de la ligne.


# sg_luns -q -s 2 -l /dev/sg1
0001000000000000 [1]
0002000000000000 [2]
c101000000000000 [49409]

Maintenant, nous utilisons l'option --test= pour décoder les LUNs saisis sur la ligne de commande (plutôt que d'envoyer une commande REPORT LUNS et d'agir sur la réponse) :


# sg_luns --test=0002000000000000
Decoded LUN:
Peripheral device addressing: lun=2


# sg_luns --test="c1 01"
Decoded LUN:
REPORT LUNS well known logical unit


# sg_luns -t 0x023a004b -H
Decoded LUN:
Peripheral device addressing: bus_id=0x02, target=0x3a
>>Second level addressing:
Peripheral device addressing: lun=0x4b

L'exemple suivant est spécifique à Linux car nous essayons de découvrir à quoi le LUN Linux 49409 se traduit dans le monde T10 :


# sg_luns --test=L49409
64 bit LUN in T10 preferred (hex) format: c1 01 00 00 00 00 00 00
Decoded LUN:
REPORT LUNS well known logical unit

Et la correspondance entre les représentations T10 et Linux LUN peut être faite dans l'autre sens :


# sg_luns -t c101L
Linux 'word flipped' integer LUN representation: 49409
Decoded LUN:
REPORT LUNS well known logical unit
