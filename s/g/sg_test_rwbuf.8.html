NOM

sg_test_rwbuf - teste un adaptateur hôte SCSI en émettant des écritures et lectures fictives

SYNTAXE

sg_test_rwbuf [--addrd=AR] [--addwr=AW] [--help] [--quick] --size=SZ [--times=NUM] [--verbose] [--version] PÉRIPHÉ

ou un ancien format déprécié sg_test_rwbuf PÉRIPHÉ SZ [AW] [AR]

DESCRIPTION

sg_test_rwbuf écrit et relit SZ octets dans le tampon interne de PÉRIPHÉ (par exemple /dev/sda ou /dev/sg0). Un motif pseudo-aléatoire est écrit dans le tampon de données sur le périphérique, puis relu. Si le même motif est trouvé, 'Success' est rapporté. S'ils ne correspondent pas (sommes de contrôle inégales), cela est rapporté et jusqu'à 24 octets du premier point de désaccord sont rapportés ; la première ligne montre ce qui a été écrit et la seconde ligne montre ce qui a été reçu. À des fins de test, vous pouvez demander d'écrire AW ou de lire AR octets supplémentaires.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-r, --addrd=AR
Lit AR octets supplémentaires (plus que ce qu'indique SZ) depuis le tampon de données. La somme de contrôle est effectuée sur les premiers SZ octets.
-w, --addwr=AW
Écrit AW octets supplémentaires (plus que ce qu'indique SZ) de zéros dans le tampon de données. La somme de contrôle est générée sur les premiers SZ octets.
-h, --help
Affiche un message d'utilisation, puis quitte.
-q, --quick
Exécute une commande READ BUFFER pour connaître la longueur et le décalage du tampon de données disponible, les affiche, puis quitte (sans tester avec des séquences d'écriture/lecture).
-s, --size=SZ
où SZ est la taille du tampon en octets à écrire, puis lire et vérifier. Ce nombre doit être inférieur ou égal à la taille du tampon de données du périphérique, visible avec l'option --quick. Soit cette option, soit l'option --quick doit être donnée.
-t, --times=NUM
où NUM est le nombre de fois où répéter le test d'écriture/lecture dans le tampon. La valeur par défaut est 1.
-v, --verbose
augmente la verbosité de la sortie.
-V, --version
affiche le numéro de version (et la date du dernier changement), puis quitte.

NOTES

Le microcode d'un périphérique SCSI n'est PAS modifié en effectuant une commande WRITE BUFFER avec son mode réglé sur "data" (0x2) comme le fait cet utilitaire. Par conséquent, cet utilitaire est sûr à cet égard. [Les valeurs de mode 0x4, 0x5, 0x6 et 0x7 sont les dangereuses :-)]

AVERTISSEMENT : Si vous accédez au périphérique en même temps (par exemple, parce qu'il s'agit d'un disque dur avec un système de fichiers monté dessus), le tampon du périphérique peut être utilisé par le périphérique lui-même pour d'autres données en même temps, et sa réécriture peut ou peut ne pas causer de corruption de données ! Cependant, la norme projet SPC-3 stipule dans sa commande WRITE BUFFER : "Cette commande ne doit pas altérer le support de l'unité logique lorsque le mode données ... est spécifié". Cela implique qu'il EST sûr d'utiliser cet utilitaire avec des périphériques qui ont des systèmes de fichiers montés dessus. Dans cette optique, un disque avec des systèmes de fichiers actifs montés peut entraîner une différence entre les données lues et celles écrites (en raison de l'activité de mise en cache) et donc une erreur de somme de contrôle.

STATUT DE SORTIE

Le statut de sortie de sg_test_rwbuf est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
