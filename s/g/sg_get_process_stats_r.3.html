DESCRIPTION

Les fonctions sg_get_process_stats fournissent des statistiques sur les processus actuellement en cours d'exécution. Les deux fonctions, sg_get_process_stats() et sg_get_process_stats_r(), prennent un paramètre optionnel entries, qui pointe (lorsqu'il est fourni) vers un size_t pour obtenir le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_process_count_of() et sg_get_process_count_r() fournissent une vue agrégée de la table des processus - elles livrent la quantité de processus par état de processus. La fonction sg_get_process_count() est en fait une macro préprocesseur pour des raisons de compatibilité descendante et appelle sg_get_process_count_of() avec le paramètre pcs de sg_entire_process_count pour émuler le comportement jusqu'à la version 0.17.

Raccourci API

fonction retourne propriétaire des données
sg_get_process_stats sg_process_stats * libstatgrab (local au thread)
sg_get_process_stats_r sg_process_stats * l'appelant
sg_get_process_count_of sg_process_count * libstatgrab (local au thread)
sg_get_process_count_r sg_process_count * l'appelant

Les vecteurs sg_process_stats reçus de sg_get_process_stats_r() ou les résumés sg_process_count reçus de sg_get_process_count_r doivent être libérés en utilisant sg_free_process_stats() ou sg_free_process_count(), respectivement. L'appelant est responsable de le faire lorsque les données ne sont plus nécessaires.

Ces fonctions comparent deux entrées sg_process_stats, et retournent un int pour représenter laquelle est la plus grande. L'utilisation principale de ces fonctions est d'être passées à qsort pour trier sg_process_stats par le type donné.

Exemple

size_t entries;
sg_process_stats *proc_stats = NULL;
while( NULL != ( proc_stats = sg_get_process_stats_r(&entries) ) ) {
    /* ordonner les entrées en comparant l'identifiant du processus */
    qsort( proc_stats, entries, sizeof(proc_stats[0]), &sg_process_compare_pid );
    show_proc_stats( proc_stats );
    sg_free_process_stats( proc_stats );
}

VALEURS DE RETOUR

La structure retournée par sg_get_process_stats est de type sg_process_stats.

typedef struct {
        char *process_name;
        char *proctitle;
        pid_t pid;    /* identifiant du processus */
        pid_t parent; /* PID du parent */
        pid_t pgid;   /* PID du leader du groupe de processus */
        pid_t sessid; /* ID de session du processus */
        uid_t uid;
        uid_t euid;
        gid_t gid;
        gid_t egid;
        unsigned long long context_switches;
        unsigned long long voluntary_context_switches;
        unsigned long long involuntary_context_switches;
        unsigned long long proc_size; /* en octets */
        unsigned long long proc_resident; /* en octets */
        time_t start_time; /* Heure de démarrage du processus */
        time_t time_spent; /* temps passé en secondes */
        double cpu_percent;
        int nice;
        sg_process_state state;
        time_t systime;
} sg_process_stats;

typedef enum {
        SG_PROCESS_STATE_RUNNING,
        SG_PROCESS_STATE_SLEEPING,
        SG_PROCESS_STATE_STOPPED,
        SG_PROCESS_STATE_ZOMBIE,
        SG_PROCESS_STATE_UNKNOWN
} sg_process_state;
process_name
Le nom de la commande exécutée. Le contenu de ce champ dépend fortement du système d'exploitation sous-jacent. Certains stockent le nom de base de l'exécutable passé à l'appel système exec(2), d'autres le chemin complet. La plupart des systèmes d'exploitation restreignent la taille de ce champ - certains, comme la famille *BSD, à une très faible valeur de 15 octets.

Ce champ est généralement immuable pour les processus utilisateur.

proctitle
La ligne de commande (le "titre") du processus. Attention - cela peut être modifié par le processus, donc il n'est pas garanti que ce soit la ligne de commande d'origine.
pid
L'identifiant du processus.
parent
L'identifiant du processus parent.
pgid
L'identifiant du processus du leader du groupe de processus.
sessid
L'identifiant de session auquel appartient le processus.
uid
L'identifiant de l'utilisateur sous lequel le processus s'exécute.
euid
L'identifiant de l'utilisateur effectif sous lequel le processus s'exécute.
gid
L'identifiant du groupe sous lequel le processus s'exécute.
egid
L'identifiant du groupe effectif sous lequel le processus s'exécute.
context_switches
Le nombre de changements de contexte de ce processus (volontaires et involontaires).
voluntary_context_switches
Le nombre de changements de contexte volontaires de ce processus (par exemple, en appelant sched_yield() ou sleep()).
involuntary_context_switches
Le nombre de changements de contexte involontaires de ce processus (par exemple, expiration de la tranche temporelle ou réception d'un signal).
proc_size
La taille de la mémoire virtuelle du processus en octets.
proc_resident
La taille de la mémoire résidente (physique) du processus en octets.
start_time
L'heure à laquelle le processus a démarré.
time_spent
Le temps total que le processus a passé en cours d'exécution, mesuré en secondes.
cpu_percent
Le pourcentage d'utilisation du processeur par ce processus depuis son démarrage.
nice
La priorité niceness du processus.
state
L'état actuel du processus. Peut être l'une des valeurs suivantes:
  • SG_PROCESS_STATE_RUNNING : Le processus est en cours d'exécution.
  • SG_PROCESS_STATE_SLEEPING : Le processus est en attente d'un événement.
  • SG_PROCESS_STATE_STOPPED : Le processus a été arrêté.
  • SG_PROCESS_STATE_ZOMBIE : Le processus est terminé mais n'a pas encore été récupéré par son parent.
  • SG_PROCESS_STATE_UNKNOWN : L'état est inconnu.
systime
Le temps total passé par le processus dans le noyau, mesuré en secondes.

sg_process_count: Cette structure est retournée par les fonctions sg_get_process_count_*. Elle contient des informations agrégées sur les processus.

typedef struct {
    unsigned long long count;
    sg_process_state state;
} sg_process_count;
count
Le nombre de processus correspondant à l'état spécifié.
state
L'état du processus pour lequel le compte est fourni.

Les fonctions de comparaison retournent 0 si les deux éléments comparés sont égaux, une valeur négative si le premier élément est plus petit que le second, et une valeur positive si le premier élément est plus grand que le second.

sg_get_process_stats_r(3) — libstatgrab — Arch Linux

NAME

sg_get_process_stats_r, sg_get_process_stats — retrieve process statistics

SYNOPSIS

#include <statgrab.h>
...
sg_process_stats_r *
sg_get_process_stats_r(sg_process_count_source_t source,
    sg_error_t *error);
sg_process_stats *
sg_get_process_stats(sg_process_count_source_t source,
    sg_error_t *error);

DESCRIPTION

The sg_get_process_stats_r() function returns a link to a read-only array of process statistics. The number of entries in the array is given by the value returned by sg_get_process_count_r(source, error). The array is valid until the next call to sg_get_process_stats_r() or sg_get_process_stats().

The sg_get_process_stats() function is identical to sg_get_process_stats_r() except that it returns a newly allocated copy of the array. This copy is valid until it is freed using sg_free_process_stats().

The source argument specifies where to get the information from. If source is sg_entire_process_count, all processes are scanned. If source is sg_last_process_count, the last scanned processes are used.

The array elements are of type sg_process_stats. The following members are available:

pid
The process identifier.
ppid
The parent process identifier.
exe
The executable name of the process.
user
The user name of the process owner.
group
The group name of the process owner.
memory
The amount of memory the process is using in bytes.
proc_resident
The size of the process that's resident in memory.
start_time
The time when the process has been started in seconds since epoch.
time_spent
The number of seconds the process has been running (user+system time, without time spent by child processes).
cpu_percent
The current percentage of CPU the process is using.
nice
The nice value of the process.
state
The current state of the process. See sg_process_state for permitted values.
systime
The time in seconds since epoch of the moment where the present statistic has been created. This might be (but doesn't have to be) the same moment for all returned entries, regardless whether they're fetched with one snapshot or puzzled from some kind of procfs.

The structure returned by sg_get_process_count_of and sg_get_process_count_r is of type sg_process_count.

typedef enum sg_process_count_source {
        sg_entire_process_count,
        sg_last_process_count
} sg_process_count_source_t;
typedef struct{
        unsigned long long total;
        unsigned long long running;
        unsigned long long sleeping;
        unsigned long long stopped;
        unsigned long long zombie;
        unsigned long long unknown;
        time_t systime;
}sg_process_count;
total
The total number of processes.
running
The number of running processes.
sleeping
The number of sleeping processes.
stopped
The number of stopped processes.
zombie
The number of zombie processes.
unknown
The number of processes not matching any of above named categories.
systime
The time in seconds since epoch of the moment where the present statistic has been created.

BUGS

The very first call of sg_get_process_count_of(sg_last_process_count) will return the same as sg_get_process_count_of(sg_entire_process_count).

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.
