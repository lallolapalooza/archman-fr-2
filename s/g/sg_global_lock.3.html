NOM

sg_comp_init, sg_comp_destroy, sg_comp_get_tls, sg_global_lock, sg_global_unlock - gestion de la livraison des statistiques système

SYNOPSIS

#include "tools.h"


void *get_global_static
(unsigned int id);


sg_error sg_global_lock
(void);


sg_error sg_global_unlock
(void);

DESCRIPTION

sg_comp_init() est appelée par sg_init() pour exécuter l'initialisation du composant global et de chaque composant libstatgrab enregistré. Cet enregistrement est fait statiquement en ajoutant une structure d'informations d'initialisation de composant (instance de sg_comp_info) à la liste comp_info dans src/libstatgrab/globals.c. L'instance de sg_comp_info est généralement définie en utilisant soit EASY_COMP_SETUP(), soit EXTENDED_COMP_SETUP(), respectivement.

sg_comp_destroy() est appelée par sg_shutdown() pour détruire toutes les ressources globales, par exemple les tables de traduction des noms de périphériques ou les expressions régulières compilées pour faire correspondre les noms de chemins, etc. Les ressources de statistiques sont gérées ailleurs et sont libérées (conceptuellement et généralement) avant que sg_comp_destroy() ne soit invoqué.

sg_comp_get_tls() est la fonction interne pour accéder au stockage local aux threads (anciennement variables globales statiques) du composant. Il est généralement plus facile de s'appuyer sur la macro encapsulante GLOBAL_GET_TLS().

NOTES

La livraison des statistiques système est le travail de libstatgrab, la gestion de la livraison est le travail du composant global. Pour accomplir ce travail, les composants à gérer doivent être préparés :

1.
déclarer la structure de données globale et TLS du composant (probablement seulement sur le papier, pas dans le code)
2.
définir les fonctions d'initialisation globale, de destruction de thread et de destruction de processus (si requis par 1.)
3.
définir la structure d'informations du composant en utilisant *_COMP_SETUP()
4.
définir les accesseurs de composant en utilisant une ou plusieurs des

EASY_COMP_ACCESS()
EASY_COMP_DIFF()
MULTI_COMP_ACCESS()
MULTI_COMP_DIFF()

Une fois ces étapes effectuées, un nouveau composant livrant de nouvelles statistiques est né et doit être "annoncé". En supposant que le composant est nommé cpu, ajoutez la ligne { &sg_cpu_init, 0 } à la liste comp_info nommée ci-dessus.

Informations d'initialisation du composant en détail :

typedef sg_error (*comp_global_init_function)(unsigned id);
typedef void (*comp_global_destroy_function)(void);
typedef void (*comp_global_cleanup_function)(void *);
struct sg_comp_status {
        sg_error init_error;
};
struct sg_comp_init {
        comp_global_init_function init_fn;
        comp_global_destroy_function destroy_fn;
        comp_global_cleanup_function cleanup_fn;
        size_t static_buf_size;
#if defined(ENABLE_THREADS) && defined(HAVE_PTHREAD)
        const char **required_locks;
#endif
        struct sg_comp_status *status;
};

Les composants qui n'ont pas besoin de quelque chose de spécial peuvent s'appuyer sur EASY_COMP_SETUP() :

Initialisation du composant mémoire

EASY_COMP_SETUP(mem,1,NULL);

Lorsque l'on a besoin de sa propre initialisation, c'est un peu plus complexe :

Initialisation du composant réseau

#define SG_NETWORK_IO_NOW_IDX	0
#define SG_NETWORK_IO_DIFF_IDX	1
#define SG_NETWORK_IFACE_IDX	2
#define SG_NETWORK_MAX_IDX	3
EXTENDED_COMP_SETUP(network,SG_NETWORK_MAX_IDX,NULL);
#ifdef LINUX
static regex_t network_io_rx;
#define RX_MATCH_COUNT (8+1)
#endif
sg_error
sg_network_init_comp(unsigned id) {
        GLOBAL_SET_ID(network,id);
#ifdef LINUX
        if( regcomp( &network_io_rx, ..., REG_EXTENDED)!=0) {
                return sg_set_error(SG_ERROR_PARSE, NULL);
        }
#endif
        return SG_ERROR_NONE;
}
void
sg_network_destroy_comp(void) {
#ifdef LINUX
        regfree(&network_io_rx);
#endif
}

EASY_COMP_SETUP() s'occupe de tout ce qui doit être fait automatiquement pour instancier une structure d'informations de composant pour le composant spécifié comp. La structure de stockage TLS créée contiendra nvect éléments pointeurs et c'est tout. Toutes les routines d'initialisation, de destruction et de nettoyage sont créées si nécessaire en utilisant EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() et EASY_COMP_CLEANUP_FN(). Après le nombre de pointeurs vectoriels requis à stocker, la liste des mutex requis doit être spécifiée, terminée par un pointeur NULL.

EXTENDED_COMP_SETUP() s'occupe de tout ce qui doit être fait automatiquement pour instancier une structure d'informations de composant pour le composant spécifié comp, mais nécessite la définition des routines d'initialisation, de destruction et de nettoyage. La structure de stockage TLS créée contiendra nvect éléments pointeurs et c'est tout. Après le nombre de pointeurs vectoriels requis à stocker, la liste des mutex requis doit être spécifiée, terminée par un pointeur NULL. Toutes les routines standard peuvent être créées semi-automatiquement en utilisant EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() et EASY_COMP_CLEANUP_FN().

DEFAULT_INIT_COMP() déclare simplement les prototypes pour les routines d'initialisation, de destruction et de nettoyage, définit le tampon d'état d'initialisation, la liste des noms de verrous et remplit enfin la structure d'initialisation du composant. Utilisez ceci lorsque votre stockage TLS contient plus que de simples pointeurs vectoriels.

GLOBAL_GET_TLS() renvoie le pointeur vers le stockage local aux threads du composant.

GLOBAL_SET_ID() stocke l'identifiant du composant, requis par exemple pour accéder à son TLS.

EASY_COMP_INIT_FN() définit une routine d'initialisation de composant par défaut. Elle stocke l'identifiant du composant et retourne avec SG_ERROR_NONE.

EASY_COMP_DESTROY_FN() définit un destructeur de composant par défaut, appelé à la fin de l'ensemble du processus (ou lorsque le dernier sg_shutdown() est appelé). Le destructeur par défaut ne fait rien et généralement une routine d'initialisation individuelle nécessite également un destructeur individuel.

EASY_COMP_CLEANUP_FN() définit une routine de nettoyage TLS par défaut, toujours appelée lorsqu'un thread se termine pour libérer les vecteurs détenus dans le stockage local aux threads.

EASY_COMP_ACCESS() définit des accesseurs pour une statistique spécifique contenant un élément fourni par le composant : les fonctions fn() et fn##_r(). La fonction suivante doit exister :
sg_error fn##_int
(sg_vector *name##_vect);
Elle accède au vecteur idx à partir du TLS du composant comp et retourne

sg_global_lock.3.en — libstatgrab

NAME

sg_global_lock, EASY_COMP_DIFF, MULTI_COMP_ACCESS, MULTI_COMP_DIFF - statgrab component macros

SYNOPSIS

#include <statgrab.h>

sg_error sg_global_lock();
sg_error sg_global_unlock();

sg_error EASY_COMP_DIFF(
char *comp,
char *name,
int nowidx,
int diffidx,
sg_error (*getfn)(void *data, size_t *num_entries),
sg_error (*cmpfn)(void *data, size_t index, void **ret)
);

sg_error MULTI_COMP_ACCESS(
char *comp,
char *name,
int idx
);

sg_error MULTI_COMP_DIFF(
char *comp,
char *name,
int nowidx,
int diffidx,
sg_error (*getfn)(void *data, size_t *num_entries),
sg_error (*cmpfn)(void *data, size_t index, void **ret)
);

DESCRIPTION

The statgrab library is threadsafe, as long as the functions are called using the sg_global_lock() and sg_global_unlock() functions.

These functions do nothing, but are meant to be used by the user of the library. The user is responsible for locking around any sequence of statgrab calls that access shared data.

EASY_COMP_DIFF() is a macro to simplify the way of accessing single element statistics from a component. It should be used by the component author and not the end user. The function should be called as: sg_error ret = EASY_COMP_DIFF(comp, name, nowidx, diffidx, getfn, cmpfn); where

comp
is the component name, ie. "cpu", "disk" or "network".
name
is the statistic name, ie. "idle", "read_bytes" or "rx_packets".
nowidx
is the index of the current statistic results within the vector, which is created by sg_vector_create().
diffidx
is the index of the statistic results that should be stored.
getfn
is a function pointer to the statistic fetching function. It is called with the data pointer and a pointer to num_entries. The function should fill the data pointer with the latest statistic values and return the number of entries in num_entries. On error, it should return a sg_error value other than SG_ERROR_NONE.
cmpfn
is a function pointer to the statistic comparison function. It should take the data pointer, the index of the statistic entry and a pointer to a void pointer. It should fill the void pointer with a pointer to the statistic entry. On error, it should return a sg_error value other than SG_ERROR_NONE.

MULTI_COMP_ACCESS() defines accessors to a specific statistic containing 0..n elements provided by the component: the functions fn() and the fn##_r(). The following function must exists:
sg_error fn##_int
(sg_vector **name##_vect);
It accesses the vector idx from TLS of component comp and returns sg_##name##_stats. It manages all standard things like memory and error anagement, return values, entries update, etc.

MULTI_COMP_DIFF() does the same as EASY_COMP_DIFF() but for vectors with more than one element.

NOTES

These functions are intended for internal use by the library implementers and may not be stable across releases.

EASY_COMP_DIFF() returns the difference between the two statistic collection runs. The variant dealing with statgrab owned statistics return the difference between the content currently in the vector specified by nowidx and the resulting vector of getfn(). The result is stored in the vector diffidx. If there is no current result, simply the result of getfn() is returned.

MULTI_COMP_ACCESS() defines accessors to a specific statistic containing 0..n elements provided by the component: the functions fn() and the fn##_r(). The following function must exists:
sg_error fn##_int
(sg_vector **name##_vect);
It accesses the vector idx from TLS of component comp and returns sg_##name##_stats. It manages all standard things like memory and error anagement, return values, entries update, etc.

MULTI_COMP_DIFF() does the same as EASY_COMP_DIFF() but for vectors with more than one element.
