NOM

sg_write_buffer - envoie des commandes SCSI WRITE BUFFER

SYNTAXE

sg_write_buffer [--bpw=CS] [--dry-run] [--help] [--id=ID] [--in=FICHIER] [--length=LONGUEUR] [--mode=MO] [--offset=OFF] [--read-stdin] [--skip=SAUTER] [--specific=MS] [--timeout=TO] [--verbose] [--version] PÉRIPHÉRIQUE

DESCRIPTION

Envoie une ou plusieurs commandes SCSI WRITE BUFFER au PÉRIPHÉRIQUE, avec des données fournies par l'utilisateur. Dans certains cas, aucune donnée n'est requise, ou les données peuvent être lues depuis le fichier donné dans l'option --in=FICHIER, ou les données sont lues depuis l'entrée standard lorsque --read-stdin ou --in=- est donné.

Certaines variantes de la commande WRITE BUFFER n'ont pas de données associées à envoyer au périphérique. Par exemple, "activate_mc" active le microcode différé qui a été envoyé via des commandes WRITE BUFFER précédentes. Il existe une méthode différente pour télécharger le microcode vers les périphériques SES, voir l'utilitaire sg_ses_microcode.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont disposées par ordre alphabétique en fonction du nom de l'option longue.

-b, --bpw=CS
où CS est la taille du bloc en octets. Ce sera le nombre maximum d'octets envoyés par commande WRITE BUFFER. Donc, si CS est inférieur à la longueur effective, plusieurs commandes WRITE BUFFER sont envoyées, chacune prenant le bloc suivant des données lues et augmentant le champ de décalage du tampon dans la commande WRITE BUFFER du montant approprié. La valeur par défaut est une taille de bloc de 0, interprétée comme un très grand nombre, donc une seule commande WRITE BUFFER sera envoyée. Cette option ne doit être utilisée qu'avec les modes qui "téléchargent le microcode, avec décalages ..."; à savoir les modes 0x6, 0x7, 0xd ou 0xe.
Le nombre dans CS peut éventuellement être suivi de ",act" ou ",activate". Dans ce cas, après que les commandes WRITE BUFFER aient été envoyées jusqu'à ce que la longueur effective soit épuisée, une autre commande WRITE BUFFER avec son mode défini sur "Activate deferred microcode mode" [mode 0xf] est envoyée.
-d, --dry-run
Effectue tous les traitements de ligne de commande et les vérifications de validité, y compris la lecture du fichier d'entrée. Cependant, au point où une ou plusieurs commandes SCSI WRITE BUFFER seraient envoyées, il saute cet appel et suppose qu'il s'est terminé sans erreur et continue. PÉRIPHÉRIQUE est toujours ouvert mais peut être /dev/null (sous Unix). Il est recommandé d'utiliser --verbose avec cette option pour obtenir un aperçu de ce qui se serait passé.
-h, --help
affiche le message d'utilisation puis quitte. Si utilisé plusieurs fois, imprime également les noms des modes et leurs acronymes.
-i, --id=ID
cette option définit le champ buffer id dans le cdb. ID est une valeur comprise entre 0 (par défaut) et 255 inclusivement.
-I, --in=FICHIER
lit les données du fichier FICHIER qui seront envoyées avec la commande WRITE BUFFER. Si FICHIER est '-', alors stdin est lu jusqu'à ce qu'un EOF soit détecté (c'est la même action que --read-stdin). Les données sont lues depuis le début de FICHIER, sauf dans le cas où il s'agit d'un fichier régulier et que l'option --skip=SAUTER est donnée.
-l, --length=LONGUEUR
où LONGUEUR est la longueur, en octets, des données à écrire sur le périphérique. Si non donné (et que la longueur ne peut être déduite de --in=FICHIER ou --read-stdin), alors la valeur par défaut est zéro. Si l'option est donnée et que la longueur déduite de --in=FICHIER ou --read-stdin est inférieure (ou aucune donnée n'est fournie), alors des octets de 0xff sont utilisés comme octets de remplissage.
-m, --mode=MO
cette option définit le champ MODE dans le cdb. MO est une valeur comprise entre 0 (par défaut) et 31 inclusivement. Alternativement, une abréviation peut être donnée. Voir la section MODES ci-dessous. Pour lister les abréviations de mode disponibles au moment de l'exécution, donnez une abréviation invalide (par exemple, '--mode=xxx') ou utilisez l'option '-hh'.
-o, --offset=OFF
cette option définit le champ BUFFER OFFSET dans le cdb. OFF est une valeur comprise entre 0 (par défaut) et 2**24-1. C'est un décalage en octets.
-r, --read-stdin
lit les données depuis stdin jusqu'à ce qu'un EOF soit détecté. Ces données sont envoyées avec la commande WRITE BUFFER au PÉRIPHÉRIQUE. L'action de cette option est la même que l'utilisation de '--in=-'. Auparavant, le nom long de cette option était --raw et elle peut encore être utilisée pour des raisons de compatibilité ascendante.
-s, --skip=SAUTER
cette option n'est active que lorsque --in=FICHIER est donné et que FICHIER est un fichier régulier, plutôt que stdin. Les données sont lues à partir du décalage d'octet SAUTER jusqu'à la fin du fichier (ou la quantité donnée par --length=LONGUEUR). Si non donné, le décalage d'octet est par défaut 0 (c'est-à-dire le début du fichier).
-S, --specific=MS
MS est le champ MODE SPECIFIC dans le cdb. C'est un champ de 3 bits, donc les valeurs de 0 à 7 sont acceptées. Ce champ a été introduit dans SPC-4 révision 32 et peut être utilisé pour spécifier des événements supplémentaires qui activent le microcode différé (lorsque MO est 0xD).
-t, --timeout=TO
TO est le délai d'expiration de la commande (en secondes) pour chaque commande WRITE BUFFER émise par cet utilitaire. Sa valeur par défaut est de 300 secondes (5 minutes) et ne doit être modifiée que si cela n'est pas suffisant.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
imprime la chaîne de version puis quitte.

NOTES

Si aucun --length=LEN n'est donné, cet utilitaire lit jusqu'à 8 Mio de données à partir du fichier donné FILE (ou stdin). Si une quantité de données plus importante est nécessaire, l'option --length=LEN doit être donnée.

L'utilisateur doit être conscient que la plupart des systèmes d'exploitation ont des limites sur la quantité de données qui peuvent être envoyées avec une seule commande SCSI. Sous Linux, cela dépend du mécanisme de passage utilisé (par exemple, bloc SG_IO ou pilote sg) et de divers réglages dans sysfs dans les séries Linux lk 2.6/3 (par exemple, /sys/block/sda/queue/max_sectors_kb). Les périphériques (c'est-à-dire les unités logiques) ont également généralement des limites sur la quantité maximale de données qu'ils peuvent gérer en une seule commande. Ces deux limitations suggèrent que les modes contenant le mot "offset" ainsi que l'option --bpw=CS sont nécessaires à mesure que les fichiers de micrologiciel deviennent de plus en plus volumineux. Et CS peut être assez petit, par exemple 4096 octets, ce qui entraîne l'envoi de nombreuses commandes WRITE BUFFER.

Tenter de télécharger un fichier de microcode/micrologiciel trop volumineux peut entraîner une erreur dans la couche de passage (c'est-à-dire avant que la commande SCSI ne soit émise). Sous Linux, de tels rapports d'erreur peuvent être obscurs, comme dans "pass through os error invalid argument". FreeBSD signale bien ces erreurs sur la console de la machine mais renvoie un message d'erreur cryptique à cet utilitaire.

Le téléchargement d'un microcode incorrect dans un périphérique a la capacité de le rendre inopérant. On peut espérer que le fournisseur du périphérique vérifie les données avant de les activer. Si la commande SCSI WRITE BUFFER reçoit des valeurs inappropriées dans son cdb (par exemple, LEN) (par exemple, trop grandes), alors le périphérique doit répondre avec une clé de sens ILLEGAL REQUEST et un code de sens supplémentaire INVALID FIELD dans CDB. Si une commande WRITE BUFFER (ou une séquence d'entre elles) échoue en raison de contrôles de vérification du fournisseur du périphérique, elle doit répondre avec une clé de sens ILLEGAL REQUEST et un code de sens supplémentaire COMMAND SEQUENCE ERROR.

Tous les nombres donnés avec les options sont supposés être décimaux. Alternativement, les valeurs numériques peuvent être données en hexadécimal précédées de "0x" ou "0X" (ou avec un "h" ou "H" final).

EXEMPLES

Ce qui suit envoie un nouveau micrologiciel à une enceinte. L'envoi d'un fichier de 1,5 Mo en une seule commande WRITE BUFFER a provoqué le blocage temporaire de l'enceinte et n'a pas mis à jour le micrologiciel. La division du fichier de micrologiciel en blocs de 4 Ko (une estimation éclairée) a été plus fructueuse :


sg_write_buffer -b 4k -m dmc_offs_save -I firmware.bin /dev/sg4

La mise à jour du micrologiciel s'est produite lors du cycle d'alimentation suivant de l'enceinte. Avec une enceinte moderne, la page Extended Inquiry VPD donne des indications dans quelles situations une mise à niveau du micrologiciel aura lieu.

STATUT DE SORTIE

Le statut de sortie de sg_write_buffer est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
