NOM

sg_read_buffer - envoie la commande SCSI READ BUFFER

SYNPOSIS

sg_read_buffer [--eh_code=EHC] [--help] [--hex] [--id=ID] [--inhex=FN] [--length=LEN] [--mode=MO] [--no_output] [--offset=OFF] [--raw] [--readonly] [--specific=MS] [--verbose] [--version] APPAREIL

DESCRIPTION

Envoie une commande SCSI READ BUFFER à l'APPAREIL, et si une réponse est reçue, soit elle est décodée, imprimée en hexadécimal, soit envoyée en binaire vers la sortie standard. Si une réponse est reçue pour un mode « descripteur », alors, en l'absence des options --hex et --raw, elle est décodée. Les réponses pour les modes non descripteurs sont sorties en hexadécimal sauf si l'option --raw est donnée.

Les réponses aux modes « Read microcode status » ('rd_microc_st' [0xf]) et « Error history » ('err_hist' [0x1c]) sont décodées comme décrit dans spc6r06.pdf et les documents T10 antérieurs.

Cet utilitaire peut être appelé sans APPAREIL mais avec l'option --inhex=FN à la place. FN est censé être un nom de fichier (ou
'-' pour l'entrée standard). Le contenu du fichier (ou du flux d'entrée standard) est supposé être des données hexadécimales (ou binaires) qui représentent une réponse à une commande SCSI READ BUFFER et est décodé comme tel.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-e, --eh_code=EHC
EHC est le code d'historique d'erreurs placé dans le champ Buffer ID de la cdb. Le champ Mode est défini sur err_hist [0x1c]. L'option équivaut à utiliser les options '--mode=eh --id=EHC'. Si cette option et l'une des autres options sont données, une erreur sera générée si elles se contredisent. La longueur de réponse par défaut (maximale) est augmentée à 64 octets lorsque cela peut être nécessaire (si c'est le cas, cela est noté si la sortie est tronquée).
Un exemple est de définir EHC à 0, auquel cas le répertoire d'historique d'erreurs sera décodé (sauf si les options --hex ou --raw sont données).
-h, --help
affiche le message d'utilisation puis quitte. Si utilisé plusieurs fois, imprime également les noms des modes et leurs acronymes.
-H, --hex
affiche la réponse en hexadécimal. Lorsqu'elle est donnée deux fois, la réponse est affichée en hexadécimal avec la représentation correspondante en ASCII à droite de chaque ligne. Lorsqu'elle est donnée trois fois, l'hexadécimal est imprimé sans adresses (index) au début de chaque ligne ; ce type de format convient à l'option --inhex=FN lors d'une invocation ultérieure.
-i, --id=ID
cette option définit le champ Buffer ID de la cdb. ID est une valeur comprise entre 0 (par défaut) et 255 inclus. La signification du champ Buffer ID varie avec la valeur du champ Mode de la cdb.
-I, --inhex=FN
FN est censé être un nom de fichier (ou '-' pour l'entrée standard) qui contient de l'hexadécimal ASCII ou du binaire représentant une réponse READ BUFFER. Si elle est connue, cette utilité décodera alors cette réponse. Il est préférable de fournir également les options --mode=MO, --id=ID et éventuellement --specific=MS, car elles ne sont pas présentes dans la réponse. Voir la section « FORMATS HEXADÉCIMAL, BINAIRE ET JSON » dans la page man de sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors le contenu de FN est traité comme binaire.
-l, --length=LEN
où LEN est la longueur, en octets, placée dans le champ « allocation length » de la cdb. La valeur par défaut est 4 (octets), elle est augmentée à 64 si le mode 'err_hist' [0x1c] est donné ou implicite. L'appareil peut répondre avec moins d'octets.
Si l'option --inhex=FN est donnée, alors la valeur par défaut de la longueur est augmentée à 8192 octets. Cette longueur peut ensuite être réduite pour correspondre au nombre d'octets décodés à partir du contenu de FN.
-m, --mode=MO
cette option définit le champ mode de la cdb. MO est une valeur comprise entre 0 (par défaut) et 31 inclus. Alternativement, une abréviation peut être donnée. Voir la section MODES ci-dessous. Pour lister les abréviations de mode disponibles, utilisez-en une invalide (par exemple, '--mode=xxx'). Par exemple, pour récupérer le descripteur de lecture de buffer, donnez '--mode=desc'.
-N, --no_output
lorsque cette option est donnée après l'envoi de la commande SCSI à l'APPAREIL, la réponse est traitée, recherchant d'éventuelles erreurs, puis cet utilitaire se termine. Toutes les données lues par la commande READ BUFFER sont ignorées.
Peut être utile pour chronométrer des lectures plus importantes depuis le buffer de l'APPAREIL en mode 'data' [0x2].
-o, --offset=OFF
cette option définit le champ buffer offset de la cdb. OFF est une valeur comprise entre 0 (par défaut) et 2^24-1. C'est un décalage en octets.
-r, --raw
si une réponse est reçue, elle est envoyée en binaire vers la sortie standard. Lorsque cette option est donnée avec --inhex=FN, le contenu de FN est supposé être binaire et la sortie de cet utilitaire est en ASCII normal (c'est-à-dire _pas_ en binaire).
-R, --readonly
ouvre l'APPAREIL en lecture seule (par exemple, sous Unix avec le flag O_RDONLY). La valeur par défaut est de l'ouvrir en lecture-écriture.
-S, --specific=MS
cette option définit le champ mode specific de la cdb. MS est une valeur comprise entre 0 et 7 car il s'agit d'un champ de 3 bits.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les sorties de débogage).
-V, --version
imprime la chaîne de version puis quitte.

MODES

Voici une liste des paramètres de la commande READ BUFFER pour le champ MODE. D'abord, un acronyme accepté par l'argument MO de cet utilitaire. Après l'acronyme entre crochets se trouvent les valeurs décimales et hexadécimales correspondantes qui peuvent également être données pour MO. Les suivants sont listés par ordre numérique.

hd [0, 0x0]
En-tête combiné et données (obsolète dans SPC-4).
vendor [1, 0x1]
Spécifique au vendeur.
data [2, 0x2]
Données.
desc [3, 0x3]
Descripteur : renvoie 4 octets contenant un champ de frontière de décalage (1 octet) et la capacité du buffer (3 octets).
echo [10, 0xa]
Lit les données du buffer d'écho (appelé « Echo buffer » dans SPC-3).
echo_desc [11, 0xb]
Descripteur de buffer d'écho : renvoie 4 octets dont les 13 bits les plus bas représentent la capacité du buffer d'écho. La taille maximale du buffer d'écho est de 4096 octets.
rd_microc_st [15, 0xf]
Statut du microcode de lecture. Ajouté dans spc5r20.
en_ex [26, 0x1a]
Active le protocole de communication d'extension et le buffer d'écho. Obsolète dans SPC-4.
err_hist|eh [28, 0x1c]
Historique des erreurs. Soit 'err_hist', soit l'abréviation courte 'eh' peuvent être utilisés pour ce mode. Introduit dans SPC-4.

NOTES

Tous les nombres donnés avec les options sont supposés être en décimal. Alternativement, les valeurs numériques peuvent être données en hexadécimal précédées de « 0x » ou « 0X » (ou avec un « h » ou « H » à la fin).

STATUT DE SORTIE

Le statut de sortie de sg_read_buffer est 0 en cas de succès. Sinon, voir la page man de sg3_utils(8).
