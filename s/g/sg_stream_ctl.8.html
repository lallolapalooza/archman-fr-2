SG_STREAM_CTL(8) SG3_UTILS SG_STREAM_CTL(8)

NOM

sg_stream_ctl - envoie la commande SCSI STREAM CONTROL ou GET STREAM STATUS

SYNTAXE

sg_stream_ctl [--brief] [--close] [--ctl=CTL] [--get] [--help] [--id=SID] [--maxlen=LEN] [--open] [--readonly] [--verbose] [--version] PÉRIPH

DESCRIPTION

Envoie une commande SCSI STREAM CONTROL ou GET STREAM STATUS au PÉRIPH. Ces commandes, conjointement avec WRITE STREAM(16 et 32) et plusieurs champs de la page VPD Block Limits Extension [0xb7] supportent le concept de flux (streams). Les commandes de flux ont été ajoutées dans la spécification SBC-4 révision 8 (septembre 2015).

Les commandes STREAM CONTROL et GET STREAM STATUS attendent des données du PÉRIPH (appelées 'data-in'). Dans le cas de STREAM CONTROL, seule l'option 'open' (STR_CTL<--0x1) nécessite réellement les données entrantes, car elle contient l'"Identifiant de flux assigné" si l'ouverture a réussi. L'identifiant de flux assigné doit être utilisé par les commandes WRITE STREAM ultérieures et finalement par la fermeture STREAM CONTROL (STR_CTL<--0x2). Les identifiants de flux valides sont compris entre 1 et 65535 inclus.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-b, --brief
cette option réduit la sortie de la commande GET STREAM STATUS à un seul nombre (en décimal) par ligne envoyée à stdout. Ces nombres sont les identifiants de flux actuellement ouverts. En cas d'erreur, -1 est envoyé à stdout et les messages liés à l'erreur sont envoyés à stderr. Par défaut, plus de mots (et champs) sont imprimés à partir de la réponse GET STREAM STATUS.
-c, --close
sélectionne la commande STREAM CONTROL et définit STR_CTL<--0x2 (c'est-à-dire 'close'). L'option --id=SID doit également être fournie car elle vaut 0 par défaut, ce qui n'est pas un identifiant de flux valide.
-C, --ctl=CTL
CTL est la valeur placée dans le champ STR_CTL de la commande STREAM CONTROL (cdb). C'est un champ de deux bits, il y a donc 4 variantes : 0 et 3 sont réservés ; 1 signifie ouvrir un nouveau flux et 2 fermer le flux donné. '--ctl=1' est équivalent à '--open' tandis que '--ctl=2' est équivalent à '--close'.
-g, --get
sélectionne la commande GET STREAM STATUS. Si l'option --id=SID est également fournie, la réponse commence par lister les identifiants de flux ouverts à partir de SID inclus. Si l'option --id=SID n'est pas fournie (ou si SID vaut 0), tous les identifiants de flux ouverts seront retournés dans la réponse (data-in) tant que la longueur d'allocation (vaut par défaut 248 octets, ce qui peut être remplacé par l'option --maxlen=LEN) est suffisante. C'est l'action par défaut de cet utilitaire (c'est-à-dire la commande GET STREAM STATUS) si aucune option de "sélection" n'est donnée.
-h, --help
affiche le message d'utilisation puis quitte.
-i, --id=SID
SID est un identifiant de flux, une valeur comprise entre 1 et 65535. Il est utilisé par STREAM CONTROL (close) pour identifier le flux à fermer. Il est utilisé par la commande GET STREAM STATUS comme identifiant de flux de départ (inclus) ; ainsi les identifiants de flux inférieurs à SID n'apparaîtront pas dans la réponse.
-m, --maxlen=LEN
LEN est la longueur maximale de la réponse. Elle devient le champ ALLOCATION LENGTH dans les deux commandes. La valeur par défaut (en l'absence de cette option) est de 8 octets pour STREAM CONTROL et de 248 octets pour GET STREAM STATUS.
-o, --open
sélectionne la commande STREAM CONTROL et définit STR_CTL<--0x1 (c'est-à-dire 'open'). Si l'option --id=SID est fournie, elle est ignorée. L'utilisateur doit observer la réponse car l'"Identifiant de flux assigné" est affiché sur stdout si l'ouverture réussit, sinon '-1' est envoyé à stdout et les messages d'erreur sont envoyés à stderr. Si l'option --brief est également fournie, la seule chose envoyée à stdout est un nombre indiquant l'identifiant de flux assigné (1 à 65535 inclus) ou '-1' en cas d'erreur.
-r, --readonly
cette option définit un indicateur 'read-only' lors de l'ouverture du PÉRIPH par le système d'exploitation sous-jacent. Cela peut ne pas fonctionner car les systèmes d'exploitation ne peuvent pas déterminer facilement si une commande de passage est une opération de lecture ou d'écriture logique sur le média (ou ses métadonnées), ils adoptent donc une position aversive au risque et exigent des permissions de type lecture-écriture sur l'ouverture du PÉRIPH, indépendamment de ce qui est effectué par le passage.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les messages de débogage).
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Il n'y a pas de commandes de lecture spéciales pour les flux. Cela implique que les lectures "normales" (6, 10, 12, 16 ou 32) peuvent être utilisées. Notez que lorsqu'un flux est fermé, toutes les ressources associées à cet identifiant de flux sont supprimées, à l'exception des données dans les LBAs écrits. Pour s'assurer que la relecture des données ne soit pas trop retardée par la récupération d'erreurs (en présence d'erreurs de média), l'utilisateur peut définir le champ RECOVERY TIME LIMIT (RTL, unités pour les valeurs non nulles : millisecondes) dans la page de mode 'Read-write error recovery'. Cela peut être fait avec l'utilitaire sdparm.

Les commandes SCSI WRITE STREAM (16 et 32) se trouvent dans l'utilitaire sg_write_x de ce paquet.

CODE DE SORTIE

Le code de sortie de sg_stream_ctl est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
