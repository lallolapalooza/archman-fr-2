NAME

sg_write_verify - envoie la commande SCSI WRITE AND VERIFY

SYNOPSIS

sg_write_verify [--16] [--bytchk=BC] [--dpo] [--group=GN] [--help] [--ilen=ILEN] [--in=IF] --lba=LBA [--num=NUM] [--repeat] [--timeout=TO] [--verbose] [--version] [--wrprotect=WP] DEVICE

DESCRIPTION

Envoie une commande SCSI WRITE AND VERIFY (10) ou (16) à DEVICE. Les données à écrire sont lues depuis le fichier IF ou, en son absence, un tampon rempli de 0xff octets est utilisé. La longueur du tampon de sortie de données envoyé avec la commande est de ILEN octets ou, si cela n'est pas spécifié, la longueur du fichier IF.

L'opération d'écriture se fait sur le support de DEVICE (éventuellement dans son cache) en commençant à l'adresse de bloc logique LBA pour NUM blocs logiques. Après l'écriture sur le support, une opération de vérification a lieu, qui peut être vue comme une lecture du support (avec les vérifications appropriées) mais sans que les données soient retournées. De plus, si BS est mis à un, les données lues depuis le support lors de l'opération de vérification sont comparées aux données du tampon de sortie d'origine.

La relation entre le nombre de blocs logiques à écrire (c'est-à-dire NUM) et la longueur (en octets) du tampon de sortie de données (c'est-à-dire ILEN) peut être simplement trouvée en multipliant le premier par la taille du bloc logique. Cependant, si le DEVICE a des informations de protection (PI), cela devient un peu plus compliqué. Par conséquent, le calcul est laissé à l'utilisateur avec la valeur par défaut de ILEN, en l'absence du fichier IF, fixée à NUM * 512.

Pour envoyer de grandes quantités de données à des blocs logiques contigus, une seule commande WRITE AND VERIFY peut ne pas être appropriée (par exemple, en raison des limitations du système d'exploitation). Dans ce cas, voir la section REPEAT ci-dessous.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont arrangées par ordre alphabétique en se basant sur le nom de l'option longue.

-S, --16
Envoie une commande WRITE AND VERIFY(16). La valeur par défaut est d'envoyer une commande WRITE AND VERIFY(10) à moins que LBA ou NUM ne soient trop grands pour la variante à 10 octets.
-b, --bytchk=BC
où BC est la valeur à placer dans le champ BYTCHK de la commande. Les valeurs comprises entre 0 et 3 (inclus) sont acceptées. La valeur par défaut est 0, ce qui implique qu'une seule écriture sur le support puis une opération de vérification sont effectuées. La seule autre valeur définie actuellement par T10 est 1, qui effectue une comparaison supplémentaire entre le tampon de sortie de données utilisé par l'opération d'écriture et le contenu des blocs logiques lus depuis le support.
-d, --dpo
Définit le bit DPO (disable page out) dans la commande. La valeur par défaut est de le laisser à clair.
-g, --group=GN
où GN est la valeur à placer dans le champ GROUP NUMBER de la commande. Les valeurs comprises entre 0 et 63 (inclus) sont acceptées. La valeur par défaut est 0.
-h, --help
affiche le message d'utilisation puis quitte.
-I, --ilen=ILEN
où ILEN est le nombre d'octets qui seront placés dans le tampon de sortie de données. Si le fichier IF est spécifié, pas plus de ILEN octets ne sont lus de ce fichier. Si le fichier IF ne contient pas ILEN octets, une erreur est signalée. Si le fichier IF n'est pas spécifié, un tampon de sortie de données avec ILEN octets de 0xff est envoyé.
-i, --in=IF
lit les données (binaires) depuis le fichier nommé IF. Si IF est "-", alors stdin est utilisé. Ces données deviendront le tampon de sortie de données et seront écrites sur le support du DEVICE. Si BC est 1, ce tampon de sortie de données sera conservé jusqu'après l'opération de vérification et comparé aux données lues depuis le support.
-l, --lba=LBA
où LBA est l'adresse de bloc logique à partir de laquelle commencer l'écriture sur le support. Supposé être en décimal sauf s'il est préfixé par '0x' ou a un suffixe 'h'. Doit être fourni.
-n, --num=NUM
où NUM est le nombre de blocs, à partir de LBA, à écrire sur le support. La valeur par défaut pour NUM est 1.
-R, --repeat
cette option continuera à effectuer des commandes WRITE AND VERIFY jusqu'à ce que le fichier IF soit épuisé. Cette option nécessite que les options --ilen=ILEN et --in=IF soient fournies. Chaque commande commence à l'adresse du bloc logique suivante et concerne au plus NUM blocs. La dernière commande peut être plus courte, le nombre de blocs étant ajusté en conséquence. S'il reste des octets résiduels, un avertissement est envoyé à stderr. Voir la section REPEAT.
-t, --timeout=TO
où TO est la valeur du délai d'attente de la commande en secondes. La valeur par défaut est 60 secondes. Si NUM est grand, la commande peut requérir considérablement plus de 60 secondes pour se terminer.
-v, --verbose
augmente le degré de verbosité (messages de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wrprotect=WP
définit le champ WRPROTECT dans le cdb à WP. La valeur par défaut est 0, ce qui implique qu'aucune information de protection n'est envoyée (avec les données utilisateur) dans le tampon de sortie de données.

REPEAT

Pour des tailles de données autour d'un mégaoctet et plus, il peut être approprié d'envoyer plusieurs commandes SCSI WRITE AND VERIFY en raison des limitations du système d'exploitation (par exemple, les interfaces SCSI de passe-partout limitent souvent la quantité de données pouvant être passée avec une commande SCSI). Avec cet utilitaire, le mécanisme pour le faire est l'option --repeat.

Dans ce mode, les options --ilen=ILEN et --in=IF doivent être fournies. Les valeurs ILEN et NUM sont traitées comme des paramètres par commande SCSI. Jusqu'à ILEN octets seront lus en continu depuis le fichier IF jusqu'à son épuisement. Si le fichier IF est stdin, la lecture continue jusqu'à ce qu'un EOF soit détecté. Les données lues à chaque itération deviennent le tampon de sortie de données pour une nouvelle commande WRITE AND VERIFY.

La dernière lecture du fichier (ou de stdin) peut lire moins de ILEN octets, auquel cas le nombre de blocs logiques envoyés à la dernière commande WRITE AND VERIFY est ajusté en conséquence. S'il reste un nombre résiduel d'octets après cet ajustement, cela est rapporté à stderr.

Si une erreur survient, elle est rapportée à stderr et via le statut de sortie, et l'utilitaire s'arrête à ce point.

NOTES

D'autres commandes SCSI WRITE ont un bit Force Unit Access (FUA), mais il est défini (implicitement) par les commandes WRITE AND VERIFY, il n'y a donc pas d'option pour le définir. Le tampon de sortie de données peut toujours être placé en outre dans le cache du DEVICE, et la définition du bit DPO est une indication de ne pas faire cela.

Les écritures SCSI normales peuvent être effectuées avec les utilitaires ddpt et sg_dd. La commande SCSI WRITE SAME peut être effectuée avec l'utilitaire sg_write_same, tandis que la commande SCSI COMPARE AND WRITE (utilitaire sg_compare_and_write) offre une fonctionnalité de « test and set ».

Divers arguments numériques (par exemple, LBA) peuvent inclure des suffixes multiplicatifs ou être donnés en hexadécimal. Voir la section « ARGUMENTS NUMÉRIQUES » de la page man sg3_utils(8).

EXIT STATUS

Le statut de sortie de sg_write_verify est 0 en cas de succès. Si l'opération de vérification échoue, cela est généralement indiqué par une erreur de support, ce qui entraîne un statut de sortie de 3.

Si BC est défini sur 1 et que la comparaison qu'il provoque échoue, cet utilitaire indiquera la non-concordance avec un statut de sortie de 14. Pour d'autres valeurs de statut de sortie, voir la section EXIT STATUS de la page man sg3_utils(8).

EXEMPLES

Pour commencer, un exemple simple : écrire 1 bloc de données contenu dans le fichier t.bin, d'une taille de 512 octets, puis écrire ce bloc sur le LBA 0x1234 sur /dev/sg4.


# sg_write_verify --lba=0x1234 --in=t.bin /dev/sg4

Comme '--num=' n'est pas spécifié, il prend par défaut la valeur 1. De plus, la valeur *ILEN* est obtenue à partir de la taille du fichier t.bin. Pour effectuer en plus une comparaison data-out avec les données lues :


# sg_write_verify -l 0x1234 -i t.bin --bytchk=1 /dev/sg4

La commande ddpt peut effectuer des copies entre périphériques SCSI en utilisant les commandes READ et WRITE. Cependant, elle ne dispose actuellement d'aucun moyen de promouvoir ces commandes WRITE en commandes WRITE AND VERIFY. En utilisant un pipe, cela pourrait être fait comme suit :


# ddpt if=/dev/sg2 bs=512 bpt=8 count=11 of=- |
sg_write_verify --in=- -l 0x567 -n 8 --ilen=4096 --repeat /dev/sg4

ddpt et sg_write_verify sont configurés pour des segments de 8 blocs logiques de 512 octets. Comme 11 blocs logiques sont lus, les 8 premiers blocs logiques sont copiés, suivis d'une copie des 3 blocs restants. Comme on suppose qu'il n'y a pas d'informations de protection, les tampons data-in et data-out auront chacun 4096 octets. Pour sg_write_verify, cela doit être indiqué explicitement avec l'option --ilen=4096.
