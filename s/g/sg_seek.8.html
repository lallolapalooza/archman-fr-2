NOM

sg_seek - envoie une commande SCSI SEEK, PRE-FETCH(10) ou PRE-FETCH(16)

SYNTAXE

sg_seek [--10] [--count=NC] [--grpnum=GN] [--help] [--immed] [--lba=LBA] [--num-blocks=NUM] [--pre-fetch] [--readonly] [--skip=SB] [--time] [--verbose] [--version] [--wrap-offset=WO] APPAREIL

DESCRIPTION

Envoie une commande SCSI SEEK(10), PRE-FETCH(10) ou PRE-FETCH(16) à l'APPAREIL. La commande SEEK est obsolète depuis SBC-2 (2005) mais est encore prise en charge sur certains disques durs et même certains SSD (disques à état solide). La commande PRE-FETCH peut être considérée comme le remplaçant moderne de SEEK. Au lieu de parler de déplacer les têtes de lecture du disque vers la piste contenant le LBA recherché, elle parle d'amener le LBA recherché (et un nombre donné de blocs) dans le cache du disque. Les commandes PRE-FETCH ont également un champ IMMED.

Les commandes PRE-FETCH peuvent signaler des erreurs « réelles » mais généralement, elles signalent l'un des deux statuts « bons ». Pour ce faire, elles retournent le statut CONDITION MET, rarement utilisé. Si le nombre de blocs rentre effectivement dans le cache (lorsque IMMED=0) ou s'il y a suffisamment d'espace dans le cache lorsque la commande arrive (lorsque IMMED=1), un statut CONDITION MET est retourné. Si le nombre de blocs demandé ne rentre pas (IMMED=0) ou ne rentrerait pas (IMMED=1), le statut GOOD est retourné. Ainsi, si un disque a un grand cache et que PRE-FETCH est utilisé avec parcimonie, la commande est plus susceptible de retourner CONDITION MET que GOOD. Cela pose des problèmes à certains sous-systèmes SCSI car, en raison de sa rareté, ils mal gèrent le statut CONDITION MET et le traitent comme une erreur (voir la section NOTES ci-dessous).

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-T, --10
utilise une commande cdb de 10 octets, soit la commande SEEK(10), soit PRE-FETCH(10). En l'absence de l'option --pre-fetch, la commande SEEK(10) est utilisée. Si l'option --pre-fetch est donnée sans cette option, une commande PRE-FETCH(16) est utilisée.
-c, --count=NC
NC est le nombre de commandes (SEEK(10), PRE-FETCH(10) ou PRE-FETCH(16)) qui seront exécutées. La valeur par défaut est 1. Si une erreur se produit, elle est notée et le programme continue jusqu'à ce que NC soit épuisé. Si NC est 0, les options sont vérifiées et l'APPAREIL est ouvert, mais aucune commande n'est envoyée.
-g, --grpnum=GN
GN est le numéro de groupe, une valeur comprise entre 0 et 63 (en hexadécimal : 0x3f). La valeur par défaut est 0. Cette option est ignorée si la commande sélectionnée est SEEK(10).
-h, --help
affiche le message d'utilisation puis quitte.
-i, --immed
cette option s'applique uniquement à PRE-FETCH(10) et PRE-FETCH(16), en définissant le bit IMMED. Sans cette option, l'APPAREIL retourne après avoir terminé le transfert de tout ou partie des blocs demandés dans le cache. Si cette option est donnée, l'APPAREIL retourne après avoir effectué des vérifications de plausibilité sur le cdb (par exemple, s'assurer que le LBA est supérieur au nombre de blocs disponibles) et avant d'effectuer le transfert dans le cache.
Notez que même lorsque cette option est donnée, le statut de retour des commandes PRE-FETCH est toujours soit le statut CONDITION MET (si le cache semble avoir suffisamment d'espace libre pour le transfert), soit un statut GOOD (si le cache ne semble pas avoir suffisamment d'espace libre).
-l, --lba=LBA
LBA est l'adresse logique de bloc de départ placée dans le descripteur de commande (cdb) de la commande sélectionnée. Notez que le champ LBA dans SEEK(10) et PRE-FETCH(10) est une quantité de 32 bits, tandis qu'avec PRE-FETCH(16), c'est une quantité de 64 bits. La valeur par défaut est 0.
-n, --num-blocks=NUM
NUM est le nombre de blocs, à partir de et incluant LBA, à placer dans le cache de l'APPAREIL. La commande SEEK(10) n'utilise pas la valeur NUM. Pour PRE-FETCH(10), NUM est une quantité de 16 bits, tandis que pour PRE-FETCH(16), c'est une quantité de 32 bits. La valeur par défaut est 1. Si NUM est 0, l'APPAREIL tentera de transférer tous les blocs à partir du LBA donné jusqu'à la fin du support.
-p, --pre-fetch
cette option sélectionne les commandes PRE-FETCH(10) ou PRE-FETCH(16). Avec --10 également donné, la commande PRE-FETCH(10) est sélectionnée ; sans cette option, PRE-FETCH(16) est sélectionnée. Par défaut (en l'absence de cette option et d'autres options de 'sélection'), la commande SEEK(10) est sélectionnée.
-r, --readonly
cette option définit un indicateur 'lecture seule' lorsque le système d'exploitation sous-jacent ouvre l'APPAREIL donné. Cela peut ne pas fonctionner car les systèmes d'exploitation ne peuvent pas facilement déterminer si un pass-through est une opération de lecture ou d'écriture logique, ils adoptent donc une position prudente et exigent des ouvertures de type lecture-écriture de l'APPAREIL, indépendamment de ce qui est effectué par le pass-through.
-s, --skip=SB
SB est le nombre d'adresses logiques de blocs à sauter, entre les commandes répétées lorsque NC est supérieur à 1. La valeur par défaut de SB est 1. SB peut être défini sur 0 afin que toutes les commandes PRE-FETCH NC utilisent le même LBA.
-t, --time
si donné, le temps écoulé pour exécuter NC commandes est enregistré. Ceci est affiché avant que cet utilitaire ne se termine. Si NC est supérieur à 1, le temps « par commande » est également affiché.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wrap-offset=WO
WO est le nombre de blocs, par rapport à LBA, qui lorsqu'il est dépassé, remet l'adresse logique de bloc de la commande suivante à LBA. Que cette action de « réinitialisation à LBA » se produise dépend des valeurs NC et SB.

NOTES

Avant le noyau Linux 4.17, le statut CONDITION MET était enregistré comme une erreur. Les versions récentes de FreeBSD gèrent correctement le statut CONDITION MET.

Si l'option --count=NC ou --verbose est donnée, une ligne de résumé comme suit est affichée :


Nombre de commandes=5, nombre de condition_met=3, nombre de good=2

avant que l'utilitaire ne se termine.

STATUT DE SORTIE

Le statut de sortie de sg_seek est 0 (GOOD) ou 25 (CONDITION_MET) lorsque cet utilitaire réussit. Si plusieurs commandes sont exécutées (par exemple, lorsque NC est supérieur à 1), le résultat de la dernière commande SEEK ou PRE-FETCH exécutée définit le statut de sortie. Sinon, voir la page man sg3_utils(8).
