NOM

sg_get_elem_status - envoie la commande SCSI GET PHYSICAL ELEMENT STATUS

SYNTAXE

sg_get_elem_status [--brief] [--filter=FLT] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--maxlen=LEN] [--raw] [--readonly] [--report-type=RT] [--starting=ELEM] [--verbose] [--version] PÉRIPH

DESCRIPTION

Envoie la commande SCSI GET PHYSICAL ELEMENT STATUS au PÉRIPH et affiche la réponse. Cette commande a été introduite dans (la version préliminaire) SBC-4 révision 16.

Les versions préliminaires de T10 parlent maintenant à la fois d'éléments « physiques » et « de stockage ». Le terme dernier est plus spécifique (c'est-à-dire que les éléments de stockage sont un sous-ensemble des éléments physiques) et fait référence aux ressources du disque qui contrôlent le stockage des données utilisateur. Un exemple d'élément de stockage est les données utilisateur associées à une tête sur un disque dur rotatif. Lorsqu'un élément de stockage a été « dépouillé », son ancien stockage accessible via les LBA n'est plus disponible. Les éléments physiques sont plus généraux et incluent les éléments de stockage et pourraient inclure des ressources de disque utilisées pour des paramètres de page de mode « sauvegardés », entre autres choses.

L'action par défaut de cet utilitaire est de décoder la réponse en un en-tête et jusqu'à 32 descripteurs d'état d'élément physique. Les descripteurs d'état sont affichés un par ligne. La quantité de sortie peut être réduite par l'option --brief.

Plutôt que d'envoyer cette commande SCSI à PÉRIPH, si l'option --inhex=FN est donnée, alors le contenu du fichier nommé FN est décodé en hexadécimal ASCII (ou binaire si --raw est également donné) puis traité comme s'il s'agissait de la réponse de la commande GET PHYSICAL ELEMENT STATUS.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-b, --brief
lorsqu'il est utilisé une fois, la sortie de chaque descripteur d'état d'élément physique est réduite à : <id_élément>: <type_élément>,<santé_élément>. Les trois sont affichés sous forme d'entiers décimaux. Lorsqu'il est utilisé deux fois, la ligne « Descripteurs d'élément : » introduisant les descripteurs d'état n'est pas affichée. Lorsqu'il est utilisé trois fois ou plus, seul l'en-tête de réponse est affiché.
-f, --filter=FLT
où FLT est placé dans un champ à deux bits appelé FILTER dans la commande GET PHYSICAL ELEMENT STATUS. Seules deux valeurs sont définies pour ce champ : 0 pour tous les descripteurs d'élément ; 1 pour les descripteurs d'élément qui sont hors spécifications ou qui ont des informations de dépouillement à rapporter. Dans les deux cas, les champs REPORT TYPE et STARTING ELEMENT peuvent restreindre (réduire) davantage le nombre de descripteurs d'élément retournés. La valeur par défaut est zéro.
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
affiche la réponse à cette commande en hexadécimal ASCII. Chaque ligne de 16 octets est précédée d'une adresse ou d'un index, à partir de 0, et l'adresse est également en hexadécimal. Si elle est donnée deux fois, un rendu ASCII de chaque octet est ajouté à la ligne de sortie. Si elle est donnée trois fois ou plus, seul l'hexadécimal ASCII de chaque octet est affiché, 16 octets par ligne (c'est-à-dire sans adresse de début ni rendu ASCII final). Cette dernière forme convient pour être placée dans un fichier et utilisée avec l'option --inhex=FN lors d'une invocation ultérieure.
-i, --inhex=FN
où FN est un nom de fichier dont le contenu est supposé être en hexadécimal ASCII. Si PÉRIPH est également donné, alors PÉRIPH est ignoré, un avertissement est émis et l'utilitaire continue, en décodant le fichier nommé FN. Voir la section « FORMATS HEX, BINARY ET JSON » de la page de manuel sg3_utils pour plus d'informations. Si l'option --raw est également donnée, alors le contenu de FN est traité comme binaire.
-j[=JO], --json[=JO]
la sortie est au format JSON au lieu du format texte brut. Notez que les arguments des formes courte et longue sont facultatifs et, s'ils sont présents, commencent par « = » sans espace autorisé autour de ce « = ».
Voir la page de manuel sg3_utils_json ou utiliser « ? » pour JO afin d'obtenir un résumé.
-J, --js-file=JFN
la sortie est au format JSON et est envoyée à un fichier nommé JFN. Si ce fichier existe, il est tronqué. Par défaut, la sortie JSON est envoyée à stdout.
Lorsque cette option est donnée, l'option --json[=JO] est implicite et il n'est pas nécessaire de la donner. L'option --json[=JO] peut toujours être nécessaire pour définir le paramètre JO à des valeurs non par défaut.
-m, --maxlen=LEN
où LEN est la longueur (maximale) de la réponse en octets. Elle est placée dans le champ « longueur d'allocation » du cdb. Si elle n'est pas donnée, 1056 est utilisé. 1056 est suffisant pour l'en-tête de réponse plus 32 descripteurs d'état d'élément physique. LEN doit être un multiple de 32 (par exemple, 32, 64 et 96 sont appropriés).
-r, --raw
affiche la réponse en binaire (sur stdout) sauf si l'option --inhex=FN est également donnée. Dans ce cas, le nom du fichier d'entrée (FN) est décodé en binaire (et la sortie n'est _pas_ en binaire).
-R, --readonly
ouvre le PÉRIPH en lecture seule (par exemple, sous Unix avec le flag O_RDONLY). La valeur par défaut est d'ouvrir en lecture-écriture.
-t, --report-type=RT
où RT sera placé dans le champ REPORT TYPE de la commande GET PHYSICAL ELEMENT STATUS. Actuellement, seules deux valeurs sont définies : 0 pour « élément physique » et 1 pour « élément de stockage ». La valeur par défaut est 0.
-s, --starting=ELEM
où ELEM est placé dans le champ STARTING ELEMENT de la commande GET PHYSICAL ELEMENT STATUS. Seuls les éléments physiques avec des identifiants supérieurs ou égaux à ELEM sont retournés. La valeur par défaut est zéro, ce qui, bien que n'étant pas un identifiant d'élément valide (car ils doivent être non nuls), est donné dans un exemple à l'annexe L de la SBC-4 révision 17. Donc, un ELEM de zéro est supposé être valide dans ce contexte.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire les messages de débogage). La sortie supplémentaire causée par cette option est envoyée à stderr.
-V, --version
affiche la chaîne de version puis quitte.

NOTES

Le code d'erreur supplémentaire « Avertissement - changement d'état d'élément physique » [0xb, 0x14] est spécial et devrait inciter un client d'application à appeler la commande GET PHYSICAL ELEMENT STATUS. La manière dont cet avertissement est déclenché dépend des paramètres de la page de mode Informational Exceptions Control [0xc, 0x0].

Après avoir détecté un ou plusieurs éléments de stockage hors spécifications, le disque en question doit soit être mis hors service, soit avoir la commande REMOVE ELEMENT AND TRUNCATE (ou... AND MODIFY ZONES) invoquée pour réparer (et réduire la capacité de stockage) du disque.

CODE DE SORTIE

Le code de sortie de sg_get_elem_status est 0 en cas de succès. Sinon, voir la page de manuel sg3_utils(8).
