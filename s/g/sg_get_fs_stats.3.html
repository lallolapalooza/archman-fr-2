sg_fs_stats *sg_get_fs_stats_diff_between
(const sg_fs_stats *cur, const sg_fs_stats *last, size_t *entries);


sg_error sg_free_fs_stats
(sg_fs_stats *data);


const char **sg_get_valid_filesystems

(const void *va, const void *vb);

DESCRIPTION

Les fonctions sg_get_fs_stats fournissent des statistiques sur les systèmes de fichiers montés. Les deux fonctions prennent un paramètre d'entrée optionnel, qui pointe (lorsqu'il est fourni) vers un size_t pour obtenir le nombre d'entrées du vecteur retourné.

Les fonctions sg_get_fs_stats() et sg_get_fs_stats_r() fournissent les statistiques du système de fichiers au moment où la fonction est appelée. Les fonctions sg_get_fs_stats_diff() et sg_get_fs_stats_diff_between() fournissent la différence entre deux appels à sg_get_fs_stats() ou sg_get_fs_stats_r(), respectivement.

Raccourci API

fonction retourne propriétaire des données
sg_get_fs_stats sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_r sg_fs_stats * appelant
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local au thread)
sg_get_fs_stats_diff_between sg_fs_stats * appelant
sg_get_valid_filesystems char ** libstatgrab (global)

Les vecteurs sg_fs_stats reçus de sg_get_fs_stats_r() ou sg_get_fs_stats_diff_between() doivent être libérés avec sg_free_fs_stats() lorsqu'ils ne sont plus nécessaires. L'appelant est responsable de le faire.

La bibliothèque statgrab est livrée avec une liste intégrée des types de systèmes de fichiers valides en fonction du système d'exploitation pour lequel elle a été compilée. Certains systèmes d'exploitation fournissent en outre une API pour connaître les types de systèmes de fichiers connus ou valides pour l'instance du système d'exploitation en cours d'exécution, qui est utilisée lorsqu'elle est détectée. Néanmoins, il existe des problèmes connus lors de la collecte des statistiques des systèmes de fichiers : les systèmes de fichiers réseau sont montés à partir de serveurs distants, les développeurs de systèmes de fichiers exécutent un pilote expérimental, etc.

Pour éviter que les processus ne se bloquent lors de la collecte des statistiques des systèmes de fichiers ou pour permettre aux développeurs de tester leurs pilotes, les processus peuvent modifier la liste des systèmes de fichiers valides à l'aide de sg_get_valid_filesystems() et sg_set_valid_filesystems(). La liste des paramètres char * avec lesquels les deux fonctions travaillent est toujours terminée par un élément pointant vers NULL.

La liste retournée par sg_get_valid_filesystems() ne doit pas être modifiée. Copiez toujours la liste dans votre propre structure si vous prévoyez d'étendre ou de réduire la liste :

Exemple de suppression de FS réseau

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* noms de types de systèmes de fichiers réseau connus sur différentes plateformes */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* dupliquer dans sa propre mémoire pour modifier la liste */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copier y compris le pointeur NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Notez qu'il n'est pas nécessaire de dupliquer les chaînes de caractères contenues dans la liste des systèmes de fichiers valides dans l'exemple ci-dessus - elles ne sont pas modifiées.

La liste retournée par sg_get_valid_filesystems() pourrait devenir invalide lorsqu'elle est utilisée pendant que le processus effectue des appels à sg_set_valid_filesystems(). Aucune des fonctions sg_fs_stats ne protège l'accès au stockage global utilisé où est conservée la copie personnelle de la liste des systèmes de fichiers valides. Il appartient à l'appelant de ne pas mélanger les appels de configuration avec les appels pour récupérer les statistiques.

De plus, deux fonctions d'assistance pour qsort(3) sont disponibles : sg_fs_compare_device_name() et sg_fs_compare_mnt_point().

Exemple de tri

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* trier les entrées par ordre alphabétique en utilisant le point de montage */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

sg_get_fs_stats retourne un pointeur vers une structure de type sg_fs_stats.

        unsigned long long io_size;

nom_de_périphérique
Le nom connu du système d'exploitation. (par exemple, sous Linux, cela peut être hda)
type_de_système_de_fichiers
Le type de système de fichiers. (par exemple, hpfs ou ufs).
point_de_montage
Le point de montage où le système de fichiers est monté.
type_de_périphérique
Le type de périphérique du système de fichiers, actuellement non rempli et toujours sg_fs_unknown.
taille
La taille totale, en octets, du système de fichiers.

taille = utilisé + libre

utilisé
La quantité d'espace, en octets, utilisée sur le système de fichiers.
disponible
La quantité d'espace, en octets, disponible sur le système de fichiers pour les utilisateurs non privilégiés.

sg_get_fs_stats(3) — libstatgrab — The Arch Linux man-pages project

NAME

sg_get_fs_stats, sg_get_fs_stats_byname — retrieve file system statistics

SYNOPSIS

#include <statgrab.h>
struct SgFsStat *
sg_get_fs_stats(int *n_filesystems, GError **error);
struct SgFsStat *
sg_get_fs_stats_byname(const char *name, int *n_filesystems, GError **error);

DESCRIPTION

The sg_get_fs_stats function shall return a list of all mounted file systems. Each element in the list is a pointer to a SgFsStat structure. The number of elements in the list is returned in the integer pointed to by n_filesystems.

The sg_get_fs_stats_byname function shall return a list of all mounted file systems matching the given name. The name is the name of the file system, like "ext4", "btrfs", or "nfs". The number of elements in the list is returned in the integer pointed to by n_filesystems.

The SgFsStat structure contains the following fields:

const char *name
The name of the file system.
const char *mount_point
The mount point of the file system.
const char *device
The device name of the file system.
long long total
The total size of the file system in bytes.
long long free
The amount of free space, in bytes, on the file system.
long long reserved
The amount of space reserved for privileged users/processes.
long long avail
The amount of space available to unprivileged users/processes (free space less reserved space).

avail = free - reserved

long long free_inodes
The number of free inodes on the file system.
long long used_inodes
The number of used inodes on the file system.
long long total_inodes
The total number of inodes on the file system.
long long block_size
The size in bytes of the minimum unit of allocation on this file system.
long long io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
long long total_blocks
The total number of blocks in the file system.
long long free_blocks
The number of free blocks in the file system.
long long used_blocks
The number of used blocks in the file system.
long long avail_blocks
The number of free blocks available to non-privileged processes.
time_t systime
The time in seconds since epoch when the statistic was retrieved from kernel.

RETURN VALUES

On success, a list of SgFsStat structures is returned. The caller is responsible for freeing this list using sg_free_fs_stats. On failure, NULL is returned and error is set to a GError structure describing the error.

The fields total, free, reserved, and avail are calculated from information provided by the operating system. Some systems may not provide all of this information, in which case the corresponding fields may be set to -1.

The fields total_inodes, used_inodes, and free_inodes are calculated from information provided by the operating system. Some systems may not provide all of this information, in which case the corresponding fields may be set to -1.

The fields total_blocks, free_blocks, used_blocks, and avail_blocks are calculated from information provided by the operating system. Some systems may not provide all of this information, in which case the corresponding fields may be set to -1.

The fields block_size and io_size are derived from system calls that may fail. If the values cannot be determined, they may be set to -1.

The systime field is the time the information was retrieved from the kernel.

A reserved amount of space is set aside for the super-user. The avail field is the amount of space that is available to non-privileged users. The avail field is calculated as free - reserved.

The fields avail_inodes is the number of free inodes available to unprivileged processes. This is calculated as free_inodes.

The fields avail_blocks is the number of free blocks available to unprivileged processes. This is calculated as free_blocks.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
