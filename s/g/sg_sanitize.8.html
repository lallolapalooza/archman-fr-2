NOM

sg_sanitize - supprime toutes les données utilisateur avec la commande SCSI SANITIZE

SYNOPSIS

sg_sanitize [--ause] [--block] [--count=OC] [--crypto] [--dry-run] [--desc] [--early] [--fail] [--help] [--invert] [--ipl=LEN] [--overwrite] [--pattern=PF] [--quick] [--test=TE] [--timeout=SECS] [--verbose] [--version] [--wait] [--zero] [--znr] PÉRIPH

DESCRIPTION

Cet utilitaire invoque la commande SCSI SANITIZE. Cette commande a été introduite pour la première fois dans la révision 27 du brouillon SBC-3. Le but de l'opération de nettoyage est de modifier les informations dans le cache et sur le support d'une unité logique (par exemple, un disque) de manière à ce que la récupération des données utilisateur ne soit pas possible. Si ces données utilisateur ne peuvent pas être effacées, ou sont en cours d'effacement, l'opération de nettoyage empêche l'accès à ces données utilisateur.

Une fois qu'une commande SCSI SANITIZE a démarré avec succès, les données utilisateur de ce disque ne sont plus disponibles. Même si le disque est mis hors tension puis remis sous tension, l'opération de nettoyage continuera après la remise sous tension jusqu'à ce qu'elle soit terminée.

Cet utilitaire nécessite soit l'option --block, --crypto, --fail ou --overwrite. Avec l'option --block, --crypto ou --overwrite, l'utilisateur dispose de 15 secondes pour reconsidérer s'il souhaite effacer toutes les données d'un disque, sauf si l'option --quick est utilisée, auquel cas l'opération de nettoyage démarre immédiatement. Les chaînes de réponse INQUIRY du disque sont affichées au cas où le PÉRIPH incorrect aurait été donné.

Si l'option --early est utilisée, cet utilitaire se terminera peu après le démarrage de la commande SANITIZE avec le bit IMMED mis à 1. L'utilisateur peut surveiller la progression de l'opération de nettoyage avec la commande "sg_requests --num=9999 --progress" qui envoie une commande REQUEST SENSE toutes les 30 secondes. Sinon, si l'option --wait est utilisée, cet utilitaire attendra que la commande SANITIZE soit terminée (ou échoue), ce qui peut prendre plusieurs heures.

Si l'option --wait n'est pas utilisée, la commande SANITIZE est démarrée avec le bit IMMED mis à 1. Si ni l'option --early ni l'option --wait ne sont utilisées, cet utilitaire envoie une commande REQUEST SENSE toutes les 60 secondes jusqu'à ce qu'il n'y ait plus d'indications de progression, auquel cas cet utilitaire se termine silencieusement. Si en plus l'option --verbose est utilisée, la sortie sera marquée par un court message indiquant que le nettoyage semble avoir réussi.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont classées par ordre alphabétique en fonction du nom de l'option longue.

-A, --ause
définit le bit AUSE dans le cdb. AUSE est l'acronyme de "allow unrestricted sanitize exit" (permettre une sortie de nettoyage sans restriction). L'action par défaut consiste à laisser le bit AUSE effacé.
-B, --block
effectue une opération de nettoyage de type "effacement par blocs" (block erase).
-c, --count=OC
où OC est le "nombre d'écrasements" (overwrite count) associé à l'opération de nettoyage "écrasement". OC peut être une valeur comprise entre 1 et 31, et 1 est la valeur par défaut.
-C, --crypto
effectue une opération de nettoyage de type "effacement cryptographique" (cryptographic erase). Notez que cet effacement est souvent très rapide car il se contente d'écraser une clé cryptographique interne avec une nouvelle valeur. Ces clés ne sont pas accessibles aux utilisateurs et chiffrent toutes les données écrites puis déchiffrent toutes les données lues depuis le support. La raison principale pour cela est de rendre cette opération rapide. Cette opération ne peut pas être inversée.
-d, --desc
définit le champ DESC dans la commande REQUEST SENSE utilisée pour le sondage. Par défaut, ce champ est mis à zéro. Une boucle de sondage REQUEST SENSE est utilisée après l'émission de la commande SANITIZE (en supposant que ni l'option --early ni l'option --wait n'aient été utilisées) pour vérifier la progression de cette commande car elle peut prendre du temps.
-D, --dry-run
cette option analyse la ligne de commande, effectue toute la préparation, mais ignore la commande SANITIZE réelle.
-e, --early
l'action par défaut de cet utilitaire consiste à interroger le disque toutes les 60 secondes pour obtenir l'indication de progression jusqu'à ce que le nettoyage soit terminé. Lorsque cette option est utilisée, cet utilitaire se termine "tôt" dès que la commande SANITIZE avec le bit IMMED mis à 1 a été acquittée. Cette option et --wait ne peuvent pas être utilisées ensemble.
-F, --fail
effectue une opération de nettoyage de type "mode échec de sortie" (exit failure mode). Nécessite généralement que la commande SANITIZE précédente ait défini le bit AUSE.
-h, --help
affiche les informations d'utilisation puis quitte.
-i, --ipl=LEN
définit la longueur du motif d'initialisation à LEN octets. Par défaut, elle est définie à la longueur du fichier de motif (PF) ou 4 si l'option --zero est utilisée. N'est active que lorsque l'option --overwrite est également utilisée. Il s'agit du nombre d'octets du fichier PF qui seront utilisés comme motif d'initialisation (si l'option --zero n'est pas utilisée). La taille minimale est de 1 octet et la taille maximale est la taille du bloc logique du PÉRIPH (et ne doit pas dépasser 65535). Si LEN dépasse la taille du fichier PF, le motif d'initialisation est complété avec des zéros.
-I, --invert
définit le bit INVERT dans la liste de paramètres de l'action de service d'écrasement. Cela n'affecte que l'opération de nettoyage "écrasement". La valeur par défaut est un bit INVERT effacé. Lorsque le bit INVERT est défini, le motif d'initialisation est inversé entre les passes d'écrasement consécutives.
-O, --overwrite
effectue une opération de nettoyage de type "écrasement" (overwrite). Lorsque cette option est utilisée, l'option --pattern=PF ou l'option --zero est requise.
-p, --pattern=PF
où PF est le nom du fichier contenant le motif d'initialisation requis par une opération de nettoyage "écrasement". La longueur de ce fichier sera utilisée comme longueur du motif d'initialisation sauf si l'option --ipl=LEN est utilisée. La longueur du motif d'initialisation doit être comprise entre 1 et la taille du bloc logique du PÉRIPH.
-Q, --quick
l'action par défaut (c'est-à-dire lorsque l'option n'est pas utilisée) consiste à donner à l'utilisateur 15 secondes pour reconsidérer l'opération de nettoyage sur le PÉRIPH. Lorsque cette option est utilisée, cette étape (c'est-à-dire la période d'avertissement de 15 secondes) est ignorée.
-T, --test=TE
définit le champ TEST dans la liste de paramètres de l'action de service d'écrasement. Cela n'affecte que l'opération de nettoyage "écrasement". La valeur par défaut est de placer 0 dans ce champ.
-t, --timeout=SECS
où SECS est le nombre de secondes utilisées pour le délai d'attente de la commande SANITIZE.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wait
l'action par défaut (c'est-à-dire sans cette option et sans l'option --early) consiste à démarrer la commande SANITIZE avec le bit IMMED mis à 1, puis à sonder la progression avec la commande REQUEST SENSE jusqu'à ce que l'opération de nettoyage soit terminée (ou échoue). Lorsque cette option est utilisée (et que l'option --early n'est pas utilisée), la commande SANITIZE est démarrée avec le bit IMMED mis à 0. Pour un grand disque, cela peut prendre des heures. [Une opération d'effacement cryptographique pourrait potentiellement être très rapide.]
-z, --zero
avec une opération de nettoyage "écrasement", cette option entraîne la mise à zéro du motif d'initialisation

EXEMPLES

Pour effectuer un effacement par blocs sur /dev/sdc et attendre la fin :

    sg_sanitize --block --wait /dev/sdc

Pour effectuer un effacement cryptographique sur /dev/sdc, sans attente et avec une durée de temporisation de 1 heure :

    sg_sanitize --crypto --timeout=3600 /dev/sdc

Pour écraser le contenu de /dev/sdc avec le motif contenu dans le fichier pattern.bin, en utilisant le motif inversé entre les passes et en attendant la fin :

    sg_sanitize --overwrite --pattern=pattern.bin --invert --wait /dev/sdc

Pour lancer rapidement un effacement par blocs sur /dev/sdc sans attente et sans message de progression :

    sg_sanitize --block --early /dev/sdc

Pour lancer une opération de nettoyage de type "exit failure mode" sur /dev/sdc :

    sg_sanitize --fail /dev/sdc

Pour lancer l'effacement par blocs sur /dev/sdc, sans délai de sécurité de 15 secondes :

    sg_sanitize --block --quick /dev/sdc

NOTES

La commande SCSI SANITIZE est étroitement liée à la commande ATA SANITIZE, les deux étant relativement nouvelles, la commande ATA étant la première définie. La définition de la traduction SCSI vers ATA (SAT) pour la commande SCSI SANITIZE est apparue dans le projet SAT-3 révision 4.

Lorsqu'une couche SAT est utilisée vers un disque (S)ATA, alors pour OVERWRITE, le motif d'initialisation doit être de 4 octets. Cela signifie donc que l'option --zero peut être donnée, ou un fichier de motif (avec l'option --pattern=PF) qui fait 4 octets de long ou est défini à cette longueur avec l'option --ipl=LEN.

La commande SCSI SANITIZE est liée à la commande SCSI FORMAT UNIT. Il est probable qu'une opération de nettoyage par bloc prenne un temps similaire à un formatage sur le même disque (par exemple, 9 heures pour un disque de 2 téraoctets). L'objectif principal d'un formatage est la configuration du disque à la fin d'un formatage (par exemple, une taille de bloc logique différente ou des informations de protection ajoutées). La suppression des données utilisateur n'est qu'un effet secondaire d'un formatage. Avec la commande SCSI SANITIZE, la suppression des données utilisateur est l'objectif principal. Si une opération de nettoyage est interrompue (par exemple, le disque est mis hors tension puis sous tension), alors après la mise sous tension, toutes les données utilisateur restantes ne seront pas disponibles et l'opération de nettoyage continuera. Lorsqu'un formatage est interrompu (par exemple, le disque est mis hors tension puis sous tension), les projets disent très peu sur l'état du disque. En pratique, certaines des données utilisateur d'origine peuvent rester et le formatage peut devoir être redémarré.

Déterminer si un disque (SCSI ou ATA) prend en charge SANITIZE peut être un défi. Si l'utilisateur a vraiment besoin de le savoir et qu'aucune autre information n'est disponible, essayer 'sg_sanitize --fail -vvv <appareil>' et observer les données de perception renvoyées pourrait être l'approche la plus sûre. L'utilisation de la variante --fail de cet utilitaire ne devrait avoir aucun effet sauf si elle suit une opération de nettoyage déjà échouée. Si la commande SCSI REPORT SUPPORTED OPERATION CODES (voir sg_opcodes) est prise en charge, alors l'utiliser serait une meilleure approche pour savoir si sanitize est pris en charge.

Si vous utilisez la commande dd pour vérifier les données avant et après un bloc particulier (c'est-à-dire vérifier que l'effacement a bien fonctionné), il est conseillé d'utiliser l'opérande 'iflag=direct'. Sinon, la première lecture pourrait être mise en cache et renvoyée lorsque le même LBA est lu un peu plus tard. Il est évident que cet utilitaire ne doit être utilisé que pour nettoyer les données sur un disque dont les systèmes de fichiers montés (le cas échéant) ont été démontés avant l'effacement !

EXEMPLES

Ces exemples utilisent des noms de périphériques Linux. Pour les noms de périphériques appropriés dans d'autres systèmes d'exploitation pris en charge, consultez la page de manuel sg3_utils(8).

Par mesure de précaution, si cet utilitaire est appelé sans option, à part l'affichage d'un message d'utilisation, rien ne se passe :


sg_sanitize /dev/sdm

Pour effectuer un nettoyage par "bloc erase", l'option --block est requise. L'utilisateur disposera d'une période de 15 secondes pour reconsidérer, la commande SCSI SANITIZE sera démarrée avec le bit IMMED défini, puis cet utilitaire interrogera pour une indication de progression avec une commande REQUEST SENSE jusqu'à ce que l'opération de nettoyage soit terminée :


sg_sanitize --block /dev/sdm

Pour démarrer un nettoyage par "bloc erase" et revenir de cet utilitaire une fois qu'il est démarré (mais pas encore terminé), utilisez l'option --early :


sg_sanitize --block --early /dev/sdm

Si le délai de 15 secondes pour reconsidérer n'est pas requis, ajoutez l'option --quick :


sg_sanitize --block --quick --early /dev/sdm

Pour effectuer un nettoyage par "overwrite", un fichier de motif peut être fourni :


sg_sanitize --overwrite --pattern=rand.img /dev/sdm

Si la longueur de ce "rand.img" est de 512 octets (une taille de bloc logique typique), alors pour utiliser seulement les 17 premiers octets (de manière répétée) dans l'opération de nettoyage "overwrite" :


sg_sanitize --overwrite --pattern=rand.img --ipl=17 /dev/sdm

Pour écraser avec des zéros, utilisez :
sg_sanitize --overwrite --zero /dev/sdm

STATUT DE SORTIE

Le statut de sortie de sg_sanitize est 0 en cas de succès. Sinon, consultez la page de manuel sg3_utils(8). Sauf si l'option --wait est donnée, le statut de sortie peut ne pas refléter le succès ou l'échec du formatage.

La convention Unix veut que "pas de nouvelles est bonne nouvelle", mais cela peut être un peu déconcertant après une opération comme le nettoyage, surtout si elle se termine rapidement (c'est-à-dire avant l'envoi du premier sondage de progression). Donner l'option --verbose une fois devrait fournir suffisamment d'informations supplémentaires pour calmer ces nerfs.
