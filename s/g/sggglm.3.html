Documentation de la fonction/sous-routine

sous-routine sggglm (integer n, integer m, integer p, real, dimension( lda, * ) a, integer lda, real, dimension( ldb, * ) b, integer ldb, real, dimension( * ) d, real, dimension( * ) x, real, dimension( * ) y, real, dimension( * ) work, integer lwork, integer info)

SGGGLM

But :

!>
!> SGGGLM résout un problème général de modèle linéaire de Gauss-Markov (GLM) :
!>
!>         minimiser || y ||_2   sous la contrainte   d = A*x + B*y
!>             x
!>
!> où A est une matrice N par M, B est une matrice N par P, et d est un
!> vecteur N donné. On suppose que M <= N <= M+P, et
!>
!>            rang(A) = M    et    rang( A B ) = N.
!>
!> Sous ces hypothèses, l'équation contrainte est toujours
!> cohérente, et il existe une solution unique x et une solution y de norme 2 minimale, qui est obtenue en utilisant une factorisation QR généralisée
!> des matrices (A, B) donnée par
!>
!>    A = Q*(R),   B = Q*T*Z.
!>          (0)
!>
!> En particulier, si la matrice B est carrée non singulière, alors le problème
!> GLM est équivalent au problème des moindres carrés linéaires pondérés suivant
!>
!>              minimiser || inv(B)*(d-A*x) ||_2
!>                  x
!>
!> où inv(B) désigne l'inverse de B.
!>
!> Les appelants de cette sous-routine doivent noter que les vérifications de singularité/déficience de rang
!> implémentées dans cette sous-routine sont rudimentaires. La sous-routine STRTRS appelée par cette
!> sous-routine ne signale un échec dû à la singularité que si le problème est exactement singulier.
!>
!> Il est concevable qu'un (ou plusieurs) des facteurs impliqués dans la factorisation QR généralisée
!> de la paire (A, B) soit subnormalement proche de la singularité sans que cette
!> sous-routine ne signale d'erreur. Les solutions calculées pour de tels problèmes presque déficients en rang
!> peuvent être moins précises en raison d'une perte de précision numérique.
!> 
!>

Paramètres

N 
!>          N est INTEGER
!>          Le nombre de lignes des matrices A et B.  N >= 0.
!>

M

!>          M est INTEGER
!>          Le nombre de colonnes de la matrice A.  0 <= M <= N.
!>

P

!>          P est INTEGER
!>          Le nombre de colonnes de la matrice B.  P >= N-M.
!>

A

!>          A est tableau REAL, dimension (LDA,M)
!>          En entrée, la matrice A de taille N x M.
!>          En sortie, la partie triangulaire supérieure du tableau A contient
!>          la matrice triangulaire supérieure R de taille M x M.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

B

!>          B est tableau REAL, dimension (LDB,P)
!>          En entrée, la matrice B de taille N x P.
!>          En sortie, si N <= P, le triangle supérieur du sous-tableau
!>          B(1:N,P-N+1:P) contient la matrice triangulaire supérieure T de taille N x N ;
!>          si N > P, les éléments sur et au-dessus de la (N-P)-ième sous-diagonale
!>          contiennent la matrice trapézoïdale supérieure T de taille N x P.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,N).
!>

D

!>          D est tableau REAL, dimension (N)
!>          En entrée, D est le membre de gauche de l'équation GLM.
!>          En sortie, D est détruit.
!>

X

!>          X est tableau REAL, dimension (M)
!>

Y

!>          Y est tableau REAL, dimension (P)
!>
!>          En sortie, X et Y sont les solutions du problème GLM.
!>

WORK

!>          WORK est tableau REAL, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la valeur optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,N+M+P).
!>          Pour des performances optimales, LWORK >= M+min(N,P)+max(N,P)*NB,
!>          où NB est une borne supérieure pour les tailles de bloc optimales pour
!>          SGEQRF, SGERQF, SORMQR et SORMRQ.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement la taille optimale du tableau WORK, renvoie
!>          cette valeur comme première entrée du tableau WORK, et aucun message d'erreur
!>          lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est INTEGER
!>          = 0 : sortie réussie.
!>          < 0 : si INFO = -i, le i-ième argument avait une valeur illégale.
!>          = 1 : le facteur triangulaire supérieur R associé à A dans la
!>                factorisation QR généralisée de la paire (A, B) est exactement
!>                singulier, de sorte que rang(A) < M ; la solution des moindres
!>                carrés n'a pas pu être calculée.
!>          = 2 : la partie inférieure (N-M) par (N-M) du facteur trapézoïdal supérieur
!>                T associé à B dans la factorisation QR généralisée
!>                de la paire (A, B) est exactement singulière, de sorte que
!>                rang( A B ) < N ; la solution des moindres carrés n'a pas pu
!>                être calculée.
!>
