NOM

osx - Un convertisseur SGML vers XML

SYNTAXE

osx [-CeghnRvx] [-anom] [-Aarchitecture] [-bencodage] [-cfichier_catalogue] [-drépertoire] [-Drépertoire] [-inom] [-ffichier] [-lfichier_dtd] [-wtype_avertissement] [-xoption_sortie_xml...] [sysid...]

DESCRIPTION

osx convertit SGML en XML. osx analyse et valide le document SGML contenu dans

et écrit un document XML équivalent sur la sortie standard. osx avertira des constructions SGML qui n'ont pas d'équivalent XML.

Fait partie d'un système SGML conforme à la norme internationale ISO 8879 -- Standard Generalized Markup Language. Un système d'extensions SGML conforme à l'annexe A de la norme internationale ISO/IEC 10744 -- Hypermedia/Time-based Structuring Language.

OPTIONS

Les options suivantes sont disponibles :

-anom, --activate=nom

Rend le doctype ou le nom de lien nom actif.

-Anom, --architecture=nom

Analyse par rapport à l'architecture nom.

-bencodage, --encoding=encodage

Utilise l'encodage BCTF pour la sortie. Par défaut, osx utilise UTF-8.

-csysid, --catalog=sysid

Mappe les identificateurs publics et les noms d'entités aux identificateurs système en utilisant le fichier d'entrées de catalogue dont l'identificateur système est sysid.

-C, --catalogs

A le même effet que dans onsgmls(1).

-drépertoire, --entity_output_location=répertoire

Place les fichiers de sortie dans répertoire.

-Drépertoire, --directory=répertoire

Recherche dans répertoire les fichiers spécifiés dans les identificateurs système. A le même effet que dans onsgmls(1).

-e, --open-entities

Décrit les entités ouvertes dans les messages d'erreur.

-Emax_erreurs, --max-errors=max_erreurs

Abandonne après max_erreurs erreurs.

-ffichier, --error-file=fichier

Redirige les erreurs vers fichier. Ceci est principalement utile avec les shells qui ne supportent pas la redirection de stderr.

-g, --open-elements

Décrit les éléments ouverts dans les messages d'erreur.

-h, --help

Affiche un texte d'aide et quitte.

-inom, --include=nom

A le même effet que dans onsgmls(1).

-lfichier_dtd, --dtd_location=fichier_dtd

Spécifie que le fichier XML résultant doit être conforme au DTD dans fichier_dtd.

-n, --error-numbers

Affiche les numéros d'erreur dans les messages d'erreur.

--references

Affiche les références dans les messages d'erreur.

-R, --restricted

A le même effet que dans onsgmls(1).

-v, --version

Affiche le numéro de version et quitte.

-wtype, --warning=type

Contrôle les avertissements et les erreurs selon le type. A le même effet que dans onsgmls(1).

-xoption_sortie_xml, --xml-output-option=option_sortie_xml

Contrôle la sortie XML selon la valeur de option_sortie_xml comme suit :

no-nl-in-tag N'utilise pas de sauts de ligne dans les balises de début. Normalement, osx utilise des sauts de ligne dans les balises de début afin de réduire la probabilité de lignes excessivement longues.

id Affiche les déclarations d'attributs pour les attributs ID.

notation Affiche les déclarations pour les notations.

ndata Affiche les déclarations pour les entités de données externes. XML requiert qu'elles soient NDATA. osx avertira des entités de données externes CDATA et SDATA et les affichera en tant qu'entités NDATA.

cdata Utilise des sections CDATA XML pour les sections marquées CDATA et pour les éléments dont le contenu déclaré est CDATA.

comment Affiche les déclarations de commentaires. Les déclarations de commentaires dans le DTD ne seront pas affichées.

lower Préfère la casse inférieure. Les noms qui ont été soumis à une substitution en majuscules par SGML seront mis en minuscules. Cela n'inclut pas les noms réservés ; XML requiert que ceux-ci soient en majuscules.

pi-escape Échappe les &<> dans le contenu des instructions de traitement en utilisant les entités amp, lt et gt. Ceci permet aux instructions de traitement de contenir la chaîne >?, mais exige que les applications gèrent les échappements.

empty Utilise la syntaxe <e/> pour les types d'éléments e déclarés comme EMPTY.

attlist Affiche une déclaration ATTLIST pour chaque élément spécifiant le type de tous les attributs. La valeur par défaut sera toujours #IMPLIED.

report-input-sources Affiche une instruction de traitement pour signaler quand une source d'entrée autre que le fichier principal est ouverte ou fermée dans l'instance. Ne signale aucun changement de source d'entrée dans le DTD.

report-entities Affiche une instruction de traitement pour signaler quand une référence d'entité externe a été résolue dans l'instance. Ne signale aucune résolution d'entité dans le DTD.

no-expand-external Préserve les entités externes, écrit un fichier de pilote de déclaration nommé "extEntities.dtf", et inclut ce fichier dans le sous-ensemble interne de l'instance.

no-expand-internal Préserve les entités internes, écrit un fichier de pilote de déclaration nommé "intEntities.dtf", et inclut ce fichier dans le sous-ensemble interne de l'instance.

no-external-decl N'inclut pas le fichier de pilote de déclaration des entités externes dans le sous-ensemble interne de l'instance.

no-internal-decl N'inclut pas le fichier de pilote de déclaration des entités internes dans le sous-ensemble interne de l'instance.

no-output-outside-outdir Lors de la préservation des entités externes, n'écrit pas de fichiers de sortie en dehors du répertoire de sortie spécifié ("." par défaut). En d'autres termes, si l'identificateur système d'une entité externe inclut suffisamment d'instances de ".." pour amener osx à écrire un fichier à l'extérieur (au-dessus) du répertoire de sortie, quitte (par défaut, osx émettra un avertissement mais écrira le fichier et continuera).

no-overwrite Lors de la préservation des entités internes ou externes, plusieurs fichiers de sortie seront écrits. Si cette option est spécifiée, ne pas écraser les fichiers existants ; à la place, essayer d'ajouter un numéro à la fin du nom de fichier original pour créer un nom de fichier unique. Quitte avec une erreur si trop de fichiers (100) existent déjà.

preserve-case Préserve la casse spécifiée dans le DTD pour les noms d'éléments ; les noms d'attributs ; les valeurs d'attributs qui sont des listes de jetons.

sdata-as-pis Lors de la traduction des entités SDATA (qu'il s'agisse de les développer ou de fournir une définition pour elles dans le sous-ensemble interne de la sortie), les exprime sous forme d'instructions de traitement plutôt que comme des entités internes générales.

Plusieurs options -x sont autorisées.

NAME

sgml2xml - Convertit un document SGML en XML

SYNOPSIS

sgml2xml [OPTIONS] [FILE...]

DESCRIPTION

La commande sgml2xml est un outil de conversion qui permet de transformer des documents SGML (Standard Generalized Markup Language) en documents XML (Extensible Markup Language). Elle est particulièrement utile pour migrer du contenu SGML existant vers le format XML, qui est devenu une norme prédominante pour le balisage de données.

L'outil analyse le fichier SGML d'entrée, applique les règles de conversion et génère un fichier XML valide en sortie. Il peut gérer différents types de documents SGML et leursDTD (Document Type Definitions) associées.

OPTIONS

Les options suivantes sont disponibles :

  • -o, --output=FICHIER : Spécifie le nom du fichier de sortie. Si cette option n'est pas utilisée, la sortie sera envoyée sur la sortie standard.
  • -d, --dtd=DTD : Spécifie le chemin vers le fichier DTD à utiliser pour la validation et la conversion.
  • -e, --entities=FICHIER : Spécifie un fichier d'entités pour la résolution des entités SGML.
  • -n, --no-declaration : N'inclut pas la déclaration XML dans le fichier de sortie.
  • -p, --pretty-print : Formate la sortie XML de manière lisible avec indentation.
  • -v, --verbose : Affiche des informations détaillées sur le processus de conversion.
  • -h, --help : Affiche l'aide et quitte.
  • -V, --version : Affiche les informations de version et quitte.
