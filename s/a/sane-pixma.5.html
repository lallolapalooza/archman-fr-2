sane-pixma(5) SANE Scanner Access Now Easy sane-pixma(5)

NOM

sane-pixma - Backend SANE pour les imprimantes multifonctions Canon et les scanners CanoScan

DESCRIPTION

La bibliothèque sane-pixma implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux appareils multifonctions Canon PIXMA / i-SENSYS / imageCLASS / imageRUNNER (imprimantes tout-en-un) et aux scanners à plat / TPU Canon CanoScan. Le backend implémente l'interface USB ainsi que l'interface réseau (utilisant les protocoles BJNP et MFNP de Canon). L'interface réseau prend en charge les scanners sur IPv4 ainsi que sur IPv6 (MFNP sur IPv6 n'a pas été testé).

Le backend prend en charge :

* des résolutions de 75, 150, 300, 600, 1200, 2400, 4800 et 9600 DPI (certaines peuvent être boguées),
* les modes couleur et niveaux de gris, ainsi que le mode lineart sur certains modèles,
* une table gamma personnalisée,
* un chargeur automatique de documents, simplex et duplex,
* une unité de numérisation de transparents, profondeur de 24 ou 48 bits. Canal infrarouge sur certains modèles.

Le nom de l'appareil pour les appareils USB est de la forme pixma:xxxxyyyy_zzzzz où x, y et z sont l'identifiant du vendeur, l'identifiant du produit et le numéro de série respectivement.

Exemple : pixma:04A91709_123456 est un MP150.

Les noms des appareils BJNP/MFNP sont de la forme pixma:aaaa_bbbbb où aaaa est le modèle du scanner et bbbb est le nom d'hôte ou l'adresse IP.

Exemple : pixma:MF4800_192.168.1.45 est un périphérique multifonction de la série MF4800.

Ce backend, basé sur le clonage des protocoles des pilotes Canon originaux, est en phase de production. La conception a été réalisée sans aucune documentation fabricant applicable, probablement jamais disponible. Cependant, nous l'avons testé du mieux que nous avons pu, mais il peut ne pas fonctionner dans toutes les situations. Vous trouverez un état à jour sur la page d'accueil du projet. (Voir ci-dessous). Les retours des utilisateurs sont essentiels pour aider à améliorer les fonctionnalités et les performances.

OPTIONS

En plus des options « bien connues » (par exemple, résolution, mode, etc.), le backend sane-pixma propose également les options suivantes. Notez que les options peuvent changer à l'avenir.
L'état des boutons peut être interrogé, par exemple avec scanimage -A.
La numérisation des boutons est désactivée sur MAC OS X en raison de la bibliothèque libusb darwin qui ne gère pas les délais dans les lectures d'interruptions USB, mais peut fonctionner lors de l'utilisation du protocole réseau.

adf-wait
Cette option active et définit le temps en secondes d'attente pour un document inséré dans le chargeur automatique de documents (Automatic Document Feeder). Le temps d'attente maximum autorisé est de 3600 secondes (= 1 heure).
button-controlled
Cette option peut être utilisée par les applications (comme scanadf(1) et scanimage(1)) en mode batch, par exemple lorsque vous souhaitez numériser de nombreuses photos ou des documents de plusieurs pages. Si elle est activée (c'est-à-dire définie sur true ou yes), le backend attend avant chaque numérisation jusqu'à ce que l'utilisateur appuie sur le bouton « SCAN » (pour le MP150) ou le bouton de numérisation couleur (pour les autres modèles). Placez simplement la première page dans le scanner, appuyez sur le bouton, puis la page suivante, appuyez sur le bouton, et ainsi de suite. Lorsque vous avez terminé, appuyez sur le bouton de numérisation gris. (Pour le MP150, vous devez arrêter le frontend en appuyant sur Ctrl-C par exemple.)
button-update (obsolète)
(en écriture uniquement) Dans le passé, cette option devait être définie pour forcer la lecture de l'état des boutons pour button-1 et button-2. Le backend sane-pixma n'exige plus l'utilisation de cette option : si aucune donnée récente n'est disponible, elle sera désormais demandée automatiquement au scanner. Cette option est laissée pour des raisons de compatibilité ascendante.
button-1 button-2
(en lecture seule) Ces options retourneront la valeur des boutons respectifs. La valeur 0 signifie que le bouton n'a pas été pressé, 1 est retourné lorsque le bouton a été pressé. Certains scanners, avec plus de deux boutons, renvoient le numéro du bouton comme cible.
original
(en lecture seule) Retourne la valeur du type ou de la taille de l'original à numériser si le scanner fournit ces données. Valeurs connues du type : 1 = document, 2 = photo, 5 = film. Valeurs connues de la taille : 1 = A4, 2 = Letter, 8 = 10x15, 9 = 13x18, b = auto. Tous les scanners ne peuvent pas fournir ces données.
target
(en lecture seule) Retourne la valeur de la cible de l'opération de numérisation si le scanner fournit ces données. Les valeurs dépendent du scanner t

FICHIERS

/usr/lib/sane/libsane-pixma.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-pixma.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).
/etc/sane.d/pixma.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous).

Le fichier contient une liste facultative de scanners réseau utilisant les protocoles BJNP ou MFNP (Voir ci-dessous pour les détails sur la prise en charge réseau des scanners). Normalement, seuls les scanners qui ne peuvent pas être auto-détectés car ils sont sur un sous-réseau différent doivent être listés ici. Si vous n'utilisez pas Linux et que votre système d'exploitation ne permet pas l'énumération des interfaces (c'est-à-dire qu'il ne prend pas en charge la fonction getifaddrs()), vous devrez peut-être également ajouter votre scanner ici.

Les scanners doivent être listés dans le fichier de configuration comme suit :

<méthode>://<hôte>[:port][/timeout=<valeur>]
méthode
indique le protocole utilisé. bjnp est utilisé pour les multifonctions à jet d'encre et mfnp est utilisé pour les multifonctions laser).
hôte
est le nom d'hôte ou l'adresse IP du scanner, par exemple bjnp://10.0.1.4 pour IPv4, bjnp://[2001:888:118e:18e2:21e:8fff:fe36:b64a] pour une adresse IPv6 littérale ou bjnp://monsccanner.mondomaine.org pour un nom d'hôte.
port
est facultatif et est normalement implicite par la méthode. Le port 8610 est le port standard pour mfnp, 8612 pour bjnp.
timeout
valeur de temporisation spécifique au scanner pour le protocole réseau. La valeur est en ms.

Définissez chaque scanner sur une ligne séparée.

Des temporisations plus globales peuvent être définies en utilisant le paramètre bjnp-timeout comme suit :

bjnp-timeout=<valeur>

Une temporisation définie à l'aide de bjnp-timeout s'appliquera aux définitions de scanners suivantes dans le fichier. Si nécessaire, le paramètre bjnp-timeout peut être défini plusieurs fois, chaque paramètre s'appliquant uniquement aux scanners qui suivent ce paramètre. Le dernier paramètre est utilisé pour les scanners auto-détectés. S'il n'est pas explicitement défini, le paramètre par défaut de 1000 ms s'appliquera.

La définition des temporisations ne devrait être nécessaire que dans des cas exceptionnels.

Si vous le souhaitez, le réseau peut être désactivé comme suit :

networking=no
Si la première ligne non commentée contient cette entrée, tout le réseau sera désactivé. Toutes les instructions supplémentaires dans le fichier de configuration seront ignorées.
auto_detection=no
Cette ligne provoquera le saut de l'auto-détection. Les scanners réseau explicitement définis seront toujours sondés.

SUPPORT USB

Les scanners USB seront auto-détectés et ne nécessiteront aucune configuration.

SUPPORT RÉSEAU

Le backend sane-pixma prend en charge les scanners réseau en utilisant les protocoles dits Canon BJNP et MFNP.

Canon semble abandonner le support de ces protocoles sur les scanners récents. Pour vérifier si votre scanner prend en charge l'un de ces protocoles, consultez le contenu de l'entrée de service _scanner._tcp dans mDNS/DNS-SD (en utilisant par exemple avahi-discover(1)). Si cela ne liste pas le port 8610 ou 8612, votre scanner ne prend probablement pas en charge les protocoles mfmp ou bjnp.

IPv4 et IPv6 sont tous deux pris en charge, mais IPv6 n'est pas encore testé avec MFNP. Veuillez signaler vos résultats sur la liste de diffusion.

La configuration n'est normalement pas requise. Le backend sane-pixma auto-détectera votre scanner s'il se trouve dans le même sous-réseau que votre ordinateur si votre système d'exploitation le prend en charge.

Si votre scanner ne peut pas être auto-détecté, vous pouvez l'ajouter au fichier de configuration sane-pixma (voir ci-dessus).

PAREFEU POUR SCANNEURS EN RÉSEAU

Le backend sane-pixma communique avec le port 8610 pour MFNP ou le port 8612 pour BJNP sur le scanner. Vous devrez donc autoriser le trafic sortant VERS le port 8610 ou 8612 sur le sous-réseau commun pour la numérisation.

La détection du scanner est légèrement plus compliquée. Le backend sane-pixma envoie une diffusion sur tous les sous-réseaux directement connectés qu'il trouve (à condition que votre système d'exploitation permette l'énumération de toutes les interfaces réseau). La diffusion est envoyée DU port 8612 AU port 8610 ou 8612 sur l'adresse de diffusion de chaque interface. Les paquets sortants seront autorisés par la règle décrite ci-dessus.

Les réponses du scanner sont renvoyées à l'ordinateur VERS le port 8612. Le suivi de connexion ne voit cependant pas de correspondance car la réponse ne provient pas de l'adresse de diffusion mais de la propre adresse du scanner. Pour la détection automatique de votre scanner, vous devrez donc autoriser les paquets entrants VERS le port 8612 sur votre ordinateur. Cela s'applique aux deux, MFNP et BJNP.

En bref : ouvrez le pare-feu pour tout le trafic de votre ordinateur vers le port 8610 (pour MFNP) ou 8612 (pour BJNP) ET vers le port 8612 (pour BJNP et MFNP) sur votre ordinateur.

Avec les règles de pare-feu ci-dessus, il n'est pas nécessaire d'ajouter le scanner au fichier pixma.conf, sauf si le scanner se trouve sur un réseau qui n'est pas directement connecté à votre ordinateur.

ENVIRONNEMENT

SANE_DEBUG_PIXMA
Si la bibliothèque a été compilée avec la prise en charge du débogage activée, cette variable d'environnement contrôle le niveau de débogage pour ce backend lui-même. Une valeur plus élevée augmente la verbosité et inclut les informations imprimées aux niveaux inférieurs.
0 n'imprime rien (par défaut)
1 imprime les messages d'erreur et d'avertissement (recommandé)
2 imprime les messages d'information
3 imprime les messages de niveau de débogage
4 imprime les messages de débogage détaillés
11 dump du trafic USB
21 dump complet du trafic USB
SANE_DEBUG_BJNP
Si la bibliothèque a été compilée avec la prise en charge du débogage activée, cette variable d'environnement contrôle le niveau de débogage pour les protocoles réseau BJNP et MFNP pour ce backend. Une valeur plus élevée augmente la verbosité et inclut les informations imprimées aux niveaux inférieurs.
0 n'imprime rien (par défaut)
1 Imprime les messages d'erreur et d'avertissement (recommandé)
2 Imprime les informations de traçage des fonctions de haut niveau
3 Imprime des informations de traçage de protocole plus détaillées
4 Imprime les en-têtes de protocole
5 Imprime le contenu complet du protocole
PIXMA_EXPERIMENT
Le réglage à une valeur non nulle activera la prise en charge expérimentale pour d'autres modèles. Vous devriez également régler SANE_DEBUG_PIXMA sur 11.
SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par un deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR sur "/tmp/config:" entraînerait la recherche des répertoires tmp/config, . et /etc/sane.d (dans cet ordre).
