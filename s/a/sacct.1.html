sacct(1) Commandes Slurm sacct(1)

NOM

sacct - affiche les données de comptabilité pour tous les travaux et étapes de travaux dans le journal de comptabilité des travaux Slurm ou la base de données Slurm

SYNOPIS

sacct [OPTIONS...]

DESCRIPTION

Les informations de comptabilité pour les travaux invoqués avec Slurm sont soit enregistrées dans le fichier journal de comptabilité des travaux, soit sauvegardées dans la base de données Slurm, selon la configuration du paramètre AccountingStorageType.

La commande sacct affiche les données de comptabilité des travaux stockées dans le fichier journal de comptabilité des travaux ou dans la base de données Slurm sous diverses formes pour votre analyse. Par défaut, la commande sacct affiche des informations sur les travaux, les étapes de travaux, l'état et les codes de sortie. Vous pouvez personnaliser la sortie en utilisant l'option --format= pour spécifier les champs à afficher.

Les enregistrements de travaux consistent en une entrée principale pour le travail dans son ensemble ainsi que des entrées pour les étapes de travaux. La page Job Launch contient une description plus détaillée de chaque type d'étape de travail. https://slurm.schedmd.com/job_launch.html#job_record

Pour l'utilisateur root, la commande sacct affiche les données de comptabilité des travaux de tous les utilisateurs, bien qu'il existe des options pour filtrer la sortie afin de ne rapporter que les travaux d'un utilisateur ou groupe spécifié.

Pour l'utilisateur non-root, la commande sacct limite l'affichage des données de comptabilité des travaux aux travaux qui ont été lancés avec leur propre identifiant d'utilisateur (UID) par défaut. Les données d'autres utilisateurs peuvent être affichées avec les options --allusers, --user ou --uid.

Les champs de temps écoulé sont présentés sous la forme [jours-]heures:minutes:secondes[.microsecondes]. Seuls les champs 'CPU' peuvent contenir des microsecondes.

NOTE: Si désigné, l'option PrivateData de slurmdbd.conf peut restreindre davantage les données comptables visibles par les utilisateurs qui ne sont pas SlurmUser, root, ou un utilisateur avec AdminLevel=Admin. Voir la page de manuel slurmdbd.conf pour des détails supplémentaires sur la restriction d'accès aux données comptables.

NOTE: Le contenu de la base de données de Slurm est conservé en minuscules. Cela peut entraîner des différences entre la sortie de sacct et celle des autres commandes Slurm.

NOTE: Une grande partie des données rapportées par sacct a été générée par les appels système wait3() et getrusage(). Certains systèmes collectent et rapportent des informations incomplètes pour ces appels ; sacct rapporte des valeurs de 0 pour ces données manquantes. Consultez la page de manuel getrusage (3) de votre système pour savoir quelles données sont réellement disponibles sur votre système.

OPTIONS

-A, --accounts=<liste_comptes>
Affiche les travaux lorsqu'une liste de comptes séparés par des virgules est fournie comme argument.
--array
Développe les tableaux de travaux. Affiche toutes les tâches du tableau sur des lignes séparées au lieu d'afficher des groupes de tâches du tableau sur des lignes uniques.
-L, --allclusters
Affiche les travaux exécutés sur tous les clusters. Par défaut, seuls les travaux exécutés sur le cluster d'où sacct est appelé sont affichés.
-X, --allocations
Affiche uniquement les statistiques pertinentes pour l'allocation du travail elle-même, sans prendre en compte les étapes.

NOTE: Sans inclure les étapes, les statistiques d'utilisation pour l'allocation ou les allocations de travaux seront rapportées comme nulles.

-a, --allusers
Affiche les travaux de tous les utilisateurs lorsqu'il est exécuté par l'utilisateur root ou si PrivateData n'est pas configuré sur jobs. Sinon, affiche les travaux de l'utilisateur actuel.
-x, --associations=<liste_assocs>
Affiche les statistiques uniquement pour les travaux s'exécutant sous les identifiants d'association spécifiés par l'opérande liste_assocs, qui est une liste d'identifiants d'association séparés par des virgules. Les espaces ne sont pas autorisés dans liste_assocs. Par défaut, toutes les associations sont prises en compte.
-B, --batch-script
Cette option imprimera le script batch du travail s'il en a utilisé un. Si le travail n'avait pas de script, 'NONE' sera affiché.
NOTE: AccountingStoreFlags=job_script est requis pour cela.
NOTE: Il est requis de demander des travaux spécifiques avec '-j' pour cela.
-b, --brief
Affiche une liste brève composée de JobID, State et ExitCode.
-M, --clusters=<liste_clusters>
Affiche les statistiques uniquement pour les travaux démarrés sur les clusters spécifiés par l'opérande liste_clusters, qui est une liste de clusters séparés par des virgules. Les espaces ne sont pas autorisés dans liste_clusters. Une valeur de 'all' interrogera tous les clusters. Par défaut, le cluster actuel sur lequel vous exécutez la commande sacct ou tous les clusters de la fédération lors de l'exécution sur un cluster fédéré. Cette option active implicitement l'option --local.
-c, --completion
Utilise les données de complétion des travaux au lieu de la comptabilité des travaux. Le paramètre JobCompType dans le fichier slurm.conf doit être défini sur une option autre que 'none'. Ne prend pas en charge les informations des clusters fédérés (données locales uniquement).
-C, --constraints=<liste_contraintes>
Liste séparée par des virgules pour filtrer les travaux en fonction des contraintes/fonctionnalités demandées par le travail. Plusieurs options seront traitées comme un 'et' et non comme un 'ou', donc le travail devrait avoir toutes les contraintes spécifiées pour être retourné, pas l'une ou l'autre.
--delimiter=<caractères>
Caractères ASCII utilisés pour séparer les champs lors de la spécification des options -p ou -P. Le délimiteur par défaut est '|'. Cette option est ignorée si les options -p ou -P ne sont pas spécifiées.
-D, --duplicates
Si les identifiants de travaux Slurm sont réinitialisés, certains numéros de travaux apparaîtront probablement plus d'une fois dans le fichier journal de comptabilité mais feront référence à des travaux différents. Ces travaux peuvent être distingués par le horodatage de "soumission" dans les enregistrements de données.

Lorsque des données pour des travaux spécifiques sont demandées avec l'option --jobs, sacct renvoie le travail le plus récent avec ce numéro. Ce comportement peut être remplacé en spécifiant --duplicates, auquel cas tous les enregistrements qui correspondent aux critères de sélection seront renvoyés.

NOTE: Les travaux frères fédérés révoqués sont cachés à moins que l'option --duplicates ne soit spécifiée.

-E, --endtime=<heure_fin>
Sélectionne les travaux dans n'importe quel état avant l'heure spécifiée. Si des états sont donnés avec l'option -s, renvoie les travaux dans cet état avant cette période. Voir la section FENÊTRE TEMPORELLE PAR DÉFAUT (ci-dessous) pour savoir comment les valeurs par défaut de --starttime et --endtime sont déterminées.

YYYY-MM-DD[THH:MM[:SS]]
today, midnight, noon, elevenses (11 AM), fika (3 PM), teatime (4 PM)
now[{+|-}count[seconds(default)|minutes|hours|days|weeks]]

NOTE: AccountingStoreFlags=job_env est requis pour cela.

par exemple, format=name%30 imprimera 30 caractères du champ nom justifié à droite. Un %-30 imprimera 30 caractères justifiés à gauche.

Lorsqu'elle est définie, la variable d'environnement SACCT_FORMAT remplacera le format par défaut. Par exemple :

NOTE: Ce n'est pas fiable lorsque des nœuds sont ajoutés ou supprimés de Slurm pendant que des travaux sont en cours d'exécution. Seuls les travaux qui ont démarré dans la plage horaire spécifiée (-S, -E) seront retournés.

Liste de partitions séparées par des virgules pour sélectionner les travaux et les étapes de travaux. La valeur par défaut est toutes les partitions.
-q, --qos

-R, --reason=<liste_raisons>
Liste séparée par des virgules pour filtrer les travaux en fonction de la raison pour laquelle le travail n'a pas été planifié en dehors des ressources/priorités.

Sélectionner les travaux dans n'importe quel état après l'heure spécifiée. La valeur par défaut est 00:00:00 du jour actuel, sauf si les options '-s' ou '-j' sont utilisées. Si l'option '-s' est utilisée, la valeur par défaut est 'now'. Si des états sont donnés avec l'option '-s', seuls les travaux dans cet état à ce moment seront retournés. Si l'option '-j' est utilisée, l'heure par défaut est l'époque Unix 0. Voir la section FENÊTRE DE TEMPS PAR DÉFAUT (ci-dessous) pour plus de détails sur la façon dont les valeurs par défaut pour --starttime et --endtime sont déterminées.

MM/DD[/AA][-HH:MM[:SS]]
AAAA-MM-JJ[THH:MM[:SS]]
today, midnight, noon, elevenses (11h), fika (15h), teatime (16h)
now[{+|-}count[seconds(défaut)|minutes|hours|days|weeks]]

-s, --state=<liste_états>
Sélectionne les travaux en fonction de leur état pendant la période donnée. Sauf indication contraire, l'heure de début et de fin sera l'heure actuelle lorsque l'option --state est spécifiée et seuls les travaux en cours d'exécution peuvent être affichés. Une heure de début et/ou de fin doit être spécifiée pour consulter les informations sur les travaux qui ne sont pas en cours d'exécution. Voir la section CODES D'ÉTAT DES TRAVAUX ci-dessous pour une liste des désignateurs d'état. Plusieurs noms d'état peuvent être spécifiés à l'aide de séparateurs de virgules. La forme courte ou longue du nom d'état peut être utilisée (par exemple, CA ou CANCELLED) et le nom n'est pas sensible à la casse (c'est-à-dire que ca et CA fonctionnent tous deux).

NOTE: Pour qu'un travail soit sélectionné dans l'état PENDING, il doit avoir "EligibleTime" dans l'intervalle de temps demandé ou différent de "Unknown". L'"EligibleTime" est affiché par la commande "scontrol show job". Par exemple, les travaux soumis avec l'option "--hold" auront "EligibleTime=Unknown" car ils sont en attente indéfiniment.

NOTE: Lorsque des états sont spécifiés et qu'aucune heure de début n'est donnée, l'heure de début par défaut est 'now'. Ceci n'est le cas que lorsque -j n'est pas utilisé. Si -j est utilisé, l'heure de début sera par défaut 'Epoch'. Dans les deux cas, si aucune heure de fin n'est donnée, elle sera par défaut 'now'. Voir la section FENÊTRE DE TEMPS PAR DÉFAUT (ci-dessous) pour plus de détails sur la façon dont cette option modifie les valeurs par défaut pour --starttime et --endtime.

-K, --timelimit-max
Ignoré seul, mais si timelimit_min est défini, ce sera le délai d'expiration maximum de la plage. La valeur par défaut est aucune restriction.
-k, --timelimit-min
N'envoyer des données que pour les travaux avec ce délai d'expiration. Si utilisé avec timelimit_max, ce sera le délai d'expiration minimum de la plage. La valeur par défaut est aucune restriction.
-T, --truncate
Tronquer le temps. Ainsi, si un travail a commencé avant --starttime, l'heure de début sera tronquée à --starttime. Idem pour l'heure de fin et --endtime.
-u, --uid=, --user=<liste_uid_ou_utilisateur>
Utiliser cette liste d'UID ou de noms d'utilisateurs séparés par des virgules pour sélectionner les travaux à afficher. Par défaut, l'UID de l'utilisateur en cours d'exécution est utilisé.
--units=[KMGTP]
Afficher les valeurs dans le type d'unité spécifié. A la priorité sur l'option --noconvert.
--usage
Afficher un résumé de l'utilisation de la commande.
--use-local-uid
Lors de l'affichage de l'UID, sacct utilise par défaut l'UID stocké dans la base de données de comptabilité de Slurm. Utilisez cette commande pour que Slurm utilise un appel système afin d'obtenir l'UID à partir du nom d'utilisateur. Cette option peut être utile dans un environnement avec plusieurs clusters et une seule base de données où les UID ne sont pas les mêmes sur tous les clusters.
-v, --verbose
Principalement à des fins de débogage, signaler l'état de diverses variables pendant le traitement.
-V, --version
Afficher la version.
-W, --wckeys=<liste_wckey>
Affiche les statistiques uniquement pour les travaux démarrés sur les wckeys spécifiés par l'opérande liste_wckey, qui est une liste de noms de wckeys séparés par des virgules. Les espaces ne sont pas autorisés dans la liste_wckey. La valeur par défaut est tous les wckeys.
--whole-hetjob[=yes|no]
Lors de la requête et du filtrage des travaux hétérogènes avec --jobs, Slurm récupérera par défaut des informations sur tous les composants du travail si l'id du travail hétérogène (id du leader) est sélectionné. Si un id de composant de travail hétérogène non leader est sélectionné, seul ce composant est récupéré par défaut. Ce comportement peut être modifié en utilisant cette option. Si elle est définie sur 'yes' (ou sans argument), les informations sur tous les composants seront récupérées, quel que soit le composant sélectionné dans le filtre de travail. Si elle est définie sur 'no', seuls les composants de travail hétérogènes sélectionnés seront récupérés, même lors de la sélection du leader.
--yaml, --yaml=liste, --yaml=<data_parser>
Vider les informations du travail au format YAML en utilisant le plugin data_parser par défaut ou un data_parser explicite avec des paramètres. Les arguments de tri et de formatage seront ignorés.

Champs de comptabilisation des travaux

Les descriptions de chaque option de champ se trouvent ci-dessous. Notez que les champs de comptabilisation Ave*, Max* et Min* examinent les valeurs de toutes les tâches de chaque étape d'un travail et retournent les valeurs moyenne, maximale ou minimale de la tâche pour cette étape de travail. Par exemple, pour MaxRSS, la valeur retournée est la consommation mémoire maximale observée par l'une des tâches de l'étape, et MaxRSSTask montre de quelle tâche il s'agit.

ALL
Imprimer tous les champs listés ci-dessous.
Account
Le compte sous lequel le travail s'est exécuté.
AdminComment
Une chaîne de commentaire sur un travail qui doit être définie par un administrateur, le SlurmUser ou root.
AllocCPUs
Nombre de CPUs alloués. Équivalent à NCPUS.
AllocNodes
Nombre de nœuds alloués au travail/à l'étape. 0 si le travail est en attente.
AllocTres
Ressources traçables. Ce sont les ressources allouées au travail/à l'étape après que le travail a commencé à s'exécuter. Pour les travaux en attente, cela doit être vide. Pour plus de détails, voir AccountingStorageTRES dans slurm.conf.

NOTE: Lorsqu'une ressource générique est configurée avec le drapeau no_consume, l'allocation sera imprimée avec un zéro.

AssocID
Référence à l'association de l'utilisateur, du compte et du cluster.
AveCPU
Temps CPU moyen (système + utilisateur) de toutes les tâches du travail.
AveCPUFreq
Fréquence CPU moyenne pondérée de toutes les tâches du travail, en kHz.
AveDiskRead
Nombre moyen d'octets lus par toutes les tâches du travail.
AveDiskWrite
Nombre moyen d'octets écrits pa
All tasks in job.

Nombre moyen de fautes de page de toutes les tâches dans le job.

Taille moyenne de l'ensemble résident de toutes les tâches dans le job.

Taille moyenne de la mémoire virtuelle de toutes les tâches dans le job.

Comment
Le commentaire du job lorsque le paramètre AccountingStoreFlags dans le fichier slurm.conf contient 'job_comment'. La chaîne Comment peut être modifiée en invoquant sacctmgr modify job ou la commande spécialisée sjobexitmod.
Constraints
Fonction(s) demandée(s) par le job comme contrainte.
ConsumedEnergy
Énergie totale consommée par toutes les tâches d'un job, en joules. La valeur peut inclure un préfixe d'unité (K, M, G, T, P). Remarque : Ce n'est que dans le cas d'une allocation de job exclusive que cette valeur reflète la consommation d'énergie réelle du job.
ConsumedEnergyRaw
Énergie totale consommée par toutes les tâches d'un job, en joules. Remarque : Ce n'est que dans le cas d'une allocation de job exclusive que cette valeur reflète la consommation d'énergie réelle du job.
Container
Chemin vers le bundle de conteneur OCI demandé.
CPUTime
Temps utilisé (temps écoulé * nombre de CPU) par un job ou une étape au format HH:MM:SS .
CPUTimeRAW
Temps utilisé (temps écoulé * nombre de CPU) par un job ou une étape en secondes CPU.
DBIndex
Index de base de données unique pour les entrées dans la table des jobs.
DerivedExitCode
Le code de sortie le plus élevé renvoyé par les étapes du job (invocations srun). Après les deux-points se trouve le signal qui a provoqué la terminaison du processus s'il a été terminé par un signal. FENÊTRE_TEMPORELLE_PAR_DÉFAUT

Les options --starttime et --endtime définissent la fenêtre temporelle entre laquelle sacct va rechercher. Pour des raisons historiques et pratiques, leurs valeurs par défaut (c'est-à-dire la fenêtre temporelle par défaut) dépendent d'autres options : --jobs et --state.

Selon que --jobs et/ou --state sont spécifiés, les valeurs par défaut des options --starttime et --endtime sont :

SANS NI --jobs NI --state spécifiés :
--starttime vaut par défaut Minuit.
--endtime vaut par défaut Maintenant.

AVEC --jobs ET SANS --state spécifiés :
--starttime vaut par défaut Époque 0.
--endtimevaut par défaut Maintenant.

SANS --jobs ET AVEC --state spécifiés :
--starttimevaut par défaut Maintenant.
--endtimevaut par défaut --starttime et Maintenant si --starttime n'est pas spécifié.

AVEC LES DEUX --jobs ET --state spécifiés :
--starttimevaut par défaut Époque 0.
--endtimevaut par défaut --starttime ou Maintenant si --starttime n'est pas spécifié.

NOTE : Avec -v/--verbose, un message concernant la fenêtre temporelle réellement utilisée est affiché.

PERFORMANCE

L'exécution de sacct envoie un appel de procédure distante (RPC) à slurmdbd. Si suffisamment d'appels de sacct ou d'autres commandes client Slurm envoyant des RPC au démon slurmdbd arrivent en même temps, cela peut entraîner une dégradation des performances du démon slurmdbd, entraînant potentiellement un déni de service.

N'exécutez pas sacct ou d'autres commandes client Slurm qui envoient des RPC à slurmdbd à partir de boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à sacct au minimum nécessaire pour les informations que vous essayez de collecter.

4.0                   srun       acct1               1 COMPLETED         0

Cet exemple montre les mêmes informations de comptabilité des travaux avec l'option brief.

# sacct --brief
     Jobid     State  ExitCode
---------- ---------- --------
2          RUNNING           0
3          RUNNING           0
4          RUNNING           0
4.0        COMPLETED         0
# sacct --allocations
Jobid      Jobname    Partition Account    AllocCPUS  State     ExitCode
---------- ---------- ---------- ---------- ------- ---------- --------
3          sja_init   andy       acct1            1 COMPLETED         0
4          sjaload    andy       acct1            2 COMPLETED         0
5          sja_scr1   andy       acct1            1 COMPLETED         0
6          sja_scr2   andy       acct1           18 COMPLETED         2

9          sja_scr7   andy       acct1           90 COMPLETED         1
10         endscript  andy       acct1          186 COMPLETED         0

Cet exemple démontre la capacité de personnaliser la sortie de la commande sacct. Les champs sont affichés dans l'ordre spécifié sur la ligne de commande.

# sacct --format=jobid,elapsed,ncpus,ntasks,state
     Jobid    Elapsed      Ncpus   Ntasks     State
---------- ---------- ---------- -------- ----------
3            00:01:30          2        1 COMPLETED
3.0          00:01:30          2        1 COMPLETED
4            00:00:00          2        2 COMPLETED
4.0          00:00:01          2        2 COMPLETED
5            00:01:23          2        1 COMPLETED
5.0          00:01:31          2        1 COMPLETED

Cet exemple démontre l'utilisation de l'option -T (--truncate) lorsqu'elle est utilisée avec -S (--starttime) et -E (--endtime). Lorsque l'option -T est utilisée, l'heure de début du travail sera la valeur -S spécifiée si le travail a été démarré avant le spécifi

ied time, otherwise the time will be the job's start time. The end time will be the specified -E option if the job ends after the specified time, otherwise it will be the jobs end time.

Sans -T (opération normale), la sortie de sacct ressemblerait à ceci.

# sacct -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,start,end,state
    JobID                 Start                  End        State
--------- --------------------- -------------------- ------------
2         2014-07-03T11:33:16   2014-07-03T11:59:01   COMPLETED
3         2014-07-03T11:35:21   Unknown               RUNNING
4         2014-07-03T11:35:21   2014-07-03T11:45:21   COMPLETED
5         2014-07-03T11:41:01   Unknown               RUNNING

En ajoutant l'option -T, les heures de début et de fin du job sont tronquées pour refléter uniquement l'heure demandée. Si un job a commencé après l'heure de début demandée ou s'est terminé avant l'heure de fin demandée, ces heures ne sont pas modifiées. L'option -T est utile pour déterminer les temps d'exécution exacts pendant une période donnée.

# sacct -T -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,jobname,user,start,end,state
    JobID                 Start                  End        State
--------- --------------------- -------------------- ------------
2         2014-07-03T11:40:00   2014-07-03T11:59:01   COMPLETED
3         2014-07-03T11:40:00   2014-07-03T12:00:00   RUNNING
4         2014-07-03T11:40:00   2014-07-03T11:45:21   COMPLETED
5         2014-07-03T11:41:01   2014-07-03T12:00:00   RUNNING

NOTE : Si aucune option -s (--state) n'est fournie, sacct affichera les jobs éligibles pendant la période de temps spécifiée, sinon il renverra les jobs qui étaient dans l'état demandé pendant cette période.

Cet exemple démontre les différences entre l'exécution de sacct avec et sans le drapeau --state pour la même période de temps. Sans l'option --state, tous les jobs éligibles de cette période sont affichés.

# sacct -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
       JobID               Start                 End      State
------------ ------------------- ------------------- ----------
2955                    11:15:12            11:20:12  COMPLETED
2956                    11:20:13            11:25:13  COMPLETED

Avec l'option --state=pending, seul le job 2956 sera affiché car il dépendait du job 2955 et était toujours PENDING de 11:20:00 jusqu'à ce qu'il démarre à 11:21:13. Notez que même si nous avons demandé des jobs PENDING, l'état affiché est COMPLETED car c'est l'état actuel du job.

# sacct --state=pending -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
       JobID               Start                 End      State
------------ ------------------- ------------------- ----------
2956                    11:20:13            11:25:13  COMPLETED

FILES

/etc/slurm.conf
Les entrées de ce fichier activent la comptabilité des jobs et désignent le fichier journal de comptabilité des jobs qui collecte la comptabilité des jobs du système.
/var/log/slurm_accounting.log
Le fichier journal de comptabilité des jobs par défaut. Par défaut, ce fichier a des permissions de lecture et d'écriture uniquement pour l'utilisateur root.
