NOM

sap - Spécification de point d'accès au service

DESCRIPTION

Les fonctions text2sap et sap2text utilisent le format décrit dans cette page de manuel. Comme tous les outils ATM standards sous Linux utilisent ces fonctions pour convertir vers ou depuis la représentation textuelle des spécifications SAP, ils s'attendent également à ce format.

Le SAP est divisé en deux parties : les informations de couche supérieure haut débit (BHLI) et les informations de couche inférieure haut débit (BLLI). Un SAP peut contenir l'une, les deux, ou aucune d'entre elles. Dans ce dernier cas, le SAP est généralement considéré comme un SAP générique, c'est-à-dire compatible avec tout autre SAP.

Chaque partie commence par son nom (bhli ou blli), suivi d'un deux-points et d'une liste (non vide) d'attributs, qui sont de la forme attribut=valeur. Certains attributs ont des sous-attributs, qui les suivent. Tout ce qui n'est pas séparé par un deux-points ou un signe égal est séparé par une virgule.

Les valeurs qui représentent un nombre d'octets sont spécifiées comme la séquence correspondante de paires de chiffres hexadécimaux. La séquence peut être préfixée optionnellement par 0x. Les valeurs entières dans une plage donnée peuvent être spécifiées en décimal (pas de préfixe), octal (préfixe 0) et hexadécimal (préfixe 0x).

Les attributs suivants, mutuellement exclusifs, sont autorisés dans la partie bhli (voir les documents correspondants de l'ATM Forum et de l'UIT pour la sémantique) :

iso=1-8 octets
ISO
user=1-8 octets
Spécifique à l'utilisateur
hlp=4 octets
Profil de couche supérieure. Notez que cet attribut n'existe que sur UNI 3.0. text2sap ne le reconnaît que si votre système est configuré pour accepter les formats de messages UNI 3.0.
oui=3 octets,id=4 octets
Identificateur d'application spécifique au fournisseur

La structure de la partie bhli est plus complexe. Elle distingue trois couches, l1, l2, et l3, dont la première est actuellement non prise en charge. Pour la couche deux, les possibilités suivantes (mutuellement exclusives) existent :

l2=iso1745
Mode de base ISO 1745
l2=q291
UIT-T Q.291 (Recommandation I.441)
l2=lapb
LAPB étendu, semi-duplex (Recommandation T.71)
l2=iso8802
LLC LAN (ISO/IEC 8802/2)
l2=x75
UIT-T X.75, SLP
l2=x25_ll ...
UIT-T X.25, couche liaison. Cet attribut et les attributs suivants jusqu'à l2=iso7776 peuvent être suivis optionnellement par un ou plusieurs des sous-attributs suivants : mode=mode (mode de fonctionnement, soit norm soit ext), et window=taille de fenêtre (taille de fenêtre en k, 1-127).
l2=x25_ml ...
UIT-T X.25, multilink
l2=hdlc_arm ...
HDLC ARM (ISO/IEC 4335)
l2=hdlc_nrm ...
HDLC NRM (ISO/IEC 4335)
l2=hdlc_abm ...
HDLC ABM (ISO/IEC 4335)
l2=q992 ...
UIT-T Q.922
l2=iso7776 ...
ISO 7776 DTE-DTE
l2=user,info=information
Spécifique à l'utilisateur. information est un entier dans la plage 0 à 255.

Pour la couche trois, les possibilités suivantes (également mutuellement exclusives) existent :

l3=iso8473
UIT-T X.233 | ISO/IEC 8473
l3=t70
Couche réseau minimale UIT-T T.70
l3=h321
Recommandation UIT-T H.321
l3=x25 ...
UIT-T X.25, couche paquet. Cet attribut et les attributs suivants jusqu'à l3=x223 peuvent être suivis optionnellement par un ou plusieurs des sous-attributs suivants : mode=mode (voir ci-dessus), size=paquet par défaut taille (4-12, correspondant à 16-4096), window=taille de fenêtre (voir ci-dessus).
l3=iso8208 ...
ISO/IEC 8208
l3=x223 ...
UIT-T X.223 | ISO/IEC 8878
l3=tr9577,ipi=identificateur ...
ISO/IEC TR 9577. identificateur est l'identificateur de protocole initial dans la plage 0-255. Pour SNAP (0x80), le mot-clé snap peut être utilisé, et les sous-attributs suivants doivent être spécifiés : oui=3 octets, et pid=2 octets.
l2=user,info=information
Spécifique à l'utilisateur, voir ci-dessus.
l3=h310 ...
Recommandation UIT-T H.310. Le sous-attribut term=type (type de terminal, rx, tx, ou rxtx) est reconnu. Si présent, il active les deux sous-attributs supplémentaires fw_mpx=capacité (capacité de multiplexage avant, ts, ts_fec, ps, ps_fec, ou h221) et bw_mpx=capacité. Les deux sont optionnels.

Notez que les virgules ne doivent jamais suivre les deux-points ou d'autres virgules. De plus, les espaces blancs ne sont pas autorisés dans une spécification SAP. Les spécifications SAP ne sont pas sensibles à la casse. À l'entrée, les éléments doivent être écrits exactement dans l'ordre utilisé dans ce document.

EXEMPLES

blli:l2=iso8802
IP classique sur ATM (RFC1577)
bhli:oui=0x0060D7,id=0x01000001,blli:l2=iso8802
Arequipa (RFC2170)
blli:l3=tr9577,ipi=snap,oui=0x00A03E,pid=0x0002
Émulation de LAN

NOM

sap — Manuel pour la bibliothèque de sous-processus SAP

DESCRIPTION

La bibliothèque de sous-processus SAP est une bibliothèque C qui fournit des fonctions pour interagir avec le système SAP. Elle permet aux applications de se connecter au système SAP, d'exécuter des transactions, de récupérer des données et d'effectuer d'autres opérations.

FONCTIONS

La bibliothèque fournit les fonctions suivantes :

  • sap_connect — Établit une connexion au système SAP.
  • sap_execute_transaction — Exécute une transaction SAP.
  • sap_get_data — Récupère des données du système SAP.
  • sap_disconnect — Ferme la connexion au système SAP.

EXEMPLE

Voici un exemple d'utilisation de la bibliothèque de sous-processus SAP :

#include <sap.h>

int main() {
    sap_connection_t conn;
    sap_data_t data;

    // Établir une connexion au système SAP
    conn = sap_connect("host", "client", "user", "password");
    if (!conn) {
        // Gérer l'erreur
        return 1;
    }

    // Exécuter une transaction et récupérer des données
    sap_execute_transaction(conn, "SE16");
    data = sap_get_data(conn);

    // Traiter les données récupérées

    // Fermer la connexion
    sap_disconnect(conn);

    return 0;
}
