saned(8) SANE Scanner Access Now Easy saned(8)

NOM

saned - démon d'accès réseau SANE

SYNTAXE

saned [ -a [ nomutilisateur ] ] [ -u nomutilisateur ] [ -b adresse ] [ -p port ] [ -l ] [ -D ] [ -o ] [ -d n ] [ -e ] [ -h ] [ -B taille-tampon ]

DESCRIPTION

saned est le démon SANE (Scanner Access Now Easy) qui permet aux clients distants d'accéder aux périphériques d'acquisition d'images disponibles sur l'hôte local.

OPTIONS

saned reconnaît les options suivantes :

-a [nomutilisateur], --alone[=nomutilisateur]
est équivalent à la combinaison des options -l -D -u nomutilisateur. Cependant, nomutilisateur est optionnel et l'utilisateur exécutant ne sera défini que lorsqu'il est spécifié.
-u nomutilisateur, --user=nomutilisateur
demande à saned de renoncer aux privilèges root et de s'exécuter en tant qu'utilisateur (et groupe) associé à nomutilisateur après la liaison.
-b adresse, --bind=adresse
indique à saned de se lier à l'adresse donnée.
-p port, --port=port
indique à saned d'écouter sur le port donné. Une valeur de 0 indique à saned de choisir un port inutilisé. Le port par défaut est le port sane (6566).
-l, --listen
demande à saned de s'exécuter en mode démon autonome. Dans ce mode, saned écoutera les connexions clients entrantes ; inetd(8) n'est pas requis pour les opérations de saned dans ce mode.
-D, --daemonize
demandera à saned de se détacher de la console et de s'exécuter en arrière-plan.
-n, --allow-network
permet à saned d'utiliser des scanners réseau. Par défaut, ceci est interdit pour empêcher saned de se contacter lui-même. Lorsque activé, la configuration du backend sane-net(5) ne doit pas mentionner l'adresse sur laquelle saned écoute.
-o, --once
demande à saned de se terminer après la déconnexion du premier client. Ceci est utile pour le débogage.
-d n, --debug=n
définit le niveau de sortie de débogage de saned à n. Lorsque compilé avec le débogage activé, ce drapeau peut être suivi d'un nombre pour demander plus ou moins d'informations de débogage. Plus le nombre est grand, plus la sortie de débogage est verbeuse. Par exemple, -d128 demandera la sortie de toutes les informations de débogage. Un niveau de 0 ne produit aucune sortie. La valeur par défaut est 2.
-e, --stderr
redirigera la sortie de débogage de saned vers stderr au lieu de la valeur par défaut syslog.
-B, --buffer-size=taille-tampon
spécifie la taille du tampon de lecture utilisé pour la communication avec le backend en Ko. La valeur par défaut est 1 Mo.
-h, --help
affiche un court message d'aide.

CONFIGURATION

Le fichier de configuration saned.conf contient à la fois des options pour le démon et la liste d'accès.

data_portrange = min_port - max_port
Spécifie la plage de ports à utiliser pour la connexion de données. Choisissez une plage de ports entre 1024 et 65535 ; ne choisissez pas une plage de ports trop grande, car cela pourrait poser des problèmes de performance. Utilisez cette option si votre serveur saned est derrière un pare-feu. Si ce pare-feu est une machine Linux, nous recommandons fortement d'utiliser plutôt le module Netfilter nf_conntrack_sane.
data_connect_timeout = délai
Spécifie le temps en millisecondes pendant lequel saned attendra une connexion de données. Sans cette option, si la connexion de données n'est pas terminée avant que le scanner n'atteigne la fin de la numérisation, le scanner continuera de numériser au-delà de la fin et pourrait l'endommager en fonction du backend. Spécifiez zéro pour avoir le comportement précédent. Le délai par défaut est de 4000 ms.

La liste d'accès est une liste de noms d'hôtes, d'adresses IP ou de sous-réseaux IP (notation CIDR) autorisés à utiliser les périphériques SANE locaux. Les adresses IPv6 doivent être entre crochets et doivent toujours être spécifiées sous leur forme compressée. Les connexions depuis localhost sont toujours autorisées. Les lignes vides et les lignes commençant par un signe dièse (#) sont ignorées. Une ligne contenant le caractère unique "+" est interprétée comme correspondant à n'importe quel nom d'hôte. Cela permet à n'importe quelle machine distante d'utiliser votre scanner et peut présenter un risque de sécurité, il ne faut donc pas l'utiliser à moins de savoir ce que l'on fait.

Un exemple de fichier de configuration est montré ci-dessous :

# Options du démon
data_portrange = 10000 - 10100
# Liste d'accès
scan-client.somedomain.firm
# ceci est un commentaire
192.168.0.1
192.168.2.12/29
[::1]
[2001:db8:185e::42:12]/64

La casse des noms d'hôtes n'a pas d'importance, donc AHost.COM est considéré comme identique à ahost.com.

FICHIERS

/etc/hosts.equiv
Les hôtes listés dans ce fichier sont autorisés à accéder à tous les périphériques SANE locaux. Attention : ce fichier présente de sérieux risques de sécurité et son utilisation n'est pas recommandée.
/etc/sane.d/saned.conf
Contient une liste d'hôtes autorisés à accéder aux périphériques SANE locaux (voir aussi la description de SANE_CONFIG_DIR ci-dessous).
/etc/sane.d/saned.users
Si ce fichier contient des lignes de la forme

utilisateur:motdepasse:backend

l'accès aux backends listés est restreint. Un backend peut être listé plusieurs fois pour différentes combinaisons utilisateur/mot de passe. Le serveur utilise le hachage MD5 si celui-ci est supporté par le client.

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires pouvant contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par un deux-points (`:`), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour résultat la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).

NOTES

saned ne fournit pas de confidentialité lors de la communication avec les clients. Si saned est exposé directement sur le réseau, d'autres utilisateurs pourraient être en mesure d'intercepter les images numérisées, ou d'apprendre les mots de passe pour se connecter à saned, avec peu d'effort. Les systèmes clients devraient se connecter à saned via un tunnel sécurisé vers le serveur à la place.

saned n'est pas un programme de confiance et ne devrait pas s'exécuter avec des privilèges root.

Consultez /usr/share/doc/sane/saned/saned.install.md pour plus de détails sur la configuration de saned en tant que service.
