sane-agfafocus(5) SANE Scanner Access Now Easy sane-agfafocus(5)

NOM

sane-agfafocus - Backend SANE pour scanners plats AGFA Focus

DESCRIPTION

La librairie sane-agfafocus implémente un backend SANE (Scanner Access Now Easy) qui fournit l'accès aux scanners plats AGFA Focus. À l'heure actuelle, les scanners suivants sont pris en charge par ce backend :

AGFA Focus GS Scanner (6 bits niveaux de gris) (non testé)
AGFA Focus Lineart Scanner (lineart) (non testé)
AGFA Focus II (8 bits niveaux de gris) (non testé)
AGFA Focus Color (couleur 24 bits, 3 passes)
AGFA Focus Color Plus (couleur 24 bits, 3 passes)

Siemens S9036 (8 bits niveaux de gris) (non testé)

Le pilote prend en charge les scans lineart, niveaux de gris 6bpp et 8bpp, couleur 18bpp et 24bpp.

Si vous possédez un scanner autre que ceux listés ci-dessus qui fonctionne avec ce backend, veuillez nous en informer en envoyant le nom du modèle du scanner, l'identifiant SCSI, et la révision du firmware à sane-devel@alioth-lists.debian.net. Consultez http://www.sane-project.org/mailing-lists.html concernant l'abonnement à sane-devel.

Tous ces scanners sont antérieurs à SCSI-2, et ne se signalent même pas correctement lors d'une interrogation SCSI. Ceci est généralement évident dans les scans du bus SCSI, où le scanner apparaîtra avec des chaînes de nom de fabricant et de modèle vides ou incorrectes.

NOMS DE PÉRIPHÉRIQUE

Ce backend attend des noms de périphérique de la forme :

spécial

où spécial est le nom de chemin du périphérique spécial correspondant à un scanner SCSI. Pour les scanners SCSI, le nom du périphérique spécial doit être un périphérique SCSI générique ou un lien symbolique vers un tel périphérique. Sous Linux, un tel nom de périphérique pourrait être /dev/sga ou /dev/sge, par exemple. Voir sane-scsi(5) pour les détails.

CONFIGURATION

Le contenu du fichier agfafocus.conf est une liste de noms de périphériques correspondant aux scanners AGFA Focus. Les lignes vides et celles commençant par un dièse (#) sont ignorées. Un exemple de fichier de configuration est montré ci-dessous :

/dev/scanner
# ceci est un commentaire
/dev/sge

FICHIERS

/etc/sane.d/agfafocus.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/libsane-agfafocus.a
La librairie statique implémentant ce backend.
/usr/lib/libsane-agfafocus.so
La librairie partagée implémentant ce backend (présente sur les systèmes qui supportent le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par un deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour résultat la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_AGFAFOCUS
Si la librairie a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des niveaux plus bas réduisent la verbosité. Valeurs de SANE_DEBUG_AGFAFOCUS : 
Nombre  Remarque
 0       affiche les erreurs importantes (affichées à chaque fois)
 1       affiche les erreurs
 2       affiche les sense
 3       affiche les avertissements
 4       affiche l'interrogation du scanner
 5       affiche les informations
 6       affiche les informations moins importantes
 7       affiche les procédures appelées
 8       affiche les messages de reader_process
 10      affiche les routines sane-init appelées
 11      affiche les procédures sane appelées
 12      affiche les infos sane
 13      affiche les messages de contrôle d'options sane

FONCTIONNALITÉ MANQUANTE

Le téléchargement des matrices de trame et des courbes de tonalité a été implémenté, mais n'a jusqu'à présent prouvé son utilité pour rien. Pour cette raison, ces options ont été désactivées.

BOGUES

Les scanners qui ne prennent pas en charge la déconnexion ont des problèmes de timeouts SCSI si le bus SCSI est chargé, par exemple si vous effectuez une compilation du noyau en même temps que la numérisation. Pour savoir si votre scanner prend en charge la déconnexion, exécutez SANE_DEBUG_AGFAFOCUS=128 scanimage -L dans un terminal et recherchez la ligne "disconnect:".

DÉBOGAGE

Si vous avez des problèmes avec la détection de votre scanner par SANE, assurez-vous que le backend Artec est désactivé. D'une manière ou d'une autre, ce backend fait que mon scanner, au minimum, ne répond pas correctement aux commandes d'interrogation SCSI.

Si vous rencontrez un bogue, veuillez définir la variable d'environnement SANE_DEBUG_AGFAFOCUS à 128 et essayer de reproduire le problème. Ensuite, envoyez-moi un rapport avec le journal joint.

Si vous rencontrez une erreur de bus SCSI ou des images coupées et/ou déplacées, veuillez également définir la variable d'environnement SANE_DEBUG_SANEI_SCSI à 128 avant de m'envoyer le rapport.

À FAIRE

Plus de scanners ?

Les scanners AGFA ACS et ARCUS sont similaires aux scanners FOCUS. Le pilote pourrait probablement être étendu pour prendre en charge ces scanners sans trop de modifications. Je n'ai pas accès à de tels scanners et ne peux pas ajouter le support. Cependant, si vous possédez un tel scanner, je pourrais vous aider à ajouter la prise en charge de ces scanners.

Les scanners AGFA HORIZON sont des scanners SCSI-2, et il serait probablement plus facile de prendre en charge ces scanners dans un backend conforme à SCSI-2.
