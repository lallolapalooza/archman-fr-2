SASLAUTHD(8) Manuel de l'administrateur système SASLAUTHD(8)

NOM

saslauthd — serveur d'authentification sasl

SYNTAXE

saslauthd -a authmech [-Tvdchlr] [-O option] [-m mux_path] [-n threads] [-s size] [-t timeout]

DESCRIPTION

saslauthd est un processus démon qui gère les requêtes d'authentification en clair au nom de la bibliothèque SASL.

Le serveur remplit deux rôles : il isole tout code nécessitant des privilèges de superutilisateur dans un seul processus, et il peut être utilisé pour fournir des services d'authentification par proxy aux clients qui ne comprennent pas l'authentification basée sur SASL.

saslauthd doit être démarré par les scripts de démarrage du système lors du passage en mode multi-utilisateur. Lors de l'exécution sur une base de données d'authentification protégée (par exemple, le mécanisme shadow), il doit être exécuté en tant que superutilisateur. Sinon, il est recommandé d'exécuter le démon sans privilèges en tant que saslauth:saslauth, nécessitant que le répertoire d'exécution ait le propriétaire root:saslauthd. Vous pouvez le faire en suivant ces étapes sur les machines utilisant systemd(1) :

  1. créer le répertoire /etc/systemd/system/saslauthd.service.d/
  2. créer le fichier /etc/systemd/system/saslauthd.service.d/user.conf avec le contenu 
    [Service]
User=saslauth
Group=saslauth
  3. Recharger le fichier de service systemd : exécutez « systemctl daemon-reload »

Options

Les options nommées par des lettres minuscules configurent le serveur lui-même. Les options majuscules contrôlent le comportement de mécanismes d'authentification spécifiques ; leur applicabilité à un mécanisme d'authentification particulier est décrite dans la section MECANISMES D'AUTHENTIFICATION.

-a authmech
Utiliser authmech comme mécanisme d'authentification. (Voir la section MECANISMES D'AUTHENTIFICATION ci-dessous.) Ce paramètre est obligatoire.
-O option
Une option spécifique au mécanisme (par exemple, nom d'hôte rimap ou chemin du fichier de configuration)
-H hostname
L'hôte distant à contacter par le mécanisme d'authentification rimap. (Obsolète, utiliser -O à la place)
-m chemin
Utiliser chemin comme nom de chemin du socket nommé sur lequel écouter les demandes de connexion. Ce doit être un nom de chemin absolu, et il NE DOIT PAS inclure le "/mux" final. Notez que la valeur par défaut est "/var/state/saslauthd" (ou ce qui a été spécifié au moment de la compilation) et que ce répertoire doit exister pour que saslauthd fonctionne.
-n threads
Utiliser threads processus pour répondre aux requêtes d'authentification. (défaut : 5) Une valeur de zéro indiquera que saslauthd doit créer un processus individuel pour chaque connexion. Cela peut résoudre les fuites qui se produisent dans certains déploiements.
-s taille
Utiliser taille comme taille de la table de hachage (en kilo-octets)
-t timeout
Utiliser timeout comme temps d'expiration du cache d'authentification (en secondes)
-T
Respecter les restrictions de connexion selon l'heure de la journée.
-h
Afficher les informations d'utilisation
-c
Activer la mise en cache des informations d'authentification
-l
Désactiver l'utilisation d'un fichier de verrouillage pour contrôler l'accès à accept().
-r
Combiner le royaume avec l'identifiant de connexion (avec un signe '@' entre les deux). Par exemple, identifiant : "foo" royaume : "bar" sera passé en tant qu'identifiant : "foo@bar". Notez que le royaume sera toujours passé, ce qui peut entraîner un comportement inattendu pour les mécanismes d'authentification qui utilisent le royaume, cependant pour les mécanismes qui n'en font pas usage, tels que getpwent, c'est la seule façon d'authentifier des utilisateurs spécifiques au domaine partageant le même identifiant utilisateur.
-v
Afficher le numéro de version et les mécanismes d'authentification disponibles sur la sortie d'erreur standard, puis quitter.
-d
Mode de débogage.

Journalisation

saslauthd enregistre ses activités via syslogd en utilisant le niveau LOG_AUTH.

MECANISMES D'AUTHENTIFICATION

saslauthd prend en charge un ou plusieurs "mécanismes d'authentification", en fonction des fonctionnalités fournies par le système d'exploitation sous-jacent. Le mécanisme est sélectionné par le drapeau -a parmi la liste de choix suivante :

dce
(AIX)

Authentifier en utilisant l'environnement d'authentification DCE.

getpwent
(Tous les plateformes)

Authentifier en utilisant la fonction de bibliothèque getpwent(). Typiquement, cela authentifie par rapport au fichier de mots de passe local. Voir la page man getpwent(3) de votre système pour plus de détails.

kerberos4
(Tous les plateformes)

Authentifier par rapport au royaume Kerberos 4 local. (Voir la section NOTES pour les mises en garde concernant ce pilote.)

kerberos5
(Tous les plateformes)

Authentifier par rapport au royaume Kerberos 5 local.

pam
(Linux, Solaris)

Authentifier en utilisant les modules d'authentification enfichables (PAM).

rimap
(Tous les plateformes)

Transférer les requêtes d'authentification à un serveur IMAP distant. Ce pilote se connecte à un serveur IMAP distant, spécifié à l'aide de l'option -O, et tente de se connecter (via une commande IMAP ‘LOGIN’) en utilisant les identifiants fournis au serveur local. Si l'authentification distante réussit, la connexion locale est également considérée comme authentifiée. La connexion distante est fermée dès que la réponse marquée de la commande ‘LOGIN’ est reçue du serveur distant.

NAME

saslauthd — SASL authentication daemon

SYNOPSIS

saslauthd [-a authtype] [-d] [-H host:port] [-m dir] [-O host:port] [-r] [-T]

DESCRIPTION

The saslauthd program is a daemon that performs authentication checks via the saslauthd API.

It is typically used in conjunction with sendmail or other MTAs that are configured to use SASL authentication.

The daemon listens for authentication requests on a Unix domain socket. It forks a child process for each incoming request. When a child process receives a request, it performs the authentication check and then exits.

The authentication mechanism used by saslauthd is determined by the -a flag, or by the authtype setting in /usr/local/etc/saslauthd.conf.

The daemon can be run in the foreground with the -d flag, which is useful for debugging.

The daemon can be configured to listen on a network socket instead of a Unix domain socket using the -H flag.

The -m flag specifies the directory where the Unix domain socket will be created. The default is /var/run/saslauthd.

The -r flag causes the daemon to chroot to the directory specified by the -m flag. This is a security measure that can be used to limit the daemon's access to the filesystem.

The -T flag is used to enable Kerberos Ticket-Granting Ticket (TGT) authentication.

AUTHENTICATION MECHANISMS

The following authentication mechanisms are supported:

kerberos5
(SASL2)

Authenticate using Kerberos V5 tickets. This mechanism requires the kadm5 libraries to be installed.

The -O flag is used to specify the remote server to forward authentication requests to. hostname can be a hostname (imap.example.com) or a dotted-quad IP address (192.168.0.1). The latter is useful if the remote server is multi-homed and has network interfaces that are unreachable from the local IMAP server. The remote host is contacted on the ‘imap’ service port. A non-default port can be specified by appending a slash and the port name or number to the hostname argument.

The -O flag and argument are mandatory when using the rimap mechanism.

shadow
(AIX, Irix, Linux, Solaris)

Authenticate against the local "shadow password file". The exact mechanism is system dependent. saslauthd currently understands the getspnam() and getuserpw() library routines. Some systems honour the -T flag.

sasldb
(All platforms)

Authenticate against the SASL authentication database. Note that this is probably not what you want to use, and is even disabled at compile-time by default. If you want to use sasldb with the SASL library, you probably want to use the pwcheck_method of "auxprop" along with the sasldb auxprop plugin instead.

ldap
(All platforms that support OpenLDAP 2.0 or higher)

Authenticate against an ldap server. The ldap configuration parameters are read from /usr/local/etc/saslauthd.conf. The location of this file can be changed with the -O parameter. See the LDAP_SASLAUTHD file included with the distribution for the list of available parameters.

sia
(Digital UNIX)

Authenticate using the Digital UNIX Security Integration Architecture (a.k.a. "enhanced security").

NOTES

The kerberos4 authentication driver consumes considerable resources. To perform an authentication it must obtain a ticket granting ticket from the TGT server on every authentication request. The Kerberos library routines that obtain the TGT also create a local ticket file, on the reasonable assumption that you will want to save the TGT for use by other Kerberos applications. These ticket files are unusable by saslauthd , however there is no way not to create them. The overhead of creating and removing these ticket files can cause serious performance degradation on busy servers. (Kerberos was never intended to be used in this manner, anyway.)

FILES

/var/run/saslauthd/mux
The default communications socket.
/usr/local/etc/saslauthd.conf
The default configuration file for ldap support.
