NOM

sane-cardscan - Backend SANE pour les scanners USB Corex CardScan

DESCRIPTION

La bibliothèque sane-cardscan implémente un backend SANE (Scanner Access Now Easy) qui fournit l'accès aux scanners de petit format Corex CardScan 800c et 600c.

Le backend ne supporte que les modes niveaux de gris et couleur, ainsi que des supports (théoriquement) de longueur infinie.

Ce backend peut supporter d'autres scanners. La meilleure façon de déterminer le niveau de support est d'obtenir une trace du pilote Windows en action et de l'envoyer à l'auteur.

OPTIONS

Le backend cardscan supporte les options suivantes :

--mode Gray|Color
Sélectionne le mode de numérisation.

FICHIER DE CONFIGURATION

Le fichier de configuration cardscan.conf est utilisé pour indiquer au backend comment rechercher les scanners et fournir des options contrôlant le fonctionnement du backend. Ce fichier est lu chaque fois que le frontend demande au backend une liste de scanners, généralement seulement au démarrage du frontend. Si le fichier de configuration est manquant, le backend utilisera un ensemble de valeurs par défaut compilées, qui sont identiques au fichier de configuration par défaut fourni avec SANE.

Les scanners peuvent être spécifiés dans le fichier de configuration de 2 manières :

« usb 0x04c5 0x1042 » (ou d'autres identifiants de vendeur/produit)

Demande au backend de rechercher sur tous les bus USB du système un périphérique utilisant cet identifiant de vendeur et de produit. Le périphérique sera alors interrogé pour déterminer s'il s'agit d'un scanner cardscan.

« usb /dev/usb/scanner0 » (ou un autre fichier de périphérique)

Certains systèmes utilisent un pilote noyau pour accéder aux scanners USB. Cette méthode n'est pas testée.

De plus, il existe deux options de configuration qui contrôlent le protocole utilisé par le backend :

« lines_per_block 16 » (ou un autre nombre de 1 à 32)

Contrôle le nombre de lignes de données d'image qui seront acquises à chaque passe. Les anciens scanners nécessiteront ce nombre réglé plus bas, souvent à 1.

« has_cal_buffer 1 » (1 ou 0)

Indique au backend d'obtenir les données de calibration du scanner lors de l'initialisation. Les anciens scanners ne supportent pas cette requête et doivent être réglés sur 0.

ENVIRONNEMENT

Le backend utilise une seule variable d'environnement, SANE_DEBUG_CARDSCAN, qui active la sortie de débogage sur la sortie d'erreur standard. Les valeurs valides sont :

5 Erreurs
10 Trace des fonctions
15 Détail des fonctions
20 Commandes d'options
25 Trace SCSI/USB
30 Détail SCSI/USB
35 Bruit inutile

PROBLÈMES CONNUS

Le scanner ne semble pas avoir beaucoup de contrôle possible, donc le backend ne peut pas définir les valeurs de coordonnées x/y, les résolutions, etc. Ces choses pourraient être simulées dans le backend, mais il existe de nombreux outils en ligne de commande.
Le backend n'envoie pas non plus toutes les commandes que le pilote Windows envoie, il peut donc ne pas fonctionner de la même manière.
Le backend n'a pas les options de calibration ou d'éjection du pilote Windows.
