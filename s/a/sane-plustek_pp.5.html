NOM

sane-plustek_pp - Backend SANE pour scanners à plat Plustek sur port parallèle

DESCRIPTION

La bibliothèque sane-plustek_pp implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners à plat Plustek basés sur port parallèle ASIC 9600[1/3] et P9800[1/3].

NOMS D'APPAREIL

Le périphérique par défaut de ce backend est :

0x378

Ce "périphérique par défaut" sera utilisé si aucun fichier de configuration ne peut être trouvé. C'est l'adresse de base du port parallèle sur les machines i386.

Comme le backend supporte jusqu'à quatre périphériques, il est possible de les spécifier dans le fichier de configuration

/etc/sane.d/plustek_pp.conf

Voir ce fichier pour des exemples.

CONFIGURATION

Cette section décrit les entrées du fichier de configuration du backend. Le fichier est situé à : /etc/sane.d/plustek_pp.conf

Pour une configuration correcte, vous aurez besoin d'au moins deux entrées :

[direct]
device 0x378

direct indique au backend que le nom de périphérique suivant (ici 0x378) doit être interprété comme un périphérique scanner sur port parallèle. En fait, c'est l'adresse à utiliser. Alternativement, vous pouvez utiliser /dev/parport0 si le backend a été compilé avec le support de libieee1284.

Autres options :

option warmup t

t spécifie la période d'échauffement en secondes

option lampOff t

t est le temps en secondes pour éteindre les lampes en mode veille

option lOffonEnd b

b spécifie le comportement lors de la fermeture du backend, 1 --> éteindre les lampes, 0 --> ne pas changer l'état des lampes

option mov m

m est le commutateur de substitution de modèle, qui ne fonctionne qu'en mode direct.
m = 0
par défaut : pas de substitution
m = 1
Substitution OpticPro 9630PL (fonctionne si OP9630 a été détecté) force la taille légale (14")
m = 2
Substitution Primax 4800Direct (fonctionne si OP600 a été détecté) inverse le rouge/vert des couleurs
m = 3
Substitution OpticPro 9636 (fonctionne si OP9636 a été détecté) désactive les capacités de transparence/négatif du backend
m = 4
Substitution OpticPro 9636P (fonctionne si OP9636 a été détecté) désactive les capacités de transparence/négatif du backend
m = 5
Substitution OpticPro A3I (fonctionne si OP12000 a été détecté) active le balayage A3
m = 6
Substitution OpticPro 4800P (fonctionne si OP600 a été détecté) inverse le rouge/vert des couleurs
m = 7
Substitution Primax 4800Direct 30bit (fonctionne si OP4830 a été détecté)

Voir le fichier plustek_pp.conf pour des exemples.

MODES DE PORT PARALLÈLE

Le pilote actuel fonctionne mieux lorsque le port parallèle est réglé en mode EPP. Lors de la détection d'un autre mode tel que ECP ou PS/2, le pilote tente de passer à un mode plus rapide et supporté. Si cela échoue, il utilisera le mode SPP, car ce mode devrait fonctionner avec tous les ports parallèles supportés par Linux. En cas de doute, accédez à votre BIOS et réglez-le sur n'importe quel mode sauf ECP.

Les anciens modèles de scanners Plustek (4830, 9630) fournissaient une carte adaptateur de port parallèle ISA. Cette carte n'est **pas** supportée par le pilote.

Les modèles basés sur ASIC 96001/3 ont parfois des problèmes avec les modes haute résolution. Si vous rencontrez des images corrompues sporadiques (parties dupliquées ou décalées horizontalement), fermez toutes les autres applications avant de numériser et (si vous avez suffisamment de mémoire) désactivez le swapping.

Voir le fichier plustek_pp.conf pour des exemples.

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail actuel (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour résultat la recherche des répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_PLUSTEK_PP
Si la bibliothèque a été compilée avec le support de débogage activé, ceci

ENVIRONNEMENT

La variable d'environnement contrôle le niveau de débogage de ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie.

Exemple : export SANE_DEBUG_PLUSTEK_PP=10

Pour obtenir des messages de débogage du backend, veuillez définir la variable d'environnement SANE_DEBUG_PLUSTEK_PP avant d'appeler votre frontend SANE préféré (par exemple, xscanimage(1)) :

La valeur contrôle la verbosité de la sortie.

BOGUES CONNUS & RESTRICTIONS

* Le tramage fonctionne, mais la qualité est médiocre

* Les imprimantes (en particulier les modèles HP) commenceront à imprimer pendant la numérisation. C'est en fait un problème pour d'autres imprimantes qui utilisent un protocole bidirectionnel (voir la page www.plustek.com (TAIWAN) pour plus de détails)

* Le pilote ne prend pas en charge ces mises à l'échelle manuelles jusqu'à 16 fois la résolution physique. La seule mise à l'échelle est effectuée entre la résolution physique du capteur CCD et le moteur pas à pas, c'est-à-dire que vous avez un scanner de 600x1200 dpi et que vous numérisez en utilisant 800 dpi, donc une mise à l'échelle est nécessaire, car le capteur ne délivre que 600 dpi mais le moteur est capable d'effectuer des pas de 800 dpi.

* Sur certains appareils, les images semblent bleutées

Modèles basés sur ASIC 98001 :

* Le mode transparence et négatif à 300 dpi ne fonctionne pas correctement.

* Il n'y a actuellement aucun moyen de distinguer un modèle avec et sans unité de transparence.

* Les images numérisées semblent trop sombres (P9636T)

Modèles basés sur ASIC 96003/1 :

* Le mode 30 bits n'est actuellement pas pris en charge.

* Sur les systèmes bas de gamme sous forte charge système, le pilote peut perdre des données, ce qui peut entraîner une corruption de l'image ou faire que le capteur heurte le plateau de numérisation.

* La vitesse de numérisation sur les modèles 600x1200 dpi est lente.

* La qualité de numérisation de l'A3I est médiocre.
