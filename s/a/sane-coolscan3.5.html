NOM

sane-coolscan3 - Backend SANE pour scanners de films Nikon Coolscan

DESCRIPTION

La bibliothèque sane-coolscan3 implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners de films Nikon Coolscan. Certaines fonctions de ce backend doivent être considérées comme des logiciels de qualité bêta. La plupart des fonctions sont stables depuis longtemps, mais il est évident que les nouveaux développements ne peuvent pas et ne fonctionneront pas correctement dès le premier jour.

Actuellement, les scanners suivants sont connus pour fonctionner avec ce backend :

Modèle :                       Type de connexion
---------------------------    -------------------
LS-30 (Coolscan III)           SCSI
LS-40 ED (Coolscan IV)         USB
LS-50 ED (Coolscan V)          USB
LS-2000                      SCSI
LS-4000 ED                   IEEE 1394
LS-8000 ED                   IEEE 1394

Veuillez envoyer un courriel à sane-devel@alioth-lists.debian.net pour signaler vos succès ou échecs.

OPTIONS

Les options prises en charge par le backend peuvent être sélectionnées soit via des options de ligne de commande pour des programmes comme scanimage(1), soit via des éléments d'interface graphique dans xscanimage(1) ou xsane(1).

Les options de ligne de commande valides et leur syntaxe peuvent être listées en utilisant :

scanimage --help -d coolscan3:<interface>:<périphérique>

où <interface> et <périphérique> spécifient le périphérique en question, comme dans le fichier de configuration (voir la section suivante). Le paramètre -d et son argument peuvent être omis pour obtenir des informations sur le premier scanner identifié. Utilisez la commande :

scanimage -L

pour lister tous les périphériques reconnus par votre installation SANE.

Les options doivent être entièrement décrites par la description ou les infobulles fournies par le frontend. Voici une description de certaines des options les plus importantes, dans la syntaxe avec laquelle elles doivent être fournies à scanimage(1) :

--cadre <n>
Cette option spécifie quel cadre utiliser, si un chargeur de films motorisé ou un adaptateur APS est utilisé. Le numéro de cadre <n> varie de 1 au nombre de cadres disponibles, qui est détecté à chaque initialisation du backend (généralement à chaque lancement du frontend).
--sous-cadre <x>
Cette option décale la fenêtre de numérisation de la quantité spécifiée (l'unité par défaut est le mm).
--infrarouge=oui/non
Si réglé sur « oui », le scanner lira le canal infrarouge, permettant ainsi la suppression des défauts par logiciel. L'image infrarouge est lue lors d'une seconde numérisation, sans aucune option modifiée. Le backend ne doit pas être redémarré entre les numérisations. Si vous utilisez scanimage(1), effectuez une numérisation par lots avec --batch-count=2 pour obtenir les informations IR.
--profondeur <n>
Ici, <n> peut être soit 8, soit le nombre maximal de bits pris en charge par le scanner (10, 12 ou 14). Il spécifie si le scanner réduit ou non les données numérisées à 8 bits avant de les envoyer au backend. Si 8 bits sont utilisés, certaines informations et donc la qualité de l'image sont perdues, mais la quantité de données est plus faible par rapport aux profondeurs plus élevées. De plus, de nombreux programmes d'imagerie et formats d'image ne peuvent pas gérer des profondeurs supérieures à 8 bits.
--autofocus
Effectuer une opération de mise au point automatique. Sauf indication contraire des autres options ( --focus-on-centre et similaires), la mise au point est effectuée au centre de la zone de numérisation sélectionnée.
--ae-wb
--ae
Effectuer une pré-numérisation pour calculer automatiquement les valeurs d'exposition. --ae-wb maintiendra la balance des blancs, tandis que --ae ajustera chaque canal séparément.
--exposition
Multiplie tous les temps d'exposition par cette valeur. Cela permet une correction d'exposition sans modifier la balance des blancs.
--charger
Charge la diapositive suivante lors de l'utilisation du chargeur de diapositives (uniquement le chargeur SF-200).
--ejecter
Éjecte la bande de film ou la diapositive montée lors de l'utilisation du chargeur de diapositives.
--reset
Réinitialise le scanner. Le scanner effectuera la même action qu'à la mise sous tension : il éjectera la diapositive (avec le chargeur SF-200) et se calibrera. Utilisez ceci chaque fois que le scanner refuse de charger une diapositive correctement, ce qui entraîne le non-fonctionnement de --ejecter.

FICHIER DE CONFIGURATION

Le fichier de configuration /etc/sane.d/coolscan3.conf spécifie les périphériques que le backend utilisera. En raison de la nature des types de connexion pris en charge (SCSI, USB et IEEE 1394), le fichier de configuration par défaut fourni avec la distribution SANE devrait fonctionner sans être modifié.

Chaque ligne du fichier de configuration est l'une des suivantes, où toutes les entrées sont sensibles à la casse :

une ligne vide ou commençant par un caractère '#'
Ces lignes sont ignorées, donc '#' peut être utilisé pour inclure des commentaires.
contenant uniquement le mot "auto"
Cela demande au backend de sonder les bus à la recherche de périphériques avec des identifiants connus. C'est l'action par défaut lorsqu'aucun fichier de configuration n'est présent.
une ligne de la forme <interface>:<périphérique>
Ici, <interface> peut être « scsi » ou « usb », et <périphérique> est le fichier du périphérique du scanner. Notez que les périphériques IEEE 1394 sont gérés par le module SBP-2 du noyau et apparaissent à SANE comme des périphériques SCSI.

FICHIERS

/usr/lib/sane/libsane-coolscan3.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-coolscan3.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).
/etc/sane.d/coolscan3.conf
Fichier de configuration pour ce backend, lu à chaque initialisation du backend.

ENVIRONNEMENT

SANE_DEBUG_COOLSCAN3
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande à afficher toutes les sorties de débogage. Des niveaux plus bas réduisent la verbosité.

sane-scsi(5), sane-usb(5), scanimage(1), xscanimage(1), xsane(1)

BOGUES

Actuellement, le protocole SANE ne permet pas la mise à jour automatique des options lorsque le matériel change. Ainsi, le nombre de choix pour l'option --cadre sera fixe lorsque le backend est initialisé (généralement lorsque l'utilisateur lance le frontend). En particulier, s'il n'y a pas de bande de film dans le chargeur automatique de bande de film lorsque le backend est initialisé, l'option --cadre n'apparaîtra pas du tout. Il est également fortement recommandé de redémarrer le frontend après avoir échangé les adaptateurs de film.

Les noyaux Linux antérieurs à 2.4.19 comportaient un correctif qui tronquait les données INQUIRY des scanners IEEE 1394 à 36 octets, supprimant ainsi des informations vitales sur le scanner. Les modèles IEEE 1394 ne fonctionnent donc qu'avec la version 2.4.19 ou ultérieure.

Aucun bogue réel connu actuellement, veuillez en signaler tout à la liste de développement de SANE.
