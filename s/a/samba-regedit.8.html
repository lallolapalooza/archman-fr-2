SAMBA-REGEDIT(8) Outils d'administration système SAMBA-REGEDIT(8)

NOM

samba-regedit - outil basé sur ncurses pour gérer le registre Samba

SYNTAXE

samba-regedit [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DE_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_DE_CONFIG] [--option=nom=valeur] [-l|--log-basename=BASE_NOM_FICHIER_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOLUTION_NOMS] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=PROTOCOLE_MAX] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=PORTEE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR[%MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=voulu|requis|désactivé] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=signer|chiffrer|désactivé] [-V|--version]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

samba-regedit est un outil basé sur ncurses pour gérer le registre Samba. Il peut être utilisé pour afficher/modifier des clés/sous-clés du registre et leurs valeurs.

OPTIONS

-?|--help

Affiche un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications clientes.

Plus cette valeur est élevée, plus les informations détaillées seront enregistrées dans les fichiers journaux sur les activités du serveur. Au niveau 0, seules les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre niveau de journalisation dans le fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients écrivent dans STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou fournir des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé au moment de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) « <nom> » à la valeur « <valeur> » depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur contient un espace, entourez tout `--option=nom=valeur` de guillemets.

-l|--log-basename=répertoire_journal

Nom de base du répertoire pour les fichiers de journalisation/débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-R|--name-resolve=ORDRE_RESOLUTION_NOMS

Cette option est utilisée pour déterminer quels services de nommage et dans quel ordre résoudre les noms d'hôtes en adresses IP. L'option prend une chaîne d'options de résolution de noms différentes séparées par des espaces. Il est préférable d'entourer tout `--name-resolve=ORDRE_RESOLUTION_NOMS` de guillemets.

Les options sont : « lmhosts », « host », « wins » et « bcast ». Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir le lmhosts(5) pour les détails), alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution standard nom d'hôte vers adresse IP, en utilisant les recherches DNS, NIS ou /etc/hosts du système. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, cela peut être contrôlé par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP répertoriée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues répertoriées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend de l'hôte cible étant sur un sous-réseau connecté localement.
Si ce paramètre n'est pas défini, alors l'ordre de résolution des noms défini dans le paramètre ordre de résolution des noms du fichier /etc/samba/smb.conf sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ni aucune entrée dans le paramètre ordre de résolution des noms du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=OPTIONS_SOCKET

Options de socket TCP à définir sur le socket client. Voir le paramètre options de socket dans la page du manuel /etc/samba/smb.conf pour la liste des options valides.

-m|--max-protocol=PROTOCOLE_MAX

La valeur du paramètre (une chaîne) est le niveau de protocole le plus élevé qui sera pris en charge par le client.

Notez que la spécification de ce paramètre ici remplacera le paramètre client max protocol dans le fichier /etc/samba/smb.conf.

-n|--netbiosname=NOM_NETBIOS

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage de ligne de commande aura la priorité sur les réglages dans /etc/samba/smb.conf.

--netbios-scope=PORTEE

Ceci spécifie une portée NetBIOS que nmblookup utilisera pour communiquer lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont *très* rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système responsable de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=GROUPE_TRAVAIL

Définit le domaine SMB du nom d'utilisateur. Ceci remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est identique au nom NetBIOS du serveur, le client se connectera en utilisant le SAM local du serveur (par opposition au SAM du domaine).

Notez que la spécification de ce paramètre ici remplacera le paramètre workgroup dans le fichier /etc/samba/smb.conf.

-r|--realm=DOMAINE

Définit le domaine pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

-U|--user=[DOMAINE\]NOM_UTILISATEUR[%MOT_DE_PASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOT_DE_PASSE n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir un mot de passe) et si l'un d'eux existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'identification qui contient le texte brut du nom d'utilisateur et du mot de passe. Cette option est principalement destinée aux scripts où l'administrateur ne souhaite pas transmettre les informations d'identification sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les autorisations du fichier restreignent l'accès aux utilisateurs non désirés. Voir le paramètre -A pour plus de détails.

Soyez prudent quant à l'inclusion de mots de passe dans les scripts ou à la transmission de valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

samba-regedit(8) — Samba 4.23.3

NAME

samba-regedit - Samba registry editing tool

SYNOPSIS

samba-regedit [options]

DESCRIPTION

The samba-regedit utility is a client-side tool for accessing and manipulating the Samba 4.0+ internal registry.

OPTIONS

-N|--no-pass

If specified, this parameter suppresses the normal password prompt from the client to the user. This is useful when accessing a service that does not require a password.

Unless a password is specified on the command line or this parameter is specified, the client will request a password.

If a password is specified on the command line and this option is also defined the password on the command line will be silently ignored and no password will be used.

--password

Specify the password on the commandline.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number.

Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

--pw-nt-hash

The supplied password is the NT hash.

-A|--authentication-file=filename

This option allows you to specify a file from which to read the username and password used in the connection. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-P|--machine-pass

Use stored machine account password.

--simple-bind-dn=DN

DN to use for a simple bind.

--use-kerberos=desired|required|off

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=CCACHE

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=sign|encrypt|off

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

VERSION

This man page is part of version 4.23.3 of the Samba suite.

SEE ALSO

smbd(8), samba(7) and net(8).

AUTHOR

The original Samba software and related utilities were created by Andrew Tridgell. Samba is now developed by the Samba Team as an Open Source project similar to the way the Linux kernel is developed.

The samba-regedit man page was written by Karolin Seeger.

NOM

samba-regedit - Outil d'édition de registre Samba

SYNTAXE

samba-regedit [options]

DESCRIPTION

L'utilitaire samba-regedit est un outil côté client pour accéder et manipuler le registre interne de Samba 4.0+.

OPTIONS

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié sur la ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifiez le mot de passe sur la ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous passez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censé contenir un numéro de descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne devrait contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

Bien que Samba tente de nettoyer le mot de passe du titre du processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une course.

--pw-nt-hash

Le mot de passe fourni est le hash NT.

-A|--authentication-file=filename

Cette option vous permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est : 
username = <valeur>
password = <valeur>
domain   = <valeur>

Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

-P|--machine-pass

Utilise le mot de passe du compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils clients Samba essaieront de s'authentifier via Kerberos. Pour l'authentification Kerberos, vous devriez utiliser des noms DNS plutôt que des adresses IP lors de la connexion à un service. Par défaut, les outils clients Samba essaieront d'utiliser le cache de crédits Kerberos (ccache) par défaut. Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache de crédits Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache de crédits pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Essaie d'utiliser le cache de crédits de winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection dans le fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus granulaire, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.
