NOM

sadc - Collecteur de données d'activité système.

SYNTAXE

/usr/lib/sa/sadc [ -C commentaire ] [ -D ] [ -F ] [ -f ] [ -L ] [ -V ] [ -S { mot-clé[,...] | TOUT | XTOUT } ] [ intervalle [ compte ] ] [ fichier_sortie ]

DESCRIPTION

La commande sadc échantillonne les données système un nombre spécifié de fois (compte) à un intervalle spécifié, mesuré en secondes (intervalle). Elle écrit au format binaire dans le fichier_sortie spécifié ou sur la sortie standard. Si fichier_sortie est défini sur -, alors sadc utilise le fichier quotidien standard des données d'activité système (voir ci-dessous). Dans ce cas, si le fichier existe déjà, sadc le remplacera s'il date du mois précédent. Par défaut, sadc collecte la plupart des données disponibles auprès du noyau. Mais il existe également des métriques optionnelles, pour lesquelles les options pertinentes doivent être explicitement passées à sadc pour être collectées (voir l'option -S ci-dessous).

Le fichier quotidien standard des données d'activité système est nommé saDD à moins que l'option -D ne soit utilisée, auquel cas son nom est saAAAAJJ, où AAAA représente l'année en cours, MM le mois en cours et JJ le jour en cours. Par défaut, il est situé dans le répertoire /var/log/sa. Il est cependant possible de spécifier un emplacement alternatif : si fichier_sortie est un répertoire (au lieu d'un fichier normal) alors il sera considéré comme le répertoire où le fichier quotidien standard des données d'activité système sera sauvegardé.

Lorsque le paramètre compte n'est pas spécifié, sadc écrit ses données indéfiniment. Lorsque les deux paramètres intervalle et compte ne sont pas spécifiés, et que l'option -C n'est pas utilisée, un enregistrement factice, utilisé au démarrage du système pour marquer le moment où les compteurs redémarrent à 0, sera écrit. Par exemple, l'un des scripts de démarrage du système peut écrire la marque de redémarrage dans le fichier de données quotidien avec la commande d'entrée :

/usr/lib/sa/sadc -

La commande sadc est destinée à être utilisée en arrière-plan par la commande sar.

Note : La commande sadc ne rend compte que des activités locales.

OPTIONS

-C commentaire
Lorsque ni le paramètre intervalle ni le paramètre compte ne sont spécifiés, cette option indique à sadc d'écrire un enregistrement factice contenant la chaîne de commentaire spécifiée. Ce commentaire peut ensuite être affiché avec l'option -C de sar.
-D
Utilise saAAAAJJ au lieu de saJJ comme nom du fichier quotidien standard des données d'activité système.
-F
La création de fichier_sortie sera forcée. Si le fichier existe déjà et a un format inconnu de sadc, il sera tronqué. Ceci peut être utile pour les fichiers de données quotidiens créés par une version antérieure de sadc et dont le format n'est plus compatible avec celui actuel.
-f
fdatasync() sera utilisé pour s'assurer que les données sont écrites sur le disque. Ceci diffère de l'opération normale dans le sens où une réinitialisation brutale du système est moins susceptible de corrompre les fichiers de données saJJ. Cependant, cela se fait au détriment des performances du processus sadc car le progrès sera bloqué pendant que les données sont écrites sur le disque sous-jacent au lieu de seulement dans le cache.
-L
sadc essaiera d'obtenir un verrou exclusif sur fichier_sortie avant d'y écrire ou de le tronquer. L'échec de l'obtention du verrou est fatal, sauf dans le cas où l'on essaie d'écrire un enregistrement normal (c'est-à-dire ni factice ni d'en-tête) dans un fichier existant, auquel cas sadc réessayera lors du prochain intervalle. Habituellement, la seule raison pour laquelle un verrou échouerait serait si un autre processus sadc écrivait également dans le fichier. Cela peut arriver lorsque cron est utilisé pour lancer sadc. Si le système est très chargé, un ancien sadc pourrait encore être en cours d'exécution lorsque cron en démarre un nouveau. Sans verrouillage, cette situation peut entraîner la corruption du fichier d'activité système.
-S { mot-clé[,...] | TOUT | XTOUT }
Les mots-clés possibles sont DISK, INT, IPV6, POWER, SNMP, XDISK, TOUT et XTOUT.
Spécifie quelles activités optionnelles doivent être collectées par sadc. Certaines activités sont optionnelles pour éviter que les fichiers de données ne deviennent trop volumineux. Le mot-clé DISK indique que sadc doit collecter les données des périphériques de bloc. Le mot-clé INT indique que sadc doit collecter les données des interruptions système. Le mot-clé IPV6 indique que les statistiques IPv6 doivent être collectées par sadc. Le mot-clé POWER indique que sadc doit collecter les statistiques de gestion de l'énergie. Le mot-clé SNMP indique que les statistiques SNMP doivent être collectées par sadc. Le mot-clé TOUT équivaut à spécifier tous les mots-clés ci-dessus et donc toutes les activités précédentes sont collectées.
Le mot-clé XDISK est une extension de celui de DISK et indique que les statistiques des partitions et des systèmes de fichiers doivent être collectées par sadc en plus des statistiques disque. Cette option ne fonctionne qu'avec les noyaux 2.6.25 et plus récents. Le mot-clé XTOUT équivaut à spécifier tous les mots-clés ci-dessus (y compris les extensions de mots-clés) et donc toutes les activités possibles sont collectées.
Note importante : Les activités (y compris optionnelles) sauvegardées dans un fichier de données existant priment sur celles sélectionnées avec l'option -S. En conséquence, l'ajout de données à un fichier de données existant entraînera l'ignorance de l'option -S.
-V
Affiche le numéro de version puis quitte.

ENVIRONNEMENT

La commande sadc prend en compte la variable d'environnement suivante :

S_TIME_DEF_TIME
Si cette variable existe et que sa valeur est UTC alors sadc sauvegardera ses données en temps UTC. sadc utilisera également le temps UTC au lieu du temps local pour déterminer le fichier quotidien actuel situé dans le répertoire /var/log/sa.

EXEMPLES

/usr/lib/sa/sadc 1 10 /tmp/fichier_donnees
Écrit 10 enregistrements d'intervalles d'une seconde dans le fichier binaire /tmp/fichier_donnees.
/usr/lib/sa/sadc -C "Début Sauvegarde" /tmp/fichier_donnees
Insère le commentaire "Début Sauvegarde" dans le fichier /tmp/fichier_donnees.

BOGUES

Le système de fichiers /proc doit être monté pour que la commande sadc fonctionne.

Toutes les statistiques ne sont pas nécessairement disponibles, en fonction de la version du noyau utilisée. sadc suppose que vous utilisez au moins un noyau 2.6.

FICHIERS

/var/log/sa/saDD
/var/log/sa/saAAAAJJ

Les fichiers quotidiens standard des données d'activité système et leur emplacement par défaut. AAAA représente l'année en cours, MM le mois en cours et JJ le jour en cours.
/proc et /sys contiennent divers fichiers avec des statistiques système.
