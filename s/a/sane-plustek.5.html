NOM

sane-plustek - Backend SANE pour les scanners à plat USB basés sur LM983[1/2/3]

DESCRIPTION

La bibliothèque sane-plustek implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners à plat USB basés sur les chipsets Merlin de National Semiconductor (LM9831, 9832 et 9833). Si vous recherchez un support pour port parallèle pour les scanners Plustek, veuillez vous référer au backend sane-plustek_pp(5).

APPAREILS SUPPORTÉS

Le backend est capable de supporter les scanners USB basés sur les chipsets LM9831, LM9832 et LM9833 de National Semiconductor. Les tableaux suivants montrent divers appareils qui sont actuellement rapportés comme fonctionnels. Si votre scanner Plustek a un identifiant de produit différent, alors l'appareil n'est PAS supporté par ce backend.

AUTRES SCANNEURS PLUSTEK

Pour le support des périphériques parallèle, voir le backend sane-plustek_pp(5).
Le scanner SCSI OpticPro 19200S est un scanner Artec AM12S rebadgé et est supporté par le backend sane-artec(5).
Seuls les appareils Plustek basés sur le chipset National Semiconductor LM983[1/2/] sont supportés par ce backend. Les anciennes versions des U12, UT12, U1212 et U1248 (chipset GrandTech) ne sont pas supportées.

CONFIGURATION

Pour utiliser votre scanner avec ce backend, vous avez besoin d'au moins deux entrées dans le fichier de configuration /etc/sane.d/plustek.conf

[usb] vendor-id product-id
device /dev/usbscanner

[usb] indique au backend que le nom de périphérique suivant (ici /dev/usbscanner) doit être interprété comme un périphérique scanner USB. Si l'identifiant du vendeur et le produit n'ont pas été spécifiés, le backend essaie de le détecter par lui-même. Si le périphérique est défini sur auto, alors le prochain périphérique correspondant est utilisé.
Les options suivantes peuvent être utilisées pour une configuration par défaut de votre appareil. La plupart d'entre elles sont également disponibles via l'interface graphique.

Les Options :

option warmup t

t spécifie la période de préchauffage en secondes, si réglé sur -1, la fonction de préchauffage automatique sera utilisée

option lampOff t

t est le temps en secondes pour éteindre les lampes en mode veille

option lOffonEnd b

b spécifie le comportement lors de la fermeture du backend, 1 --> éteindre les lampes, 0 --> ne pas changer l'état des lampes

option mov m

m est le commutateur de substitution de modèle. Il ne fonctionne qu'avec les appareils Mustek BearPaw. 
m/PID |    0x1000    |    0x1001
------+--------------+--------------
  0   | BearPaw 1200 | BearPaw 2400
  1   |  sans fonction | BearPaw 1200

option invertNegatives b

b 0 --> ne pas inverser l'image lors des scans de négatifs,
1 --> inverser l'image

option cacheCalData b

b 0 --> ne pas sauvegarder les résultats de calibrage,
1 --> sauvegarder les résultats de calibrage dans le répertoire ~/.sane/

option altCalibration b

b 0 --> utiliser les routines de calibrage standard,
1 --> utiliser le calibrage alternatif (uniquement pour les appareils non Plustek, standard pour les appareils CIS)

option skipFine b

b 0 --> effectuer le calibrage fin,
1 --> ignorer

fine calibration (uniquement pour les appareils non Plustek)

option skipFineWhite b

b 0 --> effectuer l'étalonnage fin du blanc,
1 --> ignorer l'étalonnage fin du blanc (uniquement pour les appareils non Plustek)

option skipDarkStrip b

b 0 --> effectuer l'étalonnage des noirs, avec la lampe allumée en utilisant la bande d'étalonnage des noirs du scanner. Si le scanner n'a pas une telle bande, la méthode alternative consiste à éteindre la lampe pendant cette étape.
1 --> éteindre toujours la lampe pour l'étalonnage des noirs, même si une bande noire est disponible

option skipCalibration b

b 0 --> effectuer l'étalonnage,
1 --> ignorer l'étalonnage (uniquement pour les appareils non Plustek)

option enableTPA b

b 0 --> comportement par défaut, spécifié par les tables internes,
1 --> remplacer les tables internes et autoriser le mode TPA (uniquement pour EPSON/UMAX)

option posOffX x
option posOffY y
option tpaOffX x
option tpaOffY y
option negOffX x
option negOffY y

x y En utilisant ces paramètres, l'utilisateur peut ajuster les positions d'image données. Veuillez noter qu'il n'y a pas de vérification interne de plage pour cette fonctionnalité.

option posShadingY p
option tpaShadingY p
option negShadingY p

p remplace la position d'ombrage interne. Les valeurs sont en pas. Veuillez noter qu'il n'y a pas de vérification interne de plage pour cette fonctionnalité.

option redGamma r
option greenGamma g
option blueGamma b
option grayGamma gr

r g b gr
En utilisant ces valeurs, la table gamma linéaire interne (r,g,b,gr = 1.0) peut être ajustée.

option red_gain r
option red_offset ro
option green_gain g
option green_offset go
option blue_gain b
option blue_offset bo

r g b ro go bo Ces valeurs peuvent être utilisées pour définir les valeurs de gain et de décalage de l'AFE pour chaque canal. La plage est comprise entre 0 et 63. -1 signifie autocalibration.

Voir le fichier plustek.conf pour des exemples.

Note :
Vous devez vous assurer que le sous-système USB est correctement chargé et que vous avez accès au nœud de périphérique. Pour plus de détails, consultez la page de manuel sane-usb(5). Vous pouvez utiliser sane-find-scanner(1) pour vérifier que vous avez accès à votre appareil.

Note :
S'il n'y a pas de fichier de configuration, le backend utilise par défaut device auto

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail actuel (".") et ensuite dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires spécifiés explicitement. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_PLUSTEK
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie.

Exemple : export SANE_DEBUG_PLUSTEK=10

CONTACT ET RAPPORTS DE BOGUES

Veuillez envoyer toute information et tout rapport de bogue à :
Liste de diffusion SANE

Des informations et des conseils supplémentaires peuvent être obtenus dans notre archive de liste de diffusion à l'adresse : http://www.sane-project.org/mailing-lists.html.

Pour obtenir des messages de débogage du backend, veuillez définir la variable d'environnement SANE_DEBUG_PLUSTEK avant d'appeler votre interface SANE préférée (par exemple, scanimage(1)) :

export SANE_DEBUG_PLUSTEK=20 ; scanimage

La valeur contrôle la verbosité de la sortie. Veuillez noter que les valeurs supérieures à 24 forcent le backend à produire des fichiers de données brutes qui pourraient être assez volumineux. Le suffixe de ces fichiers est ".raw". Pour les rapports de problèmes, il devrait suffire de régler la verbosité à 13.

BOGUES CONNUS & RESTRICTIONS

* Le pilote ne prend pas en charge ces mises à l'échelle manuelles jusqu'à 16 fois la résolution physique. La seule mise à l'échelle est effectuée sur les résolutions comprises entre la résolution physique du capteur CCD/CIS et le moteur pas à pas, c'est-à-dire que vous avez un scanner de 600x1200 dpi et que vous numérisez à 800 dpi, donc une mise à l'échelle est nécessaire, car le capteur ne fournit que 600 dpi mais le moteur est capable de réaliser des pas de 1200 dpi.

* La politique des modèles de Plustek est quelque peu incohérente. Ils vendent des appareils techniquement différents sous le même nom de produit. Par conséquent, il est possible que certains appareils comme les UT12 ou U12 ne fonctionnent pas - veuillez vérifier la liste des modèles ci-dessus et comparer l'ID du produit à celui de votre appareil.

* La qualité de la numérisation de négatifs/diapositives est médiocre.
