sane-st400(5) SANE Scanner Access Now Easy sane-st400(5)

NOM

sane-st400 - Backend SANE pour les scanners à plat Siemens ST/Highscan

DESCRIPTION

La bibliothèque sane-st400 implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners à plat Siemens ST400 et compatibles. Actuellement, les scanners suivants sont pris en charge par ce backend :

Siemens ST400 (niveaux de gris 6 bits)
Siemens ST800 (niveaux de gris 6 bits)

Le pilote prend en charge les numérisations en ligne et en niveaux de gris jusqu'à 8 bits par pixel.

La série Siemens ST/Highscan comprend plusieurs autres modèles, par exemple les ST300 et ST600. Si vous possédez l'un de ces scanners, ou un scanner autre que ceux listés ci-dessus qui fonctionne avec ce backend, veuillez nous en informer en envoyant le nom du modèle du scanner, l'ID SCSI et la révision du firmware à sane-devel@alioth-lists.debian.net. Consultez http://www.sane-project.org/mailing-lists.html concernant l'abonnement à sane-devel.

NOMS DE PÉRIPHÉRIQUE

Ce backend attend des noms de périphérique de la forme :

spécial

Où spécial est le nom du chemin d'accès du périphérique qui correspond à un scanner SCSI. Pour les scanners SCSI, le nom du périphérique spécial doit être un périphérique SCSI générique ou un lien symbolique vers un tel périphérique. Sous Linux, un tel nom de périphérique pourrait être /dev/sga ou /dev/sge, par exemple. Voir sane-scsi(5) pour plus de détails.

CONFIGURATION

Le contenu du fichier st400.conf est une liste de noms de périphériques correspondant aux scanners Siemens. Les lignes vides et les lignes commençant par une marque de hachage (#) sont ignorées. Un exemple de fichier de configuration est montré ci-dessous :

/dev/scanner
# ceci est un commentaire
/dev/sge

Le fichier de configuration par défaut distribué avec SANE ressemble à ceci :

scsi SIEMENS "ST 400" Scanner * * 3 0

Dans cette configuration, le pilote ne peut accéder qu'au modèle ST400 à l'ID SCSI 3 LUN 0 (voir la section BOGUES ci-dessous pour la raison). Pour utiliser le pilote avec d'autres modèles de scanner, ajoutez une ligne appropriée au fichier de configuration. Par exemple, pour l'utiliser avec un ST800 à l'ID SCSI 3 LUN 0, ajoutez la ligne :

scsi SIEMENS "ST 800" Scanner * * 3 0

FICHIERS

/etc/sane.d/st400.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-st400.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-st400.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux points (`:'), sous OS/2, ils sont séparés par un point virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_ST400
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des niveaux inférieurs réduisent la verbosité.

FONCTIONNALITÉ MANQUANTE

Tout sauf le plus basique.

BOGUES

Actuellement, le backend ne vérifie pas si le périphérique connecté est réellement un ST400. Il acceptera volontiers tout ce qui correspond aux entrées de configuration. Cela facilite le test du backend avec d'autres scanners : ajoutez simplement une ligne appropriée au fichier de configuration. Le fichier de configuration tel que distribué (voir ci-dessus) ne fonctionne qu'avec le ST400. Soyez prudent : s'il n'y a pas de fichier de configuration du tout, le backend utilise par défaut /dev/scanner.

Le ST400 répond sur les huit LUNs SCSI. Normalement, ce n'est pas un problème, car le support LUN est généralement désactivé dans les pilotes SCSI, mais si vous voyez plusieurs instances du scanner dans une liste de périphériques, désactivez les LUNs dans votre configuration SCSI ou modifiez l'entrée dans le fichier de configuration pour ne correspondre qu'à la LUN 0.

DÉBOGAGE

Si vous rencontrez un bogue, veuillez définir la variable d'environnement SANE_DEBUG_ST400 à 128 et essayer de reproduire le problème. Envoyez-moi ensuite un rapport avec le journal joint.

Si vous rencontrez une erreur sur le bus SCSI ou des images coupées et/ou déplacées, veuillez également définir la variable d'environnement SANE_DEBUG_SANEI_SCSI à 128 avant de m'envoyer le rapport.
