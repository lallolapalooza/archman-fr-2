NOM

samu — outil de construction compatible ninja

SYNOPSIS

samu [-C dir] [-d debugflag] [-f buildfile] [-j maxjobs] [-k maxfail] [-w warnflag=action] [-nv] [cible...]

samu [-C dir] [-f buildfile] -t clean [-gr] [cible...]

samu [-C dir] [-f buildfile] -t compdb [-x] [règle...]

samu [-C dir] [-f buildfile] -t commands [cible...]

samu [-C dir] [-f buildfile] -t query [cible...]

samu [-C dir] [-f buildfile] -t targets [profondeur [maxprofondeur]]

samu [-C dir] [-f buildfile] -t targets règle [nomrègle]

samu [-C dir] [-f buildfile] -t targets tout

samu -t liste

DESCRIPTION

samu charge un manifeste de construction à partir de buildfile et reconstruit les cibles si elles sont obsolètes. Si aucune cible n'est spécifiée, les cibles par défaut du manifeste sont construites. S'il n'y a pas de cibles par défaut, les nœuds feuilles du graphe de dépendances sont construits (sorties sans action consommatrice).

Les cibles sont obsolètes si elles sont plus anciennes que la plus récente entrée de l'action génératrice, s'il n'y a pas d'entrée dans le journal de construction, ou si la commande pour construire la cible diffère de celle utilisée précédemment. Les cibles construites avec des règles generator ne sont pas reconstruites si la commande change.

Si l'outil clean est utilisé, les cibles sont nettoyées à la place. Lorsqu'une cible est nettoyée, elle est supprimée ainsi que toutes ses entrées. Les cibles sans actions génératrices ne sont jamais supprimées. Les cibles construites avec des règles generator ne sont supprimées que si -g est spécifié.

Si l'outil commands est utilisé, une liste de commandes shell utilisées pour construire les cibles spécifiées (ou par défaut) est imprimée.

Si l'outil compdb est utilisé, une base de données de compilation (https://clang.llvm.org/docs/JSONCompilationDatabase.html) est imprimée à la place.

Si l'outil query est utilisé, les entrées et sorties des cibles sont imprimées à la place.

Si l'outil targets est utilisé, une liste de cibles sera affichée, soit par règle, soit par profondeur. Le premier argument détermine comment les cibles seront affichées :

profondeur
Un arbre de cibles indenté sera affiché, à partir des cibles racines (celles sans cibles dépendantes), jusqu'à la profondeur spécifiée par maxprofondeur (par défaut 1).
règle
Si nomrègle est donné, une liste de cibles utilisant la règle donnée sera affichée. Sinon, une liste de fichiers sources sera affichée.
tout
Une liste de toutes les cibles sera affichée.

Si l'outil list est utilisé, une liste des outils disponibles est affichée.

OPTIONS

-C
Changer le répertoire de travail vers dir avant la construction.
-d
Activer une option de débogage. Ce drapeau peut être spécifié plusieurs fois pour activer plusieurs options de débogage. Les valeurs possibles pour debugflag sont :
explain
Imprimer des messages expliquant pourquoi les sorties étaient sales.
keepdepfile
Ne pas supprimer $depfile après son analyse.
keeprsp
Ne pas supprimer $rspfile après la fin ou l'échec du travail.
-f
Charger le manifeste à partir de buildfile au lieu de build.ninja.
-j
Exécuter jusqu'à maxjobs travaux en parallèle (par défaut basé sur le nombre de CPU). S'il est à zéro, autoriser un nombre illimité de travaux concurrents.
-k
Autoriser jusqu'à maxfail échecs de travaux. S'il est négatif ou nul, autoriser n'importe quel nombre d'échecs de travaux.
-n
N'exécute pas réellement les commandes ni ne met à jour le journal.
-v
Imprimer les commandes complètes au lieu de seulement la description.
-w
Contrôler la façon dont certaines erreurs sont traitées. Si warnflag est dupbuild, action spécifie quoi faire si une sortie est listée dans plusieurs arêtes de construction. Si action est err, traiter cela comme une erreur et échouer. Si action est warn, imprimer seulement un message diagnostique.
-t
Au lieu de construire, invoquer un sous-outil. Tous les arguments et drapeaux après le sous-outil sont interprétés par le sous-outil. Les sous-outils actuellement supportés sont clean, compdb, et targets.
-g
Lors du nettoyage, nettoyer également les sorties des actions generator.
-r
cibles sont interprétées comme des règles, et toutes les sorties des actions avec les types de règles spécifiés seront nettoyées à la place.
-x
Lors de l'impression d'une base de données de compilation, remplacer @$rspfile par $rspfile_content (avec <espace> à la place de <nouvelle ligne).

ENVIRONNEMENT

SAMUFLAGS
Options pour samu qui sont appliquées avant celles spécifiées sur la ligne de commande. Les seules options autorisées dans SAMUFLAGS sont -v et -j.
NINJA_STATUS
La sortie de statut imprimée à gauche de la description de chaque règle, utilisant des spécificateurs de conversion de type printf. Si non défini, la valeur par défaut est "[%s/%t] ".

Spécificateurs de conversion disponibles :

%s
Nombre de tâches démarrées.
%f
Nombre de tâches terminées.
%t
Nombre total de tâches.
%r
Nombre de tâches en cours d'exécution.
%u
Nombre de tâches restantes.
%p
Pourcentage de tâches terminées.
%o
Taux de tâches terminées par seconde (à 1 décimale).
%e
Temps écoulé en secondes (à 3 décimales).
%%
Le caractère '%' .
