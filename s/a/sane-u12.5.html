sane-u12(5) SANE Scanner Access Now Easy sane-u12(5)

NOM

sane-u12 - Backend SANE pour scanners à plat USB Plustek, basé sur d'anciennes conceptions de port parallèle

DESCRIPTION

La bibliothèque sane-u12 implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners à plat USB Plustek basés sur l'ASIC 98003 de Plustek (ASIC de port parallèle) et une puce de pont USB-port parallèle GeneSys Logics.

PÉRIPHÉRIQUES SUPPORTÉS

Le backend est capable de prendre en charge certains anciens scanners USB Plustek qui basaient leur ancienne conception de port parallèle autour de l'ASIC 98003 et d'autres appareils Plustek rebadgés. Les tableaux suivants vous donneront un bref aperçu.

Si votre scanner Plustek a un autre identifiant de produit, alors l'appareil N'EST PAS supporté par ce backend.

Vendeur Plustek - ID : 0x07B3 

----------------------------------------------------------
Modèle : Vendeur-ID : ID Produit :
----------------------------------------------------------
OpticPro U12 : 0x07B3 : 0x0001
OpticPro U1212 : 0x07B3 : 0x0001
OpticPro UT12 : 0x07B3 : 0x0001

Vendeur KYE/Genius 

--------------------------------------------------------
Modèle USB : Vendeur-ID : ID Produit :
--------------------------------------------------------
ColorPage Vivid III USB : 0x07B3 : 0x0001
ColorPage HR6 V1 : 0x0458 : 0x2004

CONFIGURATION

Pour utiliser votre scanner avec ce backend, vous avez besoin d'au moins deux entrées dans le fichier de configuration /etc/sane.d/u12.conf

[usb] vendor-id product-id
device /dev/usbscanner

[usb] indique au backend que le nom de périphérique suivant (ici /dev/usbscanner) doit être interprété comme un périphérique de scanner USB. Si les identifiants de vendeur et de produit n'ont pas été spécifiés, le backend essaie de les détecter par lui-même. Si le périphérique est réglé sur auto, alors le prochain périphérique correspondant est utilisé.

Les Options :

option warmup t

t spécifie la période de préchauffage en secondes

option lampOff t

t est le temps en secondes pour éteindre les lampes en mode veille

option lOffonEnd b

b spécifie le comportement lors de la fermeture du backend, 1 --> éteindre les lampes, 0 --> ne pas changer l'état des lampes

Voir le fichier u12.conf pour des exemples.

Remarque : Vous devez vous assurer que le sous-système USB est chargé correctement et que vous avez accès au nœud de périphérique. Pour plus de détails, voir la page de manuel sane-usb(5). Vous pouvez utiliser sane-find-scanner(1) pour vérifier que vous avez accès à votre périphérique.

Remarque :
S'il n'y a pas de fichier de configuration, le backend utilise par défaut device auto

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail actuel (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires spécifiés explicitement. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, . et /etc/sane.d (dans cet ordre).
SANE_DEBUG_U12
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie.

Exemple : export SANE_DEBUG_U12=10

CONTACT ET SIGNALEMENTS DE BOGUES

Veuillez envoyer toute information et tout signalement de bogues à :
Liste de diffusion SANE

Des informations et des indices supplémentaires peuvent être obtenus auprès de l'archive de notre liste de diffusion à : http://www.sane-project.org/mailing-lists.html.

Pour obtenir des messages de débogage du backend, veuillez définir la variable d'environnement SANE_DEBUG_U12 avant d'appeler votre front-end SANE préféré (par exemple, xscanimage(1)) :

export SANE_DEBUG_U12=20 ; xscanimage

La valeur contrôle la verbosité du backend.

BOGUES CONNUS & RESTRICTIONS

* Le pilote est à l'état alpha, alors ne vous attendez pas à grand-chose !!!

* Lors de l'utilisation de libusb, il se peut que le backend se bloque. Dans ce cas, débranchez et rebranchez le scanner.
