NOM

sane-genesys - backend SANE pour scanners à plat USB basés sur GL646, GL841, GL843, GL847 et GL124

DESCRIPTION

La bibliothèque sane-genesys implémente un backend SANE (Scanner Access Now Easy) qui fournit l'accès aux scanners à plat USB basés sur les puces Genesys GL646, GL841, GL843, GL847 et GL124. Actuellement, les scanners suivants sont connus pour fonctionner avec ce backend :

Canon LiDE 35/40/50/60/100/110/120/200/210/220/700
Hewlett-Packard HP2300C/HP2400/HP3670/HP3690/G4010/G4050
Medion MD5345/MD6228/MD6274
Panasonic KV-SS080
Plustek OpticBook 3600
Pentax DSmobile 600
Syscan/Ambir DocketPORT 467/485/487/665/685
Visioneer OneTouch 7100/Strobe XP100 (rev3)/XP200/XP300/Roadwarrior
Xerox Travel Scanner 100, OneTouch 2400

C'est un logiciel stable pour les modèles supportés. Mais si vous testez des scanners nouveaux ou non testés, gardez la main sur la prise du scanner et débranchez-la si la tête heurte à la fin de la zone de balayage.

Si vous possédez un scanner autre que ceux listés ci-dessus qui fonctionne avec ce backend, veuillez m'en informer en envoyant le nom exact du modèle du scanner et les identifiants vendeur et produit USB (par exemple depuis /proc/bus/usb/devices, sane-find-scanner ou le syslog) à la liste de diffusion sane-devel. Même si le nom du scanner est seulement légèrement différent des modèles mentionnés ci-dessus, veuillez m'en informer.

Si vous possédez un scanner qui n'est pas détecté par le backend genesys mais qui possède un chipset GL646, GL841, GL843, GL847 ou GL124, vous pouvez essayer de l'ajouter au backend.

CALIBRAGE

Pour fournir une qualité d'image correcte, les scanners à défilement doivent être calibrés à l'aide de la feuille de calibration vendue avec le scanner. Pour effectuer le calibration, vous devez insérer cette cible dans le chargeur puis lancer la calibration soit en passant l'option --calibrate à scanimage(1), soit en cliquant sur le bouton 'calibrate' disponible dans les 'options avancées' d'une interface graphique. Le résultat de la calibration est stocké dans un fichier dans le répertoire personnel de l'utilisateur qui la réalise. Si vous branchez le scanner sur une autre machine ou l'utilisez avec un autre compte, la calibration devra être refaite, sauf si vous utilisez l'option --calibration-file. Si aucun répertoire personnel n'est défini, USERAPPPROFILE sera utilisé, puis TMPDIR ou TMP. Si aucun de ces répertoires n'existe, le backend essaiera d'écrire dans le répertoire de travail courant. Les scanners à plat utilisent également le fichier de calibration comme cache pour éviter la calibration avant chaque scan. Le nom du fichier de calibration est le nom du modèle du scanner si un seul scanner est détecté. Dans le cas de plusieurs modèles identiques, le nom du fichier sera le nom du périphérique USB logique. Le temps d'expiration gère la durée de validité d'une calibration dans le cache. Une valeur de -1 signifie pour toujours, 0 signifie pas de cache.

OPTIONS DE SCAN SUPPLÉMENTAIRES

--lamp-off-time nombre
La lampe sera éteinte après le temps donné (en minutes). Une valeur de 0 signifie que la lampe ne sera pas éteinte.
--threshold pourcentage
0..100% (par pas de 1). Sélectionne la luminosité minimale pour obtenir un point blanc. Les pixels avec une luminosité inférieure à cette valeur seront balayés en noir.
--brightness valeur
-100..100 (par pas de 1). Définit l'amélioration de la luminosité. 0 pour aucune amélioration, des valeurs négatives pour diminuer la luminosité, et des valeurs positives pour l'augmenter.
--contrast valeur
-100..100 (par pas de 1). Définit l'amélioration du contraste. 0 pour aucune amélioration, des valeurs négatives pour diminuer le contraste, et des valeurs positives pour l'augmenter.
--disable-interpolation oui|non
Lorsque vous utilisez des résolutions élevées où la résolution horizontale est inférieure à la résolution verticale, les données sont étendues par logiciel pour préserver la géométrie de l'image. Cela peut être désactivé par cette option pour obtenir des données numérisées réelles.
--disable-dynamic-lineart oui|non
Désactive l'utilisation d'un algorithme adaptatif logiciel pour générer du dessin au trait et s'en remet au dessin au trait matériel.
--color-filter Aucun|Rouge|Vert|Bleu
Lors de l'utilisation du niveaux de gris ou du dessin au trait, cette option sélectionne la couleur utilisée. L'utilisation d'un filtre de couleur donnera un scan monochrome. Les scanners basés sur CIS peuvent faire des vrais niveaux de gris lorsque aucun filtre (valeur Aucun) n'est sélectionné.
--lamp-off-scan
La lampe sera éteinte pendant le scan. La calibration est toujours effectuée avec la lampe allumée.
--clear-calibration
Efface les données du cache de calibration, déclenchant une nouvelle calibration pour le périphérique lors du prochain scan.
--calibration-file
Spécifie le nom du fichier de calibration à utiliser. Au moins le répertoire contenant le fichier doit exister, car il ne sera pas créé. Cette option est désactivée si le backend est exécuté en tant que root. Elle peut être utilisée pour les scanners à défilement afin de partager un fichier de calibration pour plusieurs utilisateurs.
--expiration-time
Spécifie le temps (en minutes) pendant lequel une calibration mise en cache est considérée comme valide. Si plus ancienne que la valeur donnée, une nouvelle calibration est effectuée. Une valeur de -1 signifie aucune expiration et les valeurs mises en cache sont conservées à jamais à moins d'être effacées par l'utilisateur avec l'option d'effacement de calibration. Une valeur de 0 signifie que le cache est désactivé.

De plus, plusieurs options 'logicielles' sont exposées par le backend. Ce sont des réimplémentations de fonctionnalités fournies nativement par des scanners plus grands, mais exécutées sur l'ordinateur hôte. Cela permet aux petites machines d'avoir des capacités similaires. Veuillez noter que ces fonctionnalités sont quelque peu simplistes et peuvent ne pas fonctionner aussi bien que les implémentations natives. Notez également que toutes ces fonctionnalités nécessitent que le pilote mette en cache l'image entière en mémoire. Cela entraînera très certainement une réduction de la vitesse de balayage.

--swcrop
Demande au pilote de détecter les extrémités du papier dans l'image plus grande et de rogner les bords vides.
--swdeskew
Demande au pilote de détecter la rotation du papier dans l'image plus grande et de compenser la rotation.
--swdespeck --despeck X
Demande au pilote de trouver et de supprimer les points d'un diamètre X ou plus petit de l'image, et de remplir l'espace avec la couleur environnante moyenne.
--swskip 0..100% (par pas de 1) [0]
Demande au pilote de rejeter les pages avec un faible nombre de pixels sombres.
--swderotate[=(oui|non)] [non]
Demande au pilote de détecter et de corriger la rotation de l'image de 90 degrés.

PROBLÈMES SYSTÈME

Ce backend nécessite libusb-0.1.6 ou une version ultérieure installée, et n'a pas été testé dans d'autres configurations qu'un noyau Linux 2.6.9 ou supérieur. Cependant, il devrait fonctionner sur n'importe quel système avec libusb où le paquet SANE peut être compilé. Pour la configuration des permissions et des informations USB générales, consultez sane-usb(5).

CONFIGURATION

Le contenu du fichier genesys.conf est une liste de lignes usb contenant les identifiants vendeur et produit qui correspondent aux scanners USB. Le fichier peut également contenir des lignes d'options. Les lignes vides et les lignes commençant par un dièse (#) sont ignorées. Les scanners sont autodétectés par les déclarations usb vendor_id product_id qui sont déjà incluses dans genesys.conf. "vendor_id" et "product_id" sont des nombres hexadécimaux qui identifient le scanner.

FICHIERS

/etc/sane.d/genesys.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-genesys.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-genesys.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui supportent le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") et ensuite dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour effet que les répertoires tmp/config, ., et /etc/sane.d seraient recherchés (dans cet ordre).
SANE_DEBUG_GENESYS
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie. Si le niveau de débogage est réglé à 1 ou plus, certaines options de débogage deviennent disponibles qui sont normalement cachées. Manipulez-les avec précaution. Ceci affichera des messages liés aux fonctions centrales de genesys.
SANE_DEBUG_GENESYS_IMAGE
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement permet de journaliser les données d'image intermédiaires. Pour activer ce mode, définissez la variable d'environnement à 1.

Exemple (sortie complète et très verbeuse pour gl646 :
export SANE_DEBUG_GENESYS=255

LIMITATIONS

L'économie d'énergie n'est pas implémentée pour les scanners basés sur gl646. Le mode dynamique (émulé à partir de données grises et avec tramage) n'est pas activé pour les scanners basés sur gl646. La résolution matérielle en ligne de texte est limitée à 600 dpi pour les scanners basés sur gl847, en raison de la manière dont les capteurs d'image sont construits.

Ce backend sera beaucoup plus lent s'il n'utilise pas libusb-1.0. Assurez-vous donc que sane-backends est compilé avec l'option --enable-libusb_1_0.

BOGUES

Pour le LiDE 200, les données numérisées à 4800 dpi sont obtenues "telles quelles" à partir du capteur. Il semble que le pilote Windows effectue un traitement numérique pour les améliorer, ce qui n'est pas implémenté dans le backend.
