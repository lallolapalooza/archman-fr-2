NOM

sane-dll - Chargeur dynamique de backends SANE

DESCRIPTION

La bibliothèque sane-dll implémente un backend SANE (Scanner Access Now Easy) qui fournit l'accès à un nombre arbitraire d'autres backends SANE. Ces backends peuvent être pré-chargés lors de la compilation de la bibliothèque sane-dll ou, sur les systèmes qui supportent le chargement dynamique de bibliothèques partagées, les backends peuvent être chargés à l'exécution. Dans ce dernier cas, l'ajout du support pour un nouveau backend implique simplement l'installation de la bibliothèque pertinente dans /usr/lib/sane et l'ajout d'une entrée dans le fichier de configuration dll.conf. En d'autres termes, aucune application n'a besoin d'être modifiée ou recompilée pour ajouter la prise en charge de nouveaux périphériques.

NOMS DE PÉRIPHÉRIQUES

Ce backend attend des noms de périphériques de la forme :

backend:périphérique

Où backend est le nom du backend et périphérique est le nom du périphérique dans ce backend qui doit être adressé. Si le nom du périphérique ne contient pas de deux-points (:), alors la chaîne entière est traitée comme la chaîne périphérique pour le backend par défaut. Le backend par défaut est le backend listé en dernier dans le fichier de configuration (voir ci-dessous) ou le premier backend pré-chargé (le cas échéant).

CONFIGURATION

Le contenu du fichier dll.conf est une liste de noms de backends qui peuvent être chargés dynamiquement à la demande. Les lignes vides sont ignorées, ainsi que tout ce qui suit un signe dièse (#). Un exemple de fichier de configuration est montré ci-dessous :

net
# ceci est un commentaire
pnm
mustek

Il est également possible d'ajouter un fichier dans /etc/sane.d/dll.d qui contient la liste des backends à ajouter. Les backends mentionnés dans un fichier inclus dans ce répertoire seront ajoutés avant tous les backends listés dans dll.conf. Les fichiers dans /etc/sane.d/dll.d peuvent être nommés librement. Ils doivent suivre les conventions de format applicables à dll.conf.

Notez que les backends qui étaient pré-chargés lors de la compilation de cette bibliothèque n'ont pas besoin d'être listés dans ce fichier de configuration. C'est-à-dire que si un backend était pré-chargé, alors ce backend sera toujours présent, qu'il soit listé dans le fichier de configuration ou non.

La liste des backends pré-chargés est déterminée par la macro PRELOADABLE_BACKENDS dans le fichier backend/Makefile.in de la distribution source de SANE. Après avoir modifié la valeur de cette macro, il est nécessaire de reconfigurer, reconstruire et réinstaller SANE pour que le changement prenne effet.

Les alias sont définis dans le fichier de configuration dll.aliases. Il peut contenir des entrées de la forme


alias SomeName SaneDeviceName
alias "Some Name" SaneDeviceName
hide SaneDeviceName

Par exemple :


alias Epson net:somehost:epson:/dev/sgX
alias "Siemens ST400" st400:/dev/sgY
hide net:somehost:pnm:0
hide net:somehost:pnm:1
alias "Lire depuis un fichier" pnm:0
hide pnm:1

Les noms de périphériques aliasés sont automatiquement masqués.

L'idée est que les utilisateurs n'aient pas à traiter avec des noms de périphériques compliqués (en particulier pour les périphériques réseau), et de masquer d'autres périphériques exportés qui pourraient les confondre. Notez qu'un périphérique masqué peut toujours être accédé si le nom du périphérique est connu, il n'apparaît tout simplement pas sur la liste.

FICHIERS

/etc/sane.d/dll.aliases
La liste des backends aliasés ou masqués.
/etc/sane.d/dll.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-dll.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-dll.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui supportent le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") et ensuite dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_DLL
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'impression de toutes les sorties de débogage. Des niveaux plus bas réduisent la verbosité. 
Valeur  Description
0      imprimer uniquement les erreurs graves
1      imprimer les erreurs normales et les messages importants
2      imprimer les messages normaux
3      imprimer les messages de débogage
4      imprimer tout

Exemple : export SANE_DEBUG_DLL=3
