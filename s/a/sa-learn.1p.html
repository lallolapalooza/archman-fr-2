NOM

sa-learn - entraîne le classificateur bayésien de SpamAssassin

SYNTAXE

sa-learn [options] [fichier]...

sa-learn [options] --dump [ all | data | magic ]

Options :

--ham                 Apprendre les messages suivants comme ham (non spam)
--spam                Apprendre les messages suivants comme spam
--forget              Oublier les messages suivants
--use-ignores         Utiliser bayes_ignore_from et bayes_ignore_to

--dbpath <chemin>       Permet de remplacer en ligne de commande (sous forme de bayes_path)
                      où lire la base de données Bayes

                      Accepte un argument optionnel pour ce qu'il faut afficher
 --regexp <re>        Pour le dump uniquement, spécifie quels tokens afficher
                      basé sur une expression régulière.
-f fichier, --folders=fichier  Lire la liste des fichiers/répertoires depuis le fichier
--dir                 Ignoré ; compatibilité historique
--file                Ignoré ; compatibilité historique

DESCRIPTION

Étant donné une sélection typique de vos courriels classifiés comme spam ou ham (non spam), cet outil alimentera chaque courriel dans SpamAssassin, lui permettant d' 'apprendre' quels signes signifient probablement du spam, et lesquels signifient probablement du ham.

Exécutez simplement cette commande une fois pour chacun de vos dossiers de messagerie, et elle 'apprendra' à partir des courriels qui s'y trouvent.

Notez que le globbing de style csh dans les noms de dossiers de messagerie est pris en charge ; en d'autres termes, lister un nom de dossier comme "*" numérisera tous les dossiers correspondants. Voir "Mail::SpamAssassin::ArchiveIterator" pour plus de détails.

Si vous utilisez des boîtes aux lettres dans un format autre que maildir, vous devriez utiliser les paramètres --mbox ou --mbx.

Les fichiers compressés avec gzip/bzip2/xz/lz4/lzip/lzo sont décompressés automatiquement. Voir "Mail::SpamAssassin::ArchiveIterator" pour plus de détails.

SpamAssassin se souvient des messages qu'il a déjà appris, et ne réapprendra pas ces messages, sauf si vous utilisez l'option --forget. Les messages appris comme spam verront leur balisage SpamAssassin supprimé, à la volée.

Si vous faites une erreur et analysez un courriel comme ham alors qu'il est spam, ou inversement, réexécutez simplement cette commande avec la classification correcte, et l'erreur sera corrigée. SpamAssassin 'oubliera' automatiquement les indications précédentes.

Les utilisateurs de "spamd" qui souhaitent effectuer un apprentissage à distance, sur un réseau, devraient étudier le commutateur "spamc -L".

Apprendre le(s) message(s) d'entrée dans les fichiers suivant l'option comme ham. MIGRATION

There are now multiple backend storage modules available for storing user's bayesian data. As such you might want to migrate from one backend to another. Here is a simple procedure for migrating from one backend to another.

Note that if you have individual user databases you will have to perform a similar procedure for each one of them.

sa-learn --sync
This will sync any outstanding journal entries
sa-learn --backup > backup.txt
This will save all your Bayes data to a plain text file.
sa-learn --clear
This is optional, but good to do to clear out the old database.
Repeat!
At this point, if you have multiple databases, you should perform the procedure above for each of them. (i.e. each user's database needs to be backed up before continuing.)
Switch backends
Once you have backed up all databases you can update your configuration for the new database backend. This will involve at least the bayes_store_module config option and may involve some additional config options depending on what is required by the module. (For example, you may need to configure an SQL database.)
sa-learn --restore backup.txt
Again, you need to do this for every database.

If you are migrating to SQL you can make use of the -u username option in sa-learn to populate each user's database. Otherwise, you must run sa-learn as the user who database you are restoring.

INTRODUCTION TO BAYESIAN FILTERING

(Thanks to Michael Bell for this section!)

For a more lengthy description of how this works, go to http://www.paulgraham.com/ and see "A Plan for Spam". It's reasonably readable, even if statistics make me break out in hives.

The short semi-inaccurate version: Given training, a spam heuristics engine can take the most "spammy" and "hammy" words and apply probabilistic analysis. Furthermore, once given a basis for the analysis, the engine can continue to learn iteratively by applying both the non-Bayesian and Bayesian rulesets together to create evolving "intelligence".

SpamAssassin 2.50 and later supports Bayesian spam analysis, in the form of the BAYES rules. This is a new feature, quite powerful, and is disabled until enough messages have been learnt.

The pros of Bayesian spam analysis:

Can greatly reduce false positives and false negatives.
It learns from your mail, so it is tailored to your unique e-mail flow.
Once it starts learning, it can continue to learn from SpamAssassin and improve over time.

And the cons:

A decent number of messages are required before results are useful for ham/spam determination.
It's hard to explain why a message is or isn't marked as spam.
i.e.: a straightforward rule, that matches, say, "VIAGRA" is easy to understand. If it generates a false positive or false negative, it is fairly easy to understand why.

With Bayesian analysis, it's all probabilities - "because the past says it is likely as this falls into a probabilistic distribution common to past spam in your systems". Tell that to your users! Tell that to the client when he asks "what can I do to change this". (By the way, the answer in this case is "use welcomelisting".)

It will take disk space and memory.
The databases it maintains take quite a lot of resources to store and use.

GETTING STARTED

Still interested? Ok, here's the guidelines for getting this working.

First a high-level overview:

Build a significant sample of both ham and spam.
I suggest several thousand of each, placed in SPAM and HAM directories or mailboxes. Yes, you MUST hand-sort this - otherwise the results won't be much better than SpamAssassin on its own. Verify the spamminess/haminess of EVERY message. You're urged to avoid using a publicly available corpus (sample) - this must be taken from YOUR mail server, if it is to be statistically useful. Otherwise, the results may be pretty skewed.
Use this tool to teach SpamAssassin about these samples, like so:
sa-learn --spam /path/to/spam/folder
sa-learn --ham /path/to/ham/folder
sa-learn --ham hampath1 hampath2 --spam spampath1 spampath2
...

Let SpamAssassin proceed, learning stuff. When it finds ham and spam it will add the "interesting tokens" to the database.

If you need SpamAssassin to forget about specific messages,
use the --forget switch.
utilisez l'option --forget.
Cela peut être appliqué au ham (courrier légitime) ou au spam qui a été traité par les processus sa-learn. C'est un peu comme un marteau, en fait, cela abaisse la pondération des jetons spécifiques dans ce message (uniquement si ce message a été traité auparavant).
L'apprentissage à partir de messages uniques utilise une commande comme celle-ci :
sa-learn --ham --no-sync mailmessage

C'est pratique pour lier à une touche dans votre agent utilisateur de messagerie. C'est très rapide, car toutes les opérations chronophages sont différées jusqu'à ce que vous exécutiez l'option "--sync".

L'auto-apprentissage est activé par défaut
Si vous n'avez pas de corpus de courrier sauvegardé pour apprendre, vous pouvez laisser SpamAssassin apprendre automatiquement le courrier que vous recevez. Si vous apprenez automatiquement à partir de zéro, la quantité de courrier que vous recevez déterminera combien de temps avant que les règles BAYES_* ne soient activées.

FORMATION EFFICACE

Les filtres d'apprentissage nécessitent une formation pour être efficaces. Si vous ne les formez pas, ils ne fonctionneront pas. De plus, vous devez les former régulièrement avec de nouveaux messages pour les maintenir à jour, sinon leurs données deviendront obsolètes et affecteront la précision.

Vous devez former avec des e-mails de spam et de ham. Un seul type de courrier n'aura aucun effet.

Notez que si vos dossiers de messagerie contiennent des éléments tels que des spams transférés, des discussions sur les règles de détection de spam, etc., cela causera des problèmes. Vous devriez éviter d'analyser ces messages si possible. (Un moyen simple de le faire est de les déplacer, dans un dossier qui n'est pas analysé.)

Si les messages à partir desquels vous apprenez ont déjà été filtrés par SpamAssassin, l'apprenant en tiendra compte. En effet, il apprend à quoi ressemblerait chaque message si vous aviez exécuté "spamassassin -d" dessus à l'avance.

Une autre chose à savoir est qu'en général, vous devriez viser à vous former avec au moins 1000 messages de spam et 1000 messages de ham, si possible. Plus c'est mieux, mais tout ce qui dépasse environ 5000 messages n'améliore pas significativement la précision dans nos tests.

Faites attention à vous former à partir de la même source – par exemple, si vous vous formez sur du vieux spam, mais du nouveau courrier ham, le classificateur pensera qu'un courrier avec un ancien horodatage est susceptible d'être du spam.

Il convient également de noter que se former avec une très petite quantité de ham produira des résultats épouvantables. Vous devriez viser à vous former avec au moins la même quantité (ou plus si possible !) de données ham que de spam.

Sur une base continue, il est préférable de continuer à former le filtre pour s'assurer qu'il dispose de données fraîches pour travailler. Il existe plusieurs façons de procéder :

1. Apprentissage supervisé
Cela signifie conserver une copie de tout ou partie de votre courrier, séparé en piles de spam et de ham, et les réutiliser périodiquement. Cela produit les meilleurs résultats, mais demande plus de travail de votre part, l'utilisateur.

(Un moyen simple de le faire, soit dit en passant, est de créer un nouveau dossier pour les messages 'supprimés', et au lieu de les supprimer des autres dossiers, de les y déplacer simplement. Ensuite, conservez tout le spam dans un dossier séparé et ne le supprimez jamais. Tant que vous vous souvenez de déplacer les courriers mal classifiés dans le bon ensemble de dossiers, il est assez facile de rester à jour.)

2. Apprentissage non supervisé à partir de la classification bayésienne
Une autre façon d'apprendre est de renvoyer les résultats du classificateur bayésien à l'apprentissage, afin qu'il renforce ses propres décisions. Ceci n'est sûr que si vous le réentraînez ensuite en fonction des erreurs que vous découvrez.

SpamAssassin ne prend pas en charge cette méthode, en raison de résultats expérimentaux qui indiquent fortement qu'elle ne fonctionne pas bien, et puisque Bayes n'est qu'une partie du score résultant présenté à l'utilisateur (tandis que Bayes peut avoir pris la mauvaise décision concernant un courrier, il peut avoir été remplacé par un autre système).

3. Apprentissage non supervisé à partir des règles SpamAssassin
Aussi appelé 'auto-learning' dans SpamAssassin. Basé sur l'analyse statistique des taux de réussite de SpamAssassin, nous pouvons automatiquement former la base de données bayésienne avec un certain degré de confiance que nos données d'entraînement sont exactes.

Elle doit être complétée par un apprentissage supervisé supplémentaire, si possible.

C'est le défaut, mais cela peut être désactivé en définissant le paramètre de configuration de SpamAssassin "bayes_auto_learn" sur 0.

4. Formation basée sur les erreurs
Cela signifie s'entraîner sur un petit nombre de courriers, puis seulement s'entraîner sur les messages que SpamAssassin classe incorrectement. Cela fonctionne, mais il faut plus de temps pour y parvenir qu'une session de formation complète.

FICHIERS

sa-learn et les autres parties de l'apprenant bayésien de SpamAssassin utilisent un ensemble de fichiers de base de données persistants pour stocker les jetons appris, comme suit.

bayes_toks
La base de données des jetons, contenant les jetons appris, leur nombre d'occurrences dans le ham et le spam, et l'horodatage de la dernière fois que le jeton a été vu dans un message.

Cette base de données contient également des jetons 'magiques', comme suit : le numéro de version de la base de données, le nombre de messages ham et spam appris, le nombre de jetons dans la base de données, et les horodatages de : la dernière synchronisation du journal, la dernière exécution de l'expiration, le dernier compte de réduction des jetons par expiration, le dernier delta d'horodatage de l'expiration, l'horodatage du jeton le plus ancien dans la base de données, et l'horodatage du jeton le plus récent dans la base de données.

Il s'agit d'un fichier de base de données, utilisant "DB_File". Le 'numéro de version' de la base de données est 0 pour les bases de données à partir de 2.5x, 1 pour les bases de données à partir de certaines versions de développement 2.6x, 2 pour 2.6x, et 3 pour les versions 3.0 et ultérieures.

bayes_seen
Une carte de Message-Id et certaines données des en-têtes et du corps indiquant comment ce message a été appris. Ceci est utilisé afin que SpamAssassin puisse éviter de réapprendre un message qu'il a déjà vu, et afin qu'il puisse annuler la formation si vous décidez plus tard que ce message a été mal appris.

Il s'agit d'un fichier de base de données, utilisant "DB_File".

bayes_journal
Pendant que SpamAssassin analyse les courriers, il doit suivre les jetons qu'il utilise dans ses calculs. Pour éviter la contention de chaque processus SpamAssassin tentant d'obtenir un accès en écriture à la base de données Bayes, les horodatages des jetons sont écrits dans un fichier 'journal' qui sera plus tard (soit automatiquement, soit via "sa-learn --sync") utilisé pour synchroniser la base de données Bayes.

De plus, grâce à l'utilisation de "bayes_learn_to_journal", ou lors de l'utilisation de l'option "--no-sync" avec sa-learn, les données d'apprentissage réelles seront placées dans le journal pour une synchronisation ultérieure. Ceci est généralement utile pour les sites à fort trafic afin d'éviter la même contention que celle décrite ci-dessus.

EXPIRATION

Puisque SpamAssassin peut apprendre automatiquement les messages, les fichiers de la base de données Bayes pourraient augmenter indéfiniment jusqu'à remplir votre disque. Pour contrôler cela, SpamAssassin effectue la synchronisation du journal et l'expiration de la base de données Bayes périodiquement lorsque certains critères (listés ci-dessous) sont remplis.

SpamAssassin peut synchroniser le journal et expirer les jetons de la base de données soit manuellement, soit de manière opportuniste. Une synchronisation du journal est due si --sync est passé à sa-learn (manuel), ou si ce qui suit est vrai (opportuniste) :

- bayes_journal_max_size n'est pas égal à 0 (signifie ne pas synchroniser)
- le fichier journal existe

et soit :

- la taille du fichier journal est supérieure à bayes_journal_max_size

ou

- une synchronisation du journal s'est produite précédemment, et au moins 1 jour s'est écoulé depuis cette synchronisation

L'expiration est due si --force-expire est passé à sa-learn (manuel), ou si toutes les conditions suivantes sont remplies (opportuniste) :

- la dernière expiration a été tentée il y a au moins 12 heures
- bayes_auto_expire n'est pas égal à 0
- le nombre de jetons dans la base de données est > 100 000
- le nombre de jetons dans la base de données est > bayes_expiry_max_db_size
- il y a une différence d'au moins 12 heures entre les atimes des jetons les plus anciens et les plus récents

LOGIQUE D'EXPIRATION

Si la méthode manuelle ou opportuniste déclenche une exécution d'expiration, voici la logique utilisée :

- déterminer combien de jetons conserver. prendre le plus grand entre bayes_expiry_max_db_size * 75% ou 100 000 jetons. par conséquent, la réduction cible est le nombre de jetons - le nombre de jetons à conserver.
- si le nombre de réduction est < 1000 jetons, abandonner (pas la peine de faire l'effort).
- si une expiration a déjà été effectuée, estimer le nouveau delta atime basé sur l'ancien delta atime. (nouveau_delta_atime = ancien_delta_atime * ancien_nombre_de_réduction / cible)
- si aucune expiration n'a été effectuée auparavant, ou si la dernière expiration semble "étrange", effectuer une passe d'estimation. La définition de "étrange" est :
- dernière expiration il y a plus de 30 jours
- dernier delta atime était < 12 heures
- dernier nombre de réduction était < 1000 jetons
- nouveau delta atime estimé delta est < 12 heures
- la différence entre le dernier nombre de réductions et le nombre de réductions cible est > 50%

LOGIQUE DE PASSAGE DE L'ESTIMATION

Parcourez chacun des jetons de la base de données. En commençant à 12 heures, calculez si le jeton serait expiré (en fonction de la différence entre l'atime du jeton et l'atime du jeton le plus récent de la base de données) et conservez le compte. Travaillez à partir de 12 heures de manière exponentielle par puissances de 2. C'est-à-dire : 12 heures * 1, 12 heures * 2, 12 heures * 4, 12 heures * 8, et ainsi de suite, jusqu'à 12 heures * 512 (6144 heures, soit 256 jours).

Plus le delta est grand, plus le nombre de jetons expirés est faible. Inversement, le nombre de jetons augmente lorsque le delta diminue. Ainsi, en commençant par le delta atime le plus grand, déterminez quel delta expirera le plus de jetons sans dépasser le nombre d'expirations cible. Utilisez ceci pour choisir le delta atime à utiliser, sauf si l'une des conditions suivantes se produit :

- le plus grand atime (le plus petit nombre de réductions) expirerait trop de jetons. cela signifie que les jetons appris sont principalement anciens et qu'il faut apprendre de nouveaux jetons avant qu'une expiration ne puisse avoir lieu.
- tous les choix d'atime entraînent la suppression de 0 jeton. cela signifie que tous les jetons sont plus récents que 12 heures et qu'il faut apprendre de nouveaux jetons avant qu'une expiration ne puisse avoir lieu.
- le nombre de jetons qui seraient supprimés est < 1000. le bénéfice ne vaut pas l'effort. plus de jetons doivent être appris.

Si l'exécution de l'expiration dépasse ce point, elle se poursuivra jusqu'à la fin. Une nouvelle base de données est créée car la majorité des bibliothèques de bases de données ne réduisent pas la taille du fichier de base de données lorsque des jetons sont supprimés. Nous effectuons donc l'opération "créer une nouvelle, migrer l'ancienne vers la nouvelle, supprimer l'ancienne, renommer la nouvelle".

PARAMÈTRES DE CONFIGURATION LIÉS À L'EXPIRATION

"bayes_auto_expire" est utilisé pour spécifier si SpamAssassin doit tenter de manière opportuniste d'expirer la base de données Bayes. La valeur par défaut est 1 (oui).
"bayes_expiry_max_db_size" spécifie à la fois le point de comptage des jetons d'auto-expiration, ainsi que le nombre résultant de jetons après expiration, comme décrit ci-dessus. La valeur par défaut est 150 000, ce qui équivaut à peu près à un fichier de base de données de 6 Mo si vous utilisez DB_File.
"bayes_journal_max_size" spécifie la taille maximale du journal Bayes avant qu'il ne soit synchronisé de manière opportuniste. La valeur par défaut est 102400.

INSTALLATION

La commande sa-learn fait partie du module Perl Mail::SpamAssassin. Installez-le comme un module Perl normal, en utilisant "perl -MCPAN -e shell", ou à la main.
