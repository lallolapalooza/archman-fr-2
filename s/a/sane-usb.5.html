sane-usb(5) SANE Scanner Access Now Easy sane-usb(5)

NOM

sane-usb - Conseils de configuration USB pour SANE

DESCRIPTION

Cette page de manuel contient des informations sur la manière d'accéder aux scanners avec une interface USB. Elle se concentre sur deux sujets principaux : la détection du scanner par le noyau du système d'exploitation et son utilisation avec SANE.

Cette page s'applique à la plupart des backends et scanners USB, car ils utilisent l'interface générique sanei_usb. Cependant, il existe une exception : les scanners USB pris en charge par le backend sane-microtek2(5) nécessitent un pilote noyau USB spécial.

DÉMARRAGE RAPIDE

Ceci est une courte section de type HOWTO. Pour les détails complets, lisez les sections suivantes. L'objectif de cette section est de faire détecter le scanner par sane-find-scanner(1).

Exécutez sane-find-scanner(1). S'il liste votre scanner avec les identifiants de vendeur et de produit corrects, vous avez terminé. Voir la section PROBLÈMES SANE pour plus de détails.

sane-find-scanner(1) ne liste pas votre scanner ? Fonctionne-t-il en tant que root ? Si oui, il y a un problème de permission. Voir la section LIBUSB pour plus de détails.

Rien n'est trouvé, même en tant que root ? Vérifiez que votre noyau prend en charge l'USB et que libusb est installé (voir la section LIBUSB).

MÉTHODES D'ACCÈS USB

Pour accéder aux périphériques USB, la bibliothèque USB libusb est utilisée. Il existait auparavant une autre méthode pour accéder aux périphériques USB : le pilote noyau pour scanners. La méthode du pilote noyau pour scanners est obsolète et ne doit plus être utilisée. Elle peut être supprimée de SANE à tout moment. Sous Linux, le pilote noyau pour scanners a été supprimé dans la série de noyaux 2.6.*. Seul l'accès via libusb est documenté dans cette page de manuel.

LIBUSB

SANE ne peut utiliser que libusb 0.1.6 ou plus récent. Il doit être installé au moment de la compilation. Les distributions Linux modernes et autres systèmes d'exploitation fournissent libusb.

Libusb ne peut accéder à votre scanner que s'il n'est pas réclamé par le pilote noyau pour scanners. Si vous souhaitez utiliser libusb, déchargez le pilote noyau (par exemple, rmmod scanner sous Linux) ou désactivez le pilote lors de la compilation d'un nouveau noyau. Pour Linux, votre noyau doit prendre en charge le système de fichiers USB (usbfs). Pour les noyaux plus anciens que 2.4.19, remplacez "usbfs" par "usbdevfs" car le nom a changé. Ce système de fichiers doit être monté. Cela se fait automatiquement au démarrage si /etc/fstab contient une ligne comme celle-ci :

none /proc/bus/usb usbfs defaults 0 0

Les permissions pour les fichiers de périphériques utilisés par libusb doivent être ajustées pour l'accès utilisateur. Sinon, seul root peut utiliser les périphériques SANE. Pour Linux, les périphériques se trouvent dans /proc/bus/usb/ ou dans /dev/bus/usb si vous utilisez udev. Il existe des répertoires nommés par exemple "001" (le nom du bus) contenant des fichiers "001", "002" etc. (les fichiers de périphériques). Les bons fichiers de périphériques peuvent être trouvés en exécutant : scanimage -L: en tant que root. La définition des permissions avec chmod(1) n'est cependant pas permanente. Elles seront réinitialisées après le redémarrage ou le rebranchement du scanner.

Généralement, udev(7) ou pour les distributions plus anciennes, les utilitaires hotplug sont utilisés, qui prennent en charge la définition dynamique des permissions d'accès. SANE est livré avec des scripts udev et hotplug dans les répertoires tools/udev et tools/hotplug. Ils peuvent être utilisés pour définir les permissions, voir /usr/share/doc/sane/README.linux, tools/README et le README dans le répertoire tools/hotplug pour plus de détails.

Pour les BSDs, les fichiers de périphériques utilisés par libusb sont nommés /dev/ugen*. Utilisez chmod(1) pour appliquer les permissions appropriées.

PROBLÈMES SANE

Cette section suppose que votre scanner est détecté par sane-find-scanner(1). Il n'est pas utile de continuer si ce n'est pas le cas. Bien que sane-find-scanner(1) soit capable de détecter n'importe quel scanner USB, la numérisation réelle ne fonctionnera que si le scanner est pris en charge par un backend SANE. Des informations sur le niveau de prise en charge se trouvent sur la page web de SANE (http://www.sane-project.org/) et dans les pages de manuel individuelles des backends.

La plupart des backends peuvent détecter automatiquement les scanners USB à l'aide de lignes de configuration du fichier "usb". Cette méthode permet d'identifier les scanners par les numéros de vendeur et de produit USB. La syntaxe pour spécifier un scanner de cette manière est :

usb VENDOR PRODUCT

où VENDOR est l'identifiant du vendeur USB et PRODUCT est l'identifiant du produit USB du scanner. Les deux identifiants sont des nombres entiers non négatifs au format décimal ou hexadécimal. Les valeurs correctes pour ces champs peuvent être trouvées en exécutant sane-find-scanner(1), en consultant le journal système (par exemple, /var/log/messages) ou sous Linux en exécutant la commande cat /proc/bus/usb/devices. Voici un exemple de ligne de fichier de configuration :

usb 0x055f 0x0006

aurait pour effet que tous les périphériques USB du système avec un identifiant de vendeur de 0x55f et un identifiant de produit de 0x0006 seraient sondés et reconnus par le backend.

Si votre scanner n'est pas détecté automatiquement, il peut être nécessaire de modifier le fichier de configuration du backend approprié avant d'utiliser SANE pour la première fois. Pour une description détaillée du fichier de configuration de chaque backend, veuillez vous référer à la page de manuel du backend concerné (par exemple, sane-mustek_usb(5) pour les scanners USB Mustek).

Ne créez pas de lien symbolique de /dev/scanner vers le périphérique USB car ce lien est utilisé par les backends SCSI. Le scanner peut être confondu s'il reçoit des commandes SCSI.

ENVIRONNEMENT

SANE_DEBUG_SANEI_USB
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour le sous-système d'entrée/sortie USB. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des valeurs plus petites réduisent la verbosité. Des valeurs supérieures à 4 activent le débogage libusb (si disponible). Exemple : export SANE_DEBUG_SANEI_USB=4.
SANE_USB_WORKAROUND
Si votre scanner ne fonctionne pas lorsqu'il est branché sur un port USB3, essayez de définir la variable d'environnement SANE_USB_WORKAROUND à 1. Cela peut contourner des problèmes qui surviennent avec certaines versions du noyau. Exemple : export SANE_USB_WORKAROUND=1.
SANE_XEROX_USB_HALT_WORKAROUND
Si votre ancien scanner Xerox / Samsung / HP (avant 2010) n'est détecté qu'une seule fois et que les utilisations ultérieures nécessitent de rebrancher le câble, essayez de définir la variable d'environnement SANE_XEROX_USB_HALT_WORKAROUND à 1. Cela peut contourner des problèmes qui surviennent avec certains contrôleurs USB. Exemple : export SANE_XEROX_USB_HALT_WORKAROUND=1.
