NOM

samba - Serveur pour fournir des services AD et SMB/CIFS aux clients

SYNTAXE

samba [-D|--daemon] [-F|--foreground] [-i|--interactive] [-M|--model=MODEL] [--maximum-runtime=seconds] [-b|--show-build] [--no-process-group] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] [--configfile=CONFIGFILE] [--option=name=value] [-l|--log-basename=LOGFILEBASE] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPTION

Ce programme fait partie de la suite samba(7).

samba est le démon serveur qui fournit des services Active Directory, de partage de fichiers et d'impression aux clients. Le serveur fournit des espaces de fichiers et des services d'annuaire aux clients en utilisant le protocole SMB (ou CIFS) et d'autres protocoles connexes tels que DCE/RPC, LDAP et Kerberos.

Les clients pris en charge incluent MSCLIENT 3.0 pour DOS, Windows for Workgroups, Windows 95/98/ME, Windows NT, Windows 2000/XP/2003, OS/2, DAVE pour Macintosh, et cifsfs pour Linux.

Une description détaillée des services que le serveur peut fournir se trouve dans la page de manuel du fichier de configuration contrôlant les attributs de ces services (voir smb.conf(5). Cette page de manuel ne décrira pas les services, mais se concentrera sur les aspects administratifs de l'exécution du serveur.

Veuillez noter qu'il existe des implications de sécurité importantes liées à l'exécution de ce serveur, et la page de manuel smb.conf(5) doit être considérée comme une lecture obligatoire avant de procéder à l'installation.

OPTIONS

-D|--daemon

Si spécifié, ce paramètre amène le serveur à fonctionner comme un démon. C'est-à-dire qu'il se détache et s'exécute en arrière-plan, gérant les requêtes sur les ports appropriés. L'exploitation du serveur en tant que démon est la manière recommandée d'exécuter Samba pour les serveurs qui fournissent des services de fichiers et d'impression au-delà d'une utilisation occasionnelle. Ce commutateur est supposé si Samba est exécuté sur la ligne de commande d'un shell.

-F|--foreground

Si spécifié, ce paramètre amène le processus Samba à ne pas se daemoniser, c'est-à-dire à ne pas faire de double fork et à ne pas se dissocier du terminal.

-i|--interactive

Si ce paramètre est spécifié, il amène le serveur à s'exécuter "interactivement", pas en tant que démon, même si le serveur est exécuté sur la ligne de commande d'un shell. La définition de ce paramètre annule le mode démon implicite lorsqu'il est exécuté depuis la ligne de commande. Samba enregistre également sur la sortie standard, comme si le paramètre -S avait été donné.

-M|--model

Ce paramètre peut être utilisé pour spécifier le "modèle de processus" que Samba doit utiliser. Ceci détermine comment les clients concurrents sont gérés. Les modèles de processus disponibles incluent :
•single

Tous les services Samba s'exécutent dans un seul processus. Ceci n'est pas recommandé pour les configurations de production.

•standard

Un processus est créé pour chaque service Samba, et pour les services qui le prennent en charge (actuellement seulement LDAP et NETLOGON), un nouveau processus est démarré pour chaque nouvelle connexion client.

Historiquement, c'était la manière "standard" dont Samba se comportait jusqu'à la version 4.10. Notez que ce modèle peut être gourmand en ressources si vous avez un grand nombre de connexions clients.

•prefork

Par défaut. Un processus est démarré pour chaque service Samba, et un nombre fixe de processus de travail sont démarrés pour les services qui le prennent en charge (actuellement LDAP, NETLOGON et KDC). Les connexions clients sont ensuite partagées entre les processus de travail. Les requêtes pour les services ne prenant pas en charge le préfork sont gérées par un seul processus pour ce service.

Le nombre de processus de travail préfork démarrés est contrôlé par le paramètre prefork children de smb.conf(5), qui par défaut est de 4.

--maximum-runtime=seconds

Définit la durée maximale d'exécution du processus serveur jusqu'à une auto-terminaison en secondes.

-b|--show-build

Affiche des informations sur la façon dont Samba a été compilé.

-d|--debuglevel=level

level est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 0.

Plus cette valeur est élevée, plus les informations détaillées seront enregistrées dans les fichiers journaux sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors du dépannage d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent une ÉNORME quantité de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirige la sortie de débogage vers STDOUT. Par défaut, les démons serveur enregistrent dans un fichier journal.

--configfile=CONFIGFILE

Le fichier spécifié contient les détails de configuration requis par le serveur. Les informations de ce fichier incluent des détails spécifiques au serveur tels que le fichier printcap à utiliser, ainsi que des descriptions de tous les services que le serveur doit fournir. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé au moment de la compilation.

--option=<name>=<value>

Définit l'option smb.conf(5) "<name>" à la valeur "<value>" depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues depuis le fichier de configuration. Si un nom ou une valeur contient un espace, entourez tout --option=name=value de guillemets.

-l|--log-basename=logdirectory

Nom du répertoire de base pour les fichiers journaux/de débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-?|--help

Affiche un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

FICHIERS

/etc/rc

ou quel que soit le script d'initialisation utilisé par votre système.

Si le serveur est exécuté comme un démon au démarrage, ce fichier devra contenir une séquence de démarrage appropriée pour le serveur.

/etc/services

Si le serveur est exécuté via le méta-démon inetd, ce fichier doit contenir une correspondance entre le nom du service (par exemple, netbios-ssn) et le port du service (par exemple, 139) et le type de protocole (par exemple, tcp).

/usr/local/samba/lib/smb.conf

C'est l'emplacement par défaut du fichier de configuration du serveur smb.conf(5). D'autres endroits courants où les systèmes installent ce fichier sont /usr/samba/lib/smb.conf et /etc/samba/smb.conf.

Ce fichier décrit tous les services que le serveur doit rendre disponibles aux clients. Voir smb.conf(5) pour plus d'informations.

DIAGNOSTICS

La plupart des diagnostics émis par le serveur sont enregistrés dans un fichier journal spécifié. Le nom du fichier journal est spécifié au moment de la compilation, mais peut être remplacé sur la ligne de commande.

Le nombre et la nature des diagnostics disponibles dépendent du niveau de débogage utilisé par le serveur. En cas de problèmes, définissez le niveau de débogage à 3 et parcourez les fichiers journaux.

La plupart des messages sont raisonnablement explicites. Malheureusement, au moment de la création de cette page de manuel, il y a trop de diagnostics disponibles dans le code source pour justifier la description de chacun d'eux. À ce stade, votre meilleure option reste de rechercher dans le code source et d'inspecter les conditions qui ont conduit aux diagnostics que vous observez.
