NOM

sa-update - automatise les mises à jour des règles SpamAssassin

SYNTAXE

sa-update [options]

Options :

--channel canal         Récupérer les mises à jour de ce canal
                        Utiliser plusieurs fois pour plusieurs canaux
--channelfile fichier      Récupérer les mises à jour depuis les canaux dans ce fichier
--checkonly             Vérifier seulement la disponibilité des mises à jour, ne pas installer
--install fichier         Installer les mises à jour directement depuis ce fichier. La signature
                        sera vérifiée à l'aide de "fichier.asc", ou "fichier.sha512"
                        ou "fichier.sha256".
--allowplugins          Autoriser les mises à jour à charger du code de plugin (DANGEREUX)
--gpgkey clé            Faire confiance à l'ID de clé pour signer les versions
                        Utiliser plusieurs fois pour plusieurs clés
--gpgkeyfile fichier      Faire confiance aux ID de clés dans le fichier pour signer les versions
--gpghomedir chemin       Stocker le trousseau GPG dans ce répertoire
--gpg et --nogpg       Utiliser (ou ne pas utiliser) GPG pour vérifier les mises à jour
                        (--gpg est supposé par l'utilisation des options
                        --gpgkey et --gpgkeyfile ci-dessus)
--import fichier        Importer les clés GPG depuis le fichier dans le trousseau de sa-update.
                        Utiliser plusieurs fois pour plusieurs fichiers
--updatedir chemin        Répertoire où placer les mises à jour, par défaut le
                        répertoire des règles du site SpamAssassin
                        (défaut: /var/lib/spamassassin/4.000001)
--refreshmirrors        Forcer la mise à jour du fichier MIRRORED.BY
--forcemirror url       Utiliser un miroir spécifique au lieu de télécharger depuis
                        les miroirs officiels
--httputil util         Forcer l'outil de téléchargement utilisé. Par défaut, le premier trouvé
                        parmi les suivants est utilisé : curl, wget, fetch, lwp
--score-multiplier x.x  Ajuster tous les scores du canal de mise à jour, multiplier
                        par la valeur donnée (entier ou flottant).
--score-limit x.x       Ajuster tous les scores du canal de mise à jour, limiter
                        à la valeur donnée (entier ou flottant). La limitation
                        se fait après l'éventuelle opération de multiplication.
-D, --debug [zone=n,...]  Afficher les messages de débogage
-v, --verbose           Être verbeux, comme afficher les noms des canaux mis à jour ;
                        pour plus de verbosité, spécifier plusieurs fois
-V, --version           Afficher la version
-h, --help              Afficher le message d'aide
-4                      Forcer l'utilisation du protocole inet (IPv4), pas inet6
-6                      Forcer l'utilisation du protocole inet6 (IPv6), pas inet

DESCRIPTION

sa-update automatise le processus de téléchargement et d'installation de nouvelles règles et configurations, basées sur des canaux. Le canal par défaut est updates.spamassassin.org, qui contient des règles mises à jour depuis la version précédente.

NOTE : les noms de canaux sont des noms de domaine, mais n'ont TYPIQUEMENT AUCUN enregistrement DNS autre que (peut-être) des enregistrements NS. Il existe une arborescence d'enregistrements sous ce nom qui désigne la version de SpamAssassin et résout ce nom vers le numéro de version des règles les plus récentes, par exemple pour trouver le numéro de version de la dernière mise à jour pour SpamAssassin v4.0.0 :

$ host -t txt 0.0.4.updates.spamassassin.org 
0.0.4.updates.spamassassin.org is an alias for 3.3.3.updates.spamassassin.org.
3.3.3.updates.spamassassin.org descriptive text "1907730"

Cela montre également que l'ensemble de règles actuel est supposé être rétrocompatible jusqu'à la v3.3.3.

Les archives de mise à jour sont vérifiées par défaut à l'aide de signatures GPG. Si GPG est désactivé (non recommandé), l'intégrité du fichier est vérifiée avec des sommes de contrôle SHA512 ou SHA256.

Notez que "sa-update" ne redémarrera pas "spamd" ou ne provoquera pas autrement le rechargement de l'ensemble de règles mis à jour par un analyseur. Au lieu de cela, "sa-update" est généralement utilisé dans un contexte comme le suivant :

sa-update && /etc/init.d/spamassassin reload

Cela fonctionne car "sa-update" ne renvoie un code de sortie de 0 que s'il a téléchargé et installé avec succès un ensemble de règles mis à jour.

Le programme sa-update utilise l'umask du système d'exploitation sous-jacent pour les fichiers de règles mis à jour qu'il installe. Vous pourriez souhaiter exécuter sa-update à partir d'un script qui définit l'umask avant d'appeler sa-update. Par exemple :

#!/bin/sh
umask 022
sa-update

OPTIONS

--channel
sa-update peut mettre à jour plusieurs canaux en même temps. Par défaut, il n'accédera qu'à "updates.spamassassin.org", mais d'autres canaux peuvent être spécifiés via cette option. S'il y a plusieurs canaux supplémentaires, utilisez l'option plusieurs fois, une fois par canal. Par exemple : 
sa-update --channel foo.example.com --channel bar.example.com
--channelfile
Similaire à l'option --channel, sauf que les canaux supplémentaires sont spécifiés dans un fichier au lieu de la ligne de commande. Ceci est utile lorsqu'il y a beaucoup de canaux supplémentaires.
--checkonly
Vérifier seulement si une mise à jour est disponible, ne pas la télécharger ni l'installer réellement. Le code de sortie sera 0 ou 1 comme décrit ci-dessous.
--install
Installer les mises à jour "hors ligne", à partir du fichier tar.gz nommé, au lieu d'effectuer des recherches DNS et des appels HTTP.

Les fichiers nommés fichier.asc, fichier.sha512, ou fichier.sha256 seront utilisés pour la signature GPG, et les sommes de contrôle SHA256 et SHA512, respectivement. Le nom de fichier fourni doit contenir un numéro de version d'au moins 3 chiffres, qui sera utilisé comme numéro de version de mise à jour du canal.

Plusieurs options --channel ne peuvent pas être utilisées avec --install. Pour installer plusieurs canaux depuis des archives, exécutez "sa-update" plusieurs fois avec des options --channel et --install différentes, par exemple :

sa-update --channel foo.example.com --install foo-34958.tgz
sa-update --channel bar.example.com --install bar-938455.tgz
--allowplugins
Autoriser les mises à jour téléchargées à activer les plugins. Par défaut, les plugins ne sont pas activés ; toutes les lignes "loadplugin" ou "tryplugin" seront commentées dans les fichiers de règles de mise à jour téléchargés.

Vous ne devriez jamais activer ceci pour des canaux de mise à jour tiers, car les plugins peuvent exécuter du code non restreint sur votre système, potentiellement même en tant que root ! Cela inclut les mises à jour officielles de SpamAssassin, qui n'ont pas besoin d'inclure de code exécutable.

Utilisez l'option --reallyallowplugins pour contourner les avertissements et la faire fonctionner.

--gpg, --nogpg
sa-update vérifie par défaut les archives de mise à jour à l'aide de la signature GPG.

Si vous souhaitez ignorer la vérification GPG (très dangereux), vous pouvez utiliser l'option --nogpg pour désactiver son utilisation. L'utilisation des options relatives à gpgkey ci-dessous outrepassera --nogpg et maintiendra la vérification GPG activée.

Si GPG est désactivé, seules les sommes de contrôle SHA512 ou SHA256 sont utilisées pour vérifier si l'archive téléchargée a été corrompue ou non, mais cela n'offre aucune forme de sécurité quant à la légitimité de l'archive téléchargée (c'est-à-dire : non modifiée par des malveillants).

Note : Seul GnuPG est pris en charge (c'est-à-dire : aucun autre logiciel PGP).

--gpgkey
sa-update a le concept de clés GPG "fiables pour la publication". Lorsqu'une archive est téléchargée et que la signature est vérifiée, sa-update exige que la signature provienne de l'une de ces clés "fiables pour la publication", sinon la vérification échoue. Cela empêche des tiers de manipuler les fichiers sur un miroir, par exemple, et de les signer avec leur propre clé.

Par défaut, sa-update fait confiance aux ID de clés "24F434CE" et "5244EC45", qui sont la clé de publication standard de SpamAssassin et sa sous-clé. Utilisez cette option pour faire confiance à des clés supplémentaires. Voir l'option --import pour savoir comment ajouter des clés au trousseau de sa-update. Pour que sa-update utilise une clé, celle-ci doit être dans le trousseau de sa-update et être considérée comme fiable.

Pour plusieurs clés, utilisez l'option plusieurs fois. Par exemple :

sa-update --gpgkey E580B363 --gpgkey 298BC7D0

Note : l'utilisation de cette option active automatiquement la vérification GPG.

sa-update(1p) — SpamAssassin documentation

NAME

sa-update — mise à jour des règles et des chaînes de SpamAssassin

SYNOPSIS

sa-update [-D [zone,...]] [-h | --help] [-V | --version] [--gpgkey clé,...] [--gpgkeyfile fichier] [--gpghomedir répertoire] [--import fichier] [--refreshmirrors] [--forcemirror hôte] [--updatedir répertoire] [--checkonly] [--allowempty] [--autofix] [--package-v2] [--debug-on-error] [--script script]

DESCRIPTION

La commande sa-update est un utilitaire qui met à jour les règles et les chaînes de SpamAssassin depuis un dépôt centralisé ou depuis d'autres sources tierces. Elle est particulièrement utile pour maintenir les règles de filtrage de spam à jour sans avoir à recompiler SpamAssassin.

Elle vérifie la disponibilité de nouvelles règles, télécharge les fichiers nécessaires et les installe dans le répertoire de règles de SpamAssassin.

OPTIONS

--allowempty
Permet la mise à jour même si aucun nouveau fichier de règles n'est disponible. Utile si des chaînes vides sont installées.
--autofix
Tente de corriger automatiquement certains problèmes mineurs lors de la mise à jour, comme les autorisations de fichiers incorrectes.
--checkonly
Vérifie la disponibilité des mises à jour sans les télécharger ni les installer.
-D [zone,...], --debug [zone,...]
Produit une sortie de débogage. Si aucune zone n'est spécifiée, toutes les informations de débogage sont imprimées. La sortie diagnostique peut également être activée pour chaque zone individuellement ; zone est la zone du code à instrumenter. Par exemple, pour produire une sortie diagnostique sur les canaux, gpg et http, utilisez : 
sa-update -D channel,gpg,http

Pour plus d'informations sur les zones (également appelées canaux) disponibles, veuillez consulter la documentation sur https://wiki.apache.org/spamassassin/DebugChannels.

--debug-on-error
Active le débogage uniquement en cas d'erreur.
--forcemirror
Force le téléchargement depuis un hôte spécifique au lieu de s'appuyer sur les miroirs listés dans MIRRORED.BY.
--gpgkey clé,...
Spécifie une ou plusieurs clés GPG publiques à utiliser pour vérifier l'authenticité des mises à jour. Les clés doivent être fournies sous forme de chaînes hexadécimales. Vous pouvez spécifier plusieurs clés en les séparant par des virgules.
--gpgkeyfile
Similaire à l'option --gpgkey, sauf que les clés supplémentaires sont spécifiées dans un fichier au lieu de la ligne de commande. C'est extrêmement utile lorsqu'il y a beaucoup de clés supplémentaires que vous souhaitez approuver.
--gpghomedir
Spécifie un chemin de répertoire à utiliser comme zone de stockage pour le trousseau GPG de "sa-update". Par défaut, il s'agit de 
/etc/mail/spamassassin/sa-update-keys
-h, --help
Affiche le message d'aide et quitte.
--import
Utilisé pour importer une ou plusieurs clés GPG à partir d'un fichier dans le trousseau sa-update, situé dans le répertoire spécifié par --gpghomedir. Avant d'utiliser des chaînes provenant de sources tierces, vous devez utiliser cette option pour importer la ou les clés GPG utilisées par ces chaînes. Vous devez toujours utiliser les options --gpgkey ou --gpgkeyfile ci-dessus pour que sa-update fasse confiance aux clés importées.

Pour importer plusieurs clés, utilisez l'option plusieurs fois. Par exemple :

sa-update --import channel1-GPG.KEY --import channel2-GPG.KEY

Remarque : l'utilisation de cette option active automatiquement la vérification GPG.

--package-v2
Utilise le format de paquet v2 pour les mises à jour de règles.
--refreshmirrors
Force la mise à jour de la liste des miroirs sa-update pour chaque chaîne, stockée dans le fichier MIRRORED.BY. Par défaut, le fichier MIRRORED.BY est mis en cache pendant 7 jours maximum après chaque téléchargement.
--script script
Exécute un script externe après chaque mise à jour réussie.
--updatedir
Par défaut, "sa-update" utilise le répertoire de mise à jour des règles système : 
/var/lib/spamassassin/4.000001

Si les mises à jour doivent être stockées dans un autre emplacement, spécifiez-le ici.

Notez que l'utilisation de cette option n'est pas recommandée ; si vous utilisez simplement sa-update pour télécharger des ensembles de règles mis à jour pour un scanner, et que sa-update place les mises à jour dans le mauvais répertoire, vous devez probablement reconstruire SpamAssassin avec des arguments "Makefile.PL" différents, au lieu de remplacer le comportement d'exécution de sa-update.

-V, --version
Affiche la version de sa-update et quitte.

CODES DE SORTIE

En l'absence d'une option --checkonly, un code de sortie de 0 signifie : une mise à jour était disponible, et a été téléchargée et installée avec succès. Si --checkonly a été spécifié, un code de sortie de 0 signifie : une mise à jour était disponible.

Un code de sortie de 1 signifie qu'aucune nouvelle mise à jour n'était disponible.

Un code de sortie de 2 signifie qu'au moins une mise à jour est disponible mais que la vérification linguistique des fichiers site pre a échoué. Les fichiers site pre doivent passer une vérification linguistique avant toute tentative de mise à jour.

Un code de sortie de 3 signifie qu'au moins une mise à jour a réussi tandis que d'autres chaînes ont échoué. Si vous utilisez sa-compile, vous devriez continuer avec celui-ci.

Un code de sortie de 4 ou plus élevé indique que des erreurs se sont produites lors de la tentative de téléchargement et d'extraction des mises à jour, et qu'aucune chaîne n'a été mise à jour.
