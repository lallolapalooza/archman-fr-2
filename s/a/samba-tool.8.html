SAMBA-TOOL(8) Outils d'administration système SAMBA-TOOL(8)

NOM

samba-tool - Outil principal d'administration de Samba.

SYNTAXE

samba-tool [-h] [-W mongroupe_de_travail] [-U utilisateur] [-d niveau_de_débogage] [--v]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

OPTIONS

Samba-tool se compose de nombreuses sous-commandes, chacune ayant son propre ensemble d'options. Les options listées dans cette section sont communes à plusieurs sous-commandes.

-h|--help

Affiche un message d'aide et quitte.

-r|--realm=RÉALME

Définit le realm pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui devrait contenir un descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés !

Bien que Samba tente de supprimer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

-U|--user=[DOMAINE\]NOM_UTILISATEUR[%MOT_DE_PASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOT_DE_PASSE n'est pas spécifié, l'utilisateur sera invité à le saisir. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir un mot de passe) et si l'une ou l'autre existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'informations d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'informations d'identification contenant le mot de passe en clair du nom d'utilisateur et du mot de passe. Cette option est principalement destinée aux scripts où l'administrateur ne souhaite pas transmettre les informations d'identification sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés. Voir le paramètre -A pour plus de détails.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

-W|--workgroup=GROUPE_DE_TRAVAIL

Définit le domaine SMB du nom d'utilisateur. Cela remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est le même que le nom NetBIOS du serveur, cela amène le client à se connecter en utilisant le SAM local du serveur (par opposition au SAM du domaine).

Notez que la spécification de ce paramètre ici remplacera le paramètre workgroup dans le fichier /etc/samba/smb.conf.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lorsque l'on accède à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié sur la ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera ignoré silencieusement et aucun mot de passe ne sera utilisé.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils clients Samba essaieront d'authentifier en utilisant Kerberos. Pour l'authentification Kerberos, vous devriez utiliser des noms DNS plutôt que des adresses IP lors de la connexion à un service. Par défaut, les outils clients Samba essaieront d'utiliser le cache d'informations d'identification Kerberos par défaut (ccache). Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont de saisir un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'informations d'identification Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'informations d'identification pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

-A|--authentication-file=nom_fichier

Cette option permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est le suivant : 
username = <valeur>
password = <valeur>
domain   = <valeur>

Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs non désirés !

-H URL, --URL=URL

URL LDB pour la base de données ou le serveur cible.

L'URL peut être un chemin de fichier simple, ou utiliser l'un des schémas listés ici. Si un chemin simple est utilisé, il est traité comme si 'tdb://' était utilisé.

tdb://CHEMIN

CHEMIN est l'emplacement d'une base de données TDB.

mdb://CHEMIN

CHEMIN est l'emplacement d'une base de données LMDB.

ldb://CHEMIN

CHEMIN est l'emplacement d'une base de données LDB, au format LMDB ou TDB. Les formats seront essayés l'un après l'autre jusqu'à ce qu'un réussisse ou que tous échouent. Il est sûr d'utiliser ceci si vous ne connaissez pas le format du fichier.

ldap://HOTE, ldaps://HOTE

Le backend LDB est le serveur ldap nommé. ldaps:// enveloppe la connexion dans TLS.

ldapi://SOCKET

Le serveur backend est un serveur ldap local utilisant un socket de domaine unix.

--color=always|never|auto

utilise la couleur si disponible (défaut : auto)

--ipaddress=ADRESSE_IP

Adresse IP du serveur

-s FICHIER, --configfile=FICHIER

Utilise ce fichier de configuration smb.conf.

--color=always|never|auto

Indique si samba-tool doit utiliser des codes de couleur ANSI dans sa sortie. Si 'auto' (la valeur par défaut), samba-tool utilisera la couleur lorsque sa sortie est dirigée vers un terminal, sauf si la variable d'environnement NO_COLOR est définie et non vide.

Les valeurs 'yes' et 'force' sont acceptées comme synonymes de 'always' ; 'no' et 'none' pour 'never' ; et 'tty' et 'if-tty' pour 'auto'.

Notez que demander de la couleur ne signifie pas que samba-tool sera forcément très coloré. De nombreuses commandes sont très monochromes, en particulier en cas de succès.

-V, --version

Affiche le numéro de version et quitte.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus le niveau de détail sera enregistré dans les fichiers journaux concernant les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation, et ne devraient être utilisés que lors de la résolution d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level dans le fichier /etc/samba/smb.conf.

--debug-stdout

Redirige la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

Cette commande ajoute des attributs Unix à un compte utilisateur dans le domaine Active Directory.

Le nom d'utilisateur spécifié dans la commande est le sAMAccountName.

Vous devez fournir un uid unique.

Les attributs Unix (RFC2307) seront ajoutés au compte utilisateur.

Si vous fournissez un id de groupe avec '--gid-number', celui-ci sera utilisé pour l'attribut Unix 'gidNumber' de l'utilisateur.

Si '--gid-number' n'est pas fourni, le gidNumber Unix de l'utilisateur sera défini sur celui trouvé dans 'Domain Users', ce qui signifie que Domain Users doit avoir un attribut gidNumber.

Si '--unix-home' n'est pas fourni, le répertoire personnel Unix de l'utilisateur sera défini sur /home/DOMAIN/username.

Si '--login-shell' n'est pas fourni, le shell de connexion Unix de l'utilisateur sera défini sur '/bin/sh'.

Si '--gecos' n'est pas fourni, le champ GECOS Unix de l'utilisateur sera défini sur l'attribut 'CN' de l'utilisateur.

Ajoutez 'idmap_ldb:use rfc2307 = Yes' à smb.conf sur les DC pour utiliser ces attributs pour le mappage UID/GID.

La commande peut être exécutée par l'utilisateur root ou un autre utilisateur autorisé. L'option -H ou --URL= peut être utilisée pour exécuter la commande sur un serveur distant.

Exemple 1 :

samba-tool user addunixattrs User1 10001

L'exemple 1 montre comment ajouter des attributs RFC2307 à un compte utilisateur activé dans le domaine, Domain Users sera défini comme le gidNumber de l'utilisateur.

L'ID Unix de l'utilisateur sera défini sur '10001', à condition que cet ID ne soit pas déjà utilisé.

L'exemple 2 montre comment ajouter des attributs RFC2307 à un compte utilisateur activé dans le domaine.

L'ID Unix de l'utilisateur sera défini sur '10002', à condition que cet ID ne soit pas déjà utilisé.

L'attribut gidNumber de l'utilisateur sera défini sur '10001'.

Le répertoire personnel Unix de l'utilisateur sera défini sur '/home/user2'.

Exemple 3 :

L'exemple 3 montre comment ajouter des attributs RFC2307 à un compte utilisateur activé dans le domaine.

L'ID Unix de l'utilisateur sera défini sur '10003', à condition que cet ID ne soit pas déjà utilisé. L'attribut gidNumber de l'utilisateur sera défini sur '10001'.
