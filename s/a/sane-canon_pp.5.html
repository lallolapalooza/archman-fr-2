NOM

sane-canon_pp - Backend SANE pour scanners plats Canon CanoScan à port parallèle

DESCRIPTION

La bibliothèque sane-canon_pp implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners plats Canon CanoScan suivants :

CanoScan FB320P
CanoScan FB620P
CanoScan FB330P
CanoScan FB630P
CanoScan N340P
CanoScan N640P
CanoScan N640P ex

Aucun scanner USB n'est pris en charge et il n'est pas prévu de les prendre en charge à l'avenir. D'autres projets travaillent à la prise en charge des scanners USB. Voir le fichier PROJECTS pour plus de détails. Les FB310P et FB610P sont des scanners Avision rebadgés qui utilisent un jeu de commandes différent, ils ne seront donc probablement pas pris en charge par ce backend à l'avenir.

IMPORTANT : il s'agit d'un code alpha. Bien que nous ayons fait tous les efforts possibles pour le rendre aussi fiable que possible, il ne fonctionnera pas toujours comme prévu. Les retours d'information sont toujours appréciés. Veuillez envoyer tout rapport de bogue aux mainteneurs tels qu'indiqués sur la page web (listés dans VOIR AUSSI ci-dessous).

NOMS DES PÉRIPHÉRIQUES

Ce backend attend des noms de périphériques de la forme présentée par libieee1284(3). Ces noms dépendent fortement du système d'exploitation et de sa version.

Sur les noyaux Linux 2.4, ce sera de la forme parport0 ou les anciens noyaux (2.2 et avant) peuvent produire des noms comme 0x378 (l'adresse de base de votre port) ou simplement 0 en fonction de la configuration de votre module. Vérifiez le contenu de /proc/parport s'il existe. Si vous ne souhaitez pas spécifier de port par défaut (ou si vous ne connaissez pas son nom), le backend devrait être capable de détecter sur quel port se trouve votre scanner.

CONFIGURATION

Le contenu du fichier canon_pp.conf est une liste d'options que le pilote peut utiliser. Les lignes vides et les lignes commençant par un signe dièse (#) sont ignorées.

Les options prises en charge sont actuellement ieee1284, calibrate, init_mode et force_nibble.

ieee1284 nom-port
Définit quel port utiliser. Le format de nom-port dépend du système d'exploitation, basé sur les noms présentés par libieee1284(3). Veuillez n'avoir qu'une seule de ces lignes, sinon toutes sauf une seront ignorées.
calibrate fichier-cal [nom-port]
Définit le fichier de calibration à utiliser par port. Si vous n'avez qu'un seul port parallèle, l'argument nom-port peut être omis - mais attention car cela causera des problèmes sur les systèmes multi-scanners. Vous pouvez avoir autant de ces lignes que vous le souhaitez, à condition que chacune ait un nom de port unique. Le tilde (`~') est acceptable et sera développé en la valeur de la variable d'environnement HOME.
init_mode <AUTO|FB620P|FB630P> [nom-port]
Définit le mode d'initialisation (réveil) à utiliser par port. Si vous n'avez qu'un seul port parallèle, l'argument nom-port peut être omis - mais attention car cela pourrait causer des problèmes sur les systèmes multi-scanners. Vous pouvez avoir autant de ces lignes que vous le souhaitez, à condition que chacune ait un nom de port unique. Les modes d'initialisation valides sont FB620P (qui pulse 10101010 et 01010101 sur les broches de données), FB630P (qui pulse 11001100 et 00110011 sur les broches de données) et AUTO, qui essaiera d'abord le mode FB630P puis le mode FB620P. Le mode FB620P est également utilisé par le FB320P. Le mode FB630P est utilisé par les FB330P, N340P et N640P.
force_nibble
Force le pilote à utiliser le mode nibble même si le mode ECP est signalé comme fonctionnel par libieee1284(3). Cela contourne le problème rare où le mode ECP est signalé comme fonctionnel par la bibliothèque, puis ne fonctionne pas.

ASTUCES

Appuyez sur le bouton "Calibrer" avant de numériser. Cela améliore considérablement la qualité des numérisations.

Pour activer la détection automatique de votre scanner, décommentez la ligne "canon_pp" de /etc/sane.d/dll.conf.

FICHIERS

/etc/sane.d/canon_pp.conf
Le fichier de configuration du backend (voir également la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-canon_pp.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-canon_pp.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux-points (`:') , sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR sur "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_CANON_PP
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie.

Exemple : export SANE_DEBUG_CANON_PP=4

NOTES

Fonctionnalités disponibles dans l'interface Windows

Luminosité et Contraste
Celles-ci ne sont pas implémentées, et ne le seront probablement jamais. Elles semblent être implémentées entièrement par logiciel. Utilisez GIMP ou un programme similaire si vous avez besoin de ces fonctionnalités.
Mode Désentrelacement
Cela semble, d'après notre première analyse, être juste un suréchantillonnage avec un filtre anti-aliasing. Encore une fois, il semble être implémenté entièrement par logiciel, donc GIMP est votre meilleure option pour le moment.
Tables de Gamma
Ceci est à l'étude, mais pour l'instant seul un profil gamma simple (c'est-à-dire celui renvoyé lors de la calibration) sera chargé.

Problèmes de communication

Le mode ECP dans libieee1284(3) ne fonctionne pas toujours correctement, même avec du matériel récent. Nous pensons qu'il s'agit d'un problème ppdev. Si vous modifiez le fichier de configuration pour inclure force_nibble, le problème disparaîtra, mais vous ne pourrez numériser qu'en mode nibble.

Parfois, le scanner peut être laissé dans un état où notre code ne peut pas le récupérer. Si le backend signale aucun scanner présent, essayez de débrancher l'alimentation et de la rebrancher. Essayez également de débrancher les imprimantes du port de passage.

Le scanner ne répondra pas correctement à nos commandes lorsque vous brancherez l'alimentation. Vous pourriez constater, si vous essayez de numériser très peu de temps après avoir branché l'alimentation, que le backend signalera incorrectement que vous n'avez aucun scanner présent. Pour éviter cela, laissez-lui environ 10 secondes pour se réinitialiser avant de tenter une numérisation.

Lignes répétées

Parfois, à des résolutions élevées (par exemple, 600 dpi), vous remarquerez des lignes qui apparaissent deux fois. Ces lignes correspondent aux points où la tête du scanner s'est arrêtée pendant la numérisation (elle s'arrête chaque fois que le tampon interne de 64 Ko est plein). Il s'agit essentiellement d'un problème mécanique à l'intérieur du scanner, où la tolérance de mouvement pour un événement de démarrage/arrêt est supérieure à 1/600 pouce. Je n'ai jamais essayé le pilote Windows, je ne sais donc pas comment (ou si) il contourne ce problème, mais comme nous ne savons pas comment rembobiner la tête du scanner pour faire ces bits

Numérisations en niveaux de gris

Soyez conscient que le scanner utilise les LED vertes pour lire les numérisations en niveaux de gris, ce qui signifie que les objets de couleur verte apparaîtront plus clairs que la normale, et les objets de couleur rouge et bleue apparaîtront plus sombres que la normale. Pour des numérisations en niveaux de gris de haute précision d'objets colorés, il est préférable de numériser en couleur et de convertir en niveaux de gris dans un logiciel graphique tel que GIMP.

Remarques sur les FB620P/FB320P

Ces modèles ne peuvent pas être réinitialisés de la même manière que les autres. Le pilote Windows ne sait pas non plus comment les réinitialiser - lorsqu'il est laissé avec un scanner incohérent, il commencera à numériser à mi-chemin de la page !

L'interruption est connue pour fonctionner correctement sur les modèles FB*30P, et est connue pour être défectueuse sur les modèles FB*20P. Le FB620P que j'ai testé renvoie simplement des données corrompues après l'interruption d'une numérisation en utilisant la méthode que nous connaissons. L'interruption est capable de laisser le scanner dans un état où il peut être arrêté, mais pas où une autre numérisation peut être effectuée.
