NOM

sa-compile - compile le jeu de règles SpamAssassin en code natif

SYNTAXE

sa-compile [options]

Options :

--list                        Afficher la liste des chaînes de base sur STDOUT
--sudo                        Utiliser 'sudo' pour l'escalade de privilèges
--keep-tmps                   Conserver les fichiers temporaires au lieu de les supprimer
-C chemin, --configpath=chemin, --config-file=chemin
                              Chemin vers le répertoire de configuration standard
-p prefs, --prefspath=fichier, --prefs-file=fichier
                              Définir le fichier de préférences utilisateur
--siteconfigpath=chemin       Chemin pour les configurations du site
                              (défaut : /usr/etc/mail/spamassassin)
--updatedir=chemin            Répertoire où placer les mises à jour
        (défaut : /var/lib/spamassassin/compiled/<perlversion>/4.000001)
--cf='ligne de configuration'            Ligne de configuration supplémentaire
-D, --debug [zone=n,...]      Afficher les messages de débogage
-V, --version                 Afficher la version
-h, --help                    Afficher le message d'aide

DESCRIPTION

sa-compile utilise "re2c" pour compiler les parties du jeu de règles SpamAssassin valables pour tout le système. Aucune partie de user_prefs ou de fichiers inclus depuis user_prefs ne peut être intégrée dans l'ensemble compilé.

Cet ensemble compilé est ensuite utilisé par le plugin "Mail::SpamAssassin::Plugin::Rule2XSBody" pour accélérer le fonctionnement de SpamAssassin, lorsque cela est possible et lorsque ce plugin est chargé.

"re2c" peut faire correspondre des chaînes beaucoup plus rapidement que le code perl, en construisant un automate fini déterministe (DFA) pour faire correspondre de nombreuses chaînes simples en parallèle, et en compilant cela en code objet natif. Cependant, toutes les règles SpamAssassin ne se prêtent pas à cette conversion.

Cela nécessite que "re2c" (voir "https://re2c.org/"), et le compilateur C utilisé pour construire les modules Perl XS, soient installés.

Notez que l'exécution de cette commande et la création d'un jeu de règles compilé n'auront aucun effet sur la vitesse d'analyse de SpamAssassin, à moins que vous ne modifiiez également votre fichier "v320.pre" et que vous vous assuriez que cette ligne est décommentée :

loadplugin Mail::SpamAssassin::Plugin::Rule2XSBody

De plus, "sa-compile" ne redémarrera pas "spamd" ni ne provoquera automatiquement le rechargement des règles maintenant compilées par un analyseur.

OPTIONS

--list
Affiche les chaînes de base extraites sur STDOUT, au lieu de générer le code d'extension C.
--sudo
Utilise sudo(8) pour exécuter du code en tant que 'root' lors de l'écriture de fichiers dans la zone de stockage des règles compilées (qui est "/var/lib/spamassassin/compiled/5.042/4.000001" par défaut).
--quiet
Produit moins de sortie de diagnostic. Les erreurs seront toujours affichées.
--keep-tmps
Conserve les fichiers temporaires après la complétion du script, au lieu de les supprimer.
-C chemin, --configpath=chemin, --config-file=chemin
Utilise le chemin spécifié pour localiser les fichiers de configuration distribués. Ignore les répertoires par défaut (généralement "/usr/share/spamassassin" ou similaire).
--siteconfigpath=chemin
Utilise le chemin spécifié pour localiser les fichiers de configuration spécifiques au site. Ignore les répertoires par défaut (généralement "/etc/mail/spamassassin" ou similaire).
--updatedir
Par défaut, "sa-compile" utilise le répertoire de mise à jour des règles système : 
/var/lib/spamassassin/compiled/5.042/4.000001

Si les mises à jour doivent être stockées à un autre emplacement, spécifiez-le ici.

Notez que l'utilisation de cette option n'est pas recommandée ; si sa-compile place les règles compilées dans le mauvais répertoire, vous devez probablement reconstruire SpamAssassin avec des arguments "Makefile.PL" différents, au lieu de remplacer le comportement d'exécution de sa-compile.

--cf='ligne de configuration'
Ajoute des lignes de configuration supplémentaires directement depuis la ligne de commande, analysées après la lecture des fichiers de configuration. Plusieurs arguments --cf peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte.
-p prefs, --prefspath=prefs, --prefs-file=prefs
Lit les préférences de score utilisateur depuis prefs (généralement "$HOME/.spamassassin/user_prefs").
-D [zone,...], --debug [zone,...]
Produit une sortie de débogage. Si aucune zone n'est listée, toutes les informations de débogage sont affichées. La sortie de diagnostic peut également être activée pour chaque zone individuellement ; zone est la zone du code à instrumenter.

Pour plus d'informations sur les zones (également appelées canaux) disponibles, veuillez consulter la documentation à l'adresse https://wiki.apache.org/spamassassin/DebugChannels.

-h, --help
Affiche le message d'aide et quitte.
-V, --version
Affiche la version de sa-compile et quitte.

sa-compile(1p)

SYNOPSIS

sa-compile [-n] [-q] [-v] [-d dir] [-f fopts] [-p prefix] [-t template] file ...

DESCRIPTION

sa-compile compile des fichiers source SpamAssassin (qui se terminent généralement par .cf) en fichiers binaires optimisés. Ces fichiers binaires peuvent être chargés beaucoup plus rapidement parspamass-milteretspamd. Si vous compilez des fichiers pour un utilisateur spécifique, vous devrez les placer dans le répertoire~/.spamassassin/. La compilation sera effectuée dans~/.spamassassin/. Si vous compilez des fichiers pour tout le système, vous devrez les placer dans/etc/mail/spamassassin/. La compilation sera effectuée dans/etc/mail/spamassassin/.

OPTIONS

-n
N'autorise pas l'utilisation de réseaux.
Sisa-compileest exécuté avec l'option-n, les règles qui dépendent de requêtes réseau (telles queURIBL) ne seront pas compilées dans le fichier binaire.
-q
Mode silencieux.
-v
Mode verbeux.
-d dir
Spécifie le répertoire de sortie pour les fichiers binaires compilés. Par défaut, il s'agit du même répertoire que le fichier source.
-f fopts
Options à passer à/usr/bin/compile.
-p prefix
Spécifie un préfixe pour les fichiers binaires compilés. Ceci est utile lorsque vous essayez de compiler des règles pour plus d'un utilisateur ou pour tout le système.
-t template
Utilise le fichiertemplatecomme modèle pour le fichier binaire compilé. Ceci est utile lorsque vous essayez de compiler des règles pour plus d'un utilisateur ou pour tout le système.
