SAR2PCP(1) Manuel des commandes générales SAR2PCP(1)

NOM

sar2pcp - importer des données sar et créer une archive PCP

SYNTAXE

sar2pcp fichier_entree fichier_sortie

DESCRIPTION

sar2pcp est conçu pour lire un fichier binaire de données du System Activity Reporting (sar) tel que créé par sadc(1) (fichier_entree) et le traduire en une archive Performance Co-Pilot (PCP) dont le nom de base est fichier_sortie.

Cependant, si fichier_entree a le suffixe « .xml », il sera considéré comme déjà au format XML et sar2pcp opérera directement dessus.

L'archive PCP résultante peut être utilisée avec tous les outils clients PCP pour graphiquer des sous-ensembles de données à l'aide de pmchart(1), effectuer une réduction et un rapport de données, filtrer avec le moteur d'inférence PCP pmie(1), etc.

Une série de fichiers physiques sera créée avec le préfixe fichier_sortie. Ce sont fichier_sortie.0 (les données de performance), fichier_sortie.meta (les métadonnées qui décrivent les données de performance) et fichier_sortie.index (un index temporel pour améliorer l'efficacité des opérations de relecture pour l'archive). Si l'un de ces fichiers existe déjà, alors sar2pcp ne les écrasera pas et quittera avec un message d'erreur de la forme

_&__pmLogNewFile : « blah.0 » existe déjà, non écrasé

sar2pcp est un script Perl qui utilise le wrapper Perl PCP::LogImport autour de la bibliothèque PCP libpcp_import, et en tant que tel, pourrait être utilisé comme exemple pour développer de nouveaux outils afin d'importer d'autres types de données de performance et de créer des archives PCP. Un module wrapper Python est également disponible.

NOTES

Depuis la version 12.0.5 de sysstat, sadc(1) a ajouté une fonctionnalité pour écrire directement des fichiers d'archive PCP. Pour produire des fichiers d'archive à partir de sar, exécutez :

$ sadf -l -O pcparchive=NOM_ARCHIVE sar.dat -- -A

AVERTISSEMENTS

Lorsqu'il n'utilise pas l'option d'entrée XML, sar2pcp requiert que fichier_entree ait été créé par une version de sadc(1) depuis http://sebastien.godard.pagesperso-orange.fr/ qui inclut l'utilitaire sadf(1) pour traduire fichier_entree en un flux XML (toute version depuis la 6); sar2pcp exécutera automatiquement sadf(1) et traduira le XML résultant en une archive PCP.

Lors de l'utilisation de fichiers sadc binaires, il est important de s'assurer que le sadf installé est compatible avec la version de sadc qui a initialement généré les fichiers binaires. Supposer simplement qu'une version installée plus récente fonctionnera est malheureusement trop optimiste, et il ne faut pas non plus supposer que les données binaires provenant de différentes plateformes (par exemple, une endianness différente) fonctionneront - ces problèmes sont dus à des limitations dans sadc et sadf, et non dans sar2pcp lui-même.

Heureusement, le message de sadf indiquant qu'une incompatibilité a été détectée est cohérent entre les versions, et est toujours préfixé par

Fichier d'activité système invalide

L'utilisation d'un fichier_entree XML présente l'avantage que la version installée de sadf est complètement contournée. sar2pcp s'engage à transformer tout XML valide produit par l'une des différentes variations de sadf en une archive PCP valide. Toute version de PCP sera capable d'interpréter les fichiers d'archive produits par toute version de sar2pcp, et vous êtes également libre de déplacer l'archive PCP binaire entre différentes plateformes, différents matériels, même différents systèmes d'exploitation - cela fonctionne tout simplement (TM).

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).
