NOM

sane-umax - Backend SANE pour les scanners UMAX

À PROPOS DE CE FICHIER

Ce fichier n'est qu'une brève description du backend sane-umax pour SANE ! Pour des informations détaillées, consultez le fichier sane-umax-doc.html (il est inclus dans le répertoire source de SANE et dans l'aide en ligne de xsane(1)) !

DESCRIPTION

La librairie sane-umax implémente un backend SANE qui fournit un accès à plusieurs scanners UMAX-SCSI et à certains scanners Linotype Hell SCSI. Les scanners parallèles et USB ne sont pas supportés (et ne le seront probablement jamais) !

Je vous suggère de garder une main sur le bouton d'alimentation du scanner lorsque vous tentez les premières numérisations !

CONFIGURATION

Le fichier de configuration pour ce backend se trouve dans /etc/sane.d/umax.conf.

Son contenu est une liste de noms de périphériques qui correspondent aux scanners UMAX et compatibles UMAX. Les lignes vides et les lignes commençant par un signe dièse (#) sont ignorées. Un exemple de fichier de configuration est présenté ci-dessous :

 # ceci est un commentaire
 #
 option scsi-maxqueue 4
 option scsi-buffer-size-min 65536
 option scsi-buffer-size-max 131072
 option scan-lines 40
 option preview-lines 10
 option scsi-maxqueue 2
 option execute-request-sense 0
 option force-preview-bit-rgb 0
 option slow-speed -1
 option care-about-smearing -1
 option calibration-full-ccd -1
 option calibration-width-offset -1
 option calibration-bytes-pixel -1
 option exposure-time-rgb-bind -1
 option invert-shading-data -1
 option lamp-control-available 0
 option gamma-lsb-padded 0
 /dev/sge
 #scsi Vendor Model Type Bus Channel ID LUN
 # Le scanner suivant supporte le contrôle de lampe
 option lamp-control-available 1
 scsi UMAX * Scanner * * * * *
 # le scanner sur /dev/scanner ne supporte pas le contrôle de lampe
 option lamp-control-available 0
 /dev/scanner
execute-request-sense :
valeurs : 0 = désactivé, 1 = activé
par défaut = 0
Si réglé sur 1, umax_do_request_sense() est appelé dans umax_do_calibration(). Cela peut bloquer le système, mais était activé jusqu'à cette version.
scsi-buffer-size-min, scsi-buffer-size-max :
valeurs : 4096-1048576
défaut min = 32768, max = 131072
La valeur minimale est particulièrement importante. Si cette valeur est trop petite, le backend ne pourra pas envoyer de tables gamma au scanner ni effectuer un étalonnage de couleur correct. Cela peut entraîner des effets de couleur étranges. Si la valeur minimale est trop grande, le backend ne pourra pas allouer la taille de tampon SCSI demandée et avortera avec une erreur de mémoire insuffisante. La valeur par défaut est de 32 Ko, pour certains scanners elle devrait être augmentée à 64 Ko.
scan-lines, preview-lines :
valeurs : 1-65535
défaut : scan-lines = 40, preview-lines = 10
définit le nombre maximum de lignes qui sont numérisées dans un seul tampon
force-preview-bit-rgb :
valeurs : 0 = désactivé, 1 = activé
défaut = 0
définit le bit de prévisualisation lors de la numérisation RVB réelle
slow-speed, care-about-smearing :
valeurs : -1 = auto, 0 = désactivé, 1 = activé
défaut = -1
Options dangereuses, nécessaires pour certains scanners.
Ne modifiez pas ces options à moins de savoir vraiment ce que vous faites, sinon vous pourriez détruire votre scanner avec des valeurs invalides.
calibration-full-ccd :
valeurs : -1 = auto, 0 = désactivé, 1 = activé
défaut = -1
effectue l'étalonnage pour chaque pixel du CCD au lieu de l'image sélectionnée
calibration-width-offset :
valeurs : -99999 = auto, > -99999 définit la valeur
ajoute un décalage à la largeur calculée pour l'image/CCD
calibration-bytes-pixel :
valeurs : -1 = désactivé, 0 = non défini, 1 = 1 octet/pixel, 2 = 2 octets/pixel
utilise le nombre d'octets par pixel pour l'étalonnage
exposure-time-rgb-bind :
valeurs : -1 = réglé automatiquement par le pilote - si connu, 0 = désactivé (sélection propre pour le rouge, le vert et le bleu), 1 = activé (mêmes valeurs pour le rouge, le vert et le bleu)
invert-shading-data :
valeurs : -1 = réglé automatiquement par le pilote - si connu, 0 = désactivé, 1 = activé
défaut = -1
inverse les données de masquage avant de les renvoyer au scanner
lamp-control-available :
valeurs : 0 = réglé automatiquement par le pilote - si connu, 1 = disponible
défaut = 0
gamma-lsb-padded :
valeurs : -1 = réglé automatiquement par le pilote - si connu, 0 = les données gamma sont rembourrées MSB, 1 = les données gamma sont rembourrées LSB
défaut = -1
handle-bad-sense-error :
valeurs : 0 = traiter comme périphérique occupé, 1 = traiter comme ok, 2 = traiter comme erreur d'E/S, 3 = ignorer le code d'erreur incorrect - continuer le gestionnaire de détection
défaut = 0
scsi-maxqueue :
valeurs : 1..# (maximum défini à la compilation)
défaut = 2
la plupart des pilotes SCSI permettent la mise en file d'attente de commandes interne avec une profondeur de 2 commandes. Dans la plupart des cas, cela n'améliore rien si vous augmentez cette valeur. Si votre pilote SCSI ne supporte aucune mise en file d'attente de commandes, vous pouvez essayer de définir cette valeur à 1.

Le nom de périphérique spécial doit être un périphérique SCSI générique ou un lien symbolique vers un tel périphérique. Pour savoir à quel périphérique votre scanner est attribué et comment vous devez définir les permissions de ce périphérique, consultez sane-scsi(5).

CONSEILS ADAPTATEUR SCSI

Les adaptateurs ISA-SCSI livrés avec certains scanners UMAX ne sont pas très bien supportés par Linux (je suggère de ne pas les utiliser). Les adaptateurs PCI-SCSI livrés avec certains scanners UMAX ne sont pas du tout supportés (à ma connaissance). Sur d'autres plateformes, ces adaptateurs SCSI ne sont pas supportés. Vous devrez donc généralement acheter un autre adaptateur SCSI supporté par votre plateforme. Consultez les FAQ matérielles et les HOWTOs pertinents pour votre plateforme pour plus d'informations.

Les scanners UMAX bloquent le bus SCSI pendant quelques secondes lors de la numérisation. Il n'est pas nécessaire de connecter le scanner à son propre adaptateur SCSI. Mais si vous avez besoin d'un temps de réponse court pour votre disque dur SCSI (par exemple, si votre ordinateur est un serveur de fichiers) ou d'autres périphériques SCSI, je suggère d'utiliser un propre adaptateur SCSI pour votre scanner UMAX.

Si vous rencontrez des problèmes avec votre scanner UMAX, vérifiez votre chaîne SCSI (longueur du câble, terminaison, ...).

Voir aussi : sane-scsi(5)

FICHIERS

Le fichier de configuration du backend :
/etc/sane.d/umax.conf
La librairie statique implémentant ce backend :
/usr/lib/sane/libsane-umax.a
La librairie partagée implémentant ce backend :
/usr/lib/sane/libsane-umax.so (présent sur les systèmes qui supportent le chargement dynamique)

ENVIRONNEMENT

SANE_DEBUG_UMAX
Si la librairie a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des niveaux inférieurs réduisent la verbosité. Valeurs de SANE_DEBUG_UMAX : 
Numéro  Remarque
 0       imprime les erreurs importantes (imprimées à chaque fois)
 1       imprime les erreurs
 2       imprime la détection
 3       imprime les avertissements
 4       imprime l'interrogation du scanner
 5       imprime les informations
 6       imprime les informations moins importantes
 7       imprime les procédures appelées
 8       imprime les messages du processus lecteur
 10      imprime les routines d'initialisation sane appelées
 11      imprime les procédures sane appelées
