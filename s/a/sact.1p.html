SACT(1P) Manuel du programmeur POSIX SACT(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sact — afficher l'activité d'édition actuelle d'un fichier SCCS (DÉVELOPPEMENT)

SYNTAXE

sact fichier...

DESCRIPTION

L'utilitaire sact informe l'utilisateur de toute modification imminente d'un fichier SCCS nommé en écrivant une liste sur la sortie standard. Cette situation se produit lorsque get -e a été exécuté précédemment sans exécution ultérieure de delta, unget ou sccs unedit.

OPTIONS

Aucune.

OPÉRANDES

Le ou les opérandes suivants sont pris en charge :

fichier
Un chemin d'accès à un fichier SCCS existant ou à un répertoire. Si fichier est un répertoire, l'utilitaire sact se comporte comme si chaque fichier du répertoire était spécifié comme un fichier nommé, à l'exception des fichiers non-SCCS (le dernier composant du chemin ne commence pas par s.) et des fichiers illisibles qui sont ignorés silencieusement.

Si exactement un opérande fichier est spécifié et qu'il s'agit de '-', l'entrée standard est lue ; chaque ligne de l'entrée standard est interprétée comme le nom d'un fichier SCCS à traiter. Les fichiers non-SCCS et les fichiers illisibles sont ignorés silencieusement.

ENTRÉE_STANDARD

L'entrée standard est un fichier texte utilisé uniquement lorsque l'opérande fichier est spécifié comme '-'. Chaque ligne du fichier texte est interprétée comme un chemin SCCS.

FICHIERS_ENTRÉE

Tous les fichiers SCCS interrogés sont des fichiers de format non spécifié.

VARIABLES_ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de sact :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages diagnostiques écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS_ASYNCHRONES

Par défaut.

SORTIE_STANDARD

La sortie pour chaque fichier nommé doit consister en une ligne au format suivant :

"%s %s %s %s %s\n", <SID>, <nouveau SID>, <login>, <date>, <heure>
<SID>
Spécifie le SID d'un delta qui existe actuellement dans le fichier SCCS auquel des modifications sont apportées pour créer le nouveau delta.
<nouveau SID>
Spécifie le SID du nouveau delta à créer.
<login>
Contient le nom de connexion de l'utilisateur qui crée le delta (c'est-à-dire, qui a exécuté un get pour édition).
<date>
Contient la date d'exécution de get -e, dans le format utilisé par le mot-clé de données prs :D:.
<heure>
Contient l'heure d'exécution de get -e, dans le format utilisé par le mot-clé de données prs :T:.

S'il y a plus d'un fichier nommé ou si un répertoire ou l'entrée standard est nommée, chaque chemin doit être écrit avant chacune des lignes précédentes :

"\n%s:\n", <chemin>

SORTIE_ERREUR

La sortie d'erreur standard est utilisée uniquement pour les messages informatifs optionnels concernant les fichiers SCCS sans delta imminents, et pour les messages diagnostiques.

STATUT_SORTIE

Les valeurs de sortie suivantes sont renvoyées :

 0
Terminaison réussie.
>0
Une erreur s'est produite.
