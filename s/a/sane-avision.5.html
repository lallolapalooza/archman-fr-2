sane-avision(5) SANE Scanner Access Now Easy sane-avision(5)

NOM

sane-avision - Backend SANE pour les scanners plats et films de marque Avision et OEM Avision (HP, Minolta, Mitsubishi, UMAX et potentiellement plus).

DESCRIPTION

La bibliothèque sane-avision implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès à divers scanners Avision et aux scanners OEM Avision étiquetés par HP, Minolta, Mitsubishi ou Fujitsu.

Elle est entièrement compatible avec le big-endian et est utilisée quotidiennement sur les systèmes PowerPC et SPARC.

Je suggère de garder une main sur le bouton d'alimentation du scanner pendant que vous tentez les premiers scans - surtout avec les scanners de film !

CONFIGURATION

Le fichier de configuration pour ce backend se trouve dans /etc/sane.d/avision.conf.

Son contenu est une liste de noms de périphériques qui correspondent aux scanners Avision et compatibles Avision, ainsi que des options du backend. Les lignes vides et les lignes commençant par un signe dièse (#) sont ignorées. Un exemple de fichier de configuration est présenté ci-dessous:

 # ceci est un commentaire
 option force-a4
 option force-a3
 option skip-adf
 option disable-gamma-table
 option disable-calibration
 #scsi Vendor Model Type Bus Channel ID LUN
 scsi AVISION
 scsi HP
 scsi /dev/scanner
 usb 0x03f0 0x0701
force-a4:
Force le backend à écraser la zone scannable renvoyée par le scanner pour l'ISO A4. Les scanners connus pour renvoyer des données erronées sont marqués dans le backend, donc si vous avez besoin de cette option, veuillez en informer le mainteneur du backend. À UTILISER AVEC PRÉCAUTION !
force-a3:
Force le backend à écraser la zone scannable renvoyée par le scanner pour l'ISO A3. Les scanners connus pour renvoyer des données erronées sont marqués dans le backend, donc si vous avez besoin de cette option, veuillez en informer le mainteneur du backend. À UTILISER AVEC PRÉCAUTION !
skip-adf:
Force le backend à ignorer un état ADF incohérent renvoyé par le scanner (ADF non présent, mais le numéro de modèle ADF non nul). Sans cette option, le backend tentera plusieurs fois de réinitialiser l'ADF et de relancer la requête dans cette situation, et échouera avec une erreur "non pris en charge" si l'ADF ne répond toujours pas.
disable-gamma-table:
Désactive l'utilisation de la table gamma du scanner. Vous pouvez essayer ceci si vos scans se bloquent ou ne produisent que des caractères aléatoires.
disable-calibration:
Désactive la calibration des couleurs du scanner. Vous pouvez essayer ceci si vos scans se bloquent ou ne produisent que des caractères aléatoires.
Note :
Toute option ci-dessus modifie le flux d'exécution par défaut pour votre scanner. Les options ne doivent être utilisées que lorsque vous rencontrez des problèmes avec le comportement par défaut du backend. Veuillez signaler la nécessité de ces options à l'auteur du backend afin qu'il puisse être corrigé dès que possible.

NOMS DE PÉRIPHÉRIQUES

Ce backend attend des noms de périphériques de la forme :

scsi spec-scsi

usb spec-usb

Où spec-scsi est le nom du chemin vers un périphérique spécial ou un ID de périphérique pour le périphérique correspondant à un scanner SCSI. Le nom du périphérique spécial doit être un périphérique SCSI générique ou un lien symbolique vers un tel périphérique, par exemple sous Linux /dev/sga ou /dev/sg0. L'ID du périphérique est l'ID renvoyé par le scanner, par exemple "HP" ou "AVISION". Voir sane-scsi(5) pour plus de détails.

Note :
Étant donné que le backend inclut désormais un accès USB natif, il n'est plus nécessaire - voire obsolète - d'accéder aux scanners USB via l'émulation SCSI (nommée hpusbscsi sous Linux) pour les périphériques USB Avision tels que les HP 53xx, HP 74xx ou les scanners de film Minolta.

spec-usb est le nom du périphérique USB, la paire d'ID fabricant/produit ou le nom utilisé par libusb correspondant au scanner USB. Par exemple "0x03f0 0x0701" ou "libusb:002:003". Voir sane-usb(5) pour plus de détails.

Le programme sane-find-scanner(1) aide à trouver le nom correct du périphérique scsi ou usb.

Une liste des périphériques pris en charge est intégrée au backend avision, donc normalement la spécification d'un ID ne devrait pas être nécessaire.

FICHIERS

/etc/sane.d/avision.conf
Le fichier de configuration du backend (voir également la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-avision.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-avision.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par deux points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail actuel (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche dans les répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_AVISION
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie. Le niveau de débogage 7 est la valeur préférée de l'auteur pour déboguer les problèmes du backend.

Exemple : export SANE_DEBUG_AVISION=7
