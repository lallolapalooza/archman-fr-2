safe_loadTk(n)

Paquet: tk

Licences: TCL

Safe Tk(n) Commandes intégrées Tk Safe Tk(n)

NOM

safe::loadTk - Charger Tk dans un interpréteur sécurisé.

SYNTAXE

safe::loadTk enfant ?-use identifiantFenêtre? ?-display nomAffichage?

DESCRIPTION

Safe Tk est basé sur Safe Tcl, qui fournit un mécanisme permettant un accès restreint et médiatisé au chargement automatique et aux paquets pour les interpréteurs sécurisés. Safe Tk ajoute la capacité de configurer l'interpréteur pour les opérations Tk sécurisées et de charger Tk dans les interpréteurs sécurisés.

La commande safe::loadTk initialise les structures de données requises dans l'interpréteur sécurisé nommé, puis y charge Tk. L'interpréteur doit avoir été créé avec safe::interpCreate ou avoir été initialisé avec safe::interpInit. La commande renvoie le nom de l'interpréteur sécurisé. Si -use est spécifié, la fenêtre identifiée par l'identifiant dépendant du système identifiantFenêtre est utilisée pour contenir la fenêtre “.” de l'interpréteur sécurisé ; elle peut être un identifiant valide, référençant éventuellement une fenêtre appartenant à une autre application. Par commodité, si la fenêtre que vous prévoyez d'utiliser est une fenêtre Tk de l'application, vous pouvez utiliser le nom de la fenêtre (par exemple, “.x.y”) à la place de son identifiant de fenêtre (par exemple, provenant de winfo id .x.y). Lorsque -use n'est pas spécifié, une nouvelle fenêtre de niveau supérieur est créée pour la fenêtre “.” de l'interpréteur sécurisé. Sur X11, si vous souhaitez que la fenêtre intégrée utilise un affichage différent de celui par défaut, spécifiez-le avec -display. Voir la section PROBLÈMES DE SÉCURITÉ ci-dessous pour les détails d'implémentation.

PROBLÈMES DE SÉCURITÉ

Veuillez lire la page de manuel safe pour Tcl pour en savoir plus sur les considérations de sécurité de base pour Safe Tcl.

safe::loadTk ajoute la valeur de tk_library extraite de l'interpréteur parent au chemin d'accès virtuel de l'interpréteur sécurisé afin que le chargement automatique fonctionne dans l'interpréteur sécurisé.

L'initialisation de Tk est désormais sécurisée par rapport à la non-confiance dans l'état de l'enfant pour le démarrage. safe::loadTk enregistre le nom de l'enfant afin que lorsque l'initialisation de Tk (Tk_SafeInit) est appelée et appelle à son tour safe::InitTk de l'interpréteur parent, elle renvoie l'équivalent argv souhaité (-use identifiantFenêtre, -display correct, etc.).

Lorsque -use n'est pas utilisé, la nouvelle fenêtre de niveau supérieur créée est spécialement décorée de sorte que l'utilisateur soit toujours conscient que l'interface utilisateur présentée provient d'un code potentiellement non sécurisé et puisse facilement supprimer l'interpréteur correspondant.

Sur X11, une combinaison conflictuelle de -use et -display générera probablement une erreur X fatale.
