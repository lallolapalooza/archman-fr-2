sane-umax_pp(5) SANE Scanner Access Now Easy sane-umax_pp(5)

NOM

sane-umax_pp - Backend SANE pour scanners à plat Umax à port parallèle

DESCRIPTION

La bibliothèque sane-umax_pp implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners à plat Umax à port parallèle. Les scanners suivants fonctionnent avec ce backend :

Modèle :
--------------------
Astra 610P
Astra 1220P
HP3200C
Astra 1600P
Astra 2000P
Genius ColorPage-Life Pro

Ce backend gère les résolutions de balayage 75x75, 150x150, 300x300, 600x600 et 600x1200 pour 1220P/1600P/2000P dpi, et 75x75, 150x150, 300x300 et 300x600 pour 610P. En niveaux de gris et en couleur, il existe un mode lineart logiciel.

Les modèles de nouvelle génération partagent une version plus récente du ASIC 610P intégrée dans une puce EPAT. Seules des parties telles que le CCD et l'ADC changent d'un modèle à l'autre. Ils se déclarent même tous comme UMAX Astra 1220P via IEEE1284. Il n'y a pas de méthode logicielle pour les reconnaître correctement. Sous Windows, le modèle est défini par le pilote installé, indépendamment du matériel.

UNIQUEMENT MODES EPP/ECP
La version actuelle du backend n'utilise que les modes EPP ou ECP pour communiquer avec le scanner. Le mode PS/2 n'est pas implémenté. Le 610P n'utilise que SPP. Il est recommandé de configurer votre port parallèle en mode EPP dans le BIOS avec la version actuelle de ce backend. Vous pouvez le laisser en ECP ou ECP+EPP, mais dans ce cas, vous ne pourrez pas utiliser ppdev mais seulement l'accès direct au matériel si vous devez utiliser ECP. ECPEPP ne fonctionnera que si vous utilisez un noyau 2.4 ou 2.6 avec le support du périphérique caractère ppdev.

Ce backend prend en charge le partage de port parallèle uniquement si vous avez un noyau avec le support ppdev.

Notez que si vous n'utilisez pas le périphérique caractère ppdev, le backend doit être exécuté en tant que root. Pour autoriser l'accès utilisateur au scanner, exécutez le backend via l'interface réseau (voir saned(8) et sane-net(5)). Une solution plus souple (en termes de sécurité) consiste à ajouter le bit suid au frontend (voir chmod(1)). Le backend abandonne ses privilèges root dès qu'il le peut, juste après avoir obtenu un accès direct aux ports d'E/S, ce qui réduit les risques d'être root.

NOMS DE PÉRIAUPHÉRIQUE

Ce backend s'attend à des noms de périphérique de la forme :

port valeur

Où valeur est :

auto
autodétecte tous les ports parallèles et les sonde pour le scanner
safe-auto
autodétecte tous les ports parallèles et les sonde pour le scanner, mais n'essaie pas d'accéder directement au matériel
/dev/ppi0
utilise le périphérique ppi de *BSD, en fonction du nombre de ports parallèles disponibles, vous devez utiliser /dev/ppi1, /dev/ppi2, ...
/dev/parport0
utilise le périphérique ppdev de Linux, en fonction du nombre de ports parallèles disponibles, vous devez utiliser /dev/parport1, /dev/parport2, ...
0x378
effectue un accès direct au matériel à l'adresse donnée. Les valeurs usuelles sont 0x378, 0x278, 0x3BC. Dans ce cas, vous devez exécuter le backend en tant que root (*BSD et Linux), ou avec 'IOPL=yes' sous OS/2

NOTE : dans tous les cas, vous devez disposer des privilèges suffisants pour accéder au périphérique ou à l'adresse choisi. Selon les paramètres de sécurité, les périphériques peuvent ne pas être disponibles pour tous les utilisateurs. Vous devez modifier les autorisations sur les périphériques /dev/ppi* ou /dev/parport*.
Vous pouvez renommer n'importe quel périphérique en utilisant les

nom nomdev
modèle modèle
fabricant fabricant

options. Ces options s'appliquent à la dernière option de port.

CONFIGURATION

Assurez-vous d'éditer umax_pp.conf avant d'utiliser le backend.

Le contenu du fichier umax_pp.conf est une liste d'options et de noms de périphériques correspondant aux scanners Umax. Les lignes vides et les lignes commençant par un dièse (#) sont ignorées.

Les huit options prises en charge sont red-gain, green-gain, blue-gain, red-offset, green-offset, blue-offset, astra et buffer.

Les options red-gain, green-gain et blue-gain vous permettent d'ajuster la sensibilité de votre scanner pour la couleur donnée. Les valeurs vont de 0 (gain le plus bas) à 15 (gain le plus élevé). Si l'option avancée « Gain » n'est pas cochée dans le frontend, le backend effectue un calibrage automatique du gain et n'utilise pas les valeurs fournies par l'utilisateur.

Les options red-offset, green-offset et blue-offset vous permettent d'ajuster le décalage de votre scanner pour la couleur donnée. Les valeurs vont de 0 (décalage le plus bas) à 15 (décalage le plus élevé).

L'option astra vous permet de changer le modèle de votre scanner. La détection automatique actuelle est basée sur les effets secondaires lors de la numérisation lorsque l'ensemble de commandes 1220P est utilisé sur d'autres modèles, elle peut donc échouer sur des combinaisons matérielles inconnues. Les valeurs valides sont 610, 1220, 1600 et 2000. Elle est utile uniquement lorsque la détection automatique échoue à détecter correctement le modèle de votre scanner. Si votre scanner fonctionne correctement mais est mal rapporté, laissez-le tel quel. Le seul cas valide pour changer le modèle est lorsque votre scanner produit des numérisations « noires » ou « inversées ». Dans ce cas, vous pouvez spécifier le modèle. Sachez que cela empêchera la détection automatique du modèle du scanner.

L'option buffer vous permet de changer la taille du tampon de numérisation. La taille doit être spécifiée en octets. La valeur par défaut est de 2 mégaoctets. Diminuer cette valeur améliorera la fluidité de la barre de progression dans le frontend, mais bloquera plus souvent la numérisation.

FICHIERS

Le fichier de configuration du backend (voir également la description de SANE_CONFIG_DIR ci-dessous).
/usr/lib/sane/libsane-umax_pp.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-umax_pp.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par un deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") et ensuite dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour résultat que les répertoires tmp/config, ., et /etc/sane.d seraient recherchés (dans cet ordre).
SANE_DEBUG_UMAX_PP
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des niveaux inférieurs réduisent la verbosité. 
niveau    sortie de débogage
------- ------------------------------
 0       rien
 1       erreurs
 2       avertissements & erreurs mineures
 3       informations supplémentaires
 4       informations de débogage
 5       flux de code (pas encore supporté)
 6       informations de débogage spéciales
SANE_DEBUG_UMAX_PP_LOW
Cette variable définit le niveau de débogage pour l'interface SANE pour l'ASIC Umax. Notez que son activation spammera votre terminal avec plusieurs millions de lignes de sortie de débogage. 
niveau    sortie de débogage
------- -------------------------------
 0       rien
 1       erreurs
 8       blocs de commandes
 16      flux de code détaillé
 32      dump des fichiers de données
 255     tout

RAPPORTS DE BOGUES

Si quelque chose ne fonctionne pas, contactez-moi. Mais j'ai besoin d'informations sur votre scanner pour pouvoir vous aider...

Version de SANE
Exécutez scanimage -V pour le déterminer.
La version du backend et le matériel de votre scanner
Exécutez SANE_DEBUG_UMAX_PP=255 scanimage -L 2>log en tant que root. Si vous n'obtenez aucune sortie du backend sane-umax_pp, assurez-vous qu'une ligne "umax_pp" est incluse dans votre fichier /etc/sane.d/dll.conf. Si votre scanner n'est pas détecté, assurez-vous d'avoir défini la bonne adresse de port, ou le bon périphérique dans votre fichier umax_pp.conf.
Le nom de votre scanner/fabricant
C'est également une information utile. Veuillez également inclure la résolution optique et le type de lampe de votre scanner, tous deux trouvables dans le manuel de votre scanner.
Tous commentaires supplémentaires
Si vous avez des commentaires sur la documentation (ce qui pourrait être amélioré), ou si vous pensez que je devrais savoir quelque chose, veuillez l'inclure.
