SANE-AIRSCAN(5) Backend SANE AirScan (eSCL) et WSD SANE-AIRSCAN(5)

NOM

sane-airscan - Backend SANE pour scanners et multifonctions AirScan (eSCL) et WSD

DESCRIPTION

sane-airscan est le backend universel pour la numérisation de documents "sans pilote". Il prend actuellement en charge deux protocoles :

1. eSCL, également connu sous le nom d'AirScan ou d'impression de numérisation AirPrint
2. WSD, également connu sous le nom de WS-Scan

CONFIGURATION

sane-airscan charge ses fichiers de configuration depuis les emplacements suivants :

1. /etc/sane.d/airscan.conf
2. /etc/sane.d/airscan.d/*

La syntaxe du fichier de configuration est très similaire à la syntaxe des fichiers .INI. Elle se compose de sections, chacune contenant des variables. Les commentaires sont indiqués par les caractères # ou ; et se poursuivent jusqu'à la fin de la ligne.

# Ceci est un commentaire
[section 1]
variable 1 = valeur 1  ; et un autre commentaire
variable 2 = valeur 2

Les espaces de début et de fin du nom de la variable et de la valeur sont supprimés. Si vous souhaitez les conserver, placez le nom ou la valeur entre guillemets ("comme ceci").

CONFIGURATION DES APPAREILS

Si le scanner et l'ordinateur sont connectés au même segment LAN, tout devrait fonctionner nativement, sans nécessiter de configuration manuelle.

Cependant, dans certains cas, une configuration manuelle peut être utile. Par exemple :

1. Si l'ordinateur et le scanner sont connectés via un routeur IP
2. S'il y a beaucoup d'appareils sur un réseau d'entreprise, mais
   que seule une petite partie d'entre eux est intéressante
3. Si la découverte automatique fonctionne de manière peu fiable

Pour configurer manuellement un appareil, ajoutez la section suivante au fichier de configuration :

[devices]
"Kyocera eSCL" = http://192.168.1.102:9095/eSCL, eSCL
"Kyocera WSD" = http://192.168.1.102:5358/WSDScanner, WSD
"Appareil que je ne veux pas voir" = disable

La section [devices] contient tous les appareils configurés manuellement, une ligne par appareil, et chaque ligne contient un nom d'appareil à gauche de l'équation et une URL d'appareil à droite, suivie du protocole (eSCL ou WSD). Si le protocole est omis, eSCL est supposé. Vous pouvez également désactiver un appareil particulier en utilisant le mot-clé disable à la place d'une URL.

De plus, vous pouvez configurer manuellement un appareil en passant directement son URL dans un nom d'appareil sans l'ajouter au fichier de configuration. Cela prend le format protocole:NomAppareil:URL. Les exemples ci-dessus pourraient être écrits comme escl:Kyocera eSCL:http://192.168.1.102:9095/eSCL et wsd:Kyocera WSD:http://192.168.1.102:5358/WSDScanner.

Pour connaître les URL des appareils disponibles, le moyen le plus simple est d'exécuter l'outil fourni airscan-discover(1) sur un ordinateur connecté au même segment LAN que le scanner. En cas de succès, ce programme affichera dans sa sortie standard une liste des appareils découverts dans un format adapté à l'inclusion dans le fichier de configuration.

Si l'exécution de airscan-discover(1) sur le même segment LAN qu'un scanner n'est pas possible, vous devrez emprunter la voie difficile. Votre administrateur doit connaître l'adresse IP de l'appareil, consulter le manuel de votre appareil pour le port eSCL, et la composante du chemin de l'URL sera très probablement "/eSCL", bien que cela puisse varier sur certains appareils. La découverte des URL WSD de cette manière est beaucoup plus difficile, car il est très compliqué de deviner le port TCP et le chemin de l'URL, comme c'est le cas pour eSCL.

Pour les appareils eSCL, l'URL peut également utiliser le schéma unix://, tel que unix://scanner.sock/eSCL. L'"hôte" de l'URL est un nom de fichier qui sera recherché dans le répertoire spécifié par socket_dir (voir ci-dessous). Lors de la connexion au scanner, tout le trafic sera envoyé au socket UNIX spécifié au lieu d'une connexion TCP.

Par défaut, sane-airscan traite tous les scanners comme des appareils distants. Cela peut être indésirable si vous configurez un proxy qui traduit d'eSCL/WSD vers le protocole SANE, car saned(8) ignore tout appareil qui n'est pas connecté localement. En définissant pretend-local = true, sane-airscan peut rendre ses appareils accessibles au démon réseau SANE.

OPTIONS DE CONFIGURATION

Diverses options vont dans la section [options]. Actuellement, les options suivantes sont prises en charge :

[options]
; S'il y a beaucoup de scanners et que vous n'êtes intéressé
; que par quelques-uns, désactivez la découverte automatique et
; configurez les scanners manuellement.
discovery = enable | disable
; Choisissez ce que les applications SANE afficheront dans la liste des appareils :
; le nom réseau du scanner (par défaut) ou le nom du modèle matériel.
model = network | hardware
; Si un appareil prend en charge les protocoles eSCL et WSD, sane-airscan
; peut soit choisir automatiquement le "meilleur" protocole, soit
; exposer toutes les variantes à l'utilisateur, permettant une sélection manuelle du protocole.
; La valeur par défaut est "auto".
protocol = auto | manual
; La découverte des appareils WSD peut être "fast" (rapide) ou "full" (complète). Le mode "fast"
; fonctionne aussi rapidement que la découverte DNS-SD, mais peut être peu fiable
; dans certains cas. Le mode "full" est lent et fiable.
; Il est également possible de désactiver la découverte automatique
; des appareils WSD. La valeur par défaut est "fast".
ws-discovery = fast | full | off
; Les scanners utilisant le schéma unix:// dans leur URL ne peuvent
; spécifier qu'un nom de socket (pas un chemin complet). Le nom sera
; recherché dans le répertoire spécifié ici.
; La valeur par défaut est /var/run.
socket_dir = /chemin/vers/repertoire
; Configurez si les appareils eSCL et WSD doivent être traités comme
; s'ils étaient connectés localement. Le comportement par défaut les
; considère comme des appareils distants accessibles via le réseau.
; Cette option doit être modifiée lors de l'exportation d'un scanner via
; saned. La valeur par défaut est "false"
pretend-local = false | true

LISTE NOIRE DES APPAREILS

Cette fonctionnalité peut être utile si vous êtes sur un réseau très vaste et que vous avez de nombreux appareils autour de vous, alors que vous n'êtes intéressé que par quelques-uns.

[blacklist]
model = "Xerox*"       ; liste noire par nom de modèle
name  = "HP*"          ; liste noire par nom réseau
ip    = 192.168.0.1    ; liste noire par adresse
ip    = 192.168.0.0/24 ; liste noire de tout le sous-réseau

Les noms réseau proviennent de DNS-SD, WS-Discovery ne fournit pas cette information. Pour que le filtrage par nom réseau fonctionne, Avahi doit être activé et l'appareil doit être découvrable via DNS-SD (pas nécessairement en tant que scanner, il suffit que le scanner WSD soit découvrable en tant qu'imprimante via DNS-SD).

La mise en liste noire n'affecte que la découverte automatique et n'a pas d'impact sur les appareils configurés manuellement.

DÉBOGAGE

sane-airscan fournit une excellente instrumentation pour le dépannage sans accès physique à l'appareil problématique.

Les installations de débogage peuvent être contrôlées à l'aide de la section [debug] du fichier de configuration :

[debug]
; Active ou désactive la journalisation sur console
enable = false | true
; Active le traçage du protocole et configure le répertoire de sortie
; pour les fichiers de traçage. Comme dans le shell, pour spécifier un chemin relatif au
; répertoire personnel, commencez-le par un tilde, suivi d'une barre oblique, par ex. "~/airscan/trace". Le répertoire sera
; créé automatiquement.
trace = chemin
; Affiche en hexadécimal tout le trafic dans le fichier de traçage (très verbeux !)
hexdump = false | true

VOIR AUSSI

" id='ENVIRONMENT'>ENVIRONNEMENT
SANE_DEBUG_AIRSCAN
Cette variable, si définie à true ou à une valeur numérique non nulle, active les messages de débogage qui sont imprimés sur la sortie d'erreur standard.
SANE_CONFIG_DIR
Cette variable modifie le chemin de recherche des fichiers de configuration. Il s'agit d'une liste de répertoires séparés par des deux-points. Ces répertoires sont recherchés pour le fichier de configuration airscan.conf et pour le sous-répertoire airscan.d, avant que le chemin standard (/etc/sane.d) ne soit recherché.
SANE_AIRSCAN_DEVICE
Cette variable, si définie, remplace tous les périphériques configurés manuellement dans les fichiers de configuration et désactive la découverte automatique.
Elle se compose de trois paramètres, délimités par des deux-points (:) :
"PROTO:NOM DU PÉRIPHÉRIQUE:URL"
Où :
- PROTO est soit escl, soit wsd.
- NOM DU PÉRIPHÉRIQUE apparaîtra dans la liste des périphériques.
- URL est l'URL du périphérique, utilisant les schémas http: ou https:.
Exemples :
"escl:Kyocera eSCL:http://192.168.1.102:9095/eSCL" (eSCL)
"wsd:Kyocera WSD:http://192.168.1.102:5358/WSDScanner" (WSD)
L'objectif principal de cette variable est le test automatisé du backend sane-airscan.
