NOM

sacctmgr - Permet de visualiser et modifier les informations de compte Slurm.

SYNTAXE

sacctmgr [OPTIONS...] [COMMANDE...]

DESCRIPTION

sacctmgr est utilisé pour visualiser ou modifier les informations de compte Slurm. Les informations de compte sont maintenues dans une base de données dont l'interface est fournie par slurmdbd (démon de base de données Slurm). Cette base de données peut servir de dépôt central pour les informations utilisateur et informatiques de plusieurs ordinateurs sur un même site. Les informations de compte Slurm sont enregistrées sur la base de quatre paramètres qui forment ce que l'on appelle une association. Ces paramètres sont utilisateur, cluster, partition et compte. utilisateur est le nom de connexion. cluster est le nom d'un cluster géré par Slurm, tel que spécifié par le paramètre ClusterName dans le fichier de configuration slurm.conf. partition est le nom d'une partition Slurm sur ce cluster. compte est le compte pour un travail. Le mode de fonctionnement prévu est d'initier la commande sacctmgr, d'ajouter, supprimer, modifier et/ou lister des enregistrements d'association, puis de valider les changements et de quitter.

NOTE: Le contenu de la base de données de Slurm est maintenu en minuscules. Cela peut entraîner une sortie de sacctmgr différente de celle des autres commandes Slurm.

OPTIONS

-s, --associations
À utiliser avec show ou list pour afficher les associations avec l'entité. Ceci est équivalent à la commande associations.
-h, --help
Affiche un message d'aide décrivant l'utilisation de sacctmgr. Ceci est équivalent à la commande help.
-i, --immediate
Valide les changements immédiatement sans demander de confirmation.
--json, --json=list, --json=<data_parser>
Affiche les informations au format JSON en utilisant le plugin data_parser par défaut ou un data_parser explicite avec des paramètres. Les arguments de tri et de formatage seront ignorés. Cette option n'est pas disponible pour toutes les commandes.
-n, --noheader
Aucun en-tête ne sera ajouté au début de la sortie.
-p, --parsable
La sortie sera délimitée par '|' avec un '|' à la fin.
-P, --parsable2
La sortie sera délimitée par '|' sans '|' à la fin.
-Q, --quiet
N'affiche aucun message autre que les messages d'erreur. Ceci est équivalent à la commande quiet.
-r, --readonly
Rend impossible la modification des informations de comptabilité par sacctmgr en cours d'exécution. L'option readonly est destinée à être utilisée en mode interactif.
--yaml, --yaml=list, --yaml=<data_parser>
Affiche les informations au format YAML en utilisant le plugin data_parser par défaut ou un data_parser explicite avec des paramètres. Les arguments de tri et de formatage seront ignorés. Cette option n'est pas disponible pour toutes les commandes.
-v, --verbose
Active la journalisation détaillée. Ceci est équivalent à la commande verbose.
-V , --version
Affiche le numéro de version. Ceci est équivalent à la commande version.

ENTITIES

Les entités qui peuvent être gérées par sacctmgr sont les suivantes:

  • account : Compte(s) de facturation.
  • association : Association entre un utilisateur, un cluster, une partition et un compte.
  • cluster : Cluster(s) Slurm.
  • cos : Classe(s) de service.
  • event : Événement(s) de comptabilité.
  • limits : Limite(s) de ressources.
  • node : Nœud(s).
  • partition : Partition(s) Slurm.
  • QOS : Qualité(s) de service.
  • resource : Ressource(s).
  • user : Utilisateur(s).

EXEMPLES

Afficher toutes les informations de compte :

sacctmgr show account

Afficher les associations pour l'utilisateur 'testuser' :

sacctmgr show user where name=testuser associations

Ajouter un nouveau compte :

sacctmgr create account where name=new_account description="Nouveau compte pour le projet X"

Modifier un compte existant :

sacctmgr modify account where name=old_account set description="Description mise à jour"

Supprimer un compte :

sacctmgr delete account where name=account_to_delete

ENTITÉS

account
Un compte, généralement spécifié au moment de la soumission d'un travail en utilisant l'option --account=. Ceux-ci peuvent être organisés de manière hiérarchique, par exemple, les comptes 'chemistry' et 'physics' peuvent être des enfants du compte 'science'. La hiérarchie peut avoir une profondeur arbitraire.
association
L'entité utilisée pour regrouper des informations composées de quatre paramètres : account, cluster, partition (optionnel) et user. Utilisée uniquement avec la commande list ou show. L'ajout, la modification et la suppression doivent être effectués sur une entité utilisateur, compte ou cluster, ce qui mettra à jour les associations sous-jacentes. La modification d'attributs tels que les limites est autorisée pour une association, mais pas la modification des quatre attributs principaux d'une association. Vous ne pouvez pas modifier le paramètre de partition (ou en définir un s'il n'a pas été défini) pour une association existante. Au lieu de cela, vous devrez créer une nouvelle association avec la partition incluse. Vous pouvez soit conserver l'association précédente sans partition définie, soit la supprimer. Notez que ces associations nouvellement ajoutées sont des entités uniques et que toute information d'utilisation existante ne sera pas reportée sur la nouvelle association.
cluster
Le paramètre ClusterName dans le fichier de configuration slurm.conf, utilisé pour différencier les comptes sur différentes machines.
configuration
Utilisé uniquement avec la commande list ou show pour rapporter la configuration actuelle du système.
coordinator
Un utilisateur privilégié spécial, généralement un gestionnaire de compte, qui peut ajouter des utilisateurs ou des sous-comptes au compte dont il est le coordinateur. Il doit s'agir d'une personne de confiance car elle peut modifier les limites des associations de comptes et d'utilisateurs, ainsi que supprimer, replanifier ou réaffecter les comptes des travaux dans son domaine.
event
Événements tels que des nœuds en panne ou en cours de drainage sur les clusters. Notez que cela n'inclut pas les états transitoires comme DRAINING.
federation
Un groupe de clusters qui travaillent ensemble pour planifier des travaux.
job
Utilisé pour modifier des champs spécifiques d'un travail : Code de sortie dérivé, Commentaire, Commentaire administrateur, Supplémentaire, Commentaire système, TRES, ou WCKey.
problem
À utiliser avec show ou list pour afficher les problèmes d'entité.
qos
Quality of Service (Qualité de Service).
reservation
Une collection de ressources mises de côté pour être utilisées par un compte, un utilisateur ou un groupe d'utilisateurs particulier pour une période donnée.
resource
Ressources logicielles pour le système. Il s'agit de licences logicielles partagées entre les clusters.
RunawayJobs
Utilisé uniquement avec la commande list ou show pour rapporter les travaux en cours qui ont été orphelins sur le cluster local et qui sont maintenant en fuite. S'il y a des travaux dans cet état, cela vous donnera également la possibilité de les "réparer". Cela définit l'heure de fin de chaque travail à la dernière des heures de début, éligible et de soumission du travail, et définit l'état sur complété par défaut. Une fois corrigé, cela déclenche le SlurmDBD pour recalculer l'utilisation à partir d'avant l'heure de soumission la plus ancienne de tous les travaux en fuite. NOTE : Cela peut prendre beaucoup de temps et sreport peut ne pas renvoyer de données avant que le recalcul soit terminé. NOTE : Vous devez avoir un AdminLevel d'au moins Operator pour effectuer cela.
stats
Utilisé avec la commande list ou show pour afficher les statistiques du serveur. Accepte un argument optionnel ave_time ou total_time pour trier sur ces champs. Par défaut, trie sur le champ de comptage RPC croissant.
transaction
Liste des transactions qui se sont produites pendant une période donnée.
tres
Utilisé avec la commande list ou show pour afficher une liste des RESources TRackables configurées sur le système.
user
Le nom de connexion. Les noms d'utilisateur sont insensibles à la casse (forcés en minuscules) à moins que l'option PreserveCaseUser n'ait été définie dans le fichier de configuration SlurmDBD.
wckeys
Workload Characterization Key (Clé de Caractérisation de la Charge de Travail). Une chaîne de caractères arbitraire pour grouper des comptes orthogonaux.

SPÉCIFICATIONS GÉNÉRALES POUR LES ENTITÉS BASÉES SUR DES ASSOCIATIONS

NOTE : Les limites de groupe (GrpJobs, GrpTRES, etc.) sont testées lorsqu'un travail est en cours d'examen pour l'allocation de ressources. Si le démarrage d'un travail devait dépasser l'une de ses limites de groupe, ce travail ne serait pas pris en compte pour la planification même si ce travail pourrait évincer d'autres travaux qui libéreraient suffisamment de ressources de groupe pour que le travail en attente puisse être lancé.

NOTE : Les modifications de limites TRES de quelque nature que ce soit utilisant la syntaxe « += » ou « -= » produiront toujours une valeur comprise entre 0 et 18446744073709551600. Essayer de définir une valeur négative en utilisant « -= » définira ce TRES à 0, même s'il n'y avait pas de limite TRES présente auparavant.

DefaultQOS=<default_qos>
Le QOS que cette association et ses enfants utiliseront par défaut s'il est autorisé dans la liste QosLevel mentionnée ci-dessous. Ceci est remplacé s'il est défini directement sur un utilisateur. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.
Fairshare={<fairshare_number>|parent}
Share={<fairshare_number>|parent}
Partages alloués utilisés pour le calcul du partage équitable. Peut aussi être la chaîne parent, qui est interprétée différemment si elle est définie sur un utilisateur ou sur un compte. Si elle est définie sur un utilisateur, l'association parente est utilisée pour le partage équitable. Si elle est définie sur un compte, les enfants de ce compte seront effectivement ré-parentés pour les calculs de partage équitable au premier parent de leur parent qui n'est pas Fairshare=parent. Les limites restent les mêmes, seule sa valeur de partage équitable est affectée. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.

Nombre maximum de travaux en cours globalement pour cette association et ses enfants. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.
GrpJobsAccrue=<max_jobs>
Nombre maximum de travaux en attente globalement pouvant accumuler une priorité d'âge pour cette association et ses enfants. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.
GrpSubmit=<max_jobs>
GrpSubmitJobs=<nombre_max_jobs>
Nombre maximal de travaux en état d'attente ou en cours d'exécution à tout moment, globalement pour cette association et ses enfants. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.

Nombre maximal de TRES pouvant être alloués par les travaux en cours d'exécution, globalement pour cette association et ses enfants.

GrpTRESMins=TRES[+|-]=<minutes>[,TRES[+|-]=<minutes>,...]

NOTE : Cette limite ne s'applique que lors de l'utilisation du plugin Priority Multifactor. Le temps est déprécié en utilisant la valeur de PriorityDecayHalfLife ou PriorityUsageResetPeriod telle que définie dans slurm.conf. Lorsque cette limite est atteinte, tous les travaux associés en cours d'exécution seront tués et tous les travaux futurs soumis avec des associations du groupe seront retardés jusqu'à ce qu'ils puissent s'exécuter dans la limite.

Nombre maximal de travaux en état d'attente ou en cours d'exécution à tout moment dans cette association. La valeur par défaut est la limite du cluster. Pour effacer une valeur existante, définissez une nouvelle valeur de -1.

SPÉCIFICATIONS DES COMPTES

Les comptes peuvent être créés, modifiés et supprimés avec sacctmgr. Ces options vous permettent de définir les attributs correspondants ou de les filtrer lors de la requête de comptes.

Cluster=<cluster>
Cluster spécifique auquel ajouter le compte. La valeur par défaut est tous les systèmes.
Description=<description>
Une chaîne de caractères arbitraire décrivant un compte.
Flags=<flag>[,<flag>,...]
Les options valides sont :
NoUsersAreCoords
Supprime le privilège défini par UsersAreCoords.
UsersAreCoords
Si défini, tous les utilisateurs de ce compte auront le statut de coordinateur ici et de tout sous-compte dans sa hiérarchie.
Name=<nom>
Le nom d'un compte. Notez que le nom doit être unique et ne peut pas représenter différents comptes à différents points de la hiérarchie des comptes.
Organization=<org>
Organisation à laquelle le compte appartient.
Parent=<parent>
Compte parent de ce compte. Par défaut, il s'agit du compte racine, un compte de niveau supérieur.
RawUsage=<value>
Ceci permet à un administrateur de réinitialiser l'utilisation brute accumulée d'un compte. La seule valeur actuellement supportée est 0 (zéro). Ceci est une spécification de réglage uniquement - elle ne peut pas être utilisée comme filtre pour lister les comptes.
WithAssoc
Afficher toutes les associations pour ce compte.
WithCoord
Afficher tous les coordinateurs pour ce compte.
WithDeleted
Afficher les informations avec des données précédemment supprimées. Les comptes qui sont supprimés dans les 24 heures suivant leur création et qui n'ont pas eu d'exécution de tâche pendant ce temps seront supprimés de la base de données. Sinon, le compte sera marqué comme supprimé et sera consultable avec le flag WithDeleted.

NOTE : Si vous utilisez l'option WithAssoc, vous pouvez également interroger les informations spécifiques aux associations pour n'afficher que certaines associations que ce compte peut avoir. Ces options supplémentaires se trouvent dans la section SPÉCIFICATIONS POUR LES ASSOCIATIONS. Vous pouvez également utiliser la liste des spécifications générales ci-dessus dans la section SPÉCIFICATIONS GÉNÉRALES POUR LES ENTITÉS BASÉES SUR LES ASSOCIATIONS.

SPÉCIFICATIONS POUR LES ASSOCIATIONS

Les associations peuvent être créées, modifiées et supprimées avec sacctmgr. Ces options vous permettent de définir les attributs correspondants ou de les filtrer lors de la requête d'associations.

Clusters=<nom_cluster>[,<nom_cluster>,...]
Lister les associations du ou des clusters.
Comptes=<nom_compte>[,<nom_compte>,...]
Lister les associations du ou des comptes.
Utilisateurs=<nom_utilisateur>[,<nom_utilisateur>,...]
Lister les associations du ou des utilisateurs.
Partitions=<nom_partition>[,<nom_partition>,...]
Lister les associations de la ou des partitions.

NOTE : Utilisez Partitions="" ou Partitions='' sans autres noms listés lors de la spécification du cas où il n'y a pas de partition. SPÉCIFICATIONS POUR QOS

Une QOS peut être créée, modifiée et supprimée avec sacctmgr. Ces options vous permettent de définir les attributs correspondants ou de les filtrer lors de la requête d'une QOS.

NOTE: Les limites de groupe (GrpJobs, GrpTRES, etc.) sont testées lorsqu'une tâche est considérée pour l'allocation de ressources. Si le démarrage d'une tâche entraînait le dépassement de l'une de ses limites de groupe, cette tâche ne serait pas prise en compte pour la planification, même si elle pourrait supplanter d'autres tâches qui libéreraient suffisamment de ressources de groupe pour que la tâche en attente puisse être initiée.

NOTE: Toutes les options TRES (GrpTRES, MaxTRES, etc.) peuvent également utiliser la même syntaxe "[+|-]=" disponible pour les entités basées sur des associations.

Description
Une chaîne arbitraire décrivant une QOS. Ne peut être modifié que par un administrateur Slurm.
Flags
Utilisé par slurmctld pour outrepasser ou appliquer certaines caractéristiques. Pour ajouter ou supprimer des drapeaux individuels, utilisez les opérateurs += ou -=. Pour effacer tous les drapeaux existants, définissez une nouvelle valeur de -1.
Options valides :
DenyOnLimit
S'il est défini, les tâches utilisant cette QOS seront rejetées au moment de la soumission si elles ne respectent pas les limites 'Max' ou 'Min' de la QOS en tant que tâches autonomes. Les tâches qui dépassent ces limites lorsque d'autres tâches sont prises en compte, mais qui respectent les limites lorsqu'elles sont considérées individuellement, ne seront pas rejetées. Elles seront plutôt en attente jusqu'à ce que des ressources soient disponibles. Les limites de groupe (par exemple, GrpTRES) seront également traitées comme des limites 'Max' (par exemple, MaxTRESPerNode) et les tâches seront refusées si elles violent la limite en tant que tâches autonomes. Ceci ne s'applique actuellement qu'aux limites de QOS et d'associations.
EnforceUsageThreshold
S'il est défini, et que la QOS a également un UsageThreshold, toute tâche soumise avec cette QOS qui tombe en dessous de l'UsageThreshold sera retenue jusqu'à ce que son Usage de Partage Équitable dépasse le seuil.
NoDecay
S'il est défini, cette QOS ne verra pas ses GrpTRESMins, GrpWall et UsageRaw décroître en fonction des paramètres PriorityDecayHalfLife ou PriorityUsageResetPeriod de slurm.conf. Cela permet à une QOS de fournir des limites agrégées qui, une fois consommées, ne seront pas automatiquement reconstituées. Une telle QOS agira comme un quota de ressources limité dans le temps pour une association qui y a accès. L'utilisation du compte/utilisateur continuera à décroître pour les associations utilisant la QOS. NOTE : Pour des raisons de performance, le planificateur de remplissage réserve des nœuds entiers pour les jobs, pas des nœuds partiels. Si, lors de la planification de remplissage, un job préempte un ou plusieurs autres jobs, les nœuds entiers de ces jobs préemptés sont réservés pour le job préempteur, même si le job préempteur a demandé moins de ressources que cela. Par conséquent, les jobs peuvent préempter plus de ressources lors d'une seule itération de remplissage qu'ils n'en ont demandé.

Est la valeur par défaut et désactive la préemption de jobs et la planification gang. Elle n'est compatible qu'avec PreemptType=preempt/none au niveau global.
CANCEL
Le job préempté sera annulé.
GANG
Active la planification gang (time slicing) des jobs dans la même partition, et permet la reprise des jobs suspendus. Configurez le réglage OverSubscribe sur FORCE pour toutes les partitions dans lesquelles le time-slicing doit avoir lieu. La planification gang est effectuée indépendamment pour chaque partition, donc si vous souhaitez uniquement le time-slicing par OverSubscribe, sans aucune préemption, il n'est pas recommandé de configurer des partitions avec des nœuds qui se chevauchent. Le time-slicing n'aura pas lieu entre les jobs sur différentes partitions.

Si PreemptType=preempt/qos est configuré et si le(s) job(s) préempté(s) et le job préempteur se trouvent dans la même partition, alors ils partageront les ressources avec le planificateur Gang (time-slicing). Si ce n'est pas le cas (c'est-à-dire si les jobs préemptés et le préempteur sont dans des partitions différentes), alors les jobs préemptés resteront suspendus jusqu'à la fin du préempteur.

NOTE : Les jobs suspendus ne libéreront pas les GRES. Les jobs de priorité supérieure ne pourront pas préempter pour accéder aux GRES.

Par exemple, si le facteur d'utilisation était de 2, chaque seconde d'unité TRESBillingUnit qu'un job a exécuté compterait pour 2. Si le drapeau UsageFactorSafe n'est pas activé et que AccountingStorageEnforce n'inclut pas Safe, les jobs seront planifiés tant que les limites ne sont pas atteintes, mais pourraient être tués en raison de limites.

Voir AccountingStorageEnforce dans la page man de slurm.conf.

La valeur par défaut est 1. Pour effacer une valeur existante, réglez une nouvelle valeur de -1.

Un flottant représentant la plus faible part équitable d'une association autorisée à exécuter un job. Utilisez sshare pour voir les parts actuelles sur le système. Pour effacer une valeur existante, réglez une nouvelle valeur de -1.

INFORMATIONS TRES

Les ressources traçables (TRES) sont utilisées dans de nombreuses limites de QOS ou d'association (GrpTRES* / MaxTRES*). Lors de la définition des limites, une ou plusieurs affectations "TRES=valeur" séparées par des virgules peuvent être spécifiées.

Chaque TRES peut être l'un des éléments par défaut de Slurm (par exemple, cpu, mem, node) ou une ressource générique définie. Vous pouvez voir la liste des ressources disponibles en exécutant sacctmgr show tres.

Chaque TRES a une limite différente, par exemple, "GrpTRES=cpu=16,mem=32G" établirait 2 limites différentes : une pour 16 CPUs et une autre pour 32 Go de mémoire.

La définition d'une nouvelle valeur pour un type TRES n'affecte aucun autre type TRES précédemment spécifié. Par exemple, sur la même entité que ci-dessus, une affectation ultérieure de "GrpTRES=gres/gpu=2" aboutira à "GrpTRES=cpu=16,mem=32G,gres/gpu=2" appliquée à cette entité.

Pour supprimer une limite, affectez -1 au type TRES dont la limite doit être supprimée, par exemple, "GrpTRES=cpu=-1" supprimerait uniquement la limite TRES cpu, résultant en "GrpTRES=mem=32G,gres/gpu=2" sur cette entité.

À partir de Slurm 25.11, une affectation TRES peut utiliser l'opérateur += ou -= pour ajouter ou soustraire de la valeur précédemment définie pour ce TRES, par exemple, "GrpTRES=mem-=8G,gres/gpu+=2" aboutirait à "GrpTRES=mem=24G,gres/gpu=4" sur cette entité.

NOTE : Lorsqu'il s'agit de mémoire en tant que TRES, les unités par défaut sont les Mo. Un suffixe G, T ou P peut être ajouté pour spécifier une limite dans des unités plus grandes.

NOTE : Le TRES de facturation est calculé à partir des TRESBillingWeights d'une partition. Il est calculé temporairement pendant la planification pour chaque partition afin de faire respecter les limites de facturation TRES. La valeur finale du TRES de facturation est calculée après que le job a alloué des ressources et peut être vue dans les sorties de scontrol show jobs et sacct.

Chaque fichier contient des données d'association Slurm pour un seul cluster. Depuis la version 25.05, les informations QOS sont incluses dans le fichier d'exportation. Les commentaires peuvent être ajoutés au fichier avec le caractère #. Chaque ligne d'information doit commencer par l'un des cinq titres : QOS, Cluster, Parent, Account ou User. Après le titre suit un espace, un trait, un espace, la valeur de l'entité, puis les spécifications. Les spécifications sont séparées par des deux-points. Si une variable, telle qu'un nom d'organisation, contient un espace, entourez le nom de guillemets simples ou doubles.

sacctmgr dump/load doit être exécuté en tant qu'administrateur Slurm ou root. Si vous utilisez sacctmgr load sur une base de données sans aucune association, elle doit être exécutée en tant que root (car il n'y a pas encore d'utilisateurs dans la base de données).

dump

Exporter les associations de cluster de la base de données vers un fichier. Si aucun fichier n'est donné, un sera généré, en utilisant le nom du cluster pour le nom du fichier. Ce fichier sera créé dans le répertoire de travail courant.

Pour créer un fichier avec les informations d'association, vous pouvez exécuter :

sacctmgr dump tux file=tux.cfg

File=
Spécifier un fichier pour enregistrer les données du fichier plat. Si le nom du fichier n'est pas spécifié, il utilise par défaut le nom de fichier clustername.cfg.

Charger les associations de cluster dans la base de données. Les associations importées seront rapprochées avec celles existantes.

Pour charger un fichier précédemment créé, vous pouvez exécuter :

Supprimer ce qui était déjà là et recommencer à zéro avec ces informations. Sans aucune option, cela ne supprimera que le cluster ainsi que ses associations. Aucun compte, utilisateur ou QOS ne sera supprimé. Cela accepte également une liste d'autres options à supprimer, séparées par des virgules. Celles-ci incluent 'account', 'qos' et 'user'. Si vous souhaitez supprimer les comptes, les qos et les utilisateurs ainsi que le cluster et les associations, donnez l'entrée clean=account,qos,user.
Cluster=
Spécifier un nom différent pour le cluster que celui contenu dans le fichier.
File=
Spécifier un fichier plat à charger.

FONCTIONNALITÉ D'ARCHIVAGE

Sacctmgr a la capacité d'archiver dans un fichier plat et/ou de charger ces données si nécessaire plus tard. L'archivage est généralement effectué par le slurmdbd et il est fortement recommandé de le faire uniquement via sacctmgr si vous comprenez parfaitement ce que vous faites. Pour les options de slurmdbd, voir "man slurmdbd" pour plus d'informations. Le chargement de données dans la base de données peut être effectué à partir de ces fichiers pour visualiser des données anciennes ou régénérer des données agrégées. Pour plus d'informations sur la configuration d'un serveur d'archivage, voir https://slurm.schedmd.com/accounting.html#archive.

archive dump

Exportez les données de comptabilité dans un fichier. Les données ne seront pas archivées à moins que l'option de purge correspondante ne soit incluse dans cette commande ou dans slurmdbd.conf. Cette opération ne peut pas être annulée une fois exécutée. Si l'une des options suivantes n'est pas spécifiée lors de l'appel de sacctmgr, la valeur configurée dans slurmdbd.conf est utilisée.

SYNOPSIS

PERFORMANCE

L'exécution de sacctmgr envoie un appel de procédure distante à slurmdbd. Si suffisamment d'appels provenant de sacctmgr ou d'autres commandes client Slurm qui envoient des appels de procédure distante au démon slurmdbd arrivent en même temps, cela peut entraîner une dégradation des performances du démon slurmdbd, entraînant potentiellement un déni de service.

N'exécutez pas sacctmgr ou d'autres commandes client Slurm qui envoient des appels de procédure distante à slurmdbd à partir de boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à sacctmgr au minimum nécessaire pour les informations que vous essayez de collecter.

NOTE : Il y a un ordre pour configurer les associations de comptabilité. Vous devez définir les clusters avant d'ajouter des comptes et vous devez ajouter des comptes avant de pouvoir ajouter des utilisateurs.

$ sacctmgr create cluster tux
$ sacctmgr create account name=science fairshare=50
$ sacctmgr create account name=chemistry parent=science fairshare=30
$ sacctmgr create account name=physics parent=science fairshare=20
$ sacctmgr create user name=adam cluster=tux account=physics fairshare=10
$ sacctmgr delete user name=adam cluster=tux account=physics
$ sacctmgr delete user name=adam cluster=tux account=science partition=\"\"
$ sacctmgr delete account name=physics cluster=tux
$ sacctmgr modify user where name=adam cluster=tux account=physics set maxjobs=2 maxwall=30:00
$ sacctmgr add user brian account=chemistry
$ sacctmgr list associations cluster=tux format=Account,Cluster,User,Fairshare tree withd
$ sacctmgr list transactions Action="Add Users" Start=11/03-10:30:00 format=Where,Time
$ sacctmgr dump cluster=tux file=tux_data_file
$ sacctmgr load tux_data_file

Le compte d'un utilisateur ne peut pas être modifié directement. Une nouvelle association doit être créée pour l'utilisateur avec le nouveau compte. Ensuite, l'association avec l'ancien compte peut être supprimée.

Lors de la modification d'un objet, placer les mots-clés 'set' et 'where' (facultatif) est essentiel pour effectuer correctement les actions ci-dessous. Par convention, tout ce que vous placez avant set sera utilisé comme quantificateur. Si vous souhaitez placer un quantificateur après le mot-clé 'set', vous devez utiliser le mot-clé 'where'. Ce qui suit est incorrect :

$ sacctmgr modify user name=adam set fairshare=10 cluster=tux

Cela produira une erreur car la ligne ci-dessus se lit modifier l'utilisateur adam définir fairshare=10 et cluster=tux. L'une des commandes suivantes est correcte :

$ sacctmgr modify user name=adam cluster=tux set fairshare=10
$ sacctmgr modify user name=adam set fairshare=10 where cluster=tux

Lors de la modification de qos pour quelque chose, utilisez uniquement l'opérateur '=' lorsque vous souhaitez explicitement définir le qos sur une valeur. Dans la plupart des cas, vous voudrez utiliser l'opérateur '+=' ou '-=' pour ajouter ou supprimer du qos existant déjà en place.

Si un utilisateur a déjà des qos de normal, standby pour un parent ou si cela a été explicitement défini, vous devriez utiliser qos+=expedite pour ajouter ceci à la liste de cette manière.

Si vous souhaitez ajouter le qos expedite uniquement à un compte et/ou cluster spécifique, vous pouvez le faire en les spécifiant dans la ligne sacctmgr.

$ sacctmgr modify user name=adam set qos+=expedite

ou

$ sacctmgr modify user name=adam acct=this cluster=tux set qos+=expedite

$ sacctmgr show qos format=name

Listez toutes les associations dans le cluster.
