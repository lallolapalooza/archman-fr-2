NOM

sane-mustek_pp - Backend SANE pour scanners Mustek à port parallèle

DESCRIPTION

La bibliothèque sane-mustek_pp implémente un backend SANE (Scanner Access Now Easy) qui fournit un accès aux scanners Mustek à port parallèle et à leurs versions OEM.

Il existe 2 classes de scanners Mustek à port parallèle : les scanners classiques à CCD (dispositif à cathode froide) et les scanners à CIS (capteur d'image de contact).

La version actuelle de ce backend prend en charge les scanners de type CCD et de type CIS.

Veuillez noter que ce backend est toujours en cours de développement. Certains modèles ne sont actuellement pas pris en charge et certains ne le seront peut-être jamais car le protocole de communication est encore inconnu (par ex. SE 12000 P).

Certains scanners fonctionnent plus rapidement lorsque le mode EPP/ECP est activé dans le BIOS. Le mode EPP peut cependant entraîner des blocages sur certains systèmes Linux. Si c'est votre cas, vous pouvez soit désactiver ECP/EPP dans votre BIOS, soit le désactiver dans le backend lui-même (voir OPTIONS GLOBALES).

Notez que le backend doit être exécuté en tant que root ou avoir les droits d'accès appropriés à /dev/parport* si le support de libieee1284 est compilé. Pour autoriser l'accès utilisateur au scanner, exécutez le backend via l'interface réseau (voir saned(8) et sane-net(5)). Notez également que le backend ne prend pas en charge le partage de port parallèle, c'est-à-dire que si vous essayez d'imprimer pendant la numérisation, votre ordinateur peut planter. Pour activer le partage de port parallèle, vous devez activer libieee1284(3) lors de la compilation. Vous devrez peut-être également activer explicitement le backend dans votre fichier dll.conf. Il suffit de supprimer la marque dièse devant la ligne "mustek_pp".

DÉFINITION DU PÉRIPHÉRIQUE

Ce backend permet de définir et configurer plusieurs périphériques via le fichier mustek_pp.conf (même simultanément, à condition qu'ils soient connectés à des ports parallèles différents). Veuillez vous assurer de modifier ce fichier avant d'utiliser le backend.

Un périphérique peut être défini comme suit :

scanner <nom> <nom du port> <pilote>

où

<nom> est un nom arbitraire pour le périphérique, facultativement entouré de guillemets doubles, par exemple "LifeTec 9350".

<nom du port> est le nom du port parallèle auquel le périphérique est connecté. Si libieee1284 est utilisé pour la communication avec le port (configuration par défaut), les noms de port valides sont parport0, parport1 et parport2.

Si le backend est configuré pour l'E/S brute (ancienne configuration), les adresses de port doivent être utilisées à la place des noms de port : 0x378, 0x278 ou 0x3BC. Le mappage des ports parallèles (lp0, lp1 et lp2) à ces adresses peut varier selon les versions du noyau Linux. Par exemple, si vous utilisez un noyau 2.2.x ou supérieur et que vous n'avez qu'un seul port parallèle, ce port est nommé lp0 quelle que soit l'adresse de base. Cependant, ce backend nécessite l'adresse de base de votre port. Si vous n'êtes pas sûr du port auquel votre scanner est connecté, consultez votre /etc/conf.modules, /etc/modules.conf et/ou /proc/ioports.

Si vous n'êtes pas sûr du port à utiliser, vous pouvez utiliser la valeur magique * pour sonder votre scanner.

<pilote> est le pilote à utiliser pour ce périphérique. Les pilotes actuellement disponibles sont :

cis600 : pour 600 CP, 96 CP et versions OEM
cis1200 : pour 1200 CP et versions OEM
cis1200+ : pour 1200 CP+ et versions OEM
ccd300 : pour 600 IIIE P et version OEM
Choisir le mauvais pilote peut endommager votre scanner !
En particulier, utiliser les paramètres 1200CP sur un 600CP peut être nuisible. Si le scanner commence à faire un bruit fort, éteignez-le immédiatement !!!

L'utilisation du pilote cis600 sur un 1200CP ou un 1200CP+ n'est probablement pas dangereuse. Le pilote cis1200+ fonctionne également pour le 1200CP, et l'utilisation du pilote cis1200 sur un 1200CP+ entraînera typiquement des scans qui ne couvrent que la moitié de la largeur de la zone de numérisation (également pas dangereux).

En cas de doute sur le modèle exact de votre version OEM, vérifiez la résolution optique dans le manuel ou sur la boîte : le 600CP a une résolution optique maximale de 300x600 DPI, tandis que le 1200CP et le 1200CP+ ont une résolution optique maximale de 600x1200 DPI.

Exemples :

scanner "LifeTec 9350" 0x378 cis1200

scanner Mustek_600CP 0x378 cis600

scanner Mustek_600IIIEP * ccd300

En cas de doute sur le port à utiliser, ou si votre scanner est détecté, vous pouvez utiliser sane-find-scanner -p pour sonder tous les ports configurés.

CONFIGURATION

Le contenu du fichier mustek_pp.conf est une liste de définitions de périphériques et d'options de périphériques qui correspondent aux scanners Mustek. Les lignes vides et les lignes commençant par une marque dièse (#) sont ignorées. Les options ont le format suivant :

option <nom> [<valeur>]

Selon la nature de l'option, une valeur peut être présente ou non. Les options s'appliquent toujours à la définition du scanner qui les précède. Il n'y a pas d'options globales. Les options sont également spécifiques au pilote : tous les pilotes ne prennent pas en charge toutes les options possibles.

Options communes

engine_delay : définit le délai en millisecondes entre les commandes envoyées au moteur du scanner. La valeur par défaut est de 10 ms. Pour certains scanners, il faut peut-être réduire cette valeur, par ex. à 1 ou 5 ms.
red_balance : définit la valeur de balance rouge pour la calibration en couleur. La valeur par défaut est de 1.0. Vous pouvez expérimenter avec des valeurs comprises entre 0.5 et 2.0.
green_balance : définit la valeur de balance verte pour la calibration en couleur. La valeur par défaut est de 1.0. Vous pouvez expérimenter avec des valeurs comprises entre 0.5 et 2.0.
blue_balance : définit la valeur de balance bleue pour la calibration en couleur. La valeur par défaut est de 1.0. Vous pouvez expérimenter avec des valeurs comprises entre 0.5 et 2.0.
gamma : définit la valeur gamma pour la calibration en couleur. La valeur par défaut est de 1.0. Les valeurs typiques vont de 0.5 à 2.0.
calibration_skip : cette option peut être utilisée pour éviter les problèmes de calibration. Si elle est activée (valeur 1), la première phase de calibration est ignorée. Pour de nombreux scanners CIS, cela peut être nécessaire. La valeur par défaut est 0.
swap : Permet d'échanger les octets d'entrée/sortie du port. Ceci est nécessaire pour certains scanners qui envoient leurs données dans un ordre incorrect. La valeur par défaut est 0.
reverse_port : Permet d'inverser les bits de certains registres du port. Ceci est nécessaire pour certains scanners OEM. La valeur par défaut est 0.
led_error_check : Active un contrôle d'erreur basé sur les LED du scanner. Utile pour certains modèles, désactivez-le si cela pose des problèmes. La valeur par défaut est 1.
epp_ecp : permet d'activer ou de désactiver le mode EPP/ECP. La valeur par défaut est 1 (activé). Si vous rencontrez des problèmes de blocage du système, essayez de le désactiver (valeur 0).
parity_address : permet de spécifier l'adresse du registre de parité pour le scanner. Les valeurs possibles sont 0x378, 0x278, 0x3bc. La valeur par défaut est généralement 0x378.

Options spécifiques au pilote

ccd300 : le pilote ccd300 supporte les options suivantes :
  • scan_speed : définit la vitesse de balayage en mm/s. La valeur par défaut est 3.0. Les valeurs possibles vont de 0.1 à 5.0.
  • x_offset : définit un décalage en X pendant la calibration. La valeur par défaut est 0.
  • y_offset : définit un décalage en Y pendant la calibration. La valeur par défaut est 0.
  • y_compensation : compense les erreurs dues aux mouvements du moteur. La valeur par défaut est 0.
  • x_compensation : compense les erreurs dues aux mouvements du moteur. La valeur par défaut est 0.

Exemple pour 600 IIIE P :

scanner Mustek_600IIIEP 0x378 ccd300
        x_offset 10
        y_offset 5
        scan_speed 4.5

ÉMULATION

Les scanners Mustek sont souvent vendus sous diverses marques OEM. Ce backend essaie de détecter automatiquement le type de scanner et d'utiliser le pilote approprié. Si cela échoue, vous pouvez essayer d'utiliser un pilote d'un scanner similaire ou spécifier un modèle dans le fichier de configuration.

Les options suivantes peuvent être utilisées pour forcer une émulation particulière :

force_scanner_model : force un modèle de scanner spécifique. Les valeurs possibles sont : 600CP, 1200CP, 1200CP+, 600IIIEP.
force_asic_id : force un ID ASIC spécifique. Les valeurs possibles sont 1013, 1015, 1505.

Exemple pour forcer l'émulation 1200CP :

scanner "Mustek 1200 CP OEM" 0x378 cis1200 force_scanner_model 1200CP

CONFIGURATION AU DÉMARRAGE

Si le scanner n'est pas détecté au démarrage du système, vous pouvez essayer de charger le module parport_pc avec l'option io pour lui spécifier l'adresse de base de votre port parallèle. Par exemple, pour le port LPT1 :

Ajoutez la ligne suivante à /etc/modules.conf ou /etc/modprobe.conf :

options parport_pc io=0x378

Si vous avez plusieurs ports parallèles, vous pouvez spécifier plusieurs adresses :

options parport_pc io=0x378,0x278,0x3bc

Après avoir modifié ce fichier, vous devrez peut-être recharger le module ou redémarrer votre système.

RÉGLAGE ET DÉPANNAGE DU SCANNER

Si vous rencontrez des problèmes tels que des images rayées, des couleurs incorrectes ou une vitesse de numérisation lente, voici quelques pistes :

  • Vitesse de numérisation : La vitesse par défaut peut ne pas convenir à tous les scanners. Essayez de régler l'option scan_speed (pour le pilote ccd300) ou d'ajuster engine_delay.
  • Calibration : Les scanners CIS sont particulièrement sensibles à la calibration. Essayez d'activer l'option calibration_skip pour ignorer la première phase de calibration. Vous pouvez également ajuster les options red_balance, green_balance, blue_balance et gamma pour corriger les couleurs.
  • Problèmes d'alimentation : Assurez-vous que le scanner est correctement alimenté. Certains scanners à port parallèle consomment beaucoup d'énergie et peuvent nécessiter une alimentation externe.
  • Mode EPP/ECP : Essayez d'activer ou de désactiver le mode EPP/ECP via l'option epp_ecp dans le fichier de configuration. Certains systèmes sont instables avec EPP activé.
  • Partage de port : Si vous utilisez le scanner avec un autre périphérique sur le même port parallèle (par exemple, une imprimante), vous pourriez rencontrer des problèmes. Assurez-vous que le partage de port est correctement configuré (voir la section DESCRIPTION).
  • Bruits forts : Si le scanner émet des bruits forts et inhabituels (clics répétitifs, etc.), éteignez-le immédiatement et débranchez-le. Cela peut indiquer un problème mécanique grave.

bw <valeur>
Valeur de discrimination noir/blanc à utiliser lors du balayage lineart. Les valeurs de pixel inférieures à cette valeur sont supposées être noires, les valeurs supérieures sont supposées être blanches.

Options du pilote CIS

top_adjust <valeur>
Ajustement vertical de l'origine, exprimé en millimètre (nombre à virgule flottante). Cette option peut être utilisée pour calibrer la position de l'origine, dans certaines limites. Notez que les scanners CIS sont probablement sensibles à la température, et qu'une certaine imprécision peut être difficile à éviter. Des différences de décalage entre les exécutions de l'ordre de 1 à 2 mm ne sont pas inhabituelles.
Valeur par défaut : 0.0
Minimum : -5.0
Maximum : 5.0

Exemple : option top_adjust -2.5

slow_skip
Désactive le saut rapide vers le début de la zone de numérisation. Lorsque la zone à numériser ne commence pas à l'origine, le pilote tentera de déplacer la tête de numérisation vers le début de la zone de numérisation à la vitesse la plus rapide possible. Sur certains modèles, cela peut ne pas fonctionner, entraînant de grandes imprécisions (jusqu'à plusieurs centimètres). En réglant cette option, le pilote est forcé d'utiliser une vitesse normale lors du saut, ce qui peut contourner les problèmes de précision. Actuellement, il n'y a pas de modèles pour lesquels ces problèmes d'imprécision sont connus pour se produire.

Par défaut, le saut rapide est utilisé.

Exemple : option slow_skip

engine_delay <valeur>
Dans des circonstances normales, il suffit au pilote d'attendre le signal du scanner indiquant que le moteur est stable, avant qu'une nouvelle commande moteur ne puisse être transmise. Dans de rares cas, certains scanners et/ou chipsets de port parallèle semblent empêcher une détection fiable de l'état du moteur. Par conséquent, les commandes moteur sont transmises trop tôt et le mouvement de la tête de numérisation devient peu fiable. Des imprécisions allant jusqu'à 10 cm sur toute la plage de numérisation verticale ont été signalées. Pour contourner ce problème, l'option engine_delay peut être définie. Si elle est définie, le pilote attend un temps supplémentaire après chaque commande moteur, égal au paramètre engine_delay, exprimé en millisecondes. En pratique, un engine_delay de 1 ms est généralement suffisant. Le délai maximum est de 100 ms.

Notez que chaque ms de délai supplémentaire peut ajouter jusqu'à 14 secondes au temps total de numérisation (résolution la plus élevée), donc une valeur aussi petite que possible est préférée.

Valeur par défaut : 0
Minimum : 0
Maximum : 100

Exemple : option engine_delay 1

Options du pilote CCD

top <valeur>
Nombre de lignes de numérisation à sauter pour atteindre le début de la zone de numérisation. Le nombre peut être un entier positif quelconque. Les valeurs que je connais sont 47 et 56.

Valeur par défaut : 47
Minimum : 0
Maximum : aucun

Exemple : option top 56

waitbank <valeur>
Le nombre d'utilisateurs à attendre pour un changement de banque. Vous ne devriez pas toucher à cette valeur en réalité. Peut être un entier positif quelconque.

Valeur par défaut : 700
Minimum : 0
Maximum : aucun

Exemple : option waitbank 700

OPTIONS GLOBALES

Vous pouvez contrôler le comportement général du backend sane-stek_pp via des options globales qui précèdent toute définition de scanner dans le fichier mustek_pp.conf.

Actuellement, il n'y a qu'une seule option globale :

Options globales

no_epp
Désactive le mode EPP du port parallèle : contourne un bug connu dans le code Linux parport. Activez cette option si le backend se bloque lors de la tentative d'accès au port parallèle en mode EPP.

Valeur par défaut : utilisation de l'EPP

Exemple : option no_epp

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes *NIX, les répertoires sont séparés par un deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") puis dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" entraînerait la recherche des répertoires tmp/config, ., et /etc/sane.d (dans cet ordre).
SANE_DEBUG_MUSTEK_PP
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Par exemple, une valeur de 128 demande l'affichage de toutes les sorties de débogage. Des niveaux inférieurs réduisent la verbosité. 
niveau   sortie de débogage
--------------------------------------
 0      rien
 1      erreurs
 2      avertissements & erreurs mineures
 3      informations supplémentaires
 4      informations de débogage
 5      flux de code (pas encore supporté)
 6      informations de débogage spéciales
SANE_DEBUG_SANEI_PA4S2
Cette variable définit le niveau de débogage pour l'interface SANE pour le chipset Mustek A4S2. Notez que l'activation de cette option spammera votre terminal avec environ un million de lignes de sortie de débogage.
