sane(7) Accès Facile aux Scanners SANE sane(7)

NOM

sane - Scanner Access Now Easy : API pour accéder aux scanners

DESCRIPTION

SANE est une interface de programmation d'applications (API) qui fournit un accès standardisé à tout matériel de scanner d'images matricielles. L'interface standardisée permet d'écrire un seul pilote pour chaque périphérique scanner au lieu d'un pilote pour chaque scanner et application.

Bien que SANE soit principalement destiné à un environnement UNIX, la norme a été soigneusement conçue pour permettre l'implémentation de l'API sur pratiquement n'importe quel matériel ou système d'exploitation.

Cette page de manuel fournit un résumé des informations disponibles sur SANE.

Si vous avez des difficultés à faire détecter votre scanner, lisez la section PROBLEMS.

TERMINOLOGIE

Une application qui utilise l'interface SANE est appelée un frontend SANE. Un pilote qui implémente l'interface SANE est appelé un backend SANE. Un méta-backend fournit des moyens de gérer un ou plusieurs autres backends.

PAQUETS LOGICIELS

Le paquet sane-backends contient les backends, la documentation, le support réseau et le frontend en ligne de commande scanimage(1). Les frontends xscanimage(1), xcam(1), et scanadf(1) sont inclus dans le paquet sane-frontends. Les deux paquets peuvent être téléchargés depuis la page d'accueil de SANE (http://www.sane-project.org/). Des informations sur d'autres frontends et backends peuvent également être trouvées sur la page d'accueil de SANE.

INFORMATIONS GENERALES

Les sections suivantes fournissent de courtes descriptions et des liens vers plus d'informations sur plusieurs aspects de SANE. Un nom avec un numéro entre parenthèses (par exemple sane-dll(5)) pointe vers une page de manuel. Dans ce cas, man 5 sane-dll affichera la page. Les entrées telles que /usr/share/doc/sane/README sont des références à des fichiers texte qui ont été copiés dans le répertoire de documentation SANE (/usr/share/doc/sane/) lors de l'installation. Tout le reste est une URL vers une ressource sur le web.

Page d'accueil de SANE
Des informations sur tous les aspects de SANE, y compris un tutoriel et un lien vers la FAQ SANE, peuvent être trouvées sur la page d'accueil de SANE : http://www.sane-project.org/.
Listes des périphériques SANE
Les listes de périphériques SANE contiennent des informations sur l'état du support SANE pour un périphérique spécifique. Si votre scanner n'y est pas répertorié (supporté ou non supporté), veuillez nous contacter. Voir la section COMMENT POUVEZ-VOUS AIDER SANE pour plus de détails. Il existe des listes pour les versions spécifiques de SANE, pour la version de développement actuelle et un moteur de recherche : http://www.sane-project.org/sane-supported-devices.html. Les listes sont également installées sur votre système dans /usr/share/doc/sane/.
Liste de diffusion SANE
Il existe une liste de diffusion pour discuter de la norme SANE et de ses implémentations : sane-devel. Malgré son nom, la liste n'est pas seulement destinée aux développeurs, mais aussi aux utilisateurs. Il existe également d'autres listes pour des sujets spéciaux. Cependant, pour les utilisateurs, sane-devel est la bonne liste. Comment s'abonner et se désabonner : http://www.sane-project.org/mailing-lists.html.
Canal IRC SANE
Le canal IRC (Internet Relay Chat) #sane se trouve sur le réseau Freenode (irc.libera.chat). Il sert à discuter des problèmes SANE, à parler du développement et à discuter en général de sujets liés à SANE. Avant de demander de l'aide, veuillez lire la documentation mentionnée sur cette page de manuel. Le sujet du canal est également utilisé pour annoncer les problèmes avec l'infrastructure SANE (listes de diffusion, serveur web, etc.).
Compilation et installation de SANE
Consultez /usr/share/doc/sane/README et les fichiers README spécifiques au système d'exploitation pour obtenir des informations sur la compilation et l'installation de SANE.
Configuration SCSI
Pour des informations sur divers systèmes et contrôleurs SCSI, voir sane-scsi(5).
Configuration USB
Pour des informations sur la configuration USB, voir sane-usb(5).

MISCELLANEOUS BACKENDS

dll
Implements a SANE backend that provides access to an arbitrary number of other SANE backends by dynamic loading. See sane-dll(5).

The SANE network daemon saned(8) provides access to scanners located on different computers in connection with the sane-net(5) backend. See saned(8).
pnm
PNM image reader pseudo-backend. The purpose of this backend is primarily to aid in debugging of SANE frontends. See sane-pnm(5).
pint
Supports scanners that use the PINT (Pint Is Not Twain) device driver. The PINT driver is being actively developed on the OpenBSD platform, and has been ported to a few other *NIX-like operating systems. See sane-pint(5).
test
Tests frontends and the SANE installation. It provides test pictures and various test options. See sane-test(5).
v4l
Provides generic access to video cameras and similar equipment using the V4L (Video for Linux) API. See sane-v4l(5).

Also, have a look at the backend information page at http://www.sane-project.org/sane-supported-devices.html and the list of projects in /usr/share/doc/sane/PROJECTS.

CHANGING THE TOP-LEVEL BACKEND

By default, all SANE backends (drivers) are loaded dynamically by the sane-dll meta backend. If you have any questions about the dynamic loading, read sane-dll(5). SANE frontends can also be linked to other backends directly by copying or linking a backend to libsane.so in /usr/lib/sane.

DEVELOPER'S DOCUMENTATION

It's not hard to write a SANE backend. It can take some time, however. You should have basic knowledge of C and enough patience to work through the documentation and find out how your scanner works. Appended is a list of some documents that help to write backends and frontends.

The SANE standard defines the application programming interface (API) that is used to communicate between frontends and backends. It can be found at http://sane-project.gitlab.io/standard/ .

There is some more information for programmers in /usr/share/doc/sane/backend-writing.txt. Most of the internal SANE routines (sanei) are documented using doxygen: http://www.sane-project.org/sanei/. Before a new backend or frontend project is started, have a look at /usr/share/doc/sane/PROJECTS for projects that are planned or not yet included into the SANE distribution and at our bug-tracking system: http://www.http://www.sane-project.org/bugs.html.

There are some links on how to find out about the protocol of a scanner: http://www.meier-geinitz.de/sane/misc/develop.html.

If you start writing a backend or frontend or any other part of SANE, please contact the sane-devel mailing list for coordination so that work is not duplicated.

PROBLEMS

If your device isn't found but you know that it is supported, make sure that it is detected by your operating system. For SCSI and USB scanners, use the sane-find-scanner(1) utility. It prints one line for each scanner it has detected and some comments (#). If sane-find-scanner(1) finds your scanner only as root but not as normal user, the permissions for the device files are not adjusted correctly. If the scanner isn't found at all, the operating system hasn't detected it and may need some help. Depending on the type of your scanner, read sane-usb(5) or sane-scsi(5). If your scanner (or other device) is not connected over the SCSI bus or USB, read the backend's manual page for details on how to set it up.

Is your scanner detected by the operating system but not by SANE? Try scanimage -L. If the scanner is not found, check that the backend's name is mentioned in /etc/sane.d/dll.conf. Some backends are commented out by default. Remove the comment sign for your backend in this case. Also some backends aren't compiled at all if one of their prerequisites are missing. Examples include dc210, dc240, canon_pp, hpsj5s, gphoto2, pint, qcam, v4l, net, sm3600, snapscan, pnm. If you need one of these backends and it isn't available, read the build instructions in the README file and the individual manual pages of the backends.

PROBLEMS

SANE essaie de trouver la plupart des scanners automatiquement, mais certains ne peuvent pas être configurés correctement sans l'intervention de l'administrateur. De plus, sur certains systèmes d'exploitation, la détection automatique peut ne pas fonctionner. Consultez la page de manuel du backend pour plus de détails.

Si votre scanner n'est toujours pas trouvé, essayez de définir les différentes variables d'environnement disponibles pour aider au débogage. Les variables d'environnement sont documentées dans les pages de manuel pertinentes. Par exemple, pour obtenir le maximum d'informations de débogage lors du test d'un scanner SCSI Mustek, définissez les variables d'environnement SANE_DEBUG_DLL, SANE_DEBUG_MUSTEK et SANE_DEBUG_SANEI_SCSI à 128, puis lancez scanimage -L. Les messages SANE_DEBUG_DLL indiquent si le backend sane-mustek(5) a été trouvé et chargé. Les messages SANE_DEBUG_MUSTEK expliquent ce que fait le backend, tandis que le débogage SANE_DEBUG_SCSI montre le traitement de bas niveau. Si vous ne parvenez pas à comprendre ce qui se passe en examinant attentivement les messages, contactez la liste de diffusion sane-devel pour obtenir de l'aide (voir SIGNALER LES BOGUES ci-dessous).

Maintenant que votre scanner est trouvé par scanimage -L, essayez de faire une numérisation : scanimage >image.pnm. Cette commande lance une numérisation pour le scanner par défaut avec les paramètres par défaut. Toutes les options disponibles sont listées en exécutant scanimage --help. Si la numérisation échoue avec un message d'erreur, activez le débogage comme mentionné ci-dessus. Peut-être que le fichier de configuration nécessite des ajustements, par exemple pour définir le chemin d'accès à un firmware requis par certains scanners. Consultez la page de manuel du backend pour plus de détails. Si vous ne parvenez pas à trouver la cause du problème, contactez sane-devel.

Pour vérifier que les bibliothèques SANE sont correctement installées, vous pouvez utiliser le backend de test, même si vous n'avez pas de scanner ou d'autre périphérique SANE :

scanimage -d test -T

Vous devriez obtenir une liste de tests PASSés. Vous pouvez faire de même avec votre backend en remplaçant "test" par le nom de votre backend.

Maintenant que la numérisation avec scanimage (1) fonctionne et que vous souhaitez utiliser l'une des interfaces graphiques comme xsane(1), xscanimage(1), ou quiteinsane(1), mais que ces interfaces ne détectent pas votre scanner ? Une raison possible est que vous avez installé deux versions de SANE. Par exemple, la version installée par votre distribution dans /usr et une que vous avez installée à partir des sources dans /usr/local/. Assurez-vous qu'une seule version est installée. Une autre raison possible est que le chargeur dynamique de votre système ne trouve pas les bibliothèques SANE. Pour Linux, assurez-vous que /etc/ld.so.conf contient /usr/local/lib et ne contient pas /usr/local/lib/sane. Voir aussi la documentation des interfaces.
