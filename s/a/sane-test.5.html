sane-test(5) Accès facile aux scanners SANE sane-test(5)

NOM

sane-test - Backend SANE pour tester les interfaces

DESCRIPTION

La bibliothèque sane-test implémente un backend SANE (Scanner Access Now Easy) qui permet de tester l'installation SANE et les interfaces SANE. Elle donne accès à un nombre (presque) illimité de périphériques virtuels. Il n'y a pas de support pour les vrais scanners ou caméras. Cependant, le backend simule la numérisation et la configuration des options.

L'objectif n'est pas seulement de trouver des bugs dans les interfaces, mais aussi de montrer toutes les capacités de SANE. C'est pourquoi sane-test implémente des fonctions et des options qui ne se trouvent pas (ou rarement) dans d'autres backends.

Le backend est commenté dans /etc/sane.d/dll.conf, donc il faut soit supprimer le caractère de commentaire, soit appeler explicitement le backend. Par exemple, scanimage -d test ou xscanimage test.

OPTIONS DE MODE SCAN

L'option mode sélectionne le mode de numérisation (Gris ou Couleur).

L'option depth détermine le nombre de bits par échantillon (1, 8 ou 16). Gardez à l'esprit que cette valeur se réfère à l'échantillon, pas au pixel. Ainsi, depth=16 donne 48 bits par pixel en mode couleur. Les combinaisons les plus courantes sont mode=Gris, depth=1 pour le tracé, mode=Gris, depth=8 pour le niveau de gris, et mode=Couleur, depth=8 pour le mode couleur. La combinaison de couleur et de mode 1 bit est assez obscure (8 couleurs) mais autorisée par la norme SANE. Cependant, la signification des bits n'est pas définie. Actuellement, 1 = haute intensité et 0 = basse intensité est utilisé.

La définition de l'option hand-scanner fait que le backend de test se comporte comme un scanner manuel. Les scanners manuels ne connaissent pas la hauteur de l'image à l'avance. Au lieu de cela, ils renvoient une hauteur de -1. La définition de cette option permet de tester si une interface peut gérer cela correctement. Cette option active également une largeur fixe de 11 cm.

La définition de l'option three-pass simule un scanner à trois passages. Les anciens scanners couleur avaient besoin de numériser l'image une fois par couleur (rouge/vert/bleu) pour obtenir l'image complète. Par conséquent, dans ce mode, trois trames individuelles sont transmises en mode couleur.

L'option three-pass-order permet de modifier l'ordre des trois trames (voir l'option three-pass ci-dessus). Une interface devrait supporter tous les ordres.

L'option resolution définit la résolution de l'image en points par pouce.

L'option source peut être utilisée pour simuler un chargeur automatique de documents (ADF). Après 10 numérisations, l'ADF sera « vide ».

OPTIONS SPÉCIALES

L'option test-picture permet de définir l'image renvoyée à l'interface. Alors que « Blanc uni » et « Noir uni » sont assez évidents, les autres options nécessitent quelques explications supplémentaires. Les motifs de couleur sont utilisés pour déterminer si tous les modes et leurs couleurs sont correctement représentés par l'interface. La grille doit apparaître identique dans tous les modes et résolutions. Un tableau de toutes les images de test peut être trouvé à : http://www.meier-geinitz.de/sane/test-backend/test-pictures.html.

Si l'option invert-endianness est définie, les octets de poids fort et de poids faible des données d'image dans les modes 16 bits sont échangés. Cette option peut être utilisée pour tester les modes 16 bits des interfaces, par exemple si l'interface utilise la bonne endianness.

Si l'option read-limit est définie, la quantité maximale de données transférées à chaque appel de sane_read() est limitée.

L'option read-limit-size définit la limite pour l'option read-limit. Une limite basse ralentit la numérisation. Elle peut être utilisée pour détecter des erreurs dans l'interface dues à des hypothèses erronées sur la taille du tampon ou des problèmes de synchronisation.

L'option read-delay active le délai des données vers l'interface.

L'option read-delay-duration sélectionne le nombre de microsecondes d'attente du backend après chaque transfert de tampon. Cette option est utile pour trouver des bugs liés à la synchronisation, surtout lorsqu'elle est utilisée sur le réseau.

Si l'option read-return-value est différente de « Default », le statut sélectionné sera renvoyé par chaque appel de sane_read(). Ceci est utile pour tester la gestion des statuts SANE par l'interface.

Si l'option ppl-loss est différente de 0, elle détermine le nombre de pixels « perdus » à la fin de chaque ligne. Cela signifie que les lignes sont complétées avec des données inutilisées.

L'option fuzzy-parameters sélectionne que des paramètres flous (inexacts) sont renvoyés tant que la numérisation n'a pas été démarrée. Cette option peut être utilisée pour tester si l'interface utilise les paramètres qu'elle a reçus avant le démarrage de la numérisation (ce qu'elle ne devrait pas faire).

L'option non-blocking détermine si l'E/S non bloquante pour sane_read() doit être utilisée si elle est supportée par l'interface.

Si l'option select-fd est définie, le backend propose un descripteur de fichier de sélection pour détecter si sane_read() renverra des données.

Si l'option enable-test-options est définie, une liste assez grande d'options pour tester les divers types d'options SANE est activée.

L'option print-options peut être utilisée pour afficher une liste de toutes les options sur la sortie d'erreur standard.

OPTIONS GÉOMÉTRIE

L'option tl-x détermine la position x du coin supérieur gauche de la zone de numérisation.

L'option tl-y détermine la position y du coin supérieur gauche de la zone de numérisation.

L'option br-x détermine la position x du coin inférieur droit de la zone de numérisation.

L'option br-y détermine la position y du coin inférieur droit de la zone de numérisation.

OPTIONS TEST BOOLÉENNES

Il y a 6 options de test booléennes au total. Chaque option est numérotée. (3/6) signifie : c'est l'option 3 sur 6. Le schéma de numérotation est destiné à faciliter la détection des options non affichées par l'interface (en raison du manque de support ou de bugs).

L'option bool-soft-select-soft-detect (1/6) est une option de test booléenne qui possède des capacités de sélection douce et de détection douce (et avancées). C'est juste une option booléenne normale.

L'option bool-hard-select-soft-detect (2/6) est une option de test booléenne qui possède des capacités de sélection dure et de détection douce (et avancées). Cela signifie que l'option ne peut pas être définie par l'interface mais par l'utilisateur (par exemple, en appuyant sur un bouton sur le périphérique).

L'option bool-hard-select (3/6) est une option de test booléenne qui possède des capacités de sélection dure (et avancées). Cela signifie que l'option ne peut pas être définie par l'interface mais par l'utilisateur (par exemple, en appuyant sur un bouton sur le périphérique) et ne peut pas être lue par l'interface.

L'option bool-soft-detect (4/6) est une option de test booléenne qui possède des capacités de détection douce (et avancées). Cela signifie que l'option est en lecture seule.

L'option bool-soft-select-soft-detect-emulated (5/6) est une option de test booléenne qui possède des capacités de sélection douce, de détection douce et émulée (et avancées).

L'option bool-soft-select-soft-detect-auto (6/6) est une option de test booléenne qui possède des capacités de sélection douce, de détection douce et automatique (et avancées). Cette option peut être définie automatiquement par le backend.

OPTIONS TEST ENTIÈRES

Il y a 7 options de test entières au total.

L'option int (1/7) est une option de test entière sans unité ni contrainte définie.

L'option int-constraint-range (2/7) est une option de test entière avec une unité « pixel » et une contrainte de plage définie. Le minimum est 4, le maximum 192, et le quant est 2.

L'option int-constraint-word-list (3/7) est une option de test entière avec une unité « bits » et une liste de mots de contrainte définie.

L'option int-constraint-array (4/7) est une option de test entière avec une unité « mm » et utilisant un tableau sans contraintes.

L'option int-constraint-array-constraint-range (5/7) est une option de test entière avec une unité « mm » et utilisant un tableau avec une contrainte de plage. Le minimum est 4, le maximum 192, et le quant est 2.

L'option int-constraint-array-constraint-word-list (6/7) est une option de test entière avec une unité « pourcentage » et utilisant un tableau ou une liste de mots comme contrainte.

L'option int-inexact (7/7) est une option de test entière qui incrémente la valeur demandée et renvoie le drapeau SANE_INFO_INEXACT.

OPTIONS TEST FIXES

Il y a 3 options de test fixées

OPTIONS TEST CHAÎNES

Il y a 2 options de test de chaînes.

L'option string (1/2) est une chaîne de caractères qui peut être définie par l'utilisateur.

L'option string-constraint-list (2/2) est une option de chaîne qui ne peut être définie que par l'utilisateur à partir d'une liste de choix.

OPTIONS TEST FONCTIONS

Il y a 6 options de test de fonction.

L'option button-press (1/6) est une option de fonction qui simule une pression de bouton.

L'option long-delay (2/6) est une option de fonction qui simule un long délai.

L'option print-frame (3/6) est une option de fonction qui imprime la trame avant de la transmettre.

L'option auto-test (4/6) est une option de fonction qui déclenche un auto-test du périphérique.

L'option test-all (5/6) est une option de fonction qui exécute tous les tests.

L'option quit (6/6) est une option de fonction qui quitte le mode de test.

FICHIERS

/etc/sane.d/dll.conf

EXEMPLES

Pour tester le backend sane-test avec les paramètres par défaut, vous pouvez exécuter la commande :

scanimage --device-name test

Pour tester l'option resolution et l'option mode :

scanimage --device-name test -r 300 --mode color

Pour tester l'option test-picture et l'option invert-endianness :

scanimage --device-name test --test-picture=grid --invert-endianness

VOIR AUSSI

sane(7), sane-dll(5), scanimage(1), xscanimage(1)

sane-test.5.fr — SANE test backend

NOM

sane-test — pilote SANE pour le backend de test

DESCRIPTION

Le pilote test est un pilote SANE qui simule un scanner. Il est très utile pour tester les applications SANE sans avoir besoin d'un matériel réel. Le pilote test expose un certain nombre d'options différentes qui simulent les fonctionnalités d'un scanner réel. Celles-ci sont décrites ci-dessous.

OPTIONS MODE SCAN

Il y a 7 options de mode scan au total.

L'option mode (1/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan.

L'option mode-force-invalid (2/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. La valeur maximale est toujours supérieure à la valeur minimale.

L'option mode-constraint-list (3/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. Les valeurs sont uniquement 150, 300 et 600.

L'option mode-constraint-range (4/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. La valeur minimale est 100, la valeur maximale est 600 et le pas est de 10.

L'option mode-constraint-invalid (5/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. La valeur maximale est toujours inférieure à la valeur minimale.

L'option mode-constraint-word-list (6/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. Les valeurs sont uniquement 100, 200 et 300.

L'option mode-constraint-not-word-list (7/7) est une option de mode scan. Elle permet de sélectionner la résolution du scan. Les valeurs autorisées sont toutes sauf 100, 200 et 300.

OPTIONS SPÉCIALES

Il y a 2 options spéciales au total.

L'option special (1/2) est une option spéciale. Elle permet de régler la luminosité.

L'option special-auto (2/2) est une option spéciale. Elle permet de régler la luminosité.

OPTIONS GÉOMÉTRIE

Il y a 6 options de géométrie au total.

L'option geometry (1/6) est une option de géométrie. Elle permet de régler la résolution.

L'option geometry-auto (2/6) est une option de géométrie. Elle permet de régler la résolution.

L'option geometry-auto-setting (3/6) est une option de géométrie. Elle permet de régler la résolution.

L'option geometry-constraint-range (4/6) est une option de géométrie. Elle permet de régler la résolution. La valeur minimale est 100, la valeur maximale est 600 et le pas est de 10.

L'option geometry-constraint-word-list (5/6) est une option de géométrie. Elle permet de régler la résolution. Les valeurs sont uniquement 150, 300 et 600.

L'option geometry-constraint-invalid (6/6) est une option de géométrie. Elle permet de régler la résolution. La valeur maximale est toujours inférieure à la valeur minimale.

OPTIONS TEST BOOLÉEN

Il y a 3 options de test booléen au total.

L'option bool (1/3) est une option de test booléen avec une valeur booléenne.

L'option bool-constraint-list (2/3) est une option de test booléen avec une contrainte de liste de mots. Les valeurs sont uniquement 0 et 1.

L'option bool-constraint-range (3/3) est une option de test booléen avec une contrainte de plage. Minimum est 0, maximum 1 et quant 1.0.

OPTIONS TEST ENTIER

Il y a 3 options de test entier au total.

L'option int (1/3) est une option de test entier sans unité et sans contrainte.

L'option int-constraint-range (2/3) est une option de test entier avec une unité milliseconde et une contrainte de plage. Minimum est 100, maximum 30000 et quant 50.

L'option int-constraint-word-list (3/3) est une option de test entier sans unité et avec une contrainte de liste de mots.

OPTIONS TEST FIXE

Il y a 3 options de test fixe au total.

L'option fixed (1/3) est une option de test fixe sans unité et sans contrainte définie.

L'option fixed-constraint-range (2/3) est une option de test fixe avec l'unité microseconde et une contrainte de plage définie. Minimum est -42.17, maximum 32767.9999, et quant est 2.0.

L'option fixed-constraint-word-list (3/3) est une option de test fixe sans unité et avec une contrainte de liste de mots définie.

OPTIONS TEST CHAÎNE

Il y a 3 options de test chaîne au total.

L'option string (1/3) est une option de test chaîne sans contrainte.

L'option string-constraint-string-list (2/3) est une option de test chaîne avec une contrainte de liste de chaînes.

L'option string-constraint-long-string-list (3/3) est une option de test chaîne avec une contrainte de liste de chaînes. Contient quelques entrées supplémentaires...

OPTION TEST BOUTON

L'option button (1/1) est une option de test de bouton. Imprime du texte...

FICHIERS

/etc/sane.d/test.conf
Le fichier de configuration du backend (voir aussi la description de SANE_CONFIG_DIR ci-dessous). Les valeurs initiales de la plupart des options SANE de base peuvent être configurées dans ce fichier. Un modèle contenant toutes les valeurs par défaut est fourni avec ce backend. L'une des valeurs les plus intéressantes peut être number_of_devices. Elle peut être utilisée pour vérifier la capacité du frontend à afficher une longue liste d'appareils. Les valeurs de configuration concernant la résolution et la géométrie peuvent être utiles pour tester la gestion des grandes tailles de fichiers.
/usr/lib/sane/libsane-test.a
La bibliothèque statique implémentant ce backend.
/usr/lib/sane/libsane-test.so
La bibliothèque partagée implémentant ce backend (présente sur les systèmes qui prennent en charge le chargement dynamique).

ENVIRONNEMENT

SANE_CONFIG_DIR
Cette variable d'environnement spécifie la liste des répertoires qui peuvent contenir le fichier de configuration. Sur les systèmes \*NIX, les répertoires sont séparés par un deux-points (`:'), sous OS/2, ils sont séparés par un point-virgule (`;'). Si cette variable n'est pas définie, le fichier de configuration est recherché dans deux répertoires par défaut : d'abord, le répertoire de travail courant (".") et ensuite dans /etc/sane.d. Si la valeur de la variable d'environnement se termine par le caractère séparateur de répertoire, alors les répertoires par défaut sont recherchés après les répertoires explicitement spécifiés. Par exemple, définir SANE_CONFIG_DIR à "/tmp/config:" aurait pour résultat que les répertoires tmp/config, ., et /etc/sane.d seraient recherchés (dans cet ordre).
SANE_DEBUG_TEST
Si la bibliothèque a été compilée avec le support de débogage activé, cette variable d'environnement contrôle le niveau de débogage pour ce backend. Des niveaux de débogage plus élevés augmentent la verbosité de la sortie.

Exemple : export SANE_DEBUG_TEST=4
