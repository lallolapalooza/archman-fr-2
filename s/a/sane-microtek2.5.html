sane-microtek2(5) SANE Scanner Access Now Easy sane-microtek2(5)

NOM

sane-microtek2 - Backend SANE pour les scanners Microtek avec jeu de commandes SCSI-2

DESCRIPTION

La bibliothèque sane-microtek2 implémente un backend SANE (Scanner Access Now Easy) qui permet d'accéder aux scanners Microtek avec un jeu de commandes SCSI-2. Ce backend peut être considéré comme alpha à bêta. Certains modèles de scanners fonctionnent bien, d'autres non.

Il existe un backend différent pour les scanners Microtek avec jeu de commandes SCSI-1. Voir sane-microtek(5) pour les détails.

Et il y a des progrès partiels pour le ScanMaker 3600. Voir http://sourceforge.net/projects/sm3600.

Actuellement, les scanners suivants sont connus pour fonctionner positivement avec ce backend :

Fabricant     ID produit        Remarque
--------------------------------------------------------------------
Microtek   E3+               Port parallèle et SCSI
Microtek   X6                SCSI
Microtek   X6EL              SCSI
Microtek   X6USB             USB
Microtek   ScanMaker V300    Port parallèle et SCSI
Microtek   ScanMaker V310    Port parallèle et SCSI
Microtek   ScanMaker V600    Port parallèle et SCSI
Microtek   ScanMaker 330     SCSI
Microtek   ScanMaker 630     SCSI
Microtek   ScanMaker 636     SCSI
Microtek   ScanMaker 9600XL  SCSI ; mode à plat uniquement ?
Microtek   Phantom 330CX     Port parallèle
Microtek   SlimScan C3       Port parallèle
Microtek   SlimScan C6       USB
Microtek   Phantom 636       SCSI
Microtek   Phantom 636CX     Port parallèle
Microtek   V6USL             SCSI et USB
Microtek   V6UPL             USB ; instable
Microtek   X12USL            SCSI ; couleur 8 bits uniquement, en cours de développement
Vobis      HighScan          SCSI (modèles basés sur E3+)
Scanport   SQ300             Port parallèle ?
Scanport   SQ4836            SCSI
Scanpaq    SQ2030            Port parallèle

Des informations supplémentaires peuvent être trouvées sur http://www.sane-project.org/.

Si vous possédez un scanner Microtek autre que ceux listés ci-dessus, il peut fonctionner ou non avec SANE ! Parce que des scanners identiques sont vendus sous différents noms dans différents pays, votre modèle peut être équivalent à l'un des modèles ci-dessus.

Les scanners à port parallèle fonctionnent avec les modules du noyau ppscsi + onscsi. Voir http://cyberelk.net/tim/parport/ppscsi.html et http://penguin-breeder.org/kernel/download/.

Les scanners USB fonctionnent avec le module du noyau microtek. Vous devrez peut-être ajouter les codes de vendeur et de modèle à microtek.c s'ils n'y sont pas encore listés.

Les scanners à port parallèle et USB nécessitent le support SCSI générique, alors vérifiez que vous avez chargé les modules scsi_mod et sg !

Si vous essayez votre scanner pour la première fois, gardez un œil sur lui. S'il reçoit des commandes qu'il ne comprend pas, la tête de scan peut aller au-delà de la zone de balayage. Le scanner fait alors des bruits étranges. Dans ce cas, éteignez immédiatement le scanner ou débranchez son câble d'alimentation pour éviter tout dommage !

Si votre scanner est différent des modèles mentionnés ci-dessus et qu'il fonctionne, veuillez en informer l'auteur. Il serait utile d'ajouter un fichier journal à ces informations (création du fichier journal : voir ci-dessous).

Si votre scanner ne fonctionne pas correctement, vous devriez également créer un fichier journal et l'envoyer à l'auteur. Il utilisera les informations pour améliorer le backend et potentiellement faire fonctionner votre scanner.

Comment créer le fichier journal ?

- mettez la ligne

"option dump 2" dans votre fichier microtek2.conf ou changez le "option dump" existant en "2"
- dans un terminal (bash) tapez

"export SANE_DEBUG_MICROTEK2=30" et ensuite
"scanimage -l0 -t0 -x100 -y20 2>scan.log >sout.pnm"
Vous obtenez deux fichiers : scan.log contient le fichier journal et sout.pnm l'image scannée (s'il y a eu quelque chose de scanné). Compressez-les avant de les envoyer.

OPTIONS DE FRONTEND

Ce backend active dynamiquement les options pour le frontend, qui sont supportées par le scanner en fonction du mode de numérisation et d'autres options. Les options non supportées sont désactivées.

Les options suivantes sont supportées par le pilote sane-microtek2 :

Numérisations couleur, niveaux de gris, tramage et dessin au trait.

Contrôle de la luminosité, du point moyen, de l'ombre, du contraste, de la luminosité, du temps d'exposition, de la correction gamma, du seuil (en fonction du mode de numérisation et des capacités du scanner)

Adaptateur de support transparent, chargeur automatique de documents

Des options supplémentaires peuvent être activées ou désactivées dans le fichier microtek2.conf. Voir la section configuration de cette page man.

NOMS DE PÉRIPHÉRIQUE

Ce backend attend des noms de périphériques de la forme :

spécial

Où spécial est le nom du périphérique spécial qui correspond au scanner, sous forme de chemin UNIX. Le nom du périphérique spécial doit être un périphérique SCSI générique ou un lien symbolique vers un tel périphérique. Sous Linux, un tel nom de périphérique pourrait être /dev/sga ou /dev/sge par exemple.

CONFIGURATION

Le fichier de configuration pour ce backend se trouve dans /etc/sane.d/microtek2.conf.

Son contenu est une liste de noms de périphériques qui correspondent aux scanners Microtek avec interface SCSI-2. Les lignes vides et les lignes commençant par un croisillon (#) sont ignorées.

Le fichier de configuration peut également contenir des options. Les options globales valides pour tous les périphériques sont placées avant les noms des périphériques. Les options spécifiques au périphérique sont placées sous le nom du périphérique. Notez que, à l'exception de l'option dump <n> et de l'option strip-height <n>, l'entrée dans le fichier microtek2.conf active uniquement l'option correspondante pour être affichée dans le frontend. Là, dans le frontend, vous pouvez activer et désactiver les options. Actuellement, les options suivantes sont supportées :

option dump <n>
option strip-height <n>
option no-backtrack-option <on/off>
option lightlid-35 <on/off>
option toggle-lamp <on/off>
option lineart-autoadjust <on/off>
option backend-calibration <on/off>
option colorbalance-adjust <on/off>

option dump <n> active l'impression d'informations supplémentaires sur les commandes SCSI envoyées au scanner vers stderr. Cette option est principalement utile à des fins de débogage. Cette option doit être une option globale et est mieux placée en haut du fichier microtek2.conf.

Si n=1, le contenu des blocs de commandes et les résultats pour la commande INQUIRY et READ SCANNER ATTRIBUTES sont imprimés sur stderr.

Si n=2, le contenu des blocs de commandes pour toutes les autres commandes SCSI est également imprimé sur stderr. Si n=3, le contenu de la table gamma est également imprimé. Si n=4, toutes les données de numérisation sont en plus imprimées sur stderr.

La valeur par défaut est n=1.

option strip-height <n> , où <n> est un nombre à virgule flottante, limite la quantité de données lues du scanner avec une seule commande de lecture. L'unité est le pouce et <n> est par défaut à 1.0, si cette option n'est pas définie dans le fichier de configuration. Si moins de <n> pouces de données tiennent dans le tampon SCSI, alors la valeur plus petite est utilisée et cette option n'a aucun effet.

Si votre système dispose d'un grand tampon SCSI et que vous souhaitez utiliser tout le tampon, augmentez la valeur de <n>. Par exemple, si <n> est réglé sur 14.0, aucune restriction ne s'applique aux scanners avec une zone de balayage de taille lettre, légale ou A4.

Les options suivantes activent ou désactivent des options de frontend supplémentaires. Si une option est définie sur <on>, une option appropriée apparaîtra dans le frontend.

option no-backtrack-option <on/off> empêche la tête du scanner de reculer entre les commandes de lecture. Cela accélère la numérisation. Essayez-le.

option lightlid-35 <on/off> Si vous utilisez l'adaptateur transparent LightLid-35, vous obtenez une option avancée qui éteint la lampe du scanner à plat pendant la numérisation.

option toggle-lamp <on/off> Vous obtenez un bouton dans le frontend où vous pouvez allumer et éteindre la lampe du scanner à plat.

option lineart-autoadjust <on/off> Vous pouvez indiquer au backend d'essayer de déterminer une bonne valeur pour le seuil du dessin au trait

sane-microtek2.5

NAME

sane-microtek2 - SANE backend for Microtek scanners

DESCRIPTION

The microtek2 backend is an interface library for Microtek scanners. This backend is a replacement for the older Microtek scanner backend which only supported firmware version 1.00.10. The microtek2 backend supports firmware version 1.00.10, 1.02.00 and 1.03.00 scanners. It should support all Microtek scanners that are supported by the older backend, and also some more recent models. It is recommended to use this backend instead of the older one.

The microtek2 backend is a front end to the firmware of the scanner. This means that all the image processing is done by the scanner. The backend just sends commands to the scanner and receives the scanned data.

The microtek2 backend uses the SANE SCSI device access library to communicate with the scanner. This means that the scanner must be accessible by the SANE SCSI library.

FRONTEND OPTIONS

This backend supports the following frontend options:

option lamp-speed <value>
Controls the speed of the lamp. The default value is 1.0. Larger values mean a faster lamp speed.
option lamp-intensity <value>
Controls the intensity of the lamp. The default value is 1.0. Larger values mean a higher intensity.
option lamp-delay <value>
Controls the delay before the lamp is turned on. The default value is 0.0. Larger values mean a longer delay.
option lamp-off-delay <value>
Controls the delay before the lamp is turned off. The default value is 0.0. Larger values mean a longer delay.
option strip-height <value>
Sets the height of the scanned strip. The default value is 1.0. Larger values mean a higher strip height.
option no-backtrack-option <on/off>
Disables the backtrack option. This option is enabled by default. If you have problems with your scanner, try disabling this option.
option lightlid-35 <on/off>
Enable the 35mm film adapter. If this option is enabled, the scanner will use the 35mm film adapter. This option is disabled by default.
option toggle-lamp <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have the lamp toggled on and off at the beginning of the scan. Try this option if you see vertical stripes in your pictures.
option lineart-autoadjust <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have the lineart mode adjusted automatically. Try this option if you see vertical stripes in your pictures.
option backend-calibration <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have calibrated the data by the backend. Try this option if you see vertical stripes in your pictures.
option colorbalance-adjust <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have corrected the color balance. If this option is enabled you get advanced options where you can balance the colors. And you will have a button to use the values that the firmware of the scanner provides.

A sample configuration file is shown below:

option dump 1
option strip-height 1.0
/dev/scanner
option no-backtrack-option on
# this is a comment
/dev/sge
option lightlid-35 on

This backend also supports the new configuration file format which makes it easier to detect scanners under Linux. If you have only one scanner it would be best to use the following configuration file for this backend:

option dump 1
option strip-height 14.0
option no-backtrack-option on
option backend-calibration on
option lightlid-35 on
option toggle-lamp on
option lineart-autoadjust on
option colorbalance-adjust off
scsi * * Scanner

In this case all SCSI-Scanners should be detected automatically because of the

scsi * * Scanner

line.

DEVICE NAMES

Configuration files can contain device names. These device names are used by the SANE SCSI library to access the scanner. The following device names are supported:

/dev/scanner
This is the default device name for scanners. If you have only one scanner, you can use this device name.
scsi
This keyword tells the SANE SCSI library to detect all SCSI scanners automatically. This is the recommended way to configure the backend if you have only one scanner.
/dev/sg0, /dev/sg1, ...
These are the device names for the SCSI generic devices. You can use these device names if you have multiple scanners and want to specify which scanner to use.
/dev/st0, /dev/st1, ...
These are the device names for the SCSI tape devices. Some scanners may be detected as tape devices. You can use these device names if your scanner is detected as a tape device.

CONFIGURATION

The configuration file for the microtek2 backend is /etc/sane.d/microtek2.conf. This file contains configuration options for the backend. The following options are supported:

option dump <on/off>
Enable or disable dumping of scanned data to a file. The default value is off.
option strip-height <value>
Sets the height of the scanned strip. The default value is 1.0. Larger values mean a higher strip height.
option no-backtrack-option <on/off>
Disables the backtrack option. This option is enabled by default. If you have problems with your scanner, try disabling this option.
option lightlid-35 <on/off>
Enable the 35mm film adapter. If this option is enabled, the scanner will use the 35mm film adapter. This option is disabled by default.
option toggle-lamp <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have the lamp toggled on and off at the beginning of the scan. Try this option if you see vertical stripes in your pictures.
option lineart-autoadjust <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have the lineart mode adjusted automatically. Try this option if you see vertical stripes in your pictures.
option backend-calibration <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have calibrated the data by the backend. Try this option if you see vertical stripes in your pictures.
option colorbalance-adjust <on/off>
Some scanners (e.g. Phantom 330CX and 636CX) need to have corrected the color balance. If this option is enabled you get advanced options where you can balance the colors. And you will have a button to use the values that the firmware of the scanner provides.

A sample configuration file is shown below:

/dev/scanner

FILES

The backend configuration file.
/usr/lib/sane/libsane-microtek2.a
The static library implementing this backend.
/usr/lib/sane/libsane-microtek2.so
The shared library implementing this backend (present on systems that support dynamic loading).

ENVIRONMENT

SANE_DEBUG_MICROTEK2
If the library was compiled with debug support enabled, this environment variable controls the debug level for this backend. E.g., a value of 255 requests all debug output to be printed. Smaller levels reduce verbosity. To see error messages on stderr set SANE_DEBUG_MICROTEK2 to 1 (Remark: The whole debugging levels should be better revised).
E.g. just say:
export SANE_DEBUG_MICROTEK2=128
