SQ(1) Commandes utilisateur SQ(1)

NOM

sq-key-subkey-add - Ajouter une nouvelle sous-clé à un certificat

SYNTAXE

sq key subkey add [OPTIONS]

DESCRIPTION

Ajoute une nouvelle sous-clé à un certificat.

Une sous-clé possède une ou plusieurs capacités.

`--can-sign` définit la capacité de signature, ce qui signifie que la clé peut être utilisée pour signer. `--can-authenticate` définit la capacité d'authentification, ce qui signifie que la clé peut être utilisée pour l'authentification (par exemple, en tant que clé SSH). `--can-certify` définit la capacité de certification, et signifie que la clé peut être utilisée pour faire des certifications tierces. Ces capacités peuvent être combinées.

`--can-encrypt=storage` définit la capacité de chiffrement de stockage, et signifie que la clé peut être utilisée pour le chiffrement de stockage. `--can-encrypt=transport` définit la capacité de chiffrement de transport, et signifie que la clé peut être utilisée pour le chiffrement de transport. `--can-encrypt=universal` définit les deux capacités de chiffrement de stockage et de transport, et signifie que la clé peut être utilisée pour le chiffrement de stockage et de transport. Les capacités de chiffrement ne doivent pas être combinées avec les capacités de signature ou d'authentification.

Normalement, `sq` demande à l'utilisateur un mot de passe pour chiffrer le matériel de clé secrète. Le mot de passe de la nouvelle sous-clé peut être différent des autres clés. En utilisant `--without-password`, `sq` ne demande pas de mot de passe, et ne protège pas la sous-clé par mot de passe.

Par défaut, une nouvelle sous-clé n'expire pas d'elle-même. Cependant, sa période de validité est limitée par celle du certificat. L'utilisation de l'argument `--expiration` permet de définir une date d'expiration différente.

`sq key subkey add` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Il définit l'heure de création de la sous-clé à l'heure spécifiée.

OPTIONS

Options de sous-commande

--can-authenticate
Ajouter une sous-clé capable d'authentification
--can-encrypt=BUT
Ajouter une sous-clé capable de chiffrement [défaut : universal]
Les sous-clés capables de chiffrement peuvent être marquées comme appropriées pour le chiffrement de transport, le chiffrement de stockage, ou les deux, c'est-à-dire universelles.
[valeurs possibles : transport, storage, universal]
--can-sign
Ajouter une sous-clé capable de signature
--cert=EMPREINTE|IDCLEF
Ajouter une sous-clé à la clé avec l'empreinte ou l'ID de clé spécifié
--cert-email=EMAIL
Ajouter une sous-clé à la clé où un ID utilisateur inclut l'adresse e-mail spécifiée
--cert-file=CHEMIN
Ajouter une sous-clé à la clé lue depuis CHEMIN
--cert-userid=IDUTILISATEUR
Ajouter une sous-clé à la clé avec l'ID utilisateur spécifié
--cipher-suite=SUITECHIFFREMENT
Sélectionner les algorithmes cryptographiques pour la sous-clé
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.cipher-suite`.
[défaut : cv25519]
[valeurs possibles : rsa2k, rsa3k, rsa4k, cv25519]
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date au format ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée se présente sous la forme `N[amjs]`, où les lettres représentent les années, mois, semaines, jours et secondes, respectivement. Alternativement, le mot-clé `never` ne définit pas de date d'expiration.
[défaut : never]
--new-password-file=FICHIERMOTDEPASSE
Fichier contenant le mot de passe pour chiffrer le matériel de clé secrète
Notez que l'intégralité du fichier de mot de passe sera utilisée, y compris les espaces blancs environnants comme un saut de ligne final.
--output=FICHIER
Écrire dans le FICHIER spécifié
Si non spécifié, et si le certificat a été lu à partir du magasin de certificats, importe le certificat modifié dans le magasin de clés. Si non spécifié, et si le certificat a été lu à partir d'un fichier, écrit le certificat modifié sur la sortie standard.
--without-password
Ne pas protéger le matériel de clé secrète de la sous-clé avec un mot de passe

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Ajouter une nouvelle sous-clé capable de signature à la clé d'Alice.

sq key subkey add --can-sign \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Pour la documentation complète, voir https://book.sequoia-pgp.org/.
