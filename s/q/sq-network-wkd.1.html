NOM

sq-network-wkd - Récupérer et publier des certificats via les Répertoires de Clés Web

SYNTAXE

sq network wkd search [OPTIONS] ADRESSE
sq network wkd publish [OPTIONS] DEST

DESCRIPTION

Récupérer et publier des certificats via les Répertoires de Clés Web (Web Key Directories - WKD).

Le Répertoire de Clés Web (WKD) est une méthode pour publier et récupérer des certificats depuis des serveurs web.

SOUS-COMMANDES

sq network wkd search

Récupère des certificats à partir d'un Répertoire de Clés Web.

Par défaut, tous les certificats retournés sont stockés dans le magasin de certificats local. Ceci peut être outrepassé en utilisant l'option `--output`.

Lorsqu'un certificat est récupéré d'un WKD et importé dans le magasin de certificats local, tous les User IDs ayant l'adresse e-mail recherchée sont certifiés avec une clé locale spécifique au WKD. Ce certificat proxy est à son tour certifié comme une autorité de certification (AC) de confiance minimale (niveau de confiance : 1 sur 120) par la racine de confiance locale. Le niveau de confiance de l'AC proxy WKD peut être ajusté en utilisant `sq pki link add` ou `sq pki link retract` de la manière habituelle.

sq network wkd publish

Publie des certificats dans un Répertoire de Clés Web.

Publie des certificats ou des mises à jour de certificats dans un Répertoire de Clés Web (WKD). Vous pouvez créer ou mettre à jour une hiérarchie WKD sur le système local en spécifiant un chemin comme destination.

Typiquement, un WKD est stocké sur un serveur web. Si `--rsync` est donné, cette commande gère les hiérarchies de répertoires WKD distants en utilisant rsync(1).

Pour insérer un nouveau certificat dans le WKD, utilisez `--cert`.

Toutes les mises à jour pour les certificats existant déjà dans le WKD sont automatiquement publiées.

Note : Pour mettre à jour une hiérarchie WKD, elle est d'abord copiée dans un emplacement temporaire sur la machine locale, les nouveaux certificats ou les mises à jour de certificats sont insérés dans la copie locale, et la hiérarchie est copiée à nouveau vers son emplacement d'origine. Comme il ne s'agit pas d'une opération atomique, il faut veiller à éviter les mises à jour concurrentes.

EXEMPLES

sq network wkd search

Récupérer le certificat d'Alice via WKD.

sq network wkd search alice@example.org

Récupérer les mises à jour pour tous les certificats connus via WKD.

sq network wkd search --all

sq network wkd publish

Créer une nouvelle hiérarchie WKD dans le répertoire local `public_html`, et insérer le certificat d'Alice.

sq network wkd publish --create \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--domain=example.org public_html

Ajouter le certificat de Bob à la hiérarchie WKD existante dans le répertoire local `public_html`.

sq network wkd publish \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--domain=example.org public_html

Ajouter tous les certificats avec un User ID authentifié dans example.org à la hiérarchie WKD existante.

sq network wkd publish --domain=example.org --all public_html

Rafraîchir tous les certificats dans la hiérarchie WKD existante dans le répertoire local `public_html` à partir du magasin de certificats.

sq network wkd publish --domain=example.org public_html
