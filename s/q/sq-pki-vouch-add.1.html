NOM

sq-pki-vouch-add - Certifier un identifiant utilisateur pour un certificat

SYNTAXE

sq pki vouch add [OPTIONS]

DESCRIPTION

Certifie un identifiant utilisateur pour un certificat.

En utilisant une certification, le détenteur d'une clé peut garantir que un autre certificat appartient légitimement à un identifiant utilisateur. Dans le contexte des e-mails, cela signifie que la même entité contrôle la clé et l'adresse e-mail. Ces types de certifications forment la base du Web de Confiance.

Cette commande émet le certificat avec la nouvelle certification. Le certificat mis à jour doit être distribué, de préférence en l'envoyant au titulaire du certificat pour approbation. Voir aussi `sq key approvals`.

Par défaut, une certification expire après 10 ans. En utilisant l'argument `--expiration`, des périodes de validité spécifiques peuvent être définies. Il permet de spécifier un point dans le temps où la validité prendra fin ou une durée de validité.

`sq pki vouch add` respecte le temps de référence défini par l'argument de haut niveau `--time`. Il définit le temps de création de la certification au temps de référence.

OPTIONS

Options de sous-commande

--add-email=EMAIL
Utiliser un identifiant utilisateur avec l'adresse e-mail spécifiée
L'identifiant utilisateur se compose uniquement de l'adresse e-mail. L'adresse e-mail n'a pas besoin d'apparaître dans un identifiant utilisateur auto-signé.
--add-userid=USERID
Utiliser l'identifiant utilisateur spécifié
L'identifiant utilisateur spécifié n'a pas besoin d'être auto-signé.
Comme l'utilisation d'un identifiant utilisateur qui n'est pas auto-signé est souvent une erreur, vous devez utiliser cette option pour l'accepter explicitement.
--all
Utiliser tous les identifiants utilisateurs auto-signés
--allow-non-canonical-userids
Ne pas rejeter les nouveaux identifiants utilisateurs qui ne sont pas sous forme canonique
Les identifiants utilisateurs canoniques sont de la forme `Nom (Commentaire) <localpart@example.org>`.
--amount=MONTANT
Définir le montant de confiance
Les valeurs entre 1 et 120 sont significatives. 120 signifie entièrement fiable. Les valeurs inférieures à 120 indiquent le degré de confiance. 60 est généralement utilisé pour une confiance partielle.
[défaut : plein]
--cert=EMPREINTE|IDCLE
Utiliser les certificats avec l'empreinte ou l'ID de clé spécifié(e)
--cert-file=CHEMIN
Lire les certificats depuis CHEMIN
--certifier=EMPREINTE|IDCLE
Créer la certification en utilisant la clé avec l'empreinte ou l'ID de clé spécifié(e)
--certifier-email=EMAIL
Créer la certification en utilisant la clé où un identifiant utilisateur inclut l'adresse e-mail spécifiée
--certifier-file=CHEMIN
Créer la certification en utilisant la clé lue depuis CHEMIN
--certifier-self
Créer la certification en utilisant votre clé de certification par défaut
Ceci utilise les certificats définis dans le fichier de configuration sous `pki.vouch.certifier-self` comme clé de certification.
Actuellement, il n'y a pas de clé de certification par défaut.
--certifier-userid=USERID
Créer la certification en utilisant la clé avec l'identifiant utilisateur spécifié
--email=EMAIL
Utiliser un identifiant utilisateur composé uniquement de l'adresse e-mail, si l'adresse e-mail apparaît dans un identifiant utilisateur auto-signé
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date au format ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée prend la forme `N[ymwds]`, où les lettres représentent respectivement les années, les mois, les semaines, les jours et les secondes. Alternativement, le mot-clé `never` ne définit pas d'heure d'expiration.
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `pki.vouch.expiration`.
[défaut : 10y]
--local
Faire de la certification une certification locale
Normalement, les certifications locales ne sont pas exportées.
--non-revocable
Marquer la certification comme non révocable
C'est-à-dire, vous ne pouvez pas révoquer cette certification plus tard. Ceci ne devrait normalement être utilisé qu'avec une expiration.
--output=FICHIER
Écrire dans FICHIER ou stdout si omis
--signature-notation NOM VALEUR
Ajouter une notation à la signature
Le nom d'une notation définie par l'utilisateur doit être de la forme `nom@a.domain.you.control.org`. Si le nom de la notation commence par `!`, alors la notation est marquée comme critique. Si un consommateur d'une signature ne comprend pas une notation critique, il ignorera la signature. La notation est marquée comme lisible par l'homme.
--userid=USERID
Utiliser l'identifiant utilisateur auto-signé spécifié
L'identifiant utilisateur spécifié doit être auto-signé.
--userid-by-email=EMAIL
Utiliser l'identifiant utilisateur auto-signé avec l'adresse e-mail spécifiée

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Alice certifie que Bob contrôle 3F68CB84CE537C9A et bob@example.org.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--email=bob@example.org

Alice certifie que Bob contrôle 3F68CB84CE537C9A et bob@bobs.lair.net, qui n'est pas un identifiant utilisateur auto-signé.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--add-email=bob@bobs.lair.net

VOIR AUSSI

sq(1), sq-pki(1), sq-pki-vouch(1).

Pour la documentation complète, voir https://book.sequoia-pgp.org/.
