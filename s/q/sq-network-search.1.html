NOM

sq-network-search - Récupérer des certificats en utilisant tous les services réseau pris en charge

SYNTAXE

sq network search [OPTIONS] REQUÊTE

DESCRIPTION

Récupérer des certificats en utilisant tous les services réseau pris en charge.

Cette commande tentera de localiser les certificats pertinents étant donné une requête, qui peut être une empreinte numérique, un ID de clé, une adresse e-mail ou une URL https. Elle peut également découvrir et importer des certificats liés à celui interrogé, tels que des certificats alternatifs, des certificats expirés ou des certificats révoqués.

La découverte de certificats liés est utile : les certificats alternatifs prennent en charge les rotations de clés, les certificats expirés permettent la vérification des signatures effectuées dans le passé, et la découverte de certificats révoqués est importante pour obtenir les informations de révocation. Le mécanisme PKI aidera à sélectionner le bon certificat, voir `sq pki`.

Par défaut, tous les certificats retournés sont stockés dans le magasin de certificats local. Ceci peut être remplacé en utilisant l'option `--output`.

Lorsqu'un certificat est récupéré à partir d'un serveur de clés de vérification (actuellement, cela est limité à une liste de serveurs connus : `hkps://keys.openpgp.org`, `hkps://keys.mailvelope.com`, et `hkps://mail-api.proton.me`), WKD, DANE, ou via https, et importé dans le magasin de certificats local, les User IDs sont également certifiés avec une clé locale spécifique au serveur. Ce certificat proxy est à son tour certifié comme une CA d'autorité de certification minimalement fiable (montant de confiance : 1 sur 120) par la racine de confiance locale. La confiance accordée à une CA de serveur de clés proxy peut être ajustée en utilisant `sq pki link add` ou `sq pki link retract` de la manière habituelle.

OPTIONS

Options de sous-commande

--all
Récupérer les mises à jour pour tous les certificats connus
--iterations=N
Itérer pour trouver des mises à jour et des certificats liés
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `network.search.iterations`.
[défaut : 3]
--output=FICHIER
Écrire dans FICHIER (ou stdout si omis) au lieu d'importer dans le magasin de certificats
--server=URI
Définir un serveur de clés à utiliser (peut être spécifié plusieurs fois)
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `network.keyserver.servers`.
[défaut : hkps://keys.openpgp.org, hkps://mail-api.proton.me, hkps://keys.mailvelope.com, hkps://keyserver.ubuntu.com, hkps://sks.pod01.fleetstreetops.com]
--use-dane=ACTIVATION
Utiliser DANE pour rechercher des certificats
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `network.search.use-dane`.
[défaut : true]
[valeurs possibles : true, false]
--use-wkd=ACTIVATION
Utiliser WKD pour rechercher des certificats
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `network.search.use-wkd`.
[défaut : true]
[valeurs possibles : true, false]

REQUÊTE
Récupérer le(s) certificat(s) en utilisant REQUÊTE
Il peut s'agir d'une empreinte numérique, d'un ID de clé, d'une adresse e-mail ou d'une URL https.

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Rechercher le certificat de signature maître de Qubes.

sq network search 427F11FD0FAA4B080123F01CDDFA1A3E36879494

Rechercher des certificats associés à une adresse e-mail.

sq network search alice@example.org
