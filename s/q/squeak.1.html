SQUEAK(1) Système Squeak Smalltalk SQUEAK(1)

NOM

squeak, inisqueak - machine virtuelle Unix Squeak et installeur

SYNTAXE

inisqueak
squeak [ option... ] [ image ] [ script [ argument... ] ]

DESCRIPTION

squeak est la machine virtuelle pour le système Squeak Smalltalk. Elle nécessite trois fichiers pour fonctionner correctement : un fichier image contenant un `snapshot' d'une session Squeak active, un fichier changes contenant le code source des méthodes modifiées dans l'image, et une copie (ou un lien) vers un fichier système partagé sources contenant le code source des méthodes qui n'ont pas été modifiées depuis la dernière incrémentation majeure de version.

Les fichiers image et changes contiennent l'état d'une session Squeak de l'utilisateur, qui est persistant entre les sessions consécutives. Des copies privées de ces fichiers sont donc normalement requises. Le script inisqueak vérifie que l'installation Squeak locale semble saine, puis copie les fichiers requis dans le répertoire courant. Si inisqueak ne rencontre aucun problème, il se terminera en exécutant squeak pour démarrer une session Squeak en utilisant les fichiers image et changes nouvellement copiés.

inisqueak doit être exécuté une seule fois, lors de la première utilisation de Squeak, pour créer une nouvelle session Squeak 'personnelle'. Ensuite, squeak doit être exécuté à chaque fois que cette session doit être reprise.

APPEL

inisqueak n'a pas d'options ou d'arguments. Il suffit de faire 'cd' dans le répertoire qui doit contenir les copies de travail des fichiers image et changes, puis de l'exécuter.

squeak accepte diverses options (décrites ci-dessous), puis un nom d'image optionnel (qui ne doit pas commencer par un signe moins '-'). Si un nom d'image est donné sur la ligne de commande, alors squeak essaie d'exécuter cette image. Sinon, squeak vérifie la variable d'environnement SQUEAK_IMAGE et, si elle est définie, utilise sa valeur comme nom de l'image à exécuter. Sinon, squeak recherche une image nommée 'squeak.image' dans le répertoire courant. Si le fichier image n'existe pas, alors squeak affiche un message indiquant quel fichier image il n'a pas pu trouver et se termine. Si l'extension '.image' manque dans l'argument image ou dans la valeur de la variable SQUEAK_IMAGE, elle sera ajoutée automatiquement.

L'argument image peut être suivi d'un nom de script. C'est le nom d'un 'document' qui doit contenir du code Smalltalk à exécuter au démarrage. Le document peut être soit le nom d'un fichier, soit une URL commençant par 'http:'. Tous les arguments qui apparaissent après le nom du script sont ignorés, mais sont mis à la disposition du script depuis Squeak via la méthode getSystemAttribute:. (Voir la section SCRIPTS ci-dessous.)

Si image est donné comme '--' alors squeak arrête immédiatement le traitement des arguments (et se comporte comme si image n'avait pas été spécifié). Ceci est utile pour spécifier un script (éventuellement avec des arguments de script) sans spécifier d'image explicite.

OPTIONS

Les options de ligne de commande se divisent en deux catégories : les options 'communes' qui sont reconnues par la VM de base et les options 'spécifiques' qui sont liées à un pilote d'affichage ou de son particulier. Les options communes seront toujours reconnues par squeak, tandis qu'une option spécifique donnée ne sera reconnue qu'après que squeak ait chargé le pilote auquel elle est liée. Reportez-vous à l'option '-vm' ci-dessous pour plus de détails.

Les options communes reconnues par squeak sont les suivantes :

-encoding enc
spécifie l'encodage de caractères interne à utiliser par Squeak. Cela affecte la traduction que la VM effectue lors de l'importation de texte (depuis le clavier ou via un 'copier-coller' depuis une sélection externe) ou de l'exportation de texte (copier du texte depuis Squeak vers une autre application, ou lors de la génération de noms de fichiers contenant des caractères spéciaux). Autrement dit, cela affecte la correspondance entre ce que Squeak affiche à l'écran et ce qu'il envoie à (ou reçoit de) applications externes. La valeur correcte dépend de la façon dont les polices internes de Squeak sont encodées. Les images actuelles sont livrées avec les polices traditionnelles de Mac 'New York' qui utilisent l'encodage Mac Roman, et c'est donc l'encodage interne par défaut. Si d'autres polices (provenant de X11 ou d'ailleurs) sont importées dans l'image et utilisées comme polices système, alors cette traduction par défaut donnera des résultats incorrects pour les marques diacritiques et les caractères spéciaux. Dans de tels cas, l'option -encoding peut être utilisée pour changer l'encodage interne, par exemple 
    -encoding ISO-8859-15

(alias Latin9) qui serait approprié pour bon nombre des polices conçues pour les langues européennes.

-help
imprime un bref résumé de la syntaxe de la ligne de commande, des options et des pilotes disponibles, puis quitte.
-memory size[mk]
demande qu'un tas fixe de size octets soit alloué pour l'image Squeak. Si le suffixe `k' est donné, alors l'argument est exprimé en kilo-octets. Si le suffixe `m' est donné, alors l'argument est exprimé en méga-octets. Cette option NE DEVRAIT PAS être utilisée, sauf s'il y a une bonne raison de le faire, car elle impose une limite arbitraire à la taille de la mémoire objet de Squeak.
-mmap size[mk]
demande qu'un tas variable d'au plus size octets soit alloué. (Les suffixes sont tels que décrits pour l'option '-memory'.) squeak allouera initialement un tas suffisamment grand pour contenir l'image, avec une petite marge. Si à tout moment Squeak nécessite plus de mémoire pour son image, alors un espace supplémentaire sera alloué dynamiquement. De même, lorsque la mémoire n'est plus nécessaire, elle sera désallouée et retournée au système. L'argument size place une limite supérieure à la taille que le tas peut atteindre de cette manière. squeak utilise un tas dynamique par défaut avec une taille maximale de 75% de la mémoire virtuelle disponible ou 1 giga-octet, selon le plus petit des deux.
-noevents
désactive le nouveau mécanisme d'entrée piloté par événements (image 2.8 et ultérieures). Cette option est uniquement utile pour tester la compatibilité ascendante avec les anciennes images et ne devrait pas être utilisée.
-notimer
désactive l'utilisation du minuteur d'intervalle pour le suivi du temps à basse résolution. (Si vous rencontrez des problèmes avec les entrées/sorties de fichiers, sonores ou de sockets signalant `appel système interrompu', l'activation de ce drapeau pourrait aider.)
-pathenc enc
spécifie l'encodage de caractères externe à utiliser par Squeak lors de l'accès au système de fichiers (chemins de fichiers et de répertoires). La valeur correcte dépend des caractéristiques de la plateforme locale. Si aucune conversion d'encodage ne doit être effectuée, cela devrait être défini sur le même encodage que Squeak utilise en interne (voir l'option -encoding). Sinon, ISO-8859-15 (alias Latin9) pourrait avoir du sens sur un système de fichiers prenant en charge les caractères 8 bits, et UTF-8 pour les systèmes de fichiers qui utilisent des noms de chemins basés sur Unicode. La valeur par défaut est UTF-8, ce qui est correct pour Mac OS X et les distributions GNU/Linux très récentes, et ce qui (dans un monde idéal) sera éventuellement adopté par toutes les variantes Unix.
-plugins path
spécifie un emplacement alternatif pour les plugins externes (collections de primitives nommées) et les pilotes (pour l'affichage et le son). L'argument path contient un motif dans lequel toute occurrence de `%n' sera remplacée par le nom du plugin ou du pilote en cours de chargement. Le path peut nommer un répertoire ou le plugin lui-même et peut être absolu ou relatif (par rapport au répertoire dans lequel squeak a été exécuté). Si un plugin ou un pilote ne peut pas être trouvé à l'emplacement spécifié par path, la recherche continue dans les emplacements par défaut.
-textenc enc
spécifie l'encodage de caractères externe à utiliser par Squeak lors de l'échange de texte du presse-papiers avec d'autres applications. La valeur par défaut est UTF-8 sur Mac OS X et ISO-8859-15 (alias Latin9) sur les autres systèmes Unix. Notez que les applications X11 demandant la sélection

Squeak reconnaît un sous-ensemble des noms d'encodage définis par l'IANA. (Si vous préférez utiliser le symbole de la monnaie internationale plutôt que le symbole de l'Euro dans le texte externe, vous pourriez vouloir régler ceci sur ISO-8859-1, alias Latin1.)

-version
affiche trois lignes ou plus d'informations sur la version, comme suit :
   •
l'architecture configurée pour la machine virtuelle au moment de la compilation, le numéro de `séquence' de compilation, l'heure et la date de compilation, et le nom (et la version, si connue) du compilateur utilisé pour compiler squeak ;
   •
les informations complètes de uname(1) pour l'hôte sur lequel la machine virtuelle a été compilée ;
   •
l'emplacement d'installation par défaut pour les plugins et les pilotes ;

Après avoir affiché ce qui précède, la machine virtuelle se termine.

-vm driver
demande à squeak de charger un pilote de son/affichage. Pour chaque appareil pris en charge, il existe un pilote correspondant que squeak charge lors de l'initialisation. Sauf indication contraire, squeak déterminera les pilotes par défaut appropriés à charger. Ce choix peut être outrepassé en utilisant cette option. L'argument driver est une liste d'une ou plusieurs 'affectations' de la forme

     classe=appareil

séparées par des espaces ou des virgules. Les combinaisons prises en charge sont actuellement :

   display=X11
pour afficher la fenêtre Squeak sur un serveur X Window System local ou distant.
   display=Quartz
pour afficher sur le bureau Mac OS X local.
   display=none
pour désactiver complètement l'affichage (et le clavier/la souris). (Ce pilote est principalement utile pour exécuter des applications 'serveur' dans Squeak.)
   sound=OSS
fournit une entrée et une sortie son via Open Sound System. (Si vous avez un appareil nommé '/dev/dsp', c'est probablement celui que vous voulez.)
   sound=MacOSX
fournit une entrée/sortie son via Core Audio sur Mac OS X.
   sound=NAS
fournit une E/S son via Network Audio System.
   sound=Sun
fournit du son sur le matériel Sun Microsystems.
   sound=none
désactive complètement le son. squeak ne tentera pas de lire ou d'enregistrer des sons lorsque ce pilote est chargé.
Notez que seuls les pilotes pertinents pour la plateforme locale seront disponibles. Tenter de charger un pilote non pris en charge entraînera la sortie de squeak avec un message d'erreur. Une liste des pilotes disponibles est affichée par l'option '-help'. Si un pilote particulier ne parvient pas à charger les bibliothèques système dont il dépend, il ne sera ni listé ni disponible au chargement à l'exécution.
Notez également que sur Mac OS X, les pilotes d'affichage X11 et Quartz sont pris en charge, bien que le premier refuse de se charger si les bibliothèques client X11 ne sont pas installées sur la machine locale. Le pilote Quartz se chargera volontiers (et Squeak s'exécutera comme une application à part entière) même lorsque squeak est appelé depuis la ligne de commande. Faites preuve de prudence lorsque vous êtes connecté à Mac OS X depuis une autre machine : oublier de définir DISPLAY avant d'essayer d'exécuter squeak sur l'affichage distant pourrait causer de l'embarras.

Les options spécifiques au pilote d'affichage X11 sont les suivantes :

-browserWindow id
spécifie l'id de la fenêtre que squeak doit utiliser pour son affichage. Cette option est destinée à être utilisée lorsque Squeak fonctionne comme un plugin de navigateur Web.
-display server
spécifie que Squeak doit se connecter au serveur d'affichage donné au lieu de rechercher dans la variable d'environnement DISPLAY (le comportement par défaut) pour trouver le nom du serveur à utiliser.
-cmdmod N
indique à la VM de mapper la touche modificatrice N du clavier au code modificatrice attendu par l'image pour la touche Commande.
-optmod N
indique à la VM de mapper la touche modificatrice N du clavier au code modificatrice attendu par l'image pour la touche Option.
-compositioninput
active la prise en charge d'une fenêtre de superposition dans laquelle des caractères individuels (par exemple, le hiragana japonais) sont composés avant d'être interprétés comme un seul caractère (par exemple, le kanji japonais) par l'image.
-xicfont font
indique à la VM d'utiliser la police nommée dans la fenêtre de superposition de composition.
-fullscreen
fait en sorte que la fenêtre Squeak occupe autant d'espace d'écran que possible. Implique '-notitle'.
-headless
désactive l'affichage graphique et l'entrée souris/clavier. Ce mode de fonctionnement est principalement utile pour les serveurs.
-iconic
demande au gestionnaire de fenêtres d'iconiser la fenêtre Squeak au démarrage.
-lazy
fait en sorte que Squeak 'dorme' chaque fois que la fenêtre principale est désinstallée. Ceci peut être utilisé si Squeak semble consommer du temps CPU lorsqu'il est inactif (ce qui ne devrait normalement pas être le cas). Notez que si cette option est active, lorsque la fenêtre Squeak est désinstallée, squeak ne répondra à aucun stimulus externe (sauf pour fournir la sélection X aux demandeurs, lorsque Squeak en est propriétaire).
-mapdelbs
mappe la touche Suppr sur Retour arrière. Retour arrière supprime le caractère à gauche du curseur et Suppr supprime normalement le caractère à droite du curseur. Avec cette option, Suppr se comportera comme Retour arrière. Le comportement de Retour arrière n'est pas modifié.
-noxdnd
désactive la prise en charge du protocole de glisser-déposer X.
-nointl
désactive la gestion des touches mortes sur les claviers internationaux. Sans cette option, la gestion des touches mortes est activée si LC_ALL ou LC_CTYPE est défini dans l'environnement.
-notitle
désactive la barre de titre de la fenêtre Squeak (si le gestionnaire de fenêtres la prend en charge). Cette option est implicite dans '-fullscreen'.
-swapbtn
inverse les boutons jaune et bleu. (Traditionnellement, le bouton rouge est à gauche, le jaune au milieu et le bleu à droite. Les noms colorés proviennent du Xerox Alto sur lequel Smalltalk a été implémenté pour la première fois.) Squeak mappe normalement les boutons X 1, 2 et 3 aux boutons rouge, jaune et bleu, dans cet ordre. Avec cette option, il mappe les boutons X 1, 2 et 3 aux boutons rouge, bleu et jaune.)
-xasync
fait en sorte que Squeak utilise des mises à jour d'affichage asynchrones. La machine virtuelle vide et synchronise normalement la connexion d'affichage à intervalles réguliers. L'utilisation de cette option désactive la synchronisation, qui ne sera effectuée que lorsque l'image la demandera explicitement.
-xshm
active l'utilisation de l'extension X Shared Memory sur les serveurs qui la prennent en charge. Cela peut améliorer considérablement les performances d'affichage, mais ne fonctionne que lorsque Squeak s'exécute sur le serveur.

Les options spécifiques au pilote d'affichage FBDev sont les suivantes :

-fbdev device
Utilise le périphérique de framebuffer donné device au lieu du défaut '/dev/fb0'.
-kbmap mapfile
Charge la carte du clavier à partir du fichier de carte donné mapfile au lieu de la lire à partir du noyau en cours d'exécution. Notez que squeak ne peut pas (actuellement) lire les fichiers de carte compressés ou 'raccourcis' (tels que trouvés dans /usr/share/keymaps ou /lib/kbd/keymaps). Pour générer un fichier de mappage de touches utilisable par squeak, exécutez le programme suivant depuis la console :

    dumpkeys -f -n --keys-only > key.map

Si squeak rencontre un problème lors de la tentative de chargement de mapfile, il affichera un message d'erreur et se terminera. Voir keymaps(5) pour plus d'informations sur le format du fichier de mappage de touches. Les programmes dumpkeys(1), loadkeys(1), et showkey(1) peuvent être utilisés pour modifier la carte du clavier avant de créer un fichier de mappage de touches pour squeak.

-msdev device
Utilise le périphérique de souris donné device au lieu du défaut. Le défaut est d'essayer '/dev/psaux', '/dev/input/mice' et '/dev/adbmouse', dans cet ordre, et d'utiliser le premier qui a un appareil physique connecté.
-msproto protocol
Utilise le protocole de souris donné protocol au lieu du défaut. Les protocoles pris en charge sont 'ps2' et 'adb'. Le défaut est 'ps2' pour les souris connectées à '/dev/psaux' ou '/dev/input/mice', et 'adb' pour les souris connectées à '/dev/adbmouse'.
-vtlock
Interdit le changement de VT, que la demande provienne du clavier ou d'un autre programme tel que chvt(1).
-vtswitch
Active le changement de VT par clavier. Notez que cette option est effectivement désactivée si l'option '-vtlock' est également activée.

Les options spécifiques aux pilotes sonores OSS et MacOSX sont les suivantes :

-nomixer
désactive les primitives qui modifient les réglages du mixeur (son). Si vous préférez que Squeak, laisse-les tranquilles (ils sont, après tout, réellement la responsabilité du programme de mixage ou du panneau de contrôle sonore que vous utilisez) alors cette option est pour vous.

Les options spécifiques au pilote sonore ALSA sont les suivantes :

-capture périphérique
Utilise le périphérique d'entrée nommé pour la capture sonore.
-playback périphérique
Utilise le périphérique de sortie nommé pour la lecture sonore.

Plusieurs options courantes sont dépréciées et ne sont fournies que pour la compatibilité ascendante. Ces options ne doivent pas être utilisées et seront supprimées dans une future version :

-display dpy
est équivalent à '-vm display=X11 -display dpy'.
-headless
est équivalent à '-vm display=X11 -headless'.
-nodisplay
est équivalent à '-vm display=none'.
-nosound
est équivalent à '-vm sound=none'.
-quartz
est équivalent à '-vm display=Quartz'.

ENVIRONNEMENT

Beaucoup des options qui peuvent être définies en ligne de commande peuvent également être définies à partir de variables d'environnement.

SQUEAK_ASYNC
si définie dans l'environnement alors équivalente au drapeau '-xasync'. (La valeur est ignorée.)
SQUEAK_CAPTURE
voir '-capture'.
SQUEAK_COMPOSITIONINPUT
si définie dans l'environnement alors équivalente au drapeau '-compositioninput'. (La valeur est ignorée.)
SQUEAK_ENCODING
le nom de l'encodage de caractères interne utilisé par Squeak. Équivalent à donner l'option en ligne de commande '-encoding' si défini.
SQUEAK_FBDEV
le nom du périphérique framebuffer à utiliser lors de l'exécution sur la console. Voir l'option '-fbdev'.
SQUEAK_FULLSCREEN
équivalent à '-fullscreen' si défini.
SQUEAK_ICONIC
équivalent au drapeau '-iconic'.
SQUEAK_IMAGE
le nom du fichier image à exécuter si aucun argument image n'est donné en ligne de commande.
SQUEAK_KBMAP
le nom du fichier de mappage clavier à utiliser lors de l'exécution sur la console. Voir l'option '-kbmap'.
SQUEAK_LAZY
équivalent au drapeau '-lazy'.
SQUEAK_MAPDELBS
équivalent au drapeau '-mapdelbs'.
SQUEAK_MEMORY
la taille initiale du tas, avec un suffixe optionnel 'k' ou 'm'. Équivalent au drapeau '-memory taille[km]'.
SQUEAK_MSDEV
le nom du périphérique de souris à utiliser lors de l'exécution sur la console. Voir l'option '-msdev'.
SQUEAK_MSPROTO
le nom du protocole souris à utiliser lors de l'exécution sur la console. Voir l'option '-msproto'.
SQUEAK_VTLOCK
si défini alors équivalent à spécifier l'option '-vtlock' en ligne de commande.
SQUEAK_VTSWITCH
si défini alors équivalent à spécifier l'option '-vtswitch' en ligne de commande.
SQUEAK_NOEVENTS
si défini, équivalent à '-noevents'.
SQUEAK_NOINTL
équivalent à '-nointl' si défini.
SQUEAK_NOMIXER
équivalent à '-nomixer' si défini.
SQUEAK_NOTIMER
équivalent à '-notimer' si défini.
SQUEAK_NOTITLE
si défini, équivalent à '-notitle'.
SQUEAK_PATHENC
le nom de l'encodage de caractères utilisé pour construire les noms de fichiers et de répertoires. Équivalent à donner l'option en ligne de commande '-pathenc' si défini.
SQUEAK_PLAYBACK
voir '-playback'.
SQUEAK_PLUGINS
voir '-plugins'.
SQUEAK_SWAPBTN
équivalent à '-swapbtn' si défini.
SQUEAK_TEXTENC
le nom de l'encodage de caractères utilisé pour copier/coller du texte depuis/vers des applications externes. Équivalent à donner l'option en ligne de commande '-textenc' si défini.
SQUEAK_VM
contient les noms d'un ou plusieurs pilotes à charger lors de l'initialisation. Voir l'option '-vm' pour plus de détails.
SQUEAK_XICFONT
si défini dans l'environnement alors il fournit un nom par défaut pour la police de superposition de composition ; voir le drapeau '-xicfont'.
SQUEAK_XSHM
équivalent à '-xshm'.

Si une variable d'environnement et une option en ligne de commande entrent en conflit pour une valeur particulière, alors normalement la valeur de la ligne de commande a la priorité. L'exception à cette règle est l'option '-vm'. Les variables d'environnement sont traitées avant les arguments en ligne de commande et '-vm' ne peut pas être utilisé pour décharger un pilote qui a été chargé lors du traitement du contenu de 'SQUEAK_VM'.

squeak vérifie également l'environnement pour LC_ALL et LC_CTYPE. Si l'une de ces variables est définie, alors le support des claviers internationaux (y compris les touches mortes pour les marques diacritiques) est activé. Pour empêcher ce support d'être activé même lorsque l'une ou les deux de ces variables sont définies, utilisez l'option '-nointl' (ou définissez SQUEAK_NOINTL dans l'environnement). Par exemple, pour démarrer squeak avec le support des touches mortes sur les claviers espagnols, avec l'encodage Latin-1 des caractères externes et l'encodage interne par défaut de la police MacRoman, exécutez squeak comme suit :

export LC_CTYPE=es_ES
export SQUEAK_TEXTENC=latin1
squeak

SCRIPTS

Squeak peut charger et exécuter un fichier 'script' contenant du code Smalltalk au démarrage. Le nom du fichier doit être donné comme argument script à squeak. Par exemple, en supposant que l'image 'foo.image' contient une fenêtre Transcript ouverte, alors le programme 'bonjour le monde' pour Squeak est le suivant :

Transcript cr; show: 'Hello, world'.

Si ce script est dans un fichier appelé 'hello.sq', il pourrait être exécuté comme suit :

squeak foo.image hello.sq

Il est également possible de créer des scripts 'auto-interprétables' en ajoutant une 'ligne d'interpréteur' au début du script. Le fichier 'hello.sq' pourrait être modifié pour devenir

#!/usr/bin/squeak --
Transcript cr; show: 'Hello, world'.

et ensuite rendu exécutable avec

chmod +x hello.sq

et ensuite appelé en exécutant directement le fichier script :

SQUEAK_IMAGE="foo.image"
export SQUEAK_IMAGE
./hello.sq

Si des arguments sont présents après le nom du script, ils peuvent être récupérés depuis le script en utilisant la méthode

Smalltalk getSystemAttribute:
n

où n est l'indice de l'argument, commençant à 3 pour le premier argument. (Voir le commentaire de la méthode pour

SystemDictionary>>getSystemAttribute:

dans l'image pour une explication des significations des indices.)

À titre d'exemple, voici le programme 'echo' écrit comme un script Squeak :

#!/usr/bin/squeak --
"Echo arguments to the Transcript."
| i a |
i := 2.
[(a := Smalltalk getSystemAttribute: (i := i + 1))
    notNil]
  whileTrue: [Transcript space; show: a].

Lorsqu'il est exécuté comme

./echo.sq one two three

cela imprimerait 'one two three' dans la fenêtre Transcript.

DIAGNOSTICS

inisqueak
affiche plusieurs messages d'information pendant son exécution. S'il rencontre un problème, il affiche un message approprié avant de s'arrêter. Les messages devraient être auto-explicatifs.
squeak
normalement, n'affiche rien du tout. S'il affiche quelque chose, il y a un problème. Les messages devraient être auto-explicatifs.

NOTES

Cette page de manuel documente la version 4.10.2-2614 de Squeak pour Unix. Elle peut ne pas être appropriée pour toute autre version.

Les fichiers image et changes contenant une session Squeak sauvegardée sont intimement liés. Ils doivent toujours être utilisés ensemble, ne jamais être séparés, et en aucun cas une image ne doit être exécutée avec un fichier changes qui a été utilisé avec une image différente. Le non-respect de ce qui précède pourrait entraîner le brouillage du code source des méthodes dans l'image, le rendant impossible à récupérer.

La machine virtuelle Squeak pour Unix prend entièrement en charge OpenGL avec les pilotes d'affichage X11 et Quartz. Open Croquet fonctionnera parfaitement avec l'un ou l'autre de ces pilotes (et de nombreux utilisateurs de Mac OS X auront même le choix du pilote à utiliser :).

BOGUES

Si une option 'binaire' est activée par une variable d'environnement, il n'y a aucun moyen de la désactiver sur la ligne de commande.

De même, les pilotes spécifiés dans la variable d'environnement SQUEAK_VM ne peuvent pas être outrepassés en passant des options sur la ligne de commande.

squeak ne devrait jamais planter. Dans le cas improbable où il planterait, ou imprimerait tout message qui ne semble pas être causé par des arguments incorrects ou des opérations illégales depuis un programme Squeak, veuillez envoyer un rapport de bogue à : <ian.piumarta@squeakland.org>. (N'envoyez pas de rapports de bogues à la liste de diffusion générale 'squeak-dev'. Ils ne seront pas lus. Si vous estimez devoir publier un rapport de bogue sur une liste de diffusion, envoyez-le à la liste de diffusion Squeak 'vm-dev' en plus de l'adresse e-mail ci-dessus.)
