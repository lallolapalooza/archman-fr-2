NOM

sq-key-generate - Générer une nouvelle clé

SYNTAXE

sq key generate [OPTIONS]

DESCRIPTION

Génère une nouvelle clé.

La génération d'une clé est le prérequis pour recevoir des messages chiffrés et créer des signatures. Il y a quelques paramètres pour ce processus, mais nous fournissons des valeurs par défaut raisonnables pour la plupart des utilisateurs.

Lors de la génération d'une clé, nous générons également un certificat de révocation d'urgence. Celui-ci peut être utilisé en cas de perte ou de compromission de la clé. Il est sauvegardé à côté de la clé. Ceci peut être modifié en utilisant l'argument `--rev-cert`.

Par défaut, une clé expire après 3 ans. Ceci peut être modifié en utilisant l'argument `--expiration`.

`sq key generate` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Il définit l'heure de création de la clé primaire, des sous-clés éventuelles et des signatures de liaison à l'heure de référence.

OPTIONS

Options de sous-commande

--allow-non-canonical-userids
Ne pas rejeter les identifiants utilisateur qui ne sont pas sous forme canonique
Les identifiants utilisateur canoniques sont de la forme `Nom (Commentaire) <partie_locale@example.org>`.
--can-authenticate
Ajouter une sous-clé capable d'authentification (par défaut)
--can-encrypt=BUT
Ajouter une sous-clé capable de chiffrement [par défaut : universel]
Les sous-clés capables de chiffrement peuvent être marquées comme adaptées au chiffrement de transport, au chiffrement de stockage, ou aux deux, c'est-à-dire universelles.
[valeurs possibles : transport, stockage, universel]
--can-sign
Ajouter une sous-clé capable de signature (par défaut)
--cannot-authenticate
Ne pas ajouter de sous-clé capable d'authentification
--cannot-encrypt
Ne pas ajouter de sous-clé capable de chiffrement
--cannot-sign
Ne pas ajouter de sous-clé capable de signature
--cipher-suite=SUITE_CHIFFREMENT
Sélectionner les algorithmes cryptographiques pour la clé
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.cipher-suite`.
[par défaut : cv25519]
[valeurs possibles : rsa2k, rsa3k, rsa4k, cv25519]
--email=ADRESSE
Ajouter une adresse e-mail en tant qu'identifiant utilisateur à la clé
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date au format ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée prend la forme `N[amjsh]`, où les lettres représentent respectivement les années, mois, jours, semaines et secondes. Alternativement, le mot-clé `never` ne définit pas d'heure d'expiration.
[par défaut : 3a]
--name=NOM
Ajouter un nom en tant qu'identifiant utilisateur à la clé
--new-password-file=FICHIER_MOT_DE_PASSE
Fichier contenant le mot de passe pour chiffrer le matériel de clé secrète
Notez que le fichier de clé entier sera utilisé comme mot de passe, y compris tout espace blanc environnant tel qu'une nouvelle ligne finale.
--no-userids
Créer une clé sans aucun identifiant utilisateur
--output=FICHIER
Écrire la clé dans le fichier spécifié
Lorsqu'il n'est pas spécifié, la clé est enregistrée dans le magasin de clés.
--own-key
Marquer la clé comme étant sa propre clé
La clé nouvellement générée avec tous ses identifiants utilisateur sera marquée comme authentifiée et comme un introducteur de pleine confiance.
--profile=PROFIL
Sélectionner le standard OpenPGP pour la clé
Au fur et à mesure de l'évolution d'OpenPGP, de nouvelles versions deviendront disponibles. Cette option sélectionne la version d'OpenPGP à utiliser pour la clé nouvellement générée.
Actuellement, sq prend en charge deux profils : RFC9580 et RFC4880. Actuellement, la valeur par défaut est RFC4880. Cependant, une fois que la prise en charge de RFC9580 sera plus largement déployée, la valeur par défaut changera dans une future version de sq.
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.profile`.
[par défaut : rfc4880]
[valeurs possibles : rfc9580, rfc4880]
--rev-cert=FICHIER
Écrire le certificat de révocation d'urgence dans FICHIER
Lorsque la clé est stockée dans le magasin de clés, le certificat de révocation est stocké par défaut dans $HOME/.local/share/sequoia/revocation-certificates.
Lorsque `--output` est spécifié, le certificat de révocation est écrit dans le fichier spécifié par `--rev-cert`.
Si `--output` est `-`, alors cette option ne doit pas être également `-`.
--shared-key
Marquer la clé comme une clé partagée
La clé nouvellement générée avec tous ses identifiants utilisateur sera marquée comme authentifiée, mais pas comme un introducteur de confiance. De plus, les métadonnées de la clé indiqueront qu'il s'agit d'une clé partagée.
Utilisez cette option si vous prévoyez de partager cette clé avec d'autres personnes. Normalement, vous ne devriez pas partager le matériel des clés. Un exemple où vous pourriez vouloir faire cela est une boîte aux lettres partagée.
--userid=USERID
Ajouter un identifiant utilisateur à la clé
Cet identifiant utilisateur peut combiner un nom et une adresse e-mail, peut contenir optionnellement un commentaire, ou même être libre si `--allow-non-canonical-userids` est donné. Cependant, les identifiants utilisateur qui incluent des informations différentes telles que le nom et l'adresse e-mail sont plus difficiles à raisonner, donc l'utilisation d'identifiants utilisateur distincts pour le nom et l'adresse e-mail est préférée de nos jours.
En cas de doute, préférez `--name` et `--email`.
--without-password
Ne pas protéger le matériel de clé secrète avec un mot de passe

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Générer une clé et l'enregistrer dans le magasin de clés.

sq key generate --own-key --name Alice --email \
alice@example.org

Générer une clé et l'enregistrer dans un fichier au lieu du magasin de clés.

sq key generate --own-key --name Alice --email \
alice@example.org --output alice-priv.pgp --rev-cert \
alice-priv.rev

VOIR AUSSI

sq(1), sq-key(1).

Pour la documentation complète, voir https://book.sequoia-pgp.org/.

NAME

sq-key-generate - Generate a new PGP key pair

SYNOPSIS

sq key generate [OPTIONS] [KEY-ID]

DESCRIPTION

Generate a new PGP key pair. If KEY-ID is provided, it will be used as the key ID. Otherwise, a random key ID will be generated.

OPTIONS

  • --full-name <name>: The full name for the key.
  • --email <email>: The email address for the key.
  • --comment <comment>: A comment for the key.
  • --password <password>: The password for the private key.
  • --key-type <type>: The type of key to generate (e.g., rsa, ed25519).
  • --key-length <length>: The length of the key in bits.
  • --expires <date>: The expiration date for the key (e.g., +1y, 2023-12-31).
  • --subsubkey: Generate a subkey for signing and encryption.
  • --help: Show help message.
  • --version: Show version information.

EXAMPLES

Generate a new RSA key pair with the email address "user@example.com":

sq key generate --email user@example.com --key-type rsa --key-length 4096

Generate a new Ed25519 key pair with a comment and expiration date:

sq key generate --email user@example.com --comment "My personal key" --expires +5y
