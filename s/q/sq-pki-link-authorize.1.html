SQ(1) Commandes utilisateur SQ(1)

NOM

sq-pki-link-authorize - Faire d'un certificat un introduseur de confiance

SYNTAXE

sq pki link authorize [OPTIONS]

DESCRIPTION

Faire d'un certificat un introduseur de confiance.

Cela amène `sq` à considérer le certificat comme un introduseur de confiance. Un introduseur de confiance est un autre terme pour une autorité de certification (CA). Lorsque vous liez un introduseur de confiance, vous considérez les certifications faites par cet introduseur comme valides. Un introduseur de confiance peut également désigner d'autres introduseurs de confiance.

En l'état, un introduseur de confiance a beaucoup de pouvoir. Ce pouvoir peut être limité de plusieurs manières.


- La capacité de spécifier d'autres introduseurs peut être limitée à l'aide du paramètre `--depth`.


- Le degré de confiance accordé à un introduseur peut être modifié à l'aide du paramètre `--amount`.


- Les identifiants utilisateur (user IDs) que peut certifier un introduseur peuvent être limités par domaine à l'aide du paramètre `--domain` ou par une expression régulière à l'aide du paramètre `--regex`.

Ces mécanismes vous permettent de dire que vous êtes disposé à faire confiance à la CA pour par exemple.org, mais uniquement pour les identifiants utilisateur ayant une adresse e-mail pour example.org, par exemple.

Un lien peut être rétracté en utilisant `sq pki link retract`.

Cette commande est similaire à `sq pki vouch authorize`, mais les certifications qu'elle effectue sont faites en utilisant la racine de confiance du répertoire de certificats, et non une clé arbitraire. De plus, les certificats sont marqués comme non exportables. La première rend la gestion des certifications plus facile, en particulier lorsque votre clé de certification est hors ligne. Et la seconde améliore votre vie privée, en réduisant le risque que des parties de votre réseau social soient divulguées lorsqu'un certificat est partagé.

Par défaut, un lien n'expire jamais. L'utilisation de l'argument `--expiration` permet de définir des périodes de validité spécifiques. Il permet de fournir un point dans le temps pour la fin de la validité ou une durée de validité.

`sq pki link authorize` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Il définit l'heure de création du lien à l'heure de référence.

OPTIONS

Options de sous-commande

--add-email=EMAIL
Utiliser un identifiant utilisateur avec l'adresse e-mail spécifiée
L'identifiant utilisateur se compose uniquement de l'adresse e-mail. L'adresse e-mail n'a pas besoin d'apparaître dans un identifiant utilisateur auto-signé.
--add-userid=USERID
Utiliser l'identifiant utilisateur spécifié
L'identifiant utilisateur spécifié n'a pas besoin d'être auto-signé.
Étant donné que l'utilisation d'un identifiant utilisateur non auto-signé est souvent une erreur, vous devez utiliser cette option pour y consentir explicitement.
--all
Utiliser tous les identifiants utilisateur auto-signés
--allow-non-canonical-userids
Ne pas rejeter les nouveaux identifiants utilisateur qui ne sont pas sous forme canonique
Les identifiants utilisateur canoniques sont de la forme `Nom (Commentaire) <adresse@exemple.org>`.
--amount=MONTANT
Définir le montant de confiance
Les valeurs comprises entre 1 et 120 sont significatives. 120 signifie pleinement de confiance. Les valeurs inférieures à 120 indiquent le degré de confiance. 60 est généralement utilisé pour partiellement de confiance.
[défaut: full]
--cert=EMPREINTE|IDCLEF
Utiliser les certificats avec l'empreinte ou l'ID de clé spécifiés
--cert-special=SPECIAL
Utiliser les certificats identifiés par le nom spécial
[valeurs possibles : public-directories, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--depth=PROFONDEUR_CONFIANCE
Définir la profondeur de confiance
Ceci est parfois appelé le niveau de confiance. 1 signifie que CERTIFICAT est un introduseur de confiance (par défaut), 2 signifie que CERTIFICAT est un méta-introduseur de confiance et peut autoriser un autre introduseur de confiance, etc.
[défaut: 255]
--domain=DOMAINE
Ajouter une contrainte de domaine à l'introduseur
Ajouter un domaine pour contraindre les certifications qui seront respectées. Une certification faite par le certificat n'est respectée que si elle concerne un identifiant utilisateur avec une adresse e-mail dans le domaine spécifié. Plusieurs domaines peuvent être spécifiés. Dans ce cas, l'un d'eux doit correspondre.
--email=EMAIL
Utiliser un identifiant utilisateur composé uniquement de l'adresse e-mail, si l'adresse e-mail apparaît dans un identifiant utilisateur auto-signé
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date au format ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée prend la forme `N[amjsh]`, où les lettres signifient années, mois, jours, secondes, respectivement. Alternativement, le mot-clé `never` ne définit pas d'heure d'expiration.
[défaut: never]
--recreate
Recréer la signature même si les paramètres n'ont pas changé
Si les paramètres du lien n'ont pas changé, et donc la création d'une signature ne devrait pas être nécessaire, nous omettons l'opération. Ce drapeau peut être donné pour forcer la recréation de la signature de toute façon.
--regex=REGEX
Ajouter une expression régulière pour contraindre l'introduseur
Ajouter une expression régulière pour contraindre les certifications qui seront respectées. Une certification faite par le certificat n'est respectée que si elle concerne un identifiant utilisateur qui correspond à l'une des expressions régulières spécifiées. Plusieurs expressions régulières peuvent être spécifiées. Dans ce cas, au moins une doit correspondre.
--signature-notation NOM VALEUR
Ajouter une notation à la signature
Le nom d'une notation définie par l'utilisateur doit être de la forme `nom@un.domaine.que.vous.contrôlez.org`. Si le nom de la notation commence par `!`, alors la notation est marquée comme étant critique. Si un consommateur d'une signature ne comprend pas une notation critique, alors il ignorera la signature. La notation est marquée comme étant lisible par l'homme.
--unconstrained
Ne pas contraindre l'introduseur
Normalement, un introduseur est contraint de sorte que seuls certains identifiants utilisateur soient respectés, par exemple, ceux qui ont une adresse e-mail pour un nom de domaine donné. Cette option autorise un introduseur sans le contraindre de cette manière. Étant donné que cela accorde beaucoup de pouvoir à l'introduseur, vous devez explicitement accepter ce comportement.
--userid=USERID
Utiliser l'identifiant utilisateur auto-signé spécifié
L'identifiant utilisateur spécifié doit être auto-signé.
--userid-by-email=EMAIL
Utiliser l'identifiant utilisateur auto-signé avec l'adresse e-mail spécifiée

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Ajouter un introduseur de confiance non contraint.

NAME

                    
sq-pki-link-authorize — authorizes an introducer

                

                

                    
SYNOPSIS

                    
sq pki link authorize [options] --cert=cert [--all | --domain=domain...]


                

                

                    
DESCRIPTION

                    
This command authorizes a given introducer for the current
                        key. The introducer is identified by its fingerprint, which is
                        given by the --cert
                        option. The introducer can be authorized for all keys that the
                        current key is aware of, or only for a limited set of domains.

                    
The authorization is recorded in the current key's Web of
                        Trust, and can be listed using sq-pki(1).

                

                

                    
OPTIONS

                    
In addition to the options described in sq-pki-link(1),
                        the following options are available:

                    

                        
--cert=cert

                        
Specifies the fingerprint of the introducer's key.

                        
--all

                        
Authorizes the introducer for all keys known to the current key.
                            This is a shortcut for listing all domains.

                        
--domain=domain

                        
Authorizes the introducer only for keys belonging to the given
                            domain. This option can be given multiple times to specify
                            multiple domains. If neither --all
                            nor --domain
                            are specified, it defaults to authorizing for all domains.

                        
--unconstrained

                        
Allows the introducer to authorize keys for arbitrary domains. This
                            is the default if --domain
                            is not used.

                        
--amount=amount

                        
Sets the introduction amount for this introducer. The default amount
                            is 100.

                    

                

                

                    
EXAMPLES

                    
Add a fully trusted introducer for all keys.

                    

                        
sq pki link authorize --unconstrained \

                    

                    

                        

                            
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

                        

                    

                    
Add a trusted introducer for example.org and example.com.

                    

                        
sq pki link authorize --domain=example.org \

                    

                    

                        

                            
--domain=example.com \

                        

                    

                    

                        

                            
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

                        

                    

                    
Add a partially trusted introducer.

                    

                        
sq pki link authorize --unconstrained --amount=60 \

                    

                    

                        

                            
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all
