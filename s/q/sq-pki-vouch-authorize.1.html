NOM

sq-pki-vouch-authorize - Marquer un certificat comme introducteur de confiance

SYNTAXE

sq pki vouch authorize [OPTIONS]

DESCRIPTION

Marque un certificat comme introducteur de confiance.

Crée une certification indiquant que l'émetteur considère le certificat comme un introducteur de confiance. Introducteur de confiance est un autre terme pour autorité de certification (AC). Lorsqu'un utilisateur se fie à un introducteur de confiance, l'utilisateur considère les certifications faites par cet introducteur comme valides. Un introducteur de confiance peut également désigner d'autres introducteurs de confiance.

En l'état, un introducteur de confiance a beaucoup de pouvoir. Ce pouvoir peut être limité de plusieurs manières.


- La capacité de spécifier d'autres introducteurs peut être limitée en utilisant le paramètre `--depth`.


- Le degré de confiance accordé à un introducteur peut être modifié en utilisant le paramètre `--amount`.


- Les identifiants utilisateur que peut certifier un introducteur peuvent être limités par domaine en utilisant le paramètre `--domain` ou par une expression régulière en utilisant le paramètre `--regex`.

Ces mécanismes permettent à Alice de dire qu'elle est disposée à se fier à l'AC par exemple.org, mais uniquement pour les identifiants utilisateur ayant une adresse e-mail pour example.org, par exemple.

Par défaut, une délégation expire après 10 ans. Utilisez l'argument `--expiration` pour modifier ce comportement.

Cette sous-commande respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Elle définit l'heure de création de la certification à l'heure de référence.

OPTIONS

Options de sous-commande

--add-email=EMAIL
Utiliser un identifiant utilisateur avec l'adresse e-mail spécifiée
L'identifiant utilisateur se compose uniquement de l'adresse e-mail. L'adresse e-mail n'a pas besoin d'apparaître dans un identifiant utilisateur auto-signé.
--add-userid=USERID
Utiliser l'identifiant utilisateur spécifié
L'identifiant utilisateur spécifié n'a pas besoin d'être auto-signé.
Étant donné que l'utilisation d'un identifiant utilisateur qui n'est pas auto-signé est souvent une erreur, vous devez utiliser cette option pour l'activer explicitement.
--all
Utiliser tous les identifiants utilisateur auto-signés
--allow-non-canonical-userids
Ne pas rejeter les nouveaux identifiants utilisateur qui ne sont pas sous forme canonique
Les identifiants utilisateur canoniques sont de la forme `Nom (Commentaire) <localpart@example.org>`.
--amount=MONTANT
Définir le montant de confiance
Les valeurs comprises entre 1 et 120 sont significatives. 120 signifie entièrement fiable. Les valeurs inférieures à 120 indiquent le degré de confiance. 60 est généralement utilisé pour une confiance partielle.
[défaut: full]
--cert=EMPREINTE|KEYID
Utiliser les certificats avec l'empreinte ou l'ID de clé spécifié
--cert-file=CHEMIN
Lire les certificats depuis CHEMIN
--certifier=EMPREINTE|KEYID
Créer la certification en utilisant la clé avec l'empreinte ou l'ID de clé spécifié
--certifier-email=EMAIL
Créer la certification en utilisant la clé dont un identifiant utilisateur inclut l'adresse e-mail spécifiée
--certifier-file=CHEMIN
Créer la certification en utilisant la clé lue depuis CHEMIN
--certifier-self
Créer la certification en utilisant votre clé de certification par défaut
Ceci utilise les certificats définis dans le fichier de configuration sous `pki.vouch.certifier-self` comme clé de certification.
Actuellement, il n'y a pas de clé de certification par défaut.
--certifier-userid=USERID
Créer la certification en utilisant la clé avec l'identifiant utilisateur spécifié
--depth=PROfonDEUR_CONFIANCE
Définir la profondeur de confiance
Ceci est parfois appelé le niveau de confiance. 1 signifie que le CERTIFICAT est un introducteur de confiance (défaut), 2 signifie que le CERTIFICAT est un méta-introducteur de confiance et peut autoriser un autre introducteur de confiance, etc.
[défaut: 1]
--domain=DOMAINE
Ajouter une contrainte de domaine à l'introducteur
Ajoute un domaine pour restreindre les certifications qui seront respectées. Une certification faite par le certificat n'est respectée que si elle concerne un identifiant utilisateur avec une adresse e-mail dans le domaine spécifié. Plusieurs domaines peuvent être spécifiés. Dans ce cas, l'un d'eux doit correspondre.
--email=EMAIL
Utiliser un identifiant utilisateur composé uniquement de l'adresse e-mail, si l'adresse e-mail apparaît dans un identifiant utilisateur auto-signé
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date formatée ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée a la forme `N[ymwds]`, où les lettres représentent respectivement les années, mois, semaines, jours et secondes. Alternativement, le mot-clé `never` ne définit pas d'heure d'expiration.
Le défaut peut être modifié dans le fichier de configuration via le paramètre `pki.vouch.expiration`.
[défaut: 10y]
--local
Faire de la certification une certification locale
Normalement, les certifications locales ne sont pas exportées.
--non-revocable
Marquer la certification comme non révocable
C'est-à-dire, vous ne pourrez pas révoquer cette certification plus tard. Ceci ne devrait normalement être utilisé qu'avec une expiration.
--output=FICHIER
Écrire dans FICHIER ou dans la sortie standard si omis
--regex=REGEX
Ajouter une expression régulière pour contraindre l'introducteur
Ajoute une expression régulière pour contraindre les certifications qui seront respectées. Une certification faite par le certificat n'est respectée que si elle concerne un identifiant utilisateur qui correspond à l'une des expressions régulières spécifiées. Plusieurs expressions régulières peuvent être spécifiées. Dans ce cas, au moins une doit correspondre.
--signature-notation NOM VALEUR
Ajouter une notation à la signature
Le nom d'une notation définie par l'utilisateur doit être de la forme `nom@a.domaine.que.vous.contrôlez.org`. Si le nom de la notation commence par un `!`, alors la notation est marquée comme critique. Si un consommateur d'une signature ne comprend pas une notation critique, il ignorera la signature. La notation est marquée comme lisible par l'homme.
--unconstrained
Ne pas contraindre l'introducteur
Normalement, un introducteur est contraint de sorte que seuls certains identifiants utilisateur soient respectés, par exemple, ceux qui ont une adresse e-mail pour un certain nom de domaine. Cette option autorise un introducteur sans le contraindre de cette manière. Étant donné que cela confère beaucoup de pouvoir à l'introducteur, vous devez accepter explicitement ce comportement.
--userid=USERID
Utiliser l'identifiant utilisateur auto-signé spécifié

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

dl>
L'identifiant utilisateur spécifié doit être auto-signé.
--userid-by-email=EMAIL
Utiliser l'identifiant utilisateur auto-signé avec l'adresse e-mail spécifiée

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Certifier que E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F est un introducteur de confiance pour example.org et example.com.

sq pki vouch authorize \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F \
--domain=example.org --domain=example.com --all
