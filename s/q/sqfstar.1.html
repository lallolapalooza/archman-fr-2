SQFSTAR(1) Commandes Utilisateur SQFSTAR(1)

NOM

sqfstar - outil pour créer un système de fichiers squashfs à partir d'une archive tar

SYNOPSIS


cat xxx.tar | sqfstar [OPTIONS] FILESYSTEM [fichiers exclus]
zcat xxx.tgz | sqfstar [OPTIONS] FILESYSTEM [fichiers exclus]
xzcat xxx.tar.xz | sqfstar [OPTIONS] FILESYSTEM [fichiers exclus]
zstdcat xxx.tar.zst | sqfstar [OPTIONS] FILESYSTEM [fichiers exclus]

DESCRIPTION

Squashfs est un système de fichiers en lecture seule hautement compressé pour Linux. Il utilise la compression gzip/xz/lzo/lz4/zstd pour compresser les fichiers, les inodes et les répertoires. Les inodes du système sont très petits et tous les blocs sont empaquetés pour minimiser la surcharge des données. Les tailles de bloc supérieures à 4K sont prises en charge jusqu'à un maximum de 1 Mo (taille de bloc par défaut de 128 Ko).

Squashfs est destiné à une utilisation générale en lecture seule, à des fins d'archivage (c'est-à-dire dans les cas où un fichier .tar.gz peut être utilisé) et dans des systèmes contraints en périphériques bloc/mémoire (par exemple, systèmes embarqués) où une faible surcharge est nécessaire.

OPTIONS

Options de compression du système de fichiers :

-b TAILLE-BLOC
définit le bloc de données à TAILLE-BLOC. Par défaut 128 Ko. Optionnellement, un suffixe de K, KB, Kbytes ou M, MB, Mbytes peut être donné pour spécifier des Kilo-octets ou des Méga-octets respectivement.
-comp COMP
sélectionne la compression COMP. Exécutez -help-comp COMP pour obtenir les options du compresseur pour COMP, ou ALL pour tous les compresseurs. Compresseurs disponibles : gzip (par défaut), lzo, lz4, xz, zstd, lzma.
-noI
ne pas compresser la table des inodes.
-noId
ne pas compresser la table uid/gid (impliqué par -noI).
-noD
ne pas compresser les blocs de données.
-noF
ne pas compresser les blocs de fragments.
-noX
ne pas compresser les attributs étendus.
-no-compression
ne compresser aucune des données ou métadonnées. Ceci est équivalent à spécifier -noI -noD -noF et -noX.

Options de construction du système de fichiers :

-exports
rendre le système de fichiers exportable via NFS.
-no-sparse
ne pas détecter les fichiers épars.
-no-fragments
ne pas utiliser de fragments.
-no-tailends
ne pas empaqueter les "tail ends" (fins de blocs) en fragments.
-no-duplicates
ne pas effectuer de vérification des doublons.
-no-hardlinks
ne pas lier les fichiers en dur, mais stocker les doublons.
-regex
permettre l'utilisation d'expressions régulières POSIX dans les répertoires/fichiers exclus.
-ignore-zeros
permettre la concaténation de fichiers tar et leur alimentation à Sqfstar. Normalement, un fichier tar a deux blocs consécutifs de 512 octets remplis de zéros qui signifient la fin du fichier, et Sqfstar s'arrêtera après le premier fichier tar en les rencontrant. Cette option permet à Sqfstar d'ignorer les blocs remplis de zéros.
-ef FICHIER-EXCLUSION
liste des répertoires/fichiers exclus. Un par ligne.

Options temporelles du système de fichiers :

-mkfs-time TEMPS
définit l'horodatage de création du système de fichiers à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage d'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, comme "now", "last week" ou "Wed Feb 15 21:02:39 GMT 2023".
-inode-time TEMPS
définit tous les horodatages de fichiers et de répertoires à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage d'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, comme "now", "last week" ou "Wed Feb 15 21:02:39 GMT 2025". Cette option définit et remplace l'option -root-time.
-root-time TEMPS
définit l'heure du répertoire racine à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage d'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, comme "now", "last week" ou "Wed Feb 15 21:02:39 GMT 2025".
-repro
construit une image de système de fichiers reproductible. Ceci est équivalent à -mkfs-time inode, qui permet la reproductibilité en définissant le temps de construction du système de fichiers sur le dernier horodatage d'inode. Évidemment, l'image ne sera pas reproductible si les horodatages ou le contenu changent.
-repro-time TEMPS
construit une image de système de fichiers reproductible. Ceci est équivalent à spécifier -mkfs-time TEMPS et -inode-time TEMPS, ce qui permet la reproductibilité en définissant tous les horodatages sur TEMPS. Cette option peut être utilisée dans les cas où les horodatages peuvent changer, et où -repro ne peut pas être utilisé pour cette raison.

Options de permissions du système de fichiers :

-all-root
faire de tous les fichiers et répertoires la propriété de root.
-root-mode MODE
définit les permissions du répertoire racine à MODE. MODE peut être symbolique ou octal (voir la section Spécification du mode symbolique). Le mode racine par défaut est ugo=rwx ou 0777 octal.
-root-uid UTILISATEUR
définit le propriétaire du répertoire racine à l'UTILISATEUR spécifié, UTILISATEUR peut être un uid entier ou un nom d'utilisateur.
-root-gid GROUPE
définit le groupe du répertoire racine au GROUPE spécifié, GROUPE peut être un gid entier ou un nom de groupe.
-force-file-mode MODE
définit toutes les permissions de fichier (non-répertoire) à MODE. MODE peut être symbolique ou octal (voir la section Spécification du mode symbolique).
-force-dir-mode MODE
définit toutes les permissions de répertoire à MODE. MODE peut être symbolique ou octal (voir la section Spécification du mode symbolique).
-force-uid UTILISATEUR
définit tous les uids de fichiers et de répertoires à l'UTILISATEUR spécifié, UTILISATEUR peut être un uid entier ou un nom d'utilisateur.
-force-gid GROUPE
définit tous les gids de fichiers et de répertoires au GROUPE spécifié, GROUPE peut être un gid entier ou un nom de groupe.
-uid-gid-offset VALEUR
décale tous les uid et gid de la VALEUR spécifiée. VALEUR doit être un entier positif.
-default-mode MODE
les fichiers tar ne stockent souvent pas les permissions pour les répertoires intermédiaires. Cette option définit les permissions de répertoire par défaut à MODE. MODE peut être symbolique ou octal (voir la section Spécification du mode symbolique). Le mode par défaut est u=rwx,go=rx ou 0755 octal. Ceci définit également le mode du répertoire racine.
-uid-par-défaut UTILISATEUR
Les fichiers tar ne stockent souvent pas les uid pour les répertoires intermédiaires. Cette option définit le propriétaire par défaut du répertoire sur UTILISATEUR, plutôt que l'utilisateur exécutant Sqfstar. UTILISATEUR peut être un uid entier ou un nom d'utilisateur. Ceci définit également l'uid du répertoire racine.
-gid-par-défaut GROUPE
Les fichiers tar ne stockent souvent pas les gid pour les répertoires intermédiaires. Cette option définit le groupe par défaut du répertoire sur GROUPE, plutôt que le groupe de l'utilisateur exécutant Sqfstar. GROUPE peut être un gid entier ou un nom de groupe. Ceci définit également le gid du répertoire racine.

Pseudo-options de système de fichiers :

-p DÉFINITION-PSEUDO
ajoute une définition de fichier pseudo. La définition doit être mise entre guillemets. Voir la section "Format de définition de fichier pseudo" pour les détails du format.
-pd "d mode uid gid"
spécifie un répertoire pseudo par défaut qui sera utilisé dans les définitions pseudo si un répertoire dans le chemin n'existe pas. Ceci permet également de spécifier des définitions pseudo sans spécifier tous les répertoires dans le chemin. La définition doit être mise entre guillemets.
-pd "D temps mode uid gid"
spécifie un répertoire pseudo par défaut qui sera utilisé dans les définitions pseudo si un répertoire dans le chemin n'existe pas. Le type D permet également de spécifier un horodatage en plus du mode, de l'uid et du gid.
-pf FICHIER-PSEUDO
ajoute une liste de définitions de fichiers pseudo. Les définitions de fichiers pseudo dans les fichiers pseudo ne doivent pas être mises entre guillemets.
-remplacement-pseudo
fait que les uids et gids de fichier pseudo remplacent les options -tout-root, -uid-forcé et -gid-forcé.

Options d'attributs étendus (xattrs) de système de fichiers :

-pas-xattrs
ne pas stocker les attributs étendus.
-xattrs
stocker les attributs étendus (par défaut).
-exclure-xattrs REGEX
exclut les noms de xattr correspondant à REGEX. REGEX est une expression régulière POSIX, par exemple -exclure-xattrs '^user.' exclut les xattrs de l'espace de noms utilisateur.
-inclure-xattrs REGEX
inclut les noms de xattr correspondant à REGEX. REGEX est une expression régulière POSIX, par exemple -inclure-xattrs '^user.' inclut les xattrs de l'espace de noms utilisateur.
-ajouter-xattrs NOM=VAL
ajoute le xattr NOM avec VAL aux fichiers. S'il s'agit d'un xattr utilisateur, il sera ajouté aux fichiers réguliers et aux répertoires (voir man 7 xattr). Sinon, il sera ajouté à tous les fichiers. VAL sera par défaut traité comme binaire (c'est-à-dire une séquence d'octets non interprétée), mais il peut être préfixé par 0, où il sera traité comme encodé en base64, ou préfixé par 0x, où val sera traité comme hexadécimal. De plus, il peut être préfixé par 0t où cet encodage est similaire à l'encodage binaire, sauf que les barres obliques inverses sont traitées spécialement, et une barre oblique inverse suivie de 3 chiffres octaux peut être utilisée pour encoder n'importe quel caractère ASCII, ce qui peut évidemment être utilisé pour encoder des codes de contrôle. L'option peut être répétée plusieurs fois pour ajouter plusieurs xattrs.

Options d'exécution de Sqfstar :

-version
affiche le message de version, de licence et de copyright.
-forcer
force Sqfstar à écrire sur un périphérique bloc ou un fichier.
-quitter-en-cas-d\'erreur
traite les erreurs normalement ignorées comme fatales.
-silencieux
pas de sortie verbeuse.
-info
affiche les fichiers écrits sur le système de fichiers sur la sortie standard. Ceci désactive automatiquement la barre de progression. Voir -fichier-info pour sortir dans un fichier sans désactiver la barre de progression.
-fichier-info FICHIER
affiche les fichiers écrits sur le système de fichiers dans le fichier FICHIER. Ceci ne désactive pas la barre de progression.
-pas-de-progression
ne pas afficher la barre de progression.
-progression
affiche la barre de progression lors de l'utilisation de l'option -info.
-pourcentage
affiche un pourcentage plutôt qu'une barre de progression complète. Peut être utilisé avec le dialogue --gauge, etc.
-limiteur POURCENTAGE
limite le taux d'entrée d'E/S par le pourcentage donné. Ceci peut être utilisé pour réduire la consommation d'E/S et de CPU de Sqfstar.
-limiter POURCENTAGE
limite le taux d'entrée d'E/S au pourcentage donné. Ceci peut être utilisé pour réduire la consommation d'E/S et de CPU de Sqfstar (alternative à -limiteur).
-processeurs NOMBRE
utilise NOMBRE processeurs. Par défaut, utilisera le nombre de processeurs disponibles.
-mem TAILLE
utilise TAILLE de mémoire physique pour les caches. Utilisez K, M ou G pour spécifier Kbytes, Mbytes ou Gbytes respectivement.
-pourcent-mem POURCENT
utilise POURCENT de mémoire physique pour les caches. Par défaut 25%.
-mem-défaut
affiche l'utilisation mémoire par défaut en Mbytes.
-surallocation POURCENT
autorise POURCENT de threads supplémentaires à s'exécuter en parallèle par rapport aux processeurs disponibles. Faire cela peut augmenter l'utilisation du CPU. Par défaut 0%, car normalement la surallocation réduit les performances en raison du "trashing". La valeur du pourcentage est à la granularité du nombre de processeurs, par exemple 4 processeurs ont une granularité de pourcentage de 25%, et 20 processeurs ont une granularité de pourcentage de 5%.

Options expertes (celles-ci peuvent rendre le système de fichiers non montable) :

-flux
envoie le système de fichiers vers STDOUT plutôt que vers un fichier. Ceci permet de rediriger la sortie vers un autre programme ou ailleurs avec ssh. Le système de fichiers Squashfs en flux résultant ne sera pas un système de fichiers Squashfs normal car le super bloc sera à la fin du système de fichiers. Mais il peut être corrigé par la suite avec l'option -corriger et Unsquashfs 4.7.3 et versions ultérieures peuvent lire directement les fichiers non corrigés en flux. La détection de doublons est désactivée en utilisant l'option -flux.
-corriger SYSTÈME-DE-FICHIERS
corrige un SYSTÈME-DE-FICHIERS généré en utilisant l'option -flux.
-sans-rembourrage
ne pas rembourrer le système de fichiers à un multiple de 4K.
-décalage DÉCALAGE
saute DÉCALAGE octets au début du SYSTÈME-DE-FICHIERS. Optionnellement, un suffixe de K, M ou G peut être donné pour spécifier Kbytes, Mbytes ou Gbytes respectivement. Par défaut 0 octets.
-o DÉCALAGE
synonyme de -décalage.

SPÉCIFICATION DE MODE SYMBOLIQUE

Le mode symbolique est du format [ugoa]*[[+-=]PERMS]+. PERMS = [rwxXst]+ ou [ugo], et la séquence peut être répétée séparée par des virgules.

Une combinaison des lettres ugoa spécifie quels bits de permission seront affectés, u signifie utilisateur, g signifie groupe, o signifie autre, et a signifie tous ou ugo.

La lettre suivante est +, - ou =. La lettre + signifie ajouter aux bits de permission existants, - signifie supprimer les bits des bits de permission existants, et = signifie définir les bits de permission.

Les bits de permission (PERMS) sont une combinaison de [rwxXst] qui définissent/ajoutent/suppriment ces bits pour la combinaison ugoa spécifiée, r signifie lecture, w signifie écriture et x signifie exécution pour les fichiers ou recherche pour les répertoires. X a une signification spéciale, si le fichier est un répertoire, il est équivalent à x ou recherche, mais s'il s'agit d'un fichier non-répertoire, il ne prend effet que si l'exécution est déjà définie pour l'utilisateur, le groupe ou autre. Le drapeau s définit l'ID utilisateur ou groupe à l'exécution, et le drapeau t sur un répertoire définit la suppression restreinte, ou historiquement rendait le fichier "sticky" s'il ne s'agissait pas d'un répertoire.

Les bits de permission peuvent également être u, g ou o, qui prennent les bits de permission de l'utilisateur, du groupe ou de l'autre du fichier respectivement.

STATUT DE SORTIE

0
Sqfstar a généré avec succès un système de fichiers.
1
Des erreurs fatales se sont produites, Sqfstar a été interrompu et n'a pas généré de système de fichiers.

COMPRESSEURS DISPONIBLES ET OPTIONS SPÉCIFIQUES AU COMPRESSEUR

gzip (par défaut) :

-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être 1 .. 9 (par défaut 9).
-Xwindow-size TAILLE-FENÊTRE
TAILLE-FENÊTRE doit être 8 .. 15 (par défaut 15).
-Xstrategy stratégie1,stratégie2,...,stratégieN
Compresse en utilisant successivement stratégie1,stratégie2,...,stratégieN et choisit la meilleure compression. Stratégies disponibles : default, filtered, huffman_only, run_length_encoded et fixed.

lzo :

-Xalgorithm ALGORITHME
Où ALGORITHME est l'un de : lzo1x_1, lzo1x_1_11, lzo1x_1_12, lzo1x_1_15, lzo1x_999 (par défaut).
-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être 1 .. 9 (par défaut 8). S'applique uniquement à l'algorithme lzo1x_999.

lz4 :

-Xhc
Compresse en utilisant LZ4 haute compression.

xz :

-Xbcj filtre1,filtre2,...,filtreN
Compresse en utilisant successivement filtre1,filtre2,...,filtreN (en plus de pas de filtre), et choisit la meilleure compression. Filtres disponibles : x86, arm, armthumb, arm64, powerpc, sparc, ia64, riscv.
-Xdict-size TAILLE-DICT
Utilise TAILLE-DICT comme taille du dictionnaire XZ. La taille du dictionnaire peut être spécifiée en pourcentage de la taille du bloc, ou en valeur absolue. La taille du dictionnaire doit être inférieure ou égale à la taille du bloc et supérieure ou égale à 8192 octets. Elle doit également pouvoir être stockée dans l'en-tête xz sous la forme 2^n ou 2^n+2^(n+1). Les tailles de dictionnaire exemples sont 75%, 50%, 37.5%, 25%, ou 32K, 16K, 8K etc.

zstd :

-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être -131072 .. -1 ou 1 .. 22 (par défaut 15). Les niveaux de compression négatifs correspondent à l'option zstd --fast.

lzma :

(aucune option) (obsolète - pas de prise en charge noyau)

ENVIRONNEMENT

SQFS_CMDLINE
S'il est défini, il est utilisé comme répertoire pour écrire le fichier sqfs_cmdline qui contient les arguments de la ligne de commande donnés à Sqfstar. Chaque argument de ligne de commande est entouré de guillemets pour garantir qu'il n'y a pas d'ambiguïté lorsque les arguments contiennent des espaces. Si le fichier existe déjà, la ligne de commande est ajoutée au fichier.
SOURCE_DATE_EPOCH
S'il est défini, il est utilisé comme horodatage de création du système de fichiers. De plus, tout horodatage de fichier postérieur à SOURCE_DATE_EPOCH sera limité à SOURCE_DATE_EPOCH. Voir https://reproducible-builds.org/docs/source-date-epoch/ pour plus d'informations.
PAGER
S'il est défini, il est utilisé comme nom du programme utilisé pour afficher le texte d'aide. La valeur peut être une commande simple ou un chemin d'accès. La valeur par défaut est /usr/bin/pager.

EXEMPLES

sqfstar IMAGE.SQFS < archive.tar
Crée un système de fichiers Squashfs à partir du fichier tar non compressé "archive.tar". Sqfstar utilisera le compresseur par défaut (généralement gzip) et une taille de bloc de 128 Ko.
zcat archive.tgz | sqfstar IMAGE.SQFS
Crée un système de fichiers Squashfs à partir du fichier tar compressé "archive.tgz". Sqfstar utilisera le compresseur par défaut (généralement gzip) et une taille de bloc de 128 Ko.
sqfstar -b 1M -comp zstd IMAGE.SQFS < archive.tar
Utilise une taille de bloc de 1 Mo et la compression Zstandard pour créer le système de fichiers.
sqfstar -root-uid 0 -root-gid 0 IMAGE.SQFS < archive.tar
Les fichiers Tar ne fournissent pas de définition pour le répertoire racine, et par défaut, celui-ci est possédé/groupé par l'utilisateur exécutant Sqfstar. La commande ci-dessus définit la propriété/propriété de groupe à root.
sqfstar -root-mode 0755 IMAGE.SQFS < archive.tar
Les permissions par défaut pour le répertoire racine sont 0777 (rwxrwxrwx). La commande ci-dessus définit les permissions à 0755 (rwxr-xr-x).
sqfstar -all-time n ow IMAGE.SQFS < archive.tar
Définit tous les fichiers et répertoires à "maintenant" (heure actuelle) dans le système de fichiers.
sqfstar -force-uid phillip -force-gid phillip IMAGE.SQFS < archive.tar
Rend tous les fichiers et répertoires du système de fichiers appartenant à "phillip".
sqfstar -force-file-mode ugo+r,go-w IMAGE.SQFS < archive.tar
Rend tous les fichiers lisibles par tout le monde, mais uniquement inscriptibles par l'utilisateur ; tous les autres bits de permission ne sont pas affectés.
sqfstar IMAGE.SQFS file1 file2 < archive.tar
Exclut file1 et file2 du fichier tar lors de la création du système de fichiers.
sqfstar IMAGE.SQFS "*.gz" < archive.tar
Exclut tous les fichiers du répertoire de premier niveau qui correspondent au modèle de caractère générique "*.gz".
sqfstar IMAGE.SQFS "... *.gz" < archive.tar
Exclut tous les fichiers qui correspondent au modèle de caractère générique "*.gz" n'importe où dans le fichier tar. Le "..." initial indique que le modèle de caractère générique est "non ancré" et correspondra n'importe où.

Note : lors du passage de noms avec caractères génériques à Sqfstar, ils doivent être mis entre guillemets (comme dans les exemples ci-dessus), pour s'assurer qu'ils ne sont pas traités par le shell.

Utilisation des définitions de fichiers pseudo

sqfstar -p "build_dir d 0644 0 0" IMAGE.SQFS < archive.tar
Crée un répertoire appelé "build_dir" dans le système de fichiers de sortie.
sqfstar -p "version.txt l /tmp/build/version" IMAGE.SQFS < archive.tar
Crée une référence appelée "version.txt" vers un fichier qui ne se trouve pas dans l'archive tar, ce qui agit comme si ce fichier était dans l'archive tar.
sqfstar -p "date.txt f 0644 0 0 date" IMAGE.SQFS < archive.tar
Crée un fichier appelé "date.txt" qui contient la sortie (stdout) de l'exécution de la commande "date".
sqfstar -p "\"hello world\" f 0644 0 0 date" IMAGE.SQFS < archive.tar
Comme ci-dessus, mais montrant que les noms de fichiers peuvent contenir des espaces, s'ils sont mis entre guillemets. Les guillemets doivent être précédés d'une barre oblique inverse pour les protéger du shell.
sqfstar -p "input f 0644 root root dd if=/dev/sda1 bs=1024" IMAGE.SQFS < archive.tar
Crée un fichier contenant le contenu de la partition /dev/sda1". Ce qui précède permet de capturer les entrées de ces fichiers spéciaux et de les placer dans le système de fichiers Squashfs.

Note : les définitions de fichiers pseudo doivent être mises entre guillemets (comme dans les exemples ci-dessus), pour s'assurer qu'elles sont passées à Mksquashfs en un seul argument, et pour s'assurer qu'elles ne sont pas traitées par le shell.
