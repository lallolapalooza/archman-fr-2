SQ(1) Commandes utilisateur SQ(1)

NOM

sq-pki-link - Gérer les liens authentifiés de certificat et d'identifiant utilisateur

SYNTAXE

sq pki link add [OPTIONS]
sq pki link authorize [OPTIONS]
sq pki link retract [OPTIONS]
sq pki link list [OPTIONS] MOTIF

DESCRIPTION

Gérer les liens authentifiés de certificat et d'identifiant utilisateur.

Lier un certificat et un identifiant utilisateur est une manière de considérer qu'une liaison est authentique pour `sq`. Une autre manière est d'utiliser `sq pki vouch add` pour certifier la liaison avec une racine de confiance explicitement configurée. La fonctionnalité de liaison est souvent plus facile à utiliser, et l'information est privée par défaut.

Les liaisons authentifiées peuvent être utilisées pour désigner un certificat à l'aide d'un nom symbolique. Par exemple, en utilisant les options `--for-userid` et `--for-email` de `sq encrypt`, un utilisateur peut désigner un certificat à l'aide d'un identifiant utilisateur ou d'une adresse e-mail qui est authentifié pour ce certificat.

`sq` utilise également les certificats authentifiés pour authentifier d'autres données. Par exemple, `sq verify` considère les signatures faites par un certificat authentifié comme étant authentiques.

Les utilisateurs peuvent créer un lien en utilisant `sq pki link add`. Ce lien peut ensuite être rétracté en utilisant `sq pki link retract`. Un certificat peut également être accepté comme introducteur de confiance en utilisant `sq pki link authorize`.

`sq` implémente la liaison à l'aide de certifications non exportables et d'une racine de confiance implicite. Un répertoire de certificats OpenPGP, le magasin de certificats par défaut utilisé par `sq`, inclut une racine de confiance locale, qui est stockée sous le nom spécial `trust-root`. Lorsque l'utilisateur demande à `sq` d'accepter une liaison, `sq` utilise la racine de confiance locale pour créer une certification non exportable, qu'il stocke dans le répertoire de certificats. De cette manière, les opérations qui utilisent le Web de Confiance pour authentifier une liaison utilisent automatiquement les liens.

Lorsqu'un utilisateur rétracte un lien, `sq` crée une nouvelle certification non exportable avec une confiance nulle. Cette certification supprime le lien précédent.

SOUS-COMMANDES

sq pki link add

Lier un certificat et un identifiant utilisateur.

Cela amène `sq` à considérer que le certificat et l'identifiant utilisateur liés sont authentiques. Vous feriez cela si vous êtes sûr qu'un certificat particulier doit être associé à Alice, par exemple. Note : cela ne considère pas le certificat comme un introducteur de confiance ; cela considère seulement que la liaison est authentique. Pour autoriser un certificat à être un introducteur de confiance, utilisez `sq pki link authorize`.

Un lien peut être rétracté en utilisant `sq pki link retract`.

Cette commande est similaire à `sq pki vouch add`, mais les certifications qu'elle effectue sont faites en utilisant la racine de confiance du répertoire de certificats, et non une clé arbitraire. De plus, les certificats sont marqués comme non exportables. La première rend la gestion des certifications plus facile, surtout lorsque la clé de certification de l'utilisateur est hors ligne. Et la seconde améliore la vie privée de l'utilisateur, en réduisant le risque que des parties du graphe social de l'utilisateur soient divulguées lorsqu'un certificat est partagé.

Par défaut, un lien n'expire jamais. Ceci peut être outrepassé en utilisant l'argument `--expiration`.

`sq pki link add` respecte le temps de référence défini par l'argument de niveau supérieur `--time`. Il définit le temps de création du lien au temps de référence.

sq pki link authorize

Faire d'un certificat un introducteur de confiance.

Cela amène `sq` à considérer que le certificat est un introducteur de confiance. Introducteur de confiance est un autre terme pour autorité de certification (AC). Lorsque vous liez un introducteur de confiance, vous considérez que les certifications faites par l'introducteur de confiance sont valides. Un introducteur de confiance peut également désigner d'autres introducteurs de confiance.

En l'état, un introducteur de confiance a beaucoup de pouvoir. Ce pouvoir peut être limité de plusieurs manières.


- La capacité de spécifier d'autres introducteurs peut être limitée à l'aide du paramètre `--depth`.


- Le degré de confiance accordé à un introducteur peut être modifié à l'aide du paramètre `--amount`.


- Les identifiants utilisateur que peut certifier un introducteur peuvent être limités par domaine en utilisant le paramètre `--domain` ou par une expression régulière en utilisant le paramètre `--regex`.

Ces mécanismes vous permettent de dire que vous êtes prêt à faire confiance à l'AC de example.org, par exemple, mais uniquement pour les identifiants utilisateur qui ont une adresse e-mail pour example.org, par exemple.

Un lien peut être rétracté en utilisant `sq pki link retract`.

Cette commande est similaire à `sq pki vouch authorize`, mais les certifications qu'elle effectue sont faites en utilisant la racine de confiance du répertoire de certificats, et non une clé arbitraire. De plus, les certificats sont marqués comme non exportables. La première rend la gestion des certifications plus facile, surtout lorsque votre clé de certification est hors ligne. Et la seconde améliore votre vie privée, en réduisant le risque que des parties de votre graphe social soient divulguées lorsqu'un certificat est partagé.

Par défaut, un lien n'expire jamais. L'utilisation de l'argument `--expiration` permet de définir des périodes de validité spécifiques. Il permet de fournir un point dans le temps pour la fin de la validité ou une durée de validité.

`sq pki link authorize` respecte le temps de référence défini par l'argument de niveau supérieur `--time`. Il définit le temps de création du lien au temps de référence.

sq pki link retract

Rétracter les liens.

Cette commande rétracte les liens qui ont été précédemment créés en utilisant `sq pki link add` ou `sq pki link authorize`. Voir la documentation de cette sous-commande pour plus de détails. Note : ceci s'appelle `retract` (rétracter) et non `remove` (supprimer), car les certifications ne sont pas supprimées. Au lieu de cela, une nouvelle certification est ajoutée, qui indique que la liaison n'a pas été authentifiée.

`sq pki link retract` respecte le temps de référence défini par l'argument de niveau supérieur `--time`. Cela amène un lien à être rétracté à partir d'une heure particulière au lieu de l'heure actuelle.

sq pki link list

Lister les liens.

Cette commande liste toutes les liaisons qui sont liées ou dont le lien a été rétracté.

Renvoie un code de sortie non nul si un certificat explicitement désigné n'a jamais été lié.

EXEMPLES

sq pki link add

Lier le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0 avec l'adresse e-mail alice@example.org.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--email=alice@example.org

Premièrement, examinez le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0.

sq inspect --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Ensuite, acceptez temporairement le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0 avec tous ses identifiants utilisateur auto-signés pendant une semaine.

sq pki link add --expiration=1w \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Une fois satisfait, acceptez définitivement le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0 avec tous ses identifiants utilisateur auto-signés.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link authorize

Ajouter un introducteur de confiance non contraint.

sq pki link authorize --unconstrained \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Ajouter un introducteur de confiance pour example.org et example.com.

sq pki link authorize --domain=example.org \
--domain=example.com \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Ajouter un introducteur partiellement fiable.

sq pki link authorize --unconstrained --amount=60 \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link retract

Rétracter le lien de certification pour le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0 pour l'identifiant utilisateur alice@example.org.

sq pki link retract \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--email=alice@example.org

Rétracter toutes les certifications d'introducteur de confiance pour le certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0.

sq pki link retract --unconstrained \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link list

Lister tous les liens de certificats.

sq pki link list

Lister toutes les certifications d'introducteur de confiance pour tous les certificats.

sq pki link list --all

Lister toutes les liaisons pour les certificats appartenant à alice@example.org.

sq pki link list --email=alice@example.org

Lister les liaisons et les autorisations du certificat EB28F26E2739A4870ECC47726F0073F60FD0CBF0.

sq pki link list --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

sq-pki-link(1) — Sequoia PGP

NAME

sq-pki-link — manage links between certificates and user identifiers

SYNOPSIS

sq pki link ...

DESCRIPTION

This manual page describes the sq pki link subcommands. They are used to manage associations between certificates and user identifiers.

The primary purpose of these links is to allow the user to verify that a given certificate is indeed owned by a person or an organisation that owns a specific set of user identifiers. For instance, one can link a certificate to an email address, to assert that the certificate is indeed owned by the person to whom the email address belongs.

These links are stored locally and are not transmitted anywhere. They are used by sq to perform the following operations:

  • When verifying a signature, if the signer's certificate is not trusted, sq can search for a certificate that is linked to an email address that is present in the signed message.
  • When encrypting a message, if the intended recipient is specified by an email address, sq can search for a certificate that is linked to the specified email address.

In order to assert that a given certificate is indeed owned by a person or organisation that owns a specific set of user identifiers, you must provide proof of ownership of these user identifiers.

By default, the only way to provide proof of ownership is to sign the certificate with the private key associated with the user identifier. However, there are other ways to establish that a certificate is owned by a given user identifier, such as submitting a signed statement to a trust authority.

For the moment, sq only supports the former method of establishing ownership.

SUBCOMMANDS

sq pki link add [options] [argument...]

sq pki link retract [options] [argument...]

sq pki link list [options] [argument...]

EXAMPLES

Link the certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 with the email address alice@example.org.

sq pki link add \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

Retract the acceptance of certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 and the email address alice@example.org.

sq pki link retract \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

Retract the acceptance of certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 and any associated user IDs. This effectively invalidates all links.

sq pki link retract \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link list

Link the certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 with the email address alice@example.org.

sq pki link add \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

List all links.

sq pki link list

List links to certificates with an authenticated user ID that contains an email address in the specified domain.

sq pki link list --cert-domain=example.org
