squeue(1) Commandes Slurm squeue(1)

NOM

squeue - visualiser des informations sur les travaux situés dans la file d'attente de planification Slurm.

SYNTAXE

squeue [OPTIONS...]

DESCRIPTION

squeue est utilisé pour visualiser les informations sur les travaux et les étapes de travaux gérés par Slurm.

OPTIONS

-A, --account=<liste_comptes>
Spécifie les comptes des travaux à visualiser. Accepte une liste de noms de comptes séparés par des virgules. Ceci n'a aucun effet lors du listage des étapes de travaux.
-a, --all
Affiche les informations sur les travaux et les étapes de travaux dans toutes les partitions. Cela entraîne l'affichage d'informations sur les partitions configurées comme cachées, les partitions indisponibles pour le groupe d'un utilisateur, et les travaux fédérés qui sont dans un état "révoqué".
-r, --array
Affiche un élément de tableau de travaux par ligne. Sans cette option, l'affichage sera optimisé pour l'utilisation avec des tableaux de travaux (les éléments de tableau de travaux en attente seront combinés sur une ligne de sortie avec les index de tableaux imprimés à l'aide d'une expression régulière).
-M, --clusters=<nom_cluster>
Clusters auxquels adresser les commandes. Plusieurs noms de clusters peuvent être séparés par des virgules. Une valeur de 'all' interrogera pour exécuter sur tous les clusters. Notez que le slurmdbd doit être en cours d'exécution pour que cette option fonctionne correctement, sauf en cas de fédération avec l'option FederationParameters=fed_display configurée ou l'option --federation définie. Cette option définit implicitement l'option --local.
--expand-patterns
Développe tous les motifs de noms de fichiers de StdOut, StdErr et StdIn. Les champs qui correspondent à une plage de valeurs utiliseront la première valeur de la plage. Par exemple, '%t' pour l'ID de tâche sera remplacé par '0'.
--federation
Affiche les travaux de la fédération si l'on est membre d'une.
-o, --format=<format_sortie>
Spécifie les informations à afficher, leur taille et leur position (justifié à droite ou à gauche). Voir également l'option -O, --Format=<format_sortie> décrite ci-dessous (qui offre moins de flexibilité de formatage, mais permet d'accéder à tous les champs). Si la commande est exécutée dans un environnement de cluster fédéré et que des informations sur plus d'un cluster doivent être affichées et que l'option -h, --noheader est utilisée, alors le nom du cluster sera affiché avant les formats de sortie par défaut indiqués ci-dessous.

Les formats par défaut avec diverses options sont :

défaut
"%.18i %.9P %.8j %.8u %.2t %.10M %.6D %R"
-l, --long
"%.18i %.9P %.8j %.8u %.8T %.10M %.9l %.6D %R"
-s, --steps
"%.15i %.8j %.9P %.8u %.9M %N"

Le format de chaque champ est "%[[.]taille]type[suffixe]"

taille
Taille minimale du champ. Si aucune taille n'est spécifiée, la taille nécessaire pour imprimer l'information sera utilisée.
.
Indique que la sortie doit être justifiée à droite et que la taille doit être spécifiée. Par défaut, la sortie est justifiée à gauche.
suffixe
Chaîne de caractères arbitraire à ajouter à la fin du champ.

Notez que nombre de ces spécifications de type ne sont valides que pour les travaux, tandis que d'autres ne sont valides que pour les étapes de travaux. Les spécifications de type valides incluent :

%all
Imprime tous les champs disponibles pour ce type de données avec une barre verticale séparant chaque champ.
%a
Compte associé au travail. (Valide pour les travaux uniquement)
%A
Nombre de tâches créées par une étape de travail. Ceci rapporte la valeur de l'option srun --ntasks. (Valide pour les étapes de travaux uniquement)
%A
ID du travail. Ceci aura une valeur unique pour chaque élément des tableaux de travaux. (Valide pour les travaux uniquement)
%B
Hôte d'exécution (batch). Pour une session allouée, c'est l'hôte sur lequel la session s'exécute (c'est-à-dire le nœud à partir duquel la commande srun ou salloc a été exécutée). Pour un travail batch, c'est le nœud exécutant le script batch. Dans le cas d'un cluster Linux typique, ce serait le nœud de calcul zéro de l'allocation.
%c
Nombre minimum de CPU (processeurs) par nœud demandé par le travail. Ceci rapporte la valeur de l'option srun --mincpus avec une valeur par défaut de zéro. (Valide pour les travaux uniquement)
%C
Nombre de CPU (processeurs) demandés par le travail ou qui lui sont alloués s'il est déjà en cours d'exécution. À mesure qu'un travail se termine, ce nombre reflétera le nombre actuel de CPU alloués. (Valide pour les travaux uniquement)
%d
Taille minimale d'espace disque temporaire (en Mo) demandé par le travail. (Valide pour les travaux uniquement)
%D
Nombre de nœuds alloués au travail ou nombre minimum de nœuds requis par un travail en attente. Le nombre réel de nœuds alloués à un travail en attente peut dépasser ce nombre si le travail a spécifié un nombre de nœuds dans une plage (par exemple, un nombre minimum et maximum de nœuds) ou si le travail spécifie un nombre de processeurs au lieu d'un nombre de nœuds. À mesure qu'un travail se termine, ce nombre reflétera le nombre actuel de nœuds alloués. (Valide pour les travaux uniquement)
%e
Heure à laquelle le travail s'est terminé ou est censé se terminer (en fonction de sa limite de temps). (Valide pour les travaux uniquement)
%E
Dépendances de travaux restantes. Ce travail ne commencera pas son exécution tant que ces travaux dépendants ne seront pas terminés. Dans le cas d'un travail qui ne peut pas s'exécuter en raison de dépendances de travaux jamais satisfaites, la spécification complète d'origine de la dépendance du travail sera rapportée. Une fois qu'une dépendance est satisfaite, elle est retirée du travail. Une valeur NULL implique que ce travail n'a pas de dépendances. (Valide pour les travaux uniquement)
%f
Fonctionnalités requises par le travail. (Valide pour les travaux uniquement)
%F
ID du travail de tableau de travaux. C'est l'ID de travail de base. Pour les travaux non-tableaux, c'est l'ID du travail. (Valide pour les travaux uniquement)
%g
Nom du groupe du travail. (Valide pour les travaux uniquement)
%G
ID du groupe du tra
%h
Les ressources de calcul allouées au job peuvent-elles être en surréservation par d'autres jobs. Les ressources à surréservées peuvent être des nœuds, des sockets, des cœurs ou des hyperthreads selon la configuration. La valeur sera "YES" si le job a été soumis avec l'option de surréservation ou si la partition est configurée avec OverSubscribe=Force, "NO" si le job nécessite un accès exclusif aux nœuds, "USER" si les nœuds de calcul alloués sont dédiés à un seul utilisateur, "MCS" si les nœuds de calcul alloués sont dédiés à une seule classe de sécurité (voir les paramètres de configuration MCSPlugin et MCSParameters pour plus d'informations), "OK" sinon (typiquement des CPUs dédiés alloués), (Valide pour les jobs uniquement)
%H
Nombre de sockets par nœud demandé par le job. Ceci rapporte la valeur de l'option srun --sockets-per-node. Lorsque --sockets-per-node n'a pas été défini, "*" est affiché. (Valide pour les jobs uniquement)
%i
ID du job ou de l'étape du job. Dans le cas des tableaux de jobs, le format de l'ID du job sera de la forme "<ID_job_base>_<index>". Par défaut, la taille du champ de l'index du tableau de jobs sera limitée à 64 octets. Utilisez la variable d'environnement SLURM_BITSTR_LEN pour spécifier des tailles de champ plus grandes. (Valide pour les jobs et les étapes de jobs) Dans le cas d'allocations de jobs hétérogènes, le format de l'ID du job sera de la forme "#+#" où le premier nombre est le "leader du job hétérogène" et le second nombre est le décalage d'origine zéro pour chaque composant du job.
%I
Nombre de cœurs par socket demandé par le job. Ceci rapporte la valeur de l'option srun --cores-per-socket. Lorsque --cores-per-socket n'a pas été défini, "*" est affiché. (Valide pour les jobs uniquement)
%j
Nom du job ou de l'étape du job. (Valide pour les jobs et les étapes de jobs)
%J
Nombre de threads par cœur demandé par le job. Ceci rapporte la valeur de l'option srun --threads-per-core. Lorsque --threads-per-core n'a pas été défini, "*" est affiché. (Valide pour les jobs uniquement)
%k
Commentaire associé au job. (Valide pour les jobs uniquement)
%K
Index du tableau de jobs. Par défaut, la taille de ce champ sera limitée à 64 octets. Utilisez la variable d'environnement SLURM_BITSTR_LEN pour spécifier des tailles de champ plus grandes. (Valide pour les jobs uniquement)
%l
Limite de temps du job ou de l'étape du job en jours-heures:minutes:secondes. La valeur peut être "NOT_SET" si pas encore établie ou "UNLIMITED" pour aucune limite. (Valide pour les jobs et les étapes de jobs)
%L
Temps restant pour l'exécution du job en jours-heures:minutes:secondes. Cette valeur est calculée en soustrayant le temps utilisé par le job de sa limite de temps. La valeur peut être "NOT_SET" si pas encore établie ou "UNLIMITED" pour aucune limite. (Valide pour les jobs uniquement)
%m
Taille minimale de mémoire (en Mo) demandée par le job. (Valide pour les jobs uniquement) Si la mémoire a été demandée par CPU, ou par GPU, la valeur est affichée en supposant qu'au moins un CPU, un GPU sera alloué respectivement.
%M
Temps utilisé par le job ou l'étape du job en jours-heures:minutes:secondes. Les jours et les heures sont imprimés uniquement si nécessaire. Pour les étapes de jobs, ce champ indique le temps écoulé depuis le début de l'exécution et sera donc inexact pour les étapes de jobs qui ont été suspendues. Le décalage d'horloge entre les nœuds du cluster rendra le temps inexact. Si le temps est manifestement faux (par exemple, négatif), il s'affiche comme "INVALID". (Valide pour les jobs et les étapes de jobs)
%n
Liste des noms de nœuds explicitement demandés par le job. (Valide pour les jobs uniquement)
%N
Liste des nœuds alloués au job ou à l'étape du job. Dans le cas d'un job COMPLETING, la liste des nœuds comprendra uniquement ceux qui n'ont pas encore été remis en service. (Valide pour les jobs et les étapes de jobs)
%o
La commande à exécuter.
%O
Des nœuds contigus sont-ils demandés par le job. (Valide pour les jobs uniquement)
%p
Priorité du job (convertie en nombre flottant entre 0.0 et 1.0). Voir aussi %Q. (Valide pour les jobs uniquement)
%P
Partition du job ou de l'étape du job. (Valide pour les jobs et les étapes de jobs)
%q
Qualité de service associée au job. (Valide pour les jobs uniquement)
%Q
Priorité du job (généralement un entier non signé très grand). Voir aussi %p. (Valide pour les jobs uniquement)
%r
La raison pour laquelle un job est dans son état actuel. Voir la section CODES DE RAISON DES JOBS ci-dessous pour plus d'informations. (Valide pour les jobs uniquement)
%R
Pour les jobs en attente : la raison pour laquelle le job n'a pas été démarré par le planificateur est imprimée entre parenthèses. Pour les jobs terminés avec échec : une explication de la cause de l'échec du job est imprimée entre parenthèses. Pour tous les autres états de jobs : la liste des nœuds alloués. Voir la section CODES DE RAISON DES JOBS ci-dessous pour plus d'informations. (Valide pour les jobs uniquement)
%s
SLUID (Valide pour les jobs uniquement)
%S
Heure de début réelle ou prévue du job ou de l'étape du job. (Valide pour les jobs et les étapes de jobs)
%t
État du job sous forme compacte. Voir la section CODES D'ÉTAT DES JOBS ci-dessous pour une liste des états possibles. (Valide pour les jobs uniquement)
%T
État du job sous forme étendue. Voir la section CODES D'ÉTAT DES JOBS ci-dessous pour une liste des états possibles. (Valide pour les jobs uniquement)
%u
Nom d'utilisateur pour un job ou une étape de job. (Valide pour les jobs et les étapes de jobs)
%U
ID d'utilisateur pour un job ou une étape de job. (Valide pour les jobs et les étapes de jobs)
%v
Réservation pour le job. (Valide pour les jobs uniquement)
%V
L'heure de soumission du job.
%w
Clé de caractérisation de la charge de travail (wckey). (Valide pour les jobs uniquement)
%W
Licences demandées par le job. (Valide pour les jobs uniquement)
%x
Liste des noms de nœuds explicitement exclus par le job. (Valide pour les jobs uniquement)
%X
Nombre de cœurs réservés sur chaque nœud pour l'utilisation système (spécialisation de cœur). (Valide pour les jobs uniquement)
%y
Valeur nice (ajustement de la priorité de planification d'un job). (Valide pour les jobs uniquement)
%Y
Pour les jobs en attente, une liste des nœuds qui devraient être utilisés lorsque le job sera démarré.
%z
Nombre de sockets, cœurs et threads demandés (S:C:T) par nœud pour le job. Lorsque (S:C:T) n'a pas été défini, "*" est affiché. (Valide pour les jobs uniquement)
%Z
Le répertoire de travail du job.
-O, --Format=<format_sortie>
Spécifie les informations à afficher. Voir également l'option -o, --format=<format_sortie> décrite ci-dessus (qui prend en charge une plus grande flexibilité dans le formatage, mais ne prend pas en charge l'accès à tous les champs car nous avons manqué de lettres). Demande une liste d'informations sur les jobs séparées par des virgules à afficher.

Le format de chaque champ est "type[:[.][taille][suffixe]]"

taille
Taille minimale du champ. Si aucune taille n'est spécifiée, 20 caractères seront alloués pour imprimer les informations.

Indique que la sortie doit être justifiée à droite et que la taille doit être spécifiée. Par défaut, la sortie est justifiée à gauche.
suffixe
Chaîne arbitraire à ajouter à la fin du champ.

PERFORMANCE

L'exécution de squeue envoie un appel de procédure distante à slurmctld. Si suffisamment d'appels provenant de squeue ou d'autres commandes client Slurm qui envoient des appels de procédure distante au démon slurmctld arrivent en même temps, cela peut entraîner une dégradation des performances du démon slurmctld, entraînant potentiellement un déni de service.

N'exécutez pas squeue ou d'autres commandes client Slurm qui envoient des appels de procédure distante à slurmctld à partir de boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à squeue au minimum nécessaire pour les informations que vous essayez de collecter.

VARIABLES D'ENVIRONNEMENT

Certaines options de squeue peuvent être définies via des variables d'environnement. Ces variables d'environnement, ainsi que leurs options correspondantes, sont listées ci-dessous. (Note: les options de la ligne de commande remplaceront toujours ces paramètres.)

SLURM_BITSTR_LEN
Spécifie la longueur de chaîne à utiliser pour conserver l'expression d'identifiant de tâche d'un tableau de travaux. La valeur par défaut est de 64 octets. Une valeur de 0 imprimera l'expression complète avec toute la longueur requise. Des valeurs plus grandes peuvent avoir un impact négatif sur les performances de l'application.
SLURM_CLUSTERS
Identique à --clusters
SLURM_CONF
L'emplacement du fichier de configuration Slurm.
SLURM_DEBUG_FLAGS
Spécifie les indicateurs de débogage que squeue doit utiliser. Voir DebugFlags dans la page man slurm.conf(5) pour une liste complète des indicateurs. La variable d'environnement prime sur le paramètre dans slurm.conf.
SLURM_JSON
Contrôle la sérialisation JSON :
compact
Produit la sortie JSON aussi compacte que possible.
pretty
Produit la sortie JSON dans un format esthétique pour la rendre plus lisible.
SLURM_TIME_FORMAT
Spécifie le format utilisé pour afficher les horodatages. Une valeur de standard, la valeur par défaut, génère une sortie sous la forme "année-mois-jourHeure:minute:seconde". Une valeur de relative renvoie uniquement "heure:minute:seconde" si c'est le jour actuel. Pour les autres dates de l'année en cours, elle affiche "heure:minute" précédé de "Demain", "Hier", le nom du jour de la semaine à venir (par exemple, "Lun", "Mar", etc.), sinon la date (par exemple, "25 Avr"). Pour les autres années, elle renvoie une date, un mois et une année sans heure (par exemple, "6 Juin 2012"). Tous les horodatages utilisent un format de 24 heures.

Un format strftime() valide peut également être spécifié. Par exemple, une valeur de " %a %T " affichera le jour de la semaine et un horodatage (par exemple, "Lun 12:34:56").

SLURM_YAML
Contrôle la sérialisation YAML :
compact Produit la sortie YAML aussi compacte que possible.
pretty Produit la sortie YAML dans un format esthétique pour la rendre plus lisible.

EXEMPLES

Afficher les jobs planifiés dans la partition debug et dans l'état COMPLETED dans le format avec six chiffres justifiés à droite pour l'identifiant du job suivi de la priorité avec une taille de champ arbitraire :
$ squeue -p debug -t COMPLETED -o "%.6i %p"
 JOBID PRIORITY
 65543 99993
 65544 99992
 65545 99991
Afficher les étapes de jobs dans la partition debug triées par utilisateur :
$ squeue -s -p debug -S u
  STEPID        NAME PARTITION     USER      TIME NODELIST
 65552.1       test1     debug    alice      0:23 dev[1-4]
 65562.2     big_run     debug      bob      0:18 dev22
 65550.1      param1     debug  candice   1:43:21 dev[6-12]
Afficher des informations uniquement sur les jobs 12345, 12346 et 12348 :
$ squeue --jobs 12345,12346,12348
 JOBID PARTITION NAME USER ST  TIME  NODES NODELIST(REASON)
 12345     debug job1 dave  R   0:21     4 dev[9-12]
 12346     debug job2 dave PD   0:00     8 (Resources)
 12348     debug job3 ed   PD   0:00     4 (Priority)
Afficher des informations uniquement sur l'étape de job 65552.1 :
$ squeue --steps 65552.1
  STEPID     NAME PARTITION    USER    TIME  NODELIST
 65552.1    test2     debug   alice   12:49  dev[1-4]
