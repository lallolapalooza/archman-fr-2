SQ(1) Commandes Utilisateur SQ(1)

NOM

sq-pki-vouch - Gérer les certifications

SYNTAXE

sq pki vouch add [OPTIONS]
sq pki vouch authorize [OPTIONS]
sq pki vouch list [OPTIONS]
sq pki vouch replay [OPTIONS]

DESCRIPTION

Gère les certifications.

Un "vouch" (témoignage/validation) est une déclaration potentiellement publique qu'une chose est vraie. Dans OpenPGP, il existe deux types principaux de déclarations que vous pouvez faire : les certifications et les autorisations.

Vous pouvez affirmer qu'un certificat appartient à une entité particulière. Cela ne dit rien sur la fiabilité de l'entité. Par exemple, vous pourriez certifier `bob@nsa.gov` pour un certificat donné. Cela signifie simplement que vous pensez que la personne derrière l'adresse e-mail `bob@nsa.gov` contrôle réellement ce certificat. C'est une déclaration utile même si vous ne faites pas confiance à cette personne pour agir dans votre intérêt.

Alternativement, vous pouvez dire que vous pensez qu'un certificat est un introduiteur de confiance raisonnable. Un introduiteur de confiance est une tierce partie que vous autorisez à faire des introductions. Par exemple, votre banque pourrait avoir une autorité de certification (AC). Si vous vérifiez l'empreinte digitale de l'AC, vous pouvez l'autoriser à faire des certifications. Cela signifie que sq utilisera ces certifications presque comme si vous les aviez faites. C'est pratique car vous pouvez maintenant authentifier n'importe lequel des employés de la banque.

Autoriser un introduiteur de confiance donne beaucoup de pouvoir à cet introduiteur. Vous pouvez limiter la puissance que vous lui accordez en disant qu'il n'est autorisé qu'à certifier des User IDs qui ont une adresse e-mail dans un ou plusieurs domaines, par exemple. De cette façon, vous pouvez tirer parti des endroits où vos intérêts et ceux d'une AC sont alignés, et vous protéger contre des actions potentiellement malveillantes. Par exemple, vous pourriez autoriser l'AC de votre banque à certifier des User IDs ayant une adresse e-mail dans `bank.com`. sq ignorera alors toutes les autres certifications faites par l'AC.

SOUS-COMMANDES

sq pki vouch add

Certifie un User ID pour un Certificat.

En utilisant une certification, un détenteur de clé peut attester du fait qu'un autre certificat appartient légitimement à un User ID. Dans le contexte des e-mails, cela signifie que la même entité contrôle la clé et l'adresse e-mail. Ces types de certifications forment la base du Web de Confiance.

Cette commande émet le certificat avec la nouvelle certification. Le certificat mis à jour doit être distribué, de préférence en l'envoyant au détenteur du certificat pour approbation. Voir aussi `sq key approvals`.

Par défaut, une certification expire après 10 ans. L'utilisation de l'argument `--expiration` permet de définir des périodes de validité spécifiques. Elle permet de spécifier un point dans le temps pour la fin de la validité ou une durée de validité.

`sq pki vouch add` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Elle définit l'heure de création de la certification à l'heure de référence.

sq pki vouch authorize

Marque un certificat comme introduiteur de confiance.

Crée une certification qui indique que l'émetteur considère le certificat comme un introduiteur de confiance. Un introduiteur de confiance est un autre mot pour autorité de certification (AC). Lorsqu'un utilisateur se fie à un introduiteur de confiance, il considère les certifications faites par cet introduiteur comme valides. Un introduiteur de confiance peut également désigner d'autres introduiteurs de confiance.

En l'état, un introduiteur de confiance a beaucoup de pouvoir. Ce pouvoir peut être limité de plusieurs manières.


- La capacité de spécifier d'autres introduiteurs peut être restreinte à l'aide du paramètre `--depth`.


- Le degré de confiance accordé à un introduiteur peut être modifié à l'aide du paramètre `--amount`.


- Les User IDs qu'un introduiteur peut certifier peuvent être restreints par domaine à l'aide du paramètre `--domain` ou par une expression régulière à l'aide du paramètre `--regex`.

Ces mécanismes permettent à Alice de dire qu'elle est disposée à se fier à l'AC, par exemple pour example.org, mais seulement pour les User IDs ayant une adresse e-mail pour example.org, par exemple.

Par défaut, une délégation expire après 10 ans. Utilisez l'argument `--expiration` pour modifier cela.

Cette sous-commande respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Elle définit l'heure de création de la certification à l'heure de référence.

sq pki vouch list

Liste les certifications.

Si l'argument certifieur est fourni, alors les certifications faites par le certificat spécifié sont affichées. Si l'argument certificat est fourni, alors les certifications du certificat spécifié sont affichées. Si les deux sont fournis, alors les certifications du certificat spécifié faites par le certifieur spécifié sont affichées.

Cette commande liste toutes les certifications, pas seulement la certification active.

Étant donné que les certifications sont associées au certificat certifié et non au certificat du certifieur, cette liste est probablement incomplète.

Stable depuis 1.2.0.

sq pki vouch replay

Rejoue les témoignages.

Cette commande rejoue les témoignages faits par un certificat en utilisant un autre certificat. Ceci est principalement utile lorsque vous remplacez un certificat, et que vous souhaitez que le nouveau certificat ait fait les mêmes certifications que vous aviez faites avec l'ancien certificat.

Étant donné que les certifications sont associées au certificat certifié, et non au certificat du certifieur, cela peut ne pas rejouer toutes les certifications que la source a jamais faites.

Cette commande copie uniquement la certification active pour un User ID et un certificat donnés. Cela inclut les certifications exportables (témoignages) ainsi que les certifications non exportables (liens). Elle exclut les certifications expirées. Elle ne rejoue pas non plus les certifications faites sur des certificats invalides, expirés ou révoqués, ou des User IDs révoqués.

Cette commande rejoue tous les paramètres de certification, y compris toute heure d'expiration, mais l'heure de création est définie à l'heure actuelle.

Stable depuis 1.2.0.

EXEMPLES

sq pki vouch add

Alice certifie que Bob contrôle 3F68CB84CE537C9A et bob@example.org.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--email=bob@example.org

Alice certifie que Bob contrôle 3F68CB84CE537C9A et bob@bobs.lair.net, qui n'est pas un User ID auto-signé.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--add-email=bob@bobs.lair.net

sq pki vouch authorize

Certifie que E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F est un introduiteur de confiance pour example.org et example.com.

sq pki vouch authorize \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F \
--domain=example.org --domain=example.com --all

sq pki vouch list

Liste les certifications faites par Alice.

sq pki vouch list \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Liste les certifications faites par Alice pour le certificat de Bob.

sq pki vouch list \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A
