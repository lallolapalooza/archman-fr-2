NOM

sq-cert-list - Lister les certificats et les identifiants utilisateur

SYNTAXE

sq cert list [OPTIONS] EMPREINTE|IDCLEF|MOTIF

DESCRIPTION

Lister les certificats et les identifiants utilisateur.

Lister les certificats et les identifiants utilisateur qui correspondent à une requête, sont utilisables et peuvent être authentifiés. Par défaut, les liaisons (paires certificat et identifiant utilisateur) doivent être entièrement authentifiées. Si aucun certificat ou liaison ne correspond à une requête, la commande renvoie un code de sortie non nul.

Si aucune requête n'est fournie, toutes les liaisons utilisables et authentifiables sont listées. S'il n'y a pas de telles liaisons, la commande réussit quand même.

Par défaut, les certificats inutilisables, c'est-à-dire ceux qui ne sont pas valides selon la politique, sont révoqués, ou ne sont pas actifs, sont ignorés. De même, les auto-signatures d'identifiants utilisateur et les certifications qui ne sont pas valides selon la politique, et les identifiants utilisateur qui sont révoqués sont ignorés.

OPTIONS

Options de sous-commande

--amount=MONTANT
Le montant de confiance requis
120 indique une authentification complète ; les valeurs inférieures à 120 indiquent une authentification partielle. Lorsque `--certification-network` est passé, la valeur par défaut est 1200, c'est-à-dire que cette commande tente de trouver 10 chemins.
--cert=EMPREINTE|IDCLEF
Lister les certificats avec l'empreinte ou l'ID de clé spécifié
Note : les empreintes et les ID de clé sont des identifiants auto-authentifiants. En tant que tels, un certificat avec l'empreinte ou l'ID de clé spécifié est considéré comme authentifié ; aucun identifiant utilisateur n'a besoin d'être authentifié.
--cert-domain=DOMAINE
Lister les liaisons avec des identifiants utilisateur qui contiennent une adresse e-mail dans le domaine spécifié
Le domaine d'un identifiant utilisateur est extrait de l'adresse e-mail, le cas échéant, et est normalisé en utilisant la normalisation puny-code.
--cert-email=EMAIL
Lister les liaisons avec des identifiants utilisateur qui contiennent l'adresse e-mail spécifiée
Les adresses e-mail sont d'abord normalisées en appliquant la normalisation puny-code au domaine, et en mettant en minuscules la partie locale dans le soi-disant locale vide.
--cert-grep=MOTIF
Lister les liaisons avec un identifiant utilisateur qui contient le motif
Effectue une recherche de sous-chaîne insensible à la casse. Le pliage de casse est effectué dans le locale vide.
--cert-userid=USERID
Lister les liaisons avec l'identifiant utilisateur spécifié
L'identifiant utilisateur doit correspondre exactement.
--certification-network
Traite le réseau comme un réseau de certification
Normalement, le mécanisme d'authentification traite le réseau Web de Confiance comme un réseau d'authentification où une certification signifie seulement que la liaison est correcte, mais pas que la cible doit être traitée comme un introducteur de confiance. Dans un réseau de certification, les cibles des certifications sont traitées comme des introducteurs de confiance d'une profondeur infinie, et toutes les expressions régulières sont ignorées. Note : Le montant de confiance reste inchangé. C'est ainsi que fonctionnent la plupart des algorithmes de recherche de chemin dits PGP.
--gossip
Traite tous les certificats comme des racines de confiance non fiables
Cette option est utile pour comprendre ce que les autres pensent d'un certificat (c'est-à-dire les commérages ou les ouï-dire). Autrement dit, cela trouve des chemins arbitraires vers un certificat particulier.
Les commérages sont utiles pour identifier des moyens alternatifs d'authentifier un certificat. Par exemple, imaginez qu'Ed veuille authentifier le certificat de Laura, mais que lui demander directement soit peu pratique. Ed découvre que Micah a certifié le certificat de Laura, mais Ed n'a pas encore authentifié le certificat de Micah. Si Ed est prêt à se fier à Micah en tant qu'introducteur de confiance, et que l'authentification du certificat de Micah est plus facile que l'authentification du certificat de Laura, alors Ed a découvert un moyen plus facile d'authentifier le certificat de Laura.
Stable depuis 1.1.0.
--show-paths
Afficher pourquoi une liaison est authentifiée
Par défaut, seul le degré d'authentification d'une liaison identifiant utilisateur et certificat (une valeur comprise entre 0 et 120) est affiché. Ceci modifie la sortie pour montrer également comment cette valeur a été calculée en affichant les chemins des racines de confiance vers les liaisons.
--unusable
Afficher les liaisons qui sont inutilisables
Normalement, les certificats et liaisons inutilisables ne sont pas affichés. Cette option prend en compte les liaisons, même si elles ne sont pas inutilisables, parce qu'elles (ou les certificats) ne sont pas valides selon la politique, sont révoquées, ou ne sont pas actives.
Cette option n'a de sens qu'avec `--gossip`, car les liaisons inutilisables sont toujours considérées comme non authentifiées.
Stable depuis 1.1.0.

EMPREINTE|IDCLEF|MOTIF
Lister les certificats qui correspondent au motif
Si le motif semble être une empreinte ou un ID de clé, il est traité comme s'il avait été passé à `--cert`, qui correspond à l'empreinte du certificat. Sinon, il est traité comme s'il avait été passé à `--cert-grep`, qui correspond aux identifiants utilisateur.

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Lister toutes les liaisons pour les identifiants utilisateur contenant une adresse e-mail de example.org, et qui peuvent être authentifiées.

sq cert list @example.org

Lister toutes les liaisons authentifiées pour les identifiants utilisateur contenant une adresse e-mail spécifique.

sq cert list --cert-email=alice@example.org

Lister tous les chemins vers les certificats contenant une adresse e-mail spécifique.

sq cert list --gossip --show-paths \
--cert-email=alice@example.org

VOIR AUSSI

NOM

sq-cert-list — Liste les certificats d'un magasin de certificats.

SYNTAXE

sq-cert-list [options] [fichier_magasin]...

DESCRIPTION

La commande sq-cert-list liste les certificats d'un magasin de certificats spécifié. Si aucun fichier de magasin n'est spécifié, elle essaie d'ouvrir les magasins de certificats par défaut.

OPTIONS

  • -p, --password=MOT_DE_PASSE : Spécifie le mot de passe du magasin de certificats.
  • -f, --format=FORMAT : Spécifie le format de sortie (par défaut : json). Les formats pris en charge sont json, pem, text.
  • -o, --output=FICHIER : Écrit la sortie dans le fichier spécifié.
  • -h, --help : Affiche l'aide et quitte.
  • -v, --version : Affiche les informations de version et quitte.

EXEMPLES

Lister tous les certificats du magasin par défaut au format JSON :

sq-cert-list

Lister les certificats d'un fichier de magasin spécifique au format PEM :

sq-cert-list --format pem my_store.p12

Lister les certificats avec un mot de passe et enregistrer la sortie dans un fichier :

sq-cert-list --password=mysecret --output=certs.json my_store.pfx

VOIR AUSSI

sq-key-export(1), sq-cert-add(1), sq-cert-remove(1)
