NOM

sq-network-wkd-publish - Publier des certificats dans un répertoire Web Key Directory

SYNTAXE

sq network wkd publish [OPTIONS] DEST

DESCRIPTION

Publie des certificats ou des mises à jour de certificats dans un répertoire Web Key Directory (WKD). Vous pouvez créer ou mettre à jour une hiérarchie WKD sur le système local en spécifiant un chemin comme destination.

Généralement, un WKD est stocké sur un serveur web. Si `--rsync` est spécifié, cette commande gère les hiérarchies de répertoires WKD distantes en utilisant rsync(1).

Pour insérer un nouveau certificat dans le WKD, utilisez `--cert`.

Toutes les mises à jour pour les certificats existants dans le WKD sont automatiquement publiées.

Note : Pour mettre à jour une hiérarchie WKD, elle est d'abord copiée dans un emplacement temporaire sur la machine locale, les nouveaux certificats ou les mises à jour de certificats sont insérés dans la copie locale, et la hiérarchie est copiée à nouveau dans son emplacement d'origine. Comme ce n'est pas une opération atomique, il faut veiller à éviter les mises à jour concurrentes.

OPTIONS

Options de sous-commande

--all
Publier les certificats authentifiés avec un ID utilisateur correspondant au domaine
Utilise tous les certificats dont l'ID utilisateur correspond au domaine donné au paramètre `--domain` et qui peuvent être entièrement authentifiés.
--cert=EMPREINTE|IDCLEF
Utiliser les certificats avec l'empreinte ou l'ID de clé spécifié(e)
--cert-email=EMAIL
Utiliser les certificats où un ID utilisateur inclut l'adresse e-mail spécifiée
--cert-file=CHEMIN
Lire les certificats depuis CHEMIN
--cert-userid=IDUTILISATEUR
Utiliser les certificats avec l'ID utilisateur spécifié
--create
Créer la hiérarchie WKD si elle n'existe pas encore
--domain=FQDN
Générer un WKD pour un nom de domaine pleinement qualifié pour les e-mails
--method=METHODE
Sélectionner le type de hiérarchie WKD à créer
La méthode avancée, qui est la valeur par défaut et devrait être préférée, est hébergée sur un domaine séparé (par ex. openpgpkey.example.org).
La méthode directe est hébergée sur le même domaine (par ex. example.org).
[valeurs possibles : advanced, direct]
--rsync
Utiliser rsync(1) pour accéder à DEST
--rsync-path=RSYNC
Chemin vers la commande rsync locale à utiliser, implique --rsync

DEST
Emplacement du WKD sur la machine locale ou distante
Si --rsync est spécifié, cela est passé tel quel à rsync(1).

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Créer une nouvelle hiérarchie WKD dans le répertoire local `public_html` et y insérer le certificat d'Alice.

sq network wkd publish --create \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--domain=example.org public_html

Ajouter le certificat de Bob à la hiérarchie WKD existante dans le répertoire local `public_html`.

sq network wkd publish \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--domain=example.org public_html

Ajouter tous les certificats avec un ID utilisateur authentifié dans example.org à la hiérarchie WKD existante.

sq network wkd publish --domain=example.org --all public_html

Actualiser tous les certificats dans la hiérarchie WKD existante dans le répertoire local `public_html` depuis le magasin de certificats.

sq network wkd publish --domain=example.org public_html
