NOM

sq-pki-authenticate - Authentifier une liaison

SYNTAXE

sq pki authenticate [OPTIONS]

DESCRIPTION

Authentifier une liaison.

Authentifie une liaison (un certificat et un ID utilisateur) en recherchant un chemin depuis les racines de confiance jusqu'à la liaison spécifiée dans le Web de Confiance. Comme les certifications peuvent exprimer une incertitude (c'est-à-dire que les certifications peuvent être marquées comme n'apportant qu'une confiance partielle ou marginale), plusieurs chemins peuvent être nécessaires.

Une erreur est renvoyée si aucune liaison n'a pu être authentifiée au niveau spécifié (par défaut : authentifiée complètement, c'est-à-dire un montant de confiance de 120).

Si des chemins valides vers la liaison sont trouvés, ils sont imprimés sur la sortie standard, qu'ils soient suffisants pour authentifier la liaison ou non.

OPTIONS

Options de sous-commande

--amount=MONTANT
Le montant de confiance requis
120 indique une authentification complète ; les valeurs inférieures à 120 indiquent une authentification partielle. Lorsque `--certification-network` est passé, cette option prend par défaut la valeur 1200, c'est-à-dire que cette commande tente de trouver 10 chemins.
--cert=EMPREINTE|IDCLEF
Utiliser les certificats avec l'empreinte ou l'ID de clé spécifié
--certification-network
Traiter le réseau comme un réseau de certification
Normalement, le mécanisme d'authentification traite le réseau Web de Confiance comme un réseau d'authentification où une certification signifie seulement que la liaison est correcte, pas que la cible doit être traitée comme un introduiteur de confiance. Dans un réseau de certification, les cibles des certifications sont traitées comme des introduiteurs de confiance avec une profondeur infinie, et toutes les expressions régulières sont ignorées. Remarque : Le montant de confiance reste inchangé. C'est ainsi que fonctionnent la plupart des algorithmes de recherche de chemins PGP.
--email=EMAIL
Authentifier l'adresse e-mail spécifiée
Cela vérifie s'il est possible d'authentifier un ID utilisateur avec l'adresse e-mail spécifiée. Les ID utilisateur n'ont pas besoin d'être auto-signés. Pour authentifier un ID utilisateur contenant uniquement l'adresse e-mail spécifiée, utilisez `--userid <EMAIL>`.
--gossip
Traiter tous les certificats comme des racines de confiance non fiables
Cette option est utile pour déterminer ce que les autres pensent d'un certificat (c'est-à-dire les rumeurs ou les ouï-dire). En d'autres termes, cela trouve des chemins arbitraires vers un certificat particulier.
Le bavardage est utile pour identifier des moyens alternatifs d'authentifier un certificat. Par exemple, imaginez qu'Ed souhaite authentifier le certificat de Laura, mais qu'il est gênant de la contacter directement. Ed découvre que Micah a certifié le certificat de Laura, mais Ed n'a pas encore authentifié le certificat de Micah. Si Ed est prêt à se fier à Micah en tant qu'introduiteur de confiance, et que l'authentification du certificat de Micah est plus facile que celle du certificat de Laura, alors Ed a appris un moyen plus simple d'authentifier le certificat de Laura.
Stable depuis 1.1.0.
--show-paths
Afficher pourquoi une liaison est authentifiée
Par défaut, seul le degré d'authentification d'un ID utilisateur et d'une liaison de certificat (une valeur comprise entre 0 et 120) est affiché. Ceci modifie la sortie pour montrer également comment cette valeur a été calculée en affichant les chemins depuis les racines de confiance jusqu'aux liaisons.
--unusable
Afficher les liaisons qui sont inutilisables
Normalement, les certificats et les liaisons inutilisables ne sont pas affichés. Cette option prend en compte les liaisons, même si elles ne sont pas inutilisables, car elles (ou les certificats) ne sont pas valides selon la politique, sont révoquées ou ne sont pas actives.
Cette option n'a de sens qu'avec `--gossip`, car les liaisons inutilisables sont toujours considérées comme non authentifiées.
Stable depuis 1.1.0.
--userid=IDUTILISATEUR
Authentifier l'ID utilisateur spécifié
L'ID utilisateur spécifié n'a pas besoin d'être auto-signé.

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Authentifier une liaison spécifique.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --userid \
"Alice <alice@example.org>"

Vérifier si nous pouvons authentifier n'importe quel ID utilisateur avec l'adresse e-mail spécifiée pour le certificat donné.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --email \
alice@example.org
