SQ(1) Commandes utilisateur SQ(1)

NOM

sq - Une interface en ligne de commande pour Sequoia, une implémentation d'OpenPGP

SYNTAXE

sq encrypt [OPTIONS] FICHIER
sq decrypt [OPTIONS] FICHIER
sq sign [OPTIONS] FICHIER
sq verify [OPTIONS] FICHIER
sq download [OPTIONS]
sq inspect [OPTIONS] FICHIER
sq cert [OPTIONS] SOUS-COMMANDE
sq key [OPTIONS] SOUS-COMMANDE
sq pki [OPTIONS] SOUS-COMMANDE
sq network [OPTIONS] SOUS-COMMANDE
sq keyring [OPTIONS] SOUS-COMMANDE
sq packet [OPTIONS] SOUS-COMMANDE
sq config [OPTIONS] SOUS-COMMANDE
sq version [OPTIONS]

DESCRIPTION

Une interface en ligne de commande pour Sequoia, une implémentation d'OpenPGP.

Les fonctionnalités sont regroupées et disponibles à l'aide de sous-commandes. Cette interface n'est pas complètement sans état. En particulier, le magasin de certificats par défaut de l'utilisateur est utilisé. Ceci peut être désactivé en utilisant `--cert-store=none`. De même, un magasin de clés est utilisé pour gérer et protéger le matériel des clés secrètes. Ceci peut être désactivé en utilisant `--key-store=none`.

Les données OpenPGP peuvent être fournies sous forme binaire ou armurée ASCII. Celles-ci seront gérées automatiquement. Les données OpenPGP émises sont armurées ASCII par défaut.

Nous utilisons le terme « certificat » pour désigner les clés OpenPGP qui ne contiennent pas de secrets. Inversement, nous utilisons le terme « clé » pour désigner les clés OpenPGP qui contiennent des secrets.

OPTIONS

Options globales

--batch
Empêche toute forme d'invite
Active le mode batch. En mode batch, sq ne demandera jamais d'entrée utilisateur, comme les mots de passe.
--cert-store=CHEMIN
Spécifie l'emplacement du magasin de certificats
Par défaut, `sq` utilise le répertoire de certificats OpenPGP du répertoire d'accueil de Sequoia (voir `--home`), $HOME/.local/share/pgp.cert.d. Ceci peut être remplacé en définissant la variable d'environnement `PGP_CERT_D`.
Utilisez 'default' pour utiliser explicitement le magasin de certificats par défaut, utilisez 'none' pour ne pas utiliser de magasin de certificats.
--cli-version=VERSION_CLI
Sélectionne une version CLI
L'interface CLI de `sq` est versionnée selon un schéma de versionnement sémantique. Définir cette option provoque une erreur si `sq` n'implémente pas une interface compatible avec la version spécifiée. Par exemple, si vous la définissez sur 1.1.0 et que `sq` n'implémente que la version 1.0.0 de l'interface, alors `sq` générera une erreur.
`sq` peut implémenter plusieurs interfaces (par exemple, 1.1.4 et 2.0.5). Par défaut, il sélectionne la version la plus récente. Ainsi, si vous avez besoin d'une interface particulière, vous devez définir cette option pour chaque appel à `sq`.
Cette option doit être la première option sur la ligne de commande.
Cette version de `sq` implémente la version 1.3.1 de l'interface CLI.
Stable depuis 1.2.0.
-h, --help
Affiche l'aide (voir un résumé avec '-h')
--home=CHEMIN
Définit le répertoire personnel
Le répertoire personnel par défaut de Sequoia est `$HOME`. Lors de l'utilisation de l'emplacement par défaut, les fichiers sont placés conformément aux normes locales, par exemple la spécification XDG Base Directory. Lorsqu'un emplacement alternatif est spécifié, les données utilisateur, les fichiers de configuration et les données de cache sont placés sous un seul répertoire unifié. C'est une manière légère d'isoler partiellement `sq`.
Utilisez 'default' pour utiliser explicitement l'emplacement par défaut, utilisez 'none' pour ne pas utiliser de répertoire personnel.
--key-store=CHEMIN
Remplace le serveur de magasin de clés et ses données
Un serveur de magasin de clés gère et protège le matériel des clés secrètes. Par défaut, `sq` se connecte au serveur de magasin de clés pour le répertoire personnel par défaut de Sequoia (voir `--home`), $HOME/.local/share/sequoia/keystore. Si aucun serveur de magasin de clés n'est en cours d'exécution, un est lancé.
Cette option fait que `sq` utilise un serveur de magasin de clés alternatif. Si nécessaire, un serveur de magasin de clés est lancé et configuré pour rechercher ses données dans l'emplacement spécifié.
Utilisez 'default' pour utiliser explicitement le serveur par défaut, utilisez 'none' pour ne pas utiliser de magasin de clés.
--keyring=CHEMIN
Spécifie l'emplacement d'un keyring à utiliser
Les keyrings sont utilisés en plus de tout magasin de certificats. Le contenu du keyring n'est pas importé dans le magasin de certificats. Lorsqu'un certificat est recherché, il est recherché dans tous les keyrings et tout magasin de certificats, et les résultats sont fusionnés.
--known-notation=NOTATION
Ajoute NOTATION à la liste des notations connues
Ceci est utilisé lors de la validation des signatures. Les signatures qui ont des notations inconnues avec le bit critique défini sont considérées comme invalides.
--overwrite
Écrase les fichiers existants
--password-file=FICHIER
Ameute le cache de mots de passe avec le mot de passe spécifié
Le mot de passe est ajouté au cache de mots de passe. Lors du déchiffrement du matériel de clé secrète, le cache de mots de passe n'est utilisé que si la clé n'est pas protégée par un compteur de tentatives, qui verrouille automatiquement la clé si un mauvais mot de passe est saisi trop de fois.
Notez que le fichier de clé entier sera utilisé comme mot de passe, y compris tout espace blanc environnant comme un retour à la ligne final.
--policy-as-of=TEMPS
Sélectionne la politique cryptographique à partir du temps spécifié
Le temps est exprimé comme un horodatage formaté ISO 8601. La politique détermine quels constructeurs cryptographiques sont autorisés.
Si vous travaillez avec un message que sq rejette, car il est protégé par des constructeurs cryptographiques maintenant considérés comme cassés, vous pouvez utiliser cette option pour sélectionner une politique cryptographique différente. Si vous vous fiez à la cryptographie, par exemple, si vous vérifiez une signature, vous ne devriez le faire que si vous êtes sûr que le message n'a pas été altéré.
TEMPS est interprété comme un horodatage ISO 8601. Pour définir le temps de politique au 1er janvier 2007 à minuit UTC, vous pouvez faire :
$ sq --policy-as-of 20070101 verify --message msg.pgp
Par défaut, utilise le temps de référence, qui peut être défini à l'aide de --time.
-q, --quiet
Sois plus silencieux
Le défaut peut être modifié dans le fichier de configuration à l'aide du paramètre `ui.quiet`.
--time=TEMPS
Définit le temps de référence comme un horodatage formaté ISO 8601
Normalement, les commandes utilisent l'heure actuelle comme temps de référence. Cet argument permet à l'utilisateur d'utiliser un temps de référence différent. Par exemple, lors de la création d'une clé à l'aide de `sq key generate`, l'heure de création est normalement définie sur l'heure actuelle, mais peut être remplacée à l'aide de cette option. De même, lors de la vérification d'un message, le message est vérifié par rapport à l'heure actuelle. Cette option permet à l'utilisateur d'utiliser un temps différent.

SOUS-COMMANDES

sq encrypt

Chiffrer un message.

Chiffre un message pour un nombre quelconque de destinataires et avec un nombre quelconque de mots de passe, en signant éventuellement le message au passage.

L'opération inverse est `sq decrypt`.

`sq encrypt` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Il utilise l'heure de référence lors de la sélection des clés de chiffrement et définit l'heure de création de la signature sur l'heure de référence.

sq decrypt

Déchiffrer un message.

Déchiffre un message en utilisant soit les clés fournies, soit en demandant un mot de passe. Si une falsification du message est détectée, une erreur est retournée. Voir ci-dessous pour les détails.

Si des certificats sont fournis en utilisant l'option `--signer-file`, toutes les signatures trouvées sont vérifiées à l'aide de ces certificats. La vérification n'est réussie que s'il n'y a pas de mauvaise signature et si le nombre de signatures vérifiées avec succès atteint le seuil configuré avec le paramètre `--signatures`.

Si la vérification de la signature échoue, ou si une falsification du message est détectée, le programme se termine avec un statut de sortie indiquant l'échec, et le fichier de sortie est supprimé. Si la sortie a été envoyée sur stdout, les 25 derniers MiB du message sont retenus (par conséquent, si le message est inférieur à 25 MiB, aucune sortie n'est produite).

L'opération inverse est `sq encrypt`.

sq sign

Signer des messages ou des fichiers de données.

Crée des messages signés ou des signatures détachées. Les signatures détachées sont souvent utilisées pour signer des paquets logiciels.

L'opération inverse est `sq verify`.

`sq sign` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Lorsqu'elle est définie, elle utilise l'heure spécifiée au lieu de l'heure actuelle pour déterminer quelles clés sont valides, et elle définit l'heure de création de la signature sur l'heure de référence au lieu de l'heure actuelle.

sq verify

Vérifier des messages signés ou des signatures détachées.

Lors de la vérification de messages signés, le message est écrit sur stdout ou dans le fichier donné à `--output`.

Lorsqu'une signature détachée est vérifiée, aucune sortie n'est produite. Les signatures détachées sont souvent utilisées pour signer des paquets logiciels.

La vérification n'est réussie que s'il n'y a pas de mauvaise signature et si le nombre de signatures vérifiées avec succès atteint le seuil configuré avec le paramètre `--signatures`. Si la vérification échoue, le programme se termine avec un statut de sortie indiquant l'échec, et le fichier de sortie est supprimé. Si la sortie a été envoyée sur stdout, les 25 derniers MiB du message sont retenus (par conséquent, si le message est inférieur à 25 MiB, aucune sortie n'est produite).

Une signature est considérée comme authentifiée si le signataire peut être authentifié. Si le signataire est fourni via `--signer-file`, alors le signataire est considéré comme authentifié. Sinon, le signataire est recherché et authentifié en utilisant la Toile de Confiance. Si au moins un identifiant utilisateur peut être entièrement authentifié, alors la signature est considérée comme authentifiée. Si la signature inclut un sous-paquet d'identifiant utilisateur du signataire, alors seul cet identifiant utilisateur est pris en compte. Remarque : l'identifiant utilisateur n'a pas besoin d'être auto-signé.

L'opération inverse est `sq sign`.

Si vous recherchez un programme autonome pour vérifier les signatures détachées, envisagez d'utiliser sequoia-sqv.

`sq verify` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Lorsqu'elle est définie, elle vérifie le message comme à l'heure de référence au lieu de l'heure actuelle.

sq download

Télécharger et authentifier les données.

Cette commande télécharge les données depuis l'URL spécifiée, vérifie la signature, puis authentifie le signataire. Si le signataire ne peut être authentifié, les données sont supprimées, si possible.

sq inspect

Inspecter des données, comme file(1).

Il est souvent difficile de déterminer, par une inspection superficielle avec cat(1) ou file(1), quel type d'OpenPGP on regarde. Cette sous-commande inspecte les données et fournit une description significative et lisible par l'homme.

`sq inspect` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Elle utilise l'heure de référence lors de la détermination des signatures de liaison actives.

sq cert

Gérer les certificats.

Nous utilisons le terme « certificat », ou « cert » en abrégé, pour désigner les clés OpenPGP qui ne contiennent pas de secrets. Cette sous-commande fournit des primitives pour générer et manipuler autrement des certificats.

Inversement, nous utilisons le terme « clé » pour désigner les clés OpenPGP qui contiennent des secrets. Voir `sq key` pour les opérations sur les clés.

sq key

Gérer les clés.

Nous utilisons le terme « clé » pour désigner les clés OpenPGP qui contiennent des secrets. Cette sous-commande fournit des primitives pour générer et manipuler autrement des clés.

Inversement, nous utilisons le terme « certificat », ou « cert » en abrégé, pour désigner les clés OpenPGP qui ne contiennent pas de secrets. Voir `sq cert` pour les opérations sur les certificats.

sq pki

Authentifier les certificats en utilisant la Toile de Confiance.

La « Toile de Confiance » est un modèle de confiance décentralisé popularisé par PGP. C'est un sur-ensemble de X.509, qui est un modèle de confiance hiérarchique, et le modèle de confiance le plus populaire sur l'internet public aujourd'hui. Tel qu'utilisé sur l'internet public, cependant, X.509 repose sur une poignée d'autorités de certification (AC) mondiales qui sapent souvent sa sécurité.

La Toile de Confiance est plus nuancée que X.509. En utilisant la Toile de Confiance, on exige plusieurs chemins indépendants pour authentifier une liaison en ne faisant confiance que partiellement aux AC. Cela empêche qu'un seul acteur malveillant ne compromette leur sécurité. Et ceux qui ont des exigences de sécurité plus strictes peuvent utiliser la Toile de Confiance de manière complètement décentralisée où seuls les individus qu'ils sélectionnent – qui ne sont pas nécessairement des institutions – agissent comme des introducteurs de confiance.

sq network

Récupérer et publier des certificats sur le réseau.

Les certificats OpenPGP peuvent être découverts et mis à jour à partir de, et publiés sur, des services accessibles via le réseau. C'est une collection de commandes pour interagir avec ces services.

sq keyring

Gérer des collections de clés ou de certificats.

Les collections de clés ou de certificats (également appelées « keyrings » lorsqu'elles contiennent du matériel de clé secrète, et « certrings » lorsqu'elles n'en contiennent pas) sont un nombre quelconque de certificats concaténés. Cette sous-commande fournit des outils pour lister, diviser, fusionner et filtrer les keyrings.

Remarque : Dans la documentation de cette sous-commande, nous utilisons parfois les termes clés et certificats de manière interchangeable.

sq packet

Manipulation de paquets de bas niveau.

Un flux de données OpenPGP est constitué de paquets. Ces outils permettent de travailler avec des flux de paquets. Ils intéressent principalement les développeurs, mais `sq packet dump` peut être utile à un public plus large, à la fois pour fournir des informations précieuses dans les rapports de bogues aux logiciels liés à OpenPGP, et comme outil d'apprentissage.

sq config

Interroger, inspecter et créer le fichier de configuration.

Cette sous-commande peut être utilisée pour interroger et inspecter le fichier de configuration (emplacement par défaut : $HOME/.config/sequoia/sq/config.toml), et pour créer un modèle qui peut être édité selon vos préférences.

Fichier de configuration : $HOME/.config/sequoia/sq/config.toml

sq version

Informations détaillées sur la version et la version de sortie.

Sans autres options, cette commande liste la version de `sq`, la version de l'implémentation OpenPGP sous-jacente `sequoia-openpgp`, et la bibliothèque cryptographique utilisée.

NAME

sq - Sequoia PGP Command Line Interface

SYNOPSIS

sq [--help] [--version] [--home PATH] [--store PATH] [SUBCOMMAND]

DESCRIPTION

The Sequoia PGP command line interface (`sq`) is a tool for managing OpenPGP keys and performing cryptographic operations.

OPTIONS

--help
Print a help message and exit.
--version
Print version information and exit.
--home PATH
Use PATH as the Sequoia home directory. Defaults to $HOME/.local/share/sequoia.
--store PATH
Use PATH as the key store. This option overrides the default key store server and its data.
Un serveur de magasin de clés gère et protège le matériel de clé secrète. Par défaut, `sq` se connecte au serveur de magasin de clés du répertoire personnel par défaut de Sequoia (voir `--home`), $HOME/.local/share/sequoia/keystore. Si aucun serveur de magasin de clés n'est en cours d'exécution, un est démarré.
Cette option fait en sorte que `sq` utilise un serveur de magasin de clés alternatif. Si nécessaire, un serveur de magasin de clés est démarré et configuré pour rechercher ses données à l'emplacement spécifié.
Utilisez 'default' pour utiliser explicitement le serveur par défaut, utilisez 'none' pour ne pas utiliser un magasin de clés.

EXAMPLES

sq encrypt

Chiffrer un fichier pour un destinataire donné par empreinte digitale.

sq encrypt --for=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--signer-email=juliet@example.org document.txt

Chiffrer un fichier pour un destinataire donné par e-mail.

sq encrypt --for-email=alice@example.org \
--signer-email=juliet@example.org document.txt

sq decrypt

Déchiffrer un fichier à l'aide d'une clé secrète

sq decrypt --recipient-file juliet-secret.pgp ciphertext.pgp

Déchiffrer un fichier en vérifiant les signatures

sq decrypt --recipient-file juliet-secret.pgp --signer-file \
romeo.pgp ciphertext.pgp

déchiffrer un fichier à l'aide du magasin de clés

sq decrypt ciphertext.pgp

sq sign

Créer un message signé.

sq sign --signer-file juliet-secret.pgp --message document.txt

Créer une signature détachée.

sq sign --signer-file juliet-secret.pgp \
--signature-file=document.txt.sig document.txt

sq verify

Vérifier un message signé.

sq verify --message document.pgp

Vérifier une signature détachée.

sq verify --signature-file=document.sig document.txt

Vérifier un message à la date du 19 juin 2024 à minuit UTC.

sq verify --time 2024-06-19 --message document.pgp

sq download

Télécharger et vérifier le fichier de sommes de contrôle Debian 12.

sq download --url=file://debian/SHA512SUMS \
--signature-url=file://debian/SHA512SUMS.sign \
--signer=DF9B9C49EAA9298432589D76DA87E80D6294BE9B \
--output=SHA512SUMS

sq inspect

Inspecter un certificat.

sq inspect juliet.pgp

Afficher à quoi ressemblait le certificat le 21 juillet 2013.

sq inspect --time 20130721 juliet.pgp

Inspecter un message chiffré.

sq inspect message.pgp

Inspecter une signature détachée.

sq inspect document.sig
