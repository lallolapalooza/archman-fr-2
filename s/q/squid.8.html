NOM

squid - serveur mandataire de cache HTTP pour le web

SYNTAXE

squid [-dhisrvzCFNRSVYX] [--foreground] [-l facility ] [-f fichier-config ] [-[au] port ] [-k signal ] [-n nom-service ] [-O ligne-commande ]

DESCRIPTION

squid est un serveur mandataire de cache HTTP haute performance pour les clients web, prenant en charge les objets de données FTP, ICAP, ICP, HTCP et HTTP. Contrairement aux logiciels de cache traditionnels, Squid traite toutes les requêtes dans un seul processus non bloquant.

Squid conserve les métadonnées et surtout les objets fréquemment utilisés en cache dans la RAM, met en cache les recherches DNS, prend en charge les recherches DNS non bloquantes et implémente le cache négatif des requêtes échouées.

Squid prend en charge SSL, des contrôles d'accès étendus et l'enregistrement complet des requêtes. En utilisant les protocoles légers de cache Internet ICP, HTCP ou CARP, les caches Squid peuvent être organisés en hiérarchie ou en maillage pour des économies de bande passante supplémentaires.

Squid se compose d'un programme serveur principal squid , de quelques programmes optionnels pour le traitement personnalisé et l'authentification, et de certains outils de gestion et clients. Lorsque squid démarre, il lance un nombre configurable de processus auxiliaires, chacun pouvant effectuer des recherches parallèles. Cela réduit le temps que le cache attend pour les résultats.

Squid est dérivé du projet Harvest financé par l'ARPA.

Cette page de manuel ne liste que les arguments de la ligne de commande. Pour plus de détails sur la configuration de Squid, consultez le fichier /etc/squid/squid.conf.documented, la FAQ du wiki Squid et les exemples sur https://wiki.squid-cache.org/ , ou le manuel de configuration sur la page d'accueil de Squid http://www.squid-cache.org/Doc/config/

OPTIONS

-a port
Spécifie le numéro de port HTTP où Squid doit écouter les requêtes, en plus de toute spécification http_port dans squid.conf
-C
Ne pas intercepter les signaux fatals.
-d niveau
Écrire également le débogage dans stderr.
-f fichier
Utiliser le fichier-config donné au lieu de /etc/squid/squid.conf . Si le nom du fichier commence par ! ou | alors il est supposé être une commande externe ou une ligne de commande. Peut par exemple être utilisé pour prétraiter la configuration avant qu'elle ne soit lue par Squid. Pour faciliter cela, Squid comprend également la notion courante #line pour indiquer le vrai fichier source.
-F
Ne servir aucune requête tant que le stockage n'est pas reconstruit.
-h
Afficher le message d'aide.
-i
Installer en tant que service Windows (voir l'option -n).
-k reconfigure | rotate | shutdown | interrupt | kill | debug | check | parse
Analyser le fichier de configuration, puis envoyer le signal à la copie en cours d'exécution (sauf -k parse ) et quitter.
-l facility
Utiliser la facility syslog spécifiée. Implique -s
-n nom
Spécifier le nom du service Windows à utiliser pour les opérations de service, par défaut : Squid
-N
Mode sans daemon.
--foreground
Le processus parent ne se termine pas avant que ses enfants aient fini. Il n'a aucun effet avec -N qui ne fait pas de fork/exit au démarrage.
--kid roleID
Jouer un rôle de processus SMP kid donné, avec un ID donné. N'utilisez pas cette option. Elle est destinée uniquement à l'utilisation par le processus maître.
-O options
Définir les options de ligne de commande du service Windows dans le Registre.
-r
Supprimer un service Windows (voir l'option -n).
-R
Ne pas définir REUSEADDR sur le port.
-s
Activer l'enregistrement dans syslog. Également configurable dans /etc/squid/squid.conf
-S
Vérifier deux fois le swap lors de la reconstruction.
-u port
Spécifier le numéro de port ICP (par défaut : 3130), désactiver avec 0.
-v
Afficher la version et les détails de compilation.
-X
Forcer le débogage complet.
-Y
Retourner uniquement UDP_HIT ou UDP_MISS_NOFETCH lors du rechargement rapide.
-z
Créer les répertoires de swap manquants et autres structures de cache_dir manquantes, puis quitter. Tous les types de cache_dir créent le répertoire de niveau supérieur configuré s'il est manquant. D'autres actions sont spécifiques au type. Par exemple, les systèmes de stockage basés sur ufs créent les répertoires L1 et L2 manquants tandis que Rock crée le fichier de base de données manquant.
Cette option n'active pas la validation des structures de swap présentes. Elle se concentre sur la création des éléments manquants. Si rien ne manque, squid -z se termine simplement. Si vous soupçonnez une corruption de cache_dir, vous devez supprimer le répertoire de niveau supérieur de cache_dir avant d'exécuter squid -z.
Par défaut, squid -z s'exécute en mode daemon (de sorte que les macros de configuration et d'autres fonctionnalités SMP fonctionnent comme prévu), rendant le contrôle à l'appelant avant que les cache_dirs ne soient entièrement initialisés. S'il est exécuté à partir de scripts d'initialisation ou de gestionnaires de daemon, l'appelant doit souvent attendre que l'initialisation soit terminée avant de poursuivre. Utilisez l'option --foreground pour éviter les sorties prématurées. Pour désactiver le mode daemon, utilisez l'option -N.

FICHIERS

Fichiers de configuration de Squid situés dans /etc/squid/ :

squid.conf
Le fichier de configuration principal. Vous devez initialement apporter des modifications à ce fichier pour que squid fonctionne. Par exemple, la configuration par défaut n'autorise l'accès que depuis les réseaux LAN privés RFC. Certaines distributions d'empaquetage bloquent même cela.
squid.conf.default
Copie de référence du fichier de configuration. Toujours maintenue à jour avec la version de Squid que vous utilisez.
Utilisez ceci pour rechercher les paramètres de configuration par défaut et la syntaxe après une mise à niveau.
squid.conf.documented
Copie de référence du fichier de configuration. Toujours maintenue à jour avec la version de Squid que vous utilisez.
Utilisez ceci pour lire la documentation des options de configuration disponibles dans votre build de Squid. Le manuel de configuration en ligne est également disponible pour une référence complète des options. voirhttp://www.squid-cache.org/Doc/config/
msntauth.conf
Le fichier de configuration principal pour l'authentificateur MSNT d'exemple.
errorpage.css
Feuille de style CSS pour contrôler l'affichage des pages d'erreur générées. Utilisez ceci pour définir toute image de marque de votre entreprise nécessaire, cela s'appliquera à toutes les langues pour lesquelles Squid fournit des pages d'erreur.

Certains fichiers sont également situés ailleurs :

/etc/squid/mime.conf (mime_table)
Mappages de types MIME pour le passage FTP
/usr/share/squid/errors
Emplacement des pages et modèles d'erreur de Squid.
