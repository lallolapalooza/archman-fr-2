SQLITE_TABLE(5) Manuel des formats de fichiers SQLITE_TABLE(5)

NOM

sqlite_table - Configuration SQLite de Postfix

SYNTAXE

postmap -q "chaîne" sqlite:/etc/postfix/nom_fichier
postmap -q - sqlite:/etc/postfix/nom_fichier <fichier_entree

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses ou le routage de courrier. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de consultation peuvent être spécifiées comme des bases de données SQLite. Afin d'utiliser les consultations SQLite, définissez une source SQLite comme table de consultation dans main.cf, par exemple :

    alias_maps = sqlite:/etc/postfix/sqlite-aliases.cf

Le fichier /etc/postfix/sqlite-aliases.cf a le même format que le fichier main.cf de Postfix, et peut spécifier les paramètres décrits ci-dessous.

MEMBERSHIP DE LISTES

Lors de l'utilisation de SQL pour stocker des listes telles que $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., il est important de comprendre que la table doit stocker chaque membre de la liste comme une clé distincte. La consultation de la table vérifie l'*existence* de la clé. Voir "Listes Postfix contre tables" dans le document DATABASE_README pour une discussion.

NE PAS créer de tables qui retournent la liste complète des domaines dans $mydestination ou $relay_domains etc., ou les adresses IP dans $mynetworks.

FAIRE créer des tables avec chaque élément correspondant comme clé et avec une valeur arbitraire. Avec les bases de données SQL, il n'est pas rare de retourner la clé elle-même ou une valeur constante.

PARAMETRES SQLITE

dbpath
L'emplacement du fichier de base de données SQLite. Exemple : 
    dbpath = customer_database
query
Le modèle de requête SQL utilisé pour rechercher dans la base de données, où %s est un substitut pour l'adresse que Postfix essaie de résoudre, par exemple : 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Ce paramètre prend en charge les expansions '%' suivantes :

%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la clé d'entrée. Le cytage SQL est utilisé pour s'assurer que la clé d'entrée n'ajoute pas de métacaractères inattendus.
%u
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse citée en SQL. Sinon, %u est remplacé par la chaîne de recherche entière. Si la partie locale est vide, la requête est supprimée et ne retourne aucun résultat.
%d
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse citée en SQL. Sinon, la requête est supprimée et ne retourne aucun résultat.
%[SUD]
Les équivalents majuscules des expansions ci-dessus se comportent dans le paramètre query identiquement à leurs homologues minuscules. Avec le paramètre result_format (voir ci-dessous), ils étendent la clé d'entrée plutôt que la valeur du résultat.
%[1-9]
Les modèles %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.example.com, alors %1 est com, %2 est example et %3 est mail. Si la clé d'entrée n'est pas qualifiée ou n'a pas suffisamment de composants de domaine pour satisfaire tous les modèles spécifiés, la requête est supprimée et ne retourne aucun résultat.
Le paramètre domain décrit ci-dessous limite les clés d'entrée aux adresses dans les domaines correspondants. Lorsque le paramètre domain n'est pas vide, les requêtes SQL pour les adresses non qualifiées ou les adresses dans des domaines non correspondants sont supprimées et ne retournent aucun résultat.

Ce paramètre est disponible avec Postfix 2.2. Dans les versions précédentes, la requête SQL était construite à partir des paramètres séparés : select_field, table, where_field et additional_conditions. La correspondance des anciens paramètres avec la requête équivalente est :

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

Le '%s' dans la clause WHERE est étendu à la chaîne de recherche échappée. Avec Postfix 2.2, ces paramètres hérités sont utilisés si le paramètre query n'est pas spécifié.

NOTE : N'entourez PAS la requête de guillemets.

result_format (par défaut : %s)
Modèle de format appliqué aux attributs de résultat. Le plus souvent utilisé pour ajouter (ou préfixer) du texte au résultat. Ce paramètre prend en charge les expansions '%' suivantes :
%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la valeur de l'attribut de résultat. Lorsque le résultat est vide, il est ignoré.
%u
Lorsque la valeur de l'attribut de résultat est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse. Lorsque le résultat a une partie locale vide, il est ignoré.
%d
Lorsqu'une valeur d'attribut de résultat est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de la valeur de l'attribut. Lorsque le résultat n'est pas qualifié, il est ignoré.
%[SUD1-9]
Les expansions majuscules et chiffres décimaux interpolent les parties de la clé d'entrée plutôt que le résultat. Leur comportement est identique à celui décrit avec query, et en fait, comme la clé d'entrée est connue à l'avance, les requêtes dont la clé ne contient pas toutes les informations spécifiées dans le modèle de résultat sont supprimées et ne retournent aucun résultat.
Par exemple, utiliser "result_format = smtp:[%s]" permet d'utiliser un attribut mailHost comme base d'une table transport(5). Après application du format de résultat, plusieurs valeurs sont concaténées sous forme de chaînes séparées par des virgules. L'expansion_limit et le paramètre expliqués ci-dessous permettent de limiter le nombre de valeurs dans le résultat, ce qui est particulièrement utile pour les cartes qui doivent retourner au plus une valeur.

La valeur par défaut %s spécifie que chaque valeur de résultat doit être utilisée telle quelle.

Ce paramètre est disponible avec Postfix 2.2 et versions ultérieures.

NOTE : N'entourez PAS le format de résultat de guillemets !

domain (par défaut : aucune liste de domaines)
Il s'agit d'une liste de noms de domaines, de chemins de fichiers ou de bases de données "type:table". Lorsqu'il est spécifié, seules les clés de recherche entièrement qualifiées avec une partie locale *non vide* et un domaine correspondant sont éligibles pour la recherche : les recherches de type 'utilisateur', les recherches de domaine nu et les recherches "@domaine" ne sont pas effectuées. Cela peut réduire considérablement la charge de requête sur le serveur SQLite. 
    domain = postfix.org, hash:/etc/postfix/searchdomains

Il est préférable de ne pas utiliser SQL pour stocker les domaines éligibles aux recherches SQL.

Ce paramètre est disponible avec Postfix 2.2 et versions ultérieures.

NOTE : NE PAS définir ce paramètre pour les alias local(8), car les clés d'entrée sont toujours non qualifiées.

expansion_limit (par défaut : 0)
Une limite sur le nombre total d'éléments de résultat retournés (sous forme de liste séparée par des virgules) par une recherche dans la carte. Un réglage de zéro désactive la limite. Les recherches échouent avec une erreur temporaire si la limite est dépassée. Définir la limite à 1 garantit que les recherches ne retournent pas de valeurs multiples.

PARAMETRES OBSOLETES DE MAIN.CF

Pour la compatibilité avec d'autres tables de consultation Postfix, les paramètres SQLite peuvent également être définis dans main.cf. Pour ce faire, spécifiez comme source SQLite un nom qui ne commence pas par une barre oblique ou un point. Les paramètres SQLite seront alors accessibles sous le nom que vous avez donné à la source dans sa définition, un trait de soulignement, et le nom du paramètre. Par exemple, si la carte est spécifiée comme "sqlite:nom_sqlite", le paramètre "query" serait défini dans main.cf comme "nom_sqlite_query".

INTERFACE OBSOLÈTE

Cette section décrit une interface obsolète depuis Postfix 2.2. Elle est remplacée par l'interface query plus générale décrite ci-dessus. Si le paramètre query est défini, les paramètres hérités décrits ici sont ignorés. Veuillez migrer vers la nouvelle interface car l'interface héritée pourrait être supprimée dans une future version.

Les paramètres suivants peuvent être utilisés pour remplir une instruction modèle SELECT de la forme :

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

Le spécificateur %s est remplacé par la chaîne de recherche et est échappé de sorte que s'il contient des apostrophes ou d'autres caractères étranges, il ne provoquera pas d'erreur d'analyse, ou pire, un problème de sécurité.

select_field
Le paramètre SQL « select ». Exemple : 
    select_field = forw_addr
table
Le nom de table SQL « select .. from ». Exemple : 
    table = mxaliases
where_field
Le paramètre SQL « select .. where ». Exemple : 
    where_field = alias
additional_conditions
Conditions supplémentaires à la requête SQL. Exemple : 
    additional_conditions = AND status = 'paid'
