SQ-KEYRING-LINTER(1) Commandes utilisateur SQ-KEYRING-LINTER(1)

NOM

sq-keyring-linter - sq-keyring-linter

DESCRIPTION

sq-keyring-linter 0.5.0

"sq-keyring-linter" vérifie et répare éventuellement les certificats OpenPGP qui utilisent SHA-1.

UTILISATION:

sq-keyring-linter [OPTIONS] [FICHIERS]...

OPTIONS COURTES:

-e, --export-secret-keys

Lors de la réparation d'un certificat, le certificat réparé est exporté sans aucun matériel de clé secrète. L'utilisation de ce commutateur entraîne également l'exportation de tout matériel de clé secrète.

-f, --fix

Tente de réparer les certificats, lorsque cela est possible

-h, --help

Affiche l'aide

-k, --list-keys

Si défini, affiche une liste d'empreintes digitales, une par ligne, des certificats qui présentent des problèmes. Cette sortie est destinée à être utilisée par des scripts.
Cette option implique "--quiet". Si vous spécifiez également "--fix", les erreurs seront toujours imprimées sur stderr, et les certificats réparés seront toujours émis sur stdout.

-q, --quiet

Silencieux ; ne produit aucun diagnostic

-V, --version

Affiche les informations de version

OPTIONS LONGUES:

-p, --password <mot_de_passe>...

Le mot de passe d'une clé.
Normalement, ce n'est pas nécessaire : si stdin est
connecté à un tty, le linter demandera un mot de passe si nécessaire.

ARGUMENTS:

<FICHIERS>...
Une liste de porte-clés OpenPGP à traiter.
Si aucun n'est
spécifié, un porte-clés est lu depuis stdin.

"sq-keyring-linter" vérifie les certificats fournis pour les problèmes suivants liés à SHA-1 :

- Si une révocation de certificat utilise SHA-1.
- Si la signature actuelle auto-signée d'un ID utilisateur non révoqué utilise
SHA-1.
- Si la signature actuelle de liaison de sous-clé pour une sous-clé non révoquée,
active utilise SHA-1.
- Si une signature de liaison de clé primaire (un "backsig") pour une
sous-clé non révoquée et active utilise SHA-1.

Les diagnostics sont imprimés sur stderr. À la fin, quelques statistiques sont affichées. C'est utile lors de l'examen d'un porte-clés. Si "--fix" est spécifié et qu'au moins un problème a pu être corrigé, les certificats corrigés sont imprimés sur stdout.

Cet outil ne prend pas en charge les cartes à puce pour le moment. Mais, si seules les sous-clés sont sur une carte à puce, cet outil peut encore être capable de réparer partiellement le certificat. En particulier, il pourra corriger tous les problèmes liés aux signatures auto-signées d'ID utilisateur et aux signatures de liaison de sous-clé pour les sous-clés capables de chiffrement, mais il ne pourra pas générer de nouvelles signatures de liaison de clé primaire pour les sous-clés capables de signature.

STATUT DE SORTIE :

Si "--fix" n'est pas spécifié:"

2
si des problèmes ont été trouvés,
1
si aucun problème n'a été trouvé, mais il y a eu des erreurs lors de la lecture de l'entrée,
0
s'il n'y avait aucun problème.

Si "--fix" est spécifié:"

3
si des problèmes n'ont pas pu être résolus,
1
si aucun problème n'a été trouvé, mais il y a eu des erreurs lors de la lecture de l'entrée,
0
si tous les problèmes ont été résolus ou s'il n'y avait aucun problème.
