sqlsharp(1) Manuel des commandes générales sqlsharp(1)

NOM

sqlsharp - Outil de ligne de commande Mono SQL Query

SYNTAXE

sqlsharp [-f nom_fichier] [-o nom_fichier] [-s]

DESCRIPTION

sqlsharp est un outil Mono SQL utilisé pour entrer des requêtes SQL dans une base de données en utilisant les fournisseurs de données Mono.

OPTIONS

Les options suivantes sont prises en charge :

-f nom_fichier
Fichier de sortie pour charger les commandes SQL.
-o nom_fichier
Fichier de sortie pour envoyer les résultats.
-s
Mode silencieux.

COMMENT UTILISER

L'outil SQL accepte les commandes via son interface de ligne de commande. Les commandes commencent par une barre oblique inverse suivie du nom de la commande.

Exemple :

\open

Fondamentalement, il y a cinq commandes qu'un utilisateur devrait connaître : \provider, \connectionstring, \open, \quit, et \help

Pour vous connecter à une base de données, vous devez faire ce qui suit :

1. définir votre fournisseur de données via \provider

Exemple :
	SQL# \provider mysql

2. définir votre chaîne de connexion via \connectionstring

Exemple :
	SQL# \connectionstring Database=test

3. ouvrir une connexion à la base de données via \open

Exemple :
	SQL# \open

COMMANDES DE CONNEXION ET DE FOURNISSEUR

Ces commandes sont utilisées pour configurer le fournisseur, la chaîne de connexion, et ouvrir/fermer la connexion à la base de données.

ConnectionString
Définit la chaîne de connexion. 
Exemple :
	SQL# \ConnectionString Database=testdb
	ou
	SQL# \cs Database=testdb
Pour plus d'exemples, voir la section EXEMPLES DE CHAÎNES DE CONNEXION.
Provider
Définit le fournisseur de la source de données. Pour la liste des fournisseurs, voir la section FOURNISSEURS. 
Exemple : pour définir le fournisseur pour MySQL :
	SQL# \provider mysql
           ou
	SQL# \p mysql

Note : si vous avez besoin de charger un fournisseur externe dans SQL#,
      voir la commande SQL# \loadextprovider
ListProviders
Liste les fournisseurs ADO.NET 2.0 disponibles. 
Exemple :
	SQL# \ListProviders
	   ou
	SQL# \listp
BCS
Vous demande de construire chaque paramètre de connexion, construit la chaîne de connexion et vous permet également d'entrer un mot de passe qui ne s'affiche pas. 
Exemple :
	SQL# \bcs
	Option ConnectionString : Data Source [] SQL# blazer
	Option ConnectionString : Persist Security Info [False] SQL#
	Option ConnectionString : Integrated Security [False] SQL#
	Option ConnectionString : User ID [] SQL# scott
	Password: *****
	Option ConnectionString : Enlist [False] SQL#
	Option ConnectionString : Pooling [True] SQL#
	Option ConnectionString : Min Pool Size [0] SQL#
	Option ConnectionString : Max Pool Size [100] SQL#
	Option ConnectionString : Unicode [False] SQL#
	Option ConnectionString : Load Balance Timeout [0] SQL#
	Option ConnectionString : Omit Oracle Connection Name [False] SQL#
	ConnectionString est défini.
LoadExtProvider
ASSEMBLY CLASS pour charger un fournisseur externe. Utilisez le nom complet de son assembly et sa classe de connexion. 
Exemple : pour charger le fournisseur MySQL Mono.Data.MySql
	SQL# \loadextprovider Mono.Data.MySql Mono.Data.MySql.MySqlConnection
Open
Ouvre une connexion à la base de données. 
Exemple :
	SQL# \open
Close
Ferme la connexion à la base de données. 
Exemple :
	SQL# \close
Default
affiche les variables par défaut, telles que Provider et ConnectionString. 
Exemple :
	SQL# \defaults
Q
Quitter. 
Exemple :
	SQL# \q

COMMANDES D'EXÉCUTION SQL

Commandes pour exécuter des instructions SQL.

e exécute une requête SQL (SELECT)

Exemple : pour exécuter une requête

	SQL# SELECT * FROM EMPLOYEE
	SQL# \e
Note : pour que \e fonctionne automatiquement après avoir entré une requête,
      ajoutez un point-virgule ; à la fin de la requête.

Exemple : pour entrer et exécuter une requête en même temps
	SQL# SELECT * FROM EMPLOYEE;
exenonquery
exécute une requête SQL non sélective (pas un SELECT). 
Exemple : pour insérer une ligne dans une table :

	SQL# INSERT INTO SOMETABLE (COL1, COL2) VALUES('ABC','DEF')
	SQL# \exenonquery

Note : cela peut être utilisé pour les fournisseurs récents qui n'ont pas
      encore la capacité d'exécuter des requêtes.
exescalar
exécute SQL pour obtenir une seule ligne et une seule colonne. 
Exemple : pour exécuter un agrégat de maximum
		SQL# SELECT MAX(grade) FROM class
		SQL# \exescalar
exexml
NOM_FICHIER pour exécuter SQL et sauvegarder la sortie dans un fichier XML. 
Exemple :
	SQL# SELECT fname, lname, hire_date FROM employee
	SQL# \exexml employee.xml

Note : cela dépend du bon fonctionnement de DataAdapter, DataTable et DataSet.

COMMANDES DE FICHIER

Commandes pour importer des commandes depuis un fichier vers SQL# et vice versa.

f
NOM_FICHIER pour lire un lot de commandes SQL# à partir d'un fichier. 
Exemple :
	SQL# \f batch.sql#

Note : les commandes SQL# sont interprétées au fur et à mesure de leur lecture.
      Si des instructions SQL sont présentes, elles sont exécutées.
o
NOM_FICHIER pour écrire le résultat des commandes exécutées dans un fichier. 
Exemple :
	SQL# \o result.txt
load
NOM_FICHIER pour charger des commandes SQL depuis un fichier dans le tampon SQL. 
Exemple :
	SQL# \load commands.sql
save
NOM_FICHIER pour sauvegarder les commandes SQL du tampon SQL dans un fichier. 
Exemple :
	SQL# \save commands.sql

COMMANDES GENERALES

Commandes générales à utiliser.

h
affiche l'aide (toutes les commandes). 
Exemple :
	SQL# \h
s
TRUE, FALSE pour activer/désactiver les messages silencieux. 
Exemple 1 :
	SQL# \s true

Exemple 2 :
	SQL# \s false
r
réinitialise ou efface le tampon de requête. 
Exemple :
	SQL# \r
print
affiche ce qui se trouve actuellement dans le tampon SQL. 
Exemple :
	SQL# \print
VARIABLES SH QUI PEUVENT ÊTRE UTILISÉES COMME PARAMÈTRES Commandes pour définir des variables qui peuvent être utilisées comme paramètres dans une instruction SQL. Si le SQL contient des paramètres et que la variable correspondante n'est pas définie, l'utilisateur sera invité à entrer la valeur pour chaque paramètre manquant.
set
NOM VALEUR pour définir une variable interne. 
Exemple :
	SQL# \set sFirstName John
unset
NOM pour supprimer une variable interne. 
Exemple :
	SQL# \unset sFirstName
variable
NOM pour afficher la valeur d'une variable interne. 
Exemple :
	SQL# \variable sFirstName

OPTIONS DE SUPPORT DES FOURNISSEURS

Active ou désactive le support pour une option de fournisseur particulière.

UseParameters
TRUE, FALSE pour utiliser des paramètres

sqlsharp(1) - Mono SQL Query Tool

NAME

sqlsharp - Mono SQL Query Tool

SYNOPSIS 

sqlsharp [options] [sql-file ...]

DESCRIPTION

The Mono SQL Query Tool is a command-line utility that allows you to connect to a database, execute SQL statements, and view the results. It supports various database providers and offers a range of options for customization.

OPTIONS

-c connection-string
Specify the connection string to use to connect to the database.
-cf connection-string-file
Specify a file containing the connection string.
-h
Display help message.
-p provider
Specify the database provider to use. Defaults to the first provider found.
-s script
Specify an SQL script file to execute.
-v variable=value
Set a variable to be used in SQL statements.
-v
Enable verbose output.

HOW TO USE

The sqlsharp utility can be used in interactive mode or by providing an SQL script file.

INTERACTIVE MODE

Simply run `sqlsharp` without any arguments to enter interactive mode. You can then type SQL commands directly at the prompt.

SCRIPT MODE

To execute an SQL script file, use the `-s` option:

sqlsharp -s my_script.sql

CONNECTION AND PROVIDER COMMANDS

These commands are used to manage database connections and providers.

\connect [connection-string]
Connect to a database using the provided connection string. If no connection string is provided, it will prompt for one.
\connectionstring [connection-string]
Set the default connection string to be used for subsequent connections. If no connection string is provided, it displays the current default.
\disconnect
Disconnect from the current database.
\listproviders
List all available database providers.
\provider [provider-name]
Set the default database provider. If no provider name is provided, it displays the current default.

SQL EXECUTION COMMANDS

\go
Execute the current batch of SQL commands.
\help
Display help for SQL execution commands.
\query query
Execute the given SQL query and display the results.

FILE COMMANDS

\edit [filename]
Edit the specified file in the default editor. If no filename is provided, it edits the current script.
\import filename
Import SQL commands from the specified file.
\load filename
Load SQL commands from the specified file into the current buffer.
\save filename
Save the current buffer to the specified file.

GENERAL PURPOSE COMMANDS

\help
Display general help information.
\history
Display the command history.
\pause
Pause execution and wait for user input.
\quit
Exit the sqlsharp utility.
\set name [value]
Set or unset a global variable. If no value is provided, the variable is unset.
\source filename
Execute commands from the specified file.
\variables
List all set variables.

PROVIDER SUPPORT OPTIONS

AutoDetectConnection
TRUE,FALSE to auto detect connection if the server is local. 
Example:
	SQL# \autodetectconnection true
UseParameter
TRUE,FALSE to prompt for parameters when executing SQL which use the variables that were set.

If this option is true, the SQL contains parameters, and for each parameter which does not have a SQL# variable set, the user will be prompted to enter the value For that parameter.

Example:
	SQL# \useparameter true

Default: false

UseSimpleReader
TRUE,FALSE to use simple reader when displaying results. 
Example:
	SQL# \usesimplereader true

Default: false. Mostly, this is dependent on the provider. If the provider does not have enough of IDataReader implemented to have the normal reader working, then the simple reader can be used. Providers like SqlClient, MySQL, and PostgreSQL have this ption defaulting to true.
