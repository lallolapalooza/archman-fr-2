sq-encrypt(1)

Paquet: sequoia-sq

SQ(1) Commandes utilisateur SQ(1)

NOM

sq-encrypt - Chiffrer un message

SYNTAXE

sq encrypt [OPTIONS] FICHIER

DESCRIPTION

Chiffre un message.

Chiffre un message pour n'importe quel nombre de destinataires et avec n'importe quel nombre de mots de passe, en signant éventuellement le message dans le processus.

L'opération inverse est `sq decrypt`.

`sq encrypt` respecte l'heure de référence définie par l'argument de niveau supérieur `--time`. Il utilise l'heure de référence lors de la sélection des clés de chiffrement et définit l'heure de création de la signature à l'heure de référence.

OPTIONS

Options de sous-commande

--binary
Émettre des données binaires
--compression=TYPE
Sélectionne le schéma de compression à utiliser
[par défaut : pad]
[valeurs possibles : none, pad, zip, zlib, bzip2]
--encrypt-for=BUT
Sélectionne le type de clés à considérer pour le chiffrement
[par défaut : universal]
[valeurs possibles : transport, storage, universal]
--for=EMPREINTE|IDCLEF
Utilise les certificats avec l'empreinte ou l'ID de clé spécifié
--for-email=EMAIL
Utilise les certificats où un ID utilisateur inclut l'adresse e-mail spécifiée
--for-file=CHEMIN
Lit les certificats depuis CHEMIN
--for-self
Chiffre le message pour vous-même
Ceci ajoute les certificats listés dans le fichier de configuration sous `encrypt.for-self` à la liste des destinataires. Ceci peut être utilisé pour vous assurer que vous pouvez vous-même déchiffrer le message.
Actuellement, la liste des certificats à ajouter est vide.
--for-userid=IDUTILISATEUR
Utilise les certificats avec l'ID utilisateur spécifié
--output=FICHIER
Écrit dans FICHIER ou sur stdout si omis
[par défaut : -]
--profile=PROFIL
Sélectionne la norme OpenPGP par défaut pour le conteneur de chiffrement
Lors du chiffrement pour des certificats, le conteneur de chiffrement est sélectionné en fonction des préférences déclarées des destinataires. Cependant, s'il n'y a aucune indication, par exemple parce que le message est chiffré uniquement avec des mots de passe, sq utilise par défaut ce profil.
À mesure qu'OpenPGP évolue, de nouvelles versions deviendront disponibles. Cette option sélectionne la version d'OpenPGP à utiliser pour chiffrer les messages si la version ne peut pas être déduite autrement.
Actuellement, sq prend en charge deux profils : RFC9580 et RFC4880. Actuellement, la valeur par défaut est RFC4880. Cependant, une fois que la prise en charge de RFC9580 sera plus largement déployée, la valeur par défaut changera dans une future version de sq.
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.profile`.
[par défaut : rfc4880]
[valeurs possibles : rfc9580, rfc4880]
--set-metadata-filename=DEFINIR_NOM_FICHIER_METADONNEES
Définit le nom du fichier chiffré comme métadonnée
Notez que ces métadonnées ne sont pas signées et qu'il est donc généralement dangereux de s'y fier - du côté de l'expéditeur ou du destinataire.
--signature-notation NOM VALEUR
Ajoute une notation à la signature
Le nom d'une notation définie par l'utilisateur doit être de la forme `nom@a.domaine.que.vous.contrôlez.org`. Si le nom de la notation commence par un `!`, alors la notation est marquée comme critique. Si un consommateur d'une signature ne comprend pas une notation critique, il ignorera la signature. La notation est marquée comme lisible par l'homme.
--signer=EMPREINTE|IDCLEF
Signe le message en utilisant la clé avec l'empreinte ou l'ID de clé spécifié
--signer-email=EMAIL
Signe le message en utilisant la clé où un ID utilisateur inclut l'adresse e-mail spécifiée
--signer-file=CHEMIN
Signe le message en utilisant la clé lue depuis CHEMIN
--signer-self
Signe en utilisant vos clés de signature par défaut
Ceci ajoute les certificats listés dans le fichier de configuration sous `sign.signer-self` à la liste des clés de signature.
Actuellement, la liste des clés à ajouter est vide.
--signer-userid=IDUTILISATEUR
Signe le message en utilisant la clé avec l'ID utilisateur spécifié
--use-expired-subkey
Revient aux sous-clés de chiffrement expirées
Si un certificat n'a que des sous-clés expirées capables de chiffrement, revient à l'utilisation de celle qui a expiré en dernier
--with-password
Demande d'ajouter un mot de passe pour chiffrer
Lors de l'utilisation de cette option, l'utilisateur est invité à fournir un mot de passe, qui est utilisé pour chiffrer le message. Cette option peut être fournie plus d'une fois pour fournir plusieurs mots de passe. Les données chiffrées peuvent ensuite être déchiffrées avec l'une des clés du destinataire, ou l'un des mots de passe fournis.
--with-password-file=CHEMIN
Fichier contenant le mot de passe pour chiffrer le message
Notez que l'intégralité du fichier clé sera utilisée comme mot de passe, y compris les espaces blancs environnants comme un saut de ligne final.
Cette option peut être fournie plus d'une fois pour fournir plusieurs mots de passe. Les données chiffrées peuvent ensuite être déchiffrées avec l'une des clés du destinataire, ou l'un des mots de passe fournis.
--without-signature
Ne pas signer le message

FICHIER
Lire depuis FICHIER ou stdin si FICHIER est '-'
[par défaut : -]

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Chiffrer un fichier pour un destinataire donné par empreinte.

sq encrypt --for=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--signer-email=juliet@example.org document.txt

Chiffrer un fichier pour un destinataire donné par e-mail.

sq encrypt --for-email=alice@example.org \
--signer-email=juliet@example.org document.txt

VOIR AUSSI
