SQ(1) Commandes utilisateur SQ(1)

NOM

sq-key-rotate - Faire pivoter un certificat

SYNOPSIS

sq key rotate [OPTIONS]

DESCRIPTION

Fait pivoter un certificat.

Génère un nouveau certificat pour remplacer un certificat existant.

Le nouveau certificat aura les mêmes capacités que le certificat ancien. Ceci peut être remplacé en utilisant les arguments `--can-sign`, `--cannot-sign`, etc. Remarque: le nouveau certificat peut avoir une forme différente de l'ancien. Par exemple, si la clé primaire de l'ancien certificat est marquée comme capable à la fois de certification et de signature, la clé primaire du nouveau certificat sera capable de certification, et il aura une sous-clé de signature.

Par défaut, le certificat expire après 3 ans. Ceci peut être changé en utilisant l'argument `--expiration`.

Le nouveau certificat aura les mêmes identifiants utilisateur auto-signés que l'ancien certificat. Les identifiants utilisateur révoqués sont ignorés.

Le nouveau certificat et l'ancien certificat se certifieront mutuellement comme introducers fiables sans restriction.

Le nouveau certificat sera lié de la même manière que l'ancien certificat. Ceci peut être remplacé en utilisant l'argument `--own-key` ou `--shared-key`.

Le nouveau certificat certifiera les mêmes certificats que l'ancien certificat. C'est-à-dire, les certifications de l'ancien certificat seront rejouées. Voir `sq pki vouch replay` pour plus d'informations.

Un certificat de révocation indiquant que l'ancien certificat est retiré, et que le nouveau certificat devrait être utilisé à la place, sera émis. Par défaut, il entrera en vigueur dans 182 jours. Ceci peut être changé ou supprimé en utilisant l'argument `--retire-in`.

Lors de l'utilisation de `--output`, le nouveau certificat ainsi que tous les autres certificats mis à jour sont écrits dans le fichier spécifié.

Stable depuis 1.2.0.

OPTIONS

Options de sous-commande

--can-authenticate
Ajouter une sous-clé capable d'authentification
--can-encrypt=PURPOSE
Ajouter une sous-clé capable de chiffrement
Les sous-clés capables de chiffrement peuvent être marquées comme adaptées au chiffrement de transport, au chiffrement de stockage, ou aux deux, c'est-à-dire universelles.
[valeurs possibles : transport, storage, universal]
--can-sign
Ajouter une sous-clé capable de signature
--cannot-authenticate
Ne pas ajouter de sous-clé capable d'authentification
--cannot-encrypt
Ne pas ajouter de sous-clé capable de chiffrement
--cannot-sign
Ne pas ajouter de sous-clé capable de signature
--cert=EMPREINTE|IDCLEF
Utiliser des certificats avec l'empreinte ou l'ID de clé spécifié
--cert-email=EMAIL
Utiliser des certificats où un ID utilisateur inclut l'adresse e-mail spécifiée
--cert-file=CHEMIN
Lire les certificats depuis CHEMIN
--cert-userid=USERID
Utiliser des certificats avec l'ID utilisateur spécifié
--cipher-suite=SUITE-CHIFFREMENT
Sélectionner les algorithmes cryptographiques pour la clé
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.cipher-suite`.
[par défaut : cv25519]
[valeurs possibles : rsa2k, rsa3k, rsa4k, cv25519]
--expiration=EXPIRATION
Définit l'heure d'expiration
EXPIRATION est soit une date formatée ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée prend la forme `N[ymwds]`, où les lettres représentent respectivement les années, mois, semaines, jours et secondes. Alternativement, le mot-clé `never` ne définit pas de date d'expiration.
[par défaut : 3y]
--new-password-file=FICHIERMOTDEPASSE
Fichier contenant le mot de passe pour chiffrer le matériel de la clé secrète
Notez que l'intégralité du fichier de clé sera utilisée comme mot de passe, y compris les espaces environnants comme un saut de ligne final.
--output=FICHIER
Écrit la clé dans le fichier spécifié
Lorsqu'il n'est pas spécifié, la clé est enregistrée dans le magasin de clés.
--own-key
Marquer la clé comme étant sa propre clé
La clé nouvellement générée avec tous ses identifiants utilisateur sera marquée comme authentifiée et comme un introducer entièrement fiable.
--profile=PROFIL
Sélectionne la norme OpenPGP pour la clé
À mesure qu'OpenPGP évolue, de nouvelles versions seront disponibles. Cette option sélectionne la version d'OpenPGP à utiliser pour la clé nouvellement générée.
Actuellement, sq ne prend en charge qu'une seule version : RFC4880. Par conséquent, c'est la valeur par défaut. Cependant, il existe déjà une version plus récente de la norme : RFC9580. Et, la valeur par défaut changera dans une future version de sq.
La valeur par défaut peut être modifiée dans le fichier de configuration en utilisant le paramètre `key.generate.profile`.
[par défaut : rfc4880]
[valeurs possibles : rfc9580, rfc4880]
--retire-in=TEMPS
Définit le moment où le certificat doit être retiré
TEMPS est soit une date formatée ISO 8601 avec une heure optionnelle, soit une durée personnalisée. Une durée prend la forme `N[ymwds]`, où les lettres représentent respectivement les années, mois, semaines, jours et secondes. Alternativement, le mot-clé `never` saute la certification d'un certificat de révocation.
[par défaut : 26w]
--rev-cert=FICHIER
Écrit le certificat de révocation d'urgence dans FICHIER
Lorsque la clé est stockée dans le magasin de clés, le certificat de révocation est stocké par défaut dans $HOME/.local/share/sequoia/revocation-certificates.
Lorsque `--output` est spécifié, le certificat de révocation est écrit dans le fichier spécifié par `--rev-cert`.
Si `--output` est `-`, alors cette option ne doit pas non plus être `-`.
--shared-key
Marquer la clé comme une clé partagée
La clé nouvellement générée avec tous ses identifiants utilisateur sera marquée comme authentifiée, mais pas comme un introducer fiable. De plus, les métadonnées de la clé indiqueront qu'il s'agit d'une clé partagée.
Utilisez cette option si vous prévoyez de partager cette clé avec d'autres personnes. Normalement, vous ne devriez pas partager le matériel des clés. Un exemple où vous pourriez vouloir faire cela est une boîte aux lettres partagée.
--without-password
Ne pas protéger le matériel de la clé secrète avec un mot de passe

Options globales

Voir sq(1) pour une description des options globales.

EXEMPLES

Fait pivoter le certificat d'Alice.

sq key rotate --cert EB28F26E2739A4870ECC47726F0073F60FD0CBF0
