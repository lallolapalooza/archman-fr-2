sparse(1) Manuel des commandes générales sparse(1)

NOM

sparse - Analyseur sémantique pour C

SYNOPIS

sparse [OPTIONS DE MESSAGES]... fichier.c

DESCRIPTION

Sparse analyse le code source C et recherche les erreurs, produisant des avertissements sur la sortie standard d'erreur.

Sparse accepte des options contrôlant l'ensemble des avertissements à générer. Pour activer les avertissements que Sparse n'émet pas par défaut, utilisez l'option d'avertissement correspondante -Wquelquechose. Sparse émet certains avertissements par défaut ; pour désactiver ces avertissements, passez la négation de l'option d'avertissement associée, -Wno-quelquechose.

OPTIONS DE MESSAGES

-fmax-errors=COUNT
Définit le nombre maximum d'erreurs affichées à COUNT, qui doit être une valeur numérique ou 'illimité'. La limite par défaut est 100.
-fmax-warnings=COUNT
Définit le nombre maximum d'avertissements affichés à COUNT, qui doit être une valeur numérique ou 'illimité'. La limite par défaut est 100.
-Wsparse-all
Active tous les avertissements de sparse, à l'exception de ceux explicitement désactivés via -Wno-quelquechose.
-Wsparse-error
Transforme tous les avertissements de sparse en erreurs.
-Waddress-space
Avertit sur le code qui mélange des pointeurs vers différents espaces d'adressage.

Sparse autorise un attribut étendu __attribute__((address_space(id))) sur les pointeurs, qui désigne une cible de pointeur dans l'espace d'adressage id (un identifiant ou une constante entière). Avec -Waddress-space, Sparse traite les pointeurs avec des types cibles identiques mais des espaces d'adressage différents comme des types distincts et avertira en conséquence.

Sparse avertira également sur les conversions qui suppriment l'espace d'adressage (conversions vers un type entier ou vers un type pointeur simple). Une exception à cela est lorsque le type de destination est uintptr_t (ou unsigned long), car de telles conversions sont souvent utilisées pour "obtenir une représentation de valeur de pointeur dans un type entier" et de telles valeurs sont indépendantes de l'espace d'adressage.

Pour outrepasser ces avertissements, utilisez un type qui inclut __attribute__((force)).

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-address-space.

-Wbitwise
Avertit sur les opérations non supportées ou les incompatibilités de types avec des types entiers restreints.

Sparse supporte un attribut étendu, __attribute__((bitwise)), qui crée un nouveau type entier restreint à partir d'un type entier de base, distinct du type entier de base et de tout autre type entier restreint non déclaré dans la même déclaration ou typedef. Par exemple, cela permet aux programmes de créer des typedef pour des types entiers avec une endianness spécifique. Avec -Wbitwise, Sparse avertira sur toute utilisation d'un type restreint dans des opérations arithmétiques autres que des opérations binaires, et sur toute conversion d'un type restreint en un autre, sauf via une conversion incluant __attribute__((force)).

__bitwise devient une "séparation entière plus forte", qui ne vous permet pas de mélanger avec des entiers non-bitwise, il est donc beaucoup plus difficile de perdre le type par erreur.

__bitwise est destiné aux *types uniques* qui ne peuvent pas être mélangés avec d'autres types, et que vous ne voudriez jamais simplement utiliser comme un entier aléatoire (l'entier 0 est spécial, cependant, et est silencieusement accepté, je pense - c'est un peu comme "NULL" pour les pointeurs). Donc, "gfp_t" ou les types "safe endianness" seraient __bitwise : vous ne pouvez les manipuler qu'en effectuant des opérations spécifiques qui connaissent *ce* type particulier.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-bitwise.

-Wbitwise-pointer
Identique à -Wbitwise mais pour les conversions vers ou depuis des pointeurs vers des types bitwise.

Sparse n'émet pas ces avertissements par défaut.

-Wcast-from-as
Avertit sur les conversions qui suppriment un espace d'adressage d'un type pointeur.

Ceci est similaire à -Waddress-space mais avertira également sur les conversions vers unsigned long.

Sparse n'émet pas ces avertissements par défaut.

-Wcast-to-as
Avertit sur les conversions qui ajoutent un espace d'adressage à un type pointeur.

Une conversion qui inclut __attribute__((force)) supprimera cet avertissement. Aucun avertissement n'est généré si le type original est uintptr_t (ou unsigned long).

Sparse n'émet pas ces avertissements par défaut.

-Wcast-truncate
Avertit sur les conversions qui tronquent des valeurs constantes.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-cast-truncate.

-Wconstant-suffix
Avertit si une constante entière est plus grande que la valeur maximale représentable du type indiqué par son suffixe de type (le cas échéant). Par exemple, sur un système où les int sont de 32 bits et les long de 64 bits, la constante 0x100000000U est plus grande que ce qui peut être représenté par un unsigned int mais rentre dans un unsigned long. Son type est donc unsigned long mais ce n'est pas indiqué par son suffixe. Dans ce cas, l'avertissement pourrait être supprimé en utilisant le suffixe UL : 0x100000000UL.

Sparse n'émet pas ces avertissements par défaut.

-Wconstexpr-not-const
Avertit si une expression non constante est rencontrée alors qu'une expression constante est attendue à la place. Actuellement, cela avertit lors de l'initialisation d'un objet de durée de stockage statique avec un initialiseur qui n'est pas une expression constante.

Sparse n'émet pas ces avertissements par défaut.

-Wcontext
Avertit sur les erreurs potentielles dans la synchronisation ou d'autres contextes délimités.

Sparse supporte plusieurs moyens de désigner des fonctions ou des instructions qui délimitent des contextes, comme la synchronisation. Les fonctions avec l'attribut étendu __attribute__((context(expression,in_context,out_context)) exigent que l'expression de contexte (par exemple, un verrou) ait la valeur in_context (une constante entière non négative) lors de son appel, et reviennent avec la valeur out_context (une constante entière non négative). Pour les API définies via des macros, utilisez la forme d'instruction __context__(expression,in_value,out_value) dans le corps de la macro.

Avec -Wcontext Sparse avertira lorsqu'il verra une fonction changer de contexte sans l'indiquer avec un attribut context, soit en diminuant un contexte en dessous de zéro (par exemple, en libérant un verrou sans l'avoir acquis), soit en revenant avec un contexte modifié (par exemple, en acquérant un verrou sans le libérer). Sparse avertira également sur les blocs de code qui peuvent potentiellement s'exécuter avec des contextes différents.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-context.

-Wdecl
Avertit sur toute définition de variable ou de fonction non-static qui n'a pas de déclaration préalable.

Les symboles privés (fonctions et variables) internes à un fichier source donné devraient utiliser static, afin de permettre des optimisations supplémentaires du compilateur, de détecter les symboles inutilisés et d'empêcher d'autres codes de dépendre de ces symboles internes. Les symboles publics utilisés par d'autres fichiers source nécessiteront des déclarations visibles par ces autres fichiers sources, par exemple dans un fichier d'en-tête. Toutes les déclarations devraient tomber dans l'une de ces deux catégories. Ainsi, avec -Wdecl, Sparse avertit sur toute définition de symbole sans static ni déclaration. Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-decl.

-Wdeclaration-after-statement
Avertir des déclarations qui ne sont pas au début d'un bloc.

Ces déclarations sont autorisées en C99 mais pas en C89.

Sparse émet ces avertissements par défaut uniquement lorsque le dialecte C est C89 (c'est-à-dire -ansi ou -std=c89). Pour les désactiver, utilisez -Wno-declaration-after-statement.

-Wdefault-bitfield-sign
Avertir sur tout champ de bits sans signe explicite.

Les champs de bits n'ont pas de signe par défaut spécifié par la norme. (C99 6.7.2) Un champ de bits sans signed ou unsigned explicite crée un problème de portabilité pour les logiciels qui dépendent de la plage de valeurs disponible. Pour résoudre ce problème, spécifiez explicitement le type du champ de bits comme signed ou unsigned.

Sparse n'émet pas ces avertissements par défaut.

-Wdesignated-init
Avertir sur l'initialisation positionnelle des structures marquées comme nécessitant des initialiseurs désignés.

Sparse autorise un attribut __attribute__((designated_init)) qui marque une structure comme nécessitant des initialiseurs désignés. Sparse avertira sur l'initialisation positionnelle d'une variable de structure ou d'un littéral de structure d'un type qui possède cet attribut.

Exiger des initialiseurs désignés pour un type de structure particulier protégera le code utilisant ce type de structure contre les changements dans la disposition du type, évitant ainsi le besoin de modifier les initialiseurs pour ce type à moins qu'ils n'initialisent un champ supprimé ou modifié de manière incompatible.

Les exemples courants de ce type de structure incluent les collections de pointeurs de fonctions pour les implémentations d'une classe d'opérations liées, pour lesquelles la valeur NULL par défaut pour un champ non mentionné dans un initialiseur désigné indiquera correctement l'absence de cette opération.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-designated-init.

-Wdo-while
Avertir sur les boucles do-while qui ne délimitent pas le corps de la boucle avec des accolades.

Sparse n'émet pas ces avertissements par défaut.

-Wenum-mismatch
Avertir sur l'utilisation d'une expression d'un type enum incorrect lors de l'initialisation d'un autre type enum, de l'affectation à un autre type enum, ou de la transmission d'un argument à une fonction qui attend un autre type enum.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-enum-mismatch.

-Wexternal-function-has-definition
Avertir sur les définitions de fonctions qui sont déclarées avec une liaison externe.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-external-function-has-definition.

-Wflexible-array-array
Avertir sur les tableaux de structures contenant un tableau flexible.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-flexible-array-array.

-Wflexible-array-nested
Avertir sur les structures contenant un tableau flexible étant contenues dans une autre structure, union ou tableau.

Sparse n'émet pas ces avertissements par défaut.

-Wflexible-array-sizeof
Avertir sur l'utilisation de l'opérateur sizeof sur une structure contenant un tableau flexible, éventuellement de manière récursive.

Sparse n'émet pas ces avertissements par défaut.

-Wflexible-array-union
Activer les avertissements concernant les tableaux flexibles et les unions. Pour avoir un quelconque effet, au moins une des options -Wflexible-array-array, -Wflexible-array-nested ou -Wflexible-array-sizeof doit également être activée.

Sparse émet ces avertissements par défaut.

-Winit-cstring
Avertir sur l'initialisation d'un tableau de caractères avec une chaîne C constante trop longue.

Si la taille du tableau de caractères et la longueur de la chaîne sont identiques, il n'y a pas de place pour le dernier caractère nul de la chaîne dans le tableau :

char s[3] = "abc";

Si le tableau est utilisé comme un tableau d'octets, et non comme une chaîne C, cet avertissement n'est qu'un bruit. Cependant, si le tableau est passé à des fonctions traitant les chaînes C comme printf(%s) et strcmp, cela peut causer des problèmes.

Sparse n'émet pas ces avertissements par défaut.

-Wmemcpy-max-count
Avertir sur l'appel de memcpy(), memset(), copy_from_user() ou copy_to_user() avec un grand nombre d'octets en temps de compilation.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-memcpy-max-count.

La limite peut être modifiée avec -fmemcpy-max-count=COUNT, la valeur par défaut étant 100000.

-Wnewline-eof
Avertir si le fichier d'entrée ne se termine pas par une nouvelle ligne.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-newline-eof.

-Wnon-pointer-null
Avertir sur l'utilisation de 0 comme pointeur NULL.

0 a un type entier. NULL a un type pointeur.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-non-pointer-null.

-Wold-initializer
Avertir sur l'utilisation de la syntaxe GCC pré-C99 pour les initialiseurs désignés.

C99 fournit une syntaxe standard pour les champs désignés dans les initialiseurs de struct ou union :

struct structname var = { .field = value };

GCC a également une ancienne syntaxe non standard pour les initialiseurs désignés qui est antérieure à C99 :

struct structname var = { field: value };

Sparse avertira sur l'utilisation de la syntaxe non standard de GCC pour les initialiseurs désignés. Pour corriger cet avertissement, convertissez les initialiseurs désignés pour utiliser la syntaxe C99 standard.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-old-initializer.

-Wone-bit-signed-bitfield
Avertir sur tout champ de bits signed d'un seul bit.

Un champ de bits signed d'un seul bit ne peut avoir que les valeurs 0 et -1, ou avec certains compilateurs seulement 0 ; cela entraîne un comportement inattendu pour les programmes qui s'attendaient à pouvoir stocker 0 et 1.

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-one-bit-signed-bitfield.

-Wparen-string
Avertir sur l'utilisation d'une chaîne entre parenthèses pour initialiser un tableau.

La syntaxe C standard ne permet pas une chaîne entre parenthèses comme initialiseur de tableau. GCC autorise cette syntaxe comme extension. Avec -Wparen-string, Sparse avertira sur cette syntaxe.

Sparse n'émet pas ces avertissements par défaut.

-Wpast-deep-designator
Avertir lorsqu'un initialiseur avec un désignateur profond (imbriqué) est suivi d'un initialiseur non désigné dans une liste d'initialiseurs.

Sparse n'émet pas ces avertissements par défaut.

-Wpointer-arith
Avertir sur tout ce qui dépend du sizeof d'un type void ou fonction.

C99 n'autorise pas l'opérateur sizeof à être appliqué aux types fonction ou aux types incomplets comme void. GCC autorise sizeof à être appliqué à ces types comme une extension et attribue à ces types une taille de 1. Avec -pointer-arith, Sparse avertira sur l'arithmétique des pointeurs sur des pointeurs void ou fonction, ainsi que sur les expressions qui appliquent directement l'opérateur sizeof à des types void ou fonction.

Sparse n'émet pas ces avertissements par défaut.

-Wptr-subtraction-blows
Avertir lors de la soustraction de deux pointeurs vers un type dont la taille n'est pas une puissance de deux.

La soustraction de deux pointeurs vers un type donné donne une différence en termes du nombre d'éléments de ce type. Pour générer cette valeur, les compilateurs devront généralement diviser la différence par la taille du type, une opération potentiellement coûteuse pour des tailles autres que des puissances de deux.

Le code écrit en utilisant la soustraction de pointeurs peut souvent utiliser une approche différente à la place, telle que l'indexation de tableau avec une variable d'index de tableau explicite, ce qui peut permettre aux compilateurs de générer un code plus efficace.

Sparse n'émet pas ces avertissements par défaut.

-Wreturn-void
Avertir si une fonction avec le type de retour void retourne une expression void.

C99 le permet, et dans certains cas, cela permet un code plus générique dans les macros qui utilisent typeof ou prennent un type comme argument de macro. Cependant, certains programmes considèrent cela comme un mauvais style, et ces programmes peuvent utiliser -Wreturn-void pour être avertis à ce sujet.

Sparse n'émet pas ces avertissements par défaut.

-Wshadow
Avertir lors de la déclaration d'un symbole qui masque une déclaration du même nom dans une portée externe.

De telles déclarations peuvent conduire à du code sujet aux erreurs.

Sparse n'émet pas ces avertissements par défaut.

-Wshift-count-negative
Avertir si le nombre de décalage est négatif.

Sparse émet ces avertissements par défaut.

-Wshift-count-overflow
Avertir si le nombre de décalage est supérieur à la largeur de l'opérande.

Sparse émet ces avertissements par défaut.

-Wsizeof-bool
Avertir lors de la vérification du sizeof d'un _Bool.

"Pp">C99 ne spécifie pas la taille d'un _Bool. GCC, par défaut, utilise 1.

Sparse n'émet pas ces avertissements par défaut.

-Wtransparent-union
Avertir de toute déclaration utilisant l'extension GCC __attribute__((transparent_union)).

Sparse émet ces avertissements par défaut. Pour les désactiver, utilisez -Wno-transparent-union.

-Wtypesign
Avertir lors de la conversion d'un pointeur vers un type entier en un pointeur vers un type entier de signe différent.

Sparse n'émet pas ces avertissements par défaut.

-Wundef
Avertir des conditions du préprocesseur qui utilisent la valeur d'un symbole de préprocesseur non défini.

Le C standard (C99 6.10.1) permet d'utiliser la valeur d'un symbole de préprocesseur non défini dans les conditions du préprocesseur, et spécifie qu'il a une valeur de 0. Cependant, ce comportement peut entraîner des erreurs subtiles.

Sparse n'émet pas ces avertissements par défaut.

-Wuniversal-initializer
Ne pas supprimer les avertissements causés par l'utilisation de '{ 0 }' au lieu de '{ }' sur les types agrégés, ignorant son statut spécial d'initialiseur universel. Les avertissements concernés sont, par exemple, ceux déclenchés par -Wdesignated-init ou -Wnon-pointer-null.

Sparse n'émet pas ces avertissements par défaut, traitant '{ 0 }' de la même manière que '{ }'.

-Wunion-cast
Avertir des conversions vers des types union.

Sparse n'émet pas ces avertissements par défaut.

OPTIONS DIVERSES

--arch=ARCH
Spécifier l'architecture cible. Pour les architectures ayant une variante 32 bits et une variante 64 bits (mips, powerpc, riscv et sparc), le nom de l'architecture peut être suffixé par 32 ou 64.

L'architecture et la taille par défaut sont celles de la machine utilisée pour construire Sparse.

-gcc-base-dir dir
Rechercher les en-têtes système fournis par le compilateur dans dir/include/ et dir/include-fixed/.
-multiarch-dir dir
Rechercher les en-têtes système dans le sous-répertoire multiarch dir. Le nom de dir prendrait normalement la forme du triplet GNU normalisé de la cible. (par exemple, i386-linux-gnu).
--os=OS
Spécifier le système d'exploitation cible. Cela n'entraîne que quelques différences avec les types prédéfinis. Les valeurs acceptées sont : linux, unix, freebsd, netbsd, opensd, sunos, darwin et cygwin.

L'OS par défaut est celui de la machine utilisée pour construire Sparse s'il peut être détecté, sinon certains paramètres génériques sont utilisés.

OPTIONS DE DÉBOGAGE

-fmem-report
Rapporter quelques statistiques sur l'allocation mémoire utilisée par l'outil.

AUTRES OPTIONS

-fdiagnostic-prefix[=PREFIX]
Précéder tous les diagnostics par le PREFIX donné, suivi de ": ". S'il n'y en a pas, "sparse" est utilisé. Par défaut, aucun préfixe n'est utilisé.
-fmemcpy-max-count=COUNT
Définir la limite pour les avertissements donnés par -Wmemcpy-max-count. Une COUNT de 'unlimited' ou '0' désactivera effectivement l'avertissement. La limite par défaut est 100000.
-ftabstop=WIDTH
Définir la distance entre les tabulations. Cela aide sparse à rapporter des numéros de colonne corrects dans les avertissements ou les erreurs. Si la valeur est inférieure à 1 ou supérieure à 100, l'option est ignorée. La valeur par défaut est 8.
-f[no-]unsigned-bitfields, -f[no-]signed-bitfields
Déterminer le signe des champs de bits déclarés sans signe explicite ('signed' ou 'unsigned'). Par défaut, ces champs de bits sont signés, comme d'autres entiers simples.
-f[no-]unsigned-char, -f[no-]signed-char
Faire en sorte que le 'char' simple soit non signé ou signé. Par défaut, les caractères sont signés.
