NOM

spamc - client pour spamd

SYNTAXE

spamc [options] < message

DESCRIPTION

Spamc est la moitié client de la paire spamc/spamd. Il doit être utilisé à la place de "spamassassin" dans les scripts pour traiter les e-mails. Il lira l'e-mail depuis STDIN, et le transmettra à sa connexion vers spamd, puis lira le résultat et l'affichera sur STDOUT. Spamc a une surcharge de chargement extrêmement faible, il devrait donc être beaucoup plus rapide à charger que le programme spamassassin complet.

Voir le fichier README dans le répertoire spamd de la distribution SpamAssassin pour plus de détails.

OPTIONS

Toutes les options détaillées ci-dessous peuvent être passées en arguments de ligne de commande, ou être contenues dans un fichier de configuration, comme décrit dans la section FICHIER DE CONFIGURATION ci-dessous.

Notez que les options longues, du type "--long-options", sont nouvelles depuis SpamAssassin 3.2.0, et n'étaient pas disponibles dans les versions antérieures.

-B, --bsmtp
Suppose que l'entrée est un seul message formaté BSMTP. En d'autres termes, spamc extraira tout ce qui se trouve entre la ligne DATA et la ligne de point unique pour le transmettre à spamd, et placera la sortie de spamd dans la même enveloppe (ainsi, toute extension SIZE dans votre fichier BSMTP causera de nombreux problèmes).
-c, --check
Vérifie simplement si le message est un spam ou non. Définit le code de sortie de processus à 1 si le message est un spam, 0 s'il n'est pas un spam ou si le traitement échoue. Affichera le score/seuil sur stdout (en entiers) ou 0/0 en cas d'erreur. La combinaison de -c et -E est un non-sens, car -c implique le comportement de -E.
-d hote[,hote2], --dest=hote[,hote2]
En mode TCP/IP, se connecte au serveur spamd sur l'hôte donné (défaut : localhost). Plusieurs hôtes peuvent être spécifiés s'ils sont séparés par des virgules.

Si hote résout vers plusieurs adresses, spamc tentera de basculer vers les autres adresses si la première ne peut être connectée. Il essaiera d'abord toutes les adresses d'un hôte avant d'essayer le suivant dans la liste. Notez que ce comportement de basculement est incompatible avec -x ; si ce commutateur est utilisé, le basculement ne se produira pas.

-4
Utilise uniquement IPv4 pour se connecter au serveur. Restreint la résolution des noms de domaine des hôtes du serveur spamd à la famille d'adresses AF_INET via le drapeau "hints.ai_family" dans l'appel à getaddrinfo(3).
-6
Utilise uniquement IPv6 pour se connecter au serveur. Restreint la résolution des noms de domaine des hôtes du serveur spamd à la famille d'adresses AF_INET6 via le drapeau "hints.ai_family" dans l'appel à getaddrinfo(3).
-e commande [arguments], --pipe-to commande [arguments]
Au lieu d'écrire sur stdout, dirige la sortie vers l'entrée standard de commande. Notez qu'il y a une très légère possibilité de perte d'e-mails ici, car si le fork-and-exec échoue, il n'y a aucun endroit où placer le message de l'e-mail.

Notez que ce doit être la DERNIÈRE option de ligne de commande, car tout ce qui suit -e est considéré comme des arguments pour la commande (c'est comme rxvt ou xterm).

Cette option n'est pas prise en charge sur les plateformes Win32.

-E, --exitcode
Filtre selon les autres options, mais définit le code de sortie du processus à 1 si le message est un spam, 0 s'il n'est pas un spam ou si le traitement échoue.
-F /chemin/vers/fichier, --config=chemin
Spécifie un fichier de configuration à partir duquel lire des indicateurs de ligne de commande supplémentaires. Voir FICHIER DE CONFIGURATION ci-dessous.
-h, --help
Affiche ce message d'aide et se termine sans action.
-H, --randomize
Pour les sockets TCP/IP, aléatorise les adresses IP renvoyées pour les hôtes spécifiés par le commutateur -d. Cela permet une forme simple d'équilibrage de charge. Il tentera cependant seulement trois fois.
-l, --log-to-stderr
Envoie les messages de journalisation vers stderr, au lieu de syslog.
-L type d'apprentissage, --learntype=type
Envoie le message à spamd pour apprentissage. Le "type d'apprentissage" peut être soit spam, ham ou forget. Le code de sortie de spamc sera défini à 0 si le message a été appris ou s'il avait déjà été appris. Les codes de sortie non nuls indiquent un échec réel d'une sorte ou d'une autre.

Notez que "spamd" doit être exécuté avec l'option "--allow-tell" pour que cela fonctionne.

-C type de rapport, --reporttype=type
Rapporte ou révoque un message à l'une des bases de données de filtrage collaboratif configurées. Le "type de rapport" peut être report ou revoke.

Notez que "spamd" doit être exécuté avec l'option "--allow-tell" pour que cela fonctionne.

-p port, --port=port
En mode TCP/IP, se connecte au serveur spamd écoutant sur le port donné (défaut : 783).
-r, --full-spam
Affiche uniquement le texte du rapport SpamAssassin sur stdout, si le message est un spam. Si le message est ham (non-spam), rien ne sera affiché. La première ligne de la sortie est le score du message et le seuil, dans ce format : 
score/seuil
-R, --full
Affiche uniquement le texte du rapport SpamAssassin sur stdout, pour tous les messages. Voir -r pour les détails du format de sortie utilisé.
-s taille max, --max-size=taille max
Définit la taille maximale du message qui sera envoyé à spamd -- tout ce qui est plus grand que ce seuil sera renvoyé sans être traité (défaut : 500 Ko). Si spamc reçoit un message plus grand que cela, il ne sera pas passé à spamd. La taille maximale du message est de 256 Mo.

La taille est spécifiée en octets, sous forme d'entier positif supérieur à 0. Par exemple, -s 500000.

--connect-retries=tentatives
Réessaie de se connecter à spamd tentatives fois. La valeur par défaut est 3 tentatives.
--retry-sleep=delai
Attend delai secondes entre les tentatives de connexion à spamd. La valeur par défaut est 1 seconde.
--filter-retries=tentatives
Réessaie le filtrage tentatives fois si le processus spamd échoue (généralement par dépassement de délai). Cela diffère de --connect-retries en ce qu'il expire la transaction après que la connexion TCP a été établie avec succès. La valeur par défaut est 1 tentative (c'est-à-dire une tentative et aucune réessai).
--filter-retry-sleep=delai
Attend delai secondes entre les tentatives de filtrage spamd échouées. La valeur par défaut est 1 seconde.
-S, --ssl
Si spamc a été compilé avec le support SSL, chiffre les données vers et depuis le processus spamd avec SSL ; spamd doit également prendre en charge SSL.
--ssl-cert=fichier de certificat
S'authentifie auprès du serveur spamd avec un certificat client SSL. Spécifie le fichier de certificat à utiliser.
--ssl-key=fichier de clé
S'authentifie auprès du serveur spamd avec un certificat client SSL. Spécifie le fichier de clé de certificat à utiliser.
--ssl-ca-file=fichier ca
Utilise le certificat d'autorité de certification spécifié pour vérifier le certificat du serveur. Le certificat du serveur doit être signé par ce certificat.

spamc(1) — perl v5.42.0

NAME

spamc — A Mail::SpamAssassin client interface

SYNOPSIS

       spamc [options] < in
       spamc [options] -e command [args ...]
       spamc [options] -f file

DESCRIPTION

spamc

is a client-side interface to the SpamAssassin(tm) anti-spam filtering utility. It sends a mail message to a running spamd daemon for analysis, and then returns the message to the caller, potentially modified (e.g. with added spam-detection headers).

The default behaviour is to send mail via standard input to spamd via a TCP/IP connection, and then return the message via standard output. Any errors encountered are printed to standard error.

If the -e option is specified, spamc will execute the given command, passing it the message via its standard input. The command is responsible for relaying the message to spamd and then processing the returned message.

The -f option tells spamc to read the message from the specified file, rather than standard input.

By default, spamc will attempt to contact spamd on localhost, port 783. These defaults can be overridden with the -d and -p options.

OPTIONS

-a max-size, --max-size=max-size
Set the maximum message size that spamc will transmit to spamd. The default is 200000 bytes. Messages larger than this will be returned unprocessed, with an exit code of 0.
-c, --is-spam
Causes spamc to exit with an exit code of 1 if the message is determined to be spam. This is the opposite of the default behaviour where spamc always exits with 0. Requires that spamd be configured to return spam/non-spam status (e.g. via the report_safe setting).
-C, --full-report
Perform a full report, including the message body, even if the message is not spam. This causes the message to be returned with added X-Spam-Status and X-Spam-Score headers, even if the message is not flagged as spam.
-d host, --host=host
Connect to spamd running on the specified host.
-e command, --execute=command
Execute the specified command, passing the message to it via standard input. The command is responsible for sending the message to spamd and processing the result.
-E, --exit-code
Similar to -c, but causes spamc to exit with an exit code of 1 if the message is determined to be spam, and 0 otherwise. This option is mutually exclusive with -x.
-f file, --file=file
Read the message to be scanned from the specified file. If the file is "-", then spamc will read from standard input.
-F file, --config-file=file
Use the specified file as the configuration file. See "CONFIGURATION FILE" below.
-h, --help
Print a usage message and exit.
-H, --headers
Perform a scan, but instead of allowing any part of the message (header and body) to be rewritten, limit rewriting to only the message headers. This is much more efficient in bandwidth usage, since the response message transmitted back from the spamd server will not include the body.

Note that this only makes sense if you are using "report_safe 0" in the scanning configuration on the remote end; with "report_safe 1", it is likely to result in corrupt messages.

-L, --no-safe-fallback
Disables the 'safe fallback' error-recovery method, which passes through the unaltered message if an error occurs. Instead, exit with an error code, and let the MTA queue up the mails for a retry later. See also "EXIT CODES".

This also disables the TCP fail-over behaviour from -d.

-m max-message-size, --max-message-size=max-message-size
Set the maximum message size that spamc will transmit to spamd. The default is 200000 bytes. Messages larger than this will be returned unprocessed, with an exit code of 0.
-p port, --port=port
Connect to spamd on the specified port.
-P pidfile, --pid-file=pidfile
Check the spamd PID file for a running process. If spamd is running, spamc will communicate with it. Otherwise, spamc will exit with an error. This option is intended for use by MTAs that only want to process mail if spamd is known to be running.
-r, --report
Perform a full report, including the message body, even if the message is not spam. This causes the message to be returned with added X-Spam-Status and X-Spam-Score headers, even if the message is not flagged as spam.
-R report-safe, --report-safe=report-safe
Set the value of the report_safe option in spamd. The value can be 0 (no changes), 1 (add headers), or 2 (replace message). The default is 1.
-s max-size, --max-size=max-size
Set the maximum message size that spamc will transmit to spamd. The default is 200000 bytes. Messages larger than this will be returned unprocessed, with an exit code of 0.
-S socketpath, --socket=socketpath
Connect to "spamd" via UNIX domain socket socketpath instead of a TCP/IP connection.

This option is not supported on Win32 platforms.

--ssl-ca-cert=cacert
Use the specified file as a trusted CA certificate to verify the server certificate. See the man page for IO::Socket::SSL for additional details.
--ssl-ca-dir=cadir
Use the Certificate Authority certificate files in the specified set of directories to verify the server certificate. See the man page for IO::Socket::SSL for additional details.
--ssl-cert=certfile
Use the specified file to identify the client certificate for server authentication. See the man page for IO::Socket::SSL for additional details.
--ssl-ca-path=capath
Use the Certificate Authority certificate files in the specified set of directories to verify the server certificate. The server certificate must be signed by one of these Certificate Authorities. See the man page for IO::Socket::SSL for additional details.
-t timeout, --timeout=timeout
Set the timeout for spamc-to-spamd communications (default: 600, 0 disables). If spamd takes longer than this many seconds to reply to a message, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-n timeout, --connect-timeout=timeout
Set the timeout for spamc-to-spamd connection establishment (default: 600, 0 disables). If spamc takes longer than this many seconds to establish a connection to spamd, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-u username, --username=username
To have spamd use per-user-config files, run spamc as the user whose config files spamd should load; by default the effective user-ID is sent to spamd. If you're running spamc as some other user, though, (eg. root, mail, nobody, cyrus, etc.) then you may use this flag to override the default.
-U socketpath, --socket=path
Connect to "spamd" via UNIX domain socket socketpath instead of a TCP/IP connection.

This option is not supported on Win32 platforms.

-V, --version
Report the version of this "spamc" client. If built with SSL support, an additional line will be included noting this, like so: 
SpamAssassin Client version 3.0.0-rc4
compiled with SSL support (OpenSSL 0.9.7d 17 Mar 2004)
-x, --no-safe-fallback
Disables the 'safe fallback' error-recovery method, which passes through the unaltered message if an error occurs. Instead, exit with an error code, and let the MTA queue up the mails for a retry later. See also "EXIT CODES".

This also disables the TCP fail-over behaviour from -d.

-X, --unavailable-tempfail
When disabling 'safe fallback' with -x, this option will turn EX_UNAVAILABLE errors into EX_TEMPFAIL. This may allow your MTA to defer mails with a temporary SMTP error instead of bouncing them with a permanent SMTP error. See also "EXIT CODES".
-y, --tests
Just output the names of the tests hit to stdout, on one line, separated by commas.
-K
Perform a keep-alive check of spamd, instead of a full message check.
-z
Use gzip compression to compress the mail message sent to "spamd". This is useful for long-distance use of spamc over the internet. Note that this relies on "zlib" being installed on the "spamc" client side, and the "Compress::Zlib" perl module on the server side; an error will be returned otherwise.
--headers
Perform a scan, but instead of allowing any part of the message (header and body) to be rewritten, limit rewriting to only the message headers. This is much more efficient in bandwidth usage, since the response message transmitted back from the spamd server will not include the body.

Note that this only makes sense if you are using "report_safe 0" in the scanning configuration on the remote end; with "report_safe 1", it is likely to result in corrupt messages.

CONFIGURATION FILE

The above command-line switches can also be loaded from a configuration file.

The format of the file is similar to the SpamAssassin rules files; blank lines and lines beginning with "#" are ignored. Any space-separated words are considered additions to the command line, and are prepended. Newlines are treated as equivalent to spaces. Existing command line switches will override any settings in the configuration file.

If the -F switch is specified, that file will be used. Otherwise, "spamc" will attempt to load spamc.conf in "SYSCONFDIR" (default: /etc/mail/spamassassin). If that file doesn't exist, and the -F switch is not specified, no configuration file will be read.

Example:

# spamc global configuration file 

# connect to "server.example.com", port 783
-d server.example.com
-p 783
# max message size for scanning = 350k
-s 350000

EXIT CODES

By default, spamc will use the 'safe fallback' error recovery method. That means, it will always exit with an exit code of 0, even if an error was encountered. If any error occurs, it will simply pass through the unaltered message.

The -c and -E options modify this; instead, spamc will use an exit code of 1 if the message is determined to be spam.

If one of the "-x", "-L" or "-C" options are specified, 'safe fallback' will be disabled, and certain error conditions related to communication between spamc and spamd will result in an error code.

The exit codes used are as follows:

EX_USAGE        64  command line usage error
EX_DATAERR      65  data format error       
EX_NOINPUT      66  cannot open input
EX_NOUSER       67  addressee unknown
EX_NOHOST       68  host name unknown
EX_UNAVAILABLE  69  service unavailable
EX_SOFTWARE     70  internal software error
EX_OSERR        71  system error (e.g., can't fork)
EX_OSFILE       72  critical OS file missing
EX_CANTCREAT    73  can't create (user) output file
EX_IOERR        74  input/output error
EX_TEMPFAIL     75  temp failure; user is invited to retry
EX_PROTOCOL     76  remote error in protocol
EX_NOPERM       77  permission denied
EX_CONFIG       78  configuration error
* The EX_TOOBIG error level is never used.  If spamc receives a message 
  that is too big, the exit code will be 0.
EX_TOOBIG       98  message was too big to process (see --max-size)
