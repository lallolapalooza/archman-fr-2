NOM

spamassassin - filtre de courrier électronique extensible utilisé pour identifier le spam

DESCRIPTION

SpamAssassin est un filtre de courrier électronique intelligent qui utilise une variété de tests pour identifier les courriers électroniques non sollicités en masse, plus communément appelés "spam". Ces tests sont appliqués aux en-têtes et au contenu des courriers électroniques pour classifier le courrier à l'aide de méthodes statistiques avancées. De plus, SpamAssassin possède une architecture modulaire qui permet de déployer rapidement d'autres technologies contre le spam et est conçu pour une intégration facile dans pratiquement n'importe quel système de messagerie.

Vous devriez pouvoir consulter la documentation de SpamAssassin avec votre programme man(1) ou perldoc(1).

FICHIERS DE CONFIGURATION

La base de règles de SpamAssassin, les modèles de texte et le texte de description des règles sont chargés à partir des fichiers de configuration.

Les données de configuration par défaut sont chargées à partir du premier répertoire existant dans :

/var/lib/spamassassin/4.000001
/usr/share/spamassassin
/usr/share/spamassassin
/usr/local/share/spamassassin
/usr/share/spamassassin

Les données de configuration spécifiques au site sont utilisées pour remplacer toutes les valeurs qui avaient déjà été définies. Ceci est chargé à partir du premier répertoire existant dans :

/etc/mail/spamassassin
/usr/etc/mail/spamassassin
/usr/etc/spamassassin
/usr/local/etc/spamassassin
/usr/pkg/etc/spamassassin
/usr/etc/spamassassin
/etc/mail/spamassassin
/etc/spamassassin

À partir de ces répertoires, SpamAssassin lira d'abord les fichiers se terminant par ".pre" par ordre lexical, puis il lira les fichiers se terminant par ".cf" par ordre lexical (la plupart des fichiers commencent par deux chiffres pour rendre l'ordre de tri évident).

En d'autres termes, il lira init.pre en premier, puis 10_default_prefs.cf avant 50_scores.cf et 20_body_tests.cf avant 20_head_tests.cf. Les options dans les fichiers ultérieurs remplaceront les fichiers précédents.

Les préférences individuelles de l'utilisateur sont chargées à partir de l'emplacement spécifié sur la ligne de commande "spamassassin", "sa-learn", ou "spamd" (voir la page de manuel correspondante pour les détails). Si l'emplacement n'est pas spécifié, ~/.spamassassin/user_prefs est utilisé s'il existe. SpamAssassin créera ce fichier s'il n'existe pas déjà, en utilisant user_prefs.template comme modèle. Ce fichier sera recherché dans :

/etc/mail/spamassassin
/usr/etc/mail/spamassassin
/usr/share/spamassassin
/etc/spamassassin
/etc/mail/spamassassin
/usr/local/share/spamassassin
/usr/share/spamassassin

TAGAGE

Les deux sections suivantes détaillent le tagage et le marquage par défaut qui s'effectuent pour les messages lors de l'exécution de "spamassassin" ou "spamc" avec "spamd" dans la configuration par défaut.

Remarque : avant la modification et l'ajout des en-têtes, tous les en-têtes commençant par "X-Spam-" sont supprimés pour empêcher les farces des spammeurs et aussi pour éviter les problèmes potentiels causés par des invocations antérieures de SpamAssassin.

TAGAGE DES EMAILS DE SPAM

Par défaut, tous les messages avec un score calculé de 5,0 ou plus sont tagués comme spam.

Si un message entrant est tagué comme spam, au lieu de modifier le message original, SpamAssassin créera un nouveau message de rapport et attachera le message original en tant que partie MIME de type message/rfc822 (garantissant que le message original est entièrement préservé et plus facile à récupérer).

Le nouveau message de rapport hérite des en-têtes suivants (s'ils sont présents) du message de spam original :

En-tête From:
En-tête To:
En-tête Cc:
En-tête Subject:
En-tête Date:
En-tête Message-ID:

Les en-têtes ci-dessus peuvent être modifiés si l'option "rewrite_header" pertinente est donnée (voir "Mail::SpamAssassin::Conf" pour plus d'informations).

Par défaut, ces en-têtes de message sont ajoutés au spam :

En-tête X-Spam-Flag:
Défini sur "YES".

Les en-têtes ajoutés sont entièrement configurables via l'option "add_header" (voir "Mail::SpamAssassin::Conf" pour plus d'informations).

Corps de texte du message de spam
Le rapport SpamAssassin est ajouté en haut du corps du message, si le message est marqué comme spam.

TAGGING

SpamAssassin ajoute les en-têtes suivants pour marquer les messages, qu'ils soient spam ou ham (non-spam).

En-tête X-Spam-Checker-Version :
La version et la sous-version de SpamAssassin et l'hôte sur lequel SpamAssassin a été exécuté.
En-tête X-Spam-Level :
Une série de caractères « * » où chacun représente un point de score complet.
En-tête X-Spam-Status :
Une chaîne, « (Oui|Non), score=nn requis=nn tests=xxx,xxx auto-apprentissage=(ham|spam|non|indisponible|échec)" est définie dans cet en-tête pour refléter l'état du filtre. Pour le premier mot, « Oui » signifie spam et « Non » signifie ham (non-spam).

Les en-têtes ajoutés sont entièrement configurables via l'option « add_header » (voir « Mail::SpamAssassin::Conf » pour plus d'informations).

INSTALLATION

La commande spamassassin fait partie du module Perl Mail::SpamAssassin. Installez-le comme un module Perl normal, en utilisant « perl -MCPAN -e shell », ou à la main.

Notez qu'il n'est pas possible d'utiliser la variable d'environnement « PERL5LIB » pour affecter l'endroit où SpamAssassin trouve ses modules Perl, en raison des limitations imposées par les vérifications de sécurité « taint » de Perl.

Pour plus de détails sur l'installation, veuillez lire le fichier « INSTALL » de la distribution SpamAssassin.
