SPLIT(1P) Manuel du programmeur POSIX SPLIT(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

split — diviser un fichier en morceaux

SYNTAXE

split [-l nombre_de_lignes] [-a longueur_suffixe] [fichier [nom]]
split -b n[k|m] [-a longueur_suffixe] [fichier [nom]]

DESCRIPTION

L'utilitaire split lit un fichier d'entrée et écrit zéro ou plusieurs fichiers de sortie. La taille par défaut de chaque fichier de sortie est de 1000 lignes. La taille des fichiers de sortie peut être modifiée par spécification des options -b ou -l. Chaque fichier de sortie est créé avec un suffixe unique. Le suffixe est constitué exactement de longueur_suffixe lettres minuscules de l'environnement local POSIX. Les lettres du suffixe sont utilisées comme s'il s'agissait d'un système de chiffres en base 26, le premier suffixe à être créé consistant en tous les caractères 'a', le second avec un 'b' remplaçant le dernier 'a', et ainsi de suite, jusqu'à ce qu'un nom composé entièrement de 'z' caractères soit créé. Par défaut, les noms des fichiers de sortie sont 'x', suivis d'un suffixe de deux caractères provenant de l'ensemble de caractères décrit ci-dessus, commençant par "aa", "ab", "ac", et ainsi de suite, et continuant jusqu'au suffixe "zz", pour un maximum de 676 fichiers.

Si le nombre de fichiers requis dépasse le maximum autorisé par la longueur du suffixe fournie, de telle sorte que le dernier fichier autorisé serait plus grand que la taille demandée, l'utilitaire split échoue après avoir créé le dernier fichier avec un suffixe valide ; split ne supprime pas les fichiers qu'il a créés avec des suffixes valides. Si la limite de fichiers n'est pas dépassée, le dernier fichier créé contient le reste du fichier d'entrée, et peut être plus petit que la taille demandée. Si l'entrée est un fichier vide, aucun fichier de sortie n'est créé et cela n'est pas considéré comme une erreur.

OPTIONS

L'utilitaire split est conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Règles de syntaxe des utilitaires.

Les options suivantes sont prises en charge :

-a longueur_suffixe

Utilise longueur_suffixe lettres pour former la partie suffixe des noms de fichiers du fichier divisé. Si -a n'est pas spécifié, la longueur du suffixe par défaut est de deux. Si la somme de l'opérande nom et de l'argument d'option longueur_suffixe créait un nom de fichier dépassant {NAME_MAX} octets, une erreur se produit ; split se termine avec un message de diagnostic et aucun fichier n'est créé.
-b n
Divise un fichier en morceaux de taille n octets.
-b nk
Divise un fichier en morceaux de taille n*1024 octets.
-b nm
Divise un fichier en morceaux de taille n*1048576 octets.
-l nombre_de_lignes
Spécifie le nombre de lignes dans chaque morceau de fichier résultant. L'argument nombre_de_lignes est un entier décimal non signé. La valeur par défaut est 1000. Si l'entrée ne se termine pas par un <newline>, la ligne partielle est incluse dans le dernier fichier de sortie.

OPERANDES

Les opérandes suivants sont pris en charge :

fichier
Le chemin du fichier ordinaire à diviser. Si aucun fichier d'entrée n'est donné ou si fichier est '-', l'entrée standard est utilisée.
nom
Le préfixe à utiliser pour chacun des fichiers résultant de l'opération de division. Si aucun argument nom n'est donné, 'x' est utilisé comme préfixe des fichiers de sortie. La longueur combinée du nom de base de préfixe et de longueur_suffixe ne peut pas dépasser {NAME_MAX} octets. Voir la section OPTIONS.

ENTRÉE STANDARD

Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Tout fichier peut être utilisé comme entrée.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de split :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories d'environnement local.)
LC_ALL
Si défini à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine l'environnement local pour l'interprétation des séquences d'octets de données textuelles en tant que caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine l'environnement local qui doit être utilisé pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Non utilisé.

ERREUR STANDARD

La sortie d'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Les fichiers de sortie contiennent des portions du fichier d'entrée original ; sinon, ils sont inchangés.

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

 0
Terminaison réussie.
>0
Une erreur s'est produite.

Par défaut.

EXEMPLES

Dans les exemples suivants, foo est un fichier texte contenant 5000 lignes.

1.
Crée cinq fichiers, xaa, xab, xac, xad, et xae :
split foo
2.
Crée cinq fichiers, mais la partie suffixée des fichiers créés se compose de trois lettres, xaaa, xaab, xaac, xaad, et xaae :
split -a 3 foo
3.
Crée trois fichiers avec des suffixes à quatre lettres et un préfixe fourni, bar_aaaa, bar_aaab, et bar_aaac :
> 
split -a 4 -l 2000 foo bar_
4.
Créez autant de fichiers que nécessaire pour contenir au plus 20 * 1024 octets, chacun avec le préfixe par défaut de x et un suffixe de cinq lettres :
split -a 5 -b 20k foo

RATIONALE

L'option -b a été ajoutée pour fournir un mécanisme de division des fichiers autre que par lignes. Bien que la plupart des utilisations de l'option -b soient destinées à la transmission de fichiers sur les réseaux, certains pensaient qu'elle aurait des utilisations supplémentaires.

L'option -a a été ajoutée pour surmonter la limitation de ne pouvoir créer que 676 fichiers.

On a envisagé de supprimer cet utilitaire, en raison du fait que la fonctionnalité fournie par cet utilitaire est disponible via l'utilitaire csplit (voir csplit). Après reconsidération de l'objectif de l'option des utilitaires de portabilité utilisateur, il a été décidé de conserver à la fois cet utilitaire et l'utilitaire csplit car les utilisateurs utilisent les deux utilitaires et ont des attentes historiques quant à leur comportement. De plus, la division par frontières d'octets dans split ne peut pas être reproduite avec le csplit historique.

Le texte « split ne doit pas supprimer les fichiers qu'il a créés avec des suffixes valides » serait normalement supposé, mais comme l'utilitaire apparenté, csplit, supprime des fichiers dans certaines circonstances, le comportement historique de split est rendu explicite pour éviter toute mauvaise interprétation.

Les versions antérieures de cette norme autorisaient une option -nombre_de_lignes. Cette forme n'est plus spécifiée par POSIX.1‐2008 mais peut être présente dans certaines implémentations.
