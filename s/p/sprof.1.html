sprof(1) Manuel des commandes générales sprof(1)

NOM

sprof - lire et afficher les données de profilage d'objet partagé

SYNTAXE

sprof [option ...] chemin-objet-partage [chemin-donnees-profilage]

DESCRIPTION

La commande sprof affiche un résumé de profilage pour l'objet partagé (bibliothèque partagée) spécifié comme premier argument de ligne de commande. Le résumé de profilage est créé à l'aide des données de profilage précédemment générées dans le deuxième argument de ligne de commande (facultatif). Si le chemin des données de profilage est omis, sprof tentera de le déduire en utilisant le nom de la bibliothèque (soname) de l'objet partagé, en recherchant un fichier nommé <soname>.profile dans le répertoire courant.

OPTIONS

Les options de ligne de commande suivantes spécifient la sortie de profilage à produire :

--call-pairs
-c
Imprime une liste de paires de chemins d'appel pour les interfaces exportées par l'objet partagé, ainsi que le nombre de fois où chaque chemin est utilisé.
--flat-profile
-p
Génère un profil plat de toutes les fonctions de l'objet surveillé, avec les comptes et les ticks.
--graph
-q
Génère un graphe d'appels.

Si aucune des options ci-dessus n'est spécifiée, le comportement par défaut est d'afficher un profil plat et un graphe d'appels.

Les options de ligne de commande supplémentaires suivantes sont disponibles :

--help
-?
Affiche un résumé des options et arguments de ligne de commande et quitte.
--usage
Affiche un court message d'utilisation et quitte.
--version
-V
Affiche la version du programme et quitte.

NORMES

GNU.

EXEMPLES

L'exemple suivant démontre l'utilisation de sprof. L'exemple consiste en un programme principal qui appelle deux fonctions dans un objet partagé. D'abord, le code du programme principal :


$ cat prog.c;
#include <stdlib.h>
void x1(void);
void x2(void);
int
main(int argc, char *argv[])
{
    x1();
    x2();
    exit(EXIT_SUCCESS);
}

Les fonctions x1() et x2() sont définies dans le fichier source suivant qui est utilisé pour construire l'objet partagé :


$ cat libdemo.c;
#include <unistd.h>
void
consumeCpu1(int lim)
{
    for (unsigned int j = 0; j < lim; j++)
	getppid();
}
void
x1(void) {
    for (unsigned int j = 0; j < 100; j++)
	consumeCpu1(200000);
}
void
consumeCpu2(int lim)
{
    for (unsigned int j = 0; j < lim; j++)
	getppid();
}
void
x2(void)
{
    for (unsigned int j = 0; j < 1000; j++)
	consumeCpu2(10000);
}

Maintenant, nous construisons l'objet partagé avec le nom réel libdemo.so.1.0.1 et le nom de bibliothèque (soname) libdemo.so.1 :


$ cc -g -fPIC -shared -Wl,-soname,libdemo.so.1 \
        -o libdemo.so.1.0.1 libdemo.c;

Ensuite, nous créons des liens symboliques pour le nom de bibliothèque (soname) et le nom du lieur de la bibliothèque :


$ ln -sf libdemo.so.1.0.1 libdemo.so.1;
$ ln -sf libdemo.so.1 libdemo.so;

Ensuite, nous compilons le programme principal, en le liant contre l'objet partagé, puis nous listons les dépendances dynamiques du programme :


$ cc -g -o prog prog.c -L. -ldemo;
$ ldd prog;
	linux-vdso.so.1 =>  (0x00007fff86d66000)
	libdemo.so.1 => not found
	libc.so.6 => /lib64/libc.so.6 (0x00007fd4dc138000)
	/lib64/ld-linux-x86-64.so.2 (0x00007fd4dc51f000)

Afin d'obtenir des informations de profilage pour l'objet partagé, nous définissons la variable d'environnement LD_PROFILE avec le nom de bibliothèque (soname) de la bibliothèque :


$ export LD_PROFILE=libdemo.so.1;

Nous définissons ensuite la variable d'environnement LD_PROFILE_OUTPUT avec le chemin du répertoire où la sortie de profilage doit être écrite, et nous créons ce répertoire s'il n'existe pas déjà :


$ export LD_PROFILE_OUTPUT=$(pwd)/prof_data;
$ mkdir -p $LD_PROFILE_OUTPUT;

LD_PROFILE provoque l'ajout de la sortie de profilage au fichier de sortie s'il existe déjà, nous nous assurons donc qu'il n'y a pas de données de profilage préexistantes :


$ rm -f $LD_PROFILE_OUTPUT/$LD_PROFILE.profile;

Nous exécutons ensuite le programme pour produire la sortie de profilage, qui est écrite dans un fichier dans le répertoire spécifié dans LD_PROFILE_OUTPUT :


$ LD_LIBRARY_PATH=. ./prog;
$ ls prof_data;
libdemo.so.1.profile

Nous utilisons ensuite l'option sprof -p pour générer un profil plat avec les comptes et les ticks :


$ sprof -p libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
Flat profile:
Each sample counts as 0.01 seconds.
  %   cumulative   self              self     total
 time   seconds   seconds    calls  us/call  us/call  name
 60.00      0.06     0.06      100   600.00           consumeCpu1
 40.00      0.10     0.04     1000    40.00           consumeCpu2
  0.00      0.10     0.00        1     0.00           x1
  0.00      0.10     0.00        1     0.00           x2

L'option sprof -q génère un graphe d'appels :


$ sprof -q libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
index % time    self  children    called     name
                0.00    0.00      100/100         x1 [1]
[0]    100.0    0.00    0.00      100         consumeCpu1 [0]
-----------------------------------------------
                0.00    0.00        1/1           <UNKNOWN>
[1]      0.0    0.00    0.00        1         x1 [1]
                0.00    0.00      100/100         consumeCpu1 [0]
-----------------------------------------------
                0.00    0.00     1000/1000        x2 [3]
[2]      0.0    0.00    0.00     1000         consumeCpu2 [2]
-----------------------------------------------
                0.00    0.00        1/1           <UNKNOWN>
[3]      0.0    0.00    0.00        1         x2 [3]
                0.00    0.00     1000/1000        consumeCpu2 [2]
-----------------------------------------------

Ci-dessus et ci-dessous, les chaînes "<UNKNOWN>" représentent des identificateurs qui sont en dehors de l'objet profilé (dans cet exemple, ce sont des instances de main()).

L'option sprof -c génère une liste de paires d'appels et le nombre de leurs occurrences :


$ sprof -c libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
<UNKNOWN>                  x1                                 1
x1                         consumeCpu1                      100
<UNKNOWN>                  x2                                 1
x2                         consumeCpu2                     1000

VOIR AUSSI
