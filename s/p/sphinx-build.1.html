NOM

sphinx-build - Outil de génération de documentation Sphinx

SYNTAXE

sphinx-build [options] <rep_source> <rep_sortie> [noms_fichiers ...]

DESCRIPTION

sphinx-build génère la documentation à partir des fichiers de <rep_source> et la place dans le <rep_sortie>.

sphinx-build recherche <rep_source>/conf.py pour les paramètres de configuration. sphinx-quickstart(1) peut être utilisé pour générer des fichiers modèles, y compris conf.py.

sphinx-build peut créer de la documentation dans différents formats. Un format est sélectionné en spécifiant le nom du générateur en ligne de commande ; il prend par défaut la valeur HTML. Les générateurs peuvent également effectuer d'autres tâches liées au traitement de la documentation. Pour une liste des générateurs disponibles, référez-vous à Générateurs.

Par défaut, tout ce qui est obsolète est généré. Seule la sortie pour des fichiers sélectionnés peut être générée en spécifiant des noms de fichiers individuels.

OPTIONS

-M nom_generateur
Sélectionne un générateur, en utilisant le mode make. Voir Générateurs pour une liste de tous les générateurs intégrés de Sphinx. Les extensions peuvent ajouter leurs propres générateurs.

IMPORTANT :

Sphinx ne reconnaît l'option -M que si elle est utilisée en premier, avec les répertoires source et de sortie, avant que toute autre option ne soit passée. Par exemple : 
sphinx-build -M html ./source ./build --fail-on-warning

Le mode make fournit la même fonctionnalité de construction qu'un Makefile ou Make.bat par défaut, et fournit les pipelines de construction supplémentaires suivants :

latexpdf
Construit des fichiers LaTeX et les exécute avec pdflatex, ou selon le paramètre latex_engine. Si language est défini sur 'ja', utilisera automatiquement le pipeline LaTeX vers PDF platex/dvipdfmx.
info
Construit des fichiers Texinfo et les exécute avec makeinfo.

REMARQUE :

Les emplacements par défaut du répertoire de sortie lors de l'utilisation du mode make diffèrent des valeurs par défaut lors de l'utilisation de -b.
  • les doctrees sont sauvegardées dans <rep_sortie>/doctrees
  • les fichiers de sortie sont sauvegardés dans <rep_sortie>/<nom_generateur>

Ajouté dans la version 1.2.1.

-b nom_generateur, --builder nom_generateur
Sélectionne un générateur.

Voir Générateurs pour une liste de tous les générateurs intégrés de Sphinx. Les extensions peuvent ajouter leurs propres générateurs.

Modifié dans la version 7.3 : Ajout de l'option longue --builder.

-a, --write-all
Si spécifié, écrit toujours tous les fichiers de sortie. Par défaut, seuls les fichiers de sortie pour les sources nouvelles et modifiées sont écrits. (Cela peut ne pas s'appliquer à tous les générateurs.)

REMARQUE :

Cette option ne relit pas les fichiers sources. Pour relire et retraiter tous les fichiers, utilisez plutôt --fresh-env.

Modifié dans la version 7.3 : Ajout de l'option longue --write-all.

-E, --fresh-env
N'utilise pas un environnement sauvegardé (la structure mettant en cache toutes les références croisées), mais le reconstruit complètement. Par défaut, seuls les fichiers sources nouveaux ou modifiés depuis la dernière exécution sont lus et analysés.

Modifié dans la version 7.3 : Ajout de l'option longue --fresh-env.

-t etiquette, --tag etiquette
Définit l'étiquette etiquette. Ceci est pertinent pour les directives only qui incluent leur contenu uniquement si certaines étiquettes sont définies. Voir inclure du contenu basé sur des étiquettes pour plus de détails.

Ajouté dans la version 0.6.

Modifié dans la version 7.3 : Ajout de l'option longue --tag.

-d rep, --doctree-dir rep
Étant donné que Sphinx doit lire et analyser tous les fichiers sources avant de pouvoir écrire un fichier de sortie, les fichiers sources analysés sont mis en cache sous forme de "pickles doctree". Normalement, ces fichiers sont placés dans un répertoire appelé .doctrees sous le répertoire de construction ; avec cette option, vous pouvez sélectionner un répertoire de cache différent (les doctrees peuvent être partagés entre tous les générateurs).

Modifié dans la version 7.3 : Ajout de l'option longue --doctree-dir.

-j N, --jobs N
Distribue la construction sur N processus en parallèle, pour rendre la construction plus efficace sur les machines multiprocesseurs. Cette fonctionnalité ne fonctionne que sur les systèmes prenant en charge le "fork". Windows n'est pas pris en charge. Notez que toutes les parties et tous les générateurs de Sphinx ne peuvent pas être parallélisés. Si l'argument auto est donné, Sphinx utilise le nombre de cœurs CPU comme N. Par défaut, il vaut 1.

Ajouté dans la version 1.2 : Cette option doit être considérée comme expérimentale.

Modifié dans la version 1.7 : Prend en charge l'argument auto.

Modifié dans la version 6.2 : Ajout de l'option longue --jobs.

-c rep, --conf-dir rep
Ne recherche pas le fichier conf.py dans le répertoire source, mais utilise plutôt le répertoire de configuration donné. Notez que divers autres fichiers et chemins spécifiés par les valeurs de configuration sont censés être relatifs au répertoire de configuration, ils devront donc également être présents à cet emplacement.

Ajouté dans la version 0.3.

Modifié dans la version 7.3 : Ajout de l'option longue --conf-dir.

-C, --isolated
Ne recherche pas de fichier de configuration ; prend uniquement les options via l'option --define.

Ajouté dans la version 0.5.

Modifié dans la version 7.3 : Ajout de l'option longue --isolated.

-D parametre=valeur, --define parametre=valeur
Remplace une valeur de configuration définie dans le fichier conf.py. La valeur doit être un nombre, une chaîne, une liste ou une valeur de dictionnaire.

Pour les listes, vous pouvez séparer les éléments par une virgule comme ceci : -D html_theme_path=chemin1,chemin2.

Pour les valeurs de dictionnaire, spécifiez le nom du paramètre et la clé comme suit : -D latex_elements.docclass=scrartcl.

Pour les valeurs booléennes, utilisez 0 ou 1 comme valeur.

Modifié dans la version 0.6 : La valeur peut maintenant être une valeur de dictionnaire.

Modifié dans la version 1.3 : La valeur peut maintenant aussi être une valeur de liste.

Modifié dans la version 7.3 : Ajout de l'option longue --define.

-A nom=valeur, --html-define nom=valeur
Attribue à la variable nom dans les modèles HTML la valeur valeur.

Ajouté dans la version 0.5.

Modifié dans la version 7.3 : Ajout de l'option longue --html-define.

-n, --nitpicky
Exécute en mode pointilleux. Actuellement, cela génère des avertissements pour toutes les références manquantes. Voir la valeur de configuration nitpick_ignore pour une façon d'exclure certaines références comme "manquant connu".

Modifié dans la version 7.3 : Ajout de l'option longue --nitpicky.

-N, --no-color
N'émet pas de sortie colorée.

Modifié dans la version 1.6 : Ajout de l'option longue --no-color.

OPTIONS

--color
Emit colored output. Auto-detected by default.

Added in version 1.6.

-v, --verbose
Increase verbosity (log-level). This option can be given up to three times to get more debug logging output. It implies -T.

Added in version 1.2.

Changed in version 7.3: Add --verbose long option.

-q, --quiet
Do not output anything on standard output, only write warnings and errors to standard error.

Changed in version 7.3: Add --quiet long option.

-Q, --silent
Do not output anything on standard output, also suppress warnings. Only errors are written to standard error.

Changed in version 7.3: Add --silent long option.

-w file, --warning-file file
Write warnings (and errors) to the given file, in addition to standard error.

Changed in version 7.3: ANSI control sequences are stripped when writing to file.

Changed in version 7.3: Add --warning-file long option.

-W, --fail-on-warning
Turn warnings into errors. This means that sphinx-build exits with exit status 1 if any warnings are generated during the build.

Changed in version 7.3: Add --fail-on-warning long option.

Changed in version 8.1: sphinx-build no longer exits on the first warning, but instead runs the entire build and exits with exit status 1 if any warnings were generated. This behaviour was previously enabled with --keep-going.

--keep-going
From Sphinx 8.1, --keep-going is always enabled. Previously, it was only applicable whilst using --fail-on-warning, which by default exited sphinx-build on the first warning. Using --keep-going runs !sphinx-build to completion and exits with exit status 1 if errors are encountered.

Added in version 1.8.

Changed in version 8.1: sphinx-build no longer exits on the first warning, meaning that in effect --fail-on-warning is always enabled. The option is retained for compatibility, but may be removed at some later date.

-T, --show-traceback
Display the full traceback when an unhandled exception occurs. Otherwise, only a summary is displayed and the traceback information is saved to a file for further analysis.

Added in version 1.2.

Changed in version 7.3: Add --show-traceback long option.

-P, --pdb
(Useful for debugging only.) Run the Python debugger, pdb, if an unhandled exception occurs while building.

Changed in version 7.3: Add --pdb long option.

--exception-on-warning
Raise an exception when a warning is emitted during the build. This can be useful in combination with --pdb to debug warnings.

Added in version 8.1.

-h, --help, --version
Display usage summary or Sphinx version.

Added in version 1.2.

You can also give one or more filenames on the command line after the source and build directories. Sphinx will then try to build only these output files (and their dependencies).

ENVIRONMENT VARIABLES

The sphinx-build refers following environment variables:

MAKE
A path to make command. A command name is also allowed. sphinx-build uses it to invoke sub-build process on make-mode.

Makefile Options

The Makefile and make.bat files created by sphinx-quickstart usually run sphinx-build only with the -b and -d options. However, they support the following variables to customize behavior:

PAPER
This sets the 'papersize' key of latex_elements: i.e. PAPER=a4 sets it to 'a4paper' and PAPER=letter to 'letterpaper'.

NOTE:

Usage of this environment variable got broken at Sphinx 1.5 as a4 or letter ended up as option to LaTeX document in place of the needed a4paper, resp. letterpaper. Fixed at 1.7.7.
SPHINXBUILD
The command to use instead of sphinx-build.
BUILDDIR
The build directory to use instead of the one chosen in sphinx-quickstart.
SPHINXOPTS
Additional options for sphinx-build. These options can also be set via the shortcut variable O (capital 'o').
NO_COLOR
When set (regardless of value), sphinx-build will not use color in terminal output. NO_COLOR takes precedence over FORCE_COLOR. See no-color.org for other libraries supporting this community standard.

Added in version 4.5.0.

FORCE_COLOR
When set (regardless of value), sphinx-build will use color in terminal output. NO_COLOR takes precedence over FORCE_COLOR.

Added in version 4.5.0.

DEPRECATION WARNINGS

If any deprecation warning like RemovedInSphinxXXXWarning are displayed when building a user's document, some Sphinx extension is using deprecated features. In that case, please report it to author of the extension.

To disable the deprecation warnings, please set PYTHONWARNINGS= environment variable to your environment. For example:

  • PYTHONWARNINGS= make html (Linux/Mac)
  • export PYTHONWARNINGS= and do make html (Linux/Mac)
  • set PYTHONWARNINGS= and do make html (Windows)
  • modify your Makefile/make.bat and set the environment variable
