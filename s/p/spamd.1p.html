NOM

spamd - version daemonisée de spamassassin

SYNOPIS

spamd [options]

Options :

-l, --allow-tell                  Autoriser l'apprentissage/le signalement
-c, --create-prefs                Créer les fichiers de préférences utilisateur
-C chemin, --configpath=chemin    Chemin pour les fichiers de configuration par défaut
--siteconfigpath=chemin           Chemin pour les configurations du site
--cf='ligne de configuration'     Ligne de configuration supplémentaire
--pre='ligne de configuration'    Ligne de préfixe .pre supplémentaire (placée avant la configuration)
-d, --daemonize                   Se lancer en arrière-plan (daemon)
-h, --help                        Afficher le message d'utilisation
-i [ip_ou_nom[:port]], --listen=[ip_ou_nom[:port]] Écouter sur l'IP et le port spécifiés
-p port, --port=port              Écouter sur le port spécifié, peut être remplacé par -i
-4, --ipv4-only, --ipv4           Utiliser IPv4 si applicable, désactive IPv6
-6                                Utiliser IPv6 si applicable, désactive IPv4
-A hôte,..., --allowed-ips=..,..  Restreindre aux adresses IP qui peuvent se connecter
-m num, --max-children=num        Autoriser un maximum de num enfants
--min-children=num                Autoriser un minimum de num enfants
--min-spare=num                   Limite inférieure pour le nombre d'enfants en attente
--max-spare=num                   Limite supérieure pour le nombre d'enfants en attente
--max-conn-per-child=num          Connexions maximales acceptées par un enfant
                                  avant qu'il ne soit relancé
--round-robin                     Utiliser l'algorithme traditionnel prefork
--timeout-tcp=sec                 Délai d'attente TCP pour les en-têtes client
--timeout-child=sec               Délai d'attente pour les vérifications de message par l'enfant
-q, --sql-config                  Activer la configuration SQL (nécessite -x)
-Q, --setuid-with-sql             Activer la configuration SQL (nécessite -x,
                                  permet l'utilisation de -H)
--ldap-config                     Activer la configuration LDAP (nécessite -x)
--setuid-with-ldap                Activer la configuration LDAP (nécessite -x,
                                  permet l'utilisation de -H)
--virtual-config-dir=rep          Activer les configurations virtuelles basées sur des motifs
                                  (nécessite -x)
-r pidfile, --pidfile             Écrire l'ID du processus dans pidfile
-s facility, --syslog=facility    Spécifier le facility syslog
--syslog-socket=type              Comment se connecter à syslogd
--log-timestamp-fmt=fmt           Format strftime(3) pour les horodatages, peut être
                                  vide pour désactiver les horodatages, ou 'default'
-u nomutilisateur, --username=nomutilisateur  Exécuter en tant que nomutilisateur
-g groupe, --groupname=groupe     Exécuter en tant que groupe
-v, --vpopmail                    Activer la configuration vpopmail
-x, --nouser-config               Désactiver les fichiers de configuration utilisateur
-U nomutilisateur, --default-user=nomutilisateur  Utiliser ce nomutilisateur par défaut si l'utilisateur spamc
                                  n'est pas trouvé (défaut: nobody)
-D, --debug[=zones]               Afficher les messages de débogage (pour les zones)
-L, --local                       Utiliser uniquement les tests locaux (pas de DNS)
-P, --paranoid                    Mourir en cas d'erreurs utilisateur
-H [rep], --helper-home-dir[=rep] Spécifier un répertoire HOME différent
--ssl                             Activer SSL sur les connexions TCP
--ssl-verify                      Demander un certificat client et le vérifier
--ssl-ca-file cafile              Fichier de certificat de l'autorité de certification
--ssl-ca-path capath              Répertoire de l'autorité de certification
--ssl-port port                   Remplacer le réglage --port pour les connexions SSL
--server-key keyfile              Spécifier un fichier de clé SSL
--server-cert certfile            Spécifier un certificat SSL
--socketpath=chemin               Écouter sur un socket de domaine UNIX donné
--socketowner=nom                 Définir le propriétaire du fichier de socket UNIX
--socketgroup=nom                 Définir le groupe du fichier de socket UNIX
--socketmode=mode                 Définir le mode du fichier de socket UNIX
--timing                          Activer le chronométrage et la journalisation
-V, --version                     Afficher la version et quitter

L'option --listen (ou -i) peut être spécifiée plusieurs fois, sa syntaxe est : [ ssl: ] [ nom-hôte-ou-adresse-IP ] [ : port ] ou un chemin absolu (nom de fichier) d'un socket Unix. Si le port est omis, il prend par défaut --port ou 783. L'option --ssl implique le préfixe 'ssl:'. Une adresse IPv6 doit être entourée de crochets, par exemple [::1]:783, une adresse IPv4 peut l'être mais n'est pas obligée. Un astérisque '*' à la place d'un nom d'hôte implique une adresse non spécifiée ('0.0.0.0' ou '::'), c'est-à-dire qu'il se lie à toutes les interfaces. Une valeur d'option vide implique '*'. Par défaut, c'est '--listen localhost', qui se lie uniquement à une interface de bouclage.

DESCRIPTION

Le but de ce programme est de fournir une version daemonisée de l'exécutable spamassassin. L'objectif est d'améliorer les performances de débit pour la vérification automatique des courriels.

Ceci est destiné à être utilisé avec "spamc", un programme client C rapide et à faible surcharge.

Voir le fichier README dans le répertoire "spamd" de la distribution SpamAssassin pour plus de détails.

Note : Bien que "spamd" vérifie les fichiers de configuration par utilisateur pour chaque message, tout changement dans les fichiers de configuration système nécessitera soit de redémarrer spamd, soit de le forcer à se recharger via SIGHUP pour que les changements prennent effet.

Note : Si "spamd" reçoit un SIGHUP, il se recharge lui-même en interne, ce qui signifie qu'il changera son PID et pourrait ne pas redémarrer du tout si son environnement a changé (c'est-à-dire s'il ne peut pas revenir dans son propre répertoire). Si vous prévoyez d'utiliser SIGHUP, vous devriez toujours démarrer "spamd" avec l'option -r pour connaître son PID actuel.

OPTIONS

Les options de la forme longue peuvent être raccourcies tant qu'elles restent non ambiguës. (c'est-à-dire que --dae peut être utilisé à la place de --daemonize). De plus, les options booléennes (comme --user-config) peuvent être niées en ajoutant no (--nouser-config), cependant, c'est généralement inutile.

-l, --allow-tell
Autoriser l'apprentissage et l'oubli (vers une base de données Bayes locale), le signalement et la révocation (vers une base de données distante) par spamd. Le client émet une commande TELL pour indiquer le type de message en cours de traitement et si les bases de données locales (apprentissage/oubli) ou distantes (signalement/révocation) doivent être mises à jour.

Notez que spamd fait toujours confiance au nom d'utilisateur transmis, les clients pourraient donc malicieusement apprendre des messages pour d'autres utilisateurs. (Ce n'est généralement pas une préoccupation avec une base de données Bayes SQL car les utilisateurs auront généralement un accès en lecture-écriture direct à la base de données, et peuvent également utiliser "sa-learn" avec l'option -u pour obtenir le même résultat.)

-c, --create-prefs
Créer les fichiers de préférences utilisateur s'ils n'existent pas (par défaut : ne pas créer).
-C chemin, --configpath=chemin
Utiliser le chemin spécifié pour localiser les fichiers de configuration distribués. Ignorer les répertoires par défaut (généralement "/usr/share/spamassassin" ou similaire).
--siteconfigpath=chemin
Utiliser le chemin spécifié pour localiser les fichiers de configuration spécifiques au site. Ignorer les répertoires par défaut (généralement "/etc/mail/spamassassin" ou similaire).
--cf='ligne de configuration'
Ajouter des lignes de configuration supplémentaires directement depuis la ligne de commande, analysées après la lecture des fichiers de configuration. Plusieurs arguments --cf peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte.
--pre='ligne de configuration'
Ajouter des lignes de configuration .pre supplémentaires directement depuis la ligne de commande, analysées avant la lecture des fichiers de configuration. Plusieurs arguments --pre peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte.
-d, --daemonize
Se détacher du processus de démarrage et s'exécuter en arrière-plan (daemoniser).
-h, --help
Afficher un bref message d'aide, puis quitter sans autre action.
-V, --version
Afficher les informations sur la version, puis quitter sans autre action.

Des alias supplémentaires pour cette option sont --listen-ip et --ip-address. Indique à spamd d'écouter sur l'adresse IP spécifiée, par défaut une interface de bouclage, c'est-à-dire ("--listen localhost"). Si aucune valeur n'est s

Vous pouvez également utiliser un nom d'hôte valide qui fera écouter spamd sur toutes les adresses auxquelles un nom se résout. L'option peut être spécifiée plusieurs fois. Voir aussi les options -4 et -6 pour restreindre la famille d'adresses à IPv4 ou à IPv6. Si un port est spécifié, il remplace pour ce socket le réglage global --port (et --ssl-port). Les adresses IPv6 doivent être entourées de crochets, par exemple [::1]:783. Par souci de compatibilité, les crochets sur une adresse IPv6 peuvent être omis si une spécification de numéro de port est également omise.
-p port, --port=port
Spécifie éventuellement le numéro de port sur lequel le serveur doit écouter (par défaut : 783).

Si le commutateur --ssl est utilisé, et que --ssl-port n'est pas fourni, alors ce port sera utilisé pour accepter les connexions SSL au lieu des connexions non chiffrées. Si le commutateur --ssl est utilisé, et que --ssl-port est défini, alors les connexions non chiffrées seront acceptées sur le --port en même temps que les connexions chiffrées seront acceptées sur le --ssl-port.

-q, --sql-config
Active les recherches SQL même lorsque les fichiers de configuration par utilisateur ont été désactivés avec -x. Ceci est utile pour les hôtes spamd qui n'ont pas de répertoires personnels d'utilisateurs mais qui souhaitent charger les préférences utilisateur à partir d'une base de données SQL.

Si votre client spamc ne prend pas en charge l'envoi de l'en-tête "User:", comme "exiscan", alors le nom d'utilisateur SQL utilisé sera toujours nobody.

Ceci inhibe le comportement setuid(), donc l'option "-u" est requise. Si vous souhaitez le comportement setuid(), utilisez "-Q" ou "--setuid-with-sql" à la place.

--ldap-config
Active les recherches LDAP. Ceci est complètement analogue à "--sql-config", seulement il utilise un serveur LDAP.

Comme "--sql-config", ceci désactive le comportement setuid, et requiert "-u". Si vous le souhaitez, utilisez "--setuid-with-ldap" à la place.

-Q, --setuid-with-sql
Active les recherches SQL même lorsque les fichiers de configuration par utilisateur ont été désactivés avec -x et effectue également un setuid à l'utilisateur. Ceci est utile pour les hôtes spamd qui souhaitent charger les préférences utilisateur à partir d'une base de données SQL mais souhaitent également prendre en charge l'utilisation de -H (Répertoires personnels d'aide).
--setuid-with-ldap
Active les recherches LDAP même lorsque les fichiers de configuration par utilisateur ont été désactivés avec -x et effectue également un setuid à l'utilisateur. Ceci est à nouveau complètement analogue à "--setuid-with-sql", seulement il utilise un serveur LDAP.
--virtual-config-dir=pattern
Cette option spécifie où trouver les préférences par utilisateur pour les utilisateurs virtuels, pour le commutateur -x. Le *pattern* est utilisé comme modèle de base pour le nom du répertoire. Aucune des échappements suivantes ne peut être utilisée :
%u -- remplacé par le nom complet de l'utilisateur actuel, tel qu'envoyé par spamc.
%l -- remplacé par la 'partie locale' du nom d'utilisateur actuel. En d'autres termes, si le nom d'utilisateur est une adresse e-mail, c'est la partie avant le signe "@".
%d -- remplacé par le 'domaine' du nom d'utilisateur actuel. En d'autres termes, si le nom d'utilisateur est une adresse e-mail, c'est la partie après le signe "@".
%x -- remplacé par le nom complet de l'utilisateur actuel, tel qu'envoyé par spamc. Si le répertoire de configuration résultant n'existe pas, remplacé par la partie domaine pour utiliser un défaut à l'échelle du domaine.
%% -- remplacé par un seul signe pour cent (%).

Ainsi, par exemple, si "/vhome/users/%u/spamassassin" est spécifié, et que spamc envoie un nom d'utilisateur virtuel de "jm@example.com", le répertoire "/vhome/users/jm@example.com/spamassassin" sera utilisé.

L'ensemble des caractères autorisés dans le nom d'utilisateur virtuel pour ce chemin est limité à :

A-Z a-z 0-9 - + _ . , @ =

Tous les autres seront remplacés par des underscores ("_").

Ce chemin doit être un répertoire accessible en écriture. Il sera créé s'il n'existe pas déjà. Si un fichier nommé user_prefs existe dans ce répertoire (note : pas dans un sous-répertoire ".spamassassin" !), il sera chargé comme préférences de l'utilisateur. Les bases de données Bayes pour cet utilisateur seront stockées dans ce répertoire.

Notez que cela requiert que -x soit utilisé, et ne peut pas être combiné avec la configuration basée sur SQL ou LDAP.

Le *pattern* doit se développer en un répertoire absolu lorsque spamd s'exécute en mode démon (-d).

Actuellement, l'utilisation de ceci sans -u n'est pas prise en charge. Cela inhibe le setuid.

-r pidfile, --pidfile=pidfile
Écrit l'ID du processus parent de spamd dans le fichier spécifié par *pidfile*. Le fichier sera désélectionné à la sortie du parent. Notez que lors de l'exécution avec l'option -u, le fichier doit être accessible en écriture par cet utilisateur.
-v, --vpopmail
Active la configuration vpopmail. Si elle est spécifiée avec -u défini sur l'utilisateur vpopmail, cela permet à spamd de rechercher/créer des fichiers user_prefs dans le propre répertoire de messagerie de l'utilisateur vpopmail. Cette option est utile pour les utilisateurs virtuels vpopmail qui n'ont pas d'entrée dans le fichier système /etc/passwd.

Actuellement, l'utilisation de ceci sans -u n'est pas prise en charge. Cela inhibe le setuid.

-s facility, --syslog=facility
Spécifie la facilité syslog à utiliser (par défaut : mail). Si "stderr" est spécifié, la sortie sera écrite sur stderr. (Ceci est utile si vous exécutez "spamd" sous le package "daemontools".) Avec une *facility* de "file", toute la sortie va dans spamd.log. *facility* est interprétée comme un nom de fichier pour enregistrer si elle contient des caractères autres que a-z et 0-9. "null" désactive complètement la journalisation (utilisé en interne).

Exemples :

spamd -s mail                 # utilise syslog, facilité mail (par défaut)
spamd -s ./mail               # enregistre dans le fichier ./mail
spamd -s stderr 2>/dev/null   # enregistre sur stderr, jette les messages
spamd -s null                 # identique à ci-dessus
spamd -s file                 # enregistre dans le fichier ./spamd.log
spamd -s /var/log/spamd.log   # enregistre dans le fichier /var/log/spamd.log

Si la journalisation vers un fichier est activée et que ce fichier journal est remplacé, le serveur spamd doit être redémarré avec un SIGHUP. (Si le fichier journal est simplement tronqué, ce n'est pas nécessaire mais toujours recommandé.)

Notez que la journalisation vers un fichier n'utilise pas de verrouillage, vous ne pouvez donc pas mélanger la journalisation de spamd et d'autres processus dans le même fichier. Si vous souhaitez mélanger la journalisation de cette manière, utilisez syslog à la place.

Si vous utilisez la journalisation syslog, il est essentiel d'envoyer un SIGHUP au démon spamd lors du redémarrage du démon syslogd. (Ceci est dû à une limitation dans la gestion syslog de Perl, où la disparition de la connexion à syslogd est considérée comme une erreur fatale.)

--syslog-socket=type
Spécifie comment spamd doit envoyer des messages à syslogd. Le *type* peut être l'un des types de sockets ou mécanismes de journalisation acceptés par la sous-routine Sys::Syslog::setlogsock(). Selon la version de Sys::Syslog et le système d'exploitation sous-jacent, une des valeurs suivantes (ou leur sous-ensemble) peut être utilisée : "native", "eventlog", "tcp", "udp", "inet", "unix", "stream", "pipe", ou "console". La valeur "eventlog" est spécifique au journal d'événements Win32 et nécessite l'installation du module perl Win32::EventLog. Pour plus d'informations, veuillez consulter la documentation de Sys::Syslog.

Un réglage historique --syslog-socket=none est mappé sur --syslog=stderr.

Une valeur par défaut pour les plateformes Windows est "none", sinon la valeur par défaut est d'essayer d'abord "unix", puis de revenir à "inet" si perl détecte des erreurs dans son support "unix".

Certaines plateformes, ou versions de perl, sont livrées avec des versions anciennes ou défectueuses du module Sys::Syslog qui ne prennent pas en charge certains types de sockets, vous pourriez donc avoir besoin de définir cette option explicitement. Si vous recevez des messages d'erreur concernant __PATH_LOG ou similaires de spamd, essayez de changer ce réglage.

Le type de socket "file" est utilisé en interne et ne doit pas être spécifié. Utilisez plutôt le commutateur "-s".

--log-timestamp-fmt=format
L'option --log-timestamp-fmt peut fournir un format POSIX strftime(3) pour les horodatages inclus dans chaque message journalisé. Chaque journalisateur (stderr, file, syslog) a sa propre valeur par défaut pour un format d'horodatage, qui s'applique lorsque l'option --log-timestamp-fmt n'est pas donnée, ou avec --log-timestamp-fmt=default. Les horodatages peuvent être désactivés en spécifiant une chaîne vide avec cette option, par exemple --log-timestamp-fmt='' ou simplement --log-timestamp-fmt=. Utilisation typique : --log-timestamp-fmt='%a %b %e %H:%M:%S %Y' (fournit des noms de jours de la semaine et de mois localisés dans le style ctime(3)), ou '%a, %e %b %Y

 %H:%M:%S %z (%Z)' pour un format RFC 2822, ou peut-être '%Y-%m-%d %H:%M:%S%z' pour un format ISO 8601 (EN 28601), ou juste '%Y%m%dT%H%M%S' .
-u nomutilisateur, --username=nomutilisateur
Exécuter en tant qu'utilisateur nommé. Si cette option n'est pas définie, le comportement par défaut est de setuid() à l'utilisateur exécutant "spamc", si "spamd" s'exécute en tant que root.

Note : "--username=root" n'est pas une option valide. Si elle est spécifiée, "spamd" se terminera avec une erreur fatale au démarrage.

-g nomgroupe, --groupname=nomgroupe
Exécuter en tant que groupe nommé si --username est utilisé. Si cette option n'est pas définie lorsque --username est utilisé, alors le groupe primaire de l'utilisateur donné à --username est utilisé.
-x, --nouser-config, --user-config
Désactiver (activer) la lecture des fichiers de configuration par utilisateur (user_prefs) à partir du répertoire personnel de l'utilisateur. Le comportement par défaut est de lire la configuration par utilisateur à partir du répertoire personnel de l'utilisateur (--user-config).

Cette option ne désactive ni n'influence autrement les paramètres SQL, LDAP ou Virtual Config Dir.

-U nomutilisateur, --default-user=nomutilisateur
Rebasculer vers cet utilisateur, si l'utilisateur fourni par spamc n'est pas trouvé. La valeur par défaut est nobody, qui peut ne pas exister ou ne pas avoir de répertoire personnel utilisable, utilisez ce paramètre pour définir un utilisateur approprié si nécessaire.
-A hote,..., --allowed-ips=hote,...
Spécifiez une liste d'hôtes ou de réseaux autorisés, séparés par des virgules, qui peuvent se connecter à cette instance de spamd. Chaque élément de la liste est soit une adresse IP unique, soit une plage d'adresses IP en notation CIDR d'adresse/masque, soit des plages d'adresses IPv4 en spécifiant 3 octets ou moins avec un point final. Les noms d'hôtes ne sont pas supportés, uniquement les adresses IPv4 ou IPv6. Cette option peut être spécifiée plusieurs fois, ou peut prendre une liste d'adresses séparées par des virgules. Les adresses IPv6 peuvent être (mais n'ont pas besoin de l'être) entourées de crochets pour la cohérence avec l'option --listen. Exemples :

-A 10.11.12.13 -- autoriser uniquement les connexions depuis 10.11.12.13.

-A 10.11.12.13,10.11.12.14 -- autoriser uniquement les connexions depuis 10.11.12.13 et 10.11.12.14.

-A 10.200.300.0/24 -- autoriser les connexions depuis toute machine de la plage "10.200.300.*".

-A 10. -- autoriser les connexions depuis toute machine de la plage "10.*.*.*".

-A [2001:db8::]/32,192.0.2.0/24,::1,127.0.0.0/8 -- accepter uniquement les connexions depuis les réseaux de test spécifiés et depuis localhost.

En l'absence de l'option -A, les connexions ne sont acceptées que depuis l'adresse IP 127.0.0.1 ou ::1, c'est-à-dire depuis localhost sur une interface de bouclage.

-D [zone,...], --debug [zone,...]
Produire une sortie de débogage. Si aucune zone n'est listée, toutes les informations de débogage sont imprimées. La sortie de diagnostic peut également être activée pour chaque zone individuellement ; zone est la zone du code à instrumenter. Par exemple, pour produire une sortie de diagnostic sur bayes, learn et dns, utilisez : 
spamassassin -D bayes,learn,dns

Les messages d'information de priorité plus élevée, appropriés pour la journalisation dans des circonstances normales, sont disponibles avec une zone de "info".

Pour plus d'informations sur les zones (également appelées canaux) disponibles, veuillez consulter la documentation à l'adresse :

C<https://wiki.apache.org/spamassassin/DebugChannels>
-4, --ipv4only, --ipv4-only, --ipv4
Utiliser IPv4 le cas échéant, ne pas utiliser IPv6. L'option affecte un ensemble de sockets d'écoute (voir l'option "--listen") et désactive IPv6 pour les tests DNS.
-6
Utiliser IPv6 le cas échéant, ne pas utiliser IPv4. L'option affecte un ensemble de sockets d'écoute (voir l'option "--listen") et désactive IPv4 pour les tests DNS. L'installation d'un module IO::Socket::IP est recommandée si spamd est censé recevoir des requêtes sur IPv6.
-L, --local
Effectuer uniquement des tests locaux sur tous les courriels. En d'autres termes, ignorer les tests DNS et autres tests réseau. Fonctionne de la même manière que le drapeau "-L" pour spamassassin(1).
-P, --paranoid
Mourir en cas d'erreurs utilisateur (pour l'utilisateur passé depuis spamc) au lieu de basculer vers l'utilisateur "--default-user" et d'utiliser la configuration par défaut.
-m nombre , --max-children=nombre
Cette option spécifie le nombre maximum d'enfants à générer. Spamd générera ce nombre d'enfants, puis dormira en arrière-plan jusqu'à ce qu'un enfant meure, auquel cas il ira générer un nouvel enfant.

Les connexions entrantes peuvent toujours se produire si tous les enfants sont occupés, cependant ces connexions seront mises en file d'attente en attendant un enfant libre. La valeur minimale est 1, la valeur par défaut est 5.

Veuillez noter qu'il existe une limite maximale spécifique au système d'exploitation pour le nombre de connexions pouvant être mises en file d'attente (essayez "perl -MSocket -e'print SOMAXCONN'" pour trouver ce maximum).

Notez que si vous exécutez trop de serveurs par rapport à la quantité de RAM libre disponible, vous risquez de nuire aux performances en provoquant une charge d'échange élevée, car les processus serveur seront constamment chargés et déchargés de la mémoire virtuelle.

--min-children=nombre
Le nombre minimum d'enfants qui seront maintenus en fonctionnement. La valeur minimale est 1, la valeur par défaut est 1. Si vous avez beaucoup de RAM libre, vous pourriez vouloir augmenter cette valeur.
--min-spare=nombre
La limite inférieure pour le nombre d'enfants de réserve autorisés à s'exécuter. Un enfant de réserve, ou inactif, est un enfant qui ne traite pas une demande d'analyse. S'il y a trop peu d'enfants de réserve disponibles, un nouveau serveur sera démarré toutes les secondes environ. La valeur par défaut est 1.
--max-spare=nombre
La limite supérieure pour le nombre d'enfants de réserve autorisés à s'exécuter. S'il y a trop d'enfants de réserve, un sera tué toutes les secondes environ jusqu'à ce que le nombre d'enfants inactifs soit dans la plage souhaitée. La valeur par défaut est 2.
--max-conn-per-child=nombre
Cette option spécifie le nombre maximum de connexions que chaque enfant doit traiter avant de mourir et de laisser le processus maître spamd générer un nouvel enfant. La valeur minimale est 1, la valeur par défaut est 200.
--round-robin
Par défaut, "spamd" essaie de maintenir un petit nombre de processus enfants "chauds" aussi occupés que possible, et de maintenir les autres aussi inactifs que possible, en utilisant un algorithme similaire à celui d'Apache httpd pour la mise à l'échelle. Ceci est réalisé par le processus maître qui coordonne les activités des enfants. Ce commutateur désactivera cet algorithme de mise à l'échelle, et le comportement observé dans les versions 3.0.x sera utilisé à la place, où tous les processus reçoivent une charge égale et aucune mise à l'échelle n'a lieu.
--timeout-tcp=nombre
Cette option spécifie le nombre de secondes à attendre pour recevoir les en-têtes d'un client (spamc) avant de fermer la connexion. La valeur minimale est 1, la valeur par défaut est 30, et une valeur de 0 désactivera complètement les délais d'attente des sockets.
--timeout-child=nombre
Cette option spécifie le nombre de secondes à attendre qu'un enfant spamd traite ou vérifie un message. La valeur minimale est 1, la valeur par défaut est 300, et une valeur de 0 désactivera complètement les délais d'attente des enfants.
-H répertoire, --helper-home-dir=répertoire
Spécifier que les programmes externes tels que Razor, DCC et Pyzor doivent avoir une variable d'environnement HOME définie sur un répertoire spécifique. Par défaut, la variable d'environnement HOME est utilisée telle que définie dans le shell exécutant spamd. En ne spécifiant aucun argument, spamd utilisera à la place le répertoire personnel de l'appelant spamc.
--ssl
Accepter uniquement les connexions SSL sur le port associé. Le module Perl IO::Socket::SSL doit être installé.

Si le commutateur --ssl est utilisé, et que --ssl-port n'est pas fourni, alors le port --port sera utilisé pour accepter les connexions SSL au lieu des connexions non chiffrées. Si le commutateur --ssl est utilisé, et que --ssl-port est défini, alors les connexions non chiffrées seront acceptées sur le port --port, en même temps que les connexions chiffrées seront acceptées sur le port --ssl-port.

--ssl-verify
Implique --ssl. Demander un certificat client et vérifier le certificat. Nécessite --ssl-ca-file ou --ssl-ca-path.
--ssl-ca-file=fichierca
Implique --ssl-verify. Utiliser le certificat d'autorité de certification spécifié pour vérifier le certificat client. Le certificat client doit être signé par ce certificat.
--ssl-ca-path=chemindossierca
Implique --ssl-verify. Utiliser les fichiers de certificat d'autorité de certification dans le jeu de répertoires spécifié pour vérifier le certificat client. Le certificat client doit être signé par l'une de ces autorités de certification. Voir la page man de IO::Socket::SSL pour des détails supplémentaires.
--ssl-port=port
Spécifie éventuellement le numéro de port sur lequel le serveur doit écouter les connexions SSL (par défaut : quel que soit
--port (utilisé). Voir --ssl pour plus de détails.
--server-key fichier_clé
Spécifiez le fichier de clé SSL à utiliser pour les connexions SSL.
--server-cert fichier_certificat
Spécifiez le fichier de certificat SSL à utiliser pour les connexions SSL.
--socketpath chemin_d_acc_s
Écouter sur un socket de domaine UNIX au chemin chemin_d_acc_s, en plus des sockets spécifiés avec une option "--listen". Cette option est fournie pour la compatibilité avec les anciennes versions de spamd. À partir de la version 3.4.0, l'option "--listen" peut également accepter un socket de domaine UNIX comme valeur (un nom de chemin absolu). Contrairement à "--socketpath", l'option "--listen" peut être spécifiée plusieurs fois si spamd doit écouter sur plusieurs sockets UNIX, INET ou INET6.

Avertissement : le support Perl sur les plateformes BSD pour les sockets de domaine UNIX semble avoir un bug concernant les chemins de plus de 100 octets environ (bug SpamAssassin 4380). Si vous recevez un message d'erreur 'could not find newly-created UNIX socket', et que le chemin semble tronqué, cela peut en être la cause. Essayez d'utiliser un chemin plus court pour le socket.

Par défaut, l'utilisation de --socketpath sans --listen inhibera les connexions SSL et les connexions TCP non chiffrées. Pour ajouter d'autres sockets, spécifiez-les avec --listen, par exemple '--listen=:' ou '--listen=*:'

--socketowner nom
Définir le propriétaire du socket de domaine UNIX à l'utilisateur nommé nom. Notez que cela nécessite que spamd soit démarré en tant que "root", et si "-u" est utilisé, que cet utilisateur ait des permissions d'écriture pour supprimer le fichier plus tard, lorsque le serveur "spamd" est arrêté.
--socketgroup nom
Définir le groupe du socket de domaine UNIX au groupe nommé nom. Voir "--socketowner" pour des notes sur la propriété et les permissions.
--socketmode mode
Définir le mode octal du socket de domaine UNIX à mode. Notez que si "-u" est utilisé, cet utilisateur doit avoir des permissions d'écriture pour supprimer le fichier plus tard, lorsque le serveur "spamd" est arrêté.
--timing
Active les mesures de temps et affiche les informations pour la journalisation. Ceci
est la même information que celle fournie par la balise TIMING.
