SPIN(1) Manuel des commandes générales SPIN(1)

NOM


Spin − vérification de systèmes multithreadés

SYNTAXE

spin -V
spin [ options ] fichier

DESCRIPTION

SPIN est un outil pour analyser la cohérence logique des systèmes asynchrones, spécifiquement les logiciels distribués, les systèmes multithreadés et les protocoles de communication. Un modèle du système est spécifié dans un langage de commandes gardées appelé Promela (process meta language). Ce langage de modélisation supporte la création dynamique de processus, la sélection non déterministe de cas, les boucles, les gotos, les variables locales et globales. Il permet également une spécification concise des exigences de correction logique, y compris, mais sans s'y limiter, les exigences exprimées en logique temporelle linéaire.

À partir d'un modèle Promela stocké dans fichier, SPIN peut effectuer des simulations interactives, guidées ou aléatoires de l'exécution du système. Il peut également générer un programme C qui effectue une vérification exhaustive des exigences de correction pour le système. Les principales options supportées sont les suivantes. (Vous pouvez toujours obtenir une liste complète des options actuelles avec la commande "spin --".

-a
Génère un vérificateur (un modèle checker) pour la spécification. La sortie est écrite dans un ensemble de fichiers C nommés pan.[cbhmt], qui peuvent être compilés (cc -o pan pan.c) pour produire un exécutable de vérification. Les manuels SPIN en ligne contiennent les détails sur la compilation et l'utilisation des vérificateurs.
-b
N'exécute pas les instructions printf lors d'une simulation.
-c
Produit une approximation ASCII d'un diagramme de séquence de messages pour une simulation aléatoire ou guidée (lorsqu'elle est combinée avec -t). Voir également l'option -M.
-Dxxx
Passe -Dxxx au préprocesseur (voir aussi -E et -I).
-d
Produit des informations sur la table des symboles pour le modèle spécifié dans fichier. Pour chaque objet Promela, ces informations incluent le type, le nom et le nombre d'éléments (s'il est déclaré comme tableau), la valeur initiale (s'il s'agit d'un objet de données) ou la taille (s'il s'agit d'un canal de message), la portée (globale ou locale), et si l'objet est déclaré comme variable ou comme paramètre. Pour les canaux de message, les types de données des champs du message sont listés. Pour les variables structurelles, le 3ème champ définit le nom de la déclaration de structure qui contient la variable.
-Exxx
Passe xxx au préprocesseur (voir aussi -D et -I).
-e
Si la spécification contient plusieurs revendications (never claims) ou propriétés ltl, calcule le produit synchrone de toutes les revendications et écrit le résultat sur la sortie standard.
-f LTL
Traduit la formule LTL LTL en une revendication (never claim).
Cette option lit une formule en syntaxe LTL à partir du second argument et la traduit en syntaxe Promela (une revendication, qui est l'équivalent Promela d'un automate de Büchi). Les opérateurs LTL sont écrits : [] (toujours), <> (éventuellement), et U (jusqu'à fort). Il n'y a pas d'opérateur X (suivant), pour assurer la compatibilité avec les règles de réduction de l'ordre partiel appliquées pendant le processus de vérification. Si la formule contient des espaces, elle doit être mise entre guillemets pour former un seul argument à la commande SPIN.
Cette option a été largement remplacée par la prise en charge des formules LTL spécifiées en ligne, dans la version 6.0 de Spin.
-F fichier
Traduit la formule LTL stockée dans fichier en une revendication (never claim).
Ceci se comporte de manière identique à l'option -f mais lit la formule depuis le fichier au lieu de la ligne de commande. Le fichier doit contenir la formule sur la première ligne. Tout texte qui suit cette première ligne est ignoré, il peut donc être utilisé pour stocker des commentaires ou des annotations sur la formule. (Sur certains systèmes, les conventions de guillemets du shell compliquent l'utilisation de l'option -f. L'option -F est destinée à résoudre ces problèmes.)
-g
En combinaison avec l'option -p, imprime toutes les mises à jour de variables globales lors d'une simulation.
-h
À la fin d'une simulation, imprime la valeur de la graine (seed) qui a été utilisée pour le générateur de nombres aléatoires. En spécifiant la même graine avec l'option -n, la simulation exacte peut être répétée plus tard.
-I
Affiche le résultat de l'inlining et du préprocesseur.
-i
Effectue une simulation interactive, demandant à l'utilisateur à chaque étape d'exécution qui nécessite une décision non déterministe. La simulation se poursuit sans intervention de l'utilisateur lorsque l'exécution est déterministe.
-jN
Ignore l'impression pour les N premières étapes d'une simulation.
-J
Inverse l'ordre d'évaluation pour les instructions unless imbriquées, par exemple, pour correspondre à la façon dont Java gère les exceptions.
-k fichier
Utilise le nom de fichier fichier comme fichier de trace (trail-file), voir aussi -t.
-l
En combinaison avec l'option -p, inclut toutes les mises à jour de variables locales dans la sortie d'une simulation.
-M
Produit un diagramme de séquence de messages au format tcl/tk pour une simulation aléatoire ou une simulation guidée (lorsqu'elle est combinée avec -t), pour le modèle dans fichier, et affiche le résultat avec wish. Voir également l'option -c.
-m
Modifie la sémantique des événements d'envoi. Normalement, une action d'envoi sera (bloquée) si le tampon de message cible est plein. Avec cette option, un message envoyé à un tampon plein est perdu.
-nN
Définit la graine pour une simulation aléatoire à la valeur entière N. Il n'y a pas d'espace entre -n et l'entier N. ,TP -N fichier Utilise la revendication (never claim) stockée dans fichier pour générer le vérificateur (voir -a).
-O
Utilise les règles de portée d'origine de la version pré-Spin 6.
-o[123]
Désactive l'optimisation du flux de données (-o1). Ne masque pas les variables en écriture seule (-o2) pendant la vérification. Désactive la fusion des instructions (-o3) pendant la vérification. Active l'optimisation du rendezvous (-o4) pendant la vérification. Active la mise en cache des cas (-o5) pour réduire la taille de pan.m, mais en perdant de la précision dans les rapports d'atteignabilité.
-O
Utilise les règles de portée d'avant la version 6.0. Dans ce cas, il n'y a que deux niveaux de portée possibles pour toutes les déclarations de données : globale, ou locale au proctype. Dans la version 6.0 et ultérieures, il y a un troisième niveau de portée : inlines ou blocs.
-Pxxx
Utilise la commande xxx pour le préprocesseur au lieu du préprocesseur C standard.
-p
Inclut toutes les exécutions d'instructions dans la sortie des simulations.
-qN
Supprime la sortie générée pour le canal N lors des simulations.
-r
Affiche tous les événements de réception de message, donnant le nom et le numéro du processus récepteur et le numéro de ligne source correspondant. Pour chaque paramètre de message, affiche le type de message et le numéro et nom du canal de message.
-replay
Rejoue une trace d'erreur trouvée lors d'une vérification précédente (voir -search). Comme avec -search, les arguments destinés à Spin lui-même (par exemple, -p) peuvent être donnés avant l'argument -replay. Si le rejeu ne peut être fait qu'avec l'exécutable ./pan, alors les arguments pour le rejeu avec l'exécutable ./pan peuvent être donnés après l'argument -replay.
-search
Compile et exécute directement. Les drapeaux de compilation et d'exécution de la vérification peuvent être ajoutés après ce paramètre. Tout paramètre de temps d'analyse de Spin

-s
Inclure toutes les opérations d'envoi dans la sortie des simulations.
-T
Ne pas indenter automatiquement la sortie de printf du processus i avec i tabulations.
-t[N]
Effectuer une simulation guidée, en suivant la [Nème] piste d'erreur produite par une exécution de vérification antérieure, voir les manuels en ligne pour plus de détails sur la vérification. Par défaut, la piste d'erreur est recherchée dans un fichier portant le même nom de base que le modèle, et avec l'extension .trail. Voir aussi -k.
-v
Mode verbeux, ajouter plus de détails, et générer plus d'indices et d'avertissements concernant le modèle.
-V
Afficher le numéro de version de SPIN et quitter.
-x
Générer les tables de transition à partir du modèle et quitter (génère, compile et exécute pan.c).

Avec seulement un nom de fichier comme argument et aucun indicateur d'option, SPIN effectue une simulation aléatoire du modèle spécifié dans le fichier. Cela ne génère normalement aucune sortie, à l'exception de ce qui est généré explicitement par l'utilisateur dans le modèle avec des instructions printf, et quelques détails sur l'état final atteint après la fin de la simulation. Le groupe d'options -bgilmprstv est utilisé pour définir le niveau d'information souhaité par l'utilisateur concernant une exécution de simulation aléatoire, guidée ou interactive. Chaque ligne de sortie contient normalement une référence à la ligne source de la spécification qui l'a générée. Si l'option -i est incluse, la simulation est interactive, ou si l'option -t ou -k fichier est ajoutée, la simulation est guidée.

-b
Supprimer l'exécution des instructions printf dans le modèle.
-g
Afficher à chaque pas de temps la valeur actuelle des variables globales.
-l
En combinaison avec l'option -p, afficher la valeur actuelle des variables locales du processus.
-p
Afficher à chaque pas de simulation quel processus a changé d'état, et quelle instruction source a été exécutée.
-r
Afficher tous les événements de réception de messages, en donnant le nom et le numéro du processus receveur et le numéro de ligne source correspondant. Pour chaque paramètre de message, afficher le type de message et le numéro et le nom du canal de message.
-s
Afficher tous les événements d'envoi de messages.
-v
Mode verbeux, ajouter plus de détails, et générer plus d'indices et d'avertissements concernant le modèle.
