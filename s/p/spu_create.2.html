spu_create(2) Manuel des appels système spu_create(2)

NOM

spu_create - créer un nouveau contexte spu

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/spu.h> /* Définition des constantes SPU_* */
#include <sys/syscall.h> /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_spu_create, const char *path, unsigned int flags,
            mode_t mode, int neighbor_fd);

Note: glibc ne fournit pas d'enrobage pour spu_create(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

L'appel système spu_create() est utilisé sur les machines PowerPC qui implémentent l'architecture Cell Broadband Engine afin d'accéder aux unités de traitement synergiques (SPU). Il crée un nouveau contexte logique pour une SPU dans path et retourne un descripteur de fichier associé. path doit faire référence à un répertoire inexistant dans le point de montage du système de fichiers SPU (spufs). Si spu_create() réussit, un répertoire est créé à path et il est rempli avec les fichiers décrits dans spufs(7).

Lorsqu'un contexte est créé, le descripteur de fichier retourné ne peut être passé qu'à spu_run(2), utilisé comme argument dirfd pour la famille d'appels système *at (par exemple, openat(2)), ou fermé ; d'autres opérations ne sont pas définies. Un contexte SPU logique est détruit (ainsi que tous les fichiers créés dans le répertoire path du contexte) une fois que la dernière référence au contexte a disparu ; cela se produit généralement lorsque le descripteur de fichier retourné par spu_create() est fermé.

L'argument mode (moins les bits définis dans le umask(2) du processus) spécifie les permissions utilisées pour la création du nouveau répertoire dans spufs. Voir stat(2) pour une liste complète des valeurs possibles de mode.

L'argument neighbor_fd est utilisé uniquement lorsque le drapeau SPU_CREATE_AFFINITY_SPU est spécifié ; voir ci-dessous.

L'argument flags peut être zéro ou toute combinaison OR-ée bit à bit des constantes suivantes :

SPU_CREATE_EVENTS_ENABLED
Plutôt que d'utiliser des signaux pour signaler les erreurs DMA, utiliser l'argument event de spu_run(2).
SPU_CREATE_GANG
Créer un gang SPU au lieu d'un contexte. (Un gang est un groupe de contextes SPU qui sont fonctionnellement liés les uns aux autres et qui partagent des paramètres de planification communs — priorité et politique. À l'avenir, une planification de gang pourrait être implémentée, provoquant l'entrée et la sortie du groupe en tant qu'unité unique.)
Un nouveau répertoire sera créé à l'emplacement spécifié par l'argument path. Ce gang pourra contenir d'autres contextes SPU, en fournissant un nom de chemin qui se trouve dans le répertoire du gang à d'autres appels à spu_create().
SPU_CREATE_NOSCHED
Créer un contexte qui n'est pas affecté par le planificateur SPU. Une fois le contexte exécuté, il ne sera pas planifié pour être retiré tant qu'il n'aura pas été détruit par le processus créateur.
Étant donné que le contexte ne peut pas être retiré de la SPU, certaines fonctionnalités sont désactivées pour les contextes SPU_CREATE_NOSCHED. Seul un sous-ensemble de fichiers sera disponible dans ce répertoire de contexte dans spufs. De plus, les contextes SPU_CREATE_NOSCHED ne peuvent pas générer de fichier core lors d'un plantage.
La création de contextes SPU_CREATE_NOSCHED nécessite la capacité CAP_SYS_NICE.
SPU_CREATE_ISOLATE
Créer un contexte SPU isolé. Les contextes isolés sont protégés de certaines opérations de l'élément de traitement PPE (PowerPC Processing Element), telles que l'accès au stockage local SPU et au registre NPC.
La création de contextes SPU_CREATE_ISOLATE nécessite également le drapeau SPU_CREATE_NOSCHED.
SPU_CREATE_AFFINITY_SPU (depuis Linux 2.6.23)
Créer un contexte avec affinité pour un autre contexte SPU. Ces informations d'affinité sont utilisées dans l'algorithme de planification SPU. L'utilisation de ce drapeau nécessite qu'un descripteur de fichier faisant référence à l'autre contexte SPU soit passé dans l'argument neighbor_fd.
SPU_CREATE_AFFINITY_MEM (depuis Linux 2.6.23)
Créer un contexte avec affinité pour la mémoire système. Ces informations d'affinité sont utilisées dans l'algorithme de planification SPU.

VALEUR RENVOYÉE

En cas de succès, spu_create() retourne un nouveau descripteur de fichier. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
L'utilisateur actuel n'a pas de droits d'écriture sur le point de montage spufs(7).
EEXIST
Un contexte SPU existe déjà au chemin spécifié.
EFAULT
path n'est pas un pointeur de chaîne valide dans l'espace d'adressage du processus appelant.
EINVAL
path n'est pas un répertoire dans le point de montage spufs(7), ou des drapeaux invalides ont été fournis.
ELOOP
Trop de liens symboliques ont été trouvés lors de la résolution de path.
EMFILE
La limite par processus du nombre de descripteurs de fichiers ouverts a été atteinte.
ENAMETOOLONG
path est trop long.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENODEV
Un contexte isolé a été demandé, mais le matériel ne supporte pas l'isolation SPU.
ENOENT
Une partie de path n'a pas pu être résolue.
ENOMEM
Le noyau n'a pas pu allouer toutes les ressources requises.
ENOSPC
Il n'y a pas assez de ressources SPU disponibles pour créer un nouveau contexte ou la limite spécifique à l'utilisateur pour le nombre de contextes SPU a été atteinte.
ENOSYS
La fonctionnalité n'est pas fournie par le système actuel, car soit le matériel ne fournit pas de SPU, soit le module spufs n'est pas chargé.
ENOTDIR
Une partie de path n'est pas un répertoire.
EPERM
Le drapeau SPU_CREATE_NOSCHED a été donné, mais l'utilisateur ne possède pas la capacité CAP_SYS_NICE.

FICHIERS

path doit pointer vers un emplacement sous le point de montage de spufs. Par convention, il est monté dans /spu.

NORMES

Linux sur PowerPC.

HISTORIQUE

Linux 2.6.16.

Avant l'ajout du drapeau SPU_CREATE_AFFINITY_SPU dans Linux 2.6.23, l'appel système spu_create() prenait seulement trois arguments (c'est-à-dire qu'il n'y avait pas d'argument neighbor_fd).

NOTES

spu_create() est destiné à être utilisé par des bibliothèques qui implémentent une interface plus abstraite pour les SPU, et non par des applications ordinaires. Voir http://www.bsc.es/projects/deepcomputing/linuxoncell/ pour les bibliothèques recommandées.

EXEMPLES

Voir spu_run(2) pour un exemple d'utilisation de spu_create()

VOIR AUSSI

close(2), spu_run(2), capabilities(7), spufs(7)
