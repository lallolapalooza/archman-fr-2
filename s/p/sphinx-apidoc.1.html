NOM

sphinx-apidoc - Outil de génération de documentation d'API Sphinx

SYNTAXE

sphinx-apidoc [OPTIONS] -o <CHEMIN_SORTIE> <CHEMIN_MODULE> [MOTIF_EXCLUSION ...]

DESCRIPTION

sphinx-apidoc est un outil pour la génération automatique de sources Sphinx qui, en utilisant l'extension autodoc, documente un paquet entier dans le style d'autres outils de documentation d'API automatiques.

ATTENTION :

sphinx-apidoc génère des fichiers source qui utilisent sphinx.ext.autodoc pour documenter tous les modules trouvés. Si des modules ont des effets secondaires lors de l'importation, ceux-ci seront exécutés par autodoc lorsque sphinx-build sera exécuté.

Si vous documentez des scripts (par opposition à des modules de bibliothèque), assurez-vous que leur routine principale est protégée par une condition if __name__ == '__main__'.

OPTIONS

-o <CHEMIN_SORTIE>
Répertoire où placer les fichiers de sortie. S'il n'existe pas, il est créé.
-q
Ne rien afficher sur la sortie standard, n'écrire que les avertissements et les erreurs sur la sortie d'erreur standard.
-f, --force
Forcer l'écrasement de tous les fichiers générés existants.
-l, --follow-links
Suivre les liens symboliques. Par défaut : False.
-n, --dry-run
Ne pas créer ou supprimer de fichiers.
-s <suffixe>
Suffixe pour les fichiers source générés. Par défaut : rst.
-d <PROFONDEUR_MAX>
Profondeur maximale pour le fichier de table des matières généré. Par défaut : 4.
--tocfile
Nom de fichier pour un fichier de table des matières. Par défaut : modules.
-T, --no-toc
Ne pas créer de fichier de table des matières. Ignoré lorsque --full est spécifié.
--remove-old
Supprimer les fichiers existants dans le répertoire de sortie qui ne sont plus créés. Non compatible avec --full.
-F, --full
Générer un projet Sphinx complet (conf.py, Makefile etc.) en utilisant le même mécanisme que sphinx-quickstart.
-e, --separate
Mettre la documentation de chaque module sur sa propre page.

Ajouté dans la version 1.2.

-E, --no-headings
Ne pas créer d'en-têtes pour les modules/paquets. Ceci est utile, par exemple, lorsque les docstrings contiennent déjà des en-têtes.
-P, --private
Inclure les modules "_private".

Ajouté dans la version 1.2.

--implicit-namespaces
Sans cette option, sphinx-apidoc recherche dans sys.path les paquets Python contenant des fichiers __init__.py, ou des modules Python à fichier unique.
-M, --module-first
Placer la documentation du module avant la documentation du sous-module.

Ces options sont utilisées lorsque --full est spécifié :

-a
Ajoute chemin_module à sys.path.
-H <projet>
Définit le nom du projet à inclure dans les fichiers générés (voir project).
-A <auteur>
Définit le nom de l'auteur ou des auteurs à inclure dans les fichiers générés (voir copyright).
-V <version>
Définit la version du projet à inclure dans les fichiers générés (voir version).
-R <release>
Définit la release du projet à inclure dans les fichiers générés (voir release).

Modèles de projet

Ajouté dans la version 2.2 : Options de modèles de projet pour sphinx-apidoc

-t, --templatedir=CHEMIN_MODELÈLE
Répertoire de modèles pour les fichiers de modèles. Vous pouvez modifier les modèles des fichiers de projet sphinx générés par apidoc. Les fichiers de modèles Jinja2 suivants sont autorisés :
  • module.rst.jinja
  • package.rst.jinja
  • toc.rst.jinja
  • root_doc.rst.jinja
  • conf.py.jinja
  • Makefile.jinja
  • Makefile.new.jinja
  • make.bat.jinja
  • make.bat.new.jinja

Pour plus de détails, veuillez vous référer aux fichiers de modèles système fournis par Sphinx. (sphinx/templates/apidoc et sphinx/templates/quickstart)

ENVIRONNEMENT

SPHINX_APIDOC_OPTIONS
Une liste d'options séparées par des virgules à ajouter aux directives automodule générées. Par défaut : members,undoc-members,show-inheritance.

NOM

sphinx-apidoc - Générer des squelettes de documentation API Sphinx à partir de modules Python.

SYNTAXE

sphinx-apidoc [-o|--output-dir output_path] [-f|--force] [-l|--leave-generated] [-q|--quiet] [-v|--verbose] [-e|--separate-modules] [-P|--implicit-namespaces] [-M|--module-first] [-T|--toc-only] [-b|--build-dir build_path] [-d|--dest-dir dest_path] [-x|--exclude-paths path1[,path2[,...]]] [-r|--suffix suffix] [-s|--template-dir template_dir] [-S|--subprojects subproject_dir] [--implicit-relations] [--no-toc-inheritance] [-h|--help] [-H|--html-static-path html_static_path] [-D name=value] path1 [path2 ... pathN]

DESCRIPTION

sphinx-apidoc est un utilitaire qui scanne les modules Python dans un chemin donné et génère des squelettes de documentation API dans le format reStructuredText (.rst) que Sphinx peut ensuite utiliser pour créer de la documentation HTML, PDF, etc.

Il est particulièrement utile pour documenter de grands projets Python où la génération manuelle des fichiers .rst pour chaque module serait fastidieuse.

OPTIONS

-o output_path, --output-dir=output_path
Spécifie le répertoire où les fichiers .rst générés doivent être placés. Ce répertoire sera créé s'il n'existe pas.
-f, --force
Écrase les fichiers .rst existants s'ils sont déjà présents dans le répertoire de sortie.
-l, --leave-generated
Ne supprime pas les fichiers .rst générés s'ils sont à jour. Utile pour la génération continue.
-q, --quiet
Mode silencieux, n'affiche que les erreurs.
-v, --verbose
Mode verbeux, affiche plus d'informations pendant l'exécution.
-e, --separate-modules
Crée un fichier .rst séparé pour chaque module trouvé, plutôt qu'un seul fichier récapitulatif.
-P, --implicit-namespaces
Active la découverte implicite des espaces de noms. Utile pour les projets utilisant des espaces de noms PEP 420.
-M, --module-first
Place les informations du module avant la documentation des membres du module.
-T, --toc-only
Génère uniquement la table des matières, sans la documentation API elle-même.
-b build_path, --build-dir=build_path
Spécifie le répertoire de construction de Sphinx (utile si différent du répertoire de configuration).
-d dest_path, --dest-dir=dest_path
Spécifie le répertoire de destination pour les fichiers de sortie (similaire à -o mais plus générique).
-x path1[,path2[,...]], --exclude-paths=path1[,path2[,...]]
Liste des chemins à exclure lors de la génération des fichiers .rst (séparés par des virgules).
-r suffix, --suffix=suffix
Suffixe à utiliser pour les fichiers de sortie générés (par défaut : .rst).
-s template_dir, --template-dir=template_dir
Répertoire contenant les modèles personnalisés pour la génération des fichiers .rst.
-S subproject_dir, --subprojects=subproject_dir
Indique un sous-projet dont la documentation doit être incluse.
--implicit-relations
Détecte et inclut les relations implicites entre les modules.
--no-toc-inheritance
Ne pas hériter de la table des matières des sous-modules.
-H html_static_path, --html-static-path=html_static_path
Ajoute un chemin au répertoire statique HTML.
-D name=value
Définit une variable de configuration Sphinx (par exemple, -D project=MonProjet).
path1 [path2 ... pathN]
Un ou plusieurs chemins vers les modules Python à documenter.

ENVIRONNEMENT

Aucune variable d'environnement spécifique n'est particulièrement pertinente pour sphinx-apidoc, au-delà de celles utilisées par Python lui-même pour la découverte de modules.
