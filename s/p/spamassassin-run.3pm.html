NOM

spamassassin - script de filtrage simple en façade pour SpamAssassin

SYNOPSIS

spamassassin [options] [ < message_email | chemin ... ]

spamassassin -d [ < message_email | chemin ... ]

spamassassin -r [ < message_email | chemin ... ]

spamassassin -k [ < message_email | chemin ... ]

spamassassin -W|-R [ < message_email | chemin ... ]

Options :

-L, --local                       Tests locaux seulement (pas de tests en ligne)
-r, --report                      Signaler le message comme spam
-k, --revoke                      Annuler le signalement du message comme spam
-d, --remove-markup               Supprimer les rapports de spam d'un message
-C chemin, --configpath=chemin, --config-file=chemin
                                  Chemin vers le répertoire de configuration standard
-p prefs, --prefspath=fichier, --prefs-file=fichier
                                  Définir le fichier de préférences utilisateur
--siteconfigpath=chemin           Chemin pour les configurations du site
                                  (par défaut : /etc/mail/spamassassin)
--cf='ligne de configuration'    Ligne de configuration supplémentaire
--pre='ligne de configuration'   Ligne de ".pre" supplémentaire (ajoutée au début de la configuration)
-x, --nocreate-prefs              Ne pas créer le fichier de préférences utilisateur
-e, --exit-code                   Sortir avec un code de sortie non nul si le
                                  message testé était du spam
--mbox                            lire les messages au format mbox
--mbx                             lire les messages au format UW mbx
-t, --test-mode                   Transférer le message et ajouter un rapport supplémentaire
                                  en bas
--lint                            Vérifier la syntaxe de l'ensemble des règles : signaler les erreurs de syntaxe
-W, --add-to-welcomelist          Ajouter les adresses dans l'e-mail à la liste d'accueil persistante
--add-to-blocklist                Ajouter les adresses dans l'e-mail à la liste de blocage persistante
-R, --remove-from-welcomelist     Supprimer toutes les adresses trouvées dans l'e-mail de la liste d'accueil persistante
--add-addr-to-welcomelist=addr    Ajouter addr à la liste d'accueil persistante
--add-addr-to-blocklist=addr      Ajouter addr à la liste de blocage persistante
--remove-addr-from-welcomelist=addr Supprimer addr de la liste d'accueil persistante
-u nomutilisateur, --username=nomutilisateur  Remplacer le nom d'utilisateur obtenu de l'environnement d'exécution, utilisé avec SQL
-4 --ipv4only, --ipv4-only, --ipv4 Utiliser IPv4, désactiver l'utilisation d'IPv6 pour le DNS etc.
-6                                Utiliser IPv6, désactiver l'utilisation d'IPv4 si possible
--progress                        Afficher la barre de progression
-D, --debug [zone,...]            Afficher les messages de débogage
-V, --version                     Afficher la version
-h, --help                        Afficher le message d'aide

DESCRIPTION

spamassassin est un filtre simple en façade pour SpamAssassin.

En utilisant la base de règles de SpamAssassin, il emploie un large éventail de tests heuristiques sur les en-têtes et le corps du texte des e-mails pour identifier le "spam", également connu sous le nom de courrier indésirable en masse. Une fois identifié, le courrier est ensuite marqué comme spam pour un filtrage ultérieur par l'application de l'agent utilisateur de courrier de l'utilisateur.

Les opérations de marquage par défaut qui ont lieu sont détaillées dans "TAGGING" dans spamassassin.

Par défaut, le(s) message(s) sont lus depuis STDIN (< message_email), ou depuis des fichiers et répertoires spécifiés (chemin ...) STDIN et les fichiers sont supposés être au format fichier, avec un seul message par fichier. Les répertoires sont supposés être dans un format où chaque fichier du répertoire ne contient qu'un seul message (les répertoires ne sont pas parcourus de manière récursive et les noms de fichiers contenant des espaces ou commençant par "." ou "," sont ignorés). Les options --mbox et --mbx peuvent remplacer le format supposé, voir les informations d'OPTION appropriées ci-dessous.

Les fichiers compressés avec gzip/bzip2/xz/lz4/lzip/lzo sont décompressés automatiquement. Voir "Mail::SpamAssassin::ArchiveIterator" pour plus de détails.

Veuillez noter que SpamAssassin n'est pas conçu pour analyser de très gros messages. Les messages de plus de ~10-20 Mo ne devraient pas être transmis à SpamAssassin, car la consommation de mémoire augmentera rapidement.

OPTIONS

-e, --error-code, --exit-code
Sortir avec un code d'erreur non nul, si le message est déterminé comme étant du spam.
-h, --help
Afficher le message d'aide et quitter.
-V, --version
Afficher la version et quitter.
-t, --test-mode
Mode test. Transférer le message et ajouter un rapport supplémentaire. Notez que le texte du rapport suppose que le message est du spam, car en utilisation normale, il n'est visible que dans ce cas. Faites attention au score à la place.

Si vous exécutez ceci avec -d, le message aura d'abord son balisage SpamAssassin supprimé avant d'être testé.

-r, --report
Signaler ce message comme spam vérifié manuellement. Cela soumettra le message électronique lu depuis STDIN à diverses bases de données de blocage de spam. Actuellement, il s'agit du Distributed Checksum Clearinghouse "https://www.dcc-servers.net/dcc/", Pyzor "https://www.pyzor.org/", Razor de Vipul "http://razor.sourceforge.net/", et SpamCop "https://www.spamcop.net/".

Si le message contient du balisage SpamAssassin, le balisage sera automatiquement supprimé avant la soumission. Les modules de support pour DCC, Pyzor et Razor doivent être installés pour que le spam soit signalé à chaque service. Les rapports SpamCop auront un plus grand effet si vous vous enregistrez et définissez l'option "spamcop_to_address".

Le message sera également soumis aux systèmes d'apprentissage de SpamAssassin ; actuellement, il s'agit du système de filtrage statistique bayésien interne (les règles BAYES). (Notez que si vous voulez uniquement effectuer un apprentissage statistique, et que vous ne voulez pas signaler de courrier à des tiers, vous devriez utiliser la commande "sa-learn" directement à la place.)

-k, --revoke
Annuler le signalement de ce message. Cela annulera le message électronique lu depuis STDIN auprès de diverses bases de données de blocage de spam. Actuellement, il s'agit de Razor de Vipul.

Le support de révocation pour le Distributed Checksum Clearinghouse, Pyzor et SpamCop n'est actuellement pas disponible.

Si le message contient du balisage SpamAssassin, le balisage sera automatiquement supprimé avant la soumission. Les modules de support pour Razor doivent être installés pour que le spam soit annulé du service.

Le message sera également soumis comme 'ham' (non-spam) aux systèmes d'apprentissage de SpamAssassin ; actuellement, il s'agit du système de filtrage statistique bayésien interne (les règles BAYES). (Notez que si vous voulez uniquement effectuer un apprentissage statistique, et que vous ne voulez pas signaler de courrier à des tiers, vous devriez utiliser la commande "sa-learn" directement à la place.)

--lint
Vérification syntaxique (lint) de l'ensemble des règles et des fichiers de configuration, signalant les fautes de frappe et les règles qui ne se compilent pas correctement. Se termine avec 0 s'il n'y a pas d'erreurs, ou supérieur à 0 si des erreurs sont trouvées.
-W, --add-to-welcomelist
Précédemment --add-to-whitelist qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ajoute toutes les adresses électroniques, dans les en-têtes et le corps du message électronique lu depuis STDIN, à une liste d'accueil persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

-R, --remove-from-welcomelist
Précédemment --remove-from-whitelist, qui fonctionnera de manière interchangeable jusqu'à 4.1.

Supprime toutes les adresses électroniques, dans les en-têtes et le corps du message électronique lu depuis STDIN, d'une liste d'adresses persistante. STDIN doit contenir un message électronique complet, donc pour supprimer une seule adresse, vous devriez utiliser --remove-addr-from-welcomelist à la place.

Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--add-addr-to-welcomelist
Précédemment --add-addr-to-whitelist, qui fonctionnera de manière interchangeable jusqu'à 4.1.

Ajoute l'adresse électronique nommée à une liste d'accueil (welcomelist) d'adresses persistantes. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--add-addr-to-blocklist
Précédemment --add-addr-to-blacklist, qui fonctionnera de manière interchangeable jusqu'à 4.1.

Ajoute l'adresse électronique nommée à une liste de blocage (blocklist) d'adresses persistantes. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--remove-addr-from-welcomelist
Précédemment --remove-addr-from-whitelist, qui fonctionnera de manière interchangeable jusqu'à 4.1.

Supprime l'adresse électronique nommée d'une liste d'accueil (welcomelist) d'adresses persistantes. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

-u username, --username=username
Si spécifié, ce nom d'utilisateur remplacera le nom d'utilisateur pris de l'environnement d'exécution. Vous pouvez utiliser cette option pour spécifier des utilisateurs dans une configuration d'utilisateur virtuel lors de l'utilisation de SQL comme backend Bayes.

NOTE : Cette option ne changera pas vers le username donné, elle tentera seulement d'agir au nom de cet utilisateur. Pour cette raison, vous devrez avoir les permissions appropriées pour pouvoir changer les fichiers appartenant à username. Dans le cas de SQL, ce n'est généralement pas un problème.

--ipv4only, --ipv4-only, --ipv4
N'utilise pas IPv6 pour les tests DNS. Normalement, SpamAssassin essaiera de détecter si IPv6 est disponible, en utilisant seulement IPv4 si ce n'est pas le cas. Utilisez cette option si les tests existants de disponibilité IPv6 produisent des résultats incorrects ou des plantages.
-L, --local
Effectue uniquement les tests ''locaux'', ceux qui ne nécessitent pas de connexion Internet pour fonctionner. Normalement, SpamAssassin essaiera de détecter si vous êtes connecté au réseau avant d'effectuer ces tests de toute façon, mais pour des vérifications plus rapides, vous pourriez vouloir l'utiliser.

Notez que les règles réseau de SpamAssassin sont exécutées en parallèle. Cela peut entraîner une surcharge en termes de nombre de descripteurs de fichiers requis si --local n'est pas utilisé ; il est recommandé que la limite minimale sur les fds soit augmentée à au moins 256 par sécurité.

-d, --remove-markup
Supprime le balisage SpamAssassin (le rapport "Résultats SpamAssassin", les en-têtes X-Spam-Status, etc.) du message électronique. Le message résultant, qui sera plus ou moins identique à l'entrée originale, pré-SpamAssassin, sera envoyé à STDOUT.

(Note : le message ne sera pas exactement identique ; certains en-têtes seront reformatés en raison de certaines fonctionnalités du package Mail::Internet, mais le texte du corps le sera.)

-C path, --configpath=path, --config-file=path
Utilise le chemin spécifié pour localiser les fichiers de configuration distribués. Ignore les répertoires par défaut (généralement "/usr/share/spamassassin" ou similaire).
--siteconfigpath=path
Utilise le chemin spécifié pour localiser les fichiers de configuration spécifiques au site. Ignore les répertoires par défaut (généralement "/etc/mail/spamassassin" ou similaire).
--cf='config line'
Ajoute des lignes de configuration supplémentaires directement depuis la ligne de commande, analysées après la lecture des fichiers de configuration. Plusieurs arguments --cf peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte. Par exemple : 
spamassassin -t --cf="body NEWRULE /text/" --cf="score NEWRULE 3.0"
--pre='config line'
Ajoute des lignes de configuration .pre supplémentaires directement depuis la ligne de commande, analysées avant la lecture des fichiers de configuration. Plusieurs arguments --pre peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte. Par exemple : 
spamassassin -t --pre="loadplugin Mail::SpamAssassin::Plugin::Foobar"
-p prefs, --prefspath=prefs, --prefs-file=prefs
Lit les préférences de score de l'utilisateur depuis prefs (généralement "$HOME/.spamassassin/user_prefs").
--progress
Affiche une barre de progression (sur STDERR) indiquant la progression actuelle. Cette option ne sera utile que si vous redirigez STDOUT (et non STDERR). Dans le cas où aucun terminal valide n'est trouvé, cette option se comportera de manière très similaire à l'option --showdots dans d'autres programmes SpamAssassin.
-D [area,...], --debug [area,...]
Produit une sortie de débogage. Si aucune zone n'est listée, toutes les informations de débogage sont imprimées. La sortie de diagnostic peut également être activée pour chaque zone individuellement ; area est la zone du code à instrumenter. Par exemple, pour produire une sortie de diagnostic sur bayes, learn et dns, utilisez : 
spamassassin -D bayes,learn,dns

Utilisez une chaîne vide (-D '') pour indiquer aucune zone lorsque l'élément suivant sur la ligne de commande est un chemin, afin d'empêcher que le chemin ne soit analysé comme une zone.

Les messages d'information de priorité plus élevée qui conviennent à l'enregistrement dans des circonstances normales sont disponibles avec une zone de "info".

Pour plus d'informations sur les zones (également appelées canaux) disponibles, veuillez consulter la documentation à l'adresse :

L<https://wiki.apache.org/spamassassin/DebugChannels>
-x, --nocreate-prefs
Désactive la création du fichier de préférences utilisateur.
--mbox
Indique que le(s) message(s) d'entrée sont au format mbox. mbox est un format standard de dossier de messages Unix.
--mbx
Indique que le(s) message(s) d'entrée sont au format UW .mbx. mbx est le format de boîte aux lettres utilisé dans l'implémentation IMAP de l'Université de Washington ; voir "https://en.wikipedia.org/wiki/UW_IMAP".
