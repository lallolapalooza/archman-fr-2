spawn-fcgi(1) Manuel des commandes générales spawn-fcgi(1)

NOM

spawn-fcgi - Lance des processus FastCGI

SYNTAXE

spawn-fcgi [options] [ -- <fcgiapp> [arguments de l'application fcgi]]

spawn-fcgi -v

spawn-fcgi -h

DESCRIPTION

spawn-fcgi est utilisé pour lancer des processus FastCGI locaux et distants.

Bien qu'il soit évidemment nécessaire pour lancer des backends FastCGI distants (le serveur web ne peut en lancer que des locaux), il est recommandé de lancer les backends locaux avec spawn-fcgi aussi.

Raisons pour lesquelles vous pourriez vouloir utiliser spawn-fcgi au lieu d'autre chose :

  • Séparation des privilèges sans nécessiter de binaire suid ni d'exécuter un serveur en tant que root.
  • Vous pouvez redémarrer votre serveur web et les applications FastCGI sans redémarrer les autres.
  • Vous pouvez les exécuter dans différents chroot().
  • L'exécution de vos applications FastCGI ne dépend pas du serveur web que vous utilisez, ce qui permet de tester plus facilement d'autres serveurs web.

OPTIONS

spawn-fcgi accepte les options suivantes :

-f <chemin>
Nom du fichier de l'application FastCGI à lancer. Cette option est obsolète et il est recommandé de toujours spécifier l'application (chemin absolu) et ses paramètres après "--" ; le paramètre fcgiapp est directement utilisé pour l'appel exec(), tandis que pour démarrer le binaire donné avec -f, /bin/sh est nécessaire (qui pourrait ne pas être disponible dans un chroot).
Cette option est ignorée si fcgiapp est donné.
-d <chemin>
Change le répertoire courant avant de lancer l'application.
-a <adresse>
Adresse IPv4/IPv6 à lier ; utilisé seulement si -p est aussi donné. Par défaut "0.0.0.0" (IPv4).
-p <port>
Port TCP à lier ; vous ne pouvez pas combiner cela avec l'option -s.
-s <chemin>
Chemin vers le socket de domaine Unix à lier ; vous ne pouvez pas combiner cela avec l'option -p.
-C <enfants>
(PHP uniquement) Nombre d'enfants à lancer en définissant la variable d'environnement PHP_FCGI_CHILDREN. Par défaut, la variable d'environnement n'est pas écrasée ; php ne lancera aucun enfant si la variable n'est pas définie (équivalent à la définir à 0).
-F <enfants>
Nombre d'enfants à forker, par défaut 1. Cette option ne fonctionne pas avec -n, regardez multiwatch(1) si vous voulez superviser plusieurs forks sur le même socket.
-b <attente>
Attente autorisée sur le socket (par défaut 1024). Ceci est généralement limité aussi par le noyau, vérifiez sysctl net.core.somaxconn (par défaut 128) pour linux.
L'attente est la file d'attente des connexions que le noyau accepte avant que l'application utilisateur ne les voie.
-P <chemin>
Nom du fichier PID pour les processus lancés (ignoré en mode sans fork)
-n
Aucun fork ne doit avoir lieu (pour daemontools)
-M <mode>
Change le mode du fichier du socket de domaine Unix (entier octal) ; utilisé seulement si -s est aussi donné. Par défaut lecture+écriture pour l'utilisateur et le groupe (0660) dans la mesure où l'umask le permet.
-?, -h
Instructions générales d'utilisation
-v
Affiche les informations de version et quitte

Les options suivantes ne sont disponibles que si vous invoquez spawn-fcgi en tant que root :

-c <répertoire>
Chroot vers le répertoire spécifié ; le socket de domaine Unix est créé à l'intérieur du chroot sauf si -S est donné.
-S
Crée le socket de domaine Unix avant le chroot().
-u
ID utilisateur vers lequel changer.
-g
ID de groupe vers lequel changer. Par défaut le groupe principal de l'utilisateur donné pour -u.
-U
Change l'utilisateur du socket de domaine Unix, par défaut la valeur de -u. (utilisé seulement si -s est donné)
-G
Change le groupe du socket de domaine Unix, par défaut le groupe principal de l'utilisateur donné pour -U ; si -U n'était pas donné, par défaut la valeur de -g. (utilisé seulement si -s est donné)
