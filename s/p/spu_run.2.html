spu_run(2) Manuel des appels système spu_run(2)

NOM

spu_run - exécute un contexte SPU

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/spu.h>          /* Définition des constantes SPU_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_spu_run, int fd, uint32_t *npc, uint32_t *event);

Note : glibc ne fournit pas d'enveloppe pour spu_run(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

L'appel système spu_run() est utilisé sur les machines PowerPC qui implémentent l'architecture Cell Broadband Engine afin d'accéder aux unités de traitement Synergistic Processor Units (SPU). L'argument fd est un descripteur de fichier retourné par spu_create(2) qui fait référence à un contexte SPU spécifique. Lorsque le contexte est planifié sur un SPU physique, il commence l'exécution à l' pointeur d'instruction passé dans npc.

L'exécution du code SPU se fait de manière synchrone, ce qui signifie que spu_run() bloque pendant que le SPU est toujours en exécution. S'il est nécessaire d'exécuter du code SPU en parallèle avec d'autres codes, que ce soit sur le CPU principal ou sur d'autres SPUs, un nouveau thread d'exécution doit être créé au préalable (par exemple, en utilisant pthread_create(3)).

Lorsque spu_run() retourne, la valeur courante du compteur de programme SPU est écrite dans npc, de sorte que les appels successifs à spu_run() peuvent utiliser le même pointeur npc.

L'argument event fournit un tampon pour un code d'état étendu. Si le contexte SPU a été créé avec le drapeau SPU_CREATE_EVENTS_ENABLED, ce tampon est alors rempli par le noyau Linux avant que spu_run() ne retourne.

Le code d'état peut être une (ou plusieurs) des constantes suivantes :

SPE_EVENT_DMA_ALIGNMENT
Une erreur d'alignement DMA s'est produite.
SPE_EVENT_INVALID_DMA
Une commande DMA MFC invalide a été tentée.
SPE_EVENT_SPE_DATA_STORAGE
Une erreur de stockage DMA s'est produite.
SPE_EVENT_SPE_ERROR
Une instruction illégale a été exécutée.

NULL est une valeur valide pour l'argument event. Dans ce cas, les événements ne seront pas rapportés au processus appelant.

VALEUR RENVOYÉE

En cas de succès, spu_run() renvoie la valeur du registre spu_status. En cas d'échec, il renvoie -1 et définit errno pour indiquer l'erreur.

La valeur du registre spu_status est un masque de bits de codes d'état et, éventuellement, un code de 14 bits retourné par l'instruction stop-and-signal sur le SPU. Les masques de bits pour les codes d'état sont :

0x02
Le SPU a été arrêté par une instruction stop-and-signal.
0x04
Le SPU a été arrêté par une instruction halt.
0x08
Le SPU attend sur un canal.
0x10
Le SPU est en mode pas à pas.
0x20
Le SPU a tenté d'exécuter une instruction invalide.
0x40
Le SPU a tenté d'accéder à un canal invalide.
0x3fff0000
Les bits masqués avec cette valeur contiennent le code retourné par une instruction stop-and-signal. Ces bits ne sont valides que si le bit 0x02 est défini.

Si spu_run() n'a pas renvoyé d'erreur, un ou plusieurs bits parmi les huit inférieurs sont toujours définis.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide.
EFAULT
npc n'est pas un pointeur valide, ou event est non-NULL et un pointeur invalide.
EINTR
Un signal s'est produit pendant que spu_run() était en cours ; voir signal(7). La valeur de npc a été mise à jour vers la nouvelle valeur du compteur de programme si nécessaire.
EINVAL
fd n'est pas un descripteur de fichier valide retourné par spu_create(2).
ENOMEM
Il n'y avait pas assez de mémoire disponible pour gérer une faute de page résultant d'un accès direct à la mémoire du Memory Flow Controller (MFC).
ENOSYS
La fonctionnalité n'est pas fournie par le système actuel, soit parce que le matériel ne fournit pas de SPU, soit parce que le module spufs n'est pas chargé.

NORMES

Linux sur PowerPC.

HISTORIQUE

Linux 2.6.16.

NOTES

spu_run() est destiné à être utilisé à partir de bibliothèques qui implémentent une interface plus abstraite pour les SPUs, et non à être utilisé à partir d'applications régulières. Voir http://www.bsc.es/projects/deepcomputing/linuxoncell/ pour les bibliothèques recommandées.

EXEMPLES

Voici un exemple d'exécution d'un programme SPU simple, d'une seule instruction, avec l'appel système spu_run().

#include <err.h>
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int main(void)
{
    int       context, fd, spu_status;
    uint32_t  instruction, npc;
    context = syscall(SYS_spu_create, "/spu/example-context", 0, 0755);
    if (context == -1)
        err(EXIT_FAILURE, "spu_create");
    /*
     * Écrire une instruction 'stop 0x1234' dans la mémoire locale
     * du SPU.
     */
    instruction = 0x00001234;
    fd = open("/spu/example-context/mem", O_RDWR);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    write(fd, &instruction, sizeof(instruction));
    /*
     * Définir npc à l'adresse de l'instruction de départ du
     * programme SPU. Comme nous avons écrit l'instruction au
     * début du fichier mem, le point d'entrée sera 0x0.
     */
    npc = 0;
    spu_status = syscall(SYS_spu_run, context, &npc, NULL);
    if (spu_status == -1)
        err(EXIT_FAILURE, "open");
    /*
     * Nous devrions voir un code d'état de 0x12340002 :
     *   0x00000002 (spu arrêté à cause de stop-and-signal)
     * | 0x12340000 (le code de stop-and-signal)
     */
    printf("SPU Status: %#08x\n", spu_status);
    exit(EXIT_SUCCESS);
}

VOIR AUSSI

close(2), spu_create(2), capabilities(7), spufs(7)
