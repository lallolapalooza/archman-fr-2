NOM

spamassassin - script de filtrage frontal simple pour SpamAssassin

SYNTAXE

spamassassin [options] [ < mailmessage | chemin ... ]

spamassassin -d [ < mailmessage | chemin ... ]

spamassassin -r [ < mailmessage | chemin ... ]

spamassassin -k [ < mailmessage | chemin ... ]

spamassassin -W|-R [ < mailmessage | chemin ... ]

Options :

-L, --local                       Tests locaux seulement (pas de tests en ligne)
-r, --report                      Signaler le message comme spam
-k, --revoke                      Annuler le signalement du message comme spam
-d, --remove-markup               Supprimer les rapports de spam d'un message
-C chemin, --configpath=chemin, --config-file=chemin
                                  Chemin vers le répertoire de configuration standard
-p prefs, --prefspath=fichier, --prefs-file=fichier
                                  Définir le fichier de préférences utilisateur
--siteconfigpath=chemin           Chemin pour les configurations du site
                                  (par défaut : /etc/mail/spamassassin)
--cf='ligne de configuration'     Ligne de configuration supplémentaire
--pre='ligne de configuration'    Ligne supplémentaire de ".pre" (ajoutée en préfixe à la configuration)
-x, --nocreate-prefs              Ne pas créer le fichier de préférences utilisateur
-e, --exit-code                   Sortir avec un code de sortie non nul si le
                                  message testé était du spam
--mbox                            lire les messages au format mbox
--mbx                             lire les messages au format UW mbx
-t, --test-mode                   Pipes le message et ajoute un rapport supplémentaire en bas
--lint                            Vérifier la syntaxe de l'ensemble des règles : signaler les erreurs de syntaxe
-W, --add-to-welcomelist          Ajouter les adresses du mail à la liste blanche d'adresses persistante
--add-to-blocklist                Ajouter les adresses du mail à la liste noire d'adresses persistante
-R, --remove-from-welcomelist     Supprimer toutes les adresses trouvées dans le mail de la liste d'adresses persistante
--add-addr-to-welcomelist=addr    Ajouter addr à la liste blanche d'adresses persistante
--add-addr-to-blocklist=addr      Ajouter addr à la liste noire d'adresses persistante
--remove-addr-from-welcomelist=addr Supprimer addr de la liste blanche d'adresses persistante
-u username, --username=username  Remplacer le nom d'utilisateur extrait de l'environnement d'exécution, utilisé avec SQL
-4 --ipv4only, --ipv4-only, --ipv4 Utiliser IPv4, désactiver l'utilisation d'IPv6 pour le DNS etc.
-6                                Utiliser IPv6, désactiver l'utilisation d'IPv4 lorsque possible
--progress                        Afficher la barre de progression
-D, --debug [zone,...]            Afficher les messages de débogage
-V, --version                     Afficher la version
-h, --help                        Afficher le message d'aide

DESCRIPTION

spamassassin est un filtre frontal simple pour SpamAssassin.

En utilisant la base de règles SpamAssassin, il utilise un large éventail de tests heuristiques sur les en-têtes et le corps des e-mails pour identifier le "spam", également connu sous le nom d'e-mails de masse non sollicités. Une fois identifié, l'e-mail est alors marqué comme spam pour un filtrage ultérieur par l'application de l'agent utilisateur de messagerie de l'utilisateur.

Les opérations de marquage par défaut qui ont lieu sont détaillées dans "TAGGING" dans spamassassin.

Par défaut, les messages sont lus depuis STDIN (< mailmessage), ou à partir des fichiers et répertoires spécifiés (chemin ...). STDIN et les fichiers sont supposés être au format fichier, avec un seul message par fichier. Les répertoires sont supposés être dans un format où chaque fichier du répertoire ne contient qu'un seul message (les répertoires ne sont pas parcourus de manière récursive et les noms de fichiers contenant des espaces blancs ou commençant par "." ou "," sont ignorés). Les options --mbox et --mbx peuvent remplacer le format supposé, voir les informations d'OPTION appropriées ci-dessous.

Les fichiers compressés avec gzip/bzip2/xz/lz4/lzip/lzo sont décompressés automatiquement. Voir "Mail::SpamAssassin::ArchiveIterator" pour plus de détails.

Veuillez noter que SpamAssassin n'est pas conçu pour analyser des messages très volumineux. Les messages de plus de ~10-20 Mo ne devraient pas être soumis à SpamAssassin, car la consommation de mémoire augmentera rapidement.

OPTIONS

-e, --error-code, --exit-code
Sortir avec un code d'erreur non nul si le message est déterminé comme étant du spam.
-h, --help
Afficher le message d'aide et quitter.
-V, --version
Afficher la version et quitter.
-t, --test-mode
Mode test. Pipes le message et ajoute un rapport supplémentaire. Notez que le texte du rapport suppose que le message est du spam, car en utilisation normale, il n'est visible que dans ce cas. Faites attention au score à la place.

Si vous exécutez ceci avec -d, le message aura d'abord son balisage SpamAssassin supprimé avant d'être testé.

-r, --report
Signaler ce message comme spam vérifié manuellement. Cela soumettra le message électronique lu depuis STDIN à diverses bases de données de blocage de spam. Actuellement, il s'agit du Distributed Checksum Clearinghouse "https://www.dcc-servers.net/dcc/", Pyzor "https://www.pyzor.org/", Vipul's Razor "http://razor.sourceforge.net/", et SpamCop "https://www.spamcop.net/".

Si le message contient du balisage SpamAssassin, le balisage sera automatiquement supprimé avant la soumission. Les modules de support pour DCC, Pyzor et Razor doivent être installés pour que le spam soit signalé à chaque service. Les rapports SpamCop auront un plus grand effet si vous vous enregistrez et définissez l'option "spamcop_to_address".

Le message sera également soumis aux systèmes d'apprentissage de SpamAssassin ; actuellement, il s'agit du système de filtrage statistique bayésien interne (les règles BAYES). (Notez que si vous voulez *uniquement* effectuer un apprentissage statistique, et ne pas soumettre d'e-mails à des tiers, vous devriez utiliser la commande "sa-learn" directement à la place.)

-k, --revoke
Annuler ce message. Cela annulera le message électronique lu depuis STDIN de diverses bases de données de blocage de spam. Actuellement, il s'agit de Vipul's Razor.

La prise en charge de l'annulation pour le Distributed Checksum Clearinghouse, Pyzor et SpamCop n'est pas actuellement disponible.

Si le message contient du balisage SpamAssassin, le balisage sera automatiquement supprimé avant la soumission. Les modules de support pour Razor doivent être installés pour que le spam soit annulé du service.

Le message sera également soumis comme 'ham' (pas du spam) aux systèmes d'apprentissage de SpamAssassin ; actuellement, il s'agit du système de filtrage statistique bayésien interne (les règles BAYES). (Notez que si vous voulez *uniquement* effectuer un apprentissage statistique, et ne pas soumettre d'e-mails à des tiers, vous devriez utiliser la commande "sa-learn" directement à la place.)

--lint
Vérifier la syntaxe (lint) de l'ensemble des règles et des fichiers de configuration, en signalant les fautes de frappe et les règles qui ne compilent pas correctement. S'arrête avec 0 s'il n'y a pas d'erreurs, ou supérieur à 0 si des erreurs sont trouvées.
-W, --add-to-welcomelist
Précédemment --add-to-whitelist qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ajoute toutes les adresses e-mail, dans les en-têtes et le corps du message électronique lu depuis STDIN, à une liste blanche d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--add-to-blocklist
Précédemment --add-to-blacklist qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ajoute toutes les adresses e-mail, dans les en-têtes et le corps du message électronique lu depuis STDIN, à la liste noire d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec une liste d'adresses persistante activée pour que cela fonctionne.

--add-addr-to-welcomelist=addr
Ajoute une adresse spécifique addr à la liste blanche d'adresses persistante.
--add-addr-to-blocklist=addr
Ajoute une adresse spécifique addr à la liste noire d'adresses persistante.
-R, --remove-from-welcomelist
Supprime toutes les adresses e-mail trouvées dans les en-têtes et le corps du message électronique lu depuis STDIN, de la liste blanche d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste blanche d'adresses persistante activé pour que cela fonctionne.
--remove-addr-from-welcomelist=addr
Supprime une adresse spécifique addr de la liste blanche d'adresses persistante.
-C path, --configpath=path, --config-file=path
Chemin vers le répertoire de configuration standard de SpamAssassin. Ce répertoire contient généralement des fichiers de configuration propres au site (comme "local.cf"). Les fichiers dans ce répertoire sont lus dans l'ordre alphabétique.
--siteconfigpath=path
Chemin vers les configurations du site. Il s'agit d'un répertoire où les configurations spécifiques au site sont stockées. Les fichiers de ce répertoire sont lus dans l'ordre alphabétique. Le comportement par défaut est d'utiliser "/etc/mail/spamassassin".
--cf='ligne de configuration'
Ligne de configuration supplémentaire à inclure.
--pre='ligne de configuration'
Ligne de configuration supplémentaire à ajouter avant toutes les autres configurations (en préfixe).
-x, --no-create-prefs
Ne pas créer le fichier de préférences utilisateur s'il n'existe pas. Par défaut, SpamAssassin essaiera de créer le fichier de préférences utilisateur (généralement "~/.spamassassin/user_prefs") s'il n'existe pas.
-p prefs, --prefspath=file, --prefs-file=file
Chemin vers le fichier de préférences utilisateur. Ceci remplace le chemin par défaut et le nom de fichier.
--mbox
Spécifie que le fichier d'entrée est au format mbox (c'est-à-dire qu'il contient plusieurs messages séparés par des en-têtes "From ..."). Notez que cela ne fonctionne que pour les entrées basées sur des fichiers, pas pour STDIN.
--mbx
Spécifie que le fichier d'entrée est au format UW mbx (c'est-à-dire qu'il contient plusieurs messages séparés par des en-têtes "From <date>"). Notez que cela ne fonctionne que pour les entrées basées sur des fichiers, pas pour STDIN.
-u username, --username=username
Remplace le nom d'utilisateur extrait de l'environnement d'exécution. Ceci est utilisé lorsque vous traitez des e-mails pour un utilisateur spécifique avec des bases de données SQL, par exemple.
-4, --ipv4-only, --ipv4
Utilise exclusivement IPv4 pour les opérations réseau, désactivant l'utilisation d'IPv6.
-6
Utilise exclusivement IPv6 pour les opérations réseau lorsque cela est possible, désactivant l'utilisation d'IPv4.
--progress
Affiche une barre de progression pendant le traitement des messages.
-D [zone,...], --debug [zone,...]
Active les messages de débogage. Vous pouvez spécifier une ou plusieurs zones de débogage (séparées par des virgules) pour un filtrage plus fin, par exemple "-D all" pour tout activer, ou "-D rules,Bayes" pour ne voir que les messages de débogage relatifs aux règles et à Bayes.

-R, --remove-from-welcomelist
Précédemment --remove-from-whitelist, qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Supprime toutes les adresses e-mail, dans les en-têtes et le corps du message lu depuis STDIN, d'une liste d'adresses persistante. STDIN doit contenir un message e-mail complet, donc pour supprimer une seule adresse, vous devriez utiliser --remove-addr-from-welcomelist à la place.

Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--add-addr-to-welcomelist
Précédemment --add-addr-to-whitelist, qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ajoute l'adresse e-mail nommée à une liste d'accueil d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--add-addr-to-blocklist
Précédemment --add-addr-to-blacklist, qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ajoute l'adresse e-mail nommée à une liste de blocage d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

--remove-addr-from-welcomelist
Précédemment --remove-addr-from-whitelist, qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Supprime l'adresse e-mail nommée d'une liste d'accueil d'adresses persistante. Notez que vous devez exécuter "spamassassin" ou "spamd" avec un plugin de liste d'adresses persistante activé pour que cela fonctionne.

-u nom_utilisateur, --username=nom_utilisateur
Si spécifié, ce nom d'utilisateur remplacera le nom d'utilisateur récupéré de l'environnement d'exécution. Vous pouvez utiliser cette option pour spécifier des utilisateurs dans une configuration d'utilisateur virtuel lors de l'utilisation de SQL comme backend Bayes.

NOTE : Cette option ne changera pas pour le nom_utilisateur donné, elle tentera seulement d'agir au nom de cet utilisateur. De ce fait, vous aurez besoin des autorisations appropriées pour pouvoir modifier des fichiers appartenant à nom_utilisateur. Dans le cas de SQL, ce n'est généralement pas un problème.

--ipv4only, --ipv4-only, --ipv4
N'utilise pas IPv6 pour les tests DNS. Normalement, SpamAssassin essaiera de détecter si IPv6 est disponible, n'utilisant que IPv4 si ce n'est pas le cas. À utiliser si les tests existants pour la disponibilité d'IPv6 produisent des résultats incorrects ou des plantages.
-L, --local
Effectue uniquement les tests ''locaux'', ceux qui ne nécessitent pas de connexion Internet pour fonctionner. Normalement, SpamAssassin essaiera de détecter si vous êtes connecté au réseau avant d'effectuer ces tests de toute façon, mais pour des vérifications plus rapides, vous pourriez souhaiter utiliser ceci.

Notez que les règles réseau de SpamAssassin sont exécutées en parallèle. Cela peut entraîner une surcharge en termes de descripteurs de fichiers requis si --local n'est pas utilisé ; il est recommandé de relever la limite minimale des descripteurs de fichiers à au moins 256 par sécurité.

-d, --remove-markup
Supprime le balisage SpamAssassin (le rapport "Résultats SpamAssassin", les en-têtes X-Spam-Status, etc.) du message e-mail. Le message résultant, qui sera plus ou moins identique à l'original, avant l'entrée SpamAssassin, sera envoyé sur STDOUT.

(Note : le message ne sera pas exactement identique ; certains en-têtes seront reformatés en raison de certaines fonctionnalités du package Mail::Internet, mais le texte du corps le sera.)

-C chemin, --configpath=chemin, --config-file=chemin
Utilise le chemin spécifié pour localiser les fichiers de configuration distribués. Ignore les répertoires par défaut (généralement "/usr/share/spamassassin" ou similaire).
--siteconfigpath=chemin
Utilise le chemin spécifié pour localiser les fichiers de configuration spécifiques au site. Ignore les répertoires par défaut (généralement "/etc/mail/spamassassin" ou similaire).
--cf='ligne de configuration'
Ajoute des lignes de configuration supplémentaires directement depuis la ligne de commande, analysées après la lecture des fichiers de configuration. Plusieurs arguments --cf peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte. Par exemple : 
spamassassin -t --cf="body NEWRULE /text/" --cf="score NEWRULE 3.0"
--pre='ligne de configuration'
Ajoute des lignes de configuration .pre supplémentaires directement depuis la ligne de commande, analysées avant la lecture des fichiers de configuration. Plusieurs arguments --pre peuvent être utilisés, et chacun sera considéré comme une ligne de configuration distincte. Par exemple : 
spamassassin -t --pre="loadplugin Mail::SpamAssassin::Plugin::Foobar"
-p préférences, --prefspath=préférences, --prefs-file=préférences
Lit les préférences de score utilisateur depuis préférences (généralement "$HOME/.spamassassin/user_prefs").
--progress
Affiche une barre de progression (sur STDERR) montrant la progression actuelle. Cette option ne sera utile que si vous redirigez STDOUT (et non STDERR). Dans le cas où aucun terminal valide n'est trouvé, cette option se comportera de manière très similaire à l'option --showdots dans d'autres programmes SpamAssassin.
-D [zone,...], --debug [zone,...]
Produit une sortie de débogage. Si aucune zone n'est listée, toutes les informations de débogage sont imprimées. La sortie diagnostique peut également être activée pour chaque zone individuellement ; zone est la zone du code à instrumenter. Par exemple, pour produire une sortie diagnostique sur bayes, learn et dns, utilisez : 
spamassassin -D bayes,learn,dns

Utilisez une chaîne vide (-D '') pour indiquer aucune zone lorsque l'élément suivant sur la ligne de commande est un chemin, afin d'éviter que le chemin ne soit analysé comme une zone.

Les messages d'information de priorité plus élevée, adaptés à la journalisation dans des circonstances normales, sont disponibles avec une zone de "info".

Pour plus d'informations sur les zones disponibles (également connues sous le nom de canaux), veuillez consulter la documentation à l'adresse :

L<https://wiki.apache.org/spamassassin/DebugChannels>
-x, --nocreate-prefs
Désactive la création du fichier de préférences utilisateur.
--mbox
Spécifie que le(s) message(s) d'entrée sont au format mbox. mbox est un format standard de dossier de messages Unix.
--mbx
Spécifie que le(s) message(s) d'entrée sont au format UW .mbx. mbx est le format de boîte aux lettres utilisé dans l'implémentation IMAP de l'Université de Washington ; voir "https://fr.wikipedia.org/wiki/UW_IMAP".
