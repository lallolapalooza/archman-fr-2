DESCRIPTION

Les fonctions de la famille printf() produisent une sortie selon un format tel que décrit ci-dessous. Les fonctions printf() et vprintf() écrivent la sortie sur stdout, le flux de sortie standard ; fprintf() et vfprintf() écrivent la sortie sur le flux de sortie donné ; sprintf(), snprintf(), vsprintf(), et vsnprintf() écrivent dans la chaîne de caractères str.

La fonction dprintf() est identique à fprintf() sauf qu'elle écrit sur un descripteur de fichier, fd, au lieu d'un flux stdio(3).

Les fonctions snprintf() et vsnprintf() écrivent au maximum size octets (y compris le caractère nul de fin ('\0')) dans str.

Les fonctions vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() sont équivalentes aux fonctions printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivement, sauf qu'elles sont appelées avec une liste d'arguments variables (va_list) au lieu d'un nombre variable d'arguments. Ces fonctions n'appellent pas la macro va_end. Comme elles invoquent la macro va_arg, la valeur de ap est indéfinie après l'appel. Voir stdarg(3).

Toutes ces fonctions écrivent la sortie sous le contrôle d'une chaîne de format qui spécifie comment les arguments suivants (ou les arguments accédés via les facilités d'arguments de longueur variable de stdarg(3)) sont convertis pour la sortie.

C99 et POSIX.1-2001 spécifient que les résultats sont indéfinis si un appel à sprintf(), snprintf(), vsprintf(), ou vsnprintf() provoque une copie entre des objets qui se chevauchent (par exemple, si le tableau de chaînes de destination et l'un des arguments fournis font référence au même tampon). Voir MISES EN GARDE.

Format de la chaîne de format

La chaîne de format est une chaîne de caractères, commençant et finissant dans son état de décalage initial, le cas échéant. La chaîne de format est composée de zéro ou plusieurs directives : des caractères ordinaires (pas %), qui sont copiés sans modification dans le flux de sortie ; et des spécifications de conversion, chacune d'elles aboutissant à la récupération de zéro ou plusieurs arguments suivants. Chaque spécification de conversion est introduite par le caractère %, et se termine par un spécificateur de conversion. Entre les deux, il peut y avoir (dans cet ordre) zéro ou plusieurs indicateurs, une largeur de champ minimale optionnelle, une précision optionnelle et un modificateur de longueur optionnel.

La syntaxe globale d'une spécification de conversion est :


%[argument$][indicateurs][largeur][.précision][modificateur de longueur]conversion

Les arguments doivent correspondre correctement (après promotion de type) au spécificateur de conversion. Par défaut, les arguments sont utilisés dans l'ordre donné, où chaque '*' (voir Largeur de champ et Précision ci-dessous) et chaque spécificateur de conversion demandent l'argument suivant (et il y a une erreur si suffisamment d'arguments ne sont pas fournis). On peut aussi spécifier explicitement quel argument est pris, à chaque endroit où un argument est requis, en écrivant "%m$" au lieu de '%' et "*m$" au lieu de '*', où l'entier décimal m indique la position dans la liste d'arguments de l'argument désiré, indexé à partir de 1. Ainsi,


printf("%*d", largeur, nombre);

et


printf("%2$*1$d", largeur, nombre);

sont équivalents. Le second style permet des références répétées au même argument. La norme C99 n'inclut pas le style utilisant '$', qui provient de la Single UNIX Specification. Si le style utilisant '$' est utilisé, il doit être utilisé partout pour toutes les conversions prenant un argument et tous les arguments de largeur et de précision, mais il peut être mélangé avec des formats "%%", qui ne consomment pas d'argument. Il ne doit pas y avoir de trous dans les numéros d'arguments spécifiés en utilisant '$' ; par exemple, si les arguments 1 et 3 sont spécifiés, l'argument 2 doit aussi être spécifié quelque part dans la chaîne de format.

Pour certaines conversions numériques, un caractère de séparation décimale ("point décimal") ou un séparateur de milliers est utilisé. Le caractère réel utilisé dépend de la partie LC_NUMERIC de la locale. (Voir setlocale(3).) La locale POSIX utilise '.' comme caractère décimal, et n'a pas de caractère de groupement. Ainsi,


printf("%'.2f", 1234567.89);

résulte en "1234567.89" dans la locale POSIX, en "1234567,89" dans la locale nl_NL, et en "1.234.567,89" dans la locale da_DK.

Caractères indicateurs

Le caractère % est suivi par zéro ou plusieurs des indicateurs suivants :

#
La valeur doit être convertie en une "forme alternative". Pour les conversions o, le premier caractère de la chaîne de sortie devient zéro (en préfixant un 0 si ce n'était pas déjà le cas). Pour les conversions x et X, un résultat non nul aura la chaîne "0x" (ou "0X" pour les conversions X) préfixée. Pour les conversions a, A, e, E, f, F, g, et G, le résultat contiendra toujours un point décimal, même si aucun chiffre ne le suit (normalement, un point décimal apparaît dans les résultats de ces conversions seulement si un chiffre suit). Pour les conversions g et G, les zéros de fin ne sont pas supprimés du résultat comme ils le seraient autrement. Pour m, si errno contient un code d'erreur valide, la sortie de strerrorname_np(errno) est imprimée ; sinon, la valeur stockée dans errno est imprimée sous forme de nombre décimal. Pour d'autres conversions, le comportement est indéfini.
0
La valeur doit être remplie de zéros. Pour les conversions d, i, o, u, x, X, a, A, e, E, f, F, g, et G, la valeur convertie est complétée à gauche par des zéros plutôt que par des espaces. Si les indicateurs 0 et - apparaissent tous les deux, l'indicateur 0 est ignoré. Si une précision est donnée avec une conversion entière (d, i, o, u, x, et X), l'indicateur 0 est ignoré. Pour d'autres conversions, le comportement est indéfini.
-
La valeur convertie doit être alignée à gauche sur la limite de champ. (Le défaut est l'alignement à droite.) La valeur convertie
ue est complété à droite par des espaces, plutôt qu'à gauche par des espaces ou des zéros. Un - annule un 0 s'ils sont tous deux donnés.
' '
(un espace) Un espace doit être laissé avant un nombre positif (ou une chaîne vide) produit par une conversion signée.
+
Un signe (+ ou -) doit toujours être placé avant un nombre produit par une conversion signée. Par défaut, un signe n'est utilisé que pour les nombres négatifs. Un + annule un espace si les deux sont utilisés.

Les cinq caractères de drapeau ci-dessus sont définis dans la norme C99. POSIX spécifie un caractère de drapeau supplémentaire.

'
Pour la conversion décimale (i, d, u, f, F, g, G) la sortie doit être groupée avec des caractères de groupement par milliers comme une quantité non monétaire. Trompeusement, ce n'est pas nécessairement tous les milliers : par exemple Karbi (« mjw_IN »), groupe ses chiffres par 3 une fois, puis par 2 de manière répétée. Comparer locale(7) grouping et thousands_sep, contraster avec mon_grouping/mon_thousands_sep et strfmon(3). Ceci n'a aucun effet dans la locale par défaut « C ».

glibc 2.2 ajoute un caractère de drapeau supplémentaire.

I
Pour la conversion entière décimale (i, d, u), la sortie utilise les chiffres de sortie alternatifs de la locale, le cas échéant. Par exemple, depuis glibc 2.2.3, cela donnera des chiffres arabo-indiens dans la locale persane (« fa_IR »).

Largeur de champ

Une chaîne optionnelle de chiffres décimaux (avec un premier chiffre non nul) spécifiant une largeur de champ minimale. Si la valeur convertie a moins de caractères que la largeur de champ, elle sera complétée à gauche par des espaces (ou à droite, si le drapeau d'ajustement à gauche a été donné). Au lieu d'une chaîne de chiffres décimaux, on peut écrire « * » ou « *m$ » (pour un entier décimal m) pour spécifier que la largeur du champ est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Une largeur de champ négative est traitée comme un drapeau '-' suivi d'une largeur de champ positive. Dans aucun cas une largeur de champ inexistante ou petite ne provoquera la troncature d'un champ ; si le résultat d'une conversion est plus large que la largeur du champ, le champ est étendu pour contenir le résultat de la conversion.

Précision

Une précision optionnelle, sous la forme d'un point ('.') suivi d'une chaîne optionnelle de chiffres décimaux. Au lieu d'une chaîne de chiffres décimaux, on peut écrire « * » ou « *m$ » (pour un entier décimal m) pour spécifier que la précision est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Si la précision est donnée comme juste '.', la précision est prise comme zéro. Une précision négative est traitée comme si la précision était omise. Cela donne le nombre minimum de chiffres à apparaître pour les conversions d, i, o, u, x et X, le nombre de chiffres à apparaître après le caractère de radix pour les conversions a, A, e, E, f et F, le nombre maximum de chiffres significatifs pour les conversions g et G, ou le nombre maximum de caractères à imprimer à partir d'une chaîne pour les conversions s et S.

Modificateur de longueur

Ici, « conversion entière » signifie une conversion d, i, o, u, x, ou X.

hh
Une conversion entière suivante correspond à un argument signed char ou unsigned char, ou une conversion n suivante correspond à un pointeur vers un argument signed char.
h
Une conversion entière suivante correspond à un argument short ou unsigned short, ou une conversion n suivante correspond à un pointeur vers un argument short.
l
(ell) Une conversion entière suivante correspond à un argument long ou unsigned long, ou une conversion n suivante correspond à un pointeur vers un argument long, ou une conversion c suivante correspond à un argument wint_t, ou une conversion s suivante correspond à un pointeur vers un argument wchar_t. Sur une conversion a, A, e, E, f, F, g, ou G suivante, ce modificateur de longueur est ignoré (C99 ; pas dans SUSv2).
ll
(ell-ell). Une conversion entière suivante correspond à un argument long long ou unsigned long long, ou une conversion n suivante correspond à un pointeur vers un argument long long.
q
Un synonyme de ll. Ceci est une extension non standard, dérivée de BSD ; évitez son utilisation dans du nouveau code.
L
Une conversion a, A, e, E, f, F, g, ou G suivante correspond à un argument long double. (C99 autorise %LF, mais pas SUSv2.)
j
Une conversion entière suivante correspond à un argument intmax_t ou uintmax_t, ou une conversion n suivante correspond à un pointeur vers un argument intmax_t.
z
Une conversion entière suivante correspond à un argument size_t ou ssize_t, ou une conversion n suivante correspond à un pointeur vers un argument size_t.
Z
Un synonyme non standard de z qui précède l'apparition de z. N'utilisez pas dans du nouveau code.
t
Une conversion entière suivante correspond à un argument ptrdiff_t, ou une conversion n suivante correspond à un pointeur vers un argument ptrdiff_t.

SUSv3 spécifie tous les éléments ci-dessus, à l'exception des modificateurs explicitement notés comme extensions non standard. SUSv2 ne spécifiait que les modificateurs de longueur h (dans hd, hi, ho, hx, hX, hn) et l (dans ld, li, lo, lx, lX, ln, lc, ls) et L (dans Le, LE, Lf, Lg, LG).

En tant qu'extension non standard, les implémentations GNU traitent ll et L comme des synonymes, de sorte que l'on peut, par exemple, écrire llg (comme synonyme de Lg conforme aux normes) et Ld (comme synonyme de lld conforme aux normes). Une telle utilisation n'est pas portable.

Spécificateurs de conversion

Un caractère qui spécifie le type de conversion à appliquer. Les spécificateurs de conversion et leurs significations sont :

d, i
L'argument int est converti en notation décimale signée. La précision, le cas échéant, donne le nombre minimum de chiffres qui doivent apparaître ; si la valeur convertie nécessite moins de chiffres, elle est complétée à gauche par des zéros. La précision par défaut est 1. Lorsque 0 est imprimé avec une précision explicite de 0, la sortie est vide.
o, u, x, X
L'argument unsigned int est converti en notation octale non signée (o), décimale non signée (u), ou hexadécimale non signée (x et X). Les lettres abcdef sont utilisées pour les conversions x ; les lettres ABCDEF sont utilisées pour les conversions X. La précision, le cas échéant, donne le nombre minimum de chiffres qui doivent apparaître ; si la valeur convertie nécessite moins de chiffres, elle est complétée à gauche par des zéros. La précision par défaut est 1. Lorsque 0 est imprimé avec une précision explicite de 0, la sortie est vide.
e, E
L'argument double est arrondi et converti dans le style [-]d.ddde±dd où il y a un chiffre (qui est non nul si l'argument est non nul) avant le caractère de point décimal et le nombre de chiffres après celui-ci est égal à la précision ; si la précision est manquante, elle est prise comme 6 ; si la précision est zéro, aucun caractère de point décimal n'apparaît. Une conversion E utilise la lettre E (plutôt que e) pour introduire l'exposant. L'exposant contient toujours au moins deux chiffres ; si la valeur est zéro, l'exposant est 00.
f, F
L'argument double est arrondi et converti en notation décimale dans le style [-]ddd.ddd, où le nombre de chiffres après le caractère de point décimal est égal à la spécification de précision. Si la précision est manquante, elle est prise comme 6 ; si la précision est explicitement zéro, aucun caractère de point décimal n'apparaît. Si un point décimal apparaît, au moins un chiffre apparaît avant lui.
(SUSv2 ne connaît pas F et indique que des représentations sous forme de chaînes de caractères pour l'infini et NaN peuvent être disponibles. SUSv3 ajoute une spécification pour F. La norme C99 spécifie « [-]inf » ou « [-]infinity » pour l'infini, et une chaîne commençant par « nan » pour NaN, dans le cas de la conversion f, et « [-]INF » ou « [-]INFINITY » ou « NAN » dans le cas de la conversion F.)
g, G
L'argument double est converti dans le style f ou e (ou F ou E pour les conversions G). La précision spécifie le nombre de chiffres significatifs. Si la précision est manquante, 6 chiffres sont donnés ; si la précision est zéro, elle est traitée comme 1. Le style e est utilisé si l'exposant de sa conversion est inférieur à -4 ou supérieur ou égal à la précision. Les zéros finaux sont supprimés de la partie fractionnaire du résultat ; un point décimal apparaît uniquement s'il est suivi d'au moins un chiffre.

Pour afficher Pi avec cinq décimales :


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Pour afficher une date et une heure sous la forme « dimanche, juillet 3, 10:02 », où weekday et month sont des pointeurs vers des chaînes de caractères :


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

De nombreux pays utilisent l'ordre jour-mois-année. Par conséquent, une version internationalisée doit être capable d'afficher les arguments dans un ordre spécifié par le format :


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

où format dépend de la locale, et peut permuter les arguments. Avec la valeur :


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

on pourrait obtenir « Sonntag, 3. Juli, 10:02 ».

Pour allouer une chaîne de caractères suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1) :

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Déterminer la taille requise.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un octet supplémentaire pour '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si une troncature se produit dans les versions de glibc antérieures à glibc 2.0.6, cela est traité comme une erreur au lieu d'être géré correctement.
