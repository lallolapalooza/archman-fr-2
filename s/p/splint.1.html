SPLINT(1) Release 3.1.2a SPLINT(1)

NOM

splint - Un outil pour vérifier statiquement les programmes C

SYNTAXE

splint [options]

DESCRIPTION

splint est un outil pour vérifier statiquement les programmes C pour des vulnérabilités de sécurité et des erreurs de programmation courantes. Avec un minimum d'effort, splint peut être utilisé comme un meilleur lint(1). Si un effort supplémentaire est investi dans l'ajout d'annotations aux programmes, splint peut effectuer des vérifications plus robustes que ce qui peut être fait par un lint standard. Pour une documentation complète, veuillez consulter http://www.splint.org. Cette page de manuel ne couvre que quelques-unes des options disponibles.

OPTIONS

-help
Affiche l'aide.

Initialisation

Ces indicateurs contrôlent les répertoires et les fichiers utilisés par splint. Ils peuvent être utilisés depuis la ligne de commande ou dans un fichier d'options, mais ne peuvent pas être utilisés comme commentaires de contrôle dans le code source. Sauf indication contraire, ils ont la même signification précédés de - ou +.

-tmpdir répertoire
Définit le répertoire pour l'écriture des fichiers temporaires. Le défaut est /tmp/.
-I répertoire
Ajoute le répertoire au chemin de recherche des fichiers d'inclusion C. Notez qu'il n'y a pas d'espace après le I, pour être cohérent avec les indicateurs du préprocesseur C.
-S répertoire
Ajoute le répertoire au chemin de recherche des fichiers de spécification .lcl.
-f fichier
Charge le fichier d'options <fichier>. Si cet indicateur est utilisé depuis la ligne de commande, le fichier par défaut ~/.splintrc n'est pas chargé. Cet indicateur peut être utilisé dans un fichier d'options pour charger un autre fichier d'options.
-nof
Empêche le chargement des fichiers d'options par défaut (./.splintrc et ~/.splintrc). (Définir -nof écrase +nof, provoquant le chargement normal des fichiers d'options.)
-system-dirs répertoires
Définit les répertoires pour les fichiers système (par défaut est "/usr/include"). Séparez les répertoires par des deux-points (par exemple, "/usr/include:/usr/local/lib"). Les paramètres des indicateurs se propagent aux fichiers dans un répertoire système. Si -system-dir-errors est défini, aucune erreur n'est signalée pour les fichiers dans les répertoires système.

Préprocesseur

Ces indicateurs sont utilisés pour définir ou annuler des constantes du préprocesseur. L'indicateur -I<répertoire> est également transmis au préprocesseur C.

-D initialiseur
Transmis au préprocesseur C.
-U initialiseur
Transmis au préprocesseur C.

Bibliothèques Ces indicateurs contrôlent la création et l'utilisation des bibliothèques.

-dump fichier
Sauvegarde l'état dans <fichier> pour le chargement. L'extension par défaut .lcd est ajoutée si <fichier> n'a pas d'extension.
-load fichier
Charge l'état depuis <fichier> (créé par -dump). L'extension par défaut .lcd est ajoutée si <fichier> n'a pas d'extension. Un seul fichier de bibliothèque peut être chargé.

Par défaut, la bibliothèque standard est chargée si l'indicateur -load n'est pas utilisé pour charger une bibliothèque utilisateur. Si aucune bibliothèque utilisateur n'est chargée, l'un des indicateurs suivants peut être utilisé pour sélectionner une autre bibliothèque standard. Précédez l'indicateur de + pour charger la bibliothèque décrite (ou empêcher le chargement d'une bibliothèque en utilisant nolib). Voir l'Annexe F pour plus d'informations sur les bibliothèques fournies.

-nolib
Ne charge aucune bibliothèque. Cela empêche le chargement de la bibliothèque standard.
-standard-lib
Utilise la bibliothèque standard (ISO C99) (sélectionnée par défaut).
-standard-strict-lib
Utilise la version stricte de la bibliothèque standard (ISO C99).
-posix-lib
Utilise la bibliothèque standard POSIX.
-posix-strict-lib
Utilise la version stricte de la bibliothèque standard POSIX.
-unix-lib
Utilise la version UNIX de la bibliothèque standard.
-unix-strict-lib
Utilise la version stricte de la bibliothèque standard UNIX.

Sortie

Ces indicateurs contrôlent quelles informations supplémentaires sont imprimées par splint. Définir +<indicateur> provoque l'impression des informations décrites ; définir -<indicateur> l'empêche. Par défaut, tous ces indicateurs sont désactivés.

-use-stderr
Envoie les messages d'erreur à la sortie d'erreur standard (au lieu de la sortie standard).
-show-summary
Affiche un résumé de toutes les erreurs signalées et supprimées. Les comptes d'erreurs supprimées ne sont pas nécessairement corrects car la désactivation d'un indicateur peut empêcher certaines vérifications d'être effectuées pour économiser du calcul, et les erreurs qui ne sont pas signalées peuvent se propager différemment que lorsqu'elles sont signalées.
-show-scan
Affiche les noms de fichiers au fur et à mesure de leur traitement.
-show-alluses
Affiche la liste des utilisations de tous les identifiants externes triés par nombre d'utilisations.
-stats
Affiche le nombre de lignes traitées et le temps de vérification.
-time-dist
Affiche la distribution de l'endroit où le temps de vérification est passé.
-quiet
Supprime l'en-tête et le nombre d'erreurs. (Si quiet n'est pas défini, splint affiche un en-tête avec des informations de version avant le début de la vérification, et une ligne résumant le nombre total d'erreurs signalées.)
-which-lib
Affiche le nom du fichier de la bibliothèque standard et les informations de création.
-limit nombre
Au maximum <nombre> d'erreurs similaires sont signalées consécutivement. Les erreurs supplémentaires sont supprimées, et un message indiquant le nombre de messages supprimés est imprimé.

Erreurs attendues

Normalement, splint s'attendra à ne signaler aucune erreur. Le code de sortie sera succès (0) si aucune erreur n'est signalée, et échec si des erreurs sont signalées. Des indicateurs peuvent être utilisés pour définir le nombre attendu d'erreurs signalées. En raison des mécanismes de suppression d'erreurs fournis, ces options ne devraient probablement pas être utilisées pour la vérification finale de programmes réels, mais peuvent être utiles dans le développement de programmes utilisant make.

-expect nombre
Exactement <nombre> erreurs de code sont attendues. splint se terminera avec un code de sortie d'échec sauf si <nombre> erreurs de code sont détectées.
-Message Format
Ces indicateurs contrôlent la façon dont les messages sont imprimés. Ils peuvent être définis en ligne de commande, dans des fichiers d'options, ou localement dans des commentaires syntaxiques. Les indicateurs linelen et limit peuvent être précédés de + ou - avec la même signification ; pour les autres indicateurs, + active l'impression décrite et - la désactive. La boîte à gauche de chaque indicateur donne sa valeur par défaut.
-show-column
Affiche le numéro de colonne où l'erreur est trouvée. Défaut : +
-show-func
Affiche le nom de la fonction (ou macro) définition contenant l'erreur. Le nom de la fonction est imprimé une fois avant le premier message détecté dans cette fonction. Défaut : +
-show-all-conjs
Affiche toutes les alternatives de type possibles (voir Section 8.2.2). Défaut : -
-paren-file-format
Utilise le format fichier(ligne) dans les messages.
-hi

NAME

splint

a tool for running static checks on C programs

SYNOPSIS

splint [ -checks | -standard | -strict | -weak ] [ -help ] [ -I dir ] [ -L dir ] [ -quiet ] [ -skip-all-errors ] [ -syntax-only ] [ -verbatim-errors ] [ -show-source ] [ -show-context ] [ -dump-file file ] [ -input-file file ] [ -output-file file ] [ -brief ] [ -quiet ] [ -no-lines ] [ -show-reachability ] [ -stats ] [ -trace file ] [ -unreachable-code ] [ -fall-through ] [ -ignore-case ] [ -local-paths ] [ -precond-recursion ] [ -print-lines ] [ -no-recursive-includes ] [ -no-static-checking ] [ -no-redefinitions ] [ -no-unused-variables ] [ -no-shadow-variables ] [ -no-modify-return-value ] [ -no-global-alias ] [ -no-ignored-return ] [ -no-all-parameters-used ] [ -no-storage-checked ] [ -no-malloc-checked ] [ -no-interface-checking ] [ -no-unused-includes ] [ -no-type-checking ] [ -no-constant-dropping ] [ -no-suspicious-constructs ] [ -no-modifies-parameter ] [ -no-modifies-global ] [ -no-rep-expose ] [ -no-return-alias ] [ -no-strict-newlines ] [ -no-ptr-comparison ] [ -no-reachable-code ] [ -no-fall-through ] [ -no-skip-return ] [ -warn-error ] [ -warning-as-error ] [ -show-all-warnings ] [ -show-suppressed ] [ -show-duplicates ] [ -hints ] [ -force-hints ] [ -linelen number ] file ...

DESCRIPTION

Splint is a tool that dramatically improves the practice of software development by finding errors in C programs. It is a static analysis tool that works by performing a number of checks on source code. These checks are designed to find bugs, improve portability, increase robustness, and improve maintainability. Splint can also be used to help enforce coding standards and to document code. It also supports an annotation language that can be used to specify program properties and to detect violations of these properties.

Splint analyzes C source code, looking for violations of a set of built-in checks and any checks specified via annotations. It reports violations as warnings and errors.

Splint can be used as a drop-in replacement for the traditional lint utility. Splint provides many improvements over lint, including a more powerful alias analysis algorithm, support for annotations, and many more checks.

Splint is extensible. Users can define their own checks and add them to the set of checks that splint performs.

OPTIONS

Splint supports many options. These can be divided into three groups: control flags, mode selector flags, and file names.

Options may be preceded by either - or +. If an option is preceded by +, the check is enabled. If an option is preceded by -, the check is disabled. For example, +modifies enables modifies checking, and -modifies disables it.

Options can be given on the command line, in a file specified with the -input-file option, or in special comments in the source code.

Control Flags

-help
Print a summary of options and exit.
-Idir
Add dir to the list of directories that Splint searches for included header files. This option may be repeated.
-Ldir
Add dir to the list of directories that Splint searches for library files. This option may be repeated.
-quiet
Suppress the printing of all messages.
-skip-all-errors
Do not report any errors. This option is intended for use when running splint from within another program.
-syntax-only
Perform only syntax checking. No semantic checks are performed.
-verbatim-errors
Print error messages in a verbatim format. This means that error messages are not reformatted and are printed exactly as they are generated.
-show-source
Show the source code line where the error occurred.
-show-context
Show the source code line where the error occurred, along with surrounding context.
-dump-filefile
Write internal analysis information to file. This option is intended for use by splint developers.
-input-filefile
Read options from file. This option may be repeated.
-output-filefile
Write messages to file instead of standard output.
-brief
Print only the error message and the file name and line number. This option is intended for use when running splint from within another program.
-no-lines
Do not print line numbers in error messages. This option is intended for use when running splint from within another program.
-show-reachability
Show information about code reachability. This option is intended for use by splint developers.
-stats
Print statistics about the analysis. This option is intended for use by splint developers.
-tracefile
Write trace information to file. This option is intended for use by splint developers.
-unreachable-code
Report unreachable code.
-fall-through
Report fall-through cases in switch statements.
-ignore-case
Ignore case when comparing identifiers. This option is intended for use with legacy codebases that do not follow case conventions.
-local-paths
Do not report errors related to library paths. This option is intended for use when analyzing code that uses non-standard library paths.
-precond-recursion
Allow recursion in preconditions. This option is intended for use when analyzing code that uses recursive preconditions.
-print-lines
Print line numbers in error messages. This is the default behavior.
-no-recursive-includes
Do not follow recursive includes. This option is intended for use when analyzing code that has complex include hierarchies.
-no-static-checking
Disable static checking. This option is intended for use when running splint for only syntax checking.
-no-redefinitions
Do not report redefinitions of functions or variables. This option is intended for use when analyzing code that uses redefinitions.
-no-unused-variables
Do not report unused variables. This option is intended for use when analyzing code that intentionally leaves variables unused.
-no-shadow-variables
Do not report shadowed variables. This option is intended for use when analyzing code that intentionally shadows variables.
-no-modify-return-value
Do not report modification of return values. This option is intended for use when analyzing code that intentionally modifies return values.
-no-global-alias
Do not report global aliases. This option is intended for use when analyzing code that uses global aliases.
-no-ignored-return
Do not report ignored return values. This option is intended for use when analyzing code that intentionally ignores return values.
-no-all-parameters-used
Do not report unused parameters. This option is intended for use when analyzing code that intentionally leaves parameters unused.
-no-storage-checked
Do not check storage usage. This option is intended for use when analyzing code that does not require storage checking.
-no-malloc-checked
Do not check malloc usage. This option is intended for use when analyzing code that does not require malloc checking.
-no-interface-checking
Do not perform interface checking. This option is intended for use when analyzing code that does not require interface checking.
-no-unused-includes
Do not report unused includes. This option is intended for use when analyzing code that intentionally includes unused headers.
-no-type-checking
Do not perform type checking. This option is intended for use when analyzing code that does not require type checking.
-no-constant-dropping
Do not report constant dropping. This option is intended for use when analyzing code that intentionally drops constants.
-no-suspicious-constructs
Do not report suspicious constructs. This option is intended for use when analyzing code that contains suspicious constructs.
-no-modifies-parameter
Do not report modification of parameters. This option is intended for use when analyzing code that intentionally modifies parameters.
-no-modifies-global
Do not report modification of global variables. This option is intended for use when analyzing code that intentionally modifies global variables.
-no-rep-expose
Do not report representative exposure. This option is intended for use when analyzing code that does not require representative exposure checking.
-no-return-alias
Do not report return aliases. This option is intended for use when analyzing code that does not require return alias checking.
-no-strict-newlines
Do not enforce strict newline conventions. This option is intended for use when analyzing code that does not follow strict newline conventions.
-no-ptr-comparison
Do not report pointer comparisons. This option is intended for use when analyzing code that contains pointer comparisons.
-no-reachable-code
Do not report unreachable code. This option is intended for use when analyzing code that intentionally contains unreachable code.
-no-fall-through
Do not report fall-through cases in switch statements. This option is intended for use when analyzing code that intentionally uses fall-through cases.
-no-skip-return
Do not skip return statements. This option is intended for use when analyzing code that requires all return statements to be checked.
-warn-error
Treat all warnings as errors. This option is intended for use when you want to enforce a strict coding standard.
-warning-as-error
Treat all warnings as errors. This option is the same as -warn-error.
-show-all-warnings
Show all warnings, including those that are normally suppressed. This option is intended for use when debugging splint or when you want to see all potential issues.
-show-suppressed
Show suppressed warnings. This option is intended for use when debugging splint or when you want to see warnings that have been suppressed.
-show-duplicates
Show duplicate warnings. This option is intended for use when debugging splint or when you want to see all instances of a warning.
-hints
Provide hints describing an error and how a message may be suppressed for the first error reported in each error class. Default: +
-force-hints
Provide hints for all errors reported, even if the hint has already been displayed for the same error class. Default: -
-linelen number
Set length of maximum message line to <number> characters. splint will split messages longer than <number> characters long into multiple lines. Default: 80

Mode Selector Flags

Mode selects flags set the mode checking flags to predefined values. They provide a quick coarse-grain way of controlling what classes of errors are reported. Specific checking flags may be set after a mode flag to override the mode settings. Mode flags may be used locally, however the mode settings will override specific command line flag settings. A warning is produced if a mode flag is used after a mode checking flag has been set.

These are brief descriptions to give a general idea of what each mode does. To see the complete flag settings in each mode, use splint -help modes. A mode flag has the same effect when used with either + or -.

-weak
Weak checking, intended for typical unannotated C code. No modifies checking, macro checking, rep exposure, or clean interface checking is done. Return values of type int may be ignored. The types bool, int, char and user-defined enum types are all equivalent. Old style declarations are unreported.
-standard
The default mode. All checking done by weak, plus modifies checking, global alias checking, use all parameters, using released storage, ignored return values or any type, macro checking, unreachable code, infinite loops, and fall-through cases. The types bool, int and char are distinct. Old style declarations are reported.
-checks
Moderately strict checking. All checking done by standard, plus must modification checking, rep exposure, return alias, memory management and complete interfaces.
-strict
Absurdly strict checking. All checking done by checks, plus modifications and global variables used in unspecified functions, strict standard library, and strict typing of C operators. A special reward will be presented to the first person to produce a real program that produces no errors with strict checking.
