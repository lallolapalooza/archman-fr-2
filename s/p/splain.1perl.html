SPLAIN(1perl) Guide de référence pour programmeurs Perl SPLAIN(1perl)

NOM

diagnostics, splain - produire des diagnostics d'avertissement verbeux

SYNTAXE

Utilisation du pragma "diagnostics":

use diagnostics;
use diagnostics -verbose;
diagnostics->enable;
diagnostics->disable;

Utilisation du programme de filtrage autonome "splain":

perl programme 2>diag.out
splain [-v] [-p] diag.out

Utilisation de diagnostics pour obtenir des traces de pile d'un script défaillant:

perl -Mdiagnostics=-traceonly mon_script.pl

DESCRIPTION

Le pragma "diagnostics"

Ce module étend les diagnostics concis normalement émis par le compilateur Perl et l'interpréteur Perl (lors de l'exécution de perl avec un commutateur -w ou "use warnings"), en les enrichissant avec les descriptions plus explicatives et appréciées trouvées dans perldiag. Comme les autres pragmas, il affecte la phase de compilation de votre programme plutôt que simplement la phase d'exécution.

Pour l'utiliser dans votre programme comme pragma, invoquez simplement

use diagnostics;

au début (ou près du début) de votre programme. (Notez que cela active le drapeau -w de Perl.) Toute votre compilation sera alors soumise aux diagnostics améliorés. Ceux-ci sortent toujours sur STDERR.

En raison de l'interaction entre les problèmes d'exécution et de compilation, et parce que ce n'est probablement pas une très bonne idée de toute façon, vous ne pouvez pas utiliser "no diagnostics" pour les désactiver à la compilation. Cependant, vous pouvez contrôler leur comportement à l'exécution en utilisant les méthodes disable() et enable() pour les désactiver et les activer respectivement.

Le drapeau -verbose imprime d'abord l'introduction de perldiag avant tout autre diagnostic. La variable $diagnostics::PRETTY peut générer des séquences d'échappement plus jolies pour les pagers.

Les avertissements envoyés par Perl lui-même (ou plus précisément, ceux qui correspondent aux descriptions trouvées dans perldiag) ne sont affichés qu'une seule fois (pas de descriptions dupliquées). Les avertissements générés par le code utilisateur à la manière de warn() ne sont pas affectés, ce qui permet l'affichage de messages utilisateur dupliqués.

Ce module ajoute également une trace de pile au message d'erreur lorsque Perl meurt. Ceci est utile pour identifier la cause de la mort. Le drapeau -traceonly (ou simplement -t) désactive les explications des messages d'avertissement, ne laissant que les traces de pile. Donc, si votre script meurt, relancez-le avec

perl -Mdiagnostics=-traceonly mon_mauvais_script

pour voir la pile d'appels au moment de la mort. En fournissant le drapeau -warntrace (ou simplement -w), tout avertissement émis viendra également avec une trace de pile.

Le programme splain

Un autre programme, splain, n'est en réalité rien de plus qu'un lien vers le module (exécutable) diagnostics.pm, ainsi qu'un lien vers la documentation diagnostics.pod. Le drapeau -v est comme la directive "use diagnostics -verbose". Le drapeau -p est comme la variable $diagnostics::PRETTY. Comme vous post-traitez avec splain, il n'y a aucun intérêt à pouvoir enable() ou disable() le traitement.

La sortie de splain est dirigée vers STDOUT, contrairement au pragma.

EXEMPLES

Le fichier suivant déclenchera certainement quelques erreurs à la fois à l'exécution et à la compilation:

use diagnostics;
print NOWHERE "rien\n";
print STDERR "\n\tCe message doit être sans fioritures.\n";
warn "\tCeci est un avertissement utilisateur";
print "\nTESTEUR DE DIAGNOSTICS : Veuillez appuyer sur <CR> ici : ";
my $a, $b = scalar <STDIN>;
print "\n";
print $x/$y;

Si vous préférez exécuter votre programme d'abord et examiner ses problèmes ensuite, faites ceci:

perl -w test.pl 2>test.out
./splain < test.out

Notez que ce n'est pas possible en général dans les shells d'héritage plus douteux, car le théorique

(perl -w test.pl >/dev/tty) >& test.out
./splain < test.out

Car vous avez déplacé le stdout existant ailleurs.

Si vous ne voulez pas modifier votre code source, mais avoir toujours des avertissements à la volée, faites ceci:

exec 3>&1; perl -w test.pl 2>&1 1>&3 3>&- | splain 1>&2 3>&-

Mignon, hein?

Si vous voulez contrôler les avertissements à la volée, faites quelque chose comme ceci. Assurez-vous de faire le "use" d'abord, sinon vous ne pourrez pas accéder aux méthodes enable() ou disable().

use diagnostics; # vérifie toute la phase de compilation 
    print "\ntemps pour les 1ers diagnostics bidons : CRIEEES\n";
    print BOGUS1 'nada';
    print "fini avec le 1er bidon\n";
diagnostics->disable; # désactive uniquement les avertissements d'exécution
    print "\ntemps pour le 2ème bidon : (muet)\n";
    print BOGUS2 'nada';
    print "fini avec le 2ème bidon\n";
diagnostics->enable; # réactive les avertissements d'exécution
    print "\ntemps pour le 3ème bidon : CRIEEES\n";
    print BOGUS3 'nada';
    print "fini avec le 3ème bidon\n";
diagnostics->disable;
    print "\ntemps pour le 4ème bidon : (muet)\n";
    print BOGUS4 'nada';
    print "fini avec le 4ème bidon\n";

INTERNES

Les messages de diagnostic proviennent du fichier perldiag.pod lorsqu'il est disponible à l'exécution. Sinon, ils peuvent être intégrés dans le fichier lui-même lorsque le paquet splain est construit. Voir le Makefile pour les détails.

Si un gestionnaire $SIG{__WARN__} existant est détecté, il continuera à être honoré, mais seulement après que la fonction diagnostics::splainthis() (l'intercepteur $SIG{__WARN__} du module) ait eu son mot à dire sur vos avertissements.

Il existe une variable $diagnostics::DEBUG que vous pouvez définir si vous êtes désespérément curieux de savoir quelles sortes de choses sont interceptées.

BEGIN { $diagnostics::DEBUG = 1 }

BOGUES

Ne pas pouvoir dire "no diagnostics" est ennuyeux, mais peut-être pas insurmontable.

La directive "-pretty" est appelée trop tard pour affecter les choses. Vous devez faire ceci à la place, et ce, avant de charger le module.

BEGIN { $diagnostics::PRETTY = 1 }

Je pourrais démarrer plus rapidement en retardant la compilation jusqu'à ce qu'elle soit nécessaire, mais cela provoque une erreur "panic: top_level" lors de l'utilisation de la forme pragma dans Perl 5.001e.

Bien qu'il soit vrai que cette documentation est quelque peu sérieuse, si vous utilisez un programme nommé splain, vous devriez vous attendre à un peu d'espièglerie.

SPLAIN - explication des erreurs et des avertissements Perl

Nom

splain - explication des erreurs et des avertissements Perl

Description

splain est un programme utilitaire qui vous permet de générer des explications des messages d'erreur et d'avertissement courants que Perl affiche.

Il peut également être utilisé comme un module Perl pour générer des explications dans vos propres programmes.

Utilisation

splain [option] [message_erreur | numéro_erreur]

Si aucun argument n'est fourni, splain tentera de lire les erreurs à partir de l'entrée standard.

Exemples

# Expliquer une erreur Perl courante
$ splain "Use of uninitialized value in addition"
Use of uninitialized value in addition at ...
    (W doit être défini avant d'être utilisé.)

# Expliquer une erreur Perl par son numéro
$ splain 127
127 - "Subroutine %s redefined"
    (S La sous-routine %s a déjà été définie.)

# Lire les erreurs de l'entrée standard
$ perl -w my_script.pl 2>&1 | splain

Options

-h
Afficher l'aide et quitter.
-v
Afficher la version et quitter.

Voir aussi

perl(1), perldiag(1)
