NOM

spumux - génère et multiplexe des sous-titres dans un flux de programme mpeg2 existant

SYNTAXE

spumux [ -m dvd | -m cvd | -m svcd ] [ -s flux ] [ -v niveau ] [ -P ] [ --nomux ] [ --nodvdauthor-data ] fichier < mpeg > mpeg-avec-sous-titres

DESCRIPTION

spumux encode les sous-titres et les multiplexe dans le flux de programme mpeg2.

-m mode
Définit l'encodage des sous-titres. Peut être dvd, cvd, ou svcd. Par défaut, c'est dvd.
-s flux
Définit l'ID du flux de sous-titres. Par défaut, c'est 0.
-v niveau
Définit le niveau de verbosité.
-P
Active une barre de progression.
--nomux
Désactive la lecture d'un flux MPEG depuis l'entrée standard. À la place, la sortie ne contiendra que le flux de sous-images.
--nodvdauthor-data
Désactive le passage des informations de couleur et de bouton à dvdauthor.

Voici un exemple de fichier de configuration :

<subpictures>
   <stream>
      <spu start="heure-debut" [ end="heure-fin" ] [ image="image.png" ]
           [ highlight="image.png" ] [ select="image.png" ]
           [ transparent="spec-couleur" ] [ force="yes" ]
           [ autooutline="infer" [ outlinewidth="largeur" ]
             [ autoorder="rows" | autoorder="columns" ] ]
           [ xoffset="coord-x" yoffset="coord-y" ] >
         <button [ name="nom" ] [ x0="x0" ] [ y0="y0" ] [ x1="x1" ]
                 [ y1="y1" ] [ up="nom" ] [ down="nom" ]
                 [ left="nom" ] [ right="nom" ] />
         <action [ name="nom" ] [ x0="x0" ] [ y0="y0" ] [ x1="x1" ]
                 [ y1="y1" ] />
      </spu>
   </stream>
</subpictures>

Chaque image de sous-titre est décrite par une balise <spu>. Les attributs start et end optionnel décrivent quand le sous-titre sera affiché à l'écran, au format "HH:MM:SS.CS". L'attribut image décrit l'image principale du sous-titre, qui peut être un fichier PNG ou BMP. Si votre image n'est pas une image plein écran, vous pouvez utiliser xoffset et yoffset pour déplacer l'image. Au cas où l'auteur ne pourrait pas utiliser un format graphique avec un canal alpha, l'attribut transparent peut être utilisé pour décrire quelle couleur deviendra complètement transparente. Pour les formats valides de spec-couleur, voir SPÉCIFICATION DES COULEURS ci-dessous. Si vous voulez forcer l'affichage du sous-titre, que l'utilisateur ait activé ou non les sous-titres, vous pouvez utiliser la balise force. Lorsque vous créez des menus, la balise force est obligatoire.

Les attributs et balises restants sont liés à la création de menus. L'attribut highlight montre à quoi ressemblent tous les boutons lorsqu'ils sont mis en surbrillance (c'est-à-dire lorsque vous utilisez les flèches dans le menu), et l'attribut select montre à quoi ressemblent tous les boutons lorsqu'ils sont sélectionnés (c'est-à-dire pendant 1-2 secondes après avoir appuyé sur entrée dans le menu). Si l'un de ceux-ci (ou l'attribut image) est omis, alors spumux crée une image vierge (totalement transparente). Évidemment, au moins une balise doit être spécifiée.

Pour aider à la création de boutons, l'attribut autooutline demande à spumux d'inférer l'emplacement des boutons. Il le fait en essayant de tracer des rectangles autour d'une composition des images highlight et select qui n'intersectent aucun pixel opaque ou semi-opaque. Afin de supporter les boutons textuels, l'attribut outlinewidth permet de spécifier la largeur du rectangle testé. Des rectangles plus larges ne pourront pas se glisser entre les lettres. Enfin, autoorder décrit la manière d'ordonner les boutons détectés automatiquement, ce qui est important pour les boutons sélectionnés numériquement et pour mapper les boutons à des noms de boutons ou à des noms implicites.

Les balises button et action décrivent les boutons (objets visuellement sélectionnables à l'écran) et les actions (commandes exécutées dès que la touche associée est pressée sur la télécommande). Si vous utilisez la fonction autooutline, que vous concevez uniquement des boutons, que vous êtes satisfait de la navigation des boutons inférée, et que vous pouvez gérer le système de nommage simpliste, alors vous n'avez même pas besoin de spécifier de boutons ou d'actions. Sinon, lisez la suite.

L'attribut name est utilisé pour donner un nom facile à référencer à un bouton ou une action. Par défaut, ils sont numérotés séquentiellement en commençant par "1". Les noms up, down, left, et right décrivent quel bouton ou action doit être lié à la touche correspondante lorsque le bouton actuel est mis en surbrillance, bien que s'ils sont omis, spumux utilisera un algorithme raisonnablement intelligent pour déterminer les boutons vers lesquels se déplacer.

Les coordonnées (x0,y0) décrivent le coin supérieur gauche inclusivement, tandis que les coordonnées (x1,y1) décrivent le coin inférieur droit EXCLUSIVEMENT. Les coordonnées commencent à 0,0 pour le coin supérieur gauche. Idéalement, les coordonnées y0 et y1 devraient être toutes deux paires, de sorte que les bords du bouton englobent entièrement deux lignes de balayage entrelacées, même s'il n'y a pas de données dans la ligne de balayage supplémentaire. Certains lecteurs DVD rempliront la ligne de balayage supplémentaire si elle n'est pas spécifiée; spumux fait un effort pour s'assurer que cela sera transparent, mais il n'y a aucune garantie.

GESTION DES SOUS-TITRES TEXTUELS

Spumux est également capable de gérer les sous-titres textuels, qui seront rendus graphiquement par spumux. De nombreux formats textuels différents (doivent être non graphiques) sont supportés (.sub, .srt, .ssa, .smi, .rt , .txt, .aqt, .jss, .js, ass). Spumux essaiera de déterminer le format automatiquement.

Si vous traitez des sous-titres textuels, aucun autre flux ne peut être défini, les boutons ou autres doivent être traités dans une passe supplémentaire avec spumux, en utilisant un autre fichier xml.

Le fichier .xml suivant montre les balises disponibles et leurs paramètres par défaut. Seule la balise textsub est obligatoire, les valeurs par défaut sont utilisées si la balise spécifique n'est pas spécifiée.

<subpictures [format="NTSC|PAL"]>
   <stream>
      <textsub filename="demo1.srt" characterset="UTF-8"
         fontsize="28.0" font="arial" fill-color="spec-couleur"
         outline-color="spec-couleur" outline-thickness="3.0"
         shadow-offset="0, 0" shadow-color="spec-couleur"
         horizontal-alignment="left"  vertical-alignment="bottom"
         left-margin="60" right-margin="60"
         top-margin="20" bottom-margin="30" subtitle-fps="fps"
         movie-fps="fps"
         movie-width="720" movie-height="hauteur" aspect="4:3"
         force="yes"
      />
   </stream>
</subpictures>

La balise textsub définit les paramètres du rendu du texte en graphiques.

L'attribut filename définit le chemin et le nom du fichier de sous-titres textuels d'entrée, c'est le seul attribut obligatoire.

L'attribut characterset définit le jeu de caractères à utiliser, les jeux de caractères disponibles peuvent être trouvés sur http://www.gnu.org/software/libiconv.

L'attribut fontsize définit la taille de la police en unités de police. L'attribut font définit la police utilisée. Spumux fera correspondre le nom de la police en utilisant Fontconfig si disponible, sinon il l'utilisera comme un nom de fichier sur les systèmes Linux et recherchera dans les répertoires windows/fonts et le sous-répertoire spumux du répertoire personnel cygwin/mingw et dans le répertoire d'exécution pour l'exécution sous Windows pour la police spécifiée. Vous cherchez des polices gratuites ? Une liste se trouve ici http://www.microsoft.com/typography/links/links.asp?type=free&part=1 (il ne s'agit que des polices, pas des systèmes d'exploitation).

L'attribut fill-color spécifie la couleur à utiliser pour remplir l'intérieur du texte, tandis que outline-color spécifie la couleur de la bordure du contour à dessiner autour de chaque caractère, pour le faire ressortir.

NAME

spumux - Muxes subtitle streams into a DVD-compliant MPEG-PS

SYNOPSIS

spumux [ options ] --output output.mpg --input input.mpl input.mpg [ input.mpl input.mpg ...]

DESCRIPTION

This manual page documents the spumux command.

spumux is used to take the output of svq(1) or spuconv(1) or similar programs that generate the DVDsubtitle specification, and multiplex them into an MPEG-PS.

The following command line options are supported:

•
--output output.mpg
•
--input input.mpl input.mpg

The first argument is the output MPEG-PS file. This is followed by one or more pairs of input files, the first of which is the subtitle specification file (typically ending in .mpl), and the second is the MPEG-PS file containing the video and audio streams.

The subtitle specification file format is described in the spumux.spec man page. The following global attributes can be set on the command line:

•
--font font
•
--font-style font-style
•
--font-size font-size
•
--font-color color-spec
•
--font-encoding encoding
•
--background-color color-spec
•
--outline-thickness thickness
•
--shadow-offset horizontal offset vertical
•
--shadow-color color-spec
•
--horizontal-alignment alignment
•
--vertical-alignment alignment
•
--margin top right bottom left
•
--subtitle-fps fps
•
--movie-fps fps
•
--movie-width width
•
--movie-height height
•
--aspect aspect ratio
•
--force

HANDLING TEXT-BASED SUBTITLES

The font, font-style, font-size, font-color, and font-encoding attributes specify the font to be used for rendering the text. The actual font file is determined by the fontconfig library. font-style can be empty, or contain any of "bold", "italic", "underline", "strikethrough".

The background-color attribute specifies the color of the background rectangle behind the text. The outline-thickness attribute specifies the thickness of this outline. For the valid formats for color-spec, see SPECIFYING COLORS below. The default fill color is white and the default outline color is black.

The shadow-offset and shadow-color attributes specify a shadow effect to be applied to the text. The shadow-offset is specified as 2 signed integers, being the horizontal and vertical offset respectively, with positive values being to the right and down. For the valid formats for color-spec, see SPECIFYING COLORS below. The default shadow color is black.

The horizontal-alignment attribute defines the horizontal alignment of the subtitles. Options are: "left", "right", "center" and "default". The "default" value causes spumux to use the attribute that is in the text subtitle file if the format supports such an attribute.

The vertical-alignment attribute defines the vertical alignment. Options are: "top", "center" and "bottom".

The margin attributes define the minimum blank pixel space between the border of the image and the border of the subtitle lines.

The subtitle-fps is needed for subtitle formats which use frame numbers rather than fractional seconds for specifying subtitle times, while the movie-fps is the frame rate of the movie onto which the subtitles are being multiplexed; if omitted, both of these default to 29.97 for NTSC and 25 for PAL.

Having separate subtitle-fps and movie-fps attributes make it possible for spumux to recalculate the subtitle timing if these are not the same.

The movie-width and movie-height attributes define the maximum size of the subtitle page, these shouldn't be larger than the size of the video frame (720x480 for NTSC, 720x576 for PAL), normally they are the same. Some DVD players prefer subtitle frames that are 2 or 4 pixels smaller in height. If omitted, the default movie width is 720 and the height is 2 pixels less than the video frame height.

The aspect attribute lets you specify whether the video aspect ratio is 16:9 (widescreen) or 4:3. This, together with the video format, is used to adjust the rendering of the text to ensure it appears undistorted.

The force option allows you to force the display of the subtitle, regardless of whether the user has enabled subtitles or not.

SPECIFYING COLORS

Colors for image transparency and text fill and outlines can be specified in a number of ways:

•
As a color name, e.g. "green". You can use most of the color names listed at http://www.imagemagick.org/script/color.php.
•
As a hexadecimal string preceded by a "#", similar to HTML format, e.g. "#FF8080". The number of digits must be a multiple of 3; the first group specifies the red component, the second green, and the third blue.
•
As the name of a color space, followed by one to four component values in parentheses, e.g. "hsv(120, 50%, 90%)".

Valid color spaces are "gray" (1 component), "graya" (2 components), "hsl" (3 components), "hsla" (4 components), "hsv" (3 components), "hsva" (4 components), "rgb" (3 components) and "rgba" (4 components). Each component can be specified as either a percentage of the maximum value suffixed by "%", or an absolute value in the range 0-360 for hues, 0-255 for everything else. For color space names ending with "a", the last component is the alpha (transparency) value.

Note that alpha values are meaningless for the "transparent" attribute on the <spu> tag above. <marc.leeman@gmail.com> MarcLeeman2003Marc Leeman
