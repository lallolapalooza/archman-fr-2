NOM

sprio - visualiser les facteurs qui composent la priorité d'ordonnancement d'une tâche

SYNTAXE

sprio [OPTIONS...]

DESCRIPTION

sprio est utilisé pour visualiser les composantes de la priorité d'ordonnancement d'une tâche lorsque le plugin de priorité multi-facteurs est installé. sprio est un utilitaire en lecture seule qui extrait des informations du plugin de priorité multi-facteurs. Par défaut, sprio renvoie des informations pour toutes les tâches en attente. Des options permettent d'afficher des tâches spécifiques par ID de tâche et nom d'utilisateur.

OPTIONS

-M, --clusters=<chaîne>
Le cluster auquel envoyer les commandes. Un seul nom de cluster peut être spécifié. Notez que le slurmdbd doit être démarré pour que cette option fonctionne correctement, sauf si vous exécutez dans une fédération avec FederationParameters=fed_display configuré ou l'option --federation définie. Cette option définit implicitement l'option --local.
--federation
Afficher les tâches dans la fédération si elle en fait partie.
-o, --format=<format_sortie>
Spécifie les informations à afficher, leur taille et leur position (alignées à droite ou à gauche). Les formats par défaut lorsque tous les facteurs ont des poids non nuls sont
défaut
"%.15i %9r %.10Y %.10S %.10A %.10B %.10F %.10J %.10P %.10Q %20T"
-l, --long
"%.15i %9r %.8u %.8o %.10Y %.10S %.10A %.10B %.10F %.10J %.10P %.10n %.10Q %.11N %.20T" ;

Le format de chaque champ est "%[.][taille]type".

taille
est la taille minimale du champ. Si aucune taille n'est spécifiée, la taille nécessaire pour imprimer l'information sera utilisée.
.
indique que la sortie doit être alignée à gauche. Par défaut, la sortie est alignée à droite.

Les spécifications de type valides incluent :

%a
Priorité d'âge normalisée
%A
Priorité d'âge pondérée
%b
Priorité d'association normalisée
%B
Priorité d'association pondérée
%c
Nom du cluster. Applicable uniquement aux clusters fédérés
%f
Priorité de juste partage normalisée
%F
Priorité de juste partage pondérée
%i
ID de la tâche
%j
Priorité de taille de tâche normalisée
%J
Priorité de taille de tâche pondérée
%n
Nom de la QOS
%N
Ajustement de la priorisation
%o
Nom du compte
%p
Priorité de partition normalisée
%P
Priorité de partition pondérée
%q
Priorité de qualité de service normalisée
%Q
Priorité de qualité de service pondérée
%r
Nom de la partition
%S
Priorité admin pondérée.
%t
Priorités TRES normalisées
%T
Priorités TRES pondérées
%u
Nom d'utilisateur pour une tâche
%Y
Priorité de la tâche
%y
Priorité de la tâche normalisée
--help
Imprimer un message d'aide décrivant toutes les options de sprio.
-j, --jobs=<liste_id_tâches>
Demande une liste séparée par des virgules d'ID de tâches à afficher. Par défaut, toutes les tâches. Comme l'argument de cette option est facultatif, pour un bon analyse, l'option d'une seule lettre doit être suivie immédiatement de la valeur et ne pas inclure d'espace entre les deux. Par exemple : "-j1008,1009" et non "-j 1008,1009".
--local
Afficher uniquement les tâches locales à ce cluster. Ignorer les autres clusters de cette fédération (le cas échéant). Remplace --federation.
-l, --long
Rapporter une plus grande partie des informations disponibles pour les tâches sélectionnées.
-h, --noheader
Ne pas imprimer d'en-tête sur la sortie.
-n, --norm
Afficher les facteurs de priorité normalisés pour les tâches sélectionnées.
-p, --partition=<liste_partitions>
Demande une liste de partitions séparées par des virgules à afficher. Par défaut, toutes les partitions.
--sibling
Afficher toutes les tâches sœurs sur un cluster fédéré. Sans cette option dans un cluster fédéré, chaque tâche de chaque partition aura sa priorité et ses composantes rapportées pour un seul cluster. Chaque tâche sœur sur les différents clusters de la fédération peut avoir une priorité différente, qui ne sera pas rapportée sans utiliser cette option. Ajoute implicitement "%c" (nom du cluster) au format de sortie.
-S, --sort=<liste_tri>
Spécification de l'ordre dans lequel les tâches doivent être rapportées. Ceci utilise la même spécification de champ que <format_sortie>. Plusieurs tris peuvent être effectués en listant plusieurs champs de tri séparés par des virgules. Les spécifications de champ peuvent être précédées de "+" ou "-"

; pour croissant (par défaut) ou décroissant respectivement. Par exemple, une <liste_tri> de « u,r,-y » triera les rapports de priorité des tâches par nom d'utilisateur, nom de partition et priorité de tâche décroissante, dans cet ordre. La <liste_tri> par défaut est « i » (identifiant de tâche croissant).
--usage
Affiche un bref message d'aide listant les options de sprio.
-u, --user=<liste_utilisateurs>
Demande des tâches à partir d'une liste d'utilisateurs séparés par des virgules. La liste peut être composée de noms d'utilisateurs ou de numéros d'identifiant d'utilisateur.
-v, --verbose
Rapport détaillé des actions de sprio.
-V, --version
Affiche les informations de version et quitte.
-w, --weights
Affiche les poids configurés pour chaque facteur. Ceci est uniquement à titre informatif. Les données réelles des tâches sont supprimées.

PERFORMANCE

L'exécution de sprio envoie un appel de procédure distante à slurmctld. Si un nombre suffisant d'appels provenant de sprio ou d'autres commandes client Slurm qui envoient des appels de procédure distante au démon slurmctld arrivent simultanément, cela peut entraîner une dégradation des performances du démon slurmctld, pouvant potentiellement entraîner un déni de service.

N'exécutez pas sprio ou d'autres commandes client Slurm qui envoient des appels de procédure distante à slurmctld depuis des boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à sprio au minimum nécessaire pour les informations que vous essayez de collecter.

VARIABLES D'ENVIRONNEMENT

Si aucune option de ligne de commande correspondante n'est spécifiée, sprio utilisera la valeur des variables d'environnement suivantes.

SLURM_CLUSTERS
Identique à --clusters
SLURM_CONF
L'emplacement du fichier de configuration Slurm.
SLURM_DEBUG_FLAGS
Spécifie les indicateurs de débogage que sprio doit utiliser. Voir DebugFlags dans la page de manuel slurm.conf(5) pour une liste complète des indicateurs. La variable d'environnement a la priorité sur le paramètre dans slurm.conf.
SPRIO_FEDERATION
Identique à --federation
SPRIO_FORMAT
Identique à -o <format_sortie>, --format=<format_sortie>
SPRIO_LOCAL
Identique à --local
SPRIO_SIBLING
Identique à --sibling

EXEMPLES

Imprime la liste de toutes les tâches en attente avec leurs priorités pondérées
$ sprio
  JOBID   PRIORITY        AGE  FAIRSHARE    JOBSIZE  PARTITION        QOS
  65539      62664          0      51664       1000      10000          0
  65540      62663          0      51663       1000      10000          0
  65541      62662          0      51662       1000      10000          0
Imprime la liste de toutes les tâches en attente avec leurs priorités normalisées
$ sprio -n
  JOBID PRIORITY   AGE        FAIRSHARE  JOBSIZE    PARTITION  QOS
  65539 0.00001459 0.0007180  0.5166470  1.0000000  1.0000000  0.0000000
  65540 0.00001459 0.0007180  0.5166370  1.0000000  1.0000000  0.0000000
  65541 0.00001458 0.0007180  0.5166270  1.0000000  1.0000000  0.0000000
Imprime les priorités des tâches pour des tâches spécifiques
$ sprio --jobs=65548,65547
  JOBID   PRIORITY        AGE  FAIRSHARE    JOBSIZE  PARTITION        QOS
  65547      62078          0      51078       1000      10000          0
  65548      62077          0      51077       1000      10000          0
Imprime les priorités des tâches pour les tâches d'utilisateurs spécifiques
$ sprio --users=fred,sally
  JOBID     USER  PRIORITY       AGE  FAIRSHARE   JOBSIZE  PARTITION     QOS
  65548     fred     62079         1      51077      1000      10000       0
  65549    sally     62080         1      51078      1000      10000       0
Imprime les poids configurés pour chaque composant de priorité
$ sprio -w
  JOBID   PRIORITY        AGE  FAIRSHARE    JOBSIZE  PARTITION        QOS
  Weights                1000     100000       1000      10000          1
