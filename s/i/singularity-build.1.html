NOM

apptainer-build - Construire une image Apptainer

SYNTAXE

apptainer build [options locales...]

DESCRIPTION

CHEMIN DE L'IMAGE :

Lorsque Apptainer construit le conteneur, la sortie peut être dans l'un des formats suivants :

  par défaut : Le format d'image Apptainer compressé en lecture seule (par défaut)
  sandbox : Il s'agit d'un conteneur en lecture-écriture au sein d'une structure de répertoires

note : Il est courant d'utiliser le mode "sandbox" pour le développement du
conteneur, puis de le construire au format Apptainer par défaut pour la production
. Le format par défaut est immuable.

SPÉCIFICATION DE CONSTRUCTION :

La cible de la spécification de construction est un fichier de définition (def), une image locale ou une URI pouvant être
utilisée pour créer un conteneur Apptainer. Plusieurs formats de cible locaux
existent :

  fichier def : Il s'agit d'une recette pour construire un conteneur (exemples ci-dessous)
  répertoire : Une structure de répertoires contenant un système de fichiers (ch)root
  image : Une image locale sur votre machine (sera convertie en sif si
              elle est au format hérité)

Les cibles peuvent également être distantes et définies par une URI des formats suivants :

  library://  une bibliothèque d'images (pas de défaut)
  docker://   un registre Docker/OCI (par défaut Docker Hub)
  shub://     un registre Apptainer (par défaut Singularity Hub)
  oras://     un registre OCI qui héberge des fichiers SIF utilisant ORAS

Fichiers temporaires :

L'emplacement utilisé pour les répertoires temporaires est '/tmp' par défaut, mais
peut être remplacé par la variable d'environnement TMPDIR, et celle-ci peut être
remplacée par la variable d'environnement APPTAINER_TMPDIR. Le
répertoire temporaire utilisé pendant une construction doit se trouver sur un système de fichiers disposant de suffisamment d'espace pour contenir l'intégralité de l'image du conteneur, non compressée,
y compris les fichiers temporaires qui sont créés puis supprimés
pendant la construction. Vous devrez peut-être définir APPTAINER_TMPDIR ou TMPDIR lors
de la construction d'un grand conteneur sur un système dont le répertoire /tmp est petit.

OPTIONS

--arch="amd64" architecture pour laquelle construire

--arch-variant="" variante d'architecture pour laquelle construire

--authfile="" fichier d'authentification de style Docker à utiliser pour écrire/lire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de liaison utilisateur. La spécification a le format src[:dest[:opts]], où src et dest sont les chemins extérieur et intérieur. Si dest n'est pas donné, il est défini égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, ce qui est le défaut). Plusieurs chemins de liaison peuvent être donnés par une liste séparée par des virgules.

--build-arg=[] définit variable=valeur pour remplacer les entrées {{ variable }} dans le fichier de définition de construction

--build-arg-file="" spécifie un fichier contenant des lignes variable=valeur pour remplacer '{{ variable }}' par valeur dans les fichiers de définition de construction

--disable-cache[=false] ne pas utiliser le cache ou créer de cache

--docker-host="" spécifier un hôte démon Docker personnalisé

--docker-login[=false] se connecter à un référentiel Docker interactivement

-e, --encrypt[=false] construire une image avec un système de fichiers chiffré

-f, --fakeroot[=false] construire avec l'apparence d'une exécution en tant que root (par défaut lors de la construction à partir d'un fichier de définition sans privilèges)

--fix-perms[=false] assurer que le propriétaire dispose des permissions rwX sur tout le contenu du conteneur pour les sources oci/docker

-F, --force[=false] écraser un fichier image s'il existe

-h, --help[=false] aide pour la construction

--json[=false] interpréter la définition de construction comme JSON

--library="" URL de la bibliothèque de conteneur

--mksquashfs-args="" arguments supplémentaires à passer à mksquashfs lors de la création de fichiers SIF

--mount=[] une spécification de montage par exemple 'type=bind,source=/opt,destination=/hostopt'.

--no-cleanup[=false] NE PAS nettoyer le bundle après une construction échouée, peut être utile pour le débogage

--no-https[=false] utiliser http au lieu de https pour les URIs docker:// oras:// et library:///...

-T, --notest[=false] construire sans exécuter les tests dans la section %test

--nv[=false] injecter les bibliothèques Nvidia de l'hôte pendant la construction pour les sections post et test

--nvccli[=false] utiliser nvidia-container-cli pour la configuration GPU (expérimental)

--passphrase[=false] demander une phrase secrète de chiffrement

--pem-path="" entrer un chemin vers une clé RSA au format PEM pour un conteneur chiffré

--rocm[=false] injecter les bibliothèques Rocm de l'hôte pendant la construction pour les sections post et test

-s, --sandbox[=false] construire l'image au format sandbox (structure de répertoire chroot)

--section=[all] exécuter uniquement des sections spécifiques du fichier de définition (setup, post, files, environment, test, labels, none)

-u, --update[=false] exécuter la définition sur un conteneur existant (saute l'en-tête)

--userns[=false] construire sans utiliser setuid même s'il est disponible

--warn-unused-build-args[=false] affiche un avertissement au lieu d'un message d'erreur lorsque les arguments de construction ne correspondent pas exactement

--writable-tmpfs[=false] pendant la section %test, rend le système de fichiers accessible en lecture-écriture avec des données non persistantes (uniquement avec prise en charge d'overlay)

EXEMPLE

  FICHIER DE DÉFINITION BASE OS :
      Bibliothèque :
          Bootstrap : library
          From : debian:9
      Docker :
          Bootstrap : docker
          From : tensorflow/tensorflow:latest
          IncludeCmd : yes # Utilise la commande CMD comme script d'exécution au lieu de ENTRYPOINT
      Singularity Hub :
          Bootstrap : shub
          From : singularityhub/centos
      YUM/RHEL :
          Bootstrap : yum
          OSVersion : 7
          MirrorURL : http://mirror.centos.org/centos-%{OSVERSION}/%{OSVERSION}/os/x86_64/
          Include : yum
      SUSE :
          Bootstrap : zypper # sur système SLE, l'enregistrement de l'hôte de construction est utilisé
          Include : zypper
      openSUSE :
          Bootstrap : zypper
          MirrorURL : http://download.opensuse.org/distribution/openSUSE-stable/repo/oss
          Include : zypper
      Debian/Ubuntu :
          Bootstrap : debootstrap
          OSVersion : trusty
          MirrorURL : http://us.archive.ubuntu.com/ubuntu/
      Image Locale :
          Bootstrap : localimage
          From : /home/dave/starter.img
      Scratch :
          Bootstrap : scratch # Remplit le conteneur avec un rootfs minimal dans %setup
  SECTIONS DU FICHIER DE DÉFINITION :
  Les sections suivantes sont présentées dans l'ordre de traitement, à l'exception
  des labels et de l'environnement qui peuvent également être manipulés dans %post.
      %pre
          echo "Ceci est un scriptlet qui sera exécuté sur l'hôte, en tant que root avant"
          echo "que le conteneur ne soit démarré. Cette section n'est pas couramment utilisée."
      %setup
          echo "Ceci est un scriptlet qui sera exécuté sur l'hôte, en tant que root, après"
          echo "que le conteneur n'ait été démarré. Pour installer des choses dans le conteneur"
          echo "référencez l'emplacement du système de fichiers avec $APPTAINER_ROOTFS."
      %files
          /path/on/host/file.txt /path/on/container/file.txt
          relative_file.txt /path/on/container/relative_file.txt
      %post
          echo "Cette section de scriptlet sera exécutée depuis l'intérieur du conteneur après"
          echo "que le bootstrap/base ait été créé et configuré."
      %environment
          LUKE=goodguy
          VADER=badguy
          HAN=someguy
          export HAN VADER LUKE
      %test
          echo "Définissez toutes les commandes de test qui doivent être exécutées après que le conteneur ait été"
          echo "construit. Ce scriptlet sera exécuté depuis l'intérieur du conteneur en cours d'exécution"
          echo "en tant qu'utilisateur root. Faites attention à la valeur de sortie/retour de ce scriptlet"
          echo "car tout code de sortie non nul sera supposé comme un échec."
          exit 0
      %runscript
          echo "Définissez les actions pour le conteneur à exécuter avec la commande run ou"
          echo "lorsque le conteneur est exécuté."
      %startscript
          echo "Définissez les actions que le conteneur doit effectuer lorsqu'il est démarré en tant qu'instance."
      %labels
          HELLO MOTO
          KEY VALUE
      %help
          Ceci est un fichier texte à afficher avec la commande run-help.
  COMMANDES :
      Construire un fichier sif à partir d'un fichier de recette Apptainer :
          $ apptainer build /tmp/debian0.sif /path/to/debian.def
      Construire une image sif à partir de la Bibliothèque :
          $ apptaine

NAME

apptainer-build - Build an Apptainer container image

SYNOPSIS

apptainer build [--sandbox] [--force] [--remote[=]] [--build-arg ] [-F | --force] [-o

=] [--fssize ] [--label ] [--no-eval] [--insecure] [--no-pull] [--userbindscript ] container-image image-file

apptainer build [--sandbox] [--remote[=]] [--build-arg ] [-F | --force] [-o

=] [--fssize ] [--label ] [--no-eval] [--insecure] [--no-pull] [--userbindscript ] container-image image-directory

DESCRIPTION

Build an Apptainer container image from a definition file or a sandbox.

If the image-file or image-directory parameter is a directory, the apptainer build command builds a sandbox structure rather than a single image file.

The container-image parameter can be a local file path or a URI. Supported URIs include:

  • docker:// for Docker Hub images.
  • library:// for Apptainer Library images.
  • oras:// for ORAS registry images.
  • nfsv41:// for NFSv4.1 share.
  • http:// or https:// for remote images.
  • shub:// for Singularity Hub images.
  • oci: for OCI image.
  • docker-daemon: for image in docker daemon.

The image-file parameter specifies the path for the new container image file. If it ends with a .sif extension, a SIF (Singularity Image Format) file will be created. Otherwise, an uncompressed OCI archive will be created.

If the image-file parameter is a directory, the command builds a sandbox structure. This is useful for iterative development and debugging.

You can use the --sandbox flag to explicitly build a sandbox, even if the output path does not end with .sif.

The --remote flag allows building images on a remote host. The variant can be specified to select a particular build environment.

The --build-arg flag allows passing build-time variables to the build process. These variables can be used within the container definition file.

Use --force or -F to overwrite an existing image file or sandbox directory.

The -o

= flag allows setting specific sections of the image, such as the license or autor.

The --fssize flag allows you to specify the size of the filesystem for the container image. This is only applicable when creating a SIF file.

The --label flag allows you to add custom labels to the container image.

The --no-eval flag disables the evaluation of environment variables within the definition file.

The --insecure flag disables the cryptographic signature verification for remote sources.

The --no-pull flag prevents Apptainer from automatically pulling base images. This is useful when working with local copies of base images.

The --userbindscript flag allows specifying a script that will be executed to determine user bind mounts when the container is run.

OPTIONS

apptainer build supports all global options, including verbose and quiet flags. See apptainer(1) for more details.

--sandbox
Build a sandbox structure instead of a SIF file.
-F, --force
Overwrite an existing image file or sandbox directory.
--remote[=variant]
Build image on a remote host. Optionally specify a build variant.
--build-arg key=value
Pass a build-time variable.
-o section=value
Set a specific image section (e.g., license, author).
--fssize size
Set the filesystem size for SIF images.
--label label
Add a custom label to the image.
--no-eval
Do not evaluate environment variables in the definition file.
--insecure
Disable cryptographic signature verification for remote sources.
--no-pull
Do not automatically pull base images.
--userbindscript path
Specify a script to determine user bind mounts.

EXAMPLE

Build a SIF image from a Docker Hub image, install python in it, then build a new SIF image.

      $ apptainer build --sandbox /tmp/debian library://debian:latest
      $ apptainer exec --writable /tmp/debian apt-get install python
      $ apptainer build /tmp/debian2.sif /tmp/debian
