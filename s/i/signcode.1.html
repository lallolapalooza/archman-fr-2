NOM

signcode - Signature numérique d'un exécutable PE à l'aide d'un certificat X.509.

SYNTAXE

signcode [options] nom_de_fichier

DESCRIPTION

Signe numériquement un exécutable PE (assembly CLR, EXE ou DLL Win32) à l'aide d'un certificat X.509 et de sa clé privée associée. La signature est compatible avec Authenticode(r) et peut être validée avec chktrust (soit sous Windows, soit sur toute plateforme supportée par Mono).

OPTIONS

-spc fichier_spc
Le fichier de l'éditeur de logiciels (spc) qui contient la chaîne de certificats X.509 utilisée pour signer numériquement l'exécutable PE.
-v fichier_pvk
Le fichier de clé privée (pvk) qui contient la clé privée utilisée pour signer numériquement l'exécutable PE. Cette clé privée doit correspondre à la clé publique contenue dans le certificat X.509 de l'éditeur.
-a sha1 | md5 | sha2 | sha256 | sha384 | sha512
L'algorithme de hachage utilisé dans la signature numérique de l'exécutable PE. L'algorithme par défaut est SHA1.
-$ individuel | commercial
Ajoute des informations sur l'éditeur, c'est-à-dire si la signature est générée par un individu ou une entité commerciale.
-n description
Ajoute une description textuelle du fichier signé.
-i url
Ajoute une URL associée à l'éditeur ou au fichier signé.
-t url
URL d'un service d'horodatage pour contresigner l'exécutable PE. Une contresignature est requise si vous souhaitez que la signature de l'exécutable PE soit valide après l'expiration du certificat de l'éditeur. La contresignature prouve que l'éditeur possédait un certificat valide (non expiré) au moment de la signature de l'exécutable PE.
-tr #
Nombre de tentatives pour obtenir un horodatage pour la contresignature.
-tw #
Délai (en secondes) entre les tentatives pour obtenir un horodatage pour la contresignature.
-k nom
Nom du conteneur de clé CryptoAPI (lorsque -v n'est pas utilisé).
-p nom
Nom du fournisseur CryptoAPI (lorsque -v n'est pas utilisé).
-y #
Type du fournisseur CryptoAPI (lorsque -v ou -p ne sont pas utilisés).
-ky signature | exchange | #
Type de clé CryptoAPI (lorsque -v n'est pas utilisé).
-r machineLocale | utilisateurCourant
Emplacement de la clé CryptoAPI (lorsque -v n'est pas utilisé).
-help , -h , -? , /?
Affiche l'aide relative à cet outil.

AUTRES TECHNOLOGIES DE SIGNATURE DE CODE

Les assemblies sont des fichiers PE qui peuvent également être "strongnamed" (fortement nommés) à l'aide de l'outil sn.exe. L'ordre de la signature du code est important si un fichier nécessite une signature Authenticode et une signature forte. La signature forte doit être appliquée avant la signature Authenticode. L'application d'une signature forte après la signature Authenticode, comme une nouvelle signature d'un assembly (par exemple, un "delay-sign"), invalidera la signature Authenticode.

RESTRICTIONS CONNUES

signcode ne peut pas générer de signatures Authenticode pour les fichiers CAB.
