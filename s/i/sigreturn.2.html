sigreturn(2) Manuel des appels système sigreturn(2)

NOM

sigreturn, rt_sigreturn - retour du gestionnaire de signal et nettoyage de la pile d'appels

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

int sigreturn(...);

DESCRIPTION

Si le noyau Linux détermine qu'un signal non bloqué est en attente pour un processus, alors, lors de la prochaine transition vers le mode utilisateur dans ce processus (par exemple, au retour d'un appel système ou lorsque le processus est replanifié sur le CPU), il crée une nouvelle trame sur la pile de l'espace utilisateur où il sauvegarde divers éléments du contexte du processus (mot d'état du processeur, registres, masque de signal, et paramètres de la pile de signal).

Le noyau organise également, lors de la transition vers le mode utilisateur, l'appel du gestionnaire de signal, et, au retour du gestionnaire, le contrôle passe à un morceau de code de l'espace utilisateur communément appelé le "tremplin de signal". Le code du tremplin de signal appelle ensuite sigreturn().

Cet appel sigreturn() annule tout ce qui a été fait — modification du masque de signal du processus, changement des piles de signal (voir sigaltstack(2)) — afin d'invoquer le gestionnaire de signal. En utilisant les informations qui ont été précédemment sauvegardées sur la pile de l'espace utilisateur, sigreturn() restaure le masque de signal du processus, change les piles, et restaure le contexte du processus (indicateurs et registres du processeur, y compris le pointeur de pile et le pointeur d'instruction), de sorte que le processus reprend son exécution au point où il a été interrompu par le signal.

VALEUR DE RETOUR

sigreturn() ne retourne jamais.

VERSIONS

De nombreux systèmes de type UNIX ont un appel système sigreturn() ou un équivalent proche. Cependant, cet appel n'est pas spécifié par POSIX, et les détails de son comportement varient d'un système à l'autre.

NORMES

Aucune.

NOTES

sigreturn() existe uniquement pour permettre l'implémentation des gestionnaires de signal. Il ne devrait jamais être appelé directement. (En effet, une simple enveloppe sigreturn() dans la bibliothèque C GNU retourne simplement -1, avec errno défini à ENOSYS.) Les détails des arguments (s'il y en a) passés à sigreturn() varient en fonction de l'architecture. (Sur certaines architectures, comme x86-64, sigreturn() ne prend aucun argument, car toutes les informations dont il a besoin sont disponibles dans la trame de pile qui a été précédemment créée par le noyau sur la pile de l'espace utilisateur.)

Autrefois, les systèmes UNIX plaçaient le code du tremplin de signal sur la pile utilisateur. Aujourd'hui, les pages de la pile utilisateur sont protégées afin de ne pas permettre l'exécution de code. Ainsi, sur les systèmes Linux contemporains, selon l'architecture, le code du tremplin de signal se trouve soit dans le vdso(7), soit dans la bibliothèque C. Dans ce dernier cas, la fonction d'enveloppe sigaction(2) de la bibliothèque C informe le noyau de l'emplacement du code du tremplin en plaçant son adresse dans le champ sa_restorer de la structure sigaction, et définit l'indicateur SA_RESTORER dans le champ sa_flags.

Les informations de contexte du processus sauvegardées sont placées dans une structure ucontext_t (voir <sys/ucontext.h>). Cette structure est visible dans le gestionnaire de signal en tant que troisième argument d'un gestionnaire établi via sigaction(2) avec l'indicateur SA_SIGINFO.

Sur certains autres systèmes UNIX, le fonctionnement du tremplin de signal diffère légèrement. En particulier, sur certains systèmes, lors de la transition vers le mode utilisateur, le noyau passe le contrôle au tremplin (plutôt qu'au gestionnaire de signal), et le code du tremplin appelle le gestionnaire de signal (puis appelle sigreturn() une fois que le gestionnaire est revenu).

Différences bibliothèque C/noyau

L'appel système Linux d'origine s'appelait sigreturn(). Cependant, avec l'ajout des signaux temps réel dans Linux 2.2, un nouvel appel système, rt_sigreturn(), a été ajouté pour prendre en charge un type sigset_t élargi. La bibliothèque C GNU nous cache ces détails, utilisant de manière transparente rt_sigreturn() lorsque le noyau la fournit.

VOIR AUSSI

kill(2), restart_syscall(2), sigaltstack(2), signal(2), getcontext(3), signal(7), vdso(7)
