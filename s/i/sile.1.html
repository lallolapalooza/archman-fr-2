SILE(1) Manuel des commandes générales SILE(1)

NOM

SILE - Le compositeur SILE lit un ou plusieurs fichiers d'entrée et compose le contenu dans un format de document rendu, typiquement PDF

SYNTAXE

sile [-b|--backend] [-c|--class] [-d|--debug] [-e|--evaluate] [-E|--evaluate-after] [-f|--fontmanager] [--luarocks-tree] [-m|--makedeps] [-o|--output] [-O|--option] [-p|--preamble] [-P|--postamble] [-u|--use] [-q|--quiet] [-t|--traceback] [-h|--help] [ENTRÉE]

DESCRIPTION

Le compositeur SILE lit un ou plusieurs fichiers d'entrée et compose le contenu dans un format de document rendu, typiquement PDF.

Par défaut, les fichiers d'entrée peuvent être en balisage SIL déclaratif, XML structuré ou Lua programmatique. Le format d'entrée est automatiquement détecté par les modules actifs. Par défaut, la sortie sera un fichier portant le même nom que le premier fichier d'entrée, avec l'extension changée en .pdf. Le nom du fichier de sortie peut être modifié avec l'argument `--output`. En utilisant `--backend`, on peut passer à un format de sortie différent (ou à un pilote différent pour le même format). Des entrées ou sorties supplémentaires peuvent être gérées en chargeant un module tiers qui les prend en charge en ajoutant l'argument `--use` sur la ligne de commande (qui sera chargé avant de tenter de lire les documents d'entrée).

OPTIONS

-b, --backend=BACKEND
Spécifie le backend de sortie.

La valeur par défaut est `libtexpdf` et convient à la plupart des sorties PDF. Les alternatives prises en charge directement incluent `text`, `debug`, `dummy`, `cairo` et `podofo`. D'autres générateurs peuvent être activés via `--use`.

-c, --class=CLASSE
Remplace la classe de document par défaut ou spécifiée.

La classe par défaut pour les documents qui n'en spécifient pas dans la balise racine est `plain`. Ceci peut être utilisé pour changer la classe par défaut ou pour remplacer la classe réellement spécifiée dans un document. Les autres classes groupées incluent `base`, `bible`, `book`, `diglot`, `docbook`, `docbook`, `jbook`, `jplain`, `letter`, `pecha`, `tbook`, `tplain` et `triglot`. D'autres seront chargées dynamiquement depuis le chemin des modules.

-d, --debug=INDICATEURDEBOGAGE[,INDICATEURDEBOGAGE]
Affiche des informations de débogage pour des aspects marqués de l'opération de SILE.

Plusieurs indicateurs de débogage peuvent être donnés sous forme de liste séparée par des virgules. Bien que les paquets puissent définir leurs propres indicateurs de débogage, les plus couramment utilisés sont `typesetter`, `pagebuilder`, `vboxes`, `break`, `frames`, `profile` et `versions`. Peut être spécifié plusieurs fois.

-e, --evaluate=EXPRESSION
Évalue une expression Lua avant de traiter l'entrée.

Peut être spécifié plusieurs fois.

-E, --evaluate-after=EXPRESSION
Évalue une expression Lua après le traitement de l'entrée.

Peut être spécifié plusieurs fois.

-f, --fontmanager=FONTMANGER
Spécifie le gestionnaire de polices à utiliser.

Le gestionnaire de polices est responsable de la découverte des emplacements des fichiers de polices sur le système en fonction d'un nom de police. Le gestionnaire de polices par défaut est `fontconfig` sur les systèmes non-macOS et `macfonts` sur macOS.

--luarocks-tree=ARBRE_LUAROCKS
Ajoute un chemin à la liste des arbres LuaRocks recherchés pour les modules.

Lors de l'installation de modules SILE tiers via LuaRocks, plusieurs emplacements d'installation sont possibles. Ils peuvent être installés sur le système hôte, le répertoire personnel de l'utilisateur, un chemin local au projet, ou tout emplacement arbitraire. Dans le cas du système ou d'un chemin local au projet appelé exactement `lua_modules`, ils seront trouvés automatiquement. Dans le cas de tout autre chemin, SILE doit être informé où les trouver. Ceci peut être fait en exportant une variable d'environnement LUA_PATH avant d'exécuter SILE, ou en utilisant cette option.

-m, --makedeps=FICHIER
Génère une liste des dépendances au format Makefile et les écrit dans un fichier.

Ceci suit tous les fichiers (fichiers d'entrée, bibliothèques Lua, polices, images, etc.) utilisés pendant le processus de composition. Une fois terminé, la liste est écrite dans FICHIER dans le format d'une liste de dépendances pour une cible dans un Makefile. Ceci peut être utilisé plus tard pour déterminer si un PDF doit être ré-rendu en fonction de la modification d'une des entrées.

-o, --output=FICHIER
Définit explicitement le nom du fichier de sortie.

Par défaut, le nom de base du premier fichier d'entrée sera utilisé comme nom de fichier de sortie. Une extension sera choisie en fonction du backend de sortie, généralement .pdf. Avec cette option, n'importe quel nom et chemin arbitraires peuvent être donnés. De plus, `-` peut être utilisé pour écrire la sortie vers STDOUT.

-O, --option=OPTION
Définit ou remplace les options de la classe de document.

Peut être utilisé pour modifier les options par défaut ou remplacer celles spécifiées dans un document. Par exemple, définir `--option papersize=letter` remplacerait à la fois la taille de papier par défaut A4 et toute autre taille spécifiquement définie dans les options du document. Peut être spécifié plusieurs fois.

-p, --preamble=FICHIER
Inclut le contenu d'un fichier SIL, XML ou d'une autre ressource avant le contenu du document d'entrée.

La valeur doit être un nom de fichier complet avec un chemin relatif au répertoire courant (PWD) ou un chemin absolu. Peut être spécifié plusieurs fois.

-P, --postamble=FICHIER
Inclut le contenu d'un fichier SIL, XML ou d'une autre ressource après le contenu du document d'entrée.

La valeur doit être un nom de fichier complet avec un chemin relatif au répertoire courant (PWD) ou un chemin absolu. Peut être spécifié plusieurs fois.

-u, --use=MODULE[[PARAMETRE=VALEUR[,PARAMETRE=VALEUR]]]
Charge et initialise une classe, un module d'entrée, de mise en forme ou autre module avant de traiter l'entrée principale.

La valeur doit être un nom de module chargeable (sans extension, en utilisant `.` comme séparateur de chemin) et sera chargé en utilisant le chemin de recherche des modules de SILE. Des options peuvent être passées au module en plaçant des paires `clé=valeur` entre crochets après le nom du module. Ceci est particulièrement utile lorsque le document d'entrée n'est pas SIL ou un schéma XML nativement reconnu et que SILE doit être enseigné de nouvelles astuces avant même d'essayer de lire le fichier d'entrée. Si le module est une classe de document, il remplacera `plain` comme classe par défaut pour le traitement des documents qui n'en spécifient pas explicitement une à utiliser. Comme cela s'exécute avant le chargement du document, cela peut même ajouter un analyseur d'entrée ou modifier un analyseur existant pour prendre en charge de nouveaux formats de fichiers. Les modules de paquets seront ajoutés au préambule pour être chargés après l'initialisation de la classe. Peut être spécifié plusieurs fois.

-q, --quiet
Supprime les avertissements et les messages d'information pendant le traitement.
-t, --traceback
Affiche une trace de localisation détaillée en cas d'erreurs et d'avertissements.
-h, --help
Affiche l'aide (voir un résumé avec '-h').
[ENTRÉE]
Nom(s) du fichier du document d'entrée, par défaut en formats SIL, XML ou Lua.

Un ou plusieurs fichiers d'entrée à partir desquels traiter le contenu. Le premier fichier listé est considéré comme le document maître, les autres sont traités séquentiellement. D'autres formats d'entrée peuvent être activés via `--use`. Utilisez `-` pour lire un flux de contenu depuis STDIN.
