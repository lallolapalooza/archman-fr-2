sigqueue(3) Manuel des fonctions de bibliothèque sigqueue(3)

NOM

sigqueue - met en file d'attente un signal et des données vers un processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>
int sigqueue(pid_t pid, int sig, const union sigval value);
Conditions requises pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)) :

sigqueue() :

    _POSIX_C_SOURCE >= 199309L

DESCRIPTION

sigqueue() envoie le signal spécifié par sig au processus dont le PID est donné par pid. Les autorisations requises pour envoyer un signal sont les mêmes que pour kill(2). Comme avec kill(2), le signal nul (0) peut être utilisé pour vérifier si un processus avec un PID donné existe.

L'argument value est utilisé pour spécifier une donnée associée (un entier ou un pointeur) à envoyer avec le signal, et a le type suivant :


union sigval {
    int   sival_int;
    void *sival_ptr;
};

Si le processus récepteur a installé un gestionnaire pour ce signal en utilisant le drapeau SA_SIGINFO de sigaction(2), alors il peut obtenir ces données via le champ si_value de la structure siginfo_t passée en deuxième argument au gestionnaire. De plus, le champ si_code de cette structure sera défini à SI_QUEUE.

VALEUR DE RETOUR

En cas de succès, sigqueue() retourne 0, indiquant que le signal a été mis en file d'attente avec succès pour le processus récepteur. Sinon, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EAGAIN
La limite des signaux pouvant être mis en file d'attente a été atteinte. (Voir signal(7) pour plus d'informations.)
EINVAL
sig était invalide.
EPERM
Le processus n'a pas l'autorisation d'envoyer le signal au processus récepteur. Pour les autorisations requises, voir kill(2).
ESRCH
Aucun processus n'a de PID correspondant à pid.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
sigqueue () Sécurité des threads MT-Safe

VERSIONS

Différences bibliothèque C/noyau

Sous Linux, sigqueue() est implémenté en utilisant l'appel système rt_sigqueueinfo(2). L'appel système diffère par son troisième argument, qui est la structure siginfo_t qui sera fournie au gestionnaire de signaux du processus récepteur ou retournée par l'appel sigtimedwait(2) du processus récepteur. À l'intérieur de l'enveloppe sigqueue() de glibc, cet argument, uinfo, est initialisé comme suit :


uinfo.si_signo = sig;      /* Argument fourni à sigqueue() */
uinfo.si_code = SI_QUEUE;
uinfo.si_pid = getpid();   /* ID du processus émetteur */
uinfo.si_uid = getuid();   /* UID réel de l'émetteur */
uinfo.si_value = val;      /* Argument fourni à sigqueue() */

NORMES

POSIX.1-2008.

HISTORIQUE

Linux 2.2. POSIX.1-2001.

NOTES

Si cette fonction entraîne l'envoi d'un signal au processus qui l'a appelée, et que ce signal n'était pas bloqué par le thread appelant, et qu'aucun autre thread n'était disposé à gérer ce signal (soit en le débloquant, soit en attendant ce signal à l'aide de sigwait(3)), alors au moins un signal doit être délivré à ce thread avant que cette fonction ne retourne.

VOIR AUSSI

kill(2), rt_sigqueueinfo(2), sigaction(2), signal(2), pthread_sigqueue(3), sigwait(3), signal(7)
