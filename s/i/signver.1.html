SIGNVER(1) Outils de sécurité NSS SIGNVER(1)

NOM

signver - Vérifie une signature PKCS#7 détachée pour un fichier.

SYNTAXE

signtool -A | -V -d répertoire [-a] [-i fichier_entrée] [-o fichier_sortie] [-s fichier_signature] [-v]

STATUT

Cette documentation est encore en cours de rédaction. Veuillez contribuer à l'examen initial dans Mozilla NSS bug 836477[1]

DESCRIPTION

L'outil de vérification de signature, signver, est un utilitaire simple en ligne de commande qui décompresse un objet signé PKCS#7 encodé en base64 et vérifie la signature numérique à l'aide de techniques cryptographiques standard. L'outil de vérification de signature peut également afficher le contenu de l'objet signé.

OPTIONS

-A

Affiche toutes les informations dans la signature PKCS#7.

-V

Vérifie la signature numérique.

-d répertoire

Spécifie le répertoire de base de données qui contient les certificats et les clés.

signver prend en charge deux types de bases de données : les bases de données de sécurité héritées (cert8.db, key3.db et secmod.db) et les nouvelles bases de données SQLite (cert9.db, key4.db et pkcs11.txt). Si le préfixe dbm: n'est pas utilisé, l'outil suppose que les bases de données fournies sont au format SQLite.

-a

Indique que le fichier de signature fourni est au format ASCII.

-i fichier_entrée

Donne le fichier d'entrée pour l'objet avec les données signées.

-o fichier_sortie

Donne le fichier de sortie vers lequel écrire les résultats.

-s fichier_signature

Donne le fichier d'entrée pour la signature numérique.

-v

Active la sortie détaillée.

EXEMPLES DÉTAILLÉS

Vérifier une signature

L'option -V vérifie que la signature dans un fichier de signature donné est valide lorsqu'elle est utilisée pour signer l'objet donné (provenant du fichier d'entrée).

signver -V -s fichier_signature -i fichier_signé -d /home/mon/sharednssdb
signatureValide=oui

Afficher les données de signature

L'option -A affiche toutes les informations contenues dans un fichier de signature. L'utilisation de l'option -o affiche les informations du fichier de signature dans le fichier de sortie donné plutôt que dans la sortie standard.

signver -A -s fichier_signature -o fichier_sortie

TYPES DE BASE DE DONNÉES NSS

NSS utilisait à l'origine des bases de données BerkeleyDB pour stocker des informations de sécurité. Les dernières versions de ces bases de données héritées sont :

•cert8.db pour les certificats
•key3.db pour les clés
•secmod.db pour les informations du module PKCS #11

BerkeleyDB a des limitations de performance, qui l'empêchent d'être facilement utilisé par plusieurs applications simultanément. NSS dispose d'une certaine flexibilité qui permet aux applications d'utiliser leur propre moteur de base de données indépendant tout en conservant une base de données partagée et en contournant les problèmes d'accès. Néanmoins, NSS nécessite plus de flexibilité pour fournir une base de données de sécurité véritablement partagée.

En 2009, NSS a introduit un nouvel ensemble de bases de données qui sont des bases de données SQLite plutôt que BerkleyDB. Ces nouvelles bases de données offrent plus d'accessibilité et de performance :

•cert9.db pour les certificats
•key4.db pour les clés
•pkcs11.txt, qui liste tous les modules PKCS #11 contenus dans un nouveau sous-répertoire du répertoire des bases de données de sécurité

Comme les bases de données SQLite sont conçues pour être partagées, ce sont les types de bases de données partagées. Le type de base de données partagée est préféré ; le format hérité est inclus pour la compatibilité descendante.

Par défaut, les outils (certutil, pk12util, modutil) supposent que les bases de données de sécurité fournies utilisent le type SQLite. L'utilisation des bases de données héritées doit être spécifiée manuellement en utilisant le préfixe dbm: avec le répertoire de sécurité fourni. Par exemple :

# signver -A -s signature -d dbm:/home/mon/sharednssdb

Pour définir le type de base de données héritée comme type par défaut pour les outils, définissez la variable d'environnement NSS_DEFAULT_DB_TYPE sur dbm :

export NSS_DEFAULT_DB_TYPE="dbm"

Cette ligne peut être ajoutée au fichier ~/.bashrc pour rendre le changement permanent pour l'utilisateur.

•https://wiki.mozilla.org/NSS_Shared_DB_Howto

Pour une ébauche d'ingénierie sur les changements dans les bases de données NSS partagées, consultez le wiki du projet NSS :

•https://wiki.mozilla.org/NSS_Shared_DB
