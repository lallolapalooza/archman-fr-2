SIGROK-CLI(1) Manuel des commandes générales SIGROK-CLI(1)

NOM

sigrok-cli - Client en ligne de commande pour le logiciel sigrok

SYNTAXE

sigrok-cli [OPTIONS] [COMMANDE]

DESCRIPTION

sigrok-cli est un utilitaire multiplateforme en ligne de commande pour le logiciel sigrok.

Il ne peut pas afficher de sortie graphique, mais est néanmoins suffisant pour effectuer l'ensemble du processus d'initialisation matérielle, d'acquisition, de décodage de protocole et d'enregistrement de la session.

Il est utile pour être exécuté sur des systèmes distants ou embarqués, des netbooks, des PDA, et pour divers autres cas d'utilisation. Il peut afficher des échantillons sur la sortie standard ou les enregistrer dans divers formats de fichiers.

OPTIONS

-h, --help
Affiche un texte d'aide et quitte.
-V, --version
Affiche la version de sigrok-cli et les versions des bibliothèques utilisées.
-L, --list-supported
Affiche des informations sur les pilotes matériels, les formats de fichiers d'entrée, les formats de fichiers de sortie et les décodeurs de protocoles pris en charge.
--list-supported-wiki
Affiche des informations sur les décodeurs de protocoles pris en charge en syntaxe MediaWiki. Ceci est généralement uniquement utilisé par les développeurs pour mettre à jour facilement la liste des décodeurs de protocoles pris en charge sur le wiki sigrok.
-d, --driver <nom_pilote>
Sauf si un scan global est effectué, les utilisateurs sélectionnent généralement l'un des pilotes disponibles. Cela peut accélérer le démarrage du programme et éviter les correspondances erronées pour des configurations ambiguës. La sélection d'un pilote permet également de passer des options spécifiques au pilote. Utilisez l'option -L (--list-supported) pour obtenir une liste des pilotes disponibles.

Les pilotes peuvent prendre des options, sous la forme clé=valeur séparées par des deux-points.

Les pilotes communiquant avec le matériel via un port série nécessitent toujours que le port soit spécifié comme option conn. Par exemple, pour utiliser l'Openbench Logic Sniffer :

$ sigrok-cli --driver=ols:conn=/dev/ttyACM0 [...]

Certains périphériques USB n'utilisent pas une combinaison unique de VendorID/ProductID et nécessitent donc que cela soit également spécifié. Notez que les deux-points sont utilisés pour séparer le nom du pilote de l'option conn, ainsi les deux-points ne peuvent pas être utilisés dans l'argument de l'option conn. Pour sélectionner un périphérique USB spécifique, utilisez soit VendorID.ProductID soit bus.address :

Exemple USB VendorID.ProductID :

$ sigrok-cli --driver=uni-t-ut61e:conn=1a86.e008 [...]

Exemple USB bus.address :

$ sigrok-cli --driver=uni-t-ut61e:conn=4.6 [...]

-D, --dont-scan
Ne pas scanner automatiquement les pilotes de périphériques en l'absence d'une spécification -d (--driver).
-c, --config <option_périphérique>
Une liste d'options de périphérique séparées par des deux-points, où chaque option prend la forme clé=valeur. Plusieurs occurrences de l'option --config sont prises en charge. Le premier élément de la liste d'options peut prendre la forme channel_group=<nom>, ce qui remplacerait la spécification --channel-group pour cette liste d'options. Les autres listes d'options dans d'autres occurrences de --config ne sont pas affectées par le nom du groupe de canaux de cette liste.

Par exemple, pour définir la fréquence d'échantillonnage à 1MHz sur un appareil pris en charge par le pilote fx2lafw, vous pouvez spécifier

$ sigrok-cli -d fx2lafw --config samplerate=1m [...]

La fréquence d'échantillonnage est une option commune à la plupart des analyseurs logiques. L'argument spécifie la fréquence d'échantillonnage en Hz. Vous pouvez également spécifier la fréquence d'échantillonnage en kHz, MHz ou GHz. Les lignes suivantes sont toutes équivalentes :

$ sigrok-cli -d fx2lafw --config samplerate=1000000 [...]

$ sigrok-cli -d fx2lafw --config samplerate=1m [...]

$ sigrok-cli -d fx2lafw --config "samplerate=1 MHz" [...]

Ces exemples spécifient des options au sein d'un groupe de canaux. Les deux premiers sont équivalents.

$ sigrok-cli -d demo --channel-group Logic --config pattern=random [...]

$ sigrok-cli -d demo --config channel_group=Logic:pattern=random [...]

$ sigrok-cli -d demo --config samplerate=1m --config channel_group=Logic:pattern=random [...]

-i, --input-file <nom_fichier>
Charge l'entrée à partir d'un fichier au lieu d'un périphérique matériel. Vous pouvez spécifier "-" pour utiliser stdin comme entrée. Si l'option --input-format n'est pas fournie, sigrok-cli tente de détecter automatiquement le format de fichier de l'entrée.

Exemple de chargement d'un fichier de session sigrok :

$ sigrok-cli -i exemple.sr [...]

Exemple de chargement d'un fichier WAV (détection automatique du format d'entrée) :

$ sigrok-cli -i exemple.wav [...]

Exemple de chargement d'un fichier VCD depuis stdin (détection automatique du format d'entrée) :

$ cat exemple.vcd | sigrok-cli -i - [...]

-I, --input-format <format>
Lors du chargement d'un fichier d'entrée, suppose qu'il est dans le format spécifié. Si cette option n'est pas fournie (en plus de --input-file), sigrok-cli tente de détecter automatiquement le format de fichier de l'entrée. Utilisez l'option -L (--list-supported) pour voir la liste des formats d'entrée disponibles.

Le nom du format peut éventuellement être suivi d'une liste d'options séparées par des deux-points, où chaque option prend la forme clé=valeur.

Exemple de chargement d'un fichier binaire avec des options :

$ sigrok-cli -i exemple.bin
-I binary:numchannels=4:samplerate=1mhz [...]

-o, --output-file <nom_fichier>
Enregistre la sortie dans un fichier au lieu de l'écrire sur stdout. Le format par défaut utilisé lors de l'enregistrement est le format de fichier de session sigrok. Ceci peut être modifié avec l'option --output-format.

Exemple d'enregistrement de données au format de session sigrok :

$ sigrok-cli [...] -o exemple.sr

-O, --output-format <format>
Définit le format de sortie à utiliser. Utilisez l'option -L (--list-supported) pour voir la liste des formats de sortie disponibles.

Le nom du format peut éventuellement être suivi d'une liste d'options séparées par des deux-points, où chaque option prend la forme clé=valeur.

Par exemple, les formats bits ou hex, pour un affichage binaire ASCII ou hexadécimal ASCII, peuvent prendre une option "width", spécifiant le nombre d'échantillons (en bits) à afficher par ligne. Ainsi -O hex:width=128 affichera 128 bits par ligne, en hexadécimal :


0:ffff ffff ffff ffff ffff ffff ffff ffff
1:ff00 ff00 ff00 ff00 ff00 ff00 ff00 ff00

Les lignes commencent toujours par le numéro du canal (ou le nom, s'il est défini), suivi d'un deux-points. Si aucun format n'est spécifié, il est par défaut bits:width=64, comme ceci :


0:11111111 11111111 11111111 11111111 [...]
1:11111111 00000000 11111111 00000000 [...]

Exemple d'enregistrement de données au format CSV avec des options :

$ sigrok-cli [...] -o exemple.csv -O csv:dedup:header=false

Notez que les options booléennes sont true lorsqu'aucune valeur n'est spécifiée.

-C, --channels <liste_canaux>
Une liste de canaux séparés par des virgules à utiliser dans la session.

Notez que sigrok nomme toujours les canaux selon la façon dont ils sont affichés sur le boîtier du matériel. Si votre analyseur logique numérote les canaux de 0 à 15, c'est ainsi que vous devez les spécifier avec cette option. Les canaux d'un oscilloscope seraient généralement désignés par "CH1", "CH2", etc. Utilisez l'option --show pour voir la liste des noms de canaux pour votre périphérique.

Par défaut, tous les canaux disponibles sur un périphérique sont utilisés. Vous pouvez nommer un canal comme ceci : 1=CLK. Une plage de canaux peut également être g

Exemple :

$ sigrok-cli --driver fx2lafw --samples 100

La liste séparée par des virgules est traitée de gauche à droite, c'est-à-dire que les éléments situés plus loin à droite remplacent les éléments précédents. Par exemple, 1=CS,CS=MISO nommera le canal 1 en tant que MISO.

-g, --channel-group <groupe de canaux>
Spécifiez le groupe de canaux sur lequel opérer. Certains appareils organisent les canaux en groupes dont les paramètres ne peuvent être modifiés qu'en groupe. La liste des groupes de canaux, s'il y en a, est affichée avec la commande --show.

Exemples :

$ sigrok-cli -g CH1 [...]

$ sigrok-cli -d demo -g Logic -c pattern=graycode [...]

Les spécifications de groupe de canaux dans les options --get ou --config priment sur les noms de groupe de canaux dans --channel-group, afin qu'une seule invocation de sigrok-cli puisse gérer la requête ou la manipulation de plusieurs options d'appareil situées dans différents groupes de canaux.

-t, --triggers <liste_de_déclencheurs>
Une liste de déclencheurs séparée par des virgules, sous la forme <canal>=<déclencheur>. Vous pouvez utiliser le nom ou le numéro du canal, et le déclencheur lui-même est une série de caractères :

0 ou 1 : Une valeur basse ou haute sur la broche.
r ou f : Une valeur montante ou descendante sur la broche. Un r correspond effectivement à 01.
e : Tout type de changement sur une broche (un front montant ou descendant).

Tous les appareils ne prennent pas en charge tous ces types de déclencheurs. Utilisez la commande --show pour voir quels déclencheurs votre appareil prend en charge.

-w, --wait-trigger
Ne pas afficher de données d'échantillonnage (même si elles sont effectivement reçues du matériel) avant que la condition de déclenchement ne soit remplie. En d'autres termes, ne pas afficher de données de pré-déclenchement. Cette option est utile si vous ne vous souciez pas des données qui ont précédé le déclencheur (mais le matériel fournit ces données à sigrok néanmoins).
-P, --protocol-decoders <liste>
Cette option permet à l'utilisateur de spécifier une liste de décodeurs de protocole séparée par des virgules à utiliser dans cette session. Les décodeurs sont spécifiés par leur identifiant, tel qu'affiché dans la sortie de -L (--list-supported).

Exemple :


$ sigrok-cli -i <fichier.sr> -P i2c

Chaque décodeur de protocole peut éventuellement être suivi d'une liste d'options séparées par des deux-points, où chaque option prend la forme clé=valeur.

Exemple :


$ sigrok-cli -i <fichier.sr>
-P uart:baudrate=115200:parity_type=odd

La liste des options prises en charge dépend entièrement du décodeur de protocole. Chaque décodeur de protocole a des options différentes qu'il prend en charge.

Toutes les « options » spécifiées pour un décodeur de protocole qui ne sont pas réellement des options prises en charge seront interprétées comme des affectations de noms ou de numéros de canaux.

Exemple :


$ sigrok-cli -i <fichier.sr>
-P spi:wordsize=9:miso=1:mosi=5:clk=3:cs=0

Dans cet exemple, wordsize est une option prise en charge par le décodeur de protocole spi. De plus, l'utilisateur indique à sigrok de décoder le protocole SPI en utilisant le canal 1 comme signal MISO pour SPI, le canal 5 comme MOSI, le canal 3 comme CLK et le canal 0 comme signal CS#.

Notez que l'application sigrok-cli ne prend pas en charge la « correspondance de noms ». Au lieu de cela, il est supposé que les traces dans le flux d'entrée correspondent à l'ordre des signaux d'entrée du décodeur, ou que les utilisateurs spécifient explicitement le mappage du canal d'entrée au signal du décodeur.

Lorsque plusieurs décodeurs sont spécifiés dans la même option -P, ils seront empilés les uns sur les autres dans l'ordre spécifié.

Exemple :


$ sigrok-cli -i <fichier.sr> -P i2c,eeprom24xx
$ sigrok-cli -i <fichier.sr> -P uart:baudrate=31250,midi

Lorsque plusieurs options -P sont spécifiées, chacune d'elles crée une pile de décodeurs qui s'exécute en parallèle avec d'autres piles de décodeurs.

Exemple :


$ sigrok-cli -i <fichier.sr> -Puart:tx=D0:rx=D1 -P timing:data=D2

-A, --protocol-decoder-annotations <annotations>
Par défaut, toutes les annotations de tous les décodeurs de protocole sont affichées. Avec cette option, les annotations d'un décodeur spécifique peuvent être sélectionnées pour l'affichage, en spécifiant l'identifiant du décodeur :


$ sigrok-cli -i <fichier.sr> -P i2c,i2cfilter,edid -A i2c

Si un décodeur de protocole possède plusieurs classes d'annotations, vous pouvez également spécifier celle à afficher en indiquant sa courte description comme suit :


$ sigrok-cli -i <fichier.sr> -P i2c,i2cfilter,edid
-A i2c=data-read

Sélectionnez plusieurs classes d'annotations en les séparant par deux-points :


$ sigrok-cli -i <fichier.sr> -P i2c,i2cfilter,edid
-A i2c=data-read:data-write

Les noms des lignes d'annotation seront résolus en leur liste respective de classes. Les noms de lignes et de classes peuvent être utilisés en combinaison. Lorsque les noms sont ambigus, les noms de classes priment.


$ sigrok-cli -i <fichier.sr> -P i2c
-A i2c=addr-data:warnings

Vous pouvez également sélectionner plusieurs décodeurs de protocole, avec éventuellement des classes d'annotations sélectionnées pour chacun, en les séparant par des virgules :


$ sigrok-cli -i <fichier.sr> -P i2c,i2cfilter,edid
-A i2c=data-read:data-write,edid

-M, --protocol-decoder-meta <nom_pd>
Lorsqu'elle est fournie, affiche la sortie méta du décodeur de protocole au lieu des annotations. L'argument est le nom du décodeur dont la sortie méta doit être affichée.


$ sigrok-cli -i <fichier.sr> -M i2c

Tous les décodeurs ne génèrent pas de sortie méta.

-B, --protocol-decoder-binary <spécification_binaire>
Lorsqu'elle est fournie, les données « brutes » du décodeur de divers types sont écrites sur la sortie standard au lieu des annotations (cela pourrait être des octets UART/SPI bruts, ou des fichiers WAV, PCAP, PNG, ou autre ; cela dépend entièrement du décodeur et des types de sortie binaire qui ont un sens pour ce décodeur).

Aucune autre information n'est imprimée sur la sortie standard, elle est donc adaptée au transfert vers d'autres programmes ou à la sauvegarde dans un fichier.

Les décodeurs de protocole qui prennent en charge la sortie binaire publient une liste de classes binaires. Par exemple, le décodeur UART pourrait avoir « TX » et « RX ». Pour sélectionner TX pour la sortie, l'argument de cette option serait :


$ sigrok-cli -i <fichier.sr> -Buart=tx

Si seul le décodeur de protocole est spécifié, sans classe binaire, toutes les classes sont écrites sur la sortie standard :


$ sigrok-cli -i <fichier.sr> -Buart

(ceci n'est utile que dans de rares cas, généralement vous spécifierez une classe binaire particulière qui vous intéresse)

Tous les décodeurs ne génèrent pas de sortie binaire.

--protocol-decoder-samplenum
Lorsqu'elle est fournie, les annotations du décodeur incluront également les numéros d'échantillons. Ceci permet aux consommateurs de recevoir des informations de chronométrage lisibles par machine.
-l, --loglevel <niveau>
Définissez le niveau de journalisation de libsigrok et libsigrokdecode. À l'heure actuelle, sigrok-cli ne prend pas en charge la définition indépendante des deux niveaux de journalisation. Plus le nombre est élevé, plus la sortie de débogage sera imprimée. Les niveaux de journalisation valides sont :

0 Aucun
1 Erreur
2 Avertissements
3 Informationnel
4 Débogage
5 Bavard

--show

Affiche des informations sur l'option sélectionnée. Par exemple, pour voir les options d'un appareil fx2lafw connecté :


$ sigrok-cli --driver fx2lafw --show

Pour obtenir correctement les options de l'appareil pour votre matériel, certains pilotes peuvent nécessiter la spécification d'un port série :


$ sigrok-cli --driver ols:conn=/dev/ttyACM0 --show

Cela fonctionne également pour les décodeurs de protocole, les modules d'entrée et les modules de sortie :


$ sigrok-cli --protocol-decoders i2c --show
$ sigrok-cli --input-format csv --show
$ sigrok-cli --output-format bits --show

Cela fonctionne également pour les fichiers d'entrée, y compris les spécifications optionnelles du format d'entrée :


$ sigrok-cli --input-file <fichier.sr> --show
$ sigrok-cli --input-file <fichier.vcd> --input-format vcd --show

--scan
Numérise les appareils qui peuvent être détectés automatiquement.

Exemple :


$ sigrok-cli --scan
Les appareils suivants ont été trouvés :
demo - Appareil de démonstration avec 12 canaux : D0 D1 D2 D3 D4 D5 D6 D7 A0 A1 A2 A3
fx2lafw:conn=3.26 - CWAV USBee SX avec 8 canaux : 0 1 2 3 4 5 6 7

Cependant, tous les appareils ne sont pas auto-détectables (par exemple, ceux basés sur port série). Pour ceux-là, vous devrez fournir une option conn, voir ci-dessus.


$ sigrok-cli --driver digitek-dt4000zc:conn=/dev/ttyUSB0 --scan
Les appareils suivants ont été trouvés :
Digitek DT4000ZC avec 1 canal : P1

--time <ms>
Échantillon for <ms> millisecondes, puis quitter.

Vous pouvez éventuellement faire suivre le nombre de s pour spécifier la durée de l'échantillonnage en secondes.

Par exemple, --time 2s échantillonnera pendant deux secondes.

--samples <numsamples>
Acquérir <numsamples> échantillons, puis quitter.

Vous pouvez éventuellement faire suivre le nombre de k, m, ou g pour spécifier le nombre d'échantillons en kiléchantillons, mégéchantillons, ou gigéchantillons, respectivement.

Par exemple, --samples 3m acquerra 3000000 échantillons.

--frames <numframes>
Acquérir <numframes> trames, puis quitter.
--continuous
Échantillonner en continu jusqu'à l'arrêt. Tous les périphériques ne prennent pas en charge cette option.
--get <variable>
Récupérer la valeur de <variable> du périphérique spécifié et l'afficher. Plusieurs noms de variables peuvent être spécifiés et séparés par deux-points. La liste des noms de variables peut éventuellement être précédée de channel_group=<name>, ce qui remplacera la spécification --channel-group. Plusieurs occurrences de --get sont prises en charge dans une seule invocation de sigrok-cli.


$ sigrok-cli -d demo --get samplerate:averaging --get channel_group=Logic:pattern

--set
Définir une ou plusieurs variables spécifiées avec l'option --config, sans effectuer d'acquisition.

EXEMPLES

Pour obtenir exactement 100 échantillons de l'analyseur logique connecté prenant en charge fx2lafw, exécutez la commande suivante :

sigrok-cli --driver fx2lafw --samples 100
Si vous souhaitez échantillonner des données pendant 3 secondes (3000 ms), utilisez :
sigrok-cli --driver fx2lafw --time 3000
Alternativement, vous pouvez également utiliser :
sigrok-cli --driver fx2lafw --time 3s
Pour capturer des données des 4 premiers canaux en utilisant l'Openbench Logic Sniffer pendant 100 ms à 10 MHz en commençant par la condition de déclenchement
0:high, 1:rising, 2:low, 3:high, utilisez :
sigrok-cli --driver ols:conn=/dev/ttyACM0 --config samplerate=10m \
--output-format bits --channels 0-3 --wait-trigger \
--triggers 0=1,1=r,2=0,3=1 --time 100
Pour activer la journalisation interne sur un périphérique de la série Lascar EL-USB :
sigrok-cli --driver lascar-el-usb:conn=10c4.0002 \
--config datalog=on --set

STATUT DE SORTIE

sigrok-cli se termine avec 0 en cas de succès, 1 dans la plupart des cas d'échec.
