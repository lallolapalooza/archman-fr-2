sigaltstack(2) Manuel des appels système sigaltstack(2)

NOM

sigaltstack - définir et/ou obtenir le contexte de la pile de signaux

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>
int sigaltstack(const stack_t *_Nullable restrict ss,
                stack_t *_Nullable restrict old_ss);
Conditions de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

sigaltstack():

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19 : */ _BSD_SOURCE

DESCRIPTION

sigaltstack() permet à un thread de définir une nouvelle pile de signaux alternative et/ou de récupérer l'état d'une pile de signaux alternative existante. Une pile de signaux alternative est utilisée lors de l'exécution d'un gestionnaire de signaux si l'établissement de ce gestionnaire (voir sigaction(2)) l'a demandé.

La séquence normale d'événements pour utiliser une pile de signaux alternative est la suivante :

1.
Allouer une zone mémoire pour être utilisée comme pile de signaux alternative.
2.
Utiliser sigaltstack() pour informer le système de l'existence et de l'emplacement de la pile de signaux alternative.
3.
Lors de l'établissement d'un gestionnaire de signaux à l'aide de sigaction(2), informer le système que le gestionnaire de signaux doit être exécuté sur la pile de signaux alternative en spécifiant le drapeau (flag) SA_ONSTACK.

L'argument ss est utilisé pour spécifier une nouvelle pile de signaux alternative, tandis que l'argument old_ss est utilisé pour récupérer des informations sur la pile de signaux actuellement établie. Si l'on ne souhaite effectuer que l'une de ces tâches, l'autre argument peut être spécifié comme NULL.

Le type stack_t utilisé pour typer les arguments de cette fonction est défini comme suit :


typedef struct {
    void  *ss_sp;     /* Adresse de base de la pile */
    int    ss_flags;  /* Drapeaux */
    size_t ss_size;   /* Nombre d'octets dans la pile */
} stack_t;

Pour établir une nouvelle pile de signaux alternative, les champs de cette structure sont définis comme suit :

ss.ss_flags
Ce champ contient soit 0, soit le drapeau suivant :
SS_AUTODISARM (depuis Linux 4.7)
Efface les paramètres de la pile de signaux alternative à l'entrée du gestionnaire de signaux. Lorsque le gestionnaire de signaux retourne, les paramètres précédents de la pile de signaux alternative sont restaurés.
Ce drapeau a été ajouté pour rendre sûr le passage hors de la pile du gestionnaire de signaux avec swapcontext(3). Sans ce drapeau, un signal traité ultérieurement corrompra l'état du gestionnaire de signaux dont le contexte a été déplacé. Sur les noyaux où ce drapeau n'est pas supporté, sigaltstack() échoue avec l'erreur EINVAL lorsque ce drapeau est fourni.
ss.ss_sp
Ce champ spécifie l'adresse de départ de la pile. Lorsqu'un gestionnaire de signaux est invoqué sur la pile alternative, le noyau aligne automatiquement l'adresse donnée dans ss.ss_sp sur une limite d'adresse appropriée pour l'architecture matérielle sous-jacente.
ss.ss_size
Ce champ spécifie la taille de la pile. La constante SIGSTKSZ est définie pour être suffisamment grande pour couvrir les exigences de taille habituelles pour une pile de signaux alternative, et la constante MINSIGSTKSZ définit la taille minimale requise pour exécuter un gestionnaire de signaux.

Pour désactiver une pile existante, spécifiez ss.ss_flags comme SS_DISABLE. Dans ce cas, le noyau ignore tous les autres drapeaux dans ss.ss_flags et les champs restants dans ss.

Si old_ss n'est pas NULL, alors il est utilisé pour retourner des informations sur la pile de signaux alternative qui était en vigueur avant l'appel à sigaltstack(). Les champs old_ss.ss_sp et old_ss.ss_size retournent l'adresse de départ et la taille de cette pile. Les old_ss.ss_flags peuvent retourner l'une des valeurs suivantes :

SS_ONSTACK
Le thread est actuellement en cours d'exécution sur la pile de signaux alternative. (Notez qu'il n'est pas possible de changer la pile de signaux alternative si le thread est actuellement en cours d'exécution dessus.)
SS_DISABLE
La pile de signaux alternative est actuellement désactivée.
Alternativement, cette valeur est retournée si le thread est actuellement en cours d'exécution sur une pile de signaux alternative qui a été établie en utilisant le drapeau SS_AUTODISARM. Dans ce cas, il est sûr de passer hors de la pile du gestionnaire de signaux avec swapcontext(3). Il est également possible de configurer une autre pile de signaux alternative en utilisant un autre appel à sigaltstack().
SS_AUTODISARM
La pile de signaux alternative a été marquée pour être auto-désactivée comme décrit ci-dessus.

En spécifiant ss comme NULL, et old_ss comme une valeur non-NULL, on peut obtenir les paramètres actuels de la pile de signaux alternative sans les modifier.

VALEUR DE RETOUR

sigaltstack() retourne 0 en cas de succès, ou -1 en cas d'échec avec errno défini pour indiquer l'erreur.

ERREURS

EFAULT
Soit ss, soit old_ss n'est pas NULL et pointe vers une zone en dehors de l'espace d'adressage du processus.
EINVAL
ss n'est pas NULL et le champ ss_flags contient un drapeau invalide.
ENOMEM
La taille spécifiée pour la nouvelle pile de signaux alternative ss.ss_size était inférieure à MINSIGSTKSZ.
EPERM
Une tentative a été faite pour modifier la pile de signaux alternative alors qu'elle était active (c'est-à-dire que le thread était déjà en cours d'exécution sur la pile de signaux alternative actuelle).

NORMES

POSIX.1-2024.

SS_AUTODISARM est une extension Linux.

HISTORIQUE

POSIX.1-2001, SUSv2, SVr4.

NOTES

L'utilisation la plus courante d'une pile de signaux alternative est de gérer le signal SIGSEGV qui est généré si l'espace disponible pour la pile standard est épuisé : dans ce cas, un gestionnaire de signaux pour SIGSEGV ne peut pas être invoqué sur la pile standard ; si nous voulons le gérer, nous devons utiliser une pile de signaux alternative.

L'établissement d'une pile de signaux alternative est utile si un thread s'attend à épuiser sa pile standard. Cela peut se produire, par exemple, parce que la pile devient si grande qu'elle rencontre le tas qui croît vers le haut, ou qu'elle atteint une limite établie par un appel à setrlimit(RLIMIT_STACK, &rlim). Si la pile standard est épuisée, le noyau envoie un signal SIGSEGV au thread. Dans ces circonstances, la seule façon d'intercepter ce signal est sur une pile de signaux alternative.

Sur la plupart des architectures matérielles prises en charge par Linux, les piles grandissent vers le bas. sigaltstack() tient automatiquement compte de la direction de croissance de la pile.

Les fonctions appelées depuis un gestionnaire de signaux exécutant sur une pile de signaux alternative utiliseront également la pile de signaux alternative. (Cela s'applique également à tous les gestionnaires invoqués pour d'autres signaux pendant que le thread exécute sur la pile de signaux alternative.) Contrairement à la pile standard, le système n'étend pas automatiquement la pile de signaux alternative. Le dépassement de la taille allouée de la pile de signaux alternative entraînera des résultats imprévisibles.

Un appel réussi à execve(2) supprime toute pile de signaux alternative existante. Un processus enfant créé via fork(2) hérite d'une copie des paramètres de pile de signaux alternative de son parent. Il en va de même pour un processus enfant créé à l'aide de clone(2), à moins que les drapeaux de clone n'incluent CLONE_VM et n'incluent pas CLONE_VFORK, auquel cas toute pile de signaux alternative qui a été établie dans le parent est désactivée dans le processus enfant.

sigaltstack() remplace l'ancien appel sigstack(). Pour des raisons de compatibilité ascendante, glibc fournit également sigstack(). Toutes les nouvelles applications doivent être écrites en utilisant sigaltstack().

History

4.2BSD avait un appel système sigstack(). Il utilisait une struct légèrement différente, et avait le désavantage majeur que l'appelant devait connaître la direction de croissance de la pile.

BUGS

Dans Linux 2.2 et versions antérieures, le seul drapeau qui pouvait être spécifié dans ss.sa_flags était SS_DISABLE. À l'approche de la sortie du noyau Linux 2.4, une modification a été apportée pour permettre à sigaltstack() d'autoriser ss.ss_flags==SS_ONSTACK avec la même signification que ss.ss_flags==0 (c'est-à-dire que l'inclusion de SS_ONSTACK dans ss.ss_flags est une opération nulle). Sur d'autres implémentations, et selon POSIX.1, SS_ONSTACK apparaît uniquement comme un drapeau rapporté dans old_ss.ss_flags. Sur Linux, il n'est jamais nécessaire de spécifier SS_ONSTACK dans ss.ss_flags, et le faire devrait être évité pour des raisons de portabilité : divers autres systèmes renvoient une erreur si SS_ONSTACK est spécifié dans ss.ss_flags.

EXEMPLES

Le segment de code suivant démontre l'utilisation de sigaltstack() (et sigaction(2)) pour installer une pile de signaux alternative qui est utilisée par un gestionnaire pour le signal SIGSEGV :


stack_t ss;
ss.ss_sp = malloc(SIGSTKSZ);
if (ss.ss_sp == NULL) {
    perror("malloc");
    exit(EXIT_FAILURE);
}
ss.ss_size = SIGSTKSZ;
ss.ss_flags = 0;
if (sigaltstack(&ss, NULL) == -1) {
    perror("sigaltstack");
    exit(EXIT_FAILURE);
}
sa.sa_flags = SA_ONSTACK;
sa.sa_handler = handler();      /* Adresse d'un gestionnaire de signaux */
sigemptyset(&sa.sa_mask);
if (sigaction(SIGSEGV, &sa, NULL) == -1) {
    perror("sigaction");
    exit(EXIT_FAILURE);
}
