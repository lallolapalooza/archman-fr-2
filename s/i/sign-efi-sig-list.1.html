SIGN-EFI-SIG-LIST(1) Commandes utilisateur SIGN-EFI-SIG-LIST(1)

NOM

sign-efi-sig-list - outil de signature pour les variables sécurisées en tant que listes de signatures EFI

SYNTAXE

sign-efi-sig-list [-r] [-m] [-a] [-g <guid>] [-o] [-t <horodatage>] [-i <fichier_entree>] [-c <fichier_crt>] [-k <fichier_cle>] [-e <moteur>] <var> <fichier_liste_sig_efi> <fichier_sortie>

DESCRIPTION

Produit un fichier de sortie avec un en-tête d'authentification pour une mise à jour directe vers une variable sécurisée. Cette sortie peut être signée par les clés habituelles directement ou peut être divisée pour une signature externe en utilisant les options -o et -i.

OPTIONS

-r
le certificat est rsa2048 plutôt que x509 [NON IMPLÉMENTÉ]
-m
Utiliser un compteur monotonique au lieu d'un horodatage [NON IMPLÉMENTÉ]
-a
Prépare la variable pour APPEND_WRITE plutôt que pour remplacement
-o
Ne pas signer, mais produire un fichier du paquet exact à signer
-t <horodatage>
Utilise <horodatage> comme horodatage de la mise à jour de variable temporisée. S'il n'est pas présent, l'horodatage sera pris à partir de l'heure système. Notez que vous devez utiliser cette option lors de la signature détachée, sinon la signature sera incorrecte en raison d'incohérences d'horodatage.
-i <fichier_entree>
Prendre une signature détachée (au format PEM) du paquet produit par -o et compléter la création de la mise à jour
-g <guid>
Utilise <guid> comme GUID du propriétaire de la signature
-c <crt>
<crt> est le fichier contenant le certificat de signature au format PEM
-k <cle>
<cle> est le fichier contenant la clé pour <crt> au format PEM
-e <moteur>
Utilise le moteur openssl <moteur> pour la clé privée

EXEMPLES

Pour signer une simple mise à jour d'ajout à db, qui a été préparée en tant que liste de signatures EFI dans DB.esl, et produire le résultat avec l'en-tête d'authentification dans DB.auth

sign-efi-sig-list -a -c KEK.crt -k KEK.key db DB.esl DB.auth

Pour effectuer une signature détachée de la même manière

sign-efi-sig-list -a -t 'Jul 21 09:39:37 BST 2012' -o db DB.esl DB.forsig

Maintenant, signer le fichier DB.forsig de la manière standard openssl. Notez que les normes exigent sha256 comme algorithme de signature

openssl smime -sign -binary -in DB.forsig -out DB.signed -signer KEK.crt -inkey KEK.key -outform DER -md sha256

Ce qui produit une signature PKCS7 détachée dans DB.signed. Transmettez maintenant cela au programme, en n'oubliant pas de conserver le même horodatage (et le drapeau -a) :

sign-efi-sig-list -a -i DB.signed -t 'Jul 21 09:39:37 BST 2012' db DB.auth

Pour supprimer une clé, il suffit de signer un fichier de liste de signatures EFI vide, donc pour produire une mise à jour de variable qui supprimera la PK :

> null.esl

Et ensuite la signer de manière standard (doit ne pas être une mise à jour par ajout) :

sign-efi-sig-list -c PK.crt -k PK.key PK null.esl PK.auth

Une fois que vous avez transmis le fichier .auth à la plateforme UEFI, vous pouvez utiliser le programme UpdateVars.efi pour l'appliquer

UpdateVars [-a] db DB.auth

Où le drapeau -a doit être présent si le fichier DB.auth a été créé comme une mise à jour par ajout et absent s'il remplace la variable.

VOIR AUSSI
