NOM

apptainer-run - Exécute la commande par défaut définie par l'utilisateur dans un conteneur

SYNOPIS

apptainer run [options de lancement...] [arguments...]

DESCRIPTION

Cette commande lancera un conteneur Apptainer et exécutera un script de lancement
s'il est défini pour ce conteneur. Le script de lancement est un fichier de métadonnées dans
le conteneur qui contient des commandes shell. Si le fichier est présent (et
exécutable), alors cette commande exécutera automatiquement ce fichier dans le conteneur. Tous les arguments suivant le nom du conteneur seront passés
directement au script de lancement.

apptainer run accepte les formats de conteneurs suivants :

*.sif Format d'image Singularity (SIF). Natif à Singularity
(3.0+) et Apptainer (v1.0.0+)

*.sqsh Format SquashFS. Natif à Singularity 2.4+

*.img Format ext3. Natif aux versions de Singularity < 2.4.

répertoire/ format sandbox. Répertoire contenant un système de fichiers racine valide
et éventuellement des métadonnées Apptainer.

instance://* Une instance locale en cours d'exécution d'un conteneur. (Voir le groupe de commandes instance
.)

library://* Un conteneur SIF hébergé sur une Bibliothèque (aucune par défaut)

docker://* Un conteneur Docker/OCI hébergé sur Docker Hub ou un autre
registre OCI.

shub://* Un conteneur hébergé sur Singularity Hub.

oras://* Un conteneur SIF hébergé sur un registre OCI qui prend en charge
la spécification OCI Registry As Storage (ORAS).

OPTIONS

--add-caps="" une liste de capacités séparées par des virgules à ajouter

--allow-setuid[=false] autoriser les binaires setuid dans le conteneur (root uniquement)

--app="" définir une application à exécuter dans un conteneur

--apply-cgroups="" appliquer les cgroups à partir d'un fichier pour les processus du conteneur (root uniquement)

--authfile="" fichier d'authentification de type Docker à utiliser pour écrire/lire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de liaison par l'utilisateur. La spécification a le format src[:dest[:opts]], où src et dest sont des chemins extérieurs et intérieurs. Si dest n'est pas donné, il est égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, qui est la valeur par défaut). Plusieurs chemins de liaison peuvent être donnés sous forme de liste séparée par des virgules.

--blkio-weight=0 poids relatif d'E/S de bloc dans la plage 10-1000, 0 pour désactiver

--blkio-weight-device=[] poids relatif d'E/S de bloc spécifique au périphérique

-e, --cleanenv[=false] nettoyer l'environnement avant d'exécuter le conteneur

--compat[=false] appliquer les paramètres pour une compatibilité OCI/Docker accrue. Déduit --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] utiliser un /dev minimal et vider d'autres répertoires (par exemple /tmp et $HOME) au lieu de partager les systèmes de fichiers de votre hôte

-C, --containall[=false] isoler non seulement les systèmes de fichiers, mais aussi les PID, IPC et l'environnement

--cpu-shares=-1 parts CPU pour le conteneur

--cpus="" nombre de CPU disponibles pour le conteneur

--cpuset-cpus="" liste des CPU hôtes disponibles pour le conteneur

--cpuset-mems="" liste des nœuds mémoire hôtes disponibles pour le conteneur

--cwd="" répertoire de travail initial pour le processus payload dans le conteneur (synonyme de --pwd)

--disable-cache[=false] ne pas utiliser ou créer de cache

--dns="" liste de serveurs DNS séparés par des virgules à ajouter dans resolv.conf

--docker-host="" spécifier un hôte de démon Docker personnalisé

--docker-login[=false] se connecter interactivement à un Dépôt Docker

--drop-caps="" une liste de capacités séparées par des virgules à abandonner

--env=[] passer une variable d'environnement au processus contenu

--env-file=[] passer des variables d'environnement d'un fichier au processus contenu

-f, --fakeroot[=false] exécuter le conteneur avec l'apparence d'une exécution en tant que root

--fusemount=[] une spécification de montage de système de fichiers FUSE de la forme : 'où 'est 'container' ou 'host', spécifiant où le montage sera effectué ('container-daemon' ou 'host-daemon' exécutera le processus FUSE détaché). est le chemin vers l'exécutable FUSE, plus les options pour le montage. est l'emplacement dans le conteneur auquel le montage FUSE sera attaché. Par exemple : 'container:sshfs 10.0.0.1:/ /sshfs'. Implique --pid.

-h, --help[=false] aide pour run

-H, --home="/build" une spécification de répertoire personnel. La spécification peut être un chemin src ou une paire src:dest. src est le chemin source du répertoire personnel à l'extérieur du conteneur et dest remplace le répertoire personnel dans le conteneur.

--hostname="" définir le nom d'hôte du conteneur

-i, --ipc[=false] exécuter le conteneur dans un nouvel espace de noms IPC

--keep-privs[=false] laisser l'utilisateur root conserver les privilèges dans le conteneur (root uniquement)

--memory="" limite de mémoire en octets

--memory-reservation="" limite souple de mémoire en octets

--memory-swap="" limite de swap, utiliser -1 pour swap illimité

--mount=[] une spécification de montage par exemple 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] exécuter le conteneur dans un nouvel espace de noms réseau (met en place une interface réseau bridge par défaut)

--netns-path="" rejoindre l'espace de noms réseau au chemin spécifié (en tant que root, ou si autorisé dans apptainer.conf)

--network="" spécifier le type de réseau souhaité séparé par des virgules, chaque réseau lèvera une interface dédiée à l'intérieur du conteneur

--network-args=[] spécifier les arguments réseau à passer aux plugins CNI

--no-eval[=false] ne pas évaluer shell les variables d'env ou les CMD/ENTRYPOINT/ARGS des conteneurs OCI

--no-home[=false] ne PAS monter le répertoire personnel de l'utilisateur si /home n'est pas le répertoire de travail courant

--no-https[=false] utiliser http au lieu de https pour les URI docker://, oras:// et library:///...

--no-init[=false] ne PAS démarrer le processus shim avec --pid

--no-mount=[] désactiver une ou plusieurs options 'mount xxx' définies dans apptainer.conf et/ou spécifier un chemin de destination absolu pour désactiver une entrée de chemin de liaison, ou 'bind-paths' pour désactiver toutes les entrées de chemins de liaison.

--no-pid[=false] ne pas exécuter le conteneur dans un nouvel espace de noms PID

--no-privs[=false] abandonner tous les privilèges de l'utilisateur root dans le conteneur)

--no-umask[=false] ne pas propager umask dans le conteneur, définir une valeur umask par défaut de 0022

--nv[=false] activer le support Nvidia

--nvccli[=false] utiliser nvidia-container-cli pour la configuration du GPU (expérimental)

--oom-kill-disable[=false] Désactiver le tueur OOM

-o, --overlay=[] utiliser une image overlayFS pour le stockage de données persistant ou comme couche de lecture seule du conteneur

--passphrase[=false] demander une phrase secrète de chiffrement

--pem-path="" entrer un chemin vers une clé RSA au format PEM pour un conteneur chiffré

-p, --pid[=false] exécuter le conteneur dans un nouvel espace de noms PID

--pids-limit=0 limiter le nombre de PIDs du conteneur, utiliser -1 pour illimité

--rocm[=false] activer le support Rocm expérimental

--runscript-timeout="" définir la durée du délai d'attente pour le script de lancement (par défaut 1m)

-S, --scratch=[] inclure un répertoire scratch à l'intérieur du conteneur qui est lié à un répertoire temporaire (utiliser -W pour forcer l'emplacement)

--security=[] activer les fonctionnalités de sécurité (SELinux, Apparmor, Seccomp)

--sharens[=false] partager l'espace de noms et l'image avec d'autres conteneurs lancés depuis le même processus parent

--unsquash[=false] Convertir le fichier SIF en sandbox temporaire avant de l'exécuter

-u, --userns[=false] exécuter le conteneur dans un nouvel espace de noms utilisateur

--uts[=false] exécuter le conteneur dans un nouvel espace de noms UTS

-W, --workdir="" répertoire de travail à utiliser pour /tmp, /var/tmp et $HOME (si -c/--contain a également été utilisé)

-w, --writable[=false] monter le système de fichiers du conteneur en lecture/écriture

=faux] par défaut, tous les conteneurs Apptainer sont disponibles en lecture seule. Cette option rend le système de fichiers accessible en lecture/écriture.

--writable-tmpfs[=faux] rend le système de fichiers accessible en lecture/écriture avec des données non persistantes (uniquement avec prise en charge d'overlay)

EXEMPLE

  # Ici, nous voyons que le script d'exécution affiche "Hello world: "
  $ apptainer exec /tmp/debian.sif cat /apptainer
  #!/bin/sh
  echo "Hello world: "
  # Il s'exécute avec nos entrées lorsque nous exécutons l'image
  $ apptainer run /tmp/debian.sif one two three
  Hello world: one two three
  # Notez que cela fait la même chose
  $ ./tmp/debian.sif one two three
