sigwaitinfo(2) Manuel des appels système sigwaitinfo(2)

NOM

sigwaitinfo, sigtimedwait, rt_sigtimedwait - attendre de manière synchrone des signaux mis en file d'attente

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>
int sigwaitinfo(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info);
int sigtimedwait(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info,
                const struct timespec *restrict timeout);
Conditions requises pour les macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

sigwaitinfo(), sigtimedwait():

    _POSIX_C_SOURCE >= 199309L

DESCRIPTION

sigwaitinfo() suspend l'exécution du thread appelant jusqu'à ce que l'un des signaux dans set soit en attente (Si l'un des signaux dans set est déjà en attente pour le thread appelant, sigwaitinfo() retournera immédiatement.)

sigwaitinfo() retire le signal de l'ensemble des signaux en attente et retourne le numéro du signal comme résultat de sa fonction. Si l'argument info n'est pas NULL, alors le tampon auquel il pointe est utilisé pour retourner une structure de type siginfo_t (voir sigaction(2)) contenant des informations sur le signal.

Si plusieurs signaux dans set sont en attente pour l'appelant, le signal qui est récupéré par sigwaitinfo() est déterminé selon les règles d'ordonnancement habituelles ; voir signal(7) pour plus de détails.

sigtimedwait() fonctionne exactement de la même manière que sigwaitinfo() à ceci près qu'il dispose d'un argument supplémentaire, timeout, qui spécifie l'intervalle pendant lequel le thread est suspendu en attendant un signal. (Cet intervalle sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle peut dépasser légèrement.) Cet argument est une structure timespec(3).

Si les deux champs de cette structure sont spécifiés comme 0, une interrogation est effectuée : sigtimedwait() retourne immédiatement, soit avec des informations sur un signal qui était en attente pour l'appelant, soit avec une erreur si aucun des signaux dans set n'était en attente.

VALEUR DE RETOUR

En cas de succès, sigwaitinfo() et sigtimedwait() retournent un numéro de signal (c'est-à-dire une valeur supérieure à zéro). En cas d'échec, les deux appels retournent -1, avec errno défini pour indiquer l'erreur.

ERREURS

EAGAIN
Aucun signal dans set n'est devenu en attente pendant la période de timeout spécifiée à sigtimedwait().
EINTR
L'attente a été interrompue par un gestionnaire de signaux ; voir signal(7). (Ce gestionnaire était pour un signal autre que ceux de set.)
EINVAL
timeout était invalide.

VERSIONS

Différences bibliothèque C/noyau

Sous Linux, sigwaitinfo() est une fonction de bibliothèque implémentée au-dessus de sigtimedwait().

Les fonctions enveloppes glibc pour sigwaitinfo() et sigtimedwait() ignorent silencieusement les tentatives d'attente des deux signaux temps réel utilisés en interne par l'implémentation de threads NPTL. Voir nptl(7) pour les détails.

L'appel système Linux d'origine s'appelait sigtimedwait(). Cependant, avec l'ajout des signaux temps réel dans Linux 2.2, le type sigset_t de taille fixe et 32 bits supporté par cet appel système n'était plus adapté. Par conséquent, un nouvel appel système, rt_sigtimedwait(), a été ajouté pour supporter un type sigset_t agrandi. Le nouvel appel système prend un quatrième argument, size_t sigsetsize, qui spécifie la taille en octets de l'ensemble de signaux dans set. Cet argument doit actuellement avoir la valeur sizeof(sigset_t) (sinon l'erreur EINVAL en résulte). La fonction enveloppe glibc sigtimedwait() masque ces détails, appelant de manière transparente rt_sigtimedwait() lorsque le noyau la fournit.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

NOTES

Dans une utilisation normale, le programme appelant bloque les signaux dans set via un appel préalable à sigprocmask(2) (de sorte que la disposition par défaut pour ces signaux ne se produise pas s'ils deviennent en attente entre des appels successifs à sigwaitinfo() ou sigtimedwait()) et n'établit pas de gestionnaires pour ces signaux. Dans un programme multithreadé, le signal doit être bloqué dans tous les threads, afin d'éviter que le signal ne soit traité selon sa disposition par défaut dans un thread autre que celui qui appelle sigwaitinfo() ou sigtimedwait().

L'ensemble des signaux qui est en attente pour un thread donné est l'union de l'ensemble des signaux qui est en attente spécifiquement pour ce thread et de l'ensemble des signaux qui est en attente pour le processus dans son ensemble (voir signal(7)).

Les tentatives d'attente de SIGKILL et SIGSTOP sont silencieusement ignorées.

Si plusieurs threads d'un processus sont bloqués en attente des mêmes signaux dans sigwaitinfo() ou sigtimedwait(), alors exactement un des threads recevra effectivement le signal s'il devient en attente pour le processus dans son ensemble ; le thread qui reçoit le signal est indéterminé.

sigwaitinfo() ou sigtimedwait() ne peuvent pas être utilisés pour recevoir des signaux qui sont générés de manière synchrone, tels que le signal SIGSEGV résultant de l'accès à une adresse mémoire invalide ou le signal SIGFPE résultant d'une erreur arithmétique. De tels signaux ne peuvent être interceptés que via un gestionnaire de signaux.

POSIX laisse le sens d'une valeur NULL pour l'argument timeout de sigtimedwait() sans spécification, permettant la possibilité que cela ait le même sens qu'un appel à sigwaitinfo(), et c'est effectivement ce qui est fait sous Linux.
