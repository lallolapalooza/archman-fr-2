sigvec(3) Manuel des fonctions de bibliothèque sigvec(3)

NOM

sigvec, sigblock, sigsetmask, siggetmask, sigmask - API de signaux BSD

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>
[[deprecated]] int sigvec(int sig, const struct sigvec *vec,
                          struct sigvec *ovec);
[[deprecated]] int sigmask(int signum);
[[deprecated]] int sigblock(int mask);
[[deprecated]] int sigsetmask(int mask);
[[deprecated]] int siggetmask(void);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

Toutes les fonctions présentées ci-dessus :

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE

DESCRIPTION

Ces fonctions sont fournies dans glibc en tant qu'interface de compatibilité pour les programmes qui utilisent l'API de signaux historique BSD. Cette API est obsolète : les nouvelles applications devraient utiliser l'API de signaux POSIX (sigaction(2), sigprocmask(2), etc.).

La fonction sigvec() définit et/ou récupère la disposition du signal sig (similaire à la fonction POSIX sigaction(2)). Si vec n'est pas NULL, il pointe vers une structure sigvec qui définit la nouvelle disposition pour sig. Si ovec n'est pas NULL, il pointe vers une structure sigvec qui est utilisée pour retourner la disposition précédente de sig. Pour obtenir la disposition actuelle de sig sans la modifier, spécifiez NULL pour vec et un pointeur non NULL pour ovec.

Les dispositions pour SIGKILL et SIGSTOP ne peuvent pas être modifiées.

La structure sigvec a la forme suivante :


struct sigvec {
    void (*sv_handler)(int); /* Disposition du signal */
    int    sv_mask;          /* Signaux à bloquer dans le gestionnaire */
    int    sv_flags;         /* Indicateurs */
};

Le champ sv_handler spécifie la disposition du signal, et est soit : l'adresse d'une fonction de gestion de signal ; SIG_DFL, signifiant que la disposition par défaut s'applique au signal ; ou SIG_IGN, signifiant que le signal est ignoré.

Si sv_handler spécifie l'adresse d'une fonction de gestion de signal, alors sv_mask spécifie un masque de signaux qui doivent être bloqués pendant l'exécution du gestionnaire. De plus, le signal pour lequel le gestionnaire est invoqué est également bloqué. Les tentatives de blocage de SIGKILL ou SIGSTOP sont silencieusement ignorées.

Si sv_handler spécifie l'adresse d'une fonction de gestion de signal, alors le champ sv_flags spécifie des indicateurs contrôlant ce qui se passe lorsque le gestionnaire est appelé. Ce champ peut contenir zéro ou plus des indicateurs suivants :

SV_INTERRUPT
Si le gestionnaire de signal interrompt un appel système bloquant, alors au retour du gestionnaire, l'appel système n'est pas redémarré : il échoue avec l'erreur EINTR. Si cet indicateur n'est pas spécifié, les appels système sont redémarrés par défaut.
SV_RESETHAND
Réinitialise la disposition du signal à la valeur par défaut avant d'appeler le gestionnaire de signal. Si cet indicateur n'est pas spécifié, le gestionnaire reste établi jusqu'à ce qu'il soit explicitement supprimé par un appel ultérieur à sigvec() ou jusqu'à ce que le processus effectue un execve(2).
SV_ONSTACK
Traiter le signal sur la pile de signaux alternative (historiquement établie sous BSD en utilisant la fonction obsolète sigstack() ; le remplacement POSIX est sigaltstack(2)).

La macro sigmask() construit et retourne un « masque de signal » pour signum. Par exemple, nous pouvons initialiser le champ vec.sv_mask passé à sigvec() en utilisant un code tel que le suivant :


vec.sv_mask = sigmask(SIGQUIT) | sigmask(SIGABRT);
            /* Bloquer SIGQUIT et SIGABRT pendant
               l'exécution du gestionnaire */

La fonction sigblock() ajoute les signaux dans mask au masque de signaux du processus (similaire à sigprocmask(SIG_BLOCK) de POSIX), et retourne le masque de signaux précédent du processus. Les tentatives de blocage de SIGKILL ou SIGSTOP sont silencieusement ignorées.

La fonction sigsetmask() définit le masque de signaux du processus à la valeur donnée dans mask (similaire à sigprocmask(SIG_SETMASK) de POSIX), et retourne le masque de signaux précédent du processus.

La fonction siggetmask() retourne le masque de signaux actuel du processus. Cet appel est équivalent à sigblock(0).

VALEUR RENVOYÉE

La fonction sigvec() retourne 0 en cas de succès ; en cas d'erreur, elle retourne -1 et définit la variable errno pour indiquer l'erreur.

Les fonctions sigblock() et sigsetmask() retournent le masque de signaux précédent.

La macro sigmask() retourne le masque de signaux pour signum.

ERREURS

Voir les ERREURS sous sigaction(2) et sigprocmask(2).

NOTES

Sur 4.3BSD, la fonction signal() fournissait des sémantiques fiables (comme lors de l'appel à sigvec() avec vec.sv_mask égal à 0). Sur System V, signal() fournissait des sémantiques non fiables. POSIX.1 laisse ces aspects de signal() non spécifiés. Voir signal(2) pour plus de détails.

Afin d'attendre un signal, BSD et System V fournissaient tous deux une fonction nommée sigpause(3), mais cette fonction a un argument différent sur les deux systèmes. Voir sigpause(3) pour les détails.
