SIEGE(1) Testeur de charge Siege SIEGE(1)

NOM

siege est un utilitaire de test de charge et de benchmarking HTTP/FTP.

SYNTAXE

siege [options]
siege [options] <URL>
siege [options] -g <URL>
siege [options] -f urls.txt

DESCRIPTION

siege est un utilitaire de test de charge et de benchmarking HTTP/FTP multi-thread. Il prend en charge la plupart des fonctionnalités détaillées dans les RFC 2616 (HTTP) et 959 (FTP). Les propriétés peuvent être définies à la fois depuis la ligne de commande et dans un fichier de configuration. Lorsque la même propriété est définie dans les deux emplacements, la ligne de commande a la priorité.

Le fichier de configuration par défaut est $HOME/.siege/siege.conf. Si vous n'avez pas de répertoire $HOME/.siege ni de fichier siege.conf et cookies.txt, siege générera un nouveau répertoire de configuration lorsqu'il s'exécutera. Vous pouvez générer votre répertoire de configuration avec la commande suivante : siege.config

OPTIONS

Syntaxe des options

siege prend en charge les options longues et courtes. Les options courtes ressemblent à ceci :
-c 25
-c25

Les options longues ressemblent à ceci :
--concurrent=25

Valeurs des options

-V, --version
Affiche la version de publication de siege et les informations de copyright.
-h, --help
Imprime un message d'aide décrivant les options de ligne de commande de siege.
-C, --config
Imprime un résumé détaillé de toutes les options actuellement configurées, dont la plupart sont envoyées dans $HOME/.siege/siege.conf
-v, --verbose
Cette directive met siege en mode verbeux, qui est en réalité un réglage par défaut. Cette option de ligne de commande est utile lorsque le fichier de configuration est défini sur 'verbose = false' car elle vous permet de remplacer ce réglage.

Par défaut, la sortie verbeuse de siege est affichée dans un style codé par couleur.
* HTTP 2xx est codé en bleu
* HTTP 3xx est codé en cyan
* HTTP 4xx est codé en magenta
* HTTP 5xx est codé en rouge
* HTTP en cache est codé en noir

NOTE : Vous pouvez désactiver la couleur dans siege.conf comme suit : 'color = off'

-q, --quiet
Cette directive met siege en silence. Elle est principalement utilisée pour les scripts et souvent utilisée conjointement avec -g/--get. Vous pouvez détecter le succès ou l'échec de l'exécution avec son code de sortie. 
siege --quiet -g www.joedog.org
if [ $? -eq 0 ] ; then
  echo "Succès"
else
  echo "Échec"
fi
-g URL, --get=URL
Cette option vous permet de demander une URL et d'observer la transaction d'en-tête. Il existe une directive de fichier de configuration correspondante qui vous permet de définir la méthode de requête pour ces requêtes : gmethod = HEAD|GET 
$ siege -g "https://www.joedog.org/"
HEAD / HTTP/1.0
Host: www.joedog.org
Accept: */*

Connection: close
HTTP/1.1 200 OK
Server: cloudflare-nginx

Content-Type: text/html; charset=UTF-8
Connection: close

Cache-Control: max-age=3, must-revalidate

Vary: Accept-Encoding,Cookie
CF-RAY: 27219407eeff084a-IAD

NOTE : Il est conseillé de mettre l'URL entre guillemets lorsqu'elle est passée à siege depuis la ligne de commande.

-p URL, --print=URL
Cette option est similaire à -g / --get mais elle IMPRIME la page qu'elle a reçue du serveur. 
$ siege -p http://www.joedog.org/

-c NUM, --concurrent=NUM
Cette option vous permet de définir le nombre d'utilisateurs concurrents. Le nombre total d'utilisateurs est techniquement limité par les ressources de votre ordinateur.

Vous ne devriez pas configurer plus d'utilisateurs que votre serveur web n'est configuré pour en gérer. Par exemple, la configuration par défaut d'apache est limitée à 255 threads. Si vous exécutez siege avec -c 1024, alors 769 utilisateurs siege resteront en attente d'un gestionnaire apache.

Pour cette raison, la configuration par défaut de siege est limitée à 255 utilisateurs. Vous pouvez augmenter ce nombre dans siege.conf, mais si vous faites des erreurs, ne vous plaignez pas à nous.

-r NUM, --reps=NUM|once
Cette option indique à chaque utilisateur siege combien de fois il doit s'exécuter. La valeur doit généralement être un nombre supérieur à zéro, mais elle peut être le mot-clé 'once'.

Si --reps=3, alors chaque utilisateur siege s'exécutera trois fois avant de se terminer. Cependant, si --reps=once, alors chaque utilisateur parcourra le fichier urls.txt exactement une fois.

Pour plus d'informations sur le fichier urls.txt, voir l'option -f <file>, --file=<file>

-t NUMm, --time=NUMm
Cette option est similaire à --reps, mais au lieu de spécifier le nombre de fois que chaque utilisateur doit s'exécuter, elle spécifie la durée pendant laquelle chacun doit s'exécuter.

Le format de la valeur est "NUMm", où "NUM" est une durée et le modificateur "m" est S, M ou H pour secondes, minutes et heures. Pour exécuter siege pendant une heure, vous pouvez choisir l'une des combinaisons suivantes : -t3600S, -t60M, -t1H. Le modificateur n'est pas sensible à la casse, mais il ne nécessite pas d'espace entre le nombre et lui-même.

-d NUM, --delay=NUM
Cette option indique à siege combien de temps attendre entre chaque requête de page. La valeur NUM représente le nombre de secondes entre chaque requête. Ce nombre peut être une valeur décimale. En fait, la valeur par défaut est d'une demi-seconde (--delay=0.5).

Le temps entre les requêtes retardées n'est PAS pris en compte dans le temps de transaction. Si deux transactions de 0,1 seconde ont un délai de 2 secondes entre elles, leur temps de transaction moyen est de 0,1 seconde. Il est pris en compte dans le temps total écoulé. Dans ce scénario, le temps écoulé serait de 2,2 secondes.

NOTE : lorsque le parseur est activé (voir : -p/--parser), il n'y a pas de délai entre la page et ses éléments, c'est-à-dire les feuilles de style, les javascripts, etc. Le délai se situe uniquement entre les requêtes de page.

-b, --benchmark
Cette directive indique à siege de passer en mode benchmark. Cela signifie qu'il n'y a pas de délai entre les itérations.
-i, --internet
Cette option met siege dans ce que nous appelons le mode internet. Elle effectue des requêtes à partir du fichier urls.txt (voir : -f <file> / --file=<file>) dans un ordre aléatoire.
-f FILE, --file=FILE
Cette option indique à siege de travailler avec une liste d'URL dans un fichier texte. Les URL sont listées une par ligne. Contrairement aux URL qui sont passées comme argument de ligne de commande, les URL dans ce fichier ne doivent pas être mises entre guillemets.

Le parseur d'URL de siege supporte les commentaires et les variables. Étant donné que siege utilise le signe dollar ($) comme préfixe pour les variables scalaires, vous devriez échapper toute variable que vous souhaitez envoyer au serveur :

https://$(HOST)/siege/jsoner.php POS

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

-c NUMBER, --concurrent=NUMBER
The number of concurrent users to simulate. Defaults to 10.
-r NUMBER, --runs=NUMBER
The number of times to repeat the test. Defaults to the value of concurrency.
-f FILE, --file=FILE
Select a URL list from FILE. Defaults to `urls.txt`.
-t TEXT, --time=TEXT
The timespan to run the test. Siege takes common shorthand like `30S`, `5M`, `2m` etc. Defaults to `1m`.
-s, --no-keep-alive
Disable keep-alive requests.
-b, --benchmark
Run the benchmark without any delays. This is faster, but will not accurately reflect real-world usage.
-i, --internet
Internet mode. This will randomly select a URL from the URL list. Defaults to sequential.
-l, --log
Log the result of every test run to the log file. Defaults to false.
-v, --verbose
Produce verbose output.
-?, --help
Display usage information and exit.
-h, --version
Display the version and exit.
-R FILE, --rc=FILE
This directive allows you to set an alternative resource file. By default, the siegerc file is $HOME/.siege/siege.conf With this directive, you can override the default and use an alternative file.
-L FILE, --log=FILE
The default log file is $prefix/var/log/siege.log. This directive allows you to specify an alternative file for logging.
-m "string", --mark="string"
This option allows you to log a message to the log file before your stats are written there. It is generally used to identify the proceeding run. You could, for example, mark the file with your command-line parameters so it's understood what configuration generated the following data.
-H "header: value", --header="Header: value"
This options allows you to set a custom header in the request. Generally speaking, this header will override an existing header. The Cookie header is a special case. If you set -H "Cookie: value" then siege will send that cookie in addition to the other ones.
-A "string", --agent="string"
This option allows you to override the default user-agent with a custom one. 
siege --agent="JoeDog Jr. in da hizzle"

Will set this header:

User-agent: JoeDog Jr. in da hizzle

Alternatively, you could set the User-agent with the -H/--header option above.

-T "text", --content-type="text"
This is another set header shortcut. You use this option to override the default Content-type request header.
--no-parser
Turn off the HTML parser. When siege downloads a page, it parses it for additional page elements such as style-sheets, javascript and images. It will make additional requests for any elements it finds. With this option enabled, siege will stop after it pulls down the main page.
--no-follow
This directive instructs siege not to follow 3xx redirects.

FORMAT DE URL

siege supporte les formats d'URL RFC 1738 mais il prend soin d'implémenter des raccourcis couramment utilisés pour votre commodité. En plus des formats RFC 1738, siege introduit son propre format d'URL pour indiquer la méthode du protocole.

Une URL RFC 1738 ressemble à ceci :
<scheme>://<username>:<password>@<hostname>:<port>/<path>;<params>?<query>#<frag>

Une URL siege avec un indicateur de méthode ressemble à ceci :
<scheme>://<username>:<password>@<hostname>:<port>/<path> POST <query>

Vous pouvez également poster le contenu d'un fichier en utilisant le caractère de redirection comme ceci :
<scheme>://<username>:<password>@<hostname>:<port>/<path> POST </home/jeff/haha.txt

Voici deux exemples avec l'indicateur de méthode siege :
http://www.joedog.org/ POST haha=papa&dada=mama
ftp://ftp.armstrong.com/ PUT </home/jdfulmer/etc/tests/bbc.jpg

NOTE : Si vous définissez des URL avec des indicateurs de méthode en ligne de commande, vous DEVEZ les mettre entre guillemets, sinon votre shell les traitera comme trois arguments distincts. Si l'URL est dans un fichier urls.txt, vous ne devriez pas la mettre entre guillemets.

Comme mentionné ci-dessus, siege fait de grands efforts pour permettre des raccourcis couramment utilisés auxquels vous êtes habitué dans la plupart des implémentations de navigateurs. Il traite de nombreuses parties de l'URL 1738 comme facultatives. Dans cet exemple, les parties entre crochets sont facultatives :
[scheme://] host.domain.xxx [:port] [/path/file]

Lorsque siege reçoit un nom d'hôte, il construit l'URL avec des hypothèses par défaut. www.joedog.org devient http://www.joedog.org:80/

FICHIER URLS.txt

De la section Syntaxe des options ci-dessus, nous apprenons que siege peut prendre une URL comme argument. siege -c -r2 www.joedog.org demandera la page d'index de JoeDog deux fois. Mais que faire si vous voulez accéder à de grandes parties du site ? siege vous permettra de remplir un fichier avec des URL afin qu'il puisse parcourir une liste.

Le format du fichier est une URL par ligne :
https://www.joedog.org/
https://www.joedog.org/haha/
https://www.joedog.org/haha/ POST homer=simpson&marge=doestoo

Le fichier prend également en charge les commentaires de style UNIX :
# Le commentaire ressemble à ceci
https://www.joedog.org/
https://www.joedog.org/haha/
https://www.joedog.org/haha/ POST homer=simpson&marge=doestoo

Il prend en charge la déclaration et les références de variables de style shell. C'est pratique si vous voulez exécuter le même test sur deux niveaux différents ou deux schémas différents :

SCHEME=https
HOST=bart.joedog.org
$(SCHEME)://$(HOST)/
$(SCHEME)://$(HOST)/haha/
$(SCHEME)://$(HOST)/haha/ POST homer=simpson&marge=doestoo

Vous pouvez informer siege de ce fichier avec l'option -f/--file :
siege -c1 -r50 -f /home/jeff/urls.txt

STATISTIQUES DE PERFORMANCE

Une fois son exécution terminée, siege rassemblera des données de performance de tous ses clients et les résumera après l'exécution. (Vous pouvez également choisir de consigner ces chiffres). La sortie de la ligne de commande est basée sur le script torture.pl de Lincoln Stein :

Transactions:                   2000 hits
Availability:                 100.00 %
Elapsed time:                  58.57 secs
Data transferred:               5.75 MB
Response time:                  0.25 secs
Transaction rate:              34.15 trans/sec
Throughput:                     0.10 MB/sec
Concurrency:                    8.45
Successful transactions:        2000
Failed transactions:               0
Longest transaction:            4.62
Shortest transaction:           0.00
Transactions
    Ce nombre représente le nombre total de requêtes HTTP. Dans cet
    exemple, nous avons exécuté 25 utilisateurs simulés [-c25] et chacun a
    exécuté dix fois [-r10]. Vingt-cinq fois dix égale 250, alors pourquoi le
    total des transactions est-il de 2000 ? C'est parce que siege compte chaque
    requête. Cette exécution incluait une redirection META, une redirection 301
    et la page demandée contenait plusieurs éléments qui ont également été
    téléchargés.
Availability
    C'est le pourcentage de connexions socket traitées avec succès par le
    serveur. C'est le résultat des échecs de socket (y compris les
    timeouts) divisé par la somme de toutes les tentatives de connexion. Ce
    nombre n'inclut pas les erreurs serveur de niveau 400 et 500 qui sont
    enregistrées dans "Failed transactions" décrites ci-dessous.
Elapsed time
    La durée de l'ensemble du test siege. Elle est mesurée à partir du
    moment où l'utilisateur invoque siege jusqu'à ce que le dernier utilisateur
    simulé termine ses transactions. Comme indiqué ci-dessus, le test a pris
    58,57 secondes pour s'achever.
Data transferred
    La somme des données transférées à chaque utilisateur simulé par siege.
    Elle inclut les informations d'en-tête ainsi que le contenu. Parce qu'elle
    inclut les informations d'en-tête, le nombre rapporté par siege sera
    plus grand que le nombre rapporté par le serveur. En mode internet, qui
    accède à des URL aléatoires dans un fichier de configuration, ce
    nombre devrait varier d'une exécution à l'autre.
Response time
    Le temps moyen nécessaire pour répondre aux requêtes de chaque utilisateur
    simulé.
Transaction rate
    Le nombre moyen de transactions que le serveur a pu gérer par seconde, en
    bref : c'est le compte de toutes les transactions divisé par le temps écoulé.
Throughput
    Le nombre moyen d'octets transférés chaque seconde du serveur vers tous les
    utilisateurs simulés.
Concurrency
    C'est le nombre moyen de connexions simultanées. La métrique est calculée comme
    suit : la somme de tous les temps de transaction divisée par le temps écoulé (combien
    de temps siege a fonctionné).
Successful transactions
    Le nombre de fois où le serveur a répondu avec un code de retour < 400.
Failed transactions
    Le nombre de fois où les transactions socket ont échoué, y compris les
    timeouts socket.
Longest transaction
    Le temps le plus long qu'une seule transaction a pris, parmi toutes les
    transactions.
Shortest transaction
    Le temps le plus court qu'une seule transaction a pris, parmi toutes les
    transactions.
