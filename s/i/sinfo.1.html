sinfo(1) Commandes Slurm sinfo(1)

NOM

sinfo - Visualiser les informations sur les nœuds et les partitions Slurm.

SYNTAXE

sinfo [OPTIONS...]

DESCRIPTION

sinfo est utilisé pour visualiser les informations sur les partitions et les nœuds d'un système exécutant Slurm.

OPTIONS

-a, --all
Afficher les informations sur toutes les partitions. Cela entraîne l'affichage d'informations sur les partitions qui sont configurées comme cachées et les partitions qui ne sont pas accessibles au groupe de l'utilisateur.
-M, --clusters=<chaîne>
Clusters auxquels adresser les commandes. Plusieurs noms de clusters peuvent être séparés par des virgules. Une valeur de 'all' interrogera tous les clusters. Notez que le slurmdbd doit être démarré pour que cette option fonctionne correctement, sauf si vous êtes en mode fédération avec FederationParameters=fed_display configuré ou l'option --federation définie. Cette option définit implicitement l'option --local.
-d, --dead
N'afficher que les nœuds qui ont cessé de répondre de manière inattendue. Cela peut ne pas montrer les nœuds en état POWERED_DOWN car ils sont censés être inactifs.
-e, --exact
Si défini, ne pas regrouper les informations des nœuds sur plusieurs nœuds, sauf si leurs configurations à signaler sont identiques. Sinon, le nombre de CPU, la taille de la mémoire et l'espace disque des nœuds seront indiqués avec la valeur minimale suivie d'un '+' pour les nœuds ayant la même partition et le même état (par exemple, "250+").
--federation
Afficher toutes les partitions de la fédération si membre d'une.
-F, --future
Rapporter les nœuds dans l'état FUTURE.
-o, --format=<format_de_sortie>
Spécifier les informations à afficher à l'aide d'une chaîne de format sinfo. Si la commande est exécutée dans un environnement de cluster fédéré et que des informations sur plusieurs clusters doivent être affichées et que l'option -h, --noheader est utilisée, alors le nom du cluster sera affiché avant les formats de sortie par défaut indiqués ci-dessous. Les chaînes de format utilisées de manière transparente par sinfo lors de l'exécution avec diverses options sont :
par défaut
"%#P %.5a %.10l %.6D %.6t %N"
--summarize
"%#P %.5a %.10l %.16F %N"
--long
"%#P %.5a %.10l %.10s %.4r %.8h %.10g %.6D %.11T %.11i %N"
--Node
"%#N %.6D %#P %6t"
--long --Node
"%#N %.6D %#P %.11T %.4c %.8z %.6m %.8d %.6w %.8f %20E"
--list-reasons
"%20E %9u %19H %N"
--long --list-reasons
"%20E %12U %19H %6t %N"

Dans les chaînes de format ci-dessus, l'utilisation de '#' représente la longueur maximale de tout nom de partition ou liste de nœuds à imprimer. Un passage est effectué sur les enregistrements à imprimer pour établir la taille afin d'aligner la sortie sinfo, puis un second passage est effectué sur les enregistrements pour les imprimer. Notez que le caractère littéral '#' lui-même n'est pas une spécification de longueur de champ valide, mais est seulement utilisé pour documenter ce comportement.

Le format de chaque champ est "%[[.]taille]type[suffixe]"

taille
Taille minimale du champ. Si aucune taille n'est spécifiée, la taille nécessaire pour imprimer l'information sera utilisée.
.
Indique que la sortie doit être justifiée à droite et que la taille doit être spécifiée. Par défaut, la sortie est justifiée à gauche.
suffixe
Chaîne arbitraire à ajouter à la fin du champ.

-R, --list-reasons
Liste les raisons pour lesquelles les nœuds sont dans les états down, drained, fail ou failing. Lorsque les nœuds sont dans ces états, Slurm prend en charge l'inclusion d'une chaîne « reason » par un administrateur. Cette option affichera les 20 premiers caractères du champ reason et la liste des nœuds avec cette raison pour tous les nœuds qui sont, par défaut, down, drained, draining ou failing. Cette option peut être utilisée avec d'autres options de filtrage de nœuds (par exemple, -r, -d, -t, -n), cependant, les combinaisons de ces options qui résultent en une liste de nœuds qui ne sont pas down ou drained ou failing ne produiront aucune sortie. -F, --federation
List information about the federated clusters. This option is only available when Slurm is configured with a federated cluster.
-G, --geometry
List information about the node geometry. This includes the number of sockets, cores per socket, and threads per core.
-h, --header
Do not print a header line.
-m, --mtime
List the last modification time for the node's configuration file. This is the same value as the last_mod field in the output of scontrol show node.
--Node
List information about nodes. This option should be used in conjunction with other options such as --format and --sort to specify what information to display about each node.
-o, --state_filter
List nodes that are in the specified state. This option can be used multiple times to specify multiple states. The comparison is case insensitive. Possible values include: allocated, completeting, DOWN, DRAIN, future, idle, maint, mixed, no_respond, reserved, unknown. By default nodes in the specified state are reported whether they are responding or not. The --dead and --responding options may be used to filter nodes by the corresponding flag.
-p, --partition=<partition_name>
List information about the specified partition(s). This option can be used multiple times to specify multiple partitions. If no partition is specified, then all partitions are listed.
-r, --responding
List nodes that are responding. Note that this option is the inverse of the --dead option. It will only report nodes that are responding.
--sinfo
Print a detailed message listing all sinfo options and descriptions.
--sort=<sort_fields>
Specify the order in which records should be reported. This uses the same field specification as the <output_format>. Multiple sorts may be performed by listing multiple sort fields separated by commas. The field specifications may be preceded by "+" or "-" for ascending (default) and descending order respectively. The partition field specification, "P", may be preceded by a "#" to report partitions in the same order that they appear in Slurm's configuration file, slurm.conf. For example, a sort value of "+P,-m" requests that records be printed in order of increasing partition name and within a partition by decreasing memory size. The default value of sort is "#P,-t" (partitions ordered as configured then decreasing node state). If the --Node option is selected, the default sort value is "N" (increasing node name).
-t, --states=<states>
List nodes only having the given state(s). Multiple states may be comma separated and the comparison is case insensitive. If the states are separated by '+', then the nodes must be in all states. The state can be prefixed with '~' which will invert the result of match. Possible values include (case insensitive): ALLOC, ALLOCATED, BLOCKED, CLOUD, COMP, COMPLETING, DOWN, DRAIN (for node in DRAINING or DRAINED states), DRAINED, DRAINING, FAIL, FUTURE, FUTR, IDLE, MAINT, MIX, MIXED, NO_RESPOND, NPC, PERFCTRS, PLANNED, POWER_DOWN, POWERING_DOWN, POWERED_DOWN, POWERING_UP, REBOOT_ISSUED, REBOOT_REQUESTED, RESV, RESERVED, UNK, and UNKNOWN. By default nodes in the specified state are reported whether they are responding or not. The --dead and --responding options may be used to filter nodes by the corresponding flag.
-s, --summarize
List only a partition state summary with no node state details. This is ignored if the --format option is specified.
--usage
Print a brief message listing the sinfo options.
-v, --verbose
Provide detailed event logging through program execution.
-V, --version
Print version information and exit.
--yaml, --yaml=list, --yaml=<data_parser>
Dump information as YAML using the default data_parser plugin or explicit data_parser with parameters. All information is dumped, even if it would normally not be. Sorting and formatting arguments passed to other options are ignored; however, most filtering arguments are still used.

DESCRIPTIONS DES CHAMPS DE SORTIE

AVAIL
État de la partition. Peut être up, down, drain, ou inact (pour INACTIVE). Voir le paramètre State dans la définition de la partition dans la page de manuel de slurm.conf(5) pour plus d'informations.
CPUS
Nombre de CPUs (processeurs) sur ces nœuds.
S:C:T
Nombre de sockets (S), cœurs (C) et threads (T) sur ces nœuds.
SOCKETS
Nombre de sockets sur ces nœuds.
CORES
Nombre de cœurs sur ces nœuds.
THREADS
Nombre de threads sur ces nœuds.
GROUPS
Les allocations de ressources dans cette partition sont restreintes aux groupes nommés. all indique que tous les groupes peuvent utiliser cette partition.
JOB_SIZE
Nombre minimum et maximum de nœuds pouvant être alloués à n'importe quel travail utilisateur. Un nombre unique indique que le nombre minimum et maximum de nœuds sont identiques. infinite est utilisé pour identifier les partitions sans nombre maximum de nœuds.
TIMELIMIT
Limite de temps maximale pour tout travail utilisateur en jours-heures:minutes:secondes. infinite est utilisé pour identifier les partitions sans limite de temps de travail.
MEMORY
Taille de la mémoire réelle en mégaoctets sur ces nœuds.
NODELIST
Noms des nœuds associés à cette configuration particulière.
NODES
Nombre de nœuds avec cette configuration particulière.
NODES(A/I)
Nombre de nœuds avec cette configuration particulière par état de nœud sous la forme "alloué/inactif".
NODES(A/I/O/T)
Nombre de nœuds avec cette configuration particulière par état de nœud sous la forme "alloué/inactif/autre/total".
PARTITION
Nom d'une partition. Notez que le suffixe "*" identifie la partition par défaut.
PORT
Port TCP local utilisé par slurmd sur le nœud.
ROOT
L'aptitude à allouer des ressources dans cette partition est-elle restreinte à l'utilisateur root, oui ou non.
OVERSUBSCRIBE
Si les travaux allouant des ressources dans cette partition peuvent/vont sur-allouer ces ressources de calcul (par exemple, les CPUs). NO indique que les ressources ne sont jamais sur-allouées. EXCLUSIVE indique que des nœuds entiers sont dédiés aux travaux (équivalent à l'option srun --exclusive, peut être utilisé même avec select/cons_tres gérant des processeurs individuels). FORCE indique que les ressources sont toujours disponibles pour être sur-allouées. YES indique que les ressources peuvent être sur-allouées, si demandé par l'allocation de ressources du travail.

NOTE: Si OverSubscribe est réglé sur FORCE ou YES, la valeur OversubScribe sera ajoutée à la sortie.

STATE
État des nœuds. Les états possibles incluent : allocated, blocked, completing, down, drained, draining, fail, failing, future, idle, maint, mixed, perfctrs, planned, power_down, power_up, reserved, et unknown. Leurs formes abrégées sont : alloc, block, comp, down, drain, drng, fail, failg, futr, idle, maint, mix, npc, plnd, pow_dn, pow_up, resv, et unk respectivement.

NOTE: Le suffixe "*" identifie les nœuds qui ne répondent pas actuellement.

TMP_DISK
Taille de l'espace disque temporaire en mégaoctets sur ces nœuds.

CODES D'ÉTAT DES NŒUDS

Les codes d'état des nœuds sont raccourcis selon les besoins pour la taille du champ. Ces états de nœuds peuvent être suivis d'un caractère spécial pour identifier les indicateurs d'état associés au nœud. Les suffixes et états de nœuds suivants sont utilisés :

*
Le nœud ne répond pas actuellement et aucun nouveau travail ne lui sera alloué. Si le nœud reste non réactif, il sera placé dans l'état DOWN (sauf dans le cas des nœuds COMPLETING, DRAINED, DRAINING, FAIL, FAILING).
~
Le nœud est actuellement éteint.
#
Le nœud est actuellement en cours de démarrage ou de configuration.
!
Le nœud est en attente d'extinction.
%
Le nœud est actuellement en cours d'extinction.
$
Le nœud est actuellement dans une réservation avec une valeur d'indicateur "maintenance".
@
Le nœud est en attente de redémarrage.

NOM

sinfo - état du cluster Slurm

SYNTAX

sinfo [OPTIONS]

DESCRIPTION

La commande sinfo est utilisée pour visualiser l'état du cluster Slurm. Elle affiche des informations sur les partitions et les nœuds qui leur sont associés.

L'état des nœuds est représenté par des codes abrégés. Les codes disponibles et leurs significations sont les suivants:

@
Le nœud est en mode non-rejoignable par le planificateur.
~
Le nœud est en mode batterie faible (consommation d'énergie réduite).
*
Le nœud est inconnu.
!
Le nœud est en mode de détection de panne.
#
Le nœud est en mode de maintenance.
$
Le nœud est en mode de mise hors tension.
%
Le nœud est dans une réservation.
&
Le nœud est en cours d'arrêt.
?
Le nœud est temporairement indisponible.
^
Le redémarrage du nœud a été demandé.
-
Le nœud est planifié par le planificateur de remplissage pour un travail de plus haute priorité.
ALLOCATED
Le nœud a été alloué à un ou plusieurs travaux.
ALLOCATED+
Le nœud est alloué à un ou plusieurs travaux actifs ET un ou plusieurs travaux sont en cours de finalisation (COMPLETING).
BLOCKED
Le nœud a été bloqué par un travail à topologie exclusive.
COMPLETING
Tous les travaux associés à ce nœud sont en cours de finalisation. Cet état de nœud sera supprimé lorsque tous les processus du travail auront terminé et que le programme épilogue de Slurm (le cas échéant) aura terminé. Voir la description du paramètre Epilog dans la page de manuel slurm.conf(5) pour plus d'informations.
DOWN
Le nœud est indisponible. Slurm peut automatiquement placer les nœuds dans cet état en cas de défaillance. Les administrateurs système peuvent également placer explicitement les nœuds dans cet état. Si un nœud reprend son fonctionnement normal, Slurm peut le remettre en service automatiquement. Voir les descriptions des paramètres ReturnToService et SlurmdTimeout dans la page de manuel slurm.conf(5) pour plus d'informations.
DRAINED
Le nœud est indisponible à la demande de l'administrateur système. Voir la commande update node dans la page de manuel scontrol(1) ou la page de manuel slurm.conf(5) pour plus d'informations.
DRAINING
Le nœud est actuellement alloué à un travail, mais ne sera pas alloué de travaux supplémentaires. L'état du nœud sera changé en DRAINED lorsque le dernier travail actif sur celui-ci sera terminé. Les nœuds entrent dans cet état à la demande de l'administrateur système. Voir la commande update node dans la page de manuel scontrol(1) ou la page de manuel slurm.conf(5) pour plus d'informations.
FAIL
Le nœud est censé échouer bientôt et est indisponible à la demande de l'administrateur système. Voir la commande update node dans la page de manuel scontrol(1) ou la page de manuel slurm.conf(5) pour plus d'informations.
FAILING
Le nœud exécute actuellement un travail, mais est censé échouer bientôt et est indisponible à la demande de l'administrateur système. Voir la commande update node dans la page de manuel scontrol(1) ou la page de manuel slurm.conf(5) pour plus d'informations.
FUTURE
Le nœud n'est actuellement pas entièrement configuré, mais devrait être disponible à un moment donné dans un avenir indéterminé.
IDLE
Le nœud n'est alloué à aucun travail et est disponible pour utilisation.
INVAL
Le nœud ne s'est pas enregistré correctement auprès du contrôleur. Cela se produit lorsqu'un nœud s'enregistre avec moins de ressources que celles configurées dans le fichier slurm.conf. Le nœud sortira de cet état avec un enregistrement valide (c'est-à-dire qu'un redémarrage de slurmd est requis).
MAINT
Le nœud est actuellement dans une réservation avec la valeur de drapeau "maintenance".
REBOOT_ISSUED
Une demande de redémarrage a été envoyée à l'agent configuré pour gérer cette demande.
REBOOT_REQUESTED
Une demande de redémarrage de ce nœud a été faite, mais n'a pas encore été traitée.
MIXED
Le nœud a certains de ses CPU ALLOCATED tandis que d'autres sont IDLE. Ou le nœud a un travail suspendu alloué à certains de ses TRES (par exemple, mémoire).
PERFCTRS (NPC)
Les compteurs de performance réseau associés à ce nœud sont utilisés, rendant ce nœud inutilisable pour tout autre travail.
PLANNED
Le nœud est planifié par le planificateur de remplissage pour un travail de plus haute priorité.
POWER_DOWN
Le nœud est en attente d'extinction.
POWERED_DOWN
Le nœud est actuellement éteint et incapable de lancer des travaux.
POWERING_DOWN
Le nœud est en cours d'extinction et incapable de lancer des travaux.
POWERING_UP
Le nœud est en cours d'alimentation.
RESERVED
Le nœud est dans une réservation avancée et n'est pas généralement disponible.
UNKNOWN
Le contrôleur Slurm vient de démarrer et l'état du nœud n'a pas encore été déterminé.

PERFORMANCE

L'exécution de sinfo envoie un appel de procédure distante à slurmctld. Si suffisamment d'appels provenant de sinfo ou d'autres commandes client Slurm qui envoient des appels de procédure distante au démon slurmctld arrivent en même temps, cela peut entraîner une dégradation des performances du démon slurmctld, entraînant potentiellement un déni de service.

N'exécutez pas sinfo ou d'autres commandes client Slurm qui envoient des appels de procédure distante à slurmctld depuis des boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à sinfo au minimum nécessaire pour les informations que vous essayez de collecter.

ENVIRONMENT VARIABLES

SLURM_DEBUG_FLAGS
Spécifie les indicateurs de débogage à utiliser par sinfo. Voir DebugFlags dans la page de manuel slurm.conf(5) pour une liste complète des indicateurs. La variable d'environnement a prééance sur le paramètre dans slurm.conf.
SLURM_JSON
Contrôle la sérialisation JSON :
compact
Produit la sortie JSON de la manière la plus compacte possible.
pretty
Produit la sortie JSON dans un format lisible pour la rendre plus facile à lire.
SLURM_TIME_FORMAT
Spécifie le format utilisé pour rapporter les horodatages. Une valeur de standard, la valeur par défaut, génère une sortie sous la forme "année-mois-jourTheure:minute:seconde". Une valeur de relative renvoie uniquement "heure:minute:seconde" si le jour courant. Pour d'autres dates de l'année courante, elle affiche "heure:minute" précédé de "Demain", "Hier", le nom du jour de la semaine à venir (par exemple, "Lun", "Mar", etc.), sinon la date (par exemple, "25 Avr"). Pour les années autres, elle renvoie une date, un mois et une année sans heure (par exemple, "6 Juin 2012"). Tous les horodatages utilisent un format de 24 heures.

Un format strftime() valide peut également être spécifié. Par exemple, une valeur de "%a %T" rapportera le jour de la semaine et un horodatage (par exemple, "Lun 12:34:56").

SLURM_YAML
Contrôle la sérialisation YAML :
compact Produit la sortie YAML de la manière la plus compacte possible.
pretty Produit la sortie YAML dans un format lisible pour la rendre plus facile à lire.
