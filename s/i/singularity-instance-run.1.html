NOM

apptainer-instance-run - Lance une instance nommée de l'image de conteneur donnée

SYNTAXE

apptainer instance run [options de démarrage...] [arguments du script de lancement...]

DESCRIPTION

La commande instance run permet de créer une nouvelle instance nommée à partir d'une
image de conteneur existante qui commencera à s'exécuter en arrière-plan. Si un
script de lancement est défini dans les métadonnées du conteneur, les commandes de ce script
seront également exécutées avec la commande instance run. Vous pouvez éventuellement
passer des arguments au script de lancement.

NOTE : Cette commande a été ajoutée à Apptainer bien plus tard que les autres
commandes d'action et ne fonctionnera pas avec les conteneurs plus anciens. Dans ce cas, vous pourriez
avoir besoin de reconstruire le conteneur.

apptainer instance run accepte les formats de conteneur suivants

*.sif Format d'image Singularity (SIF). Natif de Singularity
(3.0+) et Apptainer (v1.0.0+)

*.sqsh Format SquashFS. Natif de Singularity 2.4+

*.img Format ext3. Natif des versions de Singularity < 2.4.

répertoire/ format sandbox. Répertoire contenant un système de fichiers racine valide
et éventuellement des métadonnées Apptainer.

instance://* Une instance locale en cours d'exécution d'un conteneur. (Voir le groupe
de commandes instance.)

library://* Un conteneur SIF hébergé sur une Bibliothèque (aucune par défaut)

docker://* Un conteneur Docker/OCI hébergé sur Docker Hub ou un autre
registre OCI.

shub://* Un conteneur hébergé sur Singularity Hub.

oras://* Un conteneur SIF hébergé sur un registre OCI qui prend en charge
la spécification OCI Registry As Storage (ORAS).

OPTIONS

--add-caps="" une liste de capacités séparées par des virgules à ajouter

--allow-setuid[=false] autorise les binaires setuid dans le conteneur (root seulement)

--app="" définit une application à exécuter dans le conteneur

--apply-cgroups="" applique les cgroups à partir d'un fichier pour les processus du conteneur (root seulement)

--authfile="" fichier d'authentification de style Docker à utiliser pour lire/écrire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de liaison utilisateur. La spécification a le format src[:dest[:opts]], où src et dest sont les chemins extérieur et intérieur. Si dest n'est pas donné, il est défini comme égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, ce qui est la valeur par défaut). Plusieurs chemins de liaison peuvent être donnés sous forme de liste séparée par des virgules.

--blkio-weight=0 poids relatif de l'IO bloc dans la plage 10-1000, 0 pour désactiver

--blkio-weight-device=[] poids relatif de l'IO bloc spécifique à un périphérique

--boot[=false] exécute /sbin/init pour démarrer le conteneur (root seulement)

-e, --cleanenv[=false] nettoie l'environnement avant d'exécuter le conteneur

--compat[=false] applique les paramètres pour une compatibilité OCI/Docker accrue. Déduit --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] utilise un /dev minimal et vide d'autres répertoires (par exemple /tmp et $HOME) au lieu de partager les systèmes de fichiers de votre hôte

-C, --containall[=false] isole non seulement les systèmes de fichiers, mais aussi les processus, l'IPC et l'environnement

--cpu-shares=-1 parts de CPU pour le conteneur

--cpus="" nombre de CPU disponibles pour le conteneur

--cpuset-cpus="" liste des CPU de l'hôte disponibles pour le conteneur

--cpuset-mems="" liste des nœuds mémoire de l'hôte disponibles pour le conteneur

--disable-cache[=false] n'utilise ni ne crée de cache

--dmtcp-launch="" point de contrôle pour dmtcp pour sauvegarder l'état du processus du conteneur (expérimental)

--dmtcp-restart="" point de contrôle pour dmtcp pour redémarrer le processus du conteneur (expérimental)

--dns="" liste des serveurs DNS séparés par des virgules à ajouter dans resolv.conf

--docker-host="" spécifie un hôte de démon Docker personnalisé

--docker-login[=false] se connecte interactivement à un dépôt Docker

--drop-caps="" une liste de capacités séparées par des virgules à supprimer

--env=[] transmet une variable d'environnement au processus contenu

--env-file=[] transmet des variables d'environnement à partir d'un fichier au processus contenu

-f, --fakeroot[=false] exécute le conteneur avec l'apparence d'une exécution en tant que root

--fusemount=[] une spécification de montage de système de fichiers FUSE de la forme ': ' - où 'container' ou 'host', spécifiant où le montage sera effectué ('container-daemon' ou 'host-daemon' exécutera le processus FUSE détaché). est le chemin vers l'exécutable FUSE, plus les options pour le montage. est l'emplacement dans le conteneur où le montage FUSE sera attaché. Par exemple, 'container:sshfs 10.0.0.1:/ /sshfs'. Implique --pid.

-h, --help[=false] aide pour run

-H, --home="/build" une spécification de répertoire personnel. La spécification peut être un chemin source ou une paire src:dest. src est le chemin source du répertoire personnel à l'extérieur du conteneur et dest remplace le répertoire personnel à l'intérieur du conteneur.

--hostname="" définit le nom d'hôte du conteneur

-i, --ipc[=false] exécute le conteneur dans un nouvel espace de noms IPC

--keep-privs[=false] laisse l'utilisateur root conserver ses privilèges dans le conteneur (root seulement)

--memory="" limite de mémoire en octets

--memory-reservation="" limite souple de mémoire en octets

--memory-swap="" limite de swap, utiliser -1 pour un swap illimité

--mount=[] une spécification de montage, par exemple 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] exécute le conteneur dans un nouvel espace de noms réseau (met en place une interface réseau bridge par défaut)

--netns-path="" rejoint l'espace de noms réseau au chemin spécifié (en tant que root, ou si autorisé dans apptainer.conf)

--network="" spécifie le type de réseau souhaité séparé par des virgules, chaque réseau mettra en place une interface dédiée à l'intérieur du conteneur

--network-args=[] spécifie les arguments réseau à passer aux plugins CNI

--no-eval[=false] n'évalue pas les variables d'environnement ou les CMD/ENTRYPOINT/ARGS des conteneurs OCI par shell

--no-home[=false] ne monte PAS le répertoire personnel de l'utilisateur si /home n'est pas le répertoire de travail actuel

--no-https[=false] utilise http au lieu de https pour les URI docker://, oras:// et library:///...

--no-init[=false] ne démarre PAS le processus shim avec --pid

--no-mount=[] désactive une ou plusieurs options 'mount xxx' définies dans apptainer.conf et/ou spécifie un chemin de destination absolu pour désactiver une entrée de chemin de liaison, ou 'bind-paths' pour désactiver toutes les entrées de chemin de liaison.

--no-privs[=false] supprime tous les privilèges de l'utilisateur root dans le conteneur)

--no-umask[=false] ne propage pas l'umask au conteneur, définit l'umask par défaut 0022

--nv[=false] active le support Nvidia

--nvccli[=false] utilise nvidia-container-cli pour la configuration GPU (expérimental)

--oom-kill-disable[=false] Désactive le tueur OOM

-o, --overlay=[] utilise une image overlayFS pour le stockage de données persistantes ou comme couche en lecture seule du conteneur

--passphrase[=false] demande une phrase secrète de chiffrement

--pem-path="" entre un chemin vers une clé RSA au format PEM pour un conteneur chiffré

--pid-file="" écrit le PID de l'instance dans le fichier portant le nom donné

--pids-limit=0 limite le nombre de PIDs du conteneur, utiliser -1 pour illimité

--rocm[=false] active le support Rocm expérimental

--runscript-timeout="" définit la durée du délai d'attente pour le script de lancement (par défaut 1m)

-S, --scratch=[] inclut un répertoire temporaire dans le conteneur qui est lié à un répertoire temporaire (utiliser -W pour forcer l'emplacement)

--security=[] active les fonctionnalités de sécurité (SELinux, Apparmor, Seccomp)

--unsquash[=false] convertit le fichier SIF en sandbox temporaire avant l'exécution

-u, --userns[=false] exécute le conteneur dans un nouvel espace de noms utilisateur

--uts[=false] exécute le conteneur dans un nouvel espace de noms UTS

ace

-W, --workdir="" répertoire de travail à utiliser pour /tmp, /var/tmp et $HOME (si -c/--contain a également été utilisé)

-w, --writable[=false] par défaut, tous les conteneurs Apptainer sont disponibles en lecture seule. Cette option rend le système de fichiers accessible en lecture/écriture.

--writable-tmpfs[=false] rend le système de fichiers accessible en lecture/écriture avec des données non persistantes (avec prise en charge d'overlay uniquement)

  $ apptainer instance run /tmp/my-sql.sif mysql
  $ apptainer shell instance://mysql
  Apptainer my-sql.sif> pwd
  /home/mibauer/mysql
  Apptainer my-sql.sif> ps
  PID TTY          TIME CMD
    1 pts/0    00:00:00 appinit
    2 pts/0    00:00:00 bash
    3 pts/0    00:00:00 ps
  Apptainer my-sql.sif>
  $ apptainer instance stop /tmp/my-sql.sif mysql
  Stopping /tmp/my-sql.sif mysql
