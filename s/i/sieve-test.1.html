NOM

sieve-test - Testeur de scripts Sieve de Pigeonhole

SYNTAXE

sieve-test [options] fichier-script fichier-courriel

DESCRIPTION


La commande fait partie de Pigeonhole (pigeonhole(7)), qui ajoute la prise en charge de Sieve (RFC 5228) et ManageSieve (RFC 5804) à Dovecot (dovecot(1)).

En utilisant la commande sieve-test, l'exécution des scripts Sieve peut être testée. Cela évalue le script pour le message fourni, générant un ensemble d'actions Sieve. À moins que l'option -e ne soit spécifiée, elle n'exécute pas réellement ces actions, ce qui signifie qu'elle ne stocke ni ne transfère le message nulle part. Au lieu de cela, elle imprime une liste détaillée des actions qui auraient normalement lieu. Notez que, même lorsque -e est spécifié, aucun message n'est jamais transmis aux destinataires SMTP distants. Les messages sortants sont toujours imprimés sur stdout à la place.

C'est un outil très utile pour déboguer l'exécution des scripts Sieve. Il peut être utilisé pour vérifier que les nouveaux scripts installés se comportent comme prévu et il peut fournir des informations plus détaillées sur les problèmes d'exécution de scripts signalés par le plugin Sieve, par exemple en traçant l'exécution et l'évaluation des commandes et des tests respectivement.

OPTIONS

-a adresse-destinataire-orig

L'adresse originale du destinataire de l'enveloppe. C'est ce que le test de l'enveloppe Sieve comparera lorsque la partie de l'enveloppe « to » est demandée. Certains tests et actions utiliseront également ceci comme adresse e-mail du propriétaire du script. Si cette option est omise, l'adresse du destinataire est récupérée des en-têtes de message « Envelope-To: » ou « To: ». Si aucun de ces en-têtes n'est présent non plus, l'adresse du destinataire par défaut est recipient@example.com.

-c fichier-config

Chemin alternatif du fichier de configuration Dovecot.

-C

et son heure de modification est plus récente que le fichier de script, il est utilisé et le script n'est pas recompilé. Cette option force la compilation du script, ignorant ainsi tout binaire existant. Reportez-vous à sievec(1) pour plus d'informations sur la compilation Sieve.

-D

Active le débogage Sieve.

-d fichier-vidage

Provoque l'écriture d'un vidage du code généré dans le fichier spécifié. Ceci est identique au vidage produit par sieve-dump(1). Utiliser '-' comme nom de fichier provoque l'écriture du vidage sur

-e

Active la véritable exécution de l'ensemble des actions qui résultent de l'exécution du script. Utilisez le paramètre -o pour spécifier le pilote de messagerie, le chemin de messagerie et d'autres paramètres de stockage nécessaires. Ceci permet de tester la livraison réelle des messages. Notez que cela ne transmettra aucun message aux destinataires SMTP distants. De telles actions impriment uniquement le message sortant sur stdout.

-f expéditeur-enveloppe

L'adresse de l'expéditeur de l'enveloppe (chemin de retour). C'est ce que le test de l'enveloppe Sieve comparera lorsque la partie de l'enveloppe « from » est demandée. De plus, c'est là que les messages de réponse sont 'envoyés'. Si cette option est omise, l'adresse de l'expéditeur est récupérée des en-têtes de message « Return-Path: », « Sender: » ou « From: ». Si aucun de ces en-têtes n'est présent non plus, l'adresse de l'expéditeur de l'enveloppe par défaut est sender@example.com.

-m boîte-aux-lettres-par-défaut

La boîte aux lettres où l'action `keep` stocke le message. C'est « INBOX » par défaut.

-o paramètre=valeur

Remplace le paramètre de configuration de /etc/dovecot/dovecot.conf et de la base de données utilisateur par la valeur donnée. Pour remplacer plusieurs paramètres, l'option -o peut être spécifiée plusieurs fois.

-r adresse-destinataire

L'adresse finale du destinataire de l'enveloppe. Certains tests et actions utiliseront ceci comme adresse e-mail du propriétaire du script. Par exemple, c'est ce qui est utilisé par l'action `vacation` pour vérifier si une réponse est appropriée. Si l'option -r est omise, l'adresse originale du destinataire de l'enveloppe sera utilisée à la place (voir l'option -a pour plus d'informations).

-s fichier-script

Spécifie des scripts supplémentaires à exécuter avant le script principal. Plusieurs arguments -s sont autorisés et les scripts spécifiés sont exécutés séquentiellement dans l'ordre spécifié sur la ligne de commande.

-t fichier-trace

Active le débogage de trace d'exécution. Le débogage de trace fournit un aperçu détaillé des opérations effectuées par le script Sieve. Reportez-vous à la section de débogage de trace d'exécution ci-dessous. Les informations de trace sont écrites dans le fichier spécifié. Utiliser '-' comme nom de fichier provoque l'écriture des données de trace sur stdout.

-T option-trace

Configure le débogage de trace d'exécution, qui est activé avec l'option -t. Reportez-vous à la section de débogage de trace d'exécution ci-dessous.

-u utilisateur/masque

Exécute la commande uniquement pour l'utilisateur donné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par exemple -u *@example.org).

-x auth_info

auth_info spécifie des conditions supplémentaires pour la recherche user. La chaîne d'options auth_info doit être donnée comme paire nom = valeur. Pour plusieurs conditions, l'option -x peut être fournie plusieurs fois.

Les noms possibles pour auth_info sont :

service

Le service pour lequel la recherche userdb doit être testée. La valeur peut être le nom d'un service, couramment utilisé avec Dovecot. Par exemple : imap, pop3 ou smtp.

session

Identifiant de session.

lip

L'adresse IP locale (serveur) pour le test.

rip

L'adresse IP distante (client) pour le test.

lport

Le port local, par exemple 143

rport

Le port distant, par exemple 24567

real_lip

L'IP locale à laquelle le client s'est connecté sur cet hôte.

real_rip

L'IP distante d'où le client s'est connecté à cet hôte.

real_lport

Le port local auquel le client s'est connecté à cet hôte.

real_rport

Le port distant d'où le client s'est connecté à cet hôte.

forward_<champ>

Champ à transférer sous forme de %{forward:champ} au processus d'authentification.

ARGUMENTS

fichier-script

Spécifie le script à (compiler et) exécuter.

Notez que cet outil recherche un fichier binaire pré-compilé avec une extension .svbin et avec une base de nom et un chemin identiques au script spécifié. Utilisez l'option -C pour désactiver ce comportement en forçant la compilation du script dans un nouveau binaire.

fichier-courriel

Spécifie le fichier contenant le message électronique à tester.

UTILISATION

DÉBOGAGE DU TRACE D'EXÉCUTION

En utilisant l'option -t, l'outil sieve-test peut être configuré pour imprimer des informations de trace détaillées sur l'exécution du script Sieve vers un fichier ou la sortie standard. Par exemple, les commandes rencontrées, les tests effectués et les valeurs correspondantes peuvent être imprimés.

Le trace d'exécution peut être configuré à l'aide de l'option -T, qui peut être spécifiée plusieurs fois. Elle peut être utilisée comme suit :

-T level=...

Définit le niveau de détail du débogage de trace. Une des valeurs suivantes peut être fournie :

actions (par défaut) : Imprime uniquement les commandes d'action exécutées, comme keep, fileinto, reject et redirect.

commands : Imprime toutes les commandes exécutées, à l'exclusion des commandes de test.

tests : Imprime toutes les commandes exécutées et les tests effectués.

matching : Imprime toutes les commandes exécutées, les tests effectués et les valeurs correspondantes dans ces tests.

-T debug

Imprime également les messages de débogage. Ceci est généralement utile uniquement pour les développeurs et produira probablement une sortie désordonnée.

-T addresses


option ou par la commande sieve-dump(1).

EXTENSION DEBUG Sieve

Pour améliorer le débogage des scripts, cette implémentation Sieve prend en charge une extension de langage Sieve personnalisée appelée 'vnd.dovecot.debug'. Elle ajoute la commande debug_log qui permet d'enregistrer des messages de débogage.

Exemple :

require "vnd.dovecot.debug";
if header :contains "subject" "hello" {
  debug_log "Subject header contains hello!";
}

, sievec(1) et sieve-dump(1) prennent en charge l'extension vnd.dovecot.debug activée par défaut et il n'est ni nécessaire ni possible de désactiver la disponibilité de l'extension de débogage avec la

En revanche, pour le plugin Sieve réel pour le LDA de Dovecot (dovecot-lda(1)), l'extension vnd.dovecot.debug doit être activée explicitement en utilisant le paramètre sieve_extensions ou le paramètre sieve_global_extensions. Les messages sont ensuite enregistrés dans le fichier journal de script privé de l'utilisateur. S'il est utilisé dans un script global, les messages sont enregistrés via le mécanisme de journalisation par défaut de Dovecot.

CODE DE SORTIE

sieve-test se terminera avec l'une des valeurs suivantes :

0

L'exécution a réussi. (EX_OK, EXIT_SUCCESS)

1

L'opération a échoué. Ceci est retourné pour presque tous les échecs. (EXIT_FAILURE)

64

Paramètre invalide fourni. (EX_USAGE)

FICHIERS

/etc/dovecot/dovecot.conf

Fichier de configuration principal de Dovecot.

/etc/dovecot/conf.d/90-sieve.conf

Paramètres de l'interpréteur Sieve (inclus dans le fichier de configuration principal de Dovecot)

SIGNALEMENT DE BOGUES

Signalez les bogues, y compris la sortie de doveconf -n, à la liste de diffusion Dovecot ⟨dovecot@dovecot.org⟩. Des informations sur le signalement de bogues sont disponibles à l'adresse : https://dovecot.org/bugreport.html
