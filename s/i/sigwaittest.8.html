NOM

sigwaittest - Démarre deux threads ou deux processus et mesure la latence entre l'envoi et la réception d'un signal

SYNTAXE

sigwaittest [-a|--affinity PROC] [-b|--breaktrace USEC] [-d|--distance DIST] [-D|--duration TIME] [-f|--fork [OPT]] [-i|--interval INTV] [--json FILENAME] [-l|--loops LOOPS] [-p|--prio PRIO] [-t|--threads [NUM]]

DESCRIPTION

Le programme sigwaittest démarre deux threads ou, optionnellement, crée deux processus qui sont synchronisés via des signaux et mesure la latence entre l'envoi d'un signal et le retour de sigwait().

OPTIONS

-a, --affinity[=PROC]
Exécuter sur le processeur numéro PROC. Si PROC n'est pas spécifié, exécuter sur le processeur actuel.
-b, --breaktrace=USEC
Envoyer une commande de trace d'interruption lorsque la latence > USEC. Ceci est une option de débogage pour contrôler le traceur de latence dans le patch de préemption temps réel. Il est utile pour identifier les latences importantes inattendues d'un système.
-d, --distance=DIST
Définir la distance des intervalles des threads en microsecondes (par défaut 500 us). Lorsque cyclictest est appelé avec l'option -t et que plus d'un thread est créé, cette valeur de distance est ajoutée à l'intervalle des threads : Interval(thread N) = Interval(thread N-1) + DIST
-D, --duration=TIME
Spécifier une durée pour l'exécution du test.
Ajouter 'm', 'h' ou 'd' pour spécifier des minutes, des heures ou des jours.
-f, --fork[=OPT]
Au lieu de créer des threads (ce qui est le comportement par défaut), créer de nouveaux processus.
-i, --interval=INTV
Définir l'intervalle de base des threads en microsecondes (par défaut 1000 us). Ceci définit l'intervalle du premier thread. Voir aussi -d.
--json=FILENAME
Écrire les résultats finaux dans FILENAME, au format JSON.
-l, --loops=LOOPS
Définir le nombre de boucles. La valeur par défaut est 0 (infini). Cette option est utile pour les tests automatisés avec un nombre donné de cycles de test. sigwaittest s'arrête une fois le nombre d'intervalles de temps atteint.
-p, --prio=PRIO
Définir la priorité du processus.
-t, --threads[=NUM]
Définir le nombre de threads de test (par défaut 1, si cette option n'est pas fournie). Si NUM est spécifié, créer NUM threads de test. Si NUM n'est pas spécifié, NUM est défini sur le nombre de CPUs disponibles.

EXEMPLES

L'exemple suivant a été exécuté sur un CPU quad-core :

# sigwaittest -a -t -p99 -i100 -d25 -l1000000

#2: ID11512, P98, CPU1, I125; #3: ID11513, P98, CPU1, Cycles 817484
#4: ID11514, P97, CPU2, I150; #5: ID11515, P97, CPU2, Cycles 668213
#6: ID11516, P96, CPU3, I175; #7: ID11517, P96, CPU3, Cycles 597344
#1 -> #0, Min    1, Cur    2, Avg    3, Max   30
#3 -> #2, Min    1, Cur   26, Avg    3, Max   42
