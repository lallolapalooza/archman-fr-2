SIGQUEUE(3P) Manuel du programmeur POSIX SIGQUEUE(3P)

PROLOG

Cette page de manuel fait partie du manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sigqueue — met en file d'attente un signal pour un processus

SYNTAXE

#include <signal.h>
int sigqueue(pid_t pid, int signo, union sigval value);

DESCRIPTION

La fonction sigqueue() provoque l'envoi du signal spécifié par signo, avec la valeur spécifiée par value, au processus spécifié par pid. Si signo est zéro (le signal nul), une vérification des erreurs est effectuée mais aucun signal n'est réellement envoyé. Le signal nul peut être utilisé pour vérifier la validité de pid.

Les conditions requises pour qu'un processus ait l'autorisation de mettre en file d'attente un signal pour un autre processus sont les mêmes que pour la fonction kill().

La fonction sigqueue() retourne immédiatement. Si SA_SIGINFO est défini pour signo et si les ressources étaient disponibles pour mettre le signal en file d'attente, le signal sera mis en file d'attente et envoyé au processus receveur. Si SA_SIGINFO n'est pas défini pour signo, alors signo sera envoyé au moins une fois au processus receveur ; il n'est pas spécifié si value sera envoyé au processus receveur à la suite de cet appel.

Si la valeur de pid provoque la génération de signo pour le processus d'envoi, et si signo n'est pas bloqué pour le thread appelant et si aucun autre thread n'a signo débloqué ou n'attend dans une fonction sigwait() pour signo, soit signo, soit au moins le signal en attente et débloqué sera livré au thread appelant avant que la fonction sigqueue() ne retourne. Si plusieurs signaux en attente dans la plage SIGRTMIN à SIGRTMAX sont sélectionnés pour la livraison, ce sera celui avec le plus petit numéro. L'ordre de sélection entre les signaux temps réel et non temps réel, ou entre plusieurs signaux non temps réel en attente, n'est pas spécifié.

VALEUR DE RETOUR

En cas de succès, le signal spécifié aura été mis en file d'attente, et la fonction sigqueue() retournera zéro. Sinon, la fonction retournera -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction sigqueue() échoue si :

EAGAIN
Aucune ressource n'est disponible pour mettre le signal en file d'attente. Le processus a déjà mis en file d'attente {SIGQUEUE_MAX} signaux qui sont encore en attente chez le(s) destinataire(s), ou une limite de ressources à l'échelle du système a été dépassée.
EINVAL
La valeur de l'argument signo est un numéro de signal invalide ou non supporté.
EPERM
Le processus n'a pas les privilèges appropriés pour envoyer le signal au processus receveur.
ESRCH
Le processus pid n'existe pas.

RATIONALE

La fonction sigqueue() permet à une application de mettre en file d'attente un signal temps réel pour elle-même ou pour un autre processus, en spécifiant la valeur définie par l'application. C'est une pratique courante dans les applications temps réel sur les systèmes temps réel existants. Il a été jugé que la spécification d'une autre fonction dans l'espace de noms de nom sig... déjà réservé pour les signaux était préférable à l'extension de l'interface à kill().

Une telle fonction est devenue nécessaire lorsque la fonction de mise/obtention d'événements des files d'attente de messages a été supprimée. Il convient de noter que la fonction sigqueue() implique une réduction des performances dans une implémentation soucieuse de la sécurité, car les vérifications des permissions d'accès entre l'expéditeur et le destinataire doivent être effectuées à chaque envoi lorsque le pid est résolu en un processus cible. De telles vérifications d'accès n'étaient nécessaires qu'à l'ouverture de la file d'attente de messages dans l'interface précédente.

Les développeurs standard ont exigé que sigqueue() ait les mêmes sémantiques concernant le signal nul que kill(), et que les mêmes vérifications de permission soient utilisées. Mais en raison de la difficulté d'implémenter la sémantique de « diffusion » de kill() (par exemple, aux groupes de processus) et de l'interaction avec l'allocation des ressources, cette sémantique n'a pas été adoptée. La fonction sigqueue() met en file d'attente un signal pour un seul processus spécifié par l'argument pid.

La fonction sigqueue() peut échouer si le système n'a pas suffisamment de ressources pour mettre le signal en file d'attente. Une limite explicite sur le nombre de signaux mis en file d'attente qu'un processus peut envoyer a été introduite. Bien que la limite soit « par expéditeur », ce volume de POSIX.1-2017 ne spécifie pas que les ressources fassent partie de l'état de l'expéditeur. Cela nécessiterait soit que l'expéditeur soit maintenu après sa sortie jusqu'à ce que tous les signaux qu'il a envoyés à d'autres processus aient été traités, soit que tous ces signaux qui n'ont pas encore été pris en compte soient retirés de la ou des files d'attente des destinataires. Ce volume de POSIX.1-2017 n'exclut pas ce comportement, mais une implémentation qui alloue des ressources de mise en file d'attente à partir d'un pool global (avec des limites par expéditeur) et qui laisse les signaux mis en file d'attente en attente après la sortie de l'expéditeur est également autorisée.
