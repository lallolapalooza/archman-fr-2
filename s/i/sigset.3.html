sigset(3) Manuel des fonctions de bibliothèque sigset(3)

NOM

sigset, sighold, sigrelse, sigignore - API de signaux System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>
typedef typeof(void (int))  *sighandler_t;
[[deprecated]] sighandler_t sigset(int sig, sighandler_t disp);
[[deprecated]] int sighold(int sig);
[[deprecated]] int sigrelse(int sig);
[[deprecated]] int sigignore(int sig);
Conditions de Test de Fonctionnalités pour glibc (voir feature_test_macros(7)):

sigset(), sighold(), sigrelse(), sigignore():

    _XOPEN_SOURCE >= 500

DESCRIPTION

Ces fonctions sont fournies dans glibc comme interface de compatibilité pour les programmes qui utilisent l'API historique des signaux System V. Cette API est obsolète : les nouvelles applications devraient utiliser l'API de signaux POSIX (sigaction(2), sigprocmask(2), etc.)

La fonction sigset() modifie la disposition du signal sig. L'argument disp peut être l'adresse d'une fonction de gestionnaire de signaux, ou l'une des constantes suivantes :

SIG_DFL
Réinitialise la disposition de sig à la valeur par défaut.
SIG_IGN
Ignore sig.
SIG_HOLD
Ajoute sig au masque de signaux du processus, mais laisse la disposition de sig inchangée.

Si disp spécifie l'adresse d'un gestionnaire de signaux, alors sig est ajouté au masque de signaux du processus pendant l'exécution du gestionnaire.

Si disp a été spécifié comme une valeur autre que SIG_HOLD, alors sig est retiré du masque de signaux du processus.

Les dispositions pour SIGKILL et SIGSTOP ne peuvent pas être modifiées.

La fonction sighold() ajoute sig au masque de signaux du processus appelant.

La fonction sigrelse() retire sig du masque de signaux du processus appelant.

La fonction sigignore() définit la disposition de sig à SIG_IGN.

VALEUR RENVOYÉE

En cas de succès, sigset() renvoie SIG_HOLD si sig était bloqué avant l'appel, ou la disposition précédente du signal s'il n'était pas bloqué avant l'appel. En cas d'erreur, sigset() renvoie -1, avec errno défini pour indiquer l'erreur. (Mais voir ERREURS ci-dessous.)

Les fonctions sighold(), sigrelse() et sigignore() renvoient 0 en cas de succès ; en cas d'erreur, ces fonctions renvoient -1 et définissent errno pour indiquer l'erreur.

ERREURS

Pour sigset(), voir les ERREURS sous sigaction(2) et sigprocmask(2).

Pour sighold() et sigrelse(), voir les ERREURS sous sigprocmask(2).

Pour sigignore(), voir les erreurs sous sigaction(2).

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
sigset (), sighold (), sigrelse (), sigignore () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

sighandler_t
GNU. POSIX.1 utilise le même type mais sans typedef.

HISTORIQUE

glibc 2.1. SVr4, POSIX.1-2001. POSIX.1-2008 marque ces fonctions comme obsolètes, recommandant l'utilisation de sigaction(2), sigprocmask(2), pthread_sigmask(3), et sigsuspend(2) à la place.

NOTES

La fonction sigset() fournit des sémantiques de gestion de signaux fiables (comme lors de l'appel à sigaction(2) avec sa_mask égal à 0).

Sur System V, la fonction signal() fournit des sémantiques non fiables (comme lors de l'appel à sigaction(2) avec sa_mask égal à SA_RESETHAND | SA_NODEFER). Sur BSD, signal() fournit des sémantiques fiables. POSIX.1-2001 laisse ces aspects de signal() non spécifiés. Voir signal(2) pour plus de détails.

Afin d'attendre un signal, BSD et System V fournissaient tous deux une fonction nommée sigpause(3), mais cette fonction a un argument différent sur les deux systèmes. Voir sigpause(3) pour les détails.

BOGUES

Avant glibc 2.2, sigset() ne débloquait pas sig si disp était spécifié comme une valeur autre que SIG_HOLD.

Avant glibc 2.5, sigset() ne renvoie pas correctement la disposition précédente du signal dans deux cas. Premièrement, si disp est spécifié comme SIG_HOLD, alors un appel réussi à sigset() renvoie toujours SIG_HOLD. Au lieu de cela, il devrait renvoyer la disposition précédente du signal (sauf si le signal était bloqué, auquel cas SIG_HOLD devrait être renvoyé). Deuxièmement, si le signal est actuellement bloqué, alors la valeur renvoyée par un appel réussi à sigset() devrait être SIG_HOLD. Au lieu de cela, la disposition précédente du signal est renvoyée. Ces problèmes ont été corrigés depuis glibc 2.5.

VOIR AUSSI
