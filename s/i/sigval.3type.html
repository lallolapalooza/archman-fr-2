sigevent(3type) sigevent(3type)

NOM

sigevent, sigval - structure de notification à partir de routines asynchrones

SYNTAXE

#include <signal.h>
struct sigevent {
    int             sigev_notify;  /* Type de notification */
    int             sigev_signo;   /* Numéro de signal */
    union sigval    sigev_value;   /* Données transmises avec la notification */
    typeof(void (union sigval))  *sigev_notify_function;
                                   /* Fonction de notification
                                      (SIGEV_THREAD) */
    pthread_attr_t *sigev_notify_attributes;
                                   /* Attributs de notification */
    /* Linux uniquement : */
    pid_t           sigev_notify_thread_id;
                                   /* ID du thread à signaler
                                      (SIGEV_THREAD_ID) */
};
union sigval {                     /* Données transmises avec la notification */
    int             sival_int;     /* Valeur entière */
    void           *sival_ptr;     /* Valeur pointeur */
};

DESCRIPTION

sigevent

La structure sigevent est utilisée par diverses API pour décrire la manière dont un processus doit être notifié d'un événement (par exemple, l'achèvement d'une requête asynchrone, l'expiration d'un minuteur ou l'arrivée d'un message).

La définition présentée dans la SYNTAXE est approximative : certains des champs de la structure sigevent peuvent être définis dans une union. Les programmes ne doivent utiliser que les champs pertinents pour la valeur spécifiée dans sigev_notify.

Le champ sigev_notify spécifie comment la notification doit être effectuée. Ce champ peut avoir l'une des valeurs suivantes :

SIGEV_NONE
Une notification "nulle" : ne rien faire lorsque l'événement se produit.
SIGEV_SIGNAL
Notifier le processus en envoyant le signal spécifié dans sigev_signo.
Si le signal est intercepté par un gestionnaire de signal enregistré à l'aide du drapeau SA_SIGINFO de sigaction(2), alors les champs suivants sont définis dans la structure siginfo_t qui est passée comme deuxième argument du gestionnaire :
si_code
Ce champ est défini avec une valeur qui dépend de l'API délivrant la notification.
si_signo
Ce champ est défini avec le numéro de signal (c'est-à-dire la même valeur que dans sigev_signo).
si_value
Ce champ est défini avec la valeur spécifiée dans sigev_value.
Selon l'API, d'autres champs peuvent également être définis dans la structure siginfo_t.
Les mêmes informations sont également disponibles si le signal est accepté à l'aide de sigwaitinfo(2).
SIGEV_THREAD
Notifier le processus en invoquant sigev_notify_function "comme si" il s'agissait de la fonction de démarrage d'un nouveau thread. (Parmi les possibilités d'implémentation, chaque notification de minuteur pourrait entraîner la création d'un nouveau thread, ou un seul thread pourrait être créé pour recevoir toutes les notifications.) La fonction est invoquée avec sigev_value comme seul argument. Si sigev_notify_attributes n'est pas NULL, il doit pointer vers une structure pthread_attr_t qui définit les attributs du nouveau thread (voir pthread_attr_init(3)).
SIGEV_THREAD_ID (spécifique à Linux)
Actuellement utilisé uniquement par les minuteurs POSIX ; voir timer_create(2).

sigval

Données transmises avec un signal.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

<aio.h> et <time.h> définissent sigevent depuis POSIX.1-2008.

NOTES

Les en-têtes suivants fournissent également sigevent : <aio.h>, <mqueue.h> et <time.h>.
