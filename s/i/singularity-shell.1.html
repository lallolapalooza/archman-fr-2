NOM

apptainer-shell - Exécute un shell dans un conteneur

SYNOPSIS

apptainer shell [options de shell...]

DESCRIPTION

apptainer shell prend en charge les formats suivants :

*.sif Format d'image Singularity (SIF). Natif à Singularity
(3.0+) et Apptainer (v1.0.0+)

*.sqsh Format SquashFS. Natif à Singularity 2.4+

*.img Format ext3. Natif aux versions de Singularity < 2.4.

répertoire/ format sandbox. Répertoire contenant un système de fichiers racine valide
et éventuellement des métadonnées Apptainer.

instance://* Une instance de conteneur locale en cours d'exécution. (Voir le groupe de commandes instance
.)

library://* Un conteneur SIF hébergé sur une Bibliothèque (par défaut, aucune)

docker://* Un conteneur Docker/OCI hébergé sur Docker Hub ou un autre
registre OCI.

shub://* Un conteneur hébergé sur Singularity Hub.

oras://* Un conteneur SIF hébergé sur un registre OCI qui prend en charge
la spécification OCI Registry As Storage (ORAS).

OPTIONS

--add-caps="" une liste de capacités séparées par des virgules à ajouter

--allow-setuid[=false] autorise les binaires setuid dans le conteneur (root uniquement)

--app="" définit une application à exécuter à l'intérieur d'un conteneur

--apply-cgroups="" applique les cgroups depuis un fichier pour les processus du conteneur (root uniquement)

--authfile="" fichier d'authentification de style Docker à utiliser pour écrire/lire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de liaison utilisateur. La spécification a le format src[:dest[:opts]], où src et dest sont les chemins extérieurs et intérieurs. Si dest n'est pas spécifié, il est égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, ce qui est le défaut). Plusieurs chemins de liaison peuvent être donnés par une liste séparée par des virgules.

--blkio-weight=0 poids relatif du bloc IO dans la plage 10-1000, 0 pour désactiver

--blkio-weight-device=[] poids relatif du bloc IO spécifique à un appareil

-e, --cleanenv[=false] nettoie l'environnement avant d'exécuter le conteneur

--compat[=false] applique les paramètres pour une compatibilité OCI/Docker accrue. Déduit --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] utilise un /dev minimal et vide les autres répertoires (par exemple /tmp et $HOME) au lieu de partager les systèmes de fichiers de votre hôte

-C, --containall[=false] isole non seulement les systèmes de fichiers, mais aussi les PID, IPC et l'environnement

--cpu-shares=-1 parts CPU pour le conteneur

--cpus="" Nombre de CPUs disponibles pour le conteneur

--cpuset-cpus="" Liste des CPUs de l'hôte disponibles pour le conteneur

--cpuset-mems="" Liste des nœuds mémoire de l'hôte disponibles pour le conteneur

--cwd="" répertoire de travail initial pour le processus payload à l'intérieur du conteneur (synonyme de --pwd)

--disable-cache[=false] n'utilise ni ne crée de cache

--dns="" liste de serveurs DNS séparés par des virgules à ajouter dans resolv.conf

--docker-host="" spécifie un hôte de démon Docker personnalisé

--docker-login[=false] se connecte de manière interactive à un dépôt Docker

--drop-caps="" une liste de capacités séparées par des virgules à supprimer

--env=[] transmet une variable d'environnement au processus contenu

--env-file=[] transmet des variables d'environnement depuis un fichier au processus contenu

-f, --fakeroot[=false] exécute le conteneur avec l'apparence d'une exécution en tant que root

--fusemount=[] une spécification de montage de système de fichiers FUSE de la forme ': ' - où est 'container' ou 'host', spécifiant où le montage sera effectué ('container-daemon' ou 'host-daemon' exécutera le processus FUSE détaché). est le chemin vers l'exécutable FUSE, plus les options pour le montage. est l'emplacement dans le conteneur auquel le montage FUSE sera attaché. Par exemple, 'container:sshfs 10.0.0.1:/ /sshfs'. Implique --pid.

-h, --help[=false] aide pour shell

-H, --home="/build" une spécification de répertoire personnel. La spécification peut être un chemin source ou une paire source:destination. src est le chemin source du répertoire personnel en dehors du conteneur et dest remplace le répertoire personnel à l'intérieur du conteneur.

--hostname="" définit le nom d'hôte du conteneur

-i, --ipc[=false] exécute le conteneur dans un nouvel espace de noms IPC

--keep-privs[=false] laisse l'utilisateur root conserver ses privilèges dans le conteneur (root uniquement)

--memory="" limite de mémoire en octets

--memory-reservation="" limite souple de mémoire en octets

--memory-swap="" limite de swap, utiliser -1 pour un swap illimité

--mount=[] une spécification de montage par exemple 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] exécute le conteneur dans un nouvel espace de noms réseau (met en place une interface réseau bridge par défaut)

--netns-path="" rejoint l'espace de noms réseau au chemin spécifié (en tant que root, ou si autorisé dans apptainer.conf)

--network="" spécifie le type de réseau souhaité séparé par des virgules, chaque réseau activera une interface dédiée à l'intérieur du conteneur

--network-args=[] spécifie les arguments réseau à passer aux plugins CNI

--no-eval[=false] n'évalue pas les variables d'environnement ou les CMD/ENTRYPOINT/ARGS du conteneur OCI dans le shell

--no-home[=false] ne monte PAS le répertoire personnel de l'utilisateur si /home n'est pas le répertoire de travail courant

--no-https[=false] utilise http au lieu de https pour les URIs docker://, oras:// et library:///...

--no-init[=false] ne démarre PAS le processus shim avec --pid

--no-mount=[] désactive une ou plusieurs options 'mount xxx' définies dans apptainer.conf et/ou spécifie un chemin de destination absolu pour désactiver une entrée de chemin de liaison, ou 'bind-paths' pour désactiver toutes les entrées de chemin de liaison.

--no-pid[=false] n'exécute pas le conteneur dans un nouvel espace de noms PID

--no-privs[=false] supprime tous les privilèges de l'utilisateur root dans le conteneur)

--no-umask[=false] ne propage pas l'umask au conteneur, définit une umask par défaut de 0022

--nv[=false] active le support Nvidia

--nvccli[=false] utilise nvidia-container-cli pour la configuration GPU (expérimental)

--oom-kill-disable[=false] désactive le tueur OOM

-o, --overlay=[] utilise une image overlayFS pour le stockage persistant des données ou comme couche en lecture seule du conteneur

--passphrase[=false] demande une phrase secrète de chiffrement

--pem-path="" entre un chemin vers une clé RSA au format PEM pour un conteneur chiffré

-p, --pid[=false] exécute le conteneur dans un nouvel espace de noms PID

--pids-limit=0 limite le nombre de PID du conteneur, utiliser -1 pour illimité

--rocm[=false] active le support Rocm expérimental

-S, --scratch=[] inclut un répertoire temporaire dans le conteneur qui est lié à un répertoire temporaire (utiliser -W pour forcer l'emplacement)

--security=[] active les fonctionnalités de sécurité (SELinux, Apparmor, Seccomp)

--sharens[=false] partage l'espace de noms et l'image avec d'autres conteneurs lancés à partir du même processus parent

-s, --shell="" chemin vers le programme à utiliser pour le shell interactif

--unsquash[=false] convertit le fichier SIF en sandbox temporaire avant de l'exécuter

-u, --userns[=false] exécute le conteneur dans un nouvel espace de noms utilisateur

--uts[=false] exécute le conteneur dans un nouvel espace de noms UTS

-W, --workdir="" répertoire de travail à utiliser pour /tmp, /var/tmp et $HOME (si -c/--contain a également été utilisé)

-w, --writable[=false] par défaut, tous les conteneurs Apptainer sont disponibles en lecture seule. Cette option rend le système de fichiers accessible en lecture/écriture.

--writable-tmpfs[=false] rend le système de fichiers accessible en lecture/écriture sans données persistantes (uniquement avec le support overlay)

  Apptainer/Debian.sif> pwd
