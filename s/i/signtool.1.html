DESCRIPTION

L'outil de signature, signtool, crée des signatures numériques et utilise un fichier JAR (Java Archive) pour associer les signatures aux fichiers d'un répertoire. La distribution de logiciels électroniques sur n'importe quel réseau implique des problèmes de sécurité potentiels. Pour aider à résoudre certains de ces problèmes, vous pouvez associer des signatures numériques aux fichiers d'une archive JAR. Les signatures numériques permettent aux clients activés pour SSL d'effectuer deux opérations importantes :

* Confirmer l'identité de la personne, de l'entreprise ou de toute autre entité dont la signature numérique est associée aux fichiers.

* Vérifier si les fichiers ont été falsifiés depuis leur signature.

Si vous possédez un certificat de signature, vous pouvez utiliser Netscape Signing Tool pour signer numériquement des fichiers et les regrouper dans un fichier JAR. Un certificat de signature d'objet est un type spécial de certificat qui vous permet d'associer votre signature numérique à un ou plusieurs fichiers.

Un fichier individuel peut potentiellement être signé avec plusieurs signatures numériques. Par exemple, un développeur de logiciels commerciaux pourrait signer les fichiers constituant un produit logiciel pour prouver que les fichiers proviennent bien d'une entreprise particulière. Un administrateur réseau pourrait signer les mêmes fichiers avec une signature numérique supplémentaire basée sur un certificat généré par l'entreprise pour indiquer que le produit est approuvé pour une utilisation au sein de l'entreprise.

La signification d'une signature numérique est comparable à celle d'une signature manuscrite. Une fois que vous avez signé un fichier, il est difficile de prétendre plus tard que vous ne l'avez pas signé. Dans certaines situations, une signature numérique peut être considérée comme juridiquement contraignante, tout comme une signature manuscrite. Par conséquent, vous devez prendre grand soin pour vous assurer que vous pouvez cautionner tout fichier que vous signez et distribuez.

Par exemple, si vous êtes un développeur de logiciels, vous devez tester votre code pour vous assurer qu'il est exempt de virus avant de le signer. De même, si vous êtes un administrateur réseau, vous devez vous assurer, avant de signer un code, qu'il provient d'une source fiable et qu'il s'exécutera correctement avec les logiciels installés sur les machines auxquelles vous le distribuez.

Avant de pouvoir utiliser Netscape Signing Tool pour signer des fichiers, vous devez disposer d'un certificat de signature d'objet, qui est un certificat spécial dont la clé privée associée est utilisée pour créer des signatures numériques. À des fins de test uniquement, vous pouvez créer un certificat de signature d'objet avec Netscape Signing Tool 1.3. Une fois les tests terminés et que vous êtes prêt à distribuer votre logiciel, vous devriez obtenir un certificat de signature d'objet auprès de l'une des deux sources suivantes :

* Une autorité de certification (AC) indépendante qui authentifie votre identité et vous facture des frais. Vous obtenez généralement un certificat d'une AC indépendante si vous souhaitez signer des logiciels qui seront distribués sur Internet.

* Logiciel serveur AC fonctionnant sur votre intranet ou extranet d'entreprise. Netscape Certificate Management System fournit une solution complète de gestion pour la création, le déploiement et la gestion des certificats, y compris les AC qui émettent des certificats de signature d'objet.

Vous devez également disposer d'un certificat pour l'AC qui émet votre certificat de signature avant de pouvoir signer des fichiers. Si le certificat de l'autorité de certification n'est pas déjà installé dans votre copie de Communicator, vous l'installez généralement en cliquant sur le lien approprié sur le site Web de l'autorité de certification, par exemple sur la page depuis laquelle vous avez initié la demande de votre certificat de signature. C'est le cas pour certains certificats de test, ainsi que pour les certificats émis par Netscape Certificate Management System : vous devez télécharger le certificat AC en plus d'obtenir votre propre certificat de signature. Les certificats AC de plusieurs autorités de certification sont préinstallés dans la base de données des certificats de Communicator.

Lorsque vous recevez un certificat de signature d'objet pour votre propre usage, il est automatiquement installé dans votre copie du logiciel client Communicator. Communicator prend en charge la norme de cryptographie à clé publique connue sous le nom de PKCS #12, qui régit la portabilité des clés. Vous pouvez, par exemple, déplacer un certificat de signature d'objet et sa clé privée associée d'un ordinateur à un autre sur un appareil de la taille d'une carte de crédit appelé carte à puce.

OPTIONS

-b nom-de-base

Spécifie le nom de base des fichiers .rsa et .sf dans le répertoire META-INF pour se conformer au format JAR. Par exemple, -b signatures entraîne le nommage des fichiers signatures.rsa et signatures.sf. La valeur par défaut est signtool.

-c#

Spécifie le niveau de compression pour l'option -J ou -Z. Le symbole # représente un nombre de 0 à 9, où 0 signifie aucune compression et 9 signifie compression maximale. Plus le niveau de compression est élevé, plus la sortie est petite, mais plus l'opération prend de temps. Si l'option -c# n'est pas utilisée avec l'une des options -J ou -Z, la valeur de compression par défaut utilisée par les deux options -J et -Z est 6.

-d rép-cert

Spécifie votre répertoire de base de données de certificats ; c'est-à-dire le répertoire dans lequel vous avez placé vos fichiers key3.db et cert7.db. Pour spécifier le répertoire courant, utilisez "-d." (y compris le point). La version Unix de signtool suppose ~/.netscape sauf indication contraire. La version NT de signtool nécessite toujours l'utilisation de l'option -d pour spécifier l'emplacement des fichiers de base de données.

-e extension

Indique à signtool de ne signer que les fichiers ayant l'extension donnée ; par exemple, utilisez -e".class" pour ne signer que les fichiers de classe Java. Notez qu'avec Netscape Signing Tool version 1.1 et ultérieures, cette option peut apparaître plusieurs fois sur une seule ligne de commande, permettant de spécifier plusieurs types de fichiers ou classes à inclure.

-f nomfichier

Spécifie un fichier texte contenant les options et arguments de Netscape Signing Tool au format clé=valeur. Toutes les options et arguments peuvent être exprimés via ce fichier. Pour plus d'informations sur la syntaxe utilisée avec ce fichier, voir "Conseils et techniques".

-G surnom

Génère une nouvelle paire de clés publique-privée et le certificat de signature d'objet correspondant avec le surnom donné. Les nouvelles clés et le certificat générés sont installés dans les bases de données de clés et de certificats du répertoire spécifié par l'option -d. Avec la version NT de Netscape Signing Tool, vous devez utiliser l'option -d avec l'option -G. Avec la version Unix de Netscape Signing Tool, omettre l'option -d entraîne l'installation des clés et du certificat dans les bases de données de clés et de certificats de Communicator. Si vous installez les clés et le certificat dans les bases de données de Communicator, vous devez quitter Communicator avant d'utiliser cette option ; sinon, vous risquez de corrompre les bases de données. Dans tous les cas, le certificat est également exporté dans un fichier nommé x509.cacert, qui a le type MIME application/x-x509-ca-cert. Contrairement aux certificats normalement utilisés pour signer du code finalisé à distribuer sur un réseau, un certificat de test créé avec -G n'est pas signé par une autorité de certification reconnue. Il est plutôt auto-signé. De plus, un seul certificat de signature de test fonctionne à la fois comme certificat de signature d'objet et comme AC. Lorsque vous l'utilisez pour signer des objets, il se comporte comme un certificat de signature d'objet. Lorsqu'il est importé dans un logiciel de navigation tel que Communicator, il se comporte comme une AC de signature d'objet et ne peut pas être utilisé pour signer des objets. L'option -G est disponible dans Netscape Signing Tool 1.0 et versions ultérieures uniquement. Par défaut, elle produit uniquement des certificats RSA avec des clés de 1024 octets dans le jeton interne. Cependant, vous pouvez utiliser l'option -s pour spécifier la taille de clé requise et l'option -t pour spécifier le jeton.

-i nom-script

Spécifie le nom d'un script d'installation pour SmartUpdate. Ce script installe les fichiers de l'archive JAR sur le système local après que SmartUpdate a validé la signature numérique.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Pour plus de détails, voir la description de -m qui suit. L'option -i offre un moyen simple de fournir cette information si vous n'avez pas besoin de spécifier de métadonnées autres qu'un script d'installation.

-J

Signe un répertoire de fichiers HTML contenant du JavaScript et crée autant de fichiers archive qu'il est spécifié dans les balises HTML. Même si signtool crée plus d'un fichier archive, vous n'avez besoin de fournir le mot de passe de la base de données de clés qu'une seule fois. L'option -J n'est disponible que dans Netscape Signing Tool 1.0 et les versions ultérieures. L'option -J ne peut pas être utilisée en même temps que l'option -Z. Si l'option -c# n'est pas utilisée avec l'option -J, la valeur de compression par défaut est 6. Notez que les versions 1.1 et ultérieures de Netscape Signing Tool reconnaissent correctement l'attribut CODEBASE, permettent l'expression de chemins pour les attributs CLASS et SRC au lieu de simples noms de fichiers, traitent les balises LINK et analysent le HTML correctement, et offrent des messages d'erreur plus clairs.

-j répertoire

Spécifie un répertoire JavaScript spécial. Cette option entraîne la signature du répertoire spécifié et marque ses entrées comme JavaScript en ligne. Ce type spécial d'entrée n'a pas à apparaître dans le fichier JAR lui-même. Au lieu de cela, il est situé dans la page HTML contenant les scripts en ligne. Lorsque vous utilisez signtool -v, ces entrées sont affichées avec la chaîne NOT PRESENT.

-k clé ... répertoire

Spécifie le pseudonyme (clé) du certificat avec lequel vous souhaitez signer et signe les fichiers du répertoire spécifié. Le répertoire à signer est toujours spécifié comme le dernier argument de la ligne de commande. Ainsi, il est possible d'écrire signtool -k MonCert -d . annuaireASigner Vous pourriez avoir des problèmes si le pseudonyme contient une apostrophe. Pour éviter les problèmes, échappez l'apostrophe en utilisant les conventions d'échappement pour votre plateforme. Il est également possible d'utiliser l'option -k sans signer de fichiers ni spécifier de répertoire. Par exemple, vous pouvez l'utiliser avec l'option -l pour obtenir des informations détaillées sur un certificat de signature particulier.

-l

Liste les certificats de signature, y compris les AC émettrices. Si certains de vos certificats sont expirés ou invalides, la liste le spécifiera. Cette option peut être utilisée avec l'option -k pour obtenir des informations détaillées sur un certificat de signature particulier. L'option -l n'est disponible que dans Netscape Signing Tool 1.0 et les versions ultérieures.

-L

Liste les certificats de votre base de données. Un astérisque apparaît à gauche du pseudonyme pour tout certificat pouvant être utilisé pour signer des objets avec signtool.

--leavearc

Conserve les répertoires temporaires .arc (archive) que crée l'option -J. Ces répertoires sont automatiquement effacés par défaut. La conservation des répertoires temporaires peut aider au débogage.

-m fichier_meta

Spécifie le nom d'un fichier de contrôle de métadonnées. Les métadonnées sont des informations signées attachées soit à l'archive JAR elle-même, soit aux fichiers à l'intérieur de l'archive. Ces métadonnées peuvent être n'importe quelle chaîne ASCII, mais sont principalement utilisées pour spécifier un script d'installation. Le fichier de métadonnées contient une entrée par ligne, chacune avec trois champs : champ n°1 : spécification du fichier, ou + si vous voulez spécifier des métadonnées globales (c'est-à-dire des métadonnées sur l'archive JAR elle-même ou sur toutes les entrées de l'archive) champ n°2 : le nom des données que vous spécifiez ; par exemple : Script-d'Installation champ n°3 : données correspondant au nom dans le champ n°2 Par exemple, l'option -i utilise l'équivalent de cette ligne : + Script-d'Installation : script.js Cet exemple associe un type MIME à un fichier : film.qt MIME-Type : video/quicktime Pour plus d'informations sur la façon dont les informations du script d'installation apparaissent dans le fichier manifeste d'une archive JAR, voir Le Format JAR sur Netscape DevEdge.

-M

Liste les modules PKCS #11 disponibles pour signtool, y compris les cartes à puce. L'option -M n'est disponible que dans Netscape Signing Tool 1.0 et les versions ultérieures. Pour plus d'informations sur l'utilisation de Netscape Signing Tool avec des cartes à puce, voir « Utilisation de Netscape Signing Tool avec des cartes à puce ». Pour plus d'informations sur l'utilisation de l'option -M pour vérifier le mode validé FIPS-140-1, voir « Netscape Signing Tool et FIPS-140-1 ».

--norecurse

Bloque la récursion dans les sous-répertoires lors de la signature du contenu d'un répertoire ou lors de l'analyse HTML.

-o

Optimise l'archive pour la taille. Utilisez ceci uniquement si vous signez des archives très volumineuses contenant des centaines de fichiers. Cette option rend les fichiers manifeste (requis par le format JAR) considérablement plus petits, mais ils contiennent légèrement moins d'informations.

--outfile fichier_sortie

Spécifie un fichier pour recevoir la sortie redirigée de Netscape Signing Tool.

-p motdepasse

Spécifie un mot de passe pour la base de données de clés privées. Notez que le mot de passe saisi sur la ligne de commande est affiché en texte brut.

-s tailleclé

Spécifie la taille de la clé pour le certificat généré. Utilisez l'option -M pour savoir quels jetons sont disponibles. L'option -s ne peut être utilisée qu'avec l'option -G.

-t jeton

Spécifie quel jeton disponible doit générer la clé et recevoir le certificat. Utilisez l'option -M pour savoir quels jetons sont disponibles. L'option -t ne peut être utilisée qu'avec l'option -G.

-v archive

Affiche le contenu d'une archive et vérifie l'intégrité cryptographique des signatures numériques qu'elle contient et des fichiers auxquels elles sont associées. Cela inclut la vérification que le certificat de l'émetteur du certificat de signature d'objet est listé dans la base de données des certificats, que la signature numérique de l'AC sur le certificat de signature d'objet est valide, que les certificats pertinents n'ont pas expiré, etc.

--verbosity valeur

Définit la quantité d'informations générées par Netscape Signing Tool pendant son fonctionnement. Une valeur de 0 (zéro) est la valeur par défaut et donne des informations complètes. Une valeur de -1 supprime la plupart des messages, mais pas les messages d'erreur.

-w archive

Affiche les noms des signataires de tous les fichiers de l'archive.

-x répertoire

Exclut le répertoire spécifié de la signature. Notez qu'avec Netscape Signing Tool version 1.1 et ultérieures, cette option peut apparaître plusieurs fois sur une seule ligne de commande, ce qui permet de spécifier plusieurs répertoires particuliers à exclure.

-z

Indique à signtool de ne pas stocker l'heure de signature dans la signature numérique. Cette option est utile si vous souhaitez que la date d'expiration de la signature soit vérifiée par rapport à la date et à l'heure actuelles plutôt qu'à l'heure de signature des fichiers.

-Z fichier_jar

Crée un fichier JAR portant le nom spécifié. Vous devez spécifier cette option si vous voulez que signtool crée le fichier JAR ; il ne le fait pas automatiquement. Si vous ne spécifiez pas -Z, vous devez utiliser un outil ZIP externe pour créer le fichier JAR. L'option -Z ne peut pas être utilisée en même temps que l'option -J. Si l'option -c# n'est pas utilisée avec l'option -Z, la valeur de compression par défaut est 6.

LE FORMAT DU FICHIER DE COMMANDE

Les entrées dans un fichier de commande Netscape Signing Tool ont le format général suivant : mot-clé=valeur Tout ce qui précède le signe = sur une seule ligne est un mot-clé, et tout ce qui suit le signe = jusqu'à la fin de la ligne est une valeur. La valeur peut inclure des signes = ; seul le premier signe = sur une ligne est interprété. Les lignes vides sont ignorées, mais les espaces blancs sur une ligne avec des mots-clés et des valeurs sont considérés comme faisant partie du mot-clé (s'ils précèdent le signe égal) ou de la valeur (s'ils suivent le premier signe égal). Les mots-clés ne sont pas sensibles à la casse, les valeurs sont généralement sensibles à la casse. Puisque le signe = et le retour à la ligne délimitent la valeur, celle-ci ne doit pas être mise entre guillemets.

Signature d'un fichier

1. Créez un répertoire vide.

mkdir signdir

2. Placez-y un fichier.

echo boo > signdir/test.f

3. Spécifiez le nom de votre certificat de signature d'objet et signez le répertoire.

signtool -k MonCertificatSignature -Z testjar.jar signdir

Utilisation de Netscape Signing Tool avec un utilitaire ZIP

Pour utiliser Netscape Signing Tool avec un utilitaire ZIP, vous devez avoir l'utilitaire dans votre variable d'environnement PATH. Vous devriez utiliser l'utilitaire zip.exe plutôt que pkzip.exe, qui ne peut pas gérer les noms de fichiers longs. Vous pouvez utiliser un utilitaire ZIP au lieu de l'option -Z pour empaqueter une archive signée dans un fichier JAR après l'avoir signée :

cd signdir
zip -r ../myjar.jar *
 ajout de : META-INF/ (stocké 0%)
 ajout de : META-INF/manifest.mf (décomprimé 15%)
 ajout de : META-INF/signtool.sf (décomprimé 28%)
 ajout de : META-INF/signtool.rsa (stocké 0%)
 ajout de : text.txt (stocké 0%)

Génération des clés et du certificat

L'option -G de signtool génère une nouvelle paire de clés publique/privée et un nouveau certificat. Elle prend le pseudonyme du nouveau certificat comme argument. Les clés et le certificat nouvellement générés sont installés dans les bases de données de clés et de certificats du répertoire spécifié par l'option -d. Avec la version NT de Netscape Signing Tool, vous devez utiliser l'option -d avec l'option -G. Avec la version Unix de Netscape Signing Tool, omettre l'option -d permet à l'outil d'installer les clés et le certificat dans les bases de données de clés et de certificats de Communicator. Dans tous les cas, le certificat est également exporté dans un fichier nommé x509.cacert, qui a le type MIME application/x-x509-ca-cert.

Les certificats contiennent des informations standard sur l'entité qu'ils identifient, telles que le nom commun et le nom de l'organisation. Netscape Signing Tool vous demande ces informations lorsque vous exécutez la commande avec l'option -G. Cependant, tous les champs demandés sont facultatifs pour les certificats de test. Si vous ne saisissez pas de nom commun, l'outil fournit un nom par défaut. Dans l'exemple suivant, l'entrée utilisateur est en gras :

signtool -G MonCertificatDeTest
utilisation du répertoire de certificats : /u/someuser/.netscape
Entrez les informations du certificat. Tous les champs sont facultatifs. Les caractères
acceptables sont les chiffres, les lettres, les espaces et les apostrophes.
nom commun du certificat : Certificat de signature d'objet de test
organisation : Netscape Communications Corp.
unité d'organisation : Division des produits serveur
état ou province : Californie
pays (doit comporter exactement 2 caractères) : US
nom d'utilisateur : someuser
adresse e-mail : someuser@netscape.com
Entrez le mot de passe ou le code PIN pour "Base de données de certificats Communicator" : [Le mot de passe ne sera pas affiché]
paire de clés publique/privée générée
demande de certificat générée
certificat signé
certificat "MonCertificatDeTest" ajouté à la base de données
Certificat exporté vers x509.raw et x509.cacert.

Les informations du certificat sont lues depuis l'entrée standard. Par conséquent, les informations peuvent être lues à partir d'un fichier en utilisant l'opérateur de redirection (<) sur certains systèmes d'exploitation. Pour créer un fichier à cet effet, entrez chacun des sept champs d'entrée, dans l'ordre, sur une ligne distincte. Assurez-vous qu'il y a un caractère de nouvelle ligne à la fin de la dernière ligne. Ensuite, exécutez signtool avec l'entrée standard redirigée depuis votre fichier comme suit :

signtool -G MonCertificatDeTest fichier_entree

Les invites s'affichent à l'écran, mais les réponses seront lues automatiquement à partir du fichier. Le mot de passe sera toujours lu depuis la console, sauf si vous utilisez l'option -p pour fournir le mot de passe sur la ligne de commande.

Utilisation de Netscape Signing Tool et d'une carte à puce pour signer des fichiers

La commande signtool prend normalement un argument pour l'option -k afin de spécifier un certificat de signature. Pour signer avec une carte à puce, vous fournissez uniquement le nom complet du certificat.

Pour voir les noms complets des certificats lorsque vous exécutez Communicator, cliquez sur le bouton Sécurité dans Navigator, puis cliquez sur Vos certificats sous Certificats dans le cadre de gauche. Les noms complets sont du format carte à puce:certificat, par exemple "MaCarte:MonCertificatDeSignature". Vous utilisez ce nom avec l'argument -k comme suit :

signtool -k "MaCarte:MonCertificatDeSignature" répertoire
