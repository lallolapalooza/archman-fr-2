DESCRIPTION

Les périphériques audio peuvent exposer un certain nombre de contrôles, comme le contrôle du volume de lecture. Chaque contrôle possède une adresse entière et une valeur entière. Certaines valeurs sont booléennes et ne peuvent être commutées qu'à 0 (désactivé) ou 1 (activé). N'importe quel contrôle peut être modifié en soumettant une nouvelle valeur à son adresse. Lorsque les valeurs changent, des notifications asynchrones sont envoyées.

Les descriptions des contrôles sont disponibles, permettant de les regrouper et de les représenter sous une forme lisible par l'homme.

Ouverture et fermeture du périphérique de contrôle

L'application doit d'abord appeler la fonction sioctl_open() pour obtenir un descripteur qui sera passé comme argument hdl aux autres fonctions.

Le paramètre name donne la chaîne de caractères du périphérique discutée dans sndio(7). Dans la plupart des cas, il devrait être défini à SIO_DEVANY pour permettre à l'utilisateur de le sélectionner en utilisant la variable d'environnement AUDIODEVICE. Le paramètre mode est un masque de bits des constantes SIOCTL_READ et SIOCTL_WRITE indiquant si les valeurs des contrôles peuvent être lues et modifiées respectivement.

Si l'argument nbio_flag est 1, alors la fonction sioctl_setval() (voir ci-dessous) peut échouer au lieu de bloquer et la fonction sioctl_ondesc() ne bloque pas.

La fonction sioctl_close() ferme le périphérique de contrôle et libère toutes les ressources allouées associées au descripteur.

Descriptions des contrôles

La fonction sioctl_ondesc() peut être utilisée pour obtenir la description de tous les contrôles disponibles et leurs valeurs initiales. Elle enregistre une fonction de rappel qui est immédiatement appelée pour tous les contrôles. Elle est appelée une fois avec un argument NULL pour indiquer que la description complète a été envoyée et que l'appelant a une représentation cohérente de l'ensemble des contrôles.

Ensuite, chaque fois que la description d'un contrôle change, la fonction de rappel est appelée avec les informations mises à jour, suivie d'un appel avec un argument NULL.

Les contrôles sont décrits par la structure sioctl_desc comme suit :

struct sioctl_node {
	char name[SIOCTL_NAMEMAX];	/* ex. "spkr" */
	int unit;			/* numéro optionnel ou -1 */
};

struct sioctl_desc {
	unsigned int addr;		/* adresse du contrôle */
#define SIOCTL_NONE		0	/* supprimé */
#define SIOCTL_NUM		2	/* entier dans la plage maxval */
#define SIOCTL_SW		3	/* interrupteur marche/arrêt (1 ou 0) */
#define SIOCTL_VEC		4	/* nombre, élément d'un vecteur */
#define SIOCTL_LIST		5	/* interrupteur, élément d'une liste */
#define SIOCTL_SEL		6	/* élément d'un sélecteur */
	unsigned int type;		/* l'un des éléments ci-dessus */
	char func[SIOCTL_NAMEMAX];	/* nom de la fonction, ex. "level" */
	char group[SIOCTL_NAMEMAX];	/* groupe auquel appartient ce contrôle */
	struct sioctl_node node0;	/* nœud affecté */
	struct sioctl_node node1;	/* dito pour SIOCTL_{VEC,LIST,SEL} */
	unsigned int maxval;		/* valeur maximale */
	char display[SIOCTL_DISPLAYMAX];	/* indice en format libre */
};

L'attribut addr est l'adresse du contrôle, utilisable avec sioctl_setval() pour définir sa valeur.

L'attribut type indique ce que décrit la structure. Les types possibles sont :

SIOCTL_NONE
Un contrôle précédemment valide a été supprimé.
SIOCTL_NUM
Un contrôle entier dans la plage de 0 à maxval, inclus. Par exemple, le volume du haut-parleur.
SIOCTL_SW
Un contrôle booléen. Par exemple, l'interrupteur pour couper le son du haut-parleur.
SIOCTL_VEC
Élément d'un tableau de contrôles entiers. Par exemple, le bouton pour contrôler la quantité de signal provenant de l'entrée ligne vers le haut-parleur.
SIOCTL_LIST
Un élément d'un tableau d'interrupteurs booléens. Par exemple, la position de la source du haut-parleur sélectionnée par l'entrée ligne.
SIOCTL_SEL
Identique à SIOCTL_LIST, mais exactement un élément est sélectionné à la fois.

L'attribut func est le nom du paramètre contrôlé. Il ne peut y avoir de paramètres de types différents portant le même nom.

Les attributs node0 et node1 indiquent les noms des nœuds contrôlés, généralement les canaux des flux audio. node1 est pertinent uniquement pour SIOCTL_VEC, SIOCTL_LIST et SIOCTL_SEL.

Les noms dans les attributs node0 et node1 et func sont des chaînes de caractères utilisables comme identifiants uniques au sein du group donné.

L'attribut maxval indique la valeur maximale de ce contrôle. Pour les types de contrôles booléens, il est défini à 1.

L'attribut display contient une chaîne de caractères facultative en format libre fournissant des indices supplémentaires sur le contrôle, comme le modèle matériel, ou les unités.

Changement et lecture des valeurs des contrôles

Les contrôles sont modifiés avec la fonction sioctl_setval(). Le paramètre addr spécifie le contrôle à modifier, et val sa nouvelle valeur. Cette fonction retourne 0 en cas de succès, et -1 en cas d'erreur. Si la fonction a été ouverte avec l'indicateur nbio_flag à 1, elle peut retourner -1 et définir errno à EAGAIN au lieu de bloquer.

La fonction sioctl_onval() enregistre une fonction de rappel qui est appelée chaque fois qu'un contrôle change de valeur. La fonction de rappel est appelée une première fois pour tous les contrôles actuels, suivie d'un appel avec l'argument addr défini à 0 pour signaler la fin de la mise à jour. Les appels ultérieurs sont effectués uniquement lorsque la valeur d'un contrôle change.

Il est possible d'obtenir la valeur actuelle de tous les contrôles en appelant sioctl_ondesc() avec un paramètre cb défini à NULL.

Attente des événements des contrôles

Les modifications de valeurs de contrôle sont signalées au programme via un descripteur de fichier. La fonction sioctl_nfds() retourne le nombre de descripteurs de fichiers associés au descripteur hdl.

La fonction sioctl_pollfd() remplit la structure pfd avec les informations nécessaires pour utiliser poll(2). Les événements disponibles sont décrits par le masque d'événements retourné par sioctl_pollfd().

Après l'appel à poll(2), la fonction sioctl_revents() indique quels événements se sont effectivement produits.

Enfin, la fonction sioctl_eof() retourne vrai si le périphérique de contrôle a été fermé par le système, ce qui signifie que toutes les fonctions ultérieures échoueront.

Exemples

#include <stdio.h>
#include <stdlib.h>
#include <sndio.h>

struct sioctl_hdl *hdl;
struct pollfd pfd;

static void
val_cb(void *arg, unsigned int addr, unsigned int val)
{
	printf("control %u changed to %u\n", addr, val);
}

int
main(void)
{
	hdl = sioctl_open(SIO_DEVANY, SIOCTL_READ, 0);
	if (!hdl) {
		perror("sioctl_open");
		return 1;
	}

	if (sioctl_onval(hdl, val_cb, NULL) < 0) {
		perror("sioctl_onval");
		goto fail;
	}

	for (;;) {
		if (sioctl_pollfd(hdl, &pfd, POLLIN) < 0) {
			perror("sioctl_pollfd");
			goto fail;
		}
		if (poll(&pfd, 1, -1) < 0) {
			perror("poll");
			goto fail;
		}
		if (sioctl_revents(hdl, &pfd) < 0) {
			perror("sioctl_revents");
			goto fail;
		}
	}

fail:
	sioctl_close(hdl);
	return 1;
}

DESCRIPTION

The sioctl_open() function opens a connection to the sndio(7) server, and returns a handle used for subsequent operations. If path is NULL, the default device specified by the AUDIODEVICE environment variable is used. Otherwise, path specifies the path to the sndio(7) server socket.

The returned handle is a pointer to an opaque structure. It must be passed to all subsequent operations.

The sioctl_close() function closes the connection associated with hdl.

The sioctl_devctl() function performs device-specific control operations. The argument hdl is a handle to the sndio(7) device. The return value is the number of available controls, or -1 on error.

The sioctl_setpar() function sets the audio hardware parameters specified by par. sioctl_getpar() returns the current audio hardware parameters. The sndio(7) parameters are described in sio_open(3).

The sioctl_start(), sioctl_rewind(), and sioctl_stop() functions start, rewind, and stop the audio device, respectively. They return 0 on success, or -1 on error.

The sndio(7) server provides a set of controls, which are indexed integers. The functions sioctl_onval() and sioctl_setval() are used to interact with these controls. The former registers a callback function conv that will be called with the argument ptr whenever the control specified by idx changes its value. The latter function directly sets the value of the control specified by idx to val. Integer values are in the range from 0 to maxval, where maxval is the maximum value for the control, which is implicitly known by the sndio(7) server.

The sndio(7) server can be polled for events using the poll(2) interface. The sioctl_pollfd() function fills the pfd array of pollfd structures with the requested events. The latter is a bitmask of POLLIN and POLLOUT constants. sioctl_pollfd() returns the number of pollfd structures filled. The sioctl_revents() function returns the bitmask set by poll(2) in the pfd array of pollfd structures. If POLLOUT is set, sioctl_setval() can be called without blocking. POLLHUP may be set if an error occurs, even if it is not selected with sioctl_pollfd(). POLLIN is not used yet.

The sioctl_nfds() function returns the number of pollfd structures the caller must preallocate in order to be sure that sioctl_pollfd() will never overrun.

The sioctl_getinfo() function returns information about the default audio device. The sioctl_devinfo() function returns information about the audio device specified by path.

The sioctl_setval() function, by giving the index of the control and the new value. The sioctl_onval() function can be used to register a callback which will be invoked whenever a control changes. Integer values are in the range from 0 to maxval.

Interface to poll(2)

The sioctl_pollfd() function fills the array pfd of pollfd structures, used by poll(2), with events; the latter is a bit-mask of POLLIN and POLLOUT constants. sioctl_pollfd() returns the number of pollfd structures filled. The sioctl_revents() function returns the bit-mask set by poll(2) in the pfd array of pollfd structures. If POLLOUT is set, sioctl_setval() can be called without blocking. POLLHUP may be set if an error occurs, even if it is not selected with sioctl_pollfd(). POLLIN is not used yet.

The sioctl_nfds() function returns the number of pollfd structures the caller must preallocate in order to be sure that sioctl_pollfd() will never overrun.
