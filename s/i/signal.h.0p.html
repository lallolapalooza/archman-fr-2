signal.h(0p) Manuel du programmeur POSIX signal.h(0p)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

signal.h — signaux

SYNOPIS

#include <signal.h>

DESCRIPTION

Certaines fonctionnalités décrites sur cette page de référence étendent la norme ISO C. Les applications doivent définir la macro de test de fonctionnalité appropriée (voir le volume Interfaces Système de POSIX.1-2017, *Section 2.2*, *L'environnement de compilation*) pour activer la visibilité de ces symboles dans cet en-tête.

L'en-tête <signal.h> définira les macros suivantes, qui s'étendront à des expressions constantes ayant des valeurs distinctes de type compatible avec le deuxième argument de, et la valeur de retour de, la fonction signal(), et dont les valeurs seront inégales à l'adresse de toute fonction déclarable.

SIG_DFL
Requête de traitement par défaut du signal.
SIG_ERR
Valeur de retour de signal() en cas d'erreur.
SIG_HOLD
Requête de mise en attente du signal.
SIG_IGN
Requête d'ignorance du signal.

L'en-tête <signal.h> définira les types pthread_t, size_t et uid_t tels que décrits dans <sys/types.h>.

L'en-tête <signal.h> définira la structure timespec telle que décrite dans <time.h>.

L'en-tête <signal.h> définira les types de données suivants :

sig_atomic_t
Type entier potentiellement qualifié comme volatile d'un objet pouvant être accédé comme une entité atomique, même en présence d'interruptions asynchrones.
sigset_t
Type entier ou structure d'un objet utilisé pour représenter des ensembles de signaux.
pid_t
Tel que décrit dans <sys/types.h>.

L'en-tête <signal.h> définira le type pthread_attr_t tel que décrit dans <sys/types.h>.

L'en-tête <signal.h> définira la structure sigevent, qui comprendra au moins les membres suivants :

int              sigev_notify            Type de notification.
int              sigev_signo             Numéro de signal.
union sigval     sigev_value             Valeur du signal.
void           (*sigev_notify_function)(union sigval)
                                         Fonction de notification.
pthread_attr_t *sigev_notify_attributes  Attributs de notification.

L'en-tête <signal.h> définira les constantes symboliques suivantes pour les valeurs de sigev_notify :

SIGEV_NONE
Aucune notification asynchrone n'est livrée lorsque l'événement d'intérêt se produit.
SIGEV_SIGNAL
Un signal mis en file d'attente, avec une valeur définie par l'application, est généré lorsque l'événement d'intérêt se produit.
SIGEV_THREAD
Une fonction de notification est appelée pour effectuer la notification.

L'union sigval sera définie comme suit :

int    sival_int    Valeur entière du signal.
void  *sival_ptr    Valeur du pointeur du signal.

L'en-tête <signal.h> déclarera les macros SIGRTMIN et SIGRTMAX, qui s'étendront à des expressions entières positives de type int, mais qui ne sont pas nécessairement des expressions constantes. Ces macros spécifient une plage de numéros de signaux réservés à l'usage des applications et pour lesquels le comportement des signaux temps réel spécifié dans ce volume de POSIX.1-2017 est pris en charge. Les numéros de signaux dans cette plage ne se chevauchent pas avec les signaux spécifiés dans le tableau suivant.

La plage SIGRTMIN à SIGRTMAX inclusive comprendra au moins {RTSIG_MAX} numéros de signaux.

Il est défini par l'implémentation si le comportement des signaux temps réel est pris en charge pour d'autres signaux.

L'en-tête <signal.h> définira les macros suivantes utilisées pour faire référence aux signaux qui se produisent dans le système. Les signaux définis ici commencent par les lettres SIG suivies d'une lettre majuscule. Les macros s'étendront à des expressions constantes entières positives de type int et à des valeurs distinctes. La valeur 0 est réservée pour l'usage comme signal nul (voir kill()). Des signaux supplémentaires définis par l'implémentation peuvent se produire dans le système.

La norme ISO C ne requiert que les noms de signaux SIGABRT, SIGFPE, SIGILL, SIGINT, SIGSEGV et SIGTERM. Une implémentation n'est pas tenue de générer l'un de ces six signaux, sauf à la suite d'une utilisation explicite d'interfaces qui génèrent des signaux, telles que raise(), kill(), l'interface de terminal générale (voir Section 11.1.9, Caractères spéciaux), et l'utilitaire kill, sauf indication contraire (voir, par exemple, le volume Interfaces Système de POSIX.1-2017, Section 2.8.3.3, Protection de la mémoire).

Les signaux suivants seront pris en charge sur toutes les implémentations (les actions par défaut sont expliquées sous le tableau) :

Les actions par défaut sont les suivantes :

T
Terminaison anormale du processus.
A
Terminaison anormale du processus avec actions supplémentaires.
I
Ignorer le signal.
S
Arrêter le processus.
C
Continuer le processus, s'il est arrêté ; sinon, ignorer le signal.

Les effets sur le processus dans chaque cas sont décrits dans le volume Interfaces Système de POSIX.1-2017, Section 2.4.3, Actions de Signal.

L'en-tête <signal.h> doit déclarer la structure sigaction, qui doit inclure au moins les membres suivants :

void   (*sa_handler)(int)  Pointeur vers une fonction de capture de signal
                           ou l'un des SIG_IGN ou SIG_DFL.
sigset_t sa_mask           Ensemble de signaux à bloquer pendant l'exécution
                           de la fonction de gestion des signaux.
int      sa_flags          Indicateurs spéciaux.
void   (*sa_sigaction)(int, siginfo_t *, void *)
                           Pointeur vers une fonction de capture de signal.

L'espace mémoire occupé par sa_handler et sa_sigaction peut se chevaucher, et une application conforme ne doit pas utiliser les deux simultanément.

L'en-tête <signal.h> doit définir les macros suivantes qui s'étendront à des expressions constantes entières qui n'ont pas besoin d'être utilisables dans les directives de préprocesseur #if :

SIG_BLOCK
L'ensemble résultant est l'union de l'ensemble actuel et de l'ensemble de signaux pointé par l'argument set.
SIG_UNBLOCK
L'ensemble résultant est l'intersection de l'ensemble actuel et du complément de l'ensemble de signaux pointé par l'argument set.
SIG_SETMASK
L'ensemble résultant est l'ensemble de signaux pointé par l'argument set.

L'en-tête <signal.h> doit également définir les constantes symboliques suivantes :

SA_NOCLDSTOP
Ne pas générer SIGCHLD lors de l'arrêt des enfants
ou de la reprise des enfants arrêtés.
SA_ONSTACK
Cause la livraison du signal sur une pile alternative.
SA_RESETHAND
Cause la définition des dispositions de signal à SIG_DFL lors de l'entrée dans les gestionnaires de signaux.
SA_RESTART
Cause le redémarrage de certaines fonctions.
SA_SIGINFO
Cause la transmission d'informations supplémentaires aux gestionnaires de signaux au moment de la réception d'un signal.
SA_NOCLDWAIT
Cause aux implémentations de ne pas créer de processus zombies ou d'informations d'état lors de la terminaison d'un enfant. Voir sigaction().
SA_NODEFER
Cause le signal à ne pas être automatiquement bloqué à l'entrée du gestionnaire de signaux.
SS_ONSTACK
Le processus s'exécute sur une pile de signaux alternative.
SS_DISABLE
La pile de signaux alternative est désactivée.
MINSIGSTKSZ
Taille minimale de pile pour un gestionnaire de signaux.
SIGSTKSZ
Taille par défaut en octets pour la pile de signaux alternative.

void     *ss_sp       Base ou pointeur de la pile.

APPLICATION USAGE

Sur les systèmes qui ne prennent pas en charge l'option XSI, les membres si_pid et si_uid de siginfo_t ne sont requis que lorsqu'ils sont valides lorsque si_code est SI_USER ou SI_QUEUE. Sur les systèmes conformes à XSI, ils sont également valides pour toutes les valeurs de si_code inférieures ou égales à 0 ; cependant, il n'est pas spécifié si SI_USER et SI_QUEUE ont des valeurs inférieures ou égales à zéro, et donc les applications XSI devraient vérifier si si_code a la valeur SI_USER ou SI_QUEUE ou est inférieur ou égal à 0 pour savoir si si_pid et si_uid sont valides.

FUTURE DIRECTIONS
