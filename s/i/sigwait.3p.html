SIGWAIT(3P) Manuel du programmeur POSIX SIGWAIT(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sigwait — attendre des signaux mis en file d'attente

SYNTAXE

#include <signal.h>
int sigwait(const sigset_t *restrict set, int *restrict sig);

DESCRIPTION

La fonction sigwait() sélectionne un signal en attente dans set, le supprime atomiquement de l'ensemble des signaux en attente du système, et renvoie ce numéro de signal dans l'emplacement référencé par sig. Si avant l'appel à sigwait(), il y a plusieurs instances en attente d'un même numéro de signal, il est indéfini si, après un retour réussi, il reste des signaux en attente pour ce numéro de signal. Si l'implémentation prend en charge les signaux mis en file d'attente et que plusieurs signaux sont mis en file d'attente pour le numéro de signal sélectionné, le premier signal de ce type mis en file d'attente provoquera un retour de sigwait() et les restants resteront en file d'attente. Si aucun signal dans set n'est en attente au moment de l'appel, le thread sera suspendu jusqu'à ce qu'un ou plusieurs deviennent en attente. Les signaux définis par set doivent avoir été bloqués au moment de l'appel à sigwait() ; sinon, le comportement est indéfini. L'effet de sigwait() sur les actions de signal pour les signaux dans set est indéterminé.

Si plus d'un thread utilise sigwait() pour attendre le même signal, pas plus d'un de ces threads ne retournera de sigwait() avec le numéro de signal. Si plus d'un thread est bloqué dans sigwait() pour un signal lorsque ce signal est généré pour le processus, il est indéterminé lequel des threads en attente retournera de sigwait(). Si le signal est généré pour un thread spécifique, comme par pthread_kill(), seul ce thread retournera.

Si plusieurs signaux en attente dans la plage SIGRTMIN à SIGRTMAX sont sélectionnés, ce sera celui ayant le plus petit numéro. L'ordre de sélection entre les signaux temps réel et non temps réel, ou entre plusieurs signaux non temps réel en attente, est indéterminé.

VALEUR DE RETOUR

En cas de succès, sigwait() stockera le numéro du signal reçu à l'emplacement référencé par sig et retournera zéro. Sinon, un numéro d'erreur sera retourné pour indiquer l'erreur.

ERREURS

La fonction sigwait() peut échouer si :

EINVAL
L'argument set contient un numéro de signal invalide ou non pris en charge.

RATIONALE

Pour fournir un moyen pratique à un thread d'attendre un signal, ce volume de POSIX.1‐2017 fournit la fonction sigwait(). Pour la plupart des cas où un thread doit attendre un signal, la fonction sigwait() devrait être très pratique, efficace et adéquate.

Cependant, des demandes ont été faites pour une primitive de plus bas niveau que sigwait() et pour des sémaphores qui pourraient être utilisés par des threads. Après une certaine réflexion, les threads ont été autorisés à utiliser des sémaphores et sem_post() a été défini comme étant sûr en cas de signal asynchrone.

En résumé, lorsqu'il est nécessaire que le code exécuté en réponse à un signal asynchrone notifie un thread, sigwait() doit être utilisé pour gérer le signal. Alternativement, si l'implémentation fournit des sémaphores, ils peuvent également être utilisés, soit après sigwait() soit depuis une routine de gestion de signal précédemment enregistrée avec sigaction().
