NOM

apptainer-exec - Exécute une commande dans un conteneur

SYNTAXE

apptainer exec [options_exec...]

DESCRIPTION

apptainer exec supporte les formats suivants :

*.sif Format d'image Singularity (SIF). Natif à Singularity
(3.0+) et Apptainer (v1.0.0+)

*.sqsh Format SquashFS. Natif à Singularity 2.4+

*.img Format ext3. Natif aux versions de Singularity < 2.4.

directory/ Format sandbox. Répertoire contenant un système de fichiers racine valide
et éventuellement des métadonnées Apptainer.

instance://* Une instance locale en cours d'exécution d'un conteneur. (Voir le groupe de commandes
instance.)

library://* Un conteneur SIF hébergé sur une Librairie (pas de défaut)

docker://* Un conteneur Docker/OCI hébergé sur Docker Hub ou un autre
registre OCI.

shub://* Un conteneur hébergé sur Singularity Hub.

oras://* Un conteneur SIF hébergé sur un registre OCI qui supporte
la spécification OCI Registry As Storage (ORAS).

OPTIONS

--add-caps="" une liste de capacités séparées par des virgules à ajouter

--allow-setuid[=false] autoriser les binaires setuid dans le conteneur (root uniquement)

--app="" définir une application à exécuter dans un conteneur

--apply-cgroups="" appliquer les cgroups à partir d'un fichier pour les processus du conteneur (root uniquement)

--authfile="" fichier d'authentification de type Docker à utiliser pour écrire/lire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de liaison par l'utilisateur. spec a le format src[:dest[:opts]], où src et dest sont les chemins extérieurs et intérieurs. Si dest n'est pas donné, il est égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, ce qui est la valeur par défaut). Plusieurs chemins de liaison peuvent être donnés par une liste séparée par des virgules.

--blkio-weight=0 poids relatif du Block IO dans la plage 10-1000, 0 pour désactiver

--blkio-weight-device=[] poids relatif du Block IO spécifique au périphérique

-e, --cleanenv[=false] nettoyer l'environnement avant d'exécuter le conteneur

--compat[=false] appliquer les paramètres pour une compatibilité OCI/Docker accrue. Infère --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] utiliser un /dev minimal et vider d'autres répertoires (par exemple /tmp et $HOME) au lieu de partager les systèmes de fichiers de votre hôte

-C, --containall[=false] contenir non seulement les systèmes de fichiers, mais aussi les PID, IPC et l'environnement

--cpu-shares=-1 parts CPU pour le conteneur

--cpus="" nombre de CPU disponibles pour le conteneur

--cpuset-cpus="" liste des CPU de l'hôte disponibles pour le conteneur

--cpuset-mems="" liste des nœuds mémoire de l'hôte disponibles pour le conteneur

--cwd="" répertoire de travail initial pour le processus payload à l'intérieur du conteneur (synonyme de --pwd)

--disable-cache[=false] ne pas utiliser ni créer de cache

--dns="" liste de serveurs DNS séparés par des virgules à ajouter dans resolv.conf

--docker-host="" spécifier un hôte de démon Docker personnalisé

--docker-login[=false] se connecter à un dépôt Docker interactivement

--drop-caps="" une liste de capacités séparées par des virgules à supprimer

--env=[] passer une variable d'environnement au processus contenu

--env-file=[] passer des variables d'environnement depuis un fichier au processus contenu

-f, --fakeroot[=false] exécuter le conteneur avec l'apparence d'une exécution en tant que root

--fusemount=[] une spécification de montage de système de fichiers FUSE de la forme ': ' - où est 'container' ou 'host', spécifiant où le montage sera effectué ('container-daemon' ou 'host-daemon' exécutera le processus FUSE détaché). est le chemin vers l'exécutable FUSE, plus les options pour le montage. est l'emplacement dans le conteneur où le montage FUSE sera attaché. Par exemple 'container:sshfs 10.0.0.1:/ /sshfs'. Implique --pid.

-h, --help[=false] aide pour exec

-H, --home="/build" une spécification de répertoire personnel. spec peut être un chemin src ou une paire src:dest. src est le chemin source du répertoire personnel à l'extérieur du conteneur et dest remplace le répertoire personnel à l'intérieur du conteneur.

--hostname="" définir le nom d'hôte du conteneur

-i, --ipc[=false] exécuter le conteneur dans un nouveau espace de noms IPC

--keep-privs[=false] laisser l'utilisateur root conserver ses privilèges dans le conteneur (root uniquement)

--memory="" limite de mémoire en octets

--memory-reservation="" limite douce de mémoire en octets

--memory-swap="" limite de swap, utiliser -1 pour un swap illimité

--mount=[] une spécification de montage par ex. 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] exécuter le conteneur dans un nouveau espace de noms réseau (met en place une interface réseau bridge par défaut)

--netns-path="" rejoindre l'espace de noms réseau au chemin spécifié (en tant que root, ou si autorisé dans apptainer.conf)

--network="" spécifier le type de réseau souhaité séparé par des virgules, chaque réseau mettra en place une interface dédiée à l'intérieur du conteneur

--network-args=[] spécifier les arguments réseau à passer aux plugins CNI

--no-eval[=false] ne pas évaluer shell les variables d'env ou les CMD/ENTRYPOINT/ARGS de conteneur OCI

--no-home[=false] ne PAS monter le répertoire personnel de l'utilisateur si /home n'est pas le répertoire de travail courant

--no-https[=false] utiliser http au lieu de https pour les URI docker://, oras:// et library:///...

--no-init[=false] ne PAS démarrer le processus shim avec --pid

--no-mount=[] désactiver une ou plusieurs options 'mount xxx' définies dans apptainer.conf et/ou spécifier un chemin de destination absolu pour désactiver une entrée de chemin de liaison, ou 'bind-paths' pour désactiver toutes les entrées de chemin de liaison.

--no-pid[=false] ne pas exécuter le conteneur dans un nouveau espace de noms PID

--no-privs[=false] supprimer tous les privilèges de l'utilisateur root dans le conteneur)

--no-umask[=false] ne pas propager le umask au conteneur, définir un umask par défaut 0022

--nv[=false] activer le support Nvidia

--nvccli[=false] utiliser nvidia-container-cli pour la configuration GPU (expérimental)

--oom-kill-disable[=false] Désactiver le tueur OOM

-o, --overlay=[] utiliser une image overlayFS pour le stockage persistant de données ou comme couche en lecture seule du conteneur

--passphrase[=false] demander une phrase secrète de chiffrement

--pem-path="" entrer un chemin vers une clé RSA au format PEM pour un conteneur chiffré

-p, --pid[=false] exécuter le conteneur dans un nouveau espace de noms PID

--pids-limit=0 limiter le nombre de PID du conteneur, utiliser -1 pour illimité

--rocm[=false] activer le support Rocm expérimental

-S, --scratch=[] inclure un répertoire scratch dans le conteneur qui est lié à un répertoire temporaire (utiliser -W pour forcer l'emplacement)

--security=[] activer les fonctionnalités de sécurité (SELinux, Apparmor, Seccomp)

--sharens[=false] partager l'espace de noms et l'image avec d'autres conteneurs lancés à partir du même processus parent

--unsquash[=false] Convertir le fichier SIF en sandbox temporaire avant d'exécuter

-u, --userns[=false] exécuter le conteneur dans un nouveau espace de noms utilisateur

--uts[=false] exécuter le conteneur dans un nouveau espace de noms UTS

-W, --workdir="" répertoire de travail à utiliser pour /tmp, /var/tmp et $HOME (si -c/--contain a également été utilisé)

-w, --writable[=false] par défaut, tous les conteneurs Apptainer sont accessibles en lecture seule. Cette option rend le système de fichiers accessible en lecture/écriture.

--writable-tmpfs[=false] rend le système de fichiers accessible en lecture/écriture avec des données non persistantes (avec support overlay uniquement)

EXEMPLE

  $ apptainer exec /tmp/debian.sif cat /etc/debian_version
  $ apptainer exec /tmp/debian.sif python ./hello_world.py
  $ cat hello_world.py | apptainer exec /tmp/debian.sif python
  $ sudo apptainer exec --writa

apptainer-exec(1) — Arch manual pages

NAME

apptainer-exec - Execute a command inside a container

SYNOPSIS

apptainer exec [--bind<src>:<dest>[:ro]] [--cleanenv] [--contain] [--containall] [--env<KEY>=value] [--env-file<file>] [--gpu] [--ignore-missing] [--network<type>] [--no-home] [--no-mount<type>] [--overlay<path>[:ro]] [--overlay-format<format>] [--pid-namespace] [--private-cloud<file>] [--writable] [--] container command [argument...

DESCRIPTION

Run a command within the context of a container. The container can be a Singularity Image Format (SIF) file, a directory (sandbox), or a remote library resource. The container will be made available read-only by default, unless the --writable option is specified.

The command and its arguments are executed within the container environment. Standard input, output, and error streams are connected to the host.

By default, the following host directories are automatically bound into the container:

  • ~/ (Home directory)
  • /tmp
  • /proc
  • /sys

The default behavior can be modified using options like --no-home, --no-mount, and --bind.

OPTIONS

A list of options is available in the full manual page. Commonly used options include:

--bind, -B <src>:<dest>[:ro]
Bind mount a directory from the host into the container. The mount can be made read-only by appending :ro. Multiple --bind options can be used.
--cleanenv
Clean most of the environment variables, keeping only a minimal set. This helps to ensure a clean execution environment.
--contain
Run the container in a contained environment, limiting access to host system resources.
--containall
Run the container in a fully contained environment, restricting access to almost all host system resources.
--env, -e <KEY>=value
Set an environment variable within the container. This overrides any value that might be set within the container.
--env-file <file>
Read and set environment variables from a file within the container.
--gpu
Enable GPU support within the container, if available on the host.
--ignore-missing
Do not fail if a mount point or overlay is missing.
--network <type>
Set the network type for the container (e.g., bridge, host).
--no-home
Do not bind the user's home directory into the container.
--no-mount <type>
Disable the automatic mounting of a specific type of directory (e.g., home, tmp).
--overlay <path>[:ro]
Use an overlay filesystem at the specified path. The overlay can be made read-only by appending :ro.
--overlay-format <format>
Specify the format of the overlay filesystem (e.g., ext3).
--pid-namespace
Share the host's PID namespace with the container.
--private-cloud <file>
Specify a private cloud configuration file.
--writable, -w
Make the container filesystem writable. Be cautious when using this option, as changes will affect the container image itself.
--
Separate options from the container and command. Anything after this is treated as part of the container path or command.

EXAMPLE

$ apptainer exec /tmp/debian.sif apt-get update
  $ apptainer exec instance://my_instance ps -ef
  $ apptainer exec library://centos cat /etc/os-release
