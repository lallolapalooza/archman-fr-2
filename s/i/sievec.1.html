NOM

sievec - Compilateur de scripts Sieve de Pigeonhole

SYNOPSIS

sievec [options] fichier-script [fichier-sortie]

DESCRIPTION


La commande sievec fait partie de Pigeonhole (pigeonhole(7)), qui ajoute le support Sieve (RFC 5228) et ManageSieve (RFC 5804) à Dovecot (dovecot(1)).


La commande sievec permet de compiler des scripts Sieve en une représentation binaire. Le binaire résultant peut être utilisé directement pour traiter les messages électroniques lors du processus de livraison. La livraison des messages électroniques et, au moyen du plugin Sieve du LDA, également l'exécution des scripts Sieve, est effectuée par l'agent de livraison locale (LDA) de Dovecot, appelé dovecot-lda(1).

La compilation automatique est effectuée par dovecot-lda(1) si le binaire est absent. Cependant, dans certains cas, dovecot-lda(1) n'a pas l'autorisation d'écrire le binaire compilé sur disque, le forçant à recompiler le script chaque fois qu'il est exécuté. L'utilisation de la commande sievec permet de créer ce fichier binaire à l'avance.

L'implémentation Sieve de Pigeonhole reconnaît les fichiers avec une extension .sieve comme des scripts Sieve et les fichiers correspondants avec une extension .svbin comme les binaires compilés associés. Cela signifie, par exemple, que le processus LDA de Dovecot recherchera d'abord un fichier binaire "dovecot.svbin" lorsqu'il devra exécuter "dovecot.sieve". Il compilera un nouveau binaire s'il est manquant ou obsolète.


Avec l'option -d, il est possible de générer une sortie textuelle (et donc lisible par l'homme) du code Sieve généré vers le fichier spécifié. La sortie est alors identique à ce que produit la commande sieve-dump(1) pour un fichier binaire stocké. Cette sortie est principalement utile pour trouver des bugs dans le compilateur qui produisent des binaires corrompus.

OPTIONS

-c fichier-config

Chemin alternatif du fichier de configuration Dovecot.

-d


L'argument fichier-sortie peut également être omis, ce qui a le même effet que '-'. La sortie est identique à ce que produit la commande sieve-dump(1) pour un fichier binaire Sieve compilé. Notez que cette option n'est pas autorisée lorsque l'argument fichier-script est un répertoire.

-D

Activer le débogage Sieve.

-o parametre=valeur

Remplace le parametre de configuration de /etc/dovecot/dovecot.conf et de la base d'utilisateurs par la valeur donnée. Pour remplacer plusieurs paramètres, l'option -o peut être spécifiée plusieurs fois.

-u utilisateur/masque

Exécute la commande uniquement pour l'utilisateur donné. Il est également possible d'utiliser les jokers '*' et '?' (par exemple -u *@example.org).

-x auth_info

auth_info spécifie des conditions supplémentaires pour la commande user. La chaîne d'option auth_info doit être donnée sous la forme d'une paire nom = valeur. Pour plusieurs conditions, l'option -x peut être fournie plusieurs fois.

Noms possibles pour auth_info :

service

Le service pour lequel la recherche userdb doit être testée. La valeur peut être le nom d'un service couramment utilisé avec Dovecot. Par exemple : imap, pop3 ou smtp.

session

Identifiant de session.

lip

L'adresse IP locale (serveur) pour le test.

rip

L'adresse IP distante (client) pour le test.

lport

Le port local, par exemple 143

rport

Le port distant, par exemple 24567

real_lip

L'adresse IP locale à laquelle le client s'est connecté sur cet hôte.

real_rip

L'adresse IP distante à laquelle le client s'est connecté sur cet hôte.

real_lport

Le port local auquel le client s'est connecté sur cet hôte.

real_rport

Le port distant à partir duquel le client s'est connecté sur cet hôte.

forward_<champ>

Champ à transférer sous la forme %{forward:champ} au processus d'authentification.

ARGUMENTS

fichier-script

Spécifie le script à compiler. Si l'argument fichier-script est un répertoire, tous les fichiers de ce répertoire avec une extension .sieve sont compilés en un fichier binaire .svbin correspondant. La compilation ne s'arrête pas en cas d'erreurs ; elle tente de compiler autant de scripts que possible dans le répertoire. Notez que l'option -d et l'argument fichier-sortie ne sont pas autorisés lorsque l'argument fichier-script est un répertoire.

fichier-sortie

Spécifie où la sortie (binaire) doit être écrite. Cet argument est optionnel. Si cet argument est omis, un binaire compilé à partir de <nom_script>.sieve est enregistré sous le nom <nom_script>.svbin. Si cet argument est omis et que -b est spécifié, la sortie binaire est dirigée vers stdout.

ÉTAT DE SORTIE

sievec se terminera avec l'une des valeurs suivantes :

0

La compilation a réussi. (EX_OK, EXIT_SUCCESS)

1

L'opération a échoué. Ceci est retourné pour presque tous les échecs. (EXIT_FAILURE)

64

Paramètre invalide fourni. (EX_USAGE)

67

L'utilisateur n'existe pas.

68

Fichier d'entrée, adresse ou autre ressource inexistante.

73

Impossible de créer le fichier de sortie.

77

Erreur de permission.

78

Erreur de configuration.

127

Erreur inconnue.

FICHIERS

/etc/dovecot/dovecot.conf

Fichier de configuration principal de Dovecot.

/etc/dovecot/conf.d/90-sieve.conf

Paramètres de l'interpréteur Sieve (inclus depuis le fichier de configuration principal de Dovecot)

Signalez les bugs, y compris la sortie de doveconf -n, à la liste de diffusion Dovecot ⟨dovecot@dovecot.org⟩. Des informations sur le signalement des bugs sont disponibles sur : https://dovecot.org/bugreport.html

sievec(1)

sievec — Compilateur pour Sieve.

NOM

sievec — Compilateur pour Sieve

SYNTAXE

sievec [-c domaine] [-C] [-d domaine] [-D] [-e liste_de_modules] [-F] [-h] [-I chemin] [-L] [-m liste_de_modules] [-o paramètre=valeur] [-p paquet_de_modules] [-q] [-r] [-s] [-t] [-V] [-w liste_de_messages] [script_sieve...]

DESCRIPTION

Le programme sievec est un compilateur pour le langage Sieve. Sieve est un langage de filtrage de courrier conçu pour être utilisé côté serveur. Il est particulièrement utile pour les systèmes qui n'autorisent pas l'exécution de code arbitraire. Le programme sievec prend un ou plusieurs scripts Sieve et les compile en un format binaire optimisé. Il vérifie également la syntaxe et la sémantique des scripts, et signale les erreurs.

Le langage Sieve est défini dans la RFC 5228 et ses extensions. Le programme sievec prend en charge la plupart des extensions communes, mais peut nécessiter une configuration spécifique pour certaines d'entre elles. Les scripts Sieve sont généralement stockés dans le répertoire de l'utilisateur (par exemple, ~/.dovecot.sieve) ou dans des répertoires spécifiques au serveur.

OPTIONS

-c domaine
Spécifie un domaine pour la compilation. Peut être utilisé pour lier des variables ou des règles spécifiques à un domaine.
-C
Active la compilation conditionnelle, permettant d'utiliser des blocs &&if et &&elsif dans les scripts.
-d domaine
Définit le domaine de destination pour les scripts compilés. Utile lors de la compilation pour plusieurs domaines.
-D
Active la sortie de débogage détaillée pendant la compilation.
-e liste_de_modules
Spécifie une liste de modules Sieve à évaluer et à utiliser pendant la compilation. Les modules sont séparés par des virgules.
-F
Force la compilation même si des avertissements sont présents.
-h
Affiche un message d'aide et quitte.
-I chemin
Ajoute un répertoire au chemin de recherche des scripts Sieve et des modules. Peut être spécifié plusieurs fois.
-L
Évalue les variables et les expressions locales avant la compilation, produisant un script plus simple.
-m liste_de_modules
Charge les modules Sieve spécifiés. Les modules sont séparés par des virgules. Ceci est similaire à -e mais se concentre sur le chargement des modules pour l'exécution.
-o paramètre=valeur
Définit une option de configuration spécifique pour le compilateur. La liste des paramètres disponibles dépend de la version et de la configuration de sievec.
-p paquet_de_modules
Spécifie un paquet de modules Sieve à utiliser. Utile pour organiser les extensions.
-q
Mode silencieux. Supprime la plupart des messages de sortie, ne signalant que les erreurs critiques.
-r
Désactive la validation des règles de redirect. Peut être utile dans des environnements spécifiques.
-s
Désactive la validation des règles de stop. Généralement utilisé pour des raisons de compatibilité ou des cas d'utilisation particuliers.
-t
Active le mode de test. Peut modifier le comportement pour faciliter les tests unitaires des scripts Sieve.
-V
Affiche la version du programme et quitte.
-w liste_de_messages
Spécifie quels types de messages d'avertissement doivent être affichés. La liste est séparée par des virgules (par exemple, -w all,-syntax pour tout afficher sauf les erreurs de syntaxe).

ARGUMENTS

script_sieve...

Un ou plusieurs chemins vers les fichiers de scripts Sieve à compiler. Si aucun fichier n'est spécifié, sievec lit depuis l'entrée standard.

CODES DE RETOUR

0 : Compilation réussie.

>0 : Une erreur s'est produite pendant la compilation.

FICHIERS

~/.dovecot.sieve
Le script Sieve par défaut pour l'utilisateur.
/etc/dovecot/sieve-scripts/
Un répertoire commun pour les scripts Sieve système.

SIGNALEMENT DE BUGS

Veuillez signaler les bugs sur le système de suivi des bugs de Dovecot : https://github.com/dovecot/pigeonhole/issues
