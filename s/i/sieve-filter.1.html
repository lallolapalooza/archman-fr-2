NOM

sieve-filter - Outil de filtrage de boîtes aux lettres Sieve de Pigeonhole

Cet outil est encore expérimental. Lisez attentivement ce manuel et sauvegardez tout courrier important avant d'utiliser cet outil. Notez également que certaines des fonctionnalités décrites ici ne sont pas encore implémentées ; cela est clairement indiqué le cas échéant.

SYNTAXE

sieve-filter [options] fichier-script boîte-source [action-rejet]

DESCRIPTION


la commande fait partie de Pigeonhole (pigeonhole(7)), qui ajoute le support de Sieve (RFC 5228) et ManageSieve (RFC 5804) à Dovecot (dovecot(1)).

Le langage Sieve était à l'origine destiné au filtrage des messages lors de la livraison. Cependant, il y a des occasions où il est souhaitable de filtrer les messages déjà stockés dans une boîte aux lettres, par exemple lorsqu'un bug dans un script Sieve a causé la mauvaise livraison de nombreux messages. En utilisant l'outil sieve-filter, il est possible d'appliquer un script Sieve sur tous les messages d'une boîte-source particulière, permettant de supprimer des messages, de les stocker dans une autre boîte aux lettres, de modifier leur contenu et de changer les drapeaux IMAP et les mots-clés assignés. Les tentatives d'envoi de messages vers le monde extérieur sont ignorées par défaut pour des raisons évidentes, mais, en utilisant les options de ligne de commande appropriées, il est possible de capturer et de gérer également les courriers sortants.

Si aucune option n'est spécifiée, la commande sieve-filter s'exécute en mode simulation dans lequel elle ne fait qu'imprimer ce qui serait effectué, sans rien faire réellement. Utilisez l'option -e pour activer l'exécution réelle du script. De plus, la boîte-source est ouverte en lecture seule par défaut, ce qui signifie qu'elle reste normalement inchangée. Utilisez l'option -W pour autoriser les modifications dans la boîte-source.

Même avec l'option -W activée, les messages de la boîte-source ne sont que potentiellement modifiés ou déplacés vers un autre dossier. Les messages ne sont jamais perdus à moins qu'une action-rejet autre que keep (par défaut) ne soit spécifiée. Si le filtre Sieve décide de stocker le message dans la boîte-source, où il existe évidemment déjà, il n'y est jamais dupliqué. Dans ce cas, les drapeaux IMAP du message original peuvent être modifiés par l'interpréteur Sieve en utilisant l'extension imap4flags, à condition que -W soit spécifié. Si le message lui-même est modifié par l'interpréteur Sieve (par exemple en utilisant l'extension editheader), un nouveau message est stocké et l'ancien est effacé. Cependant, si -W est omis, le message original reste intact et les modifications sont rejetées.

ATTENTION

Bien que ce soit un outil très utile, il peut également être très destructeur s'il est mal utilisé. Un petit bug dans votre script Sieve combiné avec les mauvaises options de ligne de commande pourrait entraîner le rejet des mauvais e-mails. Et, même si la boîte-source est ouverte en mode lecture seule pour éviter de tels incidents, elle peut toujours encombrer d'autres boîtes aux lettres avec des copies parasites de vos e-mails si votre script Sieve décide de le faire. Par conséquent, il est conseillé aux utilisateurs de lire attentivement ce manuel et d'utiliser d'abord le mode simulation pour vérifier ce que le script fera. Et, bien sûr :

FAIRE UNE SAUVEGARDE EST IMPÉRATIF POUR TOUT COURRIER IMPORTANT !

OPTIONS

-c fichier-config

Chemin alternatif du fichier de configuration Dovecot.

-C


et son heure de modification est plus récente que le fichier script, il est utilisé et le script n'est pas recompilé. Cette option force la compilation du script, ignorant ainsi tout binaire présent. Référez-vous à sievec(1) pour plus d'informations sur la compilation Sieve.

-d fichier-débogage

Provoque l'écriture d'un vidage du code généré dans le fichier spécifié. Ceci est identique au vidage produit par sieve-dump(1). Utiliser '-' comme nom de fichier provoque l'écriture du vidage dans

-D

Active le débogage Sieve.

-e

Active le mode d'exécution. Par défaut, la commande sieve-filter s'exécute en mode simulation dans lequel elle ne change rien, ce qui signifie qu'aucune boîte aux lettres n'est modifiée d'une quelconque manière et aucune action n'est effectuée. Elle imprime seulement ce qui serait fait. En utilisant cette option, la commande sieve-filter devient active et effectue les actions demandées.

-m boîte-par-défaut

La boîte aux lettres où l'action Sieve implicite keep stocke les messages. C'est la boîte-source par défaut. Spécifier un dossier différent aura pour effet de déplacer (ou copier si -W est omis) tous les messages conservés vers le dossier indiqué, au lieu de simplement les laisser dans la boîte-source. Référez-vous à l'explication de l'argument boîte-source pour plus d'informations sur la dénomination des boîtes aux lettres.

-o paramètre=valeur

Remplace le paramètre de configuration de /etc/dovecot/dovecot.conf et de l'userdb par la valeur donnée. Pour remplacer plusieurs paramètres, l'option -o peut être spécifiée plusieurs fois.

-q boîte-sortie [pas encore implémenté]

Stocke les e-mails sortants dans la boîte-sortie indiquée. Par défaut, la commande sieve-filter ignore les actions Sieve telles que redirect, reject, vacation et notify, mais en utilisant cette option, les messages sortants peuvent être ajoutés à la boîte aux lettres indiquée. Cette option n'a aucun effet en mode simulation. Les drapeaux des messages redirigés ne sont pas conservés.

-Q commande-mail [pas encore implémenté]

Envoie les e-mails sortants (par exemple, ceux produits par redirect, reject et vacation) via le programme spécifié. Par défaut, la commande sieve-filter ignore les actions Sieve telles que redirect, reject, vacation et notify, mais en utilisant cette option, les messages sortants peuvent être transmis à l'entrée standard (stdin) d'une commande shell externe. Cette option n'a aucun effet en mode simulation. À moins que vous ne sachiez vraiment ce que vous faites, N'UTILISEZ PAS CECI POUR ENVOYER DU COURRIER À SENDMAIL !.

-s fichier-script [pas encore implémenté]

Spécifie des scripts supplémentaires à exécuter avant le script principal. Plusieurs arguments -s sont autorisés et les scripts spécifiés sont exécutés séquentiellement dans l'ordre spécifié sur la ligne de commande.

-u utilisateur/masque

Exécute la commande uniquement pour l'utilisateur donné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par exemple, -u *@example.org).

-v

Produit une sortie détaillée pendant le filtrage.

-W

Active l'accès en écriture à la boîte-source. Cela permet de (re)placer les messages depuis la boîte-source, de modifier leur contenu et de changer les drapeaux IMAP et les mots-clés assignés.

-x auth_info

auth_info spécifie des conditions supplémentaires pour la commande user. La chaîne d'options auth_info doit être donnée sous la forme de paire nom = valeur. Pour plusieurs conditions, l'option -x peut être fournie plusieurs fois.

Les noms possibles pour auth_info sont :

service

Le service pour lequel la recherche userdb doit être testée. La valeur peut être le nom d'un service, couramment utilisé avec Dovecot. Par exemple : imap, pop3 ou smtp.

session

Identifiant de session.

lip

L'adresse IP locale (serveur) pour le test.

rip

L'adresse IP distante (client) pour le test.

lport

Le port local (serveur) pour le test.

rport

Le port distant (client) pour le test.

sieve-filter(1) — pigeonhole — Arch Linux

NOM

sieve-filter — Filtre de messages Sieve

SYNTAXE

sieve-filter [-C] [-W] [-v] [-d destdir] [-m msgfile] [-e errmsg] [-f logfd] [-s stats] script-file source-mailbox [discard-action]

DESCRIPTION

Le programme sieve-filter est un outil pour tester des scripts Sieve (RFC 5228) en dehors d'un serveur de messagerie. Il peut être utilisé pour exécuter des scripts Sieve sur une boîte aux lettres existante ou pour tester des scripts Sieve avec des données de connexion spécifiques.

L'outil exécute le script Sieve spécifié sur tous les messages d'une boîte aux lettres source. Si l'option -W n'est pas utilisée, cette opération est considérée comme une copie et les messages d'origine ne sont pas modifiés. Si l'option -W est utilisée, cette opération est considérée comme un déplacement. Les messages qui ne sont pas conservés par le script Sieve sont traités selon l'argument discard-action.

Les variables d'environnement suivantes sont disponibles pour les scripts Sieve :

cc
Les adresses CC du message.
delto
Les adresses de destination de la copie cachée du message.
from
L'adresse de l'expéditeur du message.
replyto
Les adresses de l'en-tête Reply-To du message.
subject
Le sujet du message.
to
Les adresses de destination du message.
cc
Les adresses CC du message.
deliveredto
L'adresse à laquelle le message a été livré sur le serveur.
envelope
L'adresse de l'expéditeur de l'enveloppe de retour.
errors-to
L'adresse de l'en-tête Errors-To du message.
listid
messageid
L'ID du message.
return-path
L'adresse de l'en-tête Return-Path du message.
sender
L'adresse de l'en-tête Sender du message.
resent-cc
Les adresses CC de l'en-tête Resent-Cc du message.
resent-delto
resent-from
resent-replyto
resent-sender
resent-to
resent-date
resent-messageid
original-recipient
bcc
date
La date du message.
local
L'adresse de destination locale du message.
redirect
remote
L'adresse de l'expéditeur distant du message.
save
xorriso
x-loop
ip
L'adresse IP de l'hôte distant.
lport
Le port local, par exemple 143
rport
Le port distant, par exemple 24567
real_lip
L'IP locale à laquelle le client s'est connecté sur cet hôte.
real_rip
L'IP distante d'où le client s'est connecté à cet hôte.
real_lport
Le port local auquel le client s'est connecté à cet hôte.
real_rport
Le port distant d'où le client s'est connecté à cet hôte.
forward_<field>
Champ à transférer en tant que %{forward:field} au processus d'authentification.

ARGUMENTS

script-file

Spécifie le script Sieve à (compiler et) exécuter.

Notez que cet outil recherche un fichier binaire précompilé avec une extension .svbin et un nom de base et un chemin identiques au script spécifié. Utilisez l'option -C pour désactiver ce comportement en forçant la compilation du script dans un nouveau binaire.

source-mailbox

Spécifie la boîte aux lettres source contenant les messages sur lesquels le filtre Sieve agira.

C'est le nom d'une boîte aux lettres, tel qu'il est visible pour les clients IMAP, sauf au format UTF-8. Le séparateur de hiérarchie entre une boîte aux lettres parente et enfant est couramment '/' ou '.', mais cela dépend de votre format de stockage de boîtes aux lettres sélectionné et de la configuration de l'espace de noms. Les noms de boîtes aux lettres peuvent également nécessiter un préfixe d'espace de noms.

Cette boîte aux lettres n'est pas modifiée à moins que l'option -W ne soit spécifiée.

discard-action

Spécifie ce qui est fait des messages dans la source-mailbox qui n'ont pas été conservés ou stockés autrement par le script Sieve ; c'est-à-dire les messages qui seraient normalement jetés si le script Sieve était exécuté lors de la livraison. Le paramètre discard-action accepte l'une des valeurs suivantes :

keep (par défaut) : Conserve les messages rejetés dans la boîte aux lettres source.

move mailbox : Déplace les messages rejetés vers la mailbox indiquée. Ceci est par exemple utile pour déplacer des messages vers une boîte aux lettres Corbeille. Référez-vous à l'explication de l'argument source-mailbox pour plus d'informations sur la nomination des boîtes aux lettres.

delete : Marque les messages rejetés comme \DELETED.

expunge : Supprime les messages rejetés, ce qui signifie qu'ils sont supprimés de manière irréversible une fois que l'outil a terminé le filtrage.

Lorsque l'option -W n'est pas spécifiée, la source-mailbox est immuable et la discard-action spécifiée n'a aucun effet. Cela signifie que les messages sont au mieux copiés dans un nouvel emplacement. En revanche, lorsque -W est spécifié, les messages qui sont stockés avec succès ailleurs par le script Sieve sont toujours supprimés de la source-mailbox, avec pour effet qu'ils sont ainsi déplacés vers le nouvel emplacement. Cela se produit indépendamment de la discard-action spécifiée. Rappel : seuls les messages rejetés sont affectés par la discard-action spécifiée.

ÉTAT DE SORTIE

sieve-filter se terminera avec l'une des valeurs suivantes :

0

Filtre Sieve appliqué avec succès. (EX_OK, EXIT_SUCCESS)

64

Erreur d'utilisation de la ligne de commande.

65

Erreur de format de données ou opération impossible.

67

L'utilisateur n'existe pas.

68

Le fichier d'entrée, l'adresse ou une autre ressource n'existe pas.

73

Impossible de créer le fichier de sortie.

75

Il y a eu une erreur temporaire, vérifiez les journaux.

76

Erreur de protocole lors de la connexion à l'hôte distant.

77

Erreur de permission.

78

Erreur de configuration.

127

Erreur inconnue.

FICHIERS

Fichier de configuration principal de Dovecot.

/etc/dovecot/conf.d/90-sieve.conf

Paramètres de l'interpréteur Sieve (inclus depuis le fichier de configuration principal de Dovecot)
