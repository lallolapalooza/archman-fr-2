NOM

ssh-agent — agent d'authentification OpenSSH

SYNOPIS

ssh-agent [-c | -s] [-DdTU] [-a adresse_liaison] [-E hachage_empreinte] [-O option] [-P fournisseurs_autorisés] [-t durée]

ssh-agent [-TU] [-a adresse_liaison] [-E hachage_empreinte] [-O option] [-P fournisseurs_autorisés] [-t durée] commande [arg ...]

ssh-agent [-c | -s] -k

ssh-agent -u

DESCRIPTION

ssh-agent est un programme permettant de stocker des clés privées utilisées pour l'authentification par clé publique. Grâce à l'utilisation de variables d'environnement, l'agent peut être localisé et utilisé automatiquement pour l'authentification lors de la connexion à d'autres machines à l'aide de ssh(1).

Les options sont les suivantes :

-a adresse_liaison
Lier l'agent au socket de domaine UNIX adresse_liaison. Par défaut, un socket est créé à un chemin aléatoire correspondant à $HOME/.ssh/agent/s.*.
-c
Générer des commandes pour le shell C sur la sortie standard. C'est le comportement par défaut si SHELL ressemble à un shell de style csh.
-D
Mode foreground. Lorsque cette option est spécifiée, ssh-agent ne se détachera pas.
-d
Mode debug. Lorsque cette option est spécifiée, ssh-agent ne se détachera pas et écrira des informations de débogage sur la sortie d'erreur standard.
-E hachage_empreinte
Spécifie l'algorithme de hachage utilisé lors de l'affichage des empreintes de clé. Les options valides sont : « md5 » et « sha256 ». La valeur par défaut est « sha256 ».
-k
Tuer l'agent courant (identifié par la variable d'environnement SSH_AGENT_PID).
-O option
Spécifie une option lors du démarrage de ssh-agent. Les options supportées sont : allow-remote-pkcs11, no-restrict-websafe et websafe-allow.

L'option allow-remote-pkcs11 autorise les clients d'un ssh-agent transféré à charger des bibliothèques de fournisseurs PKCS#11 ou FIDO. Par défaut, seuls les clients locaux peuvent effectuer cette opération. Notez que le signalement qu'un client ssh-agent est distant est effectué par ssh(1), et l'utilisation d'autres outils pour transférer l'accès au socket de l'agent peut contourner cette restriction.

L'option no-restrict-websafe indique à ssh-agent de permettre les signatures utilisant des clés FIDO qui pourraient être des requêtes d'authentification web. Par défaut, ssh-agent refuse les requêtes de signature pour les clés FIDO dont la chaîne d'application de clé ne commence pas par « ssh: » et lorsque les données à signer ne semblent pas être une requête d'authentification utilisateur ssh(1) ou une signature ssh-keygen(1). Le comportement par défaut empêche le transfert d'accès à une clé FIDO d'autoriser également implicitement l'authentification sur des sites web.

Alternativement, l'option websafe-allow permet de spécifier une liste de motifs de chaînes d'application de clé pour remplacer la liste par défaut des applications autorisées, par exemple : « websafe-allow=ssh:*,example.org,*.example.com »

Voir PATTERNS dans ssh_config(5) pour une description de la syntaxe des listes de motifs.

-P fournisseurs_autorisés
Spécifie une liste de motifs de chemins acceptables pour les bibliothèques partagées de fournisseurs PKCS#11 et d'intergiciels d'authentification FIDO qui peuvent être utilisées avec les options -S ou -s de ssh-add(1). Les bibliothèques qui ne correspondent pas à la liste des motifs seront refusées. La liste par défaut est « usr/lib*/*,/usr/local/lib*/* ».

Voir PATTERNS dans ssh_config(5) pour une description de la syntaxe des listes de motifs.

-s
Générer des commandes pour le shell Bourne sur la sortie standard. C'est le comportement par défaut si SHELL ne ressemble pas à un shell de style csh.
-T
Lier le socket de l'agent dans un sous-répertoire aléatoire de la forme $TMPDIR/ssh-XXXXXXXXXX/agent.<ppid>, au lieu du comportement par défaut qui consiste à utiliser un nom aléatoire correspondant à $HOME/.ssh/agent/s.*.
-t durée
Définir une valeur par défaut pour la durée maximale des identités ajoutées à l'agent. La durée peut être spécifiée en secondes ou dans un format de temps spécifié dans sshd_config(5). Une durée spécifiée pour une identité avec ssh-add(1) remplace cette valeur. Sans cette option, la durée maximale par défaut est infinie.
-U
Indique à ssh-agent de ne pas nettoyer les sockets d'agent obsolètes sous $HOME/.ssh/agent/.
-u
Indique à ssh-agent de nettoyer uniquement les sockets d'agent obsolètes sous $HOME/.ssh/agent/ puis de se terminer immédiatement. Si cette option est donnée deux fois, ssh-agent supprimera les sockets d'agent obsolètes indépendamment du nom d'hôte qui les a créés.
commande [arg ...]
Si une commande (et des arguments optionnels) est fournie, elle est exécutée comme sous-processus de l'agent. L'agent se termine automatiquement lorsque la commande donnée en ligne de commande est terminée.

Il existe trois méthodes principales pour configurer un agent. La première se situe au début d'une session X, où toutes les autres fenêtres ou programmes sont démarrés comme enfants du programme ssh-agent. L'agent démarre une commande sous laquelle ses variables d'environnement sont exportées, par exemple ssh-agent xterm &. Lorsque la commande se termine, l'agent se termine également.

La deuxième méthode est utilisée pour une session de connexion. Lorsque ssh-agent est démarré, il affiche les commandes shell nécessaires pour définir ses variables d'environnement, qui peuvent à leur tour être évaluées dans le shell appelant, par exemple eval `ssh-agent -s`.

Dans les deux cas, ssh(1) examine ces variables d'environnement et les utilise pour établir une connexion vers

NAME

ssh-agent - authentification agent pour la connexion SSH

SYNOPSIS

ssh-agent [-c | -s | -t token] [-d path-to-agent-dir] [-D] [-a listen-address]

DESCRIPTION

ssh-agent est un programme qui contient les clés privées qui peuvent être utilisées pour l'authentification SSH. Son exécution permet d'éviter d'entrer sa phrase secrète à chaque fois que l'on se connecte à un serveur distant. Au démarrage, ssh-agent lit les clés privées à partir de fichiers, puis il lance un processus qui attend les demandes d'authentification. Les clés sont stockées en mémoire pour permettre une authentification ultérieure.

Il existe trois manières de lancer ssh-agent. La première, et la plus courante, consiste à le lancer sans option, ce qui crée un agent qui utilise le shell de l'utilisateur pour définir les variables d'environnement nécessaires à sa communication. La deuxième manière consiste à utiliser l'option -c, qui génère des commandes pour le shell C (csh), ou l'option -s, qui génère des commandes pour le shell de type Bourne (sh).

La troisième manière de lancer ssh-agent est via l'activation par socket à partir d'un processus superviseur, tel que systemd. Dans ce mode, le processus superviseur crée le socket d'écoute et est responsable du démarrage de ssh-agent selon les besoins, ainsi que de la communication de l'emplacement du socket d'écoute à d'autres programmes dans la session de l'utilisateur. L'activation par socket est utilisée lorsque ssh-agent est démarré avec l'une des options -d ou -D, qu'aucune adresse d'écoute de socket n'est spécifiée par l'option -a, et que les variables d'environnement LISTEN_FDS et LISTEN_PID sont correctement fournies par le processus superviseur.

L'agent ne contient initialement aucune clé privée. Les clés sont ajoutées à l'aide de ssh-add(1) ou par ssh(1) lorsque AddKeysToAgent est défini dans ssh_config(5). Plusieurs identités peuvent être stockées dans ssh-agent simultanément et ssh(1) les utilisera automatiquement si elles sont présentes. ssh-add(1) est également utilisé pour supprimer des clés de ssh-agent et pour interroger les clés qui y sont détenues.

Les connexions à ssh-agent peuvent être transférées depuis d'autres hôtes distants en utilisant l'option -A de ssh(1) (mais voir les mises en garde qui y sont documentées), évitant ainsi que les données d'authentification ne soient stockées sur d'autres machines. Les phrases secrètes d'authentification et les clés privées ne transitent jamais sur le réseau : la connexion à l'agent est transférée via les connexions distantes SSH et le résultat est renvoyé au demandeur, permettant à l'utilisateur d'accéder à ses identités n'importe où sur le réseau de manière sécurisée.

ssh-agent supprimera toutes les clés qu'il a chargées après réception de SIGUSR1.

ENVIRONMENT

SSH_AGENT_PID
Lorsque ssh-agent démarre, il stocke le nom de l'ID de processus (PID) de l'agent dans cette variable.
SSH_AUTH_SOCK
Lorsque ssh-agent démarre, il crée un socket de domaine UNIX et stocke son chemin d'accès dans cette variable. Il n'est accessible qu'à l'utilisateur actuel, mais peut être facilement exploité par root ou une autre instance du même utilisateur.

FILES

$HOME/.ssh/agent/s.*
Sockets de domaine UNIX utilisés pour contenir la connexion à l'agent d'authentification. Ces sockets ne devraient être lisibles que par le propriétaire. Les sockets devraient être automatiquement supprimés lorsque l'agent se termine.

SEE ALSO

ssh(1), ssh-add(1), ssh-keygen(1), ssh_config(5), sshd(8)
