NOM

sslh - démultiplexeur de protocoles

SYNTAXE

sslh [-Ffichier de configuration] [-t nombre] [--transparent] [-p adresse d'écoute [-p adresse d'écoute ...] [--tls adresse cible pour TLS] [--ssh adresse cible pour SSH] [--openvpn adresse cible pour OpenVPN] [--http adresse cible pour HTTP] [--xmpp adresse cible pour XMPP] [--tinc adresse cible pour TINC] [--anyprot adresse cible par défaut] [--on-timeout nom du protocole] [-u nom d'utilisateur] [-C chroot] [-P fichier pid] [-v n] [-i] [-V] [-f] [-n]

DESCRIPTION

sslh accepte les connexions sur les ports spécifiés et les transmet en fonction de tests effectués sur le premier paquet de données envoyé par le client distant.

Les sondes pour HTTP, TLS, SSH, OpenVPN, tinc, XMPP sont implémentées, et tout autre protocole pouvant être testé à l'aide d'une expression régulière peut être reconnu. Un cas d'utilisation typique est de permettre de servir plusieurs services sur le port 443 (par exemple, pour se connecter à ssh depuis l'intérieur d'un pare-feu d'entreprise, qui ne bloque presque jamais le port 443) tout en continuant à servir HTTPS sur ce port.

Ainsi, sslh agit comme un démultiplexeur de protocoles, ou un standard téléphonique. Son nom vient de sa fonction originale de servir SSH et HTTPS sur le même port.

Support Libwrap

Un inconvénient de sslh est que les serveurs ne voient plus l'adresse IP d'origine du client, car la connexion est transmise via sslh.

Pour cette raison, sslh peut être compilé avec libwrap pour vérifier les accès définis dans /etc/hosts.allow et /etc/hosts.deny. Les services Libwrap peuvent être définis à l'aide du fichier de configuration.

Fichier de configuration

Un fichier de configuration peut être fourni à sslh. Les arguments de la ligne de commande remplacent les paramètres du fichier. sslh utilise libconfig pour analyser le fichier de configuration, de sorte que le format général du fichier est indiqué dans http://www.hyperrealm.com/libconfig/libconfig_manual.html. Veuillez vous référer à l'exemple de fichier de configuration fourni avec sslh pour le format spécifique (les options ont les mêmes noms qu'en ligne de commande, à l'exception de la liste des ports d'écoute et de la liste des protocoles).

Le fichier de configuration permet de spécifier des protocoles à l'aide d'expressions régulières : une liste d'expressions régulières est fournie comme paramètre regex_patterns, et si le premier paquet reçu du client correspond à l'une de ces expressions, sslh se connecte à ce protocole.

Sondage des protocoles

En recevant une connexion entrante, sslh lira les premiers octets envoyés par le client qui se connecte. Il effectuera ensuite un sondage pour le protocole dans l'ordre spécifié sur la ligne de commande (ou dans le fichier de configuration). Par conséquent, --anyprot doit toujours être utilisé en dernier, car il réussit toujours et les protocoles suivants ne seront jamais essayés.

Si aucune donnée n'est envoyée par le client, sslh finira par expirer et se connectera au protocole spécifié avec --on-timeout, ou à ssh si aucun n'est spécifié.

Journalisation

En tant que programme de sécurité/autorisation, sslh journalise dans la facilité LOG_AUTH, avec la priorité LOG_INFO pour les connexions normales et LOG_ERR pour les échecs.

OPTIONS

-Fnom de fichier, --config nom de fichier
Utilise nom de fichier comme fichier de configuration. Si d'autres options de ligne de commande sont spécifiées, elles remplaceront les paramètres du fichier de configuration.
-t nombre, --timeout nombre
Délai avant de transférer la connexion au protocole de timeout (qui devrait généralement être SSH). Par défaut, 2s.
--on-timeout nom du protocole
Nom du protocole auquel se connecter une fois la période de timeout écoulée. Par défaut, le transfert se fait vers le premier protocole spécifié. Il est généralement judicieux de spécifier 'ssh' comme protocole de timeout, car la spécification SSH ne précise pas qui est censé parler en premier et un grand nombre de clients SSH attendent que le serveur envoie sa bannière.
--transparent
Fait que sslh se comporte comme un proxy transparent, c'est-à-dire que le service de réception voit l'adresse IP d'origine du client. Cela fonctionne uniquement sous Linux et implique des configurations iproute2. Dans certains cas, des configurations iptables/nftables sont également nécessaires. Reportez-vous au README ou à https://github.com/ftasnetamot/sslh/blob/2014-08-16--close-filehandles-with-detach/doc/simple_transparent_proxy.md pour plus d'informations.
-p adresse d'écoute, --listen adresse d'écoute
Interface et port sur lesquels écouter, par exemple foobar:443, où foobar est le nom d'une interface (typiquement l'adresse IP sur laquelle la connexion Internet aboutit).

Ceci peut être spécifié plusieurs fois pour lier sslh à plusieurs adresses.

--tls adresse cible
Interface et port sur lesquels transférer les connexions SSL, typiquement localhost:443.

Notez que vous pouvez configurer sslh pour qu'il écoute sur ip_externe:443 et httpd pour qu'il écoute sur localhost:443 : cela permet aux clients à l'intérieur de votre réseau de se connecter directement à httpd.

De plus, sslh sonde les handshakes TLS et rejettera les connexions des clients demandant SSLv2. Ceci est conforme à la RFC6176 qui interdit l'utilisation de SSLv2. Si vous souhaitez accepter SSLv2, utilisez plutôt --anyprot.

--ssh adresse cible
Interface et port sur lesquels transférer les connexions SSH, typiquement localhost:22.
--openvpn adresse cible
Interface et port sur lesquels transférer les connexions OpenVPN, typiquement localhost:1194.
--xmpp adresse cible
Interface et port sur lesquels transférer les connexions XMPP, typiquement localhost:5222.
--http adresse cible
Interface et port sur lesquels transférer les connexions HTTP, typiquement localhost:80.
--tinc adresse cible
Interface et port sur lesquels transférer les connexions tinc, typiquement localhost:655.

Ceci est expérimental. Si vous utilisez cette fonctionnalité, veuillez signaler les résultats (même si cela fonctionne !)

--anyprot adresse cible
Interface et port sur lesquels transférer si aucun autre protocole n'a été trouvé. Comme sslh essaie les protocoles dans l'ordre spécifié sur la ligne de commande, ceci doit être spécifié en dernier. Si aucun par défaut n'est spécifié, sslh transférera les protocoles inconnus au premier protocole spécifié.
-v, --verbose n
Remplace toute verbosité. Reportez-vous à example.cfg pour toutes les sous-options de verbosité.
-n, --numeric
N'essaie pas de résoudre les noms d'hôtes : les journaux contiendront des adresses IP. Ceci est principalement utile si le DNS du système est lent et que vous exécutez la variante sslh-select, car les requêtes DNS bloqueront toutes les connexions.
-V
Affiche la version de sslh.
-u nom d'utilisateur, --user nom d'utilisateur
Exige de s'exécuter sous le nom d'utilisateur spécifié.
-C chroot, --chroot chroot

NAME

sslh -- redirect incoming connections based on IP, port, or protocol.

SYNOPSIS

sslh [-f | --foreground] [-P pidfile | --pidfile pidfile] [-p listen_address | --listen listen_address] [-u user | --user user] [-t timeout | --timeout timeout] [-v | --verbose] [-V | --version] [-h | --help] [-d debug | --debug debug] [-r resolv_timeout | --resolv-timeout resolv_timeout] [-l log_level | --log-level log_level] [-i | --inetd] [--background]

DESCRIPTION

sslh is a simple tool that listens to a given port, inspects the incoming traffic and redirects it to one of several other ports based on the IP address, port or protocol. It is typically used to multiplex several services over the same port, e.g. HTTPS and SSH over port 443.

The protocol is detected by sniffing the first few bytes of the connection.

By default, sslh forks itself to the background and logs to syslog.

OPTIONS

-p listen_address, --listen listen_address
The address and port to listen on. This can be an IP address or a hostname, and a port number. Default: 0.0.0.0:443.
-t timeout, --timeout timeout
Sets the connection timeout in seconds. Default: 10.
-u user, --user user
User to switch to after opening the listening socket. The user must be specified by name. If not specified, the program will run as root.
-v, --verbose
Increase verbosity. Can be specified multiple times.
-V, --version
Print version information and exit.
-h, --help
Print help and exit.
-d debug, --debug debug
Set debug level. The debug levels are bitmasks. For example, 1 means protocol debugging, 2 means connection debugging, 4 means DNS debugging, 8 means timeout debugging. A value of 255 means all debugging is enabled.
-r resolv_timeout, --resolv-timeout resolv_timeout
Set DNS resolution timeout in seconds. Default: 5.
-l log_level, --log-level log_level
Set syslog log level. Default: LOG_INFO.
--chroot directory
Chroot the server process to the specified directory after opening the listening socket and before switching user. This is useful for security reasons.
-P pidfile, --pidfile pidfile
Specifies a file in which to write the PID of the main server.
-i, --inetd
Runs as an inetd server. Options -P (PID file), -p (listen address), -u (user) are ignored.
-f, --foreground
Runs in foreground. The server will not fork and will remain connected to the terminal. Messages normally sent to syslog will also be sent to stderr.
--background
Runs in background. This overrides foreground if set in the configuration file (or on the command line, but there is no point setting both on the command line unless you have a personality disorder).

FILES

/etc/init.d/sslh
Start-up script. The standard actions start, stop and restart are supported.
/etc/default/sslh
Server configuration. These are environment variables loaded by the start-up script and passed to sslh as command-line arguments. Refer to the OPTIONS section for a detailed explanation of the variables used by sslh.

SEE ALSO

The latest version is available from https://github.com/yrutschle/sslh. There you can find a more detailed and recent documentation.
