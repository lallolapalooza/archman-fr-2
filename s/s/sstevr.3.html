subroutine sstevr (character jobz, character range, integer n, real, dimension( * ) d, real, dimension( * ) e, real vl, real vu, integer il, integer iu, real abstol, integer m, real, dimension( * ) w, real, dimension( ldz, * ) z, integer ldz, integer, dimension( * ) isuppz, real, dimension( * ) work, integer lwork, integer, dimension( * ) iwork, integer liwork, integer info)

SSTEVR calcule les valeurs propres et, éventuellement, les vecteurs propres gauches et/ou droits pour d'AUTRES matrices

Objectif :

!>
!> SSTEVR calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!> d'une matrice tridiagonale symétrique réelle T. Les valeurs propres et les
!> vecteurs propres peuvent être sélectionnés en spécifiant soit une plage de valeurs
!> soit une plage d'indices pour les valeurs propres désirées.
!>
!> Dans la mesure du possible, SSTEVR appelle SSTEMR pour calculer le
!> spectre propre en utilisant des représentations relativement robustes.
!> SSTEMR calcule les valeurs propres par l'algorithme dqds, tandis que les vecteurs propres
!> orthogonaux sont calculés à partir de diverses représentations L D L^T
!> (également connues sous le nom de représentations relativement robustes). L'orthogonalisation
!> de Gram-Schmidt est évitée autant que possible. Plus précisément,
!> les différentes étapes de l'algorithme sont les suivantes. Pour le i-ème
!> bloc non réduit de T,
!>    (a) Calculer T - sigma_i = L_i D_i L_i^T, tel que L_i D_i L_i^T
!>         soit une représentation relativement robuste,
!>    (b) Calculer les valeurs propres, lambda_j, de L_i D_i L_i^T avec une haute
!>        précision relative par l'algorithme dqds,
!>    (c) S'il y a un cluster de valeurs propres proches, sigma_i
!>        proche du cluster, et aller à l'étape (a),
!>    (d) Étant donnée la valeur propre approximative lambda_j de L_i D_i L_i^T,
!>        calculer le vecteur propre correspondant en formant une
!>        factorisation tordue révélant le rang.
!> La précision désirée de la sortie peut être spécifiée par le paramètre d'entrée
!> ABSTOL.
!>
!> Pour plus de détails, voir , par Inderjit Dhillon,
!> rapport technique de la division informatique n° UCB//CSD-97-971,
!> UC Berkeley, mai 1997.
!>
!>
!> Remarque 1 : SSTEVR appelle SSTEMR lorsque le spectre complet est demandé
!> sur les machines conformes à la norme de virgule flottante ieee-754.
!> SSTEVR appelle SSTEBZ et SSTEIN sur les machines non-ieee et
!> lorsque des requêtes de spectre partiel sont effectuées.
!>
!> L'exécution normale de SSTEMR peut créer des NaNs et des infinis et
!> peut donc échouer en raison d'une exception de virgule flottante dans les environnements
!> qui ne gèrent pas les NaNs et les infinis selon la manière par défaut de la norme ieee.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N':  Calculer uniquement les valeurs propres ;
!>          = 'V':  Calculer les valeurs propres et les vecteurs propres.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A': toutes les valeurs propres seront trouvées.
!>          = 'V': toutes les valeurs propres dans l'intervalle ouvert à gauche (VL,VU]
!>                 seront trouvées.
!>          = 'I': les IL-èmes à IU-èmes valeurs propres seront trouvées.
!>          Pour RANGE = 'V' ou 'I' et IU - IL < N - 1, SSTEBZ et
!>          SSTEIN sont appelés.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice.  N >= 0.
!>

D

!>          D est un tableau REAL de dimension (N)
!>          À l'entrée, les n éléments diagonaux de la matrice tridiagonale
!>          A.
!>          À la sortie, D peut être multiplié par un facteur constant choisi
!>          pour éviter le dépassement/sous-dépassement lors du calcul des valeurs propres.
!>

E

!>          E est un tableau REAL de dimension (max(1,N-1))
!>          À l'entrée, les (n-1) éléments sous-diagonaux de la matrice tridiagonale
!>          A dans les éléments 1 à N-1 de E.
!>          À la sortie, E peut être multiplié par un facteur constant choisi
!>          pour éviter le dépassement/sous-dépassement lors du calcul des valeurs propres.
!>

VL

!>          VL est REAL
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est REAL
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

ABSTOL

!>          ABSTOL est REAL
!>          La tolérance d'erreur absolue pour les valeurs propres.
!>          Une valeur propre approximative est acceptée comme convergente
!>          lorsqu'elle est déterminée comme se situant dans un intervalle [a,b]
!>          de largeur inférieure ou égale à
!>
!>                  ABSTOL + EPS *   max( |a|,|b| ) ,
!>
!>          où EPS est la précision machine. Si ABSTOL est inférieur ou
!>          égal à zéro, alors EPS*|T| sera utilisé à sa place,
!>          où |T| est la norme 1 de la matrice tridiagonale obtenue
!>          en réduisant A à la forme tridiagonale.
!>
!>          Voir  par Demmel et
!>          Kahan, LAPACK Working Note #3.
!>
!>          Si une haute précision relative est importante, définir ABSTOL à
!>          SLAMCH( 'Safe minimum' ). Cela garantira que les
!>          valeurs propres sont calculées avec une haute précision relative lorsque
!>          possible dans les futures versions. Le code actuel ne fait
!>          aucune garantie concernant la haute précision relative, mais
!>          les futures versions le feront. Voir J. Barlow et J. Demmel,
!>          , LAPACK Working Note #7, pour une discussion
!>          sur les matrices qui définissent leurs valeurs propres avec une haute précision relative.
!>

M

!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!>

W

!>          W est un tableau REAL de dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées en
!>          ordre croissant.
!>

Z

!>          Z est un tableau REAL de dimension (LDZ, max(1,M) )
!>          Si JOBZ = 'V', alors si INFO = 0, les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormés de la matrice A
!>          correspondant aux valeurs propres sélectionnées, la i-ème
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Note : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et une borne supérieure doit être utilisée.
!>

LDZ

!>          LDZ est INTEGER
!>          La dimension principale du tableau Z.  LDZ >= 1, et si
!>          JOBZ = 'V', LDZ >= max(1,N).
!>

ISUPPZ

!>          ISUPPZ est un tableau INTEGER de dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ème vecteur propre
!>          est non nul uniquement dans les éléments ISUPPZ( 2*i-1 ) à
hrough !> ISUPPZ( 2*i ). !> Implémenté uniquement pour RANGE = 'A' ou 'I' et IU - IL = N - 1 !>

WORK

!>          WORK est un tableau REEL, de dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) contient la taille optimale (et
!>          minimale) de LWORK.
!>

LWORK

!>          LWORK est un entier
!>          La dimension du tableau WORK.  LWORK >= 20*N.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement les tailles optimales des tableaux WORK et IWORK,
!>          renvoie ces valeurs dans les premières entrées des tableaux WORK
!>          et IWORK, et aucun message d'erreur lié à LWORK ou
!>          LIWORK n'est émis par XERBLA.
!>

IWORK

!>          IWORK est un tableau d'entiers, de dimension (MAX(1,LIWORK))
!>          À la sortie, si INFO = 0, IWORK(1) contient la taille optimale (et
!>          minimale) de LIWORK.
!>

LIWORK

!>          LIWORK est un entier
!>          La dimension du tableau IWORK.  LIWORK >= 10*N.
!>
!>          Si LIWORK = -1, alors une requête d'espace de travail est supposée ; la
!>          routine calcule uniquement les tailles optimales des tableaux WORK et
!>          IWORK, renvoie ces valeurs dans les premières entrées des tableaux WORK
!>          et IWORK, et aucun message d'erreur lié à LWORK ou LIWORK n'est émis par
!>          XERBLA.
!>

INFO

!>          INFO est un entier
!>          = 0:  terminaison réussie
!>          < 0:  si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0:  Erreur interne
!>
