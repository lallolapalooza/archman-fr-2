SSHD_CONFIG(5) Manuel des formats de fichiers SSHD_CONFIG(5)

NOM

sshd_config — fichier de configuration du démon OpenSSH

DESCRIPTION

sshd(8) lit les données de configuration depuis /etc/ssh/sshd_config (ou le fichier spécifié avec l'option -f dans la ligne de commande). Le fichier contient des paires mot-clé-argument, une par ligne. Sauf indication contraire, la première valeur obtenue sera utilisée. Les lignes commençant par ‘#’ et les lignes vides sont interprétées comme des commentaires. Les arguments peuvent éventuellement être entourés de guillemets (") afin de représenter des arguments contenant des espaces.

Les mots-clés possibles et leurs significations sont les suivants (notez que les mots-clés ne sont pas sensibles à la casse, mais les arguments le sont) :

AcceptEnv
Spécifie quelles variables d'environnement envoyées par le client seront copiées dans l'environ(7) de la session. Voir SendEnv et SetEnv dans ssh_config(5) pour savoir comment configurer le client. La variable d'environnement TERM est toujours acceptée lorsque le client demande un pseudo-terminal car elle est requise par le protocole. Les variables sont spécifiées par leur nom, qui peut contenir les caractères génériques ‘*’ et ‘?’. Plusieurs variables d'environnement peuvent être séparées par des espaces ou réparties sur plusieurs directives AcceptEnv. Attention, certaines variables d'environnement pourraient être utilisées pour contourner des environnements utilisateurs restreints. Pour cette raison, il faut être prudent dans l'utilisation de cette directive. Par défaut, aucune variable d'environnement n'est acceptée.
AddressFamily
Spécifie quelle famille d'adresses doit être utilisée par sshd(8). Les arguments valides sont any (par défaut), inet (utiliser uniquement IPv4) ou inet6 (utiliser uniquement IPv6).
AllowAgentForwarding
Spécifie si le transfert ssh-agent(1) est autorisé. Par défaut, c'est yes. Notez que la désactivation du transfert d'agent n'améliore pas la sécurité à moins que les utilisateurs ne soient également privés d'accès shell, car ils peuvent toujours installer leurs propres forwarders.
AllowGroups
Ce mot-clé peut être suivi d'une liste de motifs de noms de groupes, séparés par des espaces. S'il est spécifié, la connexion n'est autorisée que pour les utilisateurs dont le groupe principal ou la liste des groupes supplémentaires correspond à l'un des motifs. Seuls les noms de groupes sont valides ; un ID de groupe numérique n'est pas reconnu. Par défaut, la connexion est autorisée pour tous les groupes. Les directives d'autorisation/refus de groupes sont traitées dans l'ordre suivant : DenyGroups, AllowGroups.

Voir PATTERNS dans ssh_config(5) pour plus d'informations sur les motifs. Ce mot-clé peut apparaître plusieurs fois dans sshd_config, chaque occurrence s'ajoutant à la liste.

AllowStreamLocalForwarding
Spécifie si le transfert StreamLocal (socket Unix) est autorisé. Les options disponibles sont yes (par défaut) ou all pour autoriser le transfert StreamLocal, no pour interdire tout transfert StreamLocal, local pour autoriser uniquement le transfert local (du point de vue de ssh(1)) ou remote pour autoriser uniquement le transfert distant. Notez que la désactivation du transfert StreamLocal n'améliore pas la sécurité à moins que les utilisateurs ne soient également privés d'accès shell, car ils peuvent toujours installer leurs propres forwarders.
AllowTcpForwarding
Spécifie si le transfert TCP est autorisé. Les options disponibles sont yes (par défaut) ou all pour autoriser le transfert TCP, no pour interdire tout transfert TCP, local pour autoriser uniquement le transfert local (du point de vue de ssh(1)) ou remote pour autoriser uniquement le transfert distant. Notez que la désactivation du transfert TCP n'améliore pas la sécurité à moins que les utilisateurs ne soient également privés d'accès shell, car ils peuvent toujours installer leurs propres forwarders.
AllowUsers
Ce mot-clé peut être suivi d'une liste de motifs de noms d'utilisateurs, séparés par des espaces. S'il est spécifié, la connexion n'est autorisée que pour les noms d'utilisateurs qui correspondent à l'un des motifs. Seuls les noms d'utilisateurs sont valides ; un ID d'utilisateur numérique n'est pas reconnu. Par défaut, la connexion est autorisée pour tous les utilisateurs. Si le motif prend la forme USER@HOST, alors USER et HOST sont vérifiés séparément, restreignant les connexions à des utilisateurs particuliers depuis des hôtes particuliers. Les critères HOST peuvent également contenir des adresses à faire correspondre au format d'adresse/masque CIDR. Les directives d'autorisation/refus d'utilisateurs sont traitées dans l'ordre suivant : DenyUsers, AllowUsers.

Voir PATTERNS dans ssh_config(5) pour plus d'informations sur les motifs. Ce mot-clé peut apparaître plusieurs fois dans sshd_config, chaque occurrence s'ajoutant à la liste.

AuthenticationMethods
Spécifie les méthodes d'authentification qui doivent être accomplies avec succès pour qu'un utilisateur obtienne l'accès. Cette option doit être suivie d'une ou plusieurs listes de méthodes d'authentification séparées par des virgules, ou de la chaîne unique any pour indiquer le comportement par défaut consistant à accepter n'importe quelle méthode d'authentification unique. Si le comportement par défaut est remplacé, alors une authentification réussie nécessite l'achèvement de chaque méthode dans au moins une de ces listes.

Par exemple, "publickey,password publickey,keyboard-interactive" obligerait l'utilisateur à effectuer une authentification par clé publique, suivie d'une authentification par mot de passe ou par clavier interactif. Seules les méthodes qui suivent dans une ou plusieurs listes sont proposées à chaque étape, donc pour cet exemple, il ne serait pas possible de tenter une authentification par mot de passe ou par clavier interactif avant la clé publique.

Pour l'authentification par clavier interactif, il est également possible de restreindre l'authentification à un appareil spécifique en ajoutant deux-points suivi de l'identifiant de l'appareil bsdauth ou pam, selon la configuration du serveur. Par exemple, "keyboard-interactive:bsdauth" restreindrait l'authentification par clavier interactif à l'appareil bsdauth.

Si la méthode publickey est listée plus d'une fois, sshd(8) vérifie que les clés qui ont été utilisées avec succès ne sont pas réutilisées pour des authentifications ultérieures. Par exemple, "publickey,publickey" exige une authentification réussie à l'aide de deux clés publiques différentes.

Notez que chaque méthode d'authentification listée doit également être explicitement activée dans la configuration.

Les méthodes d'authentification disponibles sont : "gssapi-with-mic", "hostbased", "keyboard-interactive", "none" (utilisé pour accéder aux comptes sans mot de passe lorsque PermitEmptyPasswords est activé), "password" et "publickey".

Le programme doit produire sur la sortie standard zéro ou plusieurs lignes de sortie authorized_keys (voir AUTHORIZED_KEYS dans sshd(8)). AuthorizedKeysCommand est essayé après les fichiers usuels AuthorizedKeysFile et ne sera pas exécuté si une clé correspondante est trouvée. AuthorizedKeysCommandUser
Spécifie l'utilisateur sous lequel le compte de AuthorizedKeysCommand est exécuté. Il est recommandé d'utiliser un utilisateur dédié qui n'a pas d'autre rôle sur l'hôte que celui d'exécuter les commandes de clés autorisées. AuthorizedKeysFile
Spécifie le fichier contenant les clés publiques utilisées pour l'authentification de l'utilisateur. Le format est décrit dans la section FORMAT DE FICHIER AUTHORIZED_KEYS de sshd(8). Les arguments de AuthorizedKeysFile peuvent inclure des jokers et acceptent les tokens décrits dans la section TOKENS. Après expansion, AuthorizedKeysFile est considéré comme un chemin absolu ou relatif au répertoire personnel de l'utilisateur. Plusieurs fichiers peuvent être listés, séparés par des espaces. Alternativement, cette option peut être définie sur none pour ignorer la vérification des clés utilisateur dans les fichiers. La valeur par défaut est ".ssh/authorized_keys .ssh/authorized_keys2".
AuthorizedPrincipalsCommand
Spécifie un programme à utiliser pour générer la liste des principaux autorisés selon AuthorizedPrincipalsFile. Le programme doit appartenir à root, ne pas être accessible en écriture par le groupe ou les autres, et être spécifié par un chemin absolu. Les arguments de AuthorizedPrincipalsCommand acceptent les tokens décrits dans la section TOKENS. Si aucun argument n'est spécifié, le nom d'utilisateur de l'utilisateur cible est utilisé.

Le programme doit produire sur la sortie standard zéro ou plusieurs lignes de sortie AuthorizedPrincipalsFile. Si AuthorizedPrincipalsCommand ou AuthorizedPrincipalsFile est spécifié, alors les certificats proposés par le client pour l'authentification doivent contenir un principal listé. Par défaut, aucune commande AuthorizedPrincipalsCommand n'est exécutée.

AuthorizedPrincipalsCommandUser
Spécifie l'utilisateur sous lequel le compte de AuthorizedPrincipalsCommand est exécuté. Il est recommandé d'utiliser un utilisateur dédié qui n'a pas d'autre rôle sur l'hôte que celui d'exécuter les commandes de principaux autorisés. Si AuthorizedPrincipalsCommand est spécifié mais AuthorizedPrincipalsCommandUser ne l'est pas, alors sshd(8) refusera de démarrer.
AuthorizedPrincipalsFile
Spécifie un fichier qui liste les noms de principaux acceptés pour l'authentification par certificat. Lors de l'utilisation de certificats signés par une clé listée dans TrustedUserCAKeys, ce fichier liste les noms, dont l'un doit apparaître dans le certificat pour qu'il soit accepté pour l'authentification. Les noms sont listés un par ligne, précédés d'options de clé (comme décrit dans le FORMAT DE FICHIER AUTHORIZED_KEYS dans sshd(8)). Les lignes vides et les commentaires commençant par '#' sont ignorés.

Les arguments de AuthorizedPrincipalsFile peuvent inclure des jokers et acceptent les tokens décrits dans la section TOKENS. Après expansion, AuthorizedPrincipalsFile est considéré comme un chemin absolu ou relatif au répertoire personnel de l'utilisateur. La valeur par défaut est none, c'est-à-dire ne pas utiliser de fichier de principaux – dans ce cas, le nom d'utilisateur de l'utilisateur doit apparaître dans la liste des principaux d'un certificat pour qu'il soit accepté.

Notez que AuthorizedPrincipalsFile est uniquement utilisé lorsque l'authentification procède à l'aide d'une CA listée dans TrustedUserCAKeys et n'est pas consulté pour les autorités de certification approuvées via ~/.ssh/authorized_keys, bien que l'option de clé principals= offre une installation similaire (voir sshd(8) pour les détails).

Banner
Le contenu du fichier spécifié est envoyé à l'utilisateur distant avant que l'authentification ne soit autorisée. Si l'argument est none, alors aucune bannière n'est affichée. Par défaut, aucune bannière n'est affichée.
CASignatureAlgorithms
Spécifie quels algorithmes sont autorisés pour la signature de certificats par les autorités de certification (AC). La valeur par défaut est : 
ssh-ed25519,ecdsa-sha2-nistp256,
ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,
sk-ssh-ed25519@openssh.com,
sk-ecdsa-sha2-nistp256@openssh.com,
rsa-sha2-512,rsa-sha2-256

Si la liste spécifiée commence par un caractère '+', alors les algorithmes spécifiés seront ajoutés à l'ensemble par défaut au lieu de le remplacer. Si la liste spécifiée commence par un caractère '-', alors les algorithmes spécifiés (y compris les jokers) seront supprimés de l'ensemble par défaut au lieu de le remplacer.

Les certificats signés à l'aide d'autres algorithmes ne seront pas acceptés pour l'authentification par clé publique ou par hôte.

ChannelTimeout
Spécifie si et à quelle vitesse sshd(8) doit fermer les canaux inactifs. Les délais sont spécifiés comme une ou plusieurs paires "type=interval" séparées par des espaces, où le "type" doit être le mot-clé spécial "global" ou un nom de type de canal de la liste ci-dessous, contenant éventuellement des caractères jokers.

La valeur du délai "interval" est spécifiée en secondes ou peut utiliser l'une des unités documentées dans la section FORMATS DE TEMPS. Par exemple, "session=5m" entraînerait la résiliation des sessions interactives après cinq minutes d'inactivité. Spécifier une valeur nulle désactive le délai d'inactivité.

Le délai spécial "global" s'applique à tous les canaux actifs, pris ensemble. Le trafic sur n'importe quel canal actif réinitialisera le délai, mais lorsque le délai expire, tous les canaux ouverts seront fermés. Notez que ce délai global n'est pas couvert par les jokers et doit être spécifié explicitement.

Les noms de types de canaux disponibles incluent :

agent-connection
Connexions ouvertes à ssh-agent(1).
direct-tcpip, direct-streamlocal@openssh.com
Connexions TCP ou de socket Unix (respectivement) ouvertes qui ont été établies à partir d'une redirection locale ssh(1), c'est-à-dire LocalForward ou DynamicForward.
forwarded-tcpip, forwarded-streamlocal@openssh.com
Connexions TCP ou de socket Unix (respectivement) ouvertes qui ont été établies vers un sshd(8) écoutant au nom d'une redirection distante ssh(1), c'est-à-dire RemoteForward.
session
La session principale interactive, y compris la session shell, l'exécution de commandes, scp(1), sftp(1), etc.
tun-connection
Connexions TunnelForward ouvertes.
x11-connection
Sessions de redirection X11 ouvertes.

Notez que dans tous les cas ci-dessus, la résiliation d'une session inactive ne garantit pas la suppression de toutes les ressources associées à la session, par exemple, les processus shell ou les clients X11 liés à la session peuvent continuer à s'exécuter.

De plus, la résiliation d'un canal ou d'une session inactive ne ferme pas nécessairement la connexion SSH, ni n'empêche un client de demander un autre canal du même type. En particulier, l'expiration d'une session de redirection inactive n'empêche pas qu'une autre redirection identique soit créée par la suite.

La valeur par défaut est de ne pas expirer les canaux de quelque type que ce soit pour inactivité.

ChrootDirectory
Spécifie le nom du chemin d'un répertoire vers lequel effectuer un chroot(2) après l'authentification. Au démarrage de la session, sshd(8) vérifie que tous les composants du nom du chemin sont des répertoires appartenant à root et qui ne sont pas accessibles en écriture par le groupe ou les autres. Après le chroot, sshd(8) change le répertoire de travail vers le répertoire personnel de l'utilisateur. Les arguments de ChrootDirectory acceptent les tokens décrits dans la section TOKENS.

Le ChrootDirectory doit contenir les fichiers et répertoires nécessaires pour supporter la session de l'utilisateur. Pour une session interactive, cela nécessite au moins un shell, typiquement sh(1), et des nœuds /dev de base tels que null(4), zero(4), stdin(4), stdout(4), stderr(4), et les périphériques tty(4). Pour les sessions de transfert de fichiers utilisant SFTP, aucune configuration supplémentaire de l'environnement n'est nécessaire si le sftp-server en cours d'exécution est utilisé, bien que les sessions qui utilisent la journalisation puissent nécessiter /dev/log à l'intérieur du répertoire chroot sur certains systèmes d'exploitation (voir sftp-server(8) pour les détails).

Pour des raisons de sécurité, il est très important que la hiérarchie des répertoires soit protégée contre la modification par d'autres processus sur le système (en particulier ceux extérieurs à la jail). Une mauvaise configuration peut conduire à des environnements non sécurisés que sshd(8) ne peut pas détecter.

La valeur par défaut est none, indiquant de ne pas chroot(2).

Ciphers
Spécifie les chiffrements autorisés. Plusieurs chiffrements doivent être séparés par des virgules. Si la liste spécifiée commence par un caractère ‘+’, les chiffrements spécifiés seront ajoutés à l'ensemble par défaut au lieu de le remplacer. Si la liste spécifiée commence par un caractère ‘-’, les chiffrements spécifiés (y compris les jokers) seront supprimés de l'ensemble par défaut au lieu de le remplacer. Si la liste spécifiée commence par un caractère ‘^’, les chiffrements spécifiés seront placés en tête de l'ensemble par défaut.

Les chiffrements supportés sont :

  • 3des-cbc
  • aes128-cbc
  • aes192-cbc
  • aes256-cbc
  • aes128-ctr
  • aes192-ctr
  • aes256-ctr
  • aes128-gcm@openssh.com
  • aes256-gcm@openssh.com
  • chacha20-poly1305@openssh.com

La valeur par défaut est :

chacha20-poly1305@openssh.com,
aes128-gcm@openssh.com,aes256-gcm@openssh.com,
aes128-ctr,aes192-ctr,aes256-ctr

La liste des chiffrements disponibles peut également être obtenue en utilisant "ssh -Q cipher".

ClientAliveCountMax
Définit le nombre de messages alive du client qui peuvent être envoyés sans que sshd(8) ne reçoive de message en retour du client. Si ce seuil est atteint pendant l'envoi de messages alive du client, sshd déconnectera le client, terminant la session. Il est important de noter que l'utilisation des messages alive du client est très différente de TCPKeepAlive. Les messages alive du client sont envoyés via le canal crypté et ne peuvent donc pas être usurpés. L'option keepalive TCP activée par TCPKeepAlive est susceptible d'usurpation. Le mécanisme alive du client est précieux lorsque le client ou le serveur dépendent de savoir quand une connexion est devenue non réactive.

La valeur par défaut est 3. Si ClientAliveInterval est réglé sur 15 et ClientAliveCountMax est laissé à la valeur par défaut, les clients SSH non réactifs seront déconnectés après environ 45 secondes. Définir ClientAliveCountMax à zéro désactive la terminaison de la connexion.

ClientAliveInterval
Définit un intervalle de temps d'attente en secondes après lequel, si aucune donnée n'a été reçue du client, sshd(8) enverra un message via le canal crypté pour demander une réponse du client. La valeur par défaut est 0, indiquant que ces messages ne seront pas envoyés au client.
Compression
Spécifie si la compression est activée après que l'utilisateur se soit authentifié avec succès. L'argument doit être yes, delayed (un synonyme hérité pour yes) ou no. La valeur par défaut est yes.
DenyGroups
Ce mot-clé peut être suivi d'une liste de motifs de noms de groupe, séparés par des espaces. La connexion est interdite aux utilisateurs dont le groupe principal ou la liste de groupes supplémentaires correspondent à l'un des motifs. Seuls les noms de groupe sont valides ; un ID de groupe numérique n'est pas reconnu. Par défaut, la connexion est autorisée pour tous les groupes. Les directives allow/deny groups sont traitées dans l'ordre suivant : DenyGroups, AllowGroups.

Voir PATTERNS dans ssh_config(5) pour plus d'informations sur les motifs. Ce mot-clé peut apparaître plusieurs fois dans sshd_config, chaque instance ajoutant à la liste.

DenyUsers
Ce mot-clé peut être suivi d'une liste de motifs de noms d'utilisateur, séparés par des espaces. La connexion est interdite aux noms d'utilisateur qui correspondent à l'un des motifs. Seuls les noms d'utilisateur sont valides ; un ID d'utilisateur numérique n'est pas reconnu. Par défaut, la connexion est autorisée pour tous les utilisateurs. Si le motif prend la forme USER@HOST, alors USER et HOST sont vérifiés séparément, restreignant les connexions à des utilisateurs particuliers depuis des hôtes particuliers. Les critères HOST peuvent également contenir des adresses à faire correspondre au format CIDR adresse/masque. Les directives allow/deny users sont traitées dans l'ordre suivant : DenyUsers, AllowUsers.

Voir PATTERNS dans ssh_config(5) pour plus d'informations sur les motifs. Ce mot-clé peut apparaître plusieurs fois dans sshd_config, chaque instance ajoutant à la liste.

DisableForwarding
Désactive toutes les fonctionnalités de transfert, y compris X11, ssh-agent(1), TCP et StreamLocal. Cette option remplace toutes les autres options liées au transfert et peut simplifier les configurations restreintes.
ExposeAuthInfo
Écrit un fichier temporaire contenant une liste des méthodes d'authentification et des identifiants publics (par exemple, clés) utilisés pour authentifier l'utilisateur. L'emplacement du fichier est exposé à la session utilisateur via la variable d'environnement SSH_USER_AUTH. La valeur par défaut est no.
FingerprintHash
Spécifie l'algorithme de hachage utilisé lors de l'enregistrement des empreintes de clés. Les options valides sont : md5 et sha256. La valeur par défaut est sha256.
ForceCommand
Force l'exécution de la commande spécifiée par ForceCommand, en ignorant toute commande fournie par le client et ~/.ssh/rc s'il est présent. La commande est invoquée en utilisant le shell de connexion de l'utilisateur avec l'option -c. Ceci s'applique à l'exécution du shell, de la commande ou du sous-système. C'est le plus utile dans un bloc Match. La commande initialement fournie par le client est disponible dans la variable d'environnement SSH_ORIGINAL_COMMAND. Spécifier une commande de internal-sftp forcera l'utilisation d'un serveur SFTP intégré qui ne nécessite aucun fichier de support lorsqu'il est utilisé avec ChrootDirectory. La valeur par défaut est none.
GatewayPorts
Spécifie si les hôtes distants sont autorisés à se connecter aux ports transférés pour le client. Par défaut, sshd(8) lie les transferts de ports distants à l'adresse de bouclage. Cela empêche les autres hôtes distants de se connecter aux ports transférés. GatewayPorts peut être utilisé pour spécifier que sshd doit autoriser les transferts de ports distants à se lier à des adresses non-bouclage, permettant ainsi à d'autres hôtes de se connecter. L'argument peut être no pour forcer les transferts de ports distants à n'être disponibles que pour l'hôte local, yes pour forcer les transferts de ports distants à se lier à l'adresse wildcard, ou clientspecified pour permettre au client de sélectionner l'adresse à laquelle le transfert est lié. La valeur par défaut est no.
GSSAPIAuthentication
Spécifie si l'authentification utilisateur basée sur GSSAPI est autorisée. La valeur par défaut est no.
GSSAPICleanupCredentials
Spécifie s'il faut détruire automatiquement le cache des identifiants de l'utilisateur à la déconnexion. La valeur par défaut est yes.
GSSAPIStrictAcceptorCheck
Détermine s'il faut être strict quant à l'identité de l'accepteur GSSAPI contre lequel un client s'authentifie. S'il est défini sur yes, le client doit s'authentifier auprès du service hôte sur le nom d'hôte actuel. S'il est défini sur no, le client peut s'authentifier auprès de n'importe quelle clé de service stockée dans le magasin par défaut de la machine. Cette fonctionnalité est fournie pour aider au fonctionnement sur des machines multi-homed. La valeur par défaut est yes.
HostbasedAcceptedAlgorithms
Spécifie les algorithmes de signature qui seront acceptés pour l'authentification basée sur l'hôte sous forme d'une liste de motifs séparés par des virgules. Alternativement, si la liste spécifiée commence par un caractère ‘+’, alors les algorithmes de signature spécifiés seront ajoutés à l'ensemble par défaut au lieu de le remplacer. Si la liste spécifiée commence par un caractère ‘
8;-’ caractère, alors les algorithmes de signature spécifiés (y compris les caractères génériques) seront supprimés de l'ensemble par défaut au lieu de les remplacer. Si le la liste spécifiée commence par un caractère ‘^’, alors les algorithmes de signature spécifiés seront placés en tête de l'ensemble par défaut. La valeur par défaut pour cette option est : 
ssh-ed25519-cert-v01@openssh.com,
ecdsa-sha2-nistp256-cert-v01@openssh.com,
ecdsa-sha2-nistp384-cert-v01@openssh.com,
ecdsa-sha2-nistp521-cert-v01@openssh.com,
sk-ssh-ed25519-cert-v01@openssh.com,
sk-ecdsa-sha2-nistp256-cert-v01@openssh.com,
rsa-sha2-512-cert-v01@openssh.com,
rsa-sha2-256-cert-v01@openssh.com,
ssh-ed25519,
ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,
sk-ssh-ed25519@openssh.com,
sk-ecdsa-sha2-nistp256@openssh.com,
rsa-sha2-512,rsa-sha2-256

La liste des algorithmes de signature disponibles peut également être obtenue à l'aide de "ssh -Q HostbasedAcceptedAlgorithms". Celle-ci était précédemment nommée HostbasedAcceptedKeyTypes.

HostbasedAuthentication
Spécifie si l'authentification rhosts ou /etc/hosts.equiv, associée à une authentification réussie de la clé publique du client, est autorisée (authentification basée sur l'hôte). La valeur par défaut est no.
HostbasedUsesNameFromPacketOnly
Spécifie si le serveur tentera d'effectuer une recherche de nom inversée lors de la mise en correspondance du nom dans les fichiers ~/.shosts, ~/.rhosts et /etc/hosts.equiv pendant HostbasedAuthentication. Une valeur de yes signifie que sshd(8) utilise le nom fourni par le client au lieu de tenter de résoudre le nom à partir de la connexion TCP elle-même. La valeur par défaut est no.
HostCertificate
Spécifie un fichier contenant un certificat d'hôte public. La clé publique du certificat doit correspondre à une clé d'hôte privée déjà spécifiée par HostKey. Le comportement par défaut de sshd(8) est de ne pas charger de certificats.
HostKey
Spécifie un fichier contenant une clé d'hôte privée utilisée par SSH. Les valeurs par défaut sont /etc/ssh/ssh_host_ecdsa_key, /etc/ssh/ssh_host_ed25519_key et /etc/ssh/ssh_host_rsa_key.

Notez que sshd(8) refusera d'utiliser un fichier s'il est accessible par le groupe/tout le monde et que l'option HostKeyAlgorithms restreint quelles clés sont effectivement utilisées par sshd(8).

Il est possible d'avoir plusieurs fichiers de clés d'hôte. Il est également possible de spécifier des fichiers de clés d'hôte publics. Dans ce cas, les opérations sur la clé privée seront déléguées à un ssh-agent(1).

HostKeyAgent
Identifie le socket de domaine UNIX utilisé pour communiquer avec un agent ayant accès aux clés d'hôte privées. Si la chaîne "SSH_AUTH_SOCK" est spécifiée, l'emplacement du socket sera lu à partir de la variable d'environnement SSH_AUTH_SOCK.

IgnoreRhosts
Spécifie si les fichiers .rhosts et .shosts par utilisateur doivent être ignorés lors de HostbasedAuthentication. Le fichier système /etc/hosts.equiv et /etc/ssh/shosts.equiv sont toujours utilisés indépendamment de ce paramètre.

Les valeurs acceptées sont yes (par défaut) pour ignorer tous les fichiers par utilisateur, shosts-only pour autoriser l'utilisation de .shosts mais ignorer .rhosts, ou no pour autoriser à la fois .shosts et .rhosts.

IgnoreUserKnownHosts
Spécifie si sshd(8) doit ignorer le fichier de l'utilisateur ~/.ssh/known_hosts pendant HostbasedAuthentication et utiliser uniquement le fichier système /etc/ssh/ssh_known_hosts. La valeur par défaut est “no”.
Include
Inclut les fichiers de configuration spécifiés. Plusieurs chemins peuvent être spécifiés et chaque chemin peut contenir des caractères génériques glob(7) qui seront développés et traités dans l'ordre lexical. Les fichiers sans chemins absolus sont supposés être dans /etc/ssh. Une directive Include peut apparaître à l'intérieur d'un bloc Match pour une inclusion conditionnelle.
IPQoS
Spécifie la valeur du champ de codage des services différenciés (DSCP) pour la connexion. Les valeurs acceptées sont af11, af12, af13, af21, af22, af23, af31, af32, af33, af41, af42, af43, cs0, cs1, cs2, cs3, cs4, cs5, cs6, cs7, ef, le, une valeur numérique, ou none pour utiliser la valeur par défaut du système d'exploitation. Cette option peut prendre un ou deux arguments, séparés par des espaces. Si un argument est spécifié, il est utilisé comme classe de paquet inconditionnellement. Si deux valeurs sont spécifiées, la première est automatiquement sélectionnée pour les sessions interactives et la seconde pour les sessions non interactives. La valeur par défaut est ef (Expedited Forwarding) pour les sessions interactives et none (la valeur par défaut du système d'exploitation) pour les sessions non interactives.
KbdInteractiveAuthentication
Spécifie si l'authentification par clavier-interactif est autorisée. Tous les styles d'authentification de login.conf(5) sont pris en charge. La valeur par défaut est yes. L'argument de ce mot-clé doit être yes ou no. ChallengeResponseAuthentication est un alias obsolète pour celui-ci.
KerberosAuthentication
Spécifie si le mot de passe fourni par l'utilisateur pour PasswordAuthentication sera validé via le KDC Kerberos. Pour utiliser cette option, le serveur a besoin d'un servtab Kerberos qui permet la vérification de l'identité du KDC. La valeur par défaut est no.
KerberosGetAFSToken

KerberosOrLocalPasswd

KerberosTicketCleanup
Spécifie si le fichier de cache de ticket de l'utilisateur doit être automatiquement détruit à la déconnexion. La valeur par défaut est yes.

ListenAddress
Spécifie les adresses locales sur lesquelles sshd(8) doit écouter. Les formes suivantes peuvent être utilisées :
  • ListenAddress nom d'hôte|adresse [rdomain domaine]
  • ListenAddress nom d'hôte:port [rdomain domaine]
  • ListenAddress adresse IPv4:port [rdomain domaine]
  • ListenAddress [nom d'hôte|adresse]:port [rdomain domaine]

Le qualificateur optionnel rdomain demande à sshd(8) d'écouter dans un domaine de routage explicite. Si port n'est pas spécifié, sshd écoutera sur l'adresse et toutes les options Port spécifiées. Le défaut est d'écouter sur toutes les adresses locales dans le domaine de routage par défaut actuel. Plusieurs options ListenAddress sont permises. Pour plus d'informations sur les domaines de routage, voir rdomain(4).

LoginGraceTime
Le serveur se déconnecte après ce délai si l'utilisateur ne s'est pas connecté avec succès. Si la valeur est 0, il n'y a pas de limite de temps. Le défaut est de 120 secondes.
LogLevel
Donne le niveau de verbosité utilisé lors de la journalisation des messages de sshd(8). Les valeurs possibles sont : QUIET, FATAL, ERROR, INFO, VERBOSE, DEBUG, DEBUG1, DEBUG2 et DEBUG3. Le défaut est INFO. DEBUG et DEBUG1 sont équivalents. DEBUG2 et DEBUG3 spécifient des niveaux de sortie de débogage plus élevés. La journalisation avec un niveau DEBUG viole la vie privée des utilisateurs et n'est pas recommandée.
LogVerbose
Spécifie un ou plusieurs remplacements pour LogLevel. Un remplacement consiste en une ou plusieurs listes de motifs qui correspondent au fichier source, à la fonction et au numéro de ligne pour forcer une journalisation détaillée. Par exemple, un motif de remplacement : 
kex.c:*:1000,*:kex_exchange_identification():*,packet.c:*

activerait la journalisation détaillée pour la ligne 1000 de kex.c, tout dans la fonction kex_exchange_identification(), et tout le code du fichier packet.c. Cette option est destinée au débogage et aucun remplacement n'est activé par défaut.

Match
Introduit un bloc conditionnel. Si tous les critères de la ligne Match sont satisfaits, les mots-clés des lignes suivantes remplacent ceux définis dans la section globale du fichier de configuration, jusqu'à ce qu'une autre ligne Match ou la fin du fichier soit atteinte. Si un mot-clé apparaît dans plusieurs blocs Match qui sont satisfaits, seule la première occurrence du mot-clé est appliquée.

Les arguments de Match sont une ou plusieurs paires critère-motif ou l'un des critères à jeton unique : All, qui correspond à tous les critères, ou Invalid-User, qui correspond lorsque le nom d'utilisateur demandé ne correspond à aucun compte connu. Les critères disponibles sont User, Group, Host, LocalAddress, LocalPort, Version, RDomain et Address (RDomain représentant le rdomain(4) sur lequel la connexion a été reçue).

Les motifs de correspondance peuvent être constitués d'entrées uniques ou de listes séparées par des virgules et peuvent utiliser les opérateurs jokers et de négation décrits dans la section PATTERNS de ssh_config(5).

Les motifs dans un critère Address peuvent en outre contenir des adresses à faire correspondre au format d'adresse/longueur de masque CIDR, tel que 192.0.2.0/24 ou 2001:db8::/32. Notez que la longueur du masque fournie doit être cohérente avec l'adresse - il est erroné de spécifier une longueur de masque trop longue pour l'adresse ou une longueur avec des bits définis dans la partie hôte de l'adresse. Par exemple, 192.0.2.0/33 et 192.0.2.0/8, respectivement.

Le mot-clé Version correspond à la chaîne de version de sshd(8), par exemple “OpenSSH_10.0”.

Seul un sous-ensemble de mots-clés peut être utilisé sur les lignes suivant un mot-clé Match. Les mots-clés disponibles sont AcceptEnv, AllowAgentForwarding, AllowGroups, AllowStreamLocalForwarding, AllowTcpForwarding, AllowUsers, AuthenticationMethods, AuthorizedKeysCommand, AuthorizedKeysCommandUser, AuthorizedKeysFile, AuthorizedPrincipalsCommand, AuthorizedPrincipalsCommandUser, AuthorizedPrincipalsFile, Banner, CASignatureAlgorithms, ChannelTimeout, ChrootDirectory, ClientAliveCountMax, ClientAliveInterval, DenyGroups, DenyUsers, DisableForwarding, ExposeAuthInfo, ForceCommand, GatewayPorts, GSSAPIAuthentication, HostbasedAcceptedAlgorithms, HostbasedAuthentication, HostbasedUsesNameFromPacketOnly, IgnoreRhosts, Include, IPQoS, KbdInteractiveAuthentication, KerberosAuthentication, LogLevel, MaxAuthTries, MaxSessions, PAMServiceName, PasswordAuthentication, PermitEmptyPasswords, PermitListen, PermitOpen, PermitRootLogin, PermitTTY, PermitTunnel, PermitUserRC, PubkeyAcceptedAlgorithms, PubkeyAuthentication, PubkeyAuthOptions, RefuseConnection, RekeyLimit, RevokedKeys, RDomain, SetEnv, StreamLocalBindMask, StreamLocalBindUnlink, TrustedUserCAKeys, UnusedConnectionTimeout, X11DisplayOffset, X11Forwarding et X11UseLocalhost.

MaxAuthTries
Spécifie le nombre maximum de tentatives d'authentification autorisées par connexion. Une fois que le nombre d'échecs atteint la moitié de cette valeur, les échecs supplémentaires sont enregistrés. La valeur par défaut est 6.
MaxSessions
Spécifie le nombre maximum de sessions shell, de connexion ou de sous-système (par exemple, sftp) ouvertes autorisées par connexion réseau. Plusieurs sessions peuvent être établies par des clients qui prennent en charge le multiplexage de connexion. La définition de MaxSessions à 1 désactivera effectivement le multiplexage de session, tandis que la définition à 0 empêchera toutes les sessions shell, de connexion et de sous-système tout en autorisant le transfert. La valeur par défaut est 10.
MaxStartups
Spécifie le nombre maximum de connexions non authentifiées simultanées vers le démon SSH. Les connexions supplémentaires seront abandonnées jusqu'à ce que l'authentification réussisse ou que le LoginGraceTime expire pour une connexion. La valeur par défaut est 10:30:100.

Alternativement, le rejet précoce aléatoire peut être activé en spécifiant les trois valeurs séparées par des deux-points start:rate:full (par exemple, "10:30:60"). sshd(8) rejettera les tentatives de connexion avec une probabilité de rate/100 (30 %) s'il y a actuellement start (10) connexions non authentifiées. La probabilité augmente linéairement et toutes les tentatives de connexion sont rejetées si le nombre de connexions non authentifiées atteint full (60).

ModuliFile
Spécifie le fichier moduli(5) qui contient les groupes Diffie-Hellman utilisés pour les méthodes d'échange de clés « diffie-hellman-group-exchange-sha1 » et « diffie-hellman-group-exchange-sha256 ». La valeur par défaut est /etc/ssh/moduli.
PAMServiceName
Spécifie le nom du service utilisé pour l'authentification, l'autorisation et le contrôle de session via les modules d'authentification enfichables (PAM) lorsque UsePAM est activé. La valeur par défaut est sshd.
PasswordAuthentication
Spécifie si l'authentification par mot de passe est autorisée. La valeur par défaut est yes.
PermitEmptyPasswords
Lorsque l'authentification par mot de passe est autorisée, spécifie si le serveur autorise la connexion aux comptes avec des mots de passe vides. La valeur par défaut est no.
PermitListen
Spécifie les adresses/ports sur lesquels un transfert de port TCP distant peut écouter. La spécification d'écoute doit être l'une des formes suivantes :
  • PermitListen port
  • PermitListen host:port

Plusieurs autorisations peuvent être spécifiées en les séparant par des espaces. Un argument de any peut être utilisé pour supprimer toutes les restrictions et autoriser toutes les requêtes d'écoute. Un argument de none peut être utilisé pour interdire toutes les requêtes d'écoute. Le nom d'hôte peut contenir des jokers comme décrit dans la section PATTERNS de ssh_config(5). Le joker ‘*’ peut également être utilisé à la place d'un numéro de port pour autoriser tous les ports. Par défaut, toutes les requêtes d'écoute de transfert de port sont autorisées. Notez que l'option GatewayPorts peut restreindre davantage les adresses sur lesquelles il est possible d'écouter. Notez également que ssh(1) demandera un hôte d'écoute de « localhost » si aucun hôte d'écoute n'a été spécifiquement demandé, et que ce nom est traité différemment des adresses localhost explicites « 127.0.0.1 » et « ::1 ».

PermitOpen
Spécifie les destinations vers lesquelles le transfert de port TCP est autorisé. La spécification de transfert doit être l'une des formes suivantes :
  • PermitOpen host:port
  • PermitOpen IPv4_addr:port
  • PermitOpen [IPv6_addr]:port

Plusieurs transferts peuvent être spécifiés en les séparant par des espaces. Un argument de any peut être utilisé pour supprimer toutes les restrictions et autoriser toutes les requêtes de transfert. Un argument de none peut être utilisé pour interdire toutes les requêtes de transfert. Le joker ‘*’ peut être utilisé pour l'hôte ou le port afin d'autoriser respectivement tous les hôtes ou tous les ports. Sinon, aucun traitement de motif ou recherche d'adresse n'est effectué sur les noms fournis. Par défaut, toutes les requêtes de transfert de port sont autorisées.

PermitRootLogin
Spécifie si root peut se connecter à l'aide de ssh(1). L'argument doit être yes, prohibit-password, forced-commands-only ou no. La valeur par défaut est prohibit-password.

Si cette option est définie sur prohibit-password (ou son alias obsolète, without-password), l'authentification par mot de passe et keyboard-interactive est désactivée pour root.

Si cette option est définie sur forced-commands-only, la connexion root avec authentification par clé publique sera autorisée, mais uniquement si l'option command a été spécifiée (ce qui peut être utile pour effectuer des sauvegardes à distance même si la connexion root n'est normalement pas autorisée). Toutes les autres méthodes d'authentification sont désactivées pour root.

Si cette option est définie sur no, root n'est pas autorisé à se connecter.

PermitTTY
Spécifie si l'allocation de pty(4) est autorisée. La valeur par défaut est yes.
PermitTunnel
Spécifie si le transfert de périphérique tun(4) est autorisé. L'argument doit être yes, point-to-point (couche 3), ethernet (couche 2) ou no. Spécifier yes autorise à la fois point-to-point et ethernet. La valeur par défaut est no.

Indépendamment de ce paramètre, les permissions du périphérique tun(4) sélectionné doivent autoriser l'accès à l'utilisateur.

PermitUserEnvironment
Spécifie si ~/.ssh/environment et les options environment= dans ~/.ssh/authorized_keys sont traités par sshd(8). Les options valides sont yes, no ou une liste de motifs spécifiant quels noms de variables d'environnement accepter (par exemple "LANG,LC_*"). La valeur par défaut est no. L'activation du traitement de l'environnement peut permettre aux utilisateurs de contourner les restrictions d'accès dans certaines configurations en utilisant des mécanismes tels que LD_PRELOAD.
PermitUserRC
Spécifie si un fichier ~/.ssh/rc est exécuté. La valeur par défaut est yes.
PerSourceMaxStartups
Spécifie le nombre de connexions non authentifiées autorisées à partir d'une adresse source donnée, ou « none » s'il n'y a pas de limite. Cette limite est appliquée en plus de MaxStartups, selon la valeur la plus basse des deux. La valeur par défaut est none.
PerSourceNetBlockSize
Spécifie le nombre de bits de l'adresse source qui sont regroupés pour appliquer les limites de PerSourceMaxStartups. Les valeurs pour IPv4 et éventuellement IPv6 peuvent être spécifiées, séparées par un deux-points. La valeur par défaut est 32:128, ce qui signifie que chaque adresse est considérée individuellement.
PerSourcePenalties
Contrôle les pénalités pour diverses conditions qui peuvent représenter des attaques contre sshd(8). Si une pénalité est appliquée à un client, son adresse source et toutes les autres adresses du même réseau, telles que définies par PerSourceNetBlockSize, se verront refuser la connexion pendant une période donnée.

Une pénalité n'affecte pas les connexions simultanées en cours, mais plusieurs pénalités provenant de la même source pour des connexions simultanées s'accumuleront jusqu'à un maximum. Inversement, les pénalités ne sont pas appliquées avant qu'un temps seuil minimum n'ait été accumulé.

Les pénalités sont activées par défaut avec les paramètres par défaut listés ci-dessous, mais peuvent être désactivées en utilisant le mot-clé no. Les valeurs par défaut peuvent être remplacées en spécifiant un ou plusieurs des mots-clés ci-dessous, séparés par des espaces. Tous les mots-clés acceptent des arguments, par exemple "crash:2m".

crash:duration
Spécifie la durée pendant laquelle les clients provoquant un crash de sshd(8) seront refusés (par défaut : 90s).
authfail:duration
Spécifie la durée pendant laquelle les clients qui se déconnectent après une ou plusieurs tentatives d'authentification infructueuses seront refusés (par défaut : 5s).
refuseconnection:duration
Spécifie la durée pendant laquelle les clients qui ont été interdits de connexion par l'administrateur via l'option RefuseConnection seront refusés (par défaut : 10s).
noauth:duration
Spécifie la durée pendant laquelle les clients qui se déconnectent sans tenter de s'authentifier seront refusés (par défaut : 1s). Ce délai d'attente doit être utilisé avec prudence, car il pourrait pénaliser des outils de balayage légitimes tels que ssh-keyscan(1).
grace-exceeded:duration
Spécifie la durée pendant laquelle les clients qui ne parviennent pas à s'authentifier après LoginGraceTime seront refusés (par défaut : 10s).
max:duration
Spécifie la durée maximale pendant laquelle une plage d'adresses source particulière se verra refuser l'accès (par défaut : 10m). Les pénalités répétées s'accumuleront jusqu'à ce maximum.
min:duration
Spécifie la pénalité minimale qui doit être accumulée avant que la sanction ne commence (par défaut : 15s).
max-sources4:number, max-sources6:number
Spécifie le nombre maximum de plages d'adresses IPv4 et IPv6 clientes à suivre pour les pénalités (par défaut : 65536 pour les deux).
overflow:mode
Contrôle le comportement du serveur lorsque max-sources4 ou max-sources6 est dépassé. Il existe deux modes de fonctionnement : deny-all, qui refuse toutes les connexions entrantes autres que celles exemptées via PerSourcePenaltyExemptList jusqu'à expiration d'une pénalité, et permissive, qui autorise les nouvelles connexions en supprimant les pénalités existantes plus tôt (par défaut : permissive). Notez que les pénalités clients inférieures au seuil min comptent dans le nombre total de pénalités suivies. Les adresses IPv4 et IPv6 sont suivies séparément, donc un débordement dans l'une n'affectera pas l'autre.
overflow6:mode
Permet de spécifier un mode de débordement différent pour les adresses IPv6. Par défaut, le même mode de débordement que celui spécifié pour IPv4 est utilisé.
PerSourcePenaltyExemptList
Spécifie une liste d'adresses séparées par des virgules pour les exempter des pénalités. Cette liste peut contenir des jokers et des plages d'adresses/masques CIDR. Notez que la longueur du masque fournie doit être cohérente avec l'adresse - il est erroné de spécifier une longueur de masque trop longue pour l'adresse ou une qui contient des bits définis dans la partie hôte de l'adresse. Par exemple, 192.0.2.0/33 et 192.0.2.0/8, respectivement. Par défaut, aucune adresse n'est exemptée.
PidFile
Spécifie le fichier contenant l'identifiant de processus du démon SSH, ou none pour ne pas en écrire. Par défaut, il s'agit de /run/sshd.pid.
Port
Spécifie le numéro de port sur lequel sshd(8) écoute. Par défaut, il s'agit du port 22. Plusieurs options de ce type sont autorisées. Voir aussi ListenAddress.
PrintLastLog
Spécifie si sshd(8) doit afficher la date et l'heure de la dernière connexion de l'utilisateur lorsqu'un utilisateur se connecte interactivement. Par défaut, c'est yes.
PrintMotd

PubkeyAuthOptions
Définit une ou plusieurs options d'authentification par clé publique. Les mots-clés pris en charge sont : none (par défaut ; indiquant qu'aucune option supplémentaire n'est activée), touch-required et verify-required.

L'option touch-required fait que l'authentification par clé publique utilisant un algorithme d'authentification FIDO (c'est-à-dire ecdsa-sk ou ed25519-sk) exige toujours que la signature atteste qu'un utilisateur physiquement présent a explicitement confirmé l'authentification (généralement en touchant l'authentificateur). Par défaut, sshd(8) exige la présence de l'utilisateur, sauf si elle est remplacée par une option authorized_keys. Le flag touch-required désactive cette substitution.

L'option verify-required exige qu'une signature de clé FIDO atteste que l'utilisateur a été vérifié, par exemple via un PIN.

Ni les options touch-required ni verify-required n'ont d'effet pour d'autres types de clés publiques, non FIDO.

Spécifie la quantité maximale de données qui peuvent être transmises ou reçues avant que la clé de session ne soit renégociée, éventuellement suivie d'une quantité maximale de temps qui peut s'écouler avant que la clé de session ne soit renégociée. La valeur par défaut pour RekeyLimit est default none, ce qui signifie que le rekeying est effectué après qu'une quantité de données par défaut du chiffrement a été envoyée ou reçue et qu'aucun rekeying basé sur le temps n'est effectué.

Spécifie la taille minimale de la clé RSA (en bits) que sshd(8) acceptera. Les clés d'authentification utilisateur et basées sur l'hôte dont la taille est inférieure à cette limite seront refusées. Pour plus d'informations sur les KRL, voir la section LISTES DE RÉVOCATION DE CLÉS dans ssh-keygen(1).

%D

%F
L'empreinte de la clé CA.

L'identifiant de la clé dans le certificat.
%K
La clé CA encodée en base64.
%k

%s
Le numéro de série du certificat.
%T
Le type de la clé CA.
%t

%U
L'identifiant utilisateur numérique de l'utilisateur cible.
%u
Le nom d'utilisateur.
