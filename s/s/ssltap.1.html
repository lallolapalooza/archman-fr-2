SSLTAP(1) Outils de sécurité NSS SSLTAP(1)

NOM

ssltap - Intercepter les connexions SSL et afficher les données qui passent

SYNTAXE

ssltap [-fhlsvx] [-p port] [nom_hote:port]

STATUT

Cette documentation est encore en cours de rédaction. Veuillez contribuer à la revue initiale dans le bug 836477 de Mozilla NSS[1]

DESCRIPTION

L'outil de débogage SSL ssltap est un proxy en ligne de commande connaissant le SSL. Il surveille les connexions TCP et affiche les données qui passent. Si une connexion est SSL, l'affichage des données comprend des enregistrements SSL interprétés et des négociations.

OPTIONS

-f

Active l'impression sophistiquée. La sortie est imprimée en HTML coloré. Les données envoyées du client au serveur sont en bleu ; la réponse du serveur est en rouge. Lorsqu'il est utilisé avec le mode de bouclage, les différentes connexions sont séparées par des lignes horizontales. Vous pouvez utiliser cette option pour importer la sortie dans un navigateur.

-h

Active l'impression hexadécimale/ASCII. Au lieu de sortir des données brutes, la commande interprète chaque enregistrement comme une ligne numérotée de valeurs hexadécimales, suivie des mêmes données en caractères ASCII. Les deux parties sont séparées par une barre verticale. Les caractères non imprimables sont remplacés par des points.

-l préfixe

Active le bouclage ; c'est-à-dire, continue d'accepter les connexions plutôt que de s'arrêter après la première connexion terminée.

-p port

Change le port de connexion par défaut (1924) à un autre port.

Les numéros de port suivants sont des ports bien connus :

* HTTP 80

* HTTPS 443

* SMTP 25

* FTP 21

* IMAP 143

* IMAPS 993 (IMAP sur SSL)

* NNTP 119

* NNTPS 563 (NNTP sur SSL)

-s

Active l'analyse et le décodage SSL. L'outil ne détecte pas automatiquement les sessions SSL. Si vous interceptez une connexion SSL, utilisez cette option afin que l'outil puisse détecter et décoder les structures SSL.

Si l'outil détecte une chaîne de certificats, il enregistre les certificats codés en DER dans des fichiers dans le répertoire courant. Les fichiers sont nommés cert.0x, où x est le numéro de séquence du certificat.

Si l'option -s est utilisée avec -h, deux parties distinctes sont imprimées pour chaque enregistrement : la sortie hexadécimale/ASCII brute, et la sortie SSL analysée.

-v

Imprime une chaîne de version pour l'outil.

-x

Active les vidages hexadécimaux SSL supplémentaires.

UTILISATION ET EXEMPLES

Vous pouvez utiliser l'outil de débogage SSL pour intercepter toute information de connexion. Bien que vous puissiez exécuter l'outil dans sa forme la plus basique en lançant la commande ssltap sans autres options que nom_hote:port, les informations que vous obtenez de cette manière ne sont pas très utiles. Par exemple, supposez que votre machine de développement s'appelle intercept. La manière la plus simple d'utiliser l'outil de débogage est d'exécuter la commande suivante depuis un shell :

$ ssltap www.netscape.com

Le programme attend une connexion entrante sur le port par défaut 1924. Dans la fenêtre de votre navigateur, entrez l'URL http://intercept:1924. Le navigateur récupère la page demandée du serveur à l'adresse www.netscape.com, mais la page est interceptée et transmise au navigateur par l'outil de débogage sur intercept. En chemin vers le navigateur, les données sont imprimées dans le shell depuis lequel vous avez lancé la commande. Les données envoyées du client au serveur sont entourées des symboles suivants : --> [ données ] Les données envoyées du serveur au client sont entourées des symboles suivants : "flèche gauche"-- [ données ] Le flux de données brutes est envoyé à la sortie standard et n'est interprété d'aucune manière. Cela peut entraîner des effets étranges, tels que des sons, des flashs, et même des plantages de la fenêtre du shell. Pour obtenir une interprétation de base et imprimable des données, utilisez l'option -h, ou, si vous examinez une connexion SSL, l'option -s. Vous remarquerez que la page que vous avez récupérée semble incomplète dans le navigateur. C'est parce que, par défaut, l'outil se ferme après la fin de la première connexion, le navigateur ne peut donc pas charger les images. Pour que l'outil continue d'accepter les connexions, activez le mode de bouclage avec l'option -l. Les exemples suivants montrent la sortie des combinaisons d'options couramment utilisées.

Exemple 1

$ ssltap.exe -sx -p 444 interzone.mcom.com:443 > sx.txt

DESCRIPTION

The ssltap tool is a SSL proxy. It makes a connection to the specified host and port, and then accepts connections from arbitrary clients, forwarding data between them. This allows for examination of the SSL traffic passing between the client and server.

The tool supports SSLv2 and SSLv3, and may not be able to interpret traffic from other SSL/TLS versions.

OPTIONS

-s
Turns on SSL parsing. This option produces more verbose output, including protocol elements such as handshake messages.
-x
Turns on hex/ASCII display. Each record is displayed in hexadecimal, with an ASCII representation of the data.
-p
Changes the port that ssltap listens on. Defaults to 443.
-h
Displays a help message and exits.

USAGE TIPS

When SSL restarts a previous session, it makes use of cached information to do a partial handshake. If you wish to capture a full SSL handshake, restart the browser to clear the session id cache.

If you run the tool on a machine other than the SSL server to which you are trying to connect, the browser will complain that the host name you are trying to connect to is different from the certificate. If you are using the default BadCert callback, you can still connect through a dialog. If you are not using the default BadCert callback, the one you supply must allow for this possibility.
