NOM

sss_cache - effectuer un nettoyage de cache

SYNTAXE

sss_cache [options]

DESCRIPTION

sss_cache invalide les enregistrements dans le cache SSSD. Les enregistrements invalidés sont forcés d'être rechargés depuis le serveur dès que le backend SSSD concerné est en ligne. Les options qui invalident un seul objet n'acceptent qu'un seul argument fourni.

OPTIONS

-E,--everything

Invalide toutes les entrées du cache.

-u,--user identifiant

Invalide un utilisateur spécifique.

-U,--users

Invalide tous les enregistrements d'utilisateurs. Cette option remplace l'invalidation d'un utilisateur spécifique s'il a également été défini.

-g,--group groupe

Invalide un groupe spécifique.

-G,--groups

Invalide tous les enregistrements de groupes. Cette option remplace l'invalidation d'un groupe spécifique s'il a également été défini.

-n,--netgroup netgroup

Invalide un netgroup spécifique.

-N,--netgroups

Invalide tous les enregistrements de netgroups. Cette option remplace l'invalidation d'un netgroup spécifique s'il a également été défini.

-s,--service service

Invalide un service spécifique.

-S,--services

Invalide tous les enregistrements de services. Cette option remplace l'invalidation d'un service spécifique s'il a également été défini.

-a,--autofs-map autofs-map

Invalide des maps autofs spécifiques.

-A,--autofs-maps

Invalide toutes les maps autofs. Cette option remplace l'invalidation d'une map spécifique s'il a également été défini.

-h,--ssh-host nom_hote

Invalide les clés publiques SSH d'un hôte spécifique.

-H,--ssh-hosts

Invalide les clés publiques SSH de tous les hôtes. Cette option remplace l'invalidation des clés publiques SSH d'un hôte spécifique s'il a également été défini.

-r,--sudo-rule règle

Invalide une règle sudo particulière.

-R,--sudo-rules

Invalide toutes les règles sudo mises en cache. Cette option remplace l'invalidation d'une règle sudo spécifique si elle a également été définie.

-d,--domain domaine

Restreint le processus d'invalidation à un domaine particulier uniquement.

-?,--help

Affiche le message d'aide et quitte.

EFFETS SUR LE CACHE RAPIDE EN MÉMOIRE

sss_cache invalide également le cache mémoire. Comme le cache mémoire est un fichier qui est mappé dans la mémoire de chaque processus ayant appelé SSSD pour résoudre des utilisateurs ou des groupes, le fichier ne peut pas être tronqué. Un indicateur spécial est défini dans l'en-tête du fichier pour indiquer que le contenu est invalide, puis le fichier est désolidarisé par le répondeur NSS de SSSD et un nouveau fichier cache est créé. Chaque fois qu'un processus effectue une nouvelle recherche d'un utilisateur ou d'un groupe, il verra l'indicateur, fermera l'ancien fichier cache mémoire et mappera le nouveau dans sa mémoire. Lorsque tous les processus qui avaient ouvert l'ancien fichier cache mémoire l'auront fermé lors de la recherche d'un utilisateur ou d'un groupe, le noyau pourra libérer l'espace disque occupé et l'ancien fichier cache mémoire sera finalement complètement supprimé.

Un cas particulier concerne les processus à longue exécution qui effectuent des recherches d'utilisateurs ou de groupes uniquement au démarrage, par exemple pour déterminer le nom de l'utilisateur sous lequel le processus s'exécute. Pour ces recherches, le fichier cache mémoire est mappé dans la mémoire du processus. Mais comme il n'y aura plus de recherches ultérieures, ce processus ne détectera jamais si le fichier cache mémoire a été invalidé et sera donc conservé en mémoire et occupera de l'espace disque jusqu'à l'arrêt du processus. Par conséquent, l'appel de sss_cache peut augmenter l'utilisation du disque car les anciens fichiers cache mémoire ne peuvent pas être supprimés du disque car ils sont toujours mappés par des processus à longue exécution.

Une solution possible pour les processus à longue exécution qui recherchent des utilisateurs et des groupes uniquement au démarrage ou très rarement est de les exécuter avec la variable d'environnement SSS_NSS_USE_MEMCACHE définie sur "NO" afin qu'ils n'utilisent pas le cache mémoire du tout et ne mappent pas le fichier cache mémoire en mémoire. En général, une meilleure solution consiste à régler les paramètres de délai d'expiration du cache pour qu'ils correspondent aux attentes locales et que l'appel de sss_cache ne soit pas nécessaire.
