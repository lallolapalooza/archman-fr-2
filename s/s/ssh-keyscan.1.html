SSH-KEYSCAN(1) Manuel des commandes générales SSH-KEYSCAN(1)

NOM

ssh-keyscan — récupère les clés publiques SSH des serveurs

SYNTAXE

ssh-keyscan [-46cDHqv] [-f fichier] [-O option] [-p port] [-T délai] [-t type] [hôte | liste_adresses nom_liste]

DESCRIPTION

ssh-keyscan est un utilitaire pour récupérer les clés publiques SSH d'un certain nombre de serveurs. Il a été conçu pour aider à construire et vérifier les fichiers ssh_known_hosts, dont le format est documenté dans sshd(8). ssh-keyscan fournit une interface minimale adaptée à une utilisation par des scripts shell et Perl.

ssh-keyscan utilise des entrées/sorties socket non bloquantes pour contacter autant de serveurs que possible en parallèle, ce qui le rend très efficace. Les clés d'un domaine de 1 000 serveurs peuvent être collectées en quelques dizaines de secondes, même lorsque certains de ces serveurs sont en panne ou n'exécutent pas sshd(8). Pour l'analyse, on n'a pas besoin d'un accès de connexion aux machines analysées, et le processus d'analyse n'implique aucun chiffrement.

Les serveurs à analyser peuvent être spécifiés par nom d'hôte, adresse ou plage réseau CIDR (par exemple, 192.168.16/28). Si une plage réseau est spécifiée, toutes les adresses de cette plage seront analysées.

Les options sont les suivantes :

-4
Force ssh-keyscan à n'utiliser que les adresses IPv4.
-6
Force ssh-keyscan à n'utiliser que les adresses IPv6.
-c
Demande des certificats aux serveurs cibles au lieu de clés brutes.
-D
Affiche les clés trouvées sous forme d'enregistrements DNS SSHFP. Par défaut, affiche les clés dans un format utilisable comme fichier ssh(1) known_hosts.
-f fichier
Lit les serveurs ou les paires « liste_adresses nom_liste » depuis fichier, une par ligne. Si ‘-’ est fourni à la place d'un nom de fichier, ssh-keyscan lira depuis l'entrée standard. Les noms lus depuis un fichier doivent commencer par une adresse, un nom d'hôte ou une plage réseau CIDR à analyser. Les adresses et noms d'hôtes peuvent éventuellement être suivis d'alias de noms ou d'adresses séparés par des virgules qui seront copiés dans la sortie. Par exemple : 
192.168.11.0/24
10.20.1.1
heureux.exemple.org
10.0.0.1,triste.exemple.org
-H
Hache tous les noms d'hôtes et adresses dans la sortie. Les noms hachés peuvent être utilisés normalement par ssh(1) et sshd(8), mais ils ne révèlent pas d'informations identifiables si le contenu du fichier est divulgué.
-O option
Spécifie une option clé/valeur. À l'heure actuelle, seule une option est prise en charge :
hashalg=algorithme
Sélectionne un algorithme de hachage à utiliser lors de l'affichage des enregistrements SSHFP avec le drapeau -D. Les algorithmes valides sont « sha1 » et « sha256 ». Par défaut, affiche les deux.
-p port
Se connecte au port sur le serveur distant.
-q
Mode silencieux : n'affiche pas le nom du serveur et les bannières dans les commentaires.
-T délai
Définit le délai d'attente pour les tentatives de connexion. Si délai secondes se sont écoulées depuis le début d'une connexion à un serveur ou depuis la dernière lecture d'une donnée provenant de ce serveur, la connexion est fermée et le serveur en question est considéré comme indisponible. La valeur par défaut est 5 secondes.
-t type
Spécifie le type de clé à récupérer des serveurs analysés. Les valeurs possibles sont « ecdsa », « ed25519 », « ecdsa-sk », « ed25519-sk » ou « rsa ». Plusieurs valeurs peuvent être spécifiées en les séparant par des virgules. Par défaut, récupère tous les types de clés ci-dessus.
-v
Mode verbeux : affiche des messages de débogage sur la progression.

Si un fichier ssh_known_hosts est construit en utilisant ssh-keyscan sans vérifier les clés, les utilisateurs seront vulnérables aux attaques de type l'homme du milieu. D'un autre côté, si le modèle de sécurité autorise un tel risque, ssh-keyscan peut aider à détecter des fichiers de clés altérés ou des attaques de l'homme du milieu qui ont commencé après la création du fichier ssh_known_hosts.

FICHIERS

/etc/ssh/ssh_known_hosts

EXEMPLES

Affiche la clé d'hôte RSA de la machine nom_hote :

$ ssh-keyscan -t rsa nom_hote

Analyse une plage réseau, affichant tous les types de clés pris en charge :

$ ssh-keyscan 192.168.0.64/25

Trouve tous les serveurs du fichier ssh_hosts qui ont des clés nouvelles ou différentes de celles du fichier trié ssh_known_hosts :

$ ssh-keyscan -t rsa,ecdsa,ed25519 -f ssh_hosts | \
	sort -u - ssh_known_hosts | diff ssh_known_hosts -
