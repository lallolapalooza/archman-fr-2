NOM

sssd - Daemon des services de sécurité système

SYNOPIS

sssd [options]

DESCRIPTION

SSSD fournit un ensemble de démons pour gérer l'accès aux répertoires distants et aux mécanismes d'authentification. Il fournit une interface NSS et PAM vers le système et un système de backend pluggable pour se connecter à de multiples sources de comptes différentes ainsi qu'une interface D-Bus. Il est également la base pour fournir des services d'audit client et de politique pour des projets comme FreeIPA. Il fournit une base de données plus robuste pour stocker les utilisateurs locaux ainsi que des données utilisateur étendues.

OPTIONS

-d,--debug-level NIVEAU

SSSD prend en charge deux représentations pour spécifier le niveau de débogage. La plus simple consiste à spécifier une valeur décimale de 0 à 9, ce qui signifie activer ce niveau et tous les messages de débogage de niveau inférieur. L'option la plus complète consiste à spécifier un masque de bits hexadécimal pour activer ou désactiver des niveaux spécifiques (par exemple, si vous souhaitez supprimer un niveau).

Veuillez noter que chaque service SSSD écrit dans son propre fichier journal. Notez également que l'activation de “debug_level” dans la section “[sssd]” n'active le débogage que pour le processus sssd lui-même, et non pour les processus répondeurs ou fournisseurs. Le paramètre “debug_level” doit être ajouté à toutes les sections à partir desquelles vous souhaitez générer des journaux de débogage.

En plus de modifier le niveau de journalisation dans le fichier de configuration à l'aide du paramètre “debug_level”, qui est persistant mais nécessite un redémarrage de SSSD, il est également possible de modifier le niveau de débogage à la volée à l'aide de l'outil sss_debuglevel(8).

Niveaux de débogage actuellement pris en charge :

0, 0x0010 : Échecs fatals. Tout ce qui pourrait empêcher SSSD de démarrer ou le faire cesser de fonctionner.

1, 0x0020 : Échecs critiques. Une erreur qui ne tue pas SSSD, mais qui indique qu'au moins une fonctionnalité majeure ne fonctionnera pas correctement.

2, 0x0040 : Échecs graves. Une erreur annonçant qu'une requête ou une opération particulière a échoué.

3, 0x0080 : Échecs mineurs. Ce sont les erreurs qui percoleraient vers le bas pour provoquer l'échec de l'opération 2.

4, 0x0100 : Paramètres de configuration.

5, 0x0200 : Données de fonction.

6, 0x0400 : Messages de trace pour les fonctions d'opération.

7, 0x1000 : Messages de trace pour les fonctions de contrôle internes.

8, 0x2000 : Contenu des variables internes de fonction qui peuvent être intéressantes.

9, 0x4000 : Informations de traçage de très bas niveau.

9, 0x20000 : Données de performance et statistiques, veuillez noter qu'en raison de la manière dont les requêtes sont traitées en interne, le temps d'exécution enregistré d'une requête peut être plus long qu'il ne l'a réellement été.

10, 0x10000 : Informations de traçage libldb encore plus bas niveau. Presque jamais vraiment nécessaire.

Pour journaliser les niveaux de débogage du masque de bits requis, ajoutez simplement leurs nombres ensemble comme montré dans les exemples suivants :

Exemple : Pour journaliser les échecs fatals, critiques et graves, ainsi que les données de fonction, utilisez 0x0270.

Exemple : Pour journaliser les échecs fatals, les paramètres de configuration, les données de fonction, les messages de trace pour les fonctions de contrôle internes, utilisez 0x1310.

Note : Le format de masque de bits des niveaux de débogage a été introduit dans la version 1.7.0.

Défaut : 0x0070 (c'est-à-dire échecs fatals, critiques et graves ; correspond à la définition 2 en notation décimale)

--debug-timestamps=mode

1 : Ajouter un horodatage aux messages de débogage

0 : Désactiver l'horodatage dans les messages de débogage

Défaut : 1

--debug-microseconds=mode

1 : Ajouter des microsecondes à l'horodatage dans les messages de débogage

0 : Désactiver les microsecondes dans l'horodatage

Défaut : 0

--logger=valeur

Emplacement où SSSD enverra les messages de journal.

stderr : Rediriger les messages de débogage vers la sortie d'erreur standard.

files : Rediriger les messages de débogage vers les fichiers journaux. Par défaut, les fichiers journaux sont stockés dans /var/log/sssd et il existe des fichiers journaux distincts pour chaque service et domaine SSSD.

journald : Rediriger les messages de débogage vers systemd-journald

Défaut : non défini (revenir à journald si disponible, sinon à stderr)

-D,--daemon

Devenir un démon après le démarrage.

-i,--interactive

S'exécuter en avant-plan, ne pas devenir un démon.

-c,--config

Spécifier un fichier de configuration non par défaut. Le défaut est /etc/sssd/sssd.conf. Pour des informations sur la syntaxe et les options du fichier de configuration, consultez la page de manuel sssd.conf(5).

-?,--help

Afficher le message d'aide et quitter.

--version

Afficher le numéro de version et quitter.

SIGNALS

SIGTERM/SIGINT

Informe SSSD de terminer gracieusement tous ses processus enfants, puis d'arrêter le moniteur.

SIGHUP

Indique à SSSD d'arrêter d'écrire dans ses descripteurs de fichiers de débogage actuels et de les fermer et rouvrir. Ceci est destiné à faciliter la rotation des journaux avec des programmes comme logrotate.

SIGUSR1

Indique à SSSD de simuler une opération hors ligne pendant la durée du paramètre “offline_timeout”. Ceci est utile pour les tests. Le signal peut être envoyé soit au processus sssd, soit directement à n'importe quel processus sssd_be.

SIGUSR2

Indique à SSSD de se mettre en ligne immédiatement. Ceci est utile pour les tests. Le signal peut être envoyé soit au processus sssd, soit directement à n'importe quel processus sssd_be.

SIGRTMIN+1

Indique à SSSD de replanifier les tâches périodiques. Le chien de garde interne envoie ce signal aux fournisseurs lorsqu'un décalage d'horloge est détecté, bien qu'il puisse être envoyé directement à n'importe quel processus sssd_be.

STATUT DE SORTIE

0

SSSD a été arrêté gracieusement.

1

Mauvaise configuration ou option de ligne de commande.

2

Erreur d'allocation mémoire.

6

SSSD est déjà en cours d'exécution.

Autres codes

D'autres codes indiquent différentes erreurs, très probablement des droits d'accès requis manquants. Voir les journaux SSSD et système pour plus de détails.

NOTES

Si la variable d'environnement SSS_NSS_USE_MEMCACHE est définie sur "NO", les applications clientes n'utiliseront pas le cache rapide en mémoire.

Si la variable d'environnement SSS_LOCKFREE est définie sur "NO", les requêtes de plusieurs threads d'une seule application seront sérialisées.
