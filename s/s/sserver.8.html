NOM

sserver - serveur d'exemple Kerberos version 5

SYNTAXE

sserver [ -p port ] [ -S keytab ] [ port_serveur ]

DESCRIPTION

sserver et sclient(1) sont une application client/serveur de démonstration simple. Lorsque sclient se connecte à sserver, il effectue une authentification Kerberos, puis sserver renvoie à sclient le principal Kerberos utilisé pour l'authentification Kerberos. Cela permet de tester avec succès l'installation de Kerberos sur une machine.

Le nom du service utilisé par sserver et sclient est sample. Par conséquent, sserver nécessitera une entrée keytab pour le service sample/hostname.domain.name@REALM.NAME. Ce keytab est généré à l'aide du programme kadmin(1). Le fichier keytab est généralement installé sous FILE:/etc/krb5.keytab.

L'option -S permet d'utiliser un keytab différent de celui par défaut.

sserver est normalement invoqué à partir d'inetd(8), en utilisant une ligne dans /etc/inetd.conf qui ressemble à ceci :

sample stream tcp nowait root /usr/local/sbin/sserver sserver

Étant donné que sample n'est normalement pas un port défini dans /etc/services, vous devrez généralement ajouter une ligne à /etc/services qui ressemble à ceci :

sample          13135/tcp

Lors de l'utilisation de sclient, vous devrez d'abord avoir une entrée dans la base de données Kerberos, en utilisant kadmin(1), puis obtenir des tickets Kerberos, en utilisant kinit(1). De plus, si vous exécutez le programme sclient sur un hôte différent de celui auquel sserver se connectera, assurez-vous que les deux hôtes ont une entrée dans /etc/services pour le port tcp sample, et que le même numéro de port est présent dans les deux fichiers.

Lorsque vous exécutez sclient, vous devriez voir quelque chose comme ceci :

sendauth succeeded, reply is:
reply len 32, contents:
You are nlgilman@JIMI.MIT.EDU

MESSAGES D'ERREUR COMMUNES

1.
kinit renvoie l'erreur :
kinit: Client not found in Kerberos database while getting
       initial credentials

Cela signifie que vous n'avez pas créé d'entrée pour votre nom d'utilisateur dans la base de données Kerberos.

2.
sclient renvoie l'erreur :
unknown service sample/tcp; check /etc/services

Cela signifie que vous n'avez pas d'entrée dans /etc/services pour le port tcp sample.

3.
sclient renvoie l'erreur :
connect: Connection refused

Cela signifie probablement que vous n'avez pas correctement modifié /etc/inetd.conf, ou que vous n'avez pas redémarré inetd après avoir modifié inetd.conf.

4.
sclient renvoie l'erreur :
sclient: Server not found in Kerberos database while using
         sendauth

Cela signifie que le service sample/hostname@LOCAL.REALM n'a pas été défini dans la base de données Kerberos ; il doit être créé à l'aide de kadmin(1), et un fichier keytab doit être généré pour rendre la clé de ce principal de service disponible pour sclient.

5.
sclient renvoie l'erreur :
sendauth rejected, error reply is:
    "No such file or directory"

Cela signifie probablement que sserver n'a pas pu trouver le fichier keytab. Il n'a probablement pas été installé dans le répertoire approprié.

ENVIRONNEMENT

Voir kerberos(7) pour une description des variables d'environnement Kerberos.

VOIR AUSSI

sclient(1), kerberos(7), services(5), inetd(8)
