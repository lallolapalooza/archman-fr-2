SSHDUMP(1)   SSHDUMP(1)

NOM

sshdump - Fournit des interfaces pour capturer des paquets depuis un hôte distant via SSH en utilisant un binaire de capture distant.

SYNTAXE

sshdump [ --help ] [ --version ] [ --extcap-interfaces ] [ --extcap-dlts ] [ --extcap-interface=<interface> ] [ --extcap-config ] [ --extcap-capture-filter=<filtre de capture> ] [ --capture ] [ --fifo=<chemin vers fichier ou tube> ] [ --remote-host=<adresse IP> ] [ --remote-port=<port TCP> ] [ --remote-username=<nomdutilisateur> ] [ --remote-password=<motdepasse> ] [ --sshkey=<chemin vers clé privée> ] [ --sshkey-passphrase=<phrase secrète clé privée> ] [ --proxycommand=<commande proxy SSH> ] [ --remote-interface=<interface> ] [ --remote-capture-command-select=<sélection commande capture> ] [ --remote-capture-command=<commande capture> ] [ --remote-priv=<sélection commande élévation privilèges> ] [ --remote-priv-user=<nom utilisateur privilégié> ] [ --remote-noprom ] [ --remote-filter=<filtre capture distant> ] [ --remote-count=<nombre> ]

sshdump --extcap-interfaces

sshdump --extcap-interface=<interface> --extcap-dlts

sshdump --extcap-interface=<interface> --extcap-config

sshdump --extcap-interface=<interface> --fifo=<chemin vers fichier ou tube> --capture --remote-host=monhotedistance --remote-port=22 --remote-username=utilisateur --remote-interface=eth2 --remote-capture-command='tcpdump -U -i eth0 -w-'

DESCRIPTION

Sshdump est un outil extcap qui permet d'exécuter un outil de capture distant sur une connexion SSH. L'exigence est que l'exécutable de capture doit avoir les capacités pour capturer depuis l'interface désirée.

La fonctionnalité est équivalente à l'exécution de commandes telles que

$ ssh utilisateurdistant@hotedistance -p 22222 'tcpdump -U -i IFACE -w -' > FICHIER &
$ wireshark FICHIER
$ ssh utilisateurdistant@hotedistance '/sbin/dumpcap -i IFACE -P -w - -f "not port 22"' > FICHIER &
$ wiresharkFICHIER
$ ssh unhote dumpcap -P -w - -f udp | tshark -i -

Typiquement, sshdump n'est pas invoqué directement. Il peut plutôt être configuré via l'interface graphique de Wireshark ou sa ligne de commande. La commande suivante démarrera Wireshark et commencera la capture depuis l'hôte hotedistance :

$ wireshark '-oextcap.sshdump.remotehost:"hotedistance"' -i sshdump -k

Pour contrôler explicitement la commande de capture distante :

$ wireshark '-oextcap.sshdump.remotehost:"hotedistance"' \
            '-oextcap.sshdump.remotecapturecommand:"tcpdump -i eth0 -Uw- not port 22"' \
            -i sshdump -k

Interfaces supportées :

1.sshdump

OPTIONS

--help

Affiche les arguments du programme.

--version

Affiche la version du programme.

--extcap-interfaces

Liste les interfaces disponibles.

--extcap-interface=<interface>

Utilise l'interface spécifiée.

--extcap-dlts

Liste les DLTs de l'interface spécifiée.

--extcap-config

Liste les options de configuration de l'interface spécifiée.

--extcap-capture-filter=<filtre de capture>

Le filtre de capture. Il correspond à la valeur fournie via l'option tshark -f, et au champ Filtre de capture à côté de la liste des interfaces dans l'interface Wireshark.

--capture

Démarre la capture depuis l'interface spécifiée et écrit les données brutes des paquets à l'emplacement spécifié par --fifo.

--fifo=<chemin vers fichier ou tube>

Sauvegarde le paquet capturé dans un fichier ou l'envoie via un tube.

--remote-host=<hôte distant>

L'adresse de l'hôte distant pour la capture.

--remote-port=<port distant>

Le port SSH de l'hôte distant.

--remote-username=<nomdutilisateur>

Le nom d'utilisateur pour l'authentification SSH.

--remote-password=<motdepasse>

Le mot de passe à utiliser (si ssh-agent et pubkey ne sont pas utilisés). ATTENTION : les mots de passe sont stockés en clair et visibles par tous les utilisateurs sur ce système. Il est recommandé d'utiliser des fichiers clés avec un agent SSH.

--sshkey=<chemin vers clé privée SSH>

Le chemin vers une clé privée pour l'authentification. NOTE : Seul le format de paire clé/valeur OPENSSH est supporté.

--sshkey-passphrase=<phrase secrète clé privée SSH>

La phrase secrète pour la clé privée pour l'authentification.

--proxycommand=<commande proxy>

La commande à utiliser comme proxy pour la connexion SSH.

--remote-interface=<interface distante>

L'interface réseau distante à partir de laquelle capturer.

--remote-capture-command-select=<sélection commande capture>

La sélection du support intégré pour les commandes de capture distantes. Soit dumpcap pour une commande de capture distante utilisant dumpcap, tcpdump pour une commande de capture distante utilisant tcpdump, soit other, où la commande de capture distante doit être fournie avec l'option --remote-capture-command.

Notez que la sélection de dumpcap permet de spécifier plusieurs interfaces de capture sous forme de liste séparée par des espaces, tandis que tcpdump ne le permet pas.

--remote-capture-command=<commande capture>

Une commande de capture distante personnalisée qui produit le flux distant affiché dans Wireshark. La commande doit pouvoir produire un flux PCAP écrit vers STDOUT. Voir ci-dessous pour plus d'exemples.

Si vous utilisez tcpdump, utilisez l'option -w- pour vous assurer que les paquets sont écrits sur la sortie standard (stdout). Incluez l'option -U pour écrire les paquets dès qu'ils sont reçus.

Lorsqu'elle est spécifiée, cette commande sera utilisée telle quelle, les options telles que le filtre de capture (--extcap-capture-filter) ne seront pas ajoutées.

--remote-priv=<sélection commande élévation privilèges>

La commande à utiliser pour obtenir l'élévation des privilèges afin de capturer sur l'hôte distant. Soit none, sudo ou doas.

--remote-priv-user=<nom utilisateur privilégié>

Si une commande est utilisée pour obtenir l'élévation des privilèges pour capturer sur l'hôte distant, cela peut nécessiter un nom d'utilisateur. Si nécessaire, utilisez cette option pour fournir ce nom d'utilisateur.

--remote-filter=<filtre de capture>

Le filtre de capture distant. Il correspond à la valeur fournie via l'option tshark -f, et au champ Filtre de capture à côté de la liste des interfaces dans l'interface Wireshark.

--remote-count=<nombre>

Le nombre de paquets à capturer.

EXEMPLES

Pour voir les arguments du programme :

sshdump --help

Pour voir la version du programme :

sshdump --version

Pour voir les interfaces :

sshdump --extcap-interfaces

Une seule interface (sshdump) est supportée.

Exemple de sortie

interface {value=sshdump}{display=Capture SSH distante}

Pour voir les DLTs de l'interface :

sshdump --extcap-interface=sshdump --extcap-dlts

Exemple de sortie

dlt {number=147}{name=sshdump}{display=DLT dépendant de la capture distante}

sshdump(8) — capture network traffic over SSH

SYNOPSIS

sshdump [ OPTIONS ]

DESCRIPTION

sshdump is an extcap tool that allows you to capture network traffic from a remote host using SSH. It leverages the standard SSH protocol to connect to the remote machine and execute capture commands like tcpdump or dumpcap.

This tool is particularly useful when you need to capture traffic from a machine that is not directly accessible via a physical interface or when you want to automate remote packet capture.

OPTIONS

The following options can be used to configure the SSH connection and the remote capture process.

Interface configuration options:

sshdump --extcap-interface=sshdump --extcap-config

EXAMPLES

To capture:

sshdump --extcap-interface=sshdump --fifo=/tmp/ssh.pcap --capture --remote-host 192.168.1.10
--remote-username user --remote-filter "not port 22"

To use different capture binaries:

sshdump --extcap-interface=sshdump --fifo=/tmp/ssh.pcap --capture --remote-host 192.168.1.10
--remote-username user --remote-priv sudo --remote-capture-command-select tcpdump
--remote-interface eth0 --remote-noprom
sshdump --extcap-interface=sshdump --fifo=/tmp/ssh.pcap --capture --remote-host 192.168.1.10
--remote-capture-command='dumpcap -i eth0 -P -w -'
sshdump --extcap-interface=sshdump --fifo=/tmp/ssh.pcap --capture --remote-host 192.168.1.10
--remote-capture-command='sudo tcpdump -i eth0 -U -w -'

Note

To stop capturing CTRL+C/kill/terminate the application.

The sshdump binary can be renamed to support multiple instances. For instance if we want sshdump to show up twice in wireshark (for instance to handle multiple profiles), we can copy sshdump to sshdump-host1 and sshdump-host2. Each binary will show up an interface name same as the executable name. Those executables not being "sshdump" will show up as "custom version" in the interface description.
