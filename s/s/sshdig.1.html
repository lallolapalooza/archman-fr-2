SSHDIG(1)   SSHDIG(1)

NOM

sshdig - Fournit des interfaces pour capturer les appels système d'un hôte distant via SSH en utilisant un binaire de capture distant.

SYNTAXE

sshdig [ --help ] [ --version ] [ --extcap-interfaces ] [ --extcap-dlts ] [ --extcap-interface=<interface> ] [ --extcap-config ] [ --extcap-capture-filter=<filtre de capture> ] [ --capture ] [ --fifo=<chemin vers fichier ou tube> ] [ --remote-host=<adresse IP> ] [ --remote-port=<port TCP> ] [ --remote-username=<nomdutilisateur> ] [ --remote-password=<motdepasse> ] [ --sshkey=<chemin vers clé privée> ] [ --sshkey-passphrase=<phrase secrète clé privée> ] [ --proxycommand=<commande proxy SSH> ] [ --remote-capture-command-select=<sélection commande capture> ] [ --remote-capture-command=<commande capture> ] [ --remote-priv=<sélection commande élévation privilèges> ] [ --remote-priv-user=<nom utilisateur privilégié> ] [ --remote-filter=<filtre capture distant> ] [ --remote-count=<nombre> ] [ --remote-modern-bpf ] [ --remote-io-snaplen=<longueur instantanée> ]

sshdig --extcap-interfaces

sshdig --extcap-interface=<interface> --extcap-dlts

sshdig --extcap-interface=<interface> --extcap-config

sshdig --extcap-interface=<interface> --fifo=<chemin vers fichier ou tube> --capture --remote-host=monhote-distant --remote-port=22 --remote-username=utilisateur --remote-capture-command='sysdig --unbuffered --write=-'

DESCRIPTION

Sshdig est un outil extcap qui permet de capturer les appels système via une connexion SSH. Vous devez avoir l'autorisation de capturer les appels système sur le système distant.

Cette fonctionnalité est fonctionnellement équivalente à

$ ssh utilisateur-distant@hote-distant -p 22222 'sysdig --unbuffered -w -' > FICHIER &
$ stratoshark FICHIER

Typiquement, sshdig n'est pas appelé directement. Il peut être configuré via l'interface graphique de Stratoshark ou sa ligne de commande. La commande suivante démarrera Stratoshark et commencera la capture depuis l'hôte hote-distant :

$ stratoshark '-oextcap.sshdig.remotehost:myserver.home.arpa' -i sshdig -k

Interfaces supportées :

1.sshdig

OPTIONS

--help

Affiche les arguments du programme.

--version

Affiche la version du programme.

--extcap-interfaces

Liste les interfaces disponibles.

--extcap-interface=<interface>

Utilise les interfaces spécifiées.

--extcap-dlts

Liste les DLTs de l'interface spécifiée.

--extcap-config

Liste les options de configuration de l'interface spécifiée.

--extcap-capture-filter=<filtre de capture>

Le filtre de capture. Il correspond à la valeur fournie via l'option tshark -f, et au champ Filtre de capture à côté de la liste des interfaces dans l'interface Stratoshark.

--capture

Commence la capture depuis l'interface spécifiée et écrit les données brutes des paquets à l'emplacement spécifié par --fifo.

--fifo=<chemin vers fichier ou tube>

Sauvegarde le paquet capturé dans un fichier ou l'envoie via un tube.

--remote-host=<hôte distant>

L'adresse de l'hôte distant pour la capture.

--remote-port=<port distant>

Le port SSH de l'hôte distant.

--remote-username=<nom d'utilisateur>

Le nom d'utilisateur pour l'authentification SSH.

--remote-password=<mot de passe>

Le mot de passe à utiliser (si ssh-agent et pubkey ne sont pas utilisés). ATTENTION : les mots de passe sont stockés en texte clair et visibles par tous les utilisateurs sur ce système. Il est recommandé d'utiliser des fichiers de clé avec un agent SSH.

--sshkey=<chemin vers clé privée SSH>

Le chemin vers une clé privée pour l'authentification. REMARQUE : Seul le format clé/valeur OPENSSH est pris en charge.

--sshkey-passphrase=<phrase secrète clé privée SSH>

La phrase secrète pour la clé privée pour l'authentification.

--proxycommand=<commande proxy>

La commande à utiliser comme proxy pour la connexion SSH.

--remote-capture-command-select=<sélection commande capture>

La commande à exécuter sur le système distant. Soit sysdig pour une commande de capture distante utilisant sysdig, soit other, où la commande de capture distante doit être fournie avec l'option --remote-capture-command.

--remote-capture-command=<commande capture>

Une commande de capture distante personnalisée qui produit le flux distant affiché dans Stratoshark. La commande doit être capable de produire un flux .scap écrit sur STDOUT.

--remote-priv=<sélection commande élévation privilèges>

La commande à utiliser pour obtenir l'élévation de privilèges afin de capturer sur l'hôte distant. Soit none, sudo ou doas.

--remote-priv-user=<nom utilisateur privilégié>

Si une commande est utilisée pour obtenir l'élévation de privilèges pour capturer sur l'hôte distant et nécessite un nom d'utilisateur, il peut être fourni ici.

--remote-filter=<filtre de capture>

Le filtre de capture distant. Il est passé au programme de capture distant, et doit respecter ses règles de syntaxe.

--remote-count=<nombre>

Le nombre d'événements à capturer.

--remote-modern-bpf

Capture en utilisant une sonde eBPF au lieu du module noyau.

--remote-io-snaplen=<longueur instantanée>

Le nombre d'octets à capturer dans chaque événement I/O.

EXEMPLES

Pour voir les arguments du programme :

sshdig --help

Pour voir la version du programme :

sshdig --version

Pour voir les interfaces :

sshdig --extcap-interfaces

sshdig(1)

NAME

sshdig - captures packets via SSH

SYNOPSIS

sshdig --extcap-interfaces
sshdig --extcap-list-interfaces
sshdig --extcap-version
sshdig --extcap-help
sshdig --extcap-interface=interface --fifo=path --capture [options]

DESCRIPTION

sshdig is an external capture plugin for Wireshark (and TShark) that allows capturing network traffic from a remote host via SSH.

It uses the SSH protocol to execute commands on the remote host, such as tcpdump or tshark, and streams the captured data back to the local machine via the FIFO.

OPTIONS

In addition to the standard extcap(4) options, sshdig supports the following:

--extcap-interface=interface
Specifies the capture interface to use. This is typically the hostname or IP address of the remote host.
--fifo=path
Specifies the path to the FIFO (named pipe) where the captured data will be written.
--remote-host=hostname/ip
The remote SSH server hostname or IP address.
--remote-port=port
The remote SSH server port (default: 22).
--remote-username=user
The username for the SSH connection.
--remote-password=password
The password for the SSH connection. Use with caution, prefer SSH keys.
--remote-key-file=path
The path to the SSH private key file for authentication.
--remote-ssh-options=options
Additional options to pass to the underlying SSH command (e.g., "-o StrictHostKeyChecking=no").
--ssh-sha1
Support SHA-1 keys (deprecated). Support keys and key exchange algorithms using SHA-1 (deprecated).
--remote-capture-command-select
Select the remote capture command to build a command line for.
sysdig
Use sysdig for capturing.
other
Specify a custom command.
--remote-capture-command=command
The remote command used to capture (e.g., tcpdump, tshark).
--remote-priv
Gain capture privilege on the remote machine.
none
Do not prepend the capture command with sudo or doas.
sudo
Prepend the capture command with sudo.
doas -n
Prepend the capture command with doas.
--remote-priv-user=user
User name of privileged user to execute the capture command on the remote machine.
--remote-count=number
The number of remote packets to capture. (Default: infinite).
--log-level
Set the log level.
message
Log messages.
info
Log info level messages.
debug
Log debug level messages.
noisy
Log noisy level messages.
--log-file=path
Set a file where log messages are written.

EXAMPLES

To capture:

sshdig --extcap-interface=sshdig --fifo=/tmp/ssh.scap --capture --remote-host 192.168.1.10
--remote-username user

Note

CTRL + C should be used to stop the capture in order to ensure clean termination.

The sshdig binary can be renamed to support multiple instances. For instance if we want sshdig to show up twice in Stratoshark (for instance to handle multiple profiles), we can copy sshdig to sshdig-host1 and sshdig-host2. Each binary will show up an interface name same as the executable name. Those executables not being "sshdig" will show up as "custom version" in the capture source description.
