NOM

sssd-sudo - Configuration de sudo avec le backend SSSD

DESCRIPTION

Cette page de manuel décrit comment configurer sudo(8) pour fonctionner avec sssd(8) et comment SSSD met en cache les règles sudo.

CONFIGURER SUDO POUR COOPÉRER AVEC SSSD

Pour activer SSSD en tant que source de règles sudo, ajoutez sss à l'entrée sudoers dans nsswitch.conf(5).

Par exemple, pour configurer sudo afin qu'il recherche d'abord les règles dans le fichier standard sudoers(5) (qui doit contenir les règles applicables aux utilisateurs locaux) puis dans SSSD, le fichier nsswitch.conf doit contenir la ligne suivante :

sudoers: files sss

Plus d'informations sur la configuration de l'ordre de recherche des fichiers sudoers à partir du fichier nsswitch.conf, ainsi que des informations sur le schéma LDAP utilisé pour stocker les règles sudo dans le répertoire, se trouvent dans sudoers.ldap(5).

Note : afin d'utiliser les netgroups ou les hostgroups IPA dans les règles sudo, vous devez également définir correctement nisdomainname(1) avec votre nom de domaine NIS (qui est égal au nom de domaine IPA lors de l'utilisation des hostgroups).

CONFIGURER SSSD POUR RÉCUPÉRER LES RÈGLES SUDO

Toute la configuration nécessaire du côté SSSD consiste à étendre la liste des services avec « sudo » dans la section [sssd] de sssd.conf(5). Pour accélérer les recherches LDAP, vous pouvez également définir la base de recherche des règles sudo à l'aide de l'option ldap_sudo_search_base.

L'exemple suivant montre comment configurer SSSD pour télécharger les règles sudo à partir d'un serveur LDAP.

[sssd]
services = nss, pam, sudo
domains = EXAMPLE
[domain/EXAMPLE]
id_provider = ldap
sudo_provider = ldap
ldap_uri = ldap://example.com
ldap_sudo_search_base = ou=sudoers,dc=example,dc=com

Il est important de noter que sur les plateformes où systemd est pris en charge, il n'est pas nécessaire d'ajouter le fournisseur « sudo » à la liste des services, car il est devenu facultatif. Cependant, le socket sssd-sudo doit être activé à la place.

Lorsque SSSD est configuré pour utiliser IPA comme fournisseur d'identifiants, le fournisseur sudo est automatiquement activé. La base de recherche sudo est configurée pour utiliser l'arborescence LDAP native IPA (cn=sudo,$SUFFIX). Si une autre base de recherche est définie dans sssd.conf, cette valeur sera utilisée à la place. L'arborescence de compatibilité (ou=sudoers,$SUFFIX) n'est plus requise pour la fonctionnalité sudo d'IPA.

LE MÉCANISME DE MISE EN CACHE DES RÈGLES SUDO

Le plus grand défi lors du développement du support sudo dans SSSD a été de garantir que l'exécution de sudo avec SSSD comme source de données offre la même expérience utilisateur et est aussi rapide que sudo, tout en fournissant l'ensemble des règles les plus récentes possible. Pour satisfaire ces exigences, SSSD utilise trois types de mises à jour. Elles sont appelées rafraîchissement complet, rafraîchissement intelligent et rafraîchissement des règles.

Le rafraîchissement intelligent télécharge périodiquement les règles nouvelles ou modifiées depuis la dernière mise à jour. Son objectif principal est de faire croître la base de données en récupérant uniquement de petits incréments qui ne génèrent pas une grande quantité de trafic réseau.

Le rafraîchissement complet supprime simplement toutes les règles sudo stockées dans le cache et les remplace par toutes les règles stockées sur le serveur. Ceci est utilisé pour maintenir la cohérence du cache en supprimant chaque règle qui a été supprimée du serveur. Cependant, un rafraîchissement complet peut produire beaucoup de trafic et doit donc être exécuté uniquement occasionnellement en fonction de la taille et de la stabilité des règles sudo.

Le rafraîchissement des règles garantit que nous n'accordons pas à l'utilisateur plus de permissions que celles définies. Il est déclenché chaque fois que l'utilisateur exécute sudo. Le rafraîchissement des règles trouvera toutes les règles qui s'appliquent à cet utilisateur, vérifiera leur heure d'expiration et les redéchargera si elles sont expirées. Dans le cas où certaines de ces règles sont manquantes sur le serveur, SSSD effectuera un rafraîchissement complet hors bande car davantage de règles (qui s'appliquent à d'autres utilisateurs) pourraient avoir été supprimées.

Si activé, SSSD ne stockera que les règles qui peuvent s'appliquer à cette machine. Cela signifie les règles qui contiennent l'une des valeurs suivantes dans l'attribut sudoHost :

•le mot-clé ALL
•un caractère générique
•un netgroup (sous la forme "+netgroup")
•le nom d'hôte ou le nom de domaine complet de cette machine
•l'une des adresses IP de cette machine
•l'une des adresses IP du réseau (sous la forme "adresse/masque")

Il existe de nombreuses options de configuration qui peuvent être utilisées pour ajuster le comportement. Veuillez vous référer à « ldap_sudo_* » dans sssd-ldap(5) et « sudo_* » dans sssd.conf(5).

OPTIMISER LES PERFORMANCES

SSSD utilise différents types de mécanismes avec des filtres LDAP plus ou moins complexes pour maintenir à jour les règles sudo mises en cache. La configuration par défaut est réglée sur des valeurs qui devraient satisfaire la plupart de nos utilisateurs, mais les paragraphes suivants contiennent quelques conseils pour affiner la configuration selon vos besoins.

1. Indexer les attributs LDAP. Assurez-vous que les attributs LDAP suivants sont indexés : objectClass, cn, entryUSN ou modifyTimestamp.

2. Définir ldap_sudo_search_base. Définissez la base de recherche sur le conteneur qui détient les règles sudo pour limiter la portée de la recherche.

3. Définir l'intervalle de rafraîchissement complet et intelligent. Si vos règles sudo ne changent pas souvent et que vous n'avez pas besoin d'une mise à jour rapide des règles mises en cache sur vos clients, vous pouvez envisager d'augmenter les valeurs de ldap_sudo_full_refresh_interval et ldap_sudo_smart_refresh_interval. Vous pouvez également envisager de désactiver le rafraîchissement intelligent en définissant ldap_sudo_smart_refresh_interval = 0.

4. Si vous avez un grand nombre de clients, vous pouvez envisager d'augmenter la valeur de ldap_sudo_random_offset pour mieux répartir la charge sur le serveur.
