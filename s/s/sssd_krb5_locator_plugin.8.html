NOM

sssd_krb5_locator_plugin - Plugin localisateur Kerberos

DESCRIPTION

Le plugin localisateur Kerberos sssd_krb5_locator_plugin est utilisé par libkrb5 pour trouver les KDC pour un domaine Kerberos donné. SSSD fournit un tel plugin pour diriger tous les clients Kerberos d'un système vers un seul KDC. En général, peu importe à quel KDC un processus client parle. Mais il y a des cas, par exemple après un changement de mot de passe, où tous les KDC ne sont pas dans le même état car les nouvelles données doivent être répliquées. Pour éviter des échecs d'authentification inattendus et éventuellement des blocages de compte, il serait bon de parler à un seul KDC aussi longtemps que possible.

libkrb5 recherche le plugin localisateur dans le sous-répertoire libkrb5 du répertoire des plugins Kerberos, voir plugin_base_dir dans krb5.conf(5) pour les détails. Le plugin ne peut être désactivé qu'en supprimant le fichier du plugin. Il n'y a pas d'option dans la configuration Kerberos pour le désactiver. Mais la variable d'environnement SSSD_KRB5_LOCATOR_DISABLE peut être utilisée pour désactiver le plugin pour des commandes individuelles. Alternativement, l'option SSSD krb5_use_kdcinfo=False peut être utilisée pour ne pas générer les données nécessaires au plugin. Avec cela, le plugin est toujours appelé mais ne fournira aucune donnée à l'appelant, de sorte que libkrb5 puisse revenir à d'autres méthodes définies dans krb5.conf.

Le plugin lit les informations sur les KDC d'un domaine donné à partir d'un fichier appelé kdcinfo.REALM. Le fichier doit contenir un ou plusieurs noms DNS ou adresses IP, soit en notation décimale quadruple IPv4, soit en notation hexadécimale IPv6. Un numéro de port optionnel peut être ajouté à la fin, séparé par un deux-points ; l'adresse IPv6 doit être entourée de crochets dans ce cas, comme d'habitude. Les entrées valides sont :

•kdc.example.com
•kdc.example.com:321
•1.2.3.4
•5.6.7.8:99
•2001:db8:85a3::8a2e:370:7334
•[2001:db8:85a3::8a2e:370:7334]:321

Le fournisseur d'authentification krb5 de SSSD, qui est également utilisé par les fournisseurs IPA et AD, ajoute l'adresse du KDC ou du contrôleur de domaine actuel que SSSD utilise à ce fichier.

Dans les environnements avec des KDC en lecture seule et en lecture-écriture où les clients sont censés utiliser les instances en lecture seule pour les opérations générales et uniquement le KDC en lecture-écriture pour les changements de configuration comme les changements de mot de passe, un fichier kpasswdinfo.REALM est également utilisé pour identifier les KDC en lecture-écriture. Si ce fichier existe pour le domaine donné, son contenu sera utilisé par le plugin pour répondre aux requêtes concernant un serveur kpasswd ou kadmin, ou pour le KDC maître spécifique à MIT Kerberos. Si l'adresse contient un numéro de port, le port KDC par défaut 88 sera utilisé pour ce dernier.

NOTES

Toutes les implémentations Kerberos ne prennent pas en charge l'utilisation de plugins. Si sssd_krb5_locator_plugin n'est pas disponible sur votre système, vous devez modifier /etc/krb5.conf pour refléter votre configuration Kerberos.

Si la variable d'environnement SSSD_KRB5_LOCATOR_DEBUG est définie sur n'importe quelle valeur, des messages de débogage seront envoyés sur la sortie d'erreur standard.

Si la variable d'environnement SSSD_KRB5_LOCATOR_DISABLE est définie sur n'importe quelle valeur, le plugin est désactivé et renverra simplement KRB5_PLUGIN_NO_HANDLE à l'appelant.

Si la variable d'environnement SSSD_KRB5_LOCATOR_IGNORE_DNS_FAILURES est définie sur n'importe quelle valeur, le plugin tentera de résoudre tous les noms DNS dans le fichier kdcinfo. Par défaut, le plugin renvoie KRB5_PLUGIN_NO_HANDLE à l'appelant immédiatement dès la première erreur de résolution DNS.
