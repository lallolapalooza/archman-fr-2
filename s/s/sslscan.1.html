SSLSCAN(1) Manuel des commandes générales SSLSCAN(1)

NOM

sslscan - Scanner SSL/TLS rapide

SYNTAXE

sslscan [options] [hôte:port | hôte]

DESCRIPTION

sslscan interroge les services SSL/TLS (tels que HTTPS) et rapporte les versions de protocole, les suites de chiffrement, les échanges de clés, les algorithmes de signature et les certificats utilisés. Cela aide l'utilisateur à comprendre quels paramètres sont faibles d'un point de vue sécurité. sslscan peut également exporter les résultats dans un fichier XML pour être facilement utilisés par des programmes externes.

La sortie sur le terminal est ainsi codée en couleurs comme suit :

Fond Rouge Chiffrements NULL (pas de chiffrement) ou chiffrements anonymes (pas de vérification du pair)
Rouge Chiffrements et algorithmes avec des vulnérabilités démontrées, ou qui sont généralement considérés comme non fiables.
Jaune Chiffrements et algorithmes avec des faiblesses connues ou qui sont encore trop nouveaux pour être largement fiables, mais qui ne sont pas généralement considérés comme exploitables (même selon les normes des vulnérabilités TLS).
Vert Chiffrements et algorithmes qui sont alignés sur les meilleures pratiques actuellement recommandées.

OPTIONS

--help

Afficher le résumé des options
--targets=<fichier>
Un fichier contenant une liste d'hôtes à vérifier. Les hôtes peuvent être fournis avec des ports (c.-à-d. hôte:port). Une cible par ligne.
--sni-name=<nom>
Utiliser un nom d'hôte différent pour SNI
--ipv4, -4

Forcer la résolution DNS IPv4. Par défaut, tente l'IPv4, et si cela échoue, se rabat sur l'IPv6.
--ipv6, -6

Forcer la résolution DNS IPv6. Par défaut, tente l'IPv4, et si cela échoue, se rabat sur l'IPv6.
--show-certificate
Afficher les informations du certificat.
--show-certificates
Afficher la chaîne de certificats complète.
--no-check-certificate
--no-check-certificate Ne pas signaler les certificats signés avec des algorithmes faibles (MD5 et SHA-1) ou des clés RSA courtes (<2048 bits).
--show-client-cas
Afficher une liste des CA que le serveur autorise pour l'authentification du client. Sera vide pour les serveurs IIS/Schannel.
--show-ciphers
Afficher une liste complète des chiffrements pris en charge par sslscan.
--show-cipher-ids
Afficher les identifiants hexadécimaux des chiffrements.
--iana-names
Utiliser les noms de chiffrement IANA/RFC plutôt que ceux d'OpenSSL.
--show-times
Afficher le temps nécessaire pour chaque négociation en millisecondes. Notez qu'une seule requête est effectuée avec chaque chiffrement, et que la taille du ClientHello n'est pas constante, elle ne doit donc pas être utilisée pour des tests de performance ou de benchmarks appropriés.

Vous pourriez également vouloir utiliser --no-cipher-details pour rendre la sortie un peu plus claire.

--ssl2

Vérifier uniquement si SSLv2 est activé.
--ssl3

Vérifier uniquement si SSLv3 est activé.
--tls10

Vérifier uniquement les chiffrements TLS 1.0.
--tls11

Vérifier uniquement les chiffrements TLS 1.1.
--tls12

Vérifier uniquement les chiffrements TLS 1.2.
--tls13

Vérifier uniquement les chiffrements TLS 1.3.
--tlsall

Vérifier uniquement les chiffrements TLS (versions 1.0, 1.1, 1.2 et 1.3).
--ocsp

Afficher le statut OCSP.
--pk=<fichier>
Un fichier contenant la clé privée ou un fichier PKCS#12 contenant une paire clé privée/certificat (comme produit par MSIE et Netscape).
--pkpass=<mot-de-passe>
Le mot de passe pour la clé privée ou le fichier PKCS#12.
--certs=<fichier>
Un fichier contenant des certificats clients au format PEM/ASN1.
--no-ciphersuites
Ne pas scanner les suites de chiffrement prises en charge.
--no-fallback
Ne pas vérifier la valeur de la suite de chiffrement de repli (fallback) de TLS.
--no-renegotiation
Ne pas vérifier la renégociation TLS sécurisée.
--no-compression
Ne pas vérifier la compression TLS (CRIME).
--no-heartbleed
Ne pas vérifier la vulnérabilité Heartbleed d'OpenSSL (CVE-2014-0160).
--no-groups
Ne pas énumérer les groupes d'échange de clés.
--show-sigs
Énumérer les algorithmes de signature.
--starttls-ftp
Configuration STARTTLS pour FTP.
--starttls-imap
Configuration STARTTLS pour IMAP.
--starttls-irc
Configuration STARTTLS pour IRC.
--starttls-ldap
Configuration STARTTLS pour LDAP.
--starttls-pop3
Configuration STARTTLS pour POP3.
--starttls-smtp
Configuration STARTTLS pour SMTP.
--starttls-mysql
Configuration STARTTLS pour MySQL.
--starttls-xmpp
Configuration STARTTLS pour XMPP.
--starttls-psql
Configuration STARTTLS pour PostgreSQL.
--xmpp-server
Effectuer une connexion XMPP serveur à serveur. Essayez ceci si --starttls-xmpp échoue.
--rdp

Envoyer un préambule RDP avant de commencer le scan.
--bugs

Active les contournements pour les bugs SSL.
--timeout=<sec>

Définir le délai d'attente de la socket. Utile pour les hôtes qui ne répondent pas aux chiffrements qu'ils ne comprennent pas. Par défaut, 3s.
--connect-timeout=<sec>

Définir le délai d'attente initial de la connexion. Utile pour les hôtes qui répondent lentement à la connexion initiale(). Par défaut, 75s.
--sleep=<msec>

Faire une pause entre les connexions. Utile sur les services SMTP STARTTLS, ou tout autre service qui effectue une limitation de débit. Par défaut, désactivé.
--xml=<fichier>

Exporter les résultats dans un fichier XML. - peut être utilisé pour signifier la sortie standard.
--version
Afficher la version du programme.
--verbose
Afficher une sortie détaillée.
--no-cipher-details

Masquer le nom de la courbe EC NIST et la longueur de la clé EDH/RSA.
--no-colour

Désactiver la sortie colorée.

EXEMPLES

Analyser un serveur HTTPS local

sslscan localhost
sslscan 127.0.0.1
sslscan 127.0.0.1:443
sslscan [::1]
sslscan [::1]:443
