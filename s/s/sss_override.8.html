NOM

sss_override - créer des remplacements locaux d'attributs d'utilisateurs et de groupes

SYNTAXE

sss_override COMMANDE [options]

DESCRIPTION

sss_override permet de créer une vue côté client et de modifier des valeurs spécifiques pour certains utilisateurs et groupes. Ces modifications n'ont d'effet que sur la machine locale.

Les données de remplacement sont stockées dans le cache SSSD. Si le cache est supprimé, tous les remplacements locaux sont perdus. Veuillez noter qu'après la création du premier remplacement à l'aide des commandes user-add, group-add, user-import ou group-import, SSSD doit être redémarré pour prendre effet. sss_override affiche un message lorsqu'un redémarrage est requis.

NOTE : Les options fournies dans cette page de manuel ne fonctionnent qu'avec les “id_provider” “ldap” et “AD”. Les remplacements IPA peuvent être gérés de manière centralisée sur le serveur IPA.

COMMANDES DISPONIBLES

Le NOM est le nom de l'objet d'origine dans toutes les commandes. Il n'est pas possible de remplacer uid ou gid par 0.

user-add NOM [-n,--nom NOM] [-u,--uid UID] [-g,--gid GID] [-h,--home HOME] [-s,--shell SHELL] [-c,--gecos GECOS] [-x,--certificate CERTIFICAT ENCODÉ EN BASE64]

Remplace les attributs d'un utilisateur. Soyez conscient que l'appel de cette commande remplacera tout remplacement précédent pour l'utilisateur (NOMmé).

user-del NOM

Supprime les remplacements d'utilisateurs. Cependant, soyez conscient que les attributs remplacés peuvent être renvoyés depuis le cache mémoire. Veuillez consulter l'option SSSD memcache_timeout pour plus d'informations.

user-find [-d,--domaine DOMAINE]

Liste tous les utilisateurs ayant des remplacements définis. Si le paramètre DOMAINE est défini, seuls les utilisateurs du domaine sont listés.

user-show NOM

Affiche les remplacements d'utilisateurs.

user-import FICHIER

Importe les remplacements d'utilisateurs depuis le FICHIER. Le format des données est similaire à celui du fichier passwd standard. Le format est :

nom_original:nom:uid:gid:gecos:home:shell:certificat_encodé_base64

où nom_original est le nom d'origine de l'utilisateur dont les attributs doivent être remplacés. Le reste des champs correspond aux nouvelles valeurs. Vous pouvez omettre une valeur en laissant simplement le champ correspondant vide.

Exemples :

ckent:superman::::::

ckent@krypton.com::501:501:Superman:/home/earth:/bin/bash:

user-export FICHIER

Exporte tous les attributs remplacés et les stocke dans le FICHIER. Voir user-import pour le format des données.

group-add NOM [-n,--nom NOM] [-g,--gid GID]

Remplace les attributs d'un groupe. Soyez conscient que l'appel de cette commande remplacera tout remplacement précédent pour le groupe (NOMmé).

group-del NOM

Supprime les remplacements de groupes. Cependant, soyez conscient que les attributs remplacés peuvent être renvoyés depuis le cache mémoire. Veuillez consulter l'option SSSD memcache_timeout pour plus d'informations.

group-find [-d,--domaine DOMAINE]

Liste tous les groupes ayant des remplacements définis. Si le paramètre DOMAINE est défini, seuls les groupes du domaine sont listés.

group-show NOM

Affiche les remplacements de groupes.

group-import FICHIER

Importe les remplacements de groupes depuis le FICHIER. Le format des données est similaire à celui du fichier group standard. Le format est :

nom_original:nom:gid

où nom_original est le nom d'origine du groupe dont les attributs doivent être remplacés. Le reste des champs correspond aux nouvelles valeurs. Vous pouvez omettre une valeur en laissant simplement le champ correspondant vide.

Exemples :

admins:administrateurs:

Domain Users:Users:501

group-export FICHIER

Exporte tous les attributs remplacés et les stocke dans le FICHIER. Voir group-import pour le format des données.

OPTIONS COMMUNES

Ces options sont disponibles avec toutes les commandes.

--debug NIVEAU

SSSD prend en charge deux représentations pour spécifier le niveau de débogage. La plus simple consiste à spécifier une valeur décimale de 0 à 9, ce qui correspond à l'activation de ce niveau et de tous les messages de débogage de niveau inférieur. L'option plus complète consiste à spécifier un masque de bits hexadécimal pour activer ou désactiver des niveaux spécifiques (par exemple, si vous souhaitez supprimer un niveau).

Niveaux de débogage actuellement pris en charge :

0, 0x0010 : Échecs fatals. Tout ce qui empêche SSSD de démarrer ou provoque son arrêt.

1, 0x0020 : Échecs critiques. Une erreur qui ne tue pas SSSD, mais qui indique qu'au moins une fonctionnalité majeure ne fonctionnera pas correctement.

2, 0x0040 : Échecs graves. Une erreur signalant qu'une requête ou une opération particulière a échoué.

3, 0x0080 : Échecs mineurs. Ce sont les erreurs qui remontent pour provoquer l'échec de l'opération 2.

4, 0x0100 : Paramètres de configuration.

5, 0x0200 : Données de fonction.

6, 0x0400 : Messages de trace pour les fonctions d'opération.

7, 0x1000 : Messages de trace pour les fonctions de contrôle internes.

8, 0x2000 : Contenu des variables internes de fonction qui peuvent être intéressantes.

9, 0x4000 : Informations de trace de niveau extrêmement bas.

10, 0x10000 : Informations de trace libldb de niveau encore plus bas. Presque jamais vraiment nécessaire.

Pour journaliser les niveaux de débogage requis par masque de bits, il suffit d'additionner leurs nombres comme indiqué dans les exemples suivants :

Exemple : Pour journaliser les échecs fatals, critiques, graves et les données de fonction, utilisez 0x0270.

Exemple : Pour journaliser les échecs fatals, les paramètres de configuration, les données de fonction, les messages de trace pour les fonctions de contrôle internes, utilisez 0x1310.

Note : Le format de masque de bits des niveaux de débogage a été introduit dans la version 1.7.0.

Défaut : 0x0070 (c'est-à-dire échecs fatals, critiques et graves ; correspond à la définition 2 en notation décimale)
