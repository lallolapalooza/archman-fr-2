NOM

sssd-idp - Fournisseur IdP de SSSD

DESCRIPTION

Cette page de manuel décrit la configuration du fournisseur IdP pour sssd(8). Pour une référence de syntaxe détaillée, consultez la section « RÉFÉRENCE DE FICHIER » de la page de manuel sssd.conf(5).

Le fournisseur IdP est un backend utilisé pour se connecter à un fournisseur d'identité (IdP) basé sur OAuth 2.0 et REST. Comme les produits peuvent avoir une implémentation individuelle de l'API REST pour rechercher les attributs des utilisateurs et des groupes, un code dédié peut être requis, voir l'option « idp_type » pour plus de détails.

Les IdP ne fournissent généralement pas d'attributs POSIX comme par exemple l'identifiant d'utilisateur (UID) ou le répertoire personnel. Le fournisseur IdP de SSSD générera automatiquement les attributs nécessaires. L'algorithme par défaut pour générer les identifiants utilisateur (UID) et identifiants de groupe (GIDs) vise à créer des identifiants reproductibles sur différents systèmes. En contrepartie, il peut arriver que l'algorithme attribue le même identifiant à différents objets et que seul le premier demandé via SSSD soit disponible.

OPTIONS DE CONFIGURATION

Reportez-vous à la section « SECTIONS DE DOMAINE » de la page de manuel sssd.conf(5) pour plus de détails sur la configuration d'un domaine SSSD.

idp_type (chaîne)

Option requise qui spécifie le produit IdP. Actuellement, Entra ID (entra_id) et Keycloak (keycloak) sont pris en charge.

Selon le produit IdP, des options supplémentaires spécifiques à la plateforme peuvent suivre le nom séparé par un deux-points (:). Par exemple, pour Keycloak, l'URI de base pour l'API REST des utilisateurs et des groupes doit être fournie. Pour Entra ID, ce n'est pas nécessaire car il existe un point de terminaison générique pour tous les locataires.

Par défaut : Non défini (Requis)

idp_client_id (chaîne)

ID du client IdP utilisé par SSSD pour authentifier les utilisateurs et en tant que client pour rechercher les attributs des utilisateurs et des groupes. Ce client doit proposer l'autorisation par appareil conformément à la RFC-8628 et doit avoir les autorisations pour rechercher et lire les attributs des utilisateurs et des groupes.

Par défaut : Non défini (Requis)

idp_client_secret (chaîne)

Mot de passe du client IdP. Le mot de passe est requis pour l'id_provider. S'il est uniquement utilisé comme auth_provider, cela dépend de la configuration côté serveur pour savoir s'il est requis ou non.

Par défaut : Non défini

idp_token_endpoint (chaîne)

Point de terminaison IdP pour demander des jetons d'accès.

Par défaut : Non défini (Requis)

idp_device_auth_endpoint (chaîne)

Point de terminaison d'autorisation par appareil de l'IdP conformément à la RFC-8628. Ceci est requis pour l'authentification des utilisateurs.

Par défaut : Non défini

idp_userinfo_endpoint (chaîne)

Point de terminaison userinfo de l'IdP pour demander les attributs de l'utilisateur après une authentification réussie de l'utilisateur. Requis pour l'authentification.

Par défaut : Non défini

idp_id_scope (chaîne)

Portée requise pour rechercher les attributs des utilisateurs et des groupes avec l'API REST. Les portées sont utilisées par le serveur pour déterminer quels attributs/revendications sont retournés à l'appelant.

Par défaut : Non défini

idp_auth_scope (chaîne)

Portée requise lors de l'authentification. Les portées sont utilisées par le serveur pour déterminer quels attributs/revendications sont retournés à l'appelant.

Actuellement, les jetons retournés lors de l'authentification de l'utilisateur ne sont pas utilisés à d'autres fins, donc la seule revendication importante est l'identifiant du sujet « sub » qui est utilisé pour vérifier si l'utilisateur authentifié est bien celui qui essaie de se connecter. Cela pourrait changer à l'avenir.

Par défaut : Non défini

idp_request_timeout (entier)

Délai d'attente en secondes pour une requête individuelle vers l'IdP.

Par défaut : 10

idmap_range_min (entier)

Spécifie la limite inférieure (inclusive) de la plage des identifiants POSIX à utiliser pour mapper les utilisateurs et les groupes IdP aux identifiants POSIX. C'est le premier identifiant POSIX qui peut être utilisé pour le mappage.

L'intervalle entre « idmap_range_min » et « idmap_range_max » sera divisé en plus petites plages de taille « idmap_range_size » qui seront utilisées par un domaine IdP individuel.

Par défaut : 200000

idmap_range_max (entier)

Spécifie la limite supérieure (exclusive) de la plage des identifiants POSIX à utiliser pour mapper les utilisateurs et les groupes IdP aux identifiants POSIX. C'est le premier identifiant POSIX qui ne sera plus utilisé pour le mappage d'identifiants POSIX.

Par défaut : 2000200000

idmap_range_size (entier)

Spécifie le nombre d'identifiants POSIX disponibles pour un domaine IdP unique.

Par défaut : 200000

EXEMPLE

[domain/entra_id]
id_provider = idp
idp_type = entra_id
idp_client_id = 12345678-abcd-0101-efef-ba9876543210
idp_client_secret = VOTRE-CLIENT-SCERET
idp_token_endpoint = https://login.microsoftonline.com/TENNANT-ID/oauth2/v2.0/token
idp_userinfo_endpoint = https://graph.microsoft.com/v1.0/me
idp_device_auth_endpoint = https://login.microsoftonline.com/TENNANT-ID/oauth2/v2.0/devicecode
idp_id_scope = https%3A%2F%2Fgraph.microsoft.com%2F.default
idp_auth_scope = openid profile email
[domain/keycloak]
idp_type = keycloak:https://master.keycloak.test:8443/auth/admin/realms/master/
id_provider = idp
idp_client_id = myclient
idp_client_secret = VOTRE-CLIENT-SCERET
idp_token_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/token
idp_userinfo_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/userinfo
idp_device_auth_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/auth/device
idp_id_scope = profile
idp_auth_scope = openid profile email
