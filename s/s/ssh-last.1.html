SSH-LAST(1) Commandes utilisateur SSH-LAST(1)

NOM

ssh-last - lister les dernières sessions SSH

SYNTAXE

           ssh-last [OPTIONS]
ssh_logs | ssh-last [OPTIONS]

Options

-a  afficher toutes les sessions                       (afficher les données masquées par le fichier 'ignored')
-c  sortie colorée                                  (mettre en surbrillance les sessions SSH actives)
-d  debug
-f  forcer l'affichage des empreintes                 (pas de mappage depuis le fichier 'known')
-h  afficher ce message d'aide
-i  forcer l'affichage des identifiants de certificat               (pas de mappage depuis le fichier 'known', pas ensemble avec -f)
-l  essayer d'utiliser les fichiers journaux au lieu de journalctl   (peut être encore plus rapide sur certains systèmes)
-n  afficher l'hôte/IP en texte clair                 (pas de mappage depuis le fichier 'known')
-w  afficher uniquement les sessions SSH actives
-?  afficher le manuel complet avec des informations plus détaillées
    (nécessite généralement l'installation de perl-doc pour fonctionner correctement)
--version    afficher les informations de version

Exemples

ssh-last
ssh-last -c | more
ssh-last -c | less -R   # conserve la sortie colorée dans less
ssh-last -cw
# Journaux d'hier
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since yesterday               | ssh-last
# Journaux d'il y a trois jours
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since -3d --until -2d         | ssh-last
# Journaux de la dernière heure
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since -1h                     | ssh-last
# Journaux jusqu'à une date spécifique
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --until "2022-03-12 07:00:00"   | ssh-last
# Depuis les fichiers journaux (l'ordre doit être du plus ancien au plus récent)
zgrep -hE 'Accepted|Disconnected' auth.log.2.gz  auth.log.1  auth.log                      | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/auth.log* --sort=time --reverse)           | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/messages* --sort=time --reverse)           | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/secure*   --sort=time --reverse)           | ssh-last

DESCRIPTION

ssh-last est comme last mais pour les sessions SSH

Indicateurs de sortie

+--------------------------------------------------------------------------+
|                                                                          |
| AUTH_ID                                                                  |
|                                                                          |
| (C) connexion autorisée sshd via (c)ertificat                              |
| (K) connexion autorisée sshd via clé publique (k)ey                               |
| (?) connexion autorisée sshd via un autre type (mot de passe, pam)            |
|                                                                          |
+--------------------------------------------------------------------------+

Algorithme

Parcours des journaux sshd dans l'ordre chronologique :
1) Recherche des lignes de connexion (Accepted) et de déconnexion (Disconnected).
2) Stockage des informations des lignes telles que le nom d'utilisateur, le type d'authentification, l'empreinte, ...
3) Utilisation du port réseau utilisé pour vérifier les sessions actives
   et reconstruction des anciennes sessions en mémorisant les ports réseau connectés
4) Utilisation principale de /etc/os-release pour s'adapter aux différents systèmes
   qui diffèrent par les noms de fichiers journaux, les motifs de journalisation, etc...

BOGUES ET LIMITATIONS

Hôtes Saut

L'utilisation d'un hôte saut avec ProxyCommand ou ProxyJump,
peut souvent entraîner une déconnexion non nette sans rien enregistrer,
donc LOGOUT et DURATION ne peuvent pas être affichés.

Utilisateurs non privilégiés

Si possible, exécutez ssh-last en tant que root ou via sudo
1) Les fichiers journaux et le journal de systemd ne peuvent généralement pas être lus par un utilisateur normal
2) ssh-last -w ne fonctionne de manière fiable qu'en tant que root,
   car ss et netstat n'affichent pas les informations du processus lorsqu'ils sont invoqués en tant qu'utilisateur normal
3) ssh-last essaie de mapper l'empreinte depuis le fichier authorized_keys d'un utilisateur
   mais les utilisateurs ne sont généralement pas autorisés à consulter les fichiers des autres

Mises à niveau du système d'exploitation

Si vous effectuez une mise à niveau sur place comme dist-upgrade sur Debian/Ubuntu,
en fonction de la différence de version,
il peut arriver que sshd enregistre différemment à partir de ce moment
et vous pourriez avoir un mélange de journaux dans les anciens et nouveaux formats
ce qui fait que ssh-last n'affiche correctement que les derniers.

Incohérence des journaux

J'ai vu des cas où certains messages de journal "Disconnect" de sshd
manquaient dans le journal de systemd mais existaient dans /var/log/auth.log.
Donc, si ssh-last n'affiche pas de déconnexion et de durée
mais que les lignes de journal existent dans le fichier journal, vérifiez si le message du journal
a bien atteint le journal de systemd car ssh-last utilise journald par défaut

NOTES

Scripts d'aide

elper Scripts 
Pour plus de commodité, vous pouvez créer de petits scripts d'enveloppe comme suit
qui évitent d'analyser trop de journaux en limitant les données à la dernière semaine
my-ssh-last
+--------------------------------------------------------------------------+
| #!/usr/bin/env bash                                                      |
|                                                                          |
| LC_TIME=C journalctl _COMM=sshd --since -1week \                         |
| | grep -E 'Accepted|Disconnected'              \                         |
| | ssh-last "$@"                                                          |
|                                                                          |
+--------------------------------------------------------------------------+
