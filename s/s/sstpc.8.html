NOM

sstpc - Client SSTP

SYNTAXE

sstpc [<options-sstp>] <nom_hote> [options-ppp] ...

DESCRIPTION

sstpc établit le côté client d'un réseau privé virtuel (VPN) en utilisant le protocole Secure Socket Tunneling Protocol (SSTP). Utilisez ce programme pour vous connecter à un VPN basé sur SSTP de votre employeur lorsque PPTP et L2TP ne fonctionnent pas.

Par défaut, sstpc établit la connexion SSTP vers le serveur SSTP, puis démarre une instance de pppd pour gérer le transfert de données. Cependant, sstpc peut également être exécuté comme un gestionnaire de connexion dans pppd.

OPTIONS

Le premier argument ne commençant pas par une option sur la ligne de commande de sstpc doit être le nom d'hôte ou l'adresse IP du serveur SSTP.

Toutes les options longues (commençant par "--") sont interprétées comme des options sstpc, et une erreur fatale survient si une option non reconnue est utilisée.

Tous les arguments de ligne de commande qui ne commencent pas par "-" sont interprétés comme des options ppp et passés tels quels à pppd à moins que --nolaunchpppd ne soit spécifié.

--ca-cert
Spécifie le certificat d'autorité de certification (CA) utilisé pour vérifier le serveur.
--ca-dir
Spécifie le répertoire de certificats contenant le certificat d'autorité de certification. Si rien n'est spécifié, le répertoire global du système est utilisé.
--cert-warn
Ignore les avertissements de certificat comme le nom commun au lieu de terminer la connexion.
--host
Lors de la connexion à une adresse IP, le paramètre d'hôte fournira le nom d'hôte pour http, proxy et tls-ext.
--ipparam
Cela aidera à spécifier le socket de rappel auquel pppd essaiera de se reconnecter à sstpc afin de communiquer les clés MPPE négociées. Les clés MPPE sont nécessaires pour s'authentifier auprès du serveur au niveau SSL. Elles peuvent être mises à zéro si aucun MPPE n'est négocié. Le nom est formé à partir de /tmp/sstpc-<ipparam>.
--nolaunchpppd
Ne pas lancer pppd mais utiliser stdin comme connexion réseau. Utilisez ce drapeau lorsque vous incluez sstpc comme processus de connexion pppd en utilisant l'option pty. Voir EXEMPLES.
--password
Spécifie un mot de passe par ligne de commande au lieu de le définir dans un fichier de configuration pour pppd dans /etc/ppp/peers.
--proxy
Se connecter au serveur SSTP via un proxy sur votre réseau. La syntaxe est http://[<utilisateur>:<mot_de_passe>@]<domaine>:port.
--priv-user
Spécifie l'utilisateur de séparation des privilèges pour exécuter sstpc.
--priv-group
Spécifie le groupe de séparation des privilèges pour exécuter sstpc.
--priv-dir
Spécifie le répertoire de séparation des privilèges pour la jail chroot où exécuter sstpc.
--user
Spécifie le nom d'utilisateur pour s'authentifier auprès du serveur SSTP au lieu de le définir dans un fichier de configuration pour pppd dans /etc/ppp/peers.
--save-server-route
Cela ajoutera et supprimera automatiquement une route vers le serveur SSTP.
--uuid
Spécifie un UUID pour la connexion afin de simplifier le débogage côté serveur.
--tls-ext
Cela activera l'extension de nom d'hôte TLS.

Dépannage

Les options suivantes sont disponibles pour aider au dépannnege de sstpc

--log-level <niveau>
Définit le niveau de débogage pour le processus sstpc. Le niveau peut être une valeur comprise entre 0 et 4.
--log-syslog
Journalise les messages dans syslog (par défaut).
--log-stderr
Journalise les messages sur la sortie d'erreur.
--log-stdout
Journalise les messages sur la sortie standard.
--log-fileno
Inclut le nom du fichier et le numéro de ligne avec les messages de journalisation.
--log-filter
Filtre les journaux par un ensemble particulier de fichiers, par exemple : sstp-packet,sstp-state
--log-ident
Spécifie l'identifiant qui sera utilisé lors de l'écriture des journaux, par exemple, dans syslog.

EXEMPLES

Connexion à un service RAS de Microsoft Windows en utilisant le protocole SSTP

Configurez les scripts peers dans /etc/ppp/peers, vous pouvez commencer par cloner l'un des scripts disponibles dans votre répertoire de documentation, /usr/share/doc/sstp-client, ou /usr/local/share/doc/sstp-client. Le contenu général de ce fichier sera proche de ce qui suit :
# Exemple de contenu de /etc/ppp/peers/sstp-test
remotename sstp-test
linkname sstp-test
ipparam sstp-test
pty "sstpc --ipparam sstp-test --nolaunchpppd sstp-test.votre-domaine.com"
name eivnaes
plugin sstp-pppd-plugin.so
sstp-sock /var/run/sstpc/sstpc-sstp-test
usepeerdns
require-mppe
require-mschap-v2
refuse-eap
refuse-pap
refuse-chap
refuse-mschap
nobsdcomp
nodeflate
Notez que le fichier chap-secrets utilisé par pppd doit inclure une entrée pour domaine\\nom_utilisateur. Pour l'exemple sstp-test, l'utilisateur eivnaes aura une entrée équivalente dans le fichier /etc/ppp/chap-secrets.

# Secrets pour l'authentification par CHAP
# client serveur secret adresses IP
eivnaes * xxxxxx *

Démarrage de sstp-test en utilisant le script pon
sudo pon sstp-test
Invocation de sstpc en utilisant la commande call
sstpc --ipparam sstp-test sstp-test.votre-domaine.com call sstp-test-nopty
Le sstp-test-nopty est un script pppd que vous devez créer dans /etc/ppp/peers, et vous pouvez cloner l'exemple sstp-test ci-dessus ; mais vous devez omettre l'instruction pty dans la configuration des peers.
