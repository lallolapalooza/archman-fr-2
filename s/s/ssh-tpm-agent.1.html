SSH-TPM-AGENT(1) Manuel ssh-tpm-agent SSH-TPM-AGENT(1)

NOM

ssh-tpm-agent - ssh-agent pour les clés TPM 2.0

SYNTAXE

ssh-tpm-agent [OPTIONS]

ssh-tpm-agent --print-socket

ssh-tpm-agent --install-user-units

DESCRIPTION

ssh-tpm-agent est un programme qui crée des clés utilisant un module de plateforme de confiance (TPM) pour activer les clés privées chiffrées pour l'authentification par clé publique.

OPTIONS

-l CHEMIN

Chemin du socket UNIX à ouvrir

Par défaut : $XDG_RUNTIME_DIR/ssh-tpm-agent.sock.

-A CHEMIN

Sockets ssh-agent de secours pour la recherche de clés supplémentaires.

--print-socket

Imprime le socket sur STDOUT.

--key-dir CHEMIN

Chemin du répertoire où chercher les clés scellées TPM.

Par défaut : ~/.ssh.

--no-load

Ne charge pas les clés scellées TPM de ~/.ssh par défaut.

-o, --owner-password

Demande le mot de passe du propriétaire.

--no-cache

L'agent ne mettra pas en cache les mots de passe des clés.

--hierarchy HIERARCHIE

Charge les clés de hiérarchie dans l'agent.

Voir Clés de hiérarchie pour plus d'informations.

Hiérarchies disponibles :

•owner, o
•endorsement, e
•null, n
•platform, p

-d

Active la journalisation de débogage.

--install-user-units

Installe les unités système systemd et les configurations sshd pour utiliser ssh-tpm-agent comme agent de clés d'hôte.

--swtpm

Stocke les clés à l'intérieur d'une instance swtpm au lieu du TPM réel. Ceci n'est pas une fonctionnalité de sécurité et vos clés ne sont pas stockées de manière sécurisée.

Peut également être activé avec la variable d'environnement SSH_TPM_AGENT_SWTPM.

EXEMPLES

Utilisation normale de l'agent

ssh-tpm-agent peut être utilisé comme remplacement direct de ssh-agent et fonctionne de la même manière.

$ ssh-tpm-keygen
# Ajouter ~/.ssh/id_ecdsa.pub à vos comptes Github
$ ssh-tpm-agent &
$ export SSH_AUTH_SOCK=$(ssh-tpm-agent --print-socket)
$ ssh git@github.com

Voir ssh-tpm-keygen(1) pour l'utilisation de keygen.

Support de secours de l'agent

ssh-tpm-agent prend en charge le secours vers différents ssh-agent. Les agents peuvent être ajoutés avec l'interrupteur -A. Ceci amènera ssh-tpm-agent à se propager à tous les agents disponibles pour les clés.

Ceci est pratique si vous avez plusieurs clés de différentes implémentations d'agent mais que vous souhaitez vous fier à un seul socket.

# Démarrer le ssh-agent habituel
$ eval $(ssh-agent)
# Créer une clé RSA forte
$ ssh-keygen -t rsa -b 4096 -f id_rsa -C ssh-agent
...
L'empreinte de la clé est :
SHA256:zLSeyU/6NKHGEvyZLA866S1jGqwdwdAxRFff8Z2N1i0 ssh-agent
$ ssh-add id_rsa
Identité ajoutée : id_rsa (ssh-agent)
# Imprimer la longue clé
$ ssh-add -L
ssh-rsa AAAAB3NzaC1yc[...]8TWynQ== ssh-agent
# Créer une clé sur le TPM
$ ssh-tpm-keygen -C ssh-tpm-agent
Génération d'une paire de clés ecdsa publique/privée scellée.
Entrez le fichier dans lequel enregistrer la clé (/home/utilisateur/.ssh/id_ecdsa) :
Entrez la phrase secrète (vide pour aucune phrase secrète) :
Confirmez la phrase secrète :
Votre identification a été enregistrée dans /home/utilisateur/.ssh/id_ecdsa.tpm
Votre clé publique a été enregistrée dans /home/utilisateur/.ssh/id_ecdsa.pub
L'empreinte de la clé est :
SHA256:PoQyuzOpEBLqT+xtP0dnvyBVL6UQTiQeCWN/EXIxPOo
L'image randomart de la clé est de la couleur de la télévision, syntonisée sur un canal mort.
# Démarrer ssh-tpm-agent avec un socket proxy
$ ssh-tpm-agent -A "${SSH_AUTH_SOCK}" &
$ export SSH_AUTH_SOCK="$(ssh-tpm-agent --print-socket)"
# ssh-tpm-agent relaie les clés de ssh-agent
$ ssh-add -L
ssh-rsa AAAAB3NzaC1yc[...]8TWynQ== ssh-agent
ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNo[...]q4whro= ssh-tpm-agent

Utilisation des clés hotes

ssh-tpm-agent peut également être utilisé pour servir des clés d'hôte pour un serveur ssh. ssh-tpm-hostkeys possède des interrupteurs pratiques pour aider à installer les configurations et services systemd dans le système. Cela créera un socket système pour ssh-tpm-agent sous /var/tmp/ssh-tpm-agent.sock.

$ sudo ssh-tpm-keygen -A
2023/09/03 17:03:08 INFO Génération d'une nouvelle clé d'hôte ECDSA
2023/09/03 17:03:08 INFO Écrit /etc/ssh/ssh_tpm_host_ecdsa_key.tpm
2023/09/03 17:03:08 INFO Génération d'une nouvelle clé d'hôte RSA
2023/09/03 17:03:15 INFO Écrit /etc/ssh/ssh_tpm_host_rsa_key.tpm
$ sudo ssh-tpm-hostkeys --install-system-units
Installé /usr/lib/systemd/system/ssh-tpm-agent.service
Installé /usr/lib/systemd/system/ssh-tpm-agent.socket
Installé /usr/lib/systemd/system/ssh-tpm-genkeys.service
Activer avec : systemctl enable --now ssh-tpm-agent.socket
$ sudo ssh-tpm-hostkeys --install-sshd-config
Installé /etc/ssh/sshd_config.d/10-ssh-tpm-agent.conf
Redémarrer sshd : systemd restart sshd
$ systemctl enable --now ssh-tpm-agent.socket
$ systemd restart sshd
$ sudo ssh-tpm-hostkeys
ecdsa-sha2-nistp256 AAAAE2V[...]YNwqWY0= root@localhost
ssh-rsa AAAAB3NzaC1ycA[...]N1Jg3fLQKSe7f root@localhost
$ ssh-keyscan -t ecdsa localhost
# localhost:22 SSH-2.0-OpenSSH_9.4
localhost ecdsa-sha2-nistp256 AAAAE2V[...]YNwqWY0=

Alternativement, on peut omettre les indicateurs d'installation intégrés et simplement inclure une configuration de remplacement pour sshd sous /etc/ssh/sshd_config.d avec le contenu suivant.

HostKeyAgent /var/tmp/ssh-tpm-agent.sock
HostKey /etc/ssh/ssh_tpm_host_ecdsa_key.pub
HostKey /etc/ssh/ssh_tpm_host_rsa_key.pub

Clés de hiérarchie

Les TPM sont capables de créer des clés statiques utilisant les hiérarchies de plus haut niveau. Cela permet à l'utilisateur de créer des clés disponibles pendant la durée de vie de l'appareil, pour le propriétaire actuel de l'appareil, ou pour la session actuelle de l'appareil. Ces clés ne quittent pas le TPM, comme les autres clés créées par ssh-tpm-keygen, et peuvent toujours être recréées.

Ces clés peuvent être préchargées dans ssh-tpm-agent.

$ ssh-tpm-agent --hierarchy owner &
$ export SSH_AUTH_SOCK="$(ssh-tpm-agent --print-socket)"
$ ssh-add -l
2048 SHA256:yt7A20tcRnzgaD2ATgAXSNWy9sP6wznysp3SkoK3Gj8 Clé de hiérarchie Owner (RSA)
256 SHA256:PmEsMeh/DwFP04iUaWLNeX4maMR6r1vfqw1BbbdFjIg Clé de hiérarchie Owner (ECDSA)

Pour une utilisation avec sshd, la partie publique de ces clés peut être créée en combinant -A avec --hierarchy.

$ ssh-tpm-keygen -A --hierarchy owner
2025/03/10 21:57:08 INFO Génération d'une nouvelle clé d'hôte hiérarchique algorithm=RSA hierarchy=owner
2025/03/10 21:57:10 INFO Nom de fichier de la clé publique écrit=/etc/ssh/ssh_tpm_host_rsa_key.pub
2025/03/10 21:57:10 INFO Génération d'une nouvelle clé d'hôte hiérarchique algorithm=ECDSA hierarchy=owner
2025/03/10 21:57:10 INFO Nom de fichier de la clé publique écrit=/etc/ssh/ssh_tpm_host_ecdsa_key.pub

Ces fichiers peuvent être utilisés avec HostKey comme normalement dans ssh_config.

Les différentes hiérarchies de clés ont des propriétés et des durées de vie différentes.

La hiérarchie endorsement stocke les clés créées pour la durée de vie de l'appareil. Cette hiérarchie ne devrait pas changer pendant la durée de vie de l'appareil.

La hiérarchie owner stocke les clés créées pour le propriétaire de l'appareil. Ces clés seront pivotées lorsque tpm2_clear(1) sera exécuté sur la plateforme, ce qui devrait être fait lorsqu'un nouvel propriétaire prend le contrôle de l'appareil.

La hiérarchie null stocke les clés créées pour la session actuelle. La session devrait être un cycle d'alimentation de l'appareil.

ssh-tpm-agent(1) — Agent pour les clés SSH dans un TPM

NOM

ssh-tpm-agent — Agent pour les clés SSH dans un TPM

SYNOPSIS

ssh-tpm-agent [-D] [-F fichier-cfg] [-h] [-L] [-l] [-s] [-t] [-u] [-V]

DESCRIPTION

ssh-tpm-agent est un agent SSH qui stocke vos clés privées dans votre module de plateforme de confiance (TPM).

Il utilise la spécification TPM 2.0 (Trusted Platform Module).

Cette fonctionnalité est expérimentale.

ssh-tpm-agent maintient les objets TPM chargés pendant son exécution. Certains périphériques TPM manquent de mémoire si vous tentez d'utiliser les clés de hiérarchie avec les clés habituelles créées par ssh-tpm-keygen.

OPTIONS

Les options sont les mêmes que pour ssh-agent(1).

EXEMPLES

Lancer l'agent :

ssh-tpm-agent

Lancer l'agent en avant-plan :

ssh-tpm-agent -D

Utiliser le fichier de configuration :

ssh-tpm-agent -F /etc/ssh/tpm_agent.conf

Activer la journalisation des actions du TPM :

ssh-tpm-agent -l

Désactiver le remplacement des clés par défaut :

ssh-tpm-agent -s

Démarrer un agent pour la clé hôte :

ssh-tpm-agent -t

ENVIRONNEMENT

SSH_TPM_AUTH_SOCK

Identifie le chemin d'un socket de domaine Unix pour la communication avec l'agent.

Par défaut, /var/tmp/ssh-tpm-agent.sock.

SSH_ASKPASS

Si ssh-tpm-agent, et d'autres binaires, ont besoin de lire un mot de passe, ils essaieront par défaut d'utiliser le terminal si possible. S'il n'y a pas de terminal disponible, ils utiliseront le binaire pointé par SSH_ASKPASS.

Voir ssh(1) sous ENVIRONNEMENT pour plus d'informations.

SSH_ASKPASS_REQUIRE

Permet de contrôler l'utilisation du programme askpass. Les valeurs valides sont :
•never garantit que ssh n'essaiera jamais d'utiliser le programme askpass.
•prefer préférera utiliser le programme askpass.
•force garantira que toutes les saisies de phrase secrète utiliseront le programme askpass.

Voir ssh(1) sous ENVIRONNEMENT pour plus d'informations.

SSH_TPM_AGENT_SWTPM

Spécifie si ssh-tpm-agent doit utiliser le backend swtpm ou non. Accepte toute valeur non vide comme vraie.

SSH_TPM_LANDLOCK

Si défini, ssh-tpm-agent, et les autres binaires, appliqueront le sandbox landlock le cas échéant.

Désactivé par défaut.

Voir landlock(7) pour plus d'informations.

FICHIERS

~/ssh/id_rsa.tpm, ~/ssh/id_ecdsa.tpm

Contient les clés privées ssh utilisées par ssh-tpm-agent. Ce sont des fichiers de clés TSS TPM 2.0 et ils sont sécurisés par le TPM. Ils peuvent être partagés publiquement car ils ne peuvent être utilisés que par le TPM sur lequel ils ont été créés. Cependant, il est probablement préférable de ne pas le faire.

~/ssh/id_rsa.pub, ~/ssh/id_ecdsa.pub

Contient les clés publiques ssh. Celles-ci peuvent être partagées publiquement et sont dans le même format que celles créées par ssh-keygen(1).

/run/user/$UID/ssh-tpm-agent.sock

Le chemin par défaut du socket UNIX de l'utilisateur ssh-tpm-agent. Utilisé par les utilisateurs individuels.

/var/tmp/ssh-tpm-agent.sock

Le chemin par défaut du socket UNIX système ssh-tpm-agent. Utilisé pour les clés hôtes et le système.
