NOM

sss_ssh_authorizedkeys - obtenir les clés autorisées OpenSSH

SYNTAXE

sss_ssh_authorizedkeys [options] UTILISATEUR

DESCRIPTION

sss_ssh_authorizedkeys acquiert les clés publiques SSH pour l'utilisateur UTILISATEUR et les affiche au format authorized_keys d'OpenSSH (voir la section “FORMAT DU FICHIER AUTHORIZED_KEYS” de sshd(8) pour plus d'informations).

sshd(8) peut être configuré pour utiliser sss_ssh_authorizedkeys pour l'authentification utilisateur par clé publique s'il est compilé avec le support de l'option “AuthorizedKeysCommand”. Veuillez vous référer à la page de manuel de sshd_config(5) pour plus de détails sur cette option.

Si “AuthorizedKeysCommand” est supporté, sshd(8) peut être configuré pour l'utiliser en ajoutant les directives suivantes dans sshd_config(5) :

  AuthorizedKeysCommand /usr/bin/sss_ssh_authorizedkeys
  AuthorizedKeysCommandUser nobody

CLÉS PROVENANT DE CERTIFICATS

En plus des clés publiques SSH pour l'utilisateur UTILISATEUR, sss_ssh_authorizedkeys peut également retourner les clés publiques SSH dérivées de la clé publique d'un certificat X.509.

Pour activer cela, l'option “ssh_use_certificate_keys” doit être définie à true (par défaut) dans la section [ssh] de sssd.conf. Si l'entrée utilisateur contient des certificats (voir “ldap_user_certificate” dans sssd-ldap(5) pour plus de détails) ou s'il y a un certificat dans une entrée de substitution pour l'utilisateur (voir sss_override(8) ou sssd-ipa(5) pour plus de détails) et que le certificat est valide, SSSD extraira la clé publique du certificat et la convertira dans le format attendu par sshd.

En plus de “ssh_use_certificate_keys”, les options

•ca_db
•p11_child_timeout
•certificate_verification

peuvent être utilisées pour contrôler comment les certificats sont validés (voir sssd.conf(5) pour plus de détails).

La validation est l'avantage d'utiliser des certificats X.509 au lieu des clés SSH directement, car elle offre un meilleur contrôle de la durée de vie des clés. Lorsque le client ssh est configuré pour utiliser les clés privées d'une carte à puce avec l'aide d'une bibliothèque partagée PKCS#11 (voir ssh(1) pour plus de détails), il peut être agaçant que l'authentification fonctionne toujours même si le certificat X.509 associé sur la carte à puce est déjà expiré, car ni ssh ni sshd ne regardent le certificat.

Il est à noter que la clé publique SSH dérivée peut toujours être ajoutée au fichier authorized_keys de l'utilisateur pour contourner la validation du certificat si la configuration sshd le permet.

OPTIONS

-d,--domain DOMAINE

Rechercher les clés publiques de l'utilisateur dans le domaine SSSD DOMAINE.

-?,--help

Afficher le message d'aide et quitter.

STATUT DE SORTIE

En cas de succès, une valeur de sortie de 0 est retournée. Sinon, 1 est retournée.
