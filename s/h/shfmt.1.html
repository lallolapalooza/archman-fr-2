shfmt(1) Manuel des commandes générales shfmt(1)

NOM

shfmt - Formater des programmes shell

SYNTAXE

shfmt [options] [chemin...]

DESCRIPTION

shfmt formate des programmes shell. Si le seul argument est un tiret (-) ou si aucun argument n'est donné, l'entrée standard sera utilisée. Si un chemin donné est un répertoire, tous les scripts shell trouvés sous ce répertoire seront utilisés.

Si des fichiers EditorConfig sont trouvés, ils seront utilisés pour appliquer les options de formatage. Si des options de parseur ou d'imprimeur sont fournies à l'outil, aucune option de formatage EditorConfig ne sera utilisée. Une valeur par défaut comme -i=0 peut être utilisée à cet effet.

Le formatage shell par défaut de shfmt a été choisi pour être cohérent, courant et prévisible. Certains aspects du format peuvent être configurés via des options d'imprimeur.

OPTIONS

Options générales

--version

Afficher la version et quitter.

-l[=0], --list[=0]

Lister les fichiers dont le formatage diffère de celui de shfmt ; les chemins sont séparés par un saut de ligne ou un caractère nul si -l=0

-w, --write

Écrire le résultat dans le fichier au lieu de la sortie standard.

-d, --diff

Générer une erreur avec un diff lorsque le formatage diffère.

Le diff utilise la couleur lorsque la sortie est un terminal. Pour ne jamais utiliser de couleur, définissez une variable NO_COLOR non vide ou TERM=dumb. Pour toujours utiliser la couleur, définissez une variable FORCE_COLOR non vide.

--apply-ignore

Toujours appliquer les règles d'ignorance d'EditorConfig.

Lors du formatage direct des fichiers, les règles d'ignorance sont sautées sans cette option. Devrait être utile pour tout outil ou éditeur qui formate l'entrée standard ou un seul fichier. Lors de l'impression des résultats sur la sortie standard, un fichier ignoré ne produit aucune sortie.

--filename str

Fournir un nom pour le fichier d'entrée standard.

L'utilisation de cette option est nécessaire pour que le support d'EditorConfig fonctionne avec l'entrée standard, car les fichiers EditorConfig sont trouvés par rapport à l'emplacement d'un script.

Options du parseur

-ln, --language-dialect <str>

Dialecte de langage (bash/posix/mksh/bats, par défaut auto).

Lorsqu'il est défini sur auto, le langage est détecté à partir du nom du fichier d'entrée, tant qu'il a une extension shell comme foo.mksh. Sinon, si l'entrée commence par un shebang shell comme #!/bin/sh, c'est ce dernier qui est utilisé. Si aucun des deux ne donne un résultat, bash est utilisé comme solution de repli.

L'extension de nom de fichier .sh est un cas spécial : elle implique posix, mais peut être remplacée par un shebang shell valide.

-p, --posix

Raccourci pour -ln=posix.

-s, --simplify

Simplifier le code.

Options de l'imprimeur

-i, --indent <uint>

Indentation : 0 pour les tabulations (par défaut), >0 pour le nombre d'espaces.

-bn, --binary-next-line

Les opérateurs binaires comme && et | peuvent commencer une ligne.

-ci, --case-indent

Les blocs case seront indentés.

-sr, --space-redirects

Les opérateurs de redirection seront suivis d'un espace.

-kp, --keep-padding

Conserver les remplissages d'alignement de colonnes.

Cette option est OBSOLÈTE et sera supprimée dans la prochaine version majeure. Pour plus d'informations, voir : https://github.com/mvdan/sh/issues/658

-fn, --func-next-line

Les accolades d'ouverture de fonction sont placées sur une ligne séparée.

-mn, --minify

Minifier le code pour réduire sa taille (implique -s).

Options utilitaires

-f[=0], --find[=0]

Trouver récursivement tous les fichiers shell et imprimer les chemins ; les chemins sont séparés par un saut de ligne ou un caractère nul si -f=0.

--to-json

Imprimer l'arbre syntaxique sur la sortie standard au format JSON typé.

--from-json

Lire l'arbre syntaxique depuis l'entrée standard au format JSON typé.

EXEMPLES

Formater tous les scripts sous le répertoire courant, en indiquant ceux qui sont modifiés :

shfmt -l -w .

Pour la CI, on peut utiliser une variante où les modifications de formatage sont simplement affichées sous forme de diffs :

shfmt -d .

Les options de formatage suivantes ressemblent étroitement au style shell de Google défini dans https://google.github.io/styleguide/shellguide.html :

shfmt -i 2 -ci -bn

Voici un exemple de fichier EditorConfig tel que défini par https://editorconfig.org/, montrant comment définir n'importe quelle option :

[*.sh]
# comme -i=4
indent_style = space
indent_size = 4
# --language-variant
shell_variant      = posix
binary_next_line   = true
# --case-indent
switch_case_indent = true
space_redirects    = true
keep_padding       = true
# --func-next-line
function_next_line = true
# Ignorer tout le répertoire "third_party" lors de l'appel de shfmt sur des répertoires,
# comme "shfmt -l -w .". Lors du formatage direct des fichiers,
# comme "shfmt -w third_party/foo.sh" ou "shfmt --filename=third_party/foo.sh",
# la logique d'ignorance n'est appliquée que lorsque l'option --apply-ignore est donnée.
[third_party/**]
ignore = true

Les sections EditorConfig peuvent également utiliser `[[shell]]` ou `[[bash]]` pour correspondre à n'importe quel script shell ou bash, ce qui est particulièrement utile lorsque les scripts utilisent un shebang mais pas d'extension. Notez que cette fonctionnalité est en dehors des spécifications EditorConfig et peut être modifiée à l'avenir.

shfmt peut également remplacer bash -n pour vérifier la syntaxe des scripts shell. Il est plus exhaustif, car il analyse toute la syntaxe statiquement et nécessite un UTF-8 valide :

$ echo '${foo:1 2}' | bash -n
$ echo '${foo:1 2}' | shfmt >/dev/null
1:9: not a valid arithmetic operator: 2
$ echo 'foo=(1 2)' | bash --posix -n
$ echo 'foo=(1 2)' | shfmt -p >/dev/null
1:5: arrays are a bash feature
