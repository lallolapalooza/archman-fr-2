DESCRIPTION

Les fonctions SHA2 implémentent la norme NIST Secure Hash Standard, FIPS PUB 180-2. Les fonctions SHA2 sont utilisées pour générer une représentation condensée d'un message appelée somme de contrôle de message, adaptée pour être utilisée comme signature numérique. Il existe trois familles de fonctions, dont les noms correspondent au nombre de bits dans la somme de contrôle de message résultante. Les fonctions SHA-256 sont limitées au traitement d'un message de moins de 2^64 bits en entrée. Les fonctions SHA-384 et SHA-512 peuvent traiter un message d'au plus 2^128 - 1 bits en entrée.

Les fonctions SHA2 sont considérées comme plus sécurisées que les fonctions sha1(3) dont elles partagent une interface similaire. Les versions 256, 384 et 512 bits de SHA2 partagent la même interface. Par souci de brièveté, seules les variantes 256 bits sont décrites ci-dessous.

La fonction SHA256Init() initialise un contexte SHA2_CTX context pour une utilisation avec SHA256Update() et SHA256Final(). La fonction SHA256Update() ajoute les données de longueur len au SHA2_CTX spécifié par context. SHA256Final() est appelée lorsque toutes les données ont été ajoutées via SHA256Update() et stocke une somme de contrôle de message dans le paramètre digest.

La fonction SHA256Pad() peut être utilisée pour appliquer le remplissage à la somme de contrôle de message

comme SHA256Final(), mais le contexte actuel peut toujours être utilisé avec SHA256Update().

La fonction SHA256Transform() est utilisée par SHA256Update() pour hacher des blocs de 512 bits et constitue le cœur de l'algorithme. La plupart des programmes devraient utiliser l'interface fournie par SHA256Init(), SHA256Update(), et SHA256Final() au lieu d'appeler SHA256Transform() directement.

La fonction SHA256End() est une interface pour SHA256Final() qui convertit le résumé en une représentation ASCII du résumé en hexadécimal.

La fonction SHA256File() calcule le résumé pour un fichier et renvoie le résultat via SHA256End(). Si SHA256File() ne peut pas ouvrir le fichier, un pointeur NULL est renvoyé.

SHA256FileChunk() se comporte comme SHA256File() mais calcule le résumé uniquement pour cette partie du fichier commençant à l'offset et continuant sur length octets ou jusqu'à la fin du fichier, selon ce qui arrive en premier. Une longueur de length zéro peut être spécifiée pour lire jusqu'à la fin du fichier. Un length ou un offset négatif sera ignoré.

La fonction SHA256Data() calcule le résumé d'une chaîne de caractères arbitraire et renvoie le résultat via SHA256End().

Pour chacune des fonctions SHA256End(), SHA256File(), SHA256FileChunk(), et SHA256Data(), le paramètre buf devrait être soit une chaîne suffisamment grande pour contenir le résumé résultant (par exemple, SHA256_DIGEST_STRING_LENGTH, SHA384_DIGEST_STRING_LENGTH, ou SHA512_DIGEST_STRING_LENGTH, selon la fonction utilisée), soit un pointeur NULL. Dans ce dernier cas, l'espace sera alloué dynamiquement via malloc(3) et devra être libéré en utilisant free(3) lorsqu'il ne sera plus nécessaire.

EXEMPLES

Le fragment de code suivant calculera le résumé SHA-256 de la chaîne de caractères "abc", qui est “0xba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad”.

SHA2_CTX ctx;
uint8_t results[SHA256_DIGEST_LENGTH];
char *buf;
int n;

buf = "abc";
n = strlen(buf);
SHA256Init(&ctx);
SHA256Update(&ctx, (uint8_t *)buf, n);
SHA256Final(results, &ctx);

/* Afficher le résumé comme une seule longue valeur hexadécimale */
printf("0x");
for (n = 0; n < SHA256_DIGEST_LENGTH; n++)
	printf("%02x", results[n]);
putchar('\n');

Alternativement, les fonctions d'aide pourraient être utilisées de la manière suivante :

uint8_t output[SHA256_DIGEST_STRING_LENGTH];
char *buf = "abc";

printf("0x%s\n", SHA256Data(buf, strlen(buf), output));

HISTORIQUE

Les fonctions SHA2 sont apparues dans OpenBSD 3.4.

AUTEURS

Cette implémentation des fonctions SHA a été écrite par Aaron D. Gifford.

Les fonctions d'aide SHA256End(), SHA256File(), SHA256FileChunk(), et SHA256Data() sont dérivées du code écrit par Poul-Henning Kamp.

CAVEATS

Cette implémentation du Secure Hash Standard n'a pas été validée par le NIST et n'est donc pas officiellement conforme à la norme.

Si un résumé de message doit être copié dans un type multi-octets (c'est-à-dire un tableau d'entiers de 32 bits), il sera nécessaire d'effectuer une permutation d'octets sur les machines peu endian comme les i386, alpha et vax.
