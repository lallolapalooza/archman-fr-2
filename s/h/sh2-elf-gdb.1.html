NOM

gdb - Le débogueur GNU

SYNTAXE

gdb [OPTIONS] [prog|prog procID|prog core]

DESCRIPTION

Le but d'un débogueur comme GDB est de vous permettre de voir ce qui se passe "à l'intérieur" d'un autre programme pendant son exécution -- ou ce que faisait un autre programme au moment où il a planté.

GDB peut faire quatre types d'actions principaux (plus d'autres en support de celles-ci) pour vous aider à attraper les bugs en flagrant délit:

  • Démarrer votre programme, en spécifiant tout ce qui pourrait affecter son comportement.
  • Faire s'arrêter votre programme à des conditions spécifiées.
  • Examiner ce qui s'est passé, lorsque votre programme s'est arrêté.
  • Changer des choses dans votre programme, afin que vous puissiez expérimenter en corrigeant les effets d'un bug et continuer pour en apprendre sur un autre.

Vous pouvez utiliser GDB pour déboguer des programmes écrits en C, C++, Fortran et Modula-2.

GDB est invoqué avec la commande shell "gdb". Une fois démarré, il lit les commandes du terminal jusqu'à ce que vous lui disiez de quitter avec la commande GDB "quit" ou "exit". Vous pouvez obtenir de l'aide en ligne de GDB lui-même en utilisant la commande "help".

Vous pouvez exécuter "gdb" sans arguments ni options ; mais la façon la plus courante de démarrer GDB est avec un ou deux arguments, spécifiant un fichier exécutable comme argument:

gdb programme

Vous pouvez aussi démarrer avec un fichier exécutable et un fichier core spécifiés:

gdb programme core

Vous pouvez, alternativement, spécifier un ID de processus comme second argument ou utiliser l'option "-p", si vous voulez déboguer un processus en cours d'exécution:

gdb programme 1234
gdb -p 1234

attachera GDB au processus 1234. Avec l'option -p vous pouvez omettre le nom de fichier programme.

Voici quelques-unes des commandes GDB les plus fréquemment nécessaires:

break [fichier:][fonction|ligne]
Définit un point d'arrêt à fonction ou ligne (dans fichier).
run [liste_args]
Démarre votre programme (avec liste_args, si spécifié).
bt
Backtrace (trace arrière) : affiche la pile du programme.
print expr
Affiche la valeur d'une expression.
c
Continue l'exécution de votre programme (après un arrêt, par ex. à un point d'arrêt).
next
Exécute la ligne de programme suivante (après un arrêt) ; passe par dessus les appels de fonction dans la ligne.
edit [fichier:]fonction
Regarde la ligne du programme où il est actuellement arrêté.
list [fichier:]fonction
Affiche le texte du programme dans le voisinage de l'endroit où il est actuellement arrêté.
step
Exécute la ligne de programme suivante (après un arrêt) ; entre dans les appels de fonction de la ligne.
help [nom]
Affiche des informations sur la commande GDB nom, ou des informations générales sur l'utilisation de GDB.
quit
exit
Quitte GDB.

Pour des détails complets sur GDB, voir Using GDB: A Guide to the GNU Source-Level Debugger, par Richard M. Stallman et Roland H. Pesch. Le même texte est disponible en ligne sous le nom "gdb" dans le programme "info".

OPTIONS

Tous les arguments autres que les options spécifient un fichier exécutable et un fichier core (ou un ID de processus) ; c'est-à-dire que le premier argument rencontré sans drapeau d'option est équivalent à une option --se, et le second, s'il y en a un, est équivalent à une option -c s'il s'agit du nom d'un fichier. Beaucoup d'options ont des formes longues et abrégées ; les deux sont indiquées ici. Les formes longues sont également reconnues si vous les tronquez, tant qu'assez de l'option est présent pour être non ambigu.

Les formes abrégées sont indiquées ici avec - et les formes longues avec -- pour refléter comment elles sont indiquées dans --help. Cependant, GDB reconnaît toutes les conventions suivantes pour la plupart des options:

"--option=valeur"
"--option valeur"
"-option=valeur"
"-option valeur"
"--o=valeur"
"--o valeur"
"-o=valeur"
"-o valeur"

Toutes les options et arguments de ligne de commande que vous donnez sont traités dans l'ordre séquentiel. L'ordre fait une différence lorsque l'option -x est utilisée.

--help
-h
Liste toutes les options, avec de brèves explications.
--symbols=fichier
-s fichier
Lit la table des symboles depuis fichier.
--write
Active l'écriture dans les fichiers exécutables et core.
--exec=fichier
-e fichier
Utilise fichier comme fichier exécutable à exécuter lorsque approprié, et pour examiner les données pures en conjonction avec un dump core.
--se=fichier
Lit la table des symboles depuis fichier et l'utilise comme fichier exécutable.
--core=fichier
-c fichier
Utilise fichier comme dump core à examiner.
--command=fichier
-x fichier
Exécute les commandes GDB depuis fichier.
--eval-command=commande
-ex commande
Exécute la commande GDB donnée.
--init-eval-command=commande
-iex
Exécute la commande GDB avant de charger l'inférieur.
--directory=répertoire
-d répertoire
Ajoute répertoire au chemin de recherche des fichiers source.
--nh
N'exécute pas les commandes depuis ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, ou ~/.gdbearlyinit
--nx
-n
N'exécute pas les commandes depuis les fichiers d'initialisation .gdbinit ou .gdbearlyinit.
--quiet
--silent
-q
"Quiet" (silencieux). N'affiche pas les messages d'introduction et de copyright. Ces messages sont également supprimés en mode batch.
--batch
Exécute en mode batch. Quitte avec le statut 0 après avoir traité tous les fichiers de commande spécifiés avec -x (et .gdbinit, si non inhibé). Quitte avec un statut non nul si une erreur se produit lors de l'exécution des commandes GDB dans les fichiers de commande.

exemple pour télécharger et exécuter un programme sur un autre ordinateur ; afin de rendre cela plus utile, le message

Program exited normally.

(qui est normalement émis chaque fois qu'un programme exécuté sous le contrôle de GDB se termine) n'est pas émis en mode batch.

--batch-silent
Exécuter en mode batch, comme --batch, mais totalement silencieux. Toute sortie GDB est supprimée (stderr n'est pas affecté). Ceci est beaucoup plus silencieux que --silent et serait inutile pour une session interactive.

Ceci est particulièrement utile lors de l'utilisation de cibles qui affichent des messages Loading section, par exemple.

Notez que les cibles qui affichent leur sortie via GDB, par opposition à l'écriture directe sur "stdout", seront également rendues silencieuses.

--args prog [arglist]
Changer l'interprétation de la ligne de commande de sorte que les arguments suivant cette option soient passés comme arguments à l'inférieur. Par exemple, prenez la commande suivante : 
gdb ./a.out -q

Cela lancerait GDB avec -q, sans afficher le message d'introduction. D'autre part, en utilisant :

gdb --args ./a.out -q

lance GDB avec le message d'introduction, et passe l'option à l'inférieur.

--pid=pid
Attacher GDB à un programme déjà en cours d'exécution, avec le PID pid.
--tui
Ouvrir l'interface utilisateur du terminal.
--readnow
Lire tous les symboles du fichier de symboles donné lors du premier accès.
--readnever
Ne pas lire les fichiers de symboles.
--return-child-result
Le code de sortie de GDB sera le même que le code de sortie de l'enfant.
--configuration
Afficher les détails de la configuration de GDB puis quitter.
--version
Afficher les informations de version puis quitter.
--cd=directory
Exécuter GDB en utilisant directory comme répertoire de travail, au lieu du répertoire courant.
--data-directory=directory
-D
Exécuter GDB en utilisant directory comme répertoire de données. Le répertoire de données est l'endroit où GDB recherche ses fichiers auxiliaires.
--fullname
-f
Emacs définit cette option lorsqu'il exécute GDB en tant que sous-processus. Elle indique à GDB de sortir le nom complet du fichier et le numéro de ligne d'une manière standard et reconnaissable chaque fois qu'un cadre de pile est affiché (ce qui inclut chaque arrêt du programme). Ce format reconnaissable ressemble à deux caractères \032, suivis du nom du fichier, du numéro de ligne et de la position du caractère séparés par des deux-points, et d'une nouvelle ligne. Le programme d'interface Emacs-vers-GDB utilise les deux caractères \032 comme signal pour afficher le code source du cadre.
-b baudrate
Définir la vitesse de ligne (débit en bauds ou bits par seconde) de toute interface série utilisée par GDB pour le débogage à distance.
-l timeout
Définir le délai d'attente, en secondes, pour le débogage à distance.
--tty=device
Exécuter en utilisant device pour l'entrée et la sortie standard de votre programme.

VOIR AUSSI

La documentation complète de GDB est maintenue sous forme de manuel Texinfo. Si les programmes "info" et "gdb" ainsi que la documentation Texinfo de GDB sont correctement installés sur votre site, la commande

info gdb

devrait vous donner accès au manuel complet.
