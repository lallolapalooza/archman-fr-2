DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE qui n'est pas dans l'ensemble actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie selon la version de la routine de réduction appelée. Lors de l'appel depuis C, reportez-vous à la section SYNTAXE pour les informations sur le type de données.

Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :

shmem_comp8_max_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 8 octets.

shmem_int4_max_to_all : Entier, avec une taille d'élément de 4 octets.

shmem_int8_max_to_all : Entier, avec une taille d'élément de 8 octets.

shmem_real4_max_to_all : Réel, avec une taille d'élément de 4 octets.

shmem_real16_max_to_all : Réel, avec une taille d'élément de 16 octets.

source
Un tableau symétrique de nreduce éléments qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PE de l'ensemble actif n'appelle la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE de l'ensemble actif. Les mêmes tableaux cible et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE de l'ensemble actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE de l'ensemble actif ne sont plus utilisés depuis un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PE de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les éléments suivants sont vrais pour le PE local : Le tableau cible est mis à jour. Les valeurs dans le tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, de sorte qu'un tableau pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur aucun PE de l'ensemble actif pendant que l'un des PE participe au traitement d'une routine de réduction SHMEM. Faites attention aux situations suivantes : Si le tableau pSync est initialisé à l'exécution, un type de synchronisation est nécessaire pour garantir que tous les PE de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PE de l'ensemble actif ne traite encore un appel de routine de réduction précédent qui utilisait les mêmes tableaux pSync ou pWrk.

En général, cela ne peut être assuré qu'en effectuant un type de synchronisation. Cependant, dans le cas particulier des routines de réduction appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors des appels successifs.

EXEMPLES

Exemple 1 : Cet exemple Fortran initialise statiquement le tableau pSync et trouve la valeur maximale de la variable réelle FOO sur tous les PE pairs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMAX, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMAX, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MAX_TO_ALL(FOOMAX, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMAX
ENDIF

Exemple 2 : Considérez l'appel C/C++ suivant :

shmem_int_max_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

L'appel précédent est plus efficace, mais sémantiquement équivalent, à la combinaison des appels suivants :

shmem_int_max_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_max_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_max_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Notez que deux jeux de tableaux pWrk et pSync sont utilisés alternativement car aucune synchronisation n'est effectuée entre les appels.
