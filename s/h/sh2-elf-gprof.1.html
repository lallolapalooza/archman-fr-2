NOM

gprof - afficher les données de profil de graphe d'appels

SYNTAXE

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nom] ]
[ -I répertoires ] [ -d[num] ] [ -k de/à ]
[ -m compte-min ] [ -R fichier-map ] [ -t longueur-tableau ]
[ --[non-]source-annotée[=nom] ]
[ --[non-]comptes-exécution[=nom] ]
[ --[non-]profil-plat[=nom] ] [ --[non-]graphe[=nom] ]
[ --[non-]temps=nom] [ --toutes-les-lignes ] [ --bref ]
[ --debug[=niveau] ] [ --ordonnancement-fonctions ]
[ --ordre-fichiers fichier-map ] [ --chemin-répertoires=répertoires ]
[ --affichage-fonctions-non-utilisées ] [ --format-fichier=nom ]
[ --infos-fichier ] [ --aide ] [ --ligne ] [ --noms-fichiers-inline ]
[ --compte-min=n ] [ --pas-statique ] [ --chemin-affichage ]
[ --fichiers-séparés ] [ --graphe-statique ] [ --somme ]
[ --longueur-tableau=longueur ] [ --traditionnel ] [ --version ]
[ --largeur=n ] [ --ignorer-non-fonctions ]
[ --démontage[=STYLE] ] [ --pas-démontage ]
[--table-symboles-externes=nom]
[ fichier-image ] [ fichiers-profil ... ]

DESCRIPTION

"gprof" produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré dans le profil de chaque appelant. Les données de profil proviennent du fichier de profil de graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc" et "f77". L'option -pg lie également les versions des routines de bibliothèque qui sont compilées pour le profilage. "Gprof" lit le fichier objet donné (par défaut "a.out") et établit la relation entre sa table de symboles et le profil de graphe d'appels de gmon.out. Si plusieurs fichiers de profil sont spécifiés, la sortie de "gprof" affiche la somme des informations de profil contenues dans les fichiers de profil donnés.

"Gprof" calcule le temps passé dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels dans un cycle sont faits pour partager le temps du cycle.

Plusieurs formes de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment le plus de cycles, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a également une estimation du temps passé dans les sous-routines de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer les appels de fonction qui consomment beaucoup de temps.

La liste de source annotée est une copie du code source du programme, étiquetée avec le nombre de fois que chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient quel format de sortie parmi plusieurs "gprof" doit produire.

Beaucoup de ces options acceptent un symspec facultatif pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec différents symspecs, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options annule le comportement par défaut (-p -q), qui imprime un profil plat et une analyse de graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--source-annotée[=symspec]"
L'option -A fait que "gprof" imprime le code source annoté. Si symspec est spécifié, imprime la sortie uniquement pour les symboles correspondants.
"-b"
"--bref"
Si l'option -b est donnée, "gprof" n'imprime pas les descriptions verbeuses qui essaient d'expliquer la signification de tous les champs dans les tableaux. Ceci est utile si vous avez l'intention d'imprimer la sortie, ou si vous en avez marre de voir les descriptions.
"-B"
L'option -B fait que "gprof" imprime l'analyse du graphe d'appels.
"-C[symspec]"
"--comptes-exécution[=symspec]"
L'option -C fait que "gprof" imprime un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, imprime le décompte uniquement pour les symboles correspondants.

Si le fichier de données de profil contient des enregistrements de comptage de blocs de base, la spécification de l'option -l, ainsi que -C, fera que les comptages d'exécution de blocs de base seront comptabilisés et affichés.

"-i"
"--infos-fichier"
L'option -i fait que "gprof" affiche des informations récapitulatives sur le ou les fichiers de données de profil puis quitte. Le nombre d'enregistrements d'histogramme, de graphe d'appels et de comptage de blocs de base est affiché.
"-I répertoires"
"--chemin-répertoires=répertoires"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers source. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Principalement utilisé pour la sortie de source annotée.
"-J[symspec]"
"--non-source-annotée[=symspec]"
L'option -J fait que "gprof" n'imprime pas le code source annoté. Si symspec est spécifié, "gprof" imprime le code source annoté, mais exclut les symboles correspondants.
"-L"
"--chemin-affichage"
Normalement, les noms de fichiers source sont imprimés avec le composant de chemin supprimé. L'option -L fait que "gprof" imprime le chemin complet des noms de fichiers source, qui est déterminé à partir des informations de débogage symboliques dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--profil-plat[=symspec]"
L'option -p fait que "gprof" imprime un profil plat. Si symspec est spécifié, imprime le profil plat uniquement pour les symboles correspondants.
"-P[symspec]"
"--non-profil-plat[=symspec]"
L'option -P fait que "gprof" supprime l'impression d'un profil plat. Si symspec est spécifié, "gprof" imprime un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graphe[=symspec]"
L'option -q fait que "gprof" imprime l'analyse du graphe d'appels. Si symspec est spécifié, imprime le graphe d'appels uniquement pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--non-graphe[=symspec]"
L'option -Q fait que "gprof" supprime l'impression du graphe d'appels. Si symspec est spécifié, "gprof" imprime un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--longueur-tableau=num"
L'option -t fait que les num lignes source les plus actives dans chaque fichier source soient listées lorsque l'annotation source est activée. La valeur par défaut est 10.
"-y"
"--fichiers-séparés"
Cette option affecte uniquement la sortie de source annotée. Normalement, "gprof" imprime les fichiers source annotés sur la sortie standard. Si cette option est spécifiée, la source annotée pour un fichier nommé chemin/nom_fichier est générée dans le fichier nom_fichier-ann. Si le système de fichiers sous-jacent tronquait nom_fichier-ann de sorte qu'il écrase le nom_fichier original, "gprof" génère la source annotée dans le fichier nom_fichier.ann à la place (si le nom de fichier original a une extension, cette extension est remplacée par .ann).
"-Z[symspec]"
"--non-comptes-exécution[=symspec]"

ss="Li">"gprof" à ne pas imprimer un décompte des fonctions et le nombre de fois que chacune a été appelée. Si symspec est spécifié, imprimer le décompte, mais exclure les symboles correspondants.
"-r"
"--function-ordering"
L'option --function-ordering demande à "gprof" d'imprimer un ordre suggéré pour les fonctions du programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui prennent en charge l'ordre arbitraire des fonctions dans un exécutable.

Les détails exacts sur la façon de forcer l'éditeur de liens à placer les fonctions dans un ordre particulier dépendent du système et sortent du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering demande à "gprof" d'imprimer un ordre de ligne de lien .o suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui ne prennent pas en charge l'ordre arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un nom de chemin vers un fichier qui fournit des correspondances entre les noms de fonctions et les fichiers objet. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec GNU "nm", tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T demande à "gprof" d'imprimer sa sortie dans le style « traditionnel » BSD.
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, cela n'est utilisé que lors de l'impression de l'index des fonctions en bas du graphe d'appel.
"-x"
"--all-lines"
Cette option affecte uniquement la sortie source annotée. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à celui de "tcov" avec -a.
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démaniglés lors de l'impression de la sortie. Par défaut, les symboles sont démaniglés. L'option "--no-demangle" peut être utilisée pour désactiver le démaniglage. Différents compilateurs ont des styles de maniglage différents. L'argument optionnel de style de démaniglage peut être utilisé pour choisir un style de démaniglage approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a demande à "gprof" de supprimer l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globaux et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels vers/depuis celles-ci, etc., seront tous attribués à la fonction qui a été chargée juste avant elles dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c demande à enrichir le graphe d'appels du programme par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonctions dans le code machine binaire. Comme les enregistrements normaux du graphe d'appels ne sont générés que lorsque les fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels à des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais seulement si des entrées de table de symboles sont présentes pour elles. Les appels aux routines de bibliothèques dynamiques ne sont généralement *pas* trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des décomptes d'appels de 0.
"-D"
"--ignore-non-functions"
L'option -D demande à "gprof" d'ignorer les symboles qui ne sont pas connus comme étant des fonctions. Cette option donnera des données de profilage plus précises sur les systèmes où elle est prise en charge (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appels tous les arcs allant des symboles correspondant à from à ceux correspondant à to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui demande à ce que les succès de l'histogramme soient attribués à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par d'anciennes versions du compilateur "gcc". Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera également le nombre de fois où chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où un programme passe son temps dans une fonction volumineuse, il augmente également considérablement le temps d'exécution de "gprof" et amplifie les inexactitudes statistiques.

"--inline-file-names"
Cette option demande à "gprof" d'imprimer le fichier source après chaque symbole, à la fois dans le profil plat et dans le graphe d'appels. Le chemin complet du fichier est imprimé si utilisé avec l'option -L.
"-m num"
"--min-count=num"
Cette option affecte uniquement la sortie du décompte d'exécution. Les symboles exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n demande à "gprof", dans son analyse du graphe d'appels, de ne propager les temps que pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n demande à "gprof", dans son analyse du graphe d'appels, de ne pas propager les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S demande à "gprof" de lire un fichier de table de symboles externe, tel que /proc/kallsyms, plutôt que de lire la table de symboles du fichier objet donné (par défaut, c'est "a.out"). Ceci est utile pour le profilage de modules noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z, "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et dans lesquelles aucun temps n'a été passé. Ceci est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, active tout le débogage.
"-h"
"--help"
L'option -h imprime l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profilage. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic, et prof (pas encore pris en charge).
"-s"
"--sum"
L'option -s demande à "gprof" de résumer les informations des fichiers de données de profilage qu'il a lus, et d'écrire un fichier de données de profilage appelé gmon.sum, qui contient toutes les informations des fichiers de données de profilage que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter "gprof" à nouveau sans -s pour analyser les données cumulatives du fichier gmon.sum.

"-v"
"--version"
L'option -v demande à "gprof" d'imprimer le numéro de version actuel, puis de quitter.

Options obsolètes

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer les informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme un enfant des fonctions qui l'appellent, mais son numéro d'index sera affiché comme [not printed]. Plus d'une option -e peut être donnée ; un seul function_name peut être indiqué avec chaque option -e.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e", mais le temps passé dans la fonction (et ses enfants qui n'ont été appelés par personne d'autre) ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appels. Plus d'une option -E peut être donnée ; un seul function_name peut être indiqué avec chaque option -E.
"-f function_name"
L'option -f function demande à pour limiter le graphe d'appels à la fonction nom_fonction et à ses enfants (et leurs enfants...). Plusieurs options -f peuvent être fournies ; un seul nom_fonction peut être indiqué avec chaque option -f.
"-F nom_fonction"
L'option -F fonction fonctionne comme l'option "-f", mais seul le temps passé dans la fonction et ses enfants (et leurs enfants...) sera utilisé pour déterminer le temps total et les pourcentages de temps pour le graphe d'appels. Plus d'une option -F peut être fournie ; un seul nom_fonction peut être indiqué avec chaque option -F. L'option -F remplace l'option -E.

FICHIERS

"a.out"
la liste de noms et l'espace de texte.
"gmon.out"
graphe d'appels dynamique et profil.
"gmon.sum"
graphe d'appels dynamique et profil résumés.

BOGUES

La granularité de l'échantillonnage est affichée, mais reste au mieux statistique. Nous supposons que le temps pour chaque exécution d'une fonction peut être exprimé par le temps total de la fonction divisé par le nombre de fois où la fonction est appelée. Ainsi, le temps propagé le long des arcs du graphe d'appels vers les parents de la fonction est directement proportionnel au nombre de fois où cet arc est traversé.

Les parents qui ne sont pas eux-mêmes profilés auront le temps de leurs enfants profilés propagé vers eux, mais ils apparaîtront comme étant invoqués spontanément dans la liste du graphe d'appels, et leur temps ne sera pas propagé davantage. De même, les attrapeurs de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Tout enfant profils d'attrapeurs de signaux devrait avoir son temps propagé correctement, à moins que l'attrapeur de signaux n'ait été invoqué pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou retourner normalement pour que les informations de profilage soient enregistrées dans le fichier gmon.out.
