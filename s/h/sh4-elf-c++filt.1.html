sh4-elf-c++filt(1)

Paquet: sh4-elf-binutils

Licences: GPL

C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - décode les symboles C++ et Java

SYNTAXE

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java permettent la surcharge de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction accepte des paramètres de types différents. Afin de pouvoir distinguer ces fonctions aux noms similaires, C++ et Java les encodent en un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de mangling (brouillage). Le programme c++filt fait l'opération inverse : il décode (démangle) les noms de bas niveau en noms de niveau utilisateur afin qu'ils soient lisibles.

Chaque mot alphanumérique (composé de lettres, chiffres, underscores, dollars ou points) rencontré dans l'entrée est un nom potentiellement brouillé. Si le nom est décodé en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot d'origine est affiché. De cette manière, vous pouvez passer un fichier source d'assembleur entier, contenant des noms brouillés, à travers c++filt et voir le même fichier source contenant des noms décodés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles à partir de l'entrée standard. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés n'être que des noms brouillés et aucun contrôle n'est effectué pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et décodera le nom en "f()" alors que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom brouillé qui le rend invalide). Cependant, cette commande fonctionnera :

echo _Z1fv, | c++filt -n

et affichera "f(),", c'est-à-dire le nom décodé suivi d'une virgule finale. Ce comportement s'explique par le fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils puissent faire partie d'un fichier source d'assembleur où il pourrait y avoir des caractères supplémentaires, parasites, après un nom brouillé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ placent un underscore au début de chaque nom. Par exemple, le nom C "foo" devient le nom de bas niveau "_foo". Cette option supprime l'underscore initial. Le comportement par défaut de c++filt concernant la suppression de l'underscore dépend de la cible.
-n
--no-strip-underscore
Ne supprime pas l'underscore initial.
-p
--no-params
Lors du décodage du nom d'une fonction, n'affiche pas les types des paramètres de la fonction.
-t
--types
Tente de décoder les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types brouillés ne sont normalement utilisés qu'en interne par le compilateur, et ils peuvent être confondus avec des noms non brouillés. Par exemple, une fonction nommée "a" traitée comme un nom de type brouillé serait décodée en "signed char".
-i
--no-verbose
N'inclut pas les détails d'implémentation (le cas échéant) dans la sortie décodée.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du décodage des chaînes. Comme les formats de brouillage de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une erreur mémoire. La limite essaie d'empêcher cela en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour décoder des noms réellement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est synonyme de l'option --no-recurse-limit. L'option -R est synonyme de --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes de brouillage, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (méthode par défaut)
"gnu"
celle utilisée par le compilateur C++ GNU (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le C++ Annotated Reference Manual
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur Java GNU (gcj)
"gnat"
celle utilisée par le compilateur Ada GNU (GNAT).
--help
Affiche un résumé des options de c++filt et quitte.
--version
Affiche le numéro de version de c++filt et quitte.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en le faisant précéder d'une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; ces options seront traitées récursivement.

NOTES DE BAS DE PAGE

1.
MS-DOS n'autorise pas les caractères "+" dans les noms de fichiers, donc sous MS-DOS, ce programme s'appelle CXXFILT.
