LD(1) Outils de développement GNU LD(1)

NOM

ld - L'éditeur de liens GNU

SYNTAXE

ld [options] fichier-objet ...

DESCRIPTION

ld combine un certain nombre de fichiers objets et d'archives, relocalise leurs données et résout les références de symboles. C'est généralement la dernière étape de la compilation d'un programme d'exécuter ld.

ld accepte des fichiers de langage de commande d'éditeur de liens écrits dans un sur-ensemble de la syntaxe du langage de commande de l'éditeur de liens d'AT&T, afin de fournir un contrôle explicite et total sur le processus d'édition de liens.

Cette page de manuel ne décrit pas le langage de commande ; voir l'entrée ld dans "info" pour les détails complets sur le langage de commande et sur d'autres aspects de l'éditeur de liens GNU.

Cette version de ld utilise les bibliothèques BFD à usage général pour opérer sur les fichiers objets. Cela permet à ld de lire, combiner et écrire des fichiers objets dans de nombreux formats différents - par exemple, COFF ou "a.out". Différents formats peuvent être liés ensemble pour produire n'importe quel type de fichier objet disponible.

Outre sa flexibilité, l'éditeur de liens GNU est plus utile que d'autres éditeurs de liens pour fournir des informations diagnostiques. De nombreux éditeurs de liens abandonnent l'exécution immédiatement lors d'une erreur ; dans la mesure du possible, ld continue l'exécution, vous permettant d'identifier d'autres erreurs (ou, dans certains cas, d'obtenir un fichier de sortie malgré l'erreur).

L'éditeur de liens GNU ld est conçu pour couvrir un large éventail de situations et pour être aussi compatible que possible avec les autres éditeurs de liens. Par conséquent, vous avez de nombreux choix pour contrôler son comportement.

OPTIONS

L'éditeur de liens prend en charge une pléthore d'options en ligne de commande, mais en pratique peu d'entre elles sont utilisées dans un contexte particulier. Par exemple, une utilisation fréquente de ld est de lier des fichiers objets Unix standard sur un système Unix standard et supporté. Sur un tel système, pour lier un fichier "hello.o" :

ld -o <sortie> /lib/crt0.o hello.o -lc

Ceci indique à ld de produire un fichier nommé sortie comme résultat de la liaison du fichier "/lib/crt0.o" avec "hello.o" et la bibliothèque "libc.a", qui proviendra des répertoires de recherche standard. (Voir la discussion de l'option -l ci-dessous.)

Certaines des options en ligne de commande pour ld peuvent être spécifiées à n'importe quel moment de la ligne de commande. Cependant, les options qui se réfèrent à des fichiers, telles que -l ou -T, provoquent la lecture du fichier au point où l'option apparaît dans la ligne de commande, par rapport aux fichiers objets et aux autres options de fichier. Répéter des options non liées à des fichiers avec un argument différent n'aura soit aucun autre effet, soit remplacera les occurrences précédentes (celles plus à gauche dans la ligne de commande) de cette option. Les options qui peuvent être spécifiées plusieurs fois de manière significative sont notées dans les descriptions ci-dessous.

Les arguments qui ne sont pas des options sont des fichiers objets ou des archives qui doivent être liés ensemble. Ils peuvent suivre, précéder ou être mélangés avec les options de la ligne de commande, sauf qu'un argument de fichier objet ne peut pas être placé entre une option et son argument.

Habituellement, l'éditeur de liens est appelé avec au moins un fichier objet, mais vous pouvez spécifier d'autres formes de fichiers d'entrée binaires en utilisant -l, -R, et le langage de script de commande. Si aucun fichier d'entrée binaire n'est spécifié du tout, l'éditeur de liens ne produit aucune sortie et affiche le message No input files.

Si l'éditeur de liens ne peut pas reconnaître le format d'un fichier objet, il supposera qu'il s'agit d'un script d'éditeur de liens. Un script spécifié de cette manière complète le script principal d'éditeur de liens utilisé pour la liaison (soit le script par défaut, soit celui spécifié à l'aide de -T). Cette fonctionnalité permet à l'éditeur de liens de lier un fichier qui ressemble à un objet ou à une archive, mais qui définit simplement certaines valeurs de symboles, ou utilise "INPUT" ou "GROUP" pour charger d'autres objets. Spécifier un script de cette manière complète simplement le script principal d'éditeur de liens, avec les commandes supplémentaires placées après le script principal ; utilisez l'option -T pour remplacer complètement le script par défaut de l'éditeur de liens, mais notez l'effet de la commande "INSERT".

Pour les options dont les noms sont une seule lettre, les arguments d'option doivent soit suivre la lettre de l'option sans espace intercalé, soit être donnés comme arguments séparés immédiatement après l'option qui les exige.

Pour les options dont les noms sont constitués de plusieurs lettres, un seul tiret ou deux peuvent précéder le nom de l'option ; par exemple, -trace-symbol et --trace-symbol sont équivalents. Notez qu'il y a une exception à cette règle. Les options de plusieurs lettres qui commencent par une minuscule 'o' ne peuvent être précédées que de deux tirets. Ceci afin de réduire la confusion avec l'option -o. Ainsi, par exemple, -omagic définit le nom du fichier de sortie à magic, tandis que --omagic définit l'indicateur NMAGIC sur la sortie.

Les arguments des options de plusieurs lettres doivent soit être séparés du nom de l'option par un signe égal, soit être donnés comme arguments séparés immédiatement après l'option qui les exige. Par exemple, --trace-symbol foo et --trace-symbol=foo sont équivalents. Des abréviations uniques des noms d'options de plusieurs lettres sont acceptées.

Notez que si l'éditeur de liens est appelé indirectement, via un pilote de compilateur (par exemple, gcc), alors toutes les options de la ligne de commande de l'éditeur de liens doivent être préfixées par -Wl, (ou ce qui est approprié pour le pilote de compilateur particulier), comme ceci :

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Ceci est important, car sinon le programme pilote de compilateur peut ignorer silencieusement les options de l'éditeur de liens, ce qui résultera en une mauvaise liaison. La confusion peut également survenir lors de la transmission d'options nécessitant des valeurs via un pilote, car l'utilisation d'un espace entre l'option et l'argument agit comme un séparateur, et fait que le pilote ne transmet que l'option à l'éditeur de liens et l'argument au compilateur. Dans ce cas, il est plus simple d'utiliser les formes jointes des options à une seule lettre et à plusieurs lettres, comme :

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Voici un tableau des options génériques acceptées par l'éditeur de liens GNU :

@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces blancs. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière d'apostrophes simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en précédant le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées récursivement.

-a mot-clé
Cette option est supportée pour la compatibilité HP/UX. L'argument mot-clé doit être l'une des chaînes archive, shared, ou default. -aarchive est fonctionnellement équivalent à -Bstatic, et les deux autres mots-clés sont fonctionnellement équivalents à -Bdynamic. Cette option peut être utilisée plusieurs fois.
--audit BIBLIO_AUDIT
Ajoute BIBLIO_AUDIT à l'entrée "DT_AUDIT" de la section dynamique. BIBLIO_AUDIT n'est pas vérifié pour son existence, ni n'utilisera le DT_SONAME spécifié dans la bibliothèque. Si spécifié plusieurs fois, "DT_AUDIT" contiendra une liste séparée par des deux-points des interfaces d'audit à utiliser. Si l'éditeur de liens trouve un objet avec une entrée d'audit lors de la recherche de bibliothèques partagées, il ajoutera une entrée "DT_DEPAUDIT" correspondante dans le fichier de sortie. Cette option n'est significative que sur les plateformes ELF supportant l'interface rtld-audit.
-b format-entrée
--format=format-entrée
ld peut être configuré pour supporter plus d'un type de fichier objet. Si votre ld est configuré de cette manière, vous pouvez utiliser l'option -b pour spécifier le format binaire pour les fichiers objets d'entrée qui suivent cette option dans la ligne de commande. Même lorsque ld est configuré pour supporter des formats d'objets alternatifs, vous n'avez généralement pas besoin de le spécifier, car ld devrait être configuré pour attendre comme valeur par défau
Le format d'entrée par défaut est le format le plus courant sur chaque machine. input-format est une chaîne de caractères, le nom d'un format particulier supporté par les bibliothèques BFD. (Vous pouvez lister les formats binaires disponibles avec objdump -i.)

Vous pourriez vouloir utiliser cette option si vous liez des fichiers avec un format binaire inhabituel. Vous pouvez aussi utiliser -b pour changer explicitement de format (lorsque vous liez des fichiers objets de formats différents), en incluant -b input-format avant chaque groupe de fichiers objets d'un format particulier.

Le format par défaut est pris de la variable d'environnement "GNUTARGET".

Vous pouvez aussi définir le format d'entrée à partir d'un script, en utilisant la commande "TARGET" ;

-c MRI-commandfile
--mri-script=MRI-commandfile
Pour la compatibilité avec les linkers produits par MRI, ld accepte des fichiers scripts écrits dans un langage de commande alternatif et restreint, décrit dans la section Fichiers scripts compatibles MRI de la documentation GNU ld. Introduisez les fichiers scripts MRI avec l'option -c ; utilisez l'option -T pour exécuter des scripts de linker écrits dans le langage de script ld à usage général. Si MRI-cmdfile n'existe pas, ld le cherche dans les répertoires spécifiés par toutes options -L.
-d
-dc
-dp
Ces trois options sont équivalentes ; plusieurs formes sont supportées pour la compatibilité avec d'autres linkers. Elles allouent de l'espace aux symboles communs même si un fichier de sortie relocalisable est spécifié (avec -r). La commande script "FORCE_COMMON_ALLOCATION" a le même effet.
--depaudit AUDITLIB
-P AUDITLIB
Ajoute AUDITLIB à l'entrée "DT_DEPAUDIT" de la section dynamique. AUDITLIB n'est pas vérifié pour son existence, et n'utilisera pas le DT_SONAME spécifié dans la bibliothèque. Si spécifié plusieurs fois, "DT_DEPAUDIT" contiendra une liste d'interfaces d'audit séparées par des deux-points à utiliser. Cette option n'est significative que sur les plateformes ELF supportant l'interface rtld-audit. L'option -P est fournie pour la compatibilité Solaris.
--enable-linker-version
Active la directive de script de linker "LINKER_VERSION", décrite dans Données de la section de sortie. Si cette directive est utilisée dans un script de linker et que cette option a été activée, alors une chaîne contenant la version du linker sera insérée au point actuel.

Notez que l'emplacement de cette option sur la ligne de commande du linker est significatif. Elle n'affectera que les scripts de linker qui la suivent sur la ligne de commande, ou qui sont intégrés au linker.

--disable-linker-version
Désactive la directive de script de linker "LINKER_VERSION", de sorte qu'elle n'insère pas de chaîne de version. C'est le comportement par défaut.
--enable-non-contiguous-regions
Cette option évite de générer une erreur si une section d'entrée ne correspond pas à une section de sortie correspondante. Le linker essaie d'allouer la section d'entrée aux sections de sortie correspondantes suivantes, et ne génère une erreur que si aucune section de sortie n'est suffisamment grande. Ceci est utile lorsque plusieurs régions mémoire non contiguës sont disponibles et que la section d'entrée n'en requiert pas une en particulier. L'ordre dans lequel les sections d'entrée sont évaluées ne change pas, par exemple : 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

avec les sections d'entrée :
.data.1: taille 8
.data.2: taille 0x10
.data.3: taille 4

résulte en .data.1 affecté à mem1, et .data.2 et .data.3
affectés à mem2, même si .data.3 rentrerait dans mem3.

Cette option est incompatible avec les instructions INSERT car elle modifie la manière dont les sections d'entrée sont mappées aux sections de sortie.

--enable-non-contiguous-regions-warnings
Cette option active les avertissements lorsque "--enable-non-contiguous-regions" permet des correspondances potentiellement inattendues dans le mappage des sections, pouvant conduire à l'abandon silencieux d'une section au lieu d'un échec car elle ne rentre dans aucune région de sortie.
-e entry
--entry=entry
Utilise entry comme symbole explicite pour le début de l'exécution de votre programme, plutôt que le point d'entrée par défaut. S'il n'y a pas de symbole nommé entry, le linker essaiera d'analyser entry comme un nombre, et l'utilisera comme adresse d'entrée (le nombre sera interprété en base 10 ; vous pouvez utiliser un préfixe 0x pour la base 16, ou un préfixe 0 pour la base 8).
--exclude-libs lib,lib,...
Spécifie une liste de bibliothèques d'archives dont les symboles ne doivent pas être exportés automatiquement. Les noms de bibliothèques peuvent être délimités par des virgules ou des deux-points. Spécifier "--exclude-libs ALL" exclut les symboles de toutes les bibliothèques d'archives de l'exportation automatique. Cette option n'est disponible que pour le port cible i386 PE du linker et pour les ports cibles ELF. Pour i386 PE, les symboles explicitement listés dans un fichier .def sont toujours exportés, indépendamment de cette option. Pour les ports cibles ELF, les symboles affectés par cette option seront traités comme cachés.
--exclude-modules-for-implib module,module,...
Spécifie une liste de fichiers objets ou de membres d'archive, dont les symboles ne doivent pas être exportés automatiquement, mais qui doivent être copiés intégralement dans la bibliothèque d'importation générée pendant la liaison. Les noms de modules peuvent être délimités par des virgules ou des deux-points, et doivent correspondre exactement aux noms de fichiers utilisés par ld pour ouvrir les fichiers ; pour les membres d'archive, il s'agit simplement du nom du membre, mais pour les fichiers objets, le nom listé doit inclure et correspondre précisément à tout chemin utilisé pour spécifier le fichier d'entrée sur la ligne de commande du linker. Cette option n'est disponible que pour le port cible i386 PE du linker. Les symboles explicitement listés dans un fichier .def sont toujours exportés, indépendamment de cette option.
-E
--export-dynamic
--no-export-dynamic
Lors de la création d'un exécutable lié dynamiquement, l'utilisation de l'option -E ou de l'option --export-dynamic fait que le linker ajoute tous les symboles à la table des symboles dynamiques. La table des symboles dynamiques est l'ensemble des symboles qui sont visibles depuis les objets dynamiques au moment de l'exécution.

Si vous n'utilisez aucune de ces options (ou utilisez l'option --no-export-dynamic pour restaurer le comportement par défaut), la table des symboles dynamiques contiendra normalement uniquement les symboles qui sont référencés par un objet dynamique mentionné dans la liaison.

Si vous utilisez "dlopen" pour charger un objet dynamique qui doit faire référence aux symboles définis par le programme, plutôt qu'à un autre objet dynamique, vous devrez probablement utiliser cette option lors de la liaison du programme lui-même.

Vous pouvez également utiliser la liste dynamique pour contrôler quels symboles doivent être ajoutés à la table des symboles dynamiques si le format de sortie le supporte. Voir la description de --dynamic-list.

Notez que cette option est spécifique aux ports cibles ELF. Les cibles PE supportent une fonction similaire pour exporter tous les symboles d'une DLL ou d'un EXE ; voir la description de --export-all-symbols ci-dessous.

--export-dynamic-symbol=glob
Lors de la création d'un exécutable lié dynamiquement, les symboles correspondant à glob seront ajoutés à la table des symboles dynamiques. Lors de la création d'une bibliothèque partagée, les références aux symboles correspondant à glob ne seront pas liées aux définitions à l'intérieur de la bibliothèque partagée. Cette option est sans effet lors de la création d'une bibliothèque partagée et si -Bsymbolic ou --dynamic-list ne sont pas spécifiés. Cette option n'est significative que sur les plateformes ELF qui supportent les bibliothèques partagées.
--export-dynamic-symbol-list=file
Spécifie un --export-dynamic-symbol pour chaque motif dans le fichier. Le format du fichier est le même que le nœud de version sans portée ni nom de nœud. Voir VERSION pour plus d'informations.
-EB
Lie des objets big-endian. Ceci affecte le format de sortie par défaut.
-EL
Lie des objets little-endian. Ceci affecte le format de sortie par défaut.
-f name
--auxiliary=name
Lors de la création d'un objet partagé ELF, définit le champ interne DT_AUXILIARY au nom spécifié. Cela indique au linker dynamique que la table des symboles de l'objet partagé doit être utilisée comme un filtre auxiliaire sur la table des symboles de l'objet partagé name.

Si vous liez plus tard un programme à cet objet filtre, alors, lorsque vous exécuterez le programme, le linker dynamique verra le champ DT_AUXILIARY. Si le linker dynamique résout des symboles à partir de l'objet filtre, il vérifiera d'abord s'il existe une définition dans l'objet partagé name. S'il y en a une, elle sera utilisée à la place de la définition dans l'objet filtre. L'objet partagé name n'a pas besoin d'exister. Ainsi, l'objet partagé name peut être utilisé pour fournir une implémentation alternative de certaines fonctions, peut-être pour le débogage ou pour des performances spécifiques à la machine.

Cette option peut être spécifiée plusieurs fois. Les entrées DT_AUXILIARY seront créées dans l'ordre où elles apparaissent sur la ligne de commande.

-F name
--filter=nom
Lors de la création d'un objet partagé ELF, définissez le champ interne DT_FILTER sur le nom spécifié. Cela indique à l'éditeur de liens dynamique que la table des symboles de l'objet partagé qui est créé doit être utilisée comme filtre sur la table des symboles de l'objet partagé nom.

Si vous liez ultérieurement un programme à cet objet filtre, alors, lors de l'exécution du programme, l'éditeur de liens dynamique verra le champ DT_FILTER. L'éditeur de liens dynamique résoudra les symboles selon la table des symboles de l'objet filtre comme d'habitude, mais il se liera réellement aux définitions trouvées dans l'objet partagé nom. Ainsi, l'objet filtre peut être utilisé pour sélectionner un sous-ensemble des symboles fournis par l'objet nom.

Certains anciens éditeurs de liens utilisaient l'option -F tout au long d'une chaîne d'outils de compilation pour spécifier le format du fichier objet pour les fichiers objets d'entrée et de sortie. L'éditeur de liens GNU utilise d'autres mécanismes à cette fin : les options -b, --format, --oformat, la commande "TARGET" dans les scripts d'éditeur de liens et la variable d'environnement "GNUTARGET". L'éditeur de liens GNU ignorera l'option -F lorsqu'il ne créera pas d'objet partagé ELF.

-fini=nom
Lors de la création d'un exécutable ou d'un objet partagé ELF, appelez NOM lorsque l'exécutable ou l'objet partagé est déchargé, en définissant DT_FINI sur l'adresse de la fonction. Par défaut, l'éditeur de liens utilise "_fini" comme fonction à appeler.
-g
Ignoré. Fourni pour la compatibilité avec d'autres outils.
-G valeur
--gpsize=valeur
Définissez la taille maximale des objets à optimiser à l'aide du registre GP sur taille. Ceci n'est pertinent que pour les formats de fichiers objets tels que MIPS ELF qui prennent en charge la mise en place d'objets grands et petits dans différentes sections. Ceci est ignoré pour les autres formats de fichiers objets.
-h nom
-soname=nom
Lors de la création d'un objet partagé ELF, définissez le champ interne DT_SONAME sur le nom spécifié. Lorsqu'un exécutable est lié à un objet partagé qui a un champ DT_SONAME, alors lorsque l'exécutable est exécuté, l'éditeur de liens dynamique tentera de charger l'objet partagé spécifié par le champ DT_SONAME plutôt que d'utiliser le nom de fichier donné à l'éditeur de liens.
-i
Effectuez une liaison incrémentielle (identique à l'option -r).
-init=nom
Lors de la création d'un exécutable ou d'un objet partagé ELF, appelez NOM lorsque l'exécutable ou l'objet partagé est chargé, en définissant DT_INIT sur l'adresse de la fonction. Par défaut, l'éditeur de liens utilise "_init" comme fonction à appeler.
-l spécification-nom
--library=spécification-nom
Ajoutez l'archive ou le fichier objet spécifié par spécification-nom à la liste des fichiers à lier. Cette option peut être utilisée un nombre quelconque de fois. Si spécification-nom est de la forme :nomfichier, ld recherchera dans le chemin de la bibliothèque un fichier appelé nomfichier, sinon il recherchera dans le chemin de la bibliothèque un fichier appelé libspécification-nom.a.

Sur les systèmes qui prennent en charge les bibliothèques partagées, ld peut également rechercher des fichiers autres que libspécification-nom.a. Spécifiquement, sur les systèmes ELF et SunOS, ld recherchera dans un répertoire une bibliothèque appelée libspécification-nom.so avant d'en rechercher une appelée libspécification-nom.a. (Par convention, une extension ".so" indique une bibliothèque partagée.) Notez que ce comportement ne s'applique pas à :nomfichier, qui spécifie toujours un fichier appelé nomfichier.

L'éditeur de liens ne recherchera dans une archive qu'une seule fois, à l'emplacement où elle est spécifiée sur la ligne de commande. Si l'archive définit un symbole qui était indéfini dans un objet apparu avant l'archive sur la ligne de commande, l'éditeur de liens inclura les fichiers appropriés de l'archive. Cependant, un symbole indéfini dans un objet apparaissant plus tard sur la ligne de commande ne fera pas rechercher à l'éditeur de liens l'archive à nouveau.

Voir l'option -( pour une façon de forcer l'éditeur de liens à rechercher les archives plusieurs fois.

Vous pouvez lister la même archive plusieurs fois sur la ligne de commande.

Ce type de recherche d'archives est standard pour les éditeurs de liens Unix. Cependant, si vous utilisez ld sur AIX, notez qu'il est différent du comportement de l'éditeur de liens AIX.

-L répertoires de recherche
--library-path=répertoires de recherche
Ajoutez le chemin répertoires de recherche à la liste des chemins que ld recherchera pour les bibliothèques d'archives et les scripts de contrôle de ld. Vous pouvez utiliser cette option un nombre quelconque de fois. Les répertoires sont recherchés dans l'ordre où ils sont spécifiés sur la ligne de commande. Les répertoires spécifiés sur la ligne de commande sont recherchés avant les répertoires par défaut. Toutes les options -L s'appliquent à toutes les options -l, quel que soit l'ordre dans lequel les options apparaissent. Les options -L n'affectent pas la façon dont ld recherche un script d'éditeur de liens à moins que l'option -T ne soit spécifiée.

Si répertoires de recherche commence par "=" ou $SYSROOT, alors ce préfixe sera remplacé par le préfixe sysroot, contrôlé par l'option --sysroot, ou spécifié lors de la configuration de l'éditeur de liens.

L'ensemble par défaut de chemins recherchés (sans être spécifié avec -L) dépend du mode d'émulation que ld utilise, et dans certains cas également de la façon dont il a été configuré.

Les chemins peuvent également être spécifiés dans un script de liaison avec la commande "SEARCH_DIR". Les répertoires spécifiés de cette manière sont recherchés au moment où le script d'éditeur de liens apparaît sur la ligne de commande.

-m émulation
Émule l'éditeur de liens émulation. Vous pouvez lister les émulations disponibles avec les options --verbose ou -V.

Si l'option -m n'est pas utilisée, l'émulation est prise de la variable d'environnement "LDEMULATION", si elle est définie.

Sinon, l'émulation par défaut dépend de la configuration de l'éditeur de liens.

--remap-inputs=motif=nomfichier
--remap-inputs-file=fichier
Ces options permettent de modifier les noms des fichiers d'entrée avant que l'éditeur de liens ne tente de les ouvrir. L'option --remap-inputs=foo.o=bar.o fera en sorte que toute tentative de chargement d'un fichier appelé foo.o essaie plutôt de charger un fichier appelé bar.o. Des motifs génériques sont autorisés dans le premier nom de fichier, donc --remap-inputs=foo*.o=bar.o renommera tout fichier d'entrée correspondant à foo*.o en bar.o.

Une forme alternative de l'option --remap-inputs-file=nomfichier permet de lire les remappages à partir d'un fichier. Chaque ligne du fichier peut contenir un seul remappage. Les lignes vides sont ignorées. Tout à partir d'un caractère dièse (#) jusqu'à la fin de la ligne est considéré comme un commentaire et est également ignoré. Le motif de mappage peut être séparé du nom de fichier par des espaces blancs ou un signe égal (=).

Les options peuvent être spécifiées plusieurs fois. Leur contenu s'accumule. Les remappages seront traités dans l'ordre où ils apparaissent sur la ligne de commande, et s'ils proviennent d'un fichier, dans l'ordre où ils apparaissent dans le fichier. Si une correspondance est trouvée, aucune vérification supplémentaire pour ce nom de fichier ne sera effectuée.

Si le nom de fichier de remplacement est /dev/null ou simplement NUL, alors le remappage provoquera l'ignorance du fichier d'entrée. Cela peut être un moyen pratique d'expérimenter la suppression de fichiers d'entrée dans un environnement de construction complexe.

Notez que cette option dépend de la position et n'affecte que les noms de fichiers qui viennent après elle sur la ligne de commande. Ainsi :

ld foo.o --remap-inputs=foo.o=bar.o

N'aura aucun effet, alors que :

ld --remap-inputs=foo.o=bar.o foo.o

Renommera le fichier d'entrée foo.o en bar.o.

Remarque - ces options affectent également les fichiers référencés par les instructions INPUT dans les scripts d'éditeur de liens. Mais comme les scripts d'éditeur de liens sont traités après la lecture complète de la ligne de commande, la position des options de remappage sur la ligne de commande n'est pas significative.

Si l'option verbose est activée, alors tout remappage qui correspondra sera signalé, bien que encore une fois l'option verbose doive être activée sur la ligne de commande avant l'apparition des noms de fichiers remappés.

Si les options -Map ou --print-map sont activées, alors la liste de remappage sera incluse dans la sortie de la carte.

-M
--print-map
Affiche une carte de liaison sur la sortie standard. Une carte de liaison fournit des informations sur la liaison, y compris les éléments suivants :
  • Où les fichiers objets sont mappés en mémoire.
  • Comment les symboles communs sont alloués.
  • Tous les membres d'archive inclus dans la liaison, avec mention du symbole qui a provoqué l'inclusion du membre d'archive.
  • Les valeurs attribuées aux symboles.

    Remarque - les symboles dont les valeurs sont calculées par une expression qui implique une référence à une valeur précédente du même symbole peuvent ne pas avoir le résultat correct affiché dans la carte de liaison. Ceci est parce que l'éditeur de liens rejette les résultats intermédiaires et ne conserve que la valeur finale d'une expression. Dans de telles circonstances, l'éditeur de liens affichera la valeur finale entourée de crochets. Ainsi, par exemple, un script d'éditeur de liens contenant :

    foo = 1
foo = foo * 4
foo = foo + 8

    produira la sortie suivante dans la carte de liaison si l'option -M est utilisée :

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    Voir Expressions pour plus d'informations.

l'information sur les expressions dans les scripts de liaison.

  • Comment les propriétés GNU sont fusionnées.

    Lorsque l'éditeur de liens fusionne les sections .note.gnu.property d'entrée en une section .note.gnu.property de sortie, certaines propriétés sont supprimées ou mises à jour. Ces actions sont rapportées dans la carte de liaison. Par exemple :

    Removed property 0xc0000002 to merge foo.o (0x1) and bar.o (not found)

    Cela indique que la propriété 0xc0000002 est supprimée de la sortie lors de la fusion des propriétés dans foo.o, dont la valeur de la propriété 0xc0000002 est 0x1, et bar.o, qui ne possède pas la propriété 0xc0000002.

    Updated property 0xc0010001 (0x1) to merge foo.o (0x1) and bar.o (0x1)

    Cela indique que la valeur de la propriété 0xc0010001 est mise à jour à 0x1 dans la sortie lors de la fusion des propriétés dans foo.o, dont la valeur de la propriété 0xc0010001 est 0x1, et bar.o, dont la valeur de la propriété 0xc0010001 est 0x1.

  • Sur certaines cibles ELF, une liste de corrections insérées par --relax 
    foo.o: Adjusting branch at 0x00000008 towards "far" in section .text

    Cela indique que le branchement à l'adresse 0x00000008 dans foo.o, ciblant le symbole "far" dans la section .text, a été remplacé par un trampoline.

    -( archives -)
    --start-group archives --end-group
    Les archives doivent être une liste de fichiers d'archives. Ils peuvent être des noms de fichiers explicites ou des options -l.

    Les archives spécifiées sont recherchées de manière répétée jusqu'à ce qu'aucune nouvelle référence non résolue ne soit créée. Normalement, une archive n'est recherchée qu'une seule fois dans l'ordre où elle est spécifiée sur la ligne de commande. Si un symbole dans cette archive est nécessaire pour résoudre un symbole non résolu référencé par un objet dans une archive qui apparaît plus tard sur la ligne de commande, l'éditeur de liens ne serait pas en mesure de résoudre cette référence. En groupant les archives, elles seront toutes recherchées de manière répétée jusqu'à ce que toutes les références possibles soient résolues.

    L'utilisation de cette option a un coût de performance significatif. Il est préférable de l'utiliser uniquement lorsqu'il existe des références circulaires inévitables entre deux archives ou plus.

    --as-needed
    --no-as-needed
    Cette option affecte les balises DT_NEEDED ELF pour les bibliothèques dynamiques mentionnées sur la ligne de commande après l'option --as-needed. Normalement, l'éditeur de liens ajoutera une balise DT_NEEDED pour chaque bibliothèque dynamique mentionnée sur la ligne de commande, que la bibliothèque soit réellement nécessaire ou non. --as-needed fait qu'une balise DT_NEEDED n'est émise que pour une bibliothèque qui, *à ce stade de l'édition de liens*, satisfait une référence de symbole non résolu non faible d'un fichier objet régulier ou, si la bibliothèque n'est pas trouvée dans les listes DT_NEEDED d'autres bibliothèques nécessaires, une référence de symbole non résolu non faible d'une autre bibliothèque dynamique nécessaire. Les fichiers objets ou les bibliothèques apparaissant sur la ligne de commande *après* la bibliothèque en question n'affectent pas si la bibliothèque est considérée comme nécessaire. Ceci est similaire aux règles d'extraction de fichiers objets des archives. --no-as-needed restaure le comportement par défaut.

    --cref
    Produit une table de références croisées. Si un fichier de carte de l'éditeur de liens est généré, la table de références croisées est imprimée dans le fichier de carte. Sinon, elle est imprimée sur la sortie standard.

    Le format de la table est intentionnellement simple, de sorte qu'il puisse être facilement traité par un script si nécessaire. Les symboles sont imprimés, triés par nom. Pour chaque symbole, une liste de noms de fichiers est donnée. Si le symbole est défini, le premier fichier listé est l'emplacement de la définition. Si le symbole est défini comme une valeur commune, alors les fichiers où cela se produit apparaissent ensuite. Enfin, tous les fichiers qui référencent le symbole sont listés.

Ces variables ne peuvent clairement pas être recherchées par adresse par les débogueurs conventionnels, de sorte que l'espace utilisé pour leurs types et leurs noms est généralement perdu : les types sont généralement petits, mais les noms ne le sont souvent pas. --ctf-variables provoque la génération d'une telle section. Le comportement par défaut peut être restauré avec --no-ctf-variables.

L'utilisation de --no-define-common permet aux symboles communs qui sont référencés à partir d'une bibliothèque partagée de se voir attribuer des adresses uniquement dans le programme principal. Cela élimine l'espace en double inutilisé dans la bibliothèque partagée, et empêche également toute confusion possible quant à la résolution vers le mauvais duplicata lorsqu'il existe de nombreux modules dynamiques avec des chemins de recherche spécialisés pour la résolution des symboles à l'exécution.

    --defsym=symbole=expression
    Crée un symbole global dans le fichier de sortie, contenant l'adresse absolue donnée par expression. Vous pouvez utiliser cette option autant de fois que nécessaire pour définir plusieurs symboles sur la ligne de commande. Une forme limitée d'arithmétique est prise en charge pour l'expression dans ce contexte : vous pouvez donner une constante hexadécimale ou le nom d'un symbole existant, ou utiliser "+" et "-" pour ajouter ou soustraire des constantes hexadécimales ou des symboles. Si vous avez besoin d'expressions plus élaborées, envisagez d'utiliser le langage de commande de l'éditeur de liens à partir d'un script. Note : il ne doit y avoir aucun espace blanc entre symbole, le signe égal ("="), et expression.

    L'éditeur de liens traite les arguments --defsym et les arguments -T dans l'ordre. Placer --defsym avant -T définira le symbole avant que le script de l'éditeur de liens de -T ne soit traité, tandis que placer --defsym après -T définira le symbole après que le script de l'éditeur de liens ait été traité. Cette différence a des conséquences pour les expressions dans le script de l'éditeur de liens qui utilisent les symboles --defsym ; l'ordre qui est correct dépendra de ce que vous essayez d'accomplir.

Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur. L'éditeur de liens démangle par défaut, sauf si la variable d'environnement COLLECT_NO_DEMANGLE est définie. Ces options peuvent être utilisées pour remplacer le comportement par défaut.

    --no-warnings
    Ne pas afficher de messages d'avertissement ou d'erreur. Ceci remplace --fatal-warnings s'il a été activé. Cette option peut être utilisée lorsqu'il est connu que le binaire de sortie ne fonctionnera pas, mais qu'il est nécessaire de le créer.
    --force-exe-suffix
    S'assurer qu'un fichier de sortie a le suffixe .exe.

    Si un fichier de sortie entièrement lié et construit avec succès ne possède pas le suffixe ".exe" ou ".dll", cette option force l'éditeur de liens à copier le fichier de sortie vers un autre portant le même nom avec un suffixe ".exe". Cette option est utile lorsque l'on utilise des makefiles Unix non modifiés sur un hôte Microsoft Windows, car certaines versions de Windows n'exécuteront pas une image si elle ne se termine pas par un suffixe ".exe".

    --gc-sections
    --no-gc-sections
    Activer la récupération de place des sections d'entrée inutilisées. Elle est ignorée sur les cibles qui ne supportent pas cette option. Le comportement par défaut (ne pas effectuer cette récupération de place) peut être restauré en spécifiant --no-gc-sections sur la ligne de commande. Notez que la récupération de place pour les cibles au format COFF et PE est supportée, mais l'implémentation est actuellement considérée comme expérimentale.

    --gc-sections décide quelles sections d'entrée sont utilisées en examinant les symboles et les relocalisations. La section contenant le symbole d'entrée et toutes les sections contenant des symboles non définis sur la ligne de commande seront conservées, tout comme les sections contenant des symboles référencés par des objets dynamiques. Notez que lors de la construction de bibliothèques partagées, l'éditeur de liens doit supposer que tout symbole visible est référencé. Une fois cet ensemble initial de sections déterminé, l'éditeur de liens marque récursivement comme utilisées toute section référencée par leurs relocalisations. Voir --entry, --undefined, et --gc-keep-exported.

    Cette option peut être définie lors d'un lien partiel (activé avec l'option -r). Dans ce cas, la racine des symboles conservés doit être explicitement spécifiée soit par l'une des options --entry, --undefined, ou --gc-keep-exported, soit par une commande "ENTRY" dans le script de l'éditeur de liens.

    En tant qu'extension GNU, les sections d'entrée ELF marquées avec le drapeau "SHF_GNU_RETAIN" ne seront pas collectées par le garbage collector.

    --print-gc-sections
    --no-print-gc-sections
    Lister toutes les sections supprimées par la récupération de place. La liste est affichée sur stderr. Cette option n'est effective que si la récupération de place a été activée via l'option --gc-sections). Le comportement par défaut (ne pas lister les sections supprimées) peut être restauré en spécifiant --no-print-gc-sections sur la ligne de commande.
    --gc-keep-exported
    Lorsque --gc-sections est activé, cette option empêche la récupération de place des sections d'entrée inutilisées qui contiennent des symboles globaux ayant une visibilité par défaut ou protégée. Cette option est destinée à être utilisée pour les exécutables où les sections non référencées seraient autrement collectées par le garbage collector, quelle que soit la visibilité externe des symboles contenus. Notez que cette option n'a aucun effet lors de l'édition de liens d'objets partagés, car c'est déjà le comportement par défaut. Cette option n'est prise en charge que pour les cibles au format ELF.
    --print-output-format
    Afficher le nom du format de sortie par défaut (éventuellement influencé par d'autres options de ligne de commande). Il s'agit de la chaîne qui apparaîtrait dans une commande de script d'éditeur de liens "OUTPUT_FORMAT".
    --print-memory-usage
    Afficher la taille utilisée, la taille totale et la taille utilisée des régions mémoire créées avec la commande MEMORY. Ceci est utile sur les cibles embarquées pour avoir une vue rapide de la quantité de mémoire libre. Le format de la sortie comporte un titre et une ligne par région. Elle est à la fois lisible par l'homme et facilement analysable par des outils. Voici un exemple de sortie : 
    Région mémoire         Taille utilisée  Taille de la région  % utilisé
             ROM:        256 Ko         1 Mo     25.00%
             RAM:          32 B         2 Go      0.00%
    --help
    Afficher un résumé des options de ligne de commande sur la sortie standard et quitter.
    --target-help
    Afficher un résumé de toutes les options spécifiques à la cible sur la sortie standard et quitter.
    -Map=fichier_carte
    Afficher une carte de liens dans le fichier fichier_carte. Voir la description de l'option -M, ci-dessus. Si fichier_carte est juste le caractère "-", la carte sera écrite sur stdout.

    Spécifier un répertoire comme fichier_carte fait que la carte de l'éditeur de liens soit écrite dans un fichier à l'intérieur du répertoire. Normalement, le nom du fichier à l'intérieur du répertoire est calculé comme la partie base du nom du fichier de sortie avec ".map" ajouté. Si cependant le caractère spécial "%" est utilisé, il sera remplacé par le chemin complet du fichier de sortie. De plus, s'il y a des caractères après le symbole "%", ".map" ne sera plus ajouté.

    -o foo.exe -Map=bar                  [Crée ./bar]
-o ../dir/foo.exe -Map=bar           [Crée ./bar]
-o foo.exe -Map=../dir               [Crée ../dir/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir       [Crée ../dir/foo.exe.map]
-o foo.exe -Map=%                    [Crée ./foo.exe.map]
-o ../dir/foo.exe -Map=%             [Crée ../dir/foo.exe.map]
-o foo.exe -Map=%.bar                [Crée ./foo.exe.bar]
-o ../dir/foo.exe -Map=%.bar         [Crée ../dir/foo.exe.bar]
-o ../dir2/foo.exe -Map=../dir/%     [Crée ../dir/../dir2/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir/%.bar [Crée ../dir/../dir2/foo.exe.bar]

    Il est erroné de spécifier plus d'un caractère "%".

    Si le fichier carte existe déjà, il sera écrasé par cette opération.

    --no-keep-memory
    ld optimise normalement pour la vitesse par rapport à l'utilisation de la mémoire en mettant en cache les tables de symboles des fichiers d'entrée en mémoire. Cette option indique à ld d'optimiser plutôt pour l'utilisation de la mémoire, en relisant les tables de symboles si nécessaire. Cela peut être requis si ld manque d'espace mémoire lors de l'édition de liens d'un grand exécutable.
    --no-undefined
    -z defs
    Signaler les références de symboles non résolues provenant de fichiers objets réguliers. Ceci est fait même si l'éditeur de liens crée une bibliothèque partagée non symbolique. Le commutateur --[no-]allow-shlib-undefined contrôle le comportement de signalement des références non résolues trouvées dans les bibliothèques partagées en cours d'édition de liens.

    Les effets de cette option peuvent être annulés en utilisant "-z undefs".

    --allow-multiple-definition
    -z muldefs
    Normalement, lorsqu'un symbole est défini plusieurs fois, l'éditeur de liens signalera une erreur fatale. Ces options autorisent les définitions multiples et la première définition sera utilisée.
    --allow-shlib-undefined
    --no-allow-shlib-undefined
    Autorise ou interdit les symboles indéfinis dans les bibliothèques partagées. Ce commutateur est similaire à --no-undefined sauf qu'il détermine le comportement lorsque les symboles indéfinis se trouvent dans une bibliothèque partagée plutôt que dans un fichier objet régulier. Il n'affecte pas la manière dont les symboles indéfinis dans les fichiers objets réguliers sont gérés.

    Le comportement par défaut est de signaler les erreurs pour tous les symboles indéfinis référencés dans les bibliothèques partagées si l'éditeur de liens est utilisé pour créer un exécutable, mais de les autoriser si l'éditeur de liens est utilisé pour créer une bibliothèque partagée.

    Les raisons d'autoriser les références de symboles indéfinis dans les bibliothèques partagées spécifiées au moment de l'édition de liens sont que :

    • Une bibliothèque partagée spécifiée au moment de l'édition de liens peut ne pas être la même que celle qui est disponible au moment du chargement, donc le symbole pourrait en fait être résoluble au moment du chargement.
    • Il existe certains systèmes d'exploitation, par exemple BeOS et HPPA, où les symboles indéfinis dans les bibliothèques partagées sont normaux.

      Le noyau BeOS, par exemple, patch les bibliothèques partagées au moment du chargement pour sélectionner la fonction la plus appropriée à l'architecture actuelle. Ceci est utilisé, par exemple, pour sélectionner dynamiquement une fonction memset appropriée.

    --error-handling-script=nom_script
    Si cette option est fournie, l'éditeur de liens invoquera nom_script chaque fois qu'une erreur est rencontrée. Actuellement, cependant, seuls deux types d'erreurs sont pris en charge : symboles manquants et bibliothèques manquantes. Deux arguments seront passés au script : le mot-clé "undefined-symbol" ou `missing-lib" et le nom du symbole indéfini ou de la bibliothèque manquante. L'intention est que le script fournisse des suggestions à l'utilisateur quant à l'endroit où le symbole ou la bibliothèque pourrait être trouvée. Après que le script ait terminé, le message d'erreur normal de l'éditeur de liens sera affiché.

    La disponibilité de cette option est contrôlée par un commutateur de configuration, elle peut donc ne pas être présente dans des implémentations spécifiques.

    --no-undefined-version
    Normalement, lorsqu'un symbole a une version indéfinie, l'éditeur de liens l'ignore. Cette option interdit les symboles avec une version indéfinie et une erreur fatale sera émise à la place.
    --default-symver
    Créer et utiliser une version de symbole par défaut (le soname) pour les symboles exportés non versionnés.
    --default-imported-symver
    Crée et utilise une version de symbole par défaut (le soname) pour les symboles importés non versionnés.
    --no-warn-mismatch
    Normalement, ld générera une erreur si vous essayez de lier des fichiers d'entrée qui sont incompatibles pour une raison quelconque, par exemple parce qu'ils ont été compilés pour des processeurs différents ou pour des architectures avec des ordres d'octets différents. Cette option indique à ld de permettre silencieusement de telles erreurs potentielles. Cette option ne doit être utilisée qu'avec prudence, dans les cas où vous avez pris des mesures spéciales qui garantissent que les erreurs du lieur sont inappropriées.
    --no-warn-search-mismatch
    Normalement, ld émettra un avertissement s'il trouve une bibliothèque incompatible lors d'une recherche de bibliothèque. Cette option supprime l'avertissement.
    --no-whole-archive
    Désactive l'effet de l'option --whole-archive pour les archives subséquentes.
    --noinhibit-exec
    Conserve le fichier exécutable de sortie tant qu'il est utilisable. Normalement, le lieur ne produira pas de fichier de sortie s'il rencontre des erreurs pendant le processus de liaison ; il se termine sans écrire de fichier de sortie lorsqu'il émet une erreur quelconque.
    -nostdlib
    Ne recherche les répertoires de bibliothèques que ceux explicitement spécifiés sur la ligne de commande. Les répertoires de bibliothèques spécifiés dans les scripts de liaison (y compris les scripts de liaison spécifiés sur la ligne de commande) sont ignorés.
    --oformat=format-sortie
    ld peut être configuré pour prendre en charge plus d'un type de fichier objet. Si votre ld est configuré de cette manière, vous pouvez utiliser l'option --oformat pour spécifier le format binaire pour le fichier objet de sortie. Même lorsque ld est configuré pour prendre en charge des formats d'objets alternatifs, vous n'avez généralement pas besoin de le spécifier, car ld devrait être configuré pour produire en tant que format de sortie par défaut le format le plus courant sur chaque machine. format-sortie est une chaîne de caractères, le nom d'un format particulier pris en charge par les bibliothèques BFD. (Vous pouvez lister les formats binaires disponibles avec objdump -i.) La commande de script "OUTPUT_FORMAT" peut également spécifier le format de sortie, mais cette option la surcharge.
    --out-implib fichier
    Crée une bibliothèque d'importation dans fichier correspondant à l'exécutable que le lieur génère (par exemple, une DLL ou un programme ELF). Cette bibliothèque d'importation (qui devrait s'appeler "*.dll.a" ou "*.a" pour les DLL) peut être utilisée pour lier des clients contre l'exécutable généré ; ce comportement permet d'éviter une étape de création de bibliothèque d'importation séparée (par exemple, "dlltool" pour les DLL). Cette option n'est disponible que pour les ports de lieur ciblés i386 PE et ELF.
    -pie
    --pic-executable
    Crée un exécutable indépendant de la position. Ceci n'est actuellement pris en charge que sur les plateformes ELF. Les exécutables indépendants de la position sont similaires aux bibliothèques partagées car ils sont déplacés par le lieur dynamique à l'adresse virtuelle que le système d'exploitation leur attribue (ce qui peut varier entre les invocations). Comme les exécutables liés dynamiquement normaux, ils peuvent être exécutés et les symboles définis dans l'exécutable ne peuvent pas être remplacés par des bibliothèques partagées.
    -no-pie
    Crée un exécutable dépendant de la position. C'est le comportement par défaut.
    -qmagic
    Cette option est ignorée pour la compatibilité Linux.
    -Qy
    Cette option est ignorée pour la compatibilité SVR4.
    --relax
    --no-relax
    Une option avec des effets dépendant de la machine. Cette option n'est prise en charge que sur quelques cibles.

    Sur certaines plateformes, l'option --relax effectue des optimisations globales spécifiques à la cible qui deviennent possibles lorsque le lieur résout l'adressage dans le programme, telles que la relaxation des modes d'adressage, la synthèse de nouvelles instructions, la sélection de versions plus courtes des instructions actuelles et la combinaison de valeurs constantes.

    Sur certaines plateformes, ces optimisations globales au moment de la liaison peuvent rendre le débogage symbolique de l'exécutable résultant impossible. C'est le cas connu pour la famille de processeurs Matsushita MN10200 et MN10300.

    Sur les plateformes où la fonctionnalité est prise en charge, l'option --no-relax la désactivera.

    Sur les plateformes où la fonctionnalité n'est pas prise en charge, les options --relax et --no-relax sont acceptées, mais ignorées.

    --retain-symbols-file=nom-fichier
    Ne conserve que les symboles listés dans le fichier nom-fichier, en rejetant tous les autres. nom-fichier est simplement un fichier plat, avec un nom de symbole par ligne. Cette option est particulièrement utile dans les environnements (comme VxWorks) où une grande table de symboles globale est accumulée progressivement, pour économiser la mémoire d'exécution.

    --retain-symbols-file ne rejette pas les symboles indéfinis, ni les symboles nécessaires aux relocations.

    Vous ne pouvez spécifier --retain-symbols-file qu'une seule fois sur la ligne de commande. Elle surcharge -s et -S.

    -rpath=rép
    Ajoute un répertoire au chemin de recherche des bibliothèques d'exécution. Ceci est utilisé lors de la liaison d'un exécutable ELF avec des objets partagés. Tous les arguments -rpath sont concaténés et transmis au lieur d'exécution, qui les utilise pour localiser les objets partagés à l'exécution.

    L'option -rpath est également utilisée lors de la localisation d'objets partagés requis par des objets partagés inclus explicitement dans la liaison ; voir la description de l'option -rpath-link. La recherche de -rpath de cette manière n'est prise en charge que par les lieurs natifs et les lieurs croisés qui ont été configurés avec l'option --with-sysroot.

    Si -rpath n'est pas utilisé lors de la liaison d'un exécutable ELF, le contenu de la variable d'environnement "LD_RUN_PATH" sera utilisé s'il est défini.

    L'option -rpath peut également être utilisée sur SunOS. Par défaut, sur SunOS, le lieur formera un chemin de recherche d'exécution à partir de toutes les options -L qui lui sont données. Si une option -rpath est utilisée, le chemin de recherche d'exécution sera formé exclusivement en utilisant les options -rpath, ignorant les options -L. Cela peut être utile lors de l'utilisation de gcc, qui ajoute de nombreuses options -L qui peuvent se trouver sur des systèmes de fichiers montés NFS.

    Pour la compatibilité avec d'autres lieurs ELF, si l'option -R est suivie d'un nom de répertoire, plutôt que d'un nom de fichier, elle est traitée comme l'option -rpath.

    -rpath-link=rép
    Lors de l'utilisation d'ELF ou SunOS, une bibliothèque partagée peut en requérir une autre. Cela se produit lorsqu'une liaison "ld -shared" inclut une bibliothèque partagée comme l'un des fichiers d'entrée.

    Lorsque le lieur rencontre une telle dépendance lors d'une liaison non partagée et non déplaçable, il essaiera automatiquement de localiser la bibliothèque partagée requise et de l'inclure dans la liaison, si elle n'est pas incluse explicitement. Dans un tel cas, l'option -rpath-link spécifie le premier ensemble de répertoires à rechercher. L'option -rpath-link peut spécifier une séquence de noms de répertoires soit en spécifiant une liste de noms séparés par des deux-points, soit en apparaissant plusieurs fois.

    Les jetons $ORIGIN et $LIB peuvent apparaître dans ces répertoires de recherche. Ils seront remplacés par le chemin complet du répertoire contenant le programme ou l'objet partagé dans le cas de $ORIGIN et soit lib - pour les binaires 32 bits - soit lib64 - pour les binaires 64 bits - dans le cas de $LIB.

    La forme alternative de ces jetons - ${ORIGIN} et ${LIB} peut également être utilisée. Le jeton $PLATFORM n'est pas pris en charge.

    Cette option doit être utilisée avec prudence car elle surcharge le chemin de recherche qui peut avoir été codé en dur dans une bibliothèque partagée. Dans un tel cas, il est possible d'utiliser involontairement un chemin de recherche différent de celui que le lieur d'exécution utiliserait.

    Le lieur utilise les chemins de recherche suivants pour localiser les bibliothèques partagées requises :

    1.
    Tous les répertoires spécifiés par les options -rpath-link.
    2.
    Tous les répertoires spécifiés par les options -rpath. La différence entre -rpath et -rpath-link est que les répertoires spécifiés par les options -rpath sont inclus dans l'exécutable et utilisés à l'exécution, tandis que l'option -rpath-link n'est effective qu'au moment de la liaison. La recherche de -rpath de cette manière n'est prise en charge que par les lieurs natifs et les lieurs croisés qui ont été configurés avec l'option --with-sysroot.
    3.
    Sur un système ELF, pour les lieurs natifs, si les options -rpath et -rpath-link n'ont pas été utilisées, recherchez le contenu de la variable d'environnement "LD_RUN_PATH".
    4.
    Sur SunOS, si l'option -rpath n'a pas été utilisée, recherchez tous les répertoires spécifiés à l'aide des options -L.
    5.
    Pour un lieur natif, recherchez le contenu de la variable d'environnement "LD_LIBRARY_PATH".
    6.
    Pour un lieur ELF natif, les répertoires dans "DT_RUNPATH" ou "DT_RPATH" d'une bibliothèque partagée sont recherchés pour les bibliothèques partagées dont elle a besoin. Les entrées "DT_RPATH" sont ignorées si des entrées "DT_RUNPATH" existent.
    7.
    Pour un lieur pour un système Linux, si le fichier /etc/ld.so.conf existe, la liste des répertoires trouvés dans ce fichier. Remarque : le chemin vers ce fichier est précédé de la valeur "sysroot", si elle est définie, puis de toute chaîne "prefix" si le lieur a été configuré avec l'option
    -préfixe=<chemin> option.
    8.
    Pour un éditeur de liens natif sur un système FreeBSD, tous les répertoires spécifiés par la macro "_PATH_ELF_HINTS" définie dans le fichier d'en-tête elf-hints.h.
    9.
    Tous les répertoires spécifiés par une commande "SEARCH_DIR" dans un script d'édition de liens donné sur la ligne de commande, y compris les scripts spécifiés par -T (mais pas -dT).
    10.
    Les répertoires par défaut, normalement /lib et /usr/lib.
    11.
    Tous les répertoires spécifiés par un plugin LDPT_SET_EXTRA_LIBRARY_PATH.
    12.
    Tous les répertoires spécifiés par une commande "SEARCH_DIR" dans un script d'édition de liens par défaut.

    Notez cependant que sur les systèmes basés sur Linux, il y a une mise en garde supplémentaire : si l'option --as-needed est active * et qu'une bibliothèque partagée est trouvée qui satisferait normalement la recherche * et que cette bibliothèque n'a pas de tag DT_NEEDED pour libc.so * et qu'il existe une bibliothèque partagée plus loin dans l'ensemble des répertoires de recherche qui satisfait également la recherche * et que cette seconde bibliothèque partagée a un tag DT_NEEDED pour libc.so * alors la seconde bibliothèque sera sélectionnée au lieu de la première.

    Si la bibliothèque partagée requise n'est pas trouvée, l'éditeur de liens affichera un avertissement et continuera le lien.

    -shared
    -Bshareable
    Crée une bibliothèque partagée. Ceci n'est actuellement pris en charge que sur les plates-formes ELF, XCOFF et SunOS. Sur SunOS, l'éditeur de liens créera automatiquement une bibliothèque partagée si l'option -e n'est pas utilisée et qu'il y a des symboles indéfinis dans le lien.
    --sort-common
    --sort-common=ascending
    --sort-common=descending
    Cette option indique à ld de trier les symboles communs par alignement dans l'ordre croissant ou décroissant lorsqu'il les place dans les sections de sortie appropriées. Les alignements de symboles considérés sont de seize octets ou plus, huit octets, quatre octets, deux octets et un octet. Ceci afin d'éviter des écarts entre les symboles dus aux contraintes d'alignement. Si aucun ordre de tri n'est spécifié, l'ordre décroissant est supposé.
    --sort-section=name
    Cette option appliquera "SORT_BY_NAME" à tous les modèles de sections joker dans le script de l'éditeur de liens.
    --sort-section=alignment
    Cette option appliquera "SORT_BY_ALIGNMENT" à tous les modèles de sections joker dans le script de l'éditeur de liens.
    --spare-dynamic-tags=count
    Cette option spécifie le nombre d'emplacements vides à laisser dans la section .dynamic des objets partagés ELF. Des emplacements vides peuvent être nécessaires pour des outils de post-traitement, tels que le pré-éditeur de liens. La valeur par défaut est 5.
    --split-by-file[=size]
    Similaire à --split-by-reloc mais crée une nouvelle section de sortie pour chaque fichier d'entrée lorsque la taille size est atteinte. size prend par défaut la valeur 1 si elle n'est pas donnée.
    --split-by-reloc[=count]
    Tente de créer des sections supplémentaires dans le fichier de sortie de sorte qu'aucune section de sortie unique dans le fichier ne contienne plus de count relocations. Ceci est utile lors de la génération de fichiers déplaçables volumineux pour le téléchargement dans certains noyaux temps réel avec le format de fichier objet COFF ; car COFF ne peut pas représenter plus de 65535 relocations dans une seule section. Notez que cela échouera avec les formats de fichiers objet qui ne prennent pas en charge les sections arbitraires. L'éditeur de liens ne divisera pas les sections d'entrée individuelles pour redistribution, donc si une seule section d'entrée contient plus de count relocations, une section de sortie contiendra ce nombre de relocations. count prend par défaut la valeur 32768.
    --stats
    Calcule et affiche des statistiques sur le fonctionnement de l'éditeur de liens, telles que le temps d'exécution et l'utilisation de la mémoire.
    --sysroot=directory
    Utilise directory comme emplacement du sysroot, remplaçant la valeur par défaut configurée. Cette option n'est prise en charge que par les éditeurs de liens configurés avec --with-sysroot.
    --task-link
    Ceci est utilisé par les cibles basées sur COFF/PE pour créer un fichier objet lié à une tâche où tous les symboles globaux ont été convertis en statiques.
    --traditional-format
    Pour certaines cibles, la sortie de ld diffère à certains égards de la sortie de certains éditeurs de liens existants. Ce commutateur demande à ld d'utiliser le format traditionnel à la place.

    Par exemple, sur SunOS, ld combine les entrées dupliquées dans la table des chaînes de symboles. Cela peut réduire la taille d'un fichier de sortie avec des informations de débogage complètes de plus de 30 %. Malheureusement, le programme SunOS "dbx" ne peut pas lire le programme résultant ("gdb" n'a aucun problème). Le commutateur --traditional-format indique à ld de ne pas combiner les entrées dupliquées.

    --section-start=sectionname=org
    Localise une section dans le fichier de sortie à l'adresse absolue donnée par org. Vous pouvez utiliser cette option autant de fois que nécessaire pour localiser plusieurs sections sur la ligne de commande. org doit être un entier hexadécimal unique ; pour la compatibilité avec d'autres éditeurs de liens, vous pouvez omettre le préfixe 0x généralement associé aux valeurs hexadécimales. Notez : il ne doit y avoir aucun espace blanc entre sectionname, le signe égal ("="), et org.
    -Tbss=org
    -Tdata=org
    -Ttext=org

    --warn-common
    Avertit lorsqu'un symbole commun est combiné avec un autre symbole commun ou avec une définition de symbole. Les éditeurs de liens Unix autorisent cette pratique quelque peu négligente, mais les éditeurs de liens sur certains autres systèmes d'exploitation ne le font pas. Cette option vous permet de détecter des problèmes potentiels dus à la combinaison de symboles globaux. Malheureusement, certaines bibliothèques C utilisent cette pratique, vous pourriez donc recevoir des avertissements concernant les symboles des bibliothèques ainsi que ceux de vos programmes.

    Il existe trois types de symboles globaux, illustrés ici par des exemples en C :

    int i = 1;
    Une définition, qui va dans la section des données initialisées du fichier de sortie.
    extern int i;
    Une référence indéfinie, qui do
    n will call the original "malloc" function.

    n> appellera la fonction "malloc" réelle.

    Vous voudrez peut-être aussi fournir une fonction "__real_malloc", afin que les liens sans l'option --wrap réussissent. Si vous le faites, vous ne devriez pas mettre la définition de "__real_malloc" dans le même fichier que "__wrap_malloc" ; si vous le faites, l'assembleur pourrait résoudre l'appel avant que l'éditeur de liens n'ait la possibilité de le relier à "malloc".

    Seules les références indéfinies sont remplacées par l'éditeur de liens. Ainsi, les références internes à l'unité de traduction à symbole ne sont pas résolues en "__wrap_symbole". Dans l'exemple suivant, l'appel à "f" dans "g" n'est pas résolu en "__wrap_f".

    int
f (void)
{
  return 123;
}

int
g (void)
{
  return f();
}

    --compress-debug-sections=none
    --compress-debug-sections=zlib
    --compress-debug-sections=zlib-gnu
    --compress-debug-sections=zlib-gabi
    --compress-debug-sections=zstd
    Sur les plateformes ELF, ces options contrôlent la manière dont les sections de débogage DWARF sont compressées à l'aide de zlib.

    --compress-debug-sections=none ne compresse pas les sections de débogage DWARF. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF et les renomme pour commencer par .zdebug au lieu de .debug. --compress-debug-sections=zlib-gabi compresse également les sections de débogage DWARF, mais au lieu de les renommer, elle définit le drapeau SHF_COMPRESSED dans les en-têtes des sections.

    L'option --compress-debug-sections=zlib est un alias pour --compress-debug-sections=zlib-gabi.

    --compress-debug-sections=zstd compresse les sections de débogage DWARF à l'aide de zstd.

    Notez que cette option remplace toute compression dans les sections de débogage d'entrée, donc si un binaire est lié avec --compress-debug-sections=none par exemple, alors toutes les sections de débogage compressées dans les fichiers d'entrée seront décompressées avant d'être copiées dans le binaire de sortie.

    Le comportement de compression par défaut varie en fonction de la cible concernée et des options de configuration utilisées pour construire la chaîne d'outils. La valeur par défaut peut être déterminée en examinant la sortie de l'option --help de l'éditeur de liens.

    --reduce-memory-overheads
    Cette option réduit les besoins en mémoire à l'exécution de ld, au détriment de la vitesse de liaison. Elle a été introduite pour sélectionner l'ancien algorithme O(n^2) pour la génération du fichier de carte de lien, plutôt que le nouvel algorithme O(n) qui utilise environ 40% de mémoire en plus pour le stockage des symboles.

    Un autre effet de ce commutateur est de définir la taille par défaut de la table de hachage à 1021, ce qui économise de la mémoire au détriment de l'allongement du temps d'exécution de l'éditeur de liens. Cependant, cela n'est pas fait si le commutateur --hash-size a été utilisé.

    Le commutateur --reduce-memory-overheads peut également être utilisé pour activer d'autres compromis dans les futures versions de l'éditeur de liens.

    --max-cache-size=taille
    ld met normalement en cache les informations de relocalisation et les tables de symboles des fichiers d'entrée en mémoire avec une taille illimitée. Cette option définit la taille maximale du cache à taille.
    --build-id
    --build-id=style
    Demande la création d'une section de note ELF ".note.gnu.build-id" ou d'une section COFF ".buildid". Le contenu de la note identifie de manière unique ce fichier lié. style peut être "uuid" pour utiliser 128 bits aléatoires, "sha1" pour utiliser un hachage SHA1 de 160 bits sur les parties normatives du contenu de sortie, "md5" pour utiliser un hachage MD5 de 128 bits sur les parties normatives du contenu de sortie, ou "0xchaînehex" pour utiliser une chaîne de bits choisie spécifiée comme un nombre pair de chiffres hexadécimaux (les caractères "-" et ":" entre les paires de chiffres sont ignorés). Si style est omis, "sha1" est utilisé.

    Les styles "md5" et "sha1" produisent un identifiant qui est toujours le même dans un fichier de sortie identique, mais qui sera unique parmi tous les fichiers non identiques. Il n'est pas destiné à être comparé comme une somme de contrôle du contenu du fichier. Un fichier lié peut être modifié ultérieurement par d'autres outils, mais la chaîne de bits build-id identifiant le fichier lié d'origine ne change pas.

    Passer "none" pour style désactive le paramètre de toute option "--build-id" précédente sur la ligne de commande.

    Les variantes PE du format d'objet COFF ajoutent une extension qui permet l'utilisation de noms de sections plus longs que huit caractères, la limite normale pour COFF. Par défaut, ces noms ne sont qu'un
    autorisé dans les fichiers objets, car les images exécutables entièrement liées ne transportent pas la table de chaînes COFF requise pour prendre en charge les noms plus longs.     Note : L'utilisation de l'extension 'auto-import' rendra la section de texte du fichier image modifiable en écriture. Ceci n'est pas conforme à la spécification du format PE-COFF publiée par Microsoft.

    Note - l'utilisation de l'extension 'auto-import' entraînera également le placement de données en lecture seule qui seraient normalement placées dans la section .rdata, dans la section .data à la place. Ceci afin de contourner un problème avec les constantes décrit ici : http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

    L'utilisation de 'auto-import' fonctionnera généralement "sans problème" -- mais parfois vous pourriez voir ce message :

    "la variable '<var>' ne peut pas être auto-importée. Veuillez lire la documentation de ld concernant "--enable-auto-import" pour plus de détails."

    Ce message survient lorsque certaines (sous)expressions accèdent à une adresse finalement donnée par la somme de deux constantes (les tables d'importation Win32 n'en autorisent qu'une). Les cas où cela peut se produire incluent les accès aux champs de membres de variables de structure importées d'une DLL, ainsi que l'utilisation d'un index constant dans une variable tableau importée d'une DLL. Toute variable multi-mot (tableaux, structures, long long, etc.) peut déclencher cette condition d'erreur. Cependant, indépendamment du type de données exact de la variable exportée fautive, ld la détectera toujours, émettra l'avertissement et se terminera.

    Il existe plusieurs façons de résoudre cette difficulté, indépendamment du type de données de la variable exportée :

    Une façon est d'utiliser l'option --enable-runtime-pseudo-reloc. Ceci laisse la tâche d'ajuster les références dans votre code client pour l'environnement d'exécution, donc cette méthode ne fonctionne que lorsque l'environnement d'exécution prend en charge cette fonctionnalité.

    Une deuxième solution consiste à forcer l'une des 'constantes' à être une variable -- c'est-à-dire inconnue et non optimisable au moment de la compilation. Pour les tableaux, il y a deux possibilités : a) rendre l'indexé (l'adresse du tableau) variable, ou b) rendre l'index 'constant' variable. Ainsi :

    extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

    ou

    extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

    Pour les structures (et la plupart des autres types de données multi-mots), la seule option est de rendre la structure elle-même (ou le long long, ou le ...) variable :

    extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

    ou

    extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

    Une troisième méthode pour traiter cette difficulté est d'abandonner 'auto-import' pour le symbole fautif et de le marquer avec "__declspec(dllimport)". Cependant, en pratique, cela nécessite d'utiliser des #defines au moment de la compilation pour indiquer si vous compilez une DLL, si vous compilez du code client qui se liera à la DLL, ou simplement si vous compilez/liez à une bibliothèque statique. En faisant le choix entre les différentes méthodes de résolution du problème de 'adresse directe avec décalage constant', vous devriez considérer l'usage réel typique :

    Original :

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Solution 1 :

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Ce contournement est pour win32 et cygwin; ne pas "optimiser" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

    Solution 2 :

    --foo.h
/* Note : auto-export est supposé (pas de __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Une quatrième façon d'éviter ce problème est de recoder votre bibliothèque pour utiliser une interface fonctionnelle plutôt qu'une interface de données pour les variables fautives (par exemple, des fonctions d'accès set_foo() et get_foo()).

    N'essaie pas d'effectuer une liaison sophistiquée de "_symbol" à "__imp__symbol" pour les importations de DONNÉES depuis des DLL. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]
    --enable-runtime-pseudo-reloc
    Si votre code contient des expressions décrites dans la section --enable-auto-import, c'est-à-dire des importations de DONNÉES depuis une DLL avec un décalage non nul, ce commutateur créera un vecteur de 'relocalisations pseudo-runtime' qui pourra être utilisé par l'environnement d'exécution pour ajuster les références à ces données dans votre code client. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]
    --disable-runtime-pseudo-reloc
    Ne crée pas de relocalisations pseudo pour les importations de DONNÉES depuis des DLL avec un décalage non nul. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]
    --enable-extra-pe-debug
    Affiche des informations de débogage supplémentaires relatives au thunking de symboles auto-importés. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]
    --section-alignment
    Définit l'alignement des sections. Les sections en mémoire commenceront toujours à des adresses qui sont un multiple de ce nombre. La valeur par défaut est 0x1000. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]
    --stack réserve
    --stack réserve,commit
    Spécifie le nombre d'octets de mémoire à réserver (et éventuellement à commiter) à utiliser comme pile pour ce programme. La valeur par défaut est 2 Mo réservés, 4 Ko commités. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]

    --subsystem quel:majeur
    --subsystem quel:majeur.mineur

Vous pouvez éventuellement définir également la version du sous-système. Des valeurs numériques sont également acceptées pour quel. [Cette option est spécifique au port cible PE i386 de l'éditeur de liens]

    --forceinteg

    Les contrôles d'intégrité du code sont appliqués. Cette option est désactivée par défaut.
    --nxcompat
    --disable-nxcompat
    L'image est compatible avec la protection contre l'exécution des données (DEP). Cette fonctionnalité a été introduite avec MS Windows XP SP2 pour les cibles PE i386. L'option est activée par défaut.
    --no-isolation

    Bien que l'image comprenne l'isolation, n'isole pas l'image. Cette option est désactivée par défaut.
    --no-seh

    L'image n'utilise pas SEH. Aucun gestionnaire SE ne peut être appelé depuis cette image. Cette option est désactivée par défaut.

    Ne lie pas cette image. Cette option est désactivée par défaut.

    Le pilote utilise le modèle de pilote MS Windows. Cette option est disabled par défaut.
    --tsaware

    L'image est compatible avec le serveur Terminal. Cette option est désactivée par défaut.
    --insert-timestamp
    --no-insert-timestamp
    Insère une vraie estampille temporelle dans l'image. C'est le comportement par défaut car il correspond au code hérité et signifie que l'image fonctionnera avec d'autres outils propriétaires. Le problème avec ce défaut est qu'il produira des images légèrement différentes à chaque fois que les mêmes sources seront liées. L'option --no-insert-timestamp peut être utilisée pour insérer une valeur zéro pour l'estampille temporelle, assurant ainsi que les binaires produits à partir de sources identiques se compareront de manière identique.

    Si --insert-timestamp est actif, le temps inséré est soit l'heure à laquelle la liaison a lieu, soit, si la variable d'environnement "SOURCE_DATE_EPOCH" est définie, le nombre de secondes depuis l'époque Unix tel que spécifié par cette variable.

    --enable-reloc-section
    --disable-reloc-section
    Crée la table de relocalisation de base, nécessaire si l'image est chargée à une base d'image différente de celle spécifiée dans l'en-tête PE. Cette option est activée par défaut.

    La cible C6X uClinux utilise un format binaire appelé DSBT pour prendre en charge les bibliothèques partagées. Chaque bibliothèque partagée du système doit avoir un index unique ; tous les exécutables utilisent un index de 0.

    --dsbt-size taille
    Cette option définit le nombre d'entrées dans le DSBT de l'exécutable ou de la bibliothèque partagée actuelle à taille. Par défaut, une table de 64 entrées est créée.
    --dsbt-index index
    Cette option définit l'index DSBT de l'exécutable ou de la bibliothèque partagée actuelle à index. La valeur par défaut est 0, ce qui est approprié pour générer des exécutables. Si une bibliothèque partagée est générée avec un index DSBT de 0, les relocations "R_C6000_DSBT_INDEX" sont copiées dans le fichier de sortie.

    Le commutateur --no-merge-exidx-entries désactive la fusion des entrées exidx adjacentes dans les informations de déroulement de trame.

    --branch-stub
    Cette option active la relaxation des branches du lieur en insérant des sections de stubs de branchement lorsque nécessaire pour étendre la plage des branches. Cette option n'est généralement pas requise car C-SKY prend en charge les instructions de branchement et d'appel qui peuvent accéder à toute la plage mémoire et la relaxation des branches est normalement gérée par le compilateur ou l'assembleur.
    --stub-group-size=N
    Cette option permet un contrôle plus fin de la création des stubs de branchement par le lieur. Elle définit la taille maximale d'un groupe de sections d'entrée qui peuvent être gérées par une section de stub. Une valeur négative de N place les sections de stub après leurs branches, tandis qu'une valeur positive permet aux sections de stub d'apparaître avant ou après les branches. Les valeurs 1 ou -1 indiquent que le lieur doit choisir les valeurs par défaut appropriées.

    Les lieurs 68HC11 et 68HC12 prennent en charge des options spécifiques pour contrôler le mappage de commutation de banque mémoire et la génération de code trampoline.

    --no-trampoline
    Cette option désactive la génération de trampoline. Par défaut, un trampoline est généré pour chaque fonction lointaine appelée à l'aide d'une instruction "jsr" (ce qui se produit lorsqu'un pointeur vers une fonction lointaine est pris).
    --bank-window nom
    Cette option indique au lieur le nom de la région mémoire dans la spécification MEMORY qui décrit la fenêtre de banque mémoire. La définition d'une telle région est ensuite utilisée par le lieur pour calculer le pagination et les adresses dans la fenêtre mémoire.

    Les options suivantes sont prises en charge pour contrôler la gestion de la génération du GOT lors de la liaison pour les cibles 68K.

    --got=type
    Cette option indique au lieur quel schéma de génération de GOT utiliser. type doit être l'un des termes suivants : single, negative, multigot ou target. Pour plus d'informations, consultez l'entrée Info de ld.

    Les options suivantes sont prises en charge pour contrôler la génération d'instructions microMIPS et les vérifications de relocalisation de branchement pour les transitions de mode ISA lors de la liaison pour les cibles MIPS.

    --insn32
    --no-insn32
    Ces options contrôlent le choix des instructions microMIPS utilisées dans le code généré par le lieur, comme celui des stubs PLT ou de liaison paresseuse, ou dans la relaxation. Si --insn32 est utilisé, le lieur n'utilise que des encodages d'instructions de 32 bits. Par défaut ou si --no-insn32 est utilisé, tous les encodages d'instructions sont utilisés, y compris ceux de 16 bits si possible.
    --ignore-branch-isa
    --no-ignore-branch-isa
    Ces options contrôlent les vérifications de relocalisation de branchement pour les transitions de mode ISA invalides. Si --ignore-branch-isa est utilisé, le lieur accepte toutes les relocalisations de branchement et toute transition de mode ISA requise est perdue dans le calcul de relocalisation, à l'exception de certains cas d'instructions "BAL" qui satisfont aux conditions de relaxation et sont converties en instructions "JALX" équivalentes lors du calcul de la relocalisation associée. Par défaut ou si --no-ignore-branch-isa est utilisé, une vérification est effectuée, ce qui entraîne la perte d'une transition de mode ISA et produit une erreur.
    --compact-branches
    --no-compact-branches
    Ces options contrôlent la génération d'instructions compactes par le lieur dans les entrées PLT pour MIPS R6.

    Pour la cible pdp11-aout, trois variantes du format de sortie peuvent être produites, sélectionnées par les options suivantes. La variante par défaut pour pdp11-aout est l'option --omagic, tandis que pour d'autres cibles, --nmagic est la valeur par défaut. L'option --imagic est définie uniquement pour la cible pdp11-aout, tandis que les autres sont décrites ici telles qu'elles s'appliquent à la cible pdp11-aout.

    -N
    --omagic
    Marque la sortie comme "OMAGIC" (0407) dans l'en-tête a.out pour indiquer que le segment texte n'est pas à protéger en écriture et à partager. Comme les segments texte et données sont tous deux lisibles et inscriptibles, le segment données est alloué immédiatement après le segment texte. C'est le format le plus ancien pour les programmes exécutables PDP11 et c'est la valeur par défaut pour ld sur les systèmes Unix PDP11 depuis le début jusqu'à 2.11BSD.
    -n
    --nmagic
    Marque la sortie comme "NMAGIC" (0410) dans l'en-tête a.out pour indiquer que lorsque le fichier de sortie est exécuté, la partie texte sera en lecture seule et partageable entre tous les processus exécutant le même fichier. Cela implique de déplacer les zones de données jusqu'à la première limite de page de 8 Ko possible après la fin du texte. Cette option crée un format d'exécutable pur.
    -z
    --imagic
    Marque la sortie comme "IMAGIC" (0411) dans l'en-tête a.out pour indiquer que lorsque le fichier de sortie est exécuté, les zones de texte et de données du programme seront chargées dans des espaces d'adressage séparés à l'aide de la fonctionnalité de division des espaces d'instructions et de données de l'unité de gestion mémoire des modèles plus grands du PDP11. Cela double l'espace d'adressage disponible pour le programme. Le segment texte est à nouveau pur, protégé en écriture et partageable. La seule différence dans le format de sortie entre cette option et les autres, outre le nombre magique, est que les segments texte et données commencent tous deux à l'emplacement 0. L'option -z sélectionnait ce format dans 2.11BSD. Cette option crée un format d'exécutable séparé.
    --no-omagic
    Équivalent à --nmagic pour pdp11-aout.

    ENVIRONNEMENT

    Vous pouvez modifier le comportement de ld avec les variables d'environnement "GNUTARGET", "LDEMULATION" et "COLLECT_NO_DEMANGLE".

    "GNUTARGET" détermine le format objet des fichiers d'entrée si vous n'utilisez pas -b (ou son synonyme --format). Sa valeur doit être l'un des noms BFD pour un format d'entrée. S'il n'y a pas de "GNUTARGET" dans l'environnement, ld utilise le format naturel de la cible. Si "GNUTARGET" est défini sur "default", alors BFD tente de découvrir le format d'entrée en examinant les fichiers d'entrée binaires ; cette méthode réussit souvent, mais il existe des ambiguïtés potentielles, car il n'existe aucun moyen de garantir que le nombre magique utilisé pour spécifier les formats de fichiers objet soit unique. Cependant, la procédure de configuration de BFD sur chaque système place le format conventionnel pour ce système en premier dans la liste de recherche, de sorte que les ambiguïtés sont résolues en faveur de la convention.

    "LDEMULATION" détermine l'émulation par défaut si vous n'utilisez pas l'option -m. L'émulation peut affecter divers aspects du comportement du lieur, en particulier le script de lieur par défaut. Vous pouvez lister les émulations disponibles avec les options --verbose ou -V. Si l'option -m n'est pas utilisée et que la variable d'environnement "LDEMULATION" n'est pas définie, l'émulation par défaut dépend de la manière dont le lieur a été configuré.

    Normalement, le lieur supprime par défaut les symboles. Cependant, si "COLLECT_NO_DEMANGLE

    " est définie dans l'environnement, alors elle sera par défaut à ne pas démangler les symboles. Cette variable d'environnement est utilisée de manière similaire par le programme d'enveloppement de lieur "gcc". La valeur par défaut peut être remplacée par les options --demangle et --no-demangle.
