SHM_UNLINK(3P) Manuel du programmeur POSIX SHM_UNLINK(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

shm_unlink — supprimer un objet de mémoire partagée (TEMPS RÉEL)

SYNTAXE

#include <sys/mman.h>
int shm_unlink(const char *name);

DESCRIPTION

La fonction shm_unlink() supprime le nom de l'objet de mémoire partagée nommé par la chaîne pointée par name.

Si une ou plusieurs références à l'objet de mémoire partagée existent lorsque l'objet est dés-enregistré, le nom sera supprimé avant que shm_unlink() ne retourne, mais la suppression du contenu de l'objet mémoire sera différée jusqu'à ce que toutes les références ouvertes et mappées à l'objet de mémoire partagée aient été supprimées.

Même si l'objet continue d'exister après la dernière shm_unlink(), la réutilisation du nom entraînera ultérieurement que shm_open() se comportera comme si aucun objet de mémoire partagée de ce nom n'existait (c'est-à-dire que shm_open() échouera si O_CREAT n'est pas défini, ou créera un nouvel objet de mémoire partagée si O_CREAT est défini).

VALEUR DE RETOUR

En cas de succès, la valeur zéro est retournée. Sinon, la valeur -1 est retournée et errno est défini pour indiquer l'erreur. Si -1 est retourné, l'objet de mémoire partagée nommé ne sera pas modifié par cet appel de fonction.

ERREURS

La fonction shm_unlink() échouera si :

EACCES
La permission est refusée pour dés-enregistrer l'objet de mémoire partagée nommé.
ENOENT
L'objet de mémoire partagée nommé n'existe pas.

La fonction shm_unlink() peut échouer si :

ENAMETOOLONG

La longueur de l'argument name dépasse {_POSIX_PATH_MAX} sur les systèmes qui ne supportent pas l'option XSI ou dépasse {_XOPEN_PATH_MAX} sur les systèmes XSI, ou possède un composant de chemin plus long que {_POSIX_NAME_MAX} sur les systèmes qui ne supportent pas l'option XSI ou plus long que {_XOPEN_NAME_MAX} sur les systèmes XSI. Un appel à shm_unlink() avec un argument name contenant le même nom d'objet de mémoire partagée que celui utilisé précédemment dans un appel réussi à shm_open() ne provoquera pas d'erreur [ENAMETOOLONG].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR APPLICATION

Les noms des objets mémoire qui ont été alloués avec open() sont supprimés avec unlink() de la manière habituelle. Les noms des objets mémoire qui ont été alloués avec shm_open() sont supprimés avec shm_unlink(). Notez que l'objet mémoire réel n'est pas détruit tant que la dernière fermeture et le dernier démappage sur celui-ci n'ont pas eu lieu s'il était déjà en cours d'utilisation.

RATIONALE

Aucun.

ORIENTATIONS FUTURES

Une future version pourrait exiger que les fonctions shm_open() et shm_unlink() aient des sémantiques similaires aux opérations normales sur le système de fichiers.
