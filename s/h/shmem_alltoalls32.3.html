SHMEM_ALLTOALLS32(3) Open MPI SHMEM_ALLTOALLS32(3)

shmem_alltoall32(3), shmem_alltoall64(3), shmem_alltoalls32(3), shmem_alltoalls64(3) - routine collective où chaque PE échange une quantité fixe de données avec tous les autres PEs de l'ensemble Actif

SYNTAXE

C ou C++ :

#include <mpp/shmem.h>
void shmem_alltoall32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoall64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoalls32(void *target, const void *source,
  ptrdiff_t dst, ptrdiff_t sst,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoalls64(void *target, const void *source,
  ptrdiff_t dst, ptrdiff_t sst,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER dst, sst, nelems, PE_root, PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_ALLTOALL_SYNC_SIZE)
CALL SHMEM_ALLTOALL32(target, source, nelems,
& PE_start, logPE_stride, PE_size, fIpSync)
CALL SHMEM_ALLTOALL64(target, source, nelems,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_ALLTOALLS32(target, source, dst, sst, nelems,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_ALLTOALLS64(target, source, dst, sst, nelems,
& PE_start, logPE_stride, PE_size, pSync)

DESCRIPTION

Les routines shmem_alltoalls sont des routines collectives. Chaque PE de l'ensemble Actif échange nelems éléments de données indexés de 32 bits (pour shmem_alltoalls32) ou 64 bits (pour shmem_alltoalls64) avec tous les autres PEs de l'ensemble. Les deux pas, dst et sst, doivent être supérieurs ou égaux à 1. Le bloc j-ème envoyé de PE i à PE j est placé dans le bloc i-ème du dst objet de données sur PE j. Comme avec toutes les routines collectives OpenSHMEM, ces routines supposent que seuls les PEs de l'ensemble Actif appellent la routine. Si un PE n'appartenant pas à l'ensemble Actif appelle une routine collective OpenSHMEM, un comportement indéfini en résulte. Les valeurs des arguments dst, sst, nelems, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble Actif. Les mêmes objets de données dest et source, et le même tableau de travail pSync doivent être passés à tous les PEs de l'ensemble Actif. Avant tout appel de PE à une routine shmem_alltoalls, les conditions suivantes doivent exister (une synchronisation par une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Le tableau pSync sur tous les PEs de l'ensemble Actif n'est pas encore utilisé à partir d'un appel précédent à une routine shmem_alltoalls. L'objet de données dest sur tous les PEs de l'ensemble Actif est prêt à recevoir les données shmem_alltoalls. Au retour d'une routine shmem_alltoalls, ce qui suit est vrai pour le PE local : Son objet de données symétrique dest est entièrement mis à jour et les données ont été copiées hors de l'objet de données source. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

Les arguments sont les suivants :

Un objet de données symétrique avec l'un des types de données suivants :

shmem_alltoall32 : Tout type non-caractère qui
a une taille d'élément de 32 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.
shmem_alltoall64 : Tout type non-caractère qui a une taille d'élément
de 64 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.

target Un objet de données symétrique suffisamment grand pour recevoir le total combiné de nelems éléments de chaque PE de l'ensemble Actif.

source
Un objet de données symétrique qui contient nelems éléments de données pour chaque PE de l'ensemble Actif, ordonnés selon le PE de destination.
dst
Le pas entre les éléments consécutifs de l'objet de données dest. Le pas est mis à l'échelle par la taille de l'élément. Une valeur de 1 indique des données contiguës. dst doit être de type ptrdiff_t. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
sst
Le pas entre les éléments consécutifs de l'objet de données source. Le pas est mis à l'échelle par la taille de l'élément. Une valeur de 1 indique des données contiguës. sst doit être de type ptrdiff_t. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
nelems
Le nombre d'éléments à échanger pour chaque PE. nelems doit être de type size_t pour C/C++. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro virtuel le plus bas du PE de l'ensemble actif de PEs. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros virtuels de PE consécutifs de l'ensemble actif. log_PE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pSync
Un tableau de travail symétrique. En C/C++, pSync doit être de type long et de taille _SHMEM_ALLTOALL_SYNC_SIZE. En Fortran, pSync doit être de type entier et de taille SHMEM_ALLTOALL_SYNC_SIZE. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PEs de l'ensemble actif n'entre dans shmem_barrier().

Au retour d'une routine shmem_alltoalls, ce qui suit est vrai pour le PE local : Son objet de données symétrique dest est entièrement mis à jour et les données ont été copiées hors de l'objet de données source. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

Les valeurs des arguments PE_root, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble actif. Les mêmes objets de données cible et source, ainsi que le même tableau de travail pSync doivent être passés à tous les PEs de l'ensemble actif.

Avant que tout PE n'appelle une routine alltoall, vous devez vous assurer que les conditions suivantes existent (une synchronisation par une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Le tableau pSync sur tous les PEs de l'ensemble actif n'est pas en cours d'utilisation par un appel précédent à une routine alltoall. Le tableau cible sur tous les PEs de l'ensemble actif est prêt à recevoir les données alltoall.

NOTES

Les termes collectif et symétrique sont définis dans intro_shmem(3).

Toutes les routines SHMEM alltoall restaurent pSync à son contenu d'origine. Des appels multiples à des routines SHMEM qui utilisent le même tableau pSync ne nécessitent pas que pSync soit réinitialisé après le premier appel.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour par aucun PE de l'ensemble actif pendant que l'un des PEs participe au traitement d'une routine de diffusion SHMEM. Faites attention à éviter ces situations : Si le tableau pSync est initialisé à l'exécution, un certain type de synchronisation est nécessaire pour garantir que tous les PEs de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync peut être réutilisé lors d'une routine de diffusion SHMEM ultérieure uniquement si aucun des PEs de l'ensemble actif n'est encore en train de traiter un appel de routine SHMEM alltoall antérieur qui utilisait le même tableau pSync. En général, cela ne peut être garanti qu'en effectuant un certain type de synchronisation. Cependant, dans le cas spécial des routines SHMEM appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et alterner entre eux lors d'appels successifs.
