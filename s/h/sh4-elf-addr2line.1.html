ADDR2LINE(1) Outils de développement GNU ADDR2LINE(1)

NOM

addr2line - convertir les adresses ou le symbole+décalage en noms de fichier et numéros de ligne

SYNTAXE

addr2line [-a|--addresses]
[-b nom_bfd|--target=nom_bfd]
[-C|--demangle[=style]]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-e nom_fichier|--exe=nom_fichier]
[-f|--functions] [-s|--basename]
[-i|--inlines]
[-p|--pretty-print]
[-j|--section=nom]
[-H|--help] [-V|--version]
[adresse adresse ...]

DESCRIPTION

addr2line traduit les adresses ou le symbole+décalage en noms de fichier et numéros de ligne. Étant donné une adresse ou un symbole+décalage dans un exécutable ou un décalage dans une section d'un objet relocalisable, il utilise les informations de débogage pour déterminer quel nom de fichier et quel numéro de ligne y sont associés.

L'exécutable ou l'objet relocalisable à utiliser est spécifié avec l'option -e. Par défaut, il s'agit du fichier a.out. La section de l'objet relocalisable à utiliser est spécifiée avec l'option -j.

addr2line a deux modes de fonctionnement.

Dans le premier, des adresses hexadécimales ou symbole+décalage sont spécifiées sur la ligne de commande, et addr2line affiche le nom du fichier et le numéro de ligne pour chaque adresse.

Dans le second, addr2line lit des adresses hexadécimales ou symbole+décalage depuis l'entrée standard, et imprime le nom du fichier et le numéro de ligne pour chaque adresse sur la sortie standard. Dans ce mode, addr2line peut être utilisé dans un pipeline pour convertir des adresses choisies dynamiquement.

Le format de sortie est NOM_FICHIER:NUMERO_LIGNE. Par défaut, chaque adresse d'entrée génère une ligne de sortie.

Deux options peuvent générer des lignes supplémentaires avant chaque ligne NOM_FICHIER:NUMERO_LIGNE (dans cet ordre).

Si l'option -a est utilisée, alors une ligne avec l'adresse d'entrée est affichée.

Si l'option -f est utilisée, alors une ligne avec le NOM_FONCTION est affichée. C'est le nom de la fonction contenant l'adresse.

Une option peut générer des lignes supplémentaires après la ligne NOM_FICHIER:NUMERO_LIGNE.

Si l'option -i est utilisée et que le code à l'adresse donnée est présent en raison d'une inlining par le compilateur, alors des lignes supplémentaires sont affichées ensuite. Une ou deux lignes supplémentaires (si l'option -f est utilisée) sont affichées pour chaque fonction inline.

Alternativement, si l'option -p est utilisée, alors chaque adresse d'entrée génère une seule longue ligne de sortie contenant l'adresse, le nom de la fonction, le nom du fichier et le numéro de ligne. Si l'option -i a également été utilisée, alors les fonctions inlines seront affichées de la même manière, mais sur des lignes séparées, et préfixées par le texte (inlined by).

Si le nom du fichier ou le nom de la fonction ne peuvent pas être déterminés, addr2line affichera deux points d'interrogation à leur place. Si le numéro de ligne ne peut pas être déterminé, addr2line affichera 0.

Lorsque symbole+décalage est utilisé, +décalage est facultatif, sauf lorsque le symbole est ambigu avec un nombre hexadécimal. Les symboles résolus peuvent être tronqués ou non, sauf que les symboles non tronqués avec + ne sont pas autorisés.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes.

-a
--addresses
Affiche l'adresse avant le nom de la fonction, le fichier et les informations de numéro de ligne. L'adresse est imprimée avec un préfixe 0x pour l'identifier facilement.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objets est nom_bfd.
-C
--demangle[=style]
Décode (démangle) les noms de symboles de bas niveau en noms de niveau utilisateur. Outre la suppression de l'underscore initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument facultatif de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
-e nom_fichier
--exe=nom_fichier
Spécifie le nom de l'exécutable pour lequel les adresses doivent être traduites. Le fichier par défaut est a.out.
-f
--functions
Affiche les noms de fonctions ainsi que les informations de fichier et de numéro de ligne.
-s
--basenames
Affiche uniquement la base de chaque nom de fichier.
-i
--inlines
Si l'adresse appartient à une fonction qui a été inlinée, les informations source pour tous les scopes englobants jusqu'à la première fonction non inlinée seront également imprimées. Par exemple, si "main" inliné "callee1" qui inliné "callee2", et que l'adresse provient de "callee2", les informations source pour "callee1" et "main" seront également imprimées.
-j
--section
Lit les décalages par rapport à la section spécifiée au lieu des adresses absolues.
-p
--pretty-print
Rend la sortie plus conviviale : chaque emplacement est imprimé sur une ligne. Si l'option -i est spécifiée, les lignes pour tous les scopes englobants sont préfixées par (inlined by).
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Les formats de mangling des noms permettant un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace pile disponible sur la machine hôte, provoquant une faute de mémoire. La limite tente d'éviter cela en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, un épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

Notez que cette option n'est effective que si l'option -C ou --demangle a été activée.

@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option originale @fichier. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. Tout caractère (y compris un antislash) peut être inclus en préfixant le caractère à inclure par un antislash. Le fichier peut contenir lui-même d'autres options @fichier ; toutes ces options seront traitées

récursivement.
