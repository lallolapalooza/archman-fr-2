NOM

shikane - fichier de configuration

DESCRIPTION

shikane utilise le format de fichier TOML pour son fichier de configuration et contient un tableau de profils. Chaque profil est une table contenant un tableau de tables output.

Les mots « output », « display » et « monitor » peuvent être utilisés de manière interchangeable. Dans le texte ci-dessous, cependant, une distinction est faite entre « display » et « output ». Un « display » fait référence à un moniteur actuellement connecté et un « output » fait référence à une table dans le fichier de configuration. Il en va de même pour « mode » et « mode » respectivement. (Veuillez noter le poids de la police.)

shikane sélectionne automatiquement les profils possibles au démarrage et lorsqu'un changement dans l'ensemble des écrans actuellement connectés se produit. Un profil est pris en considération si chaque écran actuellement connecté peut être mis en correspondance avec au moins un output et qu'aucun output n'est sans correspondance.

Un écran correspond à un output si :

•
le paramètre search correspond aux propriétés de l'écran (voir également la section CHAMP DE CHAMPS OUTPUT ci-dessous)
•
ET l'écran prend en charge le mode spécifié dans la table output.

Après avoir assemblé une liste de profils possibles, shikane génère toutes les variantes de chaque profil. Une fois toutes les variantes vérifiées et triées par exactitude, shikane essaie de les appliquer une par une jusqu'à ce que l'une réussisse ou qu'il n'y ait plus de variantes à essayer.

Les variantes sont des versions légèrement différentes du même profil.

Par exemple, un écran donné dispose d'un ensemble de modes pris en charge : 1920x1080@60Hz et 1920x1080@50Hz. Si le mode dans le fichier config.toml est spécifié comme « 1920x1080 », les deux modes correspondent à la spécification. Au lieu de choisir un seul mode et de l'utiliser, shikane prend les deux en compte en générant deux variantes basées sur le même profil. Une variante utilise le mode 1920x1080@60Hz et l'autre variante utilise le mode 1920x1080@50Hz.

Il en va de même pour le paramètre de recherche. Si plusieurs combinaisons (écran,output,mode) sont possibles, shikane génère des variantes avec toutes ces combinaisons.

Vous n'avez pas besoin d'écrire le fichier de configuration à la main. Vous pouvez utiliser n'importe quel outil pour organiser les écrans comme vous le souhaitez, puis utiliser la commande export de shikanectl(1). Elle générera la configuration pour vous.

FORMAT

timeout = timeout
Optionnel. shikane attendra le timeout spécifié (en millisecondes) chaque fois qu'un changement est détecté. Généralement, vous ne devriez pas le définir car cela ralentit shikane. Il est par défaut à 0.
[[profile]]
Optionnel. Démarre une nouvelle table de profil. Un nom doit être spécifié. Voir CHAMP DE CHAMPS PROFIL pour les détails.

CHAMP DE CHAMPS PROFIL

name = "name"
Obligatoire. Spécifie le nom du profil.
[[profile.output]]
Obligatoire. Ajoute une table output au profil. Contient les paramètres utilisés pour configurer un écran. Voir CHAMP DE CHAMPS OUTPUT pour les détails.

Sur sway(1) par exemple, les noms et descriptions des écrans peuvent être obtenus via swaymsg -t get_outputs.

exec = [ "command", ... ]
Optionnel. Un tableau exec contient un ensemble de commandes qui sont exécutées lorsque le profil a été appliqué avec succès. L'ordre d'exécution n'est pas garanti d'être préservé. Le nom du profil peut être récupéré à partir de la variable d'environnement $SHIKANE_PROFILE_NAME.

CHAMP DE CHAMPS OUTPUT

Un écran a, entre autres, les attributs name, vendor, model, serialnumber et description et peut ressembler à ceci : « DP-1 », « Société Foo », « FooHD-24 », « 12345678 », « Quelque chose Foo Quelque chose Bar »

search = "pattern"

search = "[kind]pattern"

search = "[[attrs]kind]pattern"

search = [ "[[attrs]kind]pattern", ... ]
Obligatoire. Ce champ se compose de 3 parties. La liste d'attributs attrs au début, le type de recherche kind au milieu, et le pattern à la fin.

La liste d'attributs attrs définit quels attributs seront comparés au pattern et comment ils sont pondérés. C'est une séquence de lettres de l'ensemble {dnmvs}. Les lettres correspondent aux premières lettres des attributs listés ci-dessus. Chaque attribut ne doit pas être utilisé plus d'une fois par champ search. Le premier attribut a le poids le plus élevé/meilleur, le dernier attribut a le poids le plus bas/pire. Pour qu'une seule recherche soit considérée comme applicable, tous les attributs doivent correspondre au pattern.

Le type de recherche kind peut être l'un de {=/%}. Les 3 types de recherche — regex (/), sous-chaîne (%), texte complet (=) — définissent comment le pattern est comparé à chaque attribut dans la liste attrs. Avec la comparaison de texte complet, les attributs donnés sont comparés au pattern pour égalité. Avec la comparaison de sous-chaîne, les attributs donnés doivent contenir le pattern comme sous-chaîne. Le poids est calculé en divisant les longueurs des chaînes pattern et attribut. Des longueurs égales classeront de la même manière que la comparaison de texte complet. Avec la comparaison regex, le pattern est interprété comme une expression régulière. La comparaison regex sera toujours classée plus bas que les deux autres types de recherche.

La liste d'attributs et le type de recherche sont facultatifs. Si le type de recherche n'est pas spécifié, il est par défaut une comparaison de texte complet et shikane essaie de trouver au moins un attribut correspondant.

Alternativement, plusieurs recherches, jusqu'à un maximum de 5, peuvent être spécifiées dans un tableau.

enable = true | false
Obligatoire. Active ou désactive l'écran correspondant.
exec = [ "command", ... ]
Optionnel. Un tableau exec contient un ensemble de commandes qui sont exécutées lorsque le profil a été appliqué avec succès. L'ordre d'exécution n'est pas garanti d'être préservé. Le nom de l'écran peut être récupéré à partir de la variable d'environnement $SHIKANE_OUTPUT_NAME.

Les options mode, position, scale, transform et adaptive_sync ne changeront les propriétés respectives de l'écran que si elles sont spécifiées (par exemple, le scaling d'un écran ne sera pas modifié si le champ scale n'est pas présent).

mode = "best" | "preferred"

mode = "[!]widthxheight[@rate[Hz]]"

mode = { width = width, height = height, refresh = rate[, custom = true | false] }
Optionnel. Configure l'écran correspondant pour utiliser le mode correspondant. Les modes sont une combinaison de width et height (en pixels) et d'un taux de rafraîchissement rate (en Hz) que votre écran peut être configuré pour utiliser. Le taux de rafraîchissement rate peut également être un nombre à virgule flottante. Un écran ne sera pas mis en correspondance avec un output si l'écran ne prend pas en charge le mode spécifié.

Un mode paramétré peut éventuellement être déclaré comme personnalisé en ajoutant un point d'exclamation (!). Dans ce cas, shikane n'essaiera pas de trouver un mode avec les mêmes paramètres et enverra simplement les valeurs fournies au compositeur.

Définir le mode sur best ou preferred demande à shikane de choisir lui-même le mode. Le mode best est déterminé par shikane comme le mode ayant le nombre de pixels, la largeur, la hauteur et le taux de rafraîchissement les plus élevés. La plupart des écrans annoncent un mode qu'ils préfèrent. Si mode est défini sur preferred, shikane sélectionnera le mode préféré s'il existe. Sinon, le meilleur mode sera choisi en secours.

position = "x,y"
Optionnel. Place l'écran à la position spécifiée dans l'espace de coordonnées global.
scale = facteur
Optionnel. Redimensionne l'écran par le facteur flottant spécifié.
transform = "transform"
Optionnel. Définit la transformation de l'écran. Peut être l'une des valeurs suivantes : 90, 180, 270 pour une rotation ; ou flipped, flipped-90, flipped-180, flipped-270 pour un retournement et une rotation ; ou normal pour aucune transformation.
adaptive_sync = true | false
Optionnel. Active ou désactive la synchronisation adaptative pour l'écran (également connue sous le nom de VRR, Variable Refresh Rate).

EXEMPLES

Les indentations ne sont pas nécessaires et sont utilisées ici uniquement pour illustrer la hiérarchie.

[[profile]]
name = "Société Foo avec un écran vertical"
    [[profile.output]]
    search = "v=Société Foo"
    enable = true
    mode = "1920x1080@50Hz"
    position = "0,0"
    scale = 1.3
    [[profile.output]]
    search = "n/HDMI-[ABC]-[1-9]"
    enable = true
    exec = [ "echo Ceci est la sortie $SHIKANE_OUTPUT_NAME" ]
    position = "1920,0"
    transform = "270"
        [profile.output.mode]
        width = 2560
        height = 1440
        refresh = 75
[[profile]]
name = "DP personnalisé-[1-9] retourné"
exec = [ "echo Ceci est un écran inhabituel" ]
    [[profile.output]]
    search = "/DP-[1-9]"
    enable = true
    transform = "flipped"
    position = "0,0"
    mode = "!2000x1500@55.194Hz"

Un ordinateur portable possède un écran intégré qui est toujours connecté.

[[profile]]
name = "intégré portable"
    [[profile.output]]
    search = "eDP-1"
    enable = true
[[profile]]
name = "pas d'intégré + HDMI"
    [[profile.output]]
    search = "n=eDP-1"
    enable = false
    [[profile.output]]
    search = "n=HDMI-A-1"
    mode = "best"
    enable = true

shikane vous permet de spécifier plusieurs recherches. De cette façon, les profils peuvent être aussi spécifiques que possible.

[[profile]]
name = "configuration maison"
    [[profile.output]]
    search = "n=eDP-1"
    enable = false
    [[profile.output]]
    search = [ "n=HDMI-A-1", "s=1234VBAM", "m=1QX04Z", "v=société spécifique" ]
    enable = true
    [[profile.output]]
    search = "smv=1234abcd"
    enable = true

Sur sway(1) par exemple, exec peut être utilisé pour déplacer des espaces de travail vers l'écran désiré :

[[profile]]
name = "double moniteur"
exec = [
    "swaymsg workspace 1, move workspace to eDP-1",
    "swaymsg workspace 2, move workspace to DP-1" ]
output = [
    {search = "eDP-1", enable = true},
    {search = "DP-1", enable = true} ]

shikane fournit la variable $SHIKANE_PROFILE_NAME dans l'environnement des processus exécutés du tableau profile.exec et la variable $SHIKANE_OUTPUT_NAME dans l'environnement des processus output.exec. Si vous utilisez sway(1), la dernière variable est particulièrement utile en conjonction avec swayws.

[[profile]]
name = "profil générique"
exec = ["notify-send shikane \"Le profil $SHIKANE_PROFILE_NAME a été appliqué\""]
    [[profile.output]]
    search = "/DP-[1-9]"
    enable = true
    exec = ["swayws range --numeric 1 5 $SHIKANE_OUTPUT_NAME"]
    [[profile.output]]
    search = "n%HDMI-"
    enable = true
    mode = "preferred"
    exec = ["swayws range --numeric 6 10 $SHIKANE_OUTPUT_NAME"]
