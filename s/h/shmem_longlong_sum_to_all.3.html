DESCRIPTION

Les routines de réduction de la mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, cela entraîne un comportement indéfini.

La variable nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

target
L'objet de données entier accessible à distance à mettre à jour sur le PE distant. Si vous utilisez C/C++, le type de target doit correspondre à celui implicite dans la section SYNTAXE. Si vous utilisez le compilateur Fortran, il doit être de type entier avec une taille d'élément de 4 octets pour SHMEM_INT4_ADD et de 8 octets pour SHMEM_INT8_ADD.
valeur
La valeur à ajouter atomiquement à target. Si vous utilisez C/C++, le type de valeur doit correspondre à celui implicite dans la section SYNTAXE. Si vous utilisez Fortran, il doit être de type entier avec une taille d'élément égale à celle de target.
pe
Un entier qui indique le numéro de PE sur lequel target doit être mis à jour. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
target
Un tableau symétrique de longueur nreduce éléments pour recevoir les résultats
des opérations de réduction.
Le type de données de target varie selon la version de la routine de réduction
appelée et la langue utilisée. Lors de l'appel depuis C/C++, référez-vous à la
section SYNTAXE pour les informations sur les types de données.
Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :

shmem_comp4_sum_to_all : COMPLEX(KIND=4).

shmem_comp8_sum_to_all : Complexe. Si vous utilisez Fortran, il doit s'agir d'une
valeur complexe par défaut.

shmem_int4_sum_to_all : INTEGER(KIND=4).

shmem_int8_sum_to_all : Entier. Si vous utilisez Fortran, il doit s'agir d'un
entier par défaut.

shmem_real4_sum_to_all : REAL(KIND=4).

shmem_real8_sum_to_all : Réel. Si vous utilisez Fortran, il doit s'agir d'un
réel par défaut.
shmem_real16_sum_to_all : Réel. Si vous utilisez Fortran, il doit s'agir d'un
réel par défaut.
source
Un tableau symétrique, de longueur nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que target.
nreduce
Le nombre d'éléments dans les tableaux target et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que target. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PE de l'ensemble actif n'appelle la routine de réduction.

shmem_longlong_sum_to_all(3) — Arch manual pages

SYNOPSIS

Collective Reduction routines

All PEs in the active set execute the same call statement and all PEs complete the call statement.

    int shmem_longlong_sum_to_all(long long *target, const long long *source, int nreduce, int PE_start, int logPE_stride, int PE_size, long long *pWrk, long long *pSync);
    void shmem_longlong_sum_to_all(long long *target, const long long *source, int nreduce, int PE_start, int logPE_stride, int PE_size, long long *pWrk, long long *pSync);

DESCRIPTION

These routines compute the sum of the elements in the source array on the specified PE subset and place the result in the target array on all PEs in the active set. The elements are of type long long. The arrays are accessed with the same stride on all PEs in the active set.

The arguments are defined as follows:

target
Pointer to the target array that will contain the sum. The array must be large enough to contain nreduce elements.

source
Pointer to the source array. The array must be large enough to contain nreduce elements.

nreduce
The number of elements in the source and target arrays to be reduced. This value must be greater than or equal to 1.

PE_start
The starting PE index for the reduction. This value must be less than the total number of PEs.

logPE_stride
The log of the stride in PEs between elements of the source and target arrays. For example, if logPE_stride is 1, then PE 0 accesses element 0, PE 2 accesses element 1, PE 4 accesses element 2, etc.

PE_size
The number of PEs that will participate in the reduction. This value must be less than or equal to the total number of PEs.

pWrk
Pointer to a work array. The size of this array must be at least SHMEM_LONG_LONG_REDUCE_MIN_WRKDATA_SIZE.

pSync
Pointer to a synchronization array. This array must be initialized to SHMEM_SYNC_VALUE before the call. The size of this array must be at least SHMEM_REDUCE_SYNC_SIZE.

The values of arguments nreduce, PE_start, logPE_stride, and PE_size must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_longlong_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_longlong_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_longlong_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_longlong_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
