NOM

strip - supprime les symboles et autres données des fichiers objets

SYNOPSIS

strip [-F nom_bfd |--target=nom_bfd]
[-I nom_bfd |--input-target=nom_bfd]
[-O nom_bfd |--output-target=nom_bfd]
[-s|--strip-all]
[-S|-g|-d|--strip-debug]
[--strip-dwo]
[-K nom_symbole|--keep-symbol=nom_symbole]
[-M|--merge-notes][--no-merge-notes]
[-N nom_symbole |--strip-symbol=nom_symbole]
[-w|--wildcard]
[-x|--discard-all] [-X |--discard-locals]
[-R nom_section |--remove-section=nom_section]
[--keep-section=motif_section]
[--remove-relocations=motif_section]
[--strip-section-headers]
[-o fichier] [-p|--preserve-dates]
[-D|--enable-deterministic-archives]
[-U|--disable-deterministic-archives]
[--keep-section-symbols]
[--keep-file-symbols]
[--only-keep-debug]
[-v |--verbose] [-V|--version]
[--help] [--info]
fichier_objet...

DESCRIPTION

GNU strip supprime tous les symboles des fichiers objets fichier_objet. La liste des fichiers objets peut inclure des archives. Au moins un fichier objet doit être fourni.

strip modifie les fichiers nommés dans ses arguments, plutôt que d'écrire des copies modifiées sous des noms différents.

OPTIONS

-F nom_bfd
--target=nom_bfd
Traite le fichier_objet d'origine comme un fichier avec le format de code objet nom_bfd, et le réécrit dans le même format.
--help
Affiche un résumé des options de strip et quitte.
--info
Affiche une liste montrant tous les formats d'architecture et d'objet disponibles.
-I nom_bfd
--input-target=nom_bfd
Traite le fichier_objet d'origine comme un fichier avec le format de code objet nom_bfd.
-O nom_bfd
--output-target=nom_bfd
Remplace fichier_objet par un fichier au format de sortie nom_bfd.
-R nom_section
--remove-section=nom_section
Supprime toute section nommée nom_section du fichier de sortie, en plus des sections qui seraient autrement supprimées. Cette option peut être donnée plus d'une fois. Notez qu'utiliser cette option de manière inappropriée peut rendre le fichier de sortie inutilisable. Le caractère générique * peut être donné à la fin de nom_section. Si c'est le cas, toute section commençant par nom_section sera supprimée.

Si le premier caractère de motif_section est le point d'exclamation (!), alors les sections correspondantes ne seront pas supprimées même si une utilisation antérieure de --remove-section sur la même ligne de commande les supprimerait autrement. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=motif_section
Lors de la suppression de sections du fichier de sortie, conserve les sections correspondant à motif_section.
--remove-relocations=motif_section
Supprime les relocations du fichier de sortie pour toute section correspondant à motif_section. Cette option peut être donnée plus d'une fois. Notez qu'utiliser cette option de manière inappropriée peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans motif_section. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de motif_section est le point d'exclamation (!), alors les sections correspondantes n'auront pas leurs relocations supprimées même si une utilisation antérieure de --remove-relocations sur la même ligne de commande entraînerait autrement la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations pour les sections correspondant au motif '.text.*', mais ne supprimera pas les relocations pour la section '.text.foo'.

--strip-section-headers
Supprime les en-têtes de section. Cette option est spécifique aux fichiers ELF. Implique --strip-all et --merge-notes.
-s
--strip-all
Supprime tous les symboles.
-g
-S
-d
--strip-debug
Supprime uniquement les symboles de débogage.
--strip-dwo
Supprime le contenu de toutes les sections DWARF .dwo, laissant les sections de débogage restantes et tous les symboles intacts. Voir la description de cette option dans la section objcopy pour plus d'informations.
--strip-unneeded
Supprime tous les symboles qui ne sont pas nécessaires au traitement des relocations en plus des symboles et sections de débogage supprimés par --strip-debug.
-K nom_symbole
--keep-symbol=nom_symbole
Lors de la suppression de symboles, conserve le symbole nom_symbole même s'il serait normalement supprimé. Cette option peut être donnée plus d'une fois.
-M
--merge-notes
--no-merge-notes
Pour les fichiers ELF, tente (ou n'essaie pas) de réduire la taille des sections de type SHT_NOTE en supprimant les notes dupliquées. Par défaut, il tente cette réduction, sauf si des informations de débogage ou DWO sont supprimées.
-N nom_symbole
--strip-symbol=nom_symbole
Supprime le symbole nom_symbole du fichier source. Cette option peut être donnée plus d'une fois, et peut être combinée avec d'autres options de strip autres que -K.
-o fichier
Place la sortie strippée dans fichier, plutôt que de remplacer le fichier existant. Lorsque cet argument est utilisé, un seul argument fichier_objet peut être spécifié.
-p
--preserve-dates
Conserve les dates d'accès et de modification du fichier.
-D
--enable-deterministic-archives
Fonctionne en mode déterministe. Lors de la copie des membres d'archive et de l'écriture de l'index d'archive, utilise zéro pour les UID, GID, horodatages, et utilise des modes de fichier cohérents pour tous les fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec l'option -U, ci-dessous.

-U
--disable-deterministic-archives

NAME

sh4-elf-strip

discard symbols from object files

SYNOPSIS

sh4-elf-strip [-F emulation] [-I] [--strip-symbol=symbol] [--strip-data] [--strip-unneeded] [--strip-debug] [--strip-drectve] [--strip-branches] [--strip-all] [--strip-local-codes] [--strip-non-global] [--strip-symbols] [--strip-implied-sun] [--strip-unneeded-groups] [-g | --strip-debug] [-N] [--no-discard-locals] [-R section] [--remove-section=section] [-K symbol] [--keep-symbol=symbol] [-U symbol] [--strip-symbol=symbol] [-w | --wildcard] [-x | --discard-all] [-X | --discard-locals] [--keep-section-symbols] [--keep-file-symbols] [--only-keep-debug] [-V | --version] [-v | --verbose] [--help] [--info] [objfile...

DESCRIPTION

The strip utility removes symbols from object files. It can also remove sections from object files.

This is useful for reducing the size of executables and object files. It is also useful for protecting proprietary code, by removing symbols that might help in reverse-engineering.

By default, strip removes all symbols from the object files. If you want to remove only certain symbols, you can use the --strip-symbol or --keep-symbol options.

The following options are available:

OPTIONS

-F emulation
--emulation=emulation
Use the specified emulation when processing the object files. This is useful when dealing with object files that have been created for a different architecture or operating system than the host system.
-I
--strip-implied-sun
Strip symbols that are implied by SunOS conventions. This is often used to strip symbols that are not needed for normal operation.
--strip-unneeded-groups
Strip symbols that are unneeded from group sections. This option is only relevant for object files that use GNU extensions for section grouping.
--strip-local-codes
Strip local symbols that are not needed. This option is often used to reduce the size of object files by removing symbols that are only used internally by the compiler.
--strip-non-global
Discard symbols that are not global. This includes local symbols, section symbols, and file symbols.
--strip-symbols
Discard all symbols. This is equivalent to the default behavior of strip.
--strip-drectve
Strip directives from Microsoft-style PE object files.
--strip-branches
Strip branch analysis information from object files. This is useful for reducing the size of executables that have been compiled with debugging information enabled.
--strip-data
Remove data symbols from object files. This option is useful for reducing the size of executables and object files by removing symbols that are not needed for program execution.
--strip-debug
Remove debugging symbols from object files. This option is useful for reducing the size of executables and object files by removing symbols that are only used for debugging purposes.
--strip-unneeded
Remove symbols that are not needed for relocation processing. This option is useful for reducing the size of executables and object files by removing symbols that are not required for the linker to resolve references.
--strip-all
Remove all symbols from object files. This is equivalent to the default behavior of strip.
--strip-local-codes
Remove compiler-generated local symbols. (These usually start with L or ..)
-g
--strip-debug
Remove debugging symbols from object files. This option is useful for reducing the size of executables and object files by removing symbols that are only used for debugging purposes.
-N
--no-discard-locals
Do not discard compiler-generated local symbols. This option is the inverse of the -D option, above: when copying archive members and writing the archive index, use their actual UID, GID, timestamp, and file mode values.

This is the default unless binutils was configured with --enable-deterministic-archives.

-R section
--remove-section=section
Remove the specified section from the object file. This option can be used multiple times to remove multiple sections.
-K symbol
--keep-symbol=symbol
Keep the specified symbol in the object file. This option can be used multiple times to keep multiple symbols.
-U symbol
--strip-symbol=symbol
Strip the specified symbol from the object file. This option can be used multiple times to strip multiple symbols.
-w
--wildcard
Permit regular expressions in symbolnames used in other command line options. The question mark (?), asterisk (*), backslash (\) and square brackets ([]) operators can be used anywhere in the symbol name. If the first character of the symbol name is the exclamation point (!) then the sense of the switch is reversed for that symbol. For example: 
-w -K !foo -K fo*

would cause strip to only keep symbols that start with the letters "fo", but to discard the symbol "foo".

-x
--discard-all
Remove non-global symbols.
-X
--discard-locals
Remove compiler-generated local symbols. (These usually start with L or ..)
--keep-section-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying section names, which would otherwise get stripped.
--keep-file-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying source file names, which would otherwise get stripped.
--only-keep-debug
Strip a file, emptying the contents of any sections that would not be stripped by --strip-debug and leaving the debugging sections intact. In ELF files, this preserves all the note sections in the output as well.

Note - the section headers of the stripped sections are preserved, including their sizes, but the contents of the section are discarded. The section headers are preserved so that other tools can match up the debuginfo file with the real executable, even if that executable has been relocated to a different address space.

The intention is that this option will be used in conjunction with --add-gnu-debuglink to create a two part executable. One a stripped binary which will occupy less space in RAM and in a distribution and the second a debugging information file which is only needed if debugging abilities are required. The suggested procedure to create these files is as follows:

1.<Link the executable as normal. Assuming that it is called>
"foo" then...
1.<Run "objcopy --only-keep-debug foo foo.dbg" to>
create a file containing the debugging info.
1.<Run "objcopy --strip-debug foo" to create a>
stripped executable.
1.<Run "objcopy --add-gnu-debuglink=foo.dbg foo">
to add a link to the debugging info into the stripped executable.

Note---the choice of ".dbg" as an extension for the debug info file is arbitrary. Also the "--only-keep-debug" step is optional. You could instead do this:

1.<Link the executable as normal.>
1.<Copy "foo" to "foo.full">
1.<Run "strip --strip-debug foo">
1.<Run "objcopy --add-gnu-debuglink=foo.full foo">

i.e., the file pointed to by the --add-gnu-debuglink can be the full executable. It does not have to be a file created by the --only-keep-debug switch.

Note---this switch is only intended for use on fully linked files. It does not make sense to use it on object files where the debugging information may be incomplete. Besides the gnu_debuglink feature currently only supports the presence of one filename containing debugging information, not multiple filenames on a one-per-object-file basis.

-V
--version
Show the version number for strip.
-v
--verbose
Verbose output: list all object files modified. In the case of archives, strip -v lists all members of the archive.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
