SHMEM_SHORT_XOR_TO_ALL(3) Open MPI SHMEM_SHORT_XOR_TO_ALL(3)

shmem_comp4_xor_to_all(3), shmem_int_xor_to_all(3), shmem_int4_xor_to_all(3), shmem_int8_xor_to_all(3), shmem_long_xor_to_all(3), shmem_longlong_xor_to_all(3), shmem_short_xor_to_all(3) - Effectue une opération XOR bit à bit sur des tableaux symétriques sur l'ensemble actif de PEs.

SYNTAXE

C ou C++ :

#include <mpp/shmem.h>
void shmem_int_xor_to_all(int *target, const int *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  int *pWrk, long *pSync)
void shmem_long_xor_to_all(long *target, const long *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  long *pWrk, long *pSync)
void shmem_longlong_xor_to_all(long long *target,
  const long long *source, int nreduce, int PE_start, int logPE_stride,
  int PE_size, long long *pWrk, long *pSync)
void shmem_short_xor_to_all(short *target, const short *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  short *pWrk, long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER pSync(SHMEM_REDUCE_SYNC_SIZE)
INTEGER nreduce, PE_start, logPE_stride, PE_size
CALL SHMEM_COMP4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT8_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)

DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PEs virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PEs de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PEs de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PEs de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie avec la version de la routine de réduction appelée et la langue utilisée. Lors de l'appel depuis C/C++, se référer à la section SYNTAXE pour les informations sur les types de données. Lors de l'appel depuis Fortran, les types de données de cible sont les suivants :
shmem_comp8_xor_to_all:** Complexe, avec une taille d'élément égale à deux valeurs réelles de 8 octets
shmem_comp4_xor_to_all:** Complexe, avec une taille d'élément égale à deux valeurs réelles de 4 octets

shmem_int8_xor_to_all:** Entier, avec une taille d'élément de 8 octets

shmem_int4_xor_to_all:** Entier, avec une taille d'élément de 4 octets

shmem_real8_xor_to_all:** Réel, avec une taille d'élément de 8 octets

shmem_real4_xor_to_all:** Réel, avec une taille d'élément de 4 octets

source
Un tableau symétrique, de longueur nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif de PEs. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PEs de l'ensemble actif n'entre dans la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble actif. Les mêmes tableaux cible et source, et les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PEs de l'ensemble actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer des conditions suivantes (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : les tableaux pWrk et pSync sur tous les PEs de l'ensemble actif ne sont plus utilisés à partir d'un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PEs de l'ensemble actif est prêt à accepter les résultats de la réduction.

Au retour d'une routine de réduction, les conditions suivantes sont vraies pour le PE local : le tableau cible est mis à jour. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs dans pSync avant de retourner, de sorte qu'un tampon pSync particulier n'a besoin d'être initialisé que lors de sa première utilisation.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE de l'ensemble actif pendant que l'un des PEs participe au traitement d'une routine de réduction SHMEM. Soyez prudent dans les situations suivantes : Si le tableau pSync est initialisé au moment de l'exécution, un type de synchronisation est nécessaire pour garantir que tous les PEs de l'ensemble de travail ont initialisé pSync avant que l'un d'entre eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PEs de l'ensemble actif ne traite encore un appel de routine de réduction précédent qui utilisait les mêmes tableaux pSync ou pWrk. En général, cela ne peut être garanti qu'en effectuant un type de synchronisation. Cependant, dans le cas spécial des routines de réduction appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors d'appels successifs.

EXEMPLES

Exemple 1 : Cet exemple Fortran initialise statiquement le tableau pSync et calcule le OU exclusif de la variable FOO sur tous les PEs pairs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOXOR, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOXOR, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_XOR_TO_ALL(FOOXOR, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOXOR
ENDIF

shmem_short_xor_to_all(3) — Arch manual pages

SYNOPSIS

#include <mpi.h>
#include <shmem.h>

void shmem_short_xor_to_all(
    short *target,
    const short *source,
    size_t nlong,
    int PE_min,
    int PE_max,
    int logPE_stride,
    shmem_op_t op
);

DESCRIPTION

The shmem_short_xor_to_all routine performs a one-way, all-to-all XOR sum operation on an array of short integers. The operation consists of XORing elements from the source array on all processing elements (PEs) within the specified range [PE_min, PE_max] with a stride of logPE_stride, and placing the result into the target array on each PE.

The data type of the elements is short.

The number of elements in the source and target arrays is specified by nlong.

The PEs involved in the operation are those PE indices `i’ such that PE_min <= i <= PE_max and i = PE_min + k * 2logPE_stride for some non-negative integer k.

The op parameter is not used in this routine and is reserved for future extensions.

NOTES

The symmetric heap memory region must be allocated using shmem_malloc or shmem_align_malloc. The size must be sufficient to hold nlong elements of type short.

The shmem_short_xor_to_all routine is a collective operation. All PEs must call this routine.

The behavior is undefined if any PE is included in more than one symmetric heap region access. Behavior is also undefined if a PE attempts to access data from a symmetric heap region that has not been allocated.

The shmem_short_xor_to_all routine uses internal synchronization to ensure that all data is available and placed correctly. Specifically, it ensures that all source data has been received by the target PEs before the target data is updated.

EXAMPLES

The following example demonstrates the use of shmem_short_xor_to_all:

    // Assume comm_world is the MPI communicator and has size 4.
    // Assume PE 0 has short data [1, 2, 3]
    // Assume PE 1 has short data [4, 5, 6]
    // Assume PE 2 has short data [7, 8, 9]
    // Assume PE 3 has short data [10, 11, 12]

    short target[3];
    short source[3];
    long pwrk[MY_ARRAY_SIZE]; // work array
    long psync[MY_ARRAY_SIZE]; // sync array

    // Initialize source array (example values)
    source[0] = my_pe() + 1;
    source[1] = my_pe() + 2;
    source[2] = my_pe() + 3;

    // Initialize target array (can be anything, will be overwritten)
    target[0] = 0;
    target[1] = 0;
    target[2] = 0;

    // Perform the all-to-all XOR sum
    // Elements are 3 shorts per PE.
    // PE range is all PEs (0 to 3).
    // Stride is 1 (logPE_stride = 0).
    shmem_short_xor_to_all(target, source, 3, 0, shmem_n_pes() - 1, 0, 0);

    // After the call, target will contain the XOR sum:
    // target[0] = 1 ^ 4 ^ 7 ^ 10
    // target[1] = 2 ^ 5 ^ 8 ^ 11
    // target[2] = 3 ^ 6 ^ 9 ^ 12

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_xor_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_xor_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_xor_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
