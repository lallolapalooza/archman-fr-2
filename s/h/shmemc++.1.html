oshcc, oshcxx, oshc++, oshfort, shmemcc, shmemcxx, shmemc++, shmemfort — Compilateurs wrappers pour OpenSHMEM

SYNTAX

oshcc [--showme | --showme:compile | --showme:link] ...

oshcxx [--showme | --showme:compile | --showme:link] ...

oshc++ [--showme | --showme:compile | --showme:link] ...

oshfort [--showme | --showme:compile | --showme:link] ...

shmemcc [--showme | --showme:compile | --showme:link] ...

shmemcxx [--showme | --showme:compile | --showme:link] ...

shmemc++ [--showme | --showme:compile | --showme:link] ...

shmemfort [--showme | --showme:compile | --showme:link] ...

OPTIONS

Les options ci-dessous s'appliquent à tous les compilateurs wrappers :

•
--showme : Cette option se présente sous plusieurs variantes (voir ci-dessous). Aucune des variantes n'invoque le compilateur sous-jacent ; elles fournissent toutes des informations sur la manière dont le compilateur sous-jacent aurait été invoqué si --showme n'avait pas été utilisé. L'option basique --showme affiche la ligne de commande qui serait exécutée pour compiler le programme.

NOTE :

Si un argument autre qu'un nom de fichier est passé sur la ligne de commande, l'option --showme n'affichera pas de flags supplémentaires. Par exemple, "oshcc --showme et oshcc --showme my_source.c montreront tous les flags fournis par le wrapper. Mais oshcc --showme -v ne montrera que le nom du compilateur sous-jacent et -v.
  • --showme:compile : Affiche les flags du compilateur qui auraient été fournis au compilateur sous-jacent.
  • --showme:link : Affiche les flags de l'éditeur de liens qui auraient été fournis au compilateur sous-jacent.
  • --showme:command : Affiche la commande du compilateur sous-jacent (qui peut être un ou plusieurs jetons).
  • --showme:incdirs : Affiche une liste de répertoires, séparés par des espaces (mais par ailleurs non décorés), que le compilateur wrapper aurait fournis au compilateur sous-jacent pour indiquer où se trouvent les fichiers d'en-tête pertinents.
  • --showme:libdirs : Affiche une liste de répertoires, séparés par des espaces (mais par ailleurs non décorés), que le compilateur wrapper aurait fournis à l'éditeur de liens sous-jacent pour indiquer où se trouvent les bibliothèques pertinentes.
  • --showme:libs : Affiche une liste de noms de bibliothèques, séparés par des espaces (mais par ailleurs non décorés), que le compilateur wrapper aurait utilisés pour lier une application. Par exemple : mpi open-pal util.
  • --showme:version : Affiche le numéro de version d'Open MPI.
  • --showme:help : Affiche un bref message d'aide d'utilisation.

Consultez la page de manuel de votre compilateur sous-jacent pour d'autres options qui peuvent être passées via oshcc.

DESCRIPTION

Conceptuellement, le rôle de ces commandes est assez simple : ajouter de manière transparente à la ligne de commande de l'utilisateur les flags de compilation et d'édition de liens pertinents nécessaires pour compiler/lier des programmes OpenSHMEM, puis invoquer le compilateur sous-jacent pour exécuter réellement la commande.

En tant que tels, ces commandes sont souvent appelées compilateurs « wrappers » car elles ne compilent ni ne lient réellement les applications elles-mêmes ; elles ajoutent seulement des flags à la ligne de commande et invoquent le compilateur backend.

BACKGROUND

Open MPI fournit des compilateurs wrappers pour plusieurs langages :

  • oshcc, shmemcc : C
  • oshc++, oshcxx, shmemc++, shmemcxx`:: C++
  • oshfort, shmemfort : Fortran

Les compilateurs wrappers pour chacun des langages sont identiques ; ils peuvent être utilisés de manière interchangeable. Les différents noms sont fournis uniquement pour des raisons de compatibilité descendante.

NOTES FORTRAN

Le compilateur wrapper Fortran pour OpenSHMEM (oshfort et shmemfort) peut compiler et lier des applications OpenSHMEM qui utilisent toutes les liaisons Fortran OpenSHMEM.

Notez cependant que le compilateur Fortran peut nécessiter des options de ligne de commande supplémentaires pour imposer un dialecte Fortran spécifique. Par exemple, dans certaines versions du compilateur IBM XLF, -qfixed peut être nécessaire pour compiler des fichiers source Fortran au format fixe.

Enfin, notez que oshfort sera inopérant et retournera une erreur d'utilisation si le support Fortran n'a pas été intégré à la couche OpenSHMEM.

APERÇU

oshcc et shmemcc sont des wrappers de commodité pour le compilateur C sous-jacent. La traduction d'un programme OpenSHMEM nécessite la liaison des bibliothèques spécifiques à OpenSHMEM qui peuvent ne pas résider dans l'un des répertoires de recherche standard de ld(1). Elle nécessite également souvent l'inclusion de fichiers d'en-tête qui peuvent également ne pas être trouvés dans un emplacement standard.

oshcc et shmemcc transmettent leurs arguments au compilateur C sous-jacent avec les options -I, -L et -l requises par les programmes OpenSHMEM.

Il en va de même pour tous les autres compilateurs wrappers de langage.

L'équipe OpenSHMEM encourage *fortement* l'utilisation des compilateurs wrappers plutôt que d'essayer de lier les bibliothèques OpenSHMEM manuellement. Cela permet à l'implémentation spécifique d'OpenSHMEM de changer sans forcer les modifications des directives de liaison dans les Makefiles des utilisateurs. En effet, l'ensemble spécifique de flags et de bibliothèques utilisé par les compilateurs wrappers dépend de la manière dont OpenSHMEM a été configuré et construit ; les valeurs peuvent changer entre différentes installations de la même version d'OpenSHMEM.

En effet, puisque les wrappers ne sont que des coquilles minces au-dessus d'un compilateur sous-jacent, il y a très, très peu de raisons convaincantes de ne pas utiliser oshcc. Lorsqu'il n'est pas possible d'utiliser les wrappers directement, les options --showme:compile et --showme:link doivent être utilisées pour déterminer quels flags les wrappers auraient utilisés. Par exemple :

shell$ cc -c file1.c `shmemcc --showme:compile`
shell$ cc -c file2.c `shmemcc --showme:compile`
shell$ cc file1.o file2.o `shmemcc --showme:link` -o my_oshmem_program

NOTES

Il est possible de rendre les compilateurs wrappers conscients du multi-lib. C'est-à-dire que les bibliothèques et les inclusions spécifiées peuvent différer en fonction des flags du compilateur spécifiés (par exemple, avec les compilateurs GNU sous Linux, un chemin de bibliothèque différent peut être utilisé si -m32 est vu par rapport à -m64 étant vu). Ce n'est pas le comportement par défaut dans une compilation standard, mais cela peut être activé (par exemple, dans un paquet binaire fournissant un support 32 et 64 bits). Plus d'informations peuvent être trouvées ici.

FICHIERS

Les chaînes que les compilateurs wrappers insèrent dans la ligne de commande avant d'invoquer le compilateur sous-jacent sont stockées dans un fichier texte créé par OpenSHMEM et installé dans $pkgdata/NOM-wrapper-data.txt, où :

  • $pkgdata est typiquement $prefix/share/openmpi
  • $prefix est le répertoire d'installation principal d'OpenSHMEM
  • NOM est le nom du compilateur wrapper (par exemple, $pkgdata/shmemcc-wrapper-data.txt)

Il est rarement nécessaire de modifier ces fichiers, mais ils peuvent être examinés pour mieux comprendre quels flags les wrappers placent sur la ligne de commande.

VARIABLES D'ENVIRONNEMENT

Par défaut, les wrappers utilisent les compilateurs qui ont été sélectionnés lors de la configuration d'OpenSHMEM. Ces compilateurs ont été trouvés automatiquement par le script “configure” d'Open MPI, ou ont été sélectionnés par l'utilisateur dans les variables d'environnement CC, CXX, et/ou FC avant l'invocation de configure. De plus, d'autres arguments spécifiques au compilateur ont pu être sélectionnés par configure.

Ces valeurs peuvent être remplacées sélectivement soit en modifiant les fichiers texte contenant ces informations de configuration (voir la section FICHIERS), soit en définissant des variables d'environnement sélectionnées
