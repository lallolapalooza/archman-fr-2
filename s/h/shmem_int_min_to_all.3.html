DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE du jeu actif appellent la routine. Si un PE n'appartenant pas au jeu actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE du jeu actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE du jeu actif. Le jeu actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de longueur nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie selon la version de la routine de réduction appelée. Lors de l'appel depuis C/C++, se référer à la section SYNOPIS pour les informations sur le type de données. Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :

shmem_int4_min_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_min_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_min_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_min_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_min_to_all : Réel, avec une taille d'élément de 16 octets

source Un tableau symétrique : de longueur nreduce éléments, qui contient un
élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro du PE virtuel le plus bas du jeu actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans le jeu actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans le jeu actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PE du jeu actif n'entre dans la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE du jeu actif. Les mêmes tableaux cible et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE du jeu actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE du jeu actif ne sont plus utilisés par un appel antérieur à une routine collective SHMEM. Le tableau cible sur tous les PE du jeu actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les affirmations suivantes sont vraies pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, de sorte qu'un tampon pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE du jeu actif pendant que l'un des PE participe au traitement d'une routine de réduction SHMEM. Soyez prudent dans les situations suivantes : Si le tableau pSync est initialisé à l'exécution, un certain type de synchronisation est nécessaire pour garantir que tous les PE du jeu de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PE du jeu actif n'est encore en train de traiter un appel de routine de réduction précédent qui utilisait les mêmes tableaux pSync ou pWrk. En général, cela ne peut être garanti qu'en effectuant un type de synchronisation. Cependant, dans le cas spécial des routines de réduction appelées avec le même jeu actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors d'appels successifs.

EXEMPLES

Exemple 1 : Cet exemple Fortran initialise statiquement le tableau pSync.

PROGRAM example
  INCLUDE "mpp/shmem.fh"
  INTEGER N, P_START, LOG_PE_STRIDE, PE_SIZE, NREDUCE
  REAL(4) target(2), source(2)
  REAL(4) pWrk(2 * SHMEM_REDUCE_SYNC_SIZE)
  INTEGER pSync(SHMEM_REDUCE_SYNC_SIZE)
  INTEGER i, rank
  rank = MY_PE()
  NREDUCE = 2
  P_START = 0
  LOG_PE_STRIDE = 0
  PE_SIZE = NUM_PES()
  source = 2.0, 3.0
  target = 1.0, 1.0
  DO i = 1, SHMEM_REDUCE_SYNC_SIZE
    pSync(i) = SHMEM_SYNC_VALUE
  END DO
  CALL SHMEM_REAL4_MIN_TO_ALL(target, source, NREDUCE, P_START,
& LOG_PE_STRIDE, PE_SIZE, pWrk, pSync)
  IF (rank .EQ. 0) THEN
    PRINT *, "target = ", target(1), target(2)
  END IF
END PROGRAM example

ay et trouve la valeur minimale de la variable réelle FOO sur tous les PE pairs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Exemple 2 : Considérons l'appel suivant en C/C++ :

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

L'appel précédent est plus efficace, mais sémantiquement équivalent, à la combinaison des appels suivants :

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Notez que deux ensembles de tableaux pWrk et pSync sont utilisés en alternance car aucune synchronisation n'est effectuée entre les appels.
