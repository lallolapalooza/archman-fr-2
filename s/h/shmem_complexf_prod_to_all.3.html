DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

target
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de target varie selon la version de la routine de réduction appelée et la langue utilisée. Lors de l'appel depuis C/C++, se référer à la section SYNOPIS pour les informations sur les types de données. Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :
shmem_comp4_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 4 octets.
shmem_comp8_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 8 octets.

shmem_int4_prod_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_prod_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_prod_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_prod_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_prod_to_all : Réel, avec une taille d'élément de 16 octets

source
Un tableau symétrique, de nreduce éléments, contenant un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que target.
nreduce
Le nombre d'éléments dans les tableaux target et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro du PE virtuel le plus bas de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que target. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Avant que l'un des PE de l'ensemble actif n'entre dans la routine de réduction, chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran).

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE de l'ensemble actif. Les mêmes tableaux cible et source, et les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE de l'ensemble actif. Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer des conditions suivantes (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE de l'ensemble actif ne sont plus utilisés par un appel antérieur à une routine collective SHMEM. Le tableau cible sur tous les PE de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les conditions suivantes sont vraies pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

shmem_complexf_prod_to_all(3) — Open MPI Community

NAME

shmem_complexf_prod_to_all, shmem_doublef_prod_to_all, shmem_longdoublef_prod_to_all, shmem_float_prod_to_all, shmem_double_prod_to_all, shmem_longdouble_prod_to_all, shmem_int_prod_to_all, shmem_long_prod_to_all, shmem_longlong_prod_to_all, shmem_short_prod_to_all — collect data from all PEs and compute the product

SYNOPSIS

C / C++:
#include <mpp/shmem.h>

TYPE shmem_XXXX_prod_to_all(TYPE target, TYPE source, int nreduce, int PE_start, int logPE_stride, int PE_size, void *pSync, void *pWrk);
Fortran:
INCLUDE "mpp/shmem.fh"

SUBROUTINE shmem_XXXX_prod_to_all(target, source, nreduce, PE_start, logPE_stride, PE_size, pSync, pWrk)
  TYPE, DIMENSION(*) target
  TYPE, DIMENSION(*) source
  INTEGER nreduce
  INTEGER PE_start
  INTEGER logPE_stride
  INTEGER PE_size
  TYPE, DIMENSION(SHMEM_REDUCE_SYNC_SIZE) pSync
  TYPE, DIMENSION(MAX(nreduce/2+1, SHMEM_REDUCE_MIN_WRKDATA_SIZE)) pWrk
END SUBROUTINE

DESCRIPTION

The shmem_XXXX_prod_to_all routine collects data from all the PEs specified in the set of active PEs and computes the product of the data elements. The product is then placed in the target array on all active PEs.

The set of active PEs is determined by PE_start, logPE_stride, and PE_size.

PE_start defines the first PE in the set of active PEs.

logPE_stride defines the logarithm base 2 of the stride between PEs in the set of active PEs.

PE_size defines the number of PEs in the set of active PEs.

The set of active PEs can be defined as PEs with ranks PE_start, PE_start + 2^logPE_stride, PE_start + 2 * 2^logPE_stride, ..., PE_start + (PE_size - 1) * 2^logPE_stride.

The source array on each active PE contains the data to be multiplied. The size of the source array is nreduce.

The target array on each active PE receives the final product. The size of the target array is nreduce.

pSync is a synchronization array that must be initialized to SHMEM_SYNC_VALUE on all PEs in the active set prior to calling the reduction routine. The reduction routine will update the elements of pSync to SHMEM_SYNC_VALUE when the routine completes.

pWrk is a working array that is used by the reduction routine.

The following reduction routines are available:

shmem_complexf_prod_to_all, shmem_doublef_prod_to_all, shmem_longdoublef_prod_to_all, shmem_float_prod_to_all, shmem_double_prod_to_all, shmem_longdouble_prod_to_all, shmem_int_prod_to_all, shmem_long_prod_to_all, shmem_longlong_prod_to_all, shmem_short_prod_to_all.

XXXX represents the data type of the elements in the arrays. The possible values for XXXX are:

float, double, longdouble, short, int, long, longlong, complex, doublecomplex, longdoublecomplex.

Complex types are supported with Fortran 90 and C/C++. Complex types are not supported with Fortran 77.

The following table shows the mapping between the Fortran and C/C++ types:

Fortran C/C++
REAL float
DOUBLE PRECISION double
COMPLEX float _Complex
DOUBLE COMPLEX double _Complex

NOTES

The pSync array is used for synchronization between reduction operations. It must be an array of type integer or a character array. It must be initialized to the value SHMEM_SYNC_VALUE (which is defined in mpp/shmem.fh).

The pWrk array is used for temporary storage during the reduction operation. It must be an array of the same type as the target and source arrays. The size of the pWrk array depends on the type of reduction operation and the number of elements being reduced.

The reduction routines are blocking routines. They do not return until the reduction operation is complete. This means that all PEs in the active set will have completed the reduction operation when the routine returns.

It is important to ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.h"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
