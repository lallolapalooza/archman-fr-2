shmem_wait_until(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

SHMEM_WAIT_UNTIL(3) Open MPI SHMEM_WAIT_UNTIL(3)

shmem_int_wait(3), shmem_int_wait(3)_until, shmem_int4_wait(3), shmem_int4_wait(3)_until, shmem_int8_wait(3), shmem_int8_wait(3)_until, shmem_long_wait(3), shmem_long_wait(3)_until, shmem_longlong_wait(3), shmem_longlong_wait(3)_until, shmem_short_wait(3), shmem_short_wait(3)_until, shmem_wait(3), shmem_wait(3)_until - Attend qu'une variable sur l'élément de traitement (PE) local change

SYNOPIS

C ou C++ :

#include <mpp/shmem.h>
void shmem_int_wait(volatile int *var, int value)
void shmem_int_wait_until(volatile int *var, int cond, int value)
void shmem_long_wait(volatile long *var, long value)
void shmem_long_wait_until(volatile long *var, int cond, long value)
void shmem_longlong_wait(volatile long long *var, long long value)
void shmem_longlong_wait_until(volatile long long *var, int cond,
  long long value)
void shmem_short_wait(volatile short *var, short value)
void shmem_short_wait_until(volatile short *var, int cond,
  short value)
void shmem_wait(volatile long *ivar, long cmp_value)
void shmem_wait_until(volatile long *ivar, int cmp, long value)

Fortran :

INCLUDE "mpp/shmem.fh"
CALL SHMEM_INT4_WAIT(ivar, cmp_value)
CALL SHMEM_INT4_WAIT_UNTIL(ivar, cmp, cmp_value)
CALL SHMEM_INT8_WAIT(ivar, cmp_value)
CALL SHMEM_INT8_WAIT_UNTIL(ivar, cmp, cmp_value)
CALL SHMEM_WAIT(ivar, cmp_value)
CALL SHMEM_WAIT_UNTIL(ivar, cmp, cmp_value)

DESCRIPTION

shmem_wait et shmem_wait_until attendent que ivar soit modifié par une écriture distante ou un échange atomique effectué par un autre processeur. Ces routines peuvent être utilisées pour la synchronisation dirigée point à point. Un appel à shmem_wait ne retourne que lorsqu'un autre processeur écrit une valeur, différente de cmp_value, dans ivar sur le processeur en attente. Un appel à shmem_wait_until ne retourne que lorsqu'un autre processeur modifie ivar pour satisfaire la condition implicite par cmp et cmp_value. Ce mécanisme est utile lorsqu'un processeur a besoin d'indiquer à un autre processeur qu'il a terminé une action.

Les arguments sont les suivants :

target
L'objet de données entier accessible à distance qui doit être mis à jour sur le PE distant. Si vous utilisez C/C++, le type de target doit correspondre à celui implicite dans la section SYNOPIS. Si vous utilisez le compilateur Fortran, il doit être de type entier avec une taille d'élément de 4 octets pour SHMEM_INT4_ADD et de 8 octets pour SHMEM_INT8_ADD.
value
La valeur à ajouter atomiquement à target. Si vous utilisez C/C++, le type de value doit correspondre à celui implicite dans la section SYNOPIS. Si vous utilisez Fortran, il doit être de type entier avec une taille d'élément égale à celle de target.
pe
Un entier qui indique le numéro du PE sur lequel target doit être mis à jour. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
ivar
Une variable entière accessible à distance qui est mise à jour par un autre PE. Si vous utilisez C/C++, le type de ivar doit correspondre à celui implicite dans la section SYNOPIS. Si vous utilisez Fortran, ivar doit être un type entier de taille spécifique selon la fonction appelée, comme suit :

shmem_wait, shmem_wait_until : entier par défaut

shmem_int4_wait, shmem_int4_wait_until : INTEGER*4

shmem_int8_wait, shmem_int8_wait_until : INTEGER*8

cmp
L'opérateur de comparaison qui compare ivar avec cmp_value. cmp doit être de type entier. Si vous utilisez Fortran, il doit être d'une sorte par défaut. Si vous utilisez C/C++, le type de cmp doit correspondre à celui implicite dans la section SYNOPIS. Les valeurs de cmp suivantes sont prises en charge :
SHMEM_CMP_EQ
Égal
SHMEM_CMP_NE
Différent
SHMEM_CMP_GT
Supérieur à
SHMEM_CMP_LE
Inférieur ou égal à
SHMEM_CMP_LT
Inférieur à
SHMEM_CMP_GE
Supérieur ou égal à
cmp_value
cmp_value doit être de type entier. Si vous utilisez C/C++, le type de cmp_value doit correspondre à celui implicite dans la section SYNOPIS. Si vous utilisez Fortran, cmp_value doit être un entier de même taille et de même sorte que ivar. Les routines shmem_wait retournent lorsque ivar n'est plus égal à cmp_value. Les routines shmem_wait_until retournent lorsque la condition de comparaison est vraie. La condition de comparaison est définie par l'argument ivar comparé à cmp_value en utilisant l'opérateur de comparaison, cmp.

EXEMPLES

Exemple 1 : L'appel suivant retourne lorsque la variable ivar n'est pas égale à 100 :

INTEGER*8 IVAR
CALL SHMEM_INT8_WAIT(IVAR, INT8(100))

Exemple 2 : L'appel suivant à SHMEM_INT8_WAIT_UNTIL est équivalent à l'appel à SHMEM_INT8_WAIT dans l'exemple 1 :

INTEGER*8 IVAR
CALL SHMEM_INT8_WAIT_UNTIL(IVAR, SHMEM_CMP_NE, INT8(100))

Exemple 3 : L'appel C/C++ suivant attend jusqu'à ce que le bit de signe dans ivar soit défini par un transfert depuis un PE distant :

int ivar;
shmem_int_wait_until(&ivar, SHMEM_CMP_LT, 0);

Exemple 4 : L'exemple Fortran suivant est dans le contexte d'une sous-routine :

SUBROUTINE EXAMPLE()
  INTEGER FLAG_VAR
  COMMON/FLAG/FLAG_VAR
  . . .
  FLAG_VAR = FLAG_VALUE ! initialiser la variable d'événement
  . . .
  IF (FLAG_VAR .EQ. FLAG_VALUE) THEN
    CALL SHMEM_WAIT(FLAG_VAR, FLAG_VALUE)
  ENDIF
  FLAG_VAR = FLAG_VALUE ! réinitialiser la variable d'événement pour la prochaine fois
  . . .
END
