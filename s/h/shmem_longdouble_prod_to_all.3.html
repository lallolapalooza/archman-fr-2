DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme avec toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

Le paramètre nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de la cible varie selon la version de la routine de réduction appelée et la langue utilisée. Lors de l'appel depuis C/C++, reportez-vous à la section SYNTAXE pour connaître les informations sur le type de données. Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :
shmem_comp4_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 4 octets.
shmem_comp8_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 8 octets.

shmem_int4_prod_to_all: Entier, avec une taille d'élément de 4 octets

shmem_int8_prod_to_all: Entier, avec une taille d'élément de 8 octets

shmem_real4_prod_to_all: Réel, avec une taille d'élément de 4 octets

shmem_real8_prod_to_all: Réel, avec une taille d'élément de 8 octets

shmem_real16_prod_to_all: Réel, avec une taille d'élément de 16 octets

source
Un tableau symétrique, de nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Avant que l'un des PE de l'ensemble actif n'entre dans la routine de réduction, chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran).

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE de l'ensemble actif. Les mêmes tableaux cible et source, et les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE de l'ensemble actif. Avant qu'un PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE de l'ensemble actif ne sont plus utilisés d'un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PE de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les conditions suivantes sont vraies pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, de sorte qu'un tampon pSync particulier n'a besoin d'être qu'une seule fois

shmem_longdouble_prod_to_all(3) — Open MPI Community

SYNOPSIS

For Fortran: 

include "mpp/shmem.fh"
...
call shmem_longdouble_prod_to_all(target, source, nreduce, left, right, npes, pwrk, psync)

For C/C++: 

#include <mpp/shmem.h>
...
void shmem_longdouble_prod_to_all(long double *target, long double *source, int nreduce, int left, int right, int npes, void *pwrk, _shmem_sync_t *psync);

DESCRIPTION

The collective routines shmem_longdouble_prod_to_all, shmem_prod_to_all, shmem_double_prod_to_all, shmem_float_prod_to_all, shmem_int_prod_to_all, shmem_long_prod_to_all, shmem_real_prod_to_all, shmem_longlong_prod_to_all, shmem_short_prod_to_all, shmem_signed_char_prod_to_all, shmem_uchar_prod_to_all, shmem_uint_prod_to_all, shmem_ulong_prod_to_all, shmem_ulonglong_prod_to_all, and shmem_unsigned_char_prod_to_all compute the product of the elements in the source array across all PEs in the specified active set, and store the results in the target array.

The active set is determined by the arguments left, right, and npes. The active set consists of PEs with PE IDs from left to right inclusive, with stride npes. The total number of PEs in the active set is npes.

The array elements are reduced in order, from index 0 to nreduce-1. The PEs in the active set must have the same values for target, source, nreduce, left, right, and npes.

The psync argument is a synchronization array that must be initialized to the value SHMEM_SYNC_VALUE. It is used to synchronize the PEs participating in the reduction. The size of the psync array must be at least SHMEM_REDUCE_SYNC_SIZE.

The pwrk argument is a working array that must be allocated by the user. The size of the pwrk array must be at least SHMEM_REDUCE_MIN_WRKDATA_SIZE.

NOTES

The reduction routines require that the psync and pwrk arrays be initialized before the first call to a reduction routine. Subsequent calls may reuse these arrays without re-initialization, provided that the previous reduction operation using these arrays has completed on all participating PEs. The psync array is used for synchronization, and it is essential that it is initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
