NOM

objdump - affiche des informations des fichiers objet

SYNTAXE

DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options contrôlent quelles informations spécifiques afficher. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent juste que leur programme compile et fonctionne.

fichierobjet... sont les fichiers objet à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objet membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes. Au moins une option de la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-headers
Si l'un des fichiers fichierobjet est une archive, affiche les informations d'en-tête d'archive (dans un format similaire à ls -l). Outre les informations que vous pourriez lister avec ar tv, objdump -a montre le format du fichier objet de chaque membre d'archive.
--adjust-vma=décalage
Lors de l'affichage des informations, ajoute d'abord décalage à toutes les adresses de section. Ceci est utile si les adresses de section ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise en place de sections à des adresses spécifiques lorsque l'on utilise un format qui ne peut pas représenter les adresses de section, tel que a.out.
-b nombfd
--target=nombfd
Spécifie que le format du code objet pour les fichiers objet est nombfd. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche des informations récapitulatives des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Étant donné que les formats de mangling de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Ceci tente d'analyser les informations du format de débogage STABS stockées dans le fichier et de les afficher en utilisant une syntaxe de type C. Si aucun débogage STABS n'a été trouvé, cette option se rabat sur l'option -W pour afficher les informations DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques de l'assembleur pour les instructions machine du fichier d'entrée. Cette option ne désassemble que les sections qui sont supposées contenir des instructions. Si l'argument optionnel symbole est donné, alors affiche les mnémoniques de l'assembleur en commençant à symbole. Si symbole est un nom de fonction, le désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lors de la rencontre du symbole suivant. S'il n'y a pas de correspondance pour symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lus et utilisés lors du désassemblage.

-D
--disassemble-all
Comme -d, mais désassemble
Voici le contenu traduit en français, en conservant la structure du fichier : ssemble les contenus de toutes les sections non vides et non BSS, pas seulement celles censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est activée, objdump supposera que tous les symboles présents dans une section de code se trouvent à la frontière entre les instructions et refusera de désassembler au-delà d'une telle frontière. Lorsque l'option -D est activée, cependant, cette supposition est supprimée. Cela signifie que le résultat de -d et -D peut différer si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur a également pour effet de forcer le désassembleur à décoder des morceaux de données trouvés dans des sections de code comme s'il s'agissait d'instructions.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

--no-addresses
Lors du désassemblage, n'imprime pas les adresses sur chaque ligne, ni pour les symboles et les décalages de relocalisation. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, imprime l'adresse complète sur chaque ligne. C'est l'ancien format de désassemblage.
-EB
-EL
--endian={big|little}
Spécifie l'endianness (boutisme) des fichiers objet. Cela n'affecte que le désassemblage. Cela peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas d'informations sur l'endianness, comme les enregistrements S.
-f
--file-headers
Affiche des informations récapitulatives à partir de l'en-tête global de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage de sections, chaque fois qu'un symbole est affiché, affiche également le décalage de fichier de la région de données qui est sur le point d'être déchargée. Si des zéros sont ignorés, alors lorsque le désassemblage reprend, indique à l'utilisateur combien de zéros ont été ignorés et le décalage de fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du déchargement de sections, affiche le décalage de fichier de l'emplacement à partir duquel le déchargement commence.
--file-start-context
Spécifie que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, étendre le contexte jusqu'au début du fichier.
-h
--section-headers
--headers
Affiche des informations récapitulatives à partir des en-têtes de section du fichier objet.

Les segments de fichiers peuvent être déplacés vers des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata ou -Tbss de ld. Cependant, certains formats de fichiers objet, tels que a.out, ne stockent pas l'adresse de départ des segments de fichiers. Dans ces situations, bien que ld déplace correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section de fichier ne peut pas afficher les adresses correctes. Au lieu de cela, il affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que dans certains cas, une section peut avoir à la fois les attributs READONLY et NOREAD. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump signalera les deux, car le réglage exact des bits de drapeau peut être important.

-H
--help
Affiche un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant toutes les architectures et formats objet disponibles pour la spécification avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non de débogage trouvées dans des fichiers de débogage séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom de fichier et les numéros de ligne source correspondant au code objet ou aux relocs affichés. Utile uniquement avec -d, -D ou -r.
-m machine
--architecture=machine
Spécifie l'architecture à utiliser lors du désassemblage de fichiers objet. Cela peut être utile lors du désassemblage de fichiers objet qui ne décrivent pas d'informations architecturales, comme les enregistrements S. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par deux points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Cela peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il restreint le désassemblage aux seules instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information architecturale, mais qu'il est également souhaité de désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Passe des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plus d'une option de désassembleur, plusieurs options -M peuvent être utilisées ou regroupées dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'impression des instructions DSP, spfp sélectionne l'impression des instructions FP à précision simple FPX, dpfp sélectionne l'impression des instructions FP à précision double FPX, quarkse_em sélectionne l'impression des instructions spéciales QuarkSE-EM, fpuda sélectionne l'impression des instructions d'assistance à double précision, fpus sélectionne l'impression des instructions FP à simple précision FPU, tandis que fpud sélectionne l'impression des instructions FP à double précision FPU. De plus, on peut choisir d'imprimer toutes les immédiates en hexadécimal en utilisant hex. Par défaut, les immédiates courtes sont imprimées en décimal, tandis que les valeurs immédiates longues sont imprimées en hexadécimal.

cpu=... permet de forcer un ISA particulier lors du désassemblage d'instructions, remplaçant la valeur -m ou ce qui est dans le fichier ELF. Cela peut être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur des données d'en-tête ELF privées pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois - seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option -mcpu=... de l'assembleur.

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner le jeu de noms de registres utilisé pendant le désassemblage. La spécification de -M reg-names-std (par défaut) sélectionnera les noms de registres tels qu'utilisés dans la documentation de l'ensemble d'instructions d'ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. La spécification de -M reg-names-apcs sélectionnera le jeu de noms utilisé par l'ARM Procedure Call Standard, tandis que la spécification de -M reg-names-raw utilisera simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de nommage des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de nommage de l'ARM/Thumb Procedure Call Standard. (Soit avec les noms de registres normaux, soit avec les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Cela peut être utile lors de la tentative de désassembler du code Thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées comme l'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instructions doivent être générées sous forme de commentaires dans le désassemblage en utilisant -M notes.

Pour le x86, certaines des options doublonnent les fonctions du commutateur -m, mais permettent un contrôle plus granulaire.

"x86-64"
"i386"
"i8086"
Sélectionne le désassemblage pour l'architecture donnée.
"intel"
"att"
Sélectionne entre le mode syntaxe Intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre l'ISA AMD64 et l'ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Sélectionne entre le mode mnémonique Intel et le mode mnémonique AT&T. Note : "intel-mnemonic" implique "intel" et "att-mnemonic" implique "att".
"addr64"
"addr32"
"addr16"
"data32"
"data16"
Spécifiez la taille d'adresse et la taille d'opérande par défaut. Ces cinq options seront ignorées si "x86-64", "i386" ou "i8086" apparaissent plus tard dans la chaîne d'options.
"suffix"
En mode AT&T et aussi pour un ensemble limité d'instructions en mode Intel, demande au désassembleur d'imprimer un suffixe mnémonique même lorsque le suffixe pourrait être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument -M raw sélectionne le désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont supportés. Ce sont : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle, et future. 32 et 64 modifient la sélection par défaut ou précédente d'un CPU, désactivant et activant respectivement les instructions 64 bits. De plus, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des capacités à une sélection de CPU précédente *ou ultérieure*. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations différentes ou des arguments différents, vous pourriez ne pas obtenir le désassemblage attendu. Si vous désassemblez sans spécifier de sélection de CPU, une valeur par défaut sera choisie à partir des informations obtenues par BFD dans les en-têtes des fichiers objets, mais le résultat pourrait à nouveau ne pas être celui attendu.

Pour MIPS, cette option contrôle l'impression des noms de mnémoniques d'instructions et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées :

"no-aliases"
Imprime le mnémonique d'instruction 'brut' au lieu de certains mnémoniques d'instructions pseudo. C'est-à-dire, imprime 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassemble les instructions MSA.
"virt"
Désassemble les instructions ASE de virtualisation.
"xpa"
Désassemble les instructions ASE eXtended Physical Address (XPA).
"gpr-names=ABI"
Imprime les noms des GPR (registres à usage général) conformément à l'ABI spécifié. Par défaut, les noms des GPR sont sélectionnés en fonction de l'ABI du binaire désassemblé.
"fpr-names=ABI"
Imprime les noms des FPR (registres à virgule flottante) conformément à l'ABI spécifié. Par défaut, les numéros des FPR sont imprimés plutôt que les noms.
"cp0-names=ARCH"
Imprime les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) conformément au CPU ou à l'architecture spécifié par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"hwr-names=ARCH"
Imprime les noms des HWR (registre matériel, utilisé par l'instruction "rdhwr") conformément au CPU ou à l'architecture spécifié par ARCH. Par défaut, les noms des HWR sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"reg-names=ABI"
Imprime les noms des GPR et FPR conformément à l'ABI sélectionné.
"reg-names=ARCH"
Imprime les noms des registres spécifiques au CPU (registres CP0 et noms HWR) conformément au CPU ou à l'architecture sélectionné.

Pour toutes les options listées ci-dessus, ABI ou ARCH peuvent être spécifiés comme numeric pour que les numéros soient imprimés plutôt que les noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier les adresses d'entrée des fonctions avec -M entry:0xf00ba. Vous pouvez l'utiliser plusieurs fois pour désassembler correctement les fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme les dump ROM). Dans ces cas, le masque d'entrée de fonction serait autrement décodé comme des instructions VAX, ce qui entraînerait probablement un désassemblage incorrect du reste de la fonction.

-p
--private-headers
Imprime les informations spécifiques au format du fichier objet. Les informations exactes imprimées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est imprimée.
-P options
--private=options
Imprime les informations spécifiques au format du fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (la liste des options est affichée avec l'aide).

Pour XCOFF, les options disponibles sont :

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Pour PE, les options disponibles sont :

"header"
"sections"

Tous les formats d'objets ne supportent pas cette option. En particulier, le format ELF ne l'utilise pas.

-r
--reloc
Imprime les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont imprimées en alternance avec le désassemblage.
-R
--dynamic-reloc
Imprime les entrées de relocalisation dynamique du fichier. Ceci n'est pertinent que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont imprimées en alternance avec le désassemblage.
-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non BSS sont affichées. Par défaut, toute section compressée sera affichée dans sa forme compressée. Pour voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source mélangé au désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Typiquement, txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut de "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifiez prefix à ajouter aux chemins absolus lors de l'utilisation de -S.
--prefix-strip=level
Indique combien de noms de répertoire initiaux doivent être supprimés des chemins absolus codés en dur. N'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, affiche l'instruction en hexadécimal ainsi qu'en forme symbolique. C'est le comportement par défaut sauf lorsque --prefix-addresses est utilisé.
--no-show-raw-insn
Lors du désassemblage d'instructions, n'affiche pas les octets de l'instruction. C'est le comportement par défaut lorsque --prefix-addresses est utilisé.
--insn-width=width
Affiche width octets sur une seule ligne lors du désassemblage d'instructions.
--visualize-jumps[=color|=extended-color|=off]
Visualise les sauts qui restent à l'intérieur d'une fonction en dessinant de l'art ASCII entre les adresses de début et de destination. L'argument optionnel =color ajoute de la couleur à la sortie en utilisant des couleurs de terminal simples. Alternativement, l'argument =extended-color ajoutera de la couleur en utilisant des couleurs 8 bits, mais celles-ci peuvent ne pas fonctionner sur tous les terminaux.

S'il est nécessaire de désactiver l'option visualize-jumps après qu'elle ait été précédemment activée, utilisez visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extened|extended-color|extened-colour
Active ou désactive l'utilisation de la coloration syntaxique dans la sortie de désassemblage. Le comportement par défaut
le comportement est déterminé via une option de configuration. Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et selon le terminal utilisé, la sortie colorée peut ne pas être réellement lisible.

L'argument on ajoute des couleurs en utilisant des couleurs de terminal simples.

L'argument terminal fait de même, mais seulement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

-W[lLiaprmfFsoORtUuTgAckK]

--dwarf-depth=n
Limite le vidage de la section ".debug_info" à n enfants. Ceci n'est utile qu'avec --debug-dump=info. La valeur par défaut est d'imprimer toutes les DIE ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIE à un niveau égal ou inférieur à n ne seront pas imprimés. La plage pour n est basée sur zéro.

--dwarf-start=n
Imprime uniquement les DIE en commençant par le DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si cette option est spécifiée, elle supprimera l'impression de toute information d'en-tête et de tous les DIE avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront imprimés.

Ceci peut être utilisé conjointement avec --dwarf-depth.

Active des vérifications supplémentaires pour la cohérence des informations Dwarf.

Affiche le contenu de la section CTF spécifiée. Les sections CTF elles-mêmes contiennent de nombreuses sous-sections, toutes affichées dans l'ordre.

Par défaut, affiche le nom de la section nommée .ctf, qui est le nom émis par ld.

--ctf-parent=member
Si la section CTF contient des types définis de manière ambiguë, elle contiendra une archive de nombreux dictionnaires CTF, tous héritant d'un dictionnaire contenant des types non ambigus. Ce membre est nommé par défaut .ctf, comme la section qui le contient, mais il est possible de changer ce nom en utilisant la fonction "ctf_link_set_memb_name_changer" au moment de la liaison. Lors de l'examen d'archives CTF créées par un lieur qui utilise le changeur de nom pour renommer le membre d'archive parent, --ctf-parent peut être utilisé pour spécifier le nom utilisé pour le parent.

--stabs
Affiche le contenu complet de toutes les sections demandées. Affiche le contenu des sections .stab, .stab.index et .stab.excl d'un fichier ELF. Ceci n'est utile que sur les systèmes (tels que Solaris 2.0) sur lesquels les entrées de table de symboles de débogage ".stab" sont transportées dans une section ELF. Dans la plupart des autres formats de fichiers, les entrées de table de symboles de débogage sont entrelacées avec des symboles de liaison et sont visibles dans la sortie --syms.
--start-address=address
Commence à afficher les données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
--stop-address=address
Arrête d'afficher les données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
-t
--syms
Imprime les entrées de la table des symboles du fichier. Ceci est similaire aux informations fournies par le programme nm, bien que le format d'affichage soit différent. Le format de la sortie dépend du format du fichier en cours de vidage, mais il existe deux types principaux. L'un ressemble à ceci : 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

où le numéro entre crochets est le numéro de

l'entrée dans la table des symboles, le nombre sec est le numéro de section, la valeur fl sont les bits de drapeau du symbole, le nombre ty est le type du symbole, le nombre scl est la classe de stockage du symbole et la valeur nx est le nombre d'entrées auxiliaires associées au symbole. Les deux derniers champs sont la valeur du symbole et son nom.

L'autre format de sortie courant, généralement vu avec les fichiers basés sur ELF, ressemble à ceci :

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Ici, le premier nombre est la valeur du symbole (parfois appelée son adresse). Le champ suivant est en fait un ensemble de caractères et d'espaces indiquant les bits de drapeau qui sont définis pour le symbole. Ces caractères sont décrits ci-dessous. Ensuite, il y a la section à laquelle le symbole est associé ou *ABS* si la section est absolue (c'est-à-dire non connectée à une section), ou *UND* si la section est référencée dans le fichier en cours de déchargement, mais non définie là.

Après le nom de la section, il y a un autre champ, un nombre, qui, pour les symboles courants, est l'alignement et pour les autres symboles, est la taille. Enfin, le nom du symbole est affiché.

Les caractères de drapeau sont divisés en 7 groupes comme suit :

"l"
"g"
"u"
"!"
Le symbole est local (l), global (g), global unique (u), ni global ni local (un espace) ou à la fois global et local (!). Un symbole peut être ni local ni global pour diverses raisons, par exemple, parce qu'il est utilisé pour le débogage, mais ce serait probablement une indication d'un bug s'il était à la fois local et global. Les symboles globaux uniques sont une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, l'éditeur de liens dynamique s'assurera qu'il n'y a qu'un seul symbole avec ce nom et ce type utilisé dans l'ensemble du processus.
"w"
Le symbole est faible (w) ou fort (un espace).
"C"
Le symbole représente un constructeur (C) ou un symbole ordinaire (un espace).
"W"
Le symbole est un avertissement (W) ou un symbole normal (un espace). Le nom d'un symbole d'avertissement est un message à afficher si le symbole qui suit le symbole d'avertissement est jamais référencé.
"I"
"i"
Le symbole est une référence indirecte à un autre symbole (I), une fonction à évaluer lors du traitement des relocations (i) ou un symbole normal (un espace).
"d"
"D"
Le symbole est un symbole de débogage (d) ou un symbole dynamique (D) ou un symbole normal (un espace).
"F"
"f"
"O"
Le symbole est le nom d'une fonction (F) ou d'un fichier (f) ou d'un objet (O) ou simplement d'un symbole normal (un espace).
-T
--dynamic-syms
Affiche les entrées de la table des symboles dynamiques du fichier. Ceci n'est significatif que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Ceci est similaire aux informations fournies par le programme nm lorsqu'il reçoit l'option -D (--dynamic).

Le format de sortie est similaire à celui produit par l'option --syms, à l'exception qu'un champ supplémentaire est inséré avant le nom du symbole, donnant les informations de version associées au symbole. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées au symbole, elle est affichée telle quelle, sinon elle est placée entre parenthèses.

--special-syms
Lors de l'affichage des symboles, inclure ceux que la cible considère comme spéciaux d'une manière ou d'une autre et qui ne seraient normalement pas intéressants pour l'utilisateur.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multi-octets encodés en UTF-8 dans les chaînes. La valeur par défaut (--unicode=default) est de ne leur donner aucun traitement spécial. L'option --unicode=locale affiche la séquence dans la locale actuelle, qui peut la supporter ou non. Les options --unicode=hex et --unicode=invalid les affichent sous forme de séquences d'octets hexadécimaux entourées d'angles ou d'accolades.

L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en évidence en rouge (si le périphérique de sortie le prend en charge). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

--version
Affiche le numéro de version de objdump et quitte.
-x
--all-headers
Affiche toutes les informations d'en-tête disponibles, y compris la table des symboles et les entrées de relocalisation. L'utilisation de -x équivaut à spécifier tous les -a -f -h -p -r -t.
-w
--wide
Formate certaines lignes pour les périphériques de sortie qui ont plus de 80 colonnes. Ne tronque pas non plus les noms de symboles lorsqu'ils sont affichés.
-z
--disassemble-zeroes
Normalement, la sortie de désassemblage ignore les blocs de zéros. Cette option demande au désassembleur de désassembler ces blocs, comme tout autre donnée.
-Z
--decompress
L'option -Z est destinée à être utilisée conjointement avec l'option -s. Elle demande à objdump de décompresser toute section compressée avant d'en afficher le contenu.
@file
Lit les options de la ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et non supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière d'apostrophes ou de guillemets. Tout caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le file peut lui-même contenir d'autres options @file ; ces options seront traitées récursivement.
