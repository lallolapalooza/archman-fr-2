SHRED(1) Commandes utilisateur SHRED(1)

NOM

shred - écrase un fichier pour masquer son contenu, et le supprime en option

SYNTAXE

shred [OPTION]... FICHIER...

DESCRIPTION

Écrase le(s) FICHIER(s) spécifié(s) de manière répétée, afin de rendre plus difficile la récupération des données, même avec du matériel de sondage très coûteux.

Si FICHIER est -, shred la sortie standard.

Les arguments obligatoires pour les options longues sont également obligatoires pour les options courtes.

-f, --force
change les permissions pour autoriser l'écriture si nécessaire
-n, --iterations=N
écrase N fois au lieu de la valeur par défaut (3)
--random-source=FICHIER
obtient des octets aléatoires de FICHIER
-s, --size=N
écrase N octets (les suffixes comme K, M, G sont acceptés)
-u
désalloue et supprime le fichier après l'écrasement
--remove[=COMMENT]
comme -u mais donne le contrôle sur COMMENT supprimer ; Voir ci-dessous
-v, --verbose
affiche la progression
-x, --exact
n'arrondit pas les tailles de fichier au bloc complet suivant ; c'est la valeur par défaut pour les fichiers non réguliers
-z, --zero
ajoute un dernier écrasement avec des zéros pour masquer l'écrasement
--help
affiche cette aide et quitte
--version
affiche les informations de version et quitte

Supprime le(s) FICHIER(s) si --remove (-u) est spécifié. La valeur par défaut est de ne pas supprimer les fichiers car il est courant d'opérer sur des fichiers de périphériques comme /dev/hda, et ces fichiers ne devraient généralement pas être supprimés. Le paramètre COMMENT optionnel indique comment supprimer une entrée de répertoire : 'unlink' => utilise un appel unlink standard. 'wipe' => obfusque d'abord les octets du nom. 'wipesync' => synchronise également chaque octet obfusqué avec le périphérique. Le mode par défaut est 'wipesync', mais notez que cela peut être coûteux.

ATTENTION : shred suppose que le système de fichiers et le matériel écrasent les données sur place. Bien que ce soit courant, de nombreuses plateformes fonctionnent différemment. De plus, les sauvegardes et les miroirs peuvent contenir des copies irrécupérables qui permettront de récupérer plus tard un fichier écrasé. Voir le manuel de GNU coreutils pour plus de détails.
