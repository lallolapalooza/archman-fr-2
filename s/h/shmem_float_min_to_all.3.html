DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme avec toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie avec la version de la routine de réduction appelée. Lors de l'appel depuis C/C++, reportez-vous à la section SYNOPIS pour les informations sur le type de données. Lors de l'appel depuis Fortran, les types de données cible sont les suivants :

shmem_int4_min_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_min_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_min_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_min_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_min_to_all : Réel, avec une taille d'élément de 16 octets

source Un tableau symétrique : de nreduce éléments, qui contient un
élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PE de l'ensemble actif n'entre dans la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE de l'ensemble actif. Les mêmes tableaux cible et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE de l'ensemble actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE de l'ensemble actif ne sont plus utilisés par un appel antérieur à une routine collective SHMEM. Le tableau cible sur tous les PE de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les éléments suivants sont vrais pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, de sorte qu'un tableau pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE de l'ensemble actif pendant que l'un des PE participe au traitement d'une routine de réduction SHMEM. Soyez prudent dans les situations suivantes : Si le tableau pSync est initialisé au moment de l'exécution, un certain type de synchronisation est nécessaire pour garantir que tous les PE de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PE de l'ensemble actif n'est encore en train de traiter un appel de routine de réduction antérieur qui utilisait les mêmes tableaux pSync ou pWrk. En général, cela ne peut être garanti qu'en effectuant un certain type de synchronisation. Cependant, dans le cas spécial des routines de réduction appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors des appels successifs.

shmem_float_min_to_all(3) — Open MPI 5.0.9-2 documentation

NAME

shmem_float_min_to_all, shmem_double_min_to_all, shmem_long_min_to_all, shmem_real8_min_to_all - collective reduction minimum operation across all PEs

SYNOPSIS

C/C++:
#include <mpp/shmem.h>

void shmem_float_min_to_all(float *target, const float *source, int n, int logPeMap, int cacheHint, int pe);
void shmem_double_min_to_all(double *target, const double *source, int n, int logPeMap, int cacheHint, int pe);
void shmem_long_min_to_all(long *target, const long *source, int n, int logPeMap, int cacheHint, int pe);
void shmem_real8_min_to_all(double *target, const double *source, int n, int logPeMap, int cacheHint, int pe);

Fortran:
INCLUDE "mpp/shmem.fh"

CALL shmem_real4_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_real8_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_int8_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_int16_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_int32_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_int64_min_to_all(target, source, n, logPeMap, cacheHint, pe)
CALL shmem_long_min_to_all(target, source, n, logPeMap, cacheHint, pe)

DESCRIPTION

These routines perform a reduction minimum operation on an array of elements across one or more processing elements (PEs).

The shmem_*_min_to_all routines compute the minimum value of the elements in the source array and place the result in the target array.

The operation is performed across a subset of PEs specified by pe. The logPeMap argument controls whether the reduction is performed across PEs that are contiguous or mapped in a strided pattern. The cacheHint argument is ignored.

The n parameter specifies the number of elements in the source and target arrays.

The reduction is performed across the PEs specified by the pe argument. The pe argument is interpreted as follows:

  • If pe is 0, the reduction is performed across all PEs in the Cartesian group.
  • If pe is greater than 0, it specifies the number of PEs participating in the reduction, and these PEs are determined by the logPeMap argument.

The logPeMap argument is interpreted as follows:

  • If logPeMap is 0, the reduction is performed across PEs that are contiguous in the default PE ordering.
  • If logPeMap is greater than 0, the reduction is performed across PEs that are mapped in a strided pattern, with the stride determined by logPeMap.

NOTES

The shmem_*_min_to_all routines are collective operations. All participating PEs must call these routines.

The shmem_*_min_to_all routines are point-to-point reductions. The source and target arrays must be distinct.

The shmem_real8_min_to_all routine is an alias for shmem_double_min_to_all.

The shmem_real4_min_to_all routine is an alias for shmem_float_min_to_all.

The Fortran routines use different data types than the C/C++ routines. For example, shmem_real4_min_to_all corresponds to shmem_float_min_to_all.

The C/C++ routines have a cacheHint argument which is ignored.

Fortran wrappers shmem_long_min_to_all are also provided. These correspond to the C/C++ shmem_long_min_to_all routine, which operates on 32-bit or 64-bit integers depending on the platform. The Fortran routines shmem_int8_min_to_all, shmem_int16_min_to_all, shmem_int32_min_to_all, and shmem_int64_min_to_all are provided for specific integer sizes.

The shmem_*_min_to_all routines synchronize all participating PEs. This means that no PE will return from these routines until all participating PEs have called them.

Example 1 (Fortran): Find the minimum value of FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
