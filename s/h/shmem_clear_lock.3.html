shmem_set_lock(3), shmem_clear_lock(3), shmem_test_lock(3) - Libère, verrouille et teste un verrou de mutual exclusion en mémoire.

SYNOPSIS

C ou C++ :

#include <mpp/shmem.h>
void shmem_clear_lock(volatile long *lock)
void shmem_set_lock(volatile long *lock)
int shmem_test_lock(volatile long *lock)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER lock, SHMEM_TEST_LOCK
CALL SHMEM_CLEAR_LOCK(lock)
CALL SHMEM_SET_LOCK(lock)
I = SHMEM_TEST_LOCK(lock)

DESCRIPTION

La routine shmem_set_lock positionne un verrou de mutual exclusion après avoir attendu que le verrou soit libéré par tout autre PE le détenant actuellement. Les PE en attente sont assurés d'obtenir le verrou selon un principe premier arrivé, premier servi.

La routine shmem_clear_lock libère un verrou précédemment positionné par shmem_set_lock après s'être assuré que toutes les écritures locales et distantes initiées dans la région critique sont terminées.

La fonction shmem_test_lock positionne un verrou de mutual exclusion uniquement s'il est actuellement désactivé. En utilisant cette fonction, un PE peut éviter de bloquer sur un verrou positionné. Si le verrou est actuellement positionné, la fonction retourne sans attendre. Ces routines sont appropriées pour protéger une région critique contre une mise à jour simultanée par plusieurs PE. Elles acceptent les arguments suivants :

lock
Un objet de données symétrique qui est une variable scalaire ou un tableau de longueur 1. Cet objet de données doit être initialisé à 0 sur tous les éléments de traitement (PE) avant la première utilisation. `lock` doit être de type entier. Si vous utilisez Fortran, il doit être de kind par défaut.

NOTES

Le terme objet de données symétrique est défini dans intro_shmem(3).

VALEURS DE RETOUR

La fonction shmem_test_lock retourne 0 si le verrou était initialement désactivé et que cet appel a pu le positionner. La valeur 1 est retournée si le verrou était déjà positionné et que l'appel est retourné sans attendre pour positionner le verrou.
