shar(1) Commandes utilisateur shar(1)

NOM

shar - créer une archive shell

SYNOPSIS

shar [-flags] [-flag [valeur]] [--nom-option[[=| ]valeur]] [<fichier>...]

Si aucun fichier n'est spécifié, la liste des fichiers d'entrée est lue depuis l'entrée standard. L'entrée standard ne doit pas être un terminal.

DESCRIPTION

shar crée des "archives shell" (ou fichiers shar) qui sont au format texte et peuvent être envoyées par e-mail. Ces fichiers peuvent être décompressés plus tard en les exécutant avec /bin/sh. L'archive résultante est envoyée à la sortie standard, sauf si l'option -o est donnée. Une large gamme de fonctionnalités offre une grande flexibilité pour fabriquer des shars et pour spécifier l'"intelligence" de shar. Les archives peuvent être assez simples (--vanilla-operation) ou essentiellement une archive tar destine aux e-mails.

Les options peuvent être spécifiées dans n'importe quel ordre jusqu'à ce qu'un argument fichier soit reconnu. Si l'option --intermix-type a été spécifiée, davantage d'options de compression et d'encodage seront reconnues entre les arguments fichier.

Bien que ce programme prenne en charge les fichiers uuencode-d, ceux-ci sont obsolètes. Si vous envoyez des fichiers par e-mail, veuillez considérer les fichiers encodés en MIME. Si vous utilisez uuencode, l'encodage base64 est la méthode préférée.

OPTIONS

Spécification de la compression

-p, --intermix-type

spécifier la compression pour les fichiers d'entrée. Cette option ne doit pas être combinée avec aucune des options suivantes : vanilla-operation.

Autorise les options de paramètres positionnels. Les options de méthode de compression et de méthode d'encodage peuvent être mélangées avec les noms de fichiers. Les fichiers nommés après ces options seront traités de la manière spécifiée.

-C programme, --compactor=programme

spécifier le programme de compaction (compression). Cette option peut apparaître un nombre illimité de fois. Cette option ne doit pas être combinée avec aucune des options suivantes : vanilla-operation.

Les commandes de compaction gzip, bzip2 et compress peuvent être spécifiées par le nom du programme comme nom d'option, par exemple --gzip. Ces options sont cependant obsolètes. Il y a aussi maintenant le compacteur xz. Spécifiez xz avec -C xz ou --compactor=xz.


Spécifier le compacteur "none" désactivera la compression des fichiers. Les fichiers compressés ne sont jamais traités comme du texte brut. Ils sont toujours encodés en uuencode et le destinataire doit avoir uudecode pour les décompresser.

Spécifier le compacteur compress est obsolète.

-g niveau, --level-of-compression=niveau

transmettre NIVEAU pour la compression. Cette option prend un nombre entier comme argument. La valeur de niveau est contrainte d'être : 
dans la plage 1 à 9

Le niveau par défaut pour cette option est :
9

Certains programmes de compression permettent un niveau de compression. Le défaut est 9, mais cette option vous permet d'en spécifier un autre. Cette valeur est utilisée par gzip, bzip2 et xz, mais pas par compress.

-j, --bzip2

bzip2 et uuencode les fichiers. Cette option peut apparaître un nombre illimité de fois.

Compresse les fichiers avec bzip2 et les encode en uuencode avant de les archiver. Le destinataire doit avoir uudecode et bzip2 pour décompresser.

NOTE : CETTE OPTION EST OBSOLÈTE

-z, --gzip

gzip et uuencode les fichiers. Cette option peut apparaître un nombre illimité de fois.

Compresse les fichiers avec gzip et les encode en uuencode avant de les archiver. Le destinataire doit avoir uudecode et gzip pour décompresser.

NOTE : CETTE OPTION EST OBSOLÈTE

-Z, --compress

compress et uuencode les fichiers. Cette option peut apparaître un nombre illimité de fois.

Compresse les fichiers avec compress et les encode en uuencode avant de les archiver. Le destinataire doit avoir uudecode et compress pour décompresser.

NOTE : CETTE OPTION EST OBSOLÈTE

--level-for-gzip

Ceci est un alias pour l'option --level-of-compression.

NOTE : CETTE OPTION EST OBSOLÈTE

-b bits, --bits-per-code=bits

transmettre bits (par défaut 12) à compress. Le bits par défaut pour cette option est :
12

C'est le facteur de compression utilisé par le programme compress.

NOTE : CETTE OPTION EST OBSOLÈTE

Spécification de la méthodologie d'encodage des fichiers

Les fichiers peuvent être stockés dans le shar soit en texte brut, soit encodés en uuencode. Par défaut, le programme choisit en examinant le fichier. Vous pouvez forcer la sélection pour tous les fichiers. En mode option/fichier mélangé, ce réglage peut être modifié pendant le traitement.

-M, --mixed-uuencode

décider du uuencoding pour chaque fichier. Cette option est membre de la classe d'options mixed-uuencode.

Déterminer automatiquement si les fichiers sont binaires ou texte et archiver correctement. Les fichiers trouvés binaires sont encodés en uuencode avant d'être archivés. C'est le comportement par défaut de shar.

Pour qu'un fichier soit considéré comme un fichier texte plutôt qu'un fichier binaire, toutes les conditions suivantes doivent être remplies :

Le fichier ne contient aucun caractère de contrôle ASCII autre que BS (retour arrière), HT (tabulation horizontale), LF (nouvelle ligne) ou FF (saut de page).

Le fichier ne contient aucun caractère dont le huitième bit est défini.

Le fichier ne contient aucune ligne commençant par les cinq lettres "from ", qu'elles soient en majuscules ou non. (Les programmes de traitement de courrier inséreront souvent, sans raison valable, un caractère > avant).

Le fichier est soit vide, soit se termine par un octet LF (nouvelle ligne).

Aucune ligne du fichier ne contient plus de 200 caractères. Pour le comptage, les lignes sont séparées par un LF (nouvelle ligne).

-B, --uuencode

traiter tous les fichiers comme binaires. Cette option est membre de la classe d'options mixed-uuencode.

Utiliser uuencode avant d'archiver tous les fichiers. Ceci augmente la taille de l'archive. Le destinataire doit avoir uudecode pour décompresser. Les fichiers compressés sont toujours encodés.

-T, --text-files

traiter tous les fichiers comme du texte. Cette option est membre de la classe d'options mixed-uuencode.

Si vous avez des fichiers avec des octets non-ASCII ou du texte que certains programmes de gestion de courrier n'aiment pas, vous pourriez rencontrer des difficultés. Cependant, si vous utilisez FTP ou SSH/SCP, les fichiers texte non conformes devraient convenir.

Spécification de la sélection de fichiers et des modes de sortie

-o préfixe, --output-prefix=préfixe

imprimer la sortie dans le fichier PREFIX.nn.

Sauvegarder l'archive dans les fichiers prefix.01 à prefix.nn au lieu d'envoyer toute la sortie à la sortie standard. Doit être spécifié lorsque les options --whole-size-limit ou --split-size-limit sont spécifiées.

pouvoir afficher un seul nombre décimal. Lorsque prefix ne contient pas un tel caractère %, la chaîne .%02d est ajoutée en interne.

-l taille, --whole-size-limit=taille

divise l'archive, pas les fichiers, en fonction de taille. Cette option fait partie de la classe d'options whole-size-limit. Cette option doit apparaître en combinaison avec les options suivantes : output-prefix. Cette option prend un nombre entier comme argument. La valeur de taille est limitée à : 
dans la plage de 8 à 1023, ou
dans la plage de 8192 à 4194304

Limite la taille du fichier de sortie à taille octets, mais ne divise pas les fichiers d'entrée. Si taille est inférieur à 1024, il sera multiplié par 1024. La valeur peut également être spécifiée avec un suffixe k, K, m ou M. Le nombre est alors multiplié par 1000, 1024, 1000000 ou 1048576, respectivement. 4M (4194304) est le maximum autorisé.

Contrairement à l'option split-size-limit, cela permet au destinataire des fichiers shar de les décompresser dans n'importe quel ordre.

-L taille, --split-size-limit=taille

divise l'archive ou les fichiers en fonction de taille. Cette option fait partie de la classe d'options whole-size-limit. Cette option doit apparaître en combinaison avec les options suivantes : output-prefix. Cette option prend un nombre entier comme argument. La valeur de taille est limitée à : 
dans la plage de 8 à 1023, ou
dans la plage de 8192 à 4194304

Limite la taille du fichier de sortie à taille octets, en divisant les fichiers si nécessaire. Les valeurs autorisées sont spécifiées comme pour l'option --whole-size-limit.

Les parties d'archive créées avec cette option doivent être décompressées dans le bon ordre. Si le destinataire des archives shell souhaite toutes les placer dans un seul dossier (fichier) d'e-mail, elles devront être sauvegardées dans le bon ordre pour que unshar puisse les décompresser toutes en même temps (en utilisant l'une des options de division d'archive). Voir : Invocation de unshar.

-I fichier, --input-file-list=fichier

lit la liste des fichiers à partir d'un fichier.

Cette option provoque la réouverture de fichier comme entrée standard. S'il n'y a pas de fichiers trouvés sur la ligne d'entrée, alors l'entrée standard est lue pour les noms de fichiers d'entrée. L'utilisation de cette option interdira que les fichiers d'entrée soient listés sur la ligne de commande.

L'entrée doit être sous une forme similaire à celle générée par find, un nom de fichier par ligne. Ce commutateur est particulièrement utile lorsque la ligne de commande ne peut pas contenir la liste des fichiers à archiver.

Si l'option --intermix-type est spécifiée sur la ligne de commande, alors les options de compression peuvent être incluses dans l'entrée standard sur des lignes séparées et aucun nom de fichier ne peut commencer par un trait d'union.

Par exemple :

    { echo --compact xz
       find . -type f -print | sort
    } | shar -S -p -L50K -o /quelque/part/gros
-S, --stdin-file-list

lit la liste des fichiers depuis l'entrée standard.

Cette option est en fait une opération nulle. C'est un wrapper pour --input-file-list=-.

NOTE : CETTE OPTION EST DÉPRÉCIÉE

Contrôle des en-têtes shar

-n nom, --archive-name=nom

utilise nom pour documenter l'archive.

Nom de l'archive à inclure dans l'en-tête sujet des fichiers shar. Voir l'option --net-headers.

-s qui@où, --submitter=qui@où

remplace le nom du soumissionnaire.

shar déterminera normalement le nom du soumissionnaire en interrogeant le système. Utilisez cette option si cela est fait au nom de quelqu'un d'autre.

-a, --net-headers

produit les en-têtes Submitted-by: & Archive-name:. Cette option doit apparaître en combinaison avec les options suivantes : archive-name.

Ajoute des en-têtes d'e-mail spécialisés :

    Submitted-by: qui@@où
    Archive-name: nom/part##
Le qui@@où est normalement dérivé, mais peut être spécifié avec l'option --submitter. Le nom doit être fourni avec l'option --archive-name. Si le nom de l'archive inclut un caractère slash (/), alors le /part## est omis. Ainsi -n xyzzy produit : 
    xyzzy/part01
    xyzzy/part02

tandis que -n xyzzy/patch produit :

    xyzzy/patch01
    xyzzy/patch02

et -n xyzzy/patch01. produit :

    xyzzy/patch01.01
    xyzzy/patch01.02
-c, --cut-mark

commence le shar avec une ligne de coupure.

Une ligne disant 'Coupez ici' est placée au début de chaque fichier de sortie.

-t, --translate

traduit les messages dans le script.

Traduit les messages dans le script. Si vous avez défini la variable d'environnement LANG, les messages imprimés par shar seront dans la langue spécifiée. Le script produit sera toujours émis en utilisant des messages dans la lingua franca du monde informatique : l'anglais. Cette option fera apparaître les messages du script dans les langues spécifiées par la variable d'environnement LANG définie lors de la production du script.

Protection contre les problèmes de transmission

--no-character-count

n'utilise pas `wc -c' pour vérifier la taille.

Ne vérifie PAS chaque fichier avec 'wc -c' après la décompression. La vérification est activée par défaut.

-D, --no-md5-digest

n'utilise pas le condensat md5sum pour vérifier.

N'utilise PAS le condensat md5sum pour vérifier les fichiers décompressés. La vérification est activée par défaut.

-F, --force-prefix

applique le caractère de préfixe à chaque ligne.

Force le caractère de préfixe à être ajouté à chaque ligne, même si ce n'est pas nécessaire. Cette option peut légèrement augmenter la taille de l'archive, surtout si --uuencode ou une option de compression est utilisée.

-d delim, --here-delimiter=delim

utilise delim pour délimiter les fichiers. Le delim par défaut pour cette option est :
SHAR_EOF

Utilise DELIM pour délimiter les fichiers dans le shar au lieu de SHAR_EOF. Ceci est pour ceux qui veulent personnaliser leurs fichiers shar. Le délimiteur sera toujours précédé et suivi d'underscores.

Production de différents types de shars

-V, --vanilla-operation

produit des shars très simples.

Cette option produit des shars vanilla qui ne reposent que sur l'existence de echo, test et sed dans l'environnement de décompression.

Elle change le comportement par défaut du mode mixte (--mixed-uuencode) en mode texte (--text-files). Des avertissements sont produits si des options sont spécifiées qui nécessiteront une décompression ou un décodage dans l'environnement de décompression.

-P, --no-piping

utilise des fichiers temporaires entre les programmes.

Dans le fichier shar, utilise un fichier temporaire pour conserver le contenu des fichiers entre les étapes de décompression au lieu d'utiliser des pipes. Cette option est obligatoire lorsque vous savez que la décompression aura lieu sur des systèmes qui ne supportent pas les pipes.

-x, --no-check-existing

écrase aveuglément les fichiers existants.

Crée l'archive de manière à ce que, lors de son traitement, les fichiers existants soient écrasés sans vérification préalable. Si ni cette option ni l'option --query-user n'est spécifiée, la décompression n'écrasera pas les fichiers préexistants. Dans tous les cas, cependant, si --cut-mark est passé comme paramètre au script lors de la décompression, les fichiers existants seront écrasés inconditionnellement.

    sh shar-archive-file -c
-X, --query-user

demande à l'utilisateur avant d'écraser les fichiers. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : vanilla-operation.

Lors de la décompression, demande interactivement à l'utilisateur s'il faut écraser les fichiers. Ne pas utiliser pour les shars soumis sur le net.

L'utilisation de cette option produit des shars qui causeront des problèmes avec certaines procédures de type unshar, en particulier lorsqu'ils sont utilisés conjointement avec le mode vanilla (--vanilla-operation). Utilisez cette fonctionnalité principalement pour les archives à échanger entre parties consentantes. Certes, -X n'est pas pour les archives shell qui doivent être soumises à Usenet ou à d'autres réseaux publics.

Le problème est que les programmes ou procédures unshar alimentent souvent /bin/sh depuis leur entrée standard, plaçant ainsi /bin/sh et le script d'archive shell en compétition pour les lignes d'entrée. Pour tenter d'atténuer ce problème, shar essaiera de détecter si /dev/tty existe sur le site récepteur et l'utilisera pour lire les réponses de l'utilisateur. Mais cela ne fonctionne pas dans tous les cas ; il peut arriver que l'utilisateur récepteur doive éviter d'utiliser les programmes ou procédures unshar et appeler /bin/sh directement. En mode vanilla, /dev/tty n'est même pas tenté d'être utilisé.

NAME

shar, unshar - create and unpack shell archives

SYNOPSIS

shar [-] [-number] [-B] [-b] [-c] [-e] [-f] [-H] [-i] [-k] [-l length] [-m] [-N] [-p] [-P] [-Q] [-q] [-r cfgfile] [-R [cfgfile]] [-s] [-t] [-u] [-v [{v|c|n}]] [-x] [-0..-7] [file ...]

unshar [-] [-number] [-b] [-c] [-d dir] [-e] [-f] [-H] [-i] [-k] [-l length] [-m] [-N] [-p] [-P] [-Q] [-q] [-r cfgfile] [-R [cfgfile]] [-s] [-t] [-u] [-v [{v|c|n}]] [-x] [-0..-7]

DESCRIPTION

The shar utility creates a shell archive, which is a shell script that contains one or more files. This script, when run, will extract the files it contains. Shell archives are a simple way to send collections of files via electronic mail or to archive them.

The unshar utility unpacks shell archives. It is usually called by the user to unpack an archive that was previously created with shar.

By default, shar creates a shell script that is compatible with most common versions of the sh shell. It also tries to be compatible with csh and ksh.

The shell archive produced by shar contains the original files, possibly compressed, along with a shell script that performs the extraction. The script is designed to be robust and to handle various conditions such as filename conflicts or user interruptions.

The unshar utility is designed to be flexible and can unpack archives created by various versions of shar. It attempts to restore filenames, permissions, and timestamps to their original state.

General options

-, -number

use a different archive format.

This option selects the archive format. The default format is generally the most compatible. The different formats are primarily for compatibility with older versions of shar and unshar. Use of the default is recommended unless you have specific compatibility requirements.

-B, --force-batch

force batch operation.

This option forces shar to operate in batch mode, meaning it will not prompt the user for confirmation or input during the archiving process. This is useful for scripting or automated tasks.

-b, --skip-old-files

skip files newer than the archive.

This option causes shar to skip files that are newer than the archive being created. This can be useful when updating an existing archive or when you want to ensure that only older versions of files are included.

-c, --create-empty-dirs

create empty directories.

When this option is used, shar will create empty directories in the archive, even if they do not contain any files. This is useful for preserving the directory structure of a project.

-e, --exit-on-error

exit if an error occurs.

This option causes shar to exit immediately if an error occurs during the archiving process. This is useful for preventing partially created archives.

-H, --no-timestamp

do not preserve modification times.

When this option is used, shar does not attempt to preserve the modification times of the files being archived. This can be useful in certain environments where timestamp preservation is problematic or undesirable. However, be aware that timestamp preservation is important for tools like make, as the original timestamps are preserved. When this option is not used, a special effort is made to restore timestamps.

-i, --no-internet-safe

do not create an internet-safe archive.

This option disables the creation of an "internet-safe" archive. Internet-safe archives are designed to be more robust when transmitted over networks, but they may not be compatible with older unarchiving tools. Use this option if you encounter compatibility issues with older systems.

-k, --keep-going

do not exit if a file is skipped.

This option allows shar to continue processing even if some files are skipped (e.g., due to the -b option). This is useful when you want to archive as much as possible, even if some files cannot be included.

-l length, --line-length length

pack lines to length characters.

This option sets the maximum length of each line in the shell archive to length characters. This can be useful for ensuring compatibility with systems that have limitations on line length, or for reducing the size of the archive.

-m, --no-mixed-case

do not use mixed case filenames.

This option prevents shar from creating archives that use mixed-case filenames. This is mainly for compatibility with older systems that only support uppercase filenames.

-N, --normalize

normalize line endings.

This option normalizes line endings within the archive to a standard format (typically Unix-style newlines). This can help prevent issues when transferring files between systems with different line ending conventions.

-p, --no-pipe

do not use pipes.

This option prevents shar from using pipes for compressing or encoding files. Instead, it will create temporary files for intermediate data. This may be necessary in environments where pipes are not fully supported.

-P, --force-prefix

force prefixing filenames.

This option forces shar to prefix all filenames with a directory name. This is useful for ensuring that files are extracted into a specific directory, preventing potential conflicts with existing files in the current directory.

-Q, --quiet-unshar

avoid verbose messages at unshar time.

Verbose OFF. Disables the inclusion of comments to be output when the archive is unpacked.

-f, --basename

restore in one directory, despite hierarchy.

Restore by the base file name only, rather than path. This option causes only file names to be used, which is useful when building a shar from several directories, or another directory. Note that if a directory name is passed to shar, the substructure of that directory will be restored whether this option is specified or not.

Internationalization options

--no-i18n

do not internationalize.

Do not produce internationalized shell archives, use default English messages. By default, shar produces archives that will try to output messages in the unpackers preferred language (as determined by the LANG/LC_MESSAGES environmental variables) when they are unpacked. If no message file for the unpackers language is found at unpack time, messages will be in English.

--print-text-domain-dir

print directory with shar messages.

Prints the directory shar looks in to find messages files for different languages, then immediately exits.

-q, --quiet

do not output verbose messages.

omit progress messages.

--silent

This is an alias for the --quiet option.
-h, --help

Display usage information and exit.
-!, --more-help

Pass the extended usage information through a pager.
-R [cfgfile], --save-opts [=cfgfile]

Save the option state to cfgfile. The default is the last configuration file listed in the OPTION PRESETS section, below. The command will exit after updating the config file.
-r cfgfile, --load-opts=cfgfile, --no-load-opts

OPTION PRESETS

Any option that is not marked as not presettable may be preset by loading values from configuration ("RC" or ".INI") file(s). The file "$HOME/.sharrc" will be used, if present.

WARNINGS

No attempt is made to restore the protection and modification dates for directories, even if this is done by default for files. Thus, if a directory is given to shar, the protection and modification dates of corresponding unpacked directory may not match those of the original.

If a directory is passed to shar, it may be scanned more than once, to conserve memory. Therefore, do not change the directory contents while shar is running.

Be careful that the output file(s) are not included in the inputs or shar may loop until the disk fills up. Be particularly careful when a directory is passed to shar that the output files are not in that directory or a subdirectory of it.

Use of the compression and encoding options will slow the archive process, perhaps considerably.

Use of the --query-user produces shars which will cause problems with many unshar procedures. Use this feature only for archives to be passed among agreeable parties. Certainly, query-user is NOT for shell archives which are to be distributed across the net. The use of compression in net shars will cause you to be flamed off the earth. Not using the --no-timestamp or --force-prefix options may also get you occasional complaints. Put these options into your ~/.sharrc file.

EXAMPLES

The first shows how to make a shell archive out of all C program sources. The second produces a shell archive with all .c and .h files, which unpacks silently.
