shmem_alltoall32(3), shmem_alltoall64(3), shmem_alltoalls32(3), shmem_alltoalls64(3) - routine collective où chaque PE échange une quantité fixe de données avec tous les autres PEs de l'ensemble Actif

SYNOPSIS

C ou C++ :

#include <mpp/shmem.h>
void shmem_alltoall32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoall64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoalls32(void *target, const void *source,
  ptrdiff_t dst, ptrdiff_t sst,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_alltoalls64(void *target, const void *source,
  ptrdiff_t dst, ptrdiff_t sst,
  size_t nelems, int PE_start, int logPE_stride,
  int PE_size, long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER dst, sst, nelems, PE_root, PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_ALLTOALL_SYNC_SIZE)
CALL SHMEM_ALLTOALL32(target, source, nelems,
& PE_start, logPE_stride, PE_size, fIpSync)
CALL SHMEM_ALLTOALL64(target, source, nelems,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_ALLTOALLS32(target, source, dst, sst, nelems,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_ALLTOALLS64(target, source, dst, sst, nelems,
& PE_start, logPE_stride, PE_size, pSync)

DESCRIPTION

Les routines shmem_alltoalls sont des routines collectives. Chaque PE de l'ensemble Actif échange nelems éléments de données indexés de taille 32 bits (pour shmem_alltoalls32) ou 64 bits (pour shmem_alltoalls64) avec tous les autres PEs de l'ensemble. Les deux pas, dst et sst, doivent être supérieurs ou égaux à 1. Le bloc jème de taille sst* envoyé du PE i au PE j est placé dans le bloc ième de taille dst* de l'objet de données de destination sur le PE j. Comme pour toutes les routines collectives OpenSHMEM, ces routines supposent que seuls les PEs de l'ensemble Actif appellent la routine. Si un PE qui n'est pas dans l'ensemble Actif appelle une routine collective OpenSHMEM, un comportement indéfini en résulte. Les valeurs des arguments dst, sst, nelems, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble Actif. Les mêmes objets de données de destination et source, et le même tableau de travail pSync doivent être passés à tous les PEs de l'ensemble Actif. Avant tout appel de PE à une routine shmem_alltoalls, les conditions suivantes doivent exister (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Le tableau pSync sur tous les PEs de l'ensemble Actif n'est pas encore utilisé à partir d'un appel précédent à une routine shmem_alltoalls. L'objet de données de destination sur tous les PEs de l'ensemble Actif est prêt à accepter les données shmem_alltoalls. Au retour d'une routine shmem_alltoalls, ce qui suit est vrai pour le PE local : Son objet de données symétrique de destination est complètement mis à jour et les données ont été copiées hors de l'objet de données source. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

Les arguments sont les suivants :

Un objet de données symétrique avec l'un des types de données suivants :

shmem_alltoall32 : Tout type non caractère qui
a une taille d'élément de 32 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.
shmem_alltoall64 : Tout type non caractère qui a une taille d'élément
de 64 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.

target Un objet de données symétrique suffisamment grand pour recevoir le total combiné de nelems éléments de chaque PE de l'ensemble Actif.

source
Un objet de données symétrique qui contient nelems éléments de données pour chaque PE de l'ensemble Actif, ordonnés selon le PE de destination.
dst
Le pas entre les éléments consécutifs de l'objet de données de destination. Le pas est mis à l'échelle par la taille de l'élément. Une valeur de 1 indique des données contiguës. dst doit être de type ptrdiff_t. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
sst
Le pas entre les éléments consécutifs de l'objet de données source. Le pas est mis à l'échelle par la taille de l'élément. Une valeur de 1 indique des données contiguës. sst doit être de type ptrdiff_t. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
nelems
Le nombre d'éléments à échanger pour chaque PE. nelems doit être de type size_t pour C/C++. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PEs. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. log_PE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pSync
Un tableau de travail symétrique. En C/C++, pSync doit être de type long et de taille _SHMEM_ALLTOALL_SYNC_SIZE. En Fortran, pSync doit être de type entier et de taille SHMEM_ALLTOALL_SYNC_SIZE. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PEs de l'ensemble actif n'appelle shmem_barrier().

Au retour d'une routine shmem_alltoalls, ce qui suit est vrai pour le PE local : Son objet de données symétrique de destination est complètement mis à jour et les données ont été copiées hors de l'objet de données source. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

Les valeurs des arguments PE_root, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble actif. Les mêmes objets de données cibles et sources et le même tableau de travail pSync doivent être passés à tous les PEs de l'ensemble actif.

Avant que tout PE n'appelle une routine alltoall, vous devez vous assurer que les conditions suivantes existent (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Le tableau pSync sur tous les PEs de l'ensemble actif n'est pas encore utilisé lors d'un appel précédent à une routine alltoall. Le tableau cible sur tous les PEs de l'ensemble actif est prêt à accepter les données alltoall.

NOTES

Les termes collectif et symétrique sont définis dans intro_shmem(3).

Toutes les routines SHMEM alltoall restaurent pSync à son contenu d'origine. Plusieurs appels à des routines SHMEM utilisant le même tableau pSync ne nécessitent pas que pSync soit réinitialisé après le premier appel.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour par un PE de l'ensemble actif pendant que l'un des PEs participe au traitement d'une routine de diffusion SHMEM. Faites attention à éviter ces situations : Si le tableau pSync est initialisé à l'exécution, un type de synchronisation est nécessaire pour garantir que tous les PEs de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync peut être réutilisé lors d'une routine de diffusion SHMEM ultérieure uniquement si aucun des PEs de l'ensemble actif ne traite encore un appel de routine SHMEM alltoall précédent qui utilisait le même tableau pSync. En général, cela ne peut être garanti qu'en effectuant un type de synchronisation. Cependant, dans le cas spécial des routines SHMEM appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et alterner entre eux lors d'appels successifs.

shmem_alltoall64.3.fr — Documentation Arch Linux

SYNOPSIS

Module Shmem

#include <mpp/shmem.h>

void shmem_alltoalls64(void *dest, const void *source, int stride, int nelems, int nlong, long long *pSync); void shmem_alltoall64(void *dest, const void *source, int stride, int nelems, int nlong, long long *pSync);

DESCRIPTION

La routine shmem_alltoalls64 effectue un collectif de type alltoall sur les PEs. Tous les PEs envoient le même nombre d'éléments à tous les autres PEs, et reçoivent le même nombre d'éléments de tous les autres PEs. L'ensemble des données envoyées par le PE me est source et l'ensemble des données reçues par le PE me est dest.

Chaque PE envoie nelems éléments de taille nlong octets chacun à tous les autres PEs. La routine shmem_alltoall est une version 32 bits, tandis que shmem_alltoalls64 est une version 64 bits.

Le paramètre stride spécifie le nombre d'octets entre le début d'un élément et le début du prochain élément dans les tampons source et dest.

Le paramètre pSync est un tableau de synchronisation fourni par l'utilisateur. Il doit avoir une taille d'au moins SHMEM_ALLTOALLS_SYNC_SIZE.

Les routines shmem_alltoalls et shmem_alltoalls64 sont équivalentes à shmem_alltoall et shmem_alltoall64 respectivement.

Les collectifs alltoall sont utilisés dans les applications parallèles pour redistribuer des données entre tous les processus. Par exemple, dans une application de calcul distribué, chaque PE pourrait avoir une partie d'une matrice globale. Un collectif alltoall pourrait être utilisé pour réorganiser les données afin que chaque PE ait une autre partie de la matrice globale.

NOTES

Les tampons source et dest doivent être alloués en utilisant shmem_malloc ou des primitives d'allocation équivalentes qui garantissent un alignement approprié pour les opérations de communication.

Le tableau de synchronisation pSync doit être initialisé à SHMEM_SYNC_VALUE avant l'appel collectif.

Les opérations de communication collectives comme shmem_alltoall peuvent être coûteuses en termes de performances. Il est important de minimiser leur utilisation et de les utiliser efficacement lorsque cela est nécessaire.

EXAMPLES

/* Programme exemple pour shmem_alltoalls64 */
#include <mpp/shmem.h>
#include <stdio.h>
#include <stdlib.h>

#define NELEMS 512 /* Nombre d'éléments par PE */

int main(void) {
    long long *dest, *source;
    long long pSync[SHMEM_ALLTOALLS_SYNC_SIZE];
    int pe, i;
    int count = NELEMS;

    /* initialiser les tampons */
    dest = (long long *) shmem_malloc(shmem_n_pes() * count * sizeof(long long));
    source = (long long *) shmem_malloc(shmem_n_pes() * count * sizeof(long long));

    if (dest == NULL || source == NULL) {
        fprintf(stderr, "[%d] Erreur d'allocation mémoire\n", shmem_my_pe());
        shmem_finalize();
        return 1;
    }

    /* remplir les tampons source et initialiser les tampons dest */
    for (pe = 0; pe < shmem_n_pes(); pe++) {
        for (i = 0; i < count; i++) {
            source[(pe * count) + i] = shmem_my_pe() + pe; /* Valeur arbitraire */
            dest[(pe * count) + i] = 9999; /* Valeur initiale */
        }
    }

    /* initialiser le tableau de synchronisation */
    for (i = 0; i < SHMEM_ALLTOALLS_SYNC_SIZE; i++) {
        pSync[i] = SHMEM_SYNC_VALUE;
    }

    /* attendre que tous les PEs initialisent pSync */
    shmem_barrier_all();

    /* effectuer l'opération alltoalls sur tous les PEs */
    /* shmem_alltoalls64(dest, source, 1, 1, count, 0, 0, shmem_n_pes(), pSync); */
    /* Note: La signature exacte peut varier selon la version. La signature ci-dessus
       semble inhabituelle. Typiquement, le stride serait en éléments et non en octets
       pour les types de données de base, ou il serait calculé en fonction du type.
       Dans l'exemple, on utilise un stride de 1 élément pour chaque PE, et on envoie
       'count' éléments. Le '1' après 'source' et avant 'count' correspondrait
       normalement au stride sur le tableau source et dest. Si on veut envoyer le tableau
       entier source à chaque PE, avec chaque élément de taille 'sizeof(long long)',
       et que le dest est également un tableau contigu, le stride pourrait être 1
       élément si les éléments sont contigus. */

    /* L'appel correct dépend de la manière dont les données sont structurées.
       Si 'source' et 'dest' sont des tableaux simples et contigus de 'long long',
       et que 'count' est le nombre total d'éléments longs à échanger par PE:
    */
    shmem_alltoall64(dest, source, sizeof(long long), count, sizeof(long long), pSync);
    /* Ici, sizeof(long long) est le stride en octets, et count est le nombre d'éléments.
       L'argument 'nelems' (troisième arg) est le nombre d'éléments.
       'nlong' (quatrième arg) est le nombre d'éléments dans le tableau de synchronisation.
       La signature la plus courante est (void *dest, const void *source, int element_size, int n_elements, int n_pes, long long *pSync)
       ou avec stride explicite.

       Si la signature est (void *dest, const void *source, int stride, int nelems, int nlong, long long *pSync)
       où 'nelems' est le nombre total d'éléments à envoyer/recevoir par PE,
       et 'stride' est le stride en *éléments* (pas en octets), alors:
       Pour un tableau simple de 'long long', le stride est 1 élément.
    */
    /* Assumant une signature où le stride est en éléments : */
    /* shmem_alltoall64(dest, source, 1, count, 1, pSync); // Ou similaire */

    /* Vérifier les résultats */
    for (pe = 0; pe < shmem_n_pes(); pe++) {
        for (i = 0; i < count; i++) {
            /* Dans un alltoall, le PE 'me' reçoit des données de tous les autres PEs.
               Si le PE 'src_pe' envoie la valeur 'src_pe + pe_i' où 'pe_i' est le PE distant,
               alors le PE 'dest_pe' devrait recevoir la valeur 'src_pe + dest_pe'
               pour les données envoyées par 'src_pe'.
               Dans cet exemple, chaque PE 'j' écrit (my_pe() + j) dans source.
               Chaque PE 'i' recevra de chaque PE 'j' une partie des données.
               Idéalement, le PE 'i' devrait recevoir les données de 'j' qui contiennent
               des informations de 'j'.
               Si source[(j*count)+k] = j + j (valeur envoyée par PE j),
               alors dest[(j*count)+k] devrait être j + j.
               L'exemple original a `source[(pe*count)+i] = shmem_my_pe() + pe;`
               et vérifie `dest[(pe*count)+i] != shmem_my_pe() + pe`.
               Ceci implique que le PE `shmem_my_pe()` reçoit des données de `pe`
               telles que la valeur devrait être `shmem_my_pe() + pe`.
               Donc, pour chaque PE `pe` (l'expéditeur), le PE `shmem_my_pe()` (le récepteur)
               recevra les données où l'indice `(pe*count)+i` correspond aux données
               originellement envoyées par `pe` et reçues par `shmem_my_pe()`.
               Si chaque PE `j` envoie `j + k` pour les données `k`, alors le PE `i` reçoit `j + k`
               des données de `j`.
               L'exemple `dest[(pe*count)+i] != shmem_my_pe() + pe` suggère que le PE
               `shmem_my_pe()` attend de recevoir la valeur `shmem_my_pe() + pe`
               dans l'emplacement `(pe*count)+i` des données reçues.
               Ceci serait le cas si le PE `pe` envoie la valeur `shmem_my_pe() + pe`
               à la position `(pe*count)+i` pour que le PE `shmem_my_pe()` la reçoive là.
               Donc, la valeur envoyée par PE `pe` est `shmem_my_pe() + pe`, et elle va
               dans `dest[(pe*count)+i]` du PE `shmem_my_pe()`.
               Ceci est une manière spécifique d'organiser les données.
            */
            if (dest[(pe * count) + i] != shmem_my_pe() + pe) {
                printf("[%d] ERREUR: dest[%d]=%lld, devrait être %lld\n",
                       shmem_my_pe(), (pe * count) + i, dest[(pe * count) + i],
                       shmem_my_pe() + pe);
                /* Il peut être utile d'arrêter tous les PEs en cas d'erreur */
                /* shmem_global_exit(1); */
            }
        }
    }

    /* attendre que tous les PEs terminent la vérification */
    shmem_barrier_all();

    /* libérer la mémoire allouée */
    shmem_free(dest);
    shmem_free(source);

    /* finaliser l'environnement Shmem */
    shmem_finalize();

    return 0;
}
