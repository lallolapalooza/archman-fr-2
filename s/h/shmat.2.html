SHMOP(2) System Calls Manual SHMOP(2)

NOM

shmat, shmdt - opérations sur la mémoire partagée System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/shm.h>
void *shmat(int shmid, const void *_Nullable shmaddr, int shmflg);
int shmdt(const void *shmaddr);

DESCRIPTION

shmat()

shmat() attache le segment de mémoire partagée System V identifié par shmid à l'espace d'adressage du processus appelant. L'adresse d'attachement est spécifiée par shmaddr selon l'un des critères suivants :

•
Si shmaddr est NULL, le système choisit une adresse appropriée (non utilisée) et alignée sur page pour attacher le segment.
•
Si shmaddr n'est pas NULL et que SHM_RND est spécifié dans shmflg, l'attachement se fait à l'adresse égale à shmaddr arrondie à la limite inférieure multiple de SHMLBA.
•
Sinon, shmaddr doit être une adresse alignée sur page où se fait l'attachement.

En plus de SHM_RND, les drapeaux suivants peuvent être spécifiés dans le masque de bits shmflg :

SHM_EXEC (spécifique à Linux ; depuis Linux 2.6.9)
Permet d'exécuter le contenu du segment. L'appelant doit avoir la permission d'exécution sur le segment.
SHM_RDONLY
Attache le segment en lecture seule. Le processus doit avoir la permission de lecture sur le segment. Si ce drapeau n'est pas spécifié, le segment est attaché en lecture et écriture, et le processus doit avoir les permissions de lecture et d'écriture sur le segment. Il n'y a pas de notion de segment de mémoire partagée en écriture seule.
SHM_REMAP (spécifique à Linux)
Ce drapeau spécifie que le mappage du segment doit remplacer tout mappage existant dans la plage commençant à shmaddr et continuant sur la taille du segment. (Normalement, une erreur EINVAL serait retournée si un mappage existait déjà dans cette plage d'adresses.) Dans ce cas, shmaddr ne doit pas être NULL.

La valeur de brk(2) du processus appelant n'est pas modifiée par l'attachement. Le segment sera automatiquement détaché à la sortie du processus. Le même segment peut être attaché en lecture et en lecture-écriture, et plus d'une fois, dans l'espace d'adressage du processus.

Un appel réussi à shmat() met à jour les membres de la structure shmid_ds (voir shmctl(2)) associée au segment de mémoire partagée comme suit :

•
shm_atime est défini à l'heure actuelle.
•
shm_lpid est défini à l'ID du processus appelant.
•
shm_nattch est incrémenté de un.

shmdt()

shmdt() détache le segment de mémoire partagée situé à l'adresse spécifiée par shmaddr de l'espace d'adressage du processus appelant. Le segment à détacher doit être actuellement attaché avec shmaddr égal à la valeur retournée par l'appel à shmat() qui l'a attaché.

Lors d'un appel réussi à shmdt(), le système met à jour les membres de la structure shmid_ds associée au segment de mémoire partagée comme suit :

•
shm_dtime est défini à l'heure actuelle.
•
shm_lpid est défini à l'ID du processus appelant.
•
shm_nattch est décrémenté de un. S'il devient 0 et que le segment est marqué pour suppression, le segment est supprimé.

VALEUR RENVOYÉE

En cas de succès, shmat() renvoie l'adresse du segment de mémoire partagée attaché ; en cas d'erreur, il renvoie (void *) -1 et errno est défini pour indiquer l'erreur.

En cas de succès, shmdt() renvoie 0 ; en cas d'erreur, il renvoie -1 et errno est défini pour indiquer l'erreur.

ERREURS

shmat() peut échouer avec l'une des erreurs suivantes :

EACCES
Le processus appelant n'a pas les permissions requises pour le type d'attachement demandé, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EIDRM
shmid pointe vers un identifiant supprimé.
EINVAL
Valeur shmid invalide, adresse shmaddr non alignée (c'est-à-dire pas alignée sur page et SHM_RND non spécifié) ou invalide, ou impossibilité d'attacher le segment à shmaddr, ou SHM_REMAP spécifié et shmaddr était NULL.
ENOMEM
Impossible d'allouer de la mémoire pour le descripteur ou pour les tables de pages.

shmdt() peut échouer avec l'une des erreurs suivantes :

EINVAL
Aucun segment de mémoire partagée n'est attaché à shmaddr ; ou, shmaddr n'est pas aligné sur une limite de page.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001, SVr4.

Dans SVID 3 (ou peut-être avant), le type de l'argument shmaddr a été changé de char * à const void *, et le type de retour de shmat() de char * à void *.

POSIX.1-2024 a changé le code d'erreur de (void *) -1 à SHM_FAILED.

NOTES

Après un fork(2), le fils hérite des segments de mémoire partagée attachés.

Après un execve(2), tous les segments de mémoire partagée attachés sont détachés du processus.

Lors de _exit(2), tous les segments de mémoire partagée attachés sont détachés du processus.

Utiliser shmat() avec shmaddr égal à NULL est la manière préférée et portable d'attacher un segment de mémoire partagée. Soyez conscient que le segment de mémoire partagée attaché de cette manière peut être attaché à des adresses différentes dans différents processus. Par conséquent, tous les pointeurs maintenus dans la mémoire partagée doivent être rendus relatifs (typiquement par rapport à l'adresse de début du segment), plutôt qu'absolus.

Sous Linux, il est possible d'attacher un segment de mémoire partagée même s'il est déjà marqué pour suppression. Cependant, POSIX.1 ne spécifie pas ce comportement et de nombreuses autres implémentations ne le prennent pas en charge.

Le paramètre système suivant affecte shmat() :

SHMLBA
Multiple de l'adresse de la limite inférieure du segment. Lors de la spécification explicite d'une adresse d'attachement dans un appel à shmat(), l'appelant doit s'assurer que l'adresse est un multiple de cette valeur. Ceci est nécessaire sur certaines architectures, soit pour assurer de bonnes performances du cache CPU, soit pour s'assurer que les différents attachements du même segment ont des vues cohérentes dans le cache CPU. SHMLBA est normalement un multiple de la taille de page du système. (Sur de nombreuses architectures Linux, SHMLBA est identique à la taille de page du système.)

L'implémentation n'impose aucune limite intrinsèque par processus au nombre de segments de mémoire partagée (SHMSEG).

#ifndef SVSHM_STRING_H
#define SVSHM_STRING_H

#include <stdio.h>
#include <stdlib.h>
#include <sys/sem.h>
union semun {                   /* Utilisé dans les appels à semctl() */
    int                 val;
    struct semid_ds     *buf;
    unsigned short      *array;
#if defined(__linux__)
    struct seminfo      *__buf;
#endif
};
#define MEM_SIZE 4096
#endif  // garde d'inclusion

Source du programme : svshm_string_read.c

Le programme "reader" crée un segment de mémoire partagée et un ensemble de sémaphores contenant un sémaphore. Il attache ensuite l'objet de mémoire partagée dans son espace d'adressage et initialise la valeur du sémaphore à 1. Finalement, le programme attend que la valeur du sémaphore devienne 0, et après cela, il affiche la chaîne qui a été copiée dans le segment de mémoire partagée par le "writer".


/* svshm_string_read.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(void)
{
    int            semid, shmid;
    char           *addr;
    union semun    arg, dummy;
    struct sembuf  sop;
    /* Créer la mémoire partagée et l'ensemble de sémaphores contenant un
       sémaphore.  */
    shmid = shmget(IPC_PRIVATE, MEM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1)
        err(EXIT_FAILURE, "shmget");
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0600);
    if (semid == -1)
        err(EXIT_FAILURE, "semget");
    /* Attacher la mémoire partagée dans notre espace d'adressage.  */
    addr = shmat(shmid, NULL, SHM_RDONLY);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    /* Initialiser le sémaphore 0 dans l'ensemble avec la valeur 1.  */
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1)
        err(EXIT_FAILURE, "semctl");
    printf("shmid = %d\n", shmid);
    printf("semid = %d\n", semid);
    /* Attendre que la valeur du sémaphore devienne 0.  */
    sop.sem_num = 0;
    sop.sem_op = 0;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    /* Afficher la chaîne de la mémoire partagée.  */
    printf("%s\n", addr);
    /* Supprimer la mémoire partagée et l'ensemble de sémaphores.  */
    if (shmctl(shmid, IPC_RMID, NULL) == -1)
        err(EXIT_FAILURE, "shmctl");
    if (semctl(semid, 0, IPC_RMID, dummy) == -1)
        err(EXIT_FAILURE, "semctl");
    exit(EXIT_SUCCESS);
}

Source du programme : svshm_string_write.c

Le programme writer prend trois arguments en ligne de commande : les identifiants du segment de mémoire partagée et de l'ensemble de sémaphores qui ont déjà été créés par le "reader", et une chaîne de caractères. Il attache le segment de mémoire partagée dans son espace d'adressage, puis décrémente la valeur du sémaphore à 0 afin d'informer le "reader" qu'il peut maintenant examiner le contenu de la mémoire partagée.


/* svshm_string_write.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(int argc, char *argv[])
{
    int            semid, shmid;
    char           *addr;
    size_t         size;
    struct sembuf  sop;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s shmid semid string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    size = strlen(argv[3]) + 1;  /* +1 pour inclure le '\0' final */
    if (size > MEM_SIZE) {
        fprintf(stderr, "La chaîne est trop grande !\n");
        exit(EXIT_FAILURE);
    }
    /* Obtenir les identifiants des objets à partir de la ligne de commande.  */
    shmid = atoi(argv[1]);
    semid = atoi(argv[2]);
    /* Attacher la mémoire partagée dans notre espace d'adressage et copier la chaîne
       (y compris le caractère nul final) dans la mémoire.  */
    addr = shmat(shmid, NULL, 0);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    memcpy(addr, argv[3], size);
    /* Décrémenter le sémaphore à 0.  */
    sop.sem_num = 0;
    sop.sem_op = -1;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    exit(EXIT_SUCCESS);
}
