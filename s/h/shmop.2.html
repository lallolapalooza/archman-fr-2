SHMOP(2) Manuel des appels système SHMOP(2)

NOM

shmat, shmdt - Opérations sur la mémoire partagée System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/shm.h>
void *shmat(int shmid, const void *_Nullable shmaddr, int shmflg);
int shmdt(const void *shmaddr);

DESCRIPTION

shmat()

shmat() attache le segment de mémoire partagée System V identifié par shmid à l'espace d'adressage du processus appelant. L'adresse d'attachement est spécifiée par shmaddr selon l'un des critères suivants :

•
Si shmaddr est NULL, le système choisit une adresse appropriée (non utilisée et alignée sur une page) pour attacher le segment.
•
Si shmaddr n'est pas NULL et que SHM_RND est spécifié dans shmflg, l'attachement se produit à l'adresse égale à shmaddr arrondie à la valeur inférieure multiple de SHMLBA.
•
Sinon, shmaddr doit être une adresse alignée sur une page où se produit l'attachement.

En plus de SHM_RND, les indicateurs suivants peuvent être spécifiés dans le masque de bits d'argument shmflg :

SHM_EXEC (spécifique à Linux ; depuis Linux 2.6.9)
Autorise l'exécution du contenu du segment. L'appelant doit avoir la permission d'exécution sur le segment.
SHM_RDONLY
Attache le segment en lecture seule. Le processus doit avoir la permission de lecture sur le segment. Si cet indicateur n'est pas spécifié, le segment est attaché en lecture et écriture, et le processus doit avoir les permissions de lecture et d'écriture pour le segment. Il n'y a pas de notion de segment de mémoire partagée en écriture seule.
SHM_REMAP (spécifique à Linux)
Cet indicateur spécifie que le mappage du segment doit remplacer tout mappage existant dans la plage commençant à shmaddr et s'étendant sur la taille du segment. (Normalement, une erreur EINVAL serait renvoyée si un mappage existait déjà dans cette plage d'adresses.) Dans ce cas, shmaddr ne doit pas être NULL.

La valeur brk(2) du processus appelant n'est pas modifiée par l'attachement. Le segment sera automatiquement détaché à la sortie du processus. Le même segment peut être attaché en lecture et en lecture-écriture, et plus d'une fois, dans l'espace d'adressage du processus.

Un appel réussi à shmat() met à jour les membres de la structure shmid_ds (voir shmctl(2)) associée au segment de mémoire partagée comme suit :

•
shm_atime est défini à l'heure actuelle.
•
shm_lpid est défini à l'identifiant du processus appelant.
•
shm_nattch est incrémenté de un.

shmdt()

shmdt() détache le segment de mémoire partagée situé à l'adresse spécifiée par shmaddr de l'espace d'adressage du processus appelant. Le segment à détacher doit être actuellement attaché avec shmaddr égal à la valeur renvoyée par l'appel shmat() d'attachement.

Lors d'un appel réussi à shmdt(), le système met à jour les membres de la structure shmid_ds associée au segment de mémoire partagée comme suit :

•
shm_dtime est défini à l'heure actuelle.
•
shm_lpid est défini à l'identifiant du processus appelant.
•
shm_nattch est décrémenté de un. S'il devient 0 et que le segment est marqué pour suppression, le segment est supprimé.

VALEUR RENVOYÉE

En cas de succès, shmat() renvoie l'adresse du segment de mémoire partagée attaché ; en cas d'erreur, (void *) -1 est renvoyé, et errno est défini pour indiquer l'erreur.

En cas de succès, shmdt() renvoie 0 ; en cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

shmat() peut échouer avec l'une des erreurs suivantes :

EACCES
Le processus appelant n'a pas les permissions requises pour le type d'attachement demandé, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EIDRM
shmid pointe vers un identifiant supprimé.
EINVAL
Valeur shmid invalide, adresse non alignée (c'est-à-dire non alignée sur une page et SHM_RND non spécifié) ou valeur shmaddr invalide, ou impossible d'attacher le segment à shmaddr, ou SHM_REMAP a été spécifié et shmaddr était NULL.
ENOMEM
Impossible d'allouer de la mémoire pour le descripteur ou pour les tables de pages.

shmdt() peut échouer avec l'une des erreurs suivantes :

EINVAL
Il n'y a aucun segment de mémoire partagée attaché à shmaddr ; ou, shmaddr n'est pas aligné sur une limite de page.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001, SVr4.

Dans SVID 3 (ou peut-être avant), le type de l'argument shmaddr a été modifié de char * à const void *, et le type renvoyé par shmat() de char * à void *.

POSIX.1-2024 a modifié le code d'erreur de (void *) -1 à SHM_FAILED.

NOTES

Après un fork(2), l'enfant hérite des segments de mémoire partagée attachés.

Après un execve(2), tous les segments de mémoire partagée attachés sont détachés du processus.

Lors de _exit(2), tous les segments de mémoire partagée attachés sont détachés du processus.

L'utilisation de shmat() avec shmaddr égal à NULL est la manière préférée et portable d'attacher un segment de mémoire partagée. Soyez conscient que le segment de mémoire partagée ainsi attaché peut l'être à des adresses différentes dans des processus différents. Par conséquent, tous les pointeurs maintenus dans la mémoire partagée doivent être rendus relatifs (généralement à l'adresse de départ du segment), plutôt qu'absolus.

Sur Linux, il est possible d'attacher un segment de mémoire partagée même s'il est déjà marqué pour suppression. Cependant, POSIX.1 ne spécifie pas ce comportement et de nombreuses autres implémentations ne le prennent pas en charge.

Le paramètre système suivant affecte shmat() :

SHMLBA
Multiple de l'adresse de la limite inférieure du segment. Lorsque vous spécifiez explicitement une adresse d'attachement dans un appel à shmat(), l'appelant doit s'assurer que l'adresse est un multiple de cette valeur. Ceci est nécessaire sur certaines architectures, soit pour assurer de bonnes performances du cache CPU, soit pour s'assurer que les différents attachements du même segment ont des vues cohérentes dans le cache CPU. SHMLBA est normalement un multiple de la taille de page du système. (Sur de nombreuses architectures Linux, SHMLBA est identique à la taille de page du système.)

L'implémentation ne place aucune limite intrinsèque par processus sur le nombre de segments de mémoire partagée (SHMSEG).

EXEMPLES

Les deux programmes

shown below exchange a string using a shared memory segment. Further details about the programs are given below. First, we show a shell session demonstrating their use.

In one terminal window, we run the "reader" program, which creates a System V shared memory segment and a System V semaphore set. The program prints out the IDs of the created objects, and then waits for the semaphore to change value.


$ ./svshm_string_read;
shmid = 1114194
semid = 15

In another terminal window, we run the "writer" program. The "writer" program takes three command-line arguments: the IDs of the shared memory segment and semaphore set created by the "reader", and a string. It attaches the existing shared memory segment, copies the string to the shared memory, and modifies the semaphore value.


$ ./svshm_string_write 1114194 15 'Hello, world';

Returning to the terminal where the "reader" is running, we see that the program has ceased waiting on the semaphore and has printed the string that was copied into the shared memory segment by the writer:


Hello, world

Le fichier d'en-tête suivant est inclus par les programmes "reader" et "writer":


/* svshm_string.h
   Licensed under GNU General Public License v2 or later.
*/
#ifndef SVSHM_STRING_H
#define SVSHM_STRING_H
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/sem.h>
union semun {                   /* Used in calls to semctl() */
    int                 val;
    struct semid_ds     *buf;
    unsigned short      *array;
#if defined(__linux__)
    struct seminfo      *__buf;
#endif
};
#define MEM_SIZE 4096
#endif  // include guard

Programme source: svshm_string_read.c

Le programme "reader" crée un segment de mémoire partagée et un ensemble de sémaphores contenant un sémaphore. Il joint ensuite l'objet de mémoire partagée dans son espace d'adressage et initialise la valeur du sémaphore à 1. Enfin, le programme attend que la valeur du sémaphore devienne 0, puis affiche la chaîne qui a été copiée dans le segment de mémoire partagée par le "writer".


/* svshm_string_read.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(void)
{
    int            semid, shmid;
    char           *addr;
    union semun    arg, dummy;
    struct sembuf  sop;
    /* Create shared memory and semaphore set containing one
       semaphore.  */
    shmid = shmget(IPC_PRIVATE, MEM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1)
        err(EXIT_FAILURE, "shmget");
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0600);
    if (semid == -1)
        err(EXIT_FAILURE, "semget");
    /* Attach shared memory into our address space.  */
    addr = shmat(shmid, NULL, SHM_RDONLY);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    /* Initialize semaphore 0 in set with value 1.  */
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1)
        err(EXIT_FAILURE, "semctl");
    printf("shmid = %d\n", shmid);
    printf("semid = %d\n", semid);
    /* Wait for semaphore value to become 0.  */
    sop.sem_num = 0;
    sop.sem_op = 0;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    /* Print the string from shared memory.  */
    printf("%s\n", addr);
    /* Remove shared memory and semaphore set.  */
    if (shmctl(shmid, IPC_RMID, NULL) == -1)
        err(EXIT_FAILURE, "shmctl");
    if (semctl(semid, 0, IPC_RMID, dummy) == -1)
        err(EXIT_FAILURE, "semctl");
    exit(EXIT_SUCCESS);
}

Programme source: svshm_string_write.c

Le programme "writer" prend trois arguments de ligne de commande : les identifiants du segment de mémoire partagée et de l'ensemble de sémaphores qui ont déjà été créés par le "reader", et une chaîne de caractères. Il joint le segment de mémoire partagée dans son espace d'adressage, puis décrémente la valeur du sémaphore à 0 afin d'informer le "reader" qu'il peut maintenant examiner le contenu de la mémoire partagée.


/* svshm_string_write.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(int argc, char *argv[])
{
    int            semid, shmid;
    char           *addr;
    size_t         size;
    struct sembuf  sop;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s shmid semid string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    size = strlen(argv[3]) + 1;  /* +1 to include trailing '\0' */
    if (size > MEM_SIZE) {
        fprintf(stderr, "String is too big!\n");
        exit(EXIT_FAILURE);
    }
    /* Get object IDs from command-line.  */
    shmid = atoi(argv[1]);
    semid = atoi(argv[2]);
    /* Attach shared memory into our address space and copy string
       (including trailing null byte) into memory.  */
    addr = shmat(shmid, NULL, 0);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    memcpy(addr, argv[3], size);
    /* Decrement semaphore to 0.  */
    sop.sem_num = 0;
    sop.sem_op = -1;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    exit(EXIT_SUCCESS);
}
