FBB::SharedMemory(3bobcat) Mémoire partagée FBB::SharedMemory(3bobcat)

NOM

FBB::SharedMemory - Structure de mémoire pour la mémoire partagée

SYNTAXE

#include <bobcat/sharedmemory>
Option de liaison : -lbobcat

DESCRIPTION

La classe FBB::SharedMemory implémente une interface utilisable vers un segment de mémoire partagée rendu disponible par FBB::SharedSegment et surveillé par FBB::SharedPos. C'est le bloc de construction principal pour FBB::SharedBuf, définissant le « périphérique » auquel FBB::SharedBuf s'interface. Toutes les opérations d'E/S relatives à la mémoire partagée doivent être effectuées par des objets FBB::SharedMemory, qui sont de vrais objets, ne résidant pas eux-mêmes en mémoire partagée.

Un objet FBB::SharedMemory définit, se connecte et gère l'accès à la mémoire partagée, encapsulant toutes les opérations brutes de mémoire partagée. En plus de la classe FBB::SharedMemory, le fichier d'en-tête bobcat/sharedmemory définit également une struct SharedEnum__ définissant enum SizeUnit dans l'espace de noms FBB.

La quantité demandée de mémoire partagée est toujours une borne inférieure à la quantité maximale de mémoire partagée qui pourra éventuellement devenir disponible. Lors de la définition d'un objet SharedMemory, toute sa mémoire partagée potentiellement disponible n'est pas immédiatement allouée. La mémoire partagée sera allouée par l'objet SharedMemory une fois nécessaire (jusqu'à un maximum calculé).

À titre d'exemple fictif : supposons que 100 Ko de mémoire sont demandés. L'objet SharedMemory maintient alors une table de, par exemple, 10 entrées, chaque entrée contrôlant l'accès à un bloc de mémoire partagée de 10 Ko. Ces blocs de 10 Ko ne sont pas immédiatement alloués, mais deviennent disponibles une fois que le programme lit ou écrit dans les adresses situées dans ces blocs de données. Les blocs de données nouvellement alloués sont initialisés à 0 octets.

Attention : lors de la construction d'un segment de mémoire partagée, assurez-vous que l'identifiant du segment est stocké dans un emplacement récupérable. Cela permet à d'autres processus d'accéder au segment partagé. L'identifiant du segment partagé est également requis pour supprimer un segment de mémoire partagée. Si l'identifiant du segment partagé est perdu, la mémoire occupée par le segment de mémoire partagée reste inaccessible (bien qu'elle puisse être récupérée et supprimée par des moyens supplémentaires, comme ipcs(1) et ipcrm(1)). Le membre id renvoie l'identifiant de la mémoire partagée actuellement surveillée par un objet FBB::SharedMemory.

ESPACE DE NOMS

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de noms FBB.

HERITE DE

FBB::SharedEnum__

La struct SharedEnum__ est une structure enveloppante autour de l'enum SizeUnit, qui est disponible par héritage dans plusieurs classes FBB::Shared*, et offre des constantes symboliques définissant des tailles de mémoire standard. L'enum SizeUnit définit les constantes symboliques suivantes :

o
kB, représentant 1024 (2**10) octets de mémoire ;
o
MB, représentant 1048576 (2**20) octets de mémoire ;
o
GB, représentant 1073741824 (2**30) octets de mémoire

CONSTRUCTEURS, DESTRUCTEUR

o
SharedMemory() :
Le constructeur par défaut définit une stub vide, qui ne peut pas être utilisée immédiatement. Comme la classe SharedMemory prend en charge l'affectation par déplacement, les stubs vides peuvent facilement être (re)configurées à tout moment après leur construction.
o
SharedMemory(size_t maxSize, SizeUnit sizeUnit, size_t access = 0600) :
Ce constructeur crée un segment de mémoire partagée ayant une capacité d'au moins maxSize * sizeUnit octets. Les droits d'accès de la mémoire partagée sont définis par le paramètre access, en utilisant les valeurs octales bien connues (chmod(1)) pour définir les droits d'accès pour le propriétaire, le groupe et les autres. Si la construction réussit, la mémoire partagée est prête à être utilisée. Si la construction échoue, une FBB::Exception est levée.
o
SharedMemory(int id) :
Ce constructeur se connecte à un segment de mémoire partagée ayant l'identifiant id. Si la construction réussit, la mémoire partagée est prête à être utilisée. Si la construction échoue (par exemple, aucun segment de mémoire partagée ayant l'identifiant id n'existe), une FBB::Exception est levée.
o
~SharedMemory() :
Le destructeur détache tous les segments de mémoire partagée attachés de l'objet FBB::SharedMemory. Si le segment de mémoire partagée est actuellement verrouillé par l'objet FBB::SharedMemory, le verrou est supprimé.

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) ne sont pas disponibles.

OPERATEURS SURCHARGÉS

o
std::ostream &operator<<(std::ostream &out, SharedMemory const &sharedMemory) :
L'opérateur d'insertion surchargé insère des informations sur l'objet SharedMemory dans l'objet ostream fourni. Les identifiants des segments partagés, leurs tailles, le nombre maximum de segments de mémoire partagée, le nombre d'octets qui peuvent être lus à partir de la mémoire partagée, et sa capacité de stockage réelle, etc., sont affichés.
o
SharedMemory &operator=(SharedMemory &&rhs) :
L'opérateur d'affectation par déplacement surchargé est disponible. Il est utilisé pour (re)définir le segment de mémoire partagée auquel un objet FBB::SharedMemory s'interface.

FONCTIONS MEMBRES

o
size_t blockOffset() const :
Le décalage dans le bloc de données du segment partagé correspondant à la valeur de retour de offset est renvoyé. 0 est renvoyé si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée (ou si le décalage est le décalage 0 du bloc).
o
void clear() :
Premièrement, la mémoire partagée est verrouillée. Ensuite, tous les segments de données partagés sont supprimés, et les données de la mémoire partagée sont réinitialisées pour indiquer qu'elle est complètement vide. Après cela, le segment de mémoire partagée est déverrouillé à nouveau. En retournant de clear, la mémoire partagée, l'objet FBB::SharedMemory est effectivement réinitialisé, avec offset et nReadable renvoyant 0.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
size_t dataSegmentSize() const :
Renvoie la taille (en octets) du bloc de données de mémoire partagée. 0 est renvoyé si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int get() :
Premièrement, l'objet FBB::SharedMemory appelle lock pour verrouiller le segment de mémoire partagée. Ensuite, le caractère à offset est récupéré et offset est incrémenté. Puis unlock est appelé, et le caractère récupéré est renvoyé. Si offset est au moins égal à nReadable, EOF est immédiatement renvoyé.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int id() const :
L'identifiant du segment de mémoire partagée est renvoyé. Après kill, id renvoie -1, indiquant que le segment partagé ne peut plus être utilisé (notez que operator= peut être utilisé pour réinitialiser l'objet FBB::SharedMemory).

Params &&...params):
Ce membre a été implémenté comme un modèle de membre, utilisant typename SharedType et typename ...Params, permettant le transfert parfait des arguments vers le constructeur de SharedType.
Ce membre installe un objet SharedType dans la mémoire partagée de SharedMemory au premier décalage disponible : soit au décalage actuel, soit (si la taille de SharedType est trop grande pour tenir dans le bloc de données actuel au décalage) au premier octet du prochain bloc de données partagé de SharedSegment.
Le décalage réel où l'objet SharedType est installé est retourné dans *offset, à moins qu'un nullptr ne soit passé comme premier argument de install.
Un pointeur vers le SharedType installé est retourné, avec shmem.offset pointant juste après le dernier octet de SharedType.
L'objet SharedType est installé en utilisant placement new. Par exemple, l'exemple suivant illustre comment un objet SharedMutex(3bobcat) peut être installé au premier emplacement possible de la mémoire partagée SharedMemory shmem : 
    std::streamsize offset;
    FBB::SharedMutex *mutexPtr = shmem.install<FBB::SharedMutex>(&offset);
Si l'objet installé doit être détruit, son destructeur doit être explicitement appelé. Par exemple, pour détruire le Mutex pointé par mutexPtr, utilisez mutexPtr->~SharedMutex().
Une FBB::Exception est levée si shmem n'a pas pu installer l'objet dans ses blocs de données de mémoire partagée.
o
void kill():
Sans verrouiller la mémoire partagée, toute la mémoire partagée contrôlée par l'objet SharedMemory est supprimée. L'objet SharedMemory devient inutilisable après le retour de kill, et son membre id retourne -1. Rien ne se passe si ce membre est appelé alors que l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
std::streamsize maxOffset() const:
Le décalage maximum possible qui peut être utilisé avec le segment de mémoire partagée est retourné. Les membres offset et nReadable ne dépassent jamais la valeur retournée par maxOffset. 0 est retourné si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
std::streamsize nReadable() const:
Le nombre de caractères (octets) qui peuvent être lus à partir du début de la mémoire partagée est retourné. 0 est retourné si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
std::streamsize offset() const:
Le décalage dans le segment de mémoire partagée (c'est-à-dire par rapport à la position ios::beg du segment) est retourné. 0 est retourné si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée (ou si le décalage se trouve au décalage 0 de la mémoire partagée).
o
char *ptr():
Retourne 0 si offset() == maxOffset(). Sinon, il retourne un pointeur vers le caractère à l'indice offset dans le segment de mémoire partagée.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int put(int ch):
Après avoir verrouillé le segment de données partagé approprié, ch est écrit à la position offset, et offset est incrémenté par la suite. Si ch == EOF, EOF est immédiatement retourné.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int read(Type *value):
Ce membre a été implémenté comme un modèle de membre. Il appelle le membre suivant, en convertissant Type * en char *, et en utilisant sizeof(Type) comme second argument. Le nombre d'octets effectivement lus est retourné. Ce membre retourne -1 si initialement offset était au moins égal à nReadable.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int read(char *data, std::streamsize len):
Tout en verrouillant le(s) segment(s) de données partagé(s) approprié(s), au maximum len octets sont lus à partir de la mémoire partagée, en commençant à offset. Les octets lus de la mémoire partagée sont stockés dans data. Le nombre d'octets effectivement lus est retourné. Ce membre retourne -1 si initialement offset était au moins égal à nReadable.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int read(std::ios::off_type offset, Type *value, std::ios::seekdir origin = std::ios::beg):
Ce membre a été implémenté comme un modèle de membre. Après avoir modifié le décalage de SharedMemory à offset (par rapport à origin), il appelle le premier membre read, en lui passant value. Le nombre d'octets effectivement lus est retourné. Ce membre retourne -1 si initialement offset était au moins égal à nReadable.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
void remove():
La mémoire partagée est verrouillée, après quoi toute la mémoire partagée contrôlée par l'objet FBB::SharedMemory est supprimée. L'objet FBB::SharedMemory est inutilisable après le retour de remove.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
std::ios::pos_type seek(std::ios::off_type offset, std::ios::seekdir origin = std::ios::beg):
Déplace la position offset par rapport à way. La valeur -1 est retournée lors d'une recherche avant le décalage 0 ou après maxOffset, sinon le décalage par rapport à la position de début de la mémoire partagée (c'est-à-dire offset pour origin == ios::beg) est retourné. 0 est retourné si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée (ou si le décalage se trouve au décalage 0 de la mémoire partagée).
o
std::streamsize showmanyc() const:
Le nombre de caractères qui peuvent être lus à partir du bloc de données du segment de mémoire partagée actuel est retourné. Ce membre interroge le nombre de caractères lisibles dans le segment de mémoire partagée. Ce nombre peut changer pendant l'exécution de ce membre. Afin de recevoir une valeur de retour stable, les fonctions appelantes doivent avoir obtenu un verrou sur le segment de mémoire partagée avant d'appeler ce membre. 0 est retourné si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée (ou si aucun caractère ne peut être lu actuellement).
o
void swap(SharedMemory &other):
Les objets FBB::SharedMemory actuel et other sont échangés.
o
bool truncate(std::streamsize offset):
Si offset ne dépasse pas la valeur retournée par nReadable, nReadable est changé en offset et true est retourné. Sinon, false est retourné et la valeur retournée par nReadable n'est pas modifiée.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int write(Type const *value):
Ce membre a été implémenté comme un modèle de membre. Il appelle le membre suivant, en convertissant Type const * en char const *, et en utilisant sizeof(Type) comme second argument. Le nombre d'octets effectivement écrits est retourné. Ce membre retourne -1 si initialement offset était au moins égal à maxOffset.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int write(char const *data, std::streamsize len):
L'objet FBB::SharedMemory appelle lock pour verrouiller la mémoire partagée, et écrit au maximum len octets dans la mémoire partagée, en commençant à offset. Ensuite, unlock est appelé. Le nombre d'octets effectivement écrits est retourné. La fonction membre retourne -1 si initialement offset est égal à maxOffset.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
o
int write(std::ios::off_type offset, Type const *value, std::ios::seekdir origin = std::ios::beg):
Ce membre a été implémenté comme un modèle de membre. Après avoir modifié le décalage de SharedMemory à offset (par rapport à origin), il appelle le premier membre write, en lui passant value. Le nombre d'octets effectivement écrits est retourné. Ce membre retourne -1 si initialement offset était au moins égal à maxOffset.
Une FBB::Exception est levée si l'objet SharedMemory n'a pas encore été connecté à un bloc de mémoire partagée.
