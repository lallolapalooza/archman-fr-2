NOM

addr2line - convertir les adresses ou symbole+décalage en noms de fichiers et numéros de ligne

SYNTAXE

addr2line [-a|--addresses]
[-b nom_bfd|--target=nom_bfd]
[-C|--demangle[=style]]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-e nom_fichier|--exe=nom_fichier]
[-f|--functions] [-s|--basename]
[-i|--inlines]
[-p|--pretty-print]
[-j|--section=nom]
[-H|--help] [-V|--version]
[adresse adresse ...]

DESCRIPTION

addr2line traduit les adresses ou les symboles+décalages en noms de fichiers et numéros de ligne. Étant donné une adresse ou un symbole+décalage dans un exécutable ou un décalage dans une section d'un objet déplaçable, il utilise les informations de débogage pour déterminer le nom du fichier et le numéro de ligne qui lui sont associés.

L'exécutable ou l'objet déplaçable à utiliser est spécifié avec l'option -e. Par défaut, il s'agit du fichier a.out. La section dans l'objet déplaçable à utiliser est spécifiée avec l'option -j.

addr2line a deux modes de fonctionnement.

Dans le premier, les adresses hexadécimales ou symbole+décalage sont spécifiées sur la ligne de commande, et addr2line affiche le nom du fichier et le numéro de ligne pour chaque adresse.

Dans le second, addr2line lit les adresses hexadécimales ou symbole+décalage depuis l'entrée standard, et affiche le nom du fichier et le numéro de ligne pour chaque adresse sur la sortie standard. Dans ce mode, addr2line peut être utilisé dans un pipeline pour convertir des adresses choisies dynamiquement.

Le format de la sortie est NOMFICHIER:NUMERO_LIGNE. Par défaut, chaque adresse d'entrée génère une ligne de sortie.

Deux options peuvent générer des lignes supplémentaires avant chaque ligne NOMFICHIER:NUMERO_LIGNE (dans cet ordre).

Si l'option -a est utilisée, alors une ligne avec l'adresse d'entrée est affichée.

Si l'option -f est utilisée, alors une ligne avec le NOMFONCTION est affichée. C'est le nom de la fonction contenant l'adresse.

Une option peut générer des lignes supplémentaires après la ligne NOMFICHIER:NUMERO_LIGNE.

Si l'option -i est utilisée et que le code à l'adresse donnée est présent en raison d'une inlining par le compilateur, des lignes supplémentaires seront affichées ensuite. Une ou deux lignes supplémentaires (si l'option -f est utilisée) seront affichées pour chaque fonction inlinée.

Alternativement, si l'option -p est utilisée, alors chaque adresse d'entrée génère une seule longue ligne de sortie contenant l'adresse, le nom de la fonction, le nom du fichier et le numéro de ligne. Si l'option -i a également été utilisée, alors toutes les fonctions inlinées seront affichées de la même manière, mais sur des lignes séparées et précédées du texte (inlined by).

Si le nom du fichier ou le nom de la fonction ne peuvent pas être déterminés, addr2line affichera deux points d'interrogation à leur place. Si le numéro de ligne ne peut pas être déterminé, addr2line affichera 0.

Lorsque symbole+décalage est utilisé, +décalage est facultatif, sauf lorsque le symbole est ambigu avec un nombre hexadécimal. Les symboles résolus peuvent être "mangled" (transformés) ou non, sauf que les symboles non transformés avec + ne sont pas autorisés.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes.

-a
--addresses
Affiche l'adresse avant les informations sur le nom de la fonction, le fichier et le numéro de ligne. L'adresse est imprimée avec un préfixe 0x pour l'identifier facilement.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objet est nom_bfd.
-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer le soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de "mangling". L'argument facultatif du style de déchiffrage peut être utilisé pour choisir un style de déchiffrage approprié pour votre compilateur.
-e nom_fichier
--exe=nom_fichier
Spécifie le nom de l'exécutable pour lequel les adresses doivent être traduites. Le fichier par défaut est a.out.
-f
--functions
Affiche les noms de fonctions ainsi que les informations sur le fichier et le numéro de ligne.
-s
--basenames
Affiche uniquement le nom de base de chaque nom de fichier.
-i
--inlines
Si l'adresse appartient à une fonction qui a été inlinée, les informations source pour toutes les portées englobantes jusqu'à la première fonction non inlinée seront également imprimées. Par exemple, si "main" inlinise "callee1" qui inlinise "callee2", et que l'adresse provient de "callee2", les informations source pour "callee1" et "main" seront également imprimées.
-j
--section
Lit les décalages relatifs à la section spécifiée au lieu des adresses absolues.
-p
--pretty-print
Rend la sortie plus conviviale : chaque emplacement est imprimé sur une seule ligne. Si l'option -i est spécifiée, les lignes pour toutes les portées englobantes sont précédées de (inlined by).
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du déchiffrage des chaînes. Étant donné que les formats de "mangling" de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour déchiffrer des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

Notez que cette option n'est effective que si l'option -C ou --demangle a été activée.

@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure par une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées

récursivement.
