NOM

SharedREADME - Description des classes de mémoire partagée Bobcat

DESCRIPTION

Les classes de mémoire partagée suivantes sont disponibles :

o
SharedBlock(3bobcat)
La classe SharedBlock(3bobcat) définit un petit objet constitué d'un SharedMutex et d'un identifiant (de segment partagé). Elle offre des fonctionnalités pour définir et récupérer l'identifiant, ainsi que pour verrouiller et déverrouiller le SharedMutex. Les objets SharedBlock sont utilisés par les objets SharedSegment(3bobcat) pour suivre les segments qui contiennent réellement les données de mémoire partagée. C'est une classe d'aide à la comptabilité.
o
SharedSegment(3bobcat)
La classe SharedSegment (cf. figure images/sharedsegment1.jpg) s'interface avec la mémoire partagée réelle. Sa fonction membre principale est le membre statique create, qui renvoie un pointeur vers un objet SharedMemory nouvellement alloué.
Le membre create reçoit en paramètres le nombre de blocs, la taille des segments alloués par SharedSegment et le mode d'accès du segment (tel qu'utilisé par, par exemple, chmod(1)). Il renvoie un pointeur vers le SharedSegment alloué et son ID (défini à l'aide d'un pointeur vers un int, passé comme premier paramètre).
Bien que la classe SharedSegment définisse un tableau d'un seul objet SharedBlock(3bobcat), elle contiendra en fait d_nBlocks objets SharedBlock. Le membre create alloue d'abord un bloc de mémoire brute de la taille totale requise. Ensuite, il initialise la première partie de cette mémoire partagée brute en utilisant le constructeur SharedSegment et le placement new. Ensuite, le reste de la mémoire partagée brute est initialisé avec d_nBlocks - 1 objets SharedBlock, à nouveau en utilisant le placement new (cf. figure images/sharedsegment2.jpg).
o
SharedPos(3bobcat)
La classe SharedPos(3bobcat) surveille les informations de position dans les segments de mémoire partagée gérés par les objets SharedSegment. SharedPos n'a qu'un constructeur par défaut, mais offre un membre reset recevant au moment de la construction un pointeur vers un objet SharedSegment.
o
SharedMemory(3bobcat)
La classe SharedMemory(3bobcat) offre l'interface standard pour la mémoire partagée, définissant des membres comme read, get, write et put. Elle s'interface avec un objet SharedSegment et utilise un objet SharedPos pour suivre les décalages de la SharedMemory.
Un objet SharedMemory réside lui-même dans la mémoire de travail d'un programme et non dans la zone de mémoire partagée de l'ordinateur. À tout moment, la SharedMemory charge au maximum un seul bloc réel du bloc de mémoire partagée géré par SharedSegment. La position actuelle dans la mémoire partagée gérée par SharedSegment est surveillée par le membre SharedBlock d_pos de la SharedMemory.
Après les opérations de lecture/écriture, le décalage est mis à jour en conséquence. Il n'y a qu'un seul décalage, qui est utilisé par les objets [IO]?SharedStream lors de la demande ou de la mise à jour des décalages. Un objet SharedMemory offre des protections contre une utilisation inappropriée. Par exemple, si aucune mémoire n'a encore été allouée, il peut lancer des exceptions. De plus, les décalages ne peuvent jamais dépasser le décalage maximal possible de la SharedMemory.
o
SharedMutex(3bobcat)
La classe SharedMutex implémente un mutex non récursif qui peut être stocké en mémoire partagée. Elle offre simplement des membres lock et unlock. Dans un même thread, lock ne devrait jamais être appelé de manière répétée à moins que unlock ne soit appelé en premier. Le membre unlock peut être appelé de manière répétée sans risque ; une fois le mutex déverrouillé, les demandes répétées de déverrouillage du mutex sont simplement ignorées. Lorsqu'un SharedMutex est détruit, il appelle unlock. Utilisez le membre install de SharedMemory pour définir un objet SharedMutex en mémoire partagée, et utilisez ptr->~SharedMutex() (où SharedMutex *ptr pointe vers l'objet SharedMutex) pour le détruire à nouveau.
o
SharedCondition(3bobcat)
La classe SharedCondition implémente une variable de condition et un mutex associé, tous deux créés en mémoire partagée contrôlée par un objet SharedMemory. Elle offre toutes les fonctionnalités de std::condition_variable. Un objet SharedCondition lui-même est défini dans la mémoire de travail d'un thread, mais s'interface avec un objet `Condition` contenant une variable de condition et un mutex qui sont installés en mémoire partagée. La taille de cet objet `Condition` est renvoyée par le membre statique SharedCondition::size. Les membres de SharedCondition garantissent que le thread a accès à l'objet `Condition` et que le décalage de la mémoire partagée n'a pas changé lors du retour des membres de SharedCondition.
o
SharedBuf(3bobcat)
La classe SharedBuf implémente une spécialisation de std::streambuf s'interfaçant avec un objet SharedMemory. En plus d'un constructeur par défaut qui est un stub vide, la classe offre des constructeurs qui s'interfacent immédiatement avec un objet SharedMemory, ainsi qu'un membre pour associer (ré)associer un objet SharedBuf à un objet SharedMemory.
o
SharedStream, ISharedStream, OSharedStream(3bobcat)
Ces classes de flux offrent des facilités de flux opérant sur la mémoire partagée maintenue par un objet SharedMemory. La classe SharedStream utilise le membre seek de SharedMemory pour seekp et seekg, et utilise le membre offset de SharedMemory pour tellp et tellg. Tous les objets de flux partagés, y compris ISharedStream, offrent un membre pour initialiser un SharedCondition
Un aperçu des segments de mémoire partagée actuellement définis est montré par la commande ipcs -ma. Pour supprimer un segment de mémoire partagée défini, la commande ipcrm -m <id> peut être utilisée, où <id> est l'identifiant du segment de mémoire partagée.

NAME

sharedreadme — Bobcat library general information.

DESCRIPTION

The Bobcat library is a set of classes and templates designed to support C++ developers. It provides a wide range of functionalities, from basic data structures to more advanced features like exception handling and utility functions. The library aims to simplify common programming tasks and improve code efficiency and readability.

Key features of the Bobcat library include:

  • Data Structures: Various containers and data management tools.
  • Utilities: Helper functions for string manipulation, file I/O, and more.
  • Exception Handling: A robust system for managing errors and exceptions.
  • Templates: Generic programming support for flexible and reusable code.

EXAMPLE

Here is a simple example demonstrating the usage of the Bobcat library:

#include <iostream>
#include <bobcat/string.hpp>

int main() {
    bobcat::String message = "Hello, Bobcat!";
    std::cout << message << std::endl;
    return 0;
}

To compile this example, you would typically link against the Bobcat library:

g++ your_file.cpp -lbobcat -o your_program

FILES

The Bobcat library's header files are typically installed in /usr/include/bobcat, and the compiled library files are found in /usr/lib.

SEE ALSO

Refer to the specific documentation for individual Bobcat components for more detailed information. The library's source code and examples can provide further insights.

BUGS

Please report any bugs or issues encountered to the project's issue tracker or mailing list.

NOM

sharedreadme — Informations générales sur la bibliothèque Bobcat.

DESCRIPTION

La bibliothèque Bobcat est un ensemble de classes et de modèles conçus pour supporter les développeurs C++. Elle fournit un large éventail de fonctionnalités, des structures de données de base aux fonctionnalités plus avancées comme la gestion des exceptions et les fonctions utilitaires. La bibliothèque vise à simplifier les tâches de programmation courantes et à améliorer l'efficacité et la lisibilité du code.

Les principales caractéristiques de la bibliothèque Bobcat incluent :

  • Structures de données : Divers conteneurs et outils de gestion des données.
  • Utilitaires : Fonctions d'aide pour la manipulation de chaînes de caractères, les entrées/sorties de fichiers, et plus encore.
  • Gestion des exceptions : Un système robuste pour gérer les erreurs et les exceptions.
  • Modèles : Support de la programmation générique pour un code flexible et réutilisable.

EXEMPLE

Voici un exemple simple démontrant l'utilisation de la bibliothèque Bobcat :

#include <iostream>
#include <bobcat/string.hpp>

int main() {
    bobcat::String message = "Bonjour, Bobcat!";
    std::cout << message << std::endl;
    return 0;
}

Pour compiler cet exemple, vous lieriez généralement la bibliothèque Bobcat :

g++ your_file.cpp -lbobcat -o your_program

FICHIERS

Les fichiers d'en-tête de la bibliothèque Bobcat sont typiquement installés dans /usr/include/bobcat, et les fichiers de bibliothèque compilés se trouvent dans /usr/lib.
