NOM

shp2pgsql - chargeur de shapefile vers postgis

SYNTAXE

shp2pgsql [options] shapefile [schema.]table

DESCRIPTION

Le chargeur de données shp2pgsql convertit les fichiers Shape d'ESRI en SQL exécutable pour l'insertion dans une base de données PostGIS/PostgreSQL.

Version : 1.1.5 (06/10/2006)

UTILISATION

Le <shapefile> est le nom du fichier shape, sans aucune extension. Par exemple, 'roads' serait le nom du shapefile comprenant les fichiers 'roads.shp', 'roads.shx' et 'roads.dbf'.

Le <nomdetable> est le nom (éventuellement qualifié par un schéma) de la table de base de données dans laquelle vous souhaitez stocker les données. Dans cette table, la géométrie sera placée dans la colonne 'geo_value' par défaut.

OPTIONS

Le chargeur a plusieurs modes de fonctionnement distingués par des indicateurs de ligne de commande :

(Notez que -a, -c, -d et -p sont mutuellement exclusifs.)

-d
Supprime la table de base de données avant d'en créer une nouvelle avec les données du fichier Shape.
-a
Ajoute des données du fichier Shape à la table de base de données. Notez que pour utiliser cette option afin de charger plusieurs fichiers, les fichiers doivent avoir les mêmes attributs et les mêmes types de données.
-c
Crée une nouvelle table et la remplit à partir du fichier Shape. C'est le mode par défaut.
-p
Produit uniquement le code SQL de création de table, sans ajouter de données réelles. Ceci peut être utilisé si vous avez besoin de séparer complètement les étapes de création de table et de chargement de données.
-D
Utilise le format "dump" de PostgreSQL pour les données de sortie. Ceci peut être combiné avec -a, -c et -d. Il est beaucoup plus rapide de charger que le format SQL "insert" par défaut. Utilisez ceci pour de très grands jeux de données.
-w
Produit le format WKT (Well-Known Text), au lieu de WKB (Well-Known Binary). Notez que cela peut introduire des dérives de coordonnées dues à une perte de précision.
-e
Exécute chaque instruction séparément, sans utiliser de transaction. Ceci permet de charger la majorité des données correctes lorsqu'il y a des géométries incorrectes qui génèrent des erreurs. Notez que cela ne peut pas être utilisé avec l'indicateur -D car le format "dump" utilise toujours une transaction.
-s [<SRID_ORIGINE>:]<SRID>
Crée et remplit les tables de géométrie avec le SRID spécifié. Si FROM_SRID est donné, les géométries seront reprojetées. La reprojection ne peut pas être utilisée avec -D.
-G
Utilise le type geography au lieu de geometry. Geography est utilisé pour stocker des données lat/lon. Actuellement, la seule référence spatiale supportée est 4326.
-g <colonne_geometrie>
Spécifie le nom de la colonne de géométrie (surtout utile en mode ajout).
-k
Conserve la casse des identifiants (colonnes, schémas et attributs). Notez que les attributs dans Shapefile sont généralement tous en MAJUSCULES.
-m <nomdefichier>
Spécifie un fichier contenant un ensemble de mappages de noms de colonnes (longs) vers des noms de colonnes DBF de 10 caractères. Le contenu du fichier est une ou plusieurs lignes de deux noms séparés par des espaces et sans espaces avant ou après :

NOMCOLONNE CHAMPDBF1\n
NOMDETRESLONGCHAMPDBF2\n

etc.

-i
Force tous les entiers à être des entiers 32 bits standard, ne crée pas de grands entiers 64 bits, même si la signature de l'en-tête DBF le justifie.
-S
Génère des géométries simples au lieu de MULTIgeometries. Les fichiers Shape ne font pas la différence entre LINESTRING et MULTILINESTRING, donc shp2pgsql génère des MULTILINESTRING par défaut. Cet indicateur produira des LINESTRING à la place, mais shp2pgsql échouera lorsqu'il rencontrera un vrai MULTILINESTRING. La même chose s'applique pour POLYGON vs MULTIPOLYGON.
-W <encodage>
Spécifie l'encodage des attributs du Shapefile. Si cette option est utilisée, la sortie sera encodée en UTF-8.
-I
Crée un index GiST sur la colonne de géométrie.
-N <politique>
Spécifie la politique de gestion des géométries NULL (insert, skip, abort).
-T <tablespace>
Spécifie le tablespace pour la nouvelle table. Les index utiliseront toujours le tablespace par défaut, sauf si le paramètre -X est également utilisé. La documentation PostgreSQL contient une bonne description sur quand utiliser des tablespaces personnalisés.
-X <tablespace>
Spécifie le tablespace pour les index de la nouvelle table. Ceci s'applique à l'index de clé primaire et à l'index spatial GIST si -I est également utilisé.
-?
Affiche les informations de version et d'utilisation.

INSTALLATION

Pour compiler le programme à partir des sources, exécutez simplement "make" dans le répertoire des sources. Copiez ensuite le binaire dans votre chemin de recherche shell (ou où vous le souhaitez). Ce texte est également disponible sous forme de page de manuel dans le répertoire ../doc/man/, prêt à être copié dans le chemin de recherche des manuels sur les systèmes unixoïdes.

EXEMPLES

Une session d'exemple utilisant le chargeur pour créer un fichier d'entrée et le téléverser pourrait ressembler à ceci :

# shp2pgsql shaperoads roadstable roadsdb > roads.sql
# psql -d roadsdb -f roads.sql

Une conversion et un téléversement peuvent être effectués en une seule étape en utilisant des pipes UNIX :

# shp2pgsql shaperoads roadstable roadsdb | psql -d roadsdb
