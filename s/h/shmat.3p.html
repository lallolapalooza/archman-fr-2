SHMAT(3P) Manuel du programmeur POSIX SHMAT(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

shmat — opération d'attachement de mémoire partagée XSI

SYNOPSIS

#include <sys/shm.h>
void *shmat(int shmid, const void *shmaddr, int shmflg);

DESCRIPTION

La fonction shmat() opère sur la mémoire partagée XSI (voir le volume Définitions de base de POSIX.1‐2017, Section 3.346, Objet de mémoire partagée). Il n'est pas spécifié si cette fonction interagit avec les installations de communication inter-processus temps réel définies dans la Section 2.8, Temps réel.

La fonction shmat() attache le segment de mémoire partagée associé à l'identifiant de mémoire partagée spécifié par shmid à l'espace d'adressage du processus appelant. Le segment est attaché à l'adresse spécifiée par l'un des critères suivants :

*
Si shmaddr est un pointeur nul, le segment est attaché à la première adresse disponible sélectionnée par le système.
*
Si shmaddr n'est pas un pointeur nul et (shmflg &SHM_RND) est non nul, le segment est attaché à l'adresse donnée par (shmaddr -((uintptr_t)shmaddr %SHMLBA)). Le caractère '%' est l'opérateur de reste en langage C.
*
Si shmaddr n'est pas un pointeur nul et (shmflg &SHM_RND) est 0, le segment est attaché à l'adresse donnée par shmaddr.
*
Le segment est attaché en lecture si (shmflg &SHM_RDONLY) est non nul et que le processus appelant a la permission de lecture ; sinon, si c'est 0 et que le processus appelant a la permission de lecture et d'écriture, le segment est attaché en lecture et écriture.

VALEUR DE RETOUR

En cas de succès, shmat() incrémente la valeur de shm_nattch dans la structure de données associée à l'ID de mémoire partagée du segment de mémoire partagée attaché et retourne l'adresse de début du segment. De plus, l'horodatage shm_atime est défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale de l'IPC.

Sinon, le segment de mémoire partagée n'est pas attaché, shmat() retourne (void *)-1, et errno est défini pour indiquer l'erreur.

ERREURS

La fonction shmat() échoue si :

EACCES
La permission d'opération est refusée au processus appelant ; voir la Section 2.7, Communication inter-processus XSI.
EINVAL
La valeur de shmid n'est pas un identifiant de mémoire partagée valide, shmaddr n'est pas un pointeur nul, et la valeur de (shmaddr -((uintptr_t)shmaddr %SHMLBA)) est une adresse illégale pour l'attachement de mémoire partagée ; ou shmaddr n'est pas un pointeur nul, (shmflg &SHM_RND) est 0, et la valeur de shmaddr est une adresse illégale pour l'attachement de mémoire partagée.
EMFILE
Le nombre de segments de mémoire partagée attachés au processus appelant dépasserait la limite imposée par le système.
ENOMEM
L'espace de données disponible n'est pas suffisant pour accueillir le segment de mémoire partagée.

USAGE APPLICATIF

L'extension temps réel POSIX définit des interfaces alternatives pour la communication inter-processus. Les développeurs d'applications qui doivent utiliser l'IPC devraient concevoir leurs applications de manière à ce que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication inter-processus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
