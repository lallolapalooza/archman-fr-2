DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PEs virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PEs de l'ensemble actif appellent la routine. Si un PE qui n'est pas dans l'ensemble actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PEs de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PEs de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie selon la version de la routine de réduction appelée. Lors d'un appel depuis C/C++, référez-vous à la section SYNTAXE pour les informations sur les types de données. Lors d'un appel depuis Fortran, les types de données cible sont les suivants :

shmem_int4_min_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_min_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_min_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_min_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_min_to_all : Réel, avec une taille d'élément de 16 octets

source Un tableau symétrique : de nreduce éléments, qui contient un
élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif de PEs. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs de l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PEs de l'ensemble actif n'entre dans la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble actif. Les mêmes tableaux cible et source, et les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PEs de l'ensemble actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PEs de l'ensemble actif ne sont plus utilisés depuis un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PEs de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les éléments suivants sont vrais pour le PE local : Le tableau cible est mis à jour. Les valeurs dans le tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs dans pSync avant de retourner, donc un tampon pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE de l'ensemble actif pendant que l'un des PEs participe au traitement d'une routine de réduction SHMEM. Faites attention aux situations suivantes : Si le tableau pSync est initialisé à l'exécution, un certain type de synchronisation est nécessaire pour s'assurer que tous les PEs de l'ensemble de travail ont initialisé pSync avant que l'un d'entre eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PEs de l'ensemble actif ne traite encore un appel de routine de réduction antérieur qui utilisait les mêmes tableaux pSync ou pWrk. En général, cela ne peut être assuré qu'en effectuant un certain type de synchronisation. Cependant, dans le cas particulier des routines de réduction appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors d'appels successifs.

DESCRIPTION

All of the routines in this section perform a reduction of the minimum of elements from the source arrays on a specified set of processing elements (PEs) to the corresponding elements of the target arrays on the same PEs. The reduction is across the PEs specified by the arguments PE_start, logPE_stride, and PE_size. The number of elements to be reduced is specified by nlong.

The reduction operation is the minimum function. The minimum operation is performed element-wise on the arrays.

The target and source arrays are local to each PE. The target array on each PE receives the result of the reduction.

The arguments PE_start, logPE_stride, and PE_size specify the set of PEs participating in the reduction. The PEs are indexed from 0 to num_pes() - 1. The reduction operation involves the PEs indexed as: PE_start, PE_start + 2^ logPE_stride, PE_start + 2 * 2^ logPE_stride, ..., up to PE_start + (PE_size - 1) * 2^ logPE_stride.

The argument nlong specifies the number of elements in the source and target arrays that will participate in the reduction. The minimum operation is performed element-wise on the arrays.

The arguments pWrk and pSync are pointers to working arrays. The pWrk array is used for intermediate storage during the reduction. The minimum size required for the pWrk array is given by the constant SHMEM_MIN_WRK. The pSync array is used for synchronization between PEs. The minimum size required for the pSync array is given by the constant SHMEM_SYNC.

All of the routines in this section require that the calling processing element (PE) be part of the set of PEs specified by the arguments PE_start, logPE_stride, and PE_size. If a PE is not part of the specified set, the behavior of the routine is undefined.

The reduction is performed in place on the target array. That is, the minimum value is stored in the target array.

The synchronization array pSync must be initialized with the value SHMEM_SYNC_VALUE on all participating PEs before the call to any of the minimum reduction routines. After the reduction is complete, the pSync array is reset to SHMEM_SYNC_VALUE on all participating PEs.

NOTES

The shmem_short_min_to_all, shmem_int_min_to_all, shmem_long_min_to_all, shmem_real32_min_to_all, shmem_real64_min_to_all, shmem_longdouble_min_to_all, shmem_int16_min_to_all, shmem_int32_min_to_all, and shmem_int64_min_to_all routines are collective subroutines and must be called by all PEs in the specified set of PEs. All calls within a specified set of PEs must have the same values for PE_start, logPE_stride, PE_size, and nlong.

The sizes of the pWrk and pSync arrays must be sufficient to perform the reduction. The minimum required sizes are given by the constants SHMEM_MIN_WRK and SHMEM_SYNC, respectively.

The shmem_real32_min_to_all routine operates on 32-bit real numbers (single precision floating point). The shmem_real64_min_to_all routine operates on 64-bit real numbers (double precision floating point). The shmem_longdouble_min_to_all routine operates on long double precision floating point numbers.

The shmem_int16_min_to_all routine operates on 16-bit integers. The shmem_int32_min_to_all routine operates on 32-bit integers. The shmem_int64_min_to_all routine operates on 64-bit integers.

The shmem_short_min_to_all routine operates on 16-bit integers (short integers).

The shmem_int_min_to_all routine operates on default integers.

The shmem_long_min_to_all routine operates on default long integers.

The pWrk and pSync arrays can be shared across multiple calls to reduction routines, provided that the calls do not overlap in their usage of the arrays. For example, if you call shmem_int_min_to_all with pWrk = wrk1 and pSync = sync1, you can then call shmem_int_min_to_all again with pWrk = wrk2 and pSync = sync2, where wrk1 and wrk2 are distinct arrays, and sync1 and sync2 are distinct arrays.

EXAMPLES

The following Fortran code performs a minimum reduction on the variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
