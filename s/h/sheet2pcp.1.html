SHEET2PCP(1) Manuel des commandes générales SHEET2PCP(1)

NOM

sheet2pcp - importer des données de tableur et créer une archive PCP

SYNTAXE

sheet2pcp [-h hôte] [-V version] [-Z fuseau_horaire] fichier_entree fichier_mapping fichier_sortie

DESCRIPTION

sheet2pcp est destiné à lire un tableur de données (fichier_entree) et à le traduire en une archive Performance Co-Pilot (PCP) dont le nom de base est fichier_sortie.

Le tableur d'entrée peut être dans l'un des formats courants, à condition que les modules Perl appropriés aient été installés (voir la section CAVEATS ci-dessous). Le tableur doit être « normalisé » de manière à ce que chaque ligne contienne des données pour le même intervalle de temps, et que l'une des colonnes contienne la date et l'heure des données de chaque ligne.

L'archive PCP résultante peut être utilisée avec tous les outils clients PCP pour générer des graphiques de sous-ensembles des données à l'aide de pmchart(1), effectuer des réductions de données et des rapports, filtrer avec le moteur d'inférence PCP pmie(1), etc.

Le fichier_mapping contrôle le processus d'importation et définit le mappage des données des colonnes du tableur vers le modèle de données PCP. Le fichier est écrit en XML et est conforme à la syntaxe définie dans la section CONFIGURATION DU MAPPING ci-dessous.

Une série de fichiers physiques seront créés avec le préfixe fichier_sortie. Ce sont fichier_sortie.0 (les données de performance), fichier_sortie.meta (les métadonnées qui décrivent les données de performance) et fichier_sortie.index (un index temporel pour améliorer l'efficacité des opérations de relecture de l'archive). Si l'un de ces fichiers existe déjà, alors sheet2pcp ne les écrasera pas et se terminera avec un message d'erreur.

L'option -h est une alternative à l'attribut hostname de l'élément <sheet> dans le fichier_mapping décrit ci-dessous. Si les deux sont spécifiés, la valeur du fichier_mapping est utilisée.

L'option -V spécifie la version de l'archive PCP de sortie. Par défaut, la version d'archive $PCP_ARCHIVE_VERSION (fixée à 3 dans les versions actuelles de PCP) est utilisée, et les seules valeurs actuellement prises en charge pour version sont 2 ou 3.

L'option -Z est une alternative à l'attribut timezone de l'élément <sheet> dans le fichier_mapping décrit ci-dessous. Si les deux sont spécifiés, la valeur du fichier_mapping est utilisée.

sheet2pcp est un script Perl qui utilise l'interface Perl PCP::LogImport enrobant la bibliothèque PCP libpcp_import, et à ce titre pourrait être utilisé comme exemple pour développer de nouveaux outils afin d'importer d'autres types de données de performance et de créer des archives PCP.

CONFIGURATION DU MAPPING

Le fichier_mapping contient des spécifications au format XML standard.

La spécification entière est encapsulée dans un élément <sheet> ... </sheet>. La balise sheet prend en charge les attributs optionnels suivants :

heading
Spécifie le nombre de lignes d'en-tête à ignorer au début du tableur avant de traiter les données. Exemple : heading="1".
hostname
Définit le nom d'hôte source dans l'archive PCP (par défaut, utilise le nom d'hôte de la machine locale). Exemple : hostname="quelque.part.com".
timezone
Définit le fuseau horaire source dans l'archive PCP (par défaut, utilise UTC). Le fuseau horaire doit avoir le format +HHMM (pour les heures et minutes à l'Est de l'UTC) ou -HHMM (pour les heures et minutes à l'Ouest de l'UTC). Notez en particulier que ni le format zoneinfo (alias Olson), par exemple Europe/Paris, ni le format Posix TZ, par exemple EST+5, ne sont autorisés. Exemple : timezone="+1100".
datefmt
Le format de la date importée du tableur peut être spécifié comme une concaténation de valeurs qui spécifient l'ordre de l'année (Y), du mois (M) et du jour (D) dans une date. Les variantes prises en charge sont DMY (par défaut), MDY et YMD. Exemple : datefmt="YMD".

Un élément <sheet> contient une ou plusieurs spécifications de métriques de la forme <metric>nom_metrique</metric>. La balise metric prend en charge les attributs optionnels suivants :

pmid
L'identifiant de métrique de performance (PMID), spécifié par 3 nombres séparés par des points (.) pour définir les champs domaine, cluster et item du PMID, voir PMNS(5) pour plus de détails sur les PMIDs. S'il est omis, le PMID sera attribué automatiquement par pmiAddMetric(3). La valeur PM_ID_NULL peut être utilisée pour spécifier explicitement le comportement par défaut. Exemples : pmid="60.0.2", pmid="PM_ID_NULL".
indom
Chaque métrique peut avoir une ou plusieurs valeurs. Si une métrique a toujours une seule valeur, elle est singulière et le Domaine d'Instance doit être défini sur PM_INDOM_NULL. Sinon, indom doit être spécifié par 2 nombres séparés par un point (.) pour définir les champs domaine et ordre du Domaine d'Instance. Exemples : indom="PM_INDOM_NULL", indom="60.3", indom="PMI_DOMAIN.4".

Plusieurs métriques peuvent partager le même Domaine d'Instance lorsque les métriques ont des valeurs définies sur des ensembles d'instances similaires, par exemple toutes les métriques pour chaque interface réseau. Il est d'usage que le champ domaine soit le même pour le pmid et pour l'indom ; si l'attribut pmid est manquant, alors le champ domaine pour l'indom doit être le domaine réservé PMI_DOMAIN.

Si l'attribut indom est omis, alors le Domaine d'Instance par défaut pour la métrique est PM_INDOM_NULL.

units
L'échelle et la dimension des valeurs de métriques le long des axes d'espace, de temps et de comptage (événements, messages, paquets, etc.) sont spécifiées avec un 6-uplet. Ces valeurs sont passées à la fonction pmiUnits(3) pour générer une structure pmUnits. Reportez-vous à pmLookupDesc(3) pour une description complète de tous les champs de cette structure. Par défaut, aucune échelle ou dimension n'est attribuée à la métrique, c'est-à-dire units="0,0,0,0,0,0". Exemples : units="0,1,0,0,PM_TIME_MSEC,0" (millisecondes), units="1,-1,0,PM_SPACE_MBYTE,PM_TIME_SEC,0" (Mbytes/sec), units="0,1,-1,0,PM_TIME_USEC,PM_COUNT_ONE" (microsecondes/événement).
type
Définit le type de données pour la métrique. Reportez-vous à pmLookupDesc(3) pour une description complète des valeurs de type possibles ; par défaut, il s'agit de PM_TYPE_FLOAT. Exemples : type="PM_TYPE_32", type="PM_TYPE_U64", type="PM_TYPE_STRING".
sem
Définit la sémantique de la métrique. Reportez-vous à pmLookupDesc(3) pour une description complète des valeurs possibles ; par défaut, il s'agit de PM_SEM_INSTANT. Exemples : sem="PM_SEM_COUNTER", type="PM_SEM_DISCRETE".

Les spécifications restantes définissent les colonnes de données dans l'ordre en utilisant exactement un élément <datetime></datetime>, un ou plusieurs éléments <data>spec_metrique</data> et un ou plusieurs éléments <skip></skip>.

L'élément <datetime> définit la colonne dans laquelle une date et une heure seront trouvées pour former l'horodatage dans l'archive PCP pour toutes les données de chaque ligne de l'archive PCP.

Pour l'élément <data>, une spec_metrique se compose d'un nom de métrique (défini dans un élément <metric> précédent), éventuellement suivi d'un nom d'instance encapsulé entre crochets, par exemple <data>hinv.ncpu</data>, <data>kernel.all.load[1 minute]</data>.

La balise skip définit la colonne qui doit être ignorée lors de la préparation des données pour l'archive PCP.

L'ordre des éléments <datetime>, <data> et <skip> correspond à l'ordre des colonnes dans le tableur

sheet2pcp(1) - Performance Co-Pilot

NAME

sheet2pcp – Convert spreadsheet archives to PCP archives

SYNOPSIS

sheet2pcp [options] infile

DESCRIPTION

The sheet2pcp utility reads performance metrics from a spreadsheet file (infile) and converts them into a set of Performance Co-Pilot (PCP) archives, suitable for loading via pmlogger(1).

The format of the spreadsheet is identified by the file extension. Currently supported formats are:

.csv
Comma Separated Value file. The first row may contain metric names, and subsequent rows contain timestamp and values. There should be one column for the timestamp and then one column for each desired metric value.
.sxc
OpenOffice.org .sxc spreadsheet file.
.ods
OpenDocument .ods spreadsheet file.
.xls
Microsoft Excel 97-2004 spreadsheet file.
.xlsx
Microsoft Excel 2007+ spreadsheet file.

The first column of the spreadsheet is always interpreted as the timestamp. The format of the timestamp is determined by Date::Parse(3pm).

The metric names may be specified in the first row of the spreadsheet, or they may be supplied via the --metric option. If supplied via the command line, the names must be provided in the same order as the columns in the spreadsheet. If the number of metric names supplied does not match the number of columns, an error will be generated.

If the first row of the spreadsheet is intended to be metric names, then this row will be skipped when processing the data. If the first row contains data, then the metric names specified via the command line will be used.

The metric values are expected to be numeric. Any non-numeric values will result in an error.

The output PCP archive is created in the current directory and is named using the base name of the infile, with suffix .1, e.g. mydata.1.

The following options are supported:

--align-column col
This option is used to align the metric values with specific columns in the spreadsheet. The default behaviour is to use all columns in the spreadsheet after the timestamp column. This option overrides the default behaviour and only uses the specified columns. The columns are numbered starting from 1.
--comment text
Add a comment to the PCP archive header.
--date
This option indicates that the first column is a date, rather than a full timestamp. This is useful for CSV files that only contain the date and not the time.
--help
Display a help message and exit.
--inname name
Use name as the input file name in the PCP archive header. The default is to use the actual file name.
--metric name
Use name as the metric name. This option can be specified multiple times to define multiple metric names. If this option is not specified, the metric names are taken from the first row of the spreadsheet.
--precision digits
Set the number of decimal places to use when writing floating point values to the PCP archive. The default is 3 decimal places.
--skip-row rows
Skip the specified number of rows from the beginning of the file. Default is 0. This is useful if the spreadsheet contains additional header information before the actual data or metric names.
--version
Display version information and exit.

MAPPING CONFIGURATION

The metric names in the spreadsheet are mapped to PCP metrics using the sheet2pcp mapping configuration format. This format is described in the LOGIMPORT(3) manual page.

When processing a spreadsheet, the sheet2pcp utility uses the metric names from the spreadsheet (or from the --metric option) to construct a temporary mapping configuration file. This file is then used by the pmiAddMetric(3) function to add the metrics to the PCP archive.

If the number of elements is not the same as the number of columns a warning is issued, and the extra elements or columns generate no metric values in the output archive.

EXAMPLE

The mapfile ...

    <?xml version="1.0" encoding="UTF-8"?>
    <sheet heading="1">
        <!-- simple example -->
        <metric pmid="60.0.2" indom="60.0" units="0,1,0,0,PM_TIME_MSEC,0"
            type="PM_TYPE_U64" sem="PM_SEM_COUNTER">
        kernel.percpu.cpu.sys</metric>
        <datetime></datetime>
        <skip></skip>
        <data>kernel.percpu.cpu.sys[cpu0]</data>
        <data>kernel.percpu.cpu.sys[cpu1]</data>
    </sheet>

could be used for a spreadsheet in which the first few rows are ...

    Date;"Status";"SysTime - 0";"SysTime - 1";
    26/01/2001 14:05:22;"Some Busy";0.750;0.133
    26/01/2001 14:05:37;"OK";0.150;0.273
    26/01/2001 14:05:52;"All Busy";0.733;0.653

CAVEATS

Only the first sheet from infile will be processed.

Additional Perl modules must be installed for the various spreadsheet formats, although these are checked for ar run-time so only the modules required for the specific types of spreadsheets you wish to process need be installed:

*.csv
Spreadsheets in the Comma Separated Values (CSV) format require Text::CSV_XS(3pm).
*.sxc or *.ods
OpenOffice documents require Spreadsheet::ReadSXC(3pm), which in turn requires Archive::Zip(3pm).
*.xls
Classical Microsoft Office documents require Spreadsheet::ParseExcel(3pm), which in turn requires OLE::Storage_Lite(3pm).
*.xlsx
Microsoft OpenXML documents require Spreadsheet::XLSX(3pm). sheet2pcp does not appear to work with OpenXML documents saved from OpenOffice.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
