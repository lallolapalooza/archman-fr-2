FBB::SharedSegment(3bobcat) Données de mémoire partagée FBB::SharedSegment(3bobcat)

NOM

FBB::SharedSegment - Structure de données de mémoire partagée

SYNTAXE

#include <bobcat/sharedsegment>
Option de liaison : -lbobcat

DESCRIPTION

La classe FBB::SharedSegment implémente la structure de données de mémoire partagée utilisée par les classes de mémoire partagée de Bobcat. La classe SharedMemory de Bobcat accède ou définit un segment de mémoire partagée, contrôlant toutes ses opérations de lecture et d'écriture.

La quantité de mémoire partagée demandée est toujours une limite inférieure à la quantité maximale de mémoire partagée qui peut éventuellement devenir disponible. Lors de la définition d'un objet SharedSegment, toute sa mémoire partagée potentiellement disponible n'est pas immédiatement allouée. La mémoire partagée sera allouée par l'objet SharedSegment une fois nécessaire (jusqu'à un maximum calculé).

À titre d'exemple fictif : supposons que 100 Ko de mémoire soient demandés, alors l'objet SharedSegment maintient une table, par exemple, de 10 entrées, chacune contrôlant l'accès à un bloc de mémoire partagée de 10 Ko. Ces blocs de 10 Ko ne sont pas immédiatement alloués, mais deviennent disponibles une fois que le programme lit ou écrit dans des adresses situées dans ces segments de données.

La classe SharedSegment définit donc une passerelle, contrôlant l'accès et allouant les segments de données de mémoire partagée requis. La table mentionnée se compose de nBlocks SharedBlock (sharedblock(3bobcat)) valeurs, offrant des mutex et des identifiants de segments de données partagés. Les mutex contrôlent quel processus a accès à un bloc particulier de mémoire de données partagée, et les identifiants sont soit -1, signifiant que leurs segments de données de mémoire partagée n'ont pas encore été alloués, soit ils contiennent les identifiants des segments de données de mémoire partagée définis.

La seule responsabilité de la classe SharedSegment est d'offrir le cadre tel que décrit. Lorsqu'elle est utilisée par un objet FBB::SharedMemory, différents processus peuvent accéder à différentes parties des données de mémoire partagée sans interférer avec les actions de lecture et d'écriture des autres.

sharedsegment(3bobcat)

NAME

sharedsegment - shared memory segment class

SYNOPSIS

#include <bobcat/sharedsegment>

namespace FBB {

template <class Type>
class SharedSegment {
    // ...
    public:
        // ...
        static Type *attach(int id);
        static Type *attach(int id, size_t size);
        static Type *attach(int id, size_t size, mode_t mode);
        static Type *attach(int id, size_t size, mode_t mode, char const *name = 0);
        static int createSegment(size_t size);
        static int createSegment(size_t size, char const *name);
        static int createSegment(size_t size, mode_t mode);
        static int createSegment(size_t size, mode_t mode, char const *name);
        static void deleteSegment(int id);
        template <class Type>
            Type *detach(Type *sharedPtr, bool requireOK = true);
        static size_t size(int id);
};

} // namespace FBB

DESCRIPTION

This class provides the functionality of shared memory segments.

Shared memory segments are identified by an integer ID. For instance, the value -1 represents an invalid ID.

Shared memory segments can be accessed by multiple processes. Creating shared memory segments is typically done by the createSegment member function.

The segment is created with a specified size and access mode. The access mode is a bitmask that defines the access rights for the owner, the group and others. For example, 0600 grants read and write permissions to the owner only.

Caveat: the access mode is only honored when the segment is created. When attaching to an existing segment, the access mode is ignored.

The createSegment function returns the ID of the created segment, or -1 if the segment could not be created. If a segment with the specified name already exists, its ID is returned instead of a new segment being created. Note that in this case, the specified size and mode parameters are ignored.

The attach member function attaches a shared memory segment to the calling process's address space. The segment is identified by its ID. The function returns a pointer to the shared memory segment. The second overload takes an optional size parameter which specifies the size of the segment to be mapped. This may be useful when a segment is attached by multiple processes, each of which may have a different view of the size of the segment. If this parameter is omitted, the size of the segment is determined from the system's shared memory configuration.

The third overload takes a mode parameter. This mode is used to control the creation of the shared memory segment if it does not already exist. If the segment exists, this mode is ignored.

The fourth overload takes both a size and a mode parameter.

The attach member function will throw an FBB::Exception if the shared memory segment cannot be attached.

The detach member function detaches a shared memory segment from the calling process's address space. The segment is identified by a pointer returned by a previous call to attach.

The size member function returns the size of a shared memory segment, identified by its ID.

ATTACHING TO AN EXISTING SEGMENT

When attaching to an existing segment, the size and mode parameters to attach are ignored. The actual size of the segment is determined by the system. The access mode is also ignored, as the segment already exists. However, if the segment does not exist, then the size and mode parameters are used to create the segment.

The mode parameter is a bitmask that defines the access rights for the owner, the group and others. It is used to set the file mode creation mode, as specified by chmod(1).

DELETING SHARED SEGMENTS

To return the shared segment to the operating system deleteSegment should be used.

An FBB::Exception is thrown if the shared memory data segment could not be created.

The shared memory segment having ID id is deleted. After calling deleteSegment shared memory segment id doesn’t exist anymore. The id can be the shared memory ID of any segment for which the current user has write permissions.

An FBB::Exception is thrown if shared memory data segment id could not be deleted.

This member is defined as a member template. It expects a pointer to a shared memory segment, previously mapped on the calling process’s memory space by attach, and detaches it from the process’s memory space, returning 0.

By default, detaching the memory must succeed or an FBB::Exception is thrown. Throwing an exception on failure can be prevented by passing false as the member's second argument.

Note that detaching a memory segment does not destroy it. To return a shared segment to the operating system deleteSegment should be used.

The size (in bytes) of shared memory data block having ID id is returned.

An FBB::Exception is thrown if the size of segment id could not be determined.
