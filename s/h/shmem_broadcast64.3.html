SHMEM_BROADCAST64(3) Open MPI SHMEM_BROADCAST64(3)

shmem_broadcast4(3), shmem_broadcast8(3), shmem_broadcast32(3), shmem_broadcast64(3) - Copie un objet de données d'une PE désignée vers un emplacement cible sur toutes les autres PEs de l'ensemble actif.

SYNTAXE

C ou C++ :

#include <mpp/shmem.h>
void shmem_broadcast32(void *target, const void *source,
  size_t nelems, int PE_root, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_broadcast64(void *target, const void *source,
  size_t nelems, int PE_root, int PE_start, int logPE_stride,
  int PE_size, long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER nelems, PE_root, PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_BCAST_SYNC_SIZE)
CALL SHMEM_BROADCAST4(target, source, nelems, PE_root,
& PE_start, logPE_stride, PE_size, fIpSync)
CALL SHMEM_BROADCAST8(target, source, nelems, PE_root,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_BROADCAST32(target, source, nelems,
& PE_root, PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_BROADCAST64(target, source, nelems,
& PE_root, PE_start, logPE_stride, PE_size, pSync)

DESCRIPTION

Les routines de diffusion (broadcast) écrivent les données à l'adresse source de la PE spécifiée par PE_root à l'adresse target sur toutes les autres PEs de l'ensemble actif. L'ensemble actif de PEs est défini par le triplet PE_start, logPE_stride et PE_size. Les données ne sont pas copiées à l'adresse cible sur la PE spécifiée par PE_root. Avant de retourner, les routines de diffusion s'assurent que les éléments du tableau pSync sont restaurés à leurs valeurs initiales.

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seules les PEs de l'ensemble actif appellent la routine. Si une PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

Les arguments sont les suivants :

cible
Un objet de données symétrique avec l'un des types de données suivants :
shmem_broadcast8, shmem_broadcast64 : Tout type non caractère qui
a une taille d'élément de 64 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.
shmem_broadcast32 : Tout type non caractère qui a une taille d'élément
de 32 bits. Aucun type dérivé Fortran ou structure C/C++ n'est autorisé.
shmem_broadcast4 : Tout type non caractère qui a une taille d'élément
de 32 bits.
source
Un objet de données symétrique qui peut être de tout type de données autorisé pour l'argument cible.
nelems
Le nombre d'éléments dans source. Pour shmem_broadcast32 et shmem_broadcast4, il s'agit du nombre de demi-mots de 32 bits. nelems doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_root
L'ordinal (numérotation à partir de zéro) de la PE, par rapport à l'ensemble actif, à partir de laquelle les données sont copiées. Doit être supérieur ou égal à 0 et inférieur à PE_size. PE_root doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PEs. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) de la cadence entre les numéros de PE virtuels consécutifs dans l'ensemble actif. log_PE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pSync
Un tableau de travail symétrique. En C/C++, pSync doit être de type long et de taille _SHMEM_BCAST_SYNC_SIZE. En Fortran, pSync doit être de type entier et de taille SHMEM_BCAST_SYNC_SIZE. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'une des PEs de l'ensemble actif n'entre dans shmem_barrier().

Les valeurs des arguments PE_root, PE_start, logPE_stride et PE_size doivent être égales sur toutes les PEs de l'ensemble actif. Les mêmes objets de données cible et source, et le même tableau de travail pSync doivent être passés à toutes les PEs de l'ensemble actif.

Avant qu'une PE n'appelle une routine de diffusion, vous devez vous assurer des conditions suivantes (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : le tableau pSync sur toutes les PEs de l'ensemble actif n'est pas encore utilisé lors d'un appel précédent à une routine de diffusion. Le tableau cible sur toutes les PEs de l'ensemble actif est prêt à recevoir les données diffusées.

Au retour d'une routine de diffusion, les éléments suivants sont vrais pour la PE locale : Si la PE actuelle n'est pas la PE racine, l'objet de données cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif et symétrique sont définis dans intro_shmem(3).

Toutes les routines de diffusion SHMEM restaurent pSync à son contenu d'origine. Des appels multiples à des routines SHMEM utilisant le même tableau pSync ne nécessitent pas que pSync soit réinitialisé après le premier appel.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour par une PE de l'ensemble actif pendant que l'une des PEs participe au traitement d'une routine de diffusion SHMEM. Faites attention à éviter ces situations : Si le tableau pSync est initialisé au moment de l'exécution, une forme de synchronisation est nécessaire pour garantir que toutes les PEs de l'ensemble de travail ont initialisé pSync avant que l'une d'entre elles n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync peut être réutilisé sur une routine de diffusion SHMEM ultérieure uniquement si aucune des PEs de l'ensemble actif ne traite encore un appel précédent à une routine de diffusion SHMEM qui utilisait le même tableau pSync. En général, cela ne peut être garanti qu'en effectuant une forme de synchronisation. Cependant, dans le cas spécial des routines SHMEM appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et alterner entre eux lors des appels successifs.

EXEMPLES

Dans les exemples suivants, l'appel à shmem_broadcast64 copie la source sur la PE 4 vers la cible sur les PEs 5, 6 et 7.

Exemple C/C++ :

for (i=0; i < _SHMEM_BCAST_SYNC_SIZE; i++) {
  pSync[i] = _SHMEM_SYNC_VALUE;
}
shmem_barrier_all(); /* Attendre que toutes les PEs initialisent pSync */
shmem_broadcast64(target, source, nelems, 0, 4, 0, 4, pSync);

Exemple Fortran :

INTEGER PSYNC(SHMEM_BCAST_SYNC_SIZE)
INTEGER TARGET, SOURCE, NELEMS, PE_ROOT, PE_START,
& LOGPE_STRIDE, PE_SIZE, PSYNC
COMMON /COM/ TARGET, SOURCE
DATA PSYNC /SHMEM_BCAST_SYNC_SIZE*SHMEM_SYNC_VALUE/
CALL SHMEM_BROADCAST64(TARGET, SOURCE, NELEMS, 0, 4, 0, 4,
& PSYNC)
