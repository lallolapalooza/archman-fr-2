FBB::SharedCondition(3bobcat) Variable de condition partagée FBB::SharedCondition(3bobcat)

NOM

FBB::SharedCondition - Variable de condition partagée en mémoire

SYNTAXE

#include <bobcat/sharedcondition>
Option de liaison : -lpthread, -lbobcat

DESCRIPTION

Les variables de condition sont utilisées pour synchroniser les threads en fonction des valeurs des données. Les variables de condition permettent aux threads d'attendre qu'une certaine condition soit remplie, après quoi les threads poursuivent leurs actions. Ainsi, les threads en attente n'ont pas besoin de sonder continuellement l'état d'une variable (ce qui oblige les threads à obtenir l'accès à la variable avant de pouvoir inspecter sa valeur). En utilisant des variables de condition, les threads en attente attendent simplement d'être notifiés.

Les objets SharedCondition peuvent être utilisés en combinaison avec la mémoire partagée. Les objets SharedCondition s'interfacent avec des objets (appelés objets Condition dans cette page de manuel) qui sont définis en mémoire partagée et contiennent un SharedMutex ainsi qu'un objet de condition partagé. Ces objets Condition peuvent être accédés par des threads s'exécutant dans différents processus. Ces différents processus peuvent exécuter un seul thread main, ou ils peuvent eux-mêmes être multithreadés.

Les variables de condition sont utilisées dans des situations comme celles-ci :

o
Il existe un thread qui doit être suspendu jusqu'à ce qu'une certaine condition soit remplie.
o
Ce thread verrouille un mutex (ou attend que le verrou soit obtenu)
o
Tant que la condition n'est pas remplie, le thread est suspendu (c'est-à-dire qu'il attend), libérant automatiquement le verrou du mutex.
o
D'une manière ou d'une autre (voir ci-dessous), le thread est repris, et à ce moment-là, le thread a automatiquement réacquis le verrou.
o
Une fois la condition remplie, la boucle while se termine et le verrou du mutex est libéré.
o
Il existe un second thread, qui influence les variables qui sont des éléments de la condition, et qui peut notifier le thread en attente une fois que la condition requise est remplie.
o
Ce second thread verrouille le même mutex que celui utilisé par le premier thread.
o
Le second thread modifie les variables impliquées, et si la condition requise est remplie, il notifie le premier thread.
o
Le second thread libère le verrou du mutex, permettant au premier thread d'obtenir le verrou du mutex.

Pendant que le premier thread attend, il est suspendu. Il peut être repris lorsqu'il reçoit une notification d'un autre thread, mais aussi pour des raisons fallacieuses. Par conséquent, le premier thread doit vérifier que la condition a été remplie après avoir repris ses actions.

Comme les variables de condition sont toujours utilisées en combinaison avec un mutex, SharedMutex encapsule la gestion du mutex. Le logiciel utilisant les objets SharedCondition n'a pas à gérer lui-même le mutex.

Les objets SharedCondition sont utilisés pour synchroniser les actions de différents processus, en utilisant la mémoire partagée comme véhicule de synchronisation/communication. La variable de condition réelle utilisée par un objet SharedCondition est définie en mémoire partagée. Les objets SharedCondition eux-mêmes sont de petits objets, contenant les informations nécessaires pour accéder à la variable de condition de mémoire partagée réelle.

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace nominal FBB.

CONSTRUCTEURS, DESTRUCTEUR

o
SharedCondition():
Le constructeur par défaut crée un stub vide qui ne peut pas encore être utilisé (ou une FBB::Exception est levée). Comme la classe SharedCondition prend en charge les opérateurs d'affectation, les stubs vides peuvent être facilement (re)configurés à tout moment après leur construction.
o
~SharedCondition():
Le destructeur de la classe libère (si applicable) son verrou sur le verrou du mutex de la variable de condition partagée. Le destructeur ne prend aucune action si son objet est un stub vide.

Les constructeurs par défaut, de copie et de déplacement ainsi que les opérateurs d'affectation de copie et de déplacement sont disponibles.

FONCTIONS MEMBRES

Lors du retour des fonctions membres de SharedCondition, l'offset de l'objet SharedMemory dans lequel la variable de condition a été définie n'a pas changé. Internement, l'offset courant est sauvegardé ; la fonction demandée est exécutée ; et l'offset d'origine est restauré. Par conséquent, les fonctions membres de SharedCondition peuvent être utilisées sans tenir compte de l'offset courant du SharedMemory.

o
void lock() const:
Lors du retour de ce membre, le processus courant a verrouillé l'objet SharedCondition. Faites attention à ne pas appeler lock deux fois au cours du même thread d'exécution (voir sharedmutex(3bobcat) pour plus de détails).
o
void notify() noexept:
L'un des threads en attente sur l'objet SharedCondition se réveille. Le thread appelant notify doit libérer son verrou mutex peu de temps après avoir appelé notify, permettant au thread notifié d'obtenir le verrou. Un exemple de pseudo-code illustrant l'utilisation de notify ressemble à ceci : 
    sharedCondition.lock();     // verrouiller le mutex
    ...                         // opérer sur les variables de la condition
    if (conditionSatisfaite)    // prêt à notifier
        sharedCondition.notify();
    sharedCondition.unlock();   // libérer le verrou
Comme la séquence sharedCondition.lock ... sharedCondition.unlock peut elle-même être exécutée à différentes sections de flux de contrôle, le membre unlock ne peut pas être appelé depuis notify.
o
void notifyAll() noexept:
Contrairement au membre notify simple, ce membre réveille tous les threads en attente sur l'objet SharedCondition. Cependant, une fois que le thread courant a libéré son verrou mutex, un seul de ces threads signalés obtiendra réellement le verrou. Le pseudo-code pour utiliser notifyAll est identique au pseudo-code pour utiliser notify (c'est-à-dire, en appelant notifyAll, bien sûr).
o
std::streamsize offset() const:
L'emplacement de la variable de condition partagée (au sein de l'objet SharedMemory) est renvoyé. L'objet de condition partagée se termine à offset() + SharedCondition::width(), voir ci-dessous.
o
void unlock() const:
Le verrou de l'objet est libéré (rien ne se passe si appelé alors que l'objet courant ne détient pas le verrou de l'objet).
o
void wait():
Avant d'appeler wait, le thread courant doit avoir obtenu un verrou sur l'objet SharedCondition.
Lors de l'appel de wait, le thread en cours suspend ses activités et attend d'être notifié. Une fois notifié, il réacquiert le verrou et continue. Peu de temps après, le processus doit à nouveau libérer son verrou sur l'objet SharedCondition. lock. Un exemple de pseudo-code illustrant comment utiliser wait ressemble à ceci : 
    sharedCondition.lock();         // verrouiller le mutex
    while (conditionPasAncoreSatisfaite) // attente requise
        sharedCondition.wait();
    ...                             // faire quelque chose : nous avons le verrou
    sharedCondition.unlock();       // libérer le verrou

o
std::cv_status wait_for(std::chrono::duration<Type, Unit> const &relTime) :
Ce membre a été implémenté en tant que modèle de membre. Type définit le type de la variable contenant la durée (généralement int64_t), spécifiée dans l'unité de temps Unit. Des types duration prédéfinis sont disponibles dans l'espace de noms std::chrono, comme std::chrono::seconds(4), représentant 4 secondes, ou std::chrono::milliseconds(30), représentant 30 millisecondes.
Le thread en cours d'exécution doit avoir obtenu un verrou sur SharedCondition avant d'appeler ce membre, et doit libérer le verrou après le retour de ce membre.
Ce membre agit comme wait, retournant std::cv_status::no_timeout si une notification a été reçue avant que relTime ne soit écoulé. Sinon, std::cv_status::timeout est renvoyé.
Un exemple prototypique de pseudo-code illustrant comment utiliser wait_for ressemble à ceci : 
    sharedCondition.lock();         // verrouiller le mutex
    while (conditionN’aPasAncoreEtéSatisfaite)   // attente requise
    {
        while (sharedCondition.wait_for(someTime)
               == std::cv_status::timeout)
            handle_timeout
        do_something
    }
    sharedCondition.unlock();       // libérer le verrou
Lors du retour de wait_for, le thread courant a obtenu le verrou de la condition partagée, mais peut-être en raison d'un délai d'attente : cela peut être vérifié en inspectant la valeur de retour de wait_for, et une action appropriée peut être sélectionnée.

Le pseudo-code pour utiliser ce membre est identique au pseudo-code pour utiliser le membre wait_for mentionné ci-dessus (bien que pred doive être passé à wait_for, bien sûr).
o
std::cv_status wait_until(std::chrono::time_point<Clock, Duration> const &absTime) :
Ce membre a été implémenté en tant que modèle de membre. Clock définit le type d'horloge à utiliser (généralement std::chrono::system_clock), Duration est le nom de type d'un type de durée (tel qu'utilisé avec wait_for). Par exemple, pour spécifier 5 secondes après l'heure actuelle, ce membre peut être appelé comme suit : 
    std::chrono::system_clock::now() + std::chrono::seconds(5)
Le thread en cours d'exécution doit avoir obtenu un verrou sur SharedCondition avant d'appeler ce membre, et doit libérer le verrou après le retour de ce membre.
Ce membre agit comme wait_for(relative-time), retournant std::cv_status::no_timeout si une notification a été reçue avant que absTime ne soit passé. Sinon, std::cv_status::timeout est renvoyé.
Le pseudo-code pour utiliser ce membre est identique au pseudo-code pour utiliser le membre wait_for(relative-time) mentionné ci-dessus (bien que le temps absolu doive être spécifié).
o

Ce membre a été implémenté en tant que modèle de membre. Clock et Duration définissent des types identiques tels que mentionnés dans le membre précédent. Predicate est une fonction prédicat ou un objet fonction prédicat (n'attendant pas d'arguments).
Le thread en cours d'exécution doit avoir obtenu un verrou sur SharedCondition avant d'appeler ce membre, et doit libérer le verrou après le retour de ce membre.
Tant que pred renvoie false, wait_until(absTime) est appelé. Si cette dernière fonction renvoie std::cv_status::timeout, alors pred est appelé, et sa valeur de retour est renvoyée. Sinon, true est renvoyé.
Le pseudo-code pour utiliser ce membre est identique au pseudo-code pour utiliser le membre wait_until mentionné ci-dessus (bien que pred doive être passé à wait_until, bien sûr).

FONCTIONS MEMBRES STATIQUES

o
SharedCondition &attach(SharedMemory &shmem, std::ios::off_type offset = 0, std::ios::seekdir origin = std::ios::beg) :
L'objet SharedCondition interconnectant la variable de condition partagée située à offset (par rapport à origin) dans shmem est retourné.
Une FBB::Exception est levée si l'offset demandé est invalide (c'est-à-dire inférieur à 0 ou dépassant shmem.maxOffset()).
o
FBB::SharedCondition create(SharedMemory &shmem) :
Une variable de condition partagée est initialisée au décalage actuel de l'objet SharedMemory référencé par shmem, ou au premier décalage du prochain segment de données partagées physiques.
Un objet SharedCondition interconnectant la variable de condition partagée initialisée est retourné.
Une FBB::Exception est levée s'il n'y a pas assez de mémoire disponible dans l'objet SharedMemory pour définir une variable de condition partagée.
o
size_t size() const :
Retourne la taille en octets des variables de condition partagées stockées dans les objets SharedMemory.

EXEMPLE

#include <iostream>
#include <bobcat/sharedcondition>
#include <bobcat/sharedmemory>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
try
{
    if (argc == 1)
    {
        cout <<
            "Argument:\n"
            "   c: créer un segment de mémoire partagée + SharedCondition "
                                                    ", afficher l'ID\n"
            "   k <id>: tuer le segment de mémoire partagé <id>\n"
            "   m <id>: afficher un message toutes les 5 secondes, sinon attendre\n"
            "           d'être notifié dans le segment <id>\n"
            "   n <id>: notifier la SharedCondition dans le segment ID <id>\n"
        ;
        return 0;
    }
    switch (argv[1][0])
    {
        case ’c’:
        {
            SharedMemory shmem(1, SharedMemory::kB);
            SharedCondition cond = SharedCondition::create(shmem);
            void *ptr = shmem.ptr();
            cout << "ID = " << shmem.id() << ", SharedCondition at " <<
                    cond.offset() << endl;
            break;
        }
        case ’k’:
        {
            SharedMemory shmem(stoll(argv[2]));
            shmem.kill();
            break;
        }
        case ’m’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cond.lock();
            cout << "Obtenu le verrou. En attente d'une notification\n";
            while (true)
            {
                switch (cond.wait_for(chrono::seconds(5)))
                {
                    case cv_status::timeout:
                        cout << "Attendu 5 secondes\n\n";
                    break;
                    case cv_status::no_timeout:
                        cond.unlock();
                        cout << "Notification reçue. Verroulié.\n";
                    return 0;
                }
            }
        }
        case ’w’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cond.lock();
            cout << "Obtenu le verrou. En attente d'une notification\n";
            cond.wait();
            cout << "Notification reçue. Déverrouillage.\n";
            cond.unlock();
            break;
        }
        case ’n’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cout << "Notification à l'autre après Appuyer sur Entrée ";
            cin.ignore(1000, ’\n’);
            cond.lock();
            cout << "Obtenu le verrou. Notification à l'autre\n";
            cond.notify();
            cout << "Notification envoyée. Déverrouillage.\n";
            cond.unlock();
            break;
        }
    }
}
catch (exception const &exc)
{
    cout << "Exception: " << exc.what() << endl;
}
