DESCRIPTION

Les routines de réduction de la mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

target
Un tableau symétrique de longueur nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de target varie selon la version de la routine de réduction appelée et la langue utilisée. Lors de l'appel depuis C/C++, reportez-vous à la section SYNOPIS pour les informations sur les types de données. Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :
shmem_comp4_prod_to_all : Complexe, avec une taille d'élément égale à deux
Valeurs réelles de 4 octets.
shmem_comp8_prod_to_all : Complexe, avec une taille d'élément égale à deux
Valeurs réelles de 8 octets.

shmem_int4_prod_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_prod_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_prod_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_prod_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_prod_to_all : Réel, avec une taille d'élément de 16 octets

source
Un tableau symétrique, de longueur nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que target.
nreduce
Le nombre d'éléments dans les tableaux target et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que target. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Avant que l'un des PE de l'ensemble actif n'entre dans la routine de réduction, chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran).

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE de l'ensemble actif. Les mêmes tableaux target et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être transmis à tous les PE de l'ensemble actif. Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour s'assurer de cela) : Les tableaux pWrk et pSync sur tous les PE de l'ensemble actif ne sont plus utilisés par un appel antérieur à une routine collective SHMEM. Le tableau target sur tous les PE de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les conditions suivantes sont vraies pour le PE local : Le tableau target est mis à jour. Les valeurs dans le tableau pSync sont restaurées aux valeurs d'origine.

SYNOPSIS

Fortran
SUBROUTINE SHMEM_COMPLEXD_PROD_TO_ALL(target, source, nreduce, PE_min, PE_max, logPE_stride, pWrk, pSync)
        REAL*8 target(*)
        REAL*8 source(*)
        INTEGER nreduce
        INTEGER PE_min
        INTEGER PE_max
        INTEGER logPE_stride
        REAL*8 pWrk(*)
        REAL*8 pSync(*)

C/C++
void shmem_complexd_prod_to_all(void *target, void *source, size_t nreduce, int PE_min, int PE_max, int logPE_stride, double *pWrk, double *pSync);

DESCRIPTION

The shmem_complexd_prod_to_all functions compute the product of a complex double-precision floating-point array on processing elements (PEs) in the symmetric heap and place the results in the target array on all PEs in the specified range. The computation is performed across the PEs specified by the range [PE_min, PE_max] with a stride of 2logPE_stride.

The elements of the array are accessed based on the PE indices within the specified range. The elements of the source array are combined pairwise with the elements of the target array in a reduction operation. The source array contains the values to be reduced, and the target array contains the initial values and receives the final result.

The reduction operation is a product. The elements in the source array are multiplied with the corresponding elements in the target array.

The PEs participating in the reduction are determined by `PE_min`, `PE_max`, and `logPE_stride`. `PE_min` is the smallest PE index that participates. `PE_max` is the largest PE index that participates. `logPE_stride` is the base-2 logarithm of the stride between PE indices.

The `pWrk` array is a work array used by the reduction routine. It must be large enough to support the reduction operation. The minimum size required for `pWrk` is specified by `SHMEM_REDUCE_MIN_WRKDATA_SIZE`.

The `pSync` array is a synchronization array used to ensure that all PEs participating in the reduction have reached a common point before proceeding. It must be initialized with the value `SHMEM_SYNC_VALUE` before the call. The size of the `pSync` array must be `SHMEM_REDUCE_SYNC_SIZE`.

NOTES

The `pSync` array must be initialized to `SHMEM_SYNC_VALUE` on all PEs before the routine is called. If the reduction routine is called multiple times, `pSync` must be re-initialized if any PE has not completed the previous reduction. This can be ensured by using synchronization primitives like `shmem_barrier_all()`.

The `pWrk` array is used for intermediate storage during the reduction. Its contents are not guaranteed to be preserved across calls to reduction routines unless the same `pWrk` array is used on successive calls without any intervening synchronization. If synchronization occurs between calls, the `pWrk` array may need to be re-initialized or a different `pWrk` array should be used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL*8 FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMPLEXD_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_complexd_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_complexd_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_complexd_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_complexd_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
