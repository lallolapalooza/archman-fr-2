SHELLCHECK(1) Manuel des commandes générales SHELLCHECK(1)

NOM

shellcheck - Outil d'analyse de scripts Shell

SYNTAXE

shellcheck [OPTIONS...] FICHIERS...

DESCRIPTION

ShellCheck est un outil d'analyse statique et de détection d'erreurs pour les scripts sh/bash. Il est principalement axé sur la gestion des erreurs de syntaxe et des pièges typiques pour les débutants et les intermédiaires, là où le shell donne un message d'erreur cryptique ou un comportement étrange, mais il signale également quelques problèmes plus avancés où les cas limites peuvent entraîner des échecs différés.

ShellCheck donne des conseils spécifiques au shell. Considérons la ligne suivante :

(( area = 3.14*r*r ))
•
Pour les scripts commençant par #!/bin/sh (ou en utilisant -s sh), ShellCheck signalera que (( .. )) n'est pas conforme à POSIX (similaire à checkbashisms).
•
Pour les scripts commençant par #!/bin/bash (ou en utilisant -s bash), ShellCheck signalera que les décimaux ne sont pas supportés.
•
Pour les scripts commençant par #!/bin/ksh (ou en utilisant -s ksh), ShellCheck ne signalera rien, car ksh prend en charge les décimaux dans les contextes arithmétiques.

OPTIONS

-a, --check-sourced
Émettre des avertissements dans les fichiers sourcés. Normalement, shellcheck ne signalera que les problèmes dans les fichiers spécifiés. Avec cette option, tout problème dans les fichiers sourcés sera également signalé.
-C[QUAND], --color[=QUAND]
Pour la sortie TTY, activer les couleurs toujours, jamais ou auto. La valeur par défaut est auto. --color sans argument est équivalent à --color=always.
-i CODE1[,CODE2...], --include=CODE1[,CODE2...]
Inclure explicitement uniquement les codes spécifiés dans le rapport. Les options -i suivantes sont cumulatives, mais tous les codes peuvent être spécifiés en une seule fois, séparés par des virgules comme un seul argument. Les options d'inclusion remplacent toutes les options d'exclusion fournies.
-e CODE1[,CODE2...], --exclude=CODE1[,CODE2...]
Exclure explicitement les codes spécifiés du rapport. Les options -e suivantes sont cumulatives, mais tous les codes peuvent être spécifiés en une seule fois, séparés par des virgules comme un seul argument.
--extended-analysis=true/false
Activer/désactiver l'analyse de flux de données pour identifier plus de problèmes (par défaut : vrai). Si ShellCheck utilise trop de CPU/RAM lors de l'analyse de scripts de plusieurs milliers de lignes, l'analyse étendue peut être désactivée avec ce drapeau ou une directive. Ce drapeau remplace les directives et les fichiers rc.
-f FORMAT, --format=FORMAT
Spécifier le format de sortie de shellcheck, qui imprime ses résultats sur la sortie standard. Les options -f suivantes sont ignorées, voir FORMATS ci-dessous pour plus d'informations.
--list-optional
Afficher une liste des vérifications optionnelles connues. Celles-ci peuvent être activées avec les options -o ou les directives enable.
--norc
Ne pas essayer de rechercher les fichiers de configuration .shellcheckrc.
--rcfile FICHIER_RC
Préférer le fichier de configuration spécifié plutôt que de le rechercher dans les emplacements par défaut.
-o NOM1[,NOM2...], --enable=NOM1[,NOM2...]
Activer les vérifications optionnelles. Le nom spécial all les active toutes. Les options -o suivantes s'accumulent. Ceci est équivalent à spécifier des directives enable.
-P CHEMIN_SOURCE, --source-path=CHEMIN_SOURCE
Spécifier les chemins à rechercher pour les fichiers sourcés, séparés par : sous Unix et ; sous Windows. Ceci est équivalent à spécifier des directives search-path.
-s shell, --shell=shell
Spécifier le dialecte du shell Bourne. Les valeurs valides sont sh, bash, dash, ksh, et busybox. La valeur par défaut est de déduire le shell de la directive shell du fichier, du shebang, ou de l'extension .bash/.bats/.dash/.ksh, dans cet ordre. sh fait référence à sh POSIX (pas celui du système), et signalera les problèmes de portabilité.
-S SEVERITE, --severity=severite
Spécifier la sévérité minimale des erreurs à prendre en compte. Les valeurs valides par ordre de sévérité sont error, warning, info et style. La valeur par défaut est style.
-V, --version
Afficher les informations de version et quitter.
-W NB, --wiki-link-count=NB
Pour la sortie TTY, afficher NB liens wiki vers plus d'informations sur les avertissements mentionnés. Définir à 0 pour les désactiver entièrement.
-x, --external-sources
Suivre les instructions source même lorsque le fichier n'est pas spécifié en entrée. Par défaut, shellcheck ne suivra que les fichiers spécifiés sur la ligne de commande (plus /dev/null). Cette option permet de suivre tout fichier que le script peut source.

Cette option peut également être activée en utilisant external-sources=true dans .shellcheckrc. Ce drapeau a priorité.

FICHIERS...
Un ou plusieurs fichiers de script à vérifier, ou "-" pour l'entrée standard.

FORMATS

tty
Sortie texte brut, lisible par l'homme. C'est la valeur par défaut.
gcc
Sortie compatible GCC. Utile pour les éditeurs qui prennent en charge la compilation et l'affichage des erreurs de syntaxe.

Par exemple, dans Vim, :set makeprg=shellcheck\ -f\ gcc\ % permettra d'utiliser :make pour vérifier le script, et :cnext pour passer à l'erreur suivante.

<fichier>:<ligne>:<colonne>: <type>: <message>
checkstyle
Sortie XML compatible Checkstyle. Prise en charge directement ou via des plugins par de nombreux IDE et systèmes de surveillance de build.
<?xml version='1.0' encoding='UTF-8'?>
<checkstyle version='4.3'>
  <file name='fichier'>
    <error
      line='ligne'
      column='colonne'
      severity='gravité'
      message='message'
      source='ShellCheck.SC####' />
    ...
  </file>
  ...
</checkstyle>
diff
Corrections automatiques au format diff unifié. Peut être redirigé vers git apply ou patch -p1 pour appliquer automatiquement les corrections.
--- a/test.sh
+++ b/test.sh
@@ -2,6 +2,6 @@
 ## Exemple d'un script défectueux.
 for f in $(ls *.m3u)
 do
-  grep -qi hq.*mp3 $f \
+  grep -qi hq.*mp3 "$f" \
     && echo -e 'La playlist $f contient un fichier HQ au format mp3'
 done
json1
JSON est un format de sérialisation populaire plus adapté aux applications web. Le JSON de ShellCheck est compact et ne contient que le strict minimum. Les tabulations sont comptées comme 1 caractère.
{
  commentaires: [
    {
      "fichier": "nom_fichier",
      "ligne": numero_ligne,
      "colonne": numero_colonne,
      "niveau": "niveau_gravite",
      "code": code_erreur,
      "message": "message_avertissement"
    },
    ...
  ]
}
json
Ceci est une version héritée du format json1. Il s'agit d'un tableau brut de commentaires, et tous les décalages ont une tabulation de 8.
quiet
Supprime toute sortie normale. S'arrête avec zéro si aucun problème n'est trouvé, sinon s'arrête avec un. Arrête le traitement après le premier problème.

DIRECTIVES

Les directives ShellCheck peuvent être spécifiées sous forme de commentaires dans le script shell. Si elles apparaissent avant la première commande, elles sont considérées comme s'appliquant à l'ensemble du fichier. Sinon, elles s'appliquent à la commande ou au bloc immédiatement suivant :

# shellcheck key=value key=value
commande-ou-structure

Par exemple, pour supprimer SC2035 concernant l'utilisation de ./*.jpg :

# shellcheck disable=SC2035
echo "Fichiers : " *.jpg

Pour indiquer à ShellCheck où chercher un fichier déterminé dynamiquement :

# shellcheck source=./lib.sh
source "$(trouver_repertoire_installation)/lib.sh"

Ici, un groupe d'accolades shell est utilisé pour supprimer un avertissement sur plusieurs lignes :

# shellcheck disable=SC2016
{
  echo 'Modification de PATH'
  echo 'PATH=foo:$PATH' >> ~/.bashrc
}

Les clés valides sont :

disable
Désactive une liste de codes d'erreur séparés par des virgules pour la commande suivante. La commande peut être une commande simple comme echo foo, ou une commande composée comme une définition de fonction, un bloc sous-shell ou une boucle. Une plage peut être spécifiée avec un tiret, par exemple disable=SC3000-SC4000 pour exclure les 3xxx. Tous les avertissements peuvent être désactivés avec disable=all.
enable
Active une vérification optionnelle par nom, telle que listée avec --list-optional. Seules les directives enable appliquées à l'ensemble du fichier sont prises en compte.
extended-analysis
Défini sur vrai/faux pour activer/désactiver l'analyse de flux de données. La spécification de # shellcheck extended-analysis=false dans des scripts générés automatiquement particulièrement volumineux (2000+ lignes) réduira l'utilisation des ressources de ShellCheck au détriment de certaines vérifications. L'analyse étendue est activée par défaut.
external-sources
Défini sur true dans .shellcheckrc pour toujours permettre à ShellCheck d'ouvrir des fichiers arbitraires à partir des instructions 'source' (la manière dont la plupart des outils le font).

Cette option est définie sur false par défaut uniquement en raison des origines de ShellCheck en tant que service distant pour vérifier des scripts non fiables. Elle peut être activée en toute sécurité pour le développement normal.

source
Remplace le nom de fichier inclus par une instruction source/.. Ceci peut être utilisé pour indiquer à shellcheck où chercher un fichier dont le nom est déterminé à l'exécution, ou pour ignorer une source en lui demandant d'utiliser /dev/null.
source-path
Ajoute un répertoire au chemin de recherche pour les instructions source/. (par défaut, seul le répertoire de travail de ShellCheck est inclus). Les chemins absolus seront également enracinés dans ces chemins. Le chemin spécial SCRIPTDIR peut être utilisé pour spécifier le répertoire du script actuellement vérifié, comme dans source-path=SCRIPTDIR ou source-path=SCRIPTDIR/../libs. Plusieurs chemins s'accumulent, et -P a la priorité sur eux.
shell
Remplace le shell détecté à partir du shebang. Ceci est utile pour les fichiers destinés à être inclus (et donc sans shebang), ou éventuellement comme alternative plus ciblée à 'disable=SC2039'.

FICHIERS RC

Sauf si --norc est utilisé, ShellCheck recherchera un fichier .shellcheckrc ou shellcheckrc dans le répertoire du script et dans chaque répertoire parent. S'il est trouvé, il lira les paires clé=valeur et les traitera comme des directives s'appliquant à l'ensemble du fichier.

Voici un exemple de .shellcheckrc :

# Rechercher les fichiers 'source' relativement au script vérifié,
# et rechercher également les chemins absolus dans /mnt/chroot
source-path=SCRIPTDIR
source-path=/mnt/chroot
# Depuis la version 0.9.0, les valeurs peuvent être mises entre guillemets '' ou "" pour autoriser les espaces
source-path="Mes Documents/scripts"
# Autoriser l'ouverture de tout fichier 'source'd, même s'il n'est pas spécifié comme entrée
external-sources=true
# Activer les avertissements pour les variables non citées avec des valeurs sûres
enable=quote-safe-variables
# Activer les avertissements pour les variables majuscules non assignées
enable=check-unassigned-uppercase
# Autoriser [ ! -z foo ] au lieu de suggérer -n
disable=SC2236

Si aucun .shellcheckrc n'est trouvé dans l'un des répertoires parents, ShellCheck recherchera dans ~/.shellcheckrc suivi de $XDG_CONFIG_HOME (généralement ~/.config/shellcheckrc) sur Unix, ou %APPDATA%/shellcheckrc sur Windows. Seul le premier fichier trouvé sera utilisé.

Note pour les utilisateurs de Snap : l'environnement sandbox de Snap interdit l'accès aux fichiers cachés. Utilisez shellcheckrc sans le point à la place.

Note pour les utilisateurs de Docker : ShellCheck ne pourra rechercher que les fichiers montés dans le conteneur, donc ~/.shellcheckrc ne sera pas lu.

VARIABLES ENVIRONNEMENT

La variable d'environnement SHELLCHECK_OPTS peut être définie avec des drapeaux par défaut :

export SHELLCHECK_OPTS='--shell=bash --exclude=SC2016'

Sa valeur sera divisée par des espaces et ajoutée avant la ligne de commande à chaque invocation.

VALEURS RETOUR

ShellCheck utilise les codes de sortie suivants :

•
0 : Tous les fichiers ont été analysés avec succès sans problème.
•
1 : Tous les fichiers ont été analysés avec succès avec quelques problèmes.
•
2 : Certains fichiers n'ont pas pu être traités (par exemple, fichier non trouvé).
•
3 : ShellCheck a été appelé avec une syntaxe incorrecte (par exemple, drapeau inconnu).
•
4 : ShellCheck a été appelé avec des options incorrectes (par exemple, formateur inconnu).

LOCALISATION

Cette version de ShellCheck n'est disponible qu'en anglais. Tous les fichiers sont décodés de manière flexible en UTF-8, avec un fallback en ISO-8859-1 pour les séquences invalides. LC_CTYPE est respecté pour la sortie, et est par défaut UTF-8 pour les locales où l'encodage n'est pas spécifié (comme la locale C).

Les utilisateurs Windows qui voient commitBuffer: invalid argument (invalid character) devraient définir leur terminal pour utiliser UTF-8 avec chcp 65001.

INCOMPATIBILITES CONNUES

(Si rien dans cette section n'a de sens, il est peu probable que vous en soyez affecté)

Pour éviter des suggestions confuses et malavisées, ShellCheck exige que les corps de fonction soient soit des { groupes d'accolades; }, soit des ( sous-shells ), et les noms de fonction contenant []*=! ne sont reconnus qu'après le mot-clé function.

Les définitions de fonction non conventionnelles suivantes sont identiques dans Bash, mais ShellCheck ne reconnaît que cette dernière.

[x!=y] () [[ $1 ]]
function [x!=y] () { [[ $1 ]]; }

Les shells sans le mot-clé function n'autorisent pas ces caractères dans les noms de fonction pour commencer. Les noms de fonction contenant {} ne sont pas du tout pris en charge.

De plus, si ShellCheck voit [x!=y], il supposera qu'il s'agit d'une comparaison invalide. Pour appeler la fonction ci-dessus, citez la commande comme dans '[x!=y]', ou pour conserver le même comportement de globage, utilisez command [x!=y].

ShellCheck impose des restrictions supplémentaires sur la commande [ pour aider à diagnostiquer les utilisations invalides courantes. Bien que [ $x= 1 ] soit défini dans POSIX, ShellCheck supposera qu'il était destiné à la comparaison beaucoup plus probable [ "$x" = 1 ] et échouera en conséquence. Pour des utilisations non conventionnelles ou dynamiques de la commande [, utilisez test ou \[ à la place.
