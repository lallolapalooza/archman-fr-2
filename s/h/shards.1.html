SHARDS(1) Manuel Shards SHARDS(1)

NOM

shards - gestionnaire de dépendances pour le langage Crystal

SYNTAXE

shards [<options_generales>...] [<commande>] [<options_commande>...]

DESCRIPTION

Gère les dépendances pour les projets et bibliothèques Crystal avec des installations reproductibles entre ordinateurs et systèmes.

UTILISATION

shards nécessite la présence d'un fichier shard.yml dans le dossier du projet (répertoire de travail). Ce fichier décrit le projet et liste les dépendances nécessaires à sa compilation. Voir shard.yml(5) pour plus d'informations sur son format. Un fichier par défaut peut être créé en exécutant shards init.

L'exécution de shards install résout et installe les dépendances spécifiées. Les versions installées sont écrites dans un fichier shard.lock pour utiliser exactement les mêmes versions de dépendances lors de la réexécution de shards install.

Si votre shard construit une application, shard.yml et shard.lock doivent être intégrés dans le système de contrôle de version pour fournir des installations de dépendances reproductibles. S'il s'agit uniquement d'une bibliothèque dont d'autres shards dépendent, shard.lock ne doit *pas* être intégré, seulement shard.yml. Il est conseillé de l'ajouter à .gitignore.

COMMANDES

Si aucune commande n'est fournie, la commande install sera exécutée par défaut.

Pour voir les options disponibles pour une commande particulière, utilisez --help après la commande.

build [<cibles>] [<options_compilation>...]

Compile les <cibles> spécifiées dans le répertoire bin. Si aucune cible n'est spécifiée, toutes sont compilées. Cette commande assure que toutes les dépendances sont installées, il n'est donc pas nécessaire d'exécuter shards install au préalable.

Toutes les <options_compilation> suivant la commande sont déléguées à crystal build.

check

Vérifie que toutes les dépendances sont installées et que les exigences sont satisfaites.

Statut de sortie :

0

Les dépendances sont satisfaites.

1

Les dépendances ne sont pas satisfaites.

init

Initialise un fichier shard.yml par défaut dans le dossier courant.

install [--frozen] [--without-development] [--production] [--skip-postinstall] [--skip-executables] [--jobs=N]

Résout et installe les dépendances dans le dossier lib. Si absent, génère un fichier shard.lock à partir des dépendances résolues, verrouillant les numéros de version ou les commits Git.

Lit et applique les versions et commits verrouillés si un fichier shard.lock est présent. La commande install peut échouer si une version verrouillée ne correspond pas à une exigence, mais peut réussir si une nouvelle dépendance a été ajoutée, tant qu'elle ne génère pas de conflit, générant ainsi un nouveau fichier shard.lock.

--frozen

Installe strictement les versions verrouillées depuis shard.lock. Échoue si shard.lock est manquant.

--without-development

N'installe pas les dépendances de développement.

--production

Identique à --frozen et --without-development.

--skip-postinstall

N'exécute pas les postinstallations des dépendances.

--skip-executables

N'installe pas les exécutables.

--jobs

Nombre de téléchargements de dépôts à effectuer en parallèle (défaut : 8). Actuellement uniquement pour git.

list [--tree]

Liste les dépendances installées et leurs versions.

Spécifier --tree organise les dépendances imbriquées dans un arbre, au lieu d'une liste aplatie.

lock [--update [<shards>...]]

Résout les dépendances et crée ou met à jour le fichier shard.lock comme avec la commande install, mais n'installe jamais les dépendances.

Spécifier --update suit la même sémantique que la commande update.

outdated [--pre]

Liste les dépendances obsolètes.

Lorsque --pre est spécifié, les versions de pré-version sont également prises en compte.

prune

Supprime les dépendances inutilisées du dossier lib.

update [<shards>...]

Résout et met à jour toutes les dépendances dans le dossier lib, quelles que soient les versions verrouillées dans le fichier shard.lock. Génère éventuellement un nouveau fichier shard.lock.

Spécifier shards mettra à jour uniquement ces dépendances, en essayant d'être aussi conservateur que possible avec les autres dépendances, en respectant les versions verrouillées dans le fichier shard.lock.

version [<chemin>]

Affiche la version actuelle du shard situé à chemin (par défaut, le répertoire courant).

Pour voir les options disponibles pour une commande particulière, utilisez --help après une commande.

OPTIONS GÉNÉRALES

--version

Affiche la version de shards.

-h, --help

Affiche le synopsis d'utilisation.

--no-color

Désactive la sortie colorée.

--local

Ne met pas à jour le cache du dépôt distant. Au lieu de cela, Shards utilisera les copies locales déjà présentes dans le cache (voir SHARDS_CACHE_PATH). La commande échouera si une dépendance est indisponible dans le cache.

-q, --quiet

Diminue la verbosité des journaux, n'affichant que les avertissements et les erreurs.

-v, --verbose

Augmente la verbosité des journaux, affichant tous les messages de débogage.

INSTALLATION

Shards est généralement distribué avec Crystal lui-même. Alternativement, un paquet shards séparé peut être disponible pour votre système.

Pour installer depuis les sources, téléchargez ou clonez le dépôt https://github.com/crystal-lang/shards et exécutez make CRFLAGS=--release. Le binaire compilé se trouve dans bin/shards et doit être ajouté à PATH.

VARIABLES D'ENVIRONNEMENT

SHARDS_OPTS

Permet de passer des options générales via une variable d'environnement. Exemple : SHARDS_OPTS="--no-color" shards update

SHARDS_CACHE_PATH

Définit l'emplacement du cache. Dans ce dossier, shards stocke les copies locales des dépôts distants. Par défaut, il s'agit de .cache/shards dans le répertoire personnel ($XDG_CACHE_HOME ou $HOME) ou le répertoire courant.

SHARDS_INSTALL_PATH

Définit l'emplacement où les dépendances sont installées. Par défaut, il s'agit de lib.

SHARDS_BIN_PATH

Définit l'emplacement où les exécutables sont installés. Par défaut, il s'agit de bin.

CRYSTAL_VERSION

Définit la version de Crystal pour laquelle les dépendances doivent être résolues. Par défaut, il s'agit de la sortie de crystal env CRYSTAL_VERSION.

SHARDS_OVERRIDE

Définit un emplacement alternatif pour shard.override.yml.

FICHIERS

shard.yml

Décrit un projet shard, y compris ses dépendances. Voir shard.yml(5) pour la documentation.

shard.override.yml

Permet de remplacer la source et les restrictions des dépendances. Un emplacement alternatif peut être configuré avec la variable d'environnement SHARDS_OVERRIDE.

Le fichier contient un document YAML avec une seule clé dependencies. Il a la même sémantique qu'en shard.yml. La configuration de la dépendance prime sur la configuration de shard.yml ou sur le shard.yml de toute dépendance.

shard.lock

Fichier de verrouillage qui stocke les informations sur les versions installées.
