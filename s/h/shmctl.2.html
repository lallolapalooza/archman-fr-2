shmctl(2) Manuel des appels système shmctl(2)

NOM

shmctl - Contrôle de la mémoire partagée System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/shm.h>
int shmctl(int shmid, int op, struct shmid_ds *buf);

DESCRIPTION

shmctl() effectue l'opération de contrôle spécifiée par op sur le segment de mémoire partagée System V dont l'identifiant est donné par shmid.

L'argument buf est un pointeur vers une structure shmid_ds, définie dans <sys/shm.h> comme suit :


struct shmid_ds {
    struct ipc_perm shm_perm;    /* Propriété et permissions */
    size_t          shm_segsz;   /* Taille du segment (octets) */
    time_t          shm_atime;   /* Heure du dernier attachement */
    time_t          shm_dtime;   /* Heure du dernier détachement */
    time_t          shm_ctime;   /* Heure de création/dernière
                                    modification via shmctl() */
    pid_t           shm_cpid;    /* PID du créateur */
    pid_t           shm_lpid;    /* PID du dernier shmat(2)/shmdt(2) */
    shmatt_t        shm_nattch;  /* # d'attachements actuels */
    ...
};

Les champs de la structure shmid_ds sont les suivants :

shm_perm
Il s'agit d'une structure ipc_perm (voir ci-dessous) qui spécifie les permissions d'accès au segment de mémoire partagée.
shm_segsz
Taille en octets du segment de mémoire partagée.
shm_atime
Heure du dernier appel système shmat(2) qui a attaché ce segment.
shm_dtime
Heure du dernier appel système shmdt(2) qui a détaché ce segment.
shm_ctime
Heure de création du segment ou de la dernière opération IPC_SET de shmctl().
shm_cpid
Identifiant du processus qui a créé le segment de mémoire partagée.
shm_lpid
Identifiant du dernier processus qui a exécuté un appel système shmat(2) ou shmdt(2) sur ce segment.
shm_nattch
Nombre de processus ayant ce segment attaché.

La structure ipc_perm est définie comme suit (les champs en gras sont modifiables avec IPC_SET) :


struct ipc_perm {
    key_t          __key;    /* Clé fournie à shmget(2) */
    uid_t          uid;      /* UID effectif du propriétaire */
    gid_t          gid;      /* GID effectif du propriétaire */
    uid_t          cuid;     /* UID effectif du créateur */
    gid_t          cgid;     /* GID effectif du créateur */
    unsigned short mode;     /* Permissions + drapeaux SHM_DEST et
                                SHM_LOCKED */
    unsigned short __seq;    /* Numéro de séquence */
};

Les 9 bits les moins significatifs du champ mode de la structure ipc_perm définissent les permissions d'accès au segment de mémoire partagée. Les bits de permission sont les suivants :

0400 Lecture par l'utilisateur
0200 Écriture par l'utilisateur
0040 Lecture par le groupe
0020 Écriture par le groupe
0004 Lecture par les autres
0002 Écriture par les autres

Les bits 0100, 0010 et 0001 (bits d'exécution) ne sont pas utilisés par le système. (Il n'est pas nécessaire d'avoir la permission d'exécution sur un segment pour effectuer un appel shmat(2) avec le drapeau SHM_EXEC.)

Les valeurs valides pour op sont :

IPC_STAT
Copie les informations de la structure de données du noyau associée à shmid dans la structure shmid_ds pointée par buf. L'appelant doit avoir la permission de lecture sur le segment de mémoire partagée.
IPC_SET
Écrit les valeurs de certains membres de la structure shmid_ds pointée par buf dans la structure de données du noyau associée à ce segment de mémoire partagée, mettant également à jour son membre shm_ctime.
Les champs suivants sont mis à jour : shm_perm.uid, shm_perm.gid, et (les 9 bits les moins significatifs de) shm_perm.mode.
L'UID effectif du processus appelant doit correspondre au propriétaire (shm_perm.uid) ou au créateur (shm_perm.cuid) du segment de mémoire partagée, ou l'appelant doit être privilégié.
IPC_RMID
Marque le segment pour destruction. Le segment sera effectivement détruit uniquement après que le dernier processus l'ait détaché (c'est-à-dire lorsque le membre shm_nattch de la structure associée shmid_ds est zéro).
L'appelant doit être le propriétaire ou le créateur du segment, ou être privilégié. L'argument buf est ignoré.
Si un segment a été marqué pour destruction, alors le drapeau SHM_DEST (non standard) du champ shm_perm.mode dans la structure de données associée récupérée par IPC_STAT sera positionné.
L'appelant *doit* s'assurer qu'un segment est éventuellement détruit ; sinon ses pages qui ont été déverrouillées resteront en mémoire ou en swap.
Voir également la description de /proc/sys/kernel/shm_rmid_forced dans proc(5).
IPC_INFO (spécifique à Linux)
Retourne des informations sur les limites et paramètres globaux du système de mémoire partagée dans la structure pointée par buf. Cette structure est de type shminfo (un transtypage est donc requis), définie dans <sys/shm.h> si le macro de test de fonctionnalité _GNU_SOURCE est définie :

struct shminfo {
    unsigned long shmmax; /* Taille maximale de segment */
    unsigned long shmmin; /* Taille minimale de segment;
                             toujours 1 */
    unsigned long shmmni; /* Nombre maximal de segments */
    unsigned long shmseg; /* Nombre maximal de segments
                             qu'un processus peut attacher;
                             inutilisé dans le noyau */
    unsigned long shmall; /* Nombre maximal de pages de
                             mémoire partagée, globalement */
};

Les paramètres shmmni, shmmax et shmall peuvent être modifiés via des fichiers /proc du même nom ; voir proc(5) pour plus de détails.
SHM_INFO (spécifique à Linux)
Retourne une structure shm_info dont les champs contiennent des informations sur les ressources système consommées par la mémoire partagée. Cette structure est définie dans <sys/shm.h> si le macro de test de fonctionnalité _GNU_SOURCE est définie :

struct shm_info {
    int           used_ids; /* # de segments actuellement
                               existants */
    unsigned long shm_tot;  /* Nombre total de pages de
                               mémoire partagée */
    unsigned long shm_rss;  /* # de pages de mémoire partagée
                               résidentes */
    unsigned long shm_swp;  /* # de pages de mémoire partagée
                               swappées */
    unsigned long swap_attempts;
                            /* Inutilisé depuis Linux 2.4 */
    unsigned long swap_successes;
                            /* Inutilisé depuis Linux 2.4 */
};

SHM_STAT (spécifique à Linux)
Retourne une structure shmid_ds comme pour IPC_STAT. Cependant, l'argument shmid n'est pas un identifiant de segment, mais plutôt un index dans le tableau interne du noyau qui maintient des informations sur tous les segments de mémoire partagée du système.

shmctl(2) — man pages

NOM

shmctl — interface de contrôle des segments de mémoire partagée

BIBLIOTHÈQUE

Interface de programmation système (API) – libc, version 6.

SYNTAXE

#include <sys/ipc.h>
#include <sys/shm.h>

int shmctl(int shmid, int cmd, struct shmid_ds *buf);

DESCRIPTION

La fonction shmctl effectue des opérations de contrôle sur un segment de mémoire partagée identifié par shmid. La nature exacte de l'opération est spécifiée par la valeur de l'argument cmd.

Les opérations suivantes sont disponibles :

IPC_STAT
Copie les informations associées au segment de mémoire partagée identifié par shmid dans la structure shmid_ds pointée par buf. L'appelant doit avoir des droits de lecture sur le segment (voir ERRORS).
IPC_SET
Modifie les champs spécifiés de la structure shmid_ds pointée par buf. Seuls les champs shm_perm.uid et shm_perm.gid (et shm_perm.mode dans les versions plus anciennes) peuvent être modifiés. L'appelant doit être l'utilisateur propriétaire du segment ou avoir la capacité CAP_IPC_OWNER.
IPC_RMID
Marque le segment de mémoire partagée pour suppression. La mémoire associée au segment sera libérée par le noyau lorsqu'aucun processus ne l'utilise plus (c'est-à-dire lorsque tous les processus qui l'ont attachée, voir shmat(2), l'ont détachée).

L'appelant doit être l'utilisateur propriétaire du segment ou avoir la capacité CAP_SYS_ADMIN.

Les opérations suivantes sont spécifiques à Linux :

SHM_STAT
Renvoie une structure shmid_ds comme pour IPC_STAT. Cependant, shmid est traité comme un index dans le tableau interne du noyau des segments de mémoire partagée, et non comme un ID de segment. Les informations peuvent être récupérées pour n'importe quel segment, mais seul le propriétaire ou un processus privilégié peut récupérer les informations sur tous les segments.
SHM_INFO
Renvoie une structure shminfo qui contient des informations sur les limites globales du système pour la mémoire partagée. L'argument shmid doit être 0. La structure shminfo est définie dans <sys/shm.h> et contient les champs suivants :

shmmax
Taille maximale en octets d'un segment de mémoire partagée.
shmmin
Taille minimale en octets d'un segment de mémoire partagée.
shmmni
Nombre maximal de segments de mémoire partagée dans le système.
shm_perm
Permet de contrôler l'accès aux informations sur tous les segments de mémoire partagée. Les informations sont copiées dans la structure shmid_ds pointée par buf. Le champ shm_perm.mode n'est pas vérifié pour l'accès en lecture pour shmid, ce qui signifie que n'importe quel utilisateur peut utiliser cette opération (tout comme n'importe quel utilisateur peut lire /proc/sysvipc/shm pour obtenir les mêmes informations).
SHM_LOCK (Linux-spécifique)
Empêche le swapping du segment de mémoire partagée. L'appelant doit charger toutes les pages requises en mémoire après le verrouillage. Si un segment a été verrouillé, alors le drapeau (non standard) SHM_LOCKED du champ shm_perm.mode dans la structure de données associée récupérée par IPC_STAT sera défini.
SHM_UNLOCK (Linux-spécifique)
Déverrouille le segment, lui permettant d'être swappé.

Avant Linux 2.6.10, seul un processus privilégié pouvait utiliser SHM_LOCK et SHM_UNLOCK. Depuis Linux 2.6.10, un processus non privilégié peut utiliser ces opérations si son UID effectif correspond à l'UID propriétaire ou créateur du segment, et (pour SHM_LOCK) si la quantité de mémoire à verrouiller se situe dans la limite de ressource RLIMIT_MEMLOCK (voir setrlimit(2)).

VALEUR RENVOYÉE

Une opération réussie IPC_INFO ou SHM_INFO renvoie l'index de la dernière entrée utilisée dans le tableau interne du noyau enregistrant les informations sur tous les segments de mémoire partagée. (Ces informations peuvent être utilisées avec des opérations répétées SHM_STAT ou SHM_STAT_ANY pour obtenir des informations sur tous les segments de mémoire partagée du système.) Une opération réussie SHM_STAT renvoie l'identifiant du segment de mémoire partagée dont l'index a été donné dans shmid. Les autres opérations renvoient 0 en cas de succès.

En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
IPC_STAT ou SHM_STAT est demandé et shm_perm.mode n'autorise pas l'accès en lecture pour shmid, et le processus appelant n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EFAULT
L'argument cmd a la valeur IPC_SET ou IPC_STAT mais l'adresse pointée par buf n'est pas accessible.
EIDRM
shmid pointe vers un identifiant supprimé.
EINVAL
shmid n'est pas un identifiant valide, ou cmd n'est pas une opération valide. Ou : pour une opération SHM_STAT ou SHM_STAT_ANY, la valeur d'index spécifiée dans shmid faisait référence à une slot de tableau actuellement inutilisée.
ENOMEM
(Depuis Linux 2.6.9), SHM_LOCK a été spécifié et la taille du segment à verrouiller entraînerait le dépassement de la limite des octets totaux dans les segments de mémoire partagée verrouillés pour l'UID réel du processus appelant. Cette limite est définie par la limite de ressource douce RLIMIT_MEMLOCK (voir setrlimit(2)).
EOVERFLOW
Tentative de IPC_STAT, et la valeur GID ou UID est trop grande pour être stockée dans la structure pointée par buf.
EPERM
Tentative de IPC_SET ou IPC_RMID, et l'UID effectif du processus appelant n'est ni celui du créateur (trouvé dans shm_perm.cuid), ni celui du propriétaire (trouvé dans shm_perm.uid), et le processus n'était pas privilégié (Linux : n'avait pas la capacité CAP_SYS_ADMIN).
Ou (avant Linux 2.6.9), SHM_LOCK ou SHM_UNLOCK a été spécifié, mais le processus n'était pas privilégié (Linux : n'avait pas la capacité CAP_IPC_LOCK). (Depuis Linux 2.6.9, cette erreur peut également survenir si RLIMIT_MEMLOCK est 0 et que l'appelant n'est pas privilégié.)

VERSIONS

Linux permet à un processus d'attacher (shmat(2)) un segment de mémoire partagée qui a déjà été marqué pour suppression à l'aide de shmctl(IPC_RMID). Cette fonctionnalité n'est pas disponible sur d'autres implémentations UNIX ; les applications portables doivent éviter de s'y fier.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Divers champs dans une struct shmid_ds étaient typés comme short sous Linux 2.2 et sont devenus long sous Linux 2.4. Pour en tirer parti, une recompilation sous glibc-2.1.91 ou ultérieure devrait suffire. (Le noyau distingue les anciens et les nouveaux appels par un drapeau IPC_64 dans cmd.)

NOTES

Les opérations IPC_INFO, SHM_STAT et SHM_INFO sont utilisées par le programme ipcs(1) pour fournir des informations sur les ressources allouées. À l'avenir, celles-ci pourraient être modifiées ou déplacées vers une interface du système de fichiers /proc.

VOIR AUSSI

mlock(2), setrlimit(2), shmget(2), shmop(2), capabilities(7), sysvipc(7)
