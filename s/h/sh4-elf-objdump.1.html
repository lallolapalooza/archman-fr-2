DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options contrôlent quelles informations spécifiques afficher. Ces informations sont surtout utiles aux programmeurs travaillant sur les outils de compilation, par opposition aux programmeurs qui veulent juste que leur programme compile et fonctionne.

fichierobjet... sont les fichiers objet à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objet membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme alternatives, sont équivalentes. Au moins une option parmi la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être donnée.

-a
--archive-header
Si l'un des fichiers fichierobjet est une archive, affiche les informations de l'en-tête de l'archive (dans un format similaire à ls -l). Outre les informations que vous pourriez lister avec ar tv, objdump -a montre le format du fichier objet de chaque membre de l'archive.
--adjust-vma=offset
Lors de l'affichage des informations, ajoute d'abord offset à toutes les adresses des sections. Ceci est utile si les adresses des sections ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise de sections à des adresses spécifiques en utilisant un format qui ne peut pas représenter les adresses de section, comme a.out.
-b bfdname
--target=bfdname
Spécifie que le format du code objet pour les fichiers objet est bfdname. Cette option n'est peut-être pas nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche des informations récapitulatives depuis les en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de "mangling". L'argument optionnel de style de déchiffrage peut être utilisé pour choisir un style approprié pour votre compilateur.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du déchiffrage des chaînes. Étant donné que les formats de "name mangling" permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite essaie d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour déchiffrer des noms réellement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Cela tente d'analyser les informations du format de débogage STABS stockées dans le fichier et de les afficher en utilisant une syntaxe similaire au C. Si aucun débogage STABS n'a été trouvé, cette option se rabat sur l'option -W pour afficher les informations DWARF dans le fichier.
-e
--debugging-tags
Similaire à -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques d'assembleur pour les instructions machine du fichier d'entrée. Cette option désassemble uniquement les sections qui sont censées contenir des instructions. Si l'argument optionnel symbole est donné, alors affiche les mnémoniques d'assembleur en commençant à symbole. Si symbole est un nom de fonction, le désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lorsque le symbole suivant est rencontré. S'il n'y a aucune correspondance pour symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

-D
--disassemble-all
Similaire à -d, mais désassemble

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

réassembler le contenu de toutes les sections non vides et non BSS, pas seulement celles qui sont censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est activée, objdump suppose que tous les symboles présents dans une section de code se situent sur la limite entre les instructions et refusera de désassembler au-delà d'une telle limite. Lorsque l'option -D est activée, cette hypothèse est supprimée. Cela signifie que la sortie de -d et -D peut différer si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur a également pour effet de forcer le désassembleur à décoder des morceaux de données trouvés dans les sections de code comme s'ils étaient des instructions.

Notez que si l'option --dwarf=follow-links est activée, alors toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lus et utilisés lors du désassemblage.

--no-addresses
Lors du désassemblage, n'imprimez pas les adresses sur chaque ligne ni pour les symboles et les décalages de réadressage. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, imprimez l'adresse complète sur chaque ligne. C'est l'ancien format de désassemblage.
-EB
-EL
--endian={big|little}
Spécifiez l'endianness des fichiers objet. Ceci n'affecte que le désassemblage. Ceci peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas d'informations d'endianness, tel que les enregistrements S.
-f
--file-headers
Affiche les informations récapitulatives de l'en-tête global de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage de sections, chaque fois qu'un symbole est affiché, affichez également le décalage de fichier de la région de données qui est sur le point d'être déversée. Si des zéros sont ignorés, alors lorsque le désassemblage reprend, indiquez à l'utilisateur combien de zéros ont été ignorés et le décalage de fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du déversement de sections, affichez le décalage de fichier de l'emplacement à partir duquel le déversement commence.
--file-start-context
Spécifiez que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, étendez le contexte au début du fichier.
-h
--section-headers
--headers
Affiche les informations récapitulatives des en-têtes de section du fichier objet.

Les segments de fichiers peuvent être déplacés vers des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata ou -Tbss de ld. Cependant, certains formats de fichiers objet, tels que a.out, ne stockent pas l'adresse de départ des segments de fichiers. Dans ces situations, bien que ld déplace correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section de fichier ne peut pas afficher les adresses correctes. Au lieu de cela, elle affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que, dans certains cas, une section peut avoir à la fois les attributs READONLY et NOREAD définis. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump affichera les deux, car le réglage exact des bits de drapeau peut être important.

-H
--help
Imprime un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant toutes les architectures et tous les formats d'objet disponibles pour la spécification avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non-debug trouvées dans des fichiers debuginfo séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom de fichier et les numéros de ligne source correspondant au code objet ou aux relocations affichés. Uniquement utile avec -d, -D ou -r.
-m machine
--architecture=machine
Spécifie l'architecture à utiliser lors du désassemblage des fichiers objet. Ceci peut être utile lors du désassemblage de fichiers objet qui ne décrivent pas d'informations d'architecture, tels que les enregistrements S. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par deux points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Ceci peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il restreint le désassemblage aux seules instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information d'architecture, mais que l'on souhaite également désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Passe des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plus d'une option de désassembleur, plusieurs options -M peuvent être utilisées ou regroupées dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'affichage des instructions DSP, spfp sélectionne l'affichage des instructions FP simple précision FPX, dpfp sélectionne l'affichage des instructions FP double précision FPX, quarkse_em sélectionne l'affichage des instructions spéciales QuarkSE-EM, fpuda sélectionne l'affichage des instructions d'assistance double précision, fpus sélectionne l'affichage des instructions FP simple précision FPU, tandis que fpud sélectionne l'affichage des instructions FP double précision FPU. De plus, on peut choisir d'afficher tous les immédiats en hexadécimal en utilisant hex. Par défaut, les immédiats courts sont affichés en représentation décimale, tandis que les valeurs immédiates longues sont affichées en hexadécimal.

cpu=... permet d'imposer un ISA particulier lors du désassemblage d'instructions, en remplaçant la valeur de -m ou ce qui se trouve dans le fichier ELF. Ceci peut être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur les données de l'en-tête ELF privé pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois - seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option -mcpu=... de l'assembleur.

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner le jeu de noms de registres utilisé pendant le désassemblage. Spécifier -M reg-names-std (par défaut) sélectionnera les noms de registres tels qu'utilisés dans la documentation du jeu d'instructions d'ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. Spécifier -M reg-names-apcs sélectionnera le jeu de noms utilisé par l'ARM Procedure Call Standard, tandis que spécifier -M reg-names-raw utilisera simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de nommage des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de nommage du Standard de Procédure d'Appel ARM/Thumb. (Avec soit les noms de registres normaux, soit les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Ceci peut être utile lors de la tentative de désassembler du code Thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées comme l'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instruction doivent être générées comme commentaires dans le désassemblage en utilisant -M notes.

Pour x86, certaines des options font double emploi avec les fonctions du commutateur -m, mais permettent un contrôle plus fin.

"x86-64"
"i386"
"i8086"
Sélectionne le désassemblage pour l'architecture donnée.
"intel"
"att"
Sélectionne entre le mode syntaxe Intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre ISA AMD64 et ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Sélectionne entre le mode mnémonique Intel et le mode mnémonique AT&T. Note : "intel-mnemonic" implique "intel" et "att-mnemonic" implique "att".
"addr64"
"addr32"
"addr16"
"data32"
"data16"
Spécifie la taille d'adresse et la taille d'opérande par défaut. Ces cinq options seront remplacées si "x86-64", "i386" ou "i8086" apparaissent plus tard dans la chaîne d'options.
"suffix"
Lorsqu'en mode AT&T et également pour un ensemble limité d'instructions en mode Intel, indique au désassembleur d'imprimer un suffixe mnémonique même lorsque le suffixe peut être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument -M raw sélectionne le désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont pris en charge. Ce sont : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle, et future. 32 et 64 modifient la sélection de CPU par défaut ou précédente, désactivant et activant respectivement les instructions 64 bits. De plus, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des capacités à une sélection de CPU précédente ou ultérieure. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations ou arguments différents, vous pourriez ne pas voir le désassemblage attendu. Si vous désassemblez sans fournir de sélection de CPU, une valeur par défaut sera choisie à partir des informations obtenues par BFD des en-têtes des fichiers objets, mais le résultat pourrait à nouveau ne pas être celui que vous attendez.

Pour MIPS, cette option contrôle l'impression des noms d'instructions mnémoniques et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées :

"no-aliases"
Imprime le mnémonique d'instruction 'raw' au lieu de certains mnémoniques d'instructions pseudo. C'est-à-dire, imprime 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassemble les instructions MSA.
"virt"
Désassemble les instructions ASE de virtualisation.
"xpa"
Désassemble les instructions ASE d'adresse physique étendue (XPA).
"gpr-names=ABI"
Imprime les noms des GPR (registres à usage général) appropriés pour l'ABI spécifié. Par défaut, les noms des GPR sont sélectionnés en fonction de l'ABI du binaire en cours de désassemblage.
"fpr-names=ABI"
Imprime les noms des FPR (registres à virgule flottante) appropriés pour l'ABI spécifié. Par défaut, les numéros des FPR sont imprimés plutôt que les noms.
"cp0-names=ARCH"
Imprime les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés en fonction de l'architecture et du CPU du binaire en cours de désassemblage.
"hwr-names=ARCH"
Imprime les noms des HWR (registre matériel, utilisé par l'instruction "rdhwr") appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des HWR sont sélectionnés en fonction de l'architecture et du CPU du binaire en cours de désassemblage.
"reg-names=ABI"
Imprime les noms des GPR et FPR appropriés pour l'ABI sélectionné.
"reg-names=ARCH"
Imprime les noms des registres spécifiques au CPU (registres CP0 et noms HWR) appropriés pour le CPU ou l'architecture sélectionné.

Pour l'une des options listées ci-dessus, ABI ou ARCH peuvent être spécifiés comme numeric pour que des nombres soient imprimés au lieu de noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier les adresses d'entrée de fonction avec -M entry:0xf00ba. Vous pouvez utiliser ceci plusieurs fois pour désassembler correctement les fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme les dumps ROM). Dans ces cas, le masque d'entrée de fonction serait sinon décodé comme des instructions VAX, ce qui entraînerait probablement un désassemblage erroné du reste de la fonction.

-p
--private-headers
Imprime les informations spécifiques au format de fichier objet. Les informations exactes imprimées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est imprimée.
-P options
--private=options
Imprime les informations spécifiques au format de fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (les listes d'options sont affichées avec l'aide).

Pour XCOFF, les options disponibles sont :

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Pour PE, les options disponibles sont :

"header"
"sections"

Tous les formats d'objets ne prennent pas en charge cette option. En particulier, le format ELF ne l'utilise pas.

-r
--reloc
Imprime les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont imprimées en alternance avec le désassemblage.
-R
--dynamic-reloc
Imprime les entrées de relocalisation dynamiques du fichier. Ceci n'a de sens que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont imprimées en alternance avec le désassemblage.
-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non BSS sont affichées. Par défaut, toute section compressée sera affichée dans sa forme compressée. Pour voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source mélangé au désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Typiquement txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut de "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifie prefix à ajouter aux chemins absolus lorsqu'il est utilisé avec -S.
--prefix-strip=level
Indique combien de noms de répertoire initiaux doivent être supprimés des chemins absolus codés en dur. N'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, imprime l'instruction en hexadécimal ainsi qu'en forme symbolique. C'est le comportement par défaut sauf lorsque --prefix-addresses est utilisé.
--no-show-raw-insn
Lors du désassemblage d'instructions, n'imprime pas les octets de l'instruction. C'est le comportement par défaut lorsque --prefix-addresses est utilisé.
--insn-width=width
Affiche width octets sur une seule ligne lors du désassemblage d'instructions.
--visualize-jumps[=color|=extended-color|=off]
Visualise les sauts qui restent à l'intérieur d'une fonction en dessinant de l'art ASCII entre les adresses de début et de destination. L'argument optionnel =color ajoute de la couleur à la sortie en utilisant des couleurs de terminal simples. Alternativement, l'argument =extended-color ajoutera de la couleur en utilisant des couleurs 8 bits, mais celles-ci pourraient ne pas fonctionner sur tous les terminaux.

S'il est nécessaire de désactiver l'option visualize-jumps après qu'elle ait été activée précédemment, utilisez visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extened|extended-color|extened-colour
Active ou désactive l'utilisation de la coloration syntaxique dans la sortie de désassemblage. Le comportement par défaut
le comportement est déterminé par une option de configuration. Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et selon le terminal utilisé, la sortie colorée peut ne pas être lisible.

L'argument on ajoute des couleurs à l'aide de couleurs de terminal simples.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

--dwarf-depth=n
Limite le déversement de la section ".debug_info" à n enfants. Ceci n'est utile qu'avec --debug-dump=info. La valeur par défaut est d'afficher tous les DIE ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIE à ou au-delà du niveau n ne seront pas affichés. La plage pour n est basée sur zéro.

--dwarf-start=n
Affiche uniquement les DIE à partir du DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si cette option est spécifiée, elle supprimera l'affichage de toutes les informations d'en-tête et de tous les DIE avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront affichés.

Ceci peut être utilisé conjointement avec --dwarf-depth.

--dwarf-check
Active des vérifications supplémentaires pour la cohérence des informations Dwarf.
--ctf[=section]
Affiche le contenu de la section CTF spécifiée. Les sections CTF elles-mêmes contiennent de nombreuses sous-sections, toutes affichées dans l'ordre.

Par défaut, affiche le nom de la section nommée .ctf, qui est le nom émis par ld.

--ctf-parent=member
Si la section CTF contient des types définis de manière ambiguë, elle consistera en une archive de nombreux dictionnaires CTF, tous héritant d'un dictionnaire contenant des types non ambigus. Ce membre est nommé par défaut .ctf, comme la section qui le contient, mais il est possible de changer ce nom en utilisant la fonction "ctf_link_set_memb_name_changer" au moment de la liaison. Lors de l'examen d'archives CTF créées par un éditeur de liens qui utilise le changeur de nom pour renommer le membre d'archive parent, --ctf-parent peut être utilisé pour spécifier le nom utilisé pour le parent.

Par défaut, affiche le nom de la section nommée .sframe, qui est le nom émis par ld.

--stabs
Affiche le contenu complet de toutes les sections demandées. Affiche le contenu des sections .stab, .stab.index et .stab.excl d'un fichier ELF. Ceci n'est utile que sur les systèmes (comme Solaris 2.0) sur lesquels les entrées de table de symboles de débogage ".stab" sont transportées dans une section ELF. Dans la plupart des autres formats de fichiers, les entrées de table de symboles de débogage sont entrelacées avec les symboles de liaison et sont visibles dans la sortie --syms.
--start-address=adresse
Commence à afficher les données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
--stop-address=adresse
Arrête l'affichage des données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
-t
--syms
Imprime les entrées de la table des symboles du fichier. Ceci est similaire aux informations fournies par le programme nm, bien que le format d'affichage soit différent. Le format de la sortie dépend du format du fichier qui est déversé, mais il existe deux types principaux. L'un ressemble à ceci : 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

où le numéro entre crochets est le numéro de

l'entrée dans la table des symboles, le numéro sec est le numéro de section, la valeur fl sont les bits de drapeau du symbole, le numéro ty est le type du symbole, le numéro scl est la classe de stockage du symbole et la valeur nx est le nombre d'entrées auxiliaires associées au symbole. Les deux derniers champs sont la valeur du symbole et son nom.

L'autre format de sortie courant, généralement observé avec les fichiers basés sur ELF, ressemble à ceci :

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Ici, le premier nombre est la valeur du symbole (parfois appelée son adresse). Le champ suivant est en fait un ensemble de caractères et d'espaces indiquant les bits de drapeau qui sont activés sur le symbole. Ces caractères sont décrits ci-dessous. Vient ensuite la section avec laquelle le symbole est associé, ou *ABS* si la section est absolue (c'est-à-dire non connectée à une section), ou *UND* si la section est référencée dans le fichier en cours de vidage, mais non définie là.

Après le nom de la section vient un autre champ, un nombre, qui pour les symboles communs est l'alignement et pour les autres symboles est la taille. Enfin, le nom du symbole est affiché.

Les caractères de drapeau sont divisés en 7 groupes comme suit :

"l"
"g"
"u"
"!"
Le symbole est local (l), global (g), global unique (u), ni global ni local (un espace) ou à la fois global et local (!). Un symbole peut être ni local ni global pour diverses raisons, par exemple, parce qu'il est utilisé pour le débogage, mais c'est probablement une indication d'un bug s'il est à la fois local et global. Les symboles globaux uniques sont une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, l'éditeur de liens dynamique s'assurera qu'il n'y a qu'un seul symbole avec ce nom et ce type utilisé dans tout le processus.
"w"
Le symbole est faible (w) ou fort (un espace).
"C"
Le symbole désigne un constructeur (C) ou un symbole ordinaire (un espace).
"W"
Le symbole est un avertissement (W) ou un symbole normal (un espace). Le nom d'un symbole d'avertissement est un message à afficher si le symbole qui suit le symbole d'avertissement est jamais référencé.
"I"
"i"
Le symbole est une référence indirecte à un autre symbole (I), une fonction à évaluer lors du traitement de la relocalisation (i) ou un symbole normal (un espace).
"d"
"D"
Le symbole est un symbole de débogage (d) ou un symbole dynamique (D) ou un symbole normal (un espace).
"F"
"f"
"O"
Le symbole est le nom d'une fonction (F) ou d'un fichier (f) ou d'un objet (O) ou simplement un symbole normal (un espace).
-T
--dynamic-syms
Imprime les entrées de la table des symboles dynamiques du fichier. Ceci n'est pertinent que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Ceci est similaire aux informations fournies par le programme nm lorsqu'il reçoit l'option -D (--dynamic).

Le format de sortie est similaire à celui produit par l'option --syms, à l'exception qu'un champ supplémentaire est inséré avant le nom du symbole, donnant les informations de version associées au symbole. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées au symbole, elle est affichée telle quelle, sinon elle est mise entre parenthèses.

--special-syms
Lors de l'affichage des symboles, inclut ceux que la cible considère comme spéciaux d'une manière ou d'une autre et qui ne seraient normalement pas d'intérêt pour l'utilisateur.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multibytes encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), aucun traitement spécial n'est effectué. L'option --unicode=locale affiche la séquence dans la locale actuelle, qui peut ou non les supporter. Les options --unicode=hex et --unicode=invalid les affichent sous forme de séquences d'octets hexadécimaux entourées d'accolades ou de crochets.

L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en surbrillance en rouge (si prises en charge par le périphérique de sortie). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

-V
--version
Affiche le numéro de version de objdump et quitte.
-x
--all-headers
Affiche toutes les informations d'en-tête disponibles, y compris la table des symboles et les entrées de relocalisation. L'utilisation de -x équivaut à spécifier tous les arguments -a -f -h -p -r -t.
-w
--wide
Formate certaines lignes pour les périphériques de sortie ayant plus de 80 colonnes. Ne tronque pas non plus les noms de symboles lorsqu'ils sont affichés.
-z
--disassemble-zeroes
Normalement, la sortie de désassemblage ignore les blocs de zéros. Cette option demande au désassembleur de désassembler ces blocs, comme toute autre donnée.
-Z
--decompress
L'option -Z est destinée à être utilisée conjointement avec l'option -s. Elle demande à objdump de décompresser toute section compressée avant d'afficher son contenu.
@file
Lit les options de la ligne de commande à partir de file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière d'apostrophes ou de guillemets. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en précédant le caractère à inclure avec une barre oblique inverse. Le file peut lui-même contenir des options @file supplémentaires ; toutes ces options seront traitées récursivement.
