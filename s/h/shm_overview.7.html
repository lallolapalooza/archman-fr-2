NOM

shm_overview - aperçu de la mémoire partagée POSIX

DESCRIPTION

L'API de mémoire partagée POSIX permet aux processus de communiquer des informations en partageant une région de mémoire.

Les interfaces utilisées dans l'API sont :

shm_open(3)
Crée et ouvre un nouvel objet, ou ouvre un objet existant. Ceci est analogue à open(2). L'appel retourne un descripteur de fichier à utiliser par les autres interfaces listées ci-dessous.
ftruncate(2)
Définit la taille de l'objet de mémoire partagée. (Un objet de mémoire partagée nouvellement créé a une longueur de zéro.)
mmap(2)
Mappe l'objet de mémoire partagée dans l'espace d'adressage virtuel du processus appelant.
munmap(2)
Défait la mappe de l'objet de mémoire partagée hors de l'espace d'adressage virtuel du processus appelant.
shm_unlink(3)
Supprime un nom d'objet de mémoire partagée.
close(2)
Ferme le descripteur de fichier alloué par shm_open(3) lorsqu'il n'est plus nécessaire.
fstat(2)
Obtient une structure stat décrivant l'objet de mémoire partagée. Parmi les informations retournées par cet appel figurent la taille de l'objet (st_size), les permissions (st_mode), le propriétaire (st_uid) et le groupe (st_gid).
fchown(2)
Pour changer la propriété d'un objet de mémoire partagée.
fchmod(2)
Pour changer les permissions d'un objet de mémoire partagée.

Versions

La mémoire partagée POSIX est supportée depuis Linux 2.4 et glibc 2.2.

Persistance

Les objets de mémoire partagée POSIX ont une persistance noyau : un objet de mémoire partagée existera jusqu'à l'arrêt du système, ou jusqu'à ce que tous les processus aient défait la mappe de l'objet et qu'il ait été supprimé avec shm_unlink(3)

Liaison

Les programmes utilisant l'API de mémoire partagée POSIX doivent être compilés avec cc -lrt pour se lier à la bibliothèque temps réel, librt.

Accès aux objets de mémoire partagée via le système de fichiers

Sous Linux, les objets de mémoire partagée sont créés dans un système de fichiers virtuel (tmpfs(5)), normalement monté sous /dev/shm. Depuis Linux 2.6.19, Linux supporte l'utilisation des listes de contrôle d'accès (ACL) pour contrôler les permissions des objets dans le système de fichiers virtuel.

NOTES

Typiquement, les processus doivent synchroniser leur accès à un objet de mémoire partagée, en utilisant, par exemple, des sémaphores POSIX.

La mémoire partagée System V (shmget(2), shmop(2), etc.) est une ancienne API de mémoire partagée. La mémoire partagée POSIX fournit une interface plus simple et mieux conçue ; d'un autre côté, la mémoire partagée POSIX est un peu moins disponible (surtout sur les anciens systèmes) que la mémoire partagée System V.
