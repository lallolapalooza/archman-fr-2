DESCRIPTION

Les routines de récupération indexée transfèrent des données sous forme de tableau disponibles à l'adresse source sur le PE distant (pe). Les éléments du tableau source sont séparés par un pas sst. Une fois les données reçues, elles sont stockées à l'adresse mémoire locale target, séparées par le pas tst. Les routines retournent lorsque les données ont été copiées dans le tableau local target.

Les arguments sont les suivants :

target
Tableau à mettre à jour sur le PE local.
source
Tableau contenant les données à copier sur le PE distant.
tst
Le pas entre les éléments consécutifs du tableau cible. Le pas est mis à l'échelle par la taille de l'élément du tableau cible. Une valeur de 1 indique des données contiguës. tst doit être de type entier. Si vous appelez depuis Fortran, il doit s'agir d'une valeur entière par défaut.
sst
Le pas entre les éléments consécutifs du tableau source. Le pas est mis à l'échelle par la taille de l'élément du tableau source. Une valeur de 1 indique des données contiguës. sst doit être de type entier. Si vous appelez depuis Fortran, il doit s'agir d'une valeur entière par défaut.
len
Nombre d'éléments dans les tableaux cible et source. len doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une constante, d'une variable ou d'un élément de tableau de type entier par défaut.
pe
Numéro du PE distant. pe doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une constante, d'une variable ou d'un élément de tableau de type entier par défaut.

Les objets de données cible et source doivent respecter les contraintes de typage, qui sont les suivantes :

shmem_iget32, shmem_iget4 : Tout type non caractère ayant une taille de stockage
égale à 32 bits.
shmem_iget64, shmem_iget8 : Tout type non caractère ayant une taille de stockage
égale à 64 bits.
shmem_iget128 : Tout type non caractère ayant une taille de stockage égale à
128 bits.

shmem_short_iget : Éléments de type short.

shmem_int_iget : Éléments de type int.

shmem_long_iget : Éléments de type long.

shmem_longlong_iget : Éléments de type long long.

shmem_float_iget : Éléments de type float.

shmem_double_iget : Éléments de type double.

shmem_longdouble_iget : Éléments de type long double.

SHMEM_COMPLEX_IGET : Éléments de type complex de taille par défaut.

SHMEM_DOUBLE_IGET : (Fortran) Éléments de type double précision.

SHMEM_INTEGER_IGET : Éléments de type integer.

SHMEM_LOGICAL_IGET : Éléments de type logical.

SHMEM_REAL_IGET : Éléments de type real.

shmem_longdouble_iget : Éléments de type long double.

SHMEM_COMPLEX_IGET : Éléments de type complex de taille par défaut.

SHMEM_DOUBLE_IGET : (Fortran) Éléments de type double précision.

SHMEM_INTEGER_IGET : Éléments de type integer.

SHMEM_LOGICAL_IGET : Éléments de type logical.

SHMEM_REAL_IGET : Éléments de type real.

Si vous utilisez Fortran, les types de données doivent être de taille par défaut. Par exemple, une variable réelle doit être déclarée comme REAL, REAL*4, ou REAL(KIND=4).

NOTES

Voir intro_shmem(3) pour une définition du terme accessible à distance.

EXEMPLES

L'exemple simple suivant utilise shmem_logical_iget dans un programme Fortran. Compilez cet exemple avec l'option de compilateur -lsma.

PROGRAM STRIDELOGICAL
  LOGICAL SOURCE(10), TARGET(5)
  SAVE SOURCE ! SAVE REND L'ACCESSIBLE À DISTANCE
  DATA SOURCE /.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F./
  DATA TARGET / 5*.F. /
  CALL START_PES(2)
  IF (MY_PE() .EQ. 0) THEN
    CALL SHMEM_LOGICAL_IGET(TARGET, SOURCE, 1, 2, 5, 1)
    PRINT*,'TARGET APRES SHMEM_LOGICAL_IGET:',TARGET
  ENDIF
  CALL SHMEM_BARRIER_ALL
END
