C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - démangle les symboles C++ et Java

SYNTAXE

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|-R|--no-recurse-limit|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java permettent la surcharge de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction accepte des paramètres de types différents. Afin de pouvoir distinguer ces fonctions aux noms similaires, C++ et Java les encodent en un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de *mangling* (entrelaçage). Le programme c++filt [1] effectue le mappage inverse : il décode (*démangle*) les noms de bas niveau en noms de haut niveau afin qu'ils puissent être lus.

Chaque mot alphanumérique (composé de lettres, de chiffres, de tirets bas, de dollars ou de points) vu dans l'entrée est un nom entrelaçé potentiel. Si le nom se décode en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot d'origine est affiché. De cette façon, vous pouvez passer un fichier source assembleur complet, contenant des noms entrelaçés, à travers c++filt et voir le même fichier source contenant des noms démangles.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles à partir de l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés être uniquement des noms entrelaçés et aucune vérification n'est effectuée pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et démanglera le nom en « f() » tandis que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom entrelaçé qui le rend invalide). Cependant, cette commande fonctionnera :

echo _Z1fv, | c++filt -n

et affichera « f(), », c'est-à-dire le nom démangle suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils puissent faire partie d'un fichier source assembleur où il peut y avoir des caractères supplémentaires et superflus à la suite d'un nom entrelaçé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ placent un tiret bas au début de chaque nom. Par exemple, le nom C "foo" reçoit le nom de bas niveau "_foo". Cette option supprime le tiret bas initial. Que c++filt supprime ou non le tiret bas par défaut dépend de la cible.
-n
--no-strip-underscore
Ne supprime pas le tiret bas initial.
-p
--no-params
Lors du démangle d'un nom de fonction, n'affiche pas les types des paramètres de la fonction.
-t
--types
Tente de démangle les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types entrelaçés ne sont normalement utilisés qu'en interne par le compilateur, et ils peuvent être confondus avec des noms non entrelaçés. Par exemple, une fonction appelée « a » traitée comme un nom de type entrelaçé serait démangle en « signed char ».
-i
--no-verbose
N'inclut pas les détails d'implémentation (le cas échéant) dans la sortie démangle.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangle des chaînes. Comme les formats d'entrelaçage de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une erreur de mémoire. La limite tente d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes d'entrelaçage, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (méthode par défaut)
"gnu"
celle utilisée par le compilateur C++ GNU (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le C++ Annotated Reference Manual
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur Java GNU (gcj)
"gnat"
celle utilisée par le compilateur Ada GNU (GNAT).
--help
Affiche un résumé des options de c++filt et quitte.
--version
Affiche le numéro de version de c++filt et quitte.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière entre apostrophes ou guillemets. Tout caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; de telles options seront traitées récursivement.

sh2-elf-c++filt

sh2-elf-c++filt (1) - convert demangled C++ symbol names to mangled names.

NAME

c++filt - convert demangled C++ symbol names to mangled names.

SYNOPSIS

c++filt [OPTION]... [symbol]...

DESCRIPTION

c++filt reads C++ symbol names from standard input, one per line, or from the command line arguments, and writes the demangled names to standard output.

This utility is useful for debugging C++ programs, where mangled names can be cryptic.

OPTIONS

-n, --no-demangle
Print the mangled names. This is the default behavior.
-p, --strip-underline
Strip leading underscores from mangled names.
-h, --help
Display help text and exit.
-V, --version
Display version information and exit.

FOOTNOTES

The exact demangling format may depend on the C++ compiler used to generate the symbols. This utility attempts to demangle symbols generated by common C++ compilers, such as GCC and Clang.
