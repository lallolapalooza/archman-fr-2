Paquet: sh4-elf-binutils

STRINGS(1) Outils de développement GNU STRINGS(1)

NOM

strings - imprime les séquences de caractères imprimables dans les fichiers

SYNTAXE

strings [-afovV] [-longueur-min]
[-n longueur-min] [--bytes=longueur-min]
[-t base] [--radix=base]
[-e encodage] [--encoding=encodage]
[-U méthode] [--unicode=méthode]
[-] [--all] [--print-file-name]
[-T nom-bfd] [--target=nom-bfd]
[-w] [--include-all-whitespace]
[-s] [--output-separator sep_string]
[--help] [--version] fichier...

DESCRIPTION

Pour chaque fichier donné, GNU strings imprime les séquences de caractères imprimables qui ont une longueur d'au moins 4 caractères (ou le nombre spécifié avec les options ci-dessous) et qui sont suivies d'un caractère non imprimable.

Selon la configuration du programme strings, il affichera par défaut soit toutes les séquences imprimables qu'il trouve dans chaque fichier, soit uniquement celles qui se trouvent dans les sections de données initialisées et chargeables. Si le type de fichier est non reconnaissable, ou si strings lit depuis l'entrée standard, il affichera toujours toutes les séquences imprimables qu'il peut trouver.

Pour des raisons de compatibilité ascendante, tout fichier survenant après une option de ligne de commande consistant uniquement en - sera également analysé dans son intégralité, indépendamment de la présence de l'option -d.

strings est principalement utile pour déterminer le contenu des fichiers non textuels.

OPTIONS

-a
--all
-
Analyse le fichier entier, quels que soient les sections qu'il contient ou s'ils sont chargés ou initialisés. Normalement, c'est le comportement par défaut, mais strings peut être configuré pour que -d soit le comportement par défaut à la place.

L'option - dépend de la position et force strings à effectuer des analyses complètes de tout fichier mentionné après le - sur la ligne de commande, même si l'option -d a été spécifiée.

-d
--data
N'imprime que les chaînes des sections de données initialisées et chargées dans le fichier. Cela peut réduire la quantité de « bruit » dans la sortie, mais expose également le programme strings aux failles de sécurité qui pourraient être présentes dans la bibliothèque BFD utilisée pour analyser et charger les sections. Strings peut être configuré de manière à ce que cette option soit le comportement par défaut. Dans ce cas, l'option -a peut être utilisée pour éviter d'utiliser la bibliothèque BFD et plutôt imprimer toutes les chaînes trouvées dans le fichier.
-f
--print-file-name
Imprime le nom du fichier avant chaque chaîne.
--help
Imprime un résumé de l'utilisation du programme sur la sortie standard et quitte.
-longueur-min
-n longueur-min
--bytes=longueur-min
Imprime les séquences de caractères affichables d'une longueur d'au moins longueur-min caractères. Si non spécifié, une longueur minimale par défaut de 4 est utilisée. La distinction entre caractères affichables et non affichables dépend du réglage des options -e et -U. Les séquences sont toujours terminées par des caractères de contrôle tels que nouvelle ligne et retour chariot, mais pas par le caractère tabulation.
-o
Similaire à -t o. D'autres versions de strings font agir -o comme -t d à la place. Comme nous ne pouvons pas être compatible avec les deux manières, nous en avons simplement choisi une.
-t base
--radix=base
Imprime le décalage dans le fichier avant chaque chaîne. Le caractère unique argument spécifie la base du décalage — o pour octal, x pour hexadécimal, ou d pour décimal.
-e encodage
--encoding=encodage
Sélectionne l'encodage des caractères des chaînes à trouver. Les valeurs possibles pour encodage sont : s = caractères d'un seul octet en 7 bits (par défaut), S = caractères d'un seul octet en 8 bits, b = 16 bits bigendian, l = 16 bits littleendian, B = 32 bits bigendian, L = 32 bits littleendian. Utile pour trouver des chaînes de caractères larges. (l et b s'appliquent, par exemple, aux encodages Unicode UTF-16/UCS-2).
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multibytes encodés en UTF-8 dans les chaînes. Le défaut (--unicode=default) est de ne pas leur accorder de traitement spécial, et de s'appuyer plutôt sur le réglage de l'option --encoding. Les autres valeurs de cette option activent automatiquement --encoding=S.

L'option --unicode=invalid les traite comme des caractères non graphiques et donc non valides. Toutes les autres options les traitent comme des caractères de chaîne valides.

L'option --unicode=locale les affiche dans la locale actuelle, qui peut ou non supporter l'encodage UTF-8. L'option --unicode=hex les affiche sous forme de séquences d'octets hexadécimaux entourées de caractères <>. L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en surbrillance en rouge (si supporté par le périphérique de sortie). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

-T nom-bfd
--target=nom-bfd
Spécifie un format de code objet différent du format par défaut de votre système.
-v
-V
--version
Imprime le numéro de version du programme sur la sortie standard et quitte.
-w
--include-all-whitespace
Par défaut, les caractères de tabulation et d'espace sont inclus dans les chaînes affichées, mais les autres caractères d'espacement, tels que les nouvelles lignes et les retours chariot, ne le sont pas. L'option -w change ce comportement pour que tous les caractères d'espacement soient considérés comme faisant partie d'une chaîne.
-s
--output-separator
Par défaut, les chaînes de sortie sont délimitées par une nouvelle ligne. Cette option vous permet de fournir une chaîne quelconque à utiliser comme séparateur d'enregistrements de sortie. Utile avec --include-all-whitespace où les chaînes peuvent contenir des nouvelles lignes en interne.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en précédant le caractère à inclure avec une barre oblique inverse. Le fichier peut contenir lui-même des options @fichier supplémentaires ; toute option de ce type sera traitée récursivement.
