shm_open(3) Library Functions Manual shm_open(3)

NOM

shm_open, shm_unlink - créer/ouvrir ou supprimer des objets de mémoire partagée POSIX

BIBLIOTHÈQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <sys/mman.h>
#include <sys/stat.h>        /* Pour les constantes de mode */
#include <fcntl.h>           /* Pour les constantes O_* */
int shm_open(const char *name, int oflag, mode_t mode);
int shm_unlink(const char *name);

DESCRIPTION

shm_open() crée et ouvre un nouvel objet de mémoire partagée POSIX, ou ouvre un objet existant. Un objet de mémoire partagée POSIX est en effet un descripteur qui peut être utilisé par des processus non liés pour mmap(2) la même région de mémoire partagée. La fonction shm_unlink() effectue l'opération inverse, supprimant un objet créé précédemment par shm_open().

Le fonctionnement de shm_open() est analogue à celui de open(2). name spécifie l'objet de mémoire partagée à créer ou à ouvrir. Pour une utilisation portable, un objet de mémoire partagée doit être identifié par un nom de la forme /somename ; c'est-à-dire une chaîne terminée par un octet nul, d'une longueur maximale de NAME_MAX (soit 255) caractères, comprenant une barre oblique initiale, suivie d'un ou plusieurs caractères, dont aucun n'est une barre oblique.

oflag est un masque de bits créé en combinant exactement un des drapeaux O_RDONLY ou O_RDWR avec n'importe lequel des autres drapeaux listés ici :

O_RDONLY
Ouvre l'objet en lecture seule. Un objet de mémoire partagée ouvert de cette manière ne peut être mappé en mémoire (via mmap(2)) qu'en lecture seule (PROT_READ).
O_RDWR
Ouvre l'objet en lecture-écriture.
O_CREAT
Crée l'objet de mémoire partagée s'il n'existe pas. La propriété utilisateur et groupe de l'objet est prise à partir des identifiants effectifs correspondants du processus appelant, et les bits de permissions de l'objet sont définis selon les 9 bits de poids faible de mode, à l'exception des bits définis dans le masque de création de mode de fichier du processus (voir umask(2)) qui sont effacés pour le nouvel objet. Un ensemble de constantes macro qui peuvent être utilisées pour définir mode est listé dans open(2). (Les définitions symboliques de ces constantes peuvent être obtenues en incluant <sys/stat.h>.)
Un nouvel objet de mémoire partagée a initialement une longueur nulle. La taille de l'objet peut être définie à l'aide de ftruncate(2). Les octets nouvellement alloués d'un objet de mémoire partagée sont automatiquement initialisés à 0.
O_EXCL
Si O_CREAT a également été spécifié, et qu'un objet de mémoire partagée portant le nom name existe déjà, renvoie une erreur. La vérification de l'existence de l'objet, et sa création s'il n'existe pas, sont effectuées de manière atomique.
O_TRUNC
Si l'objet de mémoire partagée existe déjà, il est tronqué à zéro octet.

Les définitions de ces valeurs de drapeau peuvent être obtenues en incluant <fcntl.h>.

En cas de succès, shm_open() renvoie un descripteur de fichier faisant référence à l'objet de mémoire partagée. Ce descripteur de fichier est garanti d'être le descripteur de fichier ayant le plus petit numéro et qui n'a pas été ouvert précédemment dans le processus. Le drapeau FD_CLOEXEC (voir fcntl(2)) est défini pour le descripteur de fichier.

Le descripteur de fichier est normalement utilisé dans les appels ultérieurs à ftruncate(2) (pour un objet nouvellement créé) et mmap(2). Après un appel à mmap(2), le descripteur de fichier peut être fermé sans affecter le mappage mémoire.

Le fonctionnement de shm_unlink() est analogue à unlink(2) : il supprime un nom d'objet de mémoire partagée et, une fois que tous les processus ont désactivé le mappage de l'objet, il désalloue et détruit le contenu de la région mémoire associée. Après un shm_unlink() réussi, les tentatives d'ouvrir (shm_open()) un objet avec le même name échouent (sauf si O_CREAT a été spécifié, auquel cas un nouvel objet distinct est créé).

VALEUR RENVOYÉE

En cas de succès, shm_open() renvoie un descripteur de fichier (un entier non négatif). En cas de succès, shm_unlink() renvoie 0. En cas d'échec, les deux fonctions renvoient -1 et définissent errno pour indiquer l'erreur.

ERREURS

EACCES
L'autorisation de supprimer (shm_unlink()) l'objet de mémoire partagée a été refusée.
EACCES
L'autorisation a été refusée pour ouvrir (shm_open()) name avec le mode spécifié, ou O_TRUNC a été spécifié et l'appelant n'a pas la permission d'écriture sur l'objet.
EEXIST
Les deux drapeaux O_CREAT et O_EXCL ont été spécifiés à shm_open() et l'objet de mémoire partagée spécifié par name existe déjà.
EINVAL
L'argument name passé à shm_open() était invalide.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENAMETOOLONG
La longueur de name dépasse PATH_MAX.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENOENT
Une tentative a été faite pour ouvrir (shm_open()) un name qui n'existait pas, et O_CREAT n'a pas été spécifié.
ENOENT
Une tentative a été faite pour supprimer (shm_unlink()) un name qui n'existait pas.

VERSIONS

POSIX laisse le comportement de la combinaison de O_RDONLY et O_TRUNC non spécifié. Sur Linux, cela tronquera avec succès un objet de mémoire partagée existant ; cela pourrait ne pas être le cas sur d'autres systèmes UNIX.

L'implémentation des objets de mémoire partagée POSIX sous Linux utilise un système de fichiers dédié tmpfs(5) qui est normalement monté sous /dev/shm.

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.2. POSIX.1-2001.

POSIX.1-2001 indique que la propriété de groupe d'un nouvel objet de mémoire partagée est définie sur l'ID de groupe effectif du processus appelant ou sur « un ID de groupe par défaut du système ». POSIX.1-2008 indique que la propriété de groupe peut être définie sur l'ID de groupe effectif du processus appelant ou, si l'objet est visible dans le système de fichiers, sur l'ID de groupe du répertoire parent.

EXEMPLES

Les programmes ci-dessous utilisent la mémoire partagée POSIX et les sémaphores anonymes POSIX pour échanger un morceau de données. Le programme "bounce" (qui doit être exécuté en premier) met en majuscules la casse d'une chaîne qui est placée dans la mémoire partagée par le programme "send". Une fois que les données ont été modifiées, le programme "send" imprime alors le contenu de la mémoire partagée modifiée.

Source du programme : pshm_ucase.h

Le fichier d'en-tête suivant est inclus par les deux programmes ci-dessous. Son objectif principal est de définir une structure qui sera imposée à l'objet mémoire partagé entre les deux programmes.


#ifndef PSHM_UCASE_H
#define PSHM_UCASE_H
#include <err.h>
#include <semaphore.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>
#define BUF_SIZE 1024   /* Taille maximale pour la chaîne échangée */
/* Définir une structure qui sera imposée à l'objet
   mémoire partagé */
struct shmbuf {
    sem_t  sem1;            /* Sémaphore anonyme POSIX */
    sem_t  sem2;            /* Sémaphore anonyme POSIX */
    size_t cnt;             /* Nombre d'octets utilisés dans 'buf' */
    char   buf[BUF_SIZE];   /* Données transférées */
};
#endif  // garde d'inclusion

Source du programme : pshm_ucase_bounce.c

Le programme "bounce" crée un nouvel objet mémoire partagé avec le nom donné dans son argument de ligne de commande et dimensionne l'objet pour correspondre à la taille de la structure shmbuf définie dans le fichier d'en-tête. Il mappe ensuite l'objet dans l'espace d'adressage du processus et initialise deux sémaphores POSIX à l'intérieur de l'objet à 0.

Après que le programme "send" a posté le premier des sémaphores, le programme "bounce" met en majuscules les données qui ont été placées dans la mémoire par le programme "send" puis poste le deuxième sémaphore pour dire au programme "send" qu'il peut maintenant accéder à la mémoire partagée.


/* pshm_ucase_bounce.c
   Sous licence GNU General Public License v2 ou ultérieure.
*/
#include <ctype.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>
#include "pshm_ucase.h"
int
main(int argc, char *argv[])
{
    int            fd;
    char           *shmpath;
    struct shmbuf  *shmp;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s /shm-path\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    shmpath = argv[1];
    /* Créer l'objet mémoire partagé et définir sa taille à celle de
       notre structure.  */
    fd = shm_open(shmpath, O_CREAT | O_EXCL | O_RDWR, 0600);
    if (fd == -1)
        err(EXIT_FAILURE, "shm_open");
    if (ftruncate(fd, sizeof(struct shmbuf)) == -1)
        err(EXIT_FAILURE, "ftruncate");
    /* Mapper l'objet dans l'espace d'adressage de l'appelant.  */
    shmp = mmap(NULL, sizeof(*shmp), PROT_READ | PROT_WRITE,
                MAP_SHARED, fd, 0);
    if (shmp == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    /* Initialiser les sémaphores comme partagés entre processus, avec la valeur 0.  */
    if (sem_init(&shmp->sem1, 1, 0) == -1)
        err(EXIT_FAILURE, "sem_init-sem1");
    if (sem_init(&shmp->sem2, 1, 0) == -1)
        err(EXIT_FAILURE, "sem_init-sem2");
    /* Attendre que 'sem1' soit posté par le pair avant de toucher à la
       mémoire partagée.  */
    if (sem_wait(&shmp->sem1) == -1)
        err(EXIT_FAILURE, "sem_wait");
    /* Convertir les données dans la mémoire partagée en majuscules.  */
    for (size_t j = 0; j < shmp->cnt; j++)
        shmp->buf[j] = toupper((unsigned char) shmp->buf[j]);
    /* Poster 'sem2' pour dire au pair qu'il peut maintenant
       accéder aux données modifiées dans la mémoire partagée.  */
    if (sem_post(&shmp->sem2) == -1)
        err(EXIT_FAILURE, "sem_post");
    /* Supprimer l'objet mémoire partagé. Même si le processus pair
       utilise toujours l'objet, ce n'est pas grave. L'objet sera
       supprimé uniquement après la fermeture de toutes les références ouvertes.  */
    shm_unlink(shmpath);
    exit(EXIT_SUCCESS);
}

Source du programme : pshm_ucase_send.c

Le programme "send" prend deux arguments de ligne de commande : le chemin d'un objet mémoire partagé précédemment créé par le programme "bounce" et une chaîne qui doit être copiée dans cet objet.

Le programme ouvre l'objet mémoire partagé et mappe l'objet dans son espace d'adressage. Il copie ensuite les données spécifiées dans son deuxième argument dans la mémoire partagée, et poste le premier sémaphore, qui dit au programme "bounce" qu'il peut maintenant accéder à ces données. Après que le programme "bounce" a posté le deuxième sémaphore, le programme "send" affiche le contenu de la mémoire partagée sur la sortie standard.


/* pshm_ucase_send.c
   Sous licence GNU General Public License v2 ou ultérieure.
*/
#include <fcntl.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>
#include "pshm_ucase.h"
int
main(int argc, char *argv[])
{
    int            fd;
    char           *shmpath, *string;
    size_t         len;
    struct shmbuf  *shmp;
    if (argc != 3) {
        fprintf(stderr, "Usage: %s /shm-path string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    shmpath = argv[1];
    string = argv[2];
    len = strlen(string);
    if (len > BUF_SIZE) {
        fprintf(stderr, "La chaîne est trop longue\n");
        exit(EXIT_FAILURE);
    }
    /* Ouvrir l'objet mémoire partagé existant et le mapper
       dans l'espace d'adressage de l'appelant.  */
    fd = shm_open(shmpath, O_RDWR, 0);
    if (fd == -1)
        err(EXIT_FAILURE, "shm_open");
    shmp = mmap(NULL, sizeof(*shmp), PROT_READ | PROT_WRITE,
                MAP_SHARED, fd, 0);
    if (shmp == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    /* Copier les données dans l'objet mémoire partagé.  */
    shmp->cnt = len;
    memcpy(&shmp->buf, string, len);
    /* Dire au pair qu'il peut maintenant accéder à la mémoire partagée.  */
    if (sem_post(&shmp->sem1) == -1)
        err(EXIT_FAILURE, "sem_post");
    /* Attendre que le pair indique qu'il a fini d'accéder
       à la mémoire partagée.  */
    if (sem_wait(&shmp->sem2) == -1)
        err(EXIT_FAILURE, "sem_wait");
    /* Écrire les données modifiées dans la mémoire partagée sur la sortie standard.  */
    if (write(STDOUT_FILENO, &shmp->buf, len) == -1)
        err(EXIT_FAILURE, "write");
    if (write(STDOUT_FILENO, "\n", 1) == -1)
        err(EXIT_FAILURE, "write");
    exit(EXIT_SUCCESS);
}
