L'option -mno-dsbt, par défaut, fait que la balise a la valeur 0, indiquant que le code n'utilise pas l'adressage DSBT. L'éditeur de liens émettra un avertissement si des objets de types différents (DSBT et non-DSBT) sont liés ensemble.
-mpid=no
-mpid=near
-mpid=far
L'option -mpid= provoque la génération par l'assembleur de l'attribut "Tag_ABI_PID" avec une valeur indiquant la forme d'adressage des données utilisée par le code. -mpid=no, par défaut, indique un adressage de données dépendant de la position, -mpid=near indique un adressage indépendant de la position avec des accès GOT utilisant un adressage DP proche, et -mpid=far indique un adressage indépendant de la position avec des accès GOT utilisant un adressage DP éloigné. L'éditeur de liens émettra un avertissement si des objets construits avec des paramètres différents de cette option sont liés ensemble.
-mpic
-mno-pic
L'option -mpic provoque la génération par l'assembleur de l'attribut "Tag_ABI_PIC" avec la valeur 1, indiquant que le code utilise un adressage de code indépendant de la position, L'option "-mno-pic", par défaut, fait que la balise a la valeur 0, indiquant un adressage de code dépendant de la position. L'éditeur de liens émettra un avertissement si des objets de types différents (dépendant de la position et indépendant de la position) sont liés ensemble.
-mbig-endian
-mlittle-endian
Génère du code pour l'endianness spécifié. Par défaut, il s'agit de little-endian.

Les options suivantes sont disponibles lorsque as est configuré pour un processeur TILE-Gx.

-m32 | -m64
Sélectionne la taille du mot, soit 32 bits soit 64 bits.
-EB | -EL
Sélectionne l'endianness, soit big-endian (-EB) soit little-endian (-EL).

L'option suivante est disponible lorsque as est configuré pour un processeur Visium.

-mtune=arch
Cette option spécifie l'architecture cible. Si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur l'architecture cible, l'assembleur émettra un message d'erreur.

Les noms suivants sont reconnus : "mcm24" "mcm" "gr5" "gr6"

Les options suivantes sont disponibles lorsque as est configuré pour un processeur Xtensa.

--text-section-literals | --no-text-section-literals
Contrôle le traitement des pools de littéraux. Par défaut, --no-text-section-literals place les littéraux dans des sections séparées dans le fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --text-section-literals, les littéraux sont entremêlés dans la section de texte afin de les maintenir aussi proches que possible de leurs références. Cela peut être nécessaire pour les fichiers d'assemblage volumineux, où les littéraux seraient autrement hors de portée des instructions "L32R" dans la section de texte. Les littéraux sont regroupés en pools suivant les directives ".literal_position" ou précédant les instructions "ENTRY". Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément.
--auto-litpools | --no-auto-litpools
Contrôle le traitement des pools de littéraux. Par défaut, --no-auto-litpools, en l'absence de --text-section-literals, place les littéraux dans des sections séparées dans le fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --auto-litpools, les littéraux sont entremêlés dans la section de texte afin de les maintenir aussi proches que possible de leurs références, les directives explicites ".literal_position" ne sont pas requises. Cela peut être nécessaire pour les fonctions très volumineuses, où un seul pool de littéraux au début de la fonction peut ne pas être accessible par les instructions "L32R" à la fin. Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément. Lorsqu'elles sont utilisées conjointement avec --text-section-literals, --auto-litpools a la priorité.
--absolute-literals | --no-absolute-literals
Indique à l'assembleur si les instructions "L32R" utilisent un adressage absolu ou relatif au PC. Si le processeur inclut l'option d'adressage absolu, la valeur par défaut est d'utiliser les relocalisations "L32R" absolues. Sinon, seules les relocalisations "L32R" relatives au PC peuvent être utilisées.
--target-align | --no-target-align
Active ou désactive l'alignement automatique pour réduire les pénalités de branchement au détriment d'une certaine taille de code. Cette optimisation est activée par défaut. Notez que l'assembleur alignera toujours les instructions comme "LOOP" qui ont des exigences d'alignement fixes.
--longcalls | --no-longcalls
Active ou désactive la transformation des instructions d'appel pour permettre des appels à une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles d'appel peuvent potentiellement être hors de portée. Elle peut dégrader la taille du code et les performances, mais l'éditeur de liens peut généralement optimiser les surcoûts inutiles lorsqu'un appel se retrouve dans la portée. La valeur par défaut est --no-longcalls.
--transform | --no-transform
Active ou désactive toutes les transformations d'assembleur des instructions Xtensa, y compris la relaxation et l'optimisation. La valeur par défaut est --transform ; --no-transform ne doit être utilisé que dans les cas rares où les instructions doivent être exactement telles que spécifiées dans la source assembleur. L'utilisation de --no-transform provoque des erreurs pour les opérandes d'instructions hors de portée.
--rename-section oldname=newname
Renomme la section oldname en newname. Cette option peut être utilisée plusieurs fois pour renommer plusieurs sections.
--trampolines | --no-trampolines
Active ou désactive la transformation des instructions de saut pour permettre des sauts à une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles de saut peuvent potentiellement être hors de portée. En l'absence de tels sauts, cette option n'affecte pas la taille du code ni les performances. La valeur par défaut est --trampolines.
--abi-windowed | --abi-call0
Choisit la balise ABI écrite dans la section ".xtensa.info". La balise ABI indique l'ABI du code assembleur. Un avertissement est émis par l'éditeur de liens en cas de tentative de lier des fichiers objets avec des balises ABI incohérentes. L'ABI par défaut est choisie par la configuration du cœur Xtensa.

Les options suivantes sont disponibles lorsque as est configuré pour un processeur Z80.

@chapter Fonctionnalités dépendantes de Z80

Options en ligne de commande

-march=CPU[-EXT...][+EXT...]
Cette option spécifie le processeur cible. L'assembleur émettra un message d'erreur si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur le processeur cible. Les noms de processeurs suivants sont reconnus : "z80", "z180", "ez80", "gbz80", "z80n", "r800". En plus de l'ensemble d'instructions de base, l'assembleur peut être configuré pour accepter certaines mnémoniques d'extension. Par exemple, "-march=z180+sli+infc" étend z180 avec les instructions SLI et IN F,(C). Les extensions suivantes sont actuellement prises en charge : "full" (toutes les instructions connues), "adl" (mode CPU ADL par défaut, eZ80 uniquement), "sli" (instruction connue sous le nom de SLI, SLL ou SL1), "xyhl" (instructions avec les moitiés des registres d'index : IXL, IXH, IYL, IYH), "xdcb" (instructions comme RotOp (II+d),R et BitOp n,(II+d),R), "infc" (instruction IN F,(C) ou IN (C)), "outc0" (instruction OUT (C),0). Notez qu'au lieu d'étendre un ensemble d'instructions de base, les mnémoniques d'extension commençant par "-" révoquent la fonctionnalité respective : "-march=z80-full+xyhl" supprime d'abord toutes les extensions par défaut et ajoute uniquement la prise en charge des moitiés des registres d'index.

Si cette option n'est pas spécifiée, alors "-march=z80+xyhl+infc" est supposé.

-local-prefix=prefix
Marque toutes les étiquettes avec le préfixe spécifié comme locales. Mais une telle étiquette peut être marquée comme globale explicitement dans le code. Cette option ne modifie pas le préfixe par défaut des étiquettes locales ".L", elle en ajoute simplement un nouveau.
-colonless
Accepte les étiquettes sans deux-points. Tous les symboles en début de ligne sont traités comme des étiquettes.
-sdcc
Accepte le code assembleur produit par SDCC.
-fp-s=FORMAT
Format des nombres à virgule flottante de précision simple. Par défaut : ieee754 (32 bits).
-fp-d=FORMAT
Format des nombres à virgule flottante de double précision. Par défaut : ieee754 (64 bits).
