DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE non membre de l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
L'objet de données entier accessible à distance à mettre à jour sur le PE distant. Si vous utilisez C/C++, le type de cible doit correspondre à celui implicite dans la section SYNTAXE. Si vous utilisez le compilateur Fortran, il doit être de type entier avec une taille d'élément de 4 octets pour SHMEM_INT4_ADD et de 8 octets pour SHMEM_INT8_ADD.
valeur
La valeur à ajouter atomiquement à cible. Si vous utilisez C/C++, le type de valeur doit correspondre à celui implicite dans la section SYNTAXE. Si vous utilisez Fortran, il doit être de type entier avec une taille d'élément égale à celle de cible.
pe
Un entier qui indique le numéro du PE sur lequel cible doit être mis à jour. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
cible
Un tableau symétrique de longueur nreduce éléments pour recevoir les résultats
des opérations de réduction.
Le type de données de cible varie selon la version de la routine de réduction
appelée et le langage utilisé. Lors de l'appel depuis
C/C++, référez-vous à la section SYNTAXE pour les informations sur le type de données.
Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :

shmem_comp4_sum_to_all : COMPLEX(KIND=4).

shmem_comp8_sum_to_all : Complexe. Si vous utilisez Fortran, il doit s'agir d'un
valeur complexe par défaut.

shmem_int4_sum_to_all : INTEGER(KIND=4).

shmem_int8_sum_to_all : Entier. Si vous utilisez Fortran, il doit s'agir d'un
valeur entière par défaut.

shmem_real4_sum_to_all : REAL(KIND=4).

shmem_real8_sum_to_all : Réel. Si vous utilisez Fortran, il doit s'agir d'un
valeur réelle par défaut.
shmem_real16_sum_to_all : Réel. Si vous utilisez Fortran, il doit s'agir d'un
valeur réelle par défaut.
source
Un tableau symétrique, de longueur nreduce éléments, contenant un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PE de l'ensemble actif n'entre dans la routine de réduction.

DESCRIPTION

These collective communication routines compute the element-wise sum of the array elements specified by the source argument across the PEs specified by PE_count and place the results in the array specified by the target argument. The summation is performed over all PEs in the active set.

The input arguments are as follows:

target
The target array where the results of the reduction will be stored. The type of this array must be complexf, complex8, or complex16.
source
The source array containing the data to be reduced. The type of this array must be the same as the type of the target array.
nlong
The number of elements in the target and source arrays to be reduced.
start
The starting element index in the target and source arrays. This index is relative to the PE that calls the routine.
stride
The stride between elements in the target and source arrays. This stride is relative to the PE that calls the routine.
PE_count
The number of PEs participating in the reduction. This count defines the active set of PEs.
pWrk
A work array. The size of this array is SHMEM_REDUCE_MIN_WRKDATA_SIZE.
pSync
A synchronization array. The size of this array is SHMEM_REDUCE_SYNC_SIZE. It is used to synchronize the PEs during the reduction operation. The elements of this array must be initialized to SHMEM_SYNC_VALUE before the call.

The values of arguments nreduce, PE_start, logPE_stride, and PE_size must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
