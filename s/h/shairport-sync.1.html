shairport-sync(1) Manuel des commandes générales shairport-sync(1)

NOM

shairport-sync - Lecteur audio AirPlay et AirPlay 2

SYNTAXE

shairport-sync [-djvw] [-a nom-service | --name=nom-service] [-B commande | --onstart=commande] [-c fichier-configuration | --configfile=fichier-configuration] [-d | --daemon] [-E commande | --onstop=commande] [-g | --get-cover-art] [-j | --justDaemoniseNoPIDFile] [--logOutputLevel] [--log-to-syslog] [-L latence | --latency=latence] [-m backend | --mdns=backend] [-M | --metadata-enable] [-o backend | --output=backend] [-p port | --port=port] [--password=secret] [-r seuil | --resync=seuil] [--statistics] [-S mode | --stuffing=mode] [-t délai | --timeout=délai] [--tolerance=trames] [-v | --verbose] [-w | --wait-cmd] [-- options_backend_audio]

shairport-sync -X | --displayConfig

shairport-sync -h

shairport-sync -k

shairport-sync -V

DESCRIPTION

Shairport Sync lit l'audio AirPlay. Il peut être compilé pour diffuser depuis des appareils AirPlay "classiques" (alias "AirPlay 1") ou depuis des appareils AirPlay 2.

Le support AirPlay 2 est limité, et AirPlay 2 depuis iTunes pour Windows n'est pas supporté. Pour le fonctionnement AirPlay 2, un programme compagnon appelé nqptp doit être installé.

Veuillez consulter https://github.com/mikebrady/shairport-sync pour plus de détails.

Le nom de l'exécutable Shairport Sync est shairport-sync.

PARAMÈTRES FICHIER CONFIGURATION

Vous devriez utiliser le fichier de configuration pour configurer Shairport Sync car -- à l'exception de quelques commandes spéciales -- il dispose d'un ensemble d'options beaucoup plus riche que celles disponibles en ligne de commande. Ce fichier est généralement shairport-sync.conf et est normalement situé dans le répertoire de configuration système, qui est habituellement le répertoire /etc sous Linux ou le répertoire /usr/local/etc sous les systèmes Unix BSD. Vous pourriez avoir besoin de privilèges root pour le modifier.

(Note : Shairport Sync peut avoir été compilé pour utiliser un répertoire de configuration différent. Vous pouvez le déterminer en exécutant la commande $ shairport-sync -V. Le dernier élément de la chaîne de sortie est la valeur de sysconfdir, c'est-à-dire le Répertoire de Configuration Système.)

Dans le fichier de configuration, les paramètres sont organisés en groupes, par exemple, il y a un groupe general pour les paramètres standard, et un groupe alsa avec des paramètres qui concernent le backend ALSA. Voici un exemple de fichier de configuration typique :

general = {

name = "Boombox de Mike";

};

alsa = {

output_device = "hw:0";

mixer_control_name = "PCM";

};

Les utilisateurs ont généralement seulement besoin de définir (1) le nom du service et (2) le périphérique de sortie. Si le paramètre name est omis, le nom du service est dérivé du nom d'hôte du système. Par défaut, le backend ALSA sera choisi s'il est inclus dans la compilation. Si le périphérique de sortie (alsa) possède un mélangeur qui peut être utilisé pour contrôler le volume, alors (3) le nom du mélangeur doit être spécifié. Il est important de le faire si le mélangeur existe. Sinon, la sortie maximale du périphérique de sortie sera le réglage que le mélangeur a par hasard, ce qui sera une question de hasard et qui pourrait être très faible, voire silencieux.

Un fichier de configuration exemple avec tous les paramètres possibles, mais tous commentés, est installé sous le nom shairport-sync.conf.sample, dans le Répertoire de Configuration Système -- /etc sous Linux, /usr/local/etc sous les systèmes Unix BSD.

Le fichier de configuration exemple inclut une documentation détaillée des paramètres, et est également disponible à l'adresse https://github.com/mikebrady/shairport-sync/blob/master/scripts/shairport-sync.conf. Veuillez vous y référer pour les informations les plus à jour sur les paramètres du fichier de configuration.

OPTIONS

Il existe deux types d'options en ligne de commande pour shairport-sync : les options de programme régulières et les options de backend audio. Les options de programme sont toujours listées en premier, suivies des options de backend audio, précédées d'un symbole --.

Voir la section EXEMPLES pour des exemples d'utilisation.

OPTIONS PROGRAMME

Les options de programme sont utilisées par shairport-sync lui-même.

-a nom-service | --name=nom-service
Utilisez ce nom-service pour identifier ce lecteur dans iTunes, etc.

Les substitutions suivantes sont autorisées : %h pour le nom d'hôte de l'ordinateur, %H pour le nom d'hôte de l'ordinateur avec la première lettre capitalisée (ASCII uniquement), %v pour le numéro de version de shairport-sync, par exemple "3.0.1" et %V pour la chaîne de version de shairport-sync, par exemple "3.0.1-OpenSSL-Avahi-ALSA-soxr-metadata-sysconfdir:/etc".

La valeur par défaut est "%H", qui est remplacé par le nom d'hôte avec la première lettre capitalisée.

-B programme | --on-start=programme
Exécute programme lorsque la lecture est sur le point de commencer. Spécifiez le chemin complet du programme, par exemple /usr/bin/logger. Les scripts exécutables peuvent être utilisés, mais ils doivent avoir le shebang approprié (#!/bin/sh) dans l'en-tête.

Si vous voulez que shairport-sync attende que la commande soit terminée avant de commencer à jouer, sélectionnez également l'option -w.

-c nom-fichier | --configfile=nom-fichier
Lit les paramètres de configuration depuis nom-fichier. Par défaut, ils sont lus à partir de shairport-sync.conf dans le Répertoire de Configuration Système -- /etc sous Linux, /usr/local/etc sous les systèmes Unix BSD. Pour plus d'informations sur les paramètres de configuration, voir la section "Paramètres du Fichier de Configuration" ci-dessus.
-d | --daemon
Demande à shairport-sync de se transformer en démon. Il écrira son identifiant de processus (PID) dans un fichier, généralement à l'adresse /var/run/shairport-sync/shairport-sync.pid, qui est utilisé par les options -k, -D et -R pour localiser le démon ultérieurement. Voir aussi l'option -j. Uniquement disponible si shairport-sync a été compilé avec le support de libdaemon.
-E programme | --on-stop=programme
Exécute programme lorsque la lecture est terminée. Spécifiez le chemin complet du programme, par exemple /usr/bin/logger. Les scripts exécutables peuvent être utilisés, mais ils doivent avoir le shebang approprié (#!/bin/sh) dans l'en-tête.

Si vous voulez que shairport-sync attende que la commande soit terminée avant de continuer, sélectionnez également l'option -w.

-g | --get-coverart
Cette option nécessite que l'option -M | --metadata-enable soit définie, et permet à shairport-sync de demander la pochette d'album à la source et de la traiter comme métadonnées.
-h | --help
Affiche un bref message d'aide et quitte.
-j | justDaemoniseNoPIDFile
Demande à shairport-sync de se transformer en démon. Contrairement à l'option -d, il n'écrira pas d'identifiant de processus (PID) dans un fichier -- il se contentera (d'où le "j") de se transformer en démon. Uniquement disponible si shairport-sync a été compilé avec libdaemon

OPTIONS

-k | --kill
Tuer le démon shairport-sync et quitter. (Nécessite que le démon ait écrit son PID dans un fichier convenu -- voir l'option -d. Uniquement disponible si shairport-sync a été compilé avec le support de libdaemon.)
--logOutputLevel
Utilisez ceci pour enregistrer le niveau de volume lorsque le volume est modifié. Il peut être utile si vous essayez de déterminer une valeur appropriée pour le niveau de volume maximum. Pas disponible en tant que paramètre de fichier de configuration.
--log-to-syslog
Les avertissements, messages d'erreur et messages sont envoyés, par défaut, à STDERR. Utilisez cette option pour router ces messages vers le syslog à la place. Ceci est destiné à être utilisé lorsque Shairport Sync fonctionne en tant que démon.

Voir aussi --displayConfig.

-L | --latency=latence
Utilisez ceci pour définir la latence par défaut, en images, pour l'audio provenant d'une source non identifiée ou d'une source iTunes version 9 ou antérieure. La valeur standard pour la latence par défaut est de 88 200 images, où il y a 44 100 images par seconde.

Veuillez noter que cette fonctionnalité est dépréciée et sera supprimée dans une future version de shairport-sync.

-M | --metadata-enable
Demande au client d'envoyer des métadonnées. Elles seront envoyées, avec les métadonnées générées par shairport-sync lui-même, vers un tuyau (pipe) et seront également envoyées sous forme de paquets UDP. Si vous ajoutez -g | --get-cover-art, la pochette d'album sera incluse, le cas échéant. Voir https://github.com/mikebrady/shairport-sync-metadata-reader pour un exemple de lecteur de métadonnées.
--metadata-pipename=chemin
Spécifiez le chemin du tuyau de métadonnées. Notez que shairport-sync aura besoin de permissions d'écriture sur ce répertoire et ce tuyau. Le défaut est /tmp/shairport-sync-metadata. Si vous renommez l'exécutable shairport-sync, le nom du tuyau par défaut changera en conséquence.
-m backend_mdns | --mdns=backend_mdns
Force l'utilisation du backend mDNS spécifié pour annoncer le lecteur sur le réseau. Le défaut est d'essayer tous les backends mDNS dans l'ordre jusqu'à ce qu'un fonctionne.
-o backend_sortie | --output=backend_sortie
Force l'utilisation du backend de sortie spécifié pour lire l'audio. Le défaut est d'essayer le premier.
-p port | --port=port
Écoute les requêtes de lecture sur le port. Le défaut est d'utiliser le port 5000 pour AirPlay et 7000 pour AirPlay 2.
--password=secret
Exige le mot de passe secret pour pouvoir se connecter et diffuser vers le service. (Ceci ne fonctionne que pour AirPlay et pas pour AirPlay 2.)
-r seuil | --resync=seuil
Resynchronise si les timings diffèrent de plus de seuil images. Si le timing de sortie diffère du timing source de plus que le seuil, la sortie sera coupée et une resynchronisation complète aura lieu. Le seuil par défaut est de 2 205 images, soit 50 millisecondes. Spécifiez 0 pour désactiver la resynchronisation. Ce réglage est déprécié et sera supprimé dans une future version de shairport-sync.
--statistics
Affiche des informations de performance sur STDERR, ou sur syslog si l'option de ligne de commande -log-to-syslog est également choisie.
-S mode | --stuffing=mode
Interpole ("bourrage") le flux audio en utilisant le mode. Le "bourrage" fait référence au processus d'ajout ou de suppression d'images audio du flux envoyé au périphérique de sortie afin de le maintenir synchronisé avec le lecteur. Le mode basic est normalement presque complètement inaudible. Le mode alternatif, soxr, est encore moins intrusif mais nécessite beaucoup plus de puissance de traitement. Pour ce mode, le support de libsoxr, la SoX Resampler Library, doit être sélectionné lors de la compilation de shairport-sync. Le réglage par défaut, auto, permet à Shairport Sync de choisir le mode soxr si le système est suffisamment puissant.
-t délai | --timeout=délai
Quitte le mode de lecture si le flux disparaît pendant plus de délai secondes.

Lorsque shairport-sync lit un flux audio, il démarre une session de lecture et renvoie un signal d'occupation à toute autre source tentant de l'utiliser. Si le flux audio disparaît pendant plus de délai secondes, la session de lecture sera terminée. Si vous spécifiez un délai de 0, shairport-sync ne signalera jamais qu'il est occupé et n'empêchera pas d'autres sources de "s'inviter" dans une session de lecture existante. La valeur par défaut est de 120 secondes.

--tolerance=images
Permet une lecture jusqu'à images de désynchronisation exacte avant de tenter de la corriger. Le défaut est de 88 images, soit 2 ms. Plus la tolérance est petite, plus il est probable qu'une surcorrection se produise. La surcorrection se produit lorsqu'un plus grand nombre de corrections (insertions et suppressions) sont effectuées que nécessaire pour maintenir le flux synchronisé. Utilisez l'option --statistics pour surveiller les niveaux de correction. Les corrections ne devraient pas dépasser considérablement les corrections nettes. Ce réglage est déprécié et sera supprimé dans une future version de shairport-sync.
-V | --version
Affiche les informations de version et quitte.
-v | --verbose
Affiche les informations de débogage sur STDERR, ou sur syslog si l'option de ligne de commande -log-to-syslog est également choisie. Répétez jusqu'à trois fois (c'est-à-dire -vv ou -vvv) pour plus de détails. Vous devriez utiliser -vvv très rarement - c'est vraiment très verbeux.
-w | --wait-cmd
Attend que les commandes spécifiées avec -B ou -E soient terminées avant de continuer l'exécution.
-X | --displayConfig
Ceci enregistre des informations relatives à la configuration de Shairport Sync. Cela peut être très utile pour le débogage. Les informations enregistrées sont des informations sur le système d'exploitation hôte, la chaîne de version de Shairport Sync (qui indique les options de compilation utilisées lors de la compilation de shairport-sync), le contenu de la ligne de commande qui a invoqué Shairport Sync, le nom du fichier de configuration et les paramètres actifs qu'il contient.

Si c'est la seule option sur la ligne de commande, shairport-sync se terminera après avoir affiché les informations.

OPTIONS DE BACKEND AUDIO

Les options de backend audio sont des options de ligne de commande qui sont transmises au backend audio choisi. Elles sont toujours précédées du symbole -- pour les introduire et les séparer des options du programme précédentes. De cette manière, les lettres d'option peuvent être utilisées comme options de programme et réutilisées comme options de backend audio sans ambiguïté.

Les backends audio sont listés avec leurs options de backend audio correspondantes dans le texte d'aide fourni par l'option d'aide (-h ou --help).

EXEMPLES

Voici un exemple légèrement artificiel :

shairport-sync -a "Joe's Stereo" -o alsa -- -d hw:1,0 -m hw:1 -c PCM

Le programme sera visible sous le nom "Joe's Stereo" ( -a "Joe's Stereo" ). L'option de programme -o alsa spécifie que le backend alsa doit être utilisé, donc que l'audio doit être envoyé vers le sous-système audio ALSA. Les options du backend audio suivant le séparateur -- sont transmises au backend alsa et spécifient que l'audio sera envoyé sur le sous-périphérique 0 de la carte son 1 ( -d hw:1,0 ) et utilisera le mixeur de la même carte son ( -m hw:1 ) en utilisant le contrôle de niveau nommé "PCM" ( -c "PCM" ).

L'exemple ci-dessus est légèrement artificiel : Premièrement, si le backend alsa a été inclus dans la compilation, il sera le défaut, donc il n'a pas besoin d'être spécifié et l'option -o alsa pourrait être omise. Deuxièmement, le sous-périphérique 0 est le défaut pour une carte son, donc le périphérique de sortie pourrait simplement être écrit -d hw:1. Troisièmement, lorsqu'un nom de mixeur est donné ( -c "PCM" ), le défaut est que le mixeur se trouve sur le périphérique de sortie, donc le -m hw:1 n'est pas nécessaire ici. En utilisant ces défauts et simplifications, on obtient la commande suivante :

shairport-sync -a "Joe's Stereo" -- -d hw:1 -c PCM
