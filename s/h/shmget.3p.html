SHMGET(3P) Manuel du programmeur POSIX SHMGET(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

shmget — obtenir un segment de mémoire partagée XSI

SYNOPIS

#include <sys/shm.h>
int shmget(key_t key, size_t size, int shmflg);

DESCRIPTION

La fonction shmget() opère sur la mémoire partagée XSI (voir le volume Définitions de base de POSIX.1‐2017, Section 3.346, Objet de mémoire partagée). Il n'est pas spécifié si cette fonction interagit avec les facilités de communication interprocessus temps réel définies dans la Section 2.8, Temps réel.

La fonction shmget() renverra l'identifiant de mémoire partagée associé à key.

Un identifiant de mémoire partagée, une structure de données associée et un segment de mémoire partagée d'au moins size octets (voir <sys/shm.h>) sont créés pour key si l'une des conditions suivantes est vraie :

*
L'argument key est égal à IPC_PRIVATE.
*
L'argument key n'a pas encore d'identifiant de mémoire partagée associé et (shmflg &IPC_CREAT) est différent de zéro.

Lors de la création, la structure de données associée au nouvel identifiant de mémoire partagée sera initialisée comme suit :

*
Les valeurs de shm_perm.cuid, shm_perm.uid, shm_perm.cgid et shm_perm.gid sont définies à l'ID utilisateur effectif et à l'ID de groupe effectif, respectivement, du processus appelant.
*
Les neuf bits de poids faible de shm_perm.mode sont définis aux neuf bits de poids faible de shmflg.
*
La valeur de shm_segsz est définie à la valeur de size.
*
Les valeurs de shm_lpid, shm_nattch, shm_atime et shm_dtime sont définies à 0.
*
La valeur de shm_ctime est définie à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale IPC.

Lorsque le segment de mémoire partagée est créé, il sera initialisé avec des valeurs toutes à zéro.

VALEUR DE RETOUR

En cas de succès, shmget() renverra un entier non négatif, à savoir un identifiant de mémoire partagée ; sinon, il renverra -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction shmget() échouera si :

EACCES
Un identifiant de mémoire partagée existe pour key mais l'autorisation d'opération telle que spécifiée par les neuf bits de poids faible de shmflg ne serait pas accordée ; voir la Section 2.7, Communication Interprocessus XSI.
EEXIST
Un identifiant de mémoire partagée existe pour l'argument key mais (shmflg &IPC_CREAT) &&(shmflg &IPC_EXCL) est différent de zéro.
EINVAL
Un segment de mémoire partagée doit être créé et la valeur de size est inférieure au minimum imposé par le système ou supérieure au maximum imposé par le système.
EINVAL
Aucun segment de mémoire partagée ne doit être créé et un segment de mémoire partagée existe pour key mais la taille du segment qui lui est associé est inférieure à size.
ENOENT
Un identifiant de mémoire partagée n'existe pas pour l'argument key et (shmflg &IPC_CREAT) est 0.
ENOMEM
Un identifiant de mémoire partagée et le segment de mémoire partagée associé doivent être créés, mais la quantité de mémoire physique disponible est insuffisante pour répondre à la demande.
ENOSPC
Un identifiant de mémoire partagée doit être créé, mais la limite imposée par le système sur le nombre maximum d'identifiants de mémoire partagée autorisés au niveau du système serait dépassée.

UTILISATION PAR L'APPLICATION

L'extension Temps réel POSIX définit des interfaces alternatives pour la communication interprocessus. Les développeurs d'applications qui ont besoin d'utiliser l'IPC doivent concevoir leurs applications de manière à ce que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication Interprocessus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
