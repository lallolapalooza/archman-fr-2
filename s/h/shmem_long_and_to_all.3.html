SHMEM_LONG_AND_TO_ALL(3) Open MPI SHMEM_LONG_AND_TO_ALL(3)

shmem_int_and_to_all(3), shmem_int4_and_to_all(3), shmem_int8_and_to_all(3), shmem_long_and_to_all(3), shmem_longlong_and_to_all(3), shmem_short_and_to_all(3) - Effectue une opération ET binaire sur des tableaux symétriques sur l'ensemble actif des PEs.

SYNTAXE

C ou C++ :

#include <mpp/shmem.h>
void shmem_int_and_to_all(int *target, const int *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  int *pWrk, long *pSync)
void shmem_long_and_to_all(long *target, const long *source,
  int nreduce, int PE_start, int  logPE_stride, int PE_size,
  long *pWrk, long *pSync)
void shmem_longlong_and_to_all(long long *target,
  const long long *source, int nreduce, int PE_start, int logPE_stride,
  int PE_size, long long *pWrk, long *pSync)
void shmem_short_and_to_all(short *target, const short *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  short *pWrk, long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER pSync(SHMEM_REDUCE_SYNC_SIZE)
INTEGER nreduce, PE_start, logPE_stride, PE_size
CALL SHMEM_INT4_AND_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT8_AND_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)

DESCRIPTION

Les routines de réduction de mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PEs virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste des autres routines de réduction SHMEM, voir intro_shmem(3).

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PEs de l'ensemble actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PEs de l'ensemble actif. L'ensemble actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent. Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PEs de l'ensemble actif appellent la routine. Si un PE n'appartenant pas à l'ensemble actif appelle une routine collective SHMEM, le comportement est indéfini.

Les arguments sont les suivants :

cible
Un tableau symétrique, de longueur nreduce éléments, pour recevoir le résultat des opérations de réduction. Le type de données de cible varie selon la version de la routine de réduction appelée. Lors de l'appel depuis C/C++, se référer à la section SYNTAXE pour les informations sur le type de données. Lors de l'appel depuis Fortran, les types de données cibles sont les suivants :

shmem_int8_and_to_all : Entier, avec une taille d'élément de 8 octets

shmem_int4_and_to_all : Entier, avec une taille d'élément de 4 octets

source
Un tableau symétrique, de longueur nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, ce doit être une valeur entière par défaut.
PE_start
Le numéro de PE virtuel le plus bas de l'ensemble actif des PEs. PE_start doit être de type entier. Si vous utilisez Fortran, ce doit être une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, ce doit être une valeur entière par défaut.
PE_size
Le nombre de PEs dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, ce doit être une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync doit être de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync doit être de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, ce doit être une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran) avant que l'un des PEs de l'ensemble actif n'entre dans la routine de réduction.

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PEs de l'ensemble actif. Les mêmes tableaux cible et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PEs de l'ensemble actif.

Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont remplies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PEs de l'ensemble actif ne sont plus utilisés d'un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PEs de l'ensemble actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les éléments suivants sont vrais pour le PE local : Le tableau cible est mis à jour. Les valeurs dans le tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, donc un tableau pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE de l'ensemble actif pendant que l'un des PEs participe au traitement d'une routine de réduction SHMEM. Faites attention à éviter les situations suivantes : Si le tableau pSync est initialisé au moment de l'exécution, un certain type de synchronisation est nécessaire pour garantir que tous les PEs de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync ou pWrk peut être réutilisé dans un appel de routine de réduction ultérieur uniquement si aucun des PEs de l'ensemble actif n'est encore en train de traiter un appel de routine de réduction précédent qui utilisait les mêmes tableaux pSync ou pWrk. En général, cela ne peut être assuré qu'en effectuant une forme de synchronisation. Cependant, dans le cas spécial des routines de réduction appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et pWrk et alterner entre eux lors des appels successifs.

EXEMPLES

Exemple 1 : Cet exemple Fortran initialise statiquement le tableau pSync et trouve le ET logique de la variable entière FOO sur tous les PEs pairs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL PWRK(MAX(NR/2+1, SHMEM_REDUCE_MIN_WRKDATA_SIZE))
INTEGER FOO, FOOAND
COMMON /COM/ FOO, FOOAND, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT8_AND_TO_ALL(FOOAND, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOAND
ENDIF

Exemple 2 : Considérons l'appel C suivant :

shmem_int_and_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

L'appel précédent est plus efficace, mais sémantiquement équivalent, à la combinaison des appels suivants :

shmem_int_and_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_and_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_and_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Notez que deux ensembles de tableaux pWrk et pSync sont utilisés en alternance car aucune synchronisation n'est effectuée entre les appels.

DESCRIPTION

Ces fonctions d'agrégation collectives effectuent des opérations d'agrégation sur les valeurs de type long à partir de tous les PEs participants dans le domaine de communication actuel, et stockent le résultat dans le target sur tous les PEs participants.

Les opérations d'agrégation sont définies comme suit :

shmem_long_and_to_all
Effectue une opération AND bit à bit.
shmem_long_add_to_all
Effectue une addition.
shmem_long_and_all
Identique à shmem_long_and_to_all.
shmem_long_add_all
Identique à shmem_long_add_to_all.
shmem_long_inc_to_all
Effectue une incrémentation.
shmem_long_inc_all
Identique à shmem_long_inc_to_all.
shmem_long_max_to_all
Trouve le maximum.
shmem_long_max_all
Identique à shmem_long_max_to_all.
shmem_long_min_to_all
Trouve le minimum.
shmem_long_min_all
Identique à shmem_long_min_to_all.
shmem_long_or_to_all
Effectue une opération OR bit à bit.
shmem_long_or_all
Identique à shmem_long_or_to_all.
shmem_long_sum_to_all
Effectue une somme.
shmem_long_sum_all
Identique à shmem_long_sum_to_all.
shmem_long_xor_to_all
Effectue une opération XOR bit à bit.
shmem_long_xor_all
Identique à shmem_long_xor_to_all.

Les fonctions avec le suffixe _to_all nécessitent que le target soit alloué par shmem_malloc ou shmem_calloc.

Les fonctions avec le suffixe _all permettent au target d'être n'importe quel tableau d'entiers longs.

Les fonctions avec le suffixe _to_all et _all sont obsolètes et devraient être remplacées par les fonctions correspondantes avec le suffixe _reduce.

Les arguments target, value, nreduce, PE_stride et pSync sont les mêmes que pour les fonctions shmem_reduce(3).

NOTES

Ces fonctions sont disponibles dans le cadre de l'API Open SHMEM. Les fonctions avec le suffixe _to_all sont obsolètes et seront supprimées dans les futures versions d'Open SHMEM. Il est recommandé d'utiliser les fonctions avec le suffixe _reduce à la place.

EXAMPLES

Voici un exemple d'utilisation de shmem_long_sum_to_all :

#include <shmem.h>
#include <stdio.h>
int
main(void)
{
    long    *target;
    long    value;
    long    pSync[_SHMEM_REDUCE_SYNC_SIZE];
    int     i;

    long    my_val;

    shmem_init();

    target = (long *) shmem_malloc(sizeof(long));
    for (i = 0; i < _SHMEM_REDUCE_SYNC_SIZE; i++) {
        pSync[i] = SHMEM_SYNC_VALUE;
    }

    my_val = 10 * (shmem_my_pe() + 1);
    value = my_val;

    shmem_long_sum_to_all(target, value, 1, 0, pSync);

    if (shmem_my_pe() == 0) {
        printf("Sum of values: %ld\n", *target);
    }

    shmem_free(target);
    shmem_finalize();

    return 0;
}
