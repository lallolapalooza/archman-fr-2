shmem_collect32(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

SHMEM_COLLECT32(3) Open MPI SHMEM_COLLECT32(3)

shmem_collect4(3), shmem_collect8(3), shmem_collect32(3), shmem_collect64(3), shmem_fcollect(3), shmem_fcollect4(3), shmem_fcollect8(3), shmem_fcollect32(3), shmem_fcollect64(3) - Concatène des blocs de données de plusieurs éléments de traitement (PE) dans un tableau dans chaque PE

SYNTAXE

C ou C++ :

#include <mpp/shmem.h>
void shmem_collect32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_collect64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_fcollect32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_fcollect64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)

Fortran :

INCLUDE "mpp/shmem.fh"
INTEGER nelems
INTEGER PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_COLLECT_SYNC_SIZE)
CALL SHMEM_COLLECT4(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_COLLECT8(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_FCOLLECT4(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_FCOLLECT8(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)

DESCRIPTION

Les routines de mémoire partagée (SHMEM) collect et fcollect concatènent nelems éléments de données de 64 bits ou 32 bits du tableau source dans le tableau cible, sur l'ensemble des PE défini par PE_start, log2PE_stride et PE_size, dans l'ordre des numéros de processeur. Le tableau cible résultant contient la contribution du PE PE_start en premier, puis la contribution du PE PE_start + PE_stride ensuite, et ainsi de suite. Le résultat collecté est écrit dans le tableau cible pour tous les PE de l'ensemble actif.

Les routines fcollect exigent que nelems soit la même valeur dans tous les PE participants, tandis que les routines collect permettent à nelems de varier d'un PE à l'autre.

Le tableau cible résultant est le suivant :

----------------------------------------------------------
   source(1..nelems)
       du PE (PE_start + 0 * (2**logPE_stride))
----------------------------------------------------------
   source(1..nelems)
       du PE (PE_start + 1 * (2**logPE_stride))
----------------------------------------------------------
   ...
----------------------------------------------------------
   source(1..nelems) du
       PE (PE_start + (PE_size - 1) * (2**logPE_stride))
----------------------------------------------------------

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE de l'ensemble actif appellent la routine. Si un PE non appartenant à l'ensemble actif appelle une routine collective SHMEM, cela entraîne un comportement indéfini.

Les arguments sont les suivants :

target
Un tableau symétrique. L'argument cible doit être suffisamment grand pour accepter la concaténation des tableaux source sur tous les PE. Les types de données sont les suivants :
[shmem_collect8, shmem_collect64, shmem_fcollect8, et
shmem_fcollect64] tout type de données avec une taille d'élément de 64 bits. Les types dérivés Fortran, le type caractère Fortran et les structures C/C++ ne sont pas autorisés.
[shmem_collect4, shmem_collect32, shmem_fcollect4, et
shmem_fcollect32] tout type de données avec une taille d'élément de 32 bits. Les types dérivés Fortran, le type caractère Fortran et les structures C/C++ ne sont pas autorisés.
source
Un objet de données symétrique qui peut être de n'importe quel type autorisé pour l'argument cible.
nelems
Le nombre d'éléments dans le tableau source. nelems doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel de l'ensemble actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le log (base 2) du pas entre les numéros de PE virtuels consécutifs dans l'ensemble actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans l'ensemble actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pSync
Un tableau de travail symétrique. En C/C++, pSync doit être de type int et de taille _SHMEM_COLLECT_SYNC_SIZE. En Fortran, pSync doit être de type entier et de taille SHMEM_COLLECT_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE en C/C++ ou SHMEM_SYNC_VALUE en Fortran avant que l'un des PE de l'ensemble actif n'entre dans shmem_barrier().

Les valeurs des arguments PE_start, logPE_stride et PE_size doivent être identiques sur tous les PE de l'ensemble actif. Les mêmes tableaux cible et source, ainsi que le même tableau de travail pSync, doivent être passés à tous les PE de l'ensemble actif.

Au retour d'une routine collective, les conditions suivantes sont vraies pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées à leurs valeurs d'origine.

NOTES

Les termes collectif et symétrique sont définis dans intro_shmem(3). Toutes les routines collectives SHMEM réinitialisent les valeurs de pSync avant de retourner. Un tableau pSync particulier n'a donc besoin d'être initialisé que la première fois qu'il est utilisé.

Vous devez vous assurer que le tableau pSync n'est pas mis à jour sur un PE de l'ensemble actif pendant que l'un des PE participe au traitement d'un appel de routine collective SHMEM utilisant pSync. Faites attention à éviter ces situations : Si le tableau pSync est initialisé au moment de l'exécution, une forme de synchronisation est nécessaire pour garantir que tous les PE de l'ensemble de travail ont initialisé pSync avant que l'un d'eux n'entre dans une routine SHMEM appelée avec le tableau de synchronisation pSync. Un tableau pSync peut être réutilisé lors d'une routine collective SHMEM ultérieure uniquement si aucun des PE de l'ensemble actif ne traite encore un appel de routine collective SHMEM antérieur qui utilisait le même tableau pSync. En général, cela ne peut être garanti qu'en effectuant une forme de synchronisation. Cependant, dans le cas particulier des routines SHMEM appelées avec le même ensemble actif, vous pouvez allouer deux tableaux pSync et alterner entre eux lors d'appels successifs.

Les routines collectives fonctionnent sur des ensembles de PE actifs ayant une taille de PE non puissance de deux avec une certaine dégradation des performances. Elles fonctionnent sans dégradation des performances lorsque nelems est une valeur non puissance de deux.

EXEMPLES

C/C++ :

for (i=0; i < _SHMEM_COLLECT_SYNC_SIZE; i++) {
  pSync[i] = _SHMEM_SYNC_VALUE;
}
shmem_barrier_all(); /* Attend que tous les PE initialisent pSync */
shmem_collect32(target, source, 64, pe_start, logPE_stride,
   pe_size, pSync);

Fortran :

INTEGER PSYNC(SHMEM_COLLECT_SYNC_SIZE)
DATA PSYNC /SHMEM_COLLECT_SYNC_SIZE*SHMEM_SYNC_VALUE/
CALL SHMEM_COLLECT4(TARGET, SOURCE, 64, PE_START,
& LOGPE_STRIDE, PE_SIZE, PSYNC)
