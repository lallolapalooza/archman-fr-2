oshcc, oshcxx, oshc++, oshfort, shmemcc, shmemcxx, shmemc++, shmemfort — Compilateurs wrapper OpenSHMEM

SYNTAX

oshcc [--showme | --showme:compile | --showme:link] ...

oshcxx [--showme | --showme:compile | --showme:link] ...

oshc++ [--showme | --showme:compile | --showme:link] ...

oshfort [--showme | --showme:compile | --showme:link] ...

shmemcc [--showme | --showme:compile | --showme:link] ...

shmemcxx [--showme | --showme:compile | --showme:link] ...

shmemc++ [--showme | --showme:compile | --showme:link] ...

shmemfort [--showme | --showme:compile | --showme:link] ...

OPTIONS

Les options ci-dessous s'appliquent à tous les compilateurs wrapper :

•
--showme : Cette option existe sous plusieurs variantes (voir ci-dessous). Aucune des variantes n'invoque le compilateur sous-jacent ; elles fournissent toutes des informations sur la manière dont le compilateur sous-jacent aurait été invoqué si --showme n'avait pas été utilisé. L'option de base --showme affiche la ligne de commande qui serait exécutée pour compiler le programme.

NOTE :

Si un argument qui n'est pas un nom de fichier est passé sur la ligne de commande, l'option --showme n'affichera pas de drapeaux supplémentaires. Par exemple, "oshcc --showme et oshcc --showme my_source.c afficheront tous les drapeaux fournis par le wrapper. Mais oshcc --showme -v n'affichera que le nom du compilateur sous-jacent et -v.
  • --showme:compile : Affiche les drapeaux du compilateur qui auraient été fournis au compilateur sous-jacent.
  • --showme:link : Affiche les drapeaux de l'éditeur de liens qui auraient été fournis au compilateur sous-jacent.
  • --showme:command : Affiche la commande du compilateur sous-jacent (qui peut être un ou plusieurs jetons).
  • --showme:incdirs : Affiche une liste de répertoires séparés par des espaces (mais autrement non décorés) que le compilateur wrapper aurait fournis au compilateur sous-jacent pour indiquer où se trouvent les fichiers d'en-tête pertinents.
  • --showme:libdirs : Affiche une liste de répertoires séparés par des espaces (mais autrement non décorés) que le compilateur wrapper aurait fournis à l'éditeur de liens sous-jacent pour indiquer où se trouvent les bibliothèques pertinentes.
  • --showme:libs : Affiche une liste de noms de bibliothèques séparés par des espaces (mais autrement non décorés) que le compilateur wrapper aurait utilisés pour lier une application. Par exemple : mpi open-pal util.
  • --showme:version : Affiche le numéro de version d'Open MPI.
  • --showme:help : Affiche un bref message d'aide sur l'utilisation.

Consultez la page de manuel de votre compilateur sous-jacent pour connaître les autres options qui peuvent être passées à oshcc.

DESCRIPTION

Conceptuellement, le rôle de ces commandes est assez simple : ajouter de manière transparente les drapeaux de compilation et d'édition de liens pertinents à la ligne de commande de l'utilisateur qui sont nécessaires pour compiler / lier les programmes OpenSHMEM, puis invoquer le compilateur sous-jacent pour effectuer réellement la commande.

En tant que tels, ces commandes sont souvent appelées compilateurs « wrapper » car elles ne compilent ou ne lient pas réellement les applications elles-mêmes ; elles ajoutent uniquement des drapeaux à la ligne de commande et invoquent le compilateur de backend.

BACKGROUND

Open MPI fournit des compilateurs wrapper pour plusieurs langages :

  • oshcc, shmemcc : C
  • oshc++, oshcxx, shmemc++, shmemcxx`:: C++
  • oshfort, shmemfort : Fortran

Les compilateurs wrapper pour chacun des langages sont identiques ; ils peuvent être utilisés de manière interchangeable. Les différents noms sont fournis uniquement pour la compatibilité ascendante.

FORTRAN NOTES

Le compilateur wrapper Fortran pour OpenSHMEM (oshfort et shmemfort) peut compiler et lier des applications OpenSHMEM qui utilisent n'importe lesquels/tous les bindings Fortran d'OpenSHMEM.

Notez, cependant, que le compilateur Fortran peut nécessiter des options de ligne de commande supplémentaires pour imposer un dialecte Fortran spécifique. Par exemple, dans certaines versions du compilateur IBM XLF, -qfixed peut être nécessaire pour compiler des fichiers source Fortran au format fixe.

Enfin, notez que oshfort sera inopérant et retournera une erreur en cas d'utilisation si le support Fortran n'a pas été intégré à la couche OpenSHMEM.

OVERVIEW

oshcc et shmemcc sont des wrappers de commodité pour le compilateur C sous-jacent. La traduction d'un programme OpenSHMEM nécessite la liaison des bibliothèques spécifiques à OpenSHMEM qui peuvent ne pas résider dans l'un des répertoires de recherche standard de ld(1). Elle nécessite également souvent l'inclusion de fichiers d'en-tête qui peuvent également ne pas être trouvés dans un emplacement standard.

oshcc et shmemcc passent leurs arguments au compilateur C sous-jacent ainsi que les options -I, -L et -l requises par les programmes OpenSHMEM.

Il en va de même pour tous les autres compilateurs wrapper de langage.

L'équipe OpenSHMEM encourage vivement l'utilisation des compilateurs wrapper plutôt que de tenter de lier manuellement les bibliothèques OpenSHMEM. Cela permet à l'implémentation spécifique d'OpenSHMEM de changer sans forcer les changements dans les directives de liaison des Makefiles des utilisateurs. En effet, l'ensemble spécifique de drapeaux et de bibliothèques utilisé par les compilateurs wrapper dépend de la manière dont OpenSHMEM a été configuré et construit ; les valeurs peuvent changer entre différentes installations de la même version d'OpenSHMEM.

En effet, puisque les wrappers ne sont que des coquilles minces au-dessus d'un compilateur sous-jacent, il y a très, très peu de raisons impérieuses de ne pas utiliser oshcc. Lorsque ce n'est pas possible d'utiliser les wrappers directement, les options --showme:compile et --showme:link doivent être utilisées pour déterminer quels drapeaux les wrappers auraient utilisés. Par exemple :

shell$ cc -c file1.c `shmemcc --showme:compile`
shell$ cc -c file2.c `shmemcc --showme:compile`
shell$ cc file1.o file2.o `shmemcc --showme:link` -o my_oshmem_program

NOTES

Il est possible de rendre les compilateurs wrapper multi-bibliothèques. C'est-à-dire que les bibliothèques et les includes spécifiés peuvent différer en fonction des drapeaux du compilateur spécifiés (par exemple, avec les compilateurs GNU sous Linux, un chemin de bibliothèque différent peut être utilisé si -m32 est vu par rapport à -m64). Ce n'est pas le comportement par défaut dans une construction standard, mais cela peut être activé (par exemple, dans un paquet binaire fournissant le support 32 et 64 bits). Plus d'informations peuvent être trouvées ici.

FILES

Les chaînes que les compilateurs wrapper insèrent dans la ligne de commande avant d'invoquer le compilateur sous-jacent sont stockées dans un fichier texte créé par OpenSHMEM et installé dans $pkgdata/NAME-wrapper-data.txt, où :

  • $pkgdata est généralement $prefix/share/openmpi
  • $prefix est le répertoire d'installation principal d'OpenSHMEM
  • NAME est le nom du compilateur wrapper (par exemple, $pkgdata/shmemcc-wrapper-data.txt)

Il est rarement nécessaire de modifier ces fichiers, mais ils peuvent être examinés pour mieux comprendre quels drapeaux les wrappers placent sur la ligne de commande.

ENVIRONMENT VARIABLES

Par défaut, les wrappers utilisent les compilateurs qui ont été sélectionnés lors de la configuration d'OpenSHMEM. Ces compilateurs ont été trouvés automatiquement par le script « configure » d'Open MPI, ou ont été sélectionnés par l'utilisateur dans les variables d'environnement CC, CXX et/ou FC avant l'invocation de configure. De plus, d'autres arguments spécifiques au compilateur peuvent avoir été sélectionnés par configure.

Ces valeurs peuvent être remplacées sélectivement soit en modifiant les fichiers texte contenant ces informations de configuration (voir la section FILES), soit en définissant des variables d'environnement sélectionnées
