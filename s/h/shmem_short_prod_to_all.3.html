DESCRIPTION

Les routines de réduction de la mémoire partagée (SHMEM) calculent une ou plusieurs réductions sur des tableaux symétriques sur plusieurs PE virtuels. Une réduction effectue une opération binaire associative sur un ensemble de valeurs. Pour une liste d'autres routines de réduction SHMEM, voir intro_shmem(3).

Comme pour toutes les routines collectives SHMEM, chacune de ces routines suppose que seuls les PE du jeu actif appellent la routine. Si un PE ne faisant pas partie du jeu actif appelle une routine collective SHMEM, un comportement indéfini en résulte.

L'argument nreduce détermine le nombre de réductions distinctes à effectuer. Le tableau source sur tous les PE du jeu actif fournit un élément pour chaque réduction. Les résultats des réductions sont placés dans le tableau cible sur tous les PE du jeu actif. Le jeu actif est défini par le triplet PE_start, logPE_stride, PE_size.

Les tableaux source et cible peuvent être le même tableau, mais ils ne peuvent pas être des tableaux qui se chevauchent.

Les arguments sont les suivants :

cible
Un tableau symétrique de nreduce éléments pour recevoir les résultats des opérations de réduction. Le type de données de cible varie selon la version de la routine de réduction appelée et la langue utilisée. Lors de l'appel depuis C/C++, reportez-vous à la section SYNTAXE pour les informations sur les types de données. Lors de l'appel depuis Fortran, les types de données de cible sont les suivants :
shmem_comp4_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 4 octets.
shmem_comp8_prod_to_all: Complexe, avec une taille d'élément égale à deux
valeurs réelles de 8 octets.

shmem_int4_prod_to_all : Entier, avec une taille d'élément de 4 octets

shmem_int8_prod_to_all : Entier, avec une taille d'élément de 8 octets

shmem_real4_prod_to_all : Réel, avec une taille d'élément de 4 octets

shmem_real8_prod_to_all : Réel, avec une taille d'élément de 8 octets

shmem_real16_prod_to_all : Réel, avec une taille d'élément de 16 octets

source
Un tableau symétrique, de nreduce éléments, qui contient un élément pour chaque opération de réduction distincte. L'argument source doit avoir le même type de données que cible.
nreduce
Le nombre d'éléments dans les tableaux cible et source. nreduce doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_start
Le plus petit numéro de PE virtuel du jeu actif de PE. PE_start doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
logPE_stride
Le logarithme (base 2) du pas entre les numéros de PE virtuels consécutifs dans le jeu actif. logPE_stride doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
PE_size
Le nombre de PE dans le jeu actif. PE_size doit être de type entier. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut.
pWrk
Un tableau de travail symétrique. L'argument pWrk doit avoir le même type de données que cible. En C/C++, il contient max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments. En Fortran, il contient max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) éléments.
pSync
Un tableau de travail symétrique. En C/C++, pSync est de type long et de taille _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync est de type entier et de taille SHMEM_REDUCE_SYNC_SIZE. Si vous utilisez Fortran, il doit s'agir d'une valeur entière par défaut. Avant que l'un des PE du jeu actif n'appelle la routine de réduction, chaque élément de ce tableau doit être initialisé avec la valeur _SHMEM_SYNC_VALUE (en C/C++) ou SHMEM_SYNC_VALUE (en Fortran).

Les valeurs des arguments nreduce, PE_start, logPE_stride et PE_size doivent être égales sur tous les PE du jeu actif. Les mêmes tableaux cible et source, ainsi que les mêmes tableaux de travail pWrk et pSync, doivent être passés à tous les PE du jeu actif. Avant que tout PE n'appelle une routine de réduction, vous devez vous assurer que les conditions suivantes sont réunies (une synchronisation via une barrière ou une autre méthode est souvent nécessaire pour garantir cela) : Les tableaux pWrk et pSync sur tous les PE du jeu actif ne sont plus utilisés à partir d'un appel précédent à une routine collective SHMEM. Le tableau cible sur tous les PE du jeu actif est prêt à recevoir les résultats de la réduction.

Au retour d'une routine de réduction, les conditions suivantes sont vraies pour le PE local : Le tableau cible est mis à jour. Les valeurs du tableau pSync sont restaurées aux valeurs d'origine.

NOTES

Les termes collective, symétrique et aligné en cache sont définis dans intro_shmem(3). Toutes les routines de réduction SHMEM réinitialisent les valeurs de pSync avant de retourner, donc un tampon pSync particulier n'a besoin d'être initialisé que la première fois qu'il est utilisé.

DESCRIPTION

These parallel routines compute the product of an array of elements across a specified subset of processing elements (PEs). The product is stored in the PE that is logically the first PE in the specified range (PE_min). The result is available on all PEs in the specified range.

The routines are named according to the data type of the elements being operated on:

COMP8
Complex 8-byte elements (e.g., 4-byte real and imaginary parts).
SHORT
Short integers.
INT
Integers.
LONG
Long integers.
DOUBLE
Double-precision floating-point elements.
LONGDOUBLE
Long double-precision floating-point elements.

The routines differ in the Fortran function name and the C function name and signature. The Fortran routines are subroutines, while the C routines are functions that return void.

The arguments are defined as follows:

target
A pointer to the target array where the result will be stored. In Fortran, this is the first element of the target array. In C, this is a pointer to the first element of the target array.
source
A pointer to the source array containing the data to be multiplied. In Fortran, this is the first element of the source array. In C, this is a pointer to the first element of the source array.
nreduce
The number of elements in the source and target arrays to be reduced. This is a size_t in C and an integer in Fortran.
PE_min
The PE number of the first PE in the range of PEs participating in the reduction. This is the PE that will hold the final result.
PE_max
The PE number of the last PE in the range of PEs participating in the reduction.
pSync
A pointer to the synchronization array. This array must be initialized before calling the reduction routine. The size and initialization requirements are described in the NOTES section.

The range of PEs involved in the reduction is defined by PE_min and PE_max, inclusive. The default range of PEs for SHMEM synchronization is all PEs in the current job. This can be changed with the use of the Symmetric Heap Manager (SHM) or by using the shmem_pe_mask and shmem_pe_set routines.

The reduction operation is a product. The operation is associative. The identity element for the product operation is 1.

The reduction is performed across the PEs specified by PE_min and PE_max. The result is stored in the `target` array on PE `PE_min`. The result is then broadcasted to all other participating PEs.

The synchronization array `pSync` is used to ensure that all PEs involved in the reduction have completed their work before proceeding. This is crucial for correctness, especially when reusing the synchronization array for subsequent reduction calls.

NOTES

The synchronization array `pSync` must be initialized to the value `SHMEM_SYNC_VALUE` (Fortran) or `SHMEM_SYNC_VALUE` (C). The size of the synchronization array is defined by the constant `SHMEM_REDUCE_SYNC_SIZE` (Fortran) or `SHMEM_REDUCE_SYNC_SIZE` (C).

The working array `pWrk` is required by some reduction routines. The size of the working array is defined by the constant `SHMEM_REDUCE_MIN_WRKDATA_SIZE` (Fortran) or `SHMEM_REDUCE_MIN_WRKDATA_SIZE` (C). The C routines pass the working array as the second to last argument. The Fortran routines do not explicitly pass a working array, but it is implicitly handled by the runtime.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
