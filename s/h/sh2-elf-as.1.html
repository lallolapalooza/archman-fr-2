DESCRIPTION

GNU as est en réalité une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les formats de fichiers objet, la plupart des directives de l'assembleur (souvent appelées pseudo-ops) et la syntaxe de l'assembleur.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour être utilisée par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte que as assemble correctement tout ce que d'autres assembleurs pour la même machine assembleraient. Les exceptions sont explicitement documentées. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture ; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage d'assemblage 680x0.

Chaque fois que vous exécutez as, il assemble exactement un programme source. Le programme source est composé d'un ou plusieurs fichiers. (L'entrée standard est également un fichier.)

Vous donnez à as une ligne de commande qui contient zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du nom de fichier de gauche vers la droite). Un argument de ligne de commande (quelle que soit sa position) qui n'a pas de signification spéciale est considéré comme un nom de fichier d'entrée.

Si vous ne donnez aucun nom de fichier à as, il tente de lire un fichier d'entrée à partir de l'entrée standard de as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler.

Utilisez -- si vous avez besoin de nommer explicitement le fichier d'entrée standard dans votre ligne de commande.

Si la source est vide, as produit un petit fichier objet vide.

as peut écrire des avertissements et des messages d'erreur dans le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas se produire lorsqu'un compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour que as puisse continuer à assembler un programme défectueux ; les erreurs signalent un problème grave qui arrête l'assemblage.

Si vous invoquez as via le compilateur GNU C, vous pouvez utiliser l'option -Wa pour passer des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple :

gcc -c -g -O -Wa,-alh,-L file.c

Ceci passe deux options à l'assembleur : -alh (émettre une liste sur la sortie standard avec la source de haut niveau et l'assembleur) et -L (conserver les symboles locaux dans la table des symboles).

Normalement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote du compilateur GNU avec l'option -v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.)

OPTIONS

@file
Lit les options de ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans file sont séparées par des espaces blancs. Un espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure d'un antislash. Le file peut lui-même contenir des options @file supplémentaires ; ces options seront traitées récursivement.

-a[cdghilmns]
Active les listes, de différentes manières :
-ac
omet les conditionnels faux
-ad
omet les directives de débogage
-ag
inclut des informations générales, comme la version de as et les options passées
-ah
inclure le code source de haut niveau
-al
inclure l'assembleur
-ali
inclure l'assembleur avec ginsn
-am
inclure les expansions de macros
-an
omettre le traitement des formulaires
-as
inclure les symboles
=fichier
définir le nom du fichier de liste

Vous pouvez combiner ces options ; par exemple, utilisez -aln pour une liste d'assemblage sans traitement des formulaires. L'option =fichier, si elle est utilisée, doit être la dernière. En soi, -a est par défaut -ahls.

--alternate
Commencer en mode macro alternatif.
--compress-debug-sections
Compresser les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens éditeurs de liens et utilitaires de fichiers objets. Notez que si la compression rend une section donnée plus grande, elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent comment les sections de débogage DWARF sont compressées. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format obsolète zlib-gnu. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Notez - si la compression rendait en fait une section plus grande, alors elle n'est ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement le défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour remplacer cela.
-D
Activer le débogage dans les backends spécifiques à la cible, si supporté. Sinon, ignoré. Même si ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrez les informations de débogage les décrivant comme dans nouveau à la place.
--defsym sym=valeur
Définir le symbole sym à valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un préfixe 0x indique une valeur hexadécimale, et un préfixe 0 indique une valeur octale. La valeur du symbole peut être remplacée à l'intérieur d'un fichier source via l'utilisation d'une pseudo-instruction ".set".
--dump-config
Affiche la configuration de l'assembleur puis quitte.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". Le défaut peut être contrôlé par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour supporter plusieurs configurations cibles différentes, cette option peut être utilisée pour sélectionner la forme désirée.
-f
"rapide"---sauter le prétraitement des espaces blancs et des commentaires (supposer que la source est une sortie de compilateur).
-g
--gen-debug
Générer des informations de débogage pour chaque ligne source d'assembleur en utilisant quel que soit le format de débogage préféré par la cible. Cela signifie actuellement soit STABS, ECOFF ou DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et ".debug_line" n'est émise que lorsque le fichier d'assemblage n'en génère pas une lui-même.
--gstabs
Générer des informations de débogage stabs pour chaque ligne d'assembleur. Cela peut aider au débogage du code d'assembleur, si le débogueur peut le gérer.
--gstabs+
Générer des informations de débogage stabs pour chaque ligne d'assembleur, avec des extensions GNU que seul gdb peut probablement gérer, et qui pourraient faire planter ou refuser de lire votre programme à d'autres débogueurs. Cela peut aider au débogage du code d'assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Générer des informations de débogage DWARF2 pour chaque ligne d'assembleur. Cela peut aider au débogage du code d'assembleur, si le débogueur peut le gérer. Notez --- cette option n'est supportée que par certaines cibles, pas toutes.
--gdwarf-3
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 3 de la spécification DWARF. Notez - activer cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-4
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 4 de la spécification DWARF. Notez - activer cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-5
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 5 de la spécification DWARF. Notez - activer cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, créez une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code appelée .text.func aura ses informations de ligne de débogage placées dans une section appelée .debug_line.text.func. Si la section de code est simplement appelée .text, alors la section de ligne de débogage sera toujours appelée juste .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'information communes DWARF (CIE) est produite. Lorsque ce drapeau n'est pas spécifié, le défaut est la version 1, bien que certaines cibles puissent modifier ce défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attributs GNU Build si aucune n'est présente dans les sources d'entrée. Le défaut peut être contrôlé par l'option de configuration --enable-generate-build-notes.
--gsframe
--gsframe
Crée la section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Supporté pour la compatibilité de la ligne de commande avec d'autres assembleurs.
--help
Affiche un résumé des options de la ligne de commande et quitte.
--target-help
Affiche un résumé de toutes les options spécifiques à la cible et quitte.
-I rep
Ajoute le répertoire rep à la liste de recherche pour les directives ".include".
-J
Ne pas avertir du dépassement signé.
-K
Émettre des avertissements lorsque les tables de différence sont modifiées pour des déplacements longs.
-L
--keep-locals
Conserver (dans la table des symboles) les symboles locaux. Ces symboles commencent par des préfixes d'étiquette locale spécifiques au système, généralement .L pour les systèmes ELF ou L pour les systèmes a.out traditionnels.
--listing-lhs-width=nombre

--text-section-literals | --no-text-section-literals
Contrôle le traitement des pools de littéraux. Le défaut est --no-text-section-literals, qui place les littéraux dans des sections séparées dans le fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --text-section-literals, les littéraux sont entrelacés dans la section de texte afin de les maintenir aussi proches que possible de leurs références. Cela peut être nécessaire pour les grands fichiers d'assemblage, où les littéraux seraient autrement hors de portée des instructions "L32R" dans la section de texte. Les littéraux sont regroupés en pools suivant les directives ".literal_position" ou précédant les instructions "ENTRY". Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément.
--auto-litpools | --no-auto-litpools
Contrôle le traitement des pools de littéraux. Le défaut est --no-auto-litpools, qui, en l'absence de --text-section-literals, place les littéraux dans des sections séparées dans le fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --auto-litpools, les littéraux sont entrelacés dans la section de texte afin de les maintenir aussi proches que possible de leurs références, les directives explicites ".literal_position" ne sont pas requises. Cela peut être nécessaire pour des fonctions très grandes, où un seul pool de littéraux au début de la fonction peut ne pas être accessible par les instructions "L32R" à la fin. Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément. Lorsqu'utilisé conjointement avec --text-section-literals, --auto-litpools prend le dessus.
--absolute-literals | --no-absolute-literals
Indique à l'assembleur si les instructions "L32R" utilisent un adressage absolu ou relatif au PC. Si le processeur inclut l'option d'adressage absolu, le défaut est d'utiliser les relocalisations "L32R" absolues. Sinon, seules les relocalisations "L32R" relatives au PC peuvent être utilisées.
--target-align | --no-target-align
Activer ou désactiver l'alignement automatique pour réduire les pénalités de branchement au détriment d'une certaine taille de code. Cette optimisation est activée par défaut. Notez que l'assembleur alignera toujours les instructions comme "LOOP" qui ont des exigences d'alignement fixes.
--longcalls | --no-longcalls
Active ou désactive la transformation des instructions d'appel pour permettre des appels à une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles d'appel peuvent potentiellement être hors de portée. Elle peut dégrader la taille du code et les performances, mais l'éditeur de liens peut généralement optimiser les surcoûts inutiles lorsqu'un appel se situe dans la plage. La valeur par défaut est --no-longcalls.
--transform | --no-transform
Active ou désactive toutes les transformations d'instructions Xtensa par l'assembleur, y compris la relaxation et l'optimisation. La valeur par défaut est --transform ; --no-transform ne doit être utilisé que dans les cas rares où les instructions doivent être exactement telles que spécifiées dans le code source assembleur. L'utilisation de --no-transform entraîne des erreurs pour les opérandes d'instructions hors de portée.
--rename-section oldname=newname
Renomme la section oldname en newname. Cette option peut être utilisée plusieurs fois pour renommer plusieurs sections.
--trampolines | --no-trampolines
Active ou désactive la transformation des instructions de saut pour permettre des sauts à une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles de saut peuvent potentiellement être hors de portée. En l'absence de tels sauts, cette option n'affecte pas la taille du code ni les performances. Options en ligne de commande

-march=CPU[-EXT...][+EXT...]
Cette option spécifie le processeur cible. L'assembleur émettra un message d'erreur si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur le processeur cible. Les noms de processeurs suivants sont reconnus : "z80", "z180", "ez80", "gbz80", "z80n", "r800". En plus de l'ensemble d'instructions de base, l'assembleur peut être informé pour accepter certaines mnémotechniques d'extension. Par exemple, "-march=z180+sli+infc" étend z180 avec les instructions SLI et IN F,(C). Les extensions suivantes sont actuellement prises en charge : "full" (toutes les instructions connues), "adl" (mode CPU ADL par défaut, eZ80 seulement), "sli" (instruction connue sous le nom de SLI, SLL ou SL1), "xyhl" (instructions avec moitiés de registres d'index : IXL, IXH, IYL, IYH), "xdcb" (instructions comme RotOp (II+d),R et BitOp n,(II+d),R), "infc" (instruction IN F,(C) ou IN (C)), "outc0" (instruction OUT (C),0). Si cette option n'est pas spécifiée, alors "-march=z80+xyhl+infc" est supposé.
