sreport(1) Commandes Slurm sreport(1)

NOM

sreport - Générer des rapports à partir des données de comptabilité slurm.

SYNTAXE

sreport [OPTIONS...] [COMMANDE...]

DESCRIPTION

sreport est utilisé pour générer des rapports d'utilisation des tâches et d'utilisation du cluster pour les tâches Slurm enregistrées dans la base de données Slurm, slurmdbd. Les données du rapport proviennent des cumuls horaires, quotidiens et mensuels des données de comptabilité qui se produisent automatiquement en arrière-plan. Les données seront extraites de la table de cumul de l'intervalle le plus long qui peut satisfaire la période de rapport demandée. Par exemple, un rapport sur la plage de temps "Start=01/01 End=03/01" pourra extraire des données de la table de cumul mensuelle, tandis qu'un rapport avec "Start=01/01-03:00 End=03/01" nécessitera l'utilisation de la table de cumul horaire.

OPTIONS

-a, --all_clusters
Utiliser tous les clusters au lieu de seulement celui à partir duquel la commande a été exécutée.
-M, --cluster
Le(s) cluster(s) pour lequel/lesquels générer des rapports. Par défaut, le cluster local, sauf si le cluster local fait actuellement partie d'une fédération, auquel cas un rapport est généré pour tous les clusters de la fédération actuelle. Si les clusters inclus dans une fédération varient dans le temps, utilisez cette option pour identifier les clusters à inclure dans le rapport. Implique --local.
--federation
Générer un rapport pour la fédération si elle en fait partie.
-h, --help
Imprimer un message d'aide décrivant l'utilisation de sreport.
--local
Générer un rapport pour le cluster local, même s'il fait partie d'une fédération. Remplace --federation.
-n, --noheader
Ne pas afficher l'en-tête lors de la liste des résultats.
-p, --parsable
La sortie sera délimitée par des '|' avec un '|' à la fin.
-P, --parsable2
La sortie sera délimitée par des '|' sans '|' à la fin.
-Q, --quiet
N'imprimer aucun message d'avertissement ou d'information, seulement des messages d'erreur.
-t <format_temps>
Spécifier le format de temps de sortie. Les options de format de temps ne sont pas sensibles à la casse et peuvent être abrégées. Le format par défaut est Minutes. Les options de format de temps supportées sont listées dans la section de commande time ci-dessous.
-T, --tres=<noms_tres>
Ressource traçable (TRES) pour laquelle afficher les valeurs. Par défaut, l'utilisation de la ressource CPU est signalée (sauf pour les rapports de réservation. Tous les types de TRES réservés par une réservation seront affichés par défaut, sauf indication contraire avec cette option). Plusieurs noms de TRES peuvent être séparés par une liste séparée par des virgules pour tous les rapports sauf les rapports de tâches, qui ne peuvent supporter qu'un seul nom de TRES, ou "ALL" pour tous les TRES.

"Reported" Billing TRES est calculé à partir du plus grand Billing TRES de chaque nœud multiplié par la période de temps. Par exemple, si un nœud fait partie de plusieurs partitions et que chacune a des TRESBillingWeights définis différemment, le Billing TRES pour le nœud sera le plus élevé des partitions. Si TRESBillingWeights n'est pas défini sur une partition pour un nœud, alors le Billing TRES sera égal au nombre de CPUs sur le nœud.

L'utilisation des nœuds TRES n'est plus signalée en format pourcentage ou en Utilisation du Cluster. Veuillez utiliser TRES CPU à la place. Le problème principal avec l'utilisation des nœuds est que dans la plupart des configurations, plusieurs tâches peuvent s'exécuter sur le même nœud. Cela fait que la comptabilité des nœuds TRES compte le même nœud plusieurs fois pendant la même période. Dans les configurations de nœuds exclusifs, la comptabilité des CPUs renvoie la même utilisation que celle des nœuds.

-v, --verbose
Imprimer une journalisation détaillée des événements.
-V , --version
Imprimer les informations de version et quitter.

TYPES DE RAPPORTS

Les types de rapports valides sont :

cluster <RAPPORT> <OPTIONS>
job <RAPPORT> <OPTIONS>
reservation <RAPPORT> <OPTIONS>
user <RAPPORT> <OPTIONS>

<OPTIONS> pour chaque type incluent :

cluster
AccountUtilizationByUser, AccountUtilizationByQOS, UserUtilizationByAccount, UserUtilizationByWckey, Utilization, WCKeyUtilizationByUser
job
SizesByAccount, SizesByAccountAndWcKey, SizesByWckey
reservation
Utilization
user
TopUsage

NOTE : Si OverSubscribe est configuré sur FORCE ou YES dans votre slurm.conf et que le système n'est pas configuré pour utiliser la préemption (PreemptMode=OFF), la comptabilisation peut facilement dépasser l'utilisation réelle. Il peut être courant sur de tels systèmes de recevoir des messages d'erreur dans le journal slurmdbd indiquant : "Nous avons plus de temps alloué que possible."

DESCRIPTION DES RAPPORTS

cluster AccountUtilizationByUser
Ce rapport affichera l'utilisation des comptes telle qu'elle apparaît sur l'arbre hiérarchique. En partant du compte spécifié ou du compte racine par défaut, ce rapport listera l'utilisation sous-jacente avec une somme à chaque niveau. Utilisez l'option 'tree' pour parcourir l'arbre pour une meilleure visibilité.

NOTE : Le temps de réservation inactif sera réparti uniformément entre les comptes/utilisateurs qui y ont accès. Lorsqu'une réservation est attribuée à des comptes entiers, le temps sera compté dans l'association des comptes, et non dans les associations des utilisateurs dans les comptes. Dans ce cas, l'utilisation d'un compte parent peut être supérieure à la somme de ses enfants.

cluster AccountUtilizationByQOS
Ce rapport affichera l'utilisation des comptes telle qu'elle apparaît sur l'arbre hiérarchique. En partant du compte racine par défaut, ou du compte spécifié, ce rapport listera l'utilisation sous-jacente dans chaque compte, avec une somme à chaque niveau. Utilisez l'option 'tree' pour développer l'arbre pour une meilleure visibilité. Les utilisateurs ne sont pas affichés ici, uniquement les comptes parents.

NOTE : Le temps de réservation inactif sera réparti uniformément entre les comptes qui y ont accès. Comme aucun QOS n'est directement lié au temps inactif, le temps est compté contre le QOS par défaut du compte, ou 'normal' lorsqu'il n'y en a pas.

NOTE : Si vous ré-enroulez les données dans la base de données et que vous avez modifié le QOS par défaut d'une association pour qu'il soit autre chose que ce qu'il était au moment du premier enroulement, vous pouvez obtenir des données différentes.

cluster UserUtilizationByAccount
Ce rapport affichera les utilisateurs par compte, classés par ordre d'utilisation, sans regrouper plusieurs comptes par utilisateur, mais en les affichant sur des lignes distinctes.
cluster UserUtilizationByWCKey
Ce rapport affichera les utilisateurs par wckey, classés par ordre d'utilisation, sans regrouper plusieurs wckey par utilisateur, mais en les affichant sur des lignes distinctes.
cluster Utilization
Ce rapport affichera l'utilisation totale divisée entre le temps Alloué, Inactif, Planifié Inactif, Oisif et Planifié pour les clusters sélectionnés.

Référez-vous à la section suivante pour les descriptions de ces champs.

Note : Les réservations créées avec le drapeau IGNORE_JOBS ne sont pas suivies dans le rapport Cluster Utilization car autoriser des travaux en cours/actifs à continuer de s'exécuter dans la réservation introduit la possibilité qu'ils soient comptabilisés incorrectement. Les travaux dans ces réservations seront suivis normalement plutôt que d'être regroupés dans le temps de réservation, comme c'est le cas pour les réservations sans le drapeau IGNORE_JOBS.

Note : La vue par défaut pour le rapport "Cluster Utilization" inclut les champs suivants : Cluster, Allocated, Down, PlannedDown, Idle, Planned, Reported. Vous pouvez inclure des champs supplémentaires comme OverCommitted et les champs TresCount avec l'option Format. Le TresName sera également inclus si vous utilisez l'option -T, --tres <tres_names>.


cluster WCKeyUtilizationByUser
Ce rapport affichera l'utilisation des wckeys triée par nom de WCKey pour chaque utilisateur sur chaque cluster.
job SizesByAccount
Ce rapport affichera la quantité de temps utilisée pour les plages de jobs spécifiées par l'option 'grouping='. Un seul niveau de l'arbre est affiché, par défaut le répertoire racine. Si vous spécifiez d'autres comptes avec l'option 'account=', sreport utilisera ces comptes comme compte racine et vous recevrez les totaux agrégés de chaque compte listé plus leurs sous-comptes.
job SizesByAccountAndWckey
Ce rapport est très similaire à SizesByAccount, la différence étant que chaque compte est associé à des wckeys, de sorte que l'identifiant est compte:wckey au lieu de seulement compte, il y aura donc très probablement plusieurs comptes listés en fonction du nombre de wckeys utilisés.
job SizesByWckey
Ce rapport affichera le temps utilisé pour chaque wckey pour les plages de jobs spécifiées par l'option 'grouping='.
reservation Utilization
Ce rapport affichera l'utilisation totale des réservations sur les systèmes. Note : Les demandes de temps sur ce rapport ne tronqueront pas le temps utilisé par la réservation, mais uniquement les réservations qui ont fonctionné à un moment donné pendant la période demandée.
user TopUsage
Affiche les meilleurs utilisateurs d'un cluster, c'est-à-dire les utilisateurs ayant la plus grande utilisation. Par défaut, les utilisateurs sont triés par CPUTime, mais l'option -T, --tres triera les utilisateurs par le premier TRES spécifié.

Utilisez l'option group pour regrouper les comptes. Par défaut, il y a une ligne distincte pour chaque combinaison utilisateur/compte.

Chaque type de rapport a diverses options...

OPTIONS SPÉCIFIQUES AUX RAPPORTS DE CLUSTER

Comptes=<OPT>
Lorsqu'il est utilisé avec UserUtilizationByAccount, ou AccountUtilizationBy[User|QOS], Liste des comptes à inclure dans le rapport. Par défaut, tous.
Arbre
Lorsqu'il est utilisé avec le rapport AccountUtilizationBy[User|QOS], il couvre les comptes tels qu'ils sont dans la hiérarchie.

Lorsqu'il est utilisé avec tout rapport autre que Utilization, Liste des utilisateurs à inclure dans le rapport. Par défaut, tous.

Lorsqu'il est utilisé avec UserUtilizationByWckey ou WCKeyUtilizationByUser, Liste des wckeys à inclure dans le rapport. Par défaut, tous.

OPTIONS SPÉCIFIQUES AUX RAPPORTS DE TÂCHES

Comptes=<OPT>
Liste des comptes à utiliser pour le rapport. Par défaut, tous, ce qui affichera une seule ligne correspondant aux totaux de tous les comptes de la hiérarchie. Cette explication ne s'applique pas lorsqu'elle est exécutée avec les options FlatView ou AcctAsParent.
AcctAsParent
Lorsqu'il est utilisé avec SizesbyAccount(*), il prend les comptes spécifiés comme parents et la couche suivante de comptes sous ceux spécifiés sera affichée. Par défaut, root si aucun compte spécifique n'est demandé. Lorsque FlatView est utilisé, cette option est ignorée.
FlatView
Lorsqu'il est utilisé avec SizesbyAccount(*), il ne regroupe pas les comptes par niveau hiérarchique, mais imprime chaque compte où les tâches ont été exécutées sur une ligne séparée sans aucune hiérarchie.
GID=<OPT>
Liste des identifiants de groupe à inclure dans le rapport. Par défaut, tous.
Regroupement=<OPT>
Liste séparée par des virgules des regroupements de taille. (par exemple, 50,100,150 regrouperait le nombre d'UC de tâche 1-49, 50-99, 100-149, > 150). grouping=individual résultera en une seule colonne pour chaque taille de tâche trouvée.
Tâches=<OPT>
Liste des tâches/étapes à inclure dans le rapport. Par défaut, toutes.
Nœuds=<OPT>
N'afficher que les tâches exécutées sur ces nœuds. Par défaut, tous.
Partitions=<OPT>
Liste des partitions sur lesquelles les tâches ont été exécutées à inclure dans le rapport. Par défaut, toutes.
PrintJobCount
Lorsqu'il est utilisé avec le rapport Sizes, imprime le nombre de tâches exécutées au lieu du temps utilisé.
Utilisateurs=<OPT>
Liste des utilisateurs dont les tâches doivent être incluses dans le rapport. Par défaut, tous.
Wckeys=<OPT>
Liste des wckeys à utiliser pour le rapport. Par défaut, tous. Le rapport SizesbyWckey regroupe tous les utilisateurs. Si vous ne souhaitez que certains utilisateurs, spécifiez-les avec l'option Users=.

PERFORMANCE

Executing sreport sends a remote procedure call to slurmdbd. If enough calls from sreport or other Slurm client commands that send remote procedure calls to the slurmdbd daemon come in at once, it can result in a degradation of performance of the slurmdbd daemon, possibly resulting in a denial of service.

Do not run sreport or other Slurm client commands that send remote procedure calls to slurmdbd from loops in shell scripts or other programs. Ensure that programs limit calls to sreport to the minimum necessary for the information you are trying to gather.
