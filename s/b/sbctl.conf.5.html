NOM

sbctl.conf - fichier de configuration de sbctl

SYNTAXE

/etc/sbctl/sbctl.conf

DESCRIPTION

Le fichier de configuration de sbctl est un fichier YAML. Il est lu au démarrage s'il est présent.

Ce fichier peut être utilisé pour la configuration initiale d'une installation de sbctl.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

Le fichier de configuration est actuellement lu uniquement à partir de /etc/sbctl. Cela pourrait changer à l'avenir.

OPTIONS

keydir: /chemin/vers/répertoire/clés

Définit le répertoire où sbctl recherchera les clés.

Défaut : /var/lib/sbctl/keys

guid: /chemin/vers/fichier/guid

L'emplacement du fichier qui définit le GUID créé par l'utilisateur.

Le GUID est utilisé pour identifier de manière unique la liste des certificats stockés dans les variables EFI.

Défaut : /var/lib/sbctl/GUID

files_db: /chemin/vers/base_de_données_fichiers.json

L'emplacement du fichier JSON stockant les fichiers que sbctl signera.

Défaut : /var/lib/sbctl/files.json

bundles_db: /chemin/vers/base_de_données_paquets.json

L'emplacement du fichier JSON stockant les paquets que sbctl signera.

Défaut : /var/lib/sbctl/bundles.json

landlock: booléen

Active ou désactive l'isolation (sandboxing) de sbctl avec Landlock.

Défaut : true

db_additions: [ options... ] Inclut des clés ou des sommes de contrôle supplémentaires dans la base de données d'autorisation pour Secure Boot. Ces valeurs sont synonymes des drapeaux passés à sbctl enroll-keys. Valeurs valides : microsoft, tpm-eventlog, firmware-builtin, custom

files: [ [path: /chemin/vers/fichier output: /chemin/vers/sortie ], ... ]

Une liste de fichiers que sbctl signera lors de la configuration. Elle sera utilisée pour peupler la `files_db` lors de la configuration initiale.

path

Chemin absolu vers un fichier que sbctl doit signer.

output

Un chemin de sortie absolu optionnel pour le fichier signé.

keys: {pk: {...}, kek: {...}, db: {...}}

Une paire clé-valeur pour toutes les clés de la hiérarchie de clés utilisée pour Secure Boot. Elle est utilisée pour le bootstrap initial pendant la configuration.
•pk
•kek
•db
Chacune des hiérarchies peut spécifier le type et l'emplacement de la clé privée et du fichier de certificat indépendamment l'un de l'autre. Cela permet aux utilisateurs de conserver certaines clés sur différents supports de stockage en fonction de leurs besoins. Par exemple, conserver la clé db comme un fichier non chiffré facilement accessible pour la signature et la PK dans une enclave matérielle pour mieux sécuriser les clés.

privkey: /chemin/vers/fichier/clé_privée

Chemin vers la clé privée.

Défauts :

•pk: /var/lib/sbctl/keys/PK/PK.key
•kek: /var/lib/sbctl/keys/KEK/KEK.key
•db: /var/lib/sbctl/keys/db/db.key

pubkey: /chemin/vers/fichier/certificat

Chemin vers la clé publique.

Défaut :

•pk: /var/lib/sbctl/keys/PK/PK.pem
•kek: /var/lib/sbctl/keys/KEK/KEK.pem
•db: /var/lib/sbctl/keys/db/db.pem

type: fichier

Le type de clé utilisé pour cette clé de signature.

Seul le type de clé fichier est actuellement pris en charge par sbctl.

Défaut : file

EXEMPLE

Un exemple de fichier /etc/sbctl/sbctl.conf avec les valeurs par défaut.

---
keydir: /var/lib/sbctl/keys
guid: /var/lib/sbctl/GUID
files_db: /var/lib/sbctl/files.json
bundles_db: /var/lib/sbctl/bundles.json
landlock: true
db_additions:
- microsoft
files:
- path: /boot/vmlinuz-linux
  output: /boot/vmlinuz-linux
- path: /efi/EFI/Linux/arch-linux.efi
  output: /efi/EFI/Linux/arch-linux.efi
keys:
  pk:
    privkey: /var/lib/sbctl/keys/PK/PK.key
    pubkey: /var/lib/sbctl/keys/PK/PK.pem
    type: file
  kek:
    privkey: /var/lib/sbctl/keys/KEK/KEK.key
    pubkey: /var/lib/sbctl/keys/KEK/KEK.pem
    type: file
  db:
    privkey: /var/lib/sbctl/keys/db/db.key
    pubkey: /var/lib/sbctl/keys/db/db.pem
    type: file
