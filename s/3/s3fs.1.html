S3FS(1) Commandes utilisateur S3FS(1)

NOM

S3FS - système de fichiers basé sur FUSE, sauvegardé par Amazon S3

SYNTAXE

montage

s3fs bucket[:/path] point_de_montage [options]
s3fs point_de_montage [options (doit spécifier l'option bucket=)]

démontage

umount point_de_montage
Pour root.
fusermount -u point_de_montage
Pour un utilisateur non privilégié.

mode utilitaire (supprimer les objets en cours de téléchargement multipart)

s3fs --incomplete-mpu-list (-u) bucket
s3fs --incomplete-mpu-abort[=all | =<date d'expiration au format>] bucket

DESCRIPTION

s3fs est un système de fichiers FUSE qui permet de monter un compartiment Amazon S3 en tant que système de fichiers local. Il stocke les fichiers de manière native et transparente dans S3 (c'est-à-dire que vous pouvez utiliser d'autres programmes pour accéder aux mêmes fichiers).

AUTHENTIFICATION

s3fs prend en charge le fichier de credentials AWS standard (https://docs.aws.amazon.com/cli/latest/userguide/cli-config-files.html) stocké dans `${HOME}/.aws/credentials`. Alternativement, s3fs prend en charge un fichier de mots de passe personnalisé. Seul le format de fichier de credentials AWS peut être utilisé lorsque le jeton de session AWS est requis. Le fichier de mots de passe s3fs a le format suivant (utilisez ce format si vous n'avez qu'un seul jeu de credentials) :

accessKeyId:secretAccessKey

Si vous avez plus d'un jeu de credentials, cette syntaxe est également reconnue :

nom_du_bucket:accessKeyId:secretAccessKey

Les fichiers de mots de passe peuvent être stockés dans deux emplacements :


/etc/passwd-s3fs [0640]
$HOME/.passwd-s3fs [0600]

s3fs reconnaît également les variables d'environnement AWS_ACCESS_KEY_ID et AWS_SECRET_ACCESS_KEY.

OPTIONS

options générales

-h --help
affiche l'aide
  --version
affiche la version
-f
Option FUSE en premier plan - ne pas exécuter en démon.
-s
Option FUSE mono-thread (désactive l'opération multi-thread)

options de montage

Toutes les options s3fs doivent être données sous la forme où "opt" est :

<nom_option>=<valeur_option>
-o bucket
s'il n'est pas spécifié le nom du bucket (et le chemin) dans la ligne de commande, cette option doit être spécifiée après l'option -o pour le nom du bucket.
-o default_acl (défaut="private")
l'ACL prédéfinie par défaut à appliquer à tous les objets S3 écrits, par exemple, "private", "public-read". Voir https://docs.aws.amazon.com/AmazonS3/latest/dev/acl-overview.html#canned-acl pour la liste complète des ACL prédéfinies.
-o retries (défaut="5")
nombre de tentatives pour une transaction S3 échouée.
-o tmpdir (défaut="/tmp")
dossier local pour les fichiers temporaires.
-o use_cache (défaut="" ce qui signifie désactivé)
dossier local à utiliser pour le cache de fichiers local.
-o check_cache_dir_exist (désactivé par défaut)
Si use_cache est défini, vérifie si le répertoire de cache existe. Si cette option n'est pas spécifiée, il sera créé à l'exécution lorsque le répertoire de cache n'existe pas.
-o del_cache - supprimer le cache de fichiers local
supprime le cache de fichiers local au démarrage et à la sortie de s3fs.
-o storage_class (défaut="standard")
stocke l'objet avec la classe de stockage spécifiée. Valeurs possibles : standard, standard_ia, onezone_ia, reduced_redundancy, intelligent_tiering, glacier, glacier_ir, et deep_archive.
-o use_rrs (désactivé par défaut)
utilise le Stockage à Redondance Réduite (RRS) d'Amazon. cette option ne peut pas être spécifiée avec use_sse. (peut spécifier use_rrs=1 pour l'ancienne version) cette option a été remplacée par la nouvelle option storage_class.
-o use_sse (désactivé par défaut)
Spécifie trois types de chiffrement côté serveur Amazon : SSE-S3, SSE-C ou SSE-KMS. SSE-S3 utilise des clés de chiffrement gérées par Amazon S3, SSE-C utilise des clés de chiffrement fournies par le client, et SSE-KMS utilise la clé maître que vous gérez dans AWS KMS. Vous pouvez spécifier "use_sse" ou "use_sse=1" pour activer le type SSE-S3 (use_sse=1 est l'ancien paramètre de type ). En cas de configuration SSE-C, vous pouvez spécifier "use_sse=custom", "use_sse=custom:<chemin du fichier de clé personnalisée>" ou "use_sse=<chemin du fichier de clé personnalisée>" (seul <chemin du fichier de clé personnalisée> spécifié est l'ancien paramètre de type). Vous pouvez utiliser "c" pour "custom" (abrégé). Le fichier de clé personnalisée doit avoir la permission 600. Le fichier peut contenir plusieurs lignes, chaque ligne étant une clé SSE-C. La première ligne du fichier est utilisée comme clés de chiffrement fournies par le client pour le téléchargement et la modification des en-têtes, etc. S'il y a des clés après la première ligne, celles-ci sont utilisées pour télécharger des objets qui sont chiffrés par une clé autre que la première. Ainsi, vous pouvez conserver toutes les clés SSE-C dans le fichier, ce qui constitue l'historique des clés SSE-C. Si vous spécifiez "custom" ("c") sans chemin de fichier, vous devez définir la clé personnalisée via l'option load_sse_c ou la variable d'environnement AWSSSECKEYS (la variable d'environnement AWSSSECKEYS contient plusieurs clés SSE-C séparées par ":"). Pour configurer SSE-KMS, spécifiez "use_sse=kmsid" ou "use_sse=kmsid:<id kms>". Vous pouvez utiliser "k" pour "kmsid" (abrégé). Si vous spécifiez SSE-KMS avec votre <kms id> dans AWS KMS, vous pouvez le définir après "kmsid:" (ou "k:"). Si vous spécifiez uniquement "kmsid" ("k"), vous devez définir la variable d'environnement AWSSSEKMSID dont la valeur est <kms id>. Vous devez faire attention au fait que vous ne pouvez pas utiliser un ID KMS qui n'est pas dans la même région EC2. De plus, si vous spécifiez SSE-KMS, vos points de terminaison doivent utiliser Secure Sockets Layer (SSL) ou Transport Layer Security (TLS).
-o load_sse_c - spécifier les clés SSE-C
Spécifie le chemin du fichier de clés de chiffrement personnalisées pour le déchiffrement lors du téléchargement. Si vous utilisez la clé de chiffrement personnalisée lors du téléchargement, vous le spécifiez avec "use_sse=custom". Le fichier contient plusieurs lignes, une ligne signifiant une clé personnalisée. Ainsi, vous pouvez conserver toutes les clés SSE-C dans le fichier, ce qui constitue l'historique des clés SSE-C. La variable d'environnement AWSSSECKEYS a le même contenu que ce fichier.
-o passwd_file (défaut="")
spécifie le chemin du fichier de mots de passe, qui prend la priorité sur le mot de passe dans $HOME/.passwd-s3fs et /etc/passwd-s3fs
-o ahbe_conf (défaut="" ce qui signifie désactivé)
Cette option spécifie le chemin du fichier de configuration qui est le fichier

e en-tête HTTP supplémentaire par extension de fichier (objet).
Le format du fichier de configuration est le suivant :
-----------
ligne = [suffixe de fichier ou regex] En-tête-HTTP [Valeurs-HTTP]
suffixe de fichier = suffixe de fichier (objet), si ce champ est vide, il signifie "reg:(.*)" (= tous les objets).
regex = expression régulière pour faire correspondre le chemin du fichier (objet). ce type commence par le préfixe "reg:".
En-tête-HTTP = nom de l'en-tête HTTP supplémentaire
Valeurs-HTTP = valeur de l'en-tête HTTP supplémentaire
-----------
Exemple :
-----------
.gz Content-Encoding gzip
.Z Content-Encoding compress
reg:^/MONREPERTOIRE/(.*)[.]t2$ Content-Encoding text2
-----------
Un exemple de fichier de configuration est téléchargé dans le répertoire "test". Si vous spécifiez cette option pour définir l'en-tête HTTP "Content-Encoding", veuillez faire attention à la RFC 2616.
-o profil (défaut="default")
Choisissez un profil de ${HOME}/.aws/credentials pour vous authentifier auprès de S3. Notez que ce format correspond au format de l'AWS CLI et diffère du format de mot de passe de s3fs.
-o bucket_public (défaut="" ce qui signifie désactivé)
montez anonymement un bucket public en le définissant sur 1, ignore les fichiers $HOME/.passwd-s3fs et /etc/passwd-s3fs. S3 n'autorise pas l'API de copie d'objets pour les utilisateurs anonymes, s3fs définit donc automatiquement l'option nocopyapi lorsque l'option public_bucket=1 est spécifiée.
-o connect_timeout (défaut="300" secondes)
temps d'attente pour la connexion avant d'abandonner.
-o readwrite_timeout (défaut="120" secondes)
temps d'attente entre l'activité de lecture/écriture avant d'abandonner.
-o list_object_max_keys (défaut="1000")
spécifiez le nombre maximum de clés retournées par l'API de liste d'objets S3. La valeur par défaut est 1000. Vous pouvez définir cette valeur à 1000 ou plus.
-o max_stat_cache_size (défaut="100 000" entrées (environ 40 Mo))
nombre maximum d'entrées dans le cache stat et le cache de liens symboliques.
-o stat_cache_expire (défaut est 900)
spécifiez le temps d'expiration (secondes) pour les entrées du cache stat et du cache de liens symboliques. Ce temps d'expiration indique le temps depuis la mise en cache.
-o stat_cache_interval_expire (défaut est 900)
spécifiez le temps d'expiration (secondes) pour les entrées du cache stat et du cache de liens symboliques. Ce temps d'expiration est basé sur le temps depuis la dernière heure d'accès de ce cache. Cette option est exclusive avec stat_cache_expire, et est laissée pour la compatibilité avec les versions antérieures.
-o disable_noobj_cache (défaut est activé)
Par défaut, s3fs mémorise quand un objet n'existe pas jusqu'au temps d'expiration du cache stat. Cette mise en cache peut entraîner des données obsolètes pour les applications. Si désactivé, s3fs ne mémorisera pas les objets et peut entraîner des requêtes HeadObject supplémentaires et réduire les performances.
-o no_check_certificate (par défaut, cette option est désactivée)
le certificat du serveur ne sera pas vérifié par rapport aux autorités de certification disponibles.
-o ssl_verify_hostname (défaut="2")
Lorsque 0, ne pas vérifier le certificat SSL par rapport au nom d'hôte.
-o ssl_client_cert (défaut="")
Spécifiez un certificat client SSL. Spécifiez ce paramètre optionnel dans le format suivant :
"<Certificat SSL>[:<Type de certificat>[:<Clé privée>[:<Type de clé>
[:<Mot de passe>]]]]"
<Certificat SSL> : Certificat client.
Spécifiez le chemin du fichier ou le NickName (pour NSS, etc.).
<Type de certificat> : Type de certificat, le défaut est "PEM" (facultatif).
<Clé privée> : Fichier de clé privée du certificat (facultatif).
<Type de clé> : Type de clé privée, le défaut est "PEM" (facultatif).
<Mot de passe> : Phrase secrète de la clé privée (facultatif). Il est également possible d'omettre cette valeur et de la spécifier via la variable d'environnement "S3FS_SSL_PRIVKEY_PASSWORD".
-o nodnscache - désactiver le cache DNS.
s3fs utilise toujours le cache DNS, cette option désactive le cache DNS.
-o nosscache - désactiver le cache de sessions SSL.
s3fs utilise toujours le cache de sessions SSL, cette option désactive le cache de sessions SSL.
-o multireq_max (défaut="20")
nombre maximum de requêtes parallèles pour lister les objets.
-o parallel_count (défaut="5")
nombre de requêtes parallèles pour le téléchargement de gros objets. s3fs télécharge les grands objets (plus de 25 Mo par défaut) par requête de publication multipartite, et envoie des requêtes parallèles. Cette option limite le nombre de requêtes parallèles que s3fs envoie à la fois. Il est nécessaire de définir cette valeur en fonction du CPU et de la bande passante réseau.
-o multipart_size (défaut="10")
taille de la partie, en Mo, pour chaque requête multipartite. La valeur minimale est de 5 Mo et la valeur maximale est de 5 Go.
-o multipart_copy_size (défaut="512")
taille de la partie, en Mo, pour chaque requête de copie multipartite, utilisée pour les renommages et le mixupload. La valeur minimale est de 5 Mo et la valeur maximale est de 5 Go. Doit être au moins 512 Mo pour copier un objet de 5 To au maximum, mais des valeurs plus basses peuvent améliorer les performances.
-o max_dirty_data (défaut="5120")
Vider les données sales vers S3 après un certain nombre de Mo écrits. La valeur minimale est de 50 Mo. La valeur -1 signifie désactivé. Ne peut pas être utilisé avec nomixupload.
-o bucket_size (défaut=valeur entière non signée maximale)
La taille du bucket avec laquelle les éléments correspondants de la structure statvfs seront remplis. L'argument de l'option est un entier suivi facultativement d'un suffixe multiplicateur (GB, GiB, TB, TiB, PB, PiB, EB, EiB) (sans espaces entre les deux). Si aucun suffixe n'est fourni, les octets sont supposés ; par exemple : 20000000, 30GB, 45TiB. Notez que s3fs ne calcule pas la taille réelle du volume (trop coûteux) : par défaut, il supposera la taille maximale possible ; cependant, comme cela peut confondre d'autres logiciels utilisant s3fs, la taille de bucket annoncée peut être définie avec cette option.
-o ensure_diskfree (défaut 0)
définit en Mo l'espace disque libre à garantir. Cette option signifie le seuil d'espace libre sur le disque qui est utilisé pour le fichier cache par s3fs. s3fs crée des fichiers pour le téléchargement, le téléversement et la mise en cache des fichiers. Si l'espace disque libre est inférieur à cette valeur, s3fs n'utilisera pas l'espace disque autant que possible en échange de performances.
-o free_space_ratio (défaut="10")
définit le ratio d'espace libre minimum du disque. La valeur de cette option peut être entre 0 et 100. Elle contrôlera la taille du cache selon ce ratio pour garantir que le ratio d'inactivité du disque est supérieur à cette valeur. Par exemple, lorsque l'espace disque est de 50 Go, la valeur par défaut garantira que le disque réservera au moins 50 Go * 10 % = 5 Go d'espace restant.
-o multipart_threshold (défaut="25")
seuil, en Mo, pour utiliser le téléchargement multipartite au lieu du téléchargement en une seule partie. Doit être au moins 5 Mo.
-o singlepart_copy_limit (défaut="512")
taille maximale, en Mo, d'une copie en une seule partie avant d'essayer une copie multipartite.
-o host (défaut="https://s3.amazonaws.com")
Définir un hôte non Amazon, par exemple https://example.com.
-o servicepath (défaut="/")
Définir un chemin de service lorsque l'hôte non Amazon nécessite un préfixe.
-o url (défaut="https://s3.amazonaws.com")
définit l'URL à utiliser pour accéder à Amazon S3. Si vous souhaitez utiliser HTTP, vous pouvez définir "url=http://s3.amazonaws.com". Si vous n'utilisez pas https, veuillez spécifier l'URL avec l'option url.
-o endpoint (défaut="us-east-1")
définit le point d'accès à utiliser pour la signature version 4. Si cette option n'est pas spécifiée, s3fs utilise la région "us-east-1" par défaut. Si s3fs ne parvient pas à se connecter à la région spécifiée par cette option, s3fs ne pourra pas s'exécuter. Mais si vous ne spécifiez pas cette option et que vous ne parvenez pas à vous connecter à la région par défaut, s3fs tentera automatiquement de se connecter à une autre région. Ainsi, s3fs peut connaître le nom correct de la région, car s3fs le trouvera dans une erreur du serveur S3.
-o sigv2 (défaut est signature version 4 avec repli vers la version 2)
définit la signature des requêtes AWS en utilisant uniquement la signature version 2.
-o sigv4 (défaut est signature version 4 avec repli vers la version 2)
définit la signature des requêtes AWS en utilisant uniquement la signature version 4.
-o mp_umask (défaut est "0000")
définit l'umask pour le répertoire du point de montage. Si l'option allow_other n'est pas définie, s3fs n'autorise l'accès au point de montage qu'au propriétaire. Dans le cas contraire, s3fs autorise l'accès à tous les utilisateurs par défaut. Mais si vous définissez allow_other avec cette option, vous pouvez contrôler les permissions du point de montage par cette option comme une umask.
-o umask (défaut est "0000")
définit l'umask pour les fichiers sous le point de montage. Cela peut autoriser les utilisateurs autres que l'utilisateur qui monte à lire et écrire des fichiers qu'ils n'ont pas créés.
-o nomultipart - désactiver les téléchargements multipartites
-o streamupload (défaut est désactivé)
Activer le téléchargement en flux. Si cette option est activée, un téléchargement séquentiel sera être effectué en parallèle avec l'écriture de la partie qui a été écrite lors d'un téléchargement multipart. Ceci devrait offrir de meilleures performances que d'autres fonctions de téléchargement. Notez que cette option est toujours expérimentale et peut changer à l'avenir.
-o nombre_max_threads (par défaut "5")
Spécifie le nombre de threads en attente pour les téléchargements en flux. Notez que cette option et le téléchargement en flux sont toujours expérimentaux et sujets à modification à l'avenir. Cette option sera fusionnée avec "nombre_parallèle" à l'avenir.
-o activer_content_md5 (par défaut désactivé)
Permet au serveur S3 de vérifier l'intégrité des données des téléchargements via l'en-tête Content-MD5. Cela peut entraîner une surcharge de CPU sur les transferts.
-o activer_charge_utile_non_signée (par défaut désactivé)
Ne calcule pas Content-SHA256 pour les charges utiles de PutObject et UploadPart. Cela peut réduire la surcharge de CPU pour les transferts.
-o ecs (par défaut désactivé)
Cette option indique à s3fs d'interroger l'adresse des métadonnées des identifiants de conteneur ECS au lieu de l'adresse des métadonnées de l'instance.
-o role_iam (par défaut aucun rôle IAM)
Cette option nécessite le nom du rôle IAM ou "auto". Si vous spécifiez "auto", s3fs utilisera automatiquement les noms de rôles IAM qui sont définis pour une instance. Si vous spécifiez cette option sans argument, cela équivaut à spécifier "auto".
-o imdsv1only (par défaut utiliser IMDSv2 avec retour à v1)
Le service de métadonnées d'instance AWS, utilisé avec l'authentification par rôle IAM, prend en charge l'utilisation d'un jeton d'API. Si vous utilisez un rôle IAM dans un environnement qui ne prend pas en charge IMDSv2, la définition de ce drapeau ignorera la récupération et l'utilisation du jeton d'API lors de la récupération des identifiants IAM.
-o authentification_ibm_iam (par défaut ne pas utiliser l'authentification IBM IAM)
Cette option indique à s3fs d'utiliser l'authentification IBM IAM. Dans ce mode, AWSAccessKey et AWSSecretKey seront utilisés respectivement comme Service-Instance-ID et APIKey d'IBM.
-o endpoint_ibm_iam (par défaut https://iam.cloud.ibm.com)
Définit l'URL à utiliser pour l'authentification IBM IAM.
-o biblio_identifiants (par défaut=
Spécifie la bibliothèque partagée qui gère les identifiants contenant le jeton d'authentification. Si cette option est spécifiée, le traitement des identifiants et des jetons fourni par la bibliothèque partagée sera effectué au lieu du traitement des identifiants intégré. Cette option ne peut pas être spécifiée avec les options passwd_file, profile, use_session_token, ecs, ibm_iam_auth, ibm_iam_endpoint, imdsv1only et iam_role.
-o options_biblio_identifiants (par défaut=
Spécifie les options à passer lorsque la bibliothèque partagée spécifiée dans biblio_identifiants est chargée puis initialisée. Pour la chaîne spécifiée dans cette option, spécifiez la chaîne définie par la bibliothèque partagée.
-o utiliser_attributs_étendus (par défaut ne pas gérer les attributs étendus)
Permet de gérer les attributs étendus (xattrs). Si vous définissez cette option, vous pouvez utiliser les attributs étendus. Par exemple, encfs et ecryptfs ont besoin de prendre en charge les attributs étendus. Remarque : si s3fs gère les attributs étendus, s3fs ne pourra pas fonctionner avec la commande copy avec preserve=mode.
-o nomxmlns - désactiver l'enregistrement de l'espace de noms xml.
Désactive l'enregistrement de l'espace de noms XML pour la réponse de ListBucketResult et ListVersionsResult, etc. L'espace de noms par défaut est recherché dans "http://s3.amazonaws.com/doc/2006-03-01". Cette option ne devrait pas être spécifiée maintenant, car s3fs recherche automatiquement xmlns après la v1.66.
-o nomixupload - désactiver la copie dans les téléchargements multipart.
Désactive l'utilisation de PUT (API de copie) lors du téléchargement multipart d'objets de grande taille. Par défaut, lors du téléchargement multipart, la plage de données inchangées utilisera PUT (API de copie) chaque fois que possible. Lorsque nocopyapi ou norenameapi est spécifié, l'utilisation de PUT (API de copie) est invalidée même si cette option n'est pas spécifiée.
-o nocopyapi - pour une autre compatibilité incomplète du stockage objet.
Pour un stockage objet distribué compatible avec l'API S3 sans l'API PUT (copie). Si vous définissez cette option, s3fs n'utilisera pas PUT avec "x-amz-copy-source" (API de copie). Comme le trafic sera multiplié par 2-3 fois par cette option, nous la déconseillons.
-o norenameapi - pour une autre compatibilité incomplète du stockage objet.
Pour un stockage objet distribué compatible avec l'API S3 sans l'API PUT (copie). Cette option est un sous-ensemble de l'option nocopyapi. L'option nocopyapi n'utilise pas l'API de copie pour toutes les commandes (par ex. chmod, chown, touch, mv, etc.), mais cette option n'utilise pas l'API de copie uniquement pour la commande de renommage (par ex. mv). Si cette option est spécifiée avec nocopyapi, alors s3fs l'ignore.
-o utiliser_style_requete_chemin (utilisation du style d'appel API hérité)
Active la compatibilité avec les API de type S3 qui ne prennent pas en charge le style de requête virtuel-hôte, en utilisant l'ancien style de requête par chemin.
-o listobjectsv2 (utilisation de ListObjectsV2)
Émet ListObjectsV2 au lieu de ListObjects, utile sur les stockages objets sans prise en charge de ListObjects.
-o noua (supprimer l'en-tête User-Agent)
Habituellement, s3fs affiche le User-Agent au format "s3fs/<version> (hash de commit <hash>; <nom de la bibliothèque SSL utilisée>)". Si cette option est spécifiée, s3fs supprime l'affichage du User-Agent.
-o suites_de_chiffrements
Personnalise la liste des suites de chiffrement TLS. Attend une liste de noms de suites de chiffrement séparés par des deux-points. Une liste des suites de chiffrement disponibles, en fonction de votre moteur TLS, peut être trouvée dans la documentation de la bibliothèque CURL : https://curl.haxx.se/docs/ssl-ciphers.html
-o nom_instance
Le nom de l'instance du point de montage s3fs actuel. Ce nom sera ajouté aux messages de journalisation et aux en-têtes d'agent utilisateur envoyés par s3fs.
-o complement_stat (complémenter le mode de fichier/répertoire manquant)
s3fs complète les informations manquantes sur le mode de fichier/répertoire si un objet fichier ou répertoire n'a pas d'en-tête x-amz-meta-mode. Par défaut, s3fs ne complète pas les informations stat pour un objet, et l'objet ne pourra alors pas être listé/modifié.
-o compat_dir (activer la prise en charge des noms de répertoires alternatifs)
s3fs prend en charge par défaut deux schémas de nommage différents : "dir/" et "dir" pour mapper les noms de répertoires vers les objets S3 et vice versa. Comme troisième variante, les répertoires peuvent être déterminés indirectement s'il existe un objet fichier avec un chemin (par exemple, "/dir/file") mais sans le répertoire parent. Cette option active une quatrième variante, "dir_$folder$", créée par d'anciennes applications.
S3fs utilise uniquement le premier schéma "dir/" pour créer des objets S3 pour les répertoires.
La prise en charge de ces différents schémas de nommage entraîne un effort de communication accru.
Si vous n'avez pas les permissions d'accès au compartiment et que vous spécifiez un chemin de répertoire créé par un client autre que s3fs pour le point de montage, vous ne pourrez pas démarrer car le répertoire du point de montage ne pourra pas être trouvé par s3fs. Mais en spécifiant cette option, vous pouvez éviter cette erreur.
-o utiliser_wtf8 - prise en charge de l'encodage arbitraire du système de fichiers.
S3 exige que tous les noms d'objets soient en UTF-8 valide. Mais certains clients, notamment les clients NFS Windows, utilisent leur propre encodage. Cette option ré-encode les noms d'objets UTF-8 invalides en UTF-8 valide en mappant les codes déviants dans une "page de codes privée" de l'ensemble Unicode. Utile sur les clients n'utilisant pas UTF-8 comme leur encodage de système de fichiers.
-o utiliser_jeton_session - indiquer que le jeton de session doit être fourni.
Si les identifiants sont fournis par des variables d'environnement, ce commutateur force la vérification de la présence de la variable AWS_SESSION_TOKEN. Sinon, une erreur est retournée.
-o requete_payante (par défaut désactivé)
Cette option indique à s3fs d'activer les requêtes impliquant des compartiments Requester Pays (Elle inclut l'entrée 'x-amz-request-payer=requester' dans l'en-tête de la requête).
-o mime (par défaut "/etc/mime.types")
Spécifie le chemin du fichier mime.types. Si cette option n'est pas spécifiée, l'existence de "/etc/mime.types" est vérifiée, et ce fichier est chargé comme informations mime. Si ce fichier n'existe pas sur macOS, alors "/etc/apache2/mime.types" est également vérifié.
-o proxy (par défaut="")
Cette option spécifie un proxy vers le serveur S3. Spécifiez le proxy au format '[<scheme://]hostname(fqdn)[:<port>]'. De plus, le ':<port>' peut également être omis. S'il est omis, le port 443 est utilisé pour le schéma HTTPS, et le port 1080 est utilisé sinon. Cette option est identique à l'option '--proxy(-x)' de la commande curl et au drapeau 'CURLOPT_PROXY' de libcurl. Cette option est équivalente et prévaut sur les variables d'environnement 'http_proxy', 'all_proxy', etc.
-o fichier_identifiants_proxy (par défaut="")
Cette option spécifie le fichier qui décrit le nom d'utilisateur et le mot de passe pour l'authentification du proxy lorsque le proxy de schéma HTTP est spécifié par l'option 'proxy'. Le nom d'utilisateur et le mot de passe ne sont valides que pour le schéma HTTP. Si le proxy HTTP ne nécessite pas d'authentification, cette option n'est pas requise. Séparez le nom d'utilisateur et le mot de passe par un caractère ':' et spécifiez chacun sous forme de chaîne encodée en URL.
-o ipresolve (par défaut="quelconque")
Sélectionne le type d'adresses IP à utiliser lors de l'établissement d'une connexion

OPTIONS

-o addr_policy
Default('whatever') peut utiliser les adresses de toutes les versions IP (IPv4 et IPv6) que votre système autorise. Si vous spécifiez 'IPv4', seules les adresses IPv4 sont utilisées. Et lorsque 'IPv6' est spécifié, seules les adresses IPv6 seront utilisées.
-o logfile - spécifier le fichier de sortie du journal.
s3fs sort le fichier journal vers syslog. Alternativement, si s3fs est démarré avec l'option "-f" spécifiée, le journal sera affiché sur la sortie standard/erreur standard. Vous pouvez utiliser cette option pour spécifier le fichier journal que s3fs sort. Si vous spécifiez un fichier journal avec cette option, il rouvrira le fichier journal lorsque s3fs recevra un signal SIGHUP. Vous pouvez utiliser le signal SIGHUP pour la rotation des journaux.
-o dbglevel (défaut="crit")
Définit le niveau des messages de débogage. Définissez la valeur comme crit (critique), err (erreur), warn (avertissement), info (information) pour le niveau de débogage. Le niveau de débogage par défaut est critique. Si s3fs s'exécute avec l'option "-d", le niveau de débogage est défini sur information. Lorsque s3fs intercepte le signal SIGUSR2, le niveau de débogage est augmenté.
-o curldbg - afficher le message de débogage de curl
Affiche le message de débogage de libcurl lorsque cette option est spécifiée. Spécifiez "normal" ou "body" pour le paramètre. Si le paramètre est omis, c'est la même chose que "normal". Si "body" est spécifié, certaines données du corps de la communication API seront affichées en plus du message de débogage affiché en mode "normal".
-o no_time_stamp_msg - pas d'horodatage dans le message de débogage
L'horodatage est affiché dans le message de débogage par défaut. Si cette option est spécifiée, l'horodatage ne sera pas affiché dans le message de débogage. Il en va de même même si la variable d'environnement "S3FS_MSGTIMESTAMP" est définie sur "no".
-o set_check_cache_sigusr1 (défaut est stdout)
Si le cache est activé, vous pouvez vérifier l'intégrité du fichier cache et le fichier d'informations sur les statistiques du fichier cache. Cette option est spécifiée et lors de l'envoi du signal SIGUSR1 au processus s3fs, l'état du cache est vérifié à ce moment-là. Cette option peut prendre un chemin de fichier comme paramètre pour afficher le résultat de la vérification dans ce fichier. Le paramètre de chemin de fichier peut être omis. S'il est omis, le résultat sera affiché sur stdout ou syslog.
-o update_parent_dir_stat (défaut est désactivé)
La mtime et la ctime du répertoire parent sont mises à jour lorsqu'un fichier ou un répertoire est créé ou supprimé (lorsque l'inode du répertoire parent est mis à jour). Par défaut, les statistiques du répertoire parent ne sont pas mises à jour.

-u ou --incomplete-mpu-list
Liste les objets multi-parties incomplets téléchargés dans le compartiment spécifié.
--incomplete-mpu-abort tous ou format de date (défaut="24H")
Supprime l'objet multi-parties incomplet téléchargé dans le compartiment spécifié. Si "all" est spécifié pour cette option, tous les objets multi-parties incomplets seront supprimés. OPTIONS FUSE/MONTAGE

La plupart des options de montage génériques décrites dans 'man mount' sont prises en charge (ro, rw, suid, nosuid, dev, nodev, exec, noexec, atime, noatime, sync, async, dirsync). Les systèmes de fichiers sont montés avec '-onodev,nosuid' par défaut, ce qui ne peut être remplacé que par un utilisateur privilégié.
Il existe de nombreuses options de montage spécifiques à FUSE qui peuvent être spécifiées. Par exemple, allow_other. Voir le README de FUSE pour la liste complète.

URL DU SERVEUR/STYLE DE REQUÊTE

Soyez prudent lorsque vous spécifiez le point d'extrémité du serveur (URL).

Si le nom de votre compartiment contient des points ("."), vous devriez utiliser le style de requête de chemin (en utilisant l'option "use_path_request_style").
De plus, si vous utilisez un serveur autre qu'Amazon S3, vous devez spécifier le point d'extrémité avec l'option "url". À ce moment-là, en fonction du serveur que vous utilisez, vous devrez peut-être spécifier le style de requête de chemin (option "use_path_request_style").

CONSOMMATION DE STOCKAGE LOCAL

s3fs nécessite un cache local pour fonctionner. Vous pouvez activer un cache local avec "-o use_cache" ou s3fs utilise des fichiers temporaires pour mettre en cache les requêtes en attente vers s3.
En dehors des exigences discutées ci-dessous, il est recommandé de conserver suffisamment de cache, respectivement de stockage temporaire, pour permettre une copie de tous les fichiers ouverts en lecture et en écriture à tout moment.

Cache local avec "-o use_cache"

s3fs maintient automatiquement un cache local de fichiers. Le dossier de cache est spécifié par le paramètre de "-o use_cache". Il ne s'agit que d'un cache local qui peut être supprimé à tout moment. s3fs le reconstruit si nécessaire.
Chaque fois que s3fs doit lire ou écrire un fichier sur S3, il crée d'abord le fichier dans le répertoire de cache et opère dessus.
La quantité de stockage de cache local utilisée peut être indirectement contrôlée avec "-o ensure_diskfree".

Sans cache local

Comme s3fs nécessite toujours un certain espace de stockage pour fonctionner, il crée des fichiers temporaires pour stocker les requêtes d'écriture entrantes jusqu'à ce que la taille requise de la requête s3 soit atteinte et que le segment ait été téléchargé. Après cela, ces données sont tronquées dans le fichier temporaire pour libérer de l'espace de stockage.
Par fichier, vous avez besoin d'au moins deux fois la taille de la partie (par défaut 5 Mo ou "-o multipart_size") pour écrire des requêtes multi-parties ou de l'espace pour le fichier entier si les requêtes uniques sont activées ("-o nomultipart").

CONSIDÉRATIONS DE PERFORMANCE

Cette section aborde les réglages pour améliorer les performances de s3fs.
Dans la plupart des cas, les performances du backend ne peuvent pas être contrôlées et ne font donc pas partie de cette discussion.
Les détails de l'utilisation du stockage local sont discutés dans "CONSOMMATION DE STOCKAGE LOCAL".

Consommation de CPU et de mémoire

s3fs est une application multi-threadée. Selon la charge de travail, il peut utiliser plusieurs CPU et une certaine quantité de mémoire. Vous pouvez surveiller la consommation de CPU et de mémoire avec l'utilitaire "top".

Performance des requêtes S3

s3fs fournit plusieurs options (par exemple, "-o multipart_size", "-o parallel_count") pour contrôler le comportement et donc indirectement les performances. Les combinaisons possibles de ces options conjointement avec les différents backends S3 sont si variées qu'il n'y a pas de recommandation individuelle autre que les valeurs par défaut. Des réglages individuels améliorés peuvent être trouvés en testant et en mesurant.
Les deux options "Activer le cache des objets inexistants" ("-o enable_noobj_cache") et "Désactiver la prise en charge des noms de répertoire alternatifs" ("-o notsup_compat_dir") peuvent être utilisées pour contrôler l'accès partagé au même compartiment par différentes applications :
•
Activer le cache des objets inexistants ("-o enable_noobj_cache")
Si un compartiment est utilisé exclusivement par une instance s3fs, vous pouvez activer le cache pour les fichiers et répertoires inexistants avec "-o enable_noobj_cache". Cela élimine les requêtes répétées pour vérifier l'existence d'un objet, économisant ainsi du temps et potentiellement de l'argent.
•
Activer la prise en charge des noms de répertoire alternatifs ("-o compat_dir")
s3fs reconnaît les objets "dir/" comme des répertoires. Les clients autres que s3fs peuvent utiliser les objets "dir", "dir_$folder$" comme répertoires, ou les objets de répertoire peuvent ne pas exister. Pour que s3fs les reconnaisse comme des répertoires, vous pouvez spécifier l'option "compat_dir".
•
Compléter les informations sur les fichiers et répertoires ("-o complement_stat")
s3fs utilise l'en-tête "x-amz-meta-mode" pour déterminer si un objet est un fichier ou un répertoire. Pour cette raison, les objets qui n'ont pas l'en-tête "x-amz-meta-mode" peuvent ne pas produire les résultats attendus (Le répertoire peut

PERFORMANCE CONSIDERATIONS

s3fs does not retrieve the mtime, size, or mode of objects in S3. This is because S3 does not store this information natively. So s3fs has to calculate this information. This is done by performing additional S3 API calls to retrieve this information. By default, s3fs will attempt to make additional S3 API calls to populate this information. However, the S3 API calls can take a long time, especially when the number of objects is large (e.g. hundreds of thousands of objects). In some cases, this can lead to performance issues (e.g. slow listing of directories, large stat times, etc.). By specifying the "complement_stat" option, s3fs can automatically complete this missing attribute information, and you can get the expected results.

NOTES

La taille maximale des objets que s3fs peut gérer dépend d'Amazon S3. Par exemple, jusqu'à 5 Go lors de l'utilisation de l'API PUT unique. Et jusqu'à 5 To est pris en charge lors de l'utilisation de l'API Multipart Upload.
s3fs utilise /etc/mime.types pour "deviner" le "bon" type de contenu en fonction de l'extension du nom de fichier. Cela signifie que vous pouvez copier un site web sur S3 et le servir directement depuis S3 avec les bons types de contenu !

BOGUES

En raison des limitations de "cohérence éventuelle" de S3, la création de fichiers peut échouer occasionnellement. Même après une création réussie, les lectures ultérieures peuvent échouer pendant un temps indéterminé, même après une ou plusieurs lectures réussies. Créez et lisez suffisamment de fichiers et vous rencontrerez éventuellement cet échec. Ce n'est pas une faille dans s3fs et ce n'est pas quelque chose qu'un wrapper FUSE comme s3fs peut contourner. L'option retries ne résout pas ce problème. Votre application doit soit tolérer, soit compenser ces échecs, par exemple en réessayant les créations ou les lectures.
