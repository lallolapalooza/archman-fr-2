s390_sthyi(2) Manuel des appels système s390_sthyi(2)

NOM

s390_sthyi - émuler l'instruction STHYI

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <asm/sthyi.h>        /* Définition des constantes STHYI_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_s390_sthyi, unsigned long function_code,
            void *resp_buffer, uint64_t *return_code,
            unsigned long flags);

Note : glibc ne fournit pas d'enveloppe pour s390_sthyi(), ce qui rend nécessaire l'utilisation de syscall(2).

DESCRIPTION

L'appel système s390_sthyi() émule l'instruction STHYI (Store Hypervisor Information). Il fournit des informations sur les ressources matérielles de la machine et de ses niveaux de virtualisation. Cela inclut le type et la capacité des processeurs, ainsi que le modèle de la machine et d'autres métriques.

L'argument function_code indique quelle fonction exécuter. Le(s) code(s) suivant(s) sont pris en charge :

STHYI_FC_CP_IFL_CAP
Retourne les informations de capacité des processeurs centraux (CP) et des unités intégrées pour Linux (IFL).

L'argument resp_buffer spécifie l'adresse d'un tampon de réponse. Lorsque le function_code est STHYI_FC_CP_IFL_CAP, le tampon doit être de la taille d'une page (4 Ko). Si l'appel système retourne 0, le tampon de réponse sera rempli avec les informations de capacité du processeur. Sinon, le contenu du tampon de réponse reste inchangé.

L'argument return_code stocke le code de retour de l'instruction STHYI, en utilisant l'une des valeurs suivantes :

0
Succès.
4
Code de fonction non pris en charge.

Pour plus de détails sur return_code, function_code et resp_buffer, voir la référence dans NOTES.

L'argument flags est fourni pour permettre des extensions futures et doit actuellement être défini à 0.

VALEUR RENVOYÉE

En cas de succès (c'est-à-dire : émulation réussie), la valeur de retour de s390_sthyi() correspond au code de condition des instructions STHYI, qui est une valeur comprise entre [0..3]. Une valeur de retour de 0 indique que les informations de capacité du processeur sont stockées dans *resp_buffer. Une valeur de retour de 3 indique un « code de fonction non pris en charge » et le contenu de *resp_buffer reste inchangé. Les valeurs de retour 1 et 2 sont réservées.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
La valeur spécifiée dans resp_buffer ou return_code n'est pas une adresse valide.
EINVAL
La valeur spécifiée dans flags est différente de zéro.
ENOMEM
L'allocation mémoire pour la gestion des informations de capacité du processeur a échoué.
EOPNOTSUPP
La valeur spécifiée dans function_code n'est pas valide.

NORMES

Linux sur s390.

HISTORIQUE

Linux 4.15.

NOTES

Pour les détails de l'instruction STHYI, voir la page de documentation.

Lorsque l'interface d'appel système est utilisée, le tampon de réponse ne doit pas satisfaire aux exigences d'alignement décrites dans la définition de l'instruction STHYI.

Le noyau met en cache la réponse (pendant une seconde au maximum, depuis Linux 4.16). Les invocations ultérieures de l'appel système peuvent retourner la réponse mise en cache.
