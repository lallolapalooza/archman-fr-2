s390_guarded_storage(2) Manuel des appels système s390_guarded_storage(2)

NOM

s390_guarded_storage - opérations avec la facilité de stockage protégé z/Architecture

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <asm/guarded_storage.h> /* Définition des constantes GS_* */
#include <sys/syscall.h>         /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_s390_guarded_storage, int command,
            struct gs_cb *gs_cb);

Note : glibc ne fournit pas d'enveloppe pour s390_guarded_storage(), rendant nécessaire l'utilisation de syscall(2).

DESCRIPTION

L'appel système s390_guarded_storage() permet d'utiliser la facilité de stockage protégé (une fonctionnalité spécifique à z/Architecture) pour les processus en espace utilisateur.

La facilité de stockage protégé est une fonctionnalité matérielle qui permet de marquer jusqu'à 64 régions de mémoire (à partir de z14) comme protégées ; la lecture d'un pointeur avec les nouvelles instructions « Load Guarded » (LGG) ou « Load Logical and Shift Guarded » (LLGFSG) provoquera une vérification de plage sur la valeur chargée et invoquera un gestionnaire en espace utilisateur (préalablement configuré) si l'une des régions protégées est affectée.

L'argument command indique quelle fonction effectuer. Les commandes suivantes sont prises en charge :

GS_ENABLE
Active la facilité de stockage protégé pour la tâche appelante. Le contenu initial du bloc de contrôle de stockage protégé sera tout zéro. Après l'activation, le code en espace utilisateur peut utiliser l'instruction « Load Guarded Storage Controls » (LGSC) (ou l'enveloppe de fonction load_gs_cb() fournie dans l'en-tête asm/guarded_storage.h) pour charger un bloc de contrôle arbitraire. Tant qu'une tâche est activée, le noyau sauvegardera et restaurera le contenu des registres de stockage protégé lors des changements de contexte.
GS_DISABLE
Désactive l'utilisation de la facilité de stockage protégé pour la tâche appelante. Le noyau cessera de sauvegarder et restaurer le contenu des registres de stockage protégé ; le contenu spécifique à la tâche de ces registres sera perdu.
GS_SET_BC_CB
Définit un bloc de contrôle de stockage protégé de diffusion à celui fourni dans l'argument gs_cb. Ceci est appelé par thread et associe un bloc de contrôle de stockage protégé spécifique à la tâche appelante. Ce bloc de contrôle sera utilisé dans la commande de diffusion GS_BROADCAST.
GS_CLEAR_BC_CB
Efface le bloc de contrôle de stockage protégé de diffusion. Le bloc de contrôle de stockage protégé n'aura plus l'association établie par la commande GS_SET_BC_CB.
GS_BROADCAST
Envoie une diffusion à tous les frères et sœurs de la tâche appelante. Chaque frère qui a établi un bloc de contrôle de stockage protégé de diffusion chargera ce bloc de contrôle et sera activé pour le stockage protégé. Le bloc de contrôle de stockage protégé de diffusion est consommé ; une deuxième diffusion sans rafraîchissement du bloc de contrôle stocké avec GS_SET_BC_CB n'aura aucun effet.

L'argument gs_cb spécifie l'adresse d'une structure de bloc de contrôle de stockage protégé et est actuellement utilisé uniquement par la commande GS_SET_BC_CB ; toutes les autres commandes susmentionnées ignorent cet argument.

VALEUR DE RETOUR

En cas de succès, la valeur de retour de s390_guarded_storage() est 0.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
command était GS_SET_BC_CB et la copie de la structure de bloc de contrôle de stockage protégé pointée par l'argument gs_cb a échoué.
EINVAL
La valeur fournie dans l'argument command n'était pas valide.
ENOMEM
command était l'une des valeurs GS_ENABLE ou GS_SET_BC_CB, et l'allocation d'un nouveau bloc de contrôle de stockage protégé a échoué.
EOPNOTSUPP
La facilité de stockage protégé n'est pas prise en charge par le matériel.

NORMES

Linux sur s390.

HISTORIQUE

Linux 4.12. System z14.

NOTES

La description de la facilité de stockage protégé ainsi que les instructions associées et les dispositions des structures du bloc de contrôle de stockage protégé et de la liste des paramètres d'événement de stockage protégé sont disponibles dans « z/Architecture Principles of Operations » à partir de la douzième édition.

La structure gs_cb a un champ gsepla (Guarded Storage Event Parameter List Address), qui est un pointeur d'espace utilisateur vers une structure Guarded Storage Event Parameter List (qui contient l'adresse du gestionnaire d'événements mentionné ci-dessus dans le champ gseha), et sa disposition est disponible sous forme de définition de type de structure gs_epl dans l'en-tête asm/guarded_storage.h.
