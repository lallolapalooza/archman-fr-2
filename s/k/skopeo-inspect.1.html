NOM

skopeo-inspect - Récupérer des informations de bas niveau sur nom-image dans un registre.

SYNTAXE

skopeo inspect [options] nom-image

DESCRIPTION

Récupérer des informations de bas niveau sur nom-image dans un registre. Voir skopeo(1) pour le format de nom-image.

La sortie par défaut inclut des données provenant de diverses sources : entrée utilisateur (Name), dépôt distant, s'il y en a (RepoTags), le manifeste de haut niveau (Digest), et une image par architecture/OS correspondant à l'environnement d'exécution actuel (la plupart des autres valeurs). Pour voir les valeurs d'une architecture/OS différente, utilisez les options --override-os / --override-arch documentées dans skopeo(1).

OPTIONS

Voir aussi skopeo(1) pour les options placées avant le nom de la sous-commande.

--authfile chemin

Chemin du fichier principal des identifiants de registre. Sur Linux, le défaut est ${XDG_RUNTIME_DIR}/containers/auth.json. Voir containers-auth.json(5) pour plus de détails sur le mécanisme de recherche des identifiants et les défauts sur d'autres plateformes.

Utilisez skopeo login pour gérer les identifiants.

La valeur par défaut de cette option est lue à partir de la variable d'environnement REGISTRY\_AUTH\_FILE.

--cert-dir chemin

Utiliser les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre.

--config

Afficher la configuration au format OCI, le défaut est le format JSON.

--creds nomutilisateur[:motdepasse]

Nom d'utilisateur et mot de passe pour accéder au registre.

--daemon-host hote

Utiliser l'hôte du démon Docker à hote (transport docker-daemon: seulement)

--format, -f=format

Formater la sortie en utilisant le modèle Go donné. Les clés du JSON retourné peuvent être utilisées comme valeurs pour l'option --format (voir les exemples ci-dessous). Prend en charge les fonctions de modélisation Go disponibles sur https://pkg.go.dev/github.com/containers/common/pkg/report#hdr-Template_Functions

--help, -h

Afficher le message d'utilisation

--no-creds

Accéder au registre de manière anonyme.

--raw

Afficher le manifeste brut ou les données de configuration selon l'option --config. L'option --format n'est pas prise en charge avec l'option --raw.

--registry-token Jeton d'authentification

Jeton de registre pour accéder au registre.

--retry-times

Le nombre de tentatives.

--retry-delay

Délai fixe entre les tentatives. S'il n'est pas défini (ou défini à 0s), le temps d'attente des tentatives sera augmenté de manière exponentielle en fonction du nombre d'échecs.

--shared-blob-dir répertoire

Répertoire à utiliser pour partager des blobs entre dépôts OCI.

--tls-verify=bool

Exiger HTTPS et vérifier les certificats lors de la connexion au registre de conteneurs ou au démon. Par défaut, utilise le paramètre de registry.conf.

--username

Le nom d'utilisateur pour accéder au registre.

--password

Le mot de passe pour accéder au registre.

--no-tags, -n

Ne pas lister les étiquettes disponibles du dépôt dans la sortie. Lorsque vrai, le tableau RepoTags sera vide. Par défaut, faux, qui inclut toutes les étiquettes disponibles.

    skopeo-inspect(1)

    DESCRIPTION

    skopeo-inspect vous permet d'inspecter l'image d'un registre.

    OPTIONS

    skopeo-inspect accepte les options communes suivantes :

    --help, -h : Afficher le message d'aide et quitter.

    --version : Afficher les informations sur la version et quitter.

    skopeo-inspect prend les arguments suivants :

    REGISTRY/IMAGE : L'image à inspecter. Elle peut être fournie sous la forme d'un chemin d'image au format REGISTRY[:PORT]/REPOSITORY[:TAG|@DIGEST].

    L'option --raw peut être ajoutée pour obtenir la sortie brute de l'API du registre.

    EXAMPLES

    Inspecter une image :

    $ skopeo inspect docker://registry.fedoraproject.org/fedora:latest
{
    "Name": "registry.fedoraproject.org/fedora",
    "Tag": "latest",
    "Digest": "sha256:f38a35248f087490c836b9931e602797415d5677069a56997903111b11b33757",
    "Created": "2023-11-14T12:00:00Z",
    "Architecture": "amd64",
    "Os": "linux",
    "Layers": [
        "sha256:b14b2c1c8a5c062204664513f2021d60011985f34411531b863a04d814174e98",
        "sha256:e71449f6f29607c4f819196f3a55138e07c79a8230b40d31b86418e5f239f4b6"
    ]
}
