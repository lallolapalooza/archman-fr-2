skopeo-copy(1)() skopeo-copy(1)()

NOM

skopeo-copy - Copie une image (manifeste, couches de système de fichiers, signatures) d'un emplacement à un autre.

SYNTAXE

skopeo copy [options] image-source image-destination

DESCRIPTION

Copie une image (manifeste, couches de système de fichiers, signatures) d'un emplacement à un autre.

Utilise la politique de confiance du système pour valider les images, rejette les images non approuvées par la politique.

image-source utilise le format de "nom d'image" décrit ci-dessus

image-destination utilise le format de "nom d'image" décrit ci-dessus

image-source et image-destination sont interprétés de manière complètement indépendante ; par exemple, le nom de destination n'hérite pas automatiquement de certaines parties du nom source.

OPTIONS

Voir aussi skopeo(1) pour les options placées avant le nom de la sous-commande.

--additional-tag=chaînes

Tags supplémentaires (prend en charge docker-archive).

--all, -a

Si image-source fait référence à une liste d'images, au lieu de copier uniquement l'image qui correspond au système d'exploitation et à l'architecture actuels (sous réserve de l'utilisation des options globales --override-os, --override-arch et --override-variant), tente de copier toutes les images de la liste, ainsi que la liste elle-même.

--authfile chemin

Chemin du fichier d'informations d'identification principal du registre. Sous Linux, la valeur par défaut est ${XDG_RUNTIME_DIR}/containers/auth.json. Voir containers-auth.json(5) pour plus de détails sur le mécanisme de recherche des informations d'identification et les valeurs par défaut sur d'autres plateformes.

Utilisez skopeo login pour gérer les informations d'identification.

La valeur par défaut de cette option est lue à partir de la variable d'environnement REGISTRY\_AUTH\_FILE.

--src-authfile chemin

Chemin du fichier d'informations d'identification principal pour le registre source. Utilise le chemin donné par --authfile s'il n'est pas fourni.

--dest-authfile chemin

Chemin du fichier d'informations d'identification principal pour le registre de destination. Utilise le chemin donné par --authfile s'il n'est pas fourni.

--dest-shared-blob-dir répertoire

Répertoire à utiliser pour partager les blobs entre les dépôts OCI.

--digestfile chemin

Après avoir copié l'image, écrit le digest de l'image résultante dans le fichier.

--preserve-digests

Préserve les digests pendant la copie. Échoue si le digest ne peut pas être préservé.

Cette option ne modifie pas ce qui sera copié ; envisagez d'utiliser --all en même temps.

--encrypt-layer entiers

Expérimental les indices de couches indexés sur 0, avec la prise en charge des index négatifs (par exemple, 0 est la première couche, -1 est la dernière couche)

--format, -f type-manifeste

TYPE DE MANIFESTE (oci, v2s1, ou v2s2) à utiliser dans la destination (par défaut, le type de manifeste de la source, avec des solutions de repli)

--help, -h

Affiche l'énoncé d'utilisation

--multi-arch option

Contrôle ce qui est copié si image-source fait référence à une image multi-architecture. Par défaut, c'est 'system'.

Options : - system : Copie uniquement l'image qui correspond à l'architecture du système - all : Copie l'image multi-architecture complète - index-only : Copie uniquement l'index

L'option 'index-only' échoue généralement sauf si les images par architecture référencées sont déjà présentes dans la destination, ou si le registre cible prend en charge les index épars.

--quiet, -q

Supprime les informations de sortie lors de la copie des images.

--remove-signatures

Ne copie pas les signatures, le cas échéant, de image-source. Nécessaire lors de la copie d'une image signée vers une destination qui ne prend pas en charge les signatures.

--sign-by id-clé

Ajoute une signature de « signature simple » utilisant cet id de clé pour un nom d'image correspondant à image-destination

--sign-by-sigstore fichier-param

Ajoute une signature sigstore basée sur les options du fichier de paramètres de signature sigstore de conteneurs spécifié, fichier-param. Voir containers-sigstore-signing-params.yaml(5) pour les détails sur le format du fichier.

--sign-by-sigstore-private-key chemin

Ajoute une signature sigstore à l'aide d'une clé privée à l'emplacement chemin pour un nom d'image correspondant à image-destination

--sign-by-sq-fingerprint empreinte

Ajoute une signature de « signature simple » utilisant une clé Sequoia-PGP avec l'empreinte spécifiée.

--sign-passphrase-file chemin

La phrase de passe à utiliser lors de la signature avec --sign-by, --sign-by-sigstore-private-key ou --sign-by-sq-fingerprint. Seule la première ligne sera lue. Une phrase de passe stockée dans un fichier est d'une sécurité discutable si d'autres utilisateurs peuvent lire ce fichier. N'utilisez pas cette option si cela peut être évité.

--sign-identity référence

L'identité à utiliser lors de la signature de l'image. L'identité doit être une référence docker entièrement spécifiée. Si l'identité n'est pas spécifiée, la référence docker cible sera utilisée.

--src-shared-blob-dir répertoire

Répertoire à utiliser pour partager les blobs entre les dépôts OCI.

--encryption-key protocole:fichier-clé

Spécifie le protocole de chiffrement, qui peut être JWE (RFC7516), PGP (RFC4880) et PKCS7 (RFC2315) ainsi que le matériel clé requis pour le chiffrement de l'image. Par exemple, jwe:/chemin/vers/key.pem ou pgp:admin@example.com ou pkcs7:/chemin/vers/fichier-x509.

--decryption-key clé[:phrase-passe]

Clé à utiliser pour le déchiffrement des images. La clé peut pointer vers des clés et/ou des certificats. Le déchiffrement sera essayé avec toutes les clés. Si la clé est protégée par une phrase de passe, elle doit être passée dans l'argument et omise sinon.

--src-creds nom-utilisateur[:mot-de-passe]

Informations d'identification pour accéder au registre source.

--dest-compress

Compresse les couches d'image au format tar lors de l'enregistrement dans un répertoire à l'aide du transport 'dir'. (par défaut, le même type de compression que la source).

--dest-decompress

Décompresse les couches d'image au format tar lors de l'enregistrement dans un répertoire à l'aide du transport 'dir'. (par défaut, le même type de compression que la source).

--dest-oci-accept-uncompressed-layers

Autorise les couches d'image non compressées lors de l'enregistrement dans une image OCI à l'aide du transport 'oci'. (par défaut, compression de ce qui n'est pas compressé).

--dest-creds nom-utilisateur[:mot-de-passe]

Informations d'identification pour accéder au registre de destination.

--src-cert-dir chemin

Utilise les certificats de l'emplacement chemin (*.crt, *.cert, *.key) pour se connecter au registre source ou au démon.

--src-no-creds

Accède au registre anonymement.

--src-tls-verify=booléen

Exige HTTPS et vérifie les certificats lors de la communication avec le registre source ou le démon de conteneur. Par défaut, utilise le paramètre du registre source.

--dest-cert-dir chemin

Utilise les certificats de l'emplacement chemin (*.crt, *.cert, *.key) pour se connecter au registre de destination ou au démon.

--dest-no-creds

Accède au registre anonymement.

--dest-tls-verify=booléen

Exige HTTPS et vérifie les certificats lors de la communication avec le registre de destination ou le démon de conteneur. Par défaut, utilise le paramètre du registre de destination.

--src-daemon-host hôte

Copie depuis le démon docker sur hôte. Si hôte commence par tcp://, HTTPS est activé par défaut. Pour utiliser HTTP simple, utilisez la forme http:// (par défaut unix:///var/run/docker.sock).

--dest-daemon-host hôte

Copie vers le démon docker sur hôte. Si hôte commence par tcp://, HTTPS est activé par défaut. Pour utiliser HTTP simple, utilisez la forme http:// (par défaut unix:///var/run/docker.sock).

Les signatures existantes, le cas échéant, sont également préservées.

--dest-compress-format format

Spécifie le format de compression à utiliser. Les valeurs prises en charge sont : gzip, zstd et zstd:chunked. zstd:chunked est incompatible avec le chiffrement des images et sera traité comme zstd avec un avertissement dans

skopeo-copy(1) — skopeo

NAME

skopeo-copy 8 — copy files between image registries, storage, or local directories

SYNOPSIS

skopeo copy [options] source destination

DESCRIPTION

Copies an image or file from a source to a destination. The allowed transports are:

• docker

• docker-archive

• oci

• oci-archive

• dir

• atomic

• containers-storage

This command can copy images between any two transports.

OPTIONS

The following options are available:

--all
Copy all tags and versions of the specified image.
--authfile path
Use a file in specified path to get authentication details. The file is in the same format as /var/lib/containers/auth.json.
--cert-dir directory
Directory containing TLS certificates for insecure registries.
--creds username:password
Use credentials for accessing the source and/or destination registry.
--daemon-host socket-path
Use specified docker daemon socket instead of the default.
--decryption-key key

Decrypt an encrypted image. The key can be a path to a file containing the private key or a string representing the key. This option can be specified multiple times for images that require more than one key.

The supported formats for the key are:

jwe:path-to-file
The key is a JWE encrypted key. The file can contain the key in PEM format.
pkcs11:uri
The key is a PKCS#11 token URI.
secret-string:key
The key is a secret string.
--dest-compress-format format
Specifies the compression format to use for the destination. Supported values are: zstd, gzip, compress, none. The default is to use the same compression format as the source, or zstd if the source compression cannot be determined.
--dest-compress-level format
Specifies the compression level to use. The value is specific to the compression algorithm used, e.g. for zstd the accepted values are in the range 1-20 (inclusive), while for gzip it is 1-9 (inclusive).
--dest-force-compress-format
Ensures that the compression algorithm set in --dest-compress-format is used exclusively.
--src-registry-token token
Bearer token for accessing the source registry.
--dest-registry-token token
Bearer token for accessing the destination registry.
--dest-precompute-digests
Precompute digests to ensure layers are not uploaded that already exist on the destination registry. Layers with initially unknown digests (ex. compressing "on the fly") will be temporarily streamed to disk.
--retry-times
The number of times to retry.
--retry-delay
Fixed delay between retries. If not set (or set to 0s), retry wait time will be exponentially increased based on the number of failed attempts.
--src-username
The username to access the source registry.
--src-password
The password to access the source registry.
--dest-username
The username to access the destination registry.
--dest-password
The password to access the destination registry.
--image-parallel-copies n
Maximum number of image layers to be copied (pulled/pushed) simultaneously. Not setting this field will fall back to containers/image defaults.
--sign-by identity
Sign the image using the specified identity. The identity must be known to `skopeo-sign(1)`. This option can be specified multiple times.
--encrypt-layer n
Encrypt only the specified layer. The layer index is 0-based, and can be negative (e.g. -1 for the last layer).

EXAMPLES

To just copy an image from one registry to another:

$ skopeo copy docker://quay.io/skopeo/stable:latest docker://registry.example.com/skopeo:latest

To copy the layers of the docker.io busybox image to a local directory:

$ mkdir -p /var/lib/images/busybox
$ skopeo copy docker://busybox:latest dir:/var/lib/images/busybox
$ ls /var/lib/images/busybox/*
  /tmp/busybox/2b8fd9751c4c0f5dd266fcae00707e67a2545ef34f9a29354585f93dac906749.tar
  /tmp/busybox/manifest.json
  /tmp/busybox/8ddc19f16526912237dd8af81971d5e4dd0587907234be2b83e249518d5b673f.tar

To create an archive consumable by docker load (but note that using a registry is almost always more efficient):

$ skopeo copy docker://busybox:latest docker-archive:archive-file.tar:busybox:latest

To copy and sign an image:

$ skopeo copy --sign-by dev@example.com containers-storage:example/busybox:streaming docker://example/busybox:gold

To encrypt an image:

$ skopeo copy docker://docker.io/library/nginx:1.17.8 oci:local_nginx:1.17.8
$ openssl genrsa -out private.key 1024
$ openssl rsa -in private.key -pubout > public.key
$ skopeo copy --encryption-key jwe:./public.key oci:local_nginx:1.17.8 oci:try-encrypt:encrypted

To decrypt an image:

$ skopeo copy --decryption-key ./private.key oci:try-encrypt:encrypted oci:try-decrypt:decrypted

To copy encrypted image without decryption:

$ skopeo copy oci:try-encrypt:encrypted oci:try-encrypt-copy:encrypted

To decrypt an image that requires more than one key:

$ skopeo copy --decryption-key ./private1.key --decryption-key ./private2.key --decryption-key ./private3.key oci:try-encrypt:encrypted oci:try-decrypt:decrypted

Container images can also be partially encrypted by specifying the index of the layer. Layers are 0-indexed indices, with support for negative indexing. i.e. 0 is the first layer, -1 is the last layer.

Let's say out of 3 layers that the image docker.io/library/nginx:1.17.8 is made up of, we only want to encrypt the 2nd layer,

$ skopeo copy --encryption-key jwe:./public.key --encrypt-layer 1 oci:local_nginx:1.17.8 oci:try-encrypt:encrypted
