NOM

skopeo-sync - Synchronise les images entre les dépôts de registres et les répertoires locaux.

SYNTAXE

skopeo sync [options] --src transport --dest transport source destination

DESCRIPTION

Synchronise les images entre les dépôts de registres et les répertoires locaux. La synchronisation est réalisée en copiant toutes les images trouvées dans source vers destination - utile pour synchroniser un miroir de registre de conteneurs local ou pour peupler des registres exécutés dans des environnements déconnectés.

Contrairement aux autres commandes skopeo, skopeo sync nécessite que les transports source et destination soient spécifiés séparément de source et destination. L'un des problèmes du préfixage d'une destination par son transport est que le registre docker://hostname:port serait interprété à tort comme une référence d'image dans un registre non entièrement qualifié, avec hostname et port comme nom et étiquette de l'image.

Transports source disponibles :
- docker (c.-à-d. --src docker) : source est un dépôt hébergé sur un registre de conteneurs (par exemple : registry.example.com/busybox).
Si aucune étiquette d'image n'est spécifiée, skopeo sync copie toutes les étiquettes trouvées dans ce dépôt.
- dir (c.-à-d. --src dir) : source est un chemin de répertoire local (par exemple : /media/usb/). Référez-vous à skopeo(1) dir:chemin pour le format d'image local.
- yaml (c.-à-d. --src yaml) : source est un chemin de fichier YAML local.
Le fichier YAML doit spécifier la liste des images copiées à partir de différents registres de conteneurs (les répertoires locaux ne sont pas pris en charge). Référez-vous à la section EXEMPLES pour le format de fichier.

Transports destination disponibles :
- docker (c.-à-d. --dest docker) : destination est un registre de conteneurs (par exemple : my-registry.local.lan).
- dir (c.-à-d. --dest dir) : destination est un chemin de répertoire local (par exemple : /media/usb/).
Un répertoire par 'image:étiquette' source est créé pour chaque image copiée.

Lorsque l'option --scoped est spécifiée, les images sont préfixées par le chemin de l'image source afin que plusieurs images portant le même nom puissent être stockées dans la destination.

OPTIONS

Voir aussi skopeo(1) pour les options placées avant le nom de la sous-commande.

--all, -a Si l'une des images dans src fait référence à une liste d'images, au lieu de copier uniquement l'image qui correspond au système d'exploitation et à l'architecture actuels (sous réserve de l'utilisation des options globales --override-os, --override-arch et --override-variant), tentez de copier toutes les images de la liste, ainsi que la liste elle-même.

--authfile chemin

Chemin du fichier d'identification principal du registre. Sous Linux, le chemin par défaut est ${XDG_RUNTIME_DIR}/containers/auth.json. Voir containers-auth.json(5) pour plus de détails sur le mécanisme de recherche des identifiants et les valeurs par défaut sur d'autres plateformes.

Utilisez skopeo login pour gérer les identifiants.

La valeur par défaut de cette option est lue à partir de la variable d'environnement REGISTRY\_AUTH\_FILE.

--src-authfile chemin

Chemin du fichier d'identification principal du registre pour le registre source. Utilise le chemin donné par --authfile, s'il n'est pas fourni.

--dest-authfile chemin

Chemin du fichier d'identification principal du registre pour le registre destination. Utilise le chemin donné par --authfile, s'il n'est pas fourni.

--dry-run

Exécute la synchronisation sans copier réellement les données vers la destination.

--src, -s transport Transport pour le dépôt source.

--dest, -d transport Transport de destination.

--format, -f type-manifeste Type de manifeste (oci, v2s1, ou v2s2) à utiliser lors de la synchronisation d'une ou plusieurs images vers une destination (la valeur par défaut est le type de manifeste source, avec des replis).

--help, -h

Affiche le message d'utilisation.

--scoped Prépare les images avec le chemin de l'image source, afin que plusieurs images portant le même nom puissent être stockées dans la destination.

--append-suffix suffixe-etiquette Chaîne à ajouter aux étiquettes de destination.

--digestfile chemin

Après avoir copié les images depuis la source, écrit le digest des images résultantes ainsi que la Référence d'Image.

sha256:bf91f90823248017a4f920fb541727fa8368dc6cf377a7debbd271cf6a31c8a7 docker://myhost.com/alpine:edge
sha256:31603596830fc7e56753139f9c2c6bd3759e48a850659506ebfb885d1cf3aef5 docker://myhost.com/postgres:14.3

--preserve-digests

Préserve les digests lors de la copie. Échoue si le digest ne peut pas être préservé.

Cette option ne modifie pas ce qui sera copié ; envisagez d'utiliser --all en même temps.

--remove-signatures Ne copie pas les signatures, le cas échéant, depuis source-image. Ceci est nécessaire lors de la copie d'une image signée vers une destination qui ne prend pas en charge les signatures.

--sign-by id-clé

Ajoute une signature de « signature simple » utilisant cet id de clé pour un nom d'image correspondant à destination-image

--sign-by-sigstore fichier-param

Ajoute une signature sigstore basée sur les options du fichier de paramètres de signature sigstore de conteneurs spécifié, fichier-param. Voir containers-sigstore-signing-params.yaml(5) pour les détails sur le format du fichier.

--sign-by-sigstore-private-key chemin

Ajoute une signature sigstore en utilisant une clé privée à chemin pour un nom d'image correspondant à destination-image

--sign-by-sq-fingerprint empreinte

Ajoute une signature de « signature simple » en utilisant une clé Sequoia-PGP avec l'empreinte spécifiée.

--sign-passphrase-file chemin

La phrase secrète à utiliser lors de la signature avec --sign-by, --sign-by-sigstore-private-key ou --sign-by-sq-fingerprint. Seule la première ligne sera lue. Une phrase secrète stockée dans un fichier est d'une sécurité discutable si d'autres utilisateurs peuvent lire ce fichier. N'utilisez pas cette option si elle peut être évitée.

--src-creds nomutilisateur[:motdepasse] pour accéder au registre source.

--dest-creds nomutilisateur[:motdepasse] pour accéder au registre destination.

--src-cert-dir chemin Utilise les certificats (*.crt, *.cert, *.key) situés dans chemin pour se connecter au registre ou au démon source.

--src-no-creds Accède au registre anonymement.

--src-tls-verify=bool Exige HTTPS et vérifie les certificats lors de la communication avec un registre ou démon conteneur source. La valeur par défaut est déterminée par l'entrée du registre dans le fichier registry.conf.

--dest-cert-dir chemin Utilise les certificats (*.crt, *.cert, *.key) situés dans chemin pour se connecter au registre ou au démon destination.

--dest-no-creds Accède au registre anonymement.

--dest-tls-verify=bool Exige HTTPS et vérifie les certificats lors de la communication avec un registre ou démon conteneur destination. La valeur par défaut est déterminée par l'entrée du registre dans le fichier registry.conf.

--src-registry-token Jeton d'authentification (Bearer token) pour accéder au registre source.

--dest-registry-token Jeton d'authentification (Bearer token) pour accéder au registre destination.

--retry-times

Le nombre de tentatives.

--retry-delay

Délai fixe entre les tentatives. S'il n'est pas défini (ou défini à 0s), le temps d'attente des tentatives augmentera de manière exponentielle en fonction du nombre d'échecs.

--keep-going Si des erreurs surviennent lors de la copie des images, ces erreurs sont enregistrées et le processus continue de synchroniser le reste des images, pour finalement échouer à la fin.

--src-username

Le nom d'utilisateur pour accéder au registre source.

--src-password

Le mot de passe pour accéder au registre source.

--dest-username

Le nom d'utilisateur pour accéder au registre destination.

--dest-password

Le mot de passe pour accéder au registre destination.

EXEMPLES

Synchronisation vers un répertoire local

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers le répertoire local '/mnt/alpine-images'
$ skopeo sync --src docker --dest dir docker.io/library/alpine /mnt/alpine-images

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers le répertoire local '/mnt/alpine-images',
# en créant un sous-répertoire par étiquette d'image et en préfixant chaque image avec le nom du dépôt.
$ skopeo sync --src docker --dest dir --scoped docker.io/library/alpine /mnt/alpine-images

# Synchroniser une image spécifique depuis un dépôt vers un répertoire local.
$ skopeo sync --src docker --dest dir docker.io/library/alpine:3.15 /mnt/alpine-images/3.15

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un répertoire local.
$ skopeo sync --src yaml --dest dir images.yaml /mnt/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un répertoire local,
# sans copier les signatures.
$ skopeo sync --src yaml --dest dir --remove-signatures images.yaml /mnt/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un répertoire local,
# en utilisant des identifiants pour accéder aux registres source et destination.
$ skopeo sync --src yaml --dest dir --src-creds user:pass --dest-creds admin:secret images.yaml /mnt/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un répertoire local,
# et enregistrer les digests des images copiées dans le fichier 'digests.txt'.
$ skopeo sync --src yaml --dest dir --digestfile digests.txt images.yaml /mnt/images

Synchronisation vers un registre local

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers le dépôt 'my-registry.local.lan/alpine'
$ skopeo sync --src docker --dest docker docker.io/library/alpine my-registry.local.lan/alpine

# Synchroniser toutes les images du répertoire local '/mnt/alpine-images' vers le dépôt 'my-registry.local.lan/alpine'
$ skopeo sync --src dir --dest docker /mnt/alpine-images my-registry.local.lan/alpine

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un dépôt distant.
$ skopeo sync --src yaml --dest docker --src-authfile /home/user/.docker/config.json --dest-authfile /home/admin/.docker/config.json images.yaml my-registry.local.lan/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un dépôt distant,
# en utilisant un suffixe pour les étiquettes de destination.
$ skopeo sync --src yaml --dest docker --append-suffix '-synced' images.yaml my-registry.local.lan/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un dépôt distant,
# en utilisant des identifiants pour accéder aux registres source et destination.
$ skopeo sync --src yaml --dest docker --src-creds user:pass --dest-creds admin:secret images.yaml my-registry.local.lan/images

# Synchroniser toutes les images spécifiées dans un fichier YAML vers un dépôt distant,
# en autorisant la copie de toutes les variantes d'une image (par exemple, différentes architectures/OS).
$ skopeo sync --src yaml --dest docker --all images.yaml my-registry.local.lan/images

Synchronisation entre deux registres

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers 'my-registry.local.lan/alpine'
$ skopeo sync --src docker --dest docker docker.io/library/alpine my-registry.local.lan/alpine

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers 'my-registry.local.lan/alpine',
# et enregistrer les digests des images copiées dans le fichier 'digests.txt'.
$ skopeo sync --src docker --dest docker --digestfile digests.txt docker.io/library/alpine my-registry.local.lan/alpine

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers 'my-registry.local.lan/alpine',
# en évitant de copier les signatures.
$ skopeo sync --src docker --dest docker --remove-signatures docker.io/library/alpine my-registry.local.lan/alpine

Synchronisation avec des certificats personnalisés

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers 'my-registry.local.lan/alpine',
# en utilisant des certificats personnalisés pour le registre source et destination.
$ skopeo sync --src docker --dest docker --src-cert-dir /etc/pki/registry-src --dest-cert-dir /etc/pki/registry-dest docker.io/library/alpine my-registry.local.lan/alpine

Synchronisation avec des jetons d'authentification

# Synchroniser toutes les images du dépôt 'docker.io/library/alpine' vers 'my-registry.local.lan/alpine',
# en utilisant des jetons d'authentification pour les registres source et destination.
$ skopeo sync --src docker --dest docker --src-registry-token my-token --dest-registry-token your-token docker.io/library/alpine my-registry.local.lan/alpine

Synchronisation avec renvoi d'erreurs et poursuite

# Synchroniser plusieurs images, en ignorant les erreurs individuelles et en continuant le processus.
# Les erreurs seront signalées à la fin.
$ skopeo sync --src yaml --dest dir --keep-going images.yaml /mnt/images

Exécution à blanc de la synchronisation

# Effectuer une synchronisation à blanc pour voir ce qui serait copié sans réellement transférer de données.
$ skopeo sync --src docker --dest dir --dry-run docker.io/library/alpine /mnt/alpine-images
$ skopeo sync --src docker --dest dir registry.example.com/busybox /media/usb

Les images sont situées à :

/media/usb/busybox:1-glibc
/media/usb/busybox:1-musl
/media/usb/busybox:1-ubuntu
...
/media/usb/busybox:latest

Synchronisation vers un registre de conteneurs depuis le local

Les images sont situées à :

/media/usb/busybox:1-glibc

Exécution de la synchronisation :

$ skopeo sync --src dir --dest docker /media/usb/busybox:1-glibc my-registry.local.lan/test/

Contenu du registre de destination :

REPO                                 TAGS
my-registry.local.lan/test/busybox   1-glibc

Synchronisation vers un répertoire local, filtrée

$ skopeo sync --src docker --dest dir --scoped registry.example.com/busybox /media/usb

Les images sont situées à :

/media/usb/registry.example.com/busybox:1-glibc
/media/usb/registry.example.com/busybox:1-musl
/media/usb/registry.example.com/busybox:1-ubuntu
...
/media/usb/registry.example.com/busybox:latest

Synchronisation vers un registre de conteneurs

$ skopeo sync --src docker --dest docker registry.example.com/busybox my-registry.local.lan

Contenu du registre de destination :

REPO                         TAGS
registry.local.lan/busybox   1-glibc, 1-musl, 1-ubuntu, ..., latest

Synchronisation vers un registre de conteneurs en conservant le répertoire

$ skopeo sync --src docker --dest docker registry.example.com/repo/busybox my-registry.local.lan/repo

Contenu du registre de destination :

REPO                              TAGS
registry.local.lan/repo/busybox   1-glibc, 1-musl, 1-ubuntu, ..., latest

Synchronisation vers un registre de conteneurs avec un suffixe de tag

$ skopeo sync --src docker --dest docker --append-suffix '-mirror' registry.example.com/busybox my-registry.local.lan

Contenu du registre de destination :

REPO                         TAGS
registry.local.lan/busybox   1-glibc-mirror, 1-musl-mirror, 1-ubuntu-mirror, ..., latest-mirror

Contenu du fichier YAML (utilisé source pour --src yaml)

registry.example.com:
    images:
        busybox: []
        redis:
            - "1.0"
            - "2.0"
            - "sha256:0000000000000000000000000000000011111111111111111111111111111111"
    images-by-tag-regex:
        nginx: ^1\.13\.[12]-alpine-perl$
    images-by-semver:
        alpine: ">= 3.12.0"
    credentials:
        username: john
        password: this is a secret
    tls-verify: true
    cert-dir: /home/john/certs
quay.io:
    tls-verify: false
    images:
        coreos/etcd:
            - latest

Si le nom du fichier yaml est sync.yml, exécution de la synchronisation :

$ skopeo sync --src yaml --dest docker sync.yml my-registry.local.lan/repo/

Cela copiera les images suivantes : - Dépôt registry.example.com/busybox : toutes les images, car aucun tag n'est spécifié. - Dépôt registry.example.com/redis : images taguées "1.0" et "2.0" ainsi que l'image avec le digest "sha256:0000000000000000000000000000000011111111111111111111111111111111". - Dépôt registry.example.com/nginx : images taguées "1.13.1-alpine-perl" et "1.13.2-alpine-perl". - Dépôt quay.io/coreos/etcd : images taguées "latest". - Dépôt registry.example.com/alpine : toutes les images dont les tags correspondent à la contrainte de version sémantique ">= 3.12.0" ("3.12.0, "3.12.1", ..., "4.0.0", ...)

La liste complète des comparaisons possibles de versions sémantiques se trouve dans la documentation de la bibliothèque amont : https://github.com/Masterminds/semver/tree/v3.2.0#basic-comparisons.

L'ordre et la priorité des versions sont compris tels que définis ici : https://semver.org/#spec-item-11.

Pour le registre registry.example.com, les identifiants "john"/"this is a secret" sont utilisés, avec les certificats TLS du serveur situés à /home/john/certs.

La vérification TLS est normalement activée, et elle peut être désactivée en réglant tls-verify sur false. Dans l'exemple ci-dessus, la vérification TLS est activée pour registry.example.com, tandis qu'elle est désactivée pour quay.io.
