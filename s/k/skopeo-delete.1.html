NOM

skopeo-delete - Marquer l'image-name pour suppression ultérieure par le collecteur de déchets du registre.

SYNTAXE

skopeo delete [options] image-name

DESCRIPTION

Marquer image-name pour suppression. L'effet de ceci est spécifique au registre ; de nombreux registres ne supportent pas cette opération, ou ne l'autorisent pas dans certaines circonstances / configurations.

ATTENTION : Si image-name contient une empreinte (digest), cela affecte le manifeste référencé et peut supprimer toutes les étiquettes (au sein du dépôt actuel ?) pointant vers ce manifeste.

ATTENTION : Si image-name contient une étiquette (mais pas d'empreinte), dans la version actuelle de Skopeo, ceci résout l'étiquette en une empreinte, puis supprime le manifeste par empreinte, comme décrit ci-dessus (supprimant éventuellement toutes les étiquettes pointant vers ce manifeste, pas seulement l'étiquette fournie). Ce comportement peut changer à l'avenir.

Lors de l'utilisation du serveur de registre github.com/distribution/distribution : Pour libérer l'espace disque alloué, vous devez vous connecter au serveur du registre de conteneurs et exécuter le collecteur de déchets du registre de conteneurs. Par exemple :

/usr/bin/registry garbage-collect /etc/docker-distribution/registry/config.yml

Note : parfois, le fichier config.yml est stocké dans /etc/docker/registry/config.yml

Si vous exécutez le registre de conteneurs à l'intérieur d'un conteneur, vous exécuteriez quelque chose comme :

$ docker exec -it registry /usr/bin/registry garbage-collect /etc/docker-distribution/registry/config.yml

OPTIONS

Voir également skopeo(1) pour les options placées avant le nom de la sous-commande.

--authfile chemin

Chemin du fichier principal d'identification du registre. Sous Linux, la valeur par défaut est ${XDG_RUNTIME_DIR}/containers/auth.json. Voir containers-auth.json(5) pour plus de détails sur le mécanisme de recherche d'identification et les valeurs par défaut sur d'autres plateformes.

Utilisez skopeo login pour gérer les identifiants.

La valeur par défaut de cette option est lue à partir de la variable d'environnement REGISTRY\_AUTH\_FILE.

--creds nomutilisateur[:motdepasse]

Identifiants pour accéder au registre.

--cert-dir chemin

Utiliser les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre.

--daemon-host hote

Utiliser l'hôte du démon Docker à hote (transport docker-daemon: uniquement)

--help, -h

Afficher le message d'utilisation

--no-creds

Accéder au registre de manière anonyme.

En outre, le registre doit autoriser les suppressions en définissant REGISTRY\_STORAGE\_DELETE\_ENABLED=true pour le démon du registre.

--registry-token jeton

Jeton porteur pour accéder au registre.

--retry-times

Le nombre de tentatives.

--retry-delay

Délai fixe entre les tentatives. S'il n'est pas défini (ou défini à 0s), le temps d'attente de nouvelle tentative augmentera de manière exponentielle en fonction du nombre d'échecs.

--shared-blob-dir répertoire

Répertoire à utiliser pour partager des blobs entre les dépôts OCI.

--tls-verify=bool

Exiger HTTPS et vérifier les certificats lors de la communication avec le registre de conteneurs ou le démon. Par défaut, utilise le réglage de registry.conf.

--username

Le nom d'utilisateur pour accéder au registre.

--password

Le mot de passe pour accéder au registre.

EXEMPLES

Marquer l'image example/pause pour suppression du registre registry.example.com :

$ skopeo delete docker://registry.example.com/example/pause:latest

Voir ci-dessus pour des détails supplémentaires sur l'utilisation de la commande delete.
