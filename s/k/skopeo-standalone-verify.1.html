NOM

skopeo-standalone-verify - Outil de débogage - Vérifier une signature d'image à partir de fichiers locaux.

SYNTAXE

skopeo standalone-verify manifest docker-reference empreintes-clés signature

DESCRIPTION

Vérifie une signature en utilisant des fichiers locaux ; la somme de contrôle sera imprimée en cas de succès. Ceci est principalement un outil de débogage, utile pour des cas spéciaux, et ne devrait généralement pas faire partie de votre flux de travail opérationnel normal. De plus, envisagez de configurer un fichier de politique de vérification de signature, conformément à containers-policy.json(5).

manifest Chemin vers un fichier contenant le manifest de l'image

docker-reference Une référence docker attendue pour identifier l'image dans la signature

empreintes-clés Identités des clés de signature de confiance (séparées par des virgules), ou "any" pour faire confiance à n'importe quelle clé connue lors de l'utilisation d'un fichier de clé publique

signature Chemin vers le fichier de signature

Note : Si vous utilisez cette commande, assurez-vous que l'image ne peut pas être modifiée à son emplacement source entre le moment de sa vérification et de son utilisation.

OPTIONS

Voir également skopeo(1) pour les options placées avant le nom de la sous-commande.

--public-key-file fichier de clé publique

Fichier contenant les clés publiques à utiliser lors de la vérification des signatures. Si ce n'est pas spécifié, les clés du répertoire personnel GPG sont utilisées.

--help, -h

Imprime le message d'utilisation

EXEMPLES

$ skopeo standalone-verify busybox-manifest.json registry.example.com/example/busybox 1D8230F6CDB6A06716E414C1DB72F2188BB46CC8  busybox.signature
Signature verified, digest sha256:20bf21ed457b390829cdbeec8795a7bea1626991fda603e0d01b4e7f60427e55

NOTES

Cette commande est destinée à être utilisée avec des signatures locales (par exemple OpenPGP, d'autres formats de signature peuvent être ajoutés à l'avenir), conformément à containers-signature(5). De plus, cette commande n'interagit **pas** avec les artefacts générés par Docker Content Trust (DCT). Pour plus d'informations, veuillez consulter containers-signature(5) ⟨https://github.com/containers/image/blob/main/docs/containers-signature.5.md⟩.
