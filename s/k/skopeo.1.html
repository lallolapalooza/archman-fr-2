NOM

skopeo -- Utilitaire en ligne de commande utilisé pour interagir avec des images de conteneurs locales et distantes et des registres d'images de conteneurs

SYNTAXE

skopeo [options globales] commande [options de commande]

DESCRIPTION

skopeo est un utilitaire en ligne de commande offrant diverses opérations avec les images de conteneurs et les registres d'images de conteneurs.

skopeo peut copier des images de conteneurs entre différents stockages d'images de conteneurs, en les convertissant si nécessaire. Par exemple, vous pouvez utiliser skopeo pour copier des images de conteneurs d'un registre de conteneurs à un autre.

skopeo peut convertir une image de conteneur Docker schema 2 ou schema 1 en une image OCI.

skopeo peut inspecter un dépôt sur un registre de conteneurs sans télécharger inutilement l'image. Le téléchargement d'une image depuis un dépôt, en particulier un dépôt distant, est une opération coûteuse en réseau et en stockage. Skopeo récupère le manifeste du dépôt et affiche une sortie JSON similaire à docker inspect concernant le dépôt ou une balise. skopeo, par opposition à docker inspect, vous aide à recueillir des informations utiles sur un dépôt ou une balise sans nécessiter l'exécution de docker pull - par exemple - Quelles balises sont disponibles pour le dépôt donné ? Quelles étiquettes l'image possède-t-elle ?

skopeo peut signer et vérifier des images de conteneurs.

skopeo peut supprimer des images de conteneurs d'un registre de conteneurs distant.

Note : skopeo ne nécessite aucun runtime de conteneur en cours d'exécution pour la plupart de ses fonctionnalités. Il ne nécessite pas non plus de droits root, sauf si vous copiez des images dans un backend de stockage de runtime de conteneur, comme le démon Docker ou github.com/containers/storage.

NOMS D'IMAGE

La plupart des commandes font référence à des images de conteneurs, en utilisant un format transport:détails. Les formats suivants sont pris en charge :

containers-storage:référence-docker
Une image située dans un magasin d'images containers/storage local. L'emplacement et le magasin d'images sont spécifiés dans /etc/containers/storage.conf. (Backend pour Podman, CRI-O, Buildah et leurs semblables)

dir:chemin
Un répertoire local chemin stockant le manifeste, les couches tarball et les signatures sous forme de fichiers individuels. Il s'agit d'un format non standardisé, principalement utile pour le débogage ou l'inspection non invasive des conteneurs.

docker://référence-docker
Une image dans un registre implémentant la "Docker Registry HTTP API V2".
Les identifiants sont généralement gérés à l'aide de (skopeo login) ;
voir containers-auth.json(5) pour plus de détails sur le mécanisme de recherche des identifiants.

docker-archive:chemin[:référence-docker]
Une image est stockée dans le fichier formaté docker save. référence-docker n'est utilisé que lors de la création d'un tel fichier, et il ne doit pas contenir de digest.

docker-daemon:référence-docker
Une image référence-docker stockée dans le stockage interne du démon Docker. référence-docker doit contenir soit une balise, soit un digest. Alternativement, lors de la lecture d'images, le format peut être docker-daemon:algo:digest (un ID d'image).

oci:chemin:tag
Une image tag dans un répertoire conforme à la "Open Container Image Layout Specification" à l'emplacement chemin.

oci-archive:chemin:tag
Une image tag dans une archive tar conforme à la "Open Container Image Layout Specification" à l'emplacement chemin.

Voir containers-transports(5) ⟨https://github.com/containers/image/blob/main/docs/containers-transports.5.md⟩ pour plus de détails.

OPTIONS

Ces options doivent être placées avant le nom de la sous-commande. Les sous-commandes individuelles ont leurs propres options.

--command-timeout durée

Délai d'exécution de la commande.

--debug

activer la sortie de débogage

--help, -h

Afficher l'aide

--insecure-policy

Adopter une politique de sécurité incohérente et permissive qui autorise tout. Cela évite le besoin d'un fichier de politique.

--override-arch arch

Utiliser arch au lieu de l'architecture de la machine pour choisir les images.

--override-os os

Utiliser OS au lieu de l'OS en cours d'exécution pour choisir les images.

--override-variant variant

Utiliser variant au lieu de la variante d'architecture en cours d'exécution pour choisir les images.

--policy chemin-vers-politique

Chemin vers un fichier policy.json à utiliser pour vérifier les signatures et décider si une image est de confiance, remplaçant le fichier de politique de confiance par défaut.

--registries.d répertoire

Utiliser les fichiers de configuration de registre dans répertoire (par exemple, pour le stockage des signatures de conteneurs), remplaçant le chemin par défaut.

--tmpdir répertoire

Répertoire utilisé pour stocker les fichiers temporaires. Par défaut, /var/tmp.

--user-agent-prefix préfixe

Préfixe à ajouter à la chaîne de l'agent utilisateur. L'agent utilisateur résultant sera au format "préfixe skopeo/version".

--version, -v

Afficher le numéro de version

COMMANDES

Commande Description
skopeo-copy(1) Copier une image (manifeste, couches de système de fichiers, signatures) d'un emplacement à un autre.
skopeo-delete(1) Marquer le nom-image pour suppression ultérieure par le collecteur de déchets du registre.
skopeo-generate-sigstore-key(1) Générer une paire de clés publique/privée sigstore.
skopeo-inspect(1) Retourner des informations de bas niveau sur nom-image dans un registre.
skopeo-list-tags(1) Lister les noms d'image dans une collection d'images spécifique au transport.
skopeo-login(1) Se connecter à un registre de conteneurs.
skopeo-logout(1) Se déconnecter d'un registre de conteneurs.
skopeo-manifest-digest(1) Calculer un digest de manifeste pour un fichier-manifeste et l'écrire sur la sortie standard.
skopeo-standalone-sign(1) Outil de débogage - Signer une image localement sans la téléverser.
skopeo-standalone-verify(1) Outil de débogage - Vérifier une signature d'image à partir de fichiers locaux.
skopeo-sync(1) Synchroniser les images entre les dépôts de registres et les répertoires locaux.

STATUT DE SORTIE

skopeo se termine avec le statut 0 en cas de succès, non nul en cas d'erreur.

Détails sur les statuts de sortie :

1 Erreur générique, les détails se trouvent dans le message d'erreur.

2 L'image d'entrée ne peut pas être trouvée. Notez que cela est fait au mieux et, pour les registres distants, le statut ne peut souvent pas être rapporté de manière fiable.

FICHIERS

/etc/containers/policy.json
Fichier de politique de confiance par défaut, si --policy n'est pas spécifié.
Le format de la politique est documenté dans containers-policy.json(5) ⟨https://github.com/containers/image/blob/main/docs/containers-policy.json.5.md⟩ .

/etc/containers/registries.d
Répertoire par défaut contenant la configuration du registre, si --registries.d n'est pas spécifié.
Le contenu de ce répertoire est documenté dans containers-registries.d(5) ⟨https://github.com/containers/image/blob/main/docs/containers-registries.d.5.md⟩.
