SYNTAXE

DESCRIPTION

sk - recherche floue en Rust

sk est un outil de recherche floue polyvalent en ligne de commande.

VARIABLES D'ENVIRONNEMENT

NO_COLOR

Si elle est définie et non vide, sk n'utilisera aucune couleur dans la sortie.

SKIM_DEFAULT_COMMAND

Commande par défaut à utiliser lorsque l'entrée est un tty. Sur les systèmes *nix, sk exécute la commande avec sh -c, assurez-vous donc qu'elle est conforme à POSIX.

SKIM_DEFAULT_OPTIONS

Options par défaut. Par exemple : export SKIM_DEFAULT_OPTIONS="--multi"

MODE DE RECHERCHE ÉTENDU

Sauf indication contraire, sk démarrera en mode "recherche étendue". Dans ce mode, vous pouvez spécifier plusieurs motifs délimités par des espaces, tels que : 'wild ^music .mp3$ sbtrkt !rmx

Vous pouvez préfixer un espace par une barre oblique inverse (\ ) pour faire correspondre un espace littéral.

Correspondance exacte (entre guillemets)

Un terme préfixé par une apostrophe (') est interprété comme un terme de "correspondance exacte" (ou "non floue"). sk recherchera les occurrences exactes de la chaîne.

Correspondance ancrée

Un terme peut être préfixé par ^, ou suffixé par $ pour devenir un terme de correspondance ancrée. sk recherchera alors les lignes qui commencent ou se terminent par la chaîne donnée. Un terme de correspondance ancrée est également un terme de correspondance exacte.

Négation

Si un terme est préfixé par !, sk exclura les lignes qui satisfont le terme du résultat. Dans ce cas, sk effectue une correspondance exacte par défaut.

Correspondance exacte par défaut

Si vous ne préférez pas la recherche floue et ne souhaitez pas "mettre entre guillemets" (préfixer par ') chaque mot, démarrez sk avec l'option -e ou --exact. Notez que lorsque --exact est défini, '-prefix "déséquote" le terme.

Opérateur OU

Un terme de barre oblique unique agit comme un opérateur OU. Par exemple, la requête suivante correspond aux entrées qui commencent par core et se terminent par go, rb, ou py.

Exemple : ^core go$ | rb$ | py$

STATUT DE SORTIE

- 0 : Sortie normale

- 1 : Aucune correspondance

- 2 : Erreur

- 130 : Interrompu avec CTRL-C ou ESC

Ne pas trier les résultats

-t, --tiebreak <TIEBREAK> [défaut : score,begin,end]
Liste séparée par des virgules de critères de tri à appliquer lorsque les scores sont égaux.

- score : Score de l'algorithme de correspondance floue

- index : Préfère la ligne qui est apparue plus tôt dans le flux d'entrée

- begin : Préfère la ligne avec le sous-chaîne correspondante plus près du début

- end : Préfère la ligne avec le sous-chaîne correspondante plus près de la fin

- length : Préfère la ligne avec une longueur plus courte

Notes :

- Chaque critère peut être nié, par exemple (-index)

- Chaque critère ne doit apparaître qu'une seule fois dans la liste

[valeurs possibles : score, -score, begin, -begin, end, -end, length, -length, index, -index]

-n, --nth <NTH> [défaut : ]
Champs à faire correspondre

Une expression d'indice de champ peut être un entier non nul ou une expression de plage ([DÉBUT]..[FIN]). --nth et --with-nth prennent une liste séparée par des virgules d'expressions d'indices de champ.

Exemples :

- 1 : Le 1er champ

- 2 : Le 2ème champ

- -1 : Le dernier champ

- -2 : L'avant-dernier champ

- 3..5 : Du 3ème champ au 5ème champ

- 2.. : Du 2ème champ jusqu'au dernier champ

- ..-3 : Du 1er champ jusqu'à l'avant-dernier champ

- .. : Tous les champs

Comportements spéciaux

Avec les actions execute(...) et reload(...), vous pouvez exécuter des commandes arbitraires sans quitter sk. Par exemple, vous pouvez transformer sk en un simple explorateur de fichiers en liant la touche entrée à la commande less comme suit :


sk --bind "enter:execute(less {})"

Note : si aucun argument n'est fourni à reload, la commande par défaut est exécutée.

Vous pouvez utiliser les mêmes expressions de placeholder que dans --preview.

Si la commande contient des parenthèses, sk peut échouer à analyser l'expression. Dans ce cas, vous pouvez utiliser l'une des notations alternatives suivantes pour éviter les erreurs d'analyse.

- execute[...]

- execute'...'

- execute"..."

- execute:...

Ceci est la forme spéciale qui vous libère des erreurs d'analyse car elle n'attend pas le caractère de fermeture. Le hic est qu'elle doit être la dernière dans la liste d'éléments clé-action séparés par des virgules.

sk bascule vers l'écran alternatif lors de l'exécution d'une commande. Cependant, si la commande est censée se terminer rapidement et que vous ne vous souciez pas de sa sortie, vous pourriez plutôt utiliser execute-silent, qui exécute silencieusement la commande sans le changement d'écran. Notez que sk ne sera pas réactif tant que la commande ne sera pas terminée. Pour une exécution asynchrone, démarrez votre commande en tant que processus d'arrière-plan (c'est-à-dire en ajoutant &).

Avec les actions if-query-empty et if-query-not-empty, vous pouvez spécifier l'action à exécuter en fonction de la condition de la requête. Par exemple :

sk --bind 'ctrl-d:if-query-empty(abort)+delete-char'

Si la requête est vide, skim exécutera l'action abort, sinon il exécutera l'action delete-char. C'est équivalent à 'delete-char/eof'.

--color <COLOR>
Définir le thème de couleur

Utilisez --color pour personnaliser le schéma de couleurs de skim. Le format est :

Format : [BASE_SCHEME][,COULEUR:VALEUR_ANSI]

Schémas de couleurs de base

- dark: Thème sombre par défaut 256 couleurs (par défaut) - light: Thème clair 256 couleurs - 16: Thème basique 16 couleurs - bw: Thème minimal noir et blanc (pas de couleurs, juste des styles) - none: Thème minimal noir et blanc (pas de couleurs, pas de styles). Défaut lorsque NO_COLOR est défini - molokai: Thème 256 couleurs inspiré de Molokai

Personnalisation des couleurs

Les couleurs peuvent être spécifiées de deux manières :

- Code couleur ANSI (0-255) : --color=fg:232,bg:255 - Valeurs hexadécimales RGB : --color=fg:#FF0000 (texte rouge)

Éléments d'interface utilisateur personnalisables

- fg: Couleur du premier plan du texte normal - bg: Couleur de l'arrière-plan du texte normal - matched (ou hl): Texte correspondant dans les résultats de recherche - matched_bg: Arrière-plan du texte correspondant - current (ou fg+): Couleur du premier plan de la ligne actuelle - current_bg (ou bg+): Couleur de l'arrière-plan de la ligne actuelle - current_match (ou hl+): Texte correspondant dans la ligne actuelle - current_match_bg: Arrière-plan du texte correspondant dans la ligne actuelle - spinner: Couleur de l'indicateur de progression - info: Couleur de la ligne d'information - prompt: Couleur de l'invite - cursor (ou pointer): Couleur du curseur - selected (ou marker): Couleur du marqueur d'élément sélectionné - header: Couleur du texte de l'en-tête - border: Couleur de la bordure pour l'aperçu/la mise en page

Exemples

- --color=light: Utiliser le schéma de couleurs clair - --color=dark,fg:232,bg:255: Utiliser le schéma sombre avec des couleurs personnalisées - --color=current_bg:24: Schéma par défaut avec un arrière-plan personnalisé pour la ligne actuelle - --color=dark,matched:#00FF00: Texte correspondant vert sur fond sombre - --color=fg:#FFFFFF,bg:#000000: Schéma de couleurs personnalisé blanc sur noir

--no-clear-if-empty
Ne pas effacer la ligne précédente si la commande renvoie un résultat vide

Ne pas effacer les éléments précédents si la nouvelle commande renvoie un résultat vide. Cela peut être utile pour réduire le scintillement lors de la saisie de nouvelles commandes dont les commandes partielles ne sont pas valides.

Ce n'est pas le comportement par défaut car des cas d'utilisation similaires pour grep et rg ont déjà été optimisés où des résultats de requête vides signifient en fait "vide" et que les résultats précédents doivent être effacés.

--tmux [<TMUX>...]
Exécuter dans une fenêtre contextuelle tmux

APERÇU

--preview <PREVIEW>
Commande d'aperçu

Exécute la commande donnée pour la ligne actuelle et affiche le résultat dans la fenêtre d'aperçu. {} dans la commande est le placeholder qui est remplacé par la chaîne entre guillemets simples de la ligne actuelle. Pour transformer la chaîne de remplacement, spécifiez des expressions d'index de champ entre les accolades (voir FIELD INDEX EXPRESSION pour les détails).

Exemples :


sk --preview='head -$LINES {}'
ls -l | sk --preview="echo user={3} when={-4..-2}; cat {-1}" --header-lines=1

sk remplace $LINES et $COLUMNS de manière à ce qu'ils représentent la taille exacte de la fenêtre d'aperçu.

Une expression placeholder commençant par le drapeau + sera remplacée par la liste séparée par des espaces des lignes sélectionnées (ou la ligne actuelle s'il n'y a pas de sélection) individuellement citées.

Exemples :


sk --multi --preview='head -10 {+}'
git log --oneline | sk --multi --preview 'git show {+1}'

Notez que vous pouvez échapper un modèle de placeholder en le faisant précéder d'une barre oblique inverse.

De plus, {q} est remplacé par la chaîne de requête actuelle. {cq} est remplacé par la chaîne de requête de commande actuelle. {n} est remplacé par l'index ordinal basé sur zéro de la ligne. Utilisez {+n} si vous voulez tous les numéros d'index lorsque plusieurs lignes sont sélectionnées

La fenêtre d'aperçu sera mise à jour même s'il n'y a pas de correspondance pour la requête actuelle si l'une des expressions placeholder s'évalue à une chaîne non vide.

--preview-window <PREVIEW_WINDOW> [défaut: right:50%]
Disposition de la fenêtre d'aperçu

Format : [up|down|left|right][:SIZE[%]][:hidden][:+SCROLL[-OFFSET]]

Détermine la disposition de la fenêtre d'aperçu. Si l'argument se termine par : hidden, la fenêtre d'aperçu sera cachée par défaut jusqu'à ce que l'action toggle-preview soit déclenchée. Les lignes longues sont tronquées par défaut. Le retour à la ligne peut être activé avec le drapeau : wrap.

Si la taille est donnée comme 0, la fenêtre d'aperçu ne sera pas visible, mais sk exécutera la commande en arrière-plan.

+SCROLL[-OFFSET] détermine le décalage initial du défilement de la fenêtre d'aperçu. SCROLL peut être soit un entier numérique, soit une expression de champ unique qui fait référence à un entier numérique. La partie facultative -OFFSET sert à ajuster le décalage de base afin que vous puissiez voir le texte au-dessus. Elle doit être donnée comme un entier numérique (-INTEGER), ou sous forme de dénominateur (-/INTEGER) pour spécifier une fraction de la hauteur de la fenêtre d'aperçu.

Exemples :


# Positions et tailles de fenêtre de défilement non par défaut
sk --preview="head {}" --preview-window=up:30%
sk --preview="file {}" --preview-window=down:2


# Le décalage de défilement initial est défini sur le numéro de ligne de chaque ligne de
# la sortie de git grep *moins* 5 lignes (-5)
git grep --line-number '' |
sk --delimiter: --preview 'nl {1}' --preview-window +{2}-5


# Aperçu avec bat, correspondance de la ligne au milieu de la fenêtre (-/2)
git grep --line-number '' |
sk --delimiter: \
--preview 'bat --style=numbers --color=always --highlight-line {2} {1}' \
--preview-window +{2}-/2

--expect <EXPECT>
[Obsolète : Utilisez --bind=<clé>:accept(<clé>) à la place] Liste séparée par des virgules des touches utilisées pour compléter skim

Liste séparée par des virgules des touches qui peuvent être utilisées pour compléter sk en plus de la touche entrée par défaut. Lorsque cette option est définie, sk imprimera le nom de la touche pressée comme première ligne de sa sortie (ou comme deuxième ligne si --print-query est également utilisé). Aucune ligne ne sera imprimée si sk est complété avec la touche entrée par défaut. Si l'option --expect est spécifiée plusieurs fois, sk attendra l'union des clés. --no-expect effacera la liste.

Exemple : sk --expect=ctrl-v,ctrl-t,alt-s --expect=f1,f2,~,@

--shell <SHELL>
Génère un script de complétion de shell

Génère un script de complétion pour le shell spécifié : bash, zsh, fish, etc. La sortie peut être directement sourcée ou enregistrée dans un fichier pour un chargement automatique. Exemples : source <(sk --shell bash) (utilisation immédiate) sk --shell bash >> ~/.bash_completion (utilisation persistante)

Shells pris en charge : bash, zsh, fish, powershell, elvish

Note : Bien que les complétions PowerShell soient prises en charge, Windows n'est pas pris en charge pour le moment.

[valeurs possibles : bash, elvish, fish, powershell, zsh]
