selection(n) Commandes intégrées Tk selection(n)

NOM

selection - Manipuler la sélection X

SYNTAXE

selection option ?arg arg ...?

DESCRIPTION

Cette commande fournit une interface Tcl au mécanisme de sélection X et implémente la fonctionnalité complète de sélection décrite dans le X Inter-Client Communication Conventions Manual (ICCCM).

Notez que pour la gestion de la sélection CLIPBOARD (voir ci-dessous), la commande clipboard peut également être utilisée.

Le premier argument de selection détermine le format du reste des arguments et le comportement de la commande. Les formes suivantes sont actuellement prises en charge :

selection clear ?-displayof window? ?-selection selection?
Si selection existe n'importe où sur l'écran de window, l'efface de sorte qu'aucune fenêtre ne possède plus la sélection. Selection spécifie la sélection X qui doit être effacée et doit être un nom d'atome tel que PRIMARY ou CLIPBOARD ; voir le Inter-Client Communication Conventions Manual pour les détails complets. Selection vaut par défaut PRIMARY et window vaut par défaut “.”. Renvoie une chaîne vide.
selection get ?-displayof window? ?-selection selection? ?-type type?
Récupère la valeur de selection à partir de l'écran de window et la renvoie comme résultat. Selection vaut par défaut PRIMARY et window vaut par défaut “.”. Type spécifie la forme dans laquelle la sélection doit être renvoyée (la « cible » souhaitée pour la conversion, dans la terminologie ICCCM), et doit être un nom d'atome tel que STRING ou FILE_NAME ; voir le Inter-Client Communication Conventions Manual pour les détails complets. Type vaut par défaut STRING. Le propriétaire de la sélection peut choisir de renvoyer la sélection dans plusieurs formats de représentation différents, tels que STRING, UTF8_STRING, ATOM, INTEGER, etc. (ce format est différent du type de sélection ; voir l'ICCCM pour tous les détails déroutants). Si la sélection est renvoyée dans un format non-chaîne, tel que INTEGER ou ATOM, la commande selection la convertit en format chaîne comme une collection de champs séparés par des espaces : les atomes sont convertis en leurs noms textuels, et tout le reste est converti en entiers hexadécimaux. Notez que selection get ne récupère pas la sélection au format UTF8_STRING à moins qu'on ne le lui demande.
selection handle ?-selection s? ?-type t? ?-format f? window command
Crée un gestionnaire pour les requêtes de sélection, de telle sorte que command sera exécutée chaque fois que la sélection s sera détenue par window et que quelqu'un tentera de la récupérer sous la forme donnée par le type t (par exemple, t est spécifié dans la commande selection get). S vaut par défaut PRIMARY, t vaut par défaut STRING, et f vaut par défaut STRING. Si command est une chaîne vide alors tout gestionnaire existant pour window, t, et s est supprimé. Notez que lorsque la sélection est gérée comme type STRING, elle est également automatiquement gérée comme type UTF8_STRING.

Lorsque selection est demandée, window est le propriétaire de la sélection, et type est le type demandé, command sera exécutée comme une commande Tcl avec deux nombres supplémentaires ajoutés (avec des séparateurs d'espaces). Les deux nombres supplémentaires sont offset et maxChars : offset spécifie une position de caractère de départ dans la sélection et maxChars donne le nombre maximum de caractères à récupérer. La commande devrait renvoyer une valeur composée au maximum de maxChars de la sélection, commençant à la position offset. Pour des sélections très volumineuses (plus grandes que maxChars), la sélection sera récupérée en utilisant plusieurs invocations de command avec des valeurs d'offset croissantes. Si command renvoie une chaîne dont la longueur est inférieure à maxChars, la valeur renvoyée est supposée inclure tout le reste de la sélection ; si la longueur du résultat de command est égale à maxChars, alors command sera invoquée à nouveau, jusqu'à ce qu'elle renvoie finalement un résultat plus court que maxChars. La valeur de maxChars sera toujours relativement grande (des milliers de caractères).

Si command renvoie une erreur, alors la récupération de la sélection est rejetée comme si la sélection n'existait pas du tout.

L'argument format spécifie la représentation qui doit être utilisée pour transmettre la sélection au demandeur (la deuxième colonne du Tableau 2 de l'ICCCM), et vaut par défaut STRING. Si format est STRING, la sélection est transmise comme des caractères ASCII 8 bits (c'est-à-dire juste sous la forme renvoyée par command, dans l'encodage du système ; le format UTF8_STRING utilise toujours UTF-8 comme encodage). Si format est ATOM, alors la valeur renvoyée par command est divisée en champs séparés par des espaces ; chaque champ est converti en sa valeur d'atome, et la valeur d'atome de 32 bits est transmise au lieu du nom de l'atome. Pour tout autre format, la valeur renvoyée par command est divisée en champs séparés par des espaces et chaque champ est converti en un entier de 32 bits ; un tableau d'entiers est transmis au demandeur de sélection.

L'argument format n'est nécessaire que pour la compatibilité avec les demandeurs de sélection qui n'utilisent pas Tk. Si Tk est utilisé pour récupérer la sélection, alors la valeur est reconvertie en chaîne du côté du demandeur, donc format est sans importance.

selection own ?-displayof window? ?-selection selection?
selection own ?-command command? ?-selection selection? window
La première forme de selection own renvoie le nom de chemin de la fenêtre de cette application qui possède la selection sur l'écran contenant window, ou une chaîne vide si aucune fenêtre de cette application ne possède la sélection. Selection vaut par défaut PRIMARY et window vaut par défaut “.”.

La seconde forme de selection own fait en sorte que window devienne le nouveau propriétaire de selection sur l'écran de window, renvoyant une chaîne vide comme résultat. Le propriétaire existant, le cas échéant, est notifié qu'il a perdu la sélection. Si command est spécifié, il s'agit d'un script Tcl à exécuter lorsqu'une autre fenêtre revendique la propriété de la sélection au détriment de window. Selection vaut par défaut PRIMARY.

FACILITÉS DES WIDGETS

Les widgets text, entry, ttk::entry, listbox, spinbox et ttk::spinbox ont l'option -exportselection. Si un widget a cette option définie sur la valeur booléenne true, alors (dans un interpréteur non sécurisé) une sélection faite dans le widget est automatiquement écrite dans la sélection PRIMARY.

Un événement GUI, par exemple <<PasteSelection>>, peut copier la sélection PRIMARY vers certains widgets. Cette copie est implémentée par une liaison de widget à l'événement. Le script de liaison fait des appels appropriés à la commande selection.

PROBLÈMES DE PORTABILITÉ

Sur X11, la sélection PRIMARY est une fonctionnalité système du serveur X, permettant la communication entre différents processus qui sont des clients X11.

Sur Windows, la sélection PRIMARY n'est pas fournie par le système, mais uniquement par Tk, et elle n'est donc partagée qu'entre les fenêtres d'un interpréteur parent et ses interpréteurs enfants. Elle n'est pas partagée entre les interpréteurs dans des processus différents ou des threads différents. Chaque interpréteur parent possède une sélection PRIMARY séparée qui n'est partagée qu'avec ses interpréteurs enfants qui ne sont pas des interpréteurs sécurisés.

selection(n) — selection

NAME

selection - manage the X selections

SYNOPSIS

selection clear ?selection?
selection exists ?selection?
selection get ?selection? ?type?
selection handle ?selection? ?type? script ?arg ...?
selection own ?selection? ?-command script?
selection type ?selection?

DESCRIPTION

The selection command is used to manage the X selections. Selections are a mechanism for inter-process communication, typically used for copy-and-paste operations between different applications. The most common selection is called PRIMARY, which is generally used for selecting text with the mouse. Another common selection is called CLIPBOARD, which is used for explicit copy-and-paste operations. Other selections may exist, such as SECONDARY, but they are less common.

The selection mechanism involves one application owning a selection and other applications requesting data from that selection. The data is described by its type (e.g., STRING, FILE_NAME, TARGETS). The selection command provides facilities for both owning and getting data from selections.

WIDGET FACILITIES

Most Tk widgets that can display or edit text (e.g., text, entry, label) have an option -exportselection. When this option is set to boolean true (the default), Tk automatically handles the PRIMARY and CLIPBOARD selections for the widget. When the widget claims one of these selections, Tk ensures that the widget's contents are available in the standard formats. When another application requests data from the selection, Tk invokes a handler to retrieve the data from the widget. If the widget loses the selection (e.g., because another application claims it), Tk automatically updates the widget's state.

If -exportselection is set to false, the widget will not automatically participate in the selection mechanism. You will need to use the selection command manually to get or set the selection contents.

PORTABILITY ISSUES

The selection command relies on the X Window System's selection mechanism. It will not work on systems that do not use X11.

SECURITY

In a safe interpreter, writing to the PRIMARY selection is disabled. This means that the selection own command cannot be used to claim the PRIMARY selection, and the -exportselection option for Tk widgets has no effect when set to true (writing from the widget to the PRIMARY selection is disabled).

These are security features. A safe interpreter may run untrusted code, and it is a security risk if this untrusted code can read or write the PRIMARY selection used by other interpreters.

EXAMPLES

On X11 platforms, one of the standard selections available is the SECONDARY selection. Hardly anything uses it, but here is how to read it using Tk:

set selContents [selection get -selection SECONDARY]

Many different types of data may be available for a selection; the special type TARGETS allows you to get a list of available types:

foreach type [selection get -type TARGETS] {
   puts "Selection PRIMARY supports type $type"
}

To claim the selection, you must first set up a handler to supply the data for the selection. Then you have to claim the selection...

# Set up the data handler ready for incoming requests
set foo "This is a string with some data in it... blah blah"
selection handle -selection SECONDARY . getData
proc getData {offset maxChars} {
   puts "Retrieving selection starting at $offset"
   return [string range $::foo $offset [expr {$offset+$maxChars-1}]]
}
# Now we grab the selection itself
puts "Claiming selection"
selection own -command lost -selection SECONDARY .
proc lost {} {
   puts "Lost selection"
}

NOM

selection - gérer les sélections X

SYNTAXE

selection clear ?sélection?
selection exists ?sélection?
selection get ?sélection? ?type?
selection handle ?sélection? ?type? script ?arg ...?
selection own ?sélection? ?-command script?
selection type ?sélection?

DESCRIPTION

La commande selection est utilisée pour gérer les sélections X. Les sélections sont un mécanisme de communication inter-processus, généralement utilisé pour les opérations de copier-coller entre différentes applications. La sélection la plus courante s'appelle PRIMARY, qui est généralement utilisée pour sélectionner du texte avec la souris. Une autre sélection courante s'appelle CLIPBOARD, qui est utilisée pour les opérations explicites de copier-coller. D'autres sélections peuvent exister, comme SECONDARY, mais elles sont moins courantes.

Le mécanisme de sélection implique qu'une application possède une sélection et que d'autres applications demandent des données de cette sélection. Les données sont décrites par leur type (par exemple, STRING, FILE_NAME, TARGETS). La commande selection fournit des installations pour posséder et obtenir des données à partir des sélections.

FACILITÉS DES WIDGETS

La plupart des widgets Tk qui peuvent afficher ou modifier du texte (par exemple, text, entry, label) ont une option -exportselection. Lorsque cette option est définie sur true (par défaut), Tk gère automatiquement les sélections PRIMARY et CLIPBOARD pour le widget. Lorsque le widget revendique une de ces sélections, Tk s'assure que le contenu du widget est disponible dans les formats standard. Lorsqu'une autre application demande des données de la sélection, Tk invoque un gestionnaire pour récupérer les données du widget. Si le widget perd la sélection (par exemple, parce qu'une autre application la revendique), Tk met automatiquement à jour l'état du widget.

Si -exportselection est défini sur false, le widget ne participera pas automatiquement au mécanisme de sélection. Vous devrez utiliser la commande selection manuellement pour obtenir ou définir le contenu de la sélection.

PROBLÈMES DE PORTABILITÉ

La commande selection repose sur le mécanisme de sélection du système X Window. Elle ne fonctionnera pas sur les systèmes qui n'utilisent pas X11.

SÉCURITÉ

Dans un interpréteur sécurisé, l'écriture dans la sélection PRIMARY est désactivée. Cela signifie que la commande selection own ne peut pas être utilisée pour revendiquer la sélection PRIMARY, et l'option -exportselection pour les widgets Tk n'a aucun effet lorsqu'elle est définie sur true (l'écriture du widget vers la sélection PRIMARY est désactivée).

Ce sont des fonctionnalités de sécurité. Un interpréteur sécurisé peut exécuter du code non fiable, et il représente un risque de sécurité si ce code non fiable peut lire ou écrire dans la sélection PRIMARY utilisée par d'autres interpréteurs.

EXEMPLES

Sur les plateformes X11, l'une des sélections standard disponibles est la sélection SECONDARY. Presque rien ne l'utilise, mais voici comment la lire en utilisant Tk :

set selContents [selection get -selection SECONDARY]

De nombreux types de données différents peuvent être disponibles pour une sélection ; le type spécial TARGETS vous permet d'obtenir une liste des types disponibles :

foreach type [selection get -type TARGETS] {
   puts "La sélection PRIMARY supporte le type $type"
}

Pour revendiquer la sélection, vous devez d'abord mettre en place un gestionnaire pour fournir les données de la sélection. Ensuite, vous devez revendiquer la sélection...

# Configurer le gestionnaire de données prêt pour les requêtes entrantes
set foo "Ceci est une chaîne avec des données... blabla blabla"
selection handle -selection SECONDARY . getData
proc getData {offset maxChars} {
   puts "Récupération de la sélection à partir de $offset"
   return [string range $::foo $offset [expr {$offset+$maxChars-1}]]
}
# Maintenant, nous capturons la sélection elle-même
puts "Revendication de la sélection"
selection own -command lost -selection SECONDARY .
proc lost {} {
   puts "Sélection perdue"
}
