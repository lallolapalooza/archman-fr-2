gettimeofday(2) Manuel des appels système gettimeofday(2)

NOM

gettimeofday, settimeofday - obtenir / définir l'heure

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/time.h>
[[deprecated]]
int gettimeofday(struct timeval *restrict tv,
                 struct timezone *_Nullable restrict tz);
[[deprecated]]
int settimeofday(const struct timeval *tv,
                 const struct timezone *_Nullable tz);
Macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

settimeofday():

    Depuis glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 et antérieur:
        _BSD_SOURCE

DESCRIPTION

Les fonctions gettimeofday() et settimeofday() permettent d'obtenir et de définir l'heure ainsi que le fuseau horaire.

L'argument tv est une struct timeval (tel que spécifié dans <sys/time.h>) :


struct timeval {
    time_t      tv_sec;     /* secondes */
    suseconds_t tv_usec;    /* microsecondes */
};

et représente le nombre de secondes et de microsecondes depuis l'Époque (voir time(2)).

L'argument tz est une struct timezone :


struct timezone {
    int tz_minuteswest;     /* minutes à l'ouest de Greenwich */
    int tz_dsttime;         /* type de correction de l'heure d'été */
};

Si tv ou tz est NULL, la structure correspondante n'est pas définie ou retournée. (Cependant, des avertissements de compilation surviendront si tv est NULL.)

L'utilisation de la structure timezone est obsolète ; l'argument tz devrait normalement être spécifié comme NULL. Voir VERSIONS.

Sous Linux, il existe des sémantiques particulières d'« horloge rebondissante » associées à l'appel système settimeofday() si lors du tout premier appel (après le démarrage) avec un argument tz non NULL, l'argument tv est NULL et le champ tz_minuteswest est non nul. (Le champ tz_dsttime devrait être zéro dans ce cas.) Dans un tel cas, il est supposé que l'horloge CMOS est en heure locale, et qu'elle doit être incrémentée de ce montant pour obtenir l'heure système UTC. Il est sans doute une mauvaise idée d'utiliser cette fonctionnalité.

VALEUR DE RETOUR

gettimeofday() et settimeofday() retournent 0 en cas de succès. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Un des arguments tv ou tz pointait en dehors de l'espace d'adressage accessible.
EINVAL
(settimeofday()) : timezone est invalide.
EINVAL
(settimeofday()) : tv.tv_sec est négatif ou tv.tv_usec est en dehors de la plage [0, 999 999].
EINVAL (depuis Linux 4.3)
(settimeofday()) : Une tentative a été faite pour régler l'heure à une valeur inférieure à la valeur actuelle de l'horloge CLOCK_MONOTONIC (voir clock_gettime(2)).
EPERM
Le processus appelant n'a pas les privilèges suffisants pour appeler settimeofday() ; sous Linux, la capacité CAP_SYS_TIME est requise.

VERSIONS

Différences bibliothèque C/noyau

Sur certaines architectures, une implémentation de gettimeofday() est fournie dans le vdso(7).

Le noyau accepte NULL pour tv et tz. L'argument timezone est ignoré par glibc et musl, et n'est ni passé au/depuis le noyau. Bionic d'Android passe l'argument timezone au/depuis le noyau, mais Android ne met pas à jour le timezone du noyau en fonction du timezone de l'appareil dans les paramètres, donc le timezone du noyau est généralement UTC.

NORMES

Aucune.

HISTORIQUE

SVr4, 4.3BSD. POSIX.1-2001 décrivait gettimeofday() mais pas settimeofday(). POSIX.1-2008 a marqué gettimeofday() comme obsolète, recommandant l'utilisation de clock_gettime(2) à la place. De même, clock_settime(2) devrait être utilisé à la place de settimeofday(). POSIX.1-2024 a supprimé gettimeofday().

Traditionnellement, les champs de struct timeval étaient de type long.

Le champ tz_dsttime

Sur un noyau non-Linux, avec glibc, le champ tz_dsttime de struct timezone sera défini à une valeur non nulle par gettimeofday() si le fuseau horaire actuel a jamais eu ou aura une règle d'heure d'été appliquée. En ce sens, il reflète exactement la signification de daylight(3) pour la zone actuelle. Sur Linux, avec glibc, la définition du champ tz_dsttime de struct timezone n'a jamais été utilisée par settimeofday() ou gettimeofday(). Ainsi, ce qui suit n'a qu'un intérêt historique.

Sur les anciens systèmes, le champ tz_dsttime contient une constante symbolique (les valeurs sont données ci-dessous) qui indique dans quelle partie de l'année l'heure d'été est en vigueur. (Note : cette valeur est constante toute l'année : elle n'indique pas que l'heure d'été est en vigueur, elle sélectionne juste un algorithme.) Les algorithmes d'heure d'été définis sont les suivants :


DST_NONE     /* pas d'heure d'été */
DST_USA      /* heure d'été style USA */
DST_AUST     /* heure d'été style australien */
DST_WET      /* heure d'été d'Europe de l'Ouest */
DST_MET      /* heure d'été d'Europe centrale */
DST_EET      /* heure d'été d'Europe de l'Est */
DST_CAN      /* Canada */
DST_GB       /* Grande-Bretagne et Irlande */
DST_RUM      /* Roumanie */
DST_TUR      /* Turquie */
DST_AUSTALT  /* style australien avec changement en 1986 */

Bien sûr, il s'est avéré que la période pendant laquelle l'heure d'été est en vigueur ne peut pas être représentée par un algorithme simple, un par pays ; en effet, cette période est déterminée par des décisions politiques imprévisibles. Ainsi, cette méthode de représentation des fuseaux horaires a été abandonnée.

NOTES

L'heure retournée par gettimeofday() est affectée par les sauts discontinus dans l'heure système (par exemple, si l'administrateur système modifie manuellement l'heure système). Si vous avez besoin d'une horloge qui progresse de manière monotone, voir clock_gettime(2).

Les macros pour opérer sur les structures timeval sont décrites dans timeradd(3).

VOIR AUSSI
