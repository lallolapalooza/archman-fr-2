SEMCTL(3P) Manuel du programmeur POSIX SEMCTL(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

semctl — opérations de contrôle de sémaphores XSI

SYNOPSIS

#include <sys/sem.h>
int semctl(int semid, int semnum, int cmd, ...);

DESCRIPTION

La fonction semctl() opère sur les sémaphores XSI (voir le volume Définitions de base de POSIX.1‐2017, Section 4.17, Sémaphore). Il n'est pas spécifié si cette fonction interopère avec les installations de communication interprocessus temps réel définies dans la Section 2.8, Temps réel.

La fonction semctl() fournit une variété d'opérations de contrôle de sémaphores comme spécifié par cmd. Le quatrième argument est facultatif et dépend de l'opération demandée. S'il est requis, il est de type union semun, que l'application doit explicitement déclarer :

union semun {
    int val;
    struct semid_ds *buf;
    unsigned short  *array;
} arg;

Chaque opération est effectuée de manière atomique.

Les opérations de contrôle de sémaphores suivantes, spécifiées par cmd, sont exécutées par rapport au sémaphore spécifié par semid et semnum. Le niveau d'autorisation requis pour chaque opération est indiqué avec chaque commande ; voir la Section 2.7, Communication interprocessus XSI. Les noms symboliques des valeurs de cmd sont définis dans l'en-tête <sys/sem.h> :

GETVAL
Retourne la valeur de semval ; voir <sys/sem.h>. Nécessite une permission de lecture.
SETVAL
Définit la valeur de semval à arg.val, où arg est la valeur du quatrième argument de semctl(). Lorsque cette commande est exécutée avec succès, la valeur semadj correspondant au sémaphore spécifié dans tous les processus est effacée. De plus, l'horodatage sem_ctime est défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale IPC. Nécessite une permission de modification ; voir la Section 2.7, Communication interprocessus XSI.
GETPID
Retourne la valeur de sempid. Nécessite une permission de lecture.
GETNCNT
Retourne la valeur de semncnt. Nécessite une permission de lecture.
GETZCNT
Retourne la valeur de semzcnt. Nécessite une permission de lecture.

Les valeurs de cmd suivantes opèrent sur chaque semval dans l'ensemble des sémaphores :

GETALL
Retourne la valeur de semval pour chaque sémaphore dans l'ensemble de sémaphores et la place dans le tableau pointé par arg.array, où arg est le quatrième argument de semctl(). Nécessite une permission de lecture.
SETALL
Définit la valeur de semval pour chaque sémaphore dans l'ensemble de sémaphores selon le tableau pointé par arg.array, où arg est le quatrième argument de semctl(). Lorsque cette commande est exécutée avec succès, les valeurs semadj correspondant à chaque sémaphore spécifié dans tous les processus sont effacées. De plus, l'horodatage sem_ctime est défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale IPC. Nécessite une permission de modification.

Les valeurs de cmd suivantes sont également disponibles :

IPC_STAT
Place la valeur actuelle de chaque membre de la structure de données semid_ds associée à semid dans la structure pointée par arg.buf, où arg est le quatrième argument de semctl(). Le contenu de cette structure est défini dans <sys/sem.h>. Nécessite une permission de lecture.
IPC_SET
Définit la valeur des membres suivants de la structure de données semid_ds associée à semid à la valeur correspondante trouvée dans la structure pointée par arg.buf, où arg est le quatrième argument de semctl() :
sem_perm.uid
sem_perm.gid
sem_perm.mode

Les bits de mode spécifiés dans la Section 2.7.1, Description générale IPC sont copiés dans les bits correspondants de sem_perm.mode associés à semid. Les valeurs stockées de tout autre bit ne sont pas spécifiées. L'horodatage sem_ctime est défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale IPC.

Cette commande ne peut être exécutée que par un processus dont l'ID utilisateur effectif est égal soit à celui d'un processus disposant des privilèges appropriés, soit à la valeur de sem_perm.cuid ou sem_perm.uid dans la structure de données semid_ds associée à semid.

IPC_RMID
Supprime l'identifiant de sémaphore spécifié par semid du système et détruit l'ensemble des sémaphores et la structure de données semid_ds qui y sont associés. Cette commande ne peut être exécutée que par un processus dont l'ID utilisateur effectif est égal soit à celui d'un processus disposant des privilèges appropriés, soit à la valeur de sem_perm.cuid ou sem_perm.uid dans la structure de données semid_ds associée à semid.

VALEUR RENVOYÉE

En cas de succès, la valeur renvoyée par semctl() dépend de cmd comme suit :

GETVAL
La valeur de semval.
GETPID
La valeur de sempid.
GETNCNT
La valeur de semncnt.
GETZCNT
La valeur de semzcnt.
Tous les autres
0.

Sinon, semctl() renvoie -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction semctl() échouera si :

EACCES
La permission d'opération est refusée au processus appelant ; voir la Section 2.7, Communication interprocessus XSI.
EINVAL
La valeur de semid n'est pas un identifiant de sémaphore valide, ou la valeur de semnum est inférieure à 0 ou supérieure ou égale à sem_nsems, ou la valeur de cmd n'est pas une commande valide.
EPERM
L'argument cmd est égal à IPC_RMID ou IPC_SET et l'ID utilisateur effectif du processus appelant n'est pas égal à celui d'un processus disposant des privilèges appropriés et n'est pas égal à la valeur de sem_perm.cuid ou sem_perm.uid dans la structure de données associée à semid.
ERANGE
L'argument cmd est égal à SETVAL ou SETALL et la valeur à laquelle semval doit être défini est supérieure au maximum imposé par le système.

UTILISATION PAR APPLICATION

Le quatrième paramètre dans la section SYNOPSIS est maintenant spécifié comme "..." afin d'éviter un conflit avec la norme ISO C lors de la référence à l'union semun (telle que définie dans Issue 3) et pour des raisons de compatibilité ascendante.

L'extension Temps réel POSIX définit des interfaces alternatives pour la communication interprocessus. Les développeurs d'applications qui ont besoin d'utiliser l'IPC devr

d conçoivent leurs applications de manière à ce que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication Inter-Processus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
