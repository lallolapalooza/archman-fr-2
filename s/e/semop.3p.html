SEMOP(3P) Manuel du programmeur POSIX SEMOP(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

semop — opérations sur sémaphores XSI

SYNTAXE

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);

DESCRIPTION

La fonction semop() opère sur les sémaphores XSI (voir le volume Bases Définitions de POSIX.1‐2017, Section 4.17, Sémàphore). Il n'est pas spécifié si cette fonction interopère avec les facilités de communication interprocessus temps réel définies dans la Section 2.8, Temps Réel.

La fonction semop() effectue de manière atomique un tableau d'opérations sur sémaphores défini par l'utilisateur, dans l'ordre du tableau, sur l'ensemble des sémaphores associés à l'identifiant de sémaphore spécifié par l'argument semid.

L'argument sops est un pointeur vers un tableau défini par l'utilisateur de structures d'opérations sur sémaphores. L'implémentation ne modifiera pas les éléments de ce tableau, sauf si l'application utilise des extensions définies par l'implémentation.

L'argument nsops est le nombre de telles structures dans le tableau.

Chaque structure, sembuf, inclut les membres suivants :

Type de membre Nom du membre Description
unsigned short sem_num Numéro du sémaphore.
short sem_op Opération sur le sémaphore.
short sem_flg Drapeaux d'opération.

Chaque opération sur sémaphore spécifiée par sem_op est effectuée sur le sémaphore correspondant spécifié par semid et sem_num.

La variable sem_op spécifie l'une des trois opérations sur sémaphores suivantes :

1.
Si sem_op est un entier négatif et que le processus appelant a l'autorisation de modification, l'une des actions suivantes se produit :
*
Si semval (voir <sys/sem.h>) est supérieur ou égal à la valeur absolue de sem_op, la valeur absolue de sem_op est soustraite de semval. De plus, si (sem_flg &SEM_UNDO) est différent de zéro, la valeur absolue de sem_op est ajoutée à la valeur semadj du processus appelant pour le sémaphore spécifié.
*
Si semval est inférieur à la valeur absolue de sem_op et que (sem_flg &IPC_NOWAIT) est différent de zéro, semop() retourne immédiatement.
*
Si semval est inférieur à la valeur absolue de sem_op et que (sem_flg &IPC_NOWAIT) est 0, semop() incrémente le semncnt associé au sémaphore spécifié et suspend l'exécution du thread appelant jusqu'à ce que l'une des conditions suivantes se produise :
--
La valeur de semval devient supérieure ou égale à la valeur absolue de sem_op. Lorsque cela se produit, la valeur de semncnt associée au sémaphore spécifié est décrémentée, la valeur absolue de sem_op est soustraite de semval et, si (sem_flg &SEM_UNDO) est différent de zéro, la valeur absolue de sem_op est ajoutée à la valeur semadj du processus appelant pour le sémaphore spécifié.
--
Le semid pour lequel le thread appelant attend une action est supprimé du système. Lorsque cela se produit, errno est défini à [EIDRM] et -1 est retourné.
--
Le thread appelant reçoit un signal qui doit être intercepté. Lorsque cela se produit, la valeur de semncnt associée au sémaphore spécifié est décrémentée, et le thread appelant reprend son exécution de la manière prescrite dans sigaction().
2.
Si sem_op est un entier positif et que le processus appelant a l'autorisation de modification, la valeur de sem_op est ajoutée à semval et, si (sem_flg &SEM_UNDO) est différent de zéro, la valeur de sem_op est soustraite de la valeur semadj du processus appelant pour le sémaphore spécifié.
3.
Si sem_op est 0 et que le processus appelant a l'autorisation de lecture, l'une des actions suivantes se produit :
*
Si semval est 0, semop() retourne immédiatement.
*
Si semval est différent de zéro et que (sem_flg &IPC_NOWAIT) est différent de zéro, semop() retourne immédiatement.
*
Si semval est différent de zéro et que (sem_flg &IPC_NOWAIT) est 0, semop() incrémente le semzcnt associé au sémaphore spécifié et suspend l'exécution du thread appelant jusqu'à ce que l'une des conditions suivantes se produise :
--
La valeur de semval devient 0, auquel cas la valeur de semzcnt associée au sémaphore spécifié est décrémentée.
--
Le semid pour lequel le thread appelant attend une action est supprimé du système. Lorsque cela se produit, errno est défini à [EIDRM] et -1 est retourné.
--
Le thread appelant reçoit un signal qui doit être intercepté. Lorsque cela se produit, la valeur de semzcnt associée au sémaphore spécifié est décrémentée, et le thread appelant reprend son exécution de la manière prescrite dans sigaction().

En cas de succès, la valeur de sempid pour chaque sémaphore spécifié dans le tableau pointé par sops est définie à l'identifiant de processus du processus appelant. De plus, l'horodatage sem_otime est défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description Générale IPC.

VALEUR DE RETOUR

En cas de succès, semop() retourne 0 ; sinon, il retourne -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction semop() échoue si :

E2BIG
La valeur de nsops est supérieure au maximum imposé par le système.
EACCES
Une autorisation d'opération est refusée au processus appelant ; voir la Section 2.7, Communication Interprocessus XSI.
EAGAIN
L'opération entraînerait la suspension du processus appelant mais (sem_flg &IPC_NOWAIT) est différent de zéro.
EFBIG
La valeur de sem_num est supérieure ou égale au nombre de sémaphores dans l'ensemble associé à semid.
EIDRM
L'identifiant de sémaphore semid est supprimé du système.
EINTR
La fonction semop() a été interrompue par un signal.
EINVAL
La valeur de semid n'est pas un identifiant de sémaphore valide, ou le nombre de sémaphores individuels pour lesquels le processus appelant demande un SEM_UNDO dépasserait la limite imposée par le système.
ENOSPC
La limite sur le nombre de processus individuels demandant un SEM_UNDO serait dépassée.
ERANGE
Une opération entraînerait le dépassement d'un semval par rapport à la limite imposée par le système, ou une opération entraînerait le dépassement d'une valeur semadj par rapport à la limite imposée par le système.

EXEMPLES

Définir les valeurs dans les sémaphores

L'exemple suivant définit les valeurs des deux sémaphores associés à l'identifiant semid aux valeurs contenues dans le tableau sb.

#include <sys/sem.h>
...
int semid;
struct sembuf sb[2];
int nsops = 2;
int result;
/* Code pour initialiser semid. */
...
/* Ajuster la valeur du sémaphore dans le tableau de sémaphores semid. */
sb[0].sem_num = 0;
sb[0].sem_op = -1;
sb[0].sem_flg = SEM_UNDO | IPC_NOWAIT;
sb[1].sem_num = 1;
sb[1].sem_op = 1;
sb[1].sem_flg = 0;
result = semop(semid, sb, nsops);

Créer un identifiant de sémaphore

L'exemple suivant obtient une clé de sémaphore unique en utilisant la fonction ftok(), puis obtient un identifiant de sémaphore associé à cette clé en utilisant la fonction semget() (le premier appel teste également pour s'assurer que le sémaphore existe). Si le sémaphore n'existe pas, le programme le crée, comme le montre le deuxième appel à semget(). En créant le sémaphore pour le processus de mise en file d'attente, le programme tente de créer un sémaphore avec des permissions de lecture/écriture pour tous. Il utilise également l'indicateur IPC_EXCL, qui oblige semget() à échouer si le sémaphore existe déjà.

Après avoir créé le sémaphore, le programme utilise des appels à semctl() et semop() pour l'initialiser aux valeurs du tableau sbuf. Le nombre de processus pouvant s'exécuter simultanément sans mise en file d'attente est initialement défini à 2. Le dernier appel à semget() crée un identifiant de sémaphore qui pourra être utilisé plus tard dans le programme.

Les processus qui obtiennent semid sans le créer vérifient que sem_otime est non nul, pour s'assurer que le processus créateur a terminé l'initialisation semop().

Le dernier appel à semop() acquiert le sémaphore et attend qu'il soit libre ; l'option SEM_UNDO libère le sémaphore lorsque le processus se termine, attendant qu'il y ait moins de deux processus en cours d'exécution simultanément.

#include <stdio.h>
#include <sys/sem.h>
#include <sys/stat.h>
#include <errno.h>
#include <stdlib.h>
...
key_t semkey;
int semid;
struct sembuf sbuf;
union semun {
    int val;
    struct semid_ds *buf;
    unsigned short *array;
} arg;
struct semid_ds ds;
...
/* Obtenir une clé unique pour le sémaphore. */
if ((semkey = ftok("/tmp", 'a')) == (key_t) -1) {
    perror("Erreur IPC : ftok"); exit(1);
}
/* Obtenir l'identifiant du sémaphore associé à cette clé. */
if ((semid = semget(semkey, 0, 0)) == -1) {
    /* Le sémaphore n'existe pas - Créer. */
    if ((semid = semget(semkey, 1, IPC_CREAT | IPC_EXCL | S_IRUSR |
        S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH)) != -1)
    {
        /* Initialiser le sémaphore. */
        arg.val = 0;
        sbuf.sem_num = 0;
        sbuf.sem_op = 2;  /* C'est le nombre d'exécutions sans mise en file d'attente. */
        sbuf.sem_flg = 0;
        if (semctl(semid, 0, SETVAL, arg) == -1
            || semop(semid, &sbuf, 1) == -1) {
            perror("Erreur IPC : semop"); exit(1);
        }
    }
    else if (errno == EEXIST) {
        if ((semid = semget(semkey, 0, 0)) == -1) {
            perror("Erreur IPC 1 : semget"); exit(1);
        }
        goto check_init;
    }
    else {
        perror("Erreur IPC 2 : semget"); exit(1);
    }
}
else
{
    /* Vérifier que semid a terminé l'initialisation. */
    /* Une application peut utiliser une boucle de nouvelle tentative à ce stade plutôt
       que de quitter. */
    check_init:
    arg.buf = &ds;
    if (semctl(semid, 0, IPC_STAT, arg) < 0) {
        perror("Erreur IPC 3 : semctl"); exit(1);
    }
    if (ds.sem_otime == 0) {
        perror("Erreur IPC 4 : semctl"); exit(1);
    }
}
...
sbuf.sem_num = 0;
sbuf.sem_op = -1;
sbuf.sem_flg = SEM_UNDO;
if (semop(semid, &sbuf, 1) == -1) {
    perror("Erreur IPC : semop"); exit(1);
}

UTILISATION APPLICATIVE

L'extension POSIX Realtime définit des interfaces alternatives pour la communication interprocessus. Les développeurs d'applications qui ont besoin d'utiliser la communication interprocessus doivent concevoir leurs applications de manière à ce que les modules utilisant les routines de communication interprocessus décrites dans la Section 2.7, Communication Interprocessus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
