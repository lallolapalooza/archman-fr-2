DESCRIPTION

Gère diverses fonctions de port série.

CONTRÔLES DU PORT SERIE

Sur un sergensio client, ces fonctions définissent divers paramètres sur le port série. La modification n'est pas nécessairement immédiate, car elle peut devoir être envoyée sous forme de message. Si vous fournissez une fonction de fin (done), elle sera appelée une fois que l'opération de réglage sera terminée. L'opération de réglage peut échouer (le matériel peut ne pas la supporter, etc.), la fonction de fin signalera la valeur actuelle du paramètre.

Si vous souhaitez seulement obtenir la valeur actuelle du paramètre, vous pouvez passer zéro à toutes les fonctions ci-dessous et cela signalera uniquement la valeur dans la fonction de fin.

Il existe des fonctions bloquantes pour toutes ces opérations, voir sergensio_b_alloc(3) pour plus de détails. Toutes celles-ci sont non bloquantes.

sergensio_baud - Définit le débit en bauds à la valeur entière. Pas tous
les systèmes et matériels ne supportent tous les débits en bauds, vérifiez la fonction de fin pour savoir à quelle vitesse le débit en bauds a effectivement été réglé.
sergensio_datasize - Définit la taille des données, 5, 6, 7, 8 sont supportés.
sergensio_parity - Définit la valeur de parité
sergensio_stopbits - Définit le nombre de bits d'arrêt, soit 1 ou 2.
sergensio_flowcontrol - Définit le type de contrôle de flux sortant.
sergensio_iflowcontrol - Définit le type de contrôle de flux entrant.
sergensio_sbreak - Active ou désactive le signal de rupture (break).
sergensio_dtr - Définit la valeur DTR.
sergensio_rts - Définit la valeur RTS.

sergensio_send_break - Envoie un signal de rupture (activé pendant un moment puis désactivé) sur la ligne.

Sur un serveur gensio, les fonctions ci-dessus sont utilisées pour répondre à un événement qui définit la valeur. Passez la valeur réelle. La valeur de fin (done) est ignorée sur le serveur.

sergensio_signature - Cette fonction est utilisée pour définir un marqueur (signature) sur la ligne série, souvent utilisé pour signaler le début d'une nouvelle trame ou une condition spécifique. La fonction de fin est appelée lorsque la signature a été envoyée ou qu'une erreur s'est produite.

sergensio_linestate - Lit l'état actuel des lignes de contrôle série et des indicateurs d'erreurs. Renvoie un masque de bits indiquant les conditions actives.

sergensio_modemstate - Lit l'état actuel des signaux du modem (CTS, DSR, RI, CD) et des changements d'état. Renvoie un masque de bits indiquant les conditions actives ou les changements d'état.

sergensio_flowcontrol_state - Active ou désactive le contrôle de flux matériel basé sur les signaux DTR/DSR.

sergensio_flush - Vide les tampons de réception et/ou d'émission du port série.

Note: Les fonctions de type `_b_` (non montrées ici) sont des versions bloquantes de ces fonctions.

DESCRIPTION

Ces fonctions sont utilisées pour le contrôle de bas niveau des ports série.

DÉBIT EN BAUD

sergensio_baud - Définit le débit en bauds du port série.
La valeur 0 peut ou non renvoyer la valeur actuelle.

CONTRÔLE DU PORT SÉRIE

Pour les ports série du côté du modem (comme ipmisol), il existe un ensemble différent de commandes de contrôle. Les commandes ci-dessus peuvent ou non fonctionner.

Utilisez plutôt les commandes suivantes. Notez que passer 0 à ces commandes peut ou peut ne pas renvoyer la valeur actuelle, elles peuvent renvoyer une erreur.

sergensio_cts - Définit la valeur CTS sur automatique (gérée par le matériel) ou
désactivée (indique à l'autre extrémité de ne pas envoyer de données).
sergensio_dcd_rts - Définit les valeurs DCD et RTS à activer ou désactiver.
sergensio_ri - Définit la valeur de l'indicateur d'appel (ring indicator) à activer ou désactiver.

SIGNATURE

Bien que ne faisant pas vraiment partie du contrôle du port série, la spécification telnet RFC2217 contient une signature qui peut être utilisée pour identifier le serveur. La fonction sergensio_signature récupère la signature (côté client) ou répond à une demande de signature (côté serveur).

FONCTIONS D'ÉTAT

Côté client, les fonctions d'état du port série définissent les informations d'état que l'utilisateur souhaite recevoir. Par exemple, si l'utilisateur souhaite connaître les erreurs de parité, il peut définir SERGENSIO_LINESTATE_OVERRUN_ERR dans linestate et il recevra des événements linestate avec des erreurs de parité.

Côté serveur, elles sont utilisées pour signaler les informations d'état. Le gensio lui-même ne suit pas ce que le client a demandé, cela relève du code du serveur lui-même.

sergensio_linestate - Diverses informations (principalement des erreurs) sur ce qui
s'est passé sur la ligne série. Tous les sergensios ne prennent pas en charge la demande de ces informations.
sergensio_modemstate - CTS, DSR, RI et CD sur le port série.
Côté client, l'utilisateur doit définir les valeurs qu'il souhaite recevoir avec les valeurs _CHANGED correspondantes. Les autres valeurs sont ignorées côté client. Côté serveur, cela est utilisé pour signaler les valeurs actuelles et les valeurs qui ont changé pour provoquer le rapport.

AUTRES CONTRÔLES DE PORT SÉRIE

Ces fonctions effectuent diverses autres fonctions sur un port série.

sergensio_flowcontrol_state - Indique à l'extrémité distante du port série d'arrêter
d'envoyer en utilisant le contrôle de flux.
sergensio_flush - Vide toutes les données des tampons vers le port série.
sergensio_send_break - Envoie un court signal de pause sur le port série.
La longueur dépend de l'implémentation.

VALEURS DE RETOUR

Zéro est renvoyé en cas de succès, ou une erreur gensio en cas d'échec.
