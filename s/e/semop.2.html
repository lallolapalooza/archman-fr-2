semop(2) Manuel des appels système semop(2)

NOM

semop, semtimedop - opérations sur les sémaphores System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);
int semtimedop(int semid, struct sembuf *sops, size_t nsops,
               const struct timespec *_Nullable timeout);
Macros de test de fonctionnalités requises pour glibc (voir feature_test_macros(7)) :

semtimedop() :

    _GNU_SOURCE

DESCRIPTION

Chaque sémaphore dans un ensemble de sémaphores System V a les valeurs associées suivantes :


unsigned short  semval;   /* valeur du sémaphore */
unsigned short  semzcnt;  /* # attendant zéro */
unsigned short  semncnt;  /* # attendant une augmentation */
pid_t           sempid;   /* PID du processus qui a dernièrement
                             modifié la valeur du sémaphore */

semop() effectue des opérations sur des sémaphores sélectionnés dans l'ensemble indiqué par semid. Chacun des nsops éléments du tableau pointé par sops est une structure qui spécifie une opération à effectuer sur un seul sémaphore. Les éléments de cette structure sont de type struct sembuf, contenant les membres suivants :


unsigned short sem_num;  /* numéro du sémaphore */
short          sem_op;   /* opération sur le sémaphore */
short          sem_flg;  /* drapeaux d'opération */

Les drapeaux reconnus dans sem_flg sont IPC_NOWAIT et SEM_UNDO. Si une opération spécifie SEM_UNDO, elle sera automatiquement annulée lorsque le processus se terminera.

L'ensemble des opérations contenues dans sops est effectué dans l'ordre du tableau et de manière atomique, c'est-à-dire que les opérations sont effectuées soit comme une unité complète, soit pas du tout. Le comportement de l'appel système si toutes les opérations ne peuvent pas être effectuées immédiatement dépend de la présence du drapeau IPC_NOWAIT dans les champs individuels sem_flg, comme indiqué ci-dessous.

Chaque opération est effectuée sur le sémaphore numéro sem_num de l'ensemble de sémaphores, où le premier sémaphore de l'ensemble est numéroté 0. Il existe trois types d'opérations, distingués par la valeur de sem_op.

Si sem_op est un entier positif, l'opération ajoute cette valeur à la valeur du sémaphore (semval). De plus, si SEM_UNDO est spécifié pour cette opération, le système soustrait la valeur sem_op de la valeur d'ajustement du sémaphore (semadj) pour ce sémaphore. Cette opération peut toujours se dérouler ; elle ne force jamais un thread à attendre. Le processus appelant doit avoir l'autorisation de modification sur l'ensemble de sémaphores.

Si sem_op est zéro, le processus doit avoir l'autorisation de lecture sur l'ensemble de sémaphores. Il s'agit d'une opération "attendre zéro" : si semval est zéro, l'opération peut se dérouler immédiatement. Sinon, si IPC_NOWAIT est spécifié dans sem_flg, semop() échoue avec errno défini sur EAGAIN (et aucune des opérations dans sops n'est effectuée). Sinon, semzcnt (le compteur des threads attendant que la valeur de ce sémaphore devienne zéro) est incrémenté de un et le thread se met en veille jusqu'à ce que l'une des conditions suivantes se produise :

•
semval devient 0, auquel cas la valeur de semzcnt est décrémentée.
•
L'ensemble de sémaphores est supprimé : semop() échoue, avec errno défini sur EIDRM.
•
Le thread appelant intercepte un signal : la valeur de semzcnt est décrémentée et semop() échoue, avec errno défini sur EINTR.

Si sem_op est inférieur à zéro, le processus doit avoir l'autorisation de modification sur l'ensemble de sémaphores. Si semval est supérieur ou égal à la valeur absolue de sem_op, l'opération peut se dérouler immédiatement : la valeur absolue de sem_op est soustraite de semval, et, si SEM_UNDO est spécifié pour cette opération, le système ajoute la valeur absolue de sem_op à la valeur d'ajustement du sémaphore (semadj) pour ce sémaphore. Si la valeur absolue de sem_op est supérieure à semval, et que IPC_NOWAIT est spécifié dans sem_flg, semop() échoue, avec errno défini sur EAGAIN (et aucune des opérations dans sops n'est effectuée). Sinon, semncnt (le compteur des threads attendant que la valeur de ce sémaphore augmente) est incrémenté de un et le thread se met en veille jusqu'à ce que l'une des conditions suivantes se produise :

•
semval devient supérieur ou égal à la valeur absolue de sem_op : l'opération se déroule alors, comme décrit ci-dessus.
•
L'ensemble de sémaphores est supprimé du système : semop() échoue, avec errno défini sur EIDRM.
•
Le thread appelant intercepte un signal : la valeur de semncnt est décrémentée et semop() échoue, avec errno défini sur EINTR.

En cas de succès, la valeur sempid pour chaque sémaphore spécifié dans le tableau pointé par sops est définie sur l'identifiant du processus appelant. De plus, sem_otime est défini à l'heure actuelle.

semtimedop()

semtimedop() se comporte de manière identique à semop(), sauf que dans les cas où le thread appelant se mettrait en veille, la durée de cette veille est limitée par la durée écoulée spécifiée par la structure timespec dont l'adresse est passée dans l'argument timeout. (Cet intervalle de veille sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle peut dépasser d'une petite quantité.) Si la limite de temps spécifiée est atteinte, semtimedop() échoue avec errno défini sur EAGAIN (et aucune des opérations dans sops n'est effectuée). Si l'argument timeout est NULL, alors semtimedop() se comporte exactement comme semop().

Notez que si semtimedop() est interrompu par un signal, provoquant l'échec de l'appel avec l'erreur EINTR, le contenu de timeout reste inchangé.

VALEUR DE RETOUR

En cas de succès, semop() et semtimedop() retournent 0. En cas d'échec, ils retournent -1 et définissent errno pour indiquer l'erreur.

ERREURS

E2BIG
L'argument nsops est supérieur à SEMOPM, le nombre maximum d'opérations autorisées par appel système.
EACCES
Le processus appelant n'a pas les permissions requises pour effectuer les opérations de sémaphore spécifiées, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EAGAIN
Une opération n'a pas pu se dérouler immédiatement et soit IPC_NOWAIT a été spécifié dans sem_flg, soit la limite de temps spécifiée dans timeout a expiré.
EFAULT
Une adresse spécifiée dans l'argument sops ou timeout n'est pas accessible.
EFBIG
Pour une opération, la valeur de sem_num est inférieure à 0 ou supérieure ou égale au nombre de sémaphores dans l'ensemble.
EIDRM
L'ensemble de sémaphores a été supprimé.
EINTR
Pendant que le thread était bloqué dans cet appel système, il a intercepté un signal ; voir signal(7).
EINVAL
L'ensemble de sémaphores n'existe pas, ou semid est inférieur à zéro, ou nsops a une valeur non positive.
ENOMEM
Le champ sem_flg d'une opération spécifiait SEM_UNDO et le système n'a pas assez de mé

semop(2) — Manuel Linux (fr)

NOM

semop — Opérations sur les sémaphores SysV

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/sem.h>

int semop(int semid, struct sembuf *sops, size_t nsops);

DESCRIPTION

La fonction semop() effectue des opérations sur des sémaphores SysV. Elle exécute une séquence d'opérations sur les sémaphores spécifiée par le tableau sops. Ce tableau contient des structures sembuf, chacune définissant une opération sur un sémaphore particulier dans un ensemble de sémaphores.

Le tableau sops contient nsops éléments. Chaque élément sembuf a la forme suivante :

struct sembuf {
    ushort_t sem_num;       /* Index du sémaphore dans l'ensemble */
    short    sem_op;        /* Opération sur le sémaphore */
    short    sem_flg;       /* Indicateurs d'opération */
};

Le champ sem_num spécifie le sémaphore sur lequel opérer (les sémaphores sont numérotés à partir de 0).

Le champ sem_op spécifie l'opération à effectuer :

  • Si sem_op est une valeur positive, cette valeur est ajoutée à la valeur actuelle du sémaphore.
  • Si sem_op est zéro, cela signifie que le processus attend que la valeur du sémaphore devienne zéro. Le processus ne continue que lorsque la valeur du sémaphore est zéro.
  • Si sem_op est une valeur négative, elle représente une soustraction de la valeur du sémaphore. Le processus ne continue que lorsque la valeur absolue de sem_op est inférieure ou égale à la valeur actuelle du sémaphore. Si l'opération réussit, la valeur absolue de sem_op est soustraite de la valeur actuelle du sémaphore.

Le champ sem_flg peut être utilisé pour modifier le comportement des opérations :

  • SEM_UNDO: Cette option crée une entrée "undo" pour l'opération. Lorsque le processus se termine, la valeur du sémaphore est automatiquement ajustée pour annuler l'effet de cette opération. Si la valeur du sémaphore devient négative suite à cet ajustement, l'opération est bloquée jusqu'à ce que le sémaphore soit disponible. Le processus est alors terminé. Les ajustements de sortie sont appliqués après que les semadj aient été traités. Si une opération spécifie SEM_UNDO et que l'opération attendue (par exemple, attente d'une valeur nulle ou décrémentation) ne peut être satisfaite immédiatement, la fonction semop() échouera avec EAGAIN si IPC_NOWAIT est également spécifié dans sem_flg.
  • IPC_NOWAIT: Si l'opération ne peut être effectuée immédiatement (c'est-à-dire si un sémaphore est négatif lorsque sem_op est négatif, ou si le sémaphore est zéro et que sem_op est zéro), semop() échoue immédiatement avec l'erreur EAGAIN.

Les opérations spécifiées dans le tableau sops sont exécutées de manière atomique. Si toutes les opérations peuvent être effectuées, semop() retourne 0. Si une ou plusieurs opérations ne peuvent pas être effectuées immédiatement, et que IPC_NOWAIT n'est pas spécifié, le processus est mis en sommeil jusqu'à ce que toutes les opérations puissent être effectuées.

Les appels semop() ne sont jamais automatiquement redémarrés après avoir été interrompus par un gestionnaire de signaux, quelle que soit la valeur du drapeau SA_RESTART lors de l'établissement du gestionnaire de signaux.

Les structures sem_undo d'un processus ne sont pas héritées par l'enfant produit par fork(2), mais elles sont héritées lors d'un appel système execve(2).

La valeur sem_op, lorsqu'elle est positive, ne peut pas dépasser SEMVMX. L'opération sem_op + semval ne peut pas non plus dépasser SEMVMX.

Les limites spécifiques à l'implémentation pour les opérations de sémaphores sont définies par les constantes suivantes :

SEMVMX
La valeur maximale autorisée pour semval (dépend de l'implémentation, généralement 32767).
SEMOPM
Le nombre maximal d'opérations autorisées pour un seul appel semop(). Sur Linux, la valeur par défaut a été portée de 32 (avant Linux 3.19) à 500 (depuis Linux 3.19). Cette limite peut être lue et modifiée via le troisième champ de /proc/sys/kernel/sem.

VALEUR DE RETOUR

En cas de succès, semop() retourne 0. En cas d'erreur, il retourne -1 et errno est définie pour indiquer l'erreur.

ERREURS

EACCES
L'accès demandé au tableau de sémaphores est refusé. Cela peut se produire si le processus n'a pas les permissions nécessaires pour lire ou écrire dans le tableau de sémaphores.
EAGAIN
L'opération ne peut pas être effectuée immédiatement et l'indicateur IPC_NOWAIT a été spécifié.
ECHILD
L'opération spécifie SEM_UNDO, mais le processus fils de fork(2) n'hérite pas des structures d'ajustement de sortie. Cette erreur ne devrait pas se produire avec la définition actuelle de SEM_UNDO.
EINVAL
La valeur de semid n'est pas valide, ou le tableau de sémaphores a été supprimé.
EINTR
L'opération a été interrompue par un signal. Étant donné que semop() n'est pas redémarré automatiquement, cette erreur se produit rarement.
EIO
Une erreur d'E/S s'est produite lors de la gestion de la structure d'ajustement de sortie (sem_undo).
ENOSPC
L'espace disque est insuffisant pour allouer la structure d'undo.
ERANGE
Pour une opération donnée, sem_op + semval est supérieur à SEMVMX, la valeur maximale dépendante de l'implémentation pour semval.

NORMES

POSIX.1-2024.

VERSIONS

Linux 2.5.52 (rétroporté dans Linux 2.4.22), glibc 2.3.3. POSIX.1-2001, SVr4.

NOTES

Les structures sem_undo d'un processus ne sont pas héritées par l'enfant produit par fork(2), mais elles sont héritées lors d'un appel système execve(2).

semop() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signaux, indépendamment du réglage du drapeau SA_RESTART lors de l'établissement d'un gestionnaire de signaux.

Une valeur d'ajustement de sémaphore (semadj) est un entier par processus et par sémaphore qui est la somme négativée de toutes les opérations effectuées sur un sémaphore spécifiant le drapeau SEM_UNDO. Chaque processus a une liste de valeurs semadj, une valeur pour chaque sémaphore sur lequel il a opéré en utilisant SEM_UNDO. Lorsqu'un processus se termine, chacune de ses valeurs semadj par sémaphore est ajoutée au sémaphore correspondant, annulant ainsi l'effet des opérations de ce processus sur le sémaphore (mais voir BUGS ci-dessous). Lorsque la valeur d'un sémaphore est directement définie à l'aide de la requête SETVAL ou SETALL pour semctl(2), les valeurs semadj correspondantes dans tous les processus sont effacées. Le drapeau clone(2) CLONE_SYSVSEM permet à plusieurs processus de partager une liste semadj ; voir clone(2) pour plus de détails.

Les valeurs semval, sempid, semzcnt et semnct d'un sémaphore peuvent toutes être récupérées à l'aide des appels semctl(2) appropriés.

Limites de sémaphores

Les limites suivantes sur les ressources des ensembles de sémaphores affectent l'appel semop() :

SEMOPM
Nombre maximal d'opérations autorisées pour un seul appel semop(). Avant Linux 3.19, la valeur par défaut pour cette limite était de 32. Depuis Linux 3.19, la valeur par défaut est de 500. Sous Linux, cette limite peut être lue et modifiée via le troisième champ de /proc/sys/kernel/sem. Remarque: cette limite ne doit pas dépasser 1000, en raison du risque que semop() échoue en raison de la fragmentation de la mémoire du noyau lors de l'allocation de mémoire pour copier le tableau sops.
SEMVMX
Valeur maximale autorisée pour semval : dépend de l'implémentation (32767).

L'implémentation n'a pas de limites intrinsèques pour la valeur maximale d'ajustement à la sortie (SEMAEM), le nombre maximal de structures d'undo au niveau du système (SEMMNU) et les paramètres système du nombre maximal d'entrées d'undo par processus.

BOGUES

Lorsqu'un processus se termine, son ensemble de structures semadj associées est utilisé pour annuler l'effet de toutes les opérations de sémaphore qu'il a effectuées avec le drapeau SEM_UNDO. Cela pose une difficulté : si l'un de ces ajustements de sémaphore (ou plusieurs) devait entraîner une tentative de diminution de la valeur d'un sémaphore en dessous de zéro, que devrait faire une implémentation ? Une approche possible serait de bloquer jusqu'à ce que tous les ajustements de sémaphore puissent être effectués. Ceci est cependant indésirable car cela pourrait forcer la terminaison du processus à bloquer pendant des périodes arbitrairement longues. Une autre possibilité est que ces ajustements de sémaphore soient complètement ignorés (un peu comme un échec lorsque IPC_NOWAIT est spécifié pour une opération sur un sémaphore). Linux adopte une troisième approche : diminuer la valeur du sémaphore autant que possible (c'est-à-dire à zéro) et permettre à la terminaison du processus de se poursuivre immédiatement.

Dans Linux 2.6.x, x <= 10, il existe un bogue qui, dans certaines circonstances, empêche un thread attendant que la valeur d'un sémaphore devienne zéro d'être réveillé lorsque la valeur devient effectivement zéro. Ce bogue est corrigé dans Linux 2.6.11.

EXEMPLES

Le segment de code suivant utilise semop() pour attendre atomiquement que la valeur du sémaphore 0 devienne zéro, puis incrémente la valeur du sémaphore de un.


struct sembuf sops[2];
int semid;
/* Code pour initialiser semid omis */
sops[0].sem_num = 0;        /* Opérer sur le sémaphore 0 */
sops[0].sem_op = 0;         /* Attendre que la valeur soit égale à 0 */
sops[0].sem_flg = 0;
sops[1].sem_num = 0;        /* Opérer sur le sémaphore 0 */
sops[1].sem_op = 1;         /* Incrémenter la valeur de un */
sops[1].sem_flg = 0;
if (semop(semid, sops, 2) == -1) {
    perror("semop");
    exit(EXIT_FAILURE);
}

Un autre exemple d'utilisation de semop() se trouve dans shmop(2).
