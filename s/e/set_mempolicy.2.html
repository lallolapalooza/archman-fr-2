set_mempolicy(2) Manuel des appels système set_mempolicy(2)

NOM

set_mempolicy - définir la politique mémoire NUMA par défaut pour un thread et ses enfants

BIBLIOTHEQUE

Bibliothèque de politique NUMA (mémoire vive à accès non uniforme) (libnuma, -lnuma)

SYNTAXE

#include <numaif.h>
long set_mempolicy(int mode, const unsigned long *nodemask,
                   unsigned long maxnode);

DESCRIPTION

set_mempolicy() définit la politique mémoire NUMA du thread appelant, composée d'un mode de politique et de zéro ou plusieurs nœuds, aux valeurs spécifiées par les arguments mode, nodemask et maxnode.

Une machine NUMA possède différents contrôleurs mémoire avec des distances variables par rapport à des CPU spécifiques. La politique mémoire définit à partir de quel nœud la mémoire est allouée pour le thread.

Cet appel système définit la politique par défaut pour le thread. La politique du thread régit l'allocation des pages dans l'espace d'adressage du processus en dehors des plages mémoire contrôlées par une politique plus spécifique définie par mbind(2). La politique par défaut du thread contrôle également l'allocation de toutes les pages pour les fichiers mappés en mémoire à l'aide de l'appel mmap(2) avec le drapeau MAP_PRIVATE et qui sont uniquement lues (chargées) par le thread, ainsi que pour les fichiers mappés en mémoire à l'aide de l'appel mmap(2) avec le drapeau MAP_SHARED, quel que soit le type d'accès. La politique n'est appliquée que lorsqu'une nouvelle page est allouée pour le thread. Pour la mémoire anonyme, cela se produit lorsque la page est touchée pour la première fois par le thread.

L'argument mode doit spécifier l'un des modes MPOL_DEFAULT, MPOL_BIND, MPOL_INTERLEAVE, MPOL_WEIGHTED_INTERLEAVE, MPOL_PREFERRED, MPOL_PREFERRED_MANY, ou MPOL_LOCAL (qui sont décrits en détail ci-dessous). Tous les modes sauf MPOL_DEFAULT exigent que l'appelant spécifie le ou les nœuds auxquels le mode s'applique, via l'argument nodemask.

L'argument mode peut également inclure un drapeau de mode optionnel. Les drapeaux de mode pris en charge sont :

MPOL_F_NUMA_BALANCING (depuis Linux 5.12)
Lorsque mode est MPOL_BIND, active l'équilibrage NUMA du noyau pour la tâche si celui-ci est pris en charge par le noyau. Si le drapeau n'est pas pris en charge par le noyau, ou s'il est utilisé avec un mode autre que MPOL_BIND, -1 est retourné et errno est défini à EINVAL.
MPOL_F_RELATIVE_NODES (depuis Linux 2.6.26)
Un nodemask non vide spécifie des ID de nœuds relatifs à l'ensemble des ID de nœuds autorisés par le cpuset actuel du processus.
MPOL_F_STATIC_NODES (depuis Linux 2.6.26)
Un nodemask non vide spécifie des ID de nœuds physiques. Linux ne réattribuera pas le nodemask lorsque le processus sera déplacé dans un contexte cpuset différent, ni lorsque l'ensemble des nœuds autorisés par le contexte cpuset actuel du processus changera.

nodemask pointe vers un masque de bits d'ID de nœuds contenant jusqu'à maxnode bits. La taille du masque de bits est arrondie au multiple supérieur de sizeof(unsigned long), mais le noyau utilisera uniquement les bits jusqu'à maxnode. Une valeur NULL pour nodemask ou une valeur maxnode de zéro spécifie l'ensemble vide de nœuds. Si la valeur de maxnode est zéro, l'argument nodemask est ignoré.

Lorsqu'un nodemask est requis, il doit contenir au moins un nœud qui est en ligne, autorisé par le contexte cpuset actuel du processus, (sauf si le drapeau de mode MPOL_F_STATIC_NODES est spécifié), et qui contient de la mémoire. Si MPOL_F_STATIC_NODES est défini dans mode et qu'un nodemask requis ne contient aucun nœud autorisé par le contexte cpuset actuel du processus, la politique mémoire revient à l'allocation locale. Cela remplace effectivement la politique spécifiée jusqu'à ce que le contexte cpuset du processus inclue un ou plusieurs des nœuds spécifiés par nodemask.

L'argument mode doit inclure l'une des valeurs suivantes :

MPOL_DEFAULT
Ce mode spécifie que toute politique mémoire de thread non par défaut doit être supprimée, de sorte que la politique mémoire "revienne" à la politique par défaut du système. La politique par défaut du système est l'"allocation locale" – c'est-à-dire, allouer la mémoire sur le nœud du CPU qui a déclenché l'allocation. nodemask doit être spécifié comme NULL. Si le "nœud local" ne contient pas de mémoire libre, le système tentera d'allouer de la mémoire à partir d'un nœud "proche".
MPOL_BIND
Ce mode définit une politique stricte qui limite l'allocation mémoire aux nœuds spécifiés dans nodemask. Si nodemask spécifie plus d'un nœud, les allocations de pages proviendront d'abord du nœud ayant le plus petit ID numérique, jusqu'à ce que ce nœud ne contienne plus de mémoire libre. Les allocations proviendront ensuite du nœud ayant l'ID le plus proche spécifié dans nodemask, et ainsi de suite, jusqu'à ce qu'aucun des nœuds spécifiés ne contienne de mémoire libre. Les pages ne seront pas allouées à partir de nœuds non spécifiés dans le nodemask.
MPOL_INTERLEAVE
Ce mode entrelace les allocations de pages sur les nœuds spécifiés dans nodemask dans l'ordre numérique des ID de nœuds. Cela optimise la bande passante plutôt que la latence en répartissant les pages et les accès mémoire à ces pages sur plusieurs nœuds. Cependant, les accès à une page individuelle resteront limités à la bande passante mémoire d'un seul nœud.
MPOL_WEIGHTED_INTERLEAVE (depuis Linux 6.9)
Ce mode entrelace les allocations de pages sur les nœuds spécifiés dans nodemask selon les poids définis dans /sys/kernel/mm/mempolicy/weighted_interleave. Par exemple, si les bits 0, 2 et 5 sont définis dans nodemask, et que le contenu de /sys/kernel/mm/mempolicy/weighted_interleave/node0, /sys/.../node2, et /sys/.../node5 sont 4, 7 et 9 respectivement, alors les pages dans cette région seront allouées sur les nœuds 0, 2 et 5 dans un rapport de 4:7:9.
MPOL_PREFERRED
Ce mode définit le nœud préféré pour l'allocation. Le noyau essaiera d'allouer des pages à partir de ce nœud en premier et se rabattra sur les nœuds "proches" si le nœud préféré manque de mémoire libre. Si nodemask spécifie plus d'un ID de nœud, le premier nœud du masque sera sélectionné comme nœud préféré. Si les arguments nodemask et maxnode spécifient l'ensemble vide, alors la politique spécifie l'"allocation locale" (similaire à la politique par défaut du système discutée ci-dessus).
MPOL_PREFERRED_MANY (depuis Linux 5.15)
Ce mode spécifie une préférence pour les nœuds à partir desquels le noyau essaiera d'allouer. Il diffère de MPOL_PREFERRED en ce qu'il accepte un ensemble de nœuds plutôt qu'un seul nœud. Cette politique est conçue pour bénéficier aux allocations de pages où des types de mémoire spécifiques (c'est-à-dire, mémoire non volatile, à large bande passante, ou mémoire accélératrice) sont plus importants que l'emplacement du nœud.
MPOL_LOCAL (depuis Linux 3.8)
Ce mode spécifie l'"allocation locale" ; la mémoire est allouée sur le nœud du CPU qui a déclenché l'allocation (le "nœud local"). Les arguments nodemask et maxnode doivent spécifier l'ensemble vide. Si le "nœud local" manque de mémoire libre, le noyau tentera d'allouer de la mémoire à partir d'autres nœuds. Le noyau allouera de la mémoire à partir du "nœud local" tant que de la mémoire sera disponible pour ce nœud. Si le "nœud local" n'est pas autorisé par le contexte cpuset actuel du processus, le noyau tentera d'allouer de la mémoire à partir d'autres nœuds. Le noyau allouera de la mémoire à partir du "nœud local" chaque fois qu'il sera autorisé par le contexte cpuset actuel du processus.

set_mempolicy(2) — set memory policy

NAME

set_mempolicy — set memory policy for a memory range

LIBRARY

Memory Access Control Library (libnuma), which may be installed by your package manager.

SYNOPSIS

#include <numaif.h>

long set_mempolicy(
    int mode,
    const unsigned long *nodemask,
    unsigned long maxnode
);

DESCRIPTION

The set_mempolicy() system call sets the NUMA memory policy for the calling thread. This policy defines where memory allocated for the thread should be allocated with respect to NUMA nodes.

The arguments are:

mode
Specifies the memory allocation policy to be used. The following values are recognized:
  • MPOL_DEFAULT

    Revert to the default memory policy. This policy typically means that memory is allocated from the node that the process is running on (local allocation).

  • MPOL_BIND

    Bind memory allocations to a specific set of nodes. Memory will only be allocated on the nodes specified in nodemask.

  • MPOL_INTERLEAVE

    Interleave memory allocations across a set of nodes. Memory is allocated in a round-robin fashion on the nodes specified in nodemask.

  • MPOL_LOCAL

    Allocate memory only on the local node (the node where the process is currently running).

  • MPOL_PREFERRED

    Preferably allocate memory on one of the nodes specified in nodemask. If the preferred node is not available, memory is allocated on the local node.

The mode can be OR-ed with the following flags:

  • MPOL_F_STATIC_NODES

    The nodes specified in nodemask are static and will not change. This can be used to optimize policy lookups by the kernel.

  • MPOL_F_RELATIVE_NODES

    The nodes specified in nodemask are relative to the nodes allowed by the process's current cpuset context. This means that the effective node mask is the intersection of the nodes in nodemask and the nodes in the process's cpuset.

  • MPOL_F_NUMA_BALANCING

    Enable NUMA balancing for the memory range. This flag can only be used with MPOL_BIND.

nodemask
A pointer to a bitmask specifying the NUMA nodes that the policy applies to. The bits in the mask correspond to node IDs. If MPOL_F_RELATIVE_NODES is used, the node IDs are relative to the process's cpuset.
maxnode
Specifies the highest node ID in the nodemask plus one. This argument is used to determine the size of the bitmask. It should be set to the number of bits to check in the nodemask, which should not exceed a page size.

The memory policy is inherited across an execve(2), and is inherited by child threads created using fork(2) or clone(2).

RETURN VALUE

On success, set_mempolicy() returns 0; on error, -1 is returned and errno is set to indicate the error.

ERRORS

EFAULT
Part of all of the memory range specified by nodemask and maxnode points outside your accessible address space.
EINVAL
mode is invalid. Or, mode is MPOL_DEFAULT and nodemask is nonempty, or mode is MPOL_BIND or MPOL_INTERLEAVE and nodemask is empty. Or, maxnode specifies more than a page worth of bits. Or, nodemask specifies one or more node IDs that are greater than the maximum supported node ID. Or, none of the node IDs specified by nodemask are on-line and allowed by the process's current cpuset context, or none of the specified nodes contain memory. Or, the mode argument specified both MPOL_F_STATIC_NODES and MPOL_F_RELATIVE_NODES. Or, the MPOL_F_NUMA_BALANCING isn't supported by the kernel, or is used with mode other than MPOL_BIND.
ENOMEM
Insufficient kernel memory was available.

STANDARDS

Linux.

HISTORY

Linux 2.6.7.

NOTES

Memory policy is not remembered if the page is swapped out. When such a page is paged back in, it will use the policy of the thread or memory range that is in effect at the time the page is allocated.

For information on library support, see numa(7).

SEE ALSO

get_mempolicy(2), getcpu(2), mbind(2), mmap(2), numa(3), cpuset(7), numa(7), numactl(8)
