SENDMAIL(1) Manuel des commandes générales SENDMAIL(1)

NOM

sendmail - Interface de compatibilité Postfix avec Sendmail

SYNTAXE

sendmail [option ...] [destinataire ...]
mailq
sendmail -bp
newaliases
sendmail -I

DESCRIPTION


La commande sendmail(1) de Postfix implémente l'interface de compatibilité de Postfix avec Sendmail. Par souci de compatibilité avec les applications existantes, certaines options de ligne de commande de Sendmail sont reconnues mais ignorées silencieusement.

Par défaut, sendmail(1) de Postfix lit un message depuis l'entrée standard jusqu'à EOF ou jusqu'à ce qu'il lise une ligne contenant uniquement un caractère ., et organise sa livraison. sendmail(1) de Postfix s'appuie sur la commande postdrop(1) pour créer un fichier de file d'attente dans le répertoire maildrop.

Des alias de commande spécifiques sont fournis pour d'autres modes de fonctionnement courants :

mailq
Liste la file d'attente de messagerie. Chaque entrée affiche l'identifiant du fichier de file d'attente, la taille du message, l'heure d'arrivée, l'expéditeur et les destinataires qui doivent encore être livrés. Si un message n'a pas pu être livré lors de la dernière tentative, la raison de l'échec est affichée. La chaîne d'identifiant de file d'attente est suivie d'un caractère de statut optionnel :
*
Le message est dans la file d'attente active, c'est-à-dire que le message est sélectionné pour la livraison.
!
Le message est dans la file d'attente hold (en attente), c'est-à-dire qu'aucune nouvelle tentative de livraison ne sera effectuée tant que le courrier ne sera pas retiré de la file d'attente.
#
Le message est forcé à expirer. Voir les options -e ou -f de postsuper(1).
Ce mode de fonctionnement est implémenté en exécutant la commande postqueue(1).
newaliases
Initialise la base de données des alias. Si aucun fichier d'entrée n'est spécifié (avec l'option -oA, voir ci-dessous), le programme traite les fichiers spécifiés avec le paramètre de configuration alias_database. Si aucun type de base de données d'alias n'est spécifié, le programme utilise le type spécifié avec le paramètre de configuration default_database_type. Ce mode de fonctionnement est implémenté en exécutant la commande postalias(1).

Remarque : il peut s'écouler une minute ou deux avant qu'une mise à jour de la base de données des alias ne devienne visible. Utilisez la commande « postfix reload » pour éliminer ce délai.

Ces fonctionnalités et d'autres peuvent être sélectionnées en spécifiant la combinaison appropriée d'options de ligne de commande. Certaines fonctionnalités sont contrôlées par des paramètres dans le fichier de configuration main.cf.

Les options suivantes sont reconnues :

-Am (ignorée)
-Ac (ignorée)
Sendmail de Postfix utilise le même fichier de configuration, que le message soit une soumission initiale ou non.
-B type_corps
Le type MIME du corps du message : 7BIT ou 8BITMIME.
-bd
Passe en mode démon. Ce mode de fonctionnement est implémenté en exécutant la commande « postfix start ».
-bh (ignorée)
-bH (ignorée)
Postfix n'a pas de base de données persistante sur l'état des hôtes.
-bi
Initialise la base de données des alias. Voir la commande newaliases ci-dessus.
-bl
Passe en mode démon. Pour accepter uniquement les connexions locales comme avec l'option -bl de Sendmail, spécifiez « inet_interfaces = loopback » dans le fichier de configuration main.cf de Postfix.
-bm
Lit le courrier depuis l'entrée standard et organise sa livraison. C'est le mode de fonctionnement par défaut.
-bp
Liste la file d'attente de messagerie. Voir la commande mailq ci-dessus.
-bs
Mode serveur SMTP autonome. Lit les commandes SMTP depuis l'entrée standard et écrit les réponses sur la sortie standard. En mode serveur SMTP autonome, le relais de messagerie et les autres contrôles d'accès sont désactivés par défaut. Pour les activer, exécutez le processus en tant qu'utilisateur mail_owner.

Ce mode de fonctionnement est implémenté en exécutant le démon smtpd(8).

-bv
Ne collecte ni ne livre de message. Au lieu de cela, envoie un rapport par e-mail après avoir vérifié chaque adresse de destinataire. Ceci est utile pour tester les configurations de réécriture et de routage d'adresses.

Cette fonctionnalité est disponible dans Postfix version 2.1 et ultérieures.

-C fichier_config
-C répertoire_config
Le chemin d'accès au fichier main.cf de Postfix, ou à son répertoire parent. Ces informations sont ignorées dans les versions de Postfix antérieures à 2.3.

Avec Postfix version 3.2 et ultérieures, un répertoire non par défaut doit être autorisé dans le fichier main.cf par défaut, via les paramètres alternate_config_directories ou multi_instance_directories.

Avec toutes les versions de Postfix, vous pouvez spécifier un chemin de répertoire avec la variable d'environnement MAIL_CONFIG pour remplacer l'emplacement des fichiers de configuration.

-F nom_complet
Définit le nom complet de l'expéditeur. Ceci remplace la variable d'environnement NAME, et est utilisé uniquement avec les messages qui n'ont pas d'en-tête de message From:.
-f expediteur
Définit l'adresse de l'expéditeur de l'enveloppe. C'est l'adresse à laquelle les problèmes de livraison sont envoyés. Avec les versions de Postfix antérieures à 2.1, l'en-tête de message Errors-To: remplace l'adresse de retour d'erreur.
-G
Soumission par passerelle (relais), par opposition à la soumission utilisateur initiale. Soit ne réécrit aucune adresse, soit met à jour les adresses incomplètes avec les informations de domaine spécifiées avec remote_header_rewrite_domain.

Cette option est ignorée avant la version 2.3 de Postfix.

-h nombre_sauts (ignoré)
Limite de sauts. Utilisez plutôt le paramètre de configuration hopcount_limit.
-I
Initialise la base de données des alias. Voir la commande newaliases ci-dessus.
-i
Lors de la lecture d'un message depuis l'entrée standard, ne traite pas une ligne contenant uniquement un caractère . comme fin d'entrée.
-L libelle (ignoré)
Le libellé de journalisation. Utilisez plutôt le paramètre de configuration syslog_name.
-m (ignoré)
Compatibilité ascendante.
-N dsn (par défaut : 'delay, failure')
Contrôle des notifications de statut de livraison. Spécifiez soit une liste séparée par des virgules avec un ou plusieurs des éléments suivants : failure (envoyer une notification en cas d'échec de livraison), delay (envoyer une notification en cas de retard de livraison), ou success (envoyer une notification lorsque le message est livré) ; soit spécifiez never (ne pas envoyer de notifications du tout).

Cette fonctionnalité est disponible dans Postfix 2.3 et ultérieures.

-n (ignoré)
Compatibilité ascendante.
-oAbase_donnees_alias
Base de données d'alias non par défaut. Spécifiez chemin_fichier ou type:chemin_fichier. Voir postalias(1) pour les détails.
-O option=valeur (ignorée)
Définit l'option nommée à valeur. Utilisez plutôt le paramètre de configuration équivalent dans main.cf.
-o7 (ignorée)
-o8 (ignorée)
Pour envoyer du contenu 8 bits ou binaire, utilisez un appropri
ate Encapsulation MIME et spécifiez l'option de ligne de commande appropriée -B.
-oi
Lors de la lecture d'un message depuis l'entrée standard, ne pas traiter une ligne contenant uniquement un caractère . comme fin d'entrée.
-om (ignoré)
L'expéditeur n'est jamais éliminé des expansions d'alias, etc.
-o x valeur (ignoré)
Définir l'option x à valeur. Utilisez plutôt le paramètre de configuration équivalent dans main.cf.
-r expéditeur
Définir l'adresse de l'expéditeur de l'enveloppe. C'est l'adresse où les problèmes de livraison sont envoyés. Avec les versions de Postfix antérieures à 2.1, l'en-tête de message Errors-To: remplace l'adresse de retour d'erreur.
-R retour
Contrôle de la notification d'état de livraison. Spécifiez "hdrs" pour retourner uniquement l'en-tête lorsqu'un message échoue, "full" pour retourner une copie complète (le comportement par défaut).

L'option -R spécifie une limite supérieure ; Postfix ne retournera que l'en-tête lorsqu'une copie complète dépasserait le réglage bounce_size_limit.

Cette option est ignorée avant la version 2.10 de Postfix.

-q
Tenter de livrer tout le courrier mis en file d'attente. Ceci est implémenté en exécutant la commande postqueue(1).

Attention : vider fréquemment le courrier non livrable entraînera une mauvaise performance de livraison de tout le reste du courrier.

-qintervalle (ignoré)
L'intervalle entre les exécutions de file d'attente. Utilisez plutôt le paramètre de configuration queue_run_delay.
-qIid_file
Planifier la livraison immédiate du courrier avec l'identifiant de file d'attente spécifié. Cette option est implémentée en exécutant la commande postqueue(1) et est disponible à partir de la version 2.4 de Postfix.
-qRsite
Planifier la livraison immédiate de tout le courrier mis en file d'attente pour le site nommé. Cette option n'accepte que les noms de site éligibles au service de "vidage rapide" (fast flush), et est implémentée en exécutant la commande postqueue(1). Voir flush(8) pour plus d'informations sur le service de "vidage rapide".
-qSsite
Cette commande n'est pas implémentée. Utilisez plutôt la commande plus lente "sendmail -q".
-t
Extraire les destinataires des en-têtes de message. Ceux-ci sont ajoutés à tous les destinataires spécifiés sur la ligne de commande.

Avec les versions de Postfix antérieures à 2.1, cette option exige qu'aucun alamat de destinataire ne soit spécifié sur la ligne de commande.

-U (ignoré)
Soumission initiale par l'utilisateur.
-V envid
Spécifier l'identifiant d'enveloppe pour la notification par les serveurs qui prennent en charge DSN.

Cette fonctionnalité est disponible dans Postfix 2.3 et versions ultérieures.

-XV (Postfix 2.2 et antérieures : -V)
Variable Envelope Return Path. Étant donné une adresse d'expéditeur d'enveloppe de la forme proprietaire-listename@origine, chaque destinataire utilisateur@domaine reçoit un courrier avec une adresse d'expéditeur d'enveloppe personnalisée.

Par défaut, l'adresse d'expéditeur d'enveloppe personnalisée est proprietaire-listename+utilisateur=domaine@origine. Les caractères par défaut + et = sont configurables avec le paramètre de configuration default_verp_delimiters.

-XVxy (Postfix 2.2 et antérieures : -Vxy)
Comme -XV, mais utilise x et y comme caractères délimiteurs VERP, au lieu des caractères spécifiés avec le paramètre de configuration default_verp_delimiters.
-v
Envoyer un rapport par e-mail de la première tentative de livraison (versions 2.1 et ultérieures de Postfix). La livraison du courrier se fait toujours en arrière-plan. Lorsque plusieurs options -v sont données, activer la journalisation détaillée à des fins de débogage.
-X fichier_journal (ignoré)
Journaliser le trafic du agent de messagerie. Utilisez plutôt les paramètres de configuration debug_peer_list et debug_peer_level.

SÉCURITÉ

Par conception, ce programme n'a pas de privilèges d'utilisateur (ou de groupe) définis. Il est préparé à traiter le contenu de messages provenant d'utilisateurs non fiables, potentiellement distants.

Cependant, comme la plupart des programmes Postfix, ce programme n'applique pas de politique de sécurité sur ses arguments de ligne de commande. Au lieu de cela, il s'appuie sur le système UNIX pour appliquer les politiques d'accès basées sur les identifiants d'utilisateur et de groupe effectifs du processus. Concrètement, cela signifie que l'exécution de commandes Postfix en tant que root (depuis sudo ou équivalent) au nom d'un utilisateur non root est susceptible de créer des opportunités d'escalade de privilèges.

Si une application exécute des programmes Postfix pour le compte d'utilisateurs qui n'ont pas d'accès shell normal aux commandes Postfix, cette application DOIT restreindre les arguments de ligne de commande spécifiés par l'utilisateur afin d'éviter l'escalade de privilèges.

  • Filtrer tous les arguments de ligne de commande, par exemple les arguments qui contiennent un chemin d'accès ou qui spécifient une méthode d'accès à une base de données. Ces vérifications de chemins d'accès doivent rejeter les liens symboliques ou les liens physiques contrôlés par l'utilisateur vers des fichiers sensibles, et ne doivent pas être vulnérables aux attaques par race TOCTOU.
  • Désactiver le traitement des options de commande pour tous les arguments de commande contenant des données spécifiées par l'utilisateur. Par exemple, la ligne de commande du programme sendmail(1) de Postfix DOIT être structurée comme suit : 
        /chemin/vers/sendmail arguments-systeme -- arguments-utilisateur

    Ici, le "--" désactive le traitement des options de commande pour tous les arguments-utilisateur qui suivent.

Sans le "--", un utilisateur malveillant pourrait activer les options de commande du programme sendmail(1) de Postfix, en spécifiant une adresse e-mail commençant par "-".

NAME

sendmail — Postfix sendmail command

SYNOPSIS

sendmail -L ln -P ln -q -v -Ac -Am -G -t -i -n -N -e -o x -F name -f from -r from -X file -bp -bpq -bs -bS -bW -bz -bh -bi -bfs -bne -bnl -bq -bU -bV -r address -R address -a address -A address -U -v [ -o x ] [ -X file ] [ -i ] [ -t ] [ -d option ... ] [ -m ] [ -n ] [ -N ] [ -e ] [ -c config_file ] [ -q ] [ -R address ] [ -r address ] [ -a address ] [ -A address ] [ -F name ] [ -f from ] [ -t ] [ -i ] [ -v ] [ -P ln ] [ -L ln ] [ -d option ... ] [ -x option ... ] [ -U ] [ -N ] [ -e ] [ -m ] [ -b type ] [ -p ] [ recipient ... ]

DESCRIPTION

The sendmail command is a command-line interface to the Postfix mail system. It is designed to be compatible with the original sendmail(8) program, allowing applications that rely on sendmail's interface to function with Postfix.

The sendmail command is primarily used for sending mail from the command line or from scripts. It can also be used for querying the mail queue and for performing other mail-related administrative tasks.

The Postfix sendmail command processes mail messages in the same way as the original sendmail command, but it uses Postfix's internal queueing and delivery mechanisms.

Refer to the postfix(1) manual page for a complete list of Postfix commands and their functions.

SECURITY

This command should only be invoked by users who have permission to send mail on behalf of others. The sendmail command can be used to send mail to any recipient, including those on remote systems. Care should be taken to ensure that the command is not used for malicious purposes.

DIAGNOSTICS

The sendmail command logs its actions to the system log. Diagnostic messages can be viewed using the syslogd(8) daemon.

ENVIRONMENT

MAIL_CONFIG
If this environment variable is set, it specifies a colon-separated list of alternative Postfix configuration directories. The first directory in the list that exists and is readable will be used.

CONFIGURATION PARAMETERS

The sendmail command is controlled by the parameters defined in the Postfix configuration files, typically located in /etc/postfix. Some of the most relevant parameters include:

alias_maps ($alias_maps)
The user-specified alias databases. The default is empty. With sendmail, alias lookups are disabled by default unless this parameter is set.
command_directory ($command_directory)
The location of administrator commands.
config_directory ($config_directory)
The default location of the Postfix configuration files.
daemon_directory ($daemon_directory)
The directory with Postfix support programs and daemon programs.
mail_owner ($mail_owner)
The UNIX system account that owns the Postfix queue and most Postfix daemon processes.
queue_directory ($queue_directory)
The location of the Postfix top-level queue directory.
sendmail_path ($sendmail_path)
The command path for the sendmail(1) command.
syslog_facility ($syslog_facility)
The syslog facility of Postfix logging.
syslog_name ($syslog_name)
A prefix that is prepended to the process name in syslog records.

COMPATIBILITY CONTROLS

allow_fips_shorthash (no)
When enabled, Postfix will use FIPS-approved shorter hashes for Bounce messages and other delivery reports. This is mostly relevant for older systems that may not fully support longer hashes.
hash_source_address (yes)
When enabled, Postfix will use the source address when calculating the hash for certain internal lookups. This can be useful for load balancing or for ensuring that mail is routed consistently.
inline_query_limit (1000)
The maximum number of parallel queries that Postfix will perform to external services, such as DNS servers or LDAP directories. This parameter helps to prevent Postfix from overwhelming external services with too many requests.
mailbox_size_limit (0)
The maximum size of a user's mailbox in bytes. A value of 0 means no limit. This parameter is used to prevent mailboxes from growing too large, which can impact performance and disk space usage.
message_size_limit (10240000)
The maximum size of a mail message in bytes. Messages larger than this limit will be rejected. This parameter helps to prevent denial-of-service attacks and reduce the load on the mail server.
parent_domain_matches_subdomains (any)
This parameter controls how Postfix matches parent domains with subdomains. It is used in various contexts, such as MX record lookups and access control checks.
propagate_unmatched_extra_recipient_headers (no)
When enabled, Postfix will propagate unmatched extra recipient headers to the next delivery stage. This can be useful for certain specialized mail configurations.
unspecified_destination_hopcount (1000)
The maximum number of hops allowed for mail destined for unspecified destinations. This parameter helps to prevent mail loops and ensure that mail eventually reaches its destination.

TROUBLE SHOOTING CONTROLS

bounce_queue_lifetime (5d)
The maximum amount of time that a bounce message will remain in the queue before being discarded. This parameter helps to prevent the queue from filling up with undeliverable bounce messages.
cleanup_service_name (cleanup)
The name of the Postfix cleanup service. This service is responsible for processing mail messages before they are delivered.
disable_dns_lookups (no)
When enabled, Postfix will disable all DNS lookups. This can be useful for testing or in environments where DNS is unreliable.
double_bounce_limit (5)
The maximum number of times that Postfix will attempt to send a bounce message before giving up. This parameter helps to prevent mail loops and ensure that bounce messages are eventually delivered.
maximal_queue_lifetime (5d)
The maximum amount of time that a mail message will remain in the queue before being discarded. This parameter helps to prevent mail from remaining undelivered indefinitely.
queue_run_delay (300s)
The time between deferred queue scans by the queue manager.
sendmail_relaunch_delay (60s)
The delay between attempts to relaunch the sendmail command. This parameter is used to prevent Postfix from overwhelming the system with too many sendmail processes.
slow_flush_timeout (1000s)
The timeout for slow flush operations. This parameter is used to prevent Postfix from getting stuck on slow or unresponsive connections.

ACCESS CONTROLS

disable_ipv4 (no)
When enabled, Postfix will disable IPv4 connections. This is useful in environments where only IPv6 is used.
disable_ipv6 (no)
When enabled, Postfix will disable IPv6 connections. This is useful in environments where only IPv4 is used.
enable_original_sendmail_groups (yes)
When enabled, Postfix will emulate the original sendmail behavior regarding group memberships for mail delivery. This is important for compatibility with older applications.
parent_domain_matches_subdomains (any)
This parameter controls how Postfix matches parent domains with subdomains. It is used in various contexts, such as MX record lookups and access control checks.

RESOURCE AND RATE CONTROLS

fork_attempts (5)
The maximal number of attempts to fork() a child process.
fork_delay (1s)
The delay between attempts to fork() a child process.
hopcount_limit (50)
The maximal number of Received: message headers that is allowed in the primary message headers.
queue_run_delay (300s)
The time between deferred queue scans by the queue manager; prior to Postfix 2.4 the default value was 1000s.

Optional list of destinations that are eligible for per-destination logfiles with mail that is queued to those destinations.
