setresuid(2) Manuel des appels système setresuid(2)

NOM

setresuid, setresgid - définir les ID utilisateur ou groupe réels, effectifs et sauvegardés

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <unistd.h>
int setresuid(uid_t ruid, uid_t euid, uid_t suid);
int setresgid(gid_t rgid, gid_t egid, gid_t sgid);

DESCRIPTION

setresuid() définit l'ID utilisateur réel, l'ID utilisateur effectif et l'ID utilisateur effectif sauvegardé du processus appelant.

Un processus non privilégié peut changer son ID utilisateur réel, son ID utilisateur effectif et son ID utilisateur effectif sauvegardé, chacun pour l'un des suivants : l'ID utilisateur réel actuel, l'ID utilisateur effectif actuel, ou l'ID utilisateur effectif sauvegardé actuel.

Un processus privilégié (sous Linux, celui qui a la capacité CAP_SETUID) peut définir son ID utilisateur réel, son ID utilisateur effectif et son ID utilisateur effectif sauvegardé à des valeurs arbitraires.

Si l'un des arguments est égal à -1, la valeur correspondante n'est pas modifiée.

Indépendamment des modifications apportées à l'ID utilisateur réel, à l'ID utilisateur effectif et à l'ID utilisateur effectif sauvegardé, l'ID utilisateur du système de fichiers est toujours défini sur la même valeur que l'ID utilisateur effectif (éventuellement nouveau).

De manière complètement analogue, setresgid() définit l'ID groupe réel, l'ID groupe effectif et l'ID groupe effectif sauvegardé du processus appelant (et modifie toujours l'ID groupe du système de fichiers pour qu'il soit identique à l'ID groupe effectif), avec les mêmes restrictions pour les processus non privilégiés.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

Note : il existe des cas où setresuid() peut échouer même lorsque l'appelant est UID 0 ; omettre de vérifier un retour d'échec de setresuid() constitue une grave faille de sécurité.

ERREURS

EAGAIN
L'appel modifierait l'ID utilisateur réel de l'appelant (c'est-à-dire que ruid ne correspond pas à l'ID utilisateur réel de l'appelant), mais il y a eu un échec temporaire d'allocation des structures de données du noyau nécessaires.
EAGAIN
ruid ne correspond pas à l'ID utilisateur réel de l'appelant et cet appel dépasserait la limite de ressources RLIMIT_NPROC de l'appelant. Depuis Linux 3.1, ce cas d'erreur ne se produit plus (mais les applications robustes devraient vérifier cette erreur) ; voir la description de EAGAIN dans execve(2).
EINVAL
Un ou plusieurs des ID utilisateur ou groupe cibles ne sont pas valides dans cet espace de noms utilisateur.
EPERM
Le processus appelant n'est pas privilégié (n'a pas la capacité nécessaire dans son espace de noms utilisateur) et a tenté de modifier les ID à des valeurs non autorisées. Pour setresuid(), la capacité nécessaire est CAP_SETUID ; pour setresgid(), c'est CAP_SETGID.

VERSIONS

Différences bibliothèque C/noyau

Au niveau du noyau, les ID utilisateur et groupe sont un attribut par fil d'exécution. Cependant, POSIX exige que tous les fils d'exécution d'un processus partagent les mêmes identifiants. L'implémentation de threading NPTL gère les exigences POSIX en fournissant des fonctions d'encapsulation pour les divers appels système qui modifient les identifiants de processus. Ces fonctions d'encapsulation (y compris celles pour setresuid() et setresgid()) utilisent une technique basée sur les signaux pour garantir que lorsqu'un fil d'exécution modifie les identifiants, tous les autres fils d'exécution du processus modifient également leurs identifiants. Pour plus de détails, voir nptl(7).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2024. Linux 2.1.44, glibc 2.3.2. HP-UX, FreeBSD.

Les appels système originaux setresuid() et setresgid() sous Linux ne supportaient que les ID utilisateur et groupe 16 bits. Par la suite, Linux 2.4 a ajouté setresuid32() et setresgid32(), supportant les ID 32 bits. Les fonctions d'encapsulation glibc setresuid() et setresgid() gèrent de manière transparente les variations entre les versions du noyau.
