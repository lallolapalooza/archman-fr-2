SET(1P) Manuel du programmeur POSIX SET(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

set — définir ou annuler des options et des paramètres positionnels

SYNTAXE

set [-abCefhmnuvx] [-o option] [argument...]
set [+abCefhmnuvx] [+o option] [argument...]
set -- [argument...]
set -o
set +o

DESCRIPTION

Si aucune option ou argument n'est spécifié, set doit écrire les noms et valeurs de toutes les variables shell dans la séquence de collation de la locale actuelle. Chaque nom doit commencer sur une ligne séparée, en utilisant le format :

"%s=%s\n", <nom>, <valeur>

La chaîne valeur doit être écrite avec un échappement approprié ; voir la description de l'échappement shell dans la Section 2.2, Échappement. La sortie doit être appropriée pour être réintroduite dans le shell, définissant ou réinitialisant, autant que possible, les variables qui sont actuellement définies ; les variables en lecture seule ne peuvent pas être réinitialisées.

Lorsque des options sont spécifiées, elles doivent définir ou annuler des attributs du shell, tels que décrits ci-dessous. Lorsque des arguments sont spécifiés, ils provoquent la définition ou l'annulation des paramètres positionnels, tels que décrits ci-dessous. La définition ou l'annulation des attributs et des paramètres positionnels ne sont pas nécessairement des actions liées, mais elles peuvent être combinées en une seule invocation de set.

L'utilitaire intégré spécial set doit prendre en charge les Définitions de Base du volume POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires, à l'exception près que les options peuvent être spécifiées avec un <trait d'union> (signifiant activer l'option) ou un <signe plus> (signifiant désactiver l'option) sauf indication contraire.

Les implémentations doivent prendre en charge les options de la liste suivante sous leurs deux formes <trait d'union> et <signe plus>. Ces options peuvent également être spécifiées comme options pour sh.

-a
Lorsque cette option est activée, l'attribut export doit être défini pour chaque variable à laquelle une assignation est effectuée ; voir le volume Définitions de Base de POSIX.1‐2017, Section 4.23, Assignation de Variable. Si l'assignation précède un nom d'utilitaire dans une commande, l'attribut export ne doit pas persister dans l'environnement d'exécution actuel après la fin de l'utilitaire, à l'exception près que précéder l'un des utilitaires intégrés spéciaux provoque la persistance de l'attribut export après la fin de l'utilitaire intégré. Si l'assignation ne précède pas un nom d'utilitaire dans la commande, ou si l'assignation est le résultat de l'opération des utilitaires getopts ou read, l'attribut export doit persister jusqu'à ce que la variable soit annulée.
-b
Cette option doit être prise en charge si l'implémentation prend en charge l'option Utilitaires de Portabilité Utilisateur. Elle doit provoquer la notification asynchrone des finis de tâches en arrière-plan à l'utilisateur. Le message suivant est écrit sur la sortie standard d'erreur :
"[%d]%c %s%s\n", <numéro_tâche>, <courant>, <statut>, <nom_tâche>

où les champs doivent être les suivants :

<courant>
Le caractère '+' identifie la tâche qui serait utilisée par défaut pour les utilitaires fg ou bg ; cette tâche peut également être spécifiée à l'aide de l'identifiant_tâche "%+" ou "%%". Le caractère '-' identifie la tâche qui deviendrait la valeur par défaut si la tâche par défaut actuelle se terminait ; cette tâche peut également être spécifiée à l'aide de l'identifiant_tâche "%-". Pour les autres tâches, ce champ est un <espace>. Au plus une tâche peut être identifiée avec '+' et au plus une tâche peut être identifiée avec '-'. S'il y a une tâche suspendue, alors la tâche actuelle doit être une tâche suspendue. S'il y a au moins deux tâches suspendues, alors la tâche précédente doit également être une tâche suspendue.
<numéro_tâche>
Un nombre qui peut être utilisé pour identifier le groupe de processus avec les utilitaires wait, fg, bg et kill. En utilisant ces utilitaires, la tâche peut être identifiée en préfixant le numéro de tâche avec '%'.
<statut>
Non spécifié.
<nom_tâche>
Non spécifié.

Lorsque le shell notifie à l'utilisateur qu'une tâche est terminée, il peut supprimer l'identifiant de processus de la tâche de la liste de ceux connus dans l'environnement d'exécution actuel du shell ; voir la Section 2.9.3.1, Exemples. La notification asynchrone ne doit pas être activée par défaut.

-C
(C majuscule.) Empêcher les fichiers existants d'être écrasés par l'opérateur de redirection '>' du shell (voir la Section 2.7.2, Redirection de la sortie) ; l'opérateur de redirection ">|" doit outrepasser cette option noclobber pour un fichier individuel.
-e
Lorsque cette option est activée, lorsqu'une commande échoue (pour l'une des raisons listées dans la Section 2.8.1, Conséquences des erreurs du shell ou en retournant un statut de sortie supérieur à zéro), le shell doit se terminer immédiatement, comme s'il exécutait l'utilitaire intégré spécial exit sans arguments, avec les exceptions suivantes :
1.
L'échec de toute commande individuelle dans un pipeline à commandes multiples ne doit pas provoquer la sortie du shell. Seul l'échec du pipeline lui-même doit être pris en compte.
2.
Le réglage -e doit être ignoré lors de l'exécution de la liste composée qui suit le mot réservé while, until, if ou elif, un pipeline commençant par le mot réservé !, ou toute commande d'une liste ET-OU autre que la dernière.
3.
Si le statut de sortie d'une commande composée autre qu'une commande de sous-shell était le résultat d'un échec alors que -e était ignoré, alors -e ne doit pas s'appliquer à cette commande.

Cette exigence s'applique séparément à l'environnement shell et à chaque environnement de sous-shell. Par exemple, dans :

set -e; (false; echo one) | cat; echo two

la commande false provoque la sortie du sous-shell sans exécuter echo one ; cependant, echo two est exécuté car le statut de sortie du pipeline (false; echo one) | cat est zéro.

-f
Le shell doit désactiver l'expansion des chemins.
-h
Localiser et mémoriser les utilitaires invoqués par les fonctions au moment de la définition de ces fonctions (les utilitaires sont normalement localisés lorsque la fonction est exécutée).
-m
Cette option doit être prise en charge si l'implémentation prend en charge l'option Utilitaires de Portabilité Utilisateur. Toutes les tâches doivent être exécutées dans leurs propres groupes de processus. Immédiatement avant que le shell n'affiche une invite après la fin de la tâche en arrière-plan, un message rapportant le statut de sortie de la tâche en arrière-plan doit être écrit sur la sortie d'erreur standard. Si une tâche au premier plan s'arrête, le shell doit écrire un message sur la sortie d'erreur standard à cet effet, formaté comme décrit par l'utilitaire jobs. De plus, si une tâche change d'état autrement qu'en se terminant (par exemple, si elle s'arrête pour une entrée ou une sortie ou est arrêtée par un signal SIGSTOP), le shell doit écrire un message similaire immédiatement avant d'écrire la prochaine invite. Cette option est activée par défaut pour les shells interactifs.
-n
Le shell doit lire les commandes mais ne pas les exécuter ; ceci peut être utilisé pour vérifier les erreurs de syntaxe de script shell. Un shell interactif peut ignorer cette option.
-o
Écrire les paramètres actuels des options sur la sortie standard dans un format non spécifié.
+o
Écrire les paramètres d'option actuels sur la sortie standard dans un format qui est approprié pour être réintroduit dans le shell sous forme de commandes qui réalisent les mêmes paramètres d'option.

Ceci est différent de la valeur par défaut où le statut de sortie d'un pipeline est le statut de sortie de la dernière commande du pipeline.

Traiter l'expansion des variables non définies ou non initialisées comme une erreur lors de l'exécution d'une commande. Le shell doit écrire un message sur la sortie d'erreur standard et se terminer avec un statut de sortie différent de zéro.
-v

La syntaxe set -- est utilisée pour séparer les options des arguments ; tout ce qui suit -- est traité comme des arguments, même s'il commence par un trait d'union.

Si un argument est spécifié, les paramètres positionnels du shell ($1, $2, ...) sont définis ou annulés en fonction de la liste des arguments. Le premier argument devient la nouvelle valeur de $1, le second devient la nouvelle valeur de $2, et ainsi de suite. Si aucun argument n'est spécifié, tous les paramètres positionnels sont annulés.

Le comportement des utilitaires intégrés set, unset, readonly, export, typeset et alias est défini par l'utilitaire ksh (conforme à la norme POSIX).

Les options peuvent être activées ou désactivées en utilisant soit un trait d'union (-) pour activer, soit un signe plus (+) pour désactiver. Par exemple, set -x active le traçage de l'exécution et set +x le désactive.

Si la variable d'environnement POSIXLY_CORRECT est définie, le shell se conforme strictement à la norme POSIX. Les extensions spécifiques à l'implémentation sont désactivées.

OPTIONS

Voir DESCRIPTION pour une description des options.

OPÉRANDES

Les arguments non optionnels sont utilisés pour définir les paramètres positionnels du shell. Si aucun argument n'est fourni, tous les paramètres positionnels sont annulés.

CONSIDÉRATIONS RELATIVES AU SYSTÈME D'EXPLOITATION

L'option -b (notify) n'est pertinente que si le shell prend en charge la gestion des tâches.

EXEMPLES

1. Définir les paramètres positionnels :
   $ set one two three
   $ echo $1 $2 $3
   one two three

2. Annuler tous les paramètres positionnels :
   $ set
   $ echo $1
   <vide>

3. Activer l'option de traçage :
   $ set -x
   $ ls -l
   + ls -l
   -rw-r--r-- 1 user group 1024 Jan 1 12:00 file.txt
   $

4. Désactiver l'option de traçage :
   $ set +x

5. Afficher tous les paramètres du shell :
   $ set

6. Vérifier la syntaxe d'un script shell sans l'exécuter :
   $ set -n mon_script.sh

ENVIRONNEMENT

Les variables suivantes affectent l'exécution de set :

COLUMNS
Utilisé par set pour déterminer le nombre de colonnes lors de l'affichage des variables shell si l'option -C n'est pas utilisée. Si COLUMNS n'est pas définie, le système doit déterminer la largeur de l'écran.
IGNOREEOF
Affecte le comportement de l'option ignoreeof.
POSIXLY_CORRECT
Si cette variable est définie, le shell se conforme strictement aux standards POSIX. Les extensions comportementales spécifiques à l'implémentation doivent être désactivées.

STATUT DE SORTIE

Zéro si la définition des options et/ou des paramètres positionnels a réussi, ou si aucun argument n'a été spécifié. Un statut différent de zéro si une option est inconnue ou si une erreur de syntaxe est rencontrée.

UTILISATION PAR L'APPLICATION

Les auteurs d'applications doivent éviter de s'appuyer sur set -e dans les fonctions. Par exemple, dans le script suivant :

set -e
start() {
    some_server
    echo some_server started successfully
}
start || echo >&2 some_server failed

le réglage -e est ignoré dans le corps de la fonction (car la fonction est une commande dans une liste ET-OU autre que la dernière). Par conséquent, si some_server échoue, la fonction continue à afficher "some_serverstartedsuccessfully", et le statut de sortie de la fonction est zéro (ce qui signifie que "some_serverfailed" n'est pas affiché).

EXEMPLES

Afficher toutes les variables et leurs valeurs :

set

Définir $1, $2 et $3 et définir "$#" à 3 :

set c a b

Activer les options -x et -v :

set -xv

Désactiver tous les paramètres positionnels :

set --

Définir $1 sur la valeur de x, même s'il commence par '-' ou '+' :

set -- "$x"

Définir les paramètres positionnels sur l'expansion de x, même si x s'étend avec un préfixe '-' ou '+' :

set -- $x

RATIONALE

La forme set -- est répertoriée spécifiquement dans le SYNOPSIS même si cette utilisation est implicite dans les directives de syntaxe utilitaire. L'explication de cette fonctionnalité élimine toute ambiguïté quant à savoir si la forme set -- pourrait être mal interprétée comme étant équivalente à set sans options ni arguments. La fonctionnalité de cette forme a été adoptée du KornShell. Dans System V, set -- ne désactive les paramètres que s'il y a au moins un argument ; la seule façon de désactiver tous les paramètres est d'utiliser shift. L'utilisation de la version KornShell ne devrait pas affecter les scripts System V car il ne devrait y avoir aucune raison de l'émettre délibérément sans arguments ; si elle était émise comme, par exemple :

set -- "$@"

et s'il n'y avait en fait aucun argument résultant de "$@", la désactivation des paramètres n'aurait aucun effet.

La forme set + dans les propositions antérieures a été omise car elle constituait un double emploi inutile de set seul et ne correspondait pas à une pratique historique répandue.

L'option noclobber a été modifiée pour autoriser set -C ainsi que l'option set -o noclobber. La version à une seule lettre a été ajoutée afin que le paradigme historique "$-" ne soit pas rompu ; voir Section 2.5.2, Paramètres spéciaux.

La description de l'option -e est destinée à correspondre au comportement de la version 1988 du KornShell.

Le drapeau -h est lié au hachage des noms de commandes. Voir hash.

Les indicateurs set suivants ont été omis intentionnellement avec la justification suivante :

-k
Le drapeau -k a été initialement ajouté par l'auteur du Bourne shell pour faciliter la tâche des utilisateurs des versions pré-release du shell. Dans les premières versions du Bourne shell, la construction set name=value devait être utilisée pour attribuer des valeurs aux variables du shell. Le problème avec -k est que le comportement affecte l'analyse, rendant pratiquement impossible l'écriture de tout compilateur. Pour expliquer le comportement de -k, il est nécessaire de décrire l'algorithme d'analyse, qui est défini par l'implémentation. Par exemple :
set -k; echo name=value

et :

set -k
echo name=value

se comportent différemment. L'interaction avec les fonctions est encore plus complexe. De plus, le drapeau -k n'est jamais nécessaire, car la ligne de commande aurait pu être réorganisée.

-t
Le drapeau -t est difficile à spécifier et est presque jamais utilisé. Le seul usage connu pourrait être fait avec des here-documents. De plus, le comportement avec ksh et sh diffère. La page de référence indique qu'elle se termine après avoir lu et exécuté une commande. Qu'est-ce qu'une commande ? Si l'entrée est date;date, sh exécute les deux commandes date tandis que ksh ne fait que la première.

La réécriture de set pour simplifier sa syntaxe confuse a été envisagée. Une suggestion spécifique a été

set(1p) — Arch manual pages

RATIONALE

Although the unset utility is the correct way to unset options, the historical practice of using the +option syntax was deemed satisfactory, and there was no compelling reason to modify this widespread historical practice.

The -o option was adopted from the KornShell to meet user needs. In addition to its user-friendly interface, -o is necessary to provide the vi command-line editing mode. Historical practices do not provide a single-letter option name for this mode. Although it might have been possible to invent such a letter, it was recognized that other editing modes would be developed, and -o provides ample naming space for describing such extensions.

Historical implementations are inconsistent in the format used for reporting the status of the -o option. The +o format without an option-argument was added to allow portable access to options that can be saved and later restored, for example, using a dot script.

Historically, sh traced the command set +x, but ksh did not.

The ignoreeof setting prevents accidental logouts when the end-of-file character (typically <control>‐D) is entered. A user must explicitly exit to leave the interactive shell.

The set -m option was added to apply only to the UPE because it primarily applies to interactive use, not shell script applications.

The ability to perform asynchronous notification became available in the 1988 version of the KornShell. To enable it, the user had to issue the command:

trap "jobs -n" CLD

The C shell provides two different levels of asynchronous notification capability. The environment variable notify is analogous to what is done in set -b or set -o notify. When set, it notifies the user immediately of background job completions. When unset, this capability is turned off.

The other notification ability comes through the built-in utility notify. The syntax is:

notify [%job ... ]

By issuing notify with no operands, it causes the C shell to notify the user asynchronously when the state of the current job changes. If operands are given, notify asynchronously informs the user of changes in the states of the specified jobs.

To add asynchronous notification to the POSIX shell, neither the KornShell extensions to trap nor the C shell notify environment variable seemed appropriate (notify is not a proper POSIX environment variable name).

The set -b option was selected as a compromise.

The notify built-in was considered to have more functionality than was required for simple asynchronous notification.

Historically, some shells applied the -u option to all parameters, including $@ and $*. The standard developers felt that this was a misfeature, as it is normal and common for $@ and $* to be used in shell scripts regardless of whether they were passed any arguments. Treating these uses as an error when no arguments are passed reduces the value of -u for its intended purpose of finding spelling mistakes in variable names and uses of unset positional parameters.
