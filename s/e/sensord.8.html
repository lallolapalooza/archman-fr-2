NOM

sensord - Démon d'enregistrement des informations des capteurs.

SYNOPIS

sensord [ options ] [ puces ]

DESCRIPTION

Sensord est un démon qui peut être utilisé pour enregistrer périodiquement les lectures des capteurs des puces matérielles de surveillance de la santé dans syslog(3) ou une base de données round-robin (RRD) et pour alerter lorsqu'une alarme de capteur est déclenchée ; par exemple, si un ventilateur tombe en panne, si une limite de température est dépassée, etc.

OPTIONS

-i, --interval temps
Spécifie l'intervalle entre les analyses des alarmes de capteur ; par défaut, l'analyse s'effectue toutes les minutes.

Le temps doit être spécifié sous forme d'entier brut (secondes) ou avec un suffixe `s' pour secondes, `m' pour minutes ou `h' pour heures ; par exemple, l'intervalle par défaut est `60' ou `1m'.

Spécifiez un intervalle de zéro pour supprimer explicitement l'analyse des alarmes.

-l, --log-interval temps
Spécifie l'intervalle entre l'enregistrement de toutes les lectures des capteurs ; par défaut, toutes les lectures sont enregistrées toutes les demi-heures.

Le temps est spécifié comme précédemment ; par exemple, `30m'.

Spécifiez un intervalle de zéro pour supprimer l'enregistrement des lectures régulières des capteurs.

-1, --oneline
Enregistre la valeur du capteur, la puce et l'adaptateur sur une seule ligne pour faciliter l'analyse.
-t, --rrd-interval temps
Spécifie l'intervalle entre l'enregistrement de toutes les lectures des capteurs dans une base de données round-robin ; par défaut, toutes les lectures sont enregistrées toutes les cinq minutes si une base de données round-robin est configurée.

Le temps est spécifié comme précédemment ; par exemple, `5m'.

-T, --rrd-no-average
Spécifie que la base de données round-robin ne doit pas être moyennée.
-r, --rrd-file fichier
Spécifie une base de données round-robin dans laquelle enregistrer toutes les lectures des capteurs ; par exemple, `/var/log/sensord.rrd'. Cette base de données sera créée si elle n'existe pas. Par défaut, aucune base de données round-robin n'est utilisée.

Voir la section BASES DE DONNÉES ROUND ROBIN ci-dessous pour plus de détails.

-c, --config-file fichier
Spécifie un fichier de configuration libsensors(3). Si aucun fichier n'est spécifié, le fichier de configuration par défaut de libsensors est utilisé.
-p, --pid-file fichier
Spécifie quel fichier PID écrire ; par défaut, le fichier `/run/sensord.pid' est écrit. Vous devriez toujours spécifier un chemin absolu ici. Le fichier est supprimé lorsque le démon se termine.
-f, --syslog-facility facility
Spécifie la facilité syslog(3) à utiliser lors de l'enregistrement des lectures et des alarmes des capteurs ; par défaut, c'est daemon.

Les autres facilités possibles incluent local0 à local7, et user.

-g, --rrd-cgi répertoire
Imprime un script CGI d'exemple rrdcgi(1) qui peut être utilisé pour afficher des graphiques des informations récentes des capteurs sur une page Web, puis se termine. Vous devez spécifier le répertoire accessible en écriture par tous et accessible par le Web où les graphiques doivent être stockés ; le script CGI suppose que celui-ci sera accédé via le répertoire `/sensord/' sur le serveur Web. Voir la section BASES DE DONNÉES ROUND ROBIN ci-dessous pour plus de détails.
-a, --load-average
Inclut la charge moyenne dans la base de données RRD. Vous devriez également spécifier ce drapeau lorsque vous créez le script CGI.
-d, --debug
Imprime une petite quantité d'informations de débogage supplémentaires.
-h, --help
Imprime un message d'aide et se termine.
-v, --version
Affiche la version du programme et se termine.

PUCES

Pour restreindre les appareils analysés par ce démon, vous pouvez éventuellement spécifier une liste de noms de puces. Par défaut, toutes les puces disponibles sont analysées.

Un nom de puce typique serait `w83782d-*' (vous voudrez peut-être échapper le `*' pour votre shell) qui analyserait toutes les puces W83782D sur n'importe quel bus. Voir sensors.conf(5) pour plus de détails. Une autre option est de simplement ne pas charger les modules de capteur pour les puces qui ne vous intéressent pas.

SIGNaux

À la réception d'un SIGTERM (voir signal(7) pour les détails), ce démon devrait s'arrêter gracieusement.

À la réception d'un SIGHUP, ce démon réanalysera l'interface du noyau pour les puces et les fonctionnalités, et rechargera le fichier de configuration libsensors.

ENREGISTREMENT

Tous les messages de ce démon sont enregistrés dans syslog(3) sous le nom de programme `sensord' et la facilité daemon, ou toute autre spécifiée en ligne de commande.

Les lectures régulières des capteurs sont enregistrées au niveau info. Les alarmes sont enregistrées au niveau alert. Les messages de statut sans conséquence sont enregistrés au niveau minimum, debug, lorsque le débogage est activé.

Vous pouvez utiliser un fichier `/etc/syslog.conf' approprié pour diriger ces messages de manière utile. Voir syslog.conf(5) pour les détails complets. En supposant que vous ayez défini la facilité d'enregistrement sur local4, voici une configuration d'exemple :

# Entrées syslog.conf d'exemple
*.info;...;local4.none;local4.warn  /var/log/messages
local4.info                        -/var/log/sensors
local4.alert                        /dev/console
local4.alert                        *

La première ligne garantit que les lectures régulières des capteurs n'encombrent pas `/var/log/messages' ; nous disons d'abord `local4.none' pour éliminer les messages d'information ; puis `local4.warn' pour activer les avertissements et au-dessus. La deuxième ligne indique d'enregistrer toutes les lectures régulières des capteurs dans `/var/log/sensors' ; le trait d'union `-' signifie que ce fichier n'est pas vidé après chaque message. Les deux dernières lignes garantissent que les alarmes sont affichées sur la console système ainsi qu'à tous les utilisateurs connectés (en plus de `/var/log/messages' et `/var/log/sensors').

ROTATION DES JOURNAUX

Sur un système typique avec une bonne puce de capteur, attendez-vous à environ 2 Ko par lecture de capteur dans le fichier journal. Cela représente environ 3 Mo par mois. Vous devriez déjà faire pivoter vos fichiers syslog, mais pour être sûr, vous voudrez utiliser quelque chose comme logrotate(8) ou un équivalent. Vous pourriez, par exemple, vouloir une entrée dans `/etc/logrotate.d/syslog' contenant :

# Entrée logrotate.d d'exemple
/var/log/sensors {
    postrotate
        /usr/sbin/killall -HUP syslogd
    endscript
}

Notez, bien sûr, que vous voulez redémarrer syslogd(8) et non sensord(8)

ALARMES

Les alarmes indiquent généralement une condition critique ; par exemple, une panne de ventilateur ou une température ou une tension inacceptable. Cependant, certaines puces de capteur ne prennent pas en charge les alarmes, tandis que d'autres sont mal configurées et peuvent signaler des alarmes incorrectement.

Notez que certains pilotes peuvent ne pas prendre en charge le reporting d'alarme même si les puces qu'ils prennent en charge ont des alarmes. Depuis Linux 2.6.23, de nombreux pilotes ne rapportent toujours pas les alarmes dans un format adapté à libsensors 3.

BIPS SONORES

Si vous voyez `(bip)' à côté d'une lecture de capteur, cela signifie simplement que votre système est configuré pour émettre un avertissement sonore depuis la carte mère si une alarme est déclenchée sur ce capteur.

BASES DE DONNÉES ROUND ROBIN

Sensord(8) fournit la prise en charge du stockage des lectures des capteurs dans une base de données round-robin. Cela peut être une alternative utile à l'utilisation de syslog(3).

Ce mécanisme utilise le format de fichier RRDtool. Pour stocker les données, vous devez d'abord créer un fichier RRD à l'aide de la commande `rrdtool create' pour spécifier les "Data Sources" (sources de données) et la période de rétention des données. Pour plus de détails, veuillez consulter la page de manuel rrdcreate(1).

Pour chaque capteur que vous souhaitez enregistrer dans le RRD, vous devez créer une source de données RRD. La commande `sensord -g' génère un script CGI d'exemple qui peut être utilisé pour visualiser les données stockées dans le RRD. Ce script nécessite que vous spécifiiez un répertoire accessible en écriture par tous et via le Web où les graphiques seront stockés. Il génère également les commandes RRDtool nécessaires pour créer le fichier RRD.

Par exemple, pour enregistrer toutes les lectures des capteurs dans un fichier RRD appelé `/var/log/sensord.rrd' toutes les 5 minutes, vous utiliseriez la commande suivante :

sensord -i 1m -l 10m -t 5m -r /var/log/sensord.rrd

Pour générer le script CGI d'exemple qui affiche les données, en supposant que les graphiques seront accessibles via `/sensord/' sur votre serveur Web, vous utiliseriez :

sensord -g /var/www/html/sensord

Ce script générera un script CGI nommé `sensord.cgi' dans le répertoire spécifié. Vous devrez le configurer sur votre serveur Web pour qu'il puisse servir les graphiques.

ROUND ROBIN DATABASES

Les bases de données à rotation sont des bases de données de taille constante qui peuvent être utilisées pour stocker, par exemple, les relevés de capteurs d'une semaine. Les relevés ultérieurs stockés dans la base de données écraseront les relevés qui ont plus d'une semaine. Cette capacité est extrêmement utile car elle permet de stocker des informations utiles de manière facilement accessible pendant une durée utile, sans le fardeau de fichiers journaux sans cesse croissants.

L'utilitaire rrdtool(1) et sa bibliothèque associée fournissent le cadre de base pour la base de données à rotation sous sensord(8). De plus, les utilitaires rrdcgi(1) et rrdgraph(1) fournissent un support pour la génération de graphiques de ces données pour l'affichage dans une page Web.

Si vous souhaitez utiliser la configuration par défaut de la base de données à rotation, qui conserve une semaine de relevés de capteurs à intervalles de cinq minutes, démarrez simplement sensord(8) et spécifiez où vous souhaitez que la base de données soit stockée. Elle sera automatiquement créée et configurée en utilisant ces paramètres par défaut.

Si vous souhaitez que les relevés soient stockés pendant une période plus longue, ou si vous souhaitez que plusieurs relevés soient moyennés dans chaque entrée de la base de données, vous devez créer et configurer manuellement la base de données avant de démarrer sensord(8). Consultez le manuel de rrdcreate(1) pour plus de détails. Notez que la base de données doit correspondre exactement aux noms et à l'ordre des capteurs lus par sensord(8). Il est recommandé de créer la base de données par défaut, puis d'utiliser rrdinfo(1) pour obtenir ces informations, et/ou rrdtune(1) pour la modifier.

Après avoir créé la base de données à rotation, vous devez ensuite configurer votre serveur Web pour afficher les informations du capteur. Cela suppose que vous avez un serveur Web préconfiguré et fonctionnel sur votre machine. Sensord(8) fournit une option en ligne de commande --rrd-cgi pour générer un script CGI de base pour afficher ces graphiques ; vous pouvez ensuite personnaliser ce script comme vous le souhaitez. Consultez le manuel de rrdcgi(1) pour plus de détails. Ce script CGI nécessite un répertoire accessible par le Web et écrivable par tout le monde, dans lequel écrire les graphiques qu'il génère.

Un exemple de la façon de configurer des graphiques accessibles via le Web des relevés de capteurs récents suit :

sensord --log-interval 0 \
  --load-average \
  --rrd-file /var/log/sensord.rrd

Ici, nous démarrons sensord(8) et le configurons pour stocker les relevés dans une base de données à rotation ; notez que nous désactivons la journalisation des relevés de capteurs dans syslog(3), et activons la journalisation de la charge moyenne.

mkdir /var/www/sensord
chown www-data:staff /var/www/sensord
chmod a=rwxs /var/www/sensord

Ici, nous créons un répertoire accessible par le Web et écrivable par tout le monde dans lequel les graphiques seront stockés ; nous définissons la propriété et les permissions de ce répertoire de manière appropriée. Vous devrez déterminer l'emplacement et la propriété appropriés pour votre machine.

sensord --load-average \
  --rrd-file /var/log/sensord.rrd \
  --rrd-cgi /var/www/sensord \
  > /usr/lib/cgi-bin/sensord.cgi
chmod a+rx /usr/lib/cgi-bin/sensord.cgi

Ici, nous créons un script CGI qui affichera les relevés de capteurs de la base de données. Vous devez spécifier l'emplacement de la base de données à rotation, l'emplacement du répertoire où les images doivent être stockées, et si vous souhaitez que la charge moyenne soit affichée. Le paramètre de ligne de commande --rrd-cgi amène sensord(8) à afficher un script CGI approprié sur stdout, puis à se terminer. Vous devrez écrire ce script dans le répertoire bin CGI de votre serveur Web, et modifier le script si le répertoire d'images que vous avez choisi n'est pas le répertoire `/sensord/' de votre serveur Web.

Enfin, vous devriez pouvoir visualiser vos relevés de capteurs à partir de l'URL `http://localhost/cgi-bin/sensord.cgi'.

MODULES

Il est attendu que tous les modules de capteurs requis soient chargés avant le démarrage de ce démon. Cela peut être réalisé avec un schéma de chargement de modules spécifique au système (par exemple, en listant les modules requis dans le fichier `/etc/modules' sous Debian) ou avec des commandes modprobe(1) explicites dans un script d'initialisation avant de charger le démon.

Par exemple, un script d'initialisation `sensord' pourrait contenir (entre autres) les commandes suivantes :

# Sample init.d scriptlet
echo -n "Loading AMD756 module: "
modprobe i2c-amd756 || { echo Fail. ; exit 1 ; }
echo OK.
echo -n "Loading W83781D module: "
modprobe w83781d || { echo Fail. ; exit 1 ; }
echo OK.
echo -n "Starting sensord: "
daemon sensord

Ignorez les fonctions shell spécifiques à la plateforme ; l'idée générale devrait être assez claire.

ERREURS

Les erreurs rencontrées par ce démon sont enregistrées dans syslogd(8) après quoi le démon se terminera.

BOGUES

La prise en charge des bases de données à rotation ne gère pas les puces de capteurs multiples ayant des étiquettes de capteurs en double.
