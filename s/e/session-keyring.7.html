session-keyring(7) Manuel d'informations diverses session-keyring(7)

NOM

session-keyring - keyring partagé par session pour les processus

DESCRIPTION

Le keyring de session est un keyring utilisé pour ancrer des clés au nom d'un processus. Il est généralement créé par pam_keyinit(8) lorsqu'un utilisateur se connecte et un lien sera ajouté faisant référence au user-keyring(7). Optionnellement, PAM(7) peut révoquer le keyring de session à la déconnexion. (Dans les configurations typiques, PAM effectue cette révocation.) Le keyring de session a le nom (description) _ses.

Une valeur spéciale de numéro de série, KEY_SPEC_SESSION_KEYRING, est définie et peut être utilisée à la place du numéro de série réel du keyring de session du processus appelant.

Depuis l'utilitaire keyctl(1), '@s' peut être utilisé à la place d'un ID de clé numérique, de manière très similaire.

Le keyring de session d'un processus est hérité lors des appels à clone(2), fork(2) et vfork(2). Le keyring de session est conservé lors des appels à execve(2), même lorsque l'exécutable est défini-user-ID, défini-group-ID ou possède des capacités. Le keyring de session est détruit lorsque le dernier processus qui y fait référence se termine.

Si un processus n'a pas de keyring de session lorsqu'il est accédé, alors, dans certaines circonstances, le user-session-keyring(7) sera attaché comme keyring de session et dans d'autres circonstances un nouveau keyring de session sera créé. (Voir user-session-keyring(7) pour plus de détails.)

Opérations spéciales

La bibliothèque keyutils fournit les opérations spéciales suivantes pour manipuler les keyrings de session :

keyctl_join_session_keyring(3)
Cette opération permet à l'appelant de changer le keyring de session auquel il s'abonne. L'appelant peut rejoindre un keyring existant avec un nom (description) spécifié, créer un nouveau keyring avec un nom donné, ou demander au noyau de créer un nouveau keyring de session "anonyme" avec le nom "_ses". (Cette fonction est une interface vers l'opération keyctl(2) KEYCTL_JOIN_SESSION_KEYRING.)
keyctl_session_to_parent(3)
Cette opération permet à l'appelant de faire en sorte que le keyring de session du processus parent soit identique au sien. Pour que cela réussisse, le processus parent doit avoir des attributs de sécurité identiques et doit être mono-threadé. (Cette fonction est une interface vers l'opération keyctl(2) KEYCTL_SESSION_TO_PARENT.)

Ces opérations sont également exposées via l'utilitaire keyctl(1) comme suit :


keyctl session
keyctl session - [<prog> <arg1> <arg2> ...]
keyctl session <nom> [<prog> <arg1> <arg2> ...]

et :


keyctl new_session
