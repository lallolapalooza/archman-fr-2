send(2) Manuel des appels système send(2)

NOM

send, sendto, sendmsg - envoyer un message sur une socket

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/socket.h>
ssize_t send(int sockfd, const void *buf, size_t size, int flags);
ssize_t sendto(int sockfd, const void *buf, size_t size, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);
ssize_t sendmsg(int sockfd, const struct msghdr *msg, int flags);

DESCRIPTION

Les appels système send(), sendto() et sendmsg() sont utilisés pour transmettre un message à une autre socket.

L'appel send() ne peut être utilisé que lorsque la socket est dans un état connecté (de sorte que le destinataire prévu est connu). La seule différence entre send() et write(2) est la présence des flags. Avec un argument flags à zéro, send() est équivalent à write(2). De plus, l'appel suivant


send(sockfd, buf, size, flags);

est équivalent à


sendto(sockfd, buf, size, flags, NULL, 0);

L'argument sockfd est le descripteur de fichier de la socket d'envoi.

Si sendto() est utilisé sur une socket en mode connecté (SOCK_STREAM, SOCK_SEQPACKET), les arguments dest_addr et addrlen sont ignorés (et l'erreur EISCONN peut être retournée lorsqu'ils ne sont pas NULL et 0), et l'erreur ENOTCONN est retournée lorsque la socket n'était pas effectivement connectée. Sinon, l'adresse de la cible est donnée par dest_addr avec addrlen spécifiant sa taille. Pour sendmsg(), l'adresse de la cible est donnée par msg.msg_name, avec msg.msg_namelen spécifiant sa taille.

Pour send() et sendto(), le message se trouve dans buf et a une taille de size. Pour sendmsg(), le message est pointé par les éléments du tableau msg.msg_iov. L'appel sendmsg() permet également d'envoyer des données accessoires (également connues sous le nom d'informations de contrôle).

Si le message est trop long pour être transmis de manière atomique par le protocole sous-jacent, l'erreur EMSGSIZE est retournée, et le message n'est pas transmis.

Aucune indication d'échec de livraison n'est implicite dans un send(). Les erreurs détectées localement sont indiquées par une valeur de retour de -1.

Lorsque le message ne rentre pas dans le tampon d'envoi de la socket, send() bloque normalement, sauf si la socket a été placée en mode E/S non bloquant. En mode non bloquant, cela échouerait avec l'erreur EAGAIN ou EWOULDBLOCK dans ce cas. L'appel select(2) peut être utilisé pour déterminer quand il est possible d'envoyer plus de données.

L'argument flags

L'argument flags est le OU bit à bit de zéro ou plusieurs des indicateurs suivants.

MSG_CONFIRM (depuis Linux 2.3.15)
Indique à la couche de liaison que des progrès ont été réalisés : vous avez reçu une réponse réussie de l'autre côté. Si la couche de liaison ne reçoit pas cela, elle sondra régulièrement le voisin (par exemple, via une ARP unicast). Valide uniquement sur les sockets SOCK_DGRAM et SOCK_RAW et actuellement implémenté uniquement pour IPv4 et IPv6. Voir arp(7) pour plus de détails.
MSG_DONTROUTE
N'utilise pas de passerelle pour envoyer le paquet, envoie uniquement aux hôtes sur les réseaux directement connectés. Ceci est généralement utilisé uniquement par les programmes de diagnostic ou de routage. Ceci n'est défini que pour les familles de protocoles qui routent ; les sockets paquet ne le font pas.
MSG_DONTWAIT (depuis Linux 2.2)
Active le fonctionnement non bloquant ; si l'opération devait bloquer, EAGAIN ou EWOULDBLOCK est retourné. Ceci fournit un comportement similaire à la définition de l'indicateur O_NONBLOCK (via l'opération F_SETFL de fcntl(2)), mais diffère en ce que MSG_DONTWAIT est une option par appel, tandis que O_NONBLOCK est un réglage sur la description de fichier ouverte (voir open(2)), qui affectera tous les threads du processus appelant ainsi que d'autres processus qui détiennent des descripteurs de fichiers faisant référence à la même description de fichier ouverte.
MSG_EOR (depuis Linux 2.2)
Termine un enregistrement (lorsque cette notion est prise en charge, comme pour les sockets de type SOCK_SEQPACKET).
MSG_MORE (depuis Linux 2.4.4)
L'appelant a plus de données à envoyer. Cet indicateur est utilisé avec les sockets TCP pour obtenir le même effet que l'option de socket TCP_CORK (voir tcp(7)), avec la différence que cet indicateur peut être défini par appel.
Depuis Linux 2.6, cet indicateur est également pris en charge pour les sockets UDP, et informe le noyau de regrouper toutes les données envoyées dans les appels avec cet indicateur défini en un seul datagramme qui n'est transmis que lorsqu'un appel est effectué qui ne spécifie pas cet indicateur. (Voir également l'option de socket UDP_CORK décrite dans udp(7).)
MSG_NOSIGNAL (depuis Linux 2.2)
Ne génère pas de signal SIGPIPE si le pair sur une socket orientée flux a fermé la connexion. L'erreur EPIPE est toujours retournée. Ceci fournit un comportement similaire à l'utilisation de sigaction(2) pour ignorer SIGPIPE, mais alors que MSG_NOSIGNAL est une fonctionnalité par appel, ignorer SIGPIPE définit un attribut de processus qui affecte tous les threads du processus.
MSG_OOB
Envoie des données hors bande sur les sockets qui le supportent (par exemple, de type SOCK_STREAM) ; le protocole sous-jacent doit également prendre en charge les données hors bande.
MSG_FASTOPEN (depuis Linux 3.7)
Tente le TCP Fast Open (RFC7413) et envoie des données dans le SYN comme une combinaison de connect(2) et write(2), en effectuant un appel connect(2) implicite. Il bloque jusqu'à ce que les données soient mises en mémoire tampon et que la poignée de main soit terminée. Pour une socket non bloquante, il renvoie le nombre d'octets mis en mémoire tampon et envoyés dans le paquet SYN. Si le cookie n'est pas disponible localement, il renvoie EINPROGRESS et envoie automatiquement un SYN avec une demande de cookie Fast Open. L'appelant doit réécrire les données lorsque la socket est connectée. En cas d'erreurs, il définit le même errno que connect(2) si la poignée de main échoue. Cet indicateur nécessite d'activer le support client TCP Fast Open dans le sysctl net.ipv4.tcp_fastopen.
Reportez-vous à l'option de socket TCP_FASTOPEN_CONNECT dans tcp(7) pour une approche alternative.

sendmsg()

La définition de la structure msghdr utilisée par sendmsg() est la suivante :


struct msghdr {
    void         *msg_name;       /* Adresse optionnelle */
    socklen_t     msg_namelen;    /* Taille de l'adresse */
    struct iovec *msg_iov;        /* Tableau de lecture/écriture séparée (scatter/gather) */
    size_t        msg_iovlen;     /* Nombre d'éléments dans msg_iov */
    void         *msg_control;    /* Données accessoires, voir ci-dessous */
    size_t        msg_controllen; /* Taille du tampon de données accessoires */
    int           msg_flags;      /* Indicateurs (non utilisé) */
};

Le champ msg_name est utilisé sur une socket non connectée pour spécifier l'adresse cible d'un datagramme. Il pointe vers un tampon contenant l'adresse ; le champ msg_namelen doit être défini à la taille de l'adresse. Pour une socket connectée, ces champs doivent être spécifiés comme NULL et 0, respectivement.

Les champs msg_iov et msg_iovlen spécifient les emplacements de lecture/écriture séparée, comme pour writev(2).

/a>.

Vous pouvez envoyer des informations de contrôle (données auxiliaires) en utilisant les membres msg_control et msg_controllen. La taille maximale du tampon de contrôle que le noyau peut traiter est limitée par socket par la valeur dans /proc/sys/net/core/optmem_max ; voir socket(7). Pour plus d'informations sur l'utilisation des données auxiliaires dans divers domaines de socket, voir unix(7) et ip(7).

Le champ msg_flags est ignoré.

VALEUR DE RETOUR

En cas de succès, ces appels retournent le nombre d'octets envoyés. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

Ce sont quelques erreurs standard générées par la couche socket. Des erreurs supplémentaires peuvent être générées et retournées par les modules de protocole sous-jacents ; voir leurs pages man respectives.

EACCES
(Pour les sockets de domaine UNIX, qui sont identifiés par un nom de chemin) La permission d'écriture est refusée sur le fichier socket de destination, ou la permission de recherche est refusée pour l'un des répertoires du préfixe du chemin. (Voir path_resolution(7).)
(Pour les sockets UDP) Une tentative a été faite d'envoyer à une adresse réseau/de diffusion comme s'il s'agissait d'une adresse unicast.
EAGAIN ou EWOULDBLOCK
Le socket est marqué comme non bloquant et l'opération demandée bloquerait. POSIX.1-2001 autorise le retour de l'une ou l'autre de ces erreurs pour ce cas, et n'exige pas que ces constantes aient la même valeur, donc une application portable devrait vérifier les deux possibilités.
EAGAIN
(Sockets de datagrammes de domaine Internet) Le socket référencé par sockfd n'avait pas été précédemment lié à une adresse et, lors de la tentative de le lier à un port éphémère, il a été déterminé que tous les numéros de port de la plage de ports éphémères sont actuellement utilisés. Voir la discussion sur /proc/sys/net/ipv4/ip_local_port_range dans ip(7).
EALREADY
Un autre Fast Open est en cours.
EBADF
sockfd n'est pas un descripteur de fichier valide et ouvert.
ECONNRESET
Connexion réinitialisée par le pair.
EDESTADDRREQ
Le socket n'est pas en mode connexion, et aucune adresse de pair n'est définie.
EFAULT
Une adresse invalide dans l'espace utilisateur a été spécifiée pour un argument.
EINTR
Un signal est survenu avant que toute donnée ne soit transmise ; voir signal(7).
EINVAL
Argument invalide passé.
EISCONN
Le socket en mode connexion était déjà connecté mais un destinataire a été spécifié. (Maintenant, soit cette erreur est retournée, soit la spécification du destinataire est ignorée.)
EMSGSIZE
Le type de socket exige que le message soit envoyé de manière atomique, et la taille du message à envoyer l'a rendu impossible.
ENOBUFS
La file d'attente de sortie pour une interface réseau était pleine. Ceci indique généralement que l'interface a arrêté d'envoyer, mais peut être causé par une congestion transitoire. (Normalement, cela ne se produit pas sous Linux. Les paquets sont simplement silencieusement abandonnés lorsque la file d'attente d'un périphérique déborde.)
ENOMEM
Aucune mémoire disponible.
ENOTCONN
Le socket n'est pas connecté, et aucune cible n'a été donnée.
ENOTSOCK
Le descripteur de fichier sockfd ne fait pas référence à un socket.
EOPNOTSUPP
Certains bits dans l'argument flags sont inappropriés pour le type de socket.
EPIPE
L'extrémité locale a été fermée sur un socket orienté connexion. Dans ce cas, le processus recevra également un signal SIGPIPE à moins que MSG_NOSIGNAL ne soit défini.

VERSIONS

Selon POSIX.1-2001, le champ msg_controllen de la structure msghdr devrait être typé comme socklen_t, et le champ msg_iovlen devrait être typé comme int, mais glibc les type actuellement tous deux comme size_t.

NORMES

POSIX.1-2024.

MSG_CONFIRM est une extension Linux.

HISTORIQUE

4.4BSD, SVr4, POSIX.1-2001. (est apparu pour la première fois dans 4.2BSD).

POSIX.1-2001 ne décrit que les drapeaux MSG_OOB et MSG_EOR. POSIX.1-2008 ajoute une spécification de MSG_NOSIGNAL.

NOTES

Voir sendmmsg(2) pour des informations sur un appel système spécifique à Linux qui peut être utilisé pour transmettre plusieurs datagrammes en un seul appel.

BOGUES

Linux peut retourner EPIPE au lieu de ENOTCONN.

EXEMPLES

Un exemple d'utilisation de sendto() est montré dans getaddrinfo(3).
