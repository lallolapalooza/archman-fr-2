NOM

seccomp_syscall_resolve_name - Résoudre le nom d'un appel système

SYNTAXE

#include <seccomp.h>

int seccomp_syscall_resolve_name(const char *name);
int seccomp_syscall_resolve_name_arch(uint32_t arch_token,
                                      const char *name);
int seccomp_syscall_resolve_name_rewrite(uint32_t arch_token,
                                         const char *name);
char *seccomp_syscall_resolve_num_arch(uint32_t arch_token, int num);

Lier avec -lseccomp.

DESCRIPTION

Les fonctions seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() et seccomp_syscall_resolve_name_rewrite() résolvent le nom couramment utilisé d'un appel système vers le numéro d'appel système utilisé par le noyau et le reste de l'API libseccomp, avec seccomp_syscall_resolve_name_rewrite() qui réécrit le numéro d'appel système pour les architectures qui modifient l'appel système. La réécriture des appels système se produit généralement en cas d'appel système multiplexé, tel que socketcall(2) ou ipc(2) sur x86. La fonction seccomp_syscall_resolve_num_arch() résout le numéro d'appel système utilisé par le noyau vers le nom d'appel système couramment utilisé.

L'appelant est responsable de libérer la chaîne de caractères retournée par seccomp_syscall_resolve_num_arch().

VALEUR DE RETOUR

Dans le cas de seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() et seccomp_syscall_resolve_name_rewrite(), le numéro d'appel système associé est retourné, avec le numéro d'appel système pseudo négatif retourné dans les cas où l'appel système donné n'existe pas pour l'architecture. La valeur __NR_SCMP_ERROR est retournée en cas d'erreur. Dans tous les cas, la valeur de retour convient pour une utilisation dans toute fonction de l'API libseccomp qui nécessite le numéro d'appel système, des exemples incluent seccomp_rule_add() et seccomp_rule_add_exact().

Dans le cas de seccomp_syscall_resolve_num_arch(), le nom d'appel système associé est retourné et il reste de la responsabilité de l'appelant de libérer la chaîne de caractères retournée via free(3).

EXEMPLES

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW,
	                      seccomp_syscall_resolve_name("open"), 0);
	if (rc < 0)
		goto out;
	/* ... */
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTES

Dans le cas des appels système nus implémentés par-dessus un appel système multiplexé, seccomp_syscall_resolve_name() et seccomp_syscall_resolve_name_arch() peuvent être utilisés pour vérifier si un appel système nu est implémenté pour une architecture spécifique, tandis que seccomp_syscall_resolve_name_rewrite() peut être utilisé pour déterminer l'appel système multiplexé sous-jacent.

Bien que le filtre seccomp puisse être généré indépendamment du noyau, le support du noyau est requis pour charger et appliquer le filtre seccomp généré par libseccomp.

Le site du projet libseccomp, avec plus d'informations et le dépôt du code source, peut être trouvé sur https://github.com/seccomp/libseccomp. Cet outil, ainsi que la bibliothèque libseccomp, sont actuellement en cours de développement, veuillez signaler tout bug sur le site du projet ou directement à l'auteur.
