SEM(1) parallel SEM(1)

NOM

sem - sémaphore pour exécuter des lignes de commande shell en parallèle

SYNTAXE

sem [--fg] [--id <id>] [--semaphore-timeout <secs>] [-j <num>] [--wait] commande

DESCRIPTION

GNU sem est un alias pour GNU parallel --semaphore.

GNU sem agit comme un sémaphore comptant. Lorsque GNU sem est appelé avec une commande, il démarre la commande en arrière-plan. Lorsque *num* commandes sont en cours d'exécution en arrière-plan, GNU sem attend qu'une d'entre elles se termine avant de démarrer la commande.

GNU sem ne lit aucun argument pour construire la commande (pas de -a, :::, et ::::). Il attend simplement qu'un sémaphore devienne disponible, puis exécute la commande donnée.

Avant de consulter les options, vous pourriez vouloir consulter les exemples après la liste des options. Cela vous donnera une idée de ce dont GNU sem est capable.

OPTIONS

commande
Commande à exécuter. La commande peut être suivie d'arguments pour la commande.
--bg
Exécute la commande en arrière-plan, ainsi GNU sem n'attendra pas la fin de la commande avant de sortir. C'est le comportement par défaut.

Analogie avec les toilettes : GNU sem attend qu'une toilette soit disponible, la donne à une personne, et sort immédiatement.

Voir aussi : --fg

--jobs N
-j N
--max-procs N
-P N
Exécute jusqu'à N commandes en parallèle. La valeur par défaut est 1, agissant ainsi comme un mutex.

Analogie avec les toilettes : -j est le nombre de toilettes.

--jobs +N
-j +N
--max-procs +N
-P +N
Ajoute N au nombre de cœurs CPU. Exécute jusqu'à N jobs en parallèle. Pour les jobs gourmands en calcul, -j +0 est utile car il exécutera N jobs simultanément, où N est le nombre de cœurs CPU.
--jobs -N
-j -N
--max-procs -N
-P -N
Soustrait N du nombre de cœurs CPU. Exécute jusqu'à N jobs en parallèle. Si le nombre calculé est inférieur à 1, alors 1 sera utilisé. Voir aussi --use-cpus-instead-of-cores.
--jobs N%
-j N%
--max-procs N%
-P N%
Multiplie N% par le nombre de cœurs CPU. Exécute jusqu'à N jobs en parallèle. Si le nombre calculé est inférieur à 1, alors 1 sera utilisé. Voir aussi --use-cpus-instead-of-cores.
--jobs procfile
-j procfile
--max-procs procfile
-P procfile
Lit le paramètre depuis un fichier. Utilise le contenu de *procfile* comme paramètre pour *-j*. Par exemple, *procfile* pourrait contenir la chaîne 100% ou +2 ou 10.
--pipe
Passe l'entrée standard (stdin) à la *commande*.

Si la *commande* lit depuis l'entrée standard (stdin), utilisez --pipe.

--semaphore-name nom
--id nom
Utilise *nom* comme nom du sémaphore. La valeur par défaut est le nom du tty contrôleur (sortie de tty).

La valeur par défaut fonctionne normalement comme prévu lorsqu'elle est utilisée de manière interactive, mais lorsqu'elle est utilisée dans un script, *nom* doit être défini. *$$* ou *mon_nom_de_tache* sont souvent une bonne valeur.

Le sémaphore est stocké dans ~/.parallel/semaphores/

Dans l'analogie des toilettes, le nom correspond à différents types de toilettes : par exemple, hommes, femmes, clients, personnel.

--fg
Ne pas mettre la commande en arrière-plan.

Analogie avec les toilettes : GNU sem attend qu'une toilette soit disponible, emmène une personne à la toilette, attend que la personne ait fini, et sort.

--semaphore-timeout secs
--st secs
Si *secs* > 0 : Si le sémaphore n'est pas libéré dans les *secs* secondes, prenez-le quand même.

Si *secs* < 0 : Si le sémaphore n'est pas libéré dans les *secs* secondes, sortez.

Analogie avec les toilettes : *secs* > 0 : Si aucune toilette n'est disponible dans les *secs* secondes, urinez sur le sol. *secs* < 0 : Si aucune toilette n'est disponible dans les *secs* secondes, sortez sans rien faire.

--wait
Attend que toutes les commandes soient terminées.

Analogie avec les toilettes : Attendez que toutes les toilettes soient vides, puis sortez.

COMPRENDRE UN SÉMAPHORE

Essayez l'exemple suivant :

sem -j 2 'sleep 1;echo 1 finished';   echo sem 1 exited
sem -j 2 'sleep 2;echo 2 finished';   echo sem 2 exited
sem -j 2 'sleep 3;echo 3 finished';   echo sem 3 exited
sem -j 2 'sleep 4;echo 4 finished';   echo sem 4 exited
sem --wait; echo sem --wait done

Dans l'analogie des toilettes, cela utilise 2 toilettes (-j 2). GNU sem prend '1' dans une toilette, et sort immédiatement. Pendant que '1' dort, un autre GNU sem prend '2' dans une toilette, et sort immédiatement.

Pendant que '1' et '2' dorment, un autre GNU sem attend une toilette libre. Quand '1' finit, une toilette devient disponible, et ce GNU sem arrête d'attendre, prend '3' dans une toilette, et sort immédiatement.

Pendant que '2' et '3' dorment, un autre GNU sem attend une toilette libre. Quand '2' finit, une toilette devient disponible, et ce GNU sem arrête d'attendre, prend '4' dans une toilette, et sort immédiatement.

Finalement, un autre GNU sem attend que toutes les toilettes deviennent libres.

EXEMPLE : Compression de *.log avec gzip

Exécute un processus gzip par cœur CPU. Bloque jusqu'à ce qu'un cœur CPU devienne disponible.

for i in *.log ; do
  echo $i
  sem -j+0 gzip $i ";" echo done
done
sem --wait

EXEMPLE : Protéger pod2html de lui-même

pod2html crée deux fichiers : pod2htmd.tmp et pod2htmi.tmp qu'il ne nettoie pas. Il utilise ces deux fichiers pendant une courte période. Mais si vous exécutez plusieurs pod2html en parallèle (par exemple, dans un Makefile avec make -j), il y a un risque que deux instances différentes de pod2html écrivent dans les fichiers en même temps :

# Peut échouer en raison de fichiers partagés pod2htmd.tmp/pod2htmi.tmp
foo.html:
        pod2html foo.pod --outfile foo.html
bar.html:
        pod2html bar.pod --outfile bar.html
$ make -j foo.html bar.html

Vous devez protéger pod2html contre une double exécution simultanée. sem fonctionnant comme un mutex assurera qu'un seul s'exécute :

foo.html:
        sem --id pod2html pod2html foo.pod --outfile foo.html
bar.html:
        sem --id pod2html pod2html bar.pod --outfile bar.html
clean: foo.html bar.html
        sem --id pod2html --wait

sem(1) - Manuel Linux

NOM

sem - Gère un nombre quelconque de sémaphores

SYNOPIS

sem [OPTION]... [COMMAND]...

DESCRIPTION

Gère un nombre quelconque de sémaphores.

La commande sem peut être utilisée pour exécuter COMMAND(s) si tous les sémaphores spécifiés par sem sont disponibles. Sinon, elle attend.

La commande sem gère les sémaphores qui sont enregistrés dans le système de fichiers sous /dev/shm.

La commande sem est une commande wrapper pour parallel(1).

Les sémaphores sont créés et utilisés par le système de fichiers. Ainsi, même si sem est arrêté, les sémaphores existent toujours.

Utilisez sem --remove pour supprimer des sémaphores.

Utilisez sem --list pour lister les sémaphores.

Les sémaphores sont des fichiers dans le système de fichiers. Le nom du fichier indique le sémaphore.

Le nombre total de sémaphores est limité par la mémoire partagée du système.

Pour les exemples, voir la section EXEMPLES.

OPTIONS

--timeout SECONDS
Définit le délai d'attente en secondes pour acquérir les sémaphores.
--remove SEMAPHORES...
Supprime les sémaphores spécifiés. Si aucun sémaphore n'est spécifié, supprime tous les sémaphores utilisés par sem.
--list
Liste tous les sémaphores utilisés par sem.
--help
Affiche l'aide et quitte.
--version
Affiche les informations sur la version et quitte.

COMPRENDRE UN SÉMAPHORE

Un sémaphore est un fichier dans le système de fichiers. Le contenu du fichier indique le nombre de ressources disponibles. La commande sem utilise le nom du fichier pour identifier le sémaphore. Le contenu du fichier est géré par la commande sem.

Lorsqu'une commande est exécutée, sem essaie d'acquérir le sémaphore en décrémentant le contenu du fichier. Si le contenu est zéro, sem attend jusqu'à ce que le sémaphore soit libéré.

Lorsqu'une commande se termine, sem libère le sémaphore en incrémentant le contenu du fichier.

EXEMPLE : COMPRESSER LES FICHIERS *.log

Pour compresser tous les fichiers *.log en utilisant gzip, mais en limitant le nombre de processus gzip à 4:

   sem --fg --jobs 4 gzip *.log

Cela crée un sémaphore nommé gzip et limite le nombre de processus gzip à 4.

EXEMPLE : PROTÉGER POD2HTML DE LUI-MÊME

Pour exécuter pod2html pour plusieurs fichiers, mais en limitant le nombre de processus pod2html à 2 afin d'éviter une utilisation excessive des ressources:

   rm -f pod2htmd.tmp pod2htmi.tmp
   make -j foo.html bar.html clean
