FBB::Semaphore(3bobcat) Sémaphore de Dijkstra FBB::Semaphore(3bobcat)

NOM

FBB::Semaphore - Implémente le type Semaphore conçu par Dijkstra

SYNOPIS

#include <bobcat/semaphore>

Option de liaison : -lpthread -lbobcat

DESCRIPTION

Selon http://en.wikipedia.org/wiki/Semaphore_(programming), un sémaphore est une variable ou un type de données abstrait utilisé pour contrôler l'accès, par plusieurs processus, à une ressource commune dans un environnement de programmation parallèle ou multi-utilisateur. Le Semaphore en tant que type de données a été conçu vers 1962 par Edsger Dijkstra.

Une façon utile de penser à un sémaphore est comme un enregistrement du nombre d'unités d'une ressource particulière disponibles, couplé à des opérations pour ajuster cet enregistrement de manière sûre (c'est-à-dire sans conditions de concurrence) lorsque des unités sont requises ou libérées, et, si nécessaire, attendre qu'une unité de la ressource devienne disponible.

Les sémaphores sont un outil utile pour la prévention des conditions de concurrence. Les sémaphores autorisant un compte de ressources arbitraire sont appelés sémaphores de comptage, tandis que les sémaphores restreints aux valeurs 0 et 1 (ou verrouillé/déverrouillé, indisponible/disponible) sont appelés sémaphores binaires. Les deux types sont pris en charge par l'implémentation de Bobcat.

ESPACE DE NOMMAGE

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de nommage FBB.

CONSTRUCTEURS

o
Semaphore(size_t nDisponible) :
Le constructeur définit l'état initial du sémaphore. Avec un sémaphore de comptage, nDisponible définit, par exemple, le nombre d'emplacements disponibles dans une zone de stockage. Le verrouillage/déverrouillage, le support des installations pour notifier d'autres threads en attente, sont implémentés via des sémaphores binaires, initialisés à 1 ou 0. Un sémaphore contenant la valeur 0 bloque. Autrement dit, son membre wait attend jusqu'à ce que sa valeur soit incrémentée par un autre thread, appelant un des membres notify du sémaphore.

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) ne sont pas disponibles.

FONCTIONS MEMBRES

o
void notify() :
La valeur interne disponible est incrémentée et un thread en attente (voir les membres wait ci-dessous) est notifié, réactivant ce thread.
o
void notify_all() :
La valeur interne disponible est incrémentée et tous les threads en attente (voir les membres wait ci-dessous) sont notifiés. Un seul thread en attente pourra obtenir le verrou du sémaphore et réduire disponible, et ce thread particulier est alors réactivé.
o
void set(size_t disponible) :
Ce membre bloque jusqu'à ce qu'il ait obtenu le verrou du std::mutex maintenu en interne par l'objet Semaphore. Ensuite, la valeur disponible du Semaphore reçoit la valeur de l'argument du membre, et le verrou est libéré.
o
size_t size() const :
Sans tenter de verrouiller le mutex de l'objet Semaphore, la valeur actuelle de la valeur disponible du Semaphore est renvoyée.
o
void wait() :
Ce membre bloque tant que la valeur stockée en interne (disponible) est égale à zéro. Au retour de wait, le thread courant détient le verrou du std::mutex maintenu en interne par l'objet Semaphore. Les membres Notify sont utilisés pour incrémenter disponible et informer wait qu'il peut retourner. Lorsque plusieurs threads attendent, un seul thread arrêtera d'attendre, tandis que les threads restants continueront d'attendre une autre notification.
o
bool wait(Fun fun, Params &&...args) :
Il s'agit d'un template de membre, où Fun est une fonction (objet) recevant l'argument passé à wait et retournant un bool. Ce membre bloque jusqu'à ce qu'il ait obtenu le verrou du mutex du Semaphore, puis, tant que sa valeur disponible est égale à 0, il attend d'être notifié. Une fois qu'il a réacquis le verrou après avoir été notifié, fun est appelée, recevant les arguments restants de wait parfaitement transférés. Ce membre retourne false si fun retourne false. Il retourne true si fun retourne true et si disponible était inégal à zéro après que fun ait retourné true. La fonction peut donc effectuer des tâches en dehors de l'environnement local du Semaphore, qui pourraient même impliquer la mise à jour de la valeur disponible du Semaphore.
o
std::cv_status wait_for(std::chrono::duration<Rep, Period> const &relTime) :
Ce membre bloque tant que la valeur stockée en interne (disponible) est égale à zéro et que la durée spécifiée par relTime n'est pas écoulée. Si cette dernière se produit, std::cv_status::timeout est renvoyé, sinon std::cv_status::no_timeout est renvoyé, auquel cas le thread courant détient le verrou du std::mutex maintenu en interne par l'objet Semaphore. Les membres Notify sont utilisés pour incrémenter disponible et informer wait qu'il peut retourner. Lorsque plusieurs threads attendent, un seul thread arrête d'attendre, tandis que les threads restants continuent d'attendre une autre notification.
o
std::cv_status wait_until(std::chrono::time_point<Clock, Duration> const &absTime) :
Ce membre bloque tant que la valeur stockée en interne (disponible) est égale à zéro et que l'heure spécifiée par absTime n'a pas été atteinte. Si cette dernière se produit (ou si absTime se situe dans le passé), std::cv_status::timeout est renvoyé, sinon std::cv_status::no_timeout est renvoyé, auquel cas le thread courant détient le verrou du std::mutex maintenu en interne par l'objet Semaphore. Les membres Notify sont utilisés pour incrémenter disponible et informer wait qu'il peut retourner. Lorsque plusieurs threads attendent, un seul thread arrête d'attendre, tandis que les threads restants continuent d'attendre une autre notification.

EXEMPLE

    #include <bobcat/semaphore>
    using namespace FBB;
    Semaphore produce(10);          // taille de la zone de stockage
    Semaphore consume(0);           // # articles en magasin
    std::queue itemQueue;           // file de stockage
    void consumer()
    {
        while (true)
        {
            consume.wait();          // attendre qu'il y ait un article en magasin
                // verrouiller la file avec plusieurs consommateurs
            size_t item = itemQueue.front();
            itemQueue.pop();
            produce.notify();   // notifier le producteur
            process(item);      // non implémenté
        }
    }
    void producer()
    {
        size_t item = 0;
        while (true)
        {
            ++item;
            produce.wait();     // attendre de la place dans le stockage
                // verrouiller la file avec plusieurs consommateurs
            itemQueue.push(item);
            consume.notify();   // notifier le consommateur
        }
    }
    int main()
    {
        thread cons(consumer);
        thread prod(producer);
        cons.join();            // fin des threads non implémentée
        prod.join();
    }
