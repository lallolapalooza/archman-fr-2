SEM_OPEN(3P) Manuel du programmeur POSIX SEM_OPEN(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sem_open — initialiser et ouvrir un sémaphore nommé

SYNTAXE

#include <semaphore.h>
sem_t *sem_open(const char *name, int oflag, ...);

DESCRIPTION

La fonction sem_open() établit une connexion entre un sémaphore nommé et un processus. Suite à un appel à sem_open() avec le nom de sémaphore name, le processus peut référencer le sémaphore associé à name en utilisant l'adresse retournée par l'appel. Ce sémaphore peut être utilisé dans des appels ultérieurs à sem_wait(), sem_timedwait(), sem_trywait(), sem_post(), et sem_close(). Le sémaphore reste utilisable par ce processus jusqu'à ce qu'il soit fermé par un appel réussi à sem_close(), _exit(), ou l'une des fonctions exec.

L'argument oflag contrôle si le sémaphore est créé ou simplement accédé par l'appel à sem_open(). Les bits de drapeau suivants peuvent être définis dans oflag :

O_CREAT
Ce drapeau est utilisé pour créer un sémaphore s'il n'existe pas déjà. Si O_CREAT est défini et que le sémaphore existe déjà, alors O_CREAT n'a aucun effet, sauf indication contraire sous O_EXCL. Sinon, sem_open() crée un sémaphore nommé. Le drapeau O_CREAT nécessite un troisième et un quatrième argument : mode, qui est de type mode_t, et value, qui est de type unsigned. Le sémaphore est créé avec une valeur initiale de value. Les valeurs initiales valides pour les sémaphores sont inférieures ou égales à {SEM_VALUE_MAX}.

L'ID utilisateur du sémaphore sera défini à l'ID utilisateur effectif du processus. L'ID de groupe du sémaphore sera défini à l'ID de groupe effectif du processus ; cependant, si l'argument name est visible dans le système de fichiers, l'ID de groupe peut être défini à l'ID de groupe du répertoire parent. Les bits d'autorisation du sémaphore sont définis à la valeur de l'argument mode, à l'exception de ceux définis dans le masque de création de mode de fichier du processus. Lorsque des bits dans mode autres que les bits d'autorisation de fichier sont spécifiés, l'effet est indéterminé.

Après que le sémaphore nommé name a été créé par sem_open() avec le drapeau O_CREAT, d'autres processus peuvent se connecter au sémaphore en appelant sem_open() avec la même valeur de name.

O_EXCL
Si O_EXCL et O_CREAT sont définis, sem_open() échoue si le sémaphore name existe. La vérification de l'existence du sémaphore et la création du sémaphore s'il n'existe pas sont atomiques par rapport aux autres processus exécutant sem_open() avec O_EXCL et O_CREAT définis. Si O_EXCL est défini et O_CREAT n'est pas défini, l'effet est indéfini.

Si des drapeaux autres que O_CREAT et O_EXCL sont spécifiés dans le paramètre oflag, l'effet est indéterminé.

L'argument name pointe vers une chaîne nommant un objet sémaphore. Il est indéterminé si le nom apparaît dans le système de fichiers et est visible par les fonctions qui prennent des noms de chemin comme arguments. L'argument name est conforme aux règles de construction pour un nom de chemin, sauf que l'interprétation des caractères <slash> autres que le caractère <slash> initial dans name est définie par l'implémentation, et que les limites de longueur pour l'argument name sont définies par l'implémentation et n'ont pas besoin d'être les mêmes que les limites de chemin {PATH_MAX} et {NAME_MAX}. Si name commence par le caractère <slash>, alors les processus appelant sem_open() avec la même valeur de name feront référence au même objet sémaphore, tant que ce nom n'a pas été supprimé. Si name ne commence pas par le caractère <slash>, l'effet est défini par l'implémentation.

Si un processus effectue plusieurs appels réussis à sem_open() avec la même valeur pour name, la même adresse de sémaphore sera retournée pour chacun de ces appels réussis, à condition qu'il n'y ait eu aucun appel à sem_unlink() pour ce sémaphore, et qu'au moins un appel précédent réussi à sem_open() pour ce sémaphore n'ait pas été mis en correspondance avec un appel sem_close().

Les références à des copies du sémaphore produisent des résultats indéfinis.

VALEUR DE RETOUR

En cas de succès, la fonction sem_open() retourne l'adresse du sémaphore. Sinon, elle retourne une valeur de SEM_FAILED et définit errno pour indiquer l'erreur. Le symbole SEM_FAILED est défini dans l'en-tête <semaphore.h>. Aucun retour réussi de sem_open() ne doit retourner la valeur SEM_FAILED.

ERREURS

Si l'une des conditions suivantes se produit, la fonction sem_open() retournera SEM_FAILED et définira errno à la valeur correspondante :

EACCES
Le sémaphore nommé existe et les permissions spécifiées par oflag sont refusées, ou le sémaphore nommé n'existe pas et la permission de créer le sémaphore nommé est refusée.
EEXIST
O_CREAT et O_EXCL sont définis et le sémaphore nommé existe déjà.
EINTR
L'opération sem_open() a été interrompue par un signal.
EINVAL
L'opération sem_open() n'est pas prise en charge pour le nom donné, ou O_CREAT a été spécifié dans oflag et value était supérieur à {SEM_VALUE_MAX}.
EMFILE
Trop de descripteurs de sémaphores ou de descripteurs de fichiers sont actuellement utilisés par ce processus.
ENFILE
Trop de sémaphores sont actuellement ouverts dans le système.
ENOENT
O_CREAT n'est pas défini et le sémaphore nommé n'existe pas.
ENOMEM
Il n'y a pas assez de mémoire pour la création du nouveau sémaphore nommé.
ENOSPC
Il n'y a pas assez d'espace sur un périphérique de stockage pour la création du nouveau sémaphore nommé.

Si l'une des conditions suivantes se produit, la fonction sem_open() peut retourner SEM_FAILED et définir errno à la valeur correspondante :

ENAMETOOLONG

La longueur de l'argument name dépasse {_POSIX_PATH_MAX} sur les systèmes qui ne prennent pas en charge l'option XSI ou dépasse {_XOPEN_PATH_MAX} sur les systèmes XSI, ou possède un composant de chemin plus long que {_POSIX_NAME_MAX} sur les systèmes qui ne prennent pas en charge l'option XSI ou plus long que {_XOPEN_NAME_MAX} sur les systèmes XSI.

RATIONNEL

Les premières versions exigeaient une valeur de retour d'erreur de -1 avec le type sem_t * pour la fonction sem_open(), ce qui n'est pas garanti d'être portable entre les implémentations. Le texte révisé fournit le code d'erreur symbolique SEM_FAILED pour éliminer le conflit de type.

ORIENTATIONS FUTURES

Une version future pourrait exiger que les fonctions sem_open() et sem_unlink() aient des sémantiques similaires aux opérations normales du système de fichiers.
