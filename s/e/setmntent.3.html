getmntent(3) Manuel des fonctions de bibliothèque getmntent(3)

NOM

getmntent, setmntent, addmntent, endmntent, hasmntopt, getmntent_r - obtenir une entrée du fichier de descripteurs de système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdio.h>
#include <mntent.h>
FILE *setmntent(const char *path, const char *type);
struct mntent *getmntent(FILE *stream);
int addmntent(FILE *restrict stream,
              const struct mntent *restrict mnt);
int endmntent(FILE *streamp);
char *hasmntopt(const struct mntent *mnt, const char *opt);
/* Extension GNU */
#include <mntent.h>
struct mntent *getmntent_r(int size;
              FILE *restrict streamp,
              struct mntent *restrict mntbuf,
              char buf[restrict size], int size);
Exigences pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)):

getmntent_r():

    Depuis glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Ces routines sont utilisées pour accéder au fichier de description des systèmes de fichiers /etc/fstab et au fichier de description des systèmes de fichiers montés /etc/mtab.

La fonction setmntent() ouvre le fichier de description des systèmes de fichiers path et retourne un pointeur de fichier qui peut être utilisé par getmntent(). L'argument type est le type d'accès requis et peut prendre les mêmes valeurs que l'argument mode de fopen(3). Le flux retourné doit être fermé en utilisant endmntent() plutôt que fclose(3).

La fonction getmntent() lit la ligne suivante du fichier de description des systèmes de fichiers à partir de stream et retourne un pointeur vers une structure contenant les champs décomposés d'une ligne du fichier. Le pointeur pointe vers une zone mémoire statique qui est écrasée par les appels ultérieurs à getmntent().

La fonction addmntent() ajoute la structure mntent mnt à la fin du flux ouvert stream.

La fonction endmntent() ferme le stream associé au fichier de description des systèmes de fichiers.

La fonction hasmntopt() scanne le champ mnt_opts (voir ci-dessous) de la structure mntent mnt à la recherche d'une sous-chaîne correspondant à opt. Voir <mntent.h> et mount(8) pour les options de montage valides.

La fonction réentrante getmntent_r() est similaire à getmntent(), mais stocke la structure mntent dans *mntbuf fourni, et stocke les chaînes pointées par les entrées de cette structure dans le tableau buf fourni de taille size.

La structure mntent est définie dans <mntent.h> comme suit:


struct mntent {
    char *mnt_fsname;   /* nom du système de fichiers monté */
    char *mnt_dir;      /* chemin préfixe du système de fichiers */
    char *mnt_type;     /* type de montage (voir mntent.h) */
    char *mnt_opts;     /* options de montage (voir mntent.h) */
    int   mnt_freq;     /* fréquence de vidage en jours */
    int   mnt_passno;   /* numéro de passage pour fsck parallèle */
};

Étant donné que les champs des fichiers mtab et fstab sont séparés par des espaces blancs, des échappements octaux sont utilisés pour représenter les caractères espace (\040), tabulation (\011), nouvelle ligne (\012) et antislash (\\) dans ces fichiers lorsqu'ils apparaissent dans l'une des quatre chaînes d'une structure mntent. Les routines addmntent() et getmntent() convertiront de la représentation chaîne vers la représentation échappée et vice versa. Lors de la conversion depuis la représentation échappée, la séquence \134 est également convertie en antislash.

VALEUR DE RETOUR

Les fonctions getmntent() et getmntent_r() retournent un pointeur vers la structure mntent ou NULL en cas d'échec.

La fonction addmntent() retourne 0 en cas de succès et 1 en cas d'échec.

La fonction endmntent() retourne toujours 1.

La fonction hasmntopt() retourne l'adresse de la sous-chaîne si une correspondance est trouvée, et NULL sinon.

FICHIERS

fichier de description des systèmes de fichiers
/etc/mtab

NORMES

Aucune.

HISTORIQUE

Les fonctions non réentrantes proviennent de SunOS 4.1.3. Une routine getmntent_r() a été introduite dans HP-UX 10, mais elle retourne un int. Le prototype montré ci-dessus est spécifique à glibc.

System V possède également une fonction getmntent(), mais la séquence d'appel diffère et la structure retournée est différente. Sous System V, /etc/mnttab est utilisé. 4.4BSD et Digital UNIX ont une routine getmntinfo(), un wrapper autour de l'appel système getfsstat().
