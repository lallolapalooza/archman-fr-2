set_thread_area(2) Manuel des appels système set_thread_area(2)

NOM

get_thread_area, set_thread_area - manipuler les informations de stockage local aux threads

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
#if defined __i386__ || defined __x86_64__
# include <asm/ldt.h>        /* Définition de struct user_desc */
int syscall(SYS_get_thread_area, struct user_desc *u_info);
int syscall(SYS_set_thread_area, struct user_desc *u_info);
#elif defined __m68k__
int syscall(SYS_get_thread_area);
int syscall(SYS_set_thread_area, unsigned long tp);
#elif defined __mips__ || defined __csky__
int syscall(SYS_set_thread_area, unsigned long addr);
#endif

Note : glibc ne fournit pas d'enveloppes pour ces appels système, ce qui rend nécessaire l'utilisation de syscall(2).

DESCRIPTION

Ces appels fournissent un support spécifique à l'architecture pour une implémentation de stockage local aux threads. Actuellement, set_thread_area() est disponible sur m68k, MIPS, C-SKY et x86 (variantes 32 bits et 64 bits) ; get_thread_area() est disponible sur m68k et x86.

Sur m68k, MIPS et C-SKY, set_thread_area() permet de stocker un pointeur arbitraire (fourni dans l'argument tp sur m68k et dans l'argument addr sur MIPS et C-SKY) dans la structure de données du noyau associée au thread appelant ; ce pointeur peut être récupéré ultérieurement en utilisant get_thread_area() (voir aussi NOTES pour des informations concernant l'obtention du pointeur de thread sur MIPS).

Sur x86, Linux dédie trois entrées de la table globale des descripteurs (GDT) au stockage local aux threads. Pour plus d'informations sur la GDT, voir le Manuel du développeur logiciel Intel ou le Manuel de programmation de l'architecture AMD.

Ces deux appels système prennent un argument qui est un pointeur vers une structure du type suivant :


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;
#ifdef __x86_64__
    unsigned int  lm:1;
#endif
};

get_thread_area() lit l'entrée GDT indiquée par u_info->entry_number et remplit les autres champs de u_info.

set_thread_area() définit une entrée TLS dans la GDT.

L'entrée du tableau TLS définie par set_thread_area() correspond à la valeur de u_info->entry_number passée par l'utilisateur. Si cette valeur est dans les limites, set_thread_area() écrit le descripteur TLS pointé par u_info dans le tableau TLS du thread.

Lorsque set_thread_area() reçoit un entry_number de -1, il recherche une entrée TLS libre. Si set_thread_area() trouve une entrée TLS libre, la valeur de u_info->entry_number est définie au retour pour indiquer quelle entrée a été modifiée.

Un user_desc est considéré comme "vide" si read_exec_only et seg_not_present sont définis à 1 et tous les autres champs sont à 0. Si un descripteur "vide" est passé à set_thread_area(), l'entrée TLS correspondante sera effacée. Voir BUGS pour plus de détails.

Depuis Linux 3.19, set_thread_area() ne peut pas être utilisé pour écrire des segments non présents, des segments 16 bits ou des segments de code, bien que l'effacement d'un segment soit toujours acceptable.

VALEUR DE RETOUR

Sur x86, ces appels système retournent 0 en cas de succès et -1 en cas d'échec, avec errno défini pour indiquer l'erreur.

Sur C-SKY, MIPS et m68k, set_thread_area() retourne toujours 0. Sur m68k, get_thread_area() retourne la valeur du pointeur de zone de thread (précédemment définie via set_thread_area()).

ERREURS

EFAULT
u_info est un pointeur invalide.
EINVAL
u_info->entry_number est hors limites.
ENOSYS
get_thread_area() ou set_thread_area() a été invoqué en tant qu'appel système 64 bits.
ESRCH
(set_thread_area()) Une entrée TLS libre n'a pas pu être trouvée.

NORMES

Linux.

HISTORIQUE

set_thread_area()
Linux 2.5.29.
get_thread_area()
Linux 2.5.32.

NOTES

Ces appels système sont généralement destinés à être utilisés uniquement par les bibliothèques de threads.

arch_prctl(2) peut interférer avec set_thread_area() sur x86. Voir arch_prctl(2) pour plus de détails. Ceci n'est normalement pas un problème, car arch_prctl(2) est normalement utilisé uniquement par les programmes 64 bits.

Sur MIPS, la valeur actuelle du pointeur de zone de thread peut être obtenue en utilisant l'instruction :


rdhwr dest, $29

Cette instruction provoque une interruption et est gérée par le noyau.

BOGUES

Sur les noyaux 64 bits avant Linux 3.19, l'un des bits de remplissage dans user_desc, s'il était défini, empêchait le descripteur d'être considéré comme vide (voir modify_ldt(2)). Par conséquent, la seule façon fiable d'effacer une entrée TLS est d'utiliser memset(3) pour mettre à zéro toute la structure user_desc, y compris les bits de remplissage, puis de définir les bits read_exec_only et seg_not_present. Sur Linux 3.19, un user_desc entièrement composé de zéros à l'exception de entry_number sera également interprété comme une demande d'effacement d'une entrée TLS, mais cela se comportait différemment sur les anciens noyaux.

Avant Linux 3.19, les registres de segment DS et ES ne devaient pas référencer les entrées TLS.

VOIR AUSSI

arch_prctl(2), modify_ldt(2), ptrace(2) (PTRACE_GET_THREAD_AREA et PTRACE_SET_THREAD_AREA)
