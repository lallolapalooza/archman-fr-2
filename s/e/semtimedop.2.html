semop(2) Manuel des appels système semop(2)

NOM

semop, semtimedop - opérations sur les sémaphores System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);
int semtimedop(int semid, struct sembuf *sops, size_t nsops,
               const struct timespec *_Nullable timeout);
Exigences pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)):

semtimedop():

    _GNU_SOURCE

DESCRIPTION

Chaque sémaphore dans un ensemble de sémaphores System V possède les valeurs associées suivantes :


unsigned short  semval;   /* valeur du sémaphore */
unsigned short  semzcnt;  /* # en attente de zéro */
unsigned short  semncnt;  /* # en attente d'augmentation */
pid_t           sempid;   /* PID du processus qui a dernièrement
                             modifié la valeur du sémaphore */

semop() effectue des opérations sur des sémaphores sélectionnés dans l'ensemble indiqué par semid. Chacun des nsops éléments dans le tableau pointé par sops est une structure qui spécifie une opération à effectuer sur un seul sémaphore. Les éléments de cette structure sont de type struct sembuf, contenant les membres suivants :


unsigned short sem_num;  /* numéro du sémaphore */
short          sem_op;   /* opération sur le sémaphore */
short          sem_flg;  /* drapeaux d'opération */

Les drapeaux reconnus dans sem_flg sont IPC_NOWAIT et SEM_UNDO. Si une opération spécifie SEM_UNDO, elle sera automatiquement annulée lorsque le processus se terminera.

L'ensemble des opérations contenu dans sops est effectué dans l'ordre du tableau, et atomiquement, c'est-à-dire que les opérations sont effectuées soit comme une unité complète, soit pas du tout. Le comportement de l'appel système si toutes les opérations ne peuvent pas être effectuées immédiatement dépend de la présence du drapeau IPC_NOWAIT dans les champs individuels sem_flg, comme indiqué ci-dessous.

Chaque opération est effectuée sur le sémaphore numéro sem_num de l'ensemble de sémaphores, où le premier sémaphore de l'ensemble est numéroté 0. Il existe trois types d'opérations, distinguées par la valeur de sem_op.

Si sem_op est un entier positif, l'opération ajoute cette valeur à la valeur du sémaphore (semval). De plus, si SEM_UNDO est spécifié pour cette opération, le système soustrait la valeur sem_op de l'ajustement de sémaphore (semadj) pour ce sémaphore. Cette opération peut toujours se dérouler - elle ne force jamais un thread à attendre. Le processus appelant doit avoir la permission de modification sur l'ensemble de sémaphores.

Si sem_op est zéro, le processus doit avoir la permission de lecture sur l'ensemble de sémaphores. Il s'agit d'une opération de "attente de zéro" : si semval est zéro, l'opération peut immédiatement se dérouler. Sinon, si IPC_NOWAIT est spécifié dans sem_flg, semop() échoue avec errno défini à EAGAIN (et aucune des opérations dans sops n'est effectuée). Sinon, semzcnt (le nombre de threads en attente que la valeur de ce sémaphore devienne zéro) est incrémenté de un et le thread dort jusqu'à ce que l'une des conditions suivantes se produise :

•
semval devient 0, auquel cas la valeur de semzcnt est décrémentée.
•
L'ensemble de sémaphores est supprimé : semop() échoue, avec errno défini à EIDRM.
•
Le thread appelant intercepte un signal : la valeur de semzcnt est décrémentée et semop() échoue, avec errno défini à EINTR.

Si sem_op est négatif, le processus doit avoir la permission de modification sur l'ensemble de sémaphores. Si semval est supérieur ou égal à la valeur absolue de sem_op, l'opération peut se dérouler immédiatement : la valeur absolue de sem_op est soustraite de semval, et, si SEM_UNDO est spécifié pour cette opération, le système ajoute la valeur absolue de sem_op à la valeur d'ajustement de sémaphore (semadj) pour ce sémaphore. Si la valeur absolue de sem_op est supérieure à semval, et que IPC_NOWAIT est spécifié dans sem_flg, semop() échoue, avec errno défini à EAGAIN (et aucune des opérations dans sops n'est effectuée). Sinon, semncnt (le compteur des threads en attente que la valeur de ce sémaphore augmente) est incrémenté de un et le thread dort jusqu'à ce que l'une des conditions suivantes se produise :

•
semval devient supérieur ou égal à la valeur absolue de sem_op : l'opération se déroule alors, comme décrit ci-dessus.
•
L'ensemble de sémaphores est supprimé du système : semop() échoue, avec errno défini à EIDRM.
•
Le thread appelant intercepte un signal : la valeur de semncnt est décrémentée et semop() échoue, avec errno défini à EINTR.

En cas de succès, la valeur sempid pour chaque sémaphore spécifié dans le tableau pointé par sops est définie à l'ID du processus appelant. De plus, sem_otime est définie à l'heure actuelle.

semtimedop()

semtimedop() se comporte de manière identique à semop() sauf que dans les cas où le thread appelant dormirait, la durée de ce sommeil est limitée par le temps écoulé spécifié par la structure timespec dont l'adresse est passée dans l'argument timeout. (Cet intervalle de sommeil sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle peut être dépassé d'une petite quantité.) Si la limite de temps spécifiée a été atteinte, semtimedop() échoue avec errno défini à EAGAIN (et aucune des opérations dans sops n'est effectuée). Si l'argument timeout est NULL, alors semtimedop() se comporte exactement comme semop().

Notez que si semtimedop() est interrompu par un signal, provoquant l'échec de l'appel avec l'erreur EINTR, le contenu de timeout reste inchangé.

VALEUR DE RETOUR

En cas de succès, semop() et semtimedop() retournent 0. En cas d'échec, ils retournent -1, et définissent errno pour indiquer l'erreur.

NOM

semop — opérations sur les sémaphores système V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, —li)

SYNTAXE

#include <sys/sem.h>

int semop(int semid, struct sembuf *sops, size_t nsops);

DESCRIPTION

La fonction semop() exécute un tableau d'opérations sur des sémaphores système V. Le tableau est spécifié par l'argument sops, et sa taille est donnée par nsops. Chaque élément du tableau sops, de type struct sembuf, spécifie une opération à effectuer sur un sémaphore particulier.

La structure sembuf a la forme suivante :

struct sembuf {
    unsigned short sem_num;     /* Index du sémaphore dans le jeu */
    short          sem_op;        /* Opération sur le sémaphore */
    short          sem_flg;       /* Indicateurs */
};

Pour un appel semop() donné, toutes les opérations spécifiées sont effectuées de manière atomique. Si une opération ne peut pas être effectuée immédiatement, l'appel semop() sera bloqué, sauf si l'indicateur IPC_NOWAIT est spécifié.

Les membres de struct sembuf ont la signification suivante :

sem_num
Index du sémaphore dans le jeu de sémaphores associé à semid. Les index sont basés sur zéro.
sem_op
Opération sur le sémaphore :
  • Si sem_op est positif, la valeur du sémaphore est augmentée de sem_op.
  • Si sem_op est négatif, la valeur du sémaphore est diminuée de la valeur absolue de sem_op. L'opération échouera si la valeur résultante du sémaphore est inférieure à zéro.
  • Si sem_op est zéro, l'opération réussira seulement si la valeur actuelle du sémaphore est zéro. L'appel semop() attendra que la valeur du sémaphore devienne zéro.
sem_flg
Un masque d'indicateurs qui modifie le comportement des opérations. La valeur peut être zéro, ou une combinaison de IPC_NOWAIT et SEM_UNDO.

L'indicateur IPC_NOWAIT (défini dans <sys/ipc.h>) a le même effet que pour msgsnd(2) et msgrcv(2). Si une opération ne peut pas être effectuée immédiatement, semop() renvoie une erreur.

L'indicateur SEM_UNDO, lorsqu'il est spécifié dans sem_flg pour une opération, indique que l'opération doit être "annulée" lorsque le processus se termine. Pour chaque sémaphore sur lequel une opération avec SEM_UNDO est effectuée, le système maintient une valeur de correction (le "semadj"). Cette valeur est l'opposé de la somme de toutes les opérations SEM_UNDO effectuées par le processus sur ce sémaphore. Lorsque le processus se termine, ces valeurs de correction sont ajoutées aux valeurs des sémaphores correspondants. Ceci permet de garantir que les opérations sur les sémaphores ne restent pas "bloquées" indéfiniment si un processus se termine de manière inattendue. Les valeurs SEM_UNDO sont également effacées lorsque la valeur d'un sémaphore est définie directement par semctl(2) avec les commandes SETVAL ou SETALL.

Si plusieurs opérations sont spécifiées dans le tableau sops, elles sont exécutées dans l'ordre où elles apparaissent dans le tableau. Cependant, l'ensemble de toutes les opérations est effectué de manière atomique. Cela signifie qu'un processus qui observe l'état des sémaphores ne verra jamais un état intermédiaire causé par une opération au sein d'un appel semop() atomique.

Si nsops est supérieur à 1, les opérations sont effectuées de manière atomique. Pour un appel semop() atomic, toutes les opérations doivent pouvoir être effectuées sans bloquer, à moins que l'indicateur IPC_NOWAIT ne soit utilisé pour l'une des opérations. Si IPC_NOWAIT n'est pas utilisé, et si l'une des opérations doit bloquer, l'appel semop() bloque jusqu'à ce que toutes les opérations puissent être effectuées ou que le processus reçoive un signal.

Lorsque nsops est égal à 1, l'opération est effectuée et le comportement est le même que si IPC_NOWAIT était spécifié.

Le comportement en cas d'interruption par un signal est sujet aux règles générales des appels système interrompus par un signal. En particulier, semop() n'est jamais automatiquement redémarré après avoir été interrompu par un gestionnaire de signaux, indépendamment de la valeur de l'indicateur SA_RESTART lors de l'établissement du gestionnaire de signaux.

VALEUR DE RETOUR

En cas de succès, semop() renvoie 0. En cas d'erreur, il renvoie -1 et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Accès refusé. Les permissions d'accès requises pour l'opération sur le jeu de sémaphores ne sont pas accordées.
EAGAIN
Opération à faire. L'opération aurait bloqué et l'indicateur IPC_NOWAIT était spécifié.
ECHILD
Processus enfant terminé. Ceci peut se produire dans le contexte de SEM_UNDO lors de la terminaison d'un processus.
EINVAL
Identifiant de sémaphore invalide (semid) ou le nombre de sémaphores dans le jeu est insuffisant pour sem_num.
EINTR
Appel système interrompu par un signal.
EIO
Erreur d'entrée/sortie.
ENOSPC
Espace insuffisant dans le système. Peut se produire lors de l'allocation de la structure de correction (undo) lorsque SEM_UNDO est utilisé, si la limite du nombre de structures d'annulation système est atteinte.
NOSPC
Espace insuffisant dans le système. Similaire à ENOSPC.
ERANGE
Valeur en dehors de la plage autorisée. La valeur du sémaphore résultant d'une opération SEM_UNDO dépasse la valeur maximale autorisée pour un sémaphore.

NORMES

POSIX.1-2024.

VERSIONS

Linux 2.5.52 (rétroporté dans Linux 2.4.22), glibc 2.3.3. POSIX.1-2001, SVr4.

NOTES

Les structures sem_undo d'un processus ne sont pas héritées par l'enfant produit par fork(2), mais elles sont héritées lors d'un appel système execve(2).

semop() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signaux, quelle que soit la valeur de l'indicateur SA_RESTART lors de l'établissement d'un gestionnaire de signaux.

Une valeur d'ajustement de sémaphore (semadj) est un entier par processus et par sémaphore qui est la somme négative de toutes les opérations effectuées sur un sémaphore spécifiant l'indicateur SEM_UNDO. Chaque processus a une liste de valeurs semadj — une valeur pour chaque sémaphore sur lequel il a opéré en utilisant SEM_UNDO. Lorsqu'un processus se termine, chacune de ses valeurs semadj par sémaphore est ajoutée au sémaphore correspondant, annulant ainsi l'effet des opérations de ce processus sur le sémaphore (mais voir BUGS ci-dessous). Lorsque la valeur d'un sémaphore est directement définie à l'aide de la requête SETVAL ou SETALL à semctl(2), les valeurs semadj correspondantes dans tous les processus sont effacées. L'indicateur CLONE_SYSVSEM de clone(2) permet à plus d'un processus de partager une liste semadj ; voir clone(2) pour plus de détails.

Les valeurs semval, sempid, semzcnt et semnct pour un sémaphore peuvent toutes être récupérées en utilisant les appels semctl(2) appropriés.

Limites de sémaphores

Les limites suivantes sur les ressources des jeux de sémaphores affectent l'appel semop():

SEMOPM
Nombre maximal d'opérations autorisées par appel semop(). Avant Linux 3.19, la valeur par défaut de cette limite était 32. Depuis Linux 3.19, la valeur par défaut est 500. Sous Linux, cette limite peut être lue et modifiée via le troisième champ de /proc/sys/kernel/sem. Note: cette limite ne doit pas être augmentée au-delà de 1000, en raison du risque que semop() échoue en raison de la fragmentation de la mémoire du noyau lors de l'allocation de mémoire pour copier le tableau sops.
SEMVMX
Valeur maximale autorisée pour semval : dépend de l'implémentation (32767).

L'implémentation n'a pas de limites intrinsèques pour la valeur maximale d'ajustement à la sortie (SEMAEM), le nombre maximal de structures d'annulation au niveau du système (SEMMNU) et le nombre maximal d'entrées d'annulation par processus, qui sont des paramètres système.

BOGUES

Lorsqu'un processus se termine, son ensemble de structures semadj associées est utilisé pour annuler l'effet de toutes les opérations de sémaphores qu'il a effectuées avec l'indicateur SEM_UNDO. Cela soulève une difficulté : si l'un (ou plusieurs) de ces ajustements de sémaphores devait entraîner une tentative de diminuer la valeur d'un sémaphore en dessous de zéro, que doit faire une implémentation ? Une approche possible serait de bloquer jusqu'à ce que tous les ajustements de sémaphores puissent être effectués. Ceci est cependant indésirable car cela pourrait forcer la terminaison du processus à bloquer pendant des périodes arbitrairement longues. Une autre possibilité est que ces ajustements de sémaphores soient ignorés (un peu comme un échec lorsque IPC_NOWAIT est spécifié pour une opération sur un sémaphore). Linux adopte une troisième approche : diminuer la valeur du sémaphore autant que possible (c'est-à-dire jusqu'à zéro) et permettre à la terminaison du processus de se poursuivre immédiatement.

Dans Linux 2.6.x, x <= 10, il y a un bogue qui, dans certaines circonstances, empêche un thread attendant qu'une valeur de sémaphore devienne zéro d'être réveillé lorsque la valeur devient effectivement zéro. Ce bogue est corrigé dans Linux 2.6.11.

EXEMPLES

Le segment de code suivant utilise semop() pour attendre atomiquement que la valeur du sémaphore 0 devienne zéro, puis incrémente la valeur du sémaphore de un.


struct sembuf sops[2];
int semid;
/* Code pour initialiser semid omis */
sops[0].sem_num = 0;        /* Opérer sur le sémaphore 0 */
sops[0].sem_op = 0;         /* Attendre que la valeur soit égale à 0 */
sops[0].sem_flg = 0;
sops[1].sem_num = 0;        /* Opérer sur le sémaphore 0 */
sops[1].sem_op = 1;         /* Incrémenter la valeur de un */
sops[1].sem_flg = 0;
if (semop(semid, sops, 2) == -1) {
    perror("semop");
    exit(EXIT_FAILURE);
}

Un autre exemple d'utilisation de semop() peut être trouvé dans shmop(2).
