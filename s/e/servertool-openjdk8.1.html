servertool(1) Outils Java IDL et RMI-IIOP servertool(1)

NOM

servertool - Fournit une interface simple à utiliser pour les développeurs afin d'enregistrer, désenregistrer, démarrer et arrêter un serveur persistant.

SYNTAXE

servertool -ORBInitialPort portserveurconnexion [ options ] [ commandes ]
options
Les options en ligne de commande. Voir Options.
commandes
Les commandes en ligne de commande. Voir Commandes.

DESCRIPTION

La commande servertool fournit l'interface en ligne de commande permettant aux développeurs d'enregistrer, désenregistrer, démarrer et arrêter un serveur persistant. Les commandes en ligne de commande vous permettent d'obtenir diverses informations statistiques sur le serveur. Voir Commandes.

OPTIONS

-ORBInitialHost hoteserveurconnexion

Cette option est requise. Elle spécifie la machine hôte sur laquelle le serveur de noms s'exécute et écoute les requêtes entrantes. La valeur hoteserveurconnexion doit spécifier le port sur lequel l orb s'exécute et écoute les requêtes. La valeur par défaut est localhost lorsque cette option n'est pas spécifiée. Si orbd et servertool s'exécutent sur des machines différentes, vous devez alors spécifier le nom ou l'adresse IP de l'hôte sur lequel orbd s'exécute.

Note : Sur Oracle Solaris, vous devez être utilisateur root pour démarrer un processus sur un port inférieur à 1024. Oracle recommande d'utiliser un numéro de port supérieur ou égal à 1024 pour la valeur portserveurconnexion.

-Joption

Passe option à la Machine Virtuelle Java, où option est l'une des options décrites sur la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).

COMMANDES

Vous pouvez démarrer la commande servertool avec ou sans commande en ligne de commande.

•
Si vous n'avez pas spécifié de commande lors du démarrage de servertool, alors l'outil en ligne de commande affiche l'invite servertool où vous pouvez entrer les commandes : servertool >.
•
Si vous spécifiez une commande lors du démarrage de servertool, alors l'outil serveur Java IDL démarre, exécute la commande et se termine.
register -server nom-classe-serveur -classpath chemin-classe-vers-serveur [ -applicationName nom-application -args arguments-pour-serveur -vmargs indicateurs-pour-JVM ]
Enregistre un nouveau serveur persistant auprès du démon de serveur de requêtes (ORBD). Si le serveur n'est pas déjà enregistré, alors il est enregistré et activé. Cette commande appelle une méthode d'installation dans la classe main du serveur identifié par l'option -server. La méthode d'installation doit être public static void install(org.omg.CORBA.ORB). La méthode install est optionnelle et permet aux développeurs de fournir leur propre comportement d'installation de serveur, comme la création d'un schéma de base de données.
unregister -serverid id-serveur | -applicationName nom-application
Désenregistre un serveur de l'ORBD soit par son identifiant de serveur, soit par son nom d'application. Cette commande appelle une méthode de désinstallation dans la classe main du serveur identifié par l'option -server. La méthode uninstall doit être public static void uninstall(org.omg.CORBA.ORB). La méthode uninstall est optionnelle et permet aux développeurs de fournir leur propre comportement de désinstallation de serveur, comme l'annulation du comportement de la méthode install.
getserverid -applicationName nom-application
Retourne l'identifiant du serveur qui correspond à la valeur nom-application.
list
Liste les informations sur tous les serveurs persistants enregistrés auprès de l'ORBD.
listappnames
Liste les noms d'application de tous les serveurs actuellement enregistrés auprès de l'ORBD.
listactive
Liste les informations sur tous les serveurs persistants qui ont été démarrés par l'ORBD et qui sont actuellement en cours d'exécution.
locate -serverid id-serveur | -applicationName nom-application [ -endpointType type-point-fin ]
Localise les points de fin (ports) d'un type spécifique pour tous les ORB créés par un serveur enregistré. Si un serveur n'est pas déjà en cours d'exécution, il est activé. Si une valeur type-point-fin n'est pas spécifiée, alors le point de fin simple/non protégé associé à chaque ORB dans un serveur est retourné.
locateperorb -serverid id-serveur | -applicationName nom-application [ -orbid nom-orb ]
Localise tous les points de fin (ports) enregistrés par un Broker de Requêtes Objet (ORB) spécifique d'un serveur enregistré. Si un serveur n'est pas déjà en cours d'exécution, il est activé. Si un orbid n'est pas spécifié, alors la valeur par défaut "" (chaîne vide) est attribuée à orbid. Si des ORB sont créés avec un orbid de chaîne vide, alors tous les ports qui y sont enregistrés sont retournés.
orblist -serverid id-serveur | -applicationName nom-application
Liste les ORBId des ORB définis sur un serveur. Un ORBId est le nom de chaîne de l'ORB créé par le serveur. Si le serveur n'est pas déjà en cours d'exécution, il est activé.
shutdown -serverid id-serveur | -applicationName nom-application
Arrête un serveur actif enregistré auprès de l'ORBD. Lors de l'exécution de cette commande, la méthode shutdown définie dans la classe spécifiée par le paramètre -serverid ou -applicationName est également appelée pour arrêter le processus serveur.
startup -serverid id-serveur | -applicationName nom-application
Démarre ou active un serveur enregistré auprès de l'ORBD. Si le serveur n'est pas en cours d'exécution, cette commande démarre le serveur. Si le serveur est déjà en cours d'exécution, un message d'erreur est affiché.
help
Liste toutes les commandes disponibles pour le serveur via la commande servertool.
quit
Quitte la commande servertool.
