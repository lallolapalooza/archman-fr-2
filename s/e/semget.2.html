semget(2) Manuel des appels système semget(2)

NOM

semget - obtenir un identifiant de jeu de sémaphores System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/sem.h>

int semget(key_t key, int nsems, int semflg);

DESCRIPTION

L'appel système semget() renvoie l'identifiant du jeu de sémaphores System V associé à l'argument key. Il peut être utilisé soit pour obtenir l'identifiant d'un jeu de sémaphores précédemment créé (lorsque semflg est zéro et que key n'a pas la valeur IPC_PRIVATE), soit pour créer un nouvel ensemble.

Un nouvel ensemble de nsems sémaphores est créé si key a la valeur IPC_PRIVATE ou si aucun jeu de sémaphores existant n'est associé à key et que IPC_CREAT est spécifié dans semflg.

Si semflg spécifie à la fois IPC_CREAT et IPC_EXCL et qu'un jeu de sémaphores existe déjà pour key, alors semget() échoue avec errno défini à EEXIST. (Ceci est analogue à l'effet de la combinaison O_CREAT | O_EXCL pour open(2).)

Lors de la création d'un nouvel ensemble de sémaphores, les 9 bits les moins significatifs de l'argument semflg définissent les permissions (pour le propriétaire, le groupe et les autres) pour le jeu de sémaphores. Ces bits ont le même format et la même signification que l'argument mode de open(2) (bien que les permissions d'exécution ne soient pas significatives pour les sémaphores, et que les permissions d'écriture signifient la permission de modifier les valeurs des sémaphores).

Lors de la création d'un nouvel ensemble de sémaphores, semget() initialise la structure de données associée à l'ensemble, semid_ds (voir semctl(2)), comme suit :

•
sem_perm.cuid et sem_perm.uid sont définis à l'ID utilisateur effectif du processus appelant.
•
sem_perm.cgid et sem_perm.gid sont définis à l'ID de groupe effectif du processus appelant.
•
Les 9 bits les moins significatifs de sem_perm.mode sont définis aux 9 bits les moins significatifs de semflg.
•
sem_nsems est défini à la valeur de nsems.
•
sem_otime est défini à 0.
•
sem_ctime est défini à l'heure actuelle.

L'argument nsems peut être 0 (ne pas s'en soucier) lorsqu'un jeu de sémaphores n'est pas créé. Sinon, nsems doit être supérieur à 0 et inférieur ou égal au nombre maximum de sémaphores par jeu de sémaphores (SEMMSL).

Si le jeu de sémaphores existe déjà, les permissions sont vérifiées.

VALEUR DE RETOUR

En cas de succès, semget() renvoie l'identifiant du jeu de sémaphores (un entier non négatif). En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Un jeu de sémaphores existe pour key, mais le processus appelant n'a pas la permission d'accéder à l'ensemble, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui gouverne son espace de noms IPC.
EEXIST
IPC_CREAT et IPC_EXCL ont été spécifiés dans semflg, mais un jeu de sémaphores existe déjà pour key.
EINVAL
nsems est inférieur à 0 ou supérieur à la limite du nombre de sémaphores par jeu de sémaphores (SEMMSL).
EINVAL
Un jeu de sémaphores correspondant à key existe déjà, mais nsems est supérieur au nombre de sémaphores dans cet ensemble.
ENOENT
Aucun jeu de sémaphores n'existe pour key et semflg n'a pas spécifié IPC_CREAT.
ENOMEM
Un jeu de sémaphores doit être créé mais le système n'a pas assez de mémoire pour la nouvelle structure de données.
ENOSPC
Un jeu de sémaphores doit être créé mais la limite du système pour le nombre maximum de jeux de sémaphores (SEMMNI), ou le nombre maximum de sémaphores au niveau du système (SEMMNS), serait dépassée.

NORMES

POSIX.1-2024.

HISTORIQUE

SVr4, POSIX.1-2001.

NOTES

IPC_PRIVATE n'est pas un champ de drapeau mais un type key_t. Si cette valeur spéciale est utilisée pour key, l'appel système ignore tous les bits sauf les 9 moins significatifs de semflg et crée un nouveau jeu de sémaphores (en cas de succès).

Initialisation des sémaphores

Les valeurs des sémaphores dans un nouvel ensemble créé sont indéterminées. (POSIX.1-2001 et POSIX.1-2008 sont explicites à ce sujet, bien que POSIX.1-2008 note qu'une version future de la norme peut exiger qu'une implémentation initialise les sémaphores à 0.) Bien que Linux, comme de nombreuses autres implémentations, initialise les valeurs des sémaphores à 0, une application portable ne peut pas s'y fier : elle doit explicitement initialiser les sémaphores aux valeurs souhaitées.

L'initialisation peut être effectuée à l'aide de l'opération SETVAL ou SETALL de semctl(2). Là où plusieurs pairs ne savent pas qui sera le premier à initialiser l'ensemble, la vérification d'un sem_otime non nul dans la structure de données associée récupérée par une opération IPC_STAT de semctl(2) peut être utilisée pour éviter les compétitions.

Limites des sémaphores

Les limites suivantes sur les ressources des jeux de sémaphores affectent l'appel semget() :

SEMMNI
Limite globale du système sur le nombre de jeux de sémaphores. Avant Linux 3.19, la valeur par défaut de cette limite était de 128. Depuis Linux 3.19, la valeur par défaut est de 32 000. Sur Linux, cette limite peut être lue et modifiée via le quatrième champ de /proc/sys/kernel/sem.
SEMMSL
Nombre maximum de sémaphores par ID de sémaphore. Avant Linux 3.19, la valeur par défaut de cette limite était de 250. Depuis Linux 3.19, la valeur par défaut est de 32 000. Sur Linux, cette limite peut être lue et modifiée via le premier champ de /proc/sys/kernel/sem.
SEMMNS
Limite globale du système sur le nombre de sémaphores : dépendante de la politique (sur Linux, cette limite peut être lue et modifiée via le second champ de /proc/sys/kernel/sem). Notez que le nombre de sémaphores au niveau du système est également limité par le produit de SEMMSL et SEMMNI.

BOGUES

Le choix du nom IPC_PRIVATE était peut-être malheureux, IPC_NEW montrerait plus clairement sa fonction.

EXEMPLES

Le programme présenté ci-dessous utilise semget() pour créer un nouveau jeu de sémaphores ou récupérer l'ID d'un ensemble existant. Il génère la clé pour semget() en utilisant ftok(3). Les deux premiers arguments de la ligne de commande sont utilisés comme arguments pathname et proj_id pour ftok(3). Le troisième argument de la ligne de commande est un entier qui spécifie l'argument nsems pour semget(). Les options de ligne de commande peuvent être utilisées pour spécifier les drapeaux IPC_CREAT (-c) et IPC_EXCL (-x) pour l'appel à semget(). L'utilisation de ce programme est démontrée ci-dessous.

Nous créons d'abord deux fichiers qui seront utilisés pour générer des clés à l'aide de ftok(3), créons deux ensembles de sémaphores à l'aide de ces fichiers, puis listons les ensembles à l'aide de ipcs(1) :


$ touch mykey mykey2;
$ ./t_semget -c mykey p 1;
ID = 9
$ ./t_semget -c mykey2 p 2;
ID = 10
$ ipcs -s;
------ Tableaux de sémaphores --------
clé        semid      propriétaire      perms      nsems
0x7004136d 9          mtk        600        1
0x70041368 10         mtk        600        2

Ensuite, nous démontrons que lorsque semctl(2) reçoit la même clé (générée par les mêmes arguments pour ftok(3)), il renvoie l'ID de l'ensemble de sémaphores déjà existant :


$ ./t_semget -c mykey p 1;
ID = 9

Enfin, nous démontrons le type de collision qui peut survenir lorsque ftok(3) reçoit des arguments de nom de chemin différents qui ont le même numéro d'inode :


$ ln mykey link;
$ ls -i1 link mykey;
2233197 link
2233197 mykey
$ ./t_semget link p 1;       # Génère la même clé que 'mykey'
ID = 9

Source du programme

/* t_semget.c
   Sous licence GNU General Public License v2 ou ultérieure.
*/
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <unistd.h>
static void
usage(const char *pname)
{
    fprintf(stderr, "Usage: %s [-cx] nom_chemin id_projet nb_sems\n",
            pname);
    fprintf(stderr, "    -c           Utiliser le drapeau IPC_CREAT\n");
    fprintf(stderr, "    -x           Utiliser le drapeau IPC_EXCL\n");
    exit(EXIT_FAILURE);
}
int
main(int argc, char *argv[])
{
    int    semid, nsems, flags, opt;
    key_t  key;
    flags = 0;
    while ((opt = getopt(argc, argv, "cx")) != -1) {
        switch (opt) {
        case 'c': flags |= IPC_CREAT;   break;
        case 'x': flags |= IPC_EXCL;    break;
        default:  usage(argv[0]);
        }
    }
    if (argc != optind + 3)
        usage(argv[0]);
    key = ftok(argv[optind], argv[optind + 1][0]);
    if (key == -1) {
        perror("ftok");
        exit(EXIT_FAILURE);
    }
    nsems = atoi(argv[optind + 2]);
    semid = semget(key, nsems, flags | 0600);
    if (semid == -1) {
        perror("semget");
        exit(EXIT_FAILURE);
    }
    printf("ID = %d\n", semid);
    exit(EXIT_SUCCESS);
}
