NOM

setpci - configurer les périphériques PCI

SYNTAXE

setpci [options] périphériques opérations...

DESCRIPTION

setpci est un utilitaire pour interroger et configurer les périphériques PCI.

Tous les nombres sont entrés en notation hexadécimale.

Des privilèges root sont nécessaires pour presque toutes les opérations, à l'exception des lectures de l'en-tête standard de l'espace de configuration sur certains systèmes d'exploitation. Veuillez consulter lspci(8) pour plus de détails sur les droits d'accès.

OPTIONS

Options générales

-v
Indique à setpci d'être verbeux et d'afficher des informations détaillées sur les accès à l'espace de configuration.
-f
Indique à setpci de ne pas se plaindre lorsqu'il n'y a rien à faire (lorsqu'aucun périphérique n'est sélectionné). Cette option est destinée à être utilisée dans des scripts de configuration largement distribués où il n'est pas certain que le périphérique en question soit présent dans la machine ou non.
-D
Mode démonstration : n'écrivez rien dans les registres de configuration. Il est utile d'essayer setpci -vD pour vérifier que votre séquence complexe d'opérations setpci fait ce que vous pensez qu'elle devrait faire.
-r
Évite le scan du bus si chaque opération sélectionne un périphérique spécifique (utilise le sélecteur -s avec un domaine, bus, slot et fonction spécifiques). C'est plus rapide, mais si le périphérique n'existe pas, cela échoue au lieu de correspondre à un ensemble vide de périphériques.
--version
Affiche la version de setpci. Cette option doit être utilisée seule.
--help
Affiche une aide détaillée sur les options disponibles. Cette option doit être utilisée seule.
--dumpregs
Affiche une liste de tous les registres et capacités PCI connus. Cette option doit être utilisée seule.

Options d'accès PCI

Les utilitaires PCI utilisent la bibliothèque PCI pour communiquer avec les périphériques PCI (voir pcilib(7) pour plus de détails). Vous pouvez utiliser les options suivantes pour influencer son comportement :

-A <méthode>
La bibliothèque prend en charge une variété de méthodes pour accéder au matériel PCI. Par défaut, elle utilise la première méthode d'accès disponible, mais vous pouvez utiliser cette option pour remplacer cette décision. Voir -A help pour une liste des méthodes disponibles et leurs descriptions.
-O <paramètre>=<valeur>
Le comportement de la bibliothèque est contrôlé par plusieurs paramètres nommés. Cette option permet de définir la valeur de n'importe lequel de ces paramètres. Utilisez -O help pour une liste des paramètres connus et leurs valeurs par défaut.
-H1
Utiliser l'accès matériel direct via le mécanisme de configuration Intel 1. (Ceci est un raccourci pour -A intel-conf1.)
-H2
Utiliser l'accès matériel direct via le mécanisme de configuration Intel 2. (Ceci est un raccourci pour -A intel-conf2.)
-G
Augmente le niveau de débogage de la bibliothèque.

SÉLECTION DU PÉRIPHÉRIQUE

Avant chaque séquence d'opérations, vous devez sélectionner les périphériques que cette opération doit affecter.

-s [[[[<domaine>]:]<bus>]:][<slot>][.[<func>]]
Ne considérer que les périphériques dans le domaine spécifié (si votre machine possède plusieurs ponts hôtes, ils peuvent partager un espace de numéros de bus commun ou chacun peut adresser son propre domaine PCI ; les domaines sont numérotés de 0 à ffff), le bus (0 à ff), le slot (0 à 1f) et la fonction (0 à 7). Chaque composant de l'adresse du périphérique peut être omis ou défini à "*", les deux signifiant "n'importe quelle valeur". Tous les nombres sont hexadécimaux. Par exemple, "0:" signifie tous les périphériques sur le bus 0, "0" signifie toutes les fonctions du périphérique 0 sur n'importe quel bus, "0.3" sélectionne la troisième fonction du périphérique 0 sur tous les bus et ".4" ne correspond qu'à la quatrième fonction de chaque périphérique.
-d [<fabricant>]:[<périphérique>][:<classe>[:<prog-if>]]
Sélectionne les périphériques avec le fabricant, le périphérique, l'ID de classe et l'interface de programmation spécifiés. Les ID sont donnés en hexadécimal et peuvent être omis ou donnés comme "*", les deux signifiant "n'importe quelle valeur". L'ID de classe peut contenir des caractères "x" qui signifient "n'importe quel chiffre".

Lorsque -s et -d sont combinés, seuls les périphériques qui correspondent aux deux critères sont sélectionnés. Lorsque plusieurs options du même type sont spécifiées, la plus à droite remplace les autres.

OPÉRATIONS

Il existe deux types d'opérations : les lectures et les écritures. Pour lire un registre, il suffit de spécifier son nom. Les écritures ont la forme nom=valeur,valeur... où chaque valeur est soit un nombre hexadécimal, soit une expression de type donnée:masque où donnée et masque sont des nombres hexadécimaux. Dans ce dernier cas, seuls les bits correspondant aux uns binaires dans le masque sont modifiés (techniquement, il s'agit d'une opération lecture-modification-écriture).

Il existe plusieurs façons d'identifier un registre :

  • Indiquer son adresse en hexadécimal.
  • Écrire son nom. Setpci connaît les noms de tous les registres dans les en-têtes de configuration standard. Utilisez `setpci --dumpregs' pour obtenir la liste complète. Consultez les spécifications du bus PCI pour la signification précise de ces registres ou consultez header.h ou /usr/include/pci/pci.h pour un bref aperçu.
  • Si le registre fait partie d'une capacité PCI, vous pouvez spécifier le nom de la capacité pour obtenir l'adresse de son premier registre. Voir les noms commençant par `CAP_' ou `ECAP_' dans la sortie --dumpregs.
  • Si le nom de la capacité n'est pas connu de setpci, vous pouvez y faire référence par son numéro sous la forme CAPid ou ECAPid, où id est l'identifiant numérique de la capacité en hexadécimal.
  • Chacun des formats précédents peut être suivi de +offset pour ajouter un décalage (un nombre hexadécimal) à l'adresse. Cette fonctionnalité peut être utile pour adresser des registres situés dans une capacité, ou pour modifier des parties de registres standard.
  • Pour choisir le nombre d'octets (1, 2 ou 4) qui doivent être transférés, vous devez ajouter un spécificateur de largeur .B, .W, ou .L. La largeur peut être omise si vous faites référence à un registre par son nom et que la largeur du registre est bien connue.
  • Enfin, si une capacité existe plusieurs fois, vous pouvez choisir celle à cibler en utilisant @nombre. L'indexation commence à 0.

Tous les noms de registres et les spécificateurs de largeur ne sont pas sensibles à la casse.

EXEMPLES

COMMANDE
demande le registre de commande de taille mot.
4.w
est une adresse numérique du même registre.
COMMANDE.l
demande un mot de 32 bits commençant à l'emplacement du registre de commande, c'est-à-dire les registres de commande et de statut ensemble.
ID_FABRICANT+1.b
spécifie l'octet supérieur du registre d'ID de fabricant (rappelez-vous, PCI est little-endian).
CAP_PM+2.w
correspond au deuxième mot de la capacité de gestion de l'alimentation.
ECAP108.l
demande le premier mot de 32 bits de la capacité étendue avec l'ID 0x108.

VOIR AUSSI

lspci(8), NAME

pcilib - PCI library interface

DESCRIPTION

The PCI library provides a simple interface for accessing the PCI bus. It can be used to find devices, read their configuration registers, map their memory-mapped regions and get various other information about the PCI hardware.

The main functions provided by the library are:

  • pci_alloc_context(): Allocates a new PCI context.
  • pci_init(): Initializes the PCI library.
  • pci_scan_bus(): Scans the PCI bus for devices.
  • pci_get_device(): Returns a pointer to a specific PCI device.
  • pci_read_long(), pci_write_long(): Read/write 32-bit configuration registers.
  • pci_read_word(), pci_write_word(): Read/write 16-bit configuration registers.
  • pci_read_byte(), pci_write_byte(): Read/write 8-bit configuration registers.
  • pci_map_resource(): Maps a PCI memory-mapped I/O resource.
  • pci_unmap_resource(): Unmaps a PCI memory-mapped I/O resource.
  • pci_present(): Checks if a PCI device is present.
  • pci_free(): Frees a PCI context.

The library is typically used by applications that need to interact directly with PCI devices, such as device drivers or hardware diagnostics tools.

For more detailed information, please refer to the header files in the pciutils package and the source code.
