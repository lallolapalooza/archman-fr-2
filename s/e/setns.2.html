setns(2) Manuel des appels système setns(2)

NOM

setns - Réassocier un thread à un espace de noms

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <sched.h>
int setns(int fd, int nstype);

DESCRIPTION

L'appel système setns() permet au thread appelant de se déplacer dans différents espaces de noms. L'argument fd est l'un des éléments suivants :

•
un descripteur de fichier faisant référence à l'un des liens magiques du répertoire /proc/pid/ns/ (ou un montage bind vers un tel lien) ;
•
un descripteur de fichier PID (voir pidfd_open(2)).

L'argument nstype est interprété différemment dans chaque cas.

fd fait référence à un lien /proc/pid/ns/

Si fd fait référence à un lien /proc/pid/ns/, alors setns() réassocie le thread appelant avec l'espace de noms associé à ce lien, sous réserve des contraintes imposées par l'argument nstype. Dans cette utilisation, chaque appel à setns() ne modifie qu'une seule des appartenances de l'appelant à un espace de noms.

L'argument nstype spécifie le type d'espace de noms auquel le thread appelant peut être réassocié. Cet argument peut avoir une des valeurs suivantes :

0
Permet de rejoindre n'importe quel type d'espace de noms.
CLONE_NEWCGROUP (depuis Linux 4.6)
fd doit faire référence à un espace de noms cgroup.
CLONE_NEWIPC (depuis Linux 3.0)
fd doit faire référence à un espace de noms IPC.
CLONE_NEWNET (depuis Linux 3.0)
fd doit faire référence à un espace de noms réseau.
CLONE_NEWNS (depuis Linux 3.8)
fd doit faire référence à un espace de noms de montage.
CLONE_NEWPID (depuis Linux 3.8)
fd doit faire référence à un espace de noms PID descendant.
CLONE_NEWTIME (depuis Linux 5.8)
fd doit faire référence à un espace de noms de temps.
CLONE_NEWUSER (depuis Linux 3.8)
fd doit faire référence à un espace de noms utilisateur.
CLONE_NEWUTS (depuis Linux 3.0)
fd doit faire référence à un espace de noms UTS.

Spécifier nstype à 0 suffit si l'appelant sait (ou ne se soucie pas) du type d'espace de noms auquel fd fait référence. Spécifier une valeur non nulle pour nstype est utile si l'appelant ne connaît pas le type d'espace de noms auquel fd fait référence et veut s'assurer que l'espace de noms est d'un type particulier. (L'appelant pourrait ne pas connaître le type de l'espace de noms auquel fd fait référence si le descripteur de fichier a été ouvert par un autre processus et, par exemple, passé à l'appelant via un socket de domaine UNIX.)

fd est un descripteur de fichier PID

Depuis Linux 5.8, fd peut faire référence à un descripteur de fichier PID obtenu à partir de pidfd_open(2) ou clone(2). Dans cette utilisation, setns() déplace atomiquement le thread appelant vers un ou plusieurs des mêmes espaces de noms que le thread référencé par fd.

L'argument nstype est un masque de bits spécifié en combinant un ou plusieurs des constantes CLONE_NEW* d'espaces de noms listées ci-dessus. L'appelant est déplacé dans chacun des espaces de noms du thread cible qui est spécifié dans nstype ; les appartenances de l'appelant aux espaces de noms restants ne sont pas modifiées.

Par exemple, le code suivant déplacerait l'appelant dans les mêmes espaces de noms utilisateur, réseau et UTS que le PID 1234, mais laisserait inchangées les autres appartenances de l'appelant aux espaces de noms :


int fd = pidfd_open(1234, 0);
setns(fd, CLONE_NEWUSER | CLONE_NEWNET | CLONE_NEWUTS);

Détails pour les types d'espace de noms spécifiques

Notez les détails et restrictions suivants lors de la réassociation avec des types d'espaces de noms spécifiques :

Espaces de noms utilisateur
Un processus se réassociant à un espace de noms utilisateur doit posséder la capacité CAP_SYS_ADMIN dans l'espace de noms utilisateur cible. (Cela implique nécessairement qu'il n'est possible de rejoindre qu'un espace de noms utilisateur descendant.) Après avoir rejoint avec succès un espace de noms utilisateur, un processus obtient toutes les capacités dans cet espace de noms, indépendamment de ses identifiants utilisateur et groupe.
Un processus multithread ne peut pas changer d'espace de noms utilisateur avec setns().
Il n'est pas permis d'utiliser setns() pour réintégrer l'espace de noms utilisateur actuel de l'appelant. Cela empêche un appelant qui a abandonné des capacités de les retrouver via un appel à setns().
Pour des raisons de sécurité, un processus ne peut pas rejoindre un nouvel espace de noms utilisateur s'il partage des attributs liés au système de fichiers (les attributs dont le partage est contrôlé par le drapeau CLONE_FS de clone(2)) avec un autre processus.
Pour plus de détails sur les espaces de noms utilisateur, voir user_namespaces(7).
Espaces de noms de montage
Changer l'espace de noms de montage nécessite que l'appelant possède les capacités CAP_SYS_CHROOT et CAP_SYS_ADMIN dans son propre espace de noms utilisateur et CAP_SYS_ADMIN dans l'espace de noms utilisateur qui possède l'espace de noms de montage cible.
Un processus ne peut pas rejoindre un nouvel espace de noms de montage s'il partage des attributs liés au système de fichiers (les attributs dont le partage est contrôlé par le drapeau CLONE_FS de clone(2)) avec un autre processus.
Voir user_namespaces(7) pour les détails sur l'interaction des espaces de noms utilisateur et de montage.
Espaces de noms PID
Afin de se réassocier à un nouvel espace de noms PID, l'appelant doit posséder la capacité CAP_SYS_ADMIN à la fois dans son propre espace de noms utilisateur et dans l'espace de noms utilisateur qui possède l'espace de noms PID cible.
La réassociation de l'espace de noms PID est quelque peu différente des autres types d'espaces de noms. La réassociation du thread appelant à un espace de noms PID ne modifie que l'espace de noms PID dans lequel les processus enfants créés par la suite par l'appelant seront placés ; elle ne modifie pas l'espace de noms PID de l'appelant lui-même.
La réassociation à un espace de noms PID n'est autorisée que si l'espace de noms PID cible est un descendant (enfant, petit-enfant, etc.) de, ou est le même que, l'espace de noms PID actuel de l'appelant.
Pour plus de détails sur les espaces de noms PID, voir pid_namespaces(7).
Espaces de noms Cgroup
Afin de se réassocier à un nouvel espace de noms cgroup, l'appelant doit posséder la capacité CAP_SYS_ADMIN à la fois dans son propre espace de noms utilisateur et dans l'espace de noms utilisateur qui possède l'espace de noms cgroup cible.
Utiliser setns() pour changer l'espace de noms cgroup de l'appelant ne modifie pas les appartenances cgroup de l'appelant.
Espaces de noms de temps
Afin de se réassocier à un nouvel espace de noms de temps, l'appelant doit posséder la capacité CAP_SYS_ADMIN à la fois dans son propre espace de noms utilisateur et dans l'espace de noms utilisateur qui possède l'espace de noms cible.
Un processus multithread ne peut pas changer d'espace de noms de temps

Espaces de noms réseau, IPC et UTS
Afin de se réassocier à un nouvel espace de noms réseau, IPC, temporel ou UTS, l'appelant doit posséder la capacité CAP_SYS_ADMIN à la fois dans son propre espace de noms utilisateur et dans l'espace de noms utilisateur qui possède l'espace de noms cible.

VALEUR DE RETOUR

En cas de succès, setns() retourne 0. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide.
EINVAL
fd fait référence à un espace de noms dont le type ne correspond pas à celui spécifié dans nstype.
EINVAL
Il y a un problème lors de la réassociation du thread avec l'espace de noms spécifié.
EINVAL
L'appelant a essayé de rejoindre un espace de noms PID ancêtre (parent, grand-parent, etc.).
EINVAL
L'appelant a tenté de rejoindre l'espace de noms utilisateur dont il est déjà membre.
EINVAL
L'appelant partage l'état du système de fichiers (CLONE_FS) (en particulier, le répertoire racine) avec d'autres processus et a tenté de rejoindre un nouvel espace de noms utilisateur.
EINVAL
L'appelant est multithread et a tenté de rejoindre un nouvel espace de noms utilisateur.
EINVAL
fd est un descripteur de fichier PID et nstype est invalide (par exemple, il est 0).
ENOMEM
Impossible d'allouer suffisamment de mémoire pour changer l'espace de noms spécifié.
EPERM
Le thread appelant n'avait pas la capacité requise pour cette opération.
ESRCH
fd est un descripteur de fichier PID mais le processus auquel il fait référence n'existe plus (c'est-à-dire qu'il s'est terminé et qu'on a attendu son état).

NORMES

Linux.

VERSIONS

Linux 3.0, glibc 2.14.

NOTES

Pour plus d'informations sur les liens symboliques magiques /proc/pid/ns/, voir namespaces(7).

Tous les attributs qui peuvent être partagés lors de la création d'un nouveau thread à l'aide de clone(2) ne peuvent pas être modifiés à l'aide de setns().

EXEMPLES

Le programme ci-dessous prend deux arguments ou plus. Le premier argument spécifie le chemin d'accès d'un fichier d'espace de noms dans un répertoire /proc/pid/ns/ existant. Les arguments restants spécifient une commande et ses arguments. Le programme ouvre le fichier d'espace de noms, rejoint cet espace de noms à l'aide de setns() et exécute la commande spécifiée à l'intérieur de cet espace de noms.

La session shell suivante démontre l'utilisation de ce programme (compilé en tant que binaire nommé ns_exec) en conjonction avec l'exemple de programme CLONE_NEWUTS dans la page de manuel de clone(2) (compilé en tant que binaire nommé newuts).

Nous commençons par exécuter le programme exemple dans clone(2) en arrière-plan. Ce programme crée un enfant dans un espace de noms UTS séparé. L'enfant modifie le nom d'hôte dans son espace de noms, puis les deux processus affichent les noms d'hôte dans leurs espaces de noms UTS, de sorte que nous puissions voir qu'ils sont différents.


$ su;                   # Nécessite les privilèges pour les opérations sur les espaces de noms
Password:
# ./newuts bizarro &
[1] 3549
clone() retourné 3550
uts.nodename dans l'enfant :  bizarro
uts.nodename dans le parent: antero
# uname -n;             # Vérifie le nom d'hôte dans le shell
antero

Nous exécutons ensuite le programme montré ci-dessous, en l'utilisant pour exécuter un shell. À l'intérieur de ce shell, nous vérifions que le nom d'hôte est celui défini par l'enfant créé par le premier programme :


# ./ns_exec /proc/3550/ns/uts /bin/bash;
# uname -n;             # Exécuté dans le shell démarré par ns_exec
bizarro

Source du programme

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int fd;
    if (argc < 3) {
        fprintf(stderr, "%s /proc/PID/ns/FILE cmd args...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Obtient le descripteur de fichier pour l'espace de noms ; le descripteur
       de fichier est ouvert avec O_CLOEXEC afin de garantir qu'il ne soit pas
       hérité par le programme qui est ensuite exécuté.  */
    fd = open(argv[1], O_RDONLY | O_CLOEXEC);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    if (setns(fd, 0) == -1)       /* Rejoint cet espace de noms */
        err(EXIT_FAILURE, "setns");
    execvp(argv[2], &argv[2]);    /* Exécute une commande dans l'espace de noms */
    err(EXIT_FAILURE, "execvp");
}
