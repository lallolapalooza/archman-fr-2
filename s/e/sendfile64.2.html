sendfile(2) Manuel des appels système sendfile(2)

NOM

sendfile - transférer des données entre descripteurs de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/sendfile.h>
ssize_t sendfile(int out_fd, int in_fd, off_t *_Nullable offset,
                 size_t count);

DESCRIPTION

sendfile() copie des données entre un descripteur de fichier et un autre. Comme cette copie est effectuée au sein du noyau, sendfile() est plus efficace que la combinaison de read(2) et write(2), qui nécessiterait de transférer des données vers et depuis l'espace utilisateur.

in_fd doit être un descripteur de fichier ouvert en lecture et out_fd doit être un descripteur ouvert en écriture.

Si offset n'est pas NULL, alors il pointe vers une variable contenant le décalage de fichier à partir duquel sendfile() commencera à lire les données de in_fd. Lorsque sendfile() retourne, cette variable sera définie au décalage de l'octet suivant le dernier octet lu. Si offset n'est pas NULL, alors sendfile() ne modifie pas le décalage de fichier de in_fd ; sinon, le décalage de fichier est ajusté pour refléter le nombre d'octets lus depuis in_fd.

Si offset est NULL, alors les données seront lues depuis in_fd en commençant au décalage de fichier, et le décalage de fichier sera mis à jour par l'appel.

count est le nombre d'octets à copier entre les descripteurs de fichiers.

L'argument in_fd doit correspondre à un fichier qui supporte des opérations de type mmap(2) (c'est-à-dire qu'il ne peut pas être un socket). Sauf depuis Linux 5.12 et si out_fd est un pipe, auquel cas sendfile() est désassemblé en un splice(2) et ses restrictions s'appliquent.

Avant Linux 2.6.33, out_fd devait se référer à un socket. Depuis Linux 2.6.33, il peut s'agir de n'importe quel fichier. S'il est positionnable, alors sendfile() modifie le décalage de fichier de manière appropriée.

VALEUR DE RETOUR

Si le transfert a réussi, le nombre d'octets écrits sur out_fd est retourné. Notez qu'un appel réussi à sendfile() peut écrire moins d'octets que demandé ; l'appelant doit être prêt à réessayer l'appel s'il y avait des octets non envoyés. Voir également NOTES.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EAGAIN
Une E/S non bloquante a été sélectionnée en utilisant O_NONBLOCK et l'écriture bloquerait.
EBADF
Le fichier d'entrée n'a pas été ouvert en lecture ou le fichier de sortie n'a pas été ouvert en écriture.
EFAULT
Mauvaise adresse.
EINVAL
Le descripteur n'est pas valide ou verrouillé, ou une opération de type mmap(2) n'est pas disponible pour in_fd, ou count est négatif.
EINVAL
out_fd a le drapeau O_APPEND défini. Ce n'est pas actuellement supporté par sendfile().
EIO
Erreur non spécifiée lors de la lecture depuis in_fd.
ENOMEM
Mémoire insuffisante pour lire depuis in_fd.
EOVERFLOW
count est trop grand, l'opération entraînerait le dépassement de la taille maximale du fichier d'entrée ou du fichier de sortie.
ESPIPE
offset n'est pas NULL mais le fichier d'entrée n'est pas positionnable.

VERSIONS

D'autres systèmes UNIX implémentent sendfile() avec des sémantiques et des prototypes différents. Il ne doit pas être utilisé dans des programmes portables.

NORMES

Aucune.

HISTORIQUE

Linux 2.2, glibc 2.1.

Dans Linux 2.4 et antérieur, out_fd pouvait également se référer à un fichier ordinaire ; cette possibilité a disparu dans la série des noyaux Linux 2.6.x, mais a été restaurée dans Linux 2.6.33.

L'appel système sendfile() original de Linux n'était pas conçu pour gérer les décalages de fichiers volumineux. Par conséquent, Linux 2.4 a ajouté sendfile64(), avec un type plus large pour l'argument offset. La fonction wrapper sendfile() de glibc gère de manière transparente les différences du noyau.

NOTES

sendfile() transférera au maximum 0x7ffff000 (2 147 479 552) octets, retournant le nombre d'octets effectivement transférés. (Ceci est vrai sur les systèmes 32 bits et 64 bits.)

Si vous prévoyez d'utiliser sendfile() pour envoyer des fichiers à un socket TCP, mais que vous devez envoyer des données d'en-tête devant le contenu du fichier, vous trouverez utile d'employer l'option TCP_CORK, décrite dans tcp(7), pour minimiser le nombre de paquets et pour optimiser les performances.

Les applications peuvent souhaiter revenir à read(2) et write(2) dans le cas où sendfile() échoue avec EINVAL ou ENOSYS.

Si out_fd fait référence à un socket ou à un pipe avec prise en charge du zero-copy, les appelants doivent s'assurer que les portions transférées du fichier auquel in_fd fait référence restent inchangées jusqu'à ce que le lecteur de l'autre extrémité de out_fd ait consommé les données transférées.

L'appel splice(2) spécifique à Linux prend en charge le transfert de données entre des descripteurs de fichiers arbitraires à condition que l'un (ou les deux) d'entre eux soit un pipe.

VOIR AUSSI

copy_file_range(2), mmap(2), open(2), socket(2), splice(2)
