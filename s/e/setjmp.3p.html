SETJMP(3P) Manuel du programmeur POSIX SETJMP(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

setjmp — définir un point de saut pour un goto non local

SYNOPIS

#include <setjmp.h>
int setjmp(jmp_buf env);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

Un appel à setjmp() doit enregistrer l'environnement d'appel dans son argument env pour une utilisation ultérieure par longjmp().

Il n'est pas spécifié si setjmp() est une macro ou une fonction. Si une définition de macro est supprimée afin d'accéder à une fonction réelle, ou si un programme définit un identifiant externe avec le nom setjmp, le comportement est indéfini.

Une application doit s'assurer qu'une invocation de setjmp() apparaît uniquement dans l'un des contextes suivants :

*
L'expression de contrôle entière d'une instruction de sélection ou d'itération
*
Un opérande d'un opérateur relationnel ou d'égalité avec l'autre opérande une expression constante entière, l'expression résultante étant l'expression de contrôle entière d'une instruction de sélection ou d'itération
*
L'opérande d'un opérateur unaire '!' avec l'expression résultante étant l'expression de contrôle entière d'une sélection ou d'itération
*
L'expression entière d'une instruction d'expression (éventuellement castée en void)

Si l'invocation apparaît dans tout autre contexte, le comportement est indéfini.

VALEUR DE RETOUR

Si le retour provient d'une invocation directe, setjmp() doit retourner 0. Si le retour provient d'un appel à longjmp(), setjmp() doit retourner une valeur non nulle.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

En général, sigsetjmp() est plus utile pour traiter les erreurs et les interruptions rencontrées dans une sous-routine de bas niveau d'un programme.
