setreuid(2) Manuel des appels système setreuid(2)

NOM

setreuid, setregid - définir l'ID utilisateur ou groupe réel et/ou effectif

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Exigences de macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE

DESCRIPTION

setreuid() définit les ID utilisateur réels et effectifs du processus appelant.

Fournir une valeur de -1 pour l'ID utilisateur réel ou effectif laisse cet ID inchangé.

Les processus non privilégiés ne peuvent définir l'ID utilisateur effectif que sur l'ID utilisateur réel, l'ID utilisateur effectif, ou l'ID utilisateur sauvegardé.

Les utilisateurs non privilégiés ne peuvent définir l'ID utilisateur réel que sur l'ID utilisateur réel ou l'ID utilisateur effectif.

Si l'ID utilisateur réel est défini (c'est-à-dire, ruid n'est pas -1) ou si l'ID utilisateur effectif est défini à une valeur différente de l'ID utilisateur réel précédent, l'ID utilisateur effectif sauvegardé sera défini sur le nouvel ID utilisateur effectif.

De manière complètement analogue, setregid() définit les ID groupe réels et effectifs du processus appelant, et tout ce qui précède s'applique avec le mot "groupe" à la place de "utilisateur".

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

Note : il y a des cas où setreuid() peut échouer même si l'appelant a l'UID 0 ; omettre la vérification d'un retour d'échec de setreuid() constitue une grave erreur de sécurité.

ERREURS

EAGAIN
L'appel modifierait l'UID réel de l'appelant (c'est-à-dire, ruid ne correspond pas à l'UID réel de l'appelant), mais il y a eu un échec temporaire lors de l'allocation des structures de données noyau nécessaires.
EAGAIN
ruid ne correspond pas à l'UID réel de l'appelant et cet appel dépasserait la limite de ressources RLIMIT_NPROC de l'appelant pour le nombre de processus appartenant à l'UID réel ruid. Depuis Linux 3.1, ce cas d'erreur ne se produit plus (mais les applications robustes doivent vérifier cette erreur) ; voir la description de EAGAIN dans execve(2).
EINVAL
Un ou plusieurs des ID utilisateur ou groupe cibles ne sont pas valides dans cet espace de noms utilisateur.
EPERM
Le processus appelant n'est pas privilégié (sur Linux, n'a pas la capacité nécessaire dans son espace de noms utilisateur : CAP_SETUID dans le cas de setreuid(), ou CAP_SETGID dans le cas de setregid()) et une modification autre que (i) l'échange de l'ID effectif avec l'ID réel, ou (ii) la définition de l'un à la valeur de l'autre, ou (iii) la définition de l'ID effectif à la valeur de l'ID effectif sauvegardé a été spécifiée.

VERSIONS

POSIX.1 ne spécifie pas toutes les modifications d'UID que Linux autorise pour un processus non privilégié. Pour setreuid(), l'ID utilisateur effectif peut être rendu identique à l'ID utilisateur réel ou à l'ID utilisateur effectif sauvegardé, et il n'est pas spécifié si les processus non privilégiés peuvent définir l'ID utilisateur réel sur l'ID utilisateur réel, l'ID utilisateur effectif ou l'ID utilisateur effectif sauvegardé. Pour setregid(), l'ID groupe réel peut être modifié pour prendre la valeur de l'ID groupe effectif sauvegardé, et l'ID groupe effectif peut être modifié pour prendre la valeur de l'ID groupe réel ou de l'ID groupe effectif sauvegardé. Les détails précis des modifications d'ID autorisées varient selon les implémentations.

POSIX.1 ne fait aucune spécification concernant l'effet de ces appels sur l'ID utilisateur effectif sauvegardé et l'ID groupe effectif sauvegardé.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, 4.3BSD (apparu pour la première fois dans 4.2BSD).

La définition de l'ID utilisateur (groupe) effectif sur l'ID utilisateur (groupe) effectif sauvegardé est possible depuis Linux 1.1.37 (1.1.38).

Les appels système setreuid() et setregid() originaux de Linux ne supportaient que les ID utilisateur et groupe de 16 bits. Ultérieurement, Linux 2.4 a ajouté setreuid32() et setregid32(), supportant les ID de 32 bits. Les fonctions wrapper setreuid() et setregid() de glibc gèrent de manière transparente les variations entre les versions du noyau.

Différences bibliothèque C/noyau

Au niveau du noyau, les ID utilisateur et groupe sont des attributs par thread. Cependant, POSIX exige que tous les threads d'un processus partagent les mêmes identifiants. L'implémentation de threading NPTL gère les exigences de POSIX en fournissant des fonctions wrapper pour les divers appels système qui modifient les UID et GID des processus. Ces fonctions wrapper (y compris celles pour setreuid() et setregid()) utilisent une technique basée sur les signaux pour garantir que lorsqu'un thread modifie ses identifiants, tous les autres threads du processus modifient également leurs identifiants. Pour plus de détails, voir nptl(7).
