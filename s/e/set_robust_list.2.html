set_robust_list(2) Manuel des appels système set_robust_list(2)

NOM

get_robust_list, set_robust_list - obtenir/définir la liste des futex robustes

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/futex.h>   /* Définition de struct robust_list_head */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_get_robust_list, int pid,
             struct robust_list_head **head_ptr, size_t *sizep);
long syscall(SYS_set_robust_list,
             struct robust_list_head *head, size_t size);

Note : glibc ne fournit pas d'enveloppes pour ces appels système, nécessitant l'utilisation de syscall(2).

DESCRIPTION

Ces appels système traitent des listes de futex robustes par thread. Ces listes sont gérées dans l'espace utilisateur : le noyau ne connaît que l'emplacement de la tête de la liste. Un thread peut informer le noyau de l'emplacement de sa liste de futex robustes en utilisant set_robust_list(). L'adresse de la liste de futex robustes d'un thread peut être obtenue en utilisant get_robust_list().

Le but de la liste de futex robustes est de garantir que si un thread omet accidentellement de déverrouiller un futex avant de se terminer ou d'appeler execve(2), un autre thread qui attend sur ce futex est notifié que l'ancien propriétaire du futex est mort. Cette notification comprend deux éléments : le bit FUTEX_OWNER_DIED est défini dans le mot futex, et le noyau effectue une opération futex(2) FUTEX_WAKE sur l'un des threads en attente sur le futex.

L'appel système get_robust_list() renvoie la tête de la liste de futex robustes du thread dont l'ID de thread est spécifié dans pid. Si pid est 0, la tête de la liste pour le thread appelant est renvoyée. La tête de la liste est stockée à l'emplacement pointé par head_ptr. La taille de l'objet pointé par **head_ptr est stockée dans sizep.

L'autorisation d'employer get_robust_list() est régie par un contrôle de mode d'accès ptrace PTRACE_MODE_READ_REALCREDS ; voir ptrace(2).

L'appel système set_robust_list() demande au noyau d'enregistrer la tête de la liste des futex robustes appartenant au thread appelant. L'argument head est la tête de liste à enregistrer. L'argument size doit être sizeof(*head).

VALEUR DE RETOUR

Les appels système set_robust_list() et get_robust_list() renvoient zéro lorsque l'opération réussit, un code d'erreur sinon.

ERREURS

L'appel système set_robust_list() peut échouer avec l'erreur suivante :

EINVAL
size n'est pas égal à sizeof(struct robust_list_head).

L'appel système get_robust_list() peut échouer avec les erreurs suivantes :

EFAULT
La tête de la liste de futex robustes ne peut pas être stockée à l'emplacement head.
EPERM
Le processus appelant n'a pas l'autorisation de voir la liste de futex robustes du thread avec l'ID de thread pid, et n'a pas la capacité CAP_SYS_PTRACE.
ESRCH
Aucun thread avec l'ID de thread pid n'a pu être trouvé.

VERSIONS

Ces appels système ont été ajoutés dans Linux 2.6.17.

NOTES

Ces appels système ne sont pas nécessaires aux applications normales.

Un thread ne peut avoir qu'une seule liste de futex robustes ; par conséquent, les applications qui souhaitent utiliser cette fonctionnalité devraient utiliser les mutex robustes fournis par glibc.

Dans l'implémentation initiale, un thread attendant sur un futex n'était notifié que le propriétaire était mort si le propriétaire se terminait. À partir de Linux 2.6.28, la notification a été étendue pour inclure le cas où le propriétaire effectue un execve(2).

Les ID de thread mentionnés dans le texte principal sont des ID de thread du noyau du type renvoyé par clone(2) et gettid(2).
