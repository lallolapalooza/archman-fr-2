setpgid(2) Manuel des appels système setpgid(2)

NOM

setpgid, getpgid, setpgrp, getpgrp - définir/obtenir le groupe de processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int setpgid(pid_t pid, pid_t pgid);
pid_t getpgid(pid_t pid);
pid_t getpgrp(void);                            /* version POSIX.1 */
[[deprecated]] pid_t getpgrp(pid_t pid);        /* version BSD */
int setpgrp(void);                              /* version System V */
[[deprecated]] int setpgrp(pid_t pid, pid_t pgid);  /* version BSD */
Exigences pour les macros de test de fonctionnalité sur glibc (voir feature_test_macros(7)):

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE

setpgrp() (BSD), getpgrp() (BSD):

    [Ces fonctions ne sont disponibles qu'avant glibc 2.19]
    _BSD_SOURCE &&
        ! (_POSIX_SOURCE || _POSIX_C_SOURCE || _XOPEN_SOURCE
            || _GNU_SOURCE || _SVID_SOURCE)

DESCRIPTION

Toutes ces interfaces sont disponibles sous Linux et sont utilisées pour obtenir et définir l'identifiant du groupe de processus (PGID) d'un processus. Les manières préférées et spécifiées par POSIX.1 pour le faire sont : getpgrp(void), pour récupérer le PGID du processus appelant ; et setpgid(), pour définir le PGID d'un processus.

setpgid() définit le PGID du processus spécifié par pid en pgid. Si pid est zéro, alors l'identifiant du processus appelant est utilisé. Si pgid est zéro, alors le PGID du processus spécifié par pid est rendu identique à son identifiant de processus. Si setpgid() est utilisé pour déplacer un processus d'un groupe de processus vers un autre (comme le font certains shells lors de la création de pipelines), les deux groupes de processus doivent faire partie de la même session (voir setsid(2) et credentials(7)). Dans ce cas, pgid spécifie un groupe de processus existant à rejoindre et l'identifiant de session de ce groupe doit correspondre à l'identifiant de session du processus qui rejoint.

La version POSIX.1 de getpgrp(), qui ne prend aucun argument, renvoie le PGID du processus appelant.

getpgid() renvoie le PGID du processus spécifié par pid. Si pid est zéro, l'identifiant du processus appelant est utilisé. (La récupération du PGID d'un processus autre que l'appelant est rarement nécessaire, et le getpgrp() de POSIX.1 est préférable pour cette tâche.)

Le setpgrp() de style System V, qui ne prend aucun argument, est équivalent à setpgid(0, 0).

L'appel setpgrp() spécifique à BSD, qui prend les arguments pid et pgid, est une fonction enveloppante qui appelle


setpgid(pid, pgid)

Depuis glibc 2.19, la fonction setpgrp() spécifique à BSD n'est plus exposée par <unistd.h> ; les appels doivent être remplacés par l'appel setpgid() montré ci-dessus.

L'appel getpgrp() spécifique à BSD, qui prend un seul argument pid, est une fonction enveloppante qui appelle


getpgid(pid)

Depuis glibc 2.19, la fonction getpgrp() spécifique à BSD n'est plus exposée par <unistd.h> ; les appels doivent être remplacés par des appels à getpgrp() de POSIX.1 qui ne prend aucun argument (si l'intention est d'obtenir le PGID de l'appelant), ou par l'appel getpgid() montré ci-dessus.

VALEUR DE RETOUR

En cas de succès, setpgid() et setpgrp() renvoient zéro. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

Le getpgrp() de POSIX.1 renvoie toujours le PGID de l'appelant.

getpgid(), et le getpgrp() spécifique à BSD renvoient un groupe de processus en cas de succès. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Une tentative a été faite pour changer l'identifiant du groupe de processus d'un des enfants du processus appelant et l'enfant avait déjà effectué un execve(2) (setpgid(), setpgrp()).
EINVAL
pgid est inférieur à 0 (setpgid(), setpgrp()).
EPERM
Une tentative a été faite pour déplacer un processus dans un groupe de processus dans une session différente, ou pour changer l'identifiant du groupe de processus d'un des enfants du processus appelant et l'enfant était dans une session différente, ou pour changer l'identifiant du groupe de processus d'un leader de session (setpgid(), setpgrp()).
EPERM
Le groupe de processus cible n'existe pas. (setpgid(), setpgrp()).
ESRCH
Pour getpgid() : pid ne correspond à aucun processus. Pour setpgid() : pid n'est pas le processus appelant et n'est pas un enfant du processus appelant.

NOTES

Un enfant créé via fork(2) hérite de l'identifiant du groupe de processus de son parent. Le PGID est préservé lors d'un execve(2).

Chaque groupe de processus fait partie d'une session et chaque processus fait partie de la session dont son groupe de processus fait partie. (Voir credentials(7).)

Une session peut avoir un terminal de contrôle. À tout moment, un (et un seul) des groupes de processus de la session peut être le groupe de processus avant pour le terminal ; les groupes de processus restants sont en arrière-plan. Si un signal est généré à partir du terminal (par exemple, en tapant la touche d'interruption pour générer SIGINT), ce signal est envoyé au groupe de processus avant. (Voir termios(3) pour une description des caractères qui génèrent des signaux.) Seul le groupe de processus avant peut lire(2) depuis le terminal ; si un groupe d'arrière-plan essaie de lire(2) depuis le terminal, alors le groupe reçoit un signal SIGTTIN, qui le suspend. Les fonctions tcgetpgrp(3) et tcsetpgrp(3)

sont utilisées pour obtenir/définir le groupe de processus avant du terminal de contrôle.

Les appels setpgid() et getpgrp() sont utilisés par des programmes tels que bash(1) pour créer des groupes de processus afin d'implémenter le contrôle des tâches du shell.

Si la terminaison d'un processus entraîne l'orphelinat d'un groupe de processus, et si un membre du groupe de processus nouvellement orphelin est arrêté, alors un signal SIGHUP suivi d'un signal SIGCONT sera envoyé à chaque processus du groupe de processus nouvellement orphelin. Un groupe de processus orphelin est un groupe dont le parent de chaque membre est lui-même un membre du groupe de processus ou est un membre d'un groupe de processus dans une session différente (voir aussi credentials(7)).
