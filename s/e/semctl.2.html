semctl(2) Manuel des appels système semctl(2)

NOM

semctl - Opérations de contrôle de sémaphores System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/sem.h>
int semctl(int semid, int semnum, int op, ...);

DESCRIPTION

semctl() effectue l'opération de contrôle spécifiée par op sur l'ensemble de sémaphores System V identifié par semid, ou sur le sémaphore numéro semnum de cet ensemble. (Les sémaphores d'un ensemble sont numérotés à partir de 0.)

Cette fonction a trois ou quatre arguments, selon op. Lorsqu'il y en a quatre, le quatrième est de type union semun. Le programme appelant doit définir cette union comme suit :


union semun {
    int              val;    /* Valeur pour SETVAL */
    struct semid_ds *buf;    /* Tampon pour IPC_STAT, IPC_SET */
    unsigned short  *array;  /* Tableau pour GETALL, SETALL */
    struct seminfo  *__buf;  /* Tampon pour IPC_INFO
                                (spécifique à Linux) */
};

La structure de données semid_ds est définie dans <sys/sem.h> comme suit :


struct semid_ds {
    struct ipc_perm sem_perm;  /* Propriété et permissions */
    time_t          sem_otime; /* Dernier temps d'opération semop */
    time_t          sem_ctime; /* Temps de création ou dernier temps
                                  de modification via semctl() */
    unsigned long   sem_nsems; /* Nombre de sémaphores dans l'ensemble */
};

Les champs de la structure semid_ds sont les suivants :

sem_perm
Il s'agit d'une structure ipc_perm (voir ci-dessous) qui spécifie les permissions d'accès sur l'ensemble de sémaphores.
sem_otime
Temps de la dernière opération système semop(2).
sem_ctime
Temps de création de l'ensemble de sémaphores ou temps de la dernière opération semctl() IPCSET, SETVAL ou SETALL.
sem_nsems
Nombre de sémaphores dans l'ensemble. Chaque sémaphore de l'ensemble est référencé par un entier non négatif allant de 0 à sem_nsems-1.

La structure ipc_perm est définie comme suit (les champs mis en évidence sont modifiables avec IPC_SET) :


struct ipc_perm {
    key_t          __key; /* Clé fournie à semget(2) */
    uid_t          uid;   /* UID effectif du propriétaire */
    gid_t          gid;   /* GID effectif du propriétaire */
    uid_t          cuid;  /* UID effectif du créateur */
    gid_t          cgid;  /* GID effectif du créateur */
    unsigned short mode;  /* Permissions */
    unsigned short __seq; /* Numéro de séquence */
};

Les 9 bits les moins significatifs du champ mode de la structure ipc_perm définissent les permissions d'accès pour l'ensemble de mémoire partagée. Les bits de permission sont les suivants :

0400 Lecture par l'utilisateur
0200 Écriture par l'utilisateur
0040 Lecture par le groupe
0020 Écriture par le groupe
0004 Lecture par les autres
0002 Écriture par les autres

En pratique, "écriture" signifie "modification" pour un ensemble de sémaphores. Les bits 0100, 0010 et 0001 (les bits d'exécution) sont inutilisés par le système.

Les valeurs valides pour op sont :

IPC_STAT
Copie les informations de la structure de données du noyau associée à semid dans la structure semid_ds pointée par arg.buf. L'argument semnum est ignoré. Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
IPC_SET
Écrit les valeurs de certains membres de la structure semid_ds pointée par arg.buf dans la structure de données du noyau associée à cet ensemble de sémaphores, en mettant également à jour son membre sem_ctime.
Les membres suivants de la structure sont mis à jour : sem_perm.uid, sem_perm.gid et (les 9 bits les moins significatifs de) sem_perm.mode.
L'UID effectif du processus appelant doit correspondre au propriétaire (sem_perm.uid) ou au créateur (sem_perm.cuid) de l'ensemble de sémaphores, ou l'appelant doit être privilégié. L'argument semnum est ignoré.
IPC_RMID
Supprime immédiatement l'ensemble de sémaphores, réveillant tous les processus bloqués dans des appels semop(2) sur l'ensemble (avec un retour d'erreur et errno défini à EIDRM). L'UID effectif du processus appelant doit correspondre au créateur ou au propriétaire de l'ensemble de sémaphores, ou l'appelant doit être privilégié. L'argument semnum est ignoré.
IPC_INFO (spécifique à Linux)
Retourne des informations sur les limites et paramètres globaux des sémaphores du système dans la structure pointée par arg.__buf. Cette structure est de type seminfo, définie dans <sys/sem.h> si le macro de test de fonctionnalité _GNU_SOURCE est définie :

struct seminfo {
    int semmap;  /* Nombre d'entrées dans la
                    carte des sémaphores; inutilisé dans le noyau */
    int semmni;  /* Nombre maximum d'ensembles de sémaphores */
    int semmns;  /* Nombre maximum de sémaphores dans tous
                    les ensembles de sémaphores */
    int semmnu;  /* Nombre maximum de structures d'annulation
                    au niveau du système; inutilisé dans le noyau */
    int semmsl;  /* Nombre maximum de sémaphores dans un
                    ensemble */
    int semopm;  /* Nombre maximum d'opérations pour
                    semop(2) */
    int semume;  /* Nombre maximum d'entrées d'annulation par
                    processus; inutilisé dans le noyau */
    int semusz;  /* Taille de struct sem_undo */
    int semvmx;  /* Valeur maximale d'un sémaphore */
    int semaem;  /* Valeur max. pouvant être enregistrée pour
                    l'ajustement de sémaphore (SEM_UNDO) */
};

Les paramètres semmsl, semmns, semopm et semmni peuvent être modifiés via /proc/sys/kernel/sem ; voir proc(5) pour les détails.
SEM_INFO (spécifique à Linux)
Retourne une structure seminfo contenant les mêmes informations que pour IPC_INFO, sauf que les champs suivants retournent des informations sur les ressources système consommées par les sémaphores : le champ semusz retourne le nombre d'ensembles de sémaphores qui existent actuellement sur le système ; et le champ semaem retourne le nombre total de sémaphores dans tous les ensembles de sémaphores sur le système.
SEM_STAT (spécifique à Linux)
Retourne une structure semid_ds comme pour IPC_STAT. Cependant, l'argument semid n'est pas un identifiant de sémaphore, mais un index dans le tableau interne du noyau qui gère les informations sur tous les ensembles de sémaphores du système.
SEM_STAT_ANY (spécifique à Linux, depuis Linux 4.17)
Retourne une structure semid_ds comme pour SEM_STAT. Cependant, sem_perm.mode n'est pas vérifié pour l'accès en lecture pour semid, ce qui signifie que n'importe quel utilisateur peut utiliser cette opération (tout comme n'importe quel utilisateur peut lire /proc/sysvipc/sem pour obtenir les mêmes informations).
GETALL
Retourne la semval (c'est-à-dire la valeur actuelle) pour tous les sémaphores de l'ensemble dans arg.array. L'argument semnum est ignoré. Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETNCNT
Retourne la valeur semncnt pour le sémaphore numéro semnum de l'ensemble (c'est-à-dire le nombre de processus en attente que la valeur du sémaphore augmente). Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETPID

semctl(2) - Linux manual pages

NAME

semctl - semaphore control operations

LIBRARY

System V IPC (libc, -lc)

SYNOPSIS

#include <sys/sem.h>

int semctl(int semid, int semnum, int cmd, ...);

DESCRIPTION

The semctl() system call performs the control operations described below on the semaphore set indicated by semid. The exact operations available depend on the value of the cmd argument.

The argument semid is a semaphore identifier obtained via a call to semget(2).

The argument semnum specifies the semaphores within the set that the operation should affect. The semaphores are numbered starting from 0.

The argument cmd specifies the operation to be performed. The operations are symbolically represented by constants defined in <sys/sem.h>. The third argument to the function, arg, is a union of type semun (also defined in <sys/sem.h>) and its interpretation depends on the value of cmd.

The semun union is defined as:

union semun {
    int              val;     /* Value for SETVAL */
    struct semid_ds *buf;     /* Buffer for IPC_STAT, IPC_SET */
    unsigned short  *array;   /* Array for GETALL, SETALL */
    struct seminfo  *__buf;   /* Buffer for IPC_INFO (internal) */
};

The following operations are available:

GETALL
Return the semval values for all semaphores of the set in the array pointed to by arg.array. The calling process must have read permission on the semaphore set.
GETNCNT
Return the semncnt value for the semnum-th semaphore of the set (i.e., the number of processes waiting for the semaphore value to become greater than its current value). The calling process must have read permission on the semaphore set.
GETPID
Return the sempid value for the semnum-th semaphore of the set. This is the PID of the process that last performed an operation on that semaphore (but see VERSIONS). The calling process must have read permission on the semaphore set.
GETVAL
Return semval (i.e., the semaphore value) for the semnum-th semaphore of the set. The calling process must have read permission on the semaphore set.
GETZCNT
Return the semzcnt value for the semnum-th semaphore of the set (i.e., the number of processes waiting for the semaphore value to become 0). The calling process must have read permission on the semaphore set.
SETALL
Set the semval values for all semaphores of the set using arg.array, updating also the sem_ctime member of the semid_ds structure associated with the set. Undo entries (see semop(2)) are cleared for altered semaphores in all processes. If the changes to semaphore values would permit blocked semop(2) calls in other processes to proceed, then those processes are woken up. The argument semnum is ignored. The calling process must have alter (write) permission on the semaphore set.
SETVAL
Set the semaphore value (semval) to arg.val for the semnum-th semaphore of the set, updating also the sem_ctime member of the semid_ds structure associated with the set. Undo entries are cleared for altered semaphores in all processes. If the changes to semaphore values would permit blocked semop(2) calls in other processes to proceed, then those processes are woken up. The calling process must have alter permission on the semaphore set.

RETURN VALUE

On success, semctl() returns a nonnegative value depending on op as follows:

GETNCNT
the value of semncnt.
GETPID
the value of sempid.
GETVAL
the value of semval.
GETZCNT
the value of semzcnt.
IPC_INFO
the index of the highest used entry in the kernel's internal array recording information about all semaphore sets. (This information can be used with repeated SEM_STAT or SEM_STAT_ANY operations to obtain information about all semaphore sets on the system.)
SEM_INFO
as for IPC_INFO.
SEM_STAT
the identifier of the semaphore set whose index was given in semid.
SEM_STAT_ANY
as for SEM_STAT.

All other op values return 0 on success.

On failure, semctl() returns -1 and sets errno to indicate the error.

ERRORS

EACCES
The argument op has one of the values GETALL, GETPID, GETVAL, GETNCNT, GETZCNT, IPC_STAT, SEM_STAT, SEM_STAT_ANY, SETALL, or SETVAL and the calling process does not have the required permissions on the semaphore set and does not have the CAP_IPC_OWNER capability in the user namespace that governs its IPC namespace.
EFAULT
The address pointed to by arg.buf or arg.array isn't accessible.
EIDRM
The semaphore set was removed.
EINVAL
Invalid value for op or semid. Or: for a SEM_STAT operation, the index value specified in semid referred to an array slot that is currently unused.
EPERM
The argument op has the value IPC_SET or IPC_RMID but the effective user ID of the calling process is not the creator (as found in sem_perm.cuid) or the owner (as found in sem_perm.uid) of the semaphore set, and the process does not have the CAP_SYS_ADMIN capability.
ERANGE
The argument op has the value SETALL or SETVAL and the value to which semval is to be set (for some semaphore of the set) is less than 0 or greater than the implementation limit SEMVMX.

VERSIONS

POSIX.1 specifies the sem_nsems field of the semid_ds structure as having the type unsigned short, and the field is so defined on most other systems. It was also so defined on Linux 2.2 and earlier, but, since Linux 2.4, the field has the type unsigned long.

The sempid value

POSIX.1 defines sempid as the "process ID of [the] last operation" on a semaphore, and explicitly notes that this value is set by a successful semop(2) call, with the implication that no other interface affects the sempid value.

While some implementations conform to the behavior specified in POSIX.1, others do not. (The fault here probably lies with POSIX.1 inasmuch as it likely failed to capture the full range of existing implementation behaviors.) Various other implementations also update sempid for the other operations that update the value of a semaphore: the SETVAL and SETALL operations, as well as the semaphore adjustments performed on process termination as a consequence of the use of the SEM_UNDO flag (see semop(2)).

Linux also updates sempid for SETVAL operations and semaphore adjustments. However, somewhat inconsistently, up to and including Linux 4.5, the kernel did not update sempid for SETALL operations. This was rectified in Linux 4.6.

STANDARDS

POSIX.1-2024.

HISTORY

POSIX.1-2001, SVr4.

Various fields in a struct semid_ds were typed as short under Linux 2.2 and have become long under Linux 2.4. To take advantage of this, a recompilation under glibc-2.1.91 or later should suffice. (The kernel distinguishes old and new calls by an IPC_64 flag in op.)

In some earlier versions of glibc, the semun union was defined in <sys/sem.h>, but POSIX.1 requires that the caller define this union. On versions of glibc where this union is not defined, the macro _SEM_SEMUN_UNDEFINED is defined in <sys/sem.h>.

NOTES

The IPC_INFO, SEM_STAT, and SEM_INFO operations are used by the ipcs(1) program to provide information on allocated resources. In the future these may modified or moved to a /proc filesystem interface.

The following system limit on semaphore sets affects a semctl() call:

SEMVMX
Maximum value for semval: implementation dependent (32767).

For greater portability, it is best to always call semctl() with four arguments.

EXAMPLES

See shmop(2).

SEE ALSO

ipc(2), semget(2), semop(2), capabilities(7), sem_overview(7), sysvipc(7)

NOM

semctl - opérations de contrôle de sémaphores

BIBLIOTHÈQUE

IPC System V (libc, -lc)

SYNOPSIS

#include <sys/sem.h>

int semctl(int semid, int semnum, int cmd, ...);

DESCRIPTION

L'appel système semctl() effectue les opérations de contrôle décrites ci-dessous sur l'ensemble de sémaphores indiqué par semid. Les opérations exactes disponibles dépendent de la valeur de l'argument cmd.

L'argument semid est un identifiant de sémaphore obtenu via un appel à semget(2).

L'argument semnum spécifie les sémaphores de l'ensemble sur lesquels l'opération doit agir. Les sémaphores sont numérotés à partir de 0.

L'argument cmd spécifie l'opération à effectuer. Les opérations sont symboliquement représentées par des constantes définies dans <sys/sem.h>. Le troisième argument de la fonction, arg, est une union de type semun (également définie dans <sys/sem.h>) et son interprétation dépend de la valeur de cmd.

L'union semun est définie comme suit :

union semun {
    int              val;     /* Valeur pour SETVAL */
    struct semid_ds *buf;     /* Buffer pour IPC_STAT, IPC_SET */
    unsigned short  *array;   /* Tableau pour GETALL, SETALL */
    struct seminfo  *__buf;   /* Buffer pour IPC_INFO (interne) */
};

Les opérations suivantes sont disponibles :

GETALL
Retourne les valeurs semval pour tous les sémaphores de l'ensemble dans le tableau pointé par arg.array. Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETNCNT
Retourne la valeur semncnt pour le sémaphore semnum de l'ensemble (c'est-à-dire le nombre de processus attendant que la valeur du sémaphore devienne supérieure à sa valeur actuelle). Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETPID
Retourne la valeur sempid pour le sémaphore semnum de l'ensemble. C'est le PID du processus qui a effectué la dernière opération sur ce sémaphore (mais voir VERSIONS). Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETVAL
Retourne semval (c'est-à-dire la valeur du sémaphore) pour le sémaphore semnum de l'ensemble. Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
GETZCNT
Retourne la valeur semzcnt pour le sémaphore semnum de l'ensemble (c'est-à-dire le nombre de processus attendant que la valeur du sémaphore devienne 0). Le processus appelant doit avoir la permission de lecture sur l'ensemble de sémaphores.
SETALL
Définit les valeurs semval pour tous les sémaphores de l'ensemble en utilisant arg.array, met également à jour le membre sem_ctime de la structure semid_ds associée à l'ensemble. Les entrées d'annulation (voir semop(2)) sont effacées pour les sémaphores modifiés dans tous les processus. Si les modifications des valeurs des sémaphores permettent à des appels semop(2) bloqués dans d'autres processus de continuer, alors ces processus sont réveillés. L'argument semnum est ignoré. Le processus appelant doit avoir la permission de modification (écriture) sur l'ensemble de sémaphores.
SETVAL
Définit la valeur du sémaphore (semval) à arg.val pour le sémaphore semnum de l'ensemble, mettant également à jour le membre sem_ctime de la structure semid_ds associée à l'ensemble. Les entrées d'annulation sont effacées pour les sémaphores modifiés dans tous les processus. Si les modifications des valeurs des sémaphores permettent à des appels semop(2) bloqués dans d'autres processus de continuer, alors ces processus sont réveillés. Le processus appelant doit avoir la permission de modification sur l'ensemble de sémaphores.

VALEUR DE RETOUR

En cas de succès, semctl() retourne une valeur non négative selon op comme suit :

GETNCNT
la valeur de semncnt.
GETPID
la valeur de sempid.
GETVAL
la valeur de semval.
GETZCNT
la valeur de semzcnt.
IPC_INFO
l'index de la plus haute entrée utilisée dans le tableau interne du noyau enregistrant les informations sur tous les ensembles de sémaphores. (Ces informations peuvent être utilisées avec des opérations répétées SEM_STAT ou SEM_STAT_ANY pour obtenir des informations sur tous les ensembles de sémaphores du système.)
SEM_INFO
comme pour IPC_INFO.
SEM_STAT
l'identifiant de l'ensemble de sémaphores dont l'index a été donné dans semid.
SEM_STAT_ANY
comme pour SEM_STAT.

Toutes les autres valeurs de op retournent 0 en cas de succès.

En cas d'échec, semctl() retourne -1 et définit errno pour indiquer l'erreur.

ERREURS

EACCES
L'argument op a l'une des valeurs GETALL, GETPID, GETVAL, GETNCNT, GETZCNT, IPC_STAT, SEM_STAT, SEM_STAT_ANY, SETALL, ou SETVAL et le processus appelant n'a pas les permissions requises sur l'ensemble de sémaphores et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EFAULT
L'adresse pointée par arg.buf ou arg.array n'est pas accessible.
EIDRM
L'ensemble de sémaphores a été supprimé.
EINVAL
Valeur invalide pour op ou semid. Ou : pour une opération SEM_STAT, la valeur d'index spécifiée dans semid faisait référence à un emplacement de tableau actuellement inutilisé.
EPERM
L'argument op a la valeur IPC_SET ou IPC_RMID mais l'ID utilisateur effectif du processus appelant n'est ni le créateur (trouvé dans sem_perm.cuid) ni le propriétaire (trouvé dans sem_perm.uid) de l'ensemble de sémaphores, et le processus n'a pas la capacité CAP_SYS_ADMIN.
ERANGE
L'argument op a la valeur SETALL ou SETVAL et la valeur à laquelle semval doit être définie (pour un sémaphore de l'ensemble) est inférieure à 0 ou supérieure à la limite d'implémentation SEMVMX.

VERSIONS

POSIX.1 spécifie que le champ sem_nsems de la structure semid_ds a le type unsigned short, et ce champ est ainsi défini sur la plupart des autres systèmes. Il était également ainsi défini sous Linux 2.2 et versions antérieures, mais, depuis Linux 2.4, le champ a le type unsigned long.

La valeur sempid

POSIX.1 définit sempid comme "l'identifiant du processus de [la] dernière opération" sur un sémaphore, et note explicitement que cette valeur est définie par un appel semop(2) réussi, avec l'implication qu'aucune autre interface n'affecte la valeur sempid.

Bien que certaines implémentations se conforment au comportement spécifié dans POSIX.1, d'autres ne le font pas. (La faute incombe probablement à POSIX.1 dans la mesure où elle n'a probablement pas capturé toute la gamme des comportements d'implémentation existants.) Diverses autres implémentations mettent également à jour sempid pour les autres opérations qui mettent à jour la valeur d'un sémaphore : les opérations SETVAL et SETALL, ainsi que les ajustements de sémaphore effectués lors de la terminaison du processus suite à l'utilisation du drapeau SEM_UNDO (voir semop(2)).

Linux met également à jour sempid pour les opérations SETVAL et les ajustements de sémaphores. Cependant, de manière quelque peu incohérente, jusqu'à et y compris Linux 4.5, le noyau ne mettait pas à jour sempid pour les opérations SETALL. Cela a été corrigé dans Linux 4.6.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Divers champs de la structure struct semid_ds étaient typiquement des short sous Linux 2.2 et sont devenus des long sous Linux 2.4. Pour en tirer parti, une recompilation sous glibc-2.1.91 ou une version ultérieure devrait suffire. (Le noyau distingue les anciens et les nouveaux appels par un drapeau IPC_64 dans op.)

Dans certaines versions antérieures de glibc, l'union semun était définie dans <sys/sem.h>, mais POSIX.1 exige que l'appelant définisse cette union. Sur les versions de glibc où cette union n'est *pas* définie, la macro _SEM_SEMUN_UNDEFINED est définie dans <sys/sem.h>.

NOTES

Les opérations IPC_INFO, SEM_STAT et SEM_INFO sont utilisées par le programme ipcs(1) pour fournir des informations sur les ressources allouées. À l'avenir, elles pourraient être modifiées ou déplacées vers une interface de système de fichiers /proc.

La limite système suivante sur les ensembles de sémaphores affecte un appel semctl() :

SEMVMX
Valeur maximale pour semval : dépend de l'implémentation (32767).

Pour une meilleure portabilité, il est préférable d'appeler toujours semctl() avec quatre arguments.

EXEMPLES

Voir shmop(2).

VOIR AUSSI

semctl(2)

semctl - semctl system calls

NAME

semctl - semctl system calls

SYNOPSIS

#include <sys/sem.h>

int semctl(int semid, int semnum, int cmd, ...);

DESCRIPTION

The semctl() system call performs the control operations described by cmd on the semaphore set indicated by semid.

semid is the identifier of the semaphore set.

semnum is the semaphore number within the set. semnum is 0-based.

cmd is the control operation to perform. The standard POSIX IPC commands are:

SETVAL
Set the value of the semaphore identified by semnum to the value contained in the sem_perm.seq field of the argument structure semun . This command is effective only if semnum is 0. The argument is a pointer to a union semun.
SETALL
Set the values of all semaphores in the set to the values contained in the array pointed to by the sem_perm.seq field of the argument structure semun . The number of elements in the array must be equal to the number of semaphores in the set. This command is effective only if semnum is 0. The argument is a pointer to a union semun.
GETVAL
Return the value of the semaphore identified by semnum . The argument is ignored.
GETALL
Return the values of all semaphores in the set to the array pointed to by the sem_perm.seq field of the argument structure semun . The number of elements in the array must be at least equal to the number of semaphores in the set. This command is effective only if semnum is 0. The argument is a pointer to a union semun.
GETPID
Return the process ID (PID) of the last process to perform an operation on the semaphore identified by semnum . The argument is ignored.
GETNCNT
Return the number of processes that are currently waiting for the semaphore identified by semnum to increase its value. The argument is ignored.
GETZCNT
Return the number of processes that are currently waiting for the semaphore identified by semnum to become zero. The argument is ignored.

The semun union is defined as:

union semun {
    int              sem_num;
    struct semid_ds *sem_ds;
    ushort          *sem_perms;
    struct seminfo  *__sem_info;     /* defined in kernel */
};

For SETVAL, SETALL, GETVAL, GETALL, GETPID, GETNCNT, and GETZCNT , the argument arg is a pointer to a union semun . The specific member used depends on the value of cmd.

The GETALL and SETALL commands require sem_perm.seq to point to an array of ushort . The GETPID, GETNCNT, and GETZCNT commands do not use the semun union.

Other commands may be available:

IPC_STAT
Return status information for the semaphore set identified by semid in the structure pointed to by sem_perm.seq . The argument is a pointer to a union semun.
IPC_SET
Set the sem_perm.uid , sem_perm.gid , and sem_perm.mode fields of the semaphore set structure to the corresponding values in the structure pointed to by sem_perm.seq . This operation can only be performed by the owner of the semaphore set or by a process with the CAP_SYS_ADMIN capability. The argument is a pointer to a union semun.
IPC_RMID
Remove the semaphore set. The argument is ignored. This operation can only be performed by the owner of the semaphore set or by a process with the CAP_SYS_ADMIN capability.

A semaphore set is a structure containing:

struct semid_ds {
    struct ipc_perm sem_perm; /* Ownership and permissions */
    struct semaphore  *sem_base;  /* Pointer to first semaphore in set */
    ushort            sem_nsems;  /* No. of semaphores in set */
    time_t            sem_otime;  /* Last semop operation time */
    time_t            sem_ctime;  /* Last change time */
    /* ... more fields ... */
};

The ipc_perm structure is defined as:

struct ipc_perm {
    key_t          key;      /* Key supplied to semget(2) */
    uid_t          uid;      /* Real UID of owner */
    gid_t          gid;      /* Real GID of owner */
    uid_t          cuid;     /* Effective UID of owner */
    gid_t          cgid;     /* Effective GID of owner */
    mode_t         mode;     /* Permissions */
    ushort         seq;      /* Sequence number */
    /* ... more fields ... */
};

RETURN VALUE

On success, the value returned depends on the cmd argument:

  • GETVAL: The value of the requested semaphore.
  • GETPID: The PID of the last process to perform an operation on the semaphore.
  • GETNCNT: The number of processes waiting for the semaphore value to increase.
  • GETZCNT: The number of processes waiting for the semaphore value to become zero.
  • GETALL: 0 .
  • SETVAL, SETALL, IPC_SET, IPC_RMID: 0 .
  • IPC_STAT: The value of semid .

On failure, semctl() returns -1 and sets errno to indicate the error.

ERRORS

EACCES
Operation is not permitted due to permissions.
EFAULT
arg points to an inaccessible buffer.
EINVAL
semid is not a valid semaphore identifier, or semnum is out of range, or cmd is invalid.
ENOSPC
cmd is SETVAL or SETALL , and the system limit on the number of semaphores has been reached.
EPERM
cmd is IPC_RMID or IPC_SET , and the calling process does not have the required privileges.
ENOMSG
cmd is GETALL or SETALL , and the sem_perm.seq argument is invalid.

STANDARDS

POSIX.1-2001, POSIX.1-2008.

HISTORY

The semctl() system call was introduced by the POSIX.1 standard.

NOTES

The behavior of semctl() can be complex, and it is often recommended to use semget() and semop() instead, as they are generally simpler to use and less error-prone.

The sem_perm.seq member of the union semun is used for different purposes depending on the command. It can be a pointer to a struct semid_ds, an array of ushort, or other types. The programmer must ensure that the correct type is passed for the given command.

The sem_perm.mode field contains the permissions for the semaphore set. The lower 9 bits are used for user, group, and other read/write permissions. The higher bits are used for the sticky bit and other flags.

The sem_base field in struct semid_ds is a pointer to the first semaphore in the set. The actual semaphore data is stored in an array of struct semaphore , where each struct semaphore contains the current value, waiting count, and PID of the last process to perform an operation.

The sem_otime and sem_ctime fields in struct semid_ds are used to record the last operation time and last change time, respectively.

The sem_nsems field indicates the number of semaphores in the set.

The sem_perm.key field stores the key that was used to create the semaphore set with semget().

The sem_perm.uid and sem_perm.gid fields store the real UID and GID of the owner of the semaphore set, respectively. The sem_perm.cuid and sem_perm.cgid fields store the effective UID and GID of the creator of the semaphore set.

The sem_perm.seq field is a sequence number that is used to prevent race conditions when multiple processes attempt to access or modify the semaphore set.

The sem_perm.mode field contains the permissions for the semaphore set. The lower 9 bits are used for user, group, and other read/write permissions. The higher bits are used for the sticky bit and other flags.

EXAMPLES

/* Example of using semctl to get the value of a semaphore */
#include <stdio.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

int main() {
    int semid;
    int semnum = 0;
    union semun arg;
    int value;

    /* Get semaphore set ID (replace with your actual semid) */
    semid = /* ... get semid ... */ ; 

    arg.sem_num = semnum;
    value = semctl(semid, semnum, GETVAL, arg);

    if (value == -1) {
        perror("semctl");
        return 1;
    }

    printf("Semaphore %d value: %d\n", semnum, value);

    return 0;
}
