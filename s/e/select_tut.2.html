SELECT_TUT(2) Manuel des appels système SELECT_TUT(2)

NOM

select, pselect - multiplexage d'E/S synchrone

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

Voir select(2)

DESCRIPTION

Les appels système select() et pselect() sont utilisés pour surveiller efficacement plusieurs descripteurs de fichiers, afin de déterminer si l'un d'entre eux est, ou devient, "prêt" ; c'est-à-dire, pour savoir si des E/S sont possibles, ou si une "condition exceptionnelle" s'est produite sur l'un des descripteurs de fichiers.

Cette page fournit des informations de base et un tutoriel sur l'utilisation de ces appels système. Pour les détails des arguments et des sémantiques de select() et pselect(), voir select(2).

Combinaison d'événements de signaux et de données

pselect() est utile si vous attendez un signal en plus que des descripteurs de fichiers soient prêts pour les E/S. Les programmes qui reçoivent des signaux utilisent normalement le gestionnaire de signaux uniquement pour lever un drapeau global. Le drapeau global indiquera que l'événement doit être traité dans la boucle principale du programme. Un signal provoquera le retour de l'appel select() (ou pselect()) avec errno défini à EINTR. Ce comportement est essentiel afin que les signaux puissent être traités dans la boucle principale du programme, sinon select() bloquerait indéfiniment.

Maintenant, quelque part dans la boucle principale, il y aura une condition pour vérifier le drapeau global. Alors nous devons nous demander : que se passe-t-il si un signal arrive après la condition, mais avant l'appel select() ? La réponse est que select() bloquerait indéfiniment, même si un événement est réellement en attente. Cette condition de course est résolue par l'appel pselect(). Cet appel peut être utilisé pour définir le masque de signaux à un ensemble de signaux qui doivent être reçus uniquement pendant l'appel pselect(). Par exemple, supposons que l'événement en question était la sortie d'un processus enfant. Avant le début de la boucle principale, nous bloquerions SIGCHLD en utilisant sigprocmask(2). Notre appel pselect() activerait SIGCHLD en utilisant un masque de signaux vide. Notre programme ressemblerait à ceci :

static volatile sig_atomic_t got_SIGCHLD = 0;
static void
child_sig_handler(int sig)
{
    got_SIGCHLD = 1;
}
int
main(int argc, char *argv[])
{
    sigset_t sigmask, empty_mask;
    struct sigaction sa;
    fd_set readfds, writefds, exceptfds;
    int r;
    sigemptyset(&sigmask);
    sigaddset(&sigmask, SIGCHLD);
    if (sigprocmask(SIG_BLOCK, &sigmask, NULL) == -1) {
        perror("sigprocmask");
        exit(EXIT_FAILURE);
    }
    sa.sa_flags = 0;
    sa.sa_handler = child_sig_handler;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGCHLD, &sa, NULL) == -1) {
        perror("sigaction");
        exit(EXIT_FAILURE);
    }
    sigemptyset(&empty_mask);
    for (;;) {          /* boucle principale */
        /* Initialiser readfds, writefds, et exceptfds
           avant l'appel pselect(). (Code omis.)  */
        r = pselect(nfds, &readfds, &writefds, &exceptfds,
                    NULL, &empty_mask);
        if (r == -1 && errno != EINTR) {
            /* Gérer l'erreur */
        }
        if (got_SIGCHLD) {
            got_SIGCHLD = 0;
            /* Gérer l'événement signalé ici ; par ex., attendre() tous les
               enfants terminés.  (Code omis.)  */
        }
        /* Corps principal du programme */
    }
}

Pratique

Quel est donc l'intérêt de select() ? Ne puis-je pas simplement lire et écrire sur mes descripteurs de fichiers quand je veux ? L'intérêt de select() est qu'il surveille plusieurs descripteurs en même temps et endort correctement le processus s'il n'y a pas d'activité. Les programmeurs UNIX se retrouvent souvent dans la position où ils doivent gérer les E/S de plus d'un descripteur de fichier où le flux de données peut être intermittent. Si vous vous contentiez de créer une séquence d'appels read(2) et write(2), vous trouveriez qu'un de vos appels peut bloquer en attendant des données depuis/vers un descripteur de fichier, alors qu'un autre descripteur de fichier est inutilisé bien que prêt pour les E/S. select() gère efficacement cette situation.

Loi de select

Beaucoup de personnes qui essaient d'utiliser select() rencontrent un comportement difficile à comprendre et qui produit des résultats non portables ou limites. Par exemple, le programme ci-dessus est écrit avec soin pour ne pas bloquer à aucun moment, même s'il ne met pas ses descripteurs de fichiers en mode non bloquant. Il est facile d'introduire des erreurs subtiles qui supprimeront l'avantage d'utiliser select(), donc voici une liste d'éléments essentiels à surveiller lors de l'utilisation de select().

1.
Vous devriez toujours essayer d'utiliser select() sans délai d'attente. Votre programme ne devrait rien faire s'il n'y a pas de données disponibles. Le code qui dépend des délais d'attente n'est généralement pas portable et est difficile à déboguer.
2.
La valeur nfds doit être calculée correctement pour l'efficacité, comme expliqué ci-dessus.
3.
Aucun descripteur de fichier ne doit être ajouté à un ensemble si vous n'avez pas l'intention de vérifier son résultat après l'appel select(), et de répondre de manière appropriée. Voir la règle suivante.
4.
Après le retour de select(), tous les descripteurs de fichiers dans tous les ensembles doivent être vérifiés pour voir s'ils sont prêts.
5.
Les fonctions read(2), recv(2), write(2), et send(2) ne lisent/écrivent pas nécessairement la quantité totale de données que vous avez demandée. Si elles lisent/écrivent la quantité totale, c'est parce que vous avez une faible charge de trafic et un flux rapide. Ce ne sera pas toujours le cas. Vous devriez gérer le cas où vos fonctions parviennent à envoyer ou recevoir un seul octet.
6.
Ne lisez/écrivez jamais par blocs d'un seul octet à la fois, à moins que vous ne soyez vraiment sûr de devoir traiter une petite quantité de données. Il est extrêmement inefficace de ne pas lire/écrire autant de données que possible à chaque fois. Les tampons dans l'exemple ci-dessous sont de 1024 octets, bien qu'ils puissent facilement être rendus plus grands.
7.
Les appels à read(2), recv(2), write(2), et send(2) peuvent échouer avec l'erreur EINTR, et les appels à read(2), recv(2), write(2), et send(2) peuvent échouer avec errno défini à EAGAIN (EWOULDBLOCK). Ces résultats doivent être gérés correctement (non fait correctement ci-dessus). Si votre programme ne reçoit aucun signal, il est peu probable que vous obteniez EINTR. Si votre programme ne définit pas les E/S non bloquantes, vous n'obtiendrez pas EAGAIN.
8.
N'appelez jamais read(2), recv(2), write(2), ou send(2) avec une longueur de tampon de zéro.
9.
Si les fonctions read(2), recv(2), write(2), et send(2) échouent avec des erreurs autres que celles listées dans 7., ou si une des fonctions d'entrée retourne 0, indiquant la fin de fichier, alors vous ne devriez *pas* passer ce descripteur de fichier à select() à nouveau. Dans l'exemple ci-dessous, je ferme le descripteur de fichier immédiatement, et le définis ensuite à -1 pour éviter qu'il ne soit inclus dans un ensemble.
10.
La valeur du délai d'attente doit être initialisée à chaque nouvel appel à select(), car certains systèmes d'exploitation modifient la structure. Cependant, pselect() ne modifie pas sa structure de délai d'attente.
11.
Comme select() modifie ses ensembles de descripteurs de fichiers, si l'appel est utilisé dans une boucle, les ensembles doivent être réinitialisés avant chaque appel.

VALEUR DE RETOUR

Voir select(2).

L'appel système poll(2) a la même fonctionnalité que select(), et est quelque peu plus efficace lors de la surveillance d'ensembles de descripteurs de fichiers épars. Il est aujourd'hui largement disponible, mais était historiquement moins portable que select().

L'API epoll(7) spécifique à Linux fournit une interface plus efficace que select(2) et poll(2) lors de la surveillance d'un grand nombre de descripteurs de fichiers.

EXEMPLES

Voici un exemple qui démontre mieux l'utilité réelle de select(). La liste ci-dessous est un programme de redirection TCP qui redirige d'un port TCP vers un autre.

#include <arpa/inet.h>
#include <errno.h>
#include <netinet/in.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/select.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
static int forward_port;
#undef max
#define max(x, y) ((x) > (y) ? (x) : (y))
static int
listen_socket(int listen_port)
{
    int                 lfd;
    int                 yes;
    struct sockaddr_in  addr;
    lfd = socket(AF_INET, SOCK_STREAM, 0);
    if (lfd == -1) {
        perror("socket");
        return -1;
    }
    yes = 1;
    if (setsockopt(lfd, SOL_SOCKET, SO_REUSEADDR,
                   &yes, sizeof(yes)) == -1)
    {
        perror("setsockopt");
        close(lfd);
        return -1;
    }
    memset(&addr, 0, sizeof(addr));
    addr.sin_port = htons(listen_port);
    addr.sin_family = AF_INET;
    if (bind(lfd, (struct sockaddr *) &addr, sizeof(addr)) == -1) {
        perror("bind");
        close(lfd);
        return -1;
    }
    printf("accepting connections on port %d\n", listen_port);
    listen(lfd, 10);
    return lfd;
}
static int
connect_socket(int connect_port, char *address)
{
    int                 cfd;
    struct sockaddr_in  addr;
    cfd = socket(AF_INET, SOCK_STREAM, 0);
    if (cfd == -1) {
        perror("socket");
        return -1;
    }
    memset(&addr, 0, sizeof(addr));
    addr.sin_port = htons(connect_port);
    addr.sin_family = AF_INET;
    if (!inet_aton(address, (struct in_addr *) &addr.sin_addr.s_addr)) {
        fprintf(stderr, "inet_aton(): bad IP address format\n");
        close(cfd);
        return -1;
    }
    if (connect(cfd, (struct sockaddr *) &addr, sizeof(addr)) == -1) {
        perror("connect()");
        shutdown(cfd, SHUT_RDWR);
        close(cfd);
        return -1;
    }
    return cfd;
}
#define SHUT_FD1 do {                                \
                     if (fd1 >= 0) {                 \
                         shutdown(fd1, SHUT_RDWR);   \
                         close(fd1);                 \
                         fd1 = -1;                   \
                     }                               \
                 } while (0)
#define SHUT_FD2 do {                                \
                     if (fd2 >= 0) {                 \
                         shutdown(fd2, SHUT_RDWR);   \
                         close(fd2);                 \
                         fd2 = -1;                   \
                     }                               \
                 } while (0)
#define BUF_SIZE 1024
int
main(int argc, char *argv[])
{
    int      h;
    int      ready, nfds;
    int      fd1 = -1, fd2 = -1;
    int      buf1_avail = 0, buf1_written = 0;
    int      buf2_avail = 0, buf2_written = 0;
    char     buf1[BUF_SIZE], buf2[BUF_SIZE];
    fd_set   readfds, writefds, exceptfds;
    ssize_t  nbytes;
    if (argc != 4) {
        fprintf(stderr, "Usage\n\tfwd <listen-port> "
                "<forward-to-port> <forward-to-ip-address>\n");
        exit(EXIT_FAILURE);
    }
    signal(SIGPIPE, SIG_IGN);
    forward_port = atoi(argv[2]);
    h = listen_socket(atoi(argv[1]));
    if (h == -1)
        exit(EXIT_FAILURE);
    for (;;) {
        nfds = 0;
        FD_ZERO(&readfds);
        FD_ZERO(&writefds);
        FD_ZERO(&exceptfds);
        FD_SET(h, &readfds);
        nfds = max(nfds, h);
        if (fd1 > 0 && buf1_avail < BUF_SIZE)
            FD_SET(fd1, &readfds);
            /* Note: nfds is updated below, when fd1 is added to
               exceptfds.  */
        if (fd2 > 0 && buf2_avail < BUF_SIZE)
            FD_SET(fd2, &readfds);
        if (fd1 > 0 && buf2_avail - buf2_written > 0)
            FD_SET(fd1, &writefds);
        if (fd2 > 0 && buf1_avail - buf1_written > 0)
            FD_SET(fd2, &writefds);
        if (fd1 > 0) {
            FD_SET(fd1, &exceptfds);
            nfds = max(nfds, fd1);
        }
        if (fd2 > 0) {
            FD_SET(fd2, &exceptfds);
            nfds = max(nfds, fd2);
        }
        ready = select(nfds + 1, &readfds, &writefds, &exceptfds, NULL);
        if (ready == -1 && errno == EINTR)
            continue;
        if (ready == -1) {
            perror("select()");
            exit(EXIT_FAILURE);
        }
        if (FD_ISSET(h, &readfds)) {
            socklen_t addrlen;
            struct sockaddr_in client_addr;
            int fd;
            addrlen = sizeof(client_addr);
            memset(&client_addr, 0, addrlen);
            fd = accept(h, (struct sockaddr *) &client_addr, &addrlen);
            if (fd == -1) {
                perror("accept()");
            } else {
                SHUT_FD1;
                SHUT_FD2;
                buf1_avail = buf1_written = 0;
                buf2_avail = buf2_written = 0;
                fd1 = fd;
                fd2 = connect_socket(forward_port, argv[3]);
                if (fd2 == -1)
                    SHUT_FD1;
                else
                    printf("connect from %s\n",
                           inet_ntoa(client_addr.sin_addr));
                /* Skip any events on the old, closed file
                   descriptors.  */
                continue;
            }
        }
        /* NB: read OOB data before normal reads.  */
        if (fd1 > 0 && FD_ISSET(fd1, &exceptfds)) {
            char c;
            nbytes = recv(fd1, &c, 1, MSG_OOB);
            if (nbytes < 1)
                SHUT_FD1;
            else
                send(fd2, &c, 1, MSG_OOB);
        }
        if (fd2 > 0 && FD_ISSET(fd2, &exceptfds)) {
            char c;
            nbytes = recv(fd2, &c, 1, MSG_OOB);
            if (nbytes < 1)
                SHUT_FD2;
            else
                send(fd1, &c, 1, MSG_OOB);
        }
        if (fd1 > 0 && FD_ISSET(fd1, &readfds)) {
            nbytes = read(fd1, buf1 + buf1_avail,
                          BUF_SIZE - buf1_avail);
            if (nbytes < 1)
                SHUT_FD1;
            else
                buf1_avail += nbytes;
        }
        if (fd2 > 0 && FD_ISSET(fd2, &readfds)) {
            nbytes = read(fd2, buf2 + buf2_avail,
                          BUF_SIZE - buf2_avail);
            if (nbytes < 1)
                SHUT_FD2;
            else
                buf2_avail += nbytes;
        }
        if (fd1 > 0 && FD_ISSET(fd1, &writefds) && buf2_avail > 0) {
            nbytes = write(fd1, buf2 + buf2_written,
                           buf2_avail - buf2_written);
            if (nbytes < 1)
                SHUT_FD1;
            else
                buf2_written += nbytes;
        }
        if (fd2 > 0 && FD_ISSET(fd2, &writefds) && buf1_avail > 0) {
            nbytes = write(fd2, buf1 + buf1_written,
                           buf1_avail - buf1_written);
            if (nbytes < 1)
                SHUT_FD2;
            else
                buf1_written += nbytes;
        }
        /* Check if write data has caught read data.  */
        if (buf1_written == buf1_avail)
            buf1_written = buf1_avail = 0;
        if (buf2_written == buf2_avail)
            buf2_written = buf2_avail = 0;
        /* One side has closed the connection, keep
           writing to the other side until empty.  */
        if (fd1 < 0 && buf1_avail - buf1_written == 0)
            SHUT_FD2;
        if (fd2 < 0 && buf2_avail - buf2_written == 0)
            SHUT_FD1;
    }
    exit(EXIT_SUCCESS);
}

Le programme ci-dessus redirige correctement la plupart des types de connexions TCP, y compris les données de signal OOB transmises par les serveurs telnet. Il gère le problème délicat de faire circuler les données dans les deux sens simultanément. Vous pourriez penser qu'il serait plus efficace d'utiliser un appel fork(2) et de dédier un thread à chaque flux. Cela devient plus délicat que vous ne le soupçonnez. Une autre idée est de définir des E/S non bloquantes à l'aide de fcntl(2). Cela a aussi ses problèmes car vous finissez par utiliser des timeouts inefficaces.

Le programme ne gère qu'une seule connexion simultanée à la fois, bien qu'il puisse être facilement étendu pour le faire avec une liste chaînée de tampons - un pour chaque connexion. Pour le moment, les nouvelles connexions entraînent la fermeture de la connexion actuelle.
