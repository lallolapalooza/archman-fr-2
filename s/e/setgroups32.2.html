getgroups(2) Manuel des appels système getgroups(2)

NOM

getgroups, setgroups - obtenir/définir la liste des identifiants de groupe supplémentaires

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int getgroups(int size, gid_t list[_Nullable size]);
#include <grp.h>
int setgroups(size_t size, const gid_t list[size]);
Conditions requises pour les macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

setgroups():

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE

DESCRIPTION

getgroups() renvoie les identifiants de groupe supplémentaires du processus appelant dans list. L'argument size doit être défini sur le nombre maximum d'éléments pouvant être stockés dans le tampon pointé par list. Si le processus appelant est membre de plus de size groupes supplémentaires, une erreur se produit.

Il n'est pas spécifié si l'identifiant de groupe effectif du processus appelant est inclus dans la liste renvoyée. (Ainsi, une application devrait également appeler getegid(2) et ajouter ou supprimer la valeur résultante.)

Si size est zéro, list n'est pas modifié, mais le nombre total d'identifiants de groupe supplémentaires pour le processus est renvoyé. Cela permet à l'appelant de déterminer la taille d'une list allouée dynamiquement à utiliser dans un autre appel à getgroups().

setgroups() définit les identifiants de groupe supplémentaires pour le processus appelant. Des privilèges appropriés sont requis (voir la description de l'erreur EPERM, ci-dessous). L'argument size spécifie le nombre d'identifiants de groupe supplémentaires dans le tampon pointé par list. Un processus peut abandonner tous ses groupes supplémentaires avec l'appel :


setgroups(0, (gid_t [0]){});

VALEUR DE RETOUR

En cas de succès, getgroups() renvoie le nombre d'identifiants de groupe supplémentaires. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

En cas de succès, setgroups() renvoie 0. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
list a une adresse invalide.

getgroups() peut également échouer avec l'erreur suivante :

EINVAL
size est inférieur au nombre d'identifiants de groupe supplémentaires, mais n'est pas zéro.

setgroups() peut également échouer avec les erreurs suivantes :

EINVAL
size est supérieur à NGROUPS_MAX (32 avant Linux 2.6.4 ; 65536 depuis Linux 2.6.4).
ENOMEM
Mémoire insuffisante.
EPERM
Le processus appelant n'a pas les privilèges suffisants (l'appelant n'a pas la capacité CAP_SETGID dans l'espace de noms utilisateur où il réside).
EPERM (depuis Linux 3.19)
L'utilisation de setgroups() est refusée dans cet espace de noms utilisateur. Voir la description de /proc/pid/setgroups dans user_namespaces(7).

VERSIONS

Différences bibliothèque C/noyau

Au niveau du noyau, les identifiants utilisateur et groupe sont un attribut par thread. Cependant, POSIX exige que tous les threads d'un processus partagent les mêmes informations d'identification. L'implémentation du multithreading NPTL gère les exigences POSIX en fournissant des fonctions enveloppantes pour les divers appels système qui modifient les UID et GID des processus. Ces fonctions enveloppantes (y compris celle pour setgroups()) utilisent une technique basée sur les signaux pour garantir que lorsqu'un thread modifie ses informations d'identification, tous les autres threads du processus modifient également les leurs. Pour plus de détails, voir nptl(7).

NORMES

HISTORIQUE

getgroups()
SVr4, 4.3BSD, POSIX.1-2001.
setgroups()
SVr4, 4.3BSD. Comme setgroups() nécessite des privilèges, il n'est pas couvert par POSIX.1.

L'appel système getgroups() original de Linux ne prenait en charge que les identifiants de groupe de 16 bits. Par la suite, Linux 2.4 a ajouté getgroups32(), prenant en charge les identifiants de 32 bits. La fonction enveloppante getgroups() de glibc gère de manière transparente les variations entre les versions du noyau.

NOTES

Un processus peut avoir jusqu'à NGROUPS_MAX identifiants de groupe supplémentaires en plus de l'identifiant de groupe effectif. La constante NGROUPS_MAX est définie dans <limits.h>. L'ensemble des identifiants de groupe supplémentaires est hérité du processus parent et conservé lors d'un appel à execve(2).

Le nombre maximum d'identifiants de groupe supplémentaires peut être trouvé à l'exécution à l'aide de sysconf(3) :


long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX);

La valeur de retour maximale de getgroups() ne peut pas être supérieure à cette valeur plus un. Depuis Linux 2.6.4, le nombre maximum d'identifiants de groupe supplémentaires est également exposé via le fichier en lecture seule spécifique à Linux, /proc/sys/kernel/ngroups_max.

EXEMPLES

#include <err.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
#define MALLOC(n, T)  ((T *) reallocarray(NULL, n, sizeof(T)))
static gid_t *agetgroups(size_t *ngids);
int
main(void)
{
    gid_t   *gids;
    size_t  n;
    gids = agetgroups(&n);
    if (gids == NULL)
        err(EXIT_FAILURE, "agetgroups");
    if (n != 0) {
        printf("%jd", (intmax_t) gids[0]);
        for (size_t i = 1; i < n; i++)
            printf(" %jd", (intmax_t) gids[i]);
    }
    puts("");
    free(gids);
    exit(EXIT_SUCCESS);
}
static gid_t *
agetgroups(size_t *ngids)
{
    int    n;
    gid_t  *gids;
    n = getgroups(0, NULL);
    if (n == -1)
        return NULL;
    gids = MALLOC(n, gid_t);
    if (gids == NULL)
        return NULL;
    n = getgroups(n, gids);
    if (n == -1) {
        free(gids);
        return NULL;
    }
    *ngids = n;
    return gids;
}
