setreuid(2) Manuel des appels système setreuid(2)

NOM

setreuid, setregid - définir l'ID utilisateur ou groupe réel et/ou effectif

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE

DESCRIPTION

setreuid() définit les identifiants utilisateur réels et effectifs du processus appelant.

Fournir une valeur de -1 pour l'identifiant utilisateur réel ou effectif laisse cet ID inchangé.

Les processus non privilégiés ne peuvent définir l'identifiant utilisateur effectif qu'à l'identifiant utilisateur réel, à l'identifiant utilisateur effectif, ou à l'identifiant utilisateur marqué (saved set-user-ID).

Les utilisateurs non privilégiés ne peuvent définir l'identifiant utilisateur réel qu'à l'identifiant utilisateur réel ou à l'identifiant utilisateur effectif.

Si l'identifiant utilisateur réel est défini (c'est-à-dire que ruid n'est pas -1) ou si l'identifiant utilisateur effectif est défini à une valeur différente de l'identifiant utilisateur réel précédent, l'identifiant utilisateur marqué sera défini à la nouvelle valeur de l'identifiant utilisateur effectif.

De manière totalement analogue, setregid() définit les identifiants de groupe réels et effectifs du processus appelant, et tout ce qui précède s'applique avec le mot "groupe" à la place de "utilisateur".

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est définie pour indiquer l'erreur.

Note : il existe des cas où setreuid() peut échouer même lorsque l'appelant a l'UID 0 ; omettre de vérifier un retour d'échec de setreuid() constitue une grave erreur de sécurité.

ERREURS

EAGAIN
L'appel modifierait l'UID réel de l'appelant (c'est-à-dire que ruid ne correspond pas à l'UID réel de l'appelant), mais il y a eu un échec temporaire d'allocation des structures de données noyau nécessaires.
EAGAIN
ruid ne correspond pas à l'UID réel de l'appelant et cet appel dépasserait la limite de ressources RLIMIT_NPROC pour l'UID réel ruid. Depuis Linux 3.1, ce cas d'erreur ne se produit plus (mais les applications robustes devraient vérifier cette erreur) ; voir la description de EAGAIN dans execve(2).
EINVAL
Un ou plusieurs des identifiants utilisateur ou groupe cibles ne sont pas valides dans cet espace de noms utilisateur.
EPERM
Le processus appelant n'est pas privilégié (sur Linux, ne possède pas la capacité nécessaire dans son espace de noms utilisateur : CAP_SETUID dans le cas de setreuid(), ou CAP_SETGID dans le cas de setregid()) et une modification autre que (i) l'échange de l'identifiant effectif (de groupe) avec l'identifiant réel (de groupe), ou (ii) la définition de l'un à la valeur de l'autre, ou (iii) la définition de l'identifiant effectif (de groupe) à la valeur de l'identifiant marqué (saved set-user-ID / saved set-group-ID) a été spécifiée.

VERSIONS

POSIX.1 ne spécifie pas toutes les modifications d'UID que Linux permet pour un processus non privilégié. Pour setreuid(), l'identifiant utilisateur effectif peut être rendu identique à l'identifiant utilisateur réel ou à l'identifiant utilisateur marqué, et il est non spécifié si les processus non privilégiés peuvent définir l'identifiant utilisateur réel à l'identifiant utilisateur réel, à l'identifiant utilisateur effectif, ou à l'identifiant utilisateur marqué. Pour setregid(), l'identifiant de groupe réel peut être modifié à la valeur de l'identifiant de groupe marqué, et l'identifiant de groupe effectif peut être modifié à la valeur de l'identifiant de groupe réel ou de l'identifiant de groupe marqué. Les détails précis des modifications d'ID autorisées varient selon les implémentations.

POSIX.1 ne fait aucune spécification sur l'effet de ces appels sur l'identifiant utilisateur marqué et l'identifiant de groupe marqué.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, 4.3BSD (est apparu pour la première fois dans 4.2BSD).

La définition de l'identifiant utilisateur (groupe) effectif à l'identifiant utilisateur (groupe) marqué est possible depuis Linux 1.1.37 (1.1.38).

Les appels système setreuid() et setregid() originaux de Linux ne supportaient que des identifiants utilisateur et de groupe de 16 bits. Par la suite, Linux 2.4 a ajouté setreuid32() et setregid32(), supportant les ID 32 bits. Les fonctions d'enrobage glibc setreuid() et setregid() gèrent de manière transparente les variations entre les versions du noyau.

Différences bibliothèque C/noyau

Au niveau du noyau, les identifiants utilisateur et de groupe sont un attribut par thread. Cependant, POSIX exige que tous les threads d'un processus partagent les mêmes informations d'identification. L'implémentation de threading NPTL gère les exigences POSIX en fournissant des fonctions d'enrobage pour les divers appels système qui modifient les UID et GID des processus. Ces fonctions d'enrobage (y compris celles pour setreuid() et setregid()) utilisent une technique basée sur les signaux pour s'assurer que lorsqu'un thread modifie ses informations d'identification, tous les autres threads du processus modifient également leurs informations d'identification. Pour plus de détails, voir nptl(7).

VOIR AUSSI

getgid(2), getuid(2), seteuid(2), setgid(2), setresuid(2), setuid(2), capabilities(7), credentials(7), user_namespaces(7)

setreuid, seteuid - Définir les identifiants réels, effectifs et sauvegardés d'utilisateur

SYNTAXE

#include <unistd.h>

int setreuid(int real, int effective);
int setresuid(uid_t ruid, uid_t euid, uid_t suid);
int setresuid32(uid_t ruid, uid_t euid, uid_t suid);

DESCRIPTION

La fonction setreuid permet de modifier les identifiants réels (real), effectifs (effective) et sauvegardés (saved) d'un processus. Les identifiants sont des nombres entiers représentant les utilisateurs sous lesquels un processus s'exécute.

L'identifiant réel correspond à l'utilisateur "qui" exécute le processus. L'identifiant effectif est celui utilisé pour les vérifications de privilèges. L'identifiant sauvegardé est une copie de l'identifiant effectif précédent, utilisé pour revenir aux privilèges précédents.

La fonction setreuid prend deux arguments :

  • real : le nouvel identifiant réel.
  • effective : le nouvel identifiant effectif.

Si un argument est égal à -1, la valeur correspondante n'est pas modifiée.

Un processus peut modifier ses identifiants selon les règles suivantes :

  • Si le processus n'est pas privilégié (UID effectif, réel et sauvegardé différents de 0), il peut modifier l'identifiant réel pour qu'il corresponde à l'identifiant réel, effectif ou sauvegardé actuel. Il peut modifier l'identifiant effectif pour qu'il corresponde à l'identifiant réel, effectif ou sauvegardé actuel. Il peut modifier l'identifiant sauvegardé pour qu'il corresponde à l'identifiant réel actuel.
  • Si le processus est privilégié (UID effectif égal à 0), il peut définir tous les identifiants (réel, effectif, sauvegardé) à n'importe quelle valeur.

La fonction setresuid est une extension GNU qui permet de définir explicitement les trois identifiants (réel, effectif, sauvegardé) séparément. Elle prend trois arguments :

  • ruid : le nouvel identifiant réel.
  • euid : le nouvel identifiant effectif.
  • suid : le nouvel identifiant sauvegardé.

Si un argument est égal à -1, la valeur correspondante n'est pas modifiée.

Un processus peut modifier ses identifiants selon les règles suivantes :

  • Si le processus n'est pas privilégié, il peut modifier l'identifiant réel pour qu'il corresponde à l'identifiant réel, effectif ou sauvegardé actuel. Il peut modifier l'identifiant effectif pour qu'il corresponde à l'identifiant réel, effectif ou sauvegardé actuel. Il peut modifier l'identifiant sauvegardé pour qu'il corresponde à l'identifiant réel actuel.
  • Si le processus est privilégié, il peut définir tous les identifiants à n'importe quelle valeur.

setresuid32 est une version 32 bits de setresuid qui est fournie pour la compatibilité. Sur les systèmes où les UID sont gérés comme des entiers 32 bits, setresuid est généralement un alias pour setresuid32.

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Les erreurs suivantes peuvent être renvoyées par setreuid et setresuid :

  • EINVAL : Une valeur d'identifiant spécifiée est invalide.
  • EPERM : Le processus n'est pas autorisé à effectuer l'opération demandée.

VERSIONS

setreuid est disponible depuis le noyau Linux 1.0.0.

setresuid est une extension GNU qui est disponible depuis le noyau Linux 2.1.17.

CONFORMITÉ

setreuid est conforme à POSIX.1-2001 et POSIX.1-2008.

setresuid n'est pas standard POSIX et est spécifique à Linux.

VOIR AUSSI

getuid(2), setuid(2), capabilities(7)
