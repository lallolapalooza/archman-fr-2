sensors.conf(5) Manuel de l'utilisateur Linux sensors.conf(5)

NOM

sensors.conf - Fichier de configuration de libsensors

DESCRIPTION

sensors.conf décrit comment libsensors, et donc tous les programmes qui l'utilisent, doivent traduire les lectures brutes des modules du noyau en valeurs du monde réel.

SEMANTIQUE

Sur un système donné, il peut y avoir une ou plusieurs puces de surveillance matérielle. Chaque puce peut avoir plusieurs fonctionnalités. Par exemple, le LM78 surveille 7 entrées de tension, 3 ventilateurs et une température. Les noms des fonctionnalités sont standardisés. Les noms typiques des fonctionnalités sont in0, in1, in2... pour les entrées de tension, fan1, fan2, fan3... pour les ventilateurs et temp1, temp2, temp3... pour les entrées de température.

Chaque fonctionnalité peut à son tour avoir une ou plusieurs sous-fonctionnalités, chacune représentant un attribut de la fonctionnalité : valeur d'entrée, limite inférieure, limite supérieure, alarme, etc. Les noms des sous-fonctionnalités sont également standardisés. Par exemple, la première entrée de tension (in0) aurait typiquement les sous-fonctionnalités in0_input (valeur mesurée), in0_min (limite inférieure), in0_max (limite supérieure) et in0_alarm (indicateur d'alarme). Les sous-fonctionnalités présentes dépendent du type exact de la puce.

Le fichier de configuration sensors.conf vous permettra de configurer chaque puce, fonctionnalité et sous-fonctionnalité d'une manière qui a du sens pour votre système.

Le reste de cette section décrit la signification de chaque instruction de configuration.

INSTRUCTION CHIP

Une instruction chip sélectionne pour quelles puces toutes les instructions compute, label, ignore et set suivantes sont destinées. Une sélection de puce reste valide jusqu'à la prochaine instruction chip. Exemple :

chip "lm78-*" "lm79-*"

Si une puce correspond à au moins une des descriptions de puce, les lignes de configuration suivantes sont examinées pour celle-ci, sinon elles sont ignorées.

Une description de puce est construite à partir de plusieurs éléments, séparés par des tirets. Le premier élément est le type de puce, le deuxième élément est le nom du bus, et le troisième élément est l'adresse hexadécimale de la puce. Ces descriptions de puces sont imprimées par sensors(1) comme première ligne pour chaque puce.

Le nom du bus est soit isa, pci, virtual, spi-*, i2c-N ou mdio, où N est un numéro de bus lié par une instruction bus. Cette liste n'est pas nécessairement exhaustive car la prise en charge d'autres types de bus peut être ajoutée à l'avenir.

Vous pouvez substituer l'opérateur générique * pour chaque élément. Notez cependant qu'il serait insensé de spécifier l'adresse sans le type de bus, donc la partie adresse est omise lorsqu'on ne spécifie pas le type de bus. Voici comment exprimer les correspondances suivantes :

Puce LM78 à l'adresse 0x2d sur le bus I2C 1 lm78-i2c-1-2d
Puce LM78 à l'adresse 0x2d sur n'importe quel bus I2C lm78-i2c-*-2d
Puce LM78 à l'adresse 0x290 sur le bus ISA lm78-isa-0290
N'importe quelle puce LM78 sur le bus I2C 1 lm78-i2c-1-*
N'importe quelle LM78 sur n'importe quel bus I2C lm78-i2c-*-*
N'importe quelle puce LM78 sur le bus ISA lm78-isa-*
N'importe quelle puce LM78 lm78-*
N'importe quelle puce à l'adresse 0x2d sur le bus I2C 1 *-i2c-1-2d
N'importe quelle puce à l'adresse 0x290 sur le bus ISA *-isa-0290

Si plusieurs instructions chip correspondent à une puce spécifique, elles sont toutes prises en compte.

INSTRUCTION LABEL

Une instruction label décrit comment une fonctionnalité doit être nommée. Les fonctionnalités sans instruction label sont simplement nommées par leur nom de fonctionnalité. Les applications peuvent utiliser ceci pour étiqueter les lectures qu'elles présentent. Exemple :

label in3 "+5V"

Le premier argument est le nom de la fonctionnalité. Le second argument est la description de la fonctionnalité.

Notez que vous devez utiliser le nom brut de la fonctionnalité, qui n'est pas nécessairement celui affiché par "sensors" par défaut. Utilisez "sensors -u" pour voir les noms bruts des fonctionnalités. Il en va de même pour tous les autres types d'instructions ci-dessous.

INSTRUCTION IGNORE

Une instruction ignore est un indice indiquant qu'une fonctionnalité spécifique doit être ignorée - probablement parce qu'elle retourne des valeurs erronées (par exemple, parce qu'un ventilateur ou un capteur de température n'est pas connecté). Exemple :

ignore fan1

Le seul argument est le nom de la fonctionnalité. Veuillez noter que cela ne désactive rien dans la puce de capteur réelle ; cela masque simplement la fonctionnalité en question pour les utilisateurs de libsensors.

INSTRUCTION COMPUTE

Une instruction compute décrit comment la valeur brute d'une fonctionnalité doit être traduite en une valeur du monde réel, et comment une valeur du monde réel doit être retraduite en une valeur brute. Ceci est très utile pour les capteurs de tension, car en général les puces de capteur ont une plage limitée et les tensions en dehors de cette plage doivent être divisées (à l'aide de résistances) avant de pouvoir être surveillées. Exemple :

compute in3 ((6.8/10)+1)*@, @/((6.8/10)+1)

L'exemple ci-dessus exprime le fait que l'entrée de tension est divisée à l'aide de deux résistances de valeurs respectives 6.8 Ohm et 10 Ohm. Voir la section DÉTAILS DU CALCUL DE TENSION ci-dessous pour plus de détails.

Le premier argument est le nom de la fonctionnalité. Le second argument est une expression qui spécifie comment une valeur brute doit être traduite en une valeur du monde réel ; '@' représente ici la valeur brute. C'est la formule qui sera appliquée lors de la lecture des valeurs de la puce. Le troisième argument est une expression qui spécifie comment une valeur du monde réel doit être retraduite en une valeur brute ; '@' représente ici la valeur du monde réel. C'est la formule qui sera appliquée lors de l'écriture des valeurs dans la puce. Les deux formules sont évidemment liées et sont séparées par une virgule.

Une instruction compute s'applique à toutes les sous-fonctionnalités de la fonctionnalité cible pour lesquelles cela a un sens. Par exemple, l'exemple ci-dessus affecterait les sous-fonctionnalités in3_min et in3_max (qui sont des valeurs de tension) mais pas in3_alarm (qui est un indicateur booléen).

Les opérateurs suivants sont pris en charge dans les instructions compute :

+ - * / ( ) ^ `
^x signifie exp(x) et `x signifie ln(x).

Vous pouvez utiliser le nom des sous-fonctionnalités dans ces expressions ; les lectures actuelles sont substituées. Soyez cependant prudent pour éviter les références circulaires.

Si, à tout moment, une traduction entre une valeur brute et une valeur du monde réel est demandée, mais qu'aucune instruction compute ne s'applique, une traduction un à un est utilisée à la place.

INSTRUCTION SET

Une instruction set est utilisée pour écrire une valeur de sous-fonctionnalité dans la puce. Bien sûr, toutes les valeurs de sous-fonctionnalité ne peuvent pas être définies de cette manière, en particulier les valeurs d'entrée et les indicateurs d'alarme ne le peuvent pas. Les sous-fonctionnalités valides sont généralement les limites min/max. Exemple :

set in3_min 5 * 0.95
set in3_max 5 * 1.05

L'exemple ci-dessus configure essentiellement la puce pour permettre un écart de 5% pour l'entrée d'alimentation +5V.

Le premier argument est le nom de la fonctionnalité. Le second argument est une expression qui détermine la valeur écrite. S'il existe une instruction compute applicable, cette valeur est transmise à son troisième argument pour la traduire en une valeur brute.

Vous pouvez utiliser le nom des sous-fonctionnalités dans ces expressions ; les lectures actuelles sont substituées. Soyez cependant prudent pour éviter les références circulaires.

Veuillez noter que les instructions set ne sont exécutées par sensors(1) que lorsque vous utilisez l'option -s. Les applications graphiques typiques de capteurs ne tiennent pas compte de ces instructions du tout.

INSTRUCTION BUS

Une instruction bus lie la description d'un adaptateur I2C ou SMBus à un numéro de bus. Cela permet de faire référence à un adaptateur dans le fichier de configuration, indépendamment de la correspondance réelle entre les numéros de bus et les adaptateurs physiques (qui peuvent changer de moment en moment). Exemple :

bus "i2c-0" "SMBus PIIX4 adapter at e800"

Le deuxième argument est le nom de l'adaptateur, il doit correspondre exactement au nom de l'adaptateur tel qu'il apparaît dans /sys/class/i2c-adapter/i2c-*/name. Il doit toujours être cité car il conviendra très certainement d'espaces ou de traits d'union.

Les instructions bus peuvent être dispersées aléatoirement dans le fichier de configuration ; il n'est pas nécessaire de placer la ligne de bus avant l'endroit où sa liaison est référencée. Néanmoins, par style, nous vous suggérons de placer toutes les instructions bus ensemble en haut de votre fichier de configuration.

L'exécution de sensors --bus-list générera ces lignes pour vous.

Dans le cas où plusieurs fichiers de configuration sont utilisés, la portée de chaque instruction bus est le fichier de configuration dans lequel elle a été définie. Cela rend possible d'avoir des instructions de bus dans tous les fichiers de configuration qui n'interféreront pas inopinément les unes avec les autres.

ORDRE DES INSTRUCTIONS

Les instructions peuvent être dans n'importe quel ordre, cependant il est recommandé de mettre les instructions `set fanX_div' avant les instructions `set fanX_min', au cas où un pilote ne conserverait pas le paramètre fanX_min lorsque la valeur fanX_div est modifiée. Même si le pilote le fait, il est toujours préférable de placer les instructions dans cet ordre pour éviter une perte de précision.

DETAILS DE COMPUTATION DE TENSION

La plupart des capteurs de tension dans les puces de capteurs ont une plage de 0 à 4,08 V. Ceci est généralement suffisant pour les tensions +3,3V et l'alimentation CPU, donc la lecture de la puce du capteur est la tension réelle.

Les autres tensions d'alimentation doivent être mises à l'échelle avec un réseau de résistances externe. Le pilote rapporte la valeur à la broche de la puce (0 - 4,08 V), et l'application userspace doit convertir cette valeur brute en une tension réelle. Les instructions compute fournissent cette facilité.

Malheureusement, les valeurs des résistances varient entre les types de cartes mères. Par conséquent, vous devez déterminer les valeurs de résistances correctes pour votre propre carte mère.

Pour les tensions positives (typiquement +5V et +12V), deux résistances sont utilisées, avec la formule suivante :
R1 = R2 * (Vs/Vin - 1)

où :
R1 et R2 sont les valeurs des résistances
Vs est la tension réelle surveillée
Vin est la tension à la broche

Cela conduit à la formule de calcul suivante :
compute inX @*((R1/R2)+1), @/(((R1/R2)+1)

Les formules réelles pour +5V et +12V ressembleraient à :
compute in3 @*((6.8/10)+1), @/((6.8/10)+1)
compute in4 @*((28/10)+1), @/((28/10)+1)

Pour les tensions négatives (typiquement -5V et -12V), deux résistances sont également utilisées, mais différentes cartes utilisent différentes stratégies pour amener la valeur de tension dans la plage de 0 à 4,08 V. Certaines utilisent un amplificateur inverseur, d'autres utilisent une tension de référence positive. Cela conduit à différentes formules de calcul. Notez que la plupart des utilisateurs n'auront pas à s'en soucier car la plupart des cartes mères modernes utilisent peu les tensions -12V et pas du tout les tensions -5V, elles ne prennent donc pas la peine de surveiller ces entrées de tension.

Exemples réels pour le cas de l'amplificateur inverseur :
compute in5 -@*(240/60), -@/(240/60)
compute in6 -@*(100/60), -@/(100/60)

Exemples réels pour le cas de la tension de référence positive :
compute in5 @*(1+232/56) - 4.096*232/56, (@ + 4.096*232/56)/(1+232/56)
compute in6 @*(1+120/56) - 4.096*120/56, (@ + 4.096*120/56)/(1+120/56)

De nombreuses puces de surveillance récentes ont une plage de 0 à 2,04 V, les résistances de mise à l'échelle sont donc encore plus nécessaires, et les valeurs des résistances sont différentes.

Il existe également quelques puces qui ont des résistances de mise à l'échelle internes, ce qui signifie que leur valeur est connue et ne change pas d'une carte mère à l'autre. Pour ces puces, le pilote gère généralement la mise à l'échelle de manière transparente pour l'utilisateur et aucune instruction compute n'est nécessaire.

CONFIGURATION THERMIQUE

En plus des fonctionnalités habituelles, les températures peuvent avoir deux sous-fonctionnalités spécifiques : le type de capteur de température (tempX_type) et les valeurs d'hystérésis (tempX_max_hyst, tempX_crit_hyst etc.).

TYPES DE CAPTEURS THERMIQUES

Types de capteurs thermiques disponibles :

1 Diode PII/Celeron
2 Transistor 3904
3 Diode thermique
4 Thermistance
5 AMD AMDSI
6 PECI Intel

Par exemple, pour définir temp1 sur le type thermistance, utilisez :

set temp1_type 4

Seules certaines puces prennent en charge la modification du type de capteur thermique, et même celles-ci ne prennent généralement en charge que certains des types ci-dessus. Veuillez vous référer à la documentation du pilote spécifique pour savoir quels types sont pris en charge par votre puce.

En théorie, le BIOS devrait avoir configuré correctement les types de capteurs, vous ne devriez donc pas avoir à y toucher, mais ce n'est parfois pas le cas.

MECANISME DHYSTERESIS THERMIQUE

De nombreuses puces de surveillance ne gèrent pas les limites de température haute et critique comme de simples limites. Au lieu de cela, elles ont deux valeurs pour chaque limite, une qui déclenche une alarme lorsque la température augmente et une autre qui efface l'alarme lorsque la température diminue. Cette dernière est généralement quelques degrés en dessous de la première. Ce mécanisme est connu sous le nom d'hystérésis.

La raison de la mise en œuvre de cette manière est que les alarmes de haute température déclenchent généralement une action pour tenter de refroidir le système, soit en réduisant la fréquence du processeur, soit en activant un ventilateur supplémentaire. Cela devrait normalement permettre à la température de baisser rapidement. Si cela effaçait l'alarme immédiatement, le système reviendrait à son état d'origine où la température augmente et l'alarme se déclencherait immédiatement à nouveau, provoquant une boucle indésirable de mise en marche et arrêt du ventilateur. Le mécanisme d'hystérésis garantit que le système est vraiment refroidi avant que le ventilateur ne s'arrête, de sorte qu'il n'aura pas à se réactiver immédiatement.

Ainsi, en plus de tempX_max, de nombreuses puces ont une sous-fonctionnalité tempX_max_hyst. De même, tempX_crit est souvent accompagné de tempX_crit_hyst. tempX_emerg_hyst, tempX_min_hyst et tempX_lcrit_hyst existent aussi mais ne sont pas aussi courants. Exemple :

set temp1_max 60
set temp1_max_hyst 56

Le mécanisme d'hystérésis peut être désactivé en donnant la même valeur aux deux limites.

Notez qu'il est fortement recommandé de définir la valeur d'hystérésis après la valeur limite à laquelle elle se rapporte dans le fichier de configuration. Des détails d'implémentation sur le matériel ou le pilote peuvent entraîner des résultats inattendus si la valeur d'hystérésis est définie en premier.

BIPS

Certaines puces prennent en charge les alarmes avec des avertissements sonores. Lorsqu'une alarme est déclenchée, vous pouvez être averti par un signal sonore via le haut-parleur de votre ordinateur. En plus des indicateurs sonores par fonctionnalité, il existe généralement un interrupteur de commande sonore maître pour activer ou désactiver les bips globalement. Activez les bips en utilisant :

set beep_enable 1

ou désactivez-les en utilisant :

set beep_enable 0

QUELLE INSTRUCTION SA APPLIQUE

Si plus d'une instruction du même type s'applique à un moment donné, la dernière dans le fichier de configuration est utilisée. Ainsi, généralement, vous devriez placer les instructions chip plus générales en haut, afin de pouvoir les remplacer en dessous.

SYNTAXE

Les commentaires sont introduits par des dièses. Un commentaire se poursuit jusqu'à la fin de la ligne. Les lignes vides, et les lignes ne contenant que des espaces ou des commentaires sont ignorées. Les autres lignes ont l'une des formes ci-dessous. Il doit y avoir un espace entre chaque élément, mais la quantité d'espace n'a pas d'importance. Une ligne peut être continuée sur la ligne suivante en la terminant par une barre oblique inverse ; cela ne fonctionne pas dans un commentaire, un NAME ou un NUMBER.

bus NAME NAME

chip NAME-LIST

label NAME NAME

compute NAME EXPR , EXPR

ignore NAME

set NAME EXPR

Un NAME est une chaîne de caractères. S'il ne contient que des lettres, des chiffres et des tirets bas, il n'a pas besoin d'être cité ; dans tous les autres cas, vous devez le mettre entre guillemets doubles. À l'intérieur des guillemets, vous pouvez utiliser les codes d'échappement normaux de C.

Une NAME-LIST est un ou plusieurs éléments NAME les uns derrière les autres, séparés par des espaces.

Un EXPR est de l'une des formes ci-dessous :

NUMBER

NAME

@

EXPR + EXPR

EXPR - EXPR

EXPR * EXPR

EXPR / EXPR

- EXPR

^ EXPR

` EXPR

( EXPR )

Un NUMBER est un nombre à virgule flottante. `10', `10.4' et `.4' sont des exemples de nombres à virgule flottante valides ; `10.' ou `10E4' ne sont pas valides.

FICHIERS

/etc/sensors3.conf
/etc/sensors.conf

Le fichier de configuration global libsensors(3). /etc/sensors3.conf est essayé en premier, et s'il n'existe pas, /etc/sensors.conf est utilisé à la place.

/etc/sensors.d

Un répertoire où vous pouvez placer des fichiers de configuration libsensors supplémentaires. Les fichiers trouvés dans ce répertoire seront traités par ordre alphabétique après le fichier de configuration par défaut. Les fichiers dont le nom commence par un point sont ignorés.
