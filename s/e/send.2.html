send(2) Manuel des appels système send(2)

NOM

send, sendto, sendmsg - envoyer un message sur une socket

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/socket.h>
ssize_t send(int sockfd, const void *buf, size_t size, int flags);
ssize_t sendto(int sockfd, const void *buf, size_t size, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);
ssize_t sendmsg(int sockfd, const struct msghdr *msg, int flags);

DESCRIPTION

Les appels système send(), sendto(), et sendmsg() sont utilisés pour transmettre un message à une autre socket.

La fonction send() peut être utilisée uniquement lorsque la socket est dans un état connecté (de sorte que le destinataire prévu soit connu). La seule différence entre send() et write(2) est la présence des flags. Avec un argument flags à zéro, send() est équivalent à write(2). De plus, l'appel suivant


send(sockfd, buf, size, flags);

est équivalent à


sendto(sockfd, buf, size, flags, NULL, 0);

L'argument sockfd est le descripteur de fichier de la socket d'envoi.

Si sendto() est utilisé sur une socket de mode connexion (SOCK_STREAM, SOCK_SEQPACKET), les arguments dest_addr et addrlen sont ignorés (et l'erreur EISCONN peut être retournée lorsqu'ils ne sont pas NULL et 0), et l'erreur ENOTCONN est retournée lorsque la socket n'était pas réellement connectée. Sinon, l'adresse de la cible est donnée par dest_addr avec addrlen spécifiant sa taille. Pour sendmsg(), l'adresse de la cible est donnée par msg.msg_name, avec msg.msg_namelen spécifiant sa taille.

Pour send() et sendto(), le message se trouve dans buf et a une taille de size. Pour sendmsg(), le message est pointé par les éléments du tableau msg.msg_iov. L'appel sendmsg() permet également d'envoyer des données auxiliaires (également appelées informations de contrôle).

Si le message est trop long pour être transmis de manière atomique par le protocole sous-jacent, l'erreur EMSGSIZE est retournée et le message n'est pas transmis.

Aucune indication d'échec de livraison n'est implicite dans un send(). Les erreurs détectées localement sont indiquées par une valeur de retour de -1.

Lorsque le message ne rentre pas dans le tampon d'envoi de la socket, send() se bloque normalement, sauf si la socket a été placée en mode d'E/S non bloquant. En mode non bloquant, il échouerait avec l'erreur EAGAIN ou EWOULDBLOCK dans ce cas. L'appel select(2) peut être utilisé pour déterminer quand il est possible d'envoyer plus de données.

L'argument flags

L'argument flags est le OU bit à bit de zéro ou plusieurs des drapeaux suivants.

MSG_CONFIRM (depuis Linux 2.3.15)
Indique à la couche de liaison que des progrès ont été réalisés : vous avez reçu une réponse réussie de l'autre côté. Si la couche de liaison ne reçoit pas cela, elle sondera régulièrement le voisin (par exemple, via une ARP unicast). Valide uniquement sur les sockets SOCK_DGRAM et SOCK_RAW et actuellement implémenté uniquement pour IPv4 et IPv6. Voir arp(7) pour plus de détails.
MSG_DONTROUTE
Ne pas utiliser de passerelle pour envoyer le paquet, envoyer uniquement aux hôtes sur des réseaux directement connectés. Ceci est généralement utilisé uniquement par les programmes de diagnostic ou de routage. Ceci n'est défini que pour les familles de protocoles qui routent ; les sockets de paquets ne le font pas.
MSG_DONTWAIT (depuis Linux 2.2)
Active le fonctionnement non bloquant ; si l'opération bloquerait, EAGAIN ou EWOULDBLOCK est retourné. Ceci fournit un comportement similaire à la définition du drapeau O_NONBLOCK (via l'opération F_SETFL de fcntl(2)), mais diffère en ce que MSG_DONTWAIT est une option par appel, tandis que O_NONBLOCK est un réglage sur la description de fichier ouverte (voir open(2)), ce qui affectera tous les threads du processus appelant ainsi que d'autres processus qui détiennent des descripteurs de fichiers faisant référence à la même description de fichier ouverte.
MSG_EOR (depuis Linux 2.2)
Termine un enregistrement (lorsque cette notion est prise en charge, comme pour les sockets de type SOCK_SEQPACKET).
MSG_MORE (depuis Linux 2.4.4)
L'appelant a plus de données à envoyer. Ce drapeau est utilisé avec les sockets TCP pour obtenir le même effet que l'option de socket TCP_CORK (voir tcp(7)), avec la différence que ce drapeau peut être défini sur une base par appel.
Depuis Linux 2.6, ce drapeau est également pris en charge pour les sockets UDP, et informe le noyau de regrouper toutes les données envoyées avec ce drapeau défini en un seul datagramme qui n'est transmis que lorsqu'un appel est effectué qui ne spécifie pas ce drapeau. (Voir aussi l'option de socket UDP_CORK décrite dans udp(7).)
MSG_NOSIGNAL (depuis Linux 2.2)
Ne pas générer de signal SIGPIPE si le pair sur une socket orientée flux a fermé la connexion. L'erreur EPIPE est toujours retournée. Ceci fournit un comportement similaire à l'utilisation de sigaction(2) pour ignorer SIGPIPE, mais alors que MSG_NOSIGNAL est une fonctionnalité par appel, l'ignorance de SIGPIPE définit un attribut de processus qui affecte tous les threads du processus.
MSG_OOB
Envoie des données hors bande sur les sockets qui le supportent (par exemple, de type SOCK_STREAM) ; le protocole sous-jacent doit également prendre en charge les données hors bande.
MSG_FASTOPEN (depuis Linux 3.7)
Tente TCP Fast Open (RFC7413) et envoie des données dans le SYN comme une combinaison de connect(2) et write(2), en effectuant une opération implicite de connect(2). Elle se bloque jusqu'à ce que les données soient mises en tampon et que la négociation soit terminée. Pour une socket non bloquante, elle retourne le nombre d'octets mis en tampon et envoyés dans le paquet SYN. Si le cookie n'est pas disponible localement, elle retourne EINPROGRESS et envoie automatiquement un SYN avec une demande de cookie Fast Open. L'appelant doit réécrire les données lorsque la socket est connectée. En cas d'erreur, elle définit le même errno que connect(2) si la négociation échoue. Ce drapeau nécessite l'activation du support client TCP Fast Open via le sysctl net.ipv4.tcp_fastopen.
Se référer à l'option de socket TCP_FASTOPEN_CONNECT dans tcp(7) pour une approche alternative.

send(2) — man.archlinux.org

NAME

send, sendto, sendmsg - send a message from a socket

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <sys/socket.h>

ssize_t send(int sockfd, const void *buf, size_t len, int flags);

ssize_t sendto(int sockfd, const void *buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen);

ssize_t sendmsg(int sockfd, const struct msghdr *msg, int flags);

DESCRIPTION

The socket interface allows processes to send and receive data across a network. The send(), sendto(), and sendmsg() calls are used to send data.

The socket referred to by sockfd must be of a socket type that supports the operation, and it must be connected if the socket type requires connection (e.g., SOCK_STREAM). If the socket is not connected, the default destination address must be specified or supplied.

send()

send() sends data from the buffer pointed to by buf with len bytes of data. If the socket is connection mode, the data is sent to the address specified by the connection.

If the socket is connectionless mode, the default destination address must have been specified previously using connect(2). In this case, send() is equivalent to sendto() with a NULL dest_addr and 0 addrlen.

sendto()

sendto() is used for connectionless sockets. It sends data from the buffer pointed to by buf with len bytes of data to the destination address pointed to by dest_addr. The addrlen argument specifies the length of the destination address structure.

If the socket is connection mode (e.g. SOCK_STREAM), the dest_addr and addrlen parameters should be NULL and 0, respectively. In this case, the data is sent to the address specified by the connection. (If a destination address is specified for a connected stream socket, the behavior is protocol-dependent, but usually an error like EISCONN is returned.)

For connectionless sockets (e.g. SOCK_DGRAM), if the socket has not been connected previously using connect(2), the data is sent to the specified destination address. If the socket has already been connected, then dest_addr and addrlen must be NULL and 0, respectively, and sendto() behaves like send().

sendmsg()

sendmsg() is a more general interface that can be used to send data, ancillary data (control information), and with multiple buffers (scatter/gather).

The msg parameter is a pointer to a msghdr structure, which is defined as follows:

struct msghdr {
    void         *msg_name;       /* Optional address to send to */
    socklen_t     msg_namelen;    /* Size of address to send to */
    struct iovec *msg_iov;        /* Scatter/gather list */
    size_t        msg_iovlen;     /* Number of scatter/gather items */
    void         *msg_control;    /* Ancillary data */
    size_t        msg_controllen; /* Ancillary data buffer len */
    int           msg_flags;      /* Flags */
};

The msghdr structure is used to specify the destination address (msg_name and msg_namelen), the data buffers (msg_iov and msg_iovlen), and ancillary data (msg_control and msg_controllen).

If the socket is connected, the msg_name and msg_namelen fields should be specified as NULL and 0, respectively. For a connectionless socket, these fields specify the destination address. The size of the address specified in msg_namelen should match the size of the address structure pointed to by msg_name.

The msg_iov and msg_iovlen fields specify scatter-gather locations, as for writev(2).

You may send control information (ancillary data) using the msg_control and msg_controllen members. The maximum control buffer size the kernel can process is limited per socket by the value in /proc/sys/net/core/optmem_max; see socket(7). For further information on the use of ancillary data in various socket domains, see unix(7) and ip(7).

The msg_flags field is ignored.

RETURN VALUE

On success, these calls return the number of bytes sent. On error, -1 is returned, and errno is set to indicate the error.

ERRORS

These are some standard errors generated by the socket layer. Additional errors may be generated and returned from the underlying protocol modules; see their respective manual pages.

EACCES
(For UNIX domain sockets, which are identified by pathname) Write permission is denied on the destination socket file, or search permission is denied for one of the directories the path prefix. (See path_resolution(7).)
(For UDP sockets) An attempt was made to send to a network/broadcast address as though it was a unicast address.
EAGAIN or EWOULDBLOCK
The socket is marked nonblocking and the requested operation would block. POSIX.1-2001 allows either error to be returned for this case, and does not require these constants to have the same value, so a portable application should check for both possibilities.
EAGAIN
(Internet domain datagram sockets) The socket referred to by sockfd had not previously been bound to an address and, upon attempting to bind it to an ephemeral port, it was determined that all port numbers in the ephemeral port range are currently in use. See the discussion of /proc/sys/net/ipv4/ip_local_port_range in ip(7).
EALREADY
Another Fast Open is in progress.
EBADF
sockfd is not a valid open file descriptor.
ECONNRESET
Connection reset by peer.
EDESTADDRREQ
The socket is not connection-mode, and no peer address is set.
EFAULT
An invalid user space address was specified for an argument.
EINTR
A signal occurred before any data was transmitted; see signal(7).
EINVAL
Invalid argument passed.
EISCONN
The connection-mode socket was connected already but a recipient was specified. (Now either this error is returned, or the recipient specification is ignored.)
EMSGSIZE
The socket type requires that message be sent atomically, and the size of the message to be sent made this impossible.
ENOBUFS
The output queue for a network interface was full. This generally indicates that the interface has stopped sending, but may be caused by transient congestion. (Normally, this does not occur in Linux. Packets are just silently dropped when a device queue overflows.)
ENOMEM
No memory available.
ENOTCONN
The socket is not connected, and no target has been given.
ENOTSOCK
The file descriptor sockfd does not refer to a socket.
EOPNOTSUPP
Some bit in the flags argument is inappropriate for the socket type.
EPIPE
The local end has been shut down on a connection oriented socket. In this case, the process will also receive a SIGPIPE unless MSG_NOSIGNAL is set.

VERSIONS

According to POSIX.1-2001, the msg_controllen field of the msghdr structure should be typed as socklen_t, and the msg_iovlen field should be typed as int, but glibc currently types both as size_t.

STANDARDS

POSIX.1-2024.

MSG_CONFIRM is a Linux extension.

HISTORY

4.4BSD, SVr4, POSIX.1-2001. (first appeared in 4.2BSD).

POSIX.1-2001 describes only the MSG_OOB and MSG_EOR flags. POSIX.1-2008 adds a specification of MSG_NOSIGNAL.

NOTES

See sendmmsg(2) for information about a Linux-specific system call that can be used to transmit multiple datagrams in a single call.

BUGS

Linux may return EPIPE instead of ENOTCONN.

EXAMPLES

An example of the use of sendto() is shown in getaddrinfo(3).
