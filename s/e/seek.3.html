Description détaillée

Une interface i/o abstraite.

Attention

C'est du matériel avancé, du gros calibre. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un accès au système de fichiers physique et aux archives dans ce système de fichiers. Cependant, parfois vous avez besoin de plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue dans la RAM, ou vous devez faire le pont avec une autre API d'i/o de fichiers à PhysicsFS, ou vous avez besoin de traduire les bits (peut-être avez-vous un fichier .zip standard qui est crypté, et vous devez le décrypter à la volée pour l'archiveur zip insoupçonneux).

Un PHYSFS_Io est l'interface que les Archiveurs utilisent pour obtenir des données d'archive. Historiquement, cela correspondait aux i/o de fichiers vers le système de fichiers physique, mais depuis PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations i/o au moment de l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour les i/o. Il y a quelques exigences notables :

  • Ils ne font que des i/o bloquants (du moins, pour l'instant).
  • Ils doivent être capables de se dupliquer. Si vous avez un descripteur de fichier de fopen(), vous devez pouvoir en créer un clone unique (afin d'avoir deux descripteurs pour le même fichier qui peuvent tous deux chercher/lire/etc. sans se gêner).
  • Ils doivent connaître la taille de leur ensemble de données complet.
  • Ils doivent être capables de chercher et de rembobiner à la demande.

...en bref, vous n'allez probablement pas écrire une implémentation HTTP.

Sécurité des threads : les implémentations PHYSFS_Io ne sont pas garanties d'être sûres pour les threads en elles-mêmes. Sous le capot, là où PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement à partir de threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io à partir de deux threads en même temps.

Documentation des champs

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance i/o. Libérer les ressources associées, y compris (opaque) le cas échéant.

Cette fonction doit toujours réussir : en tant que telle, elle retourne void. Le système peut appeler votre méthode flush() avant cela. Vous pouvez signaler un échec là-bas si nécessaire. Cette méthode peut encore être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et d'autres conditions d'échec et nettoyer.

Une fois que cette méthode est appelée pour une instance donnée, le système supposera qu'il est dangereux de toucher à nouveau cette instance et discardera toutes les références à celle-ci.

Paramètres

s L'instance i/o à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance i/o. Cela doit aboutir à une copie complète de ce PHYSFS_Io, qui peut vivre complètement indépendamment. La copie doit pouvoir effectuer toutes ses opérations sans altérer l'original, y compris la destruction de chaque objet séparément (donc, par exemple : ils ne peuvent pas partager un descripteur de fichier ; chacun a besoin du sien).

Si vous ne pouvez pas dupliquer un descripteur, il est légal de retourner NULL, mais vous aurez presque certainement besoin de cette fonctionnalité si vous voulez utiliser ce PHYSFS_Io pour supporter une archive.

Paramètres

io L'instance i/o à dupliquer.

Retours

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources vers le support, ou là où. C'est l'occasion de signaler un échec pour des écritures qui avaient prétendu réussir plus tôt, mais qui avaient encore une chance d'échouer réellement. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut également être appelée à d'autres moments.

Paramètres

io L'instance i/o à vider.

Retours

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance i/o. Retourner le nombre d'octets disponibles dans le fichier, ou -1 si vous ne pouvez pas le déterminer. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas le laisser non implémenté.

Paramètres

io L'instance i/o à interroger.

Retours

Taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qui peut être utilisé pour stocker tout ce qu'elle souhaite. Ce pointeur est par instance de flux, donc il changera probablement lors de l'appel de duplicate(). Il peut être désalloué pendant la méthode destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets de l'interface, à la position i/o actuelle, et les stocker dans (buffer). La position i/o actuelle doit avancer du nombre d'octets lus avec succès.

Vous n'avez pas à implémenter cela ; définissez-le sur NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture. S'il est défini sur NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance i/o à lire.
buf Le tampon pour stocker les données. Il doit avoir au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire de l'interface.

Retours

nombre d'octets lus depuis le fichier, 0 en fin de fichier, -1 en cas d'échec complet.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Déplacer la position i/o à un décalage d'octets donné par rapport au début. Cette méthode déplace la position i/o, donc la prochaine lecture/écriture se fera à l'octet à la position (offset). Les recherches au-delà de la fin du fichier devraient be treated as an error condition.

Paramètres

io L'instance d'E/S à rechercher.
offset Le nouvel emplacement en octets pour la position d'E/S.

Retourne

non nul en cas de succès, zéro en cas d'erreur.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Rapport de la position actuelle d'E/S. Retourne le décalage en octets, ou -1 si vous ne parvenez pas à le déterminer. Un échec sera presque certainement fatal à l'utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cette fonction non implémentée.

Paramètres

io L'instance d'E/S à interroger.

Retourne

La position actuelle en octets pour la position d'E/S, -1 si inconnue.

PHYSFS_uint32 PHYSFS_Io::version

Informations de compatibilité binaire. Ceci doit être défini à zéro pour l'instant. Les futures versions de cette structure incrémenteront ce champ, nous saurons ainsi ce qu'une implémentation donnée prend en charge. Nous continuerons probablement à prendre en charge les versions antérieures à mesure que nous proposerons de nouvelles fonctionnalités, cependant.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrit (len) octets depuis (buffer) vers l'interface à la position d'E/S actuelle. La position d'E/S actuelle doit avancer du nombre d'octets écrits avec succès.

Vous n'êtes pas obligé d'implémenter ceci; définissez-le à NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. Si défini à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Vous êtes autorisé à mettre en mémoire tampon; une écriture peut réussir ici et échouer plus tard lors de la vidange. Notez que PHYSFS_setBuffer() peut fonctionner à un niveau supérieur à vos E/S, vous ne devriez donc généralement pas implémenter vos propres routines de mise en mémoire tampon.

Paramètres

io L'instance d'E/S sur laquelle écrire.
buffer Le tampon à partir duquel lire les données. Il doit avoir au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire depuis (buffer).

Retourne

nombre d'octets écrits dans le fichier, -1 en cas d'échec complet.
