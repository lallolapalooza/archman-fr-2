NOM

seccomp_arch_add, seccomp_arch_remove, seccomp_arch_exist, seccomp_arch_native - Gérer les architectures de filtres seccomp

SYNOPSIS

#include <seccomp.h>

typedef void * scmp_filter_ctx;

#define SCMP_ARCH_NATIVE
#define SCMP_ARCH_X86
#define SCMP_ARCH_X86_64
#define SCMP_ARCH_X32
#define SCMP_ARCH_ARM
#define SCMP_ARCH_AARCH64
#define SCMP_ARCH_MIPS
#define SCMP_ARCH_MIPS64
#define SCMP_ARCH_MIPS64N32
#define SCMP_ARCH_MIPSEL
#define SCMP_ARCH_MIPSEL64
#define SCMP_ARCH_MIPSEL64N32
#define SCMP_ARCH_PPC
#define SCMP_ARCH_PPC64
#define SCMP_ARCH_PPC64LE
#define SCMP_ARCH_S390
#define SCMP_ARCH_S390X
#define SCMP_ARCH_PARISC
#define SCMP_ARCH_PARISC64
#define SCMP_ARCH_RISCV64

uint32_t seccomp_arch_resolve_name(const char *nom_arch);
uint32_t seccomp_arch_native();
int seccomp_arch_exist(const scmp_filter_ctx ctx, uint32_t token_arch);
int seccomp_arch_add(scmp_filter_ctx ctx, uint32_t token_arch);
int seccomp_arch_remove(scmp_filter_ctx ctx, uint32_t token_arch);

Liez avec -lseccomp.

DESCRIPTION

La fonction seccomp_arch_exist() teste si une architecture donnée a été ajoutée au filtre seccomp dans ctx, où seccomp_arch_add() et seccomp_arch_remove() ajoutent et suppriment respectivement des architectures du filtre seccomp. Dans les trois fonctions, les valeurs d'architecture données dans token_arch doivent être les constantes définies SCMP_ARCH_* ; la constante SCMP_ARCH_NATIVE faisant toujours référence à l'architecture compilée native. La fonction seccomp_arch_native() retourne l'architecture du système de sorte qu'elle corresponde à l'une des constantes SCMP_ARCH_*. Alors que la fonction seccomp_arch_resolve_name() retourne également une constante SCMP_ARCH_*, le jeton retourné correspond au nom de l'architecture passée en argument à la fonction.

Lorsqu'un filtre seccomp est initialisé avec l'appel à seccomp_init(3), l'architecture native est automatiquement ajoutée au filtre.

Bien qu'il soit possible de supprimer toutes les architectures d'un filtre, la plupart des API libseccomp échoueront si le filtre ne contient pas au moins une architecture.

Lors de l'ajout d'une nouvelle architecture à un filtre existant, les règles existantes ne seront pas ajoutées à la nouvelle architecture. Cependant, les règles ajoutées après l'ajout de la nouvelle architecture seront ajoutées à toutes les architectures du filtre.

VALEUR DE RETOUR

Les fonctions seccomp_arch_add(), seccomp_arch_remove() et seccomp_arch_exist() retournent zéro en cas de succès ou l'un des codes d'erreur suivants en cas d'échec :

-EDOM
Échec spécifique à l'architecture.
-EEXIST
Dans le cas de seccomp_arch_add(), l'architecture existe déjà et dans le cas de seccomp_arch_remove(), l'architecture n'existe pas.
-EINVAL
Entrée invalide, le contexte ou le jeton d'architecture est invalide.
-ENOMEM
La bibliothèque n'a pas pu allouer suffisamment de mémoire.

EXEMPLES

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	if (seccomp_arch_exist(ctx, SCMP_ARCH_X86) == -EEXIST) {
		rc = seccomp_arch_add(ctx, SCMP_ARCH_X86);
		if (rc != 0)
			goto out_all;
		rc = seccomp_arch_remove(ctx, SCMP_ARCH_NATIVE);
		if (rc != 0)
			goto out_all;
	}
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTES

Bien que le filtre seccomp puisse être généré indépendamment du noyau, un support du noyau est nécessaire pour charger et appliquer le filtre seccomp généré par libseccomp.

Le site du projet libseccomp, avec plus d'informations et le dépôt de code source, peut être trouvé sur https://github.com/seccomp/libseccomp. Cet outil, ainsi que la bibliothèque libseccomp, est actuellement en développement, veuillez signaler tout bug sur le site du projet ou directement à l'auteur.
