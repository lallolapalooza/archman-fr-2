NAME

sed — stream editor

SYNOPSIS

sed [-n] script [file...]
sed [-n] -e script [-e script]... [-f script_file]... [file...]
sed [-n] [-e script]... -f script_file [-f script_file]... [file...]

DESCRIPTION

The sed utility is a stream editor that shall read one or more text files, make editing changes according to a script of editing commands, and write the results to standard output. The script shall be obtained from either the script operand string or a combination of the option-arguments from the -e script and -f script_file options.

OPTIONS

The sed utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines, except that the order of presentation of the -e and -f options is significant.

The following options shall be supported:

-e script
Add the editing commands specified by the script option-argument to the end of the script of editing commands.
-f script_file
Add the editing commands in the file script_file to the end of the script of editing commands.
-n
Suppress the default output (in which each line, after it is examined for editing, is written to standard output). Only lines explicitly selected for output are written.

If any -e or -f options are specified, the script of editing commands shall initially be empty. The commands specified by each -e or -f option shall be added to the script in the order specified. When each addition is made, if the previous addition (if any) was from a -e option, a <newline> shall be inserted before the new addition. The resulting script shall have the same properties as the script operand, described in the OPERANDS section.

OPERANDS

The following operands shall be supported:

file
A pathname of a file whose contents are read and edited. If multiple file operands are specified, the named files shall be read in the order specified and the concatenation shall be edited. If no file operands are specified, the standard input shall be used.
script
A string to be used as the script of editing commands. The application shall not present a script that violates the restrictions of a text file except that the final character need not be a <newline>.

STDIN

The standard input shall be used if no file operands are specified, and shall be used if a file operand is '-' and the implementation treats the '-' as meaning standard input. Otherwise, the standard input shall not be used. See the INPUT FILES section.

INPUT FILES

The input files shall be text files. The script_files named by the -f option shall consist of editing commands.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of sed:

LANG
Provide a default value for the internationalization variables that are unset or null. (See the Base Definitions volume of POSIX.1‐2017, Section 8.2, Internationalization Variables for the precedence of internationalization variables used to determine the values of locale categories.)
LC_ALL
If set to a non-empty string value, override the values of all the other internationalization variables.
LC_COLLATE

Determine the locale for the behavior of ranges, equivalence classes, and multi-character collating elements within regular expressions.
LC_CTYPE
Determine the locale for the interpretation of sequences of bytes of text data as characters (for example, single-byte as opposed to multi-byte characters in arguments and input files), and the behavior of character classes within regular expressions.
LC_MESSAGES

Determine the locale that should be used to affect the format and contents of diagnostic messages written to standard error.
NLSPATH
Determine the location of message catalogs for the processing of LC_MESSAGES.

ASYNCHRONOUS EVENTS

Default.

STDOUT

The input files shall be written to standard output, with the editing commands specified in the script applied. If the -n option is specified, only those input lines selected by the script shall be written to standard output.

STDERR

The standard error shall be used only for diagnostic and warning messages.

OUTPUT FILES

The output files shall be text files whose formats are dependent on the editing commands given.

EXTENDED DESCRIPTION

The script shall consist of editing commands of the following form:

[address[,address]]function

where function represents a single-character command verb from the list in Editing Commands in sed, followed by any applicable arguments.

The command can be preceded by <blank> characters and/or <semicolon> characters. The function can be preceded by <blank> characters. These optional characters shall have no effect.

In default operation, sed cyclically shall append a line of input, less its terminating <newline> character, into the pattern space. Reading from input shall be skipped if a <newline> was in the pattern space prior to a D command ending the previous cycle. The sed utility shall then apply in sequence all commands whose addresses select that pattern space, until a command starts the next cycle or quits. If no commands explicitly started a new cycle, then at the end of the script the pattern space shall be copied to standard output (except when -n is specified) and the pattern space shall be deleted. Whenever the pattern space is written to standard output or a named file, sed shall immediately follow it with a <newline>.

Some of the editing commands use a hold space to save all or part of the pattern space for subsequent retrieval. The pattern and hold spaces shall each be able to hold at least 8192 bytes.

NOM

sed — éditeur de flux

SYNOPIS

sed [-n] script [fichier...]
sed [-n] -e script [-e script]... [-f fichier_script]... [fichier...]
sed [-n] [-e script]... -f fichier_script [-f fichier_script]... [fichier...]

DESCRIPTION

L'utilitaire sed est un éditeur de flux qui doit lire un ou plusieurs fichiers texte, effectuer des modifications d'édition selon un script de commandes d'édition, et écrire les résultats sur la sortie standard. Le script doit être obtenu soit à partir de la chaîne d'opérande script, soit d'une combinaison des arguments d'option -e script et -f fichier_script.

OPTIONS

L'utilitaire sed doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, sauf que l'ordre de présentation des options -e et -f est significatif.

Les options suivantes doivent être prises en charge :

-e script
Ajoute les commandes d'édition spécifiées par l'argument d'option script à la fin du script de commandes d'édition.
-f fichier_script
Ajoute les commandes d'édition du fichier fichier_script à la fin du script de commandes d'édition.
-n
Supprime la sortie par défaut (dans laquelle chaque ligne, après avoir été examinée pour l'édition, est écrite sur la sortie standard). Seules les lignes explicitement sélectionnées pour la sortie sont écrites.

Si des options -e ou -f sont spécifiées, le script de commandes d'édition sera initialement vide. Les commandes spécifiées par chaque option -e ou -f seront ajoutées au script dans l'ordre spécifié. Lors de chaque ajout, si l'ajout précédent (le cas échéant) provenait d'une option -e, un <saut de ligne> sera inséré avant le nouvel ajout. Le script résultant aura les mêmes propriétés que l'opérande script, décrit dans la section OPÉRANDES.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier
Un nom de chemin d'un fichier dont le contenu est lu et édité. Si plusieurs opérandes fichier sont spécifiés, les fichiers nommés seront lus dans l'ordre spécifié et leur concaténation sera éditée. Si aucun opérande fichier n'est spécifié, l'entrée standard sera utilisée.
script
Une chaîne à utiliser comme script de commandes d'édition. L'application ne doit pas présenter un script qui viole les restrictions d'un fichier texte, sauf que le caractère final n'a pas besoin d'être un <saut de ligne>.

STDIN

L'entrée standard sera utilisée si aucun opérande fichier n'est spécifié, et sera utilisée si un opérande fichier est '-' et que l'implémentation traite le '-' comme signifiant l'entrée standard. Sinon, l'entrée standard ne sera pas utilisée. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte. Les fichiers_script nommés par l'option -f doivent consister en des commandes d'édition.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de sed :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de localisation.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la localisation pour le comportement des plages, des classes d'équivalence et des éléments de collation multicaractères dans les expressions régulières.
LC_CTYPE
Détermine la localisation pour l'interprétation des séquences d'octets de données textuelles comme caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée), et le comportement des classes de caractères dans les expressions régulières.
LC_MESSAGES

Détermine la localisation qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS SYNCHRONES

Par défaut.

STDOUT

Les fichiers d'entrée seront écrits sur la sortie standard, avec les commandes d'édition spécifiées dans le script appliquées. Si l'option -n est spécifiée, seules les lignes d'entrée sélectionnées par le script seront écrites sur la sortie standard.

STDERR

La sortie d'erreur standard sera utilisée uniquement pour les messages de diagnostic et d'avertissement.

FICHIERS DE SORTIE

Les fichiers de sortie seront des fichiers texte dont les formats dépendent des commandes d'édition données.

DESCRIPTION ÉTENDUE

Le script doit consister en des commandes d'édition de la forme suivante :

[adresse[,adresse]]fonction

où fonction représente un verbe de commande à un seul caractère parmi la liste de Commandes d'édition dans sed, suivi des arguments applicables.

La commande peut être précédée de caractères <espace> et/ou de caractères <point-virgule>. La fonction peut être précédée de caractères <espace>. Ces caractères optionnels n'auront aucun effet.

En opération par défaut, sed doit ajouter cycliquement une ligne d'entrée, moins son caractère de terminaison <saut de ligne>, dans l'espace de motif. La lecture de l'entrée doit être ignorée si un <saut de ligne> était présent dans l'espace de motif avant une commande D terminant le cycle précédent. L'utilitaire sed doit alors appliquer séquentiellement toutes les commandes dont les adresses sélectionnent cet espace de motif, jusqu'à ce qu'une commande démarre le cycle suivant ou quitte. Si aucune commande n'a explicitement démarré un nouveau cycle, alors à la fin du script, l'espace de motif doit être copié sur la sortie standard (sauf lorsque -n est spécifié) et l'espace de motif doit être supprimé. Chaque fois que l'espace de motif est écrit sur la sortie standard ou un fichier nommé, sed doit immédiatement le suivre d'un <saut de ligne>.

Certaines des commandes d'édition utilisent un espace de maintien pour sauvegarder tout ou partie de l'espace de motif pour une récupération ultérieure. Les espaces de motif et de maintien doivent pouvoir contenir chacun au moins 8192 octets.

Addresses in sed

An address selects a set of lines (the "selected lines") in the input stream. The sed utility supports the following address types:

  • A line number.
  • A positive decimal value representing the line number.
  • A valid BRE (as described in Regular Expressions in sed) delimited by any character except <backslash> or <newline>. The delimiter character itself is not part of the BRE.
  • The regular expression '$', which matches the last line of input, or a context address (which consists of a BRE, as described in Regular Expressions in sed, preceded and followed by a delimiter, usually a <slash>).

An editing command with no addresses shall select every pattern space.

An editing command with one address shall select each pattern space that matches the address.

An editing command with two addresses shall select the inclusive range from the first pattern space that matches the first address through the next pattern space that matches the second. (If the second address is a number less than or equal to the line number first selected, only one line shall be selected.) Starting at the first line following the selected range, sed shall look again for the first address. Thereafter, the process shall be repeated. Omitting either or both of the address components in the following form produces undefined results:

[address[,address]]

Expressions régulières dans sed

L'utilitaire sed prend en charge les BRE telles que décrites dans le volume Définitions de base de POSIX.1‐2017, Section 9.3, Expressions régulières de base, avec les ajouts suivants :

*
Dans une adresse contextuelle, la construction "\cBREc", où c est un caractère autre que <backslash> ou <newline>, est identique à "/BRE/". Si le caractère désigné par c apparaît après un <backslash>, il est considéré comme ce caractère littéral, qui ne termine pas le BRE. Par exemple, dans l'adresse contextuelle "\xabc\xdefx", le second x représente lui-même, de sorte que le BRE est "abcxdef".
*
La séquence d'échappement '\n' correspond à un <newline> intégré dans l'espace de motif. Un <newline> littéral ne doit pas être utilisé dans le BRE d'une adresse contextuelle ou dans la fonction de substitution.
*
Si une expression régulière est vide (c'est-à-dire qu'aucun motif n'est spécifié), sed se comportera comme si la dernière expression régulière utilisée dans la dernière commande appliquée (soit comme adresse, soit dans le cadre d'une commande de substitution) était spécifiée.

Commandes d'édition dans sed

Dans la liste suivante des commandes d'édition, le nombre maximum d'adresses admissibles pour chaque fonction est indiqué par [0addr], [1addr] ou [2addr], représentant zéro, une ou deux adresses.

L'argument text consiste en une ou plusieurs lignes. Chaque <newline> intégré dans le texte est précédé d'un <backslash>. Les autres caractères <backslash> dans le texte sont supprimés, et le caractère suivant est traité littéralement.

Les verbes de commande r et w, ainsi que le drapeau w de la commande s, prennent un paramètre rfile (ou wfile), séparé de la lettre ou du drapeau de commande par un ou plusieurs caractères <blank> ; les implémentations peuvent autoriser une séparation nulle comme extension.

L'argument rfile ou wfile termine la commande d'édition. Chaque wfile est créé avant le début du traitement. Les implémentations doivent prendre en charge au moins dix arguments wfile dans le script ; le nombre réel (supérieur ou égal à 10) pris en charge par l'implémentation n'est pas spécifié. L'utilisation du paramètre wfile entraîne la création initiale du fichier s'il n'existe pas, ou le remplacement du contenu d'un fichier existant.

Les verbes de commande b, r, s, t, w, y et : acceptent des arguments supplémentaires. Les synopses suivantes indiquent quels arguments doivent être séparés des verbes de commande par un seul <espace>.

Les commandes a et r planifient le texte pour une sortie ultérieure. Le texte spécifié pour la commande a, et le contenu du fichier spécifié pour la commande r, sont écrits sur la sortie standard juste avant la prochaine tentative de lecture d'une ligne d'entrée lors de l'exécution des commandes N ou n, ou lors de l'atteinte de la fin du script. S'il est écrit lors de l'atteinte de la fin du script, et que l'option -n n'a pas été spécifiée, le texte est écrit après la copie de l'espace de motif sur la sortie standard. Le contenu du fichier spécifié pour la commande r est celui du moment de la sortie, et non du moment où la commande r a été appliquée. Le texte est affiché dans l'ordre où les commandes a et r ont été appliquées à l'entrée.

Les commandes d'édition autres que {...}, a, b, c, i, r, t, w, : et # peuvent être suivies d'un <point-virgule>, de caractères <blank> optionnels et d'une autre commande d'édition. Cependant, lorsqu'une commande d'édition s est utilisée avec le drapeau w, la suivre d'une autre commande de cette manière produit des résultats indéfinis.

Une fonction peut être précédée d'un caractère '!', auquel cas la fonction est appliquée si les adresses ne sélectionnent pas l'espace de motif. Zéro ou plusieurs caractères <blank> sont acceptés avant le caractère '!'. Il n'est pas spécifié si les caractères <blank> peuvent suivre le caractère '!', et les applications conformes ne doivent pas suivre le caractère '!' de caractères <blank>.

Si un argument label (pour une commande b, t ou :) contient des caractères en dehors de l'ensemble de caractères de nom de fichier portable, ou si un label est plus long que 8 octets, le comportement n'est pas spécifié. L'implémentation doit prendre en charge les arguments label reconnus comme uniques jusqu'à au moins 8 octets ; la longueur réelle (supérieure ou égale à 8) prise en charge par l'implémentation n'est pas spécifiée. Il n'est pas spécifié si le dépassement de la longueur maximale de label prise en charge provoque une erreur ou une troncature silencieuse.

[2addr]s/BRE/remplacement/flags

Remplace les occurrences de la BRE dans l'espace de motif par la chaîne de remplacement. Tout caractère autre que <backslash> ou <newline> peut être utilisé à la place de <slash> pour délimiter la BRE et le remplacement. Dans la BRE et le remplacement, le délimiteur de BRE lui-même peut être utilisé comme un caractère littéral s'il est précédé d'un <backslash>.

La chaîne de remplacement sera analysée de début à fin. Un <ampersand> ('&') apparaissant dans le remplacement sera remplacé par la chaîne correspondant à la BRE. Le sens spécial de '&' dans ce contexte peut être supprimé en le faisant précéder d'un <backslash>. Les caractères "\n", où n est un chiffre, seront remplacés par le texte correspondant à l'expression de référence arrière correspondante. Si l'expression de référence arrière correspondante ne correspond pas, alors les caractères "\n" seront remplacés par la chaîne vide. Le sens spécial de "\n" où n est un chiffre dans ce contexte, peut être supprimé en le faisant précéder d'un <backslash>. Pour chaque autre <backslash> rencontré, le caractère suivant perdra son sens spécial (le cas échéant).

Une ligne peut être divisée en y insérant un <newline>. L'application échappera le <newline> dans le remplacement en le faisant précéder d'un <backslash>.

Le sens d'un <backslash> non échappé immédiatement suivi d'un caractère autre que '&', <backslash>, un chiffre, <newline>, ou le caractère délimiteur utilisé pour cette commande, n'est pas spécifié.

Une substitution sera considérée comme effectuée même si la chaîne de remplacement est identique à la chaîne qu'elle remplace. Tout <backslash> utilisé pour modifier le sens par défaut d'un caractère suivant sera écarté de la BRE ou du remplacement avant d'évaluer la BRE ou d'utiliser le remplacement.

Tout caractère autre que <backslash> ou <newline> peut être utilisé à la place de <slash> pour délimiter les chaînes. Si le délimiteur n'est pas 'n', dans string1 et string2, le délimiteur lui-même peut être utilisé comme caractère littéral s'il est précédé d'un <backslash>. Si un caractère <backslash> est immédiatement suivi d'un caractère <backslash> dans string1 ou string2, les deux caractères <backslash> seront comptés comme un seul caractère <backslash> littéral. Le sens d'un <backslash> suivi d'un caractère autre que 'n', un <backslash>, ou le caractère délimiteur n'est pas défini.
[0addr]:label
Ne fait rien. Cette commande porte un label auquel les commandes b et t sautent.
[1addr]=
Écrit ce qui suit vers la sortie standard :
"%d\n", <numéro de ligne actuel>
[0addr]
Ignore cette commande vide.
[0addr]#
Ignore le '#' et le reste de la ligne (les traite comme un commentaire), à la seule exception que si les deux premiers caractères du script sont "#n", la sortie par défaut sera supprimée ; cela équivaudra à spécifier -n sur la ligne de commande.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Les expressions régulières correspondent à des chaînes entières, pas seulement à des lignes individuelles, mais un <newline> est correspondant par '\n' dans une ER de sed ; un <newline> n'est pas autorisé par la définition générale des expressions régulières dans POSIX.1‐2008. Notez également que '\n' ne peut pas être utilisé pour faire correspondre un <newline> à la fin d'une ligne d'entrée arbitraire ; les caractères <newline> apparaissent dans l'espace de motif à la suite de la commande d'édition N.

Lors de l'utilisation de sed pour traiter des noms de chemin, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les noms de chemin peuvent contenir des séquences d'octets qui ne forment pas des caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire ne serait pas défini. Dans la locale POSIX, chaque octet est un caractère valide d'un seul octet, et ce problème est donc évité.

EXEMPLES

Ce script sed simule la commande cat -s de BSD, en réduisant les lignes vides excessives de l'entrée standard.

sed -n '
# Écrit les lignes non vides.
/./ {
    p
    d
    }
# Écrit une seule ligne vide, puis recherche d'autres lignes vides.
/^$/    p
# Obtient la ligne suivante, supprime le <newline> conservé (ligne vide),
# et recherche d'autres lignes vides.
:Empty
/^$/    {
    N
    s/.//
    b Empty
    }
# Écrit la ligne non vide avant de revenir à la recherche
# de la première d'une série de lignes vides.
    p
'

La commande sed suivante est une méthode beaucoup plus simple pour réduire les lignes vides, bien qu'elle ne soit pas exactement identique à cat -s car elle supprime toute ligne vide initiale :

sed -n '/./,/^$/p'

RATIONALE

Ce volume de POSIX.1‐2017 exige que les implémentations prennent en charge au moins dix wfile distincts, ce qui correspond à la pratique historique sur de nombreuses implémentations. Les implémentations sont encouragées à en prendre en charge davantage, mais les applications conformes ne doivent pas dépasser cette limite.

Les codes de statut de sortie spécifiés ici sont différents de ceux de System V. System V retourne 2 pour des commandes sed corrompues, mais retourne zéro avec son message d'utilisation ou si le fichier d'entrée n'a pas pu être ouvert. Les développeurs du standard ont considéré cela comme un bug.

La manière dont la commande l écrit les caractères non imprimables a été modifiée pour éviter la méthode historique de retour arrière-surimpression, et d'autres exigences pour obtenir une sortie sans ambiguïté ont été ajoutées. Voir la RATIONALE pour ed pour les détails du format choisi, qui est le même que celui choisi pour sed.

Ce volume de POSIX.1‐2017 exige que les implémentations fournissent des espaces de motif et de maintien d'au moins 8192 octets, plus grands que les espaces de 4000 octets utilisés par certaines implémentations historiques, mais inférieurs à la limite de 20480 octets utilisée dans une proposition précoce. Les implémentations sont encouragées à allouer dynamiquement des espaces de motif et de maintien plus grands au besoin.

Les exigences d'acceptation des caractères <blank> et <space> dans les lignes de commande ont été rendues plus explicites que dans les propositions précoces pour décrire clairement la pratique historique et pour dissiper la confusion concernant la phrase « protéger les blancs initiaux [sic] et les tabulations de la suppression effectuée sur chaque ligne de script » qui apparaît dans une grande partie de la documentation historique de la description du texte de l'utilitaire sed. (Il n'est pas connu que toutes les implémentations aient supprimé les caractères <blank> des lignes de texte, bien qu'elles aient toutes permis les caractères <blank> en tête précédant l'adresse sur une ligne de commande.)

Le traitement des commentaires '#' diffère de celui du SVID qui ne permet qu'un commentaire comme première ligne du script, mais correspond aux implémentations dérivées de BSD. Le caractère commentaire est traité comme une commande, et il a les mêmes propriétés en termes d'acceptation avec des caractères <blank> en tête ; l'implémentation BSD a historiquement pris en charge cela.

Les propositions antérieures exigeaient qu'un script_file contienne au moins une ligne non commentée. Certaines implémentations historiques se sont comportées de manière inattendue si ce n'était pas le cas. Les développeurs du standard ont considéré que c'était une incorrection

sed(1p)

PROLOG

This manual page is a translation of the POSIX specification for the sed utility. It is not part of the GNU or FreeBSD documentation.

NAME

sed — stream editor

SYNOPSIS

sed [-n] [-e script]... [-f script_file]... [file... ]

DESCRIPTION

The sed utility shall read lines one at a time from the location specified by the INPUT FILES argument (or standard input if no INPUT FILES are specified), test each line to see whether it matches any of the criteria given in the extended DESCRIPTION of commands, and for each text line that matches, execute the commands in the script. The sed utility shall derive its script from the -e option, the -f option, or a combination of both. The sed utility shall write the resulting data to standard output.

OPTIONS

The following options shall be supported:

-n
Suppress the automatic printing of the pattern space at the end of each cycle. Only commands that explicitly print data (e.g., the p command) shall produce output. This option is the inverse of the default behavior.
-e script
Add the script to the commands to be executed. Zero or more -e options may be supplied.
-f script_file
Add the contents of the file named by script_file to the commands to be executed. The file shall contain sed commands, one per line. Zero or more -f options may be supplied.

If any -e or -f options are supplied, the sed utility shall execute the commands in the order they are presented on the command line. If no -e or -f options are supplied, the application shall take the first non-option argument as the script_file and its contents shall be used as the sed commands.

Any remaining non-option arguments shall be treated as INPUT FILES.

OPERANDS

The following operands shall be supported:

file
A pathname of a file to be processed. If no file operands are specified, the standard input shall be used.

STDIN

See INPUT FILES.

INPUT FILES

The standard input or the files specified by the file operands shall be read in the order they are specified.

ENVIRONMENT VARIABLES

The following environment variables shall be supported:

LC_ALL
Determine the locale for the interpretation of sequences of bytes of text data. See locale(7).
LC_COLLATE
Determine the locale for the comparison of filename [[...]] and *(...) character class matching.
LC_CTYPE
Determine the locale for the interpretation of sequences of bytes of text data.
LC_MESSAGES
Determine the locale that should be used to override the locale(7) messages, including diagnostic and informative messages. See locale(7).
NLSPATH
Determine the location of message catalogues for the processing of LC_MESSAGES. See locale(7).

Supporting the LC_COLLATE and LC_CTYPE environment variables requires that the implementation support the XSI extensions.

The locale settings shall affect the interpretation of character classes and the sorting order within character classes in regular expressions.

ASYNCHRONOUS EVENTS

Undefined.

STDOUT

The standard output shall contain the results of the editing commands.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

The sed utility shall execute a script of sed editing commands. The script shall be constructed from the arguments to the -e and -f options.

The sed utility processes input by reading one line at a time into a temporary memory space called the *pattern space*. Each line read shall be processed by the commands specified in the script. The default action at the end of processing each line is to print the contents of the pattern space. The -n option suppresses this default behavior.

A sed script consists of one or more editing commands, separated by newlines or semicolons. The sed editor executes these commands in the order listed.

Most sed commands consist of an optional *address* or *address range*, followed by a single *editing command character*, followed by optional parameters. If an address is provided, the command shall be applied only to lines that match the address. If an address range is provided, the command shall be applied to lines starting from the first line that matches the first address, up to and including the first line following that matches the second address.

An *address* can be one of the following:

a
A decimal line number.
a
A regular expression enclosed in slashes (/). The implementation shall support extended regular expressions as described in re.h(7), with the following exceptions:

The following Extended Regular Expression syntax constructs shall be supported:

  • . (Matches any character except a newline)

  • \ (Escapes the next character)

  • * (Zero or more preceding expressions)

  • + (One or more preceding expressions)

  • ? (Zero or one preceding expression)

  • | (Alternation)

  • () (Grouping)

  • [] (Character classes)

  • [^] (Negated character classes)

  • ^ (Beginning of line)

  • $ (End of line)

The following Extended Regular Expression syntax constructs shall NOT be supported:

  • \?, \+, \|, \(, \)`

  • \{n,\}, \{n,m\}

  • (?...)

a
A regular expression followed by ?. This matches the empty string at the beginning of the line.
a
A regular expression followed by !. This matches any line that does not match the regular expression.
a
A line number preceded by %. This matches the line number specified.
a
A regular expression preceded by %. This matches any line that matches the regular expression.
a
A line number preceded by #. This matches the line number specified.
a
A regular expression preceded by #. This matches any line that matches the regular expression.

A *regular expression* enclosed in parentheses () shall match the text that matches the regular expression.

If the first address is a / regular expression and the second address is ?, the range shall extend up to, but not including, the next line that matches the regular expression.

If an address or address range is missing, it shall be taken to match all lines. If both addresses are missing, the command applies to all lines. If only one address is present, the command applies only to lines matching that address.

The following editing commands shall be supported:

a
Append. Write text each time this command is executed. text must be preceded by a backslash (\). Each line of appended text must be quoted and end with a backslash. The last line of text does not need a trailing backslash.
b [label]
Branch. If a label is specified, transfer control to the first : command with that label. If no label is specified, transfer control to the end of the script. This command can only cause branching to labels defined within the script.
c
Change. Delete the pattern space and replace it with text. The text must be preceded by a backslash and each line of text must be quoted and end with a backslash. The last line of text does not need a trailing backslash.
d
Delete the pattern space. Without this command, all pattern space content would be printed. This command causes the current line to be deleted and the next line to be read.
D
Delete the matched portion of the pattern space. Without this command, all pattern space content would be printed. This command causes the current line to be deleted and the next line to be read.
g
Replace the contents of the pattern space with the contents of the hold space.
G
Append the contents of the hold space to the pattern space, separated by a newline.
h
Copy the contents of the pattern space into the hold space.
H
Append the contents of the pattern space to the hold space, separated by a newline.
i
Write text each time this command is executed. text must be preceded by a backslash. Each line of text must be quoted and end with a backslash. The last line of text does not need a trailing backslash.
l
List. The contents of the pattern space shall be written to standard output, followed by a newline. If the implementation supports the XSI extensions, non-printing characters shall be represented by escape sequences. If the implementation supports the XSI extensions, the implementation shall write a dollar sign ($) after the output if the input line was terminated by a newline.
p
Print. Print the contents of the pattern space.
P
Print the contents of the pattern space up to the first newline character.
q [exit_status]
Cause sed to immediately quit processing all input. If the exit_status parameter is given, it shall be used as the exit status of the sed process. If it is not given, an exit status of 0 shall be used.
r file
Copy the contents of file to standard output at the current point in the script, after writing the current pattern space and before starting the next cycle. The file shall be opened for reading at each reference.
s/regex>/replacement/[flags]
Substitute. Replace the first occurrence of the pattern space that matches the regular expression regex with the replacement replacement. The flags can be one of the following:
g
Replace all occurrences that match regex in the pattern space.
p
If a substitution was made, print the pattern space. If the -n option was also specified, this option causes the modified pattern space to be printed. If the -n option was not specified, the default output mechanism prints the pattern space, so the p flag causes double printing.
w file
If a substitution was made, append the modified pattern space to the specified file. The file shall be created if it does not exist. The file shall be truncated if it exists. The file shall be opened for writing at each reference.
number
Replace only the numberth occurrence of the pattern space that matches the regular expression.
t [label]
Branch. If any s commands have successfully made substitutions since the last line was read and the current line is not the start of the script, then transfer control to the first : command with that label. If no label is specified, transfer control to the end of the script. This command can only cause branching to labels defined within the script.
w file
Write. Append the contents of the pattern space to the specified file. The file shall be created if it does not exist. The file shall be truncated if it exists. The file shall be opened for writing at each reference.
x
Exchange the contents of the pattern space and the hold space.
y/regex>/replacement/
Transliterate. Replace occurrences of characters in regex with corresponding characters in replacement. Both regex and replacement must be the same length. The characters in regex and replacement are treated as literal characters, except for the delimiter character, which is ignored.
:label
Label. This command does nothing. It serves only as a target for branch commands.
;
Separate commands.
#
Comment. All characters from the # to the next newline shall be ignored.

EXIT STATUS

The following exit values shall be returned:

0
Success.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Undefined.

APPLICATION USAGE

The sed utility cannot accept scripts containing a mix of -e and -f options, except as specified in the SYNOPSIS. If the application mixes -e and -f options, the behavior is undefined.

Lines in -f script_files that are empty or consist only of comments shall be ignored. Application developers should not have to avoid this feature. A correct implementation of this volume of POSIX.1‐2017 shall permit -f script_files that consist only of comment lines.

Early proposals indicated that if -e and -f options were intermixed, all -e options were processed before any -f options. This has been changed to process them in the order presented because it matches historical practice and is more intuitive.

The treatment of the p flag to the s command differs between System V and BSD-based systems when the default output is suppressed. In the two examples:

echo a | sed    's/a/A/p'
echo a | sed -n 's/a/A/p'

this volume of POSIX.1‐2017, BSD, System V documentation, and the SVID indicate that the first example should write two lines with A, whereas the second should write one. Some System V systems write the A only once in both examples because the p flag is ignored if the -n option is not specified.

This is a case of a diametrical difference between systems that could not be reconciled through the compromise of declaring the behavior to be unspecified. The SVID/BSD/System V documentation behavior was adopted for this volume of POSIX.1‐2017 because:

*
No known documentation for any historic system describes the interaction between the p flag and the -n option.
*
The selected behavior is more correct as there is no technical justification for any interaction between the p flag and the -n option. A relationship between -n and the p flag might imply that they are only used together, but this ignores valid scripts that interrupt the cyclical nature of the processing through the use of the D, d, q, or branching commands. Such scripts rely on the p suffix to write the pattern space because they do not make use of the default output at the ``bottom'' of the script.
*
Because the -n option makes the p flag unnecessary, any interaction would only be useful if sed scripts were written to run both with and without the -n option. This is believed to be unlikely. It is even more unlikely that programmers have coded the p flag expecting it to be unnecessary. Because the interaction was not documented, the likelihood of a programmer discovering the interaction and depending on it is further decreased.
*
Finally, scripts that break under the specified behavior produce too much output instead of too little, which is easier to diagnose and correct.

The form of the substitute command that uses the n suffix was limited to the first 512 matches in an early proposal. This limit has been removed because there is no reason an editor processing lines of {LINE_MAX} length should have this restriction. The command s/a/A/2047 should be able to substitute the 2047th occurrence of a on a line.

The b, t, and : commands are documented to ignore leading white space, but no mention is made of trailing white space. Historical implementations of sed assigned different locations to the labels 'x' and "x". This is not useful, and leads to subtle programming errors, but it is historical practice, and changing it could theoretically break working scripts. Implementors are encouraged to provide warning messages about labels that are never referenced by a b or t command, jumps to labels that do not exist, and label arguments that are subject to truncation.

Earlier versions of this standard allowed for implementations with bytes other than eight bits, but this has been modified in this version.

EXAMPLES

None.

RATIONALE

The sed utility behaves as a stream editor, transforming input based on a script of editing commands. The standard requires that sed read input line by line, apply a script of commands, and write the results to standard output.

The standard defines a set of editing commands that mimic those found in the ed editor, along with some extensions.

The interaction between the -n option and the p flag of the s command was a point of contention. Historically, BSD and System V diverged on this behavior. POSIX.1-2017 specifies the behavior found in BSD and System V documentation, which is generally considered more logical. The rationale details the reasoning behind this decision, emphasizing correctness and ease of diagnosis in case of script errors.

The limitation on the number of substitutions in the s command with a number suffix has been removed to align with the principle of not imposing arbitrary limits unrelated to the underlying text processing capabilities.

Regarding labels and white space, the standard clarifies that leading white space is ignored for branch commands, and discourages historical implementations that treated labels with and without trailing white space differently. Implementors are encouraged to provide warnings for potentially problematic label usage.

The standard has been updated to mandate an eight-bit byte environment for POSIX.1-2017.
