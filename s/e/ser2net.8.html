NOM

ser2net - Proxy série vers réseau

SYNTAXE

ser2net [-c fichier_config] [-C répertoire_sysconf] [-Y ligne_config] [-p port_controle] [-n] [-d] [-b] [-v] [-P fichier_pid]

DESCRIPTION

Le démon ser2net permet d'établir des sessions telnet et tcp avec les ports série d'une unité ou avec une interface IPMI Serial Over LAN (SOL).

Le programme démarre normalement en tant que démon, ouvre les ports réseau spécifiés dans le fichier de configuration et attend les connexions. Une fois qu'une connexion se produit, le programme tente d'établir la connexion et d'ouvrir le port série. Si un autre utilisateur utilise déjà la connexion ou le port série, la connexion est refusée avec un message d'erreur.

OPTIONS

-c fichier_config
Définit le fichier de configuration sur un fichier autre que celui par défaut, répertoire_sysconf/ser2net/ser2net.yaml. Si le fichier_config est -, alors l'entrée standard est lue comme fichier de configuration. Voir -C pour des informations sur répertoire_sysconf.
-C répertoire_sysconf
Définit le répertoire où le fichier de configuration et les clés ssl sont stockés. Il s'agit généralement de /etc/ser2net sur les systèmes de type Unix, sous Windows, il s'agit de ../etc/ser2net à partir de l'emplacement de l'exécutable par défaut.
-a répertoire_auth
Définit le répertoire par défaut où les informations d'authentification sont stockées. Il s'agit généralement de /usr/share/ser2net sur les systèmes de type Unix, sous Windows, il s'agit de ../share/ser2net à partir de l'emplacement de l'exécutable par défaut. Ceci peut être remplacé dans le fichier de configuration. Voir ser2net.yaml.5 pour des informations sur ce que cela fait.
-A répertoire_auth_admin
Définit le répertoire par défaut où les informations d'authentification de l'administrateur sont stockées. Il s'agit de répertoire_sysconf/auth par défaut. Ceci peut être remplacé dans le fichier de configuration. Voir ser2net.yaml.5 pour des informations sur ce que cela fait.
-Y chaîne_config_yaml
Ajoute une chaîne de configuration yaml à la fin des chaînes à traiter. Ceci peut être spécifié plusieurs fois pour plusieurs chaînes. Celles-ci sont ajoutées à la fin d'un fichier de configuration yaml ; bien que si ceci est spécifié, le fichier de configuration par défaut est désactivé et vous devez l'activer avec l'option -c.

Pour faciliter la gestion, tout # dans la chaîne de configuration qui n'est pas entre guillemets (ce qui commencerait normalement un commentaire en yaml) est converti en nouvelle ligne. De plus, une nouvelle ligne est ajoutée après chaque chaîne de configuration distincte. Ainsi, par exemple :


-Y 'connexion: &con01# accepteur: tcp,2013'
-Y ' connecteur: serialdev,/dev/ttyEcho0,9600n81,local'
-Y ' options:# bannière: "### Une Bannière ###\r\n"'

peuvent être mis sur la ligne de commande ser2net.

-n
Arrête le démon de se séparer et de se détacher du terminal de contrôle. Ceci est utile pour l'exécution depuis init.
-d
Comme -n, mais envoie également les logs système à la sortie standard. Ceci est surtout utile à des fins de débogage.
-P fichier_pid
Si spécifié, place l'identifiant de processus (pid) de ser2net dans le fichier pid, remplaçant tout ce qui se trouvait auparavant dans ce fichier. Un fichier pid n'est pas créé par défaut, vous devez spécifier ceci pour en créer un. Notez également que ce nom de fichier doit être spécifié avec le chemin complet, car ser2net changera de répertoire pour aller à "/" lorsqu'il deviendra un démon.
-u
Si le verrouillage UUCP est activé, ceci désactivera l'utilisation des verrous UUCP.
-b
Cisco IOS utilise un mécanisme différent pour spécifier les débits en bauds que le mécanisme décrit dans la RFC2217. Cette option définit la version IOS de la définition des débits en bauds. Par défaut, c'est la RFC2217. Notez que cette capacité est maintenant gérée automatiquement et cette option est ignorée.
-v
Affiche la version du programme et quitte.
-t <nombre_threads>
Lance le nombre de threads donné à ser2net pour qu'il les utilise. La valeur par défaut est 1. Valide uniquement si pthreads est activé lors de la compilation.
-p <accepteur_admin>
Active l'interface administrateur sur la spécification d'accepteur donnée. Voir "CONNEXION ADMIN" dans ser2net.yaml(5) pour plus de détails sur la manière de configurer ceci, et "INTERFACE ADMIN" ci-dessous pour des détails sur la manière de l'utiliser.
-s signature
Spécifie la signature par défaut RFC2217.

INTERFACE ADMINISTRATEUR

L'interface administrateur fournit une interface simple pour contrôler les ports et visualiser leur état. Pour ce faire, elle dispose des commandes suivantes :

showport [<port_réseau>]
Affiche les informations sur un port. Si aucun port n'est donné, tous les ports sont affichés.
showshortport [<port_réseau>]
Affiche les informations sur un port, chaque port sur une seule ligne. Si aucun port n'est donné, tous les ports sont affichés. Cela peut produire une sortie très large.
help
Affiche une courte liste et un résumé des commandes.
exit
Se déconnecte du port de contrôle.
yaml
Passe en mode de sortie yaml. Voir MODES YAML ci-dessous.
version
Affiche la version de ce programme.
monitor <type> <port_réseau>
Affiche toutes les entrées pour un port donné sur le port de contrôle appelant. Une seule direction peut être surveillée à la fois. Le champ type peut être tcp ou term et spécifie si les données doivent être surveillées depuis le port réseau ou depuis le port série. Notez que la surveillance des données est effectuée au mieux, si le port contrôleur ne peut pas suivre, les données seront silencieusement ignorées. Un contrôleur ne peut surveiller qu'une seule chose et un port ne peut être surveillé que par un seul contrôleur.
monitor stop
Arrête le moniteur actuel.
disconnect <port_réseau>
Déconnecte la connexion tcp sur le port.
setporttimeout <port_réseau> <timeout>
Définit la durée en secondes avant que la connexion du port ne soit fermée si aucune activité n'a été détectée sur le port.
setportconfig <port_réseau> <config>
Définit la configuration du port comme dans la configuration de l'appareil dans le fichier /etc/ser2net/ser2net.yaml. En cas d'options conflictuelles, la dernière option sera celle utilisée. Notez que celles-ci ne changeront pas tant que le port ne sera pas déconnecté et reconnecté. Les options 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200 définissent les différents débits en bauds. Les débits suivants peuvent être disponibles si votre système a les valeurs définies et que votre matériel les prend en charge : 230400, 460800, 500000, 576000, 921600, 1000000, 1152000, 1500000, 2000000, 2500000, 3000000, 3500000, 4000000. La parité, les bits de données et les bits d'arrêt peuvent être spécifiés de la manière classique après la vitesse, comme dans 9600N81. Ceci a le format suivant : <vitesse>[N|E|O|M|S[5|6|7|8[1|2]]]. La définition des options série de cette manière ne fonctionne pas sur SOL, SOL a des options série N81 fixes. EVEN, ODD, NONE (MARK et SPACE si supportés) définissent la parité. 1STOPBIT, 2STOPBITS définissent le nombre de bits d'arrêt. 7DATABITS, 8DATABITS définissent le nombre de bits de données. [-]XONXOFF active (- désactive) le support XON/XOFF. [-]RTSCTS active (- désactive) le contrôle de flux matériel. [-]LOCAL ignore (- vérifie) les lignes de contrôle du modem (DCD, DTR, etc.)
setportcontrol <port_réseau> <contrôles>

INTERFACEDEMONS

ser2net is a daemon that allows you to make serial ports available over a TCP/IP connection. It is useful for making serial devices available over the network. This can be used for remote administration of devices, or for allowing network applications to access serial devices.

ser2net is configured via a configuration file, which defaults to /etc/ser2net.yaml. The configuration file specifies which serial ports to open, and how to make them available over the network. It can also be used to configure various other options, such as baud rate, parity, and stop bits.

ser2net supports a number of features, including:

  • Multiple serial ports can be made available over the network.
  • Each serial port can be configured independently.
  • Various baud rates, parity, and stop bit settings are supported.
  • Connections can be made using TCP/IP.
  • A telnet interface is provided for connecting to serial ports.
  • An administration interface is provided for managing ser2net.

OPTIONS

The following options are available:

-c configuration file
Use the specified configuration file instead of the default. The default configuration file is /etc/ser2net.yaml.
-d
Run in the foreground, and do not daemonize. This is useful for debugging. Error output will go to standard output instead of syslog.
-p port number
Listen on the specified port number for incoming connections. This option can be specified multiple times to listen on multiple ports. If this option is not specified, ser2net will listen on the ports specified in the configuration file.
-v
Print version information and exit.

ADMIN INTERFACE

ser2net provides an administration interface that allows you to manage the daemon remotely. The administration interface is available on TCP port 3333 by default. The administration interface can be configured using the -a option.

The administration interface supports the following commands:

status
Prints the current status of ser2net, including the status of all serial ports and network connections.
showport
Prints the status of all serial ports.
disconnect <connection name>
Disconnects the specified connection. The connection name is the alias specified in the configuration file.
setporttimeout <connection name> <timeout>
Sets the timeout for the specified connection. The timeout is specified in seconds.
setportcontrol <connection name> <control signal>
Sets the state of the specified control signal. Valid control signals are: DTRHI, DTRLO Turns on and off the DTR line. RTSHI, RTSLO Turns on and off the RTS line.
setportenable <network port> <enable state>
Sets the port operation state. Valid states are: off to shut the network port down, raw to enable the network port transfer all I/O as-is, rawlp to enable the network port input and device output without termios setting, and telnet to enable the network port is up run the telnet negotiation protocol on the port.
reload
Causes ser2net to reload its configuration. Any error output will come out in the output, along with going to syslog.

MODES YAML

If the command "yaml" is issued, the echo is turned off and all output is YAML compliant. The form is basically the same as the non-YAML output, with some minor adjustments to make it YAML compliant. In addition, all responses are in the form:


%YAML 1.1
---
response:
<response info here>
...

If there is an error, it is returned in the response with the "error" key. If the command succeeded, no "error" key will be present in the response mapping. The "..." will be at the end of all responses.

The following commands are available in yaml output mode: exit, version, showport, disconnect, setporttimeout, setportenable, setportcontrol, reload,

If "%YAML" is seen in the input, YAML input and output modes are activated, echo is disabled, and all input is expected to be in the form:


---
command:
name: <command name>
id: <optional id>
parms: [ parm1 [, parm2 [...]]]
...

The id is optional and will just be returned in the response. The parms are optional, too, unless the command requires them. Extra parms are ignored, along with unknown keys in the main mapping.

Note that you have to deal with the "->" that is issued when the connection is made, before going into YAML mode, YAML doesn't handle that well.

In YAML output mode, you will get asynchronous reports of connections and disconnections in the form:


%YAML 1.1
---
new connection:
name: !!str 'con1'
remaddr: !!str 'ipv6,::1,59072'
...


%YAML 1.1
---
disconnect:
name: !!str 'con1'
remaddr: !!str 'ipv6,::1,59072'
...

CONFIGURATION

Configuration is accomplished through the file /etc/ser2net/ser2net.yaml. A file with another name or path may be specified using the -c option.

The yaml configuration file is described in ser2net.yaml(5)

SIGNALS

SIGHUP
If ser2net receives a SIGHUP, it will reread it configuration file and make the appropriate changes. If an in use connection is changed or deleted, the actual change will not occur until the port is disconnected, except that if you disable a connection it will kick the users off.

ser2net uses the name (the connection alias) of the connection to tell if it is new, changed or deleted. If the new configuration file has a connection with the same name, it is treated as a change.

This has some unusual interactions with connections that allow more than one simultaneous connection. It works just like the other port, but the accepter is disabled and new connections will not be accepted until all the existing connections are closed.

ERREURS

All error output after startup goes to syslog, not standard output, unless you use the -d option.
