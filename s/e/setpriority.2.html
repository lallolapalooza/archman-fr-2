getpriority(2) Manuel des appels système getpriority(2)

NOM

getpriority, setpriority - obtenir/définir la priorité d'ordonnancement d'un programme

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/resource.h>
int getpriority(int which, id_t who);
int setpriority(int which, id_t who, int prio);

DESCRIPTION

La priorité d'ordonnancement du processus, du groupe de processus ou de l'utilisateur, indiquée par which et who, est obtenue avec l'appel getpriority() et définie avec l'appel setpriority(). L'attribut de processus traité par ces appels système est le même attribut (également connu sous le nom de valeur de "nice") que celui traité par nice(2).

La valeur which est l'un des PRIO_PROCESS, PRIO_PGRP, ou PRIO_USER, et who est interprété relativement à which (un identifiant de processus pour PRIO_PROCESS, un identifiant de groupe de processus pour PRIO_PGRP, et un identifiant utilisateur pour PRIO_USER). Une valeur nulle pour who désigne (respectivement) le processus appelant, le groupe de processus du processus appelant, ou l'identifiant utilisateur réel du processus appelant.

L'argument prio est une valeur comprise entre -20 et 19 (mais voir NOTES ci-dessous), -20 étant la priorité la plus élevée et 19 la priorité la plus basse. Les tentatives pour définir une priorité en dehors de cette plage sont silencieusement limitées à la plage. La priorité par défaut est 0 ; des valeurs plus basses donnent à un processus une priorité d'ordonnancement plus élevée.

L'appel getpriority() renvoie la priorité la plus élevée (valeur numérique la plus basse) dont bénéficie l'un des processus spécifiés. L'appel setpriority() définit les priorités de tous les processus spécifiés à la valeur spécifiée.

Traditionnellement, seul un processus privilégié pouvait abaisser la valeur de nice (c'est-à-dire définir une priorité plus élevée). Cependant, depuis Linux 2.6.12, un processus non privilégié peut diminuer la valeur de nice d'un processus cible qui a une limite souple RLIMIT_NICE appropriée ; voir getrlimit(2) pour plus de détails.

VALEUR DE RETOUR

En cas de succès, getpriority() renvoie la valeur de nice du thread appelant, qui peut être un nombre négatif. En cas d'erreur, il renvoie -1 et définit errno pour indiquer l'erreur.

Comme un appel réussi à getpriority() peut légitimement renvoyer la valeur -1, il est nécessaire d'effacer errno avant l'appel, puis de vérifier errno par la suite pour déterminer si -1 est une erreur ou une valeur légitime.

setpriority() renvoie 0 en cas de succès. En cas d'échec, il renvoie -1 et définit errno pour indiquer l'erreur.

ERREURS

EACCES
L'appelant a tenté de définir une valeur de nice plus basse (c'est-à-dire une priorité de processus plus élevée), mais n'avait pas le privilège requis (sous Linux : n'avait pas la capacité CAP_SYS_NICE).
EINVAL
which n'était pas PRIO_PROCESS, PRIO_PGRP, ou PRIO_USER.
EPERM
Un processus a été trouvé, mais son ID utilisateur effectif ne correspondait ni à l'ID utilisateur effectif ni à l'ID utilisateur réel de l'appelant, et n'était pas privilégié (sous Linux : n'avait pas la capacité CAP_SYS_NICE). Mais voir HISTORIQUE ci-dessous.
ESRCH
Aucun processus n'a été trouvé en utilisant les valeurs which et who spécifiées.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD (ces interfaces sont apparues pour la première fois dans 4.2BSD).

Les détails sur la condition pour EPERM dépendent du système. La description ci-dessus est ce que dit POSIX.1-2001, et semble être suivie sur tous les systèmes de type System V. Les noyaux Linux antérieurs à Linux 2.6.12 exigeaient que l'ID utilisateur réel ou effectif de l'appelant corresponde à l'utilisateur réel du processus who (au lieu de son ID utilisateur effectif). Linux 2.6.12 et versions ultérieures exigent que l'ID utilisateur effectif de l'appelant corresponde à l'ID utilisateur réel ou effectif du processus who. Tous les systèmes de type BSD (SunOS 4.1.3, Ultrix 4.2, 4.3BSD, FreeBSD 4.3, OpenBSD-2.5, ...) se comportent de la même manière que Linux 2.6.12 et versions ultérieures.

NOTES

Pour plus de détails sur la valeur de nice, voir sched(7).

Note : l'ajout de la fonctionnalité "autogroup" dans Linux 2.6.38 signifie que la valeur de nice n'a plus son effet traditionnel dans de nombreuses circonstances. Pour plus de détails, voir sched(7).

Un enfant créé par fork(2) hérite de la valeur de nice de son parent. La valeur de nice est préservée lors de execve(2).

Différences bibliothèque C/noyau

L'appel système getpriority renvoie les valeurs de nice traduites dans la plage 40..1, car une valeur de retour négative serait interprétée comme une erreur. La fonction wrapper glibc pour getpriority() traduit la valeur en arrière selon la formule unice = 20 - knice (ainsi, la plage 40..1 renvoyée par le noyau correspond à la plage -20..19 telle que vue par l'espace utilisateur).

BOGUES

Selon POSIX, la valeur de nice est un attribut par processus. Cependant, dans l'implémentation actuelle de POSIX threads sous Linux/NPTL, la valeur de nice est un attribut par thread : différents threads dans le même processus peuvent avoir des valeurs de nice différentes. Les applications portables devraient éviter de s'appuyer sur le comportement de Linux, qui pourrait être rendu conforme aux normes à l'avenir.

VOIR AUSSI

nice(1), renice(1), fork(2), capabilities(7), sched(7)

setpriority - get and set program scheduling priorities

NAME

setpriority, getpriority - get and set program scheduling priorities

SYNOPSIS

#include <sys/resource.h>

int setpriority(int which, id_t who, int priority);

int getpriority(int which, id_t who);

DESCRIPTION

The setpriority() system call sets the priority of processes or process groups. The getpriority() system call retrieves the current priority of processes or process groups.

The which argument specifies the domain of processes to which the priority setting or retrieval applies. It can take one of the following values:

  • PRIO_PROCESS: The who argument is a process ID.
  • PRIO_PGRP: The who argument is a process group ID.
  • PRIO_USER: The who argument is a real user ID.

If who is zero in any of these cases, the calling process (for PRIO_PROCESS), the calling process group (for PRIO_PGRP), or the calling process's user ID (for PRIO_USER) is affected.

The priority argument to setpriority() is a relative scheduling priority. Legal values are between -20 (highest priority) and 19 (lowest priority). The default priority is 0.

getpriority() returns the highest priority (i.e., the smallest numerical value) of any process specified by which and who.

A process's scheduling priority can only be modified by the superuser. Any process can modify the scheduling priority of its own processes (or those in its process group or associated with its user ID), but only if the new priority is not higher than the current highest priority. Specifically, a non-root user can only increase the scheduling priority of a process if the new priority is less than or equal to the scheduling priority of the calling process.

RETURN VALUE

On success, setpriority() returns 0. On failure, it returns -1 and sets errno appropriately.

On success, getpriority() returns the highest priority value. On failure, it returns -1 and sets errno appropriately.

Since the highest possible return value from getpriority() is 19, a return value of -1 is unambiguous. However, it is possible that a process has a priority of -1 (i.e. a priority of -1 was explicitly set). To distinguish this case from an error, getpriority() checks the global variable errno. If getpriority() returns -1 and errno is set to non-zero, then an error occurred. If getpriority() returns -1 and errno is zero, then the priority of the specified process(es) is -1.

ERRORS

ESRCH: No process or process group could be found with the specified which and who values.

EPERM: A non-privileged process attempted to change the priority of a process other than its own, or attempted to set a priority higher than its current priority.

EINVAL: An invalid value was specified for which or priority.

STANDARDS

The setpriority() and getpriority() functions are specified by POSIX.1-2001 and POSIX.1-2008.

HISTORY

The setpriority() and getpriority() calls first appeared in 4.2BSD.
