select(2) Manuel des appels système select(2)

NOM

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexage d'E/S synchrone

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);
Exigences des macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

pselect():

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

ATTENTION : select() ne peut surveiller que des descripteurs de fichiers dont le numéro est inférieur à FD_SETSIZE (1024) — une limite déraisonnablement basse pour de nombreuses applications modernes — et cette limitation ne changera pas. Toutes les applications modernes devraient plutôt utiliser poll(2) ou epoll(7), qui ne souffrent pas de cette limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, attendant qu'un ou plusieurs descripteurs de fichiers deviennent "prêts" pour une certaine classe d'opération d'E/S (par exemple, entrée possible). Un descripteur de fichier est considéré comme prêt si une opération d'E/S correspondante (par exemple, read(2), ou un write(2) suffisamment petit) peut être effectuée sans bloquer.

fd_set

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximum de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZE.

Ensembles de descripteurs de fichiers

Les principaux arguments de select() sont trois "ensembles" de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL si aucun descripteur de fichier ne doit être surveillé pour la classe d'événements correspondante.

Attention : Au retour, chaque ensemble de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement "prêts". Ainsi, si vous utilisez select() dans une boucle, les ensembles doivent être réinitialisés avant chaque appel.

Le contenu d'un ensemble de descripteurs de fichiers peut être manipulé à l'aide des macros suivantes :

FD_ZERO()
Cette macro efface (retire tous les descripteurs de fichiers de) set. Elle devrait être utilisée comme première étape pour initialiser un ensemble de descripteurs de fichiers.
FD_SET()
Cette macro ajoute le descripteur de fichier fd à set. L'ajout d'un descripteur de fichier déjà présent dans l'ensemble est une opération sans effet et ne génère pas d'erreur.
FD_CLR()
Cette macro retire le descripteur de fichier fd de set. Le retrait d'un descripteur de fichier absent de l'ensemble est une opération sans effet et ne génère pas d'erreur.
FD_ISSET()
select() modifie le contenu des ensembles conformément aux règles décrites ci-dessous. Après avoir appelé select(), la macro FD_ISSET() peut être utilisée pour tester si un descripteur de fichier est toujours présent dans un ensemble. FD_ISSET() renvoie une valeur non nulle si le descripteur de fichier fd est présent dans set, et zéro s'il ne l'est pas.

Arguments

Les arguments de select() sont les suivants :

readfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour voir s'ils sont prêts en lecture. Un descripteur de fichier est prêt en lecture si une opération de lecture ne bloquera pas ; en particulier, un descripteur de fichier est également prêt en cas de fin de fichier.
Après le retour de select(), readfds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en lecture.
writefds
Les descripteurs de fichiers de cet ensemble sont surveillés pour voir s'ils sont prêts en écriture. Un descripteur de fichier est prêt en écriture si une opération d'écriture ne bloquera pas. Cependant, même si un descripteur de fichier indique qu'il est accessible en écriture, une écriture importante peut toujours bloquer.
Après le retour de select(), writefds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en écriture.
exceptfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour des "conditions exceptionnelles". Pour des exemples de conditions exceptionnelles, voir la discussion sur POLLPRI dans poll(2).
Après le retour de select(), exceptfds sera vidé de tous les descripteurs de fichiers sauf ceux pour lesquels une condition exceptionnelle s'est produite.
nfds
Cet argument doit être défini sur le descripteur de fichier le plus élevé dans l'un des trois ensembles, plus 1. Les descripteurs de fichiers indiqués dans chaque ensemble sont vérifiés, jusqu'à cette limite (mais voir BUGS).
timeout
L'argument timeout est une structure timeval (montrée ci-dessous) qui spécifie l'intervalle pendant lequel select() devrait bloquer en attendant qu'un descripteur de fichier devienne prêt. L'appel bloquera jusqu'à ce que :
•
un descripteur de fichier devienne prêt ;
•
l'appel soit interrompu par un gestionnaire de signal ; ou
•
le délai d'attente expire.
Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle de blocage peut déborder d'une petite quantité.
Si les deux champs de la structure timeval sont à zéro, alors select() retourne immédiatement. (Ceci est utile pour le polling.)
Si timeout est spécifié comme NULL, select() bloque indéfiniment en attendant qu'un descripteur de fichier devienne prêt.

pselect()

L'appel système pselect() permet à une application d'attendre en toute sécurité jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit intercepté.

Le fonctionnement de select() et pselect() est identique, à l'exception de ces trois différences :

•
select() utilise un délai d'attente qui est un struct timeval (avec secondes et microsecondes), tandis que pselect() utilise un struct timespec (avec secondes et nanosecondes).
•
select() peut mettre à jour l'argument timeout pour indiquer combien de temps il restait. pselect() ne modifie pas cet argument.
•
select() n'a pas d'argument sigmask,

et'stranslate et se comporte comme pselect() appelé avec sigmask étant NULL.

sigmask est un pointeur vers un masque de signaux (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signaux courant par celui pointé par sigmask, effectue ensuite la fonction « select », puis restaure le masque de signaux d'origine. (Si sigmask est NULL, le masque de signaux n'est pas modifié pendant l'appel à pselect().)

À part la différence de précision de l'argument timeout, l'appel pselect() suivant :


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

est équivalent à l'exécution *atomique* des appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La raison d'être de pselect() est que si l'on veut attendre soit un signal, soit qu'un descripteur de fichier devienne prêt, un test atomique est nécessaire pour éviter les conditions de concurrence (race conditions). (Supposons que le gestionnaire de signaux définisse un drapeau global et revienne. Un test de ce drapeau global suivi d'un appel à select() pourrait alors rester bloqué indéfiniment si le signal arrive juste après le test mais juste avant l'appel. En revanche, pselect() permet de d'abord bloquer les signaux, de traiter les signaux qui sont arrivés, puis d'appeler pselect() avec le sigmask désiré, évitant ainsi la concurrence.)

Le timeout

L'argument timeout pour select() est une structure du type suivant :


struct timeval {
    time_t      tv_sec;         /* secondes */
    suseconds_t tv_usec;        /* microsecondes */
};

L'argument correspondant pour pselect() est une structure timespec(3).

Sous Linux, select() modifie timeout pour refléter le temps restant ; la plupart des autres implémentations ne le font pas. (POSIX autorise l'un ou l'autre comportement.) Cela pose des problèmes à la fois lorsque du code Linux qui lit timeout est porté sur d'autres systèmes d'exploitation, et lorsque du code est porté sur Linux qui réutilise un struct timeval pour plusieurs appels à select() dans une boucle sans le réinitialiser. Considérez timeout comme indéfini après le retour de select().

VALEUR DE RETOUR

En cas de succès, select() et pselect() retournent le nombre de descripteurs de fichiers contenus dans les trois ensembles de descripteurs retournés (c'est-à-dire le nombre total de bits définis dans readfds, writefds, exceptfds). La valeur de retour peut être zéro si le timeout a expiré avant que des descripteurs de fichiers ne deviennent prêts.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur ; les ensembles de descripteurs de fichiers ne sont pas modifiés, et timeout devient indéfini.

ERREURS

EBADF
Un descripteur de fichier invalide a été donné dans l'un des ensembles. (Peut-être un descripteur de fichier déjà fermé, ou sur lequel une erreur s'est produite.) Cependant, voir BUGS.
EINTR
Un signal a été capturé ; voir signal(7).
EINVAL
nfds est négatif ou dépasse la limite de ressources RLIMIT_NOFILE (voir getrlimit(2)).
EINVAL
La valeur contenue dans timeout est invalide.
ENOMEM
Impossible d'allouer de la mémoire pour les tables internes.

VERSIONS

Sur certains autres systèmes UNIX, select() peut échouer avec l'erreur EAGAIN si le système ne parvient pas à allouer des ressources internes au noyau, au lieu de ENOMEM comme le fait Linux. POSIX spécifie cette erreur pour poll(2), mais pas pour select(). Les programmes portables peuvent souhaiter vérifier EAGAIN et boucler, tout comme avec EINTR.

NORMES

POSIX.1-2024.

HISTORIQUE

Généralement portable depuis/vers des systèmes non-BSD supportant des clones de la couche socket BSD (y compris les variantes System V). Cependant, notez que la variante System V modifie généralement la variable timeout avant de retourner, tandis que la variante BSD ne le fait pas.

Avant cela, il était émulé dans glibc (mais voir BUGS).
fd_set
POSIX.1-2001.

NOTES

L'en-tête suivant fournit également le type fd_set : <sys/time.h>.

Un fd_set est un tampon de taille fixe. L'exécution de FD_CLR() ou FD_SET() avec une valeur de fd négative ou égale ou supérieure à FD_SETSIZE entraînera un comportement indéfini. De plus, POSIX exige que fd soit un descripteur de fichier valide.

Le fonctionnement de select() et pselect() n'est pas affecté par le drapeau O_NONBLOCK.

L'astuce du pipe auto-référentiel

Sur les systèmes qui n'ont pas pselect(), un piégeage fiable (et plus portable) de signaux peut être réalisé en utilisant l'astuce du pipe auto-référentiel. Dans cette technique, un gestionnaire de signaux écrit un octet dans un pipe dont l'autre extrémité est surveillée par select() dans le programme principal. (Pour éviter un blocage potentiel lors de l'écriture dans un pipe plein ou de la lecture d'un pipe vide, des E/S non bloquantes sont utilisées lors de la lecture et de l'écriture dans le pipe.)

Émulation de usleep(3)

Avant l'avènement de usleep(3), certains codes utilisaient un appel à select() avec les trois ensembles vides, nfds à zéro, et un timeout non NULL comme moyen relativement portable de dormir avec une précision sub-seconde.

Correspondance entre les notifications de select() et poll()

Dans le code source du noyau Linux, on trouve les définitions suivantes qui montrent la correspondance entre les notifications de condition lisible, accessible en écriture et exceptionnelle de select() et les notifications d'événements fournies par poll(2) et epoll(7) :


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Prêt pour lecture */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Prêt pour écriture */
#define POLLEX_SET  (EPOLLPRI)
                   /* Condition exceptionnelle */

Applications multithreadées

Si un descripteur de fichier surveillé par select() est fermé dans un autre thread, le résultat est indéterminé. Sur certains systèmes UNIX, select() se débloque et retourne, indiquant que le descripteur de fichier est prêt (une opération d'E/S ultérieure échouera probablement avec une erreur, à moins qu'un autre processus ne rouvre le descripteur de fichier entre le moment où select() a retourné et le moment où l'opération d'E/S est effectuée). Sous Linux (et certains autres systèmes), la fermeture du descripteur de fichier dans un autre thread n'a aucun effet sur select(). En résumé, toute application qui dépend d'un comportement particulier dans ce scénario doit être considérée comme défectueuse.

Différences bibliothèque C/noyau

Le noyau Linux autorise des ensembles de descripteurs de fichiers de taille arbitraire, déterminant la longueur des ensembles à vérifier à partir de la valeur de nfds. Cependant, dans l'implémentation glibc, le type fd_set est de taille fixe. Voir aussi BUGS.

L'interface pselect() décrite dans cette page est implémentée par glibc. L'appel système Linux sous-jacent est nommé pselect6(). Cet appel système a un comportement légèrement différent de la fonction wrapper glibc.

L'appel système Linux pselect6() modifie son argument timeout. Cependant, la fonction wrapper glibc masque ce comportement en utilisant une variable locale pour l'argument timeout qui est passée à l'appel système. Ainsi, la fonction glibc pselect() ne modifie pas son argument timeout ; c'est le comportement requis par POSIX.1-2001.

Le dernier argument de l'appel système pselect6() n'est pas un pointeur sigset_t *, mais est plutôt une structure de la forme :


struct {
    const kernel_sigset_t *ss;   /* Pointeur vers l'ensemble de signaux */
    size_t ss_len;               /* Taille (en octets) de l'objet
                                    pointé par 'ss' */
};

Cela permet à l'appel système d'obtenir à la fois un pointeur vers l'ensemble de signaux et sa taille, tout en tenant compte du fait que la plupart des architectures supportent un maximum de 6 arguments pour un appel système. Voir sigprocmask(2) pour une discussion sur la différence entre la notion de noyau et de libc de l'ensemble de signaux.

Détails historiques glibc

glibc 2.0 a fourni une version incorrecte de pselect() qui ne prenait pas d'argument sigmask.

De glibc 2.1 à glibc 2.2.1, il fallait définir _GNU_SOURCE pour obtenir la déclaration de ps

BOGUES

POSIX autorise une implémentation à définir une limite supérieure, annoncée via la constante FD_SETSIZE, sur la plage des descripteurs de fichiers qui peuvent être spécifiés dans un ensemble de descripteurs de fichiers. Le noyau Linux n'impose aucune limite fixe, mais l'implémentation glibc fait de fd_set un type de taille fixe, avec FD_SETSIZE défini à 1024, et les macros FD_*() opérant selon cette limite. Pour surveiller les descripteurs de fichiers supérieurs à 1023, utilisez poll(2) ou epoll(7) à la place.

L'implémentation des arguments fd_set en tant qu'arguments valeur-résultat est une erreur de conception qui est évitée dans poll(2) et epoll(7).

Selon POSIX, select() doit vérifier tous les descripteurs de fichiers spécifiés dans les trois ensembles de descripteurs de fichiers, jusqu'à la limite nfds-1. Cependant, l'implémentation actuelle ignore tout descripteur de fichier dans ces ensembles qui est supérieur au numéro maximum de descripteur de fichier actuellement ouvert par le processus. Selon POSIX, tout descripteur de fichier spécifié dans l'un des ensembles devrait entraîner l'erreur EBADF.

À partir de glibc 2.1, glibc a fourni une émulation de pselect() qui était implémentée à l'aide de sigprocmask(2) et de select(). Cette implémentation restait vulnérable à la condition de course même que pselect() était conçu pour empêcher. Les versions modernes de glibc utilisent l'appel système (sans compétition) pselect() sur les noyaux où il est fourni.

Sous Linux, select() peut signaler un descripteur de fichier de socket comme « prêt pour lecture », alors qu'une lecture ultérieure bloque néanmoins. Cela pourrait par exemple se produire lorsque des données sont arrivées mais qu'après examen, elles ont une somme de contrôle incorrecte et sont rejetées. Il peut y avoir d'autres circonstances dans lesquelles un descripteur de fichier est faussement signalé comme prêt. Il peut donc être plus sûr d'utiliser O_NONBLOCK sur les sockets qui ne devraient pas bloquer.

Sous Linux, select() modifie également timeout si l'appel est interrompu par un gestionnaire de signaux (c'est-à-dire, le retour d'erreur EINTR). Ceci n'est pas autorisé par POSIX.1. L'appel système Linux pselect() a le même comportement, mais l'enveloppe glibc masque ce comportement en copiant en interne timeout dans une variable locale et en transmettant cette variable à l'appel système.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Surveille stdin (fd 0) pour voir quand il y a une entrée.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Attend jusqu'à cinq secondes.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Ne vous fiez pas à la valeur de tv maintenant ! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Des données sont disponibles maintenant.\n");
        /* FD_ISSET(0, &rfds) sera vrai.  */
    else
        printf("Aucune donnée dans les cinq secondes.\n");
    exit(EXIT_SUCCESS);
}
