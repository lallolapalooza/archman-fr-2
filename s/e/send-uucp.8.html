NOM

send-uucp - Envoyer des articles Usenet via UUCP

SYNTAXE

send-uucp [site ...]

DESCRIPTION

Le programme send-uucp traite les fichiers batch créés par innd(8) pour envoyer des articles Usenet aux sites UUCP. Il lit un fichier de configuration pour contrôler son comportement avec différents sites. Normalement, il est exécuté périodiquement via cron pour rassembler des lots et les envoyer aux sites UUCP distants.

Il permet de réduire l'utilisation de la bande passante et d'envoyer des nouvelles à des sites UUCP distants qui ne peuvent pas recevoir de flux en temps réel (par exemple, s'ils sont connectés via une ligne commutée).

OPTIONS

Tous les arguments fournis au programme sont interprétés comme une liste de sites spécifiés dans send-uucp.cf pour lesquels des lots doivent être générés. Si aucun argument n'est fourni, des lots seront générés pour tous les sites listés dans ce fichier de configuration.

CONFIGURATION

Les sites auxquels les articles doivent être envoyés doivent être configurés dans le fichier de configuration send-uucp.cf situé dans pathetc tel que défini dans inn.conf. Chaque site est spécifié sur une ligne de la forme :

site[:hôte[:entonnoir]] [compresseur [taille_max [temps_lot]]]
site
Le nom du site de nouvelles configuré. Il doit correspondre à un nom de site de newsfeeds(5).
hôte
Le nom d'hôte UUCP auquel les lots doivent être envoyés pour ce site. Si omis, le nom du site de nouvelles sera utilisé comme nom d'hôte UUCP.
entonnoir
Dans le cas d'un site configuré comme un entonnoir, send-uucp doit vider le canal (ou l'exploder) utilisé comme cible de l'entonnoir au lieu de vider le site. C'est ainsi que l'on indique à send-uucp le nom du canal ou de l'exploder à vider pour ce site. S'il n'est pas spécifié, il vide par défaut le site.
compresseur
La méthode de compression à utiliser pour les lots. Cela devrait être l'une des options "bzip2", "compress", "gzip" ou "none". Les arguments pour la commande de compression peuvent être spécifiés en utilisant "_" à la place des espaces. Par exemple, "gzip_-9". La valeur par défaut est "gzip".
taille_max
La taille maximale en octets d'un seul lot *avant* compression. La valeur par défaut est de 500000 octets.
temps_lot
Une liste d'heures séparées par des virgules pendant lesquelles des lots doivent être générés pour un site donné. Lorsque send-uucp s'exécute, un site ne sera traité que si l'heure actuelle correspond à l'une des heures de temps_lot. Par défaut, il n'y a pas de limitation sur le moment de la génération des lots.

Les champs sont séparés par des espaces et seul le nom du site doit être spécifié, les valeurs par défaut étant utilisées pour les valeurs non spécifiées. Si le premier caractère d'une ligne est un signe dièse ("#"), le reste de la ligne est ignoré.

EXEMPLE

Voici un exemple de fichier de configuration send-uucp.cf :

zoetermeer      gzip            1048576         5,18,22
hoofddorp       gzip            1048576         5,18,22
pa3ebv          gzip            1048576         5,18,22
drinkel         bzip2           1048576         5,6,18,20,22,0,2
manhole         compress        1048576         5,18,22
owl             compress        1048576
able
pern::MYFUNNEL!

Ceci définit huit sites UUCP. Les trois premiers et les deux derniers utilisent la compression "gzip", le quatrième site ("drinkel") utilise "bzip2" et les sites restants ("manhole" et "owl") utilisent "compress". Les six premiers utilisent une taille de lot de 1 Mo, et les deux derniers sites ("able" et "pern") utilisent la valeur par défaut de 500 000 octets. Les sites "zoetermeer", "hoofddorp", "pa3ebv" et "manhole" n'auront des lots générés que pendant les heures 05:00, 18:00 et 22:00, et le site "drinkel" n'aura des lots générés que pendant ces heures ainsi qu'à 06:00, 20:00, 00:00 et 02:00. Il n'y a pas de restrictions sur le moment de la génération des lots pour "owl", "able" et "pern".

Le site "pern" est configuré comme un entonnoir vers "MYFUNNEL!". send-uucp exécutera "ctlinnd flush MYFUNNEL!" au lieu de "ctlinnd flush pern".

Quant au fichier newsfeeds, les drapeaux habituels utilisés pour un flux UUCP sont "Tf,Wnb". Voici une entrée typique pour "zoetermeer", où la mise en lot est maintenue entre 4 Ko et 1 Ko :

zoetermeer\
    :*,!junk,!control,!control.*/!foo\
    :Tf,Wnb,B4096/1024:

MISE EN PLACE DES FLUX UUCP

Voici les étapes à suivre pour mettre en place un flux UUCP sur SSH entre deux serveurs de nouvelles, en utilisant l'implémentation UUCP disponible dans Debian sous le nom de paquet "uucp". Les mécanismes décrits ci-dessous devraient être transposables si vous utilisez une autre implémentation UUCP. (Et si c'est le cas, veuillez informer les mainteneurs d'INN sur la manière de configurer un flux avec une autre implémentation UUCP, afin qu'il puisse être ajouté à cette documentation.)

1.
Avant tout, assurez-vous que rnews est correctement installé avec le bit setuid sur "news", appartenant au groupe "uucp", et avec le mode 4550. Cela permettra au sous-système UUCP d'exécuter rnews pour traiter les lots UUCP d'articles de nouvelles. L'option "configure" --enable-uucp-rnews s'en charge lors de l'installation d'INN. Sinon, vous devrez manuellement changer les permissions sur rnews.
2.
Installez le paquet "uucp". Il fournira notamment uucico(8) et uux(1).
3.
Configurez dans /etc/uucp/Poll les serveurs de nouvelles distants à interroger, et les heures auxquelles ils doivent être interrogés. Par exemple, si vous envoyez des lots UUCP à "news.server.to.feed" toutes les 4 heures, vous pouvez utiliser : 
schedule news.server.to.feed 00
poll news.server.to.feed 00 04 08 12 16 20

Si l'envoi est horaire, listez simplement toutes les heures.

4.
Configurez dans /etc/uucp/call les identifiants (noms d'utilisateur et mots de passe) à utiliser lors de l'authentification auprès des serveurs de nouvelles distants, un par ligne. Par exemple :

prepares and sends news batches using UUCP

SYNOPSIS

send-uucp [options]

DESCRIPTION

The send-uucp utility prepares outgoing news batches for transmission to remote news servers using UUCP. It reads configuration files to determine which servers to contact, the method of compression, and the batching parameters.

OPTIONS

The send-uucp utility does not accept any command-line options. Its behavior is controlled entirely by configuration files.

CONFIGURATION

The primary configuration file for send-uucp is send-uucp.cf, typically located in pathetc. This file specifies which remote sites to send news to, the compression method to use, and the batch sizes.

Another important configuration file is newsfeeds, which defines the distribution of news articles to various servers. This file is used by the INN system to determine which outgoing batches should be generated.

EXAMPLE

A typical entry in send-uucp.cf might look like this:

news.server.to.feed   bzip2      1048576   3,7,11,15,19,23

This entry indicates that news should be sent to news.server.to.feed using bzip2 compression, with a maximum batch size of 1048576 bytes, and that batches should be generated for article numbers ending in 3, 7, 11, 15, 19, or 23.

SETTING UP UUCP FEEDS

This section details the steps required to configure UUCP feeds for receiving news from remote servers.

7.
Configure the /etc/uucp/uucphosts file to specify the remote servers from which you want to receive news. A typical entry is:
news.server.to.feed
8.
Configure in /etc/uucp/poll which remote news servers connect to the local news server. A typical entry to set an SSH connection is the following one where pathbin should be changed to the real path to rnews: 
system news.server.to.feed
call-login *
call-password *
commands <pathbin>/rnews
time any
chat "" \d\d\r\c ogin: \d\L word: \P
chat-timeout 120
protocol i
port ssh.news.server.to.feed
9.
Configure in /etc/uucp/port how to connect to remote news servers. A typical entry to set an SSH connection using a private key is: 
port ssh.news.server.to.feed
type pipe
command /bin/ssh -a -x -q -i <key> -l uucp news.server.to.feed
reliable true
protocol etyig

where key is the path to the private key to use for the SSH connection, like for instance /var/spool/uucp/.ssh/id_private_key.

10.
Make sure the administrators of remote news servers have added the public key related to id_private_key for connections to the "uucp" user of the remote news servers.
11.
Supposing the home directory of the "uucp" user is /var/spool/uucp, you need to configure the SSH keys in the .ssh subdirectory. First, add the public keys of all remote news servers in authorized_keys. A typical entry is the following one, which should be in 1 line (it is wrapped here for a proper display in man page): 
no-port-forwarding,no-X11-forwarding,no-agent-forwarding,
command="/usr/sbin/uucico -l",from="news.server.to.feed"
ssh-rsa xxxyyyzzz uucp@news.server.to.feed

This ensures the SSH connection will not be used for another goal than exchanging UUCP batches.

12.
Make sure id_private_key is correctly present, as set in /etc/uucp/port, and only readable by the "uucp" user.
13.
Manually run as the "uucp" user the command set in /etc/uucp/port so as to create the known_hosts file to make sure the SSH setting is fine. 
/bin/ssh -a -x -q -i <key> -l uucp news.server.to.feed
14.
Parameterize the feed to send to the remote servers. A typical entry in newsfeeds to generate batches in pathoutgoing is: 
news.server.to.feed/pathname:*:Tf,Wnb,B4096/1024:
15.
Set up the compression method, batch sizes and when to generate them in send-uucp.cf located in pathetc, as described earlier in this documentation. 
news.server.to.feed   bzip2      1048576   3,7,11,15,19,23
16.
Check that send-uucp is started hourly in crontab by the "news" user. For instance in /etc/cron.d/inn2: 
52 * * * * news <pathbin>/send-uucp

It can be useful to set up a different launch time than your remote servers. For instance, if you generate batches every hour at minute 52, a remote peer may do the same at minute 22. This way, you may exchange articles more frequently, depending on when each other connects.

17.
Check that UUCP programs are automatically started in crontab (usually, uudemon.hr is called hourly in /etc/cron.d/uucp to poll remote news servers, and uudemon.day daily in /etc/cron.daily/uucp).

Like for send-uucp, adjust the launch time to maximize the number and the freshness of batches to exchanges.

18.
Check the logs in /var/log/uucp to ensure everything works fine, both polling and sending.

You will see that send-uucp prepares rnews batches named like D.0I8Y, that are queued by uux. When uucico is afterwards started from cron to transfer these batches, uucico takes available batches from the remote sites at the same time. These received batches are then processed by uuxqt which calls rnews to inject them.

That's all!

FILES

pathbin/send-uucp
The Perl script itself used to create news batches from the outgoing files.
pathetc/send-uucp.cf
The configuration file which specifies a list of sites to be processed.
pathlog/send-uucp.log
The log file used if the syslog facility is not available.
