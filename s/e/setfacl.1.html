SETFACL(1) Listes de contrôle d'accès SETFACL(1)

NOM

setfacl - définir les listes de contrôle d'accès des fichiers

SYNTAXE

setfacl [-bkndRLPvh] [{-m|-x} acl_spec] [{-M|-X} acl_file] fichier ...

setfacl --restore={fichier|-}

DESCRIPTION

Cet utilitaire définit les Listes de Contrôle d'Accès (ACL) des fichiers et des répertoires. Sur la ligne de commande, une séquence de commandes est suivie d'une séquence de fichiers (qui à son tour peut être suivie d'une autre séquence de commandes, ...).

Les options -m et -x attendent une ACL sur la ligne de commande. Plusieurs entrées ACL sont séparées par des virgules (`,'). Les options -M et -X lisent une ACL à partir d'un fichier ou de l'entrée standard. Le format des entrées ACL est décrit dans la Section ENTRÉES ACL.

Les options --set et --set-file définissent l'ACL d'un fichier ou d'un répertoire. L'ACL précédente est remplacée. Les entrées ACL pour cette opération doivent inclure les permissions.

Les options -m (--modify) et -M (--modify-file) modifient l'ACL d'un fichier ou d'un répertoire. Les entrées ACL pour cette opération doivent inclure les permissions.

Les options -x (--remove) et -X (--remove-file) suppriment les entrées ACL. Ce n'est pas une erreur de supprimer une entrée qui n'existe pas. Seules les entrées ACL sans le champ perms sont acceptées comme paramètres, sauf si POSIXLY_CORRECT est défini.

Lors de la lecture à partir de fichiers à l'aide des options -M et -X, setfacl accepte la sortie que getfacl produit. Il y a au plus une entrée ACL par ligne. Après un signe dièse (`#'), tout ce qui suit jusqu'à la fin de la ligne est traité comme un commentaire.

Si setfacl est utilisé sur un système de fichiers qui ne prend pas en charge les ACL, setfacl opère sur les bits de permission du mode de fichier. Si l'ACL ne rentre pas complètement dans les bits de permission, setfacl modifie les bits de permission du mode de fichier pour refléter l'ACL aussi près que possible, écrit un message d'erreur sur la sortie standard et retourne avec un statut de sortie supérieur à 0.

PERMISSIONS

Le propriétaire du fichier et les processus capables de CAP_FOWNER ont le droit de modifier les ACL d'un fichier. Ceci est analogue aux permissions requises pour accéder au mode de fichier. (Sur les systèmes Linux actuels, root est le seul utilisateur disposant de la capacité CAP_FOWNER.)

OPTIONS

-b, --remove-all
Supprime toutes les entrées ACL étendues. Les entrées ACL de base du propriétaire, du groupe et des autres sont conservées.
-k, --remove-default
Supprime l'ACL par défaut. Si aucune ACL par défaut n'existe, aucun avertissement n'est émis.
-n, --no-mask
Ne pas recalculer le masque des droits effectifs. Le comportement par défaut de setfacl est de recalculer l'entrée du masque ACL, sauf si une entrée de masque a été explicitement donnée. L'entrée masque est définie comme l'union de toutes les permissions du groupe propriétaire, et de toutes les entrées d'utilisateur et de groupe nommées. (Ce sont exactement les entrées affectées par l'entrée masque).
--mask
Recalculer le masque des droits effectifs, même si une entrée de masque ACL a été explicitement donnée. (Voir l'option -n).
-d, --default
Toutes les opérations s'appliquent à l'ACL par défaut. Les entrées ACL régulières dans l'ensemble d'entrée sont promues en entrées ACL par défaut. Les entrées ACL par défaut dans l'ensemble d'entrée sont ignorées. (Un avertissement est émis si cela se produit).
--restore={fichier|-}
Restaure une sauvegarde de permissions créée par `getfacl -R' ou similaire. Toutes les permissions d'une sous-arborescence complète de répertoires sont restaurées à l'aide de ce mécanisme. Si l'entrée contient des commentaires de propriétaire ou de groupe, setfacl tente de restaurer le propriétaire et le groupe propriétaire. Si l'entrée contient des commentaires de drapeaux (qui définissent les bits setuid, setgid et sticky), setfacl définit ces trois bits en conséquence ; sinon, il les efface. Cette option ne peut pas être mélangée avec d'autres options sauf `--test'. Si le fichier spécifié est '-', il sera lu depuis l'entrée standard.
--test
Mode test. Au lieu de modifier les ACL des fichiers, les ACL résultantes sont listées.
-R, --recursive
Applique les opérations à tous les fichiers et répertoires récursivement. Cette option ne peut pas être mélangée avec `--restore'.
-L, --logical
Parcours logique, suit les liens symboliques vers les répertoires. Le comportement par défaut est de suivre les arguments de liens symboliques, et d'ignorer les liens symboliques rencontrés dans les sous-répertoires. N'est effectif qu'en combinaison avec -R. Cette option ne peut pas être mélangée avec `--restore'.
-P, --physical
Parcours physique, ne suit pas les liens symboliques vers les répertoires. Ceci ignore également les arguments de liens symboliques. N'est effectif qu'en combinaison avec -R. Cette option ne peut pas être mélangée avec `--restore'.
-v, --version
Affiche la version de setfacl et quitte.
-h, --help
Affiche une aide expliquant les options de la ligne de commande.
--
Fin des options de la ligne de commande. Tous les paramètres restants sont interprétés comme des noms de fichiers, même s'ils commencent par un tiret.
-
Si le paramètre de nom de fichier est un simple tiret, setfacl lit une liste de fichiers depuis l'entrée standard.

ENTRÉES ACL

L'utilitaire setfacl reconnaît les formats d'entrée ACL suivants (espaces insérés pour plus de clarté) :

[d[efault]:] [u[ser]:]uid [:perms]
Permissions d'un utilisateur nommé. Permissions du propriétaire du fichier si uid est vide.
[d[efault]:] g[roup]:gid [:perms]
Permissions d'un groupe nommé. Permissions du groupe propriétaire si gid est vide.
[d[efault]:] m[ask][:] [:perms]
Masque des droits effectifs
[d[efault]:] o[ther][:] [:perms]
Permissions des autres.

Les espaces blancs entre les caractères délimiteurs et les caractères non délimiteurs sont ignorés.

Les entrées ACL complètes incluant les permissions sont utilisées dans les opérations de modification et de définition. (options -m, -M, --set et --set-file). Les entrées sans le champ perms sont utilisées pour la suppression des entrées (options -x et -X).

Pour uid et gid, vous pouvez spécifier soit un nom, soit un numéro. Les caractères littéraux peuvent être spécifiés avec une barre oblique inverse suivie des 3 chiffres octaux correspondant au code ASCII du caractère (par exemple, \101 pour 'A'). Si le nom contient une barre oblique inverse littérale suivie de 3 chiffres, la barre oblique inverse doit être échappée (c'est-à-dire \\).

Le champ perms est une combinaison de caractères qui indiquent les permissions de lecture (r), d'écriture (w), d'exécution (x). Les tirets dans le champ perms (-) sont ignorés. Le caractère X représente la permission d'exécution si le fichier est un répertoire ou possède déjà la permission d'exécution pour un utilisateur. Alternativement, le champ perms peut définir les permissions numériquement, comme une combinaison bit à bit de lecture (4), d'écriture (2) et d'exécution (1). Les champs perms nuls ou ne contenant que des tirets indiquent aucune permission.

ENTRÉES CRÉÉES AUTOMATIQUEMENT

Initialement, les fichiers et répertoires contiennent uniquement les trois entrées ACL de base pour le propriétaire, le groupe et les autres. Il existe des règles qui doivent être satisfaites pour qu'une ACL soit valide :

  • Les trois entrées de base ne peuvent pas être supprimées. Il doit y avoir exactement une entrée de chacun de ces types d'entrée de base.
  • Dès qu'une ACL contient des entrées d'utilisateur nommé ou des objets de groupe nommé, elle doit également contenir un masque de droits effectifs.
  • Dès qu'une ACL contient des entrées ACL par défaut, les trois entrées de base de l'ACL par défaut (propriétaire par défaut, groupe par défaut et autres par défaut) doivent également exister.
  • Dès qu'une ACL par défaut contient des entrées d'utilisateur nommé ou des objets de groupe nommé, elle doit également contenir un masque de droits effectifs par défaut.

EXEMPLES

Accorder à un utilisateur supplémentaire un accès en lecture

setfacl -m u:lisa:r fichier

Révoquer l'accès en écriture à tous les groupes et à tous les utilisateurs nommés (en utilisant le masque des droits effectifs)

setfacl -m m::rx fichier

Supprimer une entrée de groupe nommée de l'ACL d'un fichier

setfacl -x g:staff fichier

Copier l'ACL d'un fichier vers un autre

getfacl fichier1 | setfacl --set-file=- fichier2

Copier l'ACL d'accès dans l'ACL par défaut

getfacl --access rep | setfacl -d -M- rep

CONFORMITÉ AU PROJET DE NORME POSIX 1003.1e 17

Si la variable d'environnement POSIXLY_CORRECT est définie, le comportement par défaut de setfacl change comme suit : Toutes les options non standard sont désactivées. Le préfixe ``default:'' est désactivé. Les options -x et -X acceptent également des champs de permissions (et les ignorent).
