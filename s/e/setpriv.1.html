SETPRIV(1) Commandes utilisateur SETPRIV(1)

NOM

setpriv - exécute un programme avec des paramètres de privilèges Linux différents

SYNTAXE

setpriv [options] programme [arguments]

DESCRIPTION

Définit ou interroge divers paramètres de privilèges Linux qui sont hérités lors de l'execve(2).

Comparé à su(1) et runuser(1), setpriv n'utilise ni PAM, ni ne demande de mot de passe. C'est un simple wrapper non-set-user-ID autour de l'execve(2), et peut être utilisé pour abandonner des privilèges de la même manière que setuidgid(8) de daemontools, chpst(8) de runit, ou des outils similaires fournis par d'autres gestionnaires de services.

OPTIONS

--clear-groups

Efface les groupes supplémentaires.

-d, --dump

Affiche l'état actuel des privilèges. Cette option peut être spécifiée plus d'une fois pour montrer des informations supplémentaires, principalement inutiles. Incompatible avec toutes les autres options.

--groups groupe...

Définit les groupes supplémentaires. L'argument est une liste séparée par des virgules de GID ou de noms.

--inh-caps (+|-)cap..., --ambient-caps (+|-)cap..., --bounding-set (+|-)cap...

Définit les capacités héritables, les capacités ambiantes ou l'ensemble des capacités limites. Voir capabilities(7). L'argument est une liste séparée par des virgules d'entrées +cap et -cap, qui ajoutent ou suppriment une entrée respectivement. cap peut être soit un nom lisible par l'homme tel qu'il apparaît dans capabilities(7) sans le préfixe cap_, soit du format cap_N, où N est l'indice interne de capacité utilisé par Linux. +all et -all peuvent être utilisés pour ajouter ou supprimer toutes les capacités.

L'ensemble des capacités commence comme l'ensemble héritable actuel pour --inh-caps, l'ensemble ambiant actuel pour --ambient-caps et l'ensemble limite actuel pour --bounding-set.

Notez les restrictions suivantes (détaillées dans capabilities(7)) concernant les modifications de ces ensembles de capacités :

•Une capacité ne peut être ajoutée à l'ensemble héritable que si elle est actuellement présente dans l'ensemble limite.
•Une capacité ne peut être ajoutée à l'ensemble ambiant que si elle est actuellement présente à la fois dans les ensembles autorisé et héritable.
•Nonobstant la syntaxe offerte par setpriv, le noyau n'autorise pas l'ajout de capacités à l'ensemble limite.

Si vous supprimez une capacité de l'ensemble limite sans la supprimer également de l'ensemble héritable, vous risquez de vous retrouver confus. Ne faites pas cela.

--keep-groups

Conserve les groupes supplémentaires. Utile uniquement en conjonction avec --rgid, --egid, ou --regid.

--init-groups

Initialise les groupes supplémentaires en utilisant initgroups3. Utile uniquement en conjonction avec --ruid ou --reuid.

--list-caps

Liste toutes les capacités connues. Cette option doit être spécifiée seule.

--no-new-privs

Définit le bit no_new_privs. Avec ce bit défini, execve(2) n'accordera pas de nouveaux privilèges. Par exemple, les bits set-user-ID et set-group-ID ainsi que les capacités de fichier seront désactivés. (L'exécution de binaires avec ces bits définis fonctionnera toujours, mais ils n'obtiendront pas de privilèges. Certains LSM, notamment AppArmor, peuvent entraîner des échecs lors de l'exécution de certains programmes.) Ce bit est hérité par les processus enfants et ne peut être désactivé. Voir prctl(2) et Documentation/prctl/no_new_privs.txt dans les sources du noyau Linux.

Le bit no_new_privs est pris en charge depuis Linux 3.5.

--rgid gid, --egid gid, --regid gid

Définit les GID réels, effectifs, ou les deux. L'argument gid peut être donné sous forme de nom de groupe textuel.

Par sécurité, vous devez spécifier l'une des options --clear-groups, --groups, --keep-groups, ou --init-groups si vous définissez un gid primaire.

--ruid uid, --euid uid, --reuid uid

Définit les UID réels, effectifs, ou les deux. L'argument uid peut être donné sous forme de nom de connexion textuel.

La définition d'un uid ou d'un gid ne modifie pas les capacités, bien que l'appel exec final puisse les modifier. Cela signifie que, si vous êtes root, vous voudrez probablement faire quelque chose comme :

setpriv --reuid=1000 --regid=1000 --inh-caps=-all

--securebits (+|-)securebit...

Définit ou efface les securebits. L'argument est une liste séparée par des virgules. Les securebits valides sont noroot, noroot_locked, no_setuid_fixup, no_setuid_fixup_locked, et keep_caps_locked. keep_caps est effacé par l'execve(2) et n'est donc pas autorisé.

--pdeathsig keep|clear|<signal>

Conserve, efface ou définit le signal de mort du parent. Certains LSM, notamment SELinux et AppArmor, effacent le signal lorsque les identifiants du processus changent. Utiliser --pdeathsig keep restaurera le signal de mort du parent après avoir changé les identifiants pour remédier à cette situation.

--ptracer pid|any|none

Lorsque le mode ptrace restreint de Yama est en vigueur (c'est-à-dire lorsque /proc/sys/kernel/yama/ptrace_scope est défini à 1), autorise le débogage via ptrace(2) par le processus avec l'ID spécifié, ou par n'importe quel processus, ou par aucun processus. Voir PR_SET_PTRACER(2const). (Notez que cela n'est pas hérité par les processus enfants, bien qu'il soit préservé lors des execve(2).) Cette option n'a aucun effet lorsque Yama n'est pas activé ou est dans un mode autre que ptrace restreint.

--selinux-label label

Demande une transition SELinux particulière (en utilisant une transition sur exec, pas dyntrans). Cela échouera et provoquera l'abandon de setpriv si SELinux n'est pas utilisé, et la transition peut être ignorée ou provoquer l'échec de l'execve(2) à la discrétion de SELinux. (En particulier, cela fonctionnera probablement mal en conjonction avec no_new_privs.) Ceci est similaire à runcon(1).

--apparmor-profile profil

Demande un profil AppArmor particulier (en utilisant une transition sur exec). Cela échouera et provoquera l'abandon de setpriv si AppArmor n'est pas utilisé, et la transition peut être ignorée ou provoquer l'échec de l'execve(2) à la discrétion d'AppArmor.

--landlock-access accès

Active les restrictions Landlock pour un ensemble spécifique d'accès système. Pour autoriser des sous-ensembles spécifiques d'accès, utilisez --landlock-rule.

Bloque tout accès au système de fichiers :

setpriv --landlock-access fs

Bloque toutes les suppressions de fichiers et créations de répertoires :

setpriv --landlock-access fs:remove-file,make-dir

Pour un ensemble complet de catégories d'accès prises en charge, utilisez setpriv --help.

--landlock-rule règle

Autorise un accès spécifique parmi les catégories bloquées par --landlock-access.

La syntaxe est la suivante :

--landlock-rule $ruletype:$accès:$argumentrègle

Par exemple, accorder l'accès en lecture de fichiers à tout ce qui se trouve sous /boot :

--landlock-rule path-beneath:read-file:/boot

--seccomp-filter fichier

Charge le code de filtre seccomp BPF brut à partir d'un fichier.

Les filtres peuvent par exemple être créés avec enosys.

--reset-env

Efface toutes les variables d'environnement à l'exception de TERM ; initialise les variables d'environnement HOME, SHELL, USER, LOGNAME selon l'entrée passwd de l'utilisateur ; définit PATH

à /usr/local/bin:/bin:/usr/bin pour un utilisateur ordinaire et à /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin pour root.

La variable d'environnement PATH peut être différente sur les systèmes où /bin et /sbin sont fusionnés dans /usr. La variable d'environnement SHELL est définie par défaut à /bin/sh si aucune n'est spécifiée dans l'entrée passwd de l'utilisateur.

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

NOTES

Si l'application d'une option spécifiée échoue, program ne sera pas exécuté et setpriv retournera avec le statut de sortie 127.

Soyez prudent avec cet outil — il peut avoir des conséquences inattendues sur la sécurité. Par exemple, définir no_new_privs et ensuite exécuter un programme qui est confiné par SELinux (comme le ferait cet outil) peut empêcher les restrictions SELinux de prendre effet.

EXEMPLES

Si vous recherchez un comportement similaire à su(1)/runuser(1), ou sudo(8) (sans l'option -g), essayez quelque chose comme :

setpriv --reuid=1000 --regid=1000 --init-groups

Si vous voulez imiter setuid(8) de daemontools, essayez :

setpriv --reuid=1000 --regid=1000 --clear-groups
