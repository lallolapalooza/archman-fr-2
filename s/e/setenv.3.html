setenv(3) Manuel des fonctions de bibliothèque setenv(3)

NOM

setenv - modifier ou ajouter une variable d'environnement

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdlib.h>
int setenv(const char *name, const char *value, int overwrite);
int unsetenv(const char *name);
Conditions de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

setenv(), unsetenv():

    _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPTION

La fonction setenv() ajoute la variable name à l'environnement avec la valeur value, si name n'existe pas déjà. Si name existe déjà dans l'environnement, alors sa valeur est changée en value si overwrite est non nul ; si overwrite est nul, alors la valeur de name n'est pas modifiée (et setenv() renvoie un statut de succès). Cette fonction fait des copies des chaînes pointées par name et value (par opposition à putenv(3)).

La fonction unsetenv() supprime la variable name de l'environnement. Si name n'existe pas dans l'environnement, alors la fonction réussit et l'environnement n'est pas modifié.

VALEUR DE RETOUR

Les fonctions setenv() et unsetenv() retournent zéro en cas de succès, ou -1 en cas d'erreur, avec errno défini pour indiquer l'erreur.

ERREURS

EINVAL
name est NULL, pointe vers une chaîne de longueur 0, ou contient un caractère '='.
ENOMEM
Mémoire insuffisante pour ajouter une nouvelle variable à l'environnement.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
setenv (), unsetenv () Thread safety MT-Unsafe const:env

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001, 4.3BSD.

Avant glibc 2.2.2, unsetenv() était prototypé pour retourner void ; les versions plus récentes de glibc suivent le prototype conforme à POSIX.1 montré dans la SYNTAXE.

MISE EN GARDE

POSIX.1 ne requiert pas que setenv() ou unsetenv() soient réentrantes.

BOGUES

POSIX.1 spécifie que si name contient un caractère '=', alors setenv() devrait échouer avec l'erreur EINVAL ; cependant, les versions de glibc avant glibc 2.3.4 autorisaient un signe '=' dans name.

VOIR AUSSI

clearenv(3), getenv(3), putenv(3), environ(7)
