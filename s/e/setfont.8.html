SETFONT(8) Manuel de l'administrateur système SETFONT(8)

NOM

setfont - charger la police de l'écran console EGA/VGA

SYNTAXE

setfont [-O police+umap.orig] [-o police.orig] [-om cmap.orig] [-ou umap.orig] [-N] [police.new ...] [-m cmap] [-u umap] [-C console] [-hH] [-f] [-v] [-V]

DESCRIPTION

La commande setfont lit une police depuis le fichier police.new et la charge dans le générateur de caractères EGA/VGA, et éventuellement sortie la police précédente. Elle peut aussi charger diverses tables de mappage et sortir les versions précédentes.

Si aucun argument n'est donné (ou seulement l'option -N pour un nombre N), une police par défaut (8xN) est chargée (voir ci-dessous). On peut donner plusieurs petites polices, toutes contenant une table Unicode, et setfont les combinera et chargera l'union. Usage typique :

setfont
Charge une police par défaut.
setfont drdos8x16
Charge une police donnée (ici la police drdos 448 glyphes).
setfont cybercafe -u cybercafe
Charge une police donnée qui n'a pas de table de correspondance Unicode et en fournit une explicitement.
setfont LatArCyrHeb-19 -m 8859-2
Charge une police donnée (ici une police 512 glyphes combinant plusieurs jeux de caractères) et indique que son jeu de caractères local est ISO 8859-2.

Note : si une police a plus de 256 glyphes, seulement 8 couleurs sur 16 peuvent être utilisées simultanément. Cela peut dégrader la perception de la console (perte d'intensité et même de certaines couleurs).

FORMATS DE POLICE

Le format de police standard de Linux est la police PSF. Elle a un en-tête décrivant les propriétés de la police comme la taille des caractères, suivie des bitmaps des glyphes, optionnellement suivie d'une table de mappage Unicode donnant la valeur Unicode pour chaque glyphe. Plusieurs autres formats de police (obsolètes) sont reconnus. Si le fichier d'entrée est au format "code page" (probablement avec suffixe .cp), contenant trois polices de tailles par exemple 8x8, 8x14 et 8x16, alors une des options -8 ou -14 ou -16 doit être utilisée pour en sélectionner une. Les fichiers de police bruts sont des fichiers binaires de taille 256*N octets, contenant des images de bits pour chacun des 256 caractères, un octet par ligne de balayage, et N octets par caractère (0 < N <= 32). La plupart des polices ont une largeur de 8 bits, mais avec le périphérique framebuffer (fb) d'autres largeurs peuvent être utilisées.

HAUTEUR DE POLICE

Le programme setfont n'a pas de connaissance intégrée des modes vidéo EGA/VGA, mais demande simplement au noyau de charger la ROM de caractères de la carte vidéo avec certaines bitmaps. Cependant, depuis Linux 1.3.1 le noyau connaît suffisamment les modes vidéo EGA/VGA pour sélectionner une distance entre lignes différente. La hauteur de caractère par défaut sera le nombre N déduit de la police ou spécifié par l'option. Cependant, l'utilisateur peut spécifier une hauteur de caractère différente H en utilisant l'option -h.

TABLES DE CORRESPONDANCE CONSOLE

Plusieurs tables de correspondance sont impliquées dans le chemin allant de la sortie du programme utilisateur à l'affichage sur la console. Si la console est en mode utf8 (voir unicode_start(1)) alors le noyau s'attend à ce que la sortie du programme utilisateur soit codée en UTF-8 (voir utf-8(7)), et la convertit en Unicode (ucs2). Sinon, une table de traduction est utilisée de la sortie 8 bits du programme vers les valeurs Unicode 16 bits. Une telle table de traduction est appelée une table de correspondance console Unicode. Il y en a quatre : trois intégrées au noyau, la quatrième pouvant être réglée en utilisant l'option -m de setfont. Une séquence d'échappement choisit entre ces quatre tables ; après avoir chargé une cmap, setfont sortira la séquence d'échappement Esc ( K qui en fait la table de traduction active.

Les arguments appropriés pour l'option -m sont par exemple 8859-1, 8859-2, ..., 8859-15, cp437, ..., cp1250.

Étant donnée la valeur Unicode du symbole à afficher, le noyau trouve le bon glyphe dans la police en utilisant les informations de mappage Unicode de la police et l'affiche.

Les anciennes polices n'ont pas d'informations de mappage Unicode, et pour les gérer il existe des tables directes vers la police (également chargées avec -m) qui donnent une correspondance entre les octets utilisateur et les positions de la police. La correspondance la plus courante est celle donnée dans le fichier trivial (où les valeurs d'octets utilisateur sont utilisées directement comme positions de police). D'autres correspondances sont parfois préférables car le matériel vidéo du PC attend les caractères de dessin de lignes dans certaines positions de la police.

Donner un argument -m none inhibe le chargement et l'activation d'une table de correspondance. La table de correspondance console précédente peut être sauvegardée dans un fichier en utilisant l'option -om fichier. Ces options de setfont rendent mapscrn(8) obsolète. (Cependant, il peut être utile de lire cette page de manuel.)

TABLES DE CORRESPONDANCE UNICODE

La correspondance entre les glyphes de la police et les valeurs Unicode est décrite par une table de mappage Unicode. De nombreuses polices ont une table de mappage Unicode incluse dans le fichier de police, et une table explicite peut être indiquée en utilisant l'option -u. Le programme setfont chargera une telle table de mappage Unicode, sauf si un argument -u none est donné. La table de mappage Unicode précédente sera sauvegardée en tant que partie du fichier de police sauvegardé lorsque l'option -O est utilisée. Elle peut être sauvegardée dans un fichier séparé en utilisant l'option -ou fichier. Ces options de setfont rendent loadunimap(8) obsolète.

La table de mappage Unicode devrait assigner un glyphe à la valeur du `caractère manquant' U+fffd, sinon les caractères manquants ne sont pas traduits, donnant un résultat généralement très déroutant.

Habituellement, aucune table de mappage n'est nécessaire, et une table de mappage Unicode est déjà contenue dans la police (parfois indiqué par l'extension .psfu), de sorte que la plupart des utilisateurs n'ont pas à se soucier du sens précis et du fonctionnement de ces tables de mappage.

On peut ajouter une table de mappage Unicode à une police psf en utilisant psfaddtable(1).

OPTIONS

-N, --default8x=N
Charge la police par défaut (default8xN).
-hN, --font-height=N
Remplace la hauteur de la police. L'option courte ne doit pas avoir d'espace entre le préfixe et le nombre.
-d, --double
Double la taille de la police, en répliquant tous ses pixels verticalement et horizontalement. Ceci est adapté aux écrans à haute densité de pixels (par exemple "4k") sur lesquels les polices standard sont trop petites pour être facilement lisibles. En raison des limitations du noyau, ceci n'est adapté qu'aux polices de 16x16 ou plus petites.
-o, --output-font=FICHIER
Sauvegarde la police précédente dans FICHIER.
-om, --output-consolemap=FICHIER
Stocke la table de correspondance console dans FICHIER.
-ou, --output-unicodemap=FICHIER
Sauvegarde la table de correspondance Unicode précédente dans FICHIER.
-O, --output-fullfont=FICHIER
Sauvegarde la police et la table de correspondance Unicode précédentes dans FICHIER.
-m, --consolemap=FICHIER
Charge une table de correspondance console ou une table de correspondance console Unicode depuis FICHIER.
-u, --unicodemap=FICHIER
Charge la table Unicode décrivant la police depuis FICHIER.
-C, --console=PÉRIPHÉRIQUE
Définit la police pour la console indiquée. (Peut nécessiter les permissions de root.)
-f, --force
Forcer le chargement de la table unicode : Setfont`effectue l'appel système pour charger la table unicode même si la table spécifiée est vide. Cela peut être utile dans des cas inhabituels.
-R, --reset
Réinitialise l'écran.

setfont(8) — Arch Linux

NOM

setfont — définir la police de la console

SYNTAXIS

setfont [-v] [-V] [-h] [font_file]

setfont -o font_file

setfont -i [font_file]

setfont -c font_file

setfont -k font_file

setfont -p font_file

setfont -t font_file

setfont -u font_file

setfont -m font_file

DESCRIPTION

La commande setfont charge une police de caractères dans la RAM vidéo de la console du noyau Linux. Elle peut également définir une table de mappage Unicode et une table de caractères de la console.

Une police de caractères se compose de plusieurs fichiers : la police elle-même, une table de mappage des caractères de la console, et éventuellement une table de mappage Unicode.

Lorsque le nom du fichier de police n'est pas spécifié, setfont essaie de trouver un fichier de police par défaut. Le nom par défaut est default, default8x16, ou default8xN, où N est la hauteur de la police.

Les polices de caractères sont généralement stockées dans /usr/share/kbd/consolefonts.

Si vous utilisez une police qui a plus de 256 glyphes, alors 512 glyphes peuvent être utilisés, mais la console sera réduite à 8 couleurs (au lieu de 16).

OPTIONS

-o, --save-font
Sauvegarde la police de la console actuelle dans le fichier spécifié. Utile pour enregistrer la configuration de la police actuelle avant de la modifier.
-i, --identify
Affiche des informations sur la police de caractères actuelle ou sur le fichier de police spécifié. Cela inclut le nom du fichier, la taille du caractère, le nombre de glyphes et le mappage Unicode.
-c, --consolechars
Charge une table de caractères de la console à partir du fichier spécifié. Cette table définit la façon dont les caractères sont mappés aux glyphes de la police.
-k, --consoletrans
Charge une table de traduction de la console à partir du fichier spécifié. Cette table est utilisée pour mapper des séquences d'octets à des caractères spécifiques, ce qui est utile pour les jeux de caractères non ASCII.
-p, --psf
Charge une police de caractères au format PSF (PC Screen Font). Les polices PSF peuvent contenir des informations sur les métadonnées, telles que la taille des caractères et le mappage Unicode.
-t, --table
Charge une police de caractères au format .cp850 ou .cp852. Ces formats sont utilisés pour les jeux de caractères de la console MS-DOS.
-u, --unicode
Charge une table de mappage Unicode à partir du fichier spécifié. Ce fichier définit comment les points de code Unicode sont mappés aux glyphes de la police.
-m, --dots
Charge une police de caractères au format .dots. Ce format est plus ancien et peut ne pas supporter toutes les fonctionnalités des formats plus récents. Les options size et Unicode mapping sont appliquées aux valeurs par défaut de démarrage.
-v, --verbose
Mode verbeux. Affiche des informations détaillées sur les opérations effectuées.
-V, --version
Affiche la version du programme et quitte.
-h, --help
Affiche un message décrivant les options disponibles et quitte.

NOTE

Le matériel vidéo des PC permet d'utiliser le bit "intensité" soit pour indiquer la luminosité, soit pour accéder à 512 (au lieu de 256) glyphes dans la police. Ainsi, si la police a plus de 256 glyphes, la console sera réduite à 8 (au lieu de 16) couleurs.

FICHIERS

/usr/share/kbd/consolefonts
Le répertoire par défaut des polices.
/usr/share/kbd/unimaps
Le répertoire par défaut des cartes Unicode.
/usr/share/kbd/consoletrans
Le répertoire par défaut des mappages d'écran.

La police par défaut est un fichier default (ou default8xN si l'option -N a été donnée pour un certain nombre N) peut-être avec une extension appropriée (comme .psf).
