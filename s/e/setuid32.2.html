setuid(2) Manuel des appels système setuid(2)

NOM

setuid - définir l'identité utilisateur

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int setuid(uid_t uid);

DESCRIPTION

setuid() définit l'identifiant utilisateur effectif du processus appelant. Si le processus appelant est privilégié (plus précisément : si le processus possède la capacité CAP_SETUID dans son espace de noms utilisateur), l'identifiant utilisateur réel et l'identifiant utilisateur enregistré sont également définis.

Sous Linux, setuid() est implémenté comme la version POSIX avec la fonctionnalité _POSIX_SAVED_IDS. Cela permet à un programme défini par l'identifiant utilisateur (autre que root) de supprimer tous ses privilèges utilisateur, d'effectuer un travail sans privilège, puis de réengager l'identifiant utilisateur effectif d'origine de manière sécurisée.

Si l'utilisateur est root ou si le programme est défini par l'identifiant utilisateur root, une attention particulière doit être portée : setuid() vérifie l'identifiant utilisateur effectif de l'appelant et s'il s'agit du superutilisateur, tous les identifiants utilisateur liés au processus sont définis sur uid. Une fois cela effectué, il est impossible pour le programme de retrouver les privilèges root.

Par conséquent, un programme défini par l'identifiant utilisateur root souhaitant abandonner temporairement les privilèges root, assumer l'identité d'un utilisateur sans privilège, puis retrouver les privilèges root par la suite ne peut pas utiliser setuid(). Vous pouvez y parvenir avec seteuid(2).

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

Note : il existe des cas où setuid() peut échouer même lorsque l'appelant est l'UID 0 ; il s'agit d'une grave erreur de sécurité de ne pas vérifier le retour d'échec de setuid().

ERREURS

EAGAIN
L'appel modifierait l'UID réel de l'appelant (c'est-à-dire que uid ne correspond pas à l'UID réel de l'appelant), mais il y a eu un échec temporaire d'allocation des structures de données noyau nécessaires.
EAGAIN
uid ne correspond pas à l'identifiant utilisateur réel de l'appelant et cet appel augmenterait le nombre de processus appartenant à l'identifiant utilisateur réel uid au-delà de la limite de ressources RLIMIT_NPROC de l'appelant. Depuis Linux 3.1, ce cas d'erreur ne se produit plus (mais les applications robustes devraient vérifier cette erreur) ; voir la description de EAGAIN dans execve(2).
EINVAL
L'identifiant utilisateur spécifié dans uid n'est pas valide dans cet espace de noms utilisateur.
EPERM
L'utilisateur n'est pas privilégié (Linux : ne possède pas la capacité CAP_SETUID dans son espace de noms utilisateur) et uid ne correspond pas à l'UID réel ou à l'UID utilisateur enregistré de l'appelant.

VERSIONS

Différences bibliothèque C/noyau

Au niveau du noyau, les identifiants utilisateur et groupe sont un attribut par thread. Cependant, POSIX exige que tous les threads d'un processus partagent les mêmes informations d'identification. L'implémentation de threading NPTL gère les exigences POSIX en fournissant des fonctions d'encapsulation pour les différents appels système qui modifient les UID et GID des processus. Ces fonctions d'encapsulation (y compris celle pour setuid()) utilisent une technique basée sur les signaux pour garantir que lorsqu'un thread modifie les informations d'identification, tous les autres threads du processus modifient également leurs informations d'identification. Pour plus de détails, voir nptl(7).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Pas tout à fait compatible avec l'appel 4.4BSD, qui définit tous les identifiants utilisateur réels, enregistrés et effectifs.

L'appel système Linux setuid() original ne prenait en charge que les identifiants utilisateur 16 bits. Par la suite, Linux 2.4 a ajouté setuid32() prenant en charge les identifiants 32 bits. La fonction d'encapsulation setuid() de glibc gère de manière transparente la variation entre les versions du noyau.

NOTES

Linux a le concept d'identifiant utilisateur du système de fichiers, normalement égal à l'identifiant utilisateur effectif. L'appel setuid() définit également l'identifiant utilisateur du système de fichiers du processus appelant. Voir setfsuid(2).

Si uid est différent de l'ancien UID effectif, le processus sera interdit de générer des dumps de noyau.

VOIR AUSSI

getuid(2), seteuid(2), setfsuid(2), setreuid(2), capabilities(7), credentials(7), user_namespaces(7)
