random_r(3) Manuel des fonctions de bibliothèque random_r(3)

NOM

random_r, srandom_r, initstate_r, setstate_r - générateur de nombres aléatoires réentrant

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdlib.h>
int random_r(struct random_data *restrict buf,
             int32_t *restrict result);
int srandom_r(unsigned int seed, struct random_data *buf);
int initstate_r(unsigned int seed,
             char statebuf[restrict .statelen], size_t statelen,
             struct random_data *restrict buf);
int setstate_r(char *restrict statebuf,
             struct random_data *restrict buf);
Conditions requises pour les macros de test de fonctionnalité sur glibc (voir feature_test_macros(7)):

random_r(), srandom_r(), initstate_r(), setstate_r():

    /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE || _BSD_SOURCE

DESCRIPTION

Ces fonctions sont les équivalents réentrants des fonctions décrites dans random(3). Elles conviennent à une utilisation dans des programmes multithreads où chaque thread a besoin d'obtenir une séquence de nombres aléatoires indépendante et reproductible.

La fonction random_r() est similaire à random(3), sauf qu'au lieu d'utiliser les informations d'état maintenues dans une variable globale, elle utilise les informations d'état dans l'argument pointé par buf, qui doit avoir été préalablement initialisé par initstate_r(). Le nombre aléatoire généré est retourné dans l'argument result.

La fonction srandom_r() est similaire à srandom(3), sauf qu'elle initialise la graine pour le générateur de nombres aléatoires dont l'état est maintenu dans l'objet pointé par buf, qui doit avoir été préalablement initialisé par initstate_r(), au lieu de la graine associée à la variable d'état globale.

La fonction initstate_r() est similaire à initstate(3), sauf qu'elle initialise l'état dans l'objet pointé par buf, plutôt que d'initialiser la variable d'état globale. Avant d'appeler cette fonction, le champ buf.state doit être initialisé à NULL. La fonction initstate_r() enregistre un pointeur vers l'argument statebuf à l'intérieur de la structure pointée par buf. Par conséquent, statebuf ne doit pas être désalloué tant que buf est encore utilisé. (Ainsi, statebuf doit généralement être alloué comme variable statique, ou alloué sur le tas en utilisant malloc(3) ou une fonction similaire.)

La fonction setstate_r() est similaire à setstate(3), sauf qu'elle modifie l'état dans l'objet pointé par buf, au lieu de modifier la variable d'état globale. state doit d'abord avoir été initialisé à l'aide de initstate_r() ou être le résultat d'un appel précédent de setstate_r().

VALEUR DE RETOUR

Toutes ces fonctions retournent 0 en cas de succès. En cas d'erreur, -1 est retourné, avec errno défini pour indiquer l'erreur.

ERREURS

EINVAL
Un tableau d'état de moins de 8 octets a été spécifié à initstate_r().
EINVAL
L'argument statebuf ou buf passé à setstate_r() était NULL.
EINVAL
L'argument buf ou result passé à random_r() était NULL.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
random_r (), srandom_r (), initstate_r (), setstate_r () Sécurité des threads MT-Safe race:buf

NORMES

GNU.

BOGUES

L'interface initstate_r() est confuse. Il semble que le type random_data soit destiné à être opaque, mais l'implémentation exige que l'utilisateur initialise le champ buf.state à NULL ou efface la structure entière avant l'appel.

VOIR AUSSI
