getitimer(2) Manuel des appels système getitimer(2)

NOM

getitimer, setitimer - obtenir ou définir la valeur d'un timer d'intervalle

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/time.h>
int getitimer(int which, struct itimerval *curr_value);
int setitimer(int which, const struct itimerval *restrict new_value,
              struct itimerval *_Nullable restrict old_value);

DESCRIPTION

Ces appels système donnent accès aux timers d'intervalle, c'est-à-dire des timers qui expirent initialement à un moment donné dans le futur, et (facultativement) à intervalles réguliers après cela. Lorsqu'un timer expire, un signal est généré pour le processus appelant, et le timer est réinitialisé à l'intervalle spécifié (si l'intervalle n'est pas nul).

Trois types de timers — spécifiés via l'argument which — sont fournis, chacun d'eux comptant par rapport à une horloge différente et générant un signal différent lors de l'expiration du timer :

ITIMER_REAL
Ce timer compte à rebours en temps réel (c'est-à-dire temps universel). À chaque expiration, un signal SIGALRM est généré.
ITIMER_VIRTUAL
Ce timer compte à rebours par rapport au temps CPU en mode utilisateur consommé par le processus. (La mesure inclut le temps CPU consommé par tous les threads du processus.) À chaque expiration, un signal SIGVTALRM est généré.
ITIMER_PROF
Ce timer compte à rebours par rapport au temps CPU total (c'est-à-dire à la fois utilisateur et système) consommé par le processus. (La mesure inclut le temps CPU consommé par tous les threads du processus.) À chaque expiration, un signal SIGPROF est généré.
En conjonction avec ITIMER_VIRTUAL, ce timer peut être utilisé pour profiler le temps CPU utilisateur et système consommé par le processus.

Un processus n'a qu'un seul de chacun des trois types de timers.

Les valeurs des timers sont définies par les structures suivantes :


struct itimerval {
    struct timeval it_interval; /* Intervalle pour le timer périodique */
    struct timeval it_value;    /* Temps avant la prochaine expiration */
};
struct timeval {
    time_t      tv_sec;         /* secondes */
    suseconds_t tv_usec;        /* microsecondes */
};

getitimer()

La fonction getitimer() place la valeur actuelle du timer spécifié par which dans le tampon pointé par curr_value.

La sous-structure it_value est remplie avec la quantité de temps restant avant la prochaine expiration du timer spécifié. Cette valeur change au fur et à mesure que le timer compte à rebours, et sera réinitialisée à it_interval lorsque le timer expirera. Si les deux champs de it_value sont nuls, alors ce timer est actuellement désarmé (inactif).

La sous-structure it_interval est remplie avec l'intervalle du timer. Si les deux champs de it_interval sont nuls, alors il s'agit d'un timer à déclenchement unique (c'est-à-dire qu'il expire une seule fois).

setitimer()

La fonction setitimer() arme ou désarme le timer spécifié par which, en définissant le timer à la valeur spécifiée par new_value. Si old_value n'est pas NULL, le tampon qu'il pointe est utilisé pour renvoyer la valeur précédente du timer (c'est-à-dire les mêmes informations que celles renvoyées par getitimer()).

Si l'un ou l'autre des champs de new_value.it_value n'est pas nul, alors le timer est armé pour expirer initialement au moment spécifié. Si les deux champs de new_value.it_value sont nuls, alors le timer est désarmé.

Le champ new_value.it_interval spécifie le nouvel intervalle pour le timer ; si ses deux sous-champs sont nuls, le timer est à déclenchement unique.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est définie pour indiquer l'erreur.

ERREURS

EFAULT
new_value, old_value, ou curr_value n'est pas un pointeur valide.
EINVAL
which n'est ni ITIMER_REAL, ni ITIMER_VIRTUAL, ni ITIMER_PROF ; ou (depuis Linux 2.6.22) l'un des champs tv_usec dans la structure pointée par new_value contient une valeur en dehors de la plage [0, 999999].

VERSIONS

Les standards sont muets sur la signification de l'appel :


setitimer(which, NULL, &old_value);

De nombreux systèmes (Solaris, les BSD, et peut-être d'autres) traitent cela comme équivalent à :


getitimer(which, &old_value);

Sous Linux, cela est traité comme équivalent à un appel dans lequel les champs new_value sont nuls ; c'est-à-dire que le timer est désactivé. N'utilisez pas ce mauvais usage de Linux : il n'est pas portable et inutile.

NORMES

Aucune.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD (cet appel est apparu pour la première fois dans 4.2BSD). POSIX.1-2008 a marqué getitimer() et setitimer() comme obsolètes, recommandant l'utilisation de l'API des timers POSIX ( timer_gettime(2), timer_settime(2), etc.) à la place. POSIX.1-2024 les a supprimés.

NOTES

Les timers n'expireront jamais avant le temps demandé, mais peuvent expirer un peu plus tard, ce qui dépend de la résolution du timer système et de la charge du système ; voir time(7). (Mais voir BUGS ci-dessous.) Si le timer expire pendant que le processus est actif (toujours vrai pour ITIMER_VIRTUAL), le signal sera délivré immédiatement lorsqu'il sera généré.

Un enfant créé via fork(2) n'hérite pas des timers d'intervalle de son parent. Les timers d'intervalle sont préservés lors d'un execve(2).

POSIX.1 laisse l'interaction entre setitimer() et les trois interfaces alarm(2), sleep(3), et usleep(3) non spécifiée.

BUGS

La génération et la délivrance d'un signal sont distinctes, et une seule instance de chacun des signaux listés ci-dessus peut être en attente pour un processus. Sous une charge très lourde, un timer ITIMER_REAL peut expirer avant que le signal d'une expiration précédente n'ait été délivré. Le deuxième signal dans un tel événement sera perdu.

Avant Linux 2.6.16, les valeurs de timer sont représentées en jiffies. Si une requête est faite pour définir un timer avec une valeur dont la représentation en jiffies dépasse MAX_SEC_IN_JIFFIES (défini dans include/linux/jiffies.h), alors le timer est silencieusement tronqué à cette valeur plafond. Sur Linux/i386 (où, depuis Linux 2.6.13, le jiffy par défaut est de 0,004 secondes), cela signifie que la valeur plafond pour un timer est d'environ 99,42 jours. Depuis Linux 2.6.16, le noyau utilise une représentation interne différente pour les temps, et cette valeur plafond est supprimée.

Sur certains systèmes (y compris i386), les noyaux Linux avant Linux 2.6.12 ont un bug qui produira des expirations de timer prématurées jusqu'à un jiffy dans certaines circonstances. Ce bug est corrigé dans Linux 2.6.12.

POSIX.1-2001 indique que setitimer() devrait échouer si une valeur tv_usec est spécifiée qui est en dehors de la plage [0, 999999]. Cependant, jusqu'à et y compris Linux 2.6.21, Linux ne génère pas d'erreur, mais ajuste silencieusement la valeur des secondes correspondante pour le timer. À partir de Linux 2.6.22, cette non-conformité a été réparée : une valeur tv_usec incorrecte entraîne une erreur EINVAL.

VOIR AUSSI
