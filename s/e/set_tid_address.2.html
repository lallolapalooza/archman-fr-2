set_tid_address(2) Manuel des appels système set_tid_address(2)

NOM

set_tid_address - définir le pointeur vers l'ID du thread

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
pid_t syscall(SYS_set_tid_address, int *tidptr);

Note : glibc ne fournit pas d'enveloppe pour set_tid_address(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

Pour chaque thread, le noyau maintient deux attributs (adresses) appelés set_child_tid et clear_child_tid. Ces deux attributs contiennent la valeur NULL par défaut.

set_child_tid
Si un thread est lancé en utilisant clone(2) avec le drapeau CLONE_CHILD_SETTID, set_child_tid est défini à la valeur passée dans l'argument ctid de cet appel système.
Lorsque set_child_tid est défini, la toute première chose que fait le nouveau thread est d'écrire son identifiant de thread à cette adresse.
clear_child_tid
Si un thread est lancé en utilisant clone(2) avec le drapeau CLONE_CHILD_CLEARTID, clear_child_tid est défini à la valeur passée dans l'argument ctid de cet appel système.

L'appel système set_tid_address() définit la valeur clear_child_tid pour le thread appelant à tidptr.

Lorsqu'un thread dont clear_child_tid n'est pas NULL se termine, alors, si le thread partage de la mémoire avec d'autres threads, 0 est écrit à l'adresse spécifiée dans clear_child_tid et le noyau effectue l'opération suivante :


futex(clear_child_tid, FUTEX_WAKE, 1, NULL, NULL, 0);

L'effet de cette opération est de réveiller un seul thread qui effectue une attente futex sur l'emplacement mémoire. Les erreurs de l'opération de réveil futex sont ignorées.

VALEUR DE RETOUR

set_tid_address() retourne toujours l'identifiant du thread de l'appelant.

ERREURS

set_tid_address() réussit toujours.

NORMES

Linux.

HISTORIQUE

Linux 2.5.48.

Les détails tels qu'indiqués ici sont valides depuis Linux 2.5.49.

VOIR AUSSI

clone(2), futex(2), gettid(2)
