self(n)

Paquet: tcl

Licences: TCL

self(n) Commandes TclOO self(n)

NOM

self - introspection d'appel de méthode

SYNTAXE

package require TclOO
self ?sous-commande?

DESCRIPTION

La commande self, qui ne doit être utilisée que dans le contexte d'un appel de méthode (c'est-à-dire à l'intérieur du corps d'une méthode, constructeur ou destructeur) est utilisée pour permettre à la méthode de découvrir des informations sur la manière dont elle a été appelée. Elle prend un argument, sous-commande, qui lui indique quel type d'information est réellement souhaité ; s'il est omis, le résultat sera le même que si self object avait été appelé. Les sous-commandes prises en charge sont :

self call
Ceci retourne une liste à deux éléments décrivant les implémentations de méthode utilisées pour implémenter la chaîne d'appels actuelle. Le premier élément est le même que celui qui serait rapporté par info object call pour la méthode actuelle (sauf que cela rapporte également des valeurs utiles à partir des constructeurs et destructeurs, dont les noms sont rapportés comme <constructor> et <destructor> respectivement), et le second élément est un indice dans la liste du premier élément qui indique quelle implémentation réelle est actuellement exécutée (la première implémentation à exécuter est toujours à l'indice 0).
self caller
Lorsque la méthode a été invoquée à partir d'une autre méthode d'objet, cette sous-commande retourne une liste à trois éléments décrivant l'objet et la méthode conteneurs. Le premier élément décrit l'objet ou la classe déclarante de la méthode, le second élément est le nom de l'objet sur lequel la méthode conteneur a été invoquée, et le troisième élément est le nom de la méthode (avec les chaînes <constructor> et <destructor> indiquant respectivement les constructeurs et les destructeurs).
self class
Ceci retourne le nom de la classe dans laquelle la méthode actuelle a été définie. Notez que cela changera au fur et à mesure que la chaîne des implémentations de méthode est parcourue avec next, et que si la méthode a été définie sur un objet, cela échouera.

Si vous voulez la classe de l'objet actuel, vous devez utiliser cette autre construction :

info object class [self object]
self filter
Lorsqu'elle est invoquée à l'intérieur d'un filtre, cette sous-commande retourne une liste à trois éléments décrivant le filtre. Le premier élément donne le nom de l'objet ou de la classe qui a déclaré le filtre (notez que cela peut être différent de l'objet ou de la classe qui a fourni l'implémentation du filtre), le second élément est soit object, soit class selon que l'entité déclarante était un objet ou une classe, et le troisième élément est le nom du filtre.
self method
Ceci retourne le nom de la méthode actuelle (avec les chaînes <constructor> et <destructor> indiquant respectivement les constructeurs et les destructeurs).
self namespace
Ceci retourne le nom de l'espace de noms unique de l'objet sur lequel la méthode a été invoquée.
self next
Lorsqu'il est invoqué à partir d'une méthode qui n'est pas à la fin d'une chaîne d'appels (c'est-à-dire où la commande next invoquera une implémentation de méthode réelle), cette sous-commande retourne une liste à deux éléments décrivant le prochain élément de la chaîne d'appels de méthode ; le premier élément est le nom de la classe ou de l'objet qui déclare la prochaine partie de la chaîne d'appels, et le second élément est le nom de la méthode (avec les chaînes <constructor> et <destructor> indiquant respectivement les constructeurs et les destructeurs). S'il est invoqué à partir d'une méthode qui est à la fin d'une chaîne d'appels, cette sous-commande retourne une chaîne vide.
self object
Ceci retourne le nom de l'objet sur lequel la méthode a été invoquée.
self target
Lorsqu'elle est invoquée à l'intérieur d'une implémentation de filtre, cette sous-commande retourne une liste à deux éléments décrivant la méthode filtrée. Le premier élément sera le nom du déclarant de la méthode, et le second élément sera le nom réel de la méthode.

EXEMPLES

Cet exemple montre l'utilisation basique de self pour fournir des informations sur l'objet actuel :

oo::class create c {
    method foo {} {
        puts "c'est l'objet [self]"
    }
}
c create a
c create b
a foo                → affiche "c'est l'objet ::a"
b foo                → affiche "c'est l'objet ::b"

Ceci démontre à quoi ressemble une chaîne d'appels de méthode, et comment le déplacement le long de celle-ci modifie l'indice :

oo::class create c {
    method x {} {
        puts "Cls: [self call]"
    }
}
c create a
oo::objdefine a {
    method x {} {
        puts "Obj: [self call]"
        next
        puts "Obj: [self call]"
    }
}
a x     → Obj: {{method x object method} {method x ::c method}} 0
        → Cls: {{method x object method} {method x ::c method}} 1
        → Obj: {{method x object method} {method x ::c method}} 0
