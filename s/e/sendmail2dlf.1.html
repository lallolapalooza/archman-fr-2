NOM

sendmail2dlf - convertir les fichiers journaux sendmail en dlf

SYNTAXE

sendmail2dlf

DESCRIPTION

sendmail2dlf(1) convertit un journal sendmail (version 8.10.x ou supérieure) avec un niveau de journalisation 9, tel que créé par syslog, en un fichier au format Distilled Log Format (dlf) pour Lire.

L'entrée est une ligne par événement. La sortie est une ligne par livraison :

time logrelay queueid msgid fromuser fromdomain fromrelay \
size delay xdelay touser todomain torelay stat

(Ceci devrait être le format tel que défini dans email/dlf.cfg.)

Le fait que la livraison 'Mar 15 13:40:04 firewall sendmail[401]: NAA00401:' ne génère pas d'enregistrement dlf est un bug.

Lorsque la ligne

Mar 15 13:34:09 firewall sendmail[279]: NAA00279: \
 from=<klaas@example.com>, size=2281952, class=0, \
 pri=2311952, nrcpts=1, \
 msgid=<200003151230.NAA00112@mailhost.example.nl>, \
 proto=ESMTP, relay=host.example.nl [150.0.0.45]
Mar 15 13:34:09 firewall sendmail[279]: NAA00279: \
 to=<klaas@hotmail.com>, delay=00:00:04, mailer=smtp, \
 stat=queued
Mar 15 13:39:58 firewall sendmail[401]: NAA00279: \
 to=<klaas@hotmail.com>, delay=00:05:53, xdelay=00:00:06, \
 mailer=smtp, relay=mc5.law5.hotmail.com. \
 [216.32.243.136], stat=Service unavailable
Mar 15 13:39:58 firewall sendmail[401]: NAA00279: \
 NAA00401: postmaster notify: Service unavailable
Mar 15 13:40:04 firewall sendmail[401]: NAA00401: \
 to=klaas@host.example.com, delay=00:00:06, \
 xdelay=00:00:04, mailer=smtp, relay=host.example.nl. \
 [150.0.0.45], stat=Sent (OK)

se produit dans l'entrée, et il n'y a pas de ligne portant le même identifiant de file d'attente, la ligne est ignorée et signalée comme sautée : toute ligne to ou from, dépourvue de partenaire, sera ignorée.

Les lignes comme :

Mar 15 13:40:19 firewall sendmail[456]: alias database \
 /etc/aliases.db out of date

seront ignorées

EXEMPLES

Pour traiter un journal tel que produit par sendmail :

$ sendmail2dlf < mail.log

sendmail2dlf sera rarement utilisé seul, mais sera plus probablement appelé par lr_log2report :

$ lr_log2report sendmail < /var/log/maillog

BOGUES

Lorsque les identifiants de file d'attente sont réutilisés au sein d'un même fichier journal, le comportement est imprévisible. Les extraits de journal incomplets (par exemple, des lignes `from` sans lignes `to`) ne sont pas bien traités.

Il est rapporté que des événements comme ceux-ci se produisent dans les fichiers journaux de sendmail :

 msgid=<092246.09986@rly-yc03.mx.aol.com>, proto=ESMTP, 
 relay=omr-d06.mx.aol.com [205.188.156.71]
SAA14845: to=joe@mailhost, ctladdr=<joe@example.edu>, delay=00:00:01, 
 mailer=local, stat=User unknown
SAA14845: to=<joe@example.edu>, delay=00:00:01, mailer=local, 
 stat=User unknown
SAA14845: SAA14845: postmaster notify: User unknown
SAA14846: to="|exec /usr/local/bin/procmail", ctladdr=ann@mailhost (2217/10), 
 delay=00:00:00, xdelay=00:00:00, mailer=prog, stat=Sent
SAA14846: to=bob@imap-ns, delay=00:00:01, xdelay=00:00:01, mailer=esmtp, 
 relay=apex.example.edu. [152.19.4.80], 
 stat=Sent (Message received: GVV8N400.CMX)
SAA14846: to=eve@mailhost, delay=00:00:01, xdelay=00:00:00, mailer=local,

Notez que SAA14845 a _deux_ lignes `to` finales, tandis que la ligne `from` indique `nrcpts=1`. Cela fait voler en éclats l'axiome de ce script. Nous n'avons pas encore décidé comment gérer cela...
