setbuf(3) Manuel des fonctions de bibliothèque setbuf(3)

NOM

setbuf, setbuffer, setlinebuf, setvbuf - opérations de mise en mémoire tampon de flux

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdio.h>
int setvbuf(FILE *restrict stream, char *restrict buf, int mode, size_t size);
void setbuf(FILE *restrict stream, char *restrict buf);
void setbuffer(FILE *restrict stream, char *restrict buf, size_t size);
void setlinebuf(FILE *stream);
Exigences de macro de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

setbuffer(), setlinebuf():

    Depuis glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 et antérieur:
        _BSD_SOURCE

DESCRIPTION

Les trois types de mise en mémoire tampon disponibles sont : non mise en mémoire tampon, mise en mémoire tampon par bloc et mise en mémoire tampon par ligne. Lorsqu'un flux de sortie n'est pas mis en mémoire tampon, les informations apparaissent dans le fichier de destination ou le terminal dès qu'elles sont écrites ; lorsqu'il est mis en mémoire tampon par bloc, de nombreux caractères sont sauvegardés et écrits en bloc ; lorsqu'il est mis en mémoire tampon par ligne, les caractères sont sauvegardés jusqu'à ce qu'une nouvelle ligne soit émise ou que des données soient lues à partir de n'importe quel flux connecté à un périphérique terminal (typiquement stdin). La fonction fflush(3) peut être utilisée pour forcer la sortie du bloc plus tôt. (Voir fclose(3).)

Normalement, tous les fichiers sont mis en mémoire tampon par bloc. Si un flux fait référence à un terminal (comme stdout le fait normalement), il est mis en mémoire tampon par ligne. Le flux d'erreurs standard stderr n'est toujours pas mis en mémoire tampon par défaut.

La fonction setvbuf() peut être utilisée sur n'importe quel flux ouvert pour changer sa mémoire tampon. L'argument mode doit être l'une des trois macros suivantes :

_IONBF
non mis en mémoire tampon
_IOLBF
mise en mémoire tampon par ligne
_IOFBF
mise en mémoire tampon complète

Sauf pour les fichiers non mis en mémoire tampon, l'argument buf doit pointer vers une mémoire tampon d'au moins size octets ; cette mémoire tampon sera utilisée à la place de la mémoire tampon actuelle. Si l'argument buf est NULL, seul le mode est affecté ; une nouvelle mémoire tampon sera allouée lors de la prochaine opération de lecture ou d'écriture. La fonction setvbuf() ne peut être utilisée qu'après l'ouverture d'un flux et avant que toute autre opération n'ait été effectuée sur celui-ci.

Les trois autres appels sont, en effet, simplement des alias pour des appels à setvbuf(). La fonction setbuf() est exactement équivalente à l'appel


setvbuf(stream, buf, buf ? _IOFBF : _IONBF, BUFSIZ);

La fonction setbuffer() est la même, sauf que la taille de la mémoire tampon est déterminée par l'appelant, plutôt que par la valeur par défaut BUFSIZ. La fonction setlinebuf() est exactement équivalente à l'appel :


setvbuf(stream, NULL, _IOLBF, 0);

VALEUR RENVOYÉE

La fonction setvbuf() renvoie 0 en cas de succès. Elle renvoie une valeur non nulle en cas d'échec (mode est invalide ou la demande ne peut être satisfaite). Elle peut définir errno en cas d'échec.

Les autres fonctions ne renvoient pas de valeur.

LIMITATIONS

POSIX note que la valeur de errno n'est pas spécifiée après un appel à setbuf() et ajoute que, puisque la valeur de errno n'est pas requise pour rester inchangée après un appel réussi à setbuf(), les applications devraient plutôt utiliser setvbuf() pour détecter les erreurs.

BOGUES

Vous devez vous assurer que l'espace auquel buf pointe existe toujours au moment où stream est fermé, ce qui se produit également à la fin du programme. Par exemple, ce qui suit est invalide :

#include <stdio.h>
int
main(void)
{
    char buf[BUFSIZ];
    setbuf(stdout, buf);
    printf("Hello, world!\n");
    return 0;
}
