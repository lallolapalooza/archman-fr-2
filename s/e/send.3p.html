SEND(3P) Manuel du programmeur POSIX SEND(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

send — envoyer un message sur un socket

SYNOPIS

#include <sys/socket.h>
ssize_t send(int socket, const void *buffer, size_t length, int flags);

DESCRIPTION

La fonction send() initie la transmission d'un message depuis le socket spécifié vers son pair. La fonction send() n'envoie un message que lorsque le socket est connecté. Si le socket est un socket en mode sans connexion, le message est envoyé à l'adresse du pair pré-spécifiée.

La fonction send() prend les arguments suivants :

socket
Spécifie le descripteur de fichier du socket.
buffer
Pointe vers le tampon contenant le message à envoyer.
length
Spécifie la longueur du message en octets.
flags
Spécifie le type de transmission du message. Les valeurs de cet argument sont formées en combinant logiquement zéro ou plusieurs des drapeaux suivants :
MSG_EOR
Termine un enregistrement (si supporté par le protocole).
MSG_OOB
Envoie des données hors bande sur les sockets qui supportent les communications hors bande. La signification et la sémantique des données hors bande sont spécifiques au protocole.
MSG_NOSIGNAL
Demande de ne pas envoyer le signal SIGPIPE si une tentative d'envoi est effectuée sur un socket orienté flux qui n'est plus connecté. L'erreur [EPIPE] sera toujours retournée.

La longueur du message à envoyer est spécifiée par l'argument length. Si le message est trop long pour être transmis par le protocole sous-jacent, send() échouera et aucune donnée ne sera transmise.

L'achèvement réussi d'un appel à send() ne garantit pas la livraison du message. Une valeur de retour de -1 n'indique que des erreurs détectées localement.

Si l'espace n'est pas disponible au socket d'envoi pour contenir le message à transmettre, et si le descripteur de fichier du socket n'a pas O_NONBLOCK défini, send() bloquera jusqu'à ce que l'espace soit disponible. Si l'espace n'est pas disponible au socket d'envoi pour contenir le message à transmettre, et si le descripteur de fichier du socket a O_NONBLOCK défini, send() échouera. Les fonctions select() et poll() peuvent être utilisées pour déterminer quand il est possible d'envoyer plus de données.

Le socket utilisé peut nécessiter que le processus ait les privilèges appropriés pour utiliser la fonction send().

VALEUR DE RETOUR

En cas de succès, send() retournera le nombre d'octets envoyés. Sinon, -1 sera retourné et errno sera défini pour indiquer l'erreur.

ERREURS

La fonction send() échouera si :

EAGAIN ou EWOULDBLOCK

Le descripteur de fichier du socket est marqué O_NONBLOCK et l'opération demandée bloquerait.
EBADF
L'argument socket n'est pas un descripteur de fichier valide.
ECONNRESET
Une connexion a été fermée de force par un pair.
EDESTADDRREQ

Le socket n'est pas orienté connexion et aucune adresse de pair n'est définie.
EINTR
Un signal a interrompu send() avant que toute donnée ne soit transmise.
EMSGSIZE
Le message est trop volumineux pour être envoyé en une seule fois, tel que requis par le socket.
ENOTCONN
Le socket n'est pas connecté.
ENOTSOCK
L'argument socket ne fait pas référence à un socket.
EOPNOTSUPP
L'argument socket est associé à un socket qui ne supporte pas une ou plusieurs des valeurs définies dans flags.
EPIPE
Le socket est fermé en écriture, ou le socket est orienté connexion et n'est plus connecté. Dans ce dernier cas, et si le socket est de type SOCK_STREAM ou SOCK_SEQPACKET et que le drapeau MSG_NOSIGNAL n'est pas défini, le signal SIGPIPE est généré au thread appelant.

La fonction send() peut échouer si :

EACCES
Le processus appelant n'a pas les privilèges appropriés.
EIO
Une erreur d'E/S s'est produite lors de la lecture ou de l'écriture dans le système de fichiers.
ENETDOWN
L'interface réseau locale utilisée pour atteindre la destination est hors service.
ENETUNREACH

Aucune route vers le réseau n'est présente.
ENOBUFS
Des ressources insuffisantes étaient disponibles dans le système pour effectuer l'opération.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

Si l'argument socket fait référence à un socket orienté connexion, la fonction send() est équivalente à sendto() (avec n'importe quelle valeur pour les arguments dest_addr et dest_len, car ils sont ignorés dans ce cas). Si l'argument socket fait référence à un socket et que l'argument flags est 0, la fonction send() est équivalente à write().

NAME

send - envoyer un message à un utilisateur

SYNOPSIS

send [options] user [user...]

DESCRIPTION

La commande send est utilisée pour envoyer des messages à d'autres utilisateurs sur le système. Le message est lu à partir de l'entrée standard et envoyé à tous les utilisateurs spécifiés en arguments. Si aucun utilisateur n'est spécifié, le message est envoyé à l'utilisateur courant.

Les options suivantes sont disponibles :

-f, --force
Forcer l'envoi du message, même si l'utilisateur n'est pas connecté.
-s, --subject=SUBJECT
Spécifier un sujet pour le message.
-h, --help
Afficher un message d'aide et quitter.
-v, --version
Afficher des informations sur la version et quitter.

RETURN VALUE

Retourne 0 en cas de succès, une valeur non nulle en cas d'erreur.

ERRORS

send peut échouer pour les raisons suivantes :

  • L'utilisateur spécifié n'existe pas.
  • Les permissions d'envoi de message sont insuffisantes.
  • Erreur lors de la transmission du message.

EXAMPLES

Envoyer un message simple à l'utilisateur "bob" : 

echo "Bonjour Bob !" | send bob

Envoyer un message avec un sujet à plusieurs utilisateurs : 

echo "Réunion demain à 10h." | send -s "Réunion" alice bob charlie

APPLICATION USAGE

Cette commande est principalement destinée à une utilisation interactive par les administrateurs système ou les utilisateurs pour communiquer rapidement entre eux.

RATIONALE

La commande send offre une méthode simple et directe pour envoyer des messages courts aux utilisateurs connectés au système. Elle complète les méthodes de messagerie plus complexes comme le courrier électronique.

FUTURE DIRECTIONS

Il est prévu d'ajouter des fonctionnalités pour permettre l'envoi de messages à des groupes d'utilisateurs et pour gérer un historique des messages envoyés.

SEE ALSO

mail(1), write(1), wall(1). Pour des détails sur les bugs connus, veuillez consulter bugs.html.
