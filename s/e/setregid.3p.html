SETREGID(3P) Manuel du programmeur POSIX SETREGID(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

setregid — définir les identifiants de groupe réels et effectifs

SYNTAXE

#include <unistd.h>
int setregid(gid_t rgid, gid_t egid);

DESCRIPTION

La fonction setregid() définit les identifiants de groupe réels et effectifs du processus appelant.

Si rgid est -1, l'identifiant de groupe réel ne sera pas modifié ; si egid est -1, l'identifiant de groupe effectif ne sera pas modifié.

Les identifiants de groupe réels et effectifs peuvent être définis à des valeurs différentes dans le même appel.

Seul un processus disposant des privilèges appropriés peut définir l'identifiant de groupe réel et l'identifiant de groupe effectif à n'importe quelle valeur valide.

Un processus non privilégié peut définir soit l'identifiant de groupe réel à l'identifiant de groupe sauvegardé par un membre de la famille de fonctions exec, soit l'identifiant de groupe effectif à l'identifiant de groupe sauvegardé ou à l'identifiant de groupe réel.

Si l'identifiant de groupe réel est en cours de définition (rgid n'est pas -1), ou si l'identifiant de groupe effectif est en cours de définition à une valeur différente de l'identifiant de groupe réel, alors l'identifiant de groupe sauvegardé du processus courant sera défini à la valeur du nouvel identifiant de groupe effectif.

Tous les identifiants de groupe supplémentaires du processus appelant restent inchangés.

VALEUR EN RETOUR

En cas de succès, 0 est renvoyé. Sinon, -1 est renvoyé et errno est défini pour indiquer l'erreur, et aucun des identifiants de groupe n'est modifié.

ERREURS

La fonction setregid() échouera si :

EINVAL
La valeur de l'argument rgid ou egid est invalide ou hors limites.
EPERM
Le processus n'a pas les privilèges appropriés et une modification autre que la modification de l'identifiant de groupe réel vers l'identifiant de groupe sauvegardé, ou la modification de l'identifiant de groupe effectif vers l'identifiant de groupe réel ou l'identifiant de groupe sauvegardé, a été demandée.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

Si un processus de groupe défini par un ID non privilégié définit son identifiant de groupe effectif à son identifiant de groupe réel, il ne peut rétablir son identifiant de groupe effectif à la valeur précédente que si rgid était -1 dans l'appel setregid(), car l'identifiant de groupe sauvegardé n'est pas modifié dans ce cas. Si rgid était égal à l'identifiant de groupe réel dans l'appel setregid(), alors l'identifiant de groupe sauvegardé aura également été modifié à l'identifiant utilisateur réel.

RATIONNEL

Les versions antérieures de cette norme ne spécifiaient pas si l'identifiant de groupe sauvegardé était affecté par les appels à setregid(). Cette version spécifie la pratique courante existante qui constitue une fonctionnalité de sécurité importante. La capacité de définir à la fois l'identifiant de groupe effectif et l'identifiant de groupe sauvegardé pour qu'ils soient identiques à l'identifiant de groupe réel signifie qu'aucune faiblesse de sécurité dans le code exécuté après ce point ne peut entraîner l'exécution de code malveillant avec l'identifiant de groupe effectif précédent. Les applications privilégiées pouvaient déjà le faire en utilisant uniquement setgid(), mais pour les applications non privilégiées, la seule méthode standard disponible est d'utiliser cette fonctionnalité de setregid().
