setuid(2) Manuel des appels système setuid(2)

NOM

setuid - définir l'identité utilisateur

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int setuid(uid_t uid);

DESCRIPTION

setuid() définit l'identifiant utilisateur effectif du processus appelant. Si le processus appelant est privilégié (plus précisément : si le processus possède la capacité CAP_SETUID dans son espace de noms d'utilisateur), l'identifiant utilisateur réel et l'identifiant utilisateur enregistré sont également définis.

Sous Linux, setuid() est implémenté comme la version POSIX avec la fonctionnalité _POSIX_SAVED_IDS. Cela permet à un programme avec l'ID utilisateur défini (autre que root) de se défaire de tous ses privilèges utilisateur, d'effectuer un travail non privilégié, puis de réactiver l'identifiant utilisateur effectif d'origine de manière sécurisée.

Si l'utilisateur est root ou si le programme a l'ID utilisateur root défini, une attention particulière doit être accordée : setuid() vérifie l'identifiant utilisateur effectif de l'appelant et s'il s'agit du superutilisateur, tous les identifiants utilisateur liés au processus sont définis sur uid. Une fois cela effectué, il est impossible pour le programme de retrouver les privilèges root.

Ainsi, un programme avec l'ID utilisateur root défini souhaitant se défaire temporairement des privilèges root, assumer l'identité d'un utilisateur non privilégié, puis retrouver les privilèges root par la suite ne peut pas utiliser setuid(). Vous pouvez y parvenir avec seteuid(2).

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est définie pour indiquer l'erreur.

Note : il existe des cas où setuid() peut échouer même lorsque l'appelant est l'UID 0 ; omettre la vérification d'un retour d'échec de setuid() est une grave erreur de sécurité.

ERREURS

EAGAIN
L'appel changerait l'UID réel de l'appelant (c'est-à-dire que uid ne correspond pas à l'UID réel de l'appelant), mais il y a eu une défaillance temporaire dans l'allocation des structures de données noyau nécessaires.
EAGAIN
uid ne correspond pas à l'identifiant utilisateur réel de l'appelant et cet appel dépasserait la limite de ressources RLIMIT_NPROC de l'appelant pour le nombre de processus appartenant à l'identifiant utilisateur réel uid. Depuis Linux 3.1, ce cas d'erreur ne se produit plus (mais les applications robustes devraient vérifier cette erreur) ; voir la description de EAGAIN dans execve(2).
EINVAL
L'identifiant utilisateur spécifié dans uid n'est pas valide dans cet espace de noms d'utilisateur.
EPERM
L'utilisateur n'est pas privilégié (Linux : ne possède pas la capacité CAP_SETUID dans son espace de noms d'utilisateur) et uid ne correspond pas à l'UID réel ou à l'ID utilisateur enregistré de l'appelant.

VERSIONS

DIFFÉRENCES BIBLIOTHÈQUE C/NOYAU

Au niveau du noyau, les identifiants utilisateur et groupe sont des attributs par fil d'exécution. Cependant, POSIX exige que tous les fils d'exécution d'un processus partagent les mêmes identifiants. L'implémentation de threading NPTL gère les exigences POSIX en fournissant des fonctions d'encapsulation pour les différents appels système qui modifient les identifiants utilisateur et groupe du processus. Ces fonctions d'encapsulation (y compris celle pour setuid()) utilisent une technique basée sur les signaux pour garantir que lorsqu'un fil d'exécution modifie les identifiants, tous les autres fils d'exécution du processus modifient également leurs identifiants. Pour plus de détails, voir nptl(7).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Pas tout à fait compatible avec l'appel 4.4BSD, qui définit tous les identifiants utilisateur réels, enregistrés et effectifs.

L'appel système setuid() original sous Linux ne prenait en charge que les identifiants utilisateur 16 bits. Par la suite, Linux 2.4 a ajouté setuid32() prenant en charge les identifiants 32 bits. La fonction d'encapsulation setuid() de glibc gère de manière transparente les variations entre les versions du noyau.

NOTES

Linux a le concept d'identifiant utilisateur du système de fichiers, normalement égal à l'identifiant utilisateur effectif. L'appel setuid() définit également l'identifiant utilisateur du système de fichiers du processus appelant. Voir setfsuid(2).

Si uid est différent de l'ancien UID effectif, le processus sera interdit de générer des vidages de noyau.

VOIR AUSSI

getuid(2), seteuid(2), setfsuid(2), setreuid(2), capabilities(7), credentials(7), user_namespaces(7)
