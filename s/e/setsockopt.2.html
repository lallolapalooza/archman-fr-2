getsockopt(2) Manuel des appels système getsockopt(2)

NOM

getsockopt, setsockopt — obtenir et définir des options sur des sockets

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/socket.h>
int getsockopt(socklen_t *restrict optlen;
               int sockfd, int level, int optname,
               void optval[_Nullable restrict *optlen],
               socklen_t *restrict optlen);
int setsockopt(socklen_t optlen;
               int sockfd, int level, int optname,
               const void optval[optlen],
               socklen_t optlen);

DESCRIPTION

getsockopt() et setsockopt() manipulent les options du socket auquel fait référence le descripteur de fichier sockfd. Les options peuvent exister à plusieurs niveaux de protocole ; elles sont toujours présentes au niveau le plus élevé du socket.

Lors de la manipulation des options de socket, le niveau auquel réside l'option et le nom de l'option doivent être spécifiés. Pour manipuler les options au niveau de l'API des sockets, level est spécifié comme SOL_SOCKET. Pour manipuler les options à tout autre niveau, le numéro de protocole du protocole approprié contrôlant l'option est fourni. Par exemple, pour indiquer qu'une option doit être interprétée par le protocole TCP, level doit être défini sur le numéro de protocole de TCP ; voir getprotoent(3).

Les arguments optval et optlen sont utilisés pour accéder aux valeurs d'option pour setsockopt(). Pour getsockopt(), ils identifient un tampon dans lequel la valeur pour l'option(s) demandée(s) doit être retournée. Pour getsockopt(), optlen est un argument valeur-résultat, contenant initialement la taille du tampon pointé par optval, et modifié au retour pour indiquer la taille réelle de la valeur retournée. Si aucune valeur d'option ne doit être fournie ou retournée, optval peut être NULL.

Optname et les options spécifiées sont passés sans interprétation au module de protocole approprié pour interprétation. Le fichier d'en-tête <sys/socket.h> contient les définitions des options au niveau du socket, décrites ci-dessous. Les options à d'autres niveaux de protocole varient en format et en nom ; consultez les entrées appropriées dans la section 4 du manuel.

La plupart des options au niveau du socket utilisent un argument int pour optval. Pour setsockopt(), l'argument doit être différent de zéro pour activer une option booléenne, ou zéro si l'option doit être désactivée.

Pour une description des options de socket disponibles, voir socket(7) et les pages de manuel des protocoles appropriés.

VALEUR DE RETOUR

En cas de succès, zéro est retourné pour les options standard. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

Netfilter permet au programmeur de définir des options de socket personnalisées avec des gestionnaires associés ; pour de telles options, la valeur de retour en cas de succès est la valeur retournée par le gestionnaire.

ERREURS

EBADF
L'argument sockfd n'est pas un descripteur de fichier valide.
EFAULT
L'adresse pointée par optval ne se trouve pas dans une partie valide de l'espace d'adressage du processus. Pour getsockopt(), cette erreur peut également être retournée si optlen ne se trouve pas dans une partie valide de l'espace d'adressage du processus.
EINVAL
optlen invalide dans setsockopt(). Dans certains cas, cette erreur peut également survenir pour une valeur invalide dans optval (par exemple, pour l'option IP_ADD_MEMBERSHIP décrite dans ip(7)).
ENOPROTOOPT
L'option est inconnue au niveau indiqué.
ENOTSOCK
Le descripteur de fichier sockfd ne fait pas référence à un socket.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD (est apparu pour la première fois dans 4.2BSD).

BOGUES

Plusieurs des options de socket devraient être gérées à des niveaux inférieurs du système.

VOIR AUSSI

ioctl(2), socket(2), getprotoent(3), protocols(5), ip(7), packet(7), socket(7), tcp(7), udp(7), unix(7)
