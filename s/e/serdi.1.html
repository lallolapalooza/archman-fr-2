SERDI(1) Manuel des commandes générales SERDI(1)

NOM

serdi — lire et écrire la syntaxe RDF

SYNTAXE

serdi [-abefhlqv] [-c préfixe] [-i syntaxe] [-o syntaxe] [-p préfixe] [-r racine] [-s chaîne] entrée [uri_base]

DESCRIPTION

serdi est un utilitaire rapide en ligne de commande pour le traitement et le flux de données RDF. Il lit un document RDF et écrit les données sur la sortie standard, éventuellement transformées et/ou dans une syntaxe différente. Par défaut, la syntaxe d'entrée est devinée à partir de l'extension du fichier, et la sortie est écrite en NTriples ou NQuads.

serdi peut être utilisé pour vérifier les erreurs de syntaxe, convertir d'une syntaxe à une autre, formater joliment les documents, ou transformer les URI et les identifiants de nœuds vides.

Les options sont les suivantes :

-a
Sortie ASCII. Si cette option est activée, tous les caractères non ASCII seront échappés, même si la syntaxe de sortie les autorise en UTF-8.
-b
Écriture de sortie en bloc. Si cette option est activée, la sortie sera écrite page par page, plutôt qu'octet par octet.
-c préfixe
Supprime le préfixe des identifiants de nœuds vides correspondants. Ceci est généralement utilisé pour annuler les effets de -p. Par exemple, avec le préfixe « doc01 », le nœud vide _:doc01b42 sera émis sous la forme _:b42.
-e
Lit l'entrée caractère par caractère, plutôt que page par page comme par défaut. Ceci est utile lors de la lecture à partir d'un tube, car la sortie sera générée immédiatement à mesure que l'entrée arrive, plutôt que d'attendre qu'une page entière d'entrée soit arrivée. Avec cette option, serdi utilise une page de mémoire en moins, mais sera probablement significativement plus lent.
-f
Mode URI rapide et souple : conserve les URI complets (sans qualifier ni rendre relatifs) et transmet les noms préfixés tels quels.
-h
Affiche les options de la ligne de commande.
-i syntaxe
Lit l'entrée en tant que syntaxe. La casse est ignorée, les valeurs valides sont : « NQuads », « NTriples », « TriG », « Turtle ».
-l
Analyse souple (non stricte). Si cette option est activée, les erreurs de syntaxe récupérables afficheront un avertissement, mais l'analyse continuera à partir de l'instruction suivante si possible. Notez que des données peuvent être perdues lors de l'utilisation de cette option.
-o syntaxe
Écrit la sortie en tant que syntaxe. La casse est ignorée, les valeurs valides sont : « NQuads », « NTriples », « TriG », « Turtle ».
-p préfixe
Ajoute un préfixe aux identifiants de nœuds vides. Ceci peut être utilisé pour éviter les conflits entre les identifiants de nœuds vides dans les documents d'entrée. Les effets peuvent être inversés dans une exécution ultérieure avec -c. Par exemple, avec le préfixe « doc01 », le nœud vide _:b42 sera émis sous la forme _:doc01b42.
-q
Supprime toute sortie sauf les données.
-r racine
Conserve les URI relatifs à l'intérieur d'une URI de racine. Cela évitera de créer des références URI relatives avec des segments de chemin menant à un parent de racine, tels que ../.

Par exemple, si /home/vous/fichier.ttl est écrit dans le fichier /home/moi/sortie.ttl en utilisant l'URI de base de la destination, il pourrait être écrit comme <../vous/fichier.ttl>. La définition de -r file:///home/moi/ empêcherait les références de « s'échapper » ainsi, donc ce qui précède serait plutôt écrit comme <file:///home/vous/fichier.ttl>, car il ne peut pas être exprimé relativement à l'URI de racine.

Ceci est utile pour conserver les références relatives à l'intérieur d'un répertoire.

-s chaîne
Analyse l'entrée chaîne au lieu d'un fichier (termine les options).
-v
Affiche les informations de version et quitte.

CODE DE SORTIE

serdi se termine avec un statut de 0, ou un statut non nul si une erreur s'est produite.

EXEMPLES

Pour formater joliment un document :
serdi -o turtle fichier.ttl > out.ttl
Pour afficher toutes les erreurs :
serdi fichier.ttl > /dev/null
