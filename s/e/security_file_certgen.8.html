NOM

security_file_certgen - Générateur de certificats SSL pour Squid.

Version 1.1

SYNTAXE

security_file_certgen [-cdhv] [-s répertoire -M taille ] [-b taille_bloc_fs ]

DESCRIPTION

security_file_certgen est un binaire installé.

Étant donné que la génération et la signature des certificats SSL prennent du temps, Squid peut utiliser cette application externe comme aide pour gérer le travail. La communication se fait via des sockets TCP liés à l'interface de bouclage. Cette aide peut utiliser un cache sur disque des certificats pour améliorer les temps de réponse lors des requêtes répétées. Elle peut également fonctionner sans cache, générant de nouveaux certificats à chaque requête.

OPTIONS

-b taille_bloc_fs
Taille du bloc du système de fichiers en octets. Nécessaire pour le traitement de la taille naturelle d'un certificat sur disque. La valeur par défaut est de 2048 octets. Les suffixes suivants sont acceptés : B, KB, MB, GB. Lorsqu'aucun suffixe n'est défini, B est supposé.
-c
Initialise la base de données de stockage SSL et quitte. Nécessite les options -s et -M pour déterminer l'emplacement et la taille du stockage à créer.
-d
Écrit les informations de débogage sur la sortie d'erreur standard.
-h
Affiche l'aide du binaire et les informations de syntaxe de la ligne de commande sur la sortie d'erreur standard.
-s répertoire
Chemin du répertoire de la base de données de stockage SSL. Nécessite l'option -M.
-M taille
Taille maximale du stockage des certificats SSL sur disque. Les mêmes suffixes supportés par l'option -b peuvent être utilisés.
-v
Affiche les détails de la version du binaire sur la sortie d'erreur standard.

PROBLEMES CONNUS

Erreurs SSL après changement de l'AC

Les certificats sont stockés dans cette base de données sous forme signée. Après toute modification de l'AC de signature dans squid.conf, assurez-vous d'effacer et de réinitialiser la base de données des certificats.

Chaînage de certificats

Les versions 1.0 à 1.1 de cette aide n'ajouteront pas de certificats d'AC intermédiaires chaînés. Le client doit disposer d'une chaîne de confiance complète, de l'AC racine jusqu'au certificat final généré par ce programme. La signature avec une AC intermédiaire nécessite d'installer les AC publiques, racine et intermédiaire, sur les clients.

CONFIGURATION

Avant que cette aide puisse être utilisée avec le stockage sur disque, la zone de stockage pour les nouveaux certificats doit être initialisée manuellement. Ceci est fait depuis la ligne de commande en utilisant le paramètre -c.

Par exemple :

/usr/lib/squid/security_file_certgen -c -s /var/cache/squid/ssl_db -M 4MB

Les certificats sont stockés dans cette base de données sous forme signée. Après toute modification de l'AC de signature dans squid.conf, assurez-vous d'effacer et de réinitialiser la base de données des certificats.

Pour une configuration simple, les valeurs par défaut de l'aide peuvent être utilisées. Seules les options du port d'écoute HTTP sont nécessaires pour activer la génération et définir le certificat CA de signature.

Par exemple :

http_port 3128 ssl-bump generate-host-certificates=on dynamic_cert_mem_cache_size=4MB cert=/etc/squid/ssl_cert/example.com.pem

Pour une configuration plus personnalisée, l'emplacement du répertoire de stockage des certificats de l'aide et sa taille peuvent être modifiés avec la directive de configuration sslcrtd_program. Le nombre de processus d'aide en cours d'exécution peut être configuré avec la directive de configuration ssl_crtd_children.

Par exemple :

sslcrtd_program /usr/lib/squid/security_file_certgen -s /var/cache/squid/ssl_db -M 4MB
sslcrtd_children 5

Pour fonctionner sans stockage sur disque, l'aide doit être configurée explicitement sans les paramètres -s et -M.

Par exemple :

sslcrtd_program /usr/lib/squid/security_file_certgen
