NOM

seccomp_attr_set, seccomp_attr_get - Gérer les attributs du filtre seccomp

SYNTAXE

#include <seccomp.h>

typedef void * scmp_filter_ctx;
enum scmp_filter_attr;

int seccomp_attr_set(scmp_filter_ctx ctx,
                     enum scmp_filter_attr attr, uint32_t value);
int seccomp_attr_get(scmp_filter_ctx ctx,
                     enum scmp_filter_attr attr, uint32_t *value);

Lier avec -lseccomp.

DESCRIPTION

La fonction seccomp_attr_set() définit les différents attributs du filtre seccomp tandis que la fonction seccomp_attr_get() récupère les attributs du filtre. Les attributs du filtre seccomp sont des valeurs ajustables qui affectent le comportement de la bibliothèque lors de la génération et du chargement du filtre seccomp dans le noyau. Les attributs sont réinitialisés à leurs valeurs par défaut chaque fois que le filtre est initialisé ou réinitialisé via seccomp_init(3) ou seccomp_reset(3).

Le contexte de filtre ctx est la valeur retournée par l'appel à seccomp_init(3).

Les valeurs valides de attr sont les suivantes :

SCMP_FLTATR_ACT_DEFAULT
L'action de filtre par défaut telle que spécifiée dans l'appel à seccomp_init(3) ou seccomp_reset(3). Cet attribut est en lecture seule.
SCMP_FLTATR_ACT_BADARCH
L'action de filtre appliquée lorsque le filtre chargé ne correspond pas à l'architecture de l'application en cours d'exécution. Par défaut, l'action est SCMP_ACT_KILL.
SCMP_FLTATR_CTL_NNP
Un drapeau pour spécifier si la fonctionnalité NO_NEW_PRIVS doit être activée avant de charger le filtre seccomp dans le noyau. Le régler sur inactif ( value == 0) n'entraîne aucune action, ce qui signifie que le chargement du filtre seccomp dans le noyau échouera si CAP_SYS_ADMIN est manquant et que NO_NEW_PRIVS n'a pas été défini extérieurement. Par défaut, il est actif ( value == 1).
SCMP_FLTATR_CTL_TSYNC
Un drapeau pour spécifier si le noyau doit tenter de synchroniser les filtres sur tous les threads lors de seccomp_load(3). Si le noyau ne parvient pas à synchroniser tous les threads, l'opération de chargement échouera. Ce drapeau n'est disponible qu'à partir du noyau Linux 3.17 ; tenter d'activer ce drapeau sur des noyaux antérieurs entraînera une erreur. Par défaut, il est inactif ( value == 0).
SCMP_FLTATR_API_TSKIP
Un drapeau pour spécifier si libseccomp doit autoriser la création de règles de filtre pour l'appel système -1. La valeur d'appel système -1 peut être utilisée par les programmes de traçage pour ignorer des invocations d'appels système spécifiques, voir seccomp(2) pour plus d'informations. Par défaut, il est inactif ( value == 0).
SCMP_FLTATR_CTL_LOG
Un drapeau pour spécifier si le noyau doit journaliser toutes les actions de filtre effectuées, à l'exception de l'action SCMP_ACT_ALLOW. Par défaut, il est inactif ( value == 0).
SCMP_FLTATR_CTL_SSB
Un drapeau pour désactiver les atténuations Speculative Store Bypass pour ce filtre. Par défaut, il est inactif ( value == 0).
SCMP_FLTATR_CTL_OPTIMIZE
Un drapeau pour spécifier le niveau d'optimisation du filtre seccomp. Par défaut, libseccomp génère un ensemble d'instructions ´if´ séquentielles pour chaque règle du filtre. seccomp_syscall_priority(3) peut être utilisé pour prioriser l'ordre pour la cause par défaut. L'optimisation par arbre binaire trie par numéros d'appels système et génère une traversée de filtre cohérente en O(log n) pour chaque règle du filtre. L'arbre binaire peut être avantageux pour les filtres volumineux. Notez que seccomp_syscall_priority(3) est ignoré lorsque SCMP_FLTATR_CTL_OPTIMIZE == 2.

Les différents niveaux d'optimisation sont décrits ci-dessous :

0
Valeur réservée, non utilisée actuellement.
1
Règles triées par priorité et complexité (PAR DÉFAUT).
2
Arbre binaire trié par numéro d'appel système.
SCMP_FLTATR_API_SYSRAWRC
Un drapeau pour spécifier si libseccomp doit renvoyer les codes d'erreur système à l'appelant au lieu de -ECANCELED par défaut. Par défaut, il est inactif ( value == 0).

VALEUR DE RETOUR

Retourne zéro en cas de succès ou l'un des codes d'erreur suivants en cas d'échec :

-EACCES
La définition de l'attribut avec la valeur donnée n'est pas autorisée.
-EEXIST
L'attribut n'existe pas.
-EINVAL
Entrée invalide, soit le contexte, soit le jeton d'architecture est invalide.
-EOPNOTSUPP
La bibliothèque ne prend pas en charge l'opération particulière.

EXEMPLES

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_ALLOW);
	if (ctx == NULL)
		goto out;
	/* ... */
	rc = seccomp_attr_set(ctx, SCMP_FLTATR_ACT_BADARCH, SCMP_ACT_TRAP);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTES

Bien que le filtre seccomp puisse être généré indépendamment du noyau, un support du noyau est requis pour charger et appliquer le filtre seccomp généré par libseccomp.

Le site du projet libseccomp, avec plus d'informations et le dépôt de code source, se trouve sur https://github.com/seccomp/libseccomp. Cet outil, ainsi que la bibliothèque libseccomp, sont actuellement en cours de développement, veuillez signaler tout bogue sur le site du projet ou directement à l'auteur.
