NOM

svnserve - Serveur pour la méthode d'accès aux dépôts 'svn'

SYNTAXE

svnserve [options]

DESCRIPTION

svnserve permet d'accéder aux dépôts Subversion en utilisant le protocole réseau svn. Il peut s'exécuter comme un processus serveur autonome, ou être lancé depuis inetd. Vous devez choisir un mode de fonctionnement lorsque vous démarrez svnserve. Les options suivantes sont reconnues :

-d, --daemon
Indique à svnserve de s'exécuter en mode démon. svnserve se met en arrière-plan et accepte et gère les connexions TCP/IP sur le port svn (3690 par défaut).
--listen-port=port
Indique à svnserve d'écouter sur le port port lorsqu'il est exécuté en mode démon.
--listen-host=hôte
Indique à svnserve d'écouter sur l'interface spécifiée par hôte, qui peut être soit un nom d'hôte, soit une adresse IP.
--foreground
Lorsqu'elle est utilisée avec -d, cette option indique à svnserve de rester au premier plan. Cette option est principalement utile pour le débogage.
-i, --inetd
Indique à svnserve d'utiliser les descripteurs de fichiers stdin/stdout, comme il convient pour un démon exécuté depuis inetd.
-h, --help
Affiche un résumé de l'utilisation et quitte.
--version
Affiche la version de svnserve et le(s) backend(s) de système de fichiers de dépôt pris en charge par une instance particulière de svnserve.
-r root, --root=root
Définit la racine virtuelle pour les dépôts servis par svnserve. Le chemin dans les URL fournies par le client sera interprété par rapport à cette racine, et ne sera pas autorisé à en sortir.
-R --read-only
Force toutes les opérations d'écriture via cette instance de svnserve à être interdites, ignorant toute autre configuration de politique d'accès. N'utilisez pas cette option pour définir une politique générale d'accès aux dépôts - c'est à cela que sert le fichier de configuration du dépôt conf/svnserve.conf. Cette option doit être utilisée uniquement pour restreindre l'accès via une méthode particulière d'invocation de svnserve - par exemple, pour autoriser l'accès en écriture via SSH, mais pas via un démon svnserve, ou pour créer une clé SSH restreinte qui n'est capable que d'accès en lecture.
-t, --tunnel
Indique à svnserve de s'exécuter en mode tunnel, qui est identique au mode de fonctionnement inetd (servir une connexion sur stdin/stdout) à la différence près que la connexion est considérée comme pré-authentifiée avec le nom d'utilisateur de l'UID courant. Ce drapeau est sélectionné par le client lorsqu'il s'exécute sur un agent tunnel.
--tunnel-user=nomutilisateur
Lorsqu'il est combiné avec --tunnel, remplace le nom d'utilisateur pré-authentifié par le nomutilisateur fourni. Ceci est utile en combinaison avec la directive "command" du fichier authorized_key SSH pour permettre à un compte système unique d'être utilisé par plusieurs commiteurs, chacun ayant une identité SSH distincte.
-T, --threads
Lors de l'exécution en mode démon, indique à svnserve de créer un thread au lieu d'un processus pour chaque connexion. Le processus svnserve se met toujours en arrière-plan au démarrage.
--config-file=nomfichier
Lorsqu'il est spécifié, svnserve lit le fichier nomfichier une fois au démarrage du programme et met en cache la configuration de svnserve. Les configurations de mot de passe et d'autorisation référencées depuis nomfichier seront chargées à chaque connexion. svnserve ne lira aucun fichier conf/svnserve.conf par dépôt lorsque cette option est utilisée. Voir la page man svnserve.conf(5) pour les détails du format de fichier pour cette option.
--pid-file=nomfichier
Lorsqu'il est spécifié, svnserve écrira son ID de processus dans nomfichier.
-X, --listen-once
Indique à svnserve d'accepter une connexion sur le port svn, de la servir, puis de quitter. Cette option est principalement utile pour le débogage.

Sauf si l'option --config-file a été spécifiée en ligne de commande, une fois que le client a sélectionné un dépôt en transmettant son URL, svnserve lit un fichier nommé conf/svnserve.conf dans le répertoire du dépôt pour déterminer les paramètres spécifiques au dépôt, tels que la base de données d'authentification à utiliser et les politiques d'autorisation à appliquer. Voir la page man svnserve.conf(5) pour les détails de ce format de fichier.
