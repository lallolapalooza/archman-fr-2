NOM

svsematest - Démarre deux threads ou crée deux processus et mesure la latence des sémaphores SYSV

SYNTAXE

svsematest [-a|--affinity NUM] [-b|--breaktrace USEC] [-d|--distance DIST] [-D|--duration TIME] [-f|--fork [OPT]] [-i|--interval INTV] [--json FILENAME] [-l|--loops LOOPS] [-p|--prio PRIO] [-q|--quiet] [-S|--smp] [-t|--threads [NUM]]

DESCRIPTION

Le programme svsematest démarre deux threads ou, facultativement, crée deux processus qui sont synchronisés via des sémaphores SYSV et mesure la latence entre la libération d'un sémaphore d'un côté et son obtention de l'autre côté.

OPTIONS

-a, --affinity[=NUM]
Exécuter sur le processeur numéro NUM. Si PROC n'est pas spécifié, exécuter sur le processeur actuel.
-b, --breaktrace=USEC
Envoie la commande break trace lorsque la latence est > USEC. Ceci est une option de débogage pour contrôler le traceur de latence dans le patch de préemption temps réel. Il est utile pour identifier les latences inattendument grandes d'un système.
-d, --distance=DIST
Définit la distance des intervalles des threads en microsecondes (par défaut 500 µs). Lorsque cyclictest est appelé avec l'option -t et que plus d'un thread est créé, alors cette valeur de distance est ajoutée à l'intervalle des threads : Interval(thread N) = Interval(thread N-1) + DIST
-D, --duration=TIME
Spécifie une durée pour l'exécution du test.
Ajoutez 'm', 'h', ou 'd' pour spécifier des minutes, heures ou jours.
-f, --fork
Au lieu de créer des threads (ce qui est le comportement par défaut), crée de nouveaux processus par fork.
-i, --interval=INTV
Définit l'intervalle de base du ou des threads en microsecondes (par défaut 1000 µs). Ceci définit l'intervalle du premier thread. Voir aussi -d.
--json=FILENAME
Écrit les résultats finaux dans FILENAME, au format JSON.
-l, --loops=LOOPS
Définit le nombre de boucles. La valeur par défaut est 0 (sans fin). Cette option est utile pour les tests automatisés avec un nombre donné de cycles de test. svsematest s'arrête une fois que le nombre d'intervalles de minuteur a été atteint.
-p, --prio=PRIO
Définit la priorité du processus.
-q, --quiet
N'affiche qu'un résumé à la sortie. Utile pour les tests automatisés, où seul le résumé de sortie doit être capturé.
-S, --smp
Test SMP : options -a -t et même priorité pour tous les threads
-t, --threads[=NUM]
Définit le nombre de threads de test (par défaut 1, si cette option n'est pas fournie). Si NUM est spécifié, crée NUM threads de test. Si NUM n'est pas spécifié, NUM est défini au nombre de CPU disponibles.

EXEMPLES

L'exemple suivant a été exécuté sur un CPU à 4 cœurs :
