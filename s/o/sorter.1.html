SORTER(1) Manuel des commandes générales SORTER(1)

NOM

sorter - Trier des fichiers dans une image selon leur type

SYNTAXE

[-b taille ] [-e] [-E] [-h] [-l] [-md5] [-s] [-sha1] [-U] [-v] [-V] [-a alerte_hash ] [-c config ] [-C config ] [-d rep ] [-m mnt ] [-n db_nsrl ] [-x hash_exclu ] [-i typeimg ] [-o offsetimg ] [-f typefs ] image [image] [addr_meta]

DESCRIPTION

sorter est un script Perl qui analyse un système de fichiers pour organiser les fichiers alloués et non alloués par type de fichier. Il exécute la commande 'file' sur chaque fichier et organise les fichiers selon les règles des fichiers de configuration. La comparaison des extensions est également effectuée pour identifier les fichiers 'cachés'. On peut également fournir des bases de données de hachages pour les fichiers connus pour être valides et qui peuvent être ignorés, ainsi que pour les fichiers connus pour être invalides et qui devraient déclencher une alerte.

Par défaut, le programme utilise les fichiers de configuration du répertoire où The Sleuth Kit a été installé. Ceux-ci peuvent être remplacés par des options d'exécution. Il existe un fichier de configuration standard pour tous les types de systèmes de fichiers, puis un spécifique pour un système d'exploitation donné.

ARGUMENTS

Les arguments requis sont les suivants. Ceci analysera une ou plusieurs images et enregistrera les résultats dans le répertoire '-d' ou listera les résultats sur STDOUT (si '-l' est spécifié).

-d rep
Spécifie l'emplacement où tous les fichiers doivent être écrits. Cela inclut les fichiers d'index et les sous-répertoires si l'indicateur '-s' est spécifié. Ceci DOIT être spécifié, à moins que l'indicateur de liste '-l' soit spécifié.
-l
Liste les informations sur STDOUT (aucun fichier n'est jamais écrit). Ceci est utile pour la Réponse à Incident, avec l'utilisation de 'netcat'. Ceci ne peut pas être utilisé si '-d' est utilisé.
image [images]
L'image disque ou partition à lire, dont le format est donné avec '-i'. Plusieurs noms de fichiers image peuvent être donnés si l'image est divisée en plusieurs segments. Si un seul fichier image est donné, et que son nom est le premier d'une séquence (par exemple, se terminant par '.001'), les segments d'image suivants seront inclus automatiquement.

Les options sont les suivantes :

-f typefs
Spécifie le type de système de fichiers de l'image(s). C'est le même type que celui utilisé par The Sleuth Kit.
-i typeimg
Spécifie le type d'image dans lequel se trouve le système de fichiers. C'est le même type que celui utilisé par The Sleuth Kit.
-o offsetimg
Spécifie le décalage de secteur depuis le début de l'image jusqu'au début du système de fichiers.
-b taille
Spécifie la taille minimale de fichier à traiter. Tous les fichiers de taille inférieure seront ignorés.
-c config
Spécifie l'emplacement d'un fichier de configuration supplémentaire. Ce fichier sera chargé en plus de ceux standard dans le répertoire d'installation. Ces paramètres auront la priorité sur les fichiers standards.
-C config
Spécifie l'emplacement du SEUL fichier de configuration. Les fichiers de configuration standard ne seront pas chargés si cette option est donnée. Par exemple, dans le répertoire 'share/sort', il y a un fichier appelé 'images.sort'. Ce fichier ne contient que des règles concernant les images graphiques. S'il est spécifié avec -C, alors seules les images seront enregistrées concernant l'image.
-m mnt
Spécifie le point de montage de l'image analysée. Ceci est uniquement pour des raisons cosmétiques. Lorsque les entrées dans les fichiers de sortie seront écrites, les fichiers auront le chemin complet au lieu du simple chemin relatif. Si ceci est spécifié, alors une seule image peut être donnée.
-a alerte_hash
Spécifie l'emplacement d'une base de données de hachages contenant des entrées de fichiers 'mauvais' connus. Si un fichier est trouvé avec une valeur de hachage MD5 dans cette base de données, il sera placé dans un fichier d'alerte spécial. Cette base de données doit avoir été indexée pour MD5 à l'aide de 'hfind' dans The Sleuth Kit avant d'être utilisée par sorter.
-n db_nsrl
Spécifie l'emplacement de la base de données du NIST National Software Reference Library (NSRL) (www.nsrl.nist.org). Tout fichier trouvé dans le NSRL sera ignoré et ne sera pas classé dans une catégorie. La base de données doit être indexée pour MD5 avec 'hfind' dans The Sleuth Kit avant d'être utilisée par sorter. Le fichier de base de données s'appelle actuellement 'NSRLFile.txt'.
-x hash_exclu
Spécifie l'emplacement d'une base de données de hachages contenant des entrées de fichiers 'bons' connus. Si un fichier est trouvé avec une valeur de hachage MD5 dans cette base de données, il sera ignoré et ne sera pas traité ni sauvegardé dans les fichiers de catégorie. Cette base de données doit avoir été indexée pour MD5 à l'aide de 'hfind' dans The Sleuth Kit avant d'être utilisée par sorter.
-e
Effectuer des vérifications d'incompatibilité d'extension (aucun fichier d'index de catégorie n'est généré)
-U
Ne pas enregistrer les données sur les types de fichiers inconnus. Par défaut, un fichier 'unknown' est créé pour les fichiers dont la sortie de 'file' est inconnue. Ceci permet d'affiner sa configuration. Si ce n'est pas souhaité, utiliser cet indicateur.
-h
Créer des fichiers de catégorie en HTML
-md5
Calculer la valeur MD5 pour chaque fichier et l'enregistrer dans le fichier de catégorie. Ceci sera fait automatiquement lorsque l'une des bases de données sera fournie.
-sha1
Calculer la valeur SHA-1 pour chaque fichier et l'enregistrer dans le fichier de catégorie.
-s
Enregistrer le contenu réel du fichier dans des sous-répertoires dans le répertoire spécifié par '-d'. Par exemple, tous les fichiers JPG et GIF seraient effectivement enregistrés dans le répertoire 'images'. Si '-h' est également spécifié, des miniatures d'images graphiques sont également créées.
-v
Afficher des informations détaillées
-V
Afficher la version.
[addr_meta]
L'adresse des métadonnées du répertoire à partir duquel commencer. Par défaut, le répertoire racine est utilisé. Si ceci est spécifié, alors une seule image peut être donnée.

APERÇU DE HAUT NIVEAU DU PROCESSUS

sorter est un script Perl qui interagit avec d'autres outils de The Sleuth Kit. Il commence par lire les fichiers de configuration du répertoire d'installation. Il y a un fichier de configuration général et un spécifique pour chaque système d'exploitation. Le spécifique est déterminé par l'indicateur '-f'. Chaque fichier de configuration contient des règles pour traiter la sortie de la commande 'file'. Un type de ligne identifie à quelle catégorie (par exemple, 'images') appartient une sortie donnée de 'file' (par exemple, 'données d'image') (en utilisant des expressions régulières). Une autre règle montre les extensions de fichiers (par exemple, .txt) qui appartiennent à une sortie 'file' (par exemple, texte ASCII(.*?)text). Voir la section Règles ci-dessous.

Le programme exécute ensuite l'outil 'fls' de The Sleuth Kit pour identifier les fichiers dans l'image du système de fichiers. Chaque fichier identifié est visualisé à l'aide de l'outil 'icat'. Si une base de données de hachages est fournie, le hachage du fichier est calculé et recherché. S'il est trouvé dans une base de données 'alerte', il est ajouté à un fichier spécial 'alert.txt'. S'il est trouvé dans la base NSRL ou la base de données 'exclude', il est ignoré en tant que fichier bon connu. Les fichiers exclus sont enregistrés dans un fichier 'exclude' pour référence future mais ne sont pas enregistrés dans les fichiers de catégorie.

La commande 'file' est ensuite exécutée pour identifier le type de fichier (basé sur les informations d'en-tête). Les règles du fichier de configuration sont utilisées pour identifier à quelle catégorie il appartient. Une entrée est ajoutée au fichier de catégorie correspondant (dans le répertoire '-d rep'). Si l'indicateur '-s' est spécifié, une copie du fichier est enregistrée dans un sous-répertoire portant le même nom que la catégorie. Si le format HTML est utilisé, des hyperliens permettront de visualiser facilement les fichiers enregistrés et de voir ce que contient chaque catégorie.

Les fichiers qui n'ont pas de catégorie sont enregistrés dans la catégorie 'unknown' et la catégorie 'data'. 'data' concerne les fichiers dont la structure est inconnue de 'file' et 'unknown' concerne les fichiers dont la structure est connue de 'file'. Ceux-ci sont enregistrés pour le futur

sorter(1) - The Sleuth Kit

NOM

sorter - Classify files based on hash databases and file types

SYNOPIS

sorter [-a hashdb] [-c config] [-C] [-d dir] [-f fstype] [-h] [-H] [-i raw] [-l] [-n hashdb] [-o offset] [-s] [-S] [-t] [-U] [-v] [-x hashdb] image [images...]

DESCRIPTION

The sorter program is a tool that will examine files and classify them into categories. It uses hash databases to identify known files and file type rules to identify unknown files. This tool is primarily used to find files of interest in a file system image.

The file system type (-f) must be specified. The supported file system types are:

  • fst - Any file system
  • raw - Raw data, use with -o to specify offset
  • ewf - EnCase file format
  • aff - Advanced Forensics Format
  • dd - Disk image (same as raw)
  • ntfs - New Technology File System
  • fat - File Allocation Table
  • ufs - Unix File System
  • ext2 - Second Extended File System
  • ext3 - Third Extended File System
  • ext4 - Fourth Extended File System
  • hfs - Hierarchical File System
  • hfs+ - Hierarchical File System Plus
  • iso9660 - ISO 9660 CD-ROM file system

The sorter tool will process the specified file system image and attempt to classify each file it finds. The classification is based on whether the file is found in any of the hash databases or if it matches a file type rule.

ARGUMENTS

-a hashdb
Adds a hash database to be used for identifying known good files. Multiple -a flags can be used.
-c config
Specifies an additional configuration file to use. If this flag is used, the default configuration files will also be used unless the -C flag is also used.
-C
Use only the specified configuration file(s). If this flag is used, no default configuration files will be used.
-d dir
Specifies the directory where the classified files will be stored. Subdirectories will be created for each category.
-f fstype
Specifies the file system type of the image. This argument is required.
-h
This flag is used to turn off the checking of hash databases. Only file type rules will be used.
-H
This flag is used to turn off the checking of file type rules. Only hash databases will be used.
-i raw
Specifies the image file format. Supported formats are raw, ewf, and aff. This is used if the file system type cannot be determined automatically.
-l
List all of the files and their categories. Do not save any files.
-n hashdb
Adds a hash database to be used for identifying known good files. This is the default database used by many forensic tools. Multiple -n flags can be used.
-o offset
The offset into the image file where the file system begins. This is used for raw images that are not a full disk image.
-s
Save the classified files to disk. Files will be saved in subdirectories named after their category.
-S
This flag tells sorter to save all files to the directory specified with the -d flag. This is used to save all files that would otherwise be ignored.
-t
This flag tells sorter to only process files that have been deleted.
-U
Ignore files with unknown categories. By default, files with unknown categories are saved to a category named 'unknown'.
-v
Verbose output. Prints more information about the files being processed.
-x hashdb
Adds a hash database to be used for identifying known bad files (e.g., rootkits, viruses). Multiple -x flags can be used.

HIGH-LEVEL OVERVIEW OF PROCESS

The sorter program will process the specified image file and, for each file found, it will first check against any provided hash databases. If a hash match is found, the file is assigned to the category associated with that hash database. Known good files are typically placed in categories like 'known' or 'good'. Known bad files are placed in categories like 'bad' or 'rootkit'.

If no hash match is found, the program will then use the 'file' command to determine the file type. The output of the 'file' command is then compared against the category rules defined in the configuration files. If a match is found, the file is assigned to the corresponding category.

Files that do not match any hash databases or file type rules are assigned to the 'unknown' category. The unknown category can be ignored by using the -U flag.

A copy of the files can be saved by using the -s flag. If so, then the files are saved in a subdirectory that is named with the category name. Each file is named using the file system image name followed by the meta data address and the original file extension. The category index file can be used to translate the actual name to the saved name. The HTML format makes viewing easier as there are links to each file from the category index file.

The program will also consult the rules about the file extension. If the file has an extension at the end of it (anything after a ´.´), it will be compared to the rules. If the extension is not found in the rules as a valid extension for the file type, it will be added to the file of 'mismatch'. If the file does not have an extension it will not be entered even if the file type has valid extensions. This check is done even if the file is found in one of the known good hash databases. If it is found in one of those, it will be added to a special file. Files of type 'data' have no extension checks done by default (as they have an unknown structure).

The program repeats the above procedures using the output of the 'ils' command as well. This allows 'sorter' to examine the contents of unallocated files that still have pointers to the data units (not all file systems will produce data from this step).

FICHIERS DE CONFIGURATION

Configuration files are used to define what file types belong in which categories and what extensions belong to what file types. Configuration files are distributed with the 'sorter' tool and are located in the installation directory in the 'share/sorter' directory.

The 'default.sort' file is used by any file system type. It contains entries for common file types. A specific operating system file also exists, which is useful for extensions that are specific to a given OS. By default, the default file and the OS specific one will be used. Using the '-c' flag, an additional file can be used. If the '-C' flag is used, then only the supplied configuration file is used.

There are two rule types in the configuration files. Each rule starts with a header that specifies which rule type it is (category or ext). Both rule types have two additional columns that can be separated by any white space.

The category rule has the category name as the second column and a Perl regular expression in the third column. The category name can not have any spaces in it and can only be letters and numbers. The regular expression is used to examine the output of 'file'. The regular expression will be used case insensitive. More than one rule can exist for a category, but only one category can exist for a given file output. For example:

This saves all file output with 'image data' anywhere in it to the ´images´ category:
category images image data

This saves all file output that has 'ASCII' followed by anything and then 'text' to be saved to the 'text' category:
category text ASCII(.*?)text

This saves all file output that is just 'data' to the 'data' category (the ^ and $ define the boundaries in Perl). The 'data' value is common in the output of file for unknown binary data.
category data ^data?

There is a special category of 'ignore' that is used to skip over files of this type. This is mainly a time and space saver.

The extension rule is similar except that the second column has the value extensions for the file output. Multiple rules can exist for the same file type. The comparison will be done case insensitive. If no extension is valid for the file type, a rule does not need to be made. That is already assumed.

For example, the ASCII is used for several file extensions so the following rules could exist:


ext txt,log ASCII(.*?)text
ext c,cpp,h,js ASCII(.*?)text

Please email me any rules that you find useful for standard investigations and I will incorporate them into future releases (carrier at sleuthkit dot org).

EXEMPLES

To run sorter with no hash databases, the following can be used:


# sorter -f ntfs -d data/sorter images/hda1.dd
# sorter -d data/sorter images/hda1.dd


# sorter -i raw -f ntfs -o 63 -d data/sorter images/hda.dd

To include the NSRL, an exclude, and an alert hash database:


# sorter -f ntfs -d data/sorter -a /usr/hash/rootkit.db -x /usr/hash/win2k.db -n /usr/hash/nsrl/NSRLFile.txt images/hda1.dd

To just identify images using the supplied 'images.sort' file:


# sorter -f ntfs -C /usr/local/sleuthkit/share/sort/images.sort -d data/sorter -h -s images/hda1.dd
