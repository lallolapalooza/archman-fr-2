SOFTHSM2-UTIL(1) Manuel des commandes générales SOFTHSM2-UTIL(1)

NOM

softhsm2-util - outil de support pour libsofthsm2

SYNTAXE

softhsm2-util --show-slots

softhsm2-util --init-token --free --label texte \ [--so-pin PIN --pin PIN]

softhsm2-util --import chemin [--file-pin PIN] --token étiquette \ [--pin PIN --no-public-key] --label texte --id hex

softhsm2-util --import chemin --aes --token étiquette \ [--pin PIN] --label texte --id hex

softhsm2-util --delete-token --token texte

DESCRIPTION

softhsm2-util est un outil de support principalement pour libsofthsm2. Il peut également être utilisé avec d'autres bibliothèques PKCS#11 en utilisant l'option --module.

Lisez les sections ci-dessous pour obtenir plus d'informations sur libsofthsm2 et PKCS#11. La plupart des applications supposent que le token qu'elles souhaitent utiliser est déjà initialisé. Il appartient alors à l'utilisateur d'initialiser le token PKCS#11. Ceci est fait en utilisant l'interface PKCS#11, mais au lieu d'écrire votre propre outil, vous pouvez utiliser l'outil softhsm2-util.

Les clés sont généralement créées directement dans le token, mais l'utilisateur peut vouloir utiliser une paire de clés existante. Les clés peuvent être importées dans un token en utilisant l'interface PKCS#11, mais cet outil peut également être utilisé si l'utilisateur possède la paire de clés dans un fichier PKCS#8. Si vous avez besoin de convertir des clés du format BIND .private-key en PKCS#8, vous pouvez utiliser softhsm2-keyconv.

La bibliothèque libsofthsm2, connue sous le nom de SoftHSM, fournit des fonctionnalités cryptographiques en utilisant l'API PKCS#11. Elle a été développée dans le cadre du projet OpenDNSSEC, conçue pour répondre aux exigences d'OpenDNSSEC, mais peut également fonctionner avec d'autres logiciels qui souhaitent utiliser les fonctionnalités de l'API PKCS#11.

SoftHSM est une implémentation logicielle d'un périphérique cryptographique générique avec une interface PKCS#11. Ces périphériques sont souvent appelés tokens. Lisez le manuel softhsm2.conf(5) pour savoir comment créer ces tokens et comment ils sont ajoutés à une slot dans SoftHSM.

L'API PKCS#11 peut être utilisée pour gérer et stocker des clés cryptographiques. Cette interface spécifie comment communiquer avec des périphériques cryptographiques tels que des HSM (Hardware Security Modules) et des cartes à puce. Le but de ces périphériques est, entre autres, de générer des clés cryptographiques et de signer des informations sans révéler le matériel de clé privée au monde extérieur. Ils sont souvent conçus pour bien performer sur ces tâches spécifiques par rapport aux processus ordinaires d'un ordinateur normal.

ACTIONS

--delete-token
Supprime le token dans une slot donnée. À utiliser avec --token ou --serial. Tout contenu du token sera effacé.
--help, -h
Affiche les informations d'aide.
--import chemin
Importe une paire de clés à partir du chemin donné. Le fichier doit être au format PKCS#8.
À utiliser avec --slot ou --token ou --serial, --file-pin, --pin, --no-public-key, --label, et --id.
Peut également être utilisé avec --aes pour utiliser le fichier tel quel et l'importer comme AES.
--init-token
Initialise le token dans une slot donnée, une étiquette de token ou un numéro de série de token. Si le token est déjà initialisé, cette commande le réinitialisera, effaçant ainsi tous les objets dans le token. Le code PIN correspondant de l'Administrateur de Sécurité (SO) doit également être fourni lors de la réinitialisation. Les tokens initialisés seront réassignés à une autre slot (basée sur le numéro de série du token).
À utiliser avec --slot ou --token ou --serial ou --free, --label, --so-pin, et --pin.
--show-slots
Affiche toutes les slots disponibles et leur statut actuel.
--version, -v
Affiche les informations de version.

OPTIONS

--aes
Utilisé pour indiquer à l'importation d'utiliser le fichier tel quel et de l'importer comme AES.
--file-pin PIN
Le PIN sera utilisé pour déchiffrer le fichier PKCS#8. S'il n'est pas fourni, le fichier PKCS#8 est supposé non chiffré.
--force
Utilisez cette option pour ignorer les avertissements et forcer l'action demandée.
--free
Utilise le premier token libre/non initialisé.
--id hex
Choisit un ID pour la paire de clés. L'ID est en hexadécimal avec une longueur variable. À utiliser avec --force lors de l'importation d'une paire de clés si l'ID existe déjà.
--label texte
Définit l'étiquette de l'objet ou du token qui sera définie.
--module chemin
Utilise une autre bibliothèque PKCS#11 que SoftHSM.
--no-public-key
N'importe pas la clé publique.
--pin PIN
Le PIN pour l'utilisateur normal.
--serial numéro
Utilisera le token avec un numéro de série correspondant.
--slot numéro
La slot où se trouve le token.
--so-pin PIN
Le PIN de l'Administrateur de Sécurité (SO).
--token étiquette
Utilisera le token avec une étiquette de token correspondante.

EXEMPLES

Le token peut être initialisé en utilisant cette commande :

softhsm2-util --init-token --slot 1 --label "mon_token"

Une paire de clés peut être importée en utilisant l'outil softhsm où vous spécifiez le chemin du fichier de clé, le numéro de slot, l'étiquette et l'ID des nouveaux objets, et le PIN utilisateur. Le fichier doit être au format PKCS#8.

softhsm2-util --import cle1.pem --token "mon_token" --label "Ma clé" \
--id A1B2 --pin 123456
(Ajoutez --file-pin PIN, si le fichier clé est chiffré.)

NOM

softhsm2-util - Utilitaires pour SoftHSM 2

SYNTAXE

softhsm2-util [OPTIONS] ACTION

DESCRIPTION

softhsm2-util est un programme utilitaire qui permet de gérer le stockage de clés et les jetons SoftHSM 2. Il permet de visualiser les informations des jetons, de les initialiser, de créer des conteneurs de clés, de gérer des mécanismes de chiffrement, etc.

ACTIONS

--show-slots
Affiche les informations sur tous les slots disponibles et leur état.
--init-token [LABEL]
Initialise le slot par défaut ou spécifié avec un nouveau jeton. Le LABEL est optionnel et spécifie un nom pour le jeton.
--create-object [OPTIONS]
Crée un nouvel objet (par exemple, une clé privée ou publique) dans le jeton.
--list-objects
Liste les objets actuellement stockés sur le jeton.
--delete-object [ID_OBJET]
Supprime un objet spécifique du jeton en utilisant son identifiant.
--generate-key [TYPE_CLE] [OPTIONS]
Génère une nouvelle paire de clés (par exemple, RSA, ECC) dans le jeton.
--encrypt [ID_OBJET] [FICHIER_ENTREE] [FICHIER_SORTIE]
Chiffre un fichier en utilisant une clé stockée dans le jeton.
--decrypt [ID_OBJET] [FICHIER_ENTREE] [FICHIER_SORTIE]
Déchiffre un fichier en utilisant une clé stockée dans le jeton.
--sign [ID_OBJET] [FICHIER_ENTREE] [FICHIER_SORTIE]
Signe le hachage d'un fichier en utilisant une clé privée stockée dans le jeton.
--verify [ID_OBJET] [FICHIER_SIGNATURE] [FICHIER_ORIGINAL]
Vérifie la signature d'un fichier en utilisant une clé publique stockée dans le jeton.

OPTIONS

--slot NUMERO_SLOT
Spécifie le numéro du slot à utiliser. Si non spécifié, le premier slot disponible est utilisé.
--pin CODE_PIN
Spécifie le code PIN du jeton. Si non spécifié, il sera demandé.
--label LABEL
Spécifie un label pour le jeton ou l'objet.
--id ID_OBJET
Spécifie l'identifiant d'un objet.
--type TYPE_OBJET
Spécifie le type d'objet à créer (par exemple, RSA, ECC, CERTIFICATE).
--key-size TAILLE_CLE
Spécifie la taille de la clé à générer (en bits).
--hash-algorithm ALGORITHME_HACHAGE
Spécifie l'algorithme de hachage à utiliser pour la signature (par exemple, SHA256).

EXEMPLES

Initialiser le jeton dans le slot 0 avec le code PIN par défaut :

softhsm2-util --init-token --slot 0 --pin 1234

Lister tous les objets sur le jeton du slot 0 :

softhsm2-util --slot 0 --list-objects

Générer une paire de clés RSA 2048 bits dans le slot 0 :

softhsm2-util --slot 0 --generate-key RSA --key-size 2048
