SOCKS.CONF(5) Manuel des formats de fichiers SOCKS.CONF(5)

NOM

socks.conf - syntaxe du fichier de configuration du client socks

DESCRIPTION

Le fichier de configuration de la bibliothèque client socks permet de contrôler la journalisation et la sélection du serveur. Il est divisé en deux parties : les paramètres globaux et les routes. Une ligne peut être commentée à l'aide du caractère de commentaire standard #.

FORMAT

Les paramètres globaux sont sous la forme d'un mot-clé suivi de deux-points et de la valeur.

debug
Définir ce champ à 1 active le débogage.
logoutput
Cette valeur contrôle où la bibliothèque client envoie la sortie des journaux. Il peut s'agir de syslog, stdout, stderr, d'un nom de fichier, ou d'une combinaison. Par défaut, aucune journalisation n'est activée. Notez que la valeur syslog peut entrer en conflit avec le programme sockettisé si le programme utilise également syslog.
resolveprotocol
Le protocole utilisé pour résoudre les noms d'hôtes. Les valeurs valides sont udp, tcp et fake. Par défaut, c'est udp.
route.badexpire
Durée pendant laquelle le marquage « mauvais » d'une route reste défini avant d'être supprimé. Par défaut, 300 secondes.
route.maxfail
Nombre de fois qu'une route peut échouer avant d'être marquée comme mauvaise. Par défaut, 1.
timeout.connect
Nombre de secondes pendant lesquelles le client attend la fin d'une connexion au serveur proxy. Par défaut, 0, ce qui signifie que le client doit utiliser la valeur par défaut du système.

ROUTES

Les routes sont spécifiées avec le mot-clé route. À l'intérieur d'une paire d'accolades ({}), un ensemble de mots-clés contrôle le comportement de la route. Chaque route peut contenir trois spécifications d'adresse : from, to et via. Une route est sélectionnée pour une connexion en fonction des valeurs dans le bloc route.

Lors de la recherche d'une route pour correspondre à la demande du client, la bibliothèque recherchera d'abord une route direct. Ensuite, une route socks_v4, une route socks_v5, une route http, et enfin une route upnp.

Selon la configuration de la bibliothèque et les variables d'environnement définies (voir le manuel de socksify(1)), il peut y avoir ou non un retour automatique à une route direct générée automatiquement si aucune autre route n'est trouvée.

Le bloc route peut contenir les éléments suivants :

ADRESSES
Chaque champ d'adresse peut se composer d'une adresse IP (et, lorsque pertinent, d'un masque de réseau, séparé de l'adresse IP par un '/'), d'un nom d'hôte, d'un nom de domaine (désigné par le '.' initial), ou d'un nom d'interface (lorsque pertinent). Chaque adresse peut être suivie d'un spécificateur de port optionnel.
from
La route n'est utilisée que pour les requêtes provenant de l'adresse spécifiée comme valeur.
to
La route n'est utilisée que pour les requêtes allant vers l'adresse spécifiée comme valeur.
via
Adresse du serveur proxy qui doit être utilisé comme passerelle pour la connexion, ou la valeur spéciale direct pour indiquer que la connexion doit être directe plutôt que de passer par un serveur proxy.

Dans le cas de upnp, l'adresse peut également être le nom de l'interface à utiliser pour découvrir le point de contrôle upnp, si l'URL complète de l'IGD n'est pas encore connue, ou la valeur spéciale broadcast pour indiquer que le client doit diffuser pour un routeur upnp sur toutes les interfaces réseau disponibles.

port
Paramètre pour from, to et via. Accepte les mots-clés eq/=, ne/!=, ge/>=, le/<=, gt/>, lt/< suivis d'un nombre. Une plage de ports peut également être donnée sous la forme « port <début #> - <fin #> », ce qui correspondra à tous les numéros de port compris dans la plage <début #> et <fin #>.

Options

clientcompatibility
Active certaines options pour la compatibilité avec des serveurs défectueux. Les valeurs valides sont : necgssapi, pour la compatibilité avec les serveurs implémentant gssapi à la manière de NEC socks.
command
Le serveur prend en charge les commandes spécifiées. Les commandes valides sont bind, bindreply, connect, udpassociate et udpreply. Par défaut, toutes les commandes prises en charge par les protocoles définis pour la route.

Peut être utilisé à la place de, ou en complément de, protocol.

gssapi.enctype
Quel chiffrement imposer pour la communication authentifiée GSSAPI. Les valeurs possibles sont clear, integrity, ou confidentiality. Par défaut, on essaie la confidentialité, mais on accepte tout ce que le serveur propose sauf clear, car clear ne fait pas partie de la norme SOCKS GSSAPI.
gssapi.servicename
Quel nom de service utiliser lors de l'utilisation de GSSAPI. Par défaut, « rcmd ».
method
Liste des méthodes d'authentification prises en charge par le client et qui seront proposées au serveur. Les valeurs actuellement prises en charge sont none, gssapi et username. Par défaut, toutes les méthodes prises en charge.
protocol
Les protocoles pris en charge par le serveur. Les valeurs prises en charge sont tcp et udp. Par défaut, tous les protocoles pris en charge.
proxyprotocol
Les protocoles proxy pris en charge par le serveur. Les valeurs actuellement prises en charge sont socks_v4, socks_v5, http et upnp. Par défaut, socks_v4 et socks_v5. Notez que si le serveur socks nécessite une forme d'authentification, vous devez explicitement définir cette valeur sur socks_v5, car v4 ne prend pas en charge l'authentification.

EXEMPLES

Voir le répertoire example dans la distribution.

ENVIRONNEMENT

SOCKS_USERNAME
Utiliser la valeur de SOCKS_USERNAME comme nom d'utilisateur lors de l'authentification par nom d'utilisateur.
SOCKS_PASSWORD
Utiliser la valeur de SOCKS_PASSWORD comme mot de passe lors de l'authentification par nom d'utilisateur. Non recommandé car d'autres utilisateurs sur le système pourraient voir votre mot de passe.
SOCKS_AUTOADD_LANROUTES
Si cette variable est définie sur « no », le client n'essaiera pas d'ajouter automatiquement des routes directes pour toutes les adresses du réseau local (LAN). Par défaut, elles sont ajoutées.
SOCKS_DISABLE_THREADLOCK
Si cette variable est définie, le client n'effectuera pas de verrouillage de thread. Par défaut, le client tente de déterminer par lui-même si l'application à sockettiser nécessite un verrouillage de thread ou non.

Certaines variables d'environnement supplémentaires sont documentées dans socksify(1).

sockd.conf(5)

NAME

sockd.conf - configuration file for Dante socks server

DESCRIPTION

The sockd.conf file is used to configure the Dante SOCKS server (sockd).

This file is parsed by sockd on startup and when the server receives a SIGHUP signal.

The configuration file contains a list of directives. Each directive is on a separate line. Directives are case sensitive.

Comments start with # and end at the end of the line. Comments can be used to explain directives and their values.

The configuration file can be divided into sections. The following sections are recognized:

  • syntax
  • block
  • pass
  • logoutput
  • socksmethod
  • internal
  • external
  • socksreadahead
  • sockswriteahead
  • socksgetpeername
  • socksgetsockname
  • socksconnecttimeout
  • sockskeepalive
  • socksselecttimeout
  • tcp-udp
  • udp-tcp
  • authmethod
  • user.privileged
  • user.unprivileged
  • group.privileged
  • group.unprivileged
  • setkey
  • set-client-identifier
  • set-server-identifier
  • tunnel

Directives can be specified multiple times. The order in which directives are specified matters for some directives.

The following directives are available:

FORMAT

The configuration file consists of directives, each on a separate line. Directives consist of a name, followed by arguments. Arguments are separated by spaces. Lines starting with # are ignored.

The following directives are available:

acl <acl_name> from [!] [!]<source_port> to [!] [!]<destination_port>

authdata password <username> <password>

authuser <username> <password>

block <source_address> <source_port> <destination_address> <destination_port>

daemonize [true|false]

dgramempty [true|false]

dgrammaxsize <size>

dgramtimeout <timeout>

deny <source_address> <source_port> <destination_address> <destination_port>

fastopen [true|false]

fifo <path>

getpass [true|false]

group <groupname>

internal <interface>

listen <address> <port>

logoutput <destination>

logtime [true|false]

logsockinfo [true|false]

pass <source_address> <source_port> <destination_address> <destination_port>

passip <source_address> <source_port> <destination_address> <destination_port>

passport <source_address> <source_port> <destination_address> <destination_port>

pidfile <path>

redirect <source_address> <source_port> <destination_address> <destination_port>

resolve <destination_address> <destination_port>

socks <address> <port>

socksmethod none <method>

socksreadahead <size>

sockswriteahead <size>

socksport <port>

socksserver <address>

socksconnecttimeout <timeout>

socksselecttimeout <timeout>

socksgetpeername [true|false]

socksgetsockname [true|false]

sockskeepalive [true|false]

syntax <version>

tcp-udp [true|false]

tunnel <address> <port>

udp-tcp [true|false]

user <username>

dante.conf file is a plain ASCII file. Comments start with # and end at the end of the line.

ROUTES

The route directive allows you to specify the default gateway for outgoing connections.

route [!]<destination_address> [!]<destination_port> via <gateway_address>

The via keyword is mandatory. The ! prefix negates the match.

Examples:

  • route to 192.168.1.0/24 via 10.0.0.1
  • route to !80 via 10.0.0.1
  • route to 192.168.1.0/24 !22 via 10.0.0.1

Options

The following options are available:

allow-internal- port-range
Specifies a range of ports that are allowed for internal connections. For example, allow-internal-port-range 1024-65535.
allow-transparent- port-range
Specifies a range of ports that are allowed for transparent proxying. For example, allow-transparent-port-range 1024-65535.
auth-type
Specifies the authentication method to use. Supported methods are none, password, ident, challenge, reject, gssapi, ntlm, pam.
bind-address
Specifies the address to bind to for listening sockets. Defaults to all interfaces.
bind-port
Specifies the port to bind to for listening sockets. Defaults to 1080.
connect-timeout
Specifies the timeout for establishing outgoing connections. Defaults to 30 seconds.
dante-user
Specifies the user to run the Dante server as. Defaults to nobody.
dante-group
Specifies the group to run the Dante server as. Defaults to nogroup.
debug
Enables debugging output. Can be specified multiple times for increased verbosity.
deny-address
Specifies an address or network to deny access to. Can be specified multiple times.
deny-port
Specifies a port or port range to deny access to. Can be specified multiple times.
firewall-real-ports
Specifies that the server should try to use real ports for firewall traversal. Requires root privileges.
group
Specifies the group ID to drop privileges to after initialization. Defaults to nogroup.
helper-timeout
Specifies the timeout for helper processes. Defaults to 60 seconds.
interface
Specifies the network interface to use for outgoing connections. Defaults to all interfaces.
log-facility
Specifies the syslog facility to use for logging. Defaults to daemon.
log-level
Specifies the logging level. Possible values are error, warning, notice, info, debug.
log-path
Specifies the file path for logging. If not specified, syslog is used.
log-time
Enables timestamping of log messages. Defaults to enabled.
max-connections
Specifies the maximum number of concurrent connections. Defaults to 512.
max-per-ip
Specifies the maximum number of concurrent connections per IP address. Defaults to 64.
max-per-user
Specifies the maximum number of concurrent connections per user. Defaults to 64.
max-socks-connections
Specifies the maximum number of concurrent SOCKS connections. Defaults to 512.
max-socks-per-ip
Specifies the maximum number of concurrent SOCKS connections per IP address. Defaults to 64.
max-socks-per-user
Specifies the maximum number of concurrent SOCKS connections per user. Defaults to 64.
pid-file
Specifies the path to the PID file. Defaults to /var/run/sockd.pid.
port-range
Specifies a range of ports that are allowed for outgoing connections. For example, port-range 1024-65535.
proxy-authentication
Enables proxy authentication. Requires auth-type to be set.
recursive-clients
Allows clients to connect to other clients through the SOCKS server. Defaults to disabled.
resolve-address
Specifies the address to use for resolving hostnames. Defaults to the system's default resolver.
resolve-method
Specifies the method to use for resolving hostnames. Possible values are bind, getaddrinfo.
select-timeout
Specifies the timeout for the select() call. Defaults to 30 seconds.
server-identifier
Specifies a string that will be used to identify the SOCKS server in logs and other messages.
socks-version
Specifies the SOCKS version to use. Supported versions are 4 and 5. Defaults to 5.
tcp-keepalive
Enables TCP keepalive probes. Defaults to disabled.
tcp-nodelay
Enables TCP_NODELAY option. Defaults to disabled.
timeout
Specifies the timeout for idle connections. Defaults to 300 seconds.
transparent-proxy
Enables transparent proxying. Requires root privileges.
tun-dport
Specifies the destination port for tunneled connections. Defaults to 80.
tun-method
Specifies the method used for tunneled connections. Possible values are port, ip.
tun-port
Specifies the source port for tunneled connections. Defaults to 1080.
user
Specifies the user ID to drop privileges to after initialization. Defaults to nobody.

EXAMPLES

This is a sample configuration file:

# Dante configuration file

logoutput: /var/log/dante.log
#logoutput: syslog

# We want to run as a non-privileged user
#user.unprivileged: root
#group.unprivileged: root

# SOCKS server identity
# server-identifier "MySocksServer"

# SOCKS listen port
#listen: 1080

# Example for transparent proxying
# internal: eth0
# external: eth1
# transparent-proxy: true

# SOCKS V5
socks-version: 5

# Authentication method
# socksmethod: username none
# socksmethod: username password

# For password authentication, specify the user and password
# authuser: testuser mypassword

# Example ACL rules
# acl: localhost
#     from: 127.0.0.1/8
#     to: 0.0.0.0/0
#
# acl: internalnet
#     from: 192.168.0.0/16
#     to: 0.0.0.0/0
#
# acl: allowedports
#     to: 0.0.0.0/0
#     port: !23,21,80,443
#
# pass: localhost
# pass: internalnet
# pass: allowedports

# Allow all connections from localhost
# pass: from: 127.0.0.1/8 to: 0.0.0.0/0

# Allow connections from internal network
# pass: from: 192.168.0.0/16 to: 0.0.0.0/0

# Deny all other connections
# block: from: 0.0.0.0/0 to: 0.0.0.0/0

# Set default user for authentication
# user.privileged: root
# user.unprivileged: nobody
# group.privileged: root
# group.unprivileged: nogroup

# If you want to use the default method (username and password), you must
# have a sockd.passwd file
# authuser: user1 pass1
# authuser: user2 pass2

# You can also use pam for authentication
# socksmethod: pam

# For Kerberos V5 authentication
# socksmethod: gssapi
# server-identifier: MySocksServer

# For NTLM authentication
# socksmethod: ntlm
# server-identifier: MySocksServer
