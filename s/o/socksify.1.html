SOCKSIFY(1) Manuel des commandes générales SOCKSIFY(1)

NOM

socksify - SOCKSification à l'exécution de programmes sélectionnés

DESCRIPTION

Le script shell socksify est conçu pour aider à utiliser SOCKS avec des binaires dynamiques déjà compilés. Cela fonctionne en définissant la variable d'environnement LD_PRELOAD sur libdsocks. Il tentera ensuite d'encapsuler tous les appels système liés au réseau.

Lorsqu'il est utilisé, le script peut faire la SOCKSification d'un programme en le préfixant simplement, ainsi que ses arguments, avec le script socksify, comme dans l'exemple ci-dessous.

$ socksify ftp ftp.example.org

ENVIRONNEMENT

Le script socksify, et la bibliothèque SOCKS Dante utilisée par le script socksify, peuvent interpréter plusieurs variables d'environnement.

SOCKS_CONF
Donne le nom du fichier socks.conf. Par défaut, c'est /etc/socks.conf, sauf si cela a été modifié lors de la compilation des bibliothèques libDante SOCKS.

La création d'un fichier socks.conf est la manière recommandée d'utiliser socksify, mais socksify peut également être utilisé pour la plupart des configurations simples sans fichier socks.conf, tant que le serveur proxy à utiliser est défini dans l'une des variables d'environnement prises en charge.

SOCKS_DEBUG
Active la journalisation de débogage. La valeur fournie doit être un nombre, un ou plus, indiquant le niveau de débogage fourni.
SOCKS_LOGOUTPUT
Cette valeur contrôle où la bibliothèque cliente envoie la sortie du journal. Elle peut être syslog, stdout, stderr, un nom de fichier, ou une combinaison. Par défaut, elle n'envoie nulle part.
SOCKS_USERNAME
Utilise la valeur de SOCKS_USERNAME comme nom d'utilisateur lors de l'authentification par nom d'utilisateur.
SOCKS_PASSWORD
Utilise la valeur de SOCKS_PASSWORD comme mot de passe lors de l'authentification par nom d'utilisateur. Non recommandé car d'autres utilisateurs sur le système pourraient voir votre mot de passe.
SOCKS_SERVER, SOCKS4_SERVER, SOCKS5_SERVER,
Ces variables permettent de spécifier l'adresse du serveur sans utiliser de fichier socks.conf. Si un fichier socks.conf est présent, il est ignoré si l'une de ces variables est définie.

Le format accepté est <adresse ip>:<port>. Si la valeur SOCKS_SERVER est définie, elle indique que le serveur spécifié prend en charge toutes les versions SOCKS prises en charge par Dante. Si l'une des deux autres variables est utilisée, elles indiquent que le serveur SOCKS donné ne prend en charge que la version SOCKS correspondante, v4 ou v5. Notez que si le serveur SOCKS nécessite une forme d'authentification, vous devez utiliser SOCKS5_SERVER, car la v4 ne prend pas en charge l'authentification.

HTTP_CONNECT_PROXY
Cette variable peut être utilisée pour spécifier l'emplacement d'un proxy HTTP prenant en charge la requête connect. Le format utilisé pour spécifier un proxy HTTP est http://<adresse ip>:<port>.
UPNP_IGD
Cette variable peut être utilisée pour spécifier l'emplacement d'un routeur IGD activé par UPNP. Il existe trois valeurs possibles pour cette variable : une URL complète, le nom de l'interface via laquelle le routeur est accessible, ou la valeur "broadcast" pour rechercher l'IGD sur toutes les interfaces appropriées.
Notez que si l'une des
variables d'environnement ci-dessus, indiquant le serveur proxy à utiliser, est définie, le client Dante ne analysera pas le fichier socks.conf.
SOCKS_AUTOADD_LANROUTES
Si cette variable est définie sur "no", le client n'essaiera pas d'ajouter automatiquement des routes directes pour toutes les adresses du LAN. Par défaut, elles sont ajoutées.
SOCKS_DISABLE_THREADLOCK
Si cette variable est définie, le client n'effectuera pas de verrouillage de thread. Par défaut, le client tente de déterminer lui-même si l'application à socksifier nécessite un verrouillage de thread ou non.
SOCKS_DIRECTROUTE_FALLBACK
Si cette variable est définie sur "yes", le client se rabattra sur une tentative de connexion directe si la route proxy échoue. Par défaut, elle est "no".
