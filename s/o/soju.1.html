soju(1) Manuel des commandes générales soju(1)

NOM

soju - Rebond IRC (bouncer)

SYNTAXE

soju [options...]

DESCRIPTION

soju est un rebond IRC convivial. Il se connecte aux serveurs IRC en amont au nom de l'utilisateur pour fournir des fonctionnalités supplémentaires.

  • Plusieurs utilisateurs distincts partageant le même rebond, chacun avec ses propres serveurs en amont
  • Envoi du backlog (messages reçus pendant que l'utilisateur était déconnecté du rebond), avec des tampons par client

Pour se connecter au rebond, utilisez le nom d'utilisateur et le mot de passe du rebond. Pour utiliser un client qui ne prend pas en charge l'extension IRC soju.im/bouncer-networks, configurez une connexion par serveur configuré dans soju, et indiquez le nom du réseau dans le nom d'utilisateur : "<nom d'utilisateur>/<réseau>". Ensuite, les canaux peuvent être rejoints et quittés comme si vous étiez directement connecté au serveur en amont.

Pour que l'historique par client fonctionne sur les clients qui ne prennent pas en charge l'extension IRCv3 chathistory, les clients doivent indiquer leur nom. Cela peut être fait en ajoutant un suffixe "@<client>" au nom d'utilisateur.

Lors de la jonction à un canal, le canal sera sauvegardé et rejoint automatiquement lors de la prochaine connexion. Lors de l'enregistrement ou de l'authentification auprès de NickServ, les informations d'identification seront sauvegardées et utilisées automatiquement lors de la prochaine connexion si le serveur prend en charge SASL. Lors du départ d'un canal avec la raison "detach", le canal sera détaché au lieu d'être quitté.

Si un réseau spécifié dans le nom d'utilisateur n'existe pas, et que le nom du réseau est un nom d'hôte valide, le réseau sera automatiquement ajouté.

Lorsque tous les clients sont déconnectés du rebond, l'utilisateur est automatiquement marqué comme absent par défaut.

soju rechargera le fichier de configuration, le certificat/clé TLS et le fichier MOTD lorsqu'il recevra le signal HUP. Les options de configuration listen, db et log ne peuvent pas être rechargées.

Les administrateurs peuvent diffuser un message à tous les utilisateurs du rebond via /notice $<nom d'hôte> <texte>, ou via /notice $* <texte> si la connexion n'est pas liée à un réseau particulier. Tous les utilisateurs du rebond actuellement connectés recevront le message du service spécial BouncerServ.

OPTIONS

-h, -help

Affiche le message d'aide et quitte.

-config <chemin>

Chemin vers le fichier de configuration. S'il n'est pas défini, un fichier de configuration par défaut est utilisé.

-debug

Active la journalisation de débogage (cela divulguera des informations sensibles telles que les mots de passe). Ceci peut être remplacé en cours d'exécution avec la commande de service server debug.

-listen <uri>

URI d'écoute (par défaut : ":6697"). Peut être spécifié plusieurs fois.

FICHIER DE CONFIG

Le fichier de configuration contient une directive par ligne.

Exemple :

listen ircs://
tls cert.pem key.pem
hostname example.org

Les directives suivantes sont prises en charge :

listen <uri>

URI d'écoute (par défaut : ":6697").

Les URIs suivantes sont prises en charge :

  • [ircs://][hôte][:port] écoute avec TLS sur TCP (port par défaut si omis : 6697)
  • irc://localhost[:port] écoute en texte brut sur TCP (port par défaut si omis : 6667, l'hôte doit être "localhost")
  • irc+insecure://[hôte][:port] écoute en texte brut sur TCP (port par défaut si omis : 6667)
  • unix://<chemin> écoute sur une socket de domaine Unix
  • https://[hôte][:port] écoute les connexions HTTPS (port par défaut : 443) et gère les requêtes suivantes :
  • /socket pour WebSocket
  • /uploads (et sous-répertoires) pour les transferts de fichiers
  • http://localhost[:port] écoute les connexions HTTP en texte brut (port par défaut : 80, l'hôte doit être "localhost") et gère les requêtes comme https://
  • http+insecure://[hôte][:port] écoute les connexions HTTP en texte brut (port par défaut : 80) et gère les requêtes comme https:// fait
  • http+unix://<chemin> écoute les connexions HTTP en texte brut sur une socket de domaine Unix et gère les requêtes comme https:// fait
  • wss://[hôte][:port] écoute les connexions WebSocket sur TLS (port par défaut : 443)
  • ws://localhost[:port] écoute les connexions WebSocket en texte brut (port par défaut : 80, l'hôte doit être "localhost")
  • ws+insecure://[hôte][:port] écoute les connexions WebSocket en texte brut (port par défaut : 80)
  • ws+unix://<chemin> écoute les connexions WebSocket en texte brut sur une socket de domaine Unix
  • ident://[hôte][:port] écoute les connexions ident en texte brut (port par défaut : 113)
  • http+prometheus://localhost:<port> écoute les connexions HTTP en texte brut et sert des métriques Prometheus (l'hôte doit être "localhost")
  • http+pprof://localhost:<port> écoute les connexions HTTP en texte brut et sert des données de profilage d'exécution pprof (l'hôte doit être "localhost"). Pour plus d'informations, voir : https://pkg.go.dev/net/http/pprof.
  • unix+admin://[chemin] écoute sur une socket de domaine Unix pour les connexions administratives, telles que sojuctl (chemin par défaut : /run/soju/admin)

Si le schéma est omis, "ircs" est supposé. Si plusieurs directives listen sont spécifiées, soju écoutera sur chacune d'elles.

hostname <nom>

Nom d'hôte du serveur (par défaut : nom d'hôte du système).

Ceci doit être défini sur un nom de domaine pleinement qualifié.

title <titre>

Titre du serveur. Ceci sera envoyé comme valeur ISUPPORT NETWORK lorsque les clients ne sélectionneront pas un réseau spécifique.

tls <cert> <clé>

Active le support TLS. Les fichiers certificat et clé doivent être encodés en PEM.

db <pilote> <source>

Définit l'emplacement de la base de données pour le stockage des utilisateurs, réseaux et canaux. Par défaut, une base de données sqlite3 est ouverte dans "./soju.db".

Pilotes pris en charge :

  • sqlite3 attend que source soit un chemin vers le fichier SQLite
  • postgres attend que source soit une liste séparée par des espaces de paramètres clé=valeur, par exemple db postgres "host=/run/postgresql dbname=soju". Notez que sslmode vaut "require" par défaut. Pour plus d'informations sur les chaînes de connexion, voir : https://pkg.go.dev/github.com/lib/pq#hdr-Connection_String_Parameters.

message-store <pilote> [source]

Définit l'emplacement de la base de données pour les messages IRC. Par défaut, db est utilisé.

Pilotes pris en charge :

  • db stocke les messages dans la base de données. Un index de recherche en texte intégral est utilisé pour accélérer les requêtes de recherche.
  • fs stocke les messages sur disque, dans le même format que ZNC. source est requis et est le chemin du répertoire racine de la base de données. Ce format sur disque est sujet à perte : certains messages IRCv3 (par exemple TAGMSG) et toutes les étiquettes de message sont rejetés.
  • memory stocke les messages en mémoire. Pour chaque canal/utilisateur, seuls les 4K derniers messages sont conservés en mémoire, les messages plus anciens sont rejetés. Ce pilote est très basique et ne prend pas en charge des fonctionnalités comme l'extension chathistory et la recherche.

(log est un alias déprécié pour cette directive.)

file-upload <pilote> [source]

Définit l'emplacement de la base de données pour les fichiers téléversés.

Le téléversement de fichiers nécessite la configuration d'un écouteur HTTP (voir les URIs https:// et http+insecure:// dans la directive listen).

Pilotes pris en charge :

  • fs stocke les fichiers téléversés sur disque. source est requis.
  • http stocke les fichiers téléversés via un service HTTP externe. source est requis et doit être une URL HTTP. Lors de la réception d'un fichier, soju enverra une requête HTTP POST à cette URL, en envoyant le fichier tel quel dans le corps de la requête HTTP ; un
additionnellement l'envoi du nom d'utilisateur soju dans l'en-tête Soju-Username. Le serveur HTTP doit répondre avec un HTTP 201 en cas de succès, avec l'en-tête Location défini sur l'URL du fichier téléchargé.

http-origin <patterns...>

Liste des origines HTTP autorisées pour les écouteurs WebSocket. Les paramètres sont interprétés comme des motifs shell, voir glob(7).

Par défaut, seul l'hôte de la requête est autorisé. Utilisez cette directive pour activer les WebSockets cross-origin.

http-ingress <url>

URL externe sur laquelle les écouteurs HTTPS sont exposés.

Par défaut, il s'agit de https://<hostname>.

accept-proxy-ip <cidr...>

Autorise les IPs spécifiées à agir en tant que proxy. Les proxys ont la capacité de remplacer les adresses de connexion distantes et locales (via le protocole PROXY, le champ d'en-tête HTTP Forwarded défini dans RFC 7239 ou les champs d'en-tête HTTP X-Forwarded-*). Le nom spécial "localhost" accepte les adresses de bouclage 127.0.0.0/8 et ::1/128.

Par défaut, toutes les IPs sont rejetées.

max-user-networks <limit>

Nombre maximum de réseaux activés par utilisateur. Par défaut, il n'y a pas de limite.

motd <path>

Chemin vers le fichier MOTD. Le MOTD du bouncer est envoyé aux clients qui ne sont pas liés à un réseau spécifique. Par défaut, aucun MOTD n'est envoyé.

upstream-user-ip <cidr...>

Active les adresses IP par utilisateur. Une plage IPv4 et/ou une plage IPv6 peuvent être spécifiées en notation CIDR. Une adresse IP par plage sera attribuée à chaque utilisateur et sera utilisée comme adresse source lors de la connexion à un réseau en amont.

Cela peut être utile pour éviter que tout le bouncer ne soit banni d'un réseau en amont à cause d'un seul utilisateur malveillant.

disable-inactive-user <duration>

Désactive les utilisateurs inactifs après la durée spécifiée.

Un utilisateur est inactif lorsque la dernière connexion sortante est fermée.

La durée est un nombre décimal positif suivi de l'unité "d" (jours). Par exemple, "30d" désactive les utilisateurs 30 jours après leur dernière déconnexion du bouncer.

enable-user-on-auth true|false

Active les utilisateurs lors de leur authentification réussie.

Cela peut être utilisé conjointement avec disable-inactive-user pour désactiver et réactiver les utilisateurs de manière transparente pendant une longue période d'inactivité.

Lorsque l'authentification externe est utilisée (par exemple, auth oauth2), les utilisateurs du bouncer sont créés automatiquement après une authentification réussie.

auth <driver> ...

Définit la méthode d'authentification. Par défaut, l'authentification interne est utilisée.

Drivers supportés :

auth internal

Utilise l'authentification interne.
auth http <url>
Utilise l'authentification HTTP basic externe. Une requête HTTP est effectuée vers l'URL, passant les identifiants de l'utilisateur dans un en-tête Authorization Basic. Les identifiants sont considérés comme valides pour un HTTP 200 ; invalides pour un HTTP 403 ; et tout autre code d'erreur signifie qu'une erreur s'est produite.
auth oauth2 <url>
Utilise l'authentification OAuth 2.0 externe. L'URL du serveur d'autorisation doit être fournie. L'ID client et le secret client peuvent être fournis comme nom d'utilisateur et mot de passe dans l'URL. Le serveur d'autorisation doit supporter OAuth 2.0 Authorization Server Metadata (RFC 8414) et OAuth 2.0 Token Introspection (RFC 7662).
auth pam
Utilise l'authentification PAM.

IRC SERVICE

soju expose un service IRC appelé BouncerServ pour gérer le bouncer. Les commandes peuvent être envoyées via des messages privés réguliers (/msg BouncerServ <commande> [arguments...]). Les commandes peuvent être écrites en forme complète ou abrégée, par exemple network peut être abrégé en net ou simplement n.

Les commandes sont analysées selon les règles de shell POSIX. En particulier, les mots peuvent être mis entre guillemets (simples ou doubles) et une barre oblique inverse échappe le caractère suivant.

help [command]

Affiche la liste des commandes. Si command est spécifié, affiche un message d'aide pour la commande.

network create -addr <addr> [options...]

Se connecte à un nouveau réseau à addr. -addr est obligatoire.

addr supporte plusieurs types de connexion :

  • [ircs://]<host>[:port] se connecte avec TLS sur TCP
  • irc+insecure://<host>[:port] se connecte avec du texte brut TCP
  • irc+unix:///<path> se connecte à un socket Unix

Par exemple, pour se connecter à Libera Chat :

net create -addr irc.libera.chat

Autres options :

-name <name>

Nom court du réseau. Il sera utilisé à la place de addr pour faire référence au réseau.

-username <username>

Se connecte avec le nom d'utilisateur spécifié. Par défaut, le surnom est utilisé.

-pass <pass>

Se connecte avec le mot de passe du serveur spécifié.

-realname <realname>

Se connecte avec le nom réel spécifié. Par défaut, le nom réel du compte est utilisé s'il est défini, sinon le surnom du réseau est utilisé.

-certfp <fingerprint>

Au lieu d'utiliser des autorités de certification pour vérifier le certificat TLS du serveur, vérifie si le certificat du serveur correspond à l'empreinte fournie. Ceci peut être utilisé pour se connecter à des serveurs utilisant des certificats auto-signés. Le format de l'empreinte est SHA512. Une chaîne vide supprime toute empreinte précédente.

La commande suivante peut être utilisée pour obtenir l'empreinte du certificat d'un serveur IRC :

openssl s_client -connect irc.example.org:6697 -verify_quiet </dev/null | openssl x509 -fingerprint -sha512 -noout -in /dev/stdin

-nick <nickname>

Se connecte avec le surnom spécifié. Par défaut, le nom d'utilisateur du compte est utilisé.

-auto-away true|false

Active ou désactive la fonctionnalité d'auto-away. Si la fonctionnalité est activée, l'utilisateur sera marqué comme absent lorsque tous les clients seront déconnectés du bouncer. Par défaut, l'auto-away est activé.

-enabled true|false

Active ou désactive le réseau. Si le réseau est désactivé, le bouncer ne s'y connectera pas. Par défaut, le réseau est activé.

-ignore-limit true|false

Ignore la limite de réseaux maximum pour cette commande. Seuls les utilisateurs administrateurs peuvent ignorer la limite.

-connect-command <command>

Envoie la chaîne citée spécifiée comme une commande IRC brute immédiatement après la connexion au serveur. Cela peut être utilisé pour s'identifier à un compte lorsque le serveur ne supporte pas SASL.

Par exemple, pour s'identifier auprès de NickServ, la commande suivante peut être utilisée :

"PRIVMSG NickServ :IDENTIFY <password>"

L'indicateur peut être spécifié plusieurs fois pour envoyer plusieurs messages IRC. Pour effacer toutes les commandes, définissez-le sur une chaîne vide.

network update [name] [options...]

Met à jour un réseau existant. Les options sont les mêmes que la commande network create.

Lorsque cette commande est exécutée, soju se déconnectera et se reconnectera au réseau.

Si name n'est pas spécifié, le réseau actuel est mis à jour.

network delete [name]

Déconnecte et supprime un réseau.

Si name n'est pas spécifié, le réseau actuel est supprimé.

network quote [name] <command>

Envoie une ligne IRC brute telle quelle à un réseau.

Si name n'est pas spécifié, la commande est envoyée au réseau actuel.

network status

Affiche la liste des réseaux enregistrés et leur état actuel.

channel status [options...]

Affiche la liste des canaux enregistrés et leur état actuel.

Options :

-network <name>

Affiche uniquement les canaux du réseau spécifié. Par défaut, seuls les canaux du réseau actuel sont affichés.

channel create <name> [options...]

Rejoint un nouveau canal.

Rejoindre un canal doit généralement se faire avec un simple join depuis le client, mais cette commande peut être utilisée pour joindre un autre utilisateur à un canal lorsqu'elle est utilisée avec user run.

Les options sont :

-detached true|false

Attache ou détache ce canal.

Un canal détaché est rejoint mais est caché par le bouncer. Ceci est utile pour, par exemple, collecter des logs et des highlights dans des canaux d'intérêt faible ou à fort trafic.

-relay-detached <mode>

Définit quand relayer les messages des canaux détachés à l'utilisateur avec un NOTICE BouncerServ.

Les modes sont :

message

Relaye tout message de ce canal lorsqu'il est détaché.

highlight

Relaye uniquement les messages vous mentionnant lorsqu'il est détaché.

none

Ne relaie aucun message de ce canal lorsqu'il est détaché.

default

Actuellement identique à highlight. C'est le comportement par défaut.

-reattach-on <mode>

Définit quand rattacher automatiquement aux canaux détachés.

Les modes sont :

message

Rattache à ce canal lorsqu'un message est reçu.

highlight

Rattache à ce canal lorsqu'un message vous mentionnant est reçu.

none

Ne rattache jamais automatiquement à ce canal.

default

Actuellement identique à none. C'est le comportement par défaut.

-detach-after <duration>

Détache automatiquement ce canal après que la durée spécifiée se soit écoulée sans recevoir de message correspondant à -detach-on.

Exemples de durées : 1h30m, 30s, 2.5h.

Définir cette valeur à 0 désactivera ce comportement, c'est-à-dire que ce canal ne sera jamais automatiquement détaché. C'est le comportement par défaut.

OPTIONS

-detach-on <mode>

Définit quand réinitialiser le minuteur d'auto-détachement utilisé par -detach-after, le faisant attendre à nouveau la durée du minuteur d'auto-détachement avant de se détacher. Rejoindre, se rattacher, envoyer un message ou modifier toute option de canal réinitialisera le minuteur, en plus des messages spécifiés par le mode.

Les modes sont :

message

Recevoir n'importe quel message de ce canal réinitialisera le minuteur d'auto-détachement.

highlight

Recevoir n'importe quel message vous mentionnant de ce canal réinitialisera le minuteur d'auto-détachement.

none

Recevoir des messages de ce canal ne réinitialisera pas le minuteur d'auto-détachement. L'envoi de messages ou la jonction au canal réinitialisera toujours le minuteur.

default

Actuellement identique à message. C'est le comportement par défaut.

channel update <name> [options...]

Met à jour les options d'un canal existant. Les options sont les mêmes que celles de la commande network create.

channel delete <name>

Quitte et oublie un canal.

certfp generate [options...]

Génère un certificat auto-signé et l'utilise pour l'authentification (via SASL EXTERNAL).

Génère une clé privée RSA de 3072 bits par défaut.

Notez qu'une reconnexion au réseau amont est nécessaire pour utiliser le certificat nouvellement généré.

Les options sont :

-network <name>

Sélectionne un réseau. Par défaut, le réseau actuel est sélectionné, s'il existe.

-key-type <type>

Algorithme de clé privée à utiliser. Les valeurs valides sont : rsa, ecdsa et ed25519. ecdsa utilise la courbe NIST P-521.

-bits <bits>

Taille de la clé RSA à générer. Ignoré pour les autres types de clés.

certfp fingerprint [options...]

Affiche les empreintes SHA-1 et SHA-256 du certificat actuellement utilisé avec le réseau.

Les options sont :

-network <name>

Sélectionne un réseau. Par défaut, le réseau actuel est sélectionné, s'il existe.

sasl status [options...]

Affiche le statut SASL actuel.

Les options sont :

-network <name>

Sélectionne un réseau. Par défaut, le réseau actuel est sélectionné, s'il existe.

sasl set-plain [options...] <username> <password>

Définit les identifiants SASL PLAIN.

Notez qu'une reconnexion au réseau amont est nécessaire pour appliquer les nouveaux paramètres.

Les options sont :

-network <name>

Sélectionne un réseau. Par défaut, le réseau actuel est sélectionné, s'il existe.

sasl reset [options...]

Désactive l'authentification SASL et supprime les identifiants stockés.

Notez qu'une reconnexion au réseau amont est nécessaire pour appliquer les nouveaux paramètres.

Les options sont :

-network <name>

Sélectionne un réseau. Par défaut, le réseau actuel est sélectionné, s'il existe.

user status [username]

Affiche une liste d'utilisateurs sur ce serveur. Seuls les administrateurs peuvent interroger ces informations.

Si username est spécifié, les statistiques ne sont affichées que pour cet utilisateur.

user create -username <username> -password <password> [options...]

Crée un nouvel utilisateur soju. Seuls les utilisateurs administrateurs peuvent créer de nouveaux comptes. Les options -username et -password sont obligatoires.

Les options sont :

-username <username>

Le nom d'utilisateur du bouncer. Il ne peut pas être modifié après la création de l'utilisateur.

-password <password>

Le mot de passe du bouncer.

-disable-password

Désactive l'authentification par mot de passe. L'utilisateur ne pourra pas se connecter.

-admin true|false

Fait de ce nouvel utilisateur un administrateur.

-nick <nick>

Définit le pseudonyme de l'utilisateur. Il est utilisé comme solution de repli s'il n'y a pas de pseudonyme défini pour un réseau.

-realname <realname>

Définit le nom réel de l'utilisateur. Il est utilisé comme solution de repli s'il n'y a pas de nom réel défini pour un réseau.

-enabled true|false

Active ou désactive l'utilisateur. Si l'utilisateur est désactivé, le bouncer ne se connectera à aucun de ses réseaux et les connexions en aval seront immédiatement fermées. Par défaut, les utilisateurs sont activés.

-max-networks <max-networks>

Définit une limite au nombre de réseaux activés que cet utilisateur peut utiliser. Une limite de 0 signifie aucun réseau, et -1 signifie utiliser la valeur de configuration globale max-user-networks par défaut.

user update [username] [options...]

Met à jour un utilisateur. Les options sont les mêmes que celles de la commande user create.

Si username est omis, l'utilisateur actuel est mis à jour. Seuls les administrateurs peuvent mettre à jour les autres utilisateurs.

Toutes les options ne sont pas valides dans tous les contextes :

  • L'option -username n'est jamais valide, les noms d'utilisateur sont immuables.
  • Les options -nick et -realname ne sont valides que lors de la mise à jour de l'utilisateur actuel.
  • Les options -admin, -enabled et -max_networks ne sont valides que lors de la mise à jour d'un autre utilisateur.

user delete <username> [confirmation token]

Supprime un utilisateur soju.

Seuls les administrateurs peuvent supprimer d'autres utilisateurs.

user run <username> <command...>

Exécute une commande en tant qu'autre utilisateur.

Seuls les administrateurs peuvent utiliser cette commande.

server status

Affiche des statistiques du bouncer. Seuls les administrateurs peuvent interroger ces informations.

server notice <message>

Diffuse une annonce. Tous les utilisateurs du bouncer actuellement connectés recevront le message du service spécial BouncerServ. Seuls les administrateurs peuvent diffuser une annonce.

server debug <true|false>

Active/désactive la journalisation de débogage (cela divulguera des informations sensibles). Ceci remplace toute valeur passée à soju via -debug.
