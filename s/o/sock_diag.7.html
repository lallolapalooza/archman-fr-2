sock_diag(7) Manuel d'informations diverses sock_diag(7)

NOM

sock_diag - obtenir des informations sur les sockets

SYNTAXE

#include <sys/socket.h>
#include <linux/sock_diag.h>
#include <linux/unix_diag.h> /* pour les sockets du domaine UNIX */
#include <linux/inet_diag.h> /* pour les sockets IPv4 et IPv6 */
diag_socket = socket(AF_NETLINK, socket_type, NETLINK_SOCK_DIAG);

DESCRIPTION

Le sous-système netlink sock_diag fournit un mécanisme pour obtenir des informations sur les sockets de diverses familles d'adresses à partir du noyau. Ce sous-système peut être utilisé pour obtenir des informations sur des sockets individuels ou demander une liste de sockets.

Dans la requête, l'appelant peut spécifier des informations supplémentaires qu'il souhaiterait obtenir sur le socket, par exemple, des informations mémoire ou des informations spécifiques à la famille d'adresses.

Lors de la demande d'une liste de sockets, l'appelant peut spécifier des filtres qui seront appliqués par le noyau pour sélectionner un sous-ensemble de sockets à signaler. Pour l'instant, il n'est possible de filtrer les sockets que par état (connecté, en écoute, etc.).

Notez que sock_diag ne rapporte que les sockets qui ont un nom; c'est-à-dire soit des sockets liés explicitement avec bind(2), soit des sockets qui ont été liés automatiquement à une adresse (par exemple, par connect(2)). C'est le même ensemble de sockets qui est disponible via /proc/net/unix, /proc/net/tcp, /proc/net/udp, etc.

Requête

La requête commence par un en-tête struct nlmsghdr décrit dans netlink(7) avec le champ nlmsg_type défini à SOCK_DIAG_BY_FAMILY. Il est suivi d'un en-tête spécifique à la famille d'adresses qui commence par une partie commune partagée par toutes les familles d'adresses:


struct sock_diag_req {
    __u8 sdiag_family;
    __u8 sdiag_protocol;
};

Les champs de cette structure sont les suivants:

sdiag_family
Une famille d'adresses. Elle doit être définie à la constante AF_* appropriée.
sdiag_protocol
Dépend de sdiag_family. Elle doit être définie à la constante IPPROTO_* appropriée pour AF_INET et AF_INET6, et à 0 sinon.

Si le champ nlmsg_flags de l'en-tête struct nlmsghdr a le drapeau NLM_F_DUMP défini, cela signifie qu'une liste de sockets est demandée ; sinon, il s'agit d'une requête concernant un socket individuel.

Réponse

La réponse commence par un en-tête struct nlmsghdr et est suivie d'un tableau d'objets spécifiques à la famille d'adresses. Le tableau doit être accédé avec les macros standard NLMSG_* de l'API netlink(3).

Chaque objet est une liste d'attributs NLA (netlink attributes) qui doit être accédée avec les macros RTA_* de l'API rtnetlink(3).

Sockets du domaine UNIX

Pour les sockets du domaine UNIX, la requête est représentée dans la structure suivante:


struct unix_diag_req {
    __u8    sdiag_family;
    __u8    sdiag_protocol;
    __u16   pad;
    __u32   udiag_states;
    __u32   udiag_ino;
    __u32   udiag_show;
    __u32   udiag_cookie[2];
};

Les champs de cette structure sont les suivants:

sdiag_family
La famille d'adresses ; elle doit être définie à AF_UNIX.

sdiag_protocol

pad
Ces champs doivent être définis à 0.
udiag_states
C'est un masque de bits qui définit un filtre des états des sockets. Seuls les sockets dont les états sont dans ce masque seront rapportés. Ignoré lors de la requête d'un socket individuel. Les valeurs prises en charge sont :
1 << TCP_ESTABLISHED

1 << TCP_LISTEN

udiag_ino
C'est un numéro d'inode lors de la requête d'un socket individuel. Ignoré lors de la requête d'une liste de sockets.
udiag_show
C'est un ensemble de drapeaux définissant quel type d'informations rapporter. Chaque type d'information demandé est rapporté comme un attribut netlink tel que décrit ci-dessous :
UDIAG_SHOW_NAME
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_NAME. La charge utile associée à cet attribut est le chemin du fichier auquel le socket a été lié (une séquence d'octets jusqu'à la taille UNIX_PATH_MAX).
UDIAG_SHOW_VFS
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_VFS. La charge utile associée à cet attribut est représentée dans la structure suivante :

struct unix_diag_vfs {
    __u32 udiag_vfs_dev;
    __u32 udiag_vfs_ino;
};

Les champs de cette structure sont les suivants :
udiag_vfs_dev
Le numéro de périphérique de l'inode de socket correspondant sur disque.
udiag_vfs_ino
Le numéro d'inode de l'inode de socket correspondant sur disque.
UDIAG_SHOW_PEER
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_PEER. La charge utile associée à cet attribut est une valeur __u32 qui est le numéro d'inode du pair. Cet attribut est rapporté uniquement pour les sockets connectés.
UDIAG_SHOW_ICONS
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_ICONS. La charge utile associée à cet attribut est un tableau de valeurs __u32 qui sont les numéros d'inode des sockets qui ont passé l'appel connect(2), mais qui n'ont pas encore été traités avec accept(2). Cet attribut est rapporté uniquement pour les sockets en écoute.
UDIAG_SHOW_RQLEN
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_RQLEN. La charge utile associée à cet attribut est représentée dans la structure suivante :

struct unix_diag_rqlen {
    __u32 udiag_rqueue;
    __u32 udiag_wqueue;
};

Les champs de cette structure sont les suivants :
udiag_rqueue
Pour les sockets en écoute : le nombre de connexions en attente. La taille du tableau associé à l'attribut de réponse UNIX_DIAG_ICONS est égale à cette valeur.
Pour les sockets établis : la quantité de données dans la file de réception.
udiag_wqueue
Pour les sockets en écoute : la taille de la file d'attente, qui est égale à la valeur passée comme deuxième argument à listen(2).
Pour les sockets établis : la quantité de mémoire disponible pour l'envoi.
UDIAG_SHOW_MEMINFO
L'attribut rapporté en réponse à cette requête est UNIX_DIAG_MEMINFO. La charge utile associée à cet attribut est un tableau de valeurs __u32 décrit ci-dessous dans la sous-section « Informations sur la mémoire du socket ».

Sockets de domaine UNIX

Pour les sockets de domaine UNIX, la requête est représentée par la structure suivante :


struct unix_diag_req {
    __u8    udiag_family;
    __u8    udiag_type;
    __u8    udiag_states;
    __u8    pad;
    __u32   udiag_ino;
    __u32   udiag_cookie[2];
};

Les champs de cette structure sont les suivants :

udiag_family
Ce champ doit être réglé à AF_UNIX.
udiag_type
Ce champ doit être réglé à SOCK_DGRAM, SOCK_STREAM, ou SOCK_SEQPACKET.
udiag_states
Ce champ est un masque de bits qui définit un filtre d'états de socket. Seuls les sockets dont les états sont dans ce masque seront rapportés. Ce champ est ignoré lors de la requête pour un socket individuel.
udiag_ino
Ce champ est le numéro d'inode du socket. Il est utilisé pour spécifier un socket individuel.
udiag_cookie
Ce champ est un tableau d'identifiants opaques qui peut être utilisé avec udiag_ino pour spécifier un socket individuel. Il est ignoré lors de la requête d'une liste de sockets, ainsi que lorsque tous ses éléments sont réglés à -1.

Les attributs netlink suivants peuvent être demandés dans le cadre d'une requête :

UNIX_DIAG_shaders
Il n'y a pas de description spécifique pour cet attribut sans requête spécifique.
UNIX_DIAG_SHUTDOWN
La charge utile associée à cet attribut est une valeur __u8 qui représente les bits de l'état de shutdown(2).
udiag_cookie
Il s'agit d'un tableau d'identifiants opaques qui pourraient être utilisés avec udiag_ino pour spécifier un socket individuel. Il est ignoré lors de la requête d'une liste de sockets, ainsi que lorsque tous ses éléments sont réglés à -1.

La réponse à une requête pour des sockets de domaine UNIX est représentée par un tableau de


struct unix_diag_msg {
    __u8    udiag_family;
    __u8    udiag_type;
    __u8    udiag_state;
    __u8    pad;
    __u32   udiag_ino;
    __u32   udiag_cookie[2];
};

suivi des attributs netlink.

Les champs de cette structure sont les suivants :

udiag_family
Ce champ a la même signification que dans struct unix_diag_req.
udiag_type
Ce champ est réglé à l'une des valeurs SOCK_PACKET, SOCK_STREAM, ou SOCK_SEQPACKET.
udiag_state
Ce champ est réglé à TCP_LISTEN ou TCP_ESTABLISHED.
pad
Ce champ est réglé à 0.
udiag_ino
C'est le numéro d'inode du socket.
udiag_cookie
Il s'agit d'un tableau d'identifiants opaques qui pourraient être utilisés dans des requêtes ultérieures.

Sockets IPv4 et IPv6

Pour les sockets IPv4 et IPv6, la requête est représentée par la structure suivante :


struct inet_diag_req_v2 {
    __u8    sdiag_family;
    __u8    sdiag_protocol;
    __u8    idiag_ext;
    __u8    pad;
    __u32   idiag_states;
    struct inet_diag_sockid id;
};

où struct inet_diag_sockid est définie comme suit :


struct inet_diag_sockid {
    __be16  idiag_sport;
    __be16  idiag_dport;
    __be32  idiag_src[4];
    __be32  idiag_dst[4];
    __u32   idiag_if;
    __u32   idiag_cookie[2];
};

Les champs de struct inet_diag_req_v2 sont les suivants :

sdiag_family
Ce champ doit être réglé à AF_INET ou AF_INET6 pour les sockets IPv4 ou IPv6 respectivement.
sdiag_protocol
Ce champ doit être réglé à l'une des valeurs IPPROTO_TCP, IPPROTO_UDP, ou IPPROTO_UDPLITE.
idiag_ext
Il s'agit d'un ensemble d'indicateurs définissant le type d'informations étendues à rapporter. Chaque type d'information demandé est rapporté sous forme d'attribut netlink comme décrit ci-dessous :
INET_DIAG_TOS
La charge utile associée à cet attribut est une valeur __u8 qui est le TOS du socket.
INET_DIAG_TCLASS
La charge utile associée à cet attribut est une valeur __u8 qui est le TClass du socket. Uniquement pour les sockets IPv6. Pour les sockets LISTEN et CLOSE, cela est suivi de l'attribut INET_DIAG_SKV6ONLY avec une valeur de charge utile __u8 associée signifiant si le socket est uniquement IPv6 ou non.
INET_DIAG_MEMINFO
La charge utile associée à cet attribut est représentée par la structure suivante :

struct inet_diag_meminfo {
    __u32 idiag_rmem;
    __u32 idiag_wmem;
    __u32 idiag_fmem;
    __u32 idiag_tmem;
};

Les champs de cette structure sont les suivants :
idiag_rmem
La quantité de données dans la file de réception.
idiag_wmem
La quantité de données qui est mise en file d'attente par TCP mais pas encore envoyée.
idiag_fmem
La quantité de mémoire prévue pour une utilisation future (TCP uniquement).
idiag_tmem
La quantité de données dans la file d'envoi.
INET_DIAG_SKMEMINFO
La charge utile associée à cet attribut est un tableau de valeurs __u32 décrites ci-dessous dans la sous-section "Informations sur la mémoire du socket".
INET_DIAG_INFO
La charge utile associée à cet attribut est spécifique à la famille d'adresses. Pour les sockets TCP, il s'agit d'un objet de type struct tcp_info.
INET_DIAG_CONG
La charge utile associée à cet attribut est une chaîne de caractères qui décrit l'algorithme de contrôle de congestion utilisé. Pour les sockets TCP uniquement.
pad
Ce champ doit être réglé à 0.
idiag_states
C'est un masque de bits qui définit un filtre d'états de socket. Seuls les sockets dont les états sont dans ce masque seront rapportés. Ignoré lors de la requête d'un socket individuel.
id
C'est un objet d'identification de socket qui est utilisé dans les requêtes de vidage, dans les requêtes concernant des sockets individuels, et qui est rapporté dans chaque réponse. Contrairement aux sockets de domaine UNIX, les sockets IPv4 et IPv6 sont identifiés à l'aide d'adresses et de ports. Toutes les valeurs sont en ordre d'octet réseau.

Les champs de struct inet_diag_sockid sont les suivants :

idiag_sport
Le port source.
idiag_dport
Le port de destination.
idiag_src
L'adresse source.
idiag_dst
L'adresse de destination.
idiag_if
Le numéro d'interface auquel le socket est lié.
idiag_cookie
Il s'agit d'un tableau d'identifiants opaques qui pourraient être utilisés avec d'autres champs de cette structure pour spécifier un socket individuel. Il est ignoré lors de la requête d'une liste de sockets, ainsi que lorsque tous ses éléments sont réglés à -1.

La réponse à une requête pour des sockets IPv4 ou IPv6 est représentée par un tableau de


struct inet_diag_msg {
    __u8    idiag_family;
    __u8    idiag_state;
    __u8    idiag_timer;
    __u8    idiag_retrans;
    struct inet_diag_sockid id;
    __u32   idiag_expires;
    __u32   idiag_rqueue;
    __u32   idiag_wqueue;
    __u32   idiag_uid;
    __u32   idiag_inode;
};

suivi des attributs netlink.

Les champs de cette structure sont les suivants :

idiag_family
C'est le même champ que dans struct inet_diag_req_v2.
idiag_state
Ceci indique l'état du socket comme dans struct inet_diag_req_v2.
idiag_timer
Pour les sockets TCP, ce champ décrit le type de temporisateur actuellement actif pour le socket. Il est réglé à l'une des constantes suivantes :
0
aucun temporisateur n'est actif
1
un temporisateur de retransmission
2
un temporisateur de maintenance (keep-alive)
3
un temporisateur TIME_WAIT
4
un temporisateur de fenêtre nulle (zero window probe)
Pour les sockets non-TCP, ce champ est réglé à 0.
idiag_retrans
Pour les valeurs idiag_timer 1, 2 et 4, ce champ contient le nombre de retransmissions. Pour les autres valeurs idiag_timer, ce champ est réglé à 0.
idiag_expires
Pour les sockets TCP ayant un temporisateur actif, ce champ décrit son heure d'expiration en millisecondes. Pour les autres sockets, ce champ est réglé à 0.
idiag_rqueue
Pour les sockets en écoute : le nombre de connexions en attente.
Pour les autres sockets : la quantité de données dans la file de réception.
idiag_wqueue
Pour les sockets en écoute : la taille de la file d'attente (backlog).
Pour les autres sockets : la quantité de mémoire disponible pour l'envoi.
idiag_uid
C'est l'UID propriétaire du socket.
idiag_inode
C'est le numéro d'inode du socket.

Informations sur la mémoire du socket

La charge utile associée aux attributs netlink UNIX_DIAG_MEMINFO et INET_DIAG_SKMEMINFO est un tableau des valeurs __u32 suivantes :

SK_MEMINFO_RMEM_ALLOC
La quantité de données dans la file de réception.
SK_MEMINFO_RCVBUF
Le tampon de socket de réception tel que défini par SO_RCVBUF.
SK_MEMINFO_WMEM_ALLOC
La quantité de données qui est mise en file d'attente par TCP mais pas encore envoyée.
sock_diag.7 - Linux man-pages

NAME

sock_diag - socket monitoring interface

SYNOPSIS

 #include <linux/netlink.h>
 #include <linux/rtnetlink.h>
 #include <linux/sock_diag.h>
 #include <linux/unix_diag.h>

DESCRIPTION

The socket monitoring interface is a Netlink socket protocol (NETLINK_SOCK_DIAG) that allows querying information about sockets in the system.

The interface is based on the netlink protocol used for network configuration (NETLINK_ROUTE) and shares some structures like struct nlmsghdr, struct rtattr, and utilities like RTA_NEXT, RTA_LENGTH, etc.

The main entry point is a socket of type AF_NETLINK with protocol NETLINK_SOCK_DIAG.

Requests are sent using struct nlmsghdr with nlmsg_type set to SOCK_DIAG_BY_FAMILY. The payload must be a socket diagnostic request structure, specific to the address family being queried. The request structure is pointed to by the nlmsg_data field of the nlmsghdr.

The following structures are used for requests:

AF_UNIX
The request structure is struct unix_diag_req. See unix_diag.h for details. The query is intended to retrieve status information about Unix domain sockets.
udiag_family
Must be set to AF_UNIX.
udiag_states
Socket states to query. Set to -1 to query all states.
udiag_show
Bitmap specifying which information to return. Possible values are UDIAG_SHOW_NAME, UDIAG_SHOW_PEER.

Responses are sent as a series of Netlink messages. Each message contains a struct nlmsghdr followed by a specific diagnostic message structure and then a variable number of struct rtattr structures containing additional information.

The main diagnostic message structure for AF_UNIX sockets is struct unix_diag_msg.

udiag_ino
The inode number of the socket.
udiag_family
The address family (should be AF_UNIX).
udiag_state
The state of the socket.
udiag_cookie
A cookie value that can be used to resume a dump operation.

Additional information is provided as attributes appended to struct unix_diag_msg:

UNIX_DIAG_NAME
The name of the socket (e.g., the path for a named socket, or the address for an anonymous socket).
UNIX_DIAG_PEER
The inode number of the peer socket, if connected.
UNIX_DIAG_UID
The user ID of the socket owner.
UNIX_DIAG_TIME_LEN
The length of the socket's address structure.
UNIX_DIAG_SERIAL
A unique serial number for the socket.

For TCP sockets, the diagnostic message is struct inet_diag_msg and the available memory information is provided as attributes:

SK_MEMINFO_WMEM_ALLOC
The amount of data in the send queue.
SK_MEMINFO_SNDBUF
The send socket buffer as set by SO_SNDBUF.
SK_MEMINFO_FWD_ALLOC
The amount of memory scheduled for future use (TCP only).
SK_MEMINFO_WMEM_QUEUED
The amount of data queued by TCP, but not yet sent.
SK_MEMINFO_OPTMEM
The amount of memory allocated for the socket's service needs (e.g., socket filter).
SK_MEMINFO_BACKLOG
The amount of packets in the backlog (not yet processed).

VERSIONS

NETLINK_INET_DIAG was introduced in Linux 2.6.14 and supported AF_INET and AF_INET6 sockets only. In Linux 3.3, it was renamed to NETLINK_SOCK_DIAG and extended to support AF_UNIX sockets.

UNIX_DIAG_MEMINFO and INET_DIAG_SKMEMINFO were introduced in Linux 3.6.

STANDARDS

Linux.

EXAMPLES

The following example program prints inode number, peer's inode number, and name of all UNIX domain sockets in the current namespace.

#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <linux/netlink.h>
#include <linux/rtnetlink.h>
#include <linux/sock_diag.h>
#include <linux/unix_diag.h>
static int
send_query(int fd)
{
    struct sockaddr_nl nladdr = {
        .nl_family = AF_NETLINK
    };
    struct
    {
        struct nlmsghdr nlh;
        struct unix_diag_req udr;
    } req = {
        .nlh = {
            .nlmsg_len = sizeof(req),
            .nlmsg_type = SOCK_DIAG_BY_FAMILY,
            .nlmsg_flags = NLM_F_REQUEST | NLM_F_DUMP
        },
        .udr = {
            .sdiag_family = AF_UNIX,
            .udiag_states = -1,
            .udiag_show = UDIAG_SHOW_NAME | UDIAG_SHOW_PEER
        }
    };
    struct iovec iov = {
        .iov_base = &req,
        .iov_len = sizeof(req)
    };
    struct msghdr msg = {
        .msg_name = &nladdr,
        .msg_namelen = sizeof(nladdr),
        .msg_iov = &iov,
        .msg_iovlen = 1
    };
    for (;;) {
        if (sendmsg(fd, &msg, 0) < 0) {
            if (errno == EINTR)
                continue;
            perror("sendmsg");
            return -1;
        }
        return 0;
    }
}
static int
print_diag(const struct unix_diag_msg *diag, unsigned int size)
{
    if (size < NLMSG_LENGTH(sizeof(*diag))) {
        fputs("short response\n", stderr);
        return -1;
    }
    if (diag->udiag_family != AF_UNIX) {
        fprintf(stderr, "unexpected family %u\n", diag->udiag_family);
        return -1;
    }
    unsigned int rta_len = size - NLMSG_LENGTH(sizeof(*diag));
    unsigned int peer = 0;
    size_t path_len = 0;
    char path[sizeof(((struct sockaddr_un *) 0)->sun_path) + 1];
    for (struct rtattr *attr = (struct rtattr *) (diag + 1);
             RTA_OK(attr, rta_len); attr = RTA_NEXT(attr, rta_len)) {
        switch (attr->rta_type) {
        case UNIX_DIAG_NAME:
            if (!path_len) {
                path_len = RTA_PAYLOAD(attr);
                if (path_len > sizeof(path) - 1)
                    path_len = sizeof(path) - 1;
                memcpy(path, RTA_DATA(attr), path_len);
                path[path_len] = '\0';
            }
            break;
        case UNIX_DIAG_PEER:
            if (RTA_PAYLOAD(attr) >= sizeof(peer))
                peer = *(unsigned int *) RTA_DATA(attr);
            break;
        }
    }
    printf("inode=%u", diag->udiag_ino);
    if (peer)
        printf(", peer=%u", peer);
    if (path_len)
        printf(", name=%s%s", *path ? "" : "@",
                *path ? path : path + 1);
    putchar('\n');
    return 0;
}
static int
receive_responses(int fd)
{
    long buf[8192 / sizeof(long)];
    struct sockaddr_nl nladdr;
    struct iovec iov = {
        .iov_base = buf,
        .iov_len = sizeof(buf)
    };
    int flags = 0;
    for (;;) {
        struct msghdr msg = {
            .msg_name = &nladdr,
            .msg_namelen = sizeof(nladdr),
            .msg_iov = &iov,
            .msg_iovlen = 1
        };
        ssize_t ret = recvmsg(fd, &msg, flags);
        if (ret < 0) {
            if (errno == EINTR)
                continue;
            perror("recvmsg");
            return -1;
        }
        if (ret == 0)
            return 0;
        if (nladdr.nl_family != AF_NETLINK) {
            fputs("!AF_NETLINK\n", stderr);
            return -1;
        }
        const struct nlmsghdr *h = (struct nlmsghdr *) buf;
        if (!NLMSG_OK(h, ret)) {
            fputs("!NLMSG_OK\n", stderr);
            return -1;
        }
        for (; NLMSG_OK(h, ret); h = NLMSG_NEXT(h, ret)) {
            if (h->nlmsg_type == NLMSG_DONE)
                return 0;
            if (h->nlmsg_type == NLMSG_ERROR) {
                const struct nlmsgerr *err = NLMSG_DATA(h);
                if (h->nlmsg_len < NLMSG_LENGTH(sizeof(*err))) {
                    fputs("NLMSG_ERROR\n", stderr);
                } else {
                    errno = -err->error;
                    perror("NLMSG_ERROR");
                }
                return -1;
            }
            if (h->nlmsg_type != SOCK_DIAG_BY_FAMILY) {
                fprintf(stderr, "unexpected nlmsg_type %u\n",
                        (unsigned) h->nlmsg_type);
                return -1;
            }
            if (print_diag(NLMSG_DATA(h), h->nlmsg_len))
                return -1;
        }
    }
}
int
main(void)
{
    int fd = socket(AF_NETLINK, SOCK_RAW, NETLINK_SOCK_DIAG);
    if (fd < 0) {
        perror("socket");
        return 1;
    }
    int ret = send_query(fd) || receive_responses(fd);
    close(fd);
    return ret;
}

NOM

sock_diag - interface de surveillance des sockets

SYNTAXE

 #include <linux/netlink.h>
 #include <linux/rtnetlink.h>
 #include <linux/sock_diag.h>
 #include <linux/unix_diag.h>

DESCRIPTION

L'interface de surveillance des sockets est un protocole de socket Netlink (NETLINK_SOCK_DIAG) qui permet d'interroger des informations sur les sockets du système.

L'interface est basée sur le protocole netlink utilisé pour la configuration réseau (NETLINK_ROUTE) et partage certaines structures comme struct nlmsghdr, struct rtattr, et des utilitaires comme RTA_NEXT, RTA_LENGTH, etc.

Le point d'entrée principal est un socket de type AF_NETLINK avec le protocole NETLINK_SOCK_DIAG.

Les requêtes sont envoyées en utilisant struct nlmsghdr avec nlmsg_type défini à SOCK_DIAG_BY_FAMILY. La charge utile doit être une structure de requête de diagnostic de socket, spécifique à la famille d'adresses interrogée. La structure de requête est pointée par le champ nlmsg_data du nlmsghdr.

Les structures suivantes sont utilisées pour les requêtes :

AF_UNIX
La structure de requête est struct unix_diag_req. Voir unix_diag.h pour plus de détails. La requête vise à récupérer des informations d'état sur les sockets Unix domain.
udiag_family
Doit être défini à AF_UNIX.
udiag_states
États des sockets à interroger. Défini à -1 pour interroger tous les états.
udiag_show
Masque de bits spécifiant quelles informations retourner. Les valeurs possibles sont UDIAG_SHOW_NAME, UDIAG_SHOW_PEER.

Les réponses sont envoyées sous forme d'une série de messages Netlink. Chaque message contient un struct nlmsghdr suivi d'une structure de message de diagnostic spécifique, puis d'un nombre variable de structures struct rtattr contenant des informations supplémentaires.

La structure principale de message de diagnostic pour les sockets AF_UNIX est struct unix_diag_msg.

udiag_ino
Le numéro inode du socket.
udiag_family
La famille d'adresses (devrait être AF_UNIX).
udiag_state
L'état du socket.
udiag_cookie
Une valeur de cookie qui peut être utilisée pour reprendre une opération de vidage (dump).

Des informations supplémentaires sont fournies sous forme d'attributs ajoutés à struct unix_diag_msg :

UNIX_DIAG_NAME
Le nom du socket (par exemple, le chemin pour un socket nommé, ou l'adresse pour un socket anonyme).
UNIX_DIAG_PEER
Le numéro inode du socket pair, s'il est connecté.
UNIX_DIAG_UID
L'ID utilisateur du propriétaire du socket.
UNIX_DIAG_TIME_LEN
La longueur de la structure d'adresse du socket.
UNIX_DIAG_SERIAL
Un numéro de série unique pour le socket.

Pour les sockets TCP, le message de diagnostic est struct inet_diag_msg et les informations de mémoire disponibles sont fournies sous forme d'attributs :

SK_MEMINFO_WMEM_ALLOC
La quantité de données dans la file d'attente d'envoi.
SK_MEMINFO_SNDBUF
Le tampon de socket d'envoi tel que défini par SO_SNDBUF.
SK_MEMINFO_FWD_ALLOC
La quantité de mémoire planifiée pour une utilisation future (TCP uniquement).
SK_MEMINFO_WMEM_QUEUED
La quantité de données mises en file d'attente par TCP, mais pas encore envoyées.
SK_MEMINFO_OPTMEM
La quantité de mémoire allouée pour les besoins de service du socket (par exemple, filtre de socket).
SK_MEMINFO_BACKLOG
La quantité de paquets dans la file d'attente (pas encore traités).

VERSIONS

NETLINK_INET_DIAG a été introduit dans Linux 2.6.14 et ne prenait en charge que les sockets AF_INET et AF_INET6. Sous Linux 3.3, il a été renommé en NETLINK_SOCK_DIAG et étendu pour prendre en charge les sockets AF_UNIX.

UNIX_DIAG_MEMINFO et INET_DIAG_SKMEMINFO ont été introduits dans Linux 3.6.

STANDARDS

Linux.

EXEMPLES

L'exemple de programme suivant affiche le numéro inode, le numéro inode du pair, et le nom de tous les sockets Unix domain dans l'espace de noms actuel.

#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <linux/netlink.h>
#include <linux/rtnetlink.h>
#include <linux/sock_diag.h>
#include <linux/unix_diag.h>
static int
send_query(int fd)
{
    struct sockaddr_nl nladdr = {
        .nl_family = AF_NETLINK
    };
    struct
    {
        struct nlmsghdr nlh;
        struct unix_diag_req udr;
    } req = {
        .nlh = {
            .nlmsg_len = sizeof(req),
            .nlmsg_type = SOCK_DIAG_BY_FAMILY,
            .nlmsg_flags = NLM_F_REQUEST | NLM_F_DUMP
        },
        .udr = {
            .sdiag_family = AF_UNIX,
            .udiag_states = -1,
            .udiag_show = UDIAG_SHOW_NAME | UDIAG_SHOW_PEER
        }
    };
    struct iovec iov = {
        .iov_base = &req,
        .iov_len = sizeof(req)
    };
    struct msghdr msg = {
        .msg_name = &nladdr,
        .msg_namelen = sizeof(nladdr),
        .msg_iov = &iov,
        .msg_iovlen = 1
    };
    for (;;) {
        if (sendmsg(fd, &msg, 0) < 0) {
            if (errno == EINTR)
                continue;
            perror("sendmsg");
            return -1;
        }
        return 0;
    }
}
static int
print_diag(const struct unix_diag_msg *diag, unsigned int size)
{
    if (size < NLMSG_LENGTH(sizeof(*diag))) {
        fputs("réponse courte\n", stderr);
        return -1;
    }
    if (diag->udiag_family != AF_UNIX) {
        fprintf(stderr, "famille inattendue %u\n", diag->udiag_family);
        return -1;
    }
    unsigned int rta_len = size - NLMSG_LENGTH(sizeof(*diag));
    unsigned int peer = 0;
    size_t path_len = 0;
    char path[sizeof(((struct sockaddr_un *) 0)->sun_path) + 1];
    for (struct rtattr *attr = (struct rtattr *) (diag + 1);
             RTA_OK(attr, rta_len); attr = RTA_NEXT(attr, rta_len)) {
        switch (attr->rta_type) {
        case UNIX_DIAG_NAME:
            if (!path_len) {
                path_len = RTA_PAYLOAD(attr);
                if (path_len > sizeof(path) - 1)
                    path_len = sizeof(path) - 1;
                memcpy(path, RTA_DATA(attr), path_len);
                path[path_len] = '\0';
            }
            break;
        case UNIX_DIAG_PEER:
            if (RTA_PAYLOAD(attr) >= sizeof(peer))
                peer = *(unsigned int *) RTA_DATA(attr);
            break;
        }
    }
    printf("inode=%u", diag->udiag_ino);
    if (peer)
        printf(", pair=%u", peer);
    if (path_len)
        printf(", nom=%s%s", *path ? "" : "@",
                *path ? path : path + 1);
    putchar('\n');
    return 0;
}
static int
receive_responses(int fd)
{
    long buf[8192 / sizeof(long)];
    struct sockaddr_nl nladdr;
    struct iovec iov = {
        .iov_base = buf,
        .iov_len = sizeof(buf)
    };
    int flags = 0;
    for (;;) {
        struct msghdr msg = {
            .msg_name = &nladdr,
            .msg_namelen = sizeof(nladdr),
            .msg_iov = &iov,
            .msg_iovlen = 1
        };
        ssize_t ret = recvmsg(fd, &msg, flags);
        if (ret < 0) {
            if (errno == EINTR)
                continue;
            perror("recvmsg");
            return -1;
        }
        if (ret == 0)
            return 0;
        if (nladdr.nl_family != AF_NETLINK) {
            fputs("!AF_NETLINK\n", stderr);
            return -1;
        }
        const struct nlmsghdr *h = (struct nlmsghdr *) buf;
        if (!NLMSG_OK(h, ret)) {
            fputs("!NLMSG_OK\n", stderr);
            return -1;
        }
        for (; NLMSG_OK(h, ret); h = NLMSG_NEXT(h, ret)) {
            if (h->nlmsg_type == NLMSG_DONE)
                return 0;
            if (h->nlmsg_type == NLMSG_ERROR) {
                const struct nlmsgerr *err = NLMSG_DATA(h);
                if (h->nlmsg_len < NLMSG_LENGTH(sizeof(*err))) {
                    fputs("NLMSG_ERROR\n", stderr);
                } else {
                    errno = -err->error;
                    perror("NLMSG_ERROR");
                }
                return -1;
            }
            if (h->nlmsg_type != SOCK_DIAG_BY_FAMILY) {
                fprintf(stderr, "type nlmsg inattendu %u\n",
                        (unsigned) h->nlmsg_type);
                return -1;
            }
            if (print_diag(NLMSG_DATA(h), h->nlmsg_len))
                return -1;
        }
    }
}
int
main(void)
{
    int fd = socket(AF_NETLINK, SOCK_RAW, NETLINK_SOCK_DIAG);
    if (fd < 0) {
        perror("socket");
        return 1;
    }
    int ret = send_query(fd) || receive_responses(fd);
    close(fd);
    return ret;
}
