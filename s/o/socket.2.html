socket(2) Manuel des appels système socket(2)

NOM

socket - créer un point de terminaison pour la communication

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/socket.h>
int socket(int domain, int type, int protocol);

DESCRIPTION

socket() crée un point de terminaison pour la communication et renvoie un descripteur de fichier qui se réfère à ce point de terminaison. Le descripteur de fichier renvoyé par un appel réussi sera le descripteur de fichier ayant le plus petit numéro et qui n'est pas actuellement ouvert pour le processus.

L'argument domain spécifie un domaine de communication ; il sélectionne la famille de protocoles qui sera utilisée pour la communication. Ces familles sont définies dans <sys/socket.h>. Les formats actuellement compris par le noyau Linux incluent :

Plus de détails sur les familles d'adresses ci-dessus, ainsi que des informations sur plusieurs autres familles d'adresses, se trouvent dans address_families(7).

Le socket a le type indiqué, qui spécifie la sémantique de communication. Les types actuellement définis sont :

SOCK_STREAM
Fournit des flux d'octets séquencés, fiables, bidirectionnels et basés sur une connexion. Un mécanisme de transmission de données hors bande peut être supporté.
SOCK_DGRAM
Supporte les datagrammes (messages non connectés, non fiables d'une longueur maximale fixe).
SOCK_SEQPACKET
Fournit un chemin de transmission de données bidirectionnel basé sur une connexion, fiable et séquencé pour des datagrammes de longueur maximale fixe ; un consommateur est requis pour lire un paquet entier à chaque appel système d'entrée.
SOCK_RAW
Fournit un accès brut aux protocoles réseau.
SOCK_RDM
Fournit une couche de datagrammes fiable qui ne garantit pas l'ordre.
SOCK_PACKET
Obsolète et ne devrait pas être utilisé dans de nouveaux programmes ; voir packet(7).

Certains types de sockets peuvent ne pas être implémentés par toutes les familles de protocoles.

Depuis Linux 2.6.27, l'argument type a un second objectif : en plus de spécifier un type de socket, il peut inclure le OR bit à bit de n'importe laquelle des valeurs suivantes, pour modifier le comportement de socket():

SOCK_NONBLOCK
Définit le drapeau d'état de fichier O_NONBLOCK sur la description de fichier (voir open(2)) référencée par le nouveau descripteur de fichier. L'utilisation de ce drapeau économise des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
SOCK_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.

L'argument protocol spécifie un protocole particulier à utiliser avec le socket. Normalement, un seul protocole existe pour supporter un type de socket particulier au sein d'une famille de protocoles donnée, auquel cas protocol peut être spécifié comme 0. Cependant, il est possible que de nombreux protocoles existent, auquel cas un protocole particulier doit être spécifié de cette manière. Le numéro de protocole à utiliser est spécifique au « domaine de communication » dans lequel la communication doit avoir lieu ; voir protocols(5). Voir getprotoent(3) sur la façon de mapper les chaînes de noms de protocoles aux numéros de protocoles.

Les sockets de type SOCK_STREAM sont des flux d'octets full-duplex. Ils ne préservent pas les limites d'enregistrements. Un socket de flux doit être dans un état connecté avant que des données ne puissent y être envoyées ou reçues. Une connexion à un autre socket est créée avec un appel à connect(2). Une fois connecté, des données peuvent être transférées en utilisant les appels read(2) et write(2) ou une variante des appels send(2) et recv(2). Lorsqu'une session est terminée, un appel à close(2) peut être effectué. Des données hors bande peuvent également être transmises comme décrit dans send(2) et reçues comme décrit dans recv(2).

Les protocoles de communication qui implémentent un socket SOCK_STREAM assurent que les données ne sont ni perdues ni dupliquées. Si un morceau de données pour lequel le protocole pair dispose d'un espace tampon ne peut pas être transmis dans un délai raisonnable, alors la connexion est considérée comme morte. Lorsque SO_KEEPALIVE est activé sur le socket, le protocole vérifie d'une manière spécifique au protocole si l'autre extrémité est toujours active. Un signal SIGPIPE est déclenché si un processus envoie ou reçoit sur un flux brisé ; cela fait que les processus naïfs, qui ne gèrent pas le signal, se terminent. Les sockets SOCK_SEQPACKET utilisent les mêmes appels système que les sockets SOCK_STREAM. La seule différence est que les appels read(2) ne retourneront que la quantité de données demandée, et toute donnée restante dans le paquet entrant sera ignorée. De plus, toutes les limites de messages dans les datagrammes entrants sont préservées.

Les sockets SOCK_DGRAM et SOCK_RAW permettent l'envoi de datagrammes à des correspondants nommés dans les appels sendto(2). Les datagrammes sont généralement reçus avec recvfrom(2), qui renvoie le datagramme suivant ainsi que l'adresse de son expéditeur.

SOCK_PACKET est un type de socket obsolète pour recevoir des paquets bruts directement du pilote de périphérique. Utilisez packet(7)

DESCRIPTION

On success, zero is returned. On error, -1 is returned, and errno is set to indicate the error.

An fcntl(2) F_SETOWN operation can be used to specify a process or process group to receive a SIGURG signal when the out-of-band data arrives or SIGPIPE signal when a SOCK_STREAM connection breaks unexpectedly. This operation may also be used to set the process or process group that receives the I/O and asynchronous notification of I/O events via SIGIO. Using F_SETOWN is equivalent to an ioctl(2) call with the FIOSETOWN or SIOCSPGRP argument.

When the network signals an error condition to the protocol module (e.g., using an ICMP message for IP) the pending error flag is set for the socket. The next operation on this socket will return the error code of the pending error. For some protocols, it is possible to enable a per-socket error queue to retrieve detailed information about the error; see IP_RECVERR in ip(7).

The operation of sockets is controlled by socket level options. These options are defined in <sys/socket.h>. The functions setsockopt(2) and getsockopt(2) are used to set and get options.

VALEUR RENVOYÉE

En cas de succès, un descripteur de fichier pour le nouveau socket est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La permission de créer un socket du type et/ou du protocole spécifié est refusée.
EAFNOSUPPORT
L'implémentation ne supporte pas la famille d'adresses spécifiée.
EINVAL
Protocole inconnu, ou famille de protocoles non disponible.
EINVAL
Indicateurs invalides dans type.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENOBUFS ou ENOMEM
Mémoire insuffisante disponible. Le socket ne peut pas être créé tant que les ressources suffisantes ne sont pas libérées.
EPROTONOSUPPORT
Le type de protocole ou le protocole spécifié n'est pas supporté dans ce domaine.

D'autres erreurs peuvent être générées par les modules de protocole sous-jacents.

VERSIONS

POSIX.1-2024 spécifie SOCK_CLOFORK, mais Linux ne le supporte pas.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, 4.2BSD.

Il est généralement portable vers/depuis les systèmes non-BSD supportant des clones de la couche de sockets BSD (y compris les variantes System V).

Les constantes manifestes utilisées sous 4.x BSD pour les familles de protocoles sont PF_UNIX, PF_INET, etc., tandis que AF_UNIX, AF_INET, etc. sont utilisées pour les familles d'adresses. Cependant, la page de manuel BSD promet déjà : "La famille de protocoles est généralement la même que la famille d'adresses", et les normes ultérieures utilisent AF_* partout.
