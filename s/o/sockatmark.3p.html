SOCKATMARK(3P) Manuel du programmeur POSIX SOCKATMARK(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sockatmark — déterminer si une socket est à la marque de données urgentes

SYNTAXE

#include <sys/socket.h>
int sockatmark(int s);

DESCRIPTION

La fonction sockatmark() détermine si la socket spécifiée par le descripteur s se trouve à la marque de données urgentes (voir Section 2.10.12, État de la donnée urgente de la socket). Si le protocole de la socket prend en charge les données urgentes en marquant le flux avec une marque de données urgentes, la fonction sockatmark() renvoie 1 lorsque toutes les données précédant la marque ont été lues et que la marque de données urgentes est le premier élément dans la file d'attente de réception. La fonction sockatmark() ne supprime pas la marque du flux.

VALEUR RENVOYÉE

En cas de succès, la fonction sockatmark() renvoie une valeur indiquant si la socket est à une marque de données urgentes. Si le protocole a marqué le flux de données et que toutes les données précédant la marque ont été lues, la valeur de retour est 1 ; s'il n'y a pas de marque, ou si des données précèdent la marque dans la file d'attente de réception, la fonction sockatmark() renvoie 0. Sinon, elle renvoie une valeur de -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction sockatmark() échoue si :

EBADF
L'argument s n'est pas un descripteur de fichier valide.
ENOTTY
Le fichier associé à l'argument s n'est pas une socket.

UTILISATION PAR L'APPLICATION

L'utilisation de cette fonction entre les opérations de réception permet à une application de déterminer quelles données reçues précèdent les données urgentes et lesquelles suivent les données urgentes.

Il existe une condition de concurrence inhérente à l'utilisation de cette fonction. Sur une file d'attente de réception vide, la lecture actuelle de l'emplacement peut bien être à la « marque », mais le système n'a aucun moyen de savoir que le prochain segment de données qui arrivera du réseau portera la marque, et sockatmark() renverra false, et la prochaine opération de lecture consommera silencieusement la marque.

Par conséquent, cette fonction ne peut être utilisée de manière fiable que lorsque l'application sait déjà que les données urgentes ont été vues par le système ou qu'il est connu que des données attendent d'être lues à la socket (via SIGURG ou select()). Voir Section 2.10.11, File d'attente de réception de socket, Section 2.10.12, État de la donnée urgente de la socket, Section 2.10.14, Signaux, et pselect() pour plus de détails.

JUSTIFICATION

La fonction sockatmark() remplace la commande SIOCATMARK historique pour ioctl() qui implémentait la même fonctionnalité sur de nombreuses implémentations. L'utilisation d'une fonction d'encapsulation suit les conventions adoptées pour éviter de spécifier des commandes à la fonction ioctl(), autres que celles maintenant incluses pour prendre en charge XSI STREAMS. La fonction sockatmark() pourrait être implémentée comme suit :

#include <sys/ioctl.h>
int sockatmark(int s)
{
    int val;
    if (ioctl(s,SIOCATMARK,&val)==-1)
        return(-1);
    return(val);
}

L'utilisation de [ENOTTY] pour indiquer un type de descripteur incorrect correspond au comportement historique de SIOCATMARK.
