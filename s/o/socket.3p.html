SOCKET(3P) Manuel du programmeur POSIX SOCKET(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

socket — créer un point d'extrémité de communication

SYNTAXE

#include <sys/socket.h>
int socket(int domain, int type, int protocol);

DESCRIPTION

La fonction socket() crée un socket non lié dans un domaine de communication et retourne un descripteur de fichier qui peut être utilisé dans les appels de fonction ultérieurs opérant sur des sockets. Le descripteur de fichier est alloué comme décrit dans la Section 2.14, Allocation de descripteurs de fichiers.

La fonction socket() prend les arguments suivants :

domain
Spécifie le domaine de communication dans lequel un socket doit être créé.
type
Spécifie le type de socket à créer.
protocol
Spécifie un protocole particulier à utiliser avec le socket. La spécification d'un protocol de 0 entraîne l'utilisation par socket() d'un protocole par défaut non spécifié approprié au type de socket demandé.

L'argument domain spécifie la famille d'adresses utilisée dans le domaine de communication. Les familles d'adresses prises en charge par le système sont définies par l'implémentation.

Les constantes symboliques pouvant être utilisées pour l'argument domain sont définies dans l'en-tête <sys/socket.h>.

L'argument type spécifie le type de socket, qui détermine la sémantique de la communication sur le socket. Les types de sockets suivants sont définis ; les implémentations peuvent spécifier des types de sockets supplémentaires :

SOCK_STREAM
Fournit des flux d'octets séquencés, fiables, bidirectionnels, en mode connexion, et peut fournir un mécanisme de transmission pour les données hors bande.
SOCK_DGRAM
Fournit des datagrammes, qui sont des messages non fiables en mode sans connexion de longueur maximale fixe.
SOCK_SEQPACKET

Fournit des chemins de transmission de records séquencés, fiables, bidirectionnels, en mode connexion. Un enregistrement peut être envoyé à l'aide d'une ou plusieurs opérations de sortie et reçu à l'aide d'une ou plusieurs opérations d'entrée, mais une seule opération ne transfère jamais une partie de plus d'un enregistrement. Les frontières d'enregistrement sont visibles pour le récepteur via le drapeau MSG_EOR.

Si l'argument protocol est différent de zéro, il spécifie un protocole pris en charge par la famille d'adresses. Si l'argument protocol est zéro, le protocole par défaut pour cette famille d'adresses et ce type sera utilisé. Les protocoles pris en charge par le système sont définis par l'implémentation.

Le processus peut avoir besoin des privilèges appropriés pour utiliser la fonction socket() ou pour créer certains sockets.

VALEUR RENVOYÉE

En cas de succès, socket() renvoie un entier non négatif, le descripteur de fichier du socket. Sinon, une valeur de -1 est renvoyée et errno est défini pour indiquer l'erreur.

ERREURS

La fonction socket() échoue si :

EAFNOSUPPORT

L'implémentation ne prend pas en charge la famille d'adresses spécifiée.
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.
ENFILE
Aucun autre descripteur de fichier n'est disponible pour le système.
EPROTONOSUPPORT

Le protocole n'est pas pris en charge par la famille d'adresses, ou le protocole n'est pas pris en charge par l'implémentation.
EPROTOTYPE
Le type de socket n'est pas pris en charge par le protocole.

La fonction socket() peut échouer si :

EACCES
Le processus n'a pas les privilèges appropriés.
ENOBUFS
Des ressources insuffisantes étaient disponibles dans le système pour effectuer l'opération.
ENOMEM
Une mémoire insuffisante était disponible pour satisfaire la demande.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

La documentation des familles d'adresses spécifiques spécifie quels protocoles chaque famille d'adresses prend en charge. La documentation des protocoles spécifiques spécifie quels types de sockets chaque protocole prend en charge.

L'application peut déterminer si une famille d'adresses est prise en charge en essayant de créer un socket avec domain défini sur le protocole en question.
