NOM

soapsuds - Générateur de proxys de Rémoting Mono

SYNTAXE

soapsuds [options] [entrées] [sorties]

DESCRIPTION

soapsuds est un outil pour générer des documents WSDL et des proxys clients pour les services de Rémoting. Un document WSDL décrit les méthodes qu'un service fournit, ainsi que les schémas XML de toutes les structures de données référencées. Un proxy client est une classe qui offre les mêmes méthodes que le service qu'elle représente, mais ne fournit aucune implémentation ; elle transfère simplement les appels au service distant.

Les proxys clients générés ne sont pas strictement nécessaires, car le runtime peut générer automatiquement des proxys à partir des types de service d'origine. Cependant, cela implique la nécessité de distribuer la classe de service à tous les clients. Dans certains scénarios, une meilleure approche consiste à utiliser soapsuds pour générer une classe de proxy qui a la même interface que le service, mais sans aucune implémentation.

soapsuds peut générer un document WSDL à partir d'un ensemble de types spécifiés avec l'option -types ou peut extraire les types d'un assembly spécifié avec -inputassemblyfile. Dans ce dernier cas, soapsuds inclura des schémas pour toutes les classes sérialisables dans le document WSDL.

En prenant comme entrée un document WSDL (ou quoi que ce soit à partir duquel un tel document peut être généré), l'outil peut générer du code source pour le proxy client (en utilisant l'option -gc) ou il peut directement générer un assembly qui implémente le proxy (avec l'option -outputassemblyfile). soapsuds générera également des classes sérialisables factices pour tous les types définis dans le schéma. Cependant, attention, ces classes manqueront de la sémantique des classes d'origine, car seule la structure des données est générée.

SOURCES D'ENTRÉE

Les sources suivantes sont disponibles (une seule peut être spécifiée) :

-urltoschema:url -url:url
URL à partir de laquelle récupérer le document WSDL.
-types:type1,assembly[,serviceEndPoint][;type2,assembly[,serviceEndPoint]]...
Spécifie les types pour lesquels générer un schéma ou un proxy. Si aucun point d'accès au service n'est fourni, celui fourni avec l'option -serviceendpoint est utilisé.
-inputassemblyfile:file , -ia:file
Assembly contenant les types à exporter.
-inputschemafile:schena , -is:schema
Schéma à partir duquel générer des classes de proxy.

OPTIONS D'ENTRÉE

Les options suivantes sont disponibles :

-inputdirectory:directory , -id:directory
Répertoire où se trouvent les DLL.
-serviceendpoint:url , -se:url
URL du service à placer dans le document WSDL.

SORTIES

Les options de sortie suivantes sont disponibles (plusieurs peuvent être spécifiées) :

-outputassemblyfile:file , -oa:file
Génère le code du proxy et le compile en un assembly portant le nom fourni.
-outputschemafile:file , -os:file
Génère un document WSDL qui représente les types fournis.
-generatecode , -gc
Génère le code source du proxy pour le document WSDL ou les types fournis.

OPTIONS DE SORTIE

Les options suivantes sont disponibles :

-outputdirectory:directory , -od:directory
Répertoire où seront placés les fichiers générés.
-proxynamespace:namespace , -pn:namespace
Espace de noms du proxy généré.
-nowrappedproxy , -nowp
Ne pas générer de proxy encapsulé.
-wrappedproxy , -wp
Générer un proxy encapsulé.
-strongnamefile:file , -sn:file
Fichier de nom fort.

OPTIONS GÉNÉRALES

Les options suivantes sont disponibles :

-nologo
Supprimer le logo de démarrage.
-u:username , -user:username
Nom d'utilisateur à utiliser lors de la connexion au serveur.
-p:password , -password:password
Mot de passe à utiliser lors de la connexion au serveur.
-d:domain , -domain:domain
Domaine à utiliser lors de la connexion au serveur.
-httpproxyname:name , -hpn:name
Nom du proxy http.
-httpproxyport:port , -hpp:port
Port du proxy http.
