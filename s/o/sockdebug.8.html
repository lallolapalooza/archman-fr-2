SOCKDEBUG(8) Manuel NUT SOCKDEBUG(8)

NOM

sockdebug - Outil d'aide simple pour les développeurs/dépannage pour communiquer avec un pilote NUT en utilisant le protocole socket

SYNOPIS

sockdebug nom_socket

Par exemple (versions WIN32 et POSIX) :

:; sockdebug.exe dummy-ups-UPS1

Par exemple (systèmes compatibles POSIX utilisant un chemin d'état alternatif) :

:; sockdebug /var/state/ups/dummy-ups-UPS1

DESCRIPTION

sockdebug est un outil créé lorsque NUT est configuré avec --with-dev activé. Il peut également être créé en appelant make sockdebug dans la racine de l'espace de travail de construction. Les fichiers source réels utilisés dépendent de la plateforme.

Il est utilisé pour se connecter à un pilote NUT en utilisant le protocole socket sur un socket Unix ou un pipe Windows, de manière similaire à la façon dont le serveur de données upsd(8) communique avec les pilotes locaux en cours d'exécution afin de les représenter sur le réseau plus loin en utilisant le protocole commun NUT du projet Network UPS Tools, ou comment les programmes pilotes peuvent communiquer avec leurs instances déjà en cours d'exécution pour implémenter des commandes telles que le rechargement en direct ou la gestion des erreurs.

Cet outil permet à un développeur ou à un dépanneur de regarder les mises à jour de diffusion émises par le pilote, ainsi que d'émettre des commandes unicast et de recevoir des réponses (lors d'une session d'investigation interactive, vous pourriez vouloir commander NOBROADCAST en premier).

Pour plus de détails, consultez le fichier docs/sock-protocol.txt dans les sources NUT.

OPTIONS

sockdebug accepte (et nécessite) l'option suivante :

nom_socket

Soit un chemin complet (dans les versions POSIX), soit le nom de base du socket/pipe du périphérique (sur toutes les plateformes), composé d'un tuple nom_pilote-nom_périphérique, par exemple some dummy-ups-UPS1 pour une instance de pilote dummy-ups gérant une configuration de périphérique UPS1 (qui à son tour peut provenir du fichier ups.conf ou être construite dynamiquement pour des tests en appelant le programme pilote avec une option -s TMP sur la ligne de commande).

Sur les systèmes POSIX, si cet argument ne représente qu'un nom de base et non un chemin complet vers le fichier socket Unix, l'outil doit d'abord rechercher le fichier dans le répertoire courant, puis se rabattre sur le chemin d'état configuré (intégré) ou la valeur de la variable d'environnement NUT_STATEPATH, si elle est définie ; par exemple :

:; NUT_STATEPATH=/tmp ./server/sockdebug dummy-ups-UPS1
