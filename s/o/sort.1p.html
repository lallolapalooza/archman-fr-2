SORT(1P) Manuel du programmeur POSIX SORT(1P)

PROLOGUE

Cette page man fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man Linux correspondante pour connaître les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sort — trier, fusionner ou vérifier la séquence de fichiers texte

SYNOPIS

sort [-m] [-o sortie] [-bdfinru] [-t car] [-k clédef]... [fichier...]
sort [-c|-C] [-bdfinru] [-t car] [-k clédef] [fichier]

DESCRIPTION

L'utilitaire sort effectue l'une des fonctions suivantes :

1.
Trie les lignes de tous les fichiers nommés ensemble et écrit le résultat dans la sortie spécifiée.
2.
Fusionne les lignes de tous les fichiers nommés (prétriés) ensemble et écrit le résultat dans la sortie spécifiée.
3.
Vérifie qu'un seul fichier d'entrée est correctement prétrié.

Les comparaisons sont basées sur une ou plusieurs clés de tri extraites de chaque ligne d'entrée (ou, si aucune clé de tri n'est spécifiée, la ligne entière jusqu'à, mais sans inclure, le <newline> de terminaison), et sont effectuées en utilisant la séquence de tri de la locale courante. Si cette séquence de tri n'a pas d'ordre total de tous les caractères (voir le volume Définitions de base de POSIX.1‐2017, Section 7.3.2, LC_COLLATE), toute ligne d'entrée qui se trie de manière égale doit être comparée ultérieurement octet par octet en utilisant la séquence de tri pour la locale POSIX.

OPTIONS

L'utilitaire sort doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception de la Directive 9, et l'option -k clédef doit suivre les options -b, -d, -f, -i, -n et -r. De plus, '+' peut être reconnu comme délimiteur d'option, tout comme '-'.

Les options suivantes doivent être prises en charge :

-c
Vérifie que le fichier d'entrée unique est ordonné selon les arguments et la séquence de tri de la locale courante. Aucune sortie ne doit être envoyée à la sortie standard. Le code de sortie doit indiquer si un désordre a été détecté ou si une erreur s'est produite. Si un désordre (ou, avec -u, une clé dupliquée) est détecté, un message d'avertissement doit être envoyé à la sortie d'erreur standard, indiquant où le désordre ou la clé dupliquée a été trouvé.
-C
Identique à -c, sauf qu'un message d'avertissement ne doit pas être envoyé à la sortie d'erreur standard si un désordre ou, avec -u, une clé dupliquée est détecté.
-m
Fusion uniquement ; le fichier d'entrée est supposé être déjà trié.
-o sortie
Spécifie le nom d'un fichier de sortie à utiliser à la place de la sortie standard. Ce fichier peut être identique à l'un des fichiers d'entrée.
-u
Unique : supprime toutes les lignes ayant des clés égales, sauf une. Si utilisé avec l'option -c, vérifie qu'il n'y a pas de lignes avec des clés dupliquées, en plus de vérifier que le fichier d'entrée est trié.

Les options suivantes doivent remplacer les règles de tri par défaut. Lorsque les options de tri apparaissent indépendamment de toute spécification de champ de clé, les règles de tri demandées doivent être appliquées globalement à toutes les clés de tri. Lorsqu'elles sont attachées à une clé spécifique (voir -k), les options de tri spécifiées doivent remplacer toutes les options de tri globales pour cette clé.

-d
Spécifie que seuls les caractères <espace> et les caractères alphanumériques, selon le réglage courant de LC_CTYPE, doivent être significatifs dans les comparaisons. Le comportement est indéfini pour une clé de tri à laquelle -i ou -n s'applique également.
-f
Considère tous les caractères minuscules qui ont des équivalents majuscules, selon le réglage courant de LC_CTYPE, comme l'équivalent majuscule aux fins de comparaison.
-i
Ignore tous les caractères qui ne sont pas imprimables, selon le réglage courant de LC_CTYPE. Le comportement est indéfini pour une clé de tri pour laquelle -n s'applique également.
-n
Restreint la clé de tri à une chaîne numérique initiale, composée de caractères <espace> optionnels, d'un caractère <tiret> optionnel, et de zéro ou plusieurs chiffres avec un caractère de radix et des séparateurs de milliers optionnels (tels que définis dans la locale courante), qui doivent être triés par valeur arithmétique. Une chaîne de chiffres vide est traitée comme zéro. Les zéros de tête et les signes sur les zéros n'affectent pas l'ordre.
-r
Inverse le sens des comparaisons.

Le traitement des séparateurs de champs peut être modifié à l'aide des options :

-b
Ignore les caractères <espace> de début lors de la détermination des positions de départ et de fin d'une clé de tri restreinte. Si l'option -b est spécifiée avant la première option -k, elle s'applique à toutes les options -k. Sinon, l'option -b peut être attachée indépendamment à chaque argument d'option champ_début ou champ_fin (voir ci-dessous).
-t car
Utilise car comme caractère séparateur de champ ; car ne doit pas être considéré comme faisant partie d'un champ (bien qu'il puisse être inclus dans une clé de tri). Chaque occurrence de car doit être significative (par exemple, <car><car> délimite un champ vide). Si -t n'est pas spécifié, les caractères <espace> sont utilisés comme séparateurs de champ par défaut ; chaque séquence maximale non vide de caractères <espace> qui suit un non-<espace> doit être un séparateur de champ.

Les clés de tri peuvent être spécifiées à l'aide des options :

-k clédef
L'argument clédef est une définition de champ de clé de tri restreinte. Le format de cette définition est :
champ_début[type][,champ_fin[type]]

où champ_début et champ_fin définissent un champ de clé restreint à une partie de la ligne (voir la section DESCRIPTION ÉTENDUE), et type est un ou plusieurs modificateurs de la liste des caractères 'b', 'd', 'f', 'i', 'n', 'r'. Le modificateur 'b' se comporte comme l'option -b, mais ne s'applique qu'à champ_début ou champ_fin auquel il est attaché. Les autres modificateurs se comportent comme les options correspondantes, mais ne s'appliquent qu'au champ de clé auquel ils sont attachés ; ils ont cet effet s'ils sont spécifiés avec champ_début, champ_fin, ou les deux. Si un modificateur est attaché à un champ_début ou à un champ_fin, aucune option ne s'applique à l'un ou l'autre. Les implémentations doivent prendre en charge au moins neuf occurrences de l'option -k, qui doivent être significatives dans l'ordre de la ligne de commande. Si aucune option -k n'est spécifiée, une clé de tri par défaut de toute la ligne doit être utilisée.

Lorsqu'il existe plusieurs champs de clé, les clés ultérieures ne sont comparées qu'après que toutes les clés précédentes soient égales. Sauf lorsque l'option -u est spécifiée, les lignes qui se comparent également sont triées comme si aucune des options -d, -f, -i, -n ou -k n'était présente (mais avec -r toujours actif, s'il a été spécifié) et avec tous les octets des lignes significatifs pour la comparaison. L'ordre dans lequel les lignes qui restent égales sont écrites n'est pas spécifié.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de sort :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou sont nulles. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne non vide, remplacer les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Déterminer la locale pour les règles d'ordonnancement.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données texte comme caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée) et le comportement de la classification des caractères pour les options -b, -d, -f, -i et -n.
LC_MESSAGES

Déterminer la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LC_NUMERIC

Déterminer la locale pour la définition du caractère de séparation décimale et du séparateur de milliers pour l'option -n.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Sauf si les options -o ou -c sont actives, la sortie standard contiendra l'entrée triée.

STDERR

La sortie d'erreur standard sera utilisée pour les messages de diagnostic. Lorsque -c est spécifié, si un désordre est détecté (ou si -u est également spécifié et qu'une clé dupliquée est détectée), un message sera écrit sur la sortie d'erreur standard identifiant la ligne d'entrée à laquelle le désordre (ou une clé dupliquée) a été détecté. Un message d'avertissement concernant la correction d'une dernière ligne incomplète d'un fichier d'entrée peut être généré, mais il n'affectera pas nécessairement le statut de sortie final.

FICHIERS DE SORTIE

Si l'option -o est active, l'entrée triée sera écrite dans le fichier output.

DESCRIPTION ÉTENDUE

La notation :

-k field_start[type][,field_end[type]]

définira un champ clé qui commence à field_start et se termine à field_end inclus, sauf si field_start se trouve au-delà de la fin de la ligne ou après field_end, auquel cas le champ clé est vide. Une field_end manquante signifie le dernier caractère de la ligne.

Un champ comprend une séquence maximale de caractères non séparateurs et, en l'absence de l'option -t, tout séparateur de champ précédent.

La partie field_start de l'argument d'option keydef aura la forme :

field_number[.first_character]

Les champs et les caractères dans les champs seront numérotés à partir de 1. Les parties field_number et first_character, interprétées comme des entiers décimaux positifs, spécifieront le premier caractère à utiliser comme partie d'une clé de tri. Si .first_character est omis, il fera référence au premier caractère du champ.

La partie field_end de l'argument d'option keydef aura la forme :

field_number[.last_character]

Le field_number sera tel que décrit ci-dessus pour field_start. La partie last_character, interprétée comme un entier décimal non négatif, spécifiera le dernier caractère à utiliser comme partie de la clé de tri. Si last_character évalue à zéro ou si .last_character est omis, il fera référence au dernier caractère du champ spécifié par field_number.

Si l'option -b ou le modificateur de type b est actif, les caractères dans un champ seront comptés à partir du premier caractère non blanc (<blank>) dans le champ. (Ceci s'appliquera séparément à first_character et last_character.)

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Tous les fichiers d'entrée ont été correctement sortis, ou -c était spécifié et le fichier d'entrée était correctement trié.
 1
Sous l'option -c, le fichier n'était pas ordonné comme spécifié, ou si les options -c et -u étaient toutes deux spécifiées, deux lignes d'entrée ont été trouvées avec des clés égales.
>1
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Les exigences par défaut s'appliqueront, sauf que si sort rencontre une erreur lors de l'ouverture ou de la lecture d'un opérande file, il peut se terminer sans écrire de sortie sur la sortie standard ni traiter les opérandes ultérieurs.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

La valeur par défaut pour -t, <blanc>, a des propriétés différentes de, par exemple, -t"<espace>". Si une ligne contient :

<espace><espace>foo

le traitement suivant se produirait avec une séparation par défaut par opposition à la sélection spécifique d'un <espace> :

Champ Par défaut -t "<espace>"
1 <espace><espace>foo vide
2 vide vide
3 vide foo

Le séparateur de champ initial est inclus dans un champ lorsque -t n'est pas utilisé. Par exemple, cette commande renvoie un statut de sortie de zéro, signifiant que l'entrée était déjà triée :

sort -c -k 2 <<eof
y<tab>b
x<space>a
eof

(en supposant qu'une tabulation précède l'espace dans la séquence de classement actuelle). Le séparateur de champ n'est pas inclus dans un champ lorsqu'il est explicitement défini via -t. C'est une pratique historique et elle permet des utilisations telles que :

sort -t "|" -k 2n <<eof
Atlanta|425022|Georgia
Birmingham|284413|Alabama
Columbia|100385|South Carolina
eof

où le deuxième champ peut être correctement trié numériquement sans tenir compte du séparateur de champ non numérique.

La formulation dans la section OPTIONS clarifie que les options -b, -d, -f, -i, -n et -r doivent précéder la première clé de tri spécifiée si elles sont destinées à s'appliquer à toutes les clés spécifiées. La manière dont c'est décrit dans ce volume de POSIX.1‐2017 correspond à la pratique historique, et non à la documentation historique. Les résultats ne sont pas spécifiés si ces options sont spécifiées après une option -k.

L'option -f pourrait ne pas fonctionner comme prévu dans les locales où il n'y a pas de correspondance un-à-un entre une lettre majuscule et une lettre minuscule.

Lors de l'utilisation de sort pour traiter des noms de chemin, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les noms de chemin peuvent contenir des séquences d'octets qui ne forment pas des caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire serait indéfini. Dans la locale POSIX, chaque octet est un caractère valide mono-octet, et donc ce problème est évité.

Si la séquence de classement de la locale actuelle n'a pas d'ordre total sur tous les caractères, cela peut affecter le comportement de sort de la manière suivante :

*
Comme sort -u supprime les lignes avec des clés dupliquées, il supprime les lignes qui se classent de manière égale mais qui ne sont pas identiques.
*
La sortie de sort (sans -u) peut contenir des lignes identiques qui ne sont pas adjacentes, s'il n'implémente pas la comparaison octet par octet recommandée des lignes qui se classent de manière égale. Cela affecte l'utilisation de sort avec comm et uniq ; voir l'UTILISATION PAR L'APPLICATION pour ces utilitaires.

EXEMPLES

1.
La commande suivante trie le contenu de infile avec le deuxième champ comme clé de tri :
s

PROLOG

This page is a manual page for the sort command in the GNU C Library (or specifically, the GNU implementation of the POSIX standard utilities). It is intended to be fully compatible with the POSIX standard, documented in the Base Definitions volume of POSIX.1‐2017.

NAME

sort - sort lines of text files

SYNOPSIS

sort [-bc CdfgiMmnr -S suffix -T tempdir -u] [-H [charkey]] [-y [lines]] [file... ] [< input]
sort -k keydef ... [-y [lines]] [-H [charkey]] [-S suffix] [-T tempdir] [-b C cdfgiMmnr u] [file... ] [< input]
sort -k keydef ... -m [-y [lines]] [-H [charkey]] [-S suffix] [-T tempdir] [-b C cdfgiMmnr u] [file... ] [< input]

DESCRIPTION

The sort utility sorts the lines of one or more text files.

The default sort order is lexicographical based on the characters identified by the current locale.

The sort order is determined by the locale specified by the environment variables {@code LC_ALL}, {@code LC_COLLATE}, and {@code LANG}. See {@code locale(7)} for more information.

OPTIONS

The sort utility conforms to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines. Some options are historic and have varying behavior across implementations.

-b
Ignore leading blanks when comparing lines, except when the {@code -n} option is in effect. Historically, this was implied by {@code -n}, but this is not the case in this version.
-C
Check that the given files are already sorted. If they are, produce no output. If they are not, print an error message to standard error indicating the first line that is out of order and exit with a non-zero exit status. This option is not supported by the POSIX standard.
-c
Check that the given files are already sorted. If they are, produce no output. If they are not, print an error message to standard error indicating the first line that is out of order and exit with a non-zero exit status. This option is supported by the POSIX standard.
-d
Enable the "dictionary order" or "fold" ordering. This means that only alphanumeric characters are compared, and all other characters (such as blanks and punctuation) are ignored. If the {@code -f} option is also specified, letters are converted to lowercase before comparison.
-f
Convert uppercase letters to lowercase before comparison. This option is ignored if the {@code -d} option is not specified.
-i
Ignore characters that are not involved in the comparison. This option is intended to be used with character sets that have ignorable characters.
-k keydef
Specify a sort key. The format of keydef is:
pos1[-pos2]

where pos1 and pos2 define the start and end of the key field. The fields are separated by blanks. A field is denoted by F[.c][options], where F is the field number (starting from 1) and c is the character position within the field (starting from 0). If F is omitted, the key starts at the beginning of the line. If c is omitted, the key starts at the first character of the field. If -pos2 is omitted, the key extends to the end of the line. Several {@code -k} options can be specified.

The keydef syntax is described in detail in the EXTENDED DESCRIPTION section.

-m
Merge the sorted input files. This option is used when the input files are already sorted.
-M
Compare using the month abbreviation, thus the January sort value is first, ..., and December sort value is last. Invalid months will sort before January.
-n
Enable the numeric sort. This means that only the numeric value of the leading portion of the line is used for comparison. Leading blanks are ignored.
-r
Reverse the result of comparisons.
-S suffix
Specify the amount of space to use for sorting. The value can be a number followed by a multiplier (k for kilobytes, m for megabytes, g for gigabytes). The default is 4MB.
-T tempdir
Specify the directory that will be used for intermediate temporary files. The default is {@code /tmp}.
-u
Unique. Output only the first of an equal sequence. This is a suppress-duplicate-lines mode. The order of comparison is the same as the default. Without the {@code -f} option, lines are sorted based on the binary value of the characters. With the {@code -f} option, lines are sorted based on the binary value of the characters after converting all uppercase letters to lowercase. If the {@code -u} option is used, only one line from each set of lines that compare equal will be output.
-y lines
Specify the number of lines of memory to use. This option is obsolete and is provided for compatibility only. The behavior is the same as specifying the {@code -S} option.
-H [charkey]
Specify the number of bytes to use for the initial hash computation. This option is obsolete and is provided for compatibility only.

OPERANDS

The following operands are supported:

file
The pathnames of one or more files to be sorted. If no file operands are specified, the standard input shall be used.

STDIN

The standard input may be used if no file operands are specified.

INPUT FILES

The input files are concatenated and sorted.

ENVIRONMENT VARIABLES

The following environment variables affect the execution of sort:

{@code LC_ALL}
Determine the locale to be used for formatting of locale categories.
{@code LC_COLLATE}
Determine the locale to be used for the order of characters.
{@code LC_CTYPE}
Determine the locale to be used for the interpretation of characters as alphabetic, digit, etc.
{@code LC_MESSAGES}
Determine the locale to be used for the locale categories that are locale-dependent.
{@code LANG}
Determine the locale to be used for categories when more specific environment variables ({@code LC_ALL}, {@code LC_CTYPE}, {@code LC_COLLATE}, {@code LC_MESSAGES}) are not set.
{@code TMPDIR}
Determine the directory that will be used for intermediate temporary files. If this environment variable is not set, or if it is not set to a valid directory, the utility shall use {@code /tmp} as the default.

ASYNCHRONOUS EVENTS

Undefined.

STDOUT

The sorted lines are written to standard output.

STDERR

The standard error is used only for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

The sort utility sorts lines of text files. The sort order is determined by the locale specified by the environment variables {@code LC_ALL}, {@code LC_COLLATE}, and {@code LANG}.

The {@code -k} option specifies the sort key. A key is defined by a field start and optionally a field end. The format is:

     -k field_start[,field_end]

Each field is defined by a field number and an optional character position within the field. The format is:

     F[.C][options]

where F is the field number (starting from 1) and C is the character position within the field (starting from 0). If F is omitted, the key starts at the beginning of the line. If C is omitted, the key starts at the first character of the field. If field_end is omitted, the key extends to the end of the line.

The following options can be specified for each key:

b
Ignore leading blanks.
c
Check that the key is already sorted.
d
Use dictionary order.
f
Fold uppercase to lowercase.
i
Ignore non-alphanumeric characters.
m
Merge sorted files.
n
Use numeric sort.
r
Reverse the result of comparisons.

Multiple {@code -k} options can be specified to define multiple sort keys. The keys are compared in the order they are specified.

A blank is defined as a blank character (space or tab).

The default behavior is to sort lexicographically using the entire line as the key.

The {@code -u} option suppresses all but the first line from each set of lines that compare equal.

The {@code -C} option checks that the input files are already sorted. It produces no output if they are sorted, and exits with status 0. If the files are not sorted, it prints an error message to standard error indicating the first line that is out of order and exits with status 1.

The {@code -c} option is similar to {@code -C}, but it is POSIX compliant. It also produces no output if the files are sorted and exits with status 0. If the files are not sorted, it prints an error message to standard error indicating the first line that is out of order and exits with status 1.

The {@code -m} option merges already sorted files. It is more efficient than sorting the concatenated files.

EXIT STATUS

The following exit statuses are returned:

0
Successful completion.
1
A file specified with {@code -c} or {@code -C} was not sorted, or an error occurred.
>1
An error occurred.

CONSEQUENCES OF ERRORS

Undefined.

APPLICATION USAGE

When sorting lines, the default behavior is to use the current locale for character comparison. If locale-specific sorting is not desired, the {@code LC_ALL=C} environment variable should be set before invoking sort.

The {@code -k} option with numeric or other modifiers should be used carefully to ensure the desired sorting behavior.

EXAMPLES

1.
The following command sorts the contents of infile lexicographically and places the output in outfile:
sort -o outfile infile
2.
The following command sorts, in reverse order, the contents of infile1 and infile2, placing the output in outfile and using the second character of the second field as the sort key (assuming that the first character of the second field is the field separator):
sort -r -o outfile -k 2.2,2.2 infile1 infile2
3.
The following command sorts the contents of infile1 and infile2 using the second non-<blank> of the second field as the sort key:
sort -k 2.2b,2.2b infile1 infile2
4.
The following command prints the System V password file (user database) sorted by the numeric user ID (the third <colon>-separated field):
sort -t : -k 3,3n /etc/passwd
5.
The following command prints the lines of the already sorted file infile, suppressing all but one occurrence of lines having the same third field:
sort -um -k 3.1,3.0 infile

RATIONALE

Examples in some historical documentation state that options -um with one input file keep the first in each set of lines with equal keys. This behavior was deemed to be an implementation artifact and was not standardized.

The -z option was omitted; it is not standard practice on most systems and is inconsistent with using sort to sort several files individually and then merge them together. The text concerning -z in historical documentation appeared to require implementations to determine the proper buffer length during the sort phase of operation, but not during the merge.

The -y option was omitted because of non-portability. The -M option, present in System V, was omitted because of non-portability in international usage.

An undocumented -T option exists in some implementations. It is used to specify a directory for intermediate files. Implementations are encouraged to support the use of the TMPDIR environment variable instead of adding an option to support this functionality.

The -k option was added to satisfy two objections. First, the zero-based counting used by sort is not consistent with other utility conventions. Second, it did not meet syntax guideline requirements.

Historical documentation indicates that ``setting -n implies -b''. The description of -n already states that optional leading <blank>s are tolerated in doing the comparison. If -b is enabled, rather than implied, by -n, this has unusual side-effects. When a character offset is used in a column of numbers (for example, to sort modulo 100), that offset is measured relative to the most significant digit, not to the column. Based upon a recommendation from the author of the original sort utility, the -b implication has been omitted from this volume of POSIX.1‐2017, and an application wishing to achieve the previously mentioned side-effects has to code the -b flag explicitly.

Earlier versions of this standard allowed the -o option to appear after operands. Historical practice allowed all options to be interspersed with operands. This version of the standard allows implementations to accept options after operands but conforming applications should not use this form.

Earlier versions of this standard also allowed the -number and +number options. These options are no longer specified by POSIX.1‐2008 but may be present in some implementations.

Historical implementations produced a message on standard error when -c was specified and disorder was detected, and when -c and -u were specified and a duplicate key was detected. An earlier version of this standard contained wording that did not make it clear that this message was allowed and some implementations removed this message to be sure that they conformed to the standard's requirements. Confronted with this difference in behavior, interactive users that wanted to be sure that they got visual feedback instead of just exit code 1 could have used a command like:

sort -c file || echo disorder

whether or not the sort utility provided a message in this case. But, it was not easy for a user to find where the disorder or duplicate key occurred on implementations that do not produce a message, especially when some parts of the input line were not part of the key and when one or more of the -b, -d, -f, -i, -n, or -r options or keydef type modifiers were in use. POSIX.1‐2008 requires a message to be produced in this case. POSIX.1‐2008 also contains the -C option giving users the ability to choose either behavior.

When a disorder or duplicate is found when the -c option is specified, some implementations print a message containing the first line that is out of order or contains a duplicate key; others print a message specifying the line number of the offending line. This standard allows either type of message.

Implementations are encouraged to perform the recommended further byte-by-byte comparison of lines that collate equally, even though this may affect efficiency. The impact on efficiency can be mitigated by only performing the additional comparison if the current locale's collating sequence does not have a total ordering of all characters (if the implementation provides a way to query this) or by only performing the additional comparison if the locale name associated with the LC_COLLATE category has an '@' modifier in the name (since locales without an '@' modifier should have a total ordering of all characters — see the Base Definitions volume of POSIX.1‐2017, Section 7.3.2, LC_COLLATE). Note that if the implementation provides a stable sort option as an extension (usually -s), the additional comparison should not be performed when this option has been specified.

FUTURE DIRECTIONS

A future version of this standard may require that if the collating sequence of the current locale does not have a total ordering of all characters, any lines of input that collate equally when comparing them as whole lines are further compared byte-by-byte using the collating sequence for the POSIX locale.
