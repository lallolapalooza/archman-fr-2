SOCKETPAIR(3P) Manuel du programmeur POSIX SOCKETPAIR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

socketpair — crée une paire de sockets connectés

SYNTAXE

#include <sys/socket.h>
int socketpair(int domain, int type, int protocol,
    int socket_vector[2]);

DESCRIPTION

La fonction socketpair() crée une paire de sockets non liés et connectés dans un domaine spécifié, d'un type spécifié, sous le protocole éventuellement spécifié par l'argument protocol. Les deux sockets seront identiques. Les descripteurs de fichiers utilisés pour référencer les sockets créés seront retournés dans socket_vector[0] et socket_vector[1]. Les descripteurs de fichiers seront alloués comme décrit dans la Section 2.14, Allocation des descripteurs de fichiers.

La fonction socketpair() prend les arguments suivants :

domain
Spécifie le domaine de communication dans lequel les sockets doivent être créés.
type
Spécifie le type de sockets à créer.
protocol
Spécifie un protocole particulier à utiliser avec les sockets. Spécifier un protocol de 0 entraîne l'utilisation par socketpair() d'un protocole par défaut non spécifié et approprié pour le type de socket demandé.
socket_vector
Spécifie un tableau de 2 entiers pour contenir les descripteurs de fichiers de la paire de sockets créée.

L'argument type spécifie le type de socket, qui détermine la sémantique des communications sur le socket. Les types de socket suivants sont définis ; les implémentations peuvent spécifier des types de socket supplémentaires :

SOCK_STREAM
Fournit des flux d'octets séquencés, fiables, bidirectionnels, en mode connexion, et peut fournir un mécanisme de transmission pour les données hors bande.
SOCK_DGRAM
Fournit des datagrammes, qui sont des messages sans connexion, non fiables et de longueur maximale fixe.
SOCK_SEQPACKET
Fournit des chemins de transmission de base de données séquencés, fiables, bidirectionnels, en mode connexion. Un enregistrement peut être envoyé en utilisant une ou plusieurs opérations de sortie et reçu en utilisant une ou plusieurs opérations d'entrée, mais une seule opération ne transfère jamais une partie de plus d'un enregistrement. Les limites d'enregistrement sont visibles par le récepteur via le drapeau MSG_EOR.

Si l'argument protocol est non nul, il spécifie un protocole pris en charge par la famille d'adresses. Si l'argument protocol est zéro, le protocole par défaut pour cette famille d'adresses et ce type sera utilisé. Les protocoles pris en charge par le système sont définis par l'implémentation.

Le processus peut avoir besoin de disposer des privilèges appropriés pour utiliser la fonction socketpair() ou pour créer certains sockets.

VALEUR DE RETOUR

En cas de succès, cette fonction retourne 0 ; sinon, -1 est retourné et errno est défini pour indiquer l'erreur, aucun descripteur de fichier n'est alloué, et le contenu de socket_vector reste inchangé.

ERREURS

La fonction socketpair() échouera si :

EAFNOSUPPORT

L'implémentation ne prend pas en charge la famille d'adresses spécifiée.
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts, ou tous sauf un.
ENFILE
Plus aucun descripteur de fichier n'est disponible pour le système.
EOPNOTSUPP
Le protocole spécifié ne permet pas la création de paires de sockets.
EPROTONOSUPPORT

Le protocole n'est pas pris en charge par la famille d'adresses, ou le protocole n'est pas pris en charge par l'implémentation.
EPROTOTYPE
Le type de socket n'est pas pris en charge par le protocole.

La fonction socketpair() peut échouer si :

EACCES
Le processus ne dispose pas des privilèges appropriés.
ENOBUFS
Ressources insuffisantes disponibles dans le système pour effectuer l'opération.
ENOMEM
Mémoire insuffisante disponible pour satisfaire la demande.

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

La documentation des familles d'adresses spécifiques précise quels protocoles chaque famille d'adresses prend en charge. La documentation des protocoles spécifiques précise quels types de sockets chaque protocole prend en charge.

La fonction socketpair() est principalement utilisée avec les sockets de domaine UNIX et n'a pas besoin d'être prise en charge pour d'autres domaines.
