SOURCES.LIST(5) APT SOURCES.LIST(5)

NOM

sources.list - Liste des sources de données APT configurées

DESCRIPTION

La liste des sources /etc/apt/sources.list et les fichiers qu'elle contient dans /etc/apt/sources.list.d/ sont conçus pour prendre en charge un nombre quelconque de sources actives et une variété de supports de sources. Les fichiers listent une source par ligne (style sur une seule ligne) ou contiennent des strophes multilignes définissant une ou plusieurs sources par strophe (style deb822), la source la plus préférée étant listée en premier (au cas où une seule version est disponible à partir de plusieurs sources). Les informations disponibles auprès des sources configurées sont acquises par apt-get update (ou par une commande équivalente d'un autre front-end APT).

Si plusieurs listes de sources sont utilisées, les sources les plus préférées sont celles listées dans /etc/apt/sources.list, suivies de chaque fichier dans /etc/apt/sources.list.d/ par ordre lexicographique : par exemple, 00-haute-préférence.list est plus préférée que 50-préférence-moyenne.sources qui est plus préférée que z-basse-préférence.list.

SOURCES.LIST.D

Le répertoire /etc/apt/sources.list.d offre un moyen d'ajouter des entrées sources.list dans des fichiers séparés. Deux formats de fichiers différents sont autorisés, comme décrit dans les deux sections suivantes. Les noms de fichiers doivent avoir l'extension .list ou .sources selon le format contenu. Les noms de fichiers ne peuvent contenir que des lettres (a-z et A-Z), des chiffres (0-9), un trait de soulignement (_), un tiret (-) et un point (.). Sinon, APT affichera une notification indiquant qu'il a ignoré un fichier, à moins que ce fichier ne corresponde à un modèle dans la liste de configuration Dir::Ignore-Files-Silently - auquel cas il sera ignoré silencieusement.

Le nom de fichier suggéré pour les nouveaux systèmes est /etc/apt/sources.list.d/vendor.sources, où vendor est le résultat de dpkg-vendor --query Vendor | tr A-Z a-z, au format deb822. Par exemple, Ubuntu utilise /etc/apt/sources.list.d/ubuntu.sources.

FORMAT STYLE SUR UNE LIGNE

Les fichiers dans ce format ont l'extension .list. Chaque ligne spécifiant une source commence par un type (par exemple, deb-src) suivi d'options et d'arguments pour ce type. Les entrées individuelles ne peuvent pas être continuées sur la ligne suivante. Les lignes vides sont ignorées, et un caractère # n'importe où sur une ligne marque le reste de cette ligne comme un commentaire. Par conséquent, une entrée peut être désactivée en commentant toute la ligne. Si des options doivent être fournies, elles sont séparées par des espaces et toutes ensemble sont enfermées entre crochets ([]) incluses dans la ligne après le type, séparées de celui-ci par un espace. Si une option autorise plusieurs valeurs, celles-ci sont séparées les unes des autres par une virgule (,). Un nom d'option est séparé de sa ou ses valeurs par un signe égal (=). Les options multivaluées ont également des séparateurs -= et +=, qui au lieu de remplacer la valeur par défaut par les valeurs données, modifient les valeurs par défaut pour supprimer ou inclure les valeurs données.

C'est le format traditionnel et il est pris en charge par toutes les versions d'apt. Notez que toutes les options décrites ci-dessous ne sont pas prises en charge par toutes les versions d'apt. Notez également que certaines anciennes applications analysant ce format par elles-mêmes pourraient ne pas s'attendre à rencontrer d'options car elles étaient rares avant l'introduction du support multi-architecture.

Ce format est déprécié et pourrait être supprimé à terme, mais pas avant 2029.

FORMAT STYLE DEB822

Les fichiers dans ce format ont l'extension .sources. Le format est similaire en syntaxe à d'autres fichiers utilisés par Debian et ses dérivés, tels que les fichiers de métadonnées qu'APT téléchargera à partir des sources configurées ou le fichier debian/control dans un paquet source Debian. Les entrées individuelles sont séparées par une ligne vide ; les lignes vides supplémentaires sont ignorées, et un caractère # au début de la ligne marque toute la ligne comme un commentaire. Une entrée peut donc être désactivée en commentant chaque ligne appartenant à la strophe, mais il est généralement plus facile d'ajouter le champ "Enabled: no" à la strophe pour désactiver l'entrée. La suppression du champ ou sa définition sur yes le réactive. Les options ont la même syntaxe que tout autre champ : un nom de champ séparé par deux-points (:) et éventuellement des espaces de sa ou ses valeurs. Notez en particulier que les valeurs multiples sont séparées par des espaces blancs (comme les espaces, les tabulations et les retours à la ligne), et non par des virgules comme dans le format sur une seule ligne. Les champs multivalués tels que Architectures ont également Architectures-Add et Architectures-Remove pour modifier la valeur par défaut plutôt que de la remplacer.

C'est un nouveau format pris en charge par APT lui-même depuis la version 1.1. Les versions précédentes ignorent ces fichiers avec un message de notification, comme décrit précédemment. Il est destiné à faire de ce format progressivement le format par défaut, dépréciant le format style sur une seule ligne décrit précédemment, car il est plus facile à créer, étendre et modifier pour les humains et les machines, surtout s'il y a beaucoup de sources et/ou d'options impliquées. Les développeurs qui travaillent avec et/ou analysent les sources APT sont fortement encouragés à ajouter la prise en charge de ce format et à contacter l'équipe APT pour coordonner et partager ce travail. Les utilisateurs peuvent adopter librement ce format dès maintenant, mais peuvent rencontrer des problèmes avec les logiciels qui ne prennent pas encore en charge le format.

LES TYPES DEB ET DEB-SRC : FORMAT GÉNÉRAL

Le type deb référence une archive Debian typique à deux niveaux, distribution/composant. La distribution est généralement un nom de suite comme stable ou testing ou un nom de code comme trixie ou forky, tandis que composant est l'un de main, contrib, non-free ou non-free-firmware. Le type deb-src référence le code source d'une distribution Debian sous la même forme que le type deb. Une ligne deb-src est requise pour récupérer les index de sources.

Le format pour deux entrées style sur une seule ligne utilisant les types deb et deb-src est :

deb [ option1=valeur1 option2=valeur2 ] uri suite [composant1] [composant2] [...]
deb-src [ option1=valeur1 option2=valeur2 ] uri suite [composant1] [composant2] [...]

Alternativement, l'entrée équivalente au style deb822 ressemble à cela :

     Types : deb deb-src
     URIs : uri
     Suites : suite
     Composants : [composant1] [composant2] [...]
     option1 : valeur1
     option2 : valeur2

L'URI pour le type deb doit spécifier la base de la distribution Debian, à partir de laquelle APT trouvera les informations dont elle a besoin. suite peut spécifier un chemin exact, auquel cas les composants doivent être omis et suite doit se terminer par une barre oblique (/). Ceci est utile dans le cas où seul un sous-répertoire particulier de l'archive désigné par l'URI est intéressant. Si suite ne spécifie pas un chemin exact, au moins un composant doit être présent.

suite peut également contenir une variable, $(ARCH), qui se développe en l'architecture Debian (comme amd64 ou armel) utilisée sur le système. Ceci permet d'utiliser des fichiers sources.list indépendants de l'architecture. En général, ceci n'est intéressant que lorsque l'on spécifie un chemin exact ; APT générera automatiquement une URI avec l'architecture actuelle sinon.

En particulier dans le format sur une seule ligne, car une seule distribution peut être spécifiée par ligne, il peut être nécessaire d'avoir plusieurs lignes pour la même URI, si un sous-ensemble de toutes les distributions ou composants disponibles à cet emplacement est souhaité. APT triera la liste des URI après avoir généré un ensemble complet en interne, et regroupera plusieurs références au même hôte Internet, par exemple, en une seule connexion, de sorte qu'il n'établisse pas de manière inefficace une connexion, ne la ferme pas, ne fasse autre chose, puis ne rétablisse pas une connexion au même hôte. APT parallélise également les connexions vers différents hôtes pour mieux gérer les sites à faible bande passante.

Il est important de lister les sources par ordre de préférence, la source la plus préférée étant listée en premier. Typiquement, cela se traduira par un tri de la plus rapide à la plus lente (CD-ROM suivi des hôtes sur un réseau local, suivi des hôtes distants sur Internet, par exemple).

Par exemple, les sources de votre distribution pourraient ressembler à ceci dans le format déprécié sur une seule ligne :

deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian trixie main contrib non-free non-free-firmware
deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian trixie-updates main contrib non-free non-free-firmware

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian-security trixie-security main contrib non-free non-free-firmware

ou comme ceci au format deb822 :

Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie trixie-updates
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
Types: deb
URIs: http://deb.debian.org/debian-security
Suites: trixie-security
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg

LES TYPES DEB ET DEB-SRC : OPTIONS

Chaque entrée de source peut avoir des options spécifiées pour modifier la source à laquelle accéder et la manière dont les données en sont acquises. Le format, la syntaxe et les noms des options varient entre les formats à ligne unique et deb822, mais ils disposent tous des mêmes options disponibles. Pour plus de simplicité, nous listons le nom du champ deb822 et fournissons le nom en ligne unique entre crochets. Rappelez-vous qu'en plus de définir explicitement des options multivaluées, il existe également la possibilité de les modifier en fonction de la valeur par défaut, mais nous ne listons pas explicitement ces noms ici. Les options non prises en charge sont silencieusement ignorées par toutes les versions d'APT.

•Include (include) est une option multivaluée définissant quels paquets doivent être utilisés à partir de ce dépôt. Les autres ne sont pas analysés.
•Exclude (exclude) est une option multivaluée définissant quels paquets ne doivent pas être utilisés à partir de ce dépôt. Ils ne seront pas analysés. Cette option est mutuellement exclusive avec Include.
•Architectures (arch) est une option multivaluée définissant pour quelles architectures les informations doivent être téléchargées. Si cette option n'est pas définie, la valeur par défaut est toutes les architectures telles que définies par l'option de configuration APT::Architectures.
•Languages (lang) est une option multivaluée définissant pour quelles langues les informations telles que les descriptions de paquets traduites doivent être téléchargées. Si cette option n'est pas définie, la valeur par défaut est toutes les langues telles que définies par l'option de configuration Acquire::Languages.
•Targets (target) est une option multivaluée définissant quels cibles de téléchargement apt essaiera d'acquérir à partir de cette source. Si elle n'est pas spécifiée, l'ensemble par défaut est défini par la portée de configuration Acquire::IndexTargets (les cibles sont spécifiées par leur nom dans le champ Created-By). De plus, les cibles peuvent être activées ou désactivées en utilisant le champ Identifier comme une option avec une valeur booléenne au lieu d'utiliser cette option multivaluée.
•PDiffs (pdiffs) est une valeur oui/non qui contrôle si APT doit essayer d'utiliser les PDiffs pour mettre à jour les anciens index au lieu de télécharger entièrement les nouveaux index. La valeur de cette option est ignorée si le dépôt n'annonce pas la disponibilité des PDiffs. Par défaut, la valeur de l'option du même nom pour un fichier d'index spécifique défini dans la portée Acquire::IndexTargets, qui par défaut est la valeur de l'option de configuration Acquire::PDiffs qui par défaut est oui.
•By-Hash (by-hash) peut avoir la valeur oui, non ou forcer et contrôle si APT doit essayer d'acquérir les index via une URI construite à partir d'une somme de contrôle du fichier attendu au lieu d'utiliser le nom de fichier stable bien connu de l'index. L'utilisation de cette option peut éviter les discordances de sommes de contrôle, mais nécessite un miroir compatible. Une valeur oui ou non active/désactive l'utilisation de cette fonctionnalité si cette source l'indique, tandis que forcer activera la fonctionnalité indépendamment de ce qu'indique la source. Par défaut, la valeur de l'option du même nom pour un fichier d'index spécifique défini dans la portée Acquire::IndexTargets, qui par défaut est la valeur de l'option de configuration Acquire::By-Hash qui par défaut est oui.

De plus, il existe des options qui, si elles sont définies, affectent *toutes* les sources ayant la même URI et Suite, elles doivent donc être définies sur toutes ces entrées et ne peuvent pas varier entre les différents composants. APT essaiera de détecter et de signaler de telles anomalies.

•Allow-Insecure (allow-insecure), Allow-Weak (allow-weak) et Allow-Downgrade-To-Insecure (allow-downgrade-to-insecure) sont des valeurs booléennes qui sont toutes par défaut à non. Si elles sont définies sur oui, elles contournent certaines parties de apt-secure(8) et ne doivent donc pas être utilisées à la légère !
•Trusted (trusted) est une valeur à trois états qui est par défaut à APT décidant si une source est considérée comme fiable ou si des avertissements doivent être émis avant, par exemple, que des paquets ne soient installés à partir de cette source. Cette option peut être utilisée pour remplacer cette décision. La valeur oui indique à APT de toujours considérer cette source comme fiable, même si elle ne passe pas les vérifications d'authentification. Elle désactive certaines parties de apt-secure(8), et ne doit donc être utilisée que dans un contexte local et fiable (si tant est qu'elle le soit) car la sécurité serait autrement compromise. La valeur non fait le contraire, entraînant que la source soit traitée comme non fiable même si les vérifications d'authentification ont réussi. La valeur par défaut ne peut pas être définie explicitement.
•Signed-By (signed-by) est une option pour exiger qu'un dépôt passe la vérification apt-secure(8) avec un ensemble d'onglets spécifique plutôt qu'avec tous les onglets fiables qu'APT a configurés. Elle est spécifiée comme une liste de chemins absolus vers des fichiers de trousseaux de clés (doivent être accessibles et lisibles par l'utilisateur système _apt, assurez-vous donc que tout le monde a les permissions de lecture sur le fichier) et les empreintes digitales des clés à sélectionner parmi ces trousseaux de clés. Les emplacements recommandés pour les trousseaux de clés sont /usr/share/keyrings pour les trousseaux gérés par les paquets, et /etc/apt/keyrings pour les trousseaux gérés par l'opérateur système. Si aucun fichier de trousseau de clés n'est spécifié, la valeur par défaut est le trousseau trusted.gpg et tous les trousseaux dans le répertoire trusted.gpg.d/. Si aucune empreinte digitale n'est spécifiée, toutes les clés des trousseaux de clés sont sélectionnées. Une empreinte digitale acceptera également toutes les signatures par une sous-clé de cette clé, si cela n'est pas souhaité, un point d'exclamation (!) peut être ajouté à l'empreinte digitale pour désactiver ce comportement. L'option est par défaut à la valeur de l'option du même nom si elle est définie dans le fichier Release acquis précédemment de ce dépôt (seules les empreintes digitales peuvent y être spécifiées). Sinon, toutes les clés dans les trousseaux de clés fiables sont considérées comme des signataires valides pour ce dépôt. L'option peut également être définie directement sur un bloc de clé publique GPG intégré. •Check-Valid-Until (check-valid-until) est une valeur oui/non qui contrôle si APT doit essayer de détecter les attaques par rejeu. Un créateur de dépôt peut déclarer une heure jusqu'à laquelle les données fournies dans le dépôt doivent être considérées comme valides, et si cette heure est atteinte mais qu'aucune nouvelle donnée n'est fournie, les données sont considérées comme expirées et une erreur est générée. En plus d'augmenter la sécurité, car un attaquant malveillant ne peut pas envoyer d'anciennes données indéfiniment pour empêcher un utilisateur de passer à une nouvelle version, cela aide également les utilisateurs à identifier les miroirs qui ne sont plus mis à jour. Cependant, certains dépôts tels que les archives historiques ne sont plus mis à jour par conception, ce contrôle peut donc être désactivé en définissant cette option sur non. Par défaut, la valeur de l'option de configuration Acquire::Check-Valid-Until qui par défaut est oui.
•Valid-Until-Min (valid-until-min) et Valid-Until-Max (valid-until-max) peuvent être utilisés pour augmenter ou diminuer la période de temps en secondes pendant laquelle les données de ce dépôt sont considérées comme valides. -Max peut être particulièrement utile si le dépôt ne fournit pas de champ Valid-Until dans son fichier Release pour définir votre propre valeur, tandis que -Min peut être utilisé pour augmenter le temps de validité sur des miroirs locaux rarement mis à jour d'une archive plus fréquemment mise à jour mais moins accessible (qui est également dans sources.list) au lieu de désactiver complètement la vérification. Par défaut, la valeur des options de configuration Acquire::Min-ValidTime et Acquire::Max-ValidTime qui sont toutes deux non définies par défaut.
•Check-Date (check-date) est une valeur oui/non qui contrôle si APT doit considérer l'heure de la machine comme correcte et effectuer par conséquent des vérifications liées au temps, telles que la vérification qu'un fichier Release ne provient pas du futur. La désactivation désactive également l'option Check-Valid-Until mentionnée ci-dessus.
•Date-Max-Future (date-max-future) contrôle à quel point le futur peut être le dépôt. Par défaut, la valeur de l'option de configuration Acquire::Max-FutureTime qui est de 10 secondes par défaut.
•InRelease-Path (inrelease-path) détermine le chemin vers le fichier InRelease, relatif à la position normale d'un fichier InRelease. Par défaut, cette option n'est pas définie et APT essaiera de récupérer un fichier InRelease ou, en cas d'échec, un fichier Release et son fichier Release.gpg associé. En définissant cette option, le chemin spécifié sera essayé à la place du fichier InRelease, et le recours aux fichiers Release sera désactivé.
•Snapshot (snapshot) permet de sélectionner une version antérieure de l'archive du service de snapshot. Les valeurs prises en charge sont : enable (par défaut) pour autoriser la sélection d'un snapshot avec l'option --snapshot, ID, ou disable pour exclure le dépôt.

Les identifiants de snapshot sont généralement des horodatages sous la forme AAAA MM JJTHH MM SSZ, tels que 20220102T030405Z qui correspond au 2 janvier 2022 à 03:04:05 UTC, les serveurs peuvent cependant prendre en charge d'autres types d'identifiants, et APT n'effectue actuellement aucune vérification.

SPÉCIFICATION URI

Les types d'URI actuellement reconnus sont :

http (apt-transport-http(1))

Le schéma http spécifie un serveur HTTP pour une archive et est la méthode la plus couramment utilisée. L'URI peut inclure directement des informations de connexion si l'archive l'exige, mais l'utilisation de apt_auth.conf(5) doit être préférée. La méthode prend également en charge les proxys SOCKS5 et HTTP(S) soit configurés via la configuration spécifique à apt, soit spécifiés par la variable d'environnement http_proxy dans le format (en supposant un proxy HTTP nécessitant une authentification) http://user:pass@server:port/. Les détails d'authentification pour les proxys peuvent également être fournis via apt_auth.conf(5)<
/a>.

Notez que ces formes d'authentification sont peu sûres car l'ensemble de la communication avec le serveur distant (ou le proxy) n'est pas chiffré, de sorte qu'un attaquant suffisamment capable peut observer et enregistrer la connexion ainsi que toutes les autres interactions. L'attaquant *ne peut pas* modifier la communication car le modèle de sécurité des données d'APT est indépendant de la méthode de transport choisie. Voir apt-secure(8) pour plus de détails.

https (apt-transport-https(1))

Le schéma https spécifie un serveur HTTPS pour une archive et est très similaire en utilisation et en options disponibles au schéma http. La principale différence est que la communication entre apt et le serveur (ou le proxy) est chiffrée. Notez que le chiffrement n'empêche pas un attaquant de savoir avec quel serveur (ou proxy) apt communique et une analyse plus approfondie peut potentiellement révéler quelles données ont été téléchargées. Si cela est une préoccupation, les schémas basés sur Tor mentionnés plus loin pourraient être une alternative appropriée.

mirror, mirror+scheme (apt-transport-mirror(1))

Le schéma mirror spécifie l'emplacement d'une liste de miroirs. Par défaut, le schéma utilisé pour l'emplacement est http, mais tout autre schéma peut être utilisé via mirror+scheme. La liste de miroirs elle-même peut contenir de nombreuses URI différentes pour des miroirs entre lesquels le client APT peut choisir, sélectionner et se rabattre de manière transparente, afin d'aider à répartir la charge sur les miroirs disponibles et à garantir que les clients peuvent acquérir des données même si certains miroirs configurés ne sont pas disponibles.

file

Le schéma file permet de considérer n'importe quel répertoire du système de fichiers comme une archive. Ceci est utile pour les montages NFS et les miroirs ou archives locaux.

cdrom

Le schéma cdrom permet à APT d'utiliser un lecteur CD-ROM, DVD ou USB local avec échange de médias. Utilisez le programme apt-cdrom(8) pour créer des entrées cdrom dans la liste des sources.

copy

Le schéma copy est identique au schéma file, sauf que les paquets sont copiés dans le répertoire cache au lieu d'être utilisés directement à leur emplacement. Ceci est utile pour les personnes utilisant des supports amovibles pour copier des fichiers avec APT.

ajout de types d'URI plus reconnaissables

APT peut être étendu avec d'autres méthodes livrées dans des paquets optionnels, qui devraient suivre le schéma de nommage apt-transport-method. Par exemple, l'équipe APT maintient également le paquet apt-transport-tor, qui fournit des méthodes d'accès pour les URI HTTP et HTTPS acheminées via le réseau Tor.

EXEMPLES

Utilise l'archive stockée localement (ou montée NFS) à /home/apt/debian pour stable/main, stable/contrib, stable/non-free et stable/non-free-firmware.

deb file:/home/apt/debian stable main contrib non-free non-free-firmware
Types: deb
URIs: file:/home/apt/debian
Suites: stable
Components: main contrib non-free non-free-firmware

Comme ci-dessus, sauf que cela utilise la distribution instable (de développement).

deb file:/home/apt/debian unstable main contrib non-free non-free-firmware
Types: deb
URIs: file:/home/apt/debian
Suites: unstable
Components: main contrib non-free non-free-firmware

Spécification des sources pour ce qui précède.

deb-src file:/home/apt/debian unstable main contrib non-free non-free-firmware
Types: deb-src
URIs: file:/home/apt/debian
Suites: unstable
Components: main contrib non-free non-free-firmware

La première ligne récupère les informations de paquets pour les architectures dans APT::Architectures tandis que la seconde récupère toujours amd64 et armel.

deb http://deb.debian.org/debian trixie main
deb [ arch=amd64,armel ] http://deb.debian.org/debian trixie main
Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie
Components: main
Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie
Components: main
Architectures: amd64 armel

Utilise HTTP pour accéder à l'archive à archive.debian.org, et utilise uniquement la zone hamm/main.

deb http://archive.debian.org/debian-archive hamm main
Types: deb
URIs: http://archive.debian.org/debian-archive
Suites: hamm
Components: main

Utilise HTTPS pour accéder à l'archive à deb.debian.org, sous le répertoire debian, et utilise uniquement la zone trixie/contrib.

deb https://deb.debian.org/debian trixie contrib
Types: deb
URIs: https://deb.debian.org/debian
Suites: trixie
Components: contrib

Utilise HTTPS pour accéder à l'archive à deb.debian.org, sous le répertoire debian, et utilise uniquement la zone unstable/contrib. Si cette ligne apparaît ainsi que celle de l'exemple précédent dans sources.list, une seule session HTTPS sera utilisée pour les deux lignes de ressources.

deb https://deb.debian.org/debian unstable contrib
Types: deb
URIs: https://deb.debian.org/debian
Suites: unstable
Components: contrib

Utilise HTTP pour accéder à l'archive à ftp.tlh.debian.org, sous le répertoire universe, et utilise uniquement les fichiers trouvés sous unstable/binary-i386 sur les machines i386, unstable/binary-amd64 sur amd64, et ainsi de suite pour les autres architectures prises en charge. [Notez que cet exemple illustre seulement comment utiliser la variable de substitution ; les archives Debian officielles ne sont pas structurées ainsi]

deb http://ftp.tlh.debian.org/universe unstable/binary-$(ARCH)/
Types: deb
URIs: http://ftp.tlh.debian.org/universe
Suites: unstable/binary-$(ARCH)/

deb http://deb.debian.org/debian stable main contrib
deb-src http://deb.debian.org/debian stable main contrib
deb http://deb.debian.org/debian testing main contrib
deb-src http://deb.debian.org/debian testing main contrib
deb http://deb.debian.org/debian unstable main contrib
deb-src http://deb.debian.org/debian unstable main contrib
Types: deb deb-src
URIs: http://deb.debian.org/debian
Suites: stable testing unstable
Components: main contrib
