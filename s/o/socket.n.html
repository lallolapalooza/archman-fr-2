socket(n)

Paquet: tcl

Licences: TCL

socket(n) Commandes intégrées Tcl socket(n)

NOM

socket - Ouvre une connexion réseau TCP

SYNTAXE

socket ?options? hôte port

socket -serveur commande ?options? port

DESCRIPTION

Cette commande ouvre une socket réseau et retourne un identifiant de canal qui pourra être utilisé dans des invocations futures de commandes telles que read, puts et flush. À l'heure actuelle, seul le protocole réseau TCP est supporté sur IPv4 et IPv6 ; des versions futures pourront inclure le support de protocoles supplémentaires. La commande socket peut être utilisée pour ouvrir soit le côté client, soit le côté serveur d'une connexion, selon que l'option -serveur est spécifiée ou non.

Notez que le codage par défaut pour toutes les sockets est le codage système, tel que retourné par encoding system. La plupart du temps, vous devrez utiliser chan configure pour changer cela vers autre chose, comme utf-8 (idéal pour communiquer avec d'autres processus Tcl) ou iso8859-1 (utile pour de nombreux protocoles réseau, en particulier les plus anciens).

SOCKETS CLIENT

Si l'option -serveur n'est pas spécifiée, alors le côté client d'une connexion est ouvert et la commande retourne un identifiant de canal qui peut être utilisé pour la lecture et l'écriture. Port et hôte spécifient un port auquel se connecter ; il doit y avoir un serveur acceptant des connexions sur ce port. Port est un numéro de port entier (ou un nom de service, là où c'est supporté et compris par le système d'exploitation hôte) et hôte est soit un nom de style domaine comme www.tcl.tk, soit une adresse numérique IPv4 ou IPv6 comme 127.0.0.1 ou 2001:DB8::1. Utilisez localhost pour faire référence à l'hôte sur lequel la commande est invoquée.

Les options suivantes peuvent également être présentes avant hôte pour spécifier des informations supplémentaires sur la connexion :

-myaddr addr
Addr donne le nom de style domaine ou l'adresse IP numérique de l'interface réseau côté client à utiliser pour la connexion. Cette option peut être utile si la machine cliente a plusieurs interfaces réseau. Si l'option est omise, l'interface côté client sera choisie par le logiciel système.
-myport port
Port spécifie un numéro de port entier (ou un nom de service, là où c'est supporté et compris par le système d'exploitation hôte) à utiliser pour le côté client de la connexion. Si cette option est omise, le numéro de port du client sera choisi aléatoirement par le logiciel système.
-async
Cette option entraînera la connexion de la socket client de manière asynchrone. Cela signifie que la socket sera créée immédiatement mais qu'elle pourra ne pas être encore connectée au serveur lorsque l'appel à socket retournera.

Lorsqu'un gets ou un flush est effectué sur la socket avant que la tentative de connexion ne réussisse ou n'échoue, si la socket est en mode bloquant, l'opération attendra que la connexion soit terminée ou échoue. Si la socket est en mode non bloquant et qu'un gets ou un flush est effectué sur la socket avant que la tentative de connexion ne réussisse ou n'échoue, l'opération retourne immédiatement et fblocked sur la socket retourne 1. Les sockets clients synchrones peuvent être basculées (après qu'elles se soient connectées) en mode asynchrone en utilisant :

chan configure chan -blocking 0

Voir la commande chan configure pour plus de détails.

La boucle d'événements Tcl doit être en cours d'exécution pendant qu'une connexion asynchrone est en cours, car elle pourrait avoir à effectuer plusieurs tentatives de connexion en arrière-plan. L'exécution de la boucle d'événements vous permet également de configurer un événement de canal écrivable sur la socket pour être notifié lorsque la connexion asynchrone a réussi ou échoué. Voir la commande vwait et la commande chan pour plus de détails sur la boucle d'événements et les événements de canal.

L'option -connecting de chan configure peut être utilisée pour vérifier si la connexion est toujours en cours. Pour vérifier une connexion réussie, l'option -error peut être vérifiée lorsque -connecting a retourné 0.

Le fonctionnement sans la file d'événements nécessite pour le moment des appels à chan configure pour faire avancer la machine à états interne.

SOCKETS SERVEUR

Si l'option -serveur est spécifiée, alors la nouvelle socket sera un serveur qui écoute sur le port donné (soit un entier, soit un nom de service, là où c'est supporté et compris par le système d'exploitation hôte ; si port est zéro, le système d'exploitation attribuera un port libre à la socket serveur qui pourra être découvert en utilisant chan configure pour lire l'option -sockname). Si l'hôte supporte à la fois IPv4 et IPv6, la socket écoutera sur les deux familles d'adresses. Tcl acceptera automatiquement les connexions sur le port donné. Pour chaque connexion, Tcl créera un nouveau canal qui pourra être utilisé pour communiquer avec le client. Tcl invoquera ensuite commande (en fait un préfixe de commande, voir les EXEMPLES ci-dessous) avec trois arguments supplémentaires : le nom du nouveau canal, l'adresse, en notation d'adresse réseau, de l'hôte client, et le numéro de port client.

L'option supplémentaire suivante peut également être spécifiée avant port :

-myaddr addr
Addr donne le nom de style domaine ou l'adresse IP numérique de l'interface réseau côté serveur à utiliser pour la connexion. Cette option peut être utile si la machine serveur a plusieurs interfaces réseau. Si l'option est omise, la socket serveur est liée à l'adresse wildcard de manière à pouvoir accepter des connexions depuis n'importe quelle interface. Si addr est un nom de domaine qui se résout en plusieurs adresses IP disponibles sur la machine locale, la socket écoutera sur toutes.

Les canaux serveurs ne peuvent pas être utilisés pour l'entrée ou la sortie ; leur seul usage est d'accepter de nouvelles connexions clients. Les canaux créés pour chaque connexion client entrante sont ouverts pour l'entrée et la sortie. Fermer le canal serveur arrête le serveur de manière à ce qu'aucune nouvelle connexion ne soit acceptée ; cependant, les connexions existantes ne seront pas affectées.

Les sockets serveurs dépendent du mécanisme d'événements Tcl pour savoir quand de nouvelles connexions sont ouvertes. Si l'application n'entre pas dans la boucle d'événements, par exemple en invoquant la commande vwait ou en appelant la procédure C Tcl_DoOneEvent, aucune connexion ne sera acceptée.

Si port est spécifié comme zéro, le système d'exploitation attribuera un port inutilisé à utiliser comme socket serveur. Le numéro de port réellement attribué peut être récupéré de la socket serveur en utilisant la commande chan configure pour récupérer l'option -sockname comme décrit ci-dessous.

OPTIONS CONFIGURATION

La commande chan configure peut être utilisée pour interroger plusieurs options de configuration en lecture seule pour les canaux socket :

-error
Cette option récupère l'état d'erreur actuel de la socket donnée. C'est utile lorsque vous avez besoin de déterminer si une opération de connexion asynchrone a réussi. S'il y a eu une erreur, le message d'erreur est retourné. S'il n'y a pas eu d'erreur, une chaîne vide est retournée.

Notez que l'état d'erreur est réinitialisé par l'opération de lecture ; cela imite l'appel sous-jacent getsockopt(SO_ERROR).

-sockname
Pour les sockets clients (y compris les canaux qui sont créés lorsqu'un client se connecte à une socket serveur), cette option retourne une liste de trois éléments : l'adresse, le nom d'hôte et le numéro de port pour la socket. Si le nom d'hôte ne peut pas être calculé, le deuxième élément est identique à l'adresse, le premier élément de la liste.

Pour les sockets serveurs, cette option retourne une liste d'éléments multiples de trois, dont chaque groupe a la même signification que décrite ci-dessus. La liste contient plus d'un groupe lorsque la socket serveur a été créée sans -myaddr ou avec l'argument de -myaddr étant un nom de domaine qui se résout en plusieurs adresses IP locales à l'hôte appelant.

-peername
Cette option n'est pas prise en charge par les sockets serveur. Pour les sockets clients et acceptés, cette option renvoie une liste de trois éléments ; ce sont l'adresse, le nom d'hôte et le port auxquels le socket distant est connecté ou lié. Si le nom d'hôte ne peut pas être calculé, le deuxième élément de la liste est identique à l'adresse, son premier élément.
-connecting
Cette option n'est pas prise en charge par les sockets serveur. Pour les sockets clients, cette option renvoie 1 si une connexion asynchrone est toujours en cours, 0 sinon.

EXEMPLES

Voici un serveur de temps très simple :

proc Server {startTime channel clientaddr clientport} {
    puts "Connexion de $clientaddr enregistrée"
    set now [clock seconds]
    puts $channel [clock format $now]
    puts $channel "[expr {$now - $startTime}] depuis le démarrage"
    close $channel
}
socket -server [list Server [clock seconds]] 9900
vwait forever

Et voici le client correspondant pour parler au serveur et extraire des informations :

set server localhost
set sockChan [socket $server 9900]
gets $sockChan line1
gets $sockChan line2
close $sockChan
puts "L'heure sur $server est $line1"
puts "Cela fait [lindex $line2 0]s depuis le démarrage du serveur"
