STRFMON(3P) Manuel du programmeur POSIX STRFMON(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

strfmon, strfmon_l — convertir une valeur monétaire en chaîne de caractères

SYNOPSIS

#include <monetary.h>
ssize_t strfmon(char *restrict s, size_t maxsize,
    const char *restrict format, ...);
ssize_t strfmon_l(char *restrict s, size_t maxsize,
    locale_t locale, const char *restrict format, ...);

DESCRIPTION

La fonction strfmon() place des caractères dans le tableau pointé par s selon le contrôle de la chaîne pointée par format. Pas plus de maxsize octets sont placés dans le tableau.

Le format est une chaîne de caractères, commençant et se terminant dans son état initial, le cas échéant, qui contient deux types d'objets : des caractères simples, qui sont simplement copiés dans le flux de sortie, et des spécifications de conversion, chacune entraînant la récupération de zéro ou plusieurs arguments qui sont convertis et formatés. Les résultats sont indéfinis s'il n'y a pas suffisamment d'arguments pour le format. Si le format est épuisé alors que des arguments restent, les arguments excédentaires sont simplement ignorés.

L'application doit s'assurer qu'une spécification de conversion consiste en la séquence suivante :

*
Un caractère '%'
*
Des indicateurs optionnels
*
Une largeur de champ optionnelle
*
Une précision gauche optionnelle
*
Une précision droite optionnelle
*
Un caractère spécificateur de conversion requis qui détermine la conversion à effectuer

La fonction strfmon_l() est équivalente à la fonction strfmon(), sauf que les données de locale utilisées proviennent de la locale représentée par locale.

Indicateurs

Un ou plusieurs des indicateurs optionnels suivants peuvent être spécifiés pour contrôler la conversion :

=f
Un '=' suivi d'un seul caractère f qui est utilisé comme caractère de remplissage numérique. Pour fonctionner avec des nombres de précision ou de largeur, le caractère de remplissage doit être un caractère d'un seul octet ; sinon, le comportement est indéfini. Le caractère de remplissage numérique par défaut est l'espace <space>. Cet indicateur n'affecte pas le remplissage de la largeur du champ qui utilise toujours l'espace <space>. Cet indicateur est ignoré sauf si une précision gauche (voir ci-dessous) est spécifiée.
^
Ne pas formater le montant de la devise avec des séparateurs de groupement. Le défaut est d'insérer les séparateurs de groupement s'ils sont définis pour la locale actuelle.
+ ou (
Spécifier le style de représentation des montants monétaires positifs et négatifs. Un seul des indicateurs '+' ou '(' peut être spécifié. Si '+' est spécifié, les équivalents de la locale de '+' et '-' sont utilisés (par exemple, dans de nombreuses locales, la chaîne vide si positif et '-' si négatif). Si '(' est spécifié, les montants négatifs sont entourés de parenthèses. Si aucun indicateur n'est spécifié, le style '+' est utilisé.
!
Supprimer le symbole de la devise de la conversion de sortie.
-
Spécifier l'alignement. Si cet indicateur est présent, le résultat de la conversion est justifié à gauche (rembourré à droite) plutôt qu'à droite. Cet indicateur sera ignoré sauf si une largeur de champ (voir ci-dessous) est spécifiée.

Largeur du Champ

w
Une chaîne de chiffres décimaux w spécifiant une largeur de champ minimale en octets dans laquelle le résultat de la conversion est justifié à droite (ou à gauche si l'indicateur '-' est spécifié). La valeur par défaut est 0.

Précision Gauche

#n
Un '#' suivi d'une chaîne de chiffres décimaux n spécifiant un nombre maximum de chiffres attendus à formater à gauche du caractère de radix. Cette option peut être utilisée pour que la sortie formatée de plusieurs appels à la fonction strfmon() soit alignée dans les mêmes colonnes. Elle peut également être utilisée pour remplir les positions inutilisées avec un caractère spécial comme dans "$***123.45". Cette option entraîne le formatage d'un montant comme s'il avait le nombre de chiffres spécifié par n. Si plus de n positions de chiffres sont nécessaires, cette spécification de conversion est ignorée. Les positions de chiffres en excès par rapport à celles réellement nécessaires sont remplies avec le caractère de remplissage numérique (voir l'indicateur =f ci-dessus).

Si le groupement n'a pas été supprimé avec l'indicateur '^', et qu'il est défini pour la locale actuelle, des séparateurs de groupement sont insérés avant que les caractères de remplissage (le cas échéant) ne soient ajoutés. Les séparateurs de groupement ne sont pas appliqués aux caractères de remplissage, même si le caractère de remplissage est un chiffre.

Pour assurer l'alignement, tous les caractères apparaissant avant ou après le nombre dans la sortie formatée, tels que les symboles de devise ou de signe, sont rembourrés si nécessaire avec des caractères d'espacement <space> pour que leurs formats positifs et négatifs aient une longueur égale.

Précision Droite

.p
Un point <period> suivi d'une chaîne de chiffres décimaux p spécifiant le nombre de chiffres après le caractère de radix. Si la valeur de la précision droite p est 0, aucun caractère de radix n'apparaît. Si une précision droite n'est pas incluse, une valeur par défaut spécifiée par la locale actuelle est utilisée. Le montant formaté est arrondi au nombre de chiffres spécifié avant le formatage.

Caractères Spécificateurs de Conversion

Les caractères spécificateurs de conversion et leurs significations sont :

i
L'argument double est formaté selon le format monétaire international de la locale (par exemple, aux États-Unis : USD 1 234,56). Si l'argument est ±Inf ou NaN, le résultat de la conversion est indéfini.
n
L'argument double est formaté selon le format monétaire national de la locale (par exemple, aux États-Unis : $1 234,56). Si l'argument est ±Inf ou NaN, le résultat de la conversion est indéfini.
%
Convertir en un '%' ; aucun argument n'est converti. La spécification de conversion entière doit être %%.

Informations sur la Locale

La catégorie LC_MONETARY de la locale actuelle affecte le comportement de cette fonction, y compris le caractère de radix monétaire (qui peut être différent du caractère de radix numérique affecté par la catégorie LC_NUMERIC), le séparateur de groupement, les symboles de devise et les formats. Le symbole monétaire international doit être conforme à la norme ISO 4217:2001.

Si la valeur de maxsize est supérieure à {SSIZE_MAX}, le résultat est défini par l'implémentation.

Le comportement est indéfini si l'argument locale de strfmon_l() est l'objet de locale spécial LC_GLOBAL_LOCALE ou n'est pas un descripteur d'objet de locale valide.

VALEUR DE RETOUR

Si le nombre total d'octets résultants, y compris le caractère nul de terminaison, n'est pas supérieur à maxsize, ces fonctions retournent le nombre d'octets placés dans le tableau pointé par s, sans inclure le caractère NUL de terminaison. Sinon, -1 est retourné, le contenu du tableau est indéfini et errno est défini pour indiquer l'erreur.

ERREURS

Ces fonctions échoueront si :

E2BIG
La conversion s'est arrêtée en raison d'un manque d'espace dans le tampon.

PROLOG

This page is part of the Linux man-pages project. It describes a Linux specific or POSIX specific, or general UNIX function. In the case of a POSIX function, many man pages specify behaviour that is mandated by the POSIX standard. In the case of a Linux specific function, the man page describes the Linux behaviour.

NAME

strfmon - format monetary values

SYNOPSIS

    #include <monetary.h>
    size_t strfmon(char *restrict s, size_t maxlen,
        const char *restrict format, ...);

DESCRIPTION

The strfmon() function formats a monetary value according to the current locale settings and the format string. The function behaves like sprintf() but with additional format specifiers for monetary values.

The format string contains ordinary characters, which are copied to the output buffer, and conversion specifications, which define how to format the arguments. A conversion specification starts with a '%' character, followed by flags, width, precision, and a conversion character.

The following flags are supported:

'='
Do not output a currency symbol. This is useful when printing a list of monetary values in aligned columns.
'^'
Disable the thousands separator. The thousands separator is defined by the localeconv() function.
'('
Use an alternative representation for negative values, typically enclosing the number in parentheses.

The width specifies the minimum field width. The output is padded with spaces (or the fill character specified by the fill character flag) to meet this width. If the width is preceded by a '0', leading zeros are used for padding instead of spaces. If the width is preceded by a character other than '0', that character is used for padding (e.g., %=*...).

The precision specifies the number of digits after the decimal point. If the precision is omitted, the value is formatted according to the locale's default number of fractional digits for the currency.

The conversion characters are:

'd'
The argument is interpreted as an integer. It is formatted according to the locale's conventions for representing monetary values.
'i'
The argument is interpreted as an integer. It is formatted according to the locale's conventions for representing monetary values, including the international currency symbol.

RETURN VALUE

Upon successful completion, strfmon() returns the number of characters written to the buffer s, not including the terminating null byte. If an error occurs, it returns (size_t) -1, sets errno to indicate the error, and the contents of s are indeterminate.

If the buffer s is not large enough to hold the result, including the terminating null byte, the return value is undefined.

ERRORS

The strfmon() function may fail if:

EINVAL
The format string contains an invalid conversion specification.
ENOSPC
The buffer s is not large enough to hold the result.

EXAMPLES

Given a locale for the US and the values 123.45, -123.45, and 3456.781, the following output might be produced. Square brackets ("[]") are used in this example to delimit the output.

%n         [$123.45]         Default formatting
           [-$123.45]
           [$3,456.78]
%11n       [    $123.45]     Right align within an 11-character field
           [   -$123.45]
           [  $3,456.78]
%#5n       [ $   123.45]     Aligned columns for values up to 99999
           [-$   123.45]
           [ $ 3,456.78]
%=*#5n     [ $***123.45]     Specify a fill character
           [-$***123.45]
           [ $*3,456.78]
%=0#5n     [ $000123.45]     Fill characters do not use grouping
           [-$000123.45]     even if the fill character is a digit
           [ $03,456.78]
%^#5n      [ $  123.45]      Disable the grouping separator
           [-$  123.45]
           [ $ 3456.78]
%^#5.0n    [ $  123]         Round off to whole units
           [-$  123]
           [ $ 3457]
%^#5.4n    [ $  123.4500]    Increase the precision
           [-$  123.4500]
           [ $ 3456.7810]
%(#5n      [ $   123.45 ]    Use an alternative pos/neg style
           [($   123.45)]
           [ $ 3,456.78 ]
%!(#5n     [    123.45 ]     Disable the currency symbol
           [(   123.45)]
           [  3,456.78 ]
%-14#5.4n  [ $   123.4500 ]  Left-justify the output
           [-$   123.4500 ]
           [ $ 3,456.7810 ]
%14#5.4n   [  $   123.4500]  Corresponding right-justified output
           [ -$   123.4500]
           [  $ 3,456.7810]

See also the EXAMPLES section in fprintf().
