NOM

states - outil de traitement de texte similaire à awk

SYNOPSIS

states [-hvV] [-D var=val] [-f fichier] [-o fichier_sortie] [-p chemin] [-s etat_initial] [-W niveau] [fichier ...]

DESCRIPTION

States est un outil de traitement de texte similaire à awk, avec quelques extensions de machine à états. Il est conçu pour la coloration syntaxique de code source de programmes et pour des tâches similaires où des informations d'état facilitent le traitement des entrées.

À un instant donné, States se trouve dans un seul état. Chaque état est très similaire à l'environnement de travail d'awk : ils ont des expressions régulières qui sont mises en correspondance avec l'entrée et des actions qui sont exécutées lorsqu'une correspondance est trouvée. Depuis les blocs d'actions, states peut effectuer des transitions d'état ; il peut passer à un autre état à partir duquel le traitement est poursuivi. Les transitions d'état sont enregistrées de sorte que states puisse revenir à l'état appelant une fois que l'état actuel est terminé.

La plus grande différence entre states et awk, outre les extensions de machine à états, est que states n'est pas orienté ligne. Il met en correspondance des jetons d'expressions régulières à partir de l'entrée et une fois qu'une correspondance est traitée, il continue le traitement à partir de la position actuelle, pas depuis le début de la ligne d'entrée suivante.

OPTIONS

-D var=val, --define=var=val
Définit la variable var à la valeur de chaîne val. Les définitions en ligne de commande remplacent les définitions de variables trouvées dans le fichier de configuration.
-f fichier, --file=fichier
Lit les définitions d'état depuis le fichier fichier. Par défaut, states essaie de lire les définitions d'état depuis le fichier states.st dans le répertoire de travail courant.
-h, --help
Affiche un court message d'aide et quitte.
-o fichier, --output=fichier
Sauvegarde la sortie dans le fichier fichier au lieu de l'imprimer sur stdout.
-p chemin, --path=chemin
Définit le chemin de chargement à chemin. Le chemin de chargement par défaut est le répertoire à partir duquel le fichier de définitions d'état est chargé.
-s etat, --state=etat
Commence l'exécution à partir de l'état etat. Cette définition remplace l'état de départ résolu à partir du bloc start.
-v, --verbose
Augmente la verbosité du programme.
-V, --version
Affiche la version de states et quitte.
-W niveau, --warning=niveau
Définit le niveau d'avertissement à niveau. Les valeurs possibles pour niveau sont :
leger
avertissements légers (par défaut)
tous
tous les avertissements

FICHIERS PROGRAMMES STATES

Les fichiers de programmes States peuvent contenir un bloc start, des blocs startrules et namerules pour spécifier l'état initial, des définitions d'état et des expressions.

Le bloc start est le main() du programme states ; il est exécuté au démarrage du script pour chaque fichier d'entrée et peut effectuer toute initialisation dont le script a besoin. Il appelle normalement également les primitives check_startrules() et check_namerules() qui résolvent l'état initial à partir du nom du fichier d'entrée ou des données trouvées au début du fichier d'entrée. Voici un exemple de bloc start qui initialise deux variables et effectue la résolution standard de l'état de départ :

start
{
  a = 1;
  msg = "Bonjour, monde !";
  check_startrules ();
  check_namerules ();
}

Une fois le bloc start traité, le traitement de l'entrée est poursuivi à partir de l'état initial.

L'état initial est résolu par les informations trouvées dans les blocs startrules et namerules. Ces deux blocs contiennent des paires expression régulière - symbole. Lorsque l'expression régulière est mise en correspondance avec le nom ou le début du fichier d'entrée, l'état initial est nommé par le symbole correspondant. Par exemple, les règles de départ et de nom suivantes peuvent distinguer les fichiers C et Fortran :

namerules
{
  /\.(c|h)$/    c;
  /\.[fF]$/     fortran;
}
startrules
{
  /-\*- [cC] -\*-/      c;
  /-\*- fortran -\*-/   fortran;
}

Si ces règles sont utilisées avec le bloc start montré précédemment, states examine d'abord le début du fichier d'entrée. S'il contient la chaîne -*- c -*-, le fichier est supposé contenir du code C et le traitement commence dans l'état appelé c. Si le début du fichier d'entrée contient la chaîne -*- fortran -*-, l'état initial est fortran. Si aucune des règles de départ ne correspond, le nom du fichier d'entrée est mis en correspondance avec les namerules. Si le nom se termine par le suffixe c ou C, on passe à l'état c. Si le suffixe est f ou F, l'état initial est fortran.

Si les règles de départ et de nom échouent à résoudre l'état de départ, states copie simplement son entrée en sortie sans modification.

L'état de départ peut également être spécifié depuis la ligne de commande avec l'option -s, --state.

Les définitions d'état ont la syntaxe suivante :

state { expr {instructions} ... }

où expr est : une expression régulière, une expression spéciale ou un symbole et instructions est une liste d'instructions. Lorsque l'expression expr est mise en correspondance avec l'entrée, le bloc d'instructions est exécuté. Le bloc d'instructions peut appeler les primitives de states, des sous-routines définies par l'utilisateur, appeler d'autres états, etc. Une fois le bloc exécuté, le traitement de l'entrée est poursuivi à partir de la position actuelle dans l'entrée (qui aura pu être modifiée si le bloc d'instructions a appelé d'autres états).

Les expressions spéciales BEGIN et END peuvent être utilisées à la place de expr. L'expression BEGIN correspond au début de l'état ; son bloc est appelé lorsque l'état est entré. L'expression END correspond à la fin de l'état ; son bloc est exécuté lorsque states quitte l'état.

Si expr est un symbole, sa valeur est recherchée dans l'environnement global et s'il s'agit d'une expression régulière, elle est mise en correspondance avec l'entrée, sinon cette règle est ignorée.

Le fichier de programme states peut également contenir des expressions de niveau supérieur ; elles sont évaluées après l'analyse du fichier de programme, mais avant que tout fichier d'entrée ne soit traité ou que le bloc start ne soit évalué.

FONCTIONS PRIMITIVES

appel (symbole)
Passe à l'état symbole et continue le traitement du fichier d'entrée à partir de cet état. La fonction retourne ce que la déclaration return de l'état symbole a retourné.
appeln (nom)
Comme appel, mais l'argument nom est évalué et sa valeur doit être une chaîne. Par exemple, cette fonction peut être utilisée pour appeler un état dont le nom est stocké dans une variable.
verifier_regles_nom ()
Tente de résoudre l'état de départ à partir des règles namerules. La fonction retourne 1 si l'état de départ a été résolu, sinon 0.
verifier_regles_depart ()
Tente de résoudre l'état de départ à partir des règles startrules. La fonction retourne 1 si l'état de départ a été résolu, sinon 0.
concatener (chaine, ...)
Concatène les chaînes d'arguments et retourne le résultat sous forme de nouvelle chaîne.
flottant (quelconque)
Convertit l'argument en un nombre à virgule flottante.
lire_env (chaine)
Lit la valeur

NAME

states - POSIX-style state machine

SYNOPSIS

states [-c] [-f file] [-I dir] [-s state] [-v] [file ...]

DESCRIPTION

The states program is a simple POSIX-style state machine interpreter. It reads the state machine definition from the specified file or from the standard input if no file is given. Then, it processes the input files specified on the command line using the state machine definition.

The state machine is defined by a set of states and transitions. Each state can have an associated action, and transitions are triggered by regular expressions matching the input.

OPTIONS

-c
When executing actions, only one action is executed per input line. This option is ignored if the -f option is used.
-f file
Use file as the state machine definition. This file must contain one or more state definitions. If this option is not specified, the state machine definition is read from the standard input.
-I dir
Add dir to the list of directories that are searched for state files. This option may be specified more than once.
-s state
Set the initial state to state. If this option is not specified, the initial state is determined by the state machine definition (usually the first state defined).
-v
Print verbose output, including state transitions and matched regular expressions.

STATES PROGRAM FILES

The state machine definition file describes the states and transitions. It is a text file where each line represents a part of the state machine definition. The file format is as follows:

A state definition starts with a line containing only the state name, followed by a colon. For example:

state_name:

After the state name, lines starting with a regular expression define transitions. The regular expression is followed by the name of the target state and an optional action to be executed when the transition is taken. For example:

/regex/ target_state action

Lines starting with { and ending with } enclose action code. This code is interpreted by the states program.

Comments start with a # character and extend to the end of the line.

Example state definition file:

initial_state:
/start/	state_one	{ print("Entering state one"); }
state_one:
/data/	state_one	{ print("Processing data: ", $0); }
/end/	final_state	{ print("Exiting state one"); }
final_state:
# End of state machine
