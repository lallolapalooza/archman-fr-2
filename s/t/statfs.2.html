statfs(2) Manuel des appels système statfs(2)

NOM

statfs, fstatfs - obtenir les statistiques d'un système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/vfs.h>    /* ou <sys/statfs.h> */
int statfs(const char *path, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

Sauf si vous avez besoin du champ f_type, vous devriez utiliser l'interface standard statvfs(3) à la place.

DESCRIPTION

L'appel système statfs() renvoie des informations sur un système de fichiers monté. path est le chemin d'accès de n'importe quel fichier dans le système de fichiers monté. buf est un pointeur vers une structure statfs définie approximativement comme suit :


struct statfs {
    __fsword_t f_type;    /* Type de système de fichiers (voir ci-dessous) */
    __fsword_t f_bsize;   /* Taille de bloc optimale pour le transfert */
    fsblkcnt_t f_blocks;  /* Blocs de données totaux dans le système de fichiers */
    fsblkcnt_t f_bfree;   /* Blocs libres dans le système de fichiers */
    fsblkcnt_t f_bavail;  /* Blocs libres disponibles pour
                             utilisateur non privilégié */
    fsfilcnt_t f_files;   /* Inodes totaux dans le système de fichiers */
    fsfilcnt_t f_ffree;   /* Inodes libres dans le système de fichiers */
    fsid_t     f_fsid;    /* Identifiant du système de fichiers */
    __fsword_t f_namelen; /* Longueur maximale des noms de fichiers */
    __fsword_t f_frsize;  /* Taille du fragment (depuis Linux 2.6) */
    __fsword_t f_flags;   /* Indicateurs de montage du système de fichiers
                             (depuis Linux 2.6.36) */
    __fsword_t f_spare[xxx];
                    /* Octets de remplissage réservés pour utilisation future */
};

Le champ f_flags est un masque de bits indiquant les options de montage pour le système de fichiers. Il contient zéro ou plus des bits suivants :

ST_MANDLOCK
Le verrouillage mandataire est autorisé sur le système de fichiers (voir fcntl(2)).
ST_NOATIME
Ne pas mettre à jour les temps d'accès ; voir mount(2).
ST_NODEV
Interdire l'accès aux fichiers spéciaux de périphériques sur ce système de fichiers.
ST_NODIRATIME
Ne pas mettre à jour les temps d'accès des répertoires ; voir mount(2).
ST_NOEXEC
L'exécution de programmes est interdite sur ce système de fichiers.
ST_NOSUID
Les bits set-user-ID et set-group-ID sont ignorés par exec(3) pour les fichiers exécutables sur ce système de fichiers.
ST_RDONLY
Ce système de fichiers est monté en lecture seule.
ST_RELATIME
Mettre à jour atime par rapport à mtime/ctime ; voir mount(2).
ST_SYNCHRONOUS
Les écritures sont synchronisées immédiatement sur le système de fichiers (voir la description de O_SYNC dans open(2)).
ST_NOSYMFOLLOW (depuis Linux 5.10)
Les liens symboliques ne sont pas suivis lors de la résolution des chemins ; voir mount(2).

Personne ne sait à quoi f_fsid est censé correspondre (mais voir ci-dessous).

Les champs qui ne sont pas définis pour un système de fichiers particulier sont mis à 0.

fstatfs() renvoie les mêmes informations sur un fichier ouvert référencé par le descripteur fd.

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
(statfs()) La permission de recherche est refusée pour un composant du préfixe du chemin de path. (Voir aussi path_resolution(7).)
EBADF
(fstatfs()) fd n'est pas un descripteur de fichier valide et ouvert.
EFAULT
buf ou path pointe vers une adresse invalide.
EINTR
L'appel a été interrompu par un signal ; voir signal(7).
EIO
Une erreur d'E/S s'est produite lors de la lecture depuis le système de fichiers.
ELOOP
(statfs()) Trop de liens symboliques ont été rencontrés lors de la traduction de path.
ENAMETOOLONG

NAME

statfs, fstatfs — get file system statistics

LIBRARY

Standard C library (libc, generally, although this is a system call)

SYNOPSIS

#include <sys/statfs.h>

int statfs(const char *pathname, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

DESCRIPTION

The statfs() system call is similar to stat(2) but operates on a file system. It returns information about the file system on which the file specified by the pathname pathname resides.

The fstatfs() system call is similar to statfs() but operates on an open file described by the file descriptor fd.

The information is returned in the structure whose address is given by buf. This structure has at least the following members:

struct statfs {
    __fsid_t    f_fsid;       /* Filesystem ID */
    __loff_t    f_type;       /* Type of filesystem (see below) */
    __loff_t    f_flags;      /* Mount flags (see below) */
    long        f_bsize;      /* Optimal transfer block size */
    long        f_blocks;     /* Total data blocks in filesystem */
    long        f_bfree;      /* Free blocks in filesystem */
    long        f_bavail;     /* Free blocks available to non-superuser */
    long        f_files;      /* Total file nodes in filesystem */
    long        f_ffree;      /* Free file nodes in filesystem */
    long        f_favail;     /* Free file nodes available to non-superuser */
    long        f_fsid;       /* File system ID (deprecated, use f_fsid) */
    long        f_namelen;    /* Maximum filename length */
    long        f_frsize;     /* Fragment size (if supported) */
    /* Other fields may be present depending on the filesystem */
};

The members f_type, f_flags, f_bsize, f_blocks, f_bfree, f_bavail, f_files, f_ffree, and f_favail are common across many systems. The f_fsid member is a copy of the old f_fsid member, which is deprecated.

The f_type field contains a magic number identifying the type of filesystem. Common values include:

0x69667372
The filesystem type string "nfsr" (not used).
0x73667372
The filesystem type string "sfsr" (not used).
0x53465342
The filesystem type string "SFSB" (not used).
0xEF53
EXT2 filesystem.
0xEF51
EXT3 filesystem.
0xEF53
EXT4 filesystem.

The f_flags field contains bit flags describing the filesystem. The following flags are defined:

MS_RDONLY
Filesystem read only.
MS_NOSUID
Do not honor set-user-ID and set-group-ID bits.
MS_NODEV
Do not allow device special files.
MS_NOEXEC
Do not allow program execution.
MS_SYNCHRONOUS
Synchronous updates.
MS_MAND
Allow mandatory file locking.
MS_DIRSYNC
Synchronous directory updates.
MS_REMOUNT
Update flags of mounted filesystem.
MS_BIND
Bind mount.
MS_MOVE
Move mount.
MS_REC
Recursive operation.
MS_SILENT
Do not print messages about modifications.
MS_POSIXACL
Use POSIX Access Control Lists.
MS_UNBINDABLE
Make the mount unbindable.
MS_PRIVATE
Mark the mount as private.
MS_SLAVE
Mark the mount as slave.
MS_SHARED
Mark the mount as shared.
MS_RELATIME
Update access times relative to modification times.
MS_STRICTATIME
Update access times strictly.
MS_NODIRATIME
Do not update directory access times.

The f_flags field is the same as the second argument to the mount(2) system call.

The f_namelen field contains the maximum length of a filename for this filesystem. The f_frsize field contains the size of the smallest usable filesystem block (fragment size). If fragments are not supported, it is equal to f_bsize.

The f_fsid field is the file system identifier. The definition of this field varies across different systems. In Linux, it is defined as a structure containing two integers, val[2]. The meaning of these values is filesystem-specific. The f_fsid field is a copy of the old f_fsid field, which is deprecated.

The members f_blocks, f_bfree, f_bavail, f_files, f_ffree, and f_favail are of type long. In older kernels, these were 32-bit values, which could lead to overflow on filesystems with more than 2^32 blocks or files. Since Linux 2.6, these fields are 64-bit values. The glibc wrapper functions handle the transition transparently.

RETURN VALUE

On success, zero is returned. On failure, -1 is returned, and errno is set to indicate the error.

ERRORS

EACCES
(statfs()) A loop in the pathname could not be detected.
EBADF
(fstatfs()) fd is not a valid file descriptor.
EFAULT
buf points outside of the accessible address space.
EINTR
A signal was caught during the execution of the system call.
EINVAL
(statfs()) pathname is not a valid identifier.
EIO
An I/O error occurred.
ELOOP
(statfs()) Too many symbolic links were encountered in resolving path.
EMFILE
Too many file descriptors are in use by the process.
ENAMETOOLONG
(statfs()) path is too long.
ENOENT
(statfs()) The file referred to by path does not exist.
ENOMEM
Insufficient kernel memory was available.
ENOSYS
The filesystem does not support this call.
ENOTDIR
(statfs()) A component of the path prefix of path is not a directory.
EOVERFLOW
Some values were too large to be represented in the returned struct.

VERSIONS

The f_fsid field

Solaris, Irix, and POSIX have a system call statvfs(2) that returns a struct statvfs (defined in <sys/statvfs.h>) containing an unsigned long f_fsid. Linux, SunOS, HP-UX, 4.4BSD have a system call statfs() that returns a struct statfs (defined in <sys/vfs.h>) containing a fsid_t f_fsid, where fsid_t is defined as struct { int val[2]; }. The same holds for FreeBSD, except that it uses the include file <sys/mount.h>.

The general idea is that f_fsid contains some random stuff such that the pair (f_fsid,ino) uniquely determines a file. Some operating systems use (a variation on) the device number, or the device number combined with the filesystem type. Several operating systems restrict giving out the f_fsid field to the superuser only (and zero it for unprivileged users), because this field is used in the filehandle of the filesystem when NFS-exported, and giving it out is a security concern.

Under some operating systems, the fsid can be used as the second argument to the sysfs(2) system call.

STANDARDS

Linux.

HISTORY

The Linux statfs() was inspired by the 4.4BSD one (but they do not use the same structure).

The original Linux statfs() and fstatfs() system calls were not designed with extremely large file sizes in mind. Subsequently, Linux 2.6 added new statfs64() and fstatfs64() system calls that employ a new structure, statfs64. The new structure contains the same fields as the original statfs structure, but the sizes of various fields are increased, to accommodate large file sizes. The glibc statfs() and fstatfs() wrapper functions transparently deal with the kernel differences.

LSB has deprecated the library calls statfs() and fstatfs() and tells us to use statvfs(3) and fstatvfs(3) instead.

NOTES

The __fsword_t type used for various fields in the statfs structure definition is a glibc internal type, not intended for public use. This leaves the programmer in a bit of a conundrum when trying to copy or compare these fields to local variables in a program. Using unsigned int for such variables suffices on most systems.

Some systems have only <sys/vfs.h>, other systems also have <sys/statfs.h>, where the former includes the latter. So it seems including the former is the best choice.

BUGS

From Linux 2.6.38 up to and including Linux 3.1, fstatfs() failed with the error ENOSYS for file descriptors created by pipe(2).
