strict(3perl) Guide du programmeur Perl strict(3perl)

NOM

strict — pragma Perl pour restreindre les constructions non sécurisées

SYNTAXE

use strict;
use strict "vars";
use strict "refs";
use strict "subs";
use strict;
no strict "vars";

DESCRIPTION

Le pragma "strict" désactive certaines expressions Perl qui pourraient se comporter de manière inattendue ou être difficiles à déboguer, les transformant en erreurs. L'effet de ce pragma est limité au fichier ou au bloc de portée courant.

Si aucune liste d'importation n'est fournie, toutes les restrictions possibles sont supposées. (C'est le mode le plus sûr, mais il est parfois trop strict pour une programmation occasionnelle.) Actuellement, il y a trois choses possibles sur lesquelles être strict : "subs", "vars", et "refs".

"strict refs"
Ceci génère une erreur d'exécution si vous utilisez des références symboliques (voir perlref). 
use strict 'refs';
$ref = \$foo;
print $$ref;        # ok
$ref = "foo";
print $$ref;        # erreur d'exécution ; normalement ok
$file = "STDOUT";
print $file "Hi!";  # erreur ; note: pas de virgule après $file

Il y a une exception à cette règle :

$bar = \&{'foo'};
&$bar;

est autorisé afin que "goto &$AUTOLOAD" ne casse pas sous la stricte compatibilité.

"strict vars"
Ceci génère une erreur de compilation si vous accédez à une variable qui n'a été ni explicitement déclarée (en utilisant "my", "our", "state", ou "use vars") ni entièrement qualifiée. (Comme ceci est destiné à éviter les problèmes de suicide de variable et les subtilités des portées dynamiques, une variable simplement "local" n'est pas suffisante.) Voir "my" in perlfunc, "our" in perlfunc, "state" in perlfunc, "local" in perlfunc, et vars. 
use strict 'vars';
$X::foo = 1;         # ok, entièrement qualifié
my $foo = 10;        # ok, variable my()
local $baz = 9;      # plante, $baz non déclaré avant
package Cinna;
our $bar;                   # Déclare $bar dans le paquet courant
$bar = 'HgS';               # ok, variable globale déclarée via pragma

Le local() a généré une erreur de compilation car vous avez touché un nom global sans le qualifier entièrement.

En raison de leur utilisation spéciale par sort(), les variables $a et $b sont exemptées de cette vérification.

"strict subs"
Ceci désactive l'optimisation poétique, générant une erreur de compilation si vous essayez d'utiliser un identifiant bareword qui n'est pas une sous-routine, à moins qu'il ne s'agisse d'un identifiant simple (pas de deux-points) et qu'il apparaisse entre accolades, à gauche du symbole "=>", ou qu'il ait l'opérateur unaire moins appliqué. 
use strict 'subs';
$SIG{PIPE} = Plumber;   # plante
$SIG{PIPE} = "Plumber"; # ok: la chaîne entre guillemets est toujours ok
$SIG{PIPE} = \&Plumber; # forme préférée

Voir "Pragmatic Modules" in perlmodlib.

HISTORIQUE

"strict 'subs'", avec Perl 5.6.1, a erronément permis d'utiliser un identifiant composé non quoté (par exemple "Foo::Bar") comme clé de hachage (avant "=>" ou à l'intérieur des accolades), mais sans le forcer toujours à une chaîne littérale.

À partir de Perl 5.8.1, strict est strict dans ses restrictions : si des restrictions inconnues sont utilisées, le pragma strict s'arrêtera avec

Unknown 'strict' tag(s) '...'

Depuis la version 1.04 (Perl 5.10), strict vérifie qu'il est utilisé comme "strict" pour éviter le piège dreaded Strict sur les systèmes de fichiers insensibles à la casse.

À partir de Perl 5.12, l'utilisation de "use VERSION" (où VERSION >= 5.11.0) active désormais lexicalement les strictures comme "use strict" (en plus des effets et fonctionnalités normaux de "use VERSION"). En d'autres termes, "use v5.011" ou supérieur implique désormais automatiquement "use strict", comme indiqué dans "Implicit strictures" in perl5120delta et "use VERSION".
