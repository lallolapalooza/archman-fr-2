st(4) Manuel des pilotes de périphériques st(4)

NOM

st - périphérique de bande SCSI

SYNTAXE

#include <sys/mtio.h>
int ioctl(int fd, int request [, (void *)arg3]);
int ioctl(int fd, MTIOCTOP, (struct mtop *)mt_cmd);
int ioctl(int fd, MTIOCGET, (struct mtget *)mt_status);
int ioctl(int fd, MTIOCPOS, (struct mtpos *)mt_pos);

DESCRIPTION

Le pilote st fournit l'interface à une variété de périphériques de bande SCSI. Actuellement, le pilote prend en charge tous les périphériques détectés de type « sequential-access ». Le pilote st utilise le numéro de périphérique majeur 9.

Chaque périphérique utilise huit numéros de périphérique mineurs. Les cinq bits inférieurs des numéros mineurs sont assignés séquentiellement dans l'ordre de détection. Dans le noyau 2.6, les bits supérieurs aux huit bits inférieurs sont concaténés aux cinq bits inférieurs pour former le numéro de bande. Les numéros mineurs peuvent être groupés en deux ensembles de quatre numéros : les numéros de périphérique mineurs principaux (rembobinage automatique), n, et les numéros de périphérique « sans rembobinage », (n + 128). Les périphériques ouverts en utilisant le numéro de périphérique principal recevront une commande REWIND à la fermeture. Les périphériques ouverts en utilisant le numéro de périphérique « sans rembobinage » ne le feront pas. (Notez que l'utilisation d'un périphérique à rembobinage automatique pour positionner la bande avec, par exemple, mt, ne donne pas le résultat souhaité : la bande est rembobinée après la commande mt et la commande suivante commence depuis le début de la bande).

Au sein de chaque groupe, quatre numéros mineurs sont disponibles pour définir des périphériques avec des caractéristiques différentes (taille de bloc, compression, densité, etc.). Au démarrage du système, seul le premier périphérique est disponible. Les trois autres sont activés lorsque les caractéristiques par défaut sont définies (voir ci-dessous). (En modifiant les constantes de compilation, il est possible de modifier l'équilibre entre le nombre maximum de lecteurs de bande et le nombre de numéros mineurs pour chaque lecteur. L'allocation par défaut permet le contrôle de 32 lecteurs de bande. Par exemple, il est possible de contrôler jusqu'à 64 lecteurs de bande avec deux numéros mineurs pour différentes options.)

Les périphériques sont généralement créés par :


mknod -m 666 /dev/st0 c 9 0
mknod -m 666 /dev/st0l c 9 32
mknod -m 666 /dev/st0m c 9 64
mknod -m 666 /dev/st0a c 9 96
mknod -m 666 /dev/nst0 c 9 128
mknod -m 666 /dev/nst0l c 9 160
mknod -m 666 /dev/nst0m c 9 192
mknod -m 666 /dev/nst0a c 9 224

Il n'y a pas de périphérique bloc correspondant.

Le pilote utilise un tampon interne qui doit être suffisamment grand pour contenir au moins un bloc de bande. Avant Linux 2.1.121, le tampon est alloué comme un bloc contigu. Cela limite la taille du bloc au bloc contigu de mémoire le plus grand que l'allocateur du noyau peut fournir. La limite est actuellement de 128 Ko pour les architectures 32 bits et de 256 Ko pour les architectures 64 bits. Dans les noyaux plus récents, le pilote alloue le tampon en plusieurs parties si nécessaire. Par défaut, le nombre maximum de parties est 16. Cela signifie que la taille maximale du bloc est très grande (2 Mo si l'allocation de 16 blocs de 128 Ko réussit).

La taille du tampon interne du pilote est déterminée par une constante de compilation qui peut être outrepassée avec une option de démarrage du noyau. En plus de cela, le pilote tente d'allouer un tampon temporaire plus grand à l'exécution si nécessaire. Cependant, l'allocation à l'exécution de grands blocs contigus de mémoire peut échouer et il est conseillé de ne pas trop compter sur l'allocation dynamique de tampons avant Linux 2.1.121 (cela s'applique également au chargement à la demande du pilote avec kerneld ou kmod).

Le pilote ne prend pas spécifiquement en charge de marque ou de modèle de lecteur de bande. Après le démarrage du système, les options du périphérique de bande sont définies par le firmware du lecteur. Par exemple, si le firmware du lecteur sélectionne le mode bloc fixe, le périphérique de bande utilise le mode bloc fixe. Les options peuvent être modifiées avec des appels ioctl(2) explicites et restent en vigueur lorsque le périphérique est fermé et rouvert. La définition des options affecte à la fois le périphérique à rembobinage automatique et le périphérique sans rembobinage.

Différentes options peuvent être spécifiées pour les différents périphériques au sein du sous-groupe de quatre. Les options prennent effet lors de l'ouverture du périphérique. Par exemple, l'administrateur système peut définir un périphérique qui écrit en mode bloc fixe avec une certaine taille de bloc, et un autre qui écrit en mode bloc variable (si le lecteur prend en charge les deux modes).

Le pilote prend en charge les partitions de bande si elles sont prises en charge par le lecteur. (Notez que les partitions de bande n'ont rien à voir avec les partitions de disque. Une bande partitionnée peut être vue comme plusieurs bandes logiques au sein d'un même support.) La prise en charge des partitions doit être activée avec un ioctl(2). La position de la bande est préservée dans chaque partition lors des changements de partition. La partition utilisée pour les opérations de bande ultérieures est sélectionnée avec un ioctl(2). Le changement de partition est exécuté en même temps que la prochaine opération de bande afin d'éviter un mouvement de bande inutile. Le nombre maximum de partitions sur une bande est défini par une constante de compilation (initialement quatre). Le pilote contient un ioctl(2) qui peut formater une bande avec une ou deux partitions.

Le périphérique /dev/tape est généralement créé comme un lien physique ou symbolique vers le périphérique de bande par défaut sur le système.

À partir de Linux 2.6.2, le pilote exporte dans le répertoire sysfs /sys/class/scsi_tape les périphériques connectés et certains paramètres assignés aux périphériques.

Transfert de données

Le pilote prend en charge le fonctionnement en mode bloc fixe et en mode bloc variable (si pris en charge par le lecteur). En mode bloc fixe, le lecteur écrit des blocs de la taille spécifiée et la taille du bloc ne dépend pas des nombres d'octets des appels d'écriture. En mode bloc variable, un bloc de bande est écrit pour chaque appel d'écriture et le nombre d'octets détermine la taille du bloc de bande correspondant. Notez que les blocs sur la bande ne contiennent aucune information sur le mode d'écriture : lors de la lecture, la seule chose importante est d'utiliser des commandes qui acceptent les tailles de bloc présentes sur la bande.

En mode bloc variable, le nombre d'octets lus ne doit pas nécessairement correspondre exactement à la taille du bloc de bande. Si le nombre d'octets est supérieur au bloc suivant sur la bande, le pilote renvoie les données et la fonction renvoie la taille réelle du bloc. Si la taille du bloc est supérieure au nombre d'octets, une erreur est renvoyée.

En mode bloc fixe, les nombres d'octets lus peuvent être arbitraires si la mise en tampon est activée, ou un multiple de la taille du bloc de bande si la mise en tampon est désactivée. Avant Linux 2.1.121, les écritures avec un nombre d'octets arbitraire sont autorisées si la mise en tampon est activée. Dans tous les autres cas (avant Linux 2.1.121 avec la mise en tampon désactivée ou un noyau plus récent), le nombre d'octets d'écriture doit être un multiple de la taille du bloc de bande.

Dans Linux 2.6, le pilote essaie d'utiliser des transferts directs entre le tampon utilisateur et le périphérique. Si cela n'est pas possible, le tampon interne du pilote est utilisé. Les raisons de ne pas utiliser de transferts directs incluent un alignement incorrect du tampon utilisateur (par défaut, 512 octets, mais cela peut être modifié par le pilote HBA), une ou plusieurs pages du tampon utilisateur inaccessibles par l'adaptateur SCSI, etc.

Une marque de fichier est automatiquement écrite sur la bande si la dernière opération de bande avant la fermeture était une écriture.

Lorsqu'une marque de fichier est rencontrée pendant la lecture, il se passe ce qui suit. S'il reste des données dans le tampon lorsque la marque de fichier est trouvée, les données tamponnées sont renvoyées. La lecture suivante renvoie zéro octet. La lecture suivante renvoie les données du fichier suivant. La fin des données enregistrées est signalée en renvoyant zéro octet pour deux appels de lecture consécutifs. La troisième lecture renvoie une erreur.

Ioctls

Le pilote prend en charge trois requêtes ioctl(2). Les requêtes non reconnues par le pilote st sont transmises au pilote SCSI. Les définitions ci-dessous proviennent de /usr/include/linux/mtio.h :

MTIOCTOP — effectuer une opération de bande

Cette requête prend un argument de type (struct mtop *)

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>. Toutes les unités ne prennent pas en charge toutes les opérations. Le pilote retourne une erreur EIO si l'unité rejette une opération.


/* Structure pour MTIOCTOP - commande d'opération de bande magnétique : */
struct mtop {
    short   mt_op;       /* opérations définies ci-dessous */
    int     mt_count;    /* combien d'entre elles */
};

Opérations de bande magnétique pour une utilisation normale de la bande :

MTBSF
Recule de mt_count marques de fin de fichier.
MTBSFM
Recule de mt_count marques de fin de fichier. Repositionne la bande sur le côté EOT du dernier marqueur de fin de fichier.
MTBSR
Recule de mt_count enregistrements (blocs de bande).
MTBSS
Recule de mt_count marques de jeu.
MTCOMPRESSION
Active la compression des données de bande dans l'unité si mt_count est non nul et désactive la compression si mt_count est zéro. Cette commande utilise la page de mode 15 prise en charge par la plupart des DAT.
MTEOM
Aller à la fin du média enregistré (pour ajouter des fichiers).
MTERASE
Effacer la bande. Avec Linux 2.6, un effacement court (marquer la bande comme vide) est effectué si l'argument est zéro. Sinon, un effacement long (effacer tout) est effectué.
MTFSF
Avance de mt_count marques de fin de fichier.
MTFSFM
Avance de mt_count marques de fin de fichier. Repositionne la bande sur le côté BOT de la dernière marque de fin de fichier.
MTFSR
Avance de mt_count enregistrements (blocs de bande).
MTFSS
Avance de mt_count marques de jeu.
MTLOAD
Exécute la commande de chargement SCSI. Un cas spécial est disponible pour certains chargeurs automatiques HP. Si mt_count est la constante MT_ST_HPLOADER_OFFSET plus un nombre, ce nombre est envoyé à l'unité pour contrôler le chargeur automatique.
MTLOCK
Verrouille la porte de l'unité de bande.
MTMKPART
Formate la bande en une ou deux partitions. Si mt_count est positif, il indique la taille de la partition 1 et la partition 0 contient le reste de la bande. Si mt_count est zéro, la bande est formatée en une seule partition. À partir de Linux 4.6, un mt_count négatif spécifie la taille de la partition 0 et le reste de la bande contient la partition 1. L'ordre physique des partitions dépend de l'unité. Cette commande n'est pas autorisée pour une unité à moins que le support de partitionnement ne soit activé pour l'unité (voir MT_ST_CAN_PARTITIONS ci-dessous).
MTNOP
Aucune opération — vide le tampon du pilote par effet de bord. Doit être utilisé avant de lire l'état avec MTIOCGET.
MTOFFL
Rembobine et met l'unité hors ligne.
MTRESET
Réinitialise l'unité.
MTRETEN
Rétensionne la bande.
MTREW
Rembobine.
MTSEEK
Se positionne sur le numéro de bloc de bande spécifié dans mt_count. Cette opération nécessite soit une unité SCSI-2 prenant en charge la commande LOCATE (adresse spécifique à l'appareil), soit une unité SCSI-1 compatible Tandberg (Tandberg, Archive Viper, Wangtek, ...). Le numéro de bloc doit être celui retourné précédemment par MTIOCPOS si des adresses spécifiques à l'appareil sont utilisées.
MTSETBLK
Définit la longueur de bloc de l'unité sur la valeur spécifiée dans mt_count. Une longueur de bloc de zéro met l'unité en mode de taille de bloc variable.
MTSETDENSITY
Définit la densité de la bande sur le code dans mt_count. Les codes de densité pris en charge par une unité peuvent être trouvés dans la documentation de l'unité.
MTSETPART
La partition active est commutée sur mt_count. Les partitions sont numérotées à partir de zéro. Cette commande n'est pas autorisée pour une unité à moins que le support de partitionnement ne soit activé pour l'unité (voir MT_ST_CAN_PARTITIONS ci-dessous).
MTUNLOAD
Exécute la commande de déchargement SCSI (n'éjecte pas la bande).
MTUNLOCK
Déverrouille la porte de l'unité de bande.
MTWEOF
Écrit mt_count marques de fin de fichier.
MTWSM
Écrit mt_count marques de jeu.

Opérations de bande magnétique pour la configuration des options de l'unité (par le superutilisateur) :

MTSETDRVBUFFER
Définit diverses options d'unité et de pilote selon les bits encodés dans mt_count. Celles-ci comprennent le mode de mise en tampon de l'unité, un ensemble d'options booléennes du pilote, le seuil d'écriture du tampon, les valeurs par défaut pour la taille de bloc et la densité, et les délais (depuis Linux 2.1 uniquement). Une seule opération peut affecter un seul élément de la liste ci-dessous (les booléens comptent comme un élément).
Une valeur ayant des zéros dans les 4 bits de poids fort sera utilisée pour définir le mode de mise en tampon de l'unité. Les modes de mise en tampon sont :
0
L'unité ne rapportera pas le statut GOOD sur les commandes d'écriture tant que les blocs de données n'auront pas été effectivement écrits sur le média.
1
L'unité peut rapporter le statut GOOD sur les commandes d'écriture dès que toutes les données ont été transférées vers le tampon interne de l'unité.
2
L'unité peut rapporter le statut GOOD sur les commandes d'écriture dès que (a) toutes les données ont été transférées vers le tampon interne de l'unité, et (b) toutes les données mises en tampon provenant de différents initiateurs ont été écrites avec succès sur le média.
Pour contrôler le seuil d'écriture, la valeur dans mt_count doit inclure la constante MT_ST_WRITE_THRESHOLD OU bit à bit avec un nombre de blocs dans les 28 bits de poids faible. Le nombre de blocs fait référence à des blocs de 1024 octets, et non à la taille physique du bloc sur la bande. Le seuil ne peut pas dépasser la taille du tampon interne du pilote (voir DESCRIPTION, ci-dessus).
Pour définir et effacer les options booléennes, la valeur dans mt_count doit inclure l'une des constantes MT_ST_BOOLEANS, MT_ST_SETBOOLEANS, MT_ST_CLEARBOOLEANS ou MT_ST_DEFBOOLEANS OU bit à bit avec la combinaison souhaitée des options suivantes. En utilisant MT_ST_BOOLEANS, les options peuvent être définies sur les valeurs définies dans les bits correspondants. Avec MT_ST_SETBOOLEANS, les options peuvent être sélectivement définies et avec MT_ST_DEFBOOLEANS sélectivement effacées.
Les options par défaut pour un périphérique de bande sont définies avec MT_ST_DEFBOOLEANS. Un périphérique de bande inactif (par exemple, périphérique avec le mineur 32 ou 160) est activé lorsque les options par défaut pour celui-ci sont définies pour la première fois. Un périphérique activé hérite des options non définies explicitement du périphérique activé au démarrage.
Les options booléennes sont :
MT_ST_BUFFER_WRITES (Défaut : vrai)
Met en tampon toutes les opérations d'écriture en mode bloc fixe. Si cette option est fausse et que l'unité utilise une taille de bloc fixe, toutes les opérations d'écriture doivent être un multiple de la taille du bloc. Cette option doit être définie sur faux pour écrire des archives multivolumes fiables.
MT_ST_ASYNC_WRITES (Défaut : vrai)
Lorsque cette option est vraie, les opérations d'écriture retournent immédiatement sans attendre que les données soient transférées vers l'unité si les données tiennent dans le tampon du pilote. Le seuil d'écriture détermine à quel point le tampon doit être plein avant qu'une nouvelle commande d'écriture SCSI ne soit émise. Toute erreur signalée par l'unité sera conservée jusqu'à la prochaine opération. Cette option doit être définie sur faux pour écrire des archives multivolumes fiables.
MT_ST_READ_AHEAD (Défaut : vrai)
Cette option provoque la mise en place d'une mise en tampon de lecture et d'une lecture anticipée en mode bloc fixe par le pilote. Si cette option est fausse et que l'unité utilise une taille de bloc fixe, toutes les opérations de lecture doivent être un multiple de la taille du bloc.
MT_ST_TWO_FM (Défaut : faux)
Cette option modifie le comportement du pilote lors de la fermeture d'un fichier. L'action normale consiste à écrire une seule marque de fin de fichier. Si l'option est vraie, le pilote écrira deux marques de fin de fichier et reculera sur la deuxième.
Remarque : Cette option ne doit pas être définie sur vrai pour les unités de bande QIC car elles ne peuvent pas écraser une marque de fin de fichier. Ces unités détectent la fin des données enregistrées en testant une bande vierge plutôt que deux marques de fin de fichier consécutives. La plupart des autres unités actuelles détectent également la fin des données enregistrées et l'utilisation de deux marques de fin de fichier n'est généralement nécessaire que lors de l'échange de bandes avec certains autres systèmes.
MT_ST_DEBUGGING (Défaut : faux)
Cette option active divers messages de débogage du pilote (effective uniquement si le pilote a été compilé avec DEBUG défini sur non nul).
MT_ST_FAST_EOM (Défaut : faux)
Cette option provoque l'envoi de l'opération MTEOM directement à l'unité, ce qui peut accélérer l'opération mais fait perdre au pilote la trace du numéro de fichier actuel normalement retourné par la requête MTIOCGET. Si MT_ST_FAST_EOM est faux, le pilote répondra à une requête MTEOM en avançant sur les fichiers.
MT_ST_AUTO_LOCK (Défaut : faux)
Lorsque cette option est vraie, la porte de l'unité est verrouillée lorsque le fichier de l'unité est ouvert et déverrouillée lorsqu'il est fermé.

NAME

mt — magnetic tape drive control

SYNOPSIS

mt [-f special] operation [count]

DESCRIPTION

The mt utility controls a magnetic tape drive. It can be used to position the tape, to write file marks, to skip files or records, and to send various commands to the tape drive. The tape device is specified by the -f option, which takes the special file name of the tape device as an argument. If the -f option is omitted, mt uses the special file named in the environment variable TAPE, or if that is unset, it uses /dev/rmt0.

The operation argument specifies the action to be performed. It can be given as a symbolic name (see below) or as a number.

The optional count argument specifies how many times the operation should be performed. If omitted, it defaults to 1. Some operations ignore the count argument.

The following operations are available:

EOM
Space the tape to the logical end-of-media (the position of the first file mark after the first file). This is useful for multi-volume sequential files.
EOF, WEF
Write one or more file marks at the current position on the tape. If count is specified, that many file marks are written.
FSF
Space over one or more file marks. If count is specified, space over that many file marks. The tape is positioned at the beginning of the file following the last file mark skipped.
BSF
Space backward over one or more file marks. If count is specified, space backward over that many file marks. The tape is positioned at the beginning of the file preceding the last file mark skipped.
FSR
Space over one or more records. If count is specified, space over that many records. The tape is positioned at the beginning of the record following the last record skipped.
BSR
Space backward over one or more records. If count is specified, space backward over that many records. The tape is positioned at the beginning of the record preceding the last record skipped.
REW
Rewind the tape to the beginning of the first file.
OFFL
Rewind the tape and eject it from the drive.
FMT
Format the tape. This operation is device specific and may take a long time. For some drives, the format operation is not supported.
RET
Rewind the tape and then rewind it again to the beginning of the first file. This operation is usually used to test the tape drive.
CLIO
Rewind the tape, then space forward over the first file mark, and then rewind again. This operation is used to position the tape at the beginning of the first file. This is only applicable for tapes that use partitioning.
IEN
Set the tape to the beginning of the first file in the current partition. This is applicable for tapes that use partitioning.
BSK
Space backward over one or more partitions. If count is specified, space backward over that many partitions. The tape is positioned at the beginning of the first file in the partition preceding the last partition skipped.
LSEEK
Set the tape to the beginning of the Nth file (N = count). The first file is file 0.
LBLOCK
Set the tape to the beginning of the Nth record within the current file (N = count). The first record is record 0.
RST
Rewind the tape to the beginning of the first file and then space forward to the beginning of the Nth file (N = count). The first file is file 0.
SEEK
Set the tape to the beginning of the Nth file (N = count). The first file is file 1.
POS
Print the current tape position (file number and record number within the file). This operation is only supported by SCSI-2 tape drives that support the READ POSITION command.
STPOS
Set the tape to the specified file number and block number. The file number and block number are specified in the count argument, with the file number in the high 16 bits and the block number in the low 16 bits.
DRVBUF
Set the drive buffering mode. The count argument can be one of the following values:
MT_ST_NORMAL_BUF
Normal buffering mode.
MT_ST_BUFFER_WRITES
Enable buffering of writes.
MT_ST_ASYNC_WRITES
Enable asynchronous writes.
MT_ST_SYNCHRONOUS
Enable synchronous mode.
MT_ST_DIRECT
Enable direct mode.
MT_ST_BOOLEANS
Mask for all buffering modes.
STDEVTPL
Set the default tape partition and tape block size. The count argument is a bitmask that specifies the partition (bits 0-2) and the block size (bits 3-23).
STDEFDENSITY
Set the default density code.
STSETBLK
Set the default block size. The count argument is the block size in bytes.
STSETCOMP
Set the compression mode. The count argument can be one of the following values:
MT_ST_COMP_OFF
Compression disabled.
MT_ST_COMP_ON
Compression enabled.
MT_ST_COMP_DEF
Use default compression setting.
STSETDN
Set the drive name. The count argument is a pointer to a null-terminated string.
STSETDRVINFO
Set drive information. The count argument is a pointer to a struct mtop structure.
STATUS
Print the status of the tape drive.
VERSION
Print the version of the mt utility.

IOCTLS

The mt utility uses the following ioctls:

MTIOCTOP — tape operation

This request takes an argument of type (struct mtop *).


/* structure for MTIOCTOP - mag tape operation command */
struct mtop {
    int      mt_op;     /* operation code */
    int      mt_count;  /* number of operations */
};
mt_op
The operation code. It is a combination of the operation names above (e.g., MTBSF, MTREW) and the following options:
MT_ST_WRITEOF
Write an end-of-file mark.
MT_ST_SHORTFMT
Short form of the format command.
MT_ST_ERASE
Erase tape.
mt_count
The number of times the operation should be performed. This field is used by the driver to perform multiple operations, e.g., writing multiple file marks.

The following options can be ORed with the operation code:

MT_ST_DEF_WRITES (Default: false)
Les options de bande (taille de bloc, mode, compression, etc.) peuvent changer lors du passage d'un périphérique lié à un lecteur à un autre périphérique lié au même lecteur, en fonction de la manière dont les périphériques sont définis. Cette option définit quand les changements sont appliqués par le pilote à l'aide de commandes SCSI et quand les capacités d'auto-détection des lecteurs sont utilisées. Si cette option est fausse, le pilote envoie les commandes SCSI immédiatement lorsque le périphérique est changé. Si l'option est vraie, les commandes SCSI ne sont pas envoyées tant qu'une écriture n'est pas demandée. Dans ce cas, le micrologiciel du lecteur est autorisé à détecter la structure de la bande lors de la lecture et les commandes SCSI sont utilisées uniquement pour s'assurer qu'une bande est écrite conformément à la spécification correcte.
MT_ST_CAN_BSR (Default: false)
Lorsque la lecture anticipée est utilisée, la bande doit parfois être reculée à la bonne position lorsque le périphérique est fermé et la commande SCSI pour reculer sur les enregistrements est utilisée à cette fin. Certains lecteurs plus anciens ne peuvent pas traiter cette commande de manière fiable et cette option peut être utilisée pour indiquer au pilote de ne pas utiliser la commande. Le résultat est qu'avec la lecture anticipée et le mode à blocs fixes, la bande peut ne pas être correctement positionnée dans un fichier lorsque le périphérique est fermé. Avec Linux 2.6, la valeur par défaut est vraie pour les lecteurs prenant en charge SCSI-3.
MT_ST_NO_BLKLIMS (Default: false)
Certains lecteurs n'acceptent pas la commande SCSI READ BLOCK LIMITS. Si cela est utilisé, le pilote n'utilise pas la commande. L'inconvénient est que le pilote ne peut pas vérifier avant d'envoyer des commandes si la taille de bloc sélectionnée est acceptable pour le lecteur.
MT_ST_CAN_PARTITIONS (Default: false)
Cette option active la prise en charge de plusieurs partitions dans une bande. L'option s'applique à tous les périphériques liés à un lecteur.
MT_ST_SCSI2LOGICAL (Default: false)
Cette option indique au pilote d'utiliser les adresses de bloc logiques définies dans la norme SCSI-2 lors des opérations de recherche et de rapport (à la fois avec les commandes MTSEEK et MTIOCPOS et lors du changement de partition de bande). Sinon, les adresses spécifiques au périphérique sont utilisées. Il est fortement conseillé de définir cette option si le lecteur prend en charge les adresses logiques, car elles comptent également les marques de fichier. Il existe certains lecteurs qui ne prennent en charge que les adresses de bloc logiques.
MT_ST_SYSV (Default: false)
Lorsque cette option est activée, les périphériques de bande utilisent les sémantiques System V. Sinon, les sémantiques BSD sont utilisées. La différence la plus importante entre les sémantiques concerne ce qui se passe lorsqu'un périphérique utilisé pour la lecture est fermé : dans les sémantiques System V, la bande est avancée au-delà de la marque de fichier suivante si cela ne s'est pas produit lors de l'utilisation du périphérique. Dans les sémantiques BSD, la position de la bande n'est pas modifiée.
MT_NO_WAIT (Default: false)
Active le mode immédiat (c'est-à-dire ne pas attendre la fin de la commande) pour certaines commandes (par exemple, rembobinage).

Un exemple:


struct mtop mt_cmd;
mt_cmd.mt_op = MTSETDRVBUFFER;
mt_cmd.mt_count = MT_ST_BOOLEANS |
        MT_ST_BUFFER_WRITES | MT_ST_ASYNC_WRITES;
ioctl(fd, MTIOCTOP, mt_cmd);

La taille de bloc par défaut pour un périphérique peut être définie avec MT_ST_DEF_BLKSIZE et le code de densité par défaut peut être défini avec MT_ST_DEFDENSITY. Les valeurs des paramètres sont combinées par OR avec le code d'opération.

Avec Linux 2.1.x et versions ultérieures, les délais d'attente peuvent être définis avec le sous-commande MT_ST_SET_TIMEOUT combinée par OR avec le délai d'attente en secondes. Le délai d'attente long (utilisé pour les rembobinages et autres commandes qui peuvent prendre du temps) peut être défini avec MT_ST_SET_LONG_TIMEOUT. Les valeurs par défaut du noyau sont très longues pour garantir qu'une commande réussie ne soit pas interrompue par un délai d'attente avec un lecteur quelconque. Pour cette raison, le pilote peut sembler bloqué même s'il attend simplement le délai d'attente. Ces commandes peuvent être utilisées pour définir des valeurs plus pratiques pour un lecteur spécifique. Les délais d'attente définis pour un périphérique s'appliquent à tous les périphériques liés au même lecteur.

À partir de Linux 2.4.19 et Linux 2.5.43, le pilote prend en charge un bit d'état qui indique si le lecteur demande un nettoyage. La méthode utilisée par le lecteur pour retourner les informations de nettoyage est définie à l'aide de la sous-commande MT_ST_SEL_CLN. Si la valeur est zéro, le bit de nettoyage est toujours zéro. Si la valeur est un, les données TapeAlert définies dans la norme SCSI-3 sont utilisées (pas encore implémentées). Les valeurs 2 à 17 sont réservées. Si les huit bits de poids faible sont supérieurs ou égaux à 18, les bits des données de sense étendues sont utilisés. Les bits 9 à 16 spécifient un masque pour sélectionner les bits à examiner et les bits 17 à 23 spécifient le modèle de bits à rechercher. Si le modèle de bits est zéro, un ou plusieurs bits sous le masque indiquent la demande de nettoyage. Si le modèle est non nul, le modèle doit correspondre à l'octet de données de sense masqué.

MTIOCGET — obtenir le statut

Cette requête prend un argument de type (struct mtget *).


/* structure pour MTIOCGET - commande d'obtention de statut de bande magnétique */
struct mtget {
    long     mt_type;
    long     mt_resid;
    /* les registres suivants dépendent du périphérique */
    long     mt_dsreg;
    long     mt_gstat;
    long     mt_erreg;
    /* Les deux champs suivants ne sont pas toujours utilisés */
    daddr_t  mt_fileno;
    daddr_t  mt_blkno;
};
mt_type
Le fichier d'en-tête définit de nombreuses valeurs pour mt_type, mais le pilote actuel ne signale que les types génériques MT_ISSCSI1 (bande SCSI-1 générique) et MT_ISSCSI2 (bande SCSI-2 générique).
mt_resid
contient le numéro de partition de bande actuel.
mt_dsreg
rapporte les paramètres actuels du lecteur pour la taille de bloc (dans les 24 bits de poids faible) et la densité (dans les 8 bits de poids fort). Ces champs sont définis par MT_ST_BLKSIZE_SHIFT, MT_ST_BLKSIZE_MASK, MT_ST_DENSITY_SHIFT et MT_ST_DENSITY_MASK.
mt_gstat
rapporte des informations de statut génériques (indépendantes du périphérique). Le fichier d'en-tête définit des macros pour tester ces bits de statut :
GMT_EOF(x)
La bande est positionnée juste après une marque de fichier (toujours faux après une opération MTSEEK).
GMT_BOT(x)
La bande est positionnée au début du premier fichier (toujours faux après une opération MTSEEK).
GMT_EOT(x)
Une opération de bande a atteint la fin physique de la bande.
GMT_SM(x)
La bande est actuellement positionnée sur une marque de jeu (toujours faux après une opération MTSEEK).
GMT_EOD(x)
La bande est positionnée à la fin des données enregistrées.
GMT_WR_PROT(x)
Le lecteur est protégé en écriture. Pour certains lecteurs, cela peut aussi signifier que le lecteur ne prend pas en charge l'écriture sur le type de média actuel.
GMT_ONLINE(x)
La dernière ouverture open(2) a trouvé le lecteur avec une bande en place et prête pour l'opération.
GMT_D_6250(x)
GMT_D_1600(x)
GMT_D_800(x)
Ces informations de statut "génériques" rapportent le réglage de densité actuel pour les lecteurs de bande 9 pistes de 1/2 pouce uniquement.
GMT_DR_OPEN(x)
Le lecteur n'a pas de bande en place.
GMT_IM_REP_EN(x)
Mode de rapport immédiat. Ce bit est défini s'il n'y a aucune garantie que les données aient été physiquement écrites sur la bande lorsque l'appel d'écriture retourne. Il est défini à zéro uniquement lorsque le pilote ne met pas en mémoire tampon les données et que le lecteur est configuré pour ne pas mettre en mémoire tampon les données.
GMT_CLN(x)
Le lecteur a demandé un nettoyage. Implémenté depuis Linux 2.4.19 et Linux 2.5.43.
mt_erreg
Le seul champ défini dans mt_erreg est le nombre d'erreurs récupérées dans les 16 bits de poids faible (tel que défini par MT_ST_SOFTERR_SHIFT et MT_ST_SOFTERR_MASK). En raison d'incohérences dans la manière dont les lecteurs rapportent les erreurs récupérées, ce compteur n'est souvent pas maintenu (la plupart des lecteurs ne signalent pas les erreurs logicielles par défaut, mais cela peut être modifié avec une commande SCSI MODE SELECT).
mt_fileno
rapporte le numéro de fichier actuel (indexé à partir de zéro). Cette valeur est définie à -1 lorsque le numéro de fichier est inconnu (par exemple, après MTBSS ou MTSEEK).
mt_blkno
rapporte le numéro d'enregistrement (indexé à partir de zéro) dans le fichier actuel. Cette valeur est définie à -1 lorsque le numéro d'enregistrement est inconnu (par exemple, après MTBSF, MTBSS, ou MTSEEK).

MTIOCPOS — obtenir la position de la bande

Cette requête prend un argument de type (struct mtpos *) et rapporte la notion du lecteur du numéro d'enregistrement de bande actuel, qui n'est pas le même que mt_blkno retourné par MTIOCGET. Ce lecteur doit être un lecteur SCSI-2 qui prend en charge la commande READ POSITION (adresse spécifique au périphérique) ou un lecteur SCSI-1 compatible Tandberg (Tandberg, Archive Viper, Wangtek, ...).


/* structure pour MTIOCPOS - commande d'obtention de position de bande magnétique */
struct mtpos {
    long mt_blkno;    /* numéro d'enregistrement actuel */
};

VALEUR DE RETOUR

EACCES
Une tentative a été faite pour écrire ou effacer une bande protégée en écriture. (Cette erreur n'est pas détectée lors de l'open(2).)
EBUSY
Le périphérique est déjà utilisé ou le pilote n'a pas pu allouer de tampon.
EFAULT
Les paramètres de la commande pointent vers une mémoire n'appartenant pas au processus appelant.
EINVAL
Un ioctl(2) avait un argument invalide, ou une taille de bloc demandée était invalide.
EIO
L'opération demandée n'a pas pu être terminée.
ENOMEM
Le nombre d'octets dans read(2) est plus petit que le bloc physique suivant sur la bande. (Avant Linux 2.2.18 et Linux 2.4.0, les octets supplémentaires étaient silencieusement ignorés.)
ENOSPC
Une opération d'écriture n'a pas pu être terminée car la bande a atteint la fin du média.
ENOSYS
ioctl(2) inconnu.
ENXIO
Lors de l'ouverture, le périphérique de bande n'existe pas.
EOVERFLOW
Une tentative a été faite pour lire ou écrire un bloc de longueur variable plus grand que le tampon interne du pilote.
EROFS
Une ouverture est tentée avec O_WRONLY ou O_RDWR alors que la bande dans le lecteur est protégée en écriture.

/dev/st*
les périphériques de bande SCSI à rembobinage automatique
/dev/nst*
les périphériques de bande SCSI sans rembobinage

NOTES

•
Lors de l'échange de données entre systèmes, les deux systèmes doivent s'accorder sur la taille physique du bloc de bande. Les paramètres d'un lecteur après le démarrage ne sont souvent pas ceux que la plupart des systèmes d'exploitation utilisent avec ces périphériques. La plupart des systèmes utilisent les lecteurs en mode bloc variable si le lecteur prend en charge ce mode. Cela s'applique à la plupart des lecteurs modernes, y compris les DAT, les lecteurs à balayage hélicoïdal 8 mm, les DLT, etc. Il peut être conseillé d'utiliser ces lecteurs en mode bloc variable également sous Linux (c'est-à-dire utiliser MTSETBLK ou MTSETDEFBLK au démarrage du système pour définir le mode), du moins lors de l'échange de données avec un système étranger. L'inconvénient est qu'une taille de bloc de bande assez grande doit être utilisée pour obtenir des taux de transfert de données acceptables sur le bus SCSI.
•
De nombreux programmes (par exemple, tar(1)) permettent à l'utilisateur de spécifier le facteur de blocage sur la ligne de commande. Notez que cela ne détermine la taille du bloc physique sur la bande qu'en mode bloc variable.
•
Pour utiliser les lecteurs de bande SCSI, le pilote SCSI de base, un pilote d'adaptateur SCSI et le pilote de bande SCSI doivent être configurés dans le noyau ou chargés en tant que modules. Si le pilote de bande SCSI est absent, le lecteur est reconnu mais le support de bande décrit dans cette page n'est pas disponible.
•
Le pilote écrit des messages d'erreur sur la console/journal. Les codes SENSE écrits dans certains messages sont automatiquement traduits en texte si les messages SCSI verbeux sont activés dans la configuration du noyau.
•
La mise en mémoire tampon interne du pilote permet un bon débit en mode bloc fixe également avec de petites tailles d'octets de read(2) et write(2). Avec les transferts directs, ce n'est pas possible et peut surprendre lors du passage au noyau 2.6. La solution consiste à indiquer au logiciel d'utiliser des transferts plus importants (souvent en lui indiquant d'utiliser des blocs plus grands). Si cela n'est pas possible, les transferts directs peuvent être désactivés.
