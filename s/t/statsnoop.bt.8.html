NOM

statsnoop.bt - Trace les appels système stat(). Utilise bpftrace/eBPF.

SYNOPIS

statsnoop.bt

DESCRIPTION

statsnoop trace l'appel système stat(), montrant quels processus tentent d'accéder (stat) à quels fichiers. Cela peut être utile pour déterminer l'emplacement des fichiers de configuration et de journalisation, ou pour dépanner les applications qui échouent, notamment au démarrage.

Ceci trace les tracepoints pour statfs(), statx(), newstat(), et newlstat(). Ce ne sont pas les seuls appels système stat : si vous manquez d'activité, vous devrez peut-être ajouter d'autres variantes.

Étant donné que ceci utilise BPF, seul l'utilisateur root peut utiliser cet outil.

EXIGENCES

CONFIG_BPF et bcc.

EXEMPLES

Tracer tous les appels système stat() :
# statsnoop.bt

CHAMPS

PID ID du processus

TID
ID du thread
COMM
Nom du processus
FD
Descripteur de fichier (en cas de succès), ou -1 (en cas d'échec)
ERR
Numéro d'erreur (voir errno.h du système)
PATH
Chemin stat

SURCOUT

Ceci trace les tracepoints stat et affiche la sortie pour chaque événement. Comme le taux de ces événements est généralement attendu comme faible (< 1000/s), le surcoût est également considéré comme négligeable. Si vous avez une application qui effectue un grand nombre d'appels stat(), testez et comprenez le surcoût avant utilisation.

SOURCE

Ceci provient de bpftrace.

https://github.com/bpftrace/bpftrace

Consultez également le fichier _examples.txt dans la distribution bpftrace pour un exemple d'utilisation, de sortie et de commentaires pour cet outil.

Il s'agit d'une version bpftrace de l'outil bcc du même nom. L'outil bcc peut offrir plus d'options et de personnalisations.

https://github.com/iovisor/bcc
