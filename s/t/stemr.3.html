CSTEMR

Objectif :

!>
!> CSTEMR calcule certaines valeurs propres et, éventuellement, certains vecteurs propres
!> d'une matrice tridiagonale symétrique réelle T. Toute matrice non réduite a
!> un ensemble bien défini de valeurs propres réelles deux à deux distinctes, les vecteurs
!> propres réels correspondants sont deux à deux orthogonaux.
!>
!> Le spectre peut être calculé soit complètement, soit partiellement en spécifiant
!> soit un intervalle (VL,VU] soit une plage d'indices IL:IU pour les valeurs propres
!> souhaitées.
!>
!> Selon le nombre de valeurs propres désirées, celles-ci sont calculées soit
!> par bissection, soit par l'algorithme dqds. Des vecteurs propres numériquement orthogonaux sont
!> calculés grâce à diverses factorisations L D L^T appropriées à proximité des clusters
!> de valeurs propres proches (appelées RRR, Représentations Relativement Robustes). Un aperçu informel de l'algorithme suit.
!>
!> Pour chaque bloc non réduit (sous-matrice) de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres recherchées avec une haute précision relative.
!>        Cela signifie que de petits changements relatifs dans les entrées de D et L
!>        entraînent de petits changements relatifs dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a généralement pas cette propriété.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont désirés, l'algorithme atteint la pleine
!>        précision des valeurs propres calculées juste avant
!>        que les vecteurs correspondants doivent être calculés, voir les étapes c) et d).
!>    (c) Pour chaque cluster de valeurs propres proches, sélectionner un nouveau
!>        décalage proche du cluster, trouver une nouvelle factorisation et affiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisamment grande, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélant le rang. Revenir à (c) pour les clusters restants.
!>
!> Pour plus de détails, voir :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett : SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Également LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!> Détails supplémentaires
!> 1. CSTEMR ne fonctionne que sur des machines qui suivent la norme de
!>    virgule flottante IEEE-754 dans leur gestion des infinis et des NaN.
!>    Cela permet d'utiliser des boucles internes efficaces évitant la vérification des
!>    diviseurs nuls.
!>
!> 2. Les routines LAPACK peuvent être utilisées pour réduire une matrice hermitienne complexe à
!>    une forme tridiagonale symétrique réelle.
!>
!> (Toute matrice tridiagonale hermitienne complexe a des valeurs réelles sur sa diagonale
!> et potentiellement des nombres complexes sur ses sous-diagonales. En appliquant une
!> transformation de similarité avec une matrice diagonale appropriée
!> diag(1,e^{i \phy_1}, ... , e^{i \phy_{n-1}}), la matrice hermitienne complexe
!> peut être transformée en une matrice symétrique réelle et l'arithmétique complexe
!> peut être entièrement évitée.)
!>
!> Alors que les vecteurs propres de la matrice tridiagonale symétrique réelle sont réels,
!> les vecteurs propres de la matrice hermitienne complexe d'origine ont en général des entrées complexes.
!> Étant donné que les pilotes LAPACK écrasent les données de la matrice avec les vecteurs propres,
!> CSTEMR accepte un espace de travail complexe pour faciliter l'interopérabilité
!> avec CUNMTR ou CUPMTR.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N' : Calculer uniquement les valeurs propres ;
!>          = 'V' : Calculer les valeurs propres et les vecteurs propres.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A' : toutes les valeurs propres seront trouvées.
!>          = 'V' : toutes les valeurs propres dans l'intervalle demi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I' : les valeurs propres d'indice IL à IU seront trouvées.
!>

N

!>          N est INTEGER
!>          Ordre de la matrice.  N >= 0.
!>

D

!>          D est un tableau REAL, de dimension (N)
!>          En entrée, les N éléments diagonaux de la matrice tridiagonale
!>          T. En sortie, D est écrasé.
!>

E

!>          E est un tableau REAL, de dimension (N)
!>          En entrée, les (N-1) éléments sous-diagonaux de la matrice tridiagonale
!>          T dans les éléments 1 à N-1 de E. E(N) n'a pas besoin d'être défini à l'entrée,
!>          mais est utilisé en interne comme espace de travail.
!>          En sortie, E est écrasé.
!>

VL

!>          VL est REAL
!>
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est REAL
!>
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

M

!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!>

W

!>          W est un tableau REAL, de dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées en
!>          ordre croissant.
!>

Z

!>          Z est un tableau COMPLEX, de dimension (LDZ, max(1,M) )
!>          Si JOBZ = 'V', et si INFO = 0, alors les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormés de la matrice T
!>          correspondant aux valeurs propres sélectionnées, la i-ème
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Si JOBZ = 'N', alors Z n'est pas référencé.
!>          Note : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et peut être calculée avec une requête d'espace de travail en définissant NZC = -1, s

LDZ

!>          LDZ est un entier
!>          La dimension principale du tableau Z. LDZ >= 1, et si
!>          JOBZ = 'V', alors LDZ >= max(1,N).
!>

NZC

!>          NZC est un entier
!>          Le nombre de vecteurs propres à conserver dans le tableau Z.
!>          Si RANGE = 'A', alors NZC >= max(1,N).
!>          Si RANGE = 'V', alors NZC >= le nombre de valeurs propres dans (VL,VU].
!>          Si RANGE = 'I', alors NZC >= IU-IL+1.
!>          Si NZC = -1, une requête d'espace de travail est supposée ; la
!>          routine calcule le nombre de colonnes du tableau Z qui
!>          sont nécessaires pour contenir les vecteurs propres.
!>          Cette valeur est retournée comme première entrée du tableau Z, et
!>          aucun message d'erreur lié à NZC n'est émis par XERBLA.
!>

ISUPPZ

!>          ISUPPZ est un tableau d'entiers, de dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ème vecteur propre calculé
!>          est non nul seulement dans les éléments ISUPPZ( 2*i-1 ) jusqu'à
!>          ISUPPZ( 2*i ). Ceci est pertinent dans le cas où la matrice
!>          est divisée. ISUPPZ n'est accédé que lorsque JOBZ est 'V' et N > 0.
!>

TRYRAC

!>          TRYRAC est logique
!>          Si TRYRAC = .TRUE., indique que le code doit vérifier si
!>          la matrice tridiagonale définit ses valeurs propres avec une haute précision relative.
!>          Si c'est le cas, le code utilise des algorithmes préservant la précision relative
!>          qui peuvent être (un peu) plus lents en fonction de la matrice.
!>          Si la matrice ne définit pas ses valeurs propres avec une haute précision relative,
!>          le code peut utiliser des algorithmes potentiellement plus rapides.
!>          À la sortie, un TRYRAC .TRUE. sera mis à .FALSE. si la matrice
!>          ne définit pas ses valeurs propres avec une haute précision relative.
!>

WORK

!>          WORK est un tableau réel, de dimension (LWORK)
!>          À la sortie, si INFO = 0, WORK(1) retourne le LWORK optimal
!>          (et minimal).
!>

LWORK

!>          LWORK est un entier
!>          La dimension du tableau WORK. LWORK >= max(1,18*N)
!>          si JOBZ = 'V', et LWORK >= max(1,12*N) si JOBZ = 'N'.
!>          Si LWORK = -1, une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement la taille optimale du tableau WORK, retourne
!>          cette valeur comme première entrée du tableau WORK, et aucun message
!>          d'erreur lié à LWORK n'est émis par XERBLA.
!>

IWORK

!>          IWORK est un tableau d'entiers, de dimension (LIWORK)
!>          À la sortie, si INFO = 0, IWORK(1) retourne le LIWORK optimal.
!>

LIWORK

!>          LIWORK est un entier
!>          La dimension du tableau IWORK. LIWORK >= max(1,10*N)
!>          si les vecteurs propres sont désirés, et LIWORK >= max(1,8*N)
!>          si seules les valeurs propres doivent être calculées.
!>          Si LIWORK = -1, une requête d'espace de travail est supposée ; la
!>          routine calcule uniquement la taille optimale du tableau IWORK,
!>          retourne cette valeur comme première entrée du tableau IWORK, et
!>          aucun message d'erreur lié à LIWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est un entier
!>          À la sortie, INFO
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0 : si INFO = 1X, erreur interne dans SLARRE,
!>                si INFO = 2X, erreur interne dans CLARRV.
!>                Ici, le chiffre X = ABS( IINFO ) < 10, où IINFO est
!>                le code d'erreur non nul retourné respectivement par SLARRE ou
!>                CLARRV.
!>

!>
!> SSTEMR computes selected eigenvalues and, optionally, eigenvectors

!> a well defined set of pairwise different real eigenvalues, the corresponding

!>

!>
!> Depending on the number of desired eigenvalues, these are computed either

!> computed by the use of various suitable L D L^T factorizations near clusters

!>
!> For each unreduced block (submatrix) of T,
!>    (a) Compute T - sigma I  = L D L^T, so that L and D
!>        define all the wanted eigenvalues to high relative accuracy.

!> de valeurs propres proches (appelées RRR, Représentations Relativement Robustes). Un aperçu informel de l'algorithme suit.
!>
!> Pour chaque bloc non réduit (sous-matrice) de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres recherchées avec une haute précision relative.
!>        Cela signifie que de petits changements relatifs dans les entrées de D et L
!>        entraînent seulement de petits changements relatifs dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a pas cette propriété en général.
!>    (b) Calculer les valeurs propres avec une précision suffisante.
!>        Si les vecteurs propres sont désirés, l'algorithme atteint la pleine
!>        précision des valeurs propres calculées juste avant
!>        que les vecteurs correspondants ne soient calculés, voir les étapes c) et d).
!>    (c) Pour chaque amas de valeurs propres proches, sélectionner un nouveau
!>        décalage proche de l'amas, trouver une nouvelle factorisation et affiner
!>        les valeurs propres décalées avec une précision suffisante.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisamment grande, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélant le rang. Retourner à (c) pour tous les amas qui restent.
!>
!> Pour plus de détails, voir :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett :  SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004.  Également LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!> Détails supplémentaires
!> 1. ZSTEMR ne fonctionne que sur les machines qui suivent la norme IEEE-754
!> en virgule flottante pour la gestion des infinis et des NaN.
!> Cela permet l'utilisation de boucles internes efficaces évitant la vérification des
!> diviseurs nuls.
!>
!> 2. Les routines LAPACK peuvent être utilisées pour réduire une matrice hermitienne complexe à
!> une forme tridiagonale symétrique réelle.
!>
!> (Toute matrice tridiagonale hermitienne complexe a des valeurs réelles sur sa diagonale
!> et potentiellement des nombres complexes sur ses éléments hors diagonale. En appliquant une
!> transformation de similarité avec une matrice diagonale appropriée
!> diag(1,e^{i \phy_1}, ... , e^{i \phy_{n-1}}), la matrice hermitienne complexe
!> peut être transformée en une matrice symétrique réelle et l'arithmétique complexe
!> peut être entièrement évitée.)
!>
!> Bien que les vecteurs propres de la matrice tridiagonale symétrique réelle soient réels,
!> les vecteurs propres de la matrice hermitienne complexe d'origine ont en général des entrées complexes.
!> Comme les drivers LAPACK écrasent les données de la matrice avec les vecteurs propres,
!> ZSTEMR accepte un espace de travail complexe pour faciliter l'interopérabilité
!> avec ZUNMTR ou ZUPMTR.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A': toutes les valeurs propres seront trouvées.
!>          = 'V': toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]

N

!>          N est INTEGER
!>          L'ordre de la matrice.  N >= 0.
!>

D

!>          D est un tableau DOUBLE PRECISION, dimension (N)
!>          En entrée, les N éléments diagonaux de la matrice tridiagonale
!>          T. En sortie, D est écrasé.
!>

E

!>          E est un tableau DOUBLE PRECISION, dimension (N)
!>          En entrée, les (N-1) éléments sous-diagonaux de la matrice
!>          tridiagonale T dans les éléments 1 à N-1 de E. E(N) n'a pas besoin

!>          rechercher pour les valeurs propres. VL < VU.

!>

VU

!>          VU est DOUBLE PRECISION
!>
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.

IL

!>          IL est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

M

!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.

W

!>          W est un tableau DOUBLE PRECISION, dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées en
!>          ordre croissant.
!>

Z

!>          Z est un tableau COMPLEX*16, dimension (LDZ, max(1,M) )
!>          Si JOBZ = 'V', et si INFO = 0, alors les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormés de la matrice T
!>          correspondant aux valeurs propres sélectionnées, la i-ème
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Si JOBZ = 'N', alors Z n'est pas référencé.
!>          Note : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont

LDZ

!>          LDZ est INTEGER
!>          La dimension principale du tableau Z.  LDZ >= 1, et si
!>          JOBZ = 'V', alors LDZ >= max(1,N).
!>

NZC

!>          NZC est INTEGER
!>          Le nombre de vecteurs propres à contenir dans le tableau Z.
!>          Si RANGE = 'A', alors NZC >= max(1,N).
!>          Si RANGE = 'V', alors NZC >= le nombre de valeurs propres dans (VL,VU].

!>          Si NZC = -1, alors une requête d'espace de travail est supposée ; la

!>          contenir les vecteurs propres.
!>          Cette valeur est retournée comme première entrée du tableau Z, et
!>          aucun message d'erreur lié à NZC n'est émis par XERBLA.

!>          ISUPPZ est un tableau INTEGER, dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ème vecteur propre calculé
!>          n'est non nul que dans les éléments ISUPPZ( 2*i-1 ) à

!>

TRYRAC

!>          TRYRAC est LOGICAL
!>          Si TRYRAC = .TRUE., indique que le code doit vérifier si
!>          la matrice tridiagonale définit ses valeurs propres avec une haute
!>          précision relative. Si c'est le cas, le code utilise des
!>          algorithmes préservant la précision relative qui peuvent être (un peu)
!>          plus lents selon la matrice.
!>          Si la matrice ne définit pas ses valeurs propres avec une haute
!>          précision relative, le code peut utiliser des algorithmes potentiellement
!>          plus rapides.
!>          Si TRYRAC = .FALSE., le code n'est pas tenu de garantir
!>          des valeurs propres relativement précises et peut utiliser les techniques
!>          les plus rapides possibles.
!>          En sortie, TRYRAC sera mis à .FALSE. si la matrice
!>          ne définit pas ses valeurs propres avec une haute précision relative.
!>
