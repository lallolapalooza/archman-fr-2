statvfs(3) Manuel des fonctions de bibliothèque statvfs(3)

NOM

statvfs, fstatvfs — obtenir des statistiques sur le système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/statvfs.h>
int statvfs(const char *restrict path, struct statvfs *restrict buf);
int fstatvfs(int fd, struct statvfs *buf);

DESCRIPTION

La fonction statvfs() renvoie des informations sur un système de fichiers monté. path est le chemin d'accès à n'importe quel fichier dans le système de fichiers monté. buf est un pointeur vers une structure statvfs définie approximativement comme suit :


struct statvfs {
    unsigned long  f_bsize;    /* Taille des blocs du système de fichiers */
    unsigned long  f_frsize;   /* Taille des fragments */
    fsblkcnt_t     f_blocks;   /* Taille du système de fichiers en unités de f_frsize */
    fsblkcnt_t     f_bfree;    /* Nombre de blocs libres */
    fsblkcnt_t     f_bavail;   /* Nombre de blocs libres pour les utilisateurs non privilégiés */
    fsfilcnt_t     f_files;    /* Nombre d'inodes */
    fsfilcnt_t     f_ffree;    /* Nombre d'inodes libres */
    fsfilcnt_t     f_favail;   /* Nombre d'inodes libres pour les utilisateurs non privilégiés */
    unsigned long  f_fsid;     /* Identifiant du système de fichiers */
    unsigned long  f_flag;     /* Indicateurs de montage */
    unsigned long  f_namemax;  /* Longueur maximale d'un nom de fichier */
};

Ici, les types fsblkcnt_t et fsfilcnt_t sont définis dans <sys/types.h>. Tous deux étaient auparavant des unsigned long.

Le champ f_flag est un masque de bits indiquant diverses options qui ont été utilisées lors du montage de ce système de fichiers. Il contient zéro ou plusieurs des indicateurs suivants :

ST_MANDLOCK
Le verrouillage obligatoire est autorisé sur le système de fichiers (voir fcntl(2)).
ST_NOATIME
Ne pas mettre à jour les temps d'accès ; voir mount(2).
ST_NODEV
Interdire l'accès aux fichiers spéciaux de périphériques sur ce système de fichiers.
ST_NODIRATIME
Ne pas mettre à jour les temps d'accès des répertoires ; voir mount(2).
ST_NOEXEC
L'exécution de programmes est interdite sur ce système de fichiers.
ST_NOSUID
Les bits set-user-ID et set-group-ID sont ignorés par exec(3) pour les fichiers exécutables sur ce système de fichiers.
ST_RDONLY
Ce système de fichiers est monté en lecture seule.
ST_RELATIME
Mettre à jour atime par rapport à mtime/ctime ; voir mount(2).
ST_SYNCHRONOUS
Les écritures sont synchronisées immédiatement avec le système de fichiers (voir la description de O_SYNC dans open(2)).

Il n'est pas spécifié si tous les membres de la structure renvoyée ont des valeurs significatives sur tous les systèmes de fichiers.

fstatvfs() renvoie les mêmes informations sur un fichier ouvert référencé par le descripteur fd.

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
(statvfs()) L'autorisation de recherche est refusée pour une composante du préfixe du chemin de path. (Voir aussi path_resolution(7).)
EBADF
(fstatvfs()) fd n'est pas un descripteur de fichier ouvert valide.
EFAULT
Buf ou path pointe vers une adresse invalide.
EINTR
Cet appel a été interrompu par un signal ; voir signal(7).
EIO
Une erreur d'E/S s'est produite lors de la lecture depuis le système de fichiers.
ELOOP
(statvfs()) Trop de liens symboliques ont été rencontrés lors de la traduction de path.
ENAMETOOLONG
(statvfs()) path est trop long.
ENOENT
(statvfs()) Le fichier référencé par path n'existe pas.
ENOMEM
Mémoire noyau insuffisante disponible.
ENOSYS
Le système de fichiers ne prend pas en charge cet appel.
ENOTDIR
(statvfs()) Une composante du préfixe du chemin de path n'est pas un répertoire.
EOVERFLOW
Certaines valeurs étaient trop grandes pour être représentées dans la structure renvoyée.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
statvfs (), fstatvfs () Sécurité des threads MT-Safe

VERSIONS

Seuls les indicateurs ST_NOSUID et ST_RDONLY du champ f_flag sont spécifiés dans POSIX.1. Pour obtenir les définitions des indicateurs restants, il faut définir _GNU_SOURCE.

NOTES

Le noyau Linux dispose des appels système statfs(2) et fstatfs(2) pour prendre en charge cet appel de bibliothèque.

Les implémentations glibc de


pathconf(path, _PC_REC_XFER_ALIGN);
pathconf(path, _PC_ALLOC_SIZE_MIN);
pathconf(path, _PC_REC_MIN_XFER_SIZE);

utilisent respectivement les champs f_frsize, f_frsize et f_bsize renvoyés par un appel à statvfs() avec l'argument path.

Sous Linux, f_favail est toujours identique à f_ffree, et il n'existe aucun moyen pour un système de fichiers de signaler autrement. Ce n'est pas un problème, car il n'existe pas de systèmes de fichiers avec une réservation racine d'inodes.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

Avant glibc 2.13, statvfs() remplissait les bits du champ f_flag en parcourant les options de montage affichées dans /proc/mounts. Cependant, à partir de Linux 2.6.36, l'appel système sous-jacent statfs(2) fournit les informations nécessaires via le champ f_flags, et depuis glibc 2.13, la fonction statvfs() utilisera les informations de ce champ plutôt que de parcourir /proc/mounts.

VOIR AUSSI

statfs(2)

NAME

statvfs, fstatvfs - obtenir des informations sur l'utilisation du système de fichiers

LIBRARY

System V Interface (libc, -lc)

SYNTAXE

#include <sys/statvfs.h>

int statvfs(const char *pathname, struct statvfs *buf);
int fstatvfs(int fd, struct statvfs *buf);

DESCRIPTION

Les fonctions statvfs et fstatvfs retournent des informations sur un système de fichiers. statvfs opère sur le fichier référencé par le chemin d'accès pathname. fstatvfs opère sur un descripteur de fichier ouvert fd.

Les informations sont retournées dans la structure pointée par buf, qui contient au moins les membres suivants :

f_bsize
Taille des blocs d'E/S du système de fichiers.
f_frsize
Taille de fragment de transfert du système de fichiers. (La taille de bloc effective est souvent représentée par f_frsize et non par f_bsize).
f_blocks
Nombre total de blocs d'allocation dans le système de fichiers.
f_bfree
Nombre de blocs d'allocation libres dans le système de fichiers.
f_bavail
Nombre de blocs d'allocation disponibles pour les utilisateurs non privilégiés.
f_files
Nombre total d'inodes dans le système de fichiers.
f_ffree
Nombre d'inodes libres dans le système de fichiers.
f_favail
Nombre d'inodes disponibles pour les utilisateurs non privilégiés.
f_fsid
ID du système de fichiers. Cette structure de type fsid_t contient la valeur spécifique du système.
f_flag
Indicateurs généraux du système de fichiers. Les valeurs possibles sont :
ST_RDONLY
Le système de fichiers est en lecture seule.
ST_NOSUID
Le jeu SUID et le bit du noyau SGID sont ignorés.
f_namemax
f_postreadahead
Nombre d'octets à lire à l'avance pour chaque lecture.
f_postwcount
Nombre d'écritures à mettre en file d'attente pour chaque écriture.

Les membres f_frsize, f_blocks, f_bfree, f_bavail, f_files, f_ffree, et f_favail sont de type fsblkcnt_t et fsfilcnt_t, qui sont des types d'entiers sans signe.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fstatvfs : le descripteur de fichier fd n'est pas valide.
EFAULT
buf pointe vers une adresse mémoire invalide.
ELOOP
Trop de liens symboliques dans le chemin pathname.
ENAMETOOLONG
Le nom du fichier pathname est trop long.
ENOENT
Le fichier pathname n'existe pas ou pathname est une chaîne vide.
ENOTDIR
Un composant du chemin pathname n'est pas un répertoire.
ENOMEM
Mémoire insuffisante allouée.
EOVERFLOW
Une valeur de champ dans statvfs dépasse la taille du type de données.
EACCES
Permission de lecture refusée pour un composant du chemin.
EROFS
Le système de fichiers est en lecture seule.
ST_UNMOUNTED
Le chemin pathname est sur un système de fichiers démonté.
EPERM
Le répertoire parent n'a pas les permissions requises pour la création de liens symboliques.

ATTRIBUTS

Pour une explication des termes ci-dessous, voir attributes(7).

+-----------------+----------------------+
| Caractéristique | Valeur               |
+-----------------+----------------------+
| Interface C     | Vitesse              |
| Utilisation     | statvfs, fstatvfs    |
+-----------------+----------------------+

VERSIONS

Les fonctions statvfs et fstatvfs ont été introduites dans la bibliothèque glibc 2.1.

NOTES

Notez que les champs f_blocks, f_bfree, f_bavail, f_files, f_ffree et f_favail sont des nombres d'entiers sans signe. S'ils sont stockés dans des variables signées, ils peuvent être interprétés de manière incorrecte.

La valeur de f_favail n'est pas garantie d'être la même que celle de f_ffree sur tous les systèmes de fichiers. Elle peut être inférieure à f_ffree, car certains systèmes de fichiers réservent des inodes pour le superutilisateur.

Les champs f_postreadahead et f_postwcount ne sont pas définis dans POSIX.1-2001, mais ils sont présents dans le noyau Linux.

NORMES

Les fonctions statvfs et fstatvfs sont conformes à POSIX.1-2001.

HISTORIQUE

Les fonctions statvfs et fstatvfs sont apparues dans les systèmes BSD et ont été portées sous Linux.
