NAME

std::regex_constants - Regular expression syntax and match flags

SYNOPSIS

#include <regex>

Detailed Description

This section describes the various syntax and match flags that can be passed to the various regular expression functions. These flags are defined as members of the std::regex_constants namespace, within syntax_option_type and match_flag_type enumerations.

Enumeration Type Documentation

syntax_option_type std::regex_constants::awk [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by the AWK utility. This grammar is similar to the ECMAScript grammar, but with some minor differences.

syntax_option_type std::regex_constants::basic [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by POSIX basic regular expressions in IEEE Std 1003.1-2001, Portable Operating System Interface (POSIX), Base Definitions and Headers, Section 9, Regular Expressions.

syntax_option_type std::regex_constants::cased [inline], [constexpr]

Specifies that the matching of regular expressions against a character sequence shall be performed with regard to case.

syntax_option_type std::regex_constants:: ECMAScript [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by ECMAScript in ECMA-262, third edition, 1999. This is the default syntax.

syntax_option_type std::regex_constants::grep [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by POSIX utility grep in IEEE Std 1003.1-2001. This option is identical to syntax_option_type basic, except that newlines are treated as whitespace.

syntax_option_type std::regex_constants::extended [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by POSIX extended regular expressions in IEEE Std 1003.1-2001, Portable Operating System Interface (POSIX), Base Definitions and Headers, Section 9, Regular Expressions.

syntax_option_type std::regex_constants::egrep [inline], [constexpr]

Specifies that the grammar recognized by the regular expression engine is that used by POSIX utility grep when given the -E option in IEEE Std 1003.1-2001. This option is identical to syntax_option_type extended, except that newlines are treated as whitespace.

syntax_option_type std::regex_constants::icase [inline], [constexpr]

Specifies that the matching of regular expressions against a character sequence shall be performed without regard to case.

syntax_option_type std::regex_constants::multiline [inline], [constexpr]

Specifies that the ^ anchor matches at the beginning of a line, and the $ anchor matches at the end of a line, not only at the beginning/end of the input. Valid for the ECMAScript syntax, ignored otherwise.

Since

C++17

syntax_option_type std::regex_constants::nosubs [inline], [constexpr]

Specifies that when a regular expression is matched against a character container sequence, no sub-expression matches are to be stored in the supplied match_results structure.

syntax_option_type std::regex_constants::optimize [inline], [constexpr]

Specifies that the regular expression engine should pay more attention to the speed with which regular expressions are matched, and less to the speed with which regular expression objects are constructed. Otherwise it has no detectable effect on the program output.

match_flag_type std::regex_constants::format_sed [inline], [constexpr]

When a regular expression match is to be replaced by a new string, the new string is constructed using the rules used by the ECMAScript replace function in ECMA- 262 [Ecma International, ECMAScript Language Specification, Standard Ecma-262, third edition, 1999], part 15.5.4.11 String.prototype.replace. In addition, during search and replace operations all non-overlapping occurrences of the regular expression are located and replaced, and sections of the input that did not match the expression are copied unchanged to the output string.

Format strings (from ECMA-262 [15.5.4.11]):

  • $$ The dollar-sign itself ($)
  • $& The matched substring.
  • $` The portion of string that precedes the matched substring. This would be match_results::prefix().

NOM

std::regex_constants - Indicateurs de syntaxe et de correspondance d'expressions régulières

SYNOPSIS

#include <regex>

Description détaillée

Cette section décrit les divers indicateurs de syntaxe et de correspondance qui peuvent être passés aux différentes fonctions d'expressions régulières. Ces indicateurs sont définis comme membres de l'espace de noms std::regex_constants, au sein des énumérations syntax_option_type et match_flag_type.

Documentation du type énumération

syntax_option_type std::regex_constants::awk [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par l'utilitaire AWK. Cette grammaire est similaire à la grammaire ECMAScript, mais avec quelques différences mineures.

syntax_option_type std::regex_constants::basic [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par les expressions régulières de base POSIX dans IEEE Std 1003.1-2001, Portable Operating System Interface (POSIX), Base Definitions and Headers, Section 9, Regular Expressions.

syntax_option_type std::regex_constants::cased [inline], [constexpr]

Spécifie que la correspondance des expressions régulières avec une séquence de caractères doit être effectuée en tenant compte de la casse.

syntax_option_type std::regex_constants:: ECMAScript [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par ECMAScript dans ECMA-262, troisième édition, 1999. C'est la syntaxe par défaut.

syntax_option_type std::regex_constants::grep [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par l'utilitaire grep POSIX dans IEEE Std 1003.1-2001. Cette option est identique à syntax_option_type basic, sauf que les nouvelles lignes sont traitées comme des espaces blancs.

syntax_option_type std::regex_constants::extended [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par les expressions régulières étendues POSIX dans IEEE Std 1003.1-2001, Portable Operating System Interface (POSIX), Base Definitions and Headers, Section 9, Regular Expressions.

syntax_option_type std::regex_constants::egrep [inline], [constexpr]

Spécifie que la grammaire reconnue par le moteur d'expressions régulières est celle utilisée par l'utilitaire grep POSIX lorsqu'il reçoit l'option -E dans IEEE Std 1003.1-2001. Cette option est identique à syntax_option_type extended, sauf que les nouvelles lignes sont traitées comme des espaces blancs.

syntax_option_type std::regex_constants::icase [inline], [constexpr]

Spécifie que la correspondance des expressions régulières avec une séquence de caractères doit être effectuée sans tenir compte de la casse.

syntax_option_type std::regex_constants::multiline [inline], [constexpr]

Spécifie que l'ancre ^ correspond au début d'une ligne, et que l'ancre $ correspond à la fin d'une ligne, pas seulement au début/fin de l'entrée. Valide pour la syntaxe ECMAScript, ignoré sinon.

Depuis

C++17

syntax_option_type std::regex_constants::nosubs [inline], [constexpr]

Spécifie que lorsqu'une expression régulière est mise en correspondance avec une séquence de conteneurs de caractères, aucun résultat de sous-expression ne doit être stocké dans la structure match_results fournie.

syntax_option_type std::regex_constants::optimize [inline], [constexpr]

Spécifie que le moteur d'expressions régulières doit accorder plus d'attention à la vitesse de correspondance des expressions régulières, et moins à la vitesse de construction des objets d'expressions régulières. Sinon, cela n'a aucun effet détectable sur la sortie du programme.

match_flag_type std::regex_constants::match_not_bol [inline], [constexpr]

Le premier caractère de la séquence [first, last) est traité comme s'il n'était pas au début d'une ligne, de sorte que le caractère (^) dans l'expression régulière ne doit pas correspondre à [first, first).

match_flag_type std::regex_constants::match_not_eol [inline], [constexpr]

Le dernier caractère de la séquence [first, last) est traité comme s'il n'était pas à la fin d'une ligne, de sorte que le caractère ($) dans l'expression régulière ne doit pas correspondre à [last, last).

match_flag_type std::regex_constants::match_all [inline], [constexpr]

Toutes les correspondances sont recherchées.

match_flag_type std::regex_constants::match_any [inline], [constexpr]

Si plus d'une correspondance est possible, alors n'importe quelle correspondance est un résultat acceptable.

match_flag_type std::regex_constants::match_not_bow [inline], [constexpr]

L'expression \b n'est pas mise en correspondance avec la sous-séquence [first,first).

match_flag_type std::regex_constants::match_not_eow [inline], [constexpr]

L'expression \b ne doit pas être mise en correspondance avec la sous-séquence [last,last).

match_flag_type std::regex_constants::match_continuous [inline], [constexpr]

L'expression ne correspond qu'à une sous-séquence qui commence à first .

match_flag_type std::regex_constants::match_not_null [inline], [constexpr]

L'expression ne correspond pas à une séquence vide.

Référencé par std::regex_iterator< _Bi_iter, _Ch_type, _Rx_traits >::operator++().

match_flag_type std::regex_constants::match_prev_avail [inline], [constexpr]

--first est une position d'itérateur valide. Lorsque cet indicateur est défini, les indicateurs match_not_bol et match_not_bow sont ignorés par les algorithmes regex_match, regex_search et regex_replace, ainsi que par les itérateurs regex_iterator et regex_token_iterator.

Référencé par std::regex_iterator< _Bi_iter, _Ch_type, _Rx_traits >::operator++().

match_flag_type std::regex_constants::format_default [inline], [constexpr]

Les indicateurs de format par défaut. Ceci est équivalent à format_copy | format_sed.

match_flag_type std::regex_constants::format_copy [inline], [constexpr]

Lorsqu'une correspondance d'expression régulière doit être remplacée par une nouvelle chaîne, les sections de la séquence de conteneurs de caractères recherchée qui ne correspondent pas à l'expression régulière doivent être copiées dans la chaîne de sortie.

match_flag_type std::regex_constants::format_no_copy [inline], [constexpr]

Lors d'une opération de recherche et remplacement, les sections de la séquence de conteneurs de caractères recherchée qui ne correspondent pas à l'expression régulière ne doivent pas être copiées dans la chaîne de sortie.

match_flag_type std::regex_constants::format_first_only [inline], [constexpr]

Lorsqu'il est spécifié pendant une opération de recherche et remplacement, seule la première occurrence de l'expression régulière doit être remplacée.

match_flag_type std::regex_constants::format_sed [inline], [constexpr]

Lorsqu'une correspondance d'expression régulière doit être remplacée par une nouvelle chaîne, la nouvelle chaîne est construite en utilisant les règles utilisées par la fonction de remplacement de l'ECMAScript dans ECMA- 262 [Ecma International, ECMAScript Language Specification, Standard Ecma-262, third edition, 1999], partie 15.5.4.11 String.prototype.replace. De plus, lors des opérations de recherche et remplacement, toutes les occurrences non chevauchantes de l'expression régulière sont localisées et remplacées, et les sections de l'entrée qui ne correspondent pas à l'expression sont copiées inchangées dans la chaîne de sortie.

Chaînes de format (d'ECMA-262 [15.5.4.11]):

  • $$ Le signe dollar lui-même ($)
  • $& La sous-chaîne correspondante.
  • $` La partie de string qui précède la sous-chaîne correspondante. Ce serait match_results::prefix().
  • $' La partie de string qui suit la sous-chaîne correspondante. Ce serait match_results::suffix().

  • $nn La nn-ième capture, où nn est un nombre décimal à deux chiffres dans [01, 99]. Si nn <= match_results::size() et que la nième capture est indéfinie, utilisez une chaîne vide à la place.
