stretch(1) Étirement temporel de données sonores stretch(1)

NOM

stretch - outil d'étirement temporel pour données sonores

SYNTAXE

stretch [options] [entrée [sortie]]

DESCRIPTION

L'utilitaire stretch permet d'augmenter ou de diminuer la durée d'un flux de données audio sans affecter la hauteur tonale des données échantillonnées. Il utilise le vocodeur de phase pour obtenir cet effet, ce qui conduit généralement à de meilleurs résultats que les techniques du domaine temporel. Les données audio d'entrée peuvent être composées de plusieurs canaux, auquel cas la sortie en aura également.

À la fois sortie et entrée peuvent être '-', indiquant que les données du signal doivent être lues depuis stdin ou écrites dans stdout respectivement (Vous pouvez également omettre les noms de fichiers pour le même effet, en commençant par sortie). Dans les deux cas, le format d'échantillon est signé 16 bits little-endian (alias format CD).

Pour l'accès aux fichiers physiques, l'utilitaire utilise la bibliothèque sndfile. L'outil essaie de deviner le format de fichier de sortie prévu à partir de l'extension du nom de fichier ; de plus, vous pouvez spécifier la profondeur de bits de sortie (quantification) avec le paramètre -b (--bits).

L'outil n'est pas capable de remplacer directement le contenu du fichier d'entrée.

OPTIONS

L'invocation la plus simple de l'outil est :

stretch -t 1.5 infile.wav outfile.wav

Cet exemple étire infile.wav à 150 % de sa durée et écrit le résultat dans outfile.wav.

Options les plus utiles :

-t, --times <facteur d'étirement>
définit le rapport par lequel la durée du signal sonore est mise à l'échelle. Les valeurs extrêmes peuvent entraîner des artefacts audibles dans le signal de sortie, généralement perçus comme une modulation d'amplitude cyclique. Pour obtenir un rapport d'expansion/compression de temps exact, le produit de ce paramètre et du paramètre -o (--overlap) doit être une valeur entière.
-a, --amplify <facteur>
définit le facteur d'amplification linéaire pour le signal de sortie. La valeur par défaut est 1.0 .
-q, --quiet
rend l'utilitaire silencieux quant à ce qu'il fait.

Options de contrôle du traitement :

-f, --fft <longueur de la DFT>
définit la longueur de la DFT (transformée de Fourier discrète), qui devrait être une puissance de deux pour de meilleurs résultats. Des valeurs impaires peuvent amener l'utilitaire à planter. Des tailles de DFT plus grandes impliquent une meilleure résolution fréquentielle au prix d'une demande de calcul accrue. La valeur par défaut est 1024 échantillons.
-o, --overlap <chevauchement>
contrôle l'intervalle auquel la recomposition du signal a lieu. Des valeurs plus petites impliquent un résultat plus doux en échange d'une demande de calcul accrue. La valeur par défaut est 128 échantillons.

Options du signal d'entrée pipé :

Si l'entrée du signal provient de stdin, l'hypothèse par défaut concernant le format des données (autre que la convention mentionnée précédemment de 16 bits signés little-endian) est un audio à deux canaux avec un taux d'échantillonnage de 44,1 kHz. Les options suivantes remplacent celles-ci :

-c, --channels <nombre de canaux>
pas de surprise : 1 est mono, 2 stéréo, etc.
-r, --rate <taux d%27échantillonnage>
définit le taux d'échantillonnage.

Profondeur de bits de sortie :

-b, --bits <quantification>
définit la profondeur de bits de sortie (uniquement pour la sortie de fichier physique). 8, 16 ou 24 pour des entiers signés, 32 ou 64 pour des flottants. La valeur par défaut est 16 bits. (La précision interne est de 32 bits flottants.)
-l, --limit
cette option fait en sorte que l'utilitaire limite le signal de sortie pour qu'il reste dans la quantification de sortie ou dans la plage [-1,+1] si la sortie est au format flottant. L'utilisation de ce drapeau est fortement recommandée lorsque la sortie est au format d'échantillon entier (--bits inférieur à 32 ou sortie stdout).

Options d'information :

-h, --help
affiche les informations de version et une liste des formats/extensions de fichiers pris en charge, puis quitte.
-v, --version
affiche les informations de version, puis quitte.

EXEMPLES

Quelques exemples d'invocations de l'utilitaire, supposant toutes que les données source sont au format CD (échantillons signés 16 bits, stéréo, 44,1 kHz) :

stretch -o 100 -t 1.2 cdda.wav | aplay -fcd

étire cdda.wav à exactement 120 %, canalisant la sortie vers le programme aplay pour une lecture immédiate.

cat file.ogg | oggdec - | stretch -t.8 | aplay -fcd

lit un flux ogg, accéléré à 80 % de sa durée. Si vous préférez le mp3, une incantation équivalente est :

madplay -o raw:- file.mp3 | stretch -t.8 | aplay -f cd

BOGUES

Analyse des lignes de commande et retour d'erreurs médiocres. De nombreuses combinaisons de formats de fichiers de sortie et de quantifications sont non testées, tout comme le fonctionnement sur les systèmes big-endian. Le vocodeur de phase consomme beaucoup de cycles CPU.

AUTEURS
