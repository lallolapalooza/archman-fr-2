NOM

start_erl - Démarrer Erlang pour les systèmes embarqués sur les systèmes Windows

DESCRIPTION

Le programme start_erl est spécifique à Windows NT/2000/XP (et aux versions ultérieures de Windows). Bien qu'il existe des programmes du même nom sur d'autres plateformes, leur fonctionnalité est différente.

Ce programme est distribué sous forme compilée (dans <Erlang root>\erts-<version>\bin) et sous forme source (dans <Erlang root>\erts-<version>\src). Le but du code source est de faciliter la personnalisation du programme pour les besoins locaux, tels que la détection de redémarrage cyclique. Il existe également un fichier "make", écrit pour le programme nmake distribué avec Microsoft Visual C++. Ce programme peut cependant être compilé avec n'importe quel compilateur C Win32 (éventuellement avec des modifications mineures).

Ce programme facilite la gestion des versions sur les systèmes Windows. Le programme doit être appelé par le programme erlsrv, lire le fichier de données de la version start_erl.data et démarrer Erlang. Certaines options de start_erl sont ajoutées et supprimées par le gestionnaire de version lors de la mise à niveau avec redémarrage de l'émulateur (plus spécifiquement l'option -data).

start_erl [<options erl>] ++ [<options start_erl>]

Le programme start_erl dans sa forme originale reconnaît les options suivantes :

++

Obligatoire. Sépare les options de start_erl des options normales d'Erlang. Tout ce qui se trouve sur la ligne de commande avant ++ est interprété comme des options à envoyer au programme erl. Tout ce qui se trouve après ++ est interprété comme des options pour start_erl lui-même.

-reldir <racine de la version>

Obligatoire si la variable d'environnement RELDIR n'est pas spécifiée et si l'option -rootdir n'est pas spécifiée. Indique à start_erl où se trouve la racine de l'arbre de la version dans le système de fichiers (typiquement <Erlang root>\releases). Le fichier start_erl.data est attendu dans ce répertoire (sauf indication contraire). Si seule l'option -rootdir est spécifiée, le répertoire est supposé être <Erlang root>\releases.

-rootdir <répertoire racine Erlang>

Obligatoire si -reldir n'est pas spécifié et si RELDIR n'existe pas dans l'environnement. Ceci spécifie le répertoire racine d'installation d'Erlang (sous lequel se trouvent les répertoires lib, releases et erts-<Version>). Si seule -reldir (ou la variable d'environnement RELDIR) est spécifiée, la racine Erlang est supposée être le répertoire exactement un niveau au-dessus du répertoire de la version.

-data <nom du fichier de données>

Optionnel. Spécifie un fichier de données autre que start_erl.data dans le <racine de la version>. Il est spécifié par rapport à la <racine de la version> ou en absolu (y compris la lettre du lecteur, etc.). Cette option est utilisée par le gestionnaire de version lors de la mise à niveau et ne doit pas être utilisée en fonctionnement normal. Normalement, le fichier de données de la version ne doit pas porter un nom différent.

-bootflags <nom du fichier de drapeaux de démarrage>

Optionnel. Spécifie un nom de fichier relatif au répertoire de la version (c'est-à-dire le sous-répertoire de <racine de la version> où se trouvent le fichier .boot et autres). Le contenu de ce fichier est ajouté à la ligne de commande lors du démarrage d'Erlang. Cela permet de démarrer l'émulateur avec des options différentes pour des versions différentes.

Notes

•Comme le code source est distribué, il peut être facilement modifié pour accepter d'autres options. Le programme doit toujours accepter l'option -data avec la sémantique décrite ci-dessus pour que le gestionnaire de version fonctionne correctement.
•L'émulateur Erlang est trouvé en examinant les clés du registre pour la version de l'émulateur spécifiée dans le fichier de données de la version. Le nouvel émulateur doit être correctement installé avant la mise à niveau pour que cela fonctionne.
•Bien que le programme soit situé avec des fichiers spécifiques à la version de l'émulateur, il n'est pas censé être spécifique à la version de l'émulateur. Le gestionnaire de version ne modifie pas l'option -machine pour erlsrv lors du redémarrage de l'émulateur. Placez le programme start_erl (éventuellement personnalisé) de manière à ce qu'il ne soit pas écrasé lors de la mise à niveau.
•Les options par défaut du programme erlsrv ne sont pas suffisantes pour la gestion des versions. La machine démarrée par erlsrv doit être spécifiée comme le programme start_erl et les arguments doivent contenir ++ suivi des options souhaitées.
