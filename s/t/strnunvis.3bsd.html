NOM

unvis, strunvis, strnunvis, strunvisx, strnunvisx — décoder une représentation visuelle de caractères

BIBLIOTHÈQUE

bibliothèque « libbsd »

SYNTAXE

int
unvis(char *cp, int c, int *astate, int flag);

int
strunvis(char *dst, const char *src);

int
strnunvis(char *dst, size_t dlen, const char *src);

int
strunvisx(char *dst, const char *src, int flag);

int
strnunvisx(char *dst, size_t dlen, const char *src, int flag);

DESCRIPTION

Les fonctions unvis(), strunvis() et strunvisx() sont utilisées pour décoder une représentation visuelle de caractères, telle que produite par la fonction vis(3bsd), pour la ramener à sa forme originale.

La fonction unvis() est appelée avec des caractères successifs dans c jusqu'à ce qu'une séquence valide soit reconnue, moment où le caractère décodé est disponible dans le caractère pointé par cp.

La fonction strunvis() décode les caractères pointés par src dans le tampon pointé par dst. La fonction strunvis() copie simplement src vers dst, en décodant les séquences d'échappement en cours de route, et renvoie le nombre de caractères placés dans dst, ou -1 si une séquence d'échappement invalide a été détectée. La taille de dst doit être égale à la taille de src (c'est-à-dire qu'aucune expansion n'a lieu pendant le décodage).

La fonction strunvisx() fait la même chose que la fonction strunvis(), mais elle permet d'ajouter un indicateur qui spécifie le style avec lequel la chaîne src est encodée. Actuellement, les indicateurs supportés sont : VIS_HTTPSTYLE et VIS_MIMESTYLE.

La fonction unvis() implémente une machine à états qui peut être utilisée pour décoder un flux arbitraire d'octets. Tout l'état associé aux octets décodés est stocké à l'extérieur de la fonction unvis() (c'est-à-dire qu'un pointeur vers l'état est passé), de sorte que les appels décodant différents flux peuvent être librement entremêlés. Pour commencer à décoder un flux d'octets, initialisez d'abord un entier à zéro. Appelez unvis() avec chaque octet successif, accompagné d'un pointeur vers cet entier, et d'un pointeur vers un caractère de destination. La fonction unvis() a plusieurs codes de retour qui doivent être correctement gérés. Ce sont :

0 (zéro)
Un autre caractère est nécessaire ; rien n'a encore été reconnu.
UNVIS_VALID
Un caractère valide a été reconnu et est disponible à l'emplacement pointé par cp.
UNVIS_VALIDPUSH
Un caractère valide a été reconnu et est disponible à l'emplacement pointé par cp ; cependant, le caractère actuellement passé doit être passé à nouveau.
UNVIS_NOCHAR
Une séquence valide a été détectée, mais aucun caractère n'a été produit. Ce code de retour est nécessaire pour indiquer une rupture logique entre les caractères.
UNVIS_SYNBAD
Une séquence d'échappement invalide a été détectée, ou le décodeur est dans un état inconnu. Le décodeur est placé dans l'état initial.

Lorsque tous les octets du flux ont été traités, appelez unvis() une fois de plus avec l'indicateur défini sur UNVIS_END pour extraire tout caractère restant (le caractère passé est ignoré).

L'argument flag est également utilisé pour spécifier le style d'encodage de la source. S'il est défini sur VIS_HTTPSTYLE ou VIS_HTTP1808, unvis() décodera les chaînes d'URI comme spécifié dans la RFC 1808. S'il est défini sur VIS_HTTP1866, unvis() décodera les références d'entité et les références numériques de caractères comme spécifié dans la RFC 1866. S'il est défini sur VIS_MIMESTYLE, unvis() décodera les chaînes MIME Quoted-Printable comme spécifié dans la RFC 2045. S'il est défini sur VIS_NOESCAPE, unvis() ne décodera pas les caractères échappés par ‘\’.

Le fragment de code suivant illustre une utilisation correcte de unvis().

int state = 0;
char out;

while ((ch = getchar()) != EOF) {
again:
	switch(unvis(&out, ch, &state, 0)) {
	case 0:
	case UNVIS_NOCHAR:
		break;
	case UNVIS_VALID:
		(void)putchar(out);
		break;
	case UNVIS_VALIDPUSH:
		(void)putchar(out);
		goto again;
	case UNVIS_SYNBAD:
		errx(EXIT_FAILURE, "Mauvaise séquence de caractères !");
	}
}
if (unvis(&out, '\0', &state, UNVIS_END) == UNVIS_VALID)
	(void)putchar(out);

ERREURS

Les fonctions strunvis(), strnunvis(), strunvisx(), et strnunvisx() renverront -1 en cas d'erreur et définiront errno à :

[EINVAL]
Une séquence d'échappement invalide a été détectée, ou le décodeur est dans un état inconnu.

De plus, les fonctions strnunvis() et strnunvisx() peuvent également définir errno en cas d'erreur à :

[ENOSPC]
Pas assez d'espace pour effectuer la conversion.

HISTORIQUE

La fonction unvis() est apparue pour la première fois dans

ass="Ux">4.4BSD. Les fonctions strnunvis() et strnunvisx() sont apparues dans NetBSD 6.0.

BUGS

Les noms VIS_HTTP1808 et VIS_HTTP1866 sont incorrects. L'encodage en pourcentage a été défini dans la RFC 1738, la RFC originale pour les URL. La RFC 1866 définit HTML 2.0, une application de SGML, dont elle hérite des concepts de références de caractères numériques et de références d'entités.
