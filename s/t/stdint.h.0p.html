stdint.h(0P) Manuel du programmeur POSIX stdint.h(0P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

stdint.h — types entiers

SYNTAXE

#include <stdint.h>

DESCRIPTION

Certaines des fonctionnalités décrites dans cette page de référence étendent la norme ISO C. Les applications doivent définir la macro de test de fonctionnalité appropriée (voir le volume Interfaces système de POSIX.1‐2017, Section 2.2, L'environnement de compilation) pour rendre ces symboles visibles dans cet en-tête.

L'en-tête <stdint.h> déclare des ensembles de types entiers ayant des largeurs spécifiées, et définit des ensembles de macros correspondantes. Il définit également des macros qui spécifient les limites des types entiers correspondant aux types définis dans d'autres en-têtes standard.

Note :
La « largeur » d'un type entier est le nombre de bits utilisés pour stocker sa valeur dans un système binaire pur ; le type réel peut utiliser plus de bits que cela (par exemple, un type de 28 bits pourrait être stocké dans 32 bits de stockage réel). Un type signé de N bits a des valeurs dans la plage -2N-1 ou 1-2N-1 à 2N-1-1, tandis qu'un type non signé de N bits a des valeurs dans la plage 0 à 2N-1.

Les types sont définis dans les catégories suivantes :

*
Types entiers ayant des largeurs exactes spécifiées
*
Types entiers ayant au moins les largeurs spécifiées
*
Types entiers les plus rapides ayant au moins les largeurs spécifiées
*
Types entiers assez larges pour contenir des pointeurs vers des objets
*
Types entiers ayant la plus grande largeur

(Certains de ces types peuvent désigner le même type.)

Des macros correspondantes spécifient les limites des types déclarés et construisent des constantes appropriées.

Pour chaque type décrit ici que l'implémentation fournit, l'en-tête <stdint.h> déclare ce nom typedef et définit les macros associées. Inversement, pour chaque type décrit ici que l'implémentation ne fournit pas, l'en-tête <stdint.h> ne déclare pas ce nom typedef, et ne définit pas les macros associées. Une implémentation doit fournir les types décrits comme requis, mais n'est pas obligée de fournir les autres (décrits comme optionnels).

Types entiers

Lorsque les noms typedef ne différant que par l'absence ou la présence du u initial sont définis, ils désignent des types signés et non signés correspondants, comme décrit dans la norme ISO/IEC 9899:1999, Section 6.2.5 ; une implémentation fournissant l'un de ces types correspondants doit également fournir l'autre.

Dans les descriptions suivantes, le symbole N représente un entier décimal non signé sans zéros initiaux (par exemple, 8 ou 24, mais pas 04 ou 048).

*
Types entiers à largeur exacte

Le nom typedef intN_t désigne un type entier signé d'une largeur de N, sans bits de remplissage, et une représentation en complément à deux. Ainsi, int8_t désigne un type entier signé d'une largeur de 8 bits exactement.

Le nom typedef uintN_t désigne un type entier non signé d'une largeur de N. Ainsi, uint24_t désigne un type entier non signé d'une largeur de 24 bits exactement.

Les types suivants sont requis :

int8_t
int16_t
int32_t
uint8_t
uint16_t
uint32_t

Si une implémentation fournit des types entiers d'une largeur de 64 qui répondent à ces exigences, alors les types suivants sont requis : int64_t uint64_t

En particulier, ce sera le cas si l'un des éléments suivants est vrai :

--
L'implémentation prend en charge l'environnement de programmation _POSIX_V7_ILP32_OFFBIG et l'application est en cours de compilation dans l'environnement de programmation _POSIX_V7_ILP32_OFFBIG (voir le volume Utilitaires et shell de POSIX.1‐2017, c99, Environnements de programmation).
--
L'implémentation prend en charge l'environnement de programmation _POSIX_V7_LP64_OFF64 et l'application est en cours de compilation dans l'environnement de programmation _POSIX_V7_LP64_OFF64.
--
L'implémentation prend en charge l'environnement de programmation _POSIX_V7_LPBIG_OFFBIG et l'application est en cours de compilation dans l'environnement de programmation _POSIX_V7_LPBIG_OFFBIG.

Tous les autres types de cette forme sont optionnels.

*
Types entiers de largeur minimale

Le nom typedef int_leastN_t désigne un type entier signé d'une largeur d'au moins N, de telle sorte qu'aucun type entier signé de taille inférieure n'ait au moins la largeur spécifiée. Ainsi, int_least32_t désigne un type entier signé d'une largeur d'au moins 32 bits.

Le nom typedef uint_leastN_t désigne un type entier non signé d'une largeur d'au moins N, de telle sorte qu'aucun type entier non signé de taille inférieure n'ait au moins la largeur spécifiée. Ainsi, uint_least16_t désigne un type entier non signé d'une largeur d'au moins 16 bits.

Les types suivants sont requis : int_least8_t int_least16_t int_least32_t int_least64_t uint_least8_t uint_least16_t uint_least32_t uint_least64_t

Tous les autres types de cette forme sont optionnels.

*
Types entiers de largeur minimale les plus rapides

Chacun des types suivants désigne un type entier sur lequel il est généralement le plus rapide d'opérer parmi tous les types entiers ayant au moins la largeur spécifiée.

Le type désigné n'est pas garanti d'être le plus rapide à toutes fins utiles ; si l'implémentation n'a pas de raison claire de choisir un type plutôt qu'un autre, elle choisira simplement un type entier satisfaisant les exigences de signe et de largeur.

Le nom typedef int_fastN_t désigne le type entier signé le plus rapide d'une largeur d'au moins N. Le nom typedef uint_fastN_t désigne le type entier non signé le plus rapide d'une largeur d'au moins N.

Les types suivants sont requis : int_fast8_t int_fast16_t int_fast32_t int_fast64_t uint_fast8_t uint_fast16_t uint_fast32_t uint_fast64_t

Tous les autres types de cette forme sont optionnels.

*
Types entiers capables de contenir des pointeurs d'objets

Le type suivant désigne un type entier signé avec la propriété que tout pointeur valide vers void peut être converti en ce type, puis reconverti en un pointeur vers void, et le résultat sera égal au pointeur d'origine : intptr_t

Le type suivant désigne un type entier non signé avec la propriété que tout pointeur valide vers void peut être converti en ce type, puis reconverti en un pointeur vers void, et le résultat sera égal au pointeur d'origine : uintptr_t

Sur les systèmes conformes XSI, les types intptr_t et uintptr_t sont requis ; sinon, ils sont optionnels.

*
Types entiers de plus grande largeur

Le type suivant désigne un type entier signé capable de représenter toute valeur de tout type entier signé : intmax_t

Le type suivant désigne un type entier non signé capable de représenter toute valeur de tout type entier non signé : uintmax_t

Ces types sont requis.

Note :
Les applications peuvent tester les types optionnels en utilisant la macro de limite correspondante de la section Limites des types entiers à largeur spécifiée.

NAME

limits.h, inttypes.h — implementation-defined constants for integer types

SYNOPSIS

#include <limits.h>

#include <inttypes.h>

DESCRIPTION

The standard header limits.h defines macros that specify the minimum and maximum limits for the various integer types defined by the C language.

The standard header inttypes.h defines macros that expand to integer constant expressions suitable for use in initialization of objects that have integer types corresponding to types defined in the stdint.h header.

Integer Type Limits

The following macro names are defined by the limits.h header. Each macro name corresponds to a similar type name in Integer Types.

Each instance of any defined macro shall be replaced by a constant expression suitable for use in #if preprocessing directives, and this expression shall have the same type as would an expression that is an object of the corresponding type converted according to the integer promotions. Its implementation-defined value shall be equal to or greater in magnitude (absolute value) than the corresponding value given below, with the same sign, except where stated to be exactly the given value.

*
Limits of exact-width integer types
--
Minimum values of exact-width signed integer types:
{INTN_MIN}
Exactly -( 2^N-1 )
--
Maximum values of exact-width signed integer types:
{INTN_MAX}
Exactly 2^N-1 -1
--
Maximum values of exact-width unsigned integer types:
{UINTN_MAX}
Exactly 2^N -1
*
Limits of minimum-width integer types
--
Minimum values of minimum-width signed integer types:
{INT_LEASTN_MIN}
-( 2^N-1 -1)
--
Maximum values of minimum-width signed integer types:
{INT_LEASTN_MAX}
2^N-1 -1
--
Maximum values of minimum-width unsigned integer types:
{UINT_LEASTN_MAX}
2^N -1
*
Limits of fastest minimum-width integer types
--
Minimum values of fastest minimum-width signed integer types:
{INT_FASTN_MIN}
-( 2^N-1 -1)
--
Maximum values of fastest minimum-width signed integer types:
{INT_FASTN_MAX}
2^N-1 -1
--
Maximum values of fastest minimum-width unsigned integer types:
{UINT_FASTN_MAX}
2^N -1
*
Limits of integer types capable of holding object pointers
--
Minimum value of pointer-holding signed integer type:
{INTPTR_MIN}

--
Maximum value of pointer-holding signed integer type:
{INTPTR_MAX}
2^15 -1
--
Maximum value of pointer-holding unsigned integer type:
{UINTPTR_MAX}
2^16 -1
*
Limits of greatest-width integer types
--
Minimum value of greatest-width signed integer type:
{INTMAX_MIN}
-( 2^63 -1)
--
Maximum value of greatest-width signed integer type:
{INTMAX_MAX}
2^63 -1
--
Maximum value of greatest-width unsigned integer type:
{UINTMAX_MAX}
2^64 -1

Limits of Other Integer Types

The following macros specify the minimum and maximum limits of integer types corresponding to types defined in other standard headers.

Each instance of these macros shall be replaced by a constant expression suitable for use in #if preprocessing directives, and this expression shall have the same type as would an expression that is an object of the corresponding type converted according to the integer promotions. Its implementation-defined value shall be equal to or greater in magnitude (absolute value) than the corresponding value given below, with the same sign.

If sig_atomic_t (see the <signal.h> header) is defined as a signed integer type, the value of {SIG_ATOMIC_MIN} shall be no greater than -127 and the value of {SIG_ATOMIC_MAX} shall be no less than 127; otherwise, sig_atomic_t shall be defined as an unsigned integer type, and the value of {SIG_ATOMIC_MIN} shall be 0 and the value of {SIG_ATOMIC_MAX} shall be no less than 255.

If wchar_t (see the <stddef.h> header) is defined as a signed integer type, the value of {WCHAR_MIN} shall be no greater than -127 and the value of {WCHAR_MAX} shall be no less than 127; otherwise, wchar_t shall be defined as an unsigned integer type, and the value of {WCHAR_MIN} shall be 0 and the value of {WCHAR_MAX} shall be no less than 255.

If wint_t (see the <wchar.h> header) is defined as a signed integer type, the value of {WINT_MIN} shall be no greater than -32767 and the value of {WINT_MAX} shall be no less than 32767; otherwise, wint_t shall be defined as an unsigned integer type, and the value of {WINT_MIN} shall be 0 and the value of {WINT_MAX} shall be no less than 65535.

Macros for Integer Constant Expressions

The following macros expand to integer constant expressions suitable for initializing objects that have integer types corresponding to types defined in the <stdint.h> header. Each macro name corresponds to a similar type name listed under Minimum-width integer types and Greatest-width integer types.

Each invocation of one of these macros shall expand to an integer constant expression suitable for use in #if preprocessing directives. The type of the expression shall have the same type as would an expression that is an object of the corresponding type converted according to the integer promotions. The value of the expression shall be that of the argument.

The argument in any instance of these macros shall be an unsuffixed integer constant with a value that does not exceed the limits for the corresponding type.

*
Macros for minimum-width integer constant expressions

The macro INTN_C(value) shall expand to an integer constant expression corresponding to the type int_leastN_t. The macro UINTN_C(value) shall expand to an integer constant expression corresponding to the type uint_leastN_t. For example, if uint_least64_t is a name for the type unsigned long long, then UINT64_C(0x123) might expand to the integer constant 0x123ULL.

*
Macros for greatest-width integer constant expressions

The following macro expands to an integer constant expression having the value specified by its argument and the type intmax_t: INTMAX_C(value)

The following macro expands to an integer constant expression having the value specified by its argument and the type uintmax_t: UINTMAX_C(value)

None.

STANDARDS

The behavior of these headers is defined by the C standard. The specific names and values are implementation-defined.

HISTORY

The limits.h header appeared in AT&T Version 7 UNIX.

The inttypes.h header was introduced in the C99 standard.

AVAILABILITY

These headers are available on all systems derived from AT&T UNIX.

BUGS

The limits for sig_atomic_t, wchar_t, and wint_t are only guaranteed to be at least 255, 255, and 65535, respectively. Some implementations may provide larger limits.

JUSTIFICATION

L'en-tête <stdint.h> est un sous-ensemble de l'en-tête <inttypes.h> plus adapté à une utilisation dans des environnements indépendants (freestanding), qui pourraient ne pas prendre en charge les fonctions d'entrée/sortie formatées. Dans certains environnements, si le support de conversion formatée n'est pas souhaité, l'utilisation de cet en-tête au lieu de l'en-tête <inttypes.h> évite de définir un si grand nombre de macros.

En conséquence de l'ajout de int8_t, les éléments suivants sont vrais :

*
Un octet (byte) fait exactement 8 bits.
*
{CHAR_BIT} a la valeur 8, {SCHAR_MAX} a la valeur 127, {SCHAR_MIN} a la valeur -128, et {UCHAR_MAX} a la valeur 255.

(La norme POSIX exige explicitement un caractère de 8 bits et une arithmétique en complément à deux.)

ORIENTATIONS FUTURES

Des noms de typedef commençant par int ou uint et se terminant par _t pourraient être ajoutés aux types définis dans l'en-tête <stdint.h>. Des noms de macros commençant par INT ou UINT et se terminant par _MAX, _MIN, ou _C pourraient être ajoutés aux macros définies dans l'en-tête <stdint.h>.
