strftime(3) Manuel des fonctions de bibliothèque strftime(3)

NOM

strftime - formater la date et l'heure

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <time.h>
size_t strftime(size_t max;
                char s[restrict max], size_t max,
                const char *restrict format,
                const struct tm *restrict tm);
size_t strftime_l(size_t max;
                char s[restrict max], size_t max,
                const char *restrict format,
                const struct tm *restrict tm,
                locale_t locale);

DESCRIPTION

La fonction strftime() formate l'heure décomposée tm selon la spécification de format format et place le résultat dans le tableau de caractères s de taille max. La structure de temps décomposée tm est définie dans <time.h>. Voir aussi ctime(3).

La spécification de format est une chaîne terminée par un octet nul et peut contenir des séquences de caractères spéciales appelées spécifications de conversion, chacune introduite par un caractère '%' et terminée par un autre caractère connu sous le nom de caractère spécificateur de conversion. Toutes les autres séquences de caractères sont des séquences de caractères ordinaires.

Les caractères des séquences de caractères ordinaires (y compris l'octet nul) sont copiés verbatim de format vers s. Cependant, les caractères des spécifications de conversion sont remplacés comme indiqué dans la liste ci-dessous. Dans cette liste, les champs employés de la structure tm sont également indiqués.

%a
Le nom abrégé du jour de la semaine selon la locale actuelle. (Calculé à partir de tm_wday.) (Les noms spécifiques utilisés dans la locale actuelle peuvent être obtenus en appelant nl_langinfo(3) avec ABDAY{1–7} comme argument.)
%A
Le nom complet du jour de la semaine selon la locale actuelle. (Calculé à partir de tm_wday.) (Les noms spécifiques utilisés dans la locale actuelle peuvent être obtenus en appelant nl_langinfo(3) avec DAY{1–7} comme argument.)
%b
Le nom abrégé du mois selon la locale actuelle. (Calculé à partir de tm_mon.) (Les noms spécifiques utilisés dans la locale actuelle peuvent être obtenus en appelant nl_langinfo(3) avec ABMON{1–12} comme argument.)
%B
Le nom complet du mois selon la locale actuelle. (Calculé à partir de tm_mon.) (Les noms spécifiques utilisés dans la locale actuelle peuvent être obtenus en appelant nl_langinfo(3) avec MON{1–12} comme argument.)
%c
La représentation préférée de la date et de l'heure pour la locale actuelle. (Le format spécifique utilisé dans la locale actuelle peut être obtenu en appelant nl_langinfo(3) avec D_T_FMT comme argument pour la spécification de conversion %c, et avec ERA_D_T_FMT pour la spécification de conversion %Ec.) (Dans la locale POSIX, ceci est équivalent à %a %b %e %H:%M:%S %Y.)
%C
Le numéro du siècle (année/100) sous forme d'entier à 2 chiffres. (SU) (La spécification de conversion %EC correspond au nom de l'ère.) (Calculé à partir de tm_year.)
%d
Le jour du mois sous forme de nombre décimal (plage 01 à 31). (Calculé à partir de tm_mday.)
%D
Équivalent à %m/%d/%y. (Beurk — pour les Américains seulement. Les Américains doivent noter que dans d'autres pays, %d/%m/%y est assez courant. Cela signifie que dans un contexte international, ce format est ambigu et ne devrait pas être utilisé.) (SU)
%e
Comme %d, le jour du mois sous forme de nombre décimal, mais un zéro initial est remplacé par un espace. (SU) (Calculé à partir de tm_mday.)
%E
Modificateur : utiliser un format alternatif (« basé sur l'ère »); voir ci-dessous. (SU)
%F
Équivalent à %Y-%m-%d (le format de date ISO 8601). (C99)
%G
L'année basée sur la semaine ISO 8601 (voir NOTES) avec le siècle sous forme de nombre décimal. L'année à 4 chiffres correspondant au numéro de semaine ISO (voir %V). Ceci a le même format et la même valeur que %Y, sauf que si le numéro de semaine ISO appartient à l'année précédente ou suivante, cette année est utilisée à la place. (TZ) (Calculé à partir de tm_year, tm_yday et tm_wday.)
%g
Comme %G, mais sans le siècle, c'est-à-dire avec une année à 2 chiffres (00–99). (TZ) (Calculé à partir de tm_year, tm_yday et tm_wday.)
%h
Équivalent à %b. (SU)
%H
L'heure sous forme de nombre décimal utilisant une horloge de 24 heures (plage 00 à 23). (Calculé à partir de tm_hour.)
%I
L'heure sous forme de nombre décimal utilisant une horloge de 12 heures (plage 01 à 12). (Calculé à partir de tm_hour.)
%j
Le jour de l'année sous forme de nombre décimal (plage 001 à 366). (Calculé à partir de tm_yday.)
%k
L'heure (horloge de 24 heures) sous forme de nombre décimal (plage 0 à 23) ; les chiffres uniques sont précédés d'un espace. (Voir aussi %H.) (Calculé à partir de tm_hour.) (TZ)
%l
L'heure (horloge de 12 heures) sous forme de nombre décimal (plage 1 à 12) ; les chiffres uniques sont précédés d'un espace. (Voir aussi %I.) (Calculé à partir de tm_hour.) (TZ)
%m
Le mois sous forme de nombre décimal (plage 01 à 12). (Calculé à partir de tm_mon.)
%M
La minute sous forme de nombre décimal (plage 00 à 59). (Calculé à partir de tm_min.)
%n
Un caractère de nouvelle ligne. (SU)
%O
Modificateur : utiliser des symboles numériques alternatifs; voir ci-dessous. (SU)
%p
Soit "AM" soit "PM" selon la valeur de temps donnée, ou les chaînes correspondantes pour la locale actuelle. Midi est traité comme "PM" et minuit comme "AM". (Calculé à partir de tm_hour.) (Les représentations de chaînes spécifiques utilisées pour "AM" et "PM" dans la locale actuelle peuvent être obtenues en appelant nl_langinfo(3) avec AM_STR et PM_STR, respectivement.)
%P
Comme %p mais en minuscules : "am" ou "pm" ou une chaîne correspondante pour la locale actuelle. (Calculé à partir de tm_hour.) (GNU)
%r
L'heure en notation a.m. ou p.m. (SU) (Le format spécifique utilisé dans la locale actuelle peut être obtenu en appelant nl_langinfo(3) avec T_FMT_AMPM comme argument.) (Dans la locale POSIX, ceci est équivalent à %I:%M:%S %p.)
%R
L'heure en notation 24 heures (%H:%M). (SU) Pour une version incluant les secondes, voir %T ci-dessous.
%s
Le nombre de secondes depuis l'Epoch, 1970-01-01 00:00:00 +0000 (UTC). (TZ) (Calculé à partir de mktime(tm).)
%S
La seconde sous forme de nombre décimal (plage 00 à 60). (La plage va jusqu'à 60 pour permettre les secondes intercalaires occasionnelles.) (Calculé à partir de tm_sec.)
%t
Un caractère de tabulation. (SU)
%T
L'heure en notation 24 heures (%H:%M:%S). (SU)
%u
Le jour de la semaine sous forme décimale, plage 1 à 7, lundi étant 1. Voir aussi %w. (Calculé à partir de tm_wday.) (SU)
%U
Le numéro de semaine de l'année en cours sous forme de nombre décimal, plage 00 à 53, commençant par le premier dimanche comme premier jour de la semaine 01. Voir aussi %V et %W. (Calculé à partir de tm_yday et tm_wday.)
%V
Le numéro de semaine ISO 8601 (voir NOTES) de l'année en cours sous forme de nombre décimal, plage 01 à 53, où la semaine 1 est la première semaine qui a au moins 4 jours dans la nouvelle année. Voir aussi %U et %W. (Calculé à partir de tm_year, tm_yday et tm_wday.) (SU)
%w
Le jour de la semaine sous forme décimale, plage 0 à 6, dimanche étant 0. Voir aussi %u. (Calculé à partir de tm_wday.)
%W
Le numéro de semaine de l'année

CONFORMITÉ

La fonction strftime() est conforme à la norme POSIX.1-2017 et C99. Les spécifications de conversion %C, %D, %e, %F, %g, %G, %h, %k, %l, %n, %r, %R, %s, %t, %T, %u, %V, et %W sont des extensions.

La fonction strftime_l() est conforme à POSIX.1-2008.

NOTES

La structure tm est définie dans <time.h> et contient au moins les champs suivants :

int tm_sec;     /* secondes, 0-60 */
int tm_min;     /* minutes, 0-59 */
int tm_hour;    /* heures, 0-23 */
int tm_mday;    /* jour du mois, 1-31 */
int tm_mon;     /* mois, 0-11 */
int tm_year;    /* années depuis 1900 */
int tm_wday;    /* jour de la semaine, 0-6 (dimanche=0) */
int tm_yday;    /* jour de l'année, 0-365 */
int tm_isdst;   /* indicateur d'heure d'été */

Les valeurs de tm_sec peuvent être jusqu'à 60 pour permettre les secondes intercalaires. Les valeurs de tm_hour, tm_mday, tm_min, tm_mon, tm_sec, et tm_wday sont déterminées de manière indéfinie si tm_isdst est négatif et la date ne tombe pas pendant l'heure d'été, ou si tm_isdst est positif et la date tombe pendant l'heure d'été.

Les spécifications de conversion avec le modificateur %E sont destinées à être utilisées avec des calendriers basés sur des ères, comme le calendrier japonais. La bibliothèque C implémente la prise en charge des ères en utilisant des modificateurs avec les spécifications de conversion suivantes :

Désignation de l'heure de l'ère.

Les spécifications de conversion avec le modificateur %O sont destinées à être utilisées avec des nombres formatés différemment dans la locale. La bibliothèque C implémente la prise en charge des symboles numériques alternatifs en utilisant des modificateurs avec les spécifications de conversion suivantes :

%V et %G sont utilisés pour le calcul de l'année ISO 8601 et du numéro de semaine ISO 8601. La semaine 1 de l'année est la première semaine de l'année qui contient au moins 4 jours de cette année. Par exemple, le 1er janvier 2009 était un jeudi, donc c'était dans la semaine 53 de 2008. Le 1er janvier 2010 était un vendredi, donc c'était dans la semaine 53 de 2009. Le 1er janvier 2011 était un samedi, donc c'était dans la semaine 52 de 2010.

La fonction strftime_l() est identique à strftime() sauf qu'elle utilise la locale spécifiée par l'argument locale.

La spécification de conversion %s génère le nombre de secondes écoulées depuis l'Epoch (1er janvier 1970 à minuit UTC). Elle est souvent utilisée pour le horodatage Unix.

Si max est zéro, s est un pointeur nul, ou si une écriture dans s dépasse la taille max, la chaîne résultante est tronquée. Si la chaîne résultante, y compris l'octet nul final, est plus longue que max octets, 0 est retourné et le contenu de s est indéfini. Sinon, le nombre d'octets stockés dans s, y compris l'octet nul final, est retourné.

Si l'une des spécifications de conversion inconnue est rencontrée, elle est copiée telle quelle.

Les caractères utilisés pour les noms des jours et des mois, ainsi que le format de date/heure préféré, sont définis par la variable d'environnement LC_TIME dans la catégorie LC_TIME de la locale.

ERREURS

La fonction strftime() ne définit pas errno.

EXEMPLES

       #include <time.h>
       #include <stdio.h>

       int
       main(void)
       {
               time_t t = time(NULL);
               struct tm tm = *localtime(&t);
               char buf[100];

               strftime(buf, sizeof(buf), "je suis ne le %d/%m/%Y", &tm);
               printf("%s\n", buf);

               strftime(buf, sizeof(buf), "il est %I:%M:%S %p", &tm);
               printf("%s\n", buf);

               return 0;
       }

Certaines spécifications de conversion peuvent être modifiées en précédant le caractère spécificateur de conversion par le modificateur E ou O pour indiquer qu'un format alternatif doit être utilisé. Si le format alternatif ou la spécification n'existe pas pour la locale actuelle, le comportement sera comme si la spécification de conversion non modifiée avait été utilisée. (SU) Le Single UNIX Specification mentionne %Ec, %EC, %Ex, %EX, %Ey, %EY, %Od, %Oe, %OH, %OI, %Om, %OM, %OS, %Ou, %OU, %OV, %Ow, %OW, %Oy, où l'effet du modificateur O est d'utiliser des symboles numériques alternatifs (par exemple, des chiffres romains), et celui du modificateur E est d'utiliser une représentation alternative dépendante de la locale. Les règles régissant la représentation des dates avec le modificateur E peuvent être obtenues en fournissant ERA comme argument à un nl_langinfo(3). Un exemple de telles formes alternatives est le système de calendrier de l'ère japonaise dans la locale ja_JP de glibc.

strftime_l() est équivalent à strftime(), sauf qu'il utilise la locale spécifiée au lieu de la locale actuelle. Le comportement est indéfini si locale est invalide ou LC_GLOBAL_LOCALE.

VALEUR DE RETOUR

À condition que la chaîne de résultat, y compris l'octet nul de terminaison, ne dépasse pas max octets, strftime() renvoie le nombre d'octets (à l'exclusion de l'octet nul de terminaison) placés dans le tableau s. Si la longueur de la chaîne de résultat (y compris l'octet nul de terminaison) dépasserait max octets, alors strftime() renvoie 0, et le contenu du tableau est indéfini.

Notez que la valeur de retour 0 n'indique pas nécessairement une erreur. Par exemple, dans de nombreuses locales, %p produit une chaîne vide. Une chaîne format vide produira également une chaîne vide.

Il existe des inclusions strictes entre l'ensemble des conversions données dans ANSI C (non marquées), celles données dans le Single UNIX Specification (marquées SU), celles données dans le paquet fuseau horaire d'Olson (marquées TZ), et celles données dans glibc (marquées GNU), à l'exception du fait que %+ n'est pas pris en charge dans glibc2. D'autre part, glibc2 possède plusieurs extensions supplémentaires. POSIX.1 fait uniquement référence à ANSI C ; POSIX.2 décrit sous date(1) plusieurs extensions qui pourraient également s'appliquer à strftime(). La conversion %F est dans C99 et POSIX.1-2001.

Dans SUSv2, le spécificateur %S permettait une plage de 00 à 61, pour permettre la possibilité théorique d'une minute incluant une seconde intercalaire double (il n'y a jamais eu une telle minute).

NOTES

Dates de semaine ISO 8601

%G, %g et %V produisent des valeurs calculées à partir de l'année basée sur la semaine définie par la norme ISO 8601. Dans ce système, les semaines commencent le lundi et sont numérotées de 01, pour la première semaine, à 52 ou 53, pour la dernière semaine. La semaine 1 est la première semaine où quatre jours ou plus tombent dans la nouvelle année (ou, de manière synonyme, la semaine 01 est : la première semaine de l'année qui contient un jeudi ; ou, la semaine qui contient le 4 janvier). Lorsque trois jours ou moins de la première semaine civile de la nouvelle année tombent dans cette année, le système basé sur la semaine ISO 8601 considère ces jours comme faisant partie de la semaine 52 ou 53 de l'année précédente. Par exemple, le 1er janvier 2010 est un vendredi, ce qui signifie que seulement trois jours de cette semaine civile tombent en 2010. Ainsi, le système basé sur la semaine ISO 8601 considère ces jours comme faisant partie de la semaine 53 (%V) de l'année 2009 (%G) ; la semaine 01 de l'année ISO 8601 2010 commence le lundi 4 janvier 2010. De même, les deux premiers jours de janvier 2011 sont considérés comme faisant partie de la semaine 52 de l'année 2010.

notes glibc

glibc fournit quelques extensions pour les spécifications de conversion. (Ces extensions ne sont pas spécifiées dans POSIX.1-2001, mais quelques autres systèmes fournissent des fonctionnalités similaires.) Entre le caractère '%' et le caractère spécificateur de conversion, un indicateur facultatif et une largeur de champ peuvent être spécifiés. (Ceux-ci précèdent les modificateurs E ou O, s'ils sont présents.)

Les caractères d'indicateur suivants sont autorisés :

_
(souligné) Remplit une chaîne numérique avec des espaces.
-
(tiret) Ne remplit pas une chaîne numérique.
0
Remplit une chaîne numérique avec des zéros même si le caractère spécificateur de conversion utilise un remplissage par espaces par défaut.
^
Convertit les caractères alphabétiques de la chaîne résultante en majuscules.
#
Inverse la casse de la chaîne résultante. (Cet indicateur ne fonctionne qu'avec certains caractères spécificateurs de conversion, et parmi ceux-ci, il n'est vraiment utile qu'avec %Z.)

Une spécification de largeur décimale facultative peut suivre l'indicateur (éventuellement absent). Si la taille naturelle du champ est inférieure à cette largeur, la chaîne résultante est remplie (à gauche) à la largeur spécifiée.

BOGUES

Si la chaîne de sortie dépasse max octets, errno n'est pas défini. Cela rend impossible de distinguer ce cas d'erreur des cas où la chaîne format produit légitimement une sortie de longueur nulle. POSIX.1-2001 ne spécifie aucune définition d'errno pour strftime().

Certaines versions boguées de gcc(1) se plaignent de l'utilisation de %c : warning: `%c' yields only last 2 digits of year in some locales. Bien sûr, les programmeurs sont encouragés à utiliser %c, car il donne la représentation de date et d'heure préférée. On rencontre toutes sortes d'obfuscations étranges pour contourner ce problème de gcc(1). Une solution relativement propre consiste à ajouter une fonction intermédiaire


size_t
my_strftime(char *s, size_t max, const char *fmt,
            const struct tm *tm)
{
    return strftime(s, max, fmt, tm);
}

Aujourd'hui, gcc(1) fournit l'option -Wno-format-y2k pour empêcher l'avertissement, de sorte que la solution de contournement ci-dessus n'est plus requise.

Format de date conforme à RFC 822 (avec une locale anglaise pour %a et %b)

strftime(3) - Manual Page

NAME

strftime, strftime_l - formater la date et l'heure

LIBRARY

Library libc, Link with -lc

SYNOPSIS

#include <time.h>

char *
strftime(char *restrict s, size_t max, const char *restrict format,
       const struct tm *restrict timeptr);
char *
strftime_l(char *restrict s, size_t max, const char *restrict format,
       const struct tm *restrict timeptr, locale_t locale);

DESCRIPTION

La fonction strftime remplit le tampon pointé par s avec une chaîne de caractères représentant la date et l'heure spécifiées par la structure tm timeptr. La chaîne est formatée selon la chaîne de format format.

La fonction strftime_l est identique à strftime, sauf qu'elle utilise la locale spécifiée par locale.

La chaîne de format format est une chaîne qui peut contenir zéro ou plusieurs directives, chacune commençant par un signe pour cent (%). Ces directives sont remplacées par des représentations appropriées de la date ou de l'heure. Les caractères qui ne sont pas des directives sont copiés sans modification dans la chaîne de résultat.

La fonction strftime (et strftime_l) place au maximum max octets dans le tampon s, y compris le caractère nul final. Si la chaîne résultante (y compris le nul final) ne peut pas tenir dans max octets, la fonction retourne 0, et le contenu de s est indéterminé.

Les directives de format prises en charge sont les suivantes :

%%
Un signe pour cent littéral.
%a
Le nom abrégé du jour de la semaine selon la locale. Pour la locale C, il s'agit de « Sun » pour dimanche, « Mon » pour lundi, etc.
%A
Le nom complet du jour de la semaine selon la locale. Pour la locale C, il s'agit de « Sunday » pour dimanche, « Monday » pour lundi, etc.
%b
Le nom abrégé du mois selon la locale. Pour la locale C, il s'agit de « Jan » pour janvier, « Feb » pour février, etc.
%B
Le nom complet du mois selon la locale. Pour la locale C, il s'agit de « January » pour janvier, « February » pour février, etc.
%c
La représentation appropriée de la date et de l'heure selon la locale.
%C
Le siècle (année divisée par 100, tronquée) selon la locale. (Par exemple, pour l'année 1999, le siècle est 19.)
%d
Le jour du mois sous forme de nombre décimal (01 à 31).
%D
La date au format %m/%d/%y.
%e
Le jour du mois sous forme de nombre décimal, avec un espace de tête pour les nombres inférieurs à 10. (Par exemple, « 1 » ou « 10 »).
%F
La date au format %Y-%m-%d.
%g
Les deux derniers chiffres de l'année ISO 8601 correspondant à la semaine de l'année %V.
%G
L'année ISO 8601 complète correspondant à la semaine de l'année %V.
%h
Identique à %b.
%H
L'heure (horloge de 24 heures) sous forme de nombre décimal (00 à 23).
%I
L'heure (horloge de 12 heures) sous forme de nombre décimal (01 à 12).
%j
Le jour de l'année sous forme de nombre décimal (001 à 366).
%m
Le mois sous forme de nombre décimal (01 à 12).
%M
La minute sous forme de nombre décimal (00 à 59).
%n
Un caractère de nouvelle ligne.
%p
Soit « AM », soit « PM » selon la locale. Si l'heure est inconnue, la chaîne est vide.
%P
Identique à %p, mais en minuscules. Soit « am », soit « pm » selon la locale.
%r
L'heure au format 12 heures (par exemple, 01 : 02 : 03 PM) selon la locale.
%R
L'heure au format %H:%M.
%S
La seconde sous forme de nombre décimal (00 à 60). La valeur 60 est autorisée pour tenir compte des secondes intercalaires.
%t
Un caractère de tabulation.
%T
L'heure au format %H:%M:%S.
%u
Le jour de la semaine sous forme de nombre décimal (1 pour lundi, ..., 7 pour dimanche).
%U
Le numéro de la semaine de l'année (dimanche comme premier jour de la semaine) sous forme de nombre décimal (00 à 53).
%V
Le numéro de la semaine ISO 8601 (lundi comme premier jour de la semaine) sous forme de nombre décimal (01 à 53).
%w
Le jour de la semaine sous forme de nombre décimal (0 pour dimanche, ..., 6 pour samedi).
%W
Le numéro de la semaine de l'année (lundi comme premier jour de la semaine) sous forme de nombre décimal (00 à 53).
%x
La représentation appropriée de la date selon la locale.
%X
La représentation appropriée de l'heure selon la locale.
%y
Les deux derniers chiffres de l'année sous forme de nombre décimal (00 à 99).
%Y
L'année sous forme de nombre décimal. (Par exemple, 1999).
%z
Le décalage horaire signé par rapport à UTC au format +HHMM ou -HHMM. Si le décalage horaire ne peut pas être déterminé, une chaîne vide est retournée.
%Z
Le fuseau horaire (par exemple, le nom abrégé du fuseau horaire) selon la locale. Si le fuseau horaire ne peut pas être déterminé, une chaîne vide est retournée.

Si une directive de format n'est pas reconnue, la directive est copiée sans modification dans la chaîne de résultat.

L'argument timeptr doit pointer vers une structure tm remplie, par exemple par localtime, gmtime ou mktime.

La locale C est utilisée par défaut, à moins que la locale ne soit modifiée par setlocale.

La fonction strftime_l utilise la locale spécifiée par l'argument locale. Pour utiliser la locale par défaut de la catégorie LC_TIME, locale doit être défini sur la valeur de LC_GLOBAL_LOCALE.

Les directives %C, %G, %g, %V sont définies par la norme ISO C11.

RETURN VALUE

Au succès, strftime et strftime_l retournent le nombre d'octets dans la chaîne de résultat, sans inclure le caractère nul de fin. En cas d'échec (par exemple, si la chaîne résultante ne rentre pas dans le tampon max), ils retournent 0.

ENVIRONMENT

LC_TIME : La catégorie de locale affecte les directives de format qui dépendent de la locale (%a, %A, %b, %B, %c, %p, %r, %x, %X, %Z).

ATTRIBUTES

Pour obtenir des explications sur les termes utilisés ci-dessous, voir attributes(7).

Interface avec l'appel système | Attrribut         | Valeur
------------------------------|-------------------|--------------------------
strftime()                    | Thread safety     | MT-Safe
strftime_l()                  | Thread safety     | MT-Safe

STANDARDS

La fonction strftime est conforme à la norme C99 et aux normes POSIX.1-2001 et POSIX.1-2008. La fonction strftime_l est conforme à POSIX.1-2008.

Les directives %C, %G, %g, %V, %z, %Z sont des extensions GNU.

HISTORY

La fonction strftime est apparue dans la norme C89.

La fonction strftime_l est apparue dans POSIX.1-2008.

NOTES

La chaîne de format format et la chaîne de résultat sont encodées en UTF-8.

La structure tm n'est pas forcément remplie pour une date et une heure cohérentes. Par exemple, une application pourrait remplir artificiellement les champs de la structure tm. Dans ce cas, strftime produira une sortie basée sur les valeurs fournies, sans validation.

Les directives %z et %Z peuvent produire des chaînes vides dans certaines locales et configurations. Par exemple, tzset peut ne pas être configuré, ou le noyau peut ne pas fournir d'informations de fuseau horaire. Voir tzset(3) pour plus de détails.

Pour utiliser des directives spécifiques à un langage, par exemple pour afficher des noms de mois ou de jours dans une langue autre que celle par défaut, vous devez configurer la locale appropriée en utilisant setlocale.

Le comportement des directives %V, %G et %g est basé sur la norme ISO 8601, où la semaine 01 est celle qui contient le premier jeudi de l'année.

La directive %s est obsolète et a été remplacée par %Y dans la norme C99.

Le tampon de sortie s doit être d'au moins max octets de longueur. Si vous ne savez pas quelle taille utiliser, vous pouvez allouer un tampon suffisamment grand (par exemple, 200 octets pour une utilisation générale). Si max est 0, s peut être un pointeur NULL et la fonction retournera la taille requise sans écrire dans le tampon.

BUGS

La norme POSIX exige que strftime retourne le nombre de caractères écrits, sans compter le caractère nul final. Cependant, l'implémentation GNU C Library et la plupart des autres implémentations POSIX retournent le nombre de caractères écrits, y compris le caractère nul final.

EXAMPLES

Cet exemple montre comment utiliser strftime pour formater la date et l'heure actuelles.

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int
main(int argc, char *argv[])
{
    char outstr[200];
    time_t t;
    struct tm *tmp;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s: <format-string>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    t = time(NULL);
    tmp = localtime(&t);
    if (tmp == NULL) {
        perror("localtime");
        exit(EXIT_FAILURE);
    }

    /*strftime renvoie 0 si la chaîne résultante ne rentre pas dans le tampon */
    if (strftime(outstr, sizeof(outstr), argv[1], tmp) == 0) {
        fprintf(stderr, "strftime returned 0\n");
        exit(EXIT_FAILURE);
    }

    printf("Result string is \"%s\"\n", outstr);

    exit(EXIT_SUCCESS);
}

Pour compiler cet exemple :

gcc -o example example.c

Pour l'exécuter avec un format spécifique, par exemple pour obtenir la date au format ISO 8601 :

./example "%G-%V-%u"

Ou pour obtenir l'heure au format 12 heures avec AM/PM :

./example "It is %I:%M:%S %p"
