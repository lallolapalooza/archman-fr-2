Description détaillée

template<typename_CharT,_typename_Traits>

Le concept de flux, tel qu'implémenté dans la bibliothèque C++ Standard, est construit sur une abstraction de streambuf. Les objets de flux (comme std::cin, std::cout) interagissent avec des objets streambuf pour effectuer des opérations réelles d'entrée et de sortie.
Un streambuf est une sorte de tampon. Il est responsable du transfert de données entre la mémoire (généralement un tableau) et un flux d'entrée ou de sortie. L'interface de streambuf est suffisamment abstraite pour permettre le fonctionnement avec des flux de fichiers, des flux de chaînes de caractères, des flux de console, etc.
L'interface de streambuf est basée sur une gestion des données via des pointeurs vers des zones de lecture et d'écriture. Ces zones sont définies par trois pointeurs : un pointeur de début, un pointeur actuel et un pointeur de fin. Les opérations d'entrée utilisent la zone de lecture, et les opérations de sortie utilisent la zone d'écriture.
Les opérations élémentaires sur les streambuf sont les suivantes :

  • sgetc : lit le caractère suivant dans le flux d'entrée.
  • sbumpc : lit le caractère suivant dans le flux d'entrée et avance le pointeur de lecture.
  • snextc : lit le caractère suivant dans le flux d'entrée et avance le pointeur de lecture au caractère suivant.
  • sputc : écrit un caractère dans le flux de sortie.
  • sputbackc : remet un caractère dans le flux d'entrée (utile pour la déconstruction).
  • sungetc : avance le pointeur de lecture d'un caractère (pour une utilisation avec sputbackc).
  • xsgetn : lit plusieurs caractères dans le flux d'entrée.
  • xsputn : écrit plusieurs caractères dans le flux de sortie.
  • seekoff et seekpos : modifient la position actuelle dans le flux.
  • sync : synchronise le tampon avec le flux sous-jacent (par exemple, force l'écriture des données restantes).
  • imbue : associe une locale au streambuf pour la gestion des caractères et des conversions.

Les fonctions publiques (par exemple, pubsetbuf, pubseekoff, pubsync) sont des interfaces publiques qui appellent les fonctions virtuelles protégées correspondantes (par exemple, setbuf, seekoff, sync). Les classes dérivées redéfinissent ces fonctions virtuelles pour implémenter le comportement spécifique du tampon.
Les streambuf eux-mêmes ne gèrent pas la mémoire allouée pour les tampons. C'est la responsabilité des classes dérivées (comme basic_filebuf et basic_stringbuf) de gérer l'allocation et la désallocation des tampons. Le destructeur de basic_streambuf est virtuel pour permettre une destruction correcte des objets dérivés.

Paramètres de template

_CharT Type de flux de caractères.
_Traits Traits pour le type de caractère, par défaut char_traits<_CharT>.

Ceci est une classe de base. Les tampons de flux dérivés contrôlent chacun une paire de séquences de caractères : une pour l'entrée et une pour la sortie.

La section [27.5.1] de la norme décrit les exigences et le comportement des classes de tampons de flux. Cette section (trois paragraphes) est reproduite ici, pour plus de simplicité et d'exactitude.

1.
Les tampons de flux peuvent imposer diverses contraintes aux séquences qu'ils contrôlent. Certaines contraintes sont :
•
La séquence d'entrée contrôlée peut ne pas être lisible.
•
La séquence de sortie contrôlée peut ne pas être inscriptible.
•
Les séquences contrôlées peuvent être associées au contenu d'autres représentations de séquences de caractères, telles que des fichiers externes.
•
Les séquences contrôlées peuvent prendre en charge des opérations directement vers ou depuis des séquences associées.
•
Les séquences contrôlées peuvent imposer des limitations sur la manière dont le programme peut lire des caractères à partir d'une séquence, écrire des caractères dans une séquence, remettre des caractères dans une séquence d'entrée ou modifier la position du flux.
2.
Chaque séquence est caractérisée par trois pointeurs qui, s'ils ne sont pas nuls, pointent tous vers le même objet tableau charT. Le tableau objet représente, à tout moment, une (sous)séquence de caractères de la séquence. Les opérations effectuées sur une séquence modifient les valeurs stockées dans ces pointeurs, effectuent des lectures et écritures directement vers ou depuis des séquences associées, et modifient la position du flux et l'état de conversion si nécessaire pour maintenir cette relation de sous-séquence. Les trois pointeurs sont :
•
le pointeur de début, ou adresse du plus petit élément du tableau (appelé xbeg ici) ;
•
le pointeur suivant, ou adresse du prochain élément qui est un candidat actuel pour la lecture ou l'écriture (appelé xnext ici) ;
•
le pointeur de fin, ou adresse du premier élément au-delà de la fin du tableau (appelé xend ici).
3.
Les contraintes sémantiques suivantes doivent toujours s'appliquer pour tout ensemble de trois pointeurs pour une séquence, en utilisant les noms de pointeurs donnés immédiatement ci-dessus :
•
Si xnext n'est pas un pointeur nul, alors xbeg et xend doivent également être des pointeurs non nuls pointant vers le même tableau charT, comme décrit ci-dessus ; sinon, xbeg et xend doivent également être nuls.
•
Si xnext n'est pas un pointeur nul et xnext < xend pour une séquence de sortie, alors une position d'écriture est disponible. Dans ce cas, *xnext doit être assignable en tant que prochain élément à écrire (pour placer, ou stocker une valeur de caractère, dans la séquence).
•
Si xnext n'est pas un pointeur nul et xbeg < xnext pour une séquence d'entrée, alors une position de remise en mémoire est disponible. Dans ce cas, xnext[-1] doit avoir une valeur définie et est le prochain élément (précédent) dans lequel stocker un caractère qui est remis dans la séquence d'entrée.
•
Si xnext n'est pas un pointeur nul et xnext< xend pour une séquence d'entrée, alors une position de lecture est disponible. Dans ce cas, *xnext doit avoir une valeur définie et est le prochain élément à lire (pour obtenir, ou obtenir une valeur de caractère, à partir de la séquence).

template<typename _CharT, typename _Traits> virtual int_type std::basic_streambuf< _CharT, _Traits >::overflow (int_type __c = traits_type::eof()) [inline], [protected], [virtual]

Consomme les données du tampon ; écrit dans la séquence contrôlée.

Paramètres

__c Un caractère supplémentaire à consommer.

Retourne

eof() pour indiquer un échec, autre chose (généralement __c, ou not_eof())

Informellement, cette fonction est appelée lorsque le tampon de sortie est plein (ou n'existe pas, car la mise en tampon n'a pas besoin d'être effectivement faite). Si un tampon existe, il est consommé, avec un certain effet sur la séquence contrôlée. (Typiquement, le tampon est écrit dans la séquence verbatim.) Dans les deux cas, le caractère c est également écrit, si __c n'est pas eof().

Pour une définition formelle de cette fonction, consultez un bon texte tel que Langer & Kreft, ou [27.5.2.4.5]/3-7.

Un streambuf de sortie fonctionnel peut être créé en ne redéfinissant que cette fonction (aucune zone tampon ne sera utilisée).

Note

La version de la classe de base ne fait rien, renvoie eof().
