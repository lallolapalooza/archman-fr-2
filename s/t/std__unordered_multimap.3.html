template<typename _Key, typename _Tp, typename _Hash = hash<_Key>, typename _Pred = equal_to<_Key>, typename _Alloc = allocator<std::pair<const _Key, _Tp>>>

class std::unordered_multimap< _Key, _Tp, _Hash, _Pred, _Alloc >"Un conteneur standard composé de clés équivalentes (pouvant éventuellement contenir plusieurs instances de chaque valeur de clé) qui associe des valeurs d'un autre type aux clés.

Depuis

C++11

Paramètres de modèle

_Key Type des objets clés.
_Tp Type des objets mappés.
_Hash Type de l'objet fonction de hachage, par défaut hash<_Value>.
_Pred Type de l'objet fonction prédicat, par défaut equal_to<_Value>.
_Alloc Type de l'allocateur, par défaut std::allocator<std::pair<const _Key, _Tp>>.

Répond aux exigences d'un conteneur, et d'un conteneur associatif non ordonné.

Le type de valeur résultant du conteneur est std::pair<const _Key, _Tp>.

La base est _Hashtable, distribuée au moment de la compilation via l'alias de modèle __ummap_hashtable.

Description détaillée

La spécialisation de modèle std::unordered_multimap est un conteneur associatif qui stocke des éléments de type std::pair<const _Key, _Tp>. Contrairement à std::unordered_map, il peut y avoir plusieurs éléments avec la même clé. Les éléments ne sont pas triés. Les recherches, insertions et suppressions prennent en moyenne un temps constant, et au pire un temps linéaire.

std::unordered_multimap est implémenté en utilisant une table de hachage. La complexité de chaque opération de membre est le temps moyen O(1), le temps pire cas O(N), où N est le nombre d'éléments dans le conteneur.

Il garantit la validité des pointeurs et références aux éléments lors de l'insertion, la suppression n'invalidera pas les pointeurs ou références aux éléments restants.

Il fournit une interface pour des opérations sur des conteneurs associatifs sans ordre, comme l'insertion, la recherche, la suppression, etc.
