NOM

str_to_gensio, str_to_gensio_child, gensio_acc_str_to_gensio - Créer un gensio à partir d'une chaîne

SYNTAXE

#include <gensio/gensio.h>

int str_to_gensio(const char *str,

struct gensio_os_funcs *o,
gensio_event cb, void *user_data,
struct gensio **io);
int str_to_gensio_child(struct gensio *child, const char *str,

struct gensio_os_funcs *o,
gensio_event cb, void *user_data,
struct gensio **io);
int gensio_acc_str_to_gensio(struct gensio_accepter *accepter,

const char *str, struct gensio_os_funcs *o,
gensio_event cb, void *user_data,
struct gensio **io);
int gensio_terminal_alloc(const char *gensiotype,

const void *gdata,
const char * const args[],
struct gensio_os_funcs *o,
gensio_event cb, void *user_data,
struct gensio **new_gensio);
int gensio_filter_alloc(const char *gensiotype,

struct gensio *child,
const char * const args[],
struct gensio_os_funcs *o,
gensio_event cb, void *user_data,
struct gensio **new_gensio);

DESCRIPTION

str_to_gensio alloue une nouvelle pile de gensio basée sur la chaîne fournie str.

str_to_gensio_child alloue une pile de gensio partielle et la superpose sur le child fourni. Notez que si l'enfant est déjà ouvert, vous devriez utiliser gesnio_open_nochild() pour ouvrir uniquement ce gensio. Ceci ne peut être utilisé que pour allouer des gensios de filtrage.

gensio_acc_str_to_gensio alloue un gensio basé sur l'accepteur fourni. La disponibilité et l'utilisation de ceci varient d'un gensio à l'autre, mais il peut être utilisé sur UDP pour créer un gensio qui utilise les ports UDP appartenant à l'accepteur. Ceci proviendra de la première adresse/port sur lequel l'accepteur se trouve pour TCP et UDP. Il se liera à toutes les adresses/ports pour SCTP. Pour utiliser ceci, vous devez spécifier une chaîne qui correspond exactement aux couches de l'accepteur. Donc, par exemple, si l'accepteur est "telnet,ssl(CA=x1,key=x2,cert=x3),sctp,3095", alors la chaîne doit être de la forme "telnet,ssl(CA=x2),sctp,otherserver,3820" Les couches sont exactement les mêmes, mais vous pouvez varier les options pour les couches.

Pour allouer directement des gensios, vous pouvez utiliser gensio_terminal_alloc et gensio_filter_alloc. Un gensio terminal est celui qui se trouve au bas de la pile. Le paramètre gdata dépend du gensio particulier. Par exemple, pour serialdev, c'est une chaîne spécifiant le périphérique et les paramètres série. Pour stdio, c'est un tableau argv. Voir gensio.5 sous "Allocation Directe" pour le gensio particulier et ce qu'est gdata.

Un gensio de filtre est un gensio qui a un enfant. Vous pouvez utiliser ces deux fonctions pour allouer une pile de gensio directement, sans utiliser le format de chaîne.

Les paramètres cb et user_data définissent une fonction qui sera appelée lorsque des événements arriveront sur le gensio. user_data n'est pas utilisé par la pile gensio elle-même, il est là pour l'utilisateur et peut être n'importe quoi que l'utilisateur souhaite. cb peut être NULL avant que le gensio ne soit ouvert, mais doit être défini avant son ouverture. En particulier, le cb n'a pas besoin d'être défini si d'autres gensios seront superposés sur lui à l'avenir, car les gensios superposés définiront les valeurs de cb et user_data.

Le nouveau gensio est retourné dans io. Il sera à l'état fermé.

VALEUR DE RETOUR

Zéro est retourné en cas de succès, ou une erreur gensio en cas d'échec.
