NOM

storescu - SCU de stockage DICOM (C-STORE)

SYNTAXE

storescu [options] peer port fichier-dcm...

DESCRIPTION

L'application storescu implémente un Utilisateur de Classe de Service (SCU) pour la Classe de Service de Stockage. Pour chaque fichier DICOM sur la ligne de commande, elle envoie un message C-STORE à un Fournisseur de Classe de Service de Stockage (SCP) et attend une réponse. L'application peut être utilisée pour transmettre des images DICOM et d'autres objets composites DICOM.

PARAMETRES

peer        nom d'hôte de l'homologue DICOM
port        numéro de port TCP/IP de l'homologue
fichier-dcm fichier ou répertoire DICOM à transmettre

NOTES

Balayage des répertoires

L'ajout de répertoires en tant que paramètre à la ligne de commande n'a de sens que si l'option --scan-directories est également donnée. Si les fichiers des répertoires fournis doivent être sélectionnés selon un modèle de nom spécifique (par exemple, en utilisant une correspondance de caractères génériques), l'option --scan-pattern doit être utilisée. Veuillez noter que ce modèle de fichier ne s'applique qu'aux fichiers des répertoires balayés et, si d'autres modèles sont spécifiés sur la ligne de commande en dehors de l'option --scan-pattern (par exemple, afin de sélectionner d'autres fichiers), ceux-ci ne s'appliquent pas aux répertoires spécifiés.

Des classes SOP de stockage et des syntaxes de transfert supplémentaires peuvent être utilisées avec les "profils de négociation d'association" (voir ci-dessous).

L'application storescu ne prend pas en charge la négociation étendue par défaut. Cependant, en utilisant un profil de négociation d'association approprié (voir ci-dessous), le support optionnel de la négociation étendue peut être ajouté à des classes SOP particulières.

Profils de négociation d'association et fichiers de configuration

storescu prend en charge un mécanisme flexible pour spécifier le comportement de négociation du réseau DICOM, basé sur des "profils de négociation d'association" qui peuvent être lus à partir d'un fichier de configuration. Le format et la sémantique de ce fichier de configuration sont documentés dans asconfig.txt.

Négociation de l'identité de l'utilisateur

Négociation d'identité utilisateur

Lors de la spécification du nom d'utilisateur et/ou du mot de passe à l'aide des options --user et -e --password, la valeur doit être fournie en encodage UTF-8.

Si l'option --pos-response est utilisée, le SCP est invité à répondre explicitement, c'est-à-dire à accuser réception, des informations d'identification de l'utilisateur fournies dans la requête storescu. Sinon, si aucune réponse de ce type n'est envoyée, storescu ne continuera pas mais annulera la connexion. L'identité utilisateur est une fonctionnalité optionnelle introduite ultérieurement dans la norme, de nombreux SCP ne vérifieront donc pas l'identité utilisateur fournie et ne fourniront donc aucune réponse d'identité utilisateur.

JOURNALISATION

Le niveau de sortie de la journalisation des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits dans le flux d'erreurs standard. L'utilisation de l'option --verbose permet également de signaler des messages d'information tels que les détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, consultez la documentation du module « oflog ».

Si la sortie de journalisation doit être écrite dans un fichier (éventuellement avec rotation du fichier journal), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enferment les valeurs optionnelles (0-1), les trois points indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options s'excluent mutuellement, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

En outre, un ou plusieurs fichiers de commande peuvent être spécifiés à l'aide d'un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute évaluation supplémentaire. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et d'éviter des lignes de commande trop longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire storescu tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, à moins que le dictionnaire ne soit intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Il s'agit d'une erreur si aucun dictionnaire de données ne peut être chargé.
