FBB::Stat(3bobcat) Caractéristiques d'un objet dans le système de fichiers FBB::Stat(3bobcat)

NOM

FBB::Stat - Détermine les caractéristiques d'un fichier

SYNTAXE

#include <bobcat/stat>
Option de liaison : -lbobcat

DESCRIPTION

Stat est un wrapper autour des fonctions système stat(2) et lstat(2). En particulier, il offre des fonctionnalités pour tester directement les caractéristiques d'objet offertes par ces deux fonctions. Pour déterminer si un objet peut être correctement construit, utilisez l'opérateur de conversion Stat bool. Si cet opérateur retourne false, alors aucun autre membre, sauf error, ne doit être utilisé.

ESPACE DE NOMS

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de noms FBB.

ENUMERATIONS

Stat::Combine:
Cette énumération définit les valeurs suivantes :

tous
ALL : requiert que toutes les valeurs spécifiées de Mode ou SpecialMode correspondent ;
un
ANY : requiert une correspondance quelconque parmi les valeurs de Mode ou SpecialMode spécifiées (une correspondance suffit) ;

Stat::Mode:
Cette énumération définit les valeurs suivantes :

proprio_lecture
UR : le propriétaire de l'objet a les permissions de lecture
proprio_ecriture
UW : le propriétaire de l'objet a les permissions d'écriture
proprio_execution
UX : le propriétaire de l'objet a les permissions d'exécution
groupe_lecture
GR : le groupe auquel l'objet appartient a les permissions de lecture
groupe_ecriture
GW : le groupe auquel l'objet appartient a les permissions d'écriture
groupe_execution
GX : le groupe auquel l'objet appartient a les permissions d'exécution
autres_lecture
OR : les autres ont les permissions de lecture
autres_ecriture
OW : les autres ont les permissions d'écriture
autres_execution
OX : les autres ont les permissions d'exécution
lecture
READ : égal à UR | GR | OR
ecriture
WRITE : égal à UW | GW | OW
execution
EXEC : égal à UX | GX | OX
rxwe
RWX : tous les éléments ci-dessus.

Stat::SpecialMode:
Cette énumération définit les valeurs suivantes :

suid
SUID : le bit SUID est activé
sgid
SGID : le bit SGID est activé
sb
SB : le bit collant (sticky bit) est activé

Stat::Type:
Cette énumération, qui est identique à l'énumération Type de glob(3bobcat), définit les valeurs suivantes :

device_bloc
BLOCK_DEVICE (0060000) : l'objet est un périphérique bloc ;
device_caractere
CHARACTER_DEVICE (0020000) : l'objet est un périphérique caractère ;
repertoire
DIRECTORY (0040000) : l'objet est un répertoire ;
fifo
FIFO (0010000) : l'objet est un tube nommé (une file d'attente) ;
fichier_regulier
REGULAR_FILE (0100000) : l'objet est un fichier régulier ;
socket
SOCKET (0140000) : l'objet est une socket ;
lien_symbolique
SYMBOLIC_LINK (0120000) : l'objet est un lien symbolique ;
tout_type
ANY : n'importe lequel des types ci-dessus.

Stat::Lstat:
Cette énumération a une seule valeur : LStat, qui peut être spécifiée par les constructeurs et certains membres lorsque l'objet Stat doit distinguer les fichiers réguliers et les liens symboliques (en appelant lstat(2)) au lieu de considérer les liens symboliques comme des fichiers réguliers (en utilisant stat(2)).

Les constructeurs et membres qui définissent des paramètres de Stat::Lstat appellent lstat(2), distinguant ainsi les liens symboliques des fichiers réguliers, tandis que les constructeurs et membres qui ne définissent pas de paramètres Stat::Lstat utilisent stat(2).

Les valeurs de retour des membres statStruct et type et typeStr (voir ci-dessous) ne distinguent les liens symboliques des fichiers réguliers que lorsque l'argument Stat::LStat a été utilisé.

Les constructeurs et les fonctions membres listés ci-dessous pour lesquels [Stat::Lstat,] est spécifié comme premier paramètre peuvent optionnellement spécifier l'argument Stat::LStat.

CONSTRUCTEURS

constructeur_par_defaut
Stat():
Le constructeur par défaut, créant un objet Stat vide. Il est principalement utilisé comme objet par défaut lors de la définition, par exemple, de vecteurs d'objets Stat. Comme il ne fait pas référence à une entrée existante du système de fichiers, son opérateur bool retourne false;
nom_fichier
Stat([Stat::Lstat,] std::string const &fname):
Initialise un Stat avec un nom d'objet donné ;
nom_fichier_chemin
Stat([Stat::Lstat,] std::string const &fname, std::string const &searchPath):
Initialise un Stat avec un nom d'objet donné, où l'objet est recherché dans les répertoires searchPath, qui est une chaîne de noms de répertoires séparés par des deux-points. Les noms de fichiers sont construits en ajoutant fname à chacun des éléments de searchPath jusqu'à ce qu'un objet existant soit trouvé. Cet objet est alors utilisé. Si fname est un chemin absolu, searchPath est ignoré.

Les constructeurs et opérateurs d'affectation de copie et de déplacement sont disponibles.

OPERATEURS Surchargés

operateur_bool
operator bool() const:
Cet opérateur retourne true si l'objet Stat contient des informations sur un objet existant. Sinon, false est retourné. Lorsque false est retourné, les autres membres, à l'exception des opérateurs d'affectation, du membre error et des membres set, ne doivent pas être utilisés.

FONCTIONS MEMBRES

bool access(FBB::User const &user, size_t spec, bool useEffective = true) const:
Retourne true si user a les permissions telles que spécifiées dans spec (dont seuls les bits Mode définis sont interprétés). Si une combinaison de permissions de lecture, d'écriture et/ou d'exécution est spécifiée, alors au moins une des permissions de lecture, une des permissions d'écriture et une des permissions d'exécution doit être accordée, sinon la fonction retourne false. Par exemple, en spécifiant access(user, UW | UR | GR), l'utilisateur doit avoir les permissions d'écriture, mais l'utilisateur ou son groupe doit avoir les permissions de lecture. bool mode(size_t mode, Combine combine = ALL):
Retourne true si l'objet a le mode indiqué. Plusieurs modes peuvent être définis, qui peuvent être combinés par l'opérateur logique bitor. Par défaut, si plusieurs modes sont spécifiés, le motif résultant doit représenter exactement le mode de l'objet pour que la fonction membre retourne true. Un argument optionnel ANY peut être spécifié si la fonction doit retourner true si au moins un mode spécifié correspond au mode réel de l'objet. EXEMPLE

/*
                              driver.cc
*/
#include <iostream>
#include <string>
#include "../stat"
#include <bobcat/datetime>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    if (argc == 1)
    {
        cout << "Usage: driver [-l] objet [chemin de recherche séparé par des deux-points]\n";
        return 1;
    }
    bool lstat = "-l"s == argv[1];
    if (lstat)
    {
        ++argv;
        --argc;
    }
    Stat st;
    if (argc == 2)
    {
        if (lstat)
            st.set(Stat::LStat, argv[1]);
        else
            st.set(argv[1]);
    }
    else if (argc == 3)
    {
        if (lstat)
            st.set(Stat::LStat, argv[1], argv[2]);
        else
            st.set(argv[1], argv[2]);
    }
    if (!st)
    {
        cout << "Impossible de statuer sur " << argv[1] << ", errno = " << st.error() << endl;
        return 1;
    }
    cout << st.name() << ": accès: " << st.lastAccess() << "\n" <<
            st.name() << ": changement: " << st.lastChange() << "\n" <<
            st.name() << ": modif:  " << st.lastModification() << "\n"
            "Mode: " << oct << st.mode() <<  " (" << st.modeStr() << ")\n"
            "Type: " << st.type() << " (" << st.typeStr() << ")\n"
            "Chemin complet:  " << st.path()  << endl;
}
