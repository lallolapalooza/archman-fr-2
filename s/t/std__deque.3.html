Description détaillée

template<typename _Tp, typename _Alloc = std::allocator<_Tp>>

class std::deque< _Tp, _Alloc >"Un conteneur standard utilisant une allocation mémoire de taille fixe et une manipulation des éléments aux deux extrémités en temps constant.

Paramètres de template

_Tp Type de l'élément.
_Alloc Type de l'allocateur, par défaut allocator<_Tp>.

Respecte les exigences d'un conteneur, d'un conteneur réversible et d'une séquence, y compris les exigences optionnelles des séquences.

Dans les versions précédentes de deque par HP/SGI, il y avait un paramètre de template supplémentaire pour permettre aux utilisateurs de contrôler la taille des nœuds. Cette extension s'est avérée violer la norme C++ (elle peut être détectée à l'aide de paramètres de template de template), et elle a été supprimée.

Voici comment un deque<Tp> gère la mémoire. Chaque deque a 4 membres :

  • Tp** _M_map
  • size_t _M_map_size
  • iterator _M_start, _M_finish

map_size est au moins 8. map est un tableau de pointeurs vers des nœuds de taille map_size. (Le nom map n'a rien à voir avec la classe std::map, et nœuds ne doit pas être confondu avec l'utilisation de nœud par std::list.)

Un nœud n'a pas de nom de type spécifique en tant que tel, mais il est désigné comme nœud dans ce fichier. C'est un simple tableau de Tp. Si Tp est très volumineux, il y aura un élément Tp par nœud (c'est-à-dire un tableau d'un seul élément). Pour les Tp non énormes, la taille du nœud est inversement proportionnelle à la taille de Tp : plus Tp est grand, moins il y aura de Tp dans un nœud. Le but ici est de garder la taille totale d'un nœud relativement petite et constante sur différents Tp, afin d'améliorer l'efficacité de l'allocateur.

Tous les pointeurs du tableau map ne pointeront pas vers un nœud. Si le nombre initial d'éléments dans le deque est petit, les pointeurs map du milieu seront valides, et ceux des bords seront inutilisés. La même situation se présentera à mesure que la map grandit : les pointeurs map disponibles, le cas échéant, seront aux extrémités. Lors de la création de nouveaux nœuds, seul un sous-ensemble des pointeurs de la map doit être copié vers l'extérieur.

Invariants de classe :

•
Pour tout itérateur non singulier i :
•
i.node pointe vers un membre du tableau map. (Oui, vous avez bien lu : i.node ne pointe pas réellement vers un nœud.) C'est le membre du tableau map qui pointe réellement vers le nœud.
•
i.first == *(i.node) (Ceci pointe vers le nœud (premier élément Tp).)
•
i.last == i.first + node_size
•
i.cur est un pointeur dans l'intervalle [i.first, i.last). NOTE : l'implication est que i.cur est toujours un pointeur déréférençable, même si i est un itérateur past-the-end.
  • Start et Finish sont toujours des itérateurs non singuliers. NOTE : cela signifie qu'un deque vide doit avoir un nœud, un deque avec <N éléments (où N est la taille du buffer de nœuds) doit avoir un nœud, un deque avec N à (2N-1) éléments doit avoir deux nœuds, etc.
  • Pour chaque nœud autre que start.node et finish.node, tous les éléments du nœud sont des objets initialisés. Si start.node == finish.node, alors [start.cur, finish.cur) sont des objets initialisés, et les éléments en dehors de cet intervalle sont du stockage non initialisé. Sinon, [start.cur, start.last) et [finish.first, finish.cur) sont des objets initialisés, et [start.first, start.cur) et [finish.cur, finish.last) sont du stockage non initialisé.
  • [map, map + map_size) est un intervalle valide et non vide.
  • [start.node, finish.node] est un intervalle valide contenu dans [map, map + map_size).
  • Un pointeur dans l'intervalle [map, map + map_size) pointe vers un nœud alloué si et seulement si le pointeur se trouve dans l'intervalle [start.node, finish.node].

Voici la magie : rien dans le deque n'est conscient du stockage disjoint !

La configuration et la disposition de la mémoire se font dans le parent, _Base, et la classe iterator est entièrement responsable du passage d'un nœud à l'autre. Toutes les routines d'implémentation du deque lui-même fonctionnent uniquement via les itérateurs start et finish. Cela permet de garder les routines simples et saines, et nous pouvons également utiliser d'autres algorithmes standard.

Paramètres

__last Un itérateur d'entrée.

Crée un deque composé de copies des éléments de [__first, __last).

Si les itérateurs sont forward, bidirectional ou random-access, cela appellera le constructeur de copie des éléments N fois (où N est distance(__first,__last)) et n'effectuera aucune réallocation de mémoire. Mais si seuls des itérateurs d'entrée sont utilisés, cela effectuera au maximum 2N appels au constructeur de copie et logN réallocations de mémoire.

template<typename _Tp, typename _Alloc = std::allocator<_Tp>> std::deque< _Tp, _Alloc >::~deque () [inline]

Le destructeur efface seulement les éléments, et notez que si les éléments sont eux-mêmes des pointeurs, la mémoire pointée n'est aucunement touchée. La gestion du pointeur est la responsabilité de l'utilisateur.
