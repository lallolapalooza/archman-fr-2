strtok(3) Manuel des fonctions de bibliothèque strtok(3)

NOM

strtok, strtok_r - extraire des jetons de chaînes

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <string.h>
char *strtok(char *_Nullable restrict str, const char *restrict delim);
char *strtok_r(char *_Nullable restrict str, const char *restrict delim,
               char **restrict saveptr);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

strtok_r():

    _POSIX_C_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

La fonction strtok() divise une chaîne en une séquence de zéro ou plusieurs jetons non vides. Lors du premier appel à strtok(), la chaîne à analyser doit être spécifiée dans str. Lors de chaque appel subséquent qui doit analyser la même chaîne, str doit être NULL.

L'argument delim spécifie un ensemble d'octets qui délimitent les jetons dans la chaîne analysée. L'appelant peut spécifier des chaînes différentes dans delim lors d'appels successifs qui analysent la même chaîne.

Chaque appel à strtok() retourne un pointeur vers une chaîne terminée par un caractère nul contenant le jeton suivant. Cette chaîne n'inclut pas l'octet délimiteur. Si aucun jeton supplémentaire n'est trouvé, strtok() retourne NULL.

Une séquence d'appels à strtok() qui opèrent sur la même chaîne maintient un pointeur qui détermine le point à partir duquel commencer la recherche du jeton suivant. Le premier appel à strtok() fait pointer ce pointeur vers le premier octet de la chaîne. Le début du jeton suivant est déterminé en balayant vers l'avant pour trouver le prochain octet non délimiteur dans str. Si un tel octet est trouvé, il est considéré comme le début du jeton suivant. Si aucun octet de ce type n'est trouvé, il n'y a plus de jetons, et strtok() retourne NULL. (Une chaîne vide ou contenant uniquement des délimiteurs provoquera donc le retour de NULL par strtok() lors du premier appel.)

La fin de chaque jeton est trouvée en balayant vers l'avant jusqu'à ce que le prochain octet délimiteur soit trouvé ou jusqu'à ce que l'octet nul terminateur ('\0') soit rencontré. Si un octet délimiteur est trouvé, il est écrasé par un octet nul pour terminer le jeton courant, et strtok() enregistre un pointeur vers l'octet suivant ; ce pointeur sera utilisé comme point de départ lors de la recherche du jeton suivant. Dans ce cas, strtok() retourne un pointeur vers le début du jeton trouvé.

D'après la description ci-dessus, il s'ensuit qu'une séquence de deux octets délimiteurs contigus ou plus dans la chaîne analysée est considérée comme un seul délimiteur, et que les octets délimiteurs au début ou à la fin de la chaîne sont ignorés. Autrement dit : les jetons retournés par strtok() sont toujours des chaînes non vides. Ainsi, par exemple, étant donné la chaîne "aaa;;bbb,", des appels successifs à strtok() spécifiant la chaîne de délimiteurs ";," retour neraient les chaînes "aaa" et "bbb", puis un pointeur nul.

La fonction strtok_r() est une version réentrante de strtok(). L'argument saveptr est un pointeur vers une variable de type char * qui est utilisée en interne par strtok_r() afin de maintenir le contexte entre les appels successifs qui analysent la même chaîne.

Lors du premier appel à strtok_r(), str doit pointer vers la chaîne à analyser, et la valeur de *saveptr est ignorée (mais voir VERSIONS). Lors des appels ultérieurs, str doit être NULL, et saveptr (ainsi que le tampon auquel il pointe) doit rester inchangé depuis l'appel précédent.

Différentes chaînes peuvent être analysées simultanément à l'aide de séquences d'appels à strtok_r() spécifiant différents arguments saveptr.

VALEUR DE RETOUR

Les fonctions strtok() et strtok_r() retournent un pointeur vers le jeton suivant, ou NULL s'il n'y a plus de jetons.

BOGUES

Soyez prudent lorsque vous utilisez ces fonctions. Si vous les utilisez, notez que :

•
Ces fonctions modifient leur premier argument.
•
Ces fonctions ne peuvent pas être utilisées sur des chaînes constantes.
•
L'identité de l'octet délimiteur est perdue.
•
La fonction strtok() utilise un tampon statique lors de l'analyse, elle n'est donc pas sûre pour les threads. Utilisez strtok_r() si cela vous concerne.

EXEMPLES

Le programme ci-dessous utilise des boucles imbriquées qui emploient strtok_r() pour diviser une chaîne en une hiérarchie à deux niveaux de jetons. Le premier argument de la ligne de commande spécifie la chaîne à analyser. Le deuxième argument spécifie l'octet (ou les octets) délimiteur(s) à utiliser pour séparer cette chaîne en jetons "majeurs". Le troisième argument spécifie l'octet (ou les octets) délimiteur(s) à utiliser pour séparer les jetons "majeurs" en sous-jetons.

Un exemple de la sortie produite par ce programme est le suivant :


$ ./a.out 'a/bbb///cc;xxx:yyy:' ':;' '/'
1: a/bbb///cc
         --> a
         --> bbb
         --> cc
2: xxx
         --> xxx
3: yyy
         --> yyy

Source du programme

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    char *str1, *str2, *token, *subtoken;
    char *saveptr1, *saveptr2;
    int j;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s chaine delim sousdelim\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    for (j = 1, str1 = argv[1]; ; j++, str1 = NULL) {
        token = strtok_r(str1, argv[2], &saveptr1);
        if (token == NULL)
            break;
        printf("%d: %s\n", j, token);
        for (str2 = token; ; str2 = NULL) {
            subtoken = strtok_r(str2, argv[3], &saveptr2);
            if (subtoken == NULL)
                break;
            printf("\t --> %s\n", subtoken);
        }
    }
    exit(EXIT_SUCCESS);
}

Un autre exemple de programme utilisant strtok() se trouve dans getaddrinfo_a(3).
