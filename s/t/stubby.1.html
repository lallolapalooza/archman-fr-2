STUBBY(1) Manuel des commandes générales STUBBY(1)

NOM

stubby - un résolveur stub local pour la confidentialité DNS

SYNTAXE

stubby [-C fichier] [-ghilV] [-v niveau_log]

DESCRIPTION

stubby agit comme un résolveur stub local pour la confidentialité DNS, utilisant DNS-over-TLS. Stubby chiffre les requêtes DNS envoyées depuis la machine locale vers un résolveur de confidentialité DNS, augmentant ainsi la confidentialité de l'utilisateur final.

stubby est aux premiers stades de développement mais convient aux utilisateurs techniques/avancés.

stubby assure la confidentialité DNS en fonctionnant comme un démon qui écoute sur l'adresse de bouclage les requêtes DNS, et relaie ces requêtes via TLS. La configuration par défaut offre une confidentialité stricte et utilise un sous-ensemble des serveurs de confidentialité DNS disponibles. Voir https://dnsprivacy.org/wiki/display/DP/DNS+Privacy+Test+Servers

OPTIONS

-C fichier
Lire les paramètres depuis le fichier de configuration fichier. Si cette option n'est pas donnée, stubby recherche un fichier de configuration dans ~/.stubby.yml. S'il n'est pas présent, stubby se rabat sur le fichier de configuration global /etc/stubby/stubby.yml.
-g
Exécuter stubby comme un démon.
-h
Afficher un message d'utilisation et quitter.
-i
Lire la configuration, valider son contenu, l'afficher joliment sur la sortie standard et quitter.
-l
Activer toutes les journalisations. Équivalent à -v 7.
-v niveau_log
Activer la journalisation. Tous les messages de journalisation d'un niveau égal ou inférieur à niveau_log sont affichés sur la sortie d'erreur standard :
0: EMERG
Le système est inutilisable
1: ALERT
Une action doit être entreprise immédiatement
2: CRIT
Conditions critiques
3: ERROR
Conditions d'erreur
4: WARN
Conditions d'avertissement
5: NOTICE
Conditions normales, mais significatives
6: INFO
Messages d'information
7: DEBUG
Messages de niveau débogage
-V
Afficher la version de stubby et quitter.

CONFIGURATION

Le fichier de configuration est au format YAML. Un exemple de configuration est :

resolution_type: GETDNS_RESOLUTION_STUB
dns_transport_list:
  - GETDNS_TRANSPORT_TLS
tls_authentication: GETDNS_AUTHENTICATION_REQUIRED
tls_query_padding_blocksize: 256
edns_client_subnet_private : 1
idle_timeout: 10000
listen_addresses:
  - 127.0.0.1
  -  0::1
round_robin_upstreams: 1
upstream_recursive_servers:
  - address_data: 145.100.185.15
    tls_auth_name: "dnsovertls.sinodun.com"
    tls_pubkey_pinset:
      - digest: "sha256"
        value: 62lKu9HsDVbyiPenApnc4sfmSYTHOVfFgL3pyB+cBL4=
  - address_data: 145.100.185.16
    tls_auth_name: "dnsovertls1.sinodun.com"
    tls_pubkey_pinset:
      - digest: "sha256"
        value: cE2ecALeE5B+urJhDrJlVFmf38cJLAvqekONvjvpqUA=
  - address_data: 185.49.141.37
    tls_auth_name: "getdnsapi.net"

Les éléments de configuration sont les suivants. Certains prennent des valeurs constantes de la bibliothèque getdns sous-jacente à stubby et des explications supplémentaires sur leurs valeurs peuvent être trouvées dans la documentation de getdns ou sur http://www.getdnsapi.net

resolution_type résolution.
Ceci doit être défini sur GETDNS_RESOLUTION_STUB pour des raisons historiques. stubby se terminera avec une erreur si un autre paramètre est utilisé.
dns_transport_list liste
Définit la liste des types de transport à utiliser. Pour la confidentialité DNS, cela doit être défini sur GETDNS_TRANSPORT_TLS. Les transports en clair sont GETDNS_TRANSPORT_TCP et GETDNS_TRANSPORT_UDP
tls_authentication type
Définit le type d'authentification requis. Pour une confidentialité stricte, ceci doit être défini sur GETDNS_AUTHENTICATION_REQUIRED. Pour le mode opportuniste, supprimez ce paramètre ou définissez-le sur GETDNS_AUTHENTICATION_NONE. En mode opportuniste, l'authentification du serveur de noms n'est pas requise et le recours aux transports en clair est autorisé s'ils figurent dans dns_transport_list
tls_query_padding_blocksize taille_bloc
Utilise l'option de remplissage EDNS0 pour remplir les requêtes DNS afin de masquer leur taille.
edns_client_subnet_private 0 ou 1
Si 1, utilise la confidentialité EDNS0 Client Subnet afin que le sous-réseau client ne soit pas envoyé aux serveurs faisant autorité.
idle_timeout délai
Utilise un délai de maintenance EDNS0 Keepalive de délai millisecondes, sauf si remplacé par le serveur. Ceci maintient les connexions TLS inactives ouvertes pour éviter la surcharge d'ouverture d'une nouvelle connexion pour chaque requête.
round_robin_upstreams 0 ou 1
Si 1, distribue les requêtes en round robin sur tous les serveurs en amont configurés. Sans cette option, stubby utilisera chaque serveur en amont séquentiellement jusqu'à ce qu'il devienne indisponible, puis passera au suivant.
upstream_recursive_servers liste_serveurs
Spécifie les serveurs en amont que stubby doit utiliser. Chaque élément de la liste contient les éléments suivants :
address_data adresse
Adresse IPv4 ou IPv6 du serveur.
tls_auth_name nom
C'est le nom de domaine d'authentification qui sera vérifié par rapport au certificat présenté.
tls_pubkey_pinset jeu_de_broches
Le jeu de broches SPKI sha256 du serveur. Ceci est également vérifié par rapport au certificat présenté. Ceci contient deux éléments :
digest type
Le type du digest de clé.
value cléval
La valeur de la clé.
