STRERROR(3P) Manuel du programmeur POSIX STRERROR(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

strerror, strerror_l, strerror_r — obtenir la chaîne de message d'erreur

SYNTAXE

#include <string.h>
char *strerror(int errnum);
char *strerror_l(int errnum, locale_t locale);
int strerror_r(int errnum, char *strerrbuf, size_t buflen);

DESCRIPTION

Pour strerror(): La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1-2017 renvoie à la norme ISO C.

La fonction strerror() mappe le numéro d'erreur dans errnum à une chaîne de message d'erreur dépendante de la locale et renvoie un pointeur vers celle-ci. Typiquement, les valeurs pour errnum proviennent de errno, mais strerror() mappe toute valeur de type int à un message.

L'application ne doit pas modifier la chaîne renvoyée. Le pointeur de chaîne renvoyé peut être invalidé ou le contenu de la chaîne peut être écrasé par un appel ultérieur à strerror(), ou par un appel ultérieur à strerror_l() dans le même thread. Le pointeur renvoyé et le contenu de la chaîne peuvent également être invalidés si le thread appelant est terminé.

La chaîne peut être écrasée par un appel ultérieur à strerror_l() dans le même thread.

Le contenu des chaînes de message d'erreur renvoyées par strerror() doit être déterminé par le réglage de la catégorie LC_MESSAGES dans la locale actuelle.

L'implémentation ne doit appeler aucune fonction définie dans ce volume de POSIX.1-2017 en appelant strerror().

Les fonctions strerror() et strerror_l() ne doivent pas modifier le réglage de errno en cas de succès.

Comme aucune valeur de retour n'est réservée pour indiquer une erreur de strerror(), une application souhaitant vérifier les situations d'erreur doit définir errno à 0, puis appeler strerror(), puis vérifier errno. De même, comme strerror_l() est requis pour renvoyer une chaîne pour certaines erreurs, une application souhaitant vérifier toutes les situations d'erreur doit définir errno à 0, puis appeler strerror_l(), puis vérifier errno.

La fonction strerror() n'a pas besoin d'être thread-safe.

La fonction strerror_l() mappe le numéro d'erreur dans errnum à une chaîne de message d'erreur dépendante de la locale dans la locale représentée par locale et renvoie un pointeur vers celle-ci.

La fonction strerror_r() mappe le numéro d'erreur dans errnum à une chaîne de message d'erreur dépendante de la locale et renvoie la chaîne dans le tampon pointé par strerrbuf, avec une longueur de buflen.

Si la valeur de errnum est un numéro d'erreur valide, la chaîne de message indiquera quelle erreur s'est produite ; si la valeur de errnum est zéro, la chaîne de message sera une chaîne vide ou indiquera qu'aucune erreur ne s'est produite ; sinon, si ces fonctions se terminent avec succès, la chaîne de message indiquera qu'une erreur inconnue s'est produite.

Le comportement est indéfini si l'argument locale de strerror_l() est l'objet de locale spécial LC_GLOBAL_LOCALE ou n'est pas un descripteur d'objet de locale valide.

VALEUR DE RETOUR

À l'achèvement, qu'il y ait succès ou non, strerror() renvoie un pointeur vers la chaîne de message générée. En cas d'erreur, errno peut être défini, mais aucune valeur de retour n'est réservée pour indiquer une erreur.

En cas de succès, strerror_l() renvoie un pointeur vers la chaîne de message générée. Si errnum n'est pas un numéro d'erreur valide, errno peut être défini à [EINVAL], mais un pointeur vers une chaîne de message sera toujours renvoyé. Si une autre erreur se produit, errno sera défini pour indiquer l'erreur et un pointeur nul sera renvoyé.

En cas de succès, strerror_r() renvoie 0. Sinon, un numéro d'erreur sera renvoyé pour indiquer l'erreur.

ERREURS

Ces fonctions peuvent échouer si :

EINVAL
La valeur de errnum n'est ni un numéro d'erreur valide ni zéro.

La fonction strerror_r() peut échouer si :

ERANGE
Un espace de stockage insuffisant a été fourni via strerrbuf et buflen pour contenir la chaîne de message générée.

UTILISATION APPLICATION

Historiquement, dans certaines implémentations, les appels à perror() écrasaient la chaîne vers laquelle pointait le pointeur renvoyé par strerror(). De telles implémentations n'étaient pas conformes à la norme ISO C ; cependant, les développeurs d'applications doivent être conscients de ce comportement s'ils souhaitent que leurs applications soient portables vers de telles implémentations.

RATIONALE

La fonction strerror_l() est requise pour être thread-safe, éliminant ainsi le besoin d'un équivalent à la fonction strerror_r().

Les versions antérieures de cette norme n'exigeaient pas explicitement que les chaînes de message d'erreur renvoyées par strerror() et strerror_r() fournissent des informations sur l'erreur. Cette version de la norme exige un message significatif pour toute réussite.

Comme aucune valeur de retour n'est réservée pour indiquer une erreur de strerror(), mais que tous les appels (qu'ils réussissent ou non) doivent renvoyer un pointeur vers une chaîne de message, en cas d'erreur strerror() peut renvoyer un pointeur vers une chaîne vide ou un pointeur vers une chaîne significative qui peut être imprimée.

Notez que la condition d'erreur [EINVAL] est une erreur potentielle. Si un numéro d'erreur invalide est fourni comme valeur de errnum, les applications doivent être préparées à gérer l'un des éléments suivants :

1.
Erreur (sans message significatif) : errno est défini à [EINVAL], la valeur de retour est un pointeur vers une chaîne vide.
2.
Succès : errno est inchangé et la valeur de retour pointe vers une chaîne telle que "unknownerror" ou "errornumberxxx" (où xxx est la valeur de errnum).
3.
Combinaison de #1 et #2 : errno est défini à [EINVAL] et la valeur de retour pointe vers une chaîne telle que "unknownerror" ou "errornumberxxx" (où xxx est la valeur de errnum). Étant donné que les applications utilisent fréquemment la valeur de retour de strerror() comme argument pour des fonctions telles que fprintf() (sans vérifier la valeur de retour) et que les applications n'ont aucun moyen d'analyser une chaîne de message d'erreur pour déterminer si errnum représente un numéro d'erreur valide, les implémentations sont encouragées à implémenter #3. De même, les implémentations sont encouragées à faire en sorte que strerror_r() renvoie [EINVAL] et place une chaîne telle que "unknownerror" ou "errornumberxxx" dans le tampon pointé par strerrbuf lorsque la valeur de errnum n'est pas un numéro d'erreur valide.

Certaines applications s'appuient sur la possibilité de définir errno à 0 avant d'appeler une fonction sans valeur réservée pour indiquer une erreur, puis appellent strerror(errno) ensuite pour détecter si une erreur s'est produite (parce que errno a changé) ou pour indiquer le succès (parce que errno est resté zéro). Ce modèle d'utilisation nécessite que strerror(0) réussisse avec des résultats utiles. Les versions précédentes de la norme ne spécifiaient pas le comportement lorsque errnum est zéro.
