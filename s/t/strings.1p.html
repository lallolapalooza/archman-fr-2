STRINGS(1P) Manuel du programmeur POSIX STRINGS(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

strings — trouver des chaînes imprimables dans des fichiers

SYNTAXE

strings [-a] [-t format] [-n nombre] [fichier...]

DESCRIPTION

L'utilitaire strings recherche des chaînes imprimables dans des fichiers réguliers et écrit ces chaînes sur la sortie standard. Une chaîne imprimable est toute séquence de quatre caractères imprimables (par défaut) ou plus, terminée par un caractère <newline> ou NUL. D'autres chaînes définies par l'implémentation peuvent être écrites ; voir localedef.

Si le premier argument est '-', les résultats ne sont pas spécifiés.

OPTIONS

L'utilitaire strings doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception de l'utilisation non spécifiée de '-'.

Les options suivantes doivent être prises en charge :

-a
Analyser les fichiers dans leur intégralité. Si -a n'est pas spécifié, la partie de chaque fichier qui sera analysée pour les chaînes est définie par l'implémentation.
-n nombre
Spécifier la longueur minimale de la chaîne, où l'argument nombre est un entier décimal positif. La valeur par défaut sera 4.
-t format
Écrire chaque chaîne précédée de son décalage en octets par rapport au début du fichier. Le format dépendra du caractère unique utilisé comme argument d'option format :
d
Le décalage sera écrit en décimal.
o
Le décalage sera écrit en octal.
x
Le décalage sera écrit en hexadécimal.

OPÉRANDES

L'opérande suivant sera pris en charge :

fichier
Un nom de chemin d'un fichier régulier à utiliser comme entrée. Si aucun opérande fichier n'est spécifié, l'utilitaire strings lira depuis l'entrée standard.

STDIN

Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée nommés par les arguments de l'utilitaire ou l'entrée standard seront des fichiers réguliers de n'importe quel format.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de strings :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux multi-octets dans les arguments et les fichiers d'entrée) et pour identifier les chaînes imprimables.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Les chaînes trouvées seront écrites sur la sortie standard, une par ligne.

Lorsque l'option -t n'est pas spécifiée, le format de la sortie sera :

"%s", <chaîne>

Avec l'option -t o, le format de la sortie sera :

"%o %s", <décalage en octets>, <chaîne>

Avec l'option -t x, le format de la sortie sera :

"%x %s", <décalage en octets>, <chaîne>

Avec l'option -t d, le format de la sortie sera :

"%d %s", <décalage en octets>, <chaîne>

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucun.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront renvoyées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Par défaut, la zone de données (par opposition aux zones de texte, ``bss'', ou d'en-tête) d'un fichier exécutable binaire est analysée. Les implémentations documentent quelles zones sont analysées.

Certaines implémentations historiques n'exigent pas de terminateurs NUL ou <newline> pour les chaînes afin de permettre l'écriture des chaînes de ces langues qui n'utilisent pas NUL comme terminateur de chaîne.

EXEMPLES

Aucun.

JUSTIFICATION

Outre la rationalisation de la syntaxe des options et les légères difficultés avec les fichiers binaires objets et exécutables, strings est spécifié pour correspondre étroitement à la pratique historique. Les options -a et -n ont été introduites pour remplacer les options non conformes - et -nombre. Celles-ci ne sont plus spécifiées par POSIX.1‐2008 mais peuvent être présentes dans certaines implémentations.

L'option -o signifie historiquement différentes choses selon les implémentations. Certaines l'utilisent pour signifier « décalage en décimal », tandis que d'autres l'utilisent comme « décalage en octal ». Au lieu d'essayer de décider quelle façon serait la moins discutable, l'option -t a été ajoutée. Elle s'appelait à l'origine -O pour « décalage », mais a été changée en -t pour être cohérente avec od.

La fonction ISO C isprint() est limitée à un domaine de unsigned char. Ce volume de POSIX.1‐2017 exige des implémentations qu'elles écrivent des chaînes telles que définies par la locale actuelle.
