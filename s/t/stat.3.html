Description détaillée

Interface abstraite pour prendre en charge des archives définies par l'utilisateur.

Attention

C'est du matériel avancé, très complexe. Vous n'en avez pas besoin sauf si vous savez vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archive et des répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers d'archive.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir la prise en charge d'un type de fichier d'archive qui n'est pas fourni directement par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, toute la prise en charge des archives intégrée utilise cette interface, donc les meilleurs exemples pour construire un PHYSFS_Archiver sont le code source de PhysicsFS lui-même.

Un archiveur est ajouté au système avec PHYSFS_registerArchiver(), puis il sera automatiquement disponible pour utilisation avec PHYSFS_mount() ; si une archive donnée peut être gérée par votre archiveur, il prendra le contrôle de manière appropriée.

Ces méthodes traitent les descripteurs de répertoires. Vous avez une instance de votre archiveur, et elle génère un descripteur unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Étant donné que la durée de vie d'un Archiveur (pas d'une archive) est généralement la durée de vie entière du processus, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiveur lui-même ; l'application peut simplement utiliser des variables statiques si nécessaire.

Les liens symboliques doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier les liens symboliques et juger s'il faut continuer à appeler d'autres méthodes en fonction de cela.

Les archiveurs, lorsque nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs à l'application sans modification dans la plupart des cas.

Sécurité des threads : les implémentations de PHYSFS_Archiver ne sont pas garanties d'être sûres pour les threads en elles-mêmes. PhysicsFS assure la sécurité des threads lorsqu'il appelle un archiveur donné dans la bibliothèque, mais il ne promet pas que l'utilisation du même PHYSFS_File depuis deux threads simultanément soit sûre pour les threads ; par conséquent, votre PHYSFS_Archiver peut supposer que le verrouillage est géré pour vous tant que le PHYSFS_Io que vous retournez de PHYSFS_open* ne modifie aucun de vos états d'Archiveur, car le PHYSFS_Io ne sera pas aussi agressivement protégé.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute mémoire associée, y compris le PHYSFS_Io d'origine et (opaque) lui-même, le cas échéant. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est faite si approprié, vous pouvez donc la supprimer au retour du rappel. (dirname) est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si le rappel retourne PHYSFS_ENUM_ERROR, veuillez appeler PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) et retourner également PHYSFS_ENUM_ERROR. N'appelez plus jamais le rappel dans aucune circonstance. Si le rappel retourne PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez également PHYSFS_ENUM_STOP. Ne définissez pas de code d'erreur dans ce cas. Les rappels sont uniquement censés retourner une valeur de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Tant que le rappel a retourné PHYSFS_ENUM_OK et que vous n'avez rencontré aucune erreur de votre côté, continuez à énumérer jusqu'à ce que vous ayez terminé et retournez PHYSFS_ENUM_OK sans définir de code d'erreur.

Attention

PHYSFS_enumerate retourne zéro ou non-zéro (succès ou échec), alors soyez conscient que ce pointeur de fonction retourne des valeurs différentes !

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archive et est renvoyé dans PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application essaie de créer plusieurs répertoires, PhysicsFS les séparera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération devrait échouer. Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive pour y ajouter. Si le fichier n'existe pas, il doit être créé. Le curseur d'écriture doit être à la fin du fichier. Si l'archive est en lecture seule, cette opération devrait échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Ouvre une archive fournie par (io). C'est ici que les ressources sont allouées et que les données sont analysées lors du montage d'une archive. (name) est un nom de fichier associé à (io), mais ne correspond pas nécessairement à quoi que ce soit, encore moins à un nom de fichier réel. Ce nom potentiellement insignifiant est en notation dépendante de la plateforme. (forWrite) est non nul si cela doit être utilisé pour le répertoire d'écriture, et nul si cela doit être utilisé pour un élément de la recherche

NAME

PHYSFS_Archiver - Archive handling interface

SYNOPSIS

struct PHYSFS_Archiver { ... };

Detailed Description

This is the primary interface for archive implementations.

int(* PHYSFS_Archiver::mount) (PHYSFS_Archiver *self, const char *fname, const char *mountpoint, int (*saved_error_callback)(void), void **opaque)

Mount an archive. This function is called when an archive file is detected by PHYSFS_mount(3). (fname) is the name of the archive file. (mountpoint) is the directory in the virtual filesystem where the archive should be mounted. (saved_error_callback) is a function to call if the archiver needs to report an error, but PHYSFS_setErrorCode(3) isn't available.

(opaque) is a pointer to a pointer that will hold the archiver's private data. This opaque data will be passed to all subsequent calls into this archiver.

If the archiver can handle this file, it should return non-NULL, and set (*opaque) to point to its private data. It should also set (claimed) to 1 if this is definitely an archive your archiver implementation can handle, even if it fails. We use to decide if we should stop trying other archivers if you fail to open it. For example: the .zip archiver will set this to 1 for something that's got a .zip file signature, even if it failed because the file was also truncated. No sense in trying other archivers here, we already tried to handle it with the appropriate implementation!. Return NULL on failure and set (claimed) appropriately. If no archiver opened the archive or set (claimed), PHYSFS_mount() will report PHYSFS_ERR_UNSUPPORTED. Otherwise, it will report the error from the archiver that claimed the data through (claimed). Return non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later calls.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Open a file in this archive for reading. This filename, (fnm), is in platform-independent notation. Fail if the file does not exist. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Open a file in this archive for writing. If the file does not exist, it should be created. If it exists, it should be truncated to zero bytes. The writing offset should be the start of the file. If the archive is read-only, this operation should fail. This filename is in platform-independent notation. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Delete a file or directory in the archive. This same call is used for both files and directories; there is not a separate rmdir() call. Directories are only meant to be removed if they are empty. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtain basic file metadata. On success, fill in all the fields in (stat), using reasonable defaults for fields that apply to your archive.

Returns non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_Archiver - Interface de gestion des archives

SYNTAXE

struct PHYSFS_Archiver { ... };

Description détaillée

Ceci est l'interface principale pour les implémentations d'archives.

int(* PHYSFS_Archiver::mount) (PHYSFS_Archiver *self, const char *fname, const char *mountpoint, int (*saved_error_callback)(void), void **opaque)

Monter une archive. Cette fonction est appelée lorsqu'un fichier archive est détecté par PHYSFS_mount(3). (fname) est le nom du fichier archive. (mountpoint) est le répertoire dans le système de fichiers virtuel où l'archive doit être montée. (saved_error_callback) est une fonction à appeler si l'archiveur a besoin de signaler une erreur, mais que PHYSFS_setErrorCode(3) n'est pas disponible.

(opaque) est un pointeur vers un pointeur qui contiendra les données privées de l'archiveur. Ces données opaques seront passées à tous les appels ultérieurs à cet archiveur.

Si l'archiveur peut gérer ce fichier, il doit retourner non-NULL, et définir (*opaque) pour pointer vers ses données privées. Il doit également définir (claimed) à 1 s'il s'agit définitivement d'une archive que votre implémentation d'archiveur peut gérer, même si elle échoue. Nous utilisons pour décider si nous devons arrêter d'essayer d'autres archiveurs si vous échouez à l'ouvrir. Par exemple : l'archiveur .zip définira ceci à 1 pour quelque chose qui a une signature de fichier .zip, même s'il a échoué parce que le fichier était également tronqué. Il est inutile d'essayer d'autres archiveurs ici, nous avons déjà essayé de le gérer avec l'implémentation appropriée !. Retourne NULL en cas d'échec et définit (claimed) de manière appropriée. Si aucun archiveur n'a ouvert l'archive ou défini (claimed), PHYSFS_mount() signalera PHYSFS_ERR_UNSUPPORTED. Sinon, il signalera l'erreur de l'archiveur qui a réclamé les données via (claimed). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Ouvre un fichier dans cette archive en lecture. Ce nom de fichier, (fnm), est en notation indépendante de la plateforme. Échoue si le fichier n'existe pas. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en écriture. Si le fichier n'existe pas, il doit être créé. S'il existe, il doit être tronqué à zéro octet. L'offset d'écriture doit être le début du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Supprime un fichier ou un répertoire dans l'archive. Cet appel est utilisé pour les fichiers et les répertoires ; il n'y a pas d'appel rmdir() séparé. Les répertoires ne sont destinés à être supprimés que s'ils sont vides. Si l'archive est en lecture seule, cette opération doit échouer.

Retourne non-zéro en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtient les métadonnées de base du fichier. En cas de succès, remplit tous les champs de (stat), en utilisant des valeurs par défaut raisonnables pour les champs qui s'appliquent à votre archive.

Retourne non-zéro en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Informations de compatibilité binaire. Ceci doit être défini à zéro pour le moment. Les futures versions de cette structure incrémenteront ce champ, afin que nous sachions ce qu'une implémentation donnée supporte. Nous continuerons probablement à supporter les versions plus anciennes à mesure que nous offrirons de nouvelles fonctionnalités, cependant.
