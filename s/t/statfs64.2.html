statfs(2) Manuel des appels système statfs(2)

NOM

statfs, fstatfs - obtenir des statistiques du système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/vfs.h>    /* ou <sys/statfs.h> */
int statfs(const char *chemin, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

À moins que vous n'ayez besoin du champ f_type, vous devriez plutôt utiliser l'interface standard statvfs(3).

DESCRIPTION

L'appel système statfs() renvoie des informations sur un système de fichiers monté. chemin est le nom de chemin d'un fichier quelconque dans le système de fichiers monté. buf est un pointeur vers une structure statfs définie approximativement comme suit :


struct statfs {
    __fsword_t f_type;    /* Type de système de fichiers (voir ci-dessous) */
    __fsword_t f_bsize;   /* Taille de bloc de transfert optimale */
    fsblkcnt_t f_blocks;  /* Blocs de données totaux dans le système de fichiers */
    fsblkcnt_t f_bfree;   /* Blocs libres dans le système de fichiers */
    fsblkcnt_t f_bavail;  /* Blocs libres disponibles pour
                             l'utilisateur non privilégié */
    fsfilcnt_t f_files;   /* Inodes totaux dans le système de fichiers */
    fsfilcnt_t f_ffree;   /* Inodes libres dans le système de fichiers */
    fsid_t     f_fsid;    /* ID du système de fichiers */
    __fsword_t f_namelen; /* Longueur maximale des noms de fichiers */
    __fsword_t f_frsize;  /* Taille du fragment (depuis Linux 2.6) */
    __fsword_t f_flags;   /* Options de montage du système de fichiers
                             (depuis Linux 2.6.36) */
    __fsword_t f_spare[xxx];
                    /* Octets de remplissage réservés pour une utilisation future */
};

La plupart de ces constantes MAGIC sont définies dans /usr/include/linux/magic.h, et certaines sont codées en dur dans les sources du noyau.

Le champ f_flags est un masque de bits indiquant les options de montage pour le système de fichiers. Il contient zéro ou plus des bits suivants :

ST_MANDLOCK
Le verrouillage obligatoire est autorisé sur le système de fichiers (voir fcntl(2)).
ST_NOATIME
Ne pas mettre à jour les temps d'accès ; voir mount(2).
ST_NODEV
Interdire l'accès aux fichiers spéciaux de périphériques sur ce système de fichiers.
ST_NODIRATIME
Ne pas mettre à jour les temps d'accès aux répertoires ; voir mount(2).
ST_NOEXEC
L'exécution de programmes est interdite sur ce système de fichiers.
ST_NOSUID
Les bits set-user-ID et set-group-ID sont ignorés par exec(3) pour les fichiers exécutables sur ce système de fichiers.
ST_RDONLY
Ce système de fichiers est monté en lecture seule.
ST_RELATIME
Mettre à jour atime par rapport à mtime/ctime ; voir mount(2).
ST_SYNCHRONOUS
Les écritures sont synchronisées immédiatement sur le système de fichiers (voir la description de O_SYNC dans open(2)).
ST_NOSYMFOLLOW (depuis Linux 5.10)
Les liens symboliques ne sont pas suivis lors de la résolution des chemins ; voir mount(2).

Personne ne sait ce que f_fsid est censé contenir (mais voir ci-dessous).

Les champs qui ne sont pas définis pour un système de fichiers particulier sont mis à 0.

fstatfs() renvoie les mêmes informations sur un fichier ouvert référencé par le descripteur fd.

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
(statfs()) La permission de recherche est refusée pour un composant du préfixe de chemin de chemin. (Voir aussi path_resolution(7).)
EBADF
(fstatfs()) fd n'est pas un descripteur de fichier ouvert valide.
EFAULT
buf ou chemin pointe vers une adresse invalide.
EINTR
L'appel a été interrompu par un signal ; voir signal(7).
EIO
Une erreur d'E/S s'est produite lors de la lecture du système de fichiers.
ELOOP
(statfs()) Trop de liens symboliques ont été rencontrés lors de la traduction de chemin.
ENAMETOOLONG
(statfs()) chemin est trop long.
ENOENT
(statfs()) Le fichier référencé par chemin n'existe pas.
ENOMEM
Mémoire noyau insuffisante disponible.

VERSIONS

Le champ f_fsid

Solaris, Irix et POSIX ont un appel système statvfs(2) qui retourne une struct statvfs (définie dans <sys/statvfs.h>) contenant un unsigned long f_fsid. Linux, SunOS, HP-UX, 4.4BSD ont un appel système statfs() qui retourne une struct statfs (définie dans <sys/vfs.h>) contenant un fsid_t f_fsid, où fsid_t est défini comme struct { int val[2]; }. Il en va de même pour FreeBSD, sauf qu'il utilise le fichier d'inclusion <sys/mount.h>.

L'idée générale est que f_fsid contient des informations aléatoires telles que la paire (f_fsid,ino) détermine de manière unique un fichier. Certains systèmes d'exploitation utilisent (une variation de) le numéro de périphérique, ou le numéro de périphérique combiné avec le type de système de fichiers. Plusieurs systèmes d'exploitation restreignent la divulgation du champ f_fsid au superutilisateur uniquement (et le mettent à zéro pour les utilisateurs non privilégiés), car ce champ est utilisé dans le descripteur de fichier du système de fichiers lorsqu'il est exporté NFS, et sa divulgation pose un problème de sécurité.

Sous certains systèmes d'exploitation, le fsid peut être utilisé comme deuxième argument de l'appel système sysfs(2).

NORMES

Linux.

HISTORIQUE

Le statfs() de Linux a été inspiré par celui de 4.4BSD (mais ils n'utilisent pas la même structure).

Les appels système originaux statfs() et fstatfs() de Linux n'ont pas été conçus en tenant compte des tailles de fichiers extrêmement grandes. Par la suite, Linux 2.6 a ajouté de nouveaux appels système statfs64() et fstatfs64() qui utilisent une nouvelle structure, statfs64. La nouvelle structure contient les mêmes champs que la structure statfs d'origine, mais les tailles de divers champs sont augmentées pour prendre en charge les grandes tailles de fichiers. Les fonctions d'enrobage statfs() et fstatfs() de glibc gèrent de manière transparente les différences du noyau.

LSB a déprécié les appels de bibliothèque statfs() et fstatfs() et nous demande d'utiliser statvfs(3) et fstatvfs(3) à la place.

NOTES

Le type __fsword_t utilisé pour divers champs dans la définition de la structure statfs est un type interne de glibc, non destiné à un usage public. Cela laisse le programmeur dans une situation délicate lorsqu'il essaie de copier ou de comparer ces champs à des variables locales dans un programme. L'utilisation de unsigned int pour de telles variables suffit sur la plupart des systèmes.

Certains systèmes n'ont que <sys/vfs.h>, d'autres systèmes ont également <sys/statfs.h>, le premier incluant le second. Il semble donc que l'inclusion du premier soit le meilleur choix.

BOGUES

De Linux 2.6.38 jusqu'à Linux 3.1 inclus, fstatfs() échouait avec l'erreur ENOSYS pour les descripteurs de fichiers créés par pipe(2).

VOIR AUSSI

stat(2), statvfs(3), path_resolution(7)
