stable(3perl) Guide de référence du programmeur Perl stable(3perl)

NOM

stable - Les fonctionnalités expérimentales facilitées, une fois que nous savons qu'elles sont stables

VERSION

version 0.035

SYNOPSIS

use stable 'lexical_subs', 'bitwise';
my sub is_odd($value) { $value & 1 }

DESCRIPTION

Le pragma expérimental facilite l'activation des expériences tout en désactivant les avertissements associés. Vous devriez lire à ce sujet, si vous ne savez pas encore ce qu'il fait.

Voir "use experimental" dans le code peut être effrayant. En fait, cela devrait probablement l'être ! Le code qui utilise des fonctionnalités expérimentales peut casser à l'avenir si l'équipe de développement de perl décide que l'expérience doit être modifiée. Lorsque les expériences deviennent stables, car les développeurs décident qu'elles sont un succès, les avertissements associés disparaissent. Lorsque cela se produit, elles peuvent généralement être activées avec "use feature".

C'est formidable si vous utilisez une version de perl où la fonctionnalité que vous souhaitez est déjà stable. Si vous utilisez une version plus ancienne de perl, cependant, il se peut que vous souhaitiez utiliser une fonctionnalité expérimentale qui émet toujours un avertissement, même s'il n'y a aucun risque à l'utiliser, car les versions ultérieures de perl ont cette fonctionnalité inchangée et maintenant stable.

Voici un exemple : La fonctionnalité "postderef" a été ajoutée dans perl 5.20.0. Dans perl 5.24.0, elle a été marquée comme stable. Son utilisation ne déclenchait plus d'avertissement. Le comportement de la fonctionnalité n'a pas changé entre 5.20.0 et 5.24.0. Cela signifie qu'il est parfaitement sûr d'utiliser la fonctionnalité sur 5.20 ou 5.22, même s'il y a un avertissement.

Dans ce cas, vous pourriez très légitimement ajouter "use experimental 'postderef'", mais le lecteur occasionnel peut toujours s'inquiéter en voyant cela. Le pragma "stable" existe pour activer les fonctionnalités expérimentales uniquement lorsqu'il est connu que leur comportement dans la perl en cours d'exécution est leur comportement stable.

Si vous essayez d'utiliser une fonctionnalité expérimentale qui n'est pas stable ou disponible sur la version de perl en cours d'exécution, une exception sera levée. Vous devez également veiller à avoir requis la version de "stable" dont vous avez besoin !

Si ce n'est pas immédiatement évident pourquoi, voici une petite explication :

  • "stable" est livré avec perl, à partir de perl v5.38.
  • Imaginez que v5.38 ajoute une fonctionnalité appelée "florps". Elle cessera d'être expérimentale en v5.42.
  • La version de "stable" qui accompagne perl v5.38 ne peut pas savoir que l'expérience florps réussira, vous ne pouvez donc pas "use stable 'florps'" sur la version de stable livrée avec v5.38, car elle ne peut pas voir l'avenir !
  • Vous devrez écrire "use stable 1.234 'florps'" pour indiquer que vous avez besoin de la version 1.234 de stable, qui est le moment où florps est devenu connu de stable.

Bien sûr, c'est un peu étrange, mais ça en vaut la peine ! La documentation de ce pragma vous indiquera la version de "stable" que vous devez requérir pour utiliser diverses fonctionnalités. Voir ci-dessous.

Actuellement, il n'y a que quelques fonctionnalités "stables" :

  • "bitwise" - stable depuis perl 5.22, disponible via stable 0.031
  • "isa" - stable depuis perl 5.32, disponible via stable 0.031
  • "lexical_subs" - stable depuis perl 5.22, disponible via stable 0.031

    Les sous-routines lexicales ont été ajoutées en 5.18, et leur conception n'a pas changé, mais des bugs importants les rendent dangereuses à utiliser avant 5.22.

  • "postderef" - stable depuis perl 5.20, disponible via stable 0.031
  • "const_attr" - stable depuis perl 5.22, disponible via stable 0.032
  • "for_list" - stable depuis perl 5.36, disponible via stable 0.032
