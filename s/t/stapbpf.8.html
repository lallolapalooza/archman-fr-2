NOM

stapbpf - runtime BPF de systemtap

SYNTAXE

stapbpf [ OPTIONS ] MODULE

DESCRIPTION

Le programme stapbpf est le backend BPF de l'outil Systemtap. Il attend un fichier bpf-elf produit par le frontend stap, lorsqu'il est exécuté avec --runtime=bpf.

La division de l'outil systemtap en un frontend et un backend permet à un utilisateur de compiler un script systemtap sur une machine de développement qui possède les informations de débogage nécessaires pour compiler le script, puis de transférer l'objet partagé résultant vers une machine de production qui n'a aucun outil de développement ou information de débogage installée.

Veuillez vous référer à stappaths(7) pour le numéro de version, ou exécutez

$ rpm -q systemtap # (pour Fedora/RHEL)
$ apt-get -v systemtap # (pour Ubuntu)

OPTIONS

Le programme stapbpf prend en charge les options suivantes. Toute autre option affiche une liste des options prises en charge.

-v
Mode verbeux.
-V
Affiche le numéro de version et quitte.
-w
Supprime les avertissements du script.
-h
Affiche le message d'aide.
-x PID
La variable '_stp_target' sera définie sur PID.
-o FICHIER
Envoie la sortie vers FICHIER.

ARGUMENTS

MODULE est le chemin d'accès à un fichier bpf-elf produit par le frontend stap, lorsqu'il est exécuté avec --runtime=bpf.

EXEMPLES

Voici un exemple très basique pour générer un module stapbpf. Tout d'abord, utilisez stap pour compiler un script. Le programme stap rapportera le nom du module résultant dans le répertoire de travail courant.

$ stap --runtime=bpf -p4 -e 'probe begin { printf("Hello World!\n"); exit() }'
stap_28784.bo

Exécutez stapbpf avec le chemin d'accès au module comme argument.

$ stapbpf ./stap_28784.bo
Hello World!

Si l'option -p4 est omise, stap invoquera automatiquement stapbpf.

LIMITATIONS

Ce runtime est à un stade précoce de développement et manque actuellement de prise en charge pour un certain nombre de fonctionnalités disponibles dans le runtime par défaut. Un sous-ensemble des points de sonde suivants est pris en charge :

begin
end
kernel.*
process.*
timer.*
perf.*
procfs.*

En général, les sondes basées sur les infrastructures kprobes, uprobes, tracepoint et perf sont prises en charge. Voir stapprobes(3stap) pour plus d'informations sur les points de sonde et les infrastructures de traçage sur lesquelles ils sont basés.

Les boucles for, foreach et while ne sont utilisables que dans les sondes begin et end. Les instructions try ne sont pas prises en charge.

Il existe une prise en charge limitée des opérations sur les chaînes de caractères. Les variables et les littéraux de chaînes sont limités à 64 caractères, à l'exception des chaînes de format printf, qui sont limitées à 256 caractères.

Un sous-ensemble des fonctionnalités d'agrégation statistiques est disponible, avec prise en charge uniquement des fonctions d'extraction @count(), @sum(), @avg().

Le nom du fichier bpf-elf produit par le frontend stap ne doit pas être modifié.
