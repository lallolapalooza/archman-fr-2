STAP-EXPORTER(8) Manuel de l'administrateur système STAP-EXPORTER(8)

NOM

stap-exporter - mécanisme d'interopérabilité systemtap-prometheus

SYNTAXE

stap-exporter [ OPTIONS ]

DESCRIPTION

stap-exporter exécute un ensemble de scripts systemtap et relaie leurs sorties procfs à des clients HTTP distants à la demande. Cela rend les scripts systemtap directement utilisables en tant qu'exportateurs prometheus individuels. Ceci est assisté par un ensemble de macros fournies dans le fichier tapset prometheus.stpm.

OPTIONS

Le programme stap-exporter supporte les options suivantes.

-p --port PORT
Écoute sur le port TCP spécifié pour les requêtes HTTP. Le port 9900 est utilisé par défaut.
-k --keepalive KEEPALIVE
Les scripts qui s'exécutent plus longtemps que KEEPALIVE secondes après la dernière requête sont arrêtés. Il n'y a pas de délai d'expiration par défaut, donc une fois démarrés, les scripts restent en cours d'exécution.
-s --scripts SCRIPTS
Recherche dans le répertoire SCRIPTS les fichiers *.stp à exposer. La valeur par défaut est donnée dans la page de manuel stappaths.7.
-h --help
Affiche le message d'aide.

FONCTIONNEMENT

Au démarrage, stap-exporter recherche dans le répertoire spécifié par le répertoire -s les fichiers nommés *.stp. Le nom de chaque fichier devient disponible en tant que composant d'URL pour les requêtes HTTP GET ultérieures. Par exemple, lorsqu'un client HTTP demande /foo.stp, et que le script foo.stp (exécutable / script shell) était connu, il est alors lancé avec des options stap supplémentaires pour définir un nom de module. Ce nom de module prévisible permet à stap-exporter de transcrire un fichier procfs de ce script en cours d'exécution vers les clients HTTP.

Après une période de non-utilisation configurable (option -k ou --keepalive), un script systemtap est terminé. Il sera redémarré si un client le demande.

Tous les fichiers dont le nom inclut la sous-chaîne autostart sont démarrés immédiatement (et redémarrés s'ils s'arrêtent), plutôt qu'à la demande. Ceux-ci sont exclus des considérations de maintien en activité. Les scripts qui peuvent être trop lents à démarrer ou qui souhaitent signaler des statistiques à long terme sont des candidats pour ce traitement.

EXEMPLE

Supposons que example.stp contienne le script suivant. Il compte les appels système read sur une base par thread et par CPU.

global arr%
probe syscall.read {
    arr[tid(), cpu()]++
}
probe prometheus {
    @prometheus_dump_array2(arr, "count", "tid", "cpu")
}

Les macros prometheus_dump_array sont utilisées pour produire des métriques à partir d'un tableau. Systemtap fournit une macro prometheus_dump_arrayN pour toutes les valeurs de N de 1 à 8. Le premier argument des macros représente un tableau avec des clés à N éléments. Le deuxième argument représente le nom de la métrique. Les N arguments restants représentent les noms des labels de la métrique.

On peut lancer stap-exporter en tant que root, ou avec des privilèges stapdev équivalents, puis après un bref délai, utiliser n'importe quel client web pour récupérer les données :

# stap-exporter -p 9999 -k 60 -c . &
$ curl http://localhost:9999/example.stp
Refresh page to access metrics.  [...]
$ curl http://localhost:9999/example.stp
count{tid="12614",cpu="0"} 9
count{tid="12170",cpu="3"} 107
count{tid="1802",cpu="0"} 33687
count{tid="12617",cpu="1"} 99
[...]

La même URL peut être ajoutée à la section scrape_config d'un serveur Prometheus, ou à un répertoire config.d de pmdaprometheus du Performance Co-Pilot, pour collecter ces données dans un système de surveillance.

SURETÉ ET SÉCURITÉ

Le serveur stap-exporter ne met en œuvre aucun mécanisme de sécurité particulier. Par conséquent, le déploiement dans un environnement non fiable nécessite de prendre en compte :

sélection des scripts
Étant donné que les scripts systemtap sont exécutés sous les privilèges du processus stap-exporter (probablement root), l'administrateur système doit sélectionner uniquement des scripts sûrs et robustes. Vérifiez les scripts installés par défaut avant d'activer le service. Les scripts ne peuvent pas prendre d'entrée des clients web.
pare-feu TCP/IP
Étant donné que stap-exporter expose le port TCP/HTTP sélectionné à toutes les interfaces de l'hôte, il peut être nécessaire d'ajouter un pare-feu. Il est peu probable qu'il soit approprié d'exposer un tel service à un réseau non fiable.
filtrage HTTP
Étant donné que stap-exporter expose les scripts systemtap configurés à tous les clients HTTP sans authentification, il peut être nécessaire de le protéger contre les abus, même sur des réseaux largement fiables. Un proxy HTTP peut être utilisé pour imposer des filtres basés sur l'URL, le client, l'utilisation ou l'authentification.
HTTPS
Étant donné que stap-exporter ne parle que HTTP brut, un proxy HTTP peut être utilisé pour prendre en charge les protocoles sécurisés HTTPS.
