stoken(1) Manuel des commandes générales stoken(1)

NOM

stoken - jeton logiciel pour l'authentification cryptographique

SYNTAXE

stoken [jeton_code] [--stdin] [--force] [--next] [options]

stoken import {--file=fichier | --token=chaîne_jeton} [--force] [options]

stoken setpin [options]

stoken setpass [options]

stoken show [--seed] [options]

stoken export [{--blocks | --iphone | --android | --v3 | --sdtid | --qr=fichier.png | --show-qr}] [options]

stoken issue [--template=fichier]

stoken help

stoken version

DESCRIPTION

stoken est un jeton logiciel compatible avec les jetons RSA SecurID 128 bits (AES). L'interface en ligne de commande fournit des fonctionnalités pour importer de nouveaux jetons, afficher le jeton_code actuel, chiffrer la graine avec un mot de passe spécifié par l'utilisateur, stocker le code PIN de l'utilisateur à côté du jeton, et visualiser ou exporter les données du jeton.

UTILISATION DE BASE

Utilisez stoken import pour décoder une chaîne de jeton et l'écrire dans ~/.stokenrc. Cela peut vous demander un identifiant de périphérique et/ou un mot de passe, selon les options que votre administrateur a utilisées pour créer le jeton. La chaîne de jeton peut être fournie sur la ligne de commande, ou lue à partir d'un fichier texte.

stoken détectera automatiquement les types de chaînes de jetons suivants :

286510182209303756117707012447003320623006...
29658-21098-45467-64675-65731-01441-11337...
Chaînes "ctf" (format de jeton compressé) purement numériques (81 chiffres), avec ou sans tirets. Celles-ci peuvent avoir été fournies telles quelles, ou dérivées d'un fichier sdtid par le programme RSA TokenConverter.
com.rsa.securid.iphone://ctf?ctfData=229639330774927764401...
Chaînes de jetons compatibles iPhone.
http://127.0.0.1/securid/ctf?ctfData=250494932146245277466...
http://127.0.0.1/securid/ctf?ctfData=AwAAfBc3QSopPxxjLGnxf...
Chaînes de jetons compatibles Android.
<?xml version=...
Fichiers XML au format RSA sdtid. Ceux-ci doivent être importés à partir d'un fichier : stoken import --file=FICHIER.SDTID.

Les jetons fournis sous forme de codes QR peuvent être reconvertis en URIs standard en exécutant zbarimg(1) sur le fichier image.

L'identifiant du périphérique, s'il est utilisé, peut être vu dans le menu "à propos" de l'application jeton logiciel RSA sur le téléphone. Les chaînes ctf numériques et les jetons de smartphone liés à un identifiant de périphérique contiennent une graine chiffrée à l'aide de l'identifiant du périphérique, donc cet identifiant doit être fourni avant que stoken puisse importer le jeton avec succès. Les fichiers sdtid peuvent être importés sans connaître l'identifiant du périphérique, tant que le mot de passe (s'il y en a un) est connu.

Par défaut, stoken import refusera d'écraser un jeton existant dans ~/.stokenrc. Le commutateur --force outrepasse cette vérification.

stoken import vous demandera normalement un nouveau mot de passe, qui est utilisé pour chiffrer la graine avant de la stocker dans ~/.stokenrc. Ceci peut être contourné en entrant un mot de passe vide, ou en spécifiant --new-password='' sur la ligne de commande. Il est recommandé de choisir une phrase de passe plus longue et difficile à deviner à cet effet.

Après qu'un jeton ait été importé, l'exécution de stoken sans arguments vous demandera le mot de passe ou le code PIN requis, puis affichera le jeton_code actuel.

Les jetons_codes sont calculés à partir des données de la graine brute (déchiffrée), de l'heure actuelle, et du code PIN. Si la même graine est installée sur plusieurs périphériques, ils devraient tous produire des jetons_codes identiques. S'ils ne le font pas, vérifiez le réglage du fuseau horaire et envisagez d'utiliser NTP pour synchroniser l'heure système avec une source de référence fiable.

stoken setpin peut être utilisé pour enregistrer le code PIN dans ~/.stokenrc. Tous les jetons ne nécessitent pas de code PIN ; cela peut être configuré par l'administrateur SecurID lors de la génération de nouveaux jetons. La définition d'un code PIN vide supprimera le code PIN de ~/.stokenrc de sorte que l'utilisateur soit invité à le saisir à chaque fois qu'il sera requis. Voir la section CONSIDÉRATIONS DE SÉCURITÉ ci-dessous pour des détails supplémentaires.

stoken setpass chiffre la graine et le code PIN (s'il est présent) dans ~/.stokenrc avec un mot de passe ou une phrase de passe sélectionnable par l'utilisateur. Si un mot de passe vide est entré, le mot de passe sera supprimé. Voir la section CONSIDÉRATIONS DE SÉCURITÉ ci-dessous pour des détails supplémentaires.

VISUALISATION DES JETONS

stoken show affiche des informations sur le jeton actuel, généralement lues à partir de ~/.stokenrc. L'option --seed affiche les octets de la graine chiffrée et déchiffrée (qui doivent être traités comme des données sensibles, car ils peuvent être utilisés pour dériver les jetons_codes).

stoken export traduit le jeton actuel dans un format approprié pour l'importation vers un autre périphérique.

stoken issue génère un nouveau jeton logiciel au format XML sdtid. Un fichier modèle, lui-même au format sdtid, peut être fourni pour remplacer tout ou partie des champs lisibles par l'homme. Cela permettrait de spécifier des numéros de série, des dates d'expiration, des noms d'utilisateur, etc. appropriés. Si les champs Secret, Seed, ou MAC sont présents dans le fichier modèle, ils seront ignorés.

OPTIONS GLOBALES

--rcfile=fichier
Utilise un fichier de configuration .stokenrc alternatif. Ceci est typiquement utilisé pour supporter plusieurs jetons sur le même compte utilisateur UNIX. Notez que le fichier .stokenrc stocke des données supplémentaires (comme le code PIN), il ne peut donc pas être analysé comme une chaîne de jeton "brute" par stoken --file.
--password=mot_de_passe, -p mot_de_passe
Utilise un mot de passe fourni depuis la ligne de commande, au lieu de demander à l'utilisateur. Voir les notes dans CONSIDÉRATIONS DE SÉCURITÉ ci-dessous.
--pin=pin, -n pin
Utilise un code PIN fourni depuis la ligne de commande, au lieu de demander à l'utilisateur. Voir les notes dans CONSIDÉRATIONS DE SÉCURITÉ ci-dessous. Si vous enregistrez votre code PIN dans ~/.stokenrc, notez que --pin=0000 est souvent requis lors de l'activation d'un nouveau jeton logiciel pour la première fois.
--devid=id_périphérique
Utilise un identifiant de périphérique fourni depuis la ligne de commande pour déchiffrer le jeton. Un jeton peut être lié à un identifiant de périphérique de classe GUID (c'est-à-dire un certain type de périphérique, comme "iPhone" ou "Android"), un identifiant de périphérique unique (une unité spécifique), ou rien. stoken tentera de détecter automatiquement les correspondances avec un GUID de classe, mais dans de rares cas, cela peut entraîner de faux positifs en raison de collisions de hachage. Dans ces cas, l'identifiant de périphérique lié doit être spécifié sur la ligne de commande pour outrepasser la détection automatique.

OPTIONS D'EXPORTATION

--new-password=mot_de_passe
Fournit le mot de passe de chiffrement depuis la ligne de commande pour les opérations qui écrivent une chaîne de jeton ou un fichier .stokenrc : import, export, setpass, et issue. Voir les notes dans CONSIDÉRATIONS DE SÉCURITÉ ci-dessous.
--keep-password
Si le jeton dans le fichier .stokenrc est protégé par un mot de passe, conservez le même mot de passe lors de l'exportation du jeton. Par défaut, l'opération export ne chiffrera pas le jeton avec un mot de passe.

CONSIDÉRATIONS DE SÉCURITÉ

L'utilisation des jetons logiciels implique de stocker des données sensibles (la graine du jeton) sur votre système local. Par défaut, stoken chiffre la graine en utilisant un mot de passe que vous fournissez.

Il est possible de stocker votre code PIN dans le fichier ~/.stokenrc, ce qui permet d'éviter de le saisir à chaque fois. Cependant, si le fichier ~/.stokenrc est compromis, votre code PIN sera également révélé.

L'utilisation des options --password et --pin sur la ligne de commande entraîne l'affichage de vos informations d'identification dans l'historique de votre shell. Pour cette raison, il est fortement recommandé de ne pas utiliser ces options si vous vous souciez de la sécurité de votre système.

Si vous avez configuré un mot de passe pour chiffrer votre jeton (par exemple, en utilisant stoken setpass), vous devrez le fournir lorsque vous utiliserez stoken pour afficher ou exporter le jeton.

Le fichier ~/.stokenrc est une base de données de jetons chiffrés. Il est essentiel de le protéger contre tout accès non autorisé. Le chiffrement par mot de passe fourni par stoken setpass est une mesure de sécurité supplémentaire.

EXEMPLES

Pour importer un nouveau jeton à partir d'une chaîne de texte :

$ stoken import --token=29658-21098-45467-64675-65731-01441-11337

Pour importer un jeton à partir d'un fichier CTF :

$ stoken import --file=MonJeton.ctf

Pour afficher le jeton_code actuel :

$ stoken

Pour enregistrer votre code PIN :

$ stoken setpin

Pour chiffrer le fichier ~/.stokenrc avec un mot de passe :

$ stoken setpass

Pour exporter le jeton dans un format compatible iPhone :

$ stoken export --iphone

Pour exporter le jeton dans un format QR code :

$ stoken export --qr=mon_jeton.png

Pour afficher la graine déchiffrée (données sensibles) :

$ stoken show --seed

--blocks, --iphone, --android, --v3
Utilisé avec la commande export pour sélectionner le format de sortie. Voir les exemples dans UTILISATION DE BASE. Par défaut, la commande export affichera une chaîne non formatée de 81 chiffres sur la sortie standard.
--sdtid, --xml
Ces options sont des synonymes. Les deux exportent un jeton sur la sortie standard au format XML sdtid de RSA.

--show-qr
Encode le jeton sous forme de code QR et l'affiche immédiatement à l'écran. Cela nécessite que le programme qrencode soit installé. Si la variable d'environnement QR_VIEWER est définie, stoken utilisera ce programme comme visionneuse préférée. Sinon, il essaiera d'exécuter quelques visionneuses d'images courantes sous Linux, et abandonnera si aucune d'entre elles n'existe.
--template=fichier
Utilisé avec les commandes export ou issue pour remplacer des champs dans la sortie XML. Le fichier modèle doit ressembler à n'importe quel fichier sdtid standard, mais tous les champs sont facultatifs et prendront par défaut des valeurs raisonnablement sensées s'ils sont omis. Ceci peut être utilisé pour forcer la sortie XML à utiliser un numéro de série, un nom d'utilisateur, une date d'expiration, etc. spécifiques. Les sommes de contrôle MAC correctes seront (re)calculées sur les valeurs fournies. Voir le répertoire examples dans la distribution source pour plus d'informations.

AUTRES OPTIONS

--use-time={unix_time|+offset|-offset}
Au lieu de générer un code de jeton basé sur l'heure actuelle, force une heure spécifique, ou ajuste l'heure actuelle en fonction d'un décalage positif ou négatif (spécifié en secondes). Ceci est uniquement utilisé à des fins de test.
--next
Génère le code de jeton suivant au lieu du code de jeton actuel. Pour un jeton de 60 secondes, cela équivaut à --use-time=+60.
--stdin, -s
Lors de la génération d'un code de jeton qui nécessite soit un mot de passe, soit un code PIN, lire le mot de passe ou le code PIN en une seule ligne depuis l'entrée standard. Ceci est destiné à permettre aux programmes externes d'appeler stoken pour générer des mots de passe à usage unique sans intervention de l'utilisateur; voir UTILISATION NON INTERACTIVE ci-dessous.
--force, -f
Ignore les vérifications de date d'expiration du jeton (pour tokencode) ou les vérifications d'écrasement de jeton (pour import).
--batch, -b
Arrête avec un code de sortie d'erreur si une entrée utilisateur est requise. Destiné aux opérations automatisées et aux tests.
--file=fichier
Lit une chaîne ctf, une URI Android/iPhone ou un jeton XML sdtid depuis fichier au lieu de la configuration .stokenrc. La plupart des commandes stoken acceptent ce drapeau, mais on s'attend à ce que l'utilisateur typique enregistre son jeton dans ~/.stokenrc au lieu de le fournir manuellement à chaque invocation. Typiquement, --file et --token ne sont utilisés que pour la commande import.
--token=chaine_token
Utilise un jeton de la ligne de commande au lieu du fichier .stokenrc. Voir les notes ci-dessus sur --file.
--random
Génère un jeton aléatoire à la volée. Utilisé uniquement pour les tests ou les démonstrations. Ces jetons ne doivent pas être utilisés pour une authentification réelle.
--help, -h
Affiche des informations d'utilisation de base.
--version, -v
Affiche les informations de version.

CONSIDÉRATIONS DE SÉCURITÉ

Les jetons logiciels, contrairement aux jetons matériels, sont relativement faciles à répliquer. Les systèmes qui stockent les graines de jetons logiciels doivent être soigneusement gardés pour empêcher toute divulgation non autorisée. L'utilisation du chiffrement complet du disque, comme TrueCrypt, est fortement recommandée pour les ordinateurs portables et autres appareils portables qui sont facilement perdus ou volés.

stoken permet aux utilisateurs de stocker leur code PIN dans ~/.stokenrc pour permettre la génération automatisée (scriptable) de codes de jetons, mais les risques de cette approche doivent être soigneusement pesés par rapport aux avantages.

L'utilisation de la commande setpass pour chiffrer la graine et le code PIN dans ~/.stokenrc offre un certain degré de protection contre l'accès non autorisé, mais ne couvre pas nécessairement tous les vecteurs d'attaque possibles. Un hôte qui est déjà compromis (par exemple, exécutant un enregistreur de frappe) ne fournira pas une protection adéquate pour les graines stockées sur celui-ci.

Les mots de passe de chiffrement de stoken peuvent comporter jusqu'à 40 caractères. Une phrase de passe plus longue composée de plusieurs mots aléatoires peut offrir une meilleure protection contre les attaques par force brute qu'un mot de passe plus court.

La saisie d'un mot de passe ou d'un code PIN sur la ligne de commande est généralement dangereuse sur les systèmes multi-utilisateurs, car d'autres utilisateurs peuvent être en mesure de visualiser les arguments de la ligne de commande dans ps ou des utilitaires similaires. La ligne de commande peut également être mise en cache dans les fichiers d'historique du shell.

L'encodage des jetons QR peut exposer les données de la graine via ps, et l'option --show-qr écrit des fichiers PNG temporaires dans /tmp.

stoken tente de verrouiller les pages pour empêcher le transfert sur disque, mais ne supprime pas les secrets de la mémoire du processus.

UTILISATION NON INTERACTIVE

D'autres applications, telles que les clients VPN, peuvent souhaiter appeler stoken de manière non interactive pour générer des mots de passe à usage unique. Trois modes d'utilisation sont pris en charge, en fonction du niveau de sécurité (et/ou de commodité) requis :

Pas de mot de passe ou de PIN

L'utilisateur configure stoken pour afficher un code de jeton immédiatement dès l'invocation, sans aucune invite, en utilisant setpin pour stocker le code PIN dans ~/.stokenrc et en utilisant setpass pour définir un mot de passe vide. L'autre application peut alors appeler stoken --batch et lire le code de jeton via un tube depuis la sortie standard.

Cela n'offre aucune sécurité pour la graine, mais peut être utile dans les applications où l'authentification (ou la ré-authentification) est fréquente ou où une opération sans surveillance est requise.

Sauvegarder le PIN et définir un mot de passe

L'utilisateur configure stoken pour chiffrer les secrets de ~/.stokenrc avec un mot de passe en utilisant setpass, puis enregistre le code PIN avec setpin. Le code PIN et la graine seront tous deux chiffrés avec le mot de passe. L'autre application demandera le mot de passe à l'utilisateur, appellera ensuite stoken --stdin, écrira le mot de passe dans l'entrée standard de stoken via un tube, et lira le code de jeton depuis la sortie standard de stoken.

Pas de mot de passe ; demander le PIN

Similaire à ce qui précède, mais définissez un mot de passe vide en utilisant setpass, ne sauvegardez pas le code PIN dans ~/.stokenrc, et passez le code PIN à stoken --stdin via l'entrée standard.

stoken(1)

UTILISATION DE BASE

stoken permet de générer des tokens pour l'authentification à deux facteurs à partir d'une clé secrète partagée.

VISUALISATION DES TOKENS

stoken [OPTIONS] [USER]

  • -s, --show-secret : Affiche la clé secrète partagée pour l'utilisateur spécifié.
  • -d, --show-default : Affiche la clé secrète partagée de l'utilisateur par défaut.
  • -l, --list-users : Liste tous les utilisateurs configurés.

OPTIONS GLOBALES

stoken [OPTIONS]

  • -h, --help : Affiche un message d'aide.
  • -v, --version : Affiche des informations sur la version.
  • -c, --config FICHIER : Spécifie un fichier de configuration alternatif.

OPTIONS D'EXPORTATION

stoken [OPTIONS]

  • -e, --export FICHIER : Exporte la configuration vers un fichier spécifié.

AUTRES OPTIONS

stoken [OPTIONS]

  • -a, --add USER : Ajoute un nouvel utilisateur. Demande la clé secrète et le type d'algorithme.
  • -r, --remove USER : Supprime un utilisateur.
  • -u, --update USER : Met à jour la clé secrète d'un utilisateur.
  • -t, --time TIME : Spécifie l'heure pour générer le token (format HH:MM:SS). Par défaut, l'heure actuelle.
  • -o, --offset OFFSET : Spécifie un décalage horaire en secondes.

CONSIDÉRATIONS DE SÉCURITÉ

La clé secrète partagée est sensible et doit être protégée. Évitez de la stocker en texte clair sur des systèmes non sécurisés.

UTILISATION NON INTERACTIVE

Pour une utilisation non interactive, vous pouvez utiliser l'option -s pour obtenir le secret et le passer à un autre processus, ou utiliser le fichier de configuration pour stocker les secrets de manière plus sécurisée.
