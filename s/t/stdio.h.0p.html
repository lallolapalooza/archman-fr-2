stdio.h(0P) Manuel du programmeur POSIX stdio.h(0P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

stdio.h — Entrées/sorties tamponnées standard

SYNOPIS

#include <stdio.h>

DESCRIPTION

Certaines des fonctionnalités décrites sur cette page de référence étendent la norme ISO C. Les applications doivent définir la macro de test de fonctionnalité appropriée (voir le volume Interfaces système de POSIX.1‐2017, Section 2.2, L'environnement de compilation) pour rendre visibles ces symboles dans cet en-tête.

L'en-tête <stdio.h> doit définir les types de données suivants via typedef :

FILE
Une structure contenant des informations sur un fichier.
fpos_t
Un type non-tableau contenant toutes les informations nécessaires pour spécifier de manière unique chaque position dans un fichier.
off_t
Tel que décrit dans <sys/types.h>.
size_t
Tel que décrit dans <stddef.h>.
ssize_t
Tel que décrit dans <sys/types.h>.
va_list
Tel que décrit dans <stdarg.h>.

L'en-tête <stdio.h> doit définir les macros suivantes qui se développeront en expressions constantes entières :

BUFSIZ
Taille des tampons de <stdio.h>. Ceci doit se développer en une valeur positive.
L_ctermid
Taille maximale d'un tableau de caractères pour contenir la sortie de ctermid().
L_tmpnam
Taille maximale d'un tableau de caractères pour contenir la sortie de tmpnam().

L'en-tête <stdio.h> doit définir les macros suivantes qui se développeront en expressions constantes entières avec des valeurs distinctes :

_IOFBF
Entrée/sortie entièrement tamponnée.
_IOLBF
Entrée/sortie tamponnée par ligne.
_IONBF
Entrée/sortie non tamponnée.

L'en-tête <stdio.h> doit définir les macros suivantes qui se développeront en expressions constantes entières avec des valeurs distinctes :

SEEK_CUR
Déplacement par rapport à la position actuelle.
SEEK_END
Déplacement par rapport à la fin du fichier.
SEEK_SET
Déplacement par rapport au début du fichier.

L'en-tête <stdio.h> doit définir les macros suivantes qui se développeront en expressions constantes entières dénotant les limites de l'implémentation :

{FILENAME_MAX}
Taille maximale en octets du chemin le plus long que l'implémentation garantit pouvoir ouvrir.
{FOPEN_MAX}
Nombre de flux que l'implémentation garantit pouvoir ouvrir simultanément. La valeur est au moins de huit.
{TMP_MAX}
Nombre minimum de noms de fichiers uniques générés par tmpnam(). Nombre maximum d'appels fiables à tmpnam() par une application. La valeur de {TMP_MAX} est au moins de 25.

Sur les systèmes conformes XSI, la valeur de {TMP_MAX} est au moins de 10000.

L'en-tête <stdio.h> doit définir la macro suivante qui se développera en une expression constante entière de type int et de valeur négative :

EOF
Valeur de retour de fin de fichier.

L'en-tête <stdio.h> doit définir NULL tel que décrit dans <stddef.h>.

L'en-tête <stdio.h> doit définir la macro suivante qui se développera en une constante de chaîne :

P_tmpdir
Préfixe de répertoire par défaut pour tempnam().

L'en-tête <stdio.h> doit définir les macros suivantes qui se développeront en expressions de type ``pointeur vers FILE'' pointant vers les objets FILE associés respectivement aux flux d'erreur standard, d'entrée et de sortie :

stderr
Flux de sortie d'erreur standard.
stdin
Flux d'entrée standard.
stdout
Flux de sortie standard.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Étant donné que les flux d'E/S standard peuvent utiliser un descripteur de fichier sous-jacent pour accéder au fichier associé à un flux, les développeurs d'applications doivent être conscients que {FOPEN_MAX} flux peuvent ne pas être disponibles si des descripteurs de fichiers sont utilisés pour accéder à des fichiers qui ne sont pas associés à des flux.

RATION

Le symbole EOF est une valeur constante entière qui est distincte de toute valeur de caractère de 8 bits valide. Les applications qui lisent ou écrivent des données octet par octet en utilisant les fonctions de flux et qui supposent que les résultats de ces opérations sont des caractères de 8 bits (ce qui signifie qu'ils sont convertis en un type entier sans signe) peuvent trouver que la valeur de fin de fichier EOF n'est pas représentée comme une valeur positive dans le type int. Par conséquent, EOF est définie comme une valeur entière négative afin d'être distincte de tous les caractères.

ORIENTATIONS FUTURES

Le symbole ctermid() est obsolète et sera supprimé dans une future version de la norme.

NALE

Il existe un conflit entre la norme ISO C et la définition POSIX de la macro {TMP_MAX} qui est abordé par la norme ISO/IEC 9899:1999, Rapport d'anomalie 336. La norme POSIX est en accord avec le compte rendu public de la réponse au Rapport d'anomalie. Ce changement n'a pas encore été publié dans le cadre de la norme ISO C.
