DESCRIPTION

La fonction vis() copie dans dst une chaîne qui représente le caractère c. Si c n'a pas besoin d'être encodé, il est copié tel quel. La chaîne est terminée par un caractère nul, et un pointeur vers la fin de la chaîne est retourné. La longueur maximale d'un encodage est de quatre octets (sans compter le NUL final) ; par conséquent, lors de l'encodage d'un ensemble de caractères dans un tampon, la taille du tampon doit être quatre fois le nombre d'octets encodés, plus un pour le NUL final. Le paramètre flag est utilisé pour modifier la plage par défaut de caractères considérés pour l'encodage et pour modifier la représentation visuelle. Le caractère additionnel, nextc, n'est utilisé que lors de la sélection du format d'encodage VIS_CSTYLE (expliqué ci-dessous).

Les fonctions strvis(), stravis(), strnvis(), strvisx(), et strnvisx() copient dans dst une représentation visuelle de la chaîne src. Les fonctions strvis() et strnvis() encodent les caractères de src jusqu'au premier NUL. Les fonctions strvisx() et strnvisx() encodent exactement len caractères de src (ceci est utile pour encoder un bloc de données qui peut contenir des NUL). Les deux formes terminent dst par un NUL. La taille de dst doit être quatre fois le nombre d'octets encodés depuis src (plus un pour le NUL). Les deux formes retournent le nombre de caractères dans dst (sans inclure le NUL final). Ceci est utile lors du traitement de caractères individuels lorsque le paramètre régional peut être défini sur autre chose que le paramètre régional des caractères dans les données d'entrée.

Les fonctions svis(), snvis(), strsvis(), strsnvis(), strsvisx(), strsnvisx(), et strsenvisx() correspondent à vis(), nvis(), strvis(), strnvis(), strvisx(), strnvisx(), et strenvisx() mais ont un argument supplémentaire extra, pointant vers une liste de caractères terminée par NUL. Ces caractères seront copiés encodés ou échappés par une barre oblique inverse dans dst. Ces fonctions sont utiles, par exemple, pour supprimer la signification spéciale de certains caractères pour les shells.

L'encodage est une représentation unique et inversible composée entièrement de caractères graphiques ; il peut être décodé sous sa forme originale à l'aide des fonctions unvis(3bsd), strunvis(3bsd) ou strnunvis(3bsd).

Il y a deux paramètres qui peuvent être contrôlés : la plage de caractères qui sont encodés (s'applique uniquement à vis(), nvis(), strvis(), strnvis(), strvisx(), et strnvisx()), et le type de représentation utilisé. Par défaut, tous les caractères non graphiques, à l'exception de l'espace, de la tabulation et du saut de ligne, sont encodés (voir isgraph(3)). Les indicateurs suivants modifient ce comportement :

VIS_DQ
Encodage également des guillemets doubles
VIS_GLOB
Encodage également des caractères magiques (‘*’, ‘?’, ‘[’, et ‘#’) reconnus par glob(3).
VIS_SHELL
Encodage également des métacaractères utilisés par les shells (en plus des caractères globaux) : (‘'’, ‘`’, ‘"’, ‘;’, ‘&’, ‘<’, ‘>’, ‘(’, ‘)’, ‘|’, ‘]’, ‘\’, ‘$’, ‘!’, ‘^’, et ‘~’).
VIS_SP
Encodage également de l'espace.
VIS_TAB
Encodage également de la tabulation.
VIS_NL
Encodage également du saut de ligne.
VIS_WHITE
Synonyme de VIS_SP | VIS_TAB | VIS_NL.
VIS_META
Synonyme de VIS_WHITE | VIS_GLOB | VIS_SHELL.
VIS_SAFE
Encodage uniquement des caractères « non sécurisés ». Non sécurisé signifie des caractères de contrôle qui peuvent amener les terminaux courants à effectuer des fonctions inattendues. Actuellement, cette forme permet de ne pas encoder l'espace, la tabulation, le saut de ligne, le retour arrière, le signal sonore et le retour chariot, en plus de tous les caractères graphiques.

(Les indicateurs ci-dessus n'ont aucun effet pour svis(), snvis(), strsvis(), strsnvis(), strsvisx(), et strsnvisx(). Lors de l'utilisation de ces fonctions, placez tous les caractères graphiques à encoder dans un tableau pointé par extra. En général, le caractère barre oblique inverse doit être inclus dans ce tableau, voir l'avertissement sur l'utilisation de l'indicateur VIS_NOSLASH ci-dessous).

Il existe six formes d'encodage. Toutes les formes utilisent le caractère barre oblique inverse ‘\’ pour introduire une séquence spéciale ; deux barres obliques inverses sont utilisées pour représenter une vraie barre oblique inverse, sauf VIS_HTTPSTYLE qui utilise ‘%’, ou VIS_MIMESTYLE qui utilise ‘=’. Ce sont les formats visuels :

(par défaut)
Utiliser un ‘M’ pour représenter les métacaractères (caractères avec le 8ème bit défini), et utiliser un accent circonflexe ‘^’ pour représenter les caractères de contrôle (voir iscntrl(3)). Les formats suivants sont utilisés :
\^C
Représente le caractère de contrôle ‘C’. Couvre les caractères ‘\000’ à ‘\037’, et ‘\177’ (comme ‘\^?’).
\M-C
Représente le caractère ‘C’ avec le 8ème bit défini. Couvre les caractères ‘\241’ à ‘\376’.
\M^C
Représente le caractère de contrôle ‘C’ avec le 8ème bit défini. Couvre les caractères ‘\200’ à ‘\237’, et ‘\377’ (comme ‘\M^?’).
\040
Représente l'espace ASCII.
\240
Représente l'espace Meta.
VIS_CSTYLE
Utiliser des séquences de barres obliques inverses de style C pour représenter les caractères non imprimables standard. Les séquences suivantes sont utilisées pour représenter les caractères indiqués : 
\a — BEL (007)
\b — BS (010)
\f — NP (014)
\n — NL (012)
\r — CR (015)
\s — SP (040)
\t — HT (011)
\v — VT (013)
\0 — NUL (000)

Lors de l'utilisation de ce format, le paramètre nextc est examiné pour déterminer si un caractère NUL peut être encodé comme ‘\0’ au lieu de ‘\000’. Si nextc est un chiffre octal, la dernière représentation est utilisée pour éviter toute ambiguïté.

Les caractères non imprimables sans séquences de barres obliques inverses de style C utilisent la représentation par défaut.

VIS_OCTAL
Utiliser une séquence octale à trois chiffres. La forme est ‘\ddd’ où d représente un chiffre octal.
VIS_CSTYLE | VIS_OCTAL
Identique à VIS_CSTYLE sauf que les caractères non imprimables sans séquences de barres obliques inverses de style C utilisent une séquence octale à trois chiffres.

DESCRIPTION

The vis() family of functions converts non-printing characters in the input string src into printable sequences, storing the result in the buffer pointed to by dst. The functions differ in the way they handle buffer sizes and the format of the output.

The flag argument is a bitmask that controls the conversion process. The following flags are available:

VIS_CSTYLE
Use C escape sequences for non-printing characters. For example, a newline character is represented as ‘\n’. Other non-printing characters are represented as ‘^C’ or ‘M-C’ (meta character).
VIS_DQ
Enclose the result in double quotes ("). Double quotes and backslashes within the string are escaped with a backslash.
VIS_NOSLASH
Inhibit the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.
VIS_NL
Print the newline character (\n) as ‘\n’ instead of ‘^J’. Also print the carriage return character (\r) as ‘\r’ instead of ‘^M’. This flag implies VIS_CSTYLE.
VIS_SP
Print the space character ( ) as ‘ ’ instead of ‘^I’ (which is the ASCII character for TAB). This flag implies VIS_CSTYLE.
VIS_SAFE
Print all characters that have a visible representation. This includes characters from the C locale that are not alphanumeric or special characters. This flag implies VIS_NL and VIS_SP.
VIS_WHITE
Print the space character ( ) as ‘ ’ instead of ‘^?’ (which is the ASCII character for SPACE). This flag implies VIS_CSTYLE.
VIS_OCTAL
Use octal representation for non-printing characters. The form is ‘\XXX’ where X represents an octal digit.
'%xx' where x represents a lower case hexadecimal digit.
VIS_MIMESTYLE
Use MIME Quoted-Printable encoding as described in RFC 2045, only don't break lines and don't handle CRLF. The form is ‘=XX’ where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.

MULTIBYTE CHARACTER SUPPORT

These functions support multibyte character input. The encoding conversion is influenced by the setting of the LC_CTYPE environment variable which defines the set of characters that can be copied without encoding.

If VIS_NOLOCALE is set, processing is done assuming the C locale and overriding any other environment settings.

When 8-bit data is present in the input, LC_CTYPE must be set to the correct locale or to the C locale. If the locales of the data and the conversion are mismatched, multibyte character recognition may fail and encoding will be performed byte-by-byte instead.

As noted above, dst must be four times the number of bytes processed from src. But note that each multibyte character can be up to MB_LEN_MAX bytes so in terms of multibyte characters, dst must be four times MB_LEN_MAX times the number of characters processed from src.

ENVIRONMENT

LC_CTYPE
Specify the locale of the input data. Set to C if the input data locale is unknown.

ERRORS

The functions nvis() and snvis() will return NULL and the functions strnvis(), strnvisx(), strsnvis(), and strsnvisx(), will return -1 when the dlen destination buffer size is not enough to perform the conversion while setting errno to:

[ENOSPC]
The destination buffer size is not large enough to perform the conversion.

HISTORY

The vis(), strvis(), and strvisx() functions first appeared in 4.4BSD. The svis(), strsvis(), and strsvisx() functions appeared in NetBSD 1.5. The buffer size limited versions of the functions (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), and strsnvisx()) appeared in NetBSD 6.0 and FreeBSD 9.2. Multibyte character support was added in NetBSD 7.0 and FreeBSD 9.2.
