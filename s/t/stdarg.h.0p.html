PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

stdarg.h — gérer la liste d'arguments variables

SYNOPSIS

#include <stdarg.h>
void va_start(va_list ap, argN);
void va_copy(va_list dest, va_list src);
type va_arg(va_list ap, type);
void va_end(va_list ap);

DESCRIPTION

La fonctionnalité décrite dans cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

L'en-tête <stdarg.h> doit contenir un ensemble de macros qui permettent d'écrire des fonctions portables acceptant des listes d'arguments variables. Les fonctions qui ont des listes d'arguments variables (telles que printf()) mais n'utilisent pas ces macros sont intrinsèquement non portables, car différents systèmes utilisent des conventions de passage d'arguments différentes.

L'en-tête <stdarg.h> doit définir le type va_list pour les variables utilisées pour parcourir la liste.

La macro va_start() est appelée pour initialiser ap au début de la liste avant tout appel à va_arg().

La macro va_copy() initialise dest comme une copie de src, comme si la macro va_start() avait été appliquée à dest suivie de la même séquence d'utilisations de la macro va_arg() que celle précédemment utilisée pour atteindre l'état actuel de src. Ni la macro va_copy() ni va_start() ne doit être appelée pour réinitialiser dest sans une invocation intermédiaire de la macro va_end() pour le même dest.

L'objet ap peut être passé en argument à une autre fonction ; si cette fonction invoque la macro va_arg() avec le paramètre ap, la valeur de ap dans la fonction appelante est indéterminée et doit être passée à la macro va_end() avant toute référence ultérieure à ap. Le paramètre argN est l'identifiant du paramètre le plus à droite dans la liste de paramètres variables dans la définition de la fonction (celui juste avant le ...). Si le paramètre argN est déclaré avec la classe de stockage register, avec un type de fonction ou un type de tableau, ou avec un type qui n'est pas compatible avec le type résultant après application des promotions d'arguments par défaut, le comportement est indéfini.

La macro va_arg() renvoie l'argument suivant dans la liste pointée par ap. Chaque invocation de va_arg() modifie ap de sorte que les valeurs des arguments successifs soient renvoyées successivement. Le paramètre type doit être un nom de type spécifié de telle sorte que le type d'un pointeur vers un objet ayant le type spécifié puisse être obtenu simplement en ajoutant un '*' au type. S'il n'y a pas d'argument suivant réel, ou si type n'est pas compatible avec le type de l'argument suivant réel (tel que promu conformément aux promotions d'arguments par défaut), le comportement est indéfini, à l'exception des cas suivants :

*
Un type est un type entier signé, l'autre type est le type entier non signé correspondant, et la valeur est représentable dans les deux types.
*
Un type est un pointeur vers void et l'autre est un pointeur vers un type caractère.
*
Les deux types sont des pointeurs.

Différents types peuvent être mélangés, mais c'est à la routine de savoir quel type d'argument est attendu.

La macro va_end() est utilisée pour le nettoyage ; elle invalide ap pour utilisation (à moins que va_start() ou va_copy() ne soit à nouveau invoquée).

Chaque invocation des macros va_start() et va_copy() doit être appariée par une invocation correspondante de la macro va_end() dans la même fonction.

Des parcours multiples, chacun encadré par va_start() ... va_end(), sont possibles.

Les sections suivantes sont informatives.

EXEMPLES

Cet exemple est une implémentation possible de execl() :

#include <stdarg.h>
#define  MAXARGS     31
/*
 * execl est appelé par
 * execl(file, arg1, arg2, ..., (char *)(0));
 */
int execl(const char *file, const char *args, ...)
{
    va_list ap;
    char *array[MAXARGS +1];
    int argno = 0;
    va_start(ap, args);
    while (args != 0 && argno < MAXARGS)
    {
        array[argno++] = args;
        args = va_arg(ap, const char *);
    }
    array[argno] = (char *) 0;
    va_end(ap);
    return execv(file, array);
}

UTILISATION PAR L'APPLICATION

Il appartient à la routine appelante de communiquer à la routine appelée le nombre d'arguments, car il n'est pas toujours possible pour la routine appelée de le déterminer d'une autre manière. Par exemple, execl() reçoit un pointeur nul pour signaler la fin de la liste. La fonction printf() peut déterminer le nombre d'arguments grâce à l'argument format.

NOM

stdarg.h - Macros pour accéder aux arguments de fonction de longueur variable

SYNOPSIS

        #include <stdarg.h>

DESCRIPTION

L'en-tête stdarg.h déclare un type va_list et les macros nécessaires pour parcourir la liste des arguments d'une fonction qui peut accepter un nombre variable d'arguments. Les fonctions avec un nombre variable d'arguments sont déclarées avec une ellipse (...) comme dernier spécificateur de paramètre.

Les macros suivantes sont fournies :

va_list
Un type capable de contenir l'information nécessaire pour parcourir la liste des arguments d'une fonction. La déclaration d'une variable de type va_list est nécessaire dans toute fonction qui utilise ces macros.
va_start
La macro va_start initialise la variable va_list désignée par son premier argument (par exemple, ap) pour qu'elle fasse référence au premier argument variable de la fonction courant. Le second argument (par exemple, last_arg) est le nom du dernier argument fixe déclaré dans la liste des paramètres de la fonction.
void va_start(va_list ap, last_arg);
va_arg
La macro va_arg développe vers la valeur de l'argument suivant dans la liste des arguments. Le type de l'argument retourné est celui spécifié par le paramètre type. Chaque appel à va_arg fait avancer le pointeur de liste d'arguments pour qu'il pointe vers le prochain argument. Le comportement est indéfini si le type spécifié ne correspond pas au type réel de l'argument suivant.
type va_arg(va_list ap, type);
va_copy
La macro va_copy copie la valeur de l'argument src dans la variable va_list désignée par son argument dest. La liste d'arguments peut ensuite être parcourue indépendamment à partir de la copie.
void va_copy(va_list dest, va_list src);
va_end
La macro va_end permet à une fonction utilisant ces macros de terminer. L'appel à va_end doit être effectué avant que la fonction ne retourne. Si va_end n'est pas appelé, le comportement est indéfini. Une fois va_end appelé, la variable va_list ne doit plus être utilisée, sauf si elle est réinitialisée par un appel à va_start ou va_copy.
void va_end(va_list ap);

UTILISATION DE L'APPLICATION

Les fonctions à nombre variable d'arguments sont couramment utilisées pour des fonctions telles que printf(), scanf() et leurs variantes, où le nombre et le type des arguments peuvent varier en fonction d'une chaîne de format.

Voici un exemple simple d'une fonction qui additionne une liste d'entiers :

        #include <stdarg.h>
        #include <stdio.h>

        int sum(int count, ...) {
            va_list args;
            int sum = 0;
            int i;

            va_start(args, count); // Initialise args pour pointer vers le premier argument variable

            for (i = 0; i < count; ++i) {
                sum += va_arg(args, int); // Récupère le prochain argument entier et l'ajoute à la somme
            }

            va_end(args); // Nettoie les ressources associées à va_list
            return sum;
        }

        int main() {
            printf("Somme de 1, 2, 3 : %d\n", sum(3, 1, 2, 3));
            printf("Somme de 10, 20, 30, 40 : %d\n", sum(4, 10, 20, 30, 40));
            return 0;
        }

JUSTIFICATION

Le mécanisme stdarg.h est une manière standardisée et portable d'écrire des fonctions qui acceptent un nombre variable d'arguments. Il a été introduit pour remplacer des méthodes moins portables qui dépendaient de l'architecture sous-jacente et de la convention d'appel.

ORIENTATIONS FUTURES

Aucune orientation future significative n'est prévue pour ces macros. Elles constituent une fonctionnalité de base du langage C.
