STAPRUN(8) Manuel du gestionnaire système STAPRUN(8)

NOM

staprun - runtime de systemtap

SYNTAXE

staprun [ OPTIONS ] MODULE [ OPTIONS-MODULE ]

DESCRIPTION

Le programme staprun est le backend de l'outil Systemtap. Il attend un module noyau produit par le frontend stap.

La séparation de l'outil systemtap en un frontend et un backend permet à un utilisateur de compiler un script systemtap sur une machine de développement qui possède les outils de développement du noyau (nécessaires pour compiler le script), puis de transférer le module noyau résultant sur une machine de production qui n'a aucun outil de développement installé.

Veuillez consulter stappaths(7) pour le numéro de version, ou exécuter rpm -q systemtap (fedora/red hat) apt-get -v systemtap (ubuntu)

OPTIONS

Le programme staprun prend en charge les options suivantes. Toute autre option affiche une liste des options prises en charge.

-v
Mode verbeux. Le niveau de verbosité est également défini dans la variable d'environnement SYSTEMTAP_VERBOSE.
-V
Affiche le numéro de version et quitte.
-w
Supprime les avertissements du script.
-u
Charge le module uprobes.ko.
-c CMD
La commande CMD sera exécutée et le programme staprun se terminera lorsque CMD se terminera. La variable '_stp_target' contiendra le pid pour CMD.
-x PID
La variable '_stp_target' sera définie sur PID.
-N PID
Définit la variable '_stp_namespaces_pid' sur PID.
-o FICHIER
Envoie la sortie vers FICHIER. Si le module utilise le mode bulk, la sortie sera dans des fichiers percpu FICHIER_x(FICHIER_cpux en arrière-plan et en mode bulk) où 'x' est le numéro du cpu. Ceci prend en charge les formats strftime(3) pour FICHIER.
-b TAILLE_BUFFER
Le module systemtap spécifiera une taille de buffer. La définition d'une taille ici remplacera cette valeur. La valeur doit être un entier compris entre 1 et 4095, qui sera considéré comme la taille du buffer en Mo. Cette valeur sera par cpu si le mode bulk est utilisé.
-L
Charge le module et démarre les sondes, puis se détache du module en laissant les sondes actives. Le module peut être attaché ultérieurement en utilisant l'option -A.
-A
S'attache au module systemtap chargé.
-C QUAND
Contrôle la coloration des messages d'erreur. QUAND doit être "jamais", "toujours" ou "auto" (c'est-à-dire activé uniquement si à un terminal). Si l'option est absente, "auto" est supposé. Les couleurs peuvent être modifiées en utilisant la variable d'environnement SYSTEMTAP_COLORS. Voir la page de manuel de stap(1) pour plus d'informations sur la syntaxe et le comportement.
-M INTERVALLE
Active le mode moniteur avec INTERVALLE secondes entre les mises à jour.
-d
Supprime un module. Seuls les modules détachés ou inutilisés que l'utilisateur a la permission d'accéder seront supprimés. Utiliser "*" (entre guillemets) pour supprimer tous les modules inutilisés.
-D
Exécute staprun en arrière-plan en tant que démon et affiche son pid.
-R
Renomme le module en un nom unique avant de l'insérer.
-r N:URI
Passe le numéro et les données URI donnés aux fonctions tapset remote_id() et remote_uri().
-S taille[,N]
Définit la taille maximale du fichier de sortie et le nombre maximal de fichiers de sortie. Si la taille du fichier de sortie dépasse taille mégaoctets, systemtap passe le fichier de sortie au fichier suivant. Et si le nombre de fichiers de sortie dépasse N, systemtap supprime le plus ancien fichier de sortie. Vous pouvez omettre le second argument.
-T delai
Définit le temps maximum d'attente du thread lecteur avant de vider le buffer de trace. La valeur est en ms, la valeur par défaut est de 200 ms. Définir une valeur élevée réduit le nombre de réveils de stapio, permettant un sommeil plus profond pour les plateformes embarquées. Mais cela affecte l'interactivité sur le terminal car les traces sont vidées moins souvent en cas de faible débit. Il n'y a aucun impact sur l'interactivité ou les performances pour un débit élevé, car la trace est vidée lorsque le buffer est plein, avant que ce délai n'expire.
var1=val
Définit la valeur de la variable globale var1 à val. Les variables globales contenues dans un module sont traitées comme des options de module et peuvent être définies depuis la ligne de commande staprun.

ARGUMENTS

MODULE est soit un chemin de module, soit un nom de module. S'il s'agit d'un nom de module, le module sera recherché dans le répertoire suivant (où 'VERSION' est la sortie de "uname -r"):

/lib/modules/VERSION/systemtap

Tous les arguments supplémentaires sur la ligne de commande sont transmis au module. Une utilisation de ces arguments de module supplémentaires est de définir la valeur des variables globales déclarées dans le module.

$ stap -p4 -m mod1 -e 'global var1="foo"; probe begin{printf("%s\n", var1); exit()}'

Exécution avec un argument de module supplémentaire :

$ staprun mod1.ko var1="HelloWorld"
HelloWorld

Les espaces et les points d'exclamation ne peuvent actuellement pas être passés aux variables globales de cette manière.

EXEMPLES

Voir la page de manuel stapex(3stap) pour une collection de scripts exemples.

Voici un exemple très basique d'utilisation de staprun. Tout d'abord, utilisez stap pour compiler un script. Le programme stap signalera le chemin d'accès au module résultant.

$ stap -p4 -e 'probe begin { printf("Hello World!\n"); exit() }'
/home/user/.systemtap/cache/85/stap_8553d83f78c_265.ko

Exécutez staprun avec le chemin d'accès au module comme argument.

$ staprun /home/user/.systemtap/cache/85/stap_8553d83f78c_265.ko
Hello World!

DETACHEMENT ET ATTACHEEMENT DE MODULE

Après que le programme staprun ait installé un module noyau Systemtap, les utilisateurs peuvent se détacher du module noyau et s'y rattacher plus tard. L'option -L charge le module et se détache automatiquement. Les utilisateurs peuvent également se détacher du module noyau interactivement en envoyant le signal SIGQUIT depuis le clavier (typiquement en tapant Ctrl-\).

Pour se rattacher à un module noyau, l'option -A de staprun serait utilisée.

CHANGEMENT DE FICHIER PAR SIGNAL

Après que staprun ait lancé le programme stapio, les utilisateurs peuvent lui commander de passer au fichier de sortie suivant lorsqu'il écrit dans des fichiers (en exécutant staprun avec l'option -o) en envoyant un signal SIGUSR2 au processus stapio. Lorsqu'il reçoit SIGUSR2, il passe au fichier de sortie suivant avec le suffixe .N où N est le numéro séquentiel. Par exemple,

$ staprun -o foo ...

envoie les traces de journalisation à foo et s'il reçoit le signal SIGUSR2, il passe au fichier foo.1. Et en recevant à nouveau SIGUSR2, il passe au fichier foo.2.

SECURITE

Systemtap, dans son mode d'exécution par défaut en tant que module noyau, est un outil administratif. Il expose les structures de données internes du noyau et potentiellement des informations privées de l'utilisateur. Voir la page de manuel de stap(1) pour des informations supplémentaires sur la sécurité.

Pour renforcer la sécurité du système, les utilisateurs de systemtap doivent être root, ou appartenir au groupe stapusr afin d'exécuter ce staprun setuid p

staprun(8) — SystemTap — Arch Linux

NOM

staprun, stapvirt - charger et exécuter des scripts SystemTap

SYNOPIS

staprun [ options ] [ variables ]

stapvirt [ options ] [ variables ]

DESCRIPTION

La commande staprun est un programme wrapper rudimentaire pour le module noyau systemtap. Il est utilisé pour charger et décharger des modules de script SystemTap compilés dans le noyau. Elle est généralement appelée par le programme stap après qu'un script a été traduit en un module noyau.

La commande stapvirt est une alternative à staprun, utilisée pour exécuter des scripts SystemTap dans un environnement virtuellement isolé, ce qui offre un niveau de sécurité plus élevé.

Les deux programmes prennent en charge une gamme similaire d'options et de fonctionnalités.

OPTIONS

-l, --load
Charge le module de script spécifié. C'est le comportement par défaut si aucune autre action n'est spécifiée.
-u, --unload
Décharge le module de script spécifié.
-s, --syslog
Redirige les messages du noyau vers syslog.
-d, --debug
Active le débogage pour staprun.
-p, --privilege=level
Spécifie le niveau de privilège à utiliser pour le script. Les niveaux possibles sont 0 (utilisateur), 1 (système) et 2 (développeur). Le niveau par défaut est 0.
-v, --verbose
Augmente la verbosité de la sortie.
-h, --help
Affiche un message d'aide et quitte.

ARGUMENTS

Les arguments non reconnus comme options sont traités comme des variables à passer au script SystemTap. Les variables sont sous la forme nom=valeur.

EXEMPLES

Pour charger un module de script nommé mon_script.ko avec le niveau de privilège utilisateur :

staprun --load mon_script.ko

Pour décharger le même module :

staprun --unload mon_script.ko

Pour charger un module et passer une variable :

staprun --load mon_script.ko msg="Bonjour le monde"

Pour charger un module avec le niveau de privilège système :

staprun --load --privilege=1 mon_script.ko

MODULE DETACHING AND ATTACHING

Le chargement et le déchargement de modules sont gérés par le programme.

FILE SWITCHING BY SIGNAL

Cette fonctionnalité n'est pas directement prise en charge par staprun. Elle est généralement gérée par le programme stap lui-même.

SAFETY AND SECURITY

staprun et stapvirt permettent de contrôler les privilèges d'exécution des scripts SystemTap grâce à des groupes d'utilisateurs spécifiques et à l'option --privilege. Le niveau de privilège peut être sélectionné par l'utilisateur avec l'option --privilege=, que staprun appliquera plus tard.

stapdev
Les membres du groupe stapdev peuvent écrire et charger des modules de script avec des privilèges équivalents à ceux de root, sans contraintes de sécurité particulières. (De nombreuses contraintes de sécurité demeurent.)
stapsys
Les membres du groupe stapsys ont presque tous les privilèges de stapdev, à l'exception des constructions en mode guru.
stapusr
Les membres du seul groupe stapusr peuvent utiliser des modules privilégiés placés dans le répertoire /lib/modules/VERSION/systemtap par l'administrateur système.
stapusr
Les membres du seul groupe stapusr peuvent également écrire et charger des modules de script à faible privilège, qui sont normalement limités à la manipulation de leurs propres processus (et non du noyau ni des processus d'autres utilisateurs).

Une partie du mécanisme d'application des privilèges peut nécessiter l'utilisation d'un stap-server et la confiance administrative dans son signataire cryptographique ; voir la page de manuel de stap-server(8) pour plus d'informations.

Sur un noyau avec le mode FIPS activé, staprun refuse normalement de tenter de charger des modules noyau générés par systemtap. En effet, sur certains noyaux, cela entraîne un panic. Si votre noyau inclut des corrections telles que le commit Linux #002c77a48b47, vous pouvez forcer staprun à tenter néanmoins le chargement des modules en définissant la variable d'environnement STAP_FIPS_OVERRIDE à n'importe quelle valeur.

FICHIERS

/lib/modules/VERSION/systemtap
Si MODULE est un nom de module, le module sera recherché dans ce répertoire. Les utilisateurs qui appartiennent uniquement au groupe 'stapusr' peuvent installer des modules situés dans ce répertoire. Ce répertoire doit appartenir à l'utilisateur root et ne doit pas être accessible en écriture à tous.
