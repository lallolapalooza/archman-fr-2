statx(2) Manuel des appels système statx(2)

NOM

statx - obtenir le statut d'un fichier (étendu)

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE          /* Voir feature_test_macros(7) */
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <sys/stat.h>
int statx(int dirfd, const char *_Nullable restrict path,
          int flags, unsigned int mask,
          struct statx *restrict statxbuf);

DESCRIPTION

Cette fonction retourne des informations sur un fichier, les stockant dans le tampon pointé par statxbuf. Le tampon retourné est une structure du type suivant :


struct statx {
    __u32 stx_mask;        /* Masque de bits indiquant les champs remplis */
    __u32 stx_blksize;     /* Taille du bloc pour les E/S du système de fichiers */
    __u64 stx_attributes;  /* Indicateurs d'attributs supplémentaires du fichier */
    __u32 stx_nlink;       /* Nombre de liens physiques */
    __u32 stx_uid;         /* ID de l'utilisateur propriétaire */
    __u32 stx_gid;         /* ID du groupe propriétaire */
    __u16 stx_mode;        /* Type et mode du fichier */
    __u64 stx_ino;         /* Numéro d'inode */
    __u64 stx_size;        /* Taille totale en octets */
    __u64 stx_blocks;      /* Nombre de blocs de 512 octets alloués */
    __u64 stx_attributes_mask;
                           /* Masque indiquant ce qui est pris en charge dans stx_attributes */
    /* Les champs suivants sont des horodatages de fichier */
    struct statx_timestamp stx_atime;  /* Dernier accès */
    struct statx_timestamp stx_btime;  /* Création */
    struct statx_timestamp stx_ctime;  /* Dernier changement de statut */
    struct statx_timestamp stx_mtime;  /* Dernière modification */
    /* Si ce fichier représente un périphérique, alors les deux champs suivants contiennent l'ID du périphérique */
    __u32 stx_rdev_major;  /* ID majeur */
    __u32 stx_rdev_minor;  /* ID mineur */
    /* Les deux champs suivants contiennent l'ID du périphérique contenant le système de fichiers où réside le fichier */
    __u32 stx_dev_major;   /* ID majeur */
    __u32 stx_dev_minor;   /* ID mineur */
    __u64 stx_mnt_id;      /* ID du point de montage */
    /* Restrictions d'alignement pour les E/S directes */
    __u32 stx_dio_mem_align;
    __u32 stx_dio_offset_align;
    __u64 stx_subvol;      /* Identifiant de sous-volume */
    /* Limites d'écriture atomique pour les E/S directes */
    __u32 stx_atomic_write_unit_min;
    __u32 stx_atomic_write_unit_max;
    __u32 stx_atomic_write_segments_max;
    /* Alignement du décalage de fichier pour les lectures par E/S directes */
    __u32 stx_dio_read_offset_align;
    /* Limite maximale optionnelle pour l'écriture atomique par E/S directes */
    __u32 stx_atomic_write_unit_max_opt;
};

Les horodatages de fichier sont des structures du type suivant :


struct statx_timestamp {
    __s64 tv_sec;    /* Secondes depuis l'Époque (heure UNIX) */
    __u32 tv_nsec;   /* Nanosecondes depuis tv_sec */
};

(Notez que l'espace réservé et le remplissage sont omis.)

Invocation de statx():

Pour accéder au statut d'un fichier, aucune permission n'est requise sur le fichier lui-même, mais dans le cas de statx() avec un nom de chemin, la permission d'exécution (de parcours) est requise sur tous les répertoires de path qui mènent au fichier.

statx() utilise path, dirfd et flags pour identifier le fichier cible de l'une des manières suivantes :

Un nom de chemin absolu
Si path commence par une barre oblique, alors c'est un nom de chemin absolu qui identifie le fichier cible. Dans ce cas, dirfd est ignoré.
Un nom de chemin relatif
Si path est une chaîne qui commence par un caractère autre qu'une barre oblique et que dirfd est AT_FDCWD, alors path est un nom de chemin relatif interprété par rapport au répertoire de travail actuel du processus.
Un nom de chemin relatif à un répertoire
Si path est une chaîne qui commence par un caractère autre qu'une barre oblique et que dirfd est un descripteur de fichier faisant référence à un répertoire, alors path est un nom de chemin relatif interprété par rapport au répertoire référencé par dirfd. (Voir openat(2) pour une explication de l'utilité de cela.)
Par descripteur de fichier
Si path est une chaîne vide (ou NULL depuis Linux 6.11) et que le flag AT_EMPTY_PATH est spécifié dans flags (voir ci-dessous), alors le fichier cible est celui référencé par le descripteur de fichier dirfd.

flags peut être utilisé pour influencer la recherche basée sur le nom de chemin. Une valeur pour flags est construite en combinant par OU zéro ou plusieurs des constantes suivantes :

AT_EMPTY_PATH
Si path est une chaîne vide (ou NULL depuis Linux 6.11), opérer sur le fichier référencé par dirfd (qui peut avoir été obtenu en utilisant le flag open(2) O_PATH). Dans ce cas, dirfd peut faire référence à n'importe quel type de fichier, pas seulement un répertoire.
Si dirfd est AT_FDCWD, l'appel opère sur le répertoire de travail courant.
AT_NO_AUTOMOUNT
Ne pas automonter le composant terminal ("nom de base") de path s'il s'agit d'un répertoire qui est un point d'automontage. Cela permet à l'appelant de collecter des attributs d'un point d'automontage (plutôt que de l'emplacement qu'il monterait). Ce flag n'a aucun effet si le point de montage a déjà été monté par-dessus.
Le flag AT_NO_AUTOMOUNT peut être utilisé dans les outils qui scannent les répertoires pour empêcher l'automontage massif d'un répertoire de points d'automontage.
Tous les appels stat(2), lstat(2), et fstatat(2) agissent comme si AT_NO_AUTOMOUNT était défini.
AT_SYMLINK_NOFOLLOW
Si path est un lien symbolique, ne pas le désérialiser : retourner à la place des informations sur le lien lui-même, comme lstat(2).

flags peut également être utilisé pour contrôler le type de synchronisation que le noyau effectuera lors de la requête d'un fichier sur un système de fichiers distant. Ceci est fait en combinant par OU l'une des valeurs suivantes :

AT_STATX_SYNC_AS_STAT
Faire ce que fait stat(2). C'est le comportement par défaut et il dépend fortement du système de fichiers.
AT_STATX_FORCE_SYNC
Forcer la synchronisation des attributs avec le serveur. Cela peut nécessiter qu'un système de fichiers réseau effectue une écriture des données pour corriger les horodatages.
AT_STATX_DONT_SYNC
Ne rien synchroniser, mais simplement prendre ce que le système a en cache si possible. Cela peut signifier que les informations retournées sont approximatives, mais, sur un système de fichiers réseau, cela peut ne pas impliquer un aller-retour vers le serveur - même si aucun bail n'est détenu.

L'argument mask de statx() est utilisé pour indiquer au noyau quels champs intéressent l'appelant. mask est une combinaison combinée par OU des constantes suivantes :


STATX_TYPE Demande stx_mode & S_IFMT
STATX_MODE Demande stx_mode & ~S_IFMT
STATX_NLINK Demande stx_nlink
STATX_UID Demande stx_uid
STATX_GID Demande stx_gid
STATX_ATIME Demande stx_atime
STATX_MTIME Demande stx_mtime
STATX_CTIME Demande stx_ctime
STATX_INO Demande stx_ino
STATX_SIZE Demande stx_size
STATX_BLOCKS Demande stx_blocks
STATX_BASIC_STATS [Tous les précédents]
STATX_BTIME Demande stx_btime

STATX_ALL Identique à STATX_BASIC_STATS | STATX_BTIME. Il est obsolète et ne doit pas être utilisé. STATX_MNT_ID Demande stx_mnt_id (depuis Linux 5.8) STATX_DIOALIGN Demande stx_dio_mem_align et stx_dio_offset_align. (depuis Linux 6.1; la prise en charge varie selon le système de fichiers) STATX_MNT_ID_UNIQUE Demande un stx_mnt_id unique (depuis Linux 6.8) STATX_SUBVOL Demande stx_subvol (depuis Linux 6.10; la prise en charge varie selon le système de fichiers) STATX_WRITE_ATOMIC Demande stx_atomic_write_unit_min, stx_atomic_write_unit_max, stx_atomic_write_segments_max, et stx_atomic_write_unit_max_opt. (depuis Linux 6.11; la prise en charge varie selon le système de fichiers) STATX_DIO_READ_ALIGN Demande stx_dio_read_offset_align. (depuis Linux 6.14; la prise en charge varie selon le système de fichiers)

Notez que, en général, le noyau ne rejette pas les valeurs dans mask autres que celles ci-dessus. (Pour une exception, voir EINVAL dans errors.) Au lieu de cela, il informe simplement l'appelant quelles valeurs sont prises en charge par ce noyau et ce système de fichiers via le champ statx.stx_mask. Par conséquent, ne définissez pas simplement mask à UINT_MAX (tous les bits définis), car un ou plusieurs bits pourront, à l'avenir, être utilisés pour spécifier une extension du tampon.

Les informations retournées

Les informations d'état du fichier cible sont retournées dans la structure statx pointée par statxbuf. Ceci inclut stx_mask qui indique quelles autres informations ont été retournées. stx_mask a le même format que l'argument mask et les bits y sont définis pour indiquer quels champs ont été remplis.

Il faut noter que le noyau peut retourner des champs qui n'ont pas été demandés et peut omettre de retourner des champs qui ont été demandés, en fonction de ce que le système de fichiers sous-jacent prend en charge. (Les champs qui reçoivent des valeurs malgré le fait qu'ils n'aient pas été demandés peuvent simplement être ignorés.) Dans les deux cas, stx_mask ne sera pas égal à mask.

Si un système de fichiers ne prend pas en charge un champ ou s'il a une valeur non représentable (par exemple, un fichier avec un type exotique), alors le bit de masque correspondant à ce champ sera effacé dans stx_mask même si l'utilisateur l'a demandé et une valeur factice sera remplie à des fins de compatibilité si elle est disponible (par exemple, un UID et un GID factices peuvent être spécifiés sous certains contextes).

Un système de fichiers peut également remplir des champs que l'appelant n'a pas demandés s'il a des valeurs pour eux disponibles et que l'information est disponible sans coût supplémentaire. Si cela se produit, les bits correspondants seront définis dans stx_mask.

Note: pour des raisons de performance et de simplicité, différents champs dans la structure statx peuvent contenir des informations d'état à des moments différents pendant l'exécution de l'appel système. Par exemple, si stx_mode ou stx_uid est modifié par un autre processus en appelant chmod(2) ou chown(2), stat() pourrait retourner l'ancien stx_mode avec le nouveau stx_uid, ou l'ancien stx_uid avec le nouveau stx_mode.

Outre stx_mask (qui est décrit ci-dessus), les champs de la structure statx sont :

stx_blksize
La taille de bloc "préférée" pour des E/S efficaces du système de fichiers. (Écrire dans un fichier en morceaux plus petits peut entraîner une réécriture inefficace lire-modifier.)
stx_attributes
Informations d'état supplémentaires sur le fichier (voir ci-dessous pour plus d'informations).
stx_nlink
Le nombre de liens physiques sur un fichier.
stx_uid
Ce champ contient l'identifiant utilisateur du propriétaire du fichier.
stx_gid
Ce champ contient l'identifiant du propriétaire du groupe du fichier.
stx_mode
Le type et le mode du fichier. Voir inode(7) pour les détails.
stx_ino
Le numéro d'inode du fichier.
stx_size
La taille du fichier (s'il s'agit d'un fichier régulier ou d'un lien symbolique) en octets. La taille d'un lien symbolique est la longueur du chemin qu'il contient, sans octet nul de fin.
stx_blocks
Le nombre de blocs alloués au fichier sur le support, en unités de 512 octets. (Cela peut être inférieur à stx_size/512 lorsque le fichier a des trous.)
stx_attributes_mask
Un masque indiquant quels bits dans stx_attributes sont pris en charge par le VFS et le système de fichiers.
stx_atime
L'horodatage du dernier accès au fichier.
stx_btime
L'horodatage de création du fichier.
stx_ctime
L'horodatage du dernier changement d'état du fichier.
stx_mtime
L'horodatage de la dernière modification du fichier.
stx_dev_major
stx_dev_minor
Le périphérique sur lequel réside ce fichier (inode).
stx_rdev_major
stx_rdev_minor
Le périphérique que ce fichier (inode) représente si le fichier est de type périphérique bloc ou caractère.
stx_mnt_id
Si STATX_MNT_ID est utilisé, il s'agit de l'identifiant de montage du montage contenant le fichier. Il s'agit du même numéro signalé par name_to_handle_at(2) et correspond au numéro dans le premier champ de l'un des enregistrements de /proc/self/mountinfo.
Si STATX_MNT_ID_UNIQUE est utilisé, il s'agit de l'identifiant de montage unique du montage contenant le fichier. Il s'agit du numéro signalé par listmount(2) et c'est l'identifiant utilisé pour interroger le montage avec statmount(2). Il est garanti de ne pas être réutilisé tant que le système est en cours d'exécution.
stx_dio_mem_align
L'alignement (en octets) requis pour les tampons mémoire utilisateur pour les E/S directes (O_DIRECT) sur ce fichier, ou 0 si les E/S directes ne sont pas prises en charge sur ce fichier.
STATX_DIOALIGN (stx_dio_mem_align et stx_dio_offset_align) est pris en charge sur les périphériques blocs depuis Linux 6.1. La prise en charge sur les fichiers réguliers varie selon le système de fichiers ; elle est prise en charge par ext4, f2fs et xfs depuis Linux 6.1.
stx_dio_offset_align
L'alignement (en octets) requis pour les décalages de fichiers et les longueurs de segments d'E/S pour les E/S directes (O_DIRECT) sur ce fichier, ou 0 si les E/S directes ne sont pas prises en charge sur ce fichier. Ceci ne sera non nul que si stx_dio_mem_align est non nul, et vice versa.
stx_dio_read_offset_align
L'alignement (en octets) requis pour les décalages de fichiers et les longueurs de segments d'E/S pour les lectures en E/S directes (O_DIRECT) sur ce fichier. S'il est nul, la limite de stx_dio_offset_align s'applique également aux lectures. S'il est non nul, cette valeur doit être inférieure ou égale à stx_dio_offset_align, qui doit être fournie par le système de fichiers si demandée par l'application. L'alignement mémoire dans stx_dio_mem_align n'est pas affecté par cette valeur.
STATX_DIO_READ_ALIGN (stx_dio_offset_align) est pris en charge par xfs sur les fichiers réguliers depuis Linux 6.14.
stx_subvol
Numéro de sous-volume du fichier actuel.
Les sous-volumes sont des répertoires fantaisie, c'est-à-dire qu'ils forment une structure arborescente qui peut être parcourue récursivement. La prise en charge varie selon le système de fichiers ; elle est prise en charge par bcachefs et btrfs depuis Linux 6.10.
stx_atomic_write_unit_min
stx_atomic_write_unit_max
Les tailles minimale et maximale (en octets) prises en charge pour les E/S directes (O_DIRECT) sur le fichier pour être écrit avec une protection contre les écritures déchirées. Ces valeurs sont garanties d'être des puissances de 2.
STATX_WRITE_ATOMIC (stx_atomic_write_unit_min, stx_atomic_write_unit_max, et stx_atomic_write_segments_max) est pris en charge sur les périphériques blocs depuis Linux 6.11. La prise en charge sur les fichiers réguliers varie selon le système de fichiers ; elle est prise en charge par xfs et ext4 depuis Linux 6.13.
stx_atomic_write_unit_max_opt
La taille maximale (en octets) optimisée pour les écritures effectuées avec une protection contre les écritures déchirées. Si elle est non nulle, cette valeur ne dépassera pas la valeur de stx_atomic_write_unit_max et ne sera pas inférieure à la valeur de stx_atomic_write_unit_min. Une valeur de zéro indique que stx_atomic_write_unit_max est la limite optimisée. Des écritures plus lentes peuvent être rencontrées lorsque la taille de l'écriture dépasse stx_atomic_write_unit_max_opt (lorsqu'elle est non nulle).
stx_atomic_write_segments_max
statx(2) - Pages de manuel Linux

NOM

statx – obtenir des informations sur un fichier

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>
#include <stdint.h>
#include <sys/stat.h>

int statx(int dirfd,
const char *restrict path,
int flags,
unsigned int mask,
struct statx *restrict statxbuf);

DESCRIPTION

La fonction statx renvoie des informations sur un fichier spécifié par path. Les informations sont renvoyées dans la structure référencée par statxbuf. Le comportement de statx est similaire à celui de stat(2), mais avec une plus grande flexibilité et la possibilité de récupérer plus d'informations.

Le paramètre dirfd spécifie un répertoire depuis lequel cheminer le paramètre path. Si path est un chemin absolu, dirfd doit être AT_FDCWD. Si path est relatif, alors dirfd est un descripteur de fichier ouvert pour le répertoire à partir duquel le chemin sera résolu.

Le paramètre flags est un masque de bits qui contrôle la manière dont le chemin est traité. Les drapeaux suivants sont définis:

AT_EMPTY_PATH
Si path est une chaîne vide, cela signifie que l'on fait référence au fichier associé à dirfd. Ceci est utile pour obtenir des informations sur un fichier dont le nom pourrait être trop long pour être traité en tant que chaîne standard, ou lorsque le nom du fichier n'est pas connu. Si le fichier est ouvert via un descripteur de fichier (par exemple, via dirfd), ce drapeau peut être utilisé. Si ce drapeau est spécifié, alors path peut être NULL.
AT_NO_AUTOMOUNT
Ne pas déclencher un automontage. Si le chemin spécifié traverse un point de montage qui n'a pas encore été monté, cette opération échoue avec ENAUTOFS.
AT_SYMLINK_NOFOLLOW
Si le dernier composant de path est un lien symbolique, renvoyer des informations sur le lien symbolique lui-même, plutôt que sur le fichier auquel il fait référence. Ce drapeau peut être combiné avec AT_NO_AUTOMOUNT.

Le paramètre mask est un masque de bits qui spécifie quels champs de la structure statxbuf doivent être remplis. Les champs demandés qui ne sont pas pris en charge par le système de fichiers seront mis à zéro dans statxbuf. Les indicateurs suivants sont définis:

STATX_BASIC_STATS
Indique de remplir les champs de base de la structure statxbuf, incluant la taille, les temps d'accès, de modification et de changement, les identifiants de l'utilisateur, du groupe, du périphérique, de l'inode, le nombre de liens, et les modes.
STATX_ শুকনো
Indique de remplir les statistiques d'allocation de blocs.
STATX_BTIME
Indique de remplir le temps de création (birth time) du fichier.
STATX_CTIME
Indique de remplir le temps de changement (change time) du fichier. Ceci inclut les changements de métadonnées et de contenu.
STATX_ATIME
Indique de remplir le temps de dernier accès (access time) du fichier.
STATX_MTIME
Indique de remplir le temps de dernière modification (modification time) du fichier. Ceci inclut les changements de contenu.
STATX_MODE
Indique de remplir les modes du fichier (permissions, type de fichier).
STATX_NLINK
Indique de remplir le nombre de liens hard vers le fichier.
STATX_UID
Indique de remplir l'ID utilisateur propriétaire du fichier.
STATX_GID
Indique de remplir l'ID groupe propriétaire du fichier.
STATX_INO
Indique de remplir le numéro d'inode du fichier.
STATX_SIZE
Indique de remplir la taille du fichier en octets.
STATX_BLOCKS
Indique de remplir le nombre de blocs alloués au fichier. Cette valeur peut être supérieure à la taille du fichier si le système de fichiers alloue des blocs entiers même pour des données partielles.
STATX_DEV
Indique de remplir l'ID du périphérique sur lequel le fichier réside.
STATX_RDEV
Indique de remplir l'ID du périphérique si le fichier est un fichier spécial (périphérique bloc ou caractère).
STATX_ATTR_SYNC
Indique de remplir les attributs de synchronisation du fichier.
STATX_ATTR_INODE
Indique de remplir les attributs de l'inode du fichier.
STATX_ALL
Demande à remplir tous les champs pris en charge.

La structure statx est définie comme suit:

struct statx {
    unsigned int stx_mask;          /* Champs disponibles dans la structure statx */
    unsigned int stx_blksize;       /* Taille des blocs I/O */
    uint64_t stx_attributes;        /* Attributs du fichier */
    uint32_t stx_nlink;             /* Nombre de liens hard */
    uint32_t stx_uid;               /* ID utilisateur propriétaire */
    uint32_t stx_gid;               /* ID groupe propriétaire */
    enum statx_type stx_mode;       /* Type de fichier et permissions */
    int64_t stx_ino;                /* Numéro d'inode */
    int64_t stx_size;               /* Taille du fichier en octets */
    uint64_t stx_blocks;            /* Nombre de blocs alloués */
    int64_t stx_attributes_mask;    /* Masque des attributs disponibles */
    struct {
        int64_t tv_sec;             /* Secondes depuis l'Epoch */
        int32_t tv_nsec;            /* Nanosecondes fractions */
    } stx_atime;            /* Temps de dernier accès */
    struct {
        int64_t tv_sec;
        int32_t tv_nsec;
    } stx_mtime;            /* Temps de dernière modification */
    struct {
        int64_t tv_sec;
        int32_t tv_nsec;
    } stx_ctime;            /* Temps de changement */
    struct {
        int64_t tv_sec;
        int32_t tv_nsec;
    } stx_btime;            /* Temps de création */
    uint32_t stx_dev_major;         /* ID majeur du périphérique */
    uint32_t stx_dev_minor;         /* ID mineur du périphérique */
    uint32_t stx_rdev_major;        /* ID majeur du périphérique spécial */
    uint32_t stx_rdev_minor;        /* ID mineur du périphérique spécial */
    uint64_t stx_mnt_id;            /* ID du point de montage */
    uint64_t stx_fsid_major;        /* ID majeur du système de fichiers */
    uint64_t stx_fsid_minor;        /* ID mineur du système de fichiers */
    uint64_t stx_mnt_root;          /* ID de la racine du point de montage */
    uint64_t stx_padding;           /* Non utilisé, réservé */
};

Le champ stx_mask dans la structure statxbuf indique quels champs de la structure ont été remplis par la requête. Les champs qui ne sont pas remplis auront la valeur correspondante dans stx_mask mise à zéro.

Les champs suivants sont des indications sur les attributs du fichier.

STATX_ATTR_COMPRESSED
Le fichier est compressé par le système de fichiers et peut nécessiter des ressources supplémentaires pour y accéder.
STATX_ATTR_IMMUTABLE
Le fichier ne peut pas être modifié : il ne peut pas être supprimé ou renommé, aucun lien physique ne peut être créé vers ce fichier et aucune donnée ne peut y être écrite. Voir chattr(1).
STATX_ATTR_APPEND
Le fichier ne peut être ouvert qu'en mode ajout pour l'écriture. L'écriture aléatoire n'est pas autorisée. Voir chattr(1).
STATX_ATTR_NODUMP
Le fichier n'est pas candidat à la sauvegarde lorsqu'un programme de sauvegarde tel que dump(8) est exécuté. Voir chattr(1).
STATX_ATTR_ENCRYPTED
Une clé est requise pour que le fichier soit chiffré par le système de fichiers.
STATX_ATTR_VERITY (depuis Linux 5.5)
Le fichier a le fs-verity activé. Il ne peut pas être écrit et toutes les lectures seront vérifiées par rapport à une somme cryptographique qui couvre l'intégralité du fichier (par exemple, via un arbre de Merkle).
STATX_ATTR_WRITE_ATOMIC (depuis Linux 6.11)
Le fichier prend en charge la protection contre les écritures déchirées. Le nombre maximal d'éléments dans un tableau de vecteurs pour une écriture avec protection contre les écritures déchirées activée. Voir le drapeau RWF_ATOMIC pour pwritev2(2).
STATX_ATTR_DAX (depuis Linux 5.8)
Le fichier est dans l'état DAX (accès direct par CPU). L'état DAX tente de minimiser les effets de cache logiciel pour les E/S et les mappages mémoire de ce fichier. Il nécessite un système de fichiers qui a été configuré pour prendre en charge DAX.
DAX suppose généralement que tous les accès se font via des instructions de chargement/stockage CPU, ce qui peut minimiser la surcharge pour les petits accès, mais peut nuire à l'utilisation du CPU pour les gros transferts.
Les E/S de fichiers sont effectuées directement vers/depuis les tampons de l'espace utilisateur et les E/S mappées en mémoire peuvent être effectuées avec des mappages mémoire directs qui contournent le cache de pages du noyau.
Bien que la propriété DAX ait tendance à entraîner des transferts de données synchrones, elle ne donne pas les mêmes garanties que le drapeau O_SYNC (voir open(2)), où les données et les métadonnées nécessaires sont transférées ensemble.
Un fichier DAX peut être mappé avec le drapeau MAP_SYNC, qui permet à un programme d'utiliser des instructions de vidage de cache CPU pour persister les opérations de stockage CPU sans un fsync(2) explicite. Voir mmap(2) pour plus d'informations.
STATX_ATTR_MOUNT_ROOT (depuis Linux 5.8)
Le fichier est la racine d'un montage.

Pour plus d'informations sur les champs ci-dessus, voir inode(7).

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La permission de recherche est refusée pour l'un des répertoires du préfixe de chemin de path. (Voir aussi path_resolution(7).)
EBADF
path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
path ou statxbuf pointe vers un emplacement en dehors de l'espace d'adressage accessible par le processus ou est NULL (sauf depuis Linux 6.11 si AT_EMPTY_PATH est spécifié dans flags, path est autorisé à être NULL).
EINVAL
Drapeau invalide spécifié dans flags.
EINVAL
Drapeau réservé spécifié dans mask. (Actuellement, il y a un tel drapeau, désigné par la constante STATX__RESERVED, avec la valeur 0x80000000U.)
ELOOP
Trop de liens symboliques rencontrés lors de la traversée du nom de chemin.
ENAMETOOLONG
path est trop long.
ENOENT
Un composant de path n'existe pas, ou path est une chaîne vide et AT_EMPTY_PATH n'a pas été spécifié dans flags.
ENOMEM
Plus de mémoire (c'est-à-dire mémoire noyau).
ENOTDIR
Un composant du préfixe de chemin de path n'est pas un répertoire ou path est relatif et dirfd est un descripteur de fichier se référant à un fichier autre qu'un répertoire.
