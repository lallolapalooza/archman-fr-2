STRIP(1) Outils de développement GNU STRIP(1)

NOM

strip - supprimer les symboles et autres données des fichiers objets

SYNTAXE

strip [-F nom_bfd |--target=nom_bfd]
[-I nom_bfd |--input-target=nom_bfd]
[-O nom_bfd |--output-target=nom_bfd]
[-s|--strip-all]
[-S|-g|-d|--strip-debug]
[--strip-dwo]
[-K nom_symbole|--keep-symbol=nom_symbole]
[-M|--merge-notes][--no-merge-notes]
[-N nom_symbole |--strip-symbol=nom_symbole]
[-w|--wildcard]
[-x|--discard-all] [-X |--discard-locals]
[-R nom_section |--remove-section=nom_section]
[--keep-section=motif_section]
[--remove-relocations=motif_section]
[--strip-section-headers]
[-o fichier] [-p|--preserve-dates]
[-D|--enable-deterministic-archives]
[-U|--disable-deterministic-archives]
[--keep-section-symbols]
[--keep-file-symbols]
[--only-keep-debug]
[--plugin nom]
[-v |--verbose] [-V|--version]
[--help] [--info]
fichier_objet...

DESCRIPTION

GNU strip supprime tous les symboles des fichiers objets fichier_objet. La liste des fichiers objets peut inclure des archives. Au moins un fichier objet doit être fourni.

strip modifie les fichiers nommés dans ses arguments, plutôt que d'écrire des copies modifiées sous des noms différents.

OPTIONS

-F nom_bfd
--target=nom_bfd
Traiter le fichier_objet original comme un fichier avec le format de code objet nom_bfd, et le réécrire dans le même format.
--help
Afficher un résumé des options de strip et quitter.
--info
Afficher une liste montrant tous les formats d'architecture et d'objet disponibles.
-I nom_bfd
--input-target=nom_bfd
Traiter le fichier_objet original comme un fichier avec le format de code objet nom_bfd.
-O nom_bfd
--output-target=nom_bfd
Remplacer fichier_objet par un fichier au format de sortie nom_bfd.
-R nom_section
--remove-section=nom_section
Supprimer toute section nommée nom_section du fichier de sortie, en plus des sections qui seraient autrement supprimées. Cette option peut être donnée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Le caractère générique * peut être donné à la fin de nom_section. Si c'est le cas, alors toute section commençant par nom_section sera supprimée.

Si le premier caractère de motif_section est le point d'exclamation (!) alors les sections correspondantes ne seront pas supprimées même si une utilisation antérieure de --remove-section sur la même ligne de commande les supprimerait autrement. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=motif_section
Lors de la suppression de sections du fichier de sortie, conserver les sections correspondant à motif_section.
--remove-relocations=motif_section
Supprimer les relocations du fichier de sortie pour toute section correspondant à motif_section. Cette option peut être donnée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans motif_section. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de motif_section est le point d'exclamation (!) alors les sections correspondantes n'auront pas leurs relocations supprimées même si une utilisation antérieure de --remove-relocations sur la même ligne de commande entraînerait autrement la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations pour les sections correspondant au motif '.text.*', mais ne supprimera pas les relocations pour la section '.text.foo'.

--strip-section-headers
Supprimer les en-têtes de section. Cette option est spécifique aux fichiers ELF. Implique --strip-all et --merge-notes.
-s
--strip-all
Supprimer tous les symboles.
-g
-S
-d
--strip-debug
Supprimer uniquement les symboles de débogage.
--strip-dwo
Supprimer le contenu de toutes les sections DWARF .dwo, en laissant les sections de débogage restantes et tous les symboles intacts. Voir la description de cette option dans la section objcopy pour plus d'informations.
--strip-unneeded
Supprimer tous les symboles qui ne sont pas nécessaires au traitement des relocations en plus des symboles et sections de débogage supprimés par --strip-debug.
-K nom_symbole
--keep-symbol=nom_symbole
Lors de la suppression de symboles, conserver le symbole nom_symbole même s'il serait normalement supprimé. Cette option peut être donnée plusieurs fois.
-M
--merge-notes
--no-merge-notes
Pour les fichiers ELF, tenter (ou ne pas tenter) de réduire la taille des sections de type SHT_NOTE en supprimant les notes dupliquées. Par défaut, cette réduction est tentée, sauf si des informations de débogage ou DWO sont supprimées.
-N nom_symbole
--strip-symbol=nom_symbole
Supprimer le symbole nom_symbole du fichier source. Cette option peut être donnée plusieurs fois et peut être combinée avec d'autres options de strip, sauf -K.
-o fichier
Placer la sortie débarrassée dans fichier, plutôt que de remplacer le fichier existant. Lorsque cet argument est utilisé, un seul argument fichier_objet peut être spécifié.
-p
--preserve-dates
Conserver les dates d'accès et de modification du fichier.
-D
--enable-deterministic-archives
Fonctionner en mode déterministe. Lors de la copie des membres d'archives et de l'écriture de l'index de l'archive, utiliser zéro pour les UID, GID, timestamps, et utiliser des modes de fichiers cohérents pour tous les fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec l'option -U, ci-dessous.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-U
--disable-deterministic-archives
Ne pas fonctionner en mode déterministe. C'est l'inverse de l'option -D, ci-dessus : lors de la copie des membres d'archives et de l'écriture de l'index d'archives, utiliser leurs UID, GID, horodatages et modes de fichiers réels.

C'est le comportement par défaut à moins que binutils n'ait été configuré avec --enable-deterministic-archives.

-w
--wildcard
Permet les expressions régulières dans les nom_symboles utilisés dans d'autres options de ligne de commande. Les opérateurs point d'interrogation (?), astérisque (*), antislash (\) et crochets ([]) peuvent être utilisés n'importe où dans le nom du symbole. Si le premier caractère du nom du symbole est le point d'exclamation (!) alors le sens de l'option est inversé pour ce symbole. Par exemple : 
-w -K !foo -K fo*

cela amènerait strip à ne conserver que les symboles qui commencent par les lettres « fo », mais à rejeter le symbole « foo ».

-x
--discard-all
Supprimer les symboles non globaux.
-X
--discard-locals
Supprimer les symboles locaux générés par le compilateur. (Ceux-ci commencent généralement par L ou ..)
--keep-section-symbols
Lors de la suppression des symboles d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant des noms de section, qui seraient autrement supprimés.
--keep-file-symbols
Lors de la suppression des symboles d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant des noms de fichiers source, qui seraient autrement supprimés.
--only-keep-debug
Supprime les symboles d'un fichier, en vidant le contenu de toutes les sections qui ne seraient pas supprimées par --strip-debug et en laissant les sections de débogage intactes. Dans les fichiers ELF, cela préserve également toutes les sections de notes dans la sortie.

Note - les en-têtes des sections supprimées sont préservés, y compris leurs tailles, mais le contenu de la section est écarté. Les en-têtes de section sont préservés afin que d'autres outils puissent associer le fichier d'informations de débogage avec l'exécutable réel, même si cet exécutable a été déplacé vers un espace d'adressage différent.

L'intention est que cette option soit utilisée conjointement avec --add-gnu-debuglink pour créer un exécutable en deux parties. L'une est un binaire dépouillé qui occupera moins d'espace en RAM et dans une distribution, et la seconde est un fichier d'informations de débogage qui n'est nécessaire que si des capacités de débogage sont requises. La procédure suggérée pour créer ces fichiers est la suivante :

1.<Liez l'exécutable normalement. En supposant qu'il s'appelle>
"foo" alors...
1.<Exécutez "objcopy --only-keep-debug foo foo.dbg" pour>
créer un fichier contenant les informations de débogage.
1.<Exécutez "objcopy --strip-debug foo" pour créer un>
exécutable dépouillé.
1.<Exécutez "objcopy --add-gnu-debuglink=foo.dbg foo">
pour ajouter un lien vers les informations de débogage dans l'exécutable dépouillé.

Note - le choix de ".dbg" comme extension pour le fichier d'informations de débogage est arbitraire. Aussi, l'étape "--only-keep-debug" est optionnelle. Vous pourriez faire ceci à la place :

1.<Liez l'exécutable normalement.>
1.<Copiez "foo" dans "foo.full">
1.<Exécutez "strip --strip-debug foo">
1.<Exécutez "objcopy --add-gnu-debuglink=foo.full foo">

c'est-à-dire, le fichier pointé par --add-gnu-debuglink peut être l'exécutable complet. Il n'a pas besoin d'être un fichier créé par l'option --only-keep-debug.

Note - cette option est uniquement destinée à être utilisée sur des fichiers entièrement liés. Il n'est pas logique de l'utiliser sur des fichiers objets où les informations de débogage peuvent être incomplètes. De plus, la fonctionnalité gnu_debuglink ne prend actuellement en charge que la présence d'un seul nom de fichier contenant des informations de débogage, et non plusieurs noms de fichiers sur une base un par fichier objet.

--plugin nom
Charge le plugin appelé nom pour ajouter la prise en charge de types cibles supplémentaires. Cette option n'est disponible que si la chaîne d'outils a été construite avec la prise en charge des plugins activée.

Si --plugin n'est pas fourni, mais que la prise en charge des plugins a été activée, alors strip itère sur les fichiers dans ${libdir}/bfd-plugins par ordre alphabétique et le premier plugin qui revendique l'objet en question est utilisé.

Veuillez noter que ce répertoire de recherche de plugins n'est pas celui utilisé par l'option -plugin de ld. Pour que strip utilise le plugin de l'éditeur de liens, il doit être copié dans le répertoire ${libdir}/bfd-plugins. Pour les compilations basées sur GCC, le plugin de l'éditeur de liens s'appelle liblto_plugin.so.0.0.0. Pour les compilations basées sur Clang, il s'appelle LLVMgold.so. Le plugin GCC est toujours rétrocompatible avec les versions antérieures, il suffit donc de copier le plus récent.

-V
--version
Affiche le numéro de version de strip.
-v
--verbose
Sortie verbeuse : liste tous les fichiers objets modifiés. Dans le cas des archives, strip -v liste tous les membres de l'archive.
@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure d'un antislash. Le fichier peut lui-même contenir des options @fichier supplémentaires ; de telles options seront traitées récursivement.
