stty(1p)

STTY(1P) Manuel du programmeur POSIX STTY(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

stty — définir les options d'un terminal

SYNTAXE

stty [-a|-g]
stty opérande...

DESCRIPTION

L'utilitaire stty définit ou rapporte les caractéristiques d'E/S du terminal pour le périphérique qui est son entrée standard. Sans options ni opérandes spécifiés, il rapportera les paramètres de certaines caractéristiques, généralement celles qui diffèrent des valeurs par défaut définies par l'implémentation. Sinon, il modifiera l'état du terminal conformément aux opérandes spécifiés. Des informations détaillées sur les modes listés dans les cinq premiers groupes ci-dessous sont décrites dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface Générale de Terminal. Les opérandes du groupe Modes Combinés (voir Modes Combinés) sont implémentés en utilisant des opérandes des groupes précédents. Certaines combinaisons d'opérandes sont mutuellement exclusives sur certains types de terminaux ; les résultats de l'utilisation de telles combinaisons ne sont pas spécifiés.

Les implémentations typiques de cet utilitaire nécessitent une ligne de communication configurée pour utiliser l'interface termios définie dans le volume Interfaces Système de POSIX.1‐2017. Sur les systèmes où aucune de ces lignes n'est disponible, et sur les lignes non configurées pour supporter l'interface termios, certains opérandes n'ont pas besoin d'affecter les caractéristiques du terminal.

OPTIONS

L'utilitaire stty doit se conformer au volume des Définitions de base de POSIX.1‐2017, Section 12.2, Lignes directrices de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-a
Écrit sur la sortie standard tous les paramètres actuels du terminal.
-g
Écrit sur la sortie standard tous les paramètres actuels sous une forme non spécifiée qui peut être utilisée comme arguments à une autre invocation de l'utilitaire stty sur le même système. La forme utilisée ne doit contenir aucun caractère nécessitant un guillemet pour éviter l'expansion de mots par le shell ; voir Section 2.6, Expansions de mots.

Modes de Contrôle

Sélectionne la parité impaire (paire). Cela aura pour effet de définir (ne pas définir) PARODD dans le champ c_cflag de termios, tel que défini dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface Générale de Terminal.

Sélectionne la taille des caractères, si possible. Cela aura pour effet de définir CS5, CS6, CS7 et CS8, respectivement, dans le champ c_cflag de termios, tel que défini dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface Générale de Terminal.
nombre
Définit la vitesse de transmission du terminal au nombre donné, si possible. Si la vitesse de transmission est définie à zéro, les lignes de contrôle du modem ne seront plus assertées. Cela aura pour effet de définir (ne pas définir) HUPCL dans le champ c_cflag de termios, tel que défini dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface Générale de Terminal.

clocal (-clocal)

Il n'est pas spécifié si stty doit signaler une erreur si une tentative de définition d'un Mode de Contrôle échoue.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Si des opérandes sont spécifiés, aucune sortie ne sera produite.

Si l'option -g est spécifiée, stty écrira sur la sortie standard les paramètres actuels sous une forme qui pourra être utilisée comme arguments pour une autre instance de stty sur le même système.

Si l'option -a est spécifiée, toutes les informations décrites dans la section OPERANDES seront écrites sur la sortie standard. Sauf indication contraire, ces informations seront écrites sous forme de jetons séparés par des <espaces> dans un format non spécifié, sur une ou plusieurs lignes, avec un nombre non spécifié de jetons par ligne. Des informations supplémentaires peuvent être écrites.

Si aucune option ni aucun opérande ne sont spécifiés, un sous-ensemble non spécifié des informations écrites pour l'option -a sera écrit.

Si des informations de vitesse sont écrites dans le cadre de la sortie par défaut, ou si l'option -a est spécifiée et si la vitesse d'entrée et la vitesse de sortie du terminal sont identiques, les informations de vitesse seront écrites comme suit :

"speed %d baud;", <vitesse>

Sinon, les vitesses seront écrites comme suit :

"ispeed %d baud; ospeed %d baud;", <vitesse_entrée>, <vitesse_sortie>

Dans les locales autres que la locale POSIX, le mot baud peut être remplacé par quelque chose de plus approprié dans ces locales.

Si des caractères de contrôle sont écrits dans le cadre de la sortie par défaut, ou si l'option -a est spécifiée, les caractères de contrôle seront écrits comme suit :

"%s = %s;", <nom_caractère_de_contrôle>, <valeur>

où <valeur> est soit le caractère, soit une représentation visuelle du caractère s'il n'est pas imprimable, soit la chaîne undef si le caractère est désactivé.

SORTIE D'ERREUR

La sortie d'erreur ne sera utilisée que pour les messages de diagnostic.

Les sections suivantes sont informatives.

UTILISATION POUR LES APPLICATIONS

L'indicateur -g est conçu pour faciliter la sauvegarde et la restauration de l'état du terminal depuis le niveau du shell. Par exemple, un programme peut :

saveterm="$(stty -g)"       # sauvegarder l'état du terminal
stty (nouveaux paramètres)     # définir le nouvel état
...                         # ...
stty $saveterm              # restaurer l'état du terminal

Comme le format n'est pas spécifié, la valeur sauvegardée n'est pas portable entre les systèmes.

Comme le format -a est très peu spécifié, les scripts qui sauvegardent et restaurent les paramètres du terminal devraient utiliser l'option -g.

JUSTIFICATION

La description originale de stty a été directement tirée de System V et reflétait le pilote de terminal termio de System V. Elle a été modifiée pour correspondre au pilote de terminal termios.

Les modes de sortie sont spécifiés uniquement pour les systèmes conformes XSI. Toutes les implémentations sont censées fournir des opérandes stty correspondant à tous les modes de sortie qu'elles prennent en charge.

L'utilitaire stty est principalement utilisé pour adapter l'interface utilisateur du terminal, comme la sélection des caractères ERASE et KILL préférés. En tant qu'utilitaire de programmation d'applications, stty peut être utilisé dans des scripts shell pour modifier les paramètres du terminal pendant la durée du script.

La section termios indique que la désactivation individuelle des caractères de contrôle est possible via l'option _POSIX_VDISABLE. Si elle est activée, deux conventions existent actuellement pour la spécifier : System V utilise "^-–", et BSD utilise undef. Les deux sont acceptés par stty dans ce volume de POSIX.1‐2017. L'autre convention BSD consistant à utiliser la lettre 'u' a été rejetée car elle entre en conflit avec la lettre 'u' réelle, qui est une valeur acceptable pour un caractère de contrôle.

Les premières propositions ne spécifiaient pas le mappage de "^c" aux caractères de contrôle car les caractères de contrôle n'étaient pas spécifiés dans les exigences du fichier de description des jeux de caractères de la locale POSIX. Le jeu de caractères de contrôle est maintenant spécifié dans le volume Base Definitions de POSIX.1‐2017, Chapitre 3, Définitions, donc le mappage historique est spécifié. Notez que bien que le mappage corresponde aux affectations de touches de caractères de contrôle sur de nombreux terminaux utilisant les encodages de caractères ISO/IEC 646:1991 (ou ASCII), le mappage spécifié ici concerne les caractères de contrôle, et non leur encodage clavier.

Comme termios supporte des vitesses séparées pour l'entrée et la sortie, deux nouvelles options ont été ajoutées pour spécifier chacune distinctement.

Certaines implémentations historiques utilisent l'entrée standard pour obtenir et définir les caractéristiques du terminal ; d'autres utilisent la sortie standard. Comme l'entrée d'un TTY de connexion est généralement restreinte au propriétaire tandis que la sortie vers un TTY est fréquemment ouverte à quiconque, l'utilisation de l'entrée standard offre moins de chances d'altérer accidentellement (ou malicieusement) les paramètres du terminal d'autres utilisateurs. L'utilisation de l'entrée standard permet également de rediriger la sortie de stty -a et stty -g pour une utilisation ultérieure. Par conséquent, l'utilisation de l'entrée standard est requise par ce volume de POSIX.1‐2017.
