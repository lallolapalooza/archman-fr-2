stat(3type) stat(3type)

NOM

stat - informations sur un fichier

BIBLIOTHQUE

Bibliothèque C standard (libc)

SYNTAXE

#include <sys/stat.h>
struct stat {
    dev_t      st_dev;      /* ID du périphérique contenant le fichier */
    ino_t      st_ino;      /* Numéro d'inode */
    mode_t     st_mode;     /* Type et permissions du fichier */
    nlink_t    st_nlink;    /* Nombre de liens physiques */
    uid_t      st_uid;      /* ID utilisateur du propriétaire */
    gid_t      st_gid;      /* ID groupe du propriétaire */
    dev_t      st_rdev;     /* ID du périphérique (si fichier spécial) */
    off_t      st_size;     /* Taille totale, en octets */
    blksize_t  st_blksize;  /* Taille de bloc pour les E/S du système de fichiers */
    blkcnt_t   st_blocks;   /* Nombre de blocs de 512 octets alloués */
    /* Depuis POSIX.1-2008, cette structure prend en charge la précision en nanosecondes pour les champs d'horodatage suivants.
       Pour les détails avant POSIX.1-2008, voir VERSIONS.  */
    struct timespec  st_atim;  /* Heure du dernier accès */
    struct timespec  st_mtim;  /* Heure de la dernière modification */
    struct timespec  st_ctim;  /* Heure du dernier changement de statut */
#define st_atime  st_atim.tv_sec  /* Compatibilité ascendante */
#define st_mtime  st_mtim.tv_sec
#define st_ctime  st_ctim.tv_sec
};
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

st_atim, st_mtim, st_ctim:

    Depuis glibc 2.12 :
        _POSIX_C_SOURCE >= 200809L || _XOPEN_SOURCE >= 700
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Décrit les informations relatives à un fichier.

Les champs sont les suivants :

st_dev
Ce champ décrit le périphérique sur lequel réside ce fichier. (Les macros major(3) et minor(3) peuvent être utiles pour décomposer l'ID du périphérique dans ce champ.)
st_ino
Ce champ contient le numéro d'inode du fichier.
st_mode
Ce champ contient le type et les permissions du fichier. Voir inode(7) pour plus d'informations.
st_nlink
Ce champ contient le nombre de liens physiques vers le fichier.
st_uid
Ce champ contient l'ID utilisateur du propriétaire du fichier.
st_gid
Ce champ contient l'ID du groupe propriétaire du fichier.
st_rdev
Ce champ décrit le périphérique que ce fichier (inode) représente.
st_size
Ce champ indique la taille du fichier (s'il s'agit d'un fichier régulier ou d'un lien symbolique) en octets. La taille d'un lien symbolique est la longueur du chemin qu'il contient, sans octet nul final.
st_blksize
Ce champ indique la taille de bloc « préférée » pour des E/S efficaces du système de fichiers.
st_blocks
Ce champ indique le nombre de blocs alloués au fichier, en unités de 512 octets. (Cela peut être inférieur à st_size/512 lorsque le fichier comporte des « trous ».)
st_atime
Ceci est l'heure du dernier accès aux données du fichier.
st_mtime
Ceci est l'heure de la dernière modification des données du fichier.
st_ctime
Ceci est l'horodatage du dernier changement de statut du fichier (heure du dernier changement de l'inode).

Pour plus d'informations sur les champs ci-dessus, voir inode(7).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

Les anciens noyaux et les anciennes normes ne prenaient pas en charge les champs d'horodatage en nanosecondes. Au lieu de cela, il y avait trois champs d'horodatage — st_atime, st_mtime et st_ctime  — de type time_t qui enregistraient les horodatages avec une précision d'une seconde.

Depuis Linux 2.5.48, la structure stat prend en charge la résolution en nanosecondes pour les trois champs d'horodatage de fichier. Les composantes nanosecondes de chaque horodatage sont disponibles via des noms de la forme st_atim.tv_nsec, si les macros de test appropriées sont définies. Les horodatages en nanosecondes ont été standardisés dans POSIX.1-2008 et, à partir de glibc 2.12, glibc expose les noms des composantes nanosecondes si _POSIX_C_SOURCE est défini avec la valeur 200809L ou supérieure, ou si _XOPEN_SOURCE est défini avec la valeur 700 ou supérieure. Jusqu'à et y compris glibc 2.19, les définitions des composantes nanosecondes sont également définies si _BSD_SOURCE ou _SVID_SOURCE est défini. Si aucune des macros susmentionnées n'est définie, alors les valeurs en nanosecondes sont exposées avec des noms de la forme st_atimensec.
