NOM

stl2dcm - Encapsule un fichier STL dans un fichier DICOM

SYNOPIS

stl2dcm [options] fichier_stl_entree fichier_dcm_sortie

DESCRIPTION

L'utilitaire stl2dcm lit un fichier STL (fichier_stl_entree), le convertit en une instance SOP DICOM STL Encapsulée et stocke les données converties dans un fichier de sortie (fichier_dcm_sortie).

PARAMÈTRES

fichier_stl_entree   Nom du fichier STL d'entrée à encapsuler
fichier_dcm_sortie  Nom du fichier DICOM de sortie ("-" pour stdout)

OPTIONS

Options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de la ligne de commande développés
  -q   --quiet
         mode silencieux, n'affiche aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode de débogage, affiche les informations de débogage
  -ll  --log-level  [n]iveau: chaîne de caractères constante
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l sur le logger
  -lc  --log-config  [f]ichier: chaîne de caractères
         utilise le fichier de configuration f pour le logger

Options du document DICOM

titre du document :
  +t   --title  [t]itre : chaîne de caractères (par défaut : vide)
         titre du document
  +cn  --concept-name  [CSD] [CV] [CM] : chaîne de caractères (par défaut : vide)
         représentation codée du titre du document définie par le schéma de codage
         designateur CSD, valeur de code CV et signification de code CM
données du patient :
  +pn  --patient-name  [n]om : chaîne de caractères
         nom du patient en syntaxe PN DICOM
  +pi  --patient-id  [i]d : chaîne de caractères
         identifiant du patient
  +pb  --patient-birthdate  [d]ate : chaîne de caractères (AAAAJJMMAAAA)
         date de naissance du patient
  +ps  --patient-sex  [s]exe : chaîne de caractères (M, F ou O)
         sexe du patient
étude et série :
  +sg  --generate
         génère de nouveaux UID d'étude et de série (par défaut)
  +st  --study-from  [f]ichier : chaîne de caractères
         lit les données patient/étude du fichier DICOM
  +se  --series-from  [f]ichier : chaîne de caractères
         lit les données patient/étude/série du fichier DICOM
numéro d'instance :
  +i1  --instance-one
         utilise le numéro d'instance 1 (par défaut, pas avec +se)
  +ii  --instance-inc
         incrémente le numéro d'instance (uniquement avec +se)
  +is  --instance-set [i]nstance number : entier
         utilise le numéro d'instance i
annotation intégrée :
  +an  --annotation-yes
         le document contient des données identifiant le patient (par défaut)
  -an  --annotation-no
         le document ne contient pas de données identifiant le patient
équipement général amélioré :
  +mn  --manufacturer  [n]om : chaîne de caractères
         nom du fabricant
  +mm  --manufacturer-model  [n]om : chaîne de caractères
         modèle du fabricant
  +ds  --device-serial  [n]uméro : chaîne de caractères
         numéro de série de l'appareil
  +sv  --software-versions  [v]ersions : chaîne de caractères
         versions logicielles
unités de mesure du modèle 3D :
  +mu  --measurement-units  [CSD] [CV] [CM] : chaîne de caractères
         unités de mesure avec designateur de schéma de codage CSD,
         valeur de code CV et signification de code CM (par défaut : UCUM, um, um)

Options de traitement

autres options de traitement :
  -k   --key  [c]lé : gggg,eeee="str", chemin ou nom de dictionnaire="str"
         ajoute un attribut supplémentaire

Options de sortie

format du fichier de sortie :
  +F   --write-file
         écrit au format fichier (par défaut)
  -F   --write-dataset
         écrit le jeu de données sans informations de métadonnées du fichier
encodage de la longueur du groupe :
  +g=  --group-length-recalc
         recalcule les longueurs de groupe si présentes (par défaut)
  +g   --group-length-create
         écrit toujours avec des éléments de longueur de groupe
  -g   --group-length-remove
         écrit toujours sans éléments de longueur de groupe
encodage de la longueur dans les séquences et les éléments :
  +e   --length-explicit
         écrit avec des longueurs explicites (par défaut)
  -e   --length-undefined
         écrit avec des longueurs indéfinies
remplissage des données du jeu de données (pas avec --write-dataset) :
  -p   --padding-off
         pas de remplissage (implicite avec --write-dataset)
  +p   --padding-create  [r]emplissage_fichier [r]emplissage_élément : entier
         aligne le fichier sur un multiple de r octets
         et les éléments sur un multiple de r octets

NOTES

Sources des attributs

L'application peut être alimentée avec des entrées supplémentaires pour remplir les attributs obligatoires (et optionnels) dans le nouveau fichier DICOM, tels que les informations du patient, de l'étude et de la série :

  • L'option --key peut être utilisée pour ajouter des attributs supplémentaires au fichier DICOM de sortie.
  • Il est également possible de spécifier des séquences, des éléments et des attributs imbriqués en utilisant l'option --key. Dans ces cas, une notation spéciale de "chemin" doit être utilisée. Les détails de cette notation de chemin se trouvent dans la documentation de dcmodify.
  • L'option --key peut être répétée plusieurs fois.
  • La partie valeur (après le '=') peut être absente, ce qui amène l'attribut à être défini avec une longueur nulle.
  • Veuillez noter que l'option --key est appliquée à la toute fin, juste avant de sauvegarder le fichier DICOM, il n'y a donc aucune vérification de valeur.

JOURNALISATION

Le niveau de sortie de journalisation des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. L'utilisation de l'option --verbose permet également de signaler des messages d'information tels que des détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, consultez la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (éventuellement avec rotation de fichier journal), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent les valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de la ligne de commande sont distinguées des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de la ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options sont mutuellement exclusives, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commandes peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les espaces multiples sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute évaluation ultérieure. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer les combinaisons courantes d'options/paramètres et évite les lignes de commande longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire stl2dcm tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut être chargé.
