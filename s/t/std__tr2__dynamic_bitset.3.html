classe std::tr2::dynamic_bitset< _WordT, _Alloc >

La classe dynamic_bitset représente une séquence de bits.

Voir N2050, Proposition d'ajout d'un bitset redimensionnable dynamiquement à la bibliothèque standard. http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2006/n2050.pdf

Dans le cas général non optimisé, le stockage est alloué par blocs de taille de mot. Soit B le nombre de bits dans un mot, alors (Nb+(B-1))/B mots seront utilisés pour le stockage. B - NbB bits sont inutilisés. (Ce sont les bits de poids fort dans le mot le plus significatif.) C'est un invariant de classe que ces bits inutilisés soient toujours à zéro.

Si vous considérez dynamic_bitset comme « un simple tableau de bits », sachez que votre image mentale est inversée : un dynamic_bitset se comporte de la même manière que les bits dans les entiers, le bit d'indice 0 étant en position « de poids faible / droite », et le bit d'indice Nb-1 en position « de poids fort / gauche ». Ainsi, contrairement aux autres conteneurs, l'indice d'un dynamic_bitset « compte de droite à gauche », pour le dire très approximativement.

Ce comportement est préservé lors de la traduction depuis et vers des chaînes de caractères. Par exemple, la première ligne du programme suivant affiche probablement « b('a') est 0001100001 » sur un système ASCII moderne.

#include <dynamic_bitset>
#include <iostream>
#include <sstream>
using namespace std;
int main()
{
    long         a = 'a';
    dynamic_bitset<> b(a);
    cout << "b('a') est " << b << endl;
    ostringstream s;
    s << b;
    string  str = s.str();
    cout << "l'indice 3 dans la chaîne est " << str[3] << " mais\n"
         << "l'indice 3 dans le bitset est " << b[3] << endl;
}

La majeure partie du code réel n'est pas contenue dans dynamic_bitset<> elle-même, mais dans la classe de base __dynamic_bitset_base. La classe de base travaille avec des mots entiers, pas avec des bits individuels. Cela nous permet de spécialiser __dynamic_bitset_base pour le cas spécial important où le dynamic_bitset n'est qu'un seul mot.

Une confusion supplémentaire peut résulter du fait que le stockage pour __dynamic_bitset_base est un vecteur, et qu'il est indexé en tant que tel. Ceci est soigneusement encapsulé.
