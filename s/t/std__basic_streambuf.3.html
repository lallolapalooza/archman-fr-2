Description détaillée

template<typename _CharT, typename _Traits>

The basic_streambuf class is the base class for stream buffers, which contain character processing and buffering semantics for input and output. This class provides the main interface for stream buffers, including the buffer management and I/O operations themselves. It is intended to be used as a base class for stream buffer implementations.

This class manages input and output buffers, represented by get-area and put-area pointers. The get-area is used for input operations, while the put-area is used for output operations. The actual character processing is delegated to virtual functions such as underflow, overflow, pbackfail, and sync, which are intended to be overridden by derived classes.

The basic_streambuf class is templated on the character type (_CharT) and the character traits (_Traits). This allows it to be used with different character types (e.g., char, wchar_t) and different trait classes.

Public member functions provide access to the stream buffer's state, locale, and buffer management functions. Protected member functions are intended for use by derived classes to manage the buffer pointers and implement the character processing logic.

The following public member functions are the primary interface for interacting with a stream buffer:

• getloc: Returns the locale associated with the stream buffer.

• pubimbue: Sets the locale associated with the stream buffer.

• in_avail: Returns the number of characters available for input.

• sbumpc: Extracts and returns the next character from the input buffer.

• sgetc: Returns the next character from the input buffer without extracting it.

• sgetn: Extracts up to n characters from the input buffer into a character array.

• snextc: Extracts and returns the next character from the input buffer, after advancing the read pointer.

• sputbackc: Pushes a character back into the input buffer.

• sputc: Inserts a character into the output buffer.

• sputn: Inserts up to n characters from a character array into the output buffer.

• sungetc: Moves the input pointer back one character.

• pubsetbuf: Sets the stream buffer's underlying buffer.

• pubseekoff: Changes the stream position by an offset.

• pubseekpos: Changes the stream position to a specific position.

• pubsync: Synchronizes the buffer with the associated character sequence.

Protected virtual functions provide the core stream buffer functionality:

• overflow: Called when the output buffer is full. Derived classes should implement this to write the buffer contents and handle the new character.

• pbackfail: Called when an attempt is made to push back a character that cannot be accommodated by the buffer. Derived classes can implement this to handle such cases.

• seekoff: Called by pubseekoff to perform the actual stream positioning.

• seekpos: Called by pubseekpos to perform the actual stream positioning.

• setbuf: Called by pubsetbuf to set the buffer.

• sync: Called by pubsync to synchronize the buffer. Derived classes should implement this to ensure that buffered data is written to the underlying output device.

• uflow: Called to fetch the next character from the input stream when the input buffer is empty. Derived classes should implement this to read data from the source.

• underflow: Called to fetch the next character from the input stream when the input buffer is empty, but without consuming it. Derived classes should implement this to read data from the source.

• xsgetn: Called to extract multiple characters from the input stream. Derived classes should implement this for efficient reading.

• xsputn: Called to insert multiple characters into the output stream. Derived classes should implement this for efficient writing.

The protected attributes define the internal state of the stream buffer, including the pointers to the beginning, current position, and end of the input and output buffers, as well as the current locale.

The friends section lists classes and functions that have access to the protected members of basic_streambuf. These are typically other stream-related classes and iterator types.

_CharT Type de flux de caractères.
_Traits Traits pour le type de caractère, par défaut char_traits<_CharT>.

Ceci est une classe de base. Les tampons de flux dérivés contrôlent chacun une paire de séquences de caractères : une pour l'entrée et une pour la sortie.

La section [27.5.1] de la norme décrit les exigences et le comportement des classes de tampons de flux. Cette section (trois paragraphes) est reproduite ici, pour plus de simplicité et d'exactitude.

1.
Les tampons de flux peuvent imposer diverses contraintes sur les séquences qu'ils contrôlent. Certaines contraintes sont :
•
La séquence d'entrée contrôlée peut ne pas être lisible.
•
La séquence de sortie contrôlée peut ne pas être inscriptible.
•
Les séquences contrôlées peuvent être associées au contenu d'autres représentations de séquences de caractères, telles que des fichiers externes.
•
Les séquences contrôlées peuvent prendre en charge les opérations *directement* vers ou depuis des séquences associées.
•
Les séquences contrôlées peuvent imposer des limitations sur la manière dont le programme peut lire des caractères d'une séquence, écrire des caractères dans une séquence, remettre des caractères dans une séquence d'entrée, ou modifier la position du flux.
2.
Chaque séquence est caractérisée par trois pointeurs qui, s'ils ne sont pas nuls, pointent tous vers le même objet tableau charT. Le tableau représente, à tout moment, une (sous)séquence de caractères de la séquence. Les opérations effectuées sur une séquence modifient les valeurs stockées dans ces pointeurs, effectuent des lectures et des écritures directement vers ou depuis des séquences associées, et modifient *la position du flux* et l'état de conversion si nécessaire pour maintenir cette relation de sous-séquence. Les trois pointeurs sont :
•
le *pointeur de début*, ou adresse de l'élément le plus bas dans le tableau (appelé *xbeg* ici) ;
•
le *pointeur suivant*, ou adresse de l'élément suivant qui est un candidat actuel pour la lecture ou l'écriture (appelé *xnext* ici) ;
•
le *pointeur de fin*, ou adresse du premier élément au-delà de la fin du tableau (appelé *xend* ici).
3.
Les contraintes sémantiques suivantes s'appliquent toujours pour tout ensemble de trois pointeurs pour une séquence, en utilisant les noms de pointeurs donnés immédiatement ci-dessus :
•
Si *xnext* n'est pas un pointeur nul, alors *xbeg* et *xend* doivent également être des pointeurs non nuls dans le même tableau charT, comme décrit ci-dessus ; sinon, *xbeg* et *xend* doivent également être nuls.
•
Si *xnext* n'est pas un pointeur nul et que *xnext* < *xend* pour une séquence de sortie, alors une *position d'écriture* est disponible. Dans ce cas, *xnext* doit être assignable comme élément suivant à écrire (pour mettre, ou pour stocker une valeur de caractère, dans la séquence).
•
Si *xnext* n'est pas un pointeur nul et que *xbeg* < *xnext* pour une séquence d'entrée, alors une *position de remise* est disponible. Dans ce cas, *xnext*[-1] doit avoir une valeur définie et est l'élément suivant (précédent) à stocker un caractère qui est remis dans la séquence d'entrée.
•
Si *xnext* n'est pas un pointeur nul et que *xnext* < *xend* pour une séquence d'entrée, alors une *position de lecture* est disponible. Dans ce cas, *xnext* doit avoir une valeur définie et est l'élément suivant à lire (pour obtenir, ou pour obtenir une valeur de caractère, à partir de la séquence).

template<typename _CharT, typename _Traits> virtual int_type std::basic_streambuf< _CharT, _Traits >::underflow () [inline], [protected], [virtual]

Le premier caractère de la séquence en attente.

Informellement, cette fonction est appelée lorsque le tampon d'entrée est épuisé (ou n'existe pas, car la mise en tampon n'est pas réellement requise). Si un tampon existe, il est rempli.
