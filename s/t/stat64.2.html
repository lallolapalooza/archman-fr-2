stat(2) Manuel des appels système stat(2)

NOM

stat, fstat, lstat, fstatat - obtenir l'état d'un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

lstat():

    /* Depuis glibc 2.20 */ _DEFAULT_SOURCE
        || _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.10 : */ _POSIX_C_SOURCE >= 200112L
        || /* glibc 2.19 et antérieures */ _BSD_SOURCE

fstatat():

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _ATFILE_SOURCE

DESCRIPTION

Ces fonctions renvoient des informations sur un fichier, dans le tampon pointé par statbuf. Aucune autorisation n'est requise sur le fichier lui-même, mais—dans le cas de stat(), fstatat(), et lstat()—l'autorisation d'exécution (de recherche) est requise sur tous les répertoires de path qui mènent au fichier.

stat() et fstatat() récupèrent des informations sur le fichier pointé par path ; les différences pour fstatat() sont décrites ci-dessous.

lstat() est identique à stat(), sauf que si path est un lien symbolique, elle renvoie des informations sur le lien lui-même, pas sur le fichier auquel le lien fait référence.

fstat() est identique à stat(), sauf que le fichier pour lequel des informations doivent être récupérées est spécifié par le descripteur de fichier fd.

La structure stat

Tous ces appels système renvoient une structure stat (voir stat(3type)).

Note : pour des raisons de performance et de simplicité, différents champs de la structure stat peuvent contenir des informations d'état provenant de différents moments durant l'exécution de l'appel système. Par exemple, si st_mode ou st_uid est modifié par un autre processus en appelant chmod(2) ou chown(2), stat() pourrait renvoyer l'ancien st_mode avec le nouveau st_uid, ou l'ancien st_uid avec le nouveau st_mode.

fstatat()

L'appel système fstatat() est une interface plus générale pour accéder aux informations de fichier qui peut toujours fournir exactement le comportement de chacun de stat(), lstat(), et fstat().

Si path est relatif, alors il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme le fait stat() et lstat() pour un chemin relatif).

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel du processus appelant (comme stat() et lstat()).

Si path est absolu, alors dirfd est ignoré.

flags peut être soit 0, soit inclure un ou plusieurs des indicateurs suivants combinés par OU logique :

AT_EMPTY_PATH (depuis Linux 2.6.39)
Si path est une chaîne vide (ou NULL, depuis Linux 6.11) opérez sur le fichier référencé par dirfd (qui peut avoir été obtenu en utilisant l'indicateur O_PATH de open(2)). Dans ce cas, dirfd peut faire référence à n'importe quel type de fichier, pas seulement un répertoire, et le comportement de fstatat() est similaire à celui de fstat(). Si dirfd est AT_FDCWD, l'appel opère sur le répertoire de travail actuel. Cet indicateur est spécifique à Linux ; définissez _GNU_SOURCE pour obtenir sa définition.
AT_NO_AUTOMOUNT (depuis Linux 2.6.38)
Ne pas automatiquement monter le composant terminal ("nom de base") de path. Depuis Linux 3.1 cet indicateur est ignoré. Depuis Linux 4.11 cet indicateur est implicite.
AT_SYMLINK_NOFOLLOW
Si path est un lien symbolique, ne pas le suivre : renvoyer plutôt des informations sur le lien lui-même, comme lstat(). (Par défaut, fstatat() suit les liens symboliques, comme stat().)

Voir openat(2) pour une explication du besoin pour fstatat().

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est définie pour indiquer l'erreur.

ERREURS

EACCES
La permission de recherche est refusée pour l'un des répertoires du préfixe du chemin de path. (Voir aussi path_resolution(7).)
EBADF
fd n'est pas un descripteur de fichier ouvert valide.
EBADF
(fstatat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
Mauvaise adresse.
EINVAL
(fstatat()) Indicateur invalide spécifié dans flags.
ELOOP
Trop de liens symboliques rencontrés lors du parcours du chemin.
ENAMETOOLONG
path est trop long.
ENOENT
Un composant de path n'existe pas ou est un lien symbolique dangling.
ENOENT
path est une chaîne vide et AT_EMPTY_PATH n'a pas été spécifié dans flags.
ENOMEM
Manque de mémoire (c'est-à-dire mémoire du noyau).
ENOTDIR
Un composant du préfixe du chemin de path n'est pas un répertoire.
ENOTDIR
(fstatat()) path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.
EOVERFLOW
path ou fd fait référence à un fichier dont la taille, le numéro d'inode, ou le nombre de blocs ne peut pas être représenté dans, respectivement, les types off_t, ino_t, ou blkcnt_t. Cette erreur peut survenir lorsque, par exemple, une application compilée sur une plateforme 32 bits sans -D_FILE_OFFSET_BITS=64 appelle stat() sur un fichier dont la taille dépasse (1<<31)-1 octets.

NORMES

POSIX.1-2024.

NOM

lstat, fstatat, stat, fstat, llstat — obtenir des informations sur un fichier

BIBLIOTHQUE

Bibliothèque C standard (libc, −lc)

SYNOPSIS

#include <sys/stat.h>

int stat(const char *restrict pathname, struct stat *restrict statbuf);
int lstat(const char *restrict pathname, struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);

#define _XOPEN_SOURCE /* Voir feature_test_macros(7) */
#include <fcntl.h> /* Pour O_PATH */
int fstatat(int dirfd, const char *pathname, struct stat *statbuf, int flags);

DESCRIPTION

Les fonctions stat(), lstat() et fstat() obtiennent des informations sur le fichier spécifié par pathname ou fd et les stockent dans la structure pointée par statbuf. Ces fonctions sont identiques sauf pour la façon dont elles traitent les liens symboliques.

stat() suit les liens symboliques.

lstat() ne suit pas les liens symboliques ; si le nom de fichier donné est un lien symbolique, alors le fichier est le lien lui-même.

fstat() est similaire à stat() mais opère sur un descripteur de fichier ouvert fd.

La fonction fstatat() est similaire à fstat() sauf qu'elle agit sur un fichier spécifié par pathname relativement à un répertoire spécifié par dirfd. L'interprétation de pathname est différente de celle de stat() : si pathname est un chemin absolu, alors dirfd est ignoré. Si pathname est un chemin relatif, il est résolu par rapport au répertoire représenté par le descripteur de fichier dirfd. Si pathname spécifie un chemin relatif et que dirfd est AT_FDCWD, alors pathname est résolu par rapport au répertoire de travail courant. Si flags contient AT_SYMLINK_NOFOLLOW, alors fstatat() se comporte comme lstat() ; sinon, elle se comporte comme stat().

La structure stat contient au moins les champs suivants :

st_mode
Les bits de mode de fichier et les indicateurs de type de fichier.
st_ino
Numéro de l'i-node.
st_dev
Identifiant du périphérique sur lequel se trouve le fichier.
st_nlink
Nombre de liens matériels.
st_uid
Identifiant de l'utilisateur propriétaire.
st_gid
Identifiant du groupe propriétaire.
st_size
Taille du fichier en octets.
st_atime
Heure du dernier accès.
st_mtime
Heure de la dernière modification.
st_ctime
Heure du dernier changement d'état.

Les champs st_mode sont définis comme suit :

S_IFMT
Masque pour obtenir le type de fichier.
S_IFSOCK
Socket de domaine Unix.
S_IFLNK
Lien symbolique.
S_IFREG
Fichier régulier.
S_IFBLK
Périphérique bloc.
S_IFDIR
Répertoire.
S_IFCHR
Périphérique caractère.
S_IFIFO
FIFO (tube nommé).

Les constantes S_ISDIR, S_ISREG, etc., sont définies pour tester le type de fichier à partir de st_mode.

Les champs st_atime, st_mtime et st_ctime sont des structures timespec qui contiennent des secondes et des nanosecondes.

Les champs st_blocks et st_blksize indiquent le nombre de blocs de 512 octets alloués au fichier et la taille de bloc préférée pour les opérations d'E/S. La façon dont ces valeurs sont calculées et interprétées peut varier selon les systèmes de fichiers et les implémentations.

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Les fonctions stat(), lstat() et fstatat() échoueront dans les cas suivants :

EACCES
Le répertoire de recherche du chemin d'accès est inaccessible en lecture et en exécution, ou le fichier lui-même est inaccessible en lecture.
EBADF
fd est invalide.
EFAULT
statbuf pointe hors de l'espace d'adressage utilisateur.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution du chemin.
ENAMETOOLONG
Un composant d'un nom de fichier dépasse PATH_MAX.
ENOENT
Le fichier n'existe pas, ou pathname est un chemin vide.
ENOTDIR
pathname est un chemin relatif et dirfd représente un fichier qui n'est pas un répertoire.
ENXIO
Le fichier est un périphérique de bloc ou caractère et le nom de fichier spécifié n'existe pas sur le périphérique.
EOVERFLOW
Un champ de fichier est trop grand pour être représenté.
EROFS
Le fichier se trouve sur un système de fichiers en lecture seule et mode tente de modifier des bits de mode.
ETXTBSY
Le fichier est un fichier texte utilisé et le système d'exploitation empêche l'accès.

La fonction fstat() échouera en cas de :

EBADF
fd n'est pas un descripteur de fichier valide.
EFAULT
statbuf pointe hors de l'espace d'adressage utilisateur.
EINVAL
fd ne fait pas référence à un fichier.
EOVERFLOW
Un champ de fichier est trop grand pour être représenté.

Les fonctions fstatat() échoueront également en cas de :

EINVAL
dirfd n'est pas un descripteur de fichier valide.
EINVAL
La valeur flags n'est pas valide.

NORMES

Les fonctions stat(), lstat() et fstat() sont conformes à POSIX.1-2008.

La fonction fstatat() est conforme à POSIX.1-2008.

POSIX.1-2008 exige que lstat() renvoie des informations valides dans tous les champs, à l'exception des bits de mode dans st_mode.

L'utilisation des champs st_blocks et st_blksize peut être moins portable. (Ils ont été introduits par BSD. L'interprétation diffère entre les systèmes, et potentiellement sur un même système lorsque des montages NFS sont impliqués.)

Différences Bibliothèque C/Noyau

Au fil du temps, l'augmentation de la taille de la structure stat a conduit à trois versions successives de stat() : sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), et sys_stat64() (slot __NR_stat64) sur les plates-formes 32 bits comme i386. Les deux premières versions étaient déjà présentes dans Linux 1.0 (bien qu'avec des noms différents) ; la dernière a été ajoutée dans Linux 2.4. Des remarques similaires s'appliquent à fstat() et lstat().

Les versions internes au noyau de la structure stat traitées par les différentes versions sont, respectivement :

__old_kernel_stat
La structure originale, avec des champs assez étroits, et aucun rembourrage.
stat
Structure plus grande avec le champ st_ino et du rembourrage ajouté à diverses parties de la structure pour permettre une expansion future.
stat64
Champ st_ino encore plus grand, champs st_uid et st_gid plus grands pour accueillir l'expansion des UID et GID à 32 bits dans Linux 2.4, et divers autres champs agrandis et un rembourrage supplémentaire dans la structure. (Divers octets de rembourrage ont finalement été consommés dans Linux 2.6, avec l'avènement des identifiants de périphérique 32 bits et des composants de nanosecondes pour les champs d'horodatage.)

La fonction wrapper stat() de glibc masque ces détails aux applications, en invoquant la version la plus récente de l'appel système fournie par le noyau, et en reconditionnant les informations renvoyées si nécessaire pour les anciens binaires.

Sur les systèmes 64 bits modernes, la vie est plus simple : il n'y a qu'un seul appel système stat() et le noyau traite une structure stat contenant des champs de taille suffisante.

L'appel système sous-jacent utilisé par la fonction wrapper fstatat() de glibc s'appelle en réalité fstatat64() ou, sur certaines architectures, newfstatat().

EXEMPLES

Le programme suivant appelle lstat() et affiche des champs sélectionnés dans la structure stat renvoyée.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID du périphérique contenant :  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("Type de fichier :                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("périphérique bloc\n");            break;
    case S_IFCHR:  printf("périphérique caractère\n");        break;
    case S_IFDIR:  printf("répertoire\n");               break;
    case S_IFIFO:  printf("FIFO/tube\n");               break;
    case S_IFLNK:  printf("lien symbolique\n");                 break;
    case S_IFREG:  printf("fichier régulier\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("inconnu?\n");                break;
    }
    printf("Numéro d'i-node :            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode :                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Nombre de liens :               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Propriété :                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Taille de bloc d'E/S préférée : %jd octets\n",
           (intmax_t) sb.st_blksize);
    printf("Taille du fichier :                %jd octets\n",
           (intmax_t) sb.st_size);
    printf("Blocs alloués :         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Dernier changement d'état :       %s", ctime(&sb.st_ctime));
    printf("Dernier accès au fichier :         %s", ctime(&sb.st_atime));
    printf("Dernière modification du fichier :   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
