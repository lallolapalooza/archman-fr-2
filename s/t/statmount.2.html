statmount(2) Manuel des appels système statmount(2)

NOM

statmount - obtenir le statut d'un montage

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <linux/mount.h>  /* Définition des constantes STATMOUNT_* */
#include <unistd.h>
int syscall(SYS_statmount, struct mnt_id_req *req,
            struct statmount *smbuf, size_t bufsize,
            unsigned long flags);
#include <linux/mount.h>
struct mnt_id_req {
    __u32  size;    /* sizeof(struct mnt_id_req) */
    __u64  mnt_id;  /* L'ID de montage interrogé */
    __u64  param;   /* Une combinaison OR des constantes STATMOUNT_* */
};
struct statmount {
    __u32  size;
    __u64  mask;
    __u32  sb_dev_major;
    __u32  sb_dev_minor;
    __u64  sb_magic;
    __u32  sb_flags;
    __u32  fs_type;
    __u64  mnt_id;
    __u64  mnt_parent_id;
    __u32  mnt_id_old;
    __u32  mnt_parent_id_old;
    __u64  mnt_attr;
    __u64  mnt_propagation;
    __u64  mnt_peer_group;
    __u64  mnt_master;
    __u64  propagate_from;
    __u32  mnt_root;
    __u32  mnt_point;
    char   str[];
};

Note : glibc ne fournit pas d'enveloppe pour statmount(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

Pour accéder au statut d'un montage, l'appelant doit posséder CAP_SYS_ADMIN dans l'espace de noms utilisateur.

Cette fonction renvoie des informations sur un montage, les stockant dans le tampon pointé par smbuf. Le tampon retourné est une struct statmount dont la taille est bufsize, avec les champs remplis comme décrit ci-dessous.

(Notez que l'espace réservé et le rembourrage sont omis.)

La structure mnt_id_req

req.size est utilisée par le noyau pour déterminer quelle struct mnt_id_req est passée ; elle doit toujours être définie à sizeof(struct mnt_id_req).

req.mnt_id peut être obtenu soit de statx(2) en utilisant STATX_MNT_ID_UNIQUE, soit de listmount(2) et est utilisé comme identifiant pour interroger le statut du point de montage désiré.

req.param est utilisé pour indiquer au noyau quels champs intéressent l'appelant. C'est une combinaison OR des constantes suivantes :


STATMOUNT_SB_BASIC /* Désire/obtenu sb_* */
STATMOUNT_MNT_BASIC /* Désire/obtenu mnt_* */
STATMOUNT_PROPAGATE_FROM /* Désire/obtenu propagate_from */
STATMOUNT_MNT_ROOT /* Désire/obtenu mnt_root */
STATMOUNT_MNT_POINT /* Désire/obtenu mnt_point */
STATMOUNT_FS_TYPE /* Désire/obtenu fs_type */

En général, le noyau rejette pas les valeurs dans req.param autres que celles ci-dessus. (Pour une exception, voir EINVAL dans les erreurs.) Au lieu de cela, il informe simplement l'appelant des valeurs supportées par ce noyau et ce système de fichiers via le champ statmount.mask. Par conséquent, ne définissez pas simplement req.param à UINT_MAX (tous les bits définis), car un ou plusieurs bits pourraient, à l'avenir, être utilisés pour spécifier une extension du tampon.

Les informations renvoyées

Les informations de statut pour le montage cible sont renvoyées dans la structure statmount pointée par smbuf.

Les champs de la structure statmount sont :

smbuf.size
La taille de la structure smbuf retournée, y compris tous les champs de chaînes qui ont été remplis.
smbuf.mask
La combinaison OR des drapeaux STATMOUNT_* indiquant quels champs ont été remplis et sont donc valides. Le noyau peut renvoyer des champs qui n'étaient pas demandés, et peut ne pas renvoyer des champs qui étaient demandés, en fonction de ce que le système de fichiers sous-jacent et le noyau supportent. Dans les deux cas, req.param ne sera pas égal à mask.
smbuf.sb_dev_major
smbuf.sb_dev_minor
Le périphérique qui est monté à ce point de montage.
smbuf.sb_magic
Le nombre magique spécifique au système de fichiers de la super-bloc.
smbuf.sb_flags
Les drapeaux qui sont définis sur la super-bloc, une combinaison OR de SB_RDONLY, SB_SYNCHRONOUS, SB_DIRSYNC, SB_LAZYTIME.
smbuf.fs_type
Le décalage vers l'emplacement dans le tampon smbuf.str qui contient la représentation textuelle du système de fichiers monté. C'est une chaîne terminée par un caractère nul.
smbuf.mnt_id
L'identifiant de montage unique du montage.
smbuf.mnt_parent_id
L'identifiant de montage unique du point de montage parent de ce montage. Si c'est le point de montage racine, alors smbuf.mnt_id == smbuf.parent_mount_id.
smbuf.mnt_id_old
Ceci correspond à l'ID de montage qui est exporté par /proc/pid/mountinfo.
smbuf.mnt_parent_id_old
Ceci correspond à l'ID de montage parent qui est exporté par /proc/pid/mountinfo.
smbuf.mnt_attr
Les drapeaux MOUNT_ATTR_* définis sur ce point de montage.
smbuf.mnt_propagation
Les drapeaux de propagation de montage, qui peuvent être l'un de MS_SHARED, MS_SLAVE, MS_PRIVATE, MS_UNBINDABLE.
smbuf.mnt_peer_group
L'identifiant du groupe de pairs partagé.
smbuf.mnt_master
Le point de montage reçoit sa propagation de cet ID de montage.
smbuf.propagate_from
L'identifiant de l'espace de noms d'où nous avons propagé.
smbuf.mnt_root
Le décalage vers l'emplacement dans le tampon smbuf.str qui contient la représentation textuelle du montage par rapport à la racine du système de fichiers. C'est une chaîne terminée par un caractère nul.
smbuf.mnt_point
Le décalage vers l'emplacement dans le tampon smbuf.str qui contient la représentation textuelle du montage par rapport à la racine actuelle (c'est-à-dire si vous êtes dans un chroot). C'est une chaîne terminée par un caractère nul.

VALEUR RENVOYÉE

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EPERM
La permission d'accéder à ce montage est refusée.
EFAULT
req ou smbuf pointe vers un emplacement en dehors de l'espace d'adressage accessible du processus.
EINVAL
Un drapeau invalide est spécifié dans flags.
EINVAL
req est de taille insuffisante pour être utilisé.

ERREURS

E2BIG
req est trop grand.
EOVERFLOW
La taille de smbuf est trop petite pour contenir soit smbuf.fs_type, smbuf.mnt_root, soit smbuf.mnt_point. Allouez un tampon plus grand et réessayez l'appel.
ENOENT
Le req.mnt_id spécifié n'existe pas.
ENOMEM
Pas assez de mémoire (c'est-à-dire mémoire noyau).

NORMES

Linux.

VOIR AUSSI
