stat(2) Manuel des appels système stat(2)

NOM

stat, fstat, lstat, fstatat - obtenir le statut d'un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

lstat() :

    /* Depuis glibc 2.20 */ _DEFAULT_SOURCE
        || _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.10 : */ _POSIX_C_SOURCE >= 200112L
        || /* glibc 2.19 et versions antérieures */ _BSD_SOURCE

fstatat() :

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _ATFILE_SOURCE

DESCRIPTION

Ces fonctions renvoient des informations sur un fichier, dans le tampon pointé par statbuf. Aucune autorisation n'est requise sur le fichier lui-même, mais - dans le cas de stat(), fstatat() et lstat() - une autorisation d'exécution (recherche) est requise sur tous les répertoires de path qui mènent au fichier.

stat() et fstatat() récupèrent des informations sur le fichier pointé par path ; les différences pour fstatat() sont décrites ci-dessous.

lstat() est identique à stat(), sauf que si path est un lien symbolique, il renvoie des informations sur le lien lui-même, et non sur le fichier auquel le lien fait référence.

fstat() est identique à stat(), sauf que le fichier sur lequel les informations doivent être récupérées est spécifié par le descripteur de fichier fd.

La structure stat

Tous ces appels système renvoient une structure stat (voir stat(3type)).

Note : pour des raisons de performance et de simplicité, différents champs de la structure stat peuvent contenir des informations d'état provenant de différents moments pendant l'exécution de l'appel système. Par exemple, si st_mode ou st_uid est modifié par un autre processus en appelant chmod(2) ou chown(2), stat() pourrait renvoyer l'ancien st_mode avec le nouveau st_uid, ou le nouveau st_uid avec l'ancien st_mode.

fstatat()

L'appel système fstatat() est une interface plus générale pour accéder aux informations de fichier qui peut toujours fournir exactement le comportement de chacun de stat(), lstat() et fstat().

Si path est relatif, il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme le fait stat() et lstat() pour un nom de chemin relatif).

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel du processus appelant (comme stat() et lstat()).

Si path est absolu, alors dirfd est ignoré.

flags peut être 0, ou inclure un ou plusieurs des indicateurs suivants ORés :

AT_EMPTY_PATH (depuis Linux 2.6.39)
Si path est une chaîne vide (ou NULL, depuis Linux 6.11), agir sur le fichier référencé par dirfd (qui peut avoir été obtenu en utilisant l'indicateur open(2) O_PATH). Dans ce cas, dirfd peut faire référence à n'importe quel type de fichier, pas seulement à un répertoire, et le comportement de fstatat() est similaire à celui de fstat(). Si dirfd est AT_FDCWD, l'appel agit sur le répertoire de travail actuel. Cet indicateur est spécifique à Linux ; définissez _GNU_SOURCE pour obtenir sa définition.
AT_NO_AUTOMOUNT (depuis Linux 2.6.38)
Ne pas automonter le composant terminal ("basename") de path. Depuis Linux 3.1, cet indicateur est ignoré. Depuis Linux 4.11, cet indicateur est implicite.
AT_SYMLINK_NOFOLLOW
Si path est un lien symbolique, ne pas le déréférencer : renvoyer à la place des informations sur le lien lui-même, comme lstat(). (Par défaut, fstatat() déréférence les liens symboliques, comme stat().)

Voir openat(2) pour une explication de la nécessité de fstatat().

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
L'autorisation de recherche est refusée pour l'un des répertoires du préfixe de chemin de path. (Voir aussi path_resolution(7).)
EBADF
fd n'est pas un descripteur de fichier ouvert valide.
EBADF
(fstatat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
Mauvaise adresse.
EINVAL
(fstatat()) Indicateur invalide spécifié dans flags.
ELOOP
Trop de liens symboliques rencontrés lors de la traversée du chemin.
ENAMETOOLONG
path est trop long.
ENOENT
Un composant de path n'existe pas ou est un lien symbolique dangling.
ENOENT
path est une chaîne vide et AT_EMPTY_PATH n'a pas été spécifié dans flags.
ENOMEM
Plus de mémoire (c'est-à-dire mémoire noyau).
ENOTDIR
Un composant du préfixe de chemin de path n'est pas un répertoire.
ENOTDIR
(fstatat()) path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.
EOVERFLOW
path ou fd fait référence à un fichier dont la taille, le numéro d'inode ou le nombre de blocs ne peuvent pas être représentés dans, respectivement, les types off_t, ino_t ou blkcnt_t. Cette erreur peut survenir lorsque, par exemple, une application compilée sur une plateforme 32 bits sans -D_FILE_OFFSET_BITS=64 appelle stat() sur un fichier dont la taille dépasse (1<<31)-1 octets.

NORMES

POSIX.1-2024.

HISTORIQUE

fstat()
lstat()
SVr4, 4.3BSD, POSIX.1-2001.

NAME

stat, fstat, lstat, fstatat - get file status

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <unistd.h>
int stat(const char *pathname, struct stat *statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *pathname, struct stat *statbuf);
#define _ATFILE_SOURCE
#include <fcntl.h> /* For O_SYMLINK */
int fstatat(int dirfd, const char *pathname, struct stat *statbuf, int flags);

DESCRIPTION

These system calls (and the library functions that wrap them) retrieve information about a file and store it in the buffer pointed to by statbuf. The operations performed by stat(), lstat(), and fstatat() are similar to fstat(), except for how they identify the file to be examined.

stat()
Dereferences any symbolic links in pathname; the status returned is that of the file referenced by the final component of the path. (If pathname is a symbolic link, then stat() returns information about the file the link points to.)
fstat()
Examines the file descriptor fd, which must be an open file descriptor. The status returned is that of the open file to which fd refers. Dereferencing of symbolic links is not applicable.
lstat()
Is a related function. It is like stat(), but if pathname is a symbolic link, then lstat() returns information about the link itself rather than the file the link points to.
fstatat()
Is equivalent to calling stat() or lstat() but respectively or not respectively, depending on the value of the flags argument. The pathname argument specifies a path relative to the directory referred to by the file descriptor dirfd. If pathname is relative, then it is interpreted relative to the directory specified by dirfd. If pathname is absolute, then dirfd is ignored. If dirfd is the special value AT_FDCWD then pathname is interpreted relative to the current working directory. If flags contains the AT_SYMLINK_NOFOLLOW bit, then fstatat() does not follow the symbolic link, so if pathname refers to a symbolic link, then the status of the link itself is returned.

The stat structure (defined in <sys/stat.h>) contains at least the following fields:

   struct stat {
       dev_t     st_dev;     // ID of the device containing the file
       ino_t     st_ino;     // inode number of the file
       mode_t    st_mode;    // protection flags and file type
       nlink_t   st_nlink;   // number of hard links to the file
       uid_t     st_uid;     // user ID of the owner
       gid_t     st_gid;     // group ID of the owner
       dev_t     st_rdev;    // device ID (if special file)
       off_t     st_size;    // total size, in bytes
       blksize_t st_blksize; // blocksize for filesystem I/O
       blkcnt_t  st_blocks;  // number of 512B blocks allocated
       // for st_atime, st_mtime and st_ctime:
       timespec_t st_atim;   // time of last access
       timespec_t st_mtim;   // time of last modification
       timespec_t st_ctim;   // time of last status change
   };

The exact types (like dev_t, ino_t, mode_t, etc.) are implementation-dependent. (See stat(3type) for details.)

st_atim, st_mtim, and st_ctim are structure members added in Linux 2.6.39. For compatibility, the older st_atime, st_mtime, and st_ctime members (type time_t) are also available. On Linux, the timespec_t structure contains two members, tv_sec (seconds) and tv_nsec (nanoseconds).

The st_mode field contains information about the file type and protection bits. The file type bits are among the following constants: S_IFMT, S_IFREG, S_IFDIR, S_IFCHR, S_IFBLK, S_IFIFO, S_IFLNK, S_IFSOCK.

The protection bits are the lower 9 bits of st_mode. They are interpreted as follows:

S_IRUSR (0400)
Read permission for owner.
S_IWUSR (0200)
Write permission for owner.
S_IXUSR (0100)
Execute permission for owner.
S_IRGRP (0040)
Read permission for group.
S_IWGRP (0020)
Write permission for group.
S_IXGRP (0010)
Execute permission for group.
S_IROTH (0004)
Read permission for others.
S_IWOTH (0002)
Write permission for others.
S_IXOTH (0001)
Execute permission for others.

Also available are symbolic constants combining these bits:

S_IRWXU (0700)
Read, write, and execute by owner.
S_IRWXG (0070)
Read, write, and execute by group.
S_IRWXO (0007)
Read, write, and execute by others.

The st_blocks field indicates the number of disk blocks allocated for the file. The size of these blocks is determined by st_blksize. The value in st_blocks is the count of st_blksize-byte blocks, but the actual block size may vary. st_blocks is not the disk usage, but rather the count of allocated blocks, possibly including unused blocks in the file.

The fields st_atime, st_mtime, and st_ctime are time stamps. st_atime is the time of the last access; st_mtime is the time of the last modification of the contents of the file; and st_ctime is the time of the last modification of the file's status information (metadata).

The st_dev field describes the device on which this file resides. The st_ino field is the inode number of this file. The st_nlink field is the number of hard links to the file. The st_uid and st_gid fields contain the numeric user ID and group ID of the owner of the file, respectively.

The st_rdev field is the device ID if the file is a special file (character or block special file). Otherwise, this field is undefined.

RETURN VALUE

On success, zero is returned. On failure, -1 is returned, and errno is set to indicate the error.

ERRORS

EACCES
Search permission denied for any component of the required path prefix. Or, pathname was a symbolic link and read or search permission denied on the file specified by pathname. Or, pathname is a directory and write or search permission denied.
EBADF
fd is not a valid file descriptor for fstat() or fstatat().
EFAULT
statbuf points outside the process's accessible address space.
EINTR
A signal was caught during the system call.
EINVAL
The value of flags is not valid for fstatat().
EIO
An I/O error occurred.
ELOOP
Too many symbolic links were encountered while resolving pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
A component of pathname does not exist or is a dangling symbolic link (and the flags do not specify AT_SYMLINK_NOFOLLOW).
ENOMEM
Out of memory.
ENOTDIR
A component of pathname is not a directory. Or, dirfd was not AT_FDCWD and not a valid file descriptor referring to a directory.
ENXIO
A block special or character special file has the specified pathname, but no corresponding device exists. Or, pathname refers to a FIFO or regular file, and is associated with a device that does not exist.
EOVERFLOW
The file contains a value too large to be represented in this object type. This can happen for files with large sizes or sparse files on 32-bit systems.
EROFS
A file system is read-only and the operation would modify its contents. (This error is not normally expected for these system calls.)
ETXTBSY
A file is a regular file that is being executed and the request is for write access to the file or for metadata changes that would require writing to the file. (This error is not normally expected for these system calls.)

In addition, fstatat() may fail if:

EACCES
The directory specified by dirfd is not searchable.
EINVAL
Invalid value for flags.
ENOTDIR
dirfd is not a valid file descriptor referring to a directory.
ELOOP
Too many levels of symbolic links in pathname.
ENOMEM
Insufficient kernel memory was available.
EOVERFLOW
A value is too large to be represented in the stat structure.
ETXTBSY
A file is being executed and the operation would require writing to the file.

STANDARDS

According to POSIX.1-2001, lstat() on a symbolic link need return valid information only in the st_size field and the file type of the st_mode field of the stat structure. POSIX.1-2008 tightens the specification, requiring lstat() to return valid information in all fields except the mode bits in st_mode.

Use of the st_blocks and st_blksize fields may be less portable. (They were introduced in BSD. The interpretation differs between systems, and possibly on a single system when NFS mounts are involved.)

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
