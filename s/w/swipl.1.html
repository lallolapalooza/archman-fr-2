swipl(1) Manuel des commandes générales swipl(1)

NOM

swipl - SWI-Prolog 10.0.0

SYNTAXE

swipl [--help|--version|--arch|--dump-runtime-variables]
swipl [options] fichier-prolog ... [--] [arg ...]
swipl [options] [-o sortie] -c fichier ...
swipl [options] [-o sortie] -b fichier-initialisation ...

La première version fournit des informations sur le système et se termine immédiatement. La deuxième version est la manière principale d'appeler Prolog sur un ou plusieurs fichiers source Prolog et de fournir des arguments à l'application qui peuvent être demandés à l'aide de current_prolog_flag(argv, Argv). La troisième version est utilisée pour créer un état sauvegardé tandis que la dernière version est utilisée pour la compilation de démarrage des parties Prolog du système.

DESCRIPTION

SWI-Prolog est une implémentation complète et stable du langage Prolog avec un large ensemble de bibliothèques. Parmi ses caractéristiques distinctives figurent un support mature pour le multi-threading, une bibliothèque mature de serveur web embarqué, des outils de développement graphiques (débogueur, profileur, outil de référencement croisé, éditeur), un magasin RDF efficace embarqué, le support XML/SGML/HTML et Unicode. Parmi les fonctionnalités les plus supportées, on trouve le support de la programmation par contraintes, du garbage collector d'atomes, des interfaces vers les bases de données (ODBC), C, C++ et Java (JPL).

SWI-Prolog implémente la norme ISO core. Beaucoup de ses extensions sont largement compatibles avec YAP et SICStus Prolog.

Cette page de manuel ne liste que les options de la ligne de commande. La documentation complète est disponible en ligne ainsi qu'en format HTML et PDF sur la page d'accueil du WWW à l'adresse http://www.swi-prolog.org

OPTIONS

--help
Donne un résumé des options les plus importantes.
--version
Affiche les informations sur la version et l'architecture.
--abi-version
Affiche la clé de version ABI. Cette clé indique la compatibilité binaire des diverses interfaces.
--arch
Affiche l'identifiant de l'architecture.
--dump-runtime-variables[=format]
Affiche les informations généralement utiles pour les scripts d'installation sous la forme définie par format. Les formats définis sont sh (par défaut, shell bourne) et cmd (CMD Windows). Cette option est utilisée par swipl-ld(1) pour récupérer les informations nécessaires sur Prolog. Elle est normalement invoquée comme eval `swipl --dump-runtime-variables`, ce qui assigne les variables shell suivantes :
CC
Le compilateur C utilisé pour compiler SWI-Prolog.
PLBASE
Le répertoire d'accueil de SWI-Prolog. C'est la même valeur que celle renvoyée par current_prolog_flag home.
PLARCH
L'identifiant de l'architecture utilisé. Combiné avec PLBASE, il définit l'emplacement des divers composants. Par exemple, la bibliothèque pour l'intégration se trouve dans $PLBASE/lib/$PLARCH/libswipl.a
PLBITS
Bits d'adresse pour la VM. Soit 32, soit 64.
PLLIB
Identifiant CC pour lier à SWI-Prolog. Typiquement -lswipl
PLLIBSWIPL
Nom de chemin complet vers l'objet partagé (DLL) qui fournit le cœur de Prolog.
PLLIBS
Bibliothèques supplémentaires nécessaires pour lier PLLIB
PLCFLAGS
Options à passer au compilateur C pour générer du code compatible.
PLLDFLAGS
Options à passer à l'éditeur de liens C pour lier les exécutables embarqués.
PLSOEXT
Extension utilisée par le système d'exploitation hôte pour les objets partagés. Sur la plupart des systèmes Unix, c'est "so" ; sur MS-Windows, c'est "dll". AIX utilise "o", HPUX "sl".
PLSOPATH
Variable d'environnement utilisée par le système d'exploitation hôte pour étendre le chemin de recherche des objets partagés. Par exemple, sur les systèmes ELF, c'est "LD_LIBRARY_PATH" et sur MS-Windows, c'est "PATH".
PLVERSION
Représentation numérique de la version de SWI-Prolog.
PLVERSIONTAG
S'il est présent, une étiquette de version telle que "rc1".
PLSHARED
A la valeur yes si Prolog supporte le lien de bibliothèques partagées en utilisant load_foreign_library/[1,2] et no sinon.
PLTHREADS
A la valeur yes si Prolog a été compilé pour le multi-threading et no sinon.
--home=DIR
Utilise DIR comme répertoire d'accueil.
--stack-limit=taille[bkmg]
Définit la limite combinée de la pile à taille octets. Le suffixe ne distingue pas les majuscules des minuscules et définit l'unité comme b (octets), k (Koctets), m (Mokets) ou g (Gokets).
--table-space=taille[bkmg]
Définit la limite d'espace de table pour la résolution SLG (tabling) à taille octets. Les suffixes sont les mêmes que pour l'option --stack-limit.
--shared-table-space=taille[bkmg]
Définit la limite d'espace de table pour le tabling partagé à taille octets. Les suffixes sont les mêmes que pour l'option --stack-limit.
-O
Compilation optimisée. Voir set_prolog_flag/2 dans le Manuel de Référence SWI-Prolog.
-b fichier-initialisation ... -c fichier ...
Compilation de démarrage. fichier-initialisation ... sont compilés par le compilateur de démarrage écrit en C, fichier ... par le compilateur Prolog normal dans un fichier intermédiaire. Cette option est réservée à la maintenance du système et est donnée à titre indicatif uniquement.
-c fichier ...
Compile fichier ... en un fichier intermédiaire.
-d niveau
Définit le niveau de débogage à niveau. Cette option est réservée à la maintenance du système et est donnée à titre indicatif uniquement.
--packs[=bool]
Désactive l'attachement des paquets d'extension (modules complémentaires).
--pce[=bool]
Désactive le sous-système GUI XPCE.
--pldoc[=port]
Démarre le système de documentation PlDoc sur un port réseau libre et lance le navigateur de l'utilisateur sur http://localhost:port. Si port est spécifié, le serveur est démarré sur le port donné mais le navigateur n'est pas lancé.
-f fichier
Utilise fichier comme fichier d'initialisation au lieu de `init.pl'. `-f none' arrête SWI-Prolog de chercher un fichier d'initialisation.
-F fichier
Sélectionne un script de démarrage dans le répertoire d'accueil de SWI-Prolog. fichier Spécifie le nom de base du script. L'extension est .rc. Le script par défaut est déduit du nom de base de l'exécutable, en prenant tous les caractères alphanumériques (lettres, chiffres et underscore) au début du nom du programme. Ainsi, si le programme est nommé swi-2.0, il essaiera de charger le fichier swi.rc depuis le répertoire d'accueil de SWI-Prolog. Si le fichier n'existe pas, ou si l'utilisateur n'a pas les droits de lecture dessus, le script n'est pas chargé silencieusement.
-s fichier
Charge fichier
as a script. This option peut être utilisé depuis le shell pour faire charger Prolog un fichier avant d'entrer dans le toplevel. Obsolète car les noms de fichiers avec une extension Prolog (.pl ou .qlf) sont utilisés pour charger le programme.
-l fichier
Charge fichier comme un script. Ceci est un synonyme pour -s qui est compatible avec plusieurs autres implémentations Prolog. Si plusieurs arguments -s ou -l sont fournis, tous les fichiers spécifiés sont chargés dans l'ordre dans lequel ils apparaissent sur la liste d'arguments.
--quiet[=bool] -q
Fonctionne silencieusement. Cette option supprime tous les messages d'information.
--debug[=bool]
Désactive la génération de code qui peut être débogué à l'aide de trace/0, spy/1, etc.
--debug-on-interrupt[=bool]
Commence immédiatement le traitement de SIGINT (Control-C) pour démarrer le débogueur. Par défaut, cela est activé lorsque le toplevel interactif est entré.
--on-error=style
Comment gérer un message d'erreur (imprimé). La valeur par défaut est print, qui provoque l'impression des erreurs pendant que l'exécution continue. L'utilisation de status permet à l'exécution de continuer comme avec print, mais halt/0 provoque la sortie du processus avec le statut 1 et halt provoque la sortie du processus avec le statut 1 à la première erreur.
--on-warning=style
Similaire à --on-error, mais pour les messages d'avertissement.
-g but
But est exécuté juste avant d'entrer dans le top level. Cette option peut apparaître plusieurs fois. Les buts sont exécutés dans l'ordre d'apparition. Les points de choix possibles sont élagués. Si un but échoue, une erreur est imprimée (selon le drapeau -q) et le processus s'arrête avec le code de sortie 1. Si un but lève une exception, l'erreur est imprimée et le processus s'arrête avec le code de sortie 2. S'il n'y a pas de but, version/0 est appelée pour écrire le message de bienvenue. Le message de bienvenue peut donc être supprimé en donnant -g true. but peut être un terme complexe. Dans ce cas, des guillemets sont normalement nécessaires pour le protéger d'être étendu par le shell Unix.
-o sortie
Utilisé en combinaison avec -b ou -c pour déterminer le fichier de sortie pour la compilation.
-p alias=listederuess
Définit un alias de chemin pour file_search_path/2. listederuess est une liste séparée par des ":" de valeurs pour l'alias. Voir file_search_path/2 dans le Manuel de Référence SWI-Prolog.
-t but
Utilise but comme un top level interactif à la place du but par défaut prolog/0. but peut être un terme complexe. Si le but du top level réussit, SWI-Prolog se termine avec le statut 0. S'il échoue, le statut de sortie est 1. Ce drapeau détermine également le but démarré par break/0 et abort/0. Si vous voulez empêcher l'utilisateur d'entrer en mode interactif, démarrez l'application avec `-g but' et donnez `halt' comme top level.
-x fichierdemarrage
Démarrer à partir d'un fichier de code intermédiaire résultant d'une compilation Prolog utilisant l'option -b ou -c, ou créé à l'aide de qsave_program/[1,2].
--tty[=bool]
Active/désactive le contrôle du tty (utilisant ioctl(2)). Normalement, le contrôle du tty est activé. Ce comportement par défaut dépend de l'installation. Vous pourriez souhaiter désactiver le contrôle du tty si SWI-Prolog est utilisé depuis un éditeur tel que GNU Emacs. S'il est désactivé, get_single_char/1 et le traceur attendront une retour chariot.
--win-app
Cette option n'est disponible que dans swipl-win.exe. Le raccourci du menu Démarrer utilise cette option pour changer le répertoire de travail vers ...\Documents\Prolog. Le sous-répertoire Prolog sera créé s'il n'existe pas.
--signals[=bool]
Désactive le traitement des signaux. Souvent utilisé si SWI-Prolog est intégré dans une autre application sur les systèmes Unix.
--sigalert=NUM
Utilise NUM pour débloquer les appels système. La valeur par défaut est SIGUSR2. Utiliser 0 désactive l'installation d'un gestionnaire de signaux, retardant la livraison des signaux de thread jusqu'à ce que l'appel système bloquant se termine.
--threads[=bool]
Désactive la création de threads dans la version multi-thread. Cela empêche notamment l'exécution de la collecte globale des déchets sur un thread séparé et peut être utilisé dans des situations où plusieurs threads ne sont pas souhaitables.
--traditional
Désactive les extensions SWI-Prolog version 7 qui sont incompatibles avec les versions antérieures.
--
Arrête l'analyse des arguments supplémentaires.

VARIABLES D'ENVIRONNEMENT

SWI_HOME_DIR
Emplacement pour trouver le fichier de démarrage et les bibliothèques. Normalement découvert à partir de l'exécutable ou d'un emplacement par défaut configuré. La fourniture de la valeur via l'environnement peut être nécessaire si SWI-Prolog est intégré dans un autre exécutable.

AIDE EN LIGNE

SWI-Prolog dispose d'une aide en ligne. Celle-ci fournit une installation rapide et une fonction de navigation vers le manuel de référence de SWI-Prolog. Le manuel en ligne peut afficher les définitions de prédicats ainsi que des sections entières du manuel.

help
Équivalent à help(help/1).
help(+Quoi)
Affiche une partie spécifiée du manuel. Quoi est l'un des éléments suivants :
Nom/Arite
fournit de l'aide sur le prédicat spécifié
Nom
fournit de l'aide sur le prédicat nommé avec n'importe quelle arité ou une fonction d'interface C avec ce nom.
Section
affiche la section spécifiée du Manuel de Référence SWI-Prolog. Les numéros de section sont séparés par des tirets : par exemple, 2-3 fait référence à la section 2.3 du manuel.

Si Prolog est utilisé conjointement avec l'outil GUI XPCE, ces prédicats lancent une interface graphique, fournissant une interface cohérente à help/1, apropos/1 et explain/1.

FICHIERS

Cette installation de SWI-Prolog a été configurée à l'aide de l'option de configuration --prefix=/usr. Si les fichiers listés ci-dessous ne se trouvent pas à l'emplacement indiqué, l'installation a probablement été déplacée. Utilisez

?- current_prolog_flag(home, Home).

pour trouver le répertoire d'installation local de SWI-Prolog.

~/.config/swi-prolog/init.pl
Fichiers d'initialisation personnels consultés par SWI-Prolog au démarrage. L'emplacement exact dépend du système d'exploitation.
/usr/lib/swipl-10.0.0/bin//
Emplacement des exécutables.
/usr/lib/swipl-10.0.0/include/
Emplacement des fichiers d'inclusion. S'il est accessible en écriture, SWI-Prolog.h est également copié dans /usr/include/SWI-Prolog.h.
/usr/lib/swipl-10.0.0/library/
Bibliothèques utilisateur de SWI-Prolog.
/usr/lib/swipl-10.0.0/boot/
Composants du noyau de SWI-Prolog écrits en Prolog. Le fichier de démarrage /usr/lib/swipl-10.0.0/ peut être recréé en utilisant la commande du répertoire /usr/lib/swipl-10.0.0 :
bin//swipl -O -o -b boot/init.pl
/usr/lib/swipl-10.0.0/doc/packages
Documentation HTML et/ou PDF sur les modules complémentaires installés.
/usr/lib/swipl-10.0.0/
Fichier de démarrage par défaut. Il s'agit d'un fichier de 'code intermédiaire' contenant du code précompilé du répertoire boot. L'option -xfichierdemarrage peut être utilisée pour sélectionner un fichier différent.
/usr/lib/swipl-10.0.0/runtime//libpl.a
Bibliothèque SWI-Prolog pour l'intégration. Voir aussi plld(1).
