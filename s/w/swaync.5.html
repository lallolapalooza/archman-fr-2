swaync(5) Formats de Fichier swaync(5)

NOM

swaync - Fichier de configuration

CONFIGURATION

Il est recommandé d'utiliser un éditeur de texte avec un serveur de langage JSON pour modifier le fichier de configuration afin de pouvoir détecter les erreurs de configuration.

ignore-gtk-theme
type: bool
défaut: true
description: Annule la variable d'environnement GTK_THEME, résolvant ainsi de nombreux problèmes où les thèmes GTK corrompent les thèmes CSS personnalisés de l'utilisateur.

positionX
type: string
défaut: right
valeurs: left, right, center
description: Position horizontale du centre de contrôle et de la fenêtre de notification.

positionY
type: string
défaut: top
valeurs: top, center, bottom
description: Position verticale du centre de contrôle et de la fenêtre de notification.

layer
type: string
défaut: overlay
valeurs: background, bottom, top, overlay
description: Couche de la fenêtre de notification par rapport aux fenêtres normales.
background est sous toutes les fenêtres, overlay est au-dessus de toutes les fenêtres.

layer-shell
type: bool
défaut: true
description: Indique si les fenêtres doivent être ouvertes en tant que surfaces layer-shell.
Note : Nécessite un redémarrage de swaync pour appliquer.

cssPriority
type: string
défaut: application
valeurs: application, user
description: Quelle priorité GTK utiliser lors du chargement des fichiers CSS par défaut et utilisateur.
Choisissez "user" pour remplacer XDG_CONFIG_HOME/gtk-3.0/gtk.css

Remplace positionX si non défini à `none`.

control-center-positionY

Remplace positionY si non défini à `none`.

background est sous toutes les fenêtres, overlay est au-dessus de toutes les fenêtres.

zones exclusives du compositeur. Par exemple, le définir à

notification-window-preferred-output

défaut: ""
description: La sortie préférée pour ouvrir la fenêtre de notification

relative-timestamps
type: bool

description: Affiche les horodatages des notifications par rapport à maintenant, par exemple "il y a 26 minutes".

notification-action-filter
type: object
propriétés de l'objet visibility:
use-regex
type: bool
optionnel: true
défaut: false

type: string
optionnel: true
description: Le nom de l'application.

type: string
optionnel: true
description: L'entrée de bureau.

type: string
optionnel: true (au moins un matcher requis)
description: Correspond à l'identifiant des actions. Peut être trouvé en

text-matcher
type: string
optionnel: true (au moins un matcher requis)
description: Correspond au texte des actions visible dans la notification.
description: Masque les actions correspondantes des notifications correspondantes.
Si la notification n'inclut pas l'une des propriétés, cette
propriété sera ignorée. Si toutes les propriétés correspondent à la notification donnée,
les actions correspondantes seront masquées.
exemple:

{
    "notification-action-filter": {
        "app-name": "Test",
        "id-matcher": "1234"
    }
}

Ce qui masquera l'action avec l'identifiant "1234" de la notification "Test".

notification-visibility
type: objet
propriétés de l'objet visibility:
state
type: chaîne
facultatif: false
défaut: activé
valeurs: ignoré, muet, transitoire, activé
description: L'état de visibilité de la notification.
override-urgency
type: chaîne
facultatif: true
défaut: non défini
valeurs: non défini, bas, normal, critique
description: La nouvelle urgence pour la notification si définie.
app-name
type: chaîne
facultatif: true
description: Le nom de l'application. Utilise les expressions régulières.
desktop-entry
type: chaîne
facultatif: true
description: L'entrée de bureau. Utilise les expressions régulières.
summary
type: chaîne
facultatif: true
description: Le résumé de la notification. Utilise les expressions régulières.
body
type: chaîne
facultatif: true
description: Le corps de la notification. Utilise les expressions régulières.
urgency
type: chaîne
facultatif: true
défaut: Normal
valeurs: Bas, Normal, Critique
description: L'urgence de la notification.
category
type: chaîne
facultatif: true
description: À quelle catégorie appartient la notification. Utilise les expressions régulières.
description: Définit la visibilité ou surcharge l'urgence de chaque notification entrante.
Si la notification n'inclut pas l'une des propriétés, cette
propriété sera ignorée. Toutes les propriétés (sauf state) utilisent
les expressions régulières. Si toutes les propriétés correspondent à la notification donnée, la
notification suivra l'état fourni.
Seul le premier objet correspondant sera utilisé.
exemple:

{
	"notification-visibility": {
		"example-name": {
			"state": "L'état de la notification",
			"app-name": "Regex du nom de l'application de la notification",
			"summary": "Regex du résumé de la notification",
			"body": "Regex du corps de la notification",
			"urgency": "Bas ou Normal ou Critique",
			"category": "Regex de la catégorie de la notification"
		}
	}
}

swaync.5.en
NAME

swaync - Configuration de SwayNotificationCenter

DESCRIPTION

SwayNotificationCenter est un centre de notifications pour Wayland, inspiré par le centre de notifications de macOS.

Il est configuré via un fichier JSON. Ce fichier peut être spécifié par la variable d'environnement SWAYNC_CONFIG_DIR, qui pointe vers le répertoire contenant le fichier de configuration (qui se nomme config par défaut). Si la variable d'environnement n'est pas définie, SwayNotificationCenter recherchera le fichier dans ~/.config/swaync/config.

Si aucun fichier de configuration n'est trouvé, un fichier de configuration par défaut sera utilisé.

Configuration file format

Le fichier de configuration est au format JSON.

Global options

Ces options s'appliquent à l'ensemble du centre de notifications.

all-outputs

Type : booléen

Défaut : false

Description : Si défini sur true, les notifications seront affichées sur tous les écrans, même si le moniteur sur lequel la notification est censée apparaître n'est pas celui où le curseur de la souris se trouve.

Scripts

Cette section permet de définir des scripts qui seront exécutés en fonction des propriétés des notifications.

Le செய्ये est le nom de votre script. Il doit être unique. Le script sera exécuté si toutes les propriétés spécifiées pour ce script correspondent à la notification.

Toutes les propriétés (sauf exec) utilisent des expressions régulières (regex).

Seul le premier script correspondant sera exécuté.

exec

Type : chaîne de caractères

Obligatoire : oui

Description : La commande shell ou le chemin d'accès au script à exécuter.

app-name

Type : chaîne de caractères

Optionnel : oui

Description : Expression régulière pour faire correspondre le nom de l'application qui a envoyé la notification.

summary

Type : chaîne de caractères

Optionnel : oui

Description : Expression régulière pour faire correspondre le titre de la notification.

body

Type : chaîne de caractères

Optionnel : oui

Description : Expression régulière pour faire correspondre le corps de la notification.

urgency

Type : chaîne de caractères

Optionnel : oui

Valeurs : Low, Normal, Critical

Description : La priorité de la notification. Peut être une valeur fixe ou une expression régulière.

category

Type : chaîne de caractères

Optionnel : oui

Description : Expression régulière pour faire correspondre la catégorie de la notification.

செய्ये

Type : chaîne de caractères

Optionnel : oui

Valeurs : action, receive

Défaut : receive

Description : Indique si ce script doit être exécuté lorsque la notification est reçue, ou lorsqu'une action est effectuée sur celle-ci.

description : Quel nom de son la notification a demandé. Utilise des expressions régulières.


run-on

type: chaîne de caractères

optional: true

values: action, receive

default: receive

description: Indique si ce script doit être exécuté lorsque la notification est reçue, ou lorsqu'une action est effectuée sur celle-ci.

description : Quels scripts vérifier et potentiellement exécuter pour chaque notification. Si la notification n'inclut pas l'une des propriétés, cette propriété sera ignorée. Toutes les propriétés (sauf exec) utilisent des regex. Si toutes les propriétés correspondent à la notification donnée, le script sera exécuté. Seul le premier script correspondant sera exécuté.

example:

{
	"scripts": {
		"exemple-script": {
			"exec": "Votre commande shell ou script ici...",
			"app-name": "Regex du nom d'application de la notification",
			"summary": "Regex du résumé de la notification",
			"body": "Regex du corps de la notification",
			"urgency": "Low or Normal or Critical",
			"category": "Regex de la catégorie de notification"
		}
	}
}
