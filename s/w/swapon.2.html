swapon(2) Manuel des appels système swapon(2)

NOM

swapon, swapoff - démarrer/arrêter le swapping vers un fichier/périphérique

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/swap.h>
int swapon(const char *path, int swapflags);
int swapoff(const char *path);

DESCRIPTION

swapon() configure la zone de swap vers le fichier ou le périphérique bloc spécifié par path. swapoff() arrête le swapping vers le fichier ou le périphérique bloc spécifié par path.

Si le drapeau SWAP_FLAG_PREFER est spécifié dans l'argument swapflags de swapon(), la nouvelle zone de swap aura une priorité plus élevée que la normale. La priorité est encodée dans swapflags comme suit :


(prio << SWAP_FLAG_PRIO_SHIFT) & SWAP_FLAG_PRIO_MASK

Si le drapeau SWAP_FLAG_DISCARD est spécifié dans l'argument swapflags de swapon(), les pages de swap libérées seront ignorées avant d'être réutilisées, si le périphérique de swap prend en charge l'opération de discard ou trim. (Cela peut améliorer les performances sur certains périphériques à état solide, mais souvent ce n'est pas le cas.) Voir également la section NOTES.

Ces fonctions ne peuvent être utilisées que par un processus privilégié (celui ayant la capacité CAP_SYS_ADMIN).

Priorité

Chaque zone de swap a une priorité, soit haute, soit basse. La priorité par défaut est basse. Au sein des zones de basse priorité, les zones les plus récentes ont une priorité encore plus basse que les zones plus anciennes.

Toutes les priorités définies avec swapflags sont de haute priorité, plus élevée que la normale. Elles peuvent avoir toute valeur non négative choisie par l'appelant. Des nombres plus élevés signifient une priorité plus élevée.

Les pages de swap sont allouées à partir des zones dans l'ordre de priorité, la priorité la plus haute en premier. Pour les zones ayant des priorités différentes, une zone de priorité plus élevée est épuisée avant d'utiliser une zone de priorité plus basse. Si deux ou plusieurs zones ont la même priorité, et que c'est la priorité la plus élevée disponible, les pages sont allouées en mode round-robin entre elles.

Depuis Linux 1.3.6, le noyau suit généralement ces règles, mais il existe des exceptions.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EBUSY
(pour swapon()) Le path spécifié est déjà utilisé comme zone de swap.
EINVAL
Le fichier path existe, mais ne fait référence ni à un fichier régulier, ni à un périphérique bloc ;
EINVAL
(swapon()) Le chemin indiqué ne contient pas une signature de swap valide ou réside sur un système de fichiers en mémoire tel que tmpfs(5).
EINVAL (depuis Linux 3.4)
(swapon()) Une valeur de drapeau invalide a été spécifiée dans swapflags.
EINVAL
(swapoff()) path n'est pas actuellement une zone de swap.
ENFILE
La limite système du nombre total de fichiers ouverts a été atteinte.
ENOENT
Le fichier path n'existe pas.
ENOMEM
Le système manque de mémoire pour démarrer le swapping.
EPERM
L'appelant ne possède pas la capacité CAP_SYS_ADMIN. Alternativement, le nombre maximal de fichiers de swap est déjà utilisé ; voir NOTES ci-dessous.

NORMES

Linux.

HISTORIQUE

L'argument swapflags a été introduit dans Linux 1.3.2.

NOTES

La partition ou le chemin doit être préparé avec mkswap(8).

Il existe une limite supérieure au nombre de fichiers de swap qui peuvent être utilisés, définie par la constante du noyau MAX_SWAPFILES. Avant Linux 2.4.10, MAX_SWAPFILES a la valeur 8 ; depuis Linux 2.4.10, elle a la valeur 32. Depuis Linux 2.6.18, la limite est diminuée de 2 (donc 30), depuis Linux 5.19, la limite est diminuée de 3 (donc : 29) si le noyau est compilé avec l'option CONFIG_MIGRATION (qui réserve deux entrées de table de swap pour les fonctionnalités de migration de page de mbind(2) et migrate_pages(2)). Depuis Linux 2.6.32, la limite est encore diminuée de 1 si le noyau est compilé avec l'option CONFIG_MEMORY_FAILURE. Depuis Linux 5.14, la limite est encore diminuée de 4 si le noyau est compilé avec l'option CONFIG_DEVICE_PRIVATE. Depuis Linux 5.19, la limite est encore diminuée de 1 si le noyau est compilé avec l'option CONFIG_PTE_MARKER.

Le discard des pages de swap a été introduit dans Linux 2.6.29, puis rendu conditionnel au drapeau SWAP_FLAG_DISCARD dans Linux 2.6.36, qui ignore toujours la zone de swap entière lorsque swapon() est appelé, même si ce bit de drapeau n'est pas défini.

VOIR AUSSI

mkswap(8), swapoff(8), swapon(8)
