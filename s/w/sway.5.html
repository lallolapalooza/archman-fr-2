sway(5) Manuel des formats de fichiers sway(5)

NOM

sway - fichier de configuration et commandes

DESCRIPTION

Un fichier de configuration sway est une liste de commandes sway qui sont exécutées par sway au démarrage. Ces commandes consistent généralement à définir vos préférences et à définir des raccourcis clavier. Un exemple de configuration est probablement présent dans /etc/sway/config pour que vous puissiez le consulter.

Les lignes du fichier de configuration peuvent être étendues sur plusieurs lignes en ajoutant un caractère '\' à la fin de la ligne. Par exemple :

bindsym Shift+XF86AudioRaiseVolume exec \
	pactl set-sink-volume @DEFAULT_SINK@ -1%

Les commandes peuvent également être données sous forme de bloc de la forme commande { <sous-commandes...> }. Tout ce qui précède l'ouverture de { sera ajouté au début des lignes à l'intérieur du bloc. Par exemple :

output eDP-1 {
	background ~/wallpaper.png fill
	resolution 1920x1080
}

est identique à

output eDP-1 background ~/wallpaper.png fill
output eDP-1 resolution 1920x1080

Ces commandes peuvent être exécutées dans votre fichier de configuration, via swaymsg(1), ou via la commande bindsym.

CONVENTIONS DE COMMANDE

Les commandes sont divisées en plusieurs arguments à l'aide d'espaces. Vous pouvez entourer les arguments de guillemets ("..." ou '...') pour ajouter des espaces à un seul argument. Vous pouvez également exécuter plusieurs commandes dans l'ordre en séparant chacune par , ou ;. Les critères sont conservés pour les commandes séparées par ,, mais seront réinitialisés (et permettront de nouveaux critères, si souhaité) pour les commandes séparées par un ;.

Dans toute la documentation, | est utilisé pour distinguer les arguments entre lesquels vous ne pouvez sélectionner qu'un seul choix. [...] est utilisé pour les arguments optionnels, et <...> pour les arguments où vous êtes censé fournir une valeur.

COMMANDES

Cette section liste uniquement les commandes générales. Pour les commandes d'entrée et de sortie, consultez sway-input(5) et sway-output(5).

Commandes uniquement dans la configuration

Les commandes suivantes ne peuvent être utilisées que dans le fichier de configuration.

bar [<id-bar>] <sous-commandes-bar...>

Pour plus de détails sur les sous-commandes de bar, voir sway-bar(5).

default_orientation horizontal|vertical|auto

Définit la disposition par défaut des conteneurs pour les conteneurs en mosaïque (tiled).

include <chemins...>

Inclut des fichiers depuis chemins. chemins peuvent inclure soit un chemin complet, soit un chemin relatif à la configuration parente, et développent la syntaxe shell (voir wordexp(3) pour les détails). Le même fichier inclus ne peut être inclus qu'une seule fois ; les tentatives ultérieures seront ignorées.

swaybg_command <commande>

Exécute la commande personnalisée de fond d'écran swaybg. Par défaut, c'est swaybg. Reportez-vous à sway-output(5) pour plus d'informations.

Elle peut être désactivée en définissant la commande sur un trait d'union simple : swaybg_command -

swaynag_command <commande>

Exécute une commande personnalisée pour swaynag. Par défaut, c'est swaynag. Des arguments supplémentaires peuvent être ajoutés à la fin. Ceci ne doit être utilisé que pour diriger sway à appeler swaynag depuis un chemin personnalisé ou pour fournir des arguments supplémentaires. Ceci doit être placé en haut de la configuration pour de meilleurs résultats.

Elle peut être désactivée en définissant la commande sur un trait d'union simple : swaynag_command -

workspace_layout default|stacking|tabbed

Spécifie la disposition initiale pour les nouveaux conteneurs dans un espace de travail vide.

xwayland enable|disable|force

Active ou désactive le support de Xwayland, qui permet d'utiliser les applications X11. enable chargera Xwayland de manière paresseuse, donc Xwayland ne sera lancé que lorsqu'un premier client tentera de se connecter. Dans certains cas, comme sur des machines plus lentes, il peut être souhaitable de démarrer Xwayland immédiatement en utilisant force au lieu de enable.

Commandes d'exécution uniquement

Les commandes suivantes ne peuvent pas être utilisées directement dans le fichier de configuration. Elles sont censées être utilisées avec bindsym ou en temps d'exécution via swaymsg(1).

border none|normal|csd|pixel [<n>]

Définit le style de bordure pour la fenêtre focalisée. normal inclut une bordure d'épaisseur n et une barre de titre. pixel est une bordure sans barre de titre, épaisse de n pixels. La barre de titre s'affiche toujours dans les dispositions stacking ou tabbed. csd est l'abréviation de client-side-decorations, qui permet au client de dessiner ses propres décorations. Par défaut, c'est normal avec une épaisseur de bordure de 2.

border toggle

Parcourt les styles de bordure disponibles.

exit

Quitte sway et termine votre session Wayland.

floating enable|disable|toggle

Rend la fenêtre focalisée flottante, non flottante, ou l'inverse de ce qu'elle est actuellement.

<critères> focus

Déplace la focalisation vers le conteneur qui correspond aux critères spécifiés.

focus up|right|down|left

Déplace la focalisation vers le conteneur suivant dans la direction spécifiée.

focus prev|next [sibling]

Déplace la focalisation vers le conteneur précédent ou suivant dans la disposition actuelle. Par défaut, le dernier enfant actif du conteneur nouvellement focalisé sera focalisé. L'option sibling indique de ne pas focaliser immédiatement un enfant du conteneur.

focus child

Déplace la focalisation vers le dernier enfant focalisé du conteneur focalisé.

focus parent

Déplace la focalisation vers le parent du conteneur focalisé.

focus output up|right|down|left

Déplace la focalisation vers la sortie suivante dans la direction spécifiée.

focus output <nom>

Déplace la focalisation vers la sortie nommée.

focus tiling

Définit la focalisation sur le dernier conteneur en mosaïque focalisé.

focus floating

Définit la focalisation sur le dernier conteneur flottant focalisé.

focus mode_toggle

Déplace la focalisation entre les couches flottante et en mosaïque.

fullscreen [enable|disable|toggle] [global]

Rend la fenêtre focalisée en plein écran, non en plein écran, ou l'inverse de ce qu'elle est actuellement. Si aucun argument n'est donné, cela fait la même chose que toggle. Si global est spécifié, la fenêtre sera en plein écran sur toutes les sorties.

gaps inner|outer|horizontal|vertical|top|right|bottom|left all|current set|plus|minus|toggle <montant>

Modifie les espacements inner ou outer pour tous les espaces de travail all ou pour l'espace de travail current. Les espacements outer peuvent être modifiés par côté avec top, right, bottom et left ou par direction avec horizontal et vertical.

inhibit_idle focus|fullscreen|open|none|visible

Définit/supprime un inhibiteur d'inactivité pour la fenêtre. focus inhibera l'inactivité lorsque la fenêtre sera focalisée par n'importe quel siège. fullscreen inhibera l'inactivité lorsque la vue sera en plein écran (ou un descendant d'un conteneur en plein écran) et visible. open inhibera l'inactivité jusqu'à ce que la fenêtre soit fermée (ou que l'inhibiteur soit désactivé/modifié). visible inhibera l'inactivité lorsque la fenêtre sera visible sur n'importe quelle sortie. none supprimera tout inhibiteur d'inactivité existant pour la fenêtre.

Ceci peut également être utilisé avec des critères pour définir un inhibiteur d'inactivité pour n'importe quelle fenêtre existante ou avec for_window pour définir des inhibiteurs d'inactivité pour les futures fenêtres.

layout default|splith|splitv|stacking|tabbed

Définit le mode de disposition du conteneur focalisé.

Lors de l'utilisation de la disposition stacking, seule la fenêtre focalisée dans le conteneur est affichée, avec la liste des fenêtres ouvertes en haut du conteneur.

La disposition tabbed est similaire à stacking, mais la liste des fenêtres est divisée verticalement.

layout toggle [split|all]

Parcourt la disposition

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

mode du conteneur focalisé via une liste prédéfinie de dispositions. Si aucun argument n'est donné, il parcourt en alternance les dispositions en pile, par onglets et la dernière disposition divisée. Si split est donné, il parcourt en alternance les dispositions horizontales et verticales. Si all est donné, il parcourt en alternance toutes les dispositions.

layout toggle [split|tabbed|stacking|splitv|splith] [split|tabbed|stacking|splitv|splith]...

Fait alterner le mode de disposition du conteneur focalisé via une liste de dispositions.

max_render_time off|<msec>

Contrôle le moment où l'application concernée est informée de rendre cette fenêtre, sous la forme d'un nombre de millisecondes positif avant le prochain compositing de la sortie par sway. Un nombre plus petit permet d'obtenir des images rendues plus récentes compositées par sway et une latence d'entrée perçue plus faible, mais si le réglage est trop bas, l'application peut ne pas finir de rendre avant que sway ne compose la sortie, entraînant des retards d'images.

Lorsque réglé sur off, l'application concernée est informée de rendre cette fenêtre immédiatement après le rafraîchissement de l'écran. Le temps restant pour le rendu avant que sway ne compose la sortie dépend du réglage max_render_time de la sortie.

Pour configurer cela pour une latence optimale :

1.
Configurer output max_render_time (voir sway-output(5)).
2.
Placer l'application cible en plein écran et la faire rendre quelque chose en continu.
3.
Commencer par régler max_render_time 1. Si l'application perd des images, incrémenter de 1.

Ce réglage n'a d'effet que si un max_render_time par sortie est actif sur la sortie où se trouve actuellement la fenêtre. Voir sway-output(5) pour plus de détails.

allow_tearing yes|no

Autorise ou interdit le déchirement de l'écran résultant de pages flipping immédiates pour une application en plein écran.

Lorsque cette option n'est pas définie, les indices de déchirement fournis par l'application déterminent si le déchirement est autorisé. Lorsque yes est spécifié, l'application autorise le déchirement indépendamment des indices de déchirement. Lorsque no est spécifié, le déchirement ne sera jamais autorisé sur l'application, indépendamment des indices de déchirement.

Ce réglage n'a d'effet que si le déchirement est autorisé sur la sortie via le réglage allow_tearing par sortie. Voir sway-output(5) pour plus de détails.

move left|right|up|down [<px> px]

Déplace le conteneur focalisé dans la direction spécifiée. L'argument optionnel px spécifie le nombre de pixels à déplacer le conteneur. S'il n'est pas spécifié, la valeur par défaut est de 10 pixels. Les pixels sont ignorés lors du déplacement de conteneurs en mosaïque.

move [absolute] position <pos_x> [px|ppt] <pos_y> [px|ppt]

Déplace le conteneur focalisé à la position spécifiée dans l'espace de travail. La position peut être spécifiée en pixels ou en points de pourcentage, omettre l'unité par défaut en pixels. Si absolute est utilisé, la position est relative à toutes les sorties. absolute ne peut pas être utilisé avec des points de pourcentage.

move [absolute] position center

Centre le conteneur focalisé dans l'espace de travail. Si absolute est utilisé, il est centré sur toutes les sorties.

move position cursor|mouse|pointer

Centre le conteneur focalisé sur le curseur.

move [container|window] [to] mark <mark>

Déplace le conteneur focalisé vers la marque spécifiée.

move [--no-auto-back-and-forth] [container|window] [to] workspace [number] <name>

Déplace le conteneur focalisé vers l'espace de travail spécifié. La chaîne number est facultative et est utilisée pour faire correspondre un espace de travail portant le même numéro, même s'il a un nom différent.

move [container|window] [to] workspace prev|next|current

Déplace le conteneur focalisé vers l'espace de travail précédent, suivant ou actuel sur cette sortie, ou s'il ne reste plus d'espaces de travail, vers la sortie précédente ou suivante.

move [container|window] [to] workspace prev_on_output|next_on_output

Déplace le conteneur focalisé vers l'espace de travail précédent ou suivant sur cette sortie, en bouclant si déjà au premier ou au dernier espace de travail.

move [container|window] [to] workspace back_and_forth

Déplace le conteneur focalisé vers l'espace de travail précédemment focalisé.

move [container|window] [to] output <name-or-id>|current

Déplace le conteneur focalisé vers la sortie spécifiée.

move [container|window] [to] output up|right|down|left

Déplace le conteneur focalisé vers la sortie suivante dans la direction spécifiée.

move [container|window] [to] scratchpad

Déplace le conteneur focalisé vers le scratchpad.

move workspace [to] output <name-or-id>|current

Déplace l'espace de travail focalisé vers la sortie spécifiée.

move workspace to [output] <name-or-id>|current

Déplace l'espace de travail focalisé vers la sortie spécifiée.

move workspace [to] output up|right|down|left

Déplace l'espace de travail focalisé vers la sortie suivante dans la direction spécifiée.

move workspace to [output] up|right|down|left

Déplace l'espace de travail focalisé vers la sortie suivante dans la direction spécifiée.

nop <comment>

Une commande de non-opération qui peut être utilisée pour remplacer le comportement par défaut. L'argument de commentaire facultatif est ignoré, mais enregistré à des fins de débogage.

reload

Recharge le fichier de configuration sway et applique toute modification. Le fichier de configuration se trouve dans le chemin spécifié par les arguments de la ligne de commande au démarrage, sinon conformément à la priorité indiquée dans sway(1).

rename workspace [<old_name>] to <new_name>

Renomme soit <old_name>, soit l'espace de travail focalisé en <new_name>.

resize shrink|grow width|height [<amount> [px|ppt]]

Redimensionne le conteneur actuellement focalisé par amount, spécifié en pixels ou en points de pourcentage. Si les unités sont omises, les conteneurs flottants sont redimensionnés en px et les conteneurs en mosaïque en ppt. amount sera par défaut à 10 s'il est omis.

resize set height <height> [px|ppt]

Définit la hauteur du conteneur à height, spécifiée en pixels ou en points de pourcentage. Si les unités sont omises, les conteneurs flottants sont redimensionnés en px et les conteneurs en mosaïque en ppt. Si height est 0, le conteneur ne sera pas redimensionné.

resize set [width] <width> [px|ppt]

Définit la largeur du conteneur à width, spécifiée en pixels ou en points de pourcentage. Si les unités sont omises, les conteneurs flottants sont redimensionnés en px et les conteneurs en mosaïque en ppt. Si width est 0, le conteneur ne sera pas redimensionné.

resize set [width] <width> [px|ppt] [height] <height> [px|ppt]

Définit la largeur et la hauteur du conteneur à width et height, spécifiées en pixels ou en points de pourcentage. Si les unités sont omises, les conteneurs flottants sont redimensionnés en px et les conteneurs en mosaïque en ppt. Si width ou height est 0, le conteneur ne sera pas redimensionné sur cet axe.

scratchpad show

Affiche une fenêtre du scratchpad. Utiliser cette commande de manière répétée fera défiler les fenêtres du scratchpad.

shortcuts_inhibitor enable|disable

Active ou désactive la capacité des clients à inhiber les raccourcis clavier pour une fenêtre. Ceci est principalement utile pour les logiciels de virtualisation et de bureau à distance. Cela affecte soit la fenêtre actuellement focalisée, soit un ensemble de fenêtres sélectionnées par des critères. La sous-commande disable désactive en plus tous les inhibiteurs actifs pour la ou les fenêtres données. Les critères sont particulièrement utiles avec la commande for_window pour configurer une classe de fenêtres différemment des valeurs par défaut par siège établies par la sous-commande seat du même nom. Voir sway-input(5) pour plus de moyens d'affecter les inhibiteurs.

split vertical|v|horizontal|h|none|n|toggle|t

Divise le conteneur actuel, verticalement ou horizontalement. Lorsque none est spécifié, l'effet d'une division précédente est annulé si le conteneur actuel est le seul enfant d'un parent divisé. Lorsque toggle est spécifié, le conteneur actuel est divisé à l'opposé de la disposition du conteneur parent.

splith

Équivalent à split horizontal

splitv

Équivalent à split vertical

splitt

Équivalent à split toggle

sticky enable|disable|toggle

"Colle" une fenêtre flottante à la sortie actuelle pour qu'elle apparaisse sur tous les espaces de travail.

swap container with id|con_id|mark <arg>

Échange la position, la géométrie et l'état plein écran de deux conteneurs. Le premier conteneur peut être sélectionné par des critères ou par le focus. Le second conteneur peut être sélectionné par id, con_id ou mark. id ne peut être utilisé qu'avec des fenêtres xwayland. Si le premier conteneur a le focus, il le conservera sauf s'il est déplacé vers un autre espace de travail ou si le second conteneur devient plein écran sur le même espace de travail que le premier conteneur. Dans l'un de ces cas, le second conteneur gagnera le focus.

title_format <format>

Définit le format des titres de fenêtre. Les espaces réservés suivants peuvent être utilisés :

%title

Le titre fourni par la fenêtre

%app_id

L'identifiant d'application Wayland (applicable aux fenêtres Wayland uniquement)

%class

Le nom de classe X11 (applicable aux fenêtres Xwayland uniquement)

%instance

L'instance X11 (applicable aux fenêtres Xwayland uniquement)

%shell

Le protocole utilisé par la fenêtre (généralement xwayland ou xdg_shell)

%sandbox_engine

Le moteur de sandbox associé

%sandbox_app_id

L'identifiant d'application fourni par le moteur de sandbox associé

%sandbox_instance_id

L'identifiant d'instance fourni par le moteur de sandbox associé

Cette commande est généralement utilisée avec des critères for_window. Par exemple :

for_window [t{ "title": "\"

.

title_format\"", "content": "

Notez que le balisage nécessite que pango soit activé via la commande font.

\n

Le format par défaut est \"%title\".

Commandes de configuration ou d'exécution

\n

Les commandes suivantes peuvent être utilisées dans le fichier de configuration ou lors de l'exécution.

\n

assign <critères> [→] [espace de travail] [nombre] <espace de travail>

\n
Assigne les fenêtres correspondant aux critères (voir CRITERIA pour plus de détails) à l'espace de travail. Le symbole → (U+2192) est facultatif et cosmétique. Cette commande est équivalente à :\n
for_window <critères> move container to workspace <espace de travail>
\n
\n

assign <critères> [→] output left|right|up|down|<nom>

\n
Assigne les fenêtres correspondant aux critères (voir CRITERIA pour plus de détails) à la sortie spécifiée. Le symbole → (U+2192) est facultatif et cosmétique. Cette commande est équivalente à :\n
for_window <critères> move container to output <sortie>
\n
\n

bindsym [--whole-window] [--border] [--exclude-titlebar] [--release] [--locked] [--to-code] [--input-device=<périphérique>] [--no-warn] [--no-repeat] [--inhibited] [Group<1-4>+]<combinaison de touches> <commande>

\n
Lie la combinaison de touches à l'exécution de la commande sway commande lorsqu'elle est pressée. Vous pouvez utiliser les noms de touches XKB ici (wev(1) est un bon outil pour les découvrir). Avec l'indicateur --release, la commande est exécutée lorsque la combinaison de touches est relâchée. Si input-device est spécifié, la liaison ne sera exécutée que pour ce périphérique d'entrée et sera exécutée à la place de toute liaison générique à tous les périphériques. Si un numéro de groupe est spécifié, la liaison ne sera disponible que pour ce groupe. Par défaut, si vous remplacez une liaison, swaynag vous avertira. Pour supprimer cet avertissement, utilisez l'indicateur --no-warn.\n

Pour spécifier les touches modificatrices, vous pouvez utiliser les noms des modificateurs XKB Shift, Lock (pour Caps Lock), Control, Mod1 (pour Alt), Mod2 (pour Num Lock), Mod3 (pour le modificateur XKB Mod3), Mod4 (pour la touche Logo), et Mod5 (pour AltGr). De plus, vous pouvez utiliser les alias Ctrl (pour Control), Alt (pour Alt), et Super (pour la touche Logo).

\n

Sauf si l'indicateur --locked est défini, la commande ne sera pas exécutée lorsqu'un programme de verrouillage d'écran est actif. S'il existe une liaison correspondante avec et sans --locked, celle avec sera préférée lorsqu'elle est verrouillée et celle sans sera préférée lorsqu'elle n'est pas verrouillée. S'il existe des liaisons correspondantes et que l'une a à la fois --input-device et --locked et l'autre n'a ni l'un ni l'autre, la première sera préférée même lorsqu'elle n'est pas verrouillée.

\n

Sauf si l'indicateur --inhibited est défini, la commande ne sera pas exécutée lorsqu'un inhibiteur de raccourcis clavier est actif pour la fenêtre actuellement focalisée. De tels inhibiteurs sont généralement demandés par les logiciels de bureau à distance et de virtualisation pour permettre à l'utilisateur d'envoyer des raccourcis clavier à la session distante ou virtuelle. L'indicateur --inhibited permet de définir des liaisons qui seront exemptées de transfert vers de tels logiciels. La même logique de préférence que pour --locked s'applique.

\n

Sauf si l'indicateur --no-repeat est défini, la commande sera exécutée de manière répétée lorsque la touche est maintenue enfoncée, conformément aux paramètres de répétition spécifiés dans la configuration d'entrée.

\n

Les liaisons aux keysyms dépendent de la disposition. Cela peut être modifié avec l'indicateur --to-code. Dans ce cas, les keysyms seront traduits dans les keycodes correspondants dans la première disposition configurée.

\n

Les liaisons de souris agissent sur le conteneur sous le curseur au lieu du conteneur qui a le focus. Les boutons de la souris peuvent être spécifiés sous la forme button[1-9] ou en utilisant le nom du code événementiel (par ex. BTN_LEFT ou BTN_RIGHT). Pour la première option, les boutons seront mappés à leurs valeurs dans X11 (1=gauche, 2=milieu, 3=droite, 4=molette haut, 5=molette bas, 6=molette gauche, 7=molette droite, 8=précédent, 9=suivant). Pour la seconde option, vous pouvez trouver les noms des événements en utilisant libinput debug-events.

\n

La priorité pour la correspondance des liaisons est la suivante : périphérique d'entrée, groupe et état verrouillé.

\n

--whole-window, --border, et --exclude-titlebar sont des options uniquement pour la souris qui affectent la région dans laquelle les liaisons de souris peuvent être déclenchées. Par défaut, les liaisons de souris ne sont déclenchées que lorsqu'elles sont au-dessus de la barre de titre. Avec l'option --border, la bordure de la fenêtre sera incluse dans cette région. Avec l'option --whole-window, le curseur peut être n'importe où sur une fenêtre, y compris le titre, la bordure et le contenu. --exclude-titlebar peut être utilisé en conjonction avec toute autre option pour spécifier que la barre de titre doit être exclue de la région considérée.

\n

Si --whole-window est spécifié, la commande peut être déclenchée lorsque le curseur est au-dessus d'un espace de travail vide. L'utilisation d'une liaison de souris sur la région exclusive d'une surface de couche n'est pas actuellement possible.

\n

Exemple :

\n
\n
\n
# Exécute firefox lorsque alt, shift et f sont pressés ensemble\nbindsym Mod1+Shift+f exec firefox

bindcode [--whole-window] [--border] [--exclude-titlebar] [--release] [--locked] [--input-device=<périphérique>] [--no-warn] [--no-repeat] [--inhibited] [Group<1-4>+]<code> <commande> est également disponible pour lier avec des codes de touches/boutons au lieu de noms de touches/boutons.
\n

bindswitch [--locked] [--no-warn] [--reload] <commutateur>:<état> <commande>

\n
Lie le <commutateur> à l'exécution de la commande sway commande lors des changements d'état. Les commutateurs pris en charge sont les commutateurs lid (couvercle d'ordinateur portable) et tablet (mode tablette). Les valeurs valides pour state sont on, off et toggle. Ces commutateurs sont activés lorsque le couvercle de l'appareil est fermé et lorsque le mode tablette est actif respectivement. toggle est également pris en charge pour exécuter une commande lorsque le commutateur est activé ou désactivé.\n

Sauf si l'indicateur --locked est défini, la commande ne sera pas exécutée lorsqu'un programme de verrouillage d'écran est actif. S'il existe une liaison correspondante avec et sans --locked, celle avec sera préférée lorsqu'elle est verrouillée et celle sans sera préférée lorsqu'elle n'est pas verrouillée.

\n

Si l'indicateur --reload est spécifié, la liaison sera également exécutée lors du rechargement de la configuration. Les liaisons toggle ne seront pas exécutées lors du rechargement. L'indicateur --locked fonctionnera normalement, donc si la configuration est rechargée lorsqu'elle est verrouillée et que --locked n'est pas spécifié, la liaison ne sera pas exécutée.

\n

Par défaut, si vous remplacez une liaison, swaynag vous avertira. Pour supprimer cet avertissement, utilisez l'indicateur --no-warn.

\n

Exemple :

\n
\n
\n

Spécifie la taille maximale des fenêtres flottantes. -1 x -1 supprime la limite supérieure. La valeur par défaut est 0 x 0, ce qui utilisera la largeur et la hauteur de la disposition de sortie entière comme maximums.

Spécifie la taille minimale des fenêtres flottantes. La valeur par défaut est 75 x 50.

floating_modifier <modificateur> [normal|inverse]

Lorsque la touche modificateur est maintenue enfoncée, vous pouvez cliquer avec le bouton gauche de la souris pour déplacer les fenêtres et cliquer avec le bouton droit pour les redimensionner. Définir modificateur sur none désactive cette fonctionnalité. Si inverse est spécifié, le clic gauche est utilisé pour le redimensionnement et le clic droit pour le déplacement.

Si défini sur yes, déplacer votre souris sur une fenêtre la mettra au premier plan. Si défini sur always, la fenêtre sous le curseur sera toujours au premier plan, même après avoir changé d'espace de travail.

focus_on_window_activation smart|urgent|focus|none

Cette option détermine ce qu'il faut faire lorsqu'un client demande une activation de fenêtre. Si défini sur urgent, l'état d'urgence sera défini pour cette fenêtre. Si défini sur focus, la fenêtre sera mise au premier plan. Si défini sur smart, la fenêtre sera mise au premier plan uniquement si elle est déjà visible, sinon l'état d'urgence sera défini. Par défaut, c'est urgent.

Cette option détermine ce qu'il faut faire lorsque l'on essaie de se concentrer au-delà du bord d'un conteneur. Si défini sur no, le conteneur focalisé conservera le focus, s'il n'y a pas d'autres conteneurs dans la direction. Si défini sur yes, le focus sera ramené au bord opposé du conteneur, s'il n'y a pas d'autres conteneurs dans la direction. Si défini sur force, le focus sera ramené au bord opposé du conteneur, même s'il y a d'autres conteneurs dans la direction. Si défini sur workspace, le focus se déplacera comme dans le cas yes et se déplacera également lors du passage des limites des espaces de travail. Par défaut, c'est yes.

Si une application sur un autre espace de travail définit un indice d'urgence, le passage à cet espace de travail peut entraîner la mise au premier plan immédiate de l'application, ce qui signifie également que la couleur de la décoration de la fenêtre serait immédiatement réinitialisée à client.focused. Cela peut rendre inutilement difficile de savoir quelle fenêtre a initialement déclenché l'événement. Cette option permet de définir un délai en ms pour retarder la réinitialisation de l'indice d'urgence.

Épaisseur de la bordure de la barre de titre en pixels.

Marge du texte dans la barre de titre. La valeur horizontal affecte la marge horizontale du texte tandis que la valeur vertical affecte la marge verticale (espace au-dessus et en dessous du texte). Les espaces externes peuvent également être spécifiés par côté avec top, right, bottom, et left ou par direction avec horizontal et vertical.

Pour plus de détails sur les sous-commandes de siège, voir sway-input(5).

Par défaut, mark définit identifiant comme la seule marque sur une fenêtre. --add ajoutera plutôt identifiant à la liste des marques actuelles pour cette fenêtre. Si output est spécifié, la souris sera déplacée vers de nouvelles sorties lorsque vous basculez entre elles. Si container est spécifié, la souris sera déplacée vers le milieu du conteneur lors du changement. Par défaut, c'est output.

Détermine ce qu'il faut faire lorsqu'une fenêtre en plein écran ouvre une boîte de dialogue. Si smart (par défaut), la boîte de dialogue sera affichée. Si ignore, la boîte de dialogue ne sera pas rendue. Si leave_fullscreen, la fenêtre quittera le mode plein écran et la boîte de dialogue sera rendue.

Active ou désactive le presse-papiers de sélection primaire. Ne peut être configuré qu'au lancement. Par défaut, il est activé.

Si show_marks est défini sur yes, les marques seront affichées dans les bordures de fenêtre. Toute marque commençant par un underscore ne sera pas dessinée, même si show_marks est défini sur yes. Par défaut, la valeur est yes.

Ajuste l'opacité de la fenêtre entre 0 (complètement transparent) et 1 (complètement opaque). Si l'opération est omise, set sera utilisé.

Une fois le seuil dépassé une fois, le déplacement commence et le curseur peut revenir à l'intérieur du seuil sans arrêter le déplacement. seuil est multiplié par l'échelle de la sortie sur laquelle se trouve le curseur. Par défaut, la valeur est 9.

Définit l'alignement du titre. Si right est sélectionné et que show_marks est défini sur yes, les marques seront affichées sur le côté left au lieu du côté right.

Commute vers l'espace de travail spécifié. La partie num: du nom est facultative et sera utilisée pour l'ordre. Si num: n'est pas fourni et que name est un nombre, il sera également utilisé pour l'ordre.

Spécifie que l'espace de travail name doit avoir les paramètres d'espacement (gaps) donnés lors de sa création.

CRITÈRES

Un critère est une chaîne de caractères de la forme, par exemple :

[app_id="some-application" title="[Rr]egex.*"]

La chaîne contient un ou plusieurs attributs/valeurs séparés par des espaces. Ils sont utilisés par certaines commandes pour choisir sur quelles fenêtres exécuter des actions. Tous les attributs doivent correspondre pour que le critère soit valide. Les critères sont conservés entre les commandes séparées par une ,, mais seront réinitialisés (et permettront de nouveaux critères, si désiré) pour les commandes séparées par un ;.

Les critères peuvent être utilisés avec les commandes for_window ou assign pour spécifier les opérations à effectuer sur les nouvelles fenêtres. Un critère peut également être utilisé pour exécuter des commandes spécifiques (celles qui agissent normalement sur une seule fenêtre) sur toutes les fenêtres qui correspondent à ce critère. Par exemple :

Se focaliser sur une fenêtre avec la marque "IRC" :

[con_mark="IRC"] focus

Tuer toutes les fenêtres dont le titre contient "Emacs" :

[title="Emacs"] kill

Plusieurs attributs autorisent les expressions régulières. Celles-ci utilisent les expressions régulières compatibles Perl (PCRE2), qui sont documentées dans pcre2pattern(3) et résumées dans pcre2syntax(3). Par exemple, ceci déplace toutes les fenêtres dont les titres se terminent par "sway" ou "Sway" vers l'espace de travail 1 :

[title="[Ss]way$"] move workspace 1

Vous pourriez vouloir utiliser swaymsg -t get_tree pour trouver les valeurs de ces propriétés en pratique pour vos applications.

Les attributs suivants peuvent être utilisés pour la comparaison :

all

Correspond à toutes les fenêtres.

app_id

Compare la valeur avec l'ID de l'application. Peut être une expression régulière. Si la valeur est __focused__, alors l'ID de l'application doit être le même que celui de la fenêtre actuellement focalisée. Les app_id sont spécifiques aux applications Wayland.

class

Compare la valeur avec la classe de la fenêtre. Peut être une expression régulière. Si la valeur est __focused__, alors la classe de la fenêtre doit être la même que celle de la fenêtre actuellement focalisée. Les class sont spécifiques aux applications X11 et nécessitent XWayland.

con_id

Compare avec l'ID interne du conteneur, que vous pouvez trouver via IPC. Si la valeur est __focused__, alors l'ID doit être le même que celui de la fenêtre actuellement focalisée.

con_mark

Compare avec les marques de la fenêtre. Peut être une expression régulière.

floating

Correspond aux fenêtres flottantes.

id

Compare la valeur avec l'ID de la fenêtre X11. Doit être numérique. L'id est spécifique aux applications X11 et nécessite XWayland.

instance

Compare la valeur avec l'instance de la fenêtre. Peut être une expression régulière. Si la valeur est __focused__, alors l'instance de la fenêtre doit être la même que celle de la fenêtre actuellement focalisée. L'instance est spécifique aux applications X11 et nécessite XWayland.

pid

Compare la valeur avec l'ID de processus de la fenêtre. Doit être numérique.

shell

Compare la valeur avec le shell de la fenêtre, tel que "xdg_shell" ou "xwayland". Peut être une expression régulière. Si la valeur est __focused__, alors le shell doit être le même que celui de la fenêtre actuellement focalisée.

tiling

Correspond aux fenêtres en tiling.

title

Compare avec le titre de la fenêtre. Peut être une expression régulière. Si la valeur est __focused__, alors le titre de la fenêtre doit être le même que celui de la fenêtre actuellement focalisée.

urgent

Compare l'état urgent de la fenêtre. Peut être first, last, latest, newest, oldest ou recent.

window_role

Compare avec le rôle de la fenêtre (WM_WINDOW_ROLE). Peut be une expression régulière. Si la valeur est \_\_focused\_\_, alors le rôle de la fenêtre doit être le même que celui de la fenêtre actuellement focalisée. \texttt{window\_role} est spécifique aux applications X11 et nécessite XWayland.

window_type

Compare avec le type de fenêtre (_NET_WM_WINDOW_TYPE). Les valeurs possibles sont normal, dialog, utility, toolbar, splash, menu, dropdown\_menu, popup\_menu, tooltip et notification. \texttt{window\_type} est spécifique aux applications X11 et nécessite XWayland.

workspace

Compare avec le nom de l'espace de travail de cette fenêtre. Peut être une expression régulière. Si la valeur est \_\_focused\_\_, alors toutes les fenêtres de l'espace de travail actuellement focalisé correspondent.

sandbox_engine

Compare avec le moteur de sandbox associé. Peut être une expression régulière. Si la valeur est \_\_focused\_\_, alors le moteur de sandbox doit être le même que celui de la fenêtre actuellement focalisée.

sandbox_app_id

Compare avec l'ID d'application fourni par le moteur de sandbox associé. Peut être une expression régulière. Si la valeur est \_\_focused\_\_, alors l'ID d'application de sandbox doit être le même que celui de la fenêtre actuellement focalisée.

sandbox_instance_id

Compare avec l'ID d'instance fourni par le moteur de sandbox associé. Peut être une expression régulière. Si la valeur est \_\_focused\_\_, alors l'ID d'instance de sandbox doit être le même que celui de la fenêtre actuellement focalisée.
