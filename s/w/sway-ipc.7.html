NOM

sway-ipc - Protocole IPC pour sway

DESCRIPTION

Ceci détaille le protocole de communication inter-processus (IPC) pour sway(1). Ce protocole IPC peut être utilisé pour contrôler ou obtenir des informations d'un processus sway.

Le protocole IPC utilise un socket UNIX comme méthode de communication. Le chemin vers le socket est stocké dans la variable d'environnement SWAYSOCK et, pour la compatibilité ascendante avec i3, I3SOCK. Vous pouvez également obtenir le chemin du socket en appelant sway --get-socketpath.

FORMAT DES MESSAGES ET DES RÉPONSES

Le format des messages et des réponses est :

<chaîne-magique> <longueur-payload> <type-payload> <payload>
Où
<chaîne-magique> est i3-ipc, pour la compatibilité avec i3
<longueur-payload> est un entier de 32 bits en ordre natif des octets
<type-payload> est un entier de 32 bits en ordre natif des octets

Par exemple, envoyer la commande exit ressemblerait à l'extrait hexadécimal suivant :

00000000 | 69 33 2d 69 70 63 04 00 00 00 00 00 00 00 65 78 |i3-ipc........ex|
00000010 | 69 74                                           |it              |

Le payload des réponses sera une structure de données JSON sérialisée valide.

MESSAGES ET RÉPONSES

Les types de messages suivants et leurs types de réponses correspondants sont actuellement supportés. Pour toutes les réponses, toutes les propriétés non listées sont sujettes à suppression.

NUMÉRO DE TYPE NOM DU MESSAGE BUT
0 RUN_COMMAND Exécute le payload comme commandes sway
1 GET_WORKSPACES Obtenir la liste des espaces de travail actuels
2 SUBSCRIBE S'abonner aux événements listés dans le payload
3 GET_OUTPUTS Obtenir la liste des sorties actuelles
4 GET_TREE Obtenir l'arbre de disposition des nœuds
5 GET_MARKS Obtenir les noms de toutes les marques actuellement définies
6 GET_BAR_CONFIG Obtenir la configuration du panneau spécifiée ou une liste de noms de configuration de panneau
7 GET_VERSION Obtenir la version de sway qui possède le socket IPC
8 GET_BINDING_MODES Obtenir la liste des noms de modes de liaison
9 GET_CONFIG Retourne la configuration qui a été chargée en dernier
10 SEND_TICK Envoie un événement tick avec le payload spécifié
11 SYNC Répond avec un objet d'échec pour la compatibilité avec i3
12 GET_BINDING_STATE Demande l'état actuel des liaisons, par exemple le nom du mode de liaison actuellement actif.
100 GET_INPUTS Obtenir la liste des périphériques d'entrée
101 GET_SEATS Obtenir la liste des sièges

0. RUN_COMMAND

MESSAGE
Analyse et exécute le payload comme commandes sway

RÉPONSE
Un tableau d'objets correspondant à chaque commande analysée. Chaque objet a la propriété success, qui est une valeur booléenne indiquant si la commande a réussi ou non. L'objet peut également contenir les propriétés error et parse_error. La propriété error est un message d'erreur lisible par l'homme, tandis que parse_error est une valeur booléenne indiquant si la raison de l'échec de la commande était que la commande était inconnue ou n'a pas pu être analysée.

Exemple de réponse :

[
	{
		"success": true
	},
	{
		"success": false,
		"parse_error": true,
		"error": "Commande invalide/inconnue"
	}
]

1. GET_WORKSPACES

MESSAGE
Récupère la liste des espaces de travail.

RÉPONSE
La réponse est un tableau d'objets correspondant à chaque espace de travail. Chaque objet a les propriétés suivantes :

PROPRIÉTÉ TYPE DE DONNÉES DESCRIPTION
num entier Le numéro de l'espace de travail ou -1 pour les espaces de travail qui ne commencent pas par un nombre
name chaîne Le nom de l'espace de travail
visible booléen Si l'espace de travail est actuellement visible sur une sortie
focused booléen Si l'espace de travail est actuellement focalisé par le siège par défaut (seat0)
urgent booléen Si une fenêtre sur l'espace de travail a le drapeau urgent défini
rect objet Les limites de l'espace de travail. Il se compose de x, y, width (largeur) et height (hauteur)
output chaîne Le nom de la sortie sur laquelle se trouve l'espace de travail

Exemple de réponse :

[
	{
		"num": 1,
		"name": "1",
		"visible": true,
		"focused": true,
		"rect": {
			"x": 0,
			"y": 23,
			"width": 1920,
			"height": 1057
		},
		"output": "eDP-1"
	},
]

2. SUBSCRIBE

MESSAGE
S'abonne cette connexion IPC aux types d'événements spécifiés dans le payload du message. Le payload doit être un tableau JSON valide d'événements. Voir la section ÉVÉNEMENTS pour la liste des événements supportés.

RÉPONSE
Un seul objet qui contient la propriété success, qui est une valeur booléenne indiquant si l'abonnement a réussi ou non.

Exemple de réponse :

{
	"success": true
}

4. GET_TREE

MESSAGE
Récupérer une représentation JSON de l'arbre

RÉPONSE
Un tableau d'objets représentant l'arbre actuel. Chaque objet représente un nœud et aura les propriétés suivantes :

PROPRIÉTÉ TYPE DE DONNÉES DESCRIPTION
id entier L'ID interne unique de ce nœud
nom chaîne de caractères Le nom du nœud, tel que le nom de la sortie ou le titre de la fenêtre. Pour le bloc-notes, ce sera __i3_scratch pour la compatibilité avec i3.
type chaîne de caractères Le type de nœud. Il peut s'agir de root, output, workspace, con, ou floating_con
bordure chaîne de caractères Le style de bordure du nœud. Il peut s'agir de normal, none, pixel, ou csd
largeur_bordure_actuelle entier Nombre de pixels utilisés pour la largeur de la bordure
agencement chaîne de caractères L'agencement du nœud. Il peut s'agir de splith, splitv, stacked, tabbed, ou output
orientation chaîne de caractères L'orientation du nœud. Elle peut être verticale, horizontale, ou aucune
pourcentage flottant Le pourcentage du parent du nœud qu'il occupe, ou null pour la racine et d'autres nœuds spéciaux comme le bloc-notes
rect objet La géométrie absolue du nœud. Les décorations de fenêtre sont exclues de ceci, mais les bordures sont incluses.
rect_fenetre objet La géométrie du contenu à l'intérieur du nœud. Ces coordonnées sont relatives au nœud lui-même. Les décorations de fenêtre et les bordures sont à l'extérieur du rect_fenetre
rect_deco objet La géométrie des décorations du nœud par rapport au nœud parent
geometrie objet La géométrie naturelle du contenu s'il devait se redimensionner lui-même
urgent booléen Indique si le nœud ou l'un de ses descendants a l'indicateur urgent défini. Note : Ceci peut ne pas exister lors de la compilation sans prise en charge de xwayland
fixe booléen Indique si le nœud est fixe (s'affiche sur tous les espaces de travail)
marques tableau Liste des marques attribuées au nœud
concentre booléen Indique si le nœud est actuellement focalisé par le siège par défaut (seat0)
focus tableau Tableau des ID des nœuds enfants dans l'ordre de focalisation actuel
noeuds tableau Les nœuds enfants de type tiling pour le nœud
noeuds_flottants tableau Les nœuds enfants flottants pour le nœud
representation chaîne de caractères (Espaces de travail uniquement) Une représentation textuelle de l'agencement de l'espace de travail qui peut être utilisée pour faciliter la soumission d'étapes de reproduction pour les rapports de bogues
mode_plein_ecran entier (Conteneurs et fenêtres uniquement) Le mode plein écran du nœud. 0 signifie aucun, 1 signifie espace de travail complet, et 2 signifie plein écran global
flottant chaîne de caractères État flottant du conteneur. Peut être "auto_off" ou "user_on"
etat_bloc_notes chaîne de caractères Indique si la fenêtre est dans le bloc-notes. Peut être "none" ou "fresh"
id_application chaîne de caractères (Fenêtres uniquement) Pour une fenêtre xdg-shell, le nom de l'application, s'il est défini. Sinon, null
pid entier (Fenêtres uniquement) Le PID de l'application propriétaire de la fenêtre
identifiant_toplevel_etranger chaîne de caractères (Fenêtres uniquement) L'identifiant toplevel ext-foreign-toplevel-list-v1 de ce nœud.
visible booléen (Fenêtres uniquement) Indique si le nœud est visible
shell chaîne de caractères (Fenêtres uniquement) Le shell de la fenêtre, tel que xdg_shell ou xwayland
inhibe_veille booléen (Fenêtres uniquement) Indique si la fenêtre inhibe l'état de veille
inhibiteurs_veille objet (Fenêtres uniquement) Un objet contenant l'état des inhibiteurs de veille application et user. application peut être enabled ou none. user peut être focus, fullscreen, open, visible ou none.
moteur_sandbox chaîne de caractères (Fenêtres uniquement) Le moteur de sandbox associé (ou null)
id_application_sandbox chaîne de caractères (Fenêtres uniquement) L'ID d'application fourni par le moteur de sandbox associé (ou null)
id_instance_sandbox chaîne de caractères (Fenêtres uniquement) L'ID d'instance fourni par le moteur de sandbox associé (ou null)
fenetre entier (Fenêtres xwayland uniquement) L'ID de fenêtre X11 pour la fenêtre xwayland
ndow window_properties objet (Uniquement pour les fenêtres xwayland) Un objet contenant le titre, la classe, l'instance, le rôle de fenêtre, le type de fenêtre et transient_for pour la fenêtre

5. GET_MARKS

MESSAGE
Récupérer les marques actuellement définies

REPLY
Un tableau de marques actuellement définies. Comme chaque marque ne peut être définie que pour un seul conteneur, il s'agit d'un ensemble, donc chaque valeur est unique et l'ordre est indéfini.

Exemple de réponse :

[
	"one",
	"test"
]

6. GET_BAR_CONFIG (SANS CHARGE UTILE)

MESSAGE
Lorsque envoyé sans charge utile, ceci récupère la liste des identifiants de barres configurés

REPLY
Un tableau d'identifiants de barres, qui sont des chaînes de caractères

Exemple de réponse :

[
	"bar-0",
	"bar-1"
]

6. GET_BAR_CONFIG (AVEC UNE CHARGE UTILE)

MESSAGE
Lorsqu'envoyé avec un identifiant de barre comme charge utile, ceci récupère la configuration associée à celle spécifiée par l'identifiant de barre dans la charge utile. Ceci est utilisé par swaybar, mais pourrait également être utilisé pour des barres tierces.

REPLY
Un objet qui représente la configuration pour la barre avec l'identifiant de barre envoyé comme charge utile. Les propriétés suivantes existent et plus d'informations sur la signification de leurs valeurs peuvent être trouvées dans sway-bar(5) :

PROPRIÉTÉ TYPE DE DONNÉE DESCRIPTION
id chaîne L'ID de la barre
mode chaîne Le mode pour la barre. Il peut être dock, hide, ou invisible
position chaîne La position de la barre. Elle peut actuellement être soit bottom (en bas) soit top (en haut)
status_command chaîne La commande qui doit être exécutée pour générer la ligne de statut
font chaîne La police à utiliser pour le texte sur la barre
workspace_buttons booléen Afficher ou non les boutons d'espaces de travail sur la barre
workspace_min_width entier Largeur minimale en px pour les boutons d'espaces de travail sur la barre
binding_mode_indicator booléen Afficher ou non le mode de liaison actuel sur la barre
verbose booléen Pour la compatibilité i3, ce sera la valeur booléenne false.
colors objet Un objet contenant les couleurs #RRGGBBAA à utiliser pour la barre. Voir ci-dessous pour plus d'informations
gaps objet Un objet représentant les espaces pour la barre composé de top (haut), right (droite), bottom (bas), et left (gauche).
bar_height entier La hauteur absolue à utiliser pour la barre ou 0 pour un dimensionnement automatique basé sur la police
status_padding entier Le remplissage vertical à utiliser pour la ligne de statut
status_edge_padding entier Le remplissage horizontal à utiliser pour la ligne de statut lorsqu'elle se trouve en fin de sortie

L'objet colors contient les propriétés suivantes, qui sont toutes des chaînes contenant la représentation #RRGGBBAA de la couleur :

PROPRIÉTÉ DESCRIPTION

ÉVÉNEMENTS

Les événements sont un moyen pour les clients d'être notifiés des changements dans sway. Un client peut s'abonner à tous les événements pour lesquels il souhaite être notifié des changements. L'événement est envoyé dans le même format qu'une réponse. Les événements suivants sont actuellement disponibles :

TYPE D'ÉVÉNEMENT NOM DESCRIPTION
0x80000000 espace de travail Envoyé chaque fois qu'un événement impliquant un espace de travail se produit, tel que l'initialisation d'un nouvel espace de travail ou le focus d'un autre espace de travail
0x80000001 sortie Envoyé lorsque les sorties sont mises à jour
0x80000002 mode Envoyé chaque fois que le mode de liaison change
0x80000003 fenêtre Envoyé chaque fois qu'un événement impliquant une fenêtre se produit, comme être reparentée, focalisée ou fermée
0x80000004 mise à jour_config_barre Envoyé chaque fois qu'une configuration de barre change
0x80000005 liaison Envoyé lorsqu'une liaison configurée est exécutée
0x80000006 arrêt Envoyé lorsque l'IPC s'arrête car sway se termine
0x80000007 tick Envoyé lorsqu'un client IPC envoie un message SEND_TICK
0x80000014 mise à jour_état_barre Envoyé lorsque la visibilité d'une barre doit changer en raison d'un modificateur
0x80000015 entrée Envoyé lorsque quelque chose lié aux périphériques d'entrée change

change chaîne Le changement qui s'est produit pour la liaison. Actuellement, ce sera uniquement run
command chaîne La commande associée à la liaison
event_state_mask tableau Un tableau de chaînes qui correspondent à chaque touche modificatrice pour la liaison
input_code entier Pour les codes de touche de liaison, il s'agit du code de touche pour la liaison. Pour les liaisons de souris, il s'agit du numéro de bouton X11, s'il en existe un équivalent. Dans tous les autres cas, ce sera 0.
symbol chaîne Pour les liaisons de touches, il s'agit du bindsym pour la liaison. Sinon, ce sera null
input_type chaîne Le type d'entrée qui a déclenché la liaison. Il s'agit soit de keyboard, soit de mouse

Exemple d'événement :

{
	"change": "run",
	"binding": {
		"command": "workspace 2",
		"event_state_mask": [
			"Mod4"
		],
		"input_code": 0,
		"symbol": "2",
		"input_type": "keyboard"
	}
}

0x80000006. ARRÊT

Envoyé chaque fois que l'IPC s'arrête. L'événement est un unique objet avec la propriété change, qui est une chaîne contenant la raison de l'arrêt. Actuellement, la seule valeur pour change est exit, qui est émise lorsque sway se termine.

Exemple d'événement :

{
	"change": "exit"
}

0x80000007. TIC

Envoyé lors du premier abonnement aux événements de tic ou par un message SEND_TICK. L'événement est un unique objet avec les propriétés suivantes :

PROPRIÉTÉ TYPE DE DONNÉES DESCRIPTION
first booléen Indique si cet événement a été déclenché par l'abonnement aux événements de tic
payload chaîne La charge utile fournie avec un message SEND_TICK, le cas échéant. Sinon, une chaîne vide

Exemple d'événement :

{
	"first": true
	"payload": ""
}

0x80000014. MISE_À_JOUR_ÉTAT_BAR

Envoyé lorsque la visibilité d'une barre change en raison de l'appui sur un modificateur. L'événement est un unique objet avec les propriétés suivantes :

PROPRIÉTÉ TYPE DE DONNÉES DESCRIPTION
id chaîne L'ID de la barre concernée
visible_by_modifier booléen Indique si la barre doit être rendue visible en raison de l'appui sur un modificateur

Exemple d'événement :

{
	"id": "bar-0",
	"visible_by_modifier": true
}

0x80000015. ENTRÉE

Envoyé lorsque quelque chose lié aux périphériques d'entrée change. L'événement est un unique objet avec les propriétés suivantes :

PROPRIÉTÉ TYPE DE DONNÉES DESCRIPTION
change chaîne Ce qui a changé
input objet Un objet représentant l'entrée qui est identique à ceux que GET_INPUTS fournit

Les types de changements suivants sont actuellement disponibles :

) une option de configuration libinput pour le périphérique changé
TYPE DESCRIPTION
added Le périphérique d'entrée est devenu disponible
removed Le périphérique d'entrée n'est plus disponible
xkb_keymap (Claviers uniquement) Le keymap du clavier a changé
xkb_layout (Claviers uniquement) La disposition effective dans le keymap a changé
libinput_config (Périphérique libinput uniquement

Exemple d'événement :

{
	"change": "xkb_layout",
	"input": {
		"identifier": "1:1:AT_Translated_Set_2_keyboard",
		"name": "AT Translated Set 2 keyboard",
		"vendor": 1,
		"product": 1,
		"type": "keyboard",
		"xkb_layout_names": [
			"English (US)",
			"English (Dvorak)"
		],
		"xkb_active_layout_index": 1,
		"xkb_active_layout_name": "English (Dvorak)",
		"libinput": {
			"send_events": "enabled"
		}
	}
}
