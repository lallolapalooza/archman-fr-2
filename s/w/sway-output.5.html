NAME

sway-output - output configuration commands for sway

DESCRIPTION

You may combine output commands into one, like so:

output HDMI-A-1 mode 1920x1080 pos 1920 0 bg ~/wallpaper.png stretch

You can get a list of output names with swaymsg -t get_outputs. You may also match any output by using the output name "*". Additionally, "-" can be used to match the focused output by name and "--" can be used to match the focused output by its identifier.

Some outputs may have different names when disconnecting and reconnecting. To identify these, the name can be substituted for a string consisting of the make, model and serial which you can get from swaymsg -t get_outputs. Each value must be separated by one space. For example:

output "Some Company ABC123 0x00000000" pos 1920 0

COMMANDS

output <name> mode|resolution|res [--custom] <width>x<height>[@<rate>Hz]

Configures the specified output to use the given mode. Modes are a combination of width and height (in pixels) and a refresh rate that your display can be configured to use. For a list of available modes for each output, use swaymsg -t get_outputs.

To set a custom mode not listed in the list of available modes, use --custom. You should probably only use this if you know what you're doing.

Examples:

output HDMI-A-1 mode 1920x1080

output HDMI-A-1 mode 1920x1080@60Hz

output <name> modeline <clock> <hdisplay> <hsync_start> <hsync_end> <htotal> <vdisplay> <vsync_start> <vsync_end> <vtotal> <hsync> <vsync>

Configures the specified output to use the given modeline. It can be generated using cvt(1) and gtf(1) commands. See xorg.conf(5). Only supported on DRM backend.

Example:

output HDMI-A-1 modeline 173.00 1920 2048 2248 2576 1080 1083 1088 1120 -hsync +vsync

output <name> position|pos <X> <Y>

Places the specified output at the specific position in the global coordinate space. The cursor may only be moved between immediately adjacent outputs. If scaling is active, it has to be considered when positioning. For example, if the scaling factor for the left output is 2, the relative position for the right output has to be divided by 2. The reference point is the top left corner so if you want the bottoms aligned this has to be considered as well.

Example:

output HDMI1 scale 2

output HDMI1 pos 0 1020 res 3200x1800

output eDP1 pos 1600 0 res 1920x1080

Note that the left x-pos of eDP1 is 1600 = 3200/2 and the bottom y-pos is 1020 + (1800 / 2) = 1920 = 0 + 1920

output <name> scale <factor>

Scales the specified output by the specified scale factor. An integer is recommended, but fractional values are also supported. You may be better served by setting an integer scale factor and adjusting the font size of your applications to taste. HiDPI isn't supported with Xwayland clients (windows will blur). A fractional scale may be slightly adjusted to match requirements of the protocol.

output <name> scale_filter linear|nearest|smart

Indicates how to scale application buffers that are rendered at a scale lower than the output's configured scale, such as lo-dpi applications on hi-dpi screens. Linear is smoother and blurrier, nearest (also known as nearest neighbor) is sharper and blockier. Setting "smart" will apply nearest scaling when the output has an integer scale factor, otherwise linear. The default is "smart".

output <name> subpixel rgb|bgr|vrgb|vbgr|none

Manually sets the subpixel hinting for the specified output. This value is usually auto-detected, but some displays may misreport their subpixel geometry. Using the correct subpixel hinting allows for sharper text. Incorrect values will result in blurrier text. When changing this via swaymsg, some applications may need to be restarted to use the new value.

output <name> background|bg <file> <mode> [<fallback_color>]

Sets the wallpaper for the given output to the specified file, using the given scaling mode (one of "stretch", "fill", "fit", "center", "tile"). If the specified file cannot be accessed or if the image does not fill the entire output, a fallback color may be provided to cover the rest of the output. fallback_color should be specified as #RRGGBB. Alpha is not supported.

output <name> background|bg <color> solid_color

Sets the background of the given output to the specified color. color should be specified as #RRGGBB. Alpha is not supported.

output <name> transform <transform> [clockwise|anticlockwise]

Sets the background transform to the given value. Can be one of "90", "180", "270" for rotation; or "flipped", "flipped-90", "flipped-180", "flipped-270" to apply a rotation and flip, or "normal" to apply no transform. The rotation is performed clockwise. If a single output is chosen and a rotation direction is specified (clockwise or anticlockwise) then the transform is added or subtracted from the current transform (this cannot be used directly in the configuration file).

output <name> disable|enable

Enables or disables the specified output (all outputs are enabled by default).

As opposed to the power command, the output will lose its current workspace and windows.

output <name> toggle

Toggle the specified output.

output <name> power on|off|toggle

Turns on or off the specified output.

As opposed to the enable and disable commands, the output keeps its current workspaces and windows.

output <name> dpms on|off|toggle

Deprecated. Alias for power.

output <name> max_render_time off|<msec>

Controls when sway composites the output, as a positive number of milliseconds before the next display refresh. A smaller number leads to fresher composited frames and lower perceived input latency, but if set too low, sway may not finish compositing in time for display refresh, leading to delayed frames.

When set to off, sway composites immediately after display refresh, maximizing time available for compositing.

To adjust when applications are instructed to render, see max_render_time in sway(5).

To set this up for optimal latency:

1.
Launch some full-screen application that renders continuously, like glxgears.
2.
Start with max_render_time 1. Increment by 1 if you see frame drops.

This setting only has an effect on Wayland and DRM backends, as support for presentation timestamps and predicted output refresh rate is required.

output <name> adaptive_sync on|off|toggle

Enables or disables adaptive synchronization (often referred to as Variable Refresh Rate, or by the vendor-specific names FreeSync/G-Sync).

Adaptive sync allows clients to submit frames a little too late without having to wait a whole refresh period to display it on screen. Enabling adaptive sync can improve latency, but can cause flickering on some hardware.

output <name> render_bit_depth 6|8|10

Controls the maximum color channel bit depth at which frames are rendered; the default is currently 8 bits per channel.

Setting higher values will not have an effect if hardware and software lack support for such bit depths. Successfully increasing the render bit depth will not necessarily increase the bit depth of the frames sent to a display. An increased render bit depth may provide smoother rendering of gradients, and screenshots which can more precisely store the colors of programs which display high bit depth colors.

NOM

sway-output - commandes de configuration de sortie pour sway

DESCRIPTION

Vous pouvez combiner les commandes de sortie en une seule, comme ceci :

output HDMI-A-1 mode 1920x1080 pos 1920 0 bg ~/wallpaper.png stretch

Vous pouvez obtenir une liste des noms de sortie avec swaymsg -t get_outputs. Vous pouvez également faire correspondre n'importe quelle sortie en utilisant le nom de sortie "*". De plus, "-" peut être utilisé pour faire correspondre la sortie focalisée par son nom et "--" peut être utilisé pour faire correspondre la sortie focalisée par son identifiant.

Certaines sorties peuvent avoir des noms différents lors de la déconnexion et de la reconnexion. Pour les identifier, le nom peut être remplacé par une chaîne composée de la marque, du modèle et du numéro de série que vous pouvez obtenir depuis swaymsg -t get_outputs. Chaque valeur doit être séparée par un espace. Par exemple :

output "Some Company ABC123 0x00000000" pos 1920 0

COMMANDES

output <nom> mode|resolution|res [--custom] <largeur>x<hauteur>[@<taux>Hz]

Configure la sortie spécifiée pour utiliser le mode donné. Les modes sont une combinaison de largeur et de hauteur (en pixels) et d'un taux de rafraîchissement auquel votre écran peut être configuré. Pour une liste des modes disponibles pour chaque sortie, utilisez swaymsg -t get_outputs.

Pour définir un mode personnalisé non listé parmi les modes disponibles, utilisez --custom. Vous devriez probablement seulement utiliser cela si vous savez ce que vous faites.

Exemples :

output HDMI-A-1 mode 1920x1080

output HDMI-A-1 mode 1920x1080@60Hz

output <nom> modeline <horloge> <hdisplay> <hsync_start> <hsync_end> <htotal> <vdisplay> <vsync_start> <vsync_end> <vtotal> <hsync> <vsync>

Configure la sortie spécifiée pour utiliser la modeline donnée. Elle peut être générée en utilisant les commandes cvt(1) et gtf(1). Voir xorg.conf(5). Uniquement supporté sur le backend DRM.

Exemple :

output HDMI-A-1 modeline 173.00 1920 2048 2248 2576 1080 1083 1088 1120 -hsync +vsync

output <nom> position|pos <X> <Y>

Place la sortie spécifiée à la position spécifique dans l'espace de coordonnées global. Le curseur ne peut être déplacé qu'entre des sorties immédiatement adjacentes. Si la mise à l'échelle est active, elle doit être prise en compte lors du positionnement. Par exemple, si le facteur d'échelle pour la sortie gauche est de 2, la position relative pour la sortie droite doit être divisée par 2. Le point de référence est le coin supérieur gauche, donc si vous voulez que le bas soit aligné, cela doit également être pris en compte.

Exemple :

output HDMI1 scale 2

output HDMI1 pos 0 1020 res 3200x1800

output eDP1 pos 1600 0 res 1920x1080

Notez que la position x gauche de eDP1 est 1600 = 3200/2 et la position y inférieure est 1020 + (1800 / 2) = 1920 = 0 + 1920

output <nom> scale <facteur>

Met à l'échelle la sortie spécifiée par le facteur d'échelle spécifié. Un entier est recommandé, mais les valeurs fractionnaires sont également prises en charge. Vous pourriez être mieux servi en définissant un facteur d'échelle entier et en ajustant la taille de la police de vos applications selon vos goûts. La HiDPI n'est pas supportée avec les clients Xwayland (les fenêtres seront floues). Une échelle fractionnaire peut être légèrement ajustée pour correspondre aux exigences du protocole.

output <nom> scale_filter linear|nearest|smart

Indique comment mettre à l'échelle les tampons d'application qui sont rendus à une échelle inférieure à l'échelle configurée de la sortie, comme les applications lo-dpi sur les écrans hi-dpi. Linéaire est plus doux et plus flou, le plus proche (également connu sous le nom de voisin le plus proche) est plus net et plus pixellisé. Définir "smart" appliquera la mise à l'échelle la plus proche lorsque la sortie a un facteur d'échelle entier, sinon linéaire. La valeur par défaut est "smart".

output <nom> subpixel rgb|bgr|vrgb|vbgr|none

Définit manuellement le sous-pixel de rendu pour la sortie spécifiée. Cette valeur est généralement auto-détectée, mais certains écrans peuvent mal rapporter leur géométrie de sous-pixel. L'utilisation du bon rendu de sous-pixel permet d'obtenir un texte plus net. Des valeurs incorrectes entraîneront un texte plus flou. Lors du changement via swaymsg, certaines applications peuvent avoir besoin d'être redémarrées pour utiliser la nouvelle valeur.

output <nom> background|bg <fichier> <mode> [<couleur_de_secours>]

Définit le fond d'écran pour la sortie donnée au fichier spécifié, en utilisant le mode de mise à l'échelle donné (l'un de "stretch", "fill", "fit", "center", "tile"). Si le fichier spécifié ne peut pas être accédé ou si l'image ne remplit pas entièrement la sortie, une couleur de secours peut être fournie pour couvrir le reste de la sortie. couleur_de_secours doit être spécifiée comme #RRGGBB. L'alpha n'est pas supporté.

output <nom> background|bg <couleur> solid_color

Définit l'arrière-plan de la sortie donnée à la couleur spécifiée. couleur doit être spécifiée comme #RRGGBB. L'alpha n'est pas supporté.

output <nom> transform <transform> [clockwise|anticlockwise]

Définit la transformation de l'arrière-plan à la valeur donnée. Peut être l'une de "90", "180", "270" pour la rotation ; ou "flipped", "flipped-90", "flipped-180", "flipped-270" pour appliquer une rotation et un retournement, ou "normal" pour ne pas appliquer de transformation. La rotation est effectuée dans le sens des aiguilles d'une montre. Si une seule sortie est choisie et qu'une direction de rotation est spécifiée (clockwise ou anticlockwise), alors la transformation est ajoutée ou soustraite de la transformation actuelle (cela ne peut pas être utilisé directement dans le fichier de configuration).

output <nom> disable|enable

Active ou désactive la sortie spécifiée (toutes les sorties sont activées par défaut).

Contrairement à la commande power, la sortie perdra son espace de travail et ses fenêtres actuels.

output <nom> toggle

Inverse l'état de la sortie spécifiée.

output <nom> power on|off|toggle

Allume ou éteint la sortie spécifiée.

Contrairement aux commandes enable et disable, la sortie conserve ses espaces de travail et ses fenêtres actuels.

output <nom> dpms on|off|toggle

Obsolète. Alias de power.

output <nom> max_render_time off|<msec>

Contrôle quand sway compose la sortie, comme un nombre positif de millisecondes avant le prochain rafraîchissement de l'écran. Un nombre plus petit entraîne des images composées plus fraîches et une latence d'entrée perçue plus faible, mais s'il est réglé trop bas, sway peut ne pas terminer la composition à temps pour le rafraîchissement de l'écran, entraînant des images retardées.

Lorsqu'il est réglé sur off, sway compose immédiatement après le rafraîchissement de l'écran, maximisant le temps disponible pour la composition.

Pour ajuster le moment où les applications sont invitées à rendre, voir max_render_time dans sway(5).

Pour configurer cela pour une latence optimale :

1.
Lancez une application en plein écran qui rend en continu, comme glxgears.
2.
Commencez avec max_render_time 1. Augmentez par 1 si vous voyez des pertes d'images.

Ce paramètre n'a d'effet que sur les backends Wayland et DRM, car la prise en charge des horodatages de présentation et du taux de rafraîchissement prévu de la sortie est requise.

output <nom> adaptive_sync on|off|toggle

Active ou désactive la synchronisation adaptative (souvent appelée Taux de rafraîchissement variable, ou par les noms spécifiques aux vendeurs FreeSync/G-Sync).

La synchronisation adaptative permet aux clients de soumettre des images un peu trop tard sans avoir à attendre une période de rafraîchissement complète pour l'afficher à l'écran. L'activation de la synchronisation adaptative peut améliorer la latence, mais peut provoquer un scintillement sur certains matériels.

output <nom> render_bit_depth 6|8|10

Contrôle la profondeur de bits maximale par canal de couleur à laquelle les images sont rendues ; la valeur par défaut est actuellement de 8 bits par canal.

L'augmentation des valeurs n'aura pas d'effet si le matériel et le logiciel ne supportent pas de telles profondeurs de bits. L'augmentation réussie de la profondeur de bits de rendu n'augmentera pas nécessairement la profondeur de bits des images envoyées à un écran. Une profondeur de bits de rendu accrue peut fournir un rendu plus fluide des dégradés, et des captures d'écran qui peuvent stocker plus précisément les couleurs des programmes qui affichent des couleurs en haute profondeur de bits.

Avertissements : ceci

peut casser les programmes de capture d'écran/d'enregistrement d'écran qui n'ont pas été mis à jour pour fonctionner avec différentes profondeurs de bits. Cette commande est expérimentale et peut être supprimée ou modifiée à l'avenir.

output <name> color_profile srgb|[icc <file>]

Définit le profil de couleur pour une sortie. La valeur par défaut est srgb. <file> doit être un chemin d'accès à un profil ICC d'affichage.

Tous les moteurs de rendu ne prennent pas en charge cette fonctionnalité ; actuellement, elle ne fonctionne qu'avec le moteur de rendu Vulkan. Même lorsqu'elle est prise en charge, l'application du profil de couleur peut être inexacte.

Cette commande est expérimentale et peut être supprimée ou modifiée à l'avenir. Elle peut n'avoir aucun effet ou produire des résultats inattendus lorsqu'elle est utilisée avec de futures fonctionnalités de prise en charge HDR.

output <name> allow_tearing yes|no

Autorise ou refuse le déchirement d'écran (screen tearing) résultant de changements de page immédiats et d'un mode de présentation immédiat d'un client. La valeur par défaut est que le déchirement d'écran n'est pas autorisé.

Avec les changements de page immédiats, les images du client sont présentées dès que possible au lieu d'être synchronisées avec l'intervalle de rafraîchissement vertical (VSync) du moniteur.

Il est recommandé de régler max_render_time sur off. Dans ce cas, un changement de page se produit dès qu'un client est mis à jour. Sinon, le déchirement ne se produira que si le rendu prend plus de temps que les millisecondes configurées avant le prochain rafraîchissement de l'écran.

Pour ajuster si le déchirement est autorisé pour des applications spécifiques, consultez allow_tearing dans sway(5). Notez que le déchirement ne sera activé que s'il est autorisé à la fois pour la sortie et pour l'application.

Ce paramètre n'a d'effet que lorsqu'une fenêtre est en plein écran sur la sortie.
