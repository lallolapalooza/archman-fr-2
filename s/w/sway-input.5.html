NOM

sway-input - Fichier de configuration et commandes d'entrée

DESCRIPTION

Sway permet la configuration des périphériques dans le fichier de configuration de sway. Pour obtenir une liste des identifiants de périphériques disponibles, exécutez swaymsg -t get_inputs. Les paramètres peuvent également être appliqués à tous les périphériques d'entrée en utilisant le caractère générique, *, à la place de <identifiant> dans les commandes ci-dessous. De plus, les paramètres peuvent être appliqués à un type de périphérique, en utilisant type:<type_entrée> à la place de <identifiant>.

Dans le fichier de configuration, les paramètres avec un sélecteur plus spécifique ont priorité sur ceux plus généraux : <identifiant> > type:<type_entrée> > *. Lors de l'exécution des commandes d'entrée, cependant, les paramètres sont appliqués à tous les périphériques d'entrée correspondants ! Cela signifie que type:<type_entrée> peut outrepasser les paramètres <identifiant> définis précédemment, même si dans un fichier de configuration, ils auraient priorité. De même, * peut outrepasser les paramètres <identifiant> et type:<type_entrée>, s'il est appliqué plus tard.

Astuce : Si les paramètres de configuration ne semblent pas prendre effet, vous pouvez essayer d'utiliser * à la place de <identifiant>. Si cela fonctionne avec le caractère générique, essayez d'utiliser un identifiant différent de swaymsg -t get_inputs jusqu'à trouver le bon périphérique d'entrée.

Les types d'entrée actuellement disponibles sont :

  • touchpad
  • pointer
  • keyboard
  • touch
  • tablet_tool
  • tablet_pad
  • switch

Note : Les configurations de type sont appliquées au fur et à mesure que les périphériques apparaissent et sont appliquées par-dessus les configurations de périphériques existantes.

COMMANDES ENTRÉE

CONFIGURATION CLAVIER

input <identifiant> repeat_delay <millisecondes>

Définit le temps pendant lequel une touche doit être maintenue enfoncée avant de commencer à se répéter.

input <identifiant> repeat_rate <caractères par seconde>

Définit la fréquence des répétitions de touches une fois le délai de répétition écoulé.

Pour plus d'informations sur ces options de configuration xkb, voir xkeyboard-config(7).

input <identifiant> xkb_file <nom_fichier>

Définit toutes les configurations xkb à partir d'un fichier .xkb complet. Ce fichier peut être extrait avec xkbcomp $DISPLAY keymap.xkb. Ce paramètre remplace les paramètres xkb_layout, xkb_model, xkb_options, xkb_rules et xkb_variant.

input <identifiant> xkb_layout <nom_disposition>

Définit la disposition du clavier comme us ou de.

Plusieurs dispositions peuvent être spécifiées en les séparant par des virgules.

input <identifiant> xkb_model <nom_modèle>

Définit le modèle du clavier. Cela a une influence sur certaines touches supplémentaires que votre clavier pourrait avoir.

input <identifiant> xkb_options <options>

Définit des options de configuration xkb supplémentaires pour le clavier.

Plusieurs options peuvent être spécifiées en les séparant par des virgules.

input <identifiant> xkb_rules <règles>

Définit les fichiers de règles à utiliser pour la composition du mappage du clavier.

input <identifiant> xkb_switch_layout <index>|suivant|précédent

Change la disposition active du clavier vers l'<index> en partant de zéro ou vers la disposition suivante ou précédente dans la liste. S'il n'y a pas de disposition suivante ou précédente, cette commande saute à l'autre extrémité de la liste.

Ceci peut être utilisé lorsque plusieurs dispositions sont configurées avec xkb_layout. Une liste des dispositions entre lesquelles vous pouvez basculer peut être obtenue avec swaymsg -t get_inputs.

input <identifiant> xkb_variant <variante>

Définit la variante du clavier comme dvorak ou colemak.

Les commandes suivantes ne peuvent être utilisées que dans le fichier de configuration.

input <identifiant> xkb_capslock activé|désactivé

Active ou désactive initialement CapsLock au démarrage, par défaut c'est désactivé.

input <identifiant> xkb_numlock activé|désactivé

Active ou désactive initialement NumLock au démarrage, par défaut c'est désactivé.

CONFIGURATION TABLETTE

input <identifiant> tool_mode <outil> <absolu|relatif>

Définit si le déplacement d'un outil de tablette doit être traité comme absolu ou relatif ; par défaut, c'est absolu.

Les valeurs valides pour <outil> sont actuellement "pen", "eraser", "brush", "pencil", "airbrush", et le caractère générique *, qui correspond à tous les outils.

Les souris et les outils de lentille ignorent ce paramètre et sont toujours traités comme relatifs.

CONFIGURATION MAppage

input <identifiant> map_to_output <identifiant>

Mappe les entrées de ce périphérique vers la sortie spécifiée. Uniquement pertinent si le périphérique est un pointeur, un tactile ou une tablette graphique.

Le caractère générique * peut être utilisé pour mapper le périphérique d'entrée à l'ensemble de la disposition du bureau.

input <identifiant> map_to_region <X> <Y> <largeur> <hauteur>

Mappe les entrées de ce périphérique vers la région spécifiée de la disposition globale des sorties. Uniquement pertinent si le périphérique est un pointeur, un tactile ou une tablette graphique.

input <identifiant> map_from_region <X1xY1> <X2xY2>

Ignore les entrées de ce périphérique qui ne se produisent pas dans la région spécifiée. Peut être en millimètres (par exemple, 10x20mm 20x40mm) ou en fraction de l'espace total disponible en termes de 0..1 (par exemple, 0.5x0.5 0.7x0.7). Tous les périphériques ne prennent pas en charge les millimètres. Uniquement pertinent si le périphérique n'est pas un clavier et fournit des événements de manière absolue (comme une tablette graphique ou un écran tactile - la plupart des pointeurs fournissent des événements relatifs à la trame précédente).

Couramment utilisé pour maintenir le rapport d'aspect du périphérique d'entrée et de l'écran. Rogner une région d'entrée 16:10 pour correspondre à un écran 16:9 peut utiliser 0x0 1x0.9 comme argument.

CONFIGURATION LIBINPUT

input <identifiant> accel_profile adaptatif|plat

Définit le profil d'accélération du pointeur pour le périphérique d'entrée spécifié.

input <identifiant> calibration_matrix <6 valeurs à virgule flottante séparées par des espaces>

Définit la matrice de calibration.

input <identifiant> click_method aucun|zones_clic|doigt_clic

Change la méthode de clic pour le périphérique spécifié.

input <identifiant> clickfinger_button_map gmd|mdg

Spécifie quelle cartographie de boutons utiliser pour clickfinger. gmd traite 1 doigt comme un clic gauche, 2 doigts comme un clic droit et 3 doigts comme un clic du milieu. mdg traite 1 doigt comme un clic gauche, 2 doigts comme un clic du milieu et 3 doigts comme un clic droit.

input <identifiant> drag activé|désactivé

Active ou désactive le tap-and-drag pour le périphérique d'entrée spécifié.

input <identifiant> drag_lock activé|désactivé|activé_collant

Active ou désactive le verrouillage du glisser-déposer pour le périphérique d'entrée spécifié. Par défaut, c'est activé_collant.

input <identifiant> dwt activé|désactivé

Active ou désactive la désactivation pendant la frappe pour le périphérique d'entrée spécifié.

input <identifiant> dwtp activé|désactivé

Active ou désactive la désactivation pendant le trackpointing pour le périphérique d'entrée spécifié.

input <identifiant> events activé|désactivé|désactivé_sur_souris_externe|basculer [<modes_bascule>]

Active ou désactive send_events pour le périphérique d'entrée spécifié. La désactivation de send_events désactive le périphérique d'entrée.

L'option basculer ne peut pas être utilisée dans la configuration. Si aucun mode de bascule n'est spécifié, tous les modes pris en charge pour le périphérique seront parcourus dans l'ordre : activé, désactivé_sur_souris_exter

NOM

sway-input – configuration pour les périphériques d'entrée

DESCRIPTION

La configuration de sway vous permet de configurer les périphériques d'entrée en utilisant la commande input. Les options disponibles dépendent du pilote utilisé. Le pilote par défaut est libinput.

COMMANDES D'ENTRÉE

Configurez les options pour les périphériques d'entrée.

Un périphérique d'entrée est identifié par son nom, comme indiqué par swaymsg -t get_inputs. Les caractères génériques (*) peuvent être utilisés pour changer les paramètres de plusieurs périphériques.

input <identificateur> accel_speed <valeur flottante>

Définit la vitesse d'accélération du pointeur pour le périphérique d'entrée spécifié. Les valeurs allant de -1 à 1.

input <identificateur> calibration_matrix <matrice>

Définit la matrice de calibration pour le périphérique d'entrée spécifié. La matrice doit être une liste de 6 nombres flottants séparés par des virgules.

input <identificateur> click_method double_pixel|button

Définit la méthode de clic pour le périphérique d'entrée spécifié.

input <identificateur> drag_lock enabled|disabled

Active ou désactive le verrouillage du glisser-déposer pour le périphérique d'entrée spécifié.

input <identificateur> drag_threshold <distance>

Définit le seuil de glisser-déposer pour le périphérique d'entrée spécifié en pixels.

input <identificateur> left_handed enabled|disabled

Active ou désactive le mode gaucher pour le périphérique d'entrée spécifié.

input <identificateur> middle_emulation enabled|disabled

Active ou désactive l'émulation du clic du milieu.

input <identificateur> natural_scroll enabled|disabled

Active ou désactive le défilement naturel (inversé) pour le périphérique d'entrée spécifié.

input <identificateur> pointer_accel [<-1|1>]

Modifie l'accélération du pointeur pour le périphérique d'entrée spécifié.

input <identificateur> rotation_angle <angle>

Définit l'angle de rotation du périphérique à l'angle donné en degrés dans le sens des aiguilles d'une montre. L'angle doit être compris entre 0.0 (inclus) et 360.0 (exclus).

input <identificateur> scroll_button disable|button[1-3,8,9]|<code d'événement ou nom>

Définit le bouton utilisé pour scroll_method on_button_down. Le bouton peut être donné sous forme de nom d'événement ou de code, qui peut être obtenu à partir des événements de débogage de libinput, ou sous forme de bouton de souris x11 (button[1-3,8,9]). S'il est réglé sur disable, il désactive la méthode de défilement on_button_down.

input <identificateur> scroll_button_lock enabled|disabled

Active ou désactive le verrouillage du bouton de défilement pour le périphérique d'entrée spécifié.

input <identificateur> scroll_factor <valeur flottante>

Modifie le facteur de défilement pour le périphérique d'entrée spécifié. La vitesse de défilement sera mise à l'échelle par la valeur donnée, qui doit être non négative.

input <identificateur> scroll_method none|two_finger|edge|on_button_down

Modifie la méthode de défilement pour le périphérique d'entrée spécifié.

input <identificateur> tap enabled|disabled

Active ou désactive le tap pour le périphérique d'entrée spécifié.

input <identificateur> tap_button_map lrm|lmr

Spécifie la combinaison de boutons à utiliser pour le tap. lrm traite 1 doigt comme un clic gauche, 2 doigts comme un clic droit et 3 doigts comme un clic du milieu. lmr traite 1 doigt comme un clic gauche, 2 doigts comme un clic du milieu et 3 doigts comme un clic droit.

CONFIGURATION DES SIEGES

Configure les options pour le mode multisiège.

Un siège est une collection de périphériques d'entrée qui agissent indépendamment les uns des autres. Les sièges sont identifiés par un nom et le siège par défaut est seat0 si aucun siège n'est configuré. Pendant que sway est en cours d'exécution, - (tiret) peut être utilisé comme alias pour le siège actuel. Chaque siège a un focus clavier indépendant et un curseur séparé qui est contrôlé par les périphériques pointeur du siège. Ceci est utile pour plusieurs personnes utilisant le bureau en même temps avec leurs propres appareils (chacun assis dans son propre «siège»). Le caractère générique, *, peut également être utilisé à la place de <identificateur> pour modifier les paramètres de tous les sièges.

Astuce : Si les paramètres de configuration ne semblent pas prendre effet, vous pouvez essayer d'utiliser * au lieu de <identificateur>. S'il fonctionne avec le caractère générique, essayez d'utiliser un identificateur différent de swaymsg -t get_seats jusqu'à ce que vous trouviez le siège correct.

seat <nom> attach <identificateur d'entrée>

Attache un périphérique d'entrée à ce siège par son identificateur d'entrée. Une valeur spéciale de « * » attachera tous les périphériques au siège.

seat <siège> cursor move|set <x> <y>

Déplace le curseur du siège spécifié par rapport à la position actuelle ou en coordonnées absolues (par rapport à l'espace de coordonnées global). Spécifier l'une ou l'autre valeur comme 0 ne mettra pas à jour cette coordonnée.

Obsolète : utilisez le protocole Wayland de pointeur virtuel à la place.

seat <siège> cursor press|release button[1-9]|<nom ou code d'événement>

Simule l'appui (ou le relâchement) du bouton de souris spécifié sur le siège spécifié. Le bouton peut être fourni sous forme de nom d'événement de bouton ou de code d'événement, qui peut être obtenu à partir de libinput debug-events, ou sous forme de bouton de souris x11 (button[1-9]). Si vous utilisez button[4-7], qui correspondent aux axes, un événement d'axe sera simulé, cependant press et release seront ignorés et les deux se produiront.

Obsolète : utilisez le protocole Wayland de pointeur virtuel à la place.

seat <nom> fallback true|false

Définit ce siège comme siège de repli. Un siège de repli attachera tout périphérique non explicitement attaché à un autre siège (similaire à un siège « par défaut »).

seat <nom> hide_cursor <délai>|when-typing [enable|disable]

Masque l'image du curseur après que l'événement spécifié s'est produit.

Si délai est spécifié, alors le curseur sera masqué après que délai (en millisecondes) se soit écoulé sans activité sur le curseur. Un délai de 0 (par défaut) désactive le masquage du curseur. Le délai minimum est de 100 et toute valeur inférieure (à part 0) sera augmentée à 100.

Si when-typing est activé, alors le curseur sera masqué chaque fois qu'une touche sera pressée.

Soyez conscient que ce paramètre peut interférer avec la gestion des entrées dans les jeux et certains types de logiciels (Gimp, Blender, etc.) qui dépendent des entrées simultanées du clavier et de la souris.

seat <nom> idle_inhibit <sources...>

Définit l'ensemble des sources d'événements d'entrée qui peuvent empêcher le siège de devenir inactif, sous forme d'une liste de noms de sources séparés par des espaces. Les noms valides sont « keyboard », « pointer », « touchpad », « touch », « tablet_pad », « tablet_tool » et « switch ». Le comportement par défaut est d'empêcher l'inactivité sur tout événement.

seat <nom> keyboard_grouping none|smart

Définit comment les claviers du siège sont regroupés. Actuellement, il existe deux options. none désactivera tout regroupement de clavier. Cela signifie que chaque périphérique clavier aura son propre état isolé. smart regroupera les claviers du siège par leur mappe de touches et leurs informations de répétition. Ceci est utile lorsque le clavier apparaît comme plusieurs périphériques d'entrée distincts. Dans ce mode, la disposition effective est synchronisée entre les claviers du groupe. La valeur par défaut est smart. Pour restaurer le comportement des anciennes versions de sway, utilisez none.

seat <nom> pointer_constraint enable|disable|escape

Active ou désactive la capacité des clients à capturer le curseur (activée par défaut) pour le siège. Ceci est principalement utile pour les jeux vidéo. La commande « escape » peut être utilisée à l'exécution pour échapper à un client capturé.

seat <nom> shortcuts_inhibitor enable|disable|activate|deactivate|toggle

Active ou désactive la capacité des clients à inhiber les raccourcis clavier pour le siège. Ceci est principalement utile pour les logiciels de virtualisation et de bureau à distance. Les sous-commandes enable et disable affectent si les inhibiteurs futurs seront honorés par défaut, c'est-à-dire activés automatiquement, la valeur par défaut étant enable. Lorsqu'utilisé à l'exécution, disable désactive également tous les inhibiteurs actuellement actifs. activate, deactivate et toggle ne peuvent être utilisés qu'à l'exécution et modifient l'état d'un inhibiteur potentiellement existant sur la fenêtre actuellement focalisée. Ceci peut être utilisé avec l'alias de siège actuel (-) pour affecter uniquement la fenêtre actuellement focalisée du siège actuel. La sous-commande deactivate est particulièrement utile dans un bindsym --inhibited pour échapper à un état où les raccourcis sont inhibés et que le client devient non coopératif. Il est intéressant de noter que la suppression des inhibiteurs désactivés ou désactivés dépend entièrement du client. Selon le client, il peut donc être possible de les réactiver plus tard. Toute indication visuelle qu'un inhibiteur est présent est actuellement laissée au client.

seat <nom> xcursor_theme <thème> [<taille>]

Remplace le thème par défaut du système XCursor. Le thème du siège par défaut (seat0) est également utilisé comme thème de curseur par défaut dans XWayland, et exporté via les variables d'environnement XCURSOR_THEME et XCURSOR_SIZE.
