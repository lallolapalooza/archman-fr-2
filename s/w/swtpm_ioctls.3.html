NOM

swtpm_ioctls - Description des ioctl du TPM CUSE (swtpm_cuse) et des commandes de contrôle utilisées par le canal de contrôle via l'interface socket.

SYNTAXE

#include <tpm_ioctl.h>

DESCRIPTION

Le TPM CUSE implémente une interface ioctl sur le périphérique caractère du TPM CUSE. Les ioctl sont utilisées pour le contrôle hors bande de diverses opérations du TPM, telles que son initialisation, sa réinitialisation et la migration d'état. Le canal de contrôle via les sockets TCP ou UnixIO utilise des commandes de contrôle pour ces opérations.

Ce qui suit est une énumération des ioctl et des commandes de contrôle prises en charge, ainsi que les noms des types de structures de données. Toutes les ioctl et commandes de contrôle renvoient un code d'erreur TPM dans leur réponse. Les ioctl sont préfixées par PTM et les commandes de contrôle sont préfixées par CMD.

Dans le cas de l'interface ioctl, le pointeur vers la structure de données d'une commande est passé comme 2ème paramètre à la fonction ioctl(). Les champs de la structure de données de la commande doivent être remplis au format endianness hôte.

Dans le cas des commandes de contrôle, le code de commande doit être codé sous forme d'entier de 4 octets précédant la structure de données de la commande. Le code de commande et les données doivent être écrits au format big endian.

PTM_GET_CAPABILITY / CMD_GET_CAPABILITY, ptm_cap
Cette ioctl permet à l'appelant de vérifier quelles ioctl sont implémentées par le TPM CUSE. Voici une liste des indicateurs de capacité qui peuvent être définis au retour :
PTM_CAP_INIT (depuis v0.1)
L'ioctl PTM_INIT ou la commande CMD_INIT est prise en charge.
PTM_CAP_SHUTDOWN (depuis v0.1)
L'ioctl PTM_SHUTDOWN ou la commande CMD_SHUTDOWN est prise en charge.
PTM_CAP_GET_TPMESTABLISHED (depuis v0.1)
L'ioctl PTM_GET_TPMESTABLISHED ou la commande CMD_GET_TPMESTABLISHED est prise en charge.
PTM_CAP_SET_LOCALITY (depuis v0.1)
L'ioctl PTM_SET_LOCALITY ou la commande CMD_SET_LOCALITY est prise en charge.
PTM_CAP_HASHING (depuis v0.1)
Les ioctl PTM_HASH_START, PTM_HASH_DATA et PTM_HASH_END ou les commandes CMD_HASH_START, CMD_HASH_DATA, CMD_HASH_END sont prises en charge.
PTM_CAP_CANCEL_TPM_CMD (depuis v0.1)
L'ioctl PTM_CANCEL_TPM_CMD ou la commande CMD_CANCEL_TPM_CMD est prise en charge.
PTM_CAP_STORE_VOLATILE (depuis v0.1)
L'ioctl PTM_STORE_VOLATILE ou la commande CMD_STORE_VOLATILE est prise en charge.
PTM_CAP_RESET_TPMESTABLISHED (depuis v0.1)
L'ioctl PTM_RESET_TPMESTABLISHED ou la commande CMD_RESET_TPMESTABLISHED est prise en charge.
PTM_CAP_GET_STATEBLOB (depuis v0.1)
L'ioctl PTM_GET_STATEBLOB ou la commande CMD_GET_STATEBLOB est prise en charge.
PTM_CAP_SET_STATEBLOB (depuis v0.1)
L'ioctl PTM_SET_STATEBLOB ou la commande CMD_SET_STATEBLOB est prise en charge.
PTM_CAP_STOP (depuis v0.1)
L'ioctl PTM_STOP ou la commande CMD_STOP est prise en charge.
PTM_CAP_GET_CONFIG (depuis v0.1)
L'ioctl PTM_GET_CONFIG ou la commande CMD_GET_CONFIG est prise en charge.
PTM_CAP_SET_DATAFD (depuis v0.1)
La commande CMD_SET_DATAFD est prise en charge. Cette commande s'applique uniquement à UnixIO et il n'y a pas de prise en charge pour PTM_SET_DATAFD.
PTM_CAP_SET_BUFFERSIZE (depuis v0.1)
L'ioctl PTM_SET_BUFFERSIZE ou la commande CMD_SET_BUFFERSIZE est prise en charge.
PTM_CAP_LOCK_STORAGE (depuis v0.8)
L'ioctl PTM_LOCK_STORAGE ou la commande CMD_LOCK_STORAGE est prise en charge.
PTM_GET_CAPABILITY / CMD_GET_CAPABILITY, ptm_cap_n
La structure de données ptm_cap_n peut être utilisée pour swtpm non-CUSE et se présente comme suit : 
struct ptm_cap_n {
   union {
      struct {
          ptm_res tpm_result; /* sera toujours TPM_SUCCESS (0) */
          uint32_t caps;
      } resp; /* réponse */
   } u;
};
PTM_INIT / CMD_INIT, ptm_init
Cette ioctl doit être utilisée pour initialiser le TPM. Elle doit être envoyée au TPM avant l'envoi de toute commande TPM.

La structure de données ptm_init se présente comme suit :

struct ptm_init {
   union {
       struct {
           uint32_t init_flags; /* voir les définitions ci-dessous */
       } req; /* requête */
       struct {
           ptm_res tpm_result;
       } resp; /* réponse */
   } u;
};

Le champ init_flags dans la requête peut être utilisé pour faire supprimer l'état volatil au démarrage par le TPM (PTM_INIT_FLAG_DELETE_VOLATILE).

Un code de résultat TPM est renvoyé dans le champ tpm_result.

PTM_SHUTDOWN / CMD_SHUTDOWN, ptm_res
Cette ioctl permet à un utilisateur de désactiver le TPM.

Un code de résultat TPM est renvoyé dans ptm_res.

PTM_GET_TPMESTABLISHED / CMD_GET_TPMESTABLISHED, ptm_est
Cette ioctl est utilisée pour vérifier si le drapeau d'établissement du TPM est défini.

La structure de données tpm_est se présente comme suit :

struct ptm_est {
   union {
       struct {
           ptm_res tpm_result;
           unsigned char bit; /* bit d'établissement TPM */
       } resp; /* réponse */
   } u;
};

Un code de résultat TPM est renvoyé dans le champ tpm_result.

L'état du drapeau d'établissement du TPM est renvoyé dans le champ bit.

PTM_SET_LOCALITY / CMD_SET_LOCALITY, ptm_loc
Cette ioctl est utilisée pour définir la localité actuelle. Toutes les commandes ultérieures seront exécutées dans cette localité jusqu'à ce que la localité soit modifiée.

La structure de données ptm_loc se présente comme suit :

struct ptm_loc {
   union {
       struct {
           uint8_t loc; /* localité à définir */
       } req; /* requête */
       struct {
           ptm_res tpm_result;
       } resp; /* réponse */
   } u;
};

Le numéro de localité doit être défini dans le champ loc de la requête. Les localités valides sont comprises entre 0 et 4.

Un code de résultat TPM est renvoyé dans le champ tpm_result.

PTM_HASH_START / CMD_HASH_START, ptm_res
Cette ioctl est utilisée pour démarrer l'opération de hachage qui est généralement initiée en écrivant dans certains registres de la localité 4 de l'interface TPM (TPM TIS). Les opérations d'écriture ultérieures pour transférer des données doivent être effectuées avec l'ioctl PTM_HASH_DATA.

Un code de résultat TPM est renvoyé dans ptm_res.

PTM_HASH_DATA / CMD_HASH_DATA, ptm_hdata
Cette commande est utilisée pour transférer les données de l'opération de hachage.

La structure ptm_hdata se présente comme suit :

struct ptm_hdata {
   union {
       struct {
           uint32_t length;
           uint8_t data[4096];
       } req; /* requête */
       struct {
           ptm_res tpm_result;
       } resp; /* réponse */
   } u;
};

La longueur des données est indiquée dans le champ length, les données se trouvant dans le champ data. Jusqu'à 4096 octets peuvent être transférés par appel.

Un code de résultat TPM est renvoyé dans le champ tpm_result.

PTM_HASH_END / CMD_HASH_END, ptm_res
