NOM

swtpm_ioctl - Utilitaire pour envoyer des commandes de contrôle à swtpm

SYNTAXE

swtpm_ioctl [COMMANDE] [<périphérique>]

DESCRIPTION

swtpm_ioctl implémente un outil client pour contrôler les émulateurs logiciels TPM swtpm_cuse et swtpm, tels que leur initialisation et leur arrêt. Une fois initialisés, des commandes TPM peuvent leur être envoyées.

Note : La variable d'environnement SWTPM_IOCTL_BUFFERSIZE peut être définie à la taille du tampon pour le transfert de blobs d'état à utiliser. Si elle n'est pas définie, l'interface ioctl() est utilisée pour transférer l'état. Cette variable d'environnement est principalement utilisée à des fins de test.

Les commandes suivantes sont prises en charge :

--tpm-device <périphérique>
Utiliser le périphérique donné. Le chemin complet du périphérique caractère doit être fourni, par exemple /dev/vtpm-200.

Cette option peut être utilisée à la place de fournir le périphérique comme dernier paramètre.

--tcp <serveur>:<port>
Se connecter au serveur et au port donnés ; si aucun serveur n'est donné, 127.0.0.1 est utilisé ; si le port n'est pas donné, le port par défaut 6545 est utilisé.
--unix <chemin>
Se connecter au chemin UnixIO donné.
-c
Obtenir les indicateurs de capacité indiquant quelles commandes sont prises en charge.
-i
Envoyer un signal d'initialisation matérielle à swtpm_cuse/swtpm. L'état volatile précédemment écrit par le TPM sera lu et le fichier sera automatiquement supprimé.
-s
Initier un arrêt progressif.
--stop
Arrêter swtpm_cuse/swtpm. Cela ne l'arrête pas. La commande -i peut à nouveau lui être envoyée. Après un arrêt, il est également possible de charger des blobs d'état TPM dans le TPM en utilisant la commande --load.
-e
Obtenir le bit tpmEstablished.
-r locality
Réinitialiser le bit tpmEstablished en utilisant la localité donnée. Seules les localités 3 et 4 fonctionnent. Cette opération ne modifiera pas de manière permanente la localité qui avait été précédemment définie à l'aide de l'option -l.
-l locality
Définir la localité pour les commandes TPM ultérieures.
-v
Demander au TPM d'écrire l'état volatil dans un fichier. Lors d'un TPM_Init (-i), l'état du TPM sera lu et le TPM pourra alors reprendre son fonctionnement sans initialisation supplémentaire.
-C
Annuler une commande TPM en cours.
-h data
Réinitialiser et étendre le PCR 17 avec le hachage des données données. Si data est le caractère unique '-', alors toutes les données sont lues depuis stdin.
--save <nom du blob d'état TPM > <nom de fichier>
Sauvegarder le blob d'état TPM dans le fichier donné. Les noms de blobs d'état TPM valides sont 'permanent', 'volatile', et 'savestate'.

Notez que cette commande peut être exécutée à tout moment. Cependant, pour récupérer l'état volatil le plus récent, la commande -v doit avoir été exécutée immédiatement avant d'exécuter cette commande. Le blob savestate ne sera renvoyé que si une commande TPM_SaveState a été exécutée dans le TPM (TPM 1.2).

--load <nom du blob d'état TPM > <nom de fichier>
Charger le blob d'état TPM donné depuis le fichier donné. Les noms de blobs d'état TPM valides sont 'permanent', 'volatile', et 'savestate'.

Notez que cette commande ne peut être exécutée que sur un TPM qui est arrêté. Pour ensuite démarrer le TPM avec l'état téléchargé, la commande -i doit être émise.

-g
Obtenir les indicateurs de configuration qui indiquent, par exemple, quelles clés (de chiffrement de fichier ou de migration) sont utilisées par le TPM.
--info <indicateurs>
Obtenir des informations sur l'implémentation du TPM et sa configuration au format JSON. Les valeurs suivantes peuvent être fournies. Toutes les valeurs peuvent être combinées par OU (ou ajoutées) pour obtenir des informations sur toutes en une seule requête.
  • 0x1 : informations sur la spécification suivie par l'implémentation du TPM
  • 0x2 : informations sur le fabricant, le modèle et la version du TPM
  • 0x4 : liste les tailles de clés RSA et Camellia prises en charge
  • 0x8 : décrit les algorithmes pris en charge et activés
  • 0x10 : décrit les commandes prises en charge et activées
  • 0x20 : décrit le profil actif
  • 0x40 : liste tous les profils intégrés
  • 0x80 : décrit les attributs pris en charge
--lock-storage <réessais>
Verrouiller le stockage et réessayer un nombre donné de fois avec un délai de 10 ms entre chaque tentative. Il peut être nécessaire de verrouiller le stockage après que l'état du TPM a été migré et que le verrouillage du stockage a été libéré lors de la réception du blob 'savestate', et que le stockage doit maintenant être verrouillé à nouveau.

EXEMPLE

Démarrer swtpm sur le port 10000 pour le port de contrôle et émuler un TPM 1.2 :

#> swtpm socket --tpmstate dir=/tmp/myvtpm1 --log level=4 --ctrl type=tcp,port=10000 --server type=tcp,port=10001 --flags not-need-init

Obtenir des informations sur l'implémentation du TPM en JSON :

#> swtpm_ioctl --tcp :10000 --info 1
{"TPMSpecification":{"family":"1.2","level":2,"revision":116}}
#> swtpm_ioctl --tcp :10000 --info 2
{"TPMAttributes":{"manufacturer":"id:00001014","version":"id:00740001","model":"swtpm"}}

Arrêter le swtpm

#> swtpm_ioctl --tcp :10000 -s
