sway-bar(5) Manuel des formats de fichiers sway-bar(5)

NOM

sway-bar - fichier de configuration et commandes de la barre

DESCRIPTION

Sway permet de configurer swaybar dans le fichier de configuration de sway.

COMMANDES

Les commandes suivantes ne peuvent être utilisées que dans le fichier de configuration.

id <id_barre>

Définit l'identifiant de la barre.

swaybar_command <commande>

Exécute une commande de barre personnalisée. Par défaut, il s'agit de swaybar.

Les commandes suivantes peuvent être utilisées dans le fichier de configuration ou à l'exécution.

bindcode [--release] <code_événement> <commande>

Exécute commande lorsque le bouton de la souris a été pressé (ou si release est donné, lorsque le bouton a été relâché). Les boutons peuvent être donnés sous forme de code d'événement, qui peut être obtenu à partir de libinput debug-events. Pour désactiver le comportement par défaut d'un bouton, utilisez la commande nop.

bindsym [--release] button[1-9]|<nom_événement> <commande>

Exécute commande lorsque le bouton de la souris a été pressé (ou si release est donné, lorsque le bouton a été relâché). Les boutons peuvent être donnés sous forme de numéro de bouton x11 ou de nom d'événement, qui peut être obtenu à partir de libinput debug-events. Pour désactiver le comportement par défaut d'un bouton, utilisez la commande nop.

binding_mode_indicator yes|no

Active ou désactive l'indicateur de mode de liaison. Par défaut, il est activé (yes).

font <police>

Spécifie la police à utiliser dans la barre. police doit être spécifiée comme une description de police pango. Pour plus d'informations sur les descriptions de polices pango, consultez https://docs.gtk.org/Pango/type_func.FontDescription.from_string.html#description

gaps <tous> | <horizontal> <vertical> | <haut> <droite> <bas> <gauche>

Définit les marges par rapport au bord de l'écran pour la barre. Les marges peuvent être définies toutes à la fois, par direction, ou par côté. Notez que seuls les côtés qui touchent un bord de l'écran peuvent avoir des marges. Pour le côté qui ne touche pas un bord de l'écran, les marges externes par côté pour les espaces de travail peuvent être utiles.

height <hauteur>

Définit la hauteur de la barre. La hauteur par défaut (0) correspondra à la taille de la police.

hidden_state hide|show [<id-barre>]

Spécifie le comportement de la barre lorsqu'elle est en mode hide. Lorsque l'état caché est hide, elle est normalement cachée, et n'est dé-cachée qu'en appuyant sur la touche modificatrice ou en cas d'indicateurs d'urgence. Lorsque l'état caché est show, elle est permanentement visible, dessinée par-dessus l'espace de travail actuellement visible. Par défaut, il est caché (hide).

Pour la compatibilité avec i3, la syntaxe bar hidden_state hide|show [<id-barre>] est prise en charge, ainsi que la syntaxe sway uniquement bar <id-barre> hidden_state hide|show. Lors de l'utilisation de la syntaxe i3, si id-barre est omis, l'état caché sera modifié pour toutes les barres. Tenter d'utiliser bar <id-barre1> hidden_state hide|show <id-barre2> entraînera une erreur due à des identifiants de barre conflictuels.

mode dock|hide|invisible|overlay [<id-barre>]

Spécifie la visibilité de la barre. En mode dock, elle est permanentement visible à un bord de l'écran. En mode hide, elle est cachée sauf si la touche modificatrice est pressée, bien que ce comportement dépend de l'état caché. En mode invisible, elle est permanentement cachée. En mode overlay, elle est permanentement visible par-dessus les autres fenêtres. (En mode overlay, la barre est transparente aux événements d'entrée.) Par défaut, il est en mode dock.

Pour la compatibilité avec i3, la syntaxe bar mode <mode> [<id-barre>] est prise en charge, ainsi que la syntaxe sway uniquement bar <id-barre> mode <mode>. Lors de l'utilisation de la syntaxe i3, si id-barre est omis, le mode sera modifié pour toutes les barres. Tenter d'utiliser bar <id-barre1> mode <mode> <id-barre2> entraînera une erreur due à des identifiants de barre conflictuels.

modifier <Modificateur>|none

Spécifie la touche modificatrice qui affiche une barre cachée. Par défaut, il s'agit de Mod4.

output <sortie>|*

Limite la barre à une sortie spécifique, peut être spécifié plusieurs fois. Si la commande de sortie est omise, la barre sera affichée sur toutes les sorties. * peut être donné à tout moment pour la réinitialiser à toutes les sorties.

pango_markup enabled|disabled

Active ou désactive le balisage pango pour les lignes de statut. Cela n'a aucun effet sur les lignes de statut utilisant le protocole JSON de swaybar.

position top|bottom

Définit la position de la barre. Par défaut, il s'agit du bas (bottom).

separator_symbol <symbole>

Spécifie le symbole séparateur pour séparer les blocs sur la barre.

status_command <commande_statut>

Exécute la commande de statut de la barre avec sh -c. Chaque ligne de texte imprimée sur la sortie standard par cette commande sera affichée dans la zone de statut de la barre. Vous pouvez également utiliser le protocole de ligne de statut JSON de swaybar. Voir swaybar-protocol(7) pour plus d'informations sur le protocole.

Si vous exécutez cette commande via IPC, vous pouvez désactiver une commande de statut en cours en définissant la commande sur un seul trait d'union : swaybar bar bar-0 status_command -

status_edge_padding <rembourrage>

Définit le rembourrage utilisé lorsque la ligne de statut est sur le bord droit de la barre. Cette valeur sera multipliée par l'échelle de la sortie. La valeur par défaut est 3.

status_padding <rembourrage>

Définit le rembourrage vertical utilisé pour la ligne de statut. La valeur par défaut est 1. Si rembourrage est 0, les blocs pourront occuper toute la hauteur de la barre. Cette valeur sera multipliée par l'échelle de la sortie.

strip_workspace_name yes|no

Si défini sur yes, les noms des espaces de travail seront omis du bouton de l'espace de travail et seul le numéro personnalisé sera affiché. Par défaut, il est désactivé (no).

strip_workspace_numbers yes|no

Si défini sur yes, les numéros des espaces de travail seront omis du bouton de l'espace de travail et seul le nom personnalisé sera affiché. Par défaut, il est désactivé (no).

unbindcode [--release] <code_événement>

Supprime la liaison avec le <code_événement> donné.

unbindsym [--release] button[1-9]|<nom_événement>

Supprime la liaison avec le <bouton> ou le <nom_événement> donné.

wrap_scroll yes|no

Active ou désactive le retour à la ligne lors du défilement des espaces de travail avec la molette de la souris. Par défaut, il est désactivé (no).

workspace_buttons yes|no

Active ou désactive les boutons des espaces de travail sur la barre. Par défaut, il est activé (yes).

workspace_min_width <px> [px]

Spécifie la largeur minimale pour les boutons des espaces de travail sur la barre. Par défaut, il est de 0.

Ce paramètre s'applique également à l'indicateur de mode de liaison actuel.

Les commandes suivantes ne peuvent être utilisées qu'à l'exécution.

mode toggle [<id-barre>]

Commute le mode actuel entre hide et dock. Tout autre mode est traité comme hide.

TRAY

Swaybar fournit un plateau système où des applications tierces peuvent placer des icônes. Les commandes suivantes configurent le plateau.

tray_bindcode <code_événement> ContextMenu|Activate|SecondaryActivate|ScrollDown|ScrollLeft|ScrollRight|ScrollUp|nop

Exécute l'action lorsque le bouton de la souris a été pressé. Les boutons peuvent être donnés sous forme de code d'événement, qui peut être obtenu à partir de libinput debug-events. Pour désactiver le comportement par défaut d'un bouton, utilisez la commande nop.

tray_bindsym button[1-9]|<nom_événement> ContextMenu|Activate|SecondaryActivate|ScrollDown|ScrollLeft|ScrollRight|ScrollUp|nop

Exécute l'action lorsque le bouton de la souris a été pressé. Les boutons peuvent être donnés sous forme de numéro de bouton x11 ou de nom d'événement, qui peut être obtenu à partir de libinput debug-events. Utilisez la commande nop pour désactiver l'action par défaut (Activate pour button1, ContextMenu pour button2 et SecondaryActivate pour button3).

tray_padding <px> [px]

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Définit le remplissage en pixels de la zone de notification système. Ce remplissage entourera la zone de notification de tous les côtés et entre chaque élément. La valeur par défaut pour px est 2.

tray_output none|<output>|*

Restreint la zone de notification à une sortie spécifique, peut être spécifié plusieurs fois. Si omis, la zone de notification s'affichera sur toutes les sorties. Contrairement à i3bar, swaybar peut afficher des icônes sur n'importe quel nombre de barres et de sorties sans problèmes de concurrence. * peut être utilisé à tout moment pour réinitialiser l'affichage sur toutes les sorties.

icon_theme <name>

Définit le thème d'icônes dans lequel sway recherchera les icônes des éléments. Cette option n'a pas de valeur par défaut, car sway utilisera toujours le thème de repli, hicolor.

COULEURS

Les couleurs sont définies à l'intérieur d'un bloc colors { } dans un bloc bar { }. Les couleurs doivent être définies en hexadécimal : #RRGGBB ou #RRGGBBAA.

background <couleur>

Couleur d'arrière-plan de la barre.

statusline <couleur>

Couleur du texte à utiliser pour la barre de statut.

separator <couleur>

Couleur du texte à utiliser pour le séparateur.

focused_background <couleur>

Couleur d'arrière-plan de la barre sur la sortie du moniteur actuellement focalisé. Si elle n'est pas utilisée, la couleur sera prise dans background.

focused_statusline <couleur>

Couleur du texte à utiliser pour la barre de statut sur la sortie du moniteur actuellement focalisé. Si elle n'est pas utilisée, la couleur sera prise dans statusline.

focused_separator <couleur>

Couleur du texte à utiliser pour le séparateur sur la sortie du moniteur actuellement focalisé. Si elle n'est pas utilisée, la couleur sera prise dans separator.

focused_workspace <bordure> <arrière-plan> <texte>

Couleur de la bordure, de l'arrière-plan et du texte pour un bouton d'espace de travail lorsque l'espace de travail est focalisé.

active_workspace <bordure> <arrière-plan> <texte>

Couleur de la bordure, de l'arrière-plan et du texte pour un bouton d'espace de travail lorsque l'espace de travail est actif (visible) sur une sortie, mais que la focalisation est sur une autre. Vous ne pouvez distinguer cela de l'espace de travail focalisé que lorsque vous utilisez plusieurs moniteurs.

inactive_workspace <bordure> <arrière-plan> <texte>

Couleur de la bordure, de l'arrière-plan et du texte pour un bouton d'espace de travail lorsque l'espace de travail n'a pas le focus et n'est actif (visible) sur aucune sortie. Ce sera le cas pour la plupart des espaces de travail.

urgent_workspace <bordure> <arrière-plan> <texte>

Couleur de la bordure, de l'arrière-plan et du texte pour un bouton d'espace de travail lorsque l'espace de travail contient une fenêtre avec l'indicateur d'urgence défini.

binding_mode <bordure> <arrière-plan> <texte>

Couleur de la bordure, de l'arrière-plan et du texte pour l'indicateur du mode de raccourci. Si elle n'est pas utilisée, les couleurs seront prises dans urgent_workspace.
