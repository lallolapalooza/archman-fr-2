swayidle(1) Manuel des commandes générales swayidle(1)

NOM

swayidle — Gestionnaire d'inactivité pour Wayland

SYNTAXE

swayidle [options] [événements...]

OPTIONS

-C <chemin>

Le fichier de configuration à utiliser. Par défaut, les chemins suivants sont vérifiés dans l'ordre suivant : $XDG_CONFIG_HOME/swayidle/config, $HOME/.swayidle/config. Les entrées du fichier de configuration sont des événements décrits dans la section ÉVÉNEMENTS. La spécification d'événements dans le fichier de configuration et en tant qu'arguments n'est pas mutuellement exclusive.

-h

Afficher le message d'aide et quitter.

-d

Activer la sortie de débogage.

-w

Attendre que la commande se termine avant de continuer, utile pour s'assurer qu'une commande avant-hibernation est terminée avant que le système n'hiberne.

Note : l'utilisation de cette option fait que swayidle bloque jusqu'à ce que la commande soit terminée.

-S <nom-siège>

Spécifier le siège à utiliser. Par défaut, si aucun nom n'est spécifié, un siège arbitraire sera choisi à la place.

DESCRIPTION

swayidle écoute l'activité d'inactivité sur votre compositeur Wayland et exécute des tâches lors de divers événements liés à l'inactivité. Vous pouvez spécifier n'importe quel nombre d'événements en ligne de commande et dans le fichier de configuration.

ÉVÉNEMENTS

timeout <délai> <commande de délai> [reprise <commande de reprise>]

Exécute commande de délai s'il n'y a aucune activité pendant <délai> secondes.

Si vous spécifiez « reprise <commande de reprise> », la commande de reprise sera exécutée lorsqu'il y aura à nouveau de l'activité.

before-sleep <commande>

Si compilé avec le support de systemd, exécute commande avant que systemd ne mette l'ordinateur en veille.

Note : cela ne retarde l'hibernation que jusqu'à la limite définie dans logind.conf(5) par l'option InhibitDelayMaxSec. Une commande qui ne sera pas terminée à ce moment-là continuera de s'exécuter après la reprise de l'hibernation.

after-resume <commande>

Si compilé avec le support de systemd, exécute commande après que logind a signalé que l'ordinateur a repris après une hibernation.

lock <commande>

Si compilé avec le support de systemd, exécute commande lorsque logind signale que la session doit être verrouillée.

unlock <commande>

Si compilé avec le support de systemd, exécute commande lorsque logind signale que la session doit être déverrouillée.

idlehint <délai>

Si compilé avec le support de systemd, définit IdleHint pour indiquer une session logind/elogind inactive après <délai> secondes. L'ajout d'un événement idlehint amènera également swayidle à appeler SetIdleHint(false) lorsqu'il est exécuté, à la reprise, au déverrouillage, etc.

Toutes les commandes sont exécutées dans un shell.

SIGNAUX

swayidle répond aux signaux suivants :

SIGTERM, SIGINT

Exécute toutes les commandes de reprise en attente. Une fois terminé, swayidle se terminera.

SIGUSR1

Entre immédiatement en état d'inactivité.

EXEMPLE

swayidle -w \
	timeout 300 'swaylock -f -c 000000' \
	timeout 600 'swaymsg "output * power off"' \
		resume 'swaymsg "output * power on"' \
	before-sleep 'swaylock -f -c 000000'

Ceci verrouillera votre écran après 300 secondes d'inactivité, puis éteindra vos écrans après 300 secondes supplémentaires, et rallumera vos écrans lors de la reprise. Il verrouillera également votre écran avant que votre ordinateur n'entre en veille.

Pour s'assurer que swayidle attend que swaylock verrouille l'écran avant de libérer le verrou d'inhibition, l'option -w est utilisée dans swayidle, et -f dans swaylock.
