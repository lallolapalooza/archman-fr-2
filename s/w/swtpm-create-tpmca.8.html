NOM

swtpm-create-tpmca - Outil pour créer une CA locale pour swtpm_localca

SYNTAXE

swtpm-create-tpmca [OPTIONS]

DESCRIPTION

swtpm-create-tpmca est un outil pour créer une CA basée sur TPM 1.2 ou TPM 2 qui peut être utilisée par swtpm_localca pour signer les certificats EK et de plateforme. La CA utilise une clé GnuTLS pour signer les certificats. Si un TPM 1.2 est utilisé, GnuTLS communiquera avec le TPM 1.2 en utilisant le démon tcsd (TrouSerS). Si un TPM 2 est utilisé, le pilote Intel pkcs11 et ses outils (tpm2_ptool) sont également requis.

Étant donné que le certificat de la CA TPM doit être signé par une CA, une autorité de certification racine sera également créée et signera ce certificat. La clé privée et le certificat de la CA racine seront situés dans le même répertoire que la clé de signature et porteront respectivement les noms swtpm-localca-rootca-privkey.pem et swtpm-localca-rootca-cert.pem. La variable d'environnement SWTPM_ROOTCA_PASSWORD peut être définie pour le mot de passe de la clé privée de la CA racine.

Remarque : Cet outil est expérimental. Voir la section sur les problèmes connus ci-dessous.

Les options suivantes sont prises en charge :

--dir dir
Le répertoire où les clés seront écrites. Une CA racine existante avec les fichiers swtpm-localca-rootca-privkey.pem et swtpm-localca-rootca-cert.pem dans ce répertoire sera réutilisée. Si l'un de ces fichiers n'existe pas, une nouvelle CA racine sera créée.
--overwrite
Écrase le contenu du répertoire de sortie.
--register
Enregistre la clé auprès de TCSD. Pour que la clé soit disponible pour la signature, le même utilisateur qui a créé la CA TPM doit exécuter l'outil swtpm_localca plus tard. Si cette option n'est pas passée, la clé privée est écrite dans un fichier et peut être utilisée par d'autres également.
--key-password s
La nouvelle clé de signature aura ce mot de passe.

Remarque : En raison d'un bug dans certtool de GnuTLS, il peut être nécessaire d'utiliser le même mot de passe pour la clé de signature que pour le SRK.

--srk-password s
Le mot de passe du SRK du TPM.

Remarque : Comme tpmtool de GnuTLS ne supporte pas le mot de passe « bien connu » de 20 octets nuls, le mot de passe du SRK doit être défini.

--outfile filename
Le nom d'un fichier où écrire la configuration swtpm-localca.conf.
--owner owner
Le nom ou le numéro UID du propriétaire qui possédera le répertoire et le fichier outfile. Cette option n'a d'effet que si swtpm-create-tpmca est exécuté par l'utilisateur root.
--group group
Le nom ou le numéro GID du groupe qui possédera le répertoire et le fichier outfile. Cette option n'a d'effet que si swtpm-create-tpmca est exécuté par l'utilisateur root.
--tss-tcsd-hostname
Le nom d'hôte où tcsd est en cours d'exécution. Le nom d'hôte par défaut est 'localhost'.
-tss-tcsd-port
Le port TCP sur lequel tcsd écoute les messages. Le port par défaut est 30003.
--tpm2
Le TPM utilisé pour signer les certificats est un TPM 2 et la pile TSS d'Intel doit être en cours d'exécution (tpm2-abrmd) ainsi que son module PKCS11. Le module PKCS11 du TPM 2 doit avoir été initialisé à l'aide de tpm2_ptool.

Les variables d'environnement SWTPM_PKCS11_PIN et SWTPM_PKCS11_SO_PIN doivent être définies pour contenir les PIN. Si SWTPM_PKCS11_PIN n'est pas définie, le PIN par défaut 'swtpm-tpmca' sera utilisé. SWTPM_PKCS11_SO_PIN est nécessaire pour créer le token et doit être explicitement définie comme variable d'environnement.

--pid primary-object-id
L'identifiant de l'objet primaire que tpm2_ptool renvoie lors de l'initialisation ('init').
-help, -h, -?
Affiche l'écran d'aide et quitte.

EXEMPLE

L'exemple suivant crée une CA TPM intermédiaire et écrit les clés dans /var/lib/swtpm-localca et la configuration swtpm_localca dans /etc/swtpm-localca.conf. Elle peut ensuite être utilisée pour signer les certificats des TPMs swtpm nouvellement créés.

Si le TPM de l'hôte est un TPM 1.2, nous devons d'abord démarrer tcsd, puis nous pouvons créer la clé TPM et le certificat de CA TPM :

#> sudo systemctl start tcsd
#> sudo /usr/share/swtpm/swtpm-create-tpmca \
               --dir /var/lib/swtpm-localca \
               --overwrite \
               --outfile /etc/swtpm-localca.conf \
               --srk-password password \
               --key-password password \
               --group tss
statedir = /var/lib/swtpm-localca
signingkey = tpmkey:file=/var/lib/swtpm-localca/swtpm-localca-tpmca-privkey.pem
issuercert = /var/lib/swtpm-localca/swtpm-localca-tpmca-cert.pem
certserial = /var/lib/swtpm-localca/certserial
TSS_TCSD_HOSTNAME = localhost
TSS_TCSD_PORT = 30003
signingkey_password = password
parentkey_password = password

Alternativement, si le TPM de l'hôte est un TPM 2 et que la pile TPM 2 d'Intel est installée, nous devons démarrer tpm2-abrmd d'abord, puis nous pouvons créer la clé TPM et le certificat de CA TPM :

#> sudo systemctl start tpm2-abrmd     # peut ne pas être requis avec les outils Intel TPM 2 récents
#> sudo tpm2_ptool init
action: Created
id: 1                   # c'est le paramètre --pid ci-dessous
#> sudo SWTPM_PKCS11_PIN="mypin 123" SWTPM_PKCS11_SO_PIN=123 /usr/share/swtpm/swtpm-create-tpmca \
               --dir /var/lib/swtpm-localca \
               --overwrite \
               --outfile /etc/swtpm-localca.conf \
               --group tss \
               --tpm2 \
               --pid 1
statedir = /var/lib/swtpm-localca
signingkey = pkcs11:model=SW%20%20%20TPM\;manufacturer=IBM\;serial=0000000000000000\;token=swtpm-tpmca-1\;id=%31\;object=swtpm-tpmca-key\;type=private
issuercert = /var/lib/swtpm-localca/swtpm-localca-tpmca-cert.pem
certserial = /var/lib/swtpm-localca/certserial
SWTPM_PKCS11_PIN = mypin 123

Remarque : Cela fonctionne également pour les utilisateurs non root en adaptant les paramètres --dir et --outfile ici et ci-dessous en changeant le paramètre --dir et en ajoutant un paramètre --config.

Pour tester l'une des CA TPM ci-dessus, exécutez la commande suivante :

#> swtpm_localca \
       --type ek --ek x=11,y=13 \
       --dir /tmp --vmid test --tpm2 \
       --tpm-spec-family 2.0 --tpm-spec-revision 146 --tpm-spec-level 00 \
       --tpm-model swtpm --tpm-version 20170101 --tpm-manufacturer IBM

L'option --tpm2 dans cette commande indique que le TPM pour lequel le certificat est créé est un TPM 2.

PROBLÈMES CONNUS

L'interaction de certtool de GnuTLS avec le démon TCSD du TPM peut provoquer autant d'échecs d'authentification de TPM (clé) que le TPM refuse d'accepter davantage de commandes authentifiées jusqu'à ce que le propriétaire du TPM lui envoie la commande TPM_ORD_ResetLockValue. La raison est que certtool essaie d'abord d'utiliser 20 octets nuls pour le mot de passe du SRK, puis demande et utilise le mot de passe requis du SRK. Le tpmtool de GnuTLS ne prend pas en charge les 20 octets nuls pour le mot de passe du SRK, il force donc l'utilisation d'un mot de passe « réel ».

L'effet des échecs d'authentification peut être que la CA TPM ne peut pas signer les certificats car le TPM n'accepte pas les commandes authentifiées.
