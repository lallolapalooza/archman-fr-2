NOM

swipl-ld - Créer un exécutable embarqué SWI-Prolog

SYNTAXE

swipl-ld options fichiers-c fichiers-o fichiers-pl

DESCRIPTION

L'utilitaire swipl-ld est une interface pour le compilateur C et l'éditeur de liens afin de créer un exécutable autonome à partir d'une série de fichiers d'entrée C/C++ et Prolog. Il extrait des informations de l'exécutable SWI-Prolog swipl, après quoi il analyse les arguments et les divise en plusieurs catégories. Il appelle ensuite le compilateur C pour créer un exécutable contenant le code C de l'utilisateur et le noyau SWI-Prolog. Après cela, il appellera l'environnement de développement pour créer un état sauvegardé Prolog à partir des fichiers prolog et enfin il créera l'exécutable cible en concaténant l'état à l'émulateur. Voir aussi qsave_program/2 dans le manuel SWI-Prolog.

Options

-pl prolog
Spécifie la version de prolog à utiliser. La valeur par défaut est swipl. Ce drapeau peut être utilisé pour choisir entre différentes versions installées sur votre système, ou pour spécifier une version modifiée. Une version modifiée devrait comprendre les drapeaux -dump-runtime-variables -f fichier -F fichier -g objectif -t toplevel.
-help
Affiche brièvement les options.
-nostate
Relie simplement le noyau. Le noyau nouvellement lié ne peut fonctionner qu'en présence du système de développement. Tous les fichiers source prolog fournis sont ignorés, ainsi que les options -goal -toplevel -initfile. -class C'est la manière préférée d'attacher des modules externes à Prolog si le chargement dynamique n'est pas supporté sur votre système.
-c
Compile les fichiers source C ou C++ en fichiers objet. Cela transforme swipl-ld en un remplacement pour le compilateur C ou C++ où les options appropriées, telles que l'emplacement du répertoire d'inclusion, sont automatiquement transmises au compilateur.
-E
Invoque le préprocesseur C. Utilisé pour faire de swipl-ld un remplacement pour le compilateur C ou C++.
-shared
Lie les fichiers C, C++ ou objet dans un objet partagé (DLL) qui peut être chargé par le prédicat load_foreign_library/1. S'il est utilisé avec -c il définit les options appropriées pour compiler un fichier C ou C++ prêt à être lié dans un objet partagé.
-embed-shared
Intègre SWI-Prolog dans une DLL/un objet partagé plutôt qu'un exécutable. Voir le manuel de référence pour plus de détails.
-dll
Uniquement sous Windows Identique à -embed-shared Compatibilité ascendante.
-F base
Par défaut, aucun n'est passé à la commande swipl pour créer l'état sauvegardé. En utilisant -F xpce vous pouvez spécifier le chargement de xpce.rc, rendant XPCE disponible pour l'état sauvegardé.
-goal objectif
L'objectif qui est initialement exécuté lorsque le toplevel est démarré en utilisant PL_toplevel(). C'est-à-dire, la valeur par défaut. Le drapeau -g pour le nouvel exécutable.
-toplevel objectif
L'objectif qui est exécuté comme objectif toplevel principal. C'est-à-dire, la valeur par défaut. Le drapeau -t pour le nouvel exécutable.
-initfile fichier
Le fichier qui est chargé par le toplevel. C'est-à-dire, la valeur par défaut. Le drapeau -f pour le nouvel exécutable.
-class {runtime,kernel,development}
Définit la classe de sauvegarde de l'état Prolog sauvegardé qui est créé. Si runtime (par défaut), le système résultant laisse l'interprétation de tous les arguments à l'application. Si kernel tous les prédicats seront verrouillés pour le traceur. Enfin, si development l'état est sauvegardé `tel quel' et le système résultant traite les options tout comme l'exécutable SWI-Prolog de base le fait. Voir aussi qsave_program/2 dans le manuel de référence SWI-Prolog.
-v
Fonctionnement verbeux. Ceci affiche les commandes avant de les exécuter. Notez que certaines commandes sont imprimées sous forme de commandes shell, mais exécutées en fait par swipl-ld lui-même pour des raisons de compatibilité avec les plateformes Win32.
-f
Opération fictive. Combiné avec -v cela affiche les commandes qui doivent être exécutées sans rien faire réellement.
-Eargumentcpp ...
Si la première option est -E, toutes les options suivantes sont ajoutées et transmises au programme sélectionné par la configuration de SWI-Prolog pour exécuter cpp.
-o fichier
Spécifie le nom de l'exécutable final. La valeur par défaut est a.out.
-cc compilateur-c
Spécifie le compilateur à utiliser pour les fichiers *.c. La valeur par défaut est le compilateur utilisé pour compiler SWI-Prolog lui-même, tel que lu à partir de la caractéristique c_cc.
-c++ compilateur-c++
Spécifie le compilateur à utiliser pour les fichiers d'entrée C++. Si le compilateur C est gcc il s'agit de g++, sinon c++ est présumé.
-ld éditeur-de-liens
Spécifie l'éditeur de liens à utiliser. La valeur par défaut est le compilateur C. Sur les plateformes Win32, la valeur par défaut est link.exe.
-lbibliothèque
Spécifie une bibliothèque C pour lier l'application. Par défaut, -lswipl ainsi que les bibliothèques requises par le noyau SWI-Prolog seront passées au compilateur C.
-Lrépertoire-bibliothèque
Spécifie un répertoire de bibliothèques supplémentaire pour le compilateur C. Par défaut, le répertoire d'exécution pour l'architecture actuelle est passé.
-g|-I*|-D*|-U*|-O*|-W*
Transmis au compilateur comme indicateurs C. Par défaut, le répertoire d'inclusion de SWI-Prolog est passé comme répertoire d'inclusion supplémentaire. Les drapeaux -D suivants sont ajoutés par swipl-ld : -D__SWI_PROLOG__ et -D__SWI_EMBEDDED__.
-pl-options*
Spécifie des options supplémentaires pour swipl. Le premier caractère suivant -pl-options détermine le séparateur d'options. Le reste de l'argument est divisé en utilisant ce séparateur et les parties sont ajoutées à la liste d'options pour Prolog. Voir aussi -cc-options et -ld-options
-ld-options*
Options supplémentaires passées à l'éditeur de liens. Par exemple : -ld-options,-Bstatic
-cc-options*
Options supplémentaires passées aux compilateurs C et C++.
*.o
Passés comme fichiers d'entrée à l'éditeur de liens.
*.c
Compilé en utilisant le compilateur C, après quoi le fichier objet est passé à l'éditeur de liens. Le fichier objet est supprimé au nettoyage.
*.cc|*.C|*.cxx|*.cpp
Compilé en utilisant le compilateur C++, après quoi le fichier objet est passé à l'éditeur de liens. Le fichier objet est supprimé au nettoyage.
*.pl|*.qlf
Passés comme fichiers d'entrée Prolog

BOGUES

L'analyse des options et leur distribution sur les divers programmes est probablement incomplète. N'hésitez pas à la modifier et veuillez transmettre les modifications utiles à bugs@swi-prolog.org.

Il faut prendre certaines précautions pour que l'état créé avec qsave_program/2 soit autonome (c'est-à-dire qu'il ne contienne aucune référence aux bibliothèques Prolog). De plus, comme l'état est créé en utilisant l'environnement de développement plutôt que l'émulateur de l'utilisateur, le code Prolog ne peut pas utiliser de directives qui dépendent du code C ajouté par l'utilisateur.
