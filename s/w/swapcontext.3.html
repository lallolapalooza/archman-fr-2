makecontext(3) Manuel des fonctions de bibliothèque makecontext(3)

NOM

makecontext, swapcontext - manipuler le contexte utilisateur

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <ucontext.h>
void makecontext(ucontext_t *ucp, typeof(void (int arg0, ...)) *func,
                 int argc, ...);
int swapcontext(ucontext_t *restrict oucp,
                 const ucontext_t *restrict ucp);

DESCRIPTION

Dans un environnement de type System V, on dispose du type ucontext_t (défini dans <ucontext.h> et décrit dans getcontext(3)) et des quatre fonctions getcontext(3), setcontext(3), makecontext() et swapcontext() qui permettent la commutation de contexte au niveau utilisateur entre plusieurs fils de contrôle au sein d'un processus.

La fonction makecontext() modifie le contexte pointé par ucp (qui a été obtenu lors d'un appel à getcontext(3)). Avant d'invoquer makecontext(), l'appelant doit allouer une nouvelle pile pour ce contexte et assigner son adresse à ucp->uc_stack, et définir un contexte successeur et lui assigner son adresse dans ucp->uc_link.

Lorsque ce contexte est activé ultérieurement (en utilisant setcontext(3) ou swapcontext()), la fonction func est appelée, et les arguments entiers (int) qui suivent argc lui sont passés ; l'appelant doit spécifier le nombre de ces arguments dans argc. Lorsque cette fonction retourne, le contexte successeur est activé. Si le pointeur de contexte successeur est NULL, le thread se termine.

La fonction swapcontext() enregistre le contexte courant dans la structure pointée par oucp, puis active le contexte pointé par ucp.

VALEUR DE RETOUR

En cas de succès, swapcontext() ne retourne pas. (Mais on peut retourner plus tard, au cas où oucp est activé, auquel cas on dirait que swapcontext() retourne 0.) En cas d'erreur, swapcontext() retourne -1 et positionne errno pour indiquer l'erreur.

ERREURS

ENOMEM
Espace de pile insuffisant.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
makecontext () Sécurité des threads MT-Safe race:ucp
swapcontext () Sécurité des threads MT-Safe race:oucp race:ucp

NORMES

Aucune.

HISTORIQUE

glibc 2.1. SUSv2, POSIX.1-2001. Supprimé dans POSIX.1-2008, citant des problèmes de portabilité et recommandant que les applications soient réécrites pour utiliser les threads POSIX à la place.

NOTES

L'interprétation de ucp->uc_stack est la même que dans sigaltstack(2), c'est-à-dire que cette structure contient le début et la longueur d'une zone mémoire à utiliser comme pile, indépendamment de la direction de croissance de la pile. Il n'est donc pas nécessaire pour le programme utilisateur de s'en préoccuper.

Sur les architectures où les types int et pointeur ont la même taille (par exemple, x86-32, où les deux types sont de 32 bits), vous pourriez réussir à passer des pointeurs comme arguments à makecontext() après argc. Cependant, le faire n'est pas garanti d'être portable, est indéfini selon les normes, et ne fonctionnera pas sur les architectures où les pointeurs sont plus grands que les int. Néanmoins, à partir de glibc 2.8, glibc apporte des modifications à makecontext() pour permettre cela sur certaines architectures 64 bits (par exemple, x86-64).

EXEMPLES

Le programme d'exemple ci-dessous démontre l'utilisation de getcontext(3), makecontext() et swapcontext(). L'exécution du programme produit la sortie suivante :


$ ./a.out
main: swapcontext(&uctx_main, &uctx_func2)
func2: started
func2: swapcontext(&uctx_func2, &uctx_func1)
func1: started
func1: swapcontext(&uctx_func1, &uctx_func2)
func2: returning
func1: returning
main: exiting

Source du programme

#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <ucontext.h>
static ucontext_t uctx_main, uctx_func1, uctx_func2;
static void
func1(void)
{
    printf("%s: started\n", __func__);
    printf("%s: swapcontext(&uctx_func1, &uctx_func2)\n", __func__);
    if (swapcontext(&uctx_func1, &uctx_func2) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: returning\n", __func__);
}
static void
func2(void)
{
    printf("%s: started\n", __func__);
    printf("%s: swapcontext(&uctx_func2, &uctx_func1)\n", __func__);
    if (swapcontext(&uctx_func2, &uctx_func1) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: returning\n", __func__);
}
int
main(int argc, char *argv[])
{
    char func1_stack[16384];
    char func2_stack[16384];
    if (getcontext(&uctx_func1) == -1)
        err(EXIT_FAILURE, "getcontext");
    uctx_func1.uc_stack.ss_sp = func1_stack;
    uctx_func1.uc_stack.ss_size = sizeof(func1_stack);
    uctx_func1.uc_link = &uctx_main;
    makecontext(&uctx_func1, func1, 0);
    if (getcontext(&uctx_func2) == -1)
        err(EXIT_FAILURE, "getcontext");
    uctx_func2.uc_stack.ss_sp = func2_stack;
    uctx_func2.uc_stack.ss_size = sizeof(func2_stack);
    /* Contexte successeur est f1(), sauf si argc > 1 */
    uctx_func2.uc_link = (argc > 1) ? NULL : &uctx_func1;
    makecontext(&uctx_func2, func2, 0);
    printf("%s: swapcontext(&uctx_main, &uctx_func2)\n", __func__);
    if (swapcontext(&uctx_main, &uctx_func2) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: exiting\n", __func__);
    exit(EXIT_SUCCESS);
}

VOIR AUSSI

    swapcontext(3) - Manuel Linux

    NAME

    swapcontext - exécuter un contexte enregistré

    LIBRARY

    Bibliothèque de threads POSIX (libpthread, -lpthread)

    SYNOPSIS

    #include <ucontext.h>

int swapcontext(ucontext_t *restrict oldcontext,
                const ucontext_t *restrict newcontext);

    DESCRIPTION

    La fonction swapcontext() enregistre le contexte d'exécution actuel dans oldcontext et active le contexte spécifié par newcontext.

    Le contexte comprend le pointeur d'instruction, le pointeur de pile et les registres du processeur.

    Les contextes peuvent être manipulés à l'aide des fonctions getcontext(3), makecontext(3) et setcontext(3).

    RETURN VALUE

    En cas de succès, swapcontext() retourne 0 sur le nouveau contexte. La fonction ne retourne jamais sur l'ancien contexte ; le contrôle est transféré au nouveau contexte.

    En cas d'erreur, swapcontext() retourne -1 et errno est définie pour indiquer l'erreur.

    ERRORS

    EINVAL
    newcontext pointe vers un contexte qui n'a pas été initialisé avec makecontext(3).

    ATTRIBUTES

    Pour avoir une explication des termes ci-dessous, voir attributes(7).

    +-----------------+-----------------+
| Interface       | Attribut        |
+-----------------+-----------------+
| swapcontext()   | Thread-Safety, Cancellation |
+-----------------+-----------------+

    Dans la table ci-dessus, les valeurs possibles pour la colonne d'attributs sont : Thread-Safety, Cancellation, Realtime Signals, Safe, Unsafe, Handle, Async-Signal-Safe.

    STANDARDS

    POSIX.1-2008.

    HISTORY

    POSIX.1-2001, POSIX.1-2008.

    NOTES

    L'utilisation de swapcontext() peut être complexe et est généralement réservée aux cas où des routines de bas niveau doivent être implémentées.

    Il est important de noter que swapcontext() n'est pas une opération atomique. Il peut y avoir des conditions de concurrence si le contexte actuel est modifié par un autre thread pendant que swapcontext() est en cours d'exécution.

    EXAMPLES

    Aucun.

    SEE ALSO

    getcontext(3), makecontext(3), setcontext(3), context(7)
