sniffglue(1) Manuel des commandes générales sniffglue(1)

NOM

sniffglue - renifleur de paquets sécurisé et multithreadé

SYNTAXE

sniffglue [-vrpVh] [-n <threads>] périphérique

DESCRIPTION

sniffglue est un renifleur réseau écrit en rust. Les paquets réseau sont analysés de manière concurrente à l'aide d'un pool de threads pour utiliser tous les cœurs du processeur. Les objectifs du projet sont que vous puissiez exécuter sniffglue en toute sécurité sur des réseaux non fiables et qu'il ne plante pas lors du traitement des paquets. La sortie doit être aussi utile que possible par défaut.

OPTIONS

-v, --verbose

Augmente la sensibilité du filtre pour afficher plus de paquets (potentiellement moins utiles). La valeur par défaut n'affiche que quelques paquets, ce drapeau peut être spécifié plusieurs fois. (maximum : 4)

-h, --help

Affiche les informations d'aide.

-p, --promisc

Met périphérique en mode promiscuous.

-r, --read

Ouvre périphérique comme fichier pcap.

-n, --threads threads

Spécifie le nombre de threads.

-V, --version

Affiche les informations de version. Si -r a été spécifié, ouvre comme fichier pcap à la place.

EXEMPLES

Renifler avec les filtres par défaut (dhcp, dns, tls, http) depuis enp0s25:

sniffglue enp0s25

Augmenter la sensibilité du filtre (arp):

sniffglue -v enp0s25

Augmenter la sensibilité du filtre (cjdns, ssdp, dropbox, paquets avec utf8 valide)

sniffglue -vv enp0s25

Presque tout

sniffglue -vvv enp0s25

Tout

sniffglue -vvvv enp0s25

Lire un dump depuis sniff.pcap, avec une sensibilité de filtre accrue et décoder les paquets avec 1 thread :

sniffglue -vvrn1 sniff.pcap

PROTOCOLES

ethernet, ipv4, ipv6, arp, tcp, udp, http, tls, dns, dhcp, cjdns eth beacons, ssdp, dropbox beacons

SÉCURITÉ

Pour signaler un problème de sécurité, veuillez contacter kpcyrd sur ircs://irc.hackint.org.

SECCOMP

Pour garantir qu'un processus compromis ne compromette pas le système, sniffglue utilise seccomp pour restreindre les appels système qui peuvent être utilisés après le démarrage du processus. Ceci est fait en deux étapes, d'abord au tout début (immédiatement après l'initialisation d'env_logger) et une fois que le renifleur a été configuré, mais avant que les paquets ne soient lus du réseau.

RENFORCEMENT

Pendant la deuxième étape, un certain renforcement général est également appliqué avant que tous les appels système inutiles ne soient finalement désactivés. Ceux-ci sont spécifiques au système, donc un fichier de configuration est lu à partir de /etc/sniffglue.conf. Ce fichier de configuration spécifie un répertoire vide pour chroot et un compte non privilégié dans user qui est utilisé pour abandonner les privilèges root.

FUZZING

Le traitement des paquets de sniffglue peut être fuzzed à l'aide de cargo-fuzz. Tout ce dont vous pourriez avoir besoin est fourni dans le répertoire fuzz/ qui est distribué avec son code source. Veuillez noter que ce programme se lie à libpcap qui n'est pas inclus dans la configuration de fuzzing actuelle.

VOIR AUSSI

pcap(3PCAP), seccomp(2)
