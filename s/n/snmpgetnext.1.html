NOM

snmpgetnext - communique avec une entité réseau en utilisant des requêtes GETNEXT SNMP

SYNTAXE

snmpgetnext [OPTIONS COMMUNES] [-Cf] AGENT OID [OID]...

DESCRIPTION

snmpgetnext est une application SNMP qui utilise la requête GETNEXT SNMP pour interroger des informations sur une entité réseau. Un ou plusieurs identifiants d'objet (OID) peuvent être donnés comme arguments sur la ligne de commande. Chaque nom de variable est donné au format spécifié dans variables(5). Pour chacun, la variable qui est lexicographiquement "suivante" dans la MIB de l'entité distante sera renvoyée.

Par exemple :

snmpgetnext -c public zeus interfaces.ifTable.ifEntry.ifType.1

récupérera la variable interfaces.ifTable.ifEntry.ifType.2 :

interfaces.ifTable.ifEntry.ifType.2 = softwareLoopback(24)

Si l'entité réseau a une erreur lors du traitement du paquet de requête, un message d'erreur sera affiché, aidant à identifier la façon dont la requête était mal formée.

OPTIONS

-Cf
Si -Cf n'est *pas* spécifié, certaines applications (snmpdelta, snmpget, snmpgetnext et snmpstatus) essaieront de corriger les erreurs retournées par l'agent auquel vous parliez et renverront la requête. La seule fois où cela est vraiment utile, c'est si vous avez spécifié un OID qui n'existait pas dans votre requête et que vous utilisez SNMPv1 qui exige des requêtes de type "tout ou rien".

En plus de cette option, snmpgetnext prend les options communes décrites dans la page de manuel snmpcmd(1). Notez que snmpgetnext REQUIERT un argument spécifiant l'agent à interroger et au moins un argument OID, comme décrit là.

VOIR AUSSI

snmpcmd(1), snmpget(1), variables(5).
