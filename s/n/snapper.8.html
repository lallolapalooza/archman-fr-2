SNAPPER(8) Gestion des instantanés de système de fichiers SNAPPER(8)

NOM

snapper - Programme en ligne de commande pour la gestion des instantanés de système de fichiers

SYNTAXE

snapper [options-globales] commande [options-de-commande] [arguments-de-commande]

snapper {--help}

DESCRIPTION

Snapper est un programme en ligne de commande pour la gestion des instantanés de système de fichiers. Il peut créer, supprimer et comparer des instantanés, ainsi qu'annuler des modifications effectuées entre des instantanés.

Snapper ne modifie jamais le contenu des instantanés. Ainsi, snapper crée des instantanés en lecture seule si le noyau le prend en charge. Les systèmes de fichiers pris en charge sont btrfs et ext4 (obsolète) ainsi que les instantanés de volumes logiques LVM avec provisionnement fin (thin-provisioning). Certains systèmes de fichiers peuvent ne pas être pris en charge en fonction de votre installation.

CONCEPTS

Configurations

Pour chaque système de fichiers ou sous-volume qui doit être instantané par snapper, un fichier de configuration est requis, voir snapper-configs(5). La configuration peut être effectuée avec la commande create-config.

Instantanés

Snapper distingue trois types d'instantanés.

pre

Les instantanés 'pre' doivent toujours avoir un instantané 'post' correspondant. L'intention des paires d'instantanés pré/post est de prendre un instantané du système de fichiers avant et après une modification.

post

Voir type 'pre'.

single

Ces instantanés n'ont pas de relation spéciale avec d'autres instantanés.

Notez que, du point de vue du système de fichiers, les trois types sont identiques.

Description et Données utilisateur des instantanés

Avec chaque instantané, une description et des données utilisateur peuvent être associées. La description est une chaîne de caractères. Les données utilisateur sont une liste de paires clé-valeur où les clés et les valeurs sont des chaînes de caractères.

N'utilisez pas de caractères non-ASCII pour la description de l'instantané, les données utilisateur ou toute autre chaîne, à moins que vous n'utilisiez toujours l'encodage de caractères UTF-8.

Création automatique d'instantanés

En plus de la création manuelle d'instantanés, des instantanés sont également créés automatiquement.

•Un cronjob ou un minuteur systemd crée des instantanés horaires, si TIMELINE_CREATE est activé pour une configuration.
•Certains programmes comme YaST et zypper créent des paires d'instantanés pré/post lors de la modification du système.

Algorithmes de nettoyage

Snapper fournit plusieurs algorithmes pour nettoyer les anciens instantanés. Les algorithmes sont exécutés dans un cronjob ou un minuteur systemd horaire. Cela peut être configuré dans les fichiers de configuration correspondants avec des paramètres pour chaque algorithme.

number

Supprime les anciens instantanés lorsqu'un certain nombre d'instantanés est atteint.

timeline

Supprime les anciens instantanés mais conserve un certain nombre d'instantanés horaires, quotidiens, hebdomadaires, mensuels, trimestriels et annuels.

empty-pre-post

Supprime les paires d'instantanés pré/post avec des diffs vides.

Les algorithmes de nettoyage "number" et "timeline" peuvent également essayer de maintenir l'espace utilisé par les instantanés en dessous d'une limite et l'espace libre du système de fichiers au-dessus d'une limite. Pour la première condition, une quota doit être configurée, voir la commande setup-quota. De plus, les variables NUMBER_LIMIT et TIMELINE_LIMIT dans le fichier de configuration doivent avoir des plages (valeur minimale et maximale). Les algorithmes effectueront alors deux passes :

1. Supprime les instantanés dépassant la valeur maximale, indépendamment de l'espace des instantanés et du système de fichiers.
2. Supprime les instantanés dépassant la valeur minimale jusqu'à ce que les limites pour l'instantané et le système de fichiers soient atteintes.

La limite pour l'espace utilisé peut être configurée via la variable SPACE_LIMIT. Note : Seuls les instantanés qui ont un algorithme de nettoyage défini sont pris en compte lors du calcul de l'espace utilisé par les instantanés.

La limite pour l'espace libre peut être configurée via la variable FREE_LIMIT.

Note : Puisque le nettoyage est effectué de manière asynchrone par la création d'instantanés, les instantanés observés peuvent différer des instantanés attendus selon les limites. De plus, des qgroups obsolètes de btrfs peuvent exister temporairement.

Filtres

Certains fichiers conservent des informations d'état du système, par exemple /etc/mtab. De tels fichiers ne devraient jamais être restaurés. Pour aider les utilisateurs, snapper permet d'ignorer ces fichiers.

Les filtres sont lus à partir des fichiers /etc/snapper/filters/*.txt et /usr/share/snapper/filters/*.txt, où pour les fichiers portant le même nom, le premier emplacement a la priorité. Chaque ligne dans ces fichiers spécifie un motif. Lorsque snapper calcule la différence entre deux instantanés, il ignore tous les fichiers et répertoires correspondant à l'un de ces motifs en utilisant fnmatch(3) avec le drapeau FNM_LEADING_DIR.

Notez que les filtres n'excluent pas les fichiers ou répertoires de l'instantané. Pour cela, utilisez des sous-volumes ou des points de montage.

OPTIONS GLOBALES

-q, --quiet

Supprimer la sortie normale. Les messages d'erreur seront toujours affichés.

-v, --verbose

Augmenter la verbosité.

--logger-type type

Définir le type de logger. Les valeurs possibles sont none, stdout, logfile et syslog.

--debug

Activer le débogage.

--utc

Afficher les dates et heures en UTC. Par défaut, l'heure locale est utilisée.

--iso

Afficher les dates et heures au format ISO. Le format ISO est toujours utilisé pour les sorties lisibles par machine.

-t, --table-style style

Spécifie le style de table. Le style de table est identifié par un nombre entier.

--abbreviate

Essayer d'abréger les textes dans certaines colonnes pour que les tables s'adaptent à la largeur de l'écran.

--machine-readable format

Spécifie un format de sortie lisible par machine. Les options possibles sont csv et json.

--csvout

Définit le format de sortie CSV. Voir RFC 4180[1] pour les détails, sauf que les lignes se terminent par un LF, pas un CR+LF.

--jsonout

Définit le format de sortie JSON.

--separator caractère

Spécifie le caractère séparateur pour le format de sortie CSV.

--no-headers

Supprimer les en-têtes pour le format de sortie CSV.

-c, --config nom

Utiliser la configuration spécifiée au lieu de la configuration par défaut. La configuration par défaut est nommée "root".

--no-dbus

Opérer sans connexion DBus.

À utiliser avec prudence car un snapperd en cours d'exécution ne sera pas informé des modifications apportées au système.

-r, --root chemin

Opérer sur la racine cible. Ne fonctionne qu'avec no-dbus et uniquement pour certaines commandes.

-a, --ambit ambit

Opérer dans l'ambit spécifié. Peut être utilisé pour annuler la détection d'ambit. Les ambits autorisés sont auto, classic et transactional.

--version

Afficher la version et quitter.

COMMANDES

Snapper fournit un certain nombre de commandes. Chaque commande accepte les options listées dans la section OPTIONS GLOBALES. Ces options doivent être spécifiées avant le nom de la commande. De plus, de nombreuses commandes ont des options spécifiques, qui sont listées dans cette section. Ces options spécifiques à la commande doivent être spécifiées après le nom de la commande et avant les arguments de la commande.

help

Afficher une aide courte.

list-configs [options]

Lister les con

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

lable configurations.

--columns colonnes

Sélectionne les colonnes à afficher, séparées par des virgules.

Les colonnes possibles sont : config, subvolume.

create-config [options] sous-volume

Crée une nouvelle configuration pour un système de fichiers ou un sous-volume. Pour cette commande, vous aurez probablement besoin de l'option globale --config, voir OPTIONS GLOBALES et CONCEPTS.

-f, --fstype type-fs

Définit manuellement le type de système de fichiers. Les valeurs prises en charge sont btrfs, ext4 (obsolète) et lvm. Pour lvm, snapper utilise des snapshots LVM provisionnés en fine capacité. Le type de système de fichiers sur LVM doit être fourni entre parenthèses, par exemple lvm(xfs).

Sans cette option, snapper tente de détecter le système de fichiers.

-t, --template nom

Nom du modèle pour le nouveau fichier de configuration.

delete-config

Supprime une configuration pour un système de fichiers ou un sous-volume. Pour cette commande, vous aurez probablement besoin de l'option globale --config, voir OPTIONS GLOBALES et CONCEPTS.

get-config [options]

Affiche les paramètres de la configuration.

--columns colonnes

Sélectionne les colonnes à afficher, séparées par des virgules.

Les colonnes possibles sont : key, value.

Les colonnes ne sont pas sélectionnées lorsque le format JSON est utilisé.

set-config données-config

Modifie les paramètres de la configuration. Les paramètres données-config sont une liste de paires clé-valeur séparées par des espaces et la clé et la valeur doivent être séparées par un signe égal, par exemple "NUMBER_CLEANUP=yes NUMBER_LIMIT=10". La valeur de SUBVOLUME et FSTYPE ne peut pas être modifiée.

list (ls) [options]

Liste les snapshots.

-t, --type type

Sélectionne le type de snapshots à lister. Les valeurs possibles sont all, single et pre-post.

--disable-used-space

Désactive l'affichage de l'espace utilisé.

Le calcul de l'espace utilisé prend un certain temps. Ainsi, cette option peut accélérer le listage.

-a, --all-configs

Liste les snapshots de toutes les configurations accessibles par l'utilisateur.

--columns colonnes

Sélectionne les colonnes à afficher, séparées par des virgules.

Les colonnes possibles sont : config, subvolume, number, default, active, date, user, used-space, cleanup, description, userdata, pre-number, post-number, post-date, read-only.

Pour chaque snapshot, la sortie se compose de plusieurs colonnes. Certaines nécessitent des explications :

#, Pre # et Post #

Le numéro du snapshot.

Pour btrfs, le numéro peut être suivi d'un signe. Un "-" indique que le snapshot est le snapshot actuellement monté et un "+" indique que le snapshot sera monté la prochaine fois (c'est le sous-volume par défaut de btrfs). Si les deux conditions s'appliquent, un "*" est affiché.

Used Space

Pour btrfs, l'espace exclusif du groupe de quotas btrfs correspondant au snapshot.

L'affichage de l'espace utilisé est automatiquement désactivé s'il n'est pas disponible, par exemple si le quota n'est pas activé sur btrfs.

create [options]

Crée un nouveau snapshot.

-t, --type type

Spécifie le type du nouveau snapshot. Les valeurs possibles sont single, pre et post.

--pre-number numéro

Pour les snapshots post, le numéro du snapshot pre doit être fourni.

-p, --print-number

Affiche le numéro du snapshot créé.

-d, --description description

Description du snapshot.

-c, --cleanup-algorithm algorithme-nettoyage

Définit l'algorithme de nettoyage pour le snapshot.

-u, --userdata données-utilisateur

Définit les données utilisateur pour le snapshot. Les paires clé-valeur doivent être séparées par des virgules et la clé et la valeur doivent être séparées par un signe égal, par exemple requestid=42,user=arthur.

--command commande

Crée un snapshot pre et post et exécute la commande entre les deux.

--read-only

Crée un snapshot en lecture seule. C'est le comportement par défaut.

--read-write

Crée un snapshot en lecture-écriture.

--from numéro

Crée un snapshot à partir du snapshot avec le numéro fourni au lieu du snapshot 0.

--empty

Crée un snapshot vide. Uniquement pris en charge sur btrfs et avec --no-dbus.

modify [options] numéro

Modifie un snapshot.

-d, --description description

Nouvelle description pour le snapshot.

-c, --cleanup-algorithm algorithme-nettoyage

Définit l'algorithme de nettoyage pour le snapshot.

-u, --userdata données-utilisateur

Définit les données utilisateur pour le snapshot. Les paires clé-valeur doivent être séparées par des virgules et la clé et la valeur doivent être séparées par un signe égal, par exemple requestid=42,user=arthur.

--read-only

Définit le snapshot en lecture seule.

--read-write

Définit le snapshot en lecture-écriture.

--default

Définit le snapshot comme snapshot par défaut. Uniquement pour btrfs.

delete (remove|rm) numéro | numéro1-numéro2

Supprime un snapshot ou une plage de snapshots.

-s, --sync

Synchronise le système de fichiers après la suppression des snapshots. Les détails dépendent du type de système de fichiers.

Btrfs libère normalement l'espace de manière asynchrone après la suppression des snapshots. Avec cette option, snapper attendra que l'espace utilisé par les snapshots supprimés soit réellement disponible à nouveau.

Le snapshot 0 ne peut pas être supprimé. Pour btrfs, le snapshot actuellement monté et le snapshot qui sera monté la prochaine fois (le sous-volume par défaut de btrfs) ne peuvent pas non plus être supprimés.

mount numéro

Monte un snapshot. Non requis pour tous les types de systèmes de fichiers.

umount numéro

Démonte un snapshot. Non requis pour tous les types de systèmes de fichiers.

status [options] numéro1..numéro2

Compare les snapshots numéro1 et numéro2. Cela affichera une liste de fichiers et de répertoires qui ont été créés, modifiés ou supprimés entre le moment où les deux snapshots ont été créés.

-o, --output fichier

Écrit la sortie dans le fichier fichier.

La sortie se compose d'une chaîne codant le statut suivie du nom du fichier. Les caractères de la chaîne de statut sont :

1. Un "+" signifie que le fichier a été créé, un "-" signifie que le fichier a été supprimé. Un "c" signifie que le contenu du fichier a changé et un "t" signifie que le type de fichier a changé (par exemple, de fichier régulier à répertoire).
2. Un "p" signifie que les permissions ont changé.
3. Un "u" signifie que la propriété d'utilisateur a changé.
4. Un "g" signifie que la propriété de groupe a changé.
5. Un "x" signifie que les attributs étendus ont changé.
6. Un "a" signifie que les informations ACL ont changé.

S'il n'y a aucun changement, un "." est affiché.

diff [options] numéro1..numéro2 [fichiers]

Compare les snapshots numéro1 et numéro2. Cela affichera un diff du contenu des fichiers et répertoires qui ont été créés, modifiés ou supprimés entre le moment où les deux snapshots ont été créés.

-i, --input fichier

Lit les fichiers à comparer depuis le fichier fichier.

--diff-cmd commande

Commande utilisée pour comparer les fichiers. La valeur par défaut est /usr/bin/diff --new-file --unified. Les deux fichiers à comparer sont passés en paramètres à la commande.

-x, --extensions options

Options supplémentaires passées à la commande diff.

undochange [options] numéro1..numéro2 [fichiers]

Annule les modifications effectuées entre le snapshot numéro1 et numéro2.

-i, --input fichier

Lit les fichiers pour lesquels annuler les modifications depuis le fichier fichier.

rollback [options] [numéro]

Crée deux nouveaux snapshots et définit le sous-volume par défaut. Par défaut, le système démarre à partir du sous-volume par défaut du système de fichiers racine. Les actions exactes dépendent de la présence ou non d'un numéro :
•Sans numéro, un premier snapshot en lecture seule du sous-volume par défaut est créé. Un deuxième snapshot en lecture-écriture du système actuel est créé. Le système est configuré pour démarrer à partir du deuxième snapshot.
•Avec un numéro, un premier snapshot en lecture seule du système actuel est créé. Un deuxième snapshot en lecture-écriture est créé à partir du numéro. Le système est configuré pour démarrer à partir du deuxième snapshot.

Le rollback n'est pris en charge qu'avec btrfs et nécessite un système correctement configuré.

-p, --print-number

Affiche le numéro du deuxième snapshot créé.

-d, --description description

Description du snapshot.

-c, --cleanup-algorithm algorithme-nettoyage

Définit l'algorithme de nettoyage pour le snapshot.

-u, --userdata données-utilisateur

Définit les données utilisateur pour le snapshot. Les paires clé-valeur doivent être séparées par des virgules et la clé et la valeur doivent être séparées par un signe égal, par exemple requestid=42,user=arthur.

La commande rollback définit également la description, l'algorithme de nettoyage et certaines données utilisateur, sauf si les valeurs sont spécifiées sur la ligne de commande. Cela automatisera le nettoyage des snapshots créés par les rollbacks.

Dans d'autres contextes que le classique, la commande rollback effectue ce qui est nécessaire pour un rollback. Quoi qu'il en soit, il est recommandé d'utiliser des programmes spécifiques dans ce cas.

setup-quota

Configure le quota. Actuellement uniquement pris en charge avec btrfs.

cleanup [options] nettoyage-algorithme

Exécute l'algorithme de nettoyage cleanup-algorithm. Les algorithmes de nettoyage actuellement implémentés sont number, timeline et empty-pre-post. Pour exécuter tous les algorithmes de nettoyage, tous peuvent être fournis comme cleanup-algorithm.

--path chemin

Nettoie toutes les configurations affectant le chemin. Utile uniquement pour btrfs.

--free-space espace-libre

Essaie de libérer de l'espace-libre. Utile uniquement pour btrfs.

xadiff nombre1..nombre2 [fichiers]

Compare les attributs étendus entre le snapshot nombre1 et nombre2. Voir les exemples ci-dessous :
•+:user.foo pour les attributs créés
•-:user.bar pour les attributs supprimés
•-+:security.selinux pour les attributs modifiés

AUTORISATIONS

Les utilisateurs non root peuvent être autorisés à utiliser une configuration en définissant ALLOW_USERS ou ALLOW_GROUPS dans le fichier de configuration. Pour que toutes les opérations fonctionnent, l'utilisateur doit également pouvoir lire et accéder au répertoire .snapshots à l'intérieur du sous-volume. Le répertoire .snapshots doit appartenir à root et ne doit pas être modifiable par quiconque d'autre.

Voici quelques méthodes pour y parvenir :

•Rendre le répertoire accessible à tous :

chmod a+rx .snapshots

•Rendre le répertoire accessible à un groupe auquel l'utilisateur appartient, par exemple :

chown :users .snapshots

•Rendre le répertoire accessible à l'utilisateur à l'aide des ACL, par exemple :

setfacl -m u:tux:rx .snapshots

La dernière méthode peut être effectuée par snapper, voir le paramètre SYNC_ACL dans snapper-configs(5).

PLUGINS

snapper peut exécuter des scripts externes après certaines actions. Les scripts doivent être placés dans /usr/lib/snapper/plugins. Le nom doit commencer par un chiffre, l'ordre d'exécution est alphabétique.

Le premier argument d'un script est l'action exécutée par snapper. Les actions suivantes sont définies :

create-config-pre sous-volume type-fs

Exécuté avant la création d'une nouvelle configuration

create-config-post sous-volume type-fs

Exécuté après la création d'une nouvelle configuration

delete-config-pre sous-volume type-fs

Exécuté avant la suppression d'une configuration

delete-config-post sous-volume type-fs

Exécuté après la suppression d'une configuration

create-snapshot-pre sous-volume type-fs numero-snapshot

Exécuté avant la création d'un nouveau snapshot

create-snapshot-post sous-volume type-fs numero-snapshot

Exécuté après la création d'un nouveau snapshot

modify-snapshot-pre sous-volume type-fs numero-snapshot

Exécuté avant la modification d'un snapshot

modify-snapshot-post sous-volume type-fs numero-snapshot

Exécuté après la modification d'un snapshot

delete-snapshot-pre sous-volume type-fs numero-snapshot

Exécuté avant la suppression d'un snapshot

delete-snapshot-post sous-volume type-fs numero-snapshot

Exécuté après la suppression d'un snapshot

set-read-only-pre sous-volume type-fs numero-snapshot

Exécuté avant qu'un snapshot ne soit défini en lecture seule ou en lecture-écriture

set-read-only-post sous-volume type-fs numero-snapshot

Exécuté après qu'un snapshot ait été défini en lecture seule ou en lecture-écriture

set-default-snapshot-pre sous-volume type-fs numero-snapshot

Exécuté avant que le snapshot par défaut ne soit modifié

set-default-snapshot-post sous-volume type-fs numero-snapshot

Exécuté après que le snapshot par défaut ait été modifié

rollback-post sous-volume type-fs ancien-numero-snapshot nouveau-numero-snapshot

Exécuté après un rollback

Plus d'actions et d'arguments peuvent être ajoutés à tout moment. L'utilisation de snapper dans les plugins n'est pas autorisée.

Il n'est pas défini si les plugins sont appelés depuis le client (snapper) ou le serveur (snapperd).

STATUT DE SORTIE

Normalement, le statut de sortie est 0. Si une erreur s'est produite, le statut de sortie est 1. C'est également une erreur si le statut de sortie d'un plugin n'est pas 0.

NOTES

Il n'existe aucun mécanisme pour garantir la cohérence des fichiers lors de la création d'un snapshot. Par exemple, les fichiers d'une base de données peuvent être incohérents pendant que la base de données est en cours d'exécution.

La cohérence après undochange n'est pas garantie. Par exemple, lorsque la création d'un utilisateur est annulée, il peut encore exister des fichiers appartenant à cet utilisateur.

La prise en charge des systèmes de fichiers individuels, du rollback et des attributs étendus sont des options de compilation et peuvent ne pas être disponibles.
