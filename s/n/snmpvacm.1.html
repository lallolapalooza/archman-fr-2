NOM

snmpvacm - crée et maintient des entrées de contrôle d'accès basé sur les vues SNMPv3 sur une entité réseau

SYNTAXE

snmpvacm [OPTIONS COMMUNES] AGENT createSec2Group MODELE NOM_SECURITE NOM_GROUPE
snmpvacm [OPTIONS COMMUNES] AGENT deleteSec2Group MODELE NOM_SECURITE
snmpvacm [OPTIONS COMMUNES] AGENT createView [-Ce] NOM SOUSARBRE MASQUE
snmpvacm [OPTIONS COMMUNES] AGENT deleteView NOM SOUSARBRE
snmpvacm [OPTIONS COMMUNES] AGENT createAccess NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU CORRESPONDANCE_CONTEXTE VUE_LECTURE VUE_ECRITURE VUE_NOTIFICATION
snmpvacm [OPTIONS COMMUNES] AGENT deleteAccess NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU
snmpvacm [OPTIONS COMMUNES] AGENT createAuth NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU TYPE_AUTH CORRESPONDANCE_CONTEXTE VUE
snmpvacm [OPTIONS COMMUNES] AGENT deleteAuth NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU TYPE_AUTH

DESCRIPTION

snmpvacm est une application SNMP qui peut être utilisée pour effectuer une maintenance simple sur les tables du module de contrôle basé sur les vues (VACM) d'un agent SNMP. Les spécifications VACM de SNMPv3 (voir RFC2575) définissent diverses tables pour spécifier des groupes d'utilisateurs, des vues MIB et des paramètres d'accès autorisés. Ces commandes snmpvacm créent ou suppriment efficacement des lignes dans la table appropriée parmi celles-ci, et correspondent aux directives de configuration équivalentes qui sont documentées dans la page de manuel de snmpd.conf(5).

Une explication plus complète de leur fonctionnement peut être trouvée dans la FAQ du projet.

SOUS-COMMANDES

createSec2Group MODELE NOM_SECURITE NOM_GROUPE

Crée une entrée dans la table de nom de sécurité vers groupe SNMPv3. Cette table permet d'appliquer une entrée de contrôle d'accès unique à un certain nombre d'utilisateurs (ou 'principaux'), et est indexée par le modèle de sécurité et les valeurs du nom de sécurité.

MODELE

Un entier représentant le modèle de sécurité, prenant l'une des valeurs suivantes :
1 - réservé pour SNMPv1
2 - réservé pour SNMPv2c
3 - Modèle de sécurité basé sur l'utilisateur (USM)

NOM_SECURITE

Une chaîne représentant le nom de sécurité d'un principal (représenté dans un format indépendant du modèle de sécurité). Pour les requêtes basées sur l'USM, le nom de sécurité est le même que le nom d'utilisateur.

NOM_GROUPE

Une chaîne identifiant le groupe auquel cette entrée (c'est-à-dire la paire nom de sécurité/modèle) doit appartenir. Ce nom de groupe sera ensuite référencé dans la table d'accès (voir createAccess ci-dessous).

deleteSec2Group MODELE NOM_SECURITE

Supprime une entrée de la table de nom de sécurité vers groupe SNMPv3, retirant ainsi les paramètres de contrôle d'accès pour le principal donné. L'entrée à supprimer est indexée par les valeurs MODELE et NOM_SECURITE, qui doivent correspondre à celles utilisées dans la commande createSec2Group correspondante (ou équivalente).

createView [-Ce] NOM SOUSARBRE MASQUE

Crée une entrée dans la table de vues MIB SNMPv3. Une vue MIB se compose d'une famille de sous-arbres de vues qui peuvent être individuellement inclus dans ou (occasionnellement) exclus de la vue. Chaque sous-arbre de vue est défini par une combinaison d'un sous-arbre OID et d'un masque de chaîne binaire. La table de vues est indexée par le nom de la vue et les valeurs OID du sous-arbre.

[-Ce]

Un indicateur optionnel pour indiquer que ce sous-arbre de vue doit être exclu de la vue nommée. S'il n'est pas spécifié, la valeur par défaut est d'inclure le sous-arbre dans la vue. Lors de la construction d'une vue à partir d'un mélange de sous-arbres inclus et exclus, les sous-arbres exclus devraient être définis en premier - particulièrement si la vue nommée est déjà référencée dans une ou plusieurs entrées d'accès.

NOM

Une chaîne identifiant une vue MIB particulière, dont ce sous-arbre OID/masque fait partie (peut-être la seule partie).

SOUSARBRE

L'OID définissant la racine du sous-arbre à ajouter (ou à exclure) de la vue nommée.

MASQUE

Un masque binaire indiquant quels sous-identifiants de l'OID du sous-arbre associé doivent être considérés comme significatifs.

deleteView NOM SOUSARBRE

Supprime une entrée de la table de vues SNMPv3, retirant ainsi le sous-arbre de la vue MIB donnée. La suppression du sous-arbre final (ou unique) entraînera la suppression de la vue. L'entrée à supprimer est indexée par les valeurs NOM et SOUSARBRE, qui doivent correspondre à celles utilisées dans la commande createView correspondante (ou équivalente).

Lors de la suppression de sous-arbres d'une vue mixte (c'est-à-dire contenant des sous-arbres inclus et exclus), les sous-arbres inclus doivent être supprimés en premier.

createAccess NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU CORRESPONDANCE_CONTEXTE VUE_LECTURE VUE_ECRITURE VUE_NOTIFICATION

Crée une entrée dans la table d'accès SNMPv3, permettant ainsi un certain niveau d'accès à des vues MIB particulières pour les principaux du groupe spécifié (en fournissant un modèle de sécurité et des niveaux appropriés dans la requête). La table d'accès est indexée par le nom du groupe, le préfixe du contexte, le modèle de sécurité et les valeurs du niveau de sécurité.

NOM_GROUPE

Le nom du groupe auquel cette entrée d'accès s'applique (tel que défini par une commande createSec2Group, ou équivalent)

PREFIX_CONTEXTE

Une chaîne représentant un nom de contexte (ou une collection de noms de contexte) auquel cette entrée d'accès s'applique. L'interprétation de cette chaîne dépend de la valeur du champ CORRESPONDANCE_CONTEXTE (voir ci-dessous).
Si omis, cela prendra par défaut le contexte nul "".

MODELE

Un entier représentant le modèle de sécurité, prenant l'une des valeurs suivantes :
1 - réservé pour SNMPv1
2 - réservé pour SNMPv2c
3 - Modèle de sécurité basé sur l'utilisateur (USM)

NIVEAU

Un entier représentant le niveau de sécurité minimal, prenant l'une des valeurs suivantes :
1 - noAuthNoPriv
2 - authNoPriv
3 - authPriv
Cette entrée d'accès sera appliquée aux requêtes de ce niveau ou supérieur (où authPriv est supérieur à authNoPriv, qui est lui-même supérieur à noAuthNoPriv).

CORRESPONDANCE_CONTEXTE

Indique comment interpréter la valeur PREFIX_CONTEXTE. Si ce champ a la valeur '1' (représentant 'exact') alors le nom du contexte d'une requête doit correspondre exactement à la valeur PREFIX_CONTEXTE pour que cette entrée d'accès soit applicable à cette requête.
Si ce champ a la valeur '2' (représentant 'préfixe') alors la sous-chaîne initiale du nom du contexte d'une requête doit correspondre à la valeur PREFIX_CONTEXTE pour que cette entrée d'accès soit applicable à cette requête. Cela fournit une forme simple de joker.

VUE_LECTURE

Le nom de la vue MIB (tel que défini par createView ou équivalent) définissant les objets MIB pour lesquels cette requête peut demander les valeurs actuelles.
S'il n'y a pas de vue avec ce nom, alors l'accès en lecture n'est pas accordé.

VUE_ECRITURE

Le nom de la vue MIB (tel que défini par createView ou équivalent) définissant les objets MIB pour lesquels cette requête peut potentiellement définir de nouvelles valeurs.
S'il n'y a pas de vue avec ce nom, alors l'accès en lecture n'est pas accordé.

VUE_NOTIFICATION

Le nom de la vue MIB (tel que défini par createView ou équivalent) définissant les objets MIB qui peuvent être inclus dans une requête de notification.
S'il n'y a pas de vue avec ce nom, alors l'accès aux notifications n'est pas accordé.

deleteAccess NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU

Supprime une entrée de la table d'accès SNMPv3, retirant ainsi les paramètres d'autorisation d'accès pour le groupe donné. L'entrée à supprimer est indexée par les valeurs NOM_GROUPE, PREFIX_CONTEXTE, MODELE et NIVEAU, qui doivent correspondre à celles utilisées dans la commande createAccess correspondante (ou équivalente).

createAuth NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU TYPE_AUTH CORRESPONDANCE_CONTEXTE VUE

Crée une entrée dans la table d'autorisation SNMPv3. Cette table est principalement utilisée pour les vues d'authentification et de déchiffrement pour les modèles de sécurité basés sur les utilisateurs (USM) et les modèles de sécurité non authentifiés (SNMPv1/v2c). La table d'autorisation est indexée par le nom du groupe, le préfixe du contexte, le modèle de sécurité et le niveau de sécurité.

NOM_GROUPE

Le nom du groupe auquel cette entrée d'autorisation s'applique (tel que défini par une commande createSec2Group, ou équivalent)

PREFIX_CONTEXTE

Voir la description pour createAccess ci-dessus.

MODELE

Voir la description pour createAccess ci-dessus.

NIVEAU

Voir la description pour createAccess ci-dessus.

TYPE_AUTH

Une chaîne représentant le type d'authentification ou de déchiffrement qui doit être utilisé. Les valeurs possibles sont :
'authPriv' - pour les requêtes qui utilisent à la fois l'authentification et le chiffrement.
'authNoPriv' - pour les requêtes qui utilisent l'authentification mais pas le chiffrement.
'noAuthNoPriv' - pour les requêtes qui n'utilisent ni l'authentification ni le chiffrement.

CORRESPONDANCE_CONTEXTE

Voir la description pour createAccess ci-dessus.

VUE

Le nom de la vue MIB (tel que défini par createView ou équivalent) définissant les objets MIB pour lesquels le principal est autorisé à effectuer les opérations spécifiées par le TYPE_AUTH.

deleteAuth NOM_GROUPE [PREFIX_CONTEXTE] MODELE NIVEAU TYPE_AUTH

Supprime une entrée de la table d'autorisation SNMPv3. L'entrée à supprimer est indexée par les valeurs NOM_GROUPE, PREFIX_CONTEXTE, MODELE, NIVEAU et TYPE_AUTH, qui doivent correspondre à celles utilisées dans la commande createAuth correspondante (ou équivalente).

OPTIONS COMMUNES

Voir snmpcmd(5) pour une liste des options communes et leur signification.

EXEMPLES

Pour créer une entrée qui mappe le nom d'utilisateur 'fred' dans le modèle USM (3) au groupe 'admins' :

snmpvacm localhost createSec2Group 3 fred admins

Pour créer une vue nommée 'myView' qui inclut le sous-arbre 1.3.6.1.2.1.1, en utilisant un masque de "tout significatif" :

snmpvacm localhost createView myView 1.3.6.1.2.1.1 "ff"

Pour créer une autre vue nommée 'myView' qui exclut le sous-arbre 1.3.6.1.2.1.1.5 (sysName) :

snmpvacm localhost createView -Ce myView 1.3.6.1.2.1.1.5 "ff"

Pour autoriser les membres du groupe 'admins' à lire les objets dans la vue 'myView' pour le modèle USM (3) avec le niveau 'noAuthNoPriv' (1) dans le contexte par défaut :

snmpvacm localhost createAccess admins 3 1 "" myView none none

Pour autoriser les membres du groupe 'admins' à écrire dans les objets de la vue 'myView' pour le modèle USM (3) avec le niveau 'authPriv' (3) dans le contexte par défaut :

snmpvacm localhost createAccess admins 3 3 "" none myView none

Pour autoriser les membres du groupe 'admins' à recevoir des notifications concernant les objets dans la vue 'myView' pour le modèle USM (3) avec le niveau 'authNoPriv' (2) dans le contexte par défaut :

snmpvacm localhost createAccess admins 3 2 "" none none myView

Pour supprimer la vue nommée 'myView' qui exclut le sous-arbre 1.3.6.1.2.1.1.5 :

snmpvacm localhost deleteView myView 1.3.6.1.2.1.1.5

Pour supprimer la vue nommée 'myView' qui inclut le sous-arbre 1.3.6.1.2.1.1 :

snmpvacm localhost deleteView myView 1.3.6.1.2.1.1

Pour supprimer l'entrée qui mappe le nom d'utilisateur 'fred' du modèle USM (3) au groupe 'admins' :

snmpvacm localhost deleteSec2Group 3 fred

Pour supprimer l'autorisation de lecture pour le groupe 'admins' dans le contexte par défaut, pour le modèle USM (3) et le niveau 'noAuthNoPriv' (1) :

snmpvacm localhost deleteAccess admins 3 1 "" myView none none

CONFORMITÉ

Cette commande est conforme à la RFC2575.

deleteAccess GROUPNAME [CONTEXTPREFIX] MODEL LEVEL

Supprime une entrée de la table d'accès SNMPv3, supprimant ainsi les paramètres de contrôle d'accès spécifiés. L'entrée à supprimer est indexée par le nom du groupe, le préfixe de contexte, le modèle de sécurité et les valeurs de niveau de sécurité, qui doivent correspondre à ceux utilisés dans la commande createAccess correspondante (ou équivalent).

createAuth GROUPNAME [CONTEXTPREFIX] MODEL LEVEL AUTHTYPE CONTEXTMATCH VIEW

Crée une entrée dans l'extension Net-SNMP à la table d'accès standard, permettant ainsi un certain type d'accès à la vue MIB pour les principaux du groupe spécifié. L'interprétation de GROUPNAME, CONTEXTPREFIX, MODEL, LEVEL et CONTEXTMATCH est la même que pour la directive createAccess. La table d'accès d'extension est indexée par le nom du groupe, le préfixe de contexte, le modèle de sécurité, le niveau de sécurité et les valeurs authtype.

AUTHTYPE

Le style d'accès auquel cette entrée doit s'appliquer. Voir snmpd.conf(5) et snmptrapd.conf(5) pour les détails des jetons valides.

VIEW

Le nom de la vue MIB (telle que configurée par createView ou équivalent) définissant les objets MIB pour lesquels ce style d'accès est autorisé.

deleteAuth GROUPNAME [CONTEXTPREFIX] MODEL LEVEL AUTHTYPE

Supprime une entrée de la table d'accès d'extension, supprimant ainsi les paramètres de contrôle d'accès spécifiés. L'entrée à supprimer est indexée par le nom du groupe, le préfixe de contexte, le modèle de sécurité, le niveau de sécurité et les valeurs authtype, qui doivent correspondre à ceux utilisés dans la commande createAuth correspondante (ou équivalent).

Notez que snmpget EXIGE un argument spécifiant l'agent à interroger, comme décrit dans la page de manuel .I snmpcmd(1).

EXEMPLES

Étant donné un utilisateur préexistant dave (qui pourrait être configuré à l'aide de la commande snmpusm(1) ), nous pourrions configurer un accès complet en lecture-écriture à l'arborescence OID complète à l'aide des commandes :

snmpvacm localhost createSec2Group 3 dave RWGroup
snmpvacm localhost createView all .1 80
snmpvacm localhost createAccess RWGroup 3 1 1 all all none

Ceci crée un nouveau groupe de sécurité nommé "RWGroup" contenant l'utilisateur SNMPv3 "dave", une nouvelle vue "all" contenant l'arborescence OID complète basée sur .iso(1) , puis autorise ces utilisateurs du groupe "RWGroup" (c'est-à-dire "dave") un accès en lecture et en écriture à la vue "all" (c'est-à-dire l'arborescence OID complète) lors de l'utilisation de requêtes SNMPv3 authentifiées.

Comme deuxième exemple, nous pourrions configurer un accès en lecture seule à une partie de l'arborescence OID à l'aide des commandes :

snmpvacm localhost createSec2Group 3 wes ROGroup
snmpvacm localhost createView sysView system fe
snmpvacm localhost createAccess ROGroup 3 0 1 sysView none none

Ceci crée un nouveau groupe de sécurité nommé "ROGroup" contenant l'utilisateur "wes" (préexistant), une nouvelle vue "sysView" contenant uniquement l'arborescence OID basée sur .iso(1).org(3).dod(6).inet(1).mgmt(2).mib-2(1).system(1) , puis autorise ces utilisateurs du groupe "ROGroup" (c'est-à-dire "wes") un accès en lecture, mais pas en écriture, à la vue "sysView" (c'est-à-dire le groupe système).

STATUT DE SORTIE

Les valeurs de sortie suivantes sont renvoyées :

0 - Achèvement réussi

1 - Une erreur de syntaxe d'utilisation (qui affiche un message d'utilisation approprié) ou un délai d'attente de requête.

2 - Une erreur s'est produite lors de l'exécution de la commande (qui affiche également un message d'erreur approprié).

LIMITATIONS

Cet utilitaire ne prend pas en charge la configuration de nouvelles chaînes de communauté, il n'est donc utile que pour la configuration d'un nouveau contrôle d'accès pour les requêtes SNMPv3. Il peut être utilisé pour modifier les paramètres d'accès des chaînes de communauté existantes, mais pas pour en configurer de nouvelles.

L'utilisation de paramètres numériques pour les paramètres secLevel et contextMatch est moins intuitive. Ces commandes ne fournissent pas la flexibilité complète des directives de fichier de configuration équivalentes.

Il n'y a (actuellement) pas d'équivalent aux directives de configuration en une seule fois rouser et rwuser.
