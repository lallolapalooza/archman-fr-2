NOM

snmpbulkwalk - récupérer un sous-arbre de valeurs de gestion en utilisant les requêtes SNMP GETBULK

SYNTAXE

snmpbulkwalk [OPTIONS_APPLICATION] [OPTIONS_COMMUNES] AGENT [OID]

DESCRIPTION

snmpbulkwalk est une application SNMP qui utilise les requêtes SNMP GETBULK pour interroger efficacement une entité réseau pour un arbre d'informations.

Un identifiant d'objet (OID) peut être fourni sur la ligne de commande. Cet OID spécifie quelle partie de l'espace des identifiants d'objets sera recherchée à l'aide des requêtes GETBULK. Toutes les variables dans le sous-arbre sous l'OID donné sont interrogées et leurs valeurs présentées à l'utilisateur. Chaque nom de variable est donné dans le format spécifié dans variables(5). Si aucun argument OID n'est présent, snmpbulkwalk recherchera dans MIB-2.

Si l'entité réseau a une erreur lors du traitement du paquet de requête, un paquet d'erreur sera renvoyé et un message sera affiché, aidant à identifier la raison pour laquelle la requête était malformée.

Si la recherche dans l'arbre provoque des tentatives de recherche au-delà de la fin de la MIB, le message "End of MIB" sera affiché.

OPTIONS

-Cc
Ne pas vérifier si les OID retournés sont croissants. Certains agents (les LaserJet en sont un exemple) renvoient les OID dans le désordre, mais peuvent quand même terminer la requête. D'autres agents renvoient les OID dans le désordre et peuvent provoquer une boucle indéfinie de snmpbulkwalk. Par défaut, snmpbulkwalk essaie de détecter ce comportement et vous avertit lorsqu'il rencontre un agent agissant illégalement. Utilisez -Cc pour désactiver ce comportement.
-Ci
Inclure l'OID donné dans la plage de recherche. Normalement, snmpbulkwalk utilise des requêtes GETBULK à partir de l'OID que vous avez spécifié et renvoie tous les résultats dans l'arbre MIB après cet OID. Parfois, vous pourriez souhaiter inclure l'OID spécifié sur la ligne de commande dans les résultats imprimés s'il s'agit d'un OID valide dans l'arbre lui-même. Cette option vous permet de le faire.
-Cn<NUM>
Définir le champ non-repeaters dans les PDU GETBULK. Cela spécifie le nombre de variables fournies qui ne doivent pas être itérées. La valeur par défaut est 0.
-Cp
À la fin de la requête, afficher le nombre de variables trouvées.
-Cr<NUM>
Définir le champ max-repetitions dans les PDU GETBULK. Cela spécifie le nombre maximum d'itérations sur les variables répétitives. La valeur par défaut est 10.

En plus de ces options, snmpbulkwalk utilise les options communes décrites dans la page de manuel snmpcmd(1). Notez que snmpbulkget REQUIERT un argument spécifiant l'agent à interroger et au plus un argument OID, comme décrit ci-dessus.

EXEMPLE

La commande :

snmpbulkwalk -v2c -Os -c public zeus system

récupérera toutes les variables sous system :

sysDescr.0 = STRING: "SunOS zeus.net.cmu.edu 4.1.3_U1 1 sun4m"
sysObjectID.0 = OID: enterprises.hp.nm.hpsystem.10.1.1
sysUpTime.0 = Timeticks: (155274552) 17 jours, 23:19:05
sysContact.0 = STRING: ""
sysName.0 = STRING: "zeus.net.cmu.edu"
sysLocation.0 = STRING: ""
sysServices.0 = INTEGER: 72

Contrairement à snmpwalk, ces informations seront généralement recueillies en une seule transaction avec l'agent, plutôt qu'une transaction par variable trouvée. snmpbulkwalk est donc plus efficace en termes d'utilisation du réseau, ce qui peut être particulièrement important lors de la récupération de grandes tables.

NOTE

Comme son nom l'indique, snmpbulkwalk utilise le message SNMP GETBULK, qui n'est pas disponible dans SNMP v1.

VOIR AUSSI

snmpcmd(1), variables(5).
