Cette page vous guidera dans le processus de configuration de votre environnement et de lancement de votre première enquête.

Ajouter quelque chose à la portée

Vous voudrez probablement séparer vos enquêtes, vous devriez donc sélectionner un espace de travail où vos résultats iront :

[sn0int][default] > workspace demo
[+] Connexion à la base de données
[sn0int][demo] >

Ensuite, nous devons commencer quelque part et ajouter la première entité à notre portée :

[sn0int][demo] > add domain
Domain: example.com
[sn0int][demo] >

REMARQUE :

Il existe un concept de domaine par rapport à sous-domaine. Nous faisons référence à un domaine comme tout ce qui est un sous-domaine d'un suffixe public. Par exemple, .com est un suffixe public, ce qui fait de example.com un domaine selon les termes de sn0int. Tout sous-domaine de celui-ci, comme www.example.com, est appelé sous-domaine.

Notez que example.com peut également être ajouté en tant que sous-domaine car il peut contenir des enregistrements. Dans ce cas, example.com est à la fois le nom de la zone DNS et une entité dans cette zone.

Vous pouvez le confirmer en exécutant une sélection sur les domaines que nous avons maintenant :

[sn0int][demo] > select domains
#1, "example.com"
[sn0int][demo] >

Quelque chose dont nous n'avons pas besoin maintenant, mais qui sera utile plus tard, est la capacité de filtrer vos entités :

[sn0int][demo] > select domains where id=1
#1, "example.com"
[sn0int][demo] >
[sn0int][demo] > select domains where value like %.com
#1, "example.com"
[sn0int][demo] >
[sn0int][demo] > select domains where ( value like e% and value like %m ) or false
#1, "example.com"
[sn0int][demo] >

REMARQUE :

Presque toutes les entités ont une colonne value qui contient la valeur principale de l'entité.

Déscoping des entités

Vous rencontrerez le fait que les modules sont trop avides et ajoutent des éléments à la portée dont nous ne nous intéressons pas. Vous pouvez les supprimer en utilisant la commande delete, mais ils seront probablement récupérés par un module à nouveau.

Ce que vous pouvez faire à la place est de définir un indicateur sur une entité qui la retire de notre portée. Ceci est fait en utilisant la commande noscope :

[sn0int][demo] > use ctlogs
[sn0int][demo][kpcyrd/ctlogs] > target
#1, "example.com"
[sn0int][demo][kpcyrd/ctlogs] > add domain
Domain: google.com
[sn0int][demo][kpcyrd/ctlogs] > target
#1, "example.com"
#2, "google.com"
[sn0int][demo][kpcyrd/ctlogs] > noscope domains where value=google.com
[+] Mise à jour de 1 lignes
[sn0int][demo][kpcyrd/ctlogs] > target
#1, "example.com"
[sn0int][demo][kpcyrd/ctlogs] >

Les entités qui sont hors portée sont automatiquement ignorées par tous les modules.

Vous pouvez inverser cela en utilisant la commande scope :

[sn0int][demo][kpcyrd/ctlogs] > target
#1, "example.com"
[sn0int][demo][kpcyrd/ctlogs] > scope domains where true
[+] Mise à jour de 2 lignes
[sn0int][demo][kpcyrd/ctlogs] > target
#1, "example.com"
#2, "google.com"
[sn0int][demo][kpcyrd/ctlogs] >

INDICE :

Toutes les entités ont ce champ, vous pouvez y faire référence dans les requêtes en utilisant unscoped=1.

CONFIGURATION

Cette section documente le fichier de configuration. Par défaut, ce fichier n'existe pas et une configuration par défaut est utilisée à la place.

Linux/BSD
~/.config/sn0int.toml
OSX
~/Library/Preferences/sn0int.toml
Windows
%APPDATA%/sn0int.toml

[core]

registry
Configurez le registre que vous souhaitez utiliser. Par défaut : https://sn0int.com.
no-autoupdate
sn0int vérifiait si vos modules étaient obsolètes au démarrage une fois par semaine. Définissez cette option sur true pour désactiver cela.

[namespaces]

Par défaut, les modules sn0int sont supposés être installés depuis le registre. Vous voudrez peut-être conserver un répertoire local avec des modules privés, en particulier pendant le développement. Vous pouvez configurer un dossier contenant des modules qui ne sont pas gérés par sn0int en ajoutant une section namespaces au fichier de configuration :

[namespaces]
foo = "/opt/sn0int/foo"
bar = "~/repos/a/b/c/sn0int-modules"

Cela chargera les modules de ces deux dossiers et les enregistrera dans les espaces de noms foo et bar.

Notez que sn0int supposera également que les liens symboliques dans ~/.local/share/sn0int/modules et les dossiers contenant un dossier .git sont gérés en externe.

[network]

Pour activer un proxy, ajoutez ce qui suit à votre fichier de configuration :

[network]
proxy = "127.0.0.1:9050"

Cela force tout via tor (ou tout autre proxy socks5) et restreint toutes les autres fonctions qui dépendent du réseau. Par exemple, la fonction dns est complètement désactivée si un proxy est configuré.

RÉFÉRENCE DES FONCTIONS

asn_lookup

Exécute une recherche ASN pour une adresse IP donnée. La fonction renvoie asn et as_org. Cette fonction peut échouer.

lookup = asn_lookup('1.1.1.1')
if last_err() then return end

base64_decode

Décode une chaîne base64 avec l'alphabet par défaut + padding.

base64_decode("ww==")

base64_encode

Encode un tableau binaire en base64 avec l'alphabet par défaut + padding.

base64_encode("\x00\xff")

base64_custom_decode

Décode une chaîne base64 avec un alphabet personnalisé + padding.

-- base64
base64_custom_decode('b2hhaQ==', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/', '=')
-- base64 sans padding
base64_custom_decode('b2hhaQ', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/', '')
-- base64 url safe
base64_custom_decode('b2hhaQ==', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_', '=')

base64_custom_encode

Encode un tableau binaire en base64 avec un alphabet personnalisé + padding.

-- base64
base64_custom_encode('ohai', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/', '=')
-- base64 sans padding
base64_custom_encode('ohai', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/', '')
-- base64 url safe
base64_custom_encode('ohai', 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_', '=')

base32_custom_decode

Décode une chaîne base32 avec un alphabet personnalisé + padding.

-- rfc-4648 base32
base32_custom_decode('N5UGC2I=', 'ABCDEFGHIJKLMNOPQRSTUVWXYZ234567', '=')
-- z-base-32
base32_custom_decode('p7wgn4e', 'ybndrfg8ejkmcpqxot1uwisza345h769', '')

base32_custom_encode

Encode un tableau binaire en base32 avec un alphabet personnalisé + padding.

-- rfc-4648 base32
x = base32_custom_encode('ohai', 'ABCDEFGHIJKLMNOPQRSTUVWXYZ234567', '=')
-- z-base-32
x = base32_custom_encode('ohai', 'ybndrfg8ejkmcpqxot1uwisza345h769', '')

clear_err

Efface la dernière erreur enregistrée de l'état interne. Voir aussi last_err.

if last_err() then
    -- ignorer cette erreur
    clear_err()
end

create_blob

Pousse un tableau d'octets dans un stockage blob persistant. Cela permet de passer ces octets aux fonctions opérant sur le stockage blob. Renvoie un identifiant de blob qui est déterministe basé sur le contenu du blob. Les blobs sont immuables.

blob = create_blob("quelques octets")
debug(blob)

datetime

Renvoie l'heure actuelle en UTC. Cette fonction est appropriée pour déterminer les dates et heures pour les champs de base de données DATETIME.

now = datetime()

NOTE :

Ce format est spécifique à sn0int, pour obtenir l'heure actuelle pour le scripting, utilisez plutôt time_unix.

AVERTISSEMENT :

Cette fonction sera dépréciée à un moment donné. Préférez sn0int_time pour les nouveaux scripts.

db_add

Ajoute une entité à la base de données ou la met à jour si elle existe déjà. Cette fonction peut échouer ou renvoyer nil. Voir db_add pour plus de détails.

domain_id = db_add('domain', {
    value='example.com',
})

db_add_ttl

Ajoute une entité temporaire à la base de données. Ceci est couramment utilisé pour insérer des liens temporaires qui expirent automatiquement avec le temps. Si l'entité existe déjà et est également marquée comme temporaire, le nouveau ttl remplacera l'ancien ttl. Si l'entité existe déjà mais n'expire jamais, nous n'ajouterons pas de ttl.

-- ce lien est valide pendant 2 minutes
domain_id = db_add_ttl('network-device', {
    network_id=1,
    device_id=13,
}, 120)

db_activity

Enregistre un événement d'activité. Un événement de base ressemble à ceci :

db_activity({
    topic='harness/activity-ping
:dummy', time=sn0int_time(), content={ a='b', foo={ bar=1337, }, msg='ohai', }, })

Cette fonction est expliquée en détail dans la section activity.

db_select

Vérifie si une cible est dans le champ d'application. Si une valeur non nulle est retournée, cette entité est dans le champ d'application. Cette fonction peut échouer. Voir db_select pour plus de détails.

domain_id = db_select('domain', 'example.com')
if domain_id ~= nil then
    -- do something
end

db_update

Met à jour une entité dans la base de données. Cette fonction peut échouer. Voir db_update pour plus de détails.

db_update('ipaddr', arg, {
    asn=lookup['asn'],
    as_org=lookup['as_org'],
})

dns

Résout un enregistrement DNS. Si la requête DNS a réussi et que la réponse DNS est NoError, alors x['error'] est nil. Les enregistrements de la réponse se trouvent dans x['answers']. Cette fonction peut échouer.

Cette fonction accepte les options suivantes :

record
Le query_type, peut être l'un des A, AAAA, MX, AXFR, etc.
nameserver
Le serveur qui doit être utilisé pour la recherche. Par défaut, le résolveur de votre système.
tcp
Si la recherche doit utiliser TCP, vrai/faux.
timeout
Le temps jusqu'à ce que la requête expire en millisecondes.
records = dns('example.com', {
    record='A',
})
if last_err() then return end
if records['error'] ~= nil then return end
records = records['answers']

NOTE :

Les réponses DNS avec un code d'erreur défini ne modifient pas last_err(). Vous devez tester cela explicitement.

NOTE :

Cette fonction n'est pas disponible si un proxy socks5 est configuré.

error

Enregistre une erreur dans le terminal.

error('ohai')

geoip_lookup

Exécute une recherche géoIP pour une adresse IP donnée. La fonction retourne :

  • continent
  • continent_code
  • country
  • country_code
  • city
  • latitude
  • longitude

Cette fonction peut échouer.

lookup = geoip_lookup('1.1.1.1')
if last_err() then return end

hex

Encode en hexadécimal une liste d'octets.

hex("\x6F\x68\x61\x69\x0A\x00")

hmac_md5

Calcule un hmac avec md5. Retourne un tableau binaire.

hmac_md5("secret", "my authenticated message")

hmac_sha1

Calcule un hmac avec sha1. Retourne un tableau binaire.

hmac_sha1("secret", "my authenticated message")

hmac_sha2_256

Calcule un hmac avec sha2_256. Retourne un tableau binaire.

hmac_sha2_256("secret", "my authenticated message")

hmac_sha2_512

Calcule un hmac avec sha2_512. Retourne un tableau binaire.

hmac_sha2_512("secret", "my authenticated message")

hmac_sha3_256

Calcule un hmac avec sha3_256. Retourne un tableau binaire.

hmac_sha3_256("secret", "my authenticated message")

hmac_sha3_512

Calcule un hmac avec sha3_512. Retourne un tableau binaire.

hmac_sha3_512("secret", "my authenticated message")

html_select

Analyse un document HTML et retourne le premier élément qui correspond au sélecteur CSS. La valeur de retour est une table avec text pour le texte interne et attrs pour une table des attributs de l'élément.

csrf = html_select(html, 'input[name="csrf"]')
token = csrf["attrs"]["value"]

html_select_list

Identique à html_select mais retourne toutes les correspondances au lieu de la première.

html_select_list(html, 'input[name="csrf"]')

http_mksession

Crée un objet session. Ceci est similaire à requests.Session en python-requests et garde une trace des cookies.

session = http_mksession()

http_request

Prépare une requête HTTP. Le premier argument est la référence de la session et les cookies de cette session sont copiés dans la requête. Une fois la requête envoyée, les cookies de la réponse sont copiés dans la session.

Les arguments suivants sont la méthode, l'URL et des options supplémentaires. Veuillez noter que vous devez toujours spécifier une table vide {} même si aucune option n'est définie. Les options suivantes sont disponibles :

query
Une carte de paramètres de requête qui doivent être définis sur l'URL.
headers
Une carte d'en-têtes qui doivent être définis.
basic_auth
Configure l'en-tête d'authentification de base avec {"user, "password"}.
user_agent
Remplace l'agent utilisateur par défaut par une chaîne.
json
Le corps de la requête qui doit être encodé en JSON.
form
Le corps de la requête qui doit être encodé en formulaire.
follow_redirects
Suit automatiquement les redirections, jusqu'au nombre spécifié. Si défini sur 1, une seule redirection sera suivie. Par défaut, 0, donc les redirections ne sont pas suivies.
body
Le corps brut de la requête sous forme de chaîne.
into_blob
Si vrai, le corps de la réponse est stocké dans le stockage blob et une référence de blob est retournée sous blob au lieu du corps complet.
proxy
Utilise un proxy socks5 au format 127.0.0.1:9050. Cette option ne fonctionne que si elle n'entre pas en conflit avec les paramètres globaux du proxy.
binary
Défini sur true pour obtenir la réponse HTTP sous forme d'octets bruts.

Cette fonction peut échouer.

req = http_request(session, 'POST', 'https://httpbin.org/post', {
    json={
        user=user,
        password=password,
    }
})
resp = http_send(req)
if last_err() then return end
if resp['status'] ~= 200 then return 'http status error: ' .. resp['status'] end

http_send

Envoie la requête qui a été construite avec http_request. Retourne une table avec les clés suivantes :

status
Le code de statut HTTP.
headers
Une table d'en-têtes.
text
Le corps de la réponse sous forme de chaîne.
binary
Le corps de la réponse sous forme d'octets (si binary=true).
blob
Si into_blob était activé pour la requête, le corps est téléchargé dans le stockage blob avec une référence au corps dans ce champ.
req = http_request(session, 'POST', 'https://httpbin.org/post', {
    json={
        user=user,
        password=password,
    }
})
resp = http_send(req)
if last_err() then return end
if resp['status'] ~= 200 then return 'http status error: ' .. resp['status'] end

http_fetch

Effectue un http_send et valide également automatiquement le code de statut.

NOTE :

Vous voudrez presque toujours ceci lorsque vous définissez l'option into_blob car cette fonction vali
dates the status code avant d'insérer le corps de la réponse dans le stockage blob.
-- forme courte
data = http_fetch(req)
if last_err() then return end
-- forme longue
resp = http_send(req)
if last_err() then return end
if resp['status'] ~= 200 then return 'erreur de statut http: ' .. resp['status'] end

http_fetch_json

Identique à http_fetch mais analyse également automatiquement le corps de la réponse en tant que json.

-- forme courte
data = http_fetch_json(req)
if last_err() then return end
-- forme longue
resp = http_send(req)
if last_err() then return end
if resp['status'] ~= 200 then return 'erreur de statut http: ' .. resp['status'] end
data = json_decode(resp['text'])
if last_err() then return end

img_load

Tente de décoder un blob en tant qu'image et renvoie des métadonnées de base comme le type mime, la hauteur et la largeur.

img = img_load(blob)
if last_err() then return end
debug(img)

img_exif

Extrait les métadonnées exif d'une image.

exif = img_exif(blob)
if last_err() then return end
debug(exif)

img_ahash

Calcule le hachage perceptuel moyen (aHash).

hash = img_ahash(blob)

xml_decode

                        
Decode a lua value from an xml document.

                        

                            

                                
x = xml_decode('<body><foo fizz="buzz">bar</foo></body>')
if last_err() then return end
body = x['children'][1]
foo = body['children'][1]
print(foo['attrs']['fizz'])
print(foo['text'])

                            

                        

                    

                    

                        
xml_named

                        
Get a named child element from a parent element.

                        

                            

                                
x = xml_decode('<body><foo fizz="buzz">bar</foo></body>')
if last_err() then return end
body = x['children'][1]
foo = xml_named(body, 'foo')
if foo ~= nil then
    print(foo)
end
