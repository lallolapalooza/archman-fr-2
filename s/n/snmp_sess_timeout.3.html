struct snmp_pdu *pdu,
snmp_callback callback,
void *callbackData);

int snmp_sess_select_info(void *handle,
int *numfds, fd_set *fdset,

void snmp_sess_timeout(void *handle);

int snmp_sess_synch_response ( void *handle,

netsnmp_pdu *pdu,
netsnmp_pdu **response);

int snmp_sess_close(void *handle);

void snmp_sess_error(void *handle, int *pcliberr,
int *psnmperr, char **pperrstring);

DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multithread. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui source les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Une fois cette structure passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Le pointeur opaque renvoyé par snmp_sess_open() est plutôt utilisé pour faire référence à cette session par la suite.

Les sessions SNMP créées avec snmp_sess_open() ne sont pas affectées par, et NE DOIVENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Les fonctions équivalentes à session unique décrites ici doivent plutôt être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacun en entrée un pointeur vers un objet de structure snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et renvoie un pointeur vers sa structure snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacun un paramètre pdu, qui pointe vers un objet de structure snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read appellera le callback spécifié lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela peut inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent respectivement aux arguments nfds, readfds et timeout de select(2). La seule exception est que timeout doit TOUJOURS pointer vers un struct timeval alloué (mais peut-être non initialisé) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est à la place défini à vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données renvoyées. Lors de son retour, snmp_sess_read() doit ensuite être appelé avec le fd_set renvoyé par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire qu'il renvoie zéro), snmp_sess_timeout() doit être appelé pour vérifier si une expiration s'est produite sur la session SNMP.

snmp_sess_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour les détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut réussi renverra 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction renvoie la variable SNMP snmp_errno, la valeur de la variable système errno, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs renvoyées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

NAME

snmp_sess_timeout, snmp_sess_init, snmp_sess_send, snmp_sess_read, snmp_sess_close, snmp_sess_error - SNMP session interface

SYNOPSIS

#include <net-snmp/session.h>
int
snmp_sess_timeout(struct snmp_session *session);
int
snmp_sess_init(struct snmp_session *session);
int
snmp_sess_send(struct snmp_session *session, struct snmp_pdu *pdu);
struct snmp_pdu *
snmp_sess_read(struct snmp_session *session);
int
snmp_sess_close(struct snmp_session *session);
int
snmp_sess_error(struct snmp_session *session, int *optlen,
    char *optarg);

DESCRIPTION

The Net-SNMP library provides a collection of functions for applications to communicate with SNMP agents or managers.

The main interface is based around a struct snmp_session structure, which describes the parameters for an SNMP session (e.g., hostname, community string, SNMP version).

The basic workflow is:

1.
Fill in a struct snmp_session structure with the appropriate details for the session. See the example in netsnmp_session_api(3).
2.
snmp_sess_init() is called to establish the session with the agent.
3.
Use snmp_sess_send() to send an SNMP PDU (Protocol Data Unit) to the agent.
4.
snmp_sess_read() is called to wait for and read a response from the agent.
5.
snmp_sess_close() is called to terminate the session.

The struct snmp_session structure contains various fields that can be configured to set up the session. The most important ones are:

session->version
The SNMP version to use (e.g. SNMP_VERSION_1, SNMP_VERSION_2c, SNMP_VERSION_3).
session->peername
The hostname or IP address of the remote SNMP entity.
session->community
The community string for SNMPv1 and SNMPv2c communications.
session->timeout
The timeout value for requests, in microseconds.
session->retries
The number of retries to attempt for requests.

Refer to netsnmp_session_api(3) for a complete description of the struct snmp_session members and other related functions.

snmp_sess_timeout() returns 1 if the session's timeout value has expired, and 0 otherwise. This function is typically used with non-blocking I/O to check if a timeout has occurred before attempting to read or send data.

snmp_sess_init() initializes an SNMP session based on the parameters specified in the session structure. It returns 1 on success and 0 on failure. If it fails, snmp_sess_error() can be used to retrieve error information.

snmp_sess_send() sends the PDU specified by pdu over the session. It returns 1 on success and 0 on failure.

snmp_sess_read() waits for and reads an SNMP PDU from the session. It returns a pointer to the received PDU on success, or NULL on failure or if no PDU is currently available (in non-blocking mode). The caller is responsible for freeing the returned PDU using snmp_free_pdu.

snmp_sess_close() closes the SNMP session and frees any associated resources. It returns 1 on success and 0 on failure.

snmp_sess_error() retrieves error information related to the session. If optlen is not NULL, it is set to the length of the error message, and if optarg is not NULL, the error message is copied into it. The size of optarg should be sufficient to hold the error message.

DIAGNOSTICS

The following error codes can be returned by the session functions:

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
