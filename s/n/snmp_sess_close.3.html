DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multi-threadée. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur de type session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure `struct snmp_session` qui contient les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure a été passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Au lieu de cela, le pointeur opaque retourné par snmp_sess_open() est utilisé pour référencer cette session dorénavant.

Les sessions SNMP créées avec snmp_sess_open() ne sont pas affectées par, et NE DOIVENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Il faut plutôt utiliser les fonctions équivalentes pour session unique décrites ici.

snmp_sess_init() et snmp_sess_open() prennent chacune en entrée un pointeur vers un objet de type `struct snmp_session`. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers son `struct snmp_session` associé.

snmp_sess_send() et snmp_sess_async_send() prennent chacune un paramètre pdu, qui pointe vers un objet de type `struct snmp_pdu` contenant des informations décrivant une transaction qui sera effectuée via une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read invoquera la fonction de rappel spécifiée lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela pourrait inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées de sorte que SNMP obtienne le service dont il a besoin à partir de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent respectivement aux arguments nfds, readfds et timeout de select(2). La seule exception est que `timeout` doit TOUJOURS pointer vers une structure `struct timeval` allouée (mais peut-être non initialisée) (elle ne peut pas être NULL comme pour select(2)). Si `timeout` avait été passé comme NULL, block est défini à true, et timeout est traité comme non défini. Cette même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données retournées. Lorsqu'il revient, snmp_sess_read() doit ensuite être appelé avec le `fd_set` retourné par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire qu'il retourne zéro), snmp_sess_timeout() doit être appelé pour vérifier si un délai d'expiration s'est produit sur la session SNMP.

snmp_sess_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour les détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut de succès retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable snmp_errno de SNMP, la valeur de la variable système errno, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_BAD_ADDRESS
Le nom d'hôte ou l'adresse donné n'était pas utilisable.
SNMPERR_BAD_SESSION
La session spécifiée n'était pas ouverte.
SNMPERR_TOO_LONG

snmp_sess_close(3) — extra/net-snmp — Arch Linux

NAME

snmp_sess_close - fermer une session SNMP

SYNOPSIS

#include <net-snmp/session.h>

void
snmp_sess_close(netsnmp_session *session);

DESCRIPTION

La fonction snmp_sess_close ferme une session SNMP précédemment ouverte avec snmp_open(3). Elle libère toutes les ressources associées à la session, y compris les tampons de transmission et de réception, et ferme le descripteur de fichier sous-jacent.

Il est important d'appeler snmp_sess_close pour chaque session SNMP que vous ouvrez afin d'éviter les fuites de mémoire et les descripteurs de fichiers non libérés.

L'argument session est un pointeur vers une structure netsnmp_session qui représente la session SNMP à fermer. Ce pointeur doit avoir été obtenu lors d'un appel réussi à snmp_open(3).

DIAGNOSTICS

La fonction snmp_sess_close ne renvoie aucune valeur. Les erreurs éventuelles lors de la fermeture de la session ne sont pas signalées directement. Cependant, les erreurs sous-jacentes (par exemple, liées à la fermeture du descripteur de fichier) peuvent être visibles via le mécanisme de journalisation de Net-SNMP si le niveau de débogage est suffisamment élevé.

Les erreurs spécifiques liées aux sessions SNMP peuvent être gérées par les fonctions de rappel d'erreurs définies dans la structure netsnmp_session lors de son ouverture.

Les codes d'erreur possibles liés à la manipulation de sessions et de PDUs SNMP incluent (mais ne sont pas limités à) :

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
