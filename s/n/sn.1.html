NOM

sn - Signer/vérifier/comparer numériquement les strongnames sur les assemblages CLR.

SYNTAXE

sn [-q | -quiet] [options] [paramètres]

DESCRIPTION

Signe, vérifie ou compare numériquement les assemblages CLR en utilisant des strongnames.

Vous pouvez utiliser la commande sn pour créer des "fichiers snk" en utilisant l'option -k décrite ci-dessous.

OPTIONS DE CONFIGURATION

Les options de configuration sont stockées dans le fichier de configuration machine.config sous /configuration/strongNames.

-c fournisseur
Change le CSP (Crypto Service Provider) par défaut. Actuellement non supporté dans Mono.
-m [o|n]
Utilise un conteneur de clés machine [o] ou utilisateur [n]. Actuellement non supporté dans Mono.
-Vl
Liste les options de vérification. La liste est conservée sous /configuration/strongNames/verificationSettings dans machine.config.
-Vr assemblage [liste_utilisateurs]
Exempte l'assemblage spécifié de la vérification pour la liste d'utilisateurs spécifiée. Actuellement non supporté par sn. Vous devez modifier machine.config manuellement si vous avez besoin de cela.
-Vu assemblage
Supprime l'entrée d'exemption pour l'assemblage spécifié. Actuellement non supporté par sn, vous devez modifier machine.config manuellement si vous avez besoin de cela.
-Vx
Supprime toutes les entrées d'exemption. Actuellement non supporté par sn, vous devez modifier machine.config manuellement si vous avez besoin de cela.

OPTIONS LIÉES AU CSP

-d conteneur
Supprime la paire de clés présente dans le conteneur de clés spécifié.
-i clepair.snk conteneur
Importe le fichier strongname spécifié dans le conteneur spécifié.
-pc conteneur cle_publique
Export le clé publique du conteneur CSP spécifié vers le fichier spécifié.

OPTIONS DE CONVERSION

-e assemblage sortie.pub
Export la clé publique de l'assemblage vers le fichier de sortie spécifié.
-p clepair.snk sortie.pub
Export la clé publique à partir du fichier de clé strongname spécifié (SNK) ou d'un fichier protégé par mot de passe PKCS#12/PFX vers le fichier de sortie spécifié.
-o entree sortie.txt
Convertit le fichier d'entrée en fichier CSV (en utilisant des décimaux).
-oh entree sortie.txt
Convertit le fichier d'entrée en fichier CSV (en utilisant des hexadécimaux).

OPTIONS DE SIGNATURE STRONGNAME

-D assemblage1 assemblage2
Compare si assemblage1 et assemblage2 sont identiques à l'exception de leur signature. Ceci est fait en comparant le hash des métadonnées des deux assemblages.
-k [taille] clepair.snk
Crée une nouvelle paire de clés strongname dans le fichier spécifié. La longueur de clé par défaut est de 1024 bits et DOIT TOUJOURS être utilisée lors de la signature des assemblages 1.x. Toute valeur de 384 à 16384 bits (par incréments de 8 bits) est une longueur de clé valide pour signer les assemblages 2.x. Pour assurer une compatibilité maximale, vous pourriez vouloir continuer à utiliser des clés de 1024 bits. Notez qu'il n'y a pas de bonne raison, même si c'est possible, d'utiliser une longueur inférieure à 1024 bits.
-R assemblage clepair.snk
Resigne l'assemblage spécifié en utilisant le fichier de paire de clés strongname spécifié (SNK) ou un fichier protégé par mot de passe PKCS#12/PFX. Vous ne pouvez signer un assemblage qu'avec la clé privée qui correspond à la clé publique à l'intérieur de l'assemblage (sauf si son token de clé publique a été remappé dans machine.config).
-Rc assemblage conteneur
Resigne l'assemblage spécifié en utilisant le conteneur strongname spécifié.
-t fichier
Affiche le token de clé publique du fichier spécifié.
-tp fichier
Affiche la clé publique et le token de clé publique du fichier spécifié.
-T assemblage
Affiche le token de clé publique de l'assemblage spécifié.
-Tp assemblage
Affiche la clé publique et le token de clé publique de l'assemblage spécifié.
-v assemblage
Vérifie la signature de l'assemblage spécifié.
-vf assemblage
Vérifie la signature de l'assemblage spécifié (même si désactivé).

OPTIONS D'AIDE

-h , -?
Affiche une aide de base sur cet outil.
-h config , -? config
Affiche une aide relative à la configuration sur cet outil.
-h csp , -? csp
Affiche une aide relative aux fournisseurs de services cryptographiques sur cet outil.
-h convert , -? convert
Affiche une aide relative à la conversion sur cet outil.
-h sn , -? sn
Affiche une aide relative aux strongnames sur cet outil.

FICHIER DE CONFIGURATION

La configuration des Strongnames est conservée dans le fichier "machine.config". Actuellement, deux
fonctionnalités peuvent être configurées.
/configuration/strongNames/pubTokenMapping
Ce mécanisme permet à Mono de remapper un token de clé publique, comme le token ECMA, vers une autre clé publique pour la vérification. Ceci est utile dans deux scénarios. Premièrement, les assemblages signés avec la "clé ECMA" doivent être vérifiés par la clé "runtime" (car la clé ECMA n'est pas une clé publique). Deuxièmement, de nombreux assemblages sont signés avec des clés privées que Mono ne peut pas utiliser (par exemple, l'assemblage System.Security.dll). Une nouvelle clé ne peut pas être utilisée car elle changerait le strongname (une nouvelle paire de clés aurait une nouvelle clé publique qui produirait un nouveau token). Le remapping des tokens de clés publiques est la solution pour ces deux problèmes. Chaque token doit être configuré dans une entrée "map" similaire à celle-ci : <map Token="b77a5c561934e089" PublicKey="00..." />
/configuration/strongNames/verificationSettings
Il est souvent utile pendant le développement d'utiliser des assemblages signés avec délai. Normalement*, le runtime ne permettrait pas le chargement d'assemblages signés avec délai. Cette fonctionnalité permet à certains assemblages signés avec délai (basés sur leur token de clé publique, leur nom d'assemblage et leur nom d'utilisateur en option) d'être utilisés comme s'ils étaient des assemblages entièrement signés. [*] Notez que le "runtime" Mono 1.0 ne valide pas les signatures strongname, donc cette option ne devrait pas être requise dans la plupart des scénarios.
