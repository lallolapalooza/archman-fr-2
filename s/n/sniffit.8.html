SNIFFIT(8) Manuel de l'administrateur système SNIFFIT(8)

NOM

sniffit - outil de reniflage et de surveillance de paquets

SYNTAXE

sniffit [-xdabvnN] [-P proto ] [-A car ] [-p port ] [(-r|-R) fichier_enregistrement ] [-l longueur_reniflage ] [-L param_log ] [-F périph_reniflage ] [-D tty ] [-M plugin ] [(-t IP_Cible | -s IP_Source ) | (-i|-I) | -c fichier_config ]

DESCRIPTION

sniffit est un renifleur de paquets pour les paquets TCP/UDP/ICMP. sniffit est capable de vous donner des informations techniques très détaillées sur ces paquets (SEQ, ACK, TTL, Fenêtre, ...) mais aussi le contenu des paquets dans différents formats (hexadécimal ou texte brut, ...).

sniffit peut par défaut gérer les périphériques ethernet et PPP, mais peut être facilement forcé à utiliser d'autres périphériques (lisez les fichiers README.FIRST et sn_config.h à ce sujet !)

Le renifleur peut être facilement configuré pour 'filtrer' les paquets entrants (pour rendre les résultats du reniflage plus faciles à étudier). Le fichier de configuration (voir sniffit(5) ) vous permet d'être très précis sur les paquets à traiter.

sniffit dispose également d'un mode interactif pour la surveillance active, et peut également être utilisé pour une surveillance continue à différents niveaux.

NOTE

Cette page de manuel est censée être un manuel de référence. Lisez donc d'abord README.FIRST, et utilisez ceci uniquement pour une meilleure compréhension ou pour une vérification rapide de l'utilisation de sniffit

OPTIONS

-v
Affiche la version de sniffit que vous utilisez et quitte (remplace tout)
-t IP_Cible
Traite uniquement les paquets VERS IP_Cible. Si IP_Cible est en notation point-numéro, 'x' est autorisé comme joker. (par exemple, '-t 157.193.x', '-t x', ...) (NON compatible avec: '-s' '-i' '-I' '-c' '-v' '-L')
-s IP_Source
Similaire à '-t', traite uniquement les paquets VENANT de IP_Source. (NON compatible avec: '-t' '-i' '-I' '-c' '-v' '-L')
-b
Mode 'both' (les deux), avec '-s' ou '-t', traite uniquement VENANT de/VERS l'IP spécifiée par '-s' ou '-t' (NON compatible avec: '-t' '-i' '-I' '-c' '-v' '-L')
-c fichier_config
Utilise fichier_config pour le filtrage des paquets. Cela vous permet d'être très précis sur les paquets à traiter (voir sniffit(5) pour les détails sur le format). (NON compatible avec: '-t' '-s' '-i' '-I' '-v' '-L')
-i
Lance l'interface ncurses pour la surveillance active ('mode interactif'). (NON disponible si vous avez compilé sans support INTERACTIF, voir sn_config.h et README.FIRST ) (une des options '-t' '-s' '-i' '-I' '-c' est requise) (NON compatible avec: '-t' '-s' '-c' '-v' '-L')
-I
Identique à '-i', mais fournit plus d'informations. (une des options '-t' '-s' '-i' '-I' '-c' est requise) (NON compatible avec: '-t' '-s' '-c' '-v' '-L')
-R <fichier>
Enregistre tout le trafic dans <fichier> Ce fichier peut ensuite être fourni à Sniffit avec l'option '-r'. (Nécessite un paramètre de sélection comme '-c' '-t' '-s') (NON compatible avec '-i' '-I' '-v' '-L' '-r')
-r <fichier>
Cette option fournit le <fichier> enregistré à sniffit. Elle nécessite l'option '-F' avec le périphérique correct. Supposons que vous enregistriez un fichier sur une machine avec 'eth0'. Lorsque vous fournissez le fichier enregistré à sniffit, vous devrez ajouter '-F eth0' ou '-F eth' à la ligne de commande. Il n'est pas nécessaire d'expliquer que l'utilisation de '-i' ou '-I' en combinaison avec '-r' n'a pas de sens (pour le moment). (nécessite '-F', NON compatible avec '-R' '-i' '-I')
-n
Désactive la vérification de la somme de contrôle IP. Cela peut montrer des paquets invalides. (notez que les paquets ARP, RARP, autres paquets non-IP apparaîtront également comme invalides) (compatible avec TOUTES les options)
-N
N'effectue aucune des fonctions intégrées de Sniffit. Utile pour exécuter uniquement un Plugin. (compatible avec TOUTES les options)
-x
Affiche des informations étendues sur les paquets TCP sur stdout (SEQ, ACK, Drapeaux, etc.) Intéressant pour tracer les spoofages, les pertes de paquets et d'autres tâches réelles de débogage/vérification réseau. (si vous voulez enregistrer ceci, redirigez stdout vers un fichier) (NON compatible avec: '-i' 'I' '-v')
-d
Mode 'dump' (déchargement), affiche les paquets à l'écran (stdout) au lieu de les enregistrer dans des fichiers (par défaut). Les données sont imprimées en octets (hexadécimal). (NON compatible avec: '-i' 'I' '-v' '-L')
-a
Mode 'dump', identique à '-d' mais affiche en ASCII. Les caractères non imprimables sont remplacés par '.'. ('-d' et '-a' se mélangent sans aucun problème) (NON compatible avec: '-i' '-I' '-v' '-L')
-P proto
Spécifie les protocoles qui doivent être traités (TCP par défaut). Les options possibles actuellement sont : IP, TCP, ICMP, UDP. Elles peuvent être combinées. Les informations IP, ICMP, UDP sont affichées sur stdout. IP donne des informations SUPPLÉMENTAIRES sur l'enveloppement IP autour d'autres paquets, il n'est pas nécessaire de spécifier IP pour l'enregistrement des paquets TCP. Les paquets IP, ICMP ne sont pas filtrés (les paquets UDP le sont depuis la version 0.3.4). (NON compatible avec: '-i' '-I' '-v' '-L')
-A car
En mode 'normal' (pas '-d','-a','-i','-I','-L'), tous les caractères non imprimables seront remplacés par car (NON compatible avec: '-a' '-d' '-i' '-I' '-v' '-L')
-p port
Vérifie uniquement les paquets allant VERS (!!) le port port , 0 signifie tous les ports, par défaut c'est 0 (tous). (NON compatible avec: '-c' '-i' '-I' '-v' '-L')
-l longueur_reniflage
Quantité de données à enregistrer (par défaut 300 octets) en mode 'normal'. Les longueur_reniflage premiers octets de chaque connexion sont enregistrés. Une longueur de 0 enregistre tout. (attention à l'espace disque !) (NON compatible avec: '-i' '-I' '-v' '-L')
-F périph_reniflage
Force sniffit à utiliser un périphérique réseau spécifique. périph_reniflage peut être trouvé avec ifconfig (voir ifconfig(8)). sniffit prend en charge ethernet et PPP par défaut. Lisez README.FIRST pour des informations sur la façon de forcer l'utilisation d'autres périphériques. (compatible avec TOUTES les options)
-D tty
Toute la sortie d'enregistrement sera envoyée à ce périphérique. (Fonctionne UNIQUEMENT avec '-i' et '-I')
-M plugin
Active le Plugin n° Plugin, pour une liste de tous les plugins compilés dans votre version, tapez simplement ' sniffit '. Lisez tout sur les Plugins dans le PLUGIN-HOWTO (LISEZ-LE !) (NON compatible avec: '-i' '-I' '-v')
-L param_log
Utilise sniffit comme outil de surveillance et active différents modes d'enregistrement ( param_log ) Le fichier pour l'enregistrement peut être spécifié dans le fichier de configuration (voir sniffit(5) ) mais c'est sniffit.log par défaut. Différents param_log peuvent être combinés. (Fonctionne UNIQUEMENT avec '-c')

MODE NORMAL

Un ensemble de longueur_reniflage premiers octets (300 par défaut) de chaque connexion est enregistré dans un fichier x.x.x.x.p-y.y.y.y.o où 'x.x.x.x' est l'hôte émetteur (port 'p') et 'y.y.y.y' l'hôte récepteur (port 'o').

MODE DUMP ('-d' et/ou '-a')

La sortie est affichée sur stdout, le contenu du paquet est montré sous sa forme déballée (le paquet IP complet).

ENTRÉE
une fenêtre apparaîtra et enregistrera la connexion, ou la sortie de la connexion sera envoyée vers un périphérique choisi si vous avez utilisé l'option '-D'.
'q'
En mode enregistrement, arrête l'enregistrement. Sinon, quitte.
'n'
Active/désactive les netstatistics. Celles-ci sont échantillonnées toutes les 3 secondes, regardez dans le fichier sn_config.h pour changer cela.
'g'

Les paquets contiennent la ligne : "Ce paquet a été envoyé avec Sniffit !
'r'
Réinitialiser... efface toutes les connexions actuelles de la mémoire et redémarre.

MODE ENREGISTREMENT ('-L')

La sortie est enregistrée dans sniffit.log, sauf si vous avez spécifié un autre nom dans le fichier de configuration (voir sniffit(5)).

brut
Enregistre tous les paquets SYN, FIN, RST. Cela vous donnera un aperçu de tout le trafic réseau (TCP) de manière 'BRUTE' (une connexion qui démarre pourrait vous donner au moins 2 paquets SYN, etc...).
normal
Identique à brut, mais un peu plus intelligent. À moins que les paquets ne soient transmis plusieurs fois en raison de pertes de paquets, vous n'obtiendrez qu'une seule notification du début ou de la fin d'une connexion. (l'identifiant du paquet vous indiquera l'hôte qui a initié la connexion en premier)
telnet
Sniffit tentera de capturer les identifiants et mots de passe pour cette application. (voir telnet(1))
ftp
Sniffit tentera de capturer les identifiants et mots de passe pour cette application. (voir ftp(1))
mail
Sniffit essaiera d'identifier tout le courrier électronique qui a été enregistré.

ENREGISTREMENT IP ICMP UDP

Les informations sur ces paquets sont envoyées sur la sortie standard. Les options de filtrage de paquets ne concernent que les paquets TCP et UDP. Le contenu des paquets UDP n'est affiché que lorsque '-a' ou '-d' est activé.
