SNDIO(7) Manuel d'informations diverses SNDIO(7)

NOM

sndio — Descripteurs de périphériques audio et MIDI

DESCRIPTION

Les programmes accèdent au matériel audio et MIDI en utilisant la bibliothèque sndio. Elle permet à la fois l'accès via le serveur sndiod(8) et l'accès brut au matériel. Le périphérique audio ou le port MIDI, ainsi que la méthode d'accès, sont désignés par le descripteur sndio. Il est fourni par l'utilisateur avec la méthode de sélection de périphérique du programme, ou avec les variables d'environnement AUDIODEVICE et MIDIDEVICE s'il n'y a pas de méthode de sélection de périphérique.

Habituellement, les programmes accèdent au matériel via le serveur sndiod(8), car l'accès brut au matériel est exclusif et nécessite des privilèges supplémentaires. Le serveur sndiod(8) supporte plusieurs connexions à la fois, permettant à plusieurs programmes d'utiliser le matériel concurremment. Il effectue le traitement audio nécessaire à la volée pour surmonter toute incompatibilité entre le logiciel et le matériel. Les connexions à sndiod(8) peuvent également être établies via le réseau, y compris depuis des machines virtuelles.

Le serveur sndiod(8) expose des ports MIDI thru, permettant à un programme d'envoyer des données MIDI à d'autres programmes, par exemple pour permettre à un séquenceur d'envoyer des événements à un synthétiseur.

De plus, sndiod(8) expose un port MIDI utilisé pour contrôler les programmes audio en utilisant les messages standard MIDI Machine Control (MMC), MIDI Time Code (MTC) et volume maître.

Descripteurs de périphérique serveur

Du point de vue de l'utilisateur, chaque périphérique audio ou port MIDI exposé par sndiod(8) a un descripteur de la forme :

type[@hostname][,servnum]/[devnum|option]

Ces informations sont utilisées par les programmes pour déterminer comment accéder au périphérique audio ou au port MIDI.

type
Le type du périphérique audio ou du port MIDI. Les valeurs possibles sont :
snd
Périphérique audio exposé par sndiod(8).
midithru
Port MIDI thru créé avec sndiod(8).
midi
Port MIDI exposé par sndiod(8).
hostname
Le nom d'hôte ou l'adresse où le serveur distant sndiod(8) à connecter est en cours d'exécution.
servnum
Le numéro du serveur sndiod(8) à connecter, correspondant à l'entier spécifié avec l'option -U de sndiod(8). Utile uniquement si plusieurs serveurs sndiod(8) sont en cours d'exécution sur le même système.
devnum
Numéro de périphérique. Il correspond au numéro de l'option -f ou -q correspondante sur la ligne de commande de sndiod(8).
option
Correspond au sous-périphérique enregistré en utilisant l'option -s de sndiod(8).

Descripteurs de périphérique brut

Chaque périphérique audio brut ou port MIDI a un descripteur de la forme :

type/devnum

Le type peut être soit rsnd soit rmidi. Le descripteur de périphérique rsnd/0 accède au périphérique /dev/audio0, rsnd/1 accède à /dev/audio1, et ainsi de suite. De même, rmidi/0 accède à /dev/rmidi0 et ainsi de suite.

Périphériques audio et MIDI par défaut

Lorsqu'aucun descripteur de périphérique audio n'est fourni à un programme ou lorsque le mot réservé default est utilisé comme descripteur audio, le programme utilisera celui spécifié dans les variables d'environnement AUDIODEVICE, AUDIOPLAYDEVICE et/ou AUDIORECDEVICE. S'ils ne sont pas définis, le programme essaie d'abord de se connecter à snd/default. Si cela échoue, il essaie ensuite d'utiliser rsnd/0.

De même, si aucun descripteur MIDI n'est fourni à un programme ou lorsque le mot réservé default est passé comme descripteur de périphérique, le programme utilise celui spécifié dans la variable d'environnement MIDIDEVICE. S'il n'est pas défini, le programme essaie d'abord de se connecter à midithru/0. Si cela échoue, il essaie ensuite d'utiliser rmidi/0. Tant que sndiod(8) est en cours d'exécution, cela permet aux programmes d'échanger des données MIDI sur des machines sans matériel MIDI par défaut, par exemple un lecteur MIDI pourrait utiliser un synthétiseur logiciel sans configuration manuelle requise.

Authentification

Pour des raisons de confidentialité, un seul utilisateur peut avoir des connexions à sndiod(8) à un moment donné. Les utilisateurs sont identifiés par leur cookie de session, qui est automatiquement généré par les programmes audio ou MIDI lors de la première connexion au serveur. Le cookie est stocké dans $HOME/.sndio/cookie et contient 128 bits de données aléatoires brutes.

Si une session doit être partagée entre plusieurs utilisateurs, ils peuvent se connecter au serveur en utilisant le même cookie.

ENVIRONNEMENT

AUDIODEVICE
Descripteur de périphérique audio à utiliser lorsqu'aucun descripteur n'est explicitement spécifié à un programme.
AUDIOPLAYDEVICE
Descripteur de périphérique audio à utiliser pour le mode lecture seule lorsqu'aucun descripteur n'est explicitement spécifié à un programme. Remplace AUDIODEVICE.
AUDIORECDEVICE
Descripteur de périphérique audio à utiliser pour le mode enregistrement seul lorsqu'aucun descripteur n'est explicitement spécifié à un programme. Remplace AUDIODEVICE.
MIDIDEVICE
Descripteur de port MIDI à utiliser lorsqu'aucun descripteur n'est explicitement spécifié à un programme.

Ces variables d'environnement sont ignorées par sndio si le programme a les bits set-user-ID ou set-group-ID définis.

FICHIERS

~/.sndio/cookie
Cookie d'authentification de session utilisateur.
/dev/audioN
Périphériques audio bruts.
/dev/rmidiN
Ports MIDI bruts.

EXEMPLES

snd/0
Périphérique audio référencé par la première option -f de sndiod(8).
snd/rear
Sous-périphérique enregistré avec “-s rear”.
midithru/0
Port MIDI thru par défaut.

sndio(7) — sndio 1.10.0-1

NAME

sndio — sound input/output interface

DESCRIPTION

The sndio protocol is a network transparent sound sample exchange protocol. It is designed to be simple and flexible. The sndio library implements the client and server sides of this protocol.

The server sndiod(8) manages hardware audio devices and exposes them to the network. It can also be configured to multiplex multiple clients onto a single hardware device.

The client library provides an abstract interface to audio hardware through the sndio protocol. Applications link against this library to play or record sound samples without needing to know about the underlying hardware details or the location of the sound server.

The protocol uses a simple text-based command exchange, multiplexed over a stream socket connection. The protocol supports both PCM audio and MIDI data streams.

ENVIRONMENT

AUDIODEV

This environment variable specifies the default audio device to use. If not set, the server tries to use /dev/audio0. The value is a string representing the device, as understood by the sndio library. For example:

AUDIODEV=rsnd/0

When sndio is used over the network, the variable can take the form hostname:device, e.g.:

AUDIODEV=remotehost:rsnd/0

MIDIDEV

This environment variable specifies the default MIDI device to use. If not set, the server tries to use /dev/rmidi0. The value is a string representing the device, as understood by the sndio library. For example:

MIDIDEV=rmidi/0

When sndio is used over the network, the variable can take the form hostname:device, e.g.:

MIDIDEV=remotehost:rmidi/0

FILES

ithru/0
Premier port MIDI via créé avec sndiod(8).
default
Périphérique audio ou MIDI par défaut.
rsnd/0
Accès matériel direct à /dev/audio0.
rmidi/5
Accès matériel direct à /dev/rmidi5.

EXAMPLES

The following examples demonstrate how to use the sndio library and tools.

Playing a sound file using aucat:

aucat -f S16_LE -r 44100 -o your_file.wav

This command plays a WAV file named your_file.wav with signed 16-bit little-endian samples at a sample rate of 44100 Hz. The aucat utility uses the sndio library to send the audio data to the default audio output device.

Recording sound using aucat:

aucat -f S16_LE -r 44100 -i your_recording.wav

This command records 10 seconds of audio from the default input device and saves it to your_recording.wav.

Sending MIDI data using midicat:

midicat -p 128 -o "Hello MIDI"

This command sends the MIDI message "Hello MIDI" (which will be converted to appropriate MIDI bytes) to the default MIDI output device. The -p 128 option specifies the port to use.

Accessing a remote sound server:

To play sound on a remote machine named remote_snd, you can set the AUDIODEV environment variable:

AUDIODEV=remote_snd:rsnd/0 aucat -f S16_LE -r 44100 -o your_file.wav

This command will play the specified WAV file through the sndiod server running on remote_snd.
