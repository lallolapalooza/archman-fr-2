NOM

snmp-ups - Pilote multi-MIB pour équipements UPS SNMP

SYNTAXE

snmp-ups -h

snmp-ups -a NOM_ONDULEUR [OPTIONS]


Note

Cette page de manuel ne documente que les fonctionnalités spécifiques matériel du pilote snmp-ups. Pour des informations sur le pilote de base, voir nutupsdrv(8).

MATÉRIEL SUPPORTÉ

Le pilote snmp-ups détecte et prend automatiquement en charge une large gamme d'appareils en chargeant diverses MIB, telles que :

ietf

UPS conforme à la RFC 1628 (UPS MIB), par ex. MGE UPS SYSTEMS, Liebert, peut-être d'autres (par défaut)

mge

Cartes SNMP pour UPS MGE UPS SYSTEMS et MGE Office Protection Systems (réfs 66062, 66045, 66074 et 66244)

apcc

Cartes de gestion réseau APC AP9605, AP9606, AP9617 et AP9618, ainsi que toute autre carte prenant en charge la MIB APC POWERNET

netvision

UPS Socomec Sicon avec carte/boîtier externe de gestion Web/SNMP Netvision

eaton_pw_nm2

Cartes SNMP ConnectUPS pour appareils Powerware, ainsi que les onduleurs avec cartes Eaton Gigabit Network Cards (Network-M2) (renommé de pw)

eaton_pxg_ups

Cartes Eaton Power Xpert Gateway UPS (renommé de pxgx_ups)

aphel_genesisII

Eaton Powerware ePDU Monitored

aphel_revelation

Eaton Powerware ePDU Managed

raritan

Divers PDU Raritan (Dominion PX, PM, RPC)

raritan-px2

Divers PDU Raritan (Dominion PX2)

baytech

Divers PDU BayTech

cpqpower

Carte de gestion HP/Compaq AF401A, peut-être d'autres

cyberpower

Cyberpower RMCARD201. Devrait également prendre en charge RMCARD100 (version réseau), RMCARD202 et RMCARD301

huawei

Huawei UPS5000-E, peut-être d'autres

tripplite

UPS TrippLite ; à l'heure actuelle, il s'agit d'un mappage MIB IETF avec uniquement l'OID du point d'entrée Tripplite pour vérifier le fournisseur de l'appareil, et une configuration matérielle spécifique sera ajoutée dans les développements futurs.

Pour une liste complète et à jour, vous pouvez interroger le pilote en passant l'argument mibs=--list (voir ci-dessous).

ARGUMENTS SUPPLÉMENTAIRES

Ce pilote prend en charge les paramètres optionnels suivants dans le fichier ups.conf(5) :

port=nom_hôte[:port]

Définit le nom d'hôte SNMP, ou l'adresse IP, et le numéro de port de l'agent SNMP pair. Il n'y a pas de valeur par défaut pour le nom d'hôte, mais le port par défaut est 161.

mibs=--list

Une option spéciale qui permet de lister les correspondances MIB-à-NUT connues et de quitter le binaire du pilote, destiné à une utilisation en ligne de commande comme ceci : 
:; snmp-ups -a snmp-test -x mibs=--list

mibs=nom

Définit la conformité MIB (par défaut = auto, entrées autorisées : référez-vous à MATÉRIEL SUPPORTÉ ci-dessus).

Avec "auto", le pilote essaiera un ensemble sélectionné d'objets SNMP jusqu'à ce qu'il en trouve un auquel l'appareil répond.

Notez que depuis NUT 2.6.2, snmp-ups dispose d'une nouvelle méthode utilisant sysObjectID (qui est un pointeur vers la MIB préférée de l'appareil) pour détecter les appareils supportés. Cela rend caduque la nécessité d'utiliser l'option "mibs".

community=nom

Définit le nom de communauté (par défaut = public) pour les connexions SNMPv1 et SNMPv2c. Notez qu'une communauté avec des droits en écriture (RW) est nécessaire pour modifier les paramètres de l'onduleur et envoyer des commandes (par exemple, pour une mise hors tension).

snmp_version=version

Définit la version SNMP (par défaut = v1, autorisé : v2c, v3)

snmp_retries=tentatives

Spécifie le nombre de tentatives Net-SNMP à utiliser dans les requêtes (par défaut=5)

snmp_timeout=délai

Spécifie le délai d'attente Net-SNMP en secondes entre les tentatives (par défaut=1)

symmetrathreephase

Active les particularités des Symmetra triphasés APC (à utiliser sur les Symmetra triphasés APC) : Convertit la tension de ligne à ligne en tension de ligne à neutre (par défaut : non activé)

pollfreq=num

Définit l'intervalle d'interrogation pour les mises à jour complètes, en secondes, afin de réduire le trafic réseau SNMP par rapport aux mises à jour rapides effectuées toutes les "pollinterval" (cette dernière option est décrite dans ups.conf(5)). La valeur par défaut est 30 (en secondes).

notransferoids

Désactive la surveillance des OID de transfert de basse et haute tension dans le matériel. Cela supprimera input.transfer.low et input.transfer.high de la liste des variables. Ceci ne doit être utilisé que sur les équipements APC Symmetra qui présentent des anomalies dans le rapport de tension triphasée.

secLevel=valeur

Définit le niveau de sécurité utilisé pour les messages SNMPv3 (par défaut=noAuthNoPriv, autorisé : authNoPriv, authPriv). Ce paramètre est obligatoire si vous utilisez une authentification non triviale.

secName=valeur

Définit le nom de sécurité utilisé pour les messages SNMPv3 authentifiés (pas de valeur par défaut)

authPassword=valeur

Définit la phrase secrète d'authentification utilisée pour les messages SNMPv3 authentifiés (pas de valeur par défaut)

privPassword=valeur

Définit la phrase secrète de confidentialité utilisée pour les messages SNMPv3 chiffrés (pas de valeur par défaut)

authProtocol=valeur

Définit le protocole d'authentification (MD5, SHA, SHA256, SHA384 ou SHA512) utilisé pour les messages SNMPv3 authentifiés (par défaut=MD5). Notez que la liste exacte des protocoles dépend des capacités de la bibliothèque Net-SNMP ; consultez l'aide du programme snmp-ups pour la liste supportée en exécution.

privProtocol=valeur

Définit le protocole de confidentialité (DES, AES, AES192 ou AES256) utilisé pour les messages SNMPv3 chiffrés (par défaut=DES). Notez que la liste exacte des protocoles dépend des capacités de la bibliothèque Net-SNMP ; consultez l'aide du programme snmp-ups pour la liste supportée en exécution.

EXIGENCES

Vous devrez installer le paquet Net-SNMP à partir de http://www.net-snmp.org/ avant de compiler ce pilote.

SNMP v3 nécessite également le support d'OpenSSL à partir de http://www.openssl.org.

LIMITATIONS

Arrêt de sécurité

La séquence d'arrêt doit être testée avant de s'appuyer sur NUT pour envoyer une commande d'arrêt à l'onduleur. Le problème est que la pile réseau de l'hôte peut avoir été arrêtée au moment où le pilote est invoqué pour envoyer la commande d'arrêt. Le pilote tente d'envoyer les commandes shutdown.return, shutdown.reboot et load.off.delay à l'onduleur en séquence, en s'arrêtant après la première commande supportée.

Utilisation de noms d'hôte pour les NMC d'onduleurs

Une carte de gestion réseau d'onduleur peut se voir attribuer une adresse IP fixe/statique ou une adresse dynamique (par exemple, via DHCP) sur votre réseau. De ce fait, vous pourriez vouloir ou devoir utiliser un service de nommage dynamique pour accéder à l'onduleur. Notez que cela peut poser problème, notamment lors de pannes importantes et d'arrêts, lorsque votre serveur DHCP/DNS pourrait déjà être hors service alors que le pilote a besoin de résoudre le nom impliqué (en particulier lors des hooks de fin d'arrêt, lorsqu'une nouvelle instance du programme pilote pourrait démarrer juste pour demander à l'onduleur de s'éteindre ou de redémarrer).

Il peut être judicieux de s'assurer que le client du service de nommage de votre système d'exploitation peut mettre en cache le nom de l'onduleur suffisamment longtemps, ou d'utiliser une adresse IP fixe (et une entrée dans /etc/hosts par mesure de sécurité, afin de n'avoir qu'un seul endroit à reconfigurer éventuellement).

INSTALLATION

Ce pilote n'est compilé que si les fichiers de développement Net-SNMP sont présents au moment de la configuration. Vous pouvez également forcer sa compilation en utilisant configure --with-snmp=yes avant d'appeler make.

EXEMPLES

Le nom d'hôte de l'onduleur est spécifié avec la valeur "port" dans ups.conf, et peut inclure un port distant non standard (161) :

        [snmpv1]
                driver = snmp-ups
                port = snmp-ups.example.com
                community = public
                snmp_version = v1
                pollfreq = 15
                desc = "Exemple de périphérique SNMP v1"
        [snmpv3]
                driver = snmp-ups
                port = 166.99.224.132:170
                snmp_version = v3
                secLevel = authPriv
                secName = mysecurityname
                authPassword = myauthenticationpassphrase
                privPassword = myprivatepassphrase
                desc = "Exemple de périphérique SNMP v3, avec le niveau de sécurité le plus élevé"
