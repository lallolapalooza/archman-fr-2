snmp_alarm_register_hr(3)

Paquet: net-snmp

Licences: BSD

SNMP_ALARM(3) Net-SNMP SNMP_ALARM(3)

NOM

snmp_alarm_register, snmp_alarm_register_hr, snmp_alarm_unregister - fonctions d'alarme

SYNOPIS

#include <net-snmp/utilities.h>

unsigned int
snmp_alarm_register(unsigned int secondes,
unsigned int drapeaux,
SNMPAlarmCallback *f_callback,
void *clientarg);

unsigned int
snmp_alarm_register_hr(struct timeval t,
unsigned int drapeaux,
SNMPAlarmCallback *f_callback,
void *clientarg);

void
snmp_alarm_unregister(unsigned int reg);

DESCRIPTION

Ces fonctions implémentent un mécanisme de gestion de minuterie générique permettant à plusieurs parties d'une application d'enregistrer des rappels de fonction à exécuter à un moment donné dans le futur.

UTILISATION

L'utilisation est assez simple et directe : créez simplement une fonction que vous souhaitez appeler à un moment donné dans le futur. La définition de la fonction doit être similaire à celle-ci :

void mon_callback(unsigned int reg, void *clientarg);

Ensuite, appelez snmp_alarm_register() pour enregistrer votre rappel afin qu'il soit appelé secondes à partir de maintenant. Le champ drapeaux doit être SA_REPEAT ou NULL. Si le champ drapeaux est défini sur SA_REPEAT, alors la fonction de rappel enregistrée sera appelée toutes les secondes. Si drapeaux est NULL, la fonction ne sera appelée qu'une seule fois, puis supprimée de l'enregistrement du système d'alarme.

Le paramètre clientarg dans la fonction d'enregistrement est utilisé uniquement par la fonction cliente et est stocké et renvoyé directement à celle-ci à chaque appel du système.

La fonction snmp_alarm_register() renvoie un unsigned int unique (qui est également passé comme premier argument de chaque rappel), qui peut ensuite être utilisé pour supprimer le rappel de la file d'attente ultérieurement à l'aide de la fonction snmp_alarm_unregister(). Si l'appel snmp_alarm_register() échoue, elle renvoie zéro. Il est notamment tout à fait permis qu'une fonction d'alarme s'auto-désinscrive.

La fonction snmp_alarm_register_hr() est identique en opération à la fonction snmp_alarm_register(), mais prend un struct timeval comme premier paramètre et planifie le rappel après la période représentée par t (les lettres hr signifient "haute résolution"). Le fonctionnement de cette fonction dépend de la mise à disposition de l'appel système setitimer(2) par le système d'exploitation. Si cet appel système n'est pas disponible, l'alarme sera planifiée comme si snmp_alarm_register() avait été appelée avec un premier argument égal à la valeur du membre tv_sec de t. Voir cependant les notes ci-dessous.

INITIALISATION

La fonction init_snmp() initialise le sous-système snmp_alarm en appelant init_snmp_alarm() puis init_alarm_post_config() pour configurer le premier timer afin d'initialiser la fonction de rappel. Ces deux fonctions ne doivent pas être utilisées directement par les applications.

NOTES

Le comportement par défaut du sous-système snmp_alarm est de demander des signaux SIGALRM au système d'exploitation via les appels système alarm(2) ou setitimer(2). Cela a l'inconvénient, cependant, qu'aucune autre partie de l'application ne peut utiliser la fonctionnalité SIGALRM (ou, si une autre partie de l'application utilise la fonctionnalité SIGALRM, le sous-système snmp_alarm ne fonctionnera pas correctement).

Si votre application utilise une boucle d'événements basée sur select(2), il n'est pas nécessaire d'utiliser SIGALRM pour le sous-système snmp_alarm, le laissant disponible pour d'autres parties de l'application. Ceci est fait en effectuant l'appel suivant :

netsnmp_ds_set_boolean(NETSNMP_DS_LIBRARY_ID, 
                       NETSNMP_DS_LIB_ALARM_DONT_USE_SIG, 1);

avant d'appeler init_snmp(). Ensuite, snmp_select_info() prend en compte les alarmes lors du calcul de la valeur de timeout à utiliser pour select(2). Tout ce que vous avez à faire est d'appeler run_alarms() lorsque select(2) expire (valeur de retour zéro). C'est l'approche adoptée dans l'agent ; voir snmpd.c. De plus, en utilisant cette méthode, les alarmes haute résolution ne dépendent pas de la présence de l'appel système setitimer(2), bien que la précision globale soit bien entendu toujours déterminée par le système d'exploitation sous-jacent. Recommandé.
