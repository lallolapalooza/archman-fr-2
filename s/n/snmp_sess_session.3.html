snmp_sess_session(3)

void snmp_sess_timeout(void *handle);

int snmp_sess_close(void *handle);

DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multithreadée. À l'exception de snmp_sess_session(), ces fonctions sont des versions pour session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique en lieu et place d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure struct snmp_session qui source les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure est passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Au lieu de cela, le pointeur opaque retourné par snmp_sess_open() est utilisé pour référencer cette session par la suite.

Les sessions SNMP qui sont créées avec snmp_sess_open() ne sont pas affectées par, et NE DOIVENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Plutôt, les fonctions équivalentes pour session unique décrites ici doivent être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacune en entrée un pointeur vers un objet struct snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers son struct snmp_session associé.

snmp_sess_send() et snmp_sess_async_send() prennent chacune un paramètre pdu, qui pointe vers un objet struct snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read invoquera le callback spécifié lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se produire de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela peut inclure les descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent aux arguments nfds, readfds et timeout de select(2) respectivement. La seule exception est que timeout doit TOUJOURS pointer vers un struct timeval alloué (mais peut-être non initialisé) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors défini à vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info() , select(2) devrait être appelé avec les données retournées. Lorsqu'il retourne, snmp_sess_read() devrait alors être appelé avec le fd_set retourné par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) atteint le délai imparti (c'est-à-dire qu'il retourne zéro), snmp_sess_timeout() devrait être appelé pour voir si un délai est survenu sur la session SNMP.

snmp_sess_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour les détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut réussi retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable snmp_errno de SNMP, la valeur de la variable système errno, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_GENERR
Une erreur générique s'est produite.
SNMPERR_BAD_LOCPORT
Le port local était incorrect car il avait déjà été alloué ou la permission avait été refusée.
SNMPERR_BAD_ADDRESS
Le nom d'hôte ou l'adresse fourni était inutilisable.
SNMPERR_BAD_SESSION
La session spécifiée n'était pas ouverte.
SNMPERR_TOO_LONG
SNMPERR_NO_SOCKET
SNMPERR_V2_IN_V1
SNMPERR_V1_IN_V2
SNMPERR_BAD_REPEATERS
SNMPERR_BAD_REPETITIONS
SNMPERR_BAD_ASN1_BUILD
SNMPERR_BAD_SENDTO
SNMPERR_BAD_RCVFROM
SNMPERR_BAD_PARSE
SNMPERR_BAD_VERSION
SNMPERR_BAD_COMMUNITY
SNMPERR_NOAUTH_DESPRIV
SNMPERR_ABORT
SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
