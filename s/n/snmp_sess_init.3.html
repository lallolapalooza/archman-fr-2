#include <net-snmp/session_api.h>

void snmp_sess_init(struct snmp_session *session);

struct snmp_session *snmp_sess_session(void *handle);

int snmp_sess_async_send(void *handle,
struct snmp_pdu *pdu,
snmp_callback callback,
void *callbackData);

int snmp_sess_select_info(void *handle,
int *numfds, fd_set *fdset,
struct timeval *timeout,
int *block);

int snmp_sess_read(void *handle, fd_set *fdset);

void snmp_sess_timeout(void *handle);

int snmp_sess_synch_response ( void *handle,

netsnmp_pdu *pdu,
netsnmp_pdu **response);

int snmp_sess_close(void *handle);

void snmp_sess_error(void *handle, int *pcliberr,
int *psnmperr, char **pperrstring);

DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multi-thread. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui source les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Une fois cette structure passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Au lieu de cela, le pointeur opaque retourné par snmp_sess_open() est utilisé pour faire référence à cette session désormais.

Les sessions SNMP créées avec snmp_sess_open() ne sont pas affectées par, et NE DEVRAIENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Ce sont plutôt les fonctions équivalentes pour session unique décrites ici qui doivent être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacune en entrée un pointeur vers un objet struct snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers sa structure snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacune un paramètre pdu, qui pointe vers un objet struct snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read invoquera la fonction de rappel spécifiée lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela peut inclure les descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin lors de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent aux arguments nfds, readfds et timeout de select(2) respectivement. La seule exception est que timeout doit TOUJOURS pointer vers un struct timeval alloué (mais potentiellement non initialisé) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors mis à vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) devrait être appelé avec les données retournées. Lorsqu'il retourne, snmp_sess_read() devrait alors être appelé avec le fd_set retourné par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire, retourne zéro), snmp_sess_timeout() devrait être appelé pour vérifier si une expiration s'est produite sur la session SNMP.

snmp_sess_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour les détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut réussi retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable SNMP snmp_errno, la valeur de la variable système errno et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_GENERR
Une erreur générique s'est produite.
SNMPERR_BAD_LOCPORT
Le port local était incorrect car il était déjà alloué ou l'autorisation a été refusée.
SNMPERR_BAD_ADDRESS
Le nom d'hôte ou l'adresse fourni n'était pas utilisable.
SNMPERR_BAD_SESSION
La session spécifiée n'était pas ouverte.
SNMPERR_TOO_LONG
SNMPERR_NO_SOCKET

SNMPERR_V1_IN_V2

snmp_sess_error (3)

NAME

snmp_sess_error, snmp_sess_error_str - return SNMP session error information

SYNOPSIS

#include <net-snmp/session.h>

int
snmp_sess_error(
struct snmp_session *sp
);

#include <net-snmp/library/snmp_api.h>

char *
snmp_sess_error_str(
struct snmp_session *sp
);

DESCRIPTION

The SNMP library provides routines for communicating with SNMP entities. This man page describes routines that allow applications to retrieve error information related to an SNMP session.

The snmp_sess_error function returns an integer error code associated with the SNMP session pointed to by sp.

The snmp_sess_error_str function returns a pointer to a string describing the error associated with the SNMP session pointed to by sp.

The error code returned by snmp_sess_error can be one of the following values:

SNMPERR_SUCCESS
No error occurred.
SNMPERR_GENERIC
A generic SNMP error occurred.
SNMPERR_V2CLARIFICATION
An SNMPv2 clarification occurred.
SNMPERR_AUTHFAILURE
Authentication failed.
SNMPERR_NOTAUTHUSER
The authenticated user is not authorized.
SNMPERR_INVALIDCHUNK
An invalid chunk was received.
SNMPERR_BADVALUE
A bad value was received.
SNMPERR_TX_FAILED
The transmission failed.
SNMPERR_BADOBJECTNAME
An invalid object name was specified.
SNMPERR_NULLHOSTNAME
No hostname was specified.
SNMPERR_BADPORT
An invalid port number was specified.
SNMPERR_BADPACKET
An invalid packet was received.
SNMPERR_NOMEMORY
Not enough memory available.
SNMPERR_TIMEDOUT
The operation timed out.
SNMPERR_SECURITYERROR
A security error occurred.
SNMPERR_NOTIMPLEMENT
The requested operation is not implemented.
SNMPERR_UNSUPPORTEDSECLEVEL
The security level is not supported.
SNMPERR_INVALIDPACKETSIZE
The packet size is invalid.
SNMPERR_WRONGENCODING
The encoding is incorrect.
SNMPERR_WRONGPACKETTYPE
The packet type is incorrect.
SNMPERR_BINDORPHRASE
The bind or phrase is incorrect.
SNMPERR_BADCOMMUNITYNAME
The community name is incorrect.
SNMPERR_BADROWDESCR
The row descriptor is invalid.
SNMPERR_BADROWSTATUS
The row status is invalid.
SNMPERR_NOAUTHORIZATION
No authorization.
SNMPERR_UNKNOWN_PDU
Unknown PDU type.
SNMPERR_TIMEOUT
Timeout occurred.

DIAGNOSTICS

The snmp_sess_error function returns an integer error code. The snmp_sess_error_str function returns a pointer to a null-terminated string describing the error. If no error has occurred, snmp_sess_error returns SNMPERR_SUCCESS and snmp_sess_error_str returns a pointer to an empty string.
