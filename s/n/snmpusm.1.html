NOM

snmpusm - crée et maintient des utilisateurs SNMPv3 sur une entité réseau

SYNTAXE

snmpusm [OPTIONS COMMUNES] -Cw AGENT create UTILISATEUR [UTILISATEUR-CLONE]
snmpusm [OPTIONS COMMUNES] AGENT delete UTILISATEUR
snmpusm [OPTIONS COMMUNES] AGENT cloneFrom UTILISATEUR UTILISATEUR-CLONE
snmpusm [OPTIONS COMMUNES] [-Ca] [-Cx] AGENT passwd ANCIEN-MOTDEPASSE NOUVEAU-MOTDEPASSE [UTILISATEUR]
snmpusm [OPTIONS COMMUNES] <-Ca | -Cx> -Ck AGENT passwd ANCIENNE-CLE-OU-MOTDEPASSE NOUVELLE-CLE-OU-MOTDEPASSE [UTILISATEUR]
snmpusm [OPTIONS COMMUNES] [-Ca] [-Cx] AGENT changekey [UTILISATEUR]

DESCRIPTION

snmpusm est une application SNMP qui peut être utilisée pour effectuer une maintenance simple sur les utilisateurs connus d'un agent SNMP, en manipulant la table User-based Security Module (USM) de l'agent. L'utilisateur a besoin d'un accès en écriture à la table MIB usmUserTable. Cet outil peut être utilisé pour créer, supprimer, cloner et changer le mot de passe des utilisateurs configurés sur un agent SNMP en cours d'exécution.

OPTIONS

Options communes à toutes les commandes snmpusm :

-CE ID-MOTEUR
Définit le usmUserEngineID à utiliser comme partie de l'index de usmUserTable. Par défaut, utilise le contextEngineID (défini via -E ou sondé) comme usmUserEngineID.
-Cp CHAÎNE
Définit la valeur usmUserPublic de l' (nouvel) utilisateur à la CHAÎNE spécifiée.

Options pour les commandes passwd et changekey :

-Ca
Change la clé d'authentification.
-Cx
Change la clé de confidentialité.
-Ck
Permet d'utiliser une clé localisée (doit commencer par 0x) au lieu d'un mot de passe. Lorsque cette option est utilisée, l'option -Ca ou -Cx (mais pas les deux) doit également être utilisée.

CRÉATION DES UTILISATEURS

Un utilisateur SNMPv3 non authentifié peut être créé en utilisant la commande

snmpusm [OPTIONS COMMUNES] AGENT create UTILISATEUR

Ceci construit une entrée (inactive) dans usmUserTable, sans paramètres d'authentification ou de confidentialité. En principe, cet utilisateur devrait être utilisable pour des requêtes 'noAuthNoPriv', mais en pratique, l'agent Net-SNMP n'autorisera pas une telle entrée à être activée. L'utilisateur peut être créé via l'opération createAndWait en utilisant le drapeau -Cw à la place. Cela empêchera l'utilisateur d'être marqué comme actif dans n'importe quel agent jusqu'à ce qu'il soit explicitement activé plus tard via la commande activate.

Pour activer cette entrée, il est nécessaire de "cloner" un utilisateur existant, en utilisant la commande

snmpusm [OPTIONS COMMUNES] AGENT cloneFrom UTILISATEUR UTILISATEUR-CLONE

L'entrée UTILISATEUR hérite alors des mêmes paramètres d'authentification et de confidentialité (y compris les mots de passe) que l'utilisateur CLONEFROM.

Ces deux étapes peuvent être combinées en une seule, en utilisant la commande

snmpusm [OPTIONS COMMUNES] AGENT create UTILISATEUR UTILISATEUR-CLONE

Les deux formes de la sous-commande create nécessitent que l'utilisateur créé n'existe pas déjà. La sous-commande cloneFrom nécessite que l'utilisateur à cloner existe déjà.

Le clonage est le seul moyen de spécifier quels protocoles d'authentification et de confidentialité utiliser pour un utilisateur donné, et il n'est possible de le faire qu'une seule fois. Les tentatives ultérieures de reclonage sur le même utilisateur sembleront réussir, mais seront ignorées silencieusement. Ce comportement (plutôt inattendu) est imposé par les spécifications SNMPv3 USM (RFC 3414). Pour changer les paramètres d'authentification et de confidentialité d'un utilisateur donné, il est nécessaire de supprimer et recréer l'entrée utilisateur. Ceci n'est pas nécessaire pour simplement changer les mots de passe (voir ci-dessous). Cela signifie que l'agent doit être initialisé avec au moins un utilisateur pour chaque combinaison de protocoles d'authentification et de confidentialité. Voir la page de manuel de snmpd.conf(5) pour les détails de la directive de configuration createUser.

SUPPRESSION DES UTILISATEURS

Un utilisateur peut être supprimé de usmUserTable en utilisant la commande

snmpusm [OPTIONS COMMUNES] AGENT delete UTILISATEUR

CHANGEMENT DES MOTS DE PASSE

Les profils utilisateur contiennent des clés privées qui ne sont jamais transmises sur le réseau en clair (que les requêtes d'administration soient chiffrées ou non). Pour changer la clé secrète d'un utilisateur, il est nécessaire de spécifier l'ancien mot de passe de l'utilisateur ainsi que le nouveau. Ceci utilise la commande

snmpusm [OPTIONS COMMUNES] [-Ca] [-Cx] AGENT passwd ANCIEN-MOTDEPASSE NOUVEAU-MOTDEPASSE [UTILISATEUR]

Après avoir cloné une nouvelle entrée utilisateur à partir du modèle approprié, vous devriez immédiatement changer le mot de passe du nouvel utilisateur.

Si UTILISATEUR n'est pas spécifié, cette commande changera le mot de passe de l'utilisateur (SNMPv3) qui exécute la commande. Si les options -Ca ou -Cx sont spécifiées, seules les clés d'authentification ou de confidentialité sont modifiées. Si ces options ne sont pas spécifiées, alors les clés d'authentification et de confidentialité sont modifiées.

snmpusm [OPTIONS COMMUNES] [-Ca] [-Cx] AGENT changekey [UTILISATEUR]

Cette commande change la clé d'une manière conforme à la confidentialité parfaite en avant (perfect-forward-secrecy) via un échange diffie-helman. L'agent distant doit supporter la MIB SNMP-USM-DH-OBJECTS pour que cette commande fonctionne. Les clés résultantes sont affichées sur la console et peuvent ensuite être définies dans les futures invocations de commande en utilisant les options --defAuthLocalizedKey et --defPrivLocalizedKey ou dans votre fichier snmp.conf en utilisant les mots-clés defAuthLocalizedKey et defPrivLocalizedKey.

Notez que puisque ces clés sont générées aléatoirement sur la base d'un échange diffie helman, elles ne sont plus dérivées d'un mot de passe plus facile à taper. Elles sont cependant beaucoup plus sécurisées.

Pour passer d'une clé localisée à un mot de passe, la variante suivante de la sous-commande passwd est utilisée :

snmpusm [OPTIONS COMMUNES] <-Ca | -Cx> -Ck AGENT passwd ANCIENNE-CLE-OU-MOTDEPASSE NOUVELLE-CLE-OU-MOTDEPASSE [UTILISATEUR]

L'option -Ca ou -Cx doit être spécifiée. Les arguments ANCIENNE-CLE-OU-MOTDEPASSE et/ou NOUVELLE-CLE-OU-MOTDEPASSE peuvent être soit un mot de passe, soit une clé localisée commençant par "0x", par exemple, telle qu'affichée par la sous-commande changekey.

Notez que snmpusm REQUIERT un argument spécifiant l'agent à interroger, comme décrit dans la page de manuel de .I snmpcmd(1).

EXEMPLES

Supposons pour nos exemples que les lignes de configuration VACM et USM suivantes se trouvaient dans le fichier snmpd.conf pour un agent Net-SNMP. Ces lignes ont mis en place un utilisateur par défaut appelé "initial" avec le mot de passe d'authentification "setup_passphrase" afin que nous puissions effectuer la configuration initiale d'un agent :

# Lignes de configuration VACM
rwuser initial
# ajoutons aussi le nouvel utilisateur que nous allons créer :
rwuser wes
# Lignes de configuration USM
createUser initial MD5 setup_passphrase DES

Remarque : la configuration de l'utilisateur "initial" devrait être supprimée après la création d'un véritable utilisateur auquel vous accordez des privilèges administratifs (comme l'utilisateur "wes" que nous allons créer dans cet exemple).

Remarque : les mots de passe doivent être d'une longueur minimale de 8 caractères.

Créer un nouvel utilisateur

snmpusm -v3 -u initial -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost create wes initial

Crée un nouvel utilisateur, ici nommé "wes" en utilisant l'utilisateur "initial" pour le faire. "wes" est cloné à partir de "initial" dans le processus, donc il hérite du mot de passe de cet utilisateur ("setup_passphrase").

<

CHANGING PASS PHRASES

snmpusm -v 3 -u wes -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost passwd setup_passphrase new_passphrase

Après avoir créé l'utilisateur "wes" avec la même phrase secrète que l'utilisateur "initial", nous devons changer sa phrase secrète pour lui. La commande ci-dessus la change de "setup_passphrase", qui a été héritée de l'utilisateur initial, à "new_passphrase".

Tester le nouvel utilisateur

snmpget -v 3 -u wes -n "" -l authNoPriv -a MD5 -A new_passphrase localhost sysUpTime.0

Si les commandes ci-dessus ont réussi, cette commande aurait dû correctement effectuer une requête SNMPv3 GET authentifiée vers l'agent.

Maintenant, supprimez l'entrée vacm "group" de snmpd.conf pour l'"initial" utilisateur et vous aurez un utilisateur valide 'wes' que vous pourrez utiliser pour les transactions futures à la place de initial.

AVERTISSEMENT

La manipulation de usmUserTable à l'aide de cette commande ne peut *que* être effectuée en utilisant SNMPv3. Cette commande ne fonctionnera pas avec les versions basées sur les communautés, même si elles ont un accès en écriture à la table.
