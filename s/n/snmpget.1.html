NOM

snmpget - communique avec une entité réseau à l'aide de requêtes GET SNMP

SYNTAXE

snmpget [OPTIONS COMMUNES] [-Cf] AGENT OID [OID]...

DESCRIPTION

snmpget est une application SNMP qui utilise la requête GET SNMP pour interroger des informations sur une entité réseau. Un ou plusieurs identificateurs d'objets (OID) peuvent être fournis en arguments sur la ligne de commande. Chaque nom de variable est donné dans le format spécifié dans variables(5).

OPTIONS

-Cf
Si -Cf n'est *pas* spécifié, certaines applications (snmpdelta, snmpget, snmpgetnext et snmpstatus) essaieront de corriger les erreurs renvoyées par l'agent avec lequel vous communiquiez et renverront la requête. Le seul cas où cela est vraiment utile est si vous avez spécifié un OID qui n'existait pas dans votre requête et que vous utilisez SNMPv1, qui nécessite des requêtes de type "tout ou rien".

En plus de cette option, snmpget prend les options communes décrites dans la page de manuel snmpcmd(1). Notez que snmpget REQUIERT un argument spécifiant l'agent à interroger et au moins un argument OID, comme décrit là.

EXEMPLES

La commande :


snmpget -c public zeus system.sysDescr.0

récupérera la variable system.sysDescr.0 de l'hôte zeus en utilisant la chaîne de communauté public :


system.sysDescr.0 = "SunOS zeus.net.cmu.edu 4.1.3_U1 1 sun4m"

Si l'entité réseau a une erreur lors du traitement du paquet de requête, un paquet d'erreur sera renvoyé et un message sera affiché, aidant à localiser la manière dont la requête était mal formée. S'il y avait d'autres variables dans la requête, la requête sera renvoyée sans la variable erronée.

Voici un autre exemple. Les options -c et -v sont définies dans la page de manuel snmpcmd(1). (Notez que system.sysUpTime est un OID incomplet, car il faut y ajouter l'index .0) :

    snmpget -v1 -Cf -c public localhost system.sysUpTime system.sysContact.0

Cet exemple renverra ce qui suit :

    Error in packet
    Reason: (noSuchName) There is no such variable name in this MIB.
    This name doesn't exist: system.sysUpTime

De même, la commande :

    snmpget -v1 -c public localhost system.sysUpTime system.sysContact.0

Renverra :

    Error in packet
    Reason: (noSuchName) There is no such variable name in this MIB.
    This name doesn't exist: system.sysUpTime
    system.sysContact.0 = STRING: root@localhost

Avec le drapeau -Cf spécifié, l'application n'essaiera pas de corriger le PDU pour vous.

VOIR AUSSI

snmpcmd(1), snmpwalk(1), variables(5).
