NOM

snmptrapd - Recevoir et enregistrer les messages SNMP TRAP.

SYNTAXE

snmptrapd [OPTIONS] [ADRESSES D'ÉCOUTE]

DESCRIPTION

snmptrapd est une application SNMP qui reçoit et enregistre les messages SNMP TRAP et INFORM.

Note: par défaut, il écoute sur le port UDP 162 sur toutes les interfaces IPv4. Comme 162 est un port privilégié, snmptrapd doit généralement être exécuté en tant que root.

OPTIONS

-a
Ignorer les traps d'authentification non réussie (authenticationFailure).
-A
Ajouter au fichier journal au lieu de le tronquer.

Notez que cela doit apparaître avant toute option -Lf à laquelle il s'applique.

-c FICHIER
Lire FICHIER comme fichier de configuration (ou une liste de fichiers de configuration séparés par des virgules).
-C
Ne pas lire de fichiers de configuration autres que celui éventuellement spécifié par l'option -c.
-d
Afficher (en hexadécimal) les paquets SNMP envoyés et reçus.
-D[JETON[,...]]
Activer la sortie de débogage pour le(s) JETON(s) donné(s). Essayez ALL pour une sortie extrêmement verbeuse.
-f
Ne pas créer de fork() à partir du shell appelant.
-F FORMAT
Lors de l'enregistrement sur la sortie standard, utiliser le format de la chaîne FORMAT. Voir la section SPÉCIFICATIONS DE FORMAT ci-dessous pour plus de détails.
-h, --help
Afficher un bref message d'utilisation puis quitter.
-H
Afficher une liste des directives de fichier de configuration comprises par le démon de trap puis quitter.
-I [-]LISTE_INIT
Spécifie quels modules doivent (ou ne doivent pas) être initialisés au démarrage de snmptrapd. Si la LISTE_INIT séparée par des virgules est précédée d'un '-', c'est la liste des modules qui ne doivent pas être démarrés. Sinon, c'est la liste des seuls modules qui doivent être démarrés.

Pour obtenir une liste des modules compilés, exécutez snmptrapd avec les arguments -Dmib_init -H (en supposant que le support de débogage a été compilé).

-L[efos]
Spécifie où la sortie de journalisation doit être dirigée (erreur ou sortie standard, vers un fichier ou via syslog). Voir OPTIONS DE JOURNALISATION dans snmpcmd(1) pour les détails.
-m LISTE_MIB
Spécifie une liste de modules MIB séparés par des deux-points à charger pour cette application. Cela remplace la variable d'environnement MIBS. Voir snmpcmd(1) pour les détails.
-M LISTE_DIR
Spécifie une liste de répertoires séparés par des deux-points à rechercher pour les MIBs. Cela remplace la variable d'environnement MIBDIRS. Voir snmpcmd(1) pour les détails.
-n
Ne pas tenter de traduire les adresses sources des paquets entrants en noms d'hôtes.
-p FICHIER
Enregistrer l'ID de processus du démon de trap dans FICHIER.
-O [abeEfnqQsStTuUvxX]
Spécifie comment les objets MIB et les autres sorties doivent être affichés. Voir la section OPTIONS DE SORTIE de la page de manuel de snmpcmd(1) pour les détails.
-t
Ne pas enregistrer les traps dans syslog. Ceci désactive l'enregistrement dans syslog. C'est utile si vous voulez que l'application snmptrapd exécute uniquement les hooks traphandle et n'enregistre aucun trap nulle part.
-v, --version
Afficher les informations de version pour le démon de trap puis quitter.
-x ADRESSE
Se connecter à l'agent maître AgentX à l'adresse spécifiée, plutôt qu'à l'adresse par défaut "/var/agentx/master". Voir snmpd(8) pour les détails du format de telles adresses.
-X
Ne pas se connecter à un agent maître AgentX
--nom="valeur"
Permet de spécifier n'importe quel jeton ("nom") pris en charge dans le fichier snmptrapd.conf et de définir sa valeur à "valeur". Remplace le jeton correspondant dans le fichier snmptrapd.conf. Voir snmptrapd.conf(5) pour la liste complète des jetons.

SPÉCIFICATIONS DE FORMAT

snmptrapd interprète les chaînes de format de manière similaire à printf(3). Il comprend les séquences de formatage suivantes :

%%
un % littéral
%a
le contenu du champ agent-addr du PDU (TRAP v1 uniquement)
%A
le nom d'hôte correspondant au contenu du champ agent-addr du PDU, si disponible, sinon le contenu du champ agent-addr du PDU (TRAP v1 uniquement).
%b
adresse de transport du PDU (Note: ce n'est pas nécessairement une adresse IPv4).
Quelque chose comme "[UDP: [172.16.10.12]:23456->[10.150.0.8]]"
%B
nom d'hôte source du PDU si disponible, sinon adresse source du PDU (voir la note ci-dessus)
%E
ID du moteur de contexte SNMPv3
%h
heure actuelle sur le système local
%H
le champ heure de la variable sysUpTime.0
%j
minute actuelle sur le système local
%J
le champ minute de la variable sysUpTime.0
%k
seconde actuelle sur le système local
%K
le champ seconde de la variable sysUpTime.0
%l
jour du mois actuel sur le système local
%L
le champ jour du mois de la variable sysUpTime.0
%m
mois actuel (numérique) sur le système local
%M
le champ mois numérique de la variable sysUpTime.0
%N
chaîne d'entreprise
%P
informations de sécurité du PDU (nom de communauté pour v1/v2c, utilisateur et contexte pour v3)
%q
sous-type de trap (numérique, en décimal)
%s
numéro de version SNMP (0: v1, 1: v2c, 2: v3)
%S
numéro de version du modèle de sécurité SNMPv3
%t
nombre de secondes en décimal depuis l'époque du système d'exploitation (tel que retourné par time(2))
%T
la valeur de sysUpTime.0 en secondes
%u
nom de sécurité SNMPv3, ou nom de communauté v1/v2c
%v
liste des liaisons de variables de la charge utile de notification. Elles seront séparées par une tabulation, ou par une virgule et un espace si la forme alternative est demandée. Voir également %V
%V
spécifie le séparateur des liaisons de variables. Ceci prend une séquence de caractères, jusqu'au prochain % (pour intégrer un % dans la chaîne, utilisez \%)
%w
type de trap (numérique, en décimal)
%W
description du trap
%y
année actuelle sur le système local
%Y
le champ année de la variable sysUpTime.0

En plus de ces valeurs, une largeur de champ et une précision optionnelles peuvent également être spécifiées, tout comme dans printf(3), et une valeur de drapeau. Les drapeaux suivants sont pris en charge :

-
justifier à gauche
0
utiliser des zéros de remplissage
#
utiliser la forme alternative

Le drapeau "utiliser la forme alternative" modifie le comportement de diverses séquences de chaînes de format :

Les informations de temps seront affichées en heure GMT (plutôt qu'en fuseau horaire local)
Les liaisons de variables seront une liste séparée par des virgules (plutôt qu'une liste séparée par des tabulations)
Le temps de fonctionnement du système sera présenté dans un format lisible par l'homme (plutôt qu'un simple entier)

Exemples :

Pour obtenir un message tel que « 14:03 TRAP3.1 from humpty.ucd.edu » vous pouvez utiliser quelque chose comme ceci :

snmptrapd -P -F « %02.2h:%02.2j TRAP%w.%q from %A
»

Si vous souhaitez la même chose mais en GMT plutôt qu'en heure locale, utilisez :

snmptrapd -P -F « %#02.2h:%#02.2j TRAP%w.%q from %A
»

ADRESSES D'ÉCOUTE

Par défaut, snmptrapd écoute les paquets SNMP TRAP et INFORM entrants sur le port UDP 162 sur toutes les interfaces IPv4. Il est cependant possible de modifier ce comportement en spécifiant une ou plusieurs adresses d'écoute comme arguments à snmptrapd. Voir la page de manuel de snmpd(8) pour plus d'informations sur le format des adresses d'écoute.

SUPPORT DE NOTIFICATION-LOG-MIB

Depuis net-snmp 5.0, l'application snmptrapd prend en charge le NOTIFICATION-LOG-MIB. Elle le fait en ouvrant une connexion d'agent secondaire AgentX à l'agent maître snmpd et en enregistrant les tables de journaux de notifications. Tant que l'application snmpd est démarrée en premier, elle s'y connectera et vous devriez donc pouvoir consulter les dernières notifications enregistrées via les tables nlmLogTable et nlmLogVariableTable. Voir le fichier snmptrapd.conf et le jeton « doNotRetainNotificationLogs » pour désactiver ce support. Voir le NOTIFICATION-LOG-MIB pour plus de détails sur le MIB lui-même.
