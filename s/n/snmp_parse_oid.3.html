DESCRIPTION

The functions dealing with MIB modules fall into four groups - those dealing with initialisation and shutdown, with reading in and parsing MIB files, with searching the MIB tree, and output routines.

Initialisation and Shutdown

add_mibdir is used to add the specified directory to the path of locations which are searched for files containing MIB modules. Note that this does not actually load the MIB modules located in that directory, but is simply an initialisation step to make them available to netsnmp_read_module. This function returns a count of files found in the directory, or a -1 if there is an error. It should be called before invoking netsnmp_init_mib.

netsnmp_init_mib configures the MIB directory search path (using add_mibdir ), sets up the internal MIB framework, and then loads the appropriate MIB modules (using netsnmp_read_module and read_mib). See the ENVIRONMENTAL VARIABLES section for details.
It should be called before any other routine that manipulates or accesses the MIB tree (but after any additional add_mibdir calls).

shutdown_mib will clear the information that was gathered by netsnmp_read_module, add_mibdir and add_module_replacement. It is strongly recommended that one does not invoke shutdown_mib while there are SNMP sessions being actively managed.

Reading and Parsing MIBs

netsnmp_read_module takes the name of a MIB module (which need not be the same as the name of the file that contains the module), locates this within the configured list of MIB directories, and loads the definitions from the module into the active MIB tree. It also loads any MIB modules listed in the IMPORTS clause of this module.

read_mib is similar, but takes the name of the file containing the MIB module. Note that this file need not be located within the MIB directory search list (although any modules listed in the IMPORTS clause do).

read_all_mibs will read in all the MIB modules found on the MIB directory search list.

In general the parser is silent about what strangenesses it sees in the MIB files. To get warnings reported, call snmp_set_mib_warnings with a level of 1 (or 2 for even more warnings).

add_module_replacement can be used to allow new MIB modules to obsolete older ones, without needing to amend the IMPORTS clauses of other modules. It takes the names of the old and new modules, together with an indication of which portions of the old module are affected.

tag len load the new module when:
NULL 0 always (the old module is a strict subset of
the new)
name 0 for the given tag only
name non-0 for any identifier with this prefix
It can also be used to handle errors in the module identifiers used in MIB IMPORTS clauses (such as referring to RFC1213 instead of RFC1213-MIB).

Searching the MIB Tree

read_objid takes a string containing a textual version of an object identifier (in either numeric or descriptor form), and transforms this into the corresponding list of sub-identifiers. This is returned in the output parameter, with the number of sub-identifiers returned via out_len. When called, out_len must hold the maximum length of the output array. If multiple object identifiers are being processed, then this length should be reset before each call. This function returns a value of 1 if it succeeds in parsing the string and 0 otherwise.

snmp_parse_oid is similar, but returns a pointer to the parsed OID buffer (or NULL).

get_module_node takes a descriptor and the name of a module, and returns the corresponding oid list, in the same way as read_objid above.
If the module name is specified as "ANY", then this routine will assume that the descriptor given is unique within the tree, and will return the matching entry. If this assumption is invalid, then the behaviour as to which variable is returned is implementation dependent.

Output

print_mib will print out a representation of the currently active MIB tree to the specified FILE pointer.

print_objid will take an object identifier (as returned by read_objid, snmp_parse_oid or get_module_node), and prints the textual form of this OID to the standard output.

fprint_objid does the same, but prints to the FILE pointer specified by the initial parameter.

snprint_objid prints the same information into the buffer pointed to by buf which is of length len. It returns the number of characters printed, or -1 if the buffer was not large enough. In the latter case, buf will typically contain a truncated version of the information (but this behaviour is not guaranteed).

print_description, fprint_description, and snprint_description take a similar object identifier and print out a version of the MIB definition for that object, together with the full OID. The width argument controls how the OID is layed out.

DESCRIPTION

Les fonctions traitant des modules MIB se répartissent en quatre groupes : celles qui traitent de l'initialisation et de l'arrêt, de la lecture et de l'analyse des fichiers MIB, de la recherche dans l'arbre MIB et des routines de sortie.

Initialisation et Arrêt

add_mibdir est utilisé pour ajouter le répertoire spécifié au chemin des emplacements qui sont recherchés pour les fichiers contenant des modules MIB. Notez que cela ne charge pas réellement les modules MIB situés dans ce répertoire, mais est simplement une étape d'initialisation pour les rendre disponibles à netsnmp_read_module. Cette fonction renvoie un compte des fichiers trouvés dans le répertoire, ou -1 en cas d'erreur. Elle doit être appelée avant d'invoquer netsnmp_init_mib.

netsnmp_init_mib configure le chemin de recherche des répertoires MIB (en utilisant add_mibdir), met en place le cadre interne MIB, puis charge les modules MIB appropriés (en utilisant netsnmp_read_module et read_mib). Voir la section VARIABLES D'ENVIRONNEMENT pour plus de détails.
Elle doit être appelée avant toute autre routine qui manipule ou accède à l'arbre MIB (mais après tout appel supplémentaire à add_mibdir).

shutdown_mib effacera les informations qui ont été collectées par netsnmp_read_module, add_mibdir et add_module_replacement. Il est fortement recommandé de ne pas invoquer shutdown_mib pendant qu'il y a des sessions SNMP gérées activement.

Lecture et Analyse des MIBs

netsnmp_read_module prend le nom d'un module MIB (qui n'a pas besoin d'être le même que le nom du fichier qui contient le module), le localise dans la liste configurée des répertoires MIB, et charge les définitions du module dans l'arbre MIB actif. Il charge également tous les modules MIB listés dans la clause IMPORTS de ce module.

read_mib est similaire, mais prend le nom du fichier contenant le module MIB. Notez que ce fichier n'a pas besoin d'être situé dans la liste de recherche des répertoires MIB (bien que tous les modules listés dans la clause IMPORTS le soient).

read_all_mibs lira tous les modules MIB trouvés sur la liste de recherche des répertoires MIB.

En général, l'analyseur est silencieux quant aux étrangetés qu'il rencontre dans les fichiers MIB. Pour obtenir des avertissements, appelez snmp_set_mib_warnings avec un level de 1 (ou 2 pour encore plus d'avertissements).

add_module_replacement peut être utilisé pour permettre aux nouveaux modules MIB d'obsoléter les anciens, sans avoir besoin de modifier les clauses IMPORTS d'autres modules. Il prend les noms des anciens et nouveaux modules, avec une indication des parties de l'ancien module qui sont affectées.

tag len charge le nouveau module quand :
NULL 0 toujours (l'ancien module est un sous-ensemble strict du
nouveau)
name 0 pour la balise donnée uniquement
name non-0 pour tout identifiant avec ce préfixe
Il peut également être utilisé pour gérer les erreurs dans les identificateurs de modules utilisés dans les clauses IMPORTS des MIB (comme référencer RFC1213 au lieu de RFC1213-MIB).

Recherche dans l'Arbre MIB

read_objid prend une chaîne contenant une version textuelle d'un identificateur d'objet (sous forme numérique ou descriptive), et la transforme en la liste correspondante de sous-identificateurs. Ceci est renvoyé dans le paramètre output, avec le nombre de sous-identificateurs renvoyé via out_len. Lors de l'appel, out_len doit contenir la longueur maximale du tableau output. Si plusieurs identificateurs d'objet sont traités, cette longueur doit être réinitialisée avant chaque appel. Cette fonction renvoie la valeur 1 si elle réussit à analyser la chaîne et 0 sinon.

snmp_parse_oid est similaire, mais renvoie un pointeur vers le tampon OID analysé (ou NULL).

get_module_node prend un descripteur et le nom d'un module, et renvoie la liste OID correspondante, de la même manière que read_objid ci-dessus.
Si le nom du module est spécifié comme « ANY », cette routine suppose que le descripteur donné est unique dans l'arbre, et renvoie l'entrée correspondante. Si cette supposition est invalide, le comportement quant à la variable renvoyée dépend de l'implémentation.

Sortie

print_mib imprimera une représentation de l'arbre MIB actif sur le pointeur FILE spécifié.

print_objid prendra un identificateur d'objet (tel que renvoyé par read_objid, snmp_parse_oid ou get_module_node), et imprimera la forme textuelle de cet OID sur la sortie standard.

fprint_objid fait de même, mais imprime sur le pointeur FILE spécifié par le paramètre initial.

snprint_objid imprime les mêmes informations dans le tampon pointé par buf qui a une longueur len. Il renvoie le nombre de caractères imprimés, ou -1 si le tampon n'était pas assez grand. Dans ce dernier cas, buf contiendra généralement une version tronquée des informations (mais ce comportement n'est pas garanti).

print_description, fprint_description et snprint_description prennent un identificateur d'objet similaire et impriment une version de la définition MIB pour cet objet, ainsi que l'OID complet. Le paramètre width contrôle la manière dont l'OID est présenté.

VARIABLES D'ENVIRONNEMENT

L'utilisation principale des variables d'environnement par rapport à ces appels API est de configurer quels modules MIB doivent être chargés et où ils se trouvent.

MIBDIRS
Une liste de répertoires séparés par des deux-points où rechercher les modules MIB.
Par défaut : /usr/share/snmp/mibs
Utilisé par init_mib, netsnmp_read_module, read_all_mibs et (implicitement) par read_mib.
MIBS
Une liste de modules MIB séparés par des deux-points à charger.
La liste par défaut des modules dépendra de la manière dont le logiciel Net-SNMP a été compilé à l'origine, mais elle est généralement la suivante :
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
Si la valeur de la variable d'environnement MIBS commence par un caractère '+', alors ces modules MIB seront ajoutés à la liste par défaut. Sinon, ces modules (plus ceux dont ils dépendent par IMPORT) seront chargés *à la place* de la liste par défaut.
Si la variable d'environnement MIBS a la valeur ALL, alors read_all_mibs sera appelée pour charger la collection complète de tous les modules MIB disponibles.
Utilisé par init_mib uniquement.
MIBFILES
Une liste de fichiers séparés par des deux-points à charger.
Par défaut : (aucun)
Utilisé par init_mib uniquement.
