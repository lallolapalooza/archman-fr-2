NOM

snmp_config - gestion des fichiers de configuration Net-SNMP

DESCRIPTION

Le paquet Net-SNMP utilise divers fichiers de configuration pour configurer ses applications. Cette page de manuel décrit simplement la nature générale de ces fichiers, afin que les autres pages de manuel n'aient pas à le faire.

RÉPERTOIRES RECHERCHÉS

Tout d'abord, il existe de nombreux emplacements où les fichiers de configuration peuvent être trouvés et lus. Par défaut, les applications recherchent les fichiers de configuration dans les 4 répertoires suivants, par ordre : /etc/snmp, /usr/share/snmp, /usr/lib/snmp, et $HOME/.snmp. Dans chacun de ces répertoires, elles recherchent les fichiers snmp.conf, snmpd.conf et/ou snmptrapd.conf, ainsi que snmp.local.conf, snmpd.local.conf et/ou snmptrapd.local.conf. Les fichiers *.local.conf sont toujours lus en dernier. De cette manière, il existe 8 emplacements par défaut où un fichier de configuration peut exister pour tout type de fichier de configuration donné.

De plus, le chemin de recherche par défaut ci-dessus peut être remplacé en définissant la variable d'environnement SNMPCONFPATH avec une liste de répertoires séparés par des deux-points à rechercher. Le chemin des données persistantes doit être inclus lors de l'exécution d'applications utilisant le stockage persistant, tel que snmpd.

Les applications liront les fichiers de configuration persistants dans l'ordre de préférence suivant :

fichier dans la variable d'environnement SNMP_PERSISTENT_FILE
répertoires dans la variable d'environnement SNMPCONFPATH
répertoire défini par la variable snmp.conf persistentDir
répertoire dans la variable d'environnement SNMP_PERSISTENT_DIR
répertoire par défaut /var/net-snmp

Enfin, les applications écriront les fichiers de configuration persistants dans l'ordre de préférence suivant :

fichier dans la variable d'environnement SNMP_PERSISTENT_FILE
répertoire défini par la variable snmp.conf persistentDir
répertoire dans la variable d'environnement SNMP_PERSISTENT_DIR
répertoire par défaut /var/net-snmp

Note : Lors de l'utilisation de SNMP_PERSISTENT_FILE, le nom du fichier doit correspondre au nom de l'application. Par exemple, /var/net-snmp/snmpd.conf.

TYPES DE FICHIERS DE CONFIGURATION

Chaque application peut utiliser plusieurs fichiers de configuration, qui configureront divers aspects de l'application. Par exemple, l'agent SNMP (snmpd) sait comprendre les directives de configuration dans les fichiers snmpd.conf et snmp.conf. En fait, la plupart des applications savent lire le contenu des fichiers snmp.conf. Notez cependant que les directives de configuration comprises dans un fichier peuvent ne pas l'être dans un autre. Pour plus d'informations, lisez la page de manuel associée à chaque type de fichier de configuration. De plus, la plupart des applications prennent en charge un commutateur -H en ligne de commande qui listera les fichiers de configuration qu'elles rechercheront et les directives que chacune comprend. La plupart des applications prennent en charge un commutateur -H en ligne de commande qui listera les fichiers de configuration qu'elles recherchent et les directives comprises dans chacune.

Le fichier de configuration snmp.conf est destiné à être un fichier de configuration global pour la suite d'applications, prenant en charge les directives utiles pour contrôler la nature fondamentale de toutes les applications SNMP, telles que la manière dont elles manipulent et analysent les fichiers MIB textuels SNMP.

CHANGEMENT DES TYPES DE CONFIGURATION EN MILIEU DE FICHIER

Il est possible de changer, en cours de fichier, le type de configuration que l'analyseur est censé lire. Comme cette phrase n'a pas beaucoup de sens, donnons un exemple : supposons que vous vouliez activer la sortie de vidage de paquets pour l'agent par défaut, mais que vous ne vouliez pas le faire pour le reste des applications (c'est-à-dire snmpget, snmpwalk, ...). Normalement, pour activer le vidage de paquets dans le fichier de configuration, vous devriez mettre une ligne comme celle-ci :

dumpPacket true

dans le fichier snmp.conf. Mais cela l'activerait pour toutes les applications. Donc, au lieu de cela, vous pouvez mettre la même ligne dans le fichier snmpd.conf afin qu'elle ne s'applique qu'au démon snmpd. Cependant, vous devez indiquer à l'analyseur de s'attendre à cette ligne. Vous le faites en plaçant un jeton de spécification de type spécial entre crochets []. Autrement dit, dans votre fichier snmpd.conf, vous pourriez mettre la directive snmp.conf ci-dessus en ajoutant une ligne comme celle-ci :

[snmp] dumpPacket true

Cela indique à l'analyseur d'analyser la ligne ci-dessus comme s'il se trouvait dans un fichier snmp.conf au lieu d'un fichier snmpd.conf. Si vous voulez analyser un ensemble de lignes plutôt qu'une seule, vous pouvez faire en sorte que le changement de contexte s'applique au reste du fichier ou jusqu'à la prochaine directive de changement de contexte en plaçant le jeton spécial sur une ligne seule :

# fait en sorte que ce fichier gère les jetons snmp.conf :
[snmp]
dumpPacket true
logTimestamp true
# retourne à nos jetons snmpd.conf d'origine :
[snmpd]
rocommunity mypublic

La même approche peut être utilisée pour définir des directives de configuration pour une application cliente particulière (ou un groupe d'applications). Par exemple, tout programme utilisant l'appel 'snmp_parse_args()' pour gérer les arguments de la ligne de commande (y compris les outils de ligne de commande standard fournis avec les distributions Net-SNMP) lira automatiquement le fichier de configuration 'snmpapp.conf'. Pour définir des paramètres au niveau de la bibliothèque pour ces applications (mais pas pour d'autres outils plus spécifiques), utilisez une configuration telle que la suivante :

[snmp] defCommunity myCommunity

pour une directive unique, ou

# fait en sorte que ce fichier gère les jetons snmp.conf :
[snmp]
defCommunity myCommunity
defVersion   2c
# retourne à nos jetons snmpapp.conf d'origine :
[snmpapp]

pour plusieurs paramètres. De même pour tout autre jeton d'application (tel que passé à init_snmp()).

COMMENTAIRES

Toutes les lignes commençant par le caractère '#' dans les fichiers de configuration sont traitées comme un commentaire et ne sont pas analysées.

INCLUSION D'AUTRES FICHIERS DE CONFIGURATION

Il est possible d'inclure d'autres fichiers de configuration pour traitement pendant le traitement normal des fichiers de configuration :

# inclure la configuration spécifique du site
includeFile site.conf
Ceci chargera le fichier de configuration spécifié. Le chemin du fichier
doit être soit absolu, commençant par '/',
soit relatif. Le chemin relatif est alors relatif au répertoire
où réside le fichier parent avec la directive 'includeFile'.
Le nom du fichier inclus n'a pas besoin d'avoir le suffixe '.conf'.
# inclure tous les fichiers *.conf dans un répertoire
includeDir /etc/snmp/config.d
Ceci recherchera dans le répertoire spécifié tous les fichiers avec le suffixe '.conf'
et les traitera comme s'ils avaient été inclus en utilisant la directive includeFile.
Les fichiers de configuration ne sont pas traités dans un ordre particulier.
Le répertoire spécifié doit être un chemin de répertoire absolu.

INTERFACE API

Des informations sur l'écriture de code C utilisant ce système, que ce soit dans les modules MIB de l'agent ou dans les applications, peuvent être trouvées dans la page de manuel netsnmp_config_api(3).
