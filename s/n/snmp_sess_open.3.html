DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multithread. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur de session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui contient les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure a été passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. À la place, le pointeur opaque retourné par snmp_sess_open() est utilisé pour faire référence à cette session par la suite.

Les sessions SNMP qui sont créées avec snmp_sess_open() ne sont pas affectées par, et NE DEVRAIENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Plutôt, les fonctions équivalentes à session unique décrites ici devraient être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacun en entrée un pointeur vers un objet structure snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers sa structure snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacun un paramètre pdu, qui pointe vers un objet structure snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read invoquera le callback spécifié lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela pourrait inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent respectivement aux arguments nfds, readfds et timeout de select(2). La seule exception est que timeout doit TOUJOURS pointer vers une structure struct timeval allouée (mais potentiellement non initialisée) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors défini à vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données retournées. Lorsqu'il retourne, snmp_sess_read() doit ensuite être appelé avec le fd_set retourné par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire qu'il retourne zéro), snmp_sess_timeout() doit être appelé pour vérifier si une expiration s'est produite sur la session SNMP.

snmp_sess_synch_response est une routine pratique qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send, snmp_sess_read etc pour plus de détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut de succès retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable snmp_errno de SNMP, la valeur de la variable errno du système, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_GENERR

NAME

snmp_sess_open - open an SNMP session

SYNOPSIS

#include <net-snmp/session.h>

struct snmp_session *
snmp_sess_open(struct snmp_session *session);

DESCRIPTION

snmp_sess_open opens an SNMP session to an SNMP entity (agent or manager). It takes a pointer to an snmp_session structure, which should be initialized by the caller.

The snmp_session structure is used to specify the details of the session, such as the remote hostname or IP address, the SNMP version, community string (for SNMPv1 and v2c), or user credentials (for SNMPv3).

If the session is opened successfully, a pointer to the (possibly modified) snmp_session structure is returned. This pointer should be used in subsequent calls to Net-SNMP library functions. If an error occurs during session opening, NULL is returned.

DIAGNOSTICS

Errors during session opening are typically indicated by a NULL return value. The specific error can often be determined by examining the s_errno field of the snmp_session structure, or by using other Net-SNMP error handling functions.

Common error codes include:

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

NOM

snmp_sess_open - ouvrir une session SNMP

SYNTAXIS

#include <net-snmp/session.h>

struct snmp_session *
snmp_sess_open(struct snmp_session *session);

DESCRIPTION

snmp_sess_open ouvre une session SNMP vers une entité SNMP (agent ou gestionnaire). Il prend en argument un pointeur vers une structure snmp_session, qui doit être initialisée par l'appelant.

La structure snmp_session est utilisée pour spécifier les détails de la session, tels que le nom d'hôte ou l'adresse IP distante, la version SNMP, la chaîne de communauté (pour SNMPv1 et v2c), ou les identifiants d'utilisateur (pour SNMPv3).

Si la session est ouverte avec succès, un pointeur vers la structure snmp_session (éventuellement modifiée) est retourné. Ce pointeur doit être utilisé dans les appels ultérieurs aux fonctions de la bibliothèque Net-SNMP. Si une erreur se produit lors de l'ouverture de la session, NULL est retourné.

DIAGNOSTICS

Les erreurs lors de l'ouverture de session sont généralement indiquées par une valeur de retour NULL. L'erreur spécifique peut souvent être déterminée en examinant le champ s_errno de la structure snmp_session, ou en utilisant d'autres fonctions de gestion d'erreurs Net-SNMP.

Les codes d'erreur courants incluent :

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

VOIR AUSSI

select(2), netsnmp_session_api(3), netsnmp_pdu_api(3), netsnmp_varbind_api(3), netsnmp_mib_api(3), snmp_api.h
