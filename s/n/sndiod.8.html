SNDIOD(8) Manuel du gestionnaire système SNDIOD(8)

NOM

sndiod — serveur audio/MIDI

SYNOPIS

sndiod [-d] [-a flag] [-b nframes] [-C min:max] [-c min:max] [-e enc] [-F device] [-f device] [-j flag] [-L addr] [-m mode] [-Q port] [-q port] [-r rate] [-s name] [-t mode] [-U unit] [-v volume] [-w flag] [-z nframes]

DESCRIPTION

Le démon sndiod est une couche intermédiaire entre les programmes audio ou MIDI et le matériel. Il effectue le traitement audio nécessaire pour permettre à n'importe quel programme de fonctionner sur n'importe quel matériel supporté. Par défaut, sndiod accepte uniquement les connexions des programmes exécutés sur le même système ; il ne s'initialise que lorsque des programmes utilisent ses services, permettant à sndiod de consommer une quantité négligeable de ressources système le reste du temps. Les systèmes sans matériel audio peuvent utiliser sndiod pour maintenir les périphériques enfichables à chaud utilisables par défaut à un coût pratiquement nul.

sndiod fonctionne comme suit : il expose au moins un sous-périphérique auquel n'importe quel nombre de programmes audio peuvent se connecter et l'utiliser comme s'il s'agissait de matériel audio. Lors de la lecture, sndiod reçoit simultanément les données audio de tous les programmes, les mélange et envoie le résultat au périphérique matériel. De même, lors de l'enregistrement, il duplique les données audio enregistrées à partir du périphérique et les envoie à tous les programmes. Étant donné que les données audio transitent par le processus sndiod, celui-ci a la possibilité de traiter les données audio à la volée :

  • Changer l'encodage du son pour surmonter les incompatibilités entre le logiciel et le matériel.
  • Routage du son d'un canal à un autre, fusion de stéréo ou séparation de mono.
  • Contrôle du volume de lecture par application ainsi que du volume maître.
  • Surveillance du son en cours de lecture, permettant à un programme d'enregistrer ce que d'autres programmes jouent.

Le traitement est configuré par sous-périphérique, ce qui signifie que le son de tous les programmes connectés au même sous-périphérique sera traité selon la même configuration. Plusieurs sous-périphériques peuvent être définis, permettant à plusieurs configurations de coexister. L'utilisateur sélectionne la configuration qu'un programme donné utilisera en sélectionnant le sous-périphérique que le programme utilisera.

sndiod expose des boîtes de dérivation MIDI (hubs), permettant aux programmes de s'envoyer mutuellement des messages MIDI ou des messages vers des ports MIDI matériels de manière uniforme.

Enfin, sndiod expose un port MIDI de contrôle utilisable pour :

  • Le contrôle du volume.
  • Une source d'horloge commune pour les programmes audio et MIDI.
  • Démarrer, arrêter et déplacer des groupes de programmes audio.

Les options sont les suivantes :

-a flag
Contrôle si sndiod ouvre le périphérique audio ou le port MIDI uniquement lorsque nécessaire ou le garde ouvert en permanence. Si le drapeau est on, alors le périphérique audio ou le port MIDI est gardé ouvert en permanence, empêchant tout autre programme de le voler. Si le drapeau est off, alors il est fermé automatiquement, permettant à d'autres programmes d'avoir un accès direct au périphérique audio, ou au périphérique d'être déconnecté. La valeur par défaut est off.
-b nframes
La taille du tampon du périphérique audio en trames. Une trame consiste en un échantillon pour chaque canal du flux. Il s'agit du nombre de trames qui seront mises en mémoire tampon avant d'être jouées et contrôle donc la latence de lecture. La valeur par défaut est 7680 ou deux fois la taille du bloc (-z), si la taille du bloc est définie.
-C min:max, -c min:max
La plage de numéros de canaux pour les directions d'enregistrement et de lecture, respectivement que tout client est autorisé à utiliser. Il s'agit d'un sous-ensemble des canaux du périphérique audio. La valeur par défaut est 0:1, c'est-à-dire stéréo.
-d
Active le débogage vers la sortie d'erreur standard et ne se dissocie pas du terminal de contrôle. Peut être spécifié plusieurs fois pour augmenter davantage la verbosité des journaux.
-e enc
Tente de configurer le périphérique pour utiliser cet encodage. La valeur par défaut est s16. Les noms d'encodage utilisent le schéma suivant : signe (s ou u) suivi de la précision en bits, de l'ordre des octets (le ou be), du nombre d'octets par échantillon, et de l'alignement (msb ou lsb). Seul le signe et la précision sont obligatoires. Exemples : u8, s16le, s24le3, s24le4lsb.
-F device
Identique à -f sauf que si le périphérique est déconnecté, celui donné avec l'option précédente -f ou -F sera utilisé.
-f device
Ajoute ce périphérique audio sndio(7) aux périphériques utilisés pour la lecture et/ou l'enregistrement. Les options précédentes par périphérique (-aberwz) s'appliquent à ce périphérique. Les sous-périphériques (-s) qui sont appliqués après seront attachés à ce périphérique. Le mode et les paramètres du périphérique sont déterminés à partir des sous-périphériques qui y sont attachés. Si aucune option -f n'est utilisée, sndiod utilisera rsnd/0, rsnd/1, ..., rsnd/3.
-j flag
Contrôle si les canaux du programme sont joints ou étendus si le nombre de canaux demandés par un programme n'est pas égal au nombre de canaux du périphérique. Si le drapeau est off, alors les canaux clients sont routés vers le canal du périphérique correspondant, pouvant potentiellement supprimer les canaux non présents dans le périphérique. Si le drapeau est on, alors un seul canal client peut être envoyé sur plusieurs canaux de périphérique, ou plusieurs canaux clients peuvent être envoyés vers un seul canal de périphérique. Par exemple, cette fonctionnalité pourrait être utilisée pour des conversions de mono vers stéréo. La valeur par défaut est on.
-L addr
Spécifie une adresse réseau locale sur laquelle sndiod doit écouter ; sndiod écoutera sur le port TCP 11025+n, où n est le numéro d'unité spécifié avec -U. Sans cette option, sndiod n'écoute que sur le socket de domaine UNIX, et n'est joignable depuis aucun réseau. Si l'argument de l'option est ‘-’, alors sndiod acceptera les connexions de n'importe quelle adresse. Comme la communication n'est pas sécurisée, cette option n'est adaptée qu'aux réseaux locaux.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-a device
Use audio device device. If no -a or -f option is used, sndiod will use rsnd/0. Multiple devices can be specified, each will be exposed as a distinct sub-device.
-b nframes
The audio device buffer size in frames. This is the number of frames that are transferred between the user-space application and the kernel driver. The default is 1024 frames.
-C rate
Attempt to force the device to use this capture sample rate in Hertz. The default is 48000.
-c count
The number of channels. The default is 2.
-d delay
The audio device playback delay in frames. This is the number of frames that are recorded but not yet played. The default is 0.
-e enc
Set the default audio encoding. Valid encodings are pcm8, pcm16, pcm24, pcm32, ulaw, alaw, ima, vbr, opus, and vorbis. The default is pcm16.
-f device
Use audio device device. If no -a or -f option is used, sndiod will use rsnd/0. Multiple devices can be specified, each will be exposed as a distinct sub-device.
-F device
Use audio device device. If no -a or -f option is used, sndiod will use rsnd/0. Multiple devices can be specified, each will be exposed as a distinct sub-device.
-j count
The number of channels to be used for recording. The default is 2.
-k device
Set the default MIDI device to use. This is the device that will be used by default if no MIDI device is explicitly specified.
-l mode
Set the playback mode. Valid modes are play, rec, and mon, corresponding to playback, recording and monitoring. A monitoring stream is a fake recording stream corresponding to the mix of all playback streams. Multiple modes can be specified, separated by commas, but the same sub-device cannot be used for both recording and monitoring. The default is play,rec (i.e. full-duplex).
-m mode
Set the sub-device mode. Valid modes are play, rec, and mon, corresponding to playback, recording and monitoring. A monitoring stream is a fake recording stream corresponding to the mix of all playback streams. Multiple modes can be specified, separated by commas, but the same sub-device cannot be used for both recording and monitoring. The default is play,rec (i.e. full-duplex).
-Q port
Specify an alternate MIDI port to use. If it doesn't work, the one given with the last -Q or -q options will be used. For instance, this allows a USB MIDI controller to be replaced without the need to restart programs using it.
-q port
Expose the given MIDI port. This allows multiple programs to share the port. If no -q option is used, sndiod will use rmidi/0, rmidi/1, ..., rmidi/7.
-r rate
Attempt to force the device to use this sample rate in Hertz. The default is 48000.
-s name
Add name to the list of sub-devices to expose. This allows clients to use sndiod instead of the physical audio device for audio input and output in order to share the physical device with other clients. Defining multiple sub-devices allows splitting a physical audio device into sub-devices having different properties (e.g. channel ranges). The given name corresponds to the “option” part of the sndio(7) device name string.
-t mode
Select the way clients are controlled by MIDI Machine Control (MMC) messages received by sndiod. If the mode is off (the default), then programs are not affected by MMC messages. If the mode is slave, then programs are started synchronously by MMC start messages; additionally, the server clock is exposed as MIDI Time Code (MTC) messages allowing MTC-capable software or hardware to be synchronized to audio programs.
-U unit
Unit number. Each sndiod server instance has a unique unit number, used in sndio(7) device names. The default is 0.
-v volume
Software volume attenuation of playback. The value must be between 1 and 127, corresponding to -42dB and -0dB attenuation in 1/3dB steps. Clients inherit this parameter. Reducing the volume in advance allows a client's volume to stay independent from the number of clients as long as their number is small enough. 18 volume units (i.e. -6dB attenuation) allows the number of playback programs to be doubled. The default is 127.
-w flag
Control sndiod behaviour when the maximum volume of the hardware is reached and a new program starts playing. This happens only when volumes are not properly set using the -v option. If the flag is on, then the master volume is automatically adjusted to avoid clipping. The default is off.
-z nframes
The audio device block size in frames. This is the number of frames between audio clock ticks, i.e. the clock resolution. If a sub-device is created with the -t option, and MTC is used for synchronization, the clock resolution must be 96, 100 or 120 ticks per second for maximum accuracy. For instance, 100 ticks per second at 48000Hz corresponds to a 480 frame block size. The default is 480 or half of the buffer size (-b), if the buffer size is set.

On the command line, per-device parameters (-aberwz) must precede the device definition (-f), and per-sub-device parameters (-Ccjmtvx) must precede the sub-device definition (-s). Sub-device definitions (-s) must follow the definition of the device (-f) to which they are attached.

If no audio devices (-f) are specified, settings are applied as if the default device is specified. If no sub-devices (-s) are specified for a device, a default sub-device is created attached to it. If a device (-f) is defined twice, both definitions are merged: parameters of the first one are used but sub-devices (-s) of both definitions are created. The default sndio(7) device used by sndiod is rsnd/0, and the default sub-device exposed by sndiod is snd/default.

If sndiod is sent SIGINT or SIGTERM, it terminates. If sndiod is sent SIGHUP, it reopens all audio devices and MIDI ports.

By default, when the program cannot accept recorded data fast enough or cannot provide data to play fast enough, the program is paused, i.e. samples that cannot be written are discarded and samples that cannot be read are replaced by silence. If a sub-device is created with the -t option, then recorded samples are discarded, but the same amount of silence will be written once the program is unblocked, in order to reach the right position in time. Similarly silence is played, but the same amount of samples will be discarded once the program is unblocked. This ensures proper synchronization between programs.

CONTRÔLE MIDI

sndiod crée un port MIDI du même nom que le sous-périphérique audio exposé auquel les programmes MIDI peuvent se connecter. sndiod expose l'horloge du périphérique audio et permet de contrôler les propriétés du périphérique audio via MIDI.

Un canal MIDI est attribué à chaque flux, et le volume est modifié à l'aide du contrôleur de volume standard (numéro 7). De même, lorsque le client audio modifie son volume, le même message de contrôleur MIDI est envoyé; il peut être utilisé par exemple pour la surveillance ou comme retour pour les faders motorisés.

Le volume maître peut être modifié à l'aide du message exclusif standard de volume maître du système.

Les flux créés avec l'option -t sont contrôlés par les messages MMC suivants :

relocate
Ce message est ignoré par les clients audio sndiod, mais la position temporelle donnée est envoyée aux ports MIDI sous forme d'un message MTC “full frame” forçant tous les esclaves MTC à se relocaliser à la position donnée (voir ci-dessous).
start
Met tous les flux en mode de démarrage. Dans ce mode, sndiod attend que tous les flux soient prêts à démarrer, puis les démarre de manière synchronisée. Une fois démarrés, de nouveaux flux peuvent être créés (sndiod) mais ils seront bloqués jusqu'à la prochaine transition arrêt-démarrage.
stop
Met tous les flux en mode arrêté (par défaut). Dans ce mode, tout flux tentant de démarrer la lecture ou l'enregistrement est mis en pause. Les flux clients déjà démarrés ne sont pas affectés tant qu'ils ne s'arrêtent pas et n'essaient pas de redémarrer.

Les flux créés avec l'option -t exportent l'horloge du périphérique sndiod via MTC, permettant aux logiciels ou matériels non audio d'être synchronisés avec le flux audio. La précision maximale est atteinte lorsque le nombre de blocs par seconde est égal à l'un des taux d'horloge MTC standard (96, 100 et 120 Hz). Les taux d'échantillonnage (-r) et les tailles de bloc (-z) suivants sont recommandés :

  • 44100Hz, 441 images (taux MTC 100Hz)
  • 48000Hz, 400 images (taux MTC 120Hz)
  • 48000Hz, 480 images (taux MTC 100Hz)
  • 48000Hz, 500 images (taux MTC 96Hz)

Par exemple, la commande suivante créera deux périphériques : le périphérique par défaut snd/default et un périphérique contrôlé par MIDI snd/mmc :

$ sndiod -r 48000 -z 400 -s default -t slave -s mmc

Les flux connectés à snd/default se comportent normalement, tandis que les flux connectés à snd/mmc attendent le signal de démarrage MMC et démarrent de manière synchronisée. Indépendamment du périphérique auquel un flux est connecté, son potentiomètre de volume de lecture est exposé.

CONNEXION À CHAUD

Si les périphériques spécifiés avec -F sont indisponibles lorsque nécessaire ou débranchés à l'exécution, sndiod tentera de basculer de manière transparente vers le dernier périphérique spécifié.

sndiod ne basculera pas automatiquement vers un périphérique spécifié qui est branché à l'exécution. Au lieu de cela, sndioctl(1) doit être utilisé pour modifier le contrôle server.device.

Par exemple, spécifier un périphérique USB avec -F après un périphérique PCI avec -f permet à sndiod d'utiliser celui de l'USB de préférence lorsqu'il est connecté et de revenir à celui de PCI lorsqu'il est déconnecté.

EXEMPLES

Démarre le serveur avec les paramètres par défaut, créant un sous-périphérique supplémentaire pour la sortie uniquement vers les canaux 2:3 (haut-parleurs arrière sur la plupart des cartes), exposant les périphériques snd/default et snd/rear :

$ sndiod -s default -s rear:2,3

Démarrer le serveur avec une fréquence d'échantillonnage de 44.1kHz, une taille de tampon de 512 images, et exposant les périphériques snd/hi-fi et snd/low-fi (qui utilisent des fréquences d'échantillonnage différentes) :

$ sndiod -r 44100 -b 512 -s hi-fi -r 8000 -s low-fi

Démarrer le serveur en mode de surveillance uniquement, avec une fréquence d'échantillonnage de 48kHz et un périphérique de sortie snd/monitor :

$ sndiod -m mon -r 48000 -s monitor

NAME

sndiod

sndio server daemon

SYNOPSIS

sndiod [-abdfhLsv] [-c channel] [-m mode] [-o dev] [-p port] [-r rate] [-u user] [-v volume] [-w wav] [-x ext] [-z size]

DESCRIPTION

The sndiod daemon provides a simple interface to the audio hardware. It allows applications to share the audio device and to provide features like resampling and volume control. The daemon implements the SNDIO protocol.

When started without arguments, the daemon opens the default audio device with a default sample rate and volume.

The following options are available:

-a off
Start the server in auto mode. The audio device is opened on demand by the first client connecting to the server. The server will close the device when the last client disconnects.
-b blocks
Set the number of blocks in the playback and record buffers. The default is 2.
-c channel
Set the default channel of the audio device. The default is 0.
-d
Run in daemon mode. This is the default when started from the command line.
-f
Use the first available audio device. The default is to use the device specified by the AUDIODEV environment variable or the system default.
-h
Display a help message and exit.
-L
List available audio devices and exit.
-m mode
Set the audio device mode. The default is rw (read/write).
-o dev
Open the specified audio device. The default is to use the device specified by the AUDIODEV environment variable or the system default.
-p port
Set the TCP port to listen on. The default is 5121.
-r rate
Set the sample rate. The default is 44100 Hz.
-s subdevice
Create a sub-device with the specified name. This allows multiple applications to access the audio device with different configurations. The default sub-device is named default.
-u user
Set the user to run the daemon as. The default is the current user.
-v volume
Set the default volume. The value should be between 0 and 127. The default is 100.
-w wav
Set the WAV file to play at startup. This is useful for testing.
-x ext
Set the extension for the sound file. The default is .wav.
-z size
Set the block size in frames. The default is 1024.

MIDI CONTROL

The sndiod daemon can be controlled using MIDI messages. This feature is intended for use with hardware controllers and is not fully documented here. Consult the sndio(7) man page for more information.

HOT PLUGGING

The sndiod daemon supports hot plugging of audio devices. If a new audio device is connected while the daemon is running, it will be automatically detected and made available. Similarly, if an audio device is removed, it will be automatically disconnected.

EXAMPLES

Start the server with the default configuration:

$ sndiod

Start the server and create two sub-devices: default with low volume and rear with stereo output:

$ sndiod -s default -c 2:3 -s rear

Start server creating the default sub-device with low volume and an additional sub-device for high volume output, exposing the snd/default and snd/max devices:

$ sndiod -v 65 -s default -v 127 -s max

Start server configuring the audio device to use a 48kHz sample frequency, 240-frame block size, and 2-block buffers. The corresponding latency is 10ms, which is the time it takes the sound to propagate 3.5 meters.

$ sndiod -r 48000 -b 480 -z 240

BUGS

Resampling is low quality; down-sampling especially should be avoided when recording.

If -a off is used, sndiod creates sub-devices to expose first and then opens the audio hardware on demand. Technically, this allows sndiod to attempt to use one of the sub-devices it exposes as an audio device, creating a deadlock. There's nothing to prevent the user from shooting themselves in the foot by creating such a deadlock.
