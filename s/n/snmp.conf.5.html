SNMP.CONF(5) Net-SNMP SNMP.CONF(5)

NOM

snmp.conf - fichiers de configuration pour les applications Net-SNMP

DESCRIPTION

Les applications construites à l'aide des bibliothèques Net-SNMP utilisent généralement un ou plusieurs fichiers de configuration pour contrôler divers aspects de leur fonctionnement. Ces fichiers (snmp.conf et snmp.local.conf) peuvent être situés dans l'un des emplacements suivants, comme décrit dans la page de manuel snmp_config(5).

En particulier, /etc/snmp/snmp.conf est un fichier courant, contenant les paramètres partagés par tous les utilisateurs du système. ~/.snmp/snmp.conf est un fichier personnel, avec les paramètres spécifiques à un utilisateur donné.

FICHIERS SPÉCIFIQUES À L'HÔTE

Des fichiers spécifiques à l'hôte peuvent également être chargés et seront recherchés si un nom de transport est spécifié qui correspond à un fichier PATH/hosts/HOST.conf. Par exemple, si vous vouliez qu'un hôte particulier utilise SNMPv2c par défaut, vous pourriez créer un fichier ~/.snmp/hosts/NOM.conf et y mettre :

defVersion 2c

Toutes les connexions configurées pour se connecter à l'hôte NOM utiliseront SNMPv2c. Voir également le jeton transport ci-dessous pour des exemples supplémentaires spécifiques à l'hôte.

Les fichiers de configuration spécifiques à l'hôte sont chargés au moment où la connexion est ouverte. Ils sont donc généralement chargés après tous les autres fichiers de configuration et peuvent être utilisés pour remplacer les paramètres des fichiers génériques.

Pour éviter de charger des fichiers de configuration spécifiques à l'hôte, définissez "dontLoadHostConfig true" dans votre fichier snmp.conf.

OPTIONS EN LIGNE DE COMMANDE

Tous les jetons décrits dans ce fichier peuvent également être utilisés sur la ligne de commande des applications Net-SNMP en les préfixant avec "--". Par exemple, spécifier --dontLoadHostConfig=true sur la ligne de commande désactivera le chargement des fichiers de configuration spécifiques à l'hôte.

NOTE IMPORTANTE

Plusieurs de ces directives peuvent contenir des informations sensibles (telles que des phrases de passe). Les fichiers de configuration qui incluent de tels paramètres ne devraient être lisibles que par l'utilisateur concerné.

En plus des jetons de configuration spécifiques aux applications, il existe plusieurs directives qui concernent le comportement de la bibliothèque standard, pertinentes pour la plupart des applications Net-SNMP. Beaucoup d'entre elles correspondent à des options de ligne de commande standard, décrites dans la page de manuel snmpcmd(1).

Ces directives peuvent être divisées en plusieurs groupes distincts.

COMPORTEMENT CLIENT

defDomain domaine_application domaine
Le domaine de transport qui doit être utilisé pour un certain type d'application, sauf si quelque chose d'autre est spécifié.
defTarget cible_domaine_application
La cible qui doit être utilisée pour les connexions à une certaine application si la connexion doit être dans un domaine spécifique.
defaultPort PORT
définit le port UDP par défaut auquel les applications client SNMP tenteront de se connecter. Cela peut être remplacé en incluant explicitement un numéro de port dans la spécification AGENT. Voir la page de manuel snmpcmd(1) pour plus de détails.
Si non spécifié, la valeur par défaut pour ce jeton est 161.
transport SPÉCIFICATEUR_HÔTE
Ce jeton spécial doit aller dans un fichier de configuration spécifique à l'hôte dans un sous-répertoire hosts. Par exemple, si le fichier hosts/foo.conf existe dans le chemin de recherche, il sera chargé si un nom de transport foo a été utilisé. Dans le fichier foo.conf, vous pouvez mettre des paramètres généraux de snmp.conf ainsi qu'une chaîne transport spéciale pour spécifier la destination à connecter. Par exemple, mettre :
transport tcp:foo.example.com:9876
dans le fichier hosts/foo.conf fera que les applications faisant référence à l'hôte foo (par exemple, snmpget) se connecteront en fait via TCP à foo.exmaple.com sur le port 9876.
defVersion (1|2c|3)
définit la version SNMP par défaut à utiliser. Cela peut être remplacé à l'aide de l'option -v.
defCommunity CHAÎNE
définit la communauté par défaut à utiliser pour les requêtes SNMPv1 et SNMPv2c. Cela peut être remplacé à l'aide de l'option -c.
alias NOM DÉFINITION
Crée un alias lié à NOM pour une définition de transport donnée. L'alias peut alors être référencé en utilisant un préfixe alias:. Par exemple, une ligne de "alias here udp:127.0.0.1:6161" vous permettrait d'utiliser une hôte de destination "alias:here" au lieu de "udp:127.0.0.1:6161". Ceci devient plus utile avec des adresses de transport complexes impliquant des adresses IPv6, etc.
dumpPacket oui
définit si un vidage hexadécimal des requêtes SNMP brutes envoyées et reçues par l'application doit être affiché. Ceci est équivalent à l'option -d.
doDebugging (1|0)
active le débogage pour toutes les applications exécutées si défini sur 1.
debugTokens JETON[,JETON...]
définit les jetons de débogage qui doivent être activés lorsque doDebugging est défini. Ceci est équivalent à l'option -D.
debugLogLevel (emerg|alert|crit|err|warning|notice|info|debug)
Définit le niveau de priorité pour la journalisation de la sortie de débogage. La valeur par défaut est debug.
16bitIDs oui
restreint les requestIDs, etc. à des valeurs 16 bits.
Les spécifications SNMP définissent ces champs d'ID comme des quantités de 32 bits, et la bibliothèque Net-SNMP les initialise généralement avec des valeurs aléatoires pour des raisons de sécurité. Cependant, certains agents (défectueux) ne peuvent pas gérer des valeurs d'ID supérieures à 2^16 - cette option permet l'interopérabilité avec de tels agents.
clientaddr [<spécificateur-transport>:]<adresse-transport>
spécifie l'adresse source qui doit être utilisée par les applications en ligne de commande lors de l'envoi de requêtes SNMP. Voir snmpcmd(1) pour plus d'informations sur le format des adresses.
Cette valeur est également utilisée par snmpd lors de la génération de notifications.
clientaddrUsesPort non
spécifie, si l'option clientaddr contient un numéro de port. Définissez cette option sur "oui" si clientaddr contient un numéro de port et que ce port doit être utilisé pour envoyer des requêtes SNMP sortantes. Cette option n'affecte que les adresses client IPv4 et est ignorée pour les adresses client IPv6.
clientRecvBuf ENTIER
spécifie la taille souhaitée du tampon à utiliser lors de la réception des réponses aux requêtes SNMP. Si la limite matérielle du système d'exploitation est inférieure à la valeur clientRecvBuf, cette dernière sera utilisée à la place. Certaines plateformes peuvent décider d'augmenter la taille du tampon réellement utilisé pour l'entretien interne.
Cette directive sera ignorée si la plateforme ne prend pas en charge setsockopt().
clientSendBuf ENTIER
est similaire à clientRecvBuf, mais s'applique à la taille du tampon utilisé lors de l'envoi de requêtes SNMP.
noRangeCheck oui
désactive la validation des valeurs de varbind par rapport à la définition MIB pour l'OID concerné. Ceci est équivalent à l'option -Ir.
Cette directive est principalement pertinente pour la commande snmpset, mais s'appliquera également à toute application qui appelle snmp_add_var() avec une valeur non NULL.
noTokenWarnings
désactive les avertissements concernant les jetons de fichier de configuration inconnus.
reverseEncodeBER (1|oui|vrai|0|non|faux)
contrôle comment

ENCODING SETTINGS

reverseEncoding (1|yes|true|0|no|false)
Définit la manière dont l'encodage des requêtes SNMP est géré.
Le comportement par défaut est d'encoder les paquets en partant de la fin du PDU et en remontant. Cette directive peut être utilisée pour désactiver ce comportement et construire la requête encodée dans le sens (plus évident) avant.
Il ne devrait normalement pas être nécessaire de modifier ce réglage, car l'encodage est fondamentalement le même dans les deux cas - mais travailler en arrière produit généralement un encodage légèrement plus efficace, et donc un datagramme réseau plus petit.
dontLoadHostConfig (1|yes|true|0|no|false)
Spécifie si les fichiers de configuration spécifiques à l'hôte sont chargés ou non. Définir à "true" pour désactiver le chargement des fichiers de configuration spécifiques à l'hôte.
retries ENTIER
Spécifie le nombre de tentatives à utiliser dans les requêtes.
timeout ENTIER
Spécifie le délai d'attente en secondes entre les tentatives.

PARAMÈTRES SNMPv1/SNMPv2c

disableSNMPv1 (1|yes|true|0|no|false)
disableSNMPv2c (1|yes|true|0|no|false)
Désactive les versions de protocole à l'exécution. Les paquets entrants et sortants pour le protocole seront supprimés.

PARAMÈTRES SNMPv3

disableSNMPv3 (1|yes|true|0|no|false)
Désactive les versions de protocole à l'exécution. Les paquets entrants et sortants pour le protocole seront supprimés.
defSecurityName CHAÎNE
définit le nom de sécurité par défaut à utiliser pour les requêtes SNMPv3. Cela peut être écrasé en utilisant l'option -u.
defSecurityLevel noAuthNoPriv|authNoPriv|authPriv
définit le niveau de sécurité par défaut à utiliser pour les requêtes SNMPv3. Cela peut être écrasé en utilisant l'option -l.
S'il n'est pas spécifié, la valeur par défaut pour ce jeton est noAuthNoPriv.
Note :
authPriv n'est disponible que si le logiciel a été compilé pour utiliser les bibliothèques OpenSSL.
defPassphrase CHAÎNE
defAuthPassphrase CHAÎNE
defPrivPassphrase CHAÎNE
définissent les phrases de passe d'authentification et de confidentialité par défaut à utiliser pour les requêtes SNMPv3. Celles-ci peuvent être écrasées en utilisant les options -A et -X respectivement.
La valeur de defPassphrase sera utilisée pour les phrases de passe d'authentification et/ou de confidentialité si l'une des autres directives n'est pas spécifiée.
defAuthType MD5|SHA|SHA-512|SHA-384|SHA-256|SHA-224
defPrivType DES|AES
définissent les protocoles d'authentification et de confidentialité par défaut à utiliser pour les requêtes SNMPv3. Celles-ci peuvent être écrasées en utilisant les options -a et -x respectivement.
S'ils ne sont pas spécifiés, les requêtes SNMPv3 utiliseront par défaut l'authentification MD5 et le chiffrement DES.
Note :
Si le logiciel n'a pas été compilé pour utiliser les bibliothèques OpenSSL, alors seule l'authentification MD5 est prise en charge. Ni l'authentification SHA ni aucune forme de chiffrement ne seront disponibles.
defContext CHAÎNE
définit le contexte par défaut à utiliser pour les requêtes SNMPv3. Cela peut être écrasé en utilisant l'option -n.
S'il n'est pas spécifié, la valeur par défaut pour ce jeton est le contexte par défaut (c'est-à-dire la chaîne vide "").
defSecurityModel CHAÎNE
définit le modèle de sécurité à utiliser pour les requêtes SNMPv3. La valeur par défaut est "usm", qui est le seul modèle de sécurité largement utilisé pour SNMPv3.
defAuthMasterKey 0xCHAÎNEHEXADÉCIMALE
defPrivMasterKey 0xCHAÎNEHEXADÉCIMALE
defAuthLocalizedKey 0xCHAÎNEHEXADÉCIMALE
defPrivLocalizedKey 0xCHAÎNEHEXADÉCIMALE
définissent les clés (hexadécimales) à utiliser pour les communications sécurisées SNMPv3. Les clés SNMPv3 sont fréquemment dérivées d'une phrase secrète, comme discuté dans la section defPassphrase ci-dessus. Cependant, pour une sécurité accrue, une clé véritablement aléatoire peut être générée et utilisée à la place (ce qui aurait normalement une meilleure entropie qu'un mot de passe, sauf s'il est étonnamment long). Les directives sont équivalentes aux options de ligne de commande abrégées -3m, -3M, -3k, et -3K.
Les clés localisées sont des clés maîtres qui ont été converties en une clé unique qui ne convient qu'à un moteur SNMP (agent) particulier. La longueur de la clé doit être appropriée pour le type d'authentification ou de chiffrement utilisé (clés d'authentification : MD5=16 octets, SHA1=20 octets ; clés de confidentialité : DES=16 octets (dont 8 octets sont utilisés comme IV et non comme clé), et AES=16 octets).
sshtosnmpsocket CHEMIN
Définit le chemin du socket sshtosnmp créé par une application (par exemple, snmpd) écoutant les connexions SSH entrantes via le socket Unix sshtosnmp.
sshtosnmpsocketperms MODE [PROPRIÉTAIRE [GROUPE]]
Définit le mode, le propriétaire et le groupe du socket sshtosnmp créé par une application (par exemple, snmpd) écoutant les connexions SSH entrantes via le socket Unix sshtosnmp. Le socket doit avoir des privilèges de lecture/écriture pour les utilisateurs SSH autorisés à se connecter au service SNMP (l'accès VACM doit toujours être accordé également, très probablement via le modèle de sécurité TSM).
sshusername NOM
Définit le nom d'utilisateur SSH pour se connecter au système distant.
sshpubkey FICHIER
Définit le fichier de clé publique à utiliser lors de la connexion à un système distant.
sshprivkey FICHIER
Définit le fichier de clé privée à utiliser lors de la connexion à un système distant.

COMPORTEMENT DU SERVEUR

persistentDir RÉPERTOIRE
définit le répertoire où snmpd et snmptrapd stockent les paramètres de configuration persistants.
S'il n'est pas spécifié, le répertoire persistant est par défaut /var/net-snmp
noPersistentLoad oui
noPersistentSave oui
désactive le chargement et la sauvegarde des informations de configuration persistantes.
Note :
Cela interrompra les opérations SNMPv3 (et d'autres comportements qui dépendent des changements persistants après le redémarrage de l'application). À utiliser avec prudence.
tempFilePattern MODÈLE
définit un modèle de nom de fichier pour la création de fichiers temporaires, pour la gestion des entrées et sorties des commandes shell externes. Utilisé par les fonctions mkstemp() et mktemp().
S'il n'est pas spécifié, le modèle par défaut est "/tmp/snmpdXXXXXX".
serverRecvBuf ENTIER
spécifie la taille souhaitée du tampon à utiliser lors de la réception des requêtes SNMP entrantes. Si la limite maximale du système d'exploitation est inférieure à la valeur de serverRecvBuf, alors celle-ci sera utilisée à la place. Certaines plateformes peuvent décider d'augmenter la taille du tampon réellement utilisé pour la gestion interne.
Cette directive sera ignorée si la plateforme ne prend pas en charge setsockopt().
serverSendBuf ENTIER
est similaire à serverRecvBuf, mais s'applique à la taille du tampon utilisé lors de l'envoi des réponses SNMP.
sourceFilterType aucun|liste_acceptation|liste_blocage
spécifie si les adresses ajoutées avec sourceFilterAddress sont acceptées ou bloquées. Le défaut est aucun, indiquant que les paquets entrants ne seront pas vérifiés par rapport à la liste de filtrage.
sourceFilterAddress ADRESSE
spécifie une adresse à ajouter à la liste de filtrage des adresses sources. La configuration sourceFilterType détermine si les adresses sont acceptées ou bloquées.

GESTION DES MIB

mibdirs LISTE_DE_RÉPERTOIRES
spécifie une liste de répertoires à rechercher pour les fichiers MIB. Cela fonctionne de la même manière que l'option -M - voir snmpcmd(1) pour plus de détails. Notez que cette valeur peut être écrasée par la variable d'environnement MIBDIRS et l'option -M.
mibs LISTE_DE_MIB
spécifie une liste de modules MIB (pas de fichiers) qui doivent être chargés. Cela fonctionne de la même manière que l'option -m - voir snmpcmd(1) pour plus de détails. Notez que cette liste peut être écrasée par la variable d'environnement MIBS et l'option -m.
snmp.conf(5) — Net-SNMP configuration file format

MIB HANDLING

mibfile FICHIER
spécifie un (unique) fichier MIB à charger, en plus de la liste lue à partir du token mibs (ou la configuration équivalente). Notez que cette valeur peut être remplacée par la variable d'environnement MIBFILES.
showMibErrors (1|oui|vrai|0|non|faux)
indique s'il faut afficher les erreurs d'analyse des MIB.
commentToEOL (1|oui|vrai|0|non|faux)
indique si l'analyse des MIB doit être stricte quant à la terminaison des commentaires. De nombreux rédacteurs de MIB supposent que les commentaires ASN.1 s'étendent jusqu'à la fin de la ligne de texte, plutôt que d'être terminés par le prochain token "--". Ce token peut être utilisé pour accepter de tels MIB (strictement incorrects).
Notez que cette directive était précédemment nommée (à tort) strictCommentTerm, mais avec un comportement inverse de celui suggéré par le nom. Cet ancien token est toujours accepté pour des raisons de compatibilité ascendante.
mibAllowUnderline (1|oui|vrai|0|non|faux)
indique s'il faut autoriser les caractères de soulignement dans les noms d'objets MIB et les valeurs d'énumération. Ce token peut être utilisé pour accepter de tels MIB (strictement incorrects).
mibWarningLevel ENTIER
le niveau d'avertissement minimum des avertissements imprimés par l'analyseur de MIB.

CONFIGURATION DE LA SORTIE

logTimestamp (1|oui|vrai|0|non|faux)
Indique si les commandes doivent enregistrer des horodatages avec leur journalisation d'erreurs/messages ou non. Notez que la sortie ne sera pas aussi esthétique avec des horodatages si le code source qui effectue la journalisation effectue une journalisation incrémentielle de messages qui ne sont pas mis en tampon ligne avant d'être passés aux routines de journalisation. Cette option n'est utilisée que lorsque la journalisation de fichiers est active.
printNumericEnums (1|oui|vrai|0|non|faux)
Équivalent à -Oe.
printNumericOids (1|oui|vrai|0|non|faux)
Équivalent à -On.
dontBreakdownOids (1|oui|vrai|0|non|faux)
Équivalent à -Ob.
escapeQuotes (1|oui|vrai|0|non|faux)
Équivalent à -OE.
quickPrinting (1|oui|vrai|0|non|faux)
Équivalent à -Oq.
printValueOnly (1|oui|vrai|0|non|faux)
Équivalent à -Ov.
dontPrintUnits (1|oui|vrai|0|non|faux)
Équivalent à -OU.
numericTimeticks (1|oui|vrai|0|non|faux)
Équivalent à -Ot.
printHexText (1|oui|vrai|0|non|faux)
Équivalent à -OT.
hexOutputLength entier
Spécifie où couper la sortie des chaînes hexadécimales. Mettre à 0 pour désactiver les sauts de ligne. La valeur par défaut est 16.
suffixPrinting (0|1|2)
La valeur 1 est équivalente à -Os et la valeur 2 est équivalente à -OS.
oidOutputFormat (1|2|3|4|5|6)
Mappe les options -O comme suit : -Os=1, -OS=2, -Of=3, -On=4, -Ou=5. La valeur 6 n'a pas d'option -O correspondante. Elle supprime la sortie.
extendedIndex (1|oui|vrai|0|non|faux)
Équivalent à -OX.
noDisplayHint (1|oui|vrai|0|non|faux)
Désactive l'utilisation des informations DISPLAY-HINT lors de l'analyse des indices et des valeurs à définir. Équivalent à -Ih.
outputPrecision PRECISION
Utilise la chaîne PRECISION pour permettre la modification du format de sortie des valeurs. Voir snmpcmd(1) pour les détails. Équivalent à -Op (qui a la priorité sur le fichier de configuration).
