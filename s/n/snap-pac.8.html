NOM

snap-pac - Crochets Pacman qui utilisent snapper pour créer des instantanés btrfs pré/post comme YaST d'openSUSE

DESCRIPTION

Comme ce sont des crochets pacman, peu importe comment vous appelez pacman — que ce soit directement, via un helper AUR, ou en utilisant un alias — snapper créera les instantanés lorsque pacman installera, mettra à niveau ou supprimera un paquet. La commande pacman utilisée est enregistrée dans la description de snapper pour les instantanés. De plus, les numéros d'instantanés sont affichés à l'écran et dans le journal pacman pour chaque configuration snapper pendant la transaction pacman, afin que l'utilisateur puisse facilement trouver les modifications qu'il pourrait vouloir annuler.

Lorsque vous exécutez pacman, les instantanés pré/post de snapper sont créés automatiquement. Pour un exemple plus complet, voir Exemple.

Si vous avez une rupture grave — par exemple, snapper a disparu pour une raison quelconque et vous ne pouvez pas le récupérer — vous devrez recourir à des méthodes plus extrêmes, telles que la création d'un instantané de l'instantané pré et sa définition comme sous-volume par défaut ou son montage en tant que /. Très probablement, vous devrez utiliser une clé USB live pour accéder à un environnement chroot pour effectuer l'une de ces actions. Snapper dispose d'une fonctionnalité snapper rollback, mais votre configuration doit être correctement configurée pour l'utiliser. La procédure exacte dépend de votre configuration spécifique. Soyez prudent.

Notez que les crochets de pré-transaction se produisent avant la transaction pacman mais après la synchronisation de la base de données pacman, le cas échéant. En d'autres termes, si vous exécutez pacman -Syu et annulez la mise à niveau selon les instructions ci-dessus, vous n'aurez pas annulé la base de données pacman à l'état précédent. Ainsi, si, après la mise à niveau et l'annulation de la mise à niveau, vous installez ensuite un paquet, il s'agira potentiellement d'une mise à niveau partielle, ce qui n'est pas pris en charge.

INSTALLATION

Installez le paquet snap-pac en utilisant pacman :

gpg --verify snap-pac-<version>.tar.gz.sig

où <version> est le numéro de version que vous avez téléchargé.

Enfin, exécutez :

make install

J'ai signé l'archive tarball de la version et les commits avec ma clé PGP. À partir de la version 2.2, les archives tarballs sont signées avec ma clé dont l'empreinte est F7B28C61944FE30DABEEB0B01070BCC98C18BD66.

Pour les versions précédentes, l'empreinte de la clé était 8535CEF3F3C38EE69555BF67E4B5E45AA3B8C5C3.

Dépendances

python, pacman, et snapper sont tous requis.

Tests

Pour les tests, pytest est requis. Pour exécuter les tests, faites :

man 8 snap-pac

Pour compiler la documentation, sphinx est requis. Pour compiler la documentation, vous pouvez faire :

make docs

La documentation html résultante se trouvera alors sous docs/build/index.html. De plus, cela génère la page man qui se trouvera sous man8.

CONFIGURATION

La configuration se fait via des fichiers de configuration Python ini. Les valeurs par défaut devraient convenir à la plupart des utilisateurs, vous n'aurez donc peut-être pas besoin de configuration du tout. Par défaut, seule la configuration root de snapper est utilisée pour les instantanés.

Un fichier de configuration exemple commenté se trouve sous /etc/snap-pac.ini.

Modifiez-le avec votre éditeur préféré. Le fichier est commenté et devrait être auto-explicatif.

Chaque section correspond à une configuration snapper. Ajoutez des sections supplémentaires pour ajouter d'autres configurations snapper à utiliser pour les instantanés. Par défaut, seule la configuration root est utilisée. De plus, vous pouvez ajouter une section nommée DEFAULT avec des options qui s'appliquent à toutes les configurations snapper, sauf indication contraire dans une section ultérieure.

Chaque section peut avoir les entrées suivantes :

  • desc_limit - entier ; longueur maximale de la chaîne de description avant troncature. Défaut : 72
  • important_packages - liste de chaînes ; noms des paquets qui, s'ils sont impliqués dans une transaction pacman, ajouteront important=yes aux métadonnées de snapper pour la paire d'instantanés. Défaut : []
  • important_commands - liste de chaînes ; commandes parentes qui ajouteront important=yes aux métadonnées de snapper pour la paire d'instantanés. Défaut : []
  • pre_description - chaîne ; description pour l'instantané pré. Défaut : la commande parente qui a appelé le crochet pacman.
  • post_description - chaîne ; description pour l'instantané post. Défaut : liste séparée par des espaces des paquets qui ont été installés, mis à niveau ou supprimés.
  • snapshot - booléen ; si la configuration doit être utilisée pour les instantanés ou non. Défaut : True pour la configuration root ; False sinon.
  • userdata - liste de chaînes ; paires clé-valeur qui seront ajoutées aux métadonnées pour la paire d'instantanés. Défaut : []

Exemples

Désactiver les instantanés pour la configuration root et les activer pour la configuration home :

[root]
snapshot = False
[home]
snapshot = True

Définir snapper pour ajouter les métadonnées important=yes pour chaque instantané de la configuration root lors d'une mise à niveau système :

[root]
important_commands = ["pacman -Syu"]

Définir snapper pour ajouter les métadonnées important=yes pour chaque instantané de la configuration root lorsqu'une transaction pacman gère les paquets linux et linux-lts :

[root]
important_packages = ["linux", "linux-lts"]

VARIABLES D'ENVIRONNEMENT

Pour empêcher temporairement la création d'instantanés pour une commande pacman unique, définissez la variable d'environnement SNAP_PAC_SKIP. Par exemple :

sudo SNAP_PAC_SKIP=y pacman -Syu

DÉPANNAGE

snap-pac ne prend des instantanés que pour la configuration root.

C'est le comportement par défaut. Voir Configuration.

Aucun instantané n'est pris lorsque j'exécute pacman.

Aucune configuration snapper n'est définie pour les hooks pacman de snap-pac. Par défaut, snap-pac prendra des instantanés pour la configuration root et toute autre configuration pour laquelle SNAPSHOT est défini sur yes dans son fichier de configuration. Voir Configuration.

Après avoir restauré un instantané de snap-pac, la base de données pacman est verrouillée.

FAQ

snap-pac sauvegarde-t-il les partitions /boot non-btrfs ?

Non, mais vous pouvez ajouter un hook qui le fait pour vous. Ce serait quelque chose comme suit :

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Sauvegarde de /boot...
When = PreTransaction
Exec = /usr/bin/rsync -avzq --delete /boot /.bootbackup

Notez que vous voudrez probablement nommer le fichier avec un préfixe numérique inférieur à 05 afin qu'il soit exécuté avant que l'instantané snap-pac pré ne soit pris. Cela garantira que l'instantané pris concerne la sauvegarde de la partition boot correspondant à l'état du système. Par exemple, vous pourriez le nommer 04-backupboot.hook.

Comment lier automatiquement les anciens modules du noyau lors de la mise à niveau du noyau ?

Ce comportement ne fait plus partie de ce paquet. Utilisez un hook pacman comme suit :

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Liaison symbolique des anciens modules du noyau...
When = PostTransaction
Exec = /usr/bin/bash -c "find /usr/lib/modules -xtype l -delete; ln -sv /.snapshots/$(snapper -c root list | awk 'END{print $1}')/snapshot/usr/lib/modules/$(uname -r) /usr/lib/modules/"
