snmp_alarm_register(3)

Paquet: net-snmp

Licences: BSD

SNMP_ALARM(3) Net-SNMP SNMP_ALARM(3)

NOM

snmp_alarm_register, snmp_alarm_register_hr, snmp_alarm_unregister - fonctions d'alarme

SYNTAXE

#include <net-snmp/utilities.h>

unsigned int
snmp_alarm_register(unsigned int secondes,
unsigned int flags,
SNMPAlarmCallback *f_callback,
void *clientarg);

unsigned int
snmp_alarm_register_hr(struct timeval t,
unsigned int flags,
SNMPAlarmCallback *f_callback,
void *clientarg);

void
snmp_alarm_unregister(unsigned int reg);

DESCRIPTION

Ces fonctions implémentent un support pour un mécanisme générique de gestion de minuterie permettant à plusieurs parties d'une application d'enregistrer des rappels de fonctions qui se produiront à un moment donné dans le futur.

UTILISATION

L'utilisation est assez simple et directe : créez simplement une fonction que vous souhaitez appeler à un moment donné. La définition de la fonction doit être similaire à :

void my_callback(unsigned int reg, void *clientarg);

Ensuite, appelez snmp_alarm_register() pour enregistrer votre rappel afin qu'il soit appelé secondes à partir de maintenant. Le champ flags doit être soit SA_REPEAT, soit NULL. Si flags est défini avec SA_REPEAT, alors la fonction de rappel enregistrée sera appelée toutes les secondes. Si flags est NULL, la fonction ne sera appelée qu'une seule fois puis retirée de l'enregistrement du système d'alarme.

Le paramètre clientarg dans la fonction d'enregistrement est utilisé uniquement par la fonction client et est stocké et renvoyé directement à celle-ci à chaque appel du système.

La fonction snmp_alarm_register() renvoie un unsigned int unique (qui est également passé comme premier argument de chaque rappel), qui peut ensuite être utilisé pour supprimer le rappel de la file d'attente ultérieurement à l'aide de la fonction snmp_alarm_unregister(). Si l'appel snmp_alarm_register() échoue, il renvoie zéro. En particulier, il est tout à fait possible pour une fonction d'alarme de s'auto-désenregistrer.

La fonction snmp_alarm_register_hr() est identique en fonctionnement à la fonction snmp_alarm_register(), mais prend une struct timeval comme premier paramètre et planifie le rappel après la période représentée par t (les lettres hr signifient "haute résolution"). Le fonctionnement de cette fonction dépend de la disponibilité de l'appel système setitimer(2) par le système d'exploitation. Si cet appel système n'est pas disponible, l'alarme sera planifiée comme si snmp_alarm_register() avait été appelé avec un premier argument égal à la valeur du membre tv_sec de t. Voir cependant les notes ci-dessous.

INITIALISATION

La fonction init_snmp() initialise le sous-système snmp_alarm en appelant init_snmp_alarm() puis init_alarm_post_config() pour configurer la première minuterie afin d'initialiser la fonction de rappel. Ces deux fonctions ne doivent pas être utilisées directement par les applications.

NOTES

Le comportement par défaut du sous-système snmp_alarm est de demander des signaux SIGALRM au système d'exploitation via les appels système alarm(2) ou setitimer(2). Cela a l'inconvénient, cependant, qu'aucune autre partie de l'application ne peut utiliser la fonctionnalité SIGALRM (ou, si une autre partie de l'application utilise effectivement la fonctionnalité SIGALRM, le sous-système snmp_alarm ne fonctionnera pas correctement).

Si votre application exécute une boucle d'événements basée sur select(2), cependant, il n'est pas nécessaire d'utiliser SIGALRM pour le sous-système snmp_alarm, le laissant disponible pour d'autres parties de l'application. Ceci est fait en appelant ceci :

netsnmp_ds_set_boolean(NETSNMP_DS_LIBRARY_ID, 
                       NETSNMP_DS_LIB_ALARM_DONT_USE_SIG, 1);

avant d'appeler init_snmp(). Ensuite, snmp_select_info() prend en compte les alarmes lors du calcul de la valeur de délai d'attente à utiliser pour select(2). Tout ce que vous avez à faire est d'appeler run_alarms() lorsque select(2) expire (valeur de retour de zéro). C'est l'approche adoptée dans l'agent ; voir snmpd.c. De plus, lors de l'utilisation de cette méthode, les alarmes haute résolution ne dépendent pas de la présence de l'appel système setitimer(2), bien que la précision globale soit bien sûr toujours déterminée par le système d'exploitation sous-jacent. Recommandé.
