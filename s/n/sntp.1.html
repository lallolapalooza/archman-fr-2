sntp(1) Commandes utilisateur sntp(1)

NOM

sntp - programme client standard Simple Network Time Protocol

SYNTAXE

sntp [-indicateurs] [-indicateur [valeur]] [--nom-option[[=| ]valeur]] [ nom-hote-ou-IP ...]

DESCRIPTION

sntp peut être utilisé comme client SNTP pour interroger un serveur NTP ou SNTP et soit afficher l'heure, soit régler l'heure du système local (avec les privilèges appropriés). Il peut être exécuté comme une commande interactive ou à partir d'une tâche cron. NTP (Network Time Protocol) et SNTP (Simple Network Time Protocol) sont définis et décrits par la RFC 5905.

Par défaut, la date et l'heure locales estimées correctes (c'est-à-dire non UTC) sont écrites sur la sortie standard dans un format tel que : '1996-10-15 20:17:25.123 (+0800) +4.567 +/- 0.089 [hote] IP sN' où '(+0800)' signifie que pour passer de l'heure locale rapportée à l'UTC, il faut ajouter 8 heures et 0 minutes, le '+4.567' indique que l'horloge locale est en retard de 4.567 secondes par rapport à l'heure correcte (donc il faut ajouter 4.567 secondes à l'horloge locale pour la corriger). Notez que le nombre de décimales affiché pour cette valeur changera en fonction de la précision rapportée du serveur. '+/- 0.089' est la distance de synchronisation rapportée (en secondes), qui représente l'erreur maximale due à toutes les causes. Si le serveur ne rapporte pas de données valides nécessaires au calcul de la distance de synchronisation, cela sera rapporté comme '+/- ?'. Si l'hôte est différent de l'IP, les deux seront affichés. Sinon, seule l'IP est affichée. Enfin, le stratum de l'hôte est rapporté et l'indicateur de saut est décodé et affiché.

OPTIONS

-4, --ipv4

Forcer la résolution des noms DNS en IPv4. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : ipv6.

Forcer la résolution DNS des noms d'hôtes suivants sur la ligne de commande dans l'espace de noms IPv4.

-6, --ipv6

Forcer la résolution des noms DNS en IPv6. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : ipv4.

Forcer la résolution DNS des noms d'hôtes suivants sur la ligne de commande dans l'espace de noms IPv6.

-a nombre-cle-auth, --authentification=nombre-cle-auth

Activer l'authentification avec la clé nombre-cle-auth. Cette option prend un nombre entier comme argument.

Activer l'authentification en utilisant la clé spécifiée dans l'argument de cette option. L'argument de cette option est le keyid, un nombre spécifié dans le fichier-cle comme identifiant de cette clé. Voir l'option fichier-cle (-k) pour plus de détails.

-b adresse-diffusion, --diffusion=adresse-diffusion

Écouter sur l'adresse spécifiée pour la synchronisation horaire par diffusion. Cette option peut apparaître un nombre illimité de fois.

Si spécifié, sntp écoutera sur l'adresse spécifiée pour les diffusions NTP. Le temps d'attente maximum par défaut peut (et devrait probablement) être modifié avec -t.

-c nom-hote, --concurrent=nom-hote

Interroger simultanément tous les IPs renvoyés pour le nom d'hôte. Cette option peut apparaître un nombre illimité de fois.

Les requêtes d'un "client" NTP à un "serveur" ne doivent jamais être envoyées plus rapidement qu'une toutes les 2 secondes. Par défaut, toutes les IPs renvoyées dans le cadre d'une recherche DNS sont considérées comme appartenant à une seule instance de ntpd, et donc sntp enverra des requêtes à ces IPs l'une après l'autre, avec un intervalle de 2 secondes entre chaque requête.

L'indicateur -c ou --concurrent indique que toutes les IPs renvoyées pour la recherche DNS du nom d'hôte fourni sont sur des machines différentes, nous pouvons donc envoyer des requêtes simultanées.

-d, --niveau-debug

Augmenter le niveau de verbosité du débogage. Cette option peut apparaître un nombre illimité de fois.
-D nombre, --definir-niveau-debug=nombre

Définir le niveau de verbosité du débogage. Cette option peut apparaître un nombre illimité de fois. Cette option prend un nombre entier comme argument.
-g millisecondes, --intervalle=millisecondes

L'intervalle (en millisecondes) entre les requêtes d'heure. Cette option prend un nombre entier comme argument. Les millisecondes par défaut pour cette option sont :
50

Puisque nous n'utiliserons que la première réponse valide reçue et qu'il y a un avantage à spécifier un bon nombre de serveurs à interroger, séparez les requêtes que nous envoyons par le nombre spécifié de millisecondes.

-K nom-fichier, --kod=nom-fichier

Nom de fichier de l'historique KoD. Le nom-fichier par défaut pour cette option est :
/var/db/ntp-kod

Spécifie le nom du fichier à utiliser pour l'historique persistant des réponses KoD reçues des serveurs. Si le fichier n'existe pas, un message d'avertissement sera affiché. Le fichier ne sera pas créé.

-k nom-fichier, --fichier-cle=nom-fichier

Chercher la clé spécifiée avec -a dans ce fichier. Le nom-fichier par défaut pour cette option est :
/etc/ntp.keys

Cette option spécifie le fichier de clés. sntp recherchera la clé spécifiée avec -a keyno dans ce fichier. Voir ntp.keys(5) pour plus d'informations.

-l nom-fichier, --journal-fichier=nom-fichier

Journaliser dans le fichier journal spécifié.

Cette option fait en sorte que le client écrive les messages du journal dans le fichier-journal spécifié.

-M nombre, --limite-pas=nombre

Les ajustements inférieurs à limite-pas ms seront lissés. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

Si l'ajustement de l'heure est inférieur à limite-pas millisecondes, lisser le montant en utilisant adjtime(2). Sinon, modifier l'ajustement avec settimeofday(2). La valeur par défaut est 0, ce qui signifie que tous les ajustements seront modifiés. C'est une fonctionnalité, car différentes situations exigent des valeurs différentes.

-o nombre, --version-ntp=nombre

Envoyer int comme notre version du protocole NTP. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage 0 à 7

Le nombre par défaut pour cette option est :
4

Lors de l'envoi de requêtes à un serveur distant, lui indiquer que nous exécutons la version version-ntp du protocole NTP.

-r, --utiliser-port-reserve

Utiliser le Port Réservé NTP (port 123).

Utiliser le port 123, réservé au NTP, pour nos communications réseau.

-S, --pas

Autoriser la modification de l'heure avec settimeofday(2).
-s, --lisser

Autoriser le lissage de l'heure avec adjtime(2).
-t secondes, --delai-attente=secondes

Le nombre de secondes à attendre les réponses. Cette option prend un nombre entier comme argument. Le secondes par défaut pour cette option est :
5

Lors de l'attente d'une réponse, sntp attendra le nombre de secondes spécifié avant d'abandonner. La valeur par défaut devrait être plus que suffisante pour une réponse unicast. Si sntp attend seulement une réponse de diffusion, un délai d'attente plus long est probablement nécessaire.

sntp(1) — NTP Project

NAME

sntp — simple network time protocol client

SYNOPSIS

sntp [OPTIONS] [ntpserver ...]

DESCRIPTION

The sntp program is an implementation of the Simple Network Time Protocol (SNTP), specified in RFC 4330. It is used to synchronize the local system clock to a remote NTP server. SNTP is a simpler version of NTP that does not support all of the features of NTP, such as the full KISS-OF-DEATH (KOD) support.

This program is intended as a replacement for the older ntpdate program, which has been deprecated.

The program can be run as an unprivileged command to check the current time and error in the local clock, or with suitable privilege, it can be used to set the local clock.

When run with no arguments, sntp will query the default NTP server (typically `pool.ntp.org') and print the current time and offset.

OPTIONS

-?, --help

Display usage information and exit.
-!, --more-help

Pass the extended usage information through a pager.
-e --set-delta val

Set the maximum time offset to be corrected without stepping. The default is 128 milliseconds.
-h, --help

Display usage information and exit.
-i, --interface interface

Use the specified interface for outgoing packets.
-K, --key-file keyfile

Use the specified keyfile for authentication.
-m --max-stratum val

Set the maximum stratum number to synchronize to. The default is 10.
-M, --slew-max-delta val

Set the maximum slew rate. The default is 500 parts per million.
-p --port port

Use the specified port for outgoing packets. The default is 123.
-q, --query-mode mode

Set the query mode. The default is 3 (client mode).
-r, --tries count

Set the number of times to try querying the server. The default is 5.
-s, --step-delta val

Set the maximum time offset to be corrected without stepping. This is equivalent to -e.
-S, --setclock

Set the local clock. This option requires root privileges.
-t, --timeout seconds

Set the timeout for server responses. The default is 5 seconds.
-V, --version [{v|c|n}]

Output version of program and exit. The default mode is `v', a simple version. The `c' mode will print copyright information and `n' will print the full copyright notice.
-w, --wait-for-reply

Wait for pending replies. The no-wait form will disable the option. This option is enabled by default.
--no-wait

Wait for pending replies (if not setting the time). The no-wait form will disable the option. This option is enabled by default.

If we are not setting the time, wait for all pending responses.

-?, --help

Display usage information and exit.
-!, --more-help

Pass the extended usage information through a pager.
-> [cfgfile], --save-opts [=cfgfile]

Save the option state to cfgfile. The default is the last configuration file listed in the OPTION PRESETS section, below. The command will exit after updating the config file.
-< cfgfile, --load-opts=cfgfile, --no-load-opts

Load options from cfgfile. The no-load-opts form will disable the loading of earlier config/rc/ini files. --no-load-opts is handled early, out of order.
--version [{v|c|n}]

Output version of program and exit. The default mode is `v', a simple version. The `c' mode will print copyright information and `n' will print the full copyright notice.

OPTION PRESETS

Any option that is not marked as not presettable may be preset by loading values from configuration ("RC" or ".INI") file(s) and values from environment variables named:

  SNTP_<option-name> or SNTP

The environmental presets take precedence (are processed later than) the configuration files. The homerc files are "$HOME", and ".". If any of these are directories, then the file .ntprc is searched for within those directories.

USAGE

sntp ntpserver.somewhere

is the simplest use of this program and can be run as an unprivileged command to check the current time and error in the local clock.
sntp -Ss -M 128 ntpserver.somewhere

With suitable privilege, run as a command or from a cron(8) job, sntp -Ss -M 128 ntpserver.somewhere will request the time from the server, and if that server reports that it is synchronized then if the offset adjustment is less than 128 milliseconds the correction will be slewed, and if the correction is more than 128 milliseconds the correction will be stepped.
sntp -S ntpserver.somewhere

With suitable privilege, run as a command or from a cron(8) job, sntp -S ntpserver.somewhere will set (step) the local clock from a synchronized specified server, like the (deprecated) ntpdate(1), or rdate(8) commands.
