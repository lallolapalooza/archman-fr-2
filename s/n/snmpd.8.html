SNMPD(8) Net-SNMP SNMPD(8)

NOM

snmpd - démon pour répondre aux paquets de requêtes SNMP.

SYNOPIS

snmpd [OPTIONS] [ADRESSES D'ÉCOUTE]

DESCRIPTION

snmpd est un agent SNMP qui se lie à un port et attend les requêtes des logiciels de gestion SNMP. À la réception d'une requête, il traite la ou les requêtes, collecte les informations demandées et/ou effectue l'ou les opérations demandées, et renvoie les informations à l'expéditeur.

OPTIONS

-a
Enregistre les adresses source des requêtes entrantes.
-A
Ajoute au fichier journal au lieu de le tronquer.
-c FICHIER
Lit FICHIER comme un fichier de configuration (ou une liste de fichiers de configuration séparés par des virgules). Notez que le fichier chargé ne comprendra que les jetons de snmpd.conf, à moins que le type de configuration ne soit spécifié dans le fichier comme décrit dans la page de manuel snmp_config sous SWITCHING CONFIGURATION TYPES IN MID-FILE.
-C
Ne lit aucun fichier de configuration, sauf ceux éventuellement spécifiés par l'option -c. Notez que ce comportement couvre également les fichiers de configuration persistants. Cela peut entraîner la réinitialisation des valeurs attribuées dynamiquement après un redémarrage de l'agent, à moins que les fichiers de configuration persistants pertinents ne soient explicitement chargés à l'aide de l'option -c.
-d
Affiche (en hexadécimal) les paquets SNMP envoyés et reçus.
-D[JETON[,...]]
Active la sortie de débogage pour le ou les JETONS donnés. Sans jeton spécifié, cela imprime par défaut tous les jetons (ce qui est équivalent au mot-clé "ALL"). Vous pourriez essayer ALL pour une sortie extrêmement détaillée. Note: Vous ne pouvez pas mettre d'espace entre le drapeau -D et les JETONS listés.
-f
Ne pas forquer() du shell appelant.
-g GID
Change le groupe ID du processus snmpd en GID après l'ouverture des sockets d'écoute. Ceci remplace le paramètre de fichier de configuration agentgroup.
-h, --help
Affiche un bref message d'utilisation puis quitte.
-H
Affiche une liste de directives de fichiers de configuration comprises par l'agent puis quitte.
-I [-]INITLIST
Spécifie quels modules doivent (ou ne doivent pas) être initialisés au démarrage de l'agent. Si INITLIST séparé par des virgules est précédé d'un '-', c'est la liste des modules qui ne doivent pas être lancés. Sinon, c'est la liste des seuls modules qui doivent être lancés.

Pour obtenir une liste des modules compilés, exécutez l'agent avec les arguments -Dmib_init -H (en supposant que le support de débogage a été compilé).

-L[eEfFoOsSnN]
Spécifie où la sortie de journalisation doit être dirigée (sortie standard ou erreur, vers un fichier ou via syslog). Voir OPTIONS DE JOURNALISATION dans snmpcmd(1) pour les détails.
-m LISTEMIB
Spécifie une liste séparée par des deux-points de modules MIB à charger pour cette application. Ceci remplace la variable d'environnement MIBS. Voir snmpcmd(1) pour les détails.
-M LISTEDIR
Spécifie une liste séparée par des deux-points de répertoires à rechercher pour les MIBs. Ceci remplace la variable d'environnement MIBDIRS. Voir snmpcmd(1) pour les détails.
-n NOM
Définit un nom d'application alternatif (qui affectera les fichiers de configuration chargés). Par défaut, ce sera snmpd, quel que soit le nom du binaire réel.
-p FICHIER
Enregistre l'ID du processus du démon dans FICHIER.
-q
Affiche une sortie plus simple pour un analyse plus facile par les machines.
-r
Ne requiert pas les privilèges root pour exécuter le démon. Spécifiquement, ne pas quitter si des fichiers accessibles uniquement par root (tels que /dev/kmem etc.) ne peuvent pas être ouverts.
-u UID
Change l'ID utilisateur du processus snmpd en UID (qui peut être fourni sous forme numérique ou textuelle) après l'ouverture des sockets d'écoute. Ceci remplace le paramètre de fichier de configuration agentuser.
-U
Indique à l'agent de ne pas supprimer son fichier pid (voir l'option -p) lors de l'arrêt. Remplace le jeton leave_pidfile dans le fichier snmpd.conf, voir snmpd.conf(5).
-v, --version
Affiche les informations de version de l'agent puis quitte.
-V
Affiche symboliquement les transactions SNMP.
-x ADRESSE
Écoute les connexions AgentX sur l'adresse spécifiée plutôt que sur "/var/agentx/master" par défaut. L'adresse peut être un chemin de socket de domaine Unix, ou l'adresse d'une interface réseau. Le format est le même que le format des adresses d'écoute décrit ci-dessous.
-X
S'exécute comme sous-agent AgentX plutôt que comme agent maître SNMP.
--nom="valeur"
Permet de spécifier n'importe quel jeton ("nom") supporté dans le fichier snmpd.conf et de définir sa valeur à "valeur". Remplace le jeton correspondant dans le fichier snmpd.conf. Voir snmpd.conf(5) pour la liste complète des jetons.

ADRESSES D'ÉCOUTE

Par défaut, snmpd écoute les requêtes SNMP entrantes sur le port UDP 161 sur toutes les interfaces IPv4. Cependant, il est possible de modifier ce comportement en spécifiant une ou plusieurs adresses d'écoute comme arguments pour snmpd. Une adresse d'écoute prend la forme :

[<spécificateur-transport>:]<adresse-transport>

Dans sa forme la plus simple, une adresse d'écoute peut ne contenir qu'un numéro de port, auquel cas snmpd écoute sur ce port UDP sur toutes les interfaces IPv4. Sinon, la partie <adresse-transport> de la spécification est analysée selon le tableau suivant :

<spécificateur-transport>
Format de <adresse-transport>
udp (par défaut)
nom-hôte[:port] ou adresse-IPv4[:port]
tcp
nom-hôte[:port] ou adresse-IPv4[:port]
unix
chemin-d'accès
ipx
[réseau]:nœud[/port]
aal5pvc ou pvc
[interface.][VPI.]VCI
udp6 ou udpv6 ou udpipv6
nom-hôte[:port] ou adresse-IPv6[:port]
tcp6 ou tcpv6 ou tcpipv6
nom-hôte[:port] ou adresse-IPv6[:port]
ssh
nom-hôte:port
dtlsudp
nom-hôte:port

Notez que les chaînes de <spécificateur-transport> ne sont pas sensibles à la casse, donc par exemple, "tcp" et "TCP" sont équivalents. Voici quelques exemples, ainsi que leur interprétation :

127.0.0.1:161
écoute sur le port UDP 161, mais uniquement sur l'interface de bouclage. Cela empêche snmpd d'être interrogé à distance. La spécification du port ":161" n'est pas strictement nécessaire car c'est le port SNMP par défaut.
TCP:1161
écoute sur le port TCP 1161 sur toutes les interfaces IPv4.
ipx:/40000
écoute sur le port IPX 40000 sur toutes les interfaces IPX.
unix:/tmp/l
écoute sur le socket de domaine Unix spécifié par le chemin /tmp/local.

snmpd(8)

NAME

snmpd - An extensible SNMP agent

SYNOPSIS

snmpd [-a] [-c Conffile] [-C] [-H] [-L[eEev]] [-M transport] [-m Machine] [-n] [-N] [-p Pidfile] [-q] [-r] [-S] [-T] [-d] [-D [optimizatons]] [TrapSink[:Port] ...]

DESCRIPTION

The SNMP agent, snmpd, is a network management information base (MIB) agent. It listens for SNMP requests from SNMP managers, processes them, and returns the requested information. It can also generate SNMP traps and informs when certain events occur.

snmpd supports a variety of transport mechanisms for SNMP communications. These are specified using the -M option or through configuration directives in the snmpd.conf file.

OPTIONS

The available options are:

-a
Do not perform IP address to hostname translations for incoming v1 SNMP manager requests. This behaviour can be overridden with the nameCommunity: directive in snmpd.conf.
-c Conffile
Use the specified configuration file instead of the default /etc/snmp/snmpd.conf.
-C
Parse all configuration files. By default, snmpd only parses /etc/snmp/snmpd.conf. This option tells snmpd to parse all configuration files defined in the SNMPCONFPATH environment variable.
-H
Display a list of basic command line options and exit.
-L[eEev]
Configure logging behavior. The default is to log to stderr.
  • e: Log to stderr.
  • E: Log to stderr and do not call openlog().
  • v: Log verbose messages.
  • V: Log very verbose messages.
-M transport
Add the specified transport domain to the list of available transports. This option may be specified multiple times. For a list of available transports see section LISTENING ADDRESSES.
-m Machine
Load MIBs from the specified Machine file. This option may be specified multiple times.
-n
Do not fork() into the background. Useful for debugging.
-N
Do not exit if a configuration file is not found. Useful when running as a service and you don't want to exit if a config file is missing.
-p Pidfile
Write the process ID of the agent to the specified Pidfile. The default is /var/run/snmpd.pid.
-q
Quiet mode. Suppresses informational messages.
-r
Do not exit if an address is unable to be bound to. This is useful when you want to run snmpd on multiple interfaces, but don't want to exit if one of them is unavailable.
-S
Do not exit if a configuration file is not found. This option is deprecated and is equivalent to the -N option.
-T
Enable TSM (Transport Security Model) security model support. This is required for using SNMP over SSH and DTLS.
-d
Dump the packets sent and received. Useful for debugging.
-D [optimizatons]
Turn on specified debugging code. Write flags to stderr. For a list of valid tokens, see the section on debugging in snmpd.conf(5).
TrapSink[:Port] ...
A list of trap sinks to send traps to. If no port is specified, the default SNMP trap port (162) is used. These directives are processed after all configuration files have been read.

LISTENING ADDRESSES

The agent can be configured to listen on a variety of transport addresses. These addresses are specified using the -M command line option or the agentAddress directive in snmpd.conf. The format of these addresses depends on the transport domain being used.

Here are some common examples:

tcp:localhost:161
listen on port 161 on the loopback interface.
udp:161
listen on port 161 on all IPv4 interfaces.
udp:ipv6.example.com:161
listen on port 161 on the interface specified by ipv6.example.com.
tcp6:161
listen on port 161 on all IPv6 interfaces.
unix:/tmp/local-agent
listen on the Unix domain socket /tmp/local-agent.
/tmp/local-agent
is identical to the previous specification, since the Unix domain is assumed if the first character of the <transport-address> is '/'.
PVC:161
listen on the AAL5 permanent virtual circuit with VPI=0 and VCI=161 (decimal) on the first ATM adapter in the machine.
udp6:10161
listen on port 10161 on all IPv6 interfaces.
ssh:127.0.0.1:22
Allows connections from the snmp subsystem on the ssh server on port 22. The details of using SNMP over SSH are defined below.
dtlsudp:127.0.0.1:9161
Listen for connections over DTLS on UDP port 9161. The snmp.conf file must have the serverCert, configuration tokens defined.

Note that not all the transport domains listed above will always be available; for instance, hosts with no IPv6 support will not be able to use udp6 transport addresses, and attempts to do so will result in the error "Error opening specified endpoint". Likewise, since AAL5 PVC support is only currently available on Linux, it will fail with the same error on other platforms.

Transport Specific Notes

ssh
The SSH transport, on the server side, is actually just a unix named pipe that can be connected to via a ssh subsystem configured in the main ssh server. The pipe location (configurable with the sshtosnmpsocket token in snmp.conf) is /var/net-snmp/sshtosnmp. Packets should be submitted to it via the sshtosnmp application, which also sends the user ID as well when starting the connection. The TSM security model should be used when packets should process it.
The sshtosnmp command knows how to connect to this pipe and talk to it. It should be configured in the OpenSSH sshd configuration file (which is normally /etc/ssh/sshd_config using the following configuration line:
Subsystem snmp /usr/local/bin/sshtosnmp
The sshtosnmp command will need read/write access to the /var/net-snmp/sshtosnmp pipe. Although it should be fairly safe to grant access to the average user since it still requires modifications to the ACM settings before the user can perform operations, paranoid administrators may want to make the /var/net-snmp directory accessible only by users in a particular group. Use the sshtosnmpsocketperms snmp.conf configure option to set the permissions, owner and group of the created socket.
Access control can be granted to the user "foo" using the following style of simple snmpd.conf settings:
rouser -s tsm foo authpriv
Note that "authpriv" is acceptable assuming as SSH protects everything that way (assuming you have a non-insane setup). snmpd has no notion of how SSH has actually protected a packet and thus the snmp agent assumes all packets passed through the SSH transport have been protected at the authpriv level.
dtlsudp
The DTLS protocol, which is based off of TLS, requires both client and server certificates to establish the connection and authenticate both sides. In order to do this, the client will need to configure the snmp.conf file with the clientCert configuration tokens. The server will need to configure the snmp.conf file with the serverCert configuration tokens defined.
Access control setup is similar to the ssh transport as the TSM security model should be used to protect the packet.

CONFIGURATION FILES

snmpd checks for the existence of and parses the following files:

/etc/snmp/snmp.conf
Common configuration for the agent and applications. See snmp.conf(5) for details.
/etc/snmp/snmpd.conf
/etc/snmp/snmpd.local.conf
Agent-specific configuration. See snmpd.conf(5) for details. These files are optional and may be used to configure access control, trap generation, subagent protocols and much else besides.
In addition to these two configuration files in /etc/snmp, the agent will read any files with the names snmpd.conf and snmpd.local.conf in a colon separated path specified in the SNMPCONFPATH environment variable.
/usr/share/snmp/mibs/
The agent will also load all files in this directory as MIBs. It will not, however, load any file that begins with a '.' or descend into subdirectories.
