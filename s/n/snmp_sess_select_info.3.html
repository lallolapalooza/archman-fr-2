DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multi-threadée. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui contient les caractéristiques du transport et des informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure est passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Au lieu de cela, le pointeur opaque retourné par snmp_sess_open() est utilisé pour faire référence à cette session par la suite.

Les sessions SNMP créées avec snmp_sess_open() ne sont pas affectées par, et NE DEVRAIENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Au contraire, les fonctions équivalentes à session unique décrites ici devraient être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacun en entrée un pointeur vers un objet struct snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers sa struct snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacun un paramètre pdu, qui pointe vers un objet struct snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read appellera la fonction de rappel spécifiée lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela pourrait inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent respectivement aux arguments nfds, readfds et timeout de select(2). La seule exception est que timeout doit TOUJOURS pointer vers un struct timeval alloué (mais potentiellement non initialisé) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors défini sur vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données retournées. Lorsqu'il revient, snmp_sess_read() doit alors être appelé avec le fd_set retourné par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire qu'il retourne zéro), snmp_sess_timeout() doit être appelé pour vérifier si un délai d'attente s'est produit sur la session SNMP.

snmp_sess_synch_response est une routine pratique qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc. pour plus de détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut de succès retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable snmp_errno de SNMP, la valeur de la variable système errno, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

NAME

snmp_sess_select_info - Get SNMP session information for select(2)

SYNOPSIS


#include <net-snmp/types.h>

void *
snmp_sess_select_info(snmp_session *session);

DESCRIPTION

The snmp_sess_select_info function is used to retrieve information from an SNMP session structure that is needed by the select(2) system call.

This function takes a pointer to an snmp_session structure as input. It returns a pointer to a structure that contains the file descriptors and timeout information required by select(2). The exact type of the returned pointer is implementation-dependent and should not be relied upon; instead, it should be cast to the appropriate type or handled as opaque data.

The returned structure typically contains:

  • File descriptor(s) to monitor for read and write events.
  • Timeout value for the select(2) call.

This function is typically called in conjunction with snmp_select_list() to manage multiple SNMP sessions concurrently.

DIAGNOSTICS

The snmp_sess_select_info function itself does not return diagnostic information directly. Errors related to the SNMP session or network operations are typically handled through other functions in the Net-SNMP library, such as error codes returned by session setup or PDU sending/receiving functions. However, if the input session pointer is invalid, behavior is undefined.

The following are some common SNMP error codes that might be encountered when working with SNMP sessions:

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

NOM

snmp_sess_select_info - Obtenir des informations de session SNMP pour select(2)

SYNTAXE


#include <net-snmp/types.h>

void *
snmp_sess_select_info(snmp_session *session);

DESCRIPTION

La fonction snmp_sess_select_info est utilisée pour récupérer les informations d'une structure de session SNMP nécessaires à l'appel système select(2).

Cette fonction prend en entrée un pointeur vers une structure snmp_session. Elle renvoie un pointeur vers une structure contenant les descripteurs de fichiers et les informations de délai d'attente requises par select(2). Le type exact du pointeur renvoyé dépend de l'implémentation et ne doit pas être utilisé directement ; il doit plutôt être converti vers le type approprié ou traité comme une donnée opaque.

La structure renvoyée contient généralement :

  • Le ou les descripteurs de fichiers à surveiller pour les événements de lecture et d'écriture.
  • La valeur du délai d'attente pour l'appel select(2).

Cette fonction est généralement appelée conjointement avec snmp_select_list() pour gérer plusieurs sessions SNMP simultanément.

DIAGNOSTICS

La fonction snmp_sess_select_info elle-même ne renvoie pas directement d'informations de diagnostic. Les erreurs liées à la session SNMP ou aux opérations réseau sont généralement gérées par d'autres fonctions de la bibliothèque Net-SNMP, telles que les codes d'erreur renvoyés par les fonctions d'initialisation de session ou d'envoi/réception de PDU. Cependant, si le pointeur session fourni est invalide, le comportement est indéfini.

Voici quelques codes d'erreur SNMP courants qui peuvent être rencontrés lors de la manipulation de sessions SNMP :

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
