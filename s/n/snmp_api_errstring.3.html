DESCRIPTION

Snmp_sess_init prépare une structure netsnmp_session qui contient les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure a été passée à snmp_open pour créer une session SNMP, la structure n'est plus utilisée.

Snmp_open renvoie un pointeur vers un nouvel objet netsnmp_session, que l'application doit utiliser pour référencer la session SNMP active.

snmp_send et snmp_async_send() prennent chacun en entrée un pointeur vers un objet netsnmp_pdu. Cette structure contient des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_async_send(), snmp_read appellera la fonction de rappel spécifiée lorsque la réponse sera reçue.

Snmp_read, snmp_select_info, et snmp_timeout fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP puissent se dérouler de manière asynchrone.

Snmp_select_info reçoit les informations qui auraient été transmises à select en l'absence de SNMP. Par exemple, cela pourrait inclure des informations de mise à jour de fenêtre. Ces informations sont modifiées afin que SNMP obtienne le service dont il a besoin de l'appel à select. Dans ce cas, numfds, fdset, et timeout correspondent respectivement aux arguments nfds, readfds, et timeout de select. La seule exception est que timeout doit toujours pointer vers une structure struct timeval allouée (mais peut-être non initialisée). Si timeout avait été passé comme NULL, block est défini sur vrai, et timeout est traité comme indéfini. La même règle s'applique au retour de snmp_select_info.

Après avoir appelé snmp_select_info, select est appelé avec les données renvoyées. Lorsque select retourne, snmp_read doit être appelé avec le fd_set renvoyé par select pour lire chaque socket SNMP ayant une entrée. Si select expire (time out), snmp_timeout doit être appelé pour vérifier si l'expiration était destinée à SNMP.

snmp_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_send, snmp_read, etc. pour plus de détails.

DIAGNOSTICS

Les versions précédentes de la bibliothèque utilisaient snmp_get_errno pour lire la variable globale snmp_errno qui pouvait contenir l'état d'erreur dans la bibliothèque SNMP. La méthode existante snmp_perror doit être utilisée pour journaliser uniquement les erreurs de codage ASN.1.

La nouvelle méthode snmp_sess_perror est fournie pour capturer les erreurs qui surviennent lors du traitement d'une session SNMP particulière. Snmp_sess_perror appelle la fonction snmp_error pour obtenir l'erreur de la bibliothèque "C" errno, l'erreur de la bibliothèque SNMP snmperr, et le message d'erreur détaillé de la bibliothèque SNMP associé à une erreur survenue pendant une session donnée.

Notez que dans tous les cas sauf un, snmp_sess_perror doit recevoir le pointeur netsnmp_session * renvoyé par snmp_open. Si snmp_open renvoie un pointeur nul, passez le pointeur netsnmp_session * D'ENTRÉE utilisé pour appeler snmp_open.

Le statut de retour d'erreur de snmp_close et snmp_send est indiqué par le retour de 0. Un statut réussi renverra 1 pour snmp_close et l'ID de la requête du paquet pour snmp_send. Après un retour réussi de snmp_send, le pdu sera libéré par la bibliothèque.

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_GENERR
Une erreur générique s'est produite.
SNMPERR_BAD_LOCPORT
Le port local était incorrect car il avait déjà été alloué ou l'autorisation a été refusée.
SNMPERR_BAD_ADDRESS
Le nom d'hôte ou l'adresse fourni n'était pas utilisable.
SNMPERR_BAD_SESSION
La session spécifiée n'était pas ouverte.
SNMPERR_TOO_LONG
SNMPERR_NO_SOCKET
SNMPERR_V2_IN_V1
SNMPERR_V1_IN_V2
SNMPERR_BAD_REPEATERS
SNMPERR_BAD_REPETITIONS
SNMPERR_BAD_ASN1_BUILD
SNMPERR_BAD_SENDTO
SNMPERR_BAD_PARSE
SNMPERR_BAD_VERSION
SNMPERR_NOAUTH_DESPRIV
SNMPERR_ABORT
SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

Une représentation textuelle du code d'erreur peut être obtenue avec snmp_api_errstring, et un message d'erreur standard peut être affiché à l'aide de snmp_perror qui fonctionne comme la routine standard perror.
