DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multithread. À l'exception de snmp_sess_session(), ces fonctions sont des versions pour session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui source les caractéristiques de transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure a été passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. À la place, le pointeur opaque renvoyé par snmp_sess_open() est utilisé pour faire référence à cette session par la suite.

Les sessions SNMP qui sont créées avec snmp_sess_open() ne sont pas affectées par, et NE DEVRAIENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Les fonctions équivalentes pour session unique décrites ici doivent plutôt être utilisées.

snmp_sess_init() et snmp_sess_open() prennent chacune en entrée un pointeur vers un objet de type struct snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et renvoie un pointeur vers sa structure snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacune un paramètre pdu, qui pointe vers un objet struct snmp_pdu contenant des informations décrivant une transaction qui sera effectuée sur une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read invoquera le callback spécifié lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela peut inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées de manière à ce que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent aux arguments nfds, readfds et timeout de select(2) respectivement. La seule exception est que timeout doit TOUJOURS pointer vers un struct timeval alloué (mais peut-être non initialisé) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors défini à true, et timeout est traité comme non défini. La même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données retournées. Lorsqu'il revient, snmp_sess_read() doit alors être appelé avec le fd_set renvoyé par select(2). Cela lira toute entrée du socket SNMP de cette session. Si select(2) expire (c'est-à-dire qu'il renvoie zéro), snmp_sess_timeout() doit être appelé pour vérifier si un délai d'attente s'est produit sur la session SNMP.

snmp_sess_synch_response est une routine de commodité qui enverra la requête, attendra la réponse et la traitera avant de renvoyer. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour les détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut réussi renverra 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction renvoie la variable snmp_errno de SNMP, la valeur de la variable système errno, et une interprétation textuelle des deux variables. La chaîne doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

NAME

snmp_sess_read, snmp_sess_write, snmp_sess_error, snmp_sess_close, snmp_sess_options, snmp_sess_peername, snmp_sess_remote_port, snmp_sess_usmUserMaxSubidLen, snmp_sess_set_send_buffer, snmp_sess_set_recv_buffer, snmp_sess_get_send_buffer, snmp_sess_get_recv_buffer, snmp_sess_set_mib_parse_tree, snmp_sess_get_mib_parse_tree

SNMP session management functions.

SYNOPSIS

#include <net-snmp/session.h>

int
snmp_sess_read(netsnmp_session *session,
    netsnmp_pdu **pdu_out);

int
snmp_sess_write(netsnmp_session *session,
    netsnmp_pdu *pdu);

int
snmp_sess_error(const netsnmp_session *session,
    int *pdu_error,
    int *reason);

char *
snmp_sess_peername(const netsnmp_session *session);

int
snmp_sess_remote_port(const netsnmp_session *session);

int
snmp_sess_usmUserMaxSubidLen(const netsnmp_session *session);

int
snmp_sess_set_send_buffer(netsnmp_session *session,
    int size);

int
snmp_sess_set_recv_buffer(netsnmp_session *session,
    int size);

int
snmp_sess_get_send_buffer(const netsnmp_session *session);

int
snmp_sess_get_recv_buffer(const netsnmp_session *session);

void
snmp_sess_set_mib_parse_tree(netsnmp_session *session,
    const char *parse_tree);

char *
snmp_sess_get_mib_parse_tree(const netsnmp_session *session);

DESCRIPTION

These functions provide an interface to manage an SNMP session represented by a netsnmp_session structure. The netsnmp_session structure is typically initialized by calling snmp_open(3).

snmp_sess_read reads a PDU from the session. If a PDU is successfully read, it is returned in *pdu_out. The caller is responsible for freeing the PDU using snmp_pdu_free(3).

snmp_sess_write writes a PDU to the session.

snmp_sess_error retrieves error information about the session. If an error occurred during a previous operation, *pdu_error will be set to the SNMP error code (if applicable), and *reason will be set to a more detailed reason code.

snmp_sess_close closes the session, freeing any associated resources.

snmp_sess_peername returns the name of the remote host the session is connected to. The returned string is dynamically allocated and must be freed by the caller using snmp_mem_free(3).

snmp_sess_remote_port returns the remote port number.

snmp_sess_usmUserMaxSubidLen returns the maximum length of the USM user name sub-identifier.

snmp_sess_set_send_buffer and snmp_sess_set_recv_buffer set the socket send and receive buffer sizes, respectively. A value of 0 means the default size will be used.

snmp_sess_get_send_buffer and snmp_sess_get_recv_buffer retrieve the current socket send and receive buffer sizes.

snmp_sess_set_mib_parse_tree sets the MIB parse tree to be used for the session. This is typically a string like "SNMPv2-SMI::mib-2".

snmp_sess_get_mib_parse_tree retrieves the MIB parse tree currently set for the session. The returned string is dynamically allocated and must be freed by the caller using snmp_mem_free(3).

DIAGNOSTICS

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
