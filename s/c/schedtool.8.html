SCHEDTOOL(8) Manuel de l'administrateur système SCHEDTOOL(8)

NOM

schedtool - interroger et définir les paramètres de planification CPU

SYNTAXE

schedtool
[-0|-N] [-1|-F] [-2|-R] [-3|-B] [-4|-I] [-5|-D]
[-M politique]
[-a affinité] 
[-p priorité]
[-n niveau_nice]
[-e commande [arg ...]]
[-r]
[-v]
[-h]
[LISTE DE PIDs]

DESCRIPTION

schedtool peut définir tous les paramètres de planification CPU dont Linux est capable ou afficher des informations pour les processus donnés.

Les tâches de longue durée et non interactives peuvent bénéficier de SCHED_BATCH car les tranches de temps sont plus longues, moins de temps système est perdu à calculer le prochain processus exécutable et les caches restent stables.

Les applications audio/vidéo ou autres applications quasi temps réel peuvent s'exécuter avec moins de saccades si elles sont réglées sur SCHED_RR. Utilisez le commutateur de priorité statique -p pour désigner des hiérarchies inter-processus.

schedtool prend désormais en charge la définition de l'affinité CPU introduite dans linux 2.5.8.

OPTIONS

-N ou -0
définir tous les PIDs sur SCHED_NORMAL/OTHER
-F ou -1
sur SCHED_FIFO, privilèges root requis
-R ou -2
sur SCHED_RR, privilèges root requis
-B ou -3
sur SCHED_BATCH
-I ou -4
sur SCHED_ISO
-D ou -5
sur SCHED_IDLEPRIO
-M politique
pour le mode manuel/brut ; la politique est le numéro de la politique de planification (voir ci-dessus pour 0-4). Cette option est principalement destinée aux développeurs du noyau qui souhaitent tester leurs nouvelles implémentations.
-p priorité
spécifier la priorité statique, requise pour SCHED_FIFO et SCHED_RR. Généralement comprise entre 1 et 99.
-a affinité
définir l'affinité du PID sur ce masque binaire (hexadécimal) ; alternativement, un mode liste est pris en charge.
-n niveau_nice
définir le niveau nice du PID ; voir nice(2), nice(1).
-e commande [arg ...]
exécuter commande avec les paramètres de planification donnés (écrase l'image du processus de schedtool). Voir EXEMPLES.
-r
afficher la priorité minimale et maximale pour chaque politique.
-v
mode verbeux.
-h
aide

EXEMPLES

Pour interroger les politiques du $SHELL :

    #> schedtool $$
Pour interroger quelques PIDs, à savoir 1, 2 et 3 :
    #> schedtool 1 2 3
Pour exécuter mplayer en SCHED_RR avec la priorité 20. L'argument de priorité est nécessaire pour SCHED_RR et SCHED_FIFO. 
    #> schedtool -R -p 20 -e mplayer -quiet some_file.avi
Pour définir le shell actuel sur SCHED_BATCH, que tous les programmes lancés par le shell hériteront : 
    #> schedtool -3 $$
Pour définir tous les processus nommés 'cpu_hog' sur SCHED_BATCH : 
    #> schedtool -3 `pidof cpu_hog`
Pour définir l'affinité d'un processus sur le premier CPU uniquement (CPU0) : 
    #> schedtool -a 0x1 <PID>
Utilisation du mode liste et de l'affinité des CPU0 et CPU3 :
    #> schedtool -a 0,3 <PID>
Une combinaison d'arguments d'affinité et de politique est, bien entendu, toujours possible. 
   #> schedtool -B -a 0x1 <PID>

MASQUE D'AFFINITÉ

L'argument d'affinité détermine sur quels CPU un processus est autorisé à s'exécuter. Il se compose d'un simple masque binaire représenté en hexadécimal. Le CPU0 est désigné par le bit de poids faible, le CPU1 par le deuxième bit de poids faible, et ainsi de suite, donnant :


0x1 -> s'exécuter uniquement sur le CPU0


0x2 -> s'exécuter uniquement sur le CPU1


0x4 -> s'exécuter uniquement sur le CPU2


0x8 -> s'exécuter uniquement sur le CPU3... et ainsi de suite.

Les CPU multiples cibles peuvent être spécifiés en utilisant un OU bit à bit des valeurs :


0x7 -> s'exécuter sur les CPU 0, 1, 2 mais PAS sur le 4


0x3 -> s'exécuter uniquement sur les CPU 0 et 1

Par défaut, un processus s'exécute sur tous les CPU, donnant un masque de


0xf pour les 4 CPU


0xff pour les 8 CPU

MASQUE D'AFFINITÉ - MODE LISTE

Alternativement, un mode liste est pris en charge où vous pouvez spécifier les CPU délimités par des ",". Ce qui suit exécute <PID> sur le CPU0 et le CPU1 (équivalent à 0x3) :

   #> schedtool -a 0,1 <PID>

APERÇU DES POLITIQUES

SCHED_NORMAL / SCHED_OTHER C'est la politique par défaut et pour le programme moyen avec une certaine interaction. Prévaut sur les autres processus.

SCHED_FIFO Planificateur Premier Entré, Premier Sorti, utilisé uniquement pour les contraintes temps réel. Les processus de cette classe ne sont généralement pas préemptés par d'autres, ils doivent se libérer du CPU via sched_yield() et ainsi vous avez besoin d'applications spécialement conçues. Utiliser avec une extrême prudence. Privilèges ROOT requis.

SCHED_RR Planificateur Round-Robin, également utilisé pour les contraintes temps réel. Le temps CPU est attribué en mode round-robin avec une tranche de temps beaucoup plus petite qu'avec SCHED_NORMAL et les processus de ce groupe sont favorisés par rapport à SCHED_NORMAL. Utilisable pour les applications audio/vidéo proches du taux maximal du système. Privilèges ROOT requis.

SCHED_BATCH [depuis 2.6.16 dans le noyau principal] SCHED_BATCH a été conçu pour les applications non interactives et liées au CPU. Il utilise des tranches de temps plus longues (pour mieux exploiter le cache), mais peut être interrompu à tout moment par d'autres processus dans d'autres classes pour garantir l'interaction du système. Les processus de cette classe sont sélectionnés en dernier mais peuvent entraîner une accélération considérable (jusqu'à 300%). Aucun boost interactif n'est effectué.

SCHED_ISO [patch nécessaire] SCHED_ISO a été conçu pour offrir aux utilisateurs une classe similaire à SCHED_RR. Pour citer Con Kolivas : "Il s'agit d'une politique de planification sans expiration conçue pour garantir une tranche de temps dans une latence raisonnable tout en empêchant la famine. Bon pour les jeux, la vidéo aux limites du matériel, la capture vidéo, etc."

SCHED_IDLEPRIO [patch nécessaire] SCHED_IDLEPRIO est similaire à SCHED_BATCH, mais a été explicitement conçu pour consommer uniquement le temps où le CPU est inactif. Aucun boost interactif n'est effectué. Si vous utilisiez SCHED_BATCH dans les noyaux -ck, c'est ce que vous voulez depuis 2.6.16

INDICES

PID 0 signifie "processus courant", dans notre cas, schedtool. Peut survenir lors de l'utilisation de l'option -e.

Soyez prudent avec SCHED_FIFO ! Vous risquez de bloquer d'autres processus du CPU, y compris votre shell.

Pour SCHED_BATCH, vous avez certainement besoin d'un noyau 2.6 récent.

Un bref aperçu est donné dans SCHED_DESIGN et le fichier README contient une discussion approfondie. Le fichier INSTALL liste également toutes les prérequis et où vous pouvez obtenir des patches.

L'affinité 0x0 ne doit jamais être utilisée.
