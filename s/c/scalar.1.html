SCALAR(1) Manuel Git SCALAR(1)

NOM

scalar - Un outil pour gérer de grands dépôts Git

SYNTAXE

scalar clone [--single-branch] [--branch <branche-principale>] [--full-clone]
        [--[no-]src] [--[no-]tags] [--[no-]maintenance] <url> [<enlistment>]
scalar list
scalar register [--[no-]maintenance] [<enlistment>]
scalar unregister [<enlistment>]
scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]
scalar reconfigure [--maintenance=(enable|disable|keep)] [ --all | <enlistment> ]
scalar diagnose [<enlistment>]
scalar delete <enlistment>

DESCRIPTION

Scalar est un outil de gestion de dépôts qui optimise Git pour une utilisation dans de grands dépôts. Scalar améliore les performances en configurant des paramètres Git avancés, en maintenant les dépôts en arrière-plan et en contribuant à réduire les données envoyées sur le réseau.

Un concept important de Scalar est l'enlistment : il s'agit du répertoire de niveau supérieur du projet. Il contient généralement le sous-répertoire src/ qui est une copie de travail Git. Cela encourage la séparation entre les fichiers suivis (à l'intérieur de src/) et les fichiers non suivis, tels que les artefacts de build (à l'extérieur de src/). Lors de l'enregistrement d'une copie de travail Git existante auprès de Scalar dont le nom n'est pas src, l'enlistment sera identique à la copie de travail.

La commande scalar implémente diverses sous-commandes et différentes options en fonction de la sous-commande. À l'exception de clone, list et reconfigure --all, toutes les sous-commandes s'attendent à être exécutées dans un enlistment.

Les options suivantes peuvent être spécifiées *avant* la sous-commande :

-C <répertoire>

Avant d'exécuter la sous-commande, changez le répertoire de travail. Cette option imite la même option de git(1).

-c <clé>=<valeur>

Pour la durée de l'exécution de la sous-commande spécifiée, configurez ce paramètre. Cette option imite la même option de git(1).

COMMANDES

Clone

clone [<options>] <url> [<enlistment>]

Clone le dépôt spécifié, similaire à git-clone(1). Par défaut, seuls les objets commit et arbre sont clonés. Une fois terminé, la copie de travail se trouve dans <enlistment>/src.

La fonctionnalité sparse-checkout est activée (sauf lorsqu'elle est exécutée avec --full-clone) et les seuls fichiers présents sont ceux du répertoire de niveau supérieur. Utilisez git sparse-checkout set pour développer l'ensemble des répertoires que vous souhaitez voir, ou git sparse-checkout disable pour développer tous les fichiers (voir git-sparse-checkout(1) pour plus de détails). Vous pouvez explorer les sous-répertoires en dehors de votre sparse-checkout en utilisant git ls-tree HEAD[:<répertoire>].

-b <nom>, --branch <nom>

Au lieu de vérifier la branche pointée par le HEAD du dépôt cloné, vérifiez la branche <nom> à la place.

--single-branch, --no-single-branch

Clone uniquement l'historique menant à la pointe d'une unique branche, soit celle spécifiée par l'option --branch, soit la branche principale à laquelle le HEAD du distant pointe.

Les fetch ultérieurs dans le dépôt résultant ne mettront à jour que la branche de suivi distant pour la branche pour laquelle cette option a été utilisée lors du clonage initial. Si le HEAD au niveau du distant ne pointait pas vers une branche lors du clonage avec --single-branch, aucune branche de suivi distant n'est créée.

--src, --no-src

Par défaut, scalar clone place le dépôt cloné dans un répertoire <entlistment>/src. Utilisez --no-src pour placer le dépôt cloné directement dans le répertoire <enlistment>.

--tags, --no-tags

Par défaut, scalar clone récupérera les objets tag annoncés par le distant et les futures commandes git fetch feront de même. Utilisez --no-tags pour éviter de récupérer les tags dans scalar clone et pour configurer le dépôt afin d'éviter de récupérer les tags à l'avenir. Pour récupérer les tags après le clonage avec --no-tags, exécutez git fetch --tags.

--full-clone, --no-full-clone

Un sparse-checkout est initialisé par défaut. Ce comportement peut être désactivé via --full-clone.

--maintenance, --no-maintenance

Par défaut, scalar clone configure l'enlistment pour utiliser la fonctionnalité de maintenance en arrière-plan de Git. Utilisez --no-maintenance pour ignorer cette configuration.

Lister

list

Liste les enlistments actuellement enregistrés par Scalar. Cette sous-commande ne nécessite pas d'être exécutée dans un enlistment.

Enregistrer

register [<enlistment>]

Ajoute le dépôt de l'enlistment à la liste des dépôts enregistrés et démarre la maintenance en arrière-plan. Si <enlistment> n'est pas fourni, alors l'enlistment associé au répertoire de travail courant est enregistré.

Note : lorsque cette sous-commande est appelée dans une copie de travail nommée src/, son répertoire parent est considéré comme étant l'enlistment Scalar. Si la copie de travail ne s'appelle *pas* src/, elle sera elle-même considérée comme l'enlistment Scalar.

--maintenance, --no-maintenance

Par défaut, scalar register configure l'enlistment pour utiliser la fonctionnalité de maintenance en arrière-plan de Git. Utilisez --no-maintenance pour ignorer cette configuration. Cela ne désactive pas la maintenance qui pourrait déjà être activée par d'autres moyens.

Désenregistrer

unregister [<enlistment>]

Supprime le dépôt spécifié de la liste des dépôts enregistrés auprès de Scalar et arrête la maintenance en arrière-plan planifiée.

Exécuter

scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]

Exécute la tâche de maintenance donnée (ou toutes les tâches, si all a été spécifié). À l'exception de all et config, cette sous-commande délègue simplement à git-maintenance(1) (en mappant fetch à prefetch et pack-files à incremental-repack).

Ces tâches sont exécutées automatiquement dans le cadre de la maintenance planifiée, dès que le dépôt est enregistré auprès de Scalar. Il ne devrait donc pas être nécessaire d'exécuter cette sous-commande manuellement.

La tâche config est spécifique à Scalar et configure tous ces paramètres par défaut qui rendent Git plus efficace avec les grands dépôts. Comme cette tâche est automatiquement exécutée dans le cadre de scalar clone, les invocations explicites de cette tâche sont rarement nécessaires.

Reconfigurer

Après une mise à niveau de Scalar, ou lorsque la configuration d'un enlistment Scalar a été corrompue ou modifiée par erreur, cette sous-commande permet de reconfigurer l'enlistment.

--all

Lorsque --all est spécifié, reconfigure tous les enlistments actuellement enregistrés auprès de Scalar par la clé de configuration scalar.repo. Utilisez cette option après chaque mise à niveau pour bénéficier des dernières fonctionnalités.

--maintenance=(enable|disable|keep)

Par défaut, Scalar configure l'enlistment pour utiliser la fonctionnalité de maintenance en arrière-plan de Git ; ceci est identique à l'utilisation de la valeur 'enable' pour cette option. Utilisez la valeur disable pour retirer chaque enlistment considéré de la maintenance en arrière-plan. Utilisez `keep' pour laisser la configuration de la maintenance en arrière-plan inchangée pour ces dépôts.

Diagnostiquer

diagnose [<enlistment>]

Lors du signalement de problèmes avec Scalar, il est souvent utile de fournir les informations recueillies par cette commande, y compris les journaux et certaines statistiques décrivant la forme des données de l'enlistment actuel.

T

ET

git(1), git-clone(1), git-maintenance(1), git-sparse-checkout(1)

Le résultat de cette commande est un fichier .zip qui est écrit dans un répertoire adjacent au répertoire de travail dans le répertoire src.

Delete

delete <enlistment>

Cette sous-commande vous permet de supprimer un enregistrement Scalar existant de votre système de fichiers local, désenregistrant ainsi le dépôt.

VOIR AUSSI

git-clone(1), git-maintenance(1).
