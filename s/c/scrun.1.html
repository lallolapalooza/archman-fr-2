NOM

scrun - un proxy d'exécution OCI pour Slurm.

SYNOPSIS

Opération de création

scrun [OPTIONS GLOBALES...] create [OPTIONS DE CRÉATION] <id-conteneur>

Prépare un nouveau conteneur avec l'id-conteneur dans le répertoire de travail actuel.

Opération de démarrage

scrun [OPTIONS GLOBALES...] start <id-conteneur>

Demande de démarrage et d'exécution du conteneur dans une tâche.

Opération de requête d'état

scrun [OPTIONS GLOBALES...] state <id-conteneur>

Affiche l'état JSON défini par OCI du conteneur.

Opération de mise à mort

scrun [OPTIONS GLOBALES...] kill <id-conteneur> [signal]

Envoie un signal (par défaut : SIGTERM) au conteneur.

Opération de suppression

scrun [OPTIONS GLOBALES...] delete [OPTIONS DE SUPPRESSION] <id-conteneur>

Libère toutes les ressources détenues par le conteneur localement et à distance.

Effectue des opérations d'exécution OCI sur <id-conteneur> conformément à :
https://github.com/opencontainers/runtime-spec/blob/main/runtime.md

scrun tente d'imiter le comportement de la ligne de commande aussi fidèlement que possible à crun et runc afin de maintenir la compatibilité de remplacement en place avec DOCKER et podman. Tous les arguments de ligne de commande pour crun et runc seront acceptés pour des raisons de compatibilité, mais pourront être ignorés en fonction de leur applicabilité.

DESCRIPTION

scrun est un proxy d'exécution OCI pour Slurm. Il agit comme une interface commune avec DOCKER ou podman pour permettre l'exécution d'opérations de conteneurs sous Slurm en tant que tâches. scrun acceptera toutes les commandes comme une exécution conforme OCI, mais redirigera le conteneur et toutes les entrées/sorties vers Slurm pour la planification et l'exécution. Les conteneurs seront exécutés à distance sur les nœuds de calcul Slurm conformément aux paramètres de oci.conf(5).

scrun exige que tous les conteneurs soient conformes aux images OCI, conformément à :
https://github.com/opencontainers/image-spec/blob/main/spec.md

VALEUR DE RETOUR

En cas de succès, scrun retournera 0. Pour toute autre condition, scrun retournera un nombre non nul pour indiquer une erreur.

OPTIONS GLOBALES

--cgroup-manager
Ignoré.
--debug
Active la journalisation au niveau de débogage.
-f <chemin_conf_slurm>
Utilise le fichier slurm.conf spécifié pour la configuration.
Par défaut : sysconfdir de configure lors de la compilation
--usage
Affiche une aide rapide sur la façon d'appeler scrun
--log-format=<json|text>
Sélectionne éventuellement le format de journalisation. Peut être "json" ou "text".
Par défaut : text
--root=<chemin_racine>
Chemin vers le répertoire de mise en cache pour les sockets de communication et les répertoires et fichiers temporaires. Il devrait s'agir d'un tmpfs et être vidé au redémarrage.
Par défaut : /run/user/{id_utilisateur}/scrun/
--rootless
Ignoré. Toutes les commandes scrun sont toujours sans privilèges (rootless).
--systemd-cgroup
Ignoré.
-v
Augmente la verbosité de la journalisation. Plusieurs -v augmentent la verbosité.
-V, --version
Affiche les informations de version et quitte.

OPTIONS DE CRÉATION

-b <chemin_bundle>, --bundle=<chemin_bundle>
Chemin vers la racine du répertoire du bundle.
Par défaut : répertoire de travail de l'appelant
--console-socket=<chemin_socket_console>
Chemin facultatif vers une socket AF_UNIX qui recevra un descripteur de fichier faisant référence à l'extrémité maître du pseudo-terminal de la console.
Par défaut : ignoré
--no-pivot
Ignoré.
--no-new-keyring
Ignoré.
--pid-file=<chemin_fichier_pid>
Spécifie le fichier à verrouiller et à remplir avec l'identifiant du processus.
Par défaut : ignoré
--preserve-fds
Ignoré.

OPTIONS DE SUPPRESSION

--force
Ignoré. Toutes les demandes de suppression sont forcées et arrêteront toutes les tâches en cours.

SCRUN.LUA

Le fichier /etc/slurm/scrun.lua doit être présent sur tout nœud où scrun sera invoqué. scrun.lua doit être un script lua conforme.

Fonctions requises

Les fonctions suivantes doivent être définies.

• function slurm_scrun_stage_in(id, bundle, spool_dir, config_file, job_id, user_id, group_id, job_env)
Appelée juste après l'allocation de la tâche pour préparer le conteneur sur les nœuds de la tâche. Doit retourner SLURM.success ou la tâche sera annulée. Il est obligatoire que la fonction prépare le conteneur pour l'exécution sur les nœuds de la tâche, conformément à ce qui est configuré dans oci.conf(1). La fonction peut bloquer aussi longtemps que nécessaire jusqu'à ce que le conteneur soit entièrement préparé (dans la limite du temps mural maximal de la tâche).
id
ID du conteneur

Fonctions fournies

Les fonctions suivantes sont fournies pour que toute fonction Lua puisse les appeler au besoin.

• slurm.set_bundle_path(PATH)
Appelée pour notifier scrun d'utiliser PATH comme nouveau chemin de bundle de conteneur OCI. Selon la disposition du système de fichiers, le clonage du bundle de conteneur peut être nécessaire pour permettre l'exécution sur les nœuds de la tâche.
• slurm.set_root_path(PATH)
Appelée pour notifier scrun d'utiliser PATH comme nouveau chemin de système de fichiers racine du conteneur. Selon la disposition du système de fichiers, le clonage du bundle de conteneur peut être nécessaire pour permettre l'exécution sur les nœuds de la tâche. Le script doit également mettre à jour #/root/path dans config.json lors de la modification du chemin racine.
• STATUS,OUTPUT = slurm.remote_command(SCRIPT)
Exécute SCRIPT dans une nouvelle étape de tâche sur tous les nœuds de tâche. Retourne le statut numérique de la tâche comme STATUS et la sortie standard de la tâche comme OUTPUT. Bloque jusqu'à ce que SCRIPT se termine.
• STATUS,OUTPUT = slurm.allocator_command(SCRIPT)
Exécute SCRIPT en tant que processus enfant bifurqué de scrun. Retourne le statut numérique de la tâche comme STATUS et la sortie standard de la tâche comme OUTPUT. Bloque jusqu'à ce que SCRIPT se termine.
• slurm.log(MSG, LEVEL)
Enregistre MSG au niveau de journalisation LEVEL. La plage valide de valeurs pour LEVEL est [0, 4].
• slurm.error(MSG)
Enregistre l'erreur MSG.
• slurm.log_error(MSG)
Enregistre l'erreur MSG.
• slurm.log_info(MSG)
Enregistre MSG au niveau de journalisation INFO.
• slurm.log_verbose(MSG)
Enregistre MSG au niveau de journalisation VERBOSE.
• slurm.log_verbose(MSG)
Enregistre MSG au niveau de journalisation VERBOSE.
• slurm.log_debug(MSG)
Enregistre MSG au niveau de journalisation DEBUG.
• slurm.log_debug2(MSG)
Enregistre MSG au niveau de journalisation DEBUG2.
• slurm.log_debug3(MSG)
Enregistre MSG au niveau de journalisation DEBUG3.
• slurm.log_debug4(MSG)
Enregistre MSG au niveau de journalisation DEBUG4.
• MINUTES = slurm.time_str2mins(TIME_STRING)
Analyse TIME_STRING en nombre de minutes comme MINUTES. Formats valides :
• jours-[heures[:minutes[:secondes]]]

Exemples de scripts scrun.lua

Exemple complet de staging de conteneur utilisant rsync :
Cet exemple complet préparera un conteneur tel que donné par docker ou podman. Le fichier config.json du conteneur est modifié pour supprimer les fonctions indésirables qui pourraient provoquer l'exécution du conteneur sous crun ou runc. Le script utilise rsync pour déplacer le conteneur vers un système de fichiers partagé sous la variable scratch_path.

NOTE : Le support JSON dans liblua doit généralement être installé avant la compilation de Slurm. La syntaxe de scrun.lua et la capacité de charger le support JSON doivent être testées en appelant directement le script à l'aide de lua en dehors de Slurm.

local scratch_path = "/run/user/"
local function read_file(path)
	local file = open(path, "rb")
	if not file then return nil end
	local content = file:read "*all"
	file:close()
	return content
end
