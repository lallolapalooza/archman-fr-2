SCREEN(1) Manuel des commandes générales SCREEN(1)

NOM

screen - gestionnaire d'écrans avec émulation de terminal VT100/ANSI

SYNTAXE

screen [ -options ] [ cmd [ arguments ] ]
screen -r [[pid.]tty[.hôte]]
screen -r propriétaire_session/[[pid.]tty[.hôte]]

DESCRIPTION

Screen est un gestionnaire de fenêtres plein écran qui multiplexe un terminal physique entre plusieurs processus (typiquement des shells interactifs). Chaque terminal virtuel fournit les fonctions d'un terminal DEC VT100 et, en plus, plusieurs fonctions de contrôle des normes ISO 6429 (ECMA 48, ANSI X3.64) et ISO 2022 (par ex. insertion/suppression de ligne et support de plusieurs jeux de caractères). Il existe un tampon d'historique de défilement pour chaque terminal virtuel et un mécanisme de copie et collage qui permet de déplacer des régions de texte entre les fenêtres. Lorsque screen est appelé, il crée une seule fenêtre avec un shell à l'intérieur (ou la commande spécifiée) et vous laisse ensuite faire votre travail comme vous le feriez normalement. Ensuite, à tout moment, vous pouvez créer de nouvelles fenêtres (plein écran) avec d'autres programmes dedans (y compris d'autres shells), tuer des fenêtres existantes, afficher une liste des fenêtres, activer et désactiver la journalisation de la sortie, copier-coller du texte entre les fenêtres, visualiser l'historique de défilement, basculer entre les fenêtres de la manière que vous souhaitez, etc. Toutes les fenêtres exécutent leurs programmes complètement indépendamment les unes des autres. Les programmes continuent de s'exécuter lorsque leur fenêtre n'est pas actuellement visible et même lorsque toute la session screen est détachée du terminal de l'utilisateur. Lorsqu'un programme se termine, screen (par défaut) tue la fenêtre qui le contenait. Si cette fenêtre était au premier plan, l'affichage bascule vers la fenêtre précédente ; s'il n'en reste plus, screen se termine. Les shells distinguent généralement entre l'exécution en tant que shell de connexion ou sous-shell. Screen les exécute comme sous-shells, sauf indication contraire (Voir la commande shell .screenrc).

Tout ce que vous tapez est envoyé au programme exécuté dans la fenêtre courante. La seule exception est la combinaison de touches qui est utilisée pour initier une commande au gestionnaire de fenêtres. Par défaut, chaque commande commence par un contrôle-a (abrégé C-a à partir de maintenant), et est suivi par une autre combinaison de touches. Le caractère de commande et toutes les liaisons de touches peuvent être entièrement personnalisés pour être n'importe quoi, bien qu'ils soient toujours de deux caractères de longueur.

Screen ne comprend pas le préfixe C- pour signifier contrôle, bien que cette notation soit utilisée dans ce manuel pour des raisons de lisibilité. Veuillez utiliser la notation en chevron (^A au lieu de C-a) comme arguments pour, par exemple, la commande escape ou l'option -e. Screen affichera également les caractères de contrôle en notation en chevron.

La façon standard de créer une nouvelle fenêtre est de taper C-a c. Cela crée une nouvelle fenêtre exécutant un shell et bascule immédiatement vers cette fenêtre, quel que soit l'état du processus exécuté dans la fenêtre courante. De même, vous pouvez créer une nouvelle fenêtre avec une commande personnalisée en la liant d'abord à une combinaison de touches (dans votre fichier .screenrc ou sur la ligne de commande C-a :) et en l'utilisant ensuite comme la commande C-a c. De plus, de nouvelles fenêtres peuvent être créées en exécutant une commande comme celle-ci :

screen emacs prog.c

depuis une invite de shell dans une fenêtre précédemment créée. Cela n'exécutera pas une autre copie de screen, mais fournira plutôt le nom de la commande et ses arguments au gestionnaire de fenêtres (spécifié dans la variable d'environnement $STY) qui l'utilisera pour créer la nouvelle fenêtre. L'exemple ci-dessus lancerait l'éditeur emacs (éditant prog.c) et basculerait vers sa fenêtre. - Notez que vous ne pouvez pas transporter de variables d'environnement du shell appelant vers l'application (emacs dans ce cas), car elle est "forkée" depuis le processus screen parent, et non depuis le shell appelant.

Si /etc/utmp est inscriptible par screen, un enregistrement approprié sera écrit dans ce fichier pour chaque fenêtre, et supprimé lorsque la fenêtre se termine. Ceci est utile pour travailler avec talk, script, shutdown, rsend, sccs et d'autres programmes similaires qui utilisent le fichier utmp pour déterminer qui vous êtes. Tant que screen est actif sur votre terminal, l'enregistrement du terminal lui-même est supprimé du fichier utmp. Voir aussi C-a L.

PREMIERS PAS

Avant de commencer à utiliser screen, vous devrez vous assurer d'avoir correctement sélectionné le type de votre terminal, tout comme vous le feriez pour tout autre programme termcap/terminfo. (Vous pouvez le faire en utilisant test par exemple.)

Si vous êtes impatient et que vous voulez commencer sans lire davantage, vous devriez retenir cette seule commande : C-a ?. Taper ces deux caractères affichera une liste des commandes screen disponibles et de leurs liaisons. Chaque combinaison de touches est discutée dans la section LIAISONS DE TOUCHES PAR DÉFAUT. La section MANUEL PERSONNALISATION traite du contenu de votre .screenrc.

Si votre terminal est un véritable terminal à marge automatique (il ne permet pas que la dernière position de l'écran soit mise à jour sans faire défiler l'écran) envisagez d'utiliser une version de termcap de votre terminal avec les marges automatiques désactivées. Cela garantira une mise à jour précise et optimale de l'écran dans toutes les circonstances. La plupart des terminaux modernes ont des marges magiques (marges automatiques plus une dernière colonne utilisable). C'est le type de style VT100 et parfaitement adapté à screen. Si tout ce que vous avez est un vrai terminal à marge automatique, screen se contentera de l'utiliser, mais la mise à jour d'un caractère inséré dans la dernière position de l'écran peut ne pas être possible tant que l'écran ne défile pas ou que le caractère n'est pas déplacé dans une position sûre d'une autre manière. Ce délai peut être raccourci en utilisant un terminal avec la capacité d'insertion de caractère.

OPTIONS DE LA LIGNE DE COMMANDE

Screen a les options de ligne de commande suivantes :

-a
inclut toutes les capacités (à quelques exceptions mineures près) dans le termcap de chaque fenêtre, même si screen doit redessiner des parties de l'affichage pour implémenter une fonction.
-A
Adapte les tailles de toutes les fenêtres à la taille du terminal courant. Par défaut, screen essaie de restaurer ses anciennes tailles de fenêtre lorsqu'il se connecte à des terminaux redimensionnables (ceux avec WS dans leur description, par exemple suncmd ou certains xterm).
-c fichier
remplace le fichier de configuration par défaut de $HOME/.screenrc par fichier.
-d|-D [pid.tty.hôte]
ne démarre pas screen, mais détache la session screen en cours d'exécution ailleurs. Il a le même effet que de taper C-a d depuis le terminal de contrôle de screen. -D est l'équivalent de la touche de détachement puissant. Si aucune session ne peut être détachée, cette option est ignorée. Combinée avec l'option -r/-R, des effets plus puissants peuvent être obtenus :
-d -r
Relie une session et, si nécessaire, la détache d'abord.
-d -R
Relie une session et, si nécessaire, la détache ou la crée d'abord.
-d -RR
Relie une session et, si nécessaire, la détache ou la crée. Utilise la première session si plusieurs sont disponibles.
-D -r
Relie une session. Si nécessaire, détache et déconnecte le système distant d'abord.
-D -R
Se connecte ici et maintenant. En détail, cela signifie : Si une session est en cours d'exécution, alors relie. Si nécessaire, détache et déconnecte le système distant d'abord. Si elle n'était pas en cours d'exécution, la crée et notifie l'utilisateur. C'est la préférée de l'auteur.
-D -RR
Se connecte ici et maintenant. Quoi qu'il en soit, fais-le.
Note : Il est toujours conseillé de vérifier l'état de vos sessions en utilisant screen -list.
-e xy
spécifie que le caractère de commande est x et que le caractère générant un caractère de commande littéral est y (lorsqu'il est tapé après le caractère de commande). La valeur par défaut est C-a et `a', qui peut être spécifié comme -e^Aa. Lors de la création d'une session screen, cette option définit le caractère de commande par défaut. Dans une session multi-utilisateurs, tous les utilisateurs ajoutés commenceront avec ce caractère de commande. Mais lors de la connexion à une session déjà en cours d'exécution, cette option ne change que le caractère de commande de l'utilisateur qui se connecte. Cette option est équivalente aux commandes defescape ou escape respectivement.
-f, -fn, et -fa
active, désactive ou bascule le mode de commutation automatique du contrôle de flux. Ceci peut aussi être défini via la commande defflow .screenrc.
-h num
Spécifie la taille du tampon de défilement de l'historique à num lignes.
-i
provoque l'interruption immédiate de l'affichage par la touche d'interruption (généralement C-c) lorsque le contrôle de flux est activé. Voir la commande defflow .screenrc pour plus de détails. L'utilisation de cette option est déconseillée.
-l et -ln
active ou désactive le mode de connexion (pour la mise à jour de /etc/utmp). Ceci peut aussi être défini via la commande deflogin .screenrc.
-ls [correspondance]
-list [correspondance]
ne démarre pas screen, mais affiche une liste de chaînes pid.tty.host identifiant vos sessions screen. Les sessions marquées comme `détachées' peuvent être reprises avec screen -r. Celles marquées comme `attachées' sont en cours d'exécution et ont un terminal de contrôle. Si la session s'exécute en mode multi-utilisateur, elle est marquée `multi'. Les sessions marquées comme `inaccessibles' résident soit sur un hôte différent, soit sont `mortes'. Une session inaccessible est considérée comme morte lorsque son nom correspond soit au nom de l'hôte local, soit au paramètre spécifié, le cas échéant. Voir le drapeau -r pour une description de la manière de construire des correspondances. Les sessions marquées comme `mortes' doivent être soigneusement vérifiées et supprimées. Demandez à votre administrateur système si vous n'êtes pas sûr. Supprimez les sessions avec l'option -wipe.
-L
indique à screen d'activer la journalisation automatique de la sortie pour les fenêtres.
-Logfile fichier
Par défaut, le nom du fichier journal est screenlog.0. Vous pouvez définir un nouveau nom de fichier journal avec l'option -Logfile.
-m
fait en sorte que screen ignore la variable d'environnement $STY. Avec screen -m, la création d'une nouvelle session est forcée, que screen soit appelé depuis une autre session screen ou non. Ce drapeau a une signification spéciale en conjonction avec l'option `-d':
-d -m
Démarre screen en mode détaché. Ceci crée une nouvelle session mais ne s'y attache pas. Ceci est utile pour les scripts de démarrage système.
-D -m
Ceci démarre également screen en mode détaché, mais ne crée pas de nouveau processus. La commande se termine si la session se termine.
-O
sélectionne un mode de sortie optimal pour votre terminal plutôt qu'une émulation VT100 réelle (n'affecte que les terminaux à marge automatique sans `LP'). Ceci peut également être défini dans votre .screenrc en spécifiant `OP' dans une commande termcap.
-p nombre_ou_nom|-|=|+
Pré-sélectionne une fenêtre. Ceci est utile lorsque vous souhaitez vous rattacher à une fenêtre spécifique ou lorsque vous souhaitez envoyer une commande via l'option -X à une fenêtre spécifique. Comme avec la commande select de screen, - sélectionne la fenêtre vide. Comme cas spécial pour la reprise, = affiche la liste des fenêtres dans la fenêtre vide, tandis que + créera une nouvelle fenêtre. La commande ne sera pas exécutée si la fenêtre spécifiée n'a pas été trouvée.
-P
active l'authentification. Par défaut, screen permet de se connecter sans entrer le mot de passe de l'utilisateur. Cette option modifie ce comportement, c'est-à-dire qu'elle active l'authentification. Le même effet peut être obtenu en utilisant la commande "auth on".
-q
Supprime l'affichage des messages d'erreur. En combinaison avec -ls, la valeur de sortie est la suivante : 9 indique un répertoire sans sessions. 10 indique un répertoire avec des sessions en cours d'exécution mais non attachables. 11 (ou plus) indique 1 (ou plusieurs) sessions utilisables. En combinaison avec -r, la valeur de sortie est la suivante : 10 indique qu'il n'y a pas de session à reprendre. 12 (ou plus) indique qu'il y a 2 (ou plusieurs) sessions à reprendre et que vous devez spécifier laquelle choisir. Dans tous les autres cas, -q n'a aucun effet.
-Q
Certaines commandes peuvent maintenant être interrogées depuis une session distante en utilisant ce drapeau, par exemple screen -Q windows. Les commandes enverront la réponse à la sortie standard du processus de requête. S'il y a eu une erreur dans la commande, le processus de requête se terminera avec un statut non nul.

Les commandes qui peuvent être interrogées maintenant sont :
echo
info
lastmsg
number
select
time
title
windows

-r [pid.tty.host]
-r propriétaire_session/[pid.tty.host]
reprend une session screen détachée. Aucune autre option (sauf les combinaisons avec -d/-D) ne peut être spécifiée, bien qu'un préfixe optionnel [pid.]tty.host puisse être nécessaire pour distinguer plusieurs sessions screen détachées. La deuxième forme est utilisée pour se connecter à la session screen d'un autre utilisateur qui s'exécute en mode multi-utilisateur. Ceci indique à screen de rechercher des sessions dans le répertoire d'un autre utilisateur. Ceci nécessite setuid-root.
-R
reprend screen uniquement lorsqu'il est sans ambiguïté de savoir laquelle attacher, généralement lorsqu'une seule screen est détachée. Sinon, liste les sessions disponibles. -RR tente de reprendre la première session screen détachée qu'il trouve. En cas de succès, toutes les autres options de la ligne de commande sont ignorées. S'il n'existe pas de session détachée, démarre une nouvelle session en utilisant les options spécifiées, comme si -R n'avait pas été spécifié. L'option est définie par défaut si screen est exécuté comme shell de connexion (en fait, screen utilise -xRR dans ce cas). Pour les combinaisons avec l'option -d/-D, voir là.
-s programme
définit le shell par défaut sur le programme spécifié, au lieu de la valeur de la variable d'environnement $SHELL (ou /bin/sh si elle n'est pas définie). Ceci peut également être défini via la commande shell .screenrc. Voir aussi là.
-S nom_session
Lors de la création d'une nouvelle session, cette option peut être utilisée pour spécifier un nom significatif pour la session. Ce nom identifie la session pour les actions screen -list et screen -r. Il remplace le suffixe par défaut [tty.host]. Ce nom ne doit pas dépasser 80 symboles.
-t nom
définit le titre (alias) pour le shell par défaut ou le programme spécifié. Voir également la commande shelltitle .screenrc.
-T terminal
Définit la variable d'environnement $TERM en utilisant le terminal spécifié par opposition au réglage par défaut de screen.
-U
Exécute screen en mode UTF-8. Cette option indique à screen que votre terminal envoie et comprend les caractères encodés en UTF-8. Elle définit également le codage par défaut pour les nouvelles fenêtres sur `utf8'.
-v
Affiche le numéro de version.
-wipe [correspondance]
fait la même chose que screen -ls, mais supprime les sessions détruites au lieu de les marquer comme `mortes'. Une session inaccessible est considérée comme morte lorsque son nom correspond soit au nom de l'hôte local, soit au paramètre explicitement donné, le cas échéant. Voir le drapeau -r pour une description de la manière de construire des correspondances.
-x
Se connecte à une session screen non détachée. (Mode multi-affichage). Screen refuse de se connecter depuis lui-même. Mais lors de la mise en cascade de plusieurs screens, les boucles ne sont pas détectées ; faites attention.
-X
Envoie la commande spécifiée à une session screen en cours d'exécution. Vous pouvez utiliser l'option -S pour spécifier la session screen si vous avez plusieurs sessions screen en cours d'exécution. Vous pouvez utiliser l'option -d ou -r pour indiquer à screen de rechercher uniquement les sessions screen attachées ou détachées. Notez que cette commande ne fonctionne pas si la session est protégée par mot de passe.
-4
Résout les noms d'hôte uniquement en adresses IPv4.
-6
Résout les noms d'hôte uniquement en adresses IPv6.

PERSONNALISATION

Le répertoire des sockets est par défaut soit $HOME/.screen, soit simplement /tmp/screens, soit de préférence /usr/local/screens choisi au moment de la compilation. Si screen est installé setuid-root, l'administrateur devrait compiler screen avec un répertoire de sockets adéquat (non monté via NFS). Si screen ne s'exécute pas setuid-root, l'utilisateur peut spécifier n'importe quel répertoire avec les permissions 700 dans la variable d'environnement $SCREENDIR.

Lorsque screen est invoqué, il exécute les commandes d'initialisation à partir des fichiers /usr/local/etc/screenrc et des valeurs par défaut qui peuvent être remplacées des manières suivantes : pour le fichier screenrc global, screen recherche la variable d'environnement $SYSSCREENRC (cette fonction de remplacement peut être désactivée à la compilation). Le fichier screenrc spécifique à l'utilisateur est recherché dans $SCREENRC, puis $HOME/.screenrc. L'option de ligne de commande -c a la priorité sur les fichiers screenrc utilisateur ci-dessus.

Les commandes dans ces fichiers sont utilisées pour définir des options, lier des fonctions à des touches et établir automatiquement une ou plusieurs fenêtres au début de votre session screen. Les commandes sont listées une par ligne, les lignes vides étant ignorées. Les arguments d'une commande sont séparés par des tabulations ou des espaces, et peuvent être entourés de guillemets simples ou doubles. Un '#' transforme le reste de la ligne en commentaire, sauf entre guillemets. Les lignes incompréhensibles sont signalées et ignorées. Les commandes peuvent contenir des références aux variables d'environnement. La syntaxe est du type shell "$VAR" ou "${VAR}". Notez que cela entraîne une incompatibilité avec les versions précédentes de screen, car le caractère '$' doit maintenant être protégé par '\' si aucune substitution de variable ne doit être effectuée. Une chaîne entre guillemets simples est également protégée de la substitution de variables.

Deux fichiers de configuration sont fournis en exemple avec votre distribution screen : etc/screenrc et etc/etcscreenrc. Ils contiennent un certain nombre d'exemples utiles pour diverses commandes.

La personnalisation peut également se faire "en ligne". Pour entrer en mode commande, tapez `C-a :'. Notez que les commandes commençant par def modifient les valeurs par défaut, tandis que les autres modifient les réglages actuels.

Les commandes suivantes sont disponibles :

acladd noms d'utilisateur [mot-de-passe-chiffré]
addacl noms d'utilisateur

Permet aux utilisateurs d'accéder entièrement à cette session screen. Noms d'utilisateur peut être un seul utilisateur ou une liste d'utilisateurs séparée par des virgules. Cette commande permet de se connecter à la session screen et exécute l'équivalent de `aclchg noms d'utilisateur +rwx "#?"'. exécuté. Pour ajouter un utilisateur avec un accès restreint, utilisez la commande `aclchg' ci-dessous. Si un deuxième paramètre optionnel est fourni, il doit s'agir d'un mot de passe chiffré pour les utilisateur(s) nommé(s). 'Addacl' est un synonyme de 'acladd'. Mode multi-utilisateurs uniquement.

aclchg noms d'utilisateur bits_de_permission liste
chacl noms d'utilisateur bits_de_permission liste

Modifie les permissions pour une liste d'utilisateurs séparée par des virgules. Les bits de permission sont représentés par 'r', 'w' et 'x'. Un '+' accorde la permission, un '-' la retire. Le troisième paramètre est une liste de commandes et/ou de fenêtres séparée par des virgules (spécifiées par leur numéro ou leur titre). La liste spéciale '#' fait référence à toutes les fenêtres, '?' à toutes les commandes. Si noms d'utilisateur ne contient qu'une seule '*', tous les utilisateurs connus sont affectés.

Une commande peut être exécutée lorsque l'utilisateur a le bit 'x' pour celle-ci. L'utilisateur peut taper une entrée dans une fenêtre lorsqu'il a le bit 'w' défini et qu'aucun autre utilisateur n'obtient un verrou en écriture pour cette fenêtre. Les autres bits sont actuellement ignorés. Pour retirer le verrou en écriture d'un autre utilisateur dans la fenêtre 2 : `aclchg nom_utilisateur -w+w 2'. Pour autoriser un accès en lecture seule à la session : `acl

chg nom d'utilisateur -w "#". Dès qu'un nom d'utilisateur est connu de screen, il peut se connecter à la session et (par défaut) dispose de toutes les autorisations pour toutes les commandes et fenêtres. L'autorisation d'exécution pour les commandes acl, `at' et autres devrait également être supprimée, sinon l'utilisateur pourrait être en mesure de retrouver les autorisations d'écriture. Les droits du nom d'utilisateur spécial nobody ne peuvent pas être modifiés (voir la commande su). `Chacl' est un synonyme de `aclchg'. Mode multi-utilisateurs uniquement.

acldel nom d'utilisateur

Supprime un utilisateur de la liste de contrôle d'accès de screen. S'il est actuellement attaché, tous les affichages de l'utilisateur sont détachés de la session. Il ne pourra plus se connecter. Mode multi-utilisateurs uniquement.

aclgrp nom d'utilisateur [nom du groupe]

Crée des groupes d'utilisateurs qui partagent des droits d'accès communs. Le nom du groupe est le nom d'utilisateur du chef de groupe. Chaque membre du groupe hérite des autorisations accordées au chef de groupe. Cela signifie que si un utilisateur échoue à une vérification d'accès, une autre vérification est effectuée pour le chef de groupe. Un utilisateur est retiré de tous les groupes lorsque la valeur spéciale none est utilisée pour nom du groupe. Si le deuxième paramètre est omis, tous les groupes auxquels l'utilisateur appartient sont listés.

aclumask [[ utilisateurs ] +bits | [ utilisateurs ] -bits... ]
umask [[ utilisateurs ] +bits | [ utilisateurs ] -bits... ]

Ceci spécifie l'accès que les autres utilisateurs ont aux fenêtres qui seront créées par l'appelant de la commande. Utilisateurs peut être aucun, un ou une liste d'utilisateurs connus séparés par des virgules. Si aucun utilisateur n'est spécifié, une liste de tous les utilisateurs actuellement connus est supposée. Bits est une combinaison quelconque des bits de contrôle d'accès autorisés, définis avec la commande aclchg. Le nom d'utilisateur spécial ? prédéfinit l'accès que les utilisateurs non encore connus recevront initialement à toute fenêtre. Le nom d'utilisateur spécial ?? prédéfinit l'accès que les utilisateurs non encore connus reçoivent à toute commande. Les droits du nom d'utilisateur spécial nobody ne peuvent pas être modifiés (voir la commande su). `Umask' est un synonyme de `aclumask'.

at [identifiant][#|*|%] commande [arguments ... ]

Exécute une commande sur d'autres affichages ou fenêtres comme si elle y avait été entrée. At modifie le contexte (le réglage `fenêtre actuelle' ou `affichage actuel') de la commande. Si le premier paramètre décrit un contexte non unique, la commande sera exécutée plusieurs fois. Si le premier paramètre est de la forme `identifiant*' alors identifiant est mis en correspondance avec les noms d'utilisateurs. La commande est exécutée une fois pour chaque affichage de l'utilisateur (ou des utilisateurs) sélectionné(s). Si le premier paramètre est de la forme `identifiant%' identifiant est mis en correspondance avec les affichages. Les affichages sont nommés d'après les ttys auxquels ils se connectent. L'autorisation est vérifiée pour l'initiateur de la commande at, pas pour les propriétaires de l'affichage affecté.

backtick id durée rafraîchissement_automatique commande arguments...
backtick id

Programme la commande backtick avec l'identifiant numérique id. La sortie d'une telle commande est utilisée pour la substitution de l'échappement de la chaîne %`. La durée spécifiée est le nombre de secondes pendant lesquelles la sortie est considérée comme valide. Chaque occurrence de '%' dans message est remplacée par le numéro de la fenêtre à laquelle une sonnerie a été envoyée, et chaque occurrence de '^G' est remplacée par la définition de la sonnerie dans votre termcap (généralement un carillon audible). bind [classe] clé [commande [arguments]]

Lie une commande à une touche. Par défaut, la plupart des commandes fournissentd par screen sont liés à une ou plusieurs touches comme indiqué dans la section DEFAULT KEY BINDINGS, par exemple la commande pour créer une nouvelle fenêtre est liée à C-c et c. La commande bind peut être utilisée pour redéfinir les liaisons de touches et pour définir de nouvelles liaisons. L'argument key est soit un caractère unique, une séquence de deux caractères de la forme ^x (signifiant C-x), une barre oblique inverse suivie d'un nombre octal (spécifiant le code ASCII du caractère), ou une barre oblique inverse suivie d'un second caractère, tel que \^ ou \\. L'argument peut également être mis entre guillemets, si vous le souhaitez. Si aucun argument supplémentaire n'est donné, toute liaison précédemment établie pour cette touche est supprimée. L'argument command peut être n'importe quelle commande listée dans cette section.

Si une classe de commande est spécifiée via l'option -c, la touche est liée à la classe spécifiée. Utilisez la commande command pour activer une classe. Les classes de commande peuvent être utilisées pour créer plusieurs touches de commande ou des liaisons multi-caractères.

Quelques exemples:

bind ' ' windows
bind ^k
bind k
bind K kill
bind ^f screen telnet foobar
bind \033 screen -ln -t root -h 1000 9 su

lierait la touche espace à la commande qui affiche une liste de fenêtres (de sorte que la commande généralement invoquée par C-a C-w serait également disponible en tant que C-a espace). Les trois lignes suivantes suppriment la liaison par défaut de kill de C-a C-k et C-a k. C-a K est ensuite lié à la commande kill. Ensuite, il lie C-f à la commande de création d'une fenêtre avec une connexion TELNET à foobar, et lie la touche échappement à la commande qui crée une fenêtre sans connexion nommée root dans la fente n° 9, avec un shell superutilisateur et un tampon de défilement de 1000 lignes.

bind -c demo1 0 select 10
bind -c demo1 1 select 11
bind -c demo1 2 select 12
bindkey "^B" command -c demo1

fait que C-b 0 sélectionne la fenêtre 10, C-b 1 la fenêtre 11, etc.

bind -c demo2 0 select 10
bind -c demo2 1 select 11
bind -c demo2 2 select 12
bind - command -c demo2

fait que C-a - 0 sélectionne la fenêtre 10, C-a - 1 la fenêtre 11, etc.

bindkey [-d] [-m] [-a] [[-k|-t] string [cmd-args]]

Cette commande gère les tables de traduction d'entrée de screen. Chaque entrée de l'une des tables indique à screen comment réagir si une certaine séquence de caractères est rencontrée. Il existe trois tables : une qui doit contenir les actions programmées par l'utilisateur, une pour les actions par défaut utilisées pour l'émulation de terminal et une pour le mode copie de screen afin de déplacer le curseur. Voir la section TRANSLATION D'ENTRÉE pour une liste des liaisons de touches par défaut.

Si l'option -d est donnée, bindkey modifie la table par défaut, -m modifie la table du mode copie et sans aucune option, la table utilisateur est sélectionnée. L'argument string est la séquence de caractères auxquels une action est liée. Il peut s'agir d'une chaîne fixe ou d'un nom de capacité de clavier termcap (sélectionnable avec l'option -k).

Certaines touches sur un terminal VT100 peuvent envoyer une chaîne différente si le mode application est activé (par exemple, les touches fléchées). Ces touches ont deux entrées dans la table de traduction. Vous pouvez sélectionner l'entrée du mode application en spécifiant l'option -a.

L'option -t indique à screen de ne pas effectuer de chronométrage inter-caractères. On ne peut pas désactiver le chronométrage si une capacité termcap est utilisée.

Cmd peut être n'importe laquelle des commandes de screen avec un nombre arbitraire d'arguments args. Si cmd est omis, la liaison de touche est supprimée de la table.

Voici quelques exemples de liaisons de clavier :

        bindkey -d

Affiche toutes les liaisons de touches par défaut. Les entrées du mode application sont marquées de [A].

        bindkey -k k1 select 1

Fait que la touche "F1" bascule vers la fenêtre un.

        bindkey -t foo stuff barfoo

Fait de "foo" une abréviation du mot "barfoo". Le délai d'attente est désactivé afin que les utilisateurs puissent taper lentement.

        bindkey "\024" mapdefault

Cette liaison de touche fait de ^T un caractère d'échappement pour les liaisons de touches. Si vous avez effectué la liaison de caractères ci-dessus, vous pouvez entrer le mot foo en tapant ^Tfoo. Si vous voulez insérer un ^T, vous devez appuyer deux fois sur la touche (c'est-à-dire échapper à la liaison d'échappement).

        bindkey -k F1 command

Fait de la touche F11 (pas F1 !) une échappatoire d'écran alternative (en plus de ^A).

Il y a cependant quelques touches qui agissent différemment qu'en vi. Vi ne permet pas de 'yank' (copier) des blocs rectangulaires de texte, mais screen le fait. Appuyez sur : c ou C pour définir la marge gauche ou droite respectivement. Si aucun compteur de répétition n'est donné, les deux sont par défaut à la position actuelle du curseur.

Exemple : Essayez ceci sur un écran de texte assez rempli :

C-a [ M 20 l ESPACE c 10 l 5 j C ESPACE.

Cela déplace au milieu de l'écran, se décale de 20 colonnes vers la gauche, marque le début du tampon de collage, définit la colonne gauche, se décale de 5 colonnes vers le bas, définit la colonne droite, puis marque la fin du tampon de collage. Essayez maintenant :

C-a [ M 20 l ESPACE 10 l 5 j ESPACE

et remarquez la différence dans la quantité de texte copiée.

J joint les lignes. Il bascule entre 4 modes : lignes séparées par un caractère de nouvelle ligne (012), lignes collées sans espace, lignes séparées par un seul espace et lignes séparées par une virgule. Notez que vous pouvez préfixer le caractère de nouvelle ligne avec un caractère de retour chariot, en activant crlf.

v ou V est pour tous les utilisateurs de vi avec :set numbers - cela bascule la marge gauche entre la colonne 9 et 1. Appuyez sur

a avant la dernière touche espace pour basculer en mode ajout. Ainsi, le contenu du tampon de collage ne sera pas écrasé, mais sera ajouté.

A bascule en mode ajout et définit une (deuxième) marque.

> définit la (deuxième) marque et écrit le contenu du tampon de collage dans le fichier d'échange d'écran (/tmp/screen-exchange par défaut) une fois le mode copie terminé.

Cet exemple montre comment vider tout le tampon de défilement dans ce fichier : C-A [ g ESPACE G $ >.

C-g donne des informations sur la ligne et la colonne actuelles.

x ou o échange la première marque et la position actuelle du curseur. Vous pouvez utiliser cela pour ajuster une marque déjà placée.

C-l ('el') redessine l'écran.

@ ne fait rien. Ne quitte même pas le mode copie.

exec [[fdpat]newcommand [args ...]]

Exécute un sous-processus Unix (spécifié par un chemin d'exécutable newcommand et ses arguments optionnels) dans la fenêtre courante. Le flux de données entre stdin/stdout/stderr de newcommand, le processus initialement lancé dans la fenêtre (appelons-le "processus-application") et screen lui-même (fenêtre) est contrôlé par le motif de descripteur de fichier fdpat. Ce motif est essentiellement une séquence de trois caractères représentant stdin, stdout et stderr de newcommand. Un point (.) connecte le descripteur de fichier à screen. Un point d'exclamation (!) connecte le descripteur de fichier au processus-application. Un double point (:) combine les deux. L'entrée utilisateur ira à newcommand à moins que newcommand ne reçoive la sortie du processus-application (le premier caractère de fdpat est `!' ou `:') ou qu'un symbole pipe (|) ne soit ajouté (comme quatrième caractère) à la fin de fdpat.

L'invocation de `exec' sans arguments affiche le nom et les arguments du sous-processus en cours d'exécution dans cette fenêtre. Un seul sous-processus à la fois peut être en cours d'exécution dans chaque fenêtre.

Lorsqu'un sous-processus est en cours d'exécution, la commande `kill' l'affectera au lieu du processus des fenêtres.

Reportez-vous au fichier postscript `doc/fdpat.ps' pour une illustration confuse des 21 combinaisons possibles. Chaque dessin montre les chiffres 2,1,0 représentant les trois descripteurs de fichiers de newcommand. La boîte marquée `W' est le pty habituel qui a le processus-application sur son côté esclave. La boîte marquée `P' est le pty secondaire qui a maintenant screen à son côté maître.

Abréviations : L'espace entre le mot `exec' et fdpat et la commande peut être omis. Les points finaux et un fdpat composé uniquement de points peuvent être omis. Un simple `|' est synonyme du motif `!..|'; le mot exec peut être omis ici et peut toujours être remplacé par `!'.

Exemples :

exec ... /bin/sh
exec /bin/sh
!/bin/sh

Crée un autre shell dans la même fenêtre, tandis que le shell d'origine continue de s'exécuter. La sortie des deux shells est affichée et l'entrée utilisateur est envoyée au nouveau /bin/sh.

exec !.. stty 19200
exec ! stty 19200
!!stty 19200

Définit la vitesse du tty de la fenêtre. Si votre commande stty opère sur stdout, ajoutez un autre `!'.

exec !..| less
|less

Ceci ajoute un paginateur à la sortie de la fenêtre. Le caractère spécial `|' est nécessaire pour donner à l'utilisateur le contrôle sur le paginateur bien qu'il reçoive son entrée du processus de la fenêtre. Cela fonctionne car less écoute sur stderr (un comportement que screen n'attendrait pas sans le `|') lorsque son stdin n'est pas un tty. Les versions de less plus récentes que 177 échouent lamentablement ici ; le bon vieux pg fonctionne toujours.

!:sed -n s/.*Error.*/\007/p

Envoie la sortie de la fenêtre à la fois à l'utilisateur et à la commande sed. Le sed insère un caractère de son supplémentaire (octal 007) dans la sortie de la fenêtre vue par screen. Cela provoquera des messages "Son dans la fenêtre x", chaque fois que la chaîne "Error" apparaît dans la fenêtre.

focus [ next | prev | up | down | left | right | top | bottom ]

Déplace le focus d'entrée vers la région suivante. Ceci est fait de manière cyclique, de sorte que la région en haut à gauche soit sélectionnée après celle en bas à droite. Si aucune option n'est donnée, la valeur par défaut est `next'. La prochaine région à sélectionner est déterminée par la façon dont les régions sont superposées. Normalement, la région suivante dans la même couche serait sélectionnée. Cependant, si cette région suivante contient une ou plusieurs couches, la première région de la couche la plus haute est sélectionnée en premier. Si vous êtes dans la dernière région de la couche actuelle, `next' déplacera le focus vers la région suivante dans la couche inférieure (s'il y a une couche inférieure). `Prev' fait cycler dans l'ordre inverse. Voir split pour plus d'informations sur les couches.

Le reste des options (`up', `down', `left', `right', `top', et `bottom') sont plus indifférentes aux couches. L'option `up' déplacera le focus vers le haut vers la région qui touche le coin supérieur gauche de la région actuelle. `Down' se déplacera vers le bas vers la région qui touche le coin inférieur gauche de la région actuelle. L'option `left' déplacera le focus vers la gauche vers la région qui touche le coin supérieur gauche de la région actuelle, tandis que `right' se déplacera vers la droite vers la région qui touche le coin supérieur droit de la région actuelle. Se déplacer vers la gauche depuis une région la plus à gauche ou se déplacer vers la droite depuis une région la plus à droite n'entraînera aucune action.

L'option `top' déplacera le focus vers la toute première région dans le coin supérieur gauche de l'écran, et `bottom' déplacera vers la région dans le coin inférieur droit de l'écran. Se déplacer vers le haut depuis une région la plus en haut ou se déplacer vers le bas

n d'une région la plus en bas n'aura aucun effet.

Les raccourcis utiles sont (h, j, k et l l comme dans vi)

    bind h focus left
    bind j focus down
    bind k focus up
    bind l focus right
    bind t focus top
    bind b focus bottom
Notez que k est traditionnellement lié à la commande kill.

hardstatus [ on | off ]

Cette commande configure l'utilisation et l'émulation de la ligne de statut matérielle du terminal. La première forme active/désactive l'utilisation de la ligne de statut matérielle par screen pour afficher des messages. Si l'indicateur est réglé sur `off', ces messages sont superposés en mode vidéo inversé sur la ligne d'affichage. Le réglage par défaut est `on'.

Vous pouvez le personnaliser avec n'importe quelle chaîne souhaitée, y compris les séquences d'échappement du chapitre STRING ESCAPES. help[class]

Pas vraiment une aide en ligne, mais affiche un écran d'aide vous montrant toutes les liaisons de touches. Les premières pages listent toutes les commandes internes suivies de leurs liaisons actuelles. Les pages suivantes afficheront les commandes personnalisées, une commande par touche. Appuyez sur espace lorsque vous avez fini de lire chaque page, ou sur retour pour quitter plus tôt. Tous les autres caractères sont ignorés. Si l'option -c est donnée, affiche toutes les commandes liées pour la classe de commande spécifiée. Voir aussi la section DEFAULT KEY BINDINGS.

history

Habituellement, les utilisateurs travaillent avec un shell qui permet un accès facile aux commandes précédentes. Par exemple, csh a la commande !! pour répéter la dernière commande exécutée. Screen vous permet d'avoir un moyen primitif de rappeler la commande qui a démarré... : vous tapez simplement la première lettre de cette commande, puis vous appuyez sur `C-a {' et screen essaie de trouver une ligne précédente qui correspond au `prompt character' à gauche du curseur. Cette ligne est collée dans la file d'entrée de cette fenêtre. Ainsi, vous avez un historique de commandes rudimentaire (composé de la fenêtre visible et de son tampon de défilement).

hstatus status

Change la ligne de statut matériel de la fenêtre à la chaîne status.

idle [timeout[cmd-args]]

Définit une commande qui est exécutée après que le nombre spécifié de secondes d'inactivité soit atteint. Cette commande sera normalement la commande blanker pour créer un économiseur d'écran, mais elle peut être n'importe quelle commande screen. Si aucune commande n'est spécifiée, seul le délai d'attente est défini. Un délai d'attente de zéro (ou le délai d'attente spécial off) désactive le minuteur. Si aucun argument n'est donné, les paramètres actuels sont affichés.

ignorecase [ on | off ]

Indique à screen d'ignorer la casse des caractères dans les recherches. Par défaut, la valeur est `off'. Sans aucune option, l'état de ignorecase est inversé.

info

Utilise la ligne de messages pour afficher des informations sur la fenêtre actuelle : la position du curseur sous la forme (colonne,ligne) commençant par (1,1), la largeur et la hauteur du terminal plus la taille du tampon de défilement en lignes, comme dans (80,24)+50, l'état actuel du contrôle de flux XON/XOFF est affiché comme suit (Voir aussi la section FLOW CONTROL) :

+flow contrôle de flux automatique, actuellement activé.
-flow contrôle de flux automatique, actuellement désactivé.
+(+)flow contrôle de flux activé. Correspond au contrôle automatique.
-(+)flow contrôle de flux désactivé. Ne correspond pas au contrôle automatique.
+(-)flow contrôle de flux activé. Ne correspond pas au contrôle automatique.
-(-)flow contrôle de flux désactivé. Correspond au contrôle automatique.

Le réglage actuel de retour à la ligne (`+wrap' indique activé, `-wrap' désactivé) est également affiché. Les indicateurs `ins', `org', `app', `log', `mon' ou `nored' sont affichés lorsque la fenêtre est en mode insertion, en mode origine, en mode pavé numérique d'application, a la journalisation de sortie, la surveillance d'activité ou le redessin partiel activé.

Le jeu de caractères actif actuellement (G0, G1, G2 ou G3) et entre crochets les jeux de caractères du terminal qui sont actuellement désignés comme G0 à G3 est affiché. Si la fenêtre est en mode UTF-8, la chaîne UTF-8 est affichée à la place.

Des modes supplémentaires en fonction du type de la fenêtre sont affichés à la fin de la ligne de statut (Voir aussi le chapitre WINDOW TYPES).

Si la machine à états de l'émulateur de terminal est dans un état non par défaut, la ligne d'informations commence par une chaîne identifiant l'état actuel.

Pour les informations système, utilisez la commande time.

ins_reg [key]

N'existe plus, utilisez paste à la place.

kill

Tue la fenêtre actuelle.

S'il y a une commande `exec' en cours d'exécution, elle est tuée. Sinon, le processus (shell) s'exécutant dans la fenêtre reçoit une condition HANGUP, la structure de la fenêtre est supprimée et screen (votre affichage) passe à une autre fenêtre. Lorsque la dernière fenêtre est détruite, screen se termine. Après un kill, screen bascule vers la fenêtre affichée précédemment.

Note : les utilisateurs d'Emacs doivent garder cette commande à l'esprit lorsqu'ils tuent une ligne. Il est recommandé de ne pas utiliser C-a comme touche d'échappement screen ou de reconfigurer kill sur C-a K.

lastmsg

Affiche le dernier message.

class="Pp">Réaffichez les derniers contenus de la ligne de message/statut. Utile si vous tapez pendant qu'un message apparaît, car le message disparaît lorsque vous appuyez sur une touche (sauf si votre terminal dispose d'une ligne de statut matérielle). Reportez-vous aux commandes msgwait et msgminwait pour un réglage fin.

layout new [titre]

Crée une nouvelle disposition. L'écran passera à une seule région et sera basculé vers la fenêtre vierge. À partir de là, vous construisez les régions et les fenêtres qu'elles affichent comme vous le souhaitez. La nouvelle disposition sera numérotée avec le plus petit entier disponible, en commençant par zéro. Vous pouvez éventuellement donner un titre à votre nouvelle disposition. Sinon, elle aura un titre par défaut "layout". Vous pouvez toujours changer le titre plus tard en utilisant la commande layout title.

layout remove [n|titre]

Supprime, ou en d'autres termes, efface la disposition spécifiée. Le numéro ou le titre peuvent être spécifiés. Sans aucune spécification, screen supprimera la disposition actuelle.

La suppression d'une disposition n'affecte pas vos fenêtres ou régions définies.

layout next

Commute vers la prochaine disposition disponible.

layout prev

Commute vers la disposition précédente disponible.

layout select [n|titre]

Sélectionne la disposition souhaitée. Le numéro ou le titre peuvent être spécifiés. Sans aucune spécification, screen vous demandera quelle disposition est souhaitée. Pour voir quelles dispositions sont disponibles, utilisez la commande layout show.

layout show

Liste sur la ligne de message le(s) numéro(s) et le(s) titre(s) des dispositions disponibles. La disposition actuelle est marquée.

layout title [titre]

Change ou affiche le titre de la disposition actuelle. Une chaîne de caractères donnée sera utilisée pour nommer la disposition. Sans aucune option, le titre et le numéro actuels sont affichés sur la ligne de message.

layout number [n]

Change ou affiche le numéro de la disposition actuelle. Un entier donné sera utilisé pour numéroter la disposition. Sans aucune option, le numéro et le titre actuels sont affichés sur la ligne de message.

layout attach [titre|:last]

Change ou affiche la disposition à laquelle se rattacher. Par défaut, il s'agit de :last, ce qui indique à screen de se rattacher à la dernière disposition utilisée juste avant le détachement. En fournissant un titre, vous pouvez demander à screen de se rattacher à une disposition particulière, quelle que soit celle utilisée au moment du détachement. Sans aucune option, la disposition à laquelle se rattacher sera affichée sur la ligne de message.

layout save [n|titre]

Mémorise l'arrangement actuel des régions. Lorsqu'elle est utilisée, screen mémorisera l'arrangement des régions divisées verticalement et horizontalement. Cet arrangement est restauré lorsqu'une session screen est rattachée ou basculée depuis une autre disposition. Si la session se termine ou si le processus screen meurt, les arrangements de disposition sont perdus. La commande layout dump devrait aider dans cette situation. Si un numéro ou un titre est fourni, screen mémorisera l'arrangement de cette disposition particulière. Sans aucune option, screen mémorisera la disposition actuelle.

La sauvegarde de vos régions peut être effectuée automatiquement en utilisant la commande layout autosave.

layout autosave [ on | off]

Change ou affiche le statut de la sauvegarde automatique des dispositions. Par défaut, il est sur on, ce qui signifie que lorsque screen est détaché ou basculé vers une autre disposition, l'arrangement des régions et des fenêtres sera mémorisé au moment du changement et restauré au retour. Si l'autosave est réglé sur off, cet arrangement ne sera restauré qu'à la dernière sauvegarde manuelle, en utilisant layout save, ou à la création initiale de la disposition, à une seule région avec une seule fenêtre. Sans on ou off, le statut actuel est affiché sur la ligne de message.

layout dump [nom_fichier]

Écrit dans un fichier l'ordre des divisions effectuées dans la disposition actuelle. Ceci est utile pour recréer l'ordre de vos régions utilisées dans votre disposition actuelle. Seule la disposition actuelle est enregistrée. Bien que l'ordre des régions soit enregistré, la taille de ces régions et les fenêtres qui correspondent à ces régions ne le sont pas. Si aucun nom de fichier n'est spécifié, le nom par défaut est layout-dump, sauvegardé dans le répertoire où le processus screen a été démarré. Si le fichier existe déjà, layout dump ajoutera à ce fichier. Par exemple :

C-a : layout dump /home/user/.screenrc

sauvegardera ou ajoutera la disposition au fichier .screenrc de l'utilisateur.

license

Affiche la page de clause de non-responsabilité. Ceci est fait chaque fois que screen est démarré sans options, ce qui devrait être assez fréquent. Voir également la commande startup_message.

lockscreen

Verrouille cet écran. Appelle un programme de verrouillage d'écran. Screen n'accepte aucune touche de commande tant que ce programme ne se termine pas. Pendant ce temps, les processus dans les fenêtres peuvent continuer, car les fenêtres sont dans un état 'détaché'. Le programme de verrouillage d'écran peut être modifié via la variable d'environnement $LOCKPRG (qui doit être définie dans le shell à partir duquel screen est démarré) et est exécuté avec l'uid et le gid de l'utilisateur.

Attention : Lorsque vous laissez d'autres shells déverrouillés et que vous n'avez pas de mot de passe défini sur screen, le verrouillage est caduc : On pourrait facilement se rattacher depuis un shell déverrouillé. Cette fonctionnalité devrait plutôt s'appeler `lockterminal'.

log [ on | off ]

Démarre/arrête l'écriture de la sortie de la fenêtre actuelle dans un fichier screenlog.n dans le répertoire par défaut de la fenêtre, où n est le numéro de la fenêtre actuelle. Ce nom de fichier peut être modifié avec la commande `logfile'. Si aucun paramètre n'est donné, l'état de la journalisation est basculé. Le journal de session est ajouté au contenu précédent du fichier s'il existe déjà. Le contenu actuel et le contenu de l'historique de défilement ne sont pas inclus dans le journal de session. Par défaut, il est `off'.

logfile nom_fichier
logfile flush secs

Définit le nom que prendront les fichiers journaux. Par défaut, c'est screenlog.%n. La deuxième forme change le nombre de secondes que screen attendra avant de vider le tampon du fichier journal vers le système de fichiers. La valeur par défaut est de 10 secondes.

login [ on | off ]

Ajoute ou supprime l'entrée dans le fichier de base de données utmp pour la fenêtre actuelle. Ceci contrôle si la fenêtre est `connectée'. Quand aucun paramètre n'est donné, l'état de connexion de la fenêtre est basculé. En plus de ce basculement, il est pratique d'avoir une touche `log in' et une touche `log out'. Par exemple, `bind I login on' et `bind O login off' mapperont ces touches à C-a I et C-a O. Le réglage par défaut (dans config.h.in) devrait être on pour un screen qui tourne sous suid-root. Utilisez la commande deflogin pour changer l'état de connexion par défaut pour les nouvelles fenêtres. Les deux commandes ne sont présentes que si screen a été compilé avec le support utmp.

logtstamp [on|off]
logtstamp after [secs]
logtstamp string
[string]

Cette commande contrôle le mécanisme d'horodatage des fichiers journaux de screen. Si les horodatages sont activés, screen ajoute une chaîne contenant l'heure actuelle au fichier journal après deux minutes d'inactivité. Lorsque la sortie reprend et que plus de deux minutes se sont écoulées, un second horodatage est ajouté pour documenter le redémarrage de la sortie. Vous pouvez changer ce délai avec la deuxième forme de la commande. La troisième forme est utilisée pour personnaliser la chaîne d'horodatage (`-- %n:%t -- time-stamp -- %M/%d/%y %c:%s --\n' par défaut).

mapdefault

Indique à screen que le prochain caractère d'entrée ne doit être recherché que dans la table bindkey par défaut. Voir aussi bindkey.

mapnotnext

Comme mapdefault, mais ne cherche même pas dans la table bindkey par défaut.

maptimeout [timeout]

Définit le minuteur inter-caractères pour la détection de séquences d'entrée à un délai d'attente de timeout ms. Le délai d'attente par défaut est de 300 ms. Maptimeout sans argument affiche le réglage actuel. Voir aussi bindkey.

markkeys string

Ce

s est une méthode pour modifier le mappage de touches utilisé pour copier/historique mode. La chaîne est composée de paires ancien_caractère=nouveau_caractère séparées par `:'. Exemple : La chaîne B=^B:F=^F modifiera les touches `C-b' et `C-f' pour la liaison de style vi (défilement vers le haut/bas pour remplir la page). Cela se trouve être la liaison par défaut pour `B' et `F'. La commande markkeys h=^B:l=^F:$=^E définirait le mode pour une liaison de style emacs. Si votre terminal envoie des caractères qui vous font quitter le mode de copie, alors cette commande peut aider en associant ces caractères pour qu'ils ne fassent rien. Le caractère sans opération est `@' et est utilisé comme suit : markkeys @=L=H si vous ne souhaitez plus utiliser les commandes `H' ou `L'. Comme montré dans cet exemple, plusieurs touches peuvent être assignées à une fonction dans une seule instruction.

meta

Insère le caractère de commande (C-a) dans le flux d'entrée de la fenêtre actuelle.

monitor [ on | off ]

Active ou désactive la surveillance des activités des fenêtres. Lorsque la surveillance est activée et qu'une fenêtre affectée est basculée en arrière-plan, vous recevrez un message de notification d'activité dans la ligne de statut au premier signe de sortie et la fenêtre sera également marquée d'un `@' dans l'affichage de l'état des fenêtres. La surveillance est initialement désactivée pour toutes les fenêtres.

mousetrack [ on | off ]

Cette commande détermine si screen surveille les clics de souris. Lorsque cette commande est activée, les régions qui ont été divisées de différentes manières peuvent être sélectionnées en les pointant avec une souris et en cliquant dessus avec le bouton gauche. Sans spécifier on ou off, l'état actuel est affiché. L'état par défaut est déterminé par la commande defmousetrack.

msgminwait sec

Définit le temps pendant lequel screen retarde un nouveau message lorsqu'un message est actuellement affiché. La valeur par défaut est de 1 seconde.

msgwait sec

Définit le temps pendant lequel un message est affiché si screen n'est pas dérangé par une autre activité. La valeur par défaut est de 5 secondes.

multiuser [ on | off ]

Bascule entre le mode utilisateur unique et le mode multi-utilisateurs. Le fonctionnement standard de screen est en mode utilisateur unique. En mode multi-utilisateurs, les commandes `acladd', `aclchg', `aclgrp' et `acldel' peuvent être utilisées pour activer (et désactiver) l'accès d'autres utilisateurs à cette session screen.

next

Passe à la fenêtre suivante. Cette commande peut être utilisée de manière répétée pour parcourir la liste des fenêtres.

nonblock [ on | off | numsecs ]

Indique à screen comment gérer les interfaces utilisateur (affichages) qui cessent d'accepter la sortie. Cela peut se produire si un utilisateur appuie sur ^S ou si une connexion TCP/modem est coupée mais qu'aucun débranchement n'est reçu. Si nonblock est off (ce qui est la valeur par défaut), screen attend que l'affichage redémarre pour accepter la sortie. Si nonblock est on, screen attend que le délai d'attente soit atteint (on est traité comme 1s). Si l'affichage ne reçoit toujours aucun caractère, screen le considérera comme bloqué et cessera de lui envoyer des caractères. Si à un moment donné il recommence à accepter des caractères, screen débloquera l'affichage et réaffichera le contenu mis à jour de la fenêtre.

number [[+|-]n]

Change le numéro de la fenêtre actuelle. Si le numéro n donné est déjà utilisé par une autre fenêtre, les deux fenêtres échangent leurs numéros. Si aucun argument n'est spécifié, le numéro (et le titre) de la fenêtre actuelle est affiché. L'utilisation de `+' ou `-' changera le numéro de la fenêtre du montant relatif spécifié.

obuflimit [limit]

Si le tampon de sortie contient plus d'octets que la limite spécifiée, aucune donnée supplémentaire ne sera lue des fenêtres. La valeur par défaut est 256. Si vous avez un affichage rapide (comme xterm), vous pouvez le définir à une valeur plus élevée. Si aucun argument n'est spécifié, le réglage actuel est affiché.

only

Tue toutes les régions sauf la région actuelle.

other

Passe à la fenêtre affichée précédemment. Si cette fenêtre n'existe plus, other a le même effet que next.

partial [ on | off ]

Définit si l'affichage doit être rafraîchi (comme avec redisplay) après avoir basculé vers la fenêtre actuelle. Cette commande n'affecte que la fenêtre actuelle. Pour affecter immédiatement toutes les fenêtres, utilisez la commande allpartial. La valeur par défaut est `off', bien sûr. Cette valeur par défaut est fixe, car il n'existe actuellement pas de commande defpartial.

password [crypted_pw]

Insère un mot de passe crypté dans votre fichier .screenrc et screen vous le demandera chaque fois que quelqu'un tentera de reprendre une session détachée. Ceci est utile si vous avez des programmes privilégiés exécutés sous screen et que vous souhaitez protéger votre session contre les tentatives de reconnexion par un autre utilisateur se faisant passer pour votre uid (c'est-à-dire tout superutilisateur). Si aucun mot de passe crypté n'est spécifié, screen vous demandera deux fois de taper un mot de passe et placera son cryptage dans le tampon de collage. La valeur par défaut est `none', ce qui désactive la vérification du mot de passe.

paste [registres [reg_dest]]

Écrit le contenu (concaténé) des registres spécifiés dans la file d'attente d'entrée de la fenêtre actuelle. Le registre '.' est traité comme le tampon de collage. Si aucun paramètre n'est donné, l'utilisateur est invité à entrer un seul registre à coller. Le tampon de collage peut être rempli avec les commandes copy, history et readbuf. D'autres registres peuvent être remplis avec les commandes register, readreg et paste. Si paste est appelé avec un deuxième argument, le contenu des registres spécifiés est collé dans le registre de destination nommé plutôt que dans la fenêtre. Si '.' est utilisé comme deuxième argument, le tampon de collage de l'affichage est la destination. Notez que paste utilise une grande variété de ressources : lorsqu'un deuxième argument est spécifié, aucune fenêtre actuelle n'est nécessaire. Lorsque la spécification de la source ne contient que des registres (pas le tampon de collage), il n'est pas nécessaire qu'il y ait un affichage actuel (terminal attaché), car les registres sont une ressource globale. Le tampon de collage existe une fois pour chaque utilisateur.

pastefont [ on | off ]

Indique à screen d'inclure les informations de police dans le tampon de collage. Par défaut, ce n'est pas le cas. Cette commande est particulièrement utile pour les polices multi-caractères comme le kanji.

pow_break

Rouvre la ligne de terminal de la fenêtre et envoie une condition de rupture. Voir `break'.

pow_detach

Détachement forcé. Principalement la même chose que detach, mais envoie également un signal HANGUP au processus parent de screen. ATTENTION : Cela entraînera une déconnexion si screen a été démarré depuis votre shell de connexion.

pow_detach_msg [message]

Le message spécifié ici est affiché chaque fois qu'un `Power detach' a été effectué. Il peut être utilisé comme remplacement d'un message de déconnexion ou pour réinitialiser le débit en bauds, etc. Sans paramètre, le message actuel est affiché.

prev

Passe à la fenêtre avec le numéro inférieur suivant. Cette commande peut être utilisée de manière répétée pour parcourir la liste des fenêtres.

printcmd [cmd]

Si cmd n'est pas une chaîne vide, screen n'utilisera pas les capacités du terminal po/pf s'il détecte une séquence d'impression ansi ESC [ 5 i, mais redirigera la sortie vers cmd. Il devrait normalement s'agir d'une commande comme lpr ou printcmd sans commande affiche le réglage actuel. La séquence ansi ESC [ 4 i termine l'impression et ferme le tuyau.

Attention : Soyez prudent avec cette commande ! Si d'autres utilisateurs ont un accès en écriture à votre terminal, ils pourront déclencher des commandes d'impression.

process [key]

Insère le contenu du registre spécifié dans la file d'attente d'entrée de screen. Si aucun argument n'est donné, vous êtes invité à entrer un nom de registre. Le texte est analysé comme s'il avait été tapé depuis le clavier de l'utilisateur. Cette commande peut être utilisée pour lier plusieurs actions à une seule touche.

quit

Tue toutes les fenêtres et termine screen. Notez que sur les terminaux de type VT100, les touches C-4 et C-\ sont identiques. Cela rend les liaisons par défaut dangereuses : faites attention à ne pas taper C-a C-4 en sélectionnant la fenêtre n° 4. Utilisez la commande de liaison vide (comme dans bind '^\') pour supprimer une liaison de touche.

readbuf [encoding] [filename]

Lit le contenu de

dans le tampon de collage. Vous pouvez indiquer à screen l'encodage du fichier via l'option -e. Si aucun fichier n'est spécifié, le nom de fichier d'échange de screen est utilisé. Voir également la commande bufferfile.

readreg [encodage] [registre [nomdefichier]]

Fait l'une des deux choses, en fonction du nombre d'arguments : avec zéro ou un argument, il duplique le contenu du tampon de collage dans le registre spécifié ou entré à l'invite. Avec deux arguments, il lit le contenu du fichier nommé dans le registre, tout comme readbuf lit le fichier d'échange de screen dans le tampon de collage. Vous pouvez indiquer à screen l'encodage du fichier via l'option -e. L'exemple suivant collera le fichier de mots de passe du système dans la fenêtre screen (en utilisant le registre p, où une copie reste) :

C-a : readreg p /etc/passwd
C-a : paste p
redisplay

Redessine la fenêtre actuelle. Nécessaire pour obtenir un redessin complet en mode de redessin partiel.

register [-eencodage]chaîne-clé

Enregistre la chaîne spécifiée dans le registre clé. L'encodage de la chaîne peut être spécifié via l'option -e. Voir également la commande paste.

remove

Supprime la région actuelle. C'est une opération nulle s'il n'y a qu'une seule région.

removebuf

Supprime le lien du fichier d'échange de screen utilisé par les commandes writebuf et readbuf.

rendition [ bell | monitor | silence | so ] attr [ couleur ]

Change la manière dont screen rend les titres des fenêtres qui ont les indicateurs monitor ou bell définis dans caption ou hardstatus ou windowlist. Voir le chapitre STRING ESCAPES pour la syntaxe des modificateurs. La valeur par défaut pour monitor est actuellement =b (gras, couleurs actives), pour bell =ub (souligné, gras et couleurs actives), et =u pour silence.

reset

Réinitialise le terminal virtuel à ses valeurs de mise sous tension. Utile lorsque des paramètres étranges (comme les régions de défilement ou le jeu de caractères graphiques) sont laissés par une application.

resize
[-h|-v|-b|-l|-p] [[+|-] n[%] |=|max|min|_|0]

Redimensionne la région actuelle. L'espace sera retiré ou ajouté aux régions environnantes en fonction de l'ordre des divisions. Les options disponibles pour le redimensionnement sont `-h' (horizontal), `-v' (vertical), `-b' (les deux), `-l' (local à la couche) et `-p' (perpendiculaire). Les redimensionnements horizontaux ajouteront ou retireront de la largeur à une région, les verticaux ajouteront ou retireront de la hauteur, et les deux ajouteront ou retireront de la taille dans les deux dimensions. Local et perpendiculaire sont similaires à horizontal et vertical, mais ils tiennent compte de la manière dont une région a été divisée. Si la dernière division d'une région était horizontale, un redimensionnement local fonctionnera comme un redimensionnement vertical. Si la dernière division d'une région était verticale, un redimensionnement local fonctionnera comme un redimensionnement horizontal. Les redimensionnements perpendiculaires fonctionnent à l'inverse des redimensionnements locaux. Si aucune option n'est spécifiée, local est la valeur par défaut.

La quantité de lignes à ajouter ou à retirer peut être exprimée de plusieurs manières. En spécifiant un nombre n par lui-même, la région sera redimensionnée de ce montant absolu. Vous pouvez spécifier un montant relatif en préfixant un plus `+' ou un moins `-' au montant, comme ajouter +n lignes ou retirer -n lignes. Le redimensionnement peut également être exprimé en pourcentage absolu ou relatif en ajoutant un signe de pourcentage `%'. L'utilisation de zéro `0' est un synonyme de `min' et l'utilisation d'un underscore `_' est un synonyme de `max'.

Voici quelques exemples :

resize +N
augmente la région actuelle de N
resize -N
diminue la région actuelle de N
resize N
définit la région actuelle à N
resize 20%
définit la région actuelle à 20% de sa taille d'origine
resize +20%

screen [-opts] [n] [cmd [args]|//group]

Établit une nouvelle fenêtre. Les options de contrôle de flux (-f, -fn et -fa), l'option de titre (alias) (-t), les options de connexion (-l et -ln), l'option de type de terminal (-T <term>), l'indicateur d'activité complète (-a) et l'option de défilement (-h <num>) peuvent être spécifiées avec chaque commande. L'option (-M) active la surveillance pour cette fenêtre. L'option (-L) active l'enregistrement des sorties pour cette fenêtre. Si un nombre optionnel n dans la plage 0..MAXWIN-1 est donné, le numéro de fenêtre n est attribué à la fenêtre nouvellement créée (ou, si ce numéro est déjà utilisé, le numéro disponible suivant). Si une commande est spécifiée après screen, cette commande (avec les arguments donnés) est démarrée dans la fenêtre ; sinon, un shell est créé. Si //group est fourni, une fenêtre de type conteneur est créée dans laquelle d'autres fenêtres peuvent être créées à l'intérieur.

Ainsi, si votre .screenrc contient les lignes

# exemple pour .screenrc :
screen 1
screen -fn -t foobar -L 2 telnet foobar

screen crée une fenêtre shell (dans la fenêtre #1) et une fenêtre avec une connexion TELNET à la machine foobar (sans contrôle de flux utilisant le titre foobar dans la fenêtre #2) et écrira un fichier journal (screenlog.2) de la session telnet. Notez que, contrairement aux versions précédentes de screen, aucune fenêtre par défaut supplémentaire n'est créée lorsque les commandes screen sont incluses dans votre fichier .screenrc. Une fois l'initialisation terminée, screen bascule sur la dernière fenêtre spécifiée dans votre fichier .screenrc ou, sinon, ouvre une fenêtre par défaut #0.

Screen intègre certaines fonctionnalités de cu et telnet. Voir également le chapitre TYPES DE FENÊTRES.

termcap term modifications terminales[modifications fenêtres]
terminfo term modifications terminales[modifications fenêtres]
termcapinfo term modifications terminales[modifications fenêtres]

Utilisez cette commande pour modifier l'entrée termcap de votre terminal sans passer par toutes les difficultés liées à la création d'une entrée termcap personnalisée. De plus, vous pouvez éventuellement personnaliser le termcap généré pour les fenêtres. Vous devez placer ces commandes dans l'un des fichiers de démarrage de screenrc, car elles sont dénuées de sens une fois l'émulateur de terminal démarré.

Si votre système utilise la base de données terminfo plutôt que termcap, screen comprendra la commande `terminfo', qui a les mêmes effets que la commande `termcap'. Deux commandes distinctes sont fournies, car il existe de subtiles différences syntaxiques, par exemple, lors de l'interpolation de paramètres (utilisation de `%'). Notez que les noms de capacités de termcap doivent être utilisés avec la commande `terminfo'.

Dans de nombreux cas, où les arguments sont valides en syntaxe terminfo et termcap, vous pouvez utiliser la commande `termcapinfo', qui n'est qu'un raccourci pour une paire de commandes `termcap' et `terminfo' avec des arguments identiques.

Le premier argument spécifie quels terminaux doivent être affectés par cette définition. Vous pouvez spécifier plusieurs noms de terminaux en les séparant par des `|'. Utilisez `*' pour correspondre à tous les terminaux et `vt*' pour correspondre à tous les terminaux commençant par vt.

Chaque argument tweak contient une ou plusieurs définitions termcap (séparées par des `:`) à insérer au début de l'entrée termcap appropriée, l'améliorant ou remplaçant les valeurs existantes. Le premier tweak modifie le termcap de votre terminal et contient les définitions que votre terminal utilise pour effectuer certaines fonctions. Spécifiez une chaîne nulle pour laisser cela inchangé (par exemple, `'). Le second tweak (facultatif) modifie tous les termcaps des fenêtres et doit contenir des définitions que screen comprend (voir la section TERMINAL VIRTUEL). Les définitions de terme sont séparées par des points-virgules.

Quelques exemples:

termcap xterm* LP:hs@

Informe screen que tous les terminaux commençant par `xterm' ont des marges automatiques fermes qui permettent de mettre à jour la dernière position de l'écran (LP), mais qu'ils n'ont pas vraiment de ligne de statut (pas de 'hs' - ajoutez `@' pour désactiver les entrées). Notez que nous supposons `LP' pour tous les noms de terminaux qui commencent par vt, mais seulement si vous ne spécifiez pas de commande termcap pour ce terminal.

termcap vt*  LP

termcap vt102|vt220 Z0=\E[?3h:Z1=\E[?3l

Spécifie la capacité `LP' à marges fermes pour tous les terminaux commençant par `vt', et la deuxième ligne ajoutera également les séquences d'échappement pour passer en mode 132 caractères par ligne (Z0) et en revenir (Z1) s'il s'agit d'un VT102 ou VT220. (Vous devez spécifier Z0 et Z1 dans votre termcap pour utiliser les commandes de changement de largeur.)

termcap vt100 "" l0=PF1:l1=PF2:l2=PF3:l3=PF4

Ceci laisse votre termcap vt100 intact et ajoute les étiquettes des touches de fonction à l'entrée termcap de chaque fenêtre.

termcap h19|z19 am@:im=\E@:ei=\EO dc=\E[P

Prend un termcap h19 ou z19 et désactive les marges automatiques (am@) et active les capacités d'insertion (im) et de fin d'insertion (ei) (le `@' dans la chaîne `im' est après le `=`, il fait donc partie de la chaîne). Le fait d'avoir les définitions `im' et `ei' dans le termcap de votre terminal fera que screen annoncera automatiquement la capacité d'insertion de caractères dans le termcap de chaque fenêtre. Chaque fenêtre recevra également la capacité de suppression de caractères (dc) ajoutée à son termcap, que screen traduira en une mise à jour de ligne pour le terminal (nous prétendons qu'il ne prend pas en charge la suppression de caractères).

Si vous souhaitez spécifier entièrement l'entrée termcap de chaque fenêtre, vous devez plutôt définir la variable $SCREENCAP avant d'exécuter screen. Voir la discussion sur le TERMINAL VIRTUEL dans ce manuel, et le manuel termcap(5)

page pour plus d'informations sur les définitions termcap.

OPTIONS

writelock [ on | off | auto ]

May be able to write to the same window at once. Per default, writelock is in auto mode and grants exclusive input permission to the user who is the first to switch to the particular window. When he leaves the window, other users may obtain the writelock (automatically). The writelock of the current window is disabled by the command writelock off. zmodem [ off | auto | catch | pass ]
zmodem sendcmd [string]
zmodem recvcmd [string]

Define zmodem support for screen. Screen understands two different modes when it detects a zmodem request: pass and catch. If the mode is set to pass, screen will relay all data to the attacher until the end of the transmission is reached. In catch mode screen acts as a zmodem endpoint and starts the corresponding rz/sz commands. If the mode is set to auto, screen will use catch if the window is a tty (e.g. a serial line), otherwise it will use pass.

You can define the templates screen uses in catch mode via the second and the third form.

Note also that this is an experimental feature.

zombie [keys[onerror]]

Per default screen windows are removed from the window list as soon as the windows process (e.g. shell) exits. When a string of two keys is specified to the zombie command, `dead' windows will remain in the list. The kill command may be used to remove such a window. Pressing the first key in the dead window has the same effect. When pressing the second key, screen will attempt to resurrect the window. The process that was initially running in the window will be launched again. Calling zombie without parameters will clear the zombie setting, thus making windows disappear when their process exits.

As the zombie-setting is manipulated globally for all windows, this command should probably be called defzombie, but it isn't.

Optionally you can put the word onerror after the keys. This will cause screen to monitor exit status of the process running in the window. If it exits normally ('0'), the window disappears. Any other exit value causes the window to become a zombie.

zombie_timeout[seconds]

Per default screen windows are removed from the window list as soon as the windows process (e.g. shell) exits. If zombie keys are defined (compare with above zombie command), it is possible to also set a timeout when screen tries to automatically reconnect a dead screen window.

THE MESSAGE LINE

Screen displays informational messages and other diagnostics in a message line. While this line is distributed to appear at the bottom of the screen, it can be defined to appear at the top of the screen during compilation. If your terminal has a status line defined in its termcap, screen will use this for displaying its messages, otherwise a line of the current screen will be temporarily overwritten and output will be momentarily interrupted. The message line is automatically removed after a few seconds delay, but it can also be removed early (on terminals without a status line) by beginning to type.

The message line facility can be used by an application running in the current window by means of the ANSI Privacy message control sequence. For instance, from within the shell, try something like:

echo '<esc>^Hello world from window '$WINDOW'<esc>\\'

where '<esc>' is an escape, '^' is a literal up-arrow, and '\\' turns into a single backslash.

WINDOW TYPES

Screen provides three different window types. New windows are created with screen's screen command (see also the entry in chapter CUSTOMIZATION). The first parameter to the screen command defines which type of window is created. The different window types are all special cases of the normal type. They have been added in order to allow screen to be used efficiently as a console multiplexer with 100 or more windows.

  • The normal window contains a shell (default, if no parameter is given) or any other system command that could be executed from a shell (e.g. slogin, etc...)
  • If a tty (character special device) name (e.g. /dev/ttya) is specified as the first parameter, then the window is directly connected to this device. This window type is similar to screen cu -l /dev/ttya. Read and write access is required on the device node, an exclusive open is attempted on the node to mark the connection line as busy. An optional parameter is allowed consisting of a comma separated list of flags in the notation used by stty(1):
<baud_rate>
Usually 300, 1200, 9600 or 19200. This affects transmission as well as receive speed.
cs8 or cs7
Specify the transmission of eight (or seven) bits per byte.
cstopb or -cstopb
Specify two stop bits per character (one with '-')
parenb or -parenb
Generate parity bit in output and expect parity bit in input
parodd or -parodd
Set odd parity (or even parity with '-')
ixon or -ixon
Enables (or disables) software flow-control (CTRL-S/CTRL-Q) for sending data.
ixoff or -ixoff
Enables (or disables) software flow-control for receiving data.
istrip or -istrip
Clear (or keep) the eight bit in each received byte.

You may want to specify as many of these options as applicable. Unspecified options cause the terminal driver to make up the parameter values of the connection. These values are system dependent and may be in defaults or values saved from a previous connection.

For tty windows, the info command shows some of the modem control lines in the status line. These may include 'RTS', 'CTS', 'DTR', 'DSR', 'CD' and more. This depends on the available ioctl()'s and system header files as well as the on the physical capabilities of the serial board. Signals that are logical low (inactive) have their name preceded by an exclamation mark (!), otherwise the signal is logical high (active). Signals not supported by the hardware but available to the ioctl() interface are usually shown low.

When the CLOCAL status bit is true, the whole set of modem signals is placed inside curly braces ({ and }). When the CRTSCTS or TIOCSOFTCAR bit is set, the signals 'CTS' or 'CD' are shown in parenthesis, respectively.

For tty windows, the command break causes the Data transmission line (TxD) to go low for a specified period of time. This is expected to be interpreted as break signal on the other side. No data is sent and no modem control line is changed when a break is issued.

CONTRÔLE DE FLUX

Chaque fenêtre a un réglage de contrôle de flux qui détermine comment screen gère les caractères XON et XOFF (et éventuellement le caractère d'interruption). Lorsque le contrôle de flux est désactivé, screen ignore les caractères XON et XOFF, ce qui permet à l'utilisateur de les envoyer au programme actuel simplement en les tapant (utile pour l'éditeur emacs, par exemple). Le compromis est que la mise en pause de la sortie d'un programme normal en réponse à un XOFF prendra plus de temps. Lorsque le contrôle de flux est activé, les caractères XON et XOFF sont utilisés pour arrêter immédiatement la sortie de la fenêtre actuelle. Vous pouvez toujours envoyer ces caractères au programme actuel, mais vous devez utiliser les commandes screen à deux caractères appropriées (typiquement C-a q (xon) et C-a s (xoff)). Les commandes xon/xoff sont également utiles pour taper C-s et C-q en passant par un terminal qui intercepte ces caractères.

Chaque fenêtre a une valeur initiale de contrôle de flux définie avec l'option -f ou la commande defflow dans .screenrc. Par défaut, les fenêtres sont réglées sur le changement automatique de flux. Il peut ensuite être basculé entre les trois états 'fixe activé', 'fixe désactivé' et 'automatique' de manière interactive avec la commande flow liée à "C-a f".

Le mode de commutation automatique de flux gère le contrôle de flux en utilisant le mode TIOCPKT (comme rlogin le fait). Si le pilote tty ne prend pas en charge TIOCPKT, screen essaie de déterminer le bon mode en fonction du réglage actuel du pavé d'application - lorsqu'il est activé, le contrôle de flux est désactivé et vice versa. Bien sûr, vous pouvez toujours manipuler le contrôle de flux manuellement si nécessaire.

Si vous travaillez avec le contrôle de flux activé et que vous constatez que la pression sur la touche d'interruption (généralement C-c) n'interrompt pas l'affichage avant que 6 à 8 lignes supplémentaires ne défilent, essayez d'exécuter screen avec l'option d'interruption (ajoutez l'indicateur d'interruption à la commande flow dans votre .screenrc, ou utilisez l'option en ligne de commande -i). Cela provoque la purge de la sortie que screen a accumulée du programme interrompu. Un inconvénient est que la mémoire du terminal virtuel contient la version non purgée de la sortie, ce qui, dans de rares cas, peut entraîner de légères inexactitudes dans la sortie. Par exemple, si vous changez d'écran et revenez, ou mettez à jour l'écran avec C-a l, vous verrez la version de la sortie que vous auriez obtenue sans l'interruption activée. De plus, vous pourriez avoir besoin de désactiver le contrôle de flux (ou d'utiliser le mode auto-flux pour le désactiver automatiquement) lorsque vous exécutez un programme qui s'attend à ce que vous tapiez le caractère d'interruption en entrée, car il est possible d'interrompre la sortie du terminal virtuel vers votre terminal physique lorsque le contrôle de flux est activé. Si cela se produit, un simple rafraîchissement de l'écran avec C-a l en rétablira l'état. Essayez chaque mode et utilisez celui qui vous convient le mieux.

TITRES (nommer les fenêtres)

Vous pouvez personnaliser le nom de chaque fenêtre dans l'affichage des fenêtres (vu avec la commande windows (C-a w)) en le définissant avec l'une des commandes de titre. Normalement, le nom affiché est le nom réel de la commande du programme créé dans la fenêtre. Cependant, il est parfois utile de distinguer divers programmes portant le même nom ou de changer le nom à la volée pour refléter l'état actuel de la fenêtre.

Le nom par défaut pour toutes les fenêtres shell peut être défini avec la commande shelltitle dans le fichier .screenrc, tandis que toutes les autres fenêtres sont créées avec une commande screen et peuvent donc avoir leur nom défini avec l'option -t. Interactivement, il existe la séquence d'échappement de chaîne de titre (<esc>knom<esc>\) et la commande de titre (C-a A). La première peut être émise par une application pour contrôler le nom de la fenêtre sous contrôle logiciel, et la seconde demandera un nom lorsqu'elle sera tapée. Vous pouvez également lier des noms prédéfinis à des touches avec la commande title pour définir rapidement des choses sans demande. La modification du titre par cette séquence d'échappement peut être contrôlée par les commandes defdynamictitle et dynamictitle.

TITRE DE SHELL HEURISTIQUE

Enfin, screen possède une heuristique spécifique au shell qui est activée en définissant le nom de la fenêtre sur search|name et en arrangeant pour qu'une séquence d'échappement de titre nulle soit produite dans votre invite. La partie search spécifie une chaîne de recherche de fin d'invite, tandis que la partie name spécifie le nom par défaut du shell pour la fenêtre. Si le name se termine par un `:' screen ajoutera ce qu'il croit être la commande en cours d'exécution dans la fenêtre à la fin du nom du shell de la fenêtre (par exemple, name:cmd). Sinon, le nom de la commande en cours supplante le nom du shell pendant son exécution.

Voici comment cela fonctionne : vous devez modifier votre invite de shell pour produire une séquence d'échappement de titre nulle (<esc>k<esc>\) dans le cadre de votre invite. La dernière partie de votre invite doit être identique à la chaîne que vous avez spécifiée pour la partie search du titre. Une fois cela configuré, screen utilisera la séquence d'échappement de titre pour effacer le nom de commande précédent et se préparer pour la commande suivante. Ensuite, lorsqu'une nouvelle ligne est reçue du shell, une recherche est effectuée pour trouver la fin de l'invite. Si elle est trouvée, il saisira le premier mot après la chaîne correspondante et l'utilisera comme nom de commande. Si le nom de commande commence par '!', '%' ou '^', screen utilisera le premier mot de la ligne suivante (s'il est trouvé) de préférence au nom juste trouvé. Cela aide les utilisateurs de csh à obtenir de meilleurs noms de commande lorsqu'ils utilisent le contrôle de tâches ou les commandes de rappel d'historique.

Voici quelques exemples de .screenrc :

screen -t top 2 nice top

L'ajout de cette ligne à votre .screenrc démarrerait une version "nice"-d de la commande top dans la fenêtre 2 nommée top plutôt que nice.

shelltitle '> |csh'
screen 1

Ces commandes démarreraient un shell avec le shelltitle donné. Le titre spécifié est un auto-titre qui s'attendrait à ce que l'invite et la commande tapée ressemblent à ceci :

/usr/joe/src/dir> trn

(il recherche après le '> ' le nom de la commande). L'état de la fenêtre afficherait le nom trn pendant l'exécution de la commande, et reviendrait à csh à son achèvement.

bind R screen -t '% |root:' su

Avoir cette commande dans votre .screenrc lierait la séquence de touches C-a R à la commande su et lui donnerait un nom d'auto-titre de root:. Pour que cet auto-titre fonctionne, l'écran pourrait ressembler à ceci :

% !em
emacs file.c

Ici, l'utilisateur a tapé la commande d'historique csh !em qui a exécuté la commande emacs précédemment entrée. L'état de la fenêtre afficherait root:emacs pendant l'exécution de la commande, et reviendrait simplement à root: à son achèvement.

Avoir cette commande dans votre .screenrc lierait la séquence de touches C-a R à la commande su et lui donnerait un nom d'auto-titre de root:. Pour que cet auto-titre fonctionne, l'écran pourrait ressembler à ceci :

bind o title
bind E title ""
bind u title (unknown)

La première liaison n'a pas d'arguments, elle vous demandera donc un titre lorsque vous taperez C-a o. La deuxième liaison effacera le réglage actuel d'un auto-titre (C-a E). La troisième liaison définira le titre de la fenêtre actuelle sur (unknown) (C-a u).

Une chose à garder à l'esprit lorsque vous ajoutez une séquence d'échappement de titre nulle à votre invite est que certains shells (comme csh) comptent tous les caractères non-contrôle comme faisant partie de la longueur de l'invite. Si ces caractères invisibles ne sont pas un multiple de 8, alors un retour arrière sur une tabulation entraînera un affichage incorrect. Une façon de contourner cela est d'utiliser une invite comme celle-ci :

set prompt='^[[0000m^[k^[\% '

La séquence d'échappement <esc>[0000m normalise non seulement les attributs des caractères, mais tous les zéros arrondissent la longueur des caractères invisibles à 8. Les utilisateurs de Bash voudront probablement afficher la séquence d'échappement dans PROMPT_COMMAND :

PROMPT_COMMAND='printf "\033k\033\134"'

(J'ai utilisé \134 pour produire un `\' en raison d'un bug dans bash v1.04).

LE TERMINAL VIRTUEL

Chaque fenêtre dans une session screen émule un terminal VT100, avec quelques fonctions supplémentaires ajoutées. L'émulateur VT100 est codé en dur, aucun autre type de terminal ne peut être émulé.

Habituellement, screen essaie d'émuler autant que possible la norme VT100/ANSI. Mais si votre terminal manque de certaines capacités, l'émulation peut ne pas être complète. Dans ces cas, screen doit dire aux applications que certaines fonctionnalités sont manquantes. Ce n'est pas un problème sur les machines utilisant termcap, car screen peut utiliser la variable $TERMCAP pour personnaliser le termcap standard de screen.

Mais si vous faites un rlogin sur une autre machine ou si votre machine ne prend en charge que terminfo, cette méthode échoue. Pour cette raison, screen offre un moyen de gérer ces cas. Voici comment cela fonctionne :

Lorsque screen essaie de déterminer un nom de terminal pour lui-même, il recherche d'abord une entrée nommée screen.<term>, où <term> est le contenu de votre variable $TERM. Si aucune entrée de ce type n'existe, screen essaie screen (ou screen-w si le terminal est large (132 colonnes ou plus)). Si même cette entrée ne peut pas être trouvée, vt100 est utilisé comme substitut.

L'idée est que si vous avez un terminal qui ne prend pas en charge une fonctionnalité importante (par exemple, effacer un caractère ou effacer jusqu'à la fin de l'écran), vous pouvez créer une nouvelle entrée termcap/terminfo pour screen (nommée screen.<dumbterm>) dans laquelle cette capacité a été désactivée. Si cette entrée est installée sur vos machines, vous pouvez faire un rlogin et conserver la bonne entrée termcap/terminfo. Le nom du terminal est placé dans la variable $TERM de toutes les nouvelles fenêtres. Screen définit également la variable $TERMCAP reflétant les capacités du terminal virtuel émulé. Notez, cependant, que sur les machines utilisant la base de données terminfo, cette variable n'a aucun effet. De plus, la variable $WINDOW est définie sur le numéro de la fenêtre pour chaque fenêtre.

L'ensemble réel des capacités prises en charge par le terminal virtuel dépend des capacités prises en charge par le terminal physique. Si, par exemple, le terminal physique ne prend pas en charge le mode de soulignement, screen ne met pas les capacités `us' et `ue' dans la variable $TERMCAP de la fenêtre, en conséquence. Cependant, un nombre minimum de capacités doit être pris en charge par un terminal pour exécuter screen ; à savoir le défilement, l'effacement de l'écran et l'adressage direct du curseur (en outre, screen ne fonctionne pas sur les terminaux d'impression ou sur les terminaux qui font du sur-impression).

Vous pouvez également personnaliser la valeur $TERMCAP utilisée par screen en utilisant la commande termcap .screenrc, ou en définissant la variable $SCREENCAP avant le démarrage. Lorsque cette dernière est définie, sa valeur sera copiée verbatim dans la variable $TERMCAP de chaque fenêtre. Il peut s'agir de la définition complète du terminal, ou d'un nom de fichier où l'écran du terminal (et/ou screen-w) est défini.

Notez que screen respecte la commande terminfo .screenrc si le système utilise la base de données terminfo plutôt que termcap.

Lorsque la capacité booléenne `G0' est présente dans l'entrée termcap du terminal sur lequel screen a été appelé, l'émulation de terminal de screen prend en charge plusieurs jeux de caractères. Cela permet à une application d'utiliser, par exemple, le jeu de caractères graphiques VT100 ou les jeux de caractères nationaux. Les fonctions de contrôle suivantes de l'ISO 2022 sont prises en charge : lock shift G0 (SI), lock shift G1 (SO), lock shift G2, lock shift G3, single shift G2, et single shift G3. Lorsqu'un terminal virtuel est créé ou réinitialisé, le jeu de caractères ASCII est désigné comme G0 à G3. Lorsque la capacité `G0' est présente, screen évalue les capacités `S0', `E0', et `C0' si elles sont présentes. `S0' est la séquence que le terminal utilise pour activer et démarrer le jeu de caractères graphiques plutôt que SI. `E0' est le remplacement correspondant pour SO. `C0' donne une chaîne de traduction caractère par caractère qui est utilisée pendant le mode semi-graphique. Cette chaîne est construite comme la capacité terminfo `acsc'.

Lorsque les capacités `po' et `pf' sont présentes dans l'entrée termcap du terminal, les applications s'exécutant dans une fenêtre screen peuvent envoyer des données au port d'impression du terminal. Cela permet à un utilisateur d'avoir une application dans une fenêtre envoyant des données à une imprimante connectée au terminal, tandis que toutes les autres fenêtres sont toujours actives (le port d'impression est activé et désactivé à nouveau pour chaque bloc de sortie). Par effet secondaire, les programmes s'exécutant dans différentes fenêtres peuvent envoyer des données à l'imprimante simultanément. Les données envoyées à l'imprimante ne sont pas affichées dans la fenêtre. La commande info affiche une ligne commençant par `PRIN' pendant que l'imprimante est active.

Screen maintient une ligne d'état (hardstatus) pour chaque fenêtre. Si une fenêtre est sélectionnée, l'état d'affichage sera mis à jour pour correspondre à la ligne d'état de la fenêtre. Si l'affichage n'a pas de ligne d'état, celle-ci sera affichée comme un message standard de screen. La ligne d'état peut être modifiée avec la commande de programme d'application ANSI (APC) : ESC_<string>ESC\. Par souci de commodité pour les utilisateurs d'xterm, la séquence ESC]0..2;<string>^G est également acceptée.

Certaines capacités ne sont placées dans la variable $TERMCAP du terminal virtuel que si elles peuvent être implémentées efficacement par le terminal physique. Par exemple, `dl' (supprimer la ligne) n'est placée dans la variable $TERMCAP que si le terminal prend en charge soit la suppression de ligne elle-même, soit les régions de défilement. Notez que cela peut prêter à confusion lorsque la session est re-attachée sur un autre terminal, car la valeur de $TERMCAP ne peut pas être modifiée par les processus parents.

TRANSLATION DES CARACTÈRES

Screen dispose d'un mécanisme puissant pour traduire des caractères en chaînes arbitraires en fonction de la police et du type de terminal actuels. Utilisez cette fonctionnalité si vous souhaitez travailler avec un jeu de caractères standard courant (par exemple ISO8851-latin1) même sur des terminaux qui dispersent les caractères plus inhabituels sur plusieurs pages de polices nationales.

Syntaxe :

    XC=<mappage-jeu-caracteres>{,,<mappage-jeu-caracteres>}
    <mappage-jeu-caracteres> := <designateur><modèle>{,<mappage>}
    <mappage> := <caractère-à-mapper><argument-modèle>

Les éléments entre accolades peuvent être répétés autant de fois que nécessaire.

Un <mappage-jeu-caracteres> indique à screen comment mapper les caractères de la police <designateur> ('B' : Ascii, 'A' : UK, 'K' : Allemand, etc.) en chaînes. Chaque <mappage> décrit à quelle chaîne un seul caractère sera traduit. Un mécanisme de modèle est utilisé, car la plupart du temps les codes ont beaucoup en commun (par exemple, les chaînes pour passer d'un jeu de caractères à un autre et revenir). Chaque occurrence de '%' dans <modèle> est substituée par l' <argument-modèle> spécifié avec le caractère. Si vos chaînes ne sont pas du tout similaires, utilisez '%' comme modèle et placez la chaîne complète dans <argument-modèle>. Un mécanisme de citation

DESCRIPTION

Le caractère '\' est utilisé pour échapper les caractères spéciaux '\', '%', et ','.

Voici un exemple :


termcap hp700 'XC=B\E(K%\E(B,\304[,\326\\\\,\334]'

Ceci indique à screen comment traduire les caractères umlaut majuscules ISOlatin1 (charset 'B') sur un terminal hp700 qui a un jeu de caractères allemand. '\304' est traduit en '\E(K[\E(B' et ainsi de suite. Notez que cette ligne est analysée *trois* fois avant que la table de recherche interne ne soit construite, donc beaucoup d'échappement est nécessaire pour créer un seul '\'.

Une autre extension a été ajoutée pour permettre plus d'émulation : Si un mappage traduit le caractère '%' non échappé, il sera envoyé au terminal chaque fois que screen bascule vers le <designateur> correspondant. Dans ce cas spécial, le modèle est supposé être juste '%' car la séquence de commutation de jeu de caractères et les mappages de caractères n'ont normalement pas beaucoup de points communs.

Cet exemple montre une utilisation de l'extension :


termcap xterm 'XC=K%,%\E(B,[\304,\\\\\326,]\334'

Ici, une partie du jeu de caractères allemand ('K') est émulée sur un xterm. Si screen doit passer au jeu de caractères 'K', '\E(B' sera envoyé au terminal, c'est-à-dire que le jeu de caractères ASCII sera utilisé à la place. Le modèle est juste '%', donc le mappage est simple : '[' vers '\304', '\' vers '\326', et ']' vers '\334'.

BOGUES

  • `dm' (mode suppression) et `xs' ne sont pas gérés correctement (ils sont ignorés). `xn' est traité comme un indicateur de marge magique.
  • Screen n'a aucune idée des caractères double hauteur ou double largeur. Mais c'est le seul domaine où vttest est autorisé à échouer.
  • Il n'est pas possible de changer la variable d'environnement $TERMCAP lors de la réattachement sous un type de terminal différent.
  • Le support des systèmes basés sur terminfo est très limité. L'ajout de capacités supplémentaires à $TERMCAP peut ne pas avoir d'effet.
  • Screen n'utilise pas les tabulations matérielles.
  • Screen doit être installé en set-uid avec root comme propriétaire sur la plupart des systèmes pour pouvoir changer correctement le propriétaire du fichier de périphérique tty pour chaque fenêtre. Une permission spéciale peut également être requise pour écrire le fichier /etc/utmp.
  • Les entrées dans /etc/utmp ne sont pas supprimées lorsque screen est tué avec SIGKILL. Cela fera annoncer par certains programmes (comme "w" ou "rwho") qu'un utilisateur est connecté alors qu'il ne l'est pas vraiment.
  • Screen peut afficher un avertissement étrange lorsque votre tty n'a pas d'entrée utmp.
  • Lorsque la ligne modem a été raccrochée, screen peut ne pas se détacher (ou quitter) automatiquement, à moins que le pilote de périphérique ne soit configuré pour envoyer un signal HANGUP. Pour détacher une session screen, utilisez l'option de ligne de commande -D ou -d.
  • breaktype et defbreaktype changent tous deux la méthode de génération de rupture utilisée par tous les périphériques de terminal. Le premier devrait changer un paramètre spécifique à la fenêtre, où le second devrait changer uniquement le défaut pour les nouvelles fenêtres.
  • Lors de l'attachement à une session multi-utilisateurs, le fichier .screenrc de l'utilisateur n'est pas sourcé. Les paramètres personnels de chaque utilisateur doivent être inclus dans le fichier .screenrc à partir duquel la session est démarrée, ou doivent être modifiés manuellement.
  • Une imagination fertile est la plus utile pour tirer pleinement parti de toutes les fonctionnalités.
