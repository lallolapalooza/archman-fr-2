sco(7) Administration système Linux sco(7)

Nom

sco - Transport SCO

SYNTAXE

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/sco.h>
sco_socket = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO);

DESCRIPTION

Le transport logique SCO est un transport symétrique point à point entre le Central et un Périphérique spécifique. Le transport logique SCO réserve des créneaux et peut donc être considéré comme une connexion commutée en circuit entre le Central et le Périphérique.

En plus des créneaux réservés, lorsque eSCO est pris en charge, une fenêtre de retransmission suit immédiatement. Ensemble, les créneaux réservés et la fenêtre de retransmission forment la fenêtre eSCO complète.

ADRESSE SOCKET

struct sockaddr_sco {
    sa_family_t     sco_family;
    bdaddr_t        sco_bdaddr;
};

Exemple :

struct sockaddr_sco addr;
memset(&addr, 0, sizeof(addr));
addr.sco_family = AF_BLUETOOTH;
bacpy(&addr.sco_bdaddr, bdaddr);

OPTIONS SOCKET (SOL_BLUETOOTH)

Les options de socket listées ci-dessous peuvent être définies en utilisant setsockopt(2) et lues avec getsockopt(2) avec le niveau de socket défini à SOL_BLUETOOTH.

BT_SECURITÉ (depuis Linux 2.6.30)

Niveau de sécurité du canal, valeurs possibles :

Valeur Niveau de sécurité Type de clé de lien Chiffrement
BT_SECURITY_SDP 0 (SDP uniquement) Aucun Pas requis
BT_SECURITY_LOW 1 (Bas) Non authentifié Pas requis
BT_SECURITY_MEDIUM 2 (Moyen - par défaut) Non authentifié Souhaité
BT_SECURITY_HIGH 3 (Élevé) Authentifié Requis
BT_SECURITY_FIPS (depuis Linux 3.15) 4 (Sécurisé uniquement) Authentifié (Appairage simple sécurisé basé sur P-256 et authentification sécurisée) Requis

Exemple :

int level = BT_SECURITY_HIGH;
int err = setsockopt(sco_socket, SOL_BLUETOOTH, BT_SECURITY, &level,
                     sizeof(level));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

BT_DIFFERE_SETUP (depuis Linux 2.6.30)

Configuration différée de la connexion du canal, cela contrôle si la procédure de connexion doit être autorisée par l'espace utilisateur avant de répondre, ce qui permet l'autorisation au niveau du profil. Valeurs possibles :

Valeur Description Autorisation
0 Désactivé (par défaut) Non requis
1 Activé Requis

Exemple :

int defer_setup = 1;
int err = setsockopt(sco_socket, SOL_BLUETOOTH, BT_DEFER_SETUP,
                     &defer_setup, sizeof(defer_setup));
if (err == -1) {
    perror("setsockopt");
    return err;
}
err = listen(sco_socket, 5);
if (err) {
    perror("listen");
    return err;
}
struct sockaddr_sco remote_addr = {0};
socklen_t addr_len = sizeof(remote_addr);
int new_socket = accept(sco_socket, (struct sockaddr*)&remote_addr,
                        &addr_len);
if (new_socket < 0) {
    perror("accept");
    return new_socket;
}
/* Pour compléter la configuration de la connexion de new_socket, lire 1 octet */
char c;
struct pollfd pfd;
memset(&pfd, 0, sizeof(pfd));
pfd.fd = new_socket;
pfd.events = POLLOUT;
err = poll(&pfd, 1, 0);
if (err) {
    perror("poll");
    return err;
}
if (!(pfd.revents & POLLOUT)) {
    err = read(sk, &c, 1);
    if (err < 0) {
        perror("read");
        return err;
    }
}

BT_STATUT_PAQUET (depuis Linux 5.9)

Active le rapport du statut du paquet via CMSG BT_SCM_PKT_STATUS sur les paquets reçus. Valeurs possibles :

Valeur Description
0 Désactivé (par défaut)
1 Activé
BT_SCM_PKT_STATUS

Les valeurs sont égales au "Packet_Status_Flag" défini dans la spécification de base v6.0 sec. 5.4.3 p. 1877 :

pkt_status Description

0x2

Name

sco - Bluetooth SCO (Synchronous Connection-Oriented) sockets

SYNOPSIS

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/sco.h>

int sco_socket(int domain, int type, int protocol);

int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
int listen(int sockfd, int backlog);
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
...

DESCRIPTION

Bluetooth SCO sockets provide an interface for the SCO (Synchronous Connection-Oriented) link type defined in the Bluetooth specification.

The SCO link type is designed for real-time voice transmission. It provides connection-oriented, synchronous, and reliable data transfer. The bandwidth is usually limited (e.g. 64 kbps).

SCO sockets are stream sockets, meaning that data is received as a stream of bytes without any message boundaries. They are connection-oriented, requiring a connection to be established before data transfer can occur.

The socket type for SCO sockets is SOCK_SEQPACKET. The protocol is BTPROTO_SCO.

The sco_socket() function creates a SCO socket.

The bind() call binds the socket to a local Bluetooth device address and a port (channel). Since SCO links are point-to-point, the channel number is usually ignored and a free channel is allocated by the kernel.

The connect() call establishes a SCO connection to a remote Bluetooth device.

The listen() and accept() calls can be used to accept incoming SCO connections. The listening socket is bound to a local Bluetooth device address and channel.

SCO sockets can be used for both voice and data transfer. For voice, it is recommended to use audio frameworks like ALSA or PulseAudio.

SOCKET ADDRESS

The address structure for SCO sockets is the standard Bluetooth socket address structure:

struct sockaddr_hci {
    sa_family_t     hci_family;
    unsigned short  hci_dev;
    unsigned short  hci_channel;
};

where:

  • hci_family is set to AF_BLUETOOTH.
  • hci_dev is the Bluetooth device ID. If set to any (or 0), the first available Bluetooth device is used.
  • hci_channel is the SCO channel. For outgoing connections, this should be set to 0. For listening sockets, it should be set to a specific channel or any (0) to let the kernel pick a free channel.

SOCKET OPTIONS (SOL_BLUETOOTH)

The following socket options are available for SCO sockets at the SOL_BLUETOOTH level.

BT_SECURITY

Sets the security level for the connection. Possible values are:

Define Value Description
BT_SECURITY_LOW 0 No security.
BT_SECURITY_MEDIUM 1 Authenticated link key.
BT_SECURITY_HIGH 2 Authenticated and encrypted link key.
BT_SECURITY_FIPS 3 Authenticated and encrypted link key with FIPS compliant encryption.

BT_VOICE (since Linux 5.12)

Setting the voice setting. Possible values:

Define Value Description
BT_VOICE_TRANSPARENT 0x00 Transparent data transfer.
BT_VOICE_CVSD 0x01 CVSD codec.
BT_VOICE_MSBC 0x02 mSBC codec.
BT_VOICE_PCM_CVSD 0x03 PCM with CVSD codec.
BT_VOICE_PCM_MSBC 0x04 PCM with mSBC codec.
BT_VOICE_TRANSPARENT_TX_ONLY 0x80 Transparent data transfer, TX only.
BT_VOICE_TRANSPARENT_RX_ONLY 0x40 Transparent data transfer, RX only.

The default value is BT_VOICE_TRANSPARENT.

BT_POWER (since Linux 5.13)

Set transmit power. Possible values:

Define Value Description
BT_POWER_LOW 0x00 Low power.
BT_POWER_MEDIUM 0x01 Medium power.
BT_POWER_HIGH 0x02 High power.

The default value is BT_POWER_MEDIUM.

BT_AUTO_FLUSH (since Linux 5.14)

Auto flush data. Possible values:

Define Value Description
BT_AUTO_FLUSH_OFF 0x00 Disable auto flush.
BT_AUTO_FLUSH_ON 0x01 Enable auto flush.

The default value is BT_AUTO_FLUSH_OFF.

BT_PACKET_LEN (since Linux 5.14)

Set packet length. Possible values:

Define Value Description
BT_PACKET_LEN_MIN 0x00 Minimum packet length.
BT_PACKET_LEN_MAX 0x01 Maximum packet length.
BT_PACKET_LEN_DEFAULT 0x02 Default packet length.

The default value is BT_PACKET_LEN_DEFAULT.

BT_PCM_CONFIG (since Linux 5.14)

Configure PCM audio interface. Possible values:

Define Value Description
BT_PCM_CONFIG_A_LAW 0x00 A-law encoding.
BT_PCM_CONFIG_MU_LAW 0x01 mu-law encoding.
BT_PCM_CONFIG_SIGNED_INT8 0x02 8-bit signed integer.
BT_PCM_CONFIG_UNSIGNED_INT8 0x03 8-bit unsigned integer.
BT_PCM_CONFIG_SIGNED_INT16 0x04 16-bit signed integer.
BT_PCM_CONFIG_UNSIGNED_INT16 0x05 16-bit unsigned integer.
BT_PCM_CONFIG_MONO 0x00 Mono audio.
BT_PCM_CONFIG_STEREO 0x08 Stereo audio.
BT_PCM_CONFIG_CLOCK_INVERTED 0x10 Inverted clock.

The default value is BT_PCM_CONFIG_SIGNED_INT16 | BT_PCM_CONFIG_MONO.

BT_RCV_TIMEWAIT (since Linux 6.15)

Enable waiting for data before receiving. Possible values:

Define Value Description
BT_RCV_TIMEWAIT_OFF 0x00 Disable waiting.
BT_RCV_TIMEWAIT_ON 0x01 Enable waiting.

The default value is BT_RCV_TIMEWAIT_OFF.

If enabled, recv() or read() will return immediately even if no data is available, returning 0 bytes read. This can be useful for real-time applications that need to poll for data without blocking.

BT_SND_TIMEWAIT (since Linux 6.15)

Enable waiting for data to be sent before sending. Possible values:

Define Value Description
BT_SND_TIMEWAIT_OFF 0x00 Disable waiting.
BT_SND_TIMEWAIT_ON 0x01 Enable waiting.

The default value is BT_SND_TIMEWAIT_OFF.

If enabled, send() or write() will return immediately even if the data cannot be sent immediately, returning the number of bytes sent. This can be useful for real-time applications that need to send data without blocking.

BT_CODEC (since Linux 5.14)

Transport codec offload, possible values:

struct bt_codec {
    uint8_t id;
    uint16_t cid;
    uint16_t vid;
    uint8_t data_path_id;
    uint8_t num_caps;
    struct codec_caps {
        uint8_t len;
        uint8_t data[];
    } caps[];
} __attribute__((packed));
struct bt_codecs {
    uint8_t num_codecs;
    struct bt_codec codecs[];
} __attribute__((packed));

Example:

char buffer[sizeof(struct bt_codecs) + sizeof(struct bt_codec)];
struct bt_codec *codecs = (void *)buffer;
memset(codecs, 0, sizeof(codecs));
codec->num_codecs = 1;
codecs->codecs[0].id = 0x05;
codecs->codecs[0].data_path_id = 1;
int err = setsockopt(sco_socket, SOL_BLUETOOTH, BT_CODEC, codecs,
                     sizeof(buffer));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

BT_PHY (since Linux 5.10)

Transport supported PHY(s), read-only (no setsockopt support). Possible values:

Define Value Description
BT_PHY_BR_1M_1SLOT BIT 0 BR 1Mbps 1SLOT
BT_PHY_BR_1M_3SLOT BIT 1 BR 1Mbps 3SLOT
BT_PHY_BR_2M_1SLOT BIT 3 EDR 2Mbps 1SLOT
BT_PHY_BR_2M_3SLOT BIT 4 EDR 2Mbps 3SLOT
BT_PHY_BR_3M_1SLOT BIT 6 EDR 3Mbps 1SLOT
BT_PHY_BR_3M_3SLOT BIT 7 EDR 3Mbps 3SLOT

SOCKET OPTIONS (SOL_SOCKET)

SOL_SOCKET level socket options that modify generic socket features (SO_SNDBUF, SO_RCVBUF, etc.) have their usual meaning, see socket(7).

The SOL_SOCKET level SCO socket options that have Bluetooth-specific handling in kernel are listed below.

SO_TIMESTAMPING, SO_TIMESTAMP, SO_TIMESTAMPNS

See https://docs.kernel.org/networking/timestamping.html

For SCO sockets, software RX timestamps are supported. Software TX timestamps (SOF_TIMESTAMPING_TX_SOFTWARE) are supported since Linux 6.15.

The software RX timestamp is the time when the kernel received the packet from the controller driver.

The SCM_TSTAMP_SND timestamp is emitted when packet is sent to the controller driver.

The SCM_TSTAMP_COMPLETION timestamp is emitted when controller reports the packet completed. Completion timestamps are only supported on controllers that have SCO flow control. Other TX timestamp types are not supported.

You can use SIOCETHTOOL to query supported flags.

The timestamps are in CLOCK_REALTIME time.

Example (Enable RX timestamping):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_RX_SOFTWARE;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Example (Read packet and its RX timestamp):

char data_buf[256];
union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = data_buf,
    .iov_len = sizeof(data_buf),
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct scm_timestamping tss;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
}
tstamp_clock_realtime = tss.ts[0];

Example (Enable TX timestamping):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_TX_SOFTWARE |
    SOF_TIMESTAMPING_OPT_ID;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Example (Read TX timestamps):

union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = NULL,
    .iov_len = 0
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct cmsghdr *cmsg;
struct scm_timestamping tss;
struct sock_extended_err serr;
int res;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
    else if (cmsg->cmsg_level == SOL_BLUETOOTH && cmsg->cmsg_type == BT_SCM_ERROR)
        memcpy(&serr, CMSG_DATA(cmsg), sizeof(serr));
}
tstamp_clock_realtime = tss.ts[0];
tstamp_type = serr->ee_info;      /* SCM_TSTAMP_SND or SCM_TSTAMP_COMPLETION */
tstamp_seqnum = serr->ee_data;

IOCTLS

The following ioctls with operation specific for SCO sockets are available.

SIOCETHTOOL (since Linux 6.16-rc1)

Supports only command ETHTOOL_GET_TS_INFO, which may be used to query supported SOF_TIMESTAMPING_* flags. The SOF_TIMESTAMPING_OPT_* flags are always available as applicable.

Example:

#include <linux/ethtool.h>
#include <linux/sockios.h>
#include <net/if.h>
#include <sys/socket.h>
#include <sys/ioctl.h>
...
struct ifreq ifr = {};
struct ethtool_ts_info cmd = {};
int sk;
snprintf(ifr.ifr_name, sizeof(ifr.ifr_name), "hci0");
ifr.ifr_data = (void *)&cmd;
cmd.cmd = ETHTOOL_GET_TS_INFO;
sk = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO);
if (sk < 0)
    goto error;
if (ioctl(sk, SIOCETHTOOL, &ifr))
    goto error;
sof_available = cmd.so_timestamping;
