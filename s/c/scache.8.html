NOM

scache — serveur de cache de connexions partagé de Postfix

SYNOPSIS

scache [options génériques de démon Postfix]

DESCRIPTION


Le serveur scache(8) maintient un cache partagé de multiples connexions. Ces informations peuvent être utilisées par, par exemple, les clients SMTP de Postfix ou d'autres agents de livraison de Postfix.

Le cache de connexions est organisé en noms de destination logique, noms de points d'extrémité physiques et connexions.

À titre d'exemple spécifique, les destinations SMTP logiques spécifient (transport, domaine, port), et les points d'extrémité SMTP physiques spécifient (transport, adresse IP, port). Une connexion SMTP peut être sauvegardée après une transaction de courrier réussie.

Dans le cas général, une destination logique peut faire référence à zéro ou plusieurs points d'extrémité physiques, un point d'extrémité physique peut être référencé par zéro ou plusieurs destinations logiques, et un point d'extrémité peut faire référence à zéro ou plusieurs connexions.

La syntaxe exacte d'un nom de destination logique ou de point d'extrémité dépend de l'application ; le serveur scache(8) ne s'en soucie pas. Une connexion est stockée sous forme de descripteur de fichier avec des informations dépendantes de l'application qui sont nécessaires pour réactiver un objet de connexion. Encore une fois, le serveur scache(8) ignore complètement les détails de ces informations.

Toutes les informations sont stockées avec une durée de vie (ttl) limitée. Le démon du cache de connexions se termine lorsqu'aucun client n'est connecté pendant max_idle unités de temps.

Ce serveur implémente les requêtes suivantes :

save_endp ttl endpoint endpoint_properties file_descriptor
Sauvegarde le descripteur de fichier spécifié et les données de propriétés de connexion sous le nom de point d'extrémité spécifié. Les propriétés du point d'extrémité sont utilisées par le client pour réactiver un objet de connexion passivé.
find_endp endpoint
Recherche les propriétés mises en cache et un descripteur de fichier mis en cache pour le point d'extrémité spécifié.
save_dest ttl destination destination_properties endpoint
Sauvegarde la liaison entre une destination logique et un point d'extrémité sous le nom de destination, avec les propriétés de connexion spécifiques à la destination. Les propriétés de destination sont utilisées par le client pour réactiver un objet de connexion passivé.
find_dest destination
Recherche les propriétés de destination mises en cache, les propriétés de point d'extrémité mises en cache et un descripteur de fichier mis en cache pour la destination logique spécifiée.

SÉCURITÉ

Le serveur scache(8) n'est pas sensible à la sécurité. Il ne communique pas avec le réseau, et il ne communique pas avec les utilisateurs locaux. Le serveur scache(8) peut être exécuté en chroot à privilège faible et fixe.

Le serveur scache(8) n'est pas un processus de confiance. Il ne doit pas être utilisé pour stocker des informations sensibles pour la sécurité.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Le cache de session ne peut pas être partagé entre plusieurs machines.

Lorsqu'une connexion expire du cache, elle est fermée sans la poignée de main appropriée spécifique au protocole.

PARAMÈTRES DE CONFIGURATION

Les modifications apportées à main.cf sont prises en compte automatiquement car les processus scache(8) ne fonctionnent que pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer un changement.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

CONTRÔLES DE RESSOURCES

connection_cache_ttl_limit (2s)
La valeur maximale de temps de vie que le serveur de cache de connexions scache(8) autorise.
connection_cache_status_update_time (600s)
À quelle fréquence le serveur scache(8) enregistre les statistiques d'utilisation avec les taux de succès et d'échec du cache de connexions pour les destinations logiques et les points d'extrémité physiques.

CONTRÔLES DIVERS

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
daemon_timeout (18000s)
Combien de temps un processus démon Postfix peut prendre pour traiter une requête avant d'être terminé par un timer de surveillance intégré.
ipc_timeout (3600s)
La limite de temps pour envoyer ou recevoir des informations sur un canal de communication interne.
max_idle (100s)
La durée maximale pendant laquelle un processus démon Postfix inactif attend une connexion entrante avant de se terminer volontairement.
process_id (lecture seule)
L'ID du processus d'une commande ou d'un processus démon Postfix.
process_name (lecture seule)
Le nom du processus d'une commande ou d'un processus démon Postfix.
syslog_facility (mail)
La facility syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix 3.3 et versions ultérieures :

service_name (lecture seule)
Le nom du service master.cf d'un processus démon Postfix.
