SCRIPT(1) Commandes utilisateur SCRIPT(1)

NOM

script - crée un enregistrement d'une session de terminal

SYNTAXE

script [options] [fichier]

DESCRIPTION

script crée une copie de tout ce qui se passe dans votre session de terminal. Les données du terminal sont stockées sous forme brute dans le fichier journal et les informations de chronométrage dans un autre fichier journal structuré (optionnel). Le fichier journal de chronométrage est nécessaire pour rejouer la session ultérieurement avec scriptreplay(1) et pour stocker des informations supplémentaires sur la session.

Depuis la version 2.35, script prend en charge plusieurs flux et permet l'enregistrement des entrées et sorties vers des fichiers séparés ou vers un seul fichier. Cette version prend également en charge un nouveau fichier de chronométrage qui enregistre des informations supplémentaires. La commande scriptreplay --summary fournit alors toutes les informations.

Si l'argument fichier ou l'option --log-out fichier est donné, script enregistre le dialogue dans ce fichier. Si aucun nom de fichier n'est donné, le dialogue est enregistré dans le fichier typescript.

Notez que l'enregistrement des entrées à l'aide de --log-in ou --log-io peut enregistrer des informations sensibles pour la sécurité, car le fichier journal contient toutes les entrées de la session du terminal (par exemple, les mots de passe) indépendamment du réglage du drapeau d'écho du terminal.

OPTIONS

Ci-dessous, l'argument taille peut être suivi des suffixes multiplicatifs KiB (=1024), MiB (=1024*1024), et ainsi de suite pour GiB, TiB, PiB, EiB, ZiB et YiB (le suffixe « iB » est optionnel, par exemple, « K » a la même signification que « KiB »), ou des suffixes KB (=1000), MB (=1000*1000), et ainsi de suite pour GB, TB, PB, EB, ZB et YB.

-a, --append

Ajoute la sortie à fichier ou à typescript, en conservant le contenu précédent.

-c, --command commande

Exécute la commande au lieu d'un shell interactif. Cela permet à un script de capturer facilement la sortie d'un programme qui se comporte différemment lorsque sa sortie standard n'est pas un tty.

-E, --echo quand

Cette option contrôle le drapeau ECHO pour l'extrémité esclave du pseudo-terminal de la session. Les modes pris en charge sont always (toujours), never (jamais) ou auto.

Le mode par défaut est auto ; dans ce cas, ECHO est activé pour le pseudo-terminal esclave ; si l'entrée standard actuelle est un terminal, ECHO est désactivé pour éviter le double écho ; si l'entrée standard actuelle n'est pas un terminal (par exemple, un pipe : echo date | script), alors maintenir ECHO activé pour le pseudo-terminal esclave permet aux données d'entrée standard d'être affichées à l'écran tout en étant enregistrées simultanément dans le journal de session.

Notez que le mode 'never' affecte le contenu du journal de sortie de la session, car les entrées de l'utilisateur ne sont pas répétées en sortie.

-e, --return

Retourne le statut de sortie du processus enfant. Utilise le même format que la terminaison de bash sur une terminaison par signal (c'est-à-dire, le statut de sortie est 128 + le numéro du signal). Le statut de sortie du processus enfant est toujours stocké dans le fichier de type script également.

-f, --flush

Vide la sortie après chaque écriture. C'est utile pour la télésurveillance : une personne fait mkfifo foo ; script -f foo, et une autre peut surveiller en temps réel ce qui est fait en utilisant cat foo. Notez que la vidange a un impact sur les performances ; il est possible d'utiliser SIGUSR1 pour vider les journaux sur demande.

--force

Autorise le fichier de sortie par défaut typescript à être un lien dur ou symbolique. La commande suivra un lien symbolique.

-B, --log-io fichier

Enregistre les entrées et sorties dans le même fichier. Notez que cette option n'a de sens que si --log-timing est également spécifié, sinon il est impossible de séparer les flux de sortie et d'entrée du fichier journal.

-I, --log-in fichier

Enregistre les entrées dans le fichier. La sortie du journal est désactivée si seule l'option --log-in est spécifiée.

Utilisez cette fonctionnalité de journalisation avec prudence car elle enregistre toutes les entrées, y compris les entrées lorsque le terminal a désactivé le drapeau d'écho (par exemple, les entrées de mot de passe).

-O, --log-out fichier

Enregistre la sortie dans le fichier. Par défaut, la sortie est enregistrée dans le fichier nommé typescript si les options --log-out ou --log-in ne sont pas données. La sortie du journal est désactivée si seule l'option --log-in est spécifiée.

-T, --log-timing fichier

Enregistre les informations de chronométrage dans le fichier. Deux formats de fichier de chronométrage sont maintenant pris en charge. Le format classique est utilisé lorsqu'un seul flux (entrée ou sortie) est enregistré. Le format multi-flux est utilisé avec --log-io ou lorsque --log-in et --log-out sont utilisés ensemble. Voir également --logging-format.

-m, --logging-format format

Force l'utilisation du format de journal de chronométrage advanced (avancé) ou classic (classique). Le format par défaut est le format classique pour enregistrer uniquement la sortie et le format avancé lorsque l'enregistrement de l'entrée et de la sortie est demandé.

Format classique

Le journal de chronométrage contient deux champs, séparés par un espace. Le premier champ indique le temps écoulé depuis la sortie précédente. Le second champ indique le nombre de caractères qui ont été émis à ce moment-là.

Format avancé (multi-flux)

Le premier champ est un identifiant de type d'entrée ('I'nput, 'O'utput, 'H'eader, 'S'ignal). Le second champ est le temps écoulé depuis l'entrée précédente, et le reste de l'entrée sont des données spécifiques au type.

-o, --output-limit taille

Limite la taille des fichiers typescript et de chronométrage à taille et arrête le processus enfant après que cette taille a été dépassée. La taille de fichier calculée n'inclut pas les messages de début et de fin que la commande script préfixe et suffixe à la sortie du processus enfant. En raison de la mise en mémoire tampon, le fichier de sortie résultant peut être plus grand que la valeur spécifiée.

-q, --quiet

Silencieux (n'écrit pas les messages de début et de fin sur la sortie standard).

-t[fichier], --timing[=fichier]

Sortie des données de chronométrage sur l'erreur standard, ou sur fichier lorsqu'il est donné. Cette option est obsolète en faveur de --log-timing où l'argument fichier n'est pas optionnel.

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

SIGNALS

Lorsqu'il reçoit SIGUSR1, script vide immédiatement les fichiers de sortie.

ENVIRONNEMENT

La variable d'environnement suivante est utilisée par script :

SHELL

Si la variable SHELL existe, le shell appelé par script sera ce shell. Si SHELL n'est pas définie, le shell Bourne est supposé. (La plupart des shells définissent automatiquement cette variable).

NOTES

Le script se termine lorsque le shell enfant se termine (un control-D pour le shell Bourne (sh(1p)), et exit, logout ou control-d (si ignoreeof n'est pas défini) pour le shell C, csh(1)).

Certaines commandes interactives, telles que vi(1), créent des caractères indésirables dans le fichier typescript. script fonctionne mieux avec les commandes qui ne manipulent pas l'écran ; les résultats sont destinés à émuler un terminal en impression papier.

Il n'est pas recommandé d'exécuter script dans des shells non interactifs. Le shell interne de script est toujours interactif, et cela pourrait conduire à des résultats inattendus. Si vous utilisez script dans le fichier d'initialisation du shell, vous devez éviter d'entrer dans une boucle infinie. Vous pouvez utiliser par exemple le fichier .profile, qui n'est lu que par les shells de connexion :

if test -t 0 ; t

NOTES

script is primarily designed for interactive terminal sessions. When stdin is not a terminal (for example: echo foo | script), then the session can hang, because the interactive shell within the script session misses EOF and script has no clue when to close the session.

To avoid this hang, you can use the -e (exit-on-error) option with the script command and redirect stdin from a file or device that reflects EOF correctly.

$ echo foo | script -e
$ exit
fi

You should also avoid use of script in command pipes, as script can read more input than you would expect.

HISTORY

The script command appeared in 3.0BSD.

BUGS

script places everything in the log file, including linefeeds and backspaces. This is not what the naive user expects.
