SCTP(7) Manuel du programmeur Linux SCTP(7)

NOM

sctp - Protocole SCTP.

SYNTAXE

#include <sys/socket.h>
#include <netinet/in.h>
#include <netinet/sctp.h>

sctp_socket = socket(PF_INET, SOCK_STREAM, IPPROTO_SCTP);
sctp_socket = socket(PF_INET, SOCK_SEQPACKET, IPPROTO_SCTP);

DESCRIPTION

Ceci est une implémentation du protocole SCTP telle que définie dans la RFC4960. C'est un protocole de transport fiable, orienté message, avec support direct du multihoming, qui fonctionne par-dessus ip(7), et supporte les versions v4 et v6.

Comme TCP, SCTP fournit une livraison de données fiable et orientée connexion avec contrôle de congestion. Contrairement à TCP, SCTP fournit également la préservation des frontières des messages, la livraison ordonnée et non ordonnée des messages, le multi-streaming et le multihoming. La détection de corruption de données, de perte de données et de duplication de données est réalisée en utilisant des sommes de contrôle et des numéros de séquence. Un mécanisme de retransmission sélective est appliqué pour corriger la perte ou la corruption des données.

Cette implémentation supporte un mappage de SCTP dans l'API des sockets tel que défini dans la RFC6458 (Extensions de l'API des sockets pour SCTP). Deux styles d'interfaces sont supportés.

Une interface de style un-à-plusieurs avec une relation de 1 à PLUSIEURS entre le socket et les associations où la configuration de l'association sortante est implicite. La syntaxe d'un appel socket() de style un-à-plusieurs est

sd = socket(PF_INET, SOCK_SEQPACKET, IPPROTO_SCTP);

Un serveur typique dans ce style utilise les appels socket suivants en séquence pour préparer un point de terminaison pour traiter les requêtes.


1. socket()
2. bind()
3. listen()
4. recvmsg()
5. sendmsg()
6. close()

Un client typique utilise les appels suivants en séquence pour établir une association avec un serveur afin de demander des services.


1. socket()
2. sendmsg()
3. recvmsg()
4. close()

Une interface de style un-à-un avec une relation de 1 à 1 entre le socket et l'association, ce qui permet de porter des applications TCP existantes sur SCTP avec très peu d'effort. La syntaxe d'un appel socket() de style un-à-un est

sd = socket(PF_INET, SOCK_STREAM, IPPROTO_SCTP);

Un serveur typique dans le style un-à-un utilise la séquence d'appels système suivante pour préparer un point de terminaison SCTP pour traiter les requêtes :


1. socket()
2. bind()
3. listen()
4. accept()

L'appel accept() bloque jusqu'à ce qu'une nouvelle association soit établie. Il retourne avec un nouveau descripteur de socket. Le serveur utilise ensuite le nouveau descripteur de socket pour communiquer avec le client, en utilisant les appels recv() et send() pour obtenir les requêtes et renvoyer les réponses. Il appelle ensuite


5. close()

pour terminer l'association. Un client typique utilise la séquence d'appels système suivante pour établir une association avec un serveur afin de demander des services :


1. socket()
2. connect()

Après le retour de connect(), le client utilise les appels send() et recv() pour envoyer des requêtes et recevoir des réponses du serveur. Le client appelle


3. close()

pour terminer cette association lorsqu'il a terminé.

FORMATS D'ADRESSE

SCTP est construit par-dessus IP (voir ip(7)). Les formats d'adresse définis par ip(7) s'appliquent à SCTP. SCTP ne supporte que la communication point à point ; la diffusion et la multidiffusion ne sont pas supportées.

SYSCTLS

Ces variables peuvent être accédées via les fichiers /proc/sys/net/sctp/* ou avec l'interface sysctl(2). De plus, la plupart des sysctls IP s'appliquent également à SCTP. Voir ip(7).

Veuillez consulter la documentation du noyau à ce sujet, dans Documentation/networking/ip-sysctl.rst.

MESSAGES DE CONTRÔLE

Les données auxiliaires sont transportées dans le champ msg_control de la structure msghdr, qui est utilisée dans les appels sendmsg(2) et recvmsg(2). La pile SCTP utilise les données auxiliaires pour communiquer les attributs, tels que SCTP_RCVINFO, du message stocké dans msg_iov au point d'extrémité du socket. Chaque élément de données auxiliaires est précédé d'une structure cmsghdr, voir cmsg(3). Les différents types de cmsg pour SCTP sont listés ci-dessous, et toutes ces macros et structures associées sont définies dans /usr/include/netinet/sctp.h.

SCTP_INIT
Ce cmsg fournit des informations pour initialiser de nouvelles associations SCTP pour sendmsg() avec la structure sctp_initmsg, qui est identique à la structure de données de l'option de socket SCTP_INITMSG.
SCTP_SNDRCV
Ce cmsg spécifie les options SCTP pour sendmsg() et décrit les informations d'en-tête SCTP d'un message reçu via recvmsg() avec la structure sctp_sndrcvinfo. Il mélange le chemin d'envoi et de réception, et SCTP_SNDINFO et SCTP_RCVINFO divisent ces informations, donc ces structures doivent être utilisées, lorsque possible, car SCTP_SNDRCV est obsolète. sctp_sendmsg(3) et sctp_send(3) fournissent un moyen simple d'utiliser ce cmsg.

Notez qu'une application doit utiliser l'option de socket SCTP_RECVRCVINFO pour activer la livraison de ces informations.

SCTP_EXTRCV
Ce cmsg spécifie les options SCTP pour les informations d'en-tête SCTP d'un message reçu via recvmsg() avec la structure sctp_extrcvinfo, et cette structure est une version étendue de SCTP_SNDRCV. Notez que les données du message suivant ne sont pas valides sauf si le message actuel est complètement lu, c'est-à-dire, sauf si MSG_EOR est défini. SCTP_NXTINFO doit être utilisé lorsque possible, car SCTP_EXTRCV est considéré comme obsolète. sctp_recvmsg(3) fournit un moyen simple d'utiliser ce cmsg.

Notez qu'une application doit utiliser l'option de socket SCTP_RECVNXTINFO pour activer la livraison de ces informations.

SCTP_RCVINFO, SCTP_NXTINFO
Ces cmsgs décrivent les informations de réception SCTP d'un message reçu via recvmsg() avec la structure sctp_rcvinfo, et les informations de réception SCTP du prochain message qui sera livré via recvmsg() si ces informations sont déjà disponibles lors de la livraison du message actuel avec la structure sctp_nxtinfo. sctp_recvv(3) fournit un moyen simple d'utiliser ces cmsgs.

Notez qu'une application doit utiliser les options de socket SCTP_RECVRCVINFO et SCTP_RECVNXTINFO en conséquence pour activer la livraison de ces informations.

SCTP_SNDINFO, SCTP_PRINFO, SCTP_AUTHINFO, SCTP_DSTADDRV4, SCTP_DSTADDRV6
Ces cmsgs spécifient quelques options SCTP pour sendmsg() pour les informations d'envoi, de PRSCTP, d'AUTH et de DSTADDR avec les structures sctp_sndinfo, sctp_prinfo, sctp_authinfo et in(6)_addr respectivement. sctp_sendv(3) fournit un moyen simple d'utiliser ces cmsgs.

ÉVÉNEMENTS et NOTIFICATIONS

Une application SCTP peut avoir besoin de comprendre et de traiter les événements et les erreurs qui se produisent sur la pile SCTP. Ces événements incluent les changements d'état du réseau, les démarrages d'association, les erreurs opérationnelles à distance et les messages non livrables. Lorsqu'une notification arrive, recvmsg() renvoie la notification dans le tampon de données fourni par l'application via msg_iov, et définit MSG_NOTIFICATION dans msg_flags. Voir l'option de socket SCTP_EVENT pour l'activation des événements. Les différents événements sont listés ci-dessous, et toutes ces macros et structures associées sont définies dans /usr/include/netinet/sctp.h.

SCTP_ASSOC_CHANGE
Les notifications de communication informent l'application qu'une association SCTP a soit commencé, soit pris fin. Le format de la notification est la structure sctp_assoc_change.
SCTP_PEER_ADDR_CHANGE
Lorsqu'une adresse de destination d'un pair multi-homed rencontre un changement d'état, un événement de changement d'adresse de pair est envoyé. Le format de la notification est la structure sctp_paddr_change.
SCTP_REMOTE_ERROR
Un pair distant peut envoyer un message d'erreur d'opération à son pair. Ce message indique diverses conditions d'erreur sur une association. Le format de la notification est la structure sctp_remote_error.
SCTP_SEND_FAILED
Si SCTP ne parvient pas à livrer un message, il peut renvoyer le message sous forme de notification si l'événement SCTP_SEND_FAILED est activé. Le format de la notification est la structure sctp_send_failed. Veuillez noter que cette notification est obsolète. Utilisez SCTP_SEND_FAILED_EVENT à la place.
SCTP_SHUTDOWN_EVENT
Lorsqu'un pair envoie une commande SHUTDOWN, SCTP livre cette notification pour informer l'application qu'elle doit cesser d'envoyer des données. Le format de la notification est la structure sctp_shutdown_event.
SCTP_ADAPTATION_INDICATION
Lorsqu'un pair envoie un paramètre d'indication de couche d'adaptation, SCTP livre cette notification pour informer l'application sur l'indication de couche d'adaptation du pair. Le format de la notification est la structure sctp_adaptation_event.
SCTP_PARTIAL_DELIVERY_EVENT
Lorsqu'un récepteur est engagé dans une livraison partielle d'un message, cette notification sera utilisée pour indiquer divers événements. Le format de la notification est la structure sctp_pdapi_event.
SCTP_AUTHENTICATION_EVENT
Ceci est utilisé pour signaler différents événements liés à l'utilisation de l'extension pour authentifier les messages SCTP. Le format de la notification est la structure sctp_authkey_event.
SCTP_SENDER_DRY_EVENT
Lorsque la pile SCTP n'a plus de données utilisateur à envoyer ou à retransmettre, cette notification est transmise à l'utilisateur. De plus, au moment où une application utilisateur s'abonne à cet événement, s'il n'y a pas de données à envoyer ou à retransmettre, la pile enverra immédiatement cette notification. Le format de la notification est la structure sctp_sender_dry_event.
SCTP_SEND_FAILED_EVENT
Si SCTP ne parvient pas à livrer un message, il peut renvoyer le message sous forme de notification si l'événement SCTP_SEND_FAILED_EVENT est activé. Le format de la notification est la structure sctp_send_failed_event.

OPTIONS DE SOCKET

Pour définir ou obtenir une option de socket SCTP, appelez getsockopt(2) pour lire ou setsockopt(2) pour écrire l'option avec l'argument de niveau d'option défini sur SOL_SCTP. Notez que toutes ces macros et structures décrites pour les paramètres sont définies dans /usr/include/netinet/sctp.h, et pour les sockets de style un-à-un, un assoc_id spécifié fonctionne de la même manière que SCTP_FUTURE_ASSOC.

SCTP_RTOINFO.
Cette option est utilisée pour obtenir ou définir les paramètres du protocole utilisés pour initialiser et limiter le temps de retransmission (RTO).

Le type de paramètre est la structure sctp_rtoinfo, pour la lecture et l'écriture. srto_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Par défaut: srto_max=sysctl_net.sctp.rto_max, srto_min

=sysctl_net.sctp.rto_min, srto_initial=sysctl_net.sctp.rto_initial.

SCTP_ASSOCINFO
Cette option est utilisée pour examiner et définir divers paramètres d'association et de point de terminaison.

Le type de paramètre est struct sctp_assocparams, pour la lecture et l'écriture. sasoc_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Notez que certains champs de cette structure sont en lecture seule :


struct sctp_assocparams {
sctp_assoc_t sasoc_assoc_id;
__u16 sasoc_asocmaxrxt; (RW)
__u16 sasoc_number_peer_destinations; (R)
__u32 sasoc_peer_rwnd; (R)
__u32 sasoc_local_rwnd; (R)
__u32 sasoc_cookie_life; (RW)
};

Par défaut : sasoc_asocmaxrxt=sysctl_net.sctp.association_max_retrans, sasoc_cookie_life=sysctl_net.sctp.valid_cookie_life.

SCTP_INITMSG
Cette option est utilisée pour obtenir ou définir les paramètres du protocole pour l'initialisation par défaut de l'association.

Le type de paramètre est struct sctp_initmsg, pour la lecture et l'écriture.

Par défaut : sinit_num_ostreams=10, sinit_max_instreams=10, sinit_max_attempts=sysctl_net.sctp.max_init_retransmits, sinit_max_init_timeo=sysctl_net.sctp.rto_max.

SCTP_NODELAY
Active/désactive tout algorithme de type Nagle. Cela signifie que les paquets sont généralement envoyés dès que possible et qu'aucun délai inutile n'est introduit, au détriment de plus de paquets sur le réseau.

Le type de paramètre est un entier booléen, pour la lecture et l'écriture.

Par défaut : 0.

SCTP_AUTOCLOSE
Cette option de socket s'applique uniquement aux sockets de style un-à-plusieurs. Lorsqu'elle est définie, elle entraîne la fermeture automatique des associations inactives pendant plus d'un nombre spécifié de secondes. Une association inactive est définie comme une association qui n'a PAS envoyé ou reçu de données utilisateur pendant une période donnée.

Le type de paramètre est un entier (secondes), pour la lecture et l'écriture. 0 indique qu'aucune fermeture automatique d'association ne doit être effectuée.

Par défaut : sysctl_net.sctp.max_autoclose.

SCTP_SET_PEER_PRIMARY_ADDR
Demande au pair de marquer l'adresse incluse comme adresse primaire de l'association. L'adresse incluse doit être l'une des adresses localement liées de l'association.

Le type de paramètre est struct sctp_setpeerprim, en écriture uniquement. sspp_assoc_id est un assoc_id spécifié.

Par défaut : la 1ère adresse locale ajoutée. Nécessite : SCTP_ASCONF_SUPPORTED.

SCTP_PRIMARY_ADDR
Demande à la pile SCTP locale d'utiliser l'adresse du pair incluse comme adresse primaire de l'association. L'adresse incluse doit être l'une des adresses du pair de l'association.

Le type de paramètre est struct sctp_prim, en écriture uniquement. ssp_assoc_id est un assoc_id spécifié.

Par défaut : la 1ère adresse du pair ajoutée. Nécessite : SCTP_ASCONF_SUPPORTED.

SCTP_DISABLE_FRAGMENTS
Si activé, aucun fragment de message SCTP ne sera effectué. Au lieu de cela, si un message envoyé dépasse la taille PMTU actuelle, le message NE SERA PAS envoyé et une erreur sera signalée à l'utilisateur.

Le type de paramètre est un entier booléen, pour la lecture et l'écriture.

Par défaut : 0.

SCTP_PEER_ADDR_PARAMS
En utilisant cette option, les applications peuvent activer ou désactiver les battements de cœur pour toute adresse de pair d'une association, modifier l'intervalle de battement de cœur d'une adresse, forcer l'envoi immédiat d'un battement de cœur et ajuster le nombre maximum de retransmissions d'une adresse avant qu'elle ne soit considérée comme injoignable.

Le type de paramètre est struct sctp_paddrparams, pour la lecture et l'écriture. spp_address est une adresse de transport spécifiée ou 0, spp_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Par défaut : hbinterval=sysctl_net.sctp.hb_interval, pathmaxrxt=sysctl_net.sctp.path_max_retrans, pathmtu=dev/route's, sackdelay=sysctl_net.sctp.sack_timeout, param_flags=HB_ENABLE|PMTUD_ENABLE|SACKDELAY_ENABLE, flowlabel=0, dscp=0.

SCTP_DEFAULT_SEND_PARAM
Les applications qui souhaitent utiliser l'appel système sendto() peuvent souhaiter spécifier un ensemble par défaut de paramètres qui seraient normalement fournis par l'inclusion de données auxiliaires. Cette option a été supprimée au profit de SCTP_DEFAULT_SNDINFO.

Le type de paramètre est struct sctp_sndrcvinfo. Pour la lecture, sinfo_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Pour l'écriture, sinfo_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Par défaut : default_stream=0, default_flags=0, default_ppid=0, default_context=0, default_timetolive=0.

SCTP_EVENTS
Cette option de socket est utilisée pour spécifier diverses notifications et données auxiliaires que l'utilisateur souhaite recevoir. Cette option a été supprimée au profit de SCTP_EVENT.

Le type de paramètre est struct sctp_event_subscribe, pour la lecture et l'écriture.

Par défaut : 0.

SCTP_I_WANT_MAPPED_V4_ADDR
Cette option de socket est utilisée pour activer ou désactiver les adresses V4 mappées. Si cette option est activée et que le socket est de type PF_INET6, les adresses IPv4 seront mappées en représentation V6. Si cette option est désactivée, aucun mappage d'adresses V4 ne sera effectué et un utilisateur recevra des adresses de type PF_INET6 et PF_INET sur le socket.

Le type de paramètre est un entier booléen, pour la lecture et l'écriture.

Par défaut : 1.

SCTP_MAXSEG
Cette option de socket spécifie la taille maximale à insérer dans tout bloc de données SCTP sortant. Si un message est plus grand que cette taille, il sera fragmenté par SCTP dans la taille spécifiée. Notez que l'implémentation SCTP sous-jacente peut fragmenter en blocs de taille plus petite lorsque la PMTU de l'association sous-jacente est inférieure à la valeur définie par l'utilisateur. 0 indique que l'utilisateur ne limite PAS la fragmentation et que seule la PMTU affectera le choix de SCTP pour la taille du bloc de données.

Le type de paramètre est struct sctp_assoc_value, pour la lecture et l'écriture. assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Par défaut : 0 (aucune limite).

SCTP_STATUS
Les applications peuvent récupérer des informations d'état actuelles sur une association, y compris l'état de l'association, la taille de la fenêtre du récepteur du pair, le nombre de blocs de données non acquittés et le nombre de blocs de données en attente de réception.

Le type de paramètre est struct sctp_status, en lecture seule. sstat_assoc_id est un assoc_id spécifié.

SCTP_GET_PEER_ADDR_INFO
Les applications peuvent récupérer des informations sur une adresse de pair spécifique d'une association, y compris son état d'atteignabilité, sa fenêtre de congestion et les valeurs de son minuteur de retransmission.

Le type de paramètre est struct sctp_paddrinfo, en lecture seule. spinfo_address est une adresse de transport spécifiée, sas_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

SCTP_GET_ASSOC_STATS
Les applications peuvent récupérer les statistiques actuelles sur une association, y compris les SACK envoyés et reçus, les paquets SCTP envoyés et reçus.

Le type de paramètre est struct sctp_assoc_stats, en lecture seule. sas_assoc_id est un assoc_id spécifié.

SCTP_DELAYED_ACK, SCTP_DELAYED_ACK_TIME, SCTP_DELAYED_SACK
Ces options affecteront la manière dont les SACK retardés sont effectués. Elles permettent à l'application d'obtenir ou de définir le temps de SACK retardé, en millisecondes, et permettent également de modifier la fréquence des SACK retardés. Modifier la fréquence à 1 désactive l'algorithme de SACK retardé. Notez que si sack_delay ou sack_freq est 0 lors de la définition de cette option, les valeurs actuelles resteront inchangées.

Le type de paramètre est struct sctp_sack_info. Pour la lecture, sack_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Pour l'écriture, sack_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Par défaut : sackdelay=sysctl_net.sctp.sack_timeout,sackfreq=2.

SCTP_CONTEXT
Cette option permet de définir, sur une base associative, un contexte par défaut qui sera reçu lors de la lecture de messages du pair. Ceci est particulièrement utile pour une application utilisant des sockets de style un-à-plusieurs afin de conserver une référence à une machine d'état interne qui traite les messages sur l'association. Notez que la définition de cette valeur n'affecte que les messages reçus du pair et n'affecte pas la valeur qui est enregistrée avec les messages sortants.

Le type de paramètre est struct sctp_assoc_value. Pour la lecture, assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Pour l'écriture, assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Par défaut : 0.

SCTP_FRAGMENT_INTERLEAVE
Le contrôle d'entrelacement des fragments détermine la manière dont les messages sont présentés au récepteur. Il existe trois niveaux d'entrelacement de fragments : niveau 0 : SCTP_FRAGMENT_INTERLEAVE = 0 ; niveau 1 : SCTP_FRAGMENT_INTERLEAVE = 1 ; niveau 2 : SCTP_FRAGMENT_INTERLEAVE = 1 & SCTP_INTERLEAVING_SUPPORTED = 1.

Le type de paramètre est un entier booléen, pour la lecture et l'écriture.

Par défaut : 0.

SCTP_PARTIAL_DELIVERY_POINT
Cette option définit ou récupère le point de livraison partielle SCTP. Ce point est la taille d'un message à laquelle l'API de livraison partielle sera appelée pour aider à libérer de l'espace rwnd pour le pair. Définir une valeur plus basse provoquera des livraisons partielles plus fréquentes. Cette option attend un entier.r qui définit ou obtient le point de livraison partiel en octets. Notez également que l'appel échouera si l'utilisateur tente de définir cette valeur à une taille supérieure à la taille du tampon de réception du socket. Notez que tout message unique d'une longueur inférieure ou égale au point de livraison partiel SCTP sera livré en un seul appel de lecture tant que le tampon fourni par l'utilisateur est suffisamment grand pour contenir le message.

Le type du paramètre est uint32_t, pour la lecture et l'écriture.

Défaut : 0.

SCTP_MAX_BURST
Cette option permet à un utilisateur de modifier le nombre maximal de paquets qui peuvent être émis par cette association.

Le type du paramètre est struct sctp_assoc_value. Pour la lecture, assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Pour l'écriture, assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Défaut : sysctl_net.sctp.max_burst.

SCTP_AUTH_CHUNK
Cette option ajoute un type de bloc que l'utilisateur demande à recevoir uniquement de manière authentifiée, et elle n'affecte que les associations futures.

Le type du paramètre est struct sauth_chunk, pour l'écriture uniquement.

Défaut : aucun bloc. Requis : SCTP_AUTH_SUPPORTED. RFC : RFC4895.

SCTP_HMAC_IDENT
Cette option obtient ou définit la liste des algorithmes de code d'authentification de message haché (HMAC) que le point de terminaison local exige que le pair utilise.

Le type du paramètre est struct sctp_hmacalgo, pour la lecture et l'écriture. shmac_idents peut inclure SCTP_AUTH_HMAC_ID_{SHA1|SHA256}.

Défaut : SCTP_AUTH_HMAC_ID_SHA1. Requis : SCTP_AUTH_SUPPORTED.

SCTP_AUTH_KEY
Cette option définit une clé secrète partagée qui est utilisée pour construire une clé partagée d'association.

Le type du paramètre est struct sctp_authkey, pour l'écriture uniquement. sca_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Défaut : null_key. Requis : SCTP_AUTH_SUPPORTED.

SCTP_AUTH_ACTIVE_KEY
Cette option obtient ou définit la clé partagée active à utiliser pour construire la clé partagée d'association.

Le type du paramètre est struct sctp_authkeyid, pour l'écriture uniquement. scact_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Défaut : 0. Requis : SCTP_AUTH_SUPPORTED.

SCTP_AUTH_DEACTIVATE_KEY
Cette option de définition indique que l'application n'enverra plus de messages utilisateur en utilisant l'identifiant de clé indiqué.

Le type du paramètre est struct sctp_authkeyid, pour l'écriture uniquement. scact_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Requis : SCTP_AUTH_SUPPORTED.

SCTP_AUTH_DELETE_KEY
Cette option de définition supprimera une clé secrète partagée d'une association SCTP qui a été désactivée.

Le type du paramètre est struct sctp_authkeyid, pour l'écriture uniquement. scact_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Requis : SCTP_AUTH_SUPPORTED.

SCTP_PEER_AUTH_CHUNKS
Cette option obtient une liste de types de blocs pour une association spécifiée que le pair exige de recevoir authentifiés uniquement.

Le type du paramètre est struct sctp_authchunks, pour la lecture uniquement. gauth_assoc_id est un assoc_id spécifié.

Requis : SCTP_AUTH_SUPPORTED.

SCTP_LOCAL_AUTH_CHUNKS
Cette option obtient une liste de types de blocs pour une association spécifiée que le point de terminaison local exige de recevoir authentifiés uniquement.

Le type du paramètre est struct sctp_authchunks, pour la lecture uniquement. gauth_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Requis : SCTP_AUTH_SUPPORTED.

SCTP_GET_ASSOC_NUMBER
Cette option obtient le nombre actuel d'associations qui sont attachées à un socket de style un-à-plusieurs. Notez que ce nombre n'est qu'un instantané. Cela signifie que le nombre d'associations peut avoir changé lorsque l'appelant récupère le résultat de l'option.

Le type du paramètre est uint32_t, pour la lecture uniquement.

SCTP_GET_ASSOC_ID_LIST
Cette option obtient la liste actuelle des identifiants d'association SCTP des associations SCTP gérées par un socket de style un-à-plusieurs. Elle utilise la structure sctp_assoc_ids et doit fournir un tampon suffisamment grand pour contenir tous les identifiants d'association. Si le tampon est trop petit, une erreur doit être retournée. L'utilisateur peut utiliser l'option de socket SCTP_GET_ASSOC_NUMBER pour avoir une idée de la taille du tampon nécessaire.

Le type du paramètre est struct sctp_assoc_ids, pour la lecture uniquement.

SCTP_EXPOSE_POTENTIALLY_FAILED_STATE, SCTP_EXPOSE_PF_STATE
Les applications peuvent contrôler l'exposition de l'état du chemin PF dans l'événement SCTP_PEER_ADDR_CHANGE, et si pf_expose n'est pas 'activé', aucune notification ne sera envoyée pour un changement d'état de transport vers SCTP_PF. Cela affecte également l'option de socket SCTP_GET_PEER_ADDR_INFO, et si pf_expose est 'désactivé', les utilisateurs ne peuvent pas accéder aux informations de transport via l'option SCTP_GET_PEER_ADDR_INFO.

Le type du paramètre est struct sctp_assoc_value, pour la lecture et l'écriture. assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Défaut : sysctl_net.sctp.pf_expose.

SCTP_PEER_ADDR_THLDS
Les applications peuvent contrôler le comportement SCTP-PF en obtenant ou en définissant le nombre de timeouts consécutifs avant qu'une adresse de pair ne soit considérée comme PF ou inaccessible.

Le type du paramètre est struct sctp_paddrthlds, pour la lecture et l'écriture. spt_address est une adresse de transport spécifiée ou 0, spt_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Défaut : pathmaxrxt=sysctl_net.sctp.path_max_retrans, ps_retrans=sysctl_net.sctp.ps_retrans.

SCTP_PEER_ADDR_THLDS_V2
Similaire à SCTP_PEER_ADDR_THLDS, mais il peut également être utilisé par les applications pour définir et obtenir le nombre de timeouts avant que le chemin principal ne soit automatiquement modifié par la fonction de basculement du chemin principal.

Le type du paramètre est struct sctp_paddrthlds_v2, pour la lecture et l'écriture. spt_address est une adresse de transport spécifiée ou 0, spt_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC.

Défaut : pathmaxrxt=sysctl_net.sctp.path_max_retrans, ps_retrans=sysctl_net.sctp.ps_retrans, pf_retrans=sysctl_net.sctp.pf_retrans.

SCTP_RECVRCVINFO
La définition de cette option spécifie que SCTP_RCVINFO (informations de réception SCTP sur un message reçu) est retourné comme données auxiliaires par recvmsg(). Voir MESSAGES DE CONTRÔLE pour plus de détails.

Le type du paramètre est int, pour la lecture et l'écriture.

Défaut : 0.

SCTP_RECVNXTINFO
La définition de cette option spécifie que SCTP_NXTINFO (informations de réception SCTP du prochain message) est retourné comme données auxiliaires par recvmsg(). Voir MESSAGES DE CONTRÔLE pour les détails.

Le type du paramètre est int, pour la lecture et l'écriture.

Défaut : 0.

SCTP_DEFAULT_SNDINFO
Cette option rend obsolète SCTP_DEFAULT_SEND_PARAM.

Le type du paramètre est struct sctp_sndinfo. Pour la lecture, snd_assoc_id est un assoc_id spécifié ou SCTP_FUTURE_ASSOC. Pour l'écriture, snd_assoc_id est un assoc_id spécifié ou SCTP_{FUTURE|CURRENT|ALL}_ASSOC.

Défaut : default_stream=0, default_flags=0, default_ppid=0, default_context=0.

SCTP_REUSE_PORT
Cette option est similaire à l'option de niveau socket SO_REUSEADDR, mais elle ne prend en charge que les sockets SCTP de style un-à-un et ne doit pas être utilisée après avoir appelé bind() ou sctp_bindx().

Le type du paramètre est int, pour la lecture et l'écriture.

Défaut : 0.

SCTP_SOCKOPT_BINDX_ADD
Cette option permet à l'utilisateur de lier un sous-ensemble spécifique d'adresses ou, si l'extension SCTP ASCONF est prise en charge (voir SCTP_ASCONF_SUPPORTED), d'ajouter des adresses spécifiques. L'API sctp_bindx() est basée sur cela.

Le type du paramètre est struct sockaddr[], pour l'écriture uniquement.

SCTP_SOCKOPT_BINDX_REM
Similaire à SCTP_SOCKOPT_BINDX_ADD, mais pour supprimer des adresses spécifiques. L'API sctp_bindx() est basée sur cela.

Le type du paramètre est struct sockaddr[], pour l'écriture uniquement.

SCTP_SOCKOPT_PEELOFF
Cette option détache une association de type UDP vers un socket séparé retourné à l'utilisateur. L'API sctp_peeloff() est basée sur cette option.

Le type du paramètre est sctp_peeloff_arg_t, pour la lecture uniquement. associd est un assoc_id spécifié.

SCTP_SOCKOPT_PEELOFF_FLAGS
Détache une association de type UDP d'un socket, similaire à l'option SCTP_SOCKOPT_PEELOFF, mais elle permet d'utiliser des drapeaux tels que O_CLOEXEC et O_NONBLOCK lors de la création du nouveau socket. L'API sctp_peeloff_flags() est basée sur cette option.

Le type du paramètre est sctp_peeloff_flags_arg_t, pour la lecture uniquement. associd est un assoc_id spécifié.

SCTP_SOCKOPT_CONNECTX_OLD
Cette option permet à un utilisateur de spécifier plusieurs adresses auxquelles un pair peut être atteint, et la pile du noyau utilisera la liste d'adresses pour établir l'association. L'API sctp_connectx() est basée sur cette option.

SCTP_SOCKOPT

These socket options are used to control the behavior of SCTP sockets.

SCTP_SOCKOPT_CONNECTX_OLD
This option is used to establish a multi-homed connection. The API sctp_connectx() is based on this option.

The parameter type is struct sockaddr[], for writing only.

SCTP_SOCKOPT_CONNECTX
Similar to SCTP_SOCKOPT_CONNECTX_OLD, but it returns the new assoc's id. The API sctp_connectx2() is based on this option.

The parameter type is struct sockaddr[], for writing only. The new assoc's id is passed to users by the return value.

SCTP_SOCKOPT_CONNECTX3
Similar to SCTP_SOCKOPT_CONNECTX, but it uses different type parameter. The API sctp_connectx3() is based on this option.

The parameter type is struct sctp_getaddrs_old, for reading only. assoc_id is set to the new assoc's id by kernel and passed to users.

SCTP_GET_PEER_ADDRS
This option is used to gets all peer addresses in an association. The API sctp_getpaddrs() is based on this option.

The parameter type is struct sctp_getaddrs, for reading only. assoc_id is a specified assoc_id.

SCTP_GET_LOCAL_ADDRS
This option is used to get all local addresses in an association. The API sctp_getladdrs() is based on this option.

The parameter type is struct sctp_getaddrs, for reading only. assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.

SCTP_ADAPTATION_LAYER
This option requests that the local endpoint set the specified Adaptation Layer Indication parameter for all future INIT and INIT-ACK exchanges.

The parameter type is struct sctp_setadaptation, for reading and writing.

Default: 0.

SCTP_EVENT
This option obsoletes SCTP_EVENTS socket option, and it can set or get one specific type of event for a specified association.

The parameter type is struct sctp_event. For reading, se_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, se_assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. se_type can be one of enum sctp_sn_type.

Default: 0.

SCTP_PR_SUPPORTED
This socket option allows the enabling or disabling of the negotiation of PR-SCTP support for future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.prsctp_enable. RFC: RFC7496.

SCTP_DEFAULT_PRINFO
This option sets and gets the default parameters for PR-SCTP.

The parameter type is struct sctp_default_prinfo. For reading, pr_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, pr_assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. pr_policy can be SCTP_PR_SCTP_{NONE|TTL|RTX|PRIO}.

Default: SCTP_PR_SCTP_NONE. Require: SCTP_DEFAULT_PRINFO.

SCTP_PR_ASSOC_STATUS
This option is used to get Association-Specific PR-SCTP Status.

The parameter type is struct sctp_prstatus, for reading only. sprstat_assoc_id is a specified assoc_id, sprstat_policy can be SCTP_PR_SCTP_{TTL|RTX|PRIO|ALL}.

SCTP_PR_STREAM_STATUS
This option is used to get Stream-Specific PR-SCTP Status.

The parameter type is struct sctp_prstatus, for reading only. sprstat_assoc_id is a specified assoc_id, sprstat_policy can be SCTP_PR_SCTP_{TTL|RTX|PRIO|ALL}.

SCTP_RECONFIG_SUPPORTED
Enable the Stream Reconfiguration(RECONF) for the future associations. For different type of requests enabling, see SCTP_ENABLE_STREAM_RESET option.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.reconf_enable. RFC: RFC6525.

SCTP_ENABLE_STREAM_RESET
This option allows a user to control whether the kernel processes or denies incoming requests in RECONF chunks.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. assoc_value can be SCTP_ENABLE_{RESET_STREAM_REQ|RESET_ASSOC_REQ|CHANGE_ASSOC_REQ}.

Default: 0. Require: SCTP_RECONFIG_SUPPORTED.

SCTP_RESET_STREAMS
This option allows the user to request the reset of incoming and/or outgoing streams.

The parameter type is struct sctp_reset_streams, for writing only. srs_assoc_id is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_RESET_ASSOC
This option allows a user to request the reset of the SSN/TSN.

The parameter type is sctp_assoc_t, for writing only. It is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_ADD_STREAMS
This option allows a user to request the addition of a number of incoming and/or outgoing streams.

The parameter type is struct sctp_add_streams, for writing only. sas_assoc_id is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_STREAM_SCHEDULER
This option is used to select a stream scheduler for data sending.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. assoc_value can be SCTP_SS_{FCFS|PRIO|RR|FC|WFQ}.

Default: SCTP_SS_FCFS. RFC: RFC8260.

SCTP_STREAM_SCHEDULER_VALUE
Some stream schedulers require additional information to be set for individual streams.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id. For writing, assoc_id is a specified assoc_id or SCTP_CURRENT_ASSOC.

Require: SCTP_STREAM_SCHEDULER.

SCTP_INTERLEAVING_SUPPORTED
This socket option allows the enabling or disabling of the negotiation of user message interleaving support for future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.intl_enable. Require: SCTP_FRAGMENT_INTERLEAVE. RFC: RFC8260.

SCTP_ASCONF_SUPPORTED
Enable the Dynamic Address Reconfiguration(ASCONF) for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.addip_enable. RFC: RFC5061.

SCTP_AUTO_ASCONF
This option will enable or disable the use of the automatic generation of ASCONF chunks to add and delete addresses to an existing association. Note that this option has two caveats, namely a) it only affects sockets that are bound to all addresses available to the SCTP stack, and b) the system administrator may have an overriding control that turns the ASCONF feature off no matter what setting the socket option may have.

The parameter type is int boolean, for reading and writing.

Default: sysctl_net.sctp.default_auto_asconf.

SCTP_AUTH_SUPPORTED
Enable AUTH for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, ssoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.auth_enable. RFC: RFC4895.

SCTP_ECN_SUPPORTED
Enable ECN for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.ecn_enable.

SCTP_REMOTE_UDP_ENCAPS_PORT
This option is used to set the encapsulation port(a remote listening or dest port) for SCTP over UDP, which allows SCTP traffic to pass through legacy NATs that do not provide native SCTP support.

The parameter type is struct sctp_udpencaps, for reading and writing. sue_address is a specified transport address or 0, sue_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.encap_port. RFC: RFC6951.

SCTP_PLPMTUD_PROBE_INTERVAL
This option is used to configure the PROBE_INTERVAL for the Packetization Layer Path MTU Discovery(PLPMTUD). It can be set to a value >= 5000 or 0(disabled).

The parameter type is struct sctp_probeinterval, for reading and writing. spi_address is a specified transport address or 0, spi_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.

Default: 0(disabled). RFC: RFC8899.
