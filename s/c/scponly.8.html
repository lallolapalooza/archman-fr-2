NOM

scponly

SYNOPSIS

scponly

— shell limité pour les transferts de fichiers sécurisés

DESCRIPTION

scponly est un "shell" alternatif (en quelque sorte) pour les administrateurs système qui souhaitent fournir aux utilisateurs distants un accès en lecture et en écriture aux fichiers locaux sans leur accorder de privilèges d'exécution à distance. Fonctionnellement, il est mieux décrit comme un wrapper pour la suite fiable des applications ssh.

Une utilisation typique de scponly consiste à créer un compte semi-public, similaire au concept de connexion anonyme pour ftp. Cela permet à un administrateur de partager des fichiers de la même manière qu'une configuration ftp anonyme, en utilisant uniquement toutes les protections que ssh offre. Ceci est particulièrement significatif si l'on considère que les authentifications ftp traversent les réseaux publics sous forme de texte brut.

Au lieu d'un seul utilisateur anonyme, scponly prend en charge la configuration de potentiellement plusieurs utilisateurs, chacun pouvant être configuré pour fournir un accès à des arbres de répertoires distincts. Outre les détails d'installation, chacun de ces utilisateurs aura son shell par défaut dans /etc/passwd défini sur "/usr/local/bin/scponly" (ou partout où vous choisissez de l'installer). Cela signifie que les utilisateurs avec ce shell ne pourront ni se connecter interactivement ni exécuter de commandes à distance. Ils pourront cependant transférer des fichiers en utilisant scp, régis par les permissions de fichiers Unix habituelles.

FONCTIONNALITÉS

  • Journalisation : scponly enregistre l'heure, l'adresse IP du client, le nom d'utilisateur et la requête réelle dans syslog.
  • chroot : scponly peut chrooter vers le répertoire personnel de l'utilisateur (ou tout autre répertoire pour lequel l'utilisateur a des permissions), interdisant l'accès au reste du système de fichiers.
  • Compatibilité sftp : Mes tests de sftp avec un utilisateur scponly ont très bien fonctionné. C'est probablement la manière la plus propre et la plus utilisable pour un utilisateur scponly d'accéder aux fichiers.
  • Vérifications de sécurité : la connexion root est interdite (bien que root ne devrait jamais être configuré pour utiliser scponly comme shell par défaut).
  • Compatibilité WinSCP 2.0 : scponly peut être compilé en mode de compatibilité WinSCP qui permettra un shell "semi-interactif" que WinSCP peut utiliser.
  • Compatibilité gftp : scponly est compatible avec gftp si vous sélectionnez "utiliser le sous-système sftp ssh2" dans vos options gftp.

scponly ne fait rien pour gérer les permissions de lecture/écriture. Les applications ssh s'en chargent déjà très bien. Si vous utilisez scponly, sachez que les permissions de fichiers de style Unix classiques protègent toujours vos fichiers.

NOTES

  • Jusqu'en juin 2002, des vulnérabilités ont été découvertes dans OpenSSH. Il y a également une vulnérabilité du protocole SSH1. Si vous utilisez scponly, sachez qu'il n'est pas plus sécurisé que l'installation ssh sur laquelle il s'exécute.
  • J'ai depuis découvert que l'offre ssh commerciale de ssh.com prend en charge à la fois les "utilisateurs fictifs" et des fonctionnalités parallèles à scponly. Je n'ai pas pu trouver de notes sur ces fonctionnalités, mais j'ai lu qu'elles existaient. Je ferai un point pour inclure plus d'informations plus tard. Il semble qu'OpenSSH ne prenne pas encore en charge ces fonctionnalités. À l'heure actuelle, je n'ai pas l'intention d'arrêter le support de scponly, bien qu'en fin de compte, je reconnaisse que scponly devrait éventuellement devenir une simple fonctionnalité de quel que soit le sshd que vous exécutez.

FICHIERS

/usr/local/bin/scponly
L'emplacement par défaut du shell lui-même.
/usr/local/sbin/scponlyc
L'emplacement par défaut de la version chrootée de scponly
/etc/shells
Pour être un shell approprié, il doit être inclus ici.
