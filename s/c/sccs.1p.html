SCCS(1P) Manuel du programmeur POSIX SCCS(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sccs — interface pour le sous-système SCCS (DÉVELOPPEMENT)

SYNTAXE

sccs [-r] [-d chemin] [-p chemin] commande [options...] [opérandes...]

DESCRIPTION

L'utilitaire sccs est une interface pour les programmes SCCS. Il inclut également la capacité de s'exécuter avec des identifiants utilisateur différents pour fournir une protection supplémentaire.

L'utilitaire sccs invoquera la commande spécifiée avec les options et opérandes spécifiés. Par défaut, chacun des opérandes sera modifié en ajoutant la chaîne "SCCS/s." au début.

La commande peut être le nom d'une des utilitaires SCCS de ce volume de POSIX.1‐2017 (admin, delta, get, prs, rmdel, sact, unget, val, ou what) ou l'un des pseudo-utilitaires listés dans la section DESCRIPTION ÉTENDUE.

OPTIONS

L'utilitaire sccs se conformera aux Définitions de base du volume de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception que les opérandes options sont en fait des options à passer à l'utilitaire nommé par commande. Lorsque la partie de la commande :

commande [options ... ] [opérandes ... ]

est considérée, tous les pseudo-utilitaires utilisés comme commande supporteront les Directives de syntaxe des utilitaires. Les autres utilitaires SCCS qui peuvent être invoqués de cette manière supportent les Directives dans la mesure indiquée par leurs sections OPTIONS individuelles.

Les options suivantes seront supportées avant l'opérande commande :

-d chemin
Un nom de chemin d'un répertoire à utiliser comme répertoire racine pour les fichiers SCCS. La valeur par défaut sera le répertoire courant. L'option -d aura la priorité sur la variable PROJECTDIR. Voir -p.
-p chemin
Un nom de chemin d'un répertoire où se trouvent les fichiers SCCS. La valeur par défaut sera le répertoire SCCS.

L'option -p diffère de l'option -d en ce que l'argument de l'option -d sera préfixé à l'intégralité du nom de chemin et que l'argument de l'option -p sera inséré avant le composant final du nom de chemin. Par exemple :

sccs -d /x -p y get a/b

se traduit par :

get /x/a/y/s.b

Cela permet la création d'alias tels que :

alias syssccs="sccs -d /usr/src"

qui est utilisé comme suit :

syssccs get cmd/who.c
-r
Invoque commande avec l'identifiant utilisateur réel du processus, et non l'identifiant utilisateur effectif auquel l'utilitaire sccs est réglé. Certaines commandes (admin, check, clean, diffs, info, rmdel, et tell) ne peuvent pas être exécutées avec un identifiant utilisateur effectif par tous les utilisateurs, car cela permettrait à quiconque de modifier les autorisations. Ces commandes sont toujours exécutées en tant qu'utilisateur réel.

OPÉRANDES

Les opérandes suivants seront supportés :

commande
Un nom d'utilitaire SCCS ou le nom de l'un des pseudo-utilitaires listés dans la section DESCRIPTION ÉTENDUE.
options
Une option ou un argument d'option à passer à commande.
opérandes
Un opérande à passer à commande.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de sccs :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locales.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles comme caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages diagnostiques écrits sur l'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PROJECTDIR

Fournit une valeur par défaut pour l'option -d chemin. Si la valeur de PROJECTDIR commence par un <slash>, elle sera considérée comme un nom de chemin absolu ; sinon, la valeur de PROJECTDIR sera traitée comme un nom d'utilisateur et le répertoire de travail initial de cet utilisateur sera examiné pour un sous-répertoire src ou source. Si un tel répertoire est trouvé, il sera utilisé. Sinon, la valeur sera utilisée comme un nom de chemin relatif.

Des effets supplémentaires de variables d'environnement peuvent se trouver dans la description de l'utilitaire pour la commande spécifiée.

PROLOG

Ce document décrit les spécifications des utilitaires du système de contrôle de code source (SCCS) telles qu'elles sont définies par le standard POSIX.

NOM

sccs - utilitaires frontaux pour le système de contrôle de code source

SYNOPSIS

sccs [-r root] commande [ option… ] [ opérande… ]

DESCRIPTION

Le sccs est une interface de ligne de commande qui permet d'exécuter diverses commandes SCCS. Il est conçu pour simplifier l'utilisation de SCCS en fournissant une interface unifiée pour de nombreuses opérations courantes.

Les commandes SCCS sous-jacentes incluent, mais ne sont pas limitées à : admin, delta, get, rmdel, sact, prs, rmdelt, val, what, et diffs.

Le sccs prend un nom de commande comme premier argument, suivi des options et des opérandes de cette commande. Le caractère '-' peut être utilisé comme opérande pour indiquer l'entrée standard.

Le caractère '-r' optionnel, s'il est présent, spécifie le répertoire racine du système SCCS. S'il n'est pas spécifié, le sccs recherchera le répertoire SCCS en remontant la hiérarchie des répertoires à partir du répertoire courant.

OPTIONS

-r root
Spécifie le répertoire racine du système SCCS. S'il n'est pas spécifié, sccs recherchera le répertoire SCCS en remontant la hiérarchie des répertoires à partir du répertoire courant.

COMMANDES

Les commandes suivantes sont disponibles via sccs :

admin
Créer ou modifier les fichiers SCCS. Cette commande est généralement utilisée pour initialiser un nouveau fichier SCCS ou pour changer ses attributs. Les options de la commande admin sous-jacente sont acceptées.
check
Vérifier les fichiers SCCS pour des anomalies potentielles. Cette commande est souvent utilisée pour s'assurer de l'intégrité des fichiers SCCS et pour détecter les problèmes avant qu'ils ne causent des erreurs.
create
Créer un fichier SCCS, en prenant le contenu initial du fichier du même nom. Toutes les options de admin sont acceptées. Si la création réussit, les fichiers originaux seront renommés en ajoutant un préfixe virgule aux noms de base. Ces fichiers renommés devraient être supprimés après vérification que les fichiers SCCS ont été créés avec succès.
delget
Effectuer un delta sur les fichiers nommés, puis un get des nouvelles versions. Les nouvelles versions auront les mots-clés d'identification développés et ne seront pas éditables. Toute option '-m', '-p', '-r', '-s', et '-y' sera passée à delta, et toute option '-b', '-c', '-e', '-i', '-k', '-l', '-s', et '-x' sera passée à get.
deledit
Équivalent à delget, sauf que la phase get inclura l'option '-e'. Cette option est utile pour créer un point de contrôle de la phase d'édition en cours. Les mêmes options seront passées à delta que celles décrites ci-dessus, et toutes les options listées pour get ci-dessus, à l'exception de '-e', seront passées à edit.
diffs
Écrire une liste des différences entre la version actuelle des fichiers extraits pour édition et les versions au format SCCS. Toute option '-r', '-c', '-i', '-x', et '-t' sera passée à get ; toute option '-l', '-s', '-e', '-f', '-h', et '-b' sera passée à diff. Une option '-C' sera passée à diff comme '-c'.
edit
Équivalent à get -e.
fix
Supprimer le delta nommé, mais laisser une copie du delta avec les modifications qu'il contenait. Utile pour corriger de petits bugs de compilation, etc. L'application doit s'assurer qu'il est suivi d'une option '-r' SID. Étant donné que fix ne laisse pas de traces d'audit, il doit être utilisé avec prudence.
info
Écrire une liste de tous les fichiers en cours d'édition. Si l'option '-b' est donnée, les branches (c'est-à-dire les SID avec deux composants ou moins) seront ignorées. Si une option '-u' user est donnée, seuls les fichiers édités par l'utilisateur nommé seront listés. Une option '-U' sera équivalente à '-u'<utilisateur courant>.
print
Afficher des informations détaillées sur les fichiers nommés, équivalent à sccs prs.
show
Afficher les différences entre les versions des fichiers. C'est une interface pour la commande diffs.
sccsdiff
Afficher les différences entre deux versions d'un fichier SCCS. Cette commande est une interface pour la commande diffs avec des options spécifiques à SCCS.
tell
Écrire une liste des fichiers en cours d'édition, séparés par des sauts de ligne, vers la sortie standard. Prend les options '-b', '-u', et '-U' comme info et check.
unedit
Ceci est l'inverse d'un edit ou d'un get -e. Il doit être utilisé avec prudence, car toute modification effectuée depuis le get sera perdue.

OPÉRANDES

Les opérandes sont des noms de fichiers ou des répertoires sur lesquels les commandes SCCS doivent opérer. Si un répertoire est spécifié, la commande SCCS sera appliquée récursivement à tous les fichiers SCCS contenus dans ce répertoire et ses sous-répertoires.

STDIN

L'entrée standard peut être utilisée pour fournir des données à certaines commandes SCCS, comme admin pour la création de fichiers ou delta pour les messages de modification.

FICHIERS D'ENTRÉE

Les fichiers d'entrée sont généralement des fichiers gérés par SCCS (fichiers préfixés par s.) ou des fichiers de travail correspondants.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent affecter l'exécution des commandes SCCS :

SCCS
Si défini, SCCS spécifie le chemin du répertoire racine de SCCS. S'il n'est pas défini, le répertoire SCCS est recherché en remontant depuis le répertoire courant.
SHELL
Utilisé par certaines commandes SCCS pour lancer des éditeurs ou des shells.
TZ
Utilisé pour la gestion des fuseaux horaires et des dates.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard est utilisée pour afficher les résultats des commandes SCCS, tels que les listes de fichiers, les différences, ou les informations sur les versions.

STDERR

La sortie d'erreur standard est utilisée pour afficher les messages d'erreur et les diagnostics.

FICHIERS DE SORTIE

Les commandes SCCS peuvent créer ou modifier des fichiers de données SCCS (préfixés par s.) et des fichiers de travail correspondants.

DESCRIPTION ÉTENDUE

Cette section fournit plus de détails sur certaines des commandes SCCS les plus couramment utilisées via l'interface sccs.

admin
La commande admin est utilisée pour créer et gérer les fichiers SCCS. Elle permet d'initialiser de nouveaux fichiers SCCS à partir de fichiers existants, de définir les autorisations, de spécifier les commentaires obligatoires, et de définir d'autres attributs du fichier SCCS. Les options courantes incluent '-t' pour spécifier un fichier de description, '-f' pour définir des flags, et '-m' pour spécifier un commentaire.
delta
La commande delta est utilisée pour enregistrer les modifications apportées à un fichier de travail dans le système SCCS. Elle crée une nouvelle version (un delta) du fichier dans le fichier SCCS. Les options courantes incluent '-y' pour spécifier un commentaire de modification, '-s' pour supprimer le fichier de travail après la création du delta, et '-m' pour spécifier un fichier contenant les modifications à appliquer.
get
La commande get est utilisée pour extraire une version d'un fichier du système SCCS. Elle crée une copie du fichier (le fichier de travail) dans le répertoire courant. Les options courantes incluent '-e' pour extraire le fichier en vue de modifications ultérieures (ce qui le rend modifiable), '-r' pour spécifier le numéro de version à extraire, et '-p' pour envoyer la sortie vers la sortie standard au lieu de créer un fichier de travail.
rmdel
La commande rmdel est utilisée pour supprimer un delta spécifique d'un fichier SCCS. Cela doit être fait avec prudence car cela modifie l'historique du fichier. Elle nécessite généralement l'option '-r' pour spécifier le numéro de version du delta à supprimer.
sact
La commande sact est utilisée pour afficher les informations sur les fichiers actuellement en cours d'édition (c'est-à-dire les fichiers qui ont été extraits avec get -e mais pour lesquels un delta n'a pas encore été créé). Elle aide à suivre les modifications en cours.
prs
La commande prs est utilisée pour imprimer des informations détaillées sur les versions des fichiers SCCS, y compris l'historique des modifications, les commentaires, et les dates. Elle permet de formater la sortie selon des modèles spécifiés.
val
La commande val est utilisée pour valider les fichiers SCCS et vérifier leur intégrité. Elle peut être utilisée pour vérifier que les fichiers SCCS sont correctement formatés et ne contiennent pas d'erreurs.
what
La commande what recherche dans un fichier source des chaînes d'identification spéciales (généralement "@(#)") et affiche les informations associées, telles que le numéro de version et la date. Elle est souvent utilisée pour marquer les fichiers avec leur identifiant SCCS.
check
Vérifie les fichiers SCCS pour détecter les anomalies. Il peut rechercher des incohérences entre le fichier SCCS et les fichiers de travail, ou des problèmes internes au fichier SCCS. Il est utile pour maintenir l'intégrité de la base de données SCCS.
diffs
Compare les versions des fichiers. Cette commande est une interface pour la commande diff, avec des options spécifiques pour comparer des versions SCCS avec des fichiers de travail ou d'autres versions SCCS. Elle est utile pour examiner les changements entre différentes révisions d'un fichier.
edit
C'est un raccourci pour get -e. Il extrait une version d'un fichier SCCS et la rend modifiable pour l'utilisateur. Une fois les modifications terminées, un delta doit être créé pour enregistrer ces changements.
fix
Permet de supprimer un delta spécifique tout en conservant une copie des modifications. Ceci est utile pour corriger des erreurs mineures sans introduire de nouveaux deltas complexes. Il est généralement utilisé en conjonction avec '-r' pour spécifier le delta à corriger.
info
Affiche des informations sur les fichiers actuellement en cours d'édition (ceux qui ont été extraits avec get -e et qui attendent un delta). L'option '-b' permet d'ignorer les branches, et '-u' permet de filtrer par utilisateur. C'est un moyen de savoir qui travaille sur quoi.
print
Affiche des informations détaillées sur les fichiers SCCS, équivalent à utiliser la commande prs. Elle permet d'obtenir un résumé complet de l'état et de l'historique d'un fichier SCCS.
tell
Écrit une liste des fichiers en cours d'édition sur la sortie standard. Comme info, elle peut être filtrée par branche ('-b') ou par utilisateur ('-u', '-U').
unedit
Annule l'extraction d'un fichier pour édition sans créer de delta. Les modifications apportées depuis l'extraction sont perdues. Cette commande doit être utilisée avec prudence.

STATUT DE SORTIE

 0
Succès de l'opération.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Beaucoup des utilitaires SCCS acceptent des noms de répertoires comme opérandes ainsi que des noms de fichiers spécifiques. Les pseudo-utilitaires pris en charge par sccs ne sont pas décrits comme ayant cette capacité, mais rien ne leur interdit de le faire.

EXEMPLES

1.
Pour obtenir un fichier pour édition, l'éditer et produire un nouveau delta :
sccs get -e file.c
ex file.c
sccs delta file.c
2.
Pour obtenir un fichier d'un autre répertoire :
sccs -p /usr/src/sccs/s. get cc.c
ou : 
sccs get /usr/src/sccs/s.cc.c
3.
Pour faire un delta d'un grand nombre de fichiers dans le répertoire courant :
sccs delta *.c
4.
Pour obtenir une liste des fichiers en cours d'édition qui ne sont pas sur des branches :
sccs info -b
5.
Pour faire un delta de tout ce qui est édité par l'utilisateur courant :
sccs delta $(sccs tell -U)
6.
Dans un makefile, pour obtenir les fichiers source d'un fichier SCCS s'il n'existe pas déjà :
SRCS = <liste des fichiers source>
$(SRCS):
    sccs get $(REL) $@

RATIONALE

Les utilitaires sccs font partie de l'option XSI Development Utilities dans l'option XSI.

SCCS est une abréviation pour Source Code Control System. C'est un outil de suivi de la maintenance et de l'amélioration. Lorsqu'un fichier est placé sous SCCS, le système de contrôle de code source maintient le fichier et, lorsque des modifications sont apportées, les identifie et les stocke dans le fichier avec le code source et/ou la documentation originale. D'autres modifications étant apportées, elles sont également identifiées et conservées dans le fichier.

La récupération de l'original et de tout ensemble de modifications est possible. N'importe quelle version du fichier au fur et à mesure de son développement peut être reconstruite pour inspection ou modification supplémentaire. Des données historiques peuvent être stockées avec chaque version, documentant pourquoi les modifications ont été apportées, qui les a apportées et quand elles ont été apportées.

SYNOPSIS

sccs [-a|-c|-d|-g|-i|-l|-m|-p|-r|-s|-t|-u] [-b] [-d chemin] [-f fichier_sccs] [-i[ fichiers_inclus]] [-x[ fichiers_exclus]] [ arguments... ]

DESCRIPTION

L'utilitaire sccs est une interface pour le système SCCS (Source Code Control System). Il permet aux utilisateurs de gérer les versions des fichiers sources. SCCS est un système puissant pour le contrôle de version, bien qu'il soit considéré comme plus ancien que des systèmes comme Git ou Subversion.

Il permet d'enregistrer, de récupérer, de comparer et de suivre les modifications apportées aux fichiers au fil du temps.

OPTIONS

Les options disponibles dépendent de la commande spécifique à exécuter via sccs. Les options principales incluent :

  • -a : Ajoute un fichier au système SCCS.
  • -c : Vérifie l'intégrité d'un fichier SCCS.
  • -d : Supprime un fichier du système SCCS.
  • -g : Récupère une version spécifique d'un fichier.
  • -i : Insère des commentaires lors d'un enregistrement.
  • -l : Affiche les informations sur les modifications.
  • -m : Enregistre un fichier avec un message.
  • -p : Prépare un fichier pour l'édition.
  • -r : Enregistre les modifications apportées à un fichier.
  • -s : Affiche le statut d'un fichier.
  • -t : Permet de créer un nouveau fichier SCCS.
  • -u : Marque un fichier comme étant en cours d'édition.
  • -b : Permet l'utilisation de branches delta.
  • -d chemin : Spécifie le répertoire où se trouvent les fichiers SCCS.
  • -f fichier_sccs : Spécifie le nom du fichier SCCS à utiliser.
  • -i[ fichiers_inclus] : Inclut des fichiers spécifiques.
  • -x[ fichiers_exclus] : Exclut des fichiers spécifiques.

Le comportement exact des options peut varier en fonction de la version de SCCS et de l'implémentation. Les arguments sont généralement les noms des fichiers concernés.

FICHIERS

  • %Z%%Y%%X% : Fichier delta SCCS (%Z% est le préfixe, %Y% est le nom du fichier, %X% est le numéro de version).
  • s.nom_fichier : Représente le fichier SCCS original.

ENVIRONNEMENT

Aucune variable d'environnement spécifique n'est documentée pour cette commande dans la page de manuel standard. Cependant, les chemins d'accès aux binaires SCCS peuvent être affectés par la variable PATH.

DIAGNOSTICS

Les messages d'erreur indiquent généralement les problèmes rencontrés lors de l'accès aux fichiers SCCS, de la modification des versions, ou d'erreurs de syntaxe dans les commandes. Une documentation plus détaillée des codes d'erreur serait spécifique à chaque implémentation de SCCS.

BUGS

SCCS est un système ancien et peut présenter des limitations par rapport aux systèmes de contrôle de version modernes. Les bugs spécifiques dépendent de l'implémentation et de la version utilisée. Il est souvent recommandé d'utiliser des systèmes de contrôle de version plus récents et mieux entretenus si possible.
