NOM

scrontab - gére les fichiers crontab de Slurm

SYNOPIS

scrontab [-u utilisateur] fichier
scrontab [-u utilisateur] [ -e | -l | -r ]

DESCRIPTION

scrontab est utilisé pour définir, éditer et supprimer le crontab géré par Slurm d'un utilisateur. Ce fichier peut définir un certain nombre de tâches batch récurrentes à exécuter à un intervalle programmé.

Les lignes doivent être soit des commentaires commençant par '#', soit des espaces blancs, soit des entrées crontab valides, soit des définitions de variables personnalisées.

Les lignes commençant par #SCRON permettent de définir des options pour l'entrée crontab unique suivante. Les options sont toujours réinitialisées entre chaque entrée crontab. Les options incluent la plupart de celles disponibles pour la commande sbatch ; les détails sont disponibles dans la page de manuel sbatch(1).

Notez que l'exécution des tâches à l'heure préférée n'est pas garantie. Les tâches s'exécuteront pas plus fréquemment que demandé, mais sont gérées en définissant le champ BeginTime à la prochaine itération valide, et sont ensuite sujettes à des retards de mise en file d'attente. Le comportement exact dépendra de la configuration du site local. En raison de cette méthode d'implémentation, la tâche suivante de la série ne sera pas soumise avant la fin de la tâche précédente. Par exemple, si vous avez une tâche de surveillance programmée pour s'exécuter chaque minute sur un système chargé, si la tâche programmée pour démarrer à 08:20:00 n'est pas en mesure de démarrer avant 08:20:30 et qu'elle dure 35 secondes, alors la tâche de 08:21:00 sera ignorée et la tâche suivante sera programmée pour 08:22:00.

scrontab utilise la même syntaxe pour les spécificateurs de date et d'heure que cron. Chaque ligne a cinq champs qui ont les significations suivantes :

champ valeurs autorisées
----- --------------
minute 0-59
heure 0-23
jour du mois 1-31
mois 1-12 (ou nom)
jour de la semaine 0-7 (0 et 7 sont dimanche, ou utiliser le nom)

Un champ peut contenir un astérisque (*) qui signifie qu'il est valide pour toutes les valeurs autorisées pour la période de temps donnée. Les intervalles sont autorisés là où un intervalle est constitué de deux nombres avec un tiret entre eux. Le second nombre doit être supérieur au premier. Les listes sont autorisées, avec des virgules séparant les nombres ou les intervalles séparés. Les valeurs de pas peuvent être spécifiées en entrant une barre oblique (/), suivie de la valeur de pas, ce qui amène la tâche à s'exécuter à l'intervalle spécifié approprié pour ce champ.

Les variables personnalisées peuvent être définies comme dans un script shell régulier. Le caractère `$' introduit l'expansion de variable. L'expansion de paramètre simple est la seule variante d'expansion actuellement acceptée (c'est-à-dire que ${parameter} ou ${parameter:-word} ne sont pas pris en charge). L'expansion de variable n'aura lieu qu'au sein des commandes de tâche scrontab. Il n'est pas possible d'étendre des variables dans d'autres types de lignes (autres définitions de variables, commentaires ou entrées crontab). L'expansion se produira avant la soumission de la tâche, mais les définitions de variables resteront dans le script scrontab. Contrairement à crontab, les variables d'environnement de l'utilisateur sont ignorées.

OPTIONS

La première forme de cette commande est utilisée pour installer un nouveau crontab à partir d'un fichier nommé ou de l'entrée standard si le pseudo-nom de fichier « - » est donné.

-e
Éditer le crontab. Si un crontab n'existe pas déjà, un exemple par défaut (sans aucune entrée définie) sera fourni dans l'éditeur.
-l
Lister le crontab. (Affiche directement sur stdout.)
-r
Supprimer le crontab. Toutes les tâches définies par crontab en cours d'exécution continueront de s'exécuter mais ne seront plus récurrentes. Toutes les autres tâches définies par crontab seront annulées.
-u <utilisateur>
Éditer ou visualiser le crontab d'un utilisateur différent. La liste est permise aux opérateurs et administrateurs. L'édition/la suppression n'est autorisée que pour root et le compte SlurmUser.

OPTIONS SCRONTAB

scrontab vous permet d'utiliser des raccourcis pour spécifier certains intervalles de temps courants pour que le script spécifié s'exécute. Ceux-ci incluent les éléments suivants :

@yearly | @annually
La tâche deviendra éligible à 00:00 le 1er janvier chaque année.
@monthly
La tâche deviendra éligible à 00:00 le premier jour de chaque mois.
@weekly
La tâche deviendra éligible à 00:00 le dimanche de chaque semaine.
@daily | @midnight
La tâche deviendra éligible à 00:00 chaque jour.
@hourly
La tâche deviendra éligible à la première minute de chaque heure.
@elevenses
La tâche deviendra éligible à 11:00 chaque jour. (Ceci est une extension non standard.)
@fika
La tâche deviendra éligible à 15:00 chaque jour. (Ceci est une extension non standard.)
@teatime
La tâche deviendra éligible à 16:00 chaque jour. (Ceci est une extension non standard.)

VARIABLES D'ENVIRONNEMENT

VISUAL
Utilisé comme éditeur interactif s'il est défini.
EDITOR
Utilisé comme éditeur interactif s'il est défini et que VISUAL n'est pas défini.
SLURM_CONF
L'emplacement du fichier de configuration de Slurm.
SLURM_DEBUG_FLAGS
Spécifie les indicateurs de débogage à utiliser par scrontab. Voir DebugFlags dans la page de manuel slurm.conf(5) pour une liste complète des indicateurs. La variable d'environnement a la priorité sur le paramètre dans slurm.conf.

NOTES

scrontab n'est disponible que si l'option ScronParameters=enable a été activée dans slurm.conf.

scrontab créera un fichier temporaire dans le répertoire défini par la variable d'environnement TMPDIR. Si la variable n'est pas définie, /tmp sera utilisé.

Les tâches créées avec scrontab se voient attribuer un seul identifiant de tâche. Lorsqu'elles sont annulées, toutes les exécutions futures de la tâche seront également annulées. La définition de la tâche sera mise en commentaire dans le fichier scrontab de l'utilisateur.

L'utilisation de « scontrol requeue <id_tâche> » ignorera la prochaine exécution de la tâche cron et la replanifiera pour la prochaine heure disponible en fonction de l'expression cron.

EXEMPLES

Pour créer une tâche qui s'exécute au début de chaque heure, en utilisant la partition 'high', le compte 'sub1' et ayant un temps d'exécution de 1 minute, vous ajouteriez ce qui suit à scrontab :

DIR=/home/user1
#SCRON -p high
#SCRON -A sub1
#SCRON -t 1:00
@hourly $DIR/date.printer.job

Pour qu'une tâche s'exécute chaque mercredi, une heure sur deux pendant les heures de bureau, pendant les cinq premières minutes de chaque heure et à nouveau à la trente minute, vous ajouteriez ce qui suit à scrontab.

1-5,30 8-17/2 * * wed $DIR/example.job

LIMITATIONS

Le fuseau horaire du contrôleur Slurm sera utilisé pour évaluer les intervalles de répétition de chaque crontab. Les fuseaux horaires spécifiques à l'utilisateur ne sont pas pris en charge.
