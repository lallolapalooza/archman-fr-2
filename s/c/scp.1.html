SCP(1) Manuel des commandes générales SCP(1)

NOM

scp — Copie de fichiers sécurisée OpenSSH

SYNTAXE

scp [-346ABCOpqRrsTv] [-c chiffrement] [-D chemin_serveur_sftp] [-F config_ssh] [-i fichier_identite] [-J destination] [-l limite] [-o option_ssh] [-P port] [-S programme] [-X option_sftp] source ... cible

DESCRIPTION

scp copie des fichiers entre des hôtes sur un réseau.

scp utilise le protocole SFTP via une connexion ssh(1) pour le transfert de données, et utilise la même authentification et offre la même sécurité qu'une session de connexion.

scp demandera les mots de passe ou phrases de passe s'ils sont nécessaires pour l'authentification.

Les source et cible peuvent être spécifiés comme un chemin local, un hôte distant avec un chemin optionnel sous la forme [utilisateur@]hôte:[chemin], ou une URI sous la forme scp://[utilisateur@]hôte[:port][/chemin]. Les noms de fichiers locaux peuvent être rendus explicites en utilisant des chemins absolus ou relatifs pour éviter que scp ne traite les noms de fichiers contenant ‘:’ comme des spécificateurs d'hôte.

Lors de la copie entre deux hôtes distants, si le format URI est utilisé, un port ne peut pas être spécifié sur la cible si l'option -R est utilisée.

Les options sont les suivantes :

-3
Les copies entre deux hôtes distants sont transférées via l'hôte local. Ce mode est le comportement par défaut, mais voir aussi l'option -R pour copier des données directement entre deux hôtes distants. Notez que lors de l'utilisation du protocole SCP hérité (via l'indicateur -O), cette option sélectionne le mode batch pour le second hôte car scp ne peut pas demander les mots de passe ou phrases de passe pour les deux hôtes.
-4
Force scp à n'utiliser que des adresses IPv4.
-6
Force scp à n'utiliser que des adresses IPv6.
-A
Permet le transfert d'un agent ssh-agent(1) vers le système distant. Par défaut, aucun agent d'authentification n'est transféré.
-B
Sélectionne le mode batch (empêche de demander les mots de passe ou phrases de passe).
-C
Activation de la compression. Passe l'indicateur -C à ssh(1) pour activer la compression.
-c chiffrement
Sélectionne le chiffrement à utiliser pour crypter le transfert de données. Cette option est directement transmise à ssh(1).
-D chemin_serveur_sftp
Se connecte directement à un programme serveur SFTP local plutôt qu'à un serveur distant via ssh(1). Cette option peut être utile pour déboguer le client et le serveur.
-F config_ssh
Spécifie un fichier de configuration utilisateur alternatif pour ssh. Cette option est directement transmise à ssh(1).
-i fichier_identite
Sélectionne le fichier à partir duquel l'identité (clé privée) pour l'authentification par clé publique est lue. Cette option est directement transmise à ssh(1).
-J destination
Se connecte à l'hôte cible en établissant d'abord une connexion scp vers l'hôte de saut décrit par destination, puis en établissant une redirection TCP vers la destination ultime à partir de là. Plusieurs sauts peuvent être spécifiés séparés par des virgules. C'est un raccourci pour spécifier une directive de configuration ProxyJump. Cette option est directement transmise à ssh(1).
-l limite
Limite la bande passante utilisée, spécifiée en Kbit/s.
-O
Utilise le protocole SCP hérité pour les transferts de fichiers au lieu du protocole SFTP. Forcer l'utilisation du protocole SCP peut être nécessaire pour les serveurs qui n'implémentent pas SFTP, pour des raisons de compatibilité descendante pour des motifs spécifiques de caractères génériques de noms de fichiers et pour l'expansion des chemins avec un préfixe ‘~’ pour les serveurs SFTP plus anciens.
-o option_ssh
Peut être utilisé pour passer des options à ssh dans le format utilisé dans ssh_config(5). Ceci est utile pour spécifier des options pour lesquelles il n'y a pas de drapeau de commande scp séparé. Pour les détails complets des options listées ci-dessous, et leurs valeurs possibles, voir ssh_config(5).

-P port
Spécifie le port de connexion sur l'hôte distant. Notez que cette option est écrite avec un ‘P’ majuscule, car -p est déjà réservé pour la préservation des temps et des bits de mode du fichier.
-p
Préserve les temps de modification, les temps d'accès et les bits de mode du fichier source.
-q
Mode silencieux : désactive l'indicateur de progression ainsi que les messages d'avertissement et de diagnostic de ssh(1).
-R
Les copies entre deux hôtes distants sont transférées via l'hôte local par défaut. Cette option copie plutôt entre deux hôtes distants en se connectant à l'hôte d'origine et en exécutant scp dessus. Cela nécessite que scp s'exécutant sur l'hôte d'origine puisse s'authentifier sur l'hôte de destination sans demander de mot de passe.
-r
Copie récursivement des répertoires entiers. Notez que scp suit les liens symboliques rencontrés lors de la traversée de l'arborescence.
-S program
Nom du programme à utiliser pour la connexion chiffrée. Le programme doit comprendre les options de ssh(1).
-T
Désactive la vérification stricte des noms de fichiers. Par défaut, lors de la copie de fichiers d'un hôte distant vers un répertoire local, scp vérifie que les noms de fichiers reçus correspondent à ceux demandés en ligne de commande pour empêcher l'extrémité distante d'envoyer des fichiers inattendus ou non désirés. En raison des différences dans la manière dont divers systèmes d'exploitation et shells interprètent les jokers de noms de fichiers, ces vérifications peuvent entraîner le rejet de fichiers désirés. Cette option désactive ces vérifications au prix d'une confiance totale dans le fait que le serveur n'enverra pas de noms de fichiers inattendus.
-v
Mode verbeux. Fait en sorte que scp et ssh(1) affichent des messages de débogage sur leur progression. Ceci est utile pour le débogage des problèmes de connexion, d'authentification et de configuration.
-X sftp_option
Spécifie une option qui contrôle certains aspects du comportement du protocole SFTP. Les options valides sont :
nrequests=value
Contrôle le nombre de requêtes de lecture ou d'écriture SFTP simultanées qui peuvent être en cours à un moment donné pendant un téléchargement ou un téléversement. Par défaut, 64 requêtes peuvent être actives simultanément.
buffer=value
Contrôle la taille maximale du tampon pour une seule opération de lecture/écriture SFTP utilisée lors d'un téléchargement ou d'un téléversement. Par défaut, un tampon de 32 Ko est utilisé.

STATUT DE SORTIE

L'utilitaire scp se termine avec le statut 0 en cas de succès, et > 0 si une erreur se produit.

VOIR AUSSI

sftp(1), ssh(1), ssh-add(1), ssh-agent(1), ssh-keygen(1), ssh_config(5), sftp-server(8), sshd(8)

HISTORIQUE

scp est basé sur le programme rcp du code source BSD des Regents de l'Université de Californie.

Depuis OpenSSH 9.0, scp utilise le protocole SFTP pour les transferts par défaut.

ATTENTION

Le protocole SCP hérité (sélectionné par l'option -O) nécessite l'exécution du shell de l'utilisateur distant pour effectuer la mise en correspondance des motifs glob(3). Cela nécessite une mise entre guillemets soigneuse de tous les caractères qui ont une signification spéciale pour le shell distant, tels que les caractères de guillemets.

NAME

scp - secure copy (remote file copy program)

SYNOPSIS

scp [-12346BCpqrv] [-c cipher] [-F ssh_config] [-i identity_file] [-l limit] [-o ssh_option] [-P port] [-S program] [[user@]host1:]file1 ... [[user@]host2:]file2

DESCRIPTION

scp est un utilitaire de ligne de commande pour copier des fichiers de manière sécurisée entre des hôtes sur un réseau. Il utilise le protocole SSH pour le transfert de données et l'authentification, garantissant ainsi que toutes les communications sont cryptées. scp est basé sur le programme rcp et partage la plupart de sa syntaxe.

La syntaxe générale est la suivante :

scp [options] source destination

La source et la destination peuvent être des fichiers locaux ou des fichiers distants. Un fichier distant est spécifié sous la forme [user@]host:path.

Quelques exemples :

  • Copier un fichier local vers un hôte distant :
    scp local_file user@remote_host:/remote/directory/
  • Copier un fichier distant vers un hôte local :
    scp user@remote_host:/remote/file /local/directory/
  • Copier un fichier d'un hôte distant vers un autre :
    scp user1@host1:/path/to/file user2@host2:/path/to/destination
  • Copier un répertoire de manière récursive :
    scp -r local_directory user@remote_host:/remote/directory/

OPTIONS

scp prend en charge un large éventail d'options, dont la plupart sont transmises à ssh. Les options courantes incluent :

-1, -2, -3, -4, -6
Force l'utilisation de la version 1, 2, 3, 4 ou 6 du protocole SCP. Par défaut, scp tente d'utiliser la version 3.
-B
Mode batch. Désactive la demande de mot de passe et les autres dialogues interactifs.
-C
Active la compression des données. Utile sur des connexions lentes.
-c cipher
Choisit l'algorithme de chiffrement à utiliser pour le cryptage des données. Voir ssh_config(5) pour plus de détails.
-F ssh_config
Spécifie le fichier de configuration client SSH alternatif. Voir ssh_config(5).
-i identity_file
Sélectionne le fichier de clé privée pour l'authentification.
-l limit
Limite la bande passante par seconde en kilobits.
-o ssh_option
Permet de passer des options directement à ssh. Par exemple : -o "StrictHostKeyChecking=no".
-P port
Port de connexion sur la machine distante. Notez que la majuscule est importante.
-p
Préserve les temps de modification, d'accès et les modes des fichiers sources.
-q
Mode silencieux. Désactive la barre de progression et les messages d'erreur.
-r
Copie récursivement les répertoires.
-S program
Spécifie le programme à utiliser pour le tunnel chiffré. Il doit gérer les options d'authentification et de connexion de ssh(1).
-v
Mode verbeux. Produit des messages de débogage sur l'avancement de la connexion et de la transaction.

EXIT STATUS

scp retourne 0 en cas de succès, et une valeur différente de zéro en cas d'erreur.

CAVEATS

scp est obsolète et sftp est le protocole de transfert de fichiers recommandé. Cependant, scp est toujours largement utilisé et disponible.

Il est important de noter que scp utilise le protocole SCP, qui est différent du protocole SFTP. Le protocole SCP a certaines limitations et n'est pas aussi flexible que SFTP.
