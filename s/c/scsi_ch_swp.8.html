NOM

scsi_ch_swp - modifier la protection en écriture logicielle SCSI et les paramètres du périphérique bloc

SYNTAXE

scsi_ch_swp [--help] [--set 0|1] [--verbose] [--wr] PÉRIPH_BLOC

DESCRIPTION

Ce script shell bash tente de lire ou de modifier le bit de protection en écriture logicielle (SWP) dans la page de mode Contrôle en utilisant l'utilitaire sdparm. Si la modification réussit, il utilise l'utilitaire blockdev pour modifier le paramètre de lecture-écriture ou lecture seule de PÉRIPH_BLOC en conséquence. Ce script n'est disponible que sous Linux car l'utilitaire blockdev est spécifique à Linux.

Si la modification du bit SWP est prise en charge, la définition du bit SWP rend PÉRIPH_BLOC en lecture seule au niveau du périphérique (disque) lui-même. La suppression du bit SWP rend PÉRIPH_BLOC en lecture-écriture, ce qui est généralement le réglage par défaut au démarrage du périphérique (disque).

Si aucune option n'est donnée, l'état actuel du bit SWP est affiché (en utilisant sdparm) ainsi que le bit RO de blockdev. S'ils sont tous deux à 1, PÉRIPH_BLOC est en mode lecture seule ; s'ils sont tous deux à 0, PÉRIPH_BLOC est en mode lecture-écriture.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-h, --help
affiche le message d'utilisation puis quitte.
-s, --set 0|1
lorsque 0 est donné, le bit SWP dans la page de mode Contrôle est effacé (c'est-à-dire mis à 0) à l'aide de sdparm ; et blockdev est utilisé pour mettre PÉRIPH_BLOC en mode lecture-écriture. Lorsque 1 est donné, le bit SWP dans la page de mode Contrôle est défini à l'aide de sdparm ; et blockdev est utilisé pour mettre PÉRIPH_BLOC en mode lecture seule. Le comportement par défaut (c'est-à-dire lorsque cette option n'est pas donnée) consiste à lire l'état du bit SWP et le mode lecture seule de PÉRIPH_BLOC et à afficher ces valeurs.
-v, --verbose
augmente le niveau de verbosité.
-w, --wr
lorsque PÉRIPH_BLOC est en mode lecture seule, Linux n'autorise généralement pas PÉRIPH_BLOC à être ouvert en lecture-écriture par sdparm, donc l'action par défaut de ce script consiste à utiliser l'option --readonly de sdparm lorsque --set 0 a été invoqué. Il est possible que PÉRIPH_BLOC soit un périphérique générique (par exemple, /dev/sg3) qui a une interprétation différente du drapeau d'ouverture en lecture seule et peut échouer. Pour ces cas rares, l'option --wr fait en sorte que sdparm ouvre PÉRIPH_BLOC en lecture-écriture lorsque --set 0 est invoqué.

STATUT DE SORTIE

Le statut de sortie de ce script est 0 en cas de succès. Sinon, le statut de sortie est celui de l'utilitaire sdparm ou blockdev, selon le dernier appelé. Voir la page de manuel de sdparm(8).
