SCDAEMON(1) GNU Privacy Guard 2.4 SCDAEMON(1)

NOM

scdaemon - Démon de carte à puce pour le système GnuPG

SYNTAXE

scdaemon [--homedir rép] [--options fichier] [options] --server
scdaemon [--homedir rép] [--options fichier] [options] --daemon [ligne_de_commande]

DESCRIPTION

Le scdaemon est un démon qui gère les cartes à puce. Il est généralement invoqué par gpg-agent et n'est en général pas utilisé directement.

COMMANDES

Les commandes ne sont pas distinguées des options, à l'exception du fait qu'une seule commande est autorisée.

--version
Affiche la version du programme et les informations de licence. Notez que vous ne pouvez pas abréger cette commande.
--help, -h
Affiche un message d'utilisation résumant les options de ligne de commande les plus utiles. Notez que vous ne pouvez pas abréger cette commande.
--dump-options
Affiche une liste de toutes les options et commandes disponibles. Notez que vous ne pouvez pas abréger cette commande.
--server
S'exécute en mode serveur et attend les commandes sur stdin. Le mode par défaut consiste à créer un socket et à écouter les commandes dessus.
--multi-server
S'exécute en mode serveur et attend les commandes sur stdin ainsi que sur un socket Unix Domain supplémentaire. La commande serveur GETINFO peut être utilisée pour obtenir le nom de ce socket supplémentaire.
--daemon
Exécute le programme en arrière-plan. Cette option est requise pour l'empêcher de s'exécuter accidentellement en arrière-plan.

OPTIONS

--options fichier
Lit la configuration à partir de fichier au lieu du fichier de configuration par défaut par utilisateur. Le fichier de configuration par défaut est nommé ‘scdaemon.conf’ et est attendu dans le répertoire ‘.gnupg’ directement sous le répertoire personnel de l'utilisateur.
--homedir rép
Définit le nom du répertoire personnel à rép. Si cette option n'est pas utilisée, le répertoire personnel est par défaut ‘~/.gnupg’. Elle n'est reconnue que lorsqu'elle est donnée sur la ligne de commande. Elle remplace également tout répertoire personnel indiqué par la variable d'environnement ‘GNUPGHOME’ ou (sur les systèmes Windows) par le biais de l'entrée de registre HKCU\Software\GNU\GnuPG:HomeDir.

Sur les systèmes Windows, il est possible d'installer GnuPG comme application portable. Dans ce cas, seule cette option de ligne de commande est prise en compte, tous les autres moyens de définir un répertoire personnel sont ignorés.

-v
--verbose
Affiche des informations supplémentaires pendant l'exécution. Vous pouvez augmenter la verbosité en donnant plusieurs commandes verbeuses à gpgsm, comme ‘-vv’.
--debug-level niveau
Sélectionne le niveau de débogage pour l'investigation des problèmes. niveau peut être une valeur numérique ou un mot-clé :
none
Aucun débogage. Une valeur inférieure à 1 peut être utilisée à la place du mot-clé.
basic
Quelques messages de débogage de base. Une valeur comprise entre 1 et 2 peut être utilisée à la place du mot-clé.
advanced
Messages de débogage plus verbeux. Une valeur comprise entre 3 et 5 peut être utilisée à la place du mot-clé.
expert
Messages encore plus détaillés. Une valeur comprise entre 6 et 8 peut être utilisée à la place du mot-clé.
guru
Tous les messages de débogage possibles. Une valeur supérieure à 8 peut être utilisée à la place du mot-clé. La création de fichiers de trace de hachage n'est activée que si le mot-clé est utilisé.

La manière dont ces messages sont mappés aux drapeaux de débogage réels n'est pas spécifiée et peut changer avec les futures versions de ce programme. Ils sont cependant soigneusement sélectionnés pour aider au mieux au débogage.

Toutes les options de débogage sont sujettes à modification et ne doivent donc pas être utilisées par un programme applicatif. Comme leur nom l'indique, elles ne servent qu'à aider au débogage des problèmes.
--debug drapeaux
Définit les drapeaux de débogage. Tous les drapeaux sont combinés par OR et drapeaux peut être donné en syntaxe C (par exemple, 0x0042) ou comme une liste de noms de drapeaux séparés par des virgules. Pour obtenir une liste de tous les drapeaux pris en charge, le mot seul "help" peut être utilisé. Cette option n'est utile que pour le débogage et son comportement peut changer à tout moment sans préavis.
--debug-all
Identique à --debug=0xffffffff
--debug-wait n
Lors de l'exécution en mode serveur, attend n secondes avant d'entrer dans la boucle de traitement réelle et affiche le PID. Cela laisse le temps d'attacher un débogueur.
--debug-ccid-driver
Active la sortie de débogage du pilote CCID inclus pour les cartes à puce. Utiliser cette option deux fois activera également un certain traçage du protocole T=1. Notez que cette option peut révéler des données sensibles.
--debug-disable-ticker
Cette option désactive toutes les fonctions de "ticker" telles que la vérification de l'insertion des cartes.
--debug-allow-core-dump
Pour des raisons de sécurité, nous ne créons pas de vidage mémoire lorsque le processus s'arrête. À des fins de débogage, il est parfois préférable d'autoriser le vidage mémoire. Cette option l'active et change également le répertoire de travail en ‘/tmp’ lors de l'exécution en mode --server.
--debug-log-tid
Cette option ajoute un identifiant de thread au PID dans la sortie du journal.
--debug-assuan-log-cats cats
Modifie les catégories de journalisation Libassuan actives pour cats. La valeur pour cats est un entier non signé donné dans la syntaxe C habituelle. Une valeur de 0 passe à une catégorie par défaut. Si cette option n'est pas utilisée, les catégories sont récupérées de la variable d'environnement ASSUAN_DEBUG. Notez que cette option n'a d'effet que si le drapeau de débogage Assuan a également été utilisé avec l'option --debug. Pour une liste des catégories, consultez le manuel Libassuan.
--no-detach
Ne détache pas le processus de la console. Ceci est principalement utile pour le débogage.
--listen-backlog n
Définit la taille de la file d'attente pour les connexions en attente. La valeur par défaut est 64. Cette option n'a d'effet que si --multi-server est également utilisé.
--log-file fichier
Ajoute toute la sortie de journalisation au fichier. Ceci est très utile pour voir ce que fait réellement l'agent. Utilisez ‘socket://’ pour enregistrer dans un socket.
--pcsc-shared
Utilise le mode partagé pour accéder à la carte via PC/SC. C'est une option un peu dangereuse car Scdaemon suppose un accès exclusif à la carte et, par exemple, met en cache certaines informations de la carte. N'utilisez cette option que si vous savez ce que vous faites.
--pcsc-driver bibliothèque
Utilise bibliothèque pour accéder au lecteur de carte à puce. La valeur par défaut actuelle sous Unix est ‘libpcsclite.so’ et sous Windows ‘winscard.dll’. Au lieu d'utiliser cette option,

--disable-ccid
Le pilote CCID intégré pour les périphériques conformes CCID peut être disponible lorsque libusb a été détecté au moment de la compilation, et il est utilisé pour accéder au lecteur de carte à puce. Si un accès via le pilote PC/SC est nécessaire, veuillez configurer cette option pour désactiver la prise en charge du pilote CCID (le cas échéant). Dans GnuPG 2.2, il y avait un mécanisme de repli du pilote CCID vers le pilote PC/SC. Ce mécanisme de repli fonctionnait car scdaemon dans GnuPG 2.2 ne prenait en charge qu'un seul token/lecteur. Pour prendre en charge plusieurs tokens/lecteurs simultanément, le mécanisme de repli a été supprimé.
--reader-port numéro_ou_chaîne
Cette option peut être utilisée pour spécifier le port du terminal de carte. Une valeur de 0 fait référence au premier périphérique série ; ajoutez 32768 pour accéder aux périphériques USB. La valeur par défaut est 32768 (premier périphérique USB). Les lecteurs PC/SC ou CCID pourraient nécessiter une chaîne ici ; exécutez le programme en mode verbeux pour obtenir une liste des lecteurs disponibles. La valeur par défaut est alors le premier lecteur trouvé.

Pour obtenir une liste des lecteurs CCID disponibles, vous pouvez utiliser la commande suivante :

  echo scd getinfo reader_list \
    | gpg-connect-agent --decode | awk '/^D/ {print $2}'
--card-timeout n
Cette option est obsolète. Dans GnuPG 2.0, elle était utilisée pour la commande DISCONNECT afin de contrôler les problèmes de temporisation. Comme la commande DISCONNECT fonctionne de manière synchrone, elle n'a aucun effet.
--enable-pinpad-varlen
Veuillez spécifier cette option lorsque le lecteur de carte prend en charge une entrée de longueur variable pour le pavé numérique (par défaut, c'est non). Pour les lecteurs connus (listés dans ccid-driver.c et apdu.c), cette option n'est pas nécessaire. Notez que si votre lecteur de carte ne prend pas en charge la saisie de longueur variable mais que vous souhaitez l'utiliser, vous devez spécifier votre requête de pavé numérique sur votre carte.
--disable-pinpad
Même si un lecteur de carte est équipé d'un pavé numérique, ne tentez pas de l'utiliser.
--deny-admin
Cette option désactive l'utilisation des commandes de classe d'administration pour les applications de cartes où cela est pris en charge. Actuellement, nous le prenons en charge pour la carte OpenPGP. Cette option est utile pour empêcher l'accès accidentel aux commandes de classe d'administration qui pourraient à terme verrouiller la carte par des numéros PIN incorrects. Notez que les versions de GnuPG antérieures à 2.0.11 disposaient de l'option --allow-admin qui était nécessaire pour utiliser ces commandes d'administration. Cette option n'a plus d'effet aujourd'hui car la valeur par défaut est désormais d'autoriser les commandes d'administration.
--disable-application nom
Cette option désactive l'utilisation de l'application de carte nommée nom. Ceci est principalement utile pour le débogage ou si une application de priorité inférieure devrait être utilisée par défaut.
--application-priority liste_noms
Cette option permet de modifier l'ordre dans lequel les applications d'une carte sont essayées si aucune application spécifique n'a été demandée. liste_noms est une liste de noms d'applications séparés par des espaces ou des virgules. Les noms inconnus sont simplement ignorés. Les applications non mentionnées dans la liste sont placées dans l'ordre précédent à la fin de la nouvelle liste de priorités.

Pour obtenir la liste des applications actives actuelles, utilisez

    gpg-connect-agent 'scd getinfo app_list' /bye

Toutes les options longues peuvent également être spécifiées dans le fichier de configuration après avoir supprimé les deux tirets de début.

APPLICATIONS DE CARTE

scdaemon prend en charge les applications de cartes comme décrit ci-dessous.

L'application de carte OpenPGP ``openpgp''

 

Cette application n'est actuellement utilisée que par gpg, mais elle pourrait également être utile avec gpgsm à l'avenir. Les versions 1 et 2 de la carte sont prises en charge.

La spécification de cette carte est disponible à l'adresse
(https://gnupg.org/ftp/specs/) .

L'application de carte Telesec NetKey ``nks''

 

C'est l'application principale des cartes Telesec disponibles en Allemagne. C'est un sur-ensemble de la carte allemande DINSIG. La carte est utilisée par gpgsm.

L'application de carte DINSIG ``dinsig''

 

Il s'agit d'une application décrite dans le projet de norme allemande DIN V 66291-1. Elle est destinée à être utilisée par les cartes prenant en charge la loi allemande sur la signature et ses règlements (SigG et SigV).

L'application de carte PKCS#15 ``p15''

 

C'est un cadre commun pour les applications de cartes à puce. Il est utilisé par gpgsm.

L'application de carte Geldkarte ``geldkarte''

 

Il s'agit d'une application simple pour afficher des informations d'une Geldkarte allemande. La Geldkarte est une application de carte de débit pour de petites sommes qui accompagne presque toutes les cartes bancaires allemandes.

L'application de carte SmartCard-HSM ``sc-hsm''

 

Cette application ajoute une prise en charge en lecture seule pour les clés et certificats stockés sur un (http://www.smartcard-hsm.com, SmartCard-HSM).

Pour générer des clés et stocker des certificats, vous pouvez utiliser (https://github.com/OpenSC/OpenSC/wiki/SmartCardHSM, OpenSC) ou les outils de (http://www.openscdp.org, OpenSCDP).

Les cartes SmartCard-HSM nécessitent un lecteur de carte qui prend en charge les APDU de longueur étendue.

L'application de carte non définie ``undefined''

 

Il s'agit d'une application fictive pour permettre l'utilisation de la commande APDU même si aucune application prise en charge n'est trouvée sur la carte. Cette application n'est pas utilisée automatiquement mais doit être explicitement demandée à l'aide de la commande SERIALNO.

EXEMPLES

$ scdaemon --server -v

FICHIERS

Il existe quelques fichiers de configuration pour contrôler certains aspects de l'opération de scdaemon. Sauf indication contraire, ils sont attendus dans le répertoire personnel actuel (voir : [option --homedir]).

scdaemon.conf
C'est le fichier de configuration standard lu par scdaemon au démarrage. Il peut contenir toute option longue valide ; les deux tirets de début ne doivent pas être entrés et l'option ne peut pas être abrégée. Ce nom par défaut peut être modifié sur la ligne de commande (voir : [option --options]).
scd-event
Si ce fichier est présent et exécutable, il sera appelé à chaque changement d'état du lecteur de carte. Un exemple de ce script est fourni avec la distribution source. Cette option est obsolète au profit de DEVINFO --watch.
reader_n.status
Ce fichier est créé par scdaemon pour informer les autres applications des changements d'état des lecteurs. Son utilisation est maintenant obsolète au profit de ‘scd-event’.

    SCdaemon(1)

    SCdaemon - Démon du sous-système de carte à puce

    NOM

    scdaemon - Démon du sous-système de carte à puce

    SYNTAXE

    scdaemon [options]

    DESCRIPTION

    scdaemon est un démon qui gère l'accès aux cartes à puce et aux lecteurs de cartes. Il est utilisé par des applications telles que GnuPG pour interagir avec des cartes à puce contenant des clés cryptographiques.

    OPTIONS

    scdaemon accepte les options suivantes :

    • --server : Lance scdaemon en mode serveur.
    • --daemonize : Lance scdaemon en arrière-plan.
    • --debug : Active la journalisation de débogage.
    • --log-file FILE : Écrit les messages de journalisation dans le fichier FILE.
    • --pid-file FILE : Écrit le PID du démon dans le fichier FILE.
    • --socket FILE : Utilise le fichier FILE comme socket de communication.
    • --card-timeout SECONDS : Définit le délai d'attente pour la détection de carte à SECONDES.
    • --reader-timeout SECONDS : Définit le délai d'attente pour la détection de lecteur à SECONDES.

    APPLICATIONS DE CARTE

    scdaemon peut interagir avec diverses applications de carte à puce, telles que :

    • OpenPGP
    • PKCS#11

    EXEMPLES

    Pour lancer scdaemon en mode serveur et en arrière-plan :

    scdaemon --server --daemonize

    Pour lancer scdaemon avec la journalisation de débogage activée :

    scdaemon --debug

    FICHIERS

    • /run/pcscd/pcscd.comm : Socket de communication par défaut.
    • /etc/scdaemon.conf : Fichier de configuration.
