NAME

scanmem - localise et modifie les variables dans un processus en cours d'exécution.

SYNOPSIS

scanmem [options] [pid-du-programme-cible]

DESCRIPTION

scanmem est un utilitaire de débogage interactif qui peut être utilisé pour isoler l'adresse d'une variable dans un processus en cours d'exécution en balayant successivement l'espace d'adressage du processus à la recherche de valeurs correspondantes.
En informant scanmem de l'évolution de la valeur de la variable au fil du temps, il peut déterminer la ou les emplacements réels de la variable en éliminant successivement les non-correspondances.
scanmem détermine où chercher en recherchant des mappages avec la permission de lecture/écriture, ceux-ci sont désignés sous le nom de régions. Les utilisateurs peuvent éliminer les régions qui, selon eux, ne sont pas liées à la variable cible (par exemple, situées dans une bibliothèque partagée sans rapport avec la variable en question), ce qui améliorera la vitesse de l'analyse, qui peut initialement être assez lente dans les grands programmes.

Une fois qu'une variable a été trouvée, scanmem peut surveiller la variable, ou la modifier à une valeur spécifiée par l'utilisateur, soit une seule fois, soit en continu sur une période de temps.

scanmem fonctionne de manière similaire aux « pokefinders » autrefois couramment utilisés pour tricher aux jeux vidéo, cette fonction est une bonne démonstration de la façon d'utiliser scanmem et est utilisée dans la documentation.

USAGE

scanmem doit être appelé avec l'identifiant de processus du programme que vous souhaitez déboguer comme argument. Une fois démarré, scanmem accepte des commandes interactives. Celles-ci sont décrites ci-dessous, cependant, entrer help à l'invite > vous permettra d'accéder à la documentation en ligne de scanmem.

Le pid-du-programme-cible peut être spécifié en décimal, hexadécimal ou octal en utilisant la notation standard du langage C (préfixe 0x pour l'hexadécimal, préfixe 0 pour l'octal, tout le reste est supposé être décimal).

-p, --pid=pid
Définit le pid-du-programme-cible.
-c, --command=cmd1[;cmd2][;...]
Exécute les commandes données (séparées par « ; ») avant de démarrer le shell interactif.
-v, --version
Affiche la version et quitte.
-h, --help
Affiche une courte description des options de la ligne de commande, puis quitte.
-d, --debug
Exécute en mode débogage, plus d'informations seront affichées.
-e, --errexit
Quitte en cas d'erreur lors des commandes initiales, ignoré en mode interactif.

COMMANDS

En mode interactif, scanmem affiche un nombre décimal suivi de >, le nombre représente le nombre actuel de candidats possibles pour la variable cible connus. L'absence de ce nombre indique qu'aucune variable possible n'a encore été éliminée.
Le type de données de scan par défaut est « int ». Il peut être modifié avec la commande option.

n
Où n représente n'importe quel nombre en décimal, octal ou hexadécimal, cette commande indique à scanmem que la valeur actuelle de la variable cible est exactement n. scanmem commencera une recherche dans tout l'espace d'adressage, ou dans les correspondances connues existantes (le cas échéant), éliminant toute variable qui n'a pas cette valeur.
n..m
C'est comme la commande n mais scanmem recherche une plage de nombres comprise entre n et m inclus à la place.
>, <, +, -, =, !=
Les commandes suivantes sont extrêmement utiles pour localiser une variable dont la valeur exacte n'est pas visible, mais dont l'évolution est observable, par exemple une barre de vie. Ces commandes ne peuvent généralement pas être utilisées pour le premier scan, mais il existe quelques exceptions : > n, < n, = n et != n.
> [n]
Si n est donné, correspond aux valeurs supérieures à n. Sinon, correspond à toutes les valeurs qui ont augmenté.
< [n]
Si n est donné, correspond aux valeurs inférieures à n. Sinon, correspond à toutes les valeurs qui ont diminué.
+ [n]
Si n est donné, correspond aux valeurs qui ont augmenté de n. Sinon, correspond à toutes les valeurs qui ont augmenté (identique à >).
- [n]
Si n est donné, correspond aux valeurs qui ont diminué de n. Sinon, correspond à toutes les valeurs qui ont diminué (identique à <).
= [n]
Si n est donné, correspond aux valeurs égales à n (identique à n). Sinon, correspond à toutes les valeurs qui n'ont pas changé.
!= [n]
Si n est donné, correspond aux valeurs différentes de n. Sinon, correspond à toutes les valeurs qui ont changé.
snapshot
Correspond à n'importe quelle valeur. Ceci est utile lorsqu'une valeur ou une plage initiale n'est pas connue pour les analyses ultérieures avec >, <, +, -, = et !=.
" texte
Recherche le texte fourni en mémoire si le type de données de scan est réglé sur « string ».
update
Analyse le processus actuel, obtenant les valeurs actuelles de toutes les correspondances. Ces valeurs peuvent être consultées avec list, et sont également les anciennes valeurs auxquelles scanmem se compare lors de l'utilisation de >, < ou =. Cette commande est équivalente à une commande de recherche où toutes les correspondances actuelles sont respectées.
list [max_to_print]
Liste jusqu'à max_to_print (par défaut : 10k) candidats possibles actuellement connus, y compris leur adresse, leur ID de région, leur décalage de correspondance, leur type de région, leur dernière valeur connue et les types de valeurs possibles. La valeur dans la première colonne est l'ID de correspondance, et peut être utilisée conjointement avec la commande delete pour éliminer les correspondances.

Le décalage de correspondance est déterminé en soustrayant l'adresse de chargement du fichier ELF associé ou de la région de l'adresse. Il peut être utilisé pour contourner l'aléatoirisation de l'espace d'adressage (ASLR).

delete ensemble-d-ids-correspondance
Supprime les correspondances dans l'ensemble-d-ids-correspondance. Les ids-correspondance peuvent être trouvés dans la sortie de la commande list. Notation d'ensemble : [!][..a](,b..c | d, ...)[e..].
Pour supprimer toutes les correspondances connues, voir la commande reset.
Pour supprimer toutes les correspondances associées à une bibliothèque particulière, voir la commande dregion, qui supprime également toutes les correspondances associées.
Veuillez noter que les ids-correspondance peuvent être recalculés après la suppression ou l'ajout de correspondances.
watch id-correspondance
Surveille la valeur de l'id-correspondance, et affiche sa valeur lorsqu'elle change. Chaque changement est affiché avec un horodatage, vous pouvez interrompre cette commande avec ^C pour arrêter la surveillance.
set [ensemble-d-ids-correspondance=]valeur[/delai] [...]
Définit la valeur spécifiée dans les numéros de correspondance spécifiés dans l'ensemble-d-ids-correspondance, ou si seulement valeur est spécifiée, toutes les correspondances connues. valeur peut être spécifiée en notation standard du langage C. Tous les correspondances connues, ainsi que leurs ids-correspondance, peuvent être affichés à l'aide de la commande list. Plusieurs ensembles-d-ids-correspondance peuvent être spécifiés, terminés par un signe =. Notation d'ensemble : [!][..a](,b..c | d, ...)[e..].
Pour définir une valeur en continu, ajoutez à la commande / suivi du nombre de secondes à attendre entre chaque définition. Vous pouvez interrompre la commande set avec ^C pour revenir à l'invite scanmem. Cela peut être utilisé pour maintenir la valeur d'une variable qui diminue avec le temps, par exemple un minuteur qui est décrémenté chaque seconde peut être réglé à 100 toutes les 10 secondes pour empêcher toute propriété de changer.

write type_valeur adresse valeur
Définit manuellement la valeur de la variable à l'adresse spécifiée.
Les noms de type_valeur sont susceptibles de changer dans différentes versions de scanmem. Pour plus d'informations, utilisez la commande `help write`.
dump adresse longueur [nom_fichier]
Extrait la région mémoire à partir de adresse sur une longueur de longueur dans un format lisible par l'homme.

Si nom_fichier est fourni, les données seront enregistrées dans le fichier, sinon les données seront affichées sur la sortie standard.

pid [nouveau-pid]
Affiche l'identifiant du processus du programme cible actuel, ou change la cible pour nouveau-pid, ce qui réinitialisera les régions et les correspondances existantes.
reset
Oublie toutes les régions et correspondances connues et recommence.
lregions
Liste toutes les régions connues. Ceci peut être utilisé en combinaison avec la commande dregion pour éliminer les régions que l'utilisateur estime ne pas être liées à la variable en question, réduisant ainsi l'espace d'adressage nécessaire à la recherche. La valeur dans la première colonne est l' id_région qui doit être passé à la commande dregion. Outre l'adresse de départ, la taille et le chemin (si applicable) sont également affichés. Ceci peut être utilisé pour éliminer les régions situées dans des bibliothèques partagées qui sont peu susceptibles d'être pertinentes pour la variable requise.

Pour les experts : Le type de région et l'adresse de chargement sont également affichés. Les types sont "exe" (exécutable), "code" (bibliothèque), "heap", "stack" ou "misc" (tout le reste). L'adresse de chargement est l'emplacement mémoire où un fichier ELF (exécutable/bibliothèque) a été chargé. Ceci aide à convertir entre les adresses en mémoire et dans le fichier ELF associé. Si la région n'appartient pas à un fichier ELF, alors elle est identique à l'adresse de départ.

dregion ensemble_id_régions
Supprime les régions dans ensemble_id_régions, ainsi que toutes les correspondances de la liste des correspondances. Notation d'ensemble : [!][..a](,b..c | d, ...) [e..].
Les id_régions peuvent être trouvés dans la sortie de la commande lregions.
option nom valeur
Modifie les options à l'exécution. Par exemple, le type de données de scan peut être modifié. Voir `help option` pour tous les noms/valeurs possibles.
shell commande_shell
Exécute commande_shell en utilisant /bin/sh, puis retourne.
show info
Affiche des informations relatives à info - voir `help show` pour les détails.
version
Affiche la version de scanmem utilisée.
help
Affiche un bref résumé des commandes disponibles.
exit
Se détache du programme cible et quitte immédiatement.

EXEMPLES

Tricher à nethack, sur les systèmes où nethack n'est pas installé sgid.

ATTENTION : scanmem nécessite généralement des privilèges root. Voir PROBLÈMES CONNUS pour les détails.

Seize correspondances potentielles ont été trouvées. Ceci est également affiché dans l'invite. Beaucoup d'entre elles sont assez non pertinentes, car elles font partie de la pile, appartiennent à des bibliothèques ou à des fichiers mappés en mémoire divers. Même le tas est peu probable pour un vieux jeu en ligne de commande. Nous pourrions faire en sorte que scanmem les élimine manuellement en utilisant la commande delete, cependant, il suffit d'attendre que la quantité d'or change et de dire à scanmem la nouvelle valeur. Je trouve un peu plus d'or, et je dis à scanmem la nouvelle valeur, 83.

16> 83
..........info: nous avons actuellement 1 correspondance.
info: correspondance identifiée, utilisez "set" pour modifier la valeur.
info: entrez "help" pour d'autres commandes.
1> list
[ 0]       7b09e0,  1 +       3b09e0,   exe, 83, [I64 I32 I16 I8 ]

Une seule des 16 correspondances originales a maintenant la valeur 83, donc c'est là que la quantité d'or est stockée. Je vais essayer de la régler à 10 000 pièces.

1> set 10000
info: définition de *0x7b09e0 à 0x2710...
1>

Le statut résultant de nethack :

Dlvl:1  $:10000 HP:15(15) Pw:2(2) AC:7  Exp:1

Conclusion : Nous avons trouvé et modifié la valeur de l'or en tant que I32 dans la mémoire statique de l'exécutable à l'adresse mémoire virtuelle 0x7b09e0. Cette adresse appartient à la région avec l'id 1.

Il est maintenant important de savoir s'il s'agit d'un exécutable indépendant de la position (PIE). Nous listons les régions pour cela et vérifions l'adresse de chargement de l'exécutable.

1> lregions
[ 0]       79f000,  69632 octets,   exe,       400000, rw-, /usr/lib/nethack/nethack.tty
[ 1]       7b0000, 114688 octets,   exe,       400000, rw-, non associé
[ 2]      24d2000, 135168 octets,  heap,      24d2000, rw-, [heap]
[ 3] 7fcc04baa000,  16384 octets,  misc, 7fcc04baa000, rw-, non associé
[ 4] 7fcc04de1000,   4096 octets,  misc, 7fcc04de1000, rw-, non associé
[ 5] 7fcc051f7000,  16384 octets,  misc, 7fcc051f7000, rw-, non associé
[ 6] 7fcc05227000,  12288 octets,  misc, 7fcc05227000, rw-, non associé
[ 7] 7fcc0522c000,   4096 octets,  misc, 7fcc0522c000, rw-, non associé
[ 8] 7ffc8c113000, 135168 octets, stack, 7ffc8c113000, rw-, [stack]

Nous sommes sur x86_64 et 0x400000 est l'adresse de chargement statique pour les exécutables. Cela signifie qu'il ne s'agit pas d'un PIE et que l'or est toujours stocké à 0x7b09e0. Cela facilite l'utilisation d'un entraîneur de jeu comme GameConqueror qui remplit la valeur d'or périodiquement.

Avec un PIE, nous devons utiliser l'offset de correspondance (0x3b09e0 ici) à la place et un entraîneur de jeu avancé avec prise en charge PIE doit déterminer et ajouter l' adresse de chargement actuelle pour obtenir l'adresse mémoire actuelle de la valeur d'or de l'exécution actuelle du jeu.

NOTES

scanmem a été testé sur plusieurs grands programmes, y compris le shoot-em-up 3D quake3 linux. scanmem est également testé sur plateformes ARM et prend en charge Android depuis la version 0.16.

Évidemment, scanmem peut faire planter votre programme s'il est mal utilisé.

Certains programmes stockent les valeurs à plusieurs emplacements, c'est pourquoi set modifiera toutes les correspondances connues.

La randomisation de l'espace d'adressage (ASLR) associée aux exécutables indépendants de la position (PIE), au code indépendant de la position (PIC) ou à la mémoire dynamique sur le tas provoque le chargement des variables à différentes adresses mémoire à chaque démarrage du jeu. Des entraîneurs de jeu avancés comme ugtrain sont requis pour remplir périodiquement les variables dans de telles régions mémoire.

PROBLÈMES CONNUS

scanmem nécessite généralement des privilèges root pour ptrace(2) car les modules de sécurité contrôlent les capacités de ptrace(). Sur x86 et x86_64, il existe généralement le module de sécurité Yama fournissant le fichier /proc/sys/kernel/yama/ptrace_scope. Il est disponible depuis Linux 3.4. Si ce fichier contient "1", alors seuls les parents peuvent tracer() leurs enfants sans privilèges root. Cela signifie que scanmem devrait exécuter le jeu. Ce n'est pas possible car cela nécessiterait des modifications majeures de conception. Nous exécutons donc scanmem en tant que root.

Le premier scan peut être très lent sur de grands programmes, ce qui n'est pas un problème pour les scans ultérieurs car d'énormes portions de l'espace d'adressage sont généralement éliminées. Cela pourrait être amélioré à l'avenir, peut-être en supposant que tous les entiers sont alignés par défaut. Suggestions bienvenues.

La commande snapshot utilise la mémoire de manière inefficace et ne devrait probablement pas être utilisée sur de grands programmes.
