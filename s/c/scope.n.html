scope(n)

Paquet: tcl

Licences: TCL

scope(n) [incr Tcl] scope(n)

NOM

itcl::scope - capture le contexte d'espace de noms d'une variable

SYNTAXE

itcl::scope nom

DESCRIPTION

Crée une valeur contextuelle pour le nom spécifié, qui doit être le nom d'une variable. Si le nom est une variable d'instance, alors la commande scope renvoie un nom qui se résoudra dans n'importe quel contexte comme une variable d'instance appartenant à objet. Le format précis de ce nom est un détail interne à Itcl. L'utilisation d'une telle valeur contextuelle permet d'utiliser des variables d'instance en conjonction avec des widgets. Par exemple, si vous avez un objet avec une variable privée x, vous pouvez utiliser x en conjonction avec l'option -textvariable d'un widget d'entrée. Avant itcl3.0, seules les variables communes pouvaient être utilisées de cette manière.

Si le nom n'est pas une variable d'instance, alors ce doit être une variable commune ou une variable globale. Dans ce cas, la commande scope renvoie le nom entièrement qualifié de la variable, par exemple, ::foo::bar::x.

Si le nom n'est pas reconnu comme une variable, la commande scope renvoie une erreur.

Les noms de variables ordinaires font référence à des variables dans l'espace de noms global. Une valeur contextuelle capture un nom de variable avec son contexte d'espace de noms d'une manière qui permet de le référencer correctement plus tard. Elle est nécessaire, par exemple, pour encapsuler des noms de variables lorsqu'un widget Tk est utilisé dans un espace de noms :

namespace foo {
    private variable mode 1
    radiobutton .rb1 -text "Mode #1"         -variable [scope mode] -value 1
    pack .rb1
    radiobutton .rb2 -text "Mode #2"         -variable [scope mode] -value 2
    pack .rb2
}
Les boutons radio .rb1 et .rb2 interagissent via la variable "mode" contenue dans l'espace de noms "foo". La commande scope garantit cela en renvoyant le nom de variable entièrement qualifié ::foo::mode.

Vous ne devriez jamais tenter de créer vos propres noms de variables contextuels, même si vous pensez avoir parfaitement décrypté l'encodage. Au lieu de cela, vous devriez toujours utiliser la commande scope pour générer le nom de la variable dynamiquement. Ensuite, vous pouvez passer ce nom à un widget ou à tout autre fragment de code de votre programme.
