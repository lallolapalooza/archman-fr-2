SCAPY(1) Manuel des commandes générales SCAPY(1)

NOM

scapy - Outil interactif de manipulation de paquets

SYNTAXE

scapy [options]

DESCRIPTION

Cette page de manuel documente brièvement l'outil Scapy.

Scapy est un puissant outil interactif de manipulation de paquets, générateur de paquets, scanner réseau, découvreur de réseau, renifleur de paquets, etc. Il peut pour le moment remplacer hping, des parties de nmap, arpspoof, arp-sk, arping, tcpdump, tshark, p0f, ...

Scapy utilise l'interpréteur Python comme tableau de commande. Cela signifie que vous pouvez utiliser directement le langage Python (assigner des variables, utiliser des boucles, définir des fonctions, etc.) Si vous donnez un fichier en paramètre lors du lancement de Scapy, votre session (variables, fonctions, instances, ...) sera sauvegardée lorsque vous quitterez l'interpréteur et restaurée la prochaine fois que vous lancerez Scapy.

L'idée est simple. Ces types d'outils font deux choses : envoyer des paquets et recevoir des réponses. C'est ce que fait Scapy : vous définissez un ensemble de paquets, il les envoie, reçoit les réponses, met en correspondance les requêtes avec les réponses et renvoie une liste de couples de paquets (requête, réponse) et une liste de paquets non mis en correspondance. Ceci présente le grand avantage par rapport à des outils comme nmap ou hping qu'une réponse n'est pas réduite à (ouvert/fermé/filtré), mais est le paquet entier.

En plus de cela, il peut être utilisé pour construire des fonctions de plus haut niveau, par exemple, une qui effectue des traceroutes et ne donne comme résultat que le TTL de départ de la requête et l'IP source de la réponse. Une qui ping un réseau entier et donne la liste des machines qui répondent. Une qui effectue un scan de ports et renvoie un rapport LaTeX.

OPTIONS

Les options pour Scapy sont :

-h
affiche l'aide
-H
mode sans en-tête (header-less), réduit également la verbosité.
-d
augmente la verbosité du journal. Peut être utilisé plusieurs fois.
-s FICHIER
utilise FICHIER pour sauvegarder/charger les valeurs de session (variables, fonctions, instances, ...)
-p FICHIER_PREDEMARRAGE
utilise FICHIER_PREDEMARRAGE au lieu de $HOME/.config/scapy/prestart.py comme fichier de pré-démarrage
-P
ne pas exécuter le fichier de pré-démarrage
-c FICHIER_DEMARRAGE
utilise FICHIER_DEMARRAGE au lieu de $HOME/.config/scapy/startup.py comme fichier de démarrage
-C
ne pas exécuter le fichier de démarrage

COMMANDES

Seules les commandes essentielles pour commencer sont listées ici pour le moment.

ls()
liste les couches de protocoles supportées. Si une couche de protocole est donnée en paramètre, liste ses champs et types de champs. Si une chaîne est donnée en paramètre, elle est utilisée pour filtrer les couches.
lsc()
liste les commandes utilisateur principales de scapy.
conf
cet objet contient la configuration.

FICHIERS

$HOME/.config/scapy/prestart.py Ce fichier est exécuté avant le chargement du cœur de Scapy. Seul l'objet conf est disponible. Ce fichier peut être utilisé pour configurer l'interface en ligne de commande, configurer des paramètres tels que la liste conf.load_layers pour choisir les couches qui seront chargées, ou changer le niveau de journalisation (par exemple) :

conf.interactive_shell = "bpython"
log_loading.setLevel(logging.WARNING)
conf.load_layers.remove("bluetooth")
conf.load_layers.append("new_layer")

$HOME/.config/scapy/startup.py Ce fichier est exécuté après le chargement de Scapy. Il peut être utilisé pour configurer davantage le comportement de Scapy, comme désenregistrer des couches :

conf.prog.pdfreader = "xpdf"
split_layers(UDP,DNS)

EXEMPLES

Des exemples plus détaillés sont disponibles dans la documentation sur https://scapy.readthedocs.io/. Lancez simplement scapy et essayez les commandes suivantes dans l'interpréteur.

Tester la robustesse d'une pile réseau avec des paquets invalides :

sr(IP(dst="172.16.1.1", ihl=2, options=["verb$2"], version=3)/ICMP(), timeout=2)

Capture et dissection de paquets (avec un filtre bpf ou une sortie similaire à tshark) :

a=sniff(filter="tcp port 110")
a=sniff(prn = lambda x: x.show)

Réémission de paquets capturés :

a=sniff(filter="tcp port 110")
sendp(a)

Réémission de paquets à partir d'un fichier Pcap :

sendp(rdpcap("file.cap"))

Traceroute TCP manuelle :

sr(IP(dst="www.google.com", ttl=(1,30))/TCP(seq=RandInt(), sport=RandShort(), dport=dport)

Scan de protocoles :

sr(IP(dst="172.16.1.28", proto=(1,254)))

Ping ARP :

srp(Ether(dst="ff:ff:ff:ff:ff:ff")/ARP(pdst="172.16.1.1/24"))

Scan ACK :

sr(IP(dst="172.16.1.28")/TCP(dport=(1,1024), flags="A"))

Empreinte digitale passive du système d'exploitation :

sniff(prn=prnp0f)

Empreinte digitale active du système d'exploitation :

nmap_fp("172.16.1.232")

Empoisonnement du cache ARP :

sendp(Ether(dst=tmac)/ARP(op="who-has", psrc=victim, pdst=target))

Rapports :

report_ports("192.168.2.34", (20,30))

BOGUES

N'indique pas la bonne IP source pour les routes qui utilisent des alias d'interface.

Peut manquer des paquets sous forte charge. C'est une restriction de python lui-même

La sauvegarde de session est limitée par la capacité de Python à sérialiser les objets. Par conséquent, les fonctions lambda et les générateurs ne peuvent pas être sauvegardés, ce qui réduit sérieusement l'utilité de cette fonctionnalité.

Les filtres BPF ne fonctionnent pas sur les interfaces point à point.
