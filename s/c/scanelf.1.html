NOM

scanelf - utilitaire en espace utilisateur pour scanner les fichiers ELF

SYNTAXE

scanelf [options] ELFs ou répertoires

DESCRIPTION

scanelf est un utilitaire en espace utilisateur pour scanner rapidement les fichiers ELF donnés, les répertoires ou les chemins système courants pour obtenir différentes informations. Cela peut inclure les types ELF, leurs marquages PaX, les TEXTRELs, etc...

OPTIONS

-A, --archives

Scanner les archives (.a files)

-a, --all

Afficher toutes les informations utiles/simples

-B, --nobanner

Ne pas afficher l'en-tête

-b, --bind

Afficher les informations de liaison des symboles (lazy ou now)

-D, --endian

Afficher l'endianness de l'ELF (big/little/...)

-E, --etype ETYPE

Afficher uniquement les fichiers ELF correspondant au etype spécifié (comme ET_DYN, ET_EXEC, etc...)

-e, --header

Afficher les marquages GNU_STACK

-F, --format FORMAT

Utiliser le format spécifié pour la sortie ; voir la section FORMAT pour plus d'informations

-f, --from FILE

Lire le flux d'entrée à partir du nom de fichier spécifié

-g, --gmatch

Utiliser strncmp pour faire correspondre les bibliothèques (à utiliser avec -N). Ou une expression régulière avec une correspondance de symbole

-h, --help

Afficher l'utilisation condensée et quitter

-I, --osabi

Afficher l'OSABI

-i, --interp

Afficher les informations de l'interpréteur (.interp/PT_INTERP)

-k, --section SECTION

Trouver les ELFs avec la section spécifiée. Peut être spécifié plusieurs fois pour faire correspondre plusieurs sections simultanément. Voir CORRESPONDANCE DE SECTION pour plus d'infos.

-L, --ldcache

Utiliser les informations de ld.so.cache (à utiliser avec -r/-n)

-l, --ldpath

Scanner tous les répertoires dans /etc/ld.so.conf

-M, --bits BITS

Afficher uniquement les fichiers ELF correspondant aux bits numériques spécifiés (comme 32/64)

-m, --mount

Ne pas traverser récursivement les points de montage

-N, --lib SONAME

Trouver les ELFs qui nécessitent le SONAME spécifié. Peut être spécifié plusieurs fois pour faire correspondre plusieurs SONAMEs simultanément. Voir CORRESPONDANCE DE SONAME pour plus d'infos.

-n, --needed

Afficher les bibliothèques contre lesquelles l'ELF est lié (DT_NEEDED)

-O, --perms PERMS

Afficher uniquement les fichiers ELF avec les bits octaux correspondants spécifiés (comme 755)

-o, --file FILE

Écrire le flux de sortie dans le nom de fichier spécifié

-p, --path

Scanner tous les répertoires dans la variable d'environnement PATH

-q, --quiet

N'afficher que les choses "mauvaises"

-R, --recursive

Scanner les répertoires récursivement

-r, --rpath

Afficher les runpaths encodés dans l'ELF (DT_RPATH/DT_RUNPATH)

-S, --soname

Afficher le nom de la bibliothèque partagée de l'ELF (DT_SONAME)

-s, --symbol SYMBOL

Trouver le symbole spécifié ; voir CORRESPONDANCE DE SYMBOLE pour plus d'infos

-T, --textrels

Localiser la cause des TEXTRELs via objdump

-t, --textrel

Afficher les informations TEXTREL

-V, --version

Afficher la version et quitter

-v, --verbose

Être verbeux (peut être utilisé plusieurs fois)

-X, --fix

Essayer de "corriger" les choses (à utiliser avec -r/-e)

-x, --pax

Afficher les marquages PaX

-Y, --eabi

Afficher l'EABI (ne concerne que quelques architectures)

-y, --symlink

Ne pas scanner les liens symboliques

-Z, --size SIZE

Afficher la taille du fichier ELF

-z, --setpax FLAGS

Définit EI_PAX/PT_PAX_FLAGS aux drapeaux spécifiés (à utiliser avec -Xx)

--use-ldpath

Utiliser les chemins de ld.so.conf pour trouver le chemin complet des bibliothèques (à utiliser en conjonction avec --needed).

--root PATH

Scanner l'arbre root spécifié au lieu de /. Généralement associé à des options comme -l ou -p. Cela traite implicitement tous les chemins spécifiés sur la ligne de commande comme relatifs à la root, assurez-vous donc de l'omettre si vous listez explicitement des ELFs.

--ldcache PATH

Utiliser le chemin spécifié au lieu de /etc/ld.so.cache. Généralement associé à des options comme -L ou -n.

FORMAT

La chaîne de format est très similaire à une chaîne printf, c'est une chaîne littérale avec des indicateurs demandant différentes informations. Par exemple, vous pourriez utiliser une chaîne de format et vous attendre aux résultats suivants.

  # scanelf -BF "fichier %f a besoin de %n; temps funky" /bin/bash
  fichier bash a besoin de libncurses.so.5,libdl.so.2,libc.so.6; temps funky

Notez que lorsque vous utilisez une chaîne de format, les indicateurs généralement liés à l'information devraient être omis. En d'autres termes, vous ne voudrez pas essayer de demander une sortie NEEDED (-n) et spécifier une sortie de format en même temps car ces opérations sont mutuellement exclusives. Chaque indicateur lié à l'information a un spécificateur de conversion équivalent, utilisez donc ceux-ci à la place. Vous pouvez bien sûr continuer à utiliser des indicateurs non liés à l'information (comme --verbose).

Il y a trois caractères qui introduisent les spécificateurs de conversion.

• % - remplacer par info

•
# - correspondance booléenne silencieuse
•
+ - correspondance verbeuse

Et il y a un certain nombre de spécificateurs de conversion. Nous essayons de faire correspondre le spécificateur avec l'option correspondante.

• a - type de machine (EM)

•
b - drapeaux de liaison
•
e - en-têtes de programme
•
D - endianness
•
I - osabi
•
Y - eabi
•
F - nom de fichier long
•
f - nom de fichier court
•
i - interp
•
k - section
•
M - classe EI
•
N - besoin spécifié
•
n - bibliothèques nécessaires
•
p - nom de fichier (sans chemin)
•
o - etype
•
O - perms
•
r - runpaths
•
S - SONAME
•
s - symbole
•
T - tous les textrels
•
t - statut textrel
•
x - drapeaux pax

CORRESPONDANCE DE SYMBOLE

La chaîne spécifiée prend la forme [%[modificateurs]%][[+-]<nom du symbole>][,[.....]].

Si le nom du symbole est vide, alors tous les symboles sont mis en correspondance.

Si le nom du symbole est un glob ("*"), alors tous les symboles sont affichés dans un format de débogage. Ne vous fiez pas à la structure de cette sortie car elle change quand nous en avons envie.

NAME

scanelf

scanner for ELF files

SYNOPSIS

scanelf

[-b bits] [-e etype] [-l] [-ltype]

[-L soname] [-S section] [-y symbol]

[file ...]

DESCRIPTION

scanelf is a tool for scanning ELF files. It can search for various bits of information within an ELF file, such as specific symbol types, bindings, visibilities, ELF types, ELF bitsizes, sections, needed shared objects, or specific dynamic tags.

OPTIONS

The following options are available:

-b bits
Narrow your search by specifying the ELF bitsize. Again, specify the numeric value or the symbolic define. (See ELF BITS below).
-e etype
Narrow your search by specifying the ELF object file type (ETYPE). The command line option takes the numeric value and or symbolic type. Multiple values can be passed comma separated. Example -E ET_EXEC,ET_DYN,1
-l
List all symbols within the specified ELF file(s). If other options are present then scanelf will filter the list according to the other options specified.
-ltype
Search for symbols of a specific type. (See SYMBOL MATCHING below).
-L soname
Search for shared objects that are needed by the ELF file. This option can be prefixed with a ! to search for ELF's that do not depend on the specified library. (See NEEDED SONAME MATCHING below).
-S section
Search for sections within the ELF file. This option can be prefixed with a ! to search for ELF's that do not have the specified section. (See SECTION MATCHING below).
-y symbol
Search for symbols within the ELF file. This option can be prefixed with a ! to only match undefined symbols. (See SYMBOL MATCHING below).

FORMAT

scanelf supports multiple search formats. The default format for searching ELF files is:

%[STT group][STB group][STV group][SHN group]symbol name

The symbol name can be a wildcard, for example *main*.

The default for symbols is to be explicit. If you want to search for symbols that are not defined in the ELF file then prefix the symbol name with a ! (for example, !some_symbol). This option will only match undefined symbols. When we say "defined", we mean the symbol is defined in the ELF vs having an external reference.

Putting modifiers in between the percent signs (%) allows for more in depth filters. There are groups of modifiers. If you don't specify a member of a group, then all types in that group are matched.

• STT group (symbol type)

•
n - STT_NOTYPE
•
o - STT_OBJECT
•
f - STT_FUNC
•
F - STT_FILE
•
STB group (symbol binding)
•
l - STB_LOCAL
•
g - STB_GLOBAL
•
w - STB_WEAK
•
STV group (symbol visibility)
•
p - STV_DEFAULT
•
i - STV_INTERNAL
•
h - STV_HIDDEN
•
P - STV_PROTECTED
•
SHN group (section header)
•
d - defined
•
u - SHN_UNDEF
•
a - SHN_ABS
•
c - SHN_COMMON

You can search for multiple symbols simultaneously by using a comma (,) to separate different searches. Every symbol that matches will be displayed while unmatched symbols will not.

ELF ETYPES

You can narrow your search by specifying the ELF object file type (ETYPE). The command line option takes the numeric value and or symbolic type. Multiple values can be passed comma separated. Example -E ET_EXEC,ET_DYN,1

Here is the normal list available for your pleasure. You of course are free to specify any numeric value you want.

• 0 - ET_NONE - unknown type

•
1 - ET_REL - relocatable file
•
2 - ET_EXEC - executable file
•
3 - ET_DYN - shared object
•
4 - ET_CORE - core file

ELF BITS

You can also narrow your search by specifying the ELF bitsize. Again, specify the numeric value or the symbolic define.

• 32 - ELFCLASS32 - 32bit ELFs

•
64 - ELFCLASS64 - 64bit ELFs

SECTION MATCHING

A ! prefix will only show ELF's that do not have the specified section.

NEEDED SONAME MATCHING

A ! prefix will only show ELF's that do not depend on the specified library.
