Paquet: sg3_utils

SCSI_LOGGING_LEVEL(8) SG3_UTILS SCSI_LOGGING_LEVEL(8)

NOM

scsi_logging_level - accéder aux informations sur le niveau de journalisation SCSI de Linux

SYNTAXE

scsi_logging_level [--all=LEV] [--create] [--error=LEV] [--get] [--help] [--highlevel=LEV] [--hlcomplete=LEV] [--hlqueue=LEV] [--ioctl=LEV] [--llcomplete=LEV] [--llqueue=LEV] [--lowlevel=LEV] [--midlevel=LEV] [--mlcomplete=LEV] [--mlqueue=LEV] [--scan=LEV] [--set] [--timeout=LEV] [--version]

DESCRIPTION

Ce script shell bash accède au niveau de journalisation du sous-système SCSI de Linux. Les valeurs actuelles peuvent être affichées (par exemple, avec --get) ou modifiées (par exemple, avec --set). Des autorisations de superutilisateur seront généralement nécessaires pour définir le niveau de journalisation.

L'une de ces options : --create, --get ou --set est requise. Une seule d'entre elles peut être donnée.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également.

-a, --all=LEV
LEV est utilisé pour tous les champs SCSI_LOG.
-c, --create
Les options sont analysées et placées dans des champs internes qui sont affichés, mais aucun niveau de journalisation n'est modifié dans le noyau Linux.
-E, --error=LEV
LEV est placé dans le champ SCSI_LOG_ERROR.
-g, --get
Récupère les niveaux de journalisation SCSI actuels du noyau Linux et les affiche.
-h, --help
Affiche le message d'utilisation puis quitte.
-H, --highlevel=LEV
LEV est placé dans les champs SCSI_LOG_HLQUEUE et SCSI_LOG_HLCOMPLETE.
--hlcomplete=LEV
LEV est placé dans le champ SCSI_LOG_HLCOMPLETE.
--hlqueue=LEV
LEV est placé dans le champ SCSI_LOG_HLQUEUE.
-I, --ioctl=LEV
LEV est placé dans le champ SCSI_LOG_IOCTL.
--llcomplete=LEV
LEV est placé dans le champ SCSI_LOG_LLCOMPLETE.
--llqueue=LEV
LEV est placé dans le champ SCSI_LOG_LLQUEUE.
-L, --lowlevel=LEV
LEV est placé dans les champs SCSI_LOG_LLQUEUE et SCSI_LOG_LLCOMPLETE.
-M, --midlevel=LEV
LEV est placé dans les champs SCSI_LOG_MLQUEUE et SCSI_LOG_MLCOMPLETE.
--mlcomplete=LEV
LEV est placé dans le champ SCSI_LOG_MLCOMPLETE.
--mlqueue=LEV
LEV est placé dans le champ SCSI_LOG_MLQUEUE.
-S, --scan=LEV
LEV est placé dans le champ SCSI_LOG_SCAN.
-s, --set
Utilise les champs spécifiés dans les options de cette commande et tente de les appliquer aux niveaux de journalisation du sous-système SCSI de Linux. Des autorisations de superutilisateur seront généralement nécessaires pour ce faire.
-T, --timeout=LEV
LEV est placé dans le champ SCSI_LOG_TIMEOUT.
-v, --version
Affiche les informations de version puis quitte.

NOTES

Les options --get et --set accèdent au fichier pseudo /proc/sys/dev/scsi/logging_level.

STATUT DE SORTIE

Le statut de sortie de ce script est 0 en cas de succès. Tout autre statut de sortie indique qu'une erreur s'est produite.

EXEMPLES

Ce qui suit définira SCSI_LOG_ERROR au niveau 5 dans le noyau Linux. Cela nécessite des privilèges root :


scsi_logging_level -s -E 5

Afin de ne pas interférer avec les autres pilotes de sous-système SCSI de niveau supérieur (ULD) qui seront très probablement actifs en même temps, le pilote sg de Linux utilise SCSI_LOG_TIMEOUT à des fins de journalisation. Pour voir la journalisation de débogage et le traçage complet du pilote sg, utilisez :


scsi_logging_level -s -T 7

La sortie du pilote sg causée par cela ira dans les journaux système (par exemple, /var/log/syslog). Pour réduire la quantité de sortie, utilisez un nombre inférieur à 7. L'utilisation de 0 désactivera le traçage et le débogage.

Pour activer la journalisation maximale du sous-système SCSI, utilisez :


scsi_logging_level -s -a 7

Cela est probablement mieux fait sur un système qui n'utilise pas un périphérique de commande SCSI pour contenir le système de fichiers racine, ou le système de fichiers qui contient le journal système. Notez que les disques SATA et le stockage connecté en USB utilisent presque toujours le sous-système SCSI.
