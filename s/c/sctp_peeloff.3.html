SCTP_PEELOFF(3) Manuel du programmeur Linux SCTP_PEELOFF(3)

NOM

sctp_peeloff - Détacher une association dans un socket séparé.

SYNOPIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/sctp.h>

int sctp_peeloff(int sd, sctp_assoc_t assoc_id);
int sctp_peeloff_flags(int sd, sctp_assoc_t assoc_id, unsigned flags);

DESCRIPTION

sctp_peeloff détache une association existante assoc_id d'un socket de style "one-to-many" sd pour la créer dans un socket séparé. Le nouveau socket est un socket de style "one-to-one".

Ceci est particulièrement souhaitable lorsque, par exemple, l'application souhaite conserver un certain nombre d'expéditeurs/récepteurs de messages sporadiques sous le socket original de style "one-to-many", tout en détachant les associations transportant un trafic de données à haut volume dans leurs propres descripteurs de socket.

sctp_peeloff_flags est une variante de sctp_peeloff, dans laquelle des drapeaux décrivant le comportement du socket nouvellement détaché peuvent être spécifiés. Actuellement, les drapeaux pris en charge sont :

SOCK_NONBLOCK
Spécifie que le nouveau socket ne doit pas bloquer lors des opérations d'E/S.
SOCK_CLOEXEC
Spécifie que le nouveau socket doit être fermé lorsque le processus propriétaire appelle exec.

VALEUR DE RETOUR

En cas de succès, le nouveau descripteur de socket représentant l'association détachée est retourné. En cas d'erreur, -1 est retourné, et errno est défini de manière appropriée.

ERREURS

EBADF
sd n'est pas un descripteur valide.
EINVAL
L'ID d'association passé est invalide ou si le socket est de style "one-to-one".
ENOTSOCK
L'argument est le descripteur d'un fichier, pas d'un socket.

NOTES

sctp_peeloff_flags est une variante spécifique à Linux de sctp_peeloff. Bien qu'elle compile sur d'autres systèmes, son utilisation entraînera une erreur de retour. Le code portable doit utiliser sctp_peeloff.
