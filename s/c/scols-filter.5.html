SCOLS-FILTER(5) Formats de fichiers et conventions SCOLS-FILTER(5)

NOM

scols-filter - syntaxe pour les expressions de filtrage libsmartcols

SYNTAXE

expr: param
      | ( expr )
      | expr && expr | expr AND expr
      | expr || expr | expr OR expr
      | !expr        | NOT expr
      | expr == expr | expr EQ expr
      | expr != expr | expr NE expr
      | expr >= expr | expr GE expr
      | expr <= expr | expr LE expr
      | expr >  expr | expr GT expr
      | expr <  expr | expr LT expr
      | expr =~ string
      | expr !~ string
param: entier
      | flottant
      | chaîne
      | booléen
      | détenteur
entier: [0-9]*
      | [0-9]*[KMGTPEZY]
      | [0-9]*[KMGTPEZY]iB
flottant: entier.entier
booléen: "true" | "false" | "TRUE" | "FALSE"
chaîne: "[^\n\"]*" | '[^\n\']*'
détenteur: [a-zA-Z][a-zA-Z_.%:/\-0-9]*

DESCRIPTION

L'expression de filtre peut être utilisée par les applications liées à libsmartcols pour filtrer les données de sortie. L'application peut utiliser le filtre avant de rassembler toutes les données pour la sortie afin de réduire les ressources et d'améliorer les performances. Cela rend le filtre scols plus efficace que grep(1) sur la sortie complète. Par exemple :

 lsblk --output NAME,LABEL,FSTYPE --filter 'NAME=="sda1"'

aide lsblk(1) à ne pas lire les LABELS de tous les périphériques blocs depuis udevd ou libblkid, mais à ne les lire que pour le périphérique sda1.

Le filtre peut également être utilisé pour des colonnes qui ne sont pas utilisées dans la sortie.

NOTES SYNTAXE

Une expression est composée de détenteurs, de paramètres et d'opérateurs.

Le type de détenteur actuellement pris en charge est uniquement le nom de colonne. Le nom doit être utilisé sans guillemets. Avant l'évaluation, l'application fait correspondre les noms de colonnes dans l'expression donnée aux colonnes de table de sortie et attribue le type de données de colonne au détenteur. Le type par défaut est « chaîne ».

Le paramètre sert à représenter directement une valeur. Les types de données actuellement pris en charge sont les nombres entiers, les nombres à virgule flottante, les chaînes et les booléens.

Un opérateur fonctionne avec un ou deux opérande(s). Un opérateur attend un type de données spécifique pour ses opérandes. Donner un type de données inattendu à un opérateur entraîne une erreur de syntaxe. La bibliothèque peut effectuer des conversions entre les types de données, la préférence étant toujours le type spécifié par param et, en cas d'expression avec un nombre et un nombre à virgule flottante, la préférence est donnée au nombre à virgule flottante.

Les opérateurs prenant deux opérandes sont and, or, eq, ne, le, lt, ge, gt, =~, !~. Les opérateurs nommés alphabétiquement ont des alias similaires à ceux du langage C : &&, ||, ==, !=, <, ⇐, >=, et >.

! est le seul opérateur qui prend un seul opérande. Si aucun opérateur n'est spécifié, l'expression est vraie si le paramètre ou le détenteur n'est pas vide. Par exemple --filter NAME retournera les lignes où la colonne NAME n'est pas vide.

=~ et !~ sont pour la correspondance d'expressions régulières ; si une chaîne à droite correspond (ou ne correspond pas pour !~ à une expression régulière à gauche, le résultat est vrai. L'opérande de droite doit être une chaîne littérale.

La précédence entre les opérateurs est or, and, et eq, ne, le, gt, ge, =~, !~, not.

LIMITATIONS

Concernant les valeurs de types flottant et entier, le moteur de filtre ne prend en charge que les nombres non négatifs. L'entier est un nombre non signé de 64 bits, et le flottant est un long double. L'entier peut être suivi des suffixes multiplicatifs KiB, GiB, TiB, PiB, EiB, ZiB et YiB (le "iB" est optionnel, par exemple, "K" a la même signification que "KiB").
