scrcpy(1) Manuel des commandes générales scrcpy(1)

NOM

scrcpy - Afficher et contrôler votre appareil Android

SYNTAXE

scrcpy [options]

DESCRIPTION

scrcpy permet d'afficher et de contrôler des appareils Android connectés via USB (ou via TCP/IP). Aucune permission root n'est requise.

OPTIONS

--always-on-top
Garder la fenêtre scrcpy au premier plan (au-dessus des autres fenêtres).
--angle degrés
Faire pivoter le contenu vidéo d'un angle personnalisé, en degrés (sens horaire).
--audio-bit-rate valeur
Encoder l'audio au débit spécifié, exprimé en bits/s. Les suffixes d'unité sont supportés : 'K' (x1000) et 'M' (x1000000).

La valeur par défaut est 128K (128000).

--audio-buffer ms
Configurer le délai de mise en tampon audio (en millisecondes).

Des valeurs plus faibles diminuent la latence, mais augmentent la probabilité de sous-débordement du tampon (provoquant des artéfacts audio).

La valeur par défaut est 50.

--audio-codec nom
Sélectionner un codec audio (opus, aac, flac ou raw).

La valeur par défaut est opus.

--audio-codec-options clé[:type]=valeur[,...]
Définir une liste d'options séparées par des virgules clé:type=valeur pour l'encodeur audio de l'appareil.

Les valeurs possibles pour 'type' sont 'int' (par défaut), 'long', 'float' et 'string'.

La liste des options de codec possibles est disponible dans la documentation Android :

https://d.android.com/reference/android/media/MediaFormat

--audio-dup
Dupliquer l'audio (capturer et continuer à jouer sur l'appareil).

Cette fonctionnalité n'est disponible qu'avec --audio-source=playback.

--audio-encoder nom
Utiliser un encodeur audio MediaCodec spécifique (en fonction du codec fourni par --audio-codec).

Les encodeurs disponibles peuvent être listés par --list-encoders.

--audio-source source
Sélectionner la source audio. Les valeurs possibles sont :


- "output" : transmet toute la sortie audio et désactive la lecture sur l'appareil.
- "playback" : capture la lecture audio (les applications Android peuvent refuser, donc la sortie entière n'est pas nécessairement capturée).
- "mic" : capture le microphone.
- "mic-unprocessed" : capture le son brut (non traité) du microphone.
- "mic-camcorder" : capture le microphone réglé pour l'enregistrement vidéo, avec la même orientation que la caméra si disponible.
- "mic-voice-recognition" : capture le microphone réglé pour la reconnaissance vocale.
- "mic-voice-communication" : capture le microphone réglé pour les communications vocales (il profitera par exemple de l'annulation d'écho ou du contrôle automatique du gain si disponible).
- "voice-call" : capture l'appel vocal.
- "voice-call-uplink" : capture uniquement la liaison montante de l'appel vocal.
- "voice-call-downlink" : capture uniquement la liaison descendante de l'appel vocal.
- "voice-performance" : capture l'audio destiné à être traité pour les performances live (karaoké), incluant à la fois le microphone et la lecture de l'appareil.

La valeur par défaut est output.

--audio-output-buffer ms
Configurer la taille du tampon de sortie audio SDL (en millisecondes).

Si vous obtenez une lecture audio "robotique", vous devriez tester avec une valeur plus élevée (10). Ne modifiez pas ce paramètre sinon.

La valeur par défaut est 5.

-b, --video-bit-rate valeur
Encoder la vidéo au débit spécifié, exprimé en bits/s. Les suffixes d'unité sont supportés : 'K' (x1000) et 'M' (x1000000).

La valeur par défaut est 8M (8000000).

--camera-ar ar
Sélectionner la taille de la caméra par son rapport d'aspect (+/- 10%).

Les valeurs possibles sont "sensor" (utiliser le rapport d'aspect du capteur de la caméra), "num:den" (par exemple, "4:3") et "valeur" (par exemple, "1.6").

--camera-facing orientation
Sélectionner la caméra de l'appareil par sa direction.

Les valeurs possibles sont "front", "back" et "external".

--camera-fps fps
Spécifier la fréquence d'images de capture de la caméra.

Si non spécifié, la fréquence d'images par défaut d'Android (30 fps) est utilisée.

--camera-high-speed
Activer le mode de capture de caméra à haute vitesse.

Ce mode est limité à des résolutions et fréquences d'images spécifiques, listées par --list-camera-sizes.

--camera-id id
Spécifier l'ID de la caméra de l'appareil à afficher.

Les IDs de caméra disponibles peuvent être listés par --list-cameras.

--camera-size largeurxhauteur
Spécifier une taille de capture de caméra explicite.
--capture-orientation valeur
Les valeurs possibles sont 0, 90, 180, 270, flip0, flip90, flip180 et flip270, éventuellement précédées de '@'.

Le nombre représente la rotation dans le sens horaire en degrés ; le mot-clé "flip" applique un retournement horizontal avant la rotation.

Si un '@' initial est passé (@90) pour la capture d'affichage, alors la rotation est verrouillée et est relative à l'orientation naturelle de l'appareil.

Si '@' est passé seul, alors la rotation est verrouillée à l'orientation initiale de l'appareil.

La valeur par défaut est 0.

--crop largeur:hauteur:x:y
Recadrer l'écran de l'appareil sur le serveur.

Les valeurs sont exprimées dans l'orientation naturelle de l'appareil (typiquement, portrait pour un téléphone, paysage pour une tablette).

-d, --select-usb
Utiliser le périphérique USB (s'il n'y en a qu'un, comme adb -d).

Voir aussi -e (--select-tcpip).

--disable-screensaver
Désactiver l'économiseur d'écran pendant que scrcpy est en cours d'exécution.
--display-id id
Spécifier l'ID d'affichage de l'appareil à afficher.

Les IDs d'affichage disponibles peuvent être listés par --list-displays.

La valeur par défaut est 0.

--display-ime-policy valeur
Définir la politique pour sélectionner où l'IME doit être affiché.

Les valeurs possibles sont "local", "fallback" et "hide" :


- "local" signifie que l'IME doit apparaître sur l'affichage local.
- "fallback" signifie que l'IME doit apparaître sur un affichage de secours (l'affichage par défaut).
- "hide" signifie que l'IME doit être masqué.

Par défaut, la politique IME n'est pas modifiée.

--display-orientation valeur
Définir l'orientation initiale de l'affichage.

Les valeurs possibles sont 0, 90, 180, 270, flip0, flip90, flip180 et flip270. Le nombre représente la rotation dans le sens horaire en degrés ; le mot-clé "flip"

Set the video codec to use for recording.

Keep the server running even if the device disconnects.
--keyboard mode
Select how to send keyboard inputs to the device.

Possible values are "disabled", "sdk", "uhid" and "aoa":


- "disabled" does not send keyboard inputs to the device.
- "sdk" uses the Android system API to deliver keyboard events to applications.
- "uhid" simulates a physical HID keyboard using the Linux HID kernel module on the device.
- "aoa" simulates a physical HID keyboard using the AOAv2 protocol. It may only work over USB.

For "uhid" and "aoa", the keyboard layout must be configured (once and for all) on the device, via Settings -> System -> Languages and input -> Physical keyboard. This settings page can be started directly using the shortcut MOD+k (except in OTG mode), or by executing:


adb shell am start -a android.settings.HARD_KEYBOARD_SETTINGS

This option is only available when the HID keyboard is enabled (or a physical keyboard is connected).

Also see --mouse and --gamepad.

Limit the framerate of screen capture (officially supported since Android 10, but may work on earlier versions).
--mouse mode
Select how to send mouse inputs to the device.

Possible values are "disabled", "sdk", "uhid" and "aoa":


- "disabled" does not send mouse inputs to the device.
- "sdk" uses the Android system API to deliver mouse events to applications.
- "uhid" simulates a physical HID mouse using the Linux HID kernel module on the device.
- "aoa" simulates a physical mouse using the AOAv2 protocol. It may only work over USB.

In "uhid" and "aoa" modes, the computer mouse is captured to control the device directly (relative mouse mode).

LAlt, LSuper or RSuper toggle the capture mode, to give control of the mouse back to the computer.

Also see --keyboard and --gamepad.

--mouse-bind xxxx[:xxxx]
Configure bindings of secondary clicks.

The argument must be one or two sequences (separated by ':') of exactly 4 characters, one for each secondary click (in order: right click, middle click, 4th click, 5th click).

The first sequence defines the primary bindings, used when a mouse button is pressed alone. The second sequence defines the secondary bindings, used when a mouse button is pressed while the Shift key is held.

If the second sequence of bindings is omitted, then it is the same as the first one.

Each character must be one of the following:


- '+': forward the click to the device
- '-': ignore the click
- 'b': trigger shortcut BACK (or turn screen on if off)
- 'h': trigger shortcut HOME
- 's': trigger shortcut APP_SWITCH
- 'n': trigger shortcut "expand notification panel"

Default is 'bhsn:++++' for SDK mouse, and '++++:bhsn' for AOA and UHID.

--no-clipboard-autosync
By default, scrcpy automatically synchronizes the computer clipboard to the device clipboard before injecting Ctrl+v, and the device clipboard to the computer clipboard whenever it changes.

This option disables this automatic synchronization.

--no-downsize-on-error
