SCHED_SETSCHEDULER(3P) Manuel du programmeur POSIX SCHED_SETSCHEDULER(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sched_setscheduler — définir la politique et les paramètres de planification (TEMPS RÉEL)

SYNOPSIS

#include <sched.h>
int sched_setscheduler(pid_t pid, int policy,
    const struct sched_param *param);

DESCRIPTION

La fonction sched_setscheduler() doit définir la politique de planification et les paramètres de planification du processus spécifié par pid à policy et aux paramètres spécifiés dans la structure sched_param pointée par param, respectivement. La valeur du membre sched_priority dans la structure sched_param doit être un entier quelconque dans la plage de priorité inclusive pour la politique de planification spécifiée par policy. Si la valeur de pid est négative, le comportement de la fonction sched_setscheduler() n'est pas spécifié.

Les valeurs possibles pour le paramètre policy sont définies dans l'en-tête <sched.h>.

Si un processus spécifié par pid existe, et si le processus appelant a les permissions appropriées, la politique de planification et les paramètres de planification doivent être définis pour le processus dont l'ID de processus est égal à pid.

Si pid est zéro, la politique de planification et les paramètres de planification doivent être définis pour le processus appelant.

Les conditions dans lesquelles un processus a les privilèges appropriés pour modifier les paramètres de planification d'un autre processus sont définies par l'implémentation.

Les implémentations peuvent exiger que le processus demandeur ait la permission de définir ses propres paramètres de planification ou ceux d'un autre processus. De plus, des restrictions définies par l'implémentation peuvent s'appliquer quant aux privilèges appropriés requis pour définir la politique de planification du processus, ou la politique de planification d'un autre processus, à une valeur particulière.

La fonction sched_setscheduler() doit être considérée comme réussie si elle réussit à définir la politique de planification et les paramètres de planification du processus spécifié par pid aux valeurs spécifiées par policy et la structure pointée par param, respectivement.

Voir Politiques de Planification pour une description de la manière dont cette fonction affecte la planification des threads au sein du processus cible.

Si la politique de planification actuelle pour le processus cible n'est pas SCHED_FIFO, SCHED_RR ou SCHED_SPORADIC, le résultat est défini par l'implémentation ; ce cas inclut la politique SCHED_OTHER.

La période de remplacement sched_ss_repl_period spécifiée doit être supérieure ou égale au budget initial sched_ss_init_budget spécifié pour que la fonction réussisse ; sinon, la fonction échoue.

La valeur de sched_ss_max_repl doit être comprise dans l'intervalle inclusif [1,{SS_REPL_MAX}] pour que la fonction réussisse ; sinon, elle échoue. Il n'est pas spécifié si les valeurs sched_ss_repl_period et sched_ss_init_budget sont stockées telles que fournies par cette fonction ou si elles sont arrondies pour s'aligner sur la résolution de l'horloge utilisée.

Cette fonction n'est pas atomique par rapport aux autres threads du processus. Les threads peuvent continuer à s'exécuter pendant que cet appel de fonction modifie la politique de planification et les paramètres de planification associés pour les entités sous-jacentes planifiées par le noyau utilisées par les threads de portée de contention du processus.

VALEUR RENVOYÉE

En cas de succès, la fonction renvoie l'ancienne politique de planification du processus spécifié. Si la fonction sched_setscheduler() échoue, la politique et les paramètres de planification restent inchangés, et la fonction renvoie la valeur -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction sched_setscheduler() échoue si :

EINVAL
La valeur du paramètre policy est invalide, ou un ou plusieurs des paramètres contenus dans param est en dehors de la plage valide pour la politique de planification spécifiée.
EPERM
Le processus appelant n'a pas la permission de définir un ou les deux paramètres de planification ou la politique de planification du processus spécifié.
ESRCH
Aucun processus ne peut être trouvé correspondant à celui spécifié par pid.

sched_setscheduler(3p) - Linux manual pages

NAME

sched_setscheduler, sched_getscheduler, sched_setparam, sched_getparam, sched_get_priority_max, sched_get_priority_min, sched_rr_get_interval - set and get scheduling attributes

SYNOPSIS

#include <sched.h>

int sched_setscheduler(pid_t pid, int policy, const struct sched_param *param);

int sched_getscheduler(pid_t pid);

int sched_setparam(pid_t pid, const struct sched_param *param);

int sched_getparam(pid_t pid, struct sched_param *param);

int sched_get_priority_max(int policy);

int sched_get_priority_min(int policy);

int sched_rr_get_interval(pid_t pid, struct timespec *interval);

DESCRIPTION

These functions are part of the POSIX real-time extensions for scheduling.

The sched_setscheduler() function sets the scheduling policy and parameters for the process or thread identified by pid. If pid is 0, the calling thread's attributes are set. Otherwise, pid must be the identifier of another thread within the same process. The policy argument specifies the scheduling policy, which must be one of the following:

  • SCHED_FIFO: First-In, First-Out scheduling.
  • SCHED_RR: Round-Robin scheduling.
  • SCHED_BATCH: Batch scheduling.
  • SCHED_IDLE: Idle scheduling.
  • SCHED_OTHER: Standard Linux scheduling (often CFS - Completely Fair Scheduler).

The param argument is a pointer to a struct sched_param, which specifies the scheduling priority. The structure contains at least the following member:

int sched_priority;

The valid range of priorities depends on the policy and the system. Use sched_get_priority_max() and sched_get_priority_min() to determine the range.

sched_getscheduler() retrieves the current scheduling policy of the thread identified by pid. If pid is 0, the calling thread's policy is retrieved.

sched_setparam() sets the scheduling parameters (priority) for the thread identified by pid, leaving the policy unchanged. If pid is 0, the calling thread's parameters are set.

sched_getparam() retrieves the scheduling parameters (priority) for the thread identified by pid. If pid is 0, the calling thread's parameters are retrieved.

sched_get_priority_max() returns the maximum priority value for the given scheduling policy.

sched_get_priority_min() returns the minimum priority value for the given scheduling policy.

sched_rr_get_interval() retrieves the round-robin time slice for the thread identified by pid. The interval is returned in the timespec structure pointed to by interval. If pid is 0, the interval for the calling thread is retrieved.

RETURN VALUE

On success, sched_setscheduler(), sched_setparam(), sched_rr_get_interval() return 0. sched_getscheduler() and sched_getparam() return the policy or 0 respectively. sched_get_priority_max() and sched_get_priority_min() return the maximum or minimum priority respectively.

On error, all functions return -1, and errno is set to indicate the error.

ERRORS

The following are the general error conditions for these functions:

  • EINVAL: An invalid value was provided for a policy or priority.
  • EPERM: The calling process does not have the required privileges to set the scheduling policy or priority for the specified thread. This typically requires the CAP_SYS_NICE capability.
  • ESRCH: The process or thread identified by pid could not be found.
  • EINTR: A signal interrupted the function call.

STANDARDS

POSIX.1-2008.

HISTORY

The real-time extensions were introduced in POSIX.1b.

EXAMPLES

Setting a real-time priority:

#include <sched.h>
        #include <stdio.h>
        #include <stdlib.h>

        int main() {
            struct sched_param sp;
            int policy;
            int max_prio, min_prio;

            // Get current policy and parameters
            if (sched_getscheduler(0) == -1) {
                perror("sched_getscheduler");
                exit(EXIT_FAILURE);
            }
            if (sched_getparam(0, &sp) == -1) {
                perror("sched_getparam");
                exit(EXIT_FAILURE);
            }

            // Get priority range for SCHED_FIFO
            max_prio = sched_get_priority_max(SCHED_FIFO);
            min_prio = sched_get_priority_min(SCHED_FIFO);
            if (max_prio == -1 || min_prio == -1) {
                perror("sched_get_priority_max/min");
                exit(EXIT_FAILURE);
            }
            printf("Max priority for SCHED_FIFO: %d\n", max_prio);
            printf("Min priority for SCHED_FIFO: %d\n", min_prio);

            // Set a higher priority (e.g., max - 5)
            sp.sched_priority = max_prio - 5;
            if (sched_setscheduler(0, SCHED_FIFO, &sp) == -1) {
                perror("sched_setscheduler");
                // Might fail due to permissions, try setting param only
                if (sched_setparam(0, &sp) == -1) {
                     perror("sched_setparam");
                     exit(EXIT_FAILURE);
                } else {
                     printf("Set priority only, policy unchanged.\n");
                }
            } else {
                printf("Set SCHED_FIFO policy with priority %d\n", sp.sched_priority);
            }


            // Get interval for round-robin (if applicable, though not for SCHED_FIFO)
            // struct timespec interval;
            // if (sched_rr_get_interval(0, &interval) == 0) {
            //     printf("Round-robin interval: %ld.%09ld seconds\n", interval.tv_sec, interval.tv_nsec);
            // }


            return 0;
        }

APPLICATION USAGE

These functions allow applications to influence their scheduling behavior, particularly in real-time systems where deterministic execution is crucial. However, improper use of real-time policies (e.g., SCHED_FIFO, SCHED_RR) can lead to system instability or starvation of other processes if not managed carefully. Setting real-time priorities typically requires elevated privileges (CAP_SYS_NICE).

RATIONALE

The POSIX real-time extensions were developed to provide fine-grained control over process scheduling, enabling applications with strict timing requirements to meet deadlines. The functions cover setting and retrieving scheduling policies, priorities, and round-robin time slices.

FUTURE DIRECTIONS

Future developments might include more sophisticated scheduling policies or dynamic adjustment mechanisms, possibly integrating with cgroup schedulers for better resource management.
