sched_setattr(2) Manuel des appels système sched_setattr(2)

NOM

sched_setattr, sched_getattr - définir et obtenir la politique de planification et les attributs

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sched.h>            /* Définition des constantes SCHED_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_sched_setattr, pid_t pid, struct sched_attr *attr,
            unsigned int flags);
int syscall(SYS_sched_getattr, pid_t pid, struct sched_attr *attr,
            unsigned int size, unsigned int flags);

Note : glibc ne fournit pas de wrappers pour ces appels système, ce qui rend nécessaire l'utilisation de syscall(2).

DESCRIPTION

sched_setattr()

L'appel système sched_setattr() définit la politique de planification et les attributs associés pour le thread dont l'identifiant est spécifié dans pid. Si pid est égal à zéro, la politique de planification et les attributs du thread appelant seront définis.

Actuellement, Linux prend en charge les politiques de planification "normales" (c'est-à-dire non temps réel) suivantes comme valeurs pouvant être spécifiées dans policy :

SCHED_OTHER
la politique standard de partage de temps round-robin ;
SCHED_BATCH
pour l'exécution de processus de style "batch" ; et
SCHED_IDLE
pour l'exécution de travaux d'arrière-plan à *très* basse priorité.

Diverses politiques "temps réel" sont également prises en charge, pour les applications critiques en temps qui nécessitent un contrôle précis sur la manière dont les threads exécutables sont sélectionnés pour l'exécution. Pour les règles régissant quand un processus peut utiliser ces politiques, voir sched(7). Les politiques temps réel pouvant être spécifiées dans policy sont :

SCHED_FIFO
une politique premier entré, premier sorti ; et
SCHED_RR
une politique round-robin.

Linux fournit également la politique suivante :

SCHED_DEADLINE
une politique de planification à échéance ; voir sched(7) pour les détails.

L'argument attr est un pointeur vers une structure qui définit la nouvelle politique de planification et les attributs du thread spécifié. Cette structure a la forme suivante :


struct sched_attr {
    u32 size;              /* Taille de cette structure */
    u32 sched_policy;      /* Politique (SCHED_*) */
    u64 sched_flags;       /* Indicateurs */
    s32 sched_nice;        /* Valeur nice (SCHED_OTHER,
                              SCHED_BATCH) */
    u32 sched_priority;    /* Priorité statique (SCHED_FIFO,
                              SCHED_RR) */
    /* Pour SCHED_DEADLINE */
    u64 sched_runtime;
    u64 sched_deadline;
    u64 sched_period;
    /* Indices d'utilisation */
    u32 sched_util_min;
    u32 sched_util_max;
};

Les champs de la structure sched_attr sont les suivants :

size
Ce champ doit être défini à la taille de la structure en octets, comme dans sizeof(struct sched_attr). Si la structure fournie est plus petite que la structure du noyau, les champs supplémentaires sont supposés être '0'. Si la structure fournie est plus grande que la structure du noyau, le noyau vérifie que tous les champs supplémentaires sont à 0 ; sinon, sched_setattr() échoue avec l'erreur E2BIG et met à jour size pour contenir la taille de la structure du noyau.
Le comportement ci-dessus lorsque la taille de la structure sched_attr en espace utilisateur ne correspond pas à la taille de la structure du noyau permet une extensibilité future de l'interface. Les applications malformées passant des structures surdimensionnées ne seront pas plantées à l'avenir si la taille de la structure du noyau sched_attr est augmentée. À l'avenir, cela pourrait également permettre aux applications connaissant une structure sched_attr plus grande en espace utilisateur de déterminer si elles s'exécutent sur un ancien noyau qui ne prend pas en charge la structure plus grande.
sched_policy
Ce champ spécifie la politique de planification, comme l'une des valeurs SCHED_* listées ci-dessus.
sched_flags
Ce champ contient zéro ou plusieurs des indicateurs suivants qui sont combinés par OU pour contrôler le comportement de la planification :
SCHED_FLAG_RESET_ON_FORK
Les enfants créés par fork(2) n'héritent pas des politiques de planification privilégiées. Voir sched(7) pour les détails.
SCHED_FLAG_RECLAIM (depuis Linux 4.13)
Cet indicateur permet à un thread SCHED_DEADLINE de récupérer la bande passante non utilisée par d'autres threads temps réel.
SCHED_FLAG_DL_OVERRUN (depuis Linux 4.16)
Cet indicateur permet à une application d'être informée des dépassements de temps d'exécution dans les threads SCHED_DEADLINE. De tels dépassements peuvent être causés par (par exemple) une comptabilité de temps d'exécution grossière ou une affectation incorrecte de paramètres. La notification prend la forme d'un signal SIGXCPU généré à chaque dépassement.
Ce signal SIGXCPU est dirigé vers le processus (voir signal(7)) plutôt que dirigé vers le thread. C'est probablement un bug. D'une part, sched_setattr() est utilisé pour définir un attribut par thread. D'autre part, si le signal dirigé vers le processus est délivré à un thread du processus autre que celui qui a eu un dépassement de temps d'exécution, l'application n'a aucun moyen de savoir quel thread a dépassé.
SCHED_FLAG_UTIL_CLAMP_MIN
SCHED_FLAG_UTIL_CLAMP_MAX (tous deux depuis Linux 5.3)
Ces indicateurs indiquent que les champs sched_util_min ou sched_util_max, respectivement, sont présents, représentant l'utilisation minimale et maximale attendue du thread.
Les attributs d'utilisation fournissent au planificateur des limites à l'intérieur desquelles il doit planifier le thread, informant potentiellement ses décisions concernant le placement des tâches et la sélection de fréquence.
sched_nice
Ce champ spécifie la valeur nice à définir lors de la spécification de sched_policy comme SCHED_OTHER ou SCHED_BATCH. La valeur nice est un nombre dans la plage de -20 (haute priorité) à +19 (basse priorité) ; voir sched(7).
sched_priority
Ce champ spécifie la priorité statique à définir lors de la spécification de sched_policy comme SCHED_FIFO ou SCHED_RR. La plage autorisée de priorités pour ces politiques peut être déterminée en utilisant sched_get_priority_min(2) et sched_get_priority_max(2). Pour les autres politiques, ce champ doit être spécifié comme 0.
sched_runtime
Ce champ spécifie le paramètre "Runtime" pour la planification à échéance. La valeur est exprimée en nanosecondes. Ce champ, ainsi que les deux champs suivants, sont utilisés uniquement pour la planification SCHED_DEADLINE ; pour plus de détails, voir sched(7).
sched_setattr(2) - Manual Page

NAME

sched_setattr, sched_getattr \- définir et obtenir les attributs de planification de threads

LIBRARY

POSIX threads library (libpthread, often included by libc)

SYNOPSIS

#include <sched.h>

int sched_setattr(pid_t pid, const struct sched_attr *attr, unsigned int flags);
int sched_getattr(pid_t pid, struct sched_attr *attr, unsigned int *size, unsigned int flags);

DESCRIPTION

The sched_setattr() and sched_getattr() system calls provide an interface for setting and getting the scheduling policy and attributes for a specific thread.

sched_setattr()

The sched_setattr() system call sets the scheduling policy and attributes for the thread whose ID is specified in pid. If pid equals zero, the scheduling policy and attributes of the calling thread will be set.

The attr argument points to a sched_attr structure that specifies the desired scheduling policy and attributes. The structure is defined as follows:

struct sched_attr {
    u32 size;

    u32 sched_policy;
    u64 sched_flags;

    /* Scheduling parameters */
    s64 sched_nice;     /* Ignored for SCHED_FIFO, SCHED_RR, SCHED_DEADLINE */
    u64 sched_priority; /* Ignored for SCHED_IDLE, SCHED_BATCH */

    /* SCHED_DEADLINE parameters */
    u64 sched_runtime;
    u64 sched_period;
    u64 sched_deadline;

    /* SCHED_CORE parameters */
    u64                        sched_reuse_core; /* SCHED_CORE_REUSE_THIS_CORE */
                                               /* SCHED_CORE_REUSE_ANY_CORE */
                                               /* SCHED_CORE_PINNED_TO_CORE */

    /* SCHED_INTERACTIVE parameters */
    u32 sched_wakeup_granularity; /* In nanoseconds */

    /* SCHED_CAPACITY parameters */
    u32 sched_capacity; /* In units of 1024 */

    /* SCHED_CORE parameters */
    u64                        sched_core_policy; /* SCHED_CORE_POLICY_UNSPEC */
                                                 /* SCHED_CORE_POLICY_SINGLE */
                                                 /* SCHED_CORE_POLICY_ALL */
};

The size field should be initialized to the size of the sched_attr structure as known to user space. The kernel sets this field to the size of its own sched_attr structure. The value must be at least as large as the size of the initially published sched_attr structure, or the call fails with the error EINVAL.

The sched_policy field specifies the scheduling policy. The following values are recognized:

SCHED_EDF
Earliest Deadline First (EDF) policy. This policy is active by default for new tasks that are not explicitly assigned a policy. The parameters sched_runtime, sched_period, and sched_deadline are used.
SCHED_RR
Round-robin policy. This is the traditional POSIX real-time policy. sched_priority is used.
SCHED_FIFO
First-In, First-Out policy. This is the traditional POSIX real-time policy. sched_priority is used.
SCHED_NORMAL
Normal Linux time-sharing scheduling. This is the default policy for most processes. The parameter sched_nice is used.
SCHED_BATCH
Batch scheduling policy. This is similar to SCHED_NORMAL, but it is intended for batch jobs that do not require interactive response. Tasks running under SCHED_BATCH receive lower priority than normal tasks. sched_nice is used.
SCHED_IDLE
Idle scheduling policy. This is similar to SCHED_NORMAL, but it is intended for tasks that should run only when nothing else can. sched_nice is used.
SCHED_DEADLINE
Deadline scheduling policy. This policy supports real-time tasks with explicit deadlines. The parameters sched_runtime, sched_period, and sched_deadline are used.

These parameters specify the task's runtime, period, and deadline.

  • sched_runtime: The maximum time (in nanoseconds) the task is allowed to run within each period.
  • sched_period: The time interval (in nanoseconds) over which the runtime is measured.
  • sched_deadline: The time (in nanoseconds) by which the task must complete its execution within each period.
The parameters must satisfy the following constraints: 0 <= sched_runtime <= sched_period <= sched_deadline.

The system performs admission control to ensure that the scheduling parameters are feasible. If the parameters are not feasible, the call fails with the error EBUSY.

The sched_flags field can be used to control the behavior of the SCHED_DEADLINE policy. The following flags are supported:

SCHED_FLAG_RESTART
When the task is created or scheduled, its runtime is reset to the initial value.
SCHED_FLAG_DL_OVERRUN
If the task misses its deadline, it is preempted and put to sleep until the next period starts.
SCHED_FLAG_UTIL_CLAMP_MIN
Clamp the task's CPU utilization to be at least sched_util_min.
SCHED_FLAG_UTIL_CLAMP_MAX
Clamp the task's CPU utilization to be at most sched_util_max.

The flags argument is reserved for future extensions and must be specified as 0.

The sched_flags field can be used to specify additional flags. The following flags are supported:

SCHED_FLAG_RESET_ON_FORK
If this flag is set, the scheduling attributes of the thread are reset to the default when the thread forks. This is the default behavior for most scheduling policies.
SCHED_FLAG_KEEP_POLICY
If this flag is set, the scheduling policy is not changed when the thread forks.
sched_runtime
This field specifies the "Runtime" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_period
This field specifies the "Period" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_deadline
This field specifies the "Deadline" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_util_min
sched_util_max (les deux depuis Linux 5.3)
Ces champs spécifient l'utilisation minimale et maximale attendue, respectivement. Ils sont ignorés à moins que leurs correspondants SCHED_FLAG_UTIL_CLAMP_MIN ou SCHED_FLAG_UTIL_CLAMP_MAX ne soient définis dans sched_flags.
L'utilisation est une valeur dans l'intervalle [0, 1024], représentant le pourcentage de temps CPU utilisé par une tâche lorsqu'elle s'exécute à la fréquence maximale sur le CPU de capacité la plus élevée du système. Il s'agit d'une représentation en point fixe, où 1024 correspond à 100%, et 0 correspond à 0%. Par exemple, une tâche avec une utilisation de 20% est une tâche s'exécutant pendant 2ms toutes les 10ms à fréquence maximale et est représentée par une valeur d'utilisation de 0.2 * 1024 = 205.
Une tâche avec une valeur d'utilisation minimale supérieure à 0 est plus susceptible d'être planifiée sur un CPU avec une capacité suffisamment grande pour contenir la valeur spécifiée. Une tâche avec une valeur d'utilisation maximale inférieure à 1024 est plus susceptible d'être planifiée sur un CPU n'ayant pas plus de capacité que la valeur spécifiée.
Une limite d'utilisation de tâche peut être réinitialisée en définissant son champ à UINT32_MAX (depuis Linux 5.11).

L'argument flags est fourni pour permettre des extensions futures à l'interface ; dans l'implémentation actuelle, il doit être spécifié comme 0.

sched_getattr()

L'appel système sched_getattr() récupère la politique de planification et les attributs associés pour le thread dont l'ID est spécifié dans pid. Si pid est égal à zéro, la politique de planification et les attributs du thread appelant seront récupérés.

L'argument size doit être défini à la taille de la structure sched_attr telle que connue dans l'espace utilisateur. La valeur doit être au moins aussi grande que la taille de la structure sched_attr initialement publiée, sinon l'appel échoue avec l'erreur EINVAL.

Les attributs de planification récupérés sont placés dans les champs de la structure sched_attr pointée par attr. Le noyau définit attr.size à la taille de sa structure sched_attr.

Si le tampon attr fourni par l'appelant est plus grand que la structure sched_attr du noyau, les octets supplémentaires dans la structure de l'espace utilisateur ne sont pas modifiés. Si la structure fournie par l'appelant est plus petite que la structure sched_attr du noyau, le noyau ne retournera silencieusement aucune valeur qui serait stockée en dehors de l'espace fourni. Comme avec sched_setattr(), ces sémantiques permettent l'extensibilité future de l'interface.

L'argument flags est fourni pour permettre des extensions futures à l'interface ; dans l'implémentation actuelle, il doit être spécifié comme 0.

VALEUR DE RETOUR

En cas de succès, sched_setattr() et sched_getattr() retournent 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

sched_getattr() et sched_setattr() peuvent tous deux échouer pour les raisons suivantes :

EINVAL
attr est NULL ; ou pid est négatif ; ou flags n'est pas zéro.
ESRCH
Le thread dont l'ID est pid n'a pas pu être trouvé.

De plus, sched_getattr() peut échouer pour les raisons suivantes :

E2BIG
Le tampon spécifié par size et attr est trop petit.
EINVAL
size est invalide ; c'est-à-dire qu'il est plus petit que la version initiale de la structure sched_attr (48 octets) ou plus grand que la taille de page système.

De plus, sched_setattr() peut échouer pour les raisons suivantes :

E2BIG
Le tampon spécifié par size et attr est plus grand que la structure du noyau, et un ou plusieurs des octets excédentaires sont non nuls.
EBUSY
Échec du contrôle d'admission SCHED_DEADLINE, voir sched(7).
EINVAL
attr.sched_policy n'est pas l'une des politiques reconnues.
EINVAL
attr.sched_flags contient un drapeau autre que SCHED_FLAG_RESET_ON_FORK.
EINVAL
attr.sched_priority est invalide.
EINVAL
attr.sched_policy est SCHED_DEADLINE, et les paramètres de planification de deadline dans attr sont invalides.
EINVAL
attr.sched_flags contient SCHED_FLAG_UTIL_CLAMP_MIN ou SCHED_FLAG_UTIL_CLAMP_MAX, et attr.sched_util_min ou attr.sched_util_max sont hors limites.
EOPNOTSUPP
SCHED_FLAG_UTIL_CLAMP a été fourni, mais le noyau n'a pas été compilé avec le support CONFIG_UCLAMP_TASK.
EPERM
L'appelant ne possède pas les privilèges appropriés.
EPERM
Le masque d'affinité CPU du thread spécifié par pid n'inclut pas tous les CPU du système (voir sched_setaffinity(2)).

NORMES

Linux.

HISTORIQUE

Linux 3.14.

NOTES

glibc ne fournit pas d'enveloppes pour ces appels système ; appelez-les en utilisant syscall(2).

sched_setattr() offre un sur-ensemble des fonctionnalités de sched_setscheduler(2), sched_setparam(2), nice(2), et (à l'exception de la capacité de définir la priorité de tous les processus appartenant à un utilisateur spécifié ou à tous les processus d'un groupe spécifié) setpriority(2). De manière analogue, sched_getattr() offre un sur-ensemble des fonctionnalités de sched_getscheduler(2), sched_getparam(2), et (partiellement) getpriority(2).

BOGUES

Dans les versions de Linux jusqu'à 3.15, sched_setattr() échouait avec l'erreur EFAULT au lieu de E2BIG pour le cas décrit dans ERREURS.

Jusqu'à Linux 5.3, sched_getattr() échouait avec l'erreur EFBIG si la structure sched_attr du noyau était plus grande que la size passée par l'espace utilisateur.

sched_setattr(2)

sched_setattr(2) - define scheduling policy and parameters for a process

SYNOPSIS

#include <sched.h>

int sched_setattr(pid_t pid, const struct sched_attr *attr, unsigned int flags);
int sched_getattr(pid_t pid, struct sched_attr *attr, unsigned int *flags, void *reserved);

DESCRIPTION

The sched_setattr() function sets the scheduling policy and parameters for the process specified by pid, according to the values specified in the attr structure.

The sched_getattr() function retrieves the scheduling policy and parameters for the process specified by pid, and stores them in the attr structure.

The attr structure is defined as follows:

struct sched_attr {
    __u32 size;                 /* Taille de la structure */
    __u32 sched_policy;         /* Politique d'ordonnancement */
    __u64 sched_flags;          /* Indicateurs */
    __s32 sched_nice;           /* Nice value */
    __u32 sched_priority;       /* Priorité */
    __u64 sched_runtime;        /* Temps d'exécution (en nanosecondes) */
    __u64 sched_period;         /* Période (en nanosecondes) */
    __u64 sched_utilization;    /* Utilisation (en nanosecondes) */
};

The pid argument specifies the target process. If pid is 0, the calling process is used.

The flags argument can be used to modify the behavior of sched_setattr(). Currently, the only defined flag is SCHED_FLAG_RESET_ON_FORK, which causes the scheduling attributes to be reset to the default when the process forks.

The reserved argument is reserved for future use and must be NULL.

RETURN VALUE

On success, sched_setattr() and sched_getattr() return 0.

On error, they return -1, and errno is set to indicate the error.

ERRORS

The following values can be set in errno:

  • EINVAL: Invalid arguments.
  • EPERM: Operation not permitted.
  • ESRCH: No such process.

STANDARDS

These functions are part of the POSIX real-time extensions.

HISTORY

These functions were introduced in Linux kernel 2.6.38.

NOTES

The SCHED_DEADLINE, SCHED_RR, and SCHED_FIFO policies require root privileges or the CAP_SYS_NICE capability.

BUGS

None known.
