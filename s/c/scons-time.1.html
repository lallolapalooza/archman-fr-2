NOM

scons-time - générer et afficher des informations de chronométrage SCons

SYNTAXE

Texte d'aide

scons-time help SOUS-COMMANDE [...]

DESCRIPTION

La commande scons-time exécute une configuration SCons à travers un ensemble standard de chronométrages profilés et peut extraire et tracer des informations à partir des profils résultants et des fichiers journaux de ces chronométrages. L'action à effectuer par le script scons-time est spécifiée par une sous-commande, le premier argument sur la ligne de commande. Voir la section SOUS-COMMANDES ci-dessous pour plus d'informations sur le fonctionnement des sous-commandes spécifiques.

La manière de base d'utiliser scons-time est d'exécuter la sous-commande scons-time run (éventuellement plusieurs fois) pour générer des fichiers de profil et de journal de chronométrage, puis d'utiliser l'une des autres sous-commandes pour afficher les résultats capturés dans les profils et les fichiers journaux pour un type d'information particulier : chronométrages de fonctions (la sous-commande scons-time func), mémoire totale utilisée (la sous-commande scons-time mem), comptes d'objets (la sous-commande scons-time obj) et temps d'exécution global (la sous-commande scons-time time). Des options permettent de placer et de trouver les profils et les fichiers journaux dans des répertoires séparés, de générer la sortie dans un format adapté au traçage avec le programme gnuplot(1), et ainsi de suite.

Il existe deux manières principales d'utiliser la sous-commande scons-time run pour collecter des statistiques de chronométrage pour une configuration. L'une consiste à utiliser l'option --svn= pour tester une configuration par rapport à une liste de révisions du dépôt Subversion de SCons. Cela générera un fichier de profil et un fichier journal de chronométrage pour chaque révision listée avec l'option --number=, et peut être utilisé pour examiner l'impact des modifications validées dans la base de code SCons sur une configuration particulière au fil du temps.

L'autre manière consiste à profiler les modifications incrémentielles d'une base de code SCons locale pendant un cycle de développement, c'est-à-dire à examiner l'impact sur les performances des modifications que vous apportez dans l'arborescence locale. Dans ce mode, vous exécutez la sous-commande scons-time run *sans* l'option --svn=, auquel cas elle recherche simplement dans le répertoire de sortie des profils/journaux (le répertoire courant par défaut) et détermine automatiquement le *prochain* numéro d'exécution pour le fichier de profil et le fichier journal de sortie. Utilisée de cette manière, le cycle de développement se déroule comme suit : apportez une modification à SCons ; exécutez scons-time run pour la profiler par rapport à une configuration spécifique ; apportez une autre modification à SCons ; exécutez à nouveau scons-time run pour la profiler ; etc.

OPTIONS

La commande scons-time ne prend en charge que quelques options globales :

-h, --help

Affiche le texte d'aide global et quitte, identique à la sous-commande scons-time help.

-V, --version

Affiche la version de scons-time et quitte.

La plupart des fonctionnalités sont contrôlées par des options des sous-commandes individuelles. Voir la section suivante pour des informations sur les options des sous-commandes individuelles.

SOUS-COMMANDES

La commande scons-time prend en charge les sous-commandes individuelles suivantes.

La sous-commande func

scons-time func [-h] [--chdir=RÉP] [-f FICHIER] [--fmt=FORMAT] [--func=NOM] [-p CHAÎNE] [-t NOMBRE] [--title= TITRE] [ARGUMENTS]

La sous-commande scons-time func affiche des informations de chronométrage pour une fonction Python spécifique au sein de SCons. Par défaut, elle extrait des informations sur la fonction _main(), qui inclut le chronométrage du profileur Python pour l'ensemble de SCons.

La sous-commande scons-time func extrait les informations de chronométrage de fonction de tous les arguments de fichier spécifiés, qui devraient être des fichiers de sortie du profileur Python. (Normalement, il s'agirait de fichiers *.prof générés par la sous-commande scons-time run, mais ils peuvent en fait être générés par n'importe quelle invocation d'un profileur Python.) Tous les noms de fichiers seront globés pour les fichiers sur disque.

Si aucun argument n'est spécifié, les informations de chronométrage de fonction seront extraites de tous les fichiers *.prof, ou du sous-ensemble d'entre eux avec un préfixe spécifié par l'option -p.

Les options incluent :

-C DIRECTORY, --chdir=DIRECTORY

Change pour le RÉPERTOIRE spécifié avant de rechercher les fichiers spécifiés (ou les fichiers qui correspondent aux modèles spécifiés).

-f FICHIER, --file=FICHIER

Lit les informations de configuration du FICHIER spécifié.

-fmt=FORMAT, --format=FORMAT

Rapporte la sortie dans le FORMAT spécifié. Les formats actuellement pris en charge sont ascii (par défaut) et gnuplot.

--func=NOM

Extrait les chronométrages pour le NOM de fonction spécifié. Par défaut, il rapporte les chronométrages cumulatifs pour la fonction _main(), qui contient l'ensemble de l'exécution SCons.

-h, --help

Affiche le texte d'aide pour la sous-commande scons-time func.

-p CHAÎNE, --prefix=CHAÎNE

Spécifie la chaîne de préfixe pour les profils à partir desquels extraire les informations de chronométrage de fonction. Ceci sera utilisé pour rechercher les profils si aucun argument n'est spécifié sur la ligne de commande.

-t NOMBRE, --tail=NOMBRE

Extrait uniquement les chronométrages de fonction des NOMBRE derniers fichiers.

scons-time help SOUS-COMMANDE [...] La sous-commande help imprime le texte d'aide pour toutes autres sous-commandes listées comme arguments suivants sur la ligne de commande.

La sous-commande run

scons-time run [-hnqv] [-f FILE] [--number=NUMBER] [--outdir=OUTDIR] [-p STRING] [--python=PYTHON] [-s DIR] [--scons=SCONS] [--svn=URL] [ARGUMENTS] La sous-commande scons-time run est la sous-commande de base pour profiler une configuration spécifique contre une version de SCons.

La configuration à tester est spécifiée comme une liste de fichiers ou de répertoires qui seront décompressés ou copiés dans un répertoire temporaire dans lequel SCons sera invoqué. La sous-commande scons-time run comprend les suffixes de fichiers tels que .tar, .tar.gz, .tgz et .zip et décompressera leur contenu dans un répertoire temporaire. Si plusieurs arguments sont spécifiés, chacun sera décompressé ou copié dans le répertoire temporaire "par-dessus" les archives ou répertoires précédents, donc l'attente est que plusieurs archives spécifiées partagent la même disposition de répertoire.

Une fois les arguments de fichier ou de répertoire décompressés ou copiés dans le répertoire temporaire, la sous-commande scons-time run exécute la version demandée de SCons contre la configuration trois fois :

Démarrage

SCons est exécuté avec l'option --help afin que seuls les fichiers SConscript soient lus, puis le texte d'aide par défaut est affiché. Ceci profile uniquement "l'overhead" perçu du démarrage de SCons et du traitement des fichiers SConscript.

Construction complète

SCons est exécuté pour construire tout ce qui est spécifié dans la configuration. Des cibles spécifiques à passer en ligne de commande peuvent être spécifiées par le mot-clé targets dans un fichier de configuration ; voir ci-dessous pour plus de détails.

Reconstruction

SCons est exécuté à nouveau sur le même répertoire qui vient d'être construit. Si les dépendances de la configuration SCons sont correctes, il devrait s'agir d'une reconstruction à jour, "ne rien faire".

Chaque invocation capture le fichier journal de sortie et un profil.

La sous-commande scons-time run prend en charge les options suivantes :

-f FILE, --file=FILE

Lit les informations de configuration à partir du FILE spécifié. Ceci fournit souvent un moyen plus pratique de spécifier et de collecter les paramètres associés à une configuration de timing spécifique que de les spécifier sur la ligne de commande. Voir la section FICHIER DE CONFIGURATION ci-dessous pour des informations sur les paramètres du fichier de configuration.

-h, --help

Affiche le texte d'aide pour la sous-commande scons-time run.

-n, --no-exec

N'exécute pas les commandes, imprime simplement les équivalents en ligne de commande de ce qui serait exécuté. Notez que le script scons-time exécute ses actions en Python, si possible, pour la portabilité. Les commandes affichées sont des équivalents UNIX de ce qu'il fait.

--number=NUMBER

Spécifie le numéro d'exécution à utiliser dans les noms des fichiers journaux et des sorties de profil générés par cette exécution.

Lorsqu'il est utilisé conjointement avec l'option --svn=URL, NUMBER spécifie un ou plusieurs numéros de révision Subversion séparés par des virgules qui seront automatiquement récupérés du référentiel Subversion à l'URL spécifiée. Des plages de numéros delta ou de révision peuvent être spécifiées en séparant deux numéros par un tiret (-).

Exemple :

% scons-time run --svn=http://scons.tigris.org/svn/trunk --num=1247,1249-1252 .

-p STRING, --prefix=STRING

Spécifie la chaîne de préfixe à utiliser pour tous les fichiers journaux et profils générés par cette exécution. Par défaut, il s'agit du premier argument spécifié : si le premier argument est un répertoire, le préfixe par défaut est le nom du répertoire ; si le premier argument est une archive (fichier tar ou zip), le préfixe par défaut est le nom de base de l'archive, c'est-à-dire ce qui reste après avoir retiré le suffixe d'archive (.tgz, .tar.gz ou .zip).

--python=PYTHON

Spécifie un chemin vers l'exécutable Python à utiliser pour les exécutions de timing. Par défaut, il s'agit d'utiliser le même exécutable Python qui exécute la commande scons-time elle-même.

-q, --quiet

Supprime l'affichage des lignes de commande en cours d'exécution.

-s DIR, --subdir=DIR

Spécifie le nom du répertoire ou sous-répertoire à partir duquel les commandes doivent être exécutées. Par défaut, c'est XXX

--scons=SCONS

Spécifie un chemin vers le script SCons à utiliser pour les exécutions de timing. Par défaut, c'est XXX

--svn=URL, --subversion=URL

Spécifie l'URL du référentiel Subversion à partir duquel la ou les versions de scons chronométrées seront extraites. Lorsque --svn est spécifié, l'option --number=NUMBER spécifie les numéros de révision qui seront testés. La sortie de chaque exécution sera placée dans des noms de fichiers correspondant aux numéros de révision Subversion. Si l'option --number= n'est pas spécifiée, le comportement par défaut est de chronométrer la HEAD de l'URL spécifiée.

-v, --verbose

Affiche la sortie des commandes individuelles à l'écran (en plus de la capture de la sortie dans les fichiers journaux).

La sous-commande time

scons-time time [-h] [--chdir=DIR] [-f FILE] [--fmt=FORMAT] [-p STRING] [-t NUMBER] [--title=TITLE] [--which=WHICH] [ARGUMENTS]

La sous-commande scons-time time affiche les temps d'exécution de SCons tels que rapportés par l'option scons --debug=time.

La sous-commande scons-time time extrait les données de timing de SCons de tous les arguments de fichier spécifiés, qui doivent être des fichiers contenant la sortie de l'exécution de SCons avec l'option --debug=time. (Normalement, il s'agirait de fichiers *.log générés par la sous-commande scons-time run.) Tous les arguments de nom de fichier seront globés pour les fichiers sur disque.

Si aucun argument n'est spécifié, les temps d'exécution seront extraits de tous les fichiers *.log, ou du sous-ensemble d'entre eux avec un préfixe spécifié par l'option -p.

NOM

-scons-time

SYNTAXE

scons-time [ -C DIR ] [ -f FILE ] [ -fmt FORMAT ] [ -h | --help ] [ -p STRING ] [ -t NUMBER ] [ --which=WHICH ] [ ARGUMENTS ]

DESCRIPTION

La commande scons-time est un utilitaire de ligne de commande conçu pour faciliter la collecte et le rapport des informations de temps d'exécution à partir des exécutions de SCons. Elle peut être utilisée pour exécuter SCons et collecter des informations de temps d'exécution, ou pour créer des rapports à partir de journaux existants.

Pour exécuter SCons et collecter des informations de temps d'exécution, exécutez simplement scons-time avec les mêmes arguments que ceux que vous donneriez à SCons. scons-time exécutera SCons dans un répertoire temporaire et générera des informations de temps d'exécution pour cette exécution.

Pour créer des rapports à partir de journaux existants, exécutez scons-time avec le nom du fichier journal comme argument.

SOUS-COMMANDES

La commande scons-time prend en charge les sous-commandes suivantes :

generate

Exécute SCons et collecte les informations de temps d'exécution. Cette sous-commande est la sous-commande par défaut si aucune autre sous-commande n'est spécifiée.

report

Génère un rapport à partir des informations de temps d'exécution collectées.

help

Affiche le texte d'aide pour la sous-commande scons-time.

OPTIONS

-C DIR, --chdir=DIR

Change pour le RÉPERTOIRE spécifié avant de rechercher les fichiers spécifiés (ou les fichiers qui correspondent aux modèles spécifiés).

-f FICHIER, --file=FICHIER

Lit les informations de configuration à partir du FICHIER spécifié.

-fmt=FORMAT, --format=FORMAT

Rapporte la sortie dans le FORMAT spécifié. Les formats actuellement pris en charge sont ascii (par défaut) et gnuplot.

-h, --help

Affiche le texte d'aide pour la sous-commande scons-time time.

-p CHAÎNE, --prefix=CHAÎNE

Spécifie la chaîne de préfixe pour les fichiers journaux à partir desquels extraire les temps d'exécution. Elle sera utilisée pour rechercher les fichiers journaux si aucun argument n'est spécifié sur la ligne de commande.

-t NOMBRE, --tail=NOMBRE

Ne rapporte les comptes d'objets que des NOMBRE derniers fichiers.

--which=WHICH

Affiche le temps d'exécution pour la valeur WHICH spécifiée : total (le temps d'exécution total), SConscripts (temps d'exécution total pour les fichiers SConscript eux-mêmes), SCons (temps d'exécution dans le code SCons lui-même) ou commands (temps d'exécution des commandes et autres actions utilisées pour construire les cibles). Si aucune option --which n'est spécifiée, le comportement par défaut est total, qui rapporte le temps d'exécution total pour chaque exécution.

FICHIER DE CONFIGURATION

Diverses sous-commandes de scons-time peuvent lire des informations à partir d'un fichier de configuration spécifié lorsqu'on leur passe les options -f ou --file. Le fichier de configuration est en fait exécuté comme un script Python. La définition de variables Python dans le fichier de configuration contrôle le comportement du script scons-time plus commodément que la spécification d'options ou d'arguments de ligne de commande pour chaque exécution, et fournit un moyen pratique de "rétrécir" les informations nécessaires pour produire (et rapporter) des exécutions de chronométrage cohérentes pour une configuration donnée.

archive_list

Une liste d'archives (fichiers ou répertoires) qui seront copiées dans le répertoire temporaire dans lequel SCons sera invoqué. Les fichiers .tar, .tar.gz, .tgz et .zip auront leur contenu décompressé dans le répertoire temporaire. Les arbres de répertoires et les fichiers seront copiés tels quels.

initial_commands

Une liste de commandes qui seront exécutées avant les exécutions chronométrées de scons. Cela peut être utilisé pour des commandes nécessaires à la préparation de l'arborescence source, par exemple, la création d'un fichier de configuration qui ne doit pas faire partie de l'exécution chronométrée.

key_location

L'emplacement de la légende des informations graphiques Gnuplot générées avec l'option --format=gnuplot. La valeur par défaut est bottom left.

prefix

Le préfixe du nom de fichier à utiliser lors de l'exécution ou de l'extraction du chronométrage pour cette configuration.

python

Le nom du chemin de l'exécutable Python à utiliser lors de l'exécution ou de l'extraction d'informations pour cette configuration. La valeur par défaut est la même version de Python que celle utilisée pour exécuter SCons.

scons

Le nom du chemin du script SCons à utiliser lors de l'exécution ou de l'extraction d'informations pour cette configuration. La valeur par défaut est simplement scons.

scons_flags

Les indicateurs scons utilisés lors de l'exécution de SCons pour collecter les informations de temps. La valeur par défaut est --debug=count --debug=memory --debug=time --debug=memoizer.

scons_lib_dir, scons_wrapper, startup_targets, subdir

Le sous-répertoire du projet dans lequel le script scons-time doit se déplacer avant d'exécuter les commandes SCons à chronométrer.

subversion_url

L'URL Subversion de

svn

L'exécutable subversion utilisé pour extraire les révisions de SCons à chronométrer. La valeur par défaut est simplement svn.

svn_co_flag, tar, targets

Une chaîne contenant les cibles qui doivent être ajoutées à la ligne de commande de chaque exécution chronométrée de scons. Cela peut être utilisé pour restreindre ce qui est chronométré à un sous-ensemble de la construction complète pour la configuration.

targets0, targets1, targets2, title, unzip, verbose, vertical_bars

Exemple

Voici un exemple de fichier de configuration scons-time pour un projet hypothétique :

# Le projet n'utilise pas SCons nativement (encore), donc nous
# chronométrons un ensemble distinct de SConscript qui nous posons
# par-dessus l'archive tar du projet décompressée.
arguments = ['project-1.2.tgz', 'project-SConscripts.tar']
# Le nom du sous-répertoire contient le numéro de version du projet,
# alors dites à scons-time de s'y déplacer avant de construire.
subdir = 'project-1.2'
# Définissez le préfixe, afin que les fichiers journaux et les profils de sortie soient nommés :
#     project-000-[012].{log,prof}
#     project-001-[012].{log,prof}
# etc.
prefix = 'project'
# Les fichiers SConscript testés ne font aucune configuration SConf,
# alors exécutez leur script de configuration normal ./configure avant
# d'invoquer SCons.
initial_commands = [
    './configure',
]
# Chronométrez uniquement la construction de l'exécutable bin/project.
targets = 'bin/project'
# Chronométrez contre les révisions SCons des branches/branche principale
subversion_url = 'http://scons.tigris.org/svn/scons/branches/core'
