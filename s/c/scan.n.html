scan(n) Tcl Built-In Commands scan(n)

NOM

scan - Analyser une chaîne en utilisant des spécificateurs de conversion dans le style de sscanf

SYNOPIS

scan chaîne format ?varName varName ...?

INTRODUCTION

Cette commande analyse des sous-chaînes d'une chaîne d'entrée d'une manière similaire à la procédure ANSI C sscanf et retourne le nombre de conversions effectuées, ou -1 si la fin de la chaîne d'entrée est atteinte avant que toute conversion ait été effectuée. chaîne donne l'entrée à analyser et format indique comment l'analyser, en utilisant des spécificateurs de conversion % comme dans sscanf. Chaque varName donne le nom d'une variable; lorsqu'une sous-chaîne est analysée depuis chaîne qui correspond à un spécificateur de conversion, la sous-chaîne est assignée à la variable correspondante. Si aucune variable varName n'est spécifiée, alors scan fonctionne de manière intégrée, retournant les données qui seraient autrement stockées dans les variables sous forme de liste. Dans le cas intégré, une chaîne vide est retournée lorsque la fin de la chaîne d'entrée est atteinte avant que toute conversion ait été effectuée.

DÉTAILS SUR L'ANALYSE

Scan opère en analysant chaîne et format ensemble. Si le caractère suivant dans format est un espace ou une tabulation, il correspond à n'importe quel nombre de caractères d'espacement dans chaîne (y compris zéro). Sinon, s'il ne s'agit pas d'un caractère %, il doit correspondre au caractère suivant de chaîne. Lorsqu'un % est rencontré dans format, il indique le début d'un spécificateur de conversion. Un spécificateur de conversion contient jusqu'à quatre champs après le % : un spécificateur de position XPG3 (ou un * pour indiquer que la valeur convertie doit être ignorée au lieu d'être assignée à une variable) ; un nombre indiquant une largeur de sous-chaîne maximale ; un modificateur de taille ; et un caractère de conversion. Tous ces champs sont optionnels sauf le caractère de conversion. Les champs présents doivent apparaître dans l'ordre indiqué ci-dessus.

Lorsque scan trouve un spécificateur de conversion dans format, il ignore d'abord tous les caractères d'espacement dans chaîne (sauf si le caractère de conversion est [ ou c). Ensuite, il convertit les caractères d'entrée suivants selon le spécificateur de conversion et stocke le résultat dans la variable donnée par l'argument suivant à scan.

SPÉCIFICATEUR DE POSITION OPTIONNEL

Si le % est suivi d'un nombre décimal et d'un $, comme dans « %2$d », alors la variable à utiliser n'est pas prise à partir de l'argument séquentiel suivant. Au lieu de cela, elle est prise à partir de l'argument indiqué par le nombre, où 1 correspond au premier varName. S'il y a des spécificateurs de position dans format, alors tous les spécificateurs doivent être positionnels. Chaque varName dans la liste des arguments doit correspondre exactement à un spécificateur de conversion ou une erreur est générée, ou dans le cas intégré, chaque position peut être spécifiée au maximum une fois et les positions vides seront remplies avec des chaînes vides.

MODIFICATEUR DE TAILLE OPTIONNEL

Le champ du modificateur de taille est utilisé uniquement lors de l'analyse d'une sous-chaîne dans l'une des valeurs entières de Tcl. Le champ du modificateur de taille dicte la plage d'entiers acceptable à stocker dans une variable, ou, pour le cas intégré, dans une position de la liste de résultats. Les valeurs syntaxiquement valides pour le modificateur de taille sont h, L, l et ll. La valeur du modificateur de taille h est équivalente à l'absence de modificateur de taille dans le spécificateur de conversion. L'un ou l'autre indique que la plage d'entiers à stocker est limitée à la même plage produite par la fonction int() de la commande expr. Le modificateur de taille L est équivalent au modificateur de taille l. L'un ou l'autre indique que la plage d'entiers à stocker est limitée à la même plage produite par la fonction wide() de la commande expr. Le modificateur de taille ll indique que la plage d'entiers à stocker est illimitée.

CARACTÈRE DE CONVERSION OBLIGATOIRE

Les caractères de conversion suivants sont pris en charge :

d
La sous-chaîne d'entrée doit être un entier décimal. Elle est lue et la valeur entière est stockée dans la variable, tronquée selon les besoins du modificateur de taille.
o
La sous-chaîne d'entrée doit être un entier octal. Elle est lue et la valeur entière est stockée dans la variable, tronquée selon les besoins du modificateur de taille.
x ou X
La sous-chaîne d'entrée doit être un entier hexadécimal. Elle est lue et la valeur entière est stockée dans la variable, tronquée selon les besoins du modificateur de taille.
b
La sous-chaîne d'entrée doit être un entier binaire. Elle est lue et la valeur entière est stockée dans la variable, tronquée selon les besoins du modificateur de taille.
u
La sous-chaîne d'entrée doit être un entier décimal. La valeur entière est tronquée selon les besoins du modificateur de taille, et la valeur non signée correspondante pour cette plage de troncature est calculée et stockée dans la variable sous forme de chaîne décimale. La conversion n'a de sens qu'en référence à une plage de troncature, le modificateur de taille ll n'est donc pas autorisé en combinaison avec le caractère de conversion u.
i
La sous-chaîne d'entrée doit être un entier. La base (c'est-à-dire décimale, octale ou hexadécimale) est déterminée par la convention C (0 initial pour l'octal ; préfixe 0x pour l'hexadécimal). La valeur entière est stockée dans la variable, tronquée selon les besoins du modificateur de taille.
c
Un seul caractère est lu et sa valeur Unicode est stockée dans la variable en tant que valeur entière. Les espaces blancs initiaux ne sont pas ignorés dans ce cas, la sous-chaîne d'entrée peut donc être un caractère d'espacement.
s
La sous-chaîne d'entrée consiste en tous les caractères jusqu'au prochain caractère d'espacement ; les caractères sont copiés dans la variable.
e ou f ou g ou E ou G
La sous-chaîne d'entrée doit être un nombre à virgule flottante constitué d'un signe optionnel, d'une chaîne de chiffres décimaux pouvant contenir un point décimal, et d'un exposant optionnel constitué d'un e ou E suivi d'un signe optionnel et d'une chaîne de chiffres décimaux. Il est lu et stocké dans la variable sous forme de valeur à virgule flottante.
[chars]
La sous-chaîne d'entrée consiste en un ou plusieurs caractères dans chars. La chaîne correspondante est stockée dans la variable. Si le premier caractère entre les crochets est un ], il est traité comme faisant partie de chars plutôt que comme le crochet fermant de l'ensemble. Si chars contient une séquence de la forme a-b, alors tout caractère entre a et b (inclus) correspondra. Si le premier ou le dernier caractère entre les crochets est un -, il est traité comme faisant partie de chars plutôt que comme indiquant une plage.
[^chars]
La sous-chaîne d'entrée consiste en un ou plusieurs caractères qui ne sont pas dans chars. La chaîne correspondante est stockée dans la variable. Si le caractère immédiatement suivant le ^ est un ], il est traité comme faisant partie de l'ensemble plutôt que comme le crochet fermant de l'ensemble. Si chars contient une séquence de la forme a-b, alors tout caractère entre a et b (inclus) sera exclu de l'ensemble. Si le premier ou le dernier caractère entre les crochets est un -, il est traité comme faisant partie de chars plutôt que comme indiquant une valeur de plage.
n
Aucune entrée n'est consommée de la chaîne d'entrée. Au lieu de cela, le nombre total de caractères analysés à partir de la chaîne d'entrée jusqu'à présent est stocké dans la variable.

Le nombre de caractères lus dans l'entrée pour une conversion est le plus grand nombre qui ait un sens pour cette conversion particulière (par exemple, autant de chiffres décimaux que possible pour %d, autant de chiffres octaux que possible pour %o, etc.). scan - Tcl Command

NOM

scan - Analyser une chaîne de caractères et affecter les valeurs à des variables

SYNOPSIS

scan string format ?varName ...?

INTRODUCTION

Cette commande analyse la chaîne string en utilisant la spécification de format format. Les résultats de l'analyse sont affectés aux variables nommées par varName. Cette commande est similaire à la fonction C sscanf.

DÉTAILS DE L'ANALYSE

La commande scan est utilisée pour analyser les chaînes de caractères en fonction d'une spécification de format. Chaque spécification de conversion dans format contrôle l'analyse d'une partie de string. S'il y a des spécifications de conversion dans format, les arguments varName sont utilisés pour stocker les résultats. S'il y a plus de spécifications de conversion que de varName, les résultats supplémentaires sont ignorés. S'il y a plus de varName que de spécifications de conversion, les variables supplémentaires ne sont pas modifiées.

La spécification de format peut contenir des caractères ordinaires, qui doivent correspondre exactement aux caractères de la chaîne d'entrée, et des spécifications de conversion, qui commencent par un caractère %. La plupart des spécifications de conversion lisent des données à partir de la chaîne d'entrée et les convertissent en un certain type. Les caractères suivants peuvent apparaître entre le % et le caractère de conversion :

[*]
Si un caractère * suit le %, la valeur analysée est jetée et aucune variable n'est affectée.
[longueur]
Les spécificateurs de longueur suivants sont pris en charge :
h
Indique que la taille est courte.
l
Indique que la taille est longue.
L
Indique que la taille est longue double.
ll
Indique que la taille est extra longue (pour les entiers 64 bits).
[largeur]
Un entier facultatif spécifiant la largeur maximale des champs à lire. La conversion s'arrête soit lorsqu'un caractère d'espacement est rencontré, soit lorsque la largeur maximale de la sous-chaîne a été atteinte, le premier des deux arrivant. Si un * est présent dans le spécificateur de conversion, aucune variable n'est affectée et l'argument de scan suivant n'est pas consommé.

DIFFÉRENCES PAR RAPPORT À ANSI SSCANF

Le comportement de la commande scan est le même que le comportement de la procédure ANSI C sscanf, sauf pour les différences suivantes :

[1]
Le spécificateur de conversion %p n'est pas pris en charge.
[2]
Pour les conversions %c, une seule valeur de caractère est convertie en une chaîne décimale, qui est ensuite affectée à la varName correspondante ; aucune largeur de sous-chaîne ne peut être spécifiée pour cette conversion.
[3]
Le modificateur h est toujours ignoré et les modificateurs l et L sont ignorés lors de la conversion de valeurs réelles (c'est-à-dire que le type double est utilisé pour la représentation interne). Le modificateur ll n'a pas d'équivalent sscanf.
[4]
Si la fin de la chaîne d'entrée est atteinte avant que toute conversion n'ait été effectuée et qu'aucune variable ne soit fournie, une chaîne vide est retournée.

EXEMPLES

Convertir un caractère UNICODE en sa valeur numérique :

set char "x"
set value [scan $char %c]

Analyser une spécification de couleur simple de la forme #RRGGBB en utilisant des conversions hexadécimales avec des tailles de sous-chaîne :

set string "#08D03F"
scan $string "#%2x%2x%2x" r g b

Analyser une chaîne de temps HH:MM, en notant que cela évite les problèmes avec les nombres octaux en forçant l'interprétation en décimaux (si cela ne nous importait pas, nous utiliserions la conversion %i à la place) :

set string "08:08"   ;# Pas octal !
if {[scan $string "%d:%d" hours minutes] != 2} {
    error "not a valid time string"
}
# Nous devons comprendre nous-mêmes les plages numériques...
if {$minutes < 0 || $minutes > 59} {
    error "invalid number of minutes"
}

Diviser une chaîne en séquences de caractères non-espaces (notez l'utilisation de la conversion %n afin que nous ayons un saut correct des espaces de début) :

set string " a string {avec des mots entre accolades} + espace de début "
set words {}
while {[scan $string %s%n word length] == 2} {
    lappend words $word
    set string [string range $string $length end]
}

Analyser une chaîne de coordonnées simple, en vérifiant qu'elle est complète en recherchant explicitement le caractère de terminaison :

set string "(5.2,-4e-2)"
# Notez que les espaces avant les parties littérales du
# motif de scan sont significatifs, et que ")" est
# le caractère Unicode \u0029
if {
    [scan $string " (%f ,%f %c" x y last] != 3
    || $last != 0x0029
} then {
    error "invalid coordinate string"
}
puts "X=$x, Y=$y"

Une session interactive démontrant la troncature des valeurs entières déterminées par les modificateurs de taille :

% set tcl_platform(wordSize)
4
% scan 20000000000000000000 %d
2147483647
% scan 20000000000000000000 %ld
9223372036854775807
% scan 20000000000000000000 %lld
20000000000000000000
