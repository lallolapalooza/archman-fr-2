SCHED_SETPARAM(3P) Manuel du programmeur POSIX SCHED_SETPARAM(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sched_setparam — définir les paramètres d'ordonnancement (TEMPS RÉEL)

SYNOPSIS

#include <sched.h>
int sched_setparam(pid_t pid, const struct sched_param *param);

DESCRIPTION

La fonction sched_setparam() doit définir les paramètres d'ordonnancement du processus spécifié par pid aux valeurs spécifiées par la structure sched_param pointée par param. La valeur du membre sched_priority dans la structure sched_param doit être un entier quelconque dans la plage de priorité inclusive pour la politique d'ordonnancement actuelle du processus spécifié par pid. Des valeurs numériques plus élevées pour la priorité représentent des priorités plus élevées. Si la valeur de pid est négative, le comportement de la fonction sched_setparam() n'est pas spécifié.

Si un processus spécifié par pid existe, et si le processus appelant a la permission, les paramètres d'ordonnancement doivent être définis pour le processus dont l'identifiant de processus est égal à pid.

Si pid est zéro, les paramètres d'ordonnancement doivent être définis pour le processus appelant.

Les conditions dans lesquelles un processus a la permission de modifier les paramètres d'ordonnancement d'un autre processus sont définies par l'implémentation.

Les implémentations peuvent exiger que le processus demandeur dispose des privilèges appropriés pour définir ses propres paramètres d'ordonnancement ou ceux d'un autre processus.

Voir Politiques d'ordonnancement pour une description de la manière dont cette fonction affecte l'ordonnancement des threads au sein du processus cible.

Si la politique d'ordonnancement actuelle pour le processus cible n'est pas SCHED_FIFO, SCHED_RR ou SCHED_SPORADIC, le résultat est défini par l'implémentation ; ce cas inclut la politique SCHED_OTHER.

La valeur sched_ss_repl_period spécifiée doit être supérieure ou égale à la valeur sched_ss_init_budget spécifiée pour que la fonction réussisse ; si ce n'est pas le cas, la fonction échoue.

La valeur de sched_ss_max_repl doit être comprise dans l'intervalle inclusif [1,{SS_REPL_MAX}] pour que la fonction réussisse ; sinon, la fonction échoue. Il n'est pas spécifié si les valeurs sched_ss_repl_period et sched_ss_init_budget sont stockées telles que fournies par cette fonction ou si elles sont arrondies pour s'aligner sur la résolution de l'horloge utilisée.

Cette fonction n'est pas atomique par rapport aux autres threads du processus. Les threads peuvent continuer à s'exécuter pendant que cet appel de fonction est en cours de modification de la politique d'ordonnancement pour les entités sous-jacentes ordonnancées par le noyau utilisées par les threads de portée de contention du processus.

VALEUR RENVOYÉE

En cas de succès, la fonction sched_setparam() renvoie zéro.

Si l'appel à sched_setparam() échoue, la priorité reste inchangée, et la fonction renvoie une valeur de -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction sched_setparam() échoue si :

EINVAL
Un ou plusieurs des paramètres d'ordonnancement demandés sont en dehors de la plage définie pour la politique d'ordonnancement du pid spécifié.
EPERM
Le processus demandeur n'a pas la permission de définir les paramètres d'ordonnancement pour le processus spécifié, ou n'a pas les privilèges appropriés pour invoquer sched_setparam().
ESRCH
Aucun processus correspondant à celui spécifié par pid n'a été trouvé.
