NOM

schroot - entrer en toute sécurité dans un environnement chroot

SYNTAXE

schroot [-h|--help | -V|--version | -l|--list | -i|--info | --config | --location | --automatic-session | -b|--begin-session | --recover-session | -r|--run-session | -e|--end-session] [-f|--force] [-n nom-session|--session-name=nom-session] [-d répertoire|--directory=répertoire] [-u utilisateur|--user=utilisateur] [-p|--preserve-environment] [-s shell|--shell=shell] [-q|--quiet | -v|--verbose] [-c chroot|--chroot=chroot | [--all | --all-chroots | --all-source-chroots | --all-sessions] [--exclude-aliases]] [-o|--option=clé=valeur] [--] [COMMANDE [ ARG1 [ ARG2 [ ARGn]]]]

DESCRIPTION

schroot permet à l'utilisateur d'exécuter une commande ou un shell de connexion dans un environnement chroot. Si aucune commande n'est spécifiée, un shell de connexion sera lancé dans le répertoire de travail actuel de l'utilisateur à l'intérieur du chroot.

La commande est un programme, plus autant d'arguments optionnels que requis. Chaque argument peut être cité séparément.

Le répertoire dans lequel la commande ou le shell de connexion est exécuté dépend du contexte. Voir l'option --directory ci-dessous pour une description complète.

Toute utilisation de chroot sera enregistrée dans les logs du système. Dans certaines circonstances, l'utilisateur peut être amené à s' authentifier ; voir la section « Authentification », ci-dessous.

Si aucun chroot n'est spécifié, le nom ou l'alias de chroot ‘default’ sera utilisé par défaut. Ceci est équivalent à “--chroot=default”.

APERÇU

Il y a souvent un besoin d'exécuter des programmes dans un environnement virtualisé plutôt que directement sur le système hôte. Contrairement à d'autres systèmes de virtualisation tels que kvm ou Xen, schroot ne virtualise pas le système entier ; il ne virtualise que le système de fichiers, et certaines parties du système de fichiers peuvent encore être partagées avec l'hôte. Il est donc rapide, léger et flexible. Cependant, il ne virtualise pas d'autres aspects du système, tels que la mémoire partagée, le réseau, les périphériques, etc., et peut donc être moins sécurisé que d'autres systèmes, en fonction de son utilisation prévue. Voici quelques exemples d'utilisations existantes pour schroot :

•
Exécuter un programme non fiable dans un bac à sable (sandbox), afin qu'il ne puisse pas interférer avec les fichiers sur le système hôte ; ceci peut également être utilisé pour limiter les dommages qu'un service compromis peut infliger à l'hôte.
•
Utiliser un environnement défini ou propre, pour garantir la reproductibilité et l'intégrité d'une tâche donnée.
•
Utiliser différentes versions d'un système d'exploitation, ou même différents systèmes d'exploitation, par exemple différentes distributions GNU/Linux.
•
Exécuter des programmes 32 bits en utilisant un chroot 32 bits sur un système hôte 64 bits.
•
Construction automatique de paquets Debian en utilisant sbuild(1), qui construit chaque paquet dans un snapshot de chroot vierge lors de l'utilisation de snapshots LVM ou d'unions.
•
Prise en charge de plusieurs images système dans une configuration de cluster, où la modification de l'image de base prend beaucoup de temps et/ou la prise en charge de toutes les configurations requises par les utilisateurs est difficile : différents chroots peuvent prendre en charge toutes les configurations différentes requises, et les utilisateurs du cluster peuvent se voir accorder l'accès aux chroots dont ils ont besoin (ce qui peut inclure l'accès root pour les utilisateurs de confiance afin de maintenir leurs propres images).

Un chroot peut être utilisé directement en tant que root en exécutant chroot(8), mais les utilisateurs normaux ne peuvent pas utiliser cette commande. schroot permet l'accès aux chroots pour les utilisateurs normaux en utilisant le même mécanisme, mais avec plusieurs fonctionnalités supplémentaires. Alors que schroot utilise un répertoire comme chroot tout comme chroot(8), il n'exige pas que ce soit un répertoire régulier dans le système de fichiers. Bien que ce soit le comportement par défaut, le chroot peut également être créé à partir d'un fichier, d'un système de fichiers, y compris les snapshots LVM et Btrfs et les montages en boucle (loopback), ou être composé d'une superposition unionfs. Étant extensible par l'utilisateur, la portée pour créer des chroots à partir de différentes sources est limitée uniquement par votre imagination. schroot effectue des vérifications d'autorisation et permet une configuration automatisée supplémentaire de l'environnement chroot, telle que le montage de systèmes de fichiers supplémentaires et d'autres tâches de configuration. Cette configuration automatisée se fait via l'action de scripts de configuration qui peuvent être personnalisés et étendus pour effectuer toutes les actions requises. Les actions typiques incluent le montage du répertoire personnel de l'utilisateur, la configuration du réseau et des bases de données système, et même le démarrage de services. Ceux-ci sont à nouveau entièrement personnalisables par l'administrateur. Les scripts de configuration sont exécutés pour tous les types de chroot, à l'exception du type 'plain', le type de chroot le plus simple, n'offrant aucune fonctionnalité de configuration automatisée. La configuration de schroot est détaillée dans schroot.conf(5).

OPTIONS

schroot accepte les options suivantes :

Actions

-h, --help
Affiche un résumé d'aide.
-V, --version
Imprime les informations de version.
-l, --list
Liste tous les chroots disponibles.
-i, --info
Imprime des informations détaillées sur les chroots spécifiés.
--config
Imprime la configuration des chroots spécifiés. Ceci est utile pour tester que la configuration utilisée est la même que celle du fichier de configuration. Les commentaires du fichier original seront absents.
--location
Imprime l'emplacement (chemin) des chroots spécifiés. Notez que les types de chroot qui ne peuvent être utilisés que dans une session n'auront pas d'emplacement tant qu'ils ne seront pas actifs.

Options générales

-q, --quiet
N'imprime que les messages essentiels.
-v, --verbose
Imprime tous les messages.

Sélection du chroot

-c, --chroot=chroot
Spécifie un chroot ou une session active à utiliser. Cette option peut être utilisée plusieurs fois pour spécifier plus d'un chroot, auquel cas son effet est similaire à --all. Le nom du chroot peut être précédé d'un espace de noms ; voir la section « Espaces de noms de chroot », ci-dessous.
-a, --all
Sélectionne tous les chroots, chroots source et sessions actives. Lorsqu'une commande a été spécifiée, la commande sera exécutée dans tous les chroots, chroots source et sessions actives. Si --info a été utilisé, affiche des informations sur tous les chroots. Cette option n'a pas de sens à utiliser avec un shell de connexion (exécuté lorsqu'aucune commande n'a été spécifiée). Cette option est équivalente à “--all-chroots --all-source-chroots --all-sessions”.
--all-chroots
Sélectionne tous les chroots. Identique à --all, sauf que les chroots source et les sessions actives ne sont pas pris en compte.
--all-sessions
Sélectionne toutes les sessions actives. Identique à --all, sauf que les chroots et les chroots source ne sont pas pris en compte.
--all-source-chroots
Sélectionne tous les chroots source. Identique à --all, sauf que les chroots et les sessions actives ne sont pas pris en compte.

Options générales

-f, --force
Forcer la création d'une nouvelle session, même si une session de même nom est déjà en cours d'exécution.
-n nom-session, --session-name=nom-session
Spécifie le nom d'une nouvelle session. Le nom doit être unique pour chaque session chroot. Si la session existe déjà, elle est réutilisée, sauf si l'option --force est utilisée.
-d répertoire, --directory=répertoire
Spécifie le répertoire de travail à l'intérieur du chroot. Si non spécifié, l'utilisateur sera placé dans son répertoire personnel à l'intérieur du chroot, ou dans le répertoire racine du chroot si son répertoire personnel n'existe pas dans le chroot.
-u utilisateur, --user=utilisateur
Spécifie l'utilisateur sous lequel exécuter la commande ou le shell de connexion. L'utilisateur spécifié doit exister dans le chroot. Si non spécifié, le nom d'utilisateur de l'utilisateur courant sera utilisé. Si l'utilisateur courant n'a pas de privilèges suffisants pour entrer dans le chroot, une authentification peut être requise.
-p, --preserve-environment
Préserve toutes les variables d'environnement de l'utilisateur courant lors de l'entrée dans le chroot. Par défaut, seules quelques variables d'environnement sont préservées. Notez que certains paramètres chroot peuvent remplacer ce comportement.
-s shell, --shell=shell
Spécifie le shell à utiliser pour une session de connexion. Si non spécifié, le shell par défaut de l'utilisateur sera utilisé.

Gestion des sessions

-b, --begin-session
Démarre une nouvelle session chroot. Si une commande est spécifiée, elle sera exécutée dans la nouvelle session. Sinon, un shell de connexion sera lancé.
--recover-session
Tente de récupérer une session chroot existante. Cela est utile si la session a été interrompue de manière anormale.
-r, --run-session
Exécute une commande dans une session chroot existante. Si aucune session n'est spécifiée, la dernière session chroot utilisée sera réutilisée.
-e, --end-session
Termine une session chroot existante. Si aucune session n'est spécifiée, la dernière session chroot utilisée sera terminée.
--automatic-session
Démarre une nouvelle session chroot si aucune session n'existe, sinon la réutilise. Utile pour les sessions interactives.

Autres options

-o clé=valeur, --option=clé=valeur
Définit une option spécifique au chroot. Les options disponibles dépendent du type de chroot. Par exemple, pour un chroot de type 'directory', vous pouvez définir l'option 'source' pour spécifier le répertoire source.
--
Indique la fin des options de schroot. Toute la suite sera interprétée comme une commande et ses arguments.

EXEMPLES

Pour lancer un shell de connexion dans le chroot nommé ‘default’ :

    $ schroot

Pour lancer un shell de connexion dans le chroot nommé ‘debian-sid’ :

    $ schroot -c debian-sid

Pour lancer la commande ls dans le chroot ‘default’ en tant qu'utilisateur ‘nobody’ :

    $ schroot -u nobody ls -l /

Pour lancer un shell de connexion dans le chroot ‘s390x-build’ en tant qu'utilisateur ‘buildd’ et préserver toutes les variables d'environnement :

    $ schroot -p -u buildd -c s390x-build

Pour lancer la commande make dans le répertoire ‘/usr/src/myapp’ à l'intérieur du chroot ‘default’ :

    $ schroot -d /usr/src/myapp -- make

Pour lancer la commande dpkg-buildpackage dans un environnement chroot qui est configuré pour construire des paquets Debian :

    $ schroot -c debian-experimental -- dpkg-buildpackage -b

Pour lister tous les chroots disponibles :

    $ schroot -l

Pour afficher des informations sur tous les chroots disponibles :

    $ schroot -i --all

Pour démarrer une nouvelle session nommée ‘my session’ dans le chroot ‘default’ :

    $ schroot -b -n "my session"

Pour terminer la session nommée ‘my session’ :

    $ schroot -e -n "my session"

AUTHENTIFICATION

Sous certaines conditions, schroot peut nécessiter une authentification de l'utilisateur. Ceci est normalement configuré par l'administrateur système. Les méthodes d'authentification les plus courantes sont :

•
PAM : Le système d'authentification modulaire (Pluggable Authentication Modules) est utilisé pour l'authentification. Ceci est la méthode la plus commune et la plus flexible.
•
chroot : Le mécanisme d'authentification de base de schroot est utilisé. Cela implique généralement la vérification des UID et GID de l'utilisateur.

La configuration spécifique de l'authentification est détaillée dans schroot.conf(5).

ESPACES DE NOMS DE CHROOT

schroot utilise le concept d'espaces de noms pour distinguer les chroots. Un espace de noms est un préfixe appliqué au nom d'un chroot. Par exemple, le nom d'un chroot pourrait être ‘user:mychroot’. Dans cet exemple, ‘user’ est l'espace de noms et ‘mychroot’ est le nom du chroot. Les espaces de noms permettent de regrouper logiquement les chroots et d'éviter les conflits de noms. Les espaces de noms les plus couramment utilisés sont :

•
user : Chroots appartenant à des utilisateurs spécifiques.
•
system : Chroots gérés par le système.
•
default : Le chroot par défaut.

Si aucun espace de noms n'est spécifié, le chroot sera recherché dans l'espace de noms par défaut.

--exclude-aliases
Ne pas sélectionner d'alias en plus des chroots. Cela garantit que seuls les vrais chroots sont sélectionnés et qu'ils ne sont listés qu'une seule fois.

Environnement chroot

-d, --directory=répertoire
Se déplacer dans répertoire à l'intérieur du chroot avant d'exécuter la commande ou le shell de connexion. Si répertoire n'est pas disponible, schroot se terminera avec un code d'erreur.
Le comportement par défaut est le suivant (tous les chemins de répertoire sont à l'intérieur du chroot). Un shell de connexion est lancé dans le répertoire de travail actuel. S'il n'est pas disponible, il essaiera $HOME (lorsque --preserve-environment est utilisé), puis le répertoire personnel de l'utilisateur, et enfin / à l'intérieur du chroot. Une commande est toujours exécutée dans le répertoire de travail actuel à l'intérieur du chroot. Si aucun des répertoires n'est disponible, schroot se terminera avec un code d'erreur.
-u, --user=utilisateur
Exécuter en tant qu'un autre utilisateur. Par défaut, il s'exécute en tant qu'utilisateur actuel. Si nécessaire, l'utilisateur peut être amené à s'authentifier avec un mot de passe. Pour plus d'informations, voir la section « Authentification », ci-dessous.
-p, --preserve-environment
Préserver l'environnement de l'utilisateur à l'intérieur de l'environnement chroot. Par défaut, un environnement propre est utilisé ; cette option copie l'intégralité de l'environnement utilisateur et le définit dans la session. Les variables d'environnement autorisées sont soumises à certaines restrictions ; voir la section « Environnement », ci-dessous.
-s, --shell=shell
Utiliser shell comme shell de connexion. Lors de l'exécution d'un shell de connexion, un certain nombre de shells potentiels sont considérés, dans cet ordre : la commande dans la variable d'environnement SHELL (si --preserve-environment est utilisé, ou si preserve-environment est activé), le shell de l'utilisateur dans la base de données ‘passwd’, /bin/bash et enfin /bin/sh. Cette option remplace cette liste et utilisera le shell spécifié. Cette option remplace également la clé de configuration shell, si elle est définie.
-o, --option=clé=valeur
Définir une option. La valeur des clés de configuration sélectionnées dans schroot.conf peut être modifiée à l'aide de cette option. La clé doit être présente dans la clé de configuration user-modifiable-keys dans schroot.conf, ou de manière supplémentaire la clé user-modifiable-keys si l'on exécute en tant que (ou si l'on bascule vers) l'utilisateur root. La clé et la valeur définies ici seront définies dans l'environnement des scripts de configuration, et pourront donc être utilisées pour personnaliser le chroot sur une base par session.

Actions de session

--automatic-session
Démarrer, exécuter et terminer une session automatiquement. C'est l'action par défaut, elle n'a donc pas besoin d'être spécifiée en fonctionnement normal.
-b, --begin-session
Démarrer une session. Un identifiant de session unique (ID de session) est retourné sur la sortie standard. L'ID de session est nécessaire pour utiliser les autres options de session. Notez que l'identifiant de session peut être spécifié avec l'option --session-name.
--recover-session
Récupérer une session existante. Si une session existante est devenue indisponible, par exemple en étant démontée suite à un redémarrage, cette option la rendra à nouveau disponible pour utilisation, par exemple en la remontant. L'ID de session est spécifié avec l'option --chroot.
-r, --run-session
Exécuter une session existante. L'ID de session est spécifié avec l'option --chroot.
-e, --end-session
Terminer une session existante. L'ID de session est spécifié avec l'option --chroot.

Options de session

-n, --session-name=nom-session
Nommer une session. Le nom-session spécifié remplace le nom de session par défaut contenant un ID de session généré automatiquement. Le nom de session ne doit pas contenir de qualificateur d'espace de noms, car les sessions sont toujours créées dans l'espace de noms ‘session:’. Le nom de session est également soumis aux restrictions de nommage de chroot documentées dans schroot.conf(5).
-f, --force
Forcer une opération de session, même si elle échouerait autrement. Cela peut être utilisé pour forcer la fin d'une session, même si elle a des utilisateurs actifs. Cela ne garantit pas que la session se terminera proprement ; les systèmes de fichiers peuvent ne pas être démontés, par exemple.

Séparateur

--
Fin des options. Utilisé pour indiquer la fin des options de schroot ; toutes les options suivantes seront transmises à la commande en cours d'exécution, plutôt qu'à schroot.

AUTHENTICATION

Si l'utilisateur n'est pas un utilisateur autorisé, ou un membre des groupes autorisés (ou si le changement s'effectue vers root, les utilisateurs root autorisés ou les groupes root autorisés) pour le(s) chroot(s) spécifié(s), l'accès sera immédiatement refusé. Si l'on change d'utilisateur, et que l'utilisateur exécutant la commande a accès, l'utilisateur sera invité à s'authentifier en utilisant les identifiants de l'utilisateur vers lequel il bascule.

Sur les systèmes prenant en charge les modules d'authentification enfichables (PAM), schroot utilisera PAM pour l'authentification et l'autorisation des utilisateurs. Si et quand nécessaire, schroot demandera un mot de passe. Si PAM n'est pas disponible, toute authentification échouera automatiquement (le changement d'utilisateur n'est *pas* pris en charge sans PAM).

Notez que lorsque PAM est utilisé, l'utilisateur root ne reçoit par défaut aucun privilège spécial dans le programme. Cependant, la configuration PAM par défaut permet à root de se connecter sans mot de passe (pam_rootok.so), mais cela peut être désactivé pour empêcher root d'accéder à tout chroot sauf si spécifiquement autorisé. Dans une telle situation, root doit être ajouté aux utilisateurs ou groupes autorisés comme pour tout autre utilisateur ou groupe. Si PAM n'est pas disponible, l'utilisateur root sera autorisé à accéder à tous les chroots, même lorsqu'il n'est pas explicitement autorisé.

ESPACES DE NOMS CHROOT

Principes de base des espaces de noms

Il existe trois types différents de chroots : les chroots réguliers, les chroots sources et les chroots de session. Ces différents types de chroots sont séparés en différents espaces de noms. Un espace de noms est un préfixe d'un nom de chroot. Actuellement, il existe trois espaces de noms : ‘chroot:’, ‘source:’ et ‘session:’. Utilisez --list --all pour lister tous les chroots disponibles dans tous les espaces de noms. Étant donné que ‘:’ est utilisé comme séparateur entre le nom de l'espace de noms et le nom du chroot, ce caractère n'est pas autorisé dans les noms de chroot.

Selon l'action que vous demandez à schroot d'effectuer, il peut rechercher le chroot dans l'un des trois espaces de noms, ou un espace de noms particulier peut être spécifié. Par exemple, un chroot nommé “sid” est en fait nommé “chroot:sid” si l'espace de noms est inclus, mais l'espace de noms peut être omis pour la plupart des actions.

Chroots sources

Certains types de chroots, par exemple les snapshots LVM et Btrfs, fournissent des snapshots copy-on-write gérés par session du chroot. Ceux-ci fournissent également un chroot source pour permettre un accès facile au système de fichiers utilisé comme source pour le snapshotting. Ce sont également des chroots réguliers, juste avec le snapshotting désactivé. Pour un chroot nommé “sid-snapshot” (c'est-à-dire avec un nom qualifié complet de “chroot:sid-snapshot”), il y aura également un chroot source correspondant nommé “source:sid-snapshot”. Les versions antérieures de schroot fournissaient des chroots sources avec un suffixe ‘-source’. Ceux-ci sont également fournis pour des raisons de compatibilité. Dans cet exemple, il serait appelé “chroot:sid-snapshot-source”. Ces noms de compatibilité seront supprimés dans une future version, les programmes et scripts devraient donc passer à l'utilisation des noms qualifiés par l'espace de noms plutôt qu'aux anciens suffixes.

Chroots de session

Toutes les sessions créées avec --begin-session sont placées dans l'espace de noms ‘session:’. Une session nommée avec --session-name peut avoir n'importe quel nom, même le même nom que le chroot à partir duquel elle a été créée, à condition qu'elle soit unique dans cet espace de noms. Cela n'était pas autorisé dans les versions précédentes de schroot qui n'avaient pas d'espaces de noms.

Actions et espaces de noms par défaut

Toutes les actions utilisent ‘chroot:’ comme espace de noms par défaut, à l'exception de certaines actions de session. --run-session, --recover-session et --end-session utilisent ‘session:’ comme espace de noms par défaut à la place, car ces actions fonctionnent sur les chroots de session. En fin de compte, l'espace de noms n'est généralement jamais requis, sauf lorsque vous devez travailler avec un chroot dans un espace de noms autre que celui par défaut, par exemple lors de l'utilisation d'un chroot source. Pour rendre la sélection de chroot non ambiguë, il est toujours possible d'utiliser le nom complet incluant l'espace de noms, même lorsque cela n'est pas strictement nécessaire.

PERFORMANCE

Les performances sur certains systèmes de fichiers, par exemple Btrfs, sont mauvaises lors de l'exécution de dpkg en raison du nombre d'opérations fsync effectuées. Cela peut être atténué en installant le paquet eatmydata, puis en ajoutant eatmydata à la ligne de commande.

ss="Li"> clé de configuration, qui désactive toutes les opérations fsync. Notez que cela ne doit être fait que dans les chroots snapshots où la perte de données n'est pas un problème. C'est utile lors de l'utilisation d'un chroot pour la construction de paquets, par exemple.

FALLBACKS DE RÉPERTOIRE

schroot sélectionnera un répertoire approprié à utiliser dans le chroot en fonction de l'utilisation d'un shell de connexion interactif ou de l'invocation d'une commande, et en outre si l'option --directory est utilisée. Dans le cas de l'exécution directe de commandes, ou de la spécification explicite d'un répertoire, un seul répertoire sera utilisé pour la sécurité et la cohérence, tandis que pour un shell de connexion, plusieurs possibilités peuvent être essayées. Les sous-sections suivantes listent la séquence de fallback pour chaque cas. CWD est le répertoire de travail courant, DIR est le répertoire spécifié avec --directory.

Shell de connexion

Transition
(Hôte → Chroot) Commentaire
CWD → CWD Comportement normal (si --directory n'est pas utilisé)
CWD → $HOME Si CWD est inexistant et --preserve-environment est utilisé
CWD → pw_dir de passwd Si CWD est inexistant (ou --preserve-environment est utilisé et aucun $HOME n'existe)
CWD → / Aucun des précédents n'existe
ÉCHEC Si / est inexistant

Commande

Transition
(Hôte → Chroot) Commentaire
CWD → CWD Comportement normal (si --directory n'est pas utilisé)
ÉCHEC Si CWD est inexistant

Aucun fallback ne devrait exister en aucun cas.

Utilisation de --directory

Transition
(Hôte → Chroot) Commentaire
CWD → DIR Comportement normal
ÉCHEC Si DIR est inexistant

Aucun fallback ne devrait exister en aucun cas.

Débogage

Notez que --debug=notice affichera la liste interne des fallbacks calculée pour la session.

  Personnalité           linux32
  Emplacement            /srv/chroot/sid

Utilisez --all ou -c plusieurs fois pour utiliser tous les chroots ou plusieurs chroots, respectivement.

Utilisez -- pour permettre aux options commençant par ‘-’ ou ‘--’ dans la commande d'être exécutées dans le chroot. Cela empêche qu'elles soient interprétées comme des options pour schroot lui-même. Notez que la première ligne a été écho à la sortie d'erreur standard, et les lignes restantes à la sortie standard. C'est intentionnel, afin que la sortie du programme des commandes exécutées dans le chroot puisse être redirigée comme requis ; les données seront les mêmes que si la commande avait été exécutée directement sur le système hôte.

Changement d'utilisateur

% schroot -c sid -u root↵
Mot de passe:
[sid chroot] (rleigh→root) Exécution du shell de connexion : “/bin/bash”
#

Si l'utilisateur ‘rleigh’ était dans root-users dans /etc/schroot/schroot.conf, ou l'un des groupes auxquels il appartenait était dans root-groups, il aurait eu un accès root sans authentification, mais l'étape d'autorisation PAM est toujours appliquée.

Sessions

Un chroot peut être nécessaire pour exécuter plus d'une commande. En particulier, lorsque le chroot est créé à la volée à partir d'un LV LVM ou d'un fichier sur disque, il est nécessaire de rendre le chroot persistant pendant qu'une tâche donnée (ou un ensemble de tâches) est effectuée. NAME


schroot — run commands and applications in a chroot environment






SYNOPSIS


schroot [-d chroot] [-u user] [-g group] [-N] [--] [command]


schroot [-b] [-c chroot] [-u user] [-g group] [-n session]


schroot [-e] [-c chroot] [-u user] [-g group] [-n session]






DESCRIPTION


schroot is a program which allows you to run commands and
    applications in an existing chroot environment. It provides a more advanced
    and flexible alternative to the standard chroot(2).


The chroot environment is determined by the configuration file
    /etc/schroot/schroot.conf. This file defines the chroots that may be
    used, how they are mounted, and the conditions under which they may be
    entered.


By default, schroot runs a shell within the chroot.
    If a command is specified on the command line, that command is run instead of
    a shell.


The user and group specified with -u and
    -g are the user and group that will be run inside the
    chroot. If not specified, the current user and their groups are used.


The -c option specifies the chroot to be used.
    This can be a chroot name or an alias defined in schroot.conf.


If the -d option is used, schroot
    will unmount and clean up the specified chroot session before running the
    command.


The -N option prevents schroot
    from automatically setting up the chroot environment. This is useful for
    manual setup or when the chroot is already prepared.


The -b option creates a new session for the
    specified chroot. This is useful for creating temporary environments or for
    running multiple instances of the same chroot.


The -e option executes a command within an
    existing session. This is useful for running commands in a pre-configured
    environment.


The -n option specifies the name of the session.
    This is useful for managing multiple sessions for the same chroot.






OVERVIEW


A schroot.conf(5) configuration
    file specifies one or more chroots, which are typically directories on the
    host system which contain a separate Linux filesystem hierarchy. The chroots
    can be accessed as root or as a normal user.
    schroot.conf(5) defines how the chroots are
    mounted and what setup scripts are executed before and after entering the
    chroot.


A chroot is identified by a name, which is configured in
    schroot.conf(5). Alternatively, an
    alias may be used which maps to a chroot name.


Each chroot can have a number of different sessions. Each session
    is an instance of the chroot, with its own mount points and environment.
    Sessions are identified by a unique session id, or by an optional name.


When schroot is invoked without any options,
    it will attempt to enter the default chroot (as defined in
    schroot.conf(5)) as the current user and
    execute a shell.


The -c option must be specified to select a
    chroot. The -u option may be used to specify the
    user to enter the chroot as. The -g option may be used
    to specify the group to enter the chroot as. If neither -u
    nor -g are specified, the current user and their
    groups will be used. The -n option may be used to
    specify a session name.


If a command is specified, it will be executed within the chroot,
    otherwise a shell will be executed.


If the -b option is used, a new chroot session
    will be created and entered. The session name may be specified using the
    -n option.


If the -e option is used, an existing chroot
    session will be entered. The session name must be specified using the
    -n option.


If the -d option is used, the specified chroot
    session will be removed (unmounted and cleaned up) after the command has
    exited.


The -N option prevents schroot
    from automatically setting up the chroot environment. This is useful for
    manual setup or when the chroot is already prepared.






OPTIONS



  
-b, --build

  
Create a new chroot session.

  
-c, --chroot chroot

  
Specify the chroot to be used. This can be a chroot name or an alias
      defined in schroot.conf.

  
-d, --destroy chroot

  
Destroy the specified chroot session after the command has exited.

  
-e, --enter

  
Enter an existing chroot session. The session name must be specified with
      -n.

  
-g, --group group

  
Specify the group to run as inside the chroot. If not specified, the
      current user's primary group is used.

  
-h, --host-template

  
Run the command on the host system instead of inside the chroot.

  
-l, --list

  
List available chroots and/or sessions.

  
-m, --mount

  
Mount the specified chroot. This is implied by -b and
      -e.

  
-n, --session-name session

  
Specify the name of the session. If not specified, a unique session ID
      is generated.

  
-N, --no-setup

  
Do not run any setup scripts. The chroot environment must already be
      prepared.

  
-p, --profile profile

  
Specify the profile to use for the session. The profile name corresponds
      to a subdirectory in /etc/schroot/profile.d.

  
-r, --run-session

  
Run the command in the specified chroot session. This is implied by
      -e.

  
-s, --save

  
Save the current chroot session state. This is only applicable to
      union-based chroots.

  
-u, --user user

  
Specify the user to run as inside the chroot. If not specified, the
      current user is used.

  
--

  
End of options. Any subsequent arguments are treated as the command to
      be executed.

  
--debug=level

  
Enable debugging output. Valid levels are none,
      notice, info,
      warning, and critical.

  
-h, --help

  
Display a help message and exit.

  
-v, --version

  
Display version information and exit.








AUTHENTICATION


By default, schroot relies on PAM for
    authentication. If the chroot is configured to require authentication, the user
    will be prompted for their password.


If schroot is run as root, no authentication is
    required.


The authentication method can be configured in
    schroot.conf(5).






CHROOT NAMESPACES


When entering a chroot, a new mount namespace is created by
    default. This ensures that the mounts within the chroot do not affect the
    host system.


The -N option can be used to disable the
    creation of a new mount namespace, which can be useful for certain
    advanced use cases.






PERFORMANCE


The performance of schroot depends on the type
    of chroot being used. Union-based chroots offer the best performance, as they
    avoid copying the entire chroot filesystem.


File-based chroots can be slower, especially during the initial
    unpacking phase.


The -p option can be used to specify a profile
    which may contain performance-related settings.






DIRECTORY FALLBACKS


In the absence of a -c option,
    schroot will attempt to enter the default chroot as
    defined in /etc/schroot/schroot.conf.


If no default chroot is defined, and no chroot is specified on the
    command line, schroot will exit with an error.






EXAMPLES


Enter the default chroot and run a shell:


% schroot↵


Enter the chroot named "sid" as user "john":


% schroot -c sid -u john↵


Enter the chroot named "sid" and run the command "apt-get update":


% schroot -c sid -- apt-get update↵


Create a new session named "my-session" for the chroot "sid":


% schroot -b -c sid -n my-session↵
my-session


Enter the existing session "my-session":


% schroot -e -c sid -n my-session↵


Destroy the session "my-session" after the command exits:


% schroot -d -c sid -n my-session -- some-command↵


Finally, the session names can be long and unwieldy. A name may be
    specified instead of using the automatically generated session ID:


% schroot -b -c sid-snap -n my-session-name↵
my-session-name






DÉPANNAGE


Si quelque chose ne fonctionne pas, et que les messages d'erreur ne
    sont pas clairs quant à la cause du problème, essayez d'utiliser l'option
    --debug=niveau pour activer les messages de débogage. Cela
    fournit beaucoup plus d'informations. Les niveaux de débogage valides sont
    « none », « notice », « info », « warning » et « critical » par ordre
    de gravité croissante. Plus le niveau de gravité est bas, plus la sortie est
    importante.


Si vous rencontrez toujours des problèmes, les développeurs peuvent
    être contactés sur la liste de diffusion :
  

  Debian buildd-tools Developers
  

  <buildd-tools-devel@lists.alioth.debian.org>






BOGUES


Sur les architectures mips et mipsel, les noyaux Linux
    jusqu'à et y compris au moins la version 2.6.17 ont un support
    personality(2) défectueux, ce qui entraîne un échec de la définition de la
    personnalité. Cela se manifestera par une erreur « Opération non autorisée »
    (EPERM). Pour contourner ce problème, définissez
    personality sur « undefined », ou mettez à niveau
    vers un noyau plus récent.






ENVIRONNEMENT


Par défaut, l'environnement n'est pas préservé, et les variables
    d'environnement suivantes sont définies : HOME, LOGNAME, PATH, SHELL, TERM
    (préservée si déjà définie), et USER. Les variables d'environnement
    SCHROOT_COMMAND, SCHROOT_USER, SCHROOT_GROUP, SCHROOT_UID et SCHROOT_GID
    sont définies à l'intérieur du chroot, spécifiant la commande en cours d'exécution,
    le nom d'utilisateur, le nom de groupe, l'ID utilisateur et l'ID de groupe,
    respectivement. De plus, les variables d'environnement SCHROOT_SESSION_ID,
    SCHROOT_CHROOT_NAME et SCHROOT_ALIAS_NAME spécifient l'ID de session, le nom
    du chroot d'origine avant la création de la session, et l'alias utilisé pour
    identifier initialement le chroot sélectionné, respectivement.


Les variables d'environnement potentiellement dangereuses suivantes sont
    supprimées par défaut pour des raisons de sécurité : BASH_ENV, CDPATH, ENV,
    HOSTALIASES, IFS, KRB5_CONFIG, KRBCONFDIR, KRBTKFILE, KRB_CONF, LD_.*,
    LOCALDOMAIN, NLSPATH, PATH_LOCALE, RES_OPTIONS, TERMINFO, TERMINFO_DIRS, et
    TERMPATH. Si désiré, la clé de configuration
    environment-filter permettra de modifier la
    liste d'exclusion ; voir schroot.conf(5) pour plus de détails.






FICHIERS




Fichiers de configuration



  
/etc/schroot/schroot.conf

  
Le fichier de définition des chroots au niveau du système. Ce fichier doit
      appartenir à l'utilisateur root et ne doit pas être inscriptible par les
      autres.

  
/etc/schroot/chroot.d

  
Des définitions de chroots supplémentaires peuvent être placées dans des
      fichiers sous ce répertoire. Ils sont traités de la même manière que
      /etc/schroot/schroot.conf. Chaque fichier peut contenir une ou
      plusieurs définitions de chroot. Notez que les fichiers dans ce répertoire
      suivent les mêmes règles de nommage que run-parts(8) lorsqu'il est exécuté avec l'option
      --lsbsysinit.

  
/etc/schroot/setup.d

  
Les répertoires de scripts de configuration des chroots au niveau du
      système. Voir schroot-setup(5).

  
/etc/pam.d/schroot

  
Configuration PAM.








Répertoires système



  
/usr/lib/schroot

  
Répertoire contenant les programmes d'aide utilisés par les scripts de
      configuration.








Répertoires de sessions


Chaque répertoire contient un répertoire ou un fichier avec le nom
    de chaque session. Tous les types de chroot n'utilisent pas tous les répertoires
    suivants.



  
/var/lib/schroot/session

  
Répertoire contenant la configuration de session pour chaque session active.

  
/var/run/schroot/mount

  
Répertoire utilisé pour monter les systèmes de fichiers utilisés par chaque
      session active.

  
/var/lib/schroot/union/underlay

  
Répertoire utilisé pour la source du montage union de système de fichiers
      (underlay).

  
/var/lib/schroot/union/overlay

  
Répertoire utilisé pour la surcouche inscriptible du montage union de
      système de fichiers.

  
/var/lib/schroot/unpack

  
Répertoire utilisé pour le décompactage des chroots basés sur des fichiers.
