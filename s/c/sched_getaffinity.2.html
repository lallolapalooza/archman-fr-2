sched_setaffinity(2) Manuel des appels système sched_setaffinity(2)

NOM

sched_setaffinity, sched_getaffinity - définir et obtenir le masque d'affinité CPU d'un thread

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <sched.h>
int sched_setaffinity(pid_t pid, size_t cpusetsize,
                      const cpu_set_t *mask);
int sched_getaffinity(pid_t pid, size_t cpusetsize,
                      cpu_set_t *mask);

DESCRIPTION

Le masque d'affinité CPU d'un thread détermine l'ensemble des CPU sur lesquels il est éligible pour s'exécuter. Sur un système multiprocesseur, la définition du masque d'affinité CPU peut être utilisée pour obtenir des bénéfices de performance. Par exemple, en dédiant un CPU à un thread particulier (c'est-à-dire en définissant le masque d'affinité de ce thread pour spécifier un seul CPU, et en définissant le masque d'affinité de tous les autres threads pour exclure ce CPU), il est possible d'assurer une vitesse d'exécution maximale pour ce thread. Restreindre un thread à s'exécuter sur un seul CPU évite également le coût de performance causé par l'invalidation du cache qui se produit lorsqu'un thread cesse de s'exécuter sur un CPU et reprend ensuite son exécution sur un autre CPU.

Un masque d'affinité CPU est représenté par la structure cpu_set_t, un "ensemble de CPU", pointé par mask. Un ensemble de macros pour manipuler les ensembles de CPU est décrit dans CPU_SET(3).

sched_setaffinity() définit le masque d'affinité CPU du thread dont l'ID est pid à la valeur spécifiée par mask. Si pid est zéro, alors le thread appelant est utilisé. L'argument cpusetsize est la longueur (en octets) des données pointées par mask. Normalement, cet argument serait spécifié comme sizeof(cpu_set_t).

Si le thread spécifié par pid ne s'exécute pas actuellement sur l'un des CPU spécifiés dans mask, alors ce thread est migré vers l'un des CPU spécifiés dans mask.

sched_getaffinity() écrit le masque d'affinité du thread dont l'ID est pid dans la structure cpu_set_t pointée par mask. L'argument cpusetsize spécifie la taille (en octets) de mask. Si pid est zéro, alors le masque du thread appelant est retourné.

VALEUR DE RETOUR

En cas de succès, sched_setaffinity() et sched_getaffinity() retournent 0 (mais voir la section "Différences entre la bibliothèque C et le noyau" ci-dessous, qui note que le sched_getaffinity() sous-jacent diffère dans sa valeur de retour). En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Une adresse mémoire fournie était invalide.
EINVAL
Le masque de bits d'affinité mask ne contient aucun processeur qui est actuellement physiquement sur le système et autorisé pour le thread selon toutes les restrictions qui peuvent être imposées par les cgroups cpuset ou le mécanisme "cpuset" décrit dans cpuset(7).
EINVAL
(sched_getaffinity() et, avant Linux 2.6.9, sched_setaffinity()) cpusetsize est plus petit que la taille du masque d'affinité utilisé par le noyau.
EPERM
(sched_setaffinity()) Le thread appelant n'a pas les privilèges appropriés. L'appelant doit avoir un ID utilisateur effectif égal à l'ID utilisateur réel ou effectif du thread identifié par pid, ou il doit posséder la capacité CAP_SYS_NICE dans l'espace de noms utilisateur du thread pid.
ESRCH
Le thread dont l'ID est pid n'a pas pu être trouvé.

NORMES

Linux.

HISTORIQUE

Linux 2.5.8, glibc 2.3.

Initialement, les interfaces glibc incluaient un argument cpusetsize, typé comme unsigned int. Dans glibc 2.3.3, l'argument cpusetsize a été supprimé, mais a été restauré dans glibc 2.3.4, avec le type size_t.

NOTES

Après un appel à sched_setaffinity(), l'ensemble des CPU sur lesquels le thread s'exécutera réellement est l'intersection de l'ensemble spécifié dans l'argument mask et de l'ensemble des CPU réellement présents sur le système. Le système peut restreindre davantage l'ensemble des CPU sur lesquels le thread s'exécute si le mécanisme "cpuset" décrit dans cpuset(7) est utilisé. Ces restrictions sur l'ensemble réel des CPU sur lesquels le thread s'exécutera sont imposées silencieusement par le noyau.

Il existe diverses façons de déterminer le nombre de CPU disponibles sur le système, notamment : l'inspection du contenu de /proc/cpuinfo ; l'utilisation de sysconf(3) pour obtenir les valeurs des paramètres _SC_NPROCESSORS_CONF et _SC_NPROCESSORS_ONLN ; et l'inspection de la liste des répertoires CPU sous /sys/devices/system/cpu/.

sched(7) contient une description du schéma de planification Linux.

Le masque d'affinité est un attribut par thread qui peut être ajusté indépendamment pour chacun des threads d'un groupe de threads. La valeur retournée par un appel à gettid(2) peut être passée dans l'argument pid. Spécifier pid à 0 définira l'attribut pour le thread appelant, et passer la valeur retournée par un appel à getpid(2) définira l'attribut pour le thread principal du groupe de threads. (Si vous utilisez l'API POSIX threads, utilisez pthread_setaffinity_np(3) au lieu de sched_setaffinity().)

L'option de démarrage isolcpus peut être utilisée pour isoler un ou plusieurs CPU au démarrage, de sorte qu'aucun processus ne soit planifié sur ces CPU. Suite à l'utilisation de cette option de démarrage, la seule façon de planifier des processus sur les CPU isolés est via sched_setaffinity() ou le mécanisme cpuset(7). Pour plus d'informations, voir le fichier source du noyau Documentation/admin-guide/kernel-parameters.txt. Comme noté dans ce fichier, isolcpus est le mécanisme préféré pour isoler les CPU (par rapport à l'alternative de définir manuellement l'affinité CPU de tous les processus sur le système).

Un enfant créé via fork(2) hérite du masque d'affinité CPU de son parent. Le masque d'affinité est préservé lors d'un execve(2).

Différences bibliothèque C/noyau

Ce manuel décrit l'interface glibc pour les appels d'affinité CPU. L'interface d'appel système réelle est légèrement différente, avec le type mask étant unsigned long *, reflétant le fait que l'implémentation sous-jacente des ensembles de CPU est un simple masque de bits.

En cas de succès, l'appel système brut sched_getaffinity() retourne le nombre d'octets copiés dans le tampon mask ; ce sera le minimum de cpusetsize et de la taille (en octets) du type de données cpumask_t qui est utilisé en interne par le noyau pour représenter le masque de bits de l'ensemble de CPU.

Gestion des systèmes avec de grands masques d'affinité CPU

Les appels système sous-jacents (qui représentent les masques CPU comme des masques de bits de type unsigned long *) n'imposent aucune restriction sur la taille du masque CPU. Cependant, le type de données cpu_set_t utilisé par glibc a une taille fixe de 128 octets, ce qui signifie que le numéro CPU maximum qui peut être représenté est 1023. Si le masque d'affinité CPU du noyau est supérieur à 1024, alors les appels de la forme :


sched_getaffinity(pid, sizeof(cpu_set_t), &mask);

échouent avec l'erreur EINVAL, l'erreur produite par l'appel système sous-jacent pour le c

ase où la taille du masque spécifiée dans cpusetsize est plus petite que la taille du masque d'affinité utilisé par le noyau. (Selon la topologie CPU du système, le masque d'affinité du noyau peut être sensiblement plus grand que le nombre de CPUs actifs dans le système.)

En travaillant sur des systèmes avec de grands masques d'affinité CPU du noyau, il faut allouer dynamiquement l'argument mask (voir CPU_ALLOC(3)). Actuellement, la seule façon de faire cela est de sonder la taille du masque requis en utilisant des appels sched_getaffinity() avec des tailles de masque croissantes (jusqu'à ce que l'appel n'échoue pas avec l'erreur EINVAL).

Soyez conscient que CPU_ALLOC(3) peut allouer un jeu de CPU légèrement plus grand que demandé (car les jeux de CPU sont implémentés sous forme de masques de bits alloués par unités de sizeof(long)). Par conséquent, sched_getaffinity() peut définir des bits au-delà de la taille d'allocation demandée, car le noyau voit quelques bits supplémentaires. Par conséquent, l'appelant doit itérer sur les bits de l'ensemble retourné, compter ceux qui sont définis, et s'arrêter en atteignant la valeur retournée par CPU_COUNT(3) (plutôt qu'en itérant sur le nombre de bits demandé à allouer).

EXEMPLES

Le programme ci-dessous crée un processus enfant. Le parent et l'enfant s'attribuent chacun à un CPU spécifié et exécutent des boucles identiques qui consomment du temps CPU. Avant de se terminer, le parent attend que l'enfant achève. Le programme prend trois arguments de ligne de commande : le numéro de CPU pour le parent, le numéro de CPU pour l'enfant, et le nombre d'itérations de boucle que les deux processus doivent effectuer.

Comme les exemples ci-dessous le démontrent, la quantité de temps réel et CPU consommée lors de l'exécution du programme dépendra des effets de cache intra-cœur et de l'utilisation du même CPU par les processus.

Nous utilisons d'abord lscpu(1) pour déterminer que ce système (x86) a deux cœurs, chacun avec deux CPUs :


$ lscpu | egrep -i 'core.*:|socket';
Thread(s) par core:    2
Core(s) par socket:    2
Socket(s):             1

Nous chronométrons ensuite l'exécution du programme exemple pour trois cas : les deux processus s'exécutant sur le même CPU ; les deux processus s'exécutant sur des CPUs différents du même cœur ; et les deux processus s'exécutant sur des CPUs différents de cœurs différents.


$ time -p ./a.out 0 0 100000000;
real 14.75
user 3.02
sys 11.73
$ time -p ./a.out 0 1 100000000;
real 11.52
user 3.98
sys 19.06
$ time -p ./a.out 0 3 100000000;
real 7.89
user 3.29
sys 12.07

Source du programme

#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           parentCPU, childCPU;
    cpu_set_t     set;
    unsigned int  nloops;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s parent-cpu child-cpu num-loops\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    parentCPU = atoi(argv[1]);
    childCPU = atoi(argv[2]);
    nloops = atoi(argv[3]);
    CPU_ZERO(&set);
    switch (fork()) {
    case -1:            /* Erreur */
        err(EXIT_FAILURE, "fork");
    case 0:             /* Enfant */
        CPU_SET(childCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        exit(EXIT_SUCCESS);
    default:            /* Parent */
        CPU_SET(parentCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        wait(NULL);     /* Attend que l'enfant se termine */
        exit(EXIT_SUCCESS);
    }
}
