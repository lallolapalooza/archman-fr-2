sched_setscheduler(2) Manuel des appels système sched_setscheduler(2)

NOM

sched_setscheduler, sched_getscheduler - définir et obtenir la politique/les paramètres de planification

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sched.h>
int sched_setscheduler(pid_t pid, int policy,
                       const struct sched_param *param);
int sched_getscheduler(pid_t pid);

DESCRIPTION

L'appel système sched_setscheduler() définit la politique de planification et les paramètres pour le thread dont l'identifiant est spécifié dans pid. Si pid est égal à zéro, la politique de planification et les paramètres du thread appelant seront définis.

Les paramètres de planification sont spécifiés dans l'argument param, qui est un pointeur vers une structure de la forme suivante :


struct sched_param {
    ...
    int sched_priority;
    ...
};

Dans l'implémentation actuelle, la structure ne contient qu'un seul champ, sched_priority. L'interprétation de param dépend de la politique sélectionnée.

Actuellement, Linux prend en charge les politiques de planification "normales" (c'est-à-dire non temps réel) suivantes comme valeurs pouvant être spécifiées dans policy :

SCHED_OTHER
la politique standard de partage de temps en round-robin ;
SCHED_BATCH
pour l'exécution des processus de style "batch" ; et
SCHED_IDLE
pour l'exécution de tâches de fond à très faible priorité.

Pour chacune des politiques ci-dessus, param->sched_priority doit être 0.

Diverses politiques "temps réel" sont également prises en charge, pour les applications critiques en temps qui nécessitent un contrôle précis sur la manière dont les threads exécutables sont sélectionnés pour l'exécution. Pour les règles régissant quand un processus peut utiliser ces politiques, voir sched(7). Les politiques temps réel pouvant être spécifiées dans policy sont :

SCHED_FIFO
une politique premier entré, premier sorti ; et
SCHED_RR
une politique round-robin.

Pour chacune des politiques ci-dessus, param->sched_priority spécifie une priorité de planification pour le thread. Il s'agit d'un nombre dans la plage retournée en appelant sched_get_priority_min(2) et sched_get_priority_max(2) avec la policy spécifiée. Sous Linux, ces appels système retournent respectivement 1 et 99.

Depuis Linux 2.6.32, le drapeau SCHED_RESET_ON_FORK peut être ORé dans policy lors de l'appel à sched_setscheduler(). En incluant ce drapeau, les enfants créés par fork(2) n'héritent pas des politiques de planification privilégiées. Voir sched(7) pour plus de détails.

sched_getscheduler() retourne la politique de planification actuelle du thread identifié par pid. Si pid est égal à zéro, la politique du thread appelant sera récupérée.

VALEUR DE RETOUR

En cas de succès, sched_setscheduler() retourne zéro. En cas de succès, sched_getscheduler() retourne la politique pour le thread (un entier non négatif). En cas d'erreur, les deux appels retournent -1 et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
Arguments invalides : pid est négatif ou param est NULL.
EINVAL
(sched_setscheduler()) policy n'est pas l'une des politiques reconnues.
EINVAL
(sched_setscheduler()) param n'a pas de sens pour la policy spécifiée.
EPERM
Le thread appelant n'a pas les privilèges appropriés.
ESRCH
Le thread dont l'identifiant est pid n'a pas pu être trouvé.

VERSIONS

POSIX.1 ne détaille pas les permissions qu'un thread non privilégié doit avoir pour appeler sched_setscheduler(), et les détails varient selon les systèmes. Par exemple, la page de manuel de Solaris 7 indique que l'ID utilisateur réel ou effectif de l'appelant doit correspondre à l'ID utilisateur réel ou à l'ID utilisateur enregistré du cible.

La politique de planification et les paramètres sont en fait des attributs par thread sous Linux. La valeur retournée par un appel à gettid(2) peut être passée dans l'argument pid. Spécifier pid comme 0 agira sur les attributs du thread appelant, et passer la valeur retournée par un appel à getpid(2) agira sur les attributs du thread principal du groupe de threads. (Si vous utilisez l'API POSIX threads, utilisez plutôt pthread_setschedparam(3), pthread_getschedparam(3) et pthread_setschedprio(3), au lieu des appels système sched_*(2).)

NORMES

POSIX.1-2024 (mais voir BUGS ci-dessous).

SCHED_BATCH et SCHED_IDLE sont spécifiques à Linux.

HISTORIQUE

POSIX.1-2001.

NOTES

Plus de détails sur la sémantique de toutes les politiques de planification "normales" et "temps réel" ci-dessus se trouvent dans la page de manuel sched(7). Cette page décrit également une politique supplémentaire, SCHED_DEADLINE, qui ne peut être définie qu'à l'aide de sched_setattr(2).

Les systèmes POSIX pour lesquels sched_setscheduler() et sched_getscheduler() sont disponibles définissent _POSIX_PRIORITY_SCHEDULING dans <unistd.h>.

BUGS

POSIX.1 stipule qu'en cas de succès, sched_setscheduler() devrait retourner la politique de planification précédente. Linux sched_setscheduler() n'est pas conforme à cette exigence, car il retourne toujours 0 en cas de succès.
