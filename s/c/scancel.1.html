scancel(1) Commandes Slurm scancel(1)

NOM

scancel - Utilisé pour signaler ou annuler des jobs sous le contrôle de Slurm.

SYNTAXE

scancel [OPTIONS...] [id_job[_id_tableau][.id_etape]] [id_job[_id_tableau][.id_etape]...]

DESCRIPTION

scancel est utilisé pour signaler ou annuler des jobs, des tableaux de jobs ou des étapes de jobs. Un nombre arbitraire de jobs ou d'étapes de jobs peuvent être signalés en utilisant des filtres de spécification de job ou une liste d'ID de jobs et/ou d'étapes de jobs séparés par des espaces. Si l'ID du job d'un tableau de jobs est spécifié avec une valeur d'ID de tableau et que le job associé à cette valeur d'ID de tableau a été séparé du tableau, alors seul cet élément du tableau de jobs sera annulé. Si l'ID du job d'un tableau de jobs est spécifié sans valeur d'ID de tableau ou si la valeur d'ID de tableau correspond à un job qui n'a pas été séparé du tableau, alors tous les éléments du tableau de jobs seront annulés. Pendant qu'un job hétérogène est dans un état PENDING, seul le job entier peut être annulé plutôt que ses composants individuels. Une demande d'annulation d'un composant individuel d'un job hétérogène lorsqu'il est dans un état PENDING retournera une erreur. Une fois que le job a commencé son exécution, un composant individuel peut être annulé, à l'exception du composant zéro. Si le composant zéro est annulé, tout le job hétérogène est annulé. Un job ou une étape de job ne peut être signalé que par son propriétaire ou par l'utilisateur root. Si une tentative est faite par un utilisateur non autorisé de signaler un job ou une étape de job, un message d'erreur sera affiché et le job ne sera pas signalé.

OPTIONS

-A, --account=compte
Restreint l'opération scancel aux jobs sous ce compte de facturation.
--admin-comment=commentaire
Définit le commentaire administrateur sur le job lors de l'annulation des jobs. L'utilisateur doit avoir les privilèges d'administrateur sur le système.
-b, --batch
Par défaut, les signaux autres que SIGKILL ne sont pas envoyés à l'étape batch (le script shell). Avec cette option, scancel ne signale que l'étape batch, mais aucune autre étape. Ceci est utile lorsque le script shell doit intercepter le signal et prendre une action définie par l'application. La plupart des shells ne peuvent pas gérer les signaux pendant qu'une commande est en cours d'exécution (c'est-à-dire qu'elle est un processus enfant de l'étape batch), le shell doit donc attendre que la commande se termine pour gérer le signal. Les enfants de l'étape batch ne sont pas signalés avec cette option. Si c'est ce que vous souhaitez, utilisez plutôt -f, --full. NOTE : Si utilisée avec -f, --full, cette option est ignorée. NOTE : Cette option n'est pas applicable si id_etape est spécifié. NOTE : Le shell lui-même peut se terminer à la réception de nombreux signaux. Vous pouvez l'éviter en capturant explicitement les signaux dans le script shell (par exemple, « trap <arg> <signaux> »). Voir la documentation du shell pour plus de détails.
-M, --clusters=<chaîne>
Cluster auquel adresser les commandes. Implique --ctld. Notez que le slurmdbd doit être en cours d'exécution pour que cette option fonctionne correctement, sauf si vous utilisez le mode fédéré avec FederationParameters=fed_display configuré.
--ctld
Si cette option n'est pas utilisée avec --interactive, --sibling, les ID de jobs fédérés, ou des ID d'étapes spécifiques, elle émet une seule requête au slurmctld pour signaler tous les jobs correspondant aux filtres spécifiés. Cela améliore grandement les performances de slurmctld et scancel. Sinon, cette option fait que scancel envoie chaque demande de signalisation de job au démon slurmctld plutôt qu' directement aux démons slurmd, ce qui augmente la surcharge, mais offre une meilleure tolérance aux pannes. --ctld est le comportement par défaut lorsque l'option --clusters est utilisée.
-c, --cron
Confirme la demande d'annulation d'un job soumis par scrontab. Cette option n'a d'effet que si l'option « explicit_scancel » est définie dans ScronParameters.
-f, --full
Par défaut, les signaux autres que SIGKILL ne sont pas envoyés à l'étape batch (le script shell). Avec cette option, scancel signale également le script batch et ses processus enfants. La plupart des shells ne peuvent pas gérer les signaux pendant qu'une commande est en cours d'exécution (c'est-à-dire qu'elle est un processus enfant de l'étape batch), le shell doit donc attendre que la commande se termine pour gérer le signal. Contrairement à -b, --batch, les enfants de l'étape batch sont également signalés avec cette option. NOTE : Les étapes srun sont également des enfants de l'étape batch, donc les étapes sont aussi signalées avec cette option.
--help
Affiche un message d'aide décrivant toutes les options de scancel.
-H, --hurry
Ne sort pas de données de buffer temporaire.
-i, --interactive
Mode interactif. Confirme chaque id_job.id_etape avant d'effectuer l'opération d'annulation.
-n, --jobname=nom_job, --name=nom_job
Restreint l'opération scancel aux jobs portant ce nom.
--me
Restreint l'opération scancel aux jobs appartenant à l'utilisateur actuel.
-w, --nodelist=hote1,hote2,...
Annule tous les jobs utilisant l'un des hôtes donnés. La liste peut être spécifiée comme une liste d'hôtes séparés par des virgules, une plage d'hôtes (host[1-5,7,...] par exemple), ou un nom de fichier. La liste d'hôtes sera supposée être un nom de fichier uniquement si elle contient un caractère « / ».
-p, --partition=nom_partition
Restreint l'opération scancel aux jobs dans cette partition.
-q, --qos=qos
Restreint l'opération scancel aux jobs ayant cette qualité de service.
-Q, --quiet
Ne signale pas d'erreur si le job spécifié est déjà terminé. Cette option est incompatible avec l'option --verbose.
-R, --reservation=nom_reservation
Restreint l'opération scancel aux jobs portant ce nom de réservation.
--sibling=nom_cluster
Supprime un job frère actif d'un job fédéré.
-s, --signal=nom_signal
Le nom ou le numéro du signal à envoyer. Si cette option n'est pas utilisée, le job ou l'étape spécifié sera terminé.
-t, --state=nom_etat_job
Restreint l'opération scancel aux jobs dans cet état. nom_etat_job peut avoir la valeur soit "PENDING", "RUNNING" ou "SUSPENDED".
-v, --verbose
Active le mode verbeux. Cela inclut l'affichage des informations sur les jobs quand ils sont signalés. Cette option est incompatible avec l'option -Q, --quiet.
-V, --version
Affiche les informations de version de scancel.
-z, --defunct
Supprime les jobs qui ont été terminés par le système et qui sont encore en attente dans la liste des jobs.

ÉTENDUE

Les jobs peuvent être spécifiés par ID de job, nom de job, nom d'utilisateur, partition, compte, qualité de service, réservation, état, liste de nœuds, ou un mélange de ces options. Si aucun job n'est spécifié, tous les jobs actifs du demandeur sont annulés.

Les jobs sont spécifiés en tant que liste de valeurs séparées par des espaces. Si un argument contient des espaces, il doit être entre guillemets.

Les IDs de jobs de tableaux sont de la forme <jobid>[_<array_id>][.<step_id>]. L'ID du tableau et l'ID de l'étape sont facultatifs.

Si aucun ID de job n'est spécifié, alors tous les jobs correspondant aux filtres spécifiés sont signalés. Ceci est applicable aux jobs possédés par l'utilisateur exécutant la commande, sauf si l'utilisateur est root ou administrateur Slurm. Dans ce cas, tous les jobs Slurm peuvent être signalés.

Les signaux sont envoyés aux jobs dans l'ordre spécifié dans la ligne de commande.

Les jobs qui sont dans un état PENDING sont mis en échec et ne sont jamais exécutés. Les jobs qui sont dans un état RUNNING sont signalés avec le signal spécifié ou SIGTERM par défaut.

Notez que les jobs en attente (PENDING) sont mis en échec immédiatement. Les jobs en cours d'exécution (RUNNING) reçoivent le signal spécifié. La plupart des signaux tueront le processus, sauf si le processus a mis en place un gestionnaire de signaux pour les intercepter. SIGKILL est le seul signal qui ne peut pas être intercepté.

Si aucun signal n'est spécifié, alors SIGTERM est utilisé.

Les options de filtrage spécifiées sont cumulatives.

Si l'option --ctld n'est pas utilisée, scancel envoie une requête de signalisation à chaque démon slurmd pour chaque job concerné. Cette approche peut être très inefficace et est déconseillée.

EXEMPLES

Annuler un job spécifique :

scancel 12345

Annuler toutes les étapes d'un job spécifique :

scancel 12345.12345

Annuler tous les jobs appartenant à l'utilisateur `user1` dans la partition `debug` :

scanel -p debug -t RUNNING --user=user1

Annuler un job et envoyer le signal HUP :

scancel -s HUP 12345

Annuler un job, mais demander confirmation :

scancel -i 12345

Annuler tous les jobs avec le nom `my_job_name` :

scancel --jobname=my_job_name

Annuler tous les jobs en attente :

scancel -t PENDING

Annuler un job et le commentaire administrateur :

scancel --admin-comment="Annulé pour maintenance" 12345

--usage
Affiche un bref message d'aide listant les options de scancel.
-u, --user=nom_utilisateur
Restreint l'opération scancel aux tâches appartenant à l'utilisateur donné.
-v, --verbose
Affiche des journaux supplémentaires. Plusieurs 'v' augmentent le niveau de détail des journaux. Cette option est incompatible avec l'option --quiet.

ARGUMENTS

id_tache
L'identifiant de la tâche Slurm à signaler.
id_etape
L'identifiant de l'étape de la tâche à signaler. Si non spécifié, l'opération est effectuée au niveau de la tâche.

Si ni --batch ni --signal ne sont utilisés, la tâche entière sera terminée.

Lorsque --batch est utilisé, les processus du shell de traitement par lots seront signalés. Les processus enfants du shell ne seront pas signalés par Slurm, mais le shell peut transmettre le signal.

Lorsque --batch n'est pas utilisé mais --signal l'est, toutes les étapes de la tâche seront signalées, mais le script de traitement par lots lui-même ne le sera pas.

PERFORMANCE

Lors de l'exécution de scancel sans l'option --ctld ; ou avec l'option --ctld et --interactive, --sibling, ou des identifiants d'étape spécifiques ; un appel de procédure distante est envoyé à slurmctld pour obtenir toutes les tâches. scancel envoie ensuite un appel de procédure distante de signalement de tâche pour chaque tâche correspondant aux filtres demandés.

Lors de l'exécution de scancel avec l'option --ctld et sans --interactive, --sibling, ou des identifiants d'étape spécifiques, un seul appel de procédure distante est envoyé à slurmctld pour signaler toutes les tâches correspondant aux filtres demandés. Il est donc recommandé d'utiliser l'option --ctld afin de réduire le nombre d'appels de procédure distante envoyés à slurmctld.

Si suffisamment d'appels provenant de scancel ou d'autres commandes clientes Slurm qui envoient des appels de procédure distante au démon slurmctld arrivent en même temps, cela peut entraîner une dégradation des performances du démon slurmctld, entraînant potentiellement un déni de service.

N'exécutez pas scancel ou d'autres commandes clientes Slurm qui envoient des appels de procédure distante à slurmctld depuis des boucles dans des scripts shell ou d'autres programmes. Assurez-vous que les programmes limitent les appels à scancel au minimum nécessaire pour les informations que vous essayez de collecter.

NOTES

Si plusieurs filtres sont fournis (par exemple, --partition et --name), seules les tâches satisfaisant toutes les options de filtrage seront signalées.

L'annulation d'une étape de tâche n'entraînera pas la terminaison de la tâche. La tâche doit être annulée pour libérer une allocation de ressources.

Pour annuler une tâche, invoquez scancel sans l'option --signal. Cela enverra d'abord un SIGCONT à toutes les étapes pour les réveiller ensuite un SIGTERM, puis attendra la durée KillWait définie dans le fichier slurm.conf et enfin, si elles ne se sont pas terminées, enverra un SIGKILL. Cela laisse le temps aux tâches/étapes en cours de se nettoyer.

Si une valeur de signal "KILL" est envoyée à une tâche entière, cela annulera les étapes de tâche actives mais n'annulera pas la tâche elle-même.

AUTORISATION

Lors de l'utilisation de SlurmDBD, les utilisateurs ayant un AdminLevel défini (Opérateur ou Admin) et les utilisateurs qui sont coordinateurs de compte ont l'autorité d'invoquer scancel sur les tâches d'autres utilisateurs.

EXEMPLES

Envoyer SIGTERM aux étapes 1 et 3 de la tâche 1234 :
$ scancel --signal=TERM 1234.1 1234.3
Annuler la tâche 1234 ainsi que toutes ses étapes :
$ scancel 1234
Envoyer SIGKILL à toutes les étapes de la tâche 1235, mais sans annuler la tâche elle-même :
$ scancel --signal=KILL 1235
Envoyer SIGUSR1 aux processus du shell de traitement par lots de la tâche 1236 :
$ scancel --signal=USR1 --batch 1236
Annuler toutes les tâches en attente appartenant à l'utilisateur "bob" dans la partition "debug" :
$ scancel --state=PENDING --user=bob --partition=debug
Annuler uniquement l'ID de tableau 4 du tableau de tâches 1237
$ scancel 1237_4

NAME

scancel — send a signal to Slurm jobs or job steps

SYNOPSIS

scancel [OPTION]... job_id[.step_id]...

DESCRIPTION

The scancel command is used to send a signal to Slurm jobs or job steps. By default, the SIGTERM signal is sent to the specified jobs or job steps. Signals can be specified using the -s option.

A list of jobs or job steps may be specified on the command line. If a job id is specified, the signal will be sent to all steps within that job unless a specific step id is also supplied.

A job id can be specified as a single integer value. A job step id is specified as a job id followed by a period and then the step id (e.g. 1234.5).

For a full list of options, please refer to the scancel man page.

OPTIONS

The following options are available:

-s signal
Specifies the signal to be sent to the job or job step. The signal name may be specified with or without the SIG prefix. If not specified, then SIGTERM will be sent.
-n job_name
Cancel all jobs with the specified job name. This option can be used to cancel multiple jobs with a single command.
-u user_name
Cancel all jobs owned by the specified user.
-t state
Cancel jobs in the specified state. Valid states include PENDING, RUNNING, SUSPENDED, COMPLETING, CONFIGURING, STOPPED, SUSPENDED. Note that this option cancels jobs with the specified state, not jobs that are transitioning to that state.
-h, --help
Print a help message and exit.
-V, --version
Print version information and exit.

ARGUMENTS

The following arguments are available:

job_id[.step_id]
One or more job or job step identifiers. A job identifier is an integer. A job step identifier is a job identifier followed by a period and then the step identifier (e.g., 1234.5).

PERFORMANCE

The scancel command communicates with the Slurm controller daemon (slurmctld) to perform its actions. The performance impact is minimal as it involves a simple request to the daemon.

ENVIRONMENT VARIABLES

A number of Slurm environment variables can affect the execution of scancel. Please refer to the slurm(5) man page for details.

NOTES

Signals sent to jobs/job steps are processed by slurmctld. The signal is then forwarded to the appropriate processing node(s) for execution.

The user must have appropriate permissions to cancel jobs/job steps. Typically, this means the user must own the job/job step or be a Slurm administrator.

AUTHORIZATION

Users can cancel their own jobs. Administrators can cancel any job.

EXAMPLES

To cancel job 1234:

scancel 1234

To cancel job step 5 of job 1234:

scancel 1234.5

To send the SIGKILL signal to job 1234:

scancel -s SIGKILL 1234

To cancel all jobs owned by user 'testuser':

scancel -u testuser

To cancel all PENDING jobs:

scancel -t PENDING
