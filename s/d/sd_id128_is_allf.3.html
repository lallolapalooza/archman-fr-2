DESCRIPTION

sd-id128.h fait partie de libsystemd(3) et fournit des APIs pour générer, convertir et comparer des identifiants de 128 bits. Les identifiants de 128 bits traités et générés par ces APIs sont une généralisation des UUID OSF tels que définis par la RFC 4122[1] mais utilisent un format de chaîne plus simple. Ces fonctions n'imposent aucune structure aux identifiants utilisés, contrairement aux UUID OSF ou GUID Microsoft, mais sont largement compatibles avec ces types d'identifiants.

Un identifiant de 128 bits est implémenté comme le type union suivant :

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Ce type union permet d'accéder à l'identifiant de 128 bits comme 16 octets séparés ou deux mots de 64 bits. Il est généralement plus sûr d'accéder aux composants de l'identifiant par leur tableau de 8 bits pour éviter les problèmes d'endianness. Cette union est destinée à être passée par valeur (par opposition à la passe par référence) et peut être manipulée directement par les clients.

Quelques macros sont définies pour indiquer et décoder les identifiants de 128 bits :

SD_ID128_MAKE() est utilisé pour écrire un identifiant constant dans le code source. Une expression couramment utilisée consiste à attribuer un nom à un identifiant à l'aide de cette macro :

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL définit un identifiant composé uniquement d'octets NUL (c'est-à-dire tous les bits désactivés).

SD_ID128_ALLF définit un identifiant composé uniquement d'octets 0xFF (c'est-à-dire tous les bits activés).

SD_ID128_MAKE_STR() est similaire à SD_ID128_MAKE(), mais crée une expression const char* qui peut être utilisée de manière pratique dans des formats de message et similaires :

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convertit les identifiants constants en chaînes de caractères constantes pour la sortie. L'exemple de code suivant affichera la chaîne "fc2e22bc6ee647b6b90729ab34a250b1" :

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR et SD_ID128_FORMAT_VAL() sont utilisés pour formater un identifiant dans une chaîne de format printf(3), comme montré dans l'exemple suivant :

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR et SD_ID128_MAKE_UUID_STR() sont similaires à SD_ID128_FORMAT_STR et SD_ID128_MAKE_STR(), mais incluent des tirets séparateurs pour se conformer à la "représentation canonique des UUID[2]". Ils formatent la chaîne en fonction des règles de la variante 1 de la RFC4122[1], c'est-à-dire en convertissant à partir de l'ordre des octets Big Endian. Cela correspond au comportement de la plupart des autres infrastructures de l'espace utilisateur Linux. Il est probablement préférable d'éviter les UUID d'autres variantes afin d'éviter des ambiguïtés inutiles. Tous les identifiants de 128 bits générés par les APIs sd-id128 sont strictement conformes aux UUID de variante 1 version 4, conformément à la RFC 4122.

sd_id128_equal() compare deux identifiants de 128 bits :

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() est similaire à sd_id128_equal(), mais le premier identifiant est formaté comme const char*. Les mêmes restrictions s'appliquent qu'au premier argument de sd_id128_from_string().

sd_id128_is_null() vérifie si un identifiant est composé uniquement d'octets NUL :

assert(sd_id128_is_null(SD_ID128_NULL));

De même, sd_id128_is_allf() vérifie si un identifiant est composé uniquement d'octets 0xFF (tous les bits activés) :

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() prend une liste d'identifiants et retourne vrai si le premier argument est égal à l'un des arguments suivants. La liste d'arguments est terminée par un SD_ID128_NULL sentinelle, qui doit être présent.

sd_id128_in_set() est une fonction pratique qui prend une liste d'identifiants et retourne vrai si le premier argument est égal à l'un des arguments suivants :

int main(int argc, char *argv[]) {
  sd_id128_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() est défini comme une macro sur sd_id128_in_set_sentinel(), ajoutant automatiquement le sentinelle SD_ID128_NULL. Étant donné que sd_id128_in_set_sentinel() utilise SD_ID128_NULL comme sentinelle, SD_ID128_NULL ne peut pas être autrement placé dans la liste d'arguments.

sd_id128_in_setv() est similaire à sd_id128_in_set_sentinel(), mais prend un argument struct varargs.

De nouveaux identifiants aléatoires peuvent être générés avec la commande new de systemd-id128(1).

sd_id128_is_allf(3) — systemd — Arch Linux

NAME

sd_id128_is_allf, sd_id128_is_null, sd_id128_equal, sd_id128_string_equal, sd_id128_in_setv, sd_id128_in_set_sentinel, sd_id128_in_set - Vérifier si un ID 128 bits est nul, identique, dans un ensemble ou si tous les bits sont à 'f'.

SYNOPSIS

#include <systemd/sd-id128.h>

int
sd_id128_is_allf(const sd_id128_t id);
int
sd_id128_is_null(const sd_id128_t id);
int
sd_id128_equal(const sd_id128_t id1, const sd_id128_t id2);
int
sd_id128_string_equal(const sd_id128_t id1, const char *str);
int
sd_id128_in_setv(const sd_id128_t id, sd_id128_t *const arr[]);
int
sd_id128_in_set_sentinel(const sd_id128_t id, sd_id128_t *const arr[]);
int
sd_id128_in_set(const sd_id128_t id, sd_id128_t *const arr[]);

DESCRIPTION

Ces fonctions permettent de comparer des identifiants uniques 128 bits (UUID ou GUID).

L'identifiant 128 bits est représenté par la structure `sd_id128_t`. Cette structure contient 16 octets.

sd_id128_is_allf() vérifie si tous les 16 octets de l'ID sont définis à la valeur hexadécimale 'f'. Elle renvoie 1 si c'est le cas, et 0 sinon.

sd_id128_is_null() vérifie si l'ID est l'identifiant nul (tous les octets sont à zéro). Elle renvoie 1 si c'est le cas, et 0 sinon.

sd_id128_equal() compare deux IDs `id1` et `id2`. Elle renvoie 1 si les deux IDs sont identiques, et 0 sinon.

sd_id128_string_equal() compare un ID `id1` avec une chaîne de caractères `str` représentant un ID au format canonique (par exemple, "123e4567-e89b-12d3-a456-426614174000"). Elle renvoie 1 si la chaîne de caractères représente le même ID que `id1`, et 0 sinon. La chaîne doit être au format canonique hexadécimal, avec ou sans traits d'union. Si la chaîne est mal formée, la fonction renvoie 0.

sd_id128_in_setv() vérifie si l'ID `id` est présent dans un tableau d'IDs `arr`. Le tableau doit être terminé par un pointeur NULL. Elle renvoie 1 si l'ID est trouvé, et 0 sinon.

sd_id128_in_set_sentinel() est identique à sd_id128_in_setv(), mais le tableau doit être terminé par un ID nul (un ID dont tous les octets sont à zéro). Notez que l'ID nul lui-même n'est pas considéré comme une valeur de fin si le tableau ne contient pas explicitement un pointeur NULL.

sd_id128_in_set() est identique à sd_id128_in_set_sentinel().

Toutes ces fonctions renvoient des valeurs positives (1) en cas de succès, et des valeurs négatives en cas d'erreur. Les erreurs possibles incluent la réception de pointeurs NULL là où des données valides sont attendues (pour les fonctions qui prennent des pointeurs en argument).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a encore été démarré.
