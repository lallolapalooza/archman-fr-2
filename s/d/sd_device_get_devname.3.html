SD_DEVICE_GET_SYSPATH(3) sd_device_get_syspath SD_DEVICE_GET_SYSPATH(3)

NOM

sd_device_get_syspath, sd_device_get_devpath, sd_device_get_sysname, sd_device_get_sysnum, sd_device_get_subsystem, sd_device_get_driver_subsystem, sd_device_get_devtype, sd_device_get_devname, sd_device_get_devnum, sd_device_get_ifindex, sd_device_get_driver, sd_device_get_diskseq, sd_device_get_device_id - Retourne divers champs des objets de périphérique

SYNOPSIS

#include <systemd/sd-device.h>

int sd_device_get_syspath(sd_device *device, const char **ret);

int sd_device_get_devpath(sd_device *device, const char **ret);

int sd_device_get_sysname(sd_device *device, const char **ret);

int sd_device_get_sysnum(sd_device *device, const char **ret);

int sd_device_get_subsystem(sd_device *device, const char **ret);

int sd_device_get_driver_subsystem(sd_device *device, const char **ret);

int sd_device_get_devtype(sd_device *device, const char **ret);

int sd_device_get_devname(sd_device *device, const char **ret);

int sd_device_get_devnum(sd_device *device, dev_t *ret);

int sd_device_get_ifindex(sd_device *device, int *ret);

int sd_device_get_driver(sd_device *device, const char **ret);

int sd_device_get_diskseq(sd_device *device, uint64_t *ret);

int sd_device_get_device_id(sd_device *device, const char **ret);

DESCRIPTION

sd_device_get_syspath() retourne le chemin sysfs de l'enregistrement de périphérique spécifié, y compris le préfixe /sys. Exemple : /sys/devices/virtual/tty/tty7

sd_device_get_devpath() retourne le chemin sysfs de l'enregistrement de périphérique spécifié, sans le préfixe /sys. Exemple : /devices/virtual/tty/tty7

sd_device_get_sysname() retourne le nom sysfs de l'enregistrement de périphérique spécifié, c'est-à-dire le dernier composant du chemin sysfs. Exemple : "tty7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_sysnum() retourne le numéro de périphérique sysfs de l'enregistrement de périphérique spécifié, c'est-à-dire le suffixe numérique du dernier composant du chemin sysfs. Exemple : "7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_subsystem() retourne le sous-système du noyau de l'enregistrement de périphérique spécifié. Il s'agit d'une chaîne courte qui peut être utilisée comme nom de fichier, et qui ne contient donc pas de barre oblique et ne peut pas être vide. Exemple : "tty", "block" ou "net".

sd_device_get_driver_subsystem() retourne le type de bus connecté des périphériques chargés par l'enregistrement de pilote spécifié. Par exemple, lorsque l'enregistrement de pilote "iwlwifi" est spécifié, qui est utilisé par les interfaces réseau sans fil connectées au bus PCI, cette fonction retourne "pci". Cette fonction ne réussit que lorsque sd_device_get_subsystem() retourne "drivers". Exemple : "pci", "i2c", ou "hid".

sd_device_get_devtype() retourne le type de périphérique de l'enregistrement de périphérique spécifié, si le sous-système gère plusieurs types de périphériques. Exemple : pour les périphériques du sous-système "block", cela peut être "disk" ou "partition"

sd_device_get_devname() retourne le chemin du nœud de périphérique de l'enregistrement de périphérique spécifié si le périphérique a un nœud de périphérique. Exemple : pour /sys/devices/virtual/tty/tty7, la chaîne /dev/tty7 est généralement retournée.

sd_device_get_devnum() retourne le majeur/mineur du nœud de périphérique (c'est-à-dire dev_t) de l'enregistrement de périphérique spécifié si le périphérique a un nœud de périphérique (c'est-à-dire celui retourné par sd_device_get_devname()). Pour les périphériques appartenant au sous-système "block", cela fait référence à un nœud de périphérique de bloc, dans tous les autres cas à un nœud de périphérique de caractère. Exemple : pour le périphérique /sys/devices/virtual/tty/tty7, cela retourne généralement le numéro de périphérique avec majeur/mineur "4:7".

sd_device_get_ifindex() retourne l'index de l'interface réseau de l'enregistrement de périphérique spécifié, si le périphérique encapsule un périphérique d'interface réseau, c'est-à-dire appartient au sous-système "net". Exemple : l'interface "lo" a généralement l'index d'interface 1.

sd_device_get_driver() retourne le nom du pilote du noyau attaché au périphérique. Notez que le champ pilote est défini sur les périphériques consommés par le pilote, pas sur le périphérique créé par celui-ci. Exemple : un périphérique PCI /sys/bus/pci/devices/0000:00:1f.6 peut être attaché à un pilote "e1000e".

sd_device_get_diskseq() retourne le numéro de séquence de disque du noyau du périphérique de bloc. Ce numéro augmente de manière monotone chaque fois que le support sous-jacent d'un périphérique de bloc change sans que le nom du périphérique ne change, et est pertinent pour les périphériques de bloc encapsulant des périphériques avec des médias changeants (par exemple, disquette ou lecteur CD-ROM), ou des périphériques de bloc en boucle. Uniquement défini pour les périphériques de bloc, c'est-à-dire ceux du sous-système "block".

sd_device_get_device_id() retourne la chaîne courte qui identifie l'enregistrement de périphérique. Lorsque l'ID de périphérique obtenu par la fonction pour un enregistrement de périphérique spécifié est passé à sd_device_new_from_device_id(), une nouvelle instance du même enregistrement de périphérique sera obtenue. Lorsqu'un périphérique de bloc ou de caractère est spécifié, qui a un nœud de périphérique correspondant, cela retourne "b" ou "c", respectivement, suivi des numéros majeur et mineur du nœud de périphérique séparés par un deux-points. Exemple : "b259:1" ou "c10:121". Lorsqu'un périphérique réseau est spécifié, cela retourne "n" suivi de l'index de l'interface, qui peut être obtenu par sd_device_get_ifindex(). Exemple : "n1". Lorsqu'un périphérique dans le sous-système "driver" est spécifié, cela retourne "+drivers:" suivi de son sous-système de pilote et de son nom sysfs séparés par un deux-points. Exemple : "+drivers:pci:iwlwifi" pour un enregistrement de pilote dont le sous-système de pilote est "pci" et le nom sysfs est "iwlwifi". Lorsqu'un autre type de périphérique est spécifié, cette fonction retourne "+" suivi de son sous-système et de son nom sysfs séparés par un deux-points. Exemple : "+acpi:ACPI0003:00", "+input:input16", ou "+pci:0000:00:1f.6".

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

Ajouté dans la version 251.

-ENOENT

Le champ demandé n'est pas présent dans l'enregistrement de périphérique.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

sd_device_get_devname(3) — systemd 258.2

NAME

sd_device_get_devname, sd_device_get_driver, sd_device_get_subsystem, sd_device_get_device_id - Obtenir le nom, le pilote, le sous-système ou l'identifiant de périphérique d'un appareil

SYNOPSIS

#include <systemd/sd-device.h>

int sd_device_get_devname(sd_device *device, const char **devname);
int sd_device_get_driver(sd_device *device, const char **driver);
int sd_device_get_subsystem(sd_device *device, const char **subsystem);
int sd_device_get_device_id(sd_device *device, const char **device_id);

DESCRIPTION

La fonction sd_device_get_devname() renvoie le nom de périphérique principal associé à l'objet appareil device. Ce nom est souvent utilisé dans les chemins de périphériques dans /dev/, mais ce n'est pas garanti. Le pointeur renvoyé est valide jusqu'à la prochaine opération sur le même objet appareil.

La fonction sd_device_get_driver() renvoie le nom du pilote du noyau associé à l'objet appareil device, si un tel pilote existe. Le pointeur renvoyé est valide jusqu'à la prochaine opération sur le même objet appareil.

La fonction sd_device_get_subsystem() renvoie le nom du sous-système (par exemple, "usb", "pci", "block") auquel l'objet appareil device appartient. Le pointeur renvoyé est valide jusqu'à la prochaine opération sur le même objet appareil.

La fonction sd_device_get_device_id() renvoie l'identifiant unique du périphérique associé à l'objet appareil device. Cet identifiant est généralement une chaîne de caractères unique pour le périphérique spécifique, et il est garanti qu'il est unique sur le système. Le pointeur renvoyé est valide jusqu'à la prochaine opération sur le même objet appareil.

RETURN VALUE

En cas de succès, ces fonctions renvoient 0. Si un pointeur d'erreur est transmis, les erreurs seront renvoyées à travers celui-ci. En cas d'échec, elles renvoient une erreur négative.

Le nom, le pilote, le sous-système ou l'identifiant de périphérique renvoyé par le biais de devname, driver, subsystem ou device_id est une référence vers des données internes et ne doit pas être modifié ou libéré.

NOTES

Ces fonctions font partie de la bibliothèque libsystemd, qui est une liaison dynamique implémentée par systemd. Pour des informations sur la compilation de programmes pkg-config(1), voir sd-device(3).

Le nom de périphérique renvoyé par sd_device_get_devname() peut ne pas être un nom de périphérique valide dans /dev/. Pour obtenir le nom de périphérique le plus sûr, il est recommandé d'utiliser sd_device_get_path.

HISTORY

sd_device_get_driver_subsystem() et sd_device_get_device_id() ont été ajoutées dans la version 257.
