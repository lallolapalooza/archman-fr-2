SD_EVENT_NEW(3) sd_event_new SD_EVENT_NEW(3)

NOM

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - Acquérir et libérer un objet de boucle d'événements

SYNOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

DESCRIPTION

sd_event_new() alloue un nouvel objet de boucle d'événements. L'objet de boucle d'événements est retourné dans le paramètre event. Après utilisation, libérez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est libérée, l'objet est détruit.

sd_event_default() acquiert une référence à l'objet de boucle d'événements par défaut du thread appelant, allouant potentiellement un nouvel objet si aucun objet de boucle d'événements par défaut n'a encore été alloué pour le thread. Après utilisation, libérez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est libérée, la boucle d'événements est détruite. Si cette fonction est appelée alors que l'objet retourné par un appel précédent du même thread est toujours référencé, le même objet est retourné à nouveau, mais la référence est incrémentée de un. Il est recommandé d'utiliser cet appel plutôt que sd_event_new() afin de partager les objets de boucle d'événements entre divers composants qui sont dépêchés dans le même thread. Tous les threads ont exactement zéro ou un objet de boucle d'événements par défaut associés, mais jamais plus.

Après avoir alloué un objet de boucle d'événements, ajoutez-lui des sources d'événements avec sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3), sd_event_add_post(3) ou sd_event_add_exit(3), puis exécutez la boucle d'événements en utilisant sd_event_loop(3).

sd_event_ref() incrémente le compteur de références de l'objet de boucle d'événements spécifié de un.

sd_event_unref() décrémente le compteur de références de l'objet de boucle d'événements spécifié de un. Si le compteur atteint zéro, l'objet est détruit. Notez qu'il est détruit qu'il soit l'objet de boucle d'événements par défaut pour un thread ou non. Cela signifie que l'allocation d'une boucle d'événements avec sd_event_default(), puis sa libération, et ensuite l'acquisition d'une nouvelle avec sd_event_default() entraînera deux objets distincts. Notez que, afin de détruire un objet de boucle d'événements, toutes les sources d'événements restantes de la boucle d'événements doivent également être libérées car chacune conserve une référence à celle-ci.

sd_event_unrefp() est similaire à sd_event_unref() mais prend un pointeur vers un pointeur vers un objet sd_event. Cet appel est utile en conjonction avec l'attribut de variable de nettoyage Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme la suivante, afin d'allouer un objet de boucle d'événements qui sera automatiquement détruit à la sortie du bloc de code :

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Échec de l'allocation de la boucle d'événements : %m\n");
        }
        ...
}

sd_event_ref(), sd_event_unref() et sd_event_unrefp() n'effectuent aucune opération si l'objet de boucle d'événements passé est NULL.

sd_event_get_tid() récupère l'identifiant du thread ("TID") du thread auquel l'objet de boucle d'événements spécifié est associé. Cet appel n'est pris en charge que pour les boucles d'événements allouées avec sd_event_default(), et retourne l'identifiant du thread dont la boucle d'événements est la boucle d'événements par défaut. Voir gettid(2) pour plus d'informations sur les identifiants de thread.

VALEUR DE RETOUR

En cas de succès, sd_event_new(), sd_event_default() et sd_event_get_tid() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de type errno. sd_event_ref() retourne toujours un pointeur vers l'objet de boucle d'événements passé en argument. sd_event_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer l'objet.

-EMFILE

Le nombre maximum de boucles d'événements a été alloué.

-ENXIO

sd_event_get_tid() a été appelé sur un objet de boucle d'événements qui n'a pas été alloué avec sd_event_default().

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a encore été démarré.

HISTORIQUE

sd_event_new(), sd_event_default(), sd_event_ref(), et sd_event_unref() ont été ajoutés dans la version 213.

sd_event_unrefp() et sd_event_get_tid() ont été ajoutés dans la version 229.

sd_event_unrefp(3)

NAME

sd_event_unrefp - Release a reference to an event loop

SYNOPSIS


#include <systemd/sd-event.h>

int sd_event_unrefp(sd_event **event_p);

DESCRIPTION

The sd_event_unrefp() function decreases the reference count of the event loop object passed in the memory location pointed to by event_p. When the reference count drops to zero, the event loop is destroyed.

This is a convenient wrapper around sd_event_unref(sd_event_ref(*event_p)), but it also takes care of setting the pointer to NULL on success.

This function is useful for releasing references to event loops obtained from other functions, such as sd_event_new(3) or sd_event_get_child_event_loop(3).

ARGUMENTS

event_p: A pointer to a pointer to an sd_event object. This pointer will be set to NULL on success.

RETURN VALUE

On success, 0 is returned. On failure, a negative errno value is returned.

NOTES

The reference count is increased automatically by functions that return an sd_event object, such as sd_event_new(3) or sd_event_get_child_event_loop(3). You must call sd_event_unref(3) or sd_event_unrefp() to decrease the reference count when you are finished with the event loop object.

If *event_p is NULL, this function does nothing and returns 0.

HISTORY

The sd_event_unrefp() function was introduced in version 239.

SEE ALSO

sd_event_new(3), sd_event_ref(3), sd_event_unref(3), sd_event_get_child_event_loop(3)

sd_event_unrefp(3)

NOM

sd_event_unrefp - Libérer une référence à une boucle d'événements

SYNTAXE


#include <systemd/sd-event.h>

int sd_event_unrefp(sd_event **event_p);

DESCRIPTION

La fonction sd_event_unrefp() diminue le compteur de références de l'objet de boucle d'événements passé dans l'emplacement mémoire pointé par event_p. Lorsque le compteur de références tombe à zéro, la boucle d'événements est détruite.

C'est un wrapper pratique autour de sd_event_unref(sd_event_ref(*event_p)), mais il prend également en charge la mise à NULL du pointeur en cas de succès.

Cette fonction est utile pour libérer les références aux boucles d'événements obtenues à partir d'autres fonctions, telles que sd_event_new(3) ou sd_event_get_child_event_loop(3).

ARGUMENTS

event_p: Un pointeur vers un pointeur vers un objet sd_event. Ce pointeur sera mis à NULL en cas de succès.

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé. En cas d'échec, une valeur errno négative est renvoyée.

NOTES

Le compteur de références est automatiquement augmenté par les fonctions qui renvoient un objet sd_event, telles que sd_event_new(3) ou sd_event_get_child_event_loop(3). Vous devez appeler sd_event_unref(3) ou sd_event_unrefp() pour diminuer le compteur de références lorsque vous avez terminé avec l'objet de boucle d'événements.

Si *event_p est NULL, cette fonction ne fait rien et renvoie 0.

HISTORIQUE

La fonction sd_event_unrefp() a été introduite dans la version 239.

VOIR AUSSI

sd_event_new(3), sd_event_ref(3), sd_event_unref(3), sd_event_get_child_event_loop(3)
