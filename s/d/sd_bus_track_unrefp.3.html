NOM

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_track_handler_t)(sd_bus_track *track, void *userdata);

int sd_bus_track_new(sd_bus* bus, sd_bus_track** ret, sd_bus_track_handler_t handler, void* userdata);

sd_bus_track *sd_bus_track_ref(sd_bus_track *t);

sd_bus_track *sd_bus_track_unref(sd_bus_track *t);

void sd_bus_track_unrefp(sd_bus_track **t);

int sd_bus_track_get_recursive(sd_bus_track *t);

int sd_bus_track_set_recursive(sd_bus_track *t, int b);

sd_bus* sd_bus_track_get_bus(sd_bus_track *t);

void* sd_bus_track_get_userdata(sd_bus_track *t);

void* sd_bus_track_set_userdata(sd_bus_track *t, void *userdata);

DESCRIPTION

sd_bus_track_new() crée un nouvel objet de suivi de pairs du bus. L'objet est alloué pour le bus spécifié et renvoyé dans le paramètre *ret. Après utilisation, l'objet doit être libéré en supprimant la référence acquise avec sd_bus_track_unref() (voir ci-dessous). Un objet de suivi de pairs du bus peut être utilisé pour suivre les pairs sur un bus IPC spécifique, dans les cas où les pairs utilisent un ou plusieurs objets locaux, afin de contrôler le cycle de vie des objets locaux et de s'assurer qu'ils restent actifs tant que les pairs qui en ont besoin sont présents, et qu'ils sont désactivés (et potentiellement détruits) dès que tous les pairs pertinents ont disparu. Chaque objet de suivi de pairs du bus peut être utilisé pour suivre zéro, un ou plusieurs pairs à un moment donné. Les références aux pairs du bus sont ajoutées via sd_bus_track_add_name(3) ou sd_bus_track_add_sender(). Elles peuvent être retirées via sd_bus_track_remove_name() et sd_bus_track_remove_sender(). Alternativement, les références aux pairs sont retirées automatiquement lorsqu'ils se déconnectent du bus. Si handler n'est pas NULL, il peut spécifier une fonction qui sera appelée chaque fois que la dernière référence sera supprimée, que la référence soit supprimée explicitement via sd_bus_track_remove_name() ou implicitement parce que le pair s'est déconnecté du bus. Le dernier argument userdata peut être utilisé pour attacher un pointeur de données utilisateur générique à l'objet. Ce pointeur est passé au rappel du gestionnaire lorsqu'il est appelé.

sd_bus_track_ref() crée une nouvelle référence à un objet de suivi de pairs du bus. Cet objet ne sera pas détruit tant que sd_bus_track_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, l'objet spécifié ne peut plus être utilisé, les appels ultérieurs à sd_bus_track_ref() ou sd_bus_track_unref() sur le même objet sont illégaux.

sd_bus_track_unref() détruit une référence à un objet de suivi de pairs du bus.

sd_bus_track_unrefp() est similaire à sd_bus_track_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_track. Cet appel est utile en conjonction avec l'attribut de variable Clean-up[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction en ligne.

sd_bus_track_ref(), sd_bus_track_unref() et sd_bus_track_unrefp() n'effectuent aucune opération si l'objet de suivi de pairs du bus passé est NULL.

Les objets de suivi de pairs du bus peuvent exister dans deux modes : par défaut, ils fonctionnent en mode non récursif, mais peuvent éventuellement être basculés en mode récursif. En mode non récursif par défaut, un pair est soit suivi, soit non suivi. Dans ce mode, appeler sd_bus_track_add_name() plusieurs fois de suite pour le même pair est entièrement équivalent à l'appeler une seule fois, car l'appel ajoute le pair à l'ensemble des pairs suivis si nécessaire, et n'effectue aucune opération si le pair est déjà suivi. Un appel unique à sd_bus_track_remove_name() retire à nouveau la référence sur le pair, quel que soit le nombre de fois où sd_bus_track_add_name() a été appelé auparavant. En mode récursif, le nombre de fois où sd_bus_track_add_name() est appelé pour le même nom de pair est compté et sd_bus_track_remove_name() doit être appelé le même nombre de fois avant que le pair ne soit plus suivi, à l'exception du cas où le pair suivi disparaît du bus, auquel cas le compte est sans importance et le suivi du pair spécifique est immédiatement supprimé. sd_bus_track_get_recursive() peut être utilisé pour déterminer si l'objet de suivi de pairs du bus fonctionne en mode récursif. sd_bus_track_set_recursive() peut être utilisé pour activer ou désactiver le mode récursif. Par défaut, un objet de suivi de pairs du bus fonctionne en mode non récursif, et sd_bus_track_get_recursive() pour un objet nouvellement alloué renvoie donc une valeur égale à zéro. Utilisez sd_bus_track_set_recursive() pour activer le mode récursif, juste après l'allocation. Il prend un argument booléen pour activer ou désactiver le mode récursif. Notez que les objets de suivi pour lesquels sd_bus_track_add_name() a déjà été appelé au moins une fois (et qui suivent donc déjà un ou plusieurs pairs) ne peuvent plus être basculés du mode récursif au mode non récursif.

sd_bus_track_get_bus() renvoie l'objet bus auquel l'objet de suivi de pairs du bus appartient. Il renvoie l'objet bus passé initialement à sd_bus_track_new() lors de l'allocation de l'objet.

sd_bus_track_get_userdata() renvoie le pointeur de données utilisateur générique défini sur l'objet de suivi de pairs du bus lors de sa création via sd_bus_track_new() ou ultérieurement, via sd_bus_track_set_userdata().

VALEUR DE RETOUR

En cas de succès, sd_bus_track_new() et sd_bus_track_set_recursive() renvoient 0 ou un entier positif. En cas d'échec, ils renvoient un code d'erreur négatif de type errno.

sd_bus_track_ref() renvoie toujours l'argument.

sd_bus_track_unref() renvoie toujours NULL.

sd_bus_track_get_recursive() renvoie 0 si le mode non récursif est sélectionné (par défaut), et une valeur supérieure à 0 si le mode récursif est sélectionné. En cas d'échec, un code d'erreur négatif de type errno est renvoyé.

sd_bus_track_get_bus() renvoie l'objet bus associé à l'objet de suivi de pairs du bus.

sd_bus_track_get_userdata() renvoie le pointeur de données utilisateur générique associé à l'objet de suivi de pairs du bus. sd_bus_track_set_userdata() renvoie le pointeur de données utilisateur précédemment défini.

PROPRIÉTÉ DES RÉFÉRENCES

La fonction sd_bus_track_new() crée un nouvel objet et l'appelant possède la seule référence. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_track_unref().

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EBUSY

Des pairs du bus ont déjà été ajoutés à l'objet de suivi de pairs du bus et sd_bus_track_set_recursive() a été appelé pour modifier le mode de suivi.

-EINVAL

Le paramètre spécifié est invalide (NULL dans le cas des paramètres de sortie).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre fil d'exécution n'a été démarré.
