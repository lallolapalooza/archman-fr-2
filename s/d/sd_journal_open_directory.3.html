SD_JOURNAL_OPEN(3) sd_journal_open SD_JOURNAL_OPEN(3)

NOM

sd_journal_open, sd_journal_open_directory, sd_journal_open_directory_fd, sd_journal_open_files, sd_journal_open_files_fd, sd_journal_open_namespace, sd_journal_close, sd_journal, SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_SYSTEM, SD_JOURNAL_CURRENT_USER, SD_JOURNAL_OS_ROOT, SD_JOURNAL_ALL_NAMESPACES, SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, SD_JOURNAL_TAKE_DIRECTORY_FD - Ouvrir le journal système en lecture

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_open(sd_journal **ret, int flags);

int sd_journal_open_namespace(sd_journal **ret, const char *namespace, int flags);

int sd_journal_open_directory(sd_journal **ret, const char *path, int flags);

int sd_journal_open_directory_fd(sd_journal **ret, int fd, int flags);

int sd_journal_open_files(sd_journal **ret, const char **paths, int flags);

int sd_journal_open_files_fd(sd_journal **ret, int fds[], unsigned n_fds, int flags);

void sd_journal_close(sd_journal *j);

DESCRIPTION

sd_journal_open() ouvre le journal des logs en lecture. Il détecte automatiquement tous les fichiers du journal et les intercale lors de la lecture. Comme premier argument, il prend un pointeur vers un pointeur sd_journal, qui, en cas de succès, contiendra un objet de contexte du journal. Le second argument est un champ de drapeaux (flags), qui peut être constitué des drapeaux suivants combinés par OU logique : SD_JOURNAL_LOCAL_ONLY garantit que seuls les fichiers journaux générés sur la machine locale seront ouverts. SD_JOURNAL_RUNTIME_ONLY garantit que seuls les fichiers journaux volatils seront ouverts, excluant ceux qui sont stockés sur un stockage persistant. SD_JOURNAL_SYSTEM provoquera l'ouverture des fichiers journaux des services système et du noyau (par opposition aux processus de session utilisateur). SD_JOURNAL_CURRENT_USER provoquera l'ouverture des fichiers journaux de l'utilisateur actuel. Si ni SD_JOURNAL_SYSTEM ni SD_JOURNAL_CURRENT_USER ne sont spécifiés, tous les types de fichiers journaux seront ouverts.

sd_journal_open_namespace() est similaire à sd_journal_open() mais prend un paramètre supplémentaire namespace qui spécifie sur quel espace de noms du journal opérer. S'il est spécifié comme NULL, l'appel est identique à sd_journal_open(). S'il est non-NULL, seules les données de l'espace de noms identifié par le paramètre spécifié sont accessibles. Cet appel comprend deux drapeaux supplémentaires : si SD_JOURNAL_ALL_NAMESPACES est spécifié, le paramètre namespace est ignoré et tous les espaces de noms définis sont accessibles simultanément ; si SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, l'espace de noms spécifié et l'espace de noms par défaut sont accessibles mais aucun autre (ce drapeau n'a aucun effet lorsque namespace est passé comme NULL). Pour plus de détails sur les espaces de noms de journaux, voir systemd-journald.service(8).

sd_journal_open_directory() est similaire à sd_journal_open() mais prend un chemin de répertoire absolu comme argument. Tous les fichiers journaux dans ce répertoire seront ouverts et intercalés automatiquement. Cet appel prend également un argument de drapeaux. Les paramètres de drapeaux acceptés par cet appel sont SD_JOURNAL_OS_ROOT, SD_JOURNAL_SYSTEM, et SD_JOURNAL_CURRENT_USER. Si SD_JOURNAL_OS_ROOT est spécifié, les fichiers journaux sont recherchés sous les répertoires habituels /var/log/journal et /run/log/journal relatifs au chemin spécifié, au lieu de directement en dessous. Les deux autres drapeaux limitent les fichiers qui sont ouverts, de la même manière que pour sd_journal_open().

sd_journal_open_directory_fd() est similaire à sd_journal_open_directory(), mais prend un descripteur de fichier référençant un répertoire dans le système de fichiers au lieu d'un chemin de système de fichiers absolu. En plus des drapeaux acceptés par sd_journal_open_directory(), cette fonction accepte également SD_JOURNAL_TAKE_DIRECTORY_FD. Si SD_JOURNAL_TAKE_DIRECTORY_FD est spécifié, la fonction prendra possession du descripteur de fichier spécifié en cas de succès, et il sera fermé par sd_journal_close(), par conséquent l'appelant de la fonction ne doit pas fermer le descripteur de fichier. Lorsque le drapeau n'est pas spécifié, sd_journal_close() ne fermera pas le descripteur de fichier, donc l'appelant devrait le fermer après sd_journal_close().

sd_journal_open_files() est similaire à sd_journal_open() mais prend une liste de chemins de fichiers terminée par NULL à ouvrir. Tous les fichiers seront ouverts et intercalés automatiquement. Cet appel prend également un argument de drapeaux, mais il doit être passé comme 0 car aucun drapeau n'est actuellement compris pour cet appel. Veuillez noter que dans le cas d'un journal en direct, cette fonction n'est utile que pour le débogage, car les fichiers journaux individuels peuvent être pivotés à tout moment, et l'ouverture de fichiers spécifiques est intrinsèquement sujette à des conditions de concurrence.

sd_journal_open_files_fd() est similaire à sd_journal_open_files() mais prend un tableau de descripteurs de fichiers ouverts qui doivent référencer des fichiers journaux, au lieu d'un tableau de chemins de système de fichiers. Passez le tableau de descripteurs de fichiers comme deuxième argument, et le nombre d'entrées du tableau dans le troisième. Le paramètre de drapeaux doit être passé comme 0.

Les objets sd_journal ne peuvent pas être utilisés dans l'enfant après un fork. Les fonctions qui prennent un objet journal comme argument (sd_journal_next() et autres) retourneront -ECHILD après un fork.

sd_journal_close() fermera le contexte du journal alloué avec sd_journal_open() ou sd_journal_open_directory() et libérera ses ressources.

Lors de l'ouverture du journal, seuls les fichiers journaux accessibles à l'utilisateur appelant seront ouverts. Si les fichiers journaux ne sont pas accessibles à l'appelant, cela sera ignoré silencieusement.

Voir sd_journal_next(3) pour un exemple de la façon d'itérer à travers le journal après l'avoir ouvert avec sd_journal_open().

Un objet de contexte de journal retourné par sd_journal_open() référence une entrée de journal spécifique comme entrée actuelle, similaire à un index de recherche de fichier dans un fichier système classique, mais sans positions absolues. Il peut être modifié avec sd_journal_next(3) et sd_journal_seek_head(3) et les appels associés. La position de l'entrée actuelle peut être exportée dans des chaînes curseur, accessibles via sd_journal_get_cursor(3). Les chaînes curseur peuvent être utilisées pour identifier globalement une entrée de journal de manière stable, puis plus tard pour y rechercher (ou si l'entrée spécifique n'est pas disponible localement, à son entrée la plus proche dans le temps) sd_journal_seek_cursor(3).

La notification des changements du journal est disponible via sd_journal_get_fd() et les appels associés.

VALEUR RENVOYÉE

Les appels sd_journal_open(), sd_journal_open_directory(), et sd_journal_open_files() renvoient 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_close() ne renvoie rien.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et seul un unique thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

HISTORIQUE
