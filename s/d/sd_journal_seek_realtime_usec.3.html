SD_JOURNAL_SEEK_HEAD(3) sd_journal_seek_head SD_JOURNAL_SEEK_HEAD(3)

NOM

sd_journal_seek_head, sd_journal_seek_tail, sd_journal_seek_monotonic_usec, sd_journal_seek_realtime_usec, sd_journal_seek_cursor - Se positionner dans le journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_seek_head(sd_journal *j);

int sd_journal_seek_tail(sd_journal *j);

int sd_journal_seek_monotonic_usec(sd_journal *j, sd_id128_t boot_id, uint64_t usec);

int sd_journal_seek_realtime_usec(sd_journal *j, uint64_t usec);

int sd_journal_seek_cursor(sd_journal *j, const char *cursor);

DESCRIPTION

sd_journal_seek_head() se positionne au début du journal, c'est-à-dire avant la plus ancienne entrée disponible.

De même, sd_journal_seek_tail() peut être utilisé pour se positionner à la fin du journal, c'est-à-dire après la plus récente entrée disponible.

sd_journal_seek_monotonic_usec() se positionne à un moment donné basé sur l'horloge monotone, c'est-à-dire CLOCK_MONOTONIC. Comme le temps monotone redémarre à chaque redémarrage, l'identifiant de démarrage doit être spécifié.

sd_journal_seek_realtime_usec() se positionne à un moment donné basé sur l'horloge temps réel (horloge murale), c'est-à-dire CLOCK_REALTIME. Notez que l'horloge temps réel n'est pas nécessairement monotone. Si un horodatage temps réel est ambigu, il n'est pas défini quelle position sera visée.

sd_journal_seek_cursor() se positionne à l'emplacement indiqué par la chaîne de curseur spécifiée. Pour plus de détails sur les curseurs, voir sd_journal_get_cursor(3). Si aucune entrée ne correspond exactement au curseur spécifié, l'appel se positionnera sur l'entrée la plus proche (en termes de temps).

Notez que ces appels ne font pas de l'entrée une nouvelle entrée actuelle ; cela doit être fait dans une étape séparée avec une invocation ultérieure de sd_journal_next(3) (ou un appel similaire). Seulement alors, les données de l'entrée peuvent être récupérées via sd_journal_get_data(3) ou un curseur d'entrée peut être récupéré via sd_journal_get_cursor(3). Si aucune entrée n'existe qui corresponde exactement à l'adresse de positionnement spécifiée, l'entrée la plus proche est visée. Si sd_journal_next(3) est utilisé, l'entrée suivante la plus proche sera visée ; si sd_journal_previous(3) est utilisé, l'entrée précédente la plus proche sera visée.

Après le positionnement, et une fois que sd_journal_next(3) ou un appel similaire a été effectué, sd_journal_test_cursor(3) peut être utilisé pour vérifier si l'entrée nouvellement sélectionnée correspond réellement au curseur.

VALEUR DE RETOUR

Les fonctions retournent 0 en cas de succès ou un code d'erreur négatif de type errno.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

HISTORIQUE

sd_journal_seek_head(), sd_journal_seek_tail(), sd_journal_seek_monotonic_usec(), sd_journal_seek_realtime_usec(), et sd_journal_seek_cursor() ont été ajoutés dans la version 187.
