DESCRIPTION

sd_event_add_child() ajoute une nouvelle source d'événement de changement d'état de processus fils à une boucle d'événements. L'objet de boucle d'événements est spécifié par le paramètre event, l'objet de source d'événement est retourné dans le paramètre source. Le paramètre pid spécifie le PID du processus à surveiller, qui doit être un fils direct du processus appelant. Le paramètre options détermine quels changements d'état seront surveillés. Il doit contenir un masque OR des flags WEXITED (surveiller la terminaison du processus fils), WSTOPPED (surveiller l'arrêt du processus fils par un signal) et WCONTINUED (surveiller la reprise du processus fils par un signal). Voir waitid(2) pour plus d'informations.

Le paramètre handler doit être une fonction à appeler lorsque le processus change d'état, ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure siginfo_t contenant des informations sur l'événement du processus fils. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul gestionnaire peut être installé pour un processus fils spécifique. Le gestionnaire est activé pour un seul événement (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire renvoie un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, ou elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet de source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont abandonnées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si une référence à elle est toujours conservée, envisagez de régler la source d'événement sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Le signal SIGCHLD doit être bloqué dans tous les threads avant d'appeler cette fonction (en utilisant sigprocmask(2) ou pthread_sigmask(3)).

Si le deuxième paramètre de sd_event_add_child() est passé comme NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Notez que la fonction handler est invoquée à un moment où le processus fils n'a pas encore été collecté (et est donc encore exposé comme un processus zombie par le noyau). Cependant, le fils sera automatiquement collecté après le retour de la fonction. Les processus fils pour lesquels aucune source d'événement de changement d'état de processus fils n'est installée ne seront pas collectés par l'implémentation de la boucle d'événements.

Si le paramètre handler de sd_event_add_child() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Si à la fois une source d'événement de changement d'état de processus fils et une source d'événement de signal SIGCHLD sont installées dans la même boucle d'événements, les priorités configurées des sources d'événements décident quelle source d'événement est traitée en premier. Si le gestionnaire de signal est traité en premier, il doit laisser les processus fils pour lesquels des sources d'événements de changement d'état de processus fils sont installées non collectés.

sd_event_add_child_pidfd() est similaire à sd_event_add_child() mais prend un descripteur de fichier référençant le processus ("pidfd") au lieu du PID numérique. Un descripteur de fichier adéquat peut être obtenu via pidfd_open(2) et les appels associés. Le descripteur de fichier passé n'est pas fermé lorsque la source d'événement est libérée à nouveau, à moins que sd_event_source_set_child_pidfd_own() ne soit utilisé pour activer ce comportement. Notez que, quelle que soit la fonction utilisée, sd_event_add_child() ou sd_event_add_child_pidfd(), pour allouer une source d'événement, le processus surveillé doit être un fils direct du processus appelant. Dans les deux cas, SIGCHLD doit être bloqué dans le processus appelant.

sd_event_source_get_child_pid() récupère le PID configuré d'une source d'événement de changement d'état de processus fils créée précédemment avec sd_event_add_child(). Elle prend l'objet source d'événement comme paramètre source et un pointeur vers une variable de type pid_t pour y retourner l'ID du processus.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier référençant le processus surveillé ("pidfd"). La boucle d'événements utilise en interne les pidfds pour surveiller les processus fils, que les sources d'événements individuelles soient allouées via sd_event_add_child() ou sd_event_add_child_pidfd(). Si ce dernier appel a été utilisé pour allouer la source d'événement, cette fonction retourne le descripteur de fichier d'origine utilisé pour l'allocation. Cet appel prend l'objet source d'événement comme paramètre source et retourne le descripteur de fichier numérique.

sd_event_source_get_child_pidfd_own() peut être utilisée pour interroger si le pidfd que la source d'événement encapsule doit être fermé lorsque la source d'événement est libérée. Cette fonction retourne zéro si le pidfd doit rester ouvert, et une valeur positive s'il doit être fermé automatiquement. Par défaut, ce réglage est activé si la source d'événement a été allouée via sd_event_add_child() et désactivé si elle a été allouée via sd_event_add_child_pidfd(). La fonction sd_event_source_set_child_pidfd_own() peut être utilisée pour changer ce réglage et prend un paramètre booléen avec le nouveau réglage.

sd_event_source_get_child_process_own() peut être utilisée pour interroger si le processus que la source d'événement surveille doit être tué (avec SIGKILL) et collecté lorsque la source d'événement est libérée. Cette fonction retourne zéro si le processus doit rester en cours d'exécution, et une valeur positive s'il doit être tué et collecté automatiquement. Par défaut, ce réglage est désactivé. NAME

sd_event_source_get_child_pidfd_own, sd_event_source_set_child_pidfd_own, sd_event_source_get_child_process_own, sd_event_source_set_child_process_own, sd_event_source_send_child_signal - Get and set ownership of child process event sources, send signals to child processes

SYNOPSIS

#include <systemd/sd-event.h>
int sd_event_source_get_child_pidfd_own(sd_event_source *source, pid_t *pid);
int sd_event_source_set_child_pidfd_own(sd_event_source *source, pid_t pid);
int sd_event_source_get_child_process_own(sd_event_source *source, pid_t *pid);
int sd_event_source_set_child_process_own(sd_event_source *source, pid_t pid);
int sd_event_source_send_child_signal(sd_event_source *source, pid_t pid, int signal, const siginfo_t *info, int flags);

Link with -lsystemd

DESCRIPTION

These functions manage child process event sources. An event source of this type watches a child process. The event source is triggered when the child process terminates, stops, or resumes execution. The watched process may be identified by its process ID (PID) or by a pidfd_open(2) file descriptor.

sd_event_source_get_child_pidfd_own() retrieves the PID of the child process associated with the given source. The PID is stored in the pid parameter.

sd_event_source_set_child_pidfd_own() sets the PID of the child process associated with the given source to pid. This function is typically used internally by systemd when a new event loop is created. The caller should generally not need to use this function.

sd_event_source_get_child_process_own() retrieves the PID of the child process associated with the given source. The PID is stored in the pid parameter.

sd_event_source_set_child_process_own() sets the PID of the child process associated with the given source to pid. This function is typically used internally by systemd when a new event loop is created. The caller should generally not need to use this function.

sd_event_source_send_child_signal() sends a UNIX signal to the watched process via pidfd_send_signal(2). The specified parameters match those of the underlying system call, except that the info is never modified (and is thus declared constant). Like for the underlying system call, the flags parameter currently must be zero.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed. This includes specifying an empty mask in options or a mask which contains values different than a combination of WEXITED, WSTOPPED, and WCONTINUED.

-EBUSY

A handler is already installed for this child process, or SIGCHLD is not blocked.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EDOM

The passed event source is not a child process event source.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

EXAMPLE

Example 1. Exit loop when the child terminates

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* SIGCHLD signal must be blocked for sd_event_add_child to work */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* child */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Create the default event loop */
    sd_event_default(&e);
    assert(e);
    /* We create a floating child event source (attached to 'e').
     * The default handler will be called with 666 as userdata, which
     * will become the exit value of the loop. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
