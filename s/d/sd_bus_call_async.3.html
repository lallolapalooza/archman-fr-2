sd_bus_call_async(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_CALL(3) sd_bus_call SD_BUS_CALL(3)

NOM

sd_bus_call, sd_bus_call_async - Invoquer un appel de méthode D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_call(sd_bus *bus, sd_bus_message *m, uint64_t usec, sd_bus_error *ret_error, sd_bus_message **reply);

int sd_bus_call_async(sd_bus *bus, sd_bus_slot **slot, sd_bus_message *m, sd_bus_message_handler_t callback, void *userdata, uint64_t usec);

DESCRIPTION

sd_bus_call() prend un objet message de bus complet et appelle la méthode D-Bus correspondante. En cas de succès, la réponse est stockée dans reply. usec indique le délai d'attente en microsecondes. Si ret_error n'est pas NULL et que sd_bus_call() échoue (soit en raison d'une erreur interne, soit parce qu'il a reçu une réponse d'erreur D-Bus), ret_error est initialisé à une instance de sd_bus_error décrivant l'erreur.

sd_bus_call_async() est similaire à sd_bus_call() mais fonctionne de manière asynchrone. Le callback indique la fonction à appeler lorsque la réponse arrive. Le pointeur userdata sera passé à la fonction de rappel, et peut être choisi librement par l'appelant. Si slot n'est pas NULL et que sd_bus_call_async() réussit, slot est défini sur un objet slot qui peut être utilisé pour annuler l'appel de méthode ultérieurement en utilisant sd_bus_slot_unref(3). Si slot est NULL, la durée de vie de l'appel de méthode est liée à la durée de vie de l'objet bus lui-même, et il ne peut pas être annulé indépendamment. Voir sd_bus_slot_set_floating(3) pour plus de détails. callback est appelé lorsqu'une réponse arrive avec la réponse, userdata et un paramètre de sortie sd_bus_error comme arguments. Contrairement à sd_bus_call(), le paramètre de sortie sd_bus_error passé au rappel sera vide. Pour déterminer si l'appel de méthode a réussi, utilisez plutôt sd_bus_message_is_method_error(3) sur le message de réponse passé au rappel. Si le rappel renvoie zéro et que le paramètre de sortie sd_bus_error est toujours vide à la fin du rappel, d'autres gestionnaires enregistrés avec des fonctions telles que sd_bus_add_filter(3) ou sd_bus_add_match(3) ont une chance de traiter le message. Si le rappel renvoie une valeur non nulle ou si le paramètre de sortie sd_bus_error n'est pas vide à la fin du rappel, aucun traitement supplémentaire du message n'est effectué. En général, vous voudrez renvoyer zéro du rappel pour donner aux autres gestionnaires enregistrés une chance de traiter la réponse également. (Notez que le paramètre sd_bus_error est un paramètre de sortie de la fonction de rappel, pas un paramètre d'entrée ; il peut être utilisé pour propager des erreurs du gestionnaire de rappel, il ne recevra aucune erreur qui aurait été reçue en tant que réponse de méthode.)

Le message m passé au rappel est seulement emprunté, c'est-à-dire que le rappel ne doit pas appeler sd_bus_message_unref(3) dessus. Si le rappel veut conserver le message au-delà de la durée de vie du rappel, il doit appeler sd_bus_message_ref(3) pour créer une nouvelle référence.

Si usec est zéro, le délai d'attente par défaut pour les appels de méthode D-Bus est utilisé. Voir sd_bus_get_method_call_timeout(3).

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Lorsque sd_bus_call() reçoit en interne une réponse d'erreur D-Bus, il définira ret_error s'il n'est pas NULL, et renverra une valeur négative mappée à partir de la réponse d'erreur, voir sd_bus_error_get_errno(3).

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre d'entrée m est NULL.

Le paramètre d'entrée m n'est pas un appel de méthode D-Bus. Pour créer un nouvel appel de méthode D-Bus, utilisez sd_bus_message_new_method_call(3).

Le paramètre d'entrée m a le drapeau BUS_MESSAGE_NO_REPLY_EXPECTED défini.

Le paramètre d'entrée error n'est pas NULL mais n'a pas été défini sur SD_BUS_ERROR_NULL.

-ECHILD

La connexion bus a été allouée dans un processus parent et est réutilisée dans un processus enfant après fork().

-ENOTCONN

Le paramètre d'entrée bus est NULL ou le bus n'est pas connecté.

-ECONNRESET

La connexion bus a été fermée en attendant la réponse.

-ETIMEDOUT

Une réponse n'a pas été reçue dans le délai imparti.

-ELOOP

Le message m est adressé à son propre client.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_call() et sd_bus_call_async() ont été ajoutés dans la version 221.
