DESCRIPTION

Ces fonctions renvoient des informations de crédential à partir d'un objet sd_bus_creds. Les objets de crédential peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les crédentials du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les crédentials d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les crédentials du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les crédentials de l'expéditeur du message.

Tous les champs de crédential ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupérera le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupérera le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_pidfd_dup() récupérera le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupérera le TID (identifiant de thread).

sd_bus_creds_get_uid() récupérera l'UID numérique (identifiant d'utilisateur). De même, sd_bus_creds_get_euid() renvoie l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupérera le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() renvoie le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupérera la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupérera le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupérera le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupérera le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est renvoyé. Notez que cette propriété ne doit pas être utilisée pour plus qu'une information explicative, en particulier elle ne doit pas être utilisée pour des décisions de sécurité. C'est parce que l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

Les fonctions décrites ici permettent de récupérer des informations sur les identifiants (crédits) d'un processus ou d'une connexion D-Bus, généralement obtenues à l'aide de sd_bus_creds_new_from_pid(3). L'objet de crédits est passé comme premier argument, et les fonctions sont utilisées pour interroger des champs spécifiques.

sd_bus_creds_get_pid(), sd_bus_creds_get_tid(), sd_bus_creds_get_ppid(), sd_bus_creds_get_uid(), sd_bus_creds_get_euid(), sd_bus_creds_get_suid(), sd_bus_creds_get_fsuid(), sd_bus_creds_get_gid(), sd_bus_creds_get_egid(), sd_bus_creds_get_sgid(), sd_bus_creds_get_fsgid() récupéreront les identifiants du processus, du thread, du processus parent, utilisateur effectif, superutilisateur, simulé, fichier système, groupe, groupe effectif, groupe superutilisateur, et groupe système de fichiers, respectivement. Si la valeur n'est pas disponible, -ENODATA sera retourné.

sd_bus_creds_get_supplementary_gids() récupérera la liste des groupes supplémentaires du processus. La liste se termine par une valeur spéciale, ou la liste est vide si le processus n'appartient à aucun groupe supplémentaire. Elle sera retournée sous forme de tableau de `gid_t` terminé par `(gid_t)-1`.

sd_bus_creds_get_comm() récupérera le nom de la commande actuelle du processus, tel qu'il est stocké dans `/proc/pid/comm`. Notez que les threads du noyau n'ont pas de nom de commande, dans ce cas -ENXIO est retourné.

sd_bus_creds_get_tid_comm() récupérera le nom de la commande du thread spécifique, tel qu'il est stocké dans `/proc/pid/task/tid/comm`. Ceci est utile pour savoir quelle est la commande du thread actif, même s'il est différent de la commande du processus principal.

sd_bus_creds_get_exe() récupérera le chemin absolu du fichier exécutable du processus, tel qu'il est stocké dans `/proc/pid/exe`. Notez que les threads du noyau n'ont pas d'exécutable, dans ce cas -ENXIO est retourné.

sd_bus_creds_get_cmdline() récupérera un tableau d'arguments de ligne de commande (tel que stocké dans `/proc/pid/cmdline`). Notez que les threads du noyau n'ont pas de ligne de commande, dans ce cas -ENXIO est retourné.

sd_bus_creds_get_cgroup() récupérera le chemin du groupe de contrôle. Voir Control Groups v2[1].

sd_bus_creds_get_unit() récupérera le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, retourne -ENXIO.

sd_bus_creds_get_user_unit() récupérera le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, retourne -ENXIO.

sd_bus_creds_get_slice() récupérera le slice systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). Similairement, sd_bus_creds_get_user_slice() récupère le slice systemd du processus, dans l'instance utilisateur de systemd.

sd_bus_creds_get_session() récupérera l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un ou deux processus stub. Les processus utilisateur peuvent plutôt être démarrés à partir de leur gestionnaire d'utilisateurs systemd, par exemple les applications graphiques démarrées en utilisant l'activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, retourne -ENXIO.

sd_bus_creds_get_owner_uid() récupérera l'UID numérique (identifiant utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, retourne -ENXIO.

sd_bus_creds_has_effective_cap() vérifiera si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités permises.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités limites.

sd_bus_creds_get_selinux_context() récupérera le contexte de sécurité SELinux (label) du processus.

sd_bus_creds_get_audit_session_id() récupérera l'identifiant de session d'audit du processus. Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_audit_login_uid() récupérera l'identifiant de connexion d'utilisateur d'audit (l'identifiant de l'utilisateur qui est "responsable" de la session). Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_tty() récupérera le TTY de contrôle, sans le préfixe "/dev/". Retourne -ENXIO pour les processus qui n'ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupérera le nom unique D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_well_known_names() récupérera l'ensemble des noms bien connus de D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_description() récupérera un nom descriptif de la connexion de bus de l'homologue. Ce nom est utile pour distinguer plusieurs connexions de bus du même homologue, et peut être modifié par l'homologue avec l'appel sd_bus_set_description(3).

sd_bus_creds_get_pidfd_dup() récupérera un descripteur de fichier pour le processus spécifié, en utilisant `pidfd_open(2)`. Le descripteur de fichier retourné doit être libéré par l'appelant en utilisant close(2). Si le processus n'existe plus, ou si le PID fourni n'est pas un descripteur de fichier valide, -ENOENT est retourné.

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse à cet endroit sous forme d'adresse d'une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse à cet endroit sous forme d'adresse d'un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

VALEUR RETOURNÉE

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet crédits c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou l'homologue décrit. Ceci sera retourné par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'un slice systemd, ou d'une session logind. Il sera retourné par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également retourné par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas démarrés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-ENOENT

Le processus spécifié par c n'existe plus, ou le PID n'est pas valide. Ceci peut être retourné par sd_bus_creds_get_pidfd_dup().

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
