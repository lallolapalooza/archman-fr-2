sd_bus_release_name_async(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_REQUEST_NAME(3) sd_bus_request_name SD_BUS_REQUEST_NAME(3)

NOM

sd_bus_request_name, sd_bus_request_name_async, sd_bus_release_name, sd_bus_release_name_async - Demander ou libérer un nom de service bien connu sur un bus

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_request_name(sd_bus *bus, const char *name, uint64_t flags);

int sd_bus_request_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, uint64_t flags, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_release_name(sd_bus *bus, const char *name);

int sd_bus_release_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, sd_bus_message_handler_t callback, void *userdata);

DESCRIPTION

sd_bus_request_name() demande un nom de service bien connu sur un bus. Il prend une connexion de bus, un nom de bus valide et un paramètre de drapeaux. Le paramètre de drapeaux est une combinaison de zéro ou plusieurs des drapeaux suivants :

SD_BUS_NAME_ALLOW_REPLACEMENT

Après avoir acquis le nom avec succès, permet à d'autres pairs de prendre le relais du nom lorsqu'ils essaient de l'acquérir avec le drapeau SD_BUS_NAME_REPLACE_EXISTING défini. Si SD_BUS_NAME_ALLOW_REPLACEMENT n'est pas défini sur la requête d'origine, une telle requête par d'autres pairs sera refusée.

Ajouté dans la version 209.

SD_BUS_NAME_REPLACE_EXISTING

Prendre le relais du nom s'il a déjà été acquis par une autre pair, et que cette autre pair a autorisé la reprise en définissant SD_BUS_NAME_ALLOW_REPLACEMENT lors de son acquisition.

Ajouté dans la version 209.

SD_BUS_NAME_QUEUE

Mettre en file d'attente l'acquisition du nom lorsque le nom est déjà pris.

Ajouté dans la version 209.

sd_bus_request_name() fonctionne de manière synchrone : un message demandant le nom est envoyé au courtier du bus, et l'appel attend jusqu'à ce que le courtier réponde.

sd_bus_request_name_async() est une version asynchrone de sd_bus_request_name(). Au lieu d'attendre que la requête soit terminée, le message de requête est mis en file d'attente. Le callback spécifié sera appelé lorsque la réponse du courtier sera reçue. Si le paramètre est spécifié comme NULL, une implémentation par défaut est utilisée à la place, qui terminera la connexion lorsque le nom ne pourra pas être acquis. La fonction retourne un objet slot dans son paramètre slot — s'il est passé comme non-NULL — qui peut être utilisé comme référence à l'opération de requête de nom. Utilisez sd_bus_slot_unref(3) pour détruire cette référence. Notez que la destruction de la référence ne désenregistrera pas le nom, mais garantira simplement que le callback spécifié ne sera plus appelé.

sd_bus_release_name() libère un nom connu acquis. Il prend une connexion de bus et un nom de bus valide comme paramètres. Cette fonction fonctionne de manière synchrone, en envoyant un message de requête de libération au courtier du bus et en attendant sa réponse.

sd_bus_release_name_async() est une version asynchrone de sd_bus_release_name(). La fonction callback spécifiée est appelée lorsque le nom a été libéré avec succès. Si spécifié comme NULL, une implémentation générique est utilisée qui ignore le résultat de l'opération. Comme ci-dessus, le slot (s'il n'est pas NULL) est défini sur un objet qui peut être utilisé pour référencer l'opération.

Ces fonctions ne sont prises en charge que sur les connexions de bus, c'est-à-dire les connexions à un courtier de bus et non sur les connexions directes.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Si SD_BUS_NAME_QUEUE est spécifié, sd_bus_request_name() retournera 0 lorsque le nom est déjà pris par une autre pair et que le client a été ajouté à la file d'attente pour le nom. Dans ce cas, l'appelant peut s'abonner aux signaux "NameOwnerChanged" pour être notifié lorsque le nom est acquis avec succès. sd_bus_request_name() retourne > 0 lorsque le nom a été immédiatement acquis avec succès.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EALREADY

L'appelant est déjà le propriétaire du nom spécifié.

-EEXIST

Le nom a déjà été acquis par une pair différente, et SD_BUS_NAME_REPLACE_EXISTING n'a pas été spécifié ou l'autre pair n'a pas spécifié SD_BUS_NAME_ALLOW_REPLACEMENT lors de l'acquisition du nom.

-ESRCH

Il a été tenté de libérer un nom qui n'est actuellement pas enregistré sur le bus.

-EADDRINUSE

Il a été tenté de libérer un nom qui appartient à une autre pair sur le bus.

-EINVAL

Un paramètre spécifié est invalide. Ceci est également généré lorsque le nom demandé est un nom de service spécial réservé par la spécification D-Bus, ou lorsque l'opération est demandée sur une connexion qui ne fait pas référence à un bus.

-ENOTCONN

La connexion de bus a été déconnectée.

-ECHILD

La connexion de bus a été créée dans un processus différent de celui actuel.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour le multithreading. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_request_name() et sd_bus_release_name() ont été ajoutés dans la version 209.

sd_bus_request_name_async() et sd_bus_release_name_async() ont été ajoutés dans la version 237.
