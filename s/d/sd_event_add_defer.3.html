SD_EVENT_ADD_DEFER(3) sd_event_add_defer SD_EVENT_ADD_DEFER(3)

NOM

sd_event_add_defer, sd_event_add_post, sd_event_add_exit, sd_event_handler_t - Ajouter des sources d'événements statiques à une boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_handler_t)(sd_event_source *s, void *userdata);

int sd_event_add_defer(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

int sd_event_add_post(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

int sd_event_add_exit(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

DESCRIPTION

Ces trois fonctions ajoutent de nouvelles sources d'événements statiques à une boucle d'événements. L'objet boucle d'événements est spécifié par le paramètre event, l'objet source d'événement est retourné par le paramètre source. Les sources d'événements sont activées statiquement et seront "déclenchées" lorsque la boucle d'événements sera exécutée et que les conditions décrites ci-dessous seront remplies.

Le handler est une fonction à appeler ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

sd_event_add_defer() ajoute une nouvelle source d'événement qui sera diffusée instantanément, avant que la boucle d'événements ne se mette à nouveau en veille et attende de nouveaux événements. Par défaut, le gestionnaire sera appelé une fois (SD_EVENT_ONESHOT). Notez que si la source d'événement est définie sur SD_EVENT_ON, la boucle d'événements ne se mettra jamais en veille, mais appellera continuellement le gestionnaire, éventuellement entrecoupée par d'autres sources d'événements.

sd_event_add_post() ajoute une nouvelle source d'événement qui est exécutée avant que la boucle d'événements ne se mette en veille et attende de nouveaux événements, mais seulement après qu'au moins une autre source d'événement non-post ait été diffusée. Par défaut, la source est activée en permanence (SD_EVENT_ON). Notez que ce type de source d'événement permettra toujours à la boucle d'événements de se mettre en veille, même si elle est définie sur SD_EVENT_ON, tant qu'aucune autre source d'événement n'est déclenchée.

sd_event_add_exit() ajoute une nouvelle source d'événement qui sera diffusée lorsque la boucle d'événements sera terminée avec sd_event_exit(3).

La fonction sd_event_source_set_enabled(3) peut être utilisée pour activer la source d'événement en permanence (SD_EVENT_ON) ou pour qu'elle ne se déclenche qu'une seule fois (SD_EVENT_ONESHOT).

Si la fonction de gestionnaire retourne un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON avait été demandé auparavant, ou elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est supprimée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour vous assurer qu'une source d'événement ne se déclenche plus, même s'il existe encore une référence à celle-ci, envisagez de définir la source d'événement sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Si le deuxième paramètre de ces fonctions est passé comme NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler pour sd_event_add_defer() ou sd_event_add_post() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3). Une fonctionnalité similaire n'est pas disponible pour sd_event_add_exit(), car ces types de sources d'événements ne sont diffusés qu'au moment de la sortie.

VALEUR RENVOYÉE

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que depuis une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_add_defer(), sd_event_add_post(), sd_event_add_exit(), et sd_event_handler_t() ont été ajoutés dans la version 217.
