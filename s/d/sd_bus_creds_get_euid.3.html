DESCRIPTION

Ces fonctions retournent des informations d'identification à partir d'un objet sd_bus_creds. Les objets credentials peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). Similairement, sd_bus_creds_get_ppid() récupère le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour plus de détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant utilisateur). Similairement, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). Similairement, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GID supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel qu'enregistré dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel qu'enregistré dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin d'accès à l'exécutable du programme (tel qu'enregistré dans le lien /proc/pid/exe, mais avec le suffixe " (supprimé)" retiré). Notez que les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée pour plus d'informations explicatives, en particulier elle ne doit pas être utilisée pour des décisions de sécurité. C'est parce que l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

Les fonctions décrites ici permettent de récupérer diverses informations de crédibilité sur le processus ou l'utilisateur D-Bus associé à un objet crédibilité c. Ces objets sont généralement créés avec sd_bus_creds_new_from_pid(3) ou sd_bus_get_creds(3).

Les fonctions qui retournent des chaînes de caractères écrivent l'adresse de la chaîne dans le pointeur fourni. Le données de la chaîne sont valides tant que l'objet crédibilité c est valide.

Les fonctions qui retournent des tableaux de chaînes de caractères écrivent l'adresse du tableau dans le pointeur fourni. Le tableau est terminé par NULL et chaque chaîne est terminée par NULL. Les données du tableau et des chaînes sont valides tant que l'objet crédibilité c est valide.

sd_bus_creds_get_pid() récupère l'ID du processus.

sd_bus_creds_get_tid() récupère l'ID du thread.

sd_bus_creds_get_ppid() récupère l'ID du processus parent.

sd_bus_creds_get_uid(), sd_bus_creds_get_euid(), sd_bus_creds_get_suid(), sd_bus_creds_get_fsuid() récupèrent les ID utilisateur réels, effectifs, sauvegardés et effectifs du système de fichiers, respectivement.

sd_bus_creds_get_gid(), sd_bus_creds_get_egid(), sd_bus_creds_get_sgid(), sd_bus_creds_get_fsgid() récupèrent les ID de groupe réels, effectifs, sauvegardés et effectifs du système de fichiers, respectivement.

sd_bus_creds_get_supplementary_gids() récupère la liste des ID de groupe supplémentaires.

sd_bus_creds_get_comm() récupère le nom de commande court (maximum 16 octets) du processus tel qu'il apparaît dans /proc/pid/comm. Les noyaux plus récents peuvent retourner un nom plus long dans /proc/pid/comm, mais il sera tronqué à 16 octets. Pour les threads du noyau, cette fonction échoue avec -ENXIO.

sd_bus_creds_get_tid_comm() récupère le nom de commande court du thread tel qu'il apparaît dans /proc/pid/task/tid/comm.

sd_bus_creds_get_exe() récupère le chemin d'accès à l'exécutable du processus, tel qu'il est stocké dans /proc/pid/exe. Notez que les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est retourné.

sd_bus_creds_get_cmdline() récupère un tableau d'arguments de ligne de commande (tel que stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est retourné.

sd_bus_creds_get_cgroup() récupère le chemin du groupe de contrôle. Voir Control Groups v2[1].

sd_bus_creds_get_unit() récupère le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, retourne -ENXIO.

sd_bus_creds_get_user_unit() récupère le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, retourne -ENXIO.

sd_bus_creds_get_slice() récupère le slice systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère le slice systemd du processus, dans l'instance utilisateur de systemd.

sd_bus_creds_get_session() récupère l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un processus de type stub ou deux. Les processus utilisateur peuvent plutôt être démarrés à partir de leur gestionnaire d'utilisateurs systemd, par exemple les applications GUI démarrées à l'aide de l'activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, retourne -ENXIO.

sd_bus_creds_get_owner_uid() récupère l'UID numérique (identifiant d'utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, retourne -ENXIO.

sd_bus_creds_has_effective_cap() vérifie si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités autorisées.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités limites.

sd_bus_creds_get_selinux_context() récupère le contexte de sécurité SELinux (label) du processus.

sd_bus_creds_get_audit_session_id() récupère l'identifiant de session d'audit du processus. Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_audit_login_uid() récupère l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur qui est "responsable" de la session). Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_tty() récupère le TTY de contrôle, sans le préfixe "/dev/". Retourne -ENXIO pour les processus qui n'ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupère le nom unique D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_well_known_names() récupère l'ensemble des noms connus D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_description() récupère un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus du même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).

sd_bus_creds_get_pidfd_dup() récupère un descripteur de fichier (pidfd) qui identifie le processus. Le descripteur de fichier est géré par le système et ne doit pas être fermé par l'appelant. Il est valable tant que l'objet crédibilité c est valable.

Toutes les fonctions qui prennent un paramètre const char** y stockeront la réponse sous forme d'adresse d'une chaîne de caractères terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** y stockeront la réponse sous forme d'adresse d'un tableau de chaînes de caractères. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

VALEUR RETOURNEE

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet crédibilité c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera retourné par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'un slice systemd, ou d'une session logind. Il sera retourné par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également retourné par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas démarrés à partir d'un binaire exécutable, et n'ont pas de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
