DESCRIPTION

Ces fonctions retournent des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupérera le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupérera le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupérera le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour plus de détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupérera le TID (identifiant de thread).

sd_bus_creds_get_uid() récupérera l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupérera le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupérera la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupérera le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupérera le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupérera le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée pour des informations explicatives, en particulier elle ne doit pas être utilisée pour des décisions relatives à la sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

The sd_bus_creds type is used to hold credentials of a bus peer or a local process. This object may be created using sd_bus_creds_new_from_pid() or when receiving a message via sd_bus_message_get_creds().

These functions retrieve individual fields from the credentials object c.

sd_bus_creds_get_exe() will retrieve the path to the executable. Note that kernel threads do not have an executable path, in which case -ENXIO is returned.

sd_bus_creds_get_cmdline() will retrieve an array of command line arguments (as stored in /proc/pid/cmdline). Note that kernel threads do not have a command line, in which case -ENXIO is returned.

sd_bus_creds_get_cgroup() will retrieve the control group path. See Control Groups v2[1].

sd_bus_creds_get_unit() will retrieve the systemd unit name (in the system instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a unit, returns -ENXIO.

sd_bus_creds_get_user_unit() will retrieve the systemd unit name (in the user instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a user unit, returns -ENXIO.

sd_bus_creds_get_slice() will retrieve the systemd slice (a unit in the system instance of systemd) that the process is a part of. See systemd.slice(5). Similarly, sd_bus_creds_get_user_slice() retrieves the systemd slice of the process, in the user instance of systemd.

sd_bus_creds_get_session() will retrieve the identifier of the login session that the process is a part of. Please note the login session may be limited to a stub process or two. User processes may instead be started from their systemd user manager, e.g. GUI applications started using DBus activation, as well as service processes which are shared between multiple logins of the same user. For processes that are not part of a session, returns -ENXIO.

sd_bus_creds_get_owner_uid() will retrieve the numeric UID (user identifier) of the user who owns the user unit or login session that the process is a part of. See systemd-logind.service(8). For processes that are not part of a user unit or session, returns -ENXIO.

sd_bus_creds_has_effective_cap() will check whether the capability specified by capability was set in the effective capabilities mask. A positive return value means that it was set, zero means that it was not set, and a negative return value indicates an error. See capabilities(7) and the AmbientCapabilities= and CapabilityBoundingSet= settings in systemd.exec(5).

sd_bus_creds_has_permitted_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the permitted capabilities mask.

sd_bus_creds_has_inheritable_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the inheritable capabilities mask.

sd_bus_creds_has_bounding_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the bounding capabilities mask.

sd_bus_creds_get_selinux_context() will retrieve the SELinux security context (label) of the process.

sd_bus_creds_get_audit_session_id() will retrieve the audit session identifier of the process. Returns -ENXIO for processes that are not part of an audit session.

sd_bus_creds_get_audit_login_uid() will retrieve the audit user login identifier (the identifier of the user who is "responsible" for the session). Returns -ENXIO for processes that are not part of an audit session.

sd_bus_creds_get_tty() will retrieve the controlling TTY, without the prefixing "/dev/". Returns -ENXIO for processes that have no controlling TTY.

sd_bus_creds_get_unique_name() will retrieve the D-Bus unique name. See The D-Bus specification[2].

sd_bus_creds_get_well_known_names() will retrieve the set of D-Bus well-known names. See The D-Bus specification[2].

sd_bus_creds_get_description() will retrieve a descriptive name of the bus connection of the peer. This name is useful to discern multiple bus connections by the same peer, and may be altered by the peer with the sd_bus_set_description(3) call.

sd_bus_creds_get_pidfd_dup() will duplicate the file descriptor for the PID, returning a new file descriptor on success. This file descriptor can be used for various operations on the process, for example with pidfd_open(). Note that this function may fail with -EPERM if the caller does not have permission to duplicate the PID file descriptor, e.g. if the target process is in a different user namespace and the caller is not privileged.

All functions that take a const char** parameter will store the answer there as an address of a NUL-terminated string. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

All functions that take a char*** parameter will store the answer there as an address of an array of strings. Each individual string is NUL-terminated, and the array is NULL-terminated as a whole. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet d'identification c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une slice systemd ou d'une session logind. Il sera renvoyé par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (puisqu'ils ne sont pas lancés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le pointeur de paramètre spécifié est NULL.

-ENOMEM

Échec de l'allocation de mémoire.

-EPERM

L'appelant n'a pas les permissions nécessaires pour accéder à l'information demandée (par exemple, pour dupliquer un descripteur de fichier PID d'un autre espace utilisateur).

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
