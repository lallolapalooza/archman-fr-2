DESCRIPTION

sd_pid_get_owner_uid() peut être utilisé pour déterminer l'UID Unix (identifiant utilisateur) qui possède la session de connexion ou l'unité utilisateur systemd d'un processus identifié par le PID spécifié. Pour les processus qui ne font pas partie d'une session de connexion et ne sont pas gérés par un gestionnaire utilisateur, cette fonction échouera avec -ENODATA.

sd_pid_get_session() peut être utilisé pour déterminer l'identifiant de la session de connexion d'un processus identifié par l'identifiant de processus spécifié. L'identifiant de session est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateur peuvent plutôt être démarrés depuis leur gestionnaire utilisateur systemd, par exemple les applications graphiques démarrées à l'aide de l'activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session de connexion, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_user_unit() peut être utilisé pour déterminer l'identifiant de l'unité utilisateur systemd (c'est-à-dire service utilisateur ou unité de portée) d'un processus identifié par le PID spécifié. Le nom de l'unité est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Pour les processus qui ne sont pas gérés par un gestionnaire utilisateur, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_unit() peut être utilisé pour déterminer l'identifiant de l'unité système systemd (c'est-à-dire service système ou unité de portée) d'un processus identifié par le PID spécifié. Le nom de l'unité est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Notez que tous les processus ne font pas partie d'une unité/service système. Pour les processus qui ne font pas partie d'une unité système systemd, cette fonction échouera avec -ENODATA. (Plus spécifiquement, cet appel ne fonctionnera pas pour les threads du noyau.) La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_machine_name() peut être utilisé pour déterminer le nom de la VM ou du conteneur dont un processus est membre. Le nom de la machine est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation. Pour les processus ne faisant pas partie d'une VM ou d'un conteneur, cette fonction échoue avec -ENODATA.

sd_pid_get_slice() peut être utilisé pour déterminer l'unité de tranche dont le processus est membre. Voir systemd.slice(5) pour plus de détails sur les tranches. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

De même, sd_pid_get_user_slice() retourne la tranche utilisateur (telle que gérée par l'instance systemd de l'utilisateur) d'un processus.

sd_pid_get_cgroup() retourne le chemin du groupe de contrôle du processus spécifié, relatif à la racine de la hiérarchie. Retourne le chemin sans la barre oblique finale, sauf pour les processus situés dans le groupe de contrôle racine, où "/" est retourné. Pour trouver le chemin réel du groupe de contrôle dans le système de fichiers, le chemin retourné doit être précédé de /sys/fs/cgroup/.

Si le paramètre pid de l'une de ces fonctions est passé comme 0, l'opération est exécutée pour le processus appelant.

Les appels sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() et sd_pidfd_get_cgroup() fonctionnent de manière similaire à leurs équivalents PID, mais acceptent un PIDFD au lieu d'un PID, ce qui signifie qu'ils ne sont pas sujets aux conditions de course de recyclage car le processus est épinglé par le descripteur de fichier pendant toute la durée de l'invocation. Notez que cela nécessite un noyau qui prend en charge PIDFD. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2).

Les appels sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() et sd_peer_get_cgroup() fonctionnent de manière similaire à leurs équivalents PID, mais acceptent un socket AF_UNIX connecté et récupèrent des informations sur le processus pair connecté. Notez que ces champs sont récupérés via /proc/, et ne sont donc pas adaptés à des fins d'autorisation, car ils sont sujets à des conditions de course.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ESRCH

Le PID spécifié ne correspond pas à un processus en cours d'exécution.

-EBADF

Le descripteur de fichier spécifié est invalide.

-ENODATA

Le champ spécifié n'est pas défini pour le processus ou le pair décrit.

-EINVAL

sd_pidfd_get_user_unit(3) — systemd — Arch Linux

NOM

sd_pidfd_get_user_unit, sd_pidfd_get_unit, sd_pidfd_get_session, sd_pidfd_get_machine_name, sd_pidfd_get_cgroup, sd_pidfd_get_slice, sd_pidfd_get_user_slice, sd_pid_get_user_unit, sd_pid_get_unit, sd_pid_get_session, sd_pid_get_machine_name, sd_pid_get_cgroup, sd_pid_get_slice, sd_pid_get_user_slice, sd_pid_get_owner_uid, sd_pidfd_get_owner_uid - obtenir des informations sur le processus, l'unité, la session ou le groupe de contrôle du processus.

SYNOPSIS

#include <systemd/sd-pid.h>

int sd_pidfd_get_user_unit(sd_pid *pid, char **unit_name);
int sd_pidfd_get_unit(sd_pid *pid, char **unit_name);

int sd_pidfd_get_cgroup(sd_pid *pid, char **cgroup_path);
int sd_pidfd_get_slice(sd_pid *pid, char **slice_name);
int sd_pidfd_get_user_slice(sd_pid *pid, char **user_slice_name);
int sd_pid_get_user_unit(pid_t pid, char **unit_name);
int sd_pid_get_unit(pid_t pid, char **unit_name);
int sd_pid_get_session(pid_t pid, char **session_id);
int sd_pid_get_machine_name(pid_t pid, char **machine_name);
int sd_pid_get_cgroup(pid_t pid, char **cgroup_path);
int sd_pid_get_slice(pid_t pid, char **slice_name);
int sd_pid_get_user_slice(pid_t pid, char **user_slice_name);
int sd_pid_get_owner_uid(pid_t pid, uid_t *uid);
int sd_pidfd_get_owner_uid(sd_pid *pid, uid_t *uid);

DESCRIPTION

Ces fonctions peuvent être utilisées pour interroger diverses informations liées au processus pour un processus donné. Les fonctions préfixées par sd_pidfd_ prennent un descripteur de fichier de processus (voir pidfd_open(2)) comme premier argument, tandis que les fonctions préfixées par sd_pid_ prennent un ID de processus POSIX (pid_t).

Pour les fonctions retournant des chaînes de caractères (toutes sauf sd_pid_get_owner_uid et sd_pidfd_get_owner_uid), le pointeur fourni sera défini sur une chaîne allouée par la bibliothèque, qui doit être libérée par l'appelant en utilisant free(3).

sd_pid_get_owner_uid et sd_pidfd_get_owner_uid retournent l'ID utilisateur effectif du propriétaire du fichier ou du processus donné, respectivement. Ceci est utile pour déterminer à quel utilisateur un processus appartient dans un contexte où l'audit et le suivi sont importants.

sd_pid_get_session et sd_pidfd_get_session retournent l'ID de la session du processus donné. Ceci est une chaîne de caractères qui identifie de manière unique une session de connexion.

sd_pid_get_machine_name et sd_pidfd_get_machine_name retournent le nom de la machine virtuelle ou du conteneur à laquelle le processus donné appartient. S'il n'y a pas de telle appartenance, une chaîne vide est retournée.

sd_pid_get_unit et sd_pidfd_get_unit retournent le nom de l'unité systemd qui contrôle le processus donné. S'il n'y a pas d'unité de contrôle, une chaîne vide est retournée.

sd_pid_get_user_unit et sd_pidfd_get_user_unit retournent le nom de l'unité systemd de session utilisateur qui contrôle le processus donné. S'il n'y a pas d'unité de session utilisateur, une chaîne vide est retournée.

sd_pid_get_cgroup et sd_pidfd_get_cgroup retournent le chemin d'accès complet au groupe de contrôle sous lequel le processus donné s'exécute. Ceci est utile pour l'inspection des ressources et le contrôle.

sd_pid_get_slice et sd_pid_get_slice retournent le nom de l'unité slice (par exemple, user-*.slice, system.slice) qui héberge le processus donné. Les noms de slice sont utiles pour regrouper et gérer les ressources des processus.

sd_pid_get_user_slice et sd_pidfd_get_user_slice retournent le nom de l'unité slice dédiée à un utilisateur spécifique. Cela aide à différencier les ressources allouées aux processus de différents utilisateurs.

Les fonctions qui prennent un pid_t peuvent ne pas être en mesure de déterminer les informations pour les processus détenus par d'autres utilisateurs, à moins qu'elles ne soient appelées avec des privilèges suffisants.

Toutes ces fonctions mettent à jour le pointeur pid fourni avec le dernier sd_pid s'il est passé comme NULL. Cela permet d'éviter les recherches redondantes.

AVANTAGES

-E2BIG
Le nom de l'unité est trop long.
-EFAULT
Un pointeur invalide a été fourni.
-EINVAL
Un paramètre d'entrée invalide a été fourni (hors de portée, ou NULL, là où ce n'est pas accepté).
-ENOMEM
L'allocation de mémoire a échoué.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Notez que l'identifiant de session de connexion tel que retourné par sd_pid_get_session() n'est absolument pas lié à l'identifiant de session du processus tel que retourné par getsid(2).
