DESCRIPTION

La structure sd_bus_error transporte des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ nom contient un bref identifiant d'une erreur. Il doit suivre les règles pour les noms d'erreur décrites dans la spécification D-Bus, sous-section Noms D-Bus valides[1]. Un certain nombre de noms d'erreur courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques au domaine supplémentaires peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir les deux champs initialisés à NULL et signifie l'absence d'erreur, c'est-à-dire le succès. Attribuez SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque plus nécessaire, les ressources détenues par la structure sd_bus_error doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de nom et de message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données stockées en elle avec sd_bus_error_free().

sd_bus_error_set() retournera une valeur similaire à errno (voir errno(3)) déterminée à partir du nom d'erreur nom spécifié. Si nom est NULL, on suppose qu'aucune erreur ne s'est produite, et 0 est retourné. Si nom est non nul, une valeur négative est toujours retournée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais nom est toujours converti en une valeur de type errno.

Diverses erreurs D-Bus bien connues sont converties en leurs correspondants errno bien connus, et les autres en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreur bien connus. Des correspondances d'erreurs supplémentaires peuvent être définies avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera retourné.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et les arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition de structures d'erreur. Puisque cet appel n'alloue pas de mémoire, il n'échouera pas avec une condition de manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() retournera immédiatement 0 si le paramètre d'erreur erreur spécifié est 0. Sinon, il définira nom à partir d'une valeur de type errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Des noms d'erreur D-Bus bien connus seront utilisés pour nom si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si l'erreur erreur spécifiée est non nulle, l'appel retourne toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est retourné.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de erreur, prennent une chaîne de format printf(3) et les arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ nom d'une structure d'erreur en une valeur de type errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera retourné.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été précédemment défini avec une valeur d'erreur. Sinon, il retournera immédiatement. Si les chaînes dans e ont été définies à l'aide de sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit nouvellement initialisé avec NULL, soit réinitialisé à l'aide de sd_bus_error_free().

sd_bus_error_copy() retourne généralement 0 ou une valeur négative de type errno basée sur le paramètre d'entrée e: 0 si elle était non définie et un entier négatif si elle était définie à une erreur, de manière similaire à sd_bus_error_set(). DESCRIPTION

La structure sd_bus_error est utilisée pour transporter des informations sur les erreurs échangées entre les processus via le bus D-Bus. Elle contient un nom d'erreur (name) et un message d'erreur (message), tous deux des chaînes de caractères C standard. Le nom de l'erreur est une chaîne identifiant le type d'erreur, tandis que le message est une description plus détaillée.

La structure sd_bus_error est définie comme suit :

struct sd_bus_error {
    char *name;
    char *message;
};

Il est courant de référencer les erreurs D-Bus avec le préfixe « org.freedesktop.DBus.Error. », bien que cela ne soit pas strictement obligatoire. Par exemple, org.freedesktop.DBus.Error.FileNotFound est un nom d'erreur D-Bus courant.

La fonction sd_bus_error_default() initialise la structure e avec des valeurs nulles et la renvoie. Les fonctions définissant l'erreur peuvent être appelées avec un pointeur nul vers sd_bus_error. Dans ce cas, elles n'échouent pas et essaient d'allouer la structure d'erreur elles-mêmes. Si l'allocation échoue, elles renvoient -ENOMEM. Notez que l'utilisation d'une structure d'erreur sur la pile est généralement préférable.

Les fonctions sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_setfv(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), et sd_bus_error_set_errnofv() définissent un nouveau nom et un nouveau message d'erreur dans la structure e. Elles allouent de la mémoire pour les deux chaînes de caractères, qui devront ensuite être libérées avec sd_bus_error_free(). Si une erreur est déjà définie dans e, ces fonctions échouent avec -EINVAL.

Les variantes _errno et _errnof prennent un entier errno_val. Si cet entier est non nul, il est utilisé pour remplir le nom d'erreur D-Bus par défaut. Le nom D-Bus par défaut est soit errno_name(3) pour les erreurs POSIX, soit sd_bus_error_get_errno() pour les valeurs inconnues. Les fonctions _errnof et _errnofv peuvent également prendre un format de message et des arguments qui seront utilisés pour construire le message d'erreur D-Bus. La fonction sd_bus_error_setfv() est similaire à sd_bus_error_setf() mais prend une liste d'arguments variable va_list au lieu des arguments séparés.

La fonction sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais elle ne copie pas le nom et le message d'erreur. Au lieu de cela, elle stocke les pointeurs passés. Cela signifie que les chaînes passées doivent rester valides tant que l'erreur n'est pas libérée. Elle ne peut pas être utilisée pour définir une erreur sur un pointeur nul.

La fonction sd_bus_error_copy() copie les informations d'erreur de src vers dst. Si dst contient déjà une erreur, elle est d'abord libérée. La fonction alloue de la mémoire pour le nom et le message. Elle ne peut pas échouer, car elle renvoie une valeur d'erreur convertie d'errno en cas d'échec, par exemple -ENOMEM si une allocation de mémoire échoue.

La fonction sd_bus_error_move() est similaire à sd_bus_error_copy(), mais elle déplace toute information d'erreur de e vers dst, réinitialisant le premier. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si e n'est pas défini, dst est initialisé à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est exécutée dessus et les ressources détenues par e sont libérées et réinitialisées. Renvoie une valeur d'erreur non positive semblable à errno convertie.

La fonction sd_bus_error_is_set() renverra une valeur non nulle si e n'est pas NULL et qu'une erreur a été définie, sinon false.

La fonction sd_bus_error_has_name() renverra une valeur non nulle si e n'est pas NULL et qu'une erreur avec le même name a été définie, sinon false.

La fonction sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est un wrapper macro autour de sd_bus_error_has_names_sentinel() qui ajoute automatiquement le terminateur NULL.

La fonction sd_bus_error_free() détruira les ressources détenues par e. Le paramètre lui-même ne sera pas désalloué et devra être free(3)d par l'appelant si nécessaire. La fonction peut également être appelée en toute sécurité sur des erreurs non définies (structures d'erreur avec les deux champs définis sur NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après avoir libéré les données, de sorte que tous les champs soient définis sur NULL. La structure peut être réutilisée par la suite.

PROPRIETE DES REFERENCES

sd_bus_error n'est pas comptée par référence. Les utilisateurs doivent détruire les ressources qu'elle détient en appelant sd_bus_error_free(). Habituellement, les structures d'erreur sont allouées sur la pile ou passées en paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il incombe à l'appelant de free(3) la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

VALEUR DE RETOUR

Les fonctions sd_bus_error_set(), sd_bus_error_setf(), et sd_bus_error_set_const() renvoient toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur négative semblable à errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv(), renvoient 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur négative semblable à errno correspondant au paramètre error sinon. Si une erreur se produit en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera renvoyée. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

La fonction sd_bus_error_get_errno() renvoie false lorsque e est NULL, et une valeur errno positive mappée à partir de e->name sinon.

Les fonctions sd_bus_error_copy() et sd_bus_error_move() renvoient une valeur d'erreur négative convertie de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

La fonction sd_bus_error_is_set() renvoie une valeur non nulle lorsque e et le champ name ne sont pas NULL, zéro sinon.

Les fonctions sd_bus_error_has_name(), sd_bus_error_has_names(), et sd_bus_error_has_names_sentinel() renvoient une valeur non nulle lorsque e n'est pas NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Erreurs

La valeur de retour peut indiquer les problèmes suivants lors de l'invocation de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lors de l'appel à l'une des fonctions de définition d'erreur.

-ENOMEM

L'allocation de mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), et sd_bus_error_move() renverront une valeur négative convertie de type errno, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en valeur entière de type errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de type errno peut être renvoyée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Bonjour, Monde !\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, renvoyer le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et propager également la valeur errno
   * que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Impossible d'écrire dans le descripteur de fichier %i : %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
