SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3) sd_bus_message_get_monotonic_usec SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3)

NOM

sd_bus_message_get_monotonic_usec, sd_bus_message_get_realtime_usec, sd_bus_message_get_seqnum - Récupérer les horodatages de l'expéditeur et le numéro de séquence d'un message

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_get_monotonic_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_realtime_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_seqnum(sd_bus_message *message, uint64_t *seqnum);

DESCRIPTION

sd_bus_message_get_monotonic_usec() renvoie l'horodatage monotone du moment où le message a été envoyé. Cette valeur est en microsecondes depuis l'époque de CLOCK_MONOTONIC, voir clock_gettime(2) pour les détails.

De même, sd_bus_message_get_realtime_usec() renvoie l'horodatage temps réel (horloge murale) du moment où le message a été envoyé. Cette valeur est en microsecondes depuis le 1er janvier 1970, c'est-à-dire dans l'horloge CLOCK_REALTIME.

sd_bus_message_get_seqnum() renvoie le numéro de séquence du message assigné par le noyau. Le noyau assigne un numéro de séquence global, monotoniquement croissant, à tous les messages transmis sur le système local, au moment où le message a été envoyé. Ce numéro de séquence est utile pour déterminer l'ordre d'envoi des messages, même entre différents bus du système local. Le numéro de séquence combiné à l'identifiant de démarrage du système (tel que renvoyé par sd_id128_get_boot(3)) est un identifiant global unique approprié pour les messages de bus.

Notez que l'ordre d'envoi et l'ordre de réception des messages peuvent différer, en particulier pour les messages de diffusion (broadcast). Cela signifie que le numéro de séquence et les horodatages des messages qu'un client lit ne sont pas nécessairement croissants de manière monotone.

Ces horodatages et le numéro de séquence sont attachés à chaque message par le noyau et ne peuvent pas être manipulés par l'expéditeur.

Notez que ces horodatages ne sont disponibles que sur certains transports de bus, et seulement après que le support pour ceux-ci a été négocié avec l'appel sd_bus_negotiate_timestamp(3).

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de type errno.

En cas de succès, l'horodatage ou le numéro de séquence est renvoyé dans la variable entier non signé de 64 bits spécifiée.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

-ENODATA

Aucune information d'horodatage ou de numéro de séquence n'est attachée au message passé. Cette erreur est renvoyée si le transport sous-jacent ne supporte pas l'horodatage ou l'attribution de numéros de séquence, ou si cette fonctionnalité n'a pas été négociée avec sd_bus_negotiate_timestamp(3).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dès les premières phases du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_message_get_monotonic_usec(), sd_bus_message_get_realtime_usec(), et sd_bus_message_get_seqnum() ont été ajoutées dans la version 209.
