sd_bus_message_get_auto_start(3)

SD_BUS_MESSAGE_SET_EXPECT_REPLY(3) sd_bus_message_set_expect_reply SD_BUS_MESSAGE_SET_EXPECT_REPLY(3)

NOM

sd_bus_message_set_expect_reply, sd_bus_message_get_expect_reply, sd_bus_message_set_auto_start, sd_bus_message_get_auto_start, sd_bus_message_set_allow_interactive_authorization, sd_bus_message_get_allow_interactive_authorization - Définir et interroger les métadonnées des messages du bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_set_expect_reply(sd_bus_message *message, int b);

int sd_bus_message_get_expect_reply(sd_bus_message *message);

int sd_bus_message_set_auto_start(sd_bus_message *message, int b);

int sd_bus_message_get_auto_start(sd_bus_message *message);

int sd_bus_message_set_allow_interactive_authorization(sd_bus_message *message, int b);

int sd_bus_message_get_allow_interactive_authorization(sd_bus_message *message);

DESCRIPTION

sd_bus_message_set_expect_reply() définit ou efface le drapeau NO_REPLY_EXPECTED sur le message m. Ce drapeau n'a de pertinence que pour les messages d'appel de méthode et est utilisé pour spécifier qu'aucune réponse de retour de méthode ou d'erreur n'est attendue. Il est ignoré pour les autres types. Ainsi, pour un message d'appel de méthode, appeler

sd_bus_message_set_expect_reply(..., 0)

définit le drapeau et supprime la réponse.

sd_bus_message_get_expect_reply() vérifie si le drapeau NO_REPLY_EXPECTED est défini sur le message m. Il retournera une valeur positive s'il n'est pas défini, et zéro s'il l'est.

sd_bus_message_set_auto_start() définit ou efface le drapeau NO_AUTO_START sur le message m. Lorsque le drapeau est défini, le bus ne doit pas lancer de propriétaire pour le nom de destination en réponse à ce message. Appeler

sd_bus_message_set_auto_start(..., 0)

définit le drapeau.

sd_bus_message_get_auto_start() vérifie si le drapeau NO_AUTO_START est défini sur le message m. Il retournera une valeur positive s'il n'est pas défini, et zéro s'il l'est.

sd_bus_message_set_allow_interactive_authorization() définit ou efface le drapeau ALLOW_INTERACTIVE_AUTHORIZATION sur le message m. La définition de ce drapeau informe le destinataire que l'appelant est prêt à attendre une autorisation interactive via polkit ou un framework similaire. Notez que la définition de ce drapeau ne garantit pas que le destinataire effectuera réellement une autorisation interactive. De plus, assurez-vous de définir un délai d'attente de message approprié lors de l'utilisation de ce drapeau, car l'autorisation interactive pourrait potentiellement prendre beaucoup de temps car elle dépend de l'entrée utilisateur. Si b est non nul, le drapeau est défini.

sd_bus_message_get_allow_interactive_authorization() vérifie si le drapeau ALLOW_INTERACTIVE_AUTHORIZATION est défini sur le message m. Il retournera un entier positif si le drapeau est défini. Sinon, il retournera zéro.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre message est NULL.

-EPERM

Le message message est scellé lors de la tentative de définition d'un drapeau.

Le message message est de type incorrect.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd. 

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr en multithreading. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_message_set_expect_reply(), sd_bus_message_get_expect_reply(), sd_bus_message_set_auto_start(), et sd_bus_message_get_auto_start() ont été ajoutées dans la version 240.

sd_bus_message_set_allow_interactive_authorization() et sd_bus_message_get_allow_interactive_authorization() ont été ajoutées dans la version 246.
