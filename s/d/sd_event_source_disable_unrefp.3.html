sd_event_source_disable_unrefp(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_SOURCE_UNREF(3) sd_event_source_unref SD_EVENT_SOURCE_UNREF(3)

NOM

sd_event_source_unref, sd_event_source_unrefp, sd_event_source_ref, sd_event_source_disable_unref, sd_event_source_disable_unrefp - Augmenter ou diminuer les compteurs de références des sources d'événements

SYNTAXE

#include <systemd/sd-event.h>

sd_event_source* sd_event_source_unref(sd_event_source *source);

void sd_event_source_unrefp(sd_event_source **source);

sd_event_source* sd_event_source_ref(sd_event_source *source);

sd_event_source* sd_event_source_disable_unref(sd_event_source *source);

void sd_event_source_disable_unrefp(sd_event_source **source);

DESCRIPTION

sd_event_source_unref() peut être utilisée pour décrémenter de un le compteur de références interne de l'objet source d'événement spécifié par source. Le compteur de références est initialement défini à un, lorsque la source d'événement est créée avec des appels tels que sd_event_add_io(3) ou sd_event_add_time(3). Lorsque le compteur de références atteint zéro, l'objet est détaché de l'objet de boucle d'événements et détruit.

sd_event_source_unrefp() est similaire à sd_event_source_unref() mais prend un pointeur vers un pointeur vers un objet sd_event_source. Cet appel est utile en conjonction avec l'attribut Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_event_source_ref() peut être utilisée pour incrémenter de un le compteur de références interne de l'objet source d'événement spécifié par source.

sd_event_source_unref(), sd_bus_creds_unrefp() et sd_bus_creds_ref() n'exécutent aucune opération si l'objet source d'événement passé est NULL.

Notez que les objets sources d'événements restent actifs et peuvent être dispatchés tant que leur compteur de références est supérieur à zéro. Afin de libérer une référence d'une source d'événement et de s'assurer que la fonction de gestionnaire de source d'événement associée n'est plus appelée, il est recommandé de combiner un appel à sd_event_source_unref() avec un appel préalable à sd_event_source_set_enabled() avec SD_EVENT_OFF ou d'appeler sd_event_source_disable_unref(), voir ci-dessous.

sd_event_source_disable_unref() combine un appel à sd_event_source_set_enabled() avec SD_EVENT_OFF avec sd_event_source_unref(). Cela garantit que la source est désactivée avant que la référence locale à celle-ci ne soit perdue. Le paramètre source est autorisé à être NULL.

sd_event_source_disable_unrefp() est similaire à sd_event_source_unrefp(), mais désactive en plus la source d'abord. Cet appel est utile en conjonction avec l'attribut Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

VALEUR RENVOYÉE

sd_event_source_unref() et sd_event_source_disable_unref() renvoient toujours NULL. sd_event_source_ref() renvoie toujours l'objet source d'événement passé en paramètre.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que depuis une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_source_unref(), sd_event_source_unrefp() et sd_event_source_ref() ont été ajoutées dans la version 229.

sd_event_source_disable_unref() et sd_event_source_disable_unrefp() ont été ajoutées dans la version 243.
