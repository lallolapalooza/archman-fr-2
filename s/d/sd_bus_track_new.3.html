SD_BUS_TRACK_NEW(3) sd_bus_track_new SD_BUS_TRACK_NEW(3)

NOM

sd_bus_track_new, sd_bus_track_ref, sd_bus_track_unref, sd_bus_track_unrefp, sd_bus_track_set_recursive, sd_bus_track_get_recursive, sd_bus_track_get_bus, sd_bus_track_get_userdata, sd_bus_track_set_userdata - Suivre les pairs du bus

SYNOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_track_handler_t)(sd_bus_track *track, void *userdata);

int sd_bus_track_new(sd_bus* bus, sd_bus_track** ret, sd_bus_track_handler_t handler, void* userdata);

sd_bus_track *sd_bus_track_ref(sd_bus_track *t);

sd_bus_track *sd_bus_track_unref(sd_bus_track *t);

void sd_bus_track_unrefp(sd_bus_track **t);

int sd_bus_track_get_recursive(sd_bus_track *t);

int sd_bus_track_set_recursive(sd_bus_track *t, int b);

sd_bus* sd_bus_track_get_bus(sd_bus_track *t);

void* sd_bus_track_get_userdata(sd_bus_track *t);

void* sd_bus_track_set_userdata(sd_bus_track *t, void *userdata);

DESCRIPTION

sd_bus_track_new() crée un nouvel objet de suivi de pairs du bus. L'objet est alloué pour le bus spécifié et retourné dans le paramètre *ret. Après utilisation, l'objet doit être libéré en abandonnant la référence acquise avec sd_bus_track_unref() (voir ci-dessous). Un objet de suivi de pairs du bus peut être utilisé pour suivre les pairs sur un bus IPC spécifique, pour les cas où les pairs utilisent un ou plusieurs objets locaux, afin de contrôler le cycle de vie des objets locaux et de s'assurer qu'ils restent disponibles tant que les pairs qui en ont besoin sont présents, et qu'ils sont désactivés (et éventuellement détruits) dès que tous les pairs pertinents ont disparu. Chaque objet de suivi de pairs du bus peut être utilisé pour suivre zéro, un ou plusieurs pairs à un moment donné. Les références aux pairs du bus spécifiques sont ajoutées via sd_bus_track_add_name(3) ou sd_bus_track_add_sender(). Elles peuvent être supprimées via sd_bus_track_remove_name() et sd_bus_track_remove_sender(). Alternativement, les références aux pairs sont supprimées automatiquement lorsqu'ils se déconnectent du bus. Si handler n'est pas NULL, il peut spécifier une fonction qui sera appelée chaque fois que la dernière référence sera abandonnée, que ce soit explicitement via sd_bus_track_remove_name() ou implicitement parce que le pair s'est déconnecté du bus. Le dernier argument userdata peut être utilisé pour attacher un pointeur de données utilisateur générique à l'objet. Ce pointeur est passé au rappel du gestionnaire lorsqu'il est appelé.

sd_bus_track_ref() crée une nouvelle référence à un objet de suivi de pairs du bus. Cet objet ne sera pas détruit tant que sd_bus_track_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, l'objet spécifié ne peut plus être utilisé, les appels ultérieurs à sd_bus_track_ref() ou sd_bus_track_unref() sur le même objet sont illégaux.

sd_bus_track_unref() détruit une référence à un objet de suivi de pairs du bus.

sd_bus_track_unrefp() est similaire à sd_bus_track_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_track. Cet appel est utile en conjonction avec l'attribut Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_bus_track_ref(), sd_bus_track_unref() et sd_bus_track_unrefp() n'effectuent aucune opération si l'objet de suivi de pairs du bus passé est NULL.

Les objets de suivi de pairs du bus peuvent exister dans deux modes : par défaut, ils fonctionnent en mode non récursif, mais peuvent éventuellement être basculés en mode récursif. En mode non récursif par défaut, un pair est soit suivi, soit non suivi. Dans ce mode, l'appel à sd_bus_track_add_name() plusieurs fois de suite pour le même pair est entièrement équivalent à un seul appel, car l'appel ajoute le pair à l'ensemble des pairs suivis si nécessaire, et n'effectue aucune opération si le pair est déjà suivi. Un seul appel à sd_bus_track_remove_name() supprime à nouveau la référence au pair, quel que soit le nombre de fois où sd_bus_track_add_name() a été appelé auparavant. En mode récursif, le nombre de fois où sd_bus_track_add_name() est appelé pour le même nom de pair est compté et sd_bus_track_remove_name() doit être appelé le même nombre de fois avant que le pair ne soit plus suivi, à l'exception du cas où le pair suivi disparaît du bus, auquel cas le comptage est sans importance et le suivi du pair spécifique est immédiatement supprimé. sd_bus_track_get_recursive() peut être utilisé pour déterminer si l'objet de suivi de pairs du bus fonctionne en mode récursif. sd_bus_track_set_recursive() peut être utilisé pour activer ou désactiver le mode récursif. Par défaut, un objet de suivi de pairs du bus fonctionne en mode non récursif, et sd_bus_track_get_recursive() pour un objet nouvellement alloué renvoie donc une valeur égale à zéro. Utilisez sd_bus_track_set_recursive() pour activer le mode récursif, juste après l'allocation. Il prend un argument booléen pour activer ou désactiver le mode récursif. Notez que les objets de suivi pour lesquels sd_bus_track_add_name() a déjà été appelé au moins une fois (et qui suivent donc déjà un ou plusieurs pairs) ne peuvent plus être basculés du mode récursif au mode non récursif.

sd_bus_track_get_bus() renvoie l'objet bus auquel appartient l'objet de suivi de pairs du bus. Il renvoie l'objet bus initialement passé à sd_bus_track_new() lors de l'allocation de l'objet.

sd_bus_track_get_userdata() renvoie le pointeur de données utilisateur générique défini sur l'objet de suivi de pairs du bus au moment de sa création avec sd_bus_track_new() ou plus tard, avec sd_bus_track_set_userdata().

VALEUR DE RETOUR

En cas de succès, sd_bus_track_new() et sd_bus_track_set_recursive() retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

sd_bus_track_ref() retourne toujours l'argument.

sd_bus_track_unref() retourne toujours NULL.

sd_bus_track_get_recursive() retourne 0 si le mode non récursif est sélectionné (par défaut), et supérieur à 0 si le mode récursif est sélectionné. En cas d'échec, un code d'erreur négatif de type errno est retourné.

sd_bus_track_get_bus() retourne l'objet bus associé à l'objet de suivi de pairs du bus.

sd_bus_track_get_userdata() retourne le pointeur de données utilisateur générique associé à l'objet de suivi de pairs du bus. sd_bus_track_set_userdata() retourne le pointeur de données utilisateur précédemment défini.

PROPRIÉTÉ DES RÉFÉRENCES

La fonction sd_bus_track_new() crée un nouvel objet et l'appelant en possède la seule référence. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_track_unref().

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EBUSY

Des pairs du bus ont déjà été ajoutés à l'objet de suivi de pairs du bus et sd_bus_track_set_recursive() a été appelé pour changer le mode de suivi.

-EINVAL

Le paramètre spécifié est invalide (NULL dans le cas des paramètres de sortie).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que dès les premières phases du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

La fonctionnalité de suivi des pairs du bus a été introduite dans systemd v240.

sd_bus_track_new(3) — systemd 258.2

NAME

sd_bus_track_new, sd_bus_track_handler_t, sd_bus_track_ref, sd_bus_track_unref, sd_bus_track_unrefp, sd_bus_track_get_recursive, sd_bus_track_set_recursive, sd_bus_track_get_bus, sd_bus_track_get_userdata, sd_bus_track_set_userdata - créer et gérer des objets de suivi d'événements du bus

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_track_new(sd_bus *bus, sd_bus_track **track, sd_bus_track_handler_t handler, void *userdata);
typedef int (*sd_bus_track_handler_t)(sd_bus_track *track, uint64_t seq, int flags, void *userdata);
sd_bus_track *sd_bus_track_ref(sd_bus_track *track);
void sd_bus_track_unref(sd_bus_track *track);
sd_bus_track **sd_bus_track_unrefp(sd_bus_track **track);
int sd_bus_track_get_recursive(sd_bus_track *track);
int sd_bus_track_set_recursive(sd_bus_track *track, int recursive);
sd_bus *sd_bus_track_get_bus(sd_bus_track *track);
void *sd_bus_track_get_userdata(sd_bus_track *track);
int sd_bus_track_set_userdata(sd_bus_track *track, void *userdata);

DESCRIPTION

sd_bus_track_new() crée un nouvel objet de suivi d'événements du bus, associé au bus bus. La fonction de rappel handler sera appelée chaque fois qu'un nouvel événement d'objet se produira sur le bus, jusqu'à ce que le suivi soit désactivé ou que l'objet de suivi soit détruit. Les arguments seq et flags passés à la fonction de rappel sont des numéros de séquence d'événements et des drapeaux (voir sd_bus_event_sink(3)). L'argument userdata est un pointeur opaque vers les données définies par l'utilisateur, qui sera passé à la fonction de rappel.

Pour chaque événement d'objet sur le bus, sd_bus_track_new() enregistrera les informations sur l'objet pour permettre le suivi de ses événements ultérieurs. Le suivi d'un objet se fait en appelant sd_bus_track_add_name. Il est possible d'enregistrer le suivi de manière récursive, en appelant sd_bus_track_set_recursive().

sd_bus_track_ref() incrémente le compteur de références de l'objet de suivi track. sd_bus_track_unref() décrémente le compteur de références de l'objet de suivi track. Si le compteur de références atteint zéro, l'objet de suivi est détruit.

sd_bus_track_unrefp() est similaire à sd_bus_track_unref(), mais il prend un pointeur vers un pointeur sd_bus_track *, met ce pointeur à NULL après avoir décrémenté le compteur, et le retourne.

sd_bus_track_get_recursive() retourne la valeur booléenne indiquant si le suivi récursif est activé pour le suivi track.

sd_bus_track_set_recursive() active ou désactive le suivi récursif pour le suivi track, selon la valeur de recursive (qui est vraie si non nulle).

sd_bus_track_get_bus() retourne le bus associé au suivi track.

sd_bus_track_get_userdata() retourne les données utilisateur associées au suivi track.

sd_bus_track_set_userdata() définit les données utilisateur associées au suivi track.

RETURN VALUE

sd_bus_track_new() retourne 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. sd_bus_track_ref() retourne toujours le pointeur track passé en argument.

sd_bus_track_get_recursive() retourne 1 si le suivi récursif est activé, et 0 sinon.

sd_bus_track_set_recursive(), sd_bus_track_get_bus(), sd_bus_track_get_userdata(), et sd_bus_track_set_userdata() retournent des valeurs appropriées ou NULL.

REFERENCE OWNERSHIP

Dans le cas de sd_bus_track_new(), le nouveau suivi est possédé par l'appelant. Dans le cas de sd_bus_track_ref(), le nouveau suivi est possédé par l'appelant.

Dans le cas de sd_bus_track_unref(), le suivi est possédé par l'appelant. Dans le cas de sd_bus_track_unrefp(), le suivi est possédé par l'appelant.

NOTES

Les fonctions sd_bus_track_new(), sd_bus_track_ref(), sd_bus_track_unref(), sd_bus_track_unrefp(), sd_bus_track_get_recursive(), sd_bus_track_set_recursive(), sd_bus_track_get_bus(), sd_bus_track_get_userdata() et sd_bus_track_set_userdata() sont disponibles depuis systemd version 232.

La fonction de rappel sd_bus_track_handler_t est un pointeur de fonction qui est utilisé pour gérer les événements d'objet du bus. Elle reçoit un pointeur vers l'objet de suivi, le numéro de séquence de l'événement, des drapeaux et les données utilisateur.
