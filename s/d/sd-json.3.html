NOM

sd-json - API pour manipuler les objets JSON

SYNTAXE

#include <systemd/sd-json.h>

pkg-config --cflags --libs libsystemd

DESCRIPTION

sd-json.h fait partie de libsystemd(3) et fournit des API pour analyser, générer, formater et manipuler des objets JSON.

La structure de données centrale de l'API est JsonVariant qui encapsule un objet JSON, un tableau, une chaîne, un booléen, un nombre ou une valeur nulle. Ces structures de données sont principalement considérées comme immuables après leur construction (c'est-à-dire que leur contenu ne changera pas, mais certaines métadonnées le pourraient, tels que les compteurs de références).

Les API se divisent globalement en cinq catégories :

• API pour opérer directement avec les objets JsonVariant, dans le namespace sd_json_variant*.
• API pour construire des objets JSON complexes, dans le namespace sd_json_build*.
• API pour mapper les objets JsonVariant et leurs champs aux champs correspondants dans les structures C, dans le namespace sd_json_dispatch*.
• API pour convertir une représentation sous forme de chaîne d'un objet JSON en un objet JsonVariant, dans le namespace sd_json_parse*.
• API pour convertir un objet JsonVariant en sa représentation sous forme de chaîne, dans le namespace sd_json_format*.

Cette bibliothèque JSON encodera en interne les nombres entiers JSON dans la plage INT64_MIN...UINT64_MAX en entiers signés ou non signés natifs 64 bits, et les reproduira sans perte de précision. Les nombres non entiers sont stockés dans des nombres à virgule flottante IEEE 64 bits.

Si les fonctions renvoient des tableaux de chaînes, ceux-ci sont généralement terminés par NULL et doivent être libérés par l'appelant avec l'appel free(3) de libc après utilisation, y compris les chaînes qu'ils référencent. De même, les chaînes individuelles renvoyées doivent également être libérées.

À titre d'exception spéciale, au lieu d'un tableau de chaînes vide, NULL peut être renvoyé, ce qui doit être traité comme équivalent à un tableau de chaînes vide.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
