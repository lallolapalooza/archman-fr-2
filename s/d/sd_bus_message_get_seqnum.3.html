SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3) sd_bus_message_get_monotonic_usec SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3)

NOM

sd_bus_message_get_monotonic_usec, sd_bus_message_get_realtime_usec, sd_bus_message_get_seqnum - Récupérer les horodatages de l'expéditeur et le numéro de séquence d'un message

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_get_monotonic_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_realtime_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_seqnum(sd_bus_message *message, uint64_t *seqnum);

DESCRIPTION

sd_bus_message_get_monotonic_usec() renvoie l'horodatage monotone du moment où le message a été envoyé. Cette valeur est en microsecondes depuis l'époque de CLOCK_MONOTONIC, voir clock_gettime(2) pour plus de détails.

De même, sd_bus_message_get_realtime_usec() renvoie l'horodatage en temps réel (horloge murale) du moment où le message a été envoyé. Cette valeur est en microsecondes depuis le 1er janvier 1970, c'est-à-dire dans l'horloge CLOCK_REALTIME.

sd_bus_message_get_seqnum() renvoie le numéro de séquence attribué par le noyau au message. Le noyau attribue un numéro de séquence global et monotone à tous les messages transmis sur le système local, au moment où le message a été envoyé. Ce numéro de séquence est utile pour déterminer l'ordre d'envoi des messages, même entre différents bus du système local. Le numéro de séquence combiné à l'identifiant de démarrage du système (tel que renvoyé par sd_id128_get_boot(3)) est un identifiant globalement unique approprié pour les messages de bus.

Notez que l'ordre d'envoi et l'ordre de réception des messages peuvent différer, en particulier pour les messages de diffusion. Cela signifie que le numéro de séquence et les horodatages des messages lus par un client ne sont pas nécessairement monotones.

Ces horodatages et le numéro de séquence sont attachés à chaque message par le noyau et ne peuvent pas être manipulés par l'expéditeur.

Notez que ces horodatages ne sont disponibles que sur certains transports de bus, et uniquement après que leur prise en charge a été négociée avec l'appel sd_bus_negotiate_timestamp(3).

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

En cas de succès, l'horodatage ou le numéro de séquence est renvoyé dans la variable entière non signée de 64 bits spécifiée.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

-ENODATA

Aucune information d'horodatage ou de numéro de séquence n'est attachée au message passé. Cette erreur est renvoyée si le transport sous-jacent ne prend pas en charge l'horodatage ou l'attribution de numéros de séquence, ou si cette fonctionnalité n'a pas été négociée avec sd_bus_negotiate_timestamp(3).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_message_get_monotonic_usec(), sd_bus_message_get_realtime_usec(), et sd_bus_message_get_seqnum() ont été ajoutés dans la version 209.
