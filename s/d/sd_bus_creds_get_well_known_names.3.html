DESCRIPTION

Ces fonctions retournent des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les identifiants du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les identifiants d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les identifiants du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les identifiants de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GID supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée à des fins autres qu'explicatives, en particulier, elle ne doit pas être utilisée pour des décisions relatives à la sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

Ces fonctions sont utilisées pour obtenir les authentifications (informations d'identification) d'un processus local ou d'un pair de connexion D-Bus.

Le paramètre c est un objet sd_bus_creds, obtenu via sd_bus_creds_new_from_pid(3), ou par un appel à sd_bus_get_peer_creds(3).

Les fonctions disponibles sont les suivantes :

sd_bus_creds_get_pid()
récupère l'ID du processus.
sd_bus_creds_get_tid()
récupère l'ID du thread. Pour la plupart des processus, ceci est identique à l'ID du processus.
sd_bus_creds_get_ppid()
récupère l'ID du processus parent.
sd_bus_creds_get_uid()
récupère l'UID effectif du processus.
sd_bus_creds_get_euid()
récupère l'UID effectif du processus.
sd_bus_creds_get_suid()
récupère l'UID sauvegardé du processus.
sd_bus_creds_get_fsuid()
récupère l'UID du système de fichiers du processus.
sd_bus_creds_get_gid()
récupère le GID effectif du processus.
sd_bus_creds_get_egid()
récupère le GID effectif du processus.
sd_bus_creds_get_sgid()
récupère le GID sauvegardé du processus.
sd_bus_creds_get_fsgid()
récupère le GID du système de fichiers du processus.
sd_bus_creds_get_supplementary_gids()
récupère les GID supplémentaires du processus.
sd_bus_creds_get_comm()
récupère le nom du processus tel qu'affiché dans ps(1) et similaire.
sd_bus_creds_get_tid_comm()
récupère le nom du thread tel qu'affiché dans ps(1) et similaire.
sd_bus_creds_get_exe()
récupère le nom du chemin d'accès complet du binaire exécutable. Ceci est obtenu à partir de /proc/pid/exe. Les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est retourné.
sd_bus_creds_get_cmdline()
récupère un tableau d'arguments de ligne de commande (tel que stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est retourné.
sd_bus_creds_get_cgroup()
récupère le chemin du groupe de contrôle. Voir Control Groups v2[1].
sd_bus_creds_get_unit()
récupère le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, retourne -ENXIO.
sd_bus_creds_get_user_unit()
récupère le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, retourne -ENXIO.
sd_bus_creds_get_slice()
récupère la tranche systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). Similairement, sd_bus_creds_get_user_slice() récupère la tranche systemd du processus, dans l'instance utilisateur de systemd.
sd_bus_creds_get_session()
récupère l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un ou deux processus "stub". Les processus utilisateur peuvent être lancés depuis leur gestionnaire utilisateur systemd, par exemple des applications graphiques lancées via l'activation DBus, ainsi que des processus de service partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, retourne -ENXIO.
sd_bus_creds_get_owner_uid()
récupère l'UID numérique (identifiant utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, retourne -ENXIO.
sd_bus_creds_has_effective_cap()
vérifie si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle ne l'était pas, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).
sd_bus_creds_has_permitted_cap()
est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités permises.
sd_bus_creds_has_inheritable_cap()
est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités héritables.
sd_bus_creds_has_bounding_cap()
est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités de limitation.
sd_bus_creds_get_selinux_context()
récupère le contexte de sécurité SELinux (label) du processus.
sd_bus_creds_get_audit_session_id()
récupère l'identifiant de session d'audit du processus. Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
sd_bus_creds_get_audit_login_uid()
récupère l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur "responsable" de la session). Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
sd_bus_creds_get_tty()
récupère le TTY de contrôle, sans le préfixe "/dev/". Retourne -ENXIO pour les processus qui n'ont pas de TTY de contrôle.
sd_bus_creds_get_unique_name()
récupère le nom unique D-Bus. Voir The D-Bus specification[2].
sd_bus_creds_get_well_known_names()
récupère l'ensemble des noms connus D-Bus. Voir The D-Bus specification[2].
sd_bus_creds_get_description()
récupère un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus du même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).
sd_bus_creds_get_pidfd_dup()
renvoie un nouveau descripteur de fichier pour le processus donné. Ceci est une alternative sûre pour obtenir un descripteur de fichier pour un processus en cours d'exécution par rapport à l'utilisation de /proc/pid/exe, car cela garantit que le descripteur de fichier pointe vers le bon exécutable même si l'exécutable est mis à jour ou supprimé pendant l'exécution. Si le processus a déjà un pidfd associé, il est dupliqué et retourné. Sinon, un nouveau pidfd est créé et retourné.

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse là comme une adresse d'une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devrait pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse là comme une adresse d'un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devrait pas être libéré ou modifié par l'appelant.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet d'authentification c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera retourné par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une tranche systemd, ou d'une session logind. Il sera retourné par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas lancés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

sd_bus_creds_get_well_known_names.3

NOM

sd_bus_creds_get_well_known_names - Récupérer les noms bien connus associés aux informations d'identification du bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_creds_get_well_known_names(sd_bus_creds *creds, const char **names);

DESCRIPTION

La fonction sd_bus_creds_get_well_known_names() récupère la liste des noms bien connus (voir sd_bus_get_unique_name(3)) associés aux informations d'identification du bus données dans creds. Les noms sont renvoyés sous forme d'un tableau de chaînes de caractères se terminant par un pointeur NULL dans le paramètre names.

Le tableau pointé par names et les chaînes qu'il contient sont alloués par la fonction et doivent être libérés par l'appelant en utilisant sd_bus_creds_unref(3). Les noms eux-mêmes sont des copies des noms existants et ne doivent pas être modifiés.

Cette fonction ne fonctionne que si les informations d'identification creds ont été obtenues en utilisant sd_bus_get_creds(3) ou sd_bus_get_creds_for_pid(3) avec l'indicateur SD_BUS_CREDS_ALL ou SD_BUS_CREDS_WELL_KNOWN_NAMES.

VALEUR DE RETOUR

En cas de succès, sd_bus_creds_get_well_known_names() renvoie un nombre positif. Si le tableau de noms est vide, elle renvoie 0.

En cas d'échec, elle renvoie un nombre négatif correspondant à un code d'erreur.

EXEMPLE DE CODE

L'exemple de code suivant montre comment récupérer et imprimer les noms bien connus des informations d'identification du bus : 


    sd_bus_creds *creds = NULL;
    const char **names = NULL;
    int r;

    r = sd_bus_get_creds(SIGRTMIN, &creds);
    if (r < 0) {
        fprintf(stderr, "Impossible d'obtenir les informations d'identification : %s\n", strerror(-r));
        goto finish;
    }

    r = sd_bus_creds_get_well_known_names(creds, &names);
    if (r < 0) {
        fprintf(stderr, "Impossible d'obtenir les noms bien connus : %s\n", strerror(-r));
        goto finish;
    }

    if (r == 0) {
        printf("Aucun nom bien connu trouvé.\n");
    } else {
        printf("Noms bien connus :\n");
        for (int i = 0; names[i] != NULL; i++) {
            printf("  %s\n", names[i]);
        }
    }

finish:
    sd_bus_creds_unref(creds);
    return r < 0 ? 1 : 0;
