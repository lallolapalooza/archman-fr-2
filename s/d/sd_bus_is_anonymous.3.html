SD_BUS_SET_DESCRIPTION(3) sd_bus_set_description SD_BUS_SET_DESCRIPTION(3)

NOM

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_description(sd_bus *bus, const char *description);

int sd_bus_get_description(sd_bus *bus, const char **description);

int sd_bus_set_anonymous(sd_bus *bus, int b);

int sd_bus_is_anonymous(sd_bus *bus);

int sd_bus_set_trusted(sd_bus *bus, int b);

int sd_bus_is_trusted(sd_bus *bus);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, int b);

int sd_bus_get_allow_interactive_authorization(sd_bus *bus);

int sd_bus_get_scope(sd_bus *bus, const char **scope);

int sd_bus_get_tid(sd_bus *bus, pid_t *tid);

int sd_bus_get_unique_name(sd_bus *bus, const char **unique);

DESCRIPTION

sd_bus_set_description() définit la chaîne de description utilisée dans la journalisation sur la chaîne spécifiée. La chaîne est copiée en interne et libérée lorsque l'objet bus est désalloué. L'argument description peut être NULL, auquel cas la description est supprimée. Cette fonction doit être appelée avant que le bus ne soit démarré.

sd_bus_get_description() renvoie une chaîne de description dans description. Cette chaîne peut avoir été précédemment définie avec sd_bus_set_description() ou sd_bus_open_with_description(3) ou similaire. Si elle n'est pas définie de cette manière, une chaîne par défaut telle que « system » ou « user » sera renvoyée pour les bus système ou utilisateur, et -ENXIO sinon.

sd_bus_set_anonymous() active ou désactive l'« authentification anonyme », c'est-à-dire l'absence d'authentification, du pair du bus. Cette fonction doit être appelée avant que le bus ne soit démarré. Voir la section Mécanismes d'authentification D-Bus[1] de la spécification D-Bus pour plus de détails.

sd_bus_is_anonymous() renvoie vrai si la connexion bus autorise l'authentification anonyme (au sens décrit dans le paragraphe précédent).

sd_bus_set_trusted() définit l'état « trusted » (de confiance) sur l'objet bus. Si vrai, toutes les connexions sur le bus sont considérées comme fiables et l'accès à toutes les méthodes privilégiées et non privilégiées est accordé. Cette fonction doit être appelée avant que le bus ne soit démarré.

sd_bus_is_trusted() renvoie vrai si la connexion bus est considérée comme fiable (au sens décrit dans le paragraphe précédent).

sd_bus_set_allow_interactive_authorization() active ou désactive l'autorisation interactive pour les appels de méthode. Si vrai, les messages sont marqués avec le drapeau ALLOW_INTERACTIVE_AUTHORIZATION spécifié par la spécification D-Bus[2], informant le côté récepteur que l'appelant est prêt à attendre l'autorisation interactive, ce qui pourrait prendre un temps considérable pour se terminer. Si ce drapeau est défini, l'utilisateur peut être invité à saisir des mots de passe ou une confirmation via polkit[3] ou un framework similaire.

sd_bus_get_allow_interactive_authorization() renvoie vrai si l'autorisation interactive est autorisée et faux sinon.

sd_bus_get_scope() stocke la portée de l'objet bus donné dans scope. La portée du bus système est « system ». La portée d'un bus de session utilisateur est « user ». Si l'objet bus donné n'est ni le bus système ni un bus de session utilisateur, sd_bus_get_scope() renvoie une erreur.

sd_bus_get_tid() stocke l'identifiant du thread noyau du thread associé à l'objet bus donné dans tid. Si bus est un objet bus par défaut obtenu en appelant l'une des fonctions de la famille sd_bus_default(3), il stocke l'identifiant du thread dans lequel l'objet bus a été créé. Sinon, si l'objet bus est attaché à une boucle d'événements, il stocke l'identifiant du thread dans lequel l'objet boucle d'événements a été créé. Si bus n'est pas un objet bus par défaut et n'est pas attaché à une boucle d'événements, sd_bus_get_tid() renvoie une erreur.

sd_bus_get_unique_name() stocke le nom unique de l'objet bus sur le bus dans unique. Voir La spécification D-Bus[4] pour plus d'informations sur les noms de bus. Notez que l'appelant ne possède pas la chaîne stockée dans unique et ne doit pas la libérer.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier non négatif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un argument est invalide.

-ENOPKG

Le bus ne peut pas être résolu.

-EPERM

Le bus a déjà été démarré.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

-ENOMEM

Échec d'allocation de mémoire.

-ENODATA

L'objet bus passé à sd_bus_get_scope() n'était pas un bus système ou de session utilisateur.

Ajouté dans la version 246.

-ENXIO

L'objet bus passé à sd_bus_get_tid() n'était pas un objet bus par défaut et n'est pas attaché à une boucle d'événements.

L'objet bus passé à sd_bus_get_description() n'avait pas de description.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr en matière de multithreading. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_set_description(), sd_bus_get_description(), sd_bus_set_anonymous(), sd_bus_set_trusted(), sd_bus_set_allow_interactive_authorization(), et sd_bus_get_allow_interactive_authorization() ont été ajoutées dans la version 240.

sd_bus_is_anonymous(), sd_bus_is_trusted(), sd_bus_get_scope(), sd_bus_get_tid(), et sd_bus_get_unique_name() ont été ajoutées dans la version 246.
