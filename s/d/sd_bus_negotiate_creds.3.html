SD_BUS_NEGOTIATE_CREDS(3) sd_bus_negotiate_creds SD_BUS_NEGOTIATE_CREDS(3)

NOM

sd_bus_negotiate_fds, sd_bus_negotiate_timestamp, sd_bus_negotiate_creds, sd_bus_get_creds_mask - Contrôler la négociation des fonctionnalités sur les connexions de bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_negotiate_fds(sd_bus *bus, int b);

int sd_bus_negotiate_timestamp(sd_bus *bus, int b);

int sd_bus_negotiate_creds(sd_bus *bus, int b, uint64_t mask);

int sd_bus_get_creds_mask(sd_bus *bus, uint64_t *mask);

DESCRIPTION

sd_bus_negotiate_fds() contrôle si le passage de descripteurs de fichiers doit être négocié pour la connexion de bus spécifiée. Il prend un objet de bus et une valeur booléenne qui, lorsqu'elle est vraie, active le passage de descripteurs de fichiers, et, lorsqu'elle est fausse, le désactive. Notez que tous les transports et serveurs ne prennent pas en charge le passage de descripteurs de fichiers. En particulier, les transports réseau ne prennent généralement pas en charge le passage de descripteurs de fichiers. Pour savoir si le passage de descripteurs de fichiers est disponible après négociation, utilisez sd_bus_can_send(3) et passez SD_BUS_TYPE_UNIX_FD. Notez que le passage de descripteurs de fichiers est toujours activé pour l'envoi et la réception ou pour aucun des deux, mais jamais dans une seule direction. Par défaut, le passage de descripteurs de fichiers est négocié pour toutes les connexions.

sd_bus_negotiate_timestamp() contrôle si les horodatages implicites de l'expéditeur doivent être joints automatiquement à tous les messages entrants. Prend un objet de bus et une valeur booléenne qui, lorsqu'elle est vraie, active la journalisation des horodatages, et, lorsqu'elle est fausse, la désactive. Utilisez sd_bus_message_get_monotonic_usec(3), sd_bus_message_get_realtime_usec(3), sd_bus_message_get_seqnum(3) pour interroger les horodatages des messages entrants. Si la négociation est désactivée ou non prise en charge, ces appels échoueront avec -ENODATA. Notez qu'actuellement aucun transport ne prend en charge l'horodatage des messages. Par défaut, l'horodatage des messages n'est pas négocié pour les connexions.

sd_bus_negotiate_creds() contrôle si et quelles informations d'identification implicites de l'expéditeur doivent être jointes automatiquement à tous les messages entrants. Prend un objet de bus et une valeur booléenne indiquant s'il faut activer ou désactiver les parties d'identification encodées dans le masque de valeur de bits fourni. Notez que tous les transports ne prennent pas en charge la jointure des informations d'identification de l'expéditeur aux messages, ou ne prennent pas en charge tous les types de paramètres d'informations d'identification de l'expéditeur, ou peuvent les supprimer dans certaines circonstances pour des messages individuels. Spécifiquement, dbus1 ne prend en charge que SD_BUS_CREDS_UNIQUE_NAME. Les informations d'identification de l'expéditeur sont appropriées pour les décisions d'autorisation. Par défaut, seuls SD_BUS_CREDS_WELL_KNOWN_NAMES et SD_BUS_CREDS_UNIQUE_NAME sont activés. En fait, ces deux champs d'identification sont toujours envoyés et ne peuvent pas être désactivés.

sd_bus_get_creds_mask() renvoie l'ensemble des informations d'identification de l'expéditeur qui a été négocié pour être joint à tous les messages entrants dans mask. Cette valeur est une limite supérieure uniquement. Par conséquent, assurez-vous toujours de vérifier explicitement quelles informations d'identification sont jointes à un message spécifique avant de l'utiliser.

La fonction sd_bus_negotiate_fds() ne peut être appelée qu'avant que la connexion n'ait été démarrée avec sd_bus_start(3). Les fonctions sd_bus_negotiate_timestamp() et sd_bus_negotiate_creds() peuvent également être appelées après qu'une connexion ait été établie. Notez que, lors de l'opération sur une connexion partagée entre plusieurs composants du même programme (par exemple, via sd_bus_default(3)), il est fortement recommandé de n'activer que les champs de métadonnées supplémentaires par message, mais de ne jamais les désactiver à nouveau, afin de ne pas désactiver les fonctionnalités nécessaires à d'autres composants.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier non négatif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants:

-EPERM

La connexion de bus a déjà été démarrée.

-EINVAL

Un argument est invalide.

Ajouté dans la version 246.

-ENOPKG

Le bus ne peut pas être résolu.

Ajouté dans la version 246.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différente.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un fil d'exécution parallèle. Il est recommandé de n'effectuer les appels à setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_bus_negotiate_fds(), sd_bus_negotiate_timestamp() et sd_bus_negotiate_creds() ont été ajoutés dans la version 212.

sd_bus_get_creds_mask() a été ajouté dans la version 246.
