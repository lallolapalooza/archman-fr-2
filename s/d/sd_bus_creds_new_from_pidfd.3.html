DESCRIPTION

sd_bus_creds_new_from_pid() crée un nouvel objet d'identifiants et le remplit avec des informations sur le processus pid. Le pointeur vers cet objet sera stocké dans le pointeur ret. Notez que les objets d'identifiants peuvent également être créés et récupérés via sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) et sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() est identique à sd_bus_creds_new_from_pid(), mais prend un descripteur de fichier de PID plutôt qu'un PID numérique comme référence au processus. Voir pidfd_open(2).

Les informations qui seront stockées sont déterminées par creds_mask. Il peut contenir un sous-ensemble des constantes ORed SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, et SD_BUS_CREDS_PIDFD. Utilisez la valeur spéciale _SD_BUS_CREDS_ALL pour demander tous les champs pris en charge. La constante SD_BUS_CREDS_AUGMENT ne peut pas être ORed dans le masque pour les invocations de sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd().

Les champs peuvent être récupérés de l'objet d'identifiants en utilisant sd_bus_creds_get_pid(3) et d'autres fonctions qui correspondent directement aux constantes listées ci-dessus.

Un masque des champs qui ont été effectivement récupérés avec succès peut être obtenu avec sd_bus_creds_get_mask(). Si l'objet d'identifiants a été créé avec sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), il s'agira d'un sous-ensemble des champs demandés dans creds_mask.

Similaire à sd_bus_creds_get_mask(), la fonction sd_bus_creds_get_augmented_mask() retourne un masque de bits des champs. Le masque indique quels champs d'identifiants ont été récupérés de manière non atomique. Pour les objets d'identifiants créés via sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce masque sera identique au masque retourné par sd_bus_creds_get_mask(). Cependant, pour les objets d'identifiants récupérés via sd_bus_get_name_creds(), ce masque sera défini pour les champs d'identifiants qui n'ont pas pu être déterminés de manière atomique au moment de la connexion du pair, et qui ont été ajoutés ultérieurement en lisant des données d'identifiants augmentées depuis /proc/. De même, pour les objets d'identifiants récupérés via sd_bus_get_owner_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés de manière atomique au moment de la création du bus, mais qui ont été augmentés. De même, pour les objets d'identifiants récupérés via sd_bus_message_get_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés de manière atomique au moment de l'envoi du message, mais qui ont été augmentés. Le masque retourné par sd_bus_creds_get_augmented_mask() est toujours un sous-ensemble de (ou identique à) le masque retourné par sd_bus_creds_get_mask() pour le même objet. Cet dernier appel retourne donc tous les champs d'identifiants disponibles dans l'objet d'identifiants, le premier marque ensuite le sous-ensemble de ceux qui ont été augmentés. Notez que les champs augmentés ne conviennent pas aux décisions d'autorisation, car ils peuvent être récupérés à des moments différents, étant ainsi sujets à des courses. Par conséquent, les champs augmentés ne doivent être utilisés qu'à des fins d'information.

sd_bus_creds_ref() crée une nouvelle référence à l'objet d'identifiants c. Cet objet ne sera pas détruit tant que sd_bus_creds_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, c ne peut plus être utilisé, donc les appels ultérieurs à sd_bus_creds_ref(c) ou sd_bus_creds_unref(c) sont illégaux.

sd_bus_creds_unref() détruit une référence à c.

sd_bus_creds_unrefp() est similaire à sd_bus_creds_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_creds. Cet appel est utile en conjonction avec l'attribut de variable Clean-up[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_bus_creds_ref(), sd_bus_creds_unref() et sd_bus_creds_unrefp() n'exécutent aucune opération si l'objet d'identifiants de bus passé est NULL.

VALEUR RENVOYÉE

En cas de succès, sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

sd_bus_creds_get_mask() retourne le masque des champs acquis avec succès.

sd_bus_creds_get_augmented_mask() retourne le masque des champs qui ont été augmentés à partir des données de /proc/, et ne conviennent donc pas aux décisions d'autorisation.

sd_bus_creds_ref() retourne toujours l'argument.

sd_bus_creds_unref() retourne toujours NULL.

PROPRIÉTÉ DES RÉFÉRENCES

Les fonctions sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() créent un nouvel objet et l'appelant en possède la seule référence. Lorsque cette référence n'est plus nécessaire, elle doit être détruite avec sd_bus_creds_unref(3).

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ESRCH

Le pid spécifié n'a pas pu être trouvé.

-EINVAL

Le paramètre spécifié est invalide (NULL dans le cas des paramètres de sortie).

-ENOMEM

L'allocation de mémoire a échoué.

-EOPNOTSUPP

Un des champs demandés est inconnu du système local.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_creds_new_from_pid(), sd_bus_creds_get_mask(), sd_bus_creds_ref(), sd_bus_creds_unref() et sd_bus_creds_get_augmented_mask() ont été ajoutés dans la version 221.

sd_bus_creds_unrefp() a été ajouté dans la version 229.

sd_bus_creds_new_from_pidfd() a été ajouté dans la version 256.
