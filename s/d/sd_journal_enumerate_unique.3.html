sd_journal_enumerate_unique(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_JOURNAL_QUERY_UNIQUE(3) sd_journal_query_unique SD_JOURNAL_QUERY_UNIQUE(3)

NOM

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - Lire des champs de données uniques du journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

DESCRIPTION

sd_journal_query_unique() interroge le journal pour obtenir toutes les valeurs uniques que le champ spécifié peut prendre. Il prend deux arguments : le journal à interroger et le nom du champ à rechercher. Les noms de champs bien connus sont listés dans systemd.journal-fields(7), mais n'importe quel champ peut être spécifié. Les noms de champs doivent être spécifiés sans le "=" final. Après l'exécution réussie de cette fonction, les valeurs des champs peuvent être interrogées à l'aide de sd_journal_enumerate_unique() et sd_journal_enumerate_available_unique(). L'appel de l'une de ces fonctions changera le nom du champ interrogé et réinitialisera l'index d'énumération au premier valeur de champ correspondante.

sd_journal_enumerate_unique() peut être utilisée pour parcourir tous les champs de données qui correspondent au nom de champ précédemment sélectionné tel que défini avec sd_journal_query_unique(). À chaque invocation, la prochaine donnée de champ correspondante est retournée. L'ordre des champs de données retournés n'est pas défini. Elle prend trois arguments : l'objet journal, plus une paire de pointeurs vers des variables pointeur/taille où l'objet données et sa taille doivent être stockés. Les données retournées se trouvent dans une zone mémoire en lecture seule et ne sont valides que jusqu'à la prochaine invocation de sd_journal_enumerate_unique(). Notez que les données retournées seront précédées du nom du champ et de "=". Notez que cet appel est soumis au seuil de taille des données de champ contrôlé par sd_journal_set_data_threshold() et seule la partie initiale du champ jusqu'au seuil est retournée. Une erreur est retournée pour les champs qui ne peuvent pas être récupérés. Voir la liste des erreurs ci-dessous pour plus de détails.

sd_journal_enumerate_available_unique() est similaire à sd_journal_enumerate_unique(), mais ignore silencieusement tous les champs qui peuvent être valides, mais qui sont trop grands ou non pris en charge par l'implémentation actuelle.

sd_journal_restart_unique() réinitialise l'index d'énumération des données au début de la liste. La prochaine invocation de sd_journal_enumerate_unique() retournera à nouveau les premières données de champ correspondant au nom de champ.

Notez que la macro SD_JOURNAL_FOREACH_UNIQUE() peut être utilisée comme un wrapper pratique autour de sd_journal_restart_unique() et sd_journal_enumerate_available_unique().

Notez que ces fonctions ne sont actuellement pas influencées par les correspondances définies avec sd_journal_add_match(), mais cela pourrait changer dans une future version de ce logiciel.

Pour énumérer tous les noms de champs actuellement utilisés (et donc tous les paramètres de champs appropriés pour sd_journal_query_unique()), utilisez l'appel sd_journal_enumerate_fields(3).

VALEUR DE RETOUR

sd_journal_query_unique() retourne 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_enumerate_unique() et sd_journal_query_available_unique() retournent un entier positif si les prochaines données de champ ont été lues, 0 lorsqu'il n'y a plus de champs, ou un code d'erreur négatif de style errno. sd_journal_restart_unique() ne retourne rien.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

L'un des paramètres requis est NULL ou invalide.

Ajouté dans la version 246.

-ECHILD

L'objet journal a été créé dans un processus, une bibliothèque ou une instance de module différente.

Ajouté dans la version 246.

-EADDRNOTAVAIL

Le pointeur de lecture n'est pas positionné sur une entrée valide ; sd_journal_next(3) ou un appel similaire n'a pas été appelé au moins une fois.

Ajouté dans la version 246.

-ENOENT

L'entrée actuelle n'inclut pas le champ spécifié.

Ajouté dans la version 246.

-ENOBUFS

Une entrée compressée est trop volumineuse.

Ajouté dans la version 246.

-E2BIG

Le champ de données est trop volumineux pour cette architecture informatique (par exemple, supérieur à 4 Go sur une architecture 32 bits).

Ajouté dans la version 246.

-EPROTONOSUPPORT

Le journal est compressé avec une méthode non prise en charge ou le journal utilise une fonctionnalité non prise en charge.

Ajouté dans la version 246.

-EBADMSG

Le journal est corrompu (possiblement juste l'entrée en cours d'itération).

Ajouté dans la version 246.

-EIO

Une erreur d'E/S a été signalée par le noyau.

Ajouté dans la version 246.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à la fois. Différents threads peuvent accéder au même objet à différents moments. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

EXEMPLES

Utilisez la macro SD_JOURNAL_FOREACH_UNIQUE() pour parcourir toutes les valeurs qu'un champ du journal peut prendre (et qui sont accessibles sur l'architecture donnée et ne sont pas compressées avec un mécanisme non pris en charge). L'exemple suivant liste tous les noms d'unités référencés dans le journal :

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "Failed to query journal: %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

HISTORIQUE

sd_journal_query_unique(), sd_journal_enumerate_unique(), sd_journal_restart_unique(), et SD_JOURNAL_FOREACH_UNIQUE() ont été ajoutés dans la version 195.

sd_journal_enumerate_available_unique() a été ajoutée dans la version 246.

sd_journal_enumerate_unique

sd_journal_enumerate_unique, sd_journal_enumerate_unique_fd - Énumérer les champs de journal uniques

NOM

sd_journal_enumerate_unique, sd_journal_enumerate_unique_fd - Énumérer les champs de journal uniques

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_enumerate_unique(sd_journal *j, const char **name, const char **value);
int sd_journal_enumerate_unique_fd(sd_journal *j, const char **name, const char **value);

DESCRIPTION

sd_journal_enumerate_unique() et sd_journal_enumerate_unique_fd() peuvent être utilisées pour énumérer tous les champs de journal uniques actuellement disponibles dans le journal du système. Ils sont utilisés de manière répétitive pour parcourir tous les champs disponibles.

La première fois que ces fonctions sont appelées pour un descripteur de journal j donné, elles renvoient le premier champ unique disponible. Les appels ultérieurs renvoient le champ unique suivant, jusqu'à ce que tous les champs uniques aient été renvoyés. L'appel suivant après le dernier champ unique renvoie zéro.

Les deux fonctions sont fonctionnellement identiques.

Lors du premier appel, *name et *value sont définis pour pointer vers des chaînes de caractères constantes contenant le nom et la valeur du champ de journal. Lors des appels suivants, ces pointeurs sont mis à jour pour pointer vers le champ suivant. Il n'est pas nécessaire de libérer ces chaînes. Les données pointées par *name et *value sont valides jusqu'au prochain appel à sd_journal_enumerate_unique() ou sd_journal_enumerate_unique_fd(), ou jusqu'à ce que le descripteur de journal j soit fermé.

Pour énumérer les champs uniques, utilisez un descripteur de journal j obtenu à partir de sd_journal_open(). Utilisez un champ de journal que vous souhaitez obtenir via sd_journal_get_data() ou sd_journal_get_data_recursive() pour obtenir des informations sur des champs spécifiques.

Les champs de journal sont des paires nom/valeur qui identifient des informations spécifiques sur une entrée de journal. Par exemple, MESSAGE= identifie le message de journal principal, tandis que PRIORITY= identifie la priorité du message. Les champs de journal peuvent être des champs standard définis par journald ou des champs personnalisés ajoutés par des services ou des applications.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier positif. Si aucun champ de journal supplémentaire n'est disponible, elles renvoient zéro. En cas d'erreur, elles renvoient un nombre négatif.

NOTES

Ces fonctions peuvent être appelées sur des descripteurs de journal ouverts avec SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_TRY_REPLACE_CLOCK, SD_JOURNAL_NOP et SD_JOURNAL_INVALIDATE.

EXEMPLES

#include <stdio.h>
#include <systemd/sd-journal.h>

int main(int argc, char *argv[]) {
    sd_journal *j = NULL;
    const char *name, *value;
    int r;

    r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
    if (r < 0) {
        fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
        return 1;
    }

    printf("Listing unique journal fields:\n");
    while ((r = sd_journal_enumerate_unique(j, &name, &value)) > 0) {
        printf("  %s=%s\n", name, value);
    }

    if (r < 0) {
        fprintf(stderr, "Failed to enumerate journal fields: %s\n", strerror(-r));
    }

    sd_journal_close(j);
    return 0;
}
