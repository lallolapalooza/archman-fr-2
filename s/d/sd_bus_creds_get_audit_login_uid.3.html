DESCRIPTION

Ces fonctions retournent des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID du parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour plus de détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel qu'il est stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel qu'il est stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin vers l'exécutable du programme (tel qu'il est stocké dans le lien symbolique /proc/pid/exe, mais avec le suffixe " (deleted)" retiré). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée pour plus que des informations explicatives, en particulier elle ne doit pas être utilisée pour des décisions de sécurité. C'est parce que l'exécutable peut avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

La fonction sd_bus_creds_new_from_pid(3) crée un objet sd_bus_creds qui contient des informations d'identification sur le processus spécifié par pid. Les fonctions décrites ici extraient des informations spécifiques de cet objet.

sd_bus_creds_get_pid() renvoie l'identifiant de processus (PID) du processus.

sd_bus_creds_get_tid() renvoie l'identifiant de thread (TID) du processus.

sd_bus_creds_get_uid(), sd_bus_creds_get_euid(), sd_bus_creds_get_suid(), sd_bus_creds_get_fsuid() renvoient respectivement l'identifiant utilisateur réel, effectif, de sauvegarde et du système de fichiers du processus.

sd_bus_creds_get_gid(), sd_bus_creds_get_egid(), sd_bus_creds_get_sgid(), sd_bus_creds_get_fsgid() renvoient respectivement l'identifiant de groupe réel, effectif, de sauvegarde et du système de fichiers du processus.

sd_bus_creds_get_supplementary_gids() renvoie un tableau des identifiants de groupe supplémentaires du processus. Le tableau est terminé par un élément contenant la valeur -1.

sd_bus_creds_get_ppid() renvoie l'identifiant du processus parent du processus.

sd_bus_creds_get_comm() renvoie le nom de commande court (tel qu'affiché dans la colonne COMMAND de top, par exemple).

sd_bus_creds_get_tid_comm() renvoie le nom de commande court du thread spécifié. Pour la plupart des cas d'utilisation, ceci sera identique à sd_bus_creds_get_comm(), mais peut différer pour les threads qui effectuent des opérations différentes des autres threads du même processus.

sd_bus_creds_get_exe() renvoie le chemin d'accès de l'exécutable du processus (tel qu'il apparaît dans /proc/pid/exe). Notez que les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_cmdline() récupérera un tableau d'arguments de ligne de commande (tel qu'il est stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_cgroup() récupérera le chemin du groupe de contrôle. Voir Control Groups v2[1].

sd_bus_creds_get_unit() récupérera le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, renvoie -ENXIO.

sd_bus_creds_get_user_unit() récupérera le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, renvoie -ENXIO.

sd_bus_creds_get_slice() récupérera la tranche systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère la tranche systemd du processus, dans l'instance utilisateur de systemd.

sd_bus_creds_get_session() récupérera l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut se limiter à un processus stub ou deux. Les processus utilisateur peuvent plutôt être démarrés à partir de leur gestionnaire utilisateur systemd, par exemple des applications graphiques démarrées à l'aide de l'activation DBus, ainsi que des processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, renvoie -ENXIO.

sd_bus_creds_get_owner_uid() récupérera l'UID numérique (identifiant utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, renvoie -ENXIO.

sd_bus_creds_has_effective_cap() vérifiera si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités permises.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités de bornage.

sd_bus_creds_get_selinux_context() récupérera le contexte de sécurité SELinux (label) du processus.

sd_bus_creds_get_audit_session_id() récupérera l'identifiant de session d'audit du processus. Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_audit_login_uid() récupérera l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur "responsable" de la session). Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_tty() récupérera le TTY de contrôle, sans le préfixe "/dev/". Renvoie -ENXIO pour les processus qui n'ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupérera le nom unique D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_well_known_names() récupérera l'ensemble des noms bien connus D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_description() récupérera un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus par le même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).

sd_bus_creds_get_pidfd_dup() récupère une copie du descripteur de fichier pour le processus spécifié. Le descripteur de fichier renvoyé est un descripteur de fichier PID (voir pidfd_open(2)). Cette fonction est une alternative pour obtenir des informations sur un processus lorsqu'on ne veut pas s'appuyer sur des informations potentiellement obsolètes comme celles trouvées dans /proc. Notez que l'obtention du pidfd échouera si le processus est déjà terminé.

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse là sous forme d'adresse d'une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse là sous forme d'adresse d'un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet d'identification c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une tranche systemd, ou d'une session logind. Il sera renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas démarrés à partir d'un exécutable binaire, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation mémoire.

-EPERM

L'appelant n'a pas les permissions nécessaires pour lire les informations d'identification demandées (par exemple, il essaie de lire les informations d'identification d'un processus appartenant à un autre utilisateur sans être root).

-ENOENT

Le processus spécifié n'existe plus.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à un stade précoce du programme lorsque aucun autre thread n'a été démarré.
