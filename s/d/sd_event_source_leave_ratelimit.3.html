SD_EVENT_SOURCE_SET_RATELIMIT(3) sd_event_source_set_ratelimit SD_EVENT_SOURCE_SET_RATELIMIT(3)

NOM

sd_event_source_set_ratelimit, sd_event_source_get_ratelimit, sd_event_source_is_ratelimited, sd_event_source_set_ratelimit_expire_callback, sd_event_source_leave_ratelimit - Configurer la limitation de débit des sources d'événements

SYNTAXE

#include <systemd/sd-event.h>

int sd_event_source_set_ratelimit(sd_event_source *source, uint64_t interval_usec, unsigned burst);

int sd_event_source_get_ratelimit(sd_event_source *source, uint64_t* ret_interval_usec, unsigned* ret_burst);

int sd_event_source_is_ratelimited(sd_event_source *source);

int sd_event_source_set_ratelimit_expire_callback(sd_event_source *source, sd_event_handler_tcallback);

int sd_event_source_leave_ratelimit(sd_event_source *source);

DESCRIPTION

sd_event_source_set_ratelimit() peut être utilisée pour appliquer une limitation de débit à une source d'événements. Lorsqu'elle est utilisée, une source d'événements est temporairement désactivée lorsqu'elle se déclenche plus souvent qu'un nombre de rafales spécifié dans un intervalle de temps spécifié. Ceci est utile comme mécanisme simple pour éviter la famine de sources d'événements si des sources d'événements de haute priorité se déclenchent très fréquemment.

Passez la source d'événements sur laquelle opérer comme premier argument, un intervalle de temps en microsecondes comme second argument et une limite maximale de dispatch ("rafale") comme troisième paramètre. Chaque fois que la source d'événements est dispatche plus souvent que la rafale spécifiée pendant l'intervalle spécifié, elle est placée dans un mode similaire à celui d'une désactivation avec sd_event_source_set_enabled(3) et le paramètre SD_EVENT_OFF. Cependant, elle n'est désactivée que temporairement – une fois l'intervalle spécifié écoulé, le fonctionnement normal reprend. Elle est à nouveau désactivée temporairement la prochaine fois que la limitation de débit spécifiée est atteinte. Si l'intervalle ou la valeur de rafale sont spécifiés à zéro, la limitation de débit est désactivée. Par défaut, les sources d'événements n'ont pas de limitation de débit activée. Notez que la limitation de débit et la désactivation via sd_event_source_set_enabled() sont indépendantes l'une de l'autre, et qu'une source d'événements n'affectera les réveils de la boucle d'événements et ne sera dispatche que si elle est à la fois activée et que la limitation de débit n'est pas en vigueur.

sd_event_source_get_ratelimit() peut être utilisée pour interroger les paramètres actuels de limitation de débit définis sur l'objet source d'événements source. Les valeurs d'intervalle et de rafale précédemment définies sont retournées dans les deuxième et troisième arguments.

sd_event_source_is_ratelimited() peut être utilisée pour interroger si la source d'événements est actuellement affectée par la limitation de débit, c'est-à-dire si elle a récemment atteint la limite de débit et est actuellement temporairement désactivée en raison de cela.

sd_event_source_set_ratelimit_expire_callback() peut être utilisée pour définir une fonction de rappel qui est appelée chaque fois que la source d'événements quitte l'état de limitation de débit. Notez que la fonction est appelée dans la même itération de la boucle d'événements où la transition d'état s'est produite.

sd_event_source_leave_ratelimit() peut être utilisée pour réactiver immédiatement une source d'événements qui a été temporairement désactivée en raison de la limitation de débit. Cela réinitialisera les compteurs de limitation de débit pour l'intervalle de temps actuel.

La limitation de débit est actuellement implémentée pour les sources d'événements d'E/S, de minuteur, de signal, de report et inotify.

VALEUR DE RETOUR

En cas de succès, sd_event_source_set_ratelimit(), sd_event_source_set_ratelimit_expire_callback et sd_event_source_get_ratelimit() retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno. sd_event_source_is_ratelimited() retourne zéro si la limitation de débit n'est actuellement pas en vigueur et plus de zéro si elle l'est ; elle retourne un code d'erreur négatif de style errno en cas d'échec. sd_event_source_leave_ratelimit() retourne zéro si la limitation de débit n'était pas en vigueur sur la source d'événements spécifiée, et positif si elle l'était et que la limitation de débit est maintenant désactivée à nouveau ; elle retourne un code d'erreur négatif de style errno en cas d'échec.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

source n'est pas un pointeur valide vers un objet sd_event_source.

Ajouté dans la version 248.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

Ajouté dans la version 248.

-EDOM

On a tenté d'utiliser la fonctionnalité de limitation de débit sur un type de source d'événements qui ne prend pas en charge la limitation de débit.

Ajouté dans la version 248.

-ENOEXEC

sd_event_source_get_ratelimit() a été appelée sur une source d'événements pour laquelle aucune limitation de débit n'est configurée.

Ajouté dans la version 248.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_source_set_ratelimit(), sd_event_source_get_ratelimit(), et sd_event_source_is_ratelimited() ont été ajoutées dans la version 248.

sd_event_source_set_ratelimit_expire_callback() a été ajoutée dans la version 250.

sd_event_source_leave_ratelimit() a été ajoutée dans la version 254.
