SD_EVENT_ADD_TIME(3) sd_event_add_time SD_EVENT_ADD_TIME(3)

NOM

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Ajouter une source d'événement temporisée à une boucle d'événements

SYNOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPTION

sd_event_add_time() ajoute une nouvelle source d'événement temporisée à une boucle d'événements. L'objet de la boucle d'événements est spécifié dans le paramètre event, l'objet de la source d'événement est renvoyé dans le paramètre source. Le paramètre clock accepte un identifiant d'horloge, l'un des CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM ou CLOCK_BOOTTIME_ALARM. Voir timerfd_create(2) pour plus de détails sur les différents types d'horloges. Le paramètre usec spécifie l'heure la plus rapprochée, en microsecondes (μs), par rapport à l'époque de l'horloge, à laquelle le minuteur doit être déclenché. Si une heure déjà passée est spécifiée (y compris 0), cette source de minuteur est déclenchée immédiatement et est prête à être distribuée. Si le paramètre est spécifié comme UINT64_MAX, l'événement du minuteur n'expirera jamais, ce qui peut être utilisé comme alternative à la désactivation explicite d'une source d'événement temporisée avec sd_event_source_set_enabled(3). Le paramètre accuracy spécifie une valeur de précision supplémentaire en μs indiquant dans quelle mesure l'événement du minuteur peut être retardé. Utilisez 0 pour sélectionner la précision par défaut (250 ms). Utilisez 1 μs pour une précision maximale. Envisagez de spécifier 60000000 μs (1 min) ou plus pour les événements de longue durée qui peuvent être considérablement retardés. Le choix de valeurs de précision plus élevées permet au système de regrouper les événements de minuteur de manière plus agressive, améliorant ainsi l'efficacité énergétique.

Le handler est une fonction à appeler lorsque le minuteur expire ou NULL. Le pointeur userdata sera passé à la fonction gestionnaire, et peut être choisi librement par l'appelant. L'heure de déclenchement configurée est également passée au gestionnaire, même si l'appel se produit en réalité légèrement plus tard, sous réserve de la valeur de précision spécifiée, du délai d'attente du minuteur du noyau (voir prctl(2)), et des latences de planification supplémentaires. Pour interroger l'heure réelle à laquelle le gestionnaire a été appelé, utilisez sd_event_now(3). Le gestionnaire peut renvoyer une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Par défaut, le minuteur n'expirera qu'une seule fois (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction gestionnaire renvoie un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, ou elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3). Notez qu'un événement temporisé défini sur SD_EVENT_ON se déclenchera continuellement à moins que son heure configurée ne soit mise à jour à l'aide de sd_event_source_set_time().

sd_event_add_time_relative() est similaire à sd_event_add_time(), mais accepte une spécification de temps relatif. Elle est relative à l'heure actuelle de l'itération de la boucle d'événements, telle que renvoyée par sd_event_now(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si elle est toujours référencée, désactivez la source d'événement à l'aide de sd_event_source_set_enabled(3) avec SD_EVENT_OFF.

Si le deuxième paramètre de sd_event_add_time() est NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_time() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Utilisez CLOCK_BOOTTIME_ALARM et CLOCK_REALTIME_ALARM pour définir des sources d'événements qui peuvent réveiller le système de la veille.

Afin de configurer des minuteurs relatifs (c'est-à-dire, relatifs à l'heure actuelle), récupérez l'heure actuelle via sd_event_now(3), ajoutez la durée souhaitée, et utilisez le résultat comme paramètre usec pour sd_event_add_time().

Afin de configurer des minuteurs répétitifs (c'est-à-dire, des minuteurs qui se déclenchent à intervalles réguliers), configurez le minuteur normalement pour la première invocation. Chaque fois que le gestionnaire d'événements est appelé, mettez à jour l'heure de déclenchement du minuteur avec sd_event_source_set_time(3) pour la prochaine itération du minuteur, et réactivez le minuteur en utilisant sd_event_source_set_enabled(). Pour calculer le prochain point dans le temps à passer à sd_event_source_set_time(), utilisez soit l'heure passée en paramètre usec au rappel du minuteur, soit l'horodatage renvoyé par sd_event_now() comme base. Dans le premier cas, les événements du minuteur seront réguliers, tandis que dans le second cas, la latence de planification continuera de s'accumuler sur le minuteur.

sd_event_source_get_time() récupère la valeur de temps configurée d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker le temps, relatif à l'époque de l'horloge sélectionnée, en μs. La valeur renvoyée est relative à l'époque, même si la source d'événement a été créée avec un temps relatif via sd_event_add_time_relative().

sd_event_source_set_time() modifie l'heure d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et une heure relative à l'époque de l'horloge sélectionnée, en μs.

sd_event_source_set_time_relative() est similaire à sd_event_source_set_time(), mais accepte une heure relative à l'heure actuelle de l'itération de la boucle d'événements, telle que renvoyée par sd_event_now().

sd_event_source_get_time_accuracy() récupère la valeur de précision configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker la précision. La précision est spécifiée en μs.

sd_event_source_set_time_accuracy() modifie la précision configurée d'une source d'événement temporisée

VALEUR RENVOYÉE

Les fonctions sd_event_add_time() et sd_event_add_time_relative() renvoient 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les codes d'erreur possibles sont :

-ECHILD
    La boucle d'événements a été détruite.
-EINVAL
    Un paramètre invalide a été fourni.
-ENOMEM
    Pas assez de mémoire pour allouer la source d'événement.

Les fonctions sd_event_source_get_time(), sd_event_source_set_time(), sd_event_source_set_time_relative(), sd_event_source_get_time_accuracy(), sd_event_source_set_time_accuracy(), et sd_event_source_get_time_clock() renvoient 0 en cas de succès, ou un code d'erreur négatif.

SYNOPSIS

#include <systemd/sd-event.h>

typedef int (*sd_event_time_handler_t)(sd_event_source *source, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event,
                      sd_event_source **source,
                      clockid_t clock,
                      uint64_t usec,
                      uint64_t accuracy_usec,
                      sd_event_time_handler_t handler,
                      void *userdata);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);
int sd_event_source_get_time(sd_event_source *source, uint64_t *usec);
int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t accuracy_usec);
int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *accuracy_usec);
int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock);

int sd_event_add_time_relative(sd_event *event,
                              sd_event_source **source,
                              clockid_t clock,
                              uint64_t accuracy_usec,
                              sd_event_time_handler_t handler,
                              void *userdata);
int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

DESCRIPTION

Ces fonctions sont utilisées pour planifier l'exécution d'une fonction de rappel (callback) à un moment donné.

sd_event_add_time() planifie l'exécution de la fonction handler pour l'objet événement event. Le rappel sera déclenché lorsque l'horloge spécifiée par clock atteindra la valeur absolue usec (en microsecondes depuis l'époque de l'horloge). L'argument accuracy_usec spécifie la précision souhaitée en microsecondes ; cela peut être utilisé par l'implémentation de l'événement pour regrouper plusieurs événements temporels ou pour utiliser des mécanismes de mise en veille moins précis mais plus économes en énergie. Si source n'est pas NULL, un pointeur vers le nouvel objet source d'événement sera stocké.

sd_event_add_time_relative() est similaire à sd_event_add_time(), mais usec est interprété comme un délai relatif en microsecondes à partir du moment de l'appel. L'horloge spécifiée par clock est utilisée pour mesurer ce délai. L'argument accuracy_usec fonctionne de la même manière que pour sd_event_add_time().

sd_event_source_set_time() modifie le moment déclencheur absolu d'une source d'événement temporel existante créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et le nouveau moment déclencheur en microsecondes.

sd_event_source_set_time_relative() modifie le délai relatif d'une source d'événement temporel existante créée précédemment avec sd_event_add_time_relative(). Elle prend l'objet source d'événement et le nouveau délai relatif en microsecondes.

sd_event_source_get_time() récupère le moment déclencheur absolu configuré d'une source d'événement temporel créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker le moment déclencheur en microsecondes.

sd_event_source_set_time_accuracy() modifie la précision configurée d'une source d'événement temporel créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et la nouvelle précision en microsecondes.

sd_event_source_get_time_accuracy() récupère la précision configurée d'une source d'événement temporel créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker la précision en microsecondes.

sd_event_source_get_time_clock() récupère l'horloge configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker l'identifiant de l'horloge.

RETURN VALUE

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Errors

Les valeurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un autre processus, une autre bibliothèque ou une autre instance de module.

-EOPNOTSUPP

L'horloge sélectionnée n'est pas prise en charge par l'implémentation de la boucle d'événements.

-EDOM

La source d'événement passée n'est pas une source d'événement de type timer.

-EOVERFLOW

Le temps relatif passé est en dehors de la plage autorisée pour les valeurs temporelles (c'est-à-dire que la valeur spécifiée ajoutée au temps actuel dépasse la plage d'entier non signé de 64 bits).

Ajouté dans la version 247.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
