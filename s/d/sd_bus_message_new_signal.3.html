SD_BUS_MESSAGE_NEW_SIGNAL(3) sd_bus_message_new_signal SD_BUS_MESSAGE_NEW_SIGNAL(3)

NOM

sd_bus_message_new_signal, sd_bus_message_new_signal_to - Créer un message de signal

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_new_signal(sd_bus *bus, sd_bus_message **m, const char *path, const char *interface, const char *member);

int sd_bus_message_new_signal_to(sd_bus *bus, sd_bus_message **m, const char *destination, const char *path, const char *interface, const char *member);

DESCRIPTION

La fonction sd_bus_message_new_signal() crée un nouvel objet de message de bus qui encapsule un signal D-Bus, et le retourne dans le paramètre de sortie m. Le signal sera envoyé au chemin path, sur l'interface interface, membre member. Lorsque ce message est envoyé, aucune réponse n'est attendue. Voir sd_bus_message_new_method_call(3) pour une courte description de la signification des paramètres path, interface, et member.

sd_bus_message_new_signal_to() est un raccourci pour la création d'un nouveau message de bus vers une destination spécifique. Son comportement est similaire à l'appel de sd_bus_message_new_signal() suivi de l'appel à sd_bus_message_set_destination(3).

VALEUR DE RETOUR

Cette fonction retourne 0 si l'objet message a été créé avec succès, et un code d'erreur négatif de type errno sinon.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre de sortie m est NULL.

Le paramètre path n'est pas un chemin D-Bus valide ("/un/chemin/objet"), le paramètre interface n'est pas un nom d'interface D-Bus valide ("une.interface.nom"), ou le paramètre member n'est pas un membre D-Bus valide ("Nom").

-ENOTCONN

Le paramètre bus est NULL ou le bus n'est pas connecté.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour l'utilisation multithread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

EXEMPLES

Exemple 1. Envoyer un signal simple

/* SPDX-License-Identifier: MIT-0 */
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
int send_unit_files_changed(sd_bus *bus) {
  _cleanup_(sd_bus_message_unrefp) sd_bus_message *message = NULL;
  int r;
  r = sd_bus_message_new_signal(bus, &message,
                                "/org/freedesktop/systemd1",
                                "org.freedesktop.systemd1.Manager",
                                "UnitFilesChanged");
  if (r < 0)
    return r;
  return sd_bus_send(bus, message, NULL);
}

Cette fonction dans les sources de systemd est utilisée pour émettre le signal "UnitFilesChanged" lorsque les fichiers d'unité ont été modifiés.
