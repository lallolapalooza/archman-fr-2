int sd_path_lookup_strv(uint64_t type, const char *suffix, char ***paths);

DESCRIPTION

sd_path_lookup() et sd_bus_path_lookup_strv() renvoient un chemin unique ou un ensemble de chemins de système de fichiers spécifiés par l'argument type. Dans le cas de sd_path_lookup(), une seule chaîne terminée par NUL est renvoyée. Lorsque type spécifie un ensemble de chemins, ils sont concaténés en utilisant ":" comme séparateur (comme c'est traditionnellement fait pour par exemple $PATH ou $LD_LIBRARY_PATH). Dans le cas de sd_path_lookup_strv(), un tableau de chaînes terminé par NULL (strv) est renvoyé. Si un suffixe suffix est donné, il est concaténé à chacun des chemins après une barre oblique ("/"). Tous les chemins renvoyés sont absolus.

Pour les chemins qui font référence à des répertoires utilisateur, la norme XDG pertinente est suivie, avec la prise en charge des variables d'environnement comme $XDG_DOCUMENTS_DIR, $XDG_DESKTOP_DIR, ..., et la configuration explicite dans /etc/xdg/user-dirs.conf ou ${XDG_CONFIG_HOME}/user-dirs.dirs. Voir la Spécification des répertoires de base XDG[1] pour les détails.

systemd-path(1) est un wrapper autour de sd_path_lookup() et permet d'interroger le même ensemble de chemins.

VALEUR DE RETOUR

En cas de succès, sd_path_lookup() et sd_path_lookup_strv() renvoient un entier non négatif. En cas d'échec, un nombre d'erreur négatif de type errno est renvoyé par l'une ou l'autre fonction.

La chaîne ou le tableau de chaînes (strv) renvoyé doit être libéré par l'appelant en utilisant free(3).

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EOPNOTSUPP

Identifiant type inconnu.

Ajouté dans la version 246.

-EINVAL

L'argument de sortie est NULL.

Ajouté dans la version 246.

-ENXIO

L'interrogation a échoué en raison d'une variable d'environnement indéfinie (par exemple, pour SD_PATH_USER_RUNTIME lorsque $XDG_RUNTIME_DIR n'est pas défini).

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation mémoire.

Ajouté dans la version 246.

EXEMPLES

Rechercher l'emplacement de ~/Documents

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-path.h>
int main(void) {
  int r;
  char *t;
  r = sd_path_lookup(SD_PATH_USER_DOCUMENTS, NULL, &t);
  if (r < 0)
    return EXIT_FAILURE;
  printf("~/Documents : %s\n", t);
  free(t);
  return EXIT_SUCCESS;
}

Notez que la réponse par défaut $HOME/Documents peut être remplacée par user-dirs.conf ou $XDG_DOCUMENTS_DIR.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dès le début du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_path_lookup() et sd_path_lookup_strv() ont été ajoutés dans la version 246.
