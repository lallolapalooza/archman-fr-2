sd_bus_unrefp(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_NEW(3) sd_bus_new SD_BUS_NEW(3)

NOM

sd_bus_new, sd_bus_ref, sd_bus_unref, sd_bus_unrefp, sd_bus_close_unref, sd_bus_close_unrefp, sd_bus_flush_close_unref, sd_bus_flush_close_unrefp - Créer un nouvel objet bus et créer ou détruire des références à celui-ci

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_new(sd_bus **bus);

sd_bus *sd_bus_ref(sd_bus *bus);

sd_bus *sd_bus_unref(sd_bus *bus);

sd_bus *sd_bus_close_unref(sd_bus *bus);

sd_bus *sd_bus_flush_close_unref(sd_bus *bus);

void sd_bus_unrefp(sd_bus **busp);

void sd_bus_close_unrefp(sd_bus **busp);

void sd_bus_flush_close_unrefp(sd_bus **busp);

DESCRIPTION

sd_bus_new() crée un nouvel objet bus. Cet objet est géré par comptage de références et sera détruit lorsque toutes les références auront disparu. Initialement, l'appelant de cette fonction possède la seule référence et l'objet bus ne sera connecté à aucun bus. Pour le connecter à un bus, assurez-vous de définir une adresse avec sd_bus_set_address(3) ou un appel similaire, puis démarrez la connexion avec sd_bus_start(3).

Dans la plupart des cas, il est préférable d'utiliser sd_bus_default_user(3), sd_bus_default_system(3) ou des appels similaires plutôt que les fonctions de plus bas niveau sd_bus_new() et sd_bus_start(). Les fonctions de plus haut niveau allouent non seulement un objet bus, mais démarrent également la connexion à un bus bien connu en un seul appel de fonction.

sd_bus_ref() augmente le compteur de références de bus de un.

sd_bus_unref() diminue le compteur de références de bus de un. Une fois que le compteur de références est tombé à zéro, bus est détruit et ne peut plus être utilisé, donc les appels ultérieurs à sd_bus_ref() ou sd_bus_unref() sont illégaux.

sd_bus_unrefp() est similaire à sd_bus_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus. Cet appel est utile en conjonction avec l'attribut GCC et LLVM Clean-up Variable Attribute[1]. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme suit, afin d'allouer un objet bus qui est libéré automatiquement lorsque le bloc de code est quitté :

{
  __attribute__((cleanup(sd_bus_unrefp))) sd_bus *bus = NULL;
  int r;
  ...
  r = sd_bus_default(&bus);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Impossible d'allouer le bus : %m\n");
  }
  ...
}

sd_bus_ref() et sd_bus_unref() n'exécutent aucune opération si l'argument est NULL. sd_bus_unrefp() déréférencera d'abord son argument, qui ne doit pas être NULL, et n'exécutera aucune opération si *celui-ci* est NULL.

sd_bus_close_unref() est similaire à sd_bus_unref(), mais exécute d'abord sd_bus_close(3), garantissant que la connexion est terminée avant que la référence à la connexion ne soit supprimée et éventuellement l'objet libéré.

sd_bus_flush_close_unref() est similaire à sd_bus_unref(), mais exécute d'abord sd_bus_flush(3) ainsi que sd_bus_close(3), garantissant que tous les messages en attente sont synchroniquement évacués avant que la référence à la connexion ne soit supprimée et éventuellement l'objet libéré. Cet appel est particulièrement utile juste avant de quitter un programme car il garantit que tous les messages sortants en attente sont écrits, et les messages entrants non traités mais mis en file d'attente sont libérés avant que la connexion ne soit terminée et libérée.

sd_bus_close_unrefp() est similaire à sd_bus_close_unref(), mais peut être utilisé dans l'attribut Clean-up Variable de GCC et LLVM, voir ci-dessus. De même, sd_bus_flush_close_unrefp() est similaire à sd_bus_flush_close_unref().

VALEUR DE RETOUR

En cas de succès, sd_bus_new() retourne 0 ou un entier positif. En cas d'échec, il retourne un code d'erreur négatif de style errno.

sd_bus_ref() retourne toujours l'argument.

sd_bus_unref() et sd_bus_flush_close_unref() retournent toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Allocation de mémoire échouée.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dès les premières phases du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_new(), sd_bus_ref(), et sd_bus_unref() ont été ajoutés dans la version 209.

sd_bus_unrefp() a été ajouté dans la version 229.

sd_bus_flush_close_unref() et sd_bus_flush_close_unrefp() ont été ajoutés dans la version 240.

sd_bus_close_unref() et sd_bus_close_unrefp() ont été ajoutés dans la version 241.
