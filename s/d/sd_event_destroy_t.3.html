sd_event_destroy_t(3)

Paquet: systemd-libs

SD_EVENT_SOURCE_SET_DESTROY_CALLBACK(3) sd_event_source_set_destroy_callback SD_EVENT_SOURCE_SET_DESTROY_CALLBACK(3)

NOM

sd_event_source_set_destroy_callback, sd_event_source_get_destroy_callback, sd_event_destroy_t - Définir la fonction de rappel pour le nettoyage des ressources

SYNTAXE

#include <systemd/sd-event.h>

typedef int (*sd_event_destroy_t)(void *userdata);

int sd_event_source_set_destroy_callback(sd_event_source *source, sd_event_destroy_t callback);

int sd_event_source_get_destroy_callback(sd_event_source *source, sd_event_destroy_t *callback);

DESCRIPTION

sd_event_source_set_destroy_callback() définit callback comme fonction de rappel à appeler juste avant que l'objet source d'événement source ne soit désalloué. Le pointeur userdata de l'objet source d'événement sera passé comme paramètre userdata. Ce pointeur peut être défini par un argument des fonctions constructeurs, voir sd_event_add_io(3), ou directement, voir sd_event_source_set_userdata(3). Cette fonction de rappel est appelée même si userdata est NULL. Notez que ce rappel est déclenché à un moment où l'objet source d'événement lui-même est déjà invalidé, et l'exécution d'opérations ou la prise de nouvelles références à l'objet source d'événement ne sont pas autorisées.

sd_event_source_get_destroy_callback() renvoie le rappel actuel pour source dans le paramètre callback.

VALEUR RENVOYÉE

En cas de succès, sd_event_source_set_destroy_callback() renvoie 0 ou un entier positif. En cas d'échec, elle renvoie un code d'erreur négatif de style errno.

sd_event_source_get_destroy_callback() renvoie une valeur positive si la fonction de rappel de destruction est définie, 0 sinon. En cas d'échec, elle renvoie un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre source est NULL.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour le multithreading. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() que depuis une phase précoce du programme, lorsqu'aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_event_destroy_t(), sd_event_source_set_destroy_callback() et sd_event_source_get_destroy_callback() ont été ajoutées dans la version 239.
