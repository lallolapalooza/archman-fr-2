SD_EVENT_ADD_TIME(3) sd_event_add_time SD_EVENT_ADD_TIME(3)

NOM

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Ajouter une source d'événement de temporisation à une boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPTION

sd_event_add_time() ajoute une nouvelle source d'événement de temporisation à une boucle d'événements. L'objet boucle d'événements est spécifié par le paramètre event, l'objet source d'événement est renvoyé dans le paramètre source. Le paramètre clock accepte un identifiant d'horloge, l'un de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM ou CLOCK_BOOTTIME_ALARM. Voir timerfd_create(2) pour plus de détails sur les différents types d'horloges. Le paramètre usec spécifie l'heure la plus proche, en microsecondes (μs), par rapport à l'époque de l'horloge, à laquelle la temporisation doit se déclencher. Si une heure déjà passée est spécifiée (y compris 0), cette source de temporisation se déclenche immédiatement et est prête à être distribuée. Si le paramètre est spécifié comme UINT64_MAX, l'événement de temporisation n'expirera jamais, ce qui peut être utilisé comme alternative à la désactivation explicite d'une source d'événement de temporisation avec sd_event_source_set_enabled(3). Le paramètre accuracy spécifie une valeur de précision supplémentaire en μs indiquant à quel point l'événement de temporisation peut être retardé. Utilisez 0 pour sélectionner la précision par défaut (250 ms). Utilisez 1 μs pour une précision maximale. Envisagez de spécifier 60000000 μs (1 min) ou plus pour les événements de longue durée qui peuvent être retardés substantiellement. Le choix de valeurs de précision plus élevées permet au système de regrouper plus agressivement les événements de temporisation, améliorant ainsi l'efficacité énergétique.

Le paramètre handler est une fonction à appeler lorsque la temporisation expire, ou NULL. Le pointeur userdata sera passé à la fonction de gestionnaire et peut être choisi librement par l'appelant. L'heure de déclenchement configurée est également passée au gestionnaire, même si l'appel se produit en réalité un peu plus tard, sous réserve de la valeur de précision spécifiée, du délai d'attente du minuteur du noyau (voir prctl(2)) et des latences de planification supplémentaires. Pour interroger l'heure réelle à laquelle le gestionnaire a été appelé, utilisez sd_event_now(3). Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Par défaut, la temporisation expirera une seule fois (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire renvoie un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était précédemment demandé, soit elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3). Notez qu'une source d'événement de temporisation définie sur SD_EVENT_ON se déclenchera continuellement à moins que son heure configurée ne soit mise à jour en utilisant sd_event_source_set_time().

sd_event_add_time_relative() est similaire à sd_event_add_time(), mais prend une spécification de temps relatif. Il est relatif au temps actuel de l'itération de la boucle d'événements, tel que renvoyé par sd_event_now(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont supprimées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si elle est toujours référencée, désactivez la source d'événement en utilisant sd_event_source_set_enabled(3) avec SD_EVENT_OFF.

Si le deuxième paramètre de sd_event_add_time() est NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_time() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Utilisez CLOCK_BOOTTIME_ALARM et CLOCK_REALTIME_ALARM pour définir des sources d'événement qui peuvent réveiller le système de la veille.

Afin de configurer des temporisations relatives (c'est-à-dire, relatives au temps actuel), récupérez le temps actuel via sd_event_now(3), ajoutez la durée désirée, et utilisez le résultat comme paramètre usec pour sd_event_add_time().

Afin de configurer des temporisations répétitives (c'est-à-dire, des temporisations qui se déclenchent à intervalles réguliers), configurez la temporisation normalement, pour la première invocation. Chaque fois que le gestionnaire d'événements est appelé, mettez à jour l'heure de déclenchement de la temporisation avec sd_event_source_set_time(3) pour la prochaine itération de temporisation, et réactivez la temporisation en utilisant sd_event_source_set_enabled(). Pour calculer le prochain point dans le temps à passer à sd_event_source_set_time(), utilisez soit comme base le paramètre usec passé au rappel de temporisation, soit l'horodatage renvoyé par sd_event_now(). Dans le premier cas, les événements de temporisation seront réguliers, tandis que dans le second cas, la latence de planification continuera de s'accumuler sur la temporisation.

sd_event_source_get_time() récupère la valeur de temps configurée d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker le temps, relatif à l'époque de l'horloge sélectionnée, en μs. La valeur renvoyée est relative à l'époque, même si la source d'événement a été créée avec un temps relatif via sd_event_add_time_relative().

sd_event_source_set_time() modifie le temps d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un temps relatif à l'époque de l'horloge sélectionnée, en μs.

sd_event_source_set_time_relative() est similaire à sd_event_source_set_time(), mais prend un temps relatif au temps actuel de l'itération de la boucle d'événements, tel que renvoyé par sd_event_now().

sd_event_source_get_time_accuracy() récupère la valeur de précision configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker la précision. La précision est spécifiée en μs.

sd_event_source_set_time_accuracy() modifie la précision configurée d'une source d'événement de temporisation

sd_event_source_get_time_clock() récupère l'horloge configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Il prend l'objet source d'événement et un pointeur vers une variable pour stocker l'identifiant de l'horloge.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Les valeurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus différent, une bibliothèque ou une instance de module différente.

-EOPNOTSUPP

L'horloge sélectionnée n'est pas prise en charge par l'implémentation de la boucle d'événements.

-EDOM

La source d'événement passée n'est pas une source d'événement de minuteur.

-EOVERFLOW

Le temps relatif passé est en dehors de la plage autorisée pour les valeurs temporelles (c'est-à-dire que la valeur spécifiée ajoutée au temps actuel dépasse la plage des entiers non signés de 64 bits).

Ajouté dans la version 247.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
