SD_EVENT_SOURCE_SET_RATELIMIT(3) sd_event_source_set_ratelimit SD_EVENT_SOURCE_SET_RATELIMIT(3)

NOM

sd_event_source_set_ratelimit, sd_event_source_get_ratelimit, sd_event_source_is_ratelimited, sd_event_source_set_ratelimit_expire_callback, sd_event_source_leave_ratelimit - Configurer la limitation du débit sur les sources d'événements

SYNTAXE

#include <systemd/sd-event.h>

int sd_event_source_set_ratelimit(sd_event_source *source, uint64_t interval_usec, unsigned burst);

int sd_event_source_get_ratelimit(sd_event_source *source, uint64_t* ret_interval_usec, unsigned* ret_burst);

int sd_event_source_is_ratelimited(sd_event_source *source);

int sd_event_source_set_ratelimit_expire_callback(sd_event_source *source, sd_event_handler_tcallback);

int sd_event_source_leave_ratelimit(sd_event_source *source);

DESCRIPTION

sd_event_source_set_ratelimit() peut être utilisé pour appliquer une limitation de débit sur une source d'événement. Lorsqu'elle est utilisée, une source d'événement sera temporairement désactivée lorsqu'elle se déclenche plus souvent qu'un nombre de rafales spécifié dans un intervalle de temps donné. Ceci est utile comme mécanisme simple pour éviter la famine de sources d'événements si des sources d'événements à haute priorité se déclenchent très fréquemment.

Passez la source d'événement sur laquelle opérer comme premier argument, un intervalle de temps en microsecondes comme second argument et une limite maximale de déclenchement ("rafale") comme troisième paramètre. Chaque fois que la source d'événement est déclenchée plus souvent que la rafale spécifiée pendant l'intervalle spécifié, elle est mise dans un mode similaire à celui désactivé avec sd_event_source_set_enabled(3) et le paramètre SD_EVENT_OFF. Cependant, elle n'est désactivée que temporairement – une fois l'intervalle spécifié écoulé, le fonctionnement normal reprend. Elle est à nouveau désactivée temporairement une fois que la limitation de débit spécifiée est atteinte la prochaine fois. Si l'intervalle ou la valeur de rafale sont spécifiés à zéro, la limitation de débit est désactivée. Par défaut, les sources d'événements n'ont pas de limitation de débit activée. Notez que la limitation de débit et la désactivation via sd_event_source_set_enabled() sont indépendantes l'une de l'autre, et une source d'événement n'affectera les réveils de la boucle d'événements et ne sera déclenchée que si elle est activée et que la limitation de débit n'est pas en vigueur.

sd_event_source_get_ratelimit() peut être utilisé pour interroger les paramètres de limitation de débit actuels définis sur l'objet source d'événement source. Les valeurs d'intervalle et de rafale précédemment définies sont retournées dans le deuxième et troisième argument.

sd_event_source_is_ratelimited() peut être utilisé pour interroger si la source d'événement est actuellement affectée par la limitation de débit, c'est-à-dire si elle a récemment atteint la limite de débit et est actuellement temporairement désactivée en raison de cela.

sd_event_source_set_ratelimit_expire_callback() peut être utilisé pour définir une fonction de rappel qui est appelée chaque fois que la source d'événement quitte l'état limité par débit. Notez que la fonction est appelée dans la même itération de boucle d'événements où la transition d'état s'est produite.

sd_event_source_leave_ratelimit() peut être utilisé pour réactiver immédiatement une source d'événement qui a été temporairement désactivée en raison de la limitation de débit. Cela réinitialisera les compteurs de limitation de débit pour l'intervalle de temps actuel.

La limitation de débit est actuellement implémentée pour les sources d'événements d'E/S, de minuteur, de signal, de report et inotify.

VALEUR DE RETOUR

En cas de succès, sd_event_source_set_ratelimit(), sd_event_source_set_ratelimit_expire_callback et sd_event_source_get_ratelimit() retournent un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno. sd_event_source_is_ratelimited() retourne zéro si la limitation de débit n'est actuellement pas en vigueur et supérieur à zéro si elle l'est ; il retourne un code d'erreur négatif de style errno en cas d'échec. sd_event_source_leave_ratelimit() retourne zéro si la limitation de débit n'était pas en vigueur sur la source d'événement spécifiée, et positif si elle l'était et que la limitation de débit est maintenant désactivée à nouveau ; il retourne un code d'erreur négatif de style errno en cas d'échec.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

source n'est pas un pointeur valide vers un objet sd_event_source.

Ajouté dans la version 248.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

Ajouté dans la version 248.

-EDOM

Il a été tenté d'utiliser la fonctionnalité de limitation de débit sur un type de source d'événement qui ne prend pas en charge la limitation de débit.

Ajouté dans la version 248.

-ENOEXEC

sd_event_source_get_ratelimit() a été appelé sur une source d'événement pour laquelle la limitation de débit n'est pas configurée.

Ajouté dans la version 248.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme où aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_source_set_ratelimit(), sd_event_source_get_ratelimit() et sd_event_source_is_ratelimited() ont été ajoutés dans la version 248.

sd_event_source_set_ratelimit_expire_callback() a été ajouté dans la version 250.

sd_event_source_leave_ratelimit() a été ajouté dans la version 254.

archlinux

archlinux is a Linux distribution for computers with x86-64 architectures.

It is a member of the Linux family of operating systems and is a popular choice for users who want a system that is customizable, up-to-date, and has a strong community.

It is also known for its simplicity and its focus on providing a minimal base system that users can build upon.

Key features

  • Rolling release: Arch Linux is a rolling release distribution, which means that it is constantly updated with the latest software packages.
  • Simplicity: Arch Linux is designed to be simple and straightforward, with a minimal base system that users can customize to their needs.
  • Customization: Arch Linux is highly customizable, allowing users to install only the software they need and configure their system to their preferences.
  • Arch User Repository (AUR): The AUR is a community-driven repository that contains a vast collection of software packages that are not available in the official repositories.
  • Documentation: Arch Linux has excellent documentation, including the Arch Wiki, which is a comprehensive resource for users of all levels.

Installation

The installation of Arch Linux is done through a command-line installer. This may seem daunting to new users, but it provides a great deal of flexibility and control over the installation process.

The installation process typically involves partitioning the disks, installing the base system, configuring the system, and installing a boot loader.

Community

Arch Linux has a vibrant and active community of users and developers. This community provides support through forums, mailing lists, and the Arch Wiki.

The community is also responsible for maintaining the AUR and contributing to the development of Arch Linux.

Who is Arch Linux for?

Arch Linux is best suited for users who:

  • Are comfortable with the command line.
  • Want a highly customizable system.
  • Prefer a rolling release model.
  • Are willing to spend time learning and configuring their system.

It is not recommended for beginners who are new to Linux and prefer a more user-friendly graphical installer.
