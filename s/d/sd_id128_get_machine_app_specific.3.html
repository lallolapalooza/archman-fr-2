SD_ID128_GET_MACHINE(3) sd_id128_get_machine SD_ID128_GET_MACHINE(3)

NOM

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Récupérer des identifiants 128 bits

SYNOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPTION

sd_id128_get_machine() renvoie l'ID machine de l'hôte en cours d'exécution. Il lit et analyse le fichier machine-id(5). Cette fonction met en cache l'ID machine en interne pour que la récupération de l'ID machine soit une opération peu coûteuse. Cet ID peut être utilisé partout où un identifiant unique pour le système local est nécessaire. Cependant, il est recommandé d'utiliser cet ID tel quel uniquement dans des environnements confiants. Dans des environnements non fiables, il est recommandé de dériver un ID spécifique à l'application à partir de cet ID machine, d'une manière irréversible (cryptographiquement sécurisée). Pour faciliter cela, sd_id128_get_machine_app_specific() est fourni, voir ci-dessous.

sd_id128_get_app_specific() renvoie un ID machine qui est une combinaison des paramètres base et app_id. En interne, cette fonction calcule HMAC-SHA256 du paramètre app_id indexé par le paramètre base, et tronque ce résultat pour tenir dans sd_id128_t et le transforme en un UUID valide de variante 1 version 4, conformément à RFC 4122[1]. Aucun des deux paramètres d'entrée ne peut être calculé à partir du paramètre de sortie ret.

sd_id128_get_machine_app_specific() est similaire à sd_id128_get_machine(), mais récupère un ID machine spécifique à l'application identifiée par l'ID d'application indiqué. Il est recommandé d'utiliser cette fonction au lieu de sd_id128_get_machine() lors du passage d'un ID à des environnements non fiables, afin de s'assurer que l'ID machine d'origine ne puisse pas être déterminé extérieurement. De cette manière, l'ID utilisé par l'application reste stable sur une machine donnée, mais ne peut pas être facilement corrélé avec les ID utilisés dans d'autres applications sur la même machine. L'ID spécifique à l'application doit être généré via un outil comme systemd-id128 new, et peut être compilé dans l'application. Cette fonction renverra le même ID spécifique à l'application pour chaque combinaison d'ID machine et d'ID d'application. En interne, cette fonction appelle sd_id128_get_app_specific() avec le résultat de sd_id128_get_machine() et le paramètre app_id.

sd_id128_get_boot() renvoie l'ID de démarrage du noyau en cours d'exécution. Il lit et analyse le fichier /proc/sys/kernel/random/boot_id exposé par le noyau. Il est généré aléatoirement tôt au démarrage et est unique pour chaque instance de noyau en cours d'exécution. Voir random(4) pour plus d'informations. Cette fonction met également en cache l'ID renvoyé en interne pour faire de cet appel une opération peu coûteuse. Il est recommandé d'utiliser cet ID tel quel uniquement dans des environnements confiants. Dans des environnements non fiables, il est recommandé de dériver un ID spécifique à l'application en utilisant sd_id128_get_boot_app_specific(), voir ci-dessous.

sd_id128_get_boot_app_specific() est analogue à sd_id128_get_machine_app_specific(), mais renvoie un ID qui change entre les redémarrages. Certaines machines peuvent être utilisées pendant une longue période sans redémarrage, d'où l'ID de démarrage peut rester constant pendant une longue période, et avoir des propriétés similaires à l'ID machine pendant cette période.

sd_id128_get_invocation() renvoie l'ID d'invocation du service actuellement exécuté. Dans son implémentation actuelle, il essaie de lire et d'analyser les éléments suivants :

•La variable d'environnement $INVOCATION_ID que le gestionnaire de services définit lors de l'activation d'un service.
•Une entrée dans la keyring du noyau que le gestionnaire de services système définit lors de l'activation d'un service.

Voir systemd.exec(5) pour les détails. L'ID est mis en cache en interne. À l'avenir, un mécanisme différent pour déterminer l'ID d'invocation pourrait être ajouté.

sd_id128_get_invocation_app_specific() dérive un ID spécifique à l'application de l'ID d'invocation.

Notez que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() et sd_id128_get_invocation_app_specific renvoient toujours des ID compatibles UUID Variante 1 Version 4. sd_id128_get_machine() renverra également un ID compatible UUID Variante 1 Version 4 lors de nouvelles installations, mais pourrait ne pas le faire sur les anciennes. Il est possible de convertir l'ID machine de manière non réversible en un ID compatible UUID Variante 1 Version 4. Pour plus d'informations, voir machine-id(5). Il est donc garanti que ces fonctions ne renverront jamais l'ID composé de tous les bits zéro ou tous les bits un (SD_ID128_NULL, SD_ID128_ALLF) - avec la possible exception de sd_id128_get_machine(), comme mentionné.

Pour plus d'informations sur le type "sd_id128_t", voir sd-id128(3).

VALEUR DE RETOUR

Ces appels renvoient 0 en cas de succès (auquel cas ret est rempli), ou un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENOENT

Renvoyé par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque /etc/machine-id est manquant.

Ajouté dans la version 242.

-ENOMEDIUM

Renvoyé par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque /etc/machine-id est vide ou composé uniquement de zéros. Également renvoyé par sd_id128_get_invocation() lorsque l'ID d'invocation est composé uniquement de zéros.

Ajouté dans la version 242.

-ENOPKG

Renvoyé par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque le contenu de /etc/machine-id est "non initialisé".

Ajouté dans la version 253.

-ENOSYS

Renvoyé par sd_id128_get_boot() et sd_id128_get_boot_app_specific() lorsque /proc/ n'est pas monté.

Ajouté dans la version 253.

-ENXIO

Renvoyé par sd_id128_get_invocation() si aucun ID d'invocation n'est défini. Également renvoyé par sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), et sd_id128_get_boot_app_specific() lorsque le paramètre app_id est composé uniquement de zéros.

Ajouté dans la version 242.

-EUCLEAN

Renvoyé par n'importe laquelle des fonctions décrites ici lorsque la valeur configurée a un format invalide.

Ajouté dans la version 253.

-EPERM

Les informations demandées n'ont pas pu être récupérées en raison d'autorisations insuffisantes.

Ajouté dans la version 242.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr en multithreading. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

EXEMPLES

Exemple 1. ID machine spécifique à l'application

Tout d'abord, générez l'appli

tion ID:

$ systemd-id128 -p nouveau
En tant que chaîne :
c273277323db454ea63bb96e79b53e97
En tant qu'UUID :
c2732773-23db-454e-a63b-b96e79b53e97
En tant que macro man:sd-id128(3) :
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Ensuite, utilisez le nouvel identifiant dans une application exemple :

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Notre ID d'application : " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
