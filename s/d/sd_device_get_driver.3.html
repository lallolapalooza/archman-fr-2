SD_DEVICE_GET_SYSPATH(3) sd_device_get_syspath SD_DEVICE_GET_SYSPATH(3)

NOM

sd_device_get_syspath, sd_device_get_devpath, sd_device_get_sysname, sd_device_get_sysnum, sd_device_get_subsystem, sd_device_get_driver_subsystem, sd_device_get_devtype, sd_device_get_devname, sd_device_get_devnum, sd_device_get_ifindex, sd_device_get_driver, sd_device_get_diskseq, sd_device_get_device_id - Retourne divers champs des objets appareil

SYNOPIS

#include <systemd/sd-device.h>

int sd_device_get_syspath(sd_device *device, const char **ret);

int sd_device_get_devpath(sd_device *device, const char **ret);

int sd_device_get_sysname(sd_device *device, const char **ret);

int sd_device_get_sysnum(sd_device *device, const char **ret);

int sd_device_get_subsystem(sd_device *device, const char **ret);

int sd_device_get_driver_subsystem(sd_device *device, const char **ret);

int sd_device_get_devtype(sd_device *device, const char **ret);

int sd_device_get_devname(sd_device *device, const char **ret);

int sd_device_get_devnum(sd_device *device, dev_t *ret);

int sd_device_get_ifindex(sd_device *device, int *ret);

int sd_device_get_driver(sd_device *device, const char **ret);

int sd_device_get_diskseq(sd_device *device, uint64_t *ret);

int sd_device_get_device_id(sd_device *device, const char **ret);

DESCRIPTION

sd_device_get_syspath() retourne le chemin sysfs de l'objet appareil spécifié, incluant le préfixe /sys. Exemple : /sys/devices/virtual/tty/tty7

sd_device_get_devpath() retourne le chemin sysfs de l'objet appareil spécifié, excluant le préfixe /sys. Exemple : /devices/virtual/tty/tty7

sd_device_get_sysname() retourne le nom sysfs de l'objet appareil spécifié, c'est-à-dire le dernier composant du chemin sysfs. Exemple : "tty7" pour l'appareil /sys/devices/virtual/tty/tty7

sd_device_get_sysnum() retourne le numéro de périphérique sysfs de l'objet appareil spécifié, c'est-à-dire le suffixe numérique du dernier composant du chemin sysfs. Exemple : "7" pour l'appareil /sys/devices/virtual/tty/tty7

sd_device_get_subsystem() retourne le sous-système noyau de l'objet appareil spécifié. Il s'agit d'une courte chaîne pouvant tenir dans un nom de fichier, et ne contient donc pas de slash et ne peut pas être vide. Exemple : "tty", "block" ou "net".

sd_device_get_driver_subsystem() retourne le type de bus connecté des appareils chargés par l'objet appareil du pilote spécifié. Par exemple, lorsque le périphérique du pilote "iwlwifi" est spécifié, qui est utilisé par les interfaces réseau sans fil connectées au bus PCI, cette fonction retourne "pci". Cette fonction ne réussit que si sd_device_get_subsystem() retourne "drivers". Exemple : "pci", "i2c", ou "hid".

sd_device_get_devtype() retourne le type de périphérique de l'objet appareil spécifié, si le sous-système gère plusieurs types de périphériques. Exemple : pour les appareils du sous-système "block", cela peut être "disk" ou "partition"

sd_device_get_devname() retourne le chemin du nœud de périphérique de l'objet appareil spécifié si l'appareil possède un nœud de périphérique. Exemple : pour /sys/devices/virtual/tty/tty7, la chaîne /dev/tty7 est généralement retournée.

sd_device_get_devnum() retourne le numéro majeur/mineur du nœud de périphérique (c'est-à-dire dev_t) de l'objet appareil spécifié si l'appareil possède un nœud de périphérique (c'est-à-dire celui retourné par sd_device_get_devname()). Pour les appareils appartenant au sous-système "block", cela fait référence à un nœud de périphérique de bloc, dans tous les autres cas à un nœud de périphérique de caractère. Exemple : pour l'appareil /sys/devices/virtual/tty/tty7, cela retourne généralement le numéro de périphérique avec majeur/mineur "4:7".

sd_device_get_ifindex() retourne l'index de l'interface réseau de l'objet appareil spécifié, si l'appareil encapsule un appareil d'interface réseau, c'est-à-dire appartient au sous-système "net". Exemple : l'interface "lo" a généralement l'index d'interface 1.

sd_device_get_driver() retourne le nom du pilote noyau attaché à l'appareil. Notez que le champ pilote est défini sur les appareils consommés par le pilote, pas sur l'appareil créé par celui-ci. Exemple : un périphérique PCI /sys/bus/pci/devices/0000:00:1f.6 peut être attaché à un pilote "e1000e".

sd_device_get_diskseq() retourne le numéro de séquence de disque du noyau de l'appareil de bloc. Ce numéro augmente de manière monotone chaque fois que le support sous-jacent d'un appareil de bloc change sans que le nom de l'appareil ne change, et est pertinent pour les appareils de bloc encapsulant des appareils avec des supports changeants (par exemple, lecteurs floppy ou CD-ROM), ou des appareils de bloc en boucle. Uniquement défini pour les appareils de bloc, c'est-à-dire ceux du sous-système "block".

sd_device_get_device_id() retourne la chaîne courte qui identifie l'objet appareil. Lorsque l'ID de l'appareil obtenu par la fonction pour un objet appareil spécifié est passé à sd_device_new_from_device_id(), une nouvelle instance du même objet appareil sera obtenue. Lorsqu'un appareil de bloc ou de caractère est spécifié, qui a un nœud de périphérique correspondant, cela retourne "b" ou "c", respectivement, suivi des numéros majeur et mineur du nœud de périphérique séparés par un deux-points. Exemple : "b259:1" ou "c10:121". Lorsqu'un appareil réseau est spécifié, cela retourne "n" suivi de l'index de l'interface, qui peut être obtenu par sd_device_get_ifindex(). Exemple : "n1". Lorsqu'un appareil dans le sous-système "driver" est spécifié, cela retourne "+drivers:" suivi de son sous-système de pilote et de son nom sysfs séparés par un deux-points. Exemple : "+drivers:pci:iwlwifi" pour un objet appareil pilote dont le sous-système de pilote est "pci" et le nom sysfs est "iwlwifi". Lorsqu'un autre type d'appareil est spécifié, cette fonction retourne "+" suivi de son sous-système et de son nom sysfs séparés par un deux-points. Exemple : "+acpi:ACPI0003:00", "+input:input16", ou "+pci:0000:00:1f.6".

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

Ajouté dans la version 251.

-ENOENT

Le champ demandé n'est pas présent dans l'objet appareil.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été lancé.

HISTORIQUE

sd_device_get_driver(3)

NAME

sd_device_get_driver, sd_device_get_driver_subsystem, sd_device_get_device_id - Get device driver and ID information

SYNOPSIS

#include <systemd/sd-device.h>

int sd_device_get_driver(sd_device *device, const char **driver);
int sd_device_get_driver_subsystem(sd_device *device, const char **subsystem);
int sd_device_get_device_id(sd_device *device, const char **id);

DESCRIPTION

The sd_device_get_driver() function retrieves the name of the kernel driver controlling the device specified by device. The name is returned in the driver output parameter.

The sd_device_get_driver_subsystem() function retrieves the name of the subsystem the device belongs to (e.g. "input", "graphics", "block"). The name is returned in the subsystem output parameter.

The sd_device_get_device_id() function retrieves the device ID. The exact format of the device ID depends on the subsystem and driver, but it often corresponds to the ID_BUS, ID_MODEL, ID_SERIAL, ID_VENDOR, etc. udev properties. The value is returned in the id output parameter.

These functions do not allocate any resources and the returned strings are owned by the sd_device object.

RETURN VALUE

On success, these functions return 0. On failure, they return a negative errno value.

NOTES

These functions are wrappers around the udev_device_get_driver(), udev_device_get_subsystem() and udev_device_get_sysname() functions from libudev. They are intended to be used from C code. The strings returned in the output parameters are valid until the device object is destroyed.

HISTORY

sd_device_get_driver_subsystem() and sd_device_get_device_id() were added in version 257.

NOM

sd_device_get_driver, sd_device_get_driver_subsystem, sd_device_get_device_id - Obtenir des informations sur le pilote et l'ID du périphérique

SYNOPSIS

#include <systemd/sd-device.h>

int sd_device_get_driver(sd_device *device, const char **driver);
int sd_device_get_driver_subsystem(sd_device *device, const char **subsystem);
int sd_device_get_device_id(sd_device *device, const char **id);

DESCRIPTION

La fonction sd_device_get_driver() récupère le nom du pilote du noyau contrôlant le périphérique spécifié par device. Le nom est retourné dans le paramètre de sortie driver.

La fonction sd_device_get_driver_subsystem() récupère le nom du sous-système auquel le périphérique appartient (par exemple, "input", "graphics", "block"). Le nom est retourné dans le paramètre de sortie subsystem.

La fonction sd_device_get_device_id() récupère l'ID du périphérique. Le format exact de l'ID du périphérique dépend du sous-système et du pilote, mais il correspond souvent aux propriétés udev ID_BUS, ID_MODEL, ID_SERIAL, ID_VENDOR, etc. La valeur est retournée dans le paramètre de sortie id.

Ces fonctions ne font aucune allocation de ressources et les chaînes retournées appartiennent à l'objet sd_device.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0. En cas d'échec, elles retournent une valeur négative représentant un code d'erreur errno.

NOTES

Ces fonctions sont des wrappers autour des fonctions udev_device_get_driver(), udev_device_get_subsystem() et udev_device_get_sysname() de libudev. Elles sont destinées à être utilisées depuis du code C. Les chaînes retournées dans les paramètres de sortie sont valides jusqu'à la destruction de l'objet device.

HISTORIQUE

sd_device_get_driver_subsystem() et sd_device_get_device_id() ont été ajoutées dans la version 257.
