DESCRIPTION

sd_bus_emit_signal() est une fonction pratique pour initialiser un objet message de bus et émettre le signal D-Bus correspondant. Elle combine les fonctions sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) en un seul appel de fonction. sd_bus_emit_signalv() est équivalent à sd_bus_message_append(), à l'exception qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments.

sd_bus_emit_signal_to() et sd_bus_emit_signal_tov() sont identiques à sd_bus_emit_signal() et sd_bus_emit_signalv(), à l'exception qu'ils peuvent émettre le signal vers une seule destination. Donnez destination comme NULL pour diffuser le signal.

sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() sont utilisés pour implémenter les signaux InterfacesAdded et InterfacesRemoved de l'interface org.freedesktop.DBus.ObjectManager. Ils prennent un chemin dont les interfaces ont été modifiées comme argument et une liste variable d'interfaces qui ont été ajoutées ou supprimées, respectivement. Le dernier argument passé à sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() doit être NULL. Cela permet aux deux fonctions de déterminer en toute sécurité le nombre d'arguments d'interface passés. sd_bus_emit_interfaces_added_strv() et sd_bus_emit_interfaces_removed_strv() sont identiques à leurs homologues respectifs mais prennent tous deux la liste des interfaces comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_properties_changed() est utilisé pour implémenter le signal PropertiesChanged de l'interface org.freedesktop.DBus.Properties. Il prend un chemin d'objet, une interface et une liste variable de noms de propriétés comme arguments. Le dernier argument passé à sd_bus_emit_properties_changed() doit être NULL. Cela lui permet de déterminer en toute sécurité le nombre de noms de propriétés passés. sd_bus_emit_properties_changed_strv() est identique à sd_bus_emit_properties_changed() mais prend la liste des noms de propriétés comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_object_added() et sd_bus_emit_object_removed() sont des fonctions pratiques pour émettre les signaux InterfacesAdded ou InterfacesRemoved pour toutes les interfaces enregistrées sur un chemin d'objet spécifique, respectivement. Cela inclut toutes les tables virtuelles de repli parentes si elles ne sont pas remplacées par une table virtuelle enfant plus applicable. Cela inclut également toutes les interfaces D-Bus standard implémentées par sd-bus lui-même sur tout objet enregistré.

Notez que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() et sd_bus_emit_object_removed() nécessitent qu'un gestionnaire d'objet ait été enregistré sur le chemin d'objet donné ou l'un de ses chemins d'objet parents en utilisant sd_bus_add_object_manager(3).

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier positif ou nul. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

L'un des paramètres requis est NULL ou invalide. Une interface D-Bus réservée a été passée comme paramètre interface.

-ENOPKG

Le bus ne peut pas être résolu.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

-ENOMEM

Échec de l'allocation de mémoire.

-ESRCH

L'une des fonctions sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() ou sd_bus_emit_object_removed() a été appelée sur un objet sans gestionnaire d'objet enregistré sur son propre chemin d'objet ou l'un de ses chemins d'objet parents.

Voir les pages man de sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) pour plus d'erreurs possibles.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour le multithreading. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() que depuis une phase précoce du programme lorsque aucun autre fil d'exécution n'a été démarré.

DESCRIPTION

Ces fonctions sont utilisées pour émettre des signaux D-Bus. Elles sont conçues pour être simples à utiliser pour les cas d'utilisation courants.

Les signaux émis par ces fonctions sont envoyés au bus système ou au bus de session, en fonction de la connexion établie via sd_bus_open(3).

Les signaux OBJECT_ADDED et OBJECT_REMOVED sont utilisés pour notifier aux clients qu'un objet a été ajouté ou supprimé du bus.

Les signaux PROPERTIES_CHANGED sont utilisés pour notifier aux clients que les propriétés d'un objet ont été modifiées.

Les signaux INTERFACES_REMOVED sont utilisés pour notifier aux clients que des interfaces ont été supprimées d'un objet.

Les signaux génériques sont utilisés pour émettre n'importe quel signal.

VALEUR DE RETOUR

Ces fonctions retournent 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les codes d'erreur possibles sont.

-ENOMEM
Pas assez de mémoire pour allouer le message.
-ECHILD
Le bus est déjà fermé.
-EINVAL
Paramètres invalides.

NOTES

Ces fonctions ne doivent être appelées qu'à partir du même thread qui a créé la connexion de bus.

Le format des arguments de type `types` doit être une chaîne de caractères ASCII décrivant le type des arguments suivants, conformément aux spécifications D-Bus.
