SD_BUS_REPLY_METHOD_RETURN(3) sd_bus_reply_method_return SD_BUS_REPLY_METHOD_RETURN(3)

NOM

sd_bus_reply_method_return, sd_bus_reply_method_returnv - Répondre à un appel de méthode D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_reply_method_return(sd_bus_message *call, const char *types, ...);

int sd_bus_reply_method_returnv(sd_bus_message *call, const char *types, va_list ap);

DESCRIPTION

sd_bus_reply_method_return() envoie une réponse au message call. La chaîne de types types et les arguments qui la suivent doivent respecter le format décrit dans sd_bus_message_append(3). Si aucune réponse n'est attendue pour call, cette fonction réussit sans envoyer de réponse.

VALEUR DE RETOUR

En cas de succès, cette fonction retourne un entier non négatif. En cas d'échec, elle retourne un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre d'entrée call est NULL.

Le message call n'est pas un message d'appel de méthode.

Le message call n'est pas attaché à un bus.

Le message m n'est pas un message de réponse de méthode.

Ajouté dans la version 246.

-EPERM

Le message call a été scellé.

Ajouté dans la version 246.

-ENOTCONN

Le bus auquel le message call est attaché n'est pas connecté.

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation de mémoire.

Ajouté dans la version 246.

De plus, toute erreur renvoyée par sd_bus_send(3) peut être renvoyée.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non sécurisé pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
