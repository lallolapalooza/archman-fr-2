DESCRIPTION

sd_event_add_child() ajoute une nouvelle source d'événements d'état de processus enfant à une boucle d'événements. L'objet de la boucle d'événements est spécifié par le paramètre event, l'objet de la source d'événements est renvoyé dans le paramètre source. Le paramètre pid spécifie le PID du processus à surveiller, qui doit être un processus enfant direct du processus appelant. Le paramètre options détermine quels changements d'état seront surveillés. Il doit contenir un masque OR de WEXITED (surveiller la terminaison du processus enfant), WSTOPPED (surveiller l'arrêt du processus enfant par un signal), et WCONTINUED (surveiller la reprise du processus enfant par un signal). Voir waitid(2) pour plus d'informations.

Le paramètre handler doit être une fonction à appeler lorsque le processus change d'état, ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure siginfo_t contenant des informations sur l'événement du processus enfant. Le gestionnaire peut renvoyer une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul gestionnaire peut être installé pour un processus enfant spécifique. Le gestionnaire est activé pour un seul événement (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire renvoie un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, soit elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet de source d'événements, utilisez sd_event_source_unref(3), mais notez que la source d'événements n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événements sont lâchées. Pour s'assurer qu'une source d'événements ne se déclenche plus, même s'il y a encore une référence à elle, envisagez de définir la source d'événements sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Le signal SIGCHLD doit être bloqué dans tous les threads avant que cette fonction ne soit appelée (en utilisant sigprocmask(2) ou pthread_sigmask(3)).

Si le deuxième paramètre de sd_event_add_child() est passé comme NULL, aucune référence à l'objet de la source d'événements n'est renvoyée. Dans ce cas, la source d'événements est considérée comme "flottante", et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Notez que la fonction handler est invoquée à un moment où le processus enfant n'est pas encore collecté (et reste donc exposé comme un processus zombie par le noyau). Cependant, l'enfant sera collecté automatiquement après le retour de la fonction. Les processus enfants pour lesquels aucune source d'événements d'état de processus enfant n'est installée ne seront pas collectés par l'implémentation de la boucle d'événements.

Si le paramètre handler de sd_event_add_child() est NULL, et que la source d'événements se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Si à la fois une source d'événements d'état de processus enfant et une source d'événements de signal SIGCHLD sont installées dans la même boucle d'événements, les priorités configurées des sources d'événements décident quelle source d'événements est traitée en premier. Si le gestionnaire de signaux est traité en premier, il devrait laisser les processus enfants pour lesquels des sources d'événements d'état de processus enfant sont installés non collectés.

sd_event_add_child_pidfd() est similaire à sd_event_add_child() mais prend un descripteur de fichier référençant le processus ("pidfd") au lieu du PID numérique. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2) et les appels associés. Le descripteur de fichier passé n'est pas fermé lorsque la source d'événements est libérée à nouveau, à moins que sd_event_source_set_child_pidfd_own() ne soit utilisé pour activer ce comportement. Notez que quel que soit sd_event_add_child() ou sd_event_add_child_pidfd() utilisé pour allouer une source d'événements, le processus surveillé doit être un processus enfant direct du processus appelant. Dans les deux cas, SIGCHLD doit être bloqué dans le processus appelant.

sd_event_source_get_child_pid() récupère le PID configuré d'une source d'événements d'état de processus enfant créée précédemment avec sd_event_add_child(). Elle prend l'objet de la source d'événements comme paramètre source et un pointeur vers une variable pid_t pour y renvoyer l'identifiant du processus.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier référençant le processus surveillé ("pidfd"). La boucle d'événements utilise en interne des pidfd pour surveiller les processus enfants, que les sources d'événements individuelles soient allouées via sd_event_add_child() ou sd_event_add_child_pidfd(). Si le second appel a été utilisé pour allouer la source d'événements, cette fonction renvoie le descripteur de fichier d'origine utilisé pour l'allocation. Cet appel prend l'objet de la source d'événements comme paramètre source et renvoie le descripteur de fichier numérique.

sd_event_source_get_child_pidfd_own() peut être utilisé pour interroger si le pidfd que la source d'événements encapsule doit être fermé lorsque la source d'événements est libérée. Cette fonction renvoie zéro si le pidfd doit rester ouvert, et une valeur positive s'il doit être fermé automatiquement. Par défaut, ce paramètre vaut un si la source d'événements a été allouée via sd_event_add_child() et zéro si elle a été allouée via sd_event_add_child_pidfd(). La fonction sd_event_source_set_child_pidfd_own() peut être utilisée pour modifier le paramètre et prend un paramètre booléen avec le nouveau réglage.

sd_event_source_get_child_process_own() peut être utilisé pour interroger si le processus que la source d'événements surveille doit être tué (avec SIGKILL) et collecté lorsque la source d'événements est libérée. Cette fonction renvoie zéro si le processus doit rester en cours d'exécution, et une valeur positive s'il doit être tué et collecté automatiquement. Par défaut, ce paramètre est désactivé. VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque vide dans options ou d'un masque contenant des valeurs autres qu'une combinaison de WEXITED, WSTOPPED et WCONTINUED.

-EBUSY

Un gestionnaire est déjà installé pour ce processus enfant, ou SIGCHLD n'est pas bloqué.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

-EDOM

La source d'événements passée n'est pas une source d'événements de processus enfant.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour l'utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

EXEMPLE

Exemple 1. Boucler la sortie lorsque l'enfant se termine

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* Le signal SIGCHLD doit être bloqué pour que sd_event_add_child fonctionne */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* enfant */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Créer la boucle d'événements par défaut */
    sd_event_default(&e);
    assert(e);
    /* Nous créons une source d'événements enfant flottante (attachée à 'e').
     * Le gestionnaire par défaut sera appelé avec 666 comme données utilisateur, ce qui
     * deviendra la valeur de sortie de la boucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
