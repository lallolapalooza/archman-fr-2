NOM

int sd_session_get_state(const char *session, char **state);

int sd_session_get_seat(const char *session, char **seat);

int sd_session_get_start_time(const char *session, uint64_t *usec);

int sd_session_get_service(const char *session, char **service);

int sd_session_get_type(const char *session, char **type);

int sd_session_get_class(const char *session, char **class);

int sd_session_get_desktop(const char *session, char **desktop);

int sd_session_get_display(const char *session, char **display);

int sd_session_get_vt(const char *session, unsigned int *vt);

DESCRIPTION

sd_session_is_active() peut être utilisé pour déterminer si la session identifiée par l'identifiant de session spécifié est actuellement active (c'est-à-dire actuellement au premier plan et disponible pour l'entrée utilisateur) ou non.

sd_session_is_remote() peut être utilisé pour déterminer si la session identifiée par l'identifiant de session spécifié est une session à distance (c'est-à-dire si son hôte distant est connu) ou non.

sd_session_get_state() peut être utilisé pour déterminer l'état de la session identifiée par l'identifiant de session spécifié. Les états suivants sont actuellement connus : « online » (session connectée, mais session inactive, c'est-à-dire pas au premier plan), « active » (session connectée et active, c'est-à-dire au premier plan), « closing » (session nommément déconnectée, mais certains processus lui appartenant sont toujours présents). À l'avenir, des états supplémentaires pourraient être définis ; le code client doit être écrit pour être robuste aux chaînes d'état supplémentaires retournées. Cette fonction est une version plus générique de sd_session_is_active(). La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_uid() peut être utilisé pour déterminer l'identifiant utilisateur de l'utilisateur Unix auquel appartient la session identifiée par l'identifiant de session spécifié.

sd_session_get_username() peut être utilisé pour déterminer le nom de l'utilisateur Unix auquel appartient la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_seat() peut être utilisé pour déterminer l'identifiant du siège auquel appartient la session identifiée par l'identifiant de session spécifié. Notez que toutes les sessions ne sont pas attachées à un siège ; cet appel échouera (retournant -ENODATA) pour elles. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_start_time() peut être utilisé pour déterminer l'heure de démarrage de la session identifiée par l'identifiant de session spécifié. L'argument usec est en microsecondes depuis l'époque (CLOCK_REALTIME).

sd_session_get_service() peut être utilisé pour déterminer le nom du service (tel que passé lors de la configuration de la session PAM) qui a enregistré la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_type() peut être utilisé pour déterminer le type de la session identifiée par l'identifiant de session spécifié. La chaîne retournée est l'une des « x11 », « wayland », « tty », « mir » ou « unspecified » et doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_class() peut être utilisé pour déterminer la classe de la session identifiée par l'identifiant de session spécifié. La chaîne retournée est l'une des « user », « user-early », « user-light », « user-early-light », « user-incomplete », « greeter », « lock-screen », « background », « background-light », « manager » ou « manager-early » et doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_desktop() peut être utilisé pour déterminer la marque du bureau fonctionnant dans la session identifiée par l'identifiant de session spécifié. Ce champ peut être défini librement par les environnements de bureau et ne suit aucune formatation spéciale. Cependant, il est fortement recommandé aux bureaux d'utiliser les mêmes identifiants et la même casse que pour $XDG_CURRENT_DESKTOP, tels que définis par la Spécification de l'entrée de bureau[1]. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_display() peut être utilisé pour déterminer l'affichage X11 de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_leader() peut être utilisé pour déterminer le PID du leader de la session identifiée par l'identifiant de session spécifié.

sd_session_get_remote_host() peut être utilisé pour déterminer le nom d'hôte distant de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_remote_user() peut être utilisé pour déterminer le nom d'utilisateur distant de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation. Notez que cette valeur est rarement connue du système, et même dans ce cas, elle ne doit pas être utilisée comme base fiable.

sd_session_get_tty() peut être utilisé pour déterminer le périphérique TTY de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_session_get_vt() peut être utilisé pour déterminer le numéro de VT de la session identifiée par l'identifiant de session spécifié. Cette fonction retournera une erreur si le siège ne prend pas en charge les VT.

Si le paramètre session de l'une de ces fonctions est passé comme NULL, l'opération est exécutée pour la session dont le processus appelant est membre, s'il y en a une.

VALEUR DE RETOUR

Si le test réussit, sd_session_is_active() et sd_session_is_remote() retournent un entier positif ; en cas d'échec, 0. En cas de succès, sd_session_get_state(), sd_session_get_uid(), sd_session_get_username(), sd_session_get_seat(), sd_session_get_service(), sd_session_get_type(), sd_session_get_class

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENXIO

La session spécifiée n'existe pas.

-ENODATA

Le champ donné n'est pas spécifié pour la session décrite.

-EINVAL

Un paramètre d'entrée était invalide (hors plage, ou NULL, là où cela n'est pas accepté).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
