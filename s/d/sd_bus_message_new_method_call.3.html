SD_BUS_MESSAGE_NEW_METHOD_CALL(3) sd_bus_message_new_method_call SD_BUS_MESSAGE_NEW_METHOD_CALL(3)

NOM

sd_bus_message_new_method_call, sd_bus_message_new_method_return - Créer un message d'appel de méthode

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_call(sd_bus *bus, sd_bus_message **m, const char *destination, const char *path, const char *interface, const char *member);

int sd_bus_message_new_method_return(sd_bus_message *call, sd_bus_message **m);

DESCRIPTION

La fonction sd_bus_message_new_method_call() crée un nouvel objet message de bus qui encapsule un appel de méthode D-Bus, et le renvoie dans le paramètre de sortie m. L'appel sera effectué sur la destination destination, le chemin path, sur l'interface interface, le membre member.

En bref, la destination est un nom séparé par des points qui identifie un service connecté au bus. Le path est un identifiant séparé par des barres obliques d'un objet dans la destination qui ressemble à un chemin de système de fichiers. La signification de ce chemin est définie par la destination. L'interface est un nom séparé par des points qui ressemble à un nom d'interface Java qui identifie un groupe de méthodes et de signaux pris en charge par l'objet identifié par le chemin. Les méthodes et les signaux sont collectivement appelés membres et sont identifiés par un nom simple composé de lettres ASCII, de chiffres et d'underscores. Voir le Tutoriel D-Bus[1] pour une explication approfondie.

Le paramètre destination peut être NULL. Le paramètre interface peut être NULL, si la destination n'a qu'un seul membre du nom donné et qu'il n'y a pas d'ambiguïté si le nom de l'interface est omis.

Notez qu'il s'agit d'une interface de bas niveau. Voir sd_bus_call_method(3) pour une manière plus pratique d'appeler les méthodes D-Bus.

La fonction sd_bus_message_new_method_return() crée un nouveau objet message de bus qui est une réponse à l'appel de méthode call et le renvoie dans le paramètre de sortie m. Le paramètre call doit être un message d'appel de méthode. L'expéditeur de call est utilisé comme destination.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre de sortie m est NULL.

Le paramètre destination n'est pas NULL et n'est pas un nom de service D-Bus valide ("org.quelquechose.QuelqueChose"), le paramètre path n'est pas un chemin D-Bus valide ("/un/chemin/objet"), le paramètre interface n'est pas NULL et n'est pas un nom d'interface D-Bus valide ("une.interface.nom"), ou le paramètre member n'est pas un membre D-Bus valide ("Nom").

Le paramètre call n'est pas un objet d'appel de méthode.

-ENOTCONN

Le paramètre de bus bus est NULL ou le bus n'est pas connecté.

-ENOMEM

Échec de l'allocation mémoire.

-EPERM

Le paramètre call n'est pas scellé.

-EOPNOTSUPP

Le message call n'a pas de cookie.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

EXEMPLES

Exemple 1. Faire un appel à une méthode D-Bus qui prend un seul paramètre

/* SPDX-License-Identifier: MIT-0 */
/* Ceci est équivalent à :
 * busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 \
 *       org.freedesktop.systemd1.Manager GetUnitByPID $$
 *
 * Compiler avec 'cc print-unit-path.c -lsystemd'
 */
#include <errno.h>
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
#define DESTINATION "org.freedesktop.systemd1"
#define PATH        "/org/freedesktop/systemd1"
#define INTERFACE   "org.freedesktop.systemd1.Manager"
#define MEMBER      "GetUnitByPID"
static int log_error(int error, const char *message) {
  fprintf(stderr, "%s: %s\n", message, strerror(-error));
  return error;
}
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  _cleanup_(sd_bus_error_free) sd_bus_error error = SD_BUS_ERROR_NULL;
  _cleanup_(sd_bus_message_unrefp) sd_bus_message *reply = NULL, *m = NULL;
  int r;
  r = sd_bus_open_system(&bus);
  if (r < 0)
    return log_error(r, "Échec de l'acquisition du bus");
  r = sd_bus_message_new_method_call(bus, &m,
                                     DESTINATION, PATH, INTERFACE, MEMBER);
  if (r < 0)
    return log_error(r, "Échec de la création du message de bus");
  r = sd_bus_message_append(m, "u", (unsigned) getpid());
  if (r < 0)
    return log_error(r, "Échec de l'ajout au message de bus");
  r = sd_bus_call(bus, m, -1, &error, &reply);
  if (r < 0)
    return log_error(r, "l'appel de méthode %s a échoué");
  const char *ans;
  r = sd_bus_message_read(reply, "o", &ans);
  if (r < 0)
    return log_error(r, "Échec de la lecture de la réponse");
  printf("Le chemin de l'unité est \"%s\".\n", ans);
  return 0;
}

Ceci définit un programme minimalement utile qui ouvrira une connexion au bus, créera un objet message, l'enverra, attendra la réponse, et finalement extraira et imprimera la réponse. Il gère les erreurs et la gestion de la mémoire.

HISTORIQUE

sd_bus_message_new_method_call() et sd_bus_message_new_method_return() ont été ajoutées dans la version 246.

sd_bus_message_new_method_call - Crée un nouveau message d'appel de méthode bus

Sections

sd_bus_message_new_method_call

Syntaxe

sd_bus_message_new_method_call, sd_bus_message_new_method_call_async

Description

sd_bus_message_new_method_call et sd_bus_message_new_method_call_async allouent et initialisent un nouveau message de type "call" sur le bus système ou utilisateur. Le nouveau message sera configuré pour un appel de méthode sur le service, l'objet, l'interface et la méthode spécifiés.

Le paramètre bus est un pointeur vers une connexion bus, tel que retourné par sd_bus_open_user() ou sd_bus_open_system().

Le paramètre call est un pointeur vers une variable de pointeur de message. Si l'allocation réussit, le nouveau message sera stocké dans la variable pointée par call.

Le paramètre service est la chaîne de caractères du nom du service D-Bus à appeler (par exemple, "org.freedesktop.NetworkManager"). Si ce paramètre est NULL, l'appel de méthode sera envoyé au bus "system" par défaut.

Le paramètre path est la chaîne de caractères du chemin de l'objet sur lequel la méthode doit être appelée (par exemple, "/org/freedesktop/NetworkManager/Devices/0").

Le paramètre interface est la chaîne de caractères de l'interface D-Bus sur laquelle la méthode doit être appelée (par exemple, "org.freedesktop.DBus.Properties"). Si ce paramètre est NULL, il utilisera l'interface par défaut du bus.

Le paramètre member est la chaîne de caractères du nom de la méthode à appeler (par exemple, "Get").

sd_bus_message_new_method_call_async est similaire à sd_bus_message_new_method_call, mais elle prend en plus un paramètre cookie. Ce cookie sera renvoyé à la fonction de rappel lorsqu'une réponse sera reçue pour cet appel de méthode.

Valeur de retour

En cas de succès, ces fonctions retournent 0. En cas d'échec, elles retournent un code d'erreur négatif.

Notes

Le message retourné par ces fonctions doit être libéré avec sd_bus_message_unref() lorsqu'il n'est plus nécessaire.

Exemples

// Exemple d'utilisation de sd_bus_message_new_method_call


    sd_bus_message *message;
    int r;

    r = sd_bus_message_new_method_call(bus, &message,
                                       "org.freedesktop.NetworkManager",
                                       "/org/freedesktop/NetworkManager/Devices/0",
                                       "org.freedesktop.DBus.Properties",
                                       "Get");
    if (r < 0) {
        fprintf(stderr, "Erreur lors de la création du message : %s\n", strerror(-r));
        // Gérer l'erreur
    } else {
        // Ajouter des arguments au message si nécessaire
        // ...
        // Envoyer le message
        // ...
        sd_bus_message_unref(message);
    }

Historique

La fonction sd_bus_message_new_method_call a été introduite dans systemd v225.
