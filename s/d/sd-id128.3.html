DESCRIPTION

sd-id128.h fait partie de libsystemd(3) et fournit des APIs pour générer, convertir et comparer des identifiants 128 bits. Les identifiants 128 bits traités et générés par ces APIs sont une généralisation des UUIDs OSF tels que définis par RFC 4122[1] mais utilisent un format de chaîne plus simple. Ces fonctions n'imposent aucune structure aux identifiants utilisés, contrairement aux UUIDs OSF ou aux GUIDs Microsoft, mais sont largement compatibles avec ces types d'identifiants.

Un identifiant 128 bits est implémenté comme le type union suivant :

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Cette union permet d'accéder à l'identifiant 128 bits comme 16 octets séparés ou deux mots de 64 bits. Il est généralement plus sûr d'accéder aux composants de l'identifiant par leur tableau de 8 bits pour éviter les problèmes d'endianness. Cette union est destinée à être passée par valeur (plutôt que par référence) et peut être manipulée directement par les clients.

Quelques macros sont définies pour désigner et décoder des identifiants 128 bits :

SD_ID128_MAKE() est utilisé pour écrire un identifiant constant dans le code source. Une utilisation courante consiste à attribuer un nom à un identifiant en utilisant cette macro :

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL définit un identifiant composé uniquement d'octets NUL (c'est-à-dire tous les bits à zéro).

SD_ID128_ALLF définit un identifiant composé uniquement d'octets 0xFF (c'est-à-dire tous les bits à un).

SD_ID128_MAKE_STR() est similaire à SD_ID128_MAKE(), mais crée une expression const char* qui peut être utilisée de manière pratique dans les formats de message et similaires :

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match pour les core dumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convertit les identifiants constants en chaînes constantes pour la sortie. L'exemple de code suivant affichera la chaîne "fc2e22bc6ee647b6b90729ab34a250b1" :

int main(int argc, char *argv[]) {
  puts("Match pour les core dumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR et SD_ID128_FORMAT_VAL() sont utilisés pour formater un identifiant dans une chaîne de format printf(3), comme illustré dans l'exemple suivant :

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("L'ID encodé dans ce fichier C est " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR et SD_ID128_MAKE_UUID_STR() sont similaires à SD_ID128_FORMAT_STR et SD_ID128_MAKE_STR(), mais incluent des tirets de séparation pour se conformer à la "représentation canonique des UUID[2]". Ils formatent la chaîne selon les règles de la variante 1 de RFC4122[1], c'est-à-dire en convertissant depuis l'ordre des octets Big Endian. Cela correspond au comportement de la plupart des autres infrastructures de l'espace utilisateur Linux. Il est probablement préférable d'éviter les UUID d'autres variantes, afin d'éviter des ambiguïtés inutiles. Tous les identifiants 128 bits générés par les APIs sd-id128 sont strictement conformes aux UUID de variante 1 version 4, conformément à la RFC 4122.

sd_id128_equal() compare deux identifiants 128 bits :

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() est similaire à sd_id128_equal(), mais le premier identifiant est formaté comme const char*. Les mêmes restrictions s'appliquent qu'au premier argument de sd_id128_from_string().

sd_id128_is_null() vérifie si un identifiant est composé uniquement d'octets NUL :

assert(sd_id128_is_null(SD_ID128_NULL));

De même, sd_id128_is_allf() vérifie si un identifiant est composé uniquement d'octets 0xFF (tous les bits à un) :

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() prend une liste d'identifiants et retourne vrai si le premier argument est égal à l'un des arguments suivants. La liste d'arguments est terminée par un sentinelle SD_ID128_NULL, qui doit être présent.

sd_id128_in_set() est une fonction de commodité qui prend une liste d'identifiants et retourne vrai si le premier argument est égal à l'un des arguments suivants :

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() est définie comme une macro sur sd_id128_in_set_sentinel(), ajoutant automatiquement le sentinelle SD_ID128_NULL. Puisque sd_id128_in_set_sentinel() utilise SD_ID128_NULL comme sentinelle, SD_ID128_NULL ne peut pas être placé autrement dans la liste d'arguments.

sd_id128_in_setv() est similaire à sd_id128_in_set_sentinel(), mais prend un argument struct varargs.

De nouveaux identifiants aléatoires peuvent être générés avec la commande new de systemd-id128(1).

Voir sd_id128_to_string(3), sd_id128_randomize(3) et sd_id128_get_machine(3) pour des informations sur d'autres implémentations

DESCRIPTION

Ces fonctions comparent les identifiants ID128. Un identifiant ID128 est un tableau de 16 octets. Les fonctions de comparaison d'identifiants travaillent directement sur les structures sd_id128_t.

sd_id128_equal compare deux identifiants a et b et retourne vrai s'ils sont identiques.

sd_id128_string_equal compare deux identifiants représentés sous forme de chaînes de caractères (voir sd_id128_to_string(3)) et retourne vrai s'ils sont identiques.

sd_id128_is_null vérifie si l'identifiant id est l'identifiant nul (tous les octets sont à zéro).

sd_id128_is_allf vérifie si l'identifiant id est l'identifiant « all-f » (tous les octets sont à 0xff).

sd_id128_in_setv vérifie si l'identifiant id est présent dans l'ensemble set qui contient n identifiants.

sd_id128_in_set_sentinel est similaire à sd_id128_in_setv, mais l'ensemble set est terminé par un identifiant nul (tous les octets à zéro).

sd_id128_in_set est une fonction variadique qui vérifie si l'identifiant id est présent dans la liste d'arguments qui suit, jusqu'à ce qu'un identifiant nul soit rencontré.

Toutes ces fonctions retournent 1 si la condition est vraie, et 0 si elle est fausse. Elles retournent un nombre négatif en cas d'erreur.

Les fonctions qui prennent des chaînes de caractères en entrée s'attendent à ce qu'elles soient dans le format canonique des UUID (voir RFC 4122).

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
