SD_JOURNAL_ADD_MATCH(3) sd_journal_add_match SD_JOURNAL_ADD_MATCH(3)

NOM

sd_journal_add_match, sd_journal_add_disjunction, sd_journal_add_conjunction, sd_journal_flush_matches - Ajouter ou supprimer des correspondances d'entrées

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_add_match(sd_journal *j, const void *data, size_t size);

int sd_journal_add_disjunction(sd_journal *j);

int sd_journal_add_conjunction(sd_journal *j);

void sd_journal_flush_matches(sd_journal *j);

DESCRIPTION

sd_journal_add_match() ajoute une correspondance pour filtrer les entrées du fichier journal. Les correspondances appliquées avec cet appel filtreront ce qui peut être itéré et lu depuis le fichier journal via des appels tels que sd_journal_next(3) et sd_journal_get_data(3). Le paramètre data doit être de la forme "CHAMP=valeur", où la partie CHAMP est une courte chaîne en majuscules composée uniquement de 0-9, A-Z et du trait de soulignement ; elle ne peut pas commencer par deux traits de soulignement ni être une chaîne vide. La partie valeur peut être n'importe quoi, y compris binaire. Le paramètre size spécifie le nombre d'octets dans data (c'est-à-dire la longueur de CHAMP, plus un, plus la longueur de valeur). Le paramètre size peut aussi être spécifié comme 0, dans ce cas data doit être une chaîne terminée par un caractère NUL, et les octets avant le zéro terminateur sont utilisés comme correspondance.

Si une correspondance est appliquée, seules les entrées ayant ce champ défini seront itérées. Plusieurs correspondances peuvent être actives en même temps : si elles s'appliquent à des champs différents, seules les entrées ayant les deux champs définis de cette manière seront itérées. Si elles s'appliquent aux mêmes champs, seules les entrées où le champ prend une des valeurs spécifiées seront itérées. Les champs bien connus sont documentés dans systemd.journal-fields(7). Chaque fois qu'une nouvelle correspondance est ajoutée, la position actuelle de l'entrée est réinitialisée, et sd_journal_next(3) (ou un appel similaire) doit être appelé avant que les entrées puissent être lues à nouveau.

sd_journal_add_disjunction() peut être utilisé pour insérer une disjonction (c'est-à-dire un OU logique) dans la liste des correspondances. Si cet appel est invoqué, toutes les correspondances précédemment ajoutées depuis le dernier appel à sd_journal_add_disjunction() ou sd_journal_add_conjunction() sont combinées par un OU avec toutes les correspondances ajoutées ensuite, jusqu'à ce que sd_journal_add_disjunction() ou sd_journal_add_conjunction() soit à nouveau invoqué pour commencer le terme OU ou ET suivant.

sd_journal_add_conjunction() peut être utilisé pour insérer une conjonction (c'est-à-dire un ET logique) dans la liste des correspondances. Si cet appel est invoqué, toutes les correspondances précédemment ajoutées depuis le dernier appel à sd_journal_add_conjunction() sont combinées par un ET avec toutes les correspondances ajoutées ensuite, jusqu'à ce que sd_journal_add_conjunction() soit à nouveau invoqué pour commencer le terme ET suivant. La combinaison de sd_journal_add_match(), sd_journal_add_disjunction() et sd_journal_add_conjunction() peut être utilisée pour construire des termes de recherche complexes, même si les expressions logiques complètes ne sont pas disponibles. Notez que sd_journal_add_conjunction() opère à un niveau 'supérieur' à sd_journal_add_disjunction(). Il est donc possible de construire une expression de termes ET, composée de termes OU, composée de termes ET, composée de termes OU de correspondances (cette dernière expression OU est implicitement créée pour les correspondances portant le même nom de champ, voir ci-dessus).

sd_journal_flush_matches() peut être utilisé pour effacer toutes les correspondances, disjonctions et conjonctions à nouveau. Après cet appel, tout filtrage est supprimé et toutes les entrées du journal seront itérées à nouveau.

Notez que le filtrage via les correspondances ne s'applique qu'à la manière dont le journal est lu, il n'a aucun effet sur le stockage sur disque.

VALEUR DE RETOUR

sd_journal_add_match(), sd_journal_add_disjunction() et sd_journal_add_conjunction() retournent 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_flush_matches() ne retourne rien.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dans une phase précoce du programme lorsqu'aucun autre thread n'a été démarré.

EXEMPLES

L'exemple suivant ajoute des correspondances à un objet de contexte de journal pour itérer uniquement sur les messages générés par le service Avahi aux quatre niveaux de journalisation d'erreur, plus tous les messages de l'ID de message 03bb1dab98ab4ecfbf6fff2738bdd964 provenant de n'importe quel service (cet exemple manque de la vérification d'erreur nécessaire) :

...
int add_matches(sd_journal *j) {
  sd_journal_add_match(j, "_SYSTEMD_UNIT=avahi-daemon.service", 0);
  sd_journal_add_match(j, "PRIORITY=0", 0);
  sd_journal_add_match(j, "PRIORITY=1", 0);
  sd_journal_add_match(j, "PRIORITY=2", 0);
  sd_journal_add_match(j, "PRIORITY=3", 0);
  sd_journal_add_disjunction(j);
  sd_journal_add_match(j, "MESSAGE_ID=03bb1dab98ab4ecfbf6fff2738bdd964", 0);
}

HISTORIQUE

sd_journal_add_match(), sd_journal_add_disjunction(), et sd_journal_flush_matches() ont été ajoutés dans la version 187.

sd_journal_add_conjunction() a été ajouté dans la version 202.
