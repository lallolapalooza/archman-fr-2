sd_is_socket_inet(3)

SD_IS_FIFO(3) sd_is_fifo SD_IS_FIFO(3)

NOM

sd_is_fifo, sd_is_socket, sd_is_socket_inet, sd_is_socket_unix, sd_is_socket_sockaddr, sd_is_mq, sd_is_special - Vérifier le type d'un descripteur de fichier

SYNTAXE

#include <systemd/sd-daemon.h>

int sd_is_fifo(int fd, const char *path);

int sd_is_socket(int fd, int family, int type, int listening);

int sd_is_socket_inet(int fd, int family, int type, int listening, uint16_t port);

int sd_is_socket_sockaddr(int fd, int type, const struct sockaddr *addr, unsigned addr_len, int listening);

int sd_is_socket_unix(int fd, int type, int listening, const char *path, size_t length);

int sd_is_mq(int fd, const char *path);

int sd_is_special(int fd, const char *path);

DESCRIPTION

sd_is_fifo() peut être appelée pour vérifier si le descripteur de fichier spécifié fait référence à un FIFO ou à un tube (pipe). Si le paramètre path n'est pas NULL, on vérifie si le FIFO est lié au chemin spécifié dans le système de fichiers.

sd_is_socket() peut être appelée pour vérifier si le descripteur de fichier spécifié fait référence à une socket. Si le paramètre family n'est pas AF_UNSPEC, on vérifie si la socket est de la famille spécifiée (AF_UNIX, AF_INET, ...). Si le paramètre type n'est pas 0, on vérifie si la socket est du type spécifié (SOCK_STREAM, SOCK_DGRAM, ...). Si le paramètre listening est positif, on vérifie si la socket est en mode acceptation, c'est-à-dire si listen() a été appelée pour elle. Si listening est 0, on vérifie si la socket n'est pas dans ce mode. Si le paramètre est négatif, aucune vérification de ce type n'est effectuée. Le paramètre listening ne doit être utilisé que pour les sockets de flux et doit être réglé à une valeur négative sinon.

sd_is_socket_inet() est similaire à sd_is_socket(), mais vérifie éventuellement le numéro de port IPv4 ou IPv6 auquel la socket est liée, sauf si port est zéro. Pour cet appel, family doit être passé comme AF_UNSPEC, AF_INET ou AF_INET6.

sd_is_socket_sockaddr() est similaire à sd_is_socket_inet(), mais vérifie si la socket est liée à l'adresse spécifiée par addr. Le family spécifié par addr doit être soit AF_INET, soit AF_INET6 et addr_len doit être suffisamment grand pour cette famille. Si addr spécifie un port non nul, on vérifie également si la socket est liée à ce port. De plus, pour IPv6, si addr spécifie un sin6_flowinfo ou un sin6_scope_id non nul, on vérifie si la socket a les mêmes valeurs.

sd_is_socket_unix() est similaire à sd_is_socket() mais vérifie éventuellement le chemin AF_UNIX auquel la socket est liée, sauf si le paramètre path est NULL. Pour les sockets normales du système de fichiers AF_UNIX, réglez le paramètre length à 0. Pour les sockets de l'espace de noms abstrait Linux, réglez length à la taille de l'adresse, y compris l'octet 0 initial, et réglez path à l'octet 0 initial de l'adresse de la socket.

sd_is_mq() peut être appelée pour vérifier si le descripteur de fichier spécifié fait référence à une file d'attente de messages POSIX. Si le paramètre path n'est pas NULL, on vérifie si la file d'attente de messages est liée au nom spécifié.

sd_is_special() peut être appelée pour vérifier si le descripteur de fichier spécifié fait référence à un fichier spécial. Si le paramètre path n'est pas NULL, on vérifie si le descripteur de fichier est lié au nom de fichier spécifié. Les fichiers spéciaux dans ce contexte sont les nœuds de périphériques caractères et les fichiers dans /proc/ ou /sys/.

VALEUR DE RETOUR

En cas d'échec, ces appels retournent un code d'erreur négatif de style errno. Si le descripteur de fichier est du type spécifié et lié à l'adresse spécifiée, une valeur de retour positive est retournée, sinon zéro.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

En interne, ces fonctions utilisent une combinaison de fstat(2) et getsockname(2) pour vérifier le type du descripteur de fichier et à quoi il est lié.

HISTORIQUE

sd_is_special() a été ajoutée dans la version 209.

sd_is_socket_sockaddr() a été ajoutée dans la version 233.
