int sd_journal_printv_with_location(int priorité, const char *fichier, const char *ligne, const char *func, const char *format, va_list ap);

int sd_journal_send_with_location(const char *fichier, const char *ligne, const char *func, const char *format, ...);

int sd_journal_sendv_with_location(const char *fichier, const char *ligne, const char *func, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *fichier, const char *ligne, const char *func, const char *message);

DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples, en texte brut, au journal système. Le premier argument est une valeur de priorité. Il est suivi d'une chaîne de format et de ses paramètres, similaire à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une des suivantes : LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour les détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale système et au format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits à l'aide de cette fonction ne sont généralement pas censés se terminer par un caractère de nouvelle ligne. Cependant, comme tous les espaces blancs en fin de chaîne (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne journalisée, il est acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après suppression des espaces blancs en fin de chaîne) sont supprimées. Sur les lignes non vides, les espaces blancs en début de ligne (ainsi que les espaces blancs intérieurs) sont laissés in modifiés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variable encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Elle est sinon équivalente en comportement.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune immédiatement suivie de ses paramètres associés, terminées par NULL. Les chaînes passées doivent être au format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et ne contenir que des caractères, des chiffres et des underscores, et ne doit pas commencer par un underscore. (Toutes les affectations qui ne suivent pas cette syntaxe seront ignorées.) La valeur peut être de n'importe quelle taille et format. Il est fortement recommandé de ne soumettre que des chaînes de texte formatées dans l'encodage de caractères UTF-8, et de ne soumettre des champs binaires que lorsque le formatage en chaînes UTF-8 n'est pas judicieux. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs supplémentaires définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plus d'une valeur par entrée. Si cette fonction est utilisée, les espaces blancs en fin de chaîne sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit référencer un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprimera pas les espaces blancs en fin de chaîne des champs passés, mais transmettra les données spécifiées sans modification. Ceci est différent à la fois de sd_journal_print() et de sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs en fin de chaîne.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suffixée par ": " et une représentation lisible par l'homme du code d'erreur actuel stocké dans errno(3). Si la chaîne de message est passée comme NULL ou comme chaîne vide, seule la représentation de la chaîne d'erreur sera écrite, sans rien en préfixe. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté en chaîne décimale. La priorité du journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour le rendre plus facile à utiliser lorsque seules des chaînes de texte doivent être soumises. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Bonjour le monde, c'est le PID %lu !", (unsigned long) getpid());
sd_journal_send("MESSAGE=Bonjour le monde, c'est le PID %lu !", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont appelés. Ceci est implémenté avec des macros. Si ce n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() sont similaires à leurs équivalents sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "fichier" et "ligne" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "func" ne doit contenir que le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture de wrappers personnalisés, par exemple dans des liaisons pour un autre langage.

syslog(3) et sd_journal_print() peuvent être largement utilisés de manière interchangeable en termes de fonctionnalité. Cependant, notez que les messages de journal émis via le premier empruntent un chemin différent vers le serveur du journal que ceux émis via le second, et par conséquent, l'ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage de journaliser la ligne de code source, les noms de fichiers et les fonctions comme métadonnées le long de toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées qui sont générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client du Protocole Natif du Journal[1].

VALEUR DE RETOUR

Les dix fonctions renvoient 0 en cas de succès ou un code d'erreur négatif de style errno. Le errno(3) sd_journal_print_with_location(3) — systemd — Arch Linux

#include <systemd/sd-journal.h>

int sd_journal_print_with_location(int level, const char *file, const char *line,

                                    const char *func, const char *format, va_list ap);
int sd_journal_send_with_location(const char *file, const char *line, const char *func,
                                  const char *format, ...);
int sd_journal_sendv_with_location(const char *file, const char *line, const char *func,
                                   const char *format, va_list ap);
int sd_journal_perror_with_location(const char *file, const char *line, const char *func,
                                    const char *format, ...);

int sd_journal_print(int level, const char *format, ...);
int sd_journal_printv(int level, const char *format, va_list ap);
int sd_journal_send(const char *format, ...);
int sd_journal_sendv(const char *format, va_list ap);
int sd_journal_perror(const char *format, ...);

DESCRIPTION

These functions may be used to log messages to the systemd journal. They are similar to the standard C library functions syslog(3) and perror(3), but provide direct access to the journal.

The functions with the suffix _with_location additionally take arguments specifying the source code file name, line number, and function name where the call originated.

sd_journal_print(), sd_journal_printv(), sd_journal_print_with_location(), and sd_journal_printv_with_location() write a formatted message string to the journal. The level parameter specifies the message severity, one of the LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, or LOG_DEBUG values (defined in <syslog.h>).

sd_journal_send(), sd_journal_sendv(), sd_journal_send_with_location(), and sd_journal_sendv_with_location() write one or more key-value pairs to the journal. They take a format string followed by a variable number of arguments. The format string is processed similarly to printf(3), but each field must be of the form "FIELD=VALUE". The last argument before the variable arguments must be NULL.

sd_journal_send() and sd_journal_sendv() are shortcuts for calling sd_journal_send_with_location() and sd_journal_sendv_with_location() respectively, with NULL for the file, line, and function arguments.

sd_journal_perror() and sd_journal_perror_with_location() are similar to sd_journal_print() and sd_journal_print_with_location(), but they append a human-readable description of the current error number (as obtained from errno(3)) to the output string.

The variable argument lists for the _v functions are processed similarly to printf(3). The format string must be a string literal, and may not be a variable. The string literal may contain %-escapes, which are replaced by the corresponding arguments. The following %-escapes are supported: %s (string), %d, %i (signed decimal integer), %u (unsigned decimal integer), %x, %X (unsigned hexadecimal integer), %p (pointer, printed as hexadecimal), %% (a single '%' character).

The functions that take a variable argument list expect the final argument to be a NULL pointer, except for sd_journal_sendv* and sd_journal_printv*, which expect a NULL-terminated list of strings.

If the journal socket is not present (i.e. systemd-journald(8) is not running), these functions do nothing and return 0.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno error code.

Specifically, sd_journal_print* and sd_journal_send* return the number of bytes written to the journal socket. This value may be zero if the journal is not running. The variable itself is not altered.

If systemd-journald(8) is not running (the socket is not present), those functions do nothing, and also return 0.

THREAD SAFETY

All functions listed here are thread-safe and may be called in parallel from multiple threads.

sd_journal_sendv() and sd_journal_sendv_with_location() are "async signal safe" in the meaning of signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), and their counterparts with "_with_location" are not async signal safe.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
