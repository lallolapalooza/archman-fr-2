SD_BUS_PATH_ENCODE(3) sd_bus_path_encode SD_BUS_PATH_ENCODE(3)

NOM

sd_bus_path_encode, sd_bus_path_encode_many, sd_bus_path_decode, sd_bus_path_decode_many - Convertir un identifiant externe en chemin d'objet et inversement

SYNOPIS

#include <systemd/sd-bus.h>

int sd_bus_path_encode(const char *prefix, const char *external_id, char **ret_path);

int sd_bus_path_encode_many(char **out, const char *path_template, ...);

int sd_bus_path_decode(const char *path, const char *prefix, char **ret_external_id);

int sd_bus_path_decode_many(const char *path, const char *path_template, ...);

DESCRIPTION

sd_bus_path_encode() et sd_bus_path_decode() convertissent les chaînes d'identifiants externes en chemins d'objet et vice versa. Ces fonctions sont utiles pour mapper des identifiants spécifiques à une application de toute sorte en chemins d'objet du bus de manière simple, réversible et sûre.

sd_bus_path_encode() prend un préfixe de chemin de bus et une chaîne d'identifiant externe comme arguments, plus un emplacement pour stocker la chaîne de chemin de bus retournée. Le préfixe de chemin de bus doit être un chemin de bus valide, commençant par une barre oblique "/", et ne se terminant pas par une. La chaîne d'identifiant externe peut être dans n'importe quel format, peut être la chaîne vide, et n'a pas de restrictions sur l'ensemble de caractères - cependant, elle doit toujours être terminée par NUL. La chaîne retournée sera la concaténation du préfixe du chemin de bus plus une version échappée de la chaîne d'identifiant externe. Cette opération peut être inversée avec sd_bus_path_decode(). Il est recommandé d'utiliser uniquement des identifiants externes qui nécessitent peu d'échappement pour être transformés en identifiants de chemin de bus valides (par exemple, en s'en tenant à un jeu de caractères ASCII 7 bits), afin de garantir que le chemin de bus résultant reste court et facile à traiter.

sd_bus_path_decode() inverse l'opération de sd_bus_path_encode() et régénère ainsi une chaîne d'identifiant externe à partir d'un chemin de bus. Elle prend un chemin de bus et une chaîne de préfixe, plus un emplacement pour stocker la chaîne d'identifiant externe retournée. Si le chemin de bus ne commence pas par le préfixe spécifié, 0 est retourné et la chaîne retournée est mise à NULL. Sinon, la chaîne qui suit le préfixe est déséchappée et retournée dans la chaîne d'identifiant externe.

L'échappement utilisé remplacera tous les caractères invalides dans un chemin d'objet de bus par "_", suivi d'une valeur hexadécimale. Comme cas spécial, la chaîne vide sera remplacée par un seul "_".

sd_bus_path_encode_many() fonctionne comme son homologue sd_bus_path_encode(), mais prend un modèle de chemin comme argument et encode plusieurs étiquettes selon ses directives intégrées. Pour chaque caractère "%" trouvé dans le modèle, l'appelant doit fournir une chaîne via varargs, qui sera encodée et intégrée à la position du caractère "%". Tout autre caractère dans le modèle est copié tel quel dans le chemin encodé.

sd_bus_path_decode_many() fait l'inverse de sd_bus_path_encode_many(). Elle décode le chemin d'objet passé selon le modèle de chemin donné. Pour chaque caractère "%" dans le modèle, l'appelant doit fournir un espace de stockage de sortie ("char **") via varargs. L'étiquette décodée y sera stockée. Chaque caractère "%" ne correspondra qu'à l'étiquette actuelle. Il ne correspondra jamais entre les étiquettes. De plus, une seule directive est autorisée par étiquette. Si NULL est passé comme espace de stockage de sortie, l'étiquette est vérifiée mais non retournée à l'appelant.

VALEUR DE RETOUR

En cas de succès, sd_bus_path_encode() retourne une valeur positive ou 0, et un chemin de bus valide dans l'argument de retour. En cas de succès, sd_bus_path_decode() retourne une valeur positive si le préfixe a correspondu, ou 0 s'il n'a pas correspondu. Si le préfixe a correspondu, l'identifiant externe est retourné dans le paramètre de retour. S'il n'a pas correspondu, NULL est retourné dans le paramètre de retour. En cas d'échec, un numéro d'erreur négatif de style errno est retourné par l'une ou l'autre des fonctions. Les chaînes retournées doivent être libérées par l'appelant avec free(3).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_path_encode() et sd_bus_path_decode() ont été ajoutées dans la version 211.

sd_bus_path_encode_many() et sd_bus_path_decode_many() ont été ajoutées dans la version 227.
