SD_BUS_REQUEST_NAME(3) sd_bus_request_name SD_BUS_REQUEST_NAME(3)

NOM

sd_bus_request_name, sd_bus_request_name_async, sd_bus_release_name, sd_bus_release_name_async - Demander ou libérer un nom de service bien connu sur un bus

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_request_name(sd_bus *bus, const char *name, uint64_t flags);

int sd_bus_request_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, uint64_t flags, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_release_name(sd_bus *bus, const char *name);

int sd_bus_release_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, sd_bus_message_handler_t callback, void *userdata);

DESCRIPTION

sd_bus_request_name() demande un nom de service bien connu sur un bus. Il prend une connexion de bus, un nom de bus valide et un paramètre de drapeaux. Le paramètre de drapeaux est une combinaison de zéro ou plusieurs des drapeaux suivants :

SD_BUS_NAME_ALLOW_REPLACEMENT

Après avoir acquis le nom avec succès, permettre à d'autres pairs de prendre le nom lorsqu'ils essaient de l'acquérir avec le drapeau SD_BUS_NAME_REPLACE_EXISTING activé. Si SD_BUS_NAME_ALLOW_REPLACEMENT n'est pas défini lors de la demande initiale, une telle demande par d'autres pairs sera refusée.

Ajouté dans la version 209.

SD_BUS_NAME_REPLACE_EXISTING

Prendre possession du nom s'il a déjà été acquis par une autre paire, et que cette autre paire a permis la prise de possession en définissant SD_BUS_NAME_ALLOW_REPLACEMENT lors de son acquisition.

Ajouté dans la version 209.

SD_BUS_NAME_QUEUE

Mettre en file d'attente l'acquisition du nom lorsque le nom est déjà pris.

Ajouté dans la version 209.

sd_bus_request_name() fonctionne de manière synchrone : un message demandant le nom est envoyé au répartiteur de bus, et l'appel attend jusqu'à ce que le répartiteur réponde.

sd_bus_request_name_async() est une version asynchrone de sd_bus_request_name(). Au lieu d'attendre la fin de la demande, le message de demande est mis en file d'attente. La fonction de rappel callback spécifiée sera appelée lorsque la réponse du répartiteur est reçue. Si le paramètre est spécifié comme NULL, une implémentation par défaut est utilisée à la place, qui terminera la connexion lorsque le nom ne pourra pas être acquis. La fonction renvoie un objet slot dans son paramètre slot — s'il est passé comme non-NULL — qui peut être utilisé comme référence à l'opération de demande de nom. Utilisez sd_bus_slot_unref(3) pour détruire cette référence. Notez que la destruction de la référence ne désenregistrera pas le nom, mais garantira simplement que la fonction de rappel spécifiée ne sera plus appelée.

sd_bus_release_name() libère un nom connu acquis. Il prend une connexion de bus et un nom de bus valide comme paramètres. Cette fonction fonctionne de manière synchrone, envoyant un message de demande de libération au répartiteur de bus et attendant sa réponse.

sd_bus_release_name_async() est une version asynchrone de sd_bus_release_name(). La fonction de rappel callback spécifiée est appelée une fois que le nom a été libéré avec succès. Si spécifiée comme NULL, une implémentation générique est utilisée qui ignore le résultat de l'opération. Comme ci-dessus, le slot (s'il n'est pas NULL) est défini sur un objet qui peut être utilisé pour référencer l'opération.

Ces fonctions ne sont prises en charge que sur les connexions de bus, c'est-à-dire les connexions à un répartiteur de bus et non sur des connexions directes.

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Si SD_BUS_NAME_QUEUE est spécifié, sd_bus_request_name() renverra 0 lorsque le nom est déjà pris par une autre paire et que le client a été ajouté à la file d'attente pour le nom. Dans ce cas, l'appelant peut s'abonner aux signaux "NameOwnerChanged" pour être notifié lorsque le nom est acquis avec succès. sd_bus_request_name() renvoie > 0 lorsque le nom a été acquis avec succès immédiatement.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EALREADY

L'appelant est déjà propriétaire du nom spécifié.

-EEXIST

Le nom a déjà été acquis par une autre paire, et SD_BUS_NAME_REPLACE_EXISTING n'a pas été spécifié ou l'autre paire n'a pas spécifié SD_BUS_NAME_ALLOW_REPLACEMENT lors de l'acquisition du nom.

-ESRCH

Il a été tenté de libérer un nom qui n'est actuellement pas enregistré sur le bus.

-EADDRINUSE

Il a été tenté de libérer un nom qui appartient à une autre paire sur le bus.

-EINVAL

Un paramètre spécifié est invalide. Ceci est également généré lorsque le nom demandé est un nom de service spécial réservé par la spécification D-Bus, ou lorsque l'opération est demandée sur une connexion qui ne fait pas référence à un bus.

-ENOTCONN

La connexion du bus a été déconnectée.

-ECHILD

La connexion du bus a été créée dans un processus différent de celui actuel.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme où aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_bus_request_name() et sd_bus_release_name() ont été ajoutés dans la version 209.

sd_bus_request_name_async() et sd_bus_release_name_async() ont été ajoutés dans la version 237.

NOM

sd_bus_request_name_async, sd_bus_request_name_async_timed - Demande un nom de bus au système de manière asynchrone

SYNOPIS

#include <systemd/sd-bus.h>

int sd_bus_request_name_async(sd_bus *bus, sd_bus_error *error, const char *name, uint64_t flags, sd_bus_message_handler_t handler, void *userdata);
int sd_bus_request_name_async_timed(sd_bus *bus, sd_bus_error *error, const char *name, uint64_t flags, uint64_t usec, sd_bus_message_handler_t handler, void *userdata);

DESCRIPTION

La fonction sd_bus_request_name_async() est utilisée pour demander l'acquisition d'un nom de bus au système de manière asynchrone. La demande est envoyée à l'autodiscovery de dbus et le résultat est renvoyé dans le rappel handler spécifié.

Les drapeaux flags peuvent être une combinaison des options suivantes :

  • SD_BUS_NAME_REQUEST_REPLACE_EXISTING : Remplace un nom existant si la demande échoue.
  • SD_BUS_NAME_REQUEST_NO_FAIL_ON_ERROR : Ne génère pas d'erreur si le nom n'a pas pu être acquis.

La fonction sd_bus_request_name_async_timed() est similaire mais inclut un délai d'attente usec pour la demande.

OPTIONS

Aucune option spécifique n'est détaillée dans cette section du manuel.

VALEUR DE RETOUR

En cas de succès, sd_bus_request_name_async() renvoie 0. En cas d'échec, elle renvoie un code d'erreur négatif.

NOTES

Cette fonction est principalement utilisée pour la communication inter-processus au sein d'un système utilisant dbus.

HISTORIQUE

La fonction sd_bus_request_name_async() a été introduite dans systemd version 230.
