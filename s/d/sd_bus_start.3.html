NOM

sd_bus_start - Initier une connexion de bus au démon de courtier D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_start(sd_bus *bus);

DESCRIPTION

sd_bus_start() connecte un objet de connexion de bus existant au démon de courtier D-Bus, généralement dbus-daemon(1) ou dbus-broker(1). Le mécanisme à utiliser pour la connexion doit être configuré avant l'appel à sd_bus_start(), en utilisant soit sd_bus_set_address(3), sd_bus_set_fd(3), soit sd_bus_set_exec(3). sd_bus_start() ouvrira le socket de connexion ou lancera l'exécutable selon les besoins, et lancera de manière asynchrone un appel à org.freedesktop.DBus.Hello(). La réponse à l'appel Hello sera traitée plus tard par sd_bus_process(3). Si l'ouverture de la connexion ou la mise en file d'attente de l'appel asynchrone échouent, la connexion sera fermée avec sd_bus_close(3).

Dans la plupart des cas, il est préférable d'utiliser sd_bus_default_user(3), sd_bus_default_system(3) ou des appels associés plutôt que les appels de plus bas niveau sd_bus_new() et sd_bus_start(). Les fonctions de plus haut niveau allouent non seulement un objet bus, mais démarrent également la connexion à un bus connu en un seul appel de fonction.

VALEUR DE RETOUR

En cas de succès, cette fonction renvoie un entier non négatif. En cas d'échec, elle renvoie un code d'erreur négatif de type errno.

Erreurs

-EINVAL

Le paramètre d'entrée bus est NULL.

Ajouté dans la version 246.

-ENOPKG

L'objet bus bus n'a pas pu être résolu.

Ajouté dans la version 246.

-EPERM

Le paramètre d'entrée bus est dans un état incorrect (sd_bus_start() ne peut être appelé qu'une seule fois sur un objet bus nouvellement créé).

Ajouté dans la version 246.

-ECHILD

L'objet bus bus a été créé dans un processus différent.

Ajouté dans la version 246.

En outre, d'autres erreurs liées à la connexion peuvent être retournées. Voir sd_bus_send(3).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'effectuer les appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre fil d'exécution n'a encore été démarré.

HISTORIQUE

sd_bus_start() a été ajouté dans la version 246.
