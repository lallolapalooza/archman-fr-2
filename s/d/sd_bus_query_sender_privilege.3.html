SD_BUS_QUERY_SENDER_CREDS(3) sd_bus_query_sender_creds SD_BUS_QUERY_SENDER_CREDS(3)

NOM

sd_bus_query_sender_creds, sd_bus_query_sender_privilege - Interroger les informations d'identification/privilèges de l'expéditeur d'un message bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_query_sender_creds(sd_bus_message *m, uint64_t mask, sd_bus_creds **creds);

sd_bus_error* sd_bus_query_sender_privilege(sd_bus_message *m, int capability);

DESCRIPTION

sd_bus_query_sender_creds() renvoie les informations d'identification du message m. Le paramètre mask est une combinaison des indicateurs SD_BUS_CREDS_* qui indiquent quelles informations d'identification intéressent l'appelant. Voir sd_bus_creds_new_from_pid(3) pour une liste des indicateurs possibles. Premièrement, ce message vérifie si les informations d'identification demandées sont attachées au message lui-même. Sinon, mais si le message contient le pid de l'expéditeur et que l'appelant a spécifié l'indicateur SD_BUS_CREDS_AUGMENT, cette fonction tente de déterminer les informations d'identification manquantes par d'autres moyens (en partant du pid). Si le PID n'est pas disponible mais que le message a un expéditeur, cette fonction appelle sd_bus_get_name_creds(3) pour obtenir les informations d'identification demandées. Si le message n'a pas d'expéditeur (lorsqu'une connexion directe est utilisée), cette fonction appelle sd_bus_get_owner_creds(3) pour obtenir les informations d'identification demandées. En cas de succès, les informations d'identification demandées sont stockées dans creds. La propriété de l'objet d'informations d'identification dans creds est transférée à l'appelant et doit être libérée en appelant sd_bus_creds_unref(3).

sd_bus_query_sender_privilege() vérifie si le message m a les privilèges demandés. Si capability est un entier non négatif, cette fonction vérifie si le message a la capacité avec la même valeur. Voir capabilities(7) pour une liste des capacités. Si capability est un entier négatif, cette fonction renvoie si l'expéditeur du message s'exécute en tant que le même utilisateur que le récepteur du message, ou si l'expéditeur du message s'exécute en tant que root et que le récepteur du message ne s'exécute pas en tant que root. En cas de succès et si le message a les privilèges demandés, cette fonction renvoie un entier positif. Si le message n'a pas les privilèges demandés, cette fonction renvoie zéro.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier non négatif. En cas d'échec, elles renvoient un code d'erreur négatif de type errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le message m ou un paramètre de sortie est NULL.

Ajouté dans la version 246.

-ENOTCONN

Le bus de m n'est pas connecté.

Ajouté dans la version 246.

-ECHILD

Le bus de m a été créé dans un processus, une bibliothèque ou une instance de module différente.

Ajouté dans la version 246.

-EPERM

Le message m n'est pas scellé.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_query_sender_creds() et sd_bus_query_sender_privilege() ont été ajoutées dans la version 246.
