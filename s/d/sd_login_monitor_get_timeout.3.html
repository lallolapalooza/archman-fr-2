SD_LOGIN_MONITOR_NEW(3) sd_login_monitor_new SD_LOGIN_MONITOR_NEW(3)

NOM

sd_login_monitor_new, sd_login_monitor_unref, sd_login_monitor_unrefp, sd_login_monitor_flush, sd_login_monitor_get_fd, sd_login_monitor_get_events, sd_login_monitor_get_timeout, sd_login_monitor - Surveiller les sessions de connexion, les sièges, les utilisateurs et les machines virtuelles/conteneurs

SYNTAXE

#include <systemd/sd-login.h>

int sd_login_monitor_new(const char *category, sd_login_monitor **ret);

sd_login_monitor *sd_login_monitor_unref(sd_login_monitor *m);

void sd_login_monitor_unrefp(sd_login_monitor **m);

int sd_login_monitor_flush(sd_login_monitor *m);

int sd_login_monitor_get_fd(sd_login_monitor *m);

int sd_login_monitor_get_events(sd_login_monitor *m);

int sd_login_monitor_get_timeout(sd_login_monitor *m, uint64_t *timeout_usec);

DESCRIPTION

sd_login_monitor_new() peut être utilisé pour surveiller les sessions de connexion, les utilisateurs, les sièges et les machines virtuelles/conteneurs. Via un objet moniteur, un descripteur de fichier peut être intégré dans une boucle d'événements définie par l'application qui est réveillée chaque fois qu'un utilisateur se connecte, se déconnecte ou qu'un siège est ajouté ou supprimé, ou qu'une session, un utilisateur, un siège ou une machine virtuelle/un conteneur change d'état autrement. Le premier paramètre prend une chaîne de caractères qui peut être "seat" (pour recevoir uniquement des notifications sur les sièges ajoutés, supprimés ou modifiés), "session" (pour recevoir uniquement des notifications sur les sessions créées, supprimées ou modifiées), "uid" (pour recevoir uniquement des notifications lorsque l'état d'un utilisateur change par rapport aux connexions) ou "machine" (pour recevoir uniquement des notifications lorsqu'une machine virtuelle ou un conteneur est démarré ou arrêté). Si des notifications doivent être générées dans toutes ces conditions, NULL peut être passé. Notez que des catégories supplémentaires pourront être définies à l'avenir. Le second paramètre renvoie un objet moniteur et doit être libéré avec l'appel sd_login_monitor_unref() après utilisation.

sd_login_monitor_unref() peut être utilisé pour détruire un objet moniteur. Notez que cela invalidera tout descripteur de fichier retourné par sd_login_monitor_get_fd().

sd_login_monitor_unrefp() est similaire à sd_login_monitor_unref() mais prend un pointeur vers un pointeur vers un objet sd_login_monitor. Cet appel est utile en conjonction avec l'attribut **Clean-up Variable Attribute**[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme suit, afin d'allouer un objet de surveillance de connexion qui sera automatiquement libéré à la sortie du bloc de code :

{
  __attribute__((cleanup(sd_login_monitor_unrefp))) sd_login_monitor *m = NULL;
  int r;
  ...
  r = sd_login_monitor_new(NULL, &m);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Échec de l'allocation de l'objet de surveillance de connexion : %m\n");
  }
  ...
}

sd_login_monitor_flush() peut être utilisé pour réinitialiser l'état de réveil de l'objet moniteur. Chaque fois qu'un événement provoque le réveil du moniteur de la boucle d'événements via le descripteur de fichier, cette fonction doit être appelée pour réinitialiser l'état de réveil. Si cet appel n'est pas effectué, le descripteur de fichier réveillera immédiatement à nouveau la boucle d'événements.

sd_login_monitor_unref() et sd_login_monitor_unrefp() n'exécutent aucune opération si l'objet moniteur passé est NULL.

sd_login_monitor_get_fd() peut être utilisé pour récupérer le descripteur de fichier de l'objet moniteur qui peut être intégré dans une boucle d'événements définie par l'application, basée sur poll(2) ou une interface similaire. L'application doit inclure le descripteur de fichier retourné comme source de réveil pour le masque d'événements retourné par sd_login_monitor_get_events(). Elle doit passer une valeur de délai d'attente comme retourné par sd_login_monitor_get_timeout(). Chaque fois qu'un réveil est déclenché, le descripteur de fichier doit être réinitialisé via sd_login_monitor_flush(). Une application doit relire l'état de connexion avec une fonction comme sd_get_seats(3) ou similaire pour déterminer ce qui a changé.

sd_login_monitor_get_events() renverra le masque poll() pour lequel attendre. Cette fonction renverra une combinaison de POLLIN, POLLOUT et similaires à insérer dans le champ ".events" de struct pollfd.

sd_login_monitor_get_timeout() renverra une valeur de délai d'attente pour utilisation dans poll(). Cela renvoie une valeur en microsecondes depuis l'époque de CLOCK_MONOTONIC pour expirer poll() dans timeout_usec. Voir clock_gettime(2) pour les détails sur CLOCK_MONOTONIC. S'il n'y a pas de délai d'attente à attendre, cela remplira (uint64_t) -1 à la place. Notez que poll() prend un délai relatif en millisecondes plutôt qu'un délai absolu en microsecondes. Pour convertir le délai d'attente absolu en 'µs' en un délai relatif en 'ms', utilisez un code comme suit :

uint64_t t;
int msec;
sd_login_monitor_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

Le code ci-dessus ne fait aucune vérification d'erreur pour des raisons de brièveté. L'entier msec calculé peut être passé directement comme paramètre de délai d'attente de poll().

VALEUR DE RETOUR

En cas de succès, sd_login_monitor_new(), sd_login_monitor_flush() et sd_login_monitor_get_timeout() renvoient 0 ou un entier positif. En cas de succès, sd_login_monitor_get_fd() renvoie un descripteur de fichier Unix. En cas de succès, sd_login_monitor_get_events() renvoie une combinaison de POLLIN, POLLOUT et similaires. En cas d'échec, ces appels renvoient un code d'erreur négatif de type errno.

sd_login_monitor_unref() renvoie toujours NULL.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, là où ce n'est pas accepté). La catégorie spécifiée à surveiller n'est pas connue.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que dans une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_login_monitor_get_events() et sd_login_monitor_get_timeout() ont été ajoutés dans la version 201.

sd_login_monitor_unrefp() a été ajouté dans la version 229.
