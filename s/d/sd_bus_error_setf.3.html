DESCRIPTION

La structure sd_bus_error contient des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles des noms d'erreur décrites dans la spécification D-Bus, sous-section Noms D-Bus valides[1]. Un certain nombre de noms d'erreur courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques au domaine peuvent être définies par les applications.
•Le champ message contient généralement une chaîne de caractères lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir les deux champs initialisés à NULL, et signifie l'absence d'erreur, c'est-à-dire le succès. Assignez SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque ce n'est plus nécessaire, les ressources détenues par la structure sd_bus_error doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de caractères de nom et de message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer à nouveau le contenu lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données qu'elle contient avec sd_bus_error_free().

sd_bus_error_set() renvoie une valeur de type errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, il est supposé qu'aucune erreur ne s'est produite, et 0 est renvoyé. Si name est non nul, une valeur négative est toujours renvoyée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est quand même converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs équivalents errno bien connus, et les autres sont converties en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreur bien connus. Des mappages d'erreurs supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et les arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition des structures d'erreur. Puisque cet appel n'alloue pas de mémoire, il n'échouera pas avec une condition de manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() renverra immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur de style errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Des noms d'erreur D-Bus bien connus seront utilisés pour name si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si l'erreur spécifiée error est non nulle, l'appel renvoie toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est renvoyé.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et les arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de style errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera renvoyé.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été préalablement défini avec une valeur d'erreur. Sinon, il renverra immédiatement. Si les chaînes de caractères dans e ont été définies à l'aide de sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit fraîchement initialisé à NULL, soit réinitialisé à l'aide de sd_bus_error_free().

sd_bus_error_copy() renvoie généralement 0 ou une valeur de style errno négative basée sur le paramètre d'entrée e : 0 s'il était non défini et un entier négatif s'il était défini à une certaine erreur, de manière similaire à sd_bus_error_set(). SYNOPSIS

#include <systemd/sd-bus.h>

DESCRIPTION

The sd_bus_error structure is used to describe errors that occurred during D-Bus operations. It contains a name field and a message field.

sd_bus_error_set() sets the error described by name and message in the structure error. If an error was already set in error, the function returns -EINVAL. If name or message is NULL, the function returns 0 and resets any previously set error. Otherwise, it allocates memory for the fields and returns a negative error value which is derived from the name field. This return value can be used to propagate the error, see EXAMPLES. The name string is copied, while the message string is duplicated. A typical return value for a D-Bus error is -ENOMEM if a memory allocation fails.

sd_bus_error_setf() is similar to sd_bus_error_set(), but the message is formatted using printf-style format strings.

sd_bus_error_set_const() is similar to sd_bus_error_set(), but the message string is not copied, and the caller must ensure that it remains valid for the lifetime of the error. This is useful for static error messages.

sd_bus_error_set_errno() sets the error specified by err (an errno value) and message. If err is 0, the error is unset and the function returns 0. Otherwise, it allocates memory for the fields and returns a negative error value derived from the err parameter. The message string is duplicated.

sd_bus_error_set_errnof() and sd_bus_error_set_errnofv() are similar to sd_bus_error_set_errno(), but the message is formatted using printf-style format strings.

sd_bus_error_get_errno() returns the errno value corresponding to the error name set in error. If error is NULL or no error is set, it returns false. Otherwise, it returns a positive errno value. Note that this is a best-effort mapping and not all D-Bus errors may have a corresponding errno value.

sd_bus_error_copy() copies the error information from src to dst. If src is not set, dst is reset. If dst is already set, its contents are freed before copying. If an error occurs during allocation, -ENOMEM is returned. If dst is NULL, no operation is performed. Returns a converted errno-like, non-positive error value.

sd_bus_error_move() is similar to sd_bus_error_copy(), but will move any error information from src into dst, resetting the former. This function cannot fail, as no new memory is allocated. Note that if src is not set, dst is initialized to SD_BUS_ERROR_NULL. Moreover, if dst is NULL no operation is executed on it and resources held by src are freed and reset. Returns a converted errno-like, non-positive error value.

sd_bus_error_is_set() will return a non-zero value if error is non-NULL and an error has been set, false otherwise.

sd_bus_error_has_name() will return a non-zero value if error is non-NULL and an error with the same name has been set, false otherwise.

sd_bus_error_has_names_sentinel() is similar to sd_bus_error_has_name(), but takes multiple names to check against. The list must be terminated with NULL. sd_bus_error_has_names() is a macro wrapper around sd_bus_error_has_names_sentinel() that adds the NULL sentinel automatically.

sd_bus_error_free() will destroy resources held by error. The parameter itself will not be deallocated, and must be free(3)d by the caller if necessary. The function may also be called safely on unset errors (error structures with both fields set to NULL), in which case it performs no operation. This call will reset the error structure after freeing the data, so that all fields are set to NULL. The structure may be reused afterwards.

REFERENCE OWNERSHIP

sd_bus_error is not reference-counted. Users should destroy resources held by it by calling sd_bus_error_free(). Usually, error structures are allocated on the stack or passed in as function parameters, but they may also be allocated dynamically, in which case it is the duty of the caller to free(3) the memory held by the structure itself after freeing its contents with sd_bus_error_free().

RETURN VALUE

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() always return 0 when the specified error value is NULL, and a negative errno-like value corresponding to the name parameter otherwise. The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof() and sd_bus_error_set_errnofv(), return 0 when the specified error value is 0, and a negative errno-like value corresponding to the error parameter otherwise. If an error occurs internally, one of the negative error values listed below will be returned. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_get_errno() returns false when error is NULL, and a positive errno value mapped from error->name otherwise.

sd_bus_error_copy() and sd_bus_error_move() return a negative error value converted from the source error, and zero if the error has not been set. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_is_set() returns a non-zero value when error and the name field are non-NULL, zero otherwise.

sd_bus_error_has_name(), sd_bus_error_has_names(), and sd_bus_error_has_names_sentinel() return a non-zero value when error is non-NULL and the name field is equal to one of the given names, zero otherwise.

Erreurs

La valeur de retour peut indiquer les problèmes suivants dans l'invocation de la fonction elle-même :

-EINVAL

Une erreur était déjà définie dans la structure sd_bus_error lorsque l'une des fonctions de définition d'erreur a été appelée.

-ENOMEM

L'allocation mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), et sd_bus_error_move() retourneront une valeur de type errno convertie et négative, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en valeurs entières de type errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de type errno peut être retournée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, retourner le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et propager également la valeur errno
   * que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd de pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels concurrents (multi-thread-safe). Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a encore été démarré.
