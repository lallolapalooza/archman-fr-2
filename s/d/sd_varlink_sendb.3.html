SD_VARLINK_SEND(3) sd_varlink_send SD_VARLINK_SEND(3)

NOM

sd_varlink_send, sd_varlink_sendb, sd_varlink_sendbo - Met en file d'attente un appel de méthode Varlink, sans attendre de réponse

SYNTAXE

#include <systemd/sd-varlink.h>

int sd_varlink_send(sd_varlink *link, const char *method, sd_json_variant *parameters);

int sd_varlink_sendb(sd_varlink *link, const char *method, ...);

int sd_varlink_sendbo(sd_varlink *link, const char *method, ...);

DESCRIPTION

sd_varlink_send() soumet un appel de méthode via une connexion Varlink. Il prend l'objet de connexion Varlink, le nom d'une méthode sous forme de chaîne de caractères, et un objet JSON contenant les paramètres à passer en tant que paramètres de fonction. Cet appel est asynchrone : le message ne sera pas délivré immédiatement, mais seulement une fois que sd_varlink_process(3) sera invoqué (ce qui se produira automatiquement lors d'une des itérations de la boucle d'événements suivantes si la connexion Varlink est attachée à une boucle d'événements).

sd_varlink_sendb() est similaire à sd_varlink_send(), mais au lieu d'attendre un objet sd_json_variant entièrement construit portant les paramètres, cet objet est construit à la volée directement à partir de la liste de paramètres, dans un style identique à sd_json_build(3).

sd_varlink_sendbo() est identique à sd_varlink_sendb(), mais un objet englobant est implicitement ajouté, de sorte que la liste de paramètres doit se composer uniquement de paires champ. Pour plus de détails sur la liste d'arguments attendue, voir sd_json_buildo(3).

Utilisez sd_varlink_send(), sd_varlink_sendb() et sd_varlink_sendbo() uniquement si aucun résultat d'appel de méthode n'est requis, car ils ne fournissent ni paramètres de retour ni informations de succès/échec. Utilisez sd_varlink_call(3) (et les appels associés) pour soumettre un appel de méthode de manière synchrone, en retournant la réponse du serveur.

VALEUR DE RETOUR

En cas de succès, sd_varlink_send(), sd_varlink_sendb() et sd_varlink_sendbo() retournent un entier non négatif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un argument est invalide.

-ENOMEM

Échec de l'allocation de mémoire.

-ENOTCONN

L'objet de connexion Varlink n'est pas connecté.

-EBUSY

L'objet de connexion Varlink est déjà utilisé à d'autres fins, c'est-à-dire l'exécution d'un appel de méthode ou similaire.

-ENOBUFS

La limite interne des messages mis en file d'attente pour la connexion Varlink a été atteinte. Cette limite est très élevée et l'atteindre indique généralement que l'objet de connexion Varlink est bloqué - peut-être parce que sd_varlink_process() n'a pas été appelé assez régulièrement, ou parce que le pair ne traite aucun message mis en file d'attente. Cette limite est une mesure de sécurité pour garantir qu'un pair bloqué ne conduira pas à des allocations mémoire illimitées côté client.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multi-threads. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_varlink_send(), sd_varlink_sendb(), sd_varlink_sendbo() ont été ajoutés dans la version 257.
