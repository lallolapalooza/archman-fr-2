SD_JOURNAL_GET_CUTOFF_REALTIME_USEC(3) sd_journal_get_cutoff_realtime_usec SD_JOURNAL_GET_CUTOFF_REALTIME_USEC(3)

NOM

sd_journal_get_cutoff_realtime_usec, sd_journal_get_cutoff_monotonic_usec - Lire les horodatages de coupure de l'entrée actuelle du journal

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_cutoff_realtime_usec(sd_journal *j, uint64_t *from, uint64_t *to);

int sd_journal_get_cutoff_monotonic_usec(sd_journal *j, sd_id128_t boot_id, uint64_t *from, uint64_t *to);

DESCRIPTION

sd_journal_get_cutoff_realtime_usec() récupère les horodatages temps réel (horloge murale) des premières et dernières entrées accessibles dans le journal. Elle prend trois arguments : l'objet de contexte du journal j et deux pointeurs from et to pointant vers des entiers non signés de 64 bits pour stocker les horodatages. Les horodatages sont en microsecondes depuis l'époque, c'est-à-dire CLOCK_REALTIME. L'un des deux arguments d'horodatage peut être passé comme NULL si l'horodatage n'est pas nécessaire, mais pas les deux.

sd_journal_get_cutoff_monotonic_usec() récupère les horodatages monotones des premières et dernières entrées accessibles dans le journal. Elle prend trois arguments : l'objet de contexte du journal j, un identifiant de 128 bits pour le démarrage boot_id, et deux pointeurs vers des entiers non signés de 64 bits pour stocker les horodatages, from et to. Les horodatages sont en microsecondes depuis le démarrage de ce démarrage spécifique, c'est-à-dire CLOCK_MONOTONIC. Comme l'horloge monotone redémarre à chaque reboot, elle ne définit un point de temps bien défini que lorsqu'elle est utilisée conjointement avec un identifiant identifiant le démarrage, voir sd_id128_get_boot(3) pour plus d'informations. La fonction retournera les horodatages pour le démarrage identifié par l'ID de démarrage passé. L'un des deux arguments d'horodatage peut être passé comme NULL si l'horodatage n'est pas nécessaire, mais pas les deux.

VALEUR DE RETOUR

sd_journal_get_cutoff_realtime_usec() et sd_journal_get_cutoff_monotonic_usec() retournent 1 en cas de succès, 0 si aucune entrée appropriée ne se trouve dans le journal, ou un code d'erreur négatif de type errno.

Les emplacements pointés par les paramètres from et to seront définis uniquement si la valeur de retour est positive, et évidemment, si les paramètres ne sont pas nuls.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

HISTORIQUE

sd_journal_get_cutoff_realtime_usec() et sd_journal_get_cutoff_monotonic_usec() ont été ajoutées dans la version 187.
