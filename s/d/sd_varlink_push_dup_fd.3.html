NOM

sd_varlink_push_fd, sd_varlink_push_dup_fd - Soumettre un descripteur de fichier à envoyer avec le prochain message Varlink sortant

SYNTAXE

#include <systemd/sd-varlink.h>

int sd_varlink_push_fd(sd_varlink *link, int fd);

int sd_varlink_push_dup_fd(sd_varlink *link, int fd);

DESCRIPTION

sd_varlink_push_fd() soumet un descripteur de fichier à envoyer avec le prochain message Varlink sortant. Prend un objet de connexion Varlink et un descripteur de fichier en paramètre. Le descripteur de fichier n'est pas dupliqué, et par conséquent, la propriété du descripteur de fichier est transférée à l'objet de connexion Varlink (uniquement en cas de succès ; en cas d'échec, l'appelant conserve la propriété). Une fois que le descripteur de fichier a été écrit sur le socket de transport sous-jacent, il est automatiquement fermé. Le code de l'application appelante ne doit pas toucher au descripteur de fichier ni le fermer de sa propre initiative, sinon cela interférera avec l'implémentation du protocole Varlink. Cet appel n'est pris en charge que si le transport sous-jacent prend en charge le passage de descripteurs de fichiers (ce qui signifie effectivement que la fonctionnalité est prise en charge sur AF_UNIX local uniquement), et que le concept ne fait pas partie du protocole Varlink, mais simplement une fonctionnalité du transport sous-jacent.

sd_varlink_push_dup_fd() est identique à sd_varlink_push_fd(), sauf que le descripteur de fichier est dupliqué automatiquement, et le code de l'application appelante conserve donc la propriété du descripteur de fichier fourni, et doit le fermer de sa propre initiative.

Notez que le passage de descripteurs de fichiers n'est autorisé qu'après un appel à sd_varlink_set_allow_fd_passing_output() qui l'active, sinon ces appels échoueront avec -EPERM.

Notez que sous Linux, un maximum de 253 descripteurs de fichiers peuvent être mis en file d'attente sur des sockets AF_UNIX à la fois. Tenter d'en mettre plus sur un seul message Varlink échouera avec -ENOBUFS.

VALEUR DE RETOUR

En cas de succès, sd_varlink_push_fd() et sd_varlink_push_dup_fd() retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un argument est invalide.

-EBADF

Le descripteur de fichier fourni n'est pas valide.

-EPERM

Le passage de descripteurs de fichiers n'a pas été activé via sd_varlink_set_allow_fd_passing_output().

-ENOBUFS

Le maximum de 253 descripteurs de fichiers a déjà été soumis pour le prochain message Varlink sortant, aucun autre descripteur ne peut être mis en file d'attente pour ce message.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_varlink_push_fd() et sd_varlink_push_dup_fd() ont été ajoutés dans la version 257.
