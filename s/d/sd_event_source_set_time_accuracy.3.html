SD_EVENT_ADD_TIME(3) sd_event_add_time SD_EVENT_ADD_TIME(3)

NOM

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Ajouter une source d'événements de minuteur à une boucle d'événements

SYNOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPTION

sd_event_add_time() ajoute une nouvelle source d'événement de minuteur à une boucle d'événements. L'objet de la boucle d'événements est spécifié dans le paramètre event, l'objet de la source d'événements est renvoyé dans le paramètre source. Le paramètre clock prend un identifiant d'horloge, l'un de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, ou CLOCK_BOOTTIME_ALARM. Voir timerfd_create(2) pour plus de détails sur les différents types d'horloges. Le paramètre usec spécifie l'heure la plus tôt, en microsecondes (μs), par rapport à l'époque de l'horloge, à laquelle le minuteur doit se déclencher. Si une heure déjà passée est spécifiée (y compris 0), cette source de minuteur "se déclenche" immédiatement et est prête à être exécutée. Si le paramètre est spécifié comme UINT64_MAX, l'événement de minuteur n'expirera jamais, ce qui peut être utilisé comme alternative à la désactivation explicite d'une source d'événement de minuteur avec sd_event_source_set_enabled(3). Le paramètre accuracy spécifie une valeur de précision supplémentaire en μs indiquant de combien l'événement de minuteur peut être retardé. Utilisez 0 pour sélectionner la précision par défaut (250 ms). Utilisez 1 μs pour une précision maximale. Envisagez de spécifier 60000000 μs (1 minute) ou plus pour les événements de longue durée qui peuvent être retardés de manière significative. Le choix de valeurs de précision plus élevées permet au système de regrouper plus agressivement les événements de minuteur, améliorant l'efficacité énergétique.

Le handler est une fonction à appeler lorsque le minuteur expire ou NULL. Le pointeur userdata sera passé à la fonction de rappel, et peut être choisi librement par l'appelant. L'heure de déclenchement configurée est également passée au rappel, même si l'appel se produit en réalité légèrement plus tard, sous réserve de la valeur de précision spécifiée, du délai du minuteur du noyau (voir prctl(2)) et des latences de planification supplémentaires. Pour interroger l'heure réelle à laquelle le rappel a été appelé, utilisez sd_event_now(3). Le rappel peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un rappel par défaut qui appelle sd_event_exit(3) sera utilisé.

Par défaut, le minuteur n'expirera qu'une fois (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de rappel renvoie un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, soit elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3). Notez qu'un événement de minuteur réglé sur SD_EVENT_ON se déclenchera en continu à moins que son heure configurée ne soit mise à jour en utilisant sd_event_source_set_time().

sd_event_add_time_relative() est similaire à sd_event_add_time(), mais prend une spécification de temps relatif. Il est relatif à l'heure actuelle de l'itération de la boucle d'événements, telle que renvoyée par sd_event_now(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont supprimées. Pour vous assurer qu'une source d'événement ne se déclenche plus, même si elle est toujours référencée, désactivez la source d'événement en utilisant sd_event_source_set_enabled(3) avec SD_EVENT_OFF.

Si le deuxième paramètre de sd_event_add_time() est NULL, aucune référence à l'objet source d'événement n'est renvoyée. Dans ce cas, la source d'événement est considérée comme "flottante", et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_time() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Utilisez CLOCK_BOOTTIME_ALARM et CLOCK_REALTIME_ALARM pour définir des sources d'événements qui peuvent réveiller le système de la mise en veille.

Afin de configurer des minuteurs relatifs (c'est-à-dire, relatifs à l'heure actuelle), récupérez l'heure actuelle via sd_event_now(3), ajoutez la durée souhaitée, et utilisez le résultat comme paramètre usec pour sd_event_add_time().

Afin de configurer des minuteurs répétitifs (c'est-à-dire, des minuteurs qui se déclenchent à intervalles réguliers), configurez le minuteur normalement, pour la première invocation. Chaque fois que le gestionnaire d'événements est invoqué, mettez à jour l'heure de déclenchement du minuteur avec sd_event_source_set_time(3) pour la prochaine itération du minuteur, et réactivez le minuteur en utilisant sd_event_source_set_enabled(). Pour calculer le prochain point dans le temps à passer à sd_event_source_set_time(), utilisez soit comme base le paramètre usec passé au rappel du minuteur, soit l'horodatage renvoyé par sd_event_now(). Dans le premier cas, les événements de minuteur seront réguliers, tandis que dans le second cas, la latence de planification continuera de s'accumuler sur le minuteur.

sd_event_source_get_time() récupère la valeur de temps configurée d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker le temps, relatif à l'époque de l'horloge sélectionnée, en μs. La valeur renvoyée est relative à l'époque, même si la source d'événement a été créée avec un temps relatif via sd_event_add_time_relative().

sd_event_source_set_time() modifie l'heure d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et une heure relative à l'époque de l'horloge sélectionnée, en μs.

sd_event_source_set_time_relative() est similaire à sd_event_source_set_time(), mais prend une heure relative à l'heure actuelle de l'itération de la boucle d'événements, telle que renvoyée par sd_event_now().

sd_event_source_get_time_accuracy() récupère la valeur de précision configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker la précision. La précision est spécifiée en μs.

sd_event_source_set_time_accuracy() modifie la précision configurée d'une source d'événement de minuteur.

ERREURS

Les fonctions renvoient 0 en cas de succès, et un code d'erreur négatif en cas d'échec. En cas d'échec, la valeur peut être l'une des constantes ci-dessous.

-ENOMEM

   Pas assez de mémoire.

-EINVAL

   Paramètre invalide fourni.

-ESTALE

   Le type de compte d'horloge n'est pas valide pour le système.

-ECHILD

   La boucle d'événements a déjà été détruite.

-EAGAIN

   Le délai spécifié est trop long.

DISPONIBILITÉ

Ces fonctions sont disponibles sous forme de bibliothèque partagée dans le paquet libsystemd, et sont utilisables avec les programmes qui lient contre libsystemd.

NAME

sd_event_source_set_time_accuracy, sd_event_source_get_time_accuracy, sd_event_source_get_time_clock - Modifier et interroger la précision et l'horloge d'une source d'événements temporels

SYNOPSIS

#include <systemd/sd-event.h>

int
sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t accuracy_us);

int
sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *accuracy_us);

int
sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock_id);

DESCRIPTION

sd_event_source_set_time_accuracy() définit la précision souhaitée pour une source d'événements temporels créée précédemment avec sd_event_add_time(). L'argument accuracy_us est le temps en microsecondes. Un réglage de 0 désactive la demande de précision, et la source d'événement sera exécutée dès que possible.

sd_event_source_get_time_accuracy() récupère la précision configurée d'une source d'événements temporels créée précédemment avec sd_event_add_time(). L'argument accuracy_us est un pointeur vers une variable pour stocker la précision en microsecondes.

sd_event_source_get_time_clock() récupère l'horloge configurée d'une source d'événements temporels créée précédemment avec sd_event_add_time(). L'argument clock_id est un pointeur vers une variable pour stocker l'identifiant de l'horloge.

RETURN VALUE

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Errors

Les valeurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

-EOPNOTSUPP

L'horloge sélectionnée n'est pas prise en charge par l'implémentation de la boucle d'événements.

-EDOM

La source d'événements passée n'est pas une source d'événements temporels.

-EOVERFLOW

Le temps relatif passé est en dehors de la plage autorisée pour les valeurs temporelles (c'est-à-dire que la valeur spécifiée ajoutée au temps actuel est en dehors de la plage des entiers non signés de 64 bits).

Ajouté dans la version 247.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
