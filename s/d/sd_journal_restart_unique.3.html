SD_JOURNAL_QUERY_UNIQUE(3) sd_journal_query_unique SD_JOURNAL_QUERY_UNIQUE(3)

NOM

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - Lire les champs de données uniques du journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

DESCRIPTION

sd_journal_query_unique() interroge le journal pour obtenir toutes les valeurs uniques que le champ spécifié peut prendre. Il prend deux arguments : le journal à interroger et le nom du champ à rechercher. Les noms de champs bien connus sont listés dans systemd.journal-fields(7), mais tout champ peut être spécifié. Les noms de champs doivent être spécifiés sans "=" à la fin. Après l'exécution réussie de cette fonction, les valeurs des champs peuvent être interrogées en utilisant sd_journal_enumerate_unique() et sd_journal_enumerate_available_unique(). L'invocation de l'un de ces appels changera le nom du champ interrogé et réinitialisera l'index d'énumération au premier champ correspondant.

sd_journal_enumerate_unique() peut être utilisé pour parcourir tous les champs de données qui correspondent au nom de champ précédemment sélectionné tel que défini avec sd_journal_query_unique(). À chaque invocation, la prochaine donnée de champ correspondant au nom de champ est retournée. L'ordre des champs de données retournés n'est pas défini. Il prend trois arguments : l'objet journal, plus une paire de pointeurs vers des variables de pointeur/taille où l'objet de données et sa taille doivent être stockés. Les données retournées sont dans une zone mémoire en lecture seule et ne sont valides que jusqu'à la prochaine invocation de sd_journal_enumerate_unique(). Notez que les données retournées seront préfixées par le nom du champ et "=". Notez que cet appel est soumis au seuil de taille des champs de données contrôlé par sd_journal_set_data_threshold() et seule la partie initiale du champ jusqu'au seuil est retournée. Une erreur est retournée pour les champs qui ne peuvent pas être récupérés. Voir la liste des erreurs ci-dessous pour les détails.

sd_journal_enumerate_available_unique() est similaire à sd_journal_enumerate_unique(), mais saute silencieusement tout champ qui peut être valide, mais est trop grand ou non pris en charge par l'implémentation actuelle.

sd_journal_restart_unique() réinitialise l'index d'énumération des données au début de la liste. La prochaine invocation de sd_journal_enumerate_unique() retournera à nouveau la première donnée de champ correspondant au nom de champ.

Notez que la macro SD_JOURNAL_FOREACH_UNIQUE() peut être utilisée comme un wrapper pratique autour de sd_journal_restart_unique() et sd_journal_enumerate_available_unique().

Notez que ces fonctions ne sont actuellement pas influencées par les correspondances définies avec sd_journal_add_match(), mais cela pourrait changer dans une version ultérieure de ce logiciel.

Pour énumérer tous les noms de champs actuellement utilisés (et donc tous les paramètres de champs appropriés pour sd_journal_query_unique()), utilisez l'appel sd_journal_enumerate_fields(3).

VALEUR DE RETOUR

sd_journal_query_unique() retourne 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_enumerate_unique() et sd_journal_query_available_unique() retournent un entier positif si les données du champ suivant ont été lues, 0 s'il n'y a plus de champs, ou un code d'erreur négatif de style errno. sd_journal_restart_unique() ne retourne rien.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

L'un des paramètres requis est NULL ou invalide.

Ajouté dans la version 246.

-ECHILD

L'objet journal a été créé dans un processus, une bibliothèque ou une instance de module différente.

Ajouté dans la version 246.

-EADDRNOTAVAIL

Le pointeur de lecture n'est pas positionné sur une entrée valide ; sd_journal_next(3) ou un appel apparenté n'a pas été appelé au moins une fois.

Ajouté dans la version 246.

-ENOENT

L'entrée actuelle n'inclut pas le champ spécifié.

Ajouté dans la version 246.

-ENOBUFS

Une entrée compressée est trop volumineuse.

Ajouté dans la version 246.

-E2BIG

Le champ de données est trop volumineux pour cette architecture informatique (par exemple, au-dessus de 4 Go sur une architecture 32 bits).

Ajouté dans la version 246.

-EPROTONOSUPPORT

Le journal est compressé avec une méthode non prise en charge ou le journal utilise une fonctionnalité non prise en charge.

Ajouté dans la version 246.

-EBADMSG

Le journal est corrompu (potentiellement seulement l'entrée en cours d'itération).

Ajouté dans la version 246.

-EIO

Une erreur d'E/S a été signalée par le noyau.

Ajouté dans la version 246.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à la fois. Différents threads peuvent accéder au même objet à différents moments. Plusieurs objets indépendants peuvent être utilisés par différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

EXEMPLES

Utilisez la macro SD_JOURNAL_FOREACH_UNIQUE() pour parcourir toutes les valeurs qu'un champ du journal peut prendre (et qui sont accessibles sur l'architecture donnée et ne sont pas compressées avec un mécanisme non pris en charge). L'exemple suivant liste tous les noms d'unités référencés dans le journal :

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "Failed to query journal: %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

NAME

sd_journal_restart_unique - Restart a journal query for a specific journal entry

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_restart_unique(sd_journal *j, const char *id);

DESCRIPTION

The sd_journal_restart_unique() function may be used to reposition the journal cursor of an existing journal query object j to the entry identified by id. This is useful to restart iterating over a specific entry in the journal.

The id parameter should be a string that uniquely identifies a journal entry. Currently, this is the value of the _CURSOR field. The cursor is a string that is returned by sd_journal_get_cursor().

This function is useful if you want to, for example, retrieve all entries that were logged after a specific entry.

It is important to note that the cursor string is considered an opaque value. It might change its format or content in future versions of systemd. Thus, it should not be parsed or modified.

Use sd_journal_get_cursor() to get the cursor string for the current journal entry. Use sd_journal_seek_cursor() to seek to a specific cursor.

RETURN VALUE

On success, sd_journal_restart_unique() returns 0 or a positive integer. On failure, it returns a negative errno value.

NOTES

The cursor string obtained from sd_journal_get_cursor() might not be valid anymore when sd_journal_restart_unique() is called. This might happen if the journal has been rotated or if entries have been removed. In such cases, sd_journal_restart_unique() will return -ENOENT.

EXAMPLES

Get the cursor of the current entry, then restart the query from that entry:

char *cursor = NULL;
int r;

r = sd_journal_get_cursor(j, &cursor);
if (r < 0) {
    fprintf(stderr, "Failed to get cursor: %s\n", strerror(-r));
    goto cleanup;
}

if (cursor) {
    r = sd_journal_restart_unique(j, cursor);
    if (r < 0) {
        fprintf(stderr, "Failed to restart unique: %s\n", strerror(-r));
        goto cleanup;
    }
}
// ... process journal entries starting from the cursor ...

cleanup:
    free(cursor);

HISTORY

The sd_journal_restart_unique() function was introduced in version 220.
