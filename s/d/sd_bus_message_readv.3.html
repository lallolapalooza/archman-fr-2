SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

NOM

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Lire une séquence de valeurs à partir d'un message

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

DESCRIPTION

sd_bus_message_read() lit une séquence de champs depuis l'objet D-Bus m et fait avancer la position de lecture dans le message. La chaîne de types types décrit les types des éléments attendus dans le message et les arguments de champ qui suivent. La chaîne de types peut être NULL ou vide, auquel cas rien n'est lu.

La chaîne de types est composée des éléments décrits dans sd_bus_message_append(3), c'est-à-dire les types de base et les types conteneurs. Elle doit contenir zéro ou plusieurs "types complets" uniques. La chaîne de types est terminée par NUL.

Pour chaque type spécifié dans la chaîne de types, un ou plusieurs arguments doivent être spécifiés après le paramètre types, dans le même ordre. Les arguments doivent être des pointeurs vers des types appropriés (un pointeur vers int8_t pour un "y" dans la chaîne de types, un pointeur vers int32_t pour un "i", un pointeur vers const char* pour un "s", ...) qui sont définis en fonction des valeurs dans le message. À titre d'exception, dans le cas des tableaux et des types variants, le premier argument est un argument "d'entrée" qui spécifie davantage comment le message doit être lu. Voir le tableau ci-dessous pour une liste complète des arguments autorisés et de leurs types. Notez que si le type de base est un pointeur (par exemple, const char * dans le cas d'une chaîne), l'argument est un pointeur vers un pointeur, et la valeur du pointeur écrite est seulement empruntée et son contenu doit être copié s'il doit être utilisé après la fin de la durée de vie du message. Si le type est "h" (descripteur de fichier UNIX), le descripteur n'est pas dupliqué par cet appel et le descripteur retourné reste en possession de l'objet message, et doit être dupliqué par l'appelant afin de conserver une référence ouverte à celui-ci après la libération de l'objet message.

Chaque argument peut également être NULL, auquel cas la valeur est lue et ignorée.

Si des objets des types spécifiés ne sont pas présents à la position actuelle dans le message, une erreur est renvoyée.

sd_bus_message_readv() est équivalent à sd_bus_message_read(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments. Cette fonction n'appelle pas la macro va_end(). Comme elle invoque la macro va_arg(), la valeur de ap est indéfinie après l'appel.

sd_bus_message_peek_type() détermine le type du prochain élément dans m à lire par sd_bus_message_read() ou des fonctions similaires. En cas de succès, le type est stocké dans type, s'il n'est pas NULL. Si le type est un type conteneur, le type de ses éléments est stocké dans contents, s'il n'est pas NULL. Si cette fonction détermine avec succès le type du prochain élément dans m, elle renvoie un entier positif. S'il n'y a plus d'éléments à lire, elle renvoie zéro.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier non négatif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

La chaîne de types spécifiée est invalide ou le paramètre de message est NULL.

-ENXIO

Le message ne contient pas le type spécifié à la position actuelle.

-EBADMSG

Le message ne peut pas être analysé.

-EBUSY

Lors de la lecture à partir d'un conteneur, cette erreur sera renvoyée s'il reste des éléments non lus dans le conteneur.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

sd_bus_message_readv(3) — systemd — Arch Linux

NAME

sd_bus_message_readv, sd_bus_message_read, sd_bus_message_peek_type - Lire les données d'un message D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>
long sd_bus_message_readv(sd_bus_message *m, const char *types, sd_bus_message_message_v *v);
long sd_bus_message_read(sd_bus_message *m, const char *types, ...);
long sd_bus_message_peek_type(sd_bus_message *m, const char *type, uint8_t **value);

DESCRIPTION

La fonction sd_bus_message_readv() lit un ensemble de champs du message D-Bus m selon le type de signature types. La liste des pointeurs vers les variables où les champs lus doivent être stockés est fournie dans v. La fonction sd_bus_message_read() est une variante pratique qui accepte une liste d'arguments de variable (varargs) au lieu d'un tableau sd_bus_message_message_v. Elle est donc plus facile à utiliser pour la plupart des cas.

Les signatures de type sont décrites dans sd-bus(3). Si la lecture d'un champ échoue, ou si le type de signature ne correspond pas au champ attendu, un code d'erreur négatif est renvoyé. Si un conteneur (tableau ou dictionnaire) est lu, il est entré automatiquement.

Pour les conteneurs, la signature de type peut être préfixée par un entier qui spécifie le nombre d'éléments à lire (en cas de tableaux) ou le nombre de paires clé-valeur à lire (en cas de dictionnaires). Si aucun entier n'est fourni, tous les éléments restants dans le conteneur sont lus. Pour les tableaux, l'entier spécifie le nombre d'éléments. Pour les dictionnaires, l'entier spécifie le nombre de paires clé-valeur.

Le tableau v doit contenir un pointeur pour chaque caractère de la chaîne types. Pour les types de base, il s'agit d'un pointeur vers la variable appropriée. Pour les tableaux et les dictionnaires, il faut entrer dans le conteneur en utilisant sd_bus_message_enter_container() avant de lire les éléments, puis en sortir en utilisant sd_bus_message_exit_container(). Pour les variantes, il faut lire le type de signature interne, puis lire la valeur avec le type de signature interne. Notez que la duplication d'un descripteur de fichier lu (type 'h') est de la responsabilité de l'appelant.

La fonction sd_bus_message_peek_type() examine le prochain champ dans le message m sans le consommer. Si type est spécifié, il doit correspondre au type du champ suivant. Si c'est le cas, value sera défini sur un pointeur vers la valeur du champ. Cela ne fonctionne que pour les types de base et les descripteurs de fichier, mais pas pour les conteneurs ou les variantes. Si le champ est un descripteur de fichier, value sera un pointeur vers un entier non signé de 32 bits.

RETURN VALUE

En cas de succès, ces fonctions renvoient le nombre d'octets lus. En cas d'échec, elles renvoient un code d'erreur négatif.

NOTES

La fonction sd_bus_message_read() utilise une liste d'arguments de variable (varargs) pour passer les pointeurs de destination. Cela signifie que la liste des types de signature types ne doit pas contenir plus de 64 caractères. La fonction sd_bus_message_readv() n'a pas cette limitation.

La fonction sd_bus_message_read() est intrinsèquement non sécurisée car le nombre d'arguments passés à la fonction ne peut pas être vérifié au moment de la compilation. Il est donc recommandé d'utiliser sd_bus_message_readv() ou sd_bus_message_read_basic() autant que possible.

Lors de la lecture de types numériques, il est important d'utiliser le type C approprié pour éviter la corruption de la mémoire. Par exemple, n'utilisez pas le type C99 bool pour lire un booléen D-Bus, car il est généralement plus petit en mémoire et peut entraîner une corruption de la mémoire.

EXAMPLES

Lire un seul type de base (un entier de 64 bits) :

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Lire une valeur booléenne :

sd_bus_message *m;
int x; /* Ne pas utiliser le type C99 "bool" ici, il est généralement plus petit
          en mémoire et provoquerait une corruption de la mémoire */
sd_bus_message_read(m, "b", &x);

Lire tous les types d'entiers :

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Lire une structure composée d'une chaîne et d'un chemin D-Bus :

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Lire une variante, avec le type de signature réel "gt" (signature, entier non signé) :

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Lire un dictionnaire contenant trois paires de type {entier=>chaîne} :

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Lire un seul descripteur de fichier, et le dupliquer afin de le conserver ouvert après la libération du message.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);

HISTORY

sd_bus_message_read() et sd_bus_message_readv() ont été ajoutées dans la version 240.

sd_bus_message_peek_type() a été ajoutée dans la version 246.
