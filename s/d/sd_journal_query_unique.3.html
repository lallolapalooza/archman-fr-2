sd_journal_query_unique(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_JOURNAL_QUERY_UNIQUE(3) sd_journal_query_unique SD_JOURNAL_QUERY_UNIQUE(3)

NOM

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - Lire les champs de données uniques du journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

DESCRIPTION

sd_journal_query_unique() interroge le journal pour toutes les valeurs uniques que le champ spécifié peut prendre. Il prend deux arguments : le journal à interroger et le nom du champ à rechercher. Les noms de champs bien connus sont listés dans systemd.journal-fields(7), mais tout champ peut être spécifié. Les noms de champs doivent être spécifiés sans "=" final. Après l'exécution réussie de cette fonction, les valeurs des champs peuvent être interrogées en utilisant sd_journal_enumerate_unique() et sd_journal_enumerate_available_unique(). L'appel de l'une de ces fonctions modifiera le nom du champ interrogé et réinitialisera l'index de l'énumération au premier champ dont la valeur correspond.

sd_journal_enumerate_unique() peut être utilisé pour itérer à travers tous les champs de données qui correspondent au nom de champ précédemment sélectionné comme défini avec sd_journal_query_unique(). À chaque invocation, la prochaine donnée de champ correspondant au nom du champ est retournée. L'ordre des champs de données retournés n'est pas défini. Il prend trois arguments : l'objet journal, ainsi qu'une paire de pointeurs vers des variables pointeur/taille où l'objet de données et sa taille doivent être stockés. Les données retournées sont dans une zone mémoire en lecture seule et ne sont valides que jusqu'à la prochaine invocation de sd_journal_enumerate_unique(). Notez que les données retournées seront précédées du nom du champ et de "=". Notez que cet appel est soumis au seuil de taille des données contrôlé par sd_journal_set_data_threshold() et seule la partie initiale du champ jusqu'au seuil est retournée. Une erreur est retournée pour les champs qui ne peuvent pas être récupérés. Voir la liste des erreurs ci-dessous pour plus de détails.

sd_journal_enumerate_available_unique() est similaire à sd_journal_enumerate_unique(), mais ignore silencieusement tous les champs qui peuvent être valides, mais sont trop grands ou non pris en charge par l'implémentation actuelle.

sd_journal_restart_unique() réinitialise l'index d'énumération des données au début de la liste. La prochaine invocation de sd_journal_enumerate_unique() retournera à nouveau la première donnée de champ correspondant au nom du champ.

Notez que la macro SD_JOURNAL_FOREACH_UNIQUE() peut être utilisée comme un enveloppement pratique autour de sd_journal_restart_unique() et sd_journal_enumerate_available_unique().

Notez que ces fonctions ne sont actuellement pas influencées par les correspondances définies avec sd_journal_add_match(), mais cela pourrait changer dans une future version de ce logiciel.

Pour énumérer tous les noms de champs actuellement utilisés (et donc tous les paramètres de champs appropriés pour sd_journal_query_unique()), utilisez l'appel sd_journal_enumerate_fields(3).

VALEUR DE RETOUR

sd_journal_query_unique() retourne 0 en cas de succès ou un code d'erreur négatif de type errno. sd_journal_enumerate_unique() et sd_journal_query_available_unique() retournent un entier positif si la prochaine donnée de champ a été lue, 0 lorsqu'il ne reste plus de champs, ou un code d'erreur négatif de type errno. sd_journal_restart_unique() ne retourne rien.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

L'un des paramètres requis est NULL ou invalide.

Ajouté dans la version 246.

-ECHILD

L'objet journal a été créé dans un autre processus, bibliothèque ou instance de module.

Ajouté dans la version 246.

-EADDRNOTAVAIL

Le pointeur de lecture n'est pas positionné sur une entrée valide ; sd_journal_next(3) ou un appel similaire n'a pas été appelé au moins une fois.

Ajouté dans la version 246.

-ENOENT

L'entrée actuelle n'inclut pas le champ spécifié.

Ajouté dans la version 246.

-ENOBUFS

Une entrée compressée est trop volumineuse.

Ajouté dans la version 246.

-E2BIG

Le champ de données est trop volumineux pour cette architecture informatique (par exemple, supérieur à 4 Go sur une architecture 32 bits).

Ajouté dans la version 246.

-EPROTONOSUPPORT

Le journal est compressé avec une méthode non prise en charge ou le journal utilise une fonctionnalité non prise en charge.

Ajouté dans la version 246.

-EBADMSG

Le journal est corrompu (éventuellement seulement l'entrée en cours d'itération).

Ajouté dans la version 246.

-EIO

Une erreur d'E/S a été signalée par le noyau.

Ajouté dans la version 246.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à la fois. Différents threads peuvent accéder au même objet à différents moments. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

EXEMPLES

Utilisez la macro SD_JOURNAL_FOREACH_UNIQUE() pour itérer à travers toutes les valeurs qu'un champ du journal peut prendre (et qui sont accessibles sur l'architecture donnée et ne sont pas compressées avec un mécanisme non pris en charge). L'exemple suivant liste tous les noms d'unités référencées dans le journal :

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Échec de l'ouverture du journal : %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "Échec de l'interrogation du journal : %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

HISTORIQUE

sd_journal_query_unique(), sd_journal_enumerate_unique(), sd_journal_restart_unique(), et SD_JOURNAL_FOREACH_UNIQUE() ont été ajoutés dans la version 195.

sd_journal_enumerate_available_unique() a été ajouté dans la version 246.
