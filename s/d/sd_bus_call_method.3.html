SD_BUS_CALL_METHOD(3) sd_bus_call_method SD_BUS_CALL_METHOD(3)

NOM

sd_bus_call_method, sd_bus_call_methodv, sd_bus_call_method_async, sd_bus_call_method_asyncv - Initialise un objet message bus et invoque l'appel de méthode D-Bus correspondant

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_call_method(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *ret_error, sd_bus_message **reply, const char *types, ...);

int sd_bus_call_methodv(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *ret_error, sd_bus_message **reply, const char *types, va_list ap);

int sd_bus_call_method_async(sd_bus *bus, sd_bus_slot **slot, const char *destination, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, void *userdata, const char *types, ...);

int sd_bus_call_method_asyncv(sd_bus *bus, sd_bus_slot **slot, const char *destination, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, void *userdata, const char *types, va_list ap);

DESCRIPTION

sd_bus_call_method() est une fonction pratique pour initialiser un objet message bus et appeler la méthode D-Bus correspondante. Elle combine les fonctions sd_bus_message_new_method_call(3), sd_bus_message_append(3) et sd_bus_call(3) en un seul appel de fonction.

sd_bus_call_method_async() est une fonction pratique pour initialiser un objet message bus et appeler la méthode D-Bus correspondante de manière asynchrone. Elle combine les fonctions sd_bus_message_new_method_call(3), sd_bus_message_append(3) et sd_bus_call_async(3) en un seul appel de fonction.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Voir les pages man de sd_bus_message_new_method_call(3), sd_bus_message_append(3), sd_bus_call(3) et sd_bus_call_async(3) pour une liste des erreurs possibles.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels concurrents (multi-thread-safe). Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de faire les appels à setenv() uniquement dans une phase précoce du programme lorsque aucun autre thread n'a été démarré.

EXEMPLES

Exemple 1. Appel d'une méthode D-Bus qui prend un seul paramètre

/* SPDX-License-Identifier: MIT-0 */
/* Ceci est équivalent à :
 * busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 \
 *       org.freedesktop.systemd1.Manager GetUnitByPID $$
 *
 * Compiler avec 'cc print-unit-path-call-method.c -lsystemd'
 */
#include <errno.h>
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
#define DESTINATION "org.freedesktop.systemd1"
#define PATH        "/org/freedesktop/systemd1"
#define INTERFACE   "org.freedesktop.systemd1.Manager"
#define MEMBER      "GetUnitByPID"
static int log_error(int error, const char *message) {
  fprintf(stderr, "%s: %s\n", message, strerror(-error));
  return error;
}
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  _cleanup_(sd_bus_error_free) sd_bus_error error = SD_BUS_ERROR_NULL;
  _cleanup_(sd_bus_message_unrefp) sd_bus_message *reply = NULL;
  int r;
  r = sd_bus_open_system(&bus);
  if (r < 0)
    return log_error(r, "Failed to acquire bus");
  r = sd_bus_call_method(bus, DESTINATION, PATH, INTERFACE, MEMBER, &error, &reply, "u", (unsigned) getpid());
  if (r < 0)
    return log_error(r, MEMBER " call failed");
  const char *ans;
  r = sd_bus_message_read(reply, "o", &ans);
  if (r < 0)
    return log_error(r, "Failed to read reply");
  printf("Unit path is \"%s\".\n", ans);
  return 0;
}

Ceci définit un programme minimalement utile qui ouvrira une connexion au bus, appellera une méthode, attendra la réponse, puis extraira et affichera la réponse. Il gère les erreurs et la gestion correcte de la mémoire.

HISTORIQUE

sd_bus_call_method(), et sd_bus_call_method_async() ont été ajoutés dans la version 221.

sd_bus_call_methodv(), sd_bus_call_method_asyncv() ont été ajoutés dans la version 246.

DESCRIPTION

These functions may be used to perform a D-Bus method call synchronously or asynchronously. They are convenience wrappers around sd_bus_call(3).

The functions differ in how they handle the arguments and return values:

sd_bus_call_method(), sd_bus_call_method_async(), sd_bus_call_method_real(), sd_bus_call_method_sender()
These functions take the method arguments as a variable argument list (... or va_list). The argument types are described by the types string. The return value is the D-Bus reply message. If an error occurs, the error is returned in ret_error.
sd_bus_call_method_get(), sd_bus_call_method_get_async(), sd_bus_call_method_get_real(), sd_bus_call_method_get_sender(), sd_bus_call_method_get_put()
These functions are similar to the above, but they return the reply message in the reply parameter. This is useful for methods that return a complex data structure.
sd_bus_call_method_put()
This function is similar to sd_bus_call_method(), but it returns the reply message in the reply parameter.

The bus parameter is a connection to the D-Bus bus. The destination, path, interface, and member parameters specify the target object and method. The types string describes the types of the arguments and return values. The remaining arguments are the method arguments, followed by a null pointer to terminate the list.

The sd_bus_call_method_async() and sd_bus_call_method_get_async() functions are non-blocking. They return immediately, and the result of the method call is delivered to the callback function when it becomes available.

The sd_bus_call_method_real() and sd_bus_call_method_get_real() functions take a va_list as the argument list.

The sd_bus_call_method_sender() and sd_bus_call_method_get_sender() functions allow specifying the sender of the method call using the sender parameter.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

DESCRIPTION

Ces fonctions peuvent être utilisées pour effectuer un appel de méthode D-Bus de manière synchrone ou asynchrone. Ce sont des enveloppes pratiques autour de sd_bus_call(3).

Les fonctions diffèrent dans la manière dont elles gèrent les arguments et les valeurs de retour :

sd_bus_call_method(), sd_bus_call_method_async(), sd_bus_call_method_real(), sd_bus_call_method_sender()
Ces fonctions prennent les arguments de méthode sous forme de liste d'arguments variables (... ou va_list). Les types d'arguments sont décrits par la chaîne types. La valeur de retour est le message de réponse D-Bus. Si une erreur se produit, l'erreur est retournée dans ret_error.
sd_bus_call_method_get(), sd_bus_call_method_get_async(), sd_bus_call_method_get_real(), sd_bus_call_method_get_sender(), sd_bus_call_method_get_put()
Ces fonctions sont similaires aux précédentes, mais elles retournent le message de réponse dans le paramètre reply. Ceci est utile pour les méthodes qui retournent une structure de données complexe.
sd_bus_call_method_put()
Cette fonction est similaire à sd_bus_call_method(), mais elle retourne le message de réponse dans le paramètre reply.

Le paramètre bus est une connexion au bus D-Bus. Les paramètres destination, path, interface et member spécifient l'objet et la méthode cibles. La chaîne types décrit les types des arguments et des valeurs de retour. Les arguments restants sont les arguments de la méthode, suivis d'un pointeur nul pour terminer la liste.

Les fonctions sd_bus_call_method_async() et sd_bus_call_method_get_async() ne bloquent pas. Elles retournent immédiatement, et le résultat de l'appel de méthode est délivré à la fonction callback lorsqu'il devient disponible.

Les fonctions sd_bus_call_method_real() et sd_bus_call_method_get_real() prennent une va_list comme liste d'arguments.

Les fonctions sd_bus_call_method_sender() et sd_bus_call_method_get_sender() permettent de spécifier l'expéditeur de l'appel de méthode à l'aide du paramètre sender.

VALEUR RENVOYÉE

En cas de succès, ces fonctions retournent un entier positif. En cas d'échec, elles retournent un nombre d'erreur négatif.
