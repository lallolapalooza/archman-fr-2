NOM

sd_event_wait, sd_event_prepare, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Opérations de bas niveau de la boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_state(sd_event *event);

int sd_event_get_iteration(sd_event *event, uint64_t *ret);

DESCRIPTION

Les fonctions de bas niveau sd_event_prepare(), sd_event_wait() et sd_event_dispatch() peuvent être utilisées pour exécuter des phases spécifiques d'une boucle d'événements. Voir sd_event_run(3) et sd_event_loop(3) pour des fonctions de plus haut niveau qui exécutent des itérations individuelles mais complètes d'une boucle d'événements ou la font tourner en continu.

sd_event_prepare() vérifie les événements en attente et arme les timers nécessaires. Si des événements sont prêts à être traités ("en attente"), elle retourne une valeur positive non nulle, et l'appelant doit traiter ces événements avec sd_event_dispatch().

sd_event_dispatch() distribue la source d'événements de plus haute priorité qui a un événement en attente. En cas de succès, sd_event_dispatch() retourne soit zéro, ce qui indique qu'aucune autre source d'événement ne peut être distribuée et que la sortie de la boucle d'événements a été demandée via sd_event_exit(3) ; soit une valeur positive non nulle, ce qui signifie qu'une source d'événement a été distribuée et que la boucle est revenue à son état initial, et l'appelant doit initier la prochaine itération de la boucle d'événements en invoquant à nouveau sd_event_prepare().

Dans le cas où sd_event_prepare() a retourné zéro, sd_event_wait() doit être appelée pour attendre d'autres événements ou un délai d'attente. Si des événements sont prêts à être traités, elle retourne une valeur positive non nulle, et les événements doivent être distribués avec sd_event_dispatch(). Sinon, la boucle d'événements est revenue à son état initial et la prochaine itération de la boucle d'événements doit être initiée en invoquant à nouveau sd_event_prepare().

sd_event_get_state() peut être utilisée pour déterminer l'état dans lequel se trouve actuellement la boucle d'événements. Elle retourne un des états décrits ci-dessous.

sd_event_get_iteration() peut être utilisée pour déterminer l'itération actuelle de la boucle d'événements. Elle retourne un entier de 64 bits non signé contenant un compteur qui augmente de manière monotone à chaque itération de la boucle d'événements, en commençant par 0. Le compteur est augmenté au moment de l'invocation de sd_event_prepare().

Les cinq fonctions prennent, comme premier argument, l'objet de boucle d'événements event qui a été créé avec sd_event_new(). Le délai d'attente pour sd_event_wait() est spécifié en usec en microsecondes. (uint64_t) -1 peut être utilisé pour spécifier un délai d'attente infini.

MACHINE D'ÉTAT

La boucle d'événements connaît les états suivants, qui peuvent être interrogés avec sd_event_get_state().

SD_EVENT_INITIAL

L'état initial dans lequel se trouve la boucle d'événements, avant chaque itération de la boucle d'événements. Utiliser sd_event_prepare() pour faire passer la boucle d'événements aux états SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_PREPARING

Une source d'événements est en cours de préparation, c'est-à-dire que le gestionnaire de préparation est en cours d'exécution, comme défini avec sd_event_source_set_prepare(3). Cet état n'est vu que dans le gestionnaire de préparation d'événements qui est invoqué à partir de l'appel sd_event_prepare() et est immédiatement suivi par SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_ARMED

sd_event_prepare() a été appelé et aucune source d'événements n'était prête à être distribuée. Utiliser sd_event_wait() pour attendre de nouveaux événements, et passer à SD_EVENT_PENDING ou revenir à SD_EVENT_INITIAL.

Ajouté dans la version 229.

SD_EVENT_PENDING

sd_event_prepare() ou sd_event_wait() ont été appelés et il y avait des sources d'événements avec des événements en attente. Utiliser sd_event_dispatch() pour distribuer la source d'événements de plus haute priorité et revenir à SD_EVENT_INITIAL, ou à SD_EVENT_FINISHED.

Ajouté dans la version 229.

SD_EVENT_RUNNING

Une source d'événements régulière est actuellement en cours de distribution. Cet état n'est vu que dans le gestionnaire de source d'événements qui est invoqué à partir de l'appel sd_event_dispatch(), et est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire de source d'événements retourne. Notez que lors de la distribution des sources d'événements de sortie, l'état SD_EVENT_EXITING est vu à la place.

Ajouté dans la version 229.

SD_EVENT_EXITING

Similaire à SD_EVENT_RUNNING mais est l'état en vigueur lors de la distribution des sources d'événements de sortie. Il est suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire d'événements retourne.

Ajouté dans la version 229.

SD_EVENT_FINISHED

La boucle d'événements s'est terminée. Toutes les sources d'événements de sortie ont été exécutées. Si la boucle d'événements est dans cet état, elle ne sert plus à rien et devrait être libérée.

Ajouté dans la version 229.

Un schéma simplifié des états et des appels pour passer de l'un à l'autre est montré ci-dessous. Notez que SD_EVENT_PREPARING, SD_EVENT_RUNNING et SD_EVENT_EXITING ne sont pas montrés ici.

          INITIAL -<---<---<---<---<---<---<---<---<---<---<---<---\
             |                                                     |
             |                                                     ^
             |                                                     |
             v                 ret == 0                            |
      sd_event_prepare() >--->--->--->--->- ARMED                  |
             |                                |                    ^
             | ret > 0                        |                    |
             |                                |                    |
             v                                v          ret == 0  |
          PENDING <---<---<---<---<---< sd_event_wait() >--->--->--+
             |           ret > 0                                   ^
             |                                                     |
             |                                                     |
             v                                                     |
      sd_event_dispatch() >--->--->--->--->--->--->--->--->--->--->/
             |                             ret > 0
             | ret == 0
             |
             v
          FINISHED

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno. Dans le cas de sd_event_prepare() et sd_event_wait(), un code de retour positif non nul indique que des événements sont prêts à être traités et zéro indique qu'aucun événement n'est prêt. Dans le cas de sd_event_dispatch(), un code de retour positif non nul indique que la boucle d'événements est revenue à son état initial et zéro indique que la boucle d'événements s'est terminée. sd_event_get_state() retourne un état positif ou nul en cas de succès.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre event est invalide ou NULL.

-EBUSY

L'objet de boucle d'événements n'est pas dans le bon état.

-ESTALE

La boucle d'événements est déjà terminée.

NOM

sd_event_prepare, sd_event_wait, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration — préparer, attendre, et gérer un événement boucle

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_prepare(sd_event *s);
int sd_event_wait(sd_event *s, uint64_t usec);
int sd_event_dispatch(sd_event *s);
int sd_event_get_state(sd_event *s);
int sd_event_get_iteration(sd_event *s);

DESCRIPTION

Le noyau du système systemd utilise une boucle d'événements pour gérer et déclencher des événements. Les fonctions décrites ici sont des primitives de bas niveau pour interagir avec cette boucle d'événements.

Une boucle d'événements est représentée par la structure sd_event. Elle peut être créée avec sd_event_new(3).

sd_event_prepare est appelée au début de chaque itération de la boucle d'événements. Elle déclenche les méthodes prepare de toutes les sources d'événements qui sont configurées pour être préparées.

sd_event_wait est appelée après sd_event_prepare. Elle attend les événements entrants sur le descripteur de fichier principal de la boucle d'événements, ou sur d'autres descripteurs de fichiers ajoutés à la boucle. Le paramètre usec spécifie la durée maximale d'attente en microsecondes. Si usec est 0, la fonction attendra indéfiniment. Si usec est (uint64_t)-1, elle ne bloquera pas du tout.

sd_event_dispatch est appelée après que sd_event_wait ait retourné, indiquant qu'un ou plusieurs événements sont prêts. Elle déclenche les méthodes dispatch de toutes les sources d'événements qui sont prêtes.

sd_event_get_state renvoie l'état actuel de la boucle d'événements. Les états possibles sont :

SD_EVENT_INITIAL
L'état initial avant le démarrage de la boucle.
SD_EVENT_PREPARE
L'état pendant l'appel à sd_event_prepare.
SD_EVENT_WAIT
L'état pendant l'appel à sd_event_wait.
SD_EVENT_DISPATCH
L'état pendant l'appel à sd_event_dispatch.

sd_event_get_iteration renvoie le nombre d'itérations de la boucle d'événements effectuées depuis sa création.

STATE MACHINE

Les fonctions sd_event_prepare, sd_event_wait, et sd_event_dispatch doivent être appelées dans cet ordre, et répétées tant que la boucle d'événements n'est pas terminée. L'appel sd_event_run fait cela.

RETURN VALUE

Ces fonctions renvoient 0 en cas de succès, ou un code d'erreur négatif en cas d'échec.

Les codes d'erreur possibles sont :

ECHILD
La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

D'autres erreurs sont également possibles.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a encore été démarré.

HISTORY

sd_event_prepare(), sd_event_wait(), sd_event_dispatch(), et sd_event_get_state() ont été ajoutées dans la version 221.

sd_event_get_iteration() a été ajoutée dans la version 231.
