sd_bus_message_append(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_APPEND(3) sd_bus_message_append SD_BUS_MESSAGE_APPEND(3)

NOM

sd_bus_message_append, sd_bus_message_appendv - Joindre des champs à un message D-Bus basé sur une chaîne de types

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append(sd_bus_message *m, const char *types, ...);

int sd_bus_message_appendv(sd_bus_message *m, const char *types, va_list ap);

DESCRIPTION

La fonction sd_bus_message_append() joint une séquence de champs à l'objet message D-Bus m. La chaîne de types types décrit les types des arguments de champ qui suivent. Pour chaque type spécifié dans la chaîne de types, un ou plusieurs arguments doivent être spécifiés, dans le même ordre que celui déclaré dans la chaîne de types.

La chaîne de types est composée des éléments présentés dans le tableau ci-dessous. Elle contient zéro ou plusieurs "types complets". Chaque type complet peut être l'un des types de base ou un type conteneur entièrement décrit. Un type conteneur peut être une structure avec les types contenus, un variant, un tableau avec son type d'élément, ou une entrée de dictionnaire avec les types contenus. La chaîne de types est terminée par un caractère NUL.

Dans le cas d'un type de base, un argument du type correspondant est attendu.

Une structure est dénotée par une séquence de types complets entre "(" et ")". Cette séquence ne peut pas être vide — elle doit contenir au moins un type. Les arguments correspondant à cette séquence imbriquée suivent les mêmes règles que s'ils n'étaient pas imbriqués.

Un variant est dénoté par "v". Les arguments correspondants doivent commencer par une chaîne de types dénotant un type complet, et ensuite, les arguments correspondant au type spécifié.

Un tableau est dénoté par "a" suivi d'un type complet. Les arguments correspondants doivent commencer par le nombre d'entrées dans le tableau, suivi des entrées elles-mêmes, correspondant au type d'élément du tableau.

Un dictionnaire est un tableau d'entrées de dictionnaire, dénoté par "a" suivi d'une paire de types complets entre "{" et "}". Le premier de ces types doit être un type de base. Les arguments correspondants doivent commencer par le nombre d'entrées du dictionnaire, suivi d'une paire de valeurs pour chaque entrée correspondant au type d'élément des entrées du dictionnaire.

sd_bus_message_appendv() est équivalent à sd_bus_message_append(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments. Cette fonction n'appelle pas la macro va_end(). Étant donné qu'elle invoque la macro va_arg(), la valeur de ap est indéfinie après l'appel.

Pour plus de détails sur le système de types D-Bus, veuillez consulter la Spécification D-Bus[1].

"s" SD_BUS_TYPE_STRING chaîne Unicode variable char[]
"o" SD_BUS_TYPE_OBJECT_PATH chemin d'objet variable char[]
"g" SD_BUS_TYPE_SIGNATURE signature variable char[]
"h" SD_BUS_TYPE_UNIX_FD descripteur de fichier UNIX 4 octets int
"a" SD_BUS_TYPE_ARRAY tableau déterminé par le type de tableau et la taille int, suivi du contenu du tableau
"v" SD_BUS_TYPE_VARIANT variant déterminé par l'argument de type chaîne de signature, suivie du contenu du variant
"(" SD_BUS_TYPE_STRUCT_BEGIN début de tableau déterminé par les types imbriqués contenu de la structure
")" SD_BUS_TYPE_STRUCT_END fin de tableau
"{" SD_BUS_TYPE_DICT_ENTRY_BEGIN début d'entrée de dictionnaire déterminé par les types imbriqués contenu du dictionnaire
"}" SD_BUS_TYPE_DICT_ENTRY_END fin d'entrée de dictionnaire

Pour les types
"s" et "g" (chaîne Unicode ou signature), le pointeur peut être NULL, ce qui est équivalent à une chaîne vide. Pour "h" (descripteur de fichier UNIX), le descripteur est dupliqué par cet appel et le descripteur passé reste en possession de l'appelant. Voir sd_bus_message_append_basic(3) pour l'interprétation précise de ces types et d'autres.

GRAMMAIRE DE LA CHAÎNE DE TYPES

types ::= complete_type*
complete_type ::= basic_type | variant | structure | array | dictionary
basic_type ::= "y" | "n" | "q" | "u" | "i" | "x" | "t" | "d" |
               "b" | "h" |
               "s" | "o" | "g"
variant ::= "v"
structure ::= "(" complete_type+ ")"
array ::= "a" complete_type
dictionary ::= "a" "{" basic_type complete_type "}"

EXEMPLES

Joindre un seul type de base (la chaîne "a string") :

sd_bus_message *m;
...
sd_bus_message_append(m, "s", "a string");

Joindre tous les types d'entiers :

uint8_t y = 1;
int16_t n = 2;
uint16_t q = 3;
int32_t i = 4;
uint32_t u = 5;
int32_t x = 6;
uint32_t t = 7;
double d = 8.0;
sd_bus_message_append(m, "ynqiuxtd", y, n, q, i, u, x, t, d);

Joindre une structure composée d'une chaîne et d'un chemin D-Bus :

sd_bus_message_append(m, "(so)", "a string", "/a/path");

Joindre un tableau de descripteurs de fichiers UNIX :

sd_bus_message_append(m, "ah", 3, STDIN_FILENO, STDOUT_FILENO, STDERR_FILENO);

Joindre un variant, avec le type réel "g" (signature), et la valeur "sdbusisgood" :

sd_bus_message_append(m, "v", "g", "sdbusisgood");

Joindre un dictionnaire contenant le mappage {1=>"a", 2=>"b", 3=>""} :

sd_bus_message_append(m, "a{is}", 3, 1, "a", 2, "b", 3, NULL);

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

ERREURS

Des erreurs peuvent survenir lors de l'ajout d'un champ de base, mais elles sont plus probables lors de l'ajout de conteneurs. Voici quelques-unes des erreurs les plus courantes, ainsi que leurs causes possibles :

-EINVAL
Un type inconnu est spécifié, ou le type est incomplet (par exemple, un tableau sans type d'élément).
-EPROTO
La chaîne de types spécifie un type qui ne peut pas être représenté dans le courant D-Bus, ou les arguments fournis ne correspondent pas au type spécifié.
-ENOMEM
Mémoire insuffisante pour joindre le champ.
-ECHILD
Le descripteur de fichier passé à sd_bus_message_append() est invalide.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
