sd_event_add_signal(3)

Paquet: systemd-libs

SD_EVENT_ADD_SIGNAL(3) sd_event_add_signal SD_EVENT_ADD_SIGNAL(3)

NOM

sd_event_add_signal, sd_event_source_get_signal, sd_event_signal_handler_t, SD_EVENT_SIGNAL_PROCMASK - Ajouter une source d'événement de signal de processus UNIX à une boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;
SD_EVENT_SIGNAL_PROCMASK

typedef int (*sd_event_signal_handler_t)(sd_event_source *s, const struct signalfd_siginfo *si, void *userdata);

int sd_event_add_signal(sd_event *event, sd_event_source **source, int signal, sd_event_signal_handler_t handler, void *userdata);

int sd_event_source_get_signal(sd_event_source *source);

DESCRIPTION

sd_event_add_signal() ajoute une nouvelle source d'événement de signal de processus UNIX à une boucle d'événements. L'objet de la boucle d'événements est spécifié par le paramètre event, et l'objet de la source d'événement est retourné par le paramètre source. Le paramètre signal spécifie le signal numérique à gérer (voir signal(7)).

Le paramètre handler est une fonction à appeler lorsque le signal est reçu, ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure signalfd_siginfo contenant des informations sur le signal reçu. Voir signalfd(2) pour plus d'informations. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul gestionnaire peut être installé pour un signal spécifique. Le signal doit être bloqué dans tous les threads avant que cette fonction ne soit appelée (en utilisant sigprocmask(2) ou pthread_sigmask(3)). Par souci de commodité, si le drapeau spécial SD_EVENT_SIGNAL_PROCMASK est OR-é dans le signal spécifié, le signal sera automatiquement masqué selon les besoins pour le thread appelant. Notez que cela ne fonctionne de manière fiable que si le signal est déjà masqué dans tous les autres threads du processus, ou s'il n'y a pas d'autres threads au moment de l'invocation.

Par défaut, la source d'événement est activée en permanence (SD_EVENT_ON), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire renvoie un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, soit elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet de source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si elle est toujours référencée, désactivez la source d'événement en utilisant sd_event_source_set_enabled(3) avec SD_EVENT_OFF.

Si le deuxième paramètre de sd_event_add_signal() est NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_signal() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

sd_event_source_get_signal() retourne le numéro de signal configuré d'une source d'événement précédemment créée avec sd_event_add_signal(). Il prend l'objet source d'événement comme paramètre source.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-EBUSY

Un gestionnaire est déjà installé pour ce signal ou le signal n'était pas bloqué auparavant.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

-EDOM

La source d'événement passée n'est pas une source d'événement de signal.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que dès les premières phases du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_add_signal(), sd_event_signal_handler_t(), et sd_event_source_get_signal() ont été ajoutés dans la version 217.
