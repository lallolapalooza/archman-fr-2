SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

NOM

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Lire une séquence de valeurs d'un message

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

DESCRIPTION

sd_bus_message_read() lit une séquence de champs de l'objet message D-Bus m et avance la position de lecture dans le message. La chaîne de types types décrit les types des éléments attendus dans le message et les arguments de champ qui suivent. La chaîne de types peut être NULL ou vide, auquel cas rien n'est lu.

La chaîne de types est composée des éléments décrits dans sd_bus_message_append(3), c'est-à-dire les types de base et de conteneur. Elle doit contenir zéro ou plusieurs "types complets" uniques. La chaîne de types est terminée par un caractère NUL.

Pour chaque type spécifié dans la chaîne de types, un ou plusieurs arguments doivent être spécifiés après le paramètre types, dans le même ordre. Les arguments doivent être des pointeurs vers des types appropriés (un pointeur vers int8_t pour un "y" dans la chaîne de types, un pointeur vers int32_t pour un "i", un pointeur vers const char* pour un "s", ...) qui sont définis en fonction des valeurs dans le message. À titre d'exception, dans le cas des types tableau et variant, le premier argument est un argument "d'entrée" qui spécifie davantage comment le message doit être lu. Voir le tableau ci-dessous pour une liste complète des arguments autorisés et de leurs types. Notez que, si le type de base est un pointeur (par exemple, const char * dans le cas d'une chaîne), l'argument est un pointeur vers un pointeur, et la valeur du pointeur écrite n'est qu'empruntée, le contenu devant être copié s'il doit être utilisé après la fin de la durée de vie du message. Si le type est "h" (descripteur de fichier UNIX), le descripteur n'est pas dupliqué par cet appel et le descripteur retourné reste la possession de l'objet message, et doit être dupliqué par l'appelant afin de conserver une référence ouverte à celui-ci après la libération de l'objet message.

Chaque argument peut également être NULL, auquel cas la valeur est lue et ignorée.

Si des objets des types spécifiés ne sont pas présents à la position actuelle dans le message, une erreur est retournée.

sd_bus_message_readv() est équivalent à sd_bus_message_read(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments. Cette fonction n'appelle pas la macro va_end(). Parce qu'elle invoque la macro va_arg(), la valeur de ap est indéfinie après l'appel.

sd_bus_message_peek_type() détermine le type du prochain élément dans m à lire par sd_bus_message_read() ou des fonctions similaires. En cas de succès, le type est stocké dans type, s'il n'est pas NULL. Si le type est un type conteneur, le type de ses éléments est stocké dans contents, s'il n'est pas NULL. Si cette fonction détermine avec succès le type du prochain élément dans m, elle retourne un entier positif. S'il n'y a plus d'éléments à lire, elle retourne zéro.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

La chaîne de types spécifiée est invalide ou le paramètre message est NULL.

-ENXIO

Le message ne contient pas le type spécifié à la position actuelle.

-EBADMSG

Le message ne peut pas être analysé.

-EBUSY

Lors de la lecture à partir d'un conteneur, cette erreur sera retournée s'il reste des éléments non lus dans le conteneur.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multithread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

sd_bus_message_peek_type(3) — systemd — Arch Linux

NOM

sd_bus_message_peek_type, sd_bus_message_read, sd_bus_message_readv - Lire des données d'un message D-Bus

SYNTAXIS

#include <systemd/sd-bus.h>
int sd_bus_message_peek_type(sd_bus_message *m, char *type, uint8_t *container_kind);
int sd_bus_message_read(sd_bus_message *m, const char *signature, ...);
int sd_bus_message_readv(sd_bus_message *m, const char *signature, va_list ap);

DESCRIPTION

sd_bus_message_read() consomme des données du message de bus D-Bus m en fonction de la signature donnée et place les données lues dans les arguments variables passés. La signature est une chaîne de caractères décrivant les types de données à lire, en utilisant la notation de signature D-Bus. Voir sd-bus(3) pour une liste des types de base et des spécificateurs de conteneurs.

sd_bus_message_readv() est fonctionnellement identique à sd_bus_message_read(), mais prend une liste d'arguments de variable ap au lieu des arguments individuels.

Le premier appel à sd_bus_message_read() ou sd_bus_message_readv() sur un message commencera la lecture depuis le début du corps du message. Les appels ultérieurs liront à partir de l'endroit où la lecture précédente s'est terminée.

Pour lire des conteneurs (tableaux et dictionnaires), vous devez utiliser sd_bus_message_enter_container(), sd_bus_message_exit_container(), et sd_bus_message_close_container(). Si vous lisez un tableau ou un dictionnaire avec une signature, vous devez également passer le nombre d'éléments expected comme argument, juste avant le premier pointeur pour ce tableau ou ce dictionnaire.

sd_bus_message_peek_type() jette un coup d'œil au type de l'élément suivant dans le message sans le consommer. Si type n'est pas NULL, le type de l'élément est écrit dans *type. Si l'élément est un conteneur (tableau ou dictionnaire), *container_kind sera défini comme le caractère indiquant le type de conteneur ('a' pour tableau, 'e' pour dicté). Sinon, *container_kind sera défini à 0. Retourne -E2BIG si aucun type ne peut être trouvé.

Les types de données primitifs lus avec sd_bus_message_read() sont les suivants :

'y'
Un entier non signé de 8 bits.
'b'
Un entier booléen. Il est lu comme un entier non signé de 32 bits, mais uniquement les valeurs 0 et 1 sont valides. Notez que l'utilisation du type C99 `bool` est fortement déconseillée, car sa taille mémoire est indéfinie et peut entraîner une corruption de mémoire.
'n'
Un entier signé de 16 bits.
'q'
Un entier non signé de 16 bits.
'i'
Un entier signé de 32 bits.
'u'
Un entier non signé de 32 bits.
'x'
Un entier signé de 64 bits.
't'
Un entier non signé de 64 bits.
'd'
Un flottant à virgule flottante de double précision.
's'
Une chaîne de caractères UTF-8.
'o'
Un chemin d'objet D-Bus.
'g'
Une signature D-Bus.
'h'
Un descripteur de fichier. La valeur lue est un entier 32 bits représentant le descripteur de fichier. Il est utilisé pour les descripteurs de fichier envoyés via le protocole D-Bus. Le descripteur de fichier lu n'est pas dupliqué ; si vous souhaitez le conserver après la libération du message, vous devez le dupliquer vous-même en utilisant fcntl(2) et FD_DUPFD_CLOEXEC.
'v'
Une variante. Il est lu comme une paire de chaîne de caractères et d'une valeur. La chaîne de caractères contient la signature D-Bus du type de données contenu dans la variante, et la valeur est lue en fonction de cette signature. Vous devrez passer un pointeur vers la chaîne de caractères de signature et un pointeur vers la variable dans laquelle la valeur doit être lue.

Les conteneurs sont décrits par les caractères suivants précédés de 'a' (pour les tableaux) ou de 'e' (pour les dictionnaires, qui sont des tableaux de paires clé-valeur) :

'a{T>T}'
Un dictionnaire dont les clés et les valeurs sont décrites par la signature dans les accolades.
'aT'
Un tableau dont les éléments sont décrits par T.

Pour lire les conteneurs, vous devez passer le nombre d'éléments attendus comme argument avant le premier pointeur pour ce conteneur. Par exemple, pour lire un tableau de trois entiers de 32 bits, vous utiliseriez la signature 'ai' et passeriez 3 comme argument juste avant le pointeur vers la variable où le premier entier doit être lu.

Si la lecture échoue pour une raison quelconque (par exemple, le type de données ne correspond pas, la fin du message est atteinte prématurément), la fonction retourne un code d'erreur négatif. Si des données ont été lues avant l'échec, elles restent dans les variables fournies. Si la lecture réussit complètement, zéro est retourné.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'échec, un code d'erreur négatif est retourné. Les codes d'erreur possibles sont :

-EINVAL
Le signature est invalide, ou un argument de pointeur est NULL.
-E2BIG
Fin du message atteinte prématurément.
-EBUSY
Tentative de lecture d'un champ déjà lu.
-EPROTO
Le type de données lu ne correspond pas au type attendu dans la signature.

NOTES

L'utilisation de sd_bus_message_read() est généralement plus simple pour les cas simples, tandis que sd_bus_message_readv() est utile lorsque la signature ou le nombre d'arguments est déterminé dynamiquement.

Notez qu'après la lecture d'un descripteur de fichier ('h'), vous êtes responsable de sa fermeture. Si vous souhaitez conserver le descripteur de fichier ouvert après la libération du message, vous devez le dupliquer à l'aide de fcntl() et FD_DUPFD_CLOEXEC.

Pour les conteneurs, il est souvent plus simple d'utiliser sd_bus_message_enter_container() pour obtenir un itérateur sur le conteneur, puis d'utiliser sd_bus_message_read() sur cet itérateur.

EXEMPLES

Lire un entier de base unique (un entier de 64 bits) :

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Lire une valeur booléenne :

sd_bus_message *m;
int x; /* N'utilisez pas le type C99 "bool" ici, il est généralement plus petit
          en mémoire et pourrait causer une corruption mémoire */
sd_bus_message_read(m, "b", &x);

Lire tous les types d'entiers :

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Lire une structure composée d'une chaîne de caractères et d'un chemin D-Bus :

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Lire une variante, avec le type réel "gt" (signature, entier non signé) :

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Lire un dictionnaire contenant trois paires de type {entier=>chaîne} :

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Lire un descripteur de fichier unique, et le dupliquer afin de le conserver ouvert après la libération du message.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);
