NOM

sd_bus_set_close_on_exit, sd_bus_get_close_on_exit - Contrôler la fermeture de la connexion bus pendant la phase de sortie de la boucle d'événements

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_close_on_exit(sd_bus *bus, int b);

int sd_bus_get_close_on_exit(sd_bus *bus);

DESCRIPTION

sd_bus_set_close_on_exit() peut être utilisée pour activer ou désactiver la fermeture automatique (comme dans sd_bus_close(3)) et la vidange (comme dans sd_bus_flush(3)) de la connexion bus pendant la phase de sortie de la boucle d'événements. Cette logique ne s'applique qu'aux connexions bus attachées à une boucle d'événements sd-event(3), voir sd_bus_attach_event(3). Par défaut, ce mécanisme est activé et garantit que tous les messages en attente qui n'ont pas été écrits dans la connexion bus sont vidés lorsque la boucle d'événements s'arrête. Dans certains cas, ce comportement n'est pas souhaitable, par exemple lorsque la connexion bus doit rester utilisable après la sortie de la boucle d'événements. Si b est vrai, la fonctionnalité est activée (ce qui est le défaut), sinon elle est désactivée.

sd_bus_get_close_on_exit() peut être utilisée pour interroger le paramètre actuel de cette fonctionnalité. Elle renvoie zéro lorsque la fonctionnalité est désactivée, et un nombre positif si elle est activée.

VALEUR DE RETOUR

En cas de succès, sd_bus_set_close_on_exit() renvoie un entier non négatif. En cas d'échec, elle renvoie un code d'erreur négatif de type errno.

sd_bus_get_close_on_exit() renvoie 0 si la fonctionnalité est actuellement désactivée ou un entier positif si elle est activée. En cas d'échec, elle renvoie un code d'erreur négatif de type errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ECHILD

La connexion bus a été créée dans un processus, une bibliothèque ou une instance de module différent.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que dès le début du programme, lorsqu'aucun autre thread n'a encore été démarré.

HISTORIQUE

sd_bus_set_close_on_exit() et sd_bus_get_close_on_exit() ont été ajoutées dans la version 240.
