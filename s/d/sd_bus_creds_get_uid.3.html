DESCRIPTION

Ces fonctions retournent des informations d'identifiants à partir d'un objet sd_bus_creds. Les objets d'identifiants peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les identifiants du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les identifiants d'un pair du bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les identifiants du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les identifiants de l'expéditeur du message.

Tous les champs d'identifiants ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour plus de détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant d'utilisateur). De même, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GID supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin de l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (supprimé)" retiré). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée pour des informations à des fins de sécurité, car l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur est traitée. De plus, le noyau expose ces informations de manière ambiguë (c'est-à-dire qu'un exécutable supprimé ne peut pas être distingué en toute sécurité d'un exécutable dont le nom pourrait être identique).

sd_bus_creds_get_cmdline() récupère la ligne de commande complète du processus.

sd_bus_creds_get_cgroup() récupère le chemin du cgroup du processus.

sd_bus_creds_get_unit() récupère le nom de l'unité systemd associée au processus.

sd_bus_creds_get_slice() récupère le nom de la tranche systemd associée au processus.

sd_bus_creds_get_user_unit() récupère le nom de l'unité systemd de l'utilisateur associée au processus.

sd_bus_creds_get_user_slice() récupère le nom de la tranche systemd de l'utilisateur associée au processus.

sd_bus_creds_get_session() récupère le nom de la session associée au processus.

sd_bus_creds_get_owner_uid() récupère l'UID du propriétaire du bus.

sd_bus_creds_has_effective_cap(), sd_bus_creds_has_permitted_cap(), sd_bus_creds_has_inheritable_cap() et sd_bus_creds_has_bounding_cap() vérifient si le processus possède une capacité spécifique dans les ensembles effectif, autorisé, héritable ou limite, respectivement. La capacité doit être l'une des constantes CAP_ du header POSIX. Elle retourne 1 si la capacité est présente, 0 sinon.

sd_bus_creds_get_selinux_context() récupère le contexte SELinux du processus.

sd_bus_creds_get_audit_session_id() récupère l'identifiant de session d'audit du processus.

sd_bus_creds_get_audit_login_uid() récupère l'UID de connexion d'audit du processus.

sd_bus_creds_get_tty() récupère le nom du terminal associé au processus.

sd_bus_creds_get_unique_name() récupère le nom unique du bus du processus.

sd_bus_creds_get_well_known_names() récupère une liste des noms bien connus du bus du processus.

sd_bus_creds_get_description() récupère une chaîne décrivant le processus.

Les fonctions de type get_...() retournent une chaîne ou une valeur numérique dans le pointeur passé en argument, ou une valeur négative en cas d'erreur. Les fonctions de type has_..._cap() retournent 1 si la capacité est présente, 0 si elle ne l'est pas, ou une valeur négative en cas d'erreur.

Les chaînes retournées par les fonctions get_* ne sont pas allouées et doivent être considérées comme valides uniquement tant que l'objet sd_bus_creds existe. Les tableaux retournés par get_cmdline() et get_well_known_names() doivent être libérés avec free(3).

Si le champ demandé n'est pas disponible dans l'objet sd_bus_creds, -ENODATA est retourné.

Les erreurs possibles sont : -ENOMEM, -ENOENT, -ESRCH, -EACCES, -ENODATA, -EINVAL.

Notez que sd_bus_creds_get_exe(3) peut retourner -EACCES si le chemin de l'exécutable n'est pas lisible, ou -ENOMEM si la chaîne de chemin est trop longue.

sd_bus_creds_get_cmdline() récupérera un tableau d’arguments de ligne de commande (tel qu'il est stocké dans /proc/pid/cmdline). Notez que les threads du noyau n’ont pas de ligne de commande, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_cgroup() récupérera le chemin du groupe de contrôle. Voir Groupes de contrôle v2[1].

sd_bus_creds_get_unit() récupérera le nom de l’unité systemd (dans l’instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d’une unité, renvoie -ENXIO.

sd_bus_creds_get_user_unit() récupérera le nom de l’unité systemd (dans l’instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d’une unité utilisateur, renvoie -ENXIO.

sd_bus_creds_get_slice() récupérera la tranche systemd (une unité dans l’instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère la tranche systemd du processus, dans l’instance utilisateur de systemd.

sd_bus_creds_get_session() récupérera l’identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateurs peuvent plutôt être démarrés à partir de leur gestionnaire d’utilisateur systemd, par exemple, les applications graphiques démarrées à l’aide de l’activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d’une session, renvoie -ENXIO.

sd_bus_creds_get_owner_uid() récupérera l’UID numérique (identifiant utilisateur) de l’utilisateur qui possède l’unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d’une unité utilisateur ou d’une session, renvoie -ENXIO.

sd_bus_creds_has_effective_cap() vérifiera si la capacité spécifiée par capability a été définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu’elle était définie, zéro signifie qu’elle n’était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités autorisées.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités de délimitation.

sd_bus_creds_get_selinux_context() récupérera le contexte de sécurité SELinux (label) du processus.

sd_bus_creds_get_audit_session_id() récupérera l’identifiant de session d’audit du processus. Renvoie -ENXIO pour les processus qui ne font pas partie d’une session d’audit.

sd_bus_creds_get_audit_login_uid() récupérera l’identifiant de connexion utilisateur d’audit (l’identifiant de l’utilisateur qui est « responsable » de la session). Renvoie -ENXIO pour les processus qui ne font pas partie d’une session d’audit.

sd_bus_creds_get_tty() récupérera le TTY de contrôle, sans le préfixe « /dev/ ». Renvoie -ENXIO pour les processus qui n’ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupérera le nom unique D-Bus. Voir La spécification D-Bus[2].

sd_bus_creds_get_well_known_names() récupérera l’ensemble des noms bien connus D-Bus. Voir La spécification D-Bus[2].

sd_bus_creds_get_description() récupérera un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus du même pair, et peut être modifié par le pair avec l’appel sd_bus_set_description(3).

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse là sous forme d’adresse d’une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l’appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse là sous forme d’adresse d’un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l’appelant.

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d’échec, ces appels renvoient un code d’erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n’est pas disponible dans l’objet d’identification c.

-ENXIO

Le champ donné n’est pas spécifié pour le processus ou le pair décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d’une unité système systemd, d’une unité utilisateur systemd, d’une tranche systemd, ou d’une session logind. Il sera renvoyé par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d’une unité utilisateur systemd ou d’une session logind. Il sera également renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (puisque ceux-ci ne sont pas démarrés à partir d’un binaire exécutable, ni n’ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d’une session d’audit, et sd_bus_creds_get_tty() si le processus n’a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l’allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n’étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d’un thread parallèle. Il est recommandé de ne faire des appels à setenv() que depuis une phase précoce du programme lorsque aucun autre thread n’a été démarré.

    #include <systemd/sd-bus.h>

int sd_bus_creds_get_uid(sd_bus_creds *creds, uid_t *uid);
int sd_bus_creds_get_gid(sd_bus_creds *creds, gid_t *gid);

int sd_bus_creds_get_sgid(sd_bus_creds *creds, gid_t *gid);

int sd_bus_creds_get_fd(sd_bus_creds *creds, int *fd);

    DESCRIPTION

    Ces fonctions extraient des informations spécifiques des informations d'identification d'un processus qui a été obtenues via sd_bus_get_creds(3) ou similaires. Les arguments sont les suivants :

    • creds : Le descripteur des informations d'identification obtenues.
    • uid : Un pointeur vers une variable de type uid_t dans laquelle l'UID sera stocké.
    • gid : Un pointeur vers une variable de type gid_t dans laquelle le GID sera stocké.
    • pid : Un pointeur vers une variable de type pid_t dans laquelle le PID sera stocké.
    • name : Un pointeur vers une variable de type const char * dans laquelle le nom sera stocké. Le pointeur retourné est valide tant que creds est valide et ne doit pas être libéré par l'appelant.
    • id : Un pointeur vers une variable de type const char * dans laquelle l'ID de session sera stocké. Le pointeur retourné est valide tant que creds est valide et ne doit pas être libéré par l'appelant.
    • fd : Un pointeur vers une variable de type int dans laquelle le descripteur de fichier sera stocké. Le descripteur de fichier retourné appartient à l'appelant et doit être fermé explicitement par l'appelant à l'aide de close().

    Les fonctions suivantes sont disponibles :

    • sd_bus_creds_get_uid() : Obtient l'ID utilisateur effectif (effective user ID).
    • sd_bus_creds_get_gid() : Obtient l'ID groupe effectif (effective group ID).
    • sd_bus_creds_get_euid() : Obtient l'ID utilisateur effectif (effective user ID). C'est un synonyme de sd_bus_creds_get_uid().
    • sd_bus_creds_get_egid() : Obtient l'ID groupe effectif (effective group ID). C'est un synonyme de sd_bus_creds_get_gid().
    • sd_bus_creds_get_suid() : Obtient l'ID utilisateur sauvegardé (saved set-user-ID).
    • sd_bus_creds_get_sgid() : Obtient l'ID groupe sauvegardé (saved set-group-ID).
    • sd_bus_creds_get_pid() : Obtient l'ID du processus.
    • sd_bus_creds_get_user_name() : Obtient le nom d'utilisateur correspondant à l'UID effectif.
    • sd_bus_creds_get_process_name() : Obtient le nom du processus.
    • sd_bus_creds_get_session_id() : Obtient l'ID de la session utilisateur associée au processus.
    • sd_bus_creds_get_fd() : Obtient le descripteur de fichier associé à la communication sur le bus.

    VALEUR DE RETOUR

    En cas de succès, ces fonctions retournent 0. En cas d'échec, elles retournent un code d'erreur négatif.

    ERREURS

    Les erreurs possibles retournées par les fonctions sont les suivantes :

    • -EINVAL : Le paramètre creds est NULL ou une valeur demandée n'est pas disponible dans les informations d'identification.
    • -ENOMEM : Pas assez de mémoire pour allouer des ressources internes.

    Les erreurs spécifiques aux appels système sous-jacents peuvent également être retournées.

    CONCURRENCE

    Les fonctions sd_bus_creds_get_* sont sûres pour une utilisation par plusieurs threads. L'objet sd_bus_creds lui-même n'a pas besoin d'être protégé par un mutex lors de l'appel de ces fonctions.

    VOIR AUSSI

    sd_bus_get_creds(3), sd_bus_creds_unref(3), close(2)

    HISTORIQUE

    sd_bus_creds_get_* ont été introduits dans systemd version 232.

    NOTES

    Les informations d'identification obtenues via sd_bus_get_creds() sont généralement limitées. Par exemple, l'UID effectif est souvent root (0) pour les démons, et l'ID de session peut ne pas être disponible.

    Le descripteur de fichier retourné par sd_bus_creds_get_fd() est destiné à des fins de débogage ou d'audit et ne doit pas être utilisé pour communiquer sur le bus.
