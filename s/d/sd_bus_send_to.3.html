sd_bus_send_to(3)

SD_BUS_SEND(3) sd_bus_send SD_BUS_SEND(3)

NOM

sd_bus_send, sd_bus_send_to, sd_bus_message_send - Mettre en file d'attente un message D-Bus pour transfert

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_send(sd_bus *bus, sd_bus_message *m, uint64_t *cookie);

int sd_bus_send_to(sd_bus *bus, sd_bus_message *m, const char *destination, uint64_t *cookie);

int sd_bus_message_send(sd_bus_message *m);

DESCRIPTION

sd_bus_send() met en file d'attente l'objet message de bus m pour transfert. Si bus est NULL, le bus auquel m est attaché est utilisé. bus n'a besoin d'être défini que lorsque le message est envoyé à un bus différent de celui auquel il est attaché, par exemple lors du transfert de messages. Si le paramètre de sortie cookie n'est pas NULL, il est défini sur l'identifiant du message. Cette valeur peut être utilisée ultérieurement pour faire correspondre les réponses entrantes à leurs messages correspondants. Si cookie est défini sur NULL et que le message n'est pas scellé, sd_bus_send() suppose que le message m n'attend pas de réponse et ajoute les en-têtes nécessaires pour l'indiquer.

Notez que dans la plupart des scénarios, sd_bus_send() ne doit pas être appelé directement. Utilisez plutôt des fonctions de plus haut niveau telles que sd_bus_call_method(3) et sd_bus_reply_method_return(3) qui appellent sd_bus_send() en interne.

sd_bus_send_to() est un raccourci pour envoyer un message à une destination spécifique. Son cas d'utilisation principal est de simplifier l'envoi de messages de signal unicast (signaux qui n'ont qu'un seul destinataire). Son comportement est similaire à l'appel de sd_bus_message_set_destination(3) suivi de l'appel de sd_bus_send().

sd_bus_send()/sd_bus_send_to() écrira le message directement dans le transport sous-jacent (par exemple, le tampon de socket du noyau) si possible. Si la connexion n'est pas encore entièrement configurée, le message est mis en file d'attente localement. Si les tampons de transport sont congestionnés, toute donnée de message non écrite est également mise en file d'attente localement. Si la connexion a été fermée ou est en cours de fermeture, l'appel échoue. sd_bus_process(3) doit être invoqué pour écrire les données de message mises en file d'attente dans le transport.

sd_bus_message_send() est identique à sd_bus_send() mais sans le premier et le dernier argument. sd_bus_message_send(m) est équivalent à sd_bus_send(sd_bus_message_get_bus(m), m, NULL).

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre d'entrée m est NULL.

Ajouté dans la version 246.

-EOPNOTSUPP

La connexion de bus ne prend pas en charge l'envoi de descripteurs de fichiers.

Ajouté dans la version 246.

-ECHILD

La connexion de bus a été allouée dans un processus parent et est réutilisée dans un processus enfant après fork().

Ajouté dans la version 246.

-ENOBUFS

La file d'attente d'écriture de la connexion de bus est pleine.

Ajouté dans la version 246.

-ENOTCONN

Le paramètre d'entrée bus est NULL ou le bus n'est pas connecté.

Ajouté dans la version 246.

-ECONNRESET

La connexion de bus a été fermée pendant l'attente de la réponse.

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation mémoire.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les appels multithread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_send() et sd_bus_send_to() ont été ajoutés dans la version 246.
