DESCRIPTION

sd-id128.h fait partie de libsystemd(3) et fournit des API pour générer, convertir et comparer des valeurs d'ID de 128 bits. Les valeurs d'ID de 128 bits traitées et générées par ces API sont une généralisation des UUID OSF tels que définis par la RFC 4122[1], mais utilisent un format de chaîne plus simple. Ces fonctions n'imposent aucune structure aux ID utilisés, contrairement aux UUID OSF ou aux GUID Microsoft, mais sont largement compatibles avec ces types d'ID.

Un ID de 128 bits est implémenté comme le type union suivant :

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Cette union permet d'accéder à l'ID de 128 bits comme à 16 octets séparés ou deux mots de 64 bits. Il est généralement plus sûr d'accéder aux composants de l'ID par leur tableau de 8 bits pour éviter les problèmes d'endianness. Cette union est destinée à être passée par valeur (par opposition à pass-by-reference) et peut être directement manipulée par les clients.

Quelques macros sont définies pour représenter et décoder les ID de 128 bits :

SD_ID128_MAKE() est utilisée pour écrire un ID constant dans le code source. Une idiome couramment utilisée est d'assigner un nom à un ID en utilisant cette macro :

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL définit un ID composé uniquement d'octets NUL (c'est-à-dire tous les bits à zéro).

SD_ID128_ALLF définit un ID composé uniquement d'octets 0xFF (c'est-à-dire tous les bits à un).

SD_ID128_MAKE_STR() est similaire à SD_ID128_MAKE(), mais crée une expression const char* qui peut être utilisée commodément dans les formats de messages et autres :

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convertit les ID constants en chaînes constantes pour la sortie. Le code d'exemple suivant affichera la chaîne "fc2e22bc6ee647b6b90729ab34a250b1" :

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR et SD_ID128_FORMAT_VAL() sont utilisés pour formater un ID dans une chaîne de format printf(3), comme montré dans l'exemple suivant :

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("L'ID encodé dans ce fichier C est " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR et SD_ID128_MAKE_UUID_STR() sont similaires à SD_ID128_FORMAT_STR et SD_ID128_MAKE_STR(), mais incluent des tirets de séparation pour se conformer à la "représentation canonique des UUID[2]". Ils forment la chaîne basée sur les règles de la variante 1 de la RFC4122[1], c'est-à-dire la conversion de l'ordre des octets Big Endian. Cela correspond au comportement de la plupart des autres infrastructures de l'espace utilisateur Linux. Il est probablement préférable d'éviter les UUID d'autres variantes, afin d'éviter des ambiguïtés inutiles. Tous les ID de 128 bits générés par les API sd-id128 sont strictement conformes aux UUID de variante 1, version 4, selon la RFC 4122.

sd_id128_equal() compare deux ID de 128 bits :

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() est similaire à sd_id128_equal(), mais le premier ID est formaté en const char*. Les mêmes restrictions s'appliquent qu'au premier argument de sd_id128_from_string().

sd_id128_is_null() vérifie si un ID est composé uniquement d'octets NUL :

assert(sd_id128_is_null(SD_ID128_NULL));

De même, sd_id128_is_allf() vérifie si un ID est composé uniquement d'octets 0xFF (tous les bits à un) :

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() prend une liste d'ID et retourne vrai si le premier argument est égal à l'un des arguments suivants. La liste d'arguments est terminée par un sentinelle SD_ID128_NULL, qui doit être présent.

sd_id128_in_set() est une fonction de commodité qui prend une liste d'ID et retourne vrai si le premier argument est égal à l'un des arguments suivants :

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() est définie comme une macro sur sd_id128_in_set_sentinel(), ajoutant le sentinelle SD_ID128_NULL automatiquement. Puisque sd_id128_in_set_sentinel() utilise SD_ID128_NULL comme sentinelle, SD_ID128_NULL ne peut pas être placé autrement dans la liste d'arguments.

sd_id128_in_setv() est similaire à sd_id128_in_set_sentinel(), mais prend un argument struct varargs.

De nouveaux ID randomisés peuvent être générés avec la commande new de systemd-id128(1).

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que dès le début du programme, lorsqu'aucun autre thread n'a été démarré.
