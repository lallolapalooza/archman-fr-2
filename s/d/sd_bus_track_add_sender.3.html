SD_BUS_TRACK_ADD_NAME(3) sd_bus_track_add_name SD_BUS_TRACK_ADD_NAME(3)

NOM

sd_bus_track_add_name, sd_bus_track_add_sender, sd_bus_track_remove_name, sd_bus_track_remove_sender, sd_bus_track_count, sd_bus_track_count_sender, sd_bus_track_count_name, sd_bus_track_contains, sd_bus_track_first, sd_bus_track_next - Ajouter, supprimer et récupérer des pairs de bus suivis dans un objet de suivi de pairs de bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_add_name(sd_bus_track* t, const char* name);

int sd_bus_track_add_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_remove_name(sd_bus_track* t, const char* name);

int sd_bus_track_remove_sender(sd_bus_track* t, sd_bus_message* message);

unsigned sd_bus_track_count(sd_bus_track* t);

int sd_bus_track_count_name(sd_bus_track* t, const char* name);

int sd_bus_track_count_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_contains(sd_bus_track* t, const char* name);

const char* sd_bus_track_first(sd_bus_track* t);

const char* sd_bus_track_next(sd_bus_track* t);

DESCRIPTION

sd_bus_track_add_name() ajoute une paire à suivre à un objet de suivi de pairs de bus. Le premier argument doit faire référence à un objet de suivi de pairs de bus créé avec sd_bus_track_new(3), le nom secondaire doit faire référence à un nom de pair D-Bus à suivre, soit au format de service connu soit au format unique. Si le nom n'est pas déjà suivi, il sera ajouté à la liste des noms à suivre. S'il est déjà suivi et que le mode non récursif est activé, aucune opération n'est exécutée par cet appel. Si le mode récursif est activé, un compteur par nom est incrémenté à chaque appel de cette fonction, et sd_bus_track_remove_name() doit être appelée autant de fois que sd_bus_track_add_name() a été invoquée auparavant afin d'arrêter le suivi du nom. Utilisez sd_bus_track_set_recursive(3) pour passer du mode non récursif par défaut au mode récursif, ou revenir en arrière. Notez que le nom spécifié est suivi tel quel, les noms connus ne sont pas résolus en noms uniques par cet appel. Notez que plusieurs objets de suivi de pairs de bus peuvent suivre le même nom.

sd_bus_track_remove_name() annule l'effet de sd_bus_track_add_name() et supprime un nom de pair de bus de la liste des pairs à surveiller. Selon que le mode non récursif ou récursif est activé pour l'objet de suivi de pairs de bus, cet appel soit supprimera le nom complètement de l'objet de suivi, soit simplement décrémentera le compteur par nom de un, ne supprimant le nom que lorsque le compteur atteint zéro (voir ci-dessus). Notez qu'un pair de bus se déconnectant du bus supprimera implicitement ses noms complètement de l'objet de suivi de pairs de bus, indépendamment du compteur par nom actuel.

sd_bus_track_add_sender() et sd_bus_track_remove_sender() sont similaires à sd_bus_track_add_name() et sd_bus_track_remove_name() mais prennent un message de bus comme argument. L'expéditeur de ce message de bus est déterminé et ajouté/supprimé de l'objet de suivi de pairs de bus. Comme les messages proviennent toujours de noms uniques, et jamais de noms connus, cela signifie que cet appel ajoutera effectivement uniquement des noms uniques à l'objet de suivi de pairs de bus.

sd_bus_track_count() retourne le nombre de noms actuellement suivis par l'objet de suivi de pairs de bus spécifié. Notez que cette fonction retourne toujours le nombre réel de noms suivis, et donc si sd_bus_track_add_name() a été invoquée plusieurs fois pour le même nom, il n'est compté qu'une seule fois, que le mode récursif soit utilisé ou non.

sd_bus_track_count_name() retourne le compteur actuel par nom pour le nom spécifié. Si le mode non récursif est utilisé, cette fonction retourne soit 1 soit 0, selon que le nom spécifié a été ajouté ou non à l'objet de suivi. Si le mode récursif a été activé, des valeurs supérieures à 1 peuvent également être retournées, au cas où sd_bus_track_add_name() aurait été appelée plusieurs fois pour le même nom.

sd_bus_track_count_sender() est similaire à sd_bus_track_count_name(), mais prend un objet de message de bus et retourne le compteur par nom correspondant à l'expéditeur du message.

sd_bus_track_contains() peut être utilisé pour déterminer si le nom spécifié a été ajouté au moins une fois à l'objet de suivi de pairs de bus spécifié.

sd_bus_track_first() et sd_bus_track_next() peuvent être utilisés pour énumérer tous les noms actuellement suivis par l'objet de suivi de pairs de bus passé. sd_bus_track_first() retourne la première entrée de l'objet, et réinitialise un index de lecture maintenu en interne. Chaque appel subséquent de sd_bus_track_next() retourne le nom suivant contenu dans l'objet de bus. Si la fin est atteinte, NULL est retourné. Si aucun nom n'a encore été ajouté à l'objet, sd_bus_track_first() retournera immédiatement NULL. L'ordre dans lequel les noms sont retournés n'est pas défini ; en particulier, quel nom est considéré comme le premier retourné n'est pas défini. Si le mode récursif est activé et que le même nom a été ajouté plusieurs fois à l'objet de suivi de pairs de bus, il n'est retourné qu'une seule fois par cette énumération. Si de nouveaux noms sont ajoutés ou si des noms existants sont supprimés de l'objet de suivi de pairs de bus pendant son énumération, l'énumération se termine lors du prochain appel de sd_bus_track_next() car NULL est retourné.

VALEUR RENVOYÉE

En cas de succès, sd_bus_track_add_name() et sd_bus_track_add_sender() retournent 0 si le nom spécifié a déjà été ajouté auparavant à l'objet de suivi de pairs de bus, et une valeur positive s'il ne l'a pas été. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

sd_bus_track_remove_name() et sd_bus_track_remove_sender() retournent une valeur positive si le nom spécifié était précédemment suivi par l'objet de suivi de pairs de bus et a maintenant été supprimé. En mode non récursif, 0 est retourné si le nom spécifié n'était pas encore suivi. En mode récursif, -EUNATCH est retourné dans ce cas. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

sd_bus_track_count() retourne le nombre de noms actuellement suivis, ou 0 en cas d'échec.

sd_bus_track_count_name() et sd_bus_track_count_sender() retournent le compteur actuel par nom pour le nom spécifié ou l'expéditeur du message spécifié. Zéro est retourné pour les noms qui ne sont pas encore suivis, une valeur positive pour les noms ajoutés au moins une fois. Des valeurs supérieures à 1 ne sont retournées qu'en mode récursif. En cas d'échec, un code d'erreur négatif de type errno est retourné.

sd_bus_track_contains() retourne le nom passé s'il existe dans l'objet de suivi de pairs de bus. En cas d'échec, et si le nom n'a pas encore été ajouté, NULL est retourné.

sd_bus_track_first() et sd_bus_track_next() retournent le premier/prochain nom contenu dans l'objet de suivi de pairs de bus, et NULL si la fin de l'énumération est atteinte et en cas d'erreur.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EUNATCH

sd_bus_track_remove_name() ou sd_bus_track_remove_sender() ont été invoqués pour un nom non ajouté auparavant à l'objet de pair de bus.

-EINVAL

Le paramètre spécifié est invalide.

-ENOMEM

Échec de l'allocation de mémoire.

SYNTOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_add_sender(sd_bus_track *track, const char *sender);
int sd_bus_track_remove_sender(sd_bus_track *track, const char *sender);
int sd_bus_track_add_name(sd_bus_track *track, const char *name);
int sd_bus_track_remove_name(sd_bus_track *track, const char *name);
size_t sd_bus_track_count(sd_bus_track *track);
size_t sd_bus_track_count_sender(sd_bus_track *track, const char *sender);
size_t sd_bus_track_count_name(sd_bus_track *track, const char *name);
bool sd_bus_track_contains(sd_bus_track *track, const char *sender);
sd_bus_track *sd_bus_track_first(sd_bus_track *track);
sd_bus_track *sd_bus_track_next(sd_bus_track *track);

DESCRIPTION

Un objet sd_bus_track est utilisé pour garder une trace des correspondances de règles d'événements du bus.

La fonction sd_bus_track_add_sender() ajoute l'expéditeur spécifié sender à la liste de suivi track. Le nom de l'expéditeur est copié.

La fonction sd_bus_track_remove_sender() supprime l'expéditeur spécifié sender de la liste de suivi track.

La fonction sd_bus_track_add_name() ajoute le nom spécifié name à la liste de suivi track. Le nom est copié.

La fonction sd_bus_track_remove_name() supprime le nom spécifié name de la liste de suivi track.

La fonction sd_bus_track_count() renvoie le nombre total d'éléments dans la liste de suivi track.

La fonction sd_bus_track_count_sender() renvoie le nombre d'occurrences de l'expéditeur spécifié sender dans la liste de suivi track.

La fonction sd_bus_track_count_name() renvoie le nombre d'occurrences du nom spécifié name dans la liste de suivi track.

La fonction sd_bus_track_contains() renvoie vrai si l'expéditeur spécifié sender est présent dans la liste de suivi track, faux sinon.

Les fonctions sd_bus_track_first() et sd_bus_track_next() peuvent être utilisées pour itérer sur les noms d'expéditeurs et les noms de service dans la liste de suivi. Elles renvoient la première entrée de la liste de suivi, puis chaque appel successif à sd_bus_track_next() renvoie l'entrée suivante. Elles renvoient NULL lorsque la fin de la liste est atteinte. Les objets retournés sont des structures internes et ne doivent pas être modifiés directement.

Notez qu'un seul type de suivi (soit expéditeur, soit nom de service) est pris en charge par liste de suivi.

VALEUR RENVOYÉE

sd_bus_track_add_sender(), sd_bus_track_remove_sender(), sd_bus_track_add_name(), et sd_bus_track_remove_name() renvoient 0 en cas de succès, ou un code d'erreur négatif en cas d'échec.

sd_bus_track_count(), sd_bus_track_count_sender(), sd_bus_track_count_name() renvoient le nombre d'éléments dans la liste de suivi.

sd_bus_track_contains() renvoie true ou false.

sd_bus_track_first() et sd_bus_track_next() renvoient un pointeur opaque vers une structure interne ou NULL.

NOTES

Les fonctions sd_bus_track_* ne doivent être appelées qu'après la création d'un objet sd_bus_track avec sd_bus_track_new(3) et avant sa destruction avec sd_bus_track_unref(3). Si une liste de suivi est utilisée avec un bus qui est déjà en cours d'utilisation par d'autres threads, il est de la responsabilité de l'appelant de s'assurer que la liste de suivi n'est accédée qu'à partir d'un seul thread. L'API d'appelant est conçue pour être utilisée à partir d'un seul thread, et n'est pas sûre pour l'accès concurrentiel.

Les entrées ajoutées à la liste de suivi sont copiées. Les chaînes passées comme arguments doivent rester valides pendant la durée de vie de la liste de suivi.

Lors de l'utilisation de sd_bus_track_first() et sd_bus_track_next(), les entrées retournées sont soit des noms d'expéditeurs, soit des noms de services, selon le type de l'entrée dans la liste de suivi. L'appelant ne doit pas modifier ces entrées. Toutes les entrées de la liste de suivi sont de type expéditeur ou de type nom de service, mais pas les deux.

Il est possible d'ajouter une liste de suivi vide au démarrage du programme lorsqu'aucun autre thread n'a été démarré.
