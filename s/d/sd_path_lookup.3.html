int sd_path_lookup_strv(uint64_t type, const char *suffix, char ***paths);

DESCRIPTION

sd_path_lookup() et sd_bus_path_lookup_strv() renvoient un chemin unique ou un ensemble de chemins de système de fichiers spécifiés par l'argument type. Dans le cas de sd_path_lookup(), une seule chaîne se terminant par un NUL est renvoyée. Lorsque type spécifie un ensemble de chemins, ils sont concaténés en utilisant ":" comme séparateur (comme cela est traditionnellement fait pour par exemple $PATH ou $LD_LIBRARY_PATH). Dans le cas de sd_path_lookup_strv(), un tableau de chaînes se terminant par un NULL est renvoyé (strv). Si le suffixe suffix est fourni, il est concaténé à chacun des chemins après une barre oblique ("/"). Tous les chemins renvoyés sont absolus.

Pour les chemins qui font référence à des répertoires utilisateur, la spécification standard XDG pertinente est suivie, avec le support des variables d'environnement telles que $XDG_DOCUMENTS_DIR, $XDG_DESKTOP_DIR, ..., et une configuration explicite dans /etc/xdg/user-dirs.conf ou ${XDG_CONFIG_HOME}/user-dirs.dirs. Voir la Spécification des répertoires de base XDG[1] pour plus de détails.

systemd-path(1) est un wrapper autour de sd_path_lookup() et permet d'interroger le même ensemble de chemins.

VALEUR DE RETOUR

En cas de succès, sd_path_lookup() et sd_path_lookup_strv() renvoient un entier non négatif. En cas d'échec, un numéro d'erreur négatif de style errno est renvoyé par l'une ou l'autre des fonctions.

La chaîne ou le tableau de chaînes (strv) renvoyé doit être libéré par l'appelant en utilisant free(3).

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants:

-EOPNOTSUPP

Identifiant type inconnu.

Ajouté dans la version 246.

-EINVAL

L'argument de sortie est NULL.

Ajouté dans la version 246.

-ENXIO

La requête a échoué en raison d'une variable d'environnement non définie (par exemple, pour SD_PATH_USER_RUNTIME lorsque $XDG_RUNTIME_DIR n'est pas défini).

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation mémoire.

Ajouté dans la version 246.

EXEMPLES

Rechercher l'emplacement de ~/Documents

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-path.h>
int main(void) {
  int r;
  char *t;
  r = sd_path_lookup(SD_PATH_USER_DOCUMENTS, NULL, &t);
  if (r < 0)
    return EXIT_FAILURE;
  printf("~/Documents: %s\n", t);
  free(t);
  return EXIT_SUCCESS;
}

Notez que la réponse par défaut $HOME/Documents peut être remplacée par user-dirs.conf ou $XDG_DOCUMENTS_DIR.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multithread. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à un stade précoce du programme lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_path_lookup() et sd_path_lookup_strv() ont été ajoutées dans la version 246.

NOM

sd_path_lookup — Recherche de chemins d'accès de fichiers pour un identifiant donné

SYNOPSIS

sd_path_lookup(3) 

#include <sd-path.h>

int sd_path_lookup(const char *suffix, const char *id, const char **path);

DESCRIPTION

sd_path_lookup essaie de trouver un chemin d'accès de fichier correspondant à un identifiant donné. L'identifiant est généralement une chaîne composée, où les composants sont séparés par des '/'. Le chemin d'accès final est construit en concaténant la chaîne de préfixe définie par l'environnement et les autres composants de l'identifiant.

Cette fonction est utile pour localiser des fichiers dans une hiérarchie de répertoires basée sur une spécification d'identifiant.

VALEUR DE RETOUR

sd_path_lookup renvoie 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les codes d'erreur possibles incluent :

-ENOMEM
Une allocation de mémoire a échoué.
-ENOENT
Le chemin d'accès spécifié n'a pas été trouvé.
-EINVAL
Un argument invalide a été fourni.

EXEMPLES

La recherche de chemin d'accès suivante suppose que la variable d'environnement XDG_DATA_DIRS est définie sur "/usr/share:/usr/local/share".

const char *path;
int ret;

ret = sd_path_lookup("applications/myapp.desktop", "org.example.myapp", &path);
if (ret < 0) {
    fprintf(stderr, "Erreur lors de la recherche du chemin: %s\n", strerror(-ret));
    return 1;
}

printf("Chemin trouvé: %s\n", path);
// Sortie possible : /usr/share/org.example.myapp/applications/myapp.desktop
// ou              /usr/local/share/org.example.myapp/applications/myapp.desktop
// en fonction de l'ordre de recherche.

free((void*)path); // N'oubliez pas de libérer la mémoire allouée pour le chemin.

NOTES

Les chemins d'accès renvoyés par cette fonction doivent être libérés avec free().

La recherche de chemin d'accès peut être influencée par des variables d'environnement telles que XDG_DATA_DIRS et XDG_CONFIG_DIRS.

HISTORIQUE

La fonction sd_path_lookup est apparue pour la première fois dans systemd version 243.

VOIR AUSSI

sd_path_lookup(3), sd-path.h(3), freeboot(1), systemd(1)
