SD_BUS_MESSAGE_APPEND_ARRAY(3) sd_bus_message_append_array SD_BUS_MESSAGE_APPEND_ARRAY(3)

NOM

sd_bus_message_append_array, sd_bus_message_append_array_memfd, sd_bus_message_append_array_iovec, sd_bus_message_append_array_space - Ajouter un tableau de champs à un message D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_append_array(sd_bus_message *m, char type, const void *ptr, size_t size);

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, int memfd, uint64_t offset, uint64_t size);

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, unsigned n);

int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t size, void **ptr);

DESCRIPTION

La fonction sd_bus_message_append_array() ajoute un tableau au message D-Bus m. Un conteneur sera ouvert, le contenu du tableau sera ajouté, et le conteneur sera fermé. Le paramètre type détermine comment le pointeur p est interprété. type doit être l'un des types "triviaux" "y", "n", "q", "i", "u", "x", "t", "d" (mais pas "b"), tels que définis par la section Types de base D-Bus[1] de la spécification D-Bus, et listés dans sd_bus_message_append_basic(3). Le pointeur p doit pointer vers un tableau de taille size octets contenant des éléments du type respectif. La taille size doit être un multiple de la taille du type type. À titre de cas spécial, p peut être NULL, si size est 0. La mémoire pointée par p est copiée dans la zone mémoire contenant le message et reste en possession de l'appelant. L'appelant peut donc modifier librement les données après cet appel sans affecter le message auquel le tableau a été ajouté.

La fonction sd_bus_message_append_array_memfd() ajoute un tableau d'un type trivial au message m, de manière similaire à sd_bus_message_append_array(). Le contenu du descripteur de fichier mémoire memfd commençant à l'offset spécifié et de la taille spécifiée est utilisé comme contenu du tableau. L'offset et la taille doivent être un multiple de la taille du type type. Cependant, à titre d'exception spéciale, si l'offset est spécifié comme zéro et la taille spécifiée comme UINT64_MAX, le contenu complet du descripteur de fichier mémoire est utilisé. Le descripteur de fichier mémoire est scellé par cet appel s'il n'a pas déjà été scellé, et ne peut plus être modifié après cet appel. Voir memfd_create(2) pour plus de détails sur les descripteurs de fichiers mémoire. L'ajout de tableaux avec des descripteurs de fichiers mémoire permet un transfert de données efficace sans copie, car le descripteur de fichier mémoire peut être passé tel quel à la destination, sans copier la mémoire qu'il contient vers le processus de destination. Tous les transports de protocole ne prennent pas en charge le passage de descripteurs de fichiers mémoire entre participants, auquel cas cet appel se rabattra automatiquement sur la copie. De plus, comme le passage de descripteurs de fichiers mémoire est inefficace pour de petites quantités de données, la copie peut toujours être forcée même lorsque le passage de descripteurs de fichiers mémoire est pris en charge.

La fonction sd_bus_message_append_array_iovec() ajoute un tableau d'un type trivial au message m, de manière similaire à sd_bus_message_append_array(). Le contenu du tableau de vecteurs I/O iov est utilisé comme contenu du tableau. La taille totale de la charge utile de iov (la somme des champs iov_len) doit être un multiple de la taille du type type. L'argument iov doit pointer vers n structures de vecteurs I/O. Chaque structure peut avoir le champ iov_base défini, auquel cas la mémoire pointée sera copiée dans le message, ou non défini (mis à zéro), auquel cas un bloc de zéros de longueur iov_len octets sera inséré. La mémoire pointée par iov peut être modifiée après cet appel.

La fonction sd_bus_message_append_array_space() ajoute de l'espace pour un tableau d'un type trivial au message m. Elle se comporte comme sd_bus_message_append_array(), mais au lieu de copier les éléments dans le message, elle renvoie un pointeur vers la zone de destination à l'appelant dans le pointeur p. L'appelant doit ensuite écrire le contenu du tableau dans cette mémoire. Les modifications apportées à la mémoire pointée ne doivent être effectuées que jusqu'à la prochaine opération sur le message bus invoquée. Plus important encore, la mémoire ne doit plus être modifiée lorsqu'un autre champ a été ajouté au message ou lorsque le message a été scellé.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre spécifié est invalide.

-EPERM

Le message a été scellé.

-ESTALE

Le message est dans un état invalide.

-ENXIO

Le message ne peut pas être ajouté.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que depuis une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

sd_bus_message_append_array_space

sd_bus_message_append_array_space - Réserve de l'espace dans un message D-Bus pour un tableau

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t *idx);

DESCRIPTION

Cette fonction réserve de l'espace dans le message m pour un tableau dont les éléments sont de type type. Le type de base type doit être un des types atomiques du bus D-Bus comme décrit dans sd_bus_message_append_basic(3). La fonction retourne un pointeur vers le début de l'espace réservé. Cet espace peut ensuite être rempli avec des éléments du type spécifié en utilisant sd_bus_message_append_basic(3) ou des appels récursifs à sd_bus_message_append_array_space(3) ou sd_bus_message_append_container(3).

Après avoir rempli l'espace réservé, la fonction sd_bus_message_close_container(3) doit être appelée pour finaliser le tableau. Si idx n'est pas NULL, un pointeur vers l'index du début du tableau sera stocké à cette adresse.

PARAMÈTRES

m
Un pointeur vers le message D-Bus auquel ajouter le tableau.
type
Le type de base des éléments du tableau (par exemple, 'i' pour un entier 32 bits).
idx
Un pointeur vers une variable de type size_t où sera stocké l'index du début du tableau, ou NULL.

VALEUR DE RETOUR

En cas de succès, la fonction retourne un pointeur vers le début de l'espace réservé dans le message. En cas d'échec, elle retourne un pointeur NULL et errno est positionné pour indiquer l'erreur.

ERREURS

-EINVAL
Le type spécifié n'est pas valide ou le message est invalide.
-ENOMEM
Pas assez de mémoire pour allouer l'espace nécessaire.

VOIR AUSSI

sd_bus_message_append_basic(3), sd_bus_message_append_container(3), sd_bus_message_close_container(3)

NOTES

Cette fonction est généralement utilisée pour construire des messages D-Bus de manière plus flexible, en particulier lorsqu'il n'est pas possible de connaître à l'avance la taille exacte du tableau.
