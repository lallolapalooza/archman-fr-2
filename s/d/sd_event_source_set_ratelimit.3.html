SD_EVENT_SOURCE_SET_RATELIMIT(3) sd_event_source_set_ratelimit SD_EVENT_SOURCE_SET_RATELIMIT(3)

NOM

sd_event_source_set_ratelimit, sd_event_source_get_ratelimit, sd_event_source_is_ratelimited, sd_event_source_set_ratelimit_expire_callback, sd_event_source_leave_ratelimit - Configurer la limitation de débit sur les sources d'événements

SYNTAXE

#include <systemd/sd-event.h>

int sd_event_source_set_ratelimit(sd_event_source *source, uint64_t interval_usec, unsigned burst);

int sd_event_source_get_ratelimit(sd_event_source *source, uint64_t* ret_interval_usec, unsigned* ret_burst);

int sd_event_source_is_ratelimited(sd_event_source *source);

int sd_event_source_set_ratelimit_expire_callback(sd_event_source *source, sd_event_handler_tcallback);

int sd_event_source_leave_ratelimit(sd_event_source *source);

DESCRIPTION

sd_event_source_set_ratelimit() peut être utilisée pour imposer une limitation de débit sur une source d'événements. Lorsqu'elle est utilisée, une source d'événements sera temporairement désactivée lorsqu'elle se déclenche plus souvent qu'un nombre de rafales spécifié dans un intervalle de temps spécifié. C'est utile comme mécanisme simple pour éviter la famine des sources d'événements si des sources d'événements de haute priorité se déclenchent très fréquemment.

Passez la source d'événements à opérer comme premier argument, un intervalle de temps en microsecondes comme deuxième argument et une limite maximale de dispatch ("rafale") comme troisième paramètre. Chaque fois que la source d'événements est dispatchée plus souvent que la rafale spécifiée dans l'intervalle spécifié, elle est placée dans un mode similaire à celui de l'activation avec sd_event_source_set_enabled(3) et le paramètre SD_EVENT_OFF. Cependant, elle n'est désactivée que temporairement – une fois l'intervalle spécifié terminé, le fonctionnement régulier reprend. Elle est à nouveau désactivée temporairement une fois que la limitation de débit spécifiée est atteinte la prochaine fois. Si la valeur de l'intervalle ou de la rafale est spécifiée à zéro, la limitation de débit est désactivée. Par défaut, les sources d'événements n'ont pas la limitation de débit activée. Notez que la limitation de débit et la désactivation via sd_event_source_set_enabled() sont indépendantes l'une de l'autre, et une source d'événements n'affectera les réveils de la boucle d'événements et ne sera dispatchée que si elle est activée et que la limitation de débit n'est pas en vigueur.

sd_event_source_get_ratelimit() peut être utilisée pour interroger les paramètres actuels de limitation de débit définis sur l'objet source d'événements source. Les valeurs d'intervalle et de rafale précédemment définies sont retournées dans les deuxième et troisième arguments.

sd_event_source_is_ratelimited() peut être utilisée pour interroger si la source d'événements est actuellement affectée par la limitation de débit, c'est-à-dire si elle a récemment atteint la limite de débit et est actuellement temporairement désactivée en raison de cela.

sd_event_source_set_ratelimit_expire_callback() peut être utilisée pour définir une fonction de rappel qui est appelée chaque fois que la source d'événements quitte l'état de limitation de débit. Notez que la fonction est appelée dans la même itération de boucle d'événements lors de la transition d'état.

sd_event_source_leave_ratelimit() peut être utilisée pour réactiver immédiatement une source d'événements qui a été temporairement désactivée en raison de la limitation de débit. Cela réinitialisera les compteurs de limitation de débit pour l'intervalle de temps actuel.

La limitation de débit est actuellement implémentée pour les sources d'événements I/O, timer, signal, defer et inotify.

VALEUR DE RETOUR

En cas de succès, sd_event_source_set_ratelimit(), sd_event_source_set_ratelimit_expire_callback et sd_event_source_get_ratelimit() retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de type errno. sd_event_source_is_ratelimited() retourne zéro si la limitation de débit n'est actuellement pas en vigueur et supérieur à zéro si elle est en vigueur ; elle retourne un code d'erreur négatif de type errno en cas d'échec. sd_event_source_leave_ratelimit() retourne zéro si la limitation de débit n'était pas en vigueur pour la source d'événements spécifiée, et positif si elle l'était et que la limitation de débit est maintenant désactivée à nouveau ; elle retourne un code d'erreur négatif de type errno en cas d'échec.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

source n'est pas un pointeur valide vers un objet sd_event_source.

Ajouté dans la version 248.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

Ajouté dans la version 248.

-EDOM

Il a été tenté d'utiliser la fonctionnalité de limitation de débit sur un type de source d'événements qui ne prend pas en charge la limitation de débit.

Ajouté dans la version 248.

-ENOEXEC

sd_event_source_get_ratelimit() a été appelée sur une source d'événements pour laquelle la limitation de débit n'est pas configurée.

Ajouté dans la version 248.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dès le début du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_source_set_ratelimit(), sd_event_source_get_ratelimit() et sd_event_source_is_ratelimited() ont été ajoutées dans la version 248.

sd_event_source_set_ratelimit_expire_callback() a été ajoutée dans la version 250.

sd_event_source_leave_ratelimit() a été ajoutée dans la version 254.
