sd_bus_message_enter_container(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_OPEN_CONTAINER(3) sd_bus_message_open_container SD_BUS_MESSAGE_OPEN_CONTAINER(3)

NOM

sd_bus_message_open_container, sd_bus_message_close_container, sd_bus_message_enter_container, sd_bus_message_exit_container - Créer et naviguer entre les conteneurs dans les messages D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_open_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_close_container(sd_bus_message *m);

int sd_bus_message_enter_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_exit_container(sd_bus_message *m);

DESCRIPTION

sd_bus_message_open_container() ajoute un nouveau conteneur au message m. Après avoir ouvert un nouveau conteneur, il peut être rempli avec du contenu en utilisant sd_bus_message_append(3) et des fonctions similaires. Les conteneurs se comportent comme une pile. Pour imbriquer des conteneurs les uns dans les autres, appelez sd_bus_message_open_container() plusieurs fois sans appeler sd_bus_message_close_container() entre-temps. Chaque conteneur sera imbriqué dans le conteneur précédent. type représente le type de conteneur et doit être "r", "a", "v" ou "e" comme décrit dans sd_bus_message_append(3). Au lieu de littéraux, les constantes correspondantes SD_BUS_TYPE_STRUCT, SD_BUS_TYPE_ARRAY, SD_BUS_TYPE_VARIANT ou SD_BUS_TYPE_DICT_ENTRY peuvent également être utilisées. contents décrit le type des éléments du conteneur et doit être une chaîne de type D-Bus suivant les règles décrites dans sd_bus_message_append(3).

sd_bus_message_close_container() ferme le dernier conteneur ouvert avec sd_bus_message_open_container(). En cas de succès, le pointeur d'écriture du message m est positionné après le conteneur fermé dans son conteneur parent ou dans m lui-même s'il n'y a pas de conteneur parent.

sd_bus_message_enter_container() entre dans le conteneur suivant du message m pour la lecture. Il se comporte de manière très similaire à sd_bus_message_open_container(). Entrer dans un conteneur permet de lire son contenu avec sd_bus_message_read(3) et des fonctions similaires. type et contents sont les mêmes que dans sd_bus_message_open_container().

sd_bus_message_exit_container() quitte la portée du dernier conteneur entré avec sd_bus_message_enter_container(). Il se comporte de manière très similaire à sd_bus_message_close_container(). Notez que sd_bus_message_exit_container() ne peut être appelé qu'après avoir parcouru tous les membres du conteneur, c'est-à-dire en les lisant ou en les ignorant. Utilisez sd_bus_message_skip(3) pour ignorer les champs d'un conteneur afin de pouvoir quitter le conteneur avec sd_bus_message_exit_container() sans lire tous les membres.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier non négatif. sd_bus_message_open_container() et sd_bus_message_close_container() renvoient 0. sd_bus_message_enter_container() renvoie 1 s'il a réussi à ouvrir un nouveau conteneur, et 0 si cela n'a pas été possible car la fin du conteneur ouvert en cours ou du message a été atteinte. sd_bus_message_exit_container() renvoie 1 en cas de succès. En cas d'échec, toutes ces fonctions renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

m ou contents sont NULL ou type est invalide.

Ajouté dans la version 246.

-EBADMSG

Le message m a une structure invalide.

Ajouté dans la version 254.

-ENXIO

Le message m n'a pas de conteneur du type type à la position actuelle, ou le contenu ne correspond pas à contents.

Ajouté dans la version 254.

-EPERM

Le message m est déjà scellé.

Ajouté dans la version 246.

-ESTALE

Le message m est dans un état invalide.

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation mémoire.

Ajouté dans la version 246.

-EBUSY

sd_bus_message_exit_container() a été appelé mais il reste des membres non lus dans le conteneur.

Ajouté dans la version 247.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour le multithreading. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été lancé.

EXEMPLES

Exemple 1. Ajouter un tableau de chaînes à un message

/* SPDX-License-Identifier: MIT-0 */
#include <systemd/sd-bus.h>
int append_strings_to_message(sd_bus_message *m, const char *const *arr) {
  const char *s;
  int r;
  r = sd_bus_message_open_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (s = *arr; *s; s++) {
    r = sd_bus_message_append(m, "s", s);
    if (r < 0)
      return r;
  }
  return sd_bus_message_close_container(m);
}

Exemple 2. Lire un tableau de chaînes à partir d'un message

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-bus.h>
int read_strings_from_message(sd_bus_message *m) {
  int r;
  r = sd_bus_message_enter_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (;;) {
    const char *s;
    r = sd_bus_message_read(m, "s", &s);
    if (r < 0)
      return r;
    if (r == 0)
      break;
    printf("%s\n", s);
  }
  return sd_bus_message_exit_container(m);
}
