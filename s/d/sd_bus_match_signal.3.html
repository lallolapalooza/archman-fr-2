SD_BUS_ADD_MATCH(3) sd_bus_add_match SD_BUS_ADD_MATCH(3)

NOM

sd_bus_add_match, sd_bus_add_match_async, sd_bus_match_signal, sd_bus_match_signal_async - Ajouter une règle de correspondance pour la distribution des messages entrants

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_add_match(sd_bus *bus, sd_bus_slot **slot, const char *match, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_add_match_async(sd_bus *bus, sd_bus_slot **slot, const char *match, sd_bus_message_handler_t callback, sd_bus_message_handler_t install_callback, void *userdata);

int sd_bus_match_signal(sd_bus *bus, sd_bus_slot **slot, const char *sender, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_match_signal_async(sd_bus *bus, sd_bus_slot **slot, const char *sender, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, sd_bus_message_handler_t install_callback, void *userdata);

DESCRIPTION

sd_bus_add_match() installe une règle de correspondance pour les messages reçus sur l'objet de connexion de bus spécifié bus. La syntaxe de l'expression de la règle de correspondance passée dans match est décrite dans la Spécification D-Bus[1]. La fonction de traitement spécifiée callback est appelée pour chaque message entrant correspondant à l'expression spécifiée, le paramètre userdata est passé tel quel à la fonction de rappel. La correspondance est installée de manière synchrone lors de la connexion à un courtier de bus, c'est-à-dire que l'appel envoie un message de contrôle demandant l'ajout de la correspondance au courtier et attend la confirmation de l'installation réussie de la correspondance par le courtier.

sd_bus_add_match_async() fonctionne de manière très similaire à sd_bus_add_match(), mais installe la correspondance de manière asynchrone, non bloquante : une requête est envoyée au courtier, mais l'appel n'attend pas de réponse. La fonction install_callback est appelée lorsque la réponse est reçue plus tard, avec le message de réponse du courtier comme paramètre. Si cette fonction est spécifiée comme NULL, une implémentation par défaut est utilisée qui termine la connexion du bus si l'installation de la correspondance échoue.

sd_bus_match_signal() est très similaire à sd_bus_add_match(), mais ne correspond qu'aux signaux, et au lieu d'une expression de correspondance, accepte quatre paramètres : sender (le nom du service de l'expéditeur), path (le chemin de l'objet de l'objet émetteur), interface (l'interface à laquelle le signal appartient), member (le nom du signal), à partir desquels la chaîne de correspondance est générée en interne. Optionnellement, ces paramètres peuvent être spécifiés comme NULL, auquel cas le champ pertinent des signaux entrants n'est pas testé.

sd_bus_match_signal_async() combine la logique de correspondance des signaux de sd_bus_match_signal() avec le comportement asynchrone de sd_bus_add_match_async().

En cas de succès, et si non-NULL, le paramètre de retour slot sera défini sur un objet slot qui peut être utilisé comme référence à la correspondance installée, et peut être utilisé pour la supprimer plus tard avec sd_bus_slot_unref(3). Si spécifié comme NULL, la durée de vie de la correspondance est liée à la durée de vie de l'objet bus lui-même, et la correspondance n'est généralement pas supprimée indépendamment. Voir sd_bus_slot_set_floating(3) pour plus de détails.

Le message m passé au rappel est uniquement emprunté, c'est-à-dire que le rappel ne doit pas appeler sd_bus_message_unref(3) dessus. Si le rappel souhaite conserver le message au-delà de la durée de vie du rappel, il doit appeler sd_bus_message_ref(3) pour créer une nouvelle référence.

Si une erreur survient pendant l'invocation du rappel, le rappel doit retourner un nombre d'erreur négatif (optionnellement, une erreur plus précise peut être retournée dans ret_error, également). S'il souhaite que d'autres rappels correspondant à la même règle soient appelés, il doit retourner 0. Sinon, il doit retourner un entier positif.

Si bus fait référence à une connexion directe (c'est-à-dire pas une connexion de bus, comme défini avec sd_bus_set_bus_client(3)), la correspondance n'est installée que du côté client, et les fonctions synchrone et asynchrone fonctionnent de la même manière.

VALEUR DE RETOUR

En cas de succès, sd_bus_add_match() et les autres appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_add_match() et sd_bus_message_handler_t() ont été ajoutés dans la version 221.

sd_bus_add_match_async(), sd_bus_match_signal() et sd_bus_match_signal_async() ont été ajoutés dans la version 237.
