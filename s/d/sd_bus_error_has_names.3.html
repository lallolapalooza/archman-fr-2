DESCRIPTION

La structure sd_bus_error contient des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles pour les noms d'erreur décrites dans la spécification D-Bus, sous-section Valid D-Bus Names[1]. Un certain nombre d'erreurs courantes et standardisées sont décrites dans sd-bus-errors(3), mais des erreurs spécifiques au domaine supplémentaires peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir ses deux champs initialisés à NULL, et signifie l'absence d'erreur, c'est-à-dire le succès. Assigner SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque cela n'est plus nécessaire, les ressources détenues par la structure sd_bus_error doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur aux noms et messages spécifiés. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau quand ils ne sont plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données stockées en appelant sd_bus_error_free().

sd_bus_error_set() retournera une valeur similaire à errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, il est supposé qu'aucune erreur ne s'est produite, et 0 est retourné. Si name est non nul, une valeur négative est toujours retournée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est toujours converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs équivalents errno bien connus, et les autres sont converties en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreur bien connus. Des mappages d'erreurs supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçue pour être utilisée de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera retourné.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et des arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variés, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition des structures d'erreur. Comme cet appel n'alloue pas de mémoire, il n'échouera pas avec un manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() retournera immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur similaire à errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisée pour définir message. Les noms d'erreurs D-Bus bien connus seront utilisés pour name si applicable, sinon un nom dans le namespace "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si le numéro d'erreur spécifié error est non nul, l'appel retourne toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel pourrait échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est retournée.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et des arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variés, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur similaire à errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera retourné.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur auparavant. Sinon, il retournera immédiatement. Si les chaînes dans e ont été définies en utilisant sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit fraîchement initialisé avec NULL, soit réinitialisé en utilisant sd_bus_error_free().

sd_bus_error_copy() retourne généralement 0 ou une valeur négative similaire à errno basée sur le paramètre d'entrée e : 0 si elle était indéfinie et un entier négatif si elle était définie à une certaine erreur, de manière similaire à sd_bus_error_set(). sd_bus_error_has_names(3)

NAME

sd_bus_error_has_names_sentinel, sd_bus_error_has_names - Check for error names

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_error_has_names_sentinel(const sd_bus_error *e, const char *name, ...);
int sd_bus_error_has_names(const sd_bus_error *e, const char *first, ...);

DESCRIPTION

sd_bus_error_has_name() checks if the error structure pointed to by e has an error name set that matches the string in name. The error structure e must be valid, and the error must be set. This function returns true (a non-zero value) if the name matches, and false (zero) otherwise.

sd_bus_error_copy() makes a copy of the error structure pointed to by e into dst. If e is not set, dst is initialized to SD_BUS_ERROR_NULL. If dst is NULL, the error is simply freed. This function may fail with -ENOMEM if memory allocation fails.

sd_bus_error_move() is similar to sd_bus_error_copy(), but will move any error information from e into dst, resetting the former. This function cannot fail, as no new memory is allocated. Note that if e is not set, dst is initialized to SD_BUS_ERROR_NULL. Moreover, if dst is NULL no operation is executed on it and resources held by e are freed and reset. Returns a converted errno-like, non-positive error value.

sd_bus_error_is_set() will return a non-zero value if e is non-NULL and an error has been set, false otherwise.

sd_bus_error_has_name() will return a non-zero value if e is non-NULL and an error with the same name has been set, false otherwise.

sd_bus_error_has_names_sentinel() is similar to sd_bus_error_has_name(), but takes multiple names to check against. The list must be terminated with NULL. sd_bus_error_has_names() is a macro wrapper around sd_bus_error_has_names_sentinel() that adds the NULL sentinel automatically.

sd_bus_error_free() will destroy resources held by e. The parameter itself will not be deallocated, and must be free(3)d by the caller if necessary. The function may also be called safely on unset errors (error structures with both fields set to NULL), in which case it performs no operation. This call will reset the error structure after freeing the data, so that all fields are set to NULL. The structure may be reused afterwards.

REFERENCE OWNERSHIP

sd_bus_error is not reference-counted. Users should destroy resources held by it by calling sd_bus_error_free(). Usually, error structures are allocated on the stack or passed in as function parameters, but they may also be allocated dynamically, in which case it is the duty of the caller to free(3) the memory held by the structure itself after freeing its contents with sd_bus_error_free().

RETURN VALUE

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() always return 0 when the specified error value is NULL, and a negative errno-like value corresponding to the name parameter otherwise. The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof() and sd_bus_error_set_errnofv(), return 0 when the specified error value is 0, and a negative errno-like value corresponding to the error parameter otherwise. If an error occurs internally, one of the negative error values listed below will be returned. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_get_errno() returns false when e is NULL, and a positive errno value mapped from e->name otherwise.

sd_bus_error_copy() and sd_bus_error_move() return a negative error value converted from the source error, and zero if the error has not been set. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_is_set() returns a non-zero value when e and the name field are non-NULL, zero otherwise.

sd_bus_error_has_name(), sd_bus_error_has_names(), and sd_bus_error_has_names_sentinel() return a non-zero value when e is non-NULL and the name field is equal to one of the given names, zero otherwise.

Errors

Return value may indicate the following problems in the invocation of the function itself:

-EINVAL

Error was already set in the sd_bus_error structure when one the error-setting functions was called.

-ENOMEM

Memory allocation failed.

On success, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), and sd_bus_error_move() will return a negative converted errno-style value, or 0 if the error parameter is NULL or unset. D-Bus errors are converted to the integral errno-style value, and the mapping mechanism is extensible, see the discussion above. This effectively means that almost any negative errno-style value can be returned.

EXAMPLES

Example 1. Using the negative return value to propagate an error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* On success, return the number of bytes written, possibly 0. */
  /* On error, initialize the error structure, and also propagate the errno
   * value that write(2) set for us. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
