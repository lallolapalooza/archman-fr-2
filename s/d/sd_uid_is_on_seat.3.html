Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_UID_GET_STATE(3) sd_uid_get_state SD_UID_GET_STATE(3)

NOM

sd_uid_get_state, sd_uid_is_on_seat, sd_uid_get_sessions, sd_uid_get_seats, sd_uid_get_display, sd_uid_get_login_time - Déterminer l'état de connexion d'un identifiant utilisateur Unix spécifique

SYNTAXE

#include <systemd/sd-login.h>

int sd_uid_get_state(uid_t uid, char **state);

int sd_uid_is_on_seat(uid_t uid, int require_active, const char *seat);

int sd_uid_get_sessions(uid_t uid, int require_active, char ***sessions);

int sd_uid_get_seats(uid_t uid, int require_active, char ***seats);

int sd_uid_get_display(uid_t uid, char **session);

int sd_uid_get_login_time(uid_t uid, uint64_t *usec);

DESCRIPTION

sd_uid_get_state() peut être utilisé pour déterminer l'état de connexion d'un identifiant utilisateur Unix spécifique. Les états suivants sont actuellement connus : "offline" (l'utilisateur n'est connecté), "lingering" (l'utilisateur n'est pas connecté, mais certains services utilisateur sont en cours d'exécution), "online" (l'utilisateur est connecté, mais n'est pas actif, c'est-à-dire qu'il n'a pas de session au premier plan), "active" (l'utilisateur est connecté et a au moins une session active, c'est-à-dire une session au premier plan), "closing" (l'utilisateur n'est pas connecté et n'est pas en attente, mais certains processus sont encore présents). À l'avenir, des états supplémentaires pourraient être définis ; le code client doit être écrit pour être robuste face aux chaînes d'état supplémentaires retournées. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_uid_is_on_seat() peut être utilisé pour déterminer si un utilisateur spécifique est connecté ou actif sur un siège spécifique. Accepte un identifiant utilisateur Unix et une chaîne identifiant le siège en paramètres. Le paramètre require_active est une valeur booléenne. Si elle est non nulle (vrai), cette fonction vérifie si l'utilisateur est actif (c'est-à-dire qu'il a une session au premier plan et accepte les entrées utilisateur) sur le siège spécifié, sinon (faux) seulement si l'utilisateur est connecté (et éventuellement inactif) sur le siège spécifié.

sd_uid_get_sessions() peut être utilisé pour déterminer les sessions actuelles de l'utilisateur spécifié. Accepte un identifiant utilisateur Unix en paramètre. Le paramètre require_active contrôle si la liste retournée doit uniquement contenir les sessions où l'utilisateur est actuellement actif (> 0), où l'utilisateur est actuellement en ligne mais éventuellement inactif (= 0), ou connecté mais potentiellement en train de fermer la session (< 0). L'appel retourne un tableau de chaînes de caractères se terminant par NULL d'identifiants de session dans sessions qui doit être libéré par l'appelant avec l'appel free(3) de la libc après utilisation, y compris toutes les chaînes référencées. Si le paramètre du tableau de chaînes est passé comme NULL, le tableau ne sera pas rempli, mais le code de retour indiquera toujours le nombre de sessions actuelles. Notez qu'au lieu d'un tableau vide, NULL peut être retourné et doit être considéré comme équivalent à un tableau vide.

De même, sd_uid_get_seats() peut être utilisé pour déterminer la liste des sièges sur lesquels l'utilisateur a actuellement des sessions. Des sémantiques similaires s'appliquent, cependant, notez que l'utilisateur peut avoir plusieurs sessions sur le même siège ainsi que des sessions sans siège attaché et donc le nombre d'entrées dans le tableau retourné peut différer de celui retourné par sd_uid_get_sessions().

sd_uid_get_display() retourne le nom de la session "principale" d'un utilisateur. Si l'utilisateur a des sessions graphiques, ce sera la session graphique la plus ancienne. Sinon, ce sera la session ouverte la plus ancienne.

sd_uid_get_login_time() peut être utilisé pour déterminer l'heure à laquelle le gestionnaire de services de l'utilisateur a été invoqué, ce qui correspond à l'heure à laquelle la première session active de l'utilisateur, depuis laquelle il est resté connecté en continu, a commencé. L'argument usec est en microsecondes depuis l'époque (CLOCK_REALTIME). Cet appel échouera avec -ENXIO si l'utilisateur n'est pas actuellement connecté.

VALEUR DE RETOUR

En cas de succès, sd_uid_get_state() et sd_uid_get_login_time() retournent 0 ou un entier positif. Si le test réussit, sd_uid_is_on_seat() retourne un entier positif ; s'il échoue, 0. sd_uid_get_sessions() et sd_uid_get_seats() retournent le nombre d'entrées dans les tableaux retournés. sd_uid_get_display() retourne un code non négatif en cas de succès. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas spécifié pour l'utilisateur décrit.

-ENXIO

Le siège spécifié est inconnu.

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, là où ce n'est pas accepté). Ceci est également retourné si l'ID utilisateur passé est 0xFFFF ou 0xFFFFFFFF, ce qui est indéfini sous Linux.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que depuis une phase précoce du programme lorsque aucun autre thread n'a été démarré.
