SD_LOGIN_MONITOR_NEW(3) sd_login_monitor_new SD_LOGIN_MONITOR_NEW(3)

NOM

sd_login_monitor_new, sd_login_monitor_unref, sd_login_monitor_unrefp, sd_login_monitor_flush, sd_login_monitor_get_fd, sd_login_monitor_get_events, sd_login_monitor_get_timeout, sd_login_monitor - Surveiller les sessions de connexion, les sièges, les utilisateurs et les machines virtuelles/conteneurs

SYNTAXE

#include <systemd/sd-login.h>

int sd_login_monitor_new(const char *category, sd_login_monitor **ret);

sd_login_monitor *sd_login_monitor_unref(sd_login_monitor *m);

void sd_login_monitor_unrefp(sd_login_monitor **m);

int sd_login_monitor_flush(sd_login_monitor *m);

int sd_login_monitor_get_fd(sd_login_monitor *m);

int sd_login_monitor_get_events(sd_login_monitor *m);

int sd_login_monitor_get_timeout(sd_login_monitor *m, uint64_t *timeout_usec);

DESCRIPTION

sd_login_monitor_new() peut être utilisé pour surveiller les sessions de connexion, les utilisateurs, les sièges et les machines virtuelles/conteneurs. Via un objet de surveillance, un descripteur de fichier peut être intégré dans une boucle d'événements définie par l'application qui est réveillée chaque fois qu'un utilisateur se connecte, se déconnecte ou qu'un siège est ajouté ou supprimé, ou qu'une session, un utilisateur, un siège ou une machine virtuelle/conteneur change d'état. Le premier paramètre accepte une chaîne qui peut être "seat" (pour obtenir uniquement les notifications concernant les sièges ajoutés, supprimés ou modifiés), "session" (pour obtenir uniquement les notifications concernant les sessions créées, supprimées ou modifiées), "uid" (pour obtenir uniquement les notifications lorsque l'état d'un utilisateur change par rapport aux connexions) ou "machine" (pour obtenir uniquement les notifications lorsque qu'une machine virtuelle ou un conteneur est démarré ou arrêté). Si des notifications doivent être générées dans toutes ces conditions, NULL peut être passé. Notez qu'à l'avenir, des catégories supplémentaires pourront être définies. Le second paramètre retourne un objet de surveillance et doit être libéré avec l'appel sd_login_monitor_unref() après utilisation.

sd_login_monitor_unref() peut être utilisé pour détruire un objet de surveillance. Notez que cela invalidera tout descripteur de fichier retourné par sd_login_monitor_get_fd().

sd_login_monitor_unrefp() est similaire à sd_login_monitor_unref() mais prend un pointeur vers un pointeur vers un objet sd_login_monitor. Cet appel est utile en conjonction avec l'attribut de variable Clean-up de GCC et LLVM[1]. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme ce qui suit, afin d'allouer un objet de surveillance de connexion qui est libéré automatiquement lorsque le bloc de code est quitté :

{
  __attribute__((cleanup(sd_login_monitor_unrefp))) sd_login_monitor *m = NULL;
  int r;
  ...
  r = sd_login_monitor_new(NULL, &m);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Échec de l'allocation de l'objet de surveillance de connexion : %m\n");
  }
  ...
}

sd_login_monitor_flush() peut être utilisé pour réinitialiser l'état de réveil de l'objet de surveillance. Chaque fois qu'un événement provoque le réveil de la boucle d'événements via le descripteur de fichier, cette fonction doit être appelée pour réinitialiser l'état de réveil. Si cet appel n'est pas effectué, le descripteur de fichier réveillera immédiatement la boucle d'événements à nouveau.

sd_login_monitor_unref() et sd_login_monitor_unrefp() n'effectuent aucune opération si l'objet de surveillance passé est NULL.

sd_login_monitor_get_fd() peut être utilisé pour récupérer le descripteur de fichier de l'objet de surveillance qui peut être intégré dans une boucle d'événements définie par l'application, basée sur poll(2) ou une interface similaire. L'application devrait inclure le descripteur de fichier retourné comme source de réveil pour le masque d'événements retourné par sd_login_monitor_get_events(). Elle devrait passer une valeur de délai d'attente comme retourné par sd_login_monitor_get_timeout(). Chaque fois qu'un réveil est déclenché, le descripteur de fichier doit être réinitialisé via sd_login_monitor_flush(). Une application doit relire l'état de connexion avec une fonction comme sd_get_seats(3) ou similaire pour déterminer ce qui a changé.

sd_login_monitor_get_events() retournera le masque poll() pour lequel attendre. Cette fonction retournera une combinaison de POLLIN, POLLOUT et similaires pour remplir le champ ".events" de struct pollfd.

sd_login_monitor_get_timeout() retournera une valeur de délai d'attente à utiliser dans poll(). Ceci retourne une valeur en microsecondes depuis l'époque de CLOCK_MONOTONIC pour arrêter poll() dans timeout_usec. Voir clock_gettime(2) pour les détails sur CLOCK_MONOTONIC. S'il n'y a pas de délai d'attente, cela remplira (uint64_t) -1 à la place. Notez que poll() prend un délai relatif en millisecondes plutôt qu'un délai absolu en microsecondes. Pour convertir le délai absolu 'µs' en délai relatif 'ms', utilisez du code comme suit :

uint64_t t;
int msec;
sd_login_monitor_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

Le code ci-dessus ne fait aucun contrôle d'erreur par souci de brièveté. L'entier msec calculé peut être passé directement comme paramètre de délai d'attente de poll().

VALEUR DE RETOUR

En cas de succès, sd_login_monitor_new(), sd_login_monitor_flush() et sd_login_monitor_get_timeout() retournent 0 ou un entier positif. En cas de succès, sd_login_monitor_get_fd() retourne un descripteur de fichier Unix. En cas de succès, sd_login_monitor_get_events() retourne une combinaison de POLLIN, POLLOUT et similaires. En cas d'échec, ces appels retournent un code d'erreur négatif de type errno.

sd_login_monitor_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre d'entrée était invalide (hors plage, ou NULL, là où ce n'est pas accepté). La catégorie spécifiée à surveiller est inconnue.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_login_monitor_get_events() et sd_login_monitor_get_timeout() ont été ajoutés dans la version 201.

sd_login_monitor_unrefp() a été ajouté dans la version 229.

NOM

sd_login_monitor_new - Allouer et initialiser un nouvel objet de surveillance de connexion

SYNTAXE

#include <systemd/sd-login.h>
int sd_login_monitor_new(sd_login_monitor_t **_monitor);

DESCRIPTION

sd_login_monitor_new() alloue et initialise un nouvel objet sd_login_monitor. Cet objet peut être utilisé pour recevoir des notifications sur les événements de connexion des utilisateurs.

Le premier argument est un pointeur vers un pointeur de type sd_login_monitor_t. Si l'allocation réussit, un pointeur vers le nouvel objet de surveillance sera stocké dans la variable pointée par cet argument, et un pointeur non NULL sera retourné.

Les événements de connexion sont généralement des changements d'état pour les utilisateurs actifs (par exemple, connexion/déconnexion, changement d'état de la session).

VALEUR DE RETOUR

En cas de succès, sd_login_monitor_new() retourne 0 ou un entier positif. En cas d'échec, il retourne un entier négatif correspondant à un code d'erreur.

Codes d'erreur :

  • -ECHILD : L'opération a échoué dans un processus enfant.
  • -EINVAL : Le pointeur fourni est invalide.
  • -ENOMEM : Pas assez de mémoire.

NOTES

Après avoir créé un nouvel objet sd_login_monitor, vous pouvez utiliser sd_login_monitor_get_fd() pour obtenir le descripteur de fichier sur lequel écouter les événements. Utilisez ensuite sd_login_monitor_read_event() pour lire les événements du descripteur de fichier.

N'oubliez pas de libérer l'objet sd_login_monitor avec sd_login_monitor_unref() lorsqu'il n'est plus nécessaire.

HISTORIQUE

La fonction sd_login_monitor_new() a été introduite dans systemd version 220.

VOIR AUSSI

sd_login_monitor_unref(3), sd_login_monitor_get_fd(3), sd_login_monitor_read_event(3), systemd.login(5)
