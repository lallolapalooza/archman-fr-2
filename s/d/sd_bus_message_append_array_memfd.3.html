NOM

sd_bus_message_append_array, sd_bus_message_append_array_memfd, sd_bus_message_append_array_iovec, sd_bus_message_append_array_space - Ajouter un tableau de champs à un message D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_append_array(sd_bus_message *m, char type, const void *ptr, size_t size);

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, int memfd, uint64_t offset, uint64_t size);

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, unsigned n);

int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t size, void **ptr);

DESCRIPTION

La fonction sd_bus_message_append_array() ajoute un tableau à un message D-Bus m. Un conteneur sera ouvert, le contenu du tableau sera ajouté, puis le conteneur sera fermé. Le paramètre type détermine comment le pointeur p est interprété. type doit être l'un des types "triviaux" "y", "n", "q", "i", "u", "x", "t", "d" (mais pas "b"), tels que définis dans la section Types D-Bus de base[1] de la spécification D-Bus, et listés dans sd_bus_message_append_basic(3). Le pointeur p doit pointer vers un tableau de taille size octets contenant des éléments du type respectif. La taille size doit être un multiple de la taille du type type. Comme cas spécial, p peut être NULL, si size est 0. La mémoire pointée par p est copiée dans la zone mémoire contenant le message et reste en possession de l'appelant. L'appelant peut donc modifier librement les données après cet appel sans affecter le message auquel le tableau a été ajouté.

La fonction sd_bus_message_append_array_memfd() ajoute un tableau d'un type trivial au message m, de manière similaire à sd_bus_message_append_array(). Le contenu du descripteur de fichier mémoire memfd à partir de l'offset spécifié et de la taille spécifiée est utilisé comme contenu du tableau. L'offset et la taille doivent être un multiple de la taille du type type. Cependant, comme exception spéciale, si l'offset est spécifié comme zéro et la taille spécifiée comme UINT64_MAX, le contenu complet du descripteur de fichier mémoire est utilisé. Le descripteur de fichier mémoire est scellé par cet appel s'il n'a pas déjà été scellé, et ne peut plus être modifié après cet appel. Voir memfd_create(2) pour plus de détails sur les descripteurs de fichiers mémoire. L'ajout de tableaux avec des descripteurs de fichiers mémoire permet un transfert de données efficace sans copie (zero-copy), car le descripteur de fichier mémoire peut être passé tel quel à la destination, sans copier la mémoire qu'il contient vers le processus de destination. Tous les transports de protocole ne prennent pas en charge le passage de descripteurs de fichiers mémoire entre participants, auquel cas cet appel se repliera automatiquement sur la copie. De plus, comme le passage de descripteurs de fichiers mémoire est inefficace pour de petites quantités de données, la copie peut toujours être appliquée même lorsque le passage de descripteurs de fichiers mémoire est pris en charge.

La fonction sd_bus_message_append_array_iovec() ajoute un tableau d'un type trivial au message m, de manière similaire à sd_bus_message_append_array(). Le contenu du tableau de vecteurs d'E/S iov est utilisé comme contenu du tableau. La taille totale de la charge utile de iov (la somme des champs iov_len) doit être un multiple de la taille du type type. L'argument iov doit pointer vers n structures de vecteur d'E/S. Chaque structure peut avoir le champ iov_base défini, auquel cas la mémoire pointée sera copiée dans le message, ou non défini (mis à zéro), auquel cas un bloc de zéros d'une longueur de iov_len octets sera inséré. La mémoire pointée par iov peut être modifiée après cet appel.

La fonction sd_bus_message_append_array_space() ajoute de l'espace pour un tableau d'un type trivial au message m. Elle se comporte comme sd_bus_message_append_array(), mais au lieu de copier les éléments dans le message, elle renvoie un pointeur vers la zone de destination à l'appelant dans le pointeur p. L'appelant doit ensuite écrire le contenu du tableau dans cette mémoire. Les modifications de la mémoire pointée ne doivent avoir lieu que jusqu'à la prochaine opération sur le message du bus invoquée. Plus important encore, la mémoire ne doit plus être modifiée lorsqu'un autre champ a été ajouté au message ou que le message a été scellé.

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ils renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre spécifié est invalide.

-EPERM

Le message a été scellé.

-ESTALE

Le message est dans un état invalide.

-ENXIO

Le message ne peut pas être ajouté.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de ne faire des appels à setenv() que depuis une phase précoce du programme lorsqu'aucun autre fil d'exécution n'a été démarré.

NAME

sd_bus_message_append_array_memfd - Append an array of memfd file descriptors to a D-Bus message

SYNOPSIS


#include <systemd/sd-bus.h>

int sd_bus_message_append_array_memfd(sd_bus_message *m, const char *type, int32_t *fds, size_t n_fds);

DESCRIPTION

Appends an array of memfd file descriptors to the D-Bus message m. The elements of the array are expected to be of D-Bus type type, which must be one of the integer types (e.g. "i", "u", "x", "t") or the character type "c". The array consists of n_fds elements, passed in the array fds. The file descriptors themselves are copied into the message, and they may be duplicated or transferred to the receiving process.

The type parameter specifies the D-Bus type of the elements in the array. It must be a string representing a valid D-Bus integer or character type. For example, "i" for a 32-bit signed integer, "u" for a 32-bit unsigned integer, "x" for a 64-bit signed integer, "t" for a 64-bit unsigned integer, or "c" for a signed 8-bit integer.

The fds parameter is a pointer to an array of int32_t values, where each value represents a file descriptor. The size of this array is given by n_fds.

This function is typically used for sending file descriptors across D-Bus, for example, when using the memfd_create(2) system call to create anonymous file descriptors that can be passed to other processes.

RETURN VALUE

On success, returns 0 or a positive integer. On failure, returns a negative errno value.

ERRORS

-EINVAL
The message m is invalid, the type is invalid, or fds is NULL.
-ENOMEM
Memory allocation failed.
-EBADF
An invalid file descriptor was passed in fds.
-EPIPE
The connection to the bus is closed.
-EAGAIN
The operation would block.

NOTES

This function internally uses memfd_create() to create new file descriptors that are appended to the message. The actual file descriptors passed in fds are copied into the message. The receiving process will get copies of these file descriptors.

SEE ALSO

sd_bus_message_append_array(3), sd_bus_message_append_basic(3), sd_bus_message_new(3), memfd_create(2)

NOTES

The type parameter must correspond to the actual type of the file descriptors being passed. For example, if you are passing an array of int32_t, the type should be "i".
