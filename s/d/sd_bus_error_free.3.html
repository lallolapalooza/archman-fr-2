DESCRIPTION

La structure sd_bus_error contient des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles pour les noms d'erreurs décrites dans la spécification D-Bus, sous-section Noms D-Bus Valides[1]. Un certain nombre de noms d'erreurs courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques supplémentaires peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir ses deux champs initialisés à NULL et signifie l'absence d'erreur, c'est-à-dire le succès. Attribuez SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque cela n'est plus nécessaire, les ressources détenues par la structure sd_bus_error doivent être libérées avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur aux chaînes nom et message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer à nouveau le contenu lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données qu'elle contient avec sd_bus_error_free().

sd_bus_error_set() retournera une valeur de type errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, on suppose qu'aucune erreur ne s'est produite et 0 est retourné. Si name est non nul, une valeur négative est toujours retournée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est toujours converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs équivalents errno bien connus, et les autres en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreurs bien connus. Des mappages d'erreurs supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé commodément dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera retourné.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et des arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne et doivent donc rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition de structures d'erreur. Étant donné que cet appel n'alloue pas de mémoire, il n'échouera pas avec un manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() retournera immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur de style errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Les noms d'erreurs D-Bus bien connus seront utilisés pour name si applicable, sinon un nom de l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si l'erreur spécifiée error est non nulle, l'appel retourne toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place et -ENOMEM est retourné.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et des arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de style errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera retourné.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur auparavant. Sinon, il retournera immédiatement. Si les chaînes dans e ont été définies à l'aide de sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire fraîchement initialisé avec NULL ou réinitialisé à l'aide de sd_bus_error_free().

sd_bus_error_copy() retourne généralement 0 ou une valeur négative de style errno basée sur le paramètre d'entrée e: 0 s'il était non défini et un entier négatif s'il était défini à une erreur, de manière similaire à sd_bus_error_set(). DESCRIPTION

La structure sd_bus_error est utilisée pour renvoyer des erreurs de manière cohérente via l'API sd-bus(3). Elle contient un nom d'erreur (une chaîne de caractères) et un message d'erreur (une autre chaîne de caractères).

Les fonctions suivantes peuvent être utilisées pour définir des erreurs :

sd_bus_error_set() initialise la structure d'erreur e avec le nom d'erreur et le message spécifiés. Si e est déjà défini, un code d'erreur -EINVAL est renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais permettent de formater le message d'erreur à l'aide d'une chaîne de format et d'arguments de liste de variable (respectivement `...' et `va_list'). Si l'allocation de mémoire pour le message échoue, -ENOMEM est renvoyé.

sd_bus_error_set_const() est identique à sd_bus_error_set(), mais elle ne prend aucune référence sur le message fourni. Le message doit rester valide jusqu'à ce que l'erreur soit effacée ou copiée. Elle renvoie toujours 0 en cas de succès.

sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() sont similaires à sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_setfv() respectivement, mais elles permettent de définir le champ d'erreur sous-jacent à partir d'un entier errno. Le nom d'erreur est automatiquement dérivé de l'entier errno. Notez que ces fonctions peuvent renvoyer -ENOMEM si l'allocation de mémoire échoue.

sd_bus_error_copy() copie une structure d'erreur de src vers dst. Si dst est déjà défini, un code d'erreur -EINVAL est renvoyé. Si l'allocation de mémoire pour le message échoue, -ENOMEM est renvoyé.

sd_bus_error_move() est similaire à sd_bus_error_copy(), mais elle déplace toute information d'erreur de e vers dst, réinitialisant le premier. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si e n'est pas défini, dst est initialisé à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est exécutée sur celui-ci et les ressources détenues par e sont libérées et réinitialisées. Renvoie une valeur d'erreur convertie, de type errno, non positive.

sd_bus_error_is_set() renverra une valeur non nulle si e n'est pas NULL et qu'une erreur a été définie, false sinon.

sd_bus_error_has_name() renverra une valeur non nulle si e n'est pas NULL et qu'une erreur portant le même nom name a été définie, false sinon.

sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est un wrapper macro autour de sd_bus_error_has_names_sentinel() qui ajoute automatiquement le terminateur NULL.

sd_bus_error_free() détruira les ressources détenues par e. Le paramètre lui-même ne sera pas désalloué, et doit être free(3) par l'appelant si nécessaire. La fonction peut également être appelée en toute sécurité sur des erreurs non définies (structures d'erreur avec les deux champs définis à NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après avoir libéré les données, de sorte que tous les champs soient définis à NULL. La structure peut être réutilisée par la suite.

REFERENCE OWNERSHIP

sd_bus_error n'est pas comptée en référence. Les utilisateurs doivent détruire les ressources qu'elle détient en appelant sd_bus_error_free(). Habituellement, les structures d'erreur sont allouées sur la pile ou passées en paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il appartient à l'appelant de free(3) la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

RETURN VALUE

Les fonctions sd_bus_error_set(), sd_bus_error_setf(), et sd_bus_error_set_const() renvoient toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur négative de type errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv(), renvoient 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur négative de type errno correspondant au paramètre error sinon. Si une erreur survient en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera renvoyée. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_get_errno() renvoie false lorsque e est NULL, et une valeur errno positive mappée depuis e->name sinon.

sd_bus_error_copy() et sd_bus_error_move() renvoient une valeur d'erreur négative convertie de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_is_set() renvoie une valeur non nulle lorsque e et le champ name ne sont pas NULL, zéro sinon.

sd_bus_error_has_name(), sd_bus_error_has_names(), et sd_bus_error_has_names_sentinel() renvoient une valeur non nulle lorsque e n'est pas NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Erreurs

La valeur de retour peut indiquer les problèmes suivants lors de l'appel de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lorsqu'une des fonctions de définition d'erreur a été appelée.

-ENOMEM

L'allocation de mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), et sd_bus_error_move() renverront une valeur négative convertie de style errno, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en valeur entière de style errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de style errno peut être renvoyée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, renvoyer le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et aussi propager la valeur errno
   * que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
