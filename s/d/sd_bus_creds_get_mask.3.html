SD_BUS_CREDS_NEW_FROM_PID(3) sd_bus_creds_new_from_pid SD_BUS_CREDS_NEW_FROM_PID(3)

NOM

sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Récupérer un objet d'informations d'identification pour le PID spécifié

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_creds_new_from_pid(pid_t pid, uint64_t creds_mask, sd_bus_creds **ret);

int sd_bus_creds_new_from_pidfd(int pidfd, uint64_t creds_mask, sd_bus_creds **ret);

uint64_t sd_bus_creds_get_mask(sd_bus_creds *c);

uint64_t sd_bus_creds_get_augmented_mask(sd_bus_creds *c);

sd_bus_creds *sd_bus_creds_ref(sd_bus_creds *c);

sd_bus_creds *sd_bus_creds_unref(sd_bus_creds *c);

void sd_bus_creds_unrefp(sd_bus_creds **c);

SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, SD_BUS_CREDS_PIDFD, SD_BUS_CREDS_AUGMENT, _SD_BUS_CREDS_ALL

DESCRIPTION

sd_bus_creds_new_from_pid() crée un nouvel objet d'informations d'identification et le remplit avec les informations sur le processus pid. Le pointeur vers cet objet sera stocké dans le pointeur ret. Notez que les objets d'informations d'identification peuvent également être créés et récupérés via sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) et sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() est identique à sd_bus_creds_new_from_pid(), mais prend un descripteur de fichier de PID plutôt qu'un PID numérique comme référence au processus. Voir pidfd_open(2).

Les informations qui seront stockées sont déterminées par creds_mask. Il peut contenir un sous-ensemble de constantes ORées SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, et SD_BUS_CREDS_PIDFD. Utilisez la valeur spéciale _SD_BUS_CREDS_ALL pour demander tous les champs pris en charge. La constante SD_BUS_CREDS_AUGMENT ne peut pas être ORée dans le masque pour les appels à sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd().

Les champs peuvent être récupérés à partir de l'objet d'informations d'identification à l'aide de sd_bus_creds_get_pid(3) et d'autres fonctions qui correspondent directement aux constantes énumérées ci-dessus.

Un masque des champs qui ont été effectivement récupérés avec succès peut être obtenu avec sd_bus_creds_get_mask(). Si l'objet d'informations d'identification a été créé avec sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce sera un sous-ensemble des champs demandés dans creds_mask.

Similaire à sd_bus_creds_get_mask(), la fonction sd_bus_creds_get_augmented_mask() retourne un masque binaire de constantes de champs. Le masque indique quels champs d'informations d'identification ont été récupérés de manière non atomique. Pour les objets d'informations d'identification créés via sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce masque sera identique au masque retourné par sd_bus_creds_get_mask(). Cependant, pour les objets d'informations d'identification récupérés via sd_bus_get_name_creds(), ce masque sera défini pour les champs d'informations d'identification qui n'ont pas pu être déterminés atomiquement au moment de la connexion du pair, et qui ont été ajoutés ultérieurement en lisant des données d'informations d'identification supplémentaires à partir de /proc/. De même, pour les objets d'informations d'identification récupérés via sd_bus_get_owner_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés atomiquement au moment de la création du bus, mais qui ont été augmentés. De même, pour les objets d'informations d'identification récupérés via sd_bus_message_get_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés atomiquement au moment de l'envoi du message, mais qui ont été augmentés. Le masque retourné par sd_bus_creds_get_augmented_mask() est toujours un sous-ensemble (ou identique) au masque retourné par sd_bus_creds_get_mask() pour le même objet. Cet appel retourne donc tous les champs d'informations d'identification disponibles dans l'objet d'informations d'identification, le dernier marquant le sous-ensemble de ceux qui ont été augmentés. Notez que les champs augmentés ne conviennent pas aux décisions d'autorisation, car ils peuvent être récupérés à différents moments, et sont donc sujets à des conditions de concurrence. Par conséquent, les champs augmentés ne doivent être utilisés qu'à des fins d'information.

sd_bus_creds_ref() crée une nouvelle référence à l'objet d'informations d'identification c. Cet objet ne sera pas détruit tant que sd_bus_creds_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, c ne peut plus être utilisé, donc les appels ultérieurs à sd_bus_creds_ref(c) ou sd_bus_creds_unref(c) sont illégaux.

sd_bus_creds_unref() détruit une référence à c.

sd_bus_creds_unrefp() est similaire à sd_bus_creds_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_creds. Cette fonction est utile en conjonction avec l'attribut de variable Clean-up[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_bus_creds_ref(), sd_bus_creds_unref() et sd_bus_creds_unrefp() n'exécutent aucune opération si l'objet d'informations d'identification de bus passé est NULL.

VALEUR DE RETOUR

En cas de succès, sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

sd_bus_creds_get_mask() retourne le masque des champs acquis avec succès.

sd_bus_creds_get_augmented_mask() retourne le masque des champs qui ont été augmentés à partir de données dans /proc/, et qui ne conviennent donc pas aux décisions d'autorisation.

sd_bus_creds_ref() retourne toujours l'argument.

sd_bus_creds_unref() retourne toujours NULL.

PROPRIÉTÉ DES RÉFÉRENCES

Les fonctions sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() créent un nouvel objet et l'appelant possède la référence unique. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_creds_unref(3).

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ESRCH

Le pid spécifié n'a pas pu être trouvé.

NAME

sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask — obtenir les privilèges d'un ensemble de crédits d'autobus

SYNOPSIS

#include <systemd/sd-bus.h>

uint64_t sd_bus_creds_get_mask(sd_bus_creds *creds);
uint64_t sd_bus_creds_get_augmented_mask(sd_bus_creds *creds);

DESCRIPTION

La fonction sd_bus_creds_get_mask renvoie un masque de privilèges (type uint64_t) basé sur les crédits d'autobus contenus dans creds. Le masque contient des bits définis pour les privilèges qui sont activés pour l'utilisateur ou le processus dont les crédits sont examinés. Les privilèges correspondants sont décrits dans sd_bus_creds_get_pid(3).

La fonction sd_bus_creds_get_augmented_mask est similaire, mais elle essaie également de vérifier les privilèges supplémentaires qui ne sont pas directement disponibles dans les crédits, par exemple en examinant les groupes dont fait partie l'utilisateur.

Les bits de masque de privilèges actuellement définis sont :

La valeur renvoyée est un masque de bits des privilèges disponibles.

RETURN VALUE

Les deux fonctions renvoient un masque de bits des privilèges disponibles. Les bits actuellement définis sont :

SD_BUS_CREDS_MASK_NONE
Aucun privilège n'est défini.
SD_BUS_CREDS_MASK_LOGIN_UID
Le privilège de lire l'UID du propriétaire de la connexion est activé.
SD_BUS_CREDS_MASK_LOGIN_GID
Le privilège de lire le GID du propriétaire de la connexion est activé.
SD_BUS_CREDS_MASK_LOGIN_USERNAME
Le privilège de lire le nom d'utilisateur du propriétaire de la connexion est activé.
SD_BUS_CREDS_MASK_LOGIN_GROUPNAME
Le privilège de lire le nom du groupe principal du propriétaire de la connexion est activé.
SD_BUS_CREDS_MASK_LOGIN_SECONDARY_GROUPNAMES
Le privilège de lire les noms des groupes secondaires du propriétaire de la connexion est activé.
SD_BUS_CREDS_MASK_PID
Le privilège de lire le PID du processus est activé.
SD_BUS_CREDS_MASK_EXEC_PID
Le privilège de lire le PID du processus d'exécution est activé.
SD_BUS_CREDS_MASK_COMM
Le privilège de lire le nom du processus d'exécution est activé.
SD_BUS_CREDS_MASK_CMDLINE
Le privilège de lire la ligne de commande complète du processus d'exécution est activé.
SD_BUS_CREDS_MASK_CONMON
Le privilège de vérifier si le processus est moniteur de conteneur est activé.
SD_BUS_CREDS_MASK_SELINUX_CONTEXT
Le privilège de lire le contexte SELinux du processus est activé.
SD_BUS_CREDS_MASK_APPARMOR_CONTEXT
Le privilège de lire le contexte AppArmor du processus est activé.
SD_BUS_CREDS_MASK_ANDROID_CONTEXT
Le privilège de lire le contexte Android du processus est activé.
SD_BUS_CREDS_MASK_USER_UNIT
Le privilège de lire l'unité utilisateur associée au processus est activé.
SD_BUS_CREDS_MASK_SYSTEM_UNIT
Le privilège de lire l'unité système associée au processus est activé.
SD_BUS_CREDS_MASK_SCOPE
Le privilège de lire la portée (scope) du processus est activé.
SD_BUS_CREDS_MASK_SESSION
Le privilège de lire la session du processus est activé.
SD_BUS_CREDS_MASK_SERVICE
Le privilège de lire le nom du service associé au processus est activé.
SD_BUS_CREDS_MASK_USER_SLICE
Le privilège de lire la tranche utilisateur associée au processus est activé.
SD_BUS_CREDS_MASK_SYSTEM_SLICE
Le privilège de lire la tranche système associée au processus est activé.
SD_BUS_CREDS_MASK_PERMISSIONS
Le privilège de lire les permissions du processus est activé.
SD_BUS_CREDS_MASK_UNIQUE_NAME
Le privilège de lire le nom unique du processus est activé.
SD_BUS_CREDS_MASK_WELL_KNOWN_NAME
Le privilège de lire le nom bien connu du processus est activé.

En cas d'échec, un code d'erreur négatif est renvoyé.

ERRORS

-EINVAL
Le paramètre spécifié est invalide (NULL dans le cas des paramètres de sortie).
-ENOMEM
L'allocation de mémoire a échoué.
-EOPNOTSUPP
L'un des champs demandés est inconnu du système local.

REFERENCE OWNERSHIP

Les crédits sont la propriété du processus appelant et doivent être explicitement libérés à l'aide de sd_bus_creds_unref(3). Pour la gestion des pointeurs de crédits (y compris la gestion de la propriété via sd_bus_creds_unrefp(3)), voir sd_bus_creds_ref(3).

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
