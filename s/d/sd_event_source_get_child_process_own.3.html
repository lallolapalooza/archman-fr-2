DESCRIPTION

sd_event_add_child() ajoute une nouvelle source d'événement de changement d'état de processus fils à une boucle d'événements. L'objet de boucle d'événements est spécifié dans le paramètre event, l'objet de source d'événement est retourné dans le paramètre source. Le paramètre pid spécifie le PID du processus à surveiller, qui doit être un processus fils direct du processus appelant. Le paramètre options détermine quels changements d'état seront surveillés. Il doit contenir un masque OR-é de WEXITED (surveiller la terminaison du processus fils), WSTOPPED (surveiller l'arrêt du processus fils par un signal), et WCONTINUED (surveiller la reprise du processus fils par un signal). Voir waitid(2) pour plus d'informations.

Le handler doit être une fonction à appeler lorsque le processus change d'état ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure siginfo_t contenant des informations sur l'événement du processus fils. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul gestionnaire peut être installé pour un processus fils spécifique. Le gestionnaire est activé pour un seul événement (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction gestionnaire renvoie un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, ou elle entraînera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont supprimées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si une référence est toujours conservée, envisagez de définir la source d'événement sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Le signal SIGCHLD doit être bloqué dans tous les threads avant que cette fonction ne soit appelée (en utilisant sigprocmask(2) ou pthread_sigmask(3)).

Si le deuxième paramètre de sd_event_add_child() est passé comme NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Notez que la fonction handler est appelée à un moment où le processus fils n'a pas encore été collecté (et est donc encore exposé comme un processus zombie par le noyau). Cependant, le fils sera collecté automatiquement après le retour de la fonction. Les processus fils pour lesquels aucune source d'événement de changement d'état de processus fils n'est installée ne seront pas collectés par l'implémentation de la boucle d'événements.

Si le paramètre handler de sd_event_add_child() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Si une source d'événement de changement d'état de processus fils et une source d'événement de signal SIGCHLD sont installées dans la même boucle d'événements, les priorités configurées des sources d'événements décident quelle source d'événement est traitée en premier. Si le gestionnaire de signal est traité en premier, il doit laisser les processus fils pour lesquels des sources d'événements de changement d'état de processus fils sont installées non collectés.

sd_event_add_child_pidfd() est similaire à sd_event_add_child() mais prend un descripteur de fichier référençant le processus ("pidfd") au lieu du PID numérique. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2) et les appels connexes. Le descripteur de fichier passé n'est pas fermé lorsque la source d'événement est libérée à nouveau, à moins que sd_event_source_set_child_pidfd_own() ne soit utilisé pour activer ce comportement. Notez que, quelle que soit la fonction utilisée pour allouer une source d'événement (sd_event_add_child() ou sd_event_add_child_pidfd()), le processus surveillé doit être un processus fils direct du processus appelant. De plus, dans les deux cas, SIGCHLD doit être bloqué dans le processus appelant.

sd_event_source_get_child_pid() récupère le PID configuré d'une source d'événement de changement d'état de processus fils créée précédemment avec sd_event_add_child(). Elle prend l'objet source d'événement comme paramètre source et un pointeur vers une variable pid_t pour retourner l'identifiant du processus.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier référençant le processus surveillé ("pidfd"). La boucle d'événements utilise en interne des pidfds pour surveiller les processus fils, que les sources d'événements individuelles soient allouées via sd_event_add_child() ou sd_event_add_child_pidfd(). Si le dernier appel a été utilisé pour allouer la source d'événement, cette fonction retourne le descripteur de fichier d'origine utilisé pour l'allocation. Cet appel prend l'objet source d'événement comme paramètre source et retourne le descripteur de fichier numérique.

sd_event_source_get_child_pidfd_own() peut être utilisé pour interroger si le pidfd que la source d'événement encapsule doit être fermé lorsque la source d'événement est libérée. Cette fonction retourne zéro si le pidfd doit rester ouvert, et une valeur positive s'il doit être fermé automatiquement. Par défaut, ce paramètre est activé si la source d'événement a été allouée via sd_event_add_child() et désactivé si elle a été allouée via sd_event_add_child_pidfd(). La fonction sd_event_source_set_child_pidfd_own() peut être utilisée pour changer le réglage et prend un paramètre booléen avec le nouveau réglage.

sd_event_source_get_child_process_own() peut être utilisé pour interroger si le processus que la source d'événement surveille doit être tué (avec SIGKILL) et collecté lorsque la source d'événement est libérée. Cette fonction retourne zéro si le processus doit rester en cours d'exécution, et une valeur positive s'il doit être tué et collecté automatiquement. Par défaut, ce réglage est désactivé. NAME

sd_event_source_get_child_process_own, sd_event_source_set_child_process_own, sd_event_source_get_child_pidfd_own, sd_event_source_set_child_pidfd_own, sd_event_source_get_child_pidfd - get/set child process watcher status

SYNOPSIS

#include <systemd/sd-event.h>
bool sd_event_source_get_child_process_own(sd_event_source *source);
int sd_event_source_set_child_process_own(sd_event_source *source, bool own);
bool sd_event_source_get_child_pidfd_own(sd_event_source *source);
int sd_event_source_set_child_pidfd_own(sd_event_source *source, bool own);
int sd_event_source_get_child_pidfd(sd_event_source *source, pid_t *pid, int *pidfd);
int sd_event_source_send_child_signal(sd_event_source *source, int sig, const siginfo_t *info, uint32_t flags);

DESCRIPTION

These functions may be used to control and query whether the event loop instance owns the child process event source. By default, the event loop does not own the child process. Setting sd_event_source_set_child_process_own(3) to true makes the event loop instance responsible for cleaning up the child process resources, like calling waitpid(2). If the event loop instance owns the child process, it will automatically call waitpid(2) when the child process terminates. This is generally the desired behaviour and simplifies resource management.

Similarly, sd_event_source_set_child_pidfd_own(3) and sd_event_source_get_child_pidfd_own(3) control whether the event loop owns the pidfd_open(2) file descriptor associated with the child process.

sd_event_source_get_child_pidfd(3) retrieves the child's PID and PIDFD. The PIDFD is a file descriptor that refers to the child process, used with pidfd_send_signal(2).

The sd_event_source_send_child_signal(3) function may be used to send a signal to the watched process via pidfd_send_signal(2). The parameters match those of the underlying system call, except that the siginfo_t is never modified and is thus declared constant. For the underlying system call, the flags parameter must currently be zero.

Note that currently if the calling process is terminated abnormally the watched process might survive even though the event source ceases to exist. This behaviour might change eventually.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EDOM

The passed event source is not a child process event source.

-EBADFD

The passed PIDFD is invalid.

-ENOTSUP

The operation is not supported on this system.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd namespace pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

EXAMPLE

Example 1. Manage child process ownership

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <unistd.h>
#include <signal.h>
#include <systemd/sd-event.h>

static int child_event_handler(sd_event_source *s, int pid, uint32_t revents, void *userdata) {
    printf("Child process %d terminated.\n", pid);
    return sd_event_exit(userdata, EXIT_SUCCESS); // Exit event loop
}

int main(int argc, char **argv) {
    pid_t pid;
    int r;
    sd_event *e = NULL;
    sd_event_source *child_source = NULL;

    // Create default event loop
    r = sd_event_default(&e);
    if (r < 0) {
        fprintf(stderr, "Failed to create event loop: %s\n", strerror(-r));
        return -r;
    }

    // Fork a child process
    pid = fork();
    if (pid < 0) {
        fprintf(stderr, "Failed to fork: %s\n", strerror(-errno));
        sd_event_unref(e);
        return -errno;
    }

    if (pid == 0) {
        // Child process: do some work and exit
        printf("Child process started with PID %d.\n", getpid());
        sleep(2);
        printf("Child process exiting.\n");
        return EXIT_SUCCESS;
    } else {
        // Parent process
        printf("Parent process monitoring child PID %d.\n", pid);

        // Block SIGCHLD to ensure atomic operations with waitpid/pidfd
        sigset_t ss;
        sigemptyset(&ss);
        sigaddset(&ss, SIGCHLD);
        sigprocmask(SIG_BLOCK, &ss, NULL);

        // Add child event source. Does not take ownership by default.
        r = sd_event_add_child(e, &child_source, pid, WEXITED, child_event_handler, e);
        if (r < 0) {
            fprintf(stderr, "Failed to add child event source: %s\n", strerror(-r));
            sd_event_unref(e);
            return -r;
        }

        // Explicitly set ownership of the child process
        r = sd_event_source_set_child_process_own(child_source, true);
        if (r < 0) {
            fprintf(stderr, "Failed to set child process ownership: %s\n", strerror(-r));
            sd_event_unref(e);
            return -r;
        }

        // Ensure SIGCHLD is unblocked after setup if not needed by other threads
        sigprocmask(SIG_UNBLOCK, &ss, NULL);

        // Run the event loop
        printf("Entering event loop...\n");
        r = sd_event_loop(e);
        printf("Event loop finished with result: %d\n", r);

        sd_event_unref(e);
    }

    return 0;
}
