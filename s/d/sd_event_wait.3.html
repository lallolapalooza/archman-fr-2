SD_EVENT_WAIT(3) sd_event_wait SD_EVENT_WAIT(3)

NOM

sd_event_wait, sd_event_prepare, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Opérations de bas niveau de la boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_state(sd_event *event);

int sd_event_get_iteration(sd_event *event, uint64_t *ret);

DESCRIPTION

Les fonctions de bas niveau sd_event_prepare(), sd_event_wait() et sd_event_dispatch() peuvent être utilisées pour exécuter des phases spécifiques d'une boucle d'événements. Voir sd_event_run(3) et sd_event_loop(3) pour des fonctions de plus haut niveau qui exécutent des itérations individuelles mais complètes d'une boucle d'événements ou qui l'exécutent en continu.

sd_event_prepare() vérifie les événements en attente et active les minuteurs nécessaires. Si des événements sont prêts à être traités ("en attente"), elle renvoie une valeur positive non nulle, et l'appelant doit traiter ces événements avec sd_event_dispatch().

sd_event_dispatch() distribue la source d'événement de plus haute priorité qui a un événement en attente. En cas de succès, sd_event_dispatch() renvoie soit zéro, ce qui indique qu'aucune autre source d'événement ne peut être distribuée et que la sortie de la boucle d'événements a été demandée via sd_event_exit(3) ; soit une valeur positive non nulle, ce qui signifie qu'une source d'événement a été distribuée et que la boucle est revenue à son état initial, et que l'appelant doit initier la prochaine itération de la boucle d'événements en invoquant à nouveau sd_event_prepare().

Dans le cas où sd_event_prepare() a renvoyé zéro, sd_event_wait() doit être appelée pour attendre d'autres événements ou un délai d'attente. Si des événements sont prêts à être traités, elle renvoie une valeur positive non nulle, et les événements doivent être distribués avec sd_event_dispatch(). Sinon, la boucle d'événements est revenue à son état initial et la prochaine itération de la boucle d'événements doit être initiée en invoquant à nouveau sd_event_prepare().

sd_event_get_state() peut être utilisée pour déterminer l'état dans lequel se trouve actuellement la boucle d'événements. Elle renvoie l'un des états décrits ci-dessous.

sd_event_get_iteration() peut être utilisée pour déterminer l'itération actuelle de la boucle d'événements. Elle renvoie un entier non signé de 64 bits contenant un compteur qui augmente de manière monotone à chaque itération de la boucle d'événements, en commençant par 0. Le compteur est augmenté au moment de l'invocation de sd_event_prepare().

Les cinq fonctions prennent, comme premier argument, l'objet de boucle d'événements event qui a été créé avec sd_event_new(). Le délai d'attente pour sd_event_wait() est spécifié en usec en microsecondes. (uint64_t) -1 peut être utilisé pour spécifier un délai d'attente infini.

MACHINE D'ÉTAT

La boucle d'événements connaît les états suivants, qui peuvent être interrogés avec sd_event_get_state().

SD_EVENT_INITIAL

L'état initial dans lequel se trouve la boucle d'événements, avant chaque itération de la boucle d'événements. Utilisez sd_event_prepare() pour faire passer la boucle d'événements aux états SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_PREPARING

Une source d'événement est en cours de préparation, c'est-à-dire que le gestionnaire de préparation est en cours d'exécution, tel que défini avec sd_event_source_set_prepare(3). Cet état n'est vu que dans le gestionnaire de préparation d'événements qui est invoqué à partir de l'appel sd_event_prepare() et est immédiatement suivi par SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_ARMED

sd_event_prepare() a été appelé et aucune source d'événement n'était prête à être distribuée. Utilisez sd_event_wait() pour attendre de nouveaux événements et passer à l'état SD_EVENT_PENDING ou revenir à l'état SD_EVENT_INITIAL.

Ajouté dans la version 229.

SD_EVENT_PENDING

sd_event_prepare() ou sd_event_wait() ont été appelés et il y avait des sources d'événements avec des événements en attente. Utilisez sd_event_dispatch() pour distribuer la source d'événement de plus haute priorité et revenir à l'état SD_EVENT_INITIAL, ou à SD_EVENT_FINISHED.

Ajouté dans la version 229.

SD_EVENT_RUNNING

Une source d'événement régulière est en cours de distribution. Cet état n'est vu que dans le gestionnaire de source d'événement qui est invoqué depuis l'appel sd_event_dispatch(), et est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire de source d'événement retourne. Notez que lors de la distribution des sources d'événements de sortie, l'état SD_EVENT_EXITING est vu à la place.

Ajouté dans la version 229.

SD_EVENT_EXITING

Similaire à SD_EVENT_RUNNING mais c'est l'état en vigueur lors de la distribution des sources d'événements de sortie. Il est suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire d'événements retourne.

Ajouté dans la version 229.

SD_EVENT_FINISHED

La boucle d'événements s'est terminée. Toutes les sources d'événements de sortie ont été exécutées. Si la boucle d'événements est dans cet état, elle ne sert plus à rien et doit être libérée.

Ajouté dans la version 229.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient 0 ou un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno. Dans le cas de sd_event_prepare() et sd_event_wait(), un code de retour positif non nul indique que des événements sont prêts à être traités et zéro indique qu'aucun événement n'est prêt. Dans le cas de sd_event_dispatch(), un code de retour positif non nul indique que la boucle d'événements est revenue à son état initial et zéro indique que la boucle d'événements s'est terminée. sd_event_get_state() renvoie un état positif ou nul en cas de succès.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre event est invalide ou NULL.

-EBUSY

L'objet de boucle d'événements n'est pas dans le bon état.

-ESTALE

La boucle d'événements est déjà terminée.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a encore été démarré.
