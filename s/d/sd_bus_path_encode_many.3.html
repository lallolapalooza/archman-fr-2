NOM

sd_bus_path_encode, sd_bus_path_encode_many, sd_bus_path_decode, sd_bus_path_decode_many - Convertir un identifiant externe en chemin d'objet et vice-versa

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_path_encode(const char *prefix, const char *external_id, char **ret_path);

int sd_bus_path_encode_many(char **out, const char *path_template, ...);

int sd_bus_path_decode(const char *path, const char *prefix, char **ret_external_id);

int sd_bus_path_decode_many(const char *path, const char *path_template, ...);

DESCRIPTION

sd_bus_path_encode() et sd_bus_path_decode() convertissent des chaînes d'identifiants externes en chemins d'objets et vice-versa. Ces fonctions sont utiles pour mapper des identifiants de chaîne spécifiques à une application, de quelque nature qu'ils soient, en chemins d'objets bus d'une manière simple, réversible et sûre.

sd_bus_path_encode() prend un préfixe de chemin bus et une chaîne d'identifiant externe comme arguments, plus un emplacement pour stocker la chaîne de chemin bus retournée. Le préfixe de chemin bus doit être un chemin bus valide, commençant par une barre oblique "/", et ne se terminant pas par une. L'identifiant externe peut être dans n'importe quel format, peut être une chaîne vide, et n'a aucune restriction sur le jeu de caractères — cependant, il doit toujours être terminé par NUL. La chaîne retournée sera la concaténation du préfixe de chemin bus plus une version échappée de la chaîne d'identifiant externe. Cette opération peut être inversée avec sd_bus_path_decode(). Il est recommandé de n'utiliser que des identifiants externes qui nécessitent généralement peu d'échappement pour être transformés en identifiants de chemin bus valides (par exemple, en s'en tenant à un jeu de caractères ASCII 7 bits), afin de garantir que le chemin bus résultant reste court et facilement traitable.

sd_bus_path_decode() inverse l'opération de sd_bus_path_encode() et régénère ainsi une chaîne d'identifiant externe à partir d'un chemin bus. Elle prend un chemin bus et une chaîne de préfixe, plus un emplacement pour stocker la chaîne d'identifiant externe retournée. Si le chemin bus ne commence pas par le préfixe spécifié, 0 est retourné et la chaîne retournée est définie à NULL. Sinon, la chaîne suivant le préfixe est déséchappée et retournée dans la chaîne d'identifiant externe.

L'échappement utilisé remplacera tous les caractères invalides dans un chemin d'objet bus par "_", suivi d'une valeur hexadécimale. À titre de cas spécial, la chaîne vide sera remplacée par un simple "_".

sd_bus_path_encode_many() fonctionne comme son homologue sd_bus_path_encode(), mais prend un modèle de chemin comme argument et encode plusieurs étiquettes selon ses directives intégrées. Pour chaque caractère "%" trouvé dans le modèle, l'appelant doit fournir une chaîne via les arguments varargs, qui sera encodée et intégrée à la position du caractère "%". Tout autre caractère dans le modèle est copié tel quel dans le chemin encodé.

sd_bus_path_decode_many() fait l'inverse de sd_bus_path_encode_many(). Il décode le chemin d'objet passé selon le modèle de chemin donné. Pour chaque caractère "%" dans le modèle, l'appelant doit fournir un stockage de sortie ("char **") via les arguments varargs. L'étiquette décodée y sera stockée. Chaque caractère "%" ne correspondra qu'à l'étiquette actuelle. Il ne correspondra jamais à plusieurs étiquettes. De plus, une seule directive est autorisée par étiquette. Si NULL est passé comme stockage de sortie, l'étiquette est vérifiée mais n'est pas retournée à l'appelant.

VALEUR DE RETOUR

En cas de succès, sd_bus_path_encode() retourne une valeur positive ou 0, et un chemin bus valide dans l'argument de retour. En cas de succès, sd_bus_path_decode() retourne une valeur positive si le préfixe a correspondu, ou 0 s'il n'a pas correspondu. Si le préfixe a correspondu, l'identifiant externe est retourné dans le paramètre de retour. S'il n'a pas correspondu, NULL est retourné dans le paramètre de retour. En cas d'échec, un numéro d'erreur négatif de type errno est retourné par l'une ou l'autre fonction. Les chaînes retournées doivent être libérées par l'appelant avec free(3).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_path_encode() et sd_bus_path_decode() ont été ajoutées dans la version 211.

sd_bus_path_encode_many() et sd_bus_path_decode_many() ont été ajoutées dans la version 227.
