SD_EVENT_SET_SIGNAL_EXIT(3) sd_event_set_signal_exit SD_EVENT_SET_SIGNAL_EXIT(3)

NOM

sd_event_set_signal_exit - Quitter automatiquement la boucle d'événements sur SIGINT et SIGTERM

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_set_signal_exit(sd_event *event, int b);

DESCRIPTION

sd_event_set_signal_exit() peut être utilisé pour s'assurer que la boucle d'événements se termine une fois qu'un signal SIGINT ou SIGTERM est reçu. Il s'agit d'un wrapper de commodité pour les invocations de sd_event_add_signal(3) pour les deux signaux. Les deux signaux sont automatiquement ajoutés au masque de signaux du thread appelant (si un programme est multi-threadé, il convient de faire attention à invoquer cette fonction avant le démarrage du premier thread ou à masquer manuellement les deux signaux au niveau du processus au préalable).

Si le paramètre b est spécifié comme vrai, la boucle d'événements se terminera lors de la réception de SIGINT et SIGTERM. Si spécifié comme faux, elle ne le fera plus. Lorsque cette fonctionnalité est désactivée, le masque de signaux du thread appelant est restauré pour correspondre à l'état précédent son activation, pour les deux signaux. Par défaut, les deux signaux ne sont pas gérés par la boucle d'événements, et la gestion par défaut des signaux par Linux est en vigueur.

Il est d'usage pour les programmes UNIX de se terminer lors de la réception de l'un de ces deux signaux, il est donc généralement conseillé d'activer cette fonctionnalité pour la boucle d'événements principale d'un programme.

VALEUR DE RETOUR

sd_event_set_signal_exit() retourne une valeur entière positive non nulle lorsque le paramètre a été modifié avec succès. Elle retourne zéro lorsque le paramètre spécifié était déjà en vigueur. En cas d'échec, elle retourne un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

Ajouté dans la version 252.

-EINVAL

L'objet de boucle d'événements passé était invalide.

Ajouté dans la version 252.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_set_signal_exit() a été ajouté dans la version 252.
