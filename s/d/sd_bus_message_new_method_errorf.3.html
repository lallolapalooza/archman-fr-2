sd_bus_message_new_method_errorf(3)

SD_BUS_MESSAGE_NEW_METHOD_ERROR(3) sd_bus_message_new_method_error SD_BUS_MESSAGE_NEW_METHOD_ERROR(3)

NOM

sd_bus_message_new_method_error, sd_bus_message_new_method_errorf, sd_bus_message_new_method_errno, sd_bus_message_new_method_errnof - Créer une réponse d'erreur à un appel de méthode

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_error(sd_bus_message *call, sd_bus_message **m, const sd_bus_error *e);

int sd_bus_message_new_method_errorf(sd_bus_message *call, sd_bus_message **m, const char *name, const char *format, ...);

int sd_bus_message_new_method_errno(sd_bus_message *call, sd_bus_message **m, int error, const sd_bus_error *p);

int sd_bus_message_new_method_errnof(sd_bus_message *call, sd_bus_message **m, int error, const char *format, ...);

DESCRIPTION

La fonction sd_bus_message_new_method_error() crée un nouveau message de bus qui est une réponse d'erreur au message call, et le retourne dans le paramètre de sortie m. Les informations d'erreur de l'erreur e sont ajoutées : le champ name de e est utilisé comme identifiant d'erreur dans l'en-tête de la réponse (par exemple un nom d'erreur tel que "org.freedesktop.DBus.Error.NotSupported" ou le symbole équivalent SD_BUS_ERROR_NOT_SUPPORTED), et le champ message est défini comme la chaîne de message d'erreur lisible par l'homme si elle est présente. L'erreur e doit avoir le champ name défini, voir sd_bus_error_is_set(3).

La fonction sd_bus_message_new_method_errorf() crée une réponse d'erreur de manière similaire à sd_bus_message_new_method_error(), mais au lieu d'une structure d'erreur prête, elle prend une chaîne identifiant l'erreur name, plus une chaîne de formatage printf(3) format et les arguments correspondants. Une réponse d'erreur est envoyée avec l'identifiant d'erreur name et la chaîne formatée comme message. name et format ne doivent pas être NULL.

La fonction sd_bus_message_new_method_errno() crée une réponse d'erreur de manière similaire à sd_bus_message_new_method_error(), mais en plus de la structure d'erreur p, elle prend une valeur d'erreur errno(3) dans le paramètre error. Si l'erreur p est définie (voir sd_bus_error_is_set(3)), elle est utilisée dans la réponse. Sinon, error est traduit en un identifiant d'erreur et utilisé pour créer une nouvelle structure d'erreur en utilisant sd_bus_error_set_errno(3) et celle-ci est utilisée dans la réponse. (Si error est zéro, aucune erreur n'est réellement définie, et une réponse d'erreur sans information est créée.)

La fonction sd_bus_message_new_method_errnof() crée une réponse d'erreur de manière similaire à sd_bus_message_new_method_error(). Elle prend une valeur d'erreur errno(3) dans le paramètre error, plus une chaîne de formatage printf(3) format et les arguments correspondants. "%m" peut être utilisé dans la chaîne de format pour faire référence à la chaîne d'erreur correspondant au code errno spécifié. Le message d'erreur est initialisé en utilisant l'identifiant d'erreur généré à partir de error et la chaîne formatée. (Si error est zéro, aucune erreur n'est réellement définie, et une réponse d'erreur sans information est créée.)

VALEUR DE RETOUR

Ces fonctions retournent 0 si la réponse d'erreur a été créée avec succès, et un code d'erreur négatif de style errno sinon.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le message d'appel call ou le paramètre de sortie m sont NULL.

Le message call n'est pas un message d'appel de méthode.

Le paramètre d'erreur e pour sd_bus_message_new_method_error() n'est pas défini, voir sd_bus_error_is_set(3).

-EPERM

Le message call a été scellé.

-ENOTCONN

Le bus auquel le message call est attaché n'est pas connecté.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme quand aucun autre thread n'a été démarré.
