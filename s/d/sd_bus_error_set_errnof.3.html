DESCRIPTION

La structure sd_bus_error transporte des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles pour les noms d'erreur décrites dans la spécification D-Bus, sous-section Noms D-Bus valides[1]. Un certain nombre de noms d'erreurs courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques au domaine peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir ses deux champs initialisés à NULL, et signifie l'absence d'erreur, c'est-à-dire le succès. Assigner SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsqu'ils ne sont plus nécessaires, les ressources détenues par la structure sd_bus_error doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de nom et de message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données stockées en elle avec sd_bus_error_free().

sd_bus_error_set() renvoie une valeur de type errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, il est supposé qu'aucune erreur ne s'est produite et 0 est renvoyé. Si name n'est pas nul, une valeur négative est toujours renvoyée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est toujours converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs homologues errno bien connus, et les autres en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreurs bien connus. Des correspondances d'erreurs supplémentaires peuvent être définies avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçue pour être utilisée commodément dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer s'il n'y a pas de mémoire à allouer pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et les arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition de structures d'erreur. Puisque cet appel n'alloue pas de mémoire, il n'échouera pas avec une condition de manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() renverra immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur de style errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Les noms d'erreurs D-Bus bien connus seront utilisés pour name si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est implicitement utilisée. Si l'erreur spécifiée error est non nulle, l'appel renvoie toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est renvoyé.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et les arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de style errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera renvoyé.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur avant. Sinon, il retournera immédiatement. Si les chaînes dans e ont été définies en utilisant sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit initialisé à NULL, soit réinitialisé en utilisant sd_bus_error_free().

sd_bus_error_copy() renvoie généralement 0 ou une valeur négative de style errno basée sur le paramètre d'entrée e : 0 si elle était non définie et un entier négatif si elle était définie à une certaine erreur, de manière similaire à sd_bus_error_set(). Elle peut cependant aussi renvoyer une erreur générée en interne.

sd_bus_error_move() est similaire à sd_bus_error_copy(), mais au lieu de copier les champs name et message de e vers dst, elle les déplace. Après cet appel, e sera dans un état non défini. Ceci est utile pour éviter la copie de chaînes lors de la transmission de structures d'erreur, par exemple dans des opérations de retour.

sd_bus_error_is_set() renvoie vrai si la structure d'erreur e contient une erreur valide (c'est-à-dire que e->name n'est pas NULL). Renvoie faux sinon.

sd_bus_error_has_name() renvoie vrai si la structure d'erreur e est définie et si son champ name correspond à la chaîne fournie name. Renvoie faux sinon.

sd_bus_error_has_names_sentinel() et sd_bus_error_has_names() sont des fonctions d'aide pour vérifier si le champ name d'une structure d'erreur correspond à l'un des noms fournis. La liste des noms se termine par NULL. Utilisez le macro sd_bus_error_has_names() pour une utilisation plus pratique.

Les fonctions ci-dessus renvoient des codes de retour négatifs en cas d'échec, et 0 en cas de succès. Les erreurs spécifiques sont renvoyées comme une valeur errno. Voir errno(3).

VALEURS TYPE ERRNO

Les valeurs renvoyées par ces fonctions sont destinées à être compatibles avec errno. Par exemple, en cas de succès, 0 est renvoyé, et en cas d'échec, une valeur négative est renvoyée. Les valeurs spécifiques possibles sont :

0
Succès.
-ENOMEM
Manque de mémoire.
-EINVAL
Argument invalide.

Lorsqu'un nom d'erreur D-Bus est converti en une valeur errno, les noms bien connus sont mappés à des codes errno spécifiques. Par exemple, l'erreur D-Bus "org.freedesktop.DBus.Error.ServiceUnknown" est mappée à ENOENT. Les autres erreurs sont généralement mappées à EIO. Voir sd-bus-errors(3) pour plus de détails.

NOTES

L'initialisation d'une structure sd_bus_error à NULL ne suffit pas pour la libérer. Utilisez sd_bus_error_free() pour cela.

L'utilisation de sd_bus_error_set_const() est fortement recommandée pour les chaînes d'erreur qui ne changent pas, afin d'éviter des allocations mémoire inutiles. Si vous utilisez des chaînes littérales, assurez-vous qu'elles sont des chaînes C valides et qu'elles ne sont pas modifiées.

Les fonctions de configuration d'erreur (comme sd_bus_error_set()) peuvent être utilisées directement comme valeur de retour dans une instruction return, car elles renvoient un code d'erreur négatif en cas d'échec.

Si vous travaillez avec un pointeur vers une structure sd_bus_error qui pourrait être NULL, vous devez le vérifier avant d'appeler la plupart de ces fonctions.

EXEMPLES

Exemple 1. Utilisation basique

sd_bus_error error = SD_BUS_ERROR_NULL;
int r;

r = sd_bus_error_set_const(&error, "com.example.Error.NotFound",
                           "Resource /path/to/resource not found.");
if (r < 0)
        goto error_handler;

printf("Error name: %s\n", error.name);
printf("Error message: %s\n", error.message);

sd_bus_error_free(&error);

error_handler:
        if (error.name)
                fprintf(stderr, "Failed: %s (%s)\n", error.name, error.message);
        /* ... handle error ... */
        return r;

Exemple 2. Utilisation avec printf

sd_bus_error error = SD_BUS_ERROR_NULL;
int r;
const char *resource = "/path/to/resource";

r = sd_bus_error_setf(&error, "com.example.Error.NotFound",
                      "Resource %s not found.", resource);
if (r < 0)
        goto error_handler;

/* ... */

sd_bus_error_free(&error);

error_handler:
        if (error.name)
                fprintf(stderr, "Failed: %s (%s)\n", error.name, error.message);
        return r;

Exemple 3. Utilisation dans une instruction return

int my_function(sd_bus_error *error) {
        int ret;
        /* ... perform operation ... */
        if (/* operation failed */) {
                ret = sd_bus_error_setf(error, "com.example.Error.Failed",
                                        "Operation failed with code %d", 42);
                /* Note: ret is already negative here */
                return ret;
        }
        return 0; /* Success */
}

Exemple 4. Utilisation avec errno

int ret;
/* ... */
if (ret < 0) {
        ret = sd_bus_error_set_errno(&error, ret); /* ret is negative errno */
        if (ret < 0)
                goto out;
        /* Now 'error' contains the D-Bus representation of the errno */
        /* ret is still negative, suitable for returning */
        return ret;
}
out:
        /* ... */
        sd_bus_error_free(&error);
        return ret;

DESCRIPTION

Les structures sd_bus_error sont utilisées pour transporter des informations d'erreur sur le bus D-Bus. Elles contiennent un nom d'erreur sous forme de chaîne de caractères et un message d'erreur supplémentaire.

Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_set_const(), sd_bus_error_setf() et sd_bus_error_set() définissent une nouvelle erreur dans la structure sd_bus_error pointée par e. Si une erreur était déjà définie, elle est ignorée et la fonction renvoie -EINVAL. Notez que les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() prennent un paramètre entier error qui est un code d'erreur similaire à errno. Les autres fonctions prennent un nom d'erreur sous forme de chaîne de caractères.

sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() sont similaires à sd_bus_error_set_errno(), mais elles permettent de formater le nom de l'erreur en utilisant le paramètre format et les arguments supplémentaires (ou ap pour sd_bus_error_set_errnofv()). La chaîne formatée sera utilisée comme nom de l'erreur. La valeur entière error sera utilisée comme code d'erreur de base.

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais elle prend un code d'erreur entier similaire à errno au lieu d'une chaîne de nom d'erreur. Le code d'erreur entier sera utilisé pour construire le nom de l'erreur D-Bus.

sd_bus_error_setf() et sd_bus_error_set() sont utilisées pour définir des erreurs D-Bus standards. Elles prennent un nom d'erreur sous forme de chaîne et, pour sd_bus_error_setf(), des arguments pour formater un message d'erreur. Si e est non-NULL, le nom et le message sont copiés dans la structure sd_bus_error. Si e est NULL, la fonction ne fait rien.

sd_bus_error_get_errno() renvoie le code d'erreur entier converti à partir du nom de l'erreur dans e, ou 0 si l'erreur n'est pas définie ou si le nom de l'erreur ne peut pas être converti en un code d'erreur valide.

sd_bus_error_copy() copie le contenu de la structure d'erreur src dans la structure d'erreur dst. Si src n'a pas d'erreur définie, dst sera initialisée à SD_BUS_ERROR_NULL. Si dst est NULL, aucune opération n'est effectuée et les ressources détenues par src sont libérées et réinitialisées.

Pour les fonctions de définition d'erreurs (sauf sd_bus_error_set_const, sd_bus_error_set_errno, sd_bus_error_set_errnof et sd_bus_error_set_errnofv), un nom d'erreur est converti en un code d'erreur entier similaire à errno. La conversion est bidirectionnelle. Le mécanisme de conversion est extensible et les détails se trouvent dans sd_bus_error_add_map(3). Pour les fonctions qui prennent un code d'erreur entier, celui-ci est utilisé directement, par exemple -ENOMEM si une allocation de mémoire échoue.

sd_bus_error_move() est similaire à sd_bus_error_copy(), mais déplacera toutes les informations d'erreur de e vers dst, réinitialisant le premier. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si e n'est pas défini, dst est initialisé à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est exécutée sur celui-ci et les ressources détenues par e sont libérées et réinitialisées. Renvoie une valeur d'erreur convertie similaire à errno, non positive.

sd_bus_error_is_set() renverra une valeur non nulle si e est non-NULL et qu'une erreur a été définie, false sinon.

sd_bus_error_has_name() renverra une valeur non nulle si e est non-NULL et qu'une erreur portant le même name a été définie, false sinon.

sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est un wrapper macro autour de sd_bus_error_has_names_sentinel() qui ajoute le terminateur NULL automatiquement.

sd_bus_error_free() détruira les ressources détenues par e. Le paramètre lui-même ne sera pas désalloué et doit être free(3) par l'appelant si nécessaire. La fonction peut également être appelée en toute sécurité sur des erreurs non définies (structures d'erreur avec les deux champs définis à NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après la libération des données, de sorte que tous les champs soient définis à NULL. La structure peut être réutilisée par la suite.

REFERENCE OWNERSHIP

sd_bus_error n'est pas compté par référence. Les utilisateurs doivent détruire les ressources qu'il détient en appelant sd_bus_error_free(). Habituellement, les structures d'erreur sont allouées sur la pile ou passées en paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il incombe à l'appelant de free(3) la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

RETURN VALUE

Les fonctions sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_set_const() renvoient toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur négative similaire à errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() renvoient 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur négative similaire à errno correspondant au paramètre error sinon. Si une erreur survient en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera renvoyée. Cela permet d'utiliser facilement ces fonctions dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_get_errno() renvoie false lorsque e est NULL, et une valeur errno positive mappée à partir de e->name sinon.

sd_bus_error_copy() et sd_bus_error_move() renvoient une valeur d'erreur négative convertie de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser facilement ces fonctions dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_is_set() renvoie une valeur non nulle lorsque e et le champ name sont non-NULL, zéro sinon.

sd_bus_error_has_name(), sd_bus_error_has_names() et sd_bus_error_has_names_sentinel() renvoient une valeur non nulle lorsque e est non-NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Errors

La valeur de retour peut indiquer les problèmes suivants dans l'invocation de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lorsque l'une des fonctions de définition d'erreur a été appelée.

-ENOMEM

L'allocation de mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() et sd_bus_error_move() renverront une valeur de style errno convertie négative, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en une valeur entière de style errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de style errno peut être renvoyée.

EXAMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, renvoie le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et propager également la valeur errno
   * que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
