SD_EVENT_ADD_INOTIFY(3) sd_event_add_inotify SD_EVENT_ADD_INOTIFY(3)

NOM

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Ajouter une source d'événements d'inode de système de fichiers "inotify" à une boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPTION

sd_event_add_inotify() ajoute une nouvelle source d'événements d'inode de système de fichiers inotify(7) à une boucle d'événements. L'objet de la boucle d'événements est spécifié dans le paramètre event, l'objet de la source d'événements est retourné dans le paramètre source. Le paramètre path spécifie le chemin de l'inode du système de fichiers à surveiller. Le paramètre mask spécifie quels types d'événements d'inode surveiller spécifiquement. Il doit contenir une combinaison OR des drapeaux IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, ... Voir inotify(7) pour plus d'informations.

Le paramètre handler doit référencer une fonction à appeler lorsque l'inode change, ou être NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure inotify_event contenant des informations sur l'événement de l'inode. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

sd_event_add_inotify_fd() est identique à sd_event_add_inotify(), sauf qu'il prend un descripteur de fichier vers un inode (éventuellement un O_PATH, mais tout autre fonctionnera aussi) au lieu d'un chemin dans le système de fichiers.

Si plusieurs sources d'événements sont installées pour le même inode, le descripteur de surveillance inotify sous-jacent est automatiquement partagé. Le paramètre mask peut contenir n'importe quel drapeau défini par l'API inotify, à l'exception de IN_MASK_ADD.

Le gestionnaire est activé en continu (SD_EVENT_ON), mais cela peut être modifié avec sd_event_source_set_enabled(3). Alternativement, le drapeau de masque IN_ONESHOT peut être utilisé pour demander le mode SD_EVENT_ONESHOT. Si la fonction gestionnaire renvoie un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant.

En tant que limitation spéciale, la priorité des sources d'événements inotify ne peut être modifiée (voir sd_event_source_set_priority(3)) qu'entre la création de l'objet source d'événements avec sd_event_add_inotify() et le début de la prochaine itération de la boucle d'événements. Les tentatives de modification de la priorité ultérieurement seront refusées. Envisagez de libérer et d'allouer une nouvelle source d'événements inotify pour modifier la priorité à ce moment-là.

Pour détruire un objet source d'événements, utilisez sd_event_source_unref(3), mais notez que la source d'événements n'est supprimée de la boucle d'événements que lorsque toutes les références à la source d'événements sont abandonnées. Pour s'assurer qu'une source d'événements ne se déclenche plus, même lorsqu'il reste une référence à celle-ci, envisagez de la désactiver avec sd_event_source_set_enabled(3).

Si le second paramètre de sd_event_add_inotify() est passé comme NULL, aucune référence à l'objet source d'événements n'est retournée. Dans ce cas, la source d'événements est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_inotify() est NULL, et que la source d'événements se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé en tant que paramètre de code de sortie à sd_event_exit(3).

sd_event_source_get_inotify_mask() récupère le masque de surveillance inotify configuré d'une source d'événements créée précédemment avec sd_event_add_inotify(). Il prend l'objet source d'événements comme paramètre source et un pointeur vers une variable de type uint32_t pour y retourner le masque.

sd_event_source_get_inotify_path() récupère le chemin cible de la surveillance inotify configurée d'une source d'événements créée précédemment avec sd_event_add_inotify(). Il prend l'objet source d'événements comme paramètre source et un pointeur vers une variable de type const char ** pour y retourner le chemin. L'appelant ne doit pas libérer le chemin retourné.

VALEUR REGROUPÉE

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque avec IN_MASK_ADD défini.

-ESTALE

Retourné par sd_event_source_add_inotify() ou sd_event_source_add_inotify_fd() lorsque la boucle d'événements est déjà terminée. Retourné par sd_event_source_get_inotify_path() lorsqu'aucune donnée d'inode active n'est assignée à la source d'événements, par exemple lorsque la source d'événements est désactivée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

-EDOM

La source d'événements passée n'est pas une source d'événements de processus inotify.

-EBADF

Le descripteur de fichier passé n'est pas valide.

-ENOSYS

sd_event_add_inotify_fd() ou sd_event_source_get_inotify_path() a été appelée sans /proc/ monté.

EXEMPLES

Exemple 1. Un programme simple qui utilise inotify pour surveiller un ou deux répertoires

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <string.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminate the program if an "exit" file appears */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}
int main(int argc, char **argv) {
  _cleanup_(sd_event_unrefp) sd_event *event = NULL;
  _cleanup_(sd_event_source_unrefp) sd_event_source *source1 = NULL, *source2 = NULL;
  const char *path1 = argc > 1 ? argv[1] : "/tmp";
  const char *path2 = argc > 2 ? argv[2] : "/var/tmp";
  int r;
  r = sd_event_default(&event);
  if (r < 0) {
    fprintf(stderr, "Failed to create default event loop: %s\n", strerror(-r));
    goto finish;
  }
  r = sd_event_add_inotify(event, &source1, path1,
                           IN_CREATE|IN_DELETE|IN_MOVED_TO,
                           inotify_handler, NULL);
  if (r < 0) {
    fprintf(stderr, "Failed to add inotify watch for %s: %s\n", path1, strerror(-r));
    goto finish;
  }
  sd_event_source_set_description(source1, path1);
  r = sd_event_add_inotify(event, &source2, path2,
                           IN_CREATE|IN_DELETE|IN_MOVED_TO,
                           inotify_handler, NULL);
  if (r < 0) {
    fprintf(stderr, "Failed to add inotify watch for %s: %s\n", path2, strerror(-r));
    goto finish;
  }
  sd_event_source_set_description(source2, path2);
  printf("Watching %s and %s. Create/delete files to see events. Create a file named "
         "'exit' to terminate.\n",
         path1, path2);
  r = sd_event_loop(event);
finish:
  return r < 0 ? EXIT_FAILURE : EXIT_SUCCESS;
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
