Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_REQUEST_NAME(3) sd_bus_request_name SD_BUS_REQUEST_NAME(3)

NOM

sd_bus_request_name, sd_bus_request_name_async, sd_bus_release_name, sd_bus_release_name_async - Demander ou libérer un nom de service bien connu sur un bus

SYNOPIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_request_name(sd_bus *bus, const char *name, uint64_t flags);

int sd_bus_request_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, uint64_t flags, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_release_name(sd_bus *bus, const char *name);

int sd_bus_release_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, sd_bus_message_handler_t callback, void *userdata);

DESCRIPTION

sd_bus_request_name() demande un nom de service bien connu sur un bus. Elle prend une connexion de bus, un nom de bus valide et un paramètre de drapeaux. Le paramètre de drapeaux est une combinaison de zéro ou plusieurs des drapeaux suivants :

SD_BUS_NAME_ALLOW_REPLACEMENT

Après avoir acquis le nom avec succès, autorise d'autres pairs à reprendre le nom lorsqu'ils tentent de l'acquérir avec le drapeau SD_BUS_NAME_REPLACE_EXISTING défini. Si SD_BUS_NAME_ALLOW_REPLACEMENT n'est pas défini lors de la demande initiale, une telle demande par d'autres pairs sera refusée.

Ajouté dans la version 209.

SD_BUS_NAME_REPLACE_EXISTING

Prendre possession du nom s'il a déjà été acquis par une autre pair, et que cette autre pair a autorisé la prise de possession en définissant SD_BUS_NAME_ALLOW_REPLACEMENT lors de son acquisition.

Ajouté dans la version 209.

SD_BUS_NAME_QUEUE

Mettre en file d'attente l'acquisition du nom lorsque le nom est déjà pris.

Ajouté dans la version 209.

sd_bus_request_name() fonctionne de manière synchrone : un message demandant le nom est envoyé au courtier du bus, et l'appel attend la réponse du courtier.

sd_bus_request_name_async() est une version asynchrone de sd_bus_request_name(). Au lieu d'attendre la fin de la requête, le message de requête est mis en file d'attente. La fonction callback spécifiée sera appelée lorsque la réponse du courtier sera reçue. Si le paramètre est spécifié comme NULL, une implémentation par défaut est utilisée à la place, qui terminera la connexion lorsque le nom ne pourra pas être acquis. La fonction renvoie un objet slot dans son paramètre slot — s'il est passé comme non-NULL — qui peut être utilisé comme référence à l'opération de demande de nom. Utilisez sd_bus_slot_unref(3) pour détruire cette référence. Notez que la destruction de la référence ne désenregistre pas le nom, mais assure simplement que le rappel spécifié ne sera plus appelé.

sd_bus_release_name() libère un nom bien connu acquis. Elle prend une connexion de bus et un nom de bus valide en paramètres. Cette fonction fonctionne de manière synchrone, envoyant un message de requête de libération au courtier du bus et attendant sa réponse.

sd_bus_release_name_async() est une version asynchrone de sd_bus_release_name(). La fonction de rappel callback spécifiée est appelée lorsque le nom a été libéré avec succès. Si spécifié comme NULL, une implémentation générique est utilisée qui ignore le résultat de l'opération. Comme ci-dessus, le slot (s'il est non-NULL) est défini sur un objet qui peut être utilisé pour référencer l'opération.

Ces fonctions ne sont prises en charge que sur les connexions de bus, c'est-à-dire les connexions à un courtier de bus et non sur les connexions directes.

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Si SD_BUS_NAME_QUEUE est spécifié, sd_bus_request_name() renverra 0 lorsque le nom est déjà pris par une autre pair et que le client a été ajouté à la file d'attente pour le nom. Dans ce cas, l'appelant peut s'abonner aux signaux "NameOwnerChanged" pour être notifié lorsque le nom est acquis avec succès. sd_bus_request_name() renvoie > 0 lorsque le nom a été acquis immédiatement avec succès.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EALREADY

L'appelant est déjà le propriétaire du nom spécifié.

-EEXIST

Le nom a déjà été acquis par une autre pair, et SD_BUS_NAME_REPLACE_EXISTING n'a pas été spécifié ou l'autre pair n'a pas spécifié SD_BUS_NAME_ALLOW_REPLACEMENT lors de l'acquisition du nom.

-ESRCH

Il a été tenté de libérer un nom qui n'est actuellement pas enregistré sur le bus.

-EADDRINUSE

Il a été tenté de libérer un nom appartenant à une autre pair sur le bus.

-EINVAL

Un paramètre spécifié est invalide. Ceci est également généré lorsque le nom demandé est un nom de service spécial réservé par la spécification D-Bus, ou lorsque l'opération est demandée sur une connexion qui ne fait pas référence à un bus.

-ENOTCONN

La connexion du bus a été déconnectée.

-ECHILD

La connexion du bus a été créée dans un processus différent de celui actuel.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_request_name() et sd_bus_release_name() ont été ajoutés dans la version 209.

sd_bus_request_name_async() et sd_bus_release_name_async() ont été ajoutés dans la version 237.

sd_bus_request_name(3) - Page de manuel Linux

sd_bus_request_name - Demande un nom sur le bus système

SYNTAXE

sd_bus_request_name(3)

DESCRIPTION

sd_bus_request_name() tente d'acquérir le nom spécifié sur le bus du système ou de l'utilisateur décrit par bus. Le nom demandé doit être un nom de service valide, comme décrit dans systemd.index(7). Il peut être soit un nom bien connu (par exemple, « org.freedesktop.hostname1 »), soit un nom unique (par exemple, « org.example.MyService.unique »).

Si le nom est acquis avec succès, la fonction renvoie 0. Si le nom est déjà détenu par un autre processus, ou si la demande échoue pour une autre raison, la fonction renvoie un code d'erreur.

La fonction sd_bus_request_name() est une interface synchrone pour demander des noms de bus. Il existe également des interfaces asynchrones disponibles via sd_bus_request_name_async().

PARAMÈTRES

bus
Un pointeur vers une connexion de bus valide.
name
Le nom du service à demander. Doit être une chaîne de caractères terminée par null.
flags
Indicateurs pour modifier le comportement de la demande. Peut être une combinaison de SD_BUS_REQUEST_NAME_REPLACE_EXISTING, SD_BUS_REQUEST_NAME_NO_FAIL_ALREADY_EXISTS, SD_BUS_REQUEST_NAME_ALLOW_REPLACEMENT, SD_BUS_REQUEST_NAME_WAIT_FOR_UNREGISTER.

VALEUR DE RETOUR

Renvoie 0 en cas de succès, un code d'erreur négatif en cas d'échec.

EXEMPLE


int ret;
sd_bus *bus = NULL;

ret = sd_bus_open_system(&bus);
if (ret < 0) {
    fprintf(stderr, "Impossible d'ouvrir le bus système : %s\n", strerror(-ret));
    goto finish;
}

ret = sd_bus_request_name(bus, "org.example.MyService", 0);
if (ret < 0) {
    fprintf(stderr, "Impossible de demander le nom de service : %s\n", strerror(-ret));
    goto finish;
}

printf("Nom de service demandé avec succès.\n");

finish:
    sd_bus_unref(bus);
    return ret < 0 ? 1 : 0;
