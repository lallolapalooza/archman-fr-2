DESCRIPTION

La structure sd_bus_error contient des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles pour les noms d'erreurs décrites dans la spécification D-Bus, sous-section Noms D-Bus valides[1]. Un certain nombre de noms d'erreurs courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques au domaine peuvent être définies par les applications.
•Le champ message contient généralement une chaîne de caractères lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir ses deux champs initialisés à NULL et signifie l'absence d'erreur, c'est-à-dire le succès. Affectez SD_BUS_ERROR_NULL à la structure pour initialiser les deux champs à NULL. Lorsque les ressources détenues par la structure sd_bus_error ne sont plus nécessaires, elles doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de caractères spécifiées pour le nom et le message. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreurs déjà définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données qu'elle contient avec sd_bus_error_free().

sd_bus_error_set() renverra une valeur de type errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, on suppose qu'aucune erreur ne s'est produite, et 0 est renvoyé. Si name n'est pas nul, une valeur négative est toujours renvoyée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est toujours converti en une valeur de type errno.

Diverses erreurs D-Bus bien connues sont converties en leurs correspondants errno bien connus, et les autres sont converties en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreurs bien connus. Des mappings d'erreurs supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et des arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition de structures d'erreurs. Puisque cet appel n'alloue pas de mémoire, il n'échouera pas avec une condition de manque de mémoire comme le peut sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() retournera immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur de type errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Des noms d'erreurs D-Bus bien connus seront utilisés pour name si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si l'erreur spécifiée error n'est pas nulle, l'appel renvoie toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est renvoyé.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et des arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de type errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera renvoyé.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur auparavant. Sinon, il retournera immédiatement. Si les chaînes de caractères dans e ont été définies à l'aide de sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit fraîchement initialisé avec NULL, soit réinitialisé à l'aide de sd_bus_error_free().

sd_bus_error_copy() renvoie généralement 0 ou une valeur négative de type errno basée sur le paramètre d'entrée e : 0 s'il était non défini et un entier négatif s'il était défini sur une certaine erreur, de manière similaire à sd_bus_error_set(). Il peut cependant également renvoyer une erreur générée en interne, pour e

xample -ENOMEM si une allocation de mémoire échoue.

sd_bus_error_move() est similaire à sd_bus_error_copy(), mais déplacera toute information d'erreur de e vers dst, réinitialisant le premier. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si e n'est pas défini, dst est initialisé à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est exécutée sur lui et les ressources détenues par e sont libérées et réinitialisées. Retourne une valeur d'erreur convertie de type errno, non positive.

sd_bus_error_is_set() retournera une valeur non nulle si e n'est pas NULL et qu'une erreur a été définie, false sinon.

sd_bus_error_has_name() retournera une valeur non nulle si e n'est pas NULL et qu'une erreur portant le même name a été définie, false sinon.

sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est un wrapper macro autour de sd_bus_error_has_names_sentinel() qui ajoute automatiquement le sentinelle NULL.

sd_bus_error_free() détruira les ressources détenues par e. Le paramètre lui-même ne sera pas désalloué et doit être free(3) par l'appelant si nécessaire. La fonction peut également être appelée sans risque sur des erreurs non définies (structures d'erreur avec les deux champs définis à NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après la libération des données, de sorte que tous les champs soient définis à NULL. La structure peut être réutilisée par la suite.

PROPRIÉTÉ DES RÉFÉRENCES

sd_bus_error n'est pas compté par référence. Les utilisateurs doivent détruire les ressources qu'il détient en appelant sd_bus_error_free(). Généralement, les structures d'erreur sont allouées sur la pile ou passées en tant que paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il est du devoir de l'appelant de free(3) la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

VALEUR DE RETOUR

Les fonctions sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_set_const() retournent toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur négative de type errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv(), retournent 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur négative de type errno correspondant au paramètre error sinon. Si une erreur survient en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera retournée. Cela permet d'utiliser ces fonctions commodément dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_get_errno() retourne false lorsque e est NULL, et une valeur errno positive mappée à partir de e->name sinon.

sd_bus_error_copy() et sd_bus_error_move() retournent une valeur d'erreur négative convertie de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser ces fonctions commodément dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_is_set() retourne une valeur non nulle lorsque e et le champ name ne sont pas NULL, zéro sinon.

sd_bus_error_has_name(), sd_bus_error_has_names() et sd_bus_error_has_names_sentinel() retournent une valeur non nulle lorsque e n'est pas NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Erreurs

La valeur de retour peut indiquer les problèmes suivants lors de l'invocation de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lorsque l'une des fonctions de définition d'erreur a été appelée.

-ENOMEM

L'allocation de mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() et sd_bus_error_move() retourneront une valeur négative convertie de style errno, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en valeur intégrale de style errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de style errno peut être retournée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, retourner le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et également propager la valeur errno
   * que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
