NOM

sdparm - accéder aux pages de mode SCSI ; lire les pages VPD ; envoyer des commandes SCSI simples.

SYNTAXE

sdparm [--all] [--dbd] [--examine] [--flexible] [--get=STR] [--hex] [--long] [--num-desc] [--out-mask=OM] [--page=PG[,SPG]] [--quiet] [--readonly] [--six] [--transport=TN] [--vendor=VN] [--verbose] APPAREIL [APPAREIL...]

sdparm [--clear=STR] [--defaults] [--dummy] [--flexible] [--page=PG[,SPG]] [--quiet] [--readonly] [--save] [--set=STR] [--six] [--transport=TN] [--vendor=VN] [--verbose] APPAREIL [APPAREIL...]

sdparm --command=CMD [--hex] [--long] [--readonly] [--verbose] APPAREIL [APPAREIL...]

sdparm --inquiry [--all] [--examine] [--flexible] [--hex] [--num-desc] [--page=PG[,SPG]] [--quiet] [--readonly] [--transport=TN] [--verbose] APPAREIL [APPAREIL...]

sdparm --enumerate [--all] [--inquiry] [--long] [--page=PG[,SPG]] [--transport=TN] [--vendor=VN]

sdparm --inhex=FN [--all] [--flexible] [--hex] [--inquiry] [--long] [--pdt=DT] [--raw] [--six] [--transport=TN] [--vendor=VN] [--verbose]

sdparm --wscan [--verbose]

sdparm [--help] [--version]

DESCRIPTION

Cet utilitaire récupère et éventuellement modifie les pages de mode des périphériques SCSI (par exemple, disque). Les données d'interrogation, y compris les pages de données produit vitales (VPD), peuvent également être affichées. Les commandes associées au démarrage et à l'arrêt du support ; au chargement et au déchargement du support ; et à d'autres fonctions de maintenance peuvent également être émises par cet utilitaire.

La première invocation montrée dans la syntaxe concerne l'accès (c'est-à-dire la lecture) des champs de page de mode détenus sur l'APPAREIL. La deuxième forme concerne la modification des champs de page de mode détenus sur l'APPAREIL. La troisième forme concerne l'exécution de quelques commandes SCSI simples. La quatrième forme (c'est-à-dire la forme '--inquiry ... APPAREIL') concerne la récupération et le décodage des pages VPD à partir de l'APPAREIL donné. La forme --enumerate sert à lister les données des champs de mode ou VPD détenues par cet utilitaire (et si un APPAREIL est donné, il est ignoré). La forme --inhex=FN décode les données de réponse de mode ou de VPD fournies dans le fichier nommé (ou à partir de stdin si FN=- est donné) ; ces données peuvent être en hexadécimal ou en binaire. L'avant-dernière forme est réservée à Windows et liste les noms des périphériques de stockage disponibles ; voir l'entrée OPTIONS pour --wscan. La dernière forme sert à fournir l'aide de la ligne de commande ou le numéro de version (et la date) de cet utilitaire.

Si aucune option (autre que APPAREIL) n'est donnée, une sélection de champs de page de mode courants pour ce périphérique est listée. Si l'option --long est également donnée, une description des champs est placée à droite de chaque ligne. Si l'option --all est donnée, tous les champs de page de mode connus pour ce périphérique sont listés. Les champs individuels peuvent être affichés avec l'option --get=STR (par exemple, '--get=WCE' pour récupérer l'état du champ Writeback Cache Enable).

Cet utilitaire se termine avec un code de sortie de 0 en cas de succès. Pour les autres valeurs, voir la section CODE DE SORTIE ci-dessous.

Un ou plusieurs arguments APPAREIL peuvent être donnés. L'utilitaire appliquera essentiellement les options données à chaque APPAREIL de la liste. Si une erreur est détectée, elle est signalée et l'utilitaire continue. L'erreur de code 5 (problème d'ouverture ou de fermeture de fichier) est traitée comme de priorité inférieure lorsque d'autres erreurs sont détectées. Le code de sortie est la valeur de l'erreur la plus récemment détectée (excluant le code d'erreur 5 si d'autres erreurs ont été détectées). Si toutes les actions réussissent, le code de sortie est zéro.

Par défaut, cet utilitaire affiche les pages de mode qui sont communes à tous les protocoles de transport. Celles-ci sont appelées pages de mode "génériques". S'il n'y a pas de correspondance pour un nom de page de mode ou un champ de page de mode générique, les pages spécifiques au transport SAS sont vérifiées. Les pages de mode spécifiques au protocole de transport sont sélectionnées avec l'option --transport=TN. Voir la section TRANSPORT ci-dessous. Les pages de mode spécifiques au vendeur sont sélectionnées avec l'option --vendor=VN. Voir la section VENDEURS ci-dessous.

Bien qu'à l'origine destiné aux disques SCSI (ou aux périphériques de stockage qui apparaissent à l'OS comme des disques SCSI), de nombreuses pages de mode sont pour d'autres types de périphériques SCSI. Ceux-ci incluent les lecteurs CD/DVD qui utilisent le transport ATAPI (ou tout autre) et les lecteurs de bandes SCSI et les boîtiers SCSI.

Lorsque l'option --inquiry est donnée sans numéro de page, la page VPD Device Identification (numéro de page 0x83) est demandée et si elle est trouvée, elle est décodée et affichée. Si aucun numéro de page n'est donné et que l'option --all est donnée, une liste des noms de pages VPD (mais pas de leur contenu) supportées par l'APPAREIL est affichée. Lorsque les options --inquiry et --page=PG sont données, la page VPD peut être spécifiée comme une abréviation (par exemple, "sp" pour la page VPD SCSI ports) ou numériquement (par exemple, "0x88"). Si une page VPD est retournée par l'APPAREIL mais que sdparm ne peut pas la décoder ou que l'option --hex est donnée, elle est affichée en hexadécimal.

OPTIONS

Les arguments obligatoires pour les options longues sont également obligatoires pour les options courtes. Si une option prend un argument numérique, cet argument est supposé être décimal sauf indication contraire (par exemple, avec un "0x" préfixé ou un "h" suffixé). Les options sont triées par ordre alphabétique, en se basant sur le nom de l'option longue.

-a, --all
affiche tous les champs reconnus pour le type de périphérique (par exemple, disque) de l'APPAREIL. Sans cette option (ou l'option --page=PG[,SPG]), l'action par défaut consiste à afficher un nombre relativement faible de champs couramment utilisés provenant de différentes pages. Lorsqu'un numéro de page (de mode) spécifique est donné avec l'option --page=PG[,SPG], tous les champs de cette page sont affichés (indépendamment du réglage de cette option). Pour l'action de cette option lorsqu'elle est utilisée avec l'option --enumerate, voir la section ENUMERATE ci-dessous.
Lorsqu'elle est utilisée avec l'option --inquiry et un APPAREIL, la page VPD Supported VPD Pages [0x0] est affichée. Lorsque cette option est utilisée deux fois (forme courte : '-iaa'), toutes les pages VPD (listées dans la page VPD Supported VPD Pages) sont affichées.
Par défaut, --inhex=FN ne décode que la première page de mode trouvée dans FN. Avec cette option, d'autres pages de mode seront décodées si elles sont présentes. Lorsque --transport=TN ou --vendor=VN est également donné, si une page de mode donnée n'est pas définie pour ce transport ou ce vendeur, elle est décodée comme une page de mode générique.
-c, --clear=STR
Dans sa forme la plus simple, STR contient un acronyme de champ ou un descripteur numérique de champ. En l'absence d'argument de valeur explicite (par exemple, '--clear=WCE=1'), le champ a sa valeur effacée à zéro. Voir la section PARAMÈTRES ci-dessous.
-C, --command=CMD
Exécute la CMD donnée. Voir la section COMMANDES ci-dessous. Pour énumérer les commandes supportées, utilisez '-e -C x' (en utilisant n'importe quel nom de CMD, valide ou non).
-B, --dbd
désactive les descripteurs de bloc. C'est un bit dans les cdb MODE SENSE qui a rarement besoin d'être défini. Un cas connu est un MODE SENSE 6 adressé à un périphérique Reduced Block Commands (RBC) où la norme RBC dit qu'il doit être défini.
-D, --defaults
définit la page de mode donnée à ses valeurs par défaut. Nécessite l'option --page=PG[,SPG] pour spécifier la page de mode. Pour que les valeurs de page de mode par défaut soient également les valeurs de page de mode sauvegardées, utilisez également l'option --save.
lorsque cette option est utilisée deux fois, les valeurs actuelles dans toutes les pages de mode sont rétablies à leurs valeurs par défaut. Si l'option --save est également donnée, alors les valeurs actuelles et sauvegardées dans toutes les pages de mode sont rétablies à leurs valeurs par défaut. Cette fonctionnalité utilise le bit RTD dans la commande MODE SELECT qui a été ajouté dans la proposition SPC-5 révision 11.
-d, --dummy
lorsqu'il est défini, inhibe les modifications apportées à la page de mode du APPAREIL. Au lieu de cela, les données de mode qui auraient été envoyées
o une commande MODE SELECT, est affichée en hexadécimal ASCII sur la console. Cette option est principalement destinée aux tests.
-e, --enumerate
répertorie les informations descriptives sur les pages et les champs connus de cet utilitaire. Ignore l'argument DEVICE et les autres options à l'exception de --all, --inquiry, --long, --page=PG[,SPG], --transport=TN et --vendor=VN. Si --enumerate est fourni sans autres options, les pages de mode connues (génériques) sont répertoriées. Voir la section ENUMERATE ci-dessous.
-E, --examine
pour les pages de mode, seuls celles dont les noms de champs sont connus sont interrogées lorsque l'option --all est fournie. Pour les pages VPD, seules les pages répertoriées dans la page "Supported VPD pages" sont décodées. Dans les deux cas, certaines pages peuvent être omises. Avec cette option (c'est-à-dire --examine), toutes les pages de mode et VPD peuvent être interrogées.
Pour les pages de mode, cette option interrogera toutes les pages de mode du numéro de page 0x0 à 0x3e. Pour interroger les sous-pages de mode, fournissez un numéro de page de mode avec --page=PG, puis toutes les sous-pages (de 0x0 à 0xfe) seront interrogées.
Pour les pages VPD, utilisez cette option avec --inquiry. Cela provoquera l'interrogation de toutes les pages VPD de 0x0 à 0xb f par défaut. Une séquence de pages VPD peut être interrogée avec --page=PG[,SPG], auquel cas les pages VPD de PG (numéro inférieur) à SPG (numéro supérieur) inclus seront interrogées. Les pages VPD spécifiques au fournisseur vont de 0xc0 à 0xff et peuvent être interrogées en définissant SPG de 0xc0 à 0xff.
-f, --flexible
Certains périphériques, ponts et/ou pilotes tentent des transformations brutes entre les commandes MODE SENSE 6 et 10 octets sans reconstruire correctement la réponse. Cela entraînera une mauvaise interprétation de la réponse (généralement avec une erreur indiquant que la réponse est malformée). Avec cette option, la longueur de la réponse est vérifiée et, si elle semble incorrecte, diverses corrections sont tentées. Cette option permettra également de répertorier les pages de mode qui n'appartiennent pas au type de périphérique de ce périphérique.
-g, --get=STR
Dans sa forme la plus simple, STR contient un nom d'acronyme de champ ou un descripteur numérique de champ. Le champ est récupéré de la page de mode. Voir la section PARAMÈTRES ci-dessous. Les options --long et --hex affectent le format de sortie. De plus, si une valeur de "1" est fournie (par exemple, '--get=WCE=1'), seule la valeur actuelle est affichée (c'est-à-dire pas le masque de modification, la valeur par défaut et la valeur enregistrée).
-h, --help
affiche le message d'utilisation puis quitte.
-H, --hex
au lieu d'essayer de décoder les pages de mode (ou VPD), les affiche en hexadécimal. Lorsqu'elle est utilisée avec l'option --get=STR, les valeurs actuelles, modifiables, par défaut et enregistrées correspondantes sont affichées en hexadécimal, précédées de "0x" et séparées par des espaces. Si une valeur de "1" est fournie avec l'option --get=STR (par exemple, '--get=WCE=1'), seule la valeur actuelle est affichée en hexadécimal, précédée de "0x". Si une valeur de "2" est fournie avec l'option --get=STR, seule la valeur actuelle est affichée sous forme d'entier (signé). Cette option peut être utilisée plusieurs fois (par exemple, '-HH'). Utile avec la page d'informations ATA VPD qui affiche généralement sa réponse IDENTIFY (PACKET) DEVICE en mots hexadécimaux de 16 bits ; avec '-HH' affiche cette réponse en octets hexadécimaux ; avec '-HHH' affiche la même réponse dans un format adapté au décodage par 'hdparm --Istdin'.
La sortie des pages de mode avec l'option '-HHH' est adaptée à une invocation ultérieure de sdparm avec l'option --inhex=FN.
-i, --inquiry
affiche une page VPD qui se trouve dans la réponse d'une commande SCSI INQUIRY envoyée à DEVICE. En l'absence de cette option, l'action par défaut est d'afficher les pages de mode. Si l'option --inquiry est fournie sans l'option --page=PG[,SPG], la page VPD d'identification du périphérique (0x83) est décodée et affichée. Si cette option et l'option --all sont fournies, la page des pages VPD prises en charge (0x0) est décodée et affichée.
-I, --inhex=FN
FN est attendu comme un nom de fichier (ou '-' pour stdin) contenant de l'hexadécimal ASCII (ou binaire) représentant la réponse à MODE SENSE(10). Si --six est également fourni, la réponse de MODE SENSE(6) est supposée. Une réponse MODE SENSE contient un en-tête de paramètres de mode, suivi de 0 ou plusieurs descripteurs de bloc, puis d'une ou plusieurs pages de mode. Cet utilitaire ne décodera que la première page de mode, sauf si l'option --all est fournie. Afin de décoder une page de mode, le type de périphérique périphérique est souvent nécessaire et peut être fourni avec l'option --pdt=DT. Si --pdt=DT n'est pas fourni, une page de mode trouvée dans deux normes de type de périphérique (par exemple, SBC et SSC) peut être décodée deux fois.
Si --inquiry est fourni, alors FN est interprété comme les données de réponse d'une seule page VPD.
L'hexadécimal dans FN doit être organisé en 1 ou 2 chiffres représentant un octet chacun, séparé par des espaces ou des virgules. Tout à partir d'un signe dièse jusqu'à la fin de la ligne est ignoré. Si l'option --raw est fournie, alors FN est traité comme binaire.
-l, --long
affiche des informations supplémentaires. Dans le cas des champs de page de mode, une description (avec unités si applicable) est affichée à droite. Si utilisé deux fois, alors pour certains champs, plus d'informations sur ses valeurs sont données sur une ou plusieurs lignes suivantes, chacune précédée d'une tabulation. Pour une utilisation avec --enumerate, voir la section ENUMERATE ci-dessous.
Lorsque cette option est utilisée avec --command=capacity, la commande READ CAPACITY(16) est envoyée à DEVICE et, si elle réussit, sa réponse étendue est affichée.
-n, --num-desc
pour une page de mode qui peut avoir des descripteurs, le nombre de descripteurs pour la page donnée sur le DEVICE est affiché. Sinon, 0 est affiché.
-o, --out-mask=OM
OM est un masque de bits pour les sélections de pages de mode qui seront imprimées/affichées. La valeur 0x1 est pour les valeurs 'actuelles', 0x2 pour les valeurs 'modifiables', 0x4 pour les valeurs 'par défaut' et 0x8 pour les valeurs 'enregistrables'. La valeur par défaut est 0xf (c'est-à-dire le OU de toutes les quatre valeurs définies). L'option est utile pour limiter la quantité de sortie avec '-HHH'.
-p, --page=PG[,SPG]
fournit le numéro de page (PG) et éventuellement le numéro de sous-page (SPG) de la page de mode (ou VPD) à récupérer. Ces numéros sont interprétés comme décimaux, sauf s'ils sont précédés de "0x" ou d'un suffixe. Les numéros de sous-pages ne sont valides que pour les pages de mode (pas les pages VPD). Alternativement, une abréviation pour une page peut être donnée (voir l'entrée suivante).
-p, --page=STR
une abréviation de deux ou trois lettres pour une page peut être donnée. Les abréviations connues de pages de mode sont vérifiées en premier, suivies des abréviations connues de pages VPD. Par exemple, '--page=ca' correspond à la page de mode de mise en cache. Si aucune correspondance n'est trouvée, une erreur est émise et une liste de possibilités dans le contexte actuel est fournie (donc '-p x' peut être très utile). Si STR correspond à une abréviation connue de page VPD, alors l'option --inquiry est supposée. Pour une utilisation avec --enumerate, voir la section ENUMERATE ci-dessous.
-P, --pdt=DT
Cette option n'est active que lorsque l'option --inhex=FN est fournie. DT est le type de périphérique périphérique, une valeur comprise entre 0 et 31 et qui peut être trouvée dans la réponse à la commande INQUIRY. La valeur par défaut est -1 (qui peut également être fournie pour DT) et elle est interprétée comme SPC (c'est-à-dire les pages de mode communes) ou comme un joker. Si disponible, cette option doit être fournie avec l'option --inhex=FN.
-q, --quiet
supprime l'affichage du nom du périphérique suivi des chaînes vendeur, produit et révision récupérées d'une réponse INQUIRY. Sans cette option, une telle ligne est généralement la première ligne affichée par sdparm. Réduit la sortie de la page VPD d'identification du périphérique, généralement à une ligne (ou aucune) pour chaque di_lu, di_port, di_target et di_asis.
Si cette option est utilisée deux fois, alors en plus, la sortie des pages de mode supprime les valeurs modifiables, par défaut et enregistrées qui sont généralement affichées entre parenthèses, si elles sont disponibles.
-r, --readonly
annule d'autres logiques pour ouvrir DEVICE en mode lecture seule. Le paramètre par défaut du mode d'ouverture lecture seule/lecture-écriture dépend de l'opération demandée (par exemple, une opération --set=STR tentera par défaut une ouverture en mode lecture-écriture sur DEVICE). Cette option peut être utile si une commande est envoyée à un disque ATA via un jeu de commandes SCSI. Par exemple, sous Linux, '-C stop' peut nécessiter cette option pour empêcher un disque ATA d'être redémarré immédiatement.
-R, --raw
cette option n'est active que lorsqu'elle est utilisée avec l'option --inhex=FN. Lorsque cette option est fournie, le fichier FN est interprété comme binaire ; l'action par défaut (c'est-à-dire lorsque cette option n'est pas fournie) est d'interpréter FN comme de l'hexadécimal ASCII.
-S, --save
lorsqu'une page de mode est modifiée (en utilisant les options --clear=STR et/ou --set=STR), l'action par défaut est de modifier uniquement la page de valeurs actuelles. Lorsque cette option est fournie, la valeur correspondante dans la page de valeurs enregistrées est également modifiée. La prochaine fois que le périphérique sera mis sous tension (ou réinitialisé), la page de valeurs enregistrées deviendra (c'est-à-dire sera copiée dans) la page de valeurs actuelles. Cette option définit le champ SP dans la commande MODE SELECT. Voir la section NOTES ci-dessous.
-s, --set=STR
dans sa forme la plus simple, STR contient un nom d'acronyme de champ ou un descripteur numérique de champ. En l'absence de valeur explicite, chaque nom d'acronyme a sa valeur définie à (tous) les uns. Cela signifie qu'un champ de 16 bits sera défini à 0xffff, ce qui équivaut à 65535 en décimal. Alternativement, chaque nom d'acronyme ou descripteur numérique peut être suivi de "=<n>" où <n> est la valeur à laquelle ce champ doit être défini. Voir la section PARAMÈTRES ci-dessous.
-6, --six
L'action par défaut de cet utilitaire est d'émettre les commandes SCSI MODE SENSE et MODE SELECT avec des cdb de 10 octets. Lorsque cette option est fournie, les variantes de cdb de 6 octets sont utilisées. RBC et les anciens périphériques SCSI
may need this option. This utility outputs a suggestion to use this option if the SCSI status indicates that the 10 byte cdb variant is not supported.
The SPC-4 standard (and SPC-5 drafts) include a note stating that implementers migrate away from the SCSI MODE SELECT(6) and MODE SENSE(6) commands in favour of the 10 byte variants (e.g. MODE SEMSE(10)).
-t, --transport=TN
Spécifie le protocole de transport où TN est soit un nombre dans la plage de 0 à 15 (inclus) soit une abréviation (par exemple, « fcp » pour le Fibre Channel Protocol). Certains transports acceptent plusieurs abréviations, par exemple srp (SCSI RDMA Protocol) et ib (raccourci pour InfiniBand) sont tous deux acceptés pour le protocole de transport 0x4. Les majuscules et minuscules sont également acceptées, donc iscsi et iSCSI sont acceptés pour le protocole de transport 0x5. Une façon de lister les numéros de protocoles de transport disponibles et leurs abréviations associées est de donner un nom de protocole de transport invalide comme '-t x' ; une autre façon est '-e -l'. N.B. L'option --all peut encore être nécessaire pour afficher tous les champs disponibles.
-M, --vendor=VN
Spécifie le vendeur (c'est-à-dire le fabricant) où VN est soit un nombre (0 ou plus) soit une abréviation (par exemple, « sea » pour le vendeur spécifique de disque Seagate). Pour les lecteurs de bande, « lto5 » et « lto6 » sont traités comme des vendeurs. Une façon de lister les numéros de vendeurs disponibles et leurs abréviations associées est de donner un numéro de vendeur invalide comme '-M x' ; une autre façon est '-e -l'.
Cette option n'affecte que le décodage des pages de mode, pas les pages VPD. Pour les pages VPD spécifiques au vendeur, voir l'utilitaire sg_vpd.
-v, --verbose
augmente le niveau de verbosité (c'est-à-dire la sortie de débogage). Dans certains cas, plus de décodage est effectué (par exemple, les champs dans une réponse standard INQUIRY).
-V, --version
affiche la chaîne de version puis quitte.
-w, --wscan
cette option n'est disponible que sous Windows. Elle liste les noms des périphériques de stockage et les volumes correspondants, le cas échéant. Lorsqu'elle est utilisée deux fois, elle ajoute le « type de bus » du transport le plus proche (par exemple, un disque SATA dans un boîtier connecté en USB a le type de bus Usb). Lorsqu'elle est utilisée trois fois, un scan d'adaptateur SCSI est ajouté. Lorsqu'elle est utilisée quatre fois, seul un scan d'adaptateur SCSI est affiché. Voir les exemples ci-dessous et la section « Win32 port » dans le fichier README.

NOTES

Le document de référence utilisé pour interpréter les pages de mode et les pages VPD (et la réponse standard INQUIRY) est T10/BSR INCITS 502 Revision 17 (SPC-5, 19 septembre 2017) disponible sur http://www.t10.org. Les éléments obsolètes et réservés dans la sortie de la réponse standard INQUIRY sont affichés entre crochets. Les projets récents d'autres documents T10 sont également utilisés : SBC-4 (disques), SSC-5 (bandes), SPL-5 (transport SAS) et SAT-4 (SCSI to ATA Translation).

Une page de mode pour laquelle aucune abréviation n'est connue (par exemple, une page de mode spécifique au vendeur) peut être listée en hexadécimal en utilisant la combinaison d'options '--page=PG --hex'.

Les nombres saisis dans sdparm (par exemple, dans les arguments de la ligne de commande) sont supposés être en décimal, sauf indication hexadécimale. Une indication hexadécimale est soit un préfixe '0x' ou '0X' (c'est-à-dire la convention du langage C), soit un suffixe 'h' ou 'H' (c'est-à-dire la convention utilisée sur www.t10.org). Dans le cas de --page=, une chaîne ou un nombre est attendu, donc les nombres hexadécimaux comme 'ch' (12) doivent être préfixés par un zéro (par exemple, '0ch').

Le projet SPC-4 (rev 2) indique que les périphériques qui n'implémentent aucune distinction entre les pages courantes et sauvegardées peuvent renvoyer une erreur (ILLEGAL REQUEST, invalid field in cdb) si le bit SP (qui correspond à l'option --save) n'est PAS défini. Dans de tels cas, l'option --save doit être fournie.

Si l'option --save est fournie mais que la page de mode existante indique (via son bit PS) que la page n'est pas sauvegardable, alors cet utilitaire génère un message d'erreur. Ce message suggère de réessayer sans l'option --save.

Puisque la page VPD d'identification du périphérique (nom d'acronyme « di ») contient potentiellement beaucoup de descripteurs divers, plusieurs acronymes associés sont disponibles. Ce sont « di_lu » pour les descripteurs associés à l'unité logique adressée, « di_port » pour les descripteurs associés au port cible (via lequel la commande est arrivée) et « di_target » pour les descripteurs associés au périphérique cible. Lorsque « di » est utilisé, les descripteurs sont groupés par lu, puis par port et enfin par périphérique cible. Pour voir tous les descripteurs décodés dans l'ordre où ils apparaissent dans la page VPD, utilisez « di_asis ».

Seules les pages VPD définies par t10.org sont décodées par cet utilitaire. SPC-4 réserve les codes de pages VPD de 0xc0 à 0xff (inclus) pour les pages spécifiques aux vendeurs, dont certaines sont décodées dans l'utilitaire sg_vpd.

Pour voir toutes les pages VPD prises en charge par un DEVICE, utilisez 'sg_vpd --all'.

Dans le noyau Linux des séries 2.6 et 3, tout nœud de périphérique qui comprend un jeu de commandes SCSI (par exemple, les disques SCSI et les lecteurs CD/DVD) peut être spécifié. Plus précisément, le pilote qui « possède » le nœud de périphérique doit prendre en charge l'ioctl SG_IO. Dans la série lk 2.4, seuls les nœuds de périphériques génériques SCSI (sg) prennent en charge l'ioctl SG_IO. Cependant, dans la série lk 2.4, d'autres nœuds de périphériques SCSI sont mappés dans cet utilitaire à leurs nœuds de périphériques sg correspondants. Ainsi, s'il y a un disque SCSI sur /dev/sda, 'sdparm /dev/sda' fonctionnera dans les séries lk 2.4 et ultérieures. Cependant, s'il y a un lecteur CD/DVD ATAPI sur /dev/hdc, 'sdparm /dev/hdc' ne fonctionnera que dans les séries lk 2.6 et ultérieures.

Dans les séries Linux 2.6 et 3, en particulier avec les disques ATA, utiliser sdparm pour arrêter (mettre hors tension) un disque peut ne pas être suffisant et d'autres mécanismes redémarreront le disque plus tard. L'utilisateur pourrait en outre marquer le disque comme « hors ligne » avec 'echo offline > /sys/block/sda/device/state' où sda est le nom du bloc du disque. Pour redémarrer le disque, « offline » peut être remplacé par « running ».

PARAMETERS

Dans leur forme la plus simple, les options --clear=, --get= et --set= (ou leurs formes courtes) prennent un nom d'acronyme tel que « WCE ». Dans le cas de '--get=WCE', la valeur de « Writeback Cache Enable » dans la page de mode de mise en cache sera récupérée. Dans le cas de '--set=WCE', ce bit sera défini (à un). Dans le cas de '--clear=WCE', ce bit sera effacé (à zéro). Lorsqu'un nom d'acronyme est donné, la page de mode est déduite de ce nom d'acronyme (par exemple, WCE est dans la page de mode de mise en cache).

Au lieu d'un nom d'acronyme, un champ dans une page de mode peut être décrit numériquement avec un tuple <start_byte>:<start_bit>:<num_bits>. Ce sont le <start_byte> (origine 0) dans la page de mode, un <start_bit> (0 à 7 inclus) et <num_bits> (1 à 64 inclus). Par exemple, la représentation de bas niveau du bit RCD (le « Read Cache Disable bit dans la page de mode de mise en cache) est « 2:0:1 ». Le <start_byte> peut éventuellement être donné en hexadécimal (par exemple, '--set=0x2:0:1' ou '--set=2h:0:1'). Avec cette forme, l'option --page= est requise pour établir quelle page de mode doit être utilisée.

Chacune des formes peut éventuellement être suivie de « =<val> ». Par défaut, <val> est décimal mais peut être donné en hexadécimal de la manière habituelle. Voici quelques exemples : '--set=2h:0:1=1h' et '-s MRIE=0x3'. Lorsque le nom d'acronyme ou la forme numérique suivant --clear= n'est pas donné avec un '=<val>' explicite, la valeur est par défaut zéro. Lorsque le nom d'acronyme ou la forme numérique suivant --set= n'est pas donné avec un '=<val>' explicite, la valeur par défaut est « tous les uns » (c'est-à-dire autant que <num_bits> le permet). Par exemple, '--clear=WCE' et '--clear=WCE=0' ont la même signification : effacer Writeback Cache Enable ou, plus simplement : désactiver le cache d'écriture.

Plusieurs champs dans la même page de mode peuvent être modifiés en donnant une liste séparée par des virgules d'acronymes et/ou la forme numérique. Par exemple : '--set=TEST,MRIE=6'.

Certaines pages de mode ont plusieurs descripteurs. Elles ont typiquement une section d'en-tête fixe au début de la page de mode qui comprend un champ contenant le nombre de descripteurs qui suivent. Après l'en-tête se trouve un nombre variable de descripteurs. Un exemple est la page de mode SAS Phy Control and Discover. Un nom d'acronyme peut inclure un suffixe '.<num>' où « <num> » est un numéro de descripteur (origine 0). Par exemple, '-t sas -g PHID.0' et '-t sas -g PHID' renverront l'identifiant de phy du premier descripteur de la page de mode ci-dessus ; '-t sas -g PHID.1' renverra l'identifiant de phy du second descripteur.

ENUMERATE

L'option --enumerate vide essentiellement les informations statiques détenues par cet utilitaire. Une liste de variantes de --enumerate et leurs actions suit. Par souci de brièveté, les exemples d'options suivants sont présentés sous leur forme courte.


--enumerate liste des informations génériques sur les pages de mode
-e --all liste du contenu générique des pages de mode
(c'est-à-dire les paramètres)
-e --page=rw liste du contenu de la page de mode de récupération des erreurs de lecture/écriture
-e --inquiry liste des pages VPD que cet utilitaire peut décoder
-e --long liste des pages de mode génériques, des protocoles de transport,
des pages de mode pour chaque protocole de transport pris en charge et
des commandes prises en charge
-e -l --all liste en plus du contenu de chaque page de mode
-e --transport=fcp liste des pages de mode pour le protocole de transport fcp
-e -t fcp --all liste en plus du contenu de chaque page de mode
-e --vendor=sea liste des pages de mode spécifiques au vendeur pour
« sea » (Seagate)
-e -M sea --all liste en plus du contenu des pages de mode spécifiques au

-e -p pcd -l liste du contenu de la page de mode SAS phy control and

Lorsque les pages de mode connues sont listées (via l'option --enumerate), chaque ligne commence par une abréviation de deux ou trois lettres. Celle-ci est suivie du numéro de page (en hexadécimal préfixé par « 0x »), éventuellement suivi d'une virgule et du numéro de sous-page. Enfin, le nom descriptif de la page de mode (par exemple, tel que trouvé dans SPC-4) est affiché.

Lorsque les paramètres connus (champs) d'une page de mode sont listés, chaque ligne commence par un acronyme (indiqué avec quelques espaces). Celui-ci correspondra (ou sera un acronyme pour) la description de ce champ trouvée dans les normes (en projet). Ensuite viennent trois nombres, séparat

édits par des deux-points, entourés d'accolades. Ce sont l'octet de début (en hexadécimal, préfixé par "0x") du début du champ dans la page de mode ; le bit de début (0 à 7 inclus) puis le nombre de bits. Le nom descriptif du paramètre (champ) est ensuite donné. Le cas échéant, le nom descriptif inclut les unités (par exemple, "(ms)" signifie que les unités sont des millisecondes). L'ajout de l'option '-ll' listera des informations sur les valeurs possibles des champs pour des paramètres de page de mode sélectionnés.

Les paramètres de mode pour lesquels num_bits est supérieur à 1 peuvent être visualisés comme des entiers non signés. Souvent, les champs de 16 et 32 bits sont définis sur 0xffff et 0xffffffff respectivement (tous des uns), ce qui a généralement une signification spéciale (voir les brouillons). Cet utilitaire affiche de telles valeurs comme "-1" pour économiser de l'espace (plutôt que leurs équivalents en entiers non signés). "-1" peut également être donné comme valeur à un acronyme de champ de page de mode (par exemple, '--set=INTT=-1' définit le champ de minuteur d'intervalle dans la page de mode de contrôle des exceptions d'information sur 0xffffffff).

TRANSPORTS

Les protocoles de transport SCSI sont un domaine relativement spécialisé qui peut être ignoré en toute sécurité par la majorité des utilisateurs.

Certains protocoles de transport ont des pages de mode spécifiques au protocole. Il s'agit généralement des pages de mode de déconnexion-reconnexion (0x2), de l'unité logique spécifique au protocole (0x18) et du port spécifique au protocole (0x19). Dans certains cas, cette dernière page de mode a plusieurs sous-pages. Les abréviations de protocole de transport les plus courantes susceptibles d'être utilisées sont "fcp", "spi" et "sas".

Beaucoup de noms de champs sont réutilisés dans la même position, de sorte que les espaces de noms d'acronymes ont été divisés entre les pages de mode génériques (c'est-à-dire lorsque l'option --transport n'est _pas_ donnée) et un espace de noms pour chaque protocole de transport. Un champ LUPID de la page de mode d'unité logique spécifique au protocole (0x18) et le champ PPID de la page de mode de port spécifique au protocole (0x19) sont inclus dans les pages de mode génériques ; cela permet de visualiser les identificateurs de protocole (de transport) respectifs. Dans la plupart des cas, l'utilisateur connaîtra le transport du "port" (c'est-à-dire le même transport que celui de la carte HBA dans l'ordinateur), mais le transport de l'unité logique pourrait être différent.

VENDORS

SCSI laisse beaucoup d'espace pour les informations spécifiques au fournisseur. Celles-ci sont souvent décrites dans les manuels des produits. L'option --vendor=VN (ou -M=VN) permet d'examiner et/ou de modifier les pages de mode spécifiques connues du fournisseur par acronyme.

Dans cet utilitaire, la syntaxe et la sémantique des pages de mode spécifiques au fournisseur sont très similaires à celles des pages de mode spécifiques au protocole de transport. Les deux ne peuvent pas être spécifiés ensemble. Les pages de mode spécifiques au fournisseur peuvent toujours être accessibles numériquement (comme montré à la fin de la section EXEMPLES).

COMMANDES

L'option de commande envoie une commande SCSI au DEVICE. Si la commande échoue, cela se reflète dans le statut de sortie non nul. Pour obtenir plus d'informations sur l'erreur, utilisez l'option -v.

capacity
envoie par défaut une commande READ CAPACITY(10) (valide pour les disques et les médias CD/DVD). En cas de succès, elle renvoie "blocks: " [le nombre de blocs], "block_length: " [typiquement 512 ou 2048] et "capacity_mib: " [capacité en MebiOctets (unités de 1048576 octets)].

Si le nombre de blocs est trop grand pour tenir dans le champ de 4 octets fourni par READ CAPACITY(10) ou si l'option --long est donnée, alors la commande READ CAPACITY(16) est envoyée. Si l'option --long est donnée, les champs supplémentaires trouvés dans la réponse READ CAPACITY(16) sont affichés.

eject
arrête le média et l'éjecte du périphérique. Notez que l'éjection (par commande ou bouton) peut être empêchée, auquel cas la commande 'unlock' peut être utile dans les cas extrêmes. Généralement approprié uniquement pour les lecteurs CD/DVD et les lecteurs de disques avec médias amovibles. S'oppose si envoyé à un autre type de périphérique (mais l'opposition peut être annulée avec l'option '-f').
load
charge le média et le démarre (c'est-à-dire le fait tourner). Voir la commande 'eject' pour les types de périphériques pris en charge.
profile
liste les différents formats pris en charge par un lecteur CD/DVD/HD-DVD/BD. Ce sont les "profils" dans la norme MMC. Les profils sont listés un par ligne. Si un média est dans le lecteur, le profil qui correspond au média (le cas échéant) a un "*" à droite de la ligne.
ready
envoie la commande SCSI "Test Unit Ready" au DEVICE. Aucune erreur n'est signalée si le périphérique répond aux requêtes de données (par exemple, READ) dans un délai raisonnable. Par exemple, si un disque est arrêté, il signalera "not ready". Tous les périphériques doivent répondre à cette commande.
sense
envoie une commande REQUEST SENSE. Elle signale un dépassement de seuil matériel, une condition d'avertissement ou une faible alimentation si indiqué. S'il y a une indication de progression (par exemple, pendant un formatage), elle sera affichée en pourcentage. Renvoie un statut de processus de 0 si la commande réussit et que la clé de sens est 0 ; sinon, renvoie 1. L'option --quiet peut être utilisée pour réduire la sortie, et --hex pour afficher les données de sens en hexadécimal.
speed=SPEED
permet de définir (ou du moins d'influencer) la vitesse d'un disque CD, DVD, HD_DVD ou BD dans un lecteur. Elle a ce format : --command=speed=SPEED où SPEED est en kilo-octets par seconde. Dans ce cas, un kilo-octet est de 1000 octets. La vitesse "une fois" pour un CD est de 176.4 Ko/s, pour un DVD est de 1350 Ko/s et pour HD-DVD et BD, elle est de 4500 Ko/s. Si SPEED est zéro, le lecteur est réglé sur la vitesse qu'il considère comme donnant des performances optimales. Cette commande envoie une commande multi-média SET STREAMING (MMC) au lecteur. Le bit EXACT est effacé, de sorte que le lecteur arrondira le SPEED donné si nécessaire. La commande est conçue pour contrôler la vitesse de lecture ; la définition de la vitesse d'écriture doit être laissée aux programmes de "gravure".
start
démarre le média (c'est-à-dire le fait tourner). Sans danger si le média a déjà été démarré. Voir la commande 'eject' pour les types de périphériques pris en charge. Si le DEVICE est un disque ATA sous Linux, l'option '--readonly' peut être nécessaire.
stop
arrête le média (c'est-à-dire le fait tourner). Sans danger si le média a déjà été arrêté. Voir la commande 'eject' pour les types de périphériques pris en charge. Si le DEVICE est un disque ATA sous Linux, l'option '--readonly' peut être nécessaire. Voir la section NOTES ci-dessus.
sync
envoie une commande SYNCHRONIZE CACHE. Le périphérique doit vider toutes les données contenues dans ses tampons (volatils) sur le média.
unlock
indique à un périphérique d'autoriser le retrait du média. Il utilise la commande SCSI "prevent allow medium removal". C'est une mesure de dernier recours, qui peut potentiellement outrepasser une prévention appliquée par le système d'exploitation sur un système de fichiers monté. L'utilitaire "eject" (du paquet "eject") est plus gracieux et devrait être essayé en premier. Cette commande n'est appropriée que pour les périphériques avec des médias amovibles.

Pour le chargement et l'éjection de bandes, l'utilitaire mt doit être utilisé (c'est-à-dire pas ces commandes). La commande 'ready' est valide pour les périphériques de bande.

EXEMPLES

Pour lister les paramètres de mode courants (génériques) d'un disque :


sdparm /dev/sda

Pour lister les descripteurs dans la page VPD d'identification du périphérique d'un disque :


sdparm --inquiry /dev/sda

Pour voir tous les paramètres de la page de mode de mise en cache :


sdparm --page=ca /dev/sda

Pour voir tous les paramètres de la page de mode de mise en cache avec des descriptions de paramètres à droite :


sdparm --page=ca --long /dev/sda

Pour obtenir les valeurs WCE (actuelles, modifiables, par défaut et sauvegardées) en hexadécimal :


sdparm -g WCE -H /dev/sda
0x01 0x00 0x01 0x01

Pour obtenir la valeur actuelle de WCE en hexadécimal :


sdparm -g WCE=1 -H /dev/sda
0x01

Pour définir le bit "Writeback Cache Enable" dans la page des valeurs actuelles :


sdparm --set=WCE /dev/sda

Pour définir le bit "Writeback Cache Enable" dans les pages des valeurs actuelles et sauvegardées :


sdparm --set=WCE --save /dev/sda

Pour définir "Writeback Cache Enable" et effacer "Read Cache Disable" :


sdparm --set=WCE --clear=RCD --save /dev/sda

L'exemple précédent peut également être écrit comme suit :


sdparm -s WCE=1,RCD=0 -S /dev/sda

Pour rétablir les valeurs par défaut du fabricant dans les valeurs actuelles et sauvegardées de la page de mode de mise en cache :


sdparm --page=ca --defaults --save /dev/sda

Si un lecteur CD/DVD ATAPI est sur /dev/hdc, ses paramètres de mode communs peuvent être listés sous Linux 2.6 et 3.x avec :


sdparm /dev/hdc

S'il y a un DVD dans le lecteur sur /dev/hdc, il peut être éjecté sous Linux 2.6 et 3.x avec :


sdparm --command=eject /dev/hdc

Si l'éjection est empêchée par le logiciel, cela peut être annulé avec :


sdparm --command=unlock /dev/hdc

Un fournisseur de disques a un bit "Performance Mode" (PM) dans la page de mode d'alerte d'unité spécifique au fournisseur [0x0,0x0]. PM=0 est le mode serveur (par défaut) tandis que PM=1 est le mode bureau. Le mode bureau peut être défini (valeurs actuelles et sauvegardées) avec :


sdparm --page=0 --set=2:7:1=1 --save /dev/sda

La modification résultante peut être visualisée en hexadécimal avec l'option --hex car il n'y a pas encore d'acronymes pour les extensions spécifiques au fournisseur. Le bit PM est maintenant couvert par les pages de mode spécifiques au fournisseur et ce qui précède peut également être réalisé avec :


sdparm --vendor=sea --set=PM --save /dev/sda

Ce qui suit sont quelques exemples sous Windows utilisant l'option '--wscan'. L'idée est de lister les noms des périphériques de stockage sur le système qui pourraient être invoqués par d'autres utilisations de sdparm.


# sdparm --wscan
PD0 [C] FUJITSU MHY2160BH 0000
PD1 [DF] WD 2500BEV External 1.05 WD-WXE90
CDROM0 [E] MATSHITA DVD/CD

NOM

sdparm - interroger et modifier les paramètres de mode des périphériques SCSI et ATA

SYNTAXE

sdparm [OPTIONS] DEVICE

DESCRIPTION

La commande sdparm interroge et modifie les pages de paramètres de mode des périphériques de stockage SCSI et ATA. Les pages de paramètres de mode permettent de configurer des paramètres opérationnels tels que la mise en cache, la gestion de l'alimentation, la gestion des erreurs, etc. Le comportement précis d'un périphérique peut varier considérablement en fonction de la manière dont les pages de mode sont implémentées par le fabricant.

Si aucun DEVICE n'est donné, l'utilitaire essaie d'ouvrir "/dev/sg0". Les noms de périphériques typiques sont "/dev/sg0", "/dev/sg1", etc. sous Linux. Sous d'autres systèmes d'exploitation, ils peuvent être différents (par exemple, "/dev/esata/1" ou "/dev/disk/ata-device").

Lorsque sdparm est exécuté sans aucune option (à part le nom du périphérique), il affiche une liste des pages de mode de paramètres "standard" et de leurs champs.

Les options les plus courantes sont -a (toutes les pages de mode), -l (lecture des champs) et -s (définition des champs). Il est recommandé de consulter les pages de manuel spécifiques au périphérique ou les spécifications du fabricant pour comprendre les différents paramètres de mode.

L'option -a affiche toutes les pages de mode connues pour le type de périphérique.

Utiliser sdparm -a /dev/cdrom affichera toutes les pages de mode (connues) pour le lecteur CDROM.

Si le périphérique est un disque dur, sdparm -a /dev/sda affichera toutes les pages de mode pour ce disque.

Utiliser sdparm -a sans spécifier de périphérique tentera d'ouvrir "/dev/sg0".

Les exemples suivants montrent comment interroger et modifier des paramètres spécifiques.

Pour afficher tous les paramètres de mode pour le périphérique CDROM nommé CDROM0:


# sdparm -a CDROM0

Pour afficher tous les paramètres de mode pour le périphérique nommé E:


# sdparm -a E

Ces deux commandes montrent tous les champs de la page de mode (connus) pour le lecteur DVD/CD Matshita. En utilisant l'option --wscan deux fois, le type de bus (tel qu'il est vu par le système d'exploitation) est ajouté à la sortie:


# sdparm -ww


PD0 [C] <Ata > FUJITSU MHY2160BH 0000


PD1 [DF] <Usb > WD 2500BEV External 1.05 WD-WXE90


CDROM0 [E] <Atapi> MATSHITA DVD/CDRW UJDA775 CB03

Et le schéma continue pour ajouter un scan de l'adaptateur SCSI. Cela peut être utile s'il existe des périphériques spécialisés liés au stockage (par exemple, un périphérique SES dans un boîtier), mais cela n'ajoute pas beaucoup d'informations supplémentaires dans ce cas.


# sdparm -www


PD0 [C] <Ata > FUJITSU MHY2160BH 0000


PD1 [DF] <Usb > WD 2500BEV External 1.05 WD-WXE90


CDROM0 [E] <Atapi> MATSHITA DVD/CDRW UJDA775 CB03


SCSI0:0,0,0 claimed=1 pdt=0h FUJITSU MHY2160BH 0000


SCSI1:0,0,0 claimed=1 pdt=5h MATSHITA DVD/CDRW UJDA775 CB03

STATUT DE SORTIE

Pour aider les scripts qui appellent sdparm, le statut de sortie est défini pour indiquer le succès (0) ou l'échec (1 ou plus). Notez que certaines des valeurs inférieures correspondent aux valeurs de clé de détection SCSI. Les valeurs de statut de sortie sont:

0
succès
1
erreur de syntaxe. Soit des options de ligne de commande illégales, des options avec des arguments incorrects, soit une combinaison d'options qui n'est pas autorisée.
2
le PÉRIPHÉRIQUE signale qu'il n'est pas prêt pour l'opération demandée. Le périphérique peut être en cours de préparation (par exemple, en rotation mais pas à la bonne vitesse) donc l'utilitaire peut fonctionner après un délai.
3
le PÉRIPHÉRIQUE signale une erreur de support ou matérielle (ou un contrôle de zone vierge). Par exemple, une tentative de lecture d'un bloc corrompu sur un disque produira cette valeur.
5
le PÉRIPHÉRIQUE signale une "requête illégale" avec un code de détection supplémentaire autre que "code d'opération invalide". Il s'agit souvent d'une commande prise en charge avec un champ défini demandant une capacité non prise en charge. Pour les commandes qui nécessitent un champ "action de service", cette valeur peut indiquer que la commande n'est pas prise en charge.
6
le PÉRIPHÉRIQUE signale une condition "d'attention d'unité". Cela indique généralement que quelque chose sans rapport avec la commande demandée s'est produit (par exemple, une réinitialisation du périphérique) potentiellement avant que la commande SCSI actuelle ne soit envoyée. La commande demandée n'a pas été exécutée par le périphérique. Notez que les conditions d'attention d'unité ne sont généralement signalées qu'une seule fois par un périphérique.
7
le PÉRIPHÉRIQUE signale une clé de détection "protection des données". Cela implique qu'un mécanisme a bloqué les écritures (ou potentiellement tout accès au support).
9
le PÉRIPHÉRIQUE signale une requête illégale avec un code de détection supplémentaire de "code d'opération invalide", ce qui signifie qu'il ne prend pas en charge la commande demandée.
10
le PÉRIPHÉRIQUE signale une "copie interrompue". Cela implique qu'une autre commande ou un problème de périphérique a arrêté une opération de copie. La famille de commandes EXTENDED COPY (y compris WRITE USING TOKEN) peut renvoyer cette clé de détection.
11
le PÉRIPHÉRIQUE signale une commande interrompue. Dans certains cas, les commandes interrompues peuvent être retentées immédiatement (par exemple, si le transport a interrompu la commande en raison de la congestion).
14
le PÉRIPHÉRIQUE signale une non-concordance de clé de détection. Les commandes VERIFY et COMPARE AND WRITE peuvent signaler cela.
15
l'utilitaire est incapable d'ouvrir, fermer ou utiliser le PÉRIPHÉRIQUE donné. Le nom de fichier donné pourrait être incorrect ou il peut y avoir des problèmes de permission. L'ajout de l'option -v peut fournir plus d'informations.
20
le PÉRIPHÉRIQUE signale qu'il a une condition de détection mais "pas de détection". Certaines commandes de scrutation (par exemple, REQUEST SENSE) peuvent réagir ainsi. Il est peu probable que cette valeur se produise en tant que statut de sortie.
21
le PÉRIPHÉRIQUE signale une "erreur récupérée". La commande demandée a réussi. Le plus probable est qu'un utilitaire signale une erreur récupérée sur stderr et continue, laissant probablement l'utilitaire avec un statut de sortie de 0.
22
le PÉRIPHÉRIQUE signale que la commande actuelle ou ses paramètres impliquent une adresse de bloc logique (LBA) qui est hors de portée.
24
le PÉRIPHÉRIQUE signale un statut SCSI de "conflit de réservation". Cela signifie que l'accès au PÉRIPHÉRIQUE avec la commande actuelle a été bloqué parce qu'une autre machine (HBA ou "initiateur" SCSI) détient une réservation sur ce PÉRIPHÉRIQUE. Sur les systèmes SCSI modernes, cela est lié à l'utilisation de la famille de commandes PERSISTENT RESERVATION.
25
le PÉRIPHÉRIQUE signale un statut SCSI de "condition remplie". Actuellement, seule la commande PRE-FETCH (voir SBC-4) renvoie ce statut.
26
le PÉRIPHÉRIQUE signale un statut SCSI de "occupé". SAM-5 définit ce statut comme l'unité logique étant temporairement incapable de traiter une commande. Il est recommandé de réémettre la commande.
27
le PÉRIPHÉRIQUE signale un statut SCSI de "task set full".
28
le PÉRIPHÉRIQUE signale un statut SCSI de "ACA active". ACA signifie "auto contingent allegiance" et est rarement utilisé.
29
le PÉRIPHÉRIQUE signale un statut SCSI de "task aborted". SAM-5 dit: "Ce statut doit être renvoyé si une commande est interrompue par une commande ou une fonction de gestion de tâche sur un autre nexus I_T et que le bit TAS de la page de mode Control est défini sur un".
33
la commande envoyée au PÉRIPHÉRIQUE a expiré. Cela se produit uniquement sous Linux; dans d'autres ports, un délai d'attente de commande apparaîtra comme une erreur de transport (ou système).
40
la commande envoyée au PÉRIPHÉRIQUE a reçu une clé de détection "commande interrompue" avec un code de détection supplémentaire de 0x10. Cette valeur est liée aux problèmes d'informations de protection (PI ou DIF). Par exemple, cette erreur peut survenir lors de la lecture d'un bloc sur un lecteur qui n'a jamais été écrit (ou qui est non mappé) si ce lecteur a été formaté avec une protection de type 1, 2 ou 3.
48
il s'agit d'un message interne indiquant qu'un champ de statut NVMe (SF) est différent de zéro après l'exécution d'une commande (c'est-à-dire que quelque chose s'est mal passé). Le travail dans ce domaine est actuellement expérimental.
49
le pilote de bas niveau signale un nombre résiduel de réponse (c'est-à-dire que le nombre d'octets réellement reçus par le HBA est 'octets_demandés - nombre_résiduel') qui est trop élevé. Ainsi, aucun traitement utile ne peut être effectué avec cette réponse.
50 + <os_error_number>
Les appels système qui échouent renvoient souvent un petit nombre entier pour aider à indiquer ce qu'est l'erreur. Par exemple, sous Unix, l'incapacité d'un appel système à allouer de la mémoire renvoie (dans 'errno') ENOMEM, qui est souvent associé à l'entier 12. Ainsi, 62 (c'est-à-dire '50 + 12') peut être renvoyé par un utilitaire dans ce cas.
97
la réponse à une commande SCSI a échoué aux contrôles de cohérence.
98
le PÉRIPHÉRIQUE signale qu'il a une condition de détection mais que l'erreur ne rentre dans aucune des catégories ci-dessus.
99
toutes les erreurs qui ne peuvent pas être catégorisées dans les valeurs 1 à 98 peuvent produire cette valeur. Cela inclut les erreurs de transport et de système d'exploitation après l'envoi de la commande au périphérique.
126
l'utilitaire a été trouvé mais n'a pas pu être exécuté. Cela pourrait se produire si l'exécutable n'a pas les permissions d'exécution.
127
C'est le statut de sortie pour l'utilitaire introuvable. Cela pourrait se produire lorsqu'un script appelle un utilitaire de ce paquet mais que la variable d'environnement PATH n'a pas été correctement configurée, de sorte que le script ne trouve pas l'exécutable.
128 + <signum>
Si un signal tue un utilitaire, le statut de sortie est 128 plus le numéro du signal. Par exemple, si une erreur de segmentation se produit, un utilitaire est généralement tué par SIGSEGV qui, selon 'man 7 signal', a un numéro de signal associé de 11; le statut de sortie sera donc 139.
255
l'utilitaire a tenté de renvoyer un statut de sortie de 255 ou plus. Cela ne devrait pas se produire; donné ici pour la complétude.

La plupart des conditions d'erreur signalées ci-dessus seront répétables (un exemple de celle qui ne l'est pas est "attention d'unité") donc l'utilitaire peut être exécuté à nouveau avec l'option -v (ou plusieurs) pour obtenir plus d'informations.
