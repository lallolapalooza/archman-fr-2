#include <systemd/sd-event.h>

DESCRIPTION

sd_event_add_child() ajoute une nouvelle source d'événement de changement d'état de processus enfant à une boucle d'événements. L'objet de boucle d'événements est spécifié dans le paramètre event, l'objet de source d'événement est renvoyé dans le paramètre source. Le paramètre pid spécifie le PID du processus à surveiller, qui doit être un processus enfant direct du processus appelant. Le paramètre options détermine quels changements d'état seront surveillés. Il doit contenir un masque OR de WEXITED (surveiller la terminaison du processus enfant), WSTOPPED (surveiller l'arrêt du processus enfant par un signal), et WCONTINUED (surveiller la reprise du processus enfant par un signal). Voir waitid(2) pour plus d'informations.

Le handler doit être une fonction à appeler lorsque le processus change d'état, ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure siginfo_t contenant des informations sur l'événement du processus enfant. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul gestionnaire peut être installé pour un processus enfant spécifique. Le gestionnaire est activé pour un seul événement (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire renvoie un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, ou elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est supprimée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même s'il y a encore une référence à elle, envisagez de définir la source d'événement sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Le signal SIGCHLD doit être bloqué dans tous les threads avant d'appeler cette fonction (en utilisant sigprocmask(2) ou pthread_sigmask(3)).

Si le deuxième paramètre de sd_event_add_child() est passé comme NULL, aucune référence à l'objet source d'événement n'est renvoyée. Dans ce cas, la source d'événement est considérée comme "flottante", et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Notez que la fonction handler est invoquée à un moment où le processus enfant n'est pas encore réclamé (et est donc encore exposé comme un processus zombie par le noyau). Cependant, l'enfant sera réclamé automatiquement après le retour de la fonction. Les processus enfants pour lesquels aucune source d'événement de changement d'état de processus enfant n'est installée ne seront pas réclamés par l'implémentation de la boucle d'événements.

Si le paramètre handler de sd_event_add_child() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Si à la fois une source d'événement de changement d'état de processus enfant et une source d'événement de signal SIGCHLD sont installées dans la même boucle d'événements, les priorités configurées des sources d'événements décident quelle source d'événement est traitée en premier. Si le gestionnaire de signaux est traité en premier, il doit laisser les processus enfants pour lesquels des sources d'événements de processus enfants sont installés non réclamés.

sd_event_add_child_pidfd() est similaire à sd_event_add_child() mais prend un descripteur de fichier référençant le processus ("pidfd") au lieu du PID numérique. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2) et les appels associés. Le descripteur de fichier passé n'est pas fermé lorsque la source d'événement est à nouveau libérée, sauf si sd_event_source_set_child_pidfd_own() est utilisé pour activer ce comportement. Notez que, quelle que soit la fonction utilisée, sd_event_add_child() ou sd_event_add_child_pidfd(), pour allouer une source d'événement, le processus surveillé doit être un processus enfant direct du processus appelant. Dans les deux cas, SIGCHLD doit être bloqué dans le processus appelant.

sd_event_source_get_child_pid() récupère le PID configuré d'une source d'événement de changement d'état de processus enfant créée précédemment avec sd_event_add_child(). Elle prend l'objet source d'événement comme paramètre source et un pointeur vers une variable de type pid_t pour y renvoyer l'identifiant du processus.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier référençant le processus surveillé ("pidfd"). La boucle d'événements utilise en interne des pidfd pour surveiller les processus enfants, que les sources d'événements individuelles soient allouées via sd_event_add_child() ou sd_event_add_child_pidfd(). Si le dernier appel a été utilisé pour allouer la source d'événement, cette fonction renvoie le descripteur de fichier original utilisé pour l'allocation. Cet appel prend l'objet source d'événement comme paramètre source et renvoie le descripteur de fichier numérique.

sd_event_source_get_child_pidfd_own() peut être utilisé pour interroger si le pidfd que la source d'événement encapsule doit être fermé lorsque la source d'événement est libérée. Cette fonction renvoie zéro si le pidfd doit être laissé ouvert, et une valeur positive s'il doit être fermé automatiquement. Par défaut, ce réglage est activé si la source d'événement a été allouée via sd_event_add_child() et désactivé si elle a été allouée via sd_event_add_child_pidfd(). La fonction sd_event_source_set_child_pidfd_own() peut être utilisée pour changer le réglage et prend un paramètre booléen avec le nouveau réglage.

sd_event_source_get_child_process_own() peut être utilisé pour interroger si le processus que la source d'événement surveille doit être tué (avec SIGKILL) et réclamé lorsque la source d'événement est libérée. Cette fonction renvoie zéro si le processus doit être laissé en cours d'exécution, et une valeur positive s'il doit être tué et réclamé automatiquement. Par défaut, ce réglage est désactivé. sd_event_source_send_child_signal(3)

NAME

sd_event_add_child, sd_event_source_get_child_pid, sd_event_add_child_pidfd, sd_event_source_get_child_pidfd, sd_event_source_get_child_pidfd_own, sd_event_source_set_child_pidfd_own, sd_event_source_get_child_process_own, sd_event_source_set_child_process_own, sd_event_source_send_child_signal - ajouter un événement de processus enfant à une boucle d'événements, interroger et envoyer des signaux

SYNOPSIS

#include <systemd/sd-event.h>
int sd_event_add_child(sd_event *event, sd_event_source **source, pid_t pid, int events, sd_event_child_handler_t *callback, void *userdata);
int sd_event_add_child_pidfd(sd_event *event, sd_event_source **source, int pidfd, int events, sd_event_child_handler_t *callback, void *userdata);
int sd_event_source_get_child_pid(sd_event_source *source, pid_t *pid);
int sd_event_source_get_child_pidfd(sd_event_source *source, int *pidfd);
int sd_event_source_get_child_pidfd_own(sd_event_source *source, bool *own);
int sd_event_source_set_child_pidfd_own(sd_event_source *source, bool own);
int sd_event_source_get_child_process_own(sd_event_source *source, bool *own);
int sd_event_source_set_child_process_own(sd_event_source *source, bool own);
int sd_event_source_send_child_signal(sd_event_source *source, int signo, const union sigval *value);

DESCRIPTION

Ces fonctions permettent de surveiller les processus enfants et d'être notifié de leur changement d'état via une boucle d'événements sd-event(3). Les signaux SIGCHLD sont utilisés pour la signalisation des changements d'état des enfants.

sd_event_add_child() ajoute une nouvelle source d'événement à la boucle d'événements event qui surveille le processus enfant spécifié par pid. Lorsque le processus enfant change d'état (par exemple, se termine, est arrêté), la fonction de rappel callback est appelée avec userdata comme argument.

Le paramètre events est un masque d'options qui spécifie les événements à surveiller. Il peut s'agir d'une combinaison des drapeaux suivants :

  • WEXITED : notifier lorsque le processus enfant se termine.
  • WSTOPPED : notifier lorsque le processus enfant est arrêté par un signal.
  • WCONTINUED : notifier lorsque le processus enfant est repris après avoir été arrêté.

Si events est zéro, tous les événements spécifiés par waitid(2) sont surveillés.

sd_event_add_child_pidfd() fonctionne de manière similaire à sd_event_add_child(), mais utilise un descripteur de fichier de processus (pidfd) pour identifier le processus enfant au lieu d'un identifiant de processus (pid). Cela permet de surveiller des processus qui pourraient avoir changé de PID après leur création.

sd_event_source_get_child_pid() récupère l'identifiant du processus enfant surveillé par la source d'événement source.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier de processus (pidfd) associé à la source d'événement source.

sd_event_source_get_child_pidfd_own() et sd_event_source_set_child_pidfd_own() permettent de déterminer et de définir si la source d'événement possède le descripteur de fichier de processus. Si la source possède le pidfd, il sera fermé lorsque la source d'événement sera désactivée ou retirée.

sd_event_source_get_child_process_own() et sd_event_source_set_child_process_own() permettent de déterminer et de définir si la source d'événement possède le processus enfant. Si la source possède le processus enfant, cela signifie qu'elle est responsable de son nettoyage (par exemple, en appelant waitid(2) sur celui-ci). Cela peut être utile pour s'assurer qu'un processus enfant ne soit pas laissé orphelin.

Notez que si le processus appelant se termine anormalement, le processus surveillé pourrait survivre même si la source d'événement cesse d'exister. Ce comportement pourrait changer à l'avenir.

sd_event_source_send_child_signal() peut être utilisé pour envoyer un signal UNIX au processus surveillé via pidfd_send_signal(2). Les paramètres spécifiés correspondent à ceux de l'appel système sous-jacent, à l'exception du fait que info n'est jamais modifié (et est donc déclaré constant). Comme pour l'appel système sous-jacent, le paramètre flags doit actuellement être zéro.

RETURN VALUE

En cas de succès, ces fonctions renvoient 0 ou un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Errors

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque vide dans options ou d'un masque contenant des valeurs autres qu'une combinaison de WEXITED, WSTOPPED et WCONTINUED.

-EBUSY

Un gestionnaire est déjà installé pour ce processus enfant, ou SIGCHLD n'est pas bloqué.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

-EDOM

La source d'événement passée n'est pas une source d'événement de processus enfant.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme lorsque aucun autre thread n'a été démarré.

EXAMPLE

Exemple 1. Quitter la boucle lorsque l'enfant se termine

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* Le signal SIGCHLD doit être bloqué pour que sd_event_add_child fonctionne */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* enfant */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Créer la boucle d'événements par défaut */
    sd_event_default(&e);
    assert(e);
    /* Nous créons une source d'événement enfant flottante (attachée à 'e').
     * Le gestionnaire par défaut sera appelé avec 666 comme userdata, qui
     * deviendra la valeur de sortie de la boucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
