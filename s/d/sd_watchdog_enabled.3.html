SD_WATCHDOG_ENABLED(3) sd_watchdog_enabled SD_WATCHDOG_ENABLED(3)

NOM

sd_watchdog_enabled - Vérifie si le gestionnaire de services attend des notifications de garde (watchdog) d'un service

SYNTAXE

#include <systemd/sd-daemon.h>

int sd_watchdog_enabled(int unset_environment, uint64_t *usec);

DESCRIPTION

sd_watchdog_enabled() peut être appelée par un service pour détecter si le gestionnaire de services attend des événements réguliers de notification de garde (watchdog) de sa part, et le délai après lequel le gestionnaire agira sur le service s'il n'a pas reçu une telle notification.

Si la variable d'environnement $WATCHDOG_USEC est définie, et que la variable $WATCHDOG_PID est non définie ou définie avec le PID du processus courant, le gestionnaire de services attend des notifications de ce processus. Le gestionnaire terminera généralement un service lorsqu'il ne reçoit pas de message de notification dans le temps spécifié après le démarrage et après chaque message précédent. Il est recommandé qu'un démon envoie un message de notification de garde au gestionnaire de services toutes les moitiés du temps retourné ici. Les messages de notification peuvent être envoyés avec sd_notify(3) avec la chaîne de message "WATCHDOG=1".

Si le paramètre unset_environment est non nul, sd_watchdog_enabled() annulera les variables d'environnement $WATCHDOG_USEC et $WATCHDOG_PID avant de retourner (indépendamment du fait que l'appel de fonction lui-même ait réussi ou non). Ces variables ne seront plus héritées par les processus enfants. Les appels ultérieurs à sd_watchdog_enabled() retourneront également zéro.

Si le paramètre usec n'est pas NULL, sd_watchdog_enabled() écrira le délai en μs pour la logique de garde dans celui-ci.

Pour activer la supervision de service avec la logique de garde, utilisez WatchdogSec= dans les fichiers de service. Voir systemd.service(5) pour les détails.

Utilisez sd_event_set_watchdog(3) pour activer la prise en charge automatique de la garde dans les boucles d'événements basées sur sd-event(3).

VALEUR DE RETOUR

En cas d'échec, cet appel retourne un code d'erreur négatif de style errno. Si le gestionnaire de services attend l'envoi de messages de notification de garde, > 0 est retourné, sinon 0 est retourné. Ce n'est que si la valeur de retour est > 0 que le paramètre usec est valide après l'appel.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme lorsque aucun autre thread n'a été démarré.

En interne, cette fonction analyse les variables d'environnement $WATCHDOG_PID et $WATCHDOG_USEC. L'appel ignorera ces variables si $WATCHDOG_PID ne contient pas le PID du processus courant, partant du principe que, dans ce cas, les variables ont été définies pour un autre processus plus haut dans l'arbre des processus.

ENVIRONNEMENT

$WATCHDOG_PID

Défini par le gestionnaire système pour le processus supervisé pour lequel la prise en charge de la garde est activée, et contient le PID de ce processus. Voir ci-dessus pour les détails.

Ajouté dans la version 209.

$WATCHDOG_USEC

Défini par le gestionnaire système pour le processus supervisé pour lequel la prise en charge de la garde est activée, et contient le délai de la garde en μs. Voir ci-dessus pour les détails.

Ajouté dans la version 209.

HISTORIQUE

sd_watchdog_enabled() a été ajouté dans la version 209.
