sd_id128_to_uuid_string(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_ID128_TO_STRING(3) sd_id128_to_string SD_ID128_TO_STRING(3)

NOM

sd_id128_to_string, SD_ID128_TO_STRING, SD_ID128_STRING_MAX, sd_id128_to_uuid_string, SD_ID128_TO_UUID_STRING, SD_ID128_UUID_STRING_MAX, sd_id128_from_string - Formater ou analyser des identifiants 128 bits en chaînes de caractères

SYNTAXE

#include <systemd/sd-id128.h>
#define SD_ID128_STRING_MAX 33U
#define SD_ID128_UUID_STRING_MAX 37U
#define SD_ID128_TO_STRING(id) ...
#define SD_ID128_TO_UUID_STRING(id) ...

char *sd_id128_to_string(sd_id128_t id, char s[static SD_ID128_STRING_MAX]);

char *sd_id128_to_uuid_string(sd_id128_t id, char s[static SD_ID128_UUID_STRING_MAX]);

int sd_id128_from_string(const char *s, sd_id128_t *ret);

DESCRIPTION

sd_id128_to_string() formate un identifiant 128 bits en une chaîne de caractères. Il attend l'identifiant et un tableau de caractères capable de stocker 33 caractères (SD_ID128_STRING_MAX). L'identifiant sera formaté en 32 chiffres hexadécimaux minuscules et se terminera par un octet NUL.

SD_ID128_TO_STRING() est une macro qui encapsule sd_id128_to_string() et passe un tampon de taille appropriée comme deuxième argument, alloué sous forme de littéral composé C99. Chaque utilisation acquerra ainsi implicitement un tampon approprié sur la pile qui restera valide jusqu'à la fin du bloc de code actuel. C'est généralement la manière la plus simple d'obtenir une représentation sous forme de chaîne d'un identifiant 128 bits dans un tampon valide dans le bloc de code actuel.

sd_id128_to_uuid_string() et SD_ID128_TO_UUID_STRING() sont similaires à ces deux fonctions/macros, mais formatent les valeurs 128 bits en UUID RFC4122, c'est-à-dire une série de 36 chiffres hexadécimaux minuscules et de tirets, terminés par un octet NUL.

sd_id128_from_string() implémente l'opération inverse : il prend une chaîne de 33 caractères avec 32 chiffres hexadécimaux (minuscules ou majuscules, terminés par NUL) et les analyse à nouveau en un identifiant 128 bits retourné dans ret. Alternativement, cet appel peut également analyser une chaîne de 37 caractères avec un identifiant 128 bits formaté en UUID RFC. Si ret est passé comme NULL, la fonction validera la chaîne d'identifiant passée, mais ne la retournera pas sous forme analysée.

Notez que lors du formatage et de l'analyse des UUID de 36 caractères, cela est fait strictement en ordre d'octets Big Endian, c'est-à-dire conformément aux règles de la variante 1 de la RFC4122[1], même si l'UUID encode une variante différente. Cela correspond au comportement de divers autres outils de l'espace utilisateur Linux. Il est probablement sage d'éviter les UUID d'autres types de variantes.

Pour plus d'informations sur le type "sd_id128_t", voir sd-id128(3). Notez que ces appels fonctionnent de la même manière sur toutes les architectures, c'est-à-dire que les résultats ne dépendent pas de l'endianness.

Lors du formatage d'un identifiant 128 bits en chaîne, il est souvent plus facile d'utiliser une chaîne de format pour printf(3). Ceci est facilement réalisable à l'aide des macros SD_ID128_FORMAT_STR et SD_ID128_FORMAT_VAL(). Pour plus d'informations, voir sd-id128(3).

VALEUR DE RETOUR

sd_id128_to_string() réussit toujours et retourne un pointeur vers le tableau de chaînes passé. sd_id128_from_string() retourne 0 en cas de succès, auquel cas ret est rempli, ou un code d'erreur négatif de style errno.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multithreads. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_id128_to_string() et sd_id128_from_string() ont été ajoutées dans la version 187.

sd_id128_to_uuid_string() a été ajoutée dans la version 251.
