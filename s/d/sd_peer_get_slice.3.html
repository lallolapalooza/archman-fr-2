DESCRIPTION

sd_pid_get_owner_uid() peut être utilisé pour déterminer l'UID Unix (identifiant utilisateur) qui possède la session de connexion ou l'unité utilisateur systemd d'un processus identifié par le PID spécifié. Pour les processus qui ne font pas partie d'une session de connexion et ne sont pas gérés par un gestionnaire utilisateur, cette fonction échouera avec -ENODATA.

sd_pid_get_session() peut être utilisé pour déterminer l'identifiant de session de connexion d'un processus identifié par l'identifiant de processus spécifié. L'identifiant de session est une courte chaîne de caractères, adaptée à une utilisation dans les chemins de système de fichiers. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateur peuvent être démarrés à partir de leur gestionnaire utilisateur systemd, par exemple les applications graphiques démarrées via l'activation DBus, ainsi que les processus de service partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session de connexion, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_user_unit() peut être utilisé pour déterminer l'identifiant de l'unité utilisateur systemd (c'est-à-dire le service ou l'unité de portée utilisateur) d'un processus identifié par le PID spécifié. Le nom de l'unité est une courte chaîne de caractères, adaptée à une utilisation dans les chemins de système de fichiers. Pour les processus qui ne sont pas gérés par un gestionnaire utilisateur, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_unit() peut être utilisé pour déterminer l'identifiant de l'unité système systemd (c'est-à-dire le service ou l'unité de portée système) d'un processus identifié par le PID spécifié. Le nom de l'unité est une courte chaîne de caractères, adaptée à une utilisation dans les chemins de système de fichiers. Notez que tous les processus ne font pas partie d'une unité/service système. Pour les processus qui ne font pas partie d'une unité système systemd, cette fonction échouera avec -ENODATA. (Plus spécifiquement, cet appel ne fonctionnera pas pour les threads du noyau.) La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_machine_name() peut être utilisé pour déterminer le nom de la VM ou du conteneur auquel le processus appartient. Le nom de la machine est une courte chaîne de caractères, adaptée à une utilisation dans les chemins de système de fichiers. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation. Pour les processus qui ne font pas partie d'une VM ou d'un conteneur, cette fonction échoue avec -ENODATA.

sd_pid_get_slice() peut être utilisé pour déterminer l'unité de tranche (slice) à laquelle le processus appartient. Voir systemd.slice(5) pour plus de détails sur les tranches. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

De même, sd_pid_get_user_slice() renvoie la tranche utilisateur (telle que gérée par l'instance systemd de l'utilisateur) d'un processus.

sd_pid_get_cgroup() renvoie le chemin du groupe de contrôle du processus spécifié, relatif à la racine de la hiérarchie. Renvoie le chemin sans barre oblique finale, sauf pour les processus situés dans le groupe de contrôle racine, où "/" est renvoyé. Pour trouver le chemin réel du groupe de contrôle dans le système de fichiers, le chemin retourné doit être préfixé par /sys/fs/cgroup/.

Si le paramètre pid de l'une de ces fonctions est passé à 0, l'opération est exécutée pour le processus appelant.

Les appels sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() et sd_pidfd_get_cgroup() fonctionnent de manière similaire à leurs homologues PID, mais acceptent un PIDFD au lieu d'un PID, ce qui signifie qu'ils ne sont pas sujets aux conditions de concurrence de recyclage car le processus est épinglé par le descripteur de fichier pendant toute la durée de l'invocation. Notez que ces appels nécessitent un noyau qui prend en charge PIDFD. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2).

Les appels sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() et sd_peer_get_cgroup() fonctionnent de manière similaire à leurs homologues PID, mais acceptent un socket AF_UNIX connecté et récupèrent des informations sur le processus pair connecté. Notez que ces champs sont récupérés via /proc/, et ne conviennent donc pas à des fins d'autorisation, car ils sont sujets à des conditions de concurrence.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ESRCH

Le PID spécifié ne correspond pas à un processus en cours d'exécution.

-EBADF

Le descripteur de fichier spécifié est invalide.

-ENODATA

Le champ spécifié n'est pas défini pour le processus ou le pair décrit.

-EINVAL

Un argument invalide a été fourni.

-EACCES

L'appelant n'a pas les permissions nécessaires pour lire les informations de l'autre processus.

EXEMPLES

Exemple 1. Obtenir l'UID propriétaire d'un PID

```c

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <systemd/sd-login.h>

int main(int argc, char *argv[]) {
    pid_t pid;
    uid_t uid;
    int ret;

    if (argc < 2) {
        fprintf(stderr, "Usage: %s <pid>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    pid = (pid_t)atoi(argv[1]);

    ret = sd_pid_get_owner_uid(pid, &uid);
    if (ret < 0) {
        fprintf(stderr, "Failed to get owner UID for PID %d: %s\n", pid, strerror(-ret));
        exit(EXIT_FAILURE);
    }

    printf("Owner UID for PID %d: %u\n", pid, uid);

    exit(EXIT_SUCCESS);
}

```

Exemple 2. Obtenir l'unité utilisateur d'un PID

```c

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <systemd/sd-login.h>

int main(int argc, char *argv[]) {
    pid_t pid;
    char *unit = NULL;
    int ret;

    if (argc < 2) {
        fprintf(stderr, "Usage: %s <pid>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    pid = (pid_t)atoi(argv[1]);

    ret = sd_pid_get_user_unit(pid, &unit);
    if (ret < 0) {
        fprintf(stderr, "Failed to get user unit for PID %d: %s\n", pid, strerror(-ret));
        exit(EXIT_FAILURE);
    }

    printf("User unit for PID %d: %s\n", pid, unit);

    free(unit); // Free the allocated string
    exit(EXIT_SUCCESS);
}

```

Exemple 3. Obtenir l'unité système d'un socket pair

```c

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/socket.h>
#include <systemd/sd-login.h>

int main() {
    int sock_pair[2];
    char *unit = NULL;
    int ret;

    // Create a AF_UNIX socket pair
    if (socketpair(AF_UNIX, SOCK_STREAM, 0, sock_pair) < 0) {
        perror("socketpair");
        exit(EXIT_FAILURE);
    }

    // In a real scenario, one process would hold sock_pair[0] and
    // the other would hold sock_pair[1]. Here, we'll just use sock_pair[1]
    // to query the peer of sock_pair[0].

    ret = sd_peer_get_unit(sock_pair[1], &unit);
    if (ret < 0) {
        fprintf(stderr, "Failed to get unit of socket peer: %s\n", strerror(-ret));
        close(sock_pair[0]);
        close(sock_pair[1]);
        exit(EXIT_FAILURE);
    }

    printf("Unit of socket peer: %s\n", unit);

    free(unit); // Free the allocated string
    close(sock_pair[0]);
    close(sock_pair[1]);
    exit(EXIT_SUCCESS);
}

```

sd_peer_get_slice.3.en — systemd 258.2

NAME

sd_peer_get_slice, sd_pid_get_slice, sd_pidfd_get_slice, sd_peer_get_user_slice, sd_pid_get_user_slice, sd_pidfd_get_user_slice — Get the systemd slice unit name of a peer process

SYNOPSIS

#include <systemd/sd-login.h>

int sd_peer_get_slice(int pid, const char **slice);
int sd_pid_get_slice(int pid, const char **slice);
int sd_pidfd_get_slice(int pidfd, const char **slice);

int sd_peer_get_user_slice(int pid, const char **slice);
int sd_pid_get_user_slice(int pid, const char **slice);
int sd_pidfd_get_user_slice(int pidfd, const char **slice);

DESCRIPTION

These functions retrieve the systemd slice unit name (see systemd.slice(5)) that a given process belongs to. The process is identified by its process ID (pid) or by a file descriptor referring to it (pidfd).

The sd_peer_get_slice(), sd_peer_get_user_slice() functions may be used to query any process that the calling process has permission to query. The sd_pid_get_slice(), sd_pid_get_user_slice() functions are similar, but they may only be used to query the calling process itself. The sd_pidfd_get_slice() and sd_pidfd_get_user_slice() functions operate on a process specified by an open pidfd, which should have been created with the PIDFD_SPECIFIC flag. This is useful for querying properties of a process after it has potentially terminated.

The sd_peer_get_slice(), sd_pid_get_slice(), sd_pidfd_get_slice() functions retrieve the name of the "system" slice the process belongs to. This is usually one of system.slice, user.slice, machine.slice, etc.

The sd_peer_get_user_slice(), sd_pid_get_user_slice(), sd_pidfd_get_user_slice() functions retrieve the name of the "user" slice the process belongs to. This is usually a slice named like user-*.slice.

If successful, the functions will allocate memory for the slice name string and store a pointer to it in the memory pointed to by slice. The caller must free this memory using free(3).

The slice names are typically of the form name.slice, where name is a combination of the unit name and potentially the user id, depending on how the process was started. For instance, a service running as root might be in system.slice, while a user's graphical session might be in user-1000.slice.

See also sd_pid_get_unit(3), sd_pid_get_machine_name(3), and sd_pid_get_session(3).

RETURN VALUE

On success, these functions return a non-negative value, typically 0. On failure, they return a negative error number.

-EINVAL
An input parameter was invalid (out of range, or NULL, where that is not accepted).
-ENOMEM
Memory allocation failed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

Note that the login session identifier as returned by sd_pid_get_session() is completely unrelated to the process session identifier as returned by getsid(2).
