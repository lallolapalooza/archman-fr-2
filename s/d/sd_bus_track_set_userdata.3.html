NOM

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_track_new(sd_bus* bus, sd_bus_track** ret, sd_bus_track_handler_t handler, void* userdata);

sd_bus_track *sd_bus_track_ref(sd_bus_track *t);

sd_bus_track *sd_bus_track_unref(sd_bus_track *t);

void sd_bus_track_unrefp(sd_bus_track **t);

int sd_bus_track_get_recursive(sd_bus_track *t);

int sd_bus_track_set_recursive(sd_bus_track *t, int b);

sd_bus* sd_bus_track_get_bus(sd_bus_track *t);

void* sd_bus_track_get_userdata(sd_bus_track *t);

void* sd_bus_track_set_userdata(sd_bus_track *t, void *userdata);

DESCRIPTION

sd_bus_track_new() crée un nouvel objet de suivi des pairs du bus. L'objet est alloué pour le bus spécifié et est retourné dans le paramètre *ret. Après utilisation, l'objet doit être libéré en retirant la référence acquise avec sd_bus_track_unref() (voir ci-dessous). Un objet de suivi des pairs du bus peut être utilisé pour garder une trace des pairs sur un bus IPC spécifique, pour les cas où les pairs utilisent un ou plusieurs objets locaux, afin de contrôler le cycle de vie des objets locaux et de s'assurer qu'ils restent présents tant que les pairs qui en ont besoin sont là, et qu'ils sont détruits (et éventuellement éliminés) dès que tous les pairs pertinents ont disparu. Chaque objet de suivi des pairs du bus peut être utilisé pour suivre zéro, un ou plusieurs pairs à un moment donné. Les références aux pairs spécifiques du bus sont ajoutées via sd_bus_track_add_name(3) ou sd_bus_track_add_sender(). Elles peuvent être retirées via sd_bus_track_remove_name() et sd_bus_track_remove_sender(). Alternativement, les références aux pairs sont supprimées automatiquement lorsqu'ils se déconnectent du bus. Si le paramètre handler n'est pas NULL, il peut spécifier une fonction qui est appelée chaque fois que la dernière référence est retirée, que la référence soit retirée explicitement via sd_bus_track_remove_name() ou implicitement parce que le pair s'est déconnecté du bus. L'argument final userdata peut être utilisé pour attacher un pointeur générique de données utilisateur à l'objet. Ce pointeur est passé au rappel du gestionnaire lorsqu'il est appelé.

sd_bus_track_ref() crée une nouvelle référence à un objet de suivi des pairs du bus. Cet objet ne sera pas détruit tant que sd_bus_track_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, l'objet spécifié ne peut plus être utilisé, les appels ultérieurs à sd_bus_track_ref() ou sd_bus_track_unref() sur le même objet sont illégaux.

sd_bus_track_unref() détruit une référence à un objet de suivi des pairs du bus.

sd_bus_track_unrefp() est similaire à sd_bus_track_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_track. Cet appel est utile en conjonction avec l'attribut de variable Clean-up[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_bus_track_ref(), sd_bus_track_unref() et sd_bus_track_unrefp() n'exécutent aucune opération si l'objet de suivi des pairs du bus passé est NULL.

Les objets de suivi des pairs du bus peuvent exister dans deux modes : par défaut, ils fonctionnent en mode non récursif, mais peuvent optionnellement être basculés en mode récursif. En mode non récursif par défaut, un pair est soit suivi, soit non suivi. Dans ce mode, appeler sd_bus_track_add_name() plusieurs fois de suite pour le même pair est équivalent à l'appeler une seule fois, car l'appel ajoute le pair à l'ensemble des pairs suivis si nécessaire, et n'exécute aucune opération si le pair est déjà suivi. Un seul appel à sd_bus_track_remove_name() retire à nouveau la référence au pair, quel que soit le nombre de fois où sd_bus_track_add_name() a été appelé auparavant. En mode récursif, le nombre de fois où sd_bus_track_add_name() est appelé pour le même nom de pair est compté, et sd_bus_track_remove_name() doit être appelé le même nombre de fois avant que le pair ne soit plus suivi, à l'exception du cas où le pair suivi disparaît du bus, auquel cas le compte est sans pertinence et le suivi du pair spécifique est immédiatement supprimé. sd_bus_track_get_recursive() peut être utilisé pour déterminer si l'objet de suivi des pairs du bus fonctionne en mode récursif. sd_bus_track_set_recursive() peut être utilisé pour activer ou désactiver le mode récursif. Par défaut, un objet de suivi des pairs du bus fonctionne en mode non récursif, et sd_bus_track_get_recursive() pour un objet nouvellement alloué retourne donc une valeur égale à zéro. Utilisez sd_bus_track_set_recursive() pour activer le mode récursif, juste après l'allocation. Il prend un argument booléen pour activer ou désactiver le mode récursif. Notez que les objets de suivi pour lesquels sd_bus_track_add_name() a déjà été appelé au moins une fois (et qui suivent donc déjà un ou plusieurs pairs) ne peuvent plus être basculés du mode récursif au mode non récursif.

sd_bus_track_get_bus() retourne l'objet bus auquel appartient l'objet de suivi des pairs du bus. Il retourne l'objet bus initialement passé à sd_bus_track_new() lors de l'allocation de l'objet.

sd_bus_track_get_userdata() retourne le pointeur générique de données utilisateur défini sur l'objet de suivi des pairs du bus au moment de la création à l'aide de sd_bus_track_new() ou ultérieurement, à l'aide de sd_bus_track_set_userdata().

VALEUR DE RETOUR

En cas de succès, sd_bus_track_new() et sd_bus_track_set_recursive() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

sd_bus_track_ref() retourne toujours l'argument.

sd_bus_track_unref() retourne toujours NULL.

sd_bus_track_get_recursive() retourne 0 si le mode non récursif est sélectionné (par défaut), et supérieur à 0 si le mode récursif est sélectionné. En cas d'échec, un code d'erreur négatif de style errno est retourné.

sd_bus_track_get_bus() retourne l'objet bus associé à l'objet de suivi des pairs du bus.

sd_bus_track_get_userdata() retourne le pointeur générique de données utilisateur associé à l'objet de suivi des pairs du bus. sd_bus_track_set_userdata() retourne le pointeur précédent de données utilisateur défini.

PROPRIÉTÉ DES RÉFÉRENCES

La fonction sd_bus_track_new() crée un nouvel objet et l'appelant possède la seule référence. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_track_unref().

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EBUSY

Des pairs du bus ont déjà été ajoutés à l'objet de suivi des pairs du bus et sd_bus_track_set_recursive() a été appelé pour changer le mode de suivi.

-EINVAL

Le paramètre spécifié est invalide (NULL dans le cas des paramètres de sortie).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui n'est pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
