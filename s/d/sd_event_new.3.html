NOM

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - Acquérir et libérer un objet de boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

DESCRIPTION

sd_event_new() alloue un nouvel objet de boucle d'événements. L'objet de boucle d'événements est retourné dans le paramètre event. Après utilisation, supprimez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est supprimée, l'objet est libéré.

sd_event_default() acquiert une référence à l'objet de boucle d'événements par défaut du thread appelant, allouant éventuellement un nouvel objet si aucun objet de boucle d'événements par défaut n'a encore été alloué pour le thread. Après utilisation, supprimez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est supprimée, la boucle d'événements est libérée. Si cette fonction est appelée pendant que l'objet retourné par un appel précédent du même thread est toujours référencé, le même objet est retourné à nouveau, mais la référence est incrémentée d'un. Il est recommandé d'utiliser cet appel plutôt que sd_event_new() afin de partager les objets de boucle d'événements entre divers composants qui sont dispatchés dans le même thread. Tous les threads ont exactement soit zéro soit un objet de boucle d'événements par défaut associé, jamais plus.

Après avoir alloué un objet de boucle d'événements, ajoutez-y des sources d'événements avec sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3), sd_event_add_post(3) ou sd_event_add_exit(3), puis exécutez la boucle d'événements en utilisant sd_event_loop(3).

sd_event_ref() incrémente le compteur de références de l'objet de boucle d'événements spécifié d'une unité.

sd_event_unref() décrémente le compteur de références de l'objet de boucle d'événements spécifié d'une unité. Si le compteur atteint zéro, l'objet est libéré. Notez qu'il est libéré indépendamment du fait qu'il soit l'objet de boucle d'événements par défaut pour un thread ou non. Cela signifie qu'allouer une boucle d'événements avec sd_event_default(), puis la libérer, puis en acquérir une nouvelle avec sd_event_default() entraînera deux objets distincts. Notez que, pour libérer un objet de boucle d'événements, toutes les sources d'événements restantes de la boucle d'événements doivent également être libérées car chacune conserve une référence à celle-ci.

sd_event_unrefp() est similaire à sd_event_unref() mais prend un pointeur vers un pointeur vers un objet sd_event. Cet appel est utile en conjonction avec l'attribut de variable `Clean-up' de GCC et LLVM[1]. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme celle-ci, afin d'allouer un objet de boucle d'événements qui sera libéré automatiquement à la sortie du bloc de code :

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Failed to allocate event loop: %m\n");
        }
        ...
}

sd_event_ref(), sd_event_unref() et sd_event_unrefp() n'effectuent aucune opération si l'objet de boucle d'événements passé est NULL.

sd_event_get_tid() récupère l'identifiant du thread ("TID") du thread auquel l'objet de boucle d'événements spécifié est associé. Cet appel n'est pris en charge que pour les boucles d'événements allouées avec sd_event_default(), et retourne l'identifiant du thread pour lequel la boucle d'événements est la boucle d'événements par défaut. Voir gettid(2) pour plus d'informations sur les identifiants de threads.

VALEUR RENVOYÉE

En cas de succès, sd_event_new(), sd_event_default() et sd_event_get_tid() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno. sd_event_ref() retourne toujours un pointeur vers l'objet de boucle d'événements passé. sd_event_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer l'objet.

-EMFILE

Le nombre maximum de boucles d'événements a été alloué.

-ENXIO

sd_event_get_tid() a été invoqué sur un objet de boucle d'événements qui n'a pas été alloué avec sd_event_default().

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd de pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme non sécurisé pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_new(), sd_event_default(), sd_event_ref() et sd_event_unref() ont été ajoutés dans la version 213.

sd_event_unrefp() et sd_event_get_tid() ont été ajoutés dans la version 229.

NAME

sd_event_new - Create a new event loop

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_new(sd_event **loop);

DESCRIPTION

sd_event_new() creates and initializes a new event loop object. This object may be used to register various event sources and run them. The created event loop is initially empty and contains no event sources. It is also not associated with any specific process or thread, and is thus suitable for being passed around and used from different contexts.

The new event loop object is returned in the variable pointed to by loop. The caller takes ownership of this object and is responsible for releasing it using sd_event_unref(3).

RETURN VALUE

On success, sd_event_new() returns 0. On failure, a negative errno-based error code is returned.

NOTES

It is generally recommended to use sd_event_default(3) to obtain the default event loop of the calling process/thread, unless a new, isolated event loop is specifically needed.

HISTORY

The sd_event_new() function was introduced in version 231.
