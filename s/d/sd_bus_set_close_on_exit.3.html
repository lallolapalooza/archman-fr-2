NOM

sd_bus_set_close_on_exit, sd_bus_get_close_on_exit - Contrôler la fermeture de la connexion bus lors de la phase de sortie de la boucle d'événements

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_close_on_exit(sd_bus *bus, int b);

int sd_bus_get_close_on_exit(sd_bus *bus);

DESCRIPTION

sd_bus_set_close_on_exit() peut être utilisée pour activer ou désactiver la vidange automatique (comme dans sd_bus_flush(3)) et la fermeture (comme dans sd_bus_close(3)) de la connexion bus pendant la phase de sortie de la boucle d'événements. Cette logique ne s'applique qu'aux connexions bus attachées à une boucle d'événements sd-event(3), voir sd_bus_attach_event(3). Par défaut, ce mécanisme est activé et assure que tous les messages en attente qui n'ont pas été écrits sur la connexion bus sont vidés lorsque la boucle d'événements est en cours d'arrêt. Dans certains cas, ce comportement n'est pas souhaitable, par exemple lorsque la connexion bus doit rester utilisable après la sortie de la boucle d'événements. Si b est vrai, la fonctionnalité est activée (ce qui est le comportement par défaut), sinon elle est désactivée.

sd_bus_get_close_on_exit() peut être utilisée pour interroger le paramètre actuel de cette fonctionnalité. Elle retourne zéro lorsque la fonctionnalité est désactivée, et une valeur positive si elle est activée.

VALEUR DE RETOUR

En cas de succès, sd_bus_set_close_on_exit() retourne un entier non négatif. En cas d'échec, elle retourne un code d'erreur négatif de type errno.

sd_bus_get_close_on_exit() retourne 0 si la fonctionnalité est actuellement désactivée ou un entier positif si elle est activée. En cas d'échec, elle retourne un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants:

-ECHILD

La connexion bus a été créée dans un processus, une bibliothèque ou une instance de module différent.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui n'est pas déclaré comme sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à une phase précoce du programme, lorsque aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_bus_set_close_on_exit() et sd_bus_get_close_on_exit() ont été ajoutées dans la version 240.
