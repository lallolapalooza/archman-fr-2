SD_BUS_REQUEST_NAME(3) sd_bus_request_name SD_BUS_REQUEST_NAME(3)

NOM

sd_bus_request_name, sd_bus_request_name_async, sd_bus_release_name, sd_bus_release_name_async - Demander ou relâcher un nom de service bien connu sur un bus

SYNOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_request_name(sd_bus *bus, const char *name, uint64_t flags);

int sd_bus_request_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, uint64_t flags, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_release_name(sd_bus *bus, const char *name);

int sd_bus_release_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, sd_bus_message_handler_t callback, void *userdata);

DESCRIPTION

sd_bus_request_name() demande un nom de service bien connu sur un bus. Elle prend une connexion de bus, un nom de bus valide et un paramètre de drapeaux. Le paramètre de drapeaux est une combinaison de zéro ou plusieurs des drapeaux suivants :

SD_BUS_NAME_ALLOW_REPLACEMENT

Après avoir acquis le nom avec succès, permet à d'autres pairs de prendre le nom lorsqu'ils essaient de l'acquérir avec le drapeau SD_BUS_NAME_REPLACE_EXISTING activé. Si SD_BUS_NAME_ALLOW_REPLACEMENT n'est pas défini sur la requête originale, une telle requête par d'autres pairs sera refusée.

Ajouté dans la version 209.

SD_BUS_NAME_REPLACE_EXISTING

Prendre le nom s'il a déjà été acquis par une autre pair, et que cette autre pair a autorisé la reprise en définissant SD_BUS_NAME_ALLOW_REPLACEMENT lors de son acquisition.

Ajouté dans la version 209.

SD_BUS_NAME_QUEUE

Mettre en file d'attente l'acquisition du nom lorsque le nom est déjà pris.

Ajouté dans la version 209.

sd_bus_request_name() fonctionne de manière synchrone : un message demandant le nom est envoyé au broker du bus, et l'appel attend la réponse du broker.

sd_bus_request_name_async() est une version asynchrone de sd_bus_request_name(). Au lieu d'attendre la fin de la requête, le message de requête est mis en file d'attente. La fonction de rappel callback spécifiée sera appelée lorsque la réponse du broker sera reçue. Si le paramètre est spécifié comme NULL, une implémentation par défaut est utilisée à la place, qui terminera la connexion si le nom ne peut pas être acquis. La fonction renvoie un objet slot dans son paramètre slot — s'il est passé comme non-NULL — qui peut être utilisé comme référence à l'opération de demande de nom. Utilisez sd_bus_slot_unref(3) pour détruire cette référence. Notez que la destruction de la référence ne désenregistrera pas le nom, mais garantira simplement que la fonction de rappel spécifiée ne sera plus appelée.

sd_bus_release_name() relâche un nom bien connu acquis. Elle prend une connexion de bus et un nom de bus valide comme paramètres. Cette fonction fonctionne de manière synchrone, envoyant un message de demande de relâchement au broker du bus et attendant sa réponse.

sd_bus_release_name_async() est une version asynchrone de sd_bus_release_name(). La fonction de rappel callback spécifiée est appelée lorsque le nom a été relâché avec succès. Si elle est spécifiée comme NULL, une implémentation générique est utilisée qui ignore le résultat de l'opération. Comme ci-dessus, le slot (s'il n'est pas NULL) est défini sur un objet qui peut être utilisé pour référencer l'opération.

Ces fonctions ne sont prises en charge que sur les connexions de bus, c'est-à-dire les connexions à un broker de bus et non sur les connexions directes.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Si SD_BUS_NAME_QUEUE est spécifié, sd_bus_request_name() retournera 0 lorsque le nom est déjà pris par une autre pair et que le client a été ajouté à la file d'attente pour le nom. Dans ce cas, l'appelant peut s'abonner aux signaux "NameOwnerChanged" pour être informé lorsque le nom est acquis avec succès. sd_bus_request_name() retourne > 0 lorsque le nom a été acquis immédiatement avec succès.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EALREADY

L'appelant est déjà le propriétaire du nom spécifié.

-EEXIST

Le nom a déjà été acquis par une autre pair, et SD_BUS_NAME_REPLACE_EXISTING n'a pas été spécifié ou l'autre pair n'a pas spécifié SD_BUS_NAME_ALLOW_REPLACEMENT lors de l'acquisition du nom.

-ESRCH

Il a été tenté de relâcher un nom qui n'est actuellement pas enregistré sur le bus.

-EADDRINUSE

Il a été tenté de relâcher un nom qui appartient à une autre pair sur le bus.

-EINVAL

Un paramètre spécifié est invalide. Ceci est également généré lorsque le nom demandé est un nom de service spécial réservé par la spécification D-Bus, ou lorsque l'opération est demandée sur une connexion qui ne fait pas référence à un bus.

-ENOTCONN

La connexion de bus a été déconnectée.

-ECHILD

La connexion de bus a été créée dans un processus autre que celui actuel.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_request_name() et sd_bus_release_name() ont été ajoutées dans la version 209.

sd_bus_request_name_async() et sd_bus_release_name_async() ont été ajoutées dans la version 237.

sd_bus_release_name(3)

NOM

sd_bus_release_name - Libère un nom de bus acquis

SYNOPSIS

   #include <systemd/sd-bus.h>

   int sd_bus_release_name(sd_bus *bus, const char *name);

DESCRIPTION

La fonction sd_bus_release_name() demande au bus spécifié par bus de libérer le nom de bus name. Le nom doit avoir été précédemment acquis par sd_bus_request_name(3) ou une autre méthode. Si le nom est acquis avec succès, il sera libéré et les autres connexions au bus seront notifiées.

Le nom passé doit être un nom de bus valide. S'il est libéré avec succès, le descripteur de fichier associé sera fermée.

VALEUR DE RETOUR

Cette fonction renvoie 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les codes d'erreur possibles sont :

  • -EINVAL : Le nom spécifié n'est pas valide ou n'a pas été acquis.
  • -ENXIO : Le bus est déconnecté.
  • -EPROTO : Le nom n'a pas pu être libéré en raison d'une erreur de protocole.

NOTES

Cette fonction est idempotente ; appeler deux fois la fonction avec le même nom n'aura pas d'effet supplémentaire si le nom a déjà été libéré.

HISTORIQUE

La fonction sd_bus_release_name() a été introduite dans la version 231 de systemd.
