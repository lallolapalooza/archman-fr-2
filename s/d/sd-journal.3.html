NOM

sd-journal - API pour soumettre et interroger les entrées de journal depuis et vers le journal

SYNTAXE

#include <systemd/sd-journal.h>

pkg-config --cflags --libs libsystemd

DESCRIPTION

sd-journal.h fait partie de libsystemd(3) et fournit des API pour soumettre et interroger les entrées de journal. Les API exposées agissent à la fois comme client pour le service de journal systemd-journald.service(8) et comme analyseur pour les fichiers de journal sur disque.

Voir sd_journal_print(3), sd_journal_stream_fd(3), sd_journal_open(3), sd_journal_next(3), sd_journal_get_realtime_usec(3), sd_journal_add_match(3), sd_journal_seek_head(3), sd_journal_enumerate_fields(3), sd_journal_get_cursor(3), sd_journal_get_cutoff_realtime_usec(3), sd_journal_get_cutoff_monotonic_usec(3), sd_journal_get_usage(3), sd_journal_get_catalog(3), sd_journal_get_fd(3), sd_journal_has_runtime_files(3) et sd_journal_has_persistent_files(3) pour plus d'informations sur les fonctions implémentées.

L'accès en ligne de commande pour soumettre des entrées au journal est disponible avec l'outil systemd-cat(1). L'accès en ligne de commande pour interroger des entrées du journal est disponible avec l'outil journalctl(1).

SURETÉ DES THREADS

Les fonctions qui opèrent sur les objets sd_journal sont indépendantes des threads — un pointeur sd_journal donné ne peut être utilisé que par un seul thread à la fois, mais plusieurs threads indépendants peuvent utiliser plusieurs objets simultanément. Certaines fonctions — celles qui sont utilisées pour envoyer des entrées au journal, comme sd_journal_print(3) et similaires, ou celles qui sont utilisées pour récupérer des informations globales comme sd_journal_stream_fd(3) et sd_journal_get_catalog_for_message_id(3) — sont entièrement sûres pour les threads et peuvent être appelées par plusieurs threads en parallèle.

DÉPENDANCES OPTIONNELLES

Selon les options de construction activées, les fonctions qui opèrent sur les objets sd_journal peuvent provoquer le chargement dynamique de bibliothèques partagées optionnelles via dlopen(3), telles que des bibliothèques de décompression (xz, lz4, zstd) ou des bibliothèques cryptographiques (gcrypt).

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré non sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
