SD_JOURNAL_GET_CURSOR(3) sd_journal_get_cursor SD_JOURNAL_GET_CURSOR(3)

NOM

sd_journal_get_cursor, sd_journal_test_cursor - Obtenir la chaîne de curseur pour ou tester la chaîne de curseur par rapport à l'entrée de journal actuelle

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_cursor(sd_journal *j, char **ret_cursor);

int sd_journal_test_cursor(sd_journal *j, const char *cursor);

DESCRIPTION

sd_journal_get_cursor() renvoie une chaîne de curseur pour l'entrée de journal actuelle. Un curseur est une sérialisation de la position actuelle du journal au format texte. La chaîne ne contient que des caractères imprimables et peut être transmise sous forme de texte. Le curseur identifie une entrée de journal de manière globale et stable et peut être utilisé pour s'y positionner ultérieurement via sd_journal_seek_cursor(3). La chaîne de curseur doit être considérée comme opaque et ne doit pas être analysée par les clients. Se positionner sur une position de curseur sans que l'entrée spécifique soit disponible localement se positionnera sur l'entrée disponible la plus proche (en termes de temps). L'appel prend deux arguments : un objet de contexte de journal et un pointeur vers un pointeur de chaîne où la chaîne de curseur sera placée. La chaîne est allouée via malloc(3) de la libc et doit être libérée après utilisation avec free(3). Le paramètre ret_cursor peut être passé comme NULL auquel cas la chaîne de curseur n'est pas générée, cependant la valeur de retour indiquera si le contexte du journal est actuellement positionné sur une entrée, et donc a un curseur associé.

sd_journal_test_cursor() peut être utilisé pour vérifier si la position actuelle dans le journal correspond au curseur spécifié. Ceci est utile car les chaînes de curseur n'identifient pas une entrée de manière unique : la même entrée peut être référencée par plusieurs chaînes de curseur différentes, et par conséquent la comparaison de chaînes de curseurs n'est pas possible. Utilisez cet appel pour vérifier après une invocation de sd_journal_seek_cursor(3) si l'entrée recherchée a bien été trouvée dans le journal ou si l'entrée la plus proche a été utilisée à la place.

Notez que sd_journal_get_cursor() et sd_journal_test_cursor() ne fonctionneront pas avant que sd_journal_next(3) (ou l'une des autres fonctions qui se déplacent vers une entrée) n'ait été appelée au moins une fois pour positionner le pointeur de lecture sur une entrée valide.

VALEUR DE RETOUR

sd_journal_get_cursor() renvoie 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_test_cursor() renvoie une valeur positive si l'entrée actuelle correspond au curseur spécifié, 0 si elle ne correspond pas au curseur spécifié ou un code d'erreur négatif de style errno en cas d'échec.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EADDRNOTAVAIL

Le contexte du journal n'est actuellement positionné sur aucune entrée, et par conséquent aucune chaîne de curseur ne peut être générée.

-EINVAL

Le paramètre du contexte du journal est NULL.

-ECHILD

L'objet de contexte du journal a été alloué dans un processus différent de celui dans lequel il est utilisé actuellement.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés par différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

HISTORIQUE

sd_journal_test_cursor() a été ajouté dans la version 195.
