DESCRIPTION

Ces fonctions renvoient des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID du parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant d'utilisateur). De même, sd_bus_creds_get_euid() renvoie l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() renvoie le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GID supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel qu'il est stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel qu'il est stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin vers l'exécutable du programme (tel qu'il est stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est renvoyé. Notez que cette propriété ne doit pas être utilisée pour plus qu'une information explicative, en particulier, elle ne doit pas être utilisée pour des décisions de sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. De plus, le noyau exporte ces informations d'une manière ambiguë (c'est-à-dire qu'un exécutable supprimé ne peut pas être distingué en toute sécurité de celui qui est toujours présent).

sd_bus_creds_get_cmdline() récupère la ligne de commande du processus.

sd_bus_creds_get_cgroup() récupère le chemin du cgroup du processus, tel qu'il est affiché dans /proc/pid/cgroup.

sd_bus_creds_get_unit() récupère le nom de l'unité systemd associée au processus, s'il y en a une. Voir systemd.unit(5).

sd_bus_creds_get_slice() récupère le nom de la tranche systemd associée au processus, s'il y en a une. Voir systemd.slice(5).

sd_bus_creds_get_user_unit() récupère le nom de l'unité utilisateur systemd associée au processus, s'il y en a une. Voir systemd.unit(5).

sd_bus_creds_get_user_slice() récupère le nom de la tranche utilisateur systemd associée au processus, s'il y en a une. Voir systemd.slice(5).

sd_bus_creds_get_session() récupère le nom de la session associée au processus, s'il y en a une.

sd_bus_creds_get_owner_uid() récupère l'UID du propriétaire du bus. Un bus peut avoir un propriétaire, qui est autorisé à appeler des méthodes spécifiques sur le bus. Cet identifiant est différent de l'UID généré par l'appelant, car le bus peut être créé par un processus différent.

sd_bus_creds_has_effective_cap(), sd_bus_creds_has_permitted_cap(), sd_bus_creds_has_inheritable_cap() et sd_bus_creds_has_bounding_cap() vérifient si le processus possède la capacité spécifiée capability dans les ensembles effectif, autorisé, héritable et de délimitation, respectivement. La liste des capacités est disponible dans le fichier d'en-tête <sys/capability.h>. Si la capacité est présente, ces fonctions renvoient une valeur positive ; sinon, elles renvoient 0. Notez que les capacités ne sont pas toujours disponibles pour tous les processus.

sd_bus_creds_get_selinux_context() récupère le contexte SELinux du processus.

sd_bus_creds_get_audit_session_id() récupère l'identifiant de session d'audit du processus.

sd_bus_creds_get_audit_login_uid() récupère l'UID de connexion d'audit du processus.

sd_bus_creds_get_tty() récupère le nom du terminal associé au processus.

sd_bus_creds_get_unique_name() récupère le nom unique du bus associé au processus.

sd_bus_creds_get_well_known_names() récupère une liste de tous les noms bien connus associés au processus.

sd_bus_creds_get_description() récupère une description textuelle du processus, généralement le nom de l'unité systemd ou un autre identifiant.

Toutes ces fonctions renvoient 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les valeurs de retour courantes sont :

  • -EPERM : L'appelant n'a pas les permissions nécessaires pour lire les informations d'identification.
  • -ENOENT : Le champ d'information d'identification demandé n'est pas disponible pour ce processus ou ce bus.
  • -ENOMEM : Pas assez de mémoire pour allouer les ressources nécessaires.
  • -EINVAL : L'objet sd_bus_creds est invalide.

Les pointeurs vers les chaînes de caractères renvoyés par ces fonctions (par exemple, comm, exe, cgroup, etc.) sont valides tant que l'objet sd_bus_creds existe. Les tableaux de chaînes de caractères renvoyés par sd_bus_creds_get_cmdline() et sd_bus_creds_get_well_known_names() doivent être libérés avec sd_bus_creds_unref(3) une fois qu'ils ne sont plus utilisés.

DESCRIPTION

These functions retrieve various security and process attributes (credentials) from a D-Bus peer or from an arbitrary process on the local system. The `sd_bus_creds` object `c` is usually created by sd_bus_creds_new_from_pid(3) or sd_bus_message_get_creds(3).

sd_bus_creds_get_pidfd_dup() duplicates the process file descriptor of the peer. This descriptor can be used with functions like pidfd_open(2).

sd_bus_creds_get_pid() retrieves the process ID (PID) of the peer.

sd_bus_creds_get_tid() retrieves the thread ID (TID) of the peer.

sd_bus_creds_get_ppid() retrieves the parent process ID (PPID) of the peer.

sd_bus_creds_get_uid() retrieves the real user ID (UID) of the peer.

sd_bus_creds_get_euid() retrieves the effective user ID (EUID) of the peer.

sd_bus_creds_get_suid() retrieves the saved set-user-ID (SUID) of the peer.

sd_bus_creds_get_fsuid() retrieves the effective file system user ID (FSUID) of the peer.

sd_bus_creds_get_gid() retrieves the real group ID (GID) of the peer.

sd_bus_creds_get_egid() retrieves the effective group ID (EGID) of the peer.

sd_bus_creds_get_sgid() retrieves the saved set-group-ID (SGID) of the peer.

sd_bus_creds_get_fsgid() retrieves the effective file system group ID (FSGID) of the peer.

sd_bus_creds_get_supplementary_gids() retrieves the list of supplementary group IDs of the peer. The list is NULL-terminated, and the strings themselves are not NULL-terminated.

sd_bus_creds_get_comm() retrieves the command name of the process. This is the string typically shown in tools like `top` or `ps`, and is usually limited to 15 characters. Kernel threads do not have a command name, in which case -ENXIO is returned.

sd_bus_creds_get_tid_comm() retrieves the command name of the thread. This is the string typically shown in tools like `top` or `htop` when showing threads. The name may be truncated or altered (e.g. by adding a suffix like " (deleted)").

sd_bus_creds_get_exe() will retrieve the path to the executable image (as stored in /proc/pid/exe). Note that kernel threads do not have an executable image, in which case -ENXIO is returned.

sd_bus_creds_get_cmdline() will retrieve an array of command line arguments (as stored in /proc/pid/cmdline). Note that kernel threads do not have a command line, in which case -ENXIO is returned.

sd_bus_creds_get_cgroup() will retrieve the control group path. See Control Groups v2[1].

sd_bus_creds_get_unit() will retrieve the systemd unit name (in the system instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a unit, returns -ENXIO.

sd_bus_creds_get_user_unit() will retrieve the systemd unit name (in the user instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a user unit, returns -ENXIO.

sd_bus_creds_get_slice() will retrieve the systemd slice (a unit in the system instance of systemd) that the process is a part of. See systemd.slice(5). Similarly, sd_bus_creds_get_user_slice() retrieves the systemd slice of the process, in the user instance of systemd.

sd_bus_creds_get_session() will retrieve the identifier of the login session that the process is a part of. Please note the login session may be limited to a stub process or two. User processes may instead be started from their systemd user manager, e.g. GUI applications started using DBus activation, as well as service processes which are shared between multiple logins of the same user. For processes that are not part of a session, returns -ENXIO.

sd_bus_creds_get_owner_uid() will retrieve the numeric UID (user identifier) of the user who owns the user unit or login session that the process is a part of. See systemd-logind.service(8). For processes that are not part of a user unit or session, returns -ENXIO.

sd_bus_creds_has_effective_cap() will check whether the capability specified by capability was set in the effective capabilities mask. A positive return value means that it was set, zero means that it was not set, and a negative return value indicates an error. See capabilities(7) and the AmbientCapabilities= and CapabilityBoundingSet= settings in systemd.exec(5).

sd_bus_creds_has_permitted_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the permitted capabilities mask.

sd_bus_creds_has_inheritable_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the inheritable capabilities mask.

sd_bus_creds_has_bounding_cap() is similar to sd_bus_creds_has_effective_cap(), but will check the bounding capabilities mask.

sd_bus_creds_get_selinux_context() will retrieve the SELinux security context (label) of the process.

sd_bus_creds_get_audit_session_id() will retrieve the audit session identifier of the process. Returns -ENXIO for processes that are not part of an audit session.

sd_bus_creds_get_audit_login_uid() will retrieve the audit user login identifier (the identifier of the user who is "responsible" for the session). Returns -ENXIO for processes that are not part of an audit session.

sd_bus_creds_get_tty() will retrieve the controlling TTY, without the prefixing "/dev/". Returns -ENXIO for processes that have no controlling TTY.

sd_bus_creds_get_unique_name() will retrieve the D-Bus unique name. See The D-Bus specification[2].

sd_bus_creds_get_well_known_names() will retrieve the set of D-Bus well-known names. See The D-Bus specification[2].

sd_bus_creds_get_description() will retrieve a descriptive name of the bus connection of the peer. This name is useful to discern multiple bus connections by the same peer, and may be altered by the peer with the sd_bus_set_description(3) call.

All functions that take a const char** parameter will store the answer there as an address of a NUL-terminated string. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

All functions that take a char*** parameter will store the answer there as an address of an array of strings. Each individual string is NUL-terminated, and the array is NULL-terminated as a whole. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

RETURN VALUE

On success, these calls return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENODATA

The given field is not available in the credentials object c.

-ENXIO

The given field is not specified for the described process or peer. This will be returned by sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), and sd_bus_creds_get_session() if the process is not part of a systemd system unit, systemd user unit, systemd slice, or logind session. It will be returned by sd_bus_creds_get_owner_uid() if the process is not part of a systemd user unit or logind session. It will also be returned by sd_bus_creds_get_exe() and sd_bus_creds_get_cmdline() for kernel threads (since these are not started from an executable binary, nor have a command line), and by sd_bus_creds_get_audit_session_id() and sd_bus_creds_get_audit_login_uid() when the process is not part of an audit session, and sd_bus_creds_get_tty() if the process has no controlling TTY.

-EINVAL

Specified pointer parameter is NULL.

-ENOMEM

Memory allocation failed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
