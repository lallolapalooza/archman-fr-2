DESCRIPTION

sd_device_get_syspath() renvoie le chemin sysfs de l'objet périphérique spécifié, y compris le préfixe /sys. Exemple : /sys/devices/virtual/tty/tty7

sd_device_get_devpath() renvoie le chemin sysfs de l'objet périphérique spécifié, sans le préfixe /sys. Exemple : /devices/virtual/tty/tty7

sd_device_get_sysname() renvoie le nom sysfs de l'objet périphérique spécifié, c'est-à-dire le dernier composant du chemin sysfs. Exemple : "tty7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_sysnum() renvoie le numéro de périphérique sysfs de l'objet périphérique spécifié, c'est-à-dire le suffixe numérique du dernier composant du chemin sysfs. Exemple : "7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_subsystem() renvoie le sous-système noyau de l'objet périphérique spécifié. Il s'agit d'une courte chaîne qui tient dans un nom de fichier, et qui ne contient donc pas de slash et ne peut pas être vide. Exemple : "tty", "block" ou "net".

sd_device_get_driver_subsystem() renvoie le type de bus connecté des périphériques chargés par l'objet périphérique pilote spécifié. Par exemple, lorsqu'un objet périphérique pilote "iwlwifi" est spécifié, utilisé par les interfaces réseau sans fil connectées au bus PCI, cette fonction renvoie "pci". Cette fonction ne réussit que si sd_device_get_subsystem() renvoie "drivers". Exemple : "pci", "i2c", ou "hid".

sd_device_get_devtype() renvoie le type de périphérique de l'objet périphérique spécifié, si le sous-système gère plusieurs types de périphériques. Exemple : pour les périphériques du sous-système "block", cela peut être "disk" ou "partition"

sd_device_get_devname() renvoie le chemin du nœud périphérique de l'objet périphérique spécifié si le périphérique a un nœud périphérique. Exemple : pour /sys/devices/virtual/tty/tty7, la chaîne /dev/tty7 est généralement renvoyée.

sd_device_get_devnum() renvoie le majeur/mineur du nœud périphérique (c'est-à-dire dev_t) de l'objet périphérique spécifié si le périphérique a un nœud périphérique (c'est-à-dire celui renvoyé par sd_device_get_devname()). Pour les périphériques appartenant au sous-système "block", cela fait référence à un nœud de périphérique bloc, dans tous les autres cas à un nœud de périphérique caractère. Exemple : pour le périphérique /sys/devices/virtual/tty/tty7, cela renvoie généralement le numéro de périphérique avec majeur/mineur "4:7".

sd_device_get_ifindex() renvoie l'index de l'interface réseau de l'objet périphérique spécifié, si le périphérique encapsule un périphérique d'interface réseau, c'est-à-dire appartient au sous-système "net". Exemple : l'interface "lo" a généralement l'index d'interface 1.

sd_device_get_driver() renvoie le nom du pilote noyau attaché au périphérique. Notez que le champ pilote est défini sur les périphériques consommés par le pilote, et non sur le périphérique créé par celui-ci. Exemple : un périphérique PCI /sys/bus/pci/devices/0000:00:1f.6 pourrait être attaché à un pilote "e1000e".

sd_device_get_diskseq() renvoie le numéro de séquence de disque du noyau du périphérique bloc. Ce numéro augmente de manière monotone chaque fois que le support sous-jacent d'un périphérique bloc change sans que le nom du périphérique ne change, et est pertinent pour les périphériques bloc encapsulant des périphériques à supports changeants (par exemple, lecteur disquette ou CD-ROM), ou les périphériques bloc en boucle. Seulement défini pour les périphériques bloc, c'est-à-dire ceux du sous-système "block".

sd_device_get_device_id() renvoie la chaîne courte qui identifie l'objet périphérique. Lorsque l'ID de périphérique obtenu par la fonction pour un objet périphérique spécifié est passé à sd_device_new_from_device_id(), une nouvelle instance du même objet périphérique sera obtenue. Lorsqu'un périphérique bloc ou caractère est spécifié, qui a un nœud périphérique correspondant, cela renvoie "b" ou "c", respectivement, suivi des numéros majeur et mineur du nœud périphérique séparés par un deux-points. Exemple : "b259:1" ou "c10:121". Lorsqu'un périphérique d'interface réseau est spécifié, cela renvoie "n" suivi de l'index de l'interface, qui peut être obtenu par sd_device_get_ifindex(). Exemple : "n1". Lorsqu'un périphérique dans le sous-système "driver" est spécifié, cela renvoie "+drivers:" suivi de son sous-système de pilote et de son nom sysfs séparés par un deux-points. Exemple : "+drivers:pci:iwlwifi" pour un objet périphérique pilote dont le sous-système de pilote est "pci" et le nom sysfs est "iwlwifi". Lorsqu'un autre type de périphérique est spécifié, cette fonction renvoie "+" suivi de son sous-système et de son nom sysfs séparés par un deux-points. Exemple : "+acpi:ACPI0003:00", "+input:input16", ou "+pci:0000:00:1f.6".

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ils renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

Ajouté dans la version 251.

-ENOENT

Le champ demandé n'est pas présent dans l'objet périphérique.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de faire les appels à setenv() uniquement à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
