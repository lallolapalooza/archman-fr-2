SD_EVENT_EXIT(3) sd_event_exit SD_EVENT_EXIT(3)

NOM

sd_event_exit, sd_event_get_exit_code - Demander la sortie de la boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>

int sd_event_exit(sd_event *event, int code);

int sd_event_get_exit_code(sd_event *event, int *ret);

DESCRIPTION

sd_event_exit() demande à la boucle d'événements spécifiée dans l'objet de boucle d'événements event de se terminer. Le paramètre code peut être n'importe quelle valeur entière et est retourné tel quel par sd_event_loop(3) après la dernière itération de la boucle d'événements. Il peut également être interrogé en utilisant sd_event_get_exit_code(), voir ci-dessous.

Lorsqu'une sortie est demandée, la boucle d'événements cessera d'écouter et de distribuer les sources d'événements régulières. Au lieu de cela, elle procèdera à l'exécution uniquement des sources d'événements enregistrées avec sd_event_add_exit(3) dans l'ordre défini par leur priorité. Une fois que toutes les sources d'événements de sortie auront été distribuées, la boucle d'événements sera terminée.

Si sd_event_exit() est invoqué une seconde fois pendant que la boucle d'événements traite encore les sources d'événements de sortie, le code de sortie stocké dans l'objet de boucle d'événements est mis à jour, mais aucune autre opération n'est effectuée.

sd_event_get_exit_code() peut être utilisé pour interroger le code de sortie passé à un appel antérieur de sd_event_exit(). Le paramètre de retour ret peut être défini sur NULL, afin de simplement vérifier si sd_event_exit() a été appelé auparavant (car sd_event_get_exit_code() échoue avec -ENODATA si ce n'est pas le cas, voir ci-dessous).

Bien que toute la plage des entiers positifs et négatifs puisse être utilisée pour le code de sortie, il faut veiller à ne pas choisir des codes de sortie qui entrent en conflit avec les codes de sortie réguliers retournés par sd_event_loop(), si ces codes de sortie doivent être distinguables.

Notez que pour la plupart des types de sources d'événements, passer le pointeur de rappel comme NULL dans l'appel du constructeur respectif (c'est-à-dire dans sd_event_add_time(3), sd_event_add_signal(3), ...) a pour effet d'invoquer sd_event_exit() une fois que la source d'événement se déclenche, avec le pointeur userdata spécifié converti en entier comme paramètre de code de sortie. Ceci est utile pour terminer automatiquement une boucle d'événements après une condition donnée, telle qu'un délai d'attente ou la réception de SIGTERM ou similaire. Voir la documentation de l'appel du constructeur respectif pour plus de détails.

VALEUR DE RETOUR

En cas de succès, sd_event_exit() et sd_event_get_exit_code() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

L'objet de boucle d'événements ou le pointeur du code d'erreur sont invalides.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

-ESTALE

La boucle d'événements s'est déjà terminée et tous les gestionnaires de sortie ont déjà été traités.

-ENODATA

Retourné par sd_event_get_exit_code() dans le cas où il n'a pas encore été demandé à la boucle d'événements de se terminer.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multiples depuis des threads différents. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a encore été démarré.

HISTORIQUE

sd_event_exit() et sd_event_get_exit_code() ont été ajoutés dans la version 229.
