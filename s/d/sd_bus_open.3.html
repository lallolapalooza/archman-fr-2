DESCRIPTION

sd_bus_default() acquiert un objet de connexion de bus vers le bus utilisateur lorsqu'il est appelé dans une slice utilisateur (toute session sous "user-*.slice", par exemple : "user@1000.service"), ou vers le bus système sinon. L'objet de connexion est associé au thread appelant. Chaque fois que la fonction est appelée depuis le même thread, le même objet est renvoyé, mais son compteur de références est augmenté d'une unité, tant qu'au moins une référence est conservée. Lorsque la dernière référence à la connexion est abandonnée (en utilisant l'appel sd_bus_unref(3)), la connexion est terminée. Notez que la connexion n'est pas automatiquement terminée lorsque le thread associé se termine. Il est important d'abandonner explicitement la dernière référence à la connexion de bus avant la fin du thread, car sinon, la connexion fuira. De plus, les messages mis en file d'attente mais non lus ou non écrits maintiennent une référence au bus, voir ci-dessous.

sd_bus_default_user() renvoie un objet de connexion de bus utilisateur associé au thread appelant. sd_bus_default_system() est similaire, mais se connecte au bus système. Notez que sd_bus_default() est identique à ces deux appels, selon le contexte d'exécution.

sd_bus_open() crée une nouvelle connexion de bus indépendante vers le bus utilisateur lorsqu'il est appelé dans un contexte utilisateur, ou vers le bus système sinon. sd_bus_open_user() est similaire, mais se connecte uniquement au bus utilisateur. sd_bus_open_system() fait de même, mais se connecte au bus système. Contrairement à sd_bus_default(), sd_bus_default_user(), et sd_bus_default_system(), ces appels renvoient de nouveaux objets de connexion indépendants qui ne sont pas associés au thread appelant et ne sont pas partagés entre plusieurs invocations. Il est recommandé de partager les connexions par thread pour utiliser efficacement les ressources disponibles. Ainsi, il est recommandé d'utiliser sd_bus_default(), sd_bus_default_user() et sd_bus_default_system() pour se connecter aux bus utilisateur ou système.

sd_bus_open_with_description(), sd_bus_open_user_with_description(), et sd_bus_open_system_with_description() sont similaires à sd_bus_open(), sd_bus_open_user(), et sd_bus_open_system(), mais permettent de définir une chaîne de description, voir sd_bus_set_description(3). description peut être NULL, auquel cas cette fonction est équivalente à sd_bus_open(). Cette chaîne de description est utilisée dans les messages de log concernant l'objet de bus, et inclure un "nom" pour le bus les rend plus faciles à comprendre. Certains messages sont émis lors de l'initialisation du bus, par conséquent, l'utilisation de cette fonction est préférable à la définition de la description plus tard avec sd_bus_open_with_description(). L'argument est copié en interne et ne sera pas référencé après le retour de la fonction.

Si la variable d'environnement $DBUS_SESSION_BUS_ADDRESS est définie (voir environ(7)), elle sera utilisée comme adresse du bus utilisateur. Cette variable peut contenir plusieurs adresses séparées par des ";". Si cette variable n'est pas définie, une valeur par défaut appropriée pour l'instance par défaut du bus D-Bus utilisateur sera utilisée.

Si la variable d'environnement $DBUS_SYSTEM_BUS_ADDRESS est définie, elle sera utilisée comme adresse du bus système. Cette variable utilise la même syntaxe que $DBUS_SESSION_BUS_ADDRESS. Si cette variable n'est pas définie, une valeur par défaut appropriée pour l'instance par défaut du bus D-Bus système sera utilisée.

sd_bus_open_system_remote() se connecte au bus système sur l'hôte spécifié en utilisant ssh(1). host se compose d'un nom d'utilisateur optionnel suivi du symbole "@", et du nom d'hôte, optionnellement suivi d'un ":" et d'un port, optionnellement suivi d'un "/" et d'un nom de machine. Si le nom de machine est donné, une connexion est créée vers le bus système dans le conteneur spécifié sur la machine distante, et sinon une connexion vers le bus système sur l'hôte spécifié est créée.

Notez que l'entrée dans un conteneur est une opération privilégiée, et ne fonctionnera probablement que pour l'utilisateur root sur la machine distante.

sd_bus_open_system_machine() se connecte au bus système dans la machine spécifiée machine, où machine est le nom d'un conteneur local, éventuellement préfixé par un nom d'utilisateur et un "@" séparateur. Si le nom du conteneur est spécifié comme la chaîne spéciale ".host" la connexion est établie vers le système local. Ceci est utile pour se connecter au bus système local en tant qu'utilisateur spécifique, par exemple "foobar@.host" pour se connecter au bus système local en tant qu'utilisateur local "foobar". Si la syntaxe "@" est utilisée, soit le côté gauche, soit le côté droit peuvent être omis (mais pas les deux), auquel cas le nom d'utilisateur local ou ".host" est implicite. Si la syntaxe "@" n'est pas utilisée, la connexion est toujours établie en tant qu'utilisateur root. Voir sd_bus_set_address(3) pour une description de la syntaxe d'adresse, et machinectl(1) pour plus d'informations sur le concept de "machine". Notez que les connexions dans les conteneurs locaux ne sont actuellement disponibles que pour les processus privilégiés.

sd_bus_open_user_machine() est similaire à sd_bus_open_system_machine(), mais se connecte au bus utilisateur de l'utilisateur root, ou si la syntaxe "@" est utilisée, de l'utilisateur spécifié.

Ces appels allouent un objet de connexion de bus et initient la connexion à un bus bien connu d'une certaine forme. Une alternative à l'utilisation de ces appels de haut niveau est de créer un bus non connecté avec sd_bus_new(3) et de le connecter avec sd_bus_start(3).

PROPRIÉTÉ DES RÉFÉRENCES

Les fonctions sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote(), et sd_bus_open_system_machine() renvoient un nouvel objet de connexion et l'appelant possède la référence unique. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_unref(3).

Les fonctions sd_bus_default(), sd_bus_default_user() et sd_bus_default_system() ne créent pas nécessairement un nouvel objet, mais augmentent la référence de connexion d'un objet de connexion existant d'une unité. Utilisez sd_bus_unref(3) pour abandonner la référence.

Les messages mis en file d'attente mais non écrits/non lus conservent une référence à leur objet de connexion de bus. Pour cette raison, même si une application a abandonné toutes les références à une connexion de bus, elle pourrait ne pas être détruite immédiatement. Tant que tous les messages entrants mis en file d'attente n'ont pas été lus, et tant que tous les messages sortants non écrits n'ont pas été écrits, l'objet de bus restera actif. sd_bus_flush() peut être utilisé pour écrire tous les messages sortants mis en file d'attente afin qu'ils abandonnent leurs références. DESCRIPTION

Ces fonctions établissent une connexion au bus D-Bus. La connexion du bus du système est établie avec les privilèges de l'utilisateur root, tandis que la connexion du bus de l'utilisateur est établie avec les privilèges de l'utilisateur actuel. Le bus D-Bus par défaut de l'utilisateur est le bus de session de l'utilisateur, tandis que le bus D-Bus par défaut du système est le bus système.

sd_bus_open(), sd_bus_open_user(), sd_bus_open_system(), sd_bus_open_system_remote(), sd_bus_open_system_machine(), sd_bus_open_with_description(), sd_bus_open_user_with_description() et sd_bus_open_system_with_description() renvoient un pointeur vers un nouvel objet de connexion de bus sur successo, qui doit être libéré avec sd_bus_unref().

sd_bus_default(), sd_bus_default_user() et sd_bus_default_system() renvoient un pointeur vers un objet de connexion de bus global déjà ouvert. Ces objets ne doivent pas être libérés avec sd_bus_unref(). Leur cycle de vie est géré par le système.

L'option sd_bus_open_system_remote() permet de se connecter à un bus système distant. Le paramètre destination doit être le nom d'hôte du système distant. La connexion est établie via SSH.

L'option sd_bus_open_system_machine() permet de se connecter au bus système d'une machine conteneurisée. Le paramètre machine doit être le nom de la machine tel qu'il est connu de systemd-machined.service(8). La connexion est établie via machinectl(1).

Les fonctions portant la mention _with_description ajoutent la chaîne description aux méta-données de connexion, qui peut être utilisée par les démons de bus pour identifier l'origine de la connexion. Ceci est particulièrement utile pour les débogages et les diagnostics.

REFERENCE OWNERSHIP

Les fonctions renvoyées par les appels sd_bus_open() et similaires doivent être gérées par l'appelant. Elles sont comptées. Utilisez sd_bus_ref() pour augmenter le nombre de références et sd_bus_unref() pour le diminuer. Lorsque le nombre de références atteint zéro, l'objet de bus est libéré.

Pour les connexions au bus par défaut renvoyées par sd_bus_default() et ses variantes, il n'est pas nécessaire de gérer le comptage de références. Ces objets sont globaux et leur cycle de vie est géré par le système. Il est cependant conseillé d'appeler sd_bus_flush() suivi de sd_bus_close() avant qu'un thread ou un processus se termine et que sa connexion de bus doive être libérée.

Normalement, les objets de slot (créés par sd_bus_add_match(3) et des appels similaires) conservent également une référence à leur objet de connexion de bus. Ainsi, tant qu'un objet de slot de bus reste référencé, son objet de bus reste alloué. Facultativement, les objets de slot de bus peuvent être placés en mode "flottant". En mode flottant, le cycle de vie de l'objet de slot de bus est lié à l'objet de bus, c'est-à-dire que lorsque l'objet de bus est libéré, l'objet de slot de bus est également automatiquement déréférencé. L'état flottant d'un objet de slot peut être contrôlé explicitement avec sd_bus_slot_set_floating(3), bien que généralement les objets de slot de bus flottants soient créés en passant NULL comme paramètre slot de sd_bus_add_match() et des appels associés, indiquant ainsi que l'appelant n'est pas directement intéressé par la référencement et la gestion de l'objet de slot de bus.

Le cycle de vie de la connexion de bus par défaut devrait être sous la responsabilité du code qui crée/possède le thread auquel l'objet de connexion de bus par défaut est associé. Le code de bibliothèque ne devrait ni appeler sd_bus_flush() ni sd_bus_close() sur les objets de bus par défaut, sauf s'il le fait dans son propre thread privé et auto-alloué. Le code de bibliothèque ne devrait pas utiliser l'objet de bus par défaut dans d'autres threads, à moins qu'il ne soit clair que le programme qui l'utilise gérera le cycle de vie de l'objet de connexion de bus et le videra et le fermera avant de quitter le thread. Dans les bibliothèques où il n'est pas clair que le programme appelant gérera le cycle de vie de l'objet de connexion de bus, il est donc recommandé d'utiliser sd_bus_open_system() au lieu de sd_bus_default_system() et des appels associés.

RETURN VALUE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de type errno.

Errors

Les erreurs retournées peuvent indiquer les problèmes suivants:

-EINVAL

Les paramètres spécifiés sont invalides.

-ENOMEDIUM

Le type de bus demandé n'est pas disponible en raison d'un environnement invalide (par exemple, le bus de session utilisateur n'est pas disponible car $XDG_RUNTIME_DIR n'est pas défini).

-ENOMEM

Échec de l'allocation mémoire.

-ESOCKTNOSUPPORT

La version du protocole requise pour se connecter au bus sélectionné n'est pas prise en charge.

En outre, d'autres erreurs liées à la connexion peuvent être renvoyées. Voir sd_bus_send(3).

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
