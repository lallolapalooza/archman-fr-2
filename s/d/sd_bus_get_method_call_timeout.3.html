sd_bus_get_method_call_timeout(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_SET_METHOD_CALL_TIMEOUT(3) sd_bus_set_method_call_timeout SD_BUS_SET_METHOD_CALL_TIMEOUT(3)

NOM

sd_bus_set_method_call_timeout, sd_bus_get_method_call_timeout - Définir ou interroger le délai d'attente par défaut des appels de méthode D-Bus d'un objet de bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_method_call_timeout(sd_bus *bus, uint64_t usec);

int sd_bus_get_method_call_timeout(sd_bus *bus, uint64_t *ret);

DESCRIPTION

sd_bus_set_method_call_timeout() définit le délai d'attente par défaut des appels de méthode D-Bus de bus à usec microsecondes.

sd_bus_get_method_call_timeout() interroge le délai d'attente par défaut des appels de méthode D-Bus de bus. Si aucun délai d'attente d'appel de méthode n'a été défini à l'aide de sd_bus_set_method_call_timeout(), le délai d'attente est lu à partir de la variable d'environnement $SYSTEMD_BUS_TIMEOUT. Si cette variable d'environnement n'est pas définie ou ne contient pas de délai d'attente valide, l'implémentation se rabat sur un délai d'attente d'appel de méthode prédéfini de 25 secondes. Notez que $SYSTEMD_BUS_TIMEOUT est lu une seule fois et mis en cache. Les appelants ne doivent donc pas s'appuyer sur la possibilité de modifier le délai d'attente d'appel de méthode par défaut à l'exécution en modifiant la valeur de $SYSTEMD_BUS_TIMEOUT. Appelez plutôt sd_bus_set_method_call_timeout() pour modifier le délai d'attente d'appel de méthode par défaut.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Les paramètres bus ou ret sont NULL.

Ajouté dans la version 246.

-ENOPKG

L'objet bus bus n'a pas pu être résolu.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_set_method_call_timeout() et sd_bus_get_method_call_timeout() ont été ajoutés dans la version 246.
