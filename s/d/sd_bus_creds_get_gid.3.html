DESCRIPTION

Ces fonctions retournent des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair du bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupérera le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupérera le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est retourné.

sd_bus_creds_get_pidfd_dup() récupérera le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour plus de détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupérera le TID (identifiant de thread).

sd_bus_creds_get_uid() récupérera l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() retourne l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupérera le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() retourne le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupérera la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupérera le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupérera le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupérera le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" retiré). Notez que les threads du noyau n'ont pas de chemin exécutable, auquel cas -ENXIO est retourné. Notez que cette propriété ne doit pas être utilisée pour des informations purement explicatives, en particulier, elle ne doit pas être utilisée pour des décisions liées à la sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

Le type sd_bus_creds est un type opaque utilisé pour représenter les métadonnées associées à une connexion bus D-Bus locale.

Les fonctions suivantes sont disponibles pour obtenir diverses métadonnées à partir d'une structure sd_bus_creds:

sd_bus_creds_get_pid()
Récupère l'ID de processus (PID) du processus.
sd_bus_creds_get_tid()
Récupère l'ID de thread (TID) du thread.
sd_bus_creds_get_ppid()
Récupère l'ID du processus parent (PPID) du processus.
sd_bus_creds_get_uid()
Récupère l'ID utilisateur réel (UID) du processus.
sd_bus_creds_get_euid()
Récupère l'ID utilisateur effectif (EUID) du processus.
sd_bus_creds_get_suid()
Récupère l'ID utilisateur de sauvegarde (SUID) du processus.
sd_bus_creds_get_fsuid()
Récupère l'ID utilisateur du système de fichiers (FSUID) du processus.
sd_bus_creds_get_gid()
Récupère l'ID de groupe réel (GID) du processus.
sd_bus_creds_get_egid()
Récupère l'ID de groupe effectif (EGID) du processus.
sd_bus_creds_get_sgid()
Récupère l'ID de groupe de sauvegarde (SGID) du processus.
sd_bus_creds_get_fsgid()
Récupère l'ID de groupe du système de fichiers (FSGID) du processus.
sd_bus_creds_get_supplementary_gids()
Récupère un tableau d'IDs de groupe supplémentaires du processus. Le tableau est terminé par un pointeur NULL.
sd_bus_creds_get_comm()
Récupère le nom du processus tel qu'il apparaît dans la liste des processus du noyau (voir exec.c(3)). Notez que ce nom est généralement tronqué à 16 caractères.
sd_bus_creds_get_tid_comm()
Est similaire à sd_bus_creds_get_comm(), mais récupère le nom du thread. Ce nom n'est pas nécessairement tronqué.
sd_bus_creds_get_exe()
Récupère le chemin d'accès absolu du fichier exécutable du processus (tel qu'il est stocké dans /proc/pid/exe). Notez que les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est renvoyé.
sd_bus_creds_get_cmdline()
Récupère un tableau d'arguments de ligne de commande (tel qu'il est stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est renvoyé.
sd_bus_creds_get_cgroup()
Récupère le chemin du cgroup. Voir cgroups v2[1].
sd_bus_creds_get_unit()
Récupère le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, renvoie -ENXIO.
sd_bus_creds_get_user_unit()
Récupère le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, renvoie -ENXIO.
sd_bus_creds_get_slice()
Récupère la slice systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère la slice systemd du processus, dans l'instance utilisateur de systemd.
sd_bus_creds_get_session()
Récupère l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut se limiter à un ou deux processus de type stub. Les processus utilisateur peuvent plutôt être lancés à partir de leur gestionnaire d'utilisateurs systemd, par exemple les applications graphiques lancées via l'activation D-Bus, ainsi que les processus de service partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, renvoie -ENXIO.
sd_bus_creds_get_owner_uid()
Récupère l'UID numérique (identifiant utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, renvoie -ENXIO.
sd_bus_creds_has_effective_cap()
Vérifie si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).
sd_bus_creds_has_permitted_cap()
Est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités autorisées.
sd_bus_creds_has_inheritable_cap()
Est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités héritables.
sd_bus_creds_has_bounding_cap()
Est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités limitées.
sd_bus_creds_get_selinux_context()
Récupère le contexte de sécurité SELinux (label) du processus.
sd_bus_creds_get_audit_session_id()
Récupère l'identifiant de session d'audit du processus. Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
sd_bus_creds_get_audit_login_uid()
Récupère l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur "responsable" de la session). Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
sd_bus_creds_get_tty()
Récupère le TTY de contrôle, sans le préfixe "/dev/". Renvoie -ENXIO pour les processus qui n'ont pas de TTY de contrôle.
sd_bus_creds_get_unique_name()
Récupère le nom unique D-Bus. Voir La spécification D-Bus[2].
sd_bus_creds_get_well_known_names()
Récupère l'ensemble des noms bien connus D-Bus. Voir La spécification D-Bus[2].
sd_bus_creds_get_description()
Récupère un nom descriptif de la connexion bus de l'interlocuteur. Ce nom est utile pour distinguer plusieurs connexions bus du même interlocuteur, et peut être modifié par l'interlocuteur avec l'appel sd_bus_set_description(3).
sd_bus_creds_get_pidfd_dup()
Duplique le descripteur de fichier retourné par pidfd_open(2). Le descripteur de fichier retourné doit être fermé par l'appelant.

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse à cet endroit sous forme d'adresse d'une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse à cet endroit sous forme d'adresse d'un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par un NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet de métadonnées c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou l'interlocuteur décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une slice systemd, ou d'une session logind. Il sera renvoyé par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (puisqu'ils ne sont pas lancés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à un stade précoce du programme lorsque aucun autre thread n'a été lancé.
