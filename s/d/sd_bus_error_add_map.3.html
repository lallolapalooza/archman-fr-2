SD_BUS_ERROR_ADD_MAP(3) sd_bus_error_add_map SD_BUS_ERROR_ADD_MAP(3)

NOM

sd_bus_error_add_map, sd_bus_error_map, SD_BUS_ERROR_MAP, SD_BUS_ERROR_END - Ajout de mappages d'erreurs sd-dbus

SYNTAXE

#include <systemd/sd-bus.h>
typedef struct {
        const char *name;
        int code;
        ...
} sd_bus_error_map;
SD_BUS_ERROR_MAP(nom, code)
SD_BUS_ERROR_MAP_END

int sd_bus_error_add_map(const sd_bus_error_map *map);

DESCRIPTION

L'appel sd_bus_error_add_map() peut être utilisé pour enregistrer des mappages supplémentaires pour convertir les erreurs D-Bus en erreurs de type errno de Linux. Les mappages définis avec cet appel sont consultés par des appels tels que sd_bus_error_set(3) ou sd_bus_error_get_errno(3). Par défaut, un certain nombre de mappages génériques et standardisés sont connus, comme documenté dans sd-bus-errors(3). Utilisez cet appel pour ajouter des mappages supplémentaires spécifiques à l'application.

La fonction prend un pointeur vers un tableau de structures sd_bus_error_map. Une référence au tableau spécifié est ajoutée aux tables de recherche de mappages d'erreurs. Notez que la structure n'est pas copiée et qu'il est donc essentiel que le tableau reste disponible et constant pendant toute la durée restante de l'exécution du processus.

Le tableau de mappage doit être assemblé avec une série d'invocations de la macro SD_BUS_ERROR_MAP() qui prennent un nom de chaîne littéral et un numéro d'erreur (positif) de type errno. La dernière entrée du tableau doit être une invocation de la macro SD_BUS_ERROR_MAP_END. Le tableau ne doit pas être assemblé sans utiliser ces deux macros.

Notez que l'appel est idempotent : il est sûr de l'invoquer plusieurs fois avec le paramètre, ce qui n'ajoutera le tableau de mappage passé qu'une seule fois.

Notez que la mémoire allouée par cet appel n'est pas destinée à être libérée pendant la durée de vie du processus. Elle ne doit pas être libérée explicitement.

VALEUR RETOURNEE

sd_bus_error_add_map() renvoie une valeur positive lorsque le nouveau tableau a été ajouté aux tables de recherche. Il renvoie zéro lorsque le même tableau avait déjà été ajouté auparavant. En cas d'erreur, un code d'erreur négatif de type errno est renvoyé. Voir ci-dessous pour les codes d'erreur connus.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le tableau de mappage spécifié est invalide.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_error_add_map() a été ajouté dans la version 221.
