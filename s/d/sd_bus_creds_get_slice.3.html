DESCRIPTION

Ces fonctions renvoient des informations de crédentials à partir d'un objet sd_bus_creds. Les objets de crédentials peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les crédentials du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les crédentials d'un pair du bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les crédentials du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les crédentials de l'expéditeur du message.

Tous les champs de crédentials ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() renvoie l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() renvoie le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" retiré). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est renvoyé. Notez que cette propriété ne doit pas être utilisée pour plus qu'une information explicative, en particulier elle ne doit pas être utilisée pour des décisions relatives à la sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. DESCRIPTION

Le type sd_bus_creds(3) est utilisé pour représenter un ensemble de justificatifs d'un processus ou d'un pair D-Bus. Ces fonctions permettent de lire les divers champs de cet ensemble.

Notez que certaines fonctions renvoient un tableau de chaînes de caractères sous forme de pointeur vers un pointeur de chaîne de caractères (par exemple, char **), tandis que d'autres renvoient une chaîne de caractères unique sous forme de pointeur vers un pointeur de chaîne de caractères (par exemple, const char **).

sd_bus_creds_get_exe() récupérera le chemin d'accès à l'exécutable du processus (tel que stocké dans /proc/pid/exe). Pour les threads du noyau, un nom sera construit sous la forme « kernel:taskname ».

sd_bus_creds_get_cmdline() récupérera un tableau d'arguments de ligne de commande (tel que stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_cgroup() récupérera le chemin du groupe de contrôle. Voir Control Groups v2[1].

sd_bus_creds_get_unit() récupérera le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, renvoie -ENXIO.

sd_bus_creds_get_user_unit() récupérera le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, renvoie -ENXIO.

sd_bus_creds_get_slice() récupérera le slice systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupérera le slice systemd du processus, dans l'instance utilisateur de systemd.

sd_bus_creds_get_session() récupérera l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateur peuvent plutôt être démarrés à partir de leur gestionnaire d'utilisateur systemd, par exemple, les applications graphiques démarrées en utilisant l'activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, renvoie -ENXIO.

sd_bus_creds_get_owner_uid() récupérera l'UID numérique (identifiant utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, renvoie -ENXIO.

sd_bus_creds_has_effective_cap() vérifiera si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités permises.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités limitées.

sd_bus_creds_get_selinux_context() récupérera le contexte de sécurité SELinux (étiquette) du processus.

sd_bus_creds_get_audit_session_id() récupérera l'identifiant de session d'audit du processus. Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_audit_login_uid() récupérera l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur qui est « responsable » de la session). Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_tty() récupérera le TTY de contrôle, sans le préfixe « /dev/ ». Renvoie -ENXIO pour les processus qui n'ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupérera le nom unique D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_well_known_names() récupérera l'ensemble des noms bien connus D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_description() récupérera un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus du même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse à cet endroit comme adresse d'une chaîne de caractères se terminant par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse à cet endroit comme adresse d'un tableau de chaînes de caractères. Chaque chaîne individuelle se termine par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

VALEUR DE RETOUR

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ spécifié n'est pas disponible dans l'objet de justificatifs c.

-ENXIO

Le champ spécifié n'est pas défini pour le processus ou le pair décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'un slice systemd, ou d'une session logind. Il sera renvoyé par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (puisqu'ils ne sont pas démarrés à partir d'un binaire exécutable, et n'ont pas de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et par sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'au début du programme, lorsqu'aucun autre thread n'a été démarré.
