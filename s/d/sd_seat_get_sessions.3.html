sd_seat_get_sessions(3)

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_SEAT_GET_ACTIVE(3) sd_seat_get_active SD_SEAT_GET_ACTIVE(3)

NOM

sd_seat_get_active, sd_seat_get_sessions, sd_seat_can_tty, sd_seat_can_graphical - Déterminer l'état d'un siège spécifique

SYNTAXE

#include <systemd/sd-login.h>

int sd_seat_get_active(const char *seat, char **session, uid_t *uid);

int sd_seat_get_sessions(const char *seat, char ***ret_sessions, uid_t **ret_uids, unsigned int *ret_n_uids);

int sd_seat_can_tty(const char *seat);

int sd_seat_can_graphical(const char *seat);

DESCRIPTION

sd_seat_get_active() peut être utilisée pour déterminer quelle session est actuellement active sur un siège, s'il y en a une. Renvoie l'identifiant de la session et l'identifiant de l'utilisateur Unix auquel la session appartient. Le paramètre d'identifiant de session ou d'identifiant d'utilisateur peut être passé comme NULL, dans le cas où seul l'un des paramètres doit être interrogé. La chaîne de caractères renvoyée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_seat_get_sessions() peut être utilisée pour déterminer toutes les sessions sur le siège spécifié. Renvoie deux tableaux, un (terminé par NULL) avec les identifiants de session des sessions et un avec les identifiants d'utilisateur des utilisateurs Unix auxquels les sessions appartiennent. Un paramètre supplémentaire peut être utilisé pour renvoyer le nombre d'entrées dans ce dernier tableau. Cette valeur est la même que la valeur renvoyée si la valeur renvoyée est non négative. Les paramètres de sortie peuvent être passés comme NULL si ces valeurs de sortie ne sont pas nécessaires. Les tableaux et les chaînes référencées par ceux-ci doivent être libérés avec l'appel free(3) de la libc après utilisation. Notez qu'au lieu d'un tableau vide, NULL peut être renvoyé et doit être considéré comme équivalent à un tableau vide.

sd_seat_can_tty() peut être utilisée pour déterminer si un siège spécifique fournit des fonctionnalités TTY, c'est-à-dire s'il est utile comme console texte.

sd_seat_can_graphical() peut être utilisée pour déterminer si un siège spécifique fournit des fonctionnalités graphiques, c'est-à-dire s'il est utile comme écran graphique.

Si le paramètre seat de l'une de ces fonctions est passé comme NULL, l'opération est exécutée pour le siège de la session du processus appelant, s'il y en a un.

VALEUR DE RETOUR

En cas de succès, sd_seat_get_active() renvoie 0 ou un entier positif. En cas de succès, sd_seat_get_sessions() renvoie le nombre d'entrées dans le tableau des identifiants de session. Si le test réussit, sd_seat_can_tty() et sd_seat_can_graphical() renvoient un entier positif, sinon 0. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas spécifié pour le siège décrit.

-ENXIO

Le siège spécifié est inconnu.

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, là où cela n'est pas accepté).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

Les fonctions sd_seat_can_tty() et sd_seat_can_graphical() ont été ajoutées dans la version 186.
