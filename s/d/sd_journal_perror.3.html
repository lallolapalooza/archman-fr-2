SD_JOURNAL_PRINT(3) sd_journal_print SD_JOURNAL_PRINT(3)

NOM

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, SD_JOURNAL_SUPPRESS_LOCATION, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Soumettre des entrées de journal au journal système

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_print(int priorité, const char *format, ...);

int sd_journal_printv(int priorité, const char *format, va_list ap);

int sd_journal_send(const char *format, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *message);

int sd_journal_print_with_location(int priorité, const char *fichier, const char *ligne, const char *fonction, const char *format, ...);

int sd_journal_printv_with_location(int priorité, const char *fichier, const char *ligne, const char *fonction, const char *format, va_list ap);

int sd_journal_send_with_location(const char *fichier, const char *ligne, const char *fonction, const char *format, ...);

int sd_journal_sendv_with_location(const char *fichier, const char *ligne, const char *fonction, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *fichier, const char *ligne, const char *fonction, const char *message);

DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples en texte brut au journal système. Le premier argument est une valeur de priorité. Viennent ensuite une chaîne de format et ses paramètres, similaires à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une des suivantes : LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour les détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale système et au format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits à l'aide de cette fonction ne sont généralement pas censés se terminer par un caractère de nouvelle ligne. Cependant, tous les espaces blancs finaux (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne enregistrée, il est donc acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après la suppression des espaces blancs finaux) sont supprimées. Sur les lignes non vides, les espaces blancs initiaux (ainsi que les espaces blancs internes) restent inchangés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variables encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Son comportement est par ailleurs équivalent.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune immédiatement suivie de ses paramètres associés, terminée par NULL. Les chaînes passées doivent être au format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et composé uniquement de lettres, de chiffres et de traits de soulignement, et ne peut pas commencer par un trait de soulignement. (Toutes les affectations qui ne suivent pas cette syntaxe seront ignorées.) La valeur peut être de toute taille et de tout format. Il est fortement recommandé de soumettre uniquement des chaînes de texte formatées en encodage de caractères UTF-8, et de soumettre des champs binaires uniquement lorsqu'il n'est pas judicieux de formater en chaînes UTF-8. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs supplémentaires définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plus d'une valeur par entrée. Si cette fonction est utilisée, les espaces blancs finaux sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit faire référence à un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprimera pas les espaces blancs finaux des champs passés, mais transmettra les données spécifiées sans modification. Ceci est différent de sd_journal_print() et sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs finaux.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suivie de ": " et d'une représentation lisible par l'homme du code d'erreur actuel stocké dans errno(3). Si la chaîne de message est passée comme NULL ou comme chaîne vide, seule la représentation textuelle de l'erreur sera écrite, sans rien avant. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté en chaîne décimale. La priorité de journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour le rendre plus facile à utiliser lorsque seules des chaînes de texte doivent être soumises. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Bonjour le monde, c'est le PID %lu !", (unsigned long) getpid());
sd_journal_send("MESSAGE=Bonjour le monde, c'est le PID %lu !", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont invoqués. Ceci est implémenté avec des macros. Si ce n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() sont similaires à leurs homologues sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "fichier" et "ligne" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "fonction" ne doit contenir que le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture de wrappers personnalisés, par exemple dans des liaisons pour une autre langue.

syslog(3) et sd_journal_print() peuvent être largement utilisés de manière interchangeable en termes de fonctionnalités. Cependant, notez que les messages de journal enregistrés via le premier empruntent un chemin différent vers le serveur de journal que le second, et par conséquent, un ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage d'enregistrer la ligne de code source, les noms de fichiers et les fonctions en tant que métadonnées avec toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées qui sont générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client pour le **Protocole Natif du Journal**[1].

sd_journal_perror(3) — systemd-libs

NAME

sd_journal_perror, sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror_with_location, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location - log messages to the journal

SYNOPSIS

#include <systemd/sd-journal.h>
int sd_journal_print(int priority, const char *message);
int sd_journal_printv(int priority, const struct iovec *vector, size_t vector_len);
int sd_journal_send(const char *s1, ...);
int sd_journal_sendv(const struct iovec *vector, size_t vector_len);
int sd_journal_perror(const char *message);
int sd_journal_print_with_location(int priority, const char *file, const char *line, const char *func, const char *message);
int sd_journal_printv_with_location(int priority, const char *file, const char *line, const char *func, const struct iovec *vector, size_t vector_len);
int sd_journal_send_with_location(const char *file, const char *line, const char *func, const char *s1, ...);
int sd_journal_sendv_with_location(const char *file, const char *line, const char *func, const struct iovec *vector, size_t vector_len);
int sd_journal_perror_with_location(const char *file, const char *line, const char *func, const char *message);

DESCRIPTION

These functions provide a simple interface for logging messages to the systemd journal. They are intended for use in applications that do not need the full power of the sd-journal(3) API, but want to log messages with a priority and potentially some additional key-value pairs.

The functions write to the journal socket if it is available. If the journal service is not running, or the socket is unavailable for any other reason, the messages are redirected to stderr. This ensures that log output is not lost when the journal is unavailable. This redirection might change in future versions of systemd.

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_sendv(), sd_journal_perror(), and their counterparts with "_with_location" all log messages to the journal. They all accept a priority parameter, which should be one of the standard syslog message priorities (see syslog(3)). These are LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, and LOG_DEBUG.

sd_journal_print() logs a single message string. sd_journal_printv() logs a vector of strings. The strings in the vector are concatenated with newline characters in between.

sd_journal_send() and sd_journal_sendv() are used to log structured messages. The first argument (or the first element in the vector for sd_journal_sendv()) must be a string of the form "FIELD=value". Subsequent arguments/elements must also be strings in the same format. The priority parameter is implicitly LOG_INFO. These functions are useful for logging arbitrary data that might be used by other system services.

sd_journal_send() is variadic and takes a list of strings ending with NULL. For example: 

sd_journal_send("CMD=reboot", "USER_ID=1000", NULL);

sd_journal_sendv() takes a vector of strings. For example: 

struct iovec v[2];
v[0].iov_base = "CMD=shutdown"; v[0].iov_len = strlen(v[0].iov_base);
v[1].iov_base = "DELAY=5"; v[1].iov_len = strlen(v[1].iov_base);
sd_journal_sendv(v, 2);

sd_journal_perror() is a convenience function that logs a given message string followed by a colon, a space, and the current error message obtained via strerror(3). The priority is implicitly LOG_ERR.

The functions suffixed with "_with_location" additionally accept the source file name (file), line number (line), and function name (func) as arguments. These values are added as standard journal fields `CODE_FILE`, `CODE_LINE`, and `CODE_FUNC` respectively. This is useful for debugging and locating the origin of log messages.

The source file, line, and function can be automatically recorded by using the macros defined in <systemd/sd-journal.h>: 

#define SD_JOURNAL_PROVE_LOG(priority, message) \
        sd_journal_print_with_location(priority, __FILE__, STRINGIFY(__LINE__), __func__, message)
    #define SD_JOURNAL_PROVE_LOGV(priority, vector, vector_len) \
        sd_journal_printv_with_location(priority, __FILE__, STRINGIFY(__LINE__), __func__, vector, vector_len)
    #define SD_JOURNAL_PROVE_SEND(s1, ...) \
        sd_journal_send_with_location(__FILE__, STRINGIFY(__LINE__), __func__, s1, __VA_ARGS__)
    #define SD_JOURNAL_PROVE_SENDV(vector, vector_len) \
        sd_journal_sendv_with_location(__FILE__, STRINGIFY(__LINE__), __func__, vector, vector_len)
    #define SD_JOURNAL_PROVE_PERROR(message) \
        sd_journal_perror_with_location(__FILE__, STRINGIFY(__LINE__), __func__, message)
    #define STRINGIFY(x) #x

Using these macros is recommended over directly calling the "_with_location" functions, as they automatically capture the correct source location information.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno value.

If systemd-journald(8) is not running (the socket is not present), those functions do nothing, and also return 0.

THREAD SAFETY

All functions listed here are thread-safe and may be called in parallel from multiple threads.

sd_journal_sendv() and sd_journal_sendv_with_location() are "async signal safe" in the meaning of signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), and their counterparts with "_with_location" are not async signal safe.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_journal_print(), sd_journal_printv(), sd_journal_send(), and sd_journal_sendv() were added in version 187.

sd_journal_perror() was added in version 188.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), and sd_journal_perror_with_location() were added in version 246.
