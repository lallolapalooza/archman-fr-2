SD_BUS_EMIT_SIGNAL(3) sd_bus_emit_signal SD_BUS_EMIT_SIGNAL(3)

NOM

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_interfaces_added, sd_bus_emit_interfaces_added_strv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_object_added, sd_bus_emit_object_removed - Fonctions de commodité pour émettre des signaux D-Bus (standard)

SYNOPSIS

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, va_list ap);

int sd_bus_emit_signal_to(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *types, va_list ap);

int sd_bus_emit_interfaces_added(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_added_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_interfaces_removed(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, const char *name, ...);

int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, char **names);

int sd_bus_emit_object_added(sd_bus *bus, const char *path);

int sd_bus_emit_object_removed(sd_bus *bus, const char *path);

DESCRIPTION

sd_bus_emit_signal() est une fonction de commodité pour initialiser un objet de message de bus et émettre le signal D-Bus correspondant. Elle combine les fonctions sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) en un seul appel de fonction. sd_bus_emit_signalv() est équivalent à sd_bus_message_append(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments.

sd_bus_emit_signal_to() et sd_bus_emit_signal_tov() sont identiques à sd_bus_emit_signal() et sd_bus_emit_signalv(), sauf qu'ils peuvent émettre le signal vers une seule destination. Donnez destination comme NULL pour diffuser le signal.

sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() sont utilisés pour implémenter les signaux InterfacesAdded et InterfacesRemoved de l'interface org.freedesktop.DBus.ObjectManager. Ils prennent un chemin dont les interfaces ont été modifiées comme argument et une liste variable d'interfaces qui ont été ajoutées ou supprimées, respectivement. Le dernier argument passé à sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() *doit* être NULL. Cela permet aux deux fonctions de déterminer en toute sécurité le nombre d'arguments d'interface passés. sd_bus_emit_interfaces_added_strv() et sd_bus_emit_interfaces_removed_strv() sont identiques à leurs homologues respectifs mais prennent tous deux la liste des interfaces comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_properties_changed() est utilisé pour implémenter le signal PropertiesChanged de l'interface org.freedesktop.DBus.Properties. Il prend un chemin d'objet, une interface et une liste variable de noms de propriétés comme arguments. Le dernier argument passé à sd_bus_emit_properties_changed() *doit* être NULL. Cela lui permet de déterminer en toute sécurité le nombre de noms de propriétés passés. sd_bus_emit_properties_changed_strv() est identique à sd_bus_emit_properties_changed() mais prend la liste des noms de propriétés comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_object_added() et sd_bus_emit_object_removed() sont des fonctions de commodité pour émettre les signaux InterfacesAdded ou InterfacesRemoved pour toutes les interfaces enregistrées sur un chemin d'objet spécifique, respectivement. Cela inclut les tables de rechercheV parentes de secours si elles ne sont pas remplacées par une table de rechercheV enfant plus appropriée. Cela inclut également toutes les interfaces D-Bus standard implémentées par sd-bus lui-même sur n'importe quel objet enregistré.

Notez que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() et sd_bus_emit_object_removed() nécessitent qu'un gestionnaire d'objet ait été enregistré sur le chemin d'objet donné ou l'un de ses chemins d'objet parents en utilisant sd_bus_add_object_manager(3).

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier non négatif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

L'un des paramètres requis est NULL ou invalide. Une interface D-Bus réservée a été passée comme paramètre interface.

-ENOPKG

Le bus ne peut pas être résolu.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différente.

-ENOMEM

Échec de l'allocation mémoire.

-ESRCH

L'une des fonctions sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() ou sd_bus_emit_object_removed() a été appelée sur un objet sans gestionnaire d'objet enregistré sur son propre chemin d'objet ou l'un de ses chemins d'objet parents.

Voir les pages de manuel de sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) pour d'autres erreurs possibles.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

sd_bus_emit_object_added(3) — systemd manual pages

NAME

sd_bus_emit_object_added, sd_bus_emit_object_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov — Émettre des signaux D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_emit_object_added(sd_bus *bus, const char *path,
                             const char *interface);
int sd_bus_emit_object_removed(sd_bus *bus, const char *path,
                               const char *interface);
int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path,
                                      const char *const *interfaces);
int sd_bus_emit_properties_changed(sd_bus *bus, const char *path,
                                   const char *interface,
                                   sd_bus_error *error,
                                   const char *name, ...);
int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path,
                                      const char *interface,
                                      sd_bus_error *error,
                                      const char *const *changes);
int sd_bus_emit_signalv(sd_bus *bus, const char *path,
                        const char *interface, const char *member,
                        sd_bus_error *error, va_list ap);
int sd_bus_emit_signal_to(sd_bus *bus, sd_bus_message *message,
                          uint64_t fds, sd_bus_error *error);
int sd_bus_emit_signal_tov(sd_bus *bus, sd_bus_message *message,
                           const char *const *fds, sd_bus_error *error);

DESCRIPTION

These functions may be used to emit D-Bus signals from an object. They are convenience functions that wrap the more general functions like sd_bus_message_new_signal(3) and sd_bus_send(3).

sd_bus_emit_object_added() emits the org.freedesktop.DBus.ObjectManager.InterfacesAdded signal on the specified object path path for the given interface. This signal indicates that a new object has been added to the bus.

sd_bus_emit_object_removed() emits the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal on the specified object path path for the given interface. This signal indicates that an object has been removed from the bus.

sd_bus_emit_interfaces_removed_strv() emits the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. It is similar to sd_bus_emit_object_removed(3), but allows specifying multiple interfaces to be removed from the object at path. The interfaces array must be NULL-terminated.

sd_bus_emit_properties_changed() emits the org.freedesktop.DBus.Properties.PropertiesChanged signal. It is used to notify listeners that one or more properties of an object have changed. The signal is emitted for the specified interface on the object at path. The remaining arguments are property names and values. The last argument must be NULL.

sd_bus_emit_properties_changed_strv() is similar to sd_bus_emit_properties_changed(3), but takes an array of strings for the property changes. Each string in the changes array must be formatted as "property_name=value". The array must be NULL-terminated.

sd_bus_emit_signalv() emits a generic D-Bus signal. The signal is emitted on the bus bus for the object at path, for the specified interface and member. The signal arguments are passed via the `va_list` ap.

sd_bus_emit_signal_to() and sd_bus_emit_signal_tov() emit a signal from a pre-created message. This is useful for sending signals that were received from another bus or generated by lower-level APIs. The bus parameter is the bus connection to send the signal on. The message parameter is the signal message to send. fds specifies the number of file descriptors to be sent with the message. For sd_bus_emit_signal_tov(), fds is an array of file descriptor paths.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative error number.

NOTES

These functions are wrappers around lower-level D-Bus API calls. For more detailed information and usage examples, refer to the documentation for the underlying functions such as sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

The signals emitted by these functions conform to the standard D-Bus specifications for object management and property changes.
