SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

NOM

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Lire une séquence de valeurs à partir d'un message

SYN。PSIS

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

DESCRIPTION

sd_bus_message_read() lit une séquence de champs de l'objet de message D-Bus m et avance la position de lecture dans le message. La chaîne de types types décrit les types des éléments attendus dans le message et les arguments de champ qui suivent. La chaîne de types peut être NULL ou vide, auquel cas rien n'est lu.

La chaîne de types est composée des éléments décrits dans sd_bus_message_append(3), c'est-à-dire les types de base et les conteneurs. Elle doit contenir zéro ou plusieurs "types complets" individuels. La chaîne de types est terminée par un caractère NUL.

Pour chaque type spécifié dans la chaîne de types, un ou plusieurs arguments doivent être spécifiés après le paramètre types, dans le même ordre. Les arguments doivent être des pointeurs vers des types appropriés (un pointeur vers int8_t pour un "y" dans la chaîne de types, un pointeur vers int32_t pour un "i", un pointeur vers const char* pour un "s", ...) qui sont définis en fonction des valeurs dans le message. À titre d'exception, dans le cas des types tableau et variant, le premier argument est un argument "entrée" qui spécifie davantage comment le message doit être lu. Voir le tableau ci-dessous pour une liste complète des arguments autorisés et de leurs types. Notez que, si le type de base est un pointeur (par exemple, const char * dans le cas d'une chaîne), l'argument est un pointeur vers un pointeur, et la valeur du pointeur qui est écrite n'est qu'empruntée et le contenu doit être copié s'il doit être utilisé après la fin de la durée de vie du message. Si le type est "h" (descripteur de fichier UNIX), le descripteur n'est pas dupliqué par cet appel et le descripteur retourné reste en possession de l'objet message, et doit être dupliqué par l'appelant afin de conserver une référence ouverte à celui-ci après la libération de l'objet message.

Chaque argument peut également être NULL, auquel cas la valeur est lue et ignorée.

Si les objets des types spécifiés ne sont pas présents à la position actuelle dans le message, une erreur est renvoyée.

sd_bus_message_readv() est équivalent à sd_bus_message_read(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments. Cette fonction n'appelle pas la macro va_end(). Comme elle invoque la macro va_arg(), la valeur de ap est indéfinie après l'appel.

sd_bus_message_peek_type() détermine le type du prochain élément dans m à lire par sd_bus_message_read() ou des fonctions similaires. En cas de succès, le type est stocké dans type, s'il n'est pas NULL. Si le type est un type conteneur, le type de ses éléments est stocké dans contents, s'il n'est pas NULL. Si cette fonction détermine avec succès le type du prochain élément dans m, elle renvoie un entier positif. S'il n'y a plus d'éléments à lire, elle renvoie zéro.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

La chaîne de types spécifiée est invalide ou le paramètre message est NULL.

-ENXIO

Le message ne contient pas le type spécifié à la position actuelle.

-EBADMSG

Le message ne peut pas être analysé.

-EBUSY

Lors de la lecture à partir d'un conteneur, cette erreur sera renvoyée s'il reste des éléments non lus dans le conteneur.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr en environnement multithread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

sd_bus_message_read(3) — systemd — Arch manual pages

NAME

sd_bus_message_read, sd_bus_message_readv - Lire des données d'un message D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_message_read(sd_bus_message *m, const char *signature, ...);
int sd_bus_message_readv(sd_bus_message *m, const char *signature, va_list ap);

DESCRIPTION

La fonction sd_bus_message_read() lit une série de champs du message D-Bus m, en les plaçant dans les variables passées comme arguments suivants. Le deuxième argument, signature, est une chaîne de caractères décrivant les types des champs à lire, en utilisant la syntaxe de signature D-Bus. Les arguments suivants doivent pointer vers des variables dont le type correspond aux champs décrits dans la signature.

La fonction sd_bus_message_readv() est identique à sd_bus_message_read(), mais prend une liste d'arguments de variable ap au lieu d'une liste d'arguments de variable de longueur variable. Les deux fonctions avancent le curseur de lecture dans le message m par la longueur des données lues.

Les signatures de type D-Bus prises en charge sont les suivantes :

"y": octet signé (int8_t)

"b": booléen (int, 0 ou 1)

"n": entier court signé (int16_t)

"q": entier court non signé (uint16_t)

"i": entier signé (int32_t)

"u": entier non signé (uint32_t)

"x": entier long signé (int64_t)

"t": entier long non signé (uint64_t)

"h": descripteur de fichier (int)

"d": double précision (double)

"s": chaîne de caractères (const char *)

"o": chemin d'objet D-Bus (const char *)

"g": signature D-Bus (const char *)

"v": variant (voir ci-dessous)

"a": tableau (voir ci-dessous)

"{": début d'un dictionnaire (voir ci-dessous)

"(": début d'une structure (voir ci-dessous)

Les tableaux et les structures peuvent être imbriqués. Par exemple, "a(is)" est un tableau de structures, chacune contenant un entier et une chaîne de caractères.

Les variants "v" sont un peu spéciaux. Ils prennent un argument supplémentaire dans la signature qui décrit le type du contenu du variant. Par exemple, pour lire un variant contenant un entier signé, vous utiliseriez "vg", suivi de la signature du contenu du variant ("i"), puis d'un pointeur vers un int32_t.

Les dictionnaires sont lus comme une série de paires clé-valeur. Le nombre d'éléments doit être spécifié avant les arguments des paires. Par exemple, "a{is}" sera lu avec le nombre d'éléments, puis des paires d'entier et de chaîne de caractères.

Les structures sont lues séquentiellement selon l'ordre des champs dans la signature.

RETURN VALUE

En cas de succès, sd_bus_message_read() et sd_bus_message_readv() renvoient un nombre non négatif. En cas d'erreur, elles renvoient un code d'erreur négatif.

NOTES

Il est important de noter que pour les types qui sont plus petits que 64 bits (comme int8_t, uint16_t, etc.), la fonction sd_bus_message_read() lit toujours 64 bits à partir du message, puis effectue le décalage et le masquage nécessaires pour extraire la valeur correcte. Cela signifie que les arguments que vous passez doivent être suffisamment grands pour contenir 64 bits de données afin d'éviter la corruption de mémoire.

Pour les booléens (type 'b'), utilisez un int. Les types _Bool ou bool de C99 sont généralement plus petits que 64 bits et peuvent entraîner une corruption de mémoire.

Pour les descripteurs de fichier (type 'h'), la valeur lue est le descripteur de fichier lui-même. Il est de la responsabilité de l'appelant de cloner le descripteur de fichier s'il doit être conservé après la libération du message.

EXAMPLES

Lire un type de base unique (un entier de 64 bits) :

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Lire une valeur booléenne :

sd_bus_message *m;
int x; /* Ne pas utiliser le type C99 "bool" ici, il est généralement plus petit
          en mémoire et causerait une corruption de mémoire */
sd_bus_message_read(m, "b", &x);

Lire tous les types d'entiers :

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Lire une structure composée d'une chaîne et d'un chemin D-Bus :

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Lire un variant, avec le type réel "gt" (signature, entier non signé) :

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Lire un dictionnaire contenant trois paires de type {entier=>chaîne} :

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Lire un seul descripteur de fichier, et le dupliquer afin de le conserver ouvert après la libération du message.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);

HISTORY

sd_bus_message_read() et sd_bus_message_readv() ont été ajoutées dans la version 240.

sd_bus_message_peek_type() a été ajoutée dans la version 246.
