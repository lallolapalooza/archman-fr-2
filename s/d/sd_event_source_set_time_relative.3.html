sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Ajouter une source d'événements de temporisation à une boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPTION

sd_event_add_time() ajoute une nouvelle source d'événements de temporisation à une boucle d'événements. L'objet de la boucle d'événements est spécifié dans le paramètre event, l'objet de la source d'événements est retourné dans le paramètre source. Le paramètre clock prend un identifiant d'horloge, l'un de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, ou CLOCK_BOOTTIME_ALARM. Voir timerfd_create(2) pour des détails sur les divers types d'horloges. Le paramètre usec spécifie l'heure la plus tôt, en microsecondes (µs), par rapport à l'époque de l'horloge, à laquelle la temporisation doit être déclenchée. Si une heure déjà passée est spécifiée (y compris 0), cette source de temporisation "se déclenche" immédiatement et est prête à être distribuée. Si le paramètre est spécifié comme UINT64_MAX, l'événement de temporisation n'expirera jamais, ce qui peut être utilisé comme alternative à la désactivation explicite d'une source d'événement de temporisation avec sd_event_source_set_enabled(3). Le paramètre accuracy spécifie une valeur de précision supplémentaire en µs indiquant de combien l'événement de temporisation peut être retardé. Utilisez 0 pour sélectionner la précision par défaut (250 ms). Utilisez 1 µs pour une précision maximale. Envisagez de spécifier 60000000 µs (1 min) ou plus pour les événements de longue durée qui peuvent être retardés considérablement. Choisir des valeurs de précision plus élevées permet au système de regrouper plus agressivement les événements de temporisation, améliorant l'efficacité énergétique.

Le paramètre handler est une fonction à appeler lorsque la temporisation expire ou NULL. Le pointeur userdata sera passé à la fonction de gestionnaire, et peut être choisi librement par l'appelant. L'heure de déclenchement configurée est également passée au gestionnaire, même si l'appel se produit réellement légèrement plus tard, sous réserve de la valeur de précision spécifiée, du délai de temporisation du noyau (voir prctl(2)), et des latences de planification supplémentaires. Pour interroger l'heure réelle à laquelle le gestionnaire a été appelé, utilisez sd_event_now(3). Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

Par défaut, la temporisation expirera une fois (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction de gestionnaire retourne un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, soit elle provoquera la fin de la boucle, voir sd_event_source_set_exit_on_failure(3). Notez qu'une temporisation définie sur SD_EVENT_ON se déclenchera en continu, sauf si son heure configurée est mise à jour en utilisant sd_event_source_set_time().

sd_event_add_time_relative() est similaire à sd_event_add_time(), mais prend une spécification de temps relative. Elle est relative au temps actuel de l'itération de la boucle d'événements, tel que retourné par sd_event_now(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont abandonnées. Pour vous assurer qu'une source d'événement ne se déclenche plus, même si elle est toujours référencée, désactivez la source d'événement en utilisant sd_event_source_set_enabled(3) avec SD_EVENT_OFF.

Si le deuxième paramètre de sd_event_add_time() est NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_time() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, casté en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

Utilisez CLOCK_BOOTTIME_ALARM et CLOCK_REALTIME_ALARM pour définir des sources d'événements qui peuvent réveiller le système de la mise en veille.

Afin de configurer des temporisations relatives (c'est-à-dire relatives au temps actuel), récupérez le temps actuel via sd_event_now(3), ajoutez la durée souhaitée, et utilisez le résultat comme paramètre usec pour sd_event_add_time().

Afin de configurer des temporisations répétitives (c'est-à-dire des temporisations qui se déclenchent à intervalles réguliers), configurez la temporisation normalement, pour la première invocation. Chaque fois que le gestionnaire d'événements est appelé, mettez à jour le temps de déclenchement de la temporisation avec sd_event_source_set_time(3) pour la prochaine itération de temporisation, et réactivez la temporisation en utilisant sd_event_source_set_enabled(). Pour calculer le prochain point dans le temps à passer à sd_event_source_set_time(), utilisez comme base soit le paramètre usec passé au rappel de temporisation, soit l'horodatage retourné par sd_event_now(). Dans le premier cas, les événements de temporisation seront réguliers, tandis que dans le second cas, la latence de planification continuera de s'accumuler sur la temporisation.

sd_event_source_get_time() récupère la valeur de temps configurée d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker le temps, par rapport à l'époque de l'horloge sélectionnée, en µs. La valeur retournée est relative à l'époque, même si la source d'événement a été créée avec un temps relatif via sd_event_add_time_relative().

sd_event_source_set_time() modifie le temps d'une source d'événement créée précédemment avec sd_event_add_time() ou sd_event_add_time_relative(). Elle prend l'objet source d'événement et un temps relatif à l'époque de l'horloge sélectionnée, en µs.

sd_event_source_set_time_relative() est similaire à sd_event_source_set_time(), mais prend un temps relatif au temps actuel de l'itération de la boucle d'événements, tel que retourné par sd_event_now().

sd_event_source_get_time_accuracy() récupère la valeur de précision configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend l'objet source d'événement et un pointeur vers une variable pour stocker la précision. La précision est spécifiée en µs.

sd_event_source_set_time_relative(3) — systemd 258.2

NAME

sd_event_source_set_time_relative, sd_event_source_get_time_relative, sd_event_source_set_time_accuracy, sd_event_source_get_time_accuracy, sd_event_source_get_time_clock — Configurer et interroger les sources d'événements basées sur le temps

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);
int sd_event_source_get_time_relative(sd_event_source *source, uint64_t *usec);
int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);
int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *usec);
int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock);

DESCRIPTION

Les fonctions sd_event_source_set_time_relative() et sd_event_source_get_time_relative() configurent et interrogent la valeur de temps relative d'une source d'événement créée précédemment avec sd_event_add_time(). La valeur spécifiée en microsecondes est ajoutée au temps courant pour déterminer quand l'événement doit être déclenché.

La fonction sd_event_source_set_time_accuracy() configure la précision souhaitée d'une source d'événement créée précédemment avec sd_event_add_time(). Cette valeur en microsecondes indique la marge d'erreur acceptable pour le déclenchement de l'événement. Une valeur de 0 signifie une précision maximale.

La fonction sd_event_source_get_time_accuracy() récupère la précision configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend la source d'événement et un pointeur vers une variable pour stocker la précision en microsecondes.

La fonction sd_event_source_get_time_clock() récupère l'horloge configurée d'une source d'événement créée précédemment avec sd_event_add_time(). Elle prend la source d'événement et un pointeur vers une variable pour stocker l'identifiant de l'horloge.

RETURN VALUE

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Errors

Les valeurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

-EOPNOTSUPP

L'horloge sélectionnée n'est pas prise en charge par l'implémentation de la boucle d'événements.

-EDOM

La source d'événement passée n'est pas une source d'événement de temporisation.

-EOVERFLOW

Le temps relatif passé est en dehors de la plage autorisée pour les valeurs de temps (c'est-à-dire que la valeur spécifiée ajoutée au temps courant est en dehors de la plage des entiers non signés 64 bits).

Ajouté dans la version 247.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
