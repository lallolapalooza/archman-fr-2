DESCRIPTION

Ces fonctions renvoient des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les informations d'identification du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les informations d'identification d'un pair de bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les informations d'identification du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les informations d'identification de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupérera le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupérera le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_pidfd_dup() récupérera le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupérera le TID (identifiant de thread).

sd_bus_creds_get_uid() récupérera l'UID numérique (identifiant d'utilisateur). De même, sd_bus_creds_get_euid() renvoie l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupérera le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() renvoie le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupérera la liste des GIDs supplémentaires.

sd_bus_creds_get_comm() récupérera le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupérera le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupérera le chemin de l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est renvoyé. Notez que cette propriété ne doit pas être utilisée pour des informations à des fins d'explication, en particulier elle ne doit pas être utilisée pour des décisions relatives à la sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. De plus, le noyau exporte ces informations de manière ambiguë (c'est-à-dire qu'un exécutable supprimé ne peut pas être distingué en toute sécurité d'un exécutable dont le nom.

DESCRIPTION

La structure sd_bus_creds est utilisée pour contenir diverses informations sur les identifiants d'un processus ou d'une connexion D-Bus. Il est typiquement créé en utilisant sd_bus_creds_new_from_pid(3) ou sd_bus_get_peer_creds(3).

Les fonctions décrites ici extraient des informations spécifiques à partir d'un objet sd_bus_creds donné.

  • sd_bus_creds_get_pid() récupère l'ID de processus (PID).
  • sd_bus_creds_get_tid() récupère l'ID de thread (TID). Pour les processus qui ne sont pas dans un groupe de threads, cela renverra le même valeur que sd_bus_creds_get_pid().
  • sd_bus_creds_get_pidfd_dup() récupère un descripteur de fichier qui peut être utilisé pour obtenir un pidfd pour le processus. Le descripteur de fichier est dupliqué et le nouveau descripteur est retourné. Le retour est un fichier descripteur qui doit être fermé par l'appelant. Retourne -ENXIO s'il n'est pas possible d'obtenir un pidfd pour le processus.
  • sd_bus_creds_get_ppid() récupère l'ID du processus parent (PPID).
  • sd_bus_creds_get_uid() récupère l'UID réel du processus.
  • sd_bus_creds_get_euid() récupère l'UID effectif du processus.
  • sd_bus_creds_get_suid() récupère l'UID sauvegardé du processus.
  • sd_bus_creds_get_fsuid() récupère l'UID du système de fichiers du processus.
  • sd_bus_creds_get_gid() récupère le GID réel du processus.
  • sd_bus_creds_get_egid() récupère le GID effectif du processus.
  • sd_bus_creds_get_sgid() récupère le GID sauvegardé du processus.
  • sd_bus_creds_get_fsgid() récupère le GID du système de fichiers du processus.
  • sd_bus_creds_get_supplementary_gids() récupère un tableau des GID supplémentaires du processus. Le tableau est terminé par NULL.
  • sd_bus_creds_get_comm() récupère le nom de la commande courte (tel que vu dans /proc/pid/comm).
  • sd_bus_creds_get_tid_comm() récupère le nom de la commande courte du thread (tel que vu dans /proc/pid/task/tid/comm).
  • sd_bus_creds_get_exe() récupère le chemin du fichier exécutable du processus (tel qu'il est stocké dans /proc/pid/exe).
  • sd_bus_creds_get_cmdline() récupère un tableau d'arguments de ligne de commande (tel qu'il est stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est renvoyé.
  • sd_bus_creds_get_cgroup() récupère le chemin du groupe de contrôle. Voir Control Groups v2[1].
  • sd_bus_creds_get_unit() récupère le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, renvoie -ENXIO.
  • sd_bus_creds_get_user_unit() récupère le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, renvoie -ENXIO.
  • sd_bus_creds_get_slice() récupère la tranche systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère la tranche systemd du processus, dans l'instance utilisateur de systemd.
  • sd_bus_creds_get_session() récupère l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateurs peuvent plutôt être démarrés à partir de leur gestionnaire d'utilisateurs systemd, par exemple des applications graphiques démarrées en utilisant l'activation DBus, ainsi que des processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, renvoie -ENXIO.
  • sd_bus_creds_get_owner_uid() récupère l'UID numérique (identifiant d'utilisateur) de l'utilisateur qui possède l'unité utilisateur ou la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, renvoie -ENXIO.
  • sd_bus_creds_has_effective_cap() vérifie si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).
  • sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités permises.
  • sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités héritables.
  • sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifie le masque des capacités de limitation.
  • sd_bus_creds_get_selinux_context() récupère le contexte de sécurité SELinux (label) du processus.
  • sd_bus_creds_get_audit_session_id() récupère l'identifiant de session d'audit du processus. Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
  • sd_bus_creds_get_audit_login_uid() récupère l'identifiant de connexion d'utilisateur d'audit (l'identifiant de l'utilisateur qui est "responsable" de la session). Renvoie -ENXIO pour les processus qui ne font pas partie d'une session d'audit.
  • sd_bus_creds_get_tty() récupère le TTY de contrôle, sans le préfixe "/dev/". Renvoie -ENXIO pour les processus qui n'ont pas de TTY de contrôle.
  • sd_bus_creds_get_unique_name() récupère le nom unique D-Bus. Voir The D-Bus specification[2].
  • sd_bus_creds_get_well_known_names() récupère l'ensemble des noms connus de D-Bus. Voir The D-Bus specification[2].
  • sd_bus_creds_get_description() récupère un nom descriptif de la connexion bus du pair. Ce nom est utile pour discerner plusieurs connexions bus par le même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse là sous forme d'une adresse d'une chaîne terminée par NUL. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse là sous forme d'une adresse d'un tableau de chaînes. Chaque chaîne individuelle est terminée par NUL, et le tableau est terminé par NULL dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

RETURN VALUE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de style errno.

Errors

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet credentials c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera renvoyé par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une tranche systemd, ou d'une session logind. Il sera renvoyé par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera aussi renvoyé par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas démarrés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
