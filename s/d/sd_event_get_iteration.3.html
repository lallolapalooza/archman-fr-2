NOM

sd_event_wait, sd_event_prepare, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Opérations de bas niveau de la boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_state(sd_event *event);

int sd_event_get_iteration(sd_event *event, uint64_t *ret);

DESCRIPTION

Les fonctions de bas niveau sd_event_prepare(), sd_event_wait() et sd_event_dispatch() peuvent être utilisées pour exécuter des phases spécifiques d'une boucle d'événements. Voir sd_event_run(3) et sd_event_loop(3) pour les fonctions de plus haut niveau qui exécutent des itérations individuelles mais complètes d'une boucle d'événements ou la font tourner en continu.

sd_event_prepare() vérifie les événements en attente et arme les minuteurs nécessaires. Si des événements sont prêts à être traités (« en attente »), elle renvoie une valeur positive non nulle, et l'appelant doit traiter ces événements avec sd_event_dispatch().

sd_event_dispatch() distribue la source d'événement de plus haute priorité qui a un événement en attente. En cas de succès, sd_event_dispatch() renvoie soit zéro, ce qui indique qu'aucune autre source d'événement ne peut être distribuée et que la sortie de la boucle d'événements a été demandée via sd_event_exit(3) ; soit une valeur positive non nulle, ce qui signifie qu'une source d'événement a été distribuée et que la boucle est revenue à son état initial, et l'appelant doit initier la prochaine itération de la boucle d'événements en appelant à nouveau sd_event_prepare().

Si sd_event_prepare() a renvoyé zéro, sd_event_wait() doit être appelé pour attendre d'autres événements ou un délai d'attente. Si des événements sont prêts à être traités, elle renvoie une valeur positive non nulle, et les événements doivent être distribués avec sd_event_dispatch(). Sinon, la boucle d'événements est revenue à son état initial et la prochaine itération de la boucle d'événements doit être initiée en appelant à nouveau sd_event_prepare().

sd_event_get_state() peut être utilisé pour déterminer l'état dans lequel se trouve actuellement la boucle d'événements. Elle renvoie l'un des états décrits ci-dessous.

sd_event_get_iteration() peut être utilisé pour déterminer l'itération actuelle de la boucle d'événements. Elle renvoie un entier non signé de 64 bits contenant un compteur qui augmente de manière monotone à chaque itération de la boucle d'événements, en commençant par 0. Le compteur est incrémenté au moment de l'appel à sd_event_prepare().

Les cinq fonctions prennent, comme premier argument, l'objet de boucle d'événements event qui a été créé avec sd_event_new(). Le délai d'attente pour sd_event_wait() est spécifié en usec en microsecondes. (uint64_t) -1 peut être utilisé pour spécifier un délai d'attente infini.

MACHINE D'ÉTATS

La boucle d'événements connaît les états suivants, qui peuvent être interrogés avec sd_event_get_state().

SD_EVENT_INITIAL

L'état initial de la boucle d'événements, avant chaque itération de la boucle d'événements. Utilisez sd_event_prepare() pour passer la boucle d'événements aux états SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_PREPARING

Une source d'événement est en cours de préparation, c'est-à-dire que le gestionnaire de préparation est en cours d'exécution, tel que défini avec sd_event_source_set_prepare(3). Cet état n'est visible que dans le gestionnaire de préparation d'événements qui est appelé depuis l'appel sd_event_prepare() et est immédiatement suivi par SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_ARMED

sd_event_prepare() a été appelé et aucune source d'événement n'était prête à être distribuée. Utilisez sd_event_wait() pour attendre de nouveaux événements, et passer à SD_EVENT_PENDING ou revenir à SD_EVENT_INITIAL.

Ajouté dans la version 229.

SD_EVENT_PENDING

sd_event_prepare() ou sd_event_wait() ont été appelés et il y avait des sources d'événement avec des événements en attente. Utilisez sd_event_dispatch() pour distribuer la source d'événement de plus haute priorité et revenir à SD_EVENT_INITIAL, ou à SD_EVENT_FINISHED.

Ajouté dans la version 229.

SD_EVENT_RUNNING

Une source d'événement régulière est en cours de distribution. Cet état n'est visible que dans le gestionnaire de source d'événement qui est appelé depuis l'appel sd_event_dispatch(), et est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès le retour du gestionnaire de source d'événement. Notez que lors de la distribution des sources d'événements de sortie, l'état SD_EVENT_EXITING est vu à la place.

Ajouté dans la version 229.

SD_EVENT_EXITING

Similaire à SD_EVENT_RUNNING mais c'est l'état en vigueur lors de la distribution des sources d'événements de sortie. Il est suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès le retour du gestionnaire d'événements.

Ajouté dans la version 229.

SD_EVENT_FINISHED

La boucle d'événements s'est terminée. Toutes les sources d'événements de sortie ont été exécutées. Si la boucle d'événements est dans cet état, elle n'a plus aucun but et devrait être libérée.

Ajouté dans la version 229.

Un schéma simplifié des états et des appels pour passer de l'un à l'autre est montré ci-dessous. Notez que SD_EVENT_PREPARING, SD_EVENT_RUNNING et SD_EVENT_EXITING ne sont pas montrés ici.

          INITIAL -<---<---<---<---<---<---<---<---<---<---<---<---\
             |                                                     |
             |                                                     ^
             |                                                     |
             v                 ret == 0                            |
      sd_event_prepare() >--->--->--->--->- ARMED                  |
             |                                |                    ^
             | ret > 0                        |                    |
             |                                |                    |
             v                                v          ret == 0  |
          PENDING <---<---<---<---<---< sd_event_wait() >--->--->--+
             |           ret > 0                                   ^
             |                                                     |
             |                                                     |
             v                                                     |
      sd_event_dispatch() >--->--->--->--->--->--->--->--->--->--->/
             |                             ret > 0
             | ret == 0
             |
             v
          FINISHED

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient 0 ou un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno. Dans le cas de sd_event_prepare() et sd_event_wait(), un code de retour positif et non nul indique que des événements sont prêts à être traités et zéro indique qu'aucun événement n'est prêt. Dans le cas de sd_event_dispatch(), un code de retour positif et non nul indique que la boucle d'événements est revenue à son état initial et zéro indique que la boucle d'événements s'est terminée. sd_event_get_state() renvoie un état positif ou nul en cas de succès.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre event est invalide ou NULL.

-EBUSY

L'objet de boucle d'événements n'est pas dans le bon état.

-ESTALE

La boucle d'événements est déjà terminée.

NAME

sd_event_get_iteration, sd_event_get_state, sd_event_prepare, sd_event_wait, sd_event_dispatch — event loop state and iteration

SYNOPSIS

int sd_event_get_iteration(sd_event *event, usec_t *ret_usec);

int sd_event_get_state(sd_event *event);

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, usec_t usec);

int sd_event_dispatch(sd_event *event);

DESCRIPTION

The sd_event API provides an implementation of a generic, flexible, fully asynchronous event loop. See sd_event(3) for a detailed description.

The functions described here allow querying and controlling the state of an event loop.

sd_event_get_iteration() retrieves the time spent in the event loop's main loop in the last iteration, in microseconds. This value is stored in ret_usec. The event loop object is passed in event.

sd_event_get_state() returns the current state of the event loop. The state is one of the following:

SD_EVENT_INITIALIZING

SD_EVENT_PENDING

SD_EVENT_RUNNING

SD_EVENT_WAITING

SD_EVENT_DISPATCHING

SD_EVENT_FINISHED

The state SD_EVENT_INITIALIZING is returned before the first call to sd_event_run(). The state SD_EVENT_PENDING is returned when the event loop is not running, but has pending events or sources that might cause it to run. The state SD_EVENT_RUNNING is returned when the event loop is currently running. The state SD_EVENT_WAITING is returned when the event loop is currently blocked in a system call (e.g. poll()). The state SD_EVENT_DISPATCHING is returned when the event loop is currently dispatching an event. The state SD_EVENT_FINISHED is returned when the event loop has been shut down.

sd_event_prepare() is called by the main loop before entering the poll(2) system call. It allows all registered event sources to prepare themselves. Event sources can register a callback for this purpose using sd_event_source_set_prepare(3).

sd_event_wait() blocks until an event is available or the specified timeout usec (in microseconds) has passed. If usec is zero, it blocks indefinitely until an event is available. If usec is positive, it blocks for at most that duration. This function is intended to be called by the event loop implementation itself, not directly by user code.

sd_event_dispatch() processes all events that are ready to be dispatched. This function is also intended to be called by the event loop implementation itself, not directly by user code.

STATE MACHINE

The state of the event loop transitions as follows:

INITIALIZING -> PENDING (on first call to sd_event_run())

PENDING -> PREPARE (on call to sd_event_prepare())

PREPARE -> WAITING (on call to sd_event_wait())

WAITING -> DISPATCHING (when an event is ready)

DISPATCHING -> PENDING (after dispatching all ready events)

PENDING -> FINISHED (on call to sd_event_shutdown())

RETURN VALUE

sd_event_get_iteration() returns the time spent in the last iteration in microseconds on success, or a negative error number on failure. If no iterations have been completed yet, it returns 0.

sd_event_get_state() returns the current state of the event loop, or a negative error number on failure.

sd_event_prepare(), sd_event_wait(), and sd_event_dispatch() return 0 on success, or a negative error number on failure.

On failure, -ENOMEM may be returned if memory allocation failed. This is a sd_event_new(3)-only error.

On failure, -EINVAL may be returned if an invalid event loop was passed.

On failure, -ECHILD may be returned if the event loop has been created in a different process, library, or module instance.

Other errors are possible, too.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_event_prepare(), sd_event_wait(), sd_event_dispatch(), and sd_event_get_state() were added in version 221.

sd_event_get_iteration() was added in version 231.
