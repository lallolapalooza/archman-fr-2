NOM

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Ajouter une source d'événements d'inode de système de fichiers "inotify" à une boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPTION

sd_event_add_inotify() ajoute une nouvelle source d'événements d'inode de système de fichiers inotify(7) à une boucle d'événements. L'objet de la boucle d'événements est spécifié dans le paramètre event, l'objet source d'événement est retourné dans le paramètre source. Le paramètre path spécifie le chemin de l'inode du système de fichiers à surveiller. Le paramètre mask spécifie quels types d'événements d'inode surveiller spécifiquement. Il doit contenir une combinaison OR-ed des drapeaux IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, ... Voir inotify(7) pour plus d'informations.

Le handler doit référencer une fonction à appeler lorsque l'inode change ou NULL. La fonction de gestionnaire recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure `struct inotify_event` contenant des informations sur l'événement de l'inode. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

sd_event_add_inotify_fd() est identique à sd_event_add_inotify(), sauf qu'elle prend un descripteur de fichier vers un inode (éventuellement un descripteur O_PATH, mais tout autre fonctionnera aussi) au lieu d'un chemin dans le système de fichiers.

Si plusieurs sources d'événements sont installées pour le même inode, le descripteur de surveillance inotify sous-jacent est automatiquement partagé. Le paramètre mask peut contenir n'importe quel drapeau défini par l'API inotify, à l'exception de IN_MASK_ADD.

Le gestionnaire est activé en continu (SD_EVENT_ON), mais cela peut être modifié avec sd_event_source_set_enabled(3). Alternativement, le drapeau de masque IN_ONESHOT peut être utilisé pour demander le mode SD_EVENT_ONESHOT. Si la fonction de gestionnaire retourne un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant.

Comme limitation spéciale, la priorité des sources d'événements inotify ne peut être modifiée (voir sd_event_source_set_priority(3)) qu'entre la création de l'objet source d'événement avec sd_event_add_inotify() et le début de la prochaine itération de la boucle d'événements. Les tentatives de modification de la priorité ultérieurement seront refusées. Envisagez de libérer et d'allouer une nouvelle source d'événement inotify pour modifier la priorité à ce moment-là.

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même lorsqu'il y a encore une référence à elle, envisagez de la désactiver avec sd_event_source_set_enabled(3).

Si le deuxième paramètre de sd_event_add_inotify() est passé comme NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_inotify() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

sd_event_source_get_inotify_mask() récupère le masque de surveillance inotify configuré d'une source d'événement créée précédemment avec sd_event_add_inotify(). Elle prend l'objet source d'événement comme paramètre source et un pointeur vers une variable uint32_t pour y retourner le masque.

sd_event_source_get_inotify_path() récupère le chemin cible de la surveillance inotify configurée d'une source d'événement créée précédemment avec sd_event_add_inotify(). Elle prend l'objet source d'événement comme paramètre source et un pointeur vers une variable const char ** pour y retourner le chemin. L'appelant ne doit pas libérer le chemin retourné.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque avec IN_MASK_ADD défini.

-ESTALE

Retourné par sd_event_source_add_inotify() ou sd_event_source_add_inotify_fd() lorsque la boucle d'événements est déjà terminée. Retourné par sd_event_source_get_inotify_path() lorsqu'aucune donnée d'inode active n'est attribuée à la source d'événement, par exemple lorsque la source d'événement est désactivée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différent.

-EDOM

La source d'événement passée n'est pas une source d'événement de processus inotify.

-EBADF

Le descripteur de fichier passé n'est pas valide.

-ENOSYS

sd_event_add_inotify_fd() ou sd_event_source_get_inotify_path() a été appelé sans montage de /proc/.

static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminate the program if an "exit" file appears */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les environnements multi-threads. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
