sd_get_machine_names(3)

SD_GET_SEATS(3) sd_get_seats SD_GET_SEATS(3)

NOM

sd_get_seats, sd_get_sessions, sd_get_uids, sd_get_machine_names - Déterminer les sièges, sessions, utilisateurs connectés et machines virtuelles/conteneurs disponibles

SYNOPIS

#include <systemd/sd-login.h>

int sd_get_seats(char ***seats);

int sd_get_sessions(char ***sessions);

int sd_get_uids(uid_t **users);

int sd_get_machine_names(char ***machines);

DESCRIPTION

sd_get_seats() peut être utilisé pour déterminer tous les sièges locaux actuellement disponibles. Renvoie le nombre d'identifiants de sièges et, si le pointeur d'entrée n'est pas NULL, un tableau d'identifiants de sièges se terminant par NULL est stocké à l'adresse. Le tableau renvoyé et toutes les chaînes qu'il référence doivent être libérés avec l'appel free(3) de la libc après utilisation. Notez qu'au lieu d'un tableau vide, NULL peut être renvoyé et doit être considéré comme équivalent à un tableau vide.

De même, sd_get_sessions() peut être utilisé pour déterminer toutes les sessions de connexion actuelles.

De même, sd_get_uids() peut être utilisé pour déterminer tous les utilisateurs Unix qui ont actuellement des sessions de connexion.

De même, sd_get_machine_names() peut être utilisé pour déterminer toutes les machines virtuelles et conteneurs actuels sur le système.

Notez que les listes renvoyées ne sont pas triées et sont dans un ordre indéfini.

VALEUR RENVOYÉE

En cas de succès, sd_get_seats(), sd_get_sessions(), sd_get_uids() et sd_get_machine_names() renvoient le nombre d'entrées dans les tableaux. En cas d'échec, ces appels renvoient un code d'erreur négatif de type errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_get_machine_names() a été ajouté dans la version 203.
