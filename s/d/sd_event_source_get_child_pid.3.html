DESCRIPTION

sd_event_add_child() ajoute une nouvelle source d'événement d'état de processus enfant à une boucle d'événements. La boucle d'événements est spécifiée dans le paramètre event, la source d'événement est retournée dans le paramètre source. Le paramètre pid spécifie le PID du processus à surveiller, qui doit être un processus enfant direct du processus appelant. Le paramètre options détermine quels changements d'état seront surveillés. Il doit contenir un masque OR de WEXITED (surveiller la terminaison du processus enfant), WSTOPPED (surveiller l'arrêt du processus enfant par un signal), et WCONTINUED (surveiller la reprise du processus enfant par un signal). Voir waitid(2) pour plus d'informations.

Le handler doit être une fonction à appeler lorsque le processus change d'état ou NULL. La fonction handler recevra le pointeur userdata, qui peut être choisi librement par l'appelant. Le handler reçoit également un pointeur vers une structure siginfo_t contenant des informations sur l'événement du processus enfant. Le handler peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), les autres valeurs de retour sont ignorées. Si handler est NULL, un handler par défaut qui appelle sd_event_exit(3) sera utilisé.

Un seul handler peut être installé pour un processus enfant spécifique. Le handler est activé pour un seul événement (SD_EVENT_ONESHOT), mais cela peut être modifié avec sd_event_source_set_enabled(3). Si la fonction handler retourne un code d'erreur négatif, elle sera soit désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant, soit elle provoquera la terminaison de la boucle, voir sd_event_source_set_exit_on_failure(3).

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est retirée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même lorsqu'une référence est toujours conservée, envisagez de mettre la source d'événement sur SD_EVENT_OFF avec sd_event_source_set_enabled(3).

Le signal SIGCHLD doit être bloqué dans tous les threads avant d'appeler cette fonction (en utilisant sigprocmask(2) ou pthread_sigmask(3)).

Si le deuxième paramètre de sd_event_add_child() est passé en tant que NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Notez que la fonction handler est invoquée à un moment où le processus enfant n'a pas encore été ramassé (et est donc encore exposé comme un processus zombie par le noyau). Cependant, l'enfant sera automatiquement ramassé après le retour de la fonction. Les processus enfants pour lesquels aucune source d'événement d'état de processus enfant n'est installée ne seront pas ramassés par l'implémentation de la boucle d'événements.

Si le paramètre handler de sd_event_add_child() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé en tant que paramètre de code de sortie à sd_event_exit(3).

Si à la fois une source d'événement d'état de processus enfant et une source d'événement de signal SIGCHLD sont installées dans la même boucle d'événements, les priorités configurées des sources d'événements décident quelle source d'événement est traitée en premier. Si le gestionnaire de signal est traité en premier, il devrait laisser les processus enfants pour lesquels des sources d'événements d'état de processus enfant sont installées non ramassés.

sd_event_add_child_pidfd() est similaire à sd_event_add_child() mais prend un descripteur de fichier faisant référence au processus ("pidfd") au lieu du PID numérique. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2) et les appels associés. Le descripteur de fichier passé n'est pas fermé lorsque la source d'événement est libérée à nouveau, à moins que sd_event_source_set_child_pidfd_own() ne soit utilisé pour activer ce comportement. Notez que quel que soit l'appel utilisé, sd_event_add_child() ou sd_event_add_child_pidfd() pour allouer une source d'événement, le processus surveillé doit être un processus enfant direct du processus appelant. De plus, dans les deux cas, SIGCHLD doit être bloqué dans le processus appelant.

sd_event_source_get_child_pid() récupère le PID configuré d'une source d'événement d'état de processus enfant créée précédemment avec sd_event_add_child(). Il prend l'objet source d'événement comme paramètre source et un pointeur vers une variable pid_t pour y retourner l'ID du processus.

sd_event_source_get_child_pidfd() récupère le descripteur de fichier faisant référence au processus surveillé ("pidfd"). La boucle d'événements utilise en interne des pidfd pour surveiller les processus enfants, indépendamment du fait que les sources d'événements individuelles soient allouées via sd_event_add_child() ou sd_event_add_child_pidfd(). Si le dernier appel a été utilisé pour allouer la source d'événement, cette fonction retourne le descripteur de fichier d'origine utilisé pour l'allocation. Cet appel prend l'objet source d'événement comme paramètre source et retourne le descripteur de fichier numérique.

sd_event_source_get_child_pidfd_own() peut être utilisé pour interroger si le pidfd que la source d'événement encapsule doit être fermé lorsque la source d'événement est libérée. Cette fonction retourne zéro si le pidfd doit rester ouvert, et positif s'il doit être fermé automatiquement. Par défaut, ce réglage est activé si la source d'événement a été allouée via sd_event_add_child() et désactivé si elle a été allouée via sd_event_add_child_pidfd(). La fonction sd_event_source_set_child_pidfd_own() peut être utilisée pour changer le réglage et prend un paramètre booléen avec le nouveau réglage.

sd_event_source_get_child_process_own() peut être utilisé pour interroger si le processus que la source d'événement surveille doit être tué (avec SIGKILL) et ramassé lorsque la source d'événement est libérée. Cette fonction retourne zéro si le processus doit rester en cours d'exécution, et positif s'il doit être tué et ramassé automatiquement. Par défaut, ce réglage est désactivé. VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque vide dans options ou d'un masque contenant des valeurs différentes d'une combinaison de WEXITED, WSTOPPED et WCONTINUED.

-EBUSY

Un gestionnaire est déjà installé pour ce processus enfant, ou SIGCHLD n'est pas bloqué.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un autre processus, bibliothèque ou instance de module.

-EDOM

La source d'événements passée n'est pas une source d'événements de processus enfant.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

EXEMPLE

Exemple 1. Arrêter la boucle lorsque l'enfant se termine

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* Le signal SIGCHLD doit être bloqué pour que sd_event_add_child fonctionne */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* enfant */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Créer la boucle d'événements par défaut */
    sd_event_default(&e);
    assert(e);
    /* Nous créons une source d'événement enfant flottante (attachée à 'e').
     * Le gestionnaire par défaut sera appelé avec 666 comme userdata, qui
     * deviendra la valeur de sortie de la boucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
