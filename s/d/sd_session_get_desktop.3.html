DESCRIPTION

sd_session_is_active() peut être utilisée pour déterminer si la session identifiée par l'identifiant de session spécifié est actuellement active (c'est-à-dire actuellement au premier plan et disponible pour l'entrée utilisateur) ou non.

sd_session_is_remote() peut être utilisée pour déterminer si la session identifiée par l'identifiant de session spécifié est une session distante (c'est-à-dire que son hôte distant est connu) ou non.

sd_session_get_state() peut être utilisée pour déterminer l'état de la session identifiée par l'identifiant de session spécifié. Les états suivants sont actuellement connus : "online" (session connectée, mais session non active, c'est-à-dire pas au premier plan), "active" (session connectée et active, c'est-à-dire au premier plan), "closing" (session nominalement déconnectée, mais certains processus lui appartenant sont toujours présents). À l'avenir, des états supplémentaires pourraient être définis, le code client doit être écrit pour être robuste face à des chaînes d'état supplémentaires retournées. Cette fonction est une version plus générique de sd_session_is_active(). La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_uid() peut être utilisée pour déterminer l'identifiant d'utilisateur de l'utilisateur Unix auquel appartient la session identifiée par l'identifiant de session spécifié.

sd_session_get_username() peut être utilisée pour déterminer le nom de l'utilisateur Unix auquel appartient la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_seat() peut être utilisée pour déterminer l'identifiant du siège auquel appartient la session identifiée par l'identifiant de session spécifié. Notez que toutes les sessions ne sont pas attachées à un siège, cet appel échouera (renvoyant -ENODATA) pour elles. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_start_time() peut être utilisée pour déterminer l'heure de début de la session identifiée par l'identifiant de session spécifié. Le usec est en microsecondes depuis l'époque (CLOCK_REALTIME).

sd_session_get_service() peut être utilisée pour déterminer le nom du service (tel que passé lors de la configuration de la session PAM) qui a enregistré la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_type() peut être utilisée pour déterminer le type de la session identifiée par l'identifiant de session spécifié. La chaîne retournée est l'une des suivantes : "x11", "wayland", "tty", "mir" ou "unspecified" et doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_class() peut être utilisée pour déterminer la classe de la session identifiée par l'identifiant de session spécifié. La chaîne retournée est l'une des suivantes : "user", "user-early", "user-light", "user-early-light", "user-incomplete", "greeter", "lock-screen", "background", "background-light", "manager" ou "manager-early" et doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_desktop() peut être utilisée pour déterminer la marque du bureau exécuté dans la session identifiée par l'identifiant de session spécifié. Ce champ peut être défini librement par les environnements de bureau et ne suit aucune formatation spéciale. Cependant, il est fortement recommandé aux environnements de bureau d'utiliser les mêmes identifiants et la même capitalisation que pour $XDG_CURRENT_DESKTOP, tels que définis par la Spécification des entrées de bureau[1]. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_display() peut être utilisée pour déterminer l'affichage X11 de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_leader() peut être utilisée pour déterminer le PID du leader de la session identifiée par l'identifiant de session spécifié.

sd_session_get_remote_host() peut être utilisée pour déterminer le nom d'hôte distant de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_remote_user() peut être utilisée pour déterminer le nom d'utilisateur distant de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation. Notez que cette valeur est rarement connue du système, et même alors, il ne faut pas s'y fier.

sd_session_get_tty() peut être utilisée pour déterminer le périphérique TTY de la session identifiée par l'identifiant de session spécifié. La chaîne retournée doit être libérée avec l'appel libc free(3) après utilisation.

sd_session_get_vt() peut être utilisée pour déterminer le numéro de VT de la session identifiée par l'identifiant de session spécifié. Cette fonction renverra une erreur si le siège ne prend pas en charge les VT.

Si le paramètre session de l'une de ces fonctions est passé comme NULL, l'opération est exécutée pour la session dont le processus appelant est membre, s'il y en a une.

DESCRIPTION

Ces fonctions sont utilisées pour interroger des informations sur les sessions utilisateur gérées par systemd-logind.

Chaque session est identifiée par un ID de session sous la forme d'une chaîne de caractères (par exemple, « c1 », « 1 », « user@pts/0 »). La fonction sd_pid_get_session(3) peut être utilisée pour trouver l'ID de session d'un processus donné.

sd_session_get_state() renvoie l'état actuel de la session sous la forme d'une chaîne de caractères. Les états possibles sont : "active", "inactive", "starting", et "stopping".

sd_session_get_display() renvoie le nom de l'écran X11 (par exemple, « :0 ») ou Wayland associé à la session, s'il y en a un.

sd_session_get_leader() renvoie l'ID du processus leader de la session (PID 1 dans le contexte de la session).

sd_session_get_remote_user() renvoie le nom d'utilisateur de la machine distante si la session est établie à distance via SSH ou d'autres protocoles.

sd_session_get_remote_host() renvoie le nom d'hôte de la machine distante si la session est établie à distance.

sd_session_get_tty() renvoie le nom du périphérique TTY associé à la session (par exemple, « /dev/tty1 » ou « /dev/pts/0 »).

sd_session_get_vt() renvoie le numéro de la console virtuelle (VT) associée à la session, s'il y en a une.

sd_session_is_remote() renvoie une valeur entière positive si la session est établie à distance, et zéro sinon.

sd_session_get_username() renvoie le nom d'utilisateur effectif de la session.

sd_session_get_desktop() renvoie le nom de l'environnement de bureau, s'il est connu (voir la référence 1).

sd_session_get_start_time() renvoie le moment où la session a démarré, en microsecondes depuis l'époque POSIX. Cela utilise la résolution de temps d'horloge CLOCK_MONOTONIC.

Toutes ces fonctions renvoient 0 en cas de succès. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

RETURN VALUE

Les fonctions retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENXIO

La session spécifiée n'existe pas.

-ENODATA

Le champ donné n'est pas spécifié pour la session décrite.

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, lorsque cela n'est pas accepté).

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
