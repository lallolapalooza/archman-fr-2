SD_BUS_MESSAGE_APPEND(3) sd_bus_message_append SD_BUS_MESSAGE_APPEND(3)

NOM

sd_bus_message_append, sd_bus_message_appendv - Attacher des champs à un message D-Bus basé sur une chaîne de types

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_append(sd_bus_message *m, const char *types, ...);

int sd_bus_message_appendv(sd_bus_message *m, const char *types, va_list ap);

DESCRIPTION

La fonction sd_bus_message_append() attache une séquence de champs à l'objet de message D-Bus m. La chaîne de types types décrit les types des arguments de champ qui suivent. Pour chaque type spécifié dans la chaîne de types, un ou plusieurs arguments doivent être spécifiés, dans le même ordre que celui déclaré dans la chaîne de types.

La chaîne de types est composée des éléments montrés dans le tableau ci-dessous. Elle contient zéro ou plusieurs "types complets" uniques. Chaque type complet peut être l'un des types de base ou un type conteneur entièrement décrit. Un type conteneur peut être une structure avec les types contenus, une variante, un tableau avec son type d'élément, ou une entrée de dictionnaire avec les types contenus. La chaîne de types est terminée par NUL.

En cas de type de base, un argument du type correspondant est attendu.

Une structure est désignée par une séquence de types complets entre parenthèses "(" et ")". Cette séquence ne peut pas être vide — elle doit contenir au moins un type. Les arguments correspondant à cette séquence imbriquée suivent les mêmes règles que s'ils n'étaient pas imbriqués.

Une variante est désignée par "v". Les arguments correspondants doivent commencer par une chaîne de types désignant un type complet, et après cela, les arguments correspondant au type spécifié.

Un tableau est désigné par "a" suivi d'un type complet. Les arguments correspondants doivent commencer par le nombre d'entrées dans le tableau, suivi des entrées elles-mêmes, correspondant au type d'élément du tableau.

Un dictionnaire est un tableau d'entrées de dictionnaire, désigné par "a" suivi d'une paire de types complets entre "{" et "}". Le premier de ces types doit être un type de base. Les arguments correspondants doivent commencer par le nombre d'entrées du dictionnaire, suivi d'une paire de valeurs pour chaque entrée correspondant au type d'élément des entrées du dictionnaire.

sd_bus_message_appendv() est équivalent à sd_bus_message_append(), à la différence près qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments. Cette fonction n'appelle pas la macro va_end(). Étant donné qu'elle invoque la macro va_arg(), la valeur de ap est indéfinie après l'appel.

Pour plus de détails sur le système de types D-Bus, veuillez consulter la Spécification D-Bus[1].

Tableau 1. Spécificateurs de type d'élément

Spécificateur Constante Description Taille Type C attendu
"y" SD_BUS_TYPE_BYTE entier non signé 1 octet uint8_t
"b" SD_BUS_TYPE_BOOLEAN booléen 4 octets int
"n" SD_BUS_TYPE_INT16 entier signé 2 octets int16_t
"q" SD_BUS_TYPE_UINT16 entier non signé 2 octets uint16_t
"i" SD_BUS_TYPE_INT32 entier signé 4 octets int32_t
"u" SD_BUS_TYPE_UINT32 entier non signé 4 octets uint32_t
"x" SD_BUS_TYPE_INT64 entier signé 8 octets int64_t
"t" SD_BUS_TYPE_UINT64 entier non signé 8 octets uint64_t
"d" SD_BUS_TYPE_DOUBLE virgule flottante 8 octets double
"s" SD_BUS_TYPE_STRING chaîne Unicode variable char[]
"o" SD_BUS_TYPE_OBJECT_PATH chemin d'objet variable char[]
"g" SD_BUS_TYPE_SIGNATURE signature variable char[]
"h" SD_BUS_TYPE_UNIX_FD descripteur de fichier UNIX 4 octets int
"a" SD_BUS_TYPE_ARRAY tableau déterminé par le type de tableau et la taille int, suivi du contenu du tableau
"v" SD_BUS_TYPE_VARIANT variante déterminé par l'argument de type chaîne de signature, suivie du contenu de la variante
"(" SD_BUS_TYPE_STRUCT_BEGIN début de tableau déterminé par les types imbriqués contenu de la structure
")" SD_BUS_TYPE_STRUCT_END fin de tableau
"{" SD_BUS_TYPE_DICT_ENTRY_BEGIN début d'entrée de dictionnaire déterminé par les types imbriqués contenu du dictionnaire
"}" SD_BUS_TYPE_DICT_ENTRY_END fin d'entrée de dictionnaire

Pour les types "s" et "g" (chaîne unicode ou signature), le pointeur peut être NULL, ce qui équivaut à une chaîne vide. Pour "h" (descripteur de fichier UNIX), le descripteur est dupliqué par cet appel et le descripteur passé reste en possession de l'appelant. Voir sd_bus_message_append_basic(3) pour l'interprétation précise de ces types et d'autres.

GRAMMAIRE DES CHAÎNES DE TYPES

types ::= complete_type*
complete_type ::= basic_type | variant | structure | array | dictionary
basic_type ::= "y" | "n" | "q" | "u" | "i" | "x" | "t" | "d" |
               "b" | "h" |
               "s" | "o" | "g"
variant ::= "v"
structure ::= "(" complete_type+ ")"
array ::= "a" complete_type
dictionary ::= "a" "{" basic_type complete_type "}"

EXEMPLES

Attacher un seul type de base (la chaîne "une chaîne") :

sd_bus_message *m;
...
sd_bus_message_append(m, "s", "une chaîne");

Attacher tous les types d'entiers :

uint8_t y = 1;
int16_t n = 2;
uint16_t q = 3;
int32_t i = 4;
uint32_t u = 5;
int32_t x = 6;
uint32_t t = 7;
double d = 8.0;
sd_bus_message_append(m, "ynqiuxtd", y, n, q, i, u, x, t, d);

Attacher une structure composée d'une chaîne et d'un chemin D-Bus :

sd_bus_message_append(m, "(so)", "une chaîne", "/un/chemin");

Attacher un tableau de descripteurs de fichiers UNIX :

sd_bus_message_append(m, "ah", 3, STDIN_FILENO, STDOUT_FILENO, STDERR_FILENO);

Attacher une variante, avec le type réel "g" (signature), et la valeur "sdbusisgood" :

sd_bus_message_append(m, "v", "g", "sdbusisgood");

Attacher un dictionnaire contenant le mappage {1=>"a", 2=>"b", 3=>""} :

sd_bus_message_append(m, "a{is}", 3, 1, "a", 2, "b", 3, NULL);

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier positif ou nul. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

ERREURS

Les erreurs possibles retournées par ces fonctions sont, entre autres :

-EINVAL
La chaîne de types est invalide ou contient des types non reconnus.
-EFAULT
Un argument de pointeur est invalide.
-ENOMEM
Mémoire insuffisante pour allouer les données du message.
-EBADMSG
La chaîne de types spécifie une structure ou un dictionnaire vide.
-ENOSPC
Le message est trop grand.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme où aucun autre thread n'a été démarré.
