DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples en texte brut au journal système. Le premier argument est une valeur de priorité. Ceci est suivi par une chaîne de format et ses paramètres, similaire à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour plus de détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale système et au format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits en utilisant cette fonction ne sont généralement pas censés se terminer par un caractère de nouvelle ligne. Cependant, comme tous les espaces blancs de fin (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne enregistrée, il est acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après la suppression des espaces blancs de fin) sont supprimées. Sur les lignes non vides, les espaces blancs en début de ligne (ainsi que les espaces blancs internes) sont laissés inchangés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variable encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Elle est par ailleurs équivalente en comportement.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune suivie immédiatement de leurs paramètres associés, terminées par NULL. Les chaînes passées doivent être du format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et consister uniquement de caractères, de chiffres et de underscores, et ne peut pas commencer par un underscore. (Toutes les affectations qui ne respectent pas cette syntaxe seront ignorées.) La valeur peut être de toute taille et de tout format. Il est fortement recommandé de soumettre uniquement des chaînes de texte formatées dans le codage de caractères UTF-8, et de soumettre des champs binaires uniquement lorsqu'il n'est pas judicieux de formater en chaînes UTF-8. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs supplémentaires définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plusieurs valeurs par entrée. Si cette fonction est utilisée, les espaces blancs de fin sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit référencer un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprime pas les espaces blancs de fin des champs passés, mais transmet les données spécifiées sans modification. Ceci est différent de sd_journal_print() et sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs de fin.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suffixée par ": " et une représentation lisible par l'homme du code d'erreur actuel stocké dans errno(3). Si la chaîne de message est passée comme NULL ou chaîne vide, seule la représentation de la chaîne d'erreur sera écrite, sans préfixe. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté sous forme de chaîne décimale. La priorité de journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour le rendre plus facile à utiliser lorsque seules des chaînes de texte doivent être soumises. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Bonjour le monde, c'est le PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Bonjour le monde, c'est le PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont appelés. Ceci est implémenté avec des macros. Si ce n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() sont similaires à leurs homologues sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "fichier" et "ligne" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "fonction" doit uniquement contenir le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture de wrappers personnalisés, par exemple dans des bindings pour une autre langue.

syslog(3) et sd_journal_print() peuvent être largement utilisés de manière interchangeable en termes de fonctionnalité. Cependant, notez que les messages de journal enregistrés via le premier empruntent un chemin différent vers le serveur de journal que ce dernier, et par conséquent, un ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage d'enregistrer la ligne du code source, les noms de fichiers et les fonctions comme métadonnées avec toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client pour le **Protocole Natif du Journal**[1].

sd_journal_print(3)

NAME

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Send messages to the journal

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_print(int priority, const char *fmt, ...);

int sd_journal_printv(int priority, const char *fmt, va_list ap);

int sd_journal_send(const char *fmt, ...);

int sd_journal_sendv(const char *fmt, va_list ap);

int sd_journal_perror(const char *fmt, ...);

int sd_journal_print_with_location(int priority, const char *file, const char *line, const char *func, const char *fmt, ...);

int sd_journal_printv_with_location(int priority, const char *file, const char *line, const char *func, const char *fmt, va_list ap);

int sd_journal_send_with_location(const char *file, const char *line, const char *func, const char *fmt, ...);

int sd_journal_sendv_with_location(const char *file, const char *line, const char *func, const char *fmt, va_list ap);

int sd_journal_perror_with_location(const char *file, const char *line, const char *func, const char *fmt, ...);

DESCRIPTION

These functions may be used to send messages to the systemd journal. The primary mechanism for sending messages is the native journal protocol, which is understood by systemd-journald(8). This protocol is a simple line-based protocol where each line is a key=value pair.

sd_journal_print(), sd_journal_printv(), sd_journal_print_with_location(), and sd_journal_printv_with_location() are used to log messages with an explicit priority. The priority should be one of the standard syslog priorities (see syslog(3)). The message is formatted according to printf(3). If the systemd-journald(8) daemon is not running, these functions do nothing and return 0.

sd_journal_send(), sd_journal_sendv(), sd_journal_send_with_location(), and sd_journal_sendv_with_location() are used to send structured log messages. The arguments are key=value pairs. The last argument must be NULL. These functions are useful for sending structured data to the journal, which can then be queried using tools like journalctl(1).

sd_journal_perror() and sd_journal_perror_with_location() are similar to sd_journal_print() and sd_journal_print_with_location() respectively, but they also append the current value of errno(3) and its corresponding string representation to the log message. This is useful for logging errors reported by system calls.

The functions suffixed with "_with_location" accept the source code file name, line number, and function name as additional arguments. These are stored in the journal fields _SYSTEMD_UNIT_FILE, _SYSTEMD_LINE, and _SYSTEMD_FUNC respectively, and are useful for debugging.

If systemd-journald(8) is not running (the socket is not present), those functions do nothing, and also return 0.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno code.

THREAD SAFETY

All functions listed here are thread-safe and may be called in parallel from multiple threads.

sd_journal_sendv() and sd_journal_sendv_with_location() are "async signal safe" in the meaning of signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), and their counterparts with "_with_location" are not async signal safe.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_journal_perror() was added in version 188.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), and sd_journal_perror_with_location() were added in version 246.
