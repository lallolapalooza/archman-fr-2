DESCRIPTION

sd_device_get_syspath() retourne le chemin sysfs de l'enregistrement d'appareil spécifié, y compris le préfixe /sys. Exemple : /sys/devices/virtual/tty/tty7

sd_device_get_devpath() retourne le chemin sysfs de l'enregistrement d'appareil spécifié, excluant le préfixe /sys. Exemple : /devices/virtual/tty/tty7

sd_device_get_sysname() retourne le nom sysfs de l'enregistrement d'appareil spécifié, c'est-à-dire le dernier composant du chemin sysfs. Exemple : "tty7" pour l'appareil /sys/devices/virtual/tty/tty7

sd_device_get_sysnum() retourne le numéro d'appareil sysfs de l'enregistrement d'appareil spécifié, c'est-à-dire le suffixe numérique du dernier composant du chemin sysfs. Exemple : "7" pour l'appareil /sys/devices/virtual/tty/tty7

sd_device_get_subsystem() retourne le sous-système noyau de l'enregistrement d'appareil spécifié. C'est une chaîne courte qui tient dans un nom de fichier, et donc ne contient pas de barre oblique et ne peut pas être vide. Exemple : "tty", "block" ou "net".

sd_device_get_driver_subsystem() retourne le type de bus connecté des appareils chargés par l'enregistrement d'appareil pilote spécifié. Par exemple, lorsque l'enregistrement d'appareil pilote "iwlwifi" est spécifié, qui est utilisé par les interfaces réseau sans fil connectées au bus PCI, cette fonction retourne "pci". Cette fonction ne réussit que lorsque sd_device_get_subsystem() retourne "drivers". Exemple : "pci", "i2c", ou "hid".

sd_device_get_devtype() retourne le type d'appareil de l'enregistrement d'appareil spécifié, si le sous-système gère plusieurs types d'appareils. Exemple : pour les appareils du sous-système "block", cela peut être "disk" ou "partition"

sd_device_get_devname() retourne le chemin du nœud d'appareil de l'enregistrement d'appareil spécifié si l'appareil a un nœud d'appareil. Exemple : pour /sys/devices/virtual/tty/tty7, la chaîne /dev/tty7 est généralement retournée.

sd_device_get_devnum() retourne le majeur/mineur du nœud d'appareil (c'est-à-dire dev_t) de l'enregistrement d'appareil spécifié si l'appareil a un nœud d'appareil (c'est-à-dire celui retourné par sd_device_get_devname()). Pour les appareils appartenant au sous-système "block", cela fait référence à un nœud de périphérique bloc, dans tous les autres cas à un nœud de périphérique caractère. Exemple : pour l'appareil /sys/devices/virtual/tty/tty7, cela retourne généralement le numéro d'appareil avec majeur/mineur "4:7".

sd_device_get_ifindex() retourne l'index de l'interface réseau de l'enregistrement d'appareil spécifié, si l'appareil encapsule un appareil d'interface réseau, c'est-à-dire appartient au sous-système "net". Exemple : l'interface "lo" a généralement l'index d'interface 1.

sd_device_get_driver() retourne le nom du pilote noyau attaché à l'appareil. Notez que le champ pilote est défini sur les appareils consommés par le pilote, pas sur l'appareil créé par celui-ci. Exemple : un appareil PCI /sys/bus/pci/devices/0000:00:1f.6 peut être attaché à un pilote "e1000e".

sd_device_get_diskseq() retourne le numéro de séquence du disque noyau de l'appareil bloc. Ce numéro augmente de manière monotone chaque fois que le support sous-jacent d'un appareil bloc change sans que le nom de l'appareil change, et est pertinent pour les appareils bloc encapsulant des appareils à supports changeants (par exemple, disquette ou CD-ROM), ou des appareils bloc de type boucle. Uniquement défini pour les appareils bloc, c'est-à-dire ceux du sous-système "block".

sd_device_get_device_id() retourne la courte chaîne qui identifie l'enregistrement d'appareil. Lorsque l'ID d'appareil obtenu par la fonction pour un enregistrement d'appareil spécifié est passé à sd_device_new_from_device_id(), une nouvelle instance du même enregistrement d'appareil sera obtenue. Lorsqu'un appareil bloc ou caractère est spécifié, qui a un nœud d'appareil correspondant, cela retourne "b" ou "c", respectivement, suivi des numéros majeur et mineur du nœud d'appareil séparés par un deux-points. Exemple : "b259:1" ou "c10:121". Lorsqu'un appareil d'interface réseau est spécifié, cela retourne "n" suivi de l'index de l'interface, qui peut être obtenu par sd_device_get_ifindex(). Exemple : "n1". Lorsqu'un appareil dans le sous-système "driver" est spécifié, cela retourne "+drivers:" suivi de son sous-système pilote et de son nom sysfs séparés par un deux-points. Exemple : "+drivers:pci:iwlwifi" pour un enregistrement d'appareil pilote dont le sous-système pilote est "pci" et le nom sysfs est "iwlwifi". Lorsqu'un autre type d'appareil est spécifié, cette fonction retourne "+" suivi de son sous-système et de son nom sysfs séparés par un deux-points. Exemple : "+acpi:ACPI0003:00", "+input:input16", ou "+pci:0000:00:1f.6".

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

Ajouté dans la version 251.

-ENOENT

Le champ demandé n'est pas présent dans l'enregistrement d'appareil.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-threads. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.
