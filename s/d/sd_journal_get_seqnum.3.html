SD_JOURNAL_GET_SEQNUM(3) sd_journal_get_seqnum SD_JOURNAL_GET_SEQNUM(3)

NOM

sd_journal_get_seqnum - Lire le numéro de séquence de l'entrée de journal actuelle

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_get_seqnum(sd_journal *j, uint64_t *ret_seqnum, sd_id128_t *ret_seqnum_id);

DESCRIPTION

sd_journal_get_seqnum() renvoie le numéro de séquence de l'entrée de journal actuelle. Elle prend trois arguments : l'objet de contexte du journal, un pointeur vers un entier non signé de 64 bits pour stocker le numéro de séquence, et un tampon pour renvoyer l'identifiant de séquence de 128 bits.

Lors de l'écriture des entrées de journal sur le disque, chaque instance de systemd-journald les numérottera séquentiellement, en commençant par 1 pour la première entrée écrite après l'initialisation du sous-système. Chaque série de numéros de séquence est associée à un identifiant de séquence de 128 bits qui est initialisé aléatoirement, une seule fois lors de l'initialisation de systemd-journal. Ainsi, bien que plusieurs instances de systemd-journald attribuent les mêmes numéros de séquence à leurs entrées de journal écrites, elles auront des identifiants de séquence distincts. Le numéro de séquence est attribué au moment de l'écriture de l'entrée sur le disque. Si les entrées de journal sont réécrites (par exemple parce que les journaux volatils de /run/log/ sont vidés dans /var/log/ via systemd-journald-flush.service), elles recevront de nouveaux numéros de séquence.

Les numéros de séquence peuvent être utilisés pour ordonner les entrées (les entrées associées au même identifiant de séquence et aux numéros de séquence inférieurs doivent être ordonnées chronologiquement avant celles avec des numéros de séquence plus élevés), et pour détecter les entrées perdues. Notez que les instances du service de journal écrivent généralement dans plusieurs fichiers de journal en parallèle (par exemple, parce que SplitMode= est utilisé), auquel cas chaque fichier de journal ne contiendra qu'un sous-ensemble des numéros de séquence. Pour récupérer le flux complet des entrées de journal, les fichiers doivent être combinés ("entrelacés"), un processus qui repose principalement sur les numéros de séquence. Lorsque les fichiers de journal sont archivés (en raison de limites de taille ou de temps), la série de numéros de séquence continue dans les fichiers de remplacement. Tous les fichiers de journal générés à partir de la même instance de journal porteront le même identifiant de séquence.

Comme les numéros de séquence sont attribués au moment de l'écriture des entrées de journal sur le disque, ils n'existent pas si le stockage est désactivé via SplitMode=.

Les paramètres ret_seqnum et ret_seqnum_id peuvent être spécifiés comme NULL auquel cas les données pertinentes ne sont pas renvoyées (mais l'appel réussira par ailleurs).

Notez que ces fonctions ne fonctionneront pas avant que sd_journal_next(3) (ou un appel associé) ait été appelé au moins une fois, afin de positionner le pointeur de lecture sur une entrée valide.

VALEUR RENVOYÉE

sd_journal_get_seqnum() renvoie 0 en cas de succès ou un code d'erreur négatif de type errno.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un instant donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

HISTORIQUE

sd_journal_get_seqnum() a été ajoutée dans la version 254.
