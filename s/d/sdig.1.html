NOM

sdig - Effectuer une requête DNS et afficher les résultats

SYNTAXE

sdig ADRESSE-IP-OU-URL-DOH PORT NOMQ TYPEQ [OPTION]

DESCRIPTION

sdig envoie une requête DNS à ADRESSE-IP-OU-URL-DOH sur le port PORT et affiche la réponse de manière formatée. Si l'adresse commence par un h, elle est supposée être un point de terminaison DoH, et PORT est ignoré. Si nomq et typeq sont tous deux - et que tcp est utilisé, plusieurs lignes sont lues depuis l'entrée standard, où chaque ligne contient un nomq et un type. Si l'adresse est stdin, un paquet DNS est lu depuis l'entrée standard au lieu du réseau, et PORT est ignoré. Toute l'entrée est littérale et sensible à la casse. Les requêtes nécessitent l'option recurse pour s'attendre à une réponse d'enregistrement de ressources si le serveur cible n'est pas connu comme étant le serveur autoritaire pour cet enregistrement.

OPTIONS

Ces options peuvent être ajoutées à la ligne de commande dans n'importe quel ordre.

classe NUMCLASSE
Envoie la requête dans la classe numérotée (comme 3 pour CHAOS) au lieu de la classe par défaut 1 (pour IN).
dnssec
Définit le bit DO pour demander des informations DNSSEC.
ednssubnet SOUS-RESEAU
Envoie SOUS-RESEAU dans l'option edns-client-subnet. Si cette option n'est pas définie, aucune option edns-client-subnet n'est définie dans la requête.
cacherdetailssoa
N'affiche pas le numéro de série SOA dans la réponse.
cacherttl
Remplace les TTL par [ttl] dans la réponse.
proxy TCP? SRC DST
Encapsule la requête dans le protocole PROXYv2 avec ces paramètres. Le premier paramètre accepte 0 pour UDP et 1 pour TCP. Les deuxième et troisième prennent des adresses IP et des ports.
recurse
Définit le bit RD dans la question.
montrerflags
Affiche les drapeaux NSEC3 dans la réponse (ils sont masqués par défaut).
dumpluaraw
Affiche le contenu des enregistrements sous une forme adaptée à SpoofRawAction de dnsdist.
tcp
Utilise TCP au lieu d'UDP pour envoyer la requête.
dot
Utilise DoT au lieu d'UDP pour envoyer une requête. Implique tcp.
insecure
lors de l'utilisation de DoT, ne valide pas le certificat du serveur.
fastOpen
lors de l'utilisation de TCP ou DoT, active TCP Fast Open.
subjectName nom
lors de l'utilisation de DoT, vérifie que le certificat du serveur est délivré pour nom. Le fournisseur openssl acceptera un nom vide et s'assurera quand même que le certificat est délivré par une autorité de certification de confiance, gnutls ne fera la validation que si un nom est donné. Par défaut, c'est un nom vide. Notez également que les anciennes bibliothèques de fournisseurs peuvent ne pas effectuer de validation du tout.
caStore fichier
lors de l'utilisation de DoT, lit les certificats d'AC de confiance depuis fichier. Par défaut, utilise le magasin de CA fourni par le système.
tlsProvider nom
lors de l'utilisation de DoT, utilise le fournisseur TLS nom. Actuellement supporté (si compilé) : openssl et gnutls. Par défaut, c'est openssl s'il est disponible.
opcode NUMOP
Utilise l'opcode NUMOP au lieu de 0 (Query). Par exemple, sdig 192.0.2.1 53 example.com SOA opcode 4 envoie un NOTIFY.
cookie COOKIE
si COOKIE est -, envoie un cookie client aléatoire. Sinon, envoie le cookie donné, qui doit être une chaîne hexadécimale reçue d'un serveur précédemment.
traceid TraceID
inclut un TraceID et une valeur SpanID vide dans les données EDNS. Si TraceID est -, un TraceID aléatoire est généré ; sinon, c'est une chaîne hexadécimale.

EXEMPLES

Requêtes simples vers des résolveurs locaux
sdig 127.0.0.1 53 example.com AAAA recurse

sdig ::1 53 example.com A recurse

Requête vers un serveur DNS-over-HTTPS demandant dnssec et la récursion
sdig https://dns.example.net/dns-query 443 example.com A dnssec recurse
