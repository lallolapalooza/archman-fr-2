SD_BUS_TRACK_ADD_NAME(3) sd_bus_track_add_name SD_BUS_TRACK_ADD_NAME(3)

NOM

sd_bus_track_add_name, sd_bus_track_add_sender, sd_bus_track_remove_name, sd_bus_track_remove_sender, sd_bus_track_count, sd_bus_track_count_sender, sd_bus_track_count_name, sd_bus_track_contains, sd_bus_track_first, sd_bus_track_next - Ajouter, supprimer et récupérer des pairs de bus suivis dans un objet de suivi de pairs de bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_track_add_name(sd_bus_track* t, const char* name);

int sd_bus_track_add_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_remove_name(sd_bus_track* t, const char* name);

int sd_bus_track_remove_sender(sd_bus_track* t, sd_bus_message* message);

unsigned sd_bus_track_count(sd_bus_track* t);

int sd_bus_track_count_name(sd_bus_track* t, const char* name);

int sd_bus_track_count_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_contains(sd_bus_track* t, const char* name);

const char* sd_bus_track_first(sd_bus_track* t);

const char* sd_bus_track_next(sd_bus_track* t);

DESCRIPTION

sd_bus_track_add_name() ajoute un pair à suivre à un objet de suivi de pairs de bus. Le premier argument doit faire référence à un objet de suivi de pairs de bus créé avec sd_bus_track_new(3), le nom suivant doit faire référence à un nom de pair D-Bus à suivre, sous forme de nom unique ou de nom de service connu. Si le nom n'est pas déjà suivi, il sera ajouté à la liste des noms à suivre. S'il est déjà suivi et que le mode non récursif est activé, aucune opération n'est exécutée par cet appel. Si le mode récursif est activé, un compteur par nom est incrémenté à chaque invocation de cet appel, et sd_bus_track_remove_name() doit être appelé autant de fois que sd_bus_track_add_name() a été invoqué pour arrêter le suivi du nom. Utilisez sd_bus_track_set_recursive(3) pour passer du mode non récursif par défaut au mode récursif, ou inversement. Notez que le nom spécifié est suivi tel quel, les noms connus ne sont pas résolus en noms uniques par cet appel. Notez que plusieurs objets de suivi de pairs de bus peuvent suivre le même nom.

sd_bus_track_remove_name() annule l'effet de sd_bus_track_add_name() et supprime un nom de pair de bus de la liste des pairs à surveiller. Selon que le mode non récursif ou récursif est activé pour l'objet de suivi de pairs de bus, cet appel supprimera le nom entièrement de l'objet de suivi, ou simplement décrémentera le compteur par nom, ne supprimant le nom que lorsque le compteur atteint zéro (voir ci-dessus). Notez qu'un pair de bus se déconnectant du bus supprimera implicitement ses noms entièrement de l'objet de suivi de pairs de bus, indépendamment du compteur par nom actuel.

sd_bus_track_add_sender() et sd_bus_track_remove_sender() sont similaires à sd_bus_track_add_name() et sd_bus_track_remove_name() mais prennent un message de bus comme argument. L'expéditeur de ce message de bus est déterminé et ajouté/supprimé de l'objet de suivi de pairs de bus. Comme les messages proviennent toujours de noms uniques, et jamais de noms connus, cela signifie que cet appel ajoutera effectivement uniquement des noms uniques à l'objet de suivi de pairs de bus.

sd_bus_track_count() renvoie le nombre de noms actuellement suivis par l'objet de suivi de pairs de bus spécifié. Notez que cette fonction renvoie toujours le nombre réel de noms suivis, et donc si sd_bus_track_add_name() a été invoqué plusieurs fois pour le même nom, il n'est compté qu'une seule fois, que le mode récursif soit utilisé ou non.

sd_bus_track_count_name() renvoie le compteur actuel par nom pour le nom spécifié. Si le mode non récursif est utilisé, il renvoie soit 1, soit 0, selon que le nom spécifié a été ajouté ou non à l'objet de suivi. Si le mode récursif a été activé, des valeurs supérieures à 1 peuvent également être renvoyées, si sd_bus_track_add_name() a été appelé plusieurs fois pour le même nom.

sd_bus_track_count_sender() est similaire à sd_bus_track_count_name(), mais prend un objet de message de bus et renvoie le compteur par nom correspondant à l'expéditeur du message.

sd_bus_track_contains() peut être utilisé pour déterminer si le nom spécifié a été ajouté au moins une fois à l'objet de suivi de pairs de bus spécifié.

sd_bus_track_first() et sd_bus_track_next() peuvent être utilisés pour énumérer tous les noms actuellement suivis par l'objet de suivi de pairs de bus passé. sd_bus_track_first() renvoie la première entrée de l'objet et réinitialise un index de lecture interne. Chaque invocation subséquente de sd_bus_track_next() renvoie le nom suivant contenu dans l'objet de bus. Si la fin est atteinte, NULL est retourné. Si aucun nom n'a encore été ajouté à l'objet, sd_bus_track_first() renverra NULL immédiatement. L'ordre dans lequel les noms sont retournés n'est pas défini ; en particulier, le nom considéré comme le premier retourné n'est pas défini. Si le mode récursif est activé et que le même nom a été ajouté plusieurs fois à l'objet de suivi de pairs de bus, il n'est retourné qu'une seule fois par cette énumération. Si de nouveaux noms sont ajoutés ou des noms existants sont supprimés de l'objet de suivi de pairs de bus pendant son énumération, l'énumération se termine lors de la prochaine invocation de sd_bus_track_next() car NULL est retourné.

VALEUR DE RETOUR

En cas de succès, sd_bus_track_add_name() et sd_bus_track_add_sender() retournent 0 si le nom spécifié a déjà été ajouté à l'objet de suivi de pairs de bus auparavant, et une valeur positive s'il ne l'a pas été. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

sd_bus_track_remove_name() et sd_bus_track_remove_sender() retournent une valeur positive si le nom spécifié était précédemment suivi par l'objet de suivi de pairs de bus et qu'il a maintenant été supprimé. En mode non récursif, 0 est retourné si le nom spécifié n'était pas encore suivi. En mode récursif, -EUNATCH est retourné dans ce cas. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

sd_bus_track_count() retourne le nombre de noms actuellement suivis, ou 0 en cas d'échec.

sd_bus_track_count_name() et sd_bus_track_count_sender() retournent le compteur actuel par nom pour le nom spécifié ou l'expéditeur du message spécifié. Zéro est retourné pour les noms qui ne sont pas encore suivis, une valeur positive pour les noms ajoutés au moins une fois. Des valeurs supérieures à 1 ne sont retournées qu'en mode récursif. En cas d'échec, un code d'erreur négatif de type errno est retourné.

sd_bus_track_contains() renvoie le nom passé s'il existe dans l'objet de suivi de pairs de bus. En cas d'échec, et si le nom n'a pas encore été ajouté, NULL est retourné.

sd_bus_track_first() et sd_bus_track_next() retournent le premier/le nom suivant contenu dans l'objet de suivi de pairs de bus, et NULL si la fin de l'énumération est atteinte et en cas d'erreur.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EUNATCH

sd_bus_track_remove_name() ou sd_bus_track_remove_sender() ont été invoqués pour un nom non préalablement ajouté à l'objet de pairs de bus.

-EINVAL

Le paramètre spécifié est invalide.

-ENOMEM

Échec de l'allocation de mémoire.

sd_bus_track_add_name(3) — systemd

NAME

sd_bus_track_add_name, sd_bus_track_add_sender, sd_bus_track_remove_name, sd_bus_track_remove_sender, sd_bus_track_count, sd_bus_track_count_name, sd_bus_track_count_sender, sd_bus_track_contains, sd_bus_track_first, sd_bus_track_next — Manage D-Bus message tracking

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_add_name(sd_bus_track *track, const char *name);
int sd_bus_track_add_sender(sd_bus_track *track, const char *sender);
int sd_bus_track_remove_name(sd_bus_track *track, const char *name);
int sd_bus_track_remove_sender(sd_bus_track *track, const char *sender);
size_t sd_bus_track_count(sd_bus_track *track);
size_t sd_bus_track_count_name(sd_bus_track *track, const char *name);
size_t sd_bus_track_count_sender(sd_bus_track *track, const char *sender);
int sd_bus_track_contains(sd_bus_track *track, sd_bus_message *m);
int sd_bus_track_first(sd_bus_track *track, sd_bus_message **m);
int sd_bus_track_next(sd_bus_track *track, sd_bus_message **m);

DESCRIPTION

These functions are used to manage a sd_bus_track object, which is a collection of sd_bus_message objects. The primary use case for sd_bus_track is to implement message replay. A sd_bus_track object allows you to register interest in specific D-Bus messages, either by their sender name or by their bus name. When a message arrives on the bus that matches one of these criteria, it will be added to the track.

Use sd_bus_track_new(3) to create a new track object.

sd_bus_track_add_name and sd_bus_track_add_sender add entries to the track. sd_bus_track_add_name registers interest in messages sent by the bus name name. sd_bus_track_add_sender registers interest in messages sent by the sender name sender. A sender name is typically the bus name of the sender, but can also be an internal identifier used by the bus daemon itself. For more details, see https://dbus.freedesktop.org/doc/dbus-specification/html/message-bus-access-control.html.

sd_bus_track_remove_name and sd_bus_track_remove_sender remove entries from the track. If the specified name or sender is not currently in the track, these functions have no effect.

sd_bus_track_count returns the total number of messages currently stored in the track. sd_bus_track_count_name returns the number of messages in the track that were sent by the bus name name. sd_bus_track_count_sender returns the number of messages in the track that were sent by the sender name sender.

sd_bus_track_contains checks if the sd_bus_track object contains the given message m. This is useful for determining if a message that has just arrived on the bus should be processed further, or if it's part of a replay.

sd_bus_track_first and sd_bus_track_next are used to iterate through the messages stored in the track. sd_bus_track_first retrieves the first message in the track, and sets up the track for iteration. Subsequent calls to sd_bus_track_next retrieve the next message in the track. The iterated messages are returned as a new reference, which must be unref'd using sd_bus_message_unref(3) when no longer needed. Iteration stops when there are no more messages in the track, at which point sd_bus_track_next will return -ENODATA.

Note that the sd_bus_track object does not own the messages it stores. When a message is added to the track, a new reference to the message is created. When the track is destroyed, or when a message is removed from the track, its reference count is decremented. If the track is destroyed while messages are still being iterated over, the iterator will be invalidated.

It is recommended to use sd_bus_track_add_sender instead of sd_bus_track_add_name, as sender names are more reliably identifiable on the D-Bus.

The sd_bus_track object should be created and destroyed using sd_bus_track_new(3) and sd_bus_track_unref(3) respectively.

When a message is added to the track, it is not copied. The track simply holds a reference to the existing message. This means that if the original message is modified or destroyed, the track will reflect these changes.

The track object should be added to the bus object early in the program's execution, ideally before any other threads have been started. This ensures that all messages are captured from the beginning of the program's lifetime.

RETURN VALUE

sd_bus_track_add_name, sd_bus_track_add_sender, sd_bus_track_remove_name, sd_bus_track_remove_sender return 0 on success, or a negative errno value on failure.

sd_bus_track_count, sd_bus_track_count_name, sd_bus_track_count_sender return the count of messages on success.

sd_bus_track_contains returns non-zero if the track contains the message, and 0 otherwise.

sd_bus_track_first and sd_bus_track_next return 0 on success, and -ENODATA if there are no more messages in the track. On error, they return a negative errno value.

NOTES

These functions are thread-aware. They may be called from any thread, but they should not be called concurrently from multiple threads on the same sd_bus_track object.

The sd_bus_track object should be created and destroyed using sd_bus_track_new(3) and sd_bus_track_unref(3) respectively.

When adding messages to the track, it is recommended to use sd_bus_track_add_sender over sd_bus_track_add_name, as sender names are more reliably identifiable on the D-Bus.

The sd_bus_track object should be added to the bus object early in the program's execution, ideally before any other threads have been started. This ensures that all messages are captured from the beginning of the program's lifetime.
