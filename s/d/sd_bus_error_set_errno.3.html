DESCRIPTION

La structure sd_bus_error contient des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'une erreur. Il doit suivre les règles des noms d'erreur décrites dans la spécification D-Bus, sous-section Noms D-Bus Valides[1]. Un certain nombre d'erreurs standard communes sont décrites dans sd-bus-errors(3), mais des erreurs spécifiques au domaine supplémentaires peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir les deux champs initialisés à NULL, et signifie l'absence d'erreur, c'est-à-dire le succès. Assignez SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque les ressources détenues par la structure sd_bus_error ne sont plus nécessaires, elles doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de nom et de message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur qui ont déjà été définies. Si vous prévoyez de réutiliser une structure d'erreur, libérez d'abord les anciennes données qu'elle contient avec sd_bus_error_free().

sd_bus_error_set() retournera une valeur similaire à errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié nom. Si nom est NULL, on suppose qu'aucune erreur ne s'est produite, et 0 est retourné. Si nom n'est pas nul, une valeur négative est toujours retournée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais nom est toujours converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs équivalents errno bien connus, et les autres en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreur bien connus. Des mappages d'erreurs supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer s'il n'est pas possible d'allouer de mémoire pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera retourné.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et les arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne, et doivent donc rester constants et valides pendant la durée de vie de e. Utilisez cet appel pour éviter les allocations de mémoire lors de la définition des structures d'erreur. Comme cet appel n'alloue pas de mémoire, il n'échouera pas avec une condition de manque de mémoire comme peut le faire sd_bus_error_set(), comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() retournera immédiatement 0 si le paramètre d'erreur spécifié erreur est 0. Sinon, il définira nom à partir d'une valeur de type errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Des noms d'erreurs D-Bus bien connus seront utilisés pour nom si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si l'erreur spécifiée erreur est non nulle, l'appel retourne toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est retourné.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de erreur, prennent une chaîne de format printf(3) et les arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ nom d'une structure d'erreur en une valeur de type errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera retourné.

sd_bus_error_copy() initialisera dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur auparavant. Sinon, il retournera immédiatement. Si les chaînes dans e ont été définies à l'aide de sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire fraîchement initialisé avec NULL ou réinitialisé à l'aide de sd_bus_error_free().

sd_bus_error_copy() retourne généralement 0 ou une valeur négative de type errno basée sur le paramètre d'entrée e: 0 s'il était non défini et un entier négatif s'il était défini à une erreur, de manière similaire à sd_bus_error_set(). Il peut cependant également retourner une erreur générée en interne,

sd_bus_error_move(dst, e);

est similaire à sd_bus_error_copy(), mais déplace la valeur d'erreur de e vers dst. Après cet appel, e contiendra une structure d'erreur non définie, et dst contiendra la valeur d'erreur précédemment détenue par e. Il n'y a aucune copie de chaîne effectuée, et les chaînes internes de e sont déplacées vers dst.

sd_bus_error_is_set() retourne une valeur non nulle si la structure d'erreur e est définie, et zéro dans le cas contraire.

sd_bus_error_has_name() retourne une valeur non nulle si le champ name de la structure d'erreur e correspond à la chaîne nom, et zéro dans le cas contraire. Si e est NULL, ceci retourne toujours zéro.

sd_bus_error_has_names_sentinel() et la macro sd_bus_error_has_names() sont similaires à sd_bus_error_has_name(), mais vérifient si le champ name correspond à l'un des noms passés dans la liste d'arguments variadiques. La liste doit être terminée par un argument NULL. La fonction principale retourne une valeur non nulle si le nom correspond à l'un des arguments, zéro dans le cas contraire. Si e est NULL, ceci retourne toujours zéro.

Voir ci-dessus.

DIAGNOSTICS

Les fonctions peuvent échouer en raison d'un manque de mémoire, et retourneront -ENOMEM dans ce cas. Elles peuvent également retourner d'autres codes d'erreur négatifs similaires à errno pour indiquer d'autres échecs.

Les fonctions qui retournent une valeur de succès (par exemple, les fonctions qui définissent une erreur) retournent généralement une valeur négative (l'opposé d'un code errno) si une erreur s'est produite, et 0 si l'opération a réussi (ou s'il n'y avait aucune erreur à définir). Les fonctions qui retournent une valeur d'erreur (par exemple, celles qui interrogent une erreur) retournent une valeur positive représentant le code errno correspondant, ou 0 si aucune erreur n'est définie.

DESCRIPTION

The sd_bus_error structure is used to pass error information between bus methods and callers. It contains two character arrays, name and message, which hold the error name and a descriptive message, respectively. The name is a unique string identifying the error type, and the message is a human-readable string explaining the error. Some error names are predefined, such as org.freedesktop.DBus.Error.Failed, org.freedesktop.DBus.Error.ServiceUnknown, org.freedesktop.DBus.Error.NoMemory, org.freedesktop.DBus.Error.AccessDenied, and org.freedeskip.DBus.Error.UnknownMethod.

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() set an error in the error structure. They allocate memory for the error name and message, copy the provided strings into it, and return a negative errno-like value. sd_bus_error_setf() and sd_bus_error_setfv() support printf-style formatting for the message string. sd_bus_error_set_const() is similar to sd_bus_error_set(), but does not allocate new memory for the error strings. Instead, it takes ownership of the passed pointers, which must remain valid for the lifetime of the error structure.

The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof(), and sd_bus_error_set_errnofv() are similar to the above, but they take an integer error number (e.g., from errno) as input. They map this error number to a D-Bus error name and set the message accordingly. If the error number is 0, the error structure is considered unset.

sd_bus_error_get_errno() converts the D-Bus error name stored in the error structure back into an errno-style integer value. If no error is set, or if the name cannot be mapped, it returns 0.

sd_bus_error_copy() copies an error from the src structure to the dst structure. If src contains an error, memory is allocated for dst, and the error information is duplicated. If src is not set, dst is initialized to an unset state (SD_BUS_ERROR_NULL). This function may fail if memory allocation fails, returning -ENOMEM if a memory allocation fails.

sd_bus_error_move() is similar to sd_bus_error_copy(), but will move any error information from e into dst, resetting the former. This function cannot fail, as no new memory is allocated. Note that if e is not set, dst is initialized to SD_BUS_ERROR_NULL. Moreover, if dst is NULL no operation is executed on it and resources held by e are freed and reset. Returns a converted errno-like, non-positive error value.

sd_bus_error_is_set() will return a non-zero value if e is non-NULL and an error has been set, false otherwise.

sd_bus_error_has_name() will return a non-zero value if e is non-NULL and an error with the same name has been set, false otherwise.

sd_bus_error_has_names_sentinel() is similar to sd_bus_error_has_name(), but takes multiple names to check against. The list must be terminated with NULL. sd_bus_error_has_names() is a macro wrapper around sd_bus_error_has_names_sentinel() that adds the NULL sentinel automatically.

sd_bus_error_free() will destroy resources held by e. The parameter itself will not be deallocated, and must be free(3)d by the caller if necessary. The function may also be called safely on unset errors (error structures with both fields set to NULL), in which case it performs no operation. This call will reset the error structure after freeing the data, so that all fields are set to NULL. The structure may be reused afterwards.

REFERENCE OWNERSHIP

sd_bus_error is not reference-counted. Users should destroy resources held by it by calling sd_bus_error_free(). Usually, error structures are allocated on the stack or passed in as function parameters, but they may also be allocated dynamically, in which case it is the duty of the caller to free(3) the memory held by the structure itself after freeing its contents with sd_bus_error_free().

RETURN VALUE

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() always return 0 when the specified error value is NULL, and a negative errno-like value corresponding to the name parameter otherwise. The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof() and sd_bus_error_set_errnofv(), return 0 when the specified error value is 0, and a negative errno-like value corresponding to the error parameter otherwise. If an error occurs internally, one of the negative error values listed below will be returned. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_get_errno() returns false when e is NULL, and a positive errno value mapped from e->name otherwise.

sd_bus_error_copy() and sd_bus_error_move() return a negative error value converted from the source error, and zero if the error has not been set. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_is_set() returns a non-zero value when e and the name field are non-NULL, zero otherwise.

sd_bus_error_has_name(), sd_bus_error_has_names(), and sd_bus_error_has_names_sentinel() return a non-zero value when e is non-NULL and the name field is equal to one of the given names, zero otherwise.

Errors

Return value may indicate the following problems in the invocation of the function itself:

-EINVAL

Error was already set in the sd_bus_error structure when one the error-setting functions was called.

-ENOMEM

Memory allocation failed.

On success, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), and sd_bus_error_move() will return a negative converted errno-style value, or 0 if the error parameter is NULL or unset. D-Bus errors are converted to the integral errno-style value, and the mapping mechanism is extensible, see the discussion above. This effectively means that almost any negative errno-style value can be returned.

EXAMPLES

Example 1. Using the negative return value to propagate an error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* On success, return the number of bytes written, possibly 0. */
  /* On error, initialize the error structure, and also propagate the errno
   * value that write(2) set for us. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
