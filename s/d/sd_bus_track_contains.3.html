SD_BUS_TRACK_ADD_NAME(3) sd_bus_track_add_name SD_BUS_TRACK_ADD_NAME(3)

NOM

sd_bus_track_add_name, sd_bus_track_add_sender, sd_bus_track_remove_name, sd_bus_track_remove_sender, sd_bus_track_count, sd_bus_track_count_sender, sd_bus_track_count_name, sd_bus_track_contains, sd_bus_track_first, sd_bus_track_next - Ajouter, supprimer et récupérer des pairs de bus suivis dans un objet de suivi de pairs de bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_add_name(sd_bus_track* t, const char* name);

int sd_bus_track_add_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_remove_name(sd_bus_track* t, const char* name);

int sd_bus_track_remove_sender(sd_bus_track* t, sd_bus_message* message);

unsigned sd_bus_track_count(sd_bus_track* t);

int sd_bus_track_count_name(sd_bus_track* t, const char* name);

int sd_bus_track_count_sender(sd_bus_track* t, sd_bus_message* message);

int sd_bus_track_contains(sd_bus_track* t, const char* name);

const char* sd_bus_track_first(sd_bus_track* t);

const char* sd_bus_track_next(sd_bus_track* t);

DESCRIPTION

sd_bus_track_add_name() ajoute une paire à suivre à un objet de suivi de paires de bus. Le premier argument doit faire référence à un objet de suivi de paires de bus créé avec sd_bus_track_new(3), le nom second doit faire référence à un nom de paire D-Bus à suivre, que ce soit sous forme unique ou de service bien connu. Si le nom n'est pas déjà suivi, il sera ajouté à la liste des noms à suivre. S'il est déjà suivi et que le mode non récursif est activé, aucune opération n'est exécutée par cet appel. Si le mode récursif est activé, un compteur par nom est incrémenté d'une unité à chaque fois que cet appel est invoqué, et sd_bus_track_remove_name() doit être appelé autant de fois que sd_bus_track_add_name() a été invoqué avant pour arrêter le suivi du nom. Utilisez sd_bus_track_set_recursive(3) pour passer du mode par défaut non récursif au mode récursif, ou inversement. Notez que le nom spécifié est suivi tel quel, les noms bien connus ne sont pas résolus en noms uniques par cet appel. Notez que plusieurs objets de suivi de paires de bus peuvent suivre le même nom.

sd_bus_track_remove_name() annule l'effet de sd_bus_track_add_name() et supprime un nom de paire de bus de la liste des paires à surveiller. Selon que le mode non récursif ou récursif est activé pour l'objet de suivi de paires de bus, cet appel supprimera le nom entièrement de l'objet de suivi, ou simplement décrémentera le compteur par nom d'une unité, ne supprimant le nom que lorsque le compteur atteint zéro (voir ci-dessus). Notez qu'une paire de bus se déconnectant du bus supprimera implicitement ses noms entièrement de l'objet de suivi de paires de bus, quel que soit le compteur par nom actuel.

sd_bus_track_add_sender() et sd_bus_track_remove_sender() sont similaires à sd_bus_track_add_name() et sd_bus_track_remove_name() mais prennent un message de bus comme argument. L'expéditeur de ce message de bus est déterminé et ajouté/supprimé de l'objet de suivi de paires de bus. Comme les messages proviennent toujours de noms uniques, et jamais de noms bien connus, cela signifie que cet appel ajoutera effectivement uniquement des noms uniques à l'objet de suivi de paires de bus.

sd_bus_track_count() retourne le nombre de noms actuellement suivis par l'objet de suivi de paires de bus spécifié. Notez que cette fonction retourne toujours le nombre réel de noms suivis, et donc si sd_bus_track_add_name() a été invoqué plusieurs fois pour le même nom, il n'est compté qu'une seule fois, que le mode récursif soit utilisé ou non.

sd_bus_track_count_name() retourne le compteur par nom actuel pour le nom spécifié. Si le mode non récursif est utilisé, cela retourne soit 1 soit 0, selon que le nom spécifié a été ajouté ou non auparavant à l'objet de suivi. Si le mode récursif a été activé, des valeurs supérieures à 1 peuvent également être retournées, si sd_bus_track_add_name() a été appelé plusieurs fois pour le même nom.

sd_bus_track_count_sender() est similaire à sd_bus_track_count_name(), mais prend un objet de message de bus et retourne le compteur par nom correspondant à l'expéditeur du message.

sd_bus_track_contains() peut être utilisé pour déterminer si le nom spécifié a été ajouté au moins une fois à l'objet de suivi de paires de bus spécifié.

sd_bus_track_first() et sd_bus_track_next() peuvent être utilisés pour énumérer tous les noms actuellement suivis par l'objet de suivi de paires de bus passé. sd_bus_track_first() retourne la première entrée de l'objet et réinitialise un index de lecture interne. Chaque invocation subsquente de sd_bus_track_next() retourne le nom suivant contenu dans l'objet de bus. Si la fin est atteinte, NULL est retourné. Si aucun nom n'a encore été ajouté à l'objet, sd_bus_track_first() retournera NULL immédiatement. L'ordre dans lequel les noms sont retournés n'est pas défini ; en particulier, le nom considéré comme le premier retourné n'est pas défini. Si le mode récursif est activé et que le même nom a été ajouté plusieurs fois à l'objet de suivi de paires de bus, il n'est retourné qu'une seule fois par cette énumération. Si de nouveaux noms sont ajoutés ou si des noms existants sont supprimés de l'objet de suivi de paires de bus pendant son énumération, l'énumération se termine lors de la prochaine invocation de sd_bus_track_next() car NULL est retourné.

VALEUR DE RETOUR

En cas de succès, sd_bus_track_add_name() et sd_bus_track_add_sender() retournent 0 si le nom spécifié a déjà été ajouté auparavant à l'objet de suivi de paires de bus et une valeur positive s'il ne l'a pas été. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

sd_bus_track_remove_name() et sd_bus_track_remove_sender() retournent une valeur positive si le nom spécifié était précédemment suivi par l'objet de suivi de paires de bus et a maintenant été supprimé. En mode non récursif, 0 est retourné si le nom spécifié n'était pas encore suivi. En mode récursif, -EUNATCH est retourné dans ce cas. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

sd_bus_track_count() retourne le nombre de noms actuellement suivis, ou 0 en cas d'échec.

sd_bus_track_count_name() et sd_bus_track_count_sender() retournent le compteur par nom actuel pour le nom spécifié ou l'expéditeur du message spécifié. Zéro est retourné pour les noms qui ne sont pas encore suivis, une valeur positive pour les noms ajoutés au moins une fois. Des valeurs supérieures à 1 ne sont retournées qu'en mode récursif. En cas d'échec, un code d'erreur négatif de style errno est retourné.

sd_bus_track_contains() retourne le nom passé s'il existe dans l'objet de suivi de paires de bus. En cas d'échec, et si le nom n'a pas encore été ajouté, NULL est retourné.

sd_bus_track_first() et sd_bus_track_next() retournent le premier/prochain nom contenu dans l'objet de suivi de paires de bus, et NULL si la fin de l'énumération est atteinte et en cas d'erreur.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EUNATCH

sd_bus_track_remove_name() ou sd_bus_track_remove_sender() ont été invoqués pour un nom non ajouté auparavant à l'objet de paires de bus.

-EINVAL

Le paramètre spécifié est invalide.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que à partir du thread principal.

sd_bus_track_contains(3)

NAME

sd_bus_track_contains, sd_bus_track_first, sd_bus_track_next — check if an object is registered, iterate over registered objects

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_contains(sd_bus_track *track, const char *name, sd_bus_slot **slot, sd_bus_message **reply);

sd_bus_slot * sd_bus_track_first(sd_bus_track *track);

sd_bus_slot * sd_bus_track_next(sd_bus_slot *slot);

DESCRIPTION

These functions work with sd_bus_track objects, which are used to keep track of bus names that are currently registered and exported by the local service. They allow an efficient way to check if a specific bus name is registered, or to iterate over all registered bus names.

sd_bus_track_contains() checks if the bus name specified by name is currently registered. If slot is non-NULL, it will be set to point to the D-Bus slot object associated with the registration, if found. If reply is non-NULL, it will be set to point to the reply message received from the bus daemon when the name was registered. This might be useful for retrieving information about the registration, like the process ID of the owner.

sd_bus_track_first() returns the first registered bus name slot in the track. The returned pointer should be passed to sd_bus_track_next() to iterate through the remaining registered names.

sd_bus_track_next() returns the next registered bus name slot in the track. If there are no more slots, it returns NULL.

The returned sd_bus_slot and sd_bus_message objects are owned by the sd_bus_track object. They should not be modified or freed directly. They are automatically cleaned up when the track is destroyed using sd_bus_track_unref().

RETURN VALUE

sd_bus_track_contains() returns a positive integer if the name is registered, zero if it is not, and a negative errno value on error.

sd_bus_track_first() and sd_bus_track_next() return a pointer to the sd_bus_slot object, or NULL if no more slots are available or an error occurred.

NOTES

These functions are intended to be used with a bus track object created with sd_bus_track_new().

The tracking of bus names is done by listening to the org.freedesktop.DBus.NameOwnerChanged signal. This signal is emitted whenever a bus name is acquired or lost. The track object automatically subscribes to this signal when it is created.

It is important to note that the information provided by these functions is only guaranteed to be accurate at the moment they are called. The state of bus name registrations can change at any time due to other clients acquiring or releasing names.

It is recommended to initialize the track object as early as possible in the program's execution, ideally during the early phase of the program when no other threads have been started.
