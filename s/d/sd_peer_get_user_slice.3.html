DESCRIPTION

sd_pid_get_owner_uid() peut être utilisé pour déterminer l'UID Unix (identifiant utilisateur) qui possède la session de connexion ou l'unité utilisateur systemd d'un processus identifié par le PID spécifié. Pour les processus qui ne font pas partie d'une session de connexion et ne sont pas gérés par un gestionnaire d'utilisateurs, cette fonction échouera avec -ENODATA.

sd_pid_get_session() peut être utilisé pour déterminer l'identifiant de session de connexion d'un processus identifié par l'identifiant de processus spécifié. L'identifiant de session est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Veuillez noter que la session de connexion peut être limitée à un processus squelette ou deux. Les processus utilisateurs peuvent plutôt être démarrés à partir de leur gestionnaire d'utilisateurs systemd, par exemple des applications graphiques démarrées à l'aide de l'activation DBus, ainsi que des processus de service partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session de connexion, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_user_unit() peut être utilisé pour déterminer l'identifiant de l'unité utilisateur systemd (c'est-à-dire une unité de service ou de scope utilisateur) d'un processus identifié par le PID spécifié. Le nom de l'unité est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Pour les processus qui ne sont pas gérés par un gestionnaire d'utilisateurs, cette fonction échouera avec -ENODATA. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_unit() peut être utilisé pour déterminer l'identifiant de l'unité système systemd (c'est-à-dire une unité de service ou de scope système) d'un processus identifié par le PID spécifié. Le nom de l'unité est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. Notez que tous les processus ne font pas partie d'une unité/service système. Pour les processus qui ne font pas partie d'une unité système systemd, cette fonction échouera avec -ENODATA. (Plus précisément, cet appel ne fonctionnera pas pour les threads du noyau.) La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

sd_pid_get_machine_name() peut être utilisé pour déterminer le nom de la VM ou du conteneur dont un processus est membre. Le nom de la machine est une chaîne courte, adaptée à une utilisation dans les chemins de système de fichiers. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation. Pour les processus qui ne font pas partie d'une VM ou d'un conteneur, cette fonction échoue avec -ENODATA.

sd_pid_get_slice() peut être utilisé pour déterminer la tranche (slice) à laquelle le processus appartient. Voir systemd.slice(5) pour plus de détails sur les tranches. La chaîne retournée doit être libérée avec l'appel free(3) de la libc après utilisation.

De même, sd_pid_get_user_slice() renvoie la tranche utilisateur (gérée par l'instance systemd de l'utilisateur) d'un processus.

sd_pid_get_cgroup() renvoie le chemin du groupe de contrôle du processus spécifié, relatif à la racine de la hiérarchie. Renvoie le chemin sans barre oblique finale, sauf pour les processus situés dans le groupe de contrôle racine, où "/" est renvoyé. Pour trouver le chemin réel du groupe de contrôle dans le système de fichiers, le chemin retourné doit être précédé de /sys/fs/cgroup/.

Si le paramètre pid de l'une de ces fonctions est passé comme 0, l'opération est exécutée pour le processus appelant.

Les appels sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() et sd_pidfd_get_cgroup() fonctionnent de manière similaire à leurs homologues PID, mais acceptent un PIDFD au lieu d'un PID, ce qui signifie qu'ils ne sont pas sujets aux conditions de concurrence de recyclage car le processus est épinglé par le descripteur de fichier pendant toute la durée de l'invocation. Notez que ceux-ci nécessitent un noyau prenant en charge PIDFD. Un descripteur de fichier approprié peut être obtenu via pidfd_open(2).

Les appels sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() et sd_peer_get_cgroup() fonctionnent de manière similaire à leurs homologues PID, mais acceptent un socket AF_UNIX connecté et récupèrent les informations sur le processus pair connecté. Notez que ces champs sont récupérés via /proc/, et ne conviennent donc pas à des fins d'autorisation, car ils sont sujets aux conditions de concurrence.

VALEUR RENVOYÉE

En cas de succès, ces appels renvoient 0 ou un entier positif. En cas d'échec, ces appels renvoient un code d'erreur négatif de type errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ESRCH

Le PID spécifié ne correspond pas à un processus en cours d'exécution.

-EBADF

Le descripteur de fichier spécifié est invalide.

-ENODATA

Le champ spécifié n'est pas défini pour le processus ou le pair décrit.

-EINVAL

sd_peer_get_user_slice.3.en

NAME

sd_peer_get_user_slice, sd_pid_get_user_slice, sd_pidfd_get_user_slice - Obtenir l'unité slice d'un processus, d'un processus dans un conteneur, ou d'un processus connecté

SYNOPSIS

#include <systemd/sd-login.h>

int sd_peer_get_user_slice(const char *name, const char *type, char **ret_slice);
int sd_pid_get_user_slice(pid_t pid, const char *type, char **ret_slice);
int sd_pidfd_get_user_slice(int pidfd, const char *type, char **ret_slice);

DESCRIPTION

La fonction sd_peer_get_user_slice() récupère l'unité slice pour le processus distant ou le processus du système qui s'est connecté à ce socket via systemd-logind.service(8). Le nom du processus est passé dans le paramètre name et son type est passé dans le paramètre type. Les types pris en charge pour type sont les chaînes de caractères "cgroup", "pid", "pidfd", "path", "user" et "fd". La fonction remplit le paramètre ret_slice avec un pointeur vers une chaîne allouée contenant le nom de l'unité slice, ou NULL si aucune unité slice n'a été trouvée.

La fonction sd_pid_get_user_slice() récupère l'unité slice pour le processus donné par pid. Le paramètre type a la même signification que pour sd_peer_get_user_slice().

La fonction sd_pidfd_get_user_slice() récupère l'unité slice pour le processus donné par le descripteur de fichier pidfd. Le paramètre type a la même signification que pour sd_peer_get_user_slice().

Les unités slice sont des objets de contrôle de ressources dans systemd qui regroupent des processus ayant des caractéristiques communes. Les noms d'unités slice pour les utilisateurs sont généralement de la forme user-<uid>.slice ou user@<uid>.slice.

Si la récupération réussit, la chaîne allouée pour le nom de l'unité slice doit être libérée par l'appelant à l'aide de free(3).

RETURN VALUE

Ces fonctions renvoient 0 en cas de succès, un nombre négatif en cas d'erreur. Les codes d'erreur possibles sont :

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, là où cela n'est pas accepté).

-ENOMEM

L'allocation de mémoire a échoué.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Il est à noter que l'identifiant de session de connexion tel que retourné par sd_pid_get_session() n'est absolument pas lié à l'identifiant de session de processus tel que retourné par getsid(2).
