DESCRIPTION

sd_device_get_syspath() retourne le chemin sysfs de l'enregistrement de périphérique spécifié, y compris le préfixe /sys. Exemple : /sys/devices/virtual/tty/tty7

sd_device_get_devpath() retourne le chemin sysfs de l'enregistrement de périphérique spécifié, sans le préfixe /sys. Exemple : /devices/virtual/tty/tty7

sd_device_get_sysname() retourne le nom sysfs de l'enregistrement de périphérique spécifié, c'est-à-dire le dernier composant du chemin sysfs. Exemple : "tty7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_sysnum() retourne le numéro de périphérique sysfs de l'enregistrement de périphérique spécifié, c'est-à-dire le suffixe numérique du dernier composant du chemin sysfs. Exemple : "7" pour le périphérique /sys/devices/virtual/tty/tty7

sd_device_get_subsystem() retourne le sous-système du noyau de l'enregistrement de périphérique spécifié. Il s'agit d'une chaîne courte qui tient dans un nom de fichier, et donc ne contient pas de slash et ne peut pas être vide. Exemple : "tty", "block" ou "net".

sd_device_get_driver_subsystem() retourne le type de bus connecté de l'enregistrement de périphérique pilote chargé. Par exemple, lorsqu'un enregistrement de périphérique pilote "iwlwifi" est spécifié, qui est utilisé par les interfaces réseau sans fil connectées au bus PCI, cette fonction retourne "pci". Cette fonction ne réussit que lorsque sd_device_get_subsystem() retourne "drivers". Exemple : "pci", "i2c" ou "hid".

sd_device_get_devtype() retourne le type de périphérique de l'enregistrement de périphérique spécifié, si le sous-système gère plusieurs types de périphériques. Exemple : pour les périphériques du sous-système "block", il peut s'agir de "disk" ou "partition"

sd_device_get_devname() retourne le chemin du nœud de périphérique de l'enregistrement de périphérique spécifié si le périphérique a un nœud de périphérique. Exemple : pour /sys/devices/virtual/tty/tty7, la chaîne /dev/tty7 est généralement retournée.

sd_device_get_devnum() retourne le majeur/mineur du nœud de périphérique (c'est-à-dire dev_t) de l'enregistrement de périphérique spécifié si le périphérique a un nœud de périphérique (c'est-à-dire celui retourné par sd_device_get_devname()). Pour les périphériques appartenant au sous-système "block", cela fait référence à un nœud de périphérique bloc, dans tous les autres cas à un nœud de périphérique caractère. Exemple : pour le périphérique /sys/devices/virtual/tty/tty7, cela retourne généralement le numéro de périphérique avec majeur/mineur "4:7".

sd_device_get_ifindex() retourne l'index de l'interface réseau de l'enregistrement de périphérique spécifié, si le périphérique encapsule un périphérique d'interface réseau, c'est-à-dire qu'il appartient au sous-système "net". Exemple : l'interface "lo" a généralement l'index d'interface 1.

sd_device_get_driver() retourne le nom du pilote du noyau attaché au périphérique. Notez que le champ pilote est défini sur les périphériques consommés par le pilote, et non sur le périphérique créé par celui-ci. Exemple : un périphérique PCI /sys/bus/pci/devices/0000:00:1f.6 pourrait être attaché à un pilote "e1000e".

sd_device_get_diskseq() retourne le numéro de séquence du disque du noyau pour le périphérique bloc. Ce numéro augmente de manière monotone chaque fois que le support sous-jacent d'un périphérique bloc change sans que le nom du périphérique ne change, et est pertinent pour les périphériques blocs encapsulant des périphériques à supports changeants (par exemple, lecteurs de disquettes ou CD-ROM), ou les périphériques blocs en boucle. Seulement défini pour les périphériques blocs, c'est-à-dire ceux du sous-système "block".

sd_device_get_device_id() retourne la chaîne courte qui identifie l'enregistrement du périphérique. Lorsque l'identifiant de périphérique obtenu par la fonction pour un enregistrement de périphérique spécifié est passé à sd_device_new_from_device_id(), une nouvelle instance du même enregistrement de périphérique sera obtenue. Lorsqu'un périphérique bloc ou caractère est spécifié, qui a un nœud de périphérique correspondant, cela retourne "b" ou "c", respectivement, suivi des numéros majeur et mineur du nœud de périphérique séparés par un deux-points. Exemple : "b259:1" ou "c10:121". Lorsqu'un périphérique réseau est spécifié, cela retourne "n" suivi de l'index de l'interface, qui peut être obtenu par sd_device_get_ifindex(). Exemple : "n1". Lorsqu'un périphérique dans le sous-système "driver" est spécifié, cela retourne "+drivers:" suivi de son sous-système pilote et de son nom sysfs séparés par un deux-points. Exemple : "+drivers:pci:iwlwifi" pour un enregistrement de périphérique pilote dont le sous-système pilote est "pci" et le nom sysfs est "iwlwifi". Lorsqu'un autre type de périphérique est spécifié, cette fonction retourne "+" suivi de son sous-système et de son nom sysfs séparés par un deux-points. Exemple : "+acpi:ACPI0003:00", "+input:input16", ou "+pci:0000:00:1f.6".

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

Ajouté dans la version 251.

-ENOENT

Le champ demandé n'est pas présent dans l'enregistrement du périphérique.

Ajouté dans la version 251.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
