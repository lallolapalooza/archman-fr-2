SD_EVENT_NEW(3) sd_event_new SD_EVENT_NEW(3)

NOM

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - Acquérir et libérer un objet de boucle d'événements

SYNTAXE

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

DESCRIPTION

sd_event_new() alloue un nouvel objet de boucle d'événements. L'objet de boucle d'événements est retourné dans le paramètre event. Après utilisation, supprimez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est supprimée, l'objet est libéré.

sd_event_default() acquiert une référence vers l'objet de boucle d'événements par défaut du fil d'exécution appelant, allouant éventuellement un nouvel objet si aucun objet de boucle d'événements par défaut n'a encore été alloué pour le fil d'exécution. Après utilisation, supprimez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est supprimée, la boucle d'événements est libérée. Si cette fonction est appelée alors que l'objet retourné par un appel précédent du même fil d'exécution est toujours référencé, le même objet est retourné à nouveau, mais la référence est incrémentée de un. Il est recommandé d'utiliser cet appel au lieu de sd_event_new() afin de partager des objets de boucle d'événements entre différents composants qui sont distribués sur le même fil d'exécution. Tous les fils d'exécution ont exactement soit zéro, soit un objet de boucle d'événements par défaut associé, mais jamais plus.

Après avoir alloué un objet de boucle d'événements, ajoutez-y des sources d'événements avec sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3), sd_event_add_post(3) ou sd_event_add_exit(3), puis exécutez la boucle d'événements en utilisant sd_event_loop(3).

sd_event_ref() incrémente le compteur de références de l'objet de boucle d'événements spécifié de un.

sd_event_unref() décrémente le compteur de références de l'objet de boucle d'événements spécifié de un. Si le compte atteint zéro, l'objet est libéré. Notez qu'il est libéré indépendamment du fait qu'il soit l'objet de boucle d'événements par défaut pour un fil d'exécution ou non. Cela signifie que l'allocation d'une boucle d'événements avec sd_event_default(), puis sa libération, puis l'acquisition d'une nouvelle avec sd_event_default() résultera en deux objets distincts. Notez que, afin de libérer un objet de boucle d'événements, toutes les sources d'événements restantes de la boucle d'événements doivent également être libérées, car chacune conserve une référence à celle-ci.

sd_event_unrefp() est similaire à sd_event_unref() mais prend un pointeur vers un pointeur vers un objet sd_event. Cet appel est utile en conjonction avec l'attribut Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme suit, afin d'allouer un objet de boucle d'événements qui sera libéré automatiquement à la sortie du bloc de code :

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Échec de l'allocation de la boucle d'événements : %m\n");
        }
        ...
}

sd_event_ref(), sd_event_unref() et sd_event_unrefp() n'effectuent aucune opération si l'objet de boucle d'événements passé est NULL.

sd_event_get_tid() récupère l'identifiant du fil d'exécution ("TID") du fil d'exécution auquel l'objet de boucle d'événements spécifié est associé. Cet appel n'est pris en charge que pour les boucles d'événements allouées avec sd_event_default(), et retourne l'identifiant du fil d'exécution dont la boucle d'événements est la boucle par défaut. Voir gettid(2) pour plus d'informations sur les identifiants de fils d'exécution.

VALEUR DE RETOUR

En cas de succès, sd_event_new(), sd_event_default() et sd_event_get_tid() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno. sd_event_ref() retourne toujours un pointeur vers l'objet de boucle d'événements passé. sd_event_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer l'objet.

-EMFILE

Le nombre maximum de boucles d'événements a été alloué.

-ENXIO

sd_event_get_tid() a été appelé sur un objet de boucle d'événements qui n'a pas été alloué avec sd_event_default().

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() que dès le début du programme, lorsqu'aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_event_new(), sd_event_default(), sd_event_ref() et sd_event_unref() ont été ajoutés dans la version 213.

sd_event_unrefp() et sd_event_get_tid() ont été ajoutés dans la version 229.

sd_event_unref(3) — Arch Linux

NAME

sd_event_unref - Libère une référence à un objet sd_event

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_unref(sd_event *event);

DESCRIPTION

La fonction sd_event_unref() décrémente le compteur de références de l'objet event.

Pour chaque appel à sd_event_new() ou sd_event_ref(), un appel à sd_event_unref() est nécessaire pour libérer la mémoire.

Si le compteur de références atteint zéro, l'objet event est détruit et toute la mémoire associée est libérée.

L'appel à sd_event_unref() est sûr même si event est NULL. Dans ce cas, la fonction ne fait rien.

VALEUR DE RETOUR

La fonction sd_event_unref() renvoie toujours 0 en cas de succès. En cas d'échec, une valeur d'erreur négative est renvoyée.

NOTES

L'objet sd_event est un objet d'événement asynchrone qui permet de gérer des événements provenant de diverses sources, telles que les E/S de fichiers, les signaux, les timers et les processus enfants.

Chaque référence à un objet sd_event doit être explicitement libérée par un appel à sd_event_unref().

HISTORIQUE

La fonction sd_event_unref() a été introduite dans systemd version 231.
