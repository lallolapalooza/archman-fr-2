sd_bus_destroy_t(3)

Paquet: systemd-libs

Licences: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_SLOT_SET_DESTROY_CALLBACK(3) sd_bus_slot_set_destroy_callback SD_BUS_SLOT_SET_DESTROY_CALLBACK(3)

NOM

sd_bus_slot_set_destroy_callback, sd_bus_slot_get_destroy_callback, sd_bus_track_set_destroy_callback, sd_bus_track_get_destroy_callback, sd_bus_destroy_t - Définir la fonction de rappel pour le nettoyage des ressources

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_destroy_t)(void *userdata);

int sd_bus_slot_set_destroy_callback(sd_bus_slot *slot, sd_bus_destroy_t callback);

int sd_bus_slot_get_destroy_callback(sd_bus_slot *slot, sd_bus_destroy_t *callback);

int sd_bus_track_set_destroy_callback(sd_bus_track *track, sd_bus_destroy_t callback);

int sd_bus_track_get_destroy_callback(sd_bus_track *track, sd_bus_destroy_t *callback);

DESCRIPTION

sd_bus_slot_set_destroy_callback() définit callback comme fonction de rappel à appeler juste avant que l'objet slot du bus slot ne soit désalloué. Le pointeur userdata de l'objet slot sera passé comme paramètre userdata. Ce pointeur peut être défini par un argument des fonctions constructrices, voir sd_bus_add_match(3), ou directement, voir sd_bus_slot_set_userdata(3). Cette fonction de rappel est appelée même si userdata est NULL. Notez que ce rappel est invoqué à un moment où l'objet slot du bus est déjà invalidé, et l'exécution d'opérations ou la prise de nouvelles références sur l'objet slot du bus ne sont pas permises.

sd_bus_slot_get_destroy_callback() retourne le rappel actuel pour slot dans le paramètre callback.

sd_bus_track_set_destroy_callback() et sd_bus_track_get_destroy_callback() fournissent une fonctionnalité équivalente pour le pointeur userdata associé aux objets de suivi des pairs du bus. Pour plus de détails sur les objets de suivi des pairs du bus, voir sd_bus_track_new(3).

VALEUR DE RETOUR

En cas de succès, sd_bus_slot_set_destroy_callback() et sd_bus_track_set_destroy_callback() retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

sd_bus_slot_get_destroy_callback() et sd_bus_track_get_destroy_callback() retournent une valeur positive si la fonction de rappel de destruction est définie, 0 sinon. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre slot ou track est NULL.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer les appels à setenv() que depuis une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_destroy_t(), sd_bus_slot_set_destroy_callback(), sd_bus_slot_get_destroy_callback(), sd_bus_track_set_destroy_callback(), et sd_bus_track_get_destroy_callback() ont été ajoutées dans la version 239.
