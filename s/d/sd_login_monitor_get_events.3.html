SD_LOGIN_MONITOR_NEW(3) sd_login_monitor_new SD_LOGIN_MONITOR_NEW(3)

NOM

sd_login_monitor_new, sd_login_monitor_unref, sd_login_monitor_unrefp, sd_login_monitor_flush, sd_login_monitor_get_fd, sd_login_monitor_get_events, sd_login_monitor_get_timeout, sd_login_monitor - Surveiller les sessions, sièges, utilisateurs et machines virtuelles/conteneurs

SYNTAXE

#include <systemd/sd-login.h>

int sd_login_monitor_new(const char *category, sd_login_monitor **ret);

sd_login_monitor *sd_login_monitor_unref(sd_login_monitor *m);

void sd_login_monitor_unrefp(sd_login_monitor **m);

int sd_login_monitor_flush(sd_login_monitor *m);

int sd_login_monitor_get_fd(sd_login_monitor *m);

int sd_login_monitor_get_events(sd_login_monitor *m);

int sd_login_monitor_get_timeout(sd_login_monitor *m, uint64_t *timeout_usec);

DESCRIPTION

sd_login_monitor_new() peut être utilisé pour surveiller les sessions, utilisateurs, sièges et machines virtuelles/conteneurs. Via un objet moniteur, un descripteur de fichier peut être intégré dans une boucle d'événements définie par l'application, qui est réveillée chaque fois qu'un utilisateur se connecte, se déconnecte, qu'un siège est ajouté ou supprimé, ou qu'une session, un utilisateur, un siège ou une machine virtuelle/conteneur change d'état autrement. Le premier paramètre accepte une chaîne qui peut être "seat" (pour recevoir uniquement les notifications concernant les sièges ajoutés, supprimés ou modifiés), "session" (pour recevoir uniquement les notifications concernant les sessions créées, supprimées ou modifiées), "uid" (pour recevoir uniquement les notifications lorsque qu'un utilisateur change d'état en ce qui concerne les connexions) ou "machine" (pour recevoir uniquement les notifications lorsque qu'une machine virtuelle ou un conteneur démarre ou s'arrête). Si des notifications doivent être générées dans toutes ces conditions, NULL peut être passé. Notez qu'à l'avenir, des catégories supplémentaires pourront être définies. Le second paramètre renvoie un objet moniteur et doit être libéré avec l'appel sd_login_monitor_unref() après utilisation.

sd_login_monitor_unref() peut être utilisé pour détruire un objet moniteur. Notez que cela invalidera tout descripteur de fichier retourné par sd_login_monitor_get_fd().

sd_login_monitor_unrefp() est similaire à sd_login_monitor_unref() mais accepte un pointeur vers un pointeur vers un objet sd_login_monitor. Cet appel est utile en conjonction avec l'attribut Clean-up Variable Attribute[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme la suivante, afin d'allouer un objet moniteur de connexion qui sera libéré automatiquement à la sortie du bloc de code :

{
  __attribute__((cleanup(sd_login_monitor_unrefp))) sd_login_monitor *m = NULL;
  int r;
  ...
  r = sd_login_monitor_new(NULL, &m);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Échec de l'allocation de l'objet moniteur de connexion : %m\n");
  }
  ...
}

sd_login_monitor_flush() peut être utilisé pour réinitialiser l'état de réveil de l'objet moniteur. Chaque fois qu'un événement provoque le réveil de l'objet moniteur via le descripteur de fichier, cette fonction doit être appelée pour réinitialiser l'état de réveil. Si cet appel n'est pas invoqué, le descripteur de fichier réveillera immédiatement à nouveau la boucle d'événements.

sd_login_monitor_unref() et sd_login_monitor_unrefp() n'effectuent aucune opération si l'objet moniteur passé est NULL.

sd_login_monitor_get_fd() peut être utilisé pour récupérer le descripteur de fichier de l'objet moniteur qui peut être intégré dans une boucle d'événements définie par l'application, basée sur poll(2) ou une interface similaire. L'application doit inclure le descripteur de fichier retourné comme source de réveil pour le masque d'événements retourné par sd_login_monitor_get_events(). Elle doit passer une valeur de délai d'attente telle que retournée par sd_login_monitor_get_timeout(). Chaque fois qu'un réveil est déclenché, le descripteur de fichier doit être réinitialisé via sd_login_monitor_flush(). Une application doit relire l'état de connexion avec une fonction comme sd_get_seats(3) ou similaire pour déterminer ce qui a changé.

sd_login_monitor_get_events() retournera le masque de poll() pour lequel attendre. Cette fonction retournera une combinaison de POLLIN, POLLOUT et similaires pour remplir le champ ".events" de struct pollfd.

sd_login_monitor_get_timeout() retournera une valeur de délai d'attente à utiliser dans poll(). Il retourne une valeur en microsecondes depuis l'époque de CLOCK_MONOTONIC pour le délai d'attente de poll() dans timeout_usec. Voir clock_gettime(2) pour les détails sur CLOCK_MONOTONIC. S'il n'y a pas de délai d'attente, il remplira (uint64_t) -1 à la place. Notez que poll() prend un délai d'attente relatif en millisecondes plutôt qu'un délai d'attente absolu en microsecondes. Pour convertir le délai d'attente absolu en 'µs' en délai d'attente relatif en 'ms', utilisez un code comme le suivant :

uint64_t t;
int msec;
sd_login_monitor_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

Le code ci-dessus n'effectue aucune vérification d'erreur par souci de concision. L'entier msec calculé peut être passé directement comme paramètre de délai d'attente de poll().

VALEUR DE RETOUR

En cas de succès, sd_login_monitor_new(), sd_login_monitor_flush() et sd_login_monitor_get_timeout() retournent 0 ou un entier positif. En cas de succès, sd_login_monitor_get_fd() retourne un descripteur de fichier Unix. En cas de succès, sd_login_monitor_get_events() retourne une combinaison de POLLIN, POLLOUT et similaires. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

sd_login_monitor_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre d'entrée était invalide (hors limites, ou NULL, là où ce n'est pas accepté). La catégorie spécifiée à surveiller n'est pas connue.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_login_monitor_get_events() et sd_login_monitor_get_timeout() ont été ajoutés dans la version 201.

sd_login_monitor_unrefp() a été ajouté dans la version 229.

sd_login_monitor_get_events(3)

NOM

sd_login_monitor_get_events - Récupérer les événements de connexion du moniteur de connexion

SYNTAXE

#include <systemd/sd-login.h>

int sd_login_monitor_get_events(sd_login_monitor *monitor, const void *fd, int *events);

DESCRIPTION

La fonction sd_login_monitor_get_events() récupère les événements de connexion du moniteur de connexion fourni par monitor. Elle interroge le descripteur de fichier fourni par fd pour les événements de connexion en attente et les place dans la variable pointée par events. Le champ events est un masque de bits d'indicateurs décrivant les événements de connexion. Les indicateurs possibles sont :

  • SD_LOGIN_MONITOR_NEW_SESSION : Une nouvelle session a été créée.
  • SD_LOGIN_MONITOR_CHANGES : Les informations de session ont changé.
  • SD_LOGIN_MONITOR_LOGIN : Un utilisateur s'est connecté.
  • SD_LOGIN_MONITOR_LOGOUT : Un utilisateur s'est déconnecté.
  • SD_LOGIN_MONITOR_USER_INVALID : L'utilisateur est invalide.
  • SD_LOGIN_MONITOR_REMOTE : La session est distante.
  • SD_LOGIN_MONITOR_LOCKED : La session est verrouillée.
  • SD_LOGIN_MONITOR_UNLOCKED : La session est déverrouillée.
  • SD_LOGIN_MONITOR_MESSAGE : Un message a été reçu.
  • SD_LOGIN_MONITOR_SHUTDOWN : Le système est en cours d'arrêt.
La fonction peut également renvoyer les événements suivants :
  • SD_LOGIN_MONITOR_ALL : Tous les événements.

VALEUR DE RETOUR

La fonction renvoie 0 en cas de succès, ou un code d'erreur négatif en cas d'échec.

  • -ECHILD : Le moniteur a été détruit.
  • -EINVAL : Les arguments sont invalides.
  • -ENOMSG : Aucun événement n'est disponible.
  • -EPIPE : Le canal de communication est cassé.

NOTES

Cette fonction est conçue pour être utilisée dans une boucle d'événements (par exemple, avec sd_event_loop()). Elle doit être appelée avec un descripteur de fichier qui a été préalablement enregistré auprès d'un gestionnaire d'événements. Le descripteur de fichier peut être obtenu à l'aide de la fonction sd_login_monitor_get_fd().

HISTORIQUE

sd_login_monitor_get_events() a été introduite dans systemd version 220.

VOIR AUSSI
