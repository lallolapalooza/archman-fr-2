DESCRIPTION

Ces fonctions renvoient des informations d'identification à partir d'un objet sd_bus_creds. Les objets d'identification peuvent être créés avec sd_bus_creds_new_from_pid(3), auquel cas ils décrivent les identifiants du processus identifié par le PID spécifié, avec sd_bus_get_name_creds(3), auquel cas ils décrivent les identifiants d'un pair du bus identifié par le nom de bus spécifié, avec sd_bus_get_owner_creds(3), auquel cas ils décrivent les identifiants du créateur d'un bus, ou avec sd_bus_message_get_creds(3), auquel cas ils décrivent les identifiants de l'expéditeur du message.

Tous les champs d'identification ne font pas partie de chaque objet "sd_bus_creds". Utilisez sd_bus_creds_get_mask(3) pour déterminer le masque des champs disponibles.

sd_bus_creds_get_pid() récupère le PID (identifiant de processus). De même, sd_bus_creds_get_ppid() récupère le PID parent. Notez que le PID 1 n'a pas de processus parent, auquel cas -ENXIO est renvoyé.

sd_bus_creds_get_pidfd_dup() récupère le descripteur de fichier PID (pidfd), voir pidfd_open(2) pour les détails. Le descripteur de fichier est dupliqué et doit donc être fermé par l'appelant.

sd_bus_creds_get_tid() récupère le TID (identifiant de thread).

sd_bus_creds_get_uid() récupère l'UID numérique (identifiant utilisateur). De même, sd_bus_creds_get_euid() renvoie l'UID effectif, sd_bus_creds_get_suid() l'UID sauvegardé et sd_bus_creds_get_fsuid() l'UID du système de fichiers.

sd_bus_creds_get_gid() récupère le GID numérique (identifiant de groupe). De même, sd_bus_creds_get_egid() renvoie le GID effectif, sd_bus_creds_get_sgid() le GID sauvegardé et sd_bus_creds_get_fsgid() le GID du système de fichiers.

sd_bus_creds_get_supplementary_gids() récupère la liste des GID supplémentaires.

sd_bus_creds_get_comm() récupère le champ comm (nom tronqué de l'exécutable, tel que stocké dans /proc/pid/comm).

sd_bus_creds_get_tid_comm() récupère le champ comm du thread (tel que stocké dans /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() récupère le chemin vers l'exécutable du programme (tel que stocké dans le lien /proc/pid/exe, mais avec le suffixe " (deleted)" supprimé). Notez que les threads du noyau n'ont pas de chemin d'exécutable, auquel cas -ENXIO est renvoyé. Notez que cette propriété ne doit pas être utilisée pour des informations purement explicatives, en particulier elle ne doit pas être utilisée pour des décisions de sécurité. En effet, l'exécutable pourrait avoir été remplacé ou supprimé au moment où la valeur peut être traitée. De plus, le noyau exporte ces informations d'une manière ambiguë (c'est-à-dire qu'un exécutable supprimé ne peut pas être distingué en toute sécurité d'un exécutable

DESCRIPTION

Ces fonctions sont utilisées pour interroger les informations d'identification (ou métadonnées) d'un processus ou d'une connexion D-Bus. Les informations d'identification peuvent être obtenues à partir d'un descripteur de fichier de processus, d'un ID de processus, ou directement à partir d'une connexion D-Bus.

Les fonctions commençant par sd_bus_creds_get_ récupèrent une valeur spécifique de l'objet de métadonnées c.

Les fonctions commençant par sd_bus_creds_has_ vérifient une condition spécifique.

sd_bus_creds_get_pid(), sd_bus_creds_get_tid(), sd_bus_creds_get_uid(), sd_bus_creds_get_gid(), sd_bus_creds_get_euid(), sd_bus_creds_get_egid(), sd_bus_creds_get_suid(), sd_bus_creds_get_sgid(), sd_bus_creds_get_fsuid(), sd_bus_creds_get_fsgid(), et sd_bus_creds_get_ppid() récupèrent l'ID de processus, l'ID de thread, l'ID utilisateur réel, l'ID groupe réel, l'ID utilisateur effectif, l'ID groupe effectif, l'ID utilisateur sauvegardé, l'ID groupe sauvegardé, l'ID utilisateur du système de fichiers, l'ID groupe du système de fichiers, et l'ID de processus parent, respectivement.

sd_bus_creds_get_comm() récupère le nom de la commande du processus (voir pr_comm(5) pour plus de détails, mais attention, il peut être tronqué). Notez que les threads du noyau n'ont pas de nom de commande, auquel cas -ENXIO est retourné.

sd_bus_creds_get_tid_comm() récupère le nom de la commande du thread spécifique (voir pr_comm(5)). Pour les threads sans nom de commande, -ENXIO est retourné.

sd_bus_creds_get_exe() récupère le chemin de l'exécutable du processus. Notez que les threads du noyau n'ont pas d'exécutable, auquel cas -ENXIO est retourné.

sd_bus_creds_get_cmdline() récupérera un tableau d'arguments de ligne de commande (tel que stocké dans /proc/pid/cmdline). Notez que les threads du noyau n'ont pas de ligne de commande, auquel cas -ENXIO est retourné.

sd_bus_creds_get_cgroup() récupérera le chemin du groupe de contrôle. Voir Control Groups v2[1].

sd_bus_creds_get_unit() récupérera le nom de l'unité systemd (dans l'instance système de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité, retourne -ENXIO.

sd_bus_creds_get_user_unit() récupérera le nom de l'unité systemd (dans l'instance utilisateur de systemd) dont le processus fait partie. Voir systemd.unit(5). Pour les processus qui ne font pas partie d'une unité utilisateur, retourne -ENXIO.

sd_bus_creds_get_slice() récupérera la tranche systemd (une unité dans l'instance système de systemd) dont le processus fait partie. Voir systemd.slice(5). De même, sd_bus_creds_get_user_slice() récupère la tranche systemd du processus, dans l'instance utilisateur de systemd.

sd_bus_creds_get_session() récupérera l'identifiant de la session de connexion dont le processus fait partie. Veuillez noter que la session de connexion peut être limitée à un processus stub ou deux. Les processus utilisateurs peuvent plutôt être démarrés à partir de leur gestionnaire utilisateur systemd, par exemple les applications graphiques démarrées à l'aide de l'activation DBus, ainsi que les processus de service qui sont partagés entre plusieurs connexions du même utilisateur. Pour les processus qui ne font pas partie d'une session, retourne -ENXIO.

sd_bus_creds_get_owner_uid() récupérera l'UID numérique (identifiant utilisateur) de l'utilisateur propriétaire de l'unité utilisateur ou de la session de connexion dont le processus fait partie. Voir systemd-logind.service(8). Pour les processus qui ne font pas partie d'une unité utilisateur ou d'une session, retourne -ENXIO.

sd_bus_creds_has_effective_cap() vérifiera si la capacité spécifiée par capability était définie dans le masque des capacités effectives. Une valeur de retour positive signifie qu'elle était définie, zéro signifie qu'elle n'était pas définie, et une valeur de retour négative indique une erreur. Voir capabilities(7) et les paramètres AmbientCapabilities= et CapabilityBoundingSet= dans systemd.exec(5).

sd_bus_creds_has_permitted_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités autorisées.

sd_bus_creds_has_inheritable_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités héritables.

sd_bus_creds_has_bounding_cap() est similaire à sd_bus_creds_has_effective_cap(), mais vérifiera le masque des capacités de limitation.

sd_bus_creds_get_selinux_context() récupérera le contexte de sécurité SELinux (étiquette) du processus.

sd_bus_creds_get_audit_session_id() récupérera l'identifiant de session d'audit du processus. Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_audit_login_uid() récupérera l'identifiant de connexion utilisateur d'audit (l'identifiant de l'utilisateur "responsable" de la session). Retourne -ENXIO pour les processus qui ne font pas partie d'une session d'audit.

sd_bus_creds_get_tty() récupérera le TTY de contrôle, sans le préfixe "/dev/". Retourne -ENXIO pour les processus qui n'ont pas de TTY de contrôle.

sd_bus_creds_get_unique_name() récupérera le nom unique D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_well_known_names() récupérera l'ensemble des noms bien connus D-Bus. Voir The D-Bus specification[2].

sd_bus_creds_get_description() récupérera un nom descriptif de la connexion bus du pair. Ce nom est utile pour distinguer plusieurs connexions bus du même pair, et peut être modifié par le pair avec l'appel sd_bus_set_description(3).

Toutes les fonctions qui prennent un paramètre const char** stockeront la réponse à cet endroit sous forme d'une adresse d'une chaîne se terminant par un octet nul. Elle sera valide tant que c restera valide, et ne devra pas être libérée ou modifiée par l'appelant.

Toutes les fonctions qui prennent un paramètre char*** stockeront la réponse à cet endroit sous forme d'une adresse d'un tableau de chaînes. Chaque chaîne individuelle se termine par un octet nul, et le tableau est terminé par un pointeur nul dans son ensemble. Il sera valide tant que c restera valide, et ne devra pas être libéré ou modifié par l'appelant.

sd_bus_creds_get_pidfd_dup() retournera un descripteur de fichier pour le pidfd du processus, si celui-ci est disponible et peut être dupliqué. Cela peut échouer avec EPERM si le pidfd ne peut pas être dupliqué, ou avec EBADF si le pidfd n'est pas disponible. Le descripteur de fichier retourné doit être libéré par l'appelant en utilisant close(2).

sd_bus_creds_get_supplementary_gids() récupère le tableau des groupes supplémentaires du processus.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ces appels retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENODATA

Le champ donné n'est pas disponible dans l'objet de métadonnées c.

-ENXIO

Le champ donné n'est pas spécifié pour le processus ou le pair décrit. Ceci sera retourné par sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), et sd_bus_creds_get_session() si le processus ne fait pas partie d'une unité système systemd, d'une unité utilisateur systemd, d'une tranche systemd, ou d'une session logind. Il sera retourné par sd_bus_creds_get_owner_uid() si le processus ne fait pas partie d'une unité utilisateur systemd ou d'une session logind. Il sera également retourné par sd_bus_creds_get_exe() et sd_bus_creds_get_cmdline() pour les threads du noyau (car ceux-ci ne sont pas démarrés à partir d'un binaire exécutable, ni n'ont de ligne de commande), et par sd_bus_creds_get_audit_session_id() et sd_bus_creds_get_audit_login_uid() lorsque le processus ne fait pas partie d'une session d'audit, et sd_bus_creds_get_tty() si le processus n'a pas de TTY de contrôle.

-EINVAL

Le paramètre de pointeur spécifié est NULL.

-ENOMEM

Échec de l'allocation de mémoire.

-EBADF

Le pidfd du processus n'est pas disponible ou ne peut pas être dupliqué.

-EPERM

Le pidfd du processus ne peut pas être dupliqué.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
