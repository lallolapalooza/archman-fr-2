SD_ID128_GET_MACHINE(3) sd_id128_get_machine SD_ID128_GET_MACHINE(3)

NOM

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Récupérer des identifiants 128 bits

SYNOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPTION

sd_id128_get_machine() renvoie l'ID machine de l'hôte en cours d'exécution. Ceci lit et analyse le fichier machine-id(5). Cette fonction met en cache l'ID machine en interne pour faire de la récupération de l'ID machine une opération peu coûteuse. Cet ID peut être utilisé partout où un identifiant unique pour le système local est nécessaire. Cependant, il est recommandé d'utiliser cet ID tel quel uniquement dans des environnements de confiance. Dans des environnements non fiables, il est recommandé d'en dériver un ID spécifique à l'application de manière irréversible (cryptographiquement sécurisée). Pour faciliter cela, sd_id128_get_machine_app_specific() est fourni, voir ci-dessous.

sd_id128_get_app_specific() renvoie un ID machine qui est une combinaison des paramètres base et app_id. En interne, cette fonction calcule HMAC-SHA256 du paramètre app_id en utilisant le paramètre base comme clé, et tronque ce résultat pour qu'il tienne dans sd_id128_t et le transforme en un UUID valide de la variante 1, version 4, conformément à la RFC 4122[1]. Aucun des deux paramètres d'entrée ne peut être calculé à partir du paramètre de sortie ret.

sd_id128_get_machine_app_specific() est similaire à sd_id128_get_machine(), mais récupère un ID machine spécifique à l'application identifiée par l'ID d'application indiqué. Il est recommandé d'utiliser cette fonction au lieu de sd_id128_get_machine() lors du passage d'un ID à des environnements non fiables, afin de s'assurer que l'ID machine d'origine ne puisse pas être déterminé de l'extérieur. De cette façon, l'ID utilisé par l'application reste stable sur une machine donnée, mais ne peut pas être facilement corrélé avec les ID utilisés dans d'autres applications sur la même machine. L'ID spécifique à l'application doit être généré via un outil tel que systemd-id128 new, et peut être compilé dans l'application. Cette fonction renverra le même ID spécifique à l'application pour chaque combinaison d'ID machine et d'ID d'application. En interne, cette fonction appelle sd_id128_get_app_specific() avec le résultat de sd_id128_get_machine() et le paramètre app_id.

sd_id128_get_boot() renvoie l'ID de démarrage du noyau en cours d'exécution. Ceci lit et analyse le fichier /proc/sys/kernel/random/boot_id exposé par le noyau. Il est généré aléatoirement tôt au démarrage et est unique pour chaque instance de noyau en cours d'exécution. Voir random(4) pour plus d'informations. Cette fonction met également en cache l'ID renvoyé en interne pour que cet appel soit une opération peu coûteuse. Il est recommandé d'utiliser cet ID tel quel uniquement dans des environnements de confiance. Dans des environnements non fiables, il est recommandé d'en dériver un ID spécifique à l'application à l'aide de sd_id128_get_boot_app_specific(), voir ci-dessous.

sd_id128_get_boot_app_specific() est analogue à sd_id128_get_machine_app_specific(), mais renvoie un ID qui change entre les démarrages. Certaines machines peuvent être utilisées pendant une longue période sans redémarrage, par conséquent l'ID de démarrage peut rester constant pendant une longue période et avoir des propriétés similaires à l'ID machine pendant ce temps.

sd_id128_get_invocation() renvoie l'ID d'invocation du service actuellement exécuté. Dans son implémentation actuelle, il tente de lire et d'analyser les éléments suivants :

•La variable d'environnement $INVOCATION_ID que le gestionnaire de services définit lorsqu'il active un service.
•Une entrée dans la clé du noyau que le gestionnaire de services système définit lors de l'activation d'un service.

Voir systemd.exec(5) pour plus de détails. L'ID est mis en cache en interne. À l'avenir, un mécanisme différent pour déterminer l'ID d'invocation pourra être ajouté.

sd_id128_get_invocation_app_specific() dérive un ID spécifique à l'application à partir de l'ID d'invocation.

Notez que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() et sd_id128_get_invocation_app_specific renvoient toujours des ID compatibles avec la variante 1, version 4 des UUID. sd_id128_get_machine() renverra également un ID compatible avec la variante 1, version 4 des UUID lors de nouvelles installations, mais pourrait ne pas le faire sur les anciennes. Il est possible de convertir l'ID machine de manière non réversible en un ID compatible avec la variante 1, version 4 des UUID. Pour plus d'informations, voir machine-id(5). Il est donc garanti que ces fonctions ne renverront jamais l'ID composé uniquement de bits zéro ou de bits un (SD_ID128_NULL, SD_ID128_ALLF) — à l'exception possible de sd_id128_get_machine(), comme mentionné.

Pour plus d'informations sur le type "sd_id128_t", voir sd-id128(3).

VALEUR DE RETOUR

Ces appels renvoient 0 en cas de succès (auquel cas ret est rempli), ou un code d'erreur négatif de type errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ENOENT

Renvoée par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque /etc/machine-id est manquant.

Ajouté dans la version 242.

-ENOMEDIUM

Renvoée par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque /etc/machine-id est vide ou composé uniquement de zéros. Renvoée également par sd_id128_get_invocation() lorsque l'ID d'invocation est composé uniquement de zéros.

Ajouté dans la version 242.

-ENOPKG

Renvoée par sd_id128_get_machine() et sd_id128_get_machine_app_specific() lorsque le contenu de /etc/machine-id est "non initialisé".

Ajouté dans la version 253.

-ENOSYS

Renvoée par sd_id128_get_boot() et sd_id128_get_boot_app_specific() lorsque /proc/ n'est pas monté.

Ajouté dans la version 253.

-ENXIO

Renvoée par sd_id128_get_invocation() si aucun ID d'invocation n'est défini. Renvoée également par sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), et sd_id128_get_boot_app_specific() lorsque le paramètre app_id est composé uniquement de zéros.

Ajouté dans la version 242.

-EUCLEAN

Renvoée par l'une des fonctions décrites ici lorsque la valeur configurée a un format invalide.

Ajouté dans la version 253.

-EPERM

Les informations demandées n'ont pas pu être récupérées en raison d'autorisations insuffisantes.

Ajouté dans la version 242.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dès le début du programme, lorsqu'aucun autre thread n'a été démarré.

sd_id128_get_boot_app_specific(3)

NAME

sd_id128_get_boot_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_invocation_app_specific, sd_id128_get_app_specific - Get application-specific identifier

SYNOPSIS

#include <systemd/sd-id128.h>
int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPTION

These functions are similar to sd_id128_get_boot(3), sd_id128_get_machine(3), and sd_id128_get_invocation(3), but instead of returning the system-wide unique IDs, they return an identifier that is derived from the passed app_id and the corresponding system-wide unique ID. This is useful for generating application-specific identifiers that are still unique per-boot, per-machine, or per-invocation.

The app_id parameter should be a 128-bit UUID string that is generated specifically for the application. It is recommended to use `systemd-id128 new` to generate a new UUID.

The generated identifier is composed by XORing the system-wide unique ID and the passed app_id. It is not guaranteed that the resulting identifier will be globally unique, but it should be unique within the context it was generated for (e.g. per-boot).

sd_id128_get_boot_app_specific() derives the identifier from the current boot identifier (see sd_id128_get_boot(3)).

sd_id128_get_machine_app_specific() derives the identifier from the machine identifier (see sd_id128_get_machine(3)).

sd_id128_get_invocation_app_specific() derives the identifier from the current invocation identifier (see sd_id128_get_invocation(3)).

sd_id128_get_app_specific() derives the identifier from the current invocation identifier, but XORs it with the provided app_id. This is a convenience function for sd_id128_get_invocation_app_specific().

The generated identifier is stored in the buffer pointed to by ret.

All functions return 0 on success, and a negative errno value on failure. Possible failure values are ENODATA if the underlying system identifier could not be read.

RETURN VALUE

On success, these functions return 0. On failure, they return a negative errno value.

NOTES

The generated application-specific ID is guaranteed to be valid for the lifetime of the specific boot, machine, or invocation, respectively. It is not guaranteed to be unique across different boots, machines, or invocations.

The application UUID app_id should be generated using systemd-id128 new. For example:

$ systemd-id128 -p new
As string:
c273277323db454ea63bb96e79b53e97
As UUID:
c2732773-23db-454e-a63b-b96e79b53e97
As man:sd-id128(3) macro:
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Then use the new identifier in an example application:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

sd_id128_get_machine_app_specific() was added in version 233.

sd_id128_get_boot_app_specific() was added in version 240.

sd_id128_get_invocation_app_specific() was added in version 256.

NOM

sd_id128_get_boot_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_invocation_app_specific, sd_id128_get_app_specific - Obtenir un identifiant spécifique à une application

SYNTAXE

#include <systemd/sd-id128.h>
int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);
int sd_id128_get_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPTION

Ces fonctions sont similaires à sd_id128_get_boot(3), sd_id128_get_machine(3), et sd_id128_get_invocation(3), mais au lieu de retourner les identifiants uniques à l'échelle du système, elles retournent un identifiant dérivé de l'app_id passée et de l'identifiant unique correspondant à l'échelle du système. C'est utile pour générer des identifiants spécifiques à une application qui restent uniques par démarrage, par machine, ou par invocation.

Le paramètre app_id doit être une chaîne UUID de 128 bits générée spécifiquement pour l'application. Il est recommandé d'utiliser `systemd-id128 new` pour générer un nouvel UUID.

L'identifiant généré est composé en faisant un XOR entre l'identifiant unique à l'échelle du système et l'app_id passée. Il n'est pas garanti que l'identifiant résultant soit globalement unique, mais il devrait être unique dans le contexte pour lequel il a été généré (par exemple, par démarrage).

sd_id128_get_boot_app_specific() dérive l'identifiant de l'identifiant de démarrage actuel (voir sd_id128_get_boot(3)).

sd_id128_get_machine_app_specific() dérive l'identifiant de l'identifiant de la machine (voir sd_id128_get_machine(3)).

sd_id128_get_invocation_app_specific() dérive l'identifiant de l'identifiant d'invocation actuel (voir sd_id128_get_invocation(3)).

sd_id128_get_app_specific() dérive l'identifiant de l'identifiant d'invocation actuel, mais effectue un XOR avec l'app_id fournie. C'est une fonction de commodité pour sd_id128_get_invocation_app_specific().

L'identifiant généré est stocké dans le tampon pointé par ret.

Toutes les fonctions retournent 0 en cas de succès, et une valeur négative d'errno en cas d'échec. Les valeurs d'échec possibles sont ENODATA si l'identifiant système sous-jacent n'a pas pu être lu.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0. En cas d'échec, elles retournent une valeur négative d'errno.

NOTES

L'ID spécifique à l'application généré est garanti d'être valide pour la durée du démarrage, de la machine ou de l'invocation spécifique, respectivement. Il n'est pas garanti d'être unique entre différents démarrages, machines ou invocations.

L'UUID de l'application app_id doit être généré en utilisant systemd-id128 new. Par exemple :

$ systemd-id128 -p nouveau
En chaîne :
c273277323db454ea63bb96e79b53e97
En UUID :
c2732773-23db-454e-a63b-b96e79b53e97
En macro man:sd-id128(3) :
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Utilisez ensuite le nouvel identifiant dans une application exemple :

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define NOTRE_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(NOTRE_APPLICATION_ID, &id);
  printf("Notre ID d'application : " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
