DESCRIPTION

sd_bus_emit_signal() est une fonction pratique pour initialiser un objet message de bus et émettre le signal D-Bus correspondant. Elle combine les fonctions sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) en un seul appel de fonction. sd_bus_emit_signalv() est équivalent à sd_bus_message_append(), sauf qu'il est appelé avec une "va_list" au lieu d'un nombre variable d'arguments.

sd_bus_emit_signal_to() et sd_bus_emit_signal_tov() sont identiques à sd_bus_emit_signal() et sd_bus_emit_signalv(), sauf qu'ils peuvent émettre le signal vers une seule destination. Donnez destination comme NULL pour diffuser le signal.

sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() sont utilisés pour implémenter les signaux InterfacesAdded et InterfacesRemoved de l'interface org.freedesktop.DBus.ObjectManager. Ils prennent en argument un chemin dont les interfaces ont été modifiées et une liste variable d'interfaces qui ont été ajoutées ou supprimées, respectivement. Le dernier argument passé à sd_bus_emit_interfaces_added() et sd_bus_emit_interfaces_removed() doit être NULL. Cela permet aux deux fonctions de déterminer en toute sécurité le nombre d'arguments d'interface passés. sd_bus_emit_interfaces_added_strv() et sd_bus_emit_interfaces_removed_strv() sont identiques à leurs homologues respectifs mais prennent tous deux la liste des interfaces comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_properties_changed() est utilisé pour implémenter le signal PropertiesChanged de l'interface org.freedesktop.DBus.Properties. Il prend un chemin d'objet, une interface et une liste variable de noms de propriétés comme arguments. Le dernier argument passé à sd_bus_emit_properties_changed() doit être NULL. Cela lui permet de déterminer en toute sécurité le nombre de noms de propriétés passés. sd_bus_emit_properties_changed_strv() est identique à sd_bus_emit_properties_changed() mais prend la liste des noms de propriétés comme un seul argument au lieu d'un nombre variable d'arguments.

sd_bus_emit_object_added() et sd_bus_emit_object_removed() sont des fonctions pratiques pour émettre les signaux InterfacesAdded ou InterfacesRemoved pour toutes les interfaces enregistrées sur un chemin d'objet spécifique, respectivement. Cela inclut les tables de correspondance de repli parentes si elles ne sont pas remplacées par une table de correspondance enfant plus adaptée. Cela inclut également toutes les interfaces D-Bus standard implémentées par sd-bus lui-même sur tout objet enregistré.

Notez que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() et sd_bus_emit_object_removed() nécessitent qu'un gestionnaire d'objets ait été enregistré sur le chemin d'objet donné ou l'un de ses chemins d'objet parents en utilisant sd_bus_add_object_manager(3).

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants:

-EINVAL

L'un des paramètres requis est NULL ou invalide. Une interface D-Bus réservée a été passée comme paramètre interface.

-ENOPKG

Le bus ne peut pas être résolu.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

-ENOMEM

Échec de l'allocation mémoire.

-ESRCH

L'une des fonctions sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() ou sd_bus_emit_object_removed() a été appelée sur un objet sans gestionnaire d'objets enregistré sur son propre chemin d'objet ou l'un de ses chemins d'objet parents.

Voir les pages de manuel de sd_bus_message_new_signal(3), sd_bus_message_append(3) et sd_bus_send(3) pour d'autres erreurs possibles.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour une utilisation multi-thread. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un fil d'exécution parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre fil d'exécution n'a été démarré.
