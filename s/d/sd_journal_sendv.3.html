NOM

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_print(int priority, const char *format, ...);

int sd_journal_printv(int priority, const char *format, va_list ap);

int sd_journal_send(const char *format, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *message);

int sd_journal_print_with_location(int priority, const char *file, const char *line, const char *func, const char *format, ...);

int sd_journal_printv_with_location(int priority, const char *file, const char *line, const char *func, const char *format, va_list ap);

int sd_journal_send_with_location(const char *file, const char *line, const char *func, const char *format, ...);

int sd_journal_sendv_with_location(const char *file, const char *line, const char *func, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *file, const char *line, const char *func, const char *message);

DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples en texte brut au journal système. Le premier argument est une valeur de priorité. Ceci est suivi par une chaîne de format et ses paramètres, similaire à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour les détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale système et en format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits à l'aide de cette fonction ne devraient généralement pas se terminer par un caractère de nouvelle ligne. Cependant, comme tous les espaces blancs de fin (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne enregistrée, il est acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après suppression des espaces blancs de fin) sont supprimées. Sur les lignes non vides, les espaces blancs de début (ainsi que les espaces blancs internes) restent inchangés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variables encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Son comportement est sinon équivalent.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune immédiatement suivie de ses paramètres associés, terminée par NULL. Les chaînes passées doivent être du format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et consister uniquement de caractères, de chiffres et de traits de soulignement, et ne peut pas commencer par un trait de soulignement. (Toutes les affectations qui ne suivent pas cette syntaxe seront ignorées.) La valeur peut être de n'importe quelle taille et format. Il est fortement recommandé de ne soumettre que des chaînes de texte formatées dans l'encodage de caractères UTF-8, et de ne soumettre des champs binaires que lorsque le formatage en chaînes UTF-8 n'est pas pertinent. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs supplémentaires définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plusieurs valeurs par entrée. Si cette fonction est utilisée, les espaces blancs de fin sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit référencer un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprimera pas les espaces blancs de fin des champs passés, mais transmettra les données spécifiées sans modification. Ceci est différent de sd_journal_print() et sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs de fin.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suffixée par ": " et une représentation lisible par l'homme du code d'erreur actuel stocké dans errno(3). Si la chaîne de message est passée comme NULL ou chaîne vide, seule la représentation de la chaîne d'erreur sera écrite, préfixée par rien. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté sous forme de chaîne décimale. La priorité de journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour faciliter son utilisation lorsque seules des chaînes de texte doivent être soumises. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Hello World, this is PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Hello World, this is PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont invoqués. Ceci est implémenté avec des macros. Si cela n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() sont similaires à leurs homologues sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "file" et "line" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "func" ne doit contenir que le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture de wrappers personnalisés, par exemple dans des liaisons pour une autre langue.

syslog(3) et sd_journal_print() peuvent être en grande partie utilisés de manière interchangeable en termes de fonctionnalités. Cependant, notez que les messages de journal enregistrés via le premier empruntent un chemin différent vers le serveur de journal que ces derniers, et par conséquent, un ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage d'enregistrer la ligne du code source, les noms de fichiers et les fonctions en métadonnées avec toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client pour le Protocole de Journal Natif[1].

sd_journal_sendv(3) — systemd — Arch Linux

NAME

sd_journal_sendv, sd_journal_sendv_with_location, sd_journal_send, sd_journal_send_with_location, sd_journal_print, sd_journal_print_with_location, sd_journal_printv, sd_journal_printv_with_location, sd_journal_perror, sd_journal_perror_with_location - send messages to the journal

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_sendv(const struct iovec *iov, int len);
int sd_journal_sendv_with_location(const struct iovec *iov, int len,
                                   const char *file, const char *line,
                                   const char *func);
int sd_journal_send(const char *first, ...);
int sd_journal_send_with_location(const char *file, const char *line,
                                  const char *func, const char *first, ...);
int sd_journal_print(const char *first, ...);
int sd_journal_print_with_location(const char *file, const char *line,
                                   const char *func, const char *first, ...);
int sd_journal_printv(const struct iovec *iov, int len);
int sd_journal_printv_with_location(const struct iovec *iov, int len,
                                    const char *file, const char *line,
                                    const char *func);
int sd_journal_perror(const char *first, ...);
int sd_journal_perror_with_location(const char *file, const char *line,
                                    const char *func, const char *first, ...);

DESCRIPTION

These functions provide an interface for sending messages from applications and services to the systemd journal (systemd-journald(8)). They are intended to be used instead of, or in addition to, standard mechanisms like syslog(3).

The functions primarily differ in how they accept input and whether they include source location information.

sd_journal_sendv() and sd_journal_sendv_with_location() accept a variable number of key-value pairs via an array of iovec structures. Each structure must contain a null-terminated string. The strings are expected to be of the format "FIELD=value" or "FIELD":

    <field-name>=<value>

Fields are limited to alphanumeric characters and underscores ([a-zA-Z0-9_]). If the value part is empty, the field is set to an empty string. If the string does not contain an equals sign, it is treated as a field with an empty value.

The keys MUST be uppercase. The journal requires that certain fields are uppercase (e.g. `MESSAGE=`, `CODE_FUNCTION=`, `CODE_FILE=`, `CODE_LINE=`). While these functions don't enforce it, it is strongly recommended to use uppercase field names.

sd_journal_send(), sd_journal_send_with_location(), sd_journal_print(), sd_journal_print_with_location(), sd_journal_perror(), and sd_journal_perror_with_location() accept a variable number of arguments similar to printf(). The first argument is the first field's value. Subsequent arguments are optional additional fields' values. Each string argument is expected to be of the format "FIELD=value" or "FIELD".

sd_journal_print(), sd_journal_print_with_location(), sd_journal_printv(), and sd_journal_printv_with_location() are convenience functions for sending messages to the journal that do not strictly adhere to the "FIELD=value" format. They are functionally equivalent to calling sd_journal_send(), sd_journal_send_with_location(), sd_journal_sendv(), and sd_journal_sendv_with_location() respectively, but with the additional logic that if the first argument does not contain an equals sign, it is prepended with the field name `MESSAGE=`. This makes it easier to send simple log messages without explicitly naming the `MESSAGE` field.

sd_journal_perror() and sd_journal_perror_with_location() are similar to sd_journal_print() and sd_journal_print_with_location(), but they additionally append a string representation of the current value of the error code variable errno to the message. The appended string is prefixed with ": ". For example, if errno is ENOENT, the appended string will be ": No such file or directory".

sd_journal_send_with_location(), sd_journal_sendv_with_location(), sd_journal_print_with_location(), sd_journal_printv_with_location(), and sd_journal_perror_with_location() additionally accept the source file name, line number, and function name as arguments. These are stored in the standard journal fields `CODE_FILE=`, `CODE_LINE=`, and `CODE_FUNCTION=`, respectively. These fields are useful for debugging and tracing code execution.

All these functions send their data to the journal via the AF_UNIX domain socket located at `/run/systemd/journal/stdout` (or `/run/systemd/journal/fd` if journald is configured to use file descriptor passing). If this socket is not present (i.e. systemd-journald(8) is not running or not configured to listen on this socket), these functions will do nothing and return 0.

The strings passed to these functions are copied internally, so the caller does not need to keep them valid after the call returns.

The number of fields that can be sent is limited by system resources and the journald configuration. In practice, this limit is very high.

See systemd.journal-fields(7) for a list of standard journal fields.

RETURN VALUE

On success, these functions return a non-negative integer which is the number of fields successfully sent. On failure, they return a negative errno value.

If systemd-journald(8) is not running (the socket is not present), those functions do nothing, and also return 0.

THREAD SAFETY

All functions listed here are thread-safe and may be called in parallel from multiple threads.

sd_journal_sendv() and sd_journal_sendv_with_location() are "async signal safe" in the meaning of signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), and their counterparts with "_with_location" are not async signal safe.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
