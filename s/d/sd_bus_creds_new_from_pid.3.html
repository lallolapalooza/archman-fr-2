NOM

sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Récupérer l'objet d'informations d'identification pour le PID spécifié

#include <systemd/sd-bus.h>

DESCRIPTION

sd_bus_creds_new_from_pid() crée un nouvel objet d'informations d'identification et le remplit avec des informations sur le processus pid. Le pointeur vers cet objet sera stocké dans le pointeur ret. Notez que les objets d'informations d'identification peuvent également être créés et récupérés via sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) et sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() est identique à sd_bus_creds_new_from_pid(), mais prend un descripteur de fichier PID plutôt qu'un PID numérique comme référence au processus. Voir pidfd_open(2).

Les informations qui seront stockées sont déterminées par creds_mask. Il peut contenir un sous-ensemble de constantes ORed SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, et SD_BUS_CREDS_PIDFD. Utilisez la valeur spéciale _SD_BUS_CREDS_ALL pour demander tous les champs pris en charge. La constante SD_BUS_CREDS_AUGMENT ne doit pas être ORée dans le masque pour les appels à sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd().

Les champs peuvent être récupérés de l'objet d'informations d'identification à l'aide de sd_bus_creds_get_pid(3) et d'autres fonctions qui correspondent directement aux constantes énumérées ci-dessus.

Un masque des champs qui ont été effectivement récupérés avec succès peut être obtenu avec sd_bus_creds_get_mask(). Si l'objet d'informations d'identification a été créé avec sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), il s'agira d'un sous-ensemble des champs demandés dans creds_mask.

Similaire à sd_bus_creds_get_mask(), la fonction sd_bus_creds_get_augmented_mask() renvoie un masque de bits des constantes de champ. Le masque indique quels champs d'informations d'identification ont été récupérés de manière non atomique. Pour les objets d'informations d'identification créés via sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce masque sera identique au masque renvoyé par sd_bus_creds_get_mask(). Cependant, pour les objets d'informations d'identification récupérés via sd_bus_get_name_creds(), ce masque sera défini pour les champs d'informations d'identification qui n'ont pas pu être déterminés de manière atomique au moment de la connexion de pairs, et qui ont été ultérieurement ajoutés en lisant des données d'informations d'identification supplémentaires depuis /proc/. De même, pour les objets d'informations d'identification récupérés via sd_bus_get_owner_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés de manière atomique au moment de la création du bus, mais qui ont été augmentés. De même, pour les objets d'informations d'identification récupérés via sd_bus_message_get_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés de manière atomique au moment de l'envoi du message, mais qui ont été augmentés. Le masque renvoyé par sd_bus_creds_get_augmented_mask() est toujours un sous-ensemble (ou identique) au masque renvoyé par sd_bus_creds_get_mask() pour le même objet. L'appel à ce dernier renvoie donc tous les champs d'informations d'identification disponibles dans l'objet d'informations d'identification, le premier marquant alors le sous-ensemble de ceux qui ont été augmentés. Notez que les champs augmentés ne conviennent pas aux décisions d'autorisation, car ils peuvent être récupérés à différents moments, étant ainsi sujets aux courses. Par conséquent, les champs augmentés ne doivent être utilisés qu'à des fins d'information.

sd_bus_creds_ref() crée une nouvelle référence à l'objet d'informations d'identification c. Cet objet ne sera pas détruit tant que sd_bus_creds_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, c ne peut plus être utilisé, donc les appels ultérieurs à sd_bus_creds_ref(c) ou sd_bus_creds_unref(c) sont illégaux.

sd_bus_creds_unref() détruit une référence à c.

sd_bus_creds_unrefp() est similaire à sd_bus_creds_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_creds. Cet appel est utile conjointement avec l'attribut de variable Clean-up de GCC et LLVM[1]. Notez que cette fonction est définie comme une fonction inline.

sd_bus_creds_ref(), sd_bus_creds_unref() et sd_bus_creds_unrefp() n'exécutent aucune opération si l'objet d'informations d'identification de bus passé est NULL.

VALEUR RENVOYÉE

En cas de succès, sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() renvoient 0 ou un entier positif. En cas d'échec, ils renvoient un code d'erreur négatif de type errno.

sd_bus_creds_get_mask() renvoie le masque des champs acquis avec succès.

sd_bus_creds_get_augmented_mask() renvoie le masque des champs qui ont été augmentés à partir des données dans /proc/, et ne conviennent donc pas aux décisions d'autorisation.

sd_bus_creds_ref() renvoie toujours l'argument.

sd_bus_creds_unref() renvoie toujours NULL.

PROPRIÉTÉ DES RÉFÉRENCES

Les fonctions sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() créent un nouvel objet et l'appelant possède la seule référence. Lorsqu'elle n'est plus nécessaire, cette référence doit être détruite avec sd_bus_creds_unref(3).

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-ESRCH

Le pid spécifié n'a pas pu être trouvé.

-ENOENT

Le fichier du PID spécifié n'a pas pu être trouvé.

-EACCES

Autorisation refusée. L'appelant n'est pas autorisé à demander les informations d'identification du processus spécifié. Ceci est généralement le cas lorsque le processus appelant n'appartient pas à la même session d'utilisateur que le processus cible.

-EINVAL

Un argument invalide a été passé.

-ENOMEM

Mémoire insuffisante pour allouer l'objet d'informations d'identification.

-EPERM

L'opération n'est pas autorisée. Par exemple, certaines informations d'identification ne sont accessibles que par des processus possédant des privilèges spécifiques.

-EROFS

Le système de fichiers est en lecture seule.

-ENFILE

Trop de descripteurs de fichiers ouverts.

-ENOTSUP

La récupération de certains champs d'informations d'identification demandés n'est pas prise en charge par le système d'exploitation ou la version du noyau.

-EBADF

Le pidfd n'est pas un descripteur de fichier valide.

-EINPROGRESS

L'opération est en cours d'exécution.

-ENOBUFS

Pas assez de mémoire tampon.

-EAGAIN

Tentative temporaire de récupération des informations d'identification a échoué.

Notez que des erreurs supplémentaires peuvent être renvoyées en fonction des fonctions sous-jacentes utilisées pour récupérer les informations d'identification.

EXEMPLE

Exemple 1. Obtenir les informations d'identification d'un PID spécifique.

    sd_bus_creds *creds = NULL;
    int r;

    r = sd_bus_creds_new_from_pid(getpid(), SD_BUS_CREDS_UID|SD_BUS_CREDS_COMM, &creds);
    if (r < 0) {
        fprintf(stderr, "Impossible d'obtenir les informations d'identification : %s\n", strerror(-r));
        goto finish;
    }

    uid_t uid;
    r = sd_bus_creds_get_uid(creds, &uid);
    if (r < 0) {
        fprintf(stderr, "Impossible d'obtenir l'UID : %s\n", strerror(-r));
        goto finish;
    }
    printf("UID : %d\n", uid);

    const char *comm;
    r = sd_bus_creds_get_comm(creds, &comm);
    if (r < 0) {
        fprintf(stderr, "Impossible d'obtenir le nom de la commande : %s\n", strerror(-r));
        goto finish;
    }
    printf("Nom de la commande : %s\n", comm);

    finish:
    sd_bus_creds_unref(creds);
    return r < 0 ? EXIT_FAILURE : EXIT_SUCCESS;

Exemple 2. Utilisation de sd_bus_creds_unrefp().

    #include <stdio.h>
    #include <stdlib.h>
    #include <systemd/sd-bus.h>

    static void cleanup_creds(sd_bus_creds **c) {
        sd_bus_creds_unrefp(c);
    }

    int main(int argc, char *argv[]) {
        sd_bus_creds *creds __attribute__((cleanup(cleanup_creds))) = NULL;
        int r;

        r = sd_bus_creds_new_from_pid(getpid(), SD_BUS_CREDS_UID, &creds);
        if (r < 0) {
            fprintf(stderr, "Impossible d'obtenir les informations d'identification : %s\n", strerror(-r));
            return EXIT_FAILURE;
        }

        printf("Informations d'identification obtenues avec succès.\n");

        return EXIT_SUCCESS;
    }

VALEUR DE RETOUR

En cas de succès, sd_bus_creds_get_mask() renvoie le masque de privilèges sous forme d'entier. En cas d'erreur, un des codes d'erreur ci-dessous est renvoyé.

-EINVAL
Le paramètre spécifié est invalide (NULL dans le cas de paramètres de sortie).
-ENOMEM
L'allocation mémoire a échoué.
-EOPNOTSUPP
L'un des champs demandés est inconnu du système local.

PROPRIÉTÉ DE RÉFÉRENCE

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'appeler setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a encore été démarré.
