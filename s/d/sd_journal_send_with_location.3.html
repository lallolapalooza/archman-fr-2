SD_JOURNAL_PRINT(3) sd_journal_print SD_JOURNAL_PRINT(3)

NOM

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, SD_JOURNAL_SUPPRESS_LOCATION, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Soumettre des entrées de journal au journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_print(int priorité, const char *format, ...);

int sd_journal_printv(int priorité, const char *format, va_list ap);

int sd_journal_send(const char *format, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *message);

int sd_journal_print_with_location(int priorité, const char *fichier, const char *ligne, const char *func, const char *format, ...);

int sd_journal_printv_with_location(int priorité, const char *fichier, const char *ligne, const char *func, const char *format, va_list ap);

int sd_journal_send_with_location(const char *fichier, const char *ligne, const char *func, const char *format, ...);

int sd_journal_sendv_with_location(const char *fichier, const char *ligne, const char *func, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *fichier, const char *ligne, const char *func, const char *message);

DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples et en texte brut au journal système. Le premier argument est une valeur de priorité. Viennent ensuite une chaîne de format et ses paramètres, similaires à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une des valeurs LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour les détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale du système et au format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits à l'aide de cette fonction ne sont généralement pas censés se terminer par un caractère de nouvelle ligne. Cependant, comme tous les espaces blancs de fin (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne journalisée, il est acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après suppression des espaces blancs de fin) sont supprimées. Sur les lignes non vides, les espaces blancs de début (ainsi que les espaces blancs internes) sont laissés inchangés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variables encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Il est par ailleurs équivalent en comportement.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune immédiatement suivie de leurs paramètres associés, terminées par NULL. Les chaînes passées doivent être du format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et ne contenir que des caractères, des chiffres et des underscores, et ne peut pas commencer par un underscore. (Toutes les affectations qui ne suivent pas cette syntaxe seront ignorées.) La valeur peut être de toute taille et de tout format. Il est fortement recommandé de soumettre uniquement des chaînes de texte formatées dans le codage de caractères UTF-8, et de soumettre des champs binaires uniquement lorsqu'il n'est pas judicieux de les formater en chaînes UTF-8. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs d'application supplémentaires définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plus d'une valeur par entrée. Si cette fonction est utilisée, les espaces blancs de fin sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit référencer un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprimera pas les espaces blancs de fin des champs passés, mais transmettra les données spécifiées sans modification. Ceci est différent de sd_journal_print() et sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs de fin.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suivie de ": " et d'une représentation lisible par l'homme du code d'erreur courant stocké dans errno(3). Si la chaîne de message est passée comme NULL ou comme chaîne vide, seule la représentation de la chaîne d'erreur sera écrite, sans préfixe. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté sous forme de chaîne décimale. La priorité de journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour le rendre plus facile à utiliser lorsqu'il faut uniquement soumettre des chaînes de texte. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Bonjour le monde, ceci est le PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Bonjour le monde, ceci est le PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont appelés. Ceci est implémenté avec des macros. Si cela n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location() et sd_journal_perror_with_location() sont similaires à leurs homologues sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "fichier" et "ligne" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "func" ne doit contenir que le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture de wrappers personnalisés, par exemple dans des liaisons pour une autre langue.

syslog(3) et sd_journal_print() peuvent être largement utilisés de manière interchangeable en termes de fonctionnalités. Cependant, notez que les messages de journal enregistrés via le premier empruntent un chemin différent vers le serveur de journal que ceux enregistrés via le second, et par conséquent, l'ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage d'enregistrer la ligne du code source, les noms de fichiers et les fonctions comme métadonnées pour toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées qui sont générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client du Protocole Natif du Journal[1].

VALEUR DE RETOUR

Les dix fonctions retournent 0 en cas de succès ou un code d'erreur négatif de style errno. Le errno(3)

sd_journal_send_with_location(3) — systemd libs documentation

NAME

sd_journal_send_with_location, sd_journal_send, sd_journal_sendv_with_location, sd_journal_sendv, sd_journal_print_with_location, sd_journal_print, sd_journal_printv_with_location, sd_journal_printv, sd_journal_perror_with_location, sd_journal_perror — envoyer des messages au journal système

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_send(const char *format, ...);
int sd_journal_sendv(const struct iovec *iov, int iovcnt);
int sd_journal_print(const char *format, ...);
int sd_journal_printv(const struct iovec *iov, int iovcnt);
int sd_journal_perror(const char *format, ...);

int sd_journal_send_with_location(const char *file, const char *line, const char *func, const char *format, ...);
int sd_journal_sendv_with_location(const char *file, const char *line, const char *func, const struct iovec *iov, int iovcnt);
int sd_journal_print_with_location(const char *file, const char *line, const char *func, const char *format, ...);
int sd_journal_printv_with_location(const char *file, const char *line, const char *func, const struct iovec *iov, int iovcnt);
int sd_journal_perror_with_location(const char *file, const char *line, const char *func, const char *format, ...);

DESCRIPTION

Ces fonctions envoient des données au journal système via le démon systemd-journald(8). Elles permettent de journaliser des messages sous forme de paires champ=valeur (comme dans systemd.journal-fields(7)) ou de chaînes de caractères brutes.

Les fonctions commençant par sd_journal_send* envoient une liste de paires champ=valeur. Les fonctions commençant par sd_journal_print* envoient une chaîne de caractères brute, qui sera ajoutée au champ MESSAGE du journal. Les fonctions sd_journal_perror* sont similaires à sd_journal_print*, mais elles ajoutent également le message d'erreur système courant (obtenu via errno(3)) au champ MESSAGE.

Les fonctions avec le suffixe _with_location prennent des arguments supplémentaires pour le nom de fichier (file), le numéro de ligne (line) et le nom de la fonction (func) d'où l'appel est effectué. Ces informations sont ajoutées aux champs CODE_FILE, CODE_LINE et CODE_FUNCTION du journal.

Les fonctions qui acceptent un argument format utilisent le même mécanisme que printf(3) pour formater la chaîne de sortie. Les fonctions qui acceptent un tableau struct iovec *iov et un compteur iovcnt permettent d'envoyer plusieurs morceaux de données consécutivement. Chaque élément du tableau iov représente un tampon de chaîne de caractères et sa longueur.

Si le démon systemd-journald(8) n'est pas en cours d'exécution (le socket n'est pas présent), ces fonctions ne font rien et retournent 0.

RETURN VALUE

En cas de succès, ces fonctions retournent un nombre entier non négatif. En cas d'erreur, elles retournent un nombre entier négatif correspondant à l'une des valeurs d'erreur définies dans errno.

THREAD SAFETY

Toutes les fonctions listées ici sont thread-safe et peuvent être appelées en parallèle à partir de plusieurs threads.

sd_journal_sendv() et sd_journal_sendv_with_location() sont "async signal safe" au sens de signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), et leurs variantes avec "_with_location" ne sont pas async signal safe.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe pour les opérations d'environnement. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a encore été démarré.

HISTORY

sd_journal_print(), sd_journal_printv(), sd_journal_send(), et sd_journal_sendv() ont été ajoutées dans la version 187.

sd_journal_perror() a été ajoutée dans la version 188.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() ont été ajoutées dans la version 246.
