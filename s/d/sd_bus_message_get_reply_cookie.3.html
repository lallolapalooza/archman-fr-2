SD_BUS_MESSAGE_GET_COOKIE(3) sd_bus_message_get_cookie SD_BUS_MESSAGE_GET_COOKIE(3)

NOM

sd_bus_message_get_cookie, sd_bus_message_get_reply_cookie - Récupère le cookie de transaction d'un message

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_message_get_cookie(sd_bus_message *message, uint64_t *cookie);

int sd_bus_message_get_reply_cookie(sd_bus_message *message, uint64_t *cookie);

DESCRIPTION

sd_bus_message_get_cookie() récupère le cookie de transaction d'un message. Le cookie identifie de manière unique un message entre deux pairs du bus, mais n'est pas globalement unique. Il est attribué lors de l'envoi d'un message.

sd_bus_message_get_reply_cookie() récupère le cookie de transaction du message auquel le message spécifié répond. Lorsqu'un message de réponse est généré pour un message d'appel de méthode, son cookie est copié dans ce champ. Notez que bien que tout message transféré soit identifié par un cookie, seuls les messages de réponse portent un champ de cookie de réponse.

Les deux fonctions prennent un objet message comme premier paramètre et un emplacement pour stocker le cookie de 64 bits.

VALEUR DE RETOUR

En cas de succès, ces appels retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno.

En cas de succès, le cookie/cookie de réponse est retourné dans la variable entière non signée de 64 bits spécifiée.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre spécifié est invalide.

-ENODATA

Aucun cookie n'a été attribué à ce message. Cela indique soit que le message n'a pas encore été envoyé et n'a donc pas de cookie attribué, soit que le message n'est pas un message de réponse de méthode et ne porte donc pas de champ de cookie de réponse.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr en multithreading. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à un stade précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_message_get_cookie() et sd_bus_message_get_reply_cookie() ont été ajoutées dans la version 209.
