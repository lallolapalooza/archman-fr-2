SD_EVENT_ADD_INOTIFY(3) sd_event_add_inotify SD_EVENT_ADD_INOTIFY(3)

NOM

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Ajouter une source d'événement de noeud de fichier "inotify" à une boucle d'événements

SYNOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPTION

sd_event_add_inotify() ajoute une nouvelle source d'événement de noeud de fichier inotify(7) à une boucle d'événements. L'objet de boucle d'événements est spécifié dans le paramètre event, l'objet source d'événement est retourné dans le paramètre source. Le paramètre path spécifie le chemin du noeud de fichier à surveiller. Le paramètre mask spécifie quels types d'événements de noeud observer spécifiquement. Il doit contenir une combinaison OR-ée des drapeaux IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, .... Voir inotify(7) pour plus d'informations.

Le paramètre handler doit référencer une fonction à appeler lorsque le noeud change ou NULL. La fonction de gestionnaire sera passée au pointeur userdata, qui peut être choisi librement par l'appelant. Le gestionnaire reçoit également un pointeur vers une structure inotify_event contenant des informations sur l'événement du noeud. Le gestionnaire peut retourner une valeur négative pour signaler une erreur (voir ci-dessous), d'autres valeurs de retour sont ignorées. Si handler est NULL, un gestionnaire par défaut qui appelle sd_event_exit(3) sera utilisé.

sd_event_add_inotify_fd() est identique à sd_event_add_inotify(), sauf qu'il prend un descripteur de fichier vers un noeud (éventuellement un avec O_PATH, mais tout autre fera l'affaire) au lieu d'un chemin dans le système de fichiers.

Si plusieurs sources d'événements sont installées pour le même noeud, le descripteur de surveillance inotify sous-jacent est automatiquement partagé. Le paramètre mask peut contenir n'importe quel drapeau défini par l'API inotify, à l'exception de IN_MASK_ADD.

Le gestionnaire est activé en continu (SD_EVENT_ON), mais cela peut être modifié avec sd_event_source_set_enabled(3). Alternativement, le drapeau de masque IN_ONESHOT peut être utilisé pour demander le mode SD_EVENT_ONESHOT. Si la fonction de gestionnaire retourne un code d'erreur négatif, elle sera désactivée après l'invocation, même si le mode SD_EVENT_ON était demandé auparavant.

Comme limitation spéciale, la priorité des sources d'événements inotify ne peut être modifiée (voir sd_event_source_set_priority(3)) qu'entre la création de l'objet source d'événement avec sd_event_add_inotify() et le début de la prochaine itération de la boucle d'événements. Les tentatives de modification de la priorité ultérieurement seront refusées. Envisagez de libérer et d'allouer une nouvelle source d'événement inotify pour modifier la priorité à ce moment-là.

Pour détruire un objet source d'événement, utilisez sd_event_source_unref(3), mais notez que la source d'événement n'est supprimée de la boucle d'événements que lorsque toutes les références à la source d'événement sont libérées. Pour s'assurer qu'une source d'événement ne se déclenche plus, même si une référence à celle-ci est encore maintenue, envisagez de la désactiver avec sd_event_source_set_enabled(3).

Si le deuxième paramètre de sd_event_add_inotify() est passé en tant que NULL, aucune référence à l'objet source d'événement n'est retournée. Dans ce cas, la source d'événement est considérée comme "flottante" et sera détruite implicitement lorsque la boucle d'événements elle-même sera détruite.

Si le paramètre handler de sd_event_add_inotify() est NULL, et que la source d'événement se déclenche, cela sera considéré comme une demande de sortie de la boucle d'événements. Dans ce cas, le paramètre userdata, converti en entier, est passé comme paramètre de code de sortie à sd_event_exit(3).

sd_event_source_get_inotify_mask() récupère le masque de surveillance inotify configuré d'une source d'événement créée précédemment avec sd_event_add_inotify(). Il prend l'objet source d'événement comme paramètre source et un pointeur vers une variable uint32_t pour y retourner le masque.

sd_event_source_get_inotify_path() récupère le chemin cible de la surveillance inotify configurée d'une source d'événement créée précédemment avec sd_event_add_inotify(). Il prend l'objet source d'événement comme paramètre source et un pointeur vers une variable const char ** pour y retourner le chemin. L'appelant ne doit pas libérer le chemin retourné.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ou un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer un objet.

-EINVAL

Un argument invalide a été passé. Cela inclut la spécification d'un masque avec IN_MASK_ADD défini.

-ESTALE

Retourné par sd_event_source_add_inotify() ou sd_event_source_add_inotify_fd() lorsque la boucle d'événements est déjà terminée. Retourné par sd_event_source_get_inotify_path() lorsqu'aucun donnée de noeud active n'est attribuée à la source d'événement, par exemple, lorsque la source d'événement est désactivée.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

-EDOM

La source d'événement passée n'est pas une source d'événement de processus inotify.

-EBADF

Le descripteur de fichier passé n'est pas valide.

-ENOSYS

sd_event_add_inotify_fd() ou sd_event_source_get_inotify_path() a été appelé sans /proc/ monté.

EXEMPLES

Exemple 1. Un programme simple qui utilise inotify pour surveiller un ou deux répertoires

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <string.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminer le programme si un fichier "exit" apparaît */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}
int main(int argc, char **argv) {
  _cleanup_(sd_event_unrefp) sd_event *event = NULL;
  _cleanup_(sd_event_source_unrefp) sd_event_source *source1 = NULL, *source2 = NULL;
  const char *path1 = argc > 1 ? argv[1] : "/tmp";

sd_event_add_inotify(3) — systemd — Arch Linux

NAME

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path - Add an inotify(7) event source to an event loop

SYNOPSIS

#include <systemd/sd-event.h>

typedef int sd_event_inotify_handler_t(int fd, uint32_t events,
                                       void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source,
                         const char *path, uint32_t events,
                         sd_event_inotify_handler_t *handler, void *userdata);
int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source,
                            int fd, uint32_t events,
                            sd_event_inotify_handler_t *handler, void *userdata);
int sd_event_source_get_inotify_mask(sd_event_source *source,
                                     uint32_t *events);
int sd_event_source_get_inotify_path(sd_event_source *source,
                                     const char **path);

DESCRIPTION

The sd_event_add_inotify() function sets up monitoring of filesystem events (like creation, deletion, or modification of files) in the directory or file specified by path. The events to monitor are specified in the events mask. This mask should be a bitmask of constants defined in <sys/inotify.h>, such as IN_CREATE, IN_DELETE, IN_MODIFY, and IN_MOVED_TO.

The sd_event_add_inotify_fd() function is similar, but instead of a path, it takes an already opened file descriptor fd which must refer to a directory. The fd must have been created using inotify_init(2) or inotify_init1(2).

When one of the specified events occurs in path or on the file descriptor fd, the callback function handler is invoked with the event source structure, the events that occurred, and the arbitrary user data pointer userdata. The handler function should return a positive value to continue the event source, or zero or a negative value to unref and destroy it.

The callback handler receives the events mask as a uint32_t. This is a bitmask of events that occurred for a particular file/directory. Note that inotify_events.h defines event masks using __u32, which might not be directly compatible with uint32_t. The sd_event_add_inotify*() functions handle this conversion.

The specified path argument for sd_event_add_inotify() may be a file or directory. If it's a file, events related to that file will be monitored. If it's a directory, events occurring within that directory will be monitored. For a directory, recursive monitoring is not supported by this interface directly; nested directories must be added separately.

If successful, the newly created event source is stored in the location pointed to by source. If source is NULL, the event source is not returned.

The sd_event_source_get_inotify_mask() function retrieves the event mask that was originally passed to sd_event_add_inotify() or sd_event_add_inotify_fd() for the given event source. The mask is stored in the events parameter.

The sd_event_source_get_inotify_path() function retrieves the path that was originally passed to sd_event_add_inotify(). If the source was created with sd_event_add_inotify_fd(), this function returns NULL. The path is stored in the path parameter.

The event source should be disabled or destroyed using sd_event_source_set_enabled(3) or sd_event_source_unref(3), respectively, when it is no longer needed.

Note that the path argument is copied internally. The caller is still responsible for unlinking the file descriptor if it was not created with sd_event_add_inotify_fd().

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-based error code.

EXAMPLES

#include <stdio.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>

static int inotify_handler(int fd, uint32_t events, void *userdata) {
    printf("Inotify event detected: 0x%x\n", events);
    /*
     * In a real application, you would likely want to read the actual
     * inotify events from the fd. For simplicity, we are just printing
     * the mask provided by sd-event here.
     */
    return 1; /* Continue the event source */
}

int main(int argc, char *argv[]) {
    sd_event *event = NULL;
    sd_event_source *source1 = NULL;
    sd_event_source *source2 = NULL;
    const char *path1 = "/tmp/testdir1";
    const char *path2 = argc > 2 ? argv[2] : NULL;

    /* Note: failure handling is omitted for brevity */
    sd_event_default(&event);

    sd_event_add_inotify(event, &source1, path1,
                       IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO,
                       inotify_handler, NULL);

    if (path2)
        sd_event_add_inotify(event, &source2, path2,
                           IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO,
                           inotify_handler, NULL);

    sd_event_loop(event);

    return 0;
}

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
