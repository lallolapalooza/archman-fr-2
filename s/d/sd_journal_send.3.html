SD_JOURNAL_PRINT(3) sd_journal_print SD_JOURNAL_PRINT(3)

NOM

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, SD_JOURNAL_SUPPRESS_LOCATION, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Soumettre des entrées de journal au journal

SYNOPIS

#include <systemd/sd-journal.h>

int sd_journal_print(int priorité, const char *format, ...);

int sd_journal_printv(int priorité, const char *format, va_list ap);

int sd_journal_send(const char *format, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *message);

int sd_journal_print_with_location(int priorité, const char *fichier, const char *ligne, const char *fonction, const char *format, ...);

int sd_journal_printv_with_location(int priorité, const char *fichier, const char *ligne, const char *fonction, const char *format, va_list ap);

int sd_journal_send_with_location(const char *fichier, const char *ligne, const char *fonction, const char *format, ...);

int sd_journal_sendv_with_location(const char *fichier, const char *ligne, const char *fonction, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *fichier, const char *ligne, const char *fonction, const char *message);

DESCRIPTION

sd_journal_print() peut être utilisé pour soumettre des entrées de journal simples, en texte brut, au journal système. Le premier argument est une valeur de priorité. Celle-ci est suivie d'une chaîne de format et de ses paramètres, similaire à printf(3) ou syslog(3). Notez que le message résultant sera actuellement tronqué à LINE_MAX - 8. La valeur de priorité est l'une des constantes LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, telles que définies dans syslog.h, voir syslog(3) pour plus de détails. Il est recommandé d'utiliser cet appel pour soumettre des messages de journal dans la locale de l'application ou la locale système et au format UTF-8, mais aucune restriction de ce type n'est appliquée. Notez que les messages de journal écrits en utilisant cette fonction ne sont généralement pas censés se terminer par un caractère de nouvelle ligne. Cependant, comme tous les espaces blancs de fin (y compris les espaces, les nouvelles lignes, les tabulations et les retours chariot) sont automatiquement supprimés de la chaîne enregistrée, il est acceptable d'en spécifier un (ou plusieurs). Les lignes vides (après suppression des espaces blancs de fin) sont supprimées. Sur les lignes non vides, les espaces blancs de début (ainsi que les espaces blancs internes) sont laissés inchangés.

sd_journal_printv() est similaire à sd_journal_print() mais prend une liste d'arguments variable encapsulée dans un objet de type va_list (voir stdarg(3) pour plus d'informations) au lieu de la chaîne de format. Il est par ailleurs équivalent en comportement.

sd_journal_send() peut être utilisé pour soumettre des entrées de journal structurées au journal système. Il prend une série de chaînes de format, chacune immédiatement suivie de ses paramètres associés, terminées par NULL. Les chaînes passées doivent être du format "VARIABLE=valeur". Le nom de la variable doit être en majuscules et ne contenir que des lettres, des chiffres et des tirets bas, et ne peut pas commencer par un tiret bas. (Toutes les affectations qui ne suivent pas cette syntaxe seront ignorées.) La valeur peut être de n'importe quelle taille et format. Il est fortement recommandé de soumettre uniquement des chaînes de texte formatées dans le codage de caractères UTF-8, et de soumettre des champs binaires uniquement lorsqu'il n'est pas judicieux de formater en chaînes UTF-8. Un certain nombre de champs bien connus sont définis, voir systemd.journal-fields(7) pour les détails, mais des champs définis par l'application peuvent être utilisés. Une variable peut se voir attribuer plusieurs valeurs par entrée. Si cette fonction est utilisée, les espaces blancs de fin sont automatiquement supprimés de chaque champ formaté.

sd_journal_sendv() est similaire à sd_journal_send() mais prend un tableau de struct iovec (tel que défini dans uio.h, voir readv(3) pour les détails) au lieu de la chaîne de format. Chaque structure doit référencer un champ de l'entrée à soumettre. Le deuxième argument spécifie le nombre de structures dans le tableau. sd_journal_sendv() est particulièrement utile pour soumettre des objets binaires au journal lorsque cela est nécessaire. Notez que cette fonction ne supprime pas les espaces blancs de fin des champs passés, mais transmet les données spécifiées sans modification. Ceci est différent à la fois de sd_journal_print() et de sd_journal_send() décrits ci-dessus, qui sont basés sur des chaînes de format et suppriment les espaces blancs de fin.

sd_journal_perror() est similaire à perror(3) et écrit un message dans le journal qui consiste en la chaîne passée, suffixée par ": " et une représentation lisible par l'homme du code d'erreur actuel stocké dans errno(3). Si la chaîne de message est passée comme NULL ou comme chaîne vide, seule la représentation de la chaîne d'erreur sera écrite, sans rien précéder. Un champ de journal supplémentaire ERRNO= est inclus dans l'entrée contenant le code d'erreur numérique formaté en chaîne décimale. La priorité du journal utilisée est LOG_ERR (3).

Notez que sd_journal_send() est un wrapper autour de sd_journal_sendv() pour faciliter son utilisation lorsque seules des chaînes de texte doivent être soumises. De plus, les deux appels suivants sont largement équivalents :

sd_journal_print(LOG_INFO, "Bonjour le monde, c'est le PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Bonjour le monde, c'est le PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Notez que ces appels ajoutent implicitement des champs pour le fichier source, le nom de la fonction et la ligne de code où ils sont invoqués. Ceci est implémenté avec des macros. Si cela n'est pas souhaité, cela peut être désactivé en définissant SD_JOURNAL_SUPPRESS_LOCATION avant d'inclure sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), et sd_journal_perror_with_location() sont similaires à leurs homologues sans "_with_location", mais acceptent des paramètres supplémentaires pour définir explicitement le nom du fichier source, la fonction et la ligne. Les arguments "fichier" et "ligne" doivent contenir des entrées de journal valides incluant le nom de la variable, par exemple "CODE_FILE=src/foo.c" et "CODE_LINE=666", tandis que "fonction" ne doit contenir que le nom de la fonction, c'est-à-dire la valeur sans "CODE_FUNC=". Ces variantes sont principalement utiles lors de l'écriture d'enveloppes personnalisées, par exemple dans des bindings pour une autre langue.

syslog(3) et sd_journal_print() peuvent être utilisés de manière largement interchangeable en termes de fonctionnalités. Cependant, notez que les messages de journal enregistrés via le premier empruntent un chemin différent vers le serveur de journal que ces derniers, et par conséquent, l'ordre chronologique global entre les deux flux ne peut être garanti. L'utilisation de sd_journal_print() présente l'avantage d'enregistrer la ligne du code source, les noms de fichiers et les fonctions comme métadonnées avec toutes les entrées, et de garantir l'ordre chronologique avec les entrées de journal structurées générées via sd_journal_send(). L'utilisation de syslog() présente l'avantage d'être plus portable.

Ces fonctions implémentent un client du Protocole de Journal Natif[1].

VALEUR DE RETOUR

Les dix fonctions retournent 0 en cas de succès ou un code d'erreur négatif de type errno. La variable errno(3) elle-même

sd_journal_send(3) — systemd — Arch Linux

NAME

sd_journal_send, sd_journal_sendv, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_print, sd_journal_printv, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_perror, sd_journal_perror_with_location – Envoi d'entrées dans le journal système

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_send(const char *...);

int sd_journal_sendv(const struct iovec *iov, int iovcnt);

int sd_journal_print(const char *msg, ...);

int sd_journal_printv(const struct iovec *iov, int iovcnt);

int sd_journal_perror(const char *msg, ...);

int sd_journal_send_with_location(const char *file, const char *line, const char *func, const char *...);

int sd_journal_sendv_with_location(const struct iovec *iov, int iovcnt, const char *file, const char *line, const char *func);

int sd_journal_print_with_location(const char *file, const char *line, const char *func, const char *msg, ...);

int sd_journal_printv_with_location(const struct iovec *iov, int iovcnt, const char *file, const char *line, const char *func);

int sd_journal_perror_with_location(const char *file, const char *line, const char *func, const char *msg, ...);

DESCRIPTION

Ces fonctions permettent d'envoyer des messages au journal système systemd-journald(8). Elles fournissent une interface simple pour l'envoi d'entrées structurées et non structurées.

Les fonctions sd_journal_send* et sd_journal_print* prennent une série d'arguments sous forme de chaînes de caractères, chaque chaîne représentant un champ du journal. Chaque champ est au format CLEF=VALEUR, où CLEF est une chaîne de caractères composée de caractères alphanumériques et de traits de soulignement, et VALEUR est une chaîne de caractères arbitraire. La première chaîne de caractères doit être MESSAGE= pour les fonctions sd_journal_send*, ou elle sera traitée comme une ligne de message simple par les fonctions sd_journal_print*.

La fonction sd_journal_print() est un raccourci pour sd_journal_send("MESSAGE=%s", msg). La fonction sd_journal_perror() est similaire à sd_journal_print(), mais elle ajoute également le message d'erreur système actuel, obtenu via errno(3) et perror(3), au journal.

Les fonctions suffixées par _with_location prennent des arguments supplémentaires file, line et func qui enregistrent l'emplacement dans le code source d'où l'appel a été effectué. Ces informations sont utiles pour le débogage.

Les fonctions sd_journal_sendv() et sd_journal_printv() prennent un tableau de structures iovec pour spécifier les champs du journal. Cela est utile lorsque les champs sont déjà divisés en tampons disjoints.

Si le journal système systemd-journald(8) n'est pas en cours d'exécution (le socket n'est pas présent), ces fonctions ne font rien et retournent 0.

RETURN VALUE

En cas de succès, ces fonctions retournent un entier non négatif. En cas d'échec, elles retournent un code d'erreur négatif.

Les codes d'erreur possibles sont :

  • -ENOMEM : Mémoire insuffisante.
  • -EINVAL : Arguments invalides.
  • -EPROTO : Protocole du journal invalide.
  • -ENXIO : Pas de tel appareil ou adresse.
  • -ECONNREFUSED : Connexion refusée.

Si systemd-journald(8) n'est pas en cours d'exécution (le socket n'est pas présent), ces fonctions ne font rien et retournent 0.

THREAD SAFETY

Toutes les fonctions listées ici sont thread-safe et peuvent être appelées en parallèle à partir de plusieurs threads.

sd_journal_sendv() et sd_journal_sendv_with_location() sont "async signal safe" au sens de signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), et leurs homologues avec "_with_location" ne sont pas async signal safe.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.

HISTORY

sd_journal_perror() a été ajoutée dans la version 188.
