SD_EVENT_NEW(3) sd_event_new SD_EVENT_NEW(3)

NOM

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - Acquérir et libérer un objet de boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

DESCRIPTION

sd_event_new() alloue un nouvel objet de boucle d'événements. L'objet de boucle d'événements est retourné dans le paramètre event. Après utilisation, libérez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est libérée, l'objet est libéré.

sd_event_default() acquiert une référence à l'objet de boucle d'événements par défaut du fil d'exécution appelant, allouant éventuellement un nouvel objet si aucun objet de boucle d'événements par défaut n'a encore été alloué pour le fil d'exécution. Après utilisation, libérez la référence retournée avec sd_event_unref(). Lorsque la dernière référence est libérée, la boucle d'événements est libérée. Si cette fonction est appelée alors que l'objet retourné par un appel précédent du même fil d'exécution est toujours référencé, le même objet est retourné à nouveau, mais la référence est augmentée de un. Il est recommandé d'utiliser cet appel au lieu de sd_event_new() afin de partager les objets de boucle d'événements entre divers composants qui sont distribués dans le même fil d'exécution. Tous les fils d'exécution ont exactement zéro ou un objet de boucle d'événements par défaut associé, mais jamais plus.

Après avoir alloué un objet de boucle d'événements, ajoutez-y des sources d'événements avec sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3), sd_event_add_post(3) ou sd_event_add_exit(3), puis exécutez la boucle d'événements en utilisant sd_event_loop(3).

sd_event_ref() augmente le compteur de références de l'objet de boucle d'événements spécifié de un.

sd_event_unref() diminue le compteur de références de l'objet de boucle d'événements spécifié de un. Si le compteur atteint zéro, l'objet est libéré. Notez qu'il est libéré quel que soit le fait qu'il s'agisse de l'objet de boucle d'événements par défaut d'un fil d'exécution ou non. Cela signifie qu'allouer une boucle d'événements avec sd_event_default(), puis la libérer, puis en acquérir une nouvelle avec sd_event_default() entraînera deux objets distincts. Notez que pour libérer un objet de boucle d'événements, toutes les sources d'événements restantes de la boucle d'événements doivent également être libérées car chacune conserve une référence à elle.

sd_event_unrefp() est similaire à sd_event_unref() mais prend un pointeur vers un pointeur vers un objet sd_event. Cet appel est utile en conjonction avec l'attribut de variable Clean-up de GCC et LLVM[1]. Notez que cette fonction est définie comme une fonction inline. Utilisez une déclaration comme suit, afin d'allouer un objet de boucle d'événements qui sera automatiquement libéré à la sortie du bloc de code :

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Échec de l'allocation de la boucle d'événements : %m\n");
        }
        ...
}

sd_event_ref(), sd_event_unref() et sd_event_unrefp() n'effectuent aucune opération si l'objet de boucle d'événements passé est NULL.

sd_event_get_tid() récupère l'identifiant du fil d'exécution ("TID") du fil d'exécution auquel l'objet de boucle d'événements spécifié est associé. Cet appel n'est pris en charge que pour les boucles d'événements allouées avec sd_event_default(), et retourne l'identifiant du fil d'exécution dont la boucle d'événements est la boucle d'événements par défaut. Voir gettid(2) pour plus d'informations sur les identifiants de fil d'exécution.

VALEUR DE RETOUR

En cas de succès, sd_event_new(), sd_event_default() et sd_event_get_tid() retournent 0 ou un entier positif. En cas d'échec, ils retournent un code d'erreur négatif de style errno. sd_event_ref() retourne toujours un pointeur vers l'objet de boucle d'événements passé. sd_event_unref() retourne toujours NULL.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ENOMEM

Pas assez de mémoire pour allouer l'objet.

-EMFILE

Le nombre maximum de boucles d'événements a été alloué.

-ENXIO

sd_event_get_tid() a été invoqué sur un objet de boucle d'événements qui n'a pas été alloué avec sd_event_default().

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme lorsque aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_event_new(), sd_event_default(), sd_event_ref() et sd_event_unref() ont été ajoutés dans la version 213.

sd_event_unrefp() et sd_event_get_tid() ont été ajoutés dans la version 229.
