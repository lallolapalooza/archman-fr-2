SD_JOURNAL_GET_DATA(3) sd_journal_get_data SD_JOURNAL_GET_DATA(3)

NOM

sd_journal_get_data, sd_journal_enumerate_data, sd_journal_enumerate_available_data, sd_journal_restart_data, SD_JOURNAL_FOREACH_DATA, sd_journal_set_data_threshold, sd_journal_get_data_threshold - Lire les champs de données de l'entrée du journal actuelle

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_get_data(sd_journal *j, const char *field, const void **data, size_t *length);

int sd_journal_enumerate_data(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_available_data(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_data(sd_journal *j);

SD_JOURNAL_FOREACH_DATA(sd_journal *j, const void *data, size_t length);

int sd_journal_set_data_threshold(sd_journal *j, size_t sz);

int sd_journal_get_data_threshold(sd_journal *j, size_t *sz);

DESCRIPTION

sd_journal_get_data() obtient l'objet de données associé à un champ spécifique de l'entrée du journal actuelle. Il prend quatre arguments : l'objet de contexte du journal, une chaîne avec le nom du champ à demander, plus une paire de pointeurs vers des variables pointeur/taille où l'objet de données et sa taille doivent être stockés. Le nom du champ doit être un nom de champ d'entrée. Les noms de champs bien connus sont listés dans systemd.journal-fields(7), mais tout champ peut être spécifié. Les données retournées sont dans une carte mémoire en lecture seule et ne sont valides que jusqu'à la prochaine invocation de sd_journal_get_data(), sd_journal_enumerate_data(), sd_journal_enumerate_available_data(), ou lorsque le pointeur de lecture est modifié. Notez que les données retournées seront précédées du nom du champ et de "=". Notez également que, par défaut, les champs de données plus grands que 64 Ko peuvent être tronqués à 64 Ko. Ce seuil peut être modifié et désactivé avec sd_journal_set_data_threshold() (voir ci-dessous).

sd_journal_enumerate_data() peut être utilisé pour parcourir tous les champs de l'entrée actuelle. À chaque invocation, les données du champ suivant sont retournées. L'ordre de ces champs n'est pas défini. Les données retournées sont dans le même format qu'avec sd_journal_get_data() et suivent également les mêmes sémantiques de durée de vie.

sd_journal_enumerate_available_data() est similaire à sd_journal_enumerate_data(), mais ignore silencieusement tous les champs qui peuvent être valides, mais sont trop grands ou non pris en charge par l'implémentation actuelle.

sd_journal_restart_data() réinitialise l'index d'énumération des données au début de l'entrée. La prochaine invocation de sd_journal_enumerate_data() retournera à nouveau le premier champ de l'entrée.

Notez que la macro SD_JOURNAL_FOREACH_DATA() peut être utilisée comme un wrapper pratique autour de sd_journal_restart_data() et sd_journal_enumerate_available_data().

Notez que ces fonctions ne fonctionneront pas avant que sd_journal_next(3) (ou un appel connexe) n'ait été appelé au moins une fois, afin de positionner le pointeur de lecture sur une entrée valide.

sd_journal_set_data_threshold() peut être utilisé pour modifier le seuil de taille des champs de données pour les données retournées par sd_journal_get_data(), sd_journal_enumerate_data() et sd_journal_enumerate_unique(). Ce seuil est une indication seulement : il indique que le programme client ne s'intéresse qu'aux parties initiales des champs de données, jusqu'au seuil en taille — mais la bibliothèque peut quand même retourner des objets de données plus grands. Cela signifie que les applications ne doivent pas se fier exclusivement à ce paramètre pour limiter la taille des champs de données retournés, mais doivent également appliquer une limite de taille explicite sur les données retournées. Ce seuil est de 64 Ko par défaut. Pour récupérer les champs de données complets, ce seuil doit être désactivé en le réglant à 0, de sorte que la bibliothèque retourne toujours les objets de données complets. Il est recommandé de régler ce seuil aussi bas que possible car cela évite à la bibliothèque de devoir décompresser de grands objets de données compressés en totalité.

sd_journal_get_data_threshold() retourne le seuil de taille des champs de données actuellement configuré.

VALEUR DE RETOUR

sd_journal_get_data() retourne 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_enumerate_data() et sd_journal_enumerate_available_data() retournent un entier positif si le champ suivant a été lu, 0 lorsqu'aucun champ ne reste, ou un code d'erreur négatif de style errno. sd_journal_restart_data() ne retourne rien. sd_journal_set_data_threshold() et sd_journal_get_threshold() retournent 0 en cas de succès ou un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un des paramètres requis est NULL ou invalide.

Ajouté dans la version 246.

-ECHILD

L'objet journal a été créé dans un processus, une bibliothèque ou une instance de module différente.

Ajouté dans la version 246.

-EADDRNOTAVAIL

Le pointeur de lecture n'est pas positionné sur une entrée valide ; sd_journal_next(3) ou un appel connexe n'a pas été appelé au moins une fois.

Ajouté dans la version 246.

-ENOENT

L'entrée actuelle n'inclut pas le champ spécifié.

Ajouté dans la version 246.

-ENOMEM

Échec de l'allocation mémoire.

Ajouté dans la version 246.

-ENOBUFS

Une entrée compressée est trop volumineuse.

Ajouté dans la version 246.

-E2BIG

Le champ de données est trop volumineux pour cette architecture informatique (par exemple, supérieur à 4 Go sur une architecture 32 bits).

Ajouté dans la version 246.

-EPROTONOSUPPORT

Le journal est compressé avec une méthode non prise en charge ou le journal utilise une fonctionnalité non prise en charge.

Ajouté dans la version 246.

-EBADMSG

Le journal est corrompu (peut-être seulement l'entrée en cours d'itération).

Ajouté dans la version 246.

-EIO

Une erreur d'E/S a été signalée par le noyau.

Ajouté dans la version 246.

NOTES

Toutes les fonctions décrites ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à la fois. Différents threads peuvent accéder au même objet à différents moments. Plusieurs objets indépendants peuvent être utilisés par différents threads en parallèle.

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

EXEMPLES

Voir sd_journal_next(3) pour un exemple complet sur l'utilisation de sd_journal_get_data().

Utilisez la macro SD_JOURNAL_FOREACH_DATA() pour parcourir tous les champs de l'entrée du journal actuelle :

...
int print_fields(sd_journal *j) {
  const void *data;
  size_t length;
  SD_JOURNAL_FOREACH_DATA(j, data, length)
    printf("%.*s\n", (int) length, data);
}
...

HISTORIQUE

sd_journal_get_data(), sd_journal_enumerate_data(), sd_journal_restart_data() et SD_JOURNAL_FOREACH_DATA() ont été ajoutés dans la version 187.

sd_journal_set_data_threshold() et sd_journal_get_data_threshold() ont été ajoutés dans la version 196.

sd_journal_enumerate_available_data() a été ajouté dans la version 246.
