sd_event_source_set_enabled(3)

SD_EVENT_SOURCE_SET_ENABLED(3) sd_event_source_set_enabled SD_EVENT_SOURCE_SET_ENABLED(3)

NOM

sd_event_source_set_enabled, sd_event_source_get_enabled, SD_EVENT_ON, SD_EVENT_OFF, SD_EVENT_ONESHOT - Activer ou désactiver des sources d'événements

SYNTAXE

#include <systemd/sd-event.h>
enum {
        SD_EVENT_OFF = 0,
        SD_EVENT_ON = 1,
        SD_EVENT_ONESHOT = -1,
};

int sd_event_source_set_enabled(sd_event_source *source, int enabled);

int sd_event_source_get_enabled(sd_event_source *source, int *ret);

DESCRIPTION

sd_event_source_set_enabled() peut être utilisée pour activer ou désactiver l'objet source d'événement spécifié par source. Le paramètre enabled prend l'une des valeurs SD_EVENT_ON (pour activer), SD_EVENT_OFF (pour désactiver) ou SD_EVENT_ONESHOT. Si elle est appelée avec SD_EVENT_ONESHOT, la source d'événement sera activée mais sera automatiquement réinitialisée à SD_EVENT_OFF après une seule invocation. Pour SD_EVENT_OFF, la source d'événement source peut être NULL, auquel cas la fonction ne fait rien. Sinon, source doit être un pointeur valide vers un objet sd_event_source.

Les sources d'événements désactivées ne provoqueront pas de réveils de la boucle d'événements et ne seront pas invoquées tant qu'elles ne seront pas réactivées.

sd_event_source_get_enabled() peut être utilisée pour interroger si l'objet source d'événement source est actuellement activé ou non. Si à la fois source et le paramètre de sortie ret sont NULL, cette fonction retourne false. Sinon, source doit être un pointeur valide vers un objet sd_event_source. Si le paramètre de sortie ret n'est pas NULL, il est défini à l'état d'activation (l'une des valeurs SD_EVENT_ON, SD_EVENT_OFF, SD_EVENT_ONESHOT). La fonction retourne également true si la source d'événement n'est pas désactivée.

Les objets sources d'événements sont activés lorsqu'ils sont créés pour la première fois avec des appels tels que sd_event_add_io(3), sd_event_add_time(3). Cependant, selon le type de source d'événement, elles sont activées en continu (SD_EVENT_ON) ou seulement pour une seule invocation du gestionnaire de source d'événement (SD_EVENT_ONESHOT). Pour plus de détails, consultez les pages de manuel respectives.

Comme les objets sources d'événements restent actifs et peuvent être invoqués tant qu'il y a au moins une référence à eux, dans de nombreux cas, il est conseillé de combiner un appel à sd_event_source_unref(3) avec un appel précédent à sd_event_source_set_enabled() avec SD_EVENT_OFF, pour s'assurer que la source d'événement n'est pas invoquée à nouveau tant que toutes les autres références restantes ne sont pas supprimées.

VALEUR DE RETOUR

En cas de succès, sd_event_source_set_enabled() retourne un entier non négatif. sd_event_source_get_enabled() retourne zéro si la source est désactivée (SD_EVENT_OFF) et un entier positif sinon. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

source n'est pas un pointeur valide vers un objet sd_event_source.

-ENOMEM

Pas assez de mémoire.

-ECHILD

La boucle d'événements a été créée dans un processus, une bibliothèque ou une instance de module différente.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme, lorsqu'aucun autre thread n'a encore été démarré.

HISTORIQUE

sd_event_source_set_enabled() et sd_event_source_get_enabled() ont été ajoutées dans la version 229.
