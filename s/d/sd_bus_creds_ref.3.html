SD_BUS_CREDS_NEW_FROM_PID(3) sd_bus_creds_new_from_pid SD_BUS_CREDS_NEW_FROM_PID(3)

NAME

sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Récupérer un objet d'informations d'identification pour le PID spécifié

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_creds_new_from_pid(pid_t pid, uint64_t creds_mask, sd_bus_creds **ret);

int sd_bus_creds_new_from_pidfd(int pidfd, uint64_t creds_mask, sd_bus_creds **ret);

uint64_t sd_bus_creds_get_mask(sd_bus_creds *c);

uint64_t sd_bus_creds_get_augmented_mask(sd_bus_creds *c);

sd_bus_creds *sd_bus_creds_ref(sd_bus_creds *c);

sd_bus_creds *sd_bus_creds_unref(sd_bus_creds *c);

void sd_bus_creds_unrefp(sd_bus_creds **c);

SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, SD_BUS_CREDS_PIDFD, SD_BUS_CREDS_AUGMENT, _SD_BUS_CREDS_ALL

DESCRIPTION

sd_bus_creds_new_from_pid() crée un nouvel objet d'informations d'identification et le remplit avec des informations sur le processus pid. Le pointeur vers cet objet sera stocké dans le pointeur ret. Notez que les objets d'informations d'identification peuvent également être créés et récupérés via sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) et sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() est identique à sd_bus_creds_new_from_pid(), mais prend un descripteur de fichier PID plutôt qu'un PID numérique comme référence au processus. Voir pidfd_open(2).

Les informations qui seront stockées sont déterminées par creds_mask. Il peut contenir un sous-ensemble de constantes ORées SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, et SD_BUS_CREDS_PIDFD. Utilisez la valeur spéciale **_SD_BUS_CREDS_ALL** pour demander tous les champs pris en charge. La constante **SD_BUS_CREDS_AUGMENT** ne peut pas être ORée dans le masque pour les appels à sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd().

Les champs peuvent être récupérés à partir de l'objet d'informations d'identification à l'aide de sd_bus_creds_get_pid(3) et d'autres fonctions qui correspondent directement aux constantes énumérées ci-dessus.

Un masque des champs qui ont été effectivement récupérés avec succès peut être obtenu avec sd_bus_creds_get_mask(). Si l'objet d'informations d'identification a été créé avec sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce sera un sous-ensemble des champs demandés dans creds_mask.

Similaire à sd_bus_creds_get_mask(), la fonction sd_bus_creds_get_augmented_mask() renvoie un masque de bits des constantes de champs. Le masque indique quels champs d'informations d'identification ont été récupérés de manière non atomique. Pour les objets d'informations d'identification créés via sd_bus_creds_new_from_pid() ou sd_bus_creds_new_from_pidfd(), ce masque sera identique au masque renvoyé par sd_bus_creds_get_mask(). Cependant, pour les objets d'informations d'identification récupérés via sd_bus_get_name_creds(), ce masque sera défini pour les champs d'informations d'identification qui n'ont pas pu être déterminés atomiquement au moment de la connexion de l'homologue, et qui ont été ultérieurement ajoutés en lisant des données d'informations d'identification supplémentaires depuis /proc/. De même, pour les objets d'informations d'identification récupérés via sd_bus_get_owner_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés atomiquement au moment de la création du bus, mais qui ont été augmentés. De même, pour les objets d'informations d'identification récupérés via sd_bus_message_get_creds(), le masque est défini pour les champs qui n'ont pas pu être déterminés atomiquement au moment de l'envoi du message, mais qui ont été augmentés. Le masque renvoyé par sd_bus_creds_get_augmented_mask() est toujours un sous-ensemble de (ou identique à) le masque renvoyé par sd_bus_creds_get_mask() pour le même objet. Le dernier appel renvoie donc tous les champs d'informations d'identification disponibles dans l'objet d'informations d'identification, le premier marquant alors le sous-ensemble de ceux qui ont été augmentés. Notez que les champs augmentés ne conviennent pas aux décisions d'autorisation, car ils peuvent être récupérés à différents moments, étant ainsi sujets à des courses. Par conséquent, les champs augmentés ne doivent être utilisés qu'à des fins d'information.

sd_bus_creds_ref() crée une nouvelle référence à l'objet d'informations d'identification c. Cet objet ne sera pas détruit tant que sd_bus_creds_unref() n'aura pas été appelé autant de fois plus une fois. Une fois que le compteur de références est tombé à zéro, c ne peut plus être utilisé, donc les appels ultérieurs à sd_bus_creds_ref(c) ou sd_bus_creds_unref(c) sont illégaux.

sd_bus_creds_unref() détruit une référence à c.

sd_bus_creds_unrefp() est similaire à sd_bus_creds_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_creds. Cette fonction est utile en conjonction avec l'attribut de variable Clean-up[1] de GCC et LLVM. Notez que cette fonction est définie comme une fonction inline.

sd_bus_creds_ref(), sd_bus_creds_unref() et sd_bus_creds_unrefp() n'exécutent aucune opération si l'objet d'informations d'identification du bus passé est NULL.

RETURN VALUE

En cas de succès, sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() renvoient 0 ou un entier positif. En cas d'échec, ils renvoient un code d'erreur négatif de type errno.

sd_bus_creds_get_mask() renvoie le masque des champs acquis avec succès.

sd_bus_creds_get_augmented_mask() renvoie le masque des champs qui ont été augmentés à partir des données dans /proc/, et ne sont donc pas appropriés pour les décisions d'autorisation.

sd_bus_creds_ref() renvoie toujours l'argument.

sd_bus_creds_unref() renvoie toujours NULL.

REFERENCE OWNERSHIP

Les fonctions sd_bus_creds_new_from_pid() et sd_bus_creds_new_from_pidfd() créent un nouvel objet et l'appelant possède la référence unique. Lorsque ce n'est plus nécessaire, cette référence doit être détruite avec sd_bus_creds_unref(3).

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-ESRCH

Le pid spécifié n'a pas pu être trouvé.

-EACCES

L'accès aux informations d'identification demandées a été refusé. Cela peut se produire si le processus appelant n'a pas les autorisations nécessaires pour lire les informations d'identification d'un autre processus.

-ENOENT

Le fichier pidfd spécifié n'a pas pu être trouvé ou n'est pas un descripteur de fichier PID valide.

-ENOMEM

Mémoire insuffisante pour allouer l'objet d'informations d'identification.

-EFAULT

Un pointeur invalide a été passé.

-EINVAL

Un argument invalide a été passé.

-EPERM

L'opération a échoué parce que le processus actuel n'a pas les privilèges nécessaires pour accéder aux informations d'identification demandées (par exemple, pour lire le contexte SELinux).

-EBADF

Le descripteur de fichier pidfd n'est pas un descripteur de fichier valide.

-EINPROGRESS

La lecture des informations d'identification prend du temps et est toujours en cours.

sd_bus_creds_ref(3) - systemd library manual

NAME

sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Incremental reference counting for credentials structures

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_creds_ref(sd_bus_creds *creds);
void sd_bus_creds_unref(sd_bus_creds *creds);
void sd_bus_creds_unrefp(sd_bus_creds **creds_p);

DESCRIPTION

The sd_bus_creds_ref() function increments the reference counter of the sd_bus_creds object creds.

The sd_bus_creds_unref() function decrements the reference counter of the sd_bus_creds object creds. If the reference counter drops to zero, the object is deallocated.

The sd_bus_creds_unrefp() function is similar to sd_bus_creds_unref(), but takes a pointer to a pointer to a sd_bus_creds object. This allows you to atomically decrement the reference count and set the pointer to NULL. If creds_p is NULL or if the pointer it points to is NULL, this function does nothing.

These functions are useful for managing the lifetime of sd_bus_creds objects returned by other bus API calls.

REFERENCE OWNERSHIP

The caller takes ownership of any sd_bus_creds object on which sd_bus_creds_ref() has been called. The caller must later call sd_bus_creds_unref() or sd_bus_creds_unrefp() to release the reference. Ownership is *not* transferred when sd_bus_creds_unref() is called.

When a function returns a sd_bus_creds object (e.g. sd_bus_get_name_creds()), it is usually a new object with a reference count of 1. The caller then takes ownership of this reference.

When a function takes a pointer to a pointer to a sd_bus_creds object (e.g. sd_bus_process_exit_with_code()), it might take ownership of the object passed in, and the caller should not use it anymore after the call. Check the documentation of the specific function for details.

RETURN VALUE

On success, sd_bus_creds_ref() returns 0 or a positive integer. On failure, it returns a negative error number.

Possible error numbers are:

-EINVAL

A NULL pointer was passed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_bus_creds_new_from_pid(), sd_bus_creds_get_mask(), sd_bus_creds_ref(), sd_bus_creds_unref(), and sd_bus_creds_get_augmented_mask() were added in version 221.

sd_bus_creds_unrefp() was added in version 229.

sd_bus_creds_new_from_pidfd() was added in version 256.
