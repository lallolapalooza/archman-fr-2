SD_BUS_CALL(3) sd_bus_call SD_BUS_CALL(3)

NOM

sd_bus_call, sd_bus_call_async - Invocation d'un appel de méthode D-Bus

SYNTAXE

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_call(sd_bus *bus, sd_bus_message *m, uint64_t usec, sd_bus_error *ret_error, sd_bus_message **reply);

int sd_bus_call_async(sd_bus *bus, sd_bus_slot **slot, sd_bus_message *m, sd_bus_message_handler_t callback, void *userdata, uint64_t usec);

DESCRIPTION

sd_bus_call() prend un objet message de bus complet et appelle la méthode D-Bus correspondante. En cas de succès, la réponse est stockée dans reply. usec indique le délai d'attente en microsecondes. Si ret_error n'est pas NULL et que sd_bus_call() échoue (soit en raison d'une erreur interne, soit parce qu'il a reçu une réponse d'erreur D-Bus), ret_error est initialisé avec une instance de sd_bus_error décrivant l'erreur.

sd_bus_call_async() est similaire à sd_bus_call() mais fonctionne de manière asynchrone. Le callback indique la fonction à appeler lorsque la réponse arrive. Le pointeur userdata sera passé à la fonction de rappel, et peut être choisi librement par l'appelant. Si slot n'est pas NULL et que sd_bus_call_async() réussit, slot est défini sur un objet slot qui peut être utilisé pour annuler l'appel de méthode plus tard en utilisant sd_bus_slot_unref(3). Si slot est NULL, la durée de vie de l'appel de méthode est liée à la durée de vie de l'objet bus lui-même, et elle ne peut pas être annulée indépendamment. Voir sd_bus_slot_set_floating(3) pour plus de détails. callback est appelé lorsqu'une réponse arrive avec le message de réponse, userdata et un paramètre de sortie sd_bus_error comme arguments. Contrairement à sd_bus_call(), le paramètre de sortie sd_bus_error passé au rappel sera vide. Pour déterminer si l'appel de méthode a réussi, utilisez sd_bus_message_is_method_error(3) sur le message de réponse passé au rappel à la place. Si le rappel retourne zéro et que le paramètre de sortie sd_bus_error est toujours vide à la fin du rappel, d'autres gestionnaires enregistrés avec des fonctions telles que sd_bus_add_filter(3) ou sd_bus_add_match(3) ont la possibilité de traiter le message. Si le rappel retourne une valeur non nulle ou si le paramètre de sortie sd_bus_error n'est pas vide à la fin du rappel, aucun autre traitement du message n'est effectué. Généralement, vous voulez retourner zéro du rappel pour donner aux autres gestionnaires enregistrés la possibilité de traiter la réponse également. (Notez que le paramètre sd_bus_error est un paramètre de sortie de la fonction de rappel, pas un paramètre d'entrée ; il peut être utilisé pour propager des erreurs du gestionnaire de rappel, il ne recevra aucune erreur qui aurait été reçue en tant que réponse de méthode.)

Le message m passé au rappel n'est que référencé, c'est-à-dire que le rappel ne doit pas appeler sd_bus_message_unref(3) dessus. Si le rappel souhaite conserver le message au-delà de la durée de vie du rappel, il doit appeler sd_bus_message_ref(3) pour créer une nouvelle référence.

Si usec est zéro, le délai d'attente par défaut pour les appels de méthode D-Bus est utilisé. Voir sd_bus_get_method_call_timeout(3).

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier positif. En cas d'échec, elles retournent un code d'erreur négatif de type errno.

Erreurs

Lorsque sd_bus_call() reçoit une réponse d'erreur D-Bus en interne, il définit ret_error s'il n'est pas NULL, et retourne une valeur négative mappée à partir de la réponse d'erreur, voir sd_bus_error_get_errno(3).

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre d'entrée m est NULL.

Le paramètre d'entrée m n'est pas un appel de méthode D-Bus. Pour créer un nouvel appel de méthode D-Bus, utilisez sd_bus_message_new_method_call(3).

Le paramètre d'entrée m a le drapeau BUS_MESSAGE_NO_REPLY_EXPECTED défini.

Le paramètre d'entrée error n'est pas NULL mais n'a pas été défini sur SD_BUS_ERROR_NULL.

-ECHILD

La connexion de bus a été allouée dans un processus parent et est réutilisée dans un processus enfant après fork().

-ENOTCONN

Le paramètre d'entrée bus est NULL ou le bus n'est pas connecté.

-ECONNRESET

La connexion de bus a été fermée en attendant la réponse.

-ETIMEDOUT

Une réponse n'a pas été reçue dans le délai imparti.

-ELOOP

Le message m est adressé à son propre client.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() que dès la phase initiale du programme, lorsque aucun autre fil d'exécution n'a été démarré.

HISTORIQUE

sd_bus_call() et sd_bus_call_async() ont été ajoutés dans la version 221.

sd_bus_call(3)

NAME SYNOPSIS DESCRIPTION RETURN VALUE NOTES SEE ALSO

NAME

sd_bus_call, sd_bus_call_method, sd_bus_call_methodv, sd_bus_call_get_property, sd_bus_call_set_property, sd_bus_call_async, sd_bus_call_method_async, sd_bus_call_get_property_async, sd_bus_call_set_property_async, sd_bus_process_event, sd_bus_wait, sd_bus_flush_messages — Connect to the system or user message bus and send/receive messages

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_call(sd_bus *bus, const char *destination, const char *path,
                const char *interface, const char *member, sd_bus_error *error,
                const char *types, ...);
int sd_bus_call_method(sd_bus *bus, const char *destination, const char *path,
                       const char *interface, const char *member, sd_bus_error *error,
                       sd_bus_message **reply, const char *types, ...);
int sd_bus_call_methodv(sd_bus *bus, const char *destination, const char *path,
                        const char *interface, const char *member, sd_bus_error *error,
                        sd_bus_message **reply, const char *types, va_list args);
int sd_bus_call_get_property(sd_bus *bus, const char *destination, const char *path,
                             const char *interface, const char *property, sd_bus_error *error,
                             sd_bus_message **reply);
int sd_bus_call_set_property(sd_bus *bus, const char *destination, const char *path,
                             const char *interface, const char *property, sd_bus_error *error,
                             sd_bus_message **reply, const char *types, ...);
int sd_bus_call_async(sd_bus *bus, sd_bus_slot **slot, const char *destination,
                      const char *path, const char *interface, const char *member,
                      sd_bus_error *error, sd_bus_message_handler_t callback,
                      void *userdata, const char *types, ...);
int sd_bus_call_method_async(sd_bus *bus, sd_bus_slot **slot, const char *destination,
                             const char *path, const char *interface, const char *member,
                             sd_bus_error *error, sd_bus_message_handler_t callback,
                             void *userdata, const char *types, ...);
int sd_bus_call_get_property_async(sd_bus *bus, sd_bus_slot **slot, const char *destination,
                                   const char *path, const char *interface, const char *property,
                                   sd_bus_error *error, sd_bus_message_handler_t callback,
                                   void *userdata);
int sd_bus_call_set_property_async(sd_bus *bus, sd_bus_slot **slot, const char *destination,
                                   const char *path, const char *interface, const char *property,
                                   sd_bus_error *error, sd_bus_message_handler_t callback,
                                   void *userdata, const char *types, ...);
int sd_bus_process_event(sd_bus *bus);
int sd_bus_wait(sd_bus *bus, uint64_t usec);
int sd_bus_flush_messages(sd_bus *bus);

DESCRIPTION

These functions may be used to send messages to the D-Bus message bus system and receive replies.

sd_bus_call(), sd_bus_call_method(), sd_bus_call_get_property(), and sd_bus_call_set_property() are synchronous calls. They send a message, wait for a reply, and return it.

sd_bus_call_methodv() is similar to sd_bus_call_method() but takes a va_list of arguments instead of a variable argument list.

sd_bus_call_async(), sd_bus_call_method_async(), sd_bus_call_get_property_async(), and sd_bus_call_set_property_async() are asynchronous calls. They send a message and return immediately. A callback function is invoked when a reply is received or an error occurs.

sd_bus_process_event() processes pending events on the bus. This should be called periodically when using asynchronous calls.

sd_bus_wait() waits for events on the bus for a specified amount of time. This is useful for blocking loops.

sd_bus_flush_messages() flushes any pending outgoing messages on the bus.

RETURN VALUE

On success, these functions return 0 or a positive value. On failure, they return a negative error number. If an error occurs during the communication with the bus daemon, the error parameter will be filled with details about the error.

NOTES

The types parameter is a string that specifies the types of the arguments to be sent with the message. It follows the D-Bus type system notation.

For asynchronous calls, the callback function should have the following signature: int callback(sd_bus_message *m, void *userdata, sd_bus_error *error).
