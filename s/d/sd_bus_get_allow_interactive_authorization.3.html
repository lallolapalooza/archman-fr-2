SD_BUS_SET_DESCRIPTION(3) sd_bus_set_description SD_BUS_SET_DESCRIPTION(3)

NOM

sd_bus_set_description, sd_bus_get_description, sd_bus_set_anonymous, sd_bus_is_anonymous, sd_bus_set_trusted, sd_bus_is_trusted, sd_bus_set_allow_interactive_authorization, sd_bus_get_allow_interactive_authorization, sd_bus_get_scope, sd_bus_get_tid, sd_bus_get_unique_name - Définir ou interroger les propriétés d'un objet bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_description(sd_bus *bus, const char *description);

int sd_bus_get_description(sd_bus *bus, const char **description);

int sd_bus_set_anonymous(sd_bus *bus, int b);

int sd_bus_is_anonymous(sd_bus *bus);

int sd_bus_set_trusted(sd_bus *bus, int b);

int sd_bus_is_trusted(sd_bus *bus);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, int b);

int sd_bus_get_allow_interactive_authorization(sd_bus *bus);

int sd_bus_get_scope(sd_bus *bus, const char **scope);

int sd_bus_get_tid(sd_bus *bus, pid_t *tid);

int sd_bus_get_unique_name(sd_bus *bus, const char **unique);

DESCRIPTION

sd_bus_set_description() définit la chaîne de description utilisée dans les journaux sur la chaîne spécifiée. La chaîne est copiée en interne et libérée lorsque l'objet bus est désalloué. L'argument description peut être NULL, auquel cas la description est désactivée. Cette fonction doit être appelée avant le démarrage du bus.

sd_bus_get_description() renvoie une chaîne de description dans description. Cette chaîne peut avoir été préalablement définie avec sd_bus_set_description() ou sd_bus_open_with_description(3) ou des fonctions similaires. Si elle n'est pas définie ainsi, une chaîne par défaut comme "system" ou "user" sera renvoyée pour les bus système ou utilisateur, et -ENXIO sinon.

sd_bus_set_anonymous() active ou désactive l'"authentification anonyme", c'est-à-dire l'absence d'authentification, du pair de bus. Cette fonction doit être appelée avant le démarrage du bus. Voir la section **Mécanismes d'authentification D-Bus**[1] de la spécification D-Bus pour plus de détails.

sd_bus_is_anonymous() renvoie vrai si la connexion bus autorise l'authentification anonyme (au sens décrit au paragraphe précédent).

sd_bus_set_trusted() définit l'état "de confiance" sur l'objet bus. Si vrai, toutes les connexions sur le bus sont considérées de confiance et l'accès à toutes les méthodes privilégiées et non privilégiées est accordé. Cette fonction doit être appelée avant le démarrage du bus.

sd_bus_is_trusted() renvoie vrai si la connexion bus est de confiance (au sens décrit au paragraphe précédent).

sd_bus_set_allow_interactive_authorization() active ou désactive l'autorisation interactive pour les appels de méthode. Si vrai, les messages sont marqués avec le drapeau **ALLOW_INTERACTIVE_AUTHORIZATION** spécifié par la spécification D-Bus[2], informant le côté récepteur que l'appelant est prêt à attendre une autorisation interactive, ce qui peut prendre un temps considérable à compléter. Si ce drapeau est défini, l'utilisateur peut être invité à entrer des mots de passe ou une confirmation via polkit[3] ou un framework similaire.

sd_bus_get_allow_interactive_authorization() renvoie vrai si l'autorisation interactive est autorisée et faux sinon.

sd_bus_get_scope() stocke la portée de l'objet bus donné dans scope. La portée du bus système est "system". La portée d'un bus de session utilisateur est "user". Si l'objet bus donné n'est pas le bus système ou un bus de session utilisateur, sd_bus_get_scope() renvoie une erreur.

sd_bus_get_tid() stocke l'identifiant du thread du noyau associé à l'objet bus donné dans tid. Si bus est un objet bus par défaut obtenu en appelant une des fonctions de la famille sd_bus_default(3), il stocke l'identifiant du thread dans lequel l'objet bus a été créé. Sinon, si l'objet bus est attaché à une boucle d'événements, il stocke l'identifiant du thread dans lequel l'objet boucle d'événements a été créé. Si bus n'est pas un objet bus par défaut et n'est pas attaché à une boucle d'événements, sd_bus_get_tid() renvoie une erreur.

sd_bus_get_unique_name() stocke le nom unique de l'objet bus sur le bus dans unique. Voir **La spécification D-Bus**[4] pour plus d'informations sur les noms de bus. Notez que l'appelant ne possède pas la chaîne stockée dans unique et ne doit pas la libérer.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un entier positif ou nul. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un argument est invalide.

-ENOPKG

Le bus ne peut pas être résolu.

-EPERM

Le bus a déjà été démarré.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

-ENOMEM

Échec de l'allocation mémoire.

-ENODATA

L'objet bus passé à sd_bus_get_scope() n'était ni un bus système ni un bus de session utilisateur.

Ajouté dans la version 246.

-ENXIO

L'objet bus passé à sd_bus_get_tid() n'était pas un objet bus par défaut et n'est pas attaché à une boucle d'événements.

L'objet bus passé à sd_bus_get_description() n'avait pas de description.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme non sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_is_anonymous(), sd_bus_is_trusted(), sd_bus_get_scope(), sd_bus_get_tid(), et sd_bus_get_unique_name() ont été ajoutées dans la version 246.

sd_bus_get_allow_interactive_authorization.3.en

sd_bus_get_allow_interactive_authorization

sd_bus_get_allow_interactive_authorization, sd_bus_set_allow_interactive_authorization - Obtenir et définir le comportement d'autorisation interactive d'un bus D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_get_allow_interactive_authorization(sd_bus *bus, bool *allow_interactive_authorization);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, bool allow_interactive_authorization);

DESCRIPTION

La fonction sd_bus_get_allow_interactive_authorization() récupère le réglage actuel de l'autorisation interactive pour le bus D-Bus donné par bus. La valeur est stockée dans la variable booléenne pointée par allow_interactive_authorization.

La fonction sd_bus_set_allow_interactive_authorization() définit l'autorisation interactive pour le bus D-Bus donné par bus. Si allow_interactive_authorization est true, une autorisation interactive sera recherchée si nécessaire. Si c'est false, une autorisation interactive ne sera jamais recherchée, et toutes les requêtes d'autorisation interactive échoueront silencieusement avec -EPERM.

Par défaut, l'autorisation interactive est autorisée (true).

Ces fonctions affectent uniquement le comportement de la bibliothèque libsystemd sur ce bus spécifique. Elles n'affectent pas le comportement des autres clients D-Bus ou du démon D-Bus lui-même.

Il est généralement recommandé de désactiver l'autorisation interactive pour les applications serveur (par exemple, les démons qui s'exécutent en continu et qui ne nécessitent pas d'interaction utilisateur) afin d'éviter de bloquer le processus ou de générer des erreurs inattendues. Pour les clients D-Bus qui ont besoin de s'exécuter sans interaction utilisateur, il est également conseillé de désactiver l'autorisation interactive.

Si l'autorisation interactive est autorisée, et qu'une opération nécessite une autorisation interactive, le client D-Bus tentera d'interroger l'utilisateur pour obtenir l'autorisation. Cela se fait généralement via un mécanisme d'interface graphique ou en ligne de commande, qui peut être mis en place par le gestionnaire d'autorisation D-Bus, comme polkit(8) ou gnome-keyring. Si le mécanisme d'autorisation échoue ou si l'utilisateur refuse l'autorisation, la méthode D-Bus renverra une erreur appropriée (généralement EPERM).

Pour les opérations qui ne nécessitent pas d'autorisation interactive, ces fonctions n'ont aucun effet.

VALEUR RETOURNÉE

En cas de succès, ces fonctions renvoient 0. En cas d'échec, elles renvoient un code d'erreur négatif.

Les codes d'erreur possibles sont :

-EINVAL
Le paramètre bus n'est pas un pointeur valide, ou le paramètre allow_interactive_authorization est NULL lors de l'appel à sd_bus_get_allow_interactive_authorization().
-ENOMEM
L'allocation de mémoire a échoué.

NOTES

Ces fonctions sont implémentées dans la bibliothèque libsystemd et doivent être liées avec -lsystemd.

Pour obtenir et définir des informations d'identification pour une méthode spécifique, utilisez plutôt sd_bus_call_method_with_credentials(), sd_bus_call_method_async_with_credentials(), et les fonctions associées.

HISTORIQUE

La fonction sd_bus_get_allow_interactive_authorization() et sd_bus_set_allow_interactive_authorization() ont été ajoutées dans le version 250.

VOIR AUSSI

sd_bus_open_user(), sd_bus_open_system(), sd_bus_call(), polkit(8)

NOTES

Ces fonctions sont liées à l'autorisation d'un processus client D-Bus à déclencher une requête d'autorisation interactive. L'autorisation interactive se produit lorsqu'un serveur D-Bus (c'est-à-dire un démon) reçoit une méthode d'un client qui nécessite un niveau d'autorisation plus élevé que celui que le démon est autorisé à utiliser. Dans ce cas, le démon peut demander au client D-Bus d'initier une requête d'autorisation auprès d'un système d'autorisation externe, tel que polkit(8).

Si l'autorisation interactive est autorisée, et qu'une méthode nécessite une autorisation interactive, le client D-Bus tentera d'initier une requête d'autorisation. Cela peut impliquer d'afficher une boîte de dialogue à l'utilisateur, lui demandant de saisir son mot de passe ou d'approuver l'action. Si l'utilisateur approuve l'action, le client D-Bus recevra un jeton d'autorisation qui sera renvoyé au démon D-Bus. Le démon peut alors utiliser ce jeton pour prouver qu'il a l'autorisation nécessaire pour exécuter la méthode.

Si l'autorisation interactive est désactivée, et qu'une méthode nécessite une autorisation interactive, le client D-Bus ne tentera pas d'initier une requête d'autorisation. Au lieu de cela, la méthode renverra une erreur (généralement -EPERM) au démon D-Bus, indiquant que l'autorisation n'a pas pu être obtenue. C'est le comportement souhaité pour les applications serveur qui ne doivent pas être bloquées par des requêtes d'autorisation interactive, ou pour les applications client qui s'exécutent en arrière-plan sans interface utilisateur.

La valeur par défaut de l'autorisation interactive est true.

Pour plus d'informations sur le fonctionnement de l'autorisation D-Bus et polkit, voir les documents suivants :

2.
Le spécificateur de nom de bus D-Bus : https://dbus.freedesktop.org/doc/dbus-specification.html#message-protocol-names-bus
3.
polkit : https://www.freedesktop.org/wiki/Software/polkit
