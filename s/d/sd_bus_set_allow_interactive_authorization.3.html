SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_set_description(sd_bus *bus, const char *description);

int sd_bus_get_description(sd_bus *bus, const char **description);

int sd_bus_set_anonymous(sd_bus *bus, int b);

int sd_bus_is_anonymous(sd_bus *bus);

int sd_bus_set_trusted(sd_bus *bus, int b);

int sd_bus_is_trusted(sd_bus *bus);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, int b);

int sd_bus_get_allow_interactive_authorization(sd_bus *bus);

int sd_bus_get_scope(sd_bus *bus, const char **scope);

int sd_bus_get_tid(sd_bus *bus, pid_t *tid);

int sd_bus_get_unique_name(sd_bus *bus, const char **unique);

DESCRIPTION

sd_bus_set_description() définit la chaîne de description utilisée dans la journalisation à la chaîne spécifiée. La chaîne est copiée en interne et libérée lorsque l'objet bus est désalloué. L'argument description peut être NULL, auquel cas la description est supprimée. Cette fonction doit être appelée avant le démarrage du bus.

sd_bus_get_description() retourne une chaîne de description dans description. Cette chaîne peut avoir été définie précédemment avec sd_bus_set_description() ou sd_bus_open_with_description(3) ou une fonction similaire. Si elle n'est pas définie de cette manière, une chaîne par défaut telle que « system » ou « user » sera retournée pour les bus système ou utilisateur, et -ENXIO sinon.

sd_bus_set_anonymous() active ou désactive « l'authentification anonyme », c'est-à-dire l'absence d'authentification, du pair de bus. Cette fonction doit être appelée avant le démarrage du bus. Voir la section Mécanismes d'authentification D-Bus[1] de la spécification D-Bus pour plus de détails.

sd_bus_is_anonymous() retourne vrai si la connexion de bus autorise l'authentification anonyme (au sens décrit dans le paragraphe précédent).

sd_bus_set_trusted() définit l'état « trusted » sur l'objet bus. Si vrai, toutes les connexions sur le bus sont considérées comme fiables et l'accès à toutes les méthodes privilégiées et non privilégiées est accordé. Cette fonction doit être appelée avant le démarrage du bus.

sd_bus_is_trusted() retourne vrai si la connexion de bus est considérée comme fiable (au sens décrit dans le paragraphe précédent).

sd_bus_set_allow_interactive_authorization() active ou désactive l'autorisation interactive pour les appels de méthode. Si vrai, les messages sont marqués avec le drapeau ALLOW_INTERACTIVE_AUTHORIZATION spécifié par la spécification D-Bus[2], informant le côté récepteur que l'appelant est prêt à attendre une autorisation interactive, ce qui peut prendre un temps considérable. Si ce drapeau est défini, l'utilisateur peut être invité à saisir des mots de passe ou une confirmation via polkit[3] ou un framework similaire.

sd_bus_get_allow_interactive_authorization() retourne vrai si l'autorisation interactive est autorisée et faux sinon.

sd_bus_get_scope() enregistre la portée de l'objet bus donné dans scope. La portée du bus système est « system ». La portée d'un bus de session utilisateur est « user ». Si l'objet bus donné n'est pas le bus système ou un bus de session utilisateur, sd_bus_get_scope() retourne une erreur.

sd_bus_get_tid() enregistre l'identifiant du thread du noyau associé à l'objet bus donné dans tid. Si bus est un objet bus par défaut obtenu en appelant une des fonctions de la famille sd_bus_default(3), il enregistre l'identifiant du thread dans lequel l'objet bus a été créé. Sinon, si l'objet bus est attaché à une boucle d'événements, il enregistre l'identifiant du thread dans lequel l'objet de boucle d'événements a été créé. Si bus n'est pas un objet bus par défaut et n'est pas attaché à une boucle d'événements, sd_bus_get_tid() retourne une erreur.

sd_bus_get_unique_name() enregistre le nom unique de l'objet bus sur le bus dans unique. Voir La spécification D-Bus[4] pour plus d'informations sur les noms de bus. Notez que l'appelant ne possède pas la chaîne enregistrée dans unique et ne doit pas la libérer.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent un entier positif ou nul. En cas d'échec, elles retournent un code d'erreur négatif de style errno.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un argument est invalide.

-ENOPKG

Le bus ne peut pas être résolu.

-EPERM

Le bus a déjà été démarré.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

-ENOMEM

Échec de l'allocation de mémoire.

-ENODATA

L'objet bus passé à sd_bus_get_scope() n'était pas un bus système ou de session utilisateur.

Ajouté dans la version 246.

-ENXIO

L'objet bus passé à sd_bus_get_tid() n'était pas un objet bus par défaut et n'est pas attaché à une boucle d'événements.

L'objet bus passé à sd_bus_get_description() n'avait pas de description.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à un stade précoce du programme lorsque aucun autre thread n'a été démarré.

sd_bus_set_allow_interactive_authorization - Permettre ou interdire l'autorisation interactive pour un bus

NOM

sd_bus_set_allow_interactive_authorization - Permettre ou interdire l'autorisation interactive pour un bus

SYNOPSIS

   #include <systemd/sd-bus.h>

   int sd_bus_set_allow_interactive_authorization(sd_bus *bus,
                                                  int allow_interactive_authorization);

DESCRIPTION

La fonction sd_bus_set_allow_interactive_authorization() configure si l'autorisation interactive est autorisée pour les appels effectués via la connexion de bus bus.

Si allow_interactive_authorization est différent de zéro, l'autorisation interactive est autorisée. Sinon, elle est interdite.

Par défaut, l'autorisation interactive est autorisée. Cela signifie que si un appel nécessite une autorisation (voir sd_bus_call(3)), l'utilisateur peut être invité à fournir des informations d'identification.

La désactivation de l'autorisation interactive est utile pour les démons qui n'ont pas d'interface utilisateur pour gérer les invites d'autorisation ou qui souhaitent s'assurer que leurs appels ne seront jamais bloqués par une invite interactive.

Cette fonction n'a d'effet que sur les bus session. Elle n'est pas prise en charge sur les bus system.

VALEUR RENVOYÉE

En cas de succès, sd_bus_set_allow_interactive_authorization() renvoie 0. En cas d'échec, elle renvoie un code d'erreur négatif.

NOTES

Cette fonction est identique à sd_bus_set_property(3) avec le nom de propriété AllowInteractiveAuthorization.

L'autorisation est toujours contrôlée par le démon de bus lui-même, en fonction des politiques de polkit configurées.

HISTORIQUE

La fonction sd_bus_set_allow_interactive_authorization() a été ajoutée dans systemd v226.
