SD_BUS_GET_FD(3) sd_bus_get_fd SD_BUS_GET_FD(3)

NOM

sd_bus_get_fd, sd_bus_get_events, sd_bus_get_timeout - Obtenir le descripteur de fichier, les événements d'E/S et le délai d'attente pour un objet bus de messages

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_get_fd(sd_bus *bus);

int sd_bus_get_events(sd_bus *bus);

int sd_bus_get_timeout(sd_bus *bus, uint64_t *timeout_usec);

DESCRIPTION

sd_bus_get_fd() renvoie le descripteur de fichier utilisé pour communiquer à partir d'un objet bus de messages. Ce descripteur peut être utilisé avec poll(3) ou une fonction similaire pour attendre les événements d'E/S sur l'objet de connexion bus spécifié. Si l'objet bus a été configuré avec la fonction sd_bus_set_fd(), alors le descripteur de fichier input_fd utilisé dans cet appel est renvoyé.

sd_bus_get_events() renvoie les événements d'E/S à attendre, adaptés pour être passés à poll() ou un appel similaire. Renvoie une combinaison de POLLIN, POLLOUT, ... événements, ou une valeur négative en cas d'erreur.

sd_bus_get_timeout() renvoie le délai d'attente absolu en μs, à partir duquel le délai d'attente relatif à passer à poll() (ou un appel similaire) peut être dérivé, lors de l'attente d'événements sur la connexion bus spécifiée. Le délai d'attente renvoyé peut être zéro, auquel cas un appel de scrutation d'E/S subséquent devrait être invoqué en mode non bloquant. Le délai d'attente renvoyé peut être UINT64_MAX, auquel cas l'appel de scrutation d'E/S peut bloquer indéfiniment, sans aucun délai d'attente appliqué. Notez que le délai d'attente renvoyé ne doit être considéré que comme un temps de sommeil maximum. Il est permis (et même attendu) que des délais d'attente plus courts soient utilisés par le programme appelant, dans le cas où d'autres sources d'événements sont scrutées dans la même boucle d'événements. Notez que la valeur temporelle renvoyée est absolue, basée sur CLOCK_MONOTONIC et spécifiée en microsecondes. Lors de la conversion de cette valeur pour la passer comme troisième argument à poll() (qui attend des millisecondes relatives), il faut veiller à convertir en temps relatif et à utiliser une division qui arrondit vers le haut pour garantir que l'opération de scrutation d'E/S ne dorme pas moins longtemps que nécessaire, ce qui pourrait entraîner une boucle active involontaire (alternativement, utilisez ppoll(2) au lieu de poll() simple, qui comprend les délais d'attente avec une granularité en nanosecondes).

Ces trois fonctions sont utiles pour raccorder un objet de connexion bus à une boucle d'événements externe ou manuelle impliquant poll() ou un appel de scrutation d'E/S similaire. Avant chaque invocation de l'appel de scrutation d'E/S, les trois fonctions doivent être invoquées : le descripteur de fichier renvoyé par sd_bus_get_fd() doit être scruté pour les événements indiqués par sd_bus_get_events(), et l'appel d'E/S doit bloquer jusqu'au délai d'attente renvoyé par sd_bus_get_timeout(). Après chaque appel de scrutation d'E/S, la connexion bus doit traiter les données entrantes ou sortantes, en invoquant sd_bus_process(3).

Notez que ces fonctions ne sont qu'une des trois méthodes prises en charge pour implémenter la gestion des événements d'E/S pour les connexions bus. Utilisez alternativement sd_bus_attach_event(3) pour attacher une connexion bus à une boucle d'événements sd-event(3). Ou utilisez sd_bus_wait(3) comme un appel simple de scrutation d'E/S bloquante et synchrone.

VALEUR DE RETOUR

En cas de succès, sd_bus_get_fd() renvoie le descripteur de fichier utilisé pour la communication. En cas d'échec, il renvoie un code d'erreur négatif de style errno.

En cas de succès, sd_bus_get_events() renvoie le masque d'événements d'E/S à utiliser pour la surveillance des événements d'E/S. En cas d'échec, il renvoie un code d'erreur négatif de style errno.

En cas de succès, sd_bus_get_timeout() renvoie un entier non négatif. En cas d'échec, il renvoie un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un objet bus invalide a été passé.

-ECHILD

La connexion bus a été allouée dans un processus parent et est réutilisée dans un processus enfant après fork().

-ENOTCONN

La connexion bus a été terminée.

-EPERM

Deux descripteurs de fichiers distincts ont été passés pour l'entrée et la sortie en utilisant sd_bus_set_fd(), que sd_bus_get_fd() ne peut pas renvoyer.

-ENOPKG

Le bus ne peut pas être résolu.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_get_fd(), sd_bus_get_events() et sd_bus_get_timeout() ont été ajoutés dans la version 221.
