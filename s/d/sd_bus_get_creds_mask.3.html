SD_BUS_NEGOTIATE_FDS(3) sd_bus_negotiate_fds SD_BUS_NEGOTIATE_FDS(3)

NOM

sd_bus_negotiate_fds, sd_bus_negotiate_timestamp, sd_bus_negotiate_creds, sd_bus_get_creds_mask - Contrôler la négociation de fonctionnalités sur les connexions de bus

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_negotiate_fds(sd_bus *bus, int b);

int sd_bus_negotiate_timestamp(sd_bus *bus, int b);

int sd_bus_negotiate_creds(sd_bus *bus, int b, uint64_t mask);

int sd_bus_get_creds_mask(sd_bus *bus, uint64_t *mask);

DESCRIPTION

sd_bus_negotiate_fds() contrôle si le passage de descripteurs de fichier doit être négocié pour la connexion de bus spécifiée. Elle prend un objet de bus et une valeur booléenne qui, lorsqu'elle est vraie, active le passage de descripteurs de fichier, et, lorsqu'elle est fausse, le désactive. Notez que tous les transports et serveurs ne supportent pas le passage de descripteurs de fichier. En particulier, les transports réseau ne supportent généralement pas le passage de descripteurs de fichier. Pour savoir si le passage de descripteurs de fichier est disponible après négociation, utilisez sd_bus_can_send(3) et passez SD_BUS_TYPE_UNIX_FD. Notez que le passage de descripteurs de fichier est toujours activé pour l'envoi et la réception ou pour aucun des deux, mais jamais dans une seule direction. Par défaut, le passage de descripteurs de fichier est négocié pour toutes les connexions.

sd_bus_negotiate_timestamp() contrôle si des horodatages implicites de l'expéditeur doivent être automatiquement joints à tous les messages entrants. Prend un objet de bus et une valeur booléenne qui, lorsqu'elle est vraie, active l'horodatage, et, lorsqu'elle est fausse, le désactive. Utilisez sd_bus_message_get_monotonic_usec(3), sd_bus_message_get_realtime_usec(3), sd_bus_message_get_seqnum(3) pour interroger les horodatages des messages entrants. Si la négociation est désactivée ou non supportée, ces appels échoueront avec -ENODATA. Notez qu'actuellement, aucun transport ne supporte l'horodatage des messages. Par défaut, l'horodatage des messages n'est pas négocié pour les connexions.

sd_bus_negotiate_creds() contrôle si et quels identifiants implicites de l'expéditeur doivent être automatiquement joints à tous les messages entrants. Prend un objet de bus et une valeur booléenne indiquant s'il faut activer ou désactiver les parties d'identifiants codées dans la valeur du masque de bits fournie. Notez que tous les transports ne supportent pas l'ajout d'identifiants de l'expéditeur aux messages, ou ne supportent pas tous les types de paramètres d'identifiants de l'expéditeur, ou peuvent les supprimer dans certaines circonstances pour des messages individuels. En particulier, dbus1 ne supporte que SD_BUS_CREDS_UNIQUE_NAME. Les identifiants de l'expéditeur sont appropriés pour les décisions d'autorisation. Par défaut, seuls SD_BUS_CREDS_WELL_KNOWN_NAMES et SD_BUS_CREDS_UNIQUE_NAME sont activés. En fait, ces deux champs d'identifiants sont toujours envoyés et ne peuvent pas être désactivés.

sd_bus_get_creds_mask() renvoie l'ensemble des identifiants de l'expéditeur qui a été négocié pour être joint à tous les messages entrants dans mask. Cette valeur est seulement une limite supérieure. Par conséquent, assurez-vous toujours de vérifier explicitement quels identifiants sont joints à un message spécifique avant de l'utiliser.

La fonction sd_bus_negotiate_fds() ne peut être appelée qu'avant que la connexion n'ait été démarrée avec sd_bus_start(3). sd_bus_negotiate_timestamp() et sd_bus_negotiate_creds() peuvent également être appelées après qu'une connexion ait été établie. Notez que, lors de l'opération sur une connexion partagée entre plusieurs composants du même programme (par exemple via sd_bus_default(3)), il est fortement recommandé de n'activer que des champs de métadonnées supplémentaires par message, mais de ne jamais les désactiver à nouveau, afin de ne pas désactiver des fonctionnalités nécessaires à d'autres composants.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EPERM

La connexion de bus a déjà été démarrée.

-EINVAL

Un argument est invalide.

Ajouté dans la version 246.

-ENOPKG

Le bus ne peut pas être résolu.

Ajouté dans la version 246.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou une instance de module différent.

Ajouté dans la version 246.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_negotiate_fds(), sd_bus_negotiate_timestamp(), et sd_bus_negotiate_creds() ont été ajoutées dans la version 212.

sd_bus_get_creds_mask() a été ajoutée dans la version 246.
