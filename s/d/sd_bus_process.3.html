NOM

sd_bus_process - Piloter la connexion

SYNTAXE

#include <systemd/sd-bus.h>

int sd_bus_process(sd_bus *bus, sd_bus_message **ret);

DESCRIPTION

sd_bus_process() pilote la connexion entre le client et le bus de messages. C'est-à-dire qu'elle gère la connexion, l'authentification et le traitement des messages. Lorsqu'elle est appelée, les opérations d'E/S en attente sont exécutées et les messages entrants mis en file d'attente sont distribués aux fonctions de rappel enregistrées. Chaque fois qu'elle est appelée, une seule opération est exécutée. Elle retourne zéro lorsqu'aucune opération n'était en attente et une valeur positive si un message a été traité. Lorsque zéro est retourné, l'appelant doit interroger les événements d'E/S avant d'appeler à nouveau sd_bus_process(). Pour cela, utilisez soit l'appel simple et bloquant sd_bus_wait(3), soit accrochez l'objet de connexion du bus à une boucle d'événements externe ou manuelle en utilisant sd_bus_get_fd(3).

sd_bus_process() traite au maximum un message entrant par appel. Si le paramètre ret n'est pas NULL et que l'appel a traité un message, *ret est défini sur ce message. L'appelant détient une référence vers ce message et doit appeler sd_bus_message_unref(3) lorsque le message n'est plus nécessaire. Si ret n'est pas NULL et que des progrès ont été réalisés, mais qu'aucun message n'a été traité, *ret est défini sur NULL. Notez que seuls les messages non encore traités par les différents types de gestionnaires de messages enregistrés (c'est-à-dire par les filtres enregistrés via sd_bus_add_filter(3), les gestionnaires d'objets enregistrés via sd_bus_add_object(3), les correspondances enregistrées via sd_bus_add_match(3), et les fonctions associées) seront retournés via ce paramètre. Notez également que si un tel gestionnaire de messages retourne une valeur nulle (par opposition à une valeur > 0), un message entrant ne sera pas considéré comme traité et sera passé aux autres gestionnaires appropriés (jusqu'à ce qu'un d'eux retourne > 0), ou retourné par sd_bus_process() (si aucun ne retourne > 0).

Si l'objet de bus est connecté à une boucle d'événements sd-event(3) (avec sd_bus_attach_event(3)), il n'est pas nécessaire d'appeler sd_bus_process() directement car il est appelé automatiquement lorsque nécessaire.

VALEUR RETOURNÉE

Si des progrès ont été réalisés, un entier positif est retourné. Si aucun progrès n'a été réalisé, 0 est retourné. Si une erreur se produit, un code d'erreur négatif de style errno est retourné.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Un objet de bus invalide a été passé.

-ECHILD

La connexion du bus a été allouée dans un processus parent et est réutilisée dans un processus enfant après fork().

-ENOTCONN

La connexion du bus a déjà été terminée.

-ECONNRESET

La connexion du bus vient d'être terminée.

-EBUSY

Cette fonction est déjà en cours d'appel, c'est-à-dire que sd_bus_process() a été appelé depuis une fonction de rappel elle-même appelée par sd_bus_process().

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les threads multiples. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_process() a été ajoutée dans la version 221.
