SD_JOURNAL_STREAM_FD(3) sd_journal_stream_fd SD_JOURNAL_STREAM_FD(3)

NOM

sd_journal_stream_fd, sd_journal_stream_fd_with_namespace - Créer un descripteur de fichier de flux de journalisation vers le journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_stream_fd(const char *identifiant, int priorité, int prefixe_niveau);

int sd_journal_stream_fd_with_namespace(const char *espace_nom, const char *identifiant, int priorité, int prefixe_niveau);

DESCRIPTION

sd_journal_stream_fd() peut être utilisé pour créer un descripteur de fichier de flux de journalisation. Les messages de journalisation écrits sur ce descripteur de fichier sous forme de simples chaînes de caractères séparées par des sauts de ligne sont écrits dans le journal. Ce descripteur de fichier peut être utilisé en interne par les applications ou être rendu standard output ou standard error d'autres processus exécutés.

sd_journal_stream_fd() prend un identifiant court de programme comme premier argument, qui sera écrit dans le journal comme champ SYSLOG_IDENTIFIER= pour chaque entrée de journal (voir systemd.journal-fields(7) pour plus d'informations). Le second argument est le niveau de priorité par défaut pour tous les messages. Le niveau de priorité est l'un de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, tels que définis dans syslog.h, voir syslog(3) pour les détails. Le troisième argument est un booléen : si vrai, les préfixes de niveau de journalisation de style noyau (comme SD_WARNING) sont interprétés, voir sd-daemon(3) pour plus d'informations.

sd_journal_stream_fd_with_namespace() est similaire à sd_journal_stream_fd(), mais prend un paramètre supplémentaire espace_nom qui spécifie sur quel espace de noms du journal opérer. S'il est spécifié comme NULL, l'appel est identique à sd_journal_stream_fd(). Pour les détails sur les espaces de noms de journalisation, voir systemd-journald.service(8).

Il est recommandé que les applications ne journalisent que des messages UTF-8 avec cette API, mais cela n'est pas imposé.

Chaque invocation de ces fonctions alloue un nouveau descripteur de fichier de flux de journalisation, qui n'est pas partagé avec les invocations précédentes ou ultérieures. Le descripteur de fichier est en écriture seule (sa direction de lecture est fermée), et O_NONBLOCK est initialement désactivé.

VALEUR DE RETOUR

L'appel retourne un descripteur de fichier valide en écriture seule en cas de succès, ou un code d'erreur négatif de style errno.

SURETÉ DES SIGNAUX

sd_journal_stream_fd() et sd_journal_stream_fd_with_namespace() sont "async signal safe" dans le sens de signal-safety(7).

NOTES

Toutes les fonctions listées ici sont thread-safe et peuvent être appelées en parallèle à partir de plusieurs threads.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

EXEMPLES

Création d'un flux de journalisation adapté à fprintf(3) :

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <errno.h>
#include <syslog.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-journal.h>
#include <systemd/sd-daemon.h>
int main(int argc, char *argv[]) {
  int fd;
  FILE *log;
  fd = sd_journal_stream_fd("test", LOG_INFO, 1);
  if (fd < 0) {
    fprintf(stderr, "Échec de la création du descripteur de flux : %s\n", strerror(-fd));
    return 1;
  }
  log = fdopen(fd, "w");
  if (!log) {
    fprintf(stderr, "Échec de la création de l'objet fichier : %s\n", strerror(errno));
    close(fd);
    return 1;
  }
  fprintf(log, "Bonjour le monde !\n");
  fprintf(log, SD_WARNING "Ceci est un avertissement !\n");
  fclose(log);
  return 0;
}
