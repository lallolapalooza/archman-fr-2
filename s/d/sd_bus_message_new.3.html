sd_bus_message_new(3)

SD_BUS_MESSAGE_NEW(3) sd_bus_message_new SD_BUS_MESSAGE_NEW(3)

NOM

sd_bus_message_new, sd_bus_message_ref, sd_bus_message_unref, sd_bus_message_unrefp, SD_BUS_MESSAGE_METHOD_CALL, SD_BUS_MESSAGE_METHOD_RETURN, SD_BUS_MESSAGE_METHOD_ERROR, SD_BUS_MESSAGE_SIGNAL, sd_bus_message_get_bus - Créer un nouvel objet de message de bus et créer ou détruire des références à celui-ci

SYNTAXE

#include <systemd/sd-bus.h>
enum {
      SD_BUS_MESSAGE_METHOD_CALL,
      SD_BUS_MESSAGE_METHOD_RETURN,
      SD_BUS_MESSAGE_METHOD_ERROR,
      SD_BUS_MESSAGE_SIGNAL,
};

int sd_bus_message_new(sd_bus *bus, sd_bus_message **m, uint8_t type);

sd_bus_message *sd_bus_message_ref(sd_bus_message *m);

sd_bus_message *sd_bus_message_unref(sd_bus_message *m);

void sd_bus_message_unrefp(sd_bus_message **mp);

sd_bus *sd_bus_message_get_bus(sd_bus_message *m);

DESCRIPTION

sd_bus_message_new() crée un nouvel objet de message de bus attaché au bus bus et le retourne dans le paramètre de sortie m. Cet objet est compté par référence et sera détruit lorsque toutes les références auront disparu. Initialement, l'appelant de cette fonction possède la seule référence à l'objet message. Notez que l'objet message départient une référence à l'objet bus, donc l'objet bus ne sera pas détruit tant que le message existera.

Note : ceci est un appel de bas niveau. Dans la plupart des cas, les fonctions comme sd_bus_message_new_method_call(3), sd_bus_message_new_method_error(3), sd_bus_message_new_method_return(3) et sd_bus_message_new_signal(3) qui créent un message d'un certain type et initialisent divers champs sont plus faciles à utiliser.

Le paramètre type spécifie le type du message. Il doit être l'une des valeurs suivantes : SD_BUS_MESSAGE_METHOD_CALL - un appel de méthode, SD_BUS_MESSAGE_METHOD_RETURN - une réponse d'appel de méthode, SD_BUS_MESSAGE_METHOD_ERROR - une réponse d'erreur à un appel de méthode, SD_BUS_MESSAGE_SIGNAL - un message de diffusion sans réponse.

Le drapeau permettant l'autorisation interactive est initialisé en fonction de la valeur actuelle définie dans l'objet bus, voir sd_bus_set_allow_interactive_authorization(3). Ceci peut être modifié en utilisant sd_bus_message_set_allow_interactive_authorization(3).

sd_bus_message_ref() augmente le compteur de références interne de m d'une unité.

sd_bus_message_unref() diminue le compteur de références interne de m d'une unité. Une fois que le compteur de références est tombé à zéro, l'objet message est détruit et ne peut plus être utilisé. Par conséquent, les appels ultérieurs à sd_bus_message_ref() ou sd_bus_message_unref() sont illégaux.

sd_bus_message_unrefp() est similaire à sd_bus_message_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_message. Cet appel est utile en conjonction avec l'attribut de variable de nettoyage (Clean-up Variable Attribute) de GCC et LLVM[1]. Voir sd_bus_new(3) pour un exemple d'utilisation de l'attribut de nettoyage.

sd_bus_message_ref() et sd_bus_message_unref() n'effectuent aucune opération si l'adresse de l'objet message de bus passé est NULL. sd_bus_message_unrefp() déréférencera d'abord son argument, qui ne doit pas être NULL, et n'effectuera aucune opération si celui-ci est NULL.

sd_bus_message_get_bus() retourne l'objet bus auquel le message m est attaché.

VALEUR DE RETOUR

En cas de succès, sd_bus_message_new() retourne 0 ou un entier positif. En cas d'échec, il retourne un code d'erreur négatif de type errno.

sd_bus_message_ref() retourne toujours l'argument.

sd_bus_message_unref() retourne toujours NULL.

sd_bus_message_get_bus() retourne toujours l'objet bus.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le type spécifié est invalide.

-ENOTCONN

Le paramètre bus est NULL ou le bus n'est pas connecté.

-ENOMEM

Échec de l'allocation mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que depuis une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_bus_message_new(), sd_bus_message_ref(), sd_bus_message_unref(), sd_bus_message_unrefp() et sd_bus_message_get_bus() ont été ajoutés dans la version 240.
