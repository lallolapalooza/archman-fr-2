NOM

slapo-ppolicy - Surcouche de politique de mot de passe pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

La surcouche ppolicy est une implémentation de la proposition IETF la plus récente concernant la politique de mot de passe pour LDAP. Lorsqu'elle est instanciée, elle intercepte, décode et applique des contrôles spécifiques de politique de mot de passe à l'utilisation globale d'une base de données backend, aux changements des champs de mot de passe utilisateur, etc.

La surcouche fournit une variété de mécanismes de contrôle de mot de passe. Ils incluent la vieillesse du mot de passe -- âges minimum et maximum, contrôle de réutilisation et de duplication des mots de passe, expirations de compte, réinitialisations obligatoires de mot de passe, contenu acceptable de mot de passe, et même des connexions de grâce. Différents groupes d'utilisateurs peuvent être associés à différentes politiques de mot de passe, et il n'y a aucune limite au nombre de politiques de mot de passe qui peuvent être créées.

Notez que certaines des politiques ne prennent pas effet lorsque l'opération est effectuée avec l'identité rootdn ; toutes les opérations, lorsqu'elles sont effectuées avec une autre identité, peuvent être soumises à des contraintes, comme le contrôle d'accès. Cette surcouche nécessite qu'un rootdn soit configuré sur la base de données.

Lors de la mise à jour du mot de passe, une identité ayant un accès de gestion à l'attribut userPassword est considérée comme un administrateur de mot de passe, tel que pertinent pour la proposition IETF de politique de mot de passe.

Notez que la proposition IETF de politique de mot de passe pour LDAP a du sens lorsqu'elle considère un attribut de mot de passe à valeur unique, tandis que l'attribut userPassword permet des valeurs multiples. Cette implémentation force une valeur unique pour l'attribut userPassword, malgré sa spécification.

En plus de prendre en charge la politique de mot de passe IETF, ce module prend en charge le contrôle de la convivialité du compte SunDS (1.3.6.1.4.1.42.2.27.9.5.8) sur les requêtes de recherche et peut envoyer les contrôles de validité de mot de passe Netscape lorsqu'il est configuré pour le faire.

CONFIGURATION

Ces options de configuration slapd.conf s'appliquent à la surcouche ppolicy. Elles doivent apparaître après la directive overlay.

ppolicy_default <DN_politique>
Spécifie le DN de l'objet pwdPolicy à utiliser lorsqu'aucune politique spécifique n'est définie sur l'entrée d'un utilisateur donné. S'il n'y a pas de politique spécifique pour une entrée et qu'aucun défaut n'est donné, alors aucune politique ne sera appliquée.
ppolicy_forward_updates
Spécifie que les changements d'état de politique résultant des opérations Bind (telles que l'enregistrement des échecs, le verrouillage, etc.) sur un consommateur doivent être transférés à un fournisseur au lieu d'être écrits directement dans la base de données locale du consommateur. Ce paramètre n'est utile que sur un consommateur de réplication, et nécessite également que le paramètre updateref et la surcouche chain soient correctement configurés.
ppolicy_hash_cleartext
Spécifie que les mots de passe en clair présents dans les requêtes Add et Modify doivent être hachés avant d'être stockés dans la base de données. Cela viole le modèle d'information X.500/LDAP, mais peut être nécessaire pour compenser les clients LDAP qui n'utilisent pas l'opération étendue de modification de mot de passe pour gérer les mots de passe. Il est recommandé que lorsque cette option est utilisée, les accès compare, search et read soient refusés à tous les utilisateurs du répertoire.
ppolicy_use_lockout
Un client recevra toujours une réponse LDAP InvalidCredentials lors de la connexion à un compte verrouillé. Par défaut, lorsqu'un contrôle de politique de mot de passe était fourni sur la requête Bind, une réponse de politique de mot de passe sera incluse sans code d'erreur spécial. Cette option modifie la réponse de politique de mot de passe pour inclure le code d'erreur AccountLocked. Notez que l'envoi du code d'erreur AccountLocked fournit des informations utiles à un attaquant ; les sites sensibles aux problèmes de sécurité ne devraient pas activer cette option.
ppolicy_send_netscape_controls
Si défini, ppolicy enverra les contrôles d'expiration de politique de mot de passe (2.16.840.1.113730.3.4.4) et d'expiration imminente de politique de mot de passe (2.16.840.1.113730.3.4.5) le cas échéant. Les contrôles ne sont pas envoyés pour les requêtes bind où le contrôle de politique de mot de passe a déjà été demandé. Par défaut, les contrôles ne sont pas envoyés.
ppolicy_check_module <chemin>
Spécifie le chemin d'un module chargeable contenant une fonction check_password() pour des vérifications supplémentaires de la qualité du mot de passe. L'utilisation de ce module est décrite plus loin ci-dessous dans la description de l'objet pwdPolicyChecker.

Note : Le module chargeable défini par l'utilisateur doit se trouver dans le chemin de recherche exécutable standard de slapd, ou un chemin absolu doit être fourni.

Note : L'utilisation d'un ppolicy_check_module est une extension non standard à la proposition de politique de mot de passe LDAP.

CLASSE OBJET

La surcouche ppolicy dépend de la classe d'objet pwdPolicy. La définition de cette classe est la suivante :

( 1.3.6.1.4.1.42.2.27.8.2.1
NAME 'pwdPolicy'
AUXILIARY
SUP top
MUST ( pwdAttribute )
MAY (
pwdMinAge $ pwdMaxAge $ pwdInHistory $
pwdCheckQuality $ pwdMinLength $ pwdMaxLength $
pwdExpireWarning $ pwdAuthnLimitGrace $
pwdGraceExpiry $ pwdLockout $ pwdLockoutDuration $
pwdMaxFailure $ pwdFailureCountInterval $
pwdMustChange $ pwdAllowUserChange $
pwdSafeModify $ pwdMaxRecordedFailure $
pwdMinDelay $ pwdMaxDelay $ pwdMaxIdle ) )

La classe pwdPolicy n'est pas structurelle, et par conséquent, les entrées qui l'utilisent nécessitent une autre classe d'objet structurelle. La classe d'objet namedPolicy est un bon choix. namedPolicy requiert un attribut cn, approprié comme rDN de l'entrée de politique.

Cette implémentation fournit également une classe d'objet supplémentaire pwdPolicyChecker, utilisée pour la vérification de la qualité du mot de passe (voir ci-dessous).

( 1.3.6.1.4.1.4754.2.99.1
NAME 'pwdPolicyChecker'
AUXILIARY
SUP top
MAY ( pwdCheckModule $ pwdCheckModuleArg $ pwdUseCheckModule ) )

Chaque compte qui devrait être soumis au contrôle de politique de mot de passe devrait avoir un attribut pwdPolicySubentry contenant le DN d'une entrée pwdPolicy valide, ou ils peuvent simplement utiliser le défaut configuré. De cette manière, différents utilisateurs peuvent être gérés selon des politiques différentes.

pwdCheckQuality

Cet attribut indique si et comment la syntaxe du mot de passe sera vérifiée lors de la modification ou de l'ajout d'un mot de passe. ATTRIBUTS DE POLITIQUE DE MOT DE PASSE

Ces attributs sont utilisés pour définir et appliquer des règles de politique de mot de passe pour les utilisateurs. Ils sont généralement configurés dans un sous-entrée pwdPolicy.

pwdMaxDelay

Cet attribut spécifie le délai, en secondes, entre les tentatives de connexion échouées avant qu'un compte ne soit désactivé. Un compte est désactivé pour la durée spécifiée par pwdMaxDelay si le nombre de tentatives de connexion échouées atteint la valeur définie par pwdMaxFailure. La période de blocage se termine lorsque le délai spécifié par pwdMaxDelay s'est écoulé (ou qu'une authentification réussie se produit, ce qui réinitialise le compteur d'échecs). pwdMinDelay doit également être spécifié si pwdMaxDelay est défini.

Notez que cette implémentation utilise un verrouillage variable au lieu de retarder la réponse de la liaison.

SYNTAX 1.3.6.1.4.1.1466.115.121.1.27
SINGLE-VALUE )

pwdMaxIdle

Cet attribut spécifie le nombre de secondes pendant lesquelles un compte peut rester inutilisé avant d'être verrouillé. Si cet attribut n'est pas défini ou est défini sur zéro (0), aucune vérification n'est effectuée. Pour que cela soit appliqué, la fonctionnalité lastbind doit être activée dans la base de données, c'est-à-dire que olcLastBind est défini sur TRUE.

pwdUseCheckModule/pwdCheckModuleArg

L'attribut pwdUseCheckModule active l'utilisation d'un module chargeable précédemment configuré avec ppolicy_check_module pour la politique en cours. Le module doit instancier la fonction check_password(). Cette fonction sera appelée pour vérifier davantage un nouveau mot de passe si pwdCheckQuality est défini sur un (1) ou deux (2), après que toutes les vérifications de conformité de mot de passe intégrées aient été réussies. Cette fonction sera appelée selon le prototype suivant :

int check_password (char *pPasswd, struct berval *pErrmsg, Entry *pEntry, struct berval *pArg);
Le paramètre pPasswd contient le mot de passe utilisateur en texte clair, le paramètre pErrmsg pointe vers une struct berval contenant de l'espace pour retourner des détails lisibles par l'homme sur toute erreur rencontrée. Le champ bv_len doit contenir la taille de l'espace fourni par le champ bv_val.

Le paramètre pEntry est facultatif, s'il n'est pas NULL, il contient un pointeur vers l'entrée dont le mot de passe est vérifié.

Le paramètre facultatif pArg pointe vers une struct berval contenant la valeur de pwdCheckModuleArg dans la politique de mot de passe effective, si elle est définie, sinon NULL.

Si pErrmsg est NULL, alors funcName ne doit PAS tenter de l'utiliser. Une valeur de retour de LDAP_SUCCESS de la fonction appelée indique que le mot de passe est correct, toute autre valeur indique que le mot de passe est inacceptable. Si le mot de passe est inacceptable, le serveur renverra une erreur au client, et pErrmsg peut être utilisé pour retourner une explication textuelle lisible par l'homme de l'erreur. Si l'espace passé par l'appelant est trop petit, la fonction peut le remplacer par un tampon alloué dynamiquement, qui sera libéré par slapd.

L'attribut pwdCheckModule est maintenant obsolète et est ignoré.

ATTRIBUTS OPÉRATIONNELS

Les attributs opérationnels utilisés par le module ppolicy sont stockés dans l'entrée de l'utilisateur. La plupart de ces attributs ne sont pas destinés à être modifiés directement par les utilisateurs ; ils sont là pour suivre l'activité de l'utilisateur. Ils ont été détaillés ici afin que les administrateurs et les utilisateurs puissent comprendre le fonctionnement du module ppolicy.

Notez que la proposition actuelle de l'IETF sur la politique de mot de passe ne définit pas comment ces attributs opérationnels sont censés se comporter dans un environnement de réplication. En général, les tentatives d'authentification sur un serveur répliqué n'affectent que la copie des attributs opérationnels sur ce répliqué et n'affecteront aucun attribut de l'entrée d'un utilisateur sur le fournisseur. Les modifications des attributs opérationnels résultant des tentatives d'authentification sur un fournisseur se répliqueront généralement vers les répliqués (et écraseront également toute modification originaire du répliqué). Ces comportements ne sont pas garantis et sont sujets à modification lorsqu'une spécification formelle émergera.

userPassword

L'attribut userPassword ne fait pas strictement partie du module ppolicy. C'est cependant l'attribut qui est suivi et contrôlé par le module. Veuillez vous référer au schéma OpenLDAP standard pour sa définition.

pwdPolicySubentry

Cet attribut fait référence directement à la sous-entrée pwdPolicy qui doit être utilisée pour cet utilisateur de répertoire particulier. Si pwdPolicySubentry existe, il doit contenir le DN d'un objet pwdPolicy valide. S'il n'existe pas, le module ppolicy appliquera les règles de politique de mot de passe par défaut à l'utilisateur associé à ce DN d'authentification. S'il n'y a pas de politique par défaut, ou si la sous-entrée référencée n'existe pas, alors aucune règle de politique ne sera appliquée.

( 1.3.6.1.4.1.42.2.27.8.1.23
NAME 'pwdPolicySubentry'
DESC 'La sous-entrée pwdPolicy en vigueur pour
cet objet'
EQUALITY distinguishedNameMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.12
SINGLE-VALUE
USAGE directoryOperation)

pwdChangedTime

Cet attribut indique la dernière fois que le mot de passe de l'entrée a été modifié. Cette valeur est utilisée par la politique d'expiration du mot de passe pour déterminer si le mot de passe est trop ancien pour être utilisé pour l'authentification de l'utilisateur. Si pwdChangedTime n'existe pas, le mot de passe de l'utilisateur n'expirera pas.

( 1.3.6.1.4.1.42.2.27.8.1.16
NAME 'pwdChangedTime'
DESC 'L'heure de la dernière modification du mot de passe'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.24
EQUALITY generalizedTimeMatch
ORDERING generalizedTimeOrderingMatch
SINGLE-VALUE
NO-USER-MODIFICATION
USAGE directoryOperation)

pwdAccountLockedTime

Cet attribut contient l'heure à laquelle le compte de l'utilisateur a été verrouillé. Si le compte a été verrouillé, le mot de passe ne peut plus être utilisé pour authentifier l'utilisateur auprès du répertoire. Si pwdAccountLockedTime est défini sur 000001010000Z, le compte de l'utilisateur a été verrouillé de manière permanente et ne peut être déverrouillé que par un administrateur. Notez que le verrouillage du compte ne prend effet que lorsque l'attribut de politique de mot de passe pwdLockout est défini sur « TRUE ».

( 1.3.6.1.4.1.42.2.27.8.1.17
NAME 'pwdAccountLockedTime'
DESC 'L'heure à laquelle un compte utilisateur a été verrouillé'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.24
EQUALITY generalizedTimeMatch
ORDERING generalizedTimeOrderingMatch
SINGLE-VALUE
USAGE directoryOperation)

pwdFailureTime

Cet attribut contient les horodatages de chacune des échecs d'authentification consécutifs lors des tentatives d'authentification à ce DN (c'est-à-dire au compte). Si trop d'horodatages s'accumulent ici (voir l'attribut de politique de mot de passe pwdMaxFailure pour plus de détails), et que l'attribut de politique de mot de passe pwdLockout est défini sur « TRUE », le compte peut être verrouillé. (Veuillez également vous référer à l'attribut de politique de mot de passe pwdLockout.) Les horodatages excédentaires au-delà de ceux autorisés par pwdMaxFailure ou pwdMaxRecordedFailure peuvent également être purgés. Si une authentification réussie est effectuée sur ce DN (c'est-à-dire sur ce compte utilisateur), alors pwdFailureTime sera nettoyé des entrées.

( 1.3.6.1.4.1.42.2.27.8.1.19
NAME 'pwdFailureTime'
DESC 'Les horodatages des dernières tentatives d'authentification échouées consécutives'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.24
EQUALITY generalizedTimeMatch
ORDERING generalizedTimeOrderingMatch
NO-USER-MODIFICATION
USAGE directoryOperation )

pwdHistory

Cet attribut contient l'historique des mots de passe précédemment utilisés pour ce DN (c'est-à-dire pour ce compte utilisateur). Les valeurs de cet attribut sont stockées sous forme de chaîne de caractères comme suit :

pwdHistory=

time "#" syntaxOID "#" length "#" data

time=

GeneralizedTime tel que spécifié dans la section 3.3.13 de [RFC4517]

syntaxOID = numericoid

Il s'agit de la représentation sous forme de chaîne de l'OID en notation décimale pointée qui définit la syntaxe utilisée pour stocker le mot de passe. numericoid est décrit dans la section 1.4 de [RFC4512].

length = NumericString

Le nombre d'octets dans les données. NumericString est décrit dans la section 3.3.23 de [RFC4517].

data =

Octets représentant le mot de passe dans le format spécifié par syntaxOID.

Ce format permet au serveur de stocker et de transmettre un historique des mots de passe qui ont été utilisés. Afin que la correspondance d'égalité sur les valeurs de cet attribut fonctionne correctement, le champ temporel est au format GMT.

( 1.3.6.1.4.1.42.2.27.8.1.20
NAME 'pwdHistory'
DESC 'L'historique des mots de passe utilisateur'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.40
EQUALITY octetStringMatch
NO-USER-MODIFICATION
USAGE directoryOperation)

pwdGraceUseTime

Cet attribut contient la liste des horodatages des connexions effectuées après l'expiration du mot de passe de l'utilisateur dans le DN. Ces connexions post-expiration sont appelées « *connexions de grâce* ». Si trop de « *connexions de grâce* » ont été utilisées (veuillez vous référer à l'attribut de politique de mot de passe pwdGraceAuthnLimit), alors le DN ne sera plus autorisé à être utilisé pour authentifier l'utilisateur auprès du répertoire tant que l'administrateur n'aura pas modifié l'attribut userPassword du DN.

( 1.3.6.1.4.1.42.2.27.8.1.21

EQUALITY generalizedTimeMatch
NO-USER-MODIFICATION
USAGE directoryOperation)

pwdReset

Cet attribut indique si le mot de passe de l'utilisateur a été réinitialisé par l'administrateur et doit donc être modifié lors de la première utilisation de ce DN pour l'authentification auprès du répertoire. Si pwdReset est défini sur « TRUE », alors le mot de passe a été réinitialisé et l'utilisateur doit le modifier lors de la première authentification. Si l'attribut n'existe pas, ou s'il est défini sur « FALSE », l'utilisateur n'a pas besoin de changer son mot de passe en raison d'une réinitialisation administrative.

CONTRÔLE D'UTILISABILITÉ DE COMPTE SUNDS

Si le contrôle d'utilisabilité de compte SunDS est utilisé avec une requête de recherche, la surcouche attachera des informations de validité à chaque entrée si toutes les conditions suivantes sont remplies :

•
Il existe une politique de mot de passe qui s'applique à l'entrée
•
L'utilisateur a un accès compare à l'attribut de mot de passe de l'entrée.
•
L'attribut de mot de passe configuré est présent dans l'entrée

EXEMPLES

database mdb
suffix dc=example,dc=com
...
overlay ppolicy
ppolicy_default "cn=Standard,ou=Policies,dc=example,dc=com"
