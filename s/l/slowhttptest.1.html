SLOWHTTPTEST(1) Manuel des commandes générales SLOWHTTPTEST(1)

NOM

slowhttptest — Simulateur d'attaques par déni de service

SYNTAXE

slowhttptest [-H|B|R|X] [-g] [-a début_plage] [-b limite_plage] [-c nombre_de_connexions] [-d tous_trafics_dirigés_par_proxy_HTTP_à_hôte:port] [-e trafic_de_sonde_dirigé_par_proxy_HTTP_à_hôte:port] [-f valeur_en_tête_Content-type] [-i intervalle_en_secondes] [-k facteur_de_multiplication_requête] [-l durée_du_test_en_secondes] [-m valeur_en_tête_Accept] [-n intervalle_lecture_lente_en_secondes] [-o chemin_et/ou_nom_du_fichier_de_sortie] [-p délai_connexion_sonde_en_secondes] [-r connexions_par_seconde] [-s valeur_en_tête_Content-Length] [-t verbe_HTTP] [-u URL_absolue] [-v niveau_de_verbosité_sortie] [-w début_plage_taille_fenêtre_annoncée_TCP] [-x longueur_max_données_de_suivi] [-y fin_plage_taille_fenêtre_annoncée_TCP] [-z lecture_lente_du_tampon_réception_en_octets]

DESCRIPTION

Le slowhttptest implémente la plupart des attaques DoS courantes au niveau de l'application à faible bande passante et produit des fichiers CSV et HTML avec des statistiques de test.

Les attaques actuellement prises en charge sont :

  • Slowloris
  • Slow HTTP POST
  • Apache Range Header
  • Lecture lente

Les options sont les suivantes :

-g
Force slowhttptest à générer des fichiers CSV et HTML lorsque le test se termine avec l'horodatage dans le nom du fichier.
-H
Démarre slowhttptest en mode SlowLoris, envoyant des requêtes HTTP incomplètes.
-B
Démarre slowhttptest en mode Slow POST, envoyant des corps de messages HTTP incomplets.
-R
Démarre slowhttptest en mode Range Header, envoyant des données d'en-tête de requête malveillantes.
-X
Démarre slowhttptest en mode Lecture Lente, lisant les réponses HTTP lentement.
-a début
Définit la valeur de départ du spécificateur de plage pour l'attaque Range Header.
-b octets
Définit la valeur limite du spécificateur de plage pour l'attaque Range Header.
-c nombre de connexions
Spécifie le nombre cible de connexions à établir pendant le test.
-d hôte:port proxy HTTP
Spécifie le serveur proxy HTTP auquel se connecter pour toutes les connexions.
-e hôte:port proxy HTTP
Spécifie le serveur proxy HTTP auquel se connecter pour les connexions de sonde.
-f type-contenu
Spécifie la valeur de l'en-tête Content-Type.
-i secondes
Spécifie l'intervalle entre les données de suivi pour les tests slowloris et Slow POST.
-k facteur de pipeline
Spécifie le nombre de fois où la ressource sera demandée par socket dans le test Lecture Lente.
-l secondes
Spécifie la durée du test en secondes.
-m accept
Spécifie la valeur de l'en-tête Accept.
-n secondes
Spécifie l'intervalle entre les opérations de lecture pour le test Lecture Lente.
-o nom du fichier
Spécifie un nom de fichier personnalisé, efficace avec -g.
-p secondes
Spécifie l'intervalle d'attente de la réponse HTTP sur la connexion de sonde, avant de marquer le serveur comme DoSed.
-r connexions par seconde
Spécifie le taux de connexion.
-s octets
Spécifie la valeur de l'en-tête Content-Length pour le test Slow POST.
-t verbe HTTP
Spécifie le verbe à utiliser dans la requête HTTP.
-u URL
Spécifie l'URL.
-v niveau
Spécifie le niveau de verbosité de la journalisation.
-w octets
Spécifie le début de la plage à partir de laquelle la taille de la fenêtre TCP annoncée sera choisie dans le test Lecture Lente.
-x octets
Spécifie la longueur maximale des données de suivi pour les tests slowloris et Slow POST.
-y octets
Spécifie la fin de la plage à partir de laquelle la taille de la fenêtre TCP annoncée sera choisie dans le test Lecture Lente.
-z octets
Spécifie le nombre d'octets à lire du tampon de réception à chaque opération de lecture().

EXEMPLES

Lancez un test slowloris de host.example.com avec 1000 connexions, les statistiques vont dans my_header_stats, l'intervalle entre les en-têtes de suivi est de 10 secondes et le taux de connexion est de 200 connexions par seconde :

$ slowhttptest -c 1000 -H -g -o my_header_stats -i 10 -r 200 -t GET -u https://host.example.com/index.html -x 24 -p 3

Lancez un test slow POST de host.example.com avec 3000 connexions, les statistiques vont dans my_body_stats, l'intervalle entre les en-têtes de suivi est de 110 secondes, le taux de connexion est de 200 connexions par seconde, la valeur de l'en-tête Content-Length est 8192, la longueur maximale des données de suivi est une valeur aléatoire limitée à 10 octets et les connexions de sonde attendent 3 secondes pour une réponse HTTP avant de marquer le serveur comme DoSed :

NAME

slowhttptest — a toolkit for high-performance HTTP denial-of-service attacks

SYNOPSIS

slowhttptest [options]

DESCRIPTION

slowhttptest is a toolkit for high-performance HTTP denial-of-service attacks. It is designed to test the robustness of web applications against DoS attacks and to provide some basic DDoS mitigation techniques.

The toolkit can simulate various types of HTTP DoS attacks, including:

  • Slowloris attack: keeps many connections to the Web server open and tries to drain the server's resources.
  • R-U-Dead-Yet? attack: abuses HTTP Keep-Alive functionality to exhaust the connection pool.
  • Slow POST attack: keeps POSTing data to the server slowly, consuming resources.
  • Range Header attack: abuses Range header to split the download into small chunks.
  • Slow Read attack: reads data from the server slowly, consuming resources.

The toolkit provides the following features:

  • Adjustable number of concurrent connections.
  • Adjustable connection rate.
  • Adjustable interval between follow-up headers.
  • Adjustable HTTP methods and headers.
  • Adjustable connection timeout.
  • Adjustable TCP advertised window size.
  • Adjustable read/write buffer size.
  • Randomization of client IP addresses.
  • Support for HTTP/1.0 and HTTP/1.1.
  • Support for proxy servers.
  • Statistics generation.

EXAMPLES

Start Slowloris attack of host.example.com with 1000 connections, use GET verb, and generate HTTP headers randomly, connection rate is 200 connections per second, connection interval between follow up headers is 10 seconds and connection timeout is 3 seconds:

$ slowhttptest -c 1000 -B -g -o my_stats -i 10 -r 200 -s 8192 -t GET -u http://host.example.com/ -x 10 -p 3

Start Slow POST attack of host.example.com with 3000 connections, use FAKEVERB verb, and generate HTTP headers randomly, connection rate is 200 connections per second, connection interval between follow up headers is 110 seconds and connection timeout is 3 seconds:

$ slowhttptest -c 3000 -B -g -o my_body_stats -i 110 -r 200 -s 8192 -t FAKEVERB -u http://host.example.com/loginform.html -x 10 -p 3

Start Range Header test of host.example.com with 1000 connections, use HEAD verb, and generate HTTP header Range:0-, x-1, x-2, x-3, ... x-y, where x is 10 and y is 3000, connection rate is 500: interval between follow up headers is 10 seconds and connection rate is 200 connections per second:

$ slowhttptest -R -u http://host.example.com/ -t HEAD -c 1000 -a 10 -b 3000 -r 500

Start Slow Read test of host.example.com with 8000 connections, no statistics is generated, connection rate is 200 connections per second, TCP advertised window size is a random value between 512 and 1024, slowhttptest reads 32 bytes from each connections every 5 seconds, 3 requests are pipelined per each connections, probe connection waits 3 seconds for HTTP response before marking server as DoSed:

$ slowhttptest -c 8000 -X -r 200 -w 512 -y 1024 -n 5 -z 32 -k 3 -u https://host.example.com/resources/index.html -p 3

Start Slow Read test of host.example.com through HTTP proxy server at 10.10.0.1:8080 with 8000 connections, no statistics is generated, the rest test values are default. slowhttptest most likely would test HTTP proxy server itself, rather than target server, but it all depends on the HTTP proxy server implementation:

$ slowhttptest -d 10.10.0.1:8080 -c 8000 -X -u https://host.example.com/resources/index.html

Start Slow Read test of host.example.com and direct probe traffic through HTTP proxy server at 10.10.0.1:8080 with 8000 connections, no statistics is generated, the rest test values are default. Specifying another connection channel for probe connections helps to make sure that slowhttptest shows valid statistics for availability of server under test:

$ slowhttptest -e 10.10.0.1:8080 -c 8000 -X -u https://host.example.com/resources/index.html
