SLARFB_GETT

Purpose:

!>
!> SLARFB_GETT applique un bloc de réflecteurs de Householder réel H à une matrice réelle de taille (K+M)-par-N
!> composée de deux matrices par blocs : une matrice trapézoïdale supérieure K-par-N stockée dans le tableau A,
!> et une matrice rectangulaire M-par-(N-K), stockée dans le tableau B. Le bloc réflecteur H est stocké dans une
!> représentation compacte de type WY, où les réflecteurs élémentaires sont dans les tableaux A, B et T. Voir la section Détails supplémentaires.
!>

Paramètres

IDENT 
!>          IDENT est CHARACTER*1
!>          Si IDENT = non 'I', ou non 'i', alors V1 est une matrice
!>             unit lower-triangulaire et stockée dans le bloc K-par-K gauche
!>             de la matrice d'entrée A,
!>          Si IDENT = 'I' ou 'i', alors V1 est une matrice identité et
!>             non stockée.
!>          Voir la section Détails supplémentaires.
!>

M

!>          M est INTEGER
!>          Le nombre de lignes de la matrice B.
!>          M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes des matrices A et B.
!>          N >= 0.
!>

K

!>          K est INTEGER
!>          Le nombre de lignes de la matrice A.
!>          K est aussi l'ordre de la matrice T, c'est-à-dire le nombre de
!>          réflecteurs élémentaires dont le produit définit le bloc
!>          réflecteur. 0 <= K <= N.
!>

T

!>          T est un tableau REAL, dimension (LDT,K)
!>          La matrice triangulaire supérieure K-par-K T dans la représentation
!>          du bloc réflecteur.
!>

LDT

!>          LDT est INTEGER
!>          La dimension principale du tableau T. LDT >= K.
!>

A

!>          A est un tableau REAL, dimension (LDA,N)
!>
!>          À l'entrée :
!>           a) Dans la partie supérieure trapézoïdale K-par-N A : matrice d'entrée A.
!>           b) Dans les colonnes sous la diagonale : colonnes de V1
!>              (les uns ne sont pas stockés sur la diagonale).
!>
!>          À la sortie :
!>            A est écrasé par le produit rectangulaire K-par-N H*A.
!>
!>          Voir la section Détails supplémentaires.
!>

LDA

!>          LDB est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,K).
!>

B

!>          B est un tableau REAL, dimension (LDB,N)
!>
!>          À l'entrée :
!>            a) Dans le bloc droit M-par-(N-K) : matrice d'entrée B.
!>            b) Dans le bloc gauche M-par-N : colonnes de V2.
!>
!>          À la sortie :
!>            B est écrasé par le produit rectangulaire M-par-N H*B.
!>
!>          Voir la section Détails supplémentaires.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,M).
!>

WORK

!>          WORK est un tableau REAL,
!>          dimension (LDWORK,max(K,N-K))
!>

LDWORK

!>          LDWORK est INTEGER
!>          La dimension principale du tableau WORK. LDWORK>=max(1,K).
!>
!>

NAME

slarfb_gett - [SUN dLAMCH] This routine is used to generate the test matrices for the routines in LAPACK.

SYNOPSIS

Function/Subroutine Documentation

!> \brief Generates test matrices for SLARFB.
!>
!> \details This routine is used to generate the test matrices for the routines in LAPACK.
!>
!> \par Matrix Notation:
!> In the following comments, we denote the matrices by:
!>
!>     A1     A2
!> A = [        ]
!>     B1     B2
!>
!> where A1 is K-by-K, B1 is (M-K)-by-K, A2 is K-by-(N-K), and B2 is (M-K)-by-(N-K).
!>
!> The algorithm computes A and B from the input matrices C and D.
!>
!> \par Algorithm:
!> The algorithm performs the following operations:
!>
!> 1. Compute column block 2 (A2 and B2).
!> 2. Compute column block 1 (A1 and B1).
!>
!> \par Workspace:
!> The routine requires a workspace matrix WORK of size K-by-max(K, N-K).
!>
!> \par Input Parameters:
!> - N: Dimension of the second dimension of the matrix.
!> - K: Dimension of the first dimension of the matrix.
!> - C: The first K rows of the matrix A.
!> - LDA: Leading dimension of C.
!> - D: The remaining (M-K) rows of the matrix A.
!> - LDB: Leading dimension of D.
!> - WORK: Workspace array.
!>
!> \par Output Parameters:
!> - A: The input matrix C, modified in place.
!> - B: The input matrix D, modified in place.
!>
!> \par Mathematical Derivations:
!>
!> The transformation is given by:
!>
!> A = [ A1 A2 ] , B = [ B1 B2 ]
!>
!> The operation computed is:
!>
!> [ A B ] = [ C D ] [ V1 0 ]
!>           [ 0 V2 ]
!>
!> where V1 is K-by-K and V2 is (M-K)-by-(N-K).
!>
!> Let the input matrix be X = [ C D ].
!> Let the output matrix be Y = [ A B ].
!>
!> The transformation is Y = X * P, where P is a permutation matrix.
!>
!> The formula used in the routine is based on the definition of the blocked
!> Householder reflection:
!>
!> H = I - V * T * V^T
!>
!> where V is a matrix whose columns are the Householder vectors and T is a
!> diagonal matrix.
!>
!> The routine applies the transformation to the matrix [A B].
!>
!> Let A be KxN and B be (M-K)xN.
!>
!> The computation proceeds in two steps:
!>
!> Step 1: Compute the second block column of A and B.
!> This involves applying the transformation to the submatrix corresponding
!> to A2 and B2.
!>
!> Step 2: Compute the first block column of A and B.
!> This involves applying the transformation to the submatrix corresponding
!> to A1 and B1.
!>
!> The routine uses a workspace matrix WORK.
!>
!> Let's analyze the specific operations for clarity, assuming the input
!> matrices are C and D.
!>
!> The initial setup for the computation involves partitioning C and D.
!> C is KxK, D is (M-K)xK. Let's denote these as C1 and D1 for the first
!> block column.
!>
!> The routine actually computes A and B based on C and D, where the input
!> is essentially structured as:
!>
!> Input: C (KxN), D ((M-K)xN)
!> Output: A (KxN), B ((M-K)xN)
!>
!> The transformation applied is related to:
!>
!> [ A ] = [ V1 ] [ C ]
!> [ B ]   [ V2 ] [ D ]
!>
!> where V1 is KxK and V2 is (M-K)xK. This seems to be an application of a
!> block Householder transformation.
!>
!> The documentation provided in the source code (which I will translate
!> below) gives a more detailed step-by-step breakdown.
!>
!> Let's denote the matrices in the description as follows:
!> A is the KxN matrix.
!> B is the (M-K)xN matrix.
!> V1 is the KxK matrix.
!> V2 is the (M-K)xK matrix.
!>
!> The input to the routine is effectively the combined matrix
!> [ A ]
!> [ B ]
!> which is partitioned as:
!>
!> [ A1 A2 ]
!> [ B1 B2 ]
!>
!> where A1 is KxK, A2 is Kx(N-K), B1 is (M-K)xK, B2 is (M-K)x(N-K).
!>
!> The routine computes the updated A and B matrices.
!> The actual implementation applies transformations using V1 and V2.
!> The key is how the input C and D relate to the final A and B.
!>
!> Based on the typical use of SLARFB, it applies a block Householder
!> transformation Q to a matrix X: Q * X.
!> Q = [ I  0 ] - [ V1 ] * T * [ V1^T  V2^T ]
!>     [ 0  I ]   [ V2 ]         [ 0     0  ]
!>
!> where T is a diagonal matrix.
!>
!> However, the provided description seems to be computing A and B from
!> C and D, suggesting an operation like:
!>
!> [ A ] = [ C ] * P  where P is a permutation matrix
!> [ B ]   [ D ]
!>
!> Let's follow the translated description:
!>
!> Input matrices:
!> C: K x (N-K) matrix (this is A2 in the block notation)
!> D: (M-K) x (N-K) matrix (this is B2 in the block notation)
!> The routine also takes V1 and V2 implicitly through LDA, LDB and the actual
!> content of the arrays passed as A and B.
!> It seems the routine is designed to compute the transformation applied to
!> the second block column based on the first block column.
!>
!> Let's assume the routine computes:
!> A_out = A_in * P
!> B_out = B_in * P
!> where P = [ V1  0 ]
!>           [ 0   V2 ]
!>
!> This is confusing. Let's re-read the description carefully.
!>
!> The standard SLARFB applies a triangular factor T to a matrix X.
!> The formulation is typically:
!> OP(Q) * X, where Q = [ I  0 ] - [ V ] T [ V^H 0 ]
!>                      [ 0  I ]     [ W ]     [ 0   0 ]
!>
!> The description provided seems to be implementing a specific part of
!> a larger algorithm, possibly related to the generation of test matrices
!> for block reflector applications.
!>
!> Let's assume the input arrays A, B, C, D represent partitions of matrices.
!> A: K x K (effectively A1 in the description)
!> B: (M-K) x K (effectively B1 in the description)
!> C: K x (N-K) (effectively A2 in the description)
!> D: (M-K) x (N-K) (effectively B2 in the description)
!>
!> The description states:
!> A = [ A1 A2 ]
!>     [ B1 B2 ]
!> where A1 is KxK, B1 is (M-K)xK, A2 is Kx(N-K), B2 is (M-K)x(N-K).
!>
!> The routine computes A and B from C and D. This implies that C and D are
!> the input, and A and B are the output.
!>
!> Let's map the parameters to the description:
!> Input C: Represents the first K rows of the matrix being transformed.
!> Input D: Represents the remaining M-K rows of the matrix being transformed.
!> Output A: Updated first K rows.
!> Output B: Updated remaining M-K rows.
!>
!> The description refers to V1 and V2, and matrices A1, A2, B1, B2.
!> It seems V1 and V2 are related to the Householder vectors, and T is a diagonal
!> matrix.
!> IDENT is a character flag, likely indicating if V1 is an identity matrix.
!>
!> Let's assume the operation is applying a block reflector:
!> Let X = [ C ]
!>         [ D ]
!> We want to compute Y = [ A ] = Q * X
!>                       [ B ]
!>
!> where Q = I - V T W^H, and V and W are block matrices.
!>
!> The description seems to be describing the computation of the result
!> of applying a block reflector to a matrix that is already partitioned.
!>
!> Let's consider the common usage of SLARFB:
!> It applies the triangular factor T to a matrix Op(Q), where Q is a
!> Householder reflector.
!>
!> Routine SLARFB applies an N x K matrix V and an N x N upper triangular
!> matrix T to an M x N matrix X.
!>
!> OP(Q) * X, where Q is a general matrix Q = [ I ]
!>                                           [ 0 ]
!>                                       - [ V ] T [ V^T 0 ]
!>                                           [ W ]
!>
!> The description provided seems to be for a specific test routine (GETT)
!> that *generates* matrices relevant to testing SLARFB.
!>
!> The core computation described is:
!>
!> A = [ A1 A2 ]
!>     [ B1 B2 ]
!>
!> where A1 is KxK, B1 is (M-K)xK, A2 is Kx(N-K), B2 is (M-K)x(N-K).
!>
!> The routine computes the output A and B from the input C and D.
!> It appears that C and D are the *initial* matrices A2 and B2, and
!> the routine computes the *final* A2 and B2 after the transformation.
!>
!> Let's map the parameters to the description:
!> Input C (Kx(N-K)) -> corresponds to A2 in the description.
!> Input D ((M-K)x(N-K)) -> corresponds to B2 in the description.
!>
!> The routine uses workspace matrices W1 and W2.
!> W2 is Kx(N-K) (same size as A2). Stored in WORK(1:K, 1:(N-K)).
!> W1 is KxK (same size as A1). Stored in WORK(1:K, 1:K).
!>
!> The routine needs WORK size K x max(K, N-K).
!>
!> The overall algorithm described is:
!>
!> 1. Compute column block 2 (A2 and B2).
!> 2. Compute column block 1 (A1 and B1).
!>
!> This implies the input matrices A1, B1 are also available or derived.
!>
!> Let's look at the specific steps:
!>
!> Case (A): V1 is unit lower-triangular (IDENT != 'I')
!>
!> If N > K (computing column block 2):
!>   col2_(1) W2: = A2       (Initialize W2 with the current A2)
!>   col2_(2) W2: = (V1**T) * W2  (Multiply W2 by V1 transpose)
!>                 = (unit_lower_tr_of_(A1)**T) * W2
!>                 (This step seems to imply A1 is the unit lower triangular matrix V1)
!>   col2_(3) W2: = W2 + (V2**T) * B2 (Add a term involving V2 transpose and B2)
!>                 = W2 + (B1**T) * B2
!>                 (This step implies B1 is related to V2)
!>   col2_(4) W2: = T * W2       (Multiply W2 by T)
!>   col2_(5) B2: = B2 - V2 * W2 (Update B2 using V2 and W2)
!>                 = B2 - B1 * W2
!>   col2_(6) W2: = V1 * W2       (Update W2 using V1)
!>                 = unit_lower_tr_of_(A1) * W2
!>   col2_(7) A2: = A2 - W2       (Update A2 using W2)
!>
!> If N <= K (computing column block 1):
!>   col1_(1) W1: = A1       (Initialize W1 with A1)
!>   col1_(2) W1: = (V1**T) * W1  (Multiply W1 by V1 transpose)
!>                 = (unit_lower_tr_of_(A1)**T) * W1
!>   col1_(3) W1: = T * W1       (Multiply W1 by T)
!>   col1_(4) B1: = - V2 * W1     (Update B1 using V2 and W1)
!>                 = - B1 * W1
!>   col1_(5) square W1: = V1 * W1 (Update W1 using V1)
!>                         = unit_lower_tr_of_(A1) * W1
!>   col1_(6) square A1: = A1 - W1 (Update A1 using W1)
!>
!> Case (B): V1 is an identity matrix (IDENT == 'I')
!>
!> If N > K (computing column block 2):
!>   col2_(1) W2: = A2
!>   col2_(3) W2: = W2 + (V2**T) * B2 = W2 + (B1**T) * B2
!>   col2_(4) W2: = T * W2
!>   col2_(5) B2: = B2 - V2 * W2 = B2 - B1 * W2
!>   col2_(7) A2: = A2 - W2
!>   (Steps col2_(2) and col2_(6) are skipped because V1 is Identity)
!>
!> If N <= K (computing column block 1):
!>   col1_(1) W1: = A1
!>   col1_(3) W1: = T * W1
!>   col1_(4) B1: = - V2 * W1 = - B1 * W1
!>   col1_(6) upper-triangular_of_(A1): = A1 - W1
!>   (Steps col1_(2) and col1_(5) are skipped because V1 is Identity)
!>   Also, note col1_(6_b) seems to imply updating only the upper triangular
!>   part of A1, while col1_(6) in case (A) suggests updating the whole A1.
!>   This might be an artifact of the decomposition or test setup.
!>
!> The combined algorithm summary:
!>
!> This section consolidates the steps for both cases (A) and (B).
!>
!> If N > K (Compute column block 2):
!>
!>   col2_(1)  W2: = A2
!>   if( IDENT != 'I' ) then
!>     col2_(2)  W2: = (V1**T) * W2
!>                   = (unit_lower_tr_of_(A1)**T) * W2
!>   end if
!>   col2_(3)  W2: = W2 + (V2**T) * B2 = W2 + (B1**T) * B2
!>   col2_(4)  W2: = T * W2
!>   col2_(5)  B2: = B2 - V2 * W2 = B2 - B1 * W2
!>   if( IDENT != 'I' ) then
!>     col2_(6)    W2: = V1 * W2 = unit_lower_tr_of_(A1) * W2
!>   end if
!>   col2_(7) A2: = A2 - W2
!>
!> else (N <= K) (Compute column block 1):
!>
!>   col1_(1) W1: = A1
!>   if( IDENT != 'I' ) then
!>     col1_(2) W1: = (V1**T) * W1
!>                 = (unit_lower_tr_of_(A1)**T) * W1
!>   end if
!>   col1_(3) W1: = T * W1
!>   col1_(4) B1: = - V2 * W1 = - B1 * W1
!>   if( IDENT != 'I' ) then
!>     col1_(5) square W1: = V1 * W1 = unit_lower_tr_of_(A1) * W1
!>     col1_(6_a) below_diag_of_(A1): =  - below_diag_of_(W1)
!>   end if
!>   col1_(6_b) up_tr_of_(A1): = up_tr_of_(A1) - up_tr_of_(W1)
!>
!> end if
!>
!> Interpretation of V1, V2, T, and IDENT:
!> - V1 seems to be related to the matrix A1.
!> - V2 seems to be related to the matrix B1.
!> - T is likely a diagonal matrix used in the transformation.
!> - IDENT indicates if V1 is an identity matrix.
!>
!> The notation `unit_lower_tr_of_(A1)` suggests that A1 itself is treated
!> as the unit lower triangular matrix V1. Similarly, `B1**T` or `B1` might be
!> used for V2.
!>
!> The purpose is to generate test matrices. This routine computes the result
!> of applying a block reflector to a matrix, where the matrix is partitioned
!> and the reflector's components (V1, V2, T) are derived from the partitions
!> of the input matrix itself, or are provided implicitly.
!>
!> The input parameters A, B, C, D to the subroutine SLARFB_GETT need to be
!> interpreted in the context of the description:
!>
!> Let the full matrix be X = [A B].
!> X is partitioned into:
!> A = [ A1 A2 ]
!>     [ B1 B2 ]
!>
!> The routine seems to take C and D as input which correspond to A2 and B2.
!> It then computes the updated A2 and B2 (stored back into C and D).
!> The matrices A1 and B1 (or related V1 and V2) are also needed for the
!> computation. These might be derived from A and B themselves.
!>
!> Let's assume the input parameters are:
!> A: K x K matrix (represents A1)
!> B: (M-K) x K matrix (represents B1)
!> C: K x (N-K) matrix (represents A2)
!> D: (M-K) x (N-K) matrix (represents B2)
!>
!> The routine computes the new A2 and B2 and stores them back into C and D.
!>
!> The steps described seem to be the core logic for applying a specific type
!> of block transformation used in testing.
!>
!> The notation `V2**T` and `B1**T` in step col2_(3) suggests that V2 is related
!> to B1, and its transpose is used.
!> The notation `V2 * W2` and `B1 * W2` in step col2_(5) implies V2 is related to B1.
!>
!> The description implies that the matrices A1, B1, V1, V2, T are all related
!> and derived from the input structure.

!> Let's focus on the translated code-like comments:
!>
!> Initial equation:
!> A2_in + (V2**T)*B2_in )
!>
!> The description details how A1, A2, B1, B2 are computed, using workspace
!> matrices W1 and W2.
!>
!> The logic is divided based on whether N > K or N <= K, and whether V1
!> is an identity matrix (IDENT == 'I') or not.
!>
!> The core operations involve matrix multiplications and additions/subtractions,
!> applying transformations based on V1, V2, T, and the transpose of V1.
!>
!> The notation `unit_lower_tr_of_(A1)` implies that A1 is assumed to be
!> a unit lower triangular matrix, and this is used as V1.
!>
!> The description seems to be describing the computation of the result of
!> applying a Householder reflection of the form Q = I - v t v^T to a matrix,
!> but in a blocked fashion.
!>
!> Let's consider the example calculation from the source:
!>
!> A = [ A1 A2 ] , B = [ B1 B2 ]
!>
!> Where A1 is KxK, B1 is (M-K)xK, A2 is Kx(N-K), B2 is (M-K)x(N-K).
!>
!> The algorithm computes column block 2 (A2, B2) first, then column block 1 (A1, B1).
!>
!> Step 1 (Compute column block 2, i.e., A2 and B2):
!> Requires workspace W2 of size Kx(N-K).
!>
!> If V1 is unit lower-triangular (IDENT != 'I'):
!>   1. W2 = A2
!>   2. W2 = (V1^T) * W2   (V1 is unit lower triangular, so V1^T is unit upper triangular)
!>   3. W2 = W2 + (V2^T) * B2 (Here V2 seems related to B1, so (B1^T) * B2)

!>   6. W2 = V1 * W2       (V1 is unit lower triangular, related to A1)
!>   7. A2 = A2 - W2

!>   1. W2 = A2
!>   3. W2 = W2 + (V2^T) * B2 (i.e., W2 + (B1^T) * B2)
!>   4. W2 = T * W2
!>   5. B2 = B2 - V2 * W2   (i.e., B2 - B1 * W2)
!>   7. A2 = A2 - W2

!> Requires workspace W1 of size KxK.
!>
!> If V1 is unit lower-triangular (IDENT != 'I'):
!>   1. W1 = A1
!>   2. W1 = (V1^T) * W1   (V1 is unit lower triangular, related to A1)
!>   3. W1 = T * W1
!>   4. B1 = - V2 * W1     (V2 is related to B1)
!>   5. W1 = V1 * W1       (V1 is unit lower triangular, related to A1)
!>   6. A1 = A1 - W1
!>
!> If V1 is identity (IDENT == 'I'):
