SYSTEMD-SLEEP.CONF(5) systemd-sleep.conf SYSTEMD-SLEEP.CONF(5)

NOM

systemd-sleep.conf, sleep.conf.d — Fichier de configuration pour la mise en veille et l'hibernation

SYNTAXE

/etc/systemd/sleep.conf
/run/systemd/sleep.conf
/usr/lib/systemd/sleep.conf
/etc/systemd/sleep.conf.d/*.conf
/run/systemd/sleep.conf.d/*.conf
/usr/lib/systemd/sleep.conf.d/*.conf

DESCRIPTION

systemd prend en charge quatre modes généraux d'économie d'énergie :

suspend

un état de basse consommation où l'exécution du système d'exploitation est mise en pause, et une perte totale d'alimentation peut entraîner une perte de données, et qui est rapide à entrer et sortir. Ceci correspond aux états suspend, veille ou freeze tels qu'interprétés par le noyau.

Ajouté dans la version 203.

hibernate

un état de basse consommation où l'exécution du système d'exploitation est mise en pause, et une perte totale d'alimentation n'entraîne pas une perte de données, et qui peut être lent à entrer et sortir. Ceci correspond à l'hibernation telle qu'interprétée par le noyau.

Ajouté dans la version 203.

hybrid-sleep

un état de basse consommation où l'exécution du système d'exploitation est mise en pause, qui peut être lent à entrer, et en cas de perte totale d'alimentation, n'entraîne pas une perte de données mais peut être plus lent à sortir dans ce cas. Ce mode est appelé suspend-to-both par le noyau.

Ajouté dans la version 203.

suspend-then-hibernate

Un état de basse consommation où le système est initialement suspendu (l'état est stocké dans la RAM). Lorsque le niveau de la batterie est trop bas (moins de 5%) ou qu'un certain délai est écoulé, le système est automatiquement réveillé puis mis en hibernation. Ceci établit un équilibre entre rapidité et sécurité.

Si le système n'a pas de batterie, il sera mis en hibernation après l'expiration de HibernateDelaySec=. Si non défini, la valeur par défaut est "2h".

Si le système a une batterie et que HibernateDelaySec= n'est pas défini, les alarmes de batterie faible (ACPI _BTP) sont d'abord utilisées pour détecter le pourcentage de batterie et réveiller le système pour l'hibernation. Si elles ne sont pas disponibles, ou si HibernateDelaySec= est défini, le système se réveillera régulièrement pour vérifier l'heure et détecter le pourcentage de batterie/taux de décharge. Le taux est utilisé pour planifier la prochaine détection. Si cela n'est pas non plus disponible, SuspendEstimationSec= est utilisé en dernier recours.

Ajouté dans la version 239.

Les paramètres de ces fichiers déterminent les chaînes qui seront écrites dans /sys/power/disk et /sys/power/state par systemd-sleep(8) lorsque systemd(1) tente de suspendre ou d'hiberner la machine. Voir systemd.syntax(7) pour une description générale de la syntaxe.

DIRECTORIES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi la configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des remplacements locaux peuvent également être créés en créant des fichiers drop-in, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est livré sous /etc/), cependant l'utilisation de fichiers drop-in pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration drop-in sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces drop-ins ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, indépendamment des sous-répertoires dans lesquels ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées telles qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets doivent personnaliser la configuration, ils peuvent installer des fichiers drop-in sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers drop-in doivent être utilisés pour remplacer les fichiers drop-in des paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités de drop-in pour permettre aux fournisseurs de systèmes d'exploitation de livrer des drop-ins dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les drop-ins de paquets remplacent accidentellement les drop-ins définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les drop-ins dans /usr/ et la plage 60-90 pour les drop-ins dans /etc/ et /run/, pour s'assurer que les drop-ins locaux et transitoires ont la priorité sur les drop-ins livrés par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Les options suivantes peuvent être configurées dans la section [Sleep] de /etc/systemd/sleep.conf ou d'un fichier sleep.conf.d :

AllowSuspend=, AllowHibernation=, AllowHybridSleep=, AllowSuspendThenHibernate=

Par défaut, tout mode d'économie d'énergie est annoncé si possible (c'est-à-dire si le noyau supporte ce mode, les ressources nécessaires sont disponibles). Ces commutateurs peuvent être utilisés pour désactiver des modes spécifiques.

Si AllowHibernation=no ou AllowSuspend=no est utilisé, cela implique AllowSuspendThenHibernate=no et AllowHybridSleep=no, car ces méthodes utilisent à la fois la mise en veille et l'hibernation en interne. AllowSuspendThenHibernate=yes et AllowHybridSleep=yes peuvent être utilisés pour remplacer et activer ces modes spécifiques.

Ajouté dans la version 240.

SuspendState=

La chaîne à écrire dans /sys/power/state par systemd-suspend.service(8). Plusieurs valeurs peuvent être spécifiées en séparant les valeurs multiples par un espace blanc. Elles seront essayées tour à tour, jusqu'à ce qu'une soit écrite sans erreur. Si aucune des écritures ne réussit, l'opération sera abandonnée.

L'ensemble des valeurs autorisées est déterminé par le noyau et est affiché dans le fichier lui-même (utilisez cat /sys/power/state pour l'afficher). Voir Basic sysfs Interfaces for System Suspend and Hibernation[2] pour plus de détails.

systemd-suspend-then-hibernate.service(8) utilise cette valeur lors de la suspension.

Ajouté dans la version 203.

HibernateMode=

La chaîne à écrire dans /sys/power/disk par systemd-hibernate.service(8). Plusieurs valeurs peuvent être spécifiées en séparant les valeurs multiples par un espace blanc. Elles seront essayées tour à tour, jusqu'à ce qu'une soit écrite sans erreur. Si aucune des écritures ne réussit, l'opération sera abandonnée.

L'ensemble des valeurs autorisées est déterminé par le noyau et est affiché dans le fichier lui-même (utilisez cat /sys/power/disk pour l'afficher). Voir la page de documentation du noyau Basic sysfs Interfaces for System Suspend and Hibernation[2] pour plus de détails.

systemd-suspend-then-hibernate.service(8) utilise la valeur de HibernateMode= lors de l'hibernation.

Ajouté dans la version 203.

MemorySleepMode=

La chaîne à écrire dans /sys/power/mem_sleep lorsque SuspendState=mem ou hybrid-sleep est utilisé. Plusieurs valeurs peuvent être spécifiées en séparant les valeurs multiples par un espace blanc. Elles seront essayées tour à tour, jusqu'à ce qu'une soit écrite sans erreur. Si aucune des écritures ne réussit, l'opération sera abandonnée. Par défaut, elle est vide, c'est-à-dire que le défaut du noyau ou l'option de ligne de commande du noyau mem_sleep_default= est respecté.

L'ensemble des valeurs autorisées est déterminé par le noyau et est affiché dans le fichier lui-même (utilisez cat /sys/power/mem_sleep pour l'afficher). Voir la page de documentation du noyau Basic sysfs Ierfaces pour la mise en veille système et l'hibernation[2] pour plus de détails.

Ajouté dans la version 256.

HibernateDelaySec=

Le temps pendant lequel le système reste en mode veille avant que le système ne passe automatiquement en mode hibernation. Uniquement utilisé par systemd-suspend-then-hibernate.service(8). Référez-vous à suspend-then-hibernate pour plus de détails sur la façon dont cette option interagit avec les autres options/l'état de la batterie du système.

Ajouté dans la version 239.

HibernateOnACPower=

Autoriser l'hibernation lorsque le système est alimenté par secteur. Uniquement utilisé par systemd-suspend-then-hibernate.service(8) lorsque HibernateDelaySec= est défini.

Si cette option est désactivée, le compte à rebours de HibernateDelaySec= ne commence qu'après la déconnexion de l'alimentation secteur, maintenant le système à l'état de veille sinon.

Cette option n'est effective que sur les systèmes dotés d'une batterie.

Ajouté dans la version 257.

SuspendEstimationSec=

L'alarme RTC réveillera le système après la durée spécifiée pour mesurer le niveau de capacité de la batterie du système et estimer le taux de décharge de la batterie. Uniquement utilisé par systemd-suspend-then-hibernate.service(8). Référez-vous à suspend-then-hibernate pour plus de détails sur la façon dont cette option interagit avec les autres options/l'état de la batterie du système.

Ajouté dans la version 253.

EXEMPLE : FREEZE

Exemple : pour exploiter le mode « freeze » ajouté dans Linux 3.9, on peut utiliser systemctl suspend avec

[Sleep]
SuspendState=freeze
