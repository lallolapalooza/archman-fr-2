NOM

slapo-retcode - surcouche de code de retour pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

La surcouche retcode de slapd(8) est utile pour tester le comportement des clients lorsque des réponses erronées et/ou inhabituelles générées par le serveur se produisent, par exemple des codes d'erreur, des références, des temps de réponse excessifs, etc.

Les réponses d'erreur sont générées selon différentes stratégies.

Dans le premier cas, toutes les opérations ciblées sur un sous-arbre configurable spécifique provoquent la recherche de l'objet lié au DN de la requête et la vérification de ses données de code de retour : un code de réponse, plus un message textuel optionnel, un délai configurable optionnel, un champ DN correspondant optionnel et, lorsque le code de réponse est « référence », une (liste de) référence(s).

Les codes de réponse bien connus des documents de suivi standard sont fournis dans retcode.conf, qui peut être inclus après l'instanciation de la surcouche.

Dans le second cas, les objets des classes héritant de errAbsObject, tels que errObject ou errAuxObject, lorsqu'ils sont retournés comme réponses intermédiaires d'une requête de recherche, sont transformés en la réponse dictée par leur contenu.

Un troisième mode provoque la recherche d'objets dans la base de données sous-jacente pour découvrir si leur classe hérite de errABsObject ; dans ce cas, leur contenu est utilisé pour calculer la réponse correspondante.

Le comportement est désactivé en utilisant le contrôle manageDSAit (RFC 3296) ; dans ce cas, l'objet résultant, présent dans le répertoire ou généré dynamiquement par la surcouche, ou contenu dans la requête, est traité comme d'habitude.

Les directives de configuration spécifiques à la surcouche retcode doivent être précédées de retcode-, afin d'éviter les conflits avec les directives spécifiques à la base de données sous-jacente ou à d'autres surcouches empilées. Les directives spécifiques suivantes peuvent être utilisées pour configurer la surcouche retcode :

retcode-parent <DN>
Cette directive définit le DN parent où résident les entrées générées dynamiquement. Si elle n'est pas définie, le suffixe de la base de données est utilisé.

retcode-item <RDN> <errCode> [op=<oplist>] [text=<message>] [ref=<referral>] [sleeptime=<sec>] [matched=<DN>] [unsolicited=<OID>[:<data>]] [flags=[pre|post-]disconnect[,...]]

Une entrée générée dynamiquement, située sous retcode-parent. L'errCode est le numéro du code de réponse ; il peut être dans n'importe quel format pris en charge par strtol(3). L'oplist optionnelle est une liste d'opérations qui provoquent la génération du code de réponse ; si elle est absente, toutes les opérations sont affectées. Le champ matched est le DN correspondant retourné avec l'erreur, tandis que le champ text est un message de diagnostic optionnel. Le champ ref n'est autorisé que pour le code de réponse référence. Le champ sleeptime oblige slapd(8) à attendre le nombre de secondes spécifié avant de poursuivre l'opération. Le champ unsolicited peut être utilisé pour provoquer le retour d'un message de réponse non sollicité RFC 4511 ; si OID n'est pas « 0 », une réponse étendue est générée, avec les données optionnelles ajoutées. Si flags contient disconnect, ou pre-disconnect, slapd(8) se déconnecte brusquement, sans préavis ; post-disconnect provoque la déconnexion immédiatement après l'envoi de la réponse appropriée.
retcode-indir
Active l'exploitation de errAbsObject stocké dans le répertoire. Peut entraîner une surcharge inutile importante.
retcode-sleep [-]<n>
Définit un temps de pause en secondes qui est passé avant de traiter réellement une opération. Si négatif, une durée aléatoire entre 0 et la valeur absolue de l'argument est utilisée.

SCHÉMA

La surcouche retcode utilise le schéma « code de retour » décrit ici. Ce schéma est spécifiquement conçu pour être utilisé avec cette surcouche et n'est pas destiné à être utilisé autrement. Il est également à noter que le schéma décrit ici est un travail en cours et est donc sujet à modification sans préavis. Le schéma est chargé automatiquement par la surcouche.

Le schéma comprend un certain nombre de classes d'objets et de types d'attributs associés tels que décrits ci-dessous.

Le code d'erreur :

( 1.3.6.1.4.1.4203.666.11.4.1.1
NOM ( 'errCode' )
DESC 'Code d'erreur LDAP'
EQUALITY integerMatch
ORDERING integerOrderingMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.27
SINGLE-VALUE )

Les opérations qui déclenchent le code de réponse :

( 1.3.6.1.4.1.4203.666.11.4.1.2
NOM ( 'errOp' )
DESC 'Opérations auxquelles s'applique l'objet errObject'
EQUALITY caseIgnoreMatch
SUBSTR caseIgnoreSubstringsMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.15 )

Le message texte :

( 1.3.6.1.4.1.4203.666.11.4.1.3
NOM ( 'errText' )
DESC 'Description textuelle de l'erreur LDAP'
EQUALITY caseIgnoreMatch
SUBSTR caseIgnoreSubstringsMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.15
SINGLE-VALUE )

Le temps d'attente avant que la réponse ne soit effectivement retournée au client :

( 1.3.6.1.4.1.4203.666.11.4.1.4
NOM ( 'errSleepTime' )
DESC 'Temps d'attente avant de retourner l'erreur'
EQUALITY integerMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.27
SINGLE-VALUE )

Le DN correspondant retourné au client :

( 1.3.6.1.4.1.4203.666.11.4.1.5
NOM ( 'errMatchedDN' )
DESC 'Valeur à retourner comme DN correspondant'
EQUALITY distinguishedNameMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.12
SINGLE-VALUE )

L'OID à retourner comme OID de réponse étendue dans les réponses non sollicitées RFC 4511 (« 0 » génère une réponse normale avec msgid défini à 0) :

( 1.3.6.1.4.1.4203.666.11.4.1.6
NOM ( 'errUnsolicitedOID' )
DESC 'OID à retourner dans la réponse non sollicitée'
EQUALITY objectIdentifierMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.38
SINGLE-VALUE )

La chaîne d'octets à retourner comme données de réponse étendue dans la réponse non sollicitée RFC 4511 :

( 1.3.6.1.4.1.4203.666.11.4.1.7
NOM ( 'errUnsolicitedData' )
DESC 'Données à retourner dans la réponse non sollicitée'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.40
SINGLE-VALUE )

Si VRAI, slapd(8) se déconnecte brusquement sans préavis ; si FAUX, il se déconnecte après avoir envoyé la réponse de manière appropriée :

( 1.3.6.1.4.1.4203.666.11.4.1.8
NOM ( 'errDisconnect' )
DESC 'Déconnexion sans préavis'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.7
SINGLE-VALUE )

La classe d'objet abstraite qui déclenche la surcouche :

( 1.3.6.1.4.1.4203.666.11.4.3.0
NOM ( 'errAbsObject' )
SUP top ABSTRACT
MUST ( errCode )
MAY ( cn $ description $ errOp $ errText $ errSleepTime
$ errMatchedDN ) )

La classe d'objet structurelle autonome pour les données spécifiquement créées :

( 1.3.6.1.4.1.4203.666.11.4.3.1
NOM ( 'errObject' )
SUP errAbsObject STRUCTURAL )

La classe d'objet auxiliaire pour modifier le comportement des objets existants :

( 1.3.6.1.4.1.4203.666.11.4.3.2
NOM ( 'errAuxObject' )
SUP errAbsObject AUXILIARY )

EXEMPLE

overlay         retcode
retcode-parent  "ou=RetCodes,dc=example,dc=com"
# retcode.conf est trouvé dans tests/data/ de l'arborescence source
include         ./retcode.conf
# Attendre 10 secondes, puis retourner succès (0x00)
retcode-item    "cn=Succès après 10 secondes" 0x00 sleeptime=10
# Attendre 10 secondes, puis retourner timelimitExceeded (0x03)
retcode-item    "cn=Limitation de temps après 10 secondes" 0x03 sleeptime=10

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration slapd par défaut

NAME

slapo-retcode – return code mapping backend overlay

SYNOPSIS

slapo-retcode is a backend overlay for slapd(8) that maps specific LDAP operation return codes to other return codes.

DESCRIPTION

The slapo-retcode overlay allows specific return codes from an operation to be mapped to other return codes. This is primarily useful for mapping specific operational attributes or entry attributes to standard LDAP return codes. For example, one may wish to map an entry attribute that indicates a specific condition to a LDAP_CONSTRAINT_VIOLATION.

The overlay is configured using the standard slapd-config(5) mechanisms.

SCHEMA

The overlay requires the following schema definition:

attributetype ( 2.23.135.1.2.3 NAME 'lsrMap'
    DESC 'LDAP return code mapping'
    EQUALITY caseIgnoreMatch
    SUBSTR caseIgnoreSubstringsMatch
    SYNTAX '1.3.6.1.4.1.1466.3.12' )

objectclass ( 2.23.135.1.2.4 NAME 'lsrMapping'
    DESC 'LDAP return code mapping object'
    SUP ( top )
    STRUCTURAL
    MUST ( cn $ lsrMap )
    MAY ( description $ seeAlso $ searchGuide $ isMemberOf $ member ) )

EXAMPLE

The following example shows how to configure the retcode overlay to map the presence of the lsrMap attribute with the value unwilling-to-perform to a return code of LDAP_UNWILLING_TO_PERFORM.

dn: cn=retcode,cn=overlay,cn=config
changetype: add
objectClass: top
objectClass: olcOverlayConfig
cn: retcode
# Make the overlay use the retcode backend
# This is required for slapo-retcode to function
# overlay: retcode
# Map the presence of 'lsrMap: unwilling-to-perform' to LDAP_UNWILLING_TO_PERFORM
lsrMap: unwilling-to-perform

FILES

libldap
The client library that provides the ldap_set_option().
slapd.conf
The configuration file for the slapd(8) daemon.

SEE ALSO
