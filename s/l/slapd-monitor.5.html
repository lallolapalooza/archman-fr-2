NOM

slapd-monitor - Backend de surveillance pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

Le backend monitor de slapd(8) n'est pas une base de données réelle ; s'il est activé, il est automatiquement généré et maintenu dynamiquement par slapd avec des informations sur l'état de fonctionnement du démon.

Pour inspecter toutes les informations de surveillance, effectuez une recherche de sous-arbre avec la base cn=Monitor, en demandant que les attributs "+" et "*" soient retournés. Le backend de surveillance produit principalement des attributs opérationnels, et LDAP ne retourne que les attributs opérationnels qui sont explicitement demandés. Demander l'attribut "+" est une extension qui demande tous les attributs opérationnels.

CONFIGURATION

Ces options de slapd.conf s'appliquent à la base de données backend monitor. C'est-à-dire qu'elles doivent suivre une ligne "database monitor" et précéder toute ligne "backend" ou "database" ultérieure.

Contrairement à la plupart des bases de données, la base de données monitor ne peut être instanciée qu'une seule fois, c'est-à-dire qu'une seule occurrence de "database monitor" peut apparaître dans le fichier slapd.conf(5). De plus, le suffixe de la base de données ne peut pas être défini explicitement au moyen de la directive suffix. Le suffixe est automatiquement défini sur "cn=Monitor".

La base de données monitor respecte les directives rootdn et rootpw, ainsi que les directives ACL habituelles, par exemple la directive access.

Les autres options de base de données sont décrites dans la page de manuel slapd.conf(5).

UTILISATION

L'utilisation est la suivante :

1) activer le backend monitor lors de la configuration :
configure --enable-monitor
2) activer la base de données monitor dans le fichier slapd.conf(5) :
database monitor
3) ajouter des ACL comme détaillé dans slapd.access(5) pour contrôler l'accès à la base de données, par exemple :
access to dn.subtree="cn=Monitor"
	by dn.exact="uid=Admin,dc=my,dc=org" write
	by users read
	by * none
4) s'assurer que le fichier core.schema est chargé.
Le backend monitor s'appuie sur certains types d'attributs de suivi standard qui doivent être déjà définis lors du démarrage du backend.

CONTRÔLE D'ACCÈS

Le backend monitor respecte les sémantiques de contrôle d'accès telles qu'indiquées dans slapd.access(5), y compris le privilège d'accès disclose, sur toutes les opérations actuellement implémentées.

LIMITATIONS CONNUES

Le backend monitor ne respecte pas les limites de taille/temps dans les opérations de recherche.

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

VOIR AUSSI

slapd.conf(5), slapd-config(5), slapd.access(5), slapd(8), ldap(3).
