NOM

slapo-otp - Module de mot de passe à usage unique OATH

SYNTAXE

moduleload otp.la

DESCRIPTION

Le module otp permet d'utiliser l'authentification par mot de passe à usage unique basé sur le temps, alias le style "authenticator", et par mot de passe à usage unique basé sur HMAC, en conjonction avec un mot de passe LDAP standard pour une authentification à deux facteurs.

Avec ce module, les utilisateurs utiliseraient leur mot de passe, suivi du mot de passe à usage unique dans l'invite de mot de passe pour s'authentifier.

Le mot de passe nécessaire à un utilisateur pour s'authentifier est calculé sur la base d'un compteur (le temps actuel dans le cas de TOTP) et d'une clé référencée dans l'entrée LDAP de l'utilisateur. Comme le mot de passe est basé sur le temps ou le nombre d'utilisations, il change périodiquement. Une fois utilisé, il ne peut plus être utilisé, ce qui rend les enregistreurs de frappe et les observateurs inutiles. Une application mobile, telle que Google Authenticator ou YubiKey (un proveur), peut être utilisée pour calculer le mot de passe à usage unique actuel de l'utilisateur, qui est exprimé sous forme d'un nombre (généralement à six chiffres).

Alternativement, la valeur peut être calculée par une autre application ayant accès à la clé de l'utilisateur et délivrée à l'utilisateur via SMS ou un autre canal. Lorsqu'il est invité à s'authentifier, l'utilisateur ajoute simplement le code fourni par le proveur à la fin de son mot de passe lors de l'authentification.

Cette implémentation est conforme aux normes RFC 4226 HOTP HMAC-Based One Time Passwords et RFC 6238 TOTP Time-based One Time Passwords et inclut la prise en charge des algorithmes HMAC SHA-1, SHA-256 et SHA-512.

La clé HMAC utilisée dans le calcul OTP est stockée dans l'entrée oathOTPToken référencée dans l'entrée LDAP de l'utilisateur et les paramètres sont stockés dans l'entrée oathOTPParams LDAP référencée dans le jeton.

CONFIGURATION

Une fois le module configuré sur la base de données, il interceptera les liaisons LDAP simples pour les utilisateurs dont l'entrée LDAP possède l'une des classes d'objets dérivées oathOTPUser. Les attributs reliant l'utilisateur et le secret partagé sont :

oathTOTPToken: <dn>
Obligatoire pour oathOTPUser, indique que l'entrée nommée est dédiée à contenir le secret du mot de passe à usage unique basé sur le temps et le dernier mot de passe utilisé.
oathHOTPToken: <dn>
Obligatoire pour oathHOTPUser, indique que l'entrée nommée est dédiée à contenir le secret du mot de passe à usage unique et le dernier mot de passe utilisé.
oathTOTPParams: <dn>
Obligatoire pour oathTOTPToken, indique que l'entrée nommée est dédiée à contenir les paramètres pour générer le secret du mot de passe à usage unique basé sur le temps : sa longueur et l'algorithme à utiliser, ainsi que la longueur de chaque intervalle de temps et la période de grâce.
oathHOTPParams: <dn>
Obligatoire pour oathHOTPToken, indique que l'entrée nommée est dédiée à contenir les paramètres pour générer le secret du mot de passe à usage unique : sa longueur et l'algorithme à utiliser, ainsi que le nombre autorisé de mots de passe à sauter.

Les parties suivantes du schéma OATH-LDAP sont implémentées.

Attributs généraux :

oathSecret: <data>
Le secret partagé est stocké ici sous forme de données brutes.
oathOTPLength: <longueur>
La longueur du mot de passe, généralement 6.
oathHMACAlgorithm: <OID>
L'OID de l'algorithme de hachage à utiliser, tel que défini dans la RFC 8018. Les algorithmes pris en charge incluent SHA1, SHA224, SHA256, SHA384 et SHA512.

Les attributs HOTP :

oathHOTPLookAhead: <nombre>
Le nombre de jetons HOTP successifs qui peuvent être ignorés.
oathHOTPCounter: <nombre>
L'ordre du dernier jeton HOTP utilisé avec succès par l'utilisateur.

Les attributs TOTP :

oathTOTPTimeStepPeriod: <secondes>
La durée de la période d'intervalle de temps pour le calcul TOTP.
oathTOTPLastTimeStep: <nombre>
L'ordre du dernier jeton TOTP utilisé avec succès par l'utilisateur.
oathTOTPTimeStepWindow: <nombre>
Le nombre de périodes de temps autour de l'heure actuelle à essayer lors de la vérification du mot de passe fourni par l'utilisateur.
oathTOTPTimeStepDrift: <nombre>
Si le client n'a pas fourni le bon jeton mais qu'il correspondait à oathTOTPTimeStepWindow ci-dessus, cet attribut enregistre le décalage actuel à fournir pour le décalage lent de l'horloge de l'appareil client.
