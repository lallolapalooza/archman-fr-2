NOM

sloccount - compter les lignes de code source (SLOC)

SYNTAXE

sloccount [--version] [--cached] [--append] [ --datadir répertoire ] [--follow] [--duplicates] [--crossdups] [--autogen] [--multiproject] [--filecount] [--wide] [--details] [ --effort F E ] [ --schedule F E ] [ --personcost coût ] [ --overhead frais ] [ --addlang langage ] [ --addlangall ] [--] répertoires

DESCRIPTION

sloccount compte les lignes physiques de code source (SLOC) contenues dans les descendants des répertoires spécifiés. Il détermine automatiquement quels fichiers sont des fichiers de code source et quelle langage informatique est utilisé dans chaque fichier. Par défaut, il résume les résultats SLOC et présente diverses estimations (comme l'effort et le coût de développement), mais sa sortie peut être contrôlée par diverses options.

Si vous donnez à sloccount une liste de deux répertoires ou plus, les comptages seront ventilés selon cette liste. Il y a une limitation importante : les noms de base des répertoires donnés en paramètres doivent être différents, car ces noms sont utilisés pour regrouper les informations résumées. Ainsi, vous ne pouvez pas exécuter "sloccount /usr/src/hello /usr/local/src/hello". Cette limitation ne s'applique qu'aux paramètres de sloccount - les sous-répertoires descendants des répertoires du haut peuvent avoir le même nom de base.

Si vous ne donnez à sloccount qu'un seul répertoire, sloccount essaie de trouver automatiquement une ventilation raisonnable à des fins de rapport (il produira donc un rapport utile). Dans ce cas, si le répertoire contient au moins deux sous-répertoires, ces sous-répertoires seront utilisés comme ventilation. Si le répertoire unique contient des fichiers ainsi que des répertoires (ou si vous donnez des fichiers comme paramètres à sloccount), ces fichiers seront assignés au répertoire "top_dir" afin que vous puissiez les distinguer du reste du contenu. Enfin, s'il existe un sous-répertoire nommé "src", ce sous-répertoire est à nouveau ventilé, avec tous les sous-répertoires supplémentaires préfixés par "src_". Ainsi, si le répertoire "X" a un sous-répertoire "src", qui contient un sous-répertoire "modules", sloccount rapportera un comptage distinct pour "src_modules".

sloccount considère normalement tous les descendants de ces répertoires, bien qu'il ignore les liens symboliques, sauf indication contraire.

sloccount est le programme frontal habituel du paquet d'outils nommé "SLOCCount". Notez que le nom du paquet entier a des majuscules, tandis que le nom de ce programme frontal n'en a pas.

sloccount rapportera normalement des estimations de temps de planification, d'effort et de coût, et pour les projets uniques, il estime également le nombre moyen de développeurs actifs. Ce ne sont que des estimations, pas des certitudes ; vous pouvez modifier les paramètres utilisés pour améliorer les estimations.

OPTIONS

--version
Rapporte le numéro de version de SLOCCount et quitte immédiatement. Cette option ne peut pas être combinée utilement avec une autre option.
--cached
Ne pas recalculer ; utiliser plutôt les résultats mis en cache d'une exécution précédente. Sans l'option --cached ou --append, sloccount supprime automatiquement le répertoire de données et le recrée.
--append
Ne pas supprimer les calculs précédents du répertoire de données ; ajouter plutôt l'analyse au contenu actuel du répertoire de données.
--datadir répertoire
Stocker ou utiliser des données mises en cache dans le répertoire de données donné ; la valeur par défaut est "~/.slocdata".
--follow
Suivre les liens symboliques.
--duplicates
Compter tous les doublons. Normalement, si des fichiers ont un contenu identique (déterminé par des valeurs de hachage MD5), un seul est compté.
--crossdups
Compter les doublons s'ils se produisent dans différentes parties de la ventilation. Ainsi, si le répertoire principal contient de nombreux projets différents, et que vous voulez que les doublons dans différents projets soient comptés dans chaque projet, choisissez cette option.
--autogen
Compter les fichiers de code source qui semblent être générés automatiquement. Normalement, ils sont exclus.
--multiproject
Les différents répertoires représentent des projets différents ; sinon, il est supposé que tout le code source appartient à un seul projet. Cela ne modifie pas le nombre total de fichiers ou les valeurs SLOC, mais cela affecte les estimations d'effort et de planification. Avec cette option, l'effort est calculé séparément pour chaque projet (puis additionné), et la planification est celle estimée du plus grand projet.
--filecount
Afficher le nombre de fichiers au lieu de SLOC.
--wide
Afficher dans le format "large" (séparé par des tabulations).
--details
Afficher les détails, c'est-à-dire les résultats pour chaque fichier de code source.
--effort F E
Modifier le facteur et l'exposant pour le modèle d'effort. L'effort (en personnes-mois) est calculé comme F*(SLOC/1000)^E.
--schedule F E
Modifier le facteur et l'exposant pour le modèle de planification. La planification (en mois) est calculée comme F*(effort)^E.
--personcost coût
Modifier le salaire annuel moyen à coût.
--overhead frais
Modifier la valeur des frais généraux à frais. Le coût estimé est calculé comme effort * coût_personne * frais_généraux.
--addlang langage
Ajouter un langage qui n'est pas considéré par défaut comme un "langage" à inclure dans les rapports. Actuellement, les seules valeurs légales pour langage sont "makefile", "sql" et "html". Ces fichiers ne sont normalement pas inclus dans les comptages SLOC, bien que leurs SLOC soient calculés en interne et qu'ils soient affichés dans les comptages de fichiers. Si vous souhaitez inclure plus d'un langage de ce type, faites-le en passant --addlang plusieurs fois, par exemple, --addlang makefile --addlang sql.
--addlangall
Ajouter tous les langages qui ne sont normalement pas inclus dans les rapports finaux.

NOTES

Comme pour de nombreux autres programmes utilisant des options de type Unix, les répertoires dont le nom commence par un trait d'union ("-") peuvent être mal interprétés comme des options. Si les répertoires à analyser peuvent commencer par un trait d'union, utilisez le double trait d'union ("--") pour indiquer la fin de la liste des options avant de lister les répertoires.

BOGUES

Les noms de fichiers contenant des sauts de ligne incorporés (dans les répertoires ou leurs descendants) ne seront pas gérés correctement ; ils seront interprétés comme des noms de fichiers séparés où les sauts de ligne sont insérés. Un attaquant pourrait empêcher sloccount de fonctionner en créant des noms de fichiers de la forme /répertoire/normal/ ... SAUTDELIGNE/dev/zero. De tels noms de fichiers sont extrêmement rares dans le code source car ils sont également difficiles à manipuler avec d'autres outils. Les futures versions de sloccount pourraient utiliser en interne des noms de fichiers séparés par des NUL (comme la commande -print0 de GNU find) pour résoudre ce problème.

Il existe de nombreux langages supplémentaires non encore pris en charge par SLOCCount.

SLOCCount ne rapporte que les lignes physiques de code source. Il serait très utile s'il pouvait également rapporter les lignes logiques de code, et peut-être d'autres métriques courantes comme les mesures de complexité de McCabe et la densité de complexité (complexité/SLOC pour chaque fonction ou procédure).

sloccount(1) — Manuel Arch Linux

NAME

sloccount - Compte le nombre de lignes de code source.

SYNOPSIS

sloccount [ options ] [ file ... ]

DESCRIPTION

SLOCCount est un programme de comptage de lignes de code source (Source Lines Of Code). Il est capable de comptabiliser les lignes de code dans un grand nombre de langages de programmation.

SLOCCount tente de distinguer le code source, les commentaires et les lignes vides. Il utilise un large ensemble de règles de reconnaissance de langages, et peut être configuré pour reconnaître des langages personnalisés. Il est conçu pour être plus précis que des outils plus simples.

Pour plus de détails, voir le site web de SLOCCount à http://www.dwheeler.com/sloccount. Notez que de la documentation plus détaillée est disponible à la fois sur le site web et dans le paquet SLOCCount.

OPTIONS

Les options suivantes sont disponibles :

—help
Affiche un message d'aide et quitte.
—version
Affiche la version du programme et quitte.
—details
Affiche le décompte détaillé par langage.
—skip-dirs=dir1,dir2,...
Ignore les répertoires spécifiés.
—skip-incl=glob
Ignore les fichiers qui correspondent au motif glob.
—skip-excl=glob
Ne compte pas les fichiers qui correspondent au motif glob.
—include-langs=lang1,lang2,...
N'inclut que les langages spécifiés.
—exclude-langs=lang1,lang2,...
Exclut les langages spécifiés.
—add-slocale=lang:file1[:file2]
Ajoute un nouveau langage et les fichiers associés.
—add-slocale-recursive=lang:dir
Ajoute un nouveau langage et compte récursivement les fichiers dans le répertoire spécifié.
—charset=charset
Spécifie le jeu de caractères des fichiers source.
—progress
Affiche la progression du comptage.

NOTES

SLOCCount peut être exécuté sur des répertoires entiers, auquel cas il parcourra récursivement les sous-répertoires.

BUGS

Aucun bug connu.

SEE ALSO

Voir le site web de SLOCCount à http://www.dwheeler.com/sloccount.
