NOM

slapo-chain - superpositions de chaînage pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

La superposition chain de slapd(8) permet le suivi automatique des renvois. Chaque fois qu'un renvoi est retourné (sauf pour les opérations de bind), il est suivi en utilisant une instance du backend ldap. Si des opérations sont effectuées avec une identité (c'est-à-dire après un bind), cette identité peut être affirmée lors du suivi des renvois grâce à la fonctionnalité d'assertion d'identité de back-ldap (voir slapd-ldap(5) pour les détails), qui est essentiellement basée sur le contrôle d'autorisation déléguée [RFC 4370]. Le suivi des renvois peut être contrôlé par le client en émettant le contrôle chaining (voir draft-sermersheim-ldap-chaining pour les détails.)

Les directives de configuration spécifiques à la superposition chain sont préfixées par chain-, afin d'éviter des conflits potentiels avec des directives spécifiques à la base de données sous-jacente ou à d'autres superpositions empilées.

Il y a très peu de directives spécifiques à la superposition chain; cependant, les directives relatives aux instances du backend ldap qui peuvent être implicitement instanciées par la superposition peuvent avoir une signification particulière lorsqu'elles sont utilisées conjointement avec cette superposition. Elles sont décrites dans slapd-ldap(5), et elles doivent également être préfixées par chain-.

Note : cette superposition est intégrée au backend ldap ; ce n'est pas un module distinct.

overlay chain
Cette directive ajoute la superposition chain à la base de données actuelle. La superposition chain peut être utilisée avec n'importe quelle base de données, mais elle est principalement destinée à être utilisée avec des bases de données locales qui peuvent retourner des renvois. Elle est inutile en conjonction avec les backends slapd-ldap et slapd-meta car ils exploitent déjà la fonctionnalité de suivi de renvois spécifique à libldap. [Note : cela pourrait changer à l'avenir, car les backends ldap(5) et meta(5) pourraient ne plus suivre les renvois de leur propre initiative.]
chain-cache-uri {FALSE|true}
Cette directive demande à la superposition chain de mettre en cache les connexions aux URIs analysées à partir des renvois qui ne sont pas prédéfinis, pour être réutilisées ultérieurement. Ces URIs héritent des propriétés configurées pour le slapd-ldap(5) sous-jacent avant toute occurrence de la directive chain-uri ; en gros, elles sont chaînées anonymement.
chain-chaining [resolve=<r>] [continuation=<c>] [critical]
Cette directive active le contrôle chaining (voir draft-sermersheim-ldap-chaining pour les détails) avec les comportements de résolution et de continuation souhaités, ainsi que la criticité. Le paramètre resolve fait référence au comportement lors de la découverte d'une ressource, c'est-à-dire lors de l'accès à l'objet indiqué par le DN de la requête ; le paramètre continuation fait référence au comportement lors du traitement des réponses intermédiaires, ce qui est principalement significatif pour l'opération de recherche, mais peut affecter les opérations étendues qui retournent des réponses intermédiaires. Les valeurs r et c peuvent être n'importe lesquelles parmi chainingPreferred, chainingRequired, referralsPreferred, referralsRequired. Si le drapeau critical affecte la criticité du contrôle s'il est fourni. [Ce contrôle est expérimental et son support peut changer à l'avenir.]
chain-max-depth <n>
Dans le cas où un renvoi est retourné pendant le suivi de renvoi, le suivi ultérieur se fait au maximum à <n> niveaux de profondeur. Défini sur 1 (par défaut) pour désactiver le suivi de renvoi ultérieur.
chain-return-error {FALSE|true}
En cas d'échec du suivi de renvoi, l'erreur réelle est retournée au lieu du renvoi d'origine. S'il y a plusieurs URIs de renvoi, seule la première erreur est retournée. Ce comportement peut ne pas être toujours approprié ni souhaitable, car les échecs dans le suivi de renvoi pourraient être mieux résolus par le client (par exemple, lorsqu'ils sont causés par des problèmes d'authentification distribuée).
chain-uri <ldapuri>
Cette directive instancie une nouvelle base de données ldap sous-jacente et lui indique quelle URI contacter pour suivre les renvois. Contrairement à ce qui est indiqué dans slapd-ldap(5), une seule URI peut apparaître après cette directive ; toutes les directives slapd-ldap(5) suivantes préfixées par chain- font référence à cette instance spécifique d'un serveur distant.

Les directives de configuration de la base de données ldap sous-jacente peuvent également être requises, comme le montre cet exemple :

overlay                 chain
chain-rebind-as-user    FALSE
chain-uri               "ldap://ldap1.example.com"
chain-rebind-as-user    TRUE
chain-idassert-bind     bindmethod="simple"
                        binddn="cn=Auth,dc=example,dc=com"
                        credentials="secret"
                        mode="self"
chain-uri               "ldap://ldap2.example.com"
chain-idassert-bind     bindmethod="simple"
                        binddn="cn=Auth,dc=example,dc=com"
                        credentials="secret"
                        mode="none"

Toutes les directives valides pour la base de données ldap peuvent être utilisées ; voir slapd-ldap(5) pour les détails. Des occurrences multiples de la directive chain-uri peuvent apparaître, pour définir plusieurs URIs "de confiance" où les opérations avec assertion d'identité sont chaînées. Toutes les URIs non listées dans la configuration sont chaînées anonymement. Toutes les directives slapd-ldap(5) apparaissant avant la première occurrence de chain-uri sont héritées par toutes les URIs, sauf si elles sont spécifiquement remplacées à l'intérieur de chaque configuration d'URI.

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

VOIR AUSSI

slapd.conf(5), slapd-config(5), slapd-ldap(5), slapd(8).
