SLAPD.PLUGIN(5) Manuel des formats de fichiers SLAPD.PLUGIN(5)

NOM

slapd.plugin - configuration des plugins pour slapd, le démon LDAP autonome

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

Le fichier slapd.conf(5) contient les informations de configuration du démon slapd(8). Ce fichier de configuration est également utilisé par les outils SLAPD slapadd(8), slapcat(8), slapmodify(8), et slapindex(8).

Le fichier slapd.conf se compose d'une série d'options de configuration globales qui s'appliquent à slapd dans son ensemble (y compris tous les backends), suivies de zéro ou plusieurs définitions de backend de base de données qui contiennent des informations spécifiques à une instance de backend.

Le format général de slapd.conf est le suivant :

    # commentaire - ces options s'appliquent à toutes les bases de données
    <options de configuration globales>
    # première définition de base de données & options de configuration
    database    <type de backend 1>
    <options de configuration spécifiques au backend 1>
    # définitions de base de données et options de configuration suivantes
    ...

Si slapd est compilé avec --enable-slapi, il supporte les plugins conformément aux Netscape's Directory Server Plug-Ins. La version 4 de l'API est actuellement implémentée, avec quelques extensions de la version 5.

Les données globales et spécifiques à la base de données peuvent contenir des informations sur les plugins. Les plugins associés à une base de données spécifique sont appelés avant les plugins globaux. Cette page de manuel détaille les instructions de configuration de slapd(8) qui affectent le chargement des plugins SLAPI.

Les arguments qui doivent être remplacés par du texte réel sont affichés entre crochets <>.

La structure des directives de plugin est

plugin <type> <chemin_lib> <fonction_init> [<arguments>]
Charge un plugin du type spécifié pour la base de données actuelle.

Le <type> peut être l'un des suivants : preoperation, qui est exécuté avant le traitement de l'opération pour la base de données spécifiée ; postoperation, qui est exécuté après le traitement de l'opération pour la base de données spécifiée ; extendedop, qui est utilisé lors de l'exécution d'une opération étendue ; ou object. Ce dernier est utilisé pour des types divers tels que les plugins ACL, d'attributs calculés et de réécriture de filtres de recherche.

L'argument <chemin_lib> spécifie le chemin vers l'objet chargeable du plugin ; si un chemin relatif est donné, l'objet est recherché selon le paquet de chargement dynamique sous-jacent (libtool's ltdl est utilisé).

L'argument <fonction_init> spécifie quel symbole doit être appelé lorsque le plugin est chargé pour la première fois. Cette fonction doit enregistrer les fonctions fournies par le plugin pour les opérations désirées. Il convient de noter que c'est cette fonction d'initialisation, et non le type de plugin spécifié comme premier argument, qui détermine quand et pour quelles opérations le plugin sera invoqué. La liste optionnelle <arguments> est passée à la fonction d'initialisation.

pluginlog <fichier>
Spécifie un chemin alternatif pour le fichier journal du plugin (par défaut : /var/lib/openldap/errors).
modulepath <spécification_chemin>
Cette instruction définit le chemin de chargement des modules pour les backends chargeables dynamiquement, comme décrit dans slapd.conf(5) ; cependant, étant donné que les backends chargeables dynamiquement et les plugins SLAPI utilisent la même bibliothèque sous-jacente (libtool's ltdl), sa valeur affecte également le chemin de recherche des plugins. En général, le chemin de recherche est composé de chemins séparés par des deux-points ; généralement, le chemin défini par l'utilisateur est recherché en premier ; puis la valeur de la variable d'environnement LTDL_LIBRARY_PATH, si elle est définie, est utilisée ; enfin, le chemin de chargement dynamique spécifique au système est tenté (par exemple, sous Linux, la valeur de la variable d'environnement LD_LIBRARY_PATH). Veuillez lire attentivement la documentation de ltdl car son comportement est très dépendant de la plateforme.

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd
/var/lib/openldap/errors
fichier journal par défaut des plugins
