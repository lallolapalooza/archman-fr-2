NOM

slapo-lastbind - overlay lastbind pour slapd

SYNOPSIS

ETCDIR/slapd.conf

DESCRIPTION

L'overlay lastbind pour slapd(8) permet d'enregistrer l'horodatage de la dernière authentification réussie sur des entrées dans l'annuaire, dans l'attribut authTimestamp. L'overlay peut être configuré pour mettre à jour cet horodatage uniquement s'il est plus ancien qu'une valeur donnée, évitant ainsi un grand nombre d'opérations d'écriture pénalisant les performances. Un exemple d'utilisation de cet overlay serait de détecter les comptes inutilisés.

Maintenant qu'OpenLDAP prend nativement en charge la plupart de ces fonctionnalités, stocker la valeur dans pwdLastSuccess pour mieux interagir avec le projet de politique de mots de passe Behera draft 10. Sauf si vous avez besoin de lastbind_forward_updates, vous devriez envisager d'utiliser cette dernière à la place.

CONFIGURATION

Les directives de configuration spécifiques à l'overlay lastbind doivent être préfixées par lastbind-, afin d'éviter des conflits potentiels avec les directives spécifiques à la base de données sous-jacente ou à d'autres overlays empilés.

overlay lastbind
Cette directive ajoute l'overlay lastbind à la base de données actuelle, voir slapd.conf(5) pour les détails.

Cette option de configuration slapd.conf est définie pour l'overlay lastbind. Elle doit apparaître après la directive overlay:

lastbind-precision <secondes>
La valeur <secondes> est le nombre de secondes après lesquelles mettre à jour l'attribut authTimestamp dans une entrée. Si la valeur existante de authTimestamp est plus ancienne que <secondes>, elle ne sera pas modifiée. Si cette option de configuration est omise, l'attribut authTimestamp est mis à jour à chaque opération de liaison réussie.
lastbind_forward_updates
Spécifie que les mises à jour de l'attribut authTimestamp sur un consommateur doivent être transmises à un fournisseur au lieu d'être écrites directement dans la base de données locale du consommateur. Ce réglage est uniquement utile sur un consommateur de réplication, et nécessite également que le réglage updateref et l'overlay chain soient correctement configurés.

EXEMPLE

Cet exemple configure l'overlay lastbind pour enregistrer authTimestamp dans toutes les entrées d'une base de données, avec une précision d'une semaine. Ajoutez ce qui suit à slapd.conf(5):

    database <database>
    # ...
    overlay lastbind
    lastbind-precision 604800

slapd doit également charger lastbind.la, s'il est compilé comme module d'exécution;

FICHIERS

VOIR AUSSI

slapd.conf(5), slapd(8).

Proposition de politique de mots de passe LDAP de l'IETF par P. Behera, L. Poitou et J. Sermersheim : documentée dans le document de l'IETF "draft-behera-ldap-password-policy-10.txt".

L'overlay slapo-lastbind(5) supporte la configuration dynamique via back-config.
