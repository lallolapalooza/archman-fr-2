NOM

slurmctld - Le démon de gestion central de Slurm.

SYNTAXE

slurmctld [OPTIONS...]

DESCRIPTION

slurmctld est le démon de gestion central de Slurm. Il surveille tous les autres démons Slurm et ressources, accepte les travaux (jobs) et alloue des ressources à ces travaux. Compte tenu de la fonctionnalité critique de slurmctld, il peut y avoir un serveur de secours pour assumer ces fonctions dans le cas où le serveur principal échouerait.

OPTIONS

-c
Efface toutes les états précédents de slurmctld à partir de son dernier point de contrôle. Avec cette option, tous les travaux, y compris ceux en cours d'exécution et ceux mis en file d'attente, ainsi que tous les états des nœuds, seront supprimés. Sans cette option, les travaux précédemment en cours seront préservés, ainsi que les états des nœuds DOWN, DRAINED et DRAINING et le champ Reason associé à ces nœuds. NOTE : Il est rare que vous souhaitiez utiliser cela en production car tous les travaux seront arrêtés.
-D
Exécute slurmctld au premier plan avec la journalisation copiée sur stderr. Cela limite la résilience de 'scontrol reconfigure' et doit être évité en production.
-f <fichier>
Lit la configuration depuis le fichier spécifié. Voir les NOTES ci-dessous.
-h
Aide ; affiche un bref résumé des options de la commande.
-i
Ignore les erreurs trouvées lors de la lecture des fichiers d'état au démarrage. Attention : L'utilisation de cette option entraînera la perte des données qui n'ont pas pu être récupérées des fichiers d'état.
-L <fichier>
Écrit les messages de journal dans le fichier spécifié.
-n <valeur>
Définit la valeur nice du démon à la valeur spécifiée, généralement un nombre négatif.
-r
Récupère l'état partiel du dernier point de contrôle : informations sur les travaux et l'état DOWN/DRAIN des nœuds et leur raison. Aucun état de partition n'est récupéré. C'est l'action par défaut.
-R
Récupère l'état complet du dernier point de contrôle : état des travaux, des nœuds, des partitions et paramètres d'économie d'énergie. Sans cette option, les travaux précédemment en cours seront préservés, ainsi que les états des nœuds DOWN, DRAINED et DRAINING et le champ Reason associé à ces nœuds. Aucun autre état de nœud ou de partition ne sera préservé.
-s
Change le répertoire de travail de slurmctld vers le chemin SlurmctldLogFile si possible, ou vers Slurm's StateSaveLocation sinon. Si les deux échouent, il se rabattra sur /var/tmp.
--systemd
Utiliser lors du démarrage du démon avec systemd. Cela permettra à slurmctld de notifier systemd du nouveau PID lors de l'utilisation de 'scontrol reconfigure'.

NOTE : Les options User et Group dans le fichier d'unité systemd de slurmctld doivent toutes deux spécifier le SlurmUser.

-v
Fonctionnement verbeux. Plusieurs v peuvent être spécifiés, chaque 'v' au-delà du premier augmentant la verbosité, jusqu'à 6 fois (c'est-à-dire -vvvvvv).
-V
Affiche les informations de version et quitte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour remplacer les paramètres compilés dans slurmctld.

ABORT_ON_FATAL
Lorsqu'une erreur fatale est détectée, utilisez abort() au lieu de exit() pour terminer le processus. Cela permet de capturer des traces sans recompiler Slurm.
SLURM_CONF
L'emplacement du fichier de configuration de Slurm. Ceci est remplacé en nommant explicitement un fichier de configuration sur la ligne de commande.
SLURM_DEBUG_FLAGS
Spécifie les indicateurs de débogage à utiliser par le planificateur. Voir DebugFlags dans la page de manuel slurm.conf(5) pour une liste complète des indicateurs. La variable d'environnement a la priorité sur le paramètre dans slurm.conf.

Serveur HTTP

Sauf si désactivé via CommunicationParameters=disable_http dans slurm.conf, slurmctld acceptera les requêtes entrantes conformes HTTP/1.1 sur tout socket écoutant tel que configuré par SlurmctldPort dans slurm.conf. L'authentification des requêtes HTTP n'est pas prise en charge. Le chiffrement TLS est facultativement pris en charge sans nécessiter TLSType dans slurm.conf. Les points de terminaison suivants sont actuellement pris en charge :

GET /
Obtenir la liste des points de terminaison.
GET /healthz
Vérifie si slurmctld s'est chargé correctement.
GET /livez
Vérifie si slurmctld s'est chargé correctement.
GET /readyz
Vérifie si slurmctld est prêt à accepter les RPC entrants.
GET /metrics/jobs
Obtenir les métriques des travaux.
GET /metrics/nodes
Obtenir les métriques des nœuds.
GET /metrics/partitions
Obtenir les métriques des partitions.
GET /metrics/scheduler
Retourne les métriques du planificateur.
GET /metrics/jobs-users-accts
Retourne les métriques des travaux par utilisateur et par compte.

SIGNAL

SIGTERM SIGINT SIGQUIT
slurmctld s'arrêtera proprement, en sauvegardant son état courant dans le répertoire de sauvegarde d'état.
SIGABRT
slurmctld s'arrêtera proprement, en sauvegardant son état courant, et effectuera un vidage de noyau (core dump).
SIGHUP
Recharge les fichiers de configuration de slurm, similaire à 'scontrol reconfigure'.
SIGTSTP
Arrête le processus depuis un terminal. Ceci arrête également slurmscriptd.
SIGUSR2
Relit le niveau de journalisation depuis les configurations, puis rouvre le fichier journal. Ceci devrait être utilisé lors de la configuration de logrotate(8).
SIGPROF
Journalise l'état du gestionnaire de connexion lorsque le niveau de débogage est au moins 'info'.
SIGCHLD SIGUSR1 SIGXCPU SIGPIPE SIGALRM
Ces signaux sont explicitement ignorés.

NOTES

Il peut être utile d'expérimenter avec différents paramètres de configuration spécifiques à slurmctld en utilisant un fichier de configuration distinct (par exemple, les délais d'attente). Cependant, ce fichier de configuration spécial ne sera pas utilisé par le démon slurmd ou les programmes Slurm, à moins que vous ne leur indiquiez spécifiquement de l'utiliser. Si vous souhaitez modifier les ports de communication, l'emplacement du système de fichiers temporaire ou d'autres paramètres utilisés par d'autres composants Slurm, modifiez le fichier de configuration commun, slurm.conf.
