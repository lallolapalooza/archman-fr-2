NOM

slogverify --- Vérifie les journaux cryptographiquement sécurisés.

SYNOPSIS

slogverify [options] [arguments]

DESCRIPTION

L'utilitaire slogverify est utilisé pour vérifier l'intégrité des journaux cryptographiquement sécurisés et pour déchiffrer les entrées de journal produites dans un environnement de journalisation sécurisé syslog-ng OSE.

  • Mode normal : slogverify -k <fichier clé hôte> -m <fichier MAC d'entrée> <fichier d'entrée> <fichier de sortie> [tampons]
  • Mode itératif : slogverify -i -p <clé hôte précédente> -r <MAC précédent> -m <MAC actuel> <fichier d'entrée> <fichier de sortie> [tampons]

ARGUMENTS

•
fichier d'entrée

Un fichier journal chiffré de l'environnement de journalisation sécurisé de syslog-ng OSE qui est vérifié.

•
fichier de sortie

Le fichier qui contient les entrées de journal en texte clair après déchiffrement et vérification.

•
tampons

Nombre optionnel de tampons d'entrée. Le nombre de tampons peut être utilisé pour ajuster les performances dans le cas où le fichier journal à vérifier est très volumineux et ne peut pas être traité en une seule fois. C'est un nombre positif d'entrées de journal qui peuvent être conservées en mémoire pendant la vérification. Le nombre minimum est de 10 et le nombre maximum est de 4294967295. Si cet argument n'est pas fourni, la valeur par défaut de 1000 est utilisée.

OPTIONS

•
--iterative ou -i

Mode itératif. Ceci est utile dans le cas où les fichiers journaux sont copiés périodiquement du système sur lequel ils ont été générés vers un collecteur central. Comme la rotation des journaux, c'est-à-dire l'écrasement des fichiers journaux pour préserver l'espace, ne peut pas être effectuée dans un environnement de journalisation sécurisé, le mode itératif peut être utilisé à la place. Cela fonctionne comme suit : Si une certaine limite de stockage est atteinte, le fichier journal ainsi que le fichier clé hôte et le fichier MAC sont copiés vers une nouvelle destination et l'ancien fichier est supprimé. La vérification est alors effectuée par itérations, c'est-à-dire séparément pour chaque fichier récupéré de l'hôte journal. Pour que cela fonctionne, il est important de toujours récupérer les fichiers clé hôte et MAC correspondants. Le processus peut être automatisé, par exemple en appelant slogverify en mode itératif à partir d'un script.

•
--key-file ou -k

La clé hôte initiale (k0). Cette option est utilisée en mode normal uniquement.

•
--mac-file ou -m

Le fichier MAC actuel utilisé.

•
--prev-key-file ou -p

La clé hôte correspondant au fichier journal précédent. Cette option ne peut être utilisée qu'en mode itératif. En théorie, il peut s'agir de la clé hôte initiale (k0) mais l'utilisation de cette clé pourrait générer des avertissements, car l'écart entre la première entrée de journal jamais enregistrée (entrée de journal 0) et la première entrée de journal du fichier journal actuel pourrait être important.

•
--prev-mac-file ou -r

Le fichier MAC du fichier journal précédent. Cette option ne peut être utilisée qu'en mode itératif.

•
--help ou -h

Affiche un message d'aide.

FICHIERS
