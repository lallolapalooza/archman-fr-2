NOM

slapo-remoteauth - Délègue les requêtes d'authentification à des annuaires distants, par ex. Active Directory

SYNOPIS

/etc/openldap/slapd.conf

DESCRIPTION

La superposition remoteauth de slapd(8) permet l'authentification par transfert vers des serveurs d'annuaire distants, par ex. Active Directory, pour les opérations de liaison simple LDAP. L'entrée LDAP locale référencée dans l'opération de liaison est mappée à son homologue dans l'annuaire distant. Une opération de liaison LDAP est effectuée sur l'annuaire distant et les résultats sont renvoyés en fonction de ceux de l'opération distante.

Un serveur slapd configuré avec la superposition remoteauth traite une requête d'authentification en fonction de la présence de userPassword dans l'entrée locale. Si userPassword est présent, l'authentification est effectuée localement, sinon la superposition remoteauth effectue la requête d'authentification auprès du serveur d'annuaire distant configuré.

CONFIGURATION

Les options suivantes peuvent être appliquées à la superposition remoteauth dans le fichier slapd.conf. Toutes les options doivent suivre la directive overlay remoteauth.

overlay remoteauth
Cette directive ajoute la superposition remoteauth à la base de données actuelle, voir slapd.conf(5) pour les détails.
remoteauth_dn_attribute <dnattr>
Attribut de l'entrée locale utilisé pour stocker le DN de liaison vers un serveur d'annuaire distant.
remoteauth_mapping <domaine> <nom_hote|URI LDAP|file:///chemin/vers/liste_des_noms_hotes>
Pour un déploiement non-Windows, un domaine peut être considéré comme une collection d'un ou plusieurs hôtes sur lesquels le serveur slapd s'authentifie au nom des utilisateurs qui s'authentifient. Pour un nom de domaine donné, le mappage spécifie le(s) serveur(s) cible(s), par ex., le(s) contrôleur(s) de domaine Active Directory, auquel se connecter via LDAP. Le deuxième argument peut être donné soit comme un nom d'hôte, une URI LDAP, ou un fichier contenant une liste de noms d'hôtes/URI, un par ligne. Les noms d'hôtes sont essayés en séquence jusqu'à ce que la connexion réussisse.

Cette option peut être fournie plusieurs fois pour fournir des informations de mappage pour différents domaines. Par exemple :

    remoteauth_mapping americas file:///chemin/vers/americas.domain.hosts
    remoteauth_mapping asiapacific file:///chemin/vers/asiapacific.domain.hosts
    remoteauth_mapping emea emeadc1.emea.example.com
remoteauth_domain_attribute <attr>
Attribut de l'entrée locale qui spécifie le nom du domaine, tout texte après "\" ou ":" est ignoré.
remoteauth_default_domain <domaine par défaut>
Domaine par défaut.
remoteauth_default_realm <serveur>
Serveur de secours auquel se connecter pour les domaines non spécifiés dans remoteauth_mapping.
remoteauth_retry_count <nombre>
Nombre de tentatives de connexion. Par défaut, 3.
remoteauth_store <on|off>
Indique s'il faut stocker le mot de passe dans l'entrée locale lors d'une liaison réussie. Par défaut, off.

remoteauth_tls [starttls=yes] [tls_cert=<fichier>] [tls_key=<fichier>] [tls_cacert=<fichier>] [tls_cacertdir=<chemin>] [tls_reqcert=never|allow|try|demand] [tls_reqsan=never|allow|try|demand] [tls_cipher_suite=<chiffrements>] [tls_ecname=<noms>] [tls_crlcheck=none|peer|all]

Configuration TLS spécifique à remoteauth, voir slapd.conf(5) pour plus de détails sur chacun des paramètres et les valeurs par défaut.
remoteauth_tls_peerkey_hash <nom_hote> <nom_hash>:<base64 du hash de la clé publique>
Mappage entre les noms d'hôtes des serveurs distants et leurs hashes de clés publiques. Un seul mappage par nom d'hôte est pris en charge et si des épingles sont spécifiées, tous les hôtes doivent être épinglés. S'il est défini, l'épinglage est en vigueur, que la validation du nom du certificat soit activée ou non par tls_reqcert.

EXEMPLE

Un exemple typique de configuration de la superposition remoteauth pour AD est montré ci-dessous (en tant qu'extrait de slapd.conf(5)) :

   database <database>
   #...
   overlay remoteauth
   remoteauth_dn_attribute seeAlso
   remoteauth_domain_attribute associatedDomain
   remoteauth_default_realm americas.example.com
   remoteauth_mapping americas file:///home/ldap/etc/remoteauth.americas
   remoteauth_mapping emea emeadc1.emea.example.com
   remoteauth_tls starttls=yes tls_reqcert=demand tls_cacert=/home/ldap/etc/example-ca.pem
   remoteauth_tls_peerkey_hash ldap.americas.tld sha256:Bxv3MkLoDm6gt/iDfeGNdNNqa5TTpPDdIwvZM/cIgeo=

Où seeAlso contient le DN de liaison AD pour l'utilisateur, associatedDomain contient l'ID de domaine Windows sous la forme <nom_domaine_NT>:<nom_utilisateur_NT> dans lequel tout ce qui suit, y compris ":", est ignoré.
