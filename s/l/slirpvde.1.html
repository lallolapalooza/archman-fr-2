SLIRPVDE(1) Manuel des commandes générales SLIRPVDE(1)

NOM

slirpvde - Interface réseau Ethernet distribuée virtuelle Slirp

SYNTAXE

slirpvde OPTIONS [ répertoiresocket ]

DESCRIPTION

slirpvde est une interface Slirp pour un réseau VDE.

Slirpvde connecte toutes les unités (machines virtuelles ou réelles) au réseau de l'hôte où s'exécute slirpvde, comme s'il s'agissait d'un routeur NAT/Masquerading. La route par défaut est le nœud 2 (10.0.2.2 dans la configuration réseau par défaut) et le DNS est ré-mappé sur le nœud 3 (10.0.2.3).

Slirpvde s'exécute avec des privilèges utilisateur standards (pas besoin d'accès root) : toutes les connexions sont régénérées par slirpvde lui-même.

IPv4 uniquement. IPv6 n'est pas encore pris en charge (sera pris en charge lorsque slirpvde sera réécrit en utilisant la pile réseau LWIPv6).

OPTIONS

-s, --sock, --socket, --vdesock, --unix répertoire
spécifie le répertoire du commutateur VDE (par défaut /var/run/vde.ctl). Le répertoire du commutateur VDE peut également être spécifié à la fin de la commande, comme illustré par le paramètre optionnel répertoiresocket dans la section syntaxe, ci-dessus. Lorsque '-' est utilisé à la place du répertoire du commutateur VDE, slirpvde fonctionne comme un bouchon (voir vde_plug(1)). La commande :

dpipe vde_plug = ssh remote.machine.org slirpvde -

ce qui est équivalent à :

dpipe vde_plug = ssh remote.machine.org slirpvde -s -

connecte le commutateur local par défaut à un slirpvde distant.
-p, --pidfile nomfichier
spécifie le nom du fichier contenant le PID de slirpvde.
-g, --group groupe
spécifie le groupe UNIX pour le socket de communication VDE.
-m, --mod mode
spécifie les permissions UNIX octales pour le socket de communication VDE.
-P, --port port
spécifie le port du commutateur VDE auquel slirpvde doit être connecté.
-d, --daemon
détache du terminal et exécute slirpvde en arrière-plan.
-H, --host adresse [ / masquage ]
spécifie l'adresse de l'hôte (par défaut 10.0.2.2/24). Cette option définit automatiquement le réseau. Par exemple :
-H 192.168.55.1
ou :
--host 10.1.2.3/16
La valeur par défaut pour masquage est 24. Si la partie hôte de l'adresse est zéro, cette option définit uniquement le réseau. L'adresse hôte par défaut est l'adresse 2, le proxy DNS par défaut est le 3. Par exemple :
-H 10.1.0.0/16
définit uniquement le réseau. L'adresse hôte est 10.1.0.2 et le proxy DNS 10.1.0.3.
-n, --network adresse [ / masquage ]
spécifie l'adresse réseau (par défaut 10.0.2.0/24). Obsolète, elle a été incluse uniquement pour la compatibilité ascendante. C'est un alias de -H, --host.
-N, --dns adresse
Spécifie l'adresse du serveur DNS. Si c'est une adresse à l'intérieur du réseau slirp, slirvde agit comme un proxy DNS sur cette adresse. Le serveur DHCP de slirpvde envoie cette adresse DNS aux clients. Par défaut, il s'agit de l'hôte numéro 3 dans le réseau slirpvde. En utilisant le réseau par défaut, c'est 10.0.2.3. Attention : n'utilisez pas la même adresse pour l'hôte et le DNS.
-D, --dhcp
active le serveur DHCP pour l'autoconfiguration réseau de toutes les unités connectées au VDE. Il est possible de spécifier l'adresse de départ attribuée par le serveur DHCP comme suit :
--dhcp=10.1.1.44
DHCP attribue des adresses à partir du numéro d'hôte 15 par défaut. En utilisant le réseau par défaut, il commence à 10.0.2.15
-L port:hote_vde:port_hote_vde
spécifie une redirection de port TCP. Tous les paquets TCP reçus par l'hôte exécutant slirpvde sur le port port seront transférés vers hote_vde sur le port port_hote_vde.
-U port:hote_vde:port_hote_vde
spécifie une redirection de port UDP. Tous les paquets UDP reçus par l'hôte exécutant slirpvde sur le port port seront transférés vers hote_vde sur le port port_hote_vde.
-X hote_vde[:affichage.[ecran]]]
redirige un écran de fenêtre X d'une machine virtuelle. Slirpvde obtient le premier écran X inutilisé sur l'hôte exécutant slirpvde et redirige toutes les requêtes vers hote_vde. affichage et ecran] doivent être spécifiés s'ils sont différents de :0.0.
-x port:chemin_socket_unix]
redirige un port du routeur virtuel (généralement 10.0.2.2) vers un socket de flux UNIX. Il est utilisé par exemple pour rediriger un écran X de l'ordinateur hôte sur le réseau virtuel. Par ex. -x6000:/tmp/.X11-unix/X0. (Une configuration xhost appropriée est nécessaire (par exemple, 'xhost local:').
-t, --tftp chemin
slirpvde active un serveur tftp partageant (en lecture seule) le répertoire situé dans chemin.
-q, --quiet
Silencieux ; n'écrit rien sur la sortie standard.
