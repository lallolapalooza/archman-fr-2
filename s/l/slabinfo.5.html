slabinfo(5) Manuel des formats de fichier slabinfo(5)

NOM

slabinfo - statistiques de l'allocateur slab du noyau

SYNTAXE

cat /proc/slabinfo

DESCRIPTION

Les objets fréquemment utilisés dans le noyau Linux (têtes de tampons, inodes, dentries, etc.) ont leur propre cache. Le fichier /proc/slabinfo fournit des statistiques sur ces caches. La sortie suivante (éditée) montre un exemple du contenu de ce fichier :

$ sudo cat /proc/slabinfo;
slabinfo - version: 2.1
# nom    <objets_actifs> <nb_objets> <taille_objet> <obj_par_slab> <pages_par_slab> ...
sigqueue      100  100  160   25  1 : tunables  0  0  0 : slabdata   4   4  0
sighand_cache 355   405 2112  15  8 : tunables  0  0  0 : slabdata  27  27  0
kmalloc-8192   96   96  8192   4  8 : tunables  0  0  0 : slabdata  24  24  0
...

La première ligne de sortie inclut un numéro de version, qui permet à une application lisant le fichier de gérer les changements dans le format du fichier. (Voir VERSIONS, ci-dessous.) La ligne suivante liste les noms des colonnes dans les lignes restantes.

Chacune des lignes restantes affiche des informations sur un cache spécifié. Après le nom du cache, la sortie affichée dans chaque ligne montre trois composantes pour chaque cache :

•
statistiques
•
réglables (tunables)
•
données de slab (slabdata)

Les statistiques sont les suivantes :

objets_actifs
Le nombre d'objets actuellement actifs (c'est-à-dire en cours d'utilisation).
nb_objets
Le nombre total d'objets alloués (c'est-à-dire les objets en cours d'utilisation et ceux qui ne le sont pas).
taille_objet
La taille des objets dans ce slab, en octets.
obj_par_slab
Le nombre d'objets stockés dans chaque slab.
pages_par_slab
Le nombre de pages allouées pour chaque slab.

Les entrées tunables (réglables) dans chaque ligne montrent les paramètres ajustables pour le cache correspondant. Lors de l'utilisation de l'allocateur SLUB par défaut, il n'y a pas de réglages, le fichier /proc/slabinfo n'est pas inscriptible, et la valeur 0 est affichée dans ces champs. Lors de l'utilisation de l'ancien allocateur SLAB, les réglages pour un cache particulier peuvent être définis en écrivant des lignes de la forme suivante dans /proc/slabinfo :


# echo 'nom limit batchcount sharedfactor' > /proc/slabinfo;

Ici, nom est le nom du cache, et limit, batchcount, et sharedfactor sont des entiers définissant de nouvelles valeurs pour les réglages correspondants. La valeur limit doit être une valeur positive, batchcount doit être une valeur positive inférieure ou égale à limit, et sharedfactor doit être non négatif. Si l'une des valeurs spécifiées est invalide, les paramètres du cache restent inchangés.

Les entrées tunables dans chaque ligne contiennent les champs suivants :

limit
Le nombre maximum d'objets qui seront mis en cache.
batchcount
Sur les systèmes SMP, ceci spécifie le nombre d'objets à transférer à la fois lors du remplissage de la liste d'objets disponibles.
sharedfactor
[À documenter]

Les entrées slabdata dans chaque ligne contiennent les champs suivants :

slabs_actifs
Le nombre de slabs actifs.
nb_slabs
Le nombre total de slabs.
sharedavail
[À documenter]

Notez qu'en raison de l'alignement des objets et de la surcharge du cache slab, les objets ne sont normalement pas empaquetés de manière serrée dans les pages. Les pages contenant même un seul objet en cours d'utilisation sont considérées comme en cours d'utilisation et ne peuvent pas être libérées.

Les noyaux configurés avec CONFIG_DEBUG_SLAB auront également des champs statistiques supplémentaires dans chaque ligne, et la première ligne du fichier contiendra la chaîne « (statistics) ». Les champs statistiques comprennent : le niveau maximal d'objets actifs ; le nombre de fois où des objets ont été alloués ; le nombre de fois où le cache a grandi (nouvelles pages ajoutées à ce cache) ; le nombre de fois où le cache a été purgé (pages inutilisées supprimées de ce cache) ; et le nombre de fois où il y a eu une erreur lors de l'allocation de nouvelles pages pour ce cache.

VERSIONS

Le fichier /proc/slabinfo est apparu pour la première fois dans le noyau Linux 2.1.23. Le fichier est versionné, et au fil du temps, il y a eu plusieurs versions avec des dispositions différentes :

1.0
Présent tout au long de la série de noyaux Linux 2.2.x.
1.1
Présent dans la série de noyaux Linux 2.4.x.
1.2
Un format qui était brièvement présent dans la série de développement Linux 2.5.
2.0
Présent dans les noyaux Linux 2.6.x jusqu'à et y compris Linux 2.6.9.
2.1
Le format actuel, qui est apparu pour la première fois dans Linux 2.6.10.

NOTES

Seul root peut lire et (si le noyau a été configuré avec CONFIG_SLAB) écrire dans le fichier /proc/slabinfo.

La quantité totale de mémoire allouée au cache SLAB/SLUB est indiquée dans le champ Slab de /proc/meminfo.
