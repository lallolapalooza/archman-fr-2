NOM

slapo-refint - superposé Intégrité Référentielle pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

Le superposé Intégrité Référentielle peut être utilisé avec une base de données backend telle que slapd-mdb(5) pour maintenir la cohésion d'un schéma qui utilise des attributs de référence.

L'intégrité est maintenue en mettant à jour les enregistrements de la base de données qui contiennent les attributs nommés pour correspondre aux résultats d'une opération modrdn ou delete. Par exemple, si l'attribut d'intégrité était configuré comme manager, la suppression de l'enregistrement "uid=robert,ou=people,dc=example,dc=com" déclencherait une recherche de tous les autres enregistrements qui ont un attribut manager contenant ce DN. Les entrées correspondant à cette recherche verraient leur attribut manager supprimé. Ou, le renommage du même enregistrement en "uid=george,ou=people,dc=example,dc=com" déclencherait une recherche de tous les autres enregistrements qui ont un attribut manager contenant ce DN. Les entrées correspondant à cette recherche verraient leur attribut manager supprimé et remplacé par le nouveau DN.

rootdn doit être défini pour la base de données. refint s'exécute en tant que rootdn pour obtenir l'accès afin d'effectuer ses mises à jour. rootpw n'est pas nécessaire.

CONFIGURATION

Ces options slapd.conf s'appliquent au superposé Intégrité Référentielle. Elles doivent apparaître après la directive overlay.

refint_attributes <attribut> [...]
Spécifiez un ou plusieurs attributs pour lesquels l'intégrité sera maintenue comme décrit ci-dessus.
refint_nothing <chaîne>
Spécifiez une valeur arbitraire à utiliser comme espace réservé lorsque la dernière valeur serait autrement supprimée d'un attribut. Ceci peut être utile dans les cas où le schéma requiert l'existence d'un attribut pour lequel l'intégrité référentielle est appliquée. La suppression tentée d'un attribut requis entraînerait sinon une Violation de Classe d'Objet, provoquant l'échec de la requête. La chaîne doit être un DN valide.
refint_modifiersname <DN>
Spécifiez le DN à utiliser comme modifiersName des modifications internes effectuées par le superposé. Il est défini par défaut à "cn=Referential Integrity Overlay".

Les modifications effectuées par ce superposé ne sont pas propagées pendant la réplication. Ce superposé doit être configuré de manière identique sur les consommateurs de réplication afin de maintenir une synchronisation complète avec le fournisseur.

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

VOIR AUSSI

slapd.conf(5), slapd-config(5).
