NOM

slapd - Démon LDAP autonome

SYNTAXE

/usr/lib/slapd [-V[V[V]] [-4|-6] [-T {acl|a[dd]|auth|c[at]| d[n]|i[ndex]|m[odify]|p[asswd]|s[chema]|t[est]}] [-d niveau-debug] [-f fichier-config-slapd] [-F repertoire-config-slapd] [-h URLs] [-n nom-service] [-s niveau-syslog] [-l utilisateur-local-syslog] [-o option[=valeur]] [-r repertoire] [-u utilisateur] [-g groupe] [-c cookie]

DESCRIPTION

Slapd est le démon LDAP autonome. Il écoute les connexions LDAP sur un nombre quelconque de ports (par défaut 389), répondant aux opérations LDAP qu'il reçoit sur ces connexions. slapd est généralement appelé au démarrage du système, souvent depuis /etc/rc.local. Au démarrage, slapd se détache normalement du terminal appelant. S'il est configuré dans le fichier de configuration (ou le répertoire de configuration), le processus slapd écrira son identifiant de processus (voir getpid(2)) dans un fichier .pid, ainsi que les options de la ligne de commande lors de l'invocation dans un fichier .args (voir slapd.conf(5)). Si l'option -d est fournie, même avec un argument zéro, slapd ne se détachera pas du terminal appelant.

Consultez le "Guide de l'administrateur OpenLDAP" pour plus de détails sur slapd.

OPTIONS

-V[V[V]]
Affiche les informations de version et continue le démarrage. Si -VV est spécifié, quitte après avoir fourni les informations de version. Si -VVV est spécifié, fournit en plus des informations sur les superpositions et les backends statiques.
-4
Écoute uniquement sur les adresses IPv4.
-6
Écoute uniquement sur les adresses IPv6.
-T outil
Exécute en mode outil. L'argument outil sélectionne s'il faut exécuter en tant que slapadd, slapcat, slapdn, slapindex, slapmodify, slappasswd, slapschema, ou slaptest (slapacl et slapauth nécessitent que la valeur complète de l'option acl ou auth soit écrite en toutes lettres, car a est réservé à slapadd). Cette option doit être la première option spécifiée lorsqu'elle est utilisée ; les options restantes seront interprétées par le programme outil slap correspondant, conformément aux pages de manuel respectives. Notez que ces programmes outils seront généralement des liens symboliques vers slapd. Cette option est fournie pour les situations où les liens symboliques ne sont pas fournis ou ne sont pas utilisables.
-d niveau-debug
Active le débogage tel que défini par niveau-debug. Si cette option est spécifiée, même avec un argument zéro, slapd ne se détachera pas du terminal appelant. Des messages généraux d'opération et d'état sont imprimés pour toute valeur de niveau-debug. niveau-debug est considéré comme une chaîne de bits, chaque bit correspondant à un type différent d'informations de débogage. Voir <ldap_log.h> pour les détails. Des tableaux d'alias séparés par des virgules peuvent être spécifiés pour sélectionner la sortie de débogage des informations de débogage correspondantes. Tous les alias reconnus par la directive loglevel décrite dans slapd.conf(5) sont supportés. Si niveau-debug est ?, une liste des niveaux de débogage installés est affichée, et slapd se termine.

N'oubliez pas que si vous activez la journalisation des paquets, les paquets contenant des mots de passe de connexion seront affichés, donc si vous redirigez le journal vers un fichier journal, ce fichier doit être protégé en lecture.

-s niveau-syslog
Cette option indique à slapd à quel niveau de débogage les instructions de débogage doivent être journalisées dans la fonction syslog(8). La valeur niveau-syslog peut être définie sur n'importe quelle valeur ou combinaison autorisée par le commutateur -d. Slapd journalise tous les messages sélectionnés par niveau-syslog au niveau de gravité debug DEBUG de syslog(3), sur l'unité spécifiée avec -l.
-n nom-service
Spécifie le nom du service pour la journalisation et d'autres usages. La valeur par défaut est le nom de base de argv[0], c'est-à-dire : "slapd".
-l utilisateur-local-syslog
Sélectionne l'utilisateur local de la fonction syslog(8). La valeur peut être LOCAL0, jusqu'à LOCAL7, ainsi que USER et DAEMON. La valeur par défaut est LOCAL4. Cependant, cette option n'est autorisée que sur les systèmes qui prennent en charge les utilisateurs locaux avec la fonction syslog(8). La journalisation vers syslog(8) se fait au niveau de gravité "DEBUG".
-f fichier-config-slapd
Spécifie le fichier de configuration de slapd. La valeur par défaut est /etc/openldap/slapd.conf.
-F repertoire-config-slapd
Spécifie le répertoire de configuration de slapd. La valeur par défaut est /etc/openldap/slapd.d. Si -f et -F sont spécifiés, le fichier de configuration sera lu et converti au format de répertoire de configuration, puis écrit dans le répertoire spécifié. Si aucune option n'est spécifiée, slapd tentera de lire le répertoire de configuration par défaut avant d'essayer d'utiliser le fichier de configuration par défaut. Si un répertoire de configuration valide existe, le fichier de configuration par défaut est ignoré. Tous les outils slap qui utilisent les options de configuration observent ce même comportement.
-h liste-URL
slapd servira par défaut ldap:/// (LDAP sur TCP sur toutes les interfaces au port LDAP par défaut). C'est-à-dire qu'il se liera en utilisant INADDR_ANY et le port 389. L'option -h peut être utilisée pour spécifier des URL LDAP (et d'autres schémas) à servir. Par exemple, si slapd reçoit -h "ldap://127.0.0.1:9009/ ldaps:/// ldapi:///", il écoutera sur 127.0.0.1:9009 pour LDAP, 0.0.0.0:636 pour LDAP sur TLS, et LDAP sur IPC (sockets de domaine Unix). L'hôte 0.0.0.0 représente INADDR_ANY (toutes les interfaces). Une liste d'URL séparées par des espaces est attendue. Les URL doivent être des schémas LDAP, PLDAP, LDAPS, PLDAPS, ou LDAPI, et généralement sans DN ni autres paramètres optionnels (sauf comme discuté ci-dessous). Le support des trois derniers schémas dépend des options de configuration sélectionnées. Les hôtes peuvent être spécifiés par nom ou par formats d'adresse IPv4 et IPv6. Les ports, s'ils sont spécifiés, doivent être numériques. Le port ldap:// par défaut est 389 et le port ldaps:// par défaut est 636, idem pour les variantes prenant en charge le proxy.

Les schémas d'URL PLDAP et PLDAPS fournissent un support pour le protocole proxy HAProxy version 2, qui permet à un répartiteur de charge ou à un serveur proxy de fournir l'adresse IP du client distant à slapd pour qu'elle soit utilisée pour le contrôle d'accès ou la journalisation. Les ports configurés pour PLDAP ou PLDAPS n'accepteront que les connexions qui incluent l'en-tête de protocole proxy nécessaire. Les connexions à ces ports doivent être restreintes au niveau du réseau aux seuls répartiteurs de charge ou proxys de confiance pour éviter l'usurpation des adresses IP client par des tiers.

Pour LDAP sur IPC, nom est le nom du socket, et aucun port n'est requis, ni autorisé ; notez que les séparateurs de répertoire doivent être encodés en URL, comme tout autre caractère qui est spécial pour les URL ; donc le socket


/usr/local/var/ldapi

doit être spécifié comme


ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

L'emplacement par défaut pour le socket IPC est /var/lib/openldap/run/ldapi

Les permissions de l'écouteur sont indiquées par "x-mod=-rwxrwxrwx", "x-mod=0777" ou "x-mod=777", où l'un des "rwx" peut être "-" pour supprimer la permission associée, tandis que l'un des "7" peut être n'importe quel chiffre octal légal, conformément à chmod(1). OPTIONS

Les options suivantes sont disponibles pour slapd.

-s level
Définit le niveau de journalisation des événements pour la réplication. Les valeurs courantes incluent 0 pour aucune journalisation, 1 pour les erreurs uniquement, 2 pour les informations sur les événements de réplication, et 3 pour les journaux détaillés.
-l listener
Spécifie un ou plusieurs gestionnaires d'écoute. L'argument est une liste de chaînes séparées par des virgules, chacune spécifiant une adresse et un port où le démon doit écouter les connexions entrantes. Par défaut, slapd écoute sur 0.0.0.0:389 et ::1:389.
-n name
Spécifie le nom du service. Ceci est utilisé par les modules pour trouver leur configuration. Par défaut, le nom est slapd.
-m module
Charge un module supplémentaire. Ceci peut être utilisé pour étendre les fonctionnalités de slapd, par exemple pour ajouter de nouveaux types de backends ou de nouvelles fonctionnalités.
-M modulepath
Spécifie le chemin où rechercher les modules supplémentaires. Par défaut, les modules sont recherchés dans des emplacements prédéfinis.
-S searchbase
Spécifie la base de recherche par défaut pour les opérations LDAP. Si cette option n'est pas utilisée, la base de recherche sera déterminée à partir de la configuration du backend.
-a acl
Définit les règles d'accès (ACLs) pour les opérations LDAP. L'argument est une chaîne de caractères qui spécifie les permissions pour différents utilisateurs et groupes. La syntaxe des ACLs est complexe et détaillée dans la page de manuel slapd.access(5).
-A acl_syntax
Spécifie la syntaxe à utiliser pour les ACLs. Les options courantes sont "compat" (compatibilité avec les anciennes versions) et "openldap" (syntaxe standard d'OpenLDAP).
-r directory
Spécifie un répertoire qui deviendra la racine de l'environnement chroot. slapd changera le répertoire de travail courant vers ce répertoire et effectuera ensuite un chroot(2) vers ce répertoire. Ceci est fait après l'ouverture des gestionnaires d'écoute mais avant la lecture de tout fichier de configuration ou l'initialisation de tout backend. Lorsqu'il est utilisé comme mécanisme de sécurité, il doit être utilisé conjointement avec les options -u et -g.
-u user
slapd s'exécutera en tant que l'utilisateur spécifié (par nom ou ID), et utilisera la liste d'accès aux groupes supplémentaires de cet utilisateur telle que définie avec initgroups(3). L'ID du groupe sera également changé pour le gid de cet utilisateur, sauf si l'option -g est utilisée pour le remplacer. Notez que lorsque cette option est utilisée avec -r, slapd utilisera la base de données utilisateur dans l'environnement chroot.

Notez que sur certains systèmes, s'exécuter en tant qu'utilisateur non privilégié empêchera les backends de type "passwd" d'accéder aux mots de passe chiffrés. Notez également que tous les backends de type "shell" s'exécuteront en tant que l'utilisateur non privilégié spécifié.

-g group
slapd s'exécutera en tant que le groupe spécifié (par nom ou ID). Notez que lorsque cette option est utilisée avec -r, slapd utilisera la base de données de groupe dans l'environnement chroot.
-c cookie
Cette option fournit un cookie pour le consommateur de réplication syncrepl. Le cookie est une liste de paires name=value séparées par des virgules. Les champs de cookie syncrepl actuellement pris en charge sont rid, sid et csn. rid identifie un thread de réplication au sein du serveur consommateur et est utilisé pour trouver la spécification syncrepl dans slapd.conf(5) ou slapd-config(5) ayant l'identifiant de réplication correspondant dans sa définition. Le rid doit être fourni pour que toute autre valeur spécifiée soit utilisée. sid est l'ID du serveur dans une configuration multi-fournisseurs. csn est le numéro de séquence de validation reçu lors d'une synchronisation précédente et représente l'état du contenu du consommateur auquel le moteur syncrepl synchronisera le contenu actuel du fournisseur. En cas d'accord de réplication multi-fournisseurs, plusieurs valeurs csn, séparées par des points-virgules, peuvent apparaître. Utilisez uniquement la partie rid pour forcer un rechargement complet.
-o option[=valeur]
Cette option fournit un moyen générique de spécifier des options sans avoir besoin de réserver une lettre distincte pour elles.

Elle prend en charge les options suivantes:

slp={on|off|slp-attrs}
Lorsque le support SLP est compilé dans slapd, désactivez-le (off),
activez-le en vous enregistrant auprès des DAs SLP sans attributs SLP spécifiques (on), ou avec des attributs SLP spécifiques slp-attrs qui doivent être une définition de liste d'attributs SLP conformément à la norme SLP.

Par exemple, "slp=(tree=production),(server-type=OpenLDAP),(server-version=2.4.15)" s'enregistre auprès des DAs SLP avec les trois attributs SLP tree, server-type et server-version qui ont les valeurs indiquées ci-dessus. Cela permet de rechercher spécifiquement auprès des DAs SLP les serveurs LDAP détenant l'arbre production au cas où plusieurs arbres seraient disponibles.

EXEMPLES

Pour démarrer slapd, le faire passer en arrière-plan (fork) et se détacher du terminal, puis servir les bases de données LDAP définies dans le fichier de configuration par défaut, tapez simplement :

/usr/lib/slapd

Pour démarrer slapd avec un fichier de configuration alternatif, et activer la journalisation de débogage très détaillée qui sera imprimée sur la sortie d'erreur standard, tapez :

/usr/lib/slapd -f /var/tmp/slapd.conf -d 255

Pour tester si le fichier de configuration est correct ou non, tapez :

/usr/lib/slapd -Tt
