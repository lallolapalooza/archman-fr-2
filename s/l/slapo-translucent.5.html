NOM

slapo-translucent - Superposition de proxy translucide pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

La superposition de proxy translucide peut être utilisée avec une base de données backend telle que slapd-mdb(5) pour créer un "proxy translucide". Les entrées récupérées d'un serveur LDAP distant peuvent avoir certains ou tous leurs attributs remplacés, ou de nouveaux attributs ajoutés, par des entrées dans la base de données locale avant d'être présentées au client.

Une opération de recherche est d'abord remplie avec les entrées du serveur LDAP distant, dont les attributs sont ensuite remplacés par les attributs définis dans la base de données locale. Les remplacements locaux peuvent être peuplés avec les opérations add, modify et modrdn, dont l'utilisation est restreinte à l'utilisateur root.

Une opération de compare effectuera une comparaison avec les attributs définis dans l'enregistrement de la base de données locale (le cas échéant) avant toute comparaison avec les données de la base de données distante.

CONFIGURATION

La superposition de proxy translucide utilise une base de données proxysée, généralement un ou plusieurs serveurs LDAP distants, qui est configurée avec les options présentées dans slapd-ldap(5), slapd-meta(5) ou similaire. Ces options de slapd.conf sont spécifiques à la superposition de proxy translucide ; elles doivent apparaître après la directive overlay qui instancie la superposition translucent.

translucent_strict
Par défaut, les tentatives de suppression d'attributs dans la base de données locale ou distante seront silencieusement ignorées. La directive translucent_strict fait échouer ces modifications avec une violation de contrainte.
translucent_no_glue
Cette option de configuration désactive la création automatique d'enregistrements de "colle" pour une opération add ou modrdn, de sorte que tous les parents d'une entrée ajoutée à la base de données locale doivent être créés manuellement. Les enregistrements de colle sont toujours créés pour une opération modify.
translucent_local <attr[,attr...]>
Spécifie une liste d'attributs à rechercher dans la base de données locale lorsqu'ils sont utilisés dans un filtre de recherche. Par défaut, les filtres de recherche ne sont gérés que par la base de données distante. Avec cette directive, les filtres de recherche seront divisés en une partie locale et une partie distante, et les attributs locaux seront recherchés localement.
translucent_remote <attr[,attr...]>
Spécifie une liste d'attributs à rechercher dans la base de données distante lorsqu'ils sont utilisés dans un filtre de recherche. Cette directive complète la directive translucent_local. Les attributs peuvent être spécifiés comme locaux et distants si désiré.

Si ni translucent_local ni translucent_remote ne sont spécifiés, le comportement par défaut est de rechercher dans la base de données distante avec le filtre de recherche complet. Si seule translucent_local est spécifiée, les recherches ne seront effectuées que sur la base de données locale. De même, si seule translucent_remote est spécifiée, les recherches ne seront effectuées que sur la base de données distante. Dans tous les cas, les entrées locales et distantes correspondant à un résultat de recherche seront fusionnées avant d'être renvoyées au client.

translucent_bind_local
Active la recherche d'informations d'identification stockées localement pour la liaison simple lorsque la liaison à la base de données distante échoue. Désactivé par défaut.
translucent_pwmod_local
Active l'opération étendue de modification de mot de passe RFC 3062 sur les informations d'identification stockées localement. L'opération ne s'applique qu'aux entrées qui existent dans la base de données distante. Désactivé par défaut.

CONTRÔLE D'ACCÈS

Le contrôle d'accès est délégué au(x) DSA distant(s) ou au backend de base de données locale pour les opérations auth et write. Il est délégué au(x) DSA distant(s) et au frontend pour les opérations read. Les règles d'accès locales impliquant des données renvoyées par le(s) DSA distant(s) doivent être conçues avec soin. En fait, les entrées sont renvoyées par le(s) DSA distant(s) uniquement sur la base de la fraction distante des données, en fonction de l'identité sous laquelle l'opération est effectuée. Par conséquent, les règles locales ne pourraient permettre de voir qu'une partie des données distantes.

MISE EN GARDE

La superposition de proxy translucide désactivera la vérification du schéma dans la base de données locale, de sorte qu'une entrée composée d'attributs de superposition n'a pas besoin d'adhérer au schéma complet.

Étant donné que la superposition translucide n'effectue aucune réécriture de DN, les instances de base de données locale et distante doivent avoir le même suffixe. D'autres configurations échoueront probablement avec No Such Object et d'autres erreurs.

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

VOIR AUSSI

slapd.conf(5), slapd-config(5), slapd-ldap(5).
