NOM

slapo-memberof - Superposition de maintenance inverse de l'appartenance aux groupes pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

La superposition memberof de slapd(8) permet la maintenance automatique et inverse de l'appartenance aux groupes. Chaque fois qu'une entrée de groupe est modifiée, ses membres sont modifiés de manière appropriée afin de maintenir un attribut de type DN, « est membre de », mis à jour avec le DN du groupe.

Notez que la superposition dynlist peut également fournir cette fonctionnalité et peut être adaptée à des environnements moins exigeants.

CONFIGURATION

Les directives de configuration spécifiques à la superposition memberof doivent être préfixées par memberof-, afin d'éviter des conflits potentiels avec des directives spécifiques à la base de données sous-jacente ou à d'autres superpositions empilées.

overlay memberof
Cette directive ajoute la superposition memberof à la base de données courante ; voir slapd.conf(5) pour plus de détails.

Les options de configuration slapd.conf suivantes sont définies pour la superposition memberof.

memberof-group-oc <nom-oc-groupe>
La valeur <nom-oc-groupe> est le nom de l'objectClass qui déclenche la mise à jour inverse de l'appartenance aux groupes. Par défaut, il s'agit de groupOfNames.
memberof-member-ad <attribut-membre>
La valeur <attribut-membre> est le nom de l'attribut qui contient les noms des membres dans les objets de groupe ; il doit être de type DN. Par défaut, il s'agit de member.
memberof-memberof-ad <attribut-memberof>
La valeur <attribut-memberof> est le nom de l'attribut qui contient les noms des groupes dont une entrée est membre ; il doit être de type DN. Son contenu est automatiquement mis à jour par la superposition. Par défaut, il s'agit de memberOf.
memberof-dn <dn>
La valeur <dn> contient le DN utilisé comme modifiersName pour les modifications internes effectuées afin de mettre à jour l'appartenance inverse aux groupes. Par défaut, il s'agit du rootdn de la base de données sous-jacente.
memberof-dangling {ignore, drop, error}
Cette option détermine le comportement de la superposition lorsqu'elle rencontre des références orphelines lors d'une modification. Par défaut, elle est définie sur ignore, ce qui peut laisser des références orphelines. Les autres options sont drop, qui rejette les modifications qui résulteraient en des références orphelines, et error, qui fait échouer les modifications qui résulteraient en des références orphelines.
memberof-dangling-error <code-erreur>
Si memberof-dangling est défini sur error, ce paramètre de configuration peut être utilisé pour modifier le code de réponse renvoyé en cas de violation. Par défaut, il s'agit d'une « violation de contrainte », mais d'autres implémentations sont connues pour renvoyer « aucun objet de ce type » à la place.
memberof-refint {true|FALSE}
Cette option détermine si la superposition tente de préserver l'intégrité référentielle ou non. Si elle est définie sur TRUE, lorsqu'une entrée contenant des valeurs de l'attribut « est membre de » est modifiée, les groupes correspondants sont également modifiés.
memberof-addcheck {true|FALSE}
Cette option détermine si la superposition vérifie les nouvelles entrées ajoutées pour leur appartenance à des groupes existants. Cette vérification est utile si des groupes peuplés sont créés dans l'annuaire avant les entrées auxquelles ils font référence. Cette situation se produit souvent lors de la réplication, qui peut répliquer les entrées dans un ordre aléatoire. Si elle est définie sur TRUE, chaque opération d'ajout recherche les groupes faisant référence à l'entrée ajoutée et peuple son attribut memberof avec les DN de groupe. Notez que memberof-dangling doit rester sur son réglage par défaut ignore pour que cette option fonctionne.

La superposition memberof peut être utilisée avec n'importe quel backend qui fournit une fonctionnalité complète de lecture-écriture, mais elle est principalement destinée à être utilisée avec des backends de stockage locaux. Les opérations de maintenance qu'elle effectue sont internes au serveur sur lequel la superposition est configurée et ne sont jamais répliquées. Les serveurs consommateurs doivent être configurés avec leurs propres instances de la superposition memberOf si l'on souhaite maintenir ces attributs memberOf sur les consommateurs. Les consommateurs doivent également être configurés pour exclure l'attribut memberof de la réplication. (Voir l'option exattrs dans la configuration du consommateur.)

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

COMPATIBILITÉ ASCENDANTE

La superposition memberof a été retravaillée avec la version 2.5 pour utiliser un espace de noms cohérent, comme avec les autres superpositions. Par effet secondaire, les paramètres cn=config suivants sont obsolètes et seront supprimés dans une future version : olcMemberOf est remplacé par olcMemberOfConfig.

VOIR AUSSI

slapo-dynlist(5), slapd.conf(5), slapd-config(5), slapd(8). La superposition slapo-memberof(5) prend en charge la configuration dynamique via back-config.
