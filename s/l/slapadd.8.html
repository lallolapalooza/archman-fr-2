NOM

slapadd - Ajoute des entrées à une base de données SLAPD

SYNTAXE

/usr/bin/slapadd [-b suffixe] [-c] [-d niveau-debug] [-f slapd.conf] [-F dossier-conf] [-g] [-j no-ligne] [-l fichier-ldif] [-n no-db] [-o option[=valeur]] [-q] [-s] [-S SID] [-u] [-v] [-w]

DESCRIPTION

Slapadd est utilisé pour ajouter des entrées spécifiées dans le format LDAP Directory Interchange Format (LDIF) à une base de données slapd(8). Il ouvre la base de données donnée, déterminée par le numéro de base de données ou le suffixe, et ajoute les entrées correspondant à l'LDIF fourni à la base de données. Les bases de données configurées comme subordonnées à celle-ci sont également mises à jour, sauf si -g est spécifié. L'entrée LDIF est lue depuis l'entrée standard ou le fichier spécifié.

Tous les fichiers éventuellement créés par slapadd appartiendront à l'utilisateur sous lequel slapadd est exécuté. Assurez-vous donc soit d'exécuter slapadd avec la même identité que celle sous laquelle slapd(8) sera exécuté (voir l'option -u dans slapd(8)), soit de changer le propriétaire des fichiers avant d'exécuter slapd(8).

Remarque : slapadd effectuera également l'indexation pertinente lors de l'ajout de la base de données si des index sont configurés. Pour des détails spécifiques, veuillez consulter slapindex(8).

OPTIONS

-b suffixe
Utilise le suffixe spécifié pour déterminer la base de données à laquelle ajouter les entrées. Par défaut, la première base de données qui supporte l'opération demandée est utilisée. L'option -b ne peut pas être utilisée conjointement avec l'option -n.
-c
Active le mode continu (ignorer les erreurs).
-d niveau-debug
Active les messages de débogage tels que définis par le niveau-debug spécifié ; voir slapd(8) pour les détails.
-f slapd.conf
Spécifie un fichier slapd.conf(5) alternatif.
-F dossier-conf
Spécifie un dossier de configuration. Si -f et -F sont tous deux spécifiés, le fichier de configuration sera lu et converti au format de dossier de configuration, puis écrit dans le dossier spécifié. Si aucune option n'est spécifiée, une tentative de lecture du dossier de configuration par défaut sera effectuée avant d'essayer d'utiliser le fichier de configuration par défaut. S'il existe un dossier de configuration valide, le fichier de configuration par défaut est ignoré. Si le mode simulation est également spécifié, aucune conversion n'aura lieu.
-g
Désactive le "gluing" subordonné. Seule la base de données spécifiée sera traitée, et non ses subordonnées "collées" (le cas échéant).
-j no-ligne
Saute à la ligne spécifiée dans le fichier LDIF avant de traiter toute entrée. Cela permet de reprendre un chargement interrompu en raison d'erreurs dans l'LDIF d'entrée, après correction des erreurs.
-l fichier-ldif
Lit l'LDIF depuis le fichier spécifié au lieu de l'entrée standard.
-n no-db
Ajoute des entrées à la no-db-ème base de données listée dans le fichier de configuration. L'option -n ne peut pas être utilisée conjointement avec l'option -b. Pour peupler la base de données de configuration slapd-config(5), utilisez -n 0 car c'est toujours la première base de données. Elle doit cependant exister physiquement sur le système de fichiers au préalable.
-o option[=valeur]
Spécifie une option avec une valeur (optionnelle). Les options/valeurs génériques possibles sont :
              syslog=<sous-systèmes>  (voir `-s' dans slapd(8))
              syslog-level=<niveau> (voir `-S' dans slapd(8))
              syslog-user=<utilisateur>   (voir `-l' dans slapd(8))
              schema-check={oui|non}
              value-check={oui|non}
L'option schema-check active/désactive la vérification du schéma (activée par
défaut) ; l'option value-check active/désactive la vérification des valeurs
(désactivée par défaut). Cette dernière est incompatible avec -q.
-q
active le mode rapide (moins de vérifications d'intégrité). Effectue moins de
vérifications de cohérence sur les données d'entrée, et aucune vérification de
cohérence lors de l'écriture de la base de données. Améliore le temps de chargement,
mais si des erreurs ou des interruptions se produisent, la base de données résultante
sera inutilisable.
-s
désactive la vérification du schéma. Cette option est destinée à être utilisée lors
du chargement de bases de données contenant des objets spéciaux, tels que des objets
fractionnaires sur un consommateur partiel. Le chargement d'objets normaux qui ne
conformément pas au schéma peut entraîner un comportement inattendu et incorrect.
-S SID
ID du serveur à utiliser dans entryCSN généré. Également utilisé pour contextCSN
si -w est également défini. Par défaut sur 0.
-u
active le mode simulation (ne pas écrire dans le backend).
-v
active le mode verbeux.
-w
écrit les informations de contexte syncrepl.
Après l'ajout de toutes les entrées, le contextCSN sera mis à jour avec le CSN le plus élevé
dans la base de données.

LIMITATIONS

Votre slapd(8) ne doit pas être en cours d'exécution lorsque vous faites cela pour assurer la cohérence de la base de données.

slapadd peut ne pas fournir de vérifications de nommage ou de schéma. Il est conseillé d'utiliser ldapadd(1) lors de l'ajout de nouvelles entrées dans un répertoire existant.

EXEMPLES

Pour importer les entrées spécifiées dans le fichier ldif dans votre base de données slapd(8), tapez la commande :

/usr/bin/slapadd -l ldif
