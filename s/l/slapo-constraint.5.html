NOM

slapo-constraint - Overlay de contraintes d'attribut pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

L'overlay de contraintes est utilisé pour s'assurer que les valeurs des attributs correspondent à certaines contraintes au-delà de la syntaxe LDAP de base. Les attributs peuvent avoir plusieurs contraintes qui leur sont appliquées, et toutes doivent être satisfaites lors de la modification d'une valeur d'attribut sous contrainte.

Cet overlay est destiné à être utilisé pour forcer la régularité syntaxique sur certaines données représentées sous forme de chaînes de caractères qui ont des formes canoniques bien connues, comme les numéros de téléphone, les codes postaux, les FQDN, etc.

Il ne contraint que les commandes LDAP add, modify et rename et cherche seulement à contrôler les valeurs add et replace des requêtes modify et rename.

Aucune contrainte n'est appliquée pour les opérations effectuées avec le contrôle relax activé.

CONFIGURATION

Cette option de slapd.conf s'applique à l'overlay de contraintes. Elle doit apparaître après la directive overlay.

constraint_attribute <nom_attribut>[,...] <type> <valeur> [<extra> [...]]
Spécifie la contrainte qui doit s'appliquer à la liste d'attributs séparés par des virgules nommée comme premier paramètre. Six types de contraintes sont actuellement supportés - regex, negregex, size, count, uri, et set.

Le paramètre suivant le type regex ou negregex est une expression régulière de style Unix (Voir regex(7) ). Le paramètre suivant le type uri est une URI LDAP. L'URI sera évaluée en utilisant une recherche interne. Elle ne doit pas inclure de nom d'hôte, et elle doit inclure une liste d'attributs à évaluer.

Le paramètre suivant le type set est une chaîne de caractères interprétée selon la syntaxe utilisée pour les ensembles d'ACL. Cela permet de construire des contraintes basées sur le contenu de l'entrée.

Le type size peut être utilisé pour imposer une limite sur la longueur d'un attribut, et le type count limite le nombre de valeurs d'un attribut.

Des paramètres supplémentaires peuvent apparaître dans n'importe quel ordre après ceux décrits ci-dessus.

<extra> : restrict=<uri>
Ce paramètre supplémentaire permet de restreindre l'application de la contrainte correspondante uniquement aux entrées qui correspondent aux portions base, scope et filter de l'URI LDAP. La base, si elle est présente, doit se situer dans le contexte de nommage de la base de données. Le scope n'est utilisé que lorsque la base est présente ; il est par défaut à base. Les autres paramètres de l'URI ne sont pas autorisés.

Toute tentative d'ajout ou de modification d'un attribut nommé dans la spécification de l'overlay de contraintes qui ne correspond pas à la contrainte listée échouera avec une erreur LDAP_CONSTRAINT_VIOLATION.

EXEMPLES

overlay constraint
constraint_attribute jpegPhoto size 131072
constraint_attribute userPassword count 3
constraint_attribute mail regex ^[[:alnum:]]+@mydomain.com$
constraint_attribute mail negregex ^[[:alnum:]]+@notallowed.com$
constraint_attribute title uri
  ldap:///dc=catalog,dc=example,dc=com?title?sub?(objectClass=titleCatalog)
constraint_attribute cn,sn,givenName set
  "(this/givenName + [ ] + this/sn) & this/cn"
  restrict="ldap:///ou=People,dc=example,dc=com??sub?(objectClass=inetOrgPerson)"

Une spécification comme celle ci-dessus rejetterait tout attribut mail qui ne ressemblerait pas à <chaîne alphanumérique>@mydomain.com ou qui ressemblerait à <chaîne alphanumérique>@notallowed.com. Elle rejetterait également tout attribut title dont les valeurs ne seraient pas listées dans l'attribut title de n'importe quelle entrée titleCatalog dans le scope donné. (Notez que le sous-arbre « dc=catalog,dc=example,dc=com » devrait résider dans une base de données séparée, sinon l'ensemble initial des entrées titleCatalog ne pourrait pas être peuplé tant que la contrainte est en vigueur.) Enfin, elle exige que les valeurs de l'attribut cn soient construites en associant les valeurs des attributs sn et givenName, séparées par un espace, mais uniquement pour les entrées dérivées de l'objectClass inetOrgPerson.

FICHIERS

fichier de configuration par défaut de slapd
