NOM

slapd-null - Backend Null pour slapd

SYNTAXE

/etc/openldap/slapd.conf

DESCRIPTION

Le backend Null pour slapd(8) est sûrement la partie la plus utile de slapd :
- Les recherches retournent succès mais aucune entrée.
- Les comparaisons retournent compareFalse.
- Les mises à jour retournent succès (sauf si readonly est activé) mais ne font rien.
- Les binds autres que celui du rootdn échouent à moins que l'option de base de données "bind on" ne soit fournie.
- Les outils slapadd(8) et slapcat(8) sont tout aussi passionnants.
Inspiré du périphérique /dev/null.

CONFIGURATION

Cette option de slapd.conf s'applique à la base de données du backend NULL. C'est-à-dire qu'elle doit suivre une ligne "database null" et précéder toute ligne "database" ultérieure. Les autres options de base de données sont décrites dans la page de manuel slapd.conf(5).

bind <on/off>
Permet les binds en tant que n'importe quel DN dans le suffixe de ce backend, avec n'importe quel mot de passe. La valeur par défaut est "off".
dosearch <on/off>
Si activé, une seule entrée sera retournée pour toutes les requêtes de recherche. Le DN de l'entrée sera le même que le suffixe de la base de données. La valeur par défaut est "off".

EXEMPLE

Voici un extrait possible de slapd.conf utilisant le backend Null :

database null
suffix   "cn=Rien"
bind     on

CONTROLE D'ACCES

Le backend null ne respecte aucune des sémantiques de contrôle d'accès décrites dans slapd.access(5).

FICHIERS

/etc/openldap/slapd.conf
fichier de configuration par défaut de slapd

VOIR AUSSI

slapd.conf(5), slapd(8), slapadd(8), slapcat(8).
