NOM

slsh - Interpréteur pour scripts S-Lang

SYNOPSIS

slsh [ --help ] [ --version ] [ -g ] [ -n ] [ --init fichier ] [ --no-readline ] [ -e chaîne ] [ -i ] [ -q, --quiet ] [ -t ] [ -v ] [ -|script-fichier arguments... ]

DESCRIPTION

slsh est un programme simple pour interpréter des scripts S-Lang. Il supporte le chargement dynamique de modules S-Lang et inclut une interface readline pour une utilisation interactive.

OPTIONS

--help
Afficher un résumé des options
--version
Afficher les informations de version de slsh
-g
Compiler avec du code de débogage, des traces, etc.
-n
Ne pas charger le fichier d'initialisation personnel
--init fichier
Utiliser ce fichier à la place de ~/.slshrc
--no-readline
Ne pas utiliser d'interface readline pour le mode interactif
-e chaîne
Exécuter ``chaîne'' comme code S-Lang.
-i
Forcer le mode interactif. Normalement, slsh passera en mode interactif si stdin et stdout sont connectés à un terminal.
-q, --quiet
Démarrer silencieusement en n'affichant pas les informations de version et de copyright.
-t
Normalement, slsh appellera slsh_main s'il est défini. Cette option l'empêche, le rendant utile pour vérifier les erreurs de syntaxe.
-v
Afficher les messages de chargement détaillés. Ceci est utile pour voir quels fichiers sont chargés.

INITIALISATION

Au démarrage, le programme tentera de charger slsh.rc comme suit. Si les variables d'environnement SLSH_CONF_DIR ou SLSH_LIB_DIR existent, alors slsh recherchera dans les répertoires correspondants pour trouver slsh.rc. Sinon, il recherchera dans :

$(prefix)/etc/ (tel que spécifié dans le Makefile)

/usr/local/etc/

/usr/local/etc/slsh/

/etc/

/etc/slsh/

Le fichier slsh.rc peut charger d'autres fichiers du répertoire de bibliothèque de slsh de la manière décrite ci-dessous.

Une fois slsh.rc chargé, slsh chargera $HOME/.slshrc s'il est présent. Enfin, il chargera le script spécifié sur la ligne de commande. Si le nom du script est -, alors il sera lu depuis stdin. Si le nom du script n'est pas présent, ou si une chaîne à exécuter n'a pas été spécifiée en utilisant l'option -e, alors slsh passera en mode interactif et lira les entrées depuis le terminal. Si le script est présent et définit une fonction nommée slsh_main, cette fonction sera appelée.

CHARGEMENT DES FICHIERS

Lorsqu'un script charge un fichier via la fonction intégrée evalfile ou la fonction require (chargée automatiquement par slsh.rc), le fichier est recherché le long de SLSH_PATH tel que spécifié dans le Makefile. Un chemin alternatif peut être spécifié par la variable d'environnement SLSH_PATH.

Le chemin de recherche peut être interrogé et défini au moment de l'exécution via les fonctions get_slang_load_path et set_slang_load_path, par exemple :

   set_slang_load_path ("/home/bill/lib/slsh:/usr/share/slsh");

MODE INTERACTIF

Lorsque slsh est invoqué sans script ou reçoit l'argument de ligne de commande -i, il passe en mode interactif. Dans ce mode, l'utilisateur sera invité à saisir une entrée. Le programme quittera ce mode et se terminera s'il voit un EOF (Ctrl-D) ou si l'utilisateur quitte en émettant la commande quit.

Si une exception non interceptée se produit pendant l'exécution d'une commande, le message d'erreur sera affiché et l'utilisateur sera invité à entrer une nouvelle commande.

Tous les objets restant sur la pile après une commande seront affichés et la pile sera effacée. Cela rend le mode interactif utile comme calculatrice, par exemple :

     slsh> 3*10;
     30
     slsh> x = [1:20];
     slsh> sum (sin(x)-cos(x));
     0.458613
     slsh> quit;
Notez que dans ce mode, les variables sont automatiquement déclarées.

Le mode interactif supporte également la journalisation des commandes. La journalisation est activée par la fonction start_log. La fonction stop_log désactive la journalisation. Le fichier par défaut où les informations de journalisation seront écrites est slsh.log. Un autre fichier peut être spécifié comme argument optionnel à la fonction start_log :

     slsh> start_log;
     Logging input to slsh.log
        .
        .
     slsh> stop_log;
     slsh> start_log("foo.log");
     Logging input to foo.log
        .
        .
     slsh> stop_log;
     slsh> start_log;
     Logging input to foo.log

De même, la fonction save_input peut être utilisée pour sauvegarder l'entrée précédente dans un fichier spécifié :

     slsh> save_input;
     Input saved to slsh.log
     slsh> save_input ("foo.log");
     Input saved to foo.log

Comme les exemples ci-dessus l'indiquent, les lignes doivent se terminer par un point-virgule. C'est une fonctionnalité de base du langage et cela permet aux commandes de s'étendre sur plusieurs lignes, par exemple :

     slsh> x = [
            1,2,3,
            4,5,6];
     slsh> sum(x);
Pour plus de commodité, certains utilisateurs préfèrent que les commandes soient automatiquement terminées par un point-virgule. Pour qu'un point-virgule soit silencieusement ajouté à la fin d'une ligne d'entrée, placez ce qui suit dans le fichier $HOME/.slshrc : 
    #ifdef __INTERACTIVE__
    slsh_append_semicolon (1);
    #endif

Le mode interactif supporte également les évasions de shell. Pour passer une commande au shell, préfixez-la avec !, par exemple :

    slsh> !pwd
    /grandpa/d1/src/slang2/slsh
    slsh> !cd doc/tm
    slsh> !pwd
    /grandpa/d1/src/slang2/slsh/doc/tm

Enfin, le mode interactif supporte les fonctions d'aide et apropos :

    slsh> apropos list
    apropos list ==>
    List_Type
    list_append
    list_delete
       .
       .
    slsh> help list_append
    list_append
     SYNOPSIS
       Append an object to a list
     USAGE
       list_append (List_Type, object, Int_Type nth)
       .
       .
Pour plus de commodité, les fonctions help et apropos ne nécessitent pas les contraintes syntaxiques des autres fonctions.

MECANISME HISTORIQUE READLINE

Par défaut, slsh est compilé pour utiliser l'interface readline de S-Lang, qui inclut une complétion de commande personnalisable et un mécanisme d'historique. Lorsque slsh (ou toute application S-Lang utilisant cette fonctionnalité) démarre en mode interactif, il recherchera un fichier dans le répertoire personnel de l'utilisateur appelé .slrlinerc et le chargera s'il est présent. Ce fichier permet à l'utilisateur de personnaliser l'interface readline et d'activer la sauvegarde de l'historique entre les sessions. À titre d'exemple, voici une version du fichier .slrlinerc de l'auteur :

     % Charge quelques fonctions de base qui implémentent le mécanisme d'historique
     () = evalfile ("rline/slrline.rc");
     % Le nom du fichier d'historique -- s'étend en .slsh_hist pour slsh
     RLine_History_File = "$HOME/.${name}_hist";
     % Quelques raccourcis clavier supplémentaires. Certaines de ces fonctions sont définies
     % dans rline/editfuns.sl, chargées par rline/slrline.rc
     rline_unsetkey ("^K");
     rline_setkey ("bol",   "^B");
     rline_setkey ("eol",   "^E");
     rline_setkey (&rline_kill_eol,  "^L");
     rline_setkey (&rline_set_mark,  "^K^B");
     rline_setkey (&rline_copy_region, "^Kk");
     rline_setkey (&rline_kill_region, "^K^V");
     rline_setkey (&rline_yank,  "^K^P");
     rline_setkey ("redraw",   "^R");
     #ifexists rline_up_hist_search
     % Mappe les touches fléchées haut/bas au mécanisme de recherche d'historique
     rline_setkey (&rline_up_hist_search, "\e[A");
     rline_setkey (&rline_down_hist_search, "\e[B");
     #endif
     #ifexists rline_edit_history
     rline_setkey (&rline_edit_history, "^Kj");
     #endif

SCRIPTS DIVERS

Plusieurs scripts utiles sont situés dans $prefix/share/slsh/scripts/, où $prefix représente le préfixe d'installation de slsh (/usr, /usr/local,...). Ces scripts incluent :

sldb
Un script qui exécute le débogueur S-Lang.
jpegsize
Rapporte la taille d'un fichier jpeg.
svnsh
Un shell pour naviguer dans un dépôt SVN.
