NOM

slapacl - Vérifier l'accès à une liste d'attributs.

SYNTAXE

/usr/bin/slapacl -b DN [-d niveau-debug] [-D DN-authentification | -U ID-authentification] [-f slapd.conf] [-F repertoire-config] [-o option[=valeur]] [-u] [-v] [-X DN-autorisation | -o  authzDN=DN] [attribut[/accès][:valeur]] [...]

DESCRIPTION

slapacl est utilisé pour vérifier le comportement de slapd(8) en vérifiant l'accès aux données du répertoire conformément aux directives de liste de contrôle d'accès définies dans sa configuration. Il ouvre le fichier de configuration slapd.conf(5) ou le backend slapd-config(5), lit les directives access/olcAccess, puis analyse la liste d'attributs donnée sur la ligne de commande ; si aucune n'est donnée, l'accès au pseudo-attribut entry est testé.

OPTIONS

-b DN
spécifie le DN auquel l'accès est demandé ; l'entrée correspondante est récupérée de la base de données, et doit donc exister. Le DN est également utilisé pour déterminer quelles règles s'appliquent ; il doit donc se trouver dans le contexte de nommage d'une base de données configurée. Par défaut, la première base de données qui prend en charge l'opération demandée est utilisée. Voir aussi -u.
-d niveau-debug
active les messages de débogage tels que définis par le niveau-debug spécifié ; voir slapd(8) pour les détails.
-D DN-authentification
spécifie un DN à utiliser comme identité pendant la session de test lors de la sélection des clauses <by> appropriées dans les listes d'accès.
-f slapd.conf
spécifie un fichier slapd.conf(5) alternatif.
-F repertoire-config
spécifie un répertoire de configuration. Si -f et -F sont spécifiés, le fichier de configuration sera lu et converti au format répertoire de configuration, puis écrit dans le répertoire spécifié. Si aucune des options n'est spécifiée, une tentative de lecture du répertoire de configuration par défaut sera effectuée avant d'essayer d'utiliser le fichier de configuration par défaut. Si un répertoire de configuration valide existe, le fichier de configuration par défaut est ignoré.
-o option[=valeur]
Spécifie une option avec une valeur (optionnelle). Les options/valeurs génériques possibles sont :
              syslog=<sous-systèmes>  (voir `-s' dans slapd(8))
              syslog-level=<niveau> (voir `-S' dans slapd(8))
              syslog-user=<utilisateur>   (voir `-l' dans slapd(8))
Les options/valeurs possibles spécifiques à slapacl sont :
              authzDN
              domain
              peername
              sasl_ssf
              sockname
              sockurl
              ssf
              tls_ssf
              transport_ssf
Voir les champs associés dans slapd.access(5) pour les détails.
-u
active le mode simulation (dry-run). Ne récupère aucune entrée de la base de données. Dans ce cas, une fausse entrée avec le DN donné avec l'option -b est utilisée, sans attributs. Par conséquent, les règles qui dépendent du contenu de l'objet cible ou de tout autre objet de la base de données ne se comporteront pas comme avec l'objet réel. Le DN donné avec l'option -b est toujours utilisé pour sélectionner les règles applicables ; il doit donc se trouver dans le contexte de nommage d'une base de données configurée. Voir aussi -b.
-U ID-authentification
spécifie un ID à mapper à un DN comme par le biais des règles authz-regexp ou authz-rewrite (voir slapd.conf(5) pour les détails) ; mutuellement exclusif avec -D.
-v
active le mode verbeux.
-X DN-autorisation
spécifie un ID d'autorisation à mapper à un DN comme par le biais des règles authz-regexp ou authz-rewrite (voir slapd.conf(5) pour les détails) ; mutuellement exclusif avec -o authzDN=DN.

EXEMPLES

La commande

	/usr/bin/slapacl -f /etc/openldap/slapd.conf -v \
            -U bjorn -b "o=University of Michigan,c=US" \
	    "o/read:University of Michigan"
teste si l'utilisateur bjorn peut accéder à l'attribut o de l'entrée o=University of Michigan,c=US au niveau read.
