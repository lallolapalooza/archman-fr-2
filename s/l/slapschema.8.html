NOM

slapschema - utilitaire de vérification de schéma en base de données SLAPD

SYNTAXE

/usr/bin/slapschema [-afiltre] [-bsuffixe] [-c] [-dniveau-debug] [-fslapd.conf] [-Fconfdir] [-g] [-HURI] [-lfichier-erreurs] [-nnum-bd] [-ooption[=valeur]] [-ssous-arbre-dn] [-v]

DESCRIPTION

Slapschema est utilisé pour vérifier la conformité du schéma du contenu d'une base de données slapd(8). Il ouvre la base de données spécifiée, déterminée par le numéro de base de données ou le suffixe, et vérifie la conformité de son contenu avec le schéma correspondant. Les erreurs sont écrites sur la sortie standard ou dans le fichier spécifié. Les bases de données configurées comme subordonnées à celle-ci sont également traitées, sauf si -g est spécifié.

Les administrateurs peuvent avoir besoin de modifier des éléments de schéma existants, y compris l'ajout de nouveaux attributs requis aux objectClasses, la suppression d'attributs requis ou autorisés existants des objectClasses, la suppression complète d'objectClasses, ou tout autre changement susceptible de rendre des entrées parfaitement valides non conformes au schéma modifié. L'exécution de l'outil slapschema après la modification du schéma peut signaler des incohérences qui ne se manifesteraient autrement que lorsque des entrées incohérentes doivent être modifiées.

Les enregistrements d'entrée sont vérifiés dans l'ordre de la base de données, et non dans l'ordre supérieur d'abord. Les enregistrements d'entrée seront vérifiés en considérant tous les attributs (utilisateurs et opérationnels) stockés dans la base de données. Les attributs générés dynamiquement (comme subschemaSubentry) ne seront pas pris en compte.

OPTIONS

-a filtre
Vérifie uniquement les entrées correspondant au filtre asserté. Par exemple

slapschema -a \
"(!(entryDN:dnSubtreeMatch:=ou=People,dc=example,dc=com))"

vérifiera toutes les sous-arborescences sauf celle de "ou=People,dc=example,dc=com" de la base de données "dc=example,dc=com". Obsolète ; utiliser -H ldap:///???(filtre) à la place.

-b suffixe
Utilise le suffixe spécifié pour déterminer quelle base de données vérifier. Par défaut, la première base de données qui prend en charge l'opération demandée est utilisée. L'option -b ne peut pas être utilisée conjointement avec l'option -n.
-c
Active le mode continuer (ignorer les erreurs).
-d niveau-debug
Active les messages de débogage tels que définis par le niveau-debug spécifié ; voir slapd(8) pour les détails.
-f slapd.conf
Spécifie un fichier slapd.conf(5) alternatif.
-F confdir
Spécifie un répertoire de configuration. Si -f et -F sont tous deux spécifiés, le fichier de configuration sera lu et converti au format de répertoire de configuration, puis écrit dans le répertoire spécifié. Si aucune des options n'est spécifiée, une tentative de lecture du répertoire de configuration par défaut sera faite avant d'essayer d'utiliser le fichier de configuration par défaut. Si un répertoire de configuration valide existe, le fichier de configuration par défaut est ignoré.
-g
Désactive le collage de subordonnés. Seule la base de données spécifiée sera traitée, et non ses subordonnés collés (le cas échéant).
-H  URI
Utilise le DN, la portée et le filtre de l'URI pour ne traiter que les entrées correspondantes.
-l fichier-erreurs
Écrit les erreurs dans le fichier spécifié au lieu de la sortie standard.
-n num-bd
Vérifie la num-bd-ième base de données listée dans le fichier de configuration. La base de données de configuration slapd-config(5) est toujours la première base de données, donc utilisez -n 0.

L'option -n ne peut pas être utilisée conjointement avec l'option -b.

-o option[=valeur]
Spécifie une option avec une valeur (optionnelle). Les options/valeurs génériques possibles sont :
              syslog=<sous-systèmes>  (voir `-s' dans slapd(8))
              syslog-level=<niveau> (voir `-S' dans slapd(8))
              syslog-user=<utilisateur>   (voir `-l' dans slapd(8))
-s sous-arbre-dn
Vérifie uniquement les entrées du sous-arbre spécifié par ce DN. Implique -b sous-arbre-dn si aucune option -b ni -n n'est donnée. Obsolète ; utiliser -H ldap:///sous-arbre-dn à la place.
-v
Active le mode verbeux.

LIMITATIONS

Pour certains types de backends, votre slapd(8) ne devrait pas être en cours d'exécution (du moins, pas en mode lecture-écriture) lorsque vous faites cela pour assurer la cohérence de la base de données. Il est toujours sûr d'exécuter slapschema avec les backends slapd-mdb(5) et slapd-null(5).

EXEMPLES

Pour vérifier la conformité du schéma de votre base de données SLAPD après des modifications du schéma, et pour placer toute erreur dans un fichier appelé errors.ldif, utilisez la commande :

/usr/bin/slapschema -l errors.ldif
