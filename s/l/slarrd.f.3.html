sous-routine slarrd (character range, character order, integer n, real vl, real vu, integer il, integer iu, real, dimension( * ) gers, real reltol, real, dimension( * ) d, real, dimension( * ) e, real, dimension( * ) e2, real pivmin, integer nsplit, integer, dimension( * ) isplit, integer m, real, dimension( * ) w, real, dimension( * ) werr, real wl, real wu, integer, dimension( * ) iblock, integer, dimension( * ) indexw, real, dimension( * ) work, integer, dimension( * ) iwork, integer info)

SLARRD calcule les valeurs propres d'une matrice tridiagonale symétrique avec une précision appropriée.

Objectif :

!>
!> SLARRD calcule les valeurs propres d'une matrice tridiagonale
!> symétrique T avec une précision appropriée. Ceci est un code auxiliaire à appeler
!> depuis SSTEMR.
!> L'utilisateur peut demander toutes les valeurs propres, toutes les valeurs propres
!> dans l'intervalle semi-ouvert (VL, VU], ou les valeurs propres de rang IL à IU.
!>
!> Pour éviter le débordement, la matrice doit être mise à l'échelle de sorte que son
!> élément le plus grand ne dépasse pas overflow**(1/2) * underflow**(1/4) en valeur absolue, et pour une meilleure
!> précision, elle ne doit pas être beaucoup plus petite que cela.
!>
!> Voir W. Kahan , Rapport CS41, Département des sciences informatiques, Université de Stanford
!> Stanford, 21 juillet 1966.
!>

Paramètres

RANGE 
!>          RANGE est CHARACTER*1
!>          = 'A': ()   toutes les valeurs propres seront trouvées.
!>          = 'V': () toutes les valeurs propres dans l'intervalle
!>                           semi-ouvert (VL, VU] seront trouvées.
!>          = 'I': () les valeurs propres de rang IL à IU (de la
!>                           matrice entière) seront trouvées.
!>

ORDER

!>          ORDER est CHARACTER*1
!>          = 'B': () les valeurs propres seront groupées par
!>                              blocs décomposés (voir IBLOCK, ISPLIT) et
!>                              ordonnées de la plus petite à la plus grande au sein
!>                              du bloc.
!>          = 'E': ()
!>                              les valeurs propres de la matrice entière
!>                              seront ordonnées de la plus petite à la plus
!>                              grande.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice tridiagonale T. N >= 0.
!>

VL

!>          VL est REAL
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures ou égales
!>          à VL, ou supérieures à VU, ne seront pas retournées. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est REAL
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures ou égales
!>          à VL, ou supérieures à VU, ne seront pas retournées. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

GERS

!>          GERS est tableau REAL, dimension (2*N)
!>          Les N intervalles de Gerschgorin (le i-ème intervalle de Gerschgorin
!>          est (GERS(2*i-1), GERS(2*i)).
!>

RELTOL

!>          RELTOL est REAL
!>          La largeur relative minimale d'un intervalle. Quand un intervalle
!>          est plus étroit que RELTOL multiplié par le plus grand des
!>          points extrêmes (en valeur absolue), alors il est considéré
!>          comme suffisamment petit, c'est-à-dire convergent. Note : ceci devrait
!>          toujours être au moins epsilon machine * radix.
!>

D

!>          D est tableau REAL, dimension (N)
!>          Les N éléments diagonaux de la matrice tridiagonale T.
!>

E

!>          E est tableau REAL, dimension (N-1)
!>          Les N-1 éléments hors diagonaux de la matrice tridiagonale T.
!>

E2

!>          E2 est tableau REAL, dimension (N-1)
!>          Les N-1 éléments hors diagonaux carrés de la matrice tridiagonale T.
!>

PIVMIN

!>          PIVMIN est REAL
!>          Le pivot minimum autorisé dans la séquence de Sturm pour T.
!>

NSPLIT

!>          NSPLIT est INTEGER
!>          Le nombre de blocs diagonaux dans la matrice T.
!>          1 <= NSPLIT <= N.
!>

ISPLIT

!>          ISPLIT est tableau INTEGER, dimension (N)
!>          Les points de découpe, auxquels T se divise en sous-matrices.
!>          La première sous-matrice comprend les lignes/colonnes 1 à ISPLIT(1),
!>          la deuxième les lignes/colonnes ISPLIT(1)+1 à ISPLIT(2),
!>          etc., et la NSPLIT-ième comprend les lignes/colonnes
!>          ISPLIT(NSPLIT-1)+1 à ISPLIT(NSPLIT)=N.
!>          (Seuls les NSPLIT premiers éléments seront effectivement utilisés, mais
!>          comme l'utilisateur ne peut pas savoir à l'avance quelle valeur aura NSPLIT,
!>          N mots doivent être réservés pour ISPLIT.)
!>

M

!>          M est INTEGER
!>          Le nombre réel de valeurs propres trouvées. 0 <= M <= N.
!>          (Voir aussi la description de INFO=2,3.)
!>

W

!>          W est tableau REAL, dimension (N)
!>          En sortie, les M premiers éléments de W contiendront les
!>          approximations des valeurs propres. SLARRD calcule un intervalle
!>          I_j = (a_j, b_j] qui inclut la valeur propre j. L'approximation de la valeur propre
!>          est donnée par le point milieu de l'intervalle
!>          W(j)= ( a_j + b_j)/2. L'erreur correspondante est bornée par
!>          WERR(j) = abs( a_j - b_j)/2
!>

WERR

!>          WERR est tableau REAL, dimension (N)
!>          La borne d'erreur sur l'approximation correspondante de la valeur propre
!>          dans W.
!>

WL

!>          WL est REAL
!>

WU

!>          WU est REAL
!>          L'intervalle (WL, WU] contient toutes les valeurs propres désirées.
!>          Si RANGE='V', alors WL=VL et WU=VU.
!>          Si RANGE='A', alors WL et WU sont les bornes de Gerschgorin globales

!>          Si RANGE='I', alors WL et WU sont calculés par SLAEBZ à partir de la
!>                        plage d'indices spécifiée.
!>

IBLOCK

!>          IBLOCK est tableau INTEGER, dimension (N)
!>          À chaque ligne/colonne j où E(j) est zéro ou petit, la

!>          espace de travail.)

NOM


slarrd - Liste les valeurs propres d'une matrice par blocs.







SYNOPSIS


subroutine slarrd(range, vl, vu, il, iu, abstol, m, W, Z, Zd, iwork, resid, v,
                 iwork2, tau, info)

real            range, vl, vu, abstol
integer         il, iu, m, iwork(*), iwork2(*)
real            W(*), Z(ldz,*)
real            resid(*), v(*), tau(*)
integer         info
character       *(*) range
integer         ldz








Purpose


slarrd calcule les valeurs propres d'une matrice par blocs
    spéciale (de la forme T = diag(D) + B), où D est une matrice
    diagonale et B est une matrice bande symétrique.







Arguments


RANGE


  CHARACTER*1   RANGE



    
  
  • 
    
    RANGE est CHARACTER*1.
    
  
    • 
  
  • 
    
    Il spécifie l'ordre dans lequel les valeurs propres
        sont calculées.
    
  
    • 
  
  • 
    
    'A' : Toutes les valeurs propres sont calculées.
    
  
    • 
  
  • 
    
    'V' : Toutes les valeurs propres dans l'intervalle
        [vl, vu] sont calculées.
    
  
    • 
  
  • 
    
    'I' : Les IL-ième à IU-ième valeurs propres
        sont calculées.
    
  
    • 



VL, VU


  REAL          VL, VU



    
  
  • 
    
    Si RANGE = 'V', les bornes inférieure et supérieure
        de l'intervalle des valeurs propres à rechercher sont vl et
        vu.
    
  
    • 
  
  • 
    
    vl et vu doivent être des valeurs réelles.
    
  
    • 



IL, IU


  INTEGER       IL, IU



    
  
  • 
    
    Si RANGE = 'I', les indices de la première et de la
        dernière valeur propre à rechercher sont il et iu.
    
  
    • 
  
  • 
    
    1 <= il <= iu <= N.
    
  
    • 



ABSTOL


  REAL          ABSTOL



    
  
  • 
    
    Le seuil d'erreur absolue pour les valeurs propres.
    
  
    • 
  
  • 
    
    Pour chaque valeur propre λ, le tolérance absolue est
        max(abstol, ulp * max(|&lambda|,|v|)), où ulp est l'unité
        de dépassement la plus proche de λ. Si abstol est
        fixé à zéro, alors la tolérance par défaut est
        utilisée.
    
  
    • 



M


  INTEGER       M



    
  
  • 
    
    Le nombre de valeurs propres calculées.
    
  
    • 
  
  • 
    
    Si RANGE = 'A', m = N.
    
  
    • 
  
  • 
    
    Si RANGE = 'V', m est le nombre de valeurs propres
        dans [vl, vu].
    
  
    • 
  
  • 
    
    Si RANGE = 'I', m = iu - il + 1.
    
  
    • 



W


  REAL          W(N)



    
  
  • 
    
    Les valeurs propres calculées, triées par ordre croissant.
    
  
    • 



Z


  REAL          Z(LDZ,*)



    
  
  • 
    
    Les vecteurs propres calculés. Z(*, i) est le vecteur propre
        correspondant à W(i).
    
  
    • 



ZD


  REAL          ZD(N)



    
  
  • 
    
    Les valeurs propres calculées pour la matrice par blocs.
    
  
    • 



IWORK


  INTEGER       IWORK(3*N)



    
  
  • 
    
    Tableau de travail.
    
  
    • 



RESID


  REAL          RESID(N)



    
  
  • 
    
    Les valeurs résiduelles.
    
  
    • 



V


  REAL          V(N)



    
  
  • 
    
    Ce paramètre n'est pas utilisé dans cette sous-routine.
    
  
    • 



IWORK2


  INTEGER       IWORK2(N)



    
  
  • 
    
    Les indices des valeurs propres dans chaque bloc.
    
  
    • 
  
  • 
    
    Par exemple, INDEXW(i)= j et IBLOCK(i)=k impliquent que la
        i-ième valeur propre W(i) est la j-ième valeur propre dans le bloc
        k.
    
  
    • 



WORK


  REAL          WORK(4*N)



IWORK


  INTEGER       IWORK(3*N)



INFO


  INTEGER       INFO



    
  
  • 
    
    = 0: sortie réussie.
    
  
    • 
  
  • 
    
    < 0: Si INFO = -i, le i-ième argument avait une valeur
        illégale.
    
  
    • 
  
  • 
    
    > 0: Certaines ou toutes les valeurs propres n'ont pas convergé
        ou n'ont pas été calculées.
    
    
      
      
    • 
        
      =1 ou 3: La dichotomie n'a pas convergé pour certaines
            valeurs propres; ces valeurs propres sont signalées par un numéro
            de bloc négatif. L'effet est que les valeurs propres peuvent ne
            pas être aussi précises que les tolérances absolues et
            relatives. Ceci est généralement causé par une
            arithmétique inattendument imprécise.
      
      
      • 
      
    • 
        
      =2 ou 3: RANGE = 'I' uniquement: Toutes les valeurs
            propres IL:IU n'ont pas été trouvées.
      
        
      Effet: M < IU+1-IL
      
        
      Cause: arithmétique non-monotone, causant une séquence
            de Sturm non-monotone.
      
        
      Remède: recalculer, en utilisant RANGE = 'A', et
            extraire les valeurs propres IL:IU. Dans certains cas, augmenter le
            PARAMÈTRE FUDGE peut fonctionner.
      
      
      • 
      
    • 
        
      = 4: RANGE = 'I', et l'intervalle de
            Gershgorin initialement utilisé était trop petit. Aucune valeur
            propre n'a été calculée.
      
        
      Cause probable: votre machine a une arithmétique à virgule
            flottante peu fiable.
      
        
      Remède: Augmenter le PARAMÈTRE FUDGE,
            recompiler et réessayer.
      
      
      • 
    
    
  
    • 








Paramètres internes




  FUDGE   REAL, default = 2
          Un paramètre pour élargir les intervalles de Gershgorin. Idéalement,
          une valeur de 1 devrait fonctionner, mais sur les machines avec une
          arithmétique peu fiable, celle-ci doit être plus grande. La valeur
          par défaut pour les versions publiées publiquement devrait être
          suffisamment grande pour gérer la pire machine disponible. Noter que
          cela n'a aucun effet sur la précision de la solution.
