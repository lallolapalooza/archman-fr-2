NOM

slapd.overlays - superpositions pour slapd, le démon LDAP autonome

DESCRIPTION

Le démon slapd(8) peut utiliser une variété de superpositions différentes pour modifier ou étendre le comportement normal d'une base de données backend. Les superpositions peuvent être compilées statiquement dans slapd, ou lorsque le support des modules est activé, elles peuvent être chargées dynamiquement. La plupart des superpositions ne peuvent être configurées que sur des bases de données individuelles, mais certaines peuvent également être configurées globalement.

Les options de configuration pour chaque superposition sont documentées séparément dans les pages de manuel correspondantes slapo-<overlay>(5).

accesslog
Journalisation des accès. Cette superposition peut enregistrer les accès à une base de données backend donnée dans une autre base de données.
auditlog
Journalisation d'audit. Cette superposition enregistre les modifications apportées à une base de données backend donnée dans un fichier journal LDIF. Par défaut, elle n'est pas intégrée.
autoca
Superposition d'Autorité de Certification automatique. Cette superposition peut générer des paires certificat/clé X.509 pour les entrées de l'annuaire si slapd est lié à OpenSSL. Par défaut, elle n'est pas intégrée.
chain
Chaînage. Cette superposition permet de suivre automatiquement les références lorsqu'une référence aurait été retournée, soit configurée par le serveur, soit demandée par le client.
collect
Attributs Collectifs. Cette superposition implémente les attributs collectifs RFC 3671 ; ces attributs partagent des valeurs communes sur tous les membres de la collection héritées d'une entrée ancêtre.
constraint
Contrainte. Cette superposition applique une contrainte d'expression régulière sur toutes les valeurs des attributs spécifiés. Elle est utilisée pour appliquer une syntaxe plus rigoureuse lorsque la syntaxe d'attribut sous-jacente est trop générale.
dds
Services d'Annuaire Dynamiques. Cette superposition supporte les objets dynamiques, qui ont une durée de vie limitée après laquelle ils expirent et sont automatiquement supprimés.
deref
Contrôle de Déréférencement. Cette superposition implémente le brouillon du contrôle de déréférencement. La superposition peut être utilisée avec n'importe quelle base de données ou globalement pour toutes les bases de données.
dyngroup
Groupe Dynamique. Ceci est une superposition de démonstration qui étend l'opération Compare pour détecter les membres d'un groupe dynamique. Elle n'a aucun effet sur les autres opérations.
dynlist
Liste Dynamique. Cette superposition permet l'expansion des groupes dynamiques et plus encore.
homedir
Provisionnement de Répertoire Personnel. Cette superposition gère la création/suppression des répertoires personnels pour les comptes Unix basés sur LDAP.
memberof
MemberOf. Cette superposition maintient des valeurs automatiques de appartenance inverse aux groupes, généralement stockées dans un attribut appelé memberOf. Cette superposition est obsolète et devrait être remplacée par dynlist.
otp
Module OATH One-Time Password. Ce module permet d'utiliser le mot de passe à usage unique basé sur le temps, alias mot de passe d'authentification, et le mot de passe à usage unique basé sur HMAC en conjonction avec un mot de passe LDAP standard pour une authentification à deux facteurs.
pbind
Proxybind. Cette superposition transfère les requêtes de liaison simple sur une base de données locale à un serveur LDAP distant.
pcache
Proxycache. Cette superposition permet la mise en cache des requêtes de recherche LDAP dans une base de données locale. Elle est le plus souvent utilisée avec les backends slapd-ldap(5) ou slapd-meta(5).
ppolicy
Politique de Mot de Passe. Cette superposition fournit une variété de mécanismes de contrôle de mot de passe, par exemple, expiration du mot de passe, contrôle de réutilisation et duplication du mot de passe, réinitialisations obligatoires du mot de passe, etc.
refint
Intégrité Référentielle. Cette superposition peut être utilisée avec une base de données backend comme slapd-mdb(5) pour maintenir la cohésion d'un schéma qui utilise des attributs de référence.
remoteauth
Authentification à Distance. Cette superposition délègue les requêtes d'authentification à des annuaires distants.
retcode
Code de Retour. Cette superposition est utile pour tester le comportement des clients lorsque des réponses erronées et/ou inhabituelles générées par le serveur se produisent.
rwm
Rewrite/remap. Cette superposition est expérimentale. Elle effectue des réécritures de DN/données de base et des mappages d'objectClass/attributeType.
sssvlv
Tri côté serveur et Vues de Liste Virtuelle. Cette superposition implémente les contrôles de tri côté serveur RFC2891 et les contrôles de vue de liste virtuelle, et remplace l'implémentation des résultats paginés RFC2696 pour garantir qu'elle fonctionne avec la technique de tri.
syncprov
Fournisseur Syncrepl. Cette superposition implémente le support côté fournisseur pour la réplication syncrepl, y compris la fonctionnalité de recherche persistante.
translucent
Proxy Translucide. Cette superposition peut être utilisée avec une base de données backend comme slapd-mdb(5) pour créer un "proxy translucide". Le contenu des entrées récupérées d'un serveur LDAP distant peut être partiellement remplacé par la base de données.
unique
Unicité d'Attribut. Cette superposition peut être utilisée avec une base de données backend comme slapd-mdb(5) pour garantir l'unicité de certains ou de tous les attributs au sein d'un sous-arbre.
valsort
Tri des Valeurs. Cette superposition peut être utilisée pour imposer un ordre spécifique pour les valeurs d'un attribut lorsqu'il est retourné dans une recherche.

NOM

slapd.overlays - Configuration des superpositions de serveurs LDAP

DESCRIPTION

Le démon du serveur LDAP, slapd, prend en charge un mécanisme de superposition qui permet de modifier le comportement du serveur sans avoir à modifier le code source du serveur. Les superpositions sont configurées au niveau de l'annuaire, sous l'entrée de configuration du serveur.

La configuration d'une superposition implique les éléments suivants :

  • L'attribut ol_oc_ators de l'entrée de configuration du serveur spécifie les OIDs des classes d'objets que la superposition doit intercepter.
  • L'attribut ol_csn_behavior de l'entrée de configuration du serveur spécifie le comportement des CSN pour cette superposition.
  • L'attribut ol_type de l'entrée de configuration du serveur spécifie le type de superposition à appliquer.
  • Les attributs restants dans l'entrée de configuration du serveur sont spécifiques à la superposition et sont utilisés pour configurer son comportement.

Les superpositions courantes incluent :

  • syncprov : Permet la réplication synchronisée des modifications entre les serveurs LDAP.
  • accesslog : Enregistre toutes les opérations d'accès aux données dans un annuaire séparé.
  • auditlog : Enregistre les événements de sécurité et les modifications apportées à l'annuaire.
  • collectstats : Collecte des statistiques sur les performances du serveur.
  • rlimit : Permet de définir des limites de ressources pour les requêtes des clients.
  • pcache : Implémente un cache de performances pour accélérer les recherches.
  • val-order : Permet la validation des valeurs d'attribut en fonction d'un ordre spécifié.
  • lastmod : Enregistre la date et l'heure de la dernière modification d'une entrée.
  • unique : Garantit que les valeurs d'attribut sont uniques dans l'annuaire.
  • pmod-rewrite : Permet la réécriture des modifications apportées aux entrées.
  • chaining : Permet de chaîner plusieurs annuaires LDAP ensemble.
  • locate : Permet de localiser des entrées dans un annuaire.
  • remoteops : Permet d'exécuter des opérations à distance sur d'autres serveurs LDAP.
  • deref : Permet le déréférencement des alias lors des recherches.
  • lazybind : Permet un processus de liaison paresseux pour les clients.
  • translucent : Implémente une superposition translucide pour les données.
  • ssv : Permet la gestion des contraintes d'intégrité sémantique.

La configuration de chaque superposition est stockée sous l'entrée cn=config et peut être modifiée à l'aide d'outils LDAP standard tels que ldapmodify.

Pour plus de détails sur la configuration et l'utilisation de chaque superposition, veuillez consulter la documentation spécifique à la superposition ou le fichier slapd.conf.
