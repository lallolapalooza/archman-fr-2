NOM

slurmd - Le démon du nœud de calcul pour Slurm.

SYNTAXE

slurmd [OPTIONS...]

DESCRIPTION

slurmd est le démon du nœud de calcul de Slurm. Il surveille toutes les tâches en cours sur le nœud de calcul, accepte le travail (tâches), lance les tâches et tue les tâches en cours sur demande.

OPTIONS

--authinfo
Utilisé avec le mode sans configuration (configless) pour définir un paramètre AuthInfo alternatif utilisé pour établir la communication avec slurmctld avant que le fichier de configuration n'ait été récupéré. (Par exemple, pour spécifier un emplacement de socket MUNGE alternatif.)
-b
Signale le redémarrage du nœud lors du redémarrage du démon. Utilisé à des fins de test.
-c
Supprime les verrous système si nécessaire. Ceci peut être requis si slurmd s'est terminé anormalement.
-C
Affiche la configuration matérielle réelle (pas la configuration du fichier slurm.conf) et quitte. Le format de la sortie est le même que celui utilisé dans slurm.conf pour décrire la configuration d'un nœud, plus son temps de fonctionnement. Vous pouvez utiliser --parameters pour spécifier des options telles que 'l3cache_as_socket' qui peuvent modifier la topologie du nœud rapportée.
--ca-cert-file <fichier>
Chemin absolu vers le certificat d'autorité de certification (CA) utilisé pour récupérer la configuration lors de l'exécution sans configuration (configless) dans un cluster activé pour TLS.
--conf <paramètres du nœud>
Utilisé conjointement avec l'option -Z. Utilisé pour remplacer ou définir des paramètres supplémentaires d'un nœud dynamique en utilisant la même syntaxe et les mêmes paramètres que ceux utilisés pour définir les nœuds dans slurm.conf. La spécification de CPUs, Boards, SocketsPerBoard, CoresPerSocket ou ThreadsPerCore remplacera les valeurs par défaut définies par l'option -C. NodeName et Port ne sont pas pris en charge. Ceci peut également être utilisé pour spécifier la topologie d'un nœud cloud, auquel cas l'indicateur -Z ne doit pas être utilisé (par exemple, --conf="topology=topo-switch:s1")

Par exemple, si slurmd -C rapporte

NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848

les spécifications --conf suivantes généreront les définitions de nœuds correspondantes :

--conf "Gres=gpu:2"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848 Gres=gpu:2
--conf "RealMemory=30000"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=30000
--conf "CPUs=16"
NodeName=node1 CPUs=16 RealMemory=331848
--conf "CPUs=16 RealMemory=30000 Gres=gpu:2"
NodeName=node1 CPUs=16 RealMemory=30000 Gres=gpu:2"
--conf-server <hôte|adresse ip>[:<port>]
Liste de contrôleurs séparés par des virgules, le premier étant le slurmctld principal. Un port peut (facultativement) être spécifié pour chaque contrôleur. Ces hôtes sont ceux à partir desquels slurmd récupérera la configuration lors de l'exécution en mode « sans configuration » (configless). NOTE : Si vous spécifiez une adresse IPv6, encadrez l'<adresse ip> entre crochets [] pour distinguer l'adresse du port. Ceci est requis même si aucun port n'est spécifié.
-d <fichier>
Spécifie le chemin complet du programme slurmstepd à utiliser pour encadrer les étapes de travail des utilisateurs. Ceci peut être utile à des fins de test.
-D
Exécute slurmd au premier plan avec la journalisation copiée sur stderr.
--extra <chaîne arbitraire>
Définit des données « extra » au démarrage du nœud. Si ceci est une chaîne json et que SchedulerParameters=extra_constraints est défini dans slurm.conf, alors les travaux peuvent utiliser l'option --extra pour filtrer en fonction de ces données « extra ».
-f <fichier>
Lit la configuration depuis le fichier spécifié. Voir les NOTES ci-dessous.
-F[fonctionnalité]
Démarre ce nœud en tant que nœud Dynamic Future. Il essaiera de faire correspondre une définition de nœud avec un état FUTURE, en utilisant éventuellement la fonctionnalité spécifiée pour faire correspondre la définition du nœud.
-G
Affiche la configuration des Ressources Génériques (GRES) (basée sur slurm.conf GRES fusionnée avec le contenu de gres.conf pour ce nœud) et quitte.
-h
Aide ; affiche un bref résumé des options de commande.
--instance-id <id instance cloud>
Définit l'ID de l'instance cloud au démarrage du nœud.
--instance-type <type instance cloud>
Définit le type de l'instance cloud au démarrage du nœud.
-L <fichier>
Écrit les messages de journal dans le fichier spécifié.
-M
Verrouille les pages de slurmd en mémoire système en utilisant mlockall (2) pour désactiver la pagination du processus slurmd. Cela peut aider dans les cas où les nœuds sont marqués comme DOWN pendant les périodes d'activité intense de permutation (swap). Si l'appel système mlockall (2) n'est pas disponible, une erreur sera imprimée dans le journal et slurmd continuera normalement.

Il est suggéré de définir LaunchParameters=slurmstepd_memlock dans slurm.conf(5) lors de la définition de -M.

-n <valeur>
Définit la valeur de nice du démon à la valeur spécifiée, typiquement un nombre négatif. Notez également le paramètre de configuration PropagatePrioProcess.
-N <nom du nœud>
Exécute le démon avec le nom de nœud donné. Utilisé pour émuler un système plus grand avec plus d'un démon slurmd par nœud. Nécessite que Slurm soit compilé avec l'option de configuration --enable-multiple-slurmd.
--parameters <paramètres slurmd>
Permet des changements temporaires spécifiques au nœud pour SlurmdParameters. Peut être utilisé conjointement avec -C pour spécifier des options telles que 'l3cache_as_socket' qui peuvent modifier la topologie du nœud rapportée. Ces paramètres sont ajoutés à tous les Paramètres spécifiques au nœud définis dans slurm.conf.
-s
Change le répertoire de travail de slurmd vers le chemin SlurmdLogFile si possible, sinon vers SlurmdSpoolDir. Si les deux échouent, il se rabattra sur /var/tmp.

NOM

slurmd – Slurm daemon

SYNTOPSIS

slurmd [-aCchDdFfGgIiLlMmNnOoPprSstVvXxZ] [--conf fichier_configuration] [--daemonize] [--debug [niveau_debug]] [--disable_http] [--disable_rpc] [--dump_config] [--file_desc desc_max] [--foreground] [--get_api_settings] [--get_affinity] [--get_config] [--get_load_avg] [--get_node_name] [--get_topology_nodes] [--get_topology_parents] [--get_topology_parents_mask] [--get_topology_siblings] [--help] [--http_port port_num] [--job_log job_log_file] [--log_level niveau_log] [--log_file fichier_log] [--message_level niveau_message] [--network type_reseau] [--no_fork] [--no_http] [--no_resolve] [--pid_file fichier_pid] [--plugin_debug drapeaux_debug_plugin] [--plugin_path chemin_plugin] [--port port_num] [--preempt_mode mode_preempt] [--ptrace] [--reconfigure] [--resv_port] [--rpc_timeout delai_rpc] [--srun_priority priorite_srun] [--srun_timeout delai_srun] [--state_save_level niveau_sauvegarde_etat] [--std_listen_port port_std] [--std_network reseau_std] [--std_port port_std] [--syslog [niveau_syslog]] [--tmp_dir rep_temporaire] [--user_fmt format_utilisateur] [--verbose] [--version] [-Z]

DESCRIPTION

Le programme slurmd est le démon principal du nœud de calcul pour le système de gestion de ressources Slurm. Ce démon est responsable de la gestion des tâches sur un nœud de calcul. Il communique avec le démon du contrôleur slurmctld(8) et lance, surveille et termine les tâches selon les instructions de slurmctld.

Si le démon est démarré avec l'option -D, il s'exécute en premier plan. Sinon, il s'exécute en arrière-plan, et son comportement est contrôlé par les options --daemonize et --no_fork.

OPTIONS

-a, --all
Utilisé pour des requêtes de réinitialisation de configuration à partir du contrôleur, pour demander des informations sur l'ensemble des nœuds.
-C, --conf_file fichier_configuration
Spécifie le fichier de configuration à utiliser. Voir slurm.conf(5) pour la syntaxe et les descriptions des paramètres.
-c, --check_srun
Vérifie la présence des exécutables slurm à l'aide de l'option de configuration CheckSrunRC.
-d, --daemonize
Fait fonctionner le démon en arrière-plan.
-D, --debug [niveau_debug]
Exécute le démon en premier plan et définir le niveau de débogage. Si aucun niveau n'est spécifié, il utilise la valeur de configuration par défaut.
-f, --foreground
Exécute le démon en premier plan. Les informations de débogage seront écrites sur la sortie d'erreur standard.
-F, --disable_http
Désactive le serveur HTTP.
-G, --get_api_settings
Récupère les paramètres de l'API et quitte.
-g, --get_config
Récupère la configuration et quitte.
-h, --help
Affiche un message d'aide et quitte.
-i, --no_fork
N'effectue pas de fork du processus principal. Utile lors de l'utilisation de l'option -D.
-I, --disable_rpc
Désactive le serveur RPC.
-l, --log_level niveau_log
Définit le niveau de log. Les niveaux possibles sont basic, debug, detailed, info, state, all.
-L, --log_file fichier_log
Spécifie le fichier où les logs doivent être écrits. Si aucun fichier n'est spécifié, les logs iront sur la sortie d'erreur standard.
-m, --message_level niveau_message
Définit le niveau de message. Les niveaux possibles sont basic, debug, detailed, info, state, all.
-M, --get_load_avg
Récupère la charge moyenne et quitte.
-n, --no_resolve
Ne résout pas les noms des hôtes, utilise directement les adresses IP.
-N, --get_node_name
Récupère le nom du nœud et quitte.
-o, --get_topology_nodes
Récupère la liste des nœuds du système et quitte.
-O, --get_topology_parents
Récupère les parents des nœuds du système et quitte.
-p, --pid_file fichier_pid
Spécifie le fichier où le PID du démon doit être écrit.
-P, --plugin_path chemin_plugin
Spécifie le chemin vers les plugins Slurm.
-r, --reconfigure
Recharge la configuration à partir du fichier slurm.conf.
-R, --resv_port
Demande à l'OS de réserver les ports pour le service RPC.
-s, --syslog [niveau_syslog]
Envoie les logs au démon syslog. Si aucun niveau n'est spécifié, tous les messages seront envoyés.
-S, --state_save_level niveau_sauvegarde_etat
Définit le niveau de sauvegarde de l'état. Les niveaux possibles sont basic, debug, detailed, info, state, all.
-t, --tmp_dir rep_temporaire
Spécifie le répertoire temporaire à utiliser.
--systemd
À utiliser lors du démarrage du démon avec systemd. Cela permettra à slurmd de notifier systemd du nouveau PID lors de l'utilisation de 'scontrol reconfigure'.
-v
Fonctionnement détaillé. Plusieurs -v augmentent le niveau de détail.
-V, --version
Affiche les informations de version et quitte.
-Z
Démarre ce nœud en tant que nœud Normal Dynamique. Si aucun --conf n'est spécifié, alors slurmd s'enregistrera avec la même configuration matérielle (sauf GRES) que celle définie par l'option -C.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour remplacer les paramètres compilés dans slurmd.

ABORT_ON_FATAL
Lorsqu'une erreur fatale est détectée, utiliser abort() au lieu de exit() pour terminer le processus. Cela permet de capturer des traces de pile sans recompiler Slurm.
SLURM_CONF
L'emplacement du fichier de configuration de Slurm. Ceci est annulé en spécifiant explicitement un fichier de configuration sur la ligne de commande.
SLURM_DEBUG_FLAGS
Spécifie les drapeaux de débogage que slurmd doit utiliser. Voir DebugFlags dans la page de manuel slurm.conf(5) pour une liste complète des drapeaux. La variable d'environnement a priorité sur le paramètre dans slurm.conf.

SERVEUR HTTP

Sauf si désactivé via CommunicationParameters=disable_http dans slurm.conf, slurmd acceptera les requêtes conformes HTTP/1.1 entrantes sur n'importe quel socket d'écoute configuré par SlurmdPort dans slurm.conf. L'authentification des requêtes HTTP n'est pas prise en charge. L'encapsulation TLS est facultativement prise en charge sans nécessiter TLSType dans slurm.conf. Les points d'extrémité suivants sont actuellement pris en charge :

GET /
Obtenir la liste des points d'extrémité.
GET /healthz
Vérifier si slurmd s'est chargé avec succès.
GET /livez
Vérifier si slurmd s'est chargé avec succès.
GET /readyz
Vérifier si slurmd est prêt à accepter les RPC entrants.

SIGNaux

SIGTERM SIGINT SIGQUIT
slurmd s'arrêtera proprement.
SIGHUP
Recharge les fichiers de configuration de slurm, similaire à 'scontrol reconfigure'.
SIGUSR2
Relit le niveau de log à partir des configurations, puis rouvre le fichier de log. Ceci doit être utilisé lors de la configuration de logrotate(8).
SIGPIPE
Ce signal est explicitement ignoré.

EMPLACEMENT DES FICHIERS DE CŒUR

Si slurmd est démarré avec l'option -D, le fichier de cœur sera écrit dans le répertoire de travail actuel. Sinon, si SlurmdLogFile est un nom de chemin entièrement qualifié (commençant par un slash), le fichier de cœur sera écrit dans le même répertoire que le fichier de log. Sinon, le fichier de cœur sera écrit dans le répertoire SlurmdSpoolDir, ou "/var/tmp/" en dernier recours. Si aucun des répertoires ci-dessus ne peut être écrit, aucun fichier de cœur ne sera produit.

NOTES

Il peut être utile d'expérimenter avec différents paramètres de configuration spécifiques à slurmd en utilisant un fichier de configuration distinct (par exemple, les délais d'attente). Cependant, ce fichier de configuration spécial ne sera pas utilisé par le démon slurmctld ou les programmes Slurm, sauf si vous leur demandez spécifiquement de l'utiliser. Si vous souhaitez modifier les ports de communication, l'emplacement du système de fichiers temporaire ou d'autres paramètres utilisés par d'autres composants Slurm, modifiez le fichier de configuration commun, slurm.conf.

Si vous utilisez le mode sans configuration avec un nœud de connexion qui exécute de nombreuses commandes client, vous pourriez envisager d'exécuter slurmd sur cette machine afin qu'il puisse gérer une version mise en cache des fichiers de configuration. Sinon, chaque commande client utilisera l'enregistrement DNS pour contacter le contrôleur et obtenir les informations de configuration, ce qui pourrait imposer une charge supplémentaire au contrôleur.
