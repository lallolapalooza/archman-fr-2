subroutine slarfb_gett (character ident, integer m, integer n, integer k, real, dimension( ldt, * ) t, integer ldt, real, dimension( lda, * ) a, integer lda, real, dimension( ldb, * ) b, integer ldb, real, dimension( ldwork, * ) work, integer ldwork)

SLARFB_GETT

Objectif:

!>
!> SLARFB_GETT applique un bloc réflecteur de Householder réel H de la
!> gauche à une matrice réelle (K+M)-par-N
!> composée de deux matrices blocs : une matrice trapézoïdale supérieure K-par-N stockée dans le tableau A, et une matrice rectangulaire M-par-(N-K), stockée
!> dans le tableau B. Le bloc réflecteur H est stocké dans une représentation
!> WY compacte, où les réflecteurs élémentaires sont dans les
!> tableaux A, B et T. Voir la section Détails supplémentaires.
!>

Paramètres

IDENT 
!>          IDENT est CHARACTER*1
!>          Si IDENT n'est pas égal à 'I', ou pas égal à 'i', alors V1 est unité
!>             triangulaire inférieure et stockée dans le bloc K-par-K gauche de
!>             la matrice d'entrée A,
!>          Si IDENT est égal à 'I' ou 'i', alors V1 est une matrice identité et
!>             non stockée.
!>          Voir la section Détails supplémentaires.
!>

M

!>          M est INTEGER
!>          Le nombre de lignes de la matrice B.
!>          M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes des matrices A et B.
!>          N >= 0.
!>

K

!>          K est INTEGER
!>          Le nombre de lignes de la matrice A.
!>          K est aussi l'ordre de la matrice T, c'est-à-dire le nombre de
!>          réflecteurs élémentaires dont le produit définit le bloc
!>          réflecteur. 0 <= K <= N.
!>

T

!>          T est un tableau REAL, dimension (LDT,K)
!>          La matrice triangulaire supérieure K-par-K T dans la représentation
!>          du bloc réflecteur.
!>

LDT

!>          LDT est INTEGER
!>          La dimension principale du tableau T. LDT >= K.
!>

A

!>          A est un tableau REAL, dimension (LDA,N)
!>
!>          À l'entrée :
!>           a) Dans la partie trapézoïdale supérieure K-par-N A : matrice d'entrée A.
!>           b) Dans les colonnes sous la diagonale : colonnes de V1
!>              (les uns ne sont pas stockés sur la diagonale).
!>
!>          À la sortie :
!>            A est écrasée par le produit matriciel rectangulaire K-par-N H*A.
!>
!>          Voir la section Détails supplémentaires.
!>

LDA

!>          LDB est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,K).
!>

B

!>          B est un tableau REAL, dimension (LDB,N)
!>
!>          À l'entrée :
!>            a) Dans le bloc droit M-par-(N-K) : matrice d'entrée B.
!>            b) Dans le bloc gauche M-par-N : colonnes de V2.
!>
!>          À la sortie :
!>            B est écrasée par le produit matriciel rectangulaire M-par-N H*B.
!>
!>          Voir la section Détails supplémentaires.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,M).
!>

WORK

!>          WORK est un tableau REAL,
!>          dimension (LDWORK,max(K,N-K))
!>

LDWORK

!>          LDWORK est INTEGER
!>          La dimension principale du tableau WORK. LDWORK>=max(1,K).
!>
!>

!>
!>    (1) Description de l'opération algébrique.
!>
!>    La matrice A est une matrice K-par-N composée de deux matrices blocs de colonnes,
!>    A1, qui est K-par-K, et A2, qui est K-par-(N-K) :

!>       ( B_out )        ( B_in )                          ( B_in )

NAME

slarfb_gett

documentation of routines that implement the WY-bound transformations

SYNOPSIS

Subroutine SLARFB( SIDE, TRANS, DIRECT,
&                STOREQ, M, N, K, L,
&                V, LDV, T, LDT,
&                C, LDC, WORK, LDWORK )

Character SIDE*1
Character TRANS*1
Character DIRECT*1
Character STOREQ*1
Integer M, N, K, L, LDV, LDT, LDC, LDWORK

Real V( LDV, * ), T( LDT, * ), C( LDC, * ), WORK( LDWORK, * )

Function/Subroutine Documentation

This file documents the algorithmic details of the routines that implement the WY-bound transformations.

!
!     This file describes the implementation details of routines that
!     apply WY-bound transformations of the form
!
!        C := C - V*T*V**T * C
!
!     or
!
!        C := C - V*T*V**T * C
!
!     where V is a matrix of size M-by-K or N-by-K, T is a K-by-K
!     triangular matrix, and C is a matrix of size M-by-N.
!
!     The transformation is computed as follows.
!
!     Let C be partitioned as
!
!        C = [ A1 A2 ]
!            [ B1 B2 ]
!
!     where A1 is K-by-K, A2 is K-by-(N-K), B1 is (M-K)-by-K,
!     and B2 is (M-K)-by-(N-K).
!
!     Let V be partitioned as
!
!        V = [ V1 ]
!            [ V2 ]
!
!     where V1 is K-by-K and V2 is (M-K)-by-K.
!
!     The transformation can be written as
!
!        C := C - V * (T * V**T * C)
!
!     Let W = T * V**T * C.
!
!     If C is M-by-N, we can partition it as
!
!        C = [ C1 ]
!            [ C2 ]
!
!     where C1 is K-by-N and C2 is (M-K)-by-N.
!
!     Then W = T * V**T * C = T * [ V1**T V2**T ] * [ C1 ]
!                                                 [ C2 ]
!                               = T * (V1**T * C1 + V2**T * C2)
!
!     The matrix W has size K-by-N.
!
!     The computation is performed in two steps:
!
!     Step 1: Compute W.
!        W1 = V1**T * C1
!        W2 = V2**T * C2
!        W = T * (W1 + W2)
!
!     Step 2: Update C.
!        C = C - V * W
!
!     The matrix W can be partitioned similarly to C:
!
!        W = [ W1 ]
!            [ W2 ]
!
!     where W1 is K-by-K and W2 is (M-K)-by-K.
!
!     Then the update step is:
!
!        C1 = C1 - V1 * W1
!        C2 = C2 - V2 * W2
!
!     In practice, to reduce the number of matrix-vector operations,
!     the computation is performed in-place.
!
!     Let's consider the update C := C - V * W.
!     The matrix W is computed as W = T * (V**T * C).
!     The computation is organized as follows:
!
!     Let's assume C is M-by-N. We partition V as K-by-M and C as
!     N-by-M, so that V*T*V**T * C is computed.
!
!     Let V be M-by-K and C be M-by-N.
!     The transformation is C := C - V * T * (V**T * C).
!
!     Let W = V**T * C. W is K-by-N.
!     Partition W as
!
!        W = [ W1 ]
!            [ W2 ]
!
!     where W1 is K-by-K and W2 is (N-K)-by-K.  (This partition seems wrong.
!     W should be K-by-N. If C is M-by-N, V is M-by-K, then V**T is K-by-M.
!     V**T * C is (K x M) * (M x N) = K x N.
!     So W is K-by-N.
!
!     If we partition V as V = [V1 V2] where V1 is M-by-K and V2 is M-by-(N-K),
!     and C as C = [C1 C2] where C1 is M-by-K and C2 is M-by-(N-K).
!
!     This is confusing. Let's stick to the LAPACK convention.
!
!     The general form of the transformation is
!
!        apply( V, T, C )
!
!     where C is M-by-N, V is M-by-K, and T is K-by-K.
!     The transformation applied is C := C - V*T*V**T * C.
!
!     In the routine SLARFB, we have the following parameters:
!     SIDE = 'L': C is M-by-N, V is M-by-K, T is K-by-K.
!                 C := C - V*T*V**T * C
!     SIDE = 'R': C is M-by-N, V is N-by-K, T is K-by-K.
!                 C := C - V*T*V**T * C
!
!     Let's focus on SIDE = 'L'.
!
!     C is M-by-N. V is M-by-K. T is K-by-K.
!
!     If DIRECT = 'F' (Forward), then V contains the vectors, and T is
!     upper triangular.
!     If DIRECT = 'B' (Backward), then V contains the vectors, and T is
!     lower triangular.
!
!     The transformation is C := C - V*T*V**T * C.
!     Let W = T * V**T * C.
!     The computation is performed in two steps:
!     1. Compute W.
!     2. Compute C := C - V*W.
!
!     Let's focus on the implementation details.
!
!     The transformation is C := C - V * T * (V**T * C).
!
!     Let C = [ A1 A2 ]
!             [ B1 B2 ]
!
!     where A1 is K-by-K, A2 is K-by-(N-K), B1 is (M-K)-by-K, B2 is (M-K)-by-(N-K).
!     Let V = [ V1 ]
!             [ V2 ]
!
!     where V1 is K-by-K, V2 is (M-K)-by-K.
!
!     The transformation is C := C - V * T * V**T * C.
!
!     This can be rewritten as:
!     C := C - V * W
!     where W = T * V**T * C
!
!     Let's consider the computation of W.
!     W = T * (V**T * C)
!     Let X = V**T * C. X is K-by-N.
!
!     If C is M-by-N, V is M-by-K.
!     V**T is K-by-M.
!     X = V**T * C is (K x M) * (M x N) = K x N.
!
!     W = T * X is (K x K) * (K x N) = K x N.
!
!     So W has the same dimensions as C1.
!
!     Let's consider the algorithm described in the file
!     `slarfb_gett.f` (which is this file).
!
!     It seems to describe a different transformation.
!
!     The description seems to be related to a specific algorithm
!     for applying WY-transformations, possibly in the context of
!     Householder reflections.
!
!     Let's re-read the description carefully.
!
!     (2) Description of the Algorithmic Computation.
!
!     In the first step, we compute column block 2, i.e. A2 and B2.
!     Here, we need to use the K-by-(N-K) rectangular workspace
!     matrix W2 that is of the same size as the matrix A2.
!     W2 is stored in the array WORK(1:K,1:(N-K)).
!
!     In the second step, we compute column block 1, i.e. A1 and B1.
!     Here, we need to use the K-by-K square workspace matrix W1
!     that is of the same size as the as the matrix A1.
!     W1 is stored in the array WORK(1:K,1:K).
!
!     NOTE: Hence, in this routine, we need the workspace array WORK
!     only of size WORK(1:K,1:max(K,N-K)) so it can hold both W2 from
!     the first step and W1 from the second step.
!
!     The description seems to assume a partitioning of the matrix C
!     and the application of a transformation.
!
!     Let's analyze the operations described.
!
!     Case (A), when V1 is unit lower-triangular, i.e. IDENT != 'I',
!     more computations than in the Case (B).
!
!     This suggests that V1 is related to the matrix being transformed.
!
!     If ( N > K ) then  (First Step - column block 2)
!       col2_(1) W2: = A2
!       col2_(2) W2: = (V1**T) * W2 = (unit_lower_tr_of_(A1)**T) * W2
!       col2_(3) W2: = W2 + (V2**T) * B2 = W2 + (B1**T) * B2
!       col2_(4) W2: = T * W2
!       col2_(5) B2: = B2 - V2 * W2 = B2 - B1 * W2
!       col2_(6) W2: = V1 * W2 = unit_lower_tr_of_(A1) * W2
!       col2_(7) A2: = A2 - W2
!     else (Second Step - column block 1)
!       col1_(1) W1: = A1
!       col1_(2) W1: = (V1**T) * W1 = (unit_lower_tr_of_(A1)**T) * W1
!       col1_(3) W1: = T * W1
!       col1_(4) B1: = - V2 * W1 = - B1 * W1
!       col1_(5) square W1: = V1 * W1 = unit_lower_tr_of_(A1) * W1
!       col1_(6) square A1: = A1 - W1
!     end if
!
!     This description seems to be a detailed breakdown of the WY
!     transformation application.
!
!     Let's assume the transformation is C := C - V * T * V**T * C,
!     where C is M-by-N, V is M-by-K, T is K-by-K.
!
!     Partition C = [A1 A2] where A1 is M-by-K, A2 is M-by-(N-K).
!     Partition V = [V1 V2] where V1 is M-by-K, V2 is M-by-(N-K).
!
!     This is not matching the description.
!
!     Let's consider the description again:
!     C = [ A1 A2 ]  (K x K, K x (N-K))
!         [ B1 B2 ]  ((M-K) x K, (M-K) x (N-K))
!
!     V = [ V1 ]  (K x K)
!         [ V2 ]  ((M-K) x K)
!
!     This implies V is M-by-K and C is M-by-N.
!     The transformation is C := C - V * T * V**T * C.
!
!     The description is about computing A1, A2, B1, B2.
!     It seems the goal is to compute the updated A1, A2, B1, B2.
!
!     Let's assume the algorithm computes W = T * V**T * C.
!     And then updates C = C - V * W.
!
!     Let's trace the steps for N > K (First Step - column block 2).
!     This step updates A2 and B2.
!     W2 is a workspace of size K-by-(N-K).
!
!     col2_(1) W2: = A2
!       This seems to be initializing W2 with the A2 part of C.
!       This does not match W = T * V**T * C.
!
!     Let's look at the case N=M=K (square matrices).
!     C is KxK. V is KxK. T is KxK.
!     C := C - V * T * V**T * C.
!
!     If N <= K (Second Step - column block 1)
!       col1_(1) W1: = A1
!         A1 is the KxK matrix C.
!         So W1 = C.
!       col1_(2) W1: = (V1**T) * W1 = (unit_lower_tr_of_(A1)**T) * W1
!         V1 is the KxK part of V.
!         This implies V1 = V.
!         So W1 = V**T * C.
!       col1_(3) W1: = T * W1
!         So W1 = T * V**T * C.
!       col1_(4) B1: = - V2 * W1 = - B1 * W1
!         This seems to be updating B1.
!         But B1 is part of C.
!         This suggests the partitioning is different.
!
!     Let's reconsider the notation.
!     The description uses A1, A2, B1, B2 for partitioning C.
!     And V1, V2 for partitioning V.
!
!     Let C be M-by-N.
!     Let V be M-by-K.
!
!     If N > K, we compute column block 2 (A2, B2).
!     Workspace W2 is K-by-(N-K).
!
!     col2_(1) W2: = A2   (K x (N-K))
!     col2_(2) W2: = (V1**T) * W2
!       V1 is KxK. W2 is Kx(N-K). V1**T is KxK.
!       Result is Kx(N-K).
!       This assumes V1 is the top K rows of V.
!       So V1 is the top KxK submatrix of V.
!       A2 is the top K rows of the right (N-K) columns of C.
!       So W2 = V1**T * A2.
!
!     col2_(3) W2: = W2 + (V2**T) * B2
!       V2 is (M-K)xK. B2 is (M-K)x(N-K). V2**T is Kx(M-K).
!       This multiplication (V2**T) * B2 is not possible dimension-wise.
!       (K x (M-K)) * ((M-K) x (N-K)) = K x (N-K). This is correct.
!       The description says (V2**T) * B2 = (B1**T) * B2.
!       This implies V2 = B1 (or related).
!       If C = [A1 A2]
!               [B1 B2]
!       then B1 is (M-K)xK. V2 is (M-K)xK.
!       So V2 should be B1.
!       This means V = [A1]
!                     [B1]
!       And C = [A1 A2]
!               [B1 B2]
!       This implies A1 in V is the same as A1 in C.
!       And B1 in V is the same as B1 in C.
!       This means V is the first K columns of C.
!       Let C = [V C_rest].
!       Then C = [ A1 A2 ]
!                [ B1 B2 ]
!       V1 = A1, V2 = B1.
!       So col2_(3) W2: = W2 + (B1**T) * B2 = W2 + (V2**T) * B2.
!       So W2 = V1**T * A2 + V2**T * B2.
!
!     col2_(4) W2: = T * W2
!       T is KxK. W2 is Kx(N-K).
!       So W2 = T * (V1**T * A2 + V2**T * B2).
