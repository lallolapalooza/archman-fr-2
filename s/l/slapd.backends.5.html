NOM

slapd.backends - backends pour slapd, le démon LDAP autonome

DESCRIPTION

Le démon slapd(8) peut utiliser une variété de backends différents pour servir les requêtes LDAP. Les backends peuvent être compilés statiquement dans slapd, ou lorsque le support des modules est activé, ils peuvent être chargés dynamiquement. Plusieurs instances d'un backend peuvent être configurées pour servir des bases de données séparées à partir du même serveur slapd.

Les options de configuration pour chaque backend sont documentées séparément dans les pages de manuel slapd-<backend>(5) correspondantes.

asyncmeta
Ce backend effectue un proxy LDAP de base par rapport à un ensemble de serveurs LDAP distants. C'est une amélioration du backend ldap qui opère de manière asynchrone, pour éviter de bloquer les threads de slapd en attendant que les opérations se terminent.
config
Ce backend est utilisé pour gérer la configuration de slapd à l'exécution. Contrairement aux autres backends, une seule instance du backend config peut être définie. Il s'instancie également automatiquement, il est donc toujours présent même s'il n'est pas explicitement défini dans le fichier slapd.conf(5).
dnssrv
Ce backend est expérimental. Il sert des renvois basés sur les enregistrements ressource SRV détenus dans le système de noms de domaine.
ldap
Ce backend agit comme un proxy pour transférer les requêtes entrantes vers un autre serveur LDAP.
ldif
Cette base de données utilise le système de fichiers pour construire la structure arborescente de la base de données, en utilisant des fichiers texte brut pour stocker les données. Son utilisation devrait être limitée à des bases de données très simples, où la performance n'est pas une exigence. Ce backend prend également en charge les renommages de sous-arbres.
mdb
C'est le backend principal recommandé. Ce backend utilise la bibliothèque base de données transactionnelle MDB propre à OpenLDAP. Ce backend prend également en charge les renommages de sous-arbres.
meta
Ce backend effectue un proxy LDAP de base par rapport à un ensemble de serveurs LDAP distants. C'est une amélioration du backend ldap.
monitor
Ce backend fournit des informations sur l'état d'exécution du démon slapd. Une seule instance du backend monitor peut être définie.
null
Les opérations dans ce backend réussissent mais ne font rien.
passwd
Ce backend est fourni à des fins de démonstration uniquement. Il sert des informations de compte utilisateur à partir du fichier système passwd(5).
perl
Ce backend intègre un interpréteur perl(1) dans slapd. Il exécute des sous-routines Perl pour implémenter les opérations LDAP. Ce backend est obsolète.
relay
Ce backend est expérimental. Il redirige les opérations LDAP vers une autre base de données dans le même serveur, en fonction du contexte de nommage de la requête. Son utilisation nécessite la superposition rwm (voir slapo-rwm(5) pour plus de détails) pour réécrire le contexte de nommage de la requête. Il est principalement destiné à implémenter des vues virtuelles sur des bases de données qui stockent réellement les données.
sql
Ce backend est expérimental et obsolète. Il sert les requêtes LDAP à partir d'une base de données SQL.
wiredtiger
Ce backend est expérimental. Il sert les requêtes LDAP à partir d'une base de données wiredtiger.

FICHIERS
