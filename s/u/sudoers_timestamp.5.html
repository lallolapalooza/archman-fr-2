SUDOERS_TIMESTAMP(5) Manuel des formats de fichiers SUDOERS_TIMESTAMP(5)

NOM

sudoers_timestamp — Format des horodatages Sudoers

DESCRIPTION

Le plugin sudoers utilise des fichiers d'horodatage par ID utilisateur pour la mise en cache des identifiants. Une fois qu'un utilisateur a été authentifié, il peut utiliser sudo sans mot de passe pendant une courte période de temps (5 minutes sauf indication contraire de l'option timestamp_timeout). Par défaut, sudoers utilise un enregistrement séparé pour chaque terminal, ce qui signifie que les sessions de connexion de l'utilisateur sont authentifiées séparément. L'option timestamp_type peut être utilisée pour sélectionner le type d'enregistrement d'horodatage que sudoers utilisera.

Un format de fichier d'horodatage multi-enregistrements a été introduit dans sudo 1.8.10, qui utilise un seul fichier par utilisateur. Auparavant, un fichier séparé était utilisé pour chaque combinaison utilisateur et terminal, sauf si les horodatages basés sur tty étaient désactivés. Le nouveau format est extensible et des enregistrements de plusieurs types et versions peuvent coexister dans le même fichier.

Tous les enregistrements, quel que soit leur type ou leur version, commencent par un numéro de version de 16 bits et une taille d'enregistrement de 16 bits.

Les enregistrements d'horodatage ont la structure suivante :

/* Types d'entrées d'horodatage */
#define TS_GLOBAL               0x01U   /* non restreint par tty ou ppid */
#define TS_TTY                  0x02U   /* restreint par tty */
#define TS_PPID                 0x03U   /* restreint par ppid */
#define TS_LOCKEXCL             0x04U   /* enregistrement de verrouillage spécial */

/* Indicateurs d'horodatage */
#define TS_DISABLED             0x01U   /* entrée désactivée */
#define TS_ANYUID               0x02U   /* ignorer uid, valide uniquement dans la clé */

struct timestamp_entry {
    unsigned short version;     /* numéro de version */
    unsigned short size;        /* taille de l'enregistrement */
    unsigned short type;        /* TS_GLOBAL, TS_TTY, TS_PPID */
    unsigned short flags;       /* TS_DISABLED, TS_ANYUID */
    uid_t auth_uid;             /* uid à authentifier en tant que */
    pid_t sid;                  /* identifiant de session associé à tty/ppid */
    struct timespec start_time; /* démarrage de la session/ppid */
    struct timespec ts;         /* horodatage (CLOCK_MONOTONIC) */
    union {
        dev_t ttydev;           /* numéro de périphérique tty */
        pid_t ppid;             /* pid parent */
    } u;
};

Les champs de la structure timestamp_entry sont les suivants :

version
Le numéro de version de la structure timestamp_entry. De nouvelles entrées sont créées avec le numéro de version 2. Les enregistrements avec des numéros de version différents peuvent coexister dans le même fichier mais ne sont pas interopérables.
size
La taille de l'enregistrement en octets.
type
Le type d'enregistrement, actuellement TS_GLOBAL, TS_TTY, ou TS_PPID.
flags
Zéro ou plusieurs indicateurs d'enregistrement qui peuvent être combinés par un OU bit à bit. Les indicateurs pris en charge sont TS_DISABLED, pour les enregistrements désactivés via sudo -k et TS_ANYUID, qui est utilisé uniquement lors de la comparaison des enregistrements.
auth_uid
L'identifiant utilisateur qui a été utilisé pour l'authentification. Selon la valeur des options rootpw, runaspw et targetpw, l'identifiant utilisateur peut être celui de l'utilisateur appelant, de l'utilisateur root, de l'utilisateur runas par défaut ou de l'utilisateur cible.
sid
L'identifiant de la session du terminal de l'utilisateur, le cas échéant. L'identifiant de session n'est utilisé que lors de la comparaison des enregistrements de type TS_TTY.
start_time
L'heure de début du leader de session pour les enregistrements de type TS_TTY ou du processus parent pour les enregistrements de type TS_PPID. Le champ start_time est utilisé pour aider à prévenir la réutilisation d'un enregistrement d'horodatage après la déconnexion d'un utilisateur. Tous les systèmes ne prennent pas en charge une méthode pour récupérer facilement l'heure de début d'un processus. Le champ start_time a été ajouté dans la version sudoers 1.8.22 pour la deuxième révision de la structure timestamp_entry.
ts
L'horodatage réel. Une source de temps monotone (qui ne recule pas) est utilisée si le système la prend en charge. Dans la mesure du possible, sudoers utilise un minuteur monotone qui s'incrémente même lorsque le système est suspendu. La valeur de ts est mise à jour chaque fois qu'une commande est exécutée via sudo. Si la différence entre ts et l'heure actuelle est inférieure à la valeur de l'option timestamp_timeout, aucun mot de passe n'est requis.
u.ttydev
Le numéro de périphérique du terminal associé à la session pour les enregistrements de type TS_TTY.
u.ppid
L'identifiant du processus parent pour les enregistrements de type TS_PPID.

L'utilitaire tsdump, inclus dans la distribution source de sudo, peut être utilisé pour afficher le contenu d'un fichier d'horodatage sudoers.

VERROUILLAGE

Dans les versions de sudoers 1.8.10 à 1.8.14, l'ensemble du fichier d'horodatage était verrouillé pour un accès exclusif lors de la lecture ou de l'écriture dans le fichier. À partir de sudoers 1.8.15, les enregistrements individuels sont verrouillés dans le fichier d'horodatage au lieu du fichier entier, et le verrou est maintenu pendant une période plus longue. Ce système est décrit ci-dessous.

Le premier enregistrement dans le fichier d'horodatage est de type TS_LOCKEXCL et est utilisé comme enregistrement de verrouillage pour empêcher plus d'un processus sudo d'ajouter un nouvel enregistrement en même temps. Une fois l'enregistrement d'horodatage souhaité trouvé ou créé (et verrouillé), l'enregistrement TS_LOCKEXCL est déverrouillé. Le verrou sur l'enregistrement d'horodatage individuel, cependant, est maintenu jusqu'à ce que l'authentification soit terminée. Cela permet à sudoers d'éviter de demander un mot de passe plusieurs fois lorsqu'il est utilisé plus d'une fois dans un pipeline.

Les enregistrements de type TS_GLOBAL ne peuvent pas être verrouillés pendant une longue période, car cela interférerait avec d'autres processus sudo. Au lieu de cela, un enregistrement de verrouillage distinct est utilisé pour empêcher plusieurs processus sudo utilisant le même terminal (ou le même ID de processus parent) de demander un mot de passe en même temps.

VOIR AUSSI

sudoers(5), sudo(8)

HISTORIQUE

À l'origine, sudo utilisait un seul fichier de longueur nulle par utilisateur et l'heure de modification du fichier servait d'horodatage. Les versions ultérieures de sudo ont ajouté des restrictions sur la propriété des fichiers d'horodatage et du répertoire, ainsi que des vérifications sur la validité de l'horodatage lui-même. Des modifications notables ont été introduites dans les versions suivantes de sudo :

1.4.0
La prise en charge des fichiers d'horodatage basés sur tty a été ajoutée en ajoutant le nom du terminal au nom du fichier d'horodatage.
1.6.2
Le fichier d'horodatage a été remplacé par un répertoire par utilisateur qui contenait tous les fichiers d'horodatage basés sur tty.
1.6.3p2
Le nom de l'utilisateur cible a été ajouté au nom du fichier d'horodatage lorsque l'option targetpw était définie.
1.7.3
Des informations sur le périphérique du terminal ont été stockées dans les fichiers d'horodatage basés sur tty pour des vérifications de validité. Cela incluait les numéros de périphérique du terminal, le numéro d'inode et, sur les systèmes où il n'était pas mis à jour lors de l'écriture sur le périphérique, l'heure de modification de l'inode. Cela a contribué à empêcher la réutilisation du fichier d'horodatage après la déconnexion.
1.8.6p7
L'identifiant de session du terminal a été ajouté aux fichiers d'horodatage basés sur tty pour empêcher la réutilisation de l'horodatage par le même utilisateur dans une session de terminal différente. Cela a également contribué à empêcher la réutilisation du fichier d'horodatage sur les systèmes où l'heure de modification du périphérique de terminal était mise à jour par écriture.
1.8.10
Un nouveau format de fichier d'horodatage multi-enregistrements a été introduit, qui utilise un seul fichier par utilisateur. L'heure de modification du périphérique de terminal n'a pas été incluse car la plupart des systèmes mettent maintenant à jour l'heure de modification

sudoers_timestamp(5) — sudo

NAME

sudoers_timestamp — sudo timestamp file format

DESCRIPTION

The sudo utility uses a timestamp file to allow users to run multiple commands with privileges without having to re-enter their password. This file is a text file containing a list of privileged command usage time stamps. The format of the timestamp file is detailed below.

The timestamp file is usually located in /var/run/sudo/ts/, but this can be overridden by the --timestampdir option when compiling sudo, or by setting the SUDO_TIMESTAMPDIR environment variable.

LOCKING

The timestamp file is protected by a lock file, typically /var/run/sudo/ts/ts.lock. This lock file is used to prevent race conditions when multiple sudo processes access the same timestamp file.

SEE ALSO

sudoers(5), sudo.conf(5), sudo(8)

HISTORY

1.8.10
The timestamp file is created with 0600 mode after a write is performed as required by POSIX.
1.8.15
Individual records are locked in the time stamp file instead of the entire file and the lock is held until authentication is complete.
1.8.22
The start time of the terminal session leader or parent process is now stored in non-global time stamp records. This prevents reuse of the time stamp file after logout in most cases.

Support was added for the kernel-based tty time stamps available in OpenBSD which do not use an on-disk time stamp file.

1.9.15
Time stamp file path names are now based on the invoking user-ID instead of the user name. This avoids problems with user names that include a path separator character.
