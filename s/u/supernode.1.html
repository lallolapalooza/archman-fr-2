supernode(1) COMMANDES UTILISATEUR supernode(1)

NOM

supernode - démon supernode n2n

SYNTAXE

supernode <fichier de configuration>
supernode [OPTION]...

DESCRIPTION

N2N est un système VPN de pair à pair. Supernode est un registre d'introduction de nœuds, un canal de diffusion et un nœud de relais de paquets pour le système n2n. Au démarrage, supernode commence à écouter sur le port UDP spécifié pour les enregistrements de nœuds et d'autres paquets à router. Le supernode peut desservir un nombre quelconque de communautés et route les paquets uniquement entre les membres de la même communauté. Le supernode ne détient pas la clé de chiffrement de la communauté et ne peut donc pas écouter ou injecter de paquets dans la communauté.

Supernode peut gérer plusieurs communautés n2n simultanément. Le trafic ne traverse pas entre les communautés.

Toutes les journalisations vont vers la sortie standard.

Le fichier de configuration est similaire à la ligne de commande, avec une option par ligne. Les lignes commençant par un "#" sont ignorées. Un signe égal ('=') doit être utilisé entre la clé et la valeur. Exemple : -p=7777

OPTIONS POUR LA CONNEXION RÉSEAU SOUS-JACENTE

-p <port_local>, --local-port=<port_local>
écouter sur ce port UDP local fixe, par défaut 7654
-F <nom_fédération>
nom de la fédération du supernode, par défaut '*Federation' (voir aussi N2N_FEDERATION dans ENVIRONNEMENT)
-l <hôte:port>
adresse IP ou nom, et port du supernode connu
-m <adresse_mac>
adresse MAC fixe pour le supernode, par exemple
'-m 10:20:30:40:50:60', aléatoire sinon
-M
désactiver la protection des adresses MAC et IP usurpées pour toutes les communautés ne s'authentifiant pas par nom d'utilisateur et mot de passe
-V <chaîne_version>
modifier la chaîne de version du supernode qui est distribuée aux points de terminaison et affichée dans la sortie de leur port de gestion, jusqu'à 19 caractères

CONFIGURATION DU PÉRIPHÉRIQUE TAP ET DU RÉSEAU SUPERPOSÉ

-c <chemin>, --communities=<chemin>
fichier contenant les communautés autorisées et les détails d'authentification par utilisateur/mot de passe (Voir la section FICHIER DES COMMUNAUTÉS AUTORISÉES)
-a <réseau-réseau/n>, --autoip=<réseau-réseau/n>
plage de sous-réseau pour le service d'adresses IP automatiques,
par exemple '-a 192.168.0.0-192.168.255.0/24',
par défaut '10.128.255.0-10.255.255.0/24'

OPTIONS LOCALES

-f, --foreground
désactiver le mode démon (UNIX) et exécuter en premier plan.
-t <port>, --mgmt-port=<port>
port UDP de gestion, pour plusieurs supernodes sur une machine, par défaut 5645
--management-password <mot_de_passe>
définit le mot de passe pour l'accès à l'API JSON sur le port de gestion, par défaut 'n2n'. Le mot de passe doit être fourni pour un accès pertinent à l'API JSON sur le port de gestion.
-v, --verbose
utiliser une journalisation détaillée
-u <UID>
identifiant utilisateur numérique à utiliser lorsque les privilèges sont abandonnés
-g <GID>
identifiant groupe numérique à utiliser lorsque les privilèges sont abandonnés
-h
affiche une référence rapide incluant toutes les options disponibles
--help
affiche la description détaillée des paramètres

FICHIER DES COMMUNAUTÉS AUTORISÉES

Ce fichier est un fichier texte brut. Les commentaires sont introduits par un dièse au début de la ligne. Une ligne qui commence par un astérisque est une définition d'authentification utilisateur et ajoute un utilisateur autorisé à la communauté définie le plus récemment. Les communautés autorisées peuvent être spécifiées avec une expression régulière.

Exemple de fichier de communauté :

# Liste des communautés autorisées
mynetwork
netleo
* logan nHWum+r42k1qDXdIeH-WFKeylK5UyLStRzxofRNAgpG
* sister HwHpPrdMft+38tFDDiunUds6927t0+zhCMMkQdJafcC

Plus de détails sur la création du fichier des communautés autorisées se trouvent dans la documentation Communities.md et Authentication.md incluse avec ce paquet.

ENVIRONNEMENT

N2N_FEDERATION
définit le nom de la fédération afin qu'il ne soit pas visible sur la ligne de commande

EXEMPLES

supernode -p 7654 -v
Lance supernode en écoutant sur le port UDP 7654 avec une sortie détaillée.
echo | nc -w1 -u 127.0.0.1 5645
Affiche l'état de gestion d'un supernode en cours d'exécution.

REDÉMARRAGE

Lorsque supernode redémarre, il perd toutes les informations d'enregistrement des nœuds de bord associés. Il peut s'écouler jusqu'à cinq minutes pour que les nœuds de bord se réenregistrent et que le flux de trafic normal reprenne.

STATUT DE SORTIE

supernode est un démon et toute sortie est une erreur

NOM

supernode - un démon qui gère les proxys supernode.

SYNTAXE

supernode [OPTIONS]...

DESCRIPTION

supernode est un démon qui gère les proxys supernode.

OPTIONS

-h, --help
Afficher un message d'aide et quitter.
-v, --version
Afficher les informations de version et quitter.
-c, --config fichier
Spécifier un fichier de configuration.
-d, --daemon
Exécuter en tant que démon.
-p, --pidfile fichier
Spécifier un fichier PID.
-l, --logfile fichier
Spécifier un fichier journal.

EXEMPLES

supernode -d -c /etc/supernode.conf

Exécute supernode en tant que démon avec le fichier de configuration /etc/supernode.conf.

REDÉMARRAGE

Pour redémarrer supernode, vous pouvez envoyer un signal SIGHUP au processus.

kill -HUP $(cat /var/run/supernode.pid)

STATUT DE SORTIE

0 si succès, 1 si échec.

AUTEUR

Écrit par supernode.
