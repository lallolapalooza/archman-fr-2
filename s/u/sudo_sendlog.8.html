SUDO_SENDLOG(8) Manuel de l'administrateur système SUDO_SENDLOG(8)

NOM

sudo_sendlog — envoie le journal E/S de sudo à un serveur de journalisation

SYNTAXE

sudo_sendlog [-AnV] [-b ca_bundle] [-c cert_file] [-h hôte] [-i iolog-id] [-k key_file] [-p port] [-r point-reprise] [-R raison-refus] [-s point-arret] [-t nombre] chemin

DESCRIPTION

sudo_sendlog peut être utilisé pour envoyer le journal E/S sudoers existant à l'emplacement indiqué par chemin à un serveur de journalisation distant tel que sudo_logsrvd(8) pour un stockage centralisé.

Les options sont les suivantes :

-A, --accept-only
N'envoie que l'événement d'acceptation, pas les E/S associées au journal. Ceci peut être utilisé pour tester la journalisation des événements d'acceptation sans E/S associées.
-b, --ca-bundle
Le chemin vers un fichier de bundle d'autorité de certification, au format PEM, à utiliser à la place de la base de données d'autorités de certification par défaut du système lors de l'authentification du serveur de journalisation. Par défaut, utilise la base de données d'autorités de certification par défaut du système.
-c, --cert
Le chemin vers le fichier de certificat du client au format PEM. Ce paramètre est requis lorsque la connexion au serveur de journalisation distant est sécurisée avec TLS.
--help
Affiche un court message d'aide sur la sortie standard et quitte.
-h, --host
Se connecte à l'hôte spécifié au lieu de localhost.
-i, --iolog-id
Utilise l'iolog-id spécifié lors de la reprise d'un transfert de journal. L'iolog-id est rapporté par le serveur lors de la création du journal d'E/S distant. Cette option ne peut être utilisée qu'en conjonction avec l'option -r.
-k, --key
Le chemin vers le fichier de clé privée du client au format PEM. Ce paramètre est requis lorsque la connexion au serveur de journalisation distant est sécurisée avec TLS.
-n, --no-verify
Si spécifié, le certificat du serveur ne sera pas vérifié pendant la négociation TLS. Par défaut, sudo_sendlog vérifie que le certificat du serveur est valide et qu'il contient le nom d'hôte ou l'adresse IP du serveur. Ce paramètre n'est pris en charge que lorsque la connexion au serveur de journalisation distant est sécurisée avec TLS.
-p, --port
Utilise le port réseau spécifié lors de la connexion au serveur de journalisation au lieu du port par défaut, le port 30344.
-r, --restart
Reprend une connexion interrompue au serveur de journalisation. Le point-reprise spécifié est utilisé pour indiquer au serveur le point dans le temps auquel continuer le journal. Le point-reprise est spécifié sous la forme « secondes,nanosecondes » et est généralement le dernier point de validation reçu du serveur. L'option -i doit également être spécifiée lors de la reprise d'un transfert.
-R, --reject
Envoie un événement de refus pour la commande en utilisant la raison-refus spécifiée, même si elle a été réellement acceptée localement. Ceci peut être utilisé pour tester la journalisation des événements de refus ; aucune E/S ne sera envoyée.
-s, --stop-after
Arrête l'envoi des enregistrements de journal et ferme la connexion lorsque le point-arret est atteint. Ceci peut être utilisé à des fins de test pour envoyer un journal d'E/S partiel au serveur. Les journaux partiels peuvent être repris à l'aide de l'option -r. Le point-arret est un temps écoulé spécifié sous la forme « secondes,nanosecondes ».
-t, --test
Ouvre nombre connexions simultanées au serveur de journalisation et envoie le fichier journal d'E/S spécifié sur chacune d'elles. Cette option est utile pour les tests de performance.
-V, --version
Affiche la version de sudo_sendlog et quitte.

DÉBOGAGE DE SENDLOG

sudo_sendlog prend en charge un framework de débogage flexible qui est configuré via des lignes Debug dans le fichier sudo.conf(5).

Pour plus d'informations sur la configuration de sudo.conf(5), référez-vous à son manuel.

BOGUES

Si vous pensez avoir trouvé un bogue dans sudo_sendlog, vous pouvez soit signaler un bogue dans la base de données des bogues de sudo, https://bugzilla.sudo.ws/, soit ouvrir un ticket sur https://github.com/sudo-project/sudo/issues. Si vous préférez utiliser l'e-mail, les messages peuvent être envoyés à la liste de diffusion sudo-workers, https://www.sudo.ws/mailman/listinfo/sudo-workers (public) ou <sudo@sudo.ws> (privé).

Veuillez ne pas signaler les vulnérabilités de sécurité via les problèmes publics de GitHub, Bugzilla ou les listes de diffusion. Signalez-les plutôt par e-mail à <Todd.Miller@sudo.ws>. Vous pouvez chiffrer votre message avec PGP si vous le souhaitez, en utilisant la clé trouvée à https://www.sudo.ws/dist/PGPKEYS.
