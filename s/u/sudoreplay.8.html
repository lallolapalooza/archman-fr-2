SUDOREPLAY(8) Manuel de l'administrateur système SUDOREPLAY(8)

NOM

sudoreplay — rejouer les logs de session sudo

SYNTAXE

sudoreplay [-FhnRS] [-d rép] [-f filtre] [-m num] [-s num] ID[@décalage]

sudoreplay [-h] [-d rép] -l [expression de recherche]

DESCRIPTION

sudoreplay rejoue ou liste les logs de sortie créés par sudo. Lors du rejeu, sudoreplay peut rejouer la session en temps réel, ou la vitesse de lecture peut être ajustée (plus rapide ou plus lente) en fonction des options de la ligne de commande.

L'ID doit être soit une séquence de six caractères alphanumériques (chiffres et lettres majuscules), par exemple « 0100A5 », soit un nom de chemin. L'ID peut inclure un suffixe optionnel @décalage qui peut être utilisé pour commencer le rejeu à un décalage temporel spécifique. Le @décalage est spécifié comme un nombre en secondes depuis le début de la session avec une fraction décimale optionnelle.

Les noms de chemins peuvent être relatifs au répertoire des logs d'E/S /var/log/sudo-io (sauf s'il est remplacé par l'option -d) ou être des chemins complets, commençant par un caractère « / ». Lorsqu'une commande est exécutée via sudo avec log_output activé dans le fichier sudoers, une chaîne « TSID=ID » est journalisée via syslog(3) ou dans le fichier log de sudo. L'ID peut également être déterminé en utilisant le mode liste de sudoreplay.

En mode liste, sudoreplay peut être utilisé pour trouver l'ID d'une session basé sur plusieurs critères tels que l'utilisateur, le tty, ou la commande exécutée.

En mode rejeu, si les entrées/sorties standard sont connectées à un terminal et que l'option -n n'est pas spécifiée, sudoreplay fonctionnera de manière interactive. En mode interactif, sudoreplay tentera d'ajuster la taille du terminal pour correspondre à celle de la session et écrira directement sur le terminal (tous les terminaux ne supportent pas cela). De plus, il interrogera le clavier et agira sur les touches suivantes :

« \n » ou « \r »
Passe à l'événement de rejeu suivant ; utile pour les longues pauses.
« ‘’ » (espace)
Met la sortie en pause ; appuyez sur n'importe quelle touche pour reprendre.
« < »
Réduit la vitesse de lecture de moitié.
« > »
Double la vitesse de lecture.

La session peut être interrompue via Ctrl+C. Lorsque la session est terminée, le terminal est restauré à sa taille d'origine s'il a été modifié pendant la lecture.

Les options sont les suivantes :

-d rép, --directory=rép
Stocke les logs de session dans rép au lieu du répertoire par défaut, /var/log/sudo-io.
-f filtre, --filter=filtre
Sélectionne les types d'E/S à afficher. Par défaut, sudoreplay affichera la sortie standard, l'erreur standard et la sortie tty de la commande. Le filtre est une liste séparée par des virgules, composée d'un ou plusieurs des éléments suivants : stdin, stdout, stderr, ttyin, et ttyout.
-F, --follow
Active le mode « suivre » (follow mode). Lors du rejeu d'une session, sudoreplay ignorera la fin de fichier et continuera le rejeu jusqu'à ce que le log soit complet. Ceci peut être utilisé pour rejouer une session en cours, similaire à « tail -f ». Un fichier log d'E/S est considéré comme complet lorsque les bits d'écriture ont été désactivés sur le fichier de temporisation de la session. Les versions de sudo antérieures à 1.9.1 ne désactivent pas les bits d'écriture à la fin.
-h, --help
Affiche un court message d'aide sur la sortie standard et quitte.
-l, --list [expression de recherche]
Active le mode « liste » (list mode). Dans ce mode, sudoreplay listera les sessions disponibles dans un format similaire au format du fichier log de sudo, trié par nom de fichier (ou numéro de séquence). Tous les caractères de contrôle présents dans les données du log sont formatés en octal avec un caractère « # » en préfixe. Par exemple, une tabulation horizontale est affichée comme « #011 » et un retour chariot intégré est affiché comme « #015 ». Les espaces dans le nom de commande et les arguments sont également formatés en octal.

Si une expression de recherche est spécifiée, elle sera utilisée pour restreindre les ID affichés. Une expression est composée des prédicats suivants :

command modèle
Vrai si la commande exécutée correspond à l'expression régulière étendue POSIX modèle.
cwd répertoire
Vrai si la commande a été exécutée avec le répertoire de travail courant spécifié.
fromdate date
Vrai si la commande a été exécutée à partir de la date spécifiée. Voir Format de date et heure pour une description des formats de date et heure pris en charge.
group groupe_runas
Vrai si la commande a été exécutée avec le groupe_runas spécifié. Sauf si un groupe_runas a été explicitement spécifié lors de l'exécution de sudo, ce champ sera vide dans le log.
host nom_hôte
Vrai si la commande a été exécutée sur le nom_hôte spécifié.
runas utilisateur_runas
Vrai si la commande a été exécutée en tant que utilisateur_runas spécifié. Par défaut, sudo exécute les commandes en tant que root utilisateur.
todate date
Vrai si la commande a été exécutée au plus tard à la date spécifiée. Voir Format de date et heure pour une description des formats de date et heure pris en charge.
tty nom_tty
Vrai si la commande a été exécutée sur le périphérique terminal spécifié. Le nom_tty doit être spécifié sans le préfixe /dev/, par exemple tty01 au lieu de /dev/tty01.
user nom_utilisateur
Vrai si l'ID correspond à une commande exécutée par nom_utilisateur.

Les prédicats peuvent être abrégés en la plus courte chaîne unique.

Les prédicats peuvent être combinés en utilisant les opérateurs and, or, et ! ainsi que les parenthèses.

-m num, --message-tag=num
Définit la taille du tampon de sortie du terminal à num octets. Le comportement par défaut est d'utiliser la taille du terminal. Utiliser une valeur de 0 désactive la sortie du terminal et ne génère que le contenu de la sortie standard et de l'erreur standard.
-n, --no-pause
Ne pas mettre en pause avant chaque événement. Utile pour le rejeu non interactif.
-R, --raw
Rejouer la sortie brute telle qu'elle a été enregistrée. Ceci désactive le traitement spécial pour les caractères de contrôle et les caractères d'échappement ANSI.
-S, --skip-comment
Ignorer les commandes précédées d'un symbole dièse (#) dans le log. Ceci est utile pour ignorer les commentaires inclus dans les logs générés par certains programmes.
-s num, --speed=num
Ajuste la vitesse de lecture du rejeu à num. Une valeur de 1.0 correspond à la vitesse normale. Les valeurs supérieures à 1.0 accélèrent la lecture, tandis que les valeurs inférieures à 1.0 la ralentissent. La valeur par défaut est de 1.0.

DATE ET HEURE FORMAT

Le format de date et d'heure est :YYYY[MM[DD[HH[MM[SS]]]]]

Les champs peuvent être omis de droite à gauche. Les dates peuvent également être spécifiées en utilisant le format MM/DD/YYYY.

Les horodatages peuvent être relatifs au moment présent sous la forme +Ns, +Nm, +Nh, +Nd, +Nw pour les secondes, minutes, heures, jours, ou semaines respectivement.

EXEMPLES

Rejouer la session avec l'ID 0100A5 à vitesse normale :

$ sudoreplay 0100A5

Rejouer la session avec l'ID 0100A5 à deux fois la vitesse normale :

$ sudoreplay -s 2 0100A5

Rejouer la session de l'utilisateur root, ID 0100A5, en temps réel sans pause :

$ sudoreplay -n 0100A5

Rejouer le contenu de la session de l'utilisateur `bob` exécutée le 15 septembre 2008 à partir de 14h00 :

$ sudoreplay -l user bob fromdate 200809151400

Rejouer le contenu de la session exécutée sur le tty `pts/0` :

$ sudoreplay -l tty pts/0

Rejouer uniquement la sortie standard et l'erreur standard de la session ID `0100A5` :

$ sudoreplay -f stdout,stderr 0100A5

Rejouer la session dont le nom de fichier est `foo.log` :

$ sudoreplay foo.log

VOIR AUSSI

sudo(8), sudoers(5)

NAME

sudoreplay

visualiser les sessions sudo

SYNOPSIS

sudoreplay

-a | --append [session_id]
Joindre la sortie à une session existante.
-b | --background
Exécuter en arrière-plan et détacher le terminal.
-c | --check
Vérifier l'intégrité d'une session enregistrée.
-d | --delete [session_id]
Supprimer une session enregistrée.
-e | --edit [session_id]
Modifier une session enregistrée.
-f | --follow
Suivre les événements en temps réel.
-h | --help
Afficher les messages d'aide et quitter.
-i | --interactive
Afficher l'invite utilisateur pour les sessions interactives.
-k | --kill [session_id]
Arrêter une session enregistrée.
-l | --list [[type] [operande]]
Lister les sessions enregistrées.
-m | --max-wait max_wait
Spécifier un délai maximum entre les frappes ou les sorties.
-n | --non-interactive
Ne pas demander d'entrée utilisateur ou tenter de redimensionner le terminal.
-q | --quiet
Désactiver tous les messages de sortie.
-R | --no-resize
Ne pas tenter de redimensionner le terminal.
-S | --suspend-wait
Attendre pendant que la commande était suspendue.
-s | --speed speed_factor
Ajuster la vitesse de lecture de la session.
-V | --version
Afficher le numéro de version et quitter.
session_id ...
Les identifiants des sessions à visualiser.

DESCRIPTION

sudoreplay est un utilitaire pour visualiser les sessions enregistrées par sudo(8). Il peut lire les sessions à partir de fichiers journaux ou directement depuis l'entrée standard. Les sessions sont généralement enregistrées dans des fichiers journaux sous forme de séquences de frappes et de sorties de terminal.

L'option -l, --list permet de rechercher les sessions enregistrées selon différents critères. Les opérandes de type type peuvent inclure user, tty, command, etc. Les opérateurs logiques comme and, or, not peuvent être utilisés pour combiner les critères de recherche. Les parenthèses doivent généralement être échappées du shell. L'opérateur and est facultatif ; les prédicats adjacents ont un and implicite sauf s'ils sont séparés par un or.

-m, --max-wait max_wait
Spécifie une limite supérieure au temps d'attente entre les frappes ou les sorties de données. Par défaut, sudoreplay reproduit fidèlement les délais entre les frappes ou les sorties du programme. Cependant, cela peut être fastidieux lorsque la session inclut de longues pauses. Lorsque l'option -m est spécifiée, sudoreplay limite ces pauses à au plus max_wait secondes. La valeur peut être spécifiée en nombre à virgule flottante, par exemple, 2.5. Une valeur de max_wait nulle ou négative éliminera entièrement les pauses.
-n, --non-interactive
Ne pas demander d'entrée utilisateur ou tenter de redimensionner le terminal. La session est écrite sur la sortie standard, pas directement sur le terminal de l'utilisateur.
-R, --no-resize
Ne pas tenter de redimensionner le terminal pour correspondre à la taille du terminal de la session.
-S, --suspend-wait
Attendre pendant que la commande était suspendue. Par défaut, sudoreplay ignore l'intervalle de temps entre la suspension de la commande et sa reprise. Si l'option -S est spécifiée, sudoreplay attendra.
-s, --speed speed_factor
Cette option permet à sudoreplay d'ajuster le nombre de secondes d'attente entre les frappes ou les sorties du programme. Cela peut être utilisé pour ralentir ou accélérer l'affichage. Par exemple, un speed_factor de 2 rendrait la sortie deux fois plus rapide, tandis qu'un speed_factor de .5 la ralentirait deux fois.
-V, --version
Afficher le numéro de version de sudoreplay et quitter.

Format de date et d'heure

L'heure et la date peuvent être spécifiées de plusieurs manières, les formats courants incluent :

HH:MM:SS am MM/JJ/AAAA fuseau_horaire
L'heure sur 24 heures peut être utilisée à la place de am/pm.
HH:MM:SS am Mois, Jour Année fuseau_horaire
L'heure sur 24 heures peut être utilisée à la place de am/pm, et les noms des mois et des jours de la semaine peuvent être abrégés. Les noms des mois et des jours de la semaine doivent être spécifiés en anglais.
AAAA-MM-JJ HH:MM:SS
Format horaire ISO
JJ Mois AAAA HH:MM:SS
Le nom du mois peut être abrégé.

L'heure ou la date peuvent être omises, le format am/pm et le fuseau horaire sont facultatifs. Si aucune date n'est spécifiée, le jour actuel est supposé ; si aucune heure n'est spécifiée, la première seconde du jour spécifié est utilisée. Les parties moins significatives de l'heure et de la date peuvent également être omises, auquel cas zéro est supposé.

Les spécifications de date et d'heure suivantes sont toutes valides :

now
L'heure et la date actuelles.
tomorrow
Exactement un jour à partir de maintenant.
yesterday
Il y a 24 heures.
2 hours ago
Il y a 2 heures.
next Friday
La première seconde du vendredi de la semaine prochaine (à venir). À ne pas confondre avec « ce vendredi » qui correspondrait au vendredi de la semaine en cours.
last week
L'heure actuelle mais il y a 7 jours. C'est équivalent à « il y a une semaine ».
a fortnight ago
L'heure actuelle mais il y a 14 jours.
10:01 am 9/17/2009
10h01, le 17 septembre 2009.
10:01 am
10h01 du jour actuel.
10
10h00 du jour actuel.
9/17/2009
00h00, le 17 septembre 2009.
10:01 am Sep 17, 2009
10h01, le 17 septembre 2009.

Les spécifications de temps relatives ne fonctionnent pas toujours comme prévu. Par exemple, le qualificateur « next » est destiné à être utilisé en conjonction avec un jour tel que « next Monday » (lundi prochain). Lorsqu'il est utilisé avec des unités de semaines, de mois, d'années, etc., le résultat sera supérieur à ce qui est attendu. Par exemple, « next week » (semaine prochaine) résultera en une heure exactement deux semaines à partir de maintenant, ce qui n'est probablement pas ce qui était prévu. Cela sera corrigé dans une future version de sudoreplay.

Débogage de Sudoreplay

sudoreplay versions 1.8.4 et ultérieures prend en charge un cadre de débogage flexible qui est configuré via des lignes Debug dans le fichier sudo.conf(5).

Pour plus d'informations sur la configuration de sudo.conf(5), référez-vous à son manuel.

FICHIERS

/etc/sudo.conf
Configuration du cadre de débogage
/var/log/sudo-io
Le répertoire par défaut des journaux d'E/S.
/var/log/sudo-io/00/00/01/log
Exemple d'informations de journal de session.
/var/log/sudo-io/00/00/01/log.json
Exemple d'informations de journal de session (format JSON).
/var/log/sudo-io/00/00/01/stdin
Exemple de fichier journal d'entrée standard de la session.
/var/log/sudo-io/00/00/01/stdout
Exemple de fichier journal de sortie standard de la session.
/var/log/sudo-io/00/00/01/stderr
Exemple de fichier journal d'erreur standard de la session.
/var/log/sudo-io/00/00/01/ttyin
Exemple de fichier d'entrée tty de la session.
/var/log/sudo-io/00/00/01/ttyout
Exemple de fichier de sortie tty de la session.
/var/log/sudo-io/00/00/01/timing
Exemple de fichier de synchronisation de session.

Les fichiers stdin, stdout et stderr seront vides sauf si sudo a été utilisé dans le cadre d'un pipeline pour une commande particulière.

EXEMPLES

Lister les sessions exécutées par l'utilisateur millert :

# sudoreplay -l user millert

Lister les sessions exécutées par l'utilisateur bob avec une commande contenant la chaîne vi :

# sudoreplay -l user bob command vi

Lister les sessions exécutées par l'utilisateur jeff qui correspondent à une expression régulière :

# sudoreplay -l user jeff command '/bin/[a-z]*sh'

Lister les sessions exécutées par jeff ou bob sur la console :

# sudoreplay -l ( user jeff or user bob ) tty console
