NOM

subgid - la configuration des identifiants de groupe subordonnés

DESCRIPTION

Subgid autorise un identifiant de groupe à mapper des plages d'identifiants de groupe de son espace de noms vers les espaces de noms enfants.

La délégation des gids subordonnés peut être configurée via le champ subid dans le fichier /etc/nsswitch.conf. Une seule valeur peut être définie comme source de délégation. Définir ce champ sur files configure la délégation des gids à /etc/subgid. Toute autre valeur traite la délégation comme un plugin suivant avec un nom de la forme libsubid_$value.so. Si la valeur ou le plugin est manquant, alors la délégation de gid subordonné reviendra à files.

Notez que newusers, useradd, et usermod créeront seulement des entrées dans /etc/subgid si la délégation subid est gérée via des fichiers subid.

DÉLÉGATION LOCALE DES GROUPES SUBORDONNÉS

Chaque ligne de /etc/subgid contient un nom d'utilisateur et une plage d'identifiants de groupe subordonnés que cet utilisateur est autorisé à utiliser. Ceci est spécifié avec trois champs délimités par des deux-points (“:”). Ces champs sont :

•nom de connexion ou UID
•identifiant de groupe subordonné numérique
•compte d'identifiant de groupe subordonné numérique

Ce fichier spécifie les identifiants de groupe que les utilisateurs ordinaires peuvent utiliser, avec la commande newgidmap, pour configurer le mappage de gid dans un espace de noms utilisateur.

Plusieurs plages peuvent être spécifiées par utilisateur.

Lorsque un grand nombre d'entrées (10000-100000 ou plus) est défini dans /etc/subgid, une pénalité de performance d'analyse deviendra notable. Dans ce cas, il est recommandé d'utiliser des UIDs au lieu de noms de connexion. Les benchmarks ont montré des accélérations allant jusqu'à 20x.

FICHIERS

/etc/subgid

Identifiants de groupe subordonnés par utilisateur.

/etc/subgid-

Fichier de sauvegarde pour /etc/subgid.
