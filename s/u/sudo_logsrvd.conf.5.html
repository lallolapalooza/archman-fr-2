Paquet: sudo

SUDO_LOGSRVD.CONF(5) Formats de fichiers SUDO_LOGSRVD.CONF(5)

NOM

sudo_logsrvd.conf — configuration de sudo_logsrvd

DESCRIPTION

Le fichier sudo_logsrvd.conf est utilisé pour configurer le serveur de logs sudo_logsrvd. Il utilise un format de type INI composé de sections entre crochets et de paires « clé = valeur » spécifiques à chaque section sous le nom de la section. Selon la clé, les valeurs peuvent être des entiers, des booléens ou des chaînes. Les noms de section et de clé ne sont pas sensibles à la casse, mais les valeurs le sont.

Le signe dièse (« # ») est utilisé pour indiquer un commentaire. Le caractère de commentaire et tout texte après celui-ci, jusqu'à la fin de la ligne, sont ignorés. Les lignes commençant par un point-virgule (« ; ») sont également ignorées.

Les lignes longues peuvent être poursuivies par une barre oblique inverse (« \ ») comme dernier caractère de la ligne. L'espace blanc en début de ligne est supprimé, même lorsque le caractère de continuation est utilisé.

La section EXEMPLES contient une copie du fichier sudo_logsrvd.conf par défaut.

Les sections de configuration suivantes sont reconnues :

  • server
  • relay
  • iolog
  • eventlog
  • syslog
  • logfile

Chaque section est décrite en détail ci-dessous.

server

La section server configure l'adresse et le port sur lesquels le serveur écoutera. Les clés suivantes sont reconnues :

listen_address = hôte[:port][(tls)]
Le nom d'hôte ou l'adresse IP, le port optionnel sur lequel écouter et un indicateur Transport Layer Security (TLS) optionnel entre parenthèses.

L'hôte peut être un nom d'hôte, une adresse IPv4, une adresse IPv6 entre crochets ou l'entrée générique « * ». Un réglage d'hôte de « * » fera en sorte que sudo_logsrvd écoute sur toutes les interfaces réseau configurées.

Si l'indicateur tls est présent, sudo_logsrvd sécurisera la connexion avec TLS version 1.2 ou 1.3. Les versions de TLS antérieures à 1.2 ne sont pas prises en charge. Voir sudo_logsrvd(8) pour plus de détails sur la génération des clés et certificats TLS.

Si un port est spécifié, il peut s'agir soit d'un numéro de port, soit d'un nom de service connu tel que défini par la base de données des noms de services du système. Si aucun port n'est spécifié, le port 30343 sera utilisé pour les connexions en clair et le port 30344 sera utilisé pour les connexions TLS.

La valeur par défaut est :

listen_address = *:30343
listen_address = *:30344(tls)
ce qui écoutera sur toutes les interfaces réseau configurées pour les connexions en clair et TLS. Plusieurs lignes listen_address peuvent être spécifiées pour écouter sur plus d'un port ou d'une interface.
server_log = chaîne
Où enregistrer les messages d'avertissement et d'erreur du serveur. Les valeurs prises en charge sont none, stderr, syslog, ou un chemin d'accès commençant par le caractère « / ». Une valeur de stderr n'est effective que lorsqu'elle est utilisée conjointement avec l'option -n. La valeur par défaut est syslog.
pid_file = chemin
Le chemin vers le fichier contenant l'identifiant de processus de sudo_logsrvd en cours d'exécution. S'il est défini sur une valeur vide, ou si sudo_logsrvd est exécuté avec l'option -n, aucun fichier pid_file ne sera créé. Si pid_file fait référence à un lien symbolique, il sera ignoré. La valeur par défaut est /run/sudo/sudo_logsrvd.pid.
tcp_keepalive = booléen
Si vrai, sudo_logsrvd activera l'option de socket TCP keepalive sur la connexion client. Cela permet la transmission périodique de messages keepalive au client. Si le client ne répond pas à un message à temps, la connexion sera fermée. Par défaut, la valeur est true.
timeout = nombre
La durée, en secondes, pendant laquelle sudo_logsrvd attendra une réponse du client. Une valeur de 0 désactivera le délai d'attente. La valeur par défaut est 30.
tls_cacert = chemin
Le chemin vers un fichier de bundle d'autorités de certification, au format PEM, à utiliser à la place de la base de données des autorités de certification par défaut du système lors de l'authentification des clients. Par défaut, utilise /etc/ssl/sudo/cacert.pem s'il existe, sinon la base de données des autorités de certification par défaut du système est utilisée.
tls_cert = chemin
Le chemin vers le fichier de certificat du serveur, au format PEM. La valeur par défaut est /etc/ssl/sudo/certs/logsrvd_cert.pem.
tls_checkpeer = bool
Si vrai, les certificats clients seront validés par sudo_logsrvd ; les clients sans certificat valide ne pourront pas se connecter. Si faux, aucune validation des certificats clients ne sera effectuée. S'il est vrai et que les certificats clients sont créés à l'aide d'une autorité de certification privée, le réglage tls_cacert doit être défini sur un bundle d'AC contenant le certificat d'AC utilisé pour générer le certificat client. La valeur par défaut est false.
tls_ciphers_v12 = chaîne
Une liste de chiffrements à utiliser pour les connexions sécurisées par TLS version 1.2 uniquement, séparés par deux-points (« : »). Voir la section FORMAT DE LA LISTE DES CHIFFREMENTS de openssl-ciphers(1) pour les détails complets. La valeur par défaut est « HIGH:!aNULL », qui se compose de suites de chiffrement de cryptage avec des clés de plus de 128 bits, et de certaines suites de chiffrement avec des clés de 128 bits. Les suites de chiffrement qui n'offrent aucune authentification sont exclues.
tls_ciphers_v13 = chaîne
Une liste de chiffrements à utiliser pour les connexions sécurisées par TLS version 1.3 uniquement, séparés par deux-points (« : »). Les suites de chiffrement prises en charge dépendent de la version d'OpenSSL utilisée, mais devraient inclure les suivantes :
TLS_AES_128_GCM_SHA256
 
TLS_AES_256_GCM_SHA384
 
TLS_CHACHA20_POLY1305_SHA256
 
TLS_AES_128_CCM_SHA256
 
TLS_AES_128_CCM_8_SHA256
 

La suite de chiffrement par défaut est « TLS_AES_256_GCM_SHA384 ».

tls_dhparams = chemin
Le chemin vers un fichier contenant des paramètres Diffie-Hellman personnalisés au format PEM. Ce fichier peut être créé avec la commande suivante : 
openssl dhparam -out /etc/sudo_logsrvd_dhparams.pem 2048

Par défaut, sudo_logsrvd utilisera les paramètres par défaut d'OpenSSL pour la génération de clés Diffie-Hellman.

tls_key = chemin
Le chemin vers le fichier de clé privée du serveur, au format PEM. La valeur par défaut est /etc/ssl/sudo/private/logsrvd_key.pem.
tls_verify = bool
Si vrai, sudo_logsrvd vérifiera son propre certificat au démarrage ou lors de la modification de la configuration. Si faux, aucune vérification du certificat du serveur ne sera effectuée. Lors de l'utilisation de certificats auto-signés sans autorité de certification, ce réglage doit être défini sur faux. La valeur par défaut est true.

Les clés suivantes sont reconnues :

relay_dir = chemin
Le répertoire dans lequel les messages de journal sont temporairement stockés avant d'être envoyés à l'hôte relais. Les messages sont stockés dans le format de transmission spécifié par sudo_logsrv.proto(5). La valeur par défaut est /var/log/sudo_logsrvd.
relay_host = hôte[:port][(tls)]
Le nom d'hôte ou l'adresse IP de l'hôte relais, le port optionnel auquel se connecter et un indicateur optionnel de Transport Layer Security (TLS) entre parenthèses. La syntaxe est identique à celle de listen_address dans la section server, à une exception près : la syntaxe du joker ‘*’ n'est pas prise en charge.

Lorsque ce paramètre est activé, les messages du client sont transmis à l'un des hôtes relais spécifiés au lieu d'être stockés localement. L'hôte hôte peut exécuter une instance de sudo_logsrvd ou un autre serveur prenant en charge le protocole sudo_logsrv.proto(5).

Si plusieurs lignes relay_host sont spécifiées, le premier hôte relais disponible est utilisé.

retry_interval = nombre
Le nombre de secondes à attendre après une erreur de connexion avant de tenter à nouveau de transmettre un message à un hôte relais. La valeur par défaut est 30.
store_first = booléen
Si vrai, sudo_logsrvd stockera les journaux localement avant de les relayer. Une fois le journal complet, une connexion à l'hôte relais est ouverte et le journal est relayé. Si la connexion réseau est interrompue avant que le journal ne puisse être entièrement transféré, il sera retransmis ultérieurement. La valeur par défaut est de relayer les journaux en temps réel.
tcp_keepalive = booléen
Si vrai, sudo_logsrvd activera l'option de socket TCP keepalive sur la connexion relais. Cela permet la transmission périodique de messages keepalive au serveur relais. Si le relais ne répond pas à un message dans les délais impartis, la connexion sera fermée.
timeout = nombre
Le temps, en secondes, pendant lequel sudo_logsrvd attend une réponse du serveur relais après une connexion réussie. Une valeur de 0 désactive le délai d'attente. La valeur par défaut est 30.
tls_cacert = chemin
Le chemin vers un fichier de bundle d'autorité de certification, au format PEM, à utiliser à la place de la base de données des autorités de certification par défaut du système lors de l'authentification des clients. Par défaut, utilise la valeur spécifiée dans la section server, ou la base de données des autorités de certification par défaut du système si aucune valeur n'est définie.
tls_cert = chemin
Le chemin vers le fichier de certificat du serveur, au format PEM. Par défaut, utilise la valeur spécifiée dans la section server.
tls_checkpeer = bool
Si vrai, le certificat de l'hôte relais sera validé par sudo_logsrvd ; les connexions à un relais sans certificat valide échoueront. Si faux, aucune validation des certificats relais ne sera effectuée. S'il est vrai et que les certificats relais sont créés à l'aide d'une autorité de certification privée, le paramètre tls_cacert doit être défini sur un bundle CA contenant le certificat CA utilisé pour générer le certificat relais. Par défaut, utilise la valeur spécifiée dans la section server.

Une liste de chiffrements à utiliser uniquement pour les connexions sécurisées par TLS version 1.2, séparés par un deux-points ‘:’. Voir la section FORMAT DE LISTE DE CHIFFREMENTS dans openssl-ciphers(1) pour tous les détails. Par défaut, utilise la valeur spécifiée dans la section server.
tls_ciphers_v13 = chaîne
Une liste de chiffrements à utiliser uniquement pour les connexions sécurisées par TLS version 1.3, séparés par un deux-points ‘:’. Les suites de chiffrement prises en charge dépendent de la version d'OpenSSL utilisée, voir la section server pour plus d'informations. Par défaut, utilise la valeur spécifiée dans la section server.
tls_dhparams = chemin
Le chemin vers un fichier contenant des paramètres Diffie-Hellman personnalisés au format PEM. Par défaut, utilise la valeur spécifiée dans la section server.
tls_key = chemin
Le chemin vers le fichier de clé privée du serveur, au format PEM. Par défaut, utilise la valeur spécifiée dans la section server.
tls_verify = bool
Si vrai, le certificat du serveur utilisé pour le relais sera vérifié au démarrage. Si faux, aucune vérification du certificat serveur ne sera effectuée. Lors de l'utilisation de certificats auto-signés sans autorité de certification, ce paramètre doit être défini sur faux. Par défaut, utilise la valeur spécifiée dans la section server.

iolog

La section iolog configure les paramètres de journalisation d'E/S. Ces paramètres sont identiques à la configuration des E/S dans sudoers(5). Les clés suivantes sont reconnues :

iolog_compress = booléen
S'il est défini, les journaux d'E/S seront compressés à l'aide de zlib. L'activation de la compression peut rendre plus difficile la visualisation des journaux en temps réel pendant l'exécution du programme en raison de la mise en tampon. La valeur par défaut est false.
iolog_dir = chemin
Le répertoire de niveau supérieur à utiliser lors de la construction du nom de chemin pour le répertoire de journalisation des E/S. Le numéro de séquence de session, le cas échéant, est stocké dans le répertoire. La valeur par défaut est /var/log/sudo-io.

Les séquences d'échappement suivantes utilisant le signe pour cent (‘%’) sont prises en charge :

%{seq}
développé en un numéro de séquence en base 36 qui augmente monotoniquement, tel que 0100A5, où deux chiffres sont utilisés pour former un nouveau répertoire, par exemple, 01/00/A5
%{user}
développé en le nom de connexion de l'utilisateur appelant
%{group}
développé en le nom du groupe réel de l'utilisateur appelant
%{runas_user}
développé en le nom de connexion de l'utilisateur sous lequel la commande sera exécutée (par exemple, root)
%{runas_group}
développé en le nom du groupe de l'utilisateur sous lequel la commande sera exécutée (par exemple, wheel)
%{hostname}
développé en le nom d'hôte local sans le nom de domaine
%{command}
développé en le nom de base de la commande exécutée

De plus, toutes les séquences d'échappement prises en charge par la fonction strftime(3) du système seront développées.

Pour inclure un caractère ‘%’ littéral, la chaîne ‘%%’ doit être utilisée.

iolog_file = chemin
Le nom du chemin, relatif à iolog_dir, dans lequel stocker les journaux d'E/S. Il est possible que iolog_file contienne des composants de répertoire. La valeur par défaut est “%{seq}”.

Voir le paramètre iolog_dir ci-dessus pour une liste des séquences d'échappement prises en charge avec le signe pour cent (‘%’).

En plus des séquences d'échappement, les noms de chemin se terminant par six ou plusieurs X seront remplacés par une combinaison unique de chiffres et de lettres, similaire à la fonction mktemp(3).

Si le chemin créé en concaténant iolog_dir et iolog_file existe déjà, le fichier de journal d'E/S existant sera tronqué et écrasé, sauf si iolog_file se termine par six ou plusieurs X.

iolog_flush = booléen
S'il est défini, les données du journal d'E/S sont vidées sur le disque après chaque écriture au lieu d'être mises en mémoire tampon. Cela permet de visualiser les journaux en temps réel pendant l'exécution du programme, mais peut réduire considérablement l'efficacité de la compression des journaux d'E/S. Les journaux d'E/S sont toujours vidés avant d'envoyer un point de validation au client, quelle que soit la valeur de ce paramètre. La valeur par défaut est true.
iolog_group = nom
Le nom du groupe à rechercher lors de la définition de l'ID de groupe sur les nouveaux fichiers et répertoires de journaux d'E/S. Si iolog_group n'est pas défini, l'ID de groupe principal de l'utilisateur spécifié par iolog_user est utilisé. Si ni iolog_group ni iolog_user ne sont définis, les fichiers et répertoires de journaux d'E/S sont créés avec l'ID de groupe 0.
iolog_mode = mode
Le mode de fichier à utiliser lors de la création de fichiers de journaux d'E/S. Les bits de mode pour les permissions de lecture et d'écriture pour le propriétaire, le groupe ou les autres sont respectés, tout le reste est ignoré. Les permissions du fichier incluront toujours les bits de lecture et d'écriture du propriétaire, même s'ils ne sont pas présents dans le mode spécifié. Lors de la création de répertoires de journaux d'E/S, les bits de recherche (exécution) sont ajoutés pour correspondre aux bits de lecture et d'écriture spécifiés par iolog_mode. La valeur par défaut est 0600.
iolog_user = nom
Le nom d'utilisateur à rechercher lors de la définition du propriétaire des nouveaux fichiers et répertoires de journaux d'E/S. Si iolog_group est défini, il sera utilisé à la place de l'ID de groupe principal de l'utilisateur. Par défaut, les fichiers et répertoires de journaux d'E/S sont créés avec l'ID utilisateur et groupe 0.
log_passwords = bool
La plupart des programmes qui demandent le mot de passe d'un utilisateur désactivent l'écho avant de lire le mot de passe pour éviter d'afficher le mot de passe en clair à l'écran. Cependant, si l'entrée du terminal est enregistrée, le mot de passe sera toujours présent dans le journal d'E/S. Si log_passwords est défini sur false, sudo_logsrvd tentera d'empêcher l'enregistrement des mots de passe. Il le fait en utilisant les expressions régulières dans passprompt_regex pour faire correspondre une invite de mot de passe dans le tampon de sortie du terminal. Lorsqu'une correspondance est trouvée, les caractères d'entrée dans le journal d'E/S seront remplacés par ‘*’ jusqu'à ce qu'une ligne de fin ou un retour chariot soit trouvé dans le ter{ "content": "input ou une nouvelle sortie de terminal\n le tampon est reçu. Si, toutefois, un programme affiche des caractères au fur et à mesure que l'utilisateur\n tape (par exemple sudo lorsque le\n pwfeedback\n est défini), seul le premier caractère du mot de passe sera remplacé\n dans le journal des E/S. La valeur par défaut est true.
\n
maxseq = nombre
\n
\n Le numéro de séquence maximum qui sera substitué par le\n échappement “%{seq}” dans le fichier journal des E/S (voir la\n description de iolog_dir ci-dessus pour plus d'informations). Alors que\n la valeur substituée pour “%{seq}” est en base 36,\n maxseq lui-même\n doit être exprimé en décimal. Les valeurs supérieures à 2176782336 (ce qui\n correspond au numéro de séquence en base 36 “ZZZZZZ”) seront\n tronquées silencieusement à 2176782336. La valeur par défaut est\n 2176782336.

\n
Une ou plusieurs expressions régulières étendues POSIX utilisées pour faire correspondre les invites de mot de passe\n dans la sortie du terminal lorsque log_passwords est\n désactivé. Comme extension, si l'expression régulière commence par\n “(?i)”, elle sera mise en correspondance de manière insensible à la casse.\n Plusieurs paramètres passprompt_regex peuvent être spécifiés.\n Chaque expression régulière est limitée à 1024 caractères. La valeur par défaut est\n “[Pp]assword[: ]*”.

La section eventlog configure comment (et si)\n les événements de politique de sécurité sont enregistrés.

\n
\n
log_type = chaîne
\n
\n Où enregistrer les événements d'acceptation, de rejet et d'alerte signalés par la politique.\n Les valeurs prises en charge sont syslog, logfile et\n none. La valeur par défaut est\n syslog.
\n
log_exit = booléen
\n
\n Si vrai, sudo_logsrvd enregistrera un événement lorsqu'une\n commande se termine ou est terminée par un signal. Par défaut :\n false.
\n
log_format = chaîne
\n
\n Le format du journal d'événements. Les formats de journal pris en charge sont :\n
\n
json
\n
\n Actuellement, c'est un alias pour json_pretty. Dans une\n future version de sudo_logsrvd,\n json sera\n équivalent à json_compact. Les entrées de journal JSON contiennent\n le contenu complet des messages d'acceptation, de rejet, de sortie et d'alerte.
\n
json_compact
\n
\n Enregistrer les événements au format JSON « compact » (minifié).\n Chaque événement est écrit sous forme d'objet JSON distinct sur une seule ligne sans\n espaces blancs superflus. En raison des limitations du protocole, les événements JSON\n envoyés via syslog peuvent être tronqués.
\n
json_pretty
\n
\n Enregistrer les événements au format JSON « pretty ».\n Lors de l'enregistrement dans un fichier, le fichier entier est traité comme un seul objet JSON\n composé de plusieurs événements, chaque événement s'étendant sur plusieurs lignes.\n Lors de l'enregistrement via syslog, il n'y a pas de différence entre les\n formats json_pretty et json_compact.
\n
sudo
\n
\n Enregistrer les événements au format de journal traditionnel de style sudo.\n Voir la section JOURNAL DES ÉVÉNEMENTS\n dans sudoers(5) pour\n plus de détails.
\n
\n

La valeur par défaut est\n sudo.

syslog

\n

La section syslog configure comment les événements sont\n enregistrés via syslog(3).

\n
\n
facility = chaîne
\n
\n Installation syslog si syslog est utilisé pour la journalisation. Valeur par défaut :\n auth.\n

Les installations syslog suivantes sont prises en charge :authpriv (si\n votre système d'exploitation le prend en charge), auth, daemon,\n user,\n local0,\n local1,\n local2,\n local3,\n local4,\n local5,\n local6, et\n local7.

\n
\n
accept_priority = chaîne
\n
\n Priorité syslog à utiliser lorsque l'utilisateur est autorisé à exécuter une commande et que\n l'authentification réussit. Valeur par défaut : notice.\n

Les priorités syslog suivantes sont prises en charge :\n alert,\n crit,\n debug,\n emerg,\n err,\n info,\n notice,\n warning, et none. La définir sur une valeur de\n none désactivera la journalisation des commandes réussies.

\n
\n
reject_priority = chaîne
\n
\n Priorité syslog à utiliser lorsque l'utilisateur n'est pas autorisé à exécuter une commande ou\n lorsque l'authentification échoue. Valeur par défaut : alert.\n

Voir accept_priority pour la liste\n des priorités syslog prises en charge.

\n
\n
alert_priority = chaîne
\n
\n Priorité syslog à utiliser pour les messages d'alerte du journal d'événements reçus du\n client. Valeur par défaut : alert.\n

Voir accept_priority pour la liste\n des priorités syslog prises en charge.

\n
\n
maxlen = nombre
\n
\n Sur de nombreux systèmes, syslog(3) a un\n tampon de journal relativement petit. L'IETF RFC 5424 stipule que les serveurs syslog doivent\n prendre en charge les messages d'au moins 480 octets et devraient prendre en charge les messages jusqu'à\n 2048 octets. Par défaut, sudo_logsrvd crée des messages de journal\n jusqu'à 960 octets, ce qui correspond à l'implémentation historique du syslog de\n BSD qui utilisait un tampon de 1024 octets pour stocker le message, la date, le nom d'hôte et le nom du programme.\n

Pour éviter que les messages syslog ne soient tronqués,\n sudo_logsrvd divisera les messages de journal de style sudo qui sont plus grands que\n maxlen octets. Lorsqu'un message est divisé, les parties supplémentaires incluront la chaîne\n “(commande continuée)” après le nom d'utilisateur et avant les arguments de ligne de commande continués. Les\n entrées de journal au format JSON ne sont jamais divisées et ne sont pas affectées par maxlen.

\n
\n
server_facility = chaîne
\n
\n Installation syslog si syslog est utilisé pour les messages d'avertissement du serveur. Voir\n ci-dessus pour une liste des installations prises en charge. Valeur par défaut :\n daemon

La section logfile contient des paramètres liés à\n la journalisation dans un fichier plat (pas syslog).

\n
\n
path = chaîne
\n
\n Le chemin d'accès au journal d'événements basé sur un fichier. Ce chemin doit être entièrement qualifié\n et commencer par un caractère ‘/’. La valeur par défaut est\n /var/log/sudo.log.

time_format = chaîne
\n
\n La chaîne utilisée lors du formatage de la date et de l'heure pour les journaux d'événements basés sur des fichiers.\n Le formatage est effectué via la fonction strftime(3)\n du système, de sorte que toutes les séquences d'échappement prises en charge par cette fonction seront développées.\n La valeur par défaut est “%h %e %T”, ce qui produit des dates comme “Oct 3 07:15:24”\n dans la locale ‘C’.
\n
