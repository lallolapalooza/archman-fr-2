SU(1) Commandes utilisateur SU(1)

NOM

su - exécuter une commande avec un utilisateur et un groupe substituts

SYNTAXE

su [options] [-] [utilisateur [argument...]]

DESCRIPTION

su permet d'exécuter des commandes avec un identifiant d'utilisateur et de groupe substituts.

Lorsqu'elle est appelée sans spécifier d'utilisateur, su exécute par défaut un shell interactif en tant que root. Lorsqu'un utilisateur est spécifié, des arguments supplémentaires peuvent être fournis, auquel cas ils sont transmis au shell.

Pour des raisons de compatibilité ascendante, su ne change pas le répertoire courant par défaut et ne définit que les variables d'environnement HOME et SHELL (plus USER et LOGNAME si l'utilisateur cible n'est pas root). Il est recommandé d'utiliser toujours l'option --login (au lieu de son raccourci -) pour éviter les effets secondaires causés par le mélange des environnements.

Cette version de su utilise PAM pour l'authentification, la gestion des comptes et des sessions. Certaines options de configuration trouvées dans d'autres implémentations de su, comme le support du groupe wheel, doivent être configurées via PAM.

su est principalement conçu pour les utilisateurs non privilégiés. La solution recommandée pour les utilisateurs privilégiés (par exemple, scripts exécutés par root) est d'utiliser la commande non-set-user-ID runuser(1) qui ne nécessite pas d'authentification et fournit une configuration PAM distincte. Si la session PAM n'est pas nécessaire du tout, la solution recommandée est d'utiliser la commande setpriv(1).

Notez que su utilise dans tous les cas PAM (pam_getenvlist(3)) pour effectuer la modification finale de l'environnement. Les options en ligne de commande telles que --login et --preserve-environment affectent l'environnement avant qu'il ne soit modifié par PAM.

Depuis la version 2.38, su réinitialise les limites de ressources du processus RLIMIT_NICE, RLIMIT_RTPRIO, RLIMIT_FSIZE, RLIMIT_AS et RLIMIT_NOFILE.

OPTIONS

-c, --command commande

Passe la commande au shell avec l'option -c.

-f, --fast

Passe -f au shell, ce qui peut être utile ou non, selon le shell.

-g, --group groupe

Spécifie le groupe primaire. Cette option n'est disponible que pour l'utilisateur root.

-G, --supp-group groupe

Spécifie un groupe supplémentaire. Cette option n'est disponible que pour l'utilisateur root. Le premier groupe supplémentaire spécifié est également utilisé comme groupe primaire si l'option --group n'est pas spécifiée.

-, -l, --login

Démarre le shell comme un shell de connexion avec un environnement similaire à une connexion réelle.

Notez que sur les systèmes basés sur systemd, une nouvelle session peut être définie comme un véritable point d'entrée dans le système. Cependant, su ne crée pas de session réelle (par PAM) de ce point de vue. Vous devez utiliser des outils tels que systemd-run ou machinectl pour initier une session complète et réelle.

su effectue les actions suivantes :

•efface toutes les variables d'environnement sauf TERM et les variables spécifiées par --whitelist-environment
•initialise les variables d'environnement HOME, SHELL, USER, LOGNAME et PATH
•change pour le répertoire personnel de l'utilisateur cible
•définit argv[0] du shell à '-' afin de faire du shell un shell de connexion

-m, -p, --preserve-environment

Préserve l'environnement entier, c'est-à-dire ne définit pas HOME, SHELL, USER ou LOGNAME. Cette option est ignorée si l'option --login est spécifiée.

-P, --pty

Crée un pseudo-terminal pour la session. Le terminal indépendant offre une meilleure sécurité car l'utilisateur ne partage pas de terminal avec la session d'origine. Cela peut être utilisé pour éviter l'injection de commandes par l'ioctl TIOCSTI et d'autres attaques de sécurité contre les descripteurs de fichiers de terminal. La session entière peut également être déplacée en arrière-plan (par exemple, su --pty - utilisateur -c application &). Si le pseudo-terminal est activé, alors su fonctionne comme un proxy entre les sessions (synchronisation de l'entrée et de la sortie standard).

Cette fonctionnalité est principalement conçue pour les sessions interactives. Si l'entrée standard n'est pas un terminal, mais par exemple un pipe (par exemple, echo "date" | su --pty), alors le drapeau ECHO du pseudo-terminal est désactivé pour éviter une sortie confuse.

-s, --shell shell

Exécute le shell spécifié au lieu de celui par défaut. Si l'utilisateur cible a un shell restreint (c'est-à-dire non listé dans /etc/shells), l'option --shell et la variable d'environnement SHELL sont ignorées à moins que l'utilisateur appelant ne soit root.

Le shell à exécuter est sélectionné selon les règles suivantes, par ordre de priorité :

•le shell spécifié avec --shell
•le shell spécifié dans la variable d'environnement SHELL, si l'option --preserve-environment est utilisée
•le shell listé dans l'entrée passwd de l'utilisateur cible
•/bin/sh

--session-command=commande

Identique à -c, mais ne crée pas de nouvelle session. (Déconseillé.)

-T, --no-pty

Ne crée pas de pseudo-terminal, l'opposé de --pty et -P. Notez que l'exécution sans pseudo-terminal présente un risque de sécurité d'escalade de privilèges par injection de commandes via ioctl TIOCSTI/TIOCLINUX.

-w, --whitelist-environment liste

N'efface pas les variables d'environnement spécifiées dans la liste séparée par des virgules lors de l'effacement de l'environnement pour --login. La liste blanche est ignorée pour les variables d'environnement HOME, SHELL, USER, LOGNAME et PATH.

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

SIGNALS

Lors de la réception de SIGINT, SIGQUIT ou SIGTERM, su termine son enfant et ensuite se termine elle-même avec le signal reçu. L'enfant est terminé par SIGTERM, après une tentative infructueuse et un délai de 2 secondes, l'enfant est tué par SIGKILL.

FICHIERS CONFIGURATION

su lit les fichiers de configuration /etc/default/su et /etc/login.defs. Les éléments de configuration suivants sont pertinents pour su :

FAIL_DELAY (nombre)

Délai en secondes en cas d'échec d'authentification. Le nombre doit être un entier non négatif.

ENV_PATH (chaîne)

Définit la variable d'environnement PATH pour un utilisateur ordinaire. La valeur par défaut est /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (chaîne), ENV_SUPATH (chaîne)

Définit la variable d'environnement PATH pour root. ENV_SUPATH a priorité. La valeur par défaut est /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

ALWAYS_SET_PATH (booléen)

Si défini à yes et que --login et --preserve-environment n'ont pas été spécifiés, su initialise PATH.

La variable d'environnement PATH peut être différente sur les systèmes où /bin et /sbin sont fusionnés dans /usr ; cette variable est également affectée par l'option de ligne de commande --login et le paramètre système PAM (par exemple, pam_env(8)).

STATUT SORTIE

Retourne 127 si la commande spécifiée avec l'option -c n'a pas pu être trouvée, ou 126 si elle a été trouvée mais n'a pas pu être exécutée. Retourne le statut de sortie de la commande exécutée sinon. Retourne 1-125 en cas d'erreur de su.

su(1) - Arch Linux manual pages

NOM

su - changer d'ID utilisateur

SYNTAXIS

su [OPTIONS] [USER [ARGUMENT] ...]

su [OPTIONS] [-] [USER [ARGUMENT] ...]

DESCRIPTION

La commande su permet de changer d'ID utilisateur. Si aucun utilisateur n'est spécifié, su passe à l'utilisateur root.

OPTIONS

-, --login
Se connecter avec l'environnement cible. Cela inclut le changement de répertoire de travail vers le répertoire personnel de l'utilisateur cible, le vidage de l'environnement (sauf les variables spécifiées dans login.defs(5)) et le passage au shell de l'utilisateur cible.
-c, --command COMMAND
Exécuter la commande spécifiée par COMMAND et quitter. L'interpréteur de commandes sera exécuté avec l'option -c.
-f, --fast
Ne pas enregistrer la commande ou la session dans lastlog. Cette option n'est disponible que si le noyau le permet.
-g, --gid GROUP
Spécifier l'ID de groupe réel.
-G, --groups GROUP1[,GROUP2,...]
Spécifier les groupes supplémentaires.
-i, --ignore-environment
Ne pas exécuter le shell de l'utilisateur cible avec son environnement d'origine. Au lieu de cela, le shell sera exécuté avec un environnement minimal. Les variables d'environnement spécifiques au shell sont toujours utilisées.
-m, --preserve-environment
Conserver l'environnement actuel. L'environnement de l'utilisateur cible sera utilisé tel quel.
-p
Équivalent de -m.
-s, --shell SHELL
Exécuter le shell spécifié par SHELL.
-u, --uid USER
Spécifier l'ID utilisateur réel.

SIGNALS

su renvoie normalement le statut de sortie de la commande qu'il a exécutée. Si la commande a été tuée par un signal, su renvoie le numéro du signal plus 128.

EXIT STATUS

Statuts de sortie générés par su lui-même :

1

Erreur générique avant d'exécuter la commande demandée

126

La commande demandée n'a pas pu être exécutée

127

La commande demandée n'a pas été trouvée

FILES

/etc/pam.d/su

fichier de configuration PAM par défaut

/etc/pam.d/su-l

fichier de configuration PAM si --login est spécifié

/etc/default/su

fichier de configuration logindef spécifique à la commande

/etc/login.defs

fichier de configuration logindef global

NOTES

Pour des raisons de sécurité, su enregistre toujours les tentatives de connexion échouées dans le fichier btmp, mais n'écrit pas du tout dans le fichier lastlog. Cette solution peut être utilisée pour contrôler le comportement de su par la configuration PAM. Si vous souhaitez utiliser le module pam_lastlog(8) pour afficher un message d'avertissement sur les tentatives de connexion échouées, alors pam_lastlog(8) doit également être configuré pour mettre à jour le fichier lastlog. Par exemple :

session required pam_lastlog.so nowtmp

HISTORY

Cette commande su est dérivée de la commande su de coreutils, qui était basée sur une implémentation de David MacKenzie. La version util-linux a été refactorisée par Karel Zak.
