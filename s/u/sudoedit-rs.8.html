NOM

sudo, sudoedit - exécuter une commande en tant qu'un autre utilisateur

SYNTAXE

sudo -h | -K | -k | -V

sudo [-u utilisateur] [-g groupe] [-D répertoire] [-BknS] [-i | -s] [VAR=valeur] [<commande>]

sudo -v [-BknS] [-u utilisateur] [-g groupe]

sudo -l [-BknS] [-U utilisateur] [-u utilisateur] [-g groupe] [commande [arg ...]]

sudo -e [-BknS] [-u utilisateur] [-g groupe] fichier ...

sudoedit [-BknS] [-u utilisateur] [-g groupe] fichier ...

DESCRIPTION

sudo permet à un utilisateur autorisé de faire exécuter une commande par un autre utilisateur (par exemple root). Les autorisations sont spécifiées par une politique de sécurité définie dans /etc/sudoers (voir sudoers(5)).

Sudo-rs est une réimplémentation de l'implémentation originale de sudo par Todd Miller, axée sur la sécurité et la sécurité mémoire.

Lorsqu'une commande est exécutée, un enregistrement de session est stocké pour cette session spécifique, permettant aux utilisateurs d'exécuter d'autres commandes sans avoir à se réauthentifier. Le délai d'expiration des enregistrements de session peut être spécifié dans la politique.

Certaines précautions sont prises pour transmettre les signaux reçus par sudo-rs au processus enfant, même si ce processus s'exécute dans son propre pseudo-terminal.

Sur les systèmes où sudo est la méthode principale pour obtenir des privilèges de superutilisateur, il est impératif d'éviter les erreurs de syntaxe dans le fichier /etc/sudoers. Les modifications de ce fichier doivent être effectuées à l'aide de l'utilitaire visudo(8) qui garantira qu'aucune erreur de syntaxe n'est introduite.

OPTIONS

-B, --bell
Fait sonner la cloche dans le cadre de l'invite de mot de passe lorsqu'un terminal est présent.
-D répertoire, --chdir=répertoire
Exécute la commande dans le répertoire spécifié au lieu du répertoire de travail actuel. La politique de sécurité peut renvoyer une erreur si l'utilisateur n'a pas l'autorisation de spécifier le répertoire de travail.
-g groupe, --group=groupe
Utilise ce groupe comme groupe principal au lieu d'utiliser le groupe principal spécifié dans la base de données des mots de passe pour l'utilisateur cible.
-h, --help
Affiche un message d'aide.
-i, --login
Exécute le shell spécifié dans l'entrée de la base de données des mots de passe de l'utilisateur cible en tant que shell de connexion. Cela signifie que les fichiers de ressources spécifiques à la connexion tels que .profile, .bash_profile ou .login seront lus par le shell. Si une commande est spécifiée, elle est transmise au shell en utilisant l'option -c.
-K, --remove-timestamp
Supprime tous les enregistrements de session mis en cache pour l'utilisateur, indépendamment de l'endroit où la commande est exécutée. La prochaine fois que sudo-rs sera exécuté, une authentification aura lieu si la politique l'exige. Aucun mot de passe n'est requis pour exécuter cette commande.
-k, --reset-timestamp
Lorsqu'elle est utilisée sans commande, invalide l'enregistrement de session de l'utilisateur pour la session actuelle. La prochaine fois que sudo-rs sera exécuté, une authentification aura lieu si la politique l'exige.

Lorsqu'elle est utilisée conjointement avec une commande ou une option pouvant nécessiter un mot de passe, cette option entraînera l'ignorance de l'enregistrement de session de l'utilisateur par sudo-rs. En conséquence, une authentification aura lieu si la politique l'exige. Lorsqu'elle est utilisée conjointement avec une commande, aucune invalidation des enregistrements de session existants n'aura lieu.

-n, --non-interactive
Évite de demander une quelconque saisie à l'utilisateur. Si une saisie est requise pour que la commande s'exécute, sudo-rs affichera un message d'erreur et se terminera.
p, --prompt=invite
Utilise une invite d'authentification personnalisée avec des séquences d'échappement optionnelles. Les séquences d'échappement suivantes avec le signe pourcent ('%') sont prises en charge :
 %H  développé en nom d'hôte local
 %h  développé en nom d'hôte local sans le nom de domaine
 %p  développé en nom de l'utilisateur dont le mot de passe est demandé
     (ceci respecte les drapeaux rootpw, targetpw)
 %U  développé en nom de connexion de l'utilisateur qui exécutera la commande
     (par défaut root sauf si l'option -u est également spécifiée)
 %u  développé en nom de connexion de l'utilisateur appelant
 %%  deux caractères '%' consécutifs sont remplacés par un seul caractère '%'

L'invite personnalisée remplacera l'invite par défaut ou celle spécifiée par la variable d'environnement SUDO_PROMPT. Aucun invite ne supprimera l'invite fournie par PAM, sauf si l'invite demandée est vide ("")

-S, --stdin
Lit depuis l'entrée standard au lieu d'utiliser le périphérique de terminal.
-s, --shell
Exécute le shell spécifié par la variable d'environnement SHELL. Si aucun shell n'est spécifié, le shell de l'entrée de la base de données des mots de passe de l'utilisateur sera utilisé à la place. Si une commande est spécifiée, elle est transmise au shell en utilisant l'option -c.

-e, sudoedit

Modifie un ou plusieurs fichiers au lieu d'exécuter une commande. Au lieu d'un nom de chemin, la chaîne "sudoedit" est utilisée lors de la consultation de la politique de sécurité. Si l'utilisateur est autorisé par la politique, les étapes suivantes sont effectuées :
1. Des copies temporaires des fichiers à modifier sont créées avec le propriétaire défini sur l'utilisateur appelant.
2. L'éditeur spécifié par la politique est exécuté pour modifier les fichiers temporaires. La politique sudoers utilise les variables d'environnement SUDO_EDITOR, VISUAL et EDITOR (dans cet ordre). Si aucune de ces variables n'est définie, le premier programme listé dans l'option sudoers(5) pour l'éditeur est utilisé.
3. S'ils ont été modifiés, le contenu des fichiers temporaires est copié dans les originaux et les versions temporaires sont supprimées.
Pour aider à prévenir la modification de fichiers non autorisés, les restrictions suivantes sont appliquées (sauf si l'utilisateur est root) :
* Les liens symboliques ne peuvent pas être modifiés.
* Si un composant du chemin menant au fichier est modifiable par l'utilisateur appelant, le fichier ne peut pas être modifié.
* Les utilisateurs ne sont jamais autorisés à modifier les fichiers spéciaux de périphériques.
Si le fichier spécifié n'existe pas, il sera créé. Contrairement à la plupart des commandes exécutées par sudo, l'éditeur est exécuté avec l'environnement de l'utilisateur appelant non modifié. Si le fichier temporaire devient vide après modification, l'utilisateur sera invité avant son installation.
-u utilisateur, --user=utilisateur
Exécute la commande en tant qu'un autre utilisateur que le défaut (root).
-V, --version
Affiche la version actuelle de sudo-rs.
-v, --validate

Valide la politique sudoers. En cas de succès, sudo-rs ne renvoie rien et sortira avec un statut de succès. Sinon, il affichera un message d'erreur et sortira avec un statut de défaillance.

NAME

sudoedit-rs — éditer des fichiers de manière sécurisée

SYNOPSIS

sudoedit-rs [-h | -l [-U user]] [-s] [VAR=value] command

DESCRIPTION

sudoedit-rs est une implémentation de l'éditeur de fichiers sécurisé de sudo.

Lorsque sudoedit-rs est exécuté, il vérifie d'abord que l'utilisateur est autorisé à éditer le fichier spécifié en utilisant la politique de sécurité de sudo. Ensuite, il copie le fichier dans un répertoire temporaire appartenant à l'utilisateur et ouvre le fichier temporaire dans l'éditeur spécifié par la variable d'environnement EDITOR ou VISUAL (ou vi par défaut). Une fois l'éditeur fermé, il copie le fichier temporaire modifié pour remplacer le fichier d'origine, à condition que l'utilisateur soit autorisé à effectuer cette opération.

Cette approche permet d'éditer des fichiers avec des privilèges élevés sans avoir à exécuter le processus d'édition complet en tant que root, ce qui réduit considérablement la surface d'attaque.

OPTIONS

-h, --help
Afficher un message d'aide et quitter.
-s, --session
Mettre à jour l'enregistrement de session pour la session actuelle, en authentifiant l'utilisateur si nécessaire.
-l, --list
Lister les privilèges de l'utilisateur ou vérifier une commande spécifique ; utiliser deux fois pour un format plus long.
-U, --other-user=user
Utilisé en mode liste, afficher les privilèges pour un autre utilisateur.
--
Indique la fin des options de sudo-rs et le début de la commande.

Les variables d'environnement à définir pour la commande peuvent être passées sur la ligne de commande sous la forme VAR=valeur. Les variables passées sur la ligne de commande sont soumises aux restrictions imposées par la politique de sécurité. Les variables passées sur la ligne de commande sont soumises aux mêmes restrictions que les variables d'environnement normales, à une exception importante près : si la commande à exécuter a la balise SETENV définie ou si la commande correspondante est ALL, l'utilisateur peut définir des variables qui seraient autrement interdites. Voir sudoers(5) pour plus d'informations.
