NOM

subuid - configuration pour les identifiants d'utilisateur subordonnés

DESCRIPTION

Subuid autorise un identifiant d'utilisateur à mapper des plages d'identifiants d'utilisateur de son espace de noms vers des espaces de noms enfants.

La délégation des uids subordonnés peut être configurée via le champ subid dans le fichier /etc/nsswitch.conf. Une seule valeur peut être définie comme source de délégation. Définir ce champ sur files configure la délégation des uids vers /etc/subuid. Toute autre valeur traite la délégation comme un plugin portant un nom de la forme libsubid_$valeur.so. Si la valeur ou le plugin est manquant, la délégation d'uid subordonné revient à files.

Notez que newusers, useradd et usermod ne créeront des entrées dans /etc/subuid que si la délégation subid est gérée via les fichiers subid.

DÉLÉGATION LOCALE DES UTILISATEURS SUBORDONNÉS

Chaque ligne de /etc/subuid contient un nom d'utilisateur et une plage d'identifiants d'utilisateur subordonnés que cet utilisateur est autorisé à utiliser. Ceci est spécifié avec trois champs délimités par des deux-points (“:”). Ces champs sont :

•nom de connexion ou UID
•identifiant numérique d'utilisateur subordonné
•nombre d'identifiants numériques d'utilisateur subordonné

Ce fichier spécifie les identifiants d'utilisateur que les utilisateurs ordinaires peuvent utiliser, avec la commande newuidmap, pour configurer le mappage d'uid dans un espace de noms utilisateur.

Plusieurs plages peuvent être spécifiées par utilisateur.

Lorsque un grand nombre d'entrées (10000-100000 ou plus) sont définies dans /etc/subuid, la pénalité de performance de l'analyse deviendra perceptible. Dans ce cas, il est recommandé d'utiliser des UIDs au lieu de noms de connexion. Des benchmarks ont montré des accélérations allant jusqu'à 20x.

FICHIERS

/etc/subuid

Identifiants d'utilisateur subordonnés par utilisateur.

/etc/subuid-

Fichier de sauvegarde pour /etc/subuid.
