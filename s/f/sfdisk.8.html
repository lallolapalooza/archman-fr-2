SFDISK(8) Administration système SFDISK(8)

NOM

sfdisk - afficher ou manipuler une table de partitions de disque

SYNTAXE

sfdisk [options] périphérique [-N numéro-de-partition]

sfdisk [options] commande

DESCRIPTION

sfdisk est un outil orienté script pour partitionner n'importe quel périphérique bloc. Il s'exécute en mode interactif s'il est exécuté sur un terminal (stdin fait référence à un terminal).

Depuis la version 2.26, sfdisk supporte les étiquettes de disque MBR (DOS), GPT, SUN et SGI, mais ne fournit plus aucune fonctionnalité pour l'adressage CHS (Cylinder-Head-Sector). CHS n'a jamais été important pour Linux, et ce concept d'adressage n'a aucun sens pour les nouveaux périphériques.

sfdisk protège le premier secteur du disque lors de la création d'une nouvelle étiquette de disque. L'option --wipe always désactive cette protection. Notez que fdisk(8) et cfdisk(8) effacent complètement cette zone par défaut.

sfdisk (depuis la version 2.26) **aligne le début et la fin des partitions** sur les limites d'E/S du périphérique bloc lorsque des tailles relatives sont spécifiées, lorsque les valeurs par défaut sont utilisées ou lorsque des suffixes multiplicatifs (par exemple, MiB) sont utilisés pour les tailles. Il est possible que la taille de la partition soit optimisée (réduite ou agrandie) en raison de l'alignement si le décalage de début est spécifié exactement en secteurs et que la taille de la partition est relative ou par suffixes multiplicatifs.

La méthode recommandée est de ne pas spécifier du tout les décalages de début et de spécifier la taille de la partition en MiB, GiB (ou similaire). Dans ce cas, sfdisk aligne toutes les partitions sur les limites d'E/S du périphérique bloc (ou si les limites d'E/S sont trop petites, alors sur la limite du mégaoctet pour maintenir la portabilité de la disposition du disque). Si ce comportement par défaut n'est pas souhaité (généralement pour les partitions très petites), spécifiez les décalages et les tailles en secteurs. Dans ce cas, sfdisk suit entièrement les nombres spécifiés sans aucune optimisation.

sfdisk ne crée pas les partitions système standard pour les étiquettes de disque SGI et SUN comme le fait fdisk(8). Il est nécessaire de créer explicitement toutes les partitions, y compris les partitions système du disque entier.

sfdisk utilise l'appel système BLKRRPART (relire la table de partitions) pour s'assurer que le périphérique n'est pas utilisé par le système ou d'autres outils (voir aussi --no-reread). Il est possible que cette fonctionnalité ou une autre activité de sfdisk entre en conflit avec systemd-udevd(8). La méthode recommandée pour éviter d'éventuels conflits est d'utiliser l'option --lock. Le verrouillage exclusif entraînera systemd-udevd à ignorer le traitement des événements sur le périphérique.

L'invite de sfdisk est uniquement un indicateur pour les utilisateurs et un numéro de partition affiché ne signifie pas que la même entrée de table de partitions sera créée (si -N n'est pas spécifié), en particulier pour les tables avec des espaces.

COMMANDES

Les commandes sont mutuellement exclusives.

[-N numéro-de-partition] périphérique

La commande par défaut de sfdisk est de lire la spécification pour le partitionnement désiré du périphérique à partir de l'entrée standard, puis de créer une table de partitions selon la spécification. Voir ci-dessous pour la description du format d'entrée. Si l'entrée standard est un terminal, alors sfdisk démarre une session interactive.

Si l'option -N est spécifiée, alors les modifications sont appliquées à la partition adressée par numéro-de-partition. Les champs non spécifiés de la partition ne sont pas modifiés.

Notez qu'il est possible d'adresser une partition inutilisée avec -N. Par exemple, un MBR contient toujours 4 partitions, mais le nombre de partitions utilisées peut être inférieur. Dans ce cas, sfdisk suit les valeurs par défaut de la table de partitions et n'utilise pas les valeurs par défaut intégrées pour la partition inutilisée donnée avec -N. Voir aussi --append.

-A, --activate périphérique [numéro-de-partition...]

Active le drapeau amorçable pour les partitions spécifiées et désactive le drapeau amorçable sur toutes les partitions non spécifiées. Le marqueur spécial '-' peut être utilisé à la place des numéros de partition pour désactiver le drapeau amorçable sur toutes les partitions.

La commande d'activation est prise en charge pour MBR et PMBR uniquement. Si une étiquette GPT est détectée, alors sfdisk affiche un avertissement et passe automatiquement en PMBR.

Si aucun numéro-de-partition n'est spécifié, alors liste les partitions avec un drapeau activé.

--backup-pt-sectors périphérique

Sauvegarde les secteurs de la table de partitions actuelle au format binaire et quitte. Voir la section SAUVEGARDE DE LA TABLE DES PARTITIONS.

-d, --dump périphérique

Affiche les partitions d'un périphérique dans un format utilisable comme entrée pour sfdisk. Voir la section SAUVEGARDE DE LA TABLE DES PARTITIONS.

-g, --show-geometry [périphérique...]

Liste la géométrie de tous les périphériques ou des périphériques spécifiés. Pour la compatibilité descendante, l'option dépréciée --show-pt-geometry a la même signification que celle-ci.

-J, --json périphérique

Affiche les partitions d'un périphérique au format JSON. Notez que sfdisk n'est pas capable d'utiliser JSON comme format d'entrée.

-l, --list [périphérique...]

Liste les partitions de tous les périphériques ou des périphériques spécifiés. Cette commande peut être utilisée conjointement avec --verify.

-F, --list-free [périphérique...]

Liste les zones libres non partitionnées sur tous les périphériques ou les périphériques spécifiés.

--part-attrs périphérique numéro-de-partition [attributs]

Modifie les bits d'attribut de partition GPT. Si attributs n'est pas spécifié, alors affiche les paramètres actuels de la partition. L'argument attributs est une liste de numéros de bits ou de noms de bits délimitée par des virgules ou des espaces. Par exemple, la chaîne "RequiredPartition,50,51" définit trois bits. Les bits d'attribut actuellement pris en charge sont :

Bit 0 (RequiredPartition)

Si ce bit est défini, la partition est requise pour que la plateforme fonctionne. Le créateur de la partition indique que la suppression ou la modification du contenu peut entraîner une perte de fonctionnalités de la plateforme ou un échec du démarrage ou du fonctionnement de la plateforme. Le système ne peut pas fonctionner normalement si cette partition est supprimée, et elle doit être considérée comme faisant partie du matériel du système.

Bit 1 (NoBlockIOProtocol)

Le firmware EFI doit ignorer le contenu de la partition et ne pas essayer d'en lire.

Bit 2 (LegacyBIOSBootable)

La partition peut être amorçable par le firmware BIOS hérité.

Bits 3-47

Indéfinis et doivent être à zéro. Réservés pour une expansion par les futures versions de la spécification UEFI.

Bits 48-63

Réservés à l'usage spécifique du GUID. L'utilisation de ces bits variera en fonction du type de partition. Par exemple, Microsoft utilise le bit 60 pour indiquer la lecture seule, 61 pour une copie miroir d'une autre partition, 62 pour les partitions cachées et 63 pour désactiver le montage automatique.

--part-label périphérique numéro-de-partition [étiquette]

Modifie le nom (étiquette) de la partition GPT. Si étiquette n'est pas spécifié, alors affiche l'étiquette actuelle de la partition.

--part-type périphérique numéro-de-partition [type]

Modifie le type de partition. Si type n'est pas spécifié, alors affiche le type actuel de la partition.

L'argument type est hexadécimal pour MBR, GUID pour GPT, alias de type (par exemple, "linux") ou raccourci de type (par exemple, 'L'). Pour la compatibilité descendante, les options -c et --id ont la même signification que celle-ci.

--part-uuid périphérique numéro-de-partition [uuid]

Modifie l'UUID de la partition GPT. Si uuid n'est pas spécifié, alors affiche l'UUID actuel de la partition.

--disk-id périphérique [id]

Modifie l'identifiant du disque. Si id n'est pas spécifié

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

COMMANDS

-A, --activate device

Activate or deactivate all partitions of the specified device. The partitions are specified by their bootable flag. See also fdisk(8).

-a, --active device

Toggle the boot flag of the first known partition (MBR only).

-c, --cyl-heads cyl:heads

Set the number of cylinders and heads. This option is useful for old systems and is ignored by modern operating systems. The default values are determined automatically.

-d, --dump [device...]

Dump the partition table (for the specified devices or for all block devices if no device is specified) in a scriptable format to standard output.

-F, --show-ptable

Show the partition table type (e.g., GPT or MBR) for the specified device.

-g, --get-partitions device

Get partition table (GPT or MBR).

-L, --list-free device

List all free regions on the device.

-l, --list-types

Print all supported partition types.

-N, --part-of-table partition

Specify the partition number to use for the operation. Partition numbers start at 1. Use + to use the next available partition number.

-t, --change-type device

Change the partition type ID.

-u, --swap-partitions device

Swap the partition types of the first two partitions.

-v, --show-uuid [device...]

Print the partition UUID for GPT or the partition identifier for MBR. If no device is specified, then print the identifier for all partitions. If the partition table is not recognized or if the partition is not specifed, then print the current identifier. The identifier is UUID for GPT or unsigned integer for MBR.

--discard-free device

Discard any unused (unpartitioned) sectors on the device. Use the --list-free option to get a list of the free regions. See also blkdiscard(8).

Warning

All data in the discarded regions on the device will be lost! Do not use this option if you are unsure.

Note that the 'T' command in fdisk provides a dialog to specify which unused area should be discarded. However, sfdisk always discards all unpartitioned regions (except for the areas where it is not possible to create partitions, such as the beginning of the device).

-r, --reorder device

Renumber the partitions, ordering them by their start offset.

-s, --show-size [device...]

List the sizes of all or the specified devices in units of 1024 byte size. This command is DEPRECATED in favour of blockdev(8).

-T, --list-types

Print all supported types for the current disk label or the label specified by --label.

-V, --verify [device...]

Test whether the partition table and partitions seem correct.

--relocate oper device

Relocate partition table header. This command is currently supported for GPT header only. The argument oper can be:

gpt-bak-std

Move GPT backup header to the standard location at the end of the device.

gpt-bak-mini

Move GPT backup header behind the last partition. Note that UEFI standard requires the backup header at the end of the device and partitioning tools can automatically relocate the header to follow the standard.

OPTIONS

-a, --append

Don’t create a new partition table, but only append the specified partitions.

Note that unused partition maybe be re-used in this case although it is not the last partition in the partition table. See also -N to specify entry in the partition table.

-b, --backup

Back up the current partition table sectors before starting the partitioning. The default backup file name is ~/sfdisk-<device>-<offset>.bak; to use another name see option -O, --backup-file. See section BACKING UP THE PARTITION TABLE for more details.

--color[=when]

Colorize the output. The optional argument when can be auto, never or always. If the when argument is omitted, it defaults to auto. The colors can be disabled; for the current built-in default see the --help output. See also the COLORS section.

-f, --force

Disable all consistency checking.

--Linux

Deprecated and ignored option. Partitioning that is compatible with Linux (and other modern operating systems) is the default.

--lock[=mode]

Use exclusive BSD lock for device or file it operates. The optional argument mode can be yes, no (or 1 and 0) or nonblock. If the mode argument is omitted, it defaults to yes. This option overwrites environment variable $LOCK_BLOCK_DEVICE. The default is not to use any lock at all, but it’s recommended to avoid collisions with systemd-udevd(8) or other tools.

-n, --no-act

Do everything except writing to the device.

--no-reread

Do not check through the re-read-partition-table ioctl whether the device is in use.

--no-tell-kernel

Don’t tell the kernel about partition changes. This option is recommended together with --no-reread to modify a partition on used disk. The modified partition should not be used (e.g., mounted).

-O, --backup-file path

Override the default backup file name. Note that the device name and offset are always appended to the file name.

--move-data[=path]

Move data after partition relocation, for example when moving the beginning of a partition to another place on the disk. The size of the partition has to remain the same, the new and old location may overlap. This option requires option -N in order to be processed on one specific partition only.

The optional path specifies log file name. The log file contains information about all read/write operations on the partition data. The word "@default" as a path forces sfdisk to use ~/sfdisk-<devname>.move for the log. The log is optional since v2.35.

Note that this operation is risky and not atomic. Don’t forget to backup your data!

See also --move-use-fsync.

In the example below, the first command creates a 100MiB free area before the first partition and moves the data it contains (e.g., a filesystem), the next command creates a new partition from the free space (at offset 2048), and the last command reorders partitions to match disk order (the original sdc1 will become sdc2).

echo '+100M,' | sfdisk --move-data /dev/sdc -N 1

echo '2048,' | sfdisk /dev/sdc --append

sfdisk /dev/sdc --reorder

--move-use-fsync

Use the fsync(2) system call after each write when moving data to a new location by --move-data.

-o, --output list

Specify which output columns to print. Use --help to get a list of all supported columns.

The default list of columns may be extended if list is specified in the format +list (e.g., -o +UUID).

-q, --quiet

Suppress extra info messages.

--sector-size sectorsize

Specify the sector size of the disk. Valid values are 512, 1024, 2048, and 4096. The kernel is aware of the sector size for regular block devices. Use this option only on very old kernels, when working with disk images, or to override the kernel’s default sector size. Since util-linux-2.17, fdisk distinguishes between logical and physical sector size. This option changes both sector sizes to the specified sectorsize.

-u, --unit S

Deprecated option. Only the sector unit is supported. This option is not supported when using the --show-size command.

-X, --label type

Specify the disk label type (e.g., dos, gpt, ...). If this option is not given, then sfdisk defaults to the existing label, but if there is no label on the device yet, then the type defaults to dos. The default or the current label may be overwritten by the "label: <name>" script header line. The option --label does not force sfdisk to create empty disk label (see the EMPTY DISK LABEL section below).

-Y, --label-nested type

Force editing of a nested disk label. The primary disk label has to exist already. This option allows editing for example a hybrid/protective MBR on devices with GPT.

-w, --wipe when

Wipe filesystem, RAID and partition-table signatures from the device, in order to avoid possible collisions. The argument when can be auto, never or always. When this option is not given, the default is auto, in which case signatures are wiped only when in interactive mode; except the old partition-table signatures which are always wiped before create a new partition-table if the argument when is not never. The auto mode also does not wipe the first sector (boot sector), it is necessary to use the always mode to wipe this area. In all cases detected signatures are reported by warning messages before a new partition table is created. See also the wipefs(8) command.

-W, --wipe-partitions when

Wipe filesystem, RAID and partition-table signatures from a newly created partition, in order to avoid possible collisions. The argument when can be auto, never or always. When this option is not given, the default is auto, in which case signatures are wiped only when in interactive mode and after confirmation by user. In all cases detected signatures are reported by warning messages after a new partition is created. See also wipefs(8) command.

-v, --version

Display version information and exit.

-h, --help

Display help text and exit.

INPUT FORMATS

sfdisk supports two input formats and generic header lines.

Header lines

The optional header lines specify generic information that apply to the partition table. The header-line format is:

<name>: <value>

The currently recognized headers are:

unit

Specify the partitioning unit. The only supported unit is sectors.

label

Specify the partition table type. For example dos or gpt.

label-id

Specify the partition table identifier. It should be a hexadecimal number (with a 0x prefix) for MBR and a UUID for GPT.

first-lba

Specify the first usable sector for GPT partitions. This header is ignored if the script and device sector size differ. In this case sfdisk uses label specific default.

last-lba

Specify the last usable sector for GPT partitions. This header is ignored if the script and device sector size differ. In this case sfdisk uses label specific default. The last-lba header is ign ored if the script and device sector size differ. In this case sfdisk uses label specific default.
ored si --force est spécifié, rendant le script utilisable sur des disques de tailles différentes.

table-length

Spécifiez le nombre maximal de partitions GPT.

grain

Spécifiez la taille minimale en octets utilisée pour calculer l'alignement des partitions. La valeur par défaut est 1 MiB et il est fortement recommandé d'utiliser la valeur par défaut. Ne modifiez pas cette variable si vous n'êtes pas sûr.

sector-size

Spécifie la taille du secteur utilisée dans l'entrée. sfdisk utilise toujours en interne la taille de secteur du périphérique fournie par le noyau pour le périphérique bloc, ou telle que spécifiée par l'utilisateur sur la ligne de commande (voir --sector-size). À partir de la version 2.39, sfdisk recalcule les tailles à partir de l'entrée si l'en-tête sector-size et la taille de secteur du périphérique sont différentes.

Notez qu'il n'est possible d'utiliser des lignes d'en-tête qu'avant que la première partition ne soit spécifiée dans l'entrée.

Format sans nom

début taille type amorçable

où chaque ligne remplit un descripteur de partition.

Les champs sont séparés par des espaces, une virgule (recommandée) ou un point-virgule éventuellement suivi d'espaces ; les espaces initiaux et finaux sont ignorés. Les nombres peuvent être octaux, décimaux ou hexadécimaux ; le décimal est la valeur par défaut. Lorsqu'un champ est absent, vide ou spécifié comme '-', une valeur par défaut est utilisée. Mais lorsque l'option -N (modifier une seule partition) est donnée, la valeur par défaut de chaque champ est sa valeur précédente.

La valeur par défaut de début est le premier secteur non attribué aligné selon les limites d'E/S du périphérique. Le décalage de départ par défaut pour la première partition est de 1 MiB. Si le décalage est suivi des suffixes multiplicatifs (KiB, MiB, GiB, TiB, PiB, EiB, ZiB et YiB), alors le nombre est interprété comme le décalage en octets. Depuis la v2.38, lorsque l'option -N (modifier une seule partition) est donnée, un '+' peut être utilisé pour agrandir la partition en déplaçant le début de la partition s'il y a de l'espace libre avant la partition.

La valeur par défaut de taille indique « autant que possible » ; c'est-à-dire jusqu'à la partition suivante ou la fin du périphérique. Un argument numérique est par défaut interprété comme un nombre de secteurs, cependant si la taille est suivie d'un des suffixes multiplicatifs (KiB, MiB, GiB, TiB, PiB, EiB, ZiB et YiB), alors le nombre est interprété comme la taille de la partition en octets et elle est ensuite alignée selon les limites d'E/S du périphérique. Un '+' peut être utilisé à la place d'un nombre pour agrandir la partition autant que possible. Notez que '+' est équivalent au comportement par défaut pour une nouvelle partition ; les partitions existantes seront redimensionnées si nécessaire.

Le type de partition est donné en hexadécimal pour MBR (DOS) où le préfixe 0x est facultatif ; une chaîne GUID pour GPT ; un raccourci ou un alias. Il est recommandé d'utiliser deux lettres pour les codes hexadécimaux MBR afin d'éviter la collision entre le raccourci obsolète 'E' et le code hexadécimal MBR '0E'. Pour des raisons de compatibilité ascendante, sfdisk essaie d'interpréter type comme un raccourci en premier lieu dans les scripts de partitionnement, bien que dans d'autres endroits (par exemple, la commande --part-type), il essaie les raccourcis en dernier recours.

Depuis la v2.36, libfdisk prend en charge les alias de type de partition en extension des raccourcis. L'alias est un simple mot lisible par l'homme (par exemple, « linux »).

Depuis la v2.37, libfdisk prend en charge les noms de type de partition en entrée, ignorant la casse des caractères et tous les caractères non alphanumériques et non numériques dans le nom (par exemple, « Linux /usr x86 » est identique à « linux usr-x86 »).

Raccourcis et alias pris en charge :

L - alias 'linux'

Linux ; signifie 83 pour MBR et 0FC63DAF-8483-4772-8E79-3D69D8477DE4 pour GPT.

S - alias 'swap'

Espace d'échange ; signifie 82 pour MBR et 0657FD6D-A4AB-43C4-84E5-0933C84B4F4F pour GPT.

Ex - alias 'extended'

Partition étendue MBR ; signifie 05 pour MBR. Le raccourci d'origine 'E' est obsolète en raison de la collision avec le type de partition MBR 0x0E.

H - alias 'home'

Partition /home ; signifie 933AC7E1-2EB4-4F13-B844-0E14E2AEF915 pour GPT.

U - alias 'uefi'

Partition système EFI, signifie EF pour MBR et C12A7328-F81F-11D2-BA4B-00A0C93EC93B pour GPT.

R - alias 'raid'

RAID Linux ; signifie FD pour MBR et A19D880F-05FC-4D3B-A006-743F0F84911E pour GPT.

V - alias 'lvm'

LVM ; signifie 8E pour MBR et E6D6D379-F507-44C2-A23C-238F2A3DF928 pour GPT.

La valeur par défaut de type est linux.

Le raccourci 'X' pour la partition étendue Linux (85) est obsolète au profit de 'Ex'.

amorçable est spécifié comme [*|-], avec par défaut non amorçable. La valeur de ce champ est sans importance pour Linux - lorsqu'il tourne, il a déjà été démarré - mais elle peut jouer un rôle pour certains chargeurs de démarrage et pour d'autres systèmes d'exploitation.

Format avec noms

Ce format est plus lisible, robuste, extensible et permet de spécifier des informations supplémentaires (par exemple, un UUID). Il est recommandé d'utiliser ce format pour rendre vos scripts plus lisibles.

[périphérique :] nom[=valeur], ...

Le champ périphérique est facultatif. sfdisk extrait le numéro de partition du nom du périphérique. Il permet de spécifier les partitions dans un ordre aléatoire. Cette fonctionnalité est principalement utilisée par --dump. Ne l'utilisez pas si vous n'êtes pas sûr.

La valeur peut être entre guillemets (par exemple, nom="Ceci est le nom de la partition"). Les champs start= et size= prennent en charge '+' et '-' de la même manière que le Format sans nom.

Les champs actuellement pris en charge sont :

start=nombre

Le premier secteur non attribué, aligné selon les limites d'E/S du périphérique. Le décalage de départ par défaut pour la première partition est de 1 MiB. Si le décalage est suivi des suffixes multiplicatifs (KiB, MiB, GiB, TiB, PiB, EiB, ZiB et YiB), alors le nombre est interprété comme le décalage en octets.

size=nombre

Spécifie la taille de la partition en secteurs. Le nombre peut être suivi des suffixes multiplicatifs (KiB, MiB, GiB, TiB, PiB, EiB, ZiB et YiB), alors il est interprété comme la taille en octets et la taille est alignée selon les limites d'E/S du périphérique.

bootable

Marque la partition comme amorçable.

attrs=chaîne

Attributs de partition, généralement les bits d'attribut de partition GPT. Voir --part-attrs pour plus de détails sur le format de la chaîne de bits GPT.

uuid=chaîne

UUID de partition GPT.

name=chaîne

Nom de partition GPT.

type=code

Un nombre hexadécimal (sans 0x) pour une partition MBR, un GUID pour une partition GPT, un raccourci comme pour le format sans nom ou un nom de type (par exemple, type="Linux /usr (x86)"). Voir ci-dessus la section sur le format sans nom pour plus de détails. Pour des raisons de compatibilité ascendante, le champ Id= a la même signification.

ÉTIQUETTE DISQUE VIDE

sfdisk ne crée pas de table de partitions sans partitions par défaut. Les lignes avec des partitions sont attendues dans le script par défaut. La table de partitions vide doit être explicitement demandée par une ligne d'en-tête de script « label: <nom> » sans aucune ligne de partition. Par exemple :

echo 'label: gpt' | sfdisk /dev/sdb

crée une table de partitions GPT vide. Notez que --append désactive cette fonctionnalité.

SAUVEGARDE DE LA TABLE DES PARTITIONS

Il est recommandé de sauvegarder la configuration de vos périphériques. sfdisk prend en charge deux méthodes.

Sauvegarde au format compatible sfdisk

Utilisez la commande --dump pour enregistrer une description de la configuration du périphérique dans un fichier texte. Le format de sauvegarde convient pour une utilisation ultérieure par sfdisk. Par exemple :

sfdisk --dump /dev/sda > sda.dump

Cela peut être restauré plus tard par :

sfdisk /dev/sda < sda.dump

Notez que sfdisk restaure complètement les types de partitions et les UUID de partitions. Cela peut potentiellement devenir problématique si vous dupliquez la même configuration sur différents disques, car cela peut entraîner des UUID dupliqués dans votre système.

Sauvegarde binaire complète

Si vous souhaitez effectuer une sauvegarde binaire complète de tous les secteurs où la table de partitions est stockée, utilisez la commande --backup-pt-sectors. Elle écrit les secteurs dans des fichiers ~/sfdisk-<périphérique>-<décalage>.bak. Le nom par défaut du fichier de sauvegarde peut être modifié avec l'option --backup-file. Les fichiers de sauvegarde ne contiennent que les données brutes du périphérique. Par exemple :

sfdisk --backup-pt-sectors /dev/sda

L'en-tête GPT peut être restauré plus tard par :

dd if=~/sfdisk-sda-0x00000200.bak of=/dev/sda seek=$((0x00000200)) bs=1 conv=notrunc

Il est également possible d'utiliser l'option --backup pour créer la même sauvegarde immédiatement après le démarrage pour d'autres commandes sfdisk. Par exemple, sauvegarder la table de partitions avant de supprimer toutes les partitions :

sfdisk --backup --delete /dev/sda

Le même concept de fichiers de sauvegarde est utilisé par wipefs(8).

Notez que sfdisk depuis la version 2.26 ne fournit plus l'option -I pour restaurer les secteurs. dd(1) fournit toutes les fonctionnalités nécessaires.

La coloration de la sortie est implémentée par la fonctionnalité terminal-colors.d(5). La coloration implicite peut être désactivée par un fichier vide

COULEURS

La sortie de sfdisk peut être colorisée. La colorisation est activée par défaut, sauf si elle est désactivée par un fichier de configuration ou une variable d'environnement.

Pour désactiver la colorisation pour un outil spécifique, créez un fichier vide sous le nom

/etc/terminal-colors.d/sfdisk.disable

ou pour tous les outils par

/etc/terminal-colors.d/disable

Depuis la version 2.41, la variable d'environnement $NO_COLOR est également prise en charge pour désactiver la colorisation de la sortie, sauf si elle est explicitement activée par une option de ligne de commande.

Les répertoires $XDG_CONFIG_HOME/terminal-colors.d ou $HOME/.config/terminal-colors.d de l'utilisateur remplacent le réglage global.

Notez que la colorisation de la sortie peut être activée par défaut, et dans ce cas les répertoires terminal-colors.d n'ont pas besoin d'exister encore.

Les noms de couleurs logiques pris en charge par sfdisk sont :

header

L'en-tête des tableaux de sortie.

warn

Les messages d'avertissement.

welcome

Le message de bienvenue.

NOTES

Depuis la version 2.26, sfdisk ne fournit plus l'option -R ou --re-read pour forcer le noyau à relire la table de partitions. Utilisez blockdev --rereadpt à la place.

Depuis la version 2.26, sfdisk ne fournit pas les options --DOS, --IBM, --DOS-extended, --unhide, --show-extended, --cylinders, --heads, --sectors, --inside-outer, --not-inside-outer.

EXEMPLES

sfdisk --list --label-nested=mbr /dev/sda

Affiche la table de partitions MBR protectrice sur un périphérique avec une étiquette de disque GPT.

echo -e ',10M,L\n,10M,L\n,+,\n' | sfdisk /dev/sdc

Crée trois partitions Linux, avec le début par défaut, la taille des deux premières partitions est de 10 Mio, et la dernière partition remplit tout l'espace disponible sur le périphérique.

echo -e 'size=10M, type=L\n size=10M, type=L\n size=+\n' | sfdisk /dev/sdc

Identique à l'exemple précédent, mais au format champs nommés.

echo -e 'type=swap' | sfdisk -N 3 /dev/sdc

Définit le type de la 3ème partition sur 'swap'.

sfdisk --part-type /dev/sdc 3 swap

Identique à l'exemple précédent, mais sans utilisation de script.

sfdisk --delete /dev/sdc 2

Supprime la 2ème partition.

echo "+,+" | sfdisk -N 3 --move-data /dev/sdc

Agrandit la 3ème partition dans les deux sens, déplace le début pour utiliser l'espace libre avant la partition et agrandit la taille pour utiliser tout l'espace libre après la partition, et déplace également les données de la partition.
