SYSTEMD-JOURNAL-REMOTE.SERVICE(8) systemd-journal-remote.service SYSTEMD-JOURNAL-REMOTE.SERVICE(8)

NOM

systemd-journal-remote.service, systemd-journal-remote.socket, systemd-journal-remote - Recevoir des messages du journal sur le réseau

SYNTAXE

systemd-journal-remote.service

systemd-journal-remote.socket

/usr/lib/systemd/systemd-journal-remote [OPTIONS...] [-o/--output=DIR|FICHIER] [SOURCES...]

DESCRIPTION

systemd-journal-remote est une commande pour recevoir des événements de journal sérialisés et les stocker dans des fichiers de journal. Les flux d'entrée sont au format Journal Export Format[1], c'est-à-dire comme la sortie de journalctl --output=export. Pour le transport sur le réseau, ce flux sérialisé est généralement véhiculé via une connexion HTTPS.

systemd-journal-remote.service est un service système qui utilise systemd-journal-remote pour écouter les connexions. systemd-journal-remote.socket configure l'adresse réseau sur laquelle systemd-journal-remote.service écoute. Par défaut, il s'agit du port 19532. Quelles connexions sont acceptées et comment les données reçues sont stockées peuvent être configurés via le fichier de configuration journal-remote.conf(5).

SOURCES

Les sources peuvent être soit "actives" (systemd-journal-remote demande et récupère les données), soit "passives" (systemd-journal-remote attend une connexion et reçoit ensuite les événements poussés par l'autre côté).

systemd-journal-remote peut lire plus d'un flux d'événements à la fois. Ils seront entrelacés dans le fichier de sortie. Dans le cas des connexions "actives", chaque "source" est un flux, et dans le cas des connexions "passives", chaque connexion peut résulter en un flux distinct. Les sockets peuvent être configurés en mode "accept" (c'est-à-dire une seule connexion), ou en mode "listen" (c'est-à-dire plusieurs connexions, chacune résultant en un flux).

Lorsqu'il n'y a plus de connexions, et qu'il ne peut plus en être créé (il n'y a pas de sockets d'écoute), alors systemd-journal-remote se terminera.

Les sources actives peuvent être spécifiées de la manière suivante :

[SOURCES]

Lorsque - est donné comme argument positionnel, les événements seront lus depuis l'entrée standard. D'autres arguments positionnels seront traités comme des noms de fichiers à ouvrir et à lire.

Ajouté dans la version 239.

--url=ADRESSE

Avec l'option --url=ADRESSE, les événements seront récupérés via HTTP depuis ADRESSE. Cette URL doit faire référence à la racine d'une instance distante de systemd-journal-gatewayd(8), par exemple http://some.host:19531/ ou https://some.host:19531/.

Ajouté dans la version 239.

--getter='PROG [OPTIONS]'

Programme à invoquer pour récupérer les données. Le flux d'événements du journal doit être généré sur la sortie standard.

Exemples:

--getter='curl "-HAccept: application/vnd.fdo.journal" https://some.host:19531/'
--getter='wget --header="Accept: application/vnd.fdo.journal" -O- https://some.host:19531/'

Ajouté dans la version 239.

Les sources passives peuvent être spécifiées de la manière suivante :

--listen-raw=ADRESSE

ADRESSE doit être une adresse appropriée pour ListenStream= (voir systemd.socket(5)). systemd-journal-remote écoutera sur ce socket les connexions. Chaque connexion est attendue comme un flux d'événements de journal.

Ajouté dans la version 239.

--listen-http=ADRESSE, --listen-https=ADRESSE

ADRESSE doit être soit un entier négatif, auquel cas il sera interprété comme le numéro du descripteur de fichier (négativé), soit une adresse appropriée pour ListenStream= (cf. systemd.socket(5)). Dans le premier cas, le serveur écoute sur le port 19532 par défaut, et le descripteur de fichier correspondant doit être hérité via $LISTEN_FDS/$LISTEN_PID. Dans le second cas, un serveur HTTP ou HTTPS sera lancé sur ce port, respectivement pour --listen-http= et --listen-https=. Actuellement, seuls les requêtes POST vers /upload avec "Content-Type: application/vnd.fdo.journal" sont prises en charge.

Ajouté dans la version 239.

$LISTEN_FDS

systemd-journal-remote prend en charge le protocole $LISTEN_FDS/$LISTEN_PID. Les sockets ouverts hérités via l'activation de socket se comportent comme ceux ouverts avec --listen-raw= décrit ci-dessus, sauf s'ils sont spécifiés comme argument dans --listen-http=-n ou --listen-https=-n ci-dessus. Dans ce dernier cas, un serveur HTTP ou HTTPS sera lancé en utilisant ce descripteur et les connexions devront être effectuées via le protocole HTTP.

Ajouté dans la version 239.

--key=

Prend un chemin vers un fichier de clé secrète SSL au format PEM. Par défaut, c'est /etc/ssl/private/journal-remote.pem. Cette option peut être utilisée avec --listen-https=. Si le chemin fait référence à un socket de flux AF_UNIX dans le système de fichiers, une connexion est établie et la clé est lue à partir de là.

Ajouté dans la version 239.

--cert=

Prend un chemin vers un fichier de certificat SSL au format PEM. Par défaut, c'est /etc/ssl/certs/journal-remote.pem. Cette option peut être utilisée avec --listen-https=. Si le chemin fait référence à un socket de flux AF_UNIX dans le système de fichiers, une connexion est établie et le certificat est lu à partir de là.

Ajouté dans la version 239.

--trust=

Prend un chemin vers un fichier de certificat CA SSL au format PEM, ou all. Si all est défini, la vérification du certificat sera désactivée. Par défaut, c'est /etc/ssl/ca/trusted.pem. Cette option peut être utilisée avec --listen-https=. Si le chemin fait référence à un socket de flux AF_UNIX dans le système de fichiers, une connexion est établie et le certificat est lu à partir de là.

Ajouté dans la version 239.

--gnutls-log=

Prend une liste de catégories de journalisation gnutls séparées par des virgules. Cette option peut être utilisée avec --listen-http= ou --listen-https=.

Ajouté dans la version 239.

DESTINATIONS

L'emplacement du journal de sortie peut être spécifié avec -o ou --output=.

-o FICHIER, --output=FICHIER

Écrira dans ce fichier journal. Le nom de fichier doit se terminer par .journal. Le fichier sera créé s'il n'existe pas. Si nécessaire (fichier journal plein ou corrompu), le fichier sera renommé conformément aux règles normales de journald et un nouveau fichier journal sera créé à sa place.

Ajouté dans la version 239.

-o DIR, --output=DIR

Créera des fichiers journaux dans le répertoire DIR. Le répertoire doit exister. Si nécessaire (fichiers journaux hors taille, ou corrompus), les fichiers journaux seront mis en rotation conformément aux règles normales de journald. Les noms des fichiers sous DIR seront générés en utilisant les règles décrites ci-dessous.

Ajouté dans la version 239.

Si --output= n'est pas utilisé, le répertoire de sortie /var/log/journal/remote/ sera utilisé. Dans le cas où le fichier de sortie n'est pas spécifié, les fichiers journaux seront créés sous le répertoire sélectionné. Les fichiers seront nommés remote-hostname.journal, où la partie hostname est le nom d'hôte échappé du point de terminaison source de la connexion, ou l'adresse numérique si le nom d'hôte ne peut être déterminé.

Dans le cas où des sources "actives" sont fournies par les arguments positionnels ou l'option --getter=, le nom du fichier de sortie doit toujours être spécifié explicitement.

OPTIONS

Les options suivantes sont comprises:

--split-mode

Un parmi none ou host. Pour le premier, un seul fichier journal de sortie est utilisé. Pour le second, un fichier de sortie distinct est utilisé, basé sur le nom d'hôte de l'autre point de terminaison d'une connexion.

systemd-journal-remote 8 — systemd 258.2

NAME

systemd-journal-remote — Forward journal entries to a remote system

SYNOPSIS

systemd-journal-remote [OPTION...]

DESCRIPTION

The systemd-journal-remote service collects journal entries sent by systemd-journal-upload(8) and writes them to a local journal file, usually in /var/log/journal/remote/. It can also listen on a network socket and accept connections from systemd-journal-gatewayd(8).

It is typically run as a system service, managed by systemd itself, via the systemd-journal-remote.service(5) unit.

The configuration file for this service is journal-remote.conf(5).

SOURCES

By default, systemd-journal-remote listens on the network socket defined in journal-remote.conf(5) for incoming journal data. If --listen-stream or --listen-datagram are used, these will override the configuration file.

It may also receive journal data via standard input if the - argument is given.

SINKS

By default, systemd-journal-remote writes all received journal entries to a local journal file. The directory for these files is configured in journal-remote.conf(5) with the Storage= setting, and defaults to /var/log/journal/remote/. If --directory= is used, it overrides the configuration file.

If the --output= option is used, the journal entries will be written to the specified file instead of the default directory.

OPTIONS

The following options are understood:

--listen-stream=ADDRESS
Listen on the specified network address for incoming journal entries via TCP or UNIX stream sockets. This option may be specified multiple times. See sd_listen_fds(3) for a list of valid address formats. This option overrides the ListenStream= setting in journal-remote.conf(5).
--listen-datagram=ADDRESS
Listen on the specified network address for incoming journal entries via UDP or UNIX datagram sockets. This option may be specified multiple times. See sd_listen_fds(3) for a list of valid address formats. This option overrides the ListenDatagram= setting in journal-remote.conf(5).
--directory=DIR
Write journal files into the directory DIR instead of the default /var/log/journal/remote/. This option overrides the Storage= setting in journal-remote.conf(5).
--output=FILE
Write journal entries to the specified FILE in the journal export format. If this option is used, the --directory= and Storage= settings are ignored. This option overrides the Output= setting in journal-remote.conf(5).
--compress
Compress journal data using XZ. This is the default unless explicitly disabled in journal-remote.conf(5) or by passing --compress=no.
--seal
Sign journal data using Forward Secure Sealing. This is disabled by default unless explicitly enabled in journal-remote.conf(5) or by passing --seal=yes.
--url=URL
Connect to the journal gateway service at the specified URL and retrieve journal entries. This option may be specified multiple times. The --url option implies --listen-stream= and disables listening for incoming connections. The following protocols are supported: http:, https:, sd:. See systemd-journal-gatewayd(8) for details on the journal gateway protocol.
--no-exit-with-failure
Do not exit if journal entries cannot be sent to the configured remote journal. This is the default.
--exit-with-failure
Exit if journal entries cannot be sent to the configured remote journal. This is only effective when using the --url option.
--compress [BOOL]
If this is set to "yes" then compress the data in the journal using XZ. The default is "yes".

Added in version 239.

--seal [BOOL]
If this is set to "yes" then periodically sign the data in the journal using Forward Secure Sealing. The default is "no".

Added in version 239.

-h, --help
Print a short help text and exit.
--version
Print a short version string and exit.

Command line options override settings in the journal-remote.conf(5) file.

If - is passed as the last argument, journal entries read from standard input will be written to the journal files. This is useful for piping the output of journalctl(1) to another journal instance.

EXAMPLES

Copy local journal events to a different journal directory:

journalctl -o export | systemd-journal-remote -o /tmp/dir/foo.journal -

Retrieve all available events from a remote systemd-journal-gatewayd(8) instance and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/

Retrieve current boot events and wait for new events from a remote systemd-journal-gatewayd(8) instance, and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/entries?boot&follow
