NOM

systemd-machine-id-setup - Initialise l'ID machine dans /etc/machine-id

SYNTAXE

systemd-machine-id-setup

DESCRIPTION

systemd-machine-id-setup peut être utilisé par les outils d'installation système pour initialiser l'ID machine stocké dans /etc/machine-id lors de l'installation, avec un ID provisionné ou généré aléatoirement. Voir machine-id(5) pour plus d'informations sur ce fichier.

Si l'outil est appelé sans le commutateur --commit, /etc/machine-id est initialisé avec un nouvel ID machine valide s'il est absent ou vide. Le nouvel ID machine sera obtenu de la manière suivante :

1.Si un ID machine valide est stocké dans /run/machine-id, l'ID machine est copié et utilisé pour initialiser l'ID machine dans /etc/machine-id. Cette étape est ignorée si --root= est spécifié ou si l'on exécute dans un environnement chroot.
2.Si un ID machine D-Bus valide est déjà configuré pour le système, l'ID machine D-Bus est copié et utilisé pour initialiser l'ID machine dans /etc/machine-id.
3.Si un ID machine valide est fourni via l'identifiant de credential system.machine_id, l'ID machine est copié et utilisé pour initialiser l'ID machine dans /etc/machine-id. Cette étape est ignorée si --root= est spécifié ou si l'on exécute dans un environnement chroot.
4.Si exécuté à l'intérieur d'une machine virtuelle KVM et qu'un UUID est configuré (via l'option -uuid), cet UUID est utilisé pour initialiser l'ID machine. L'appelant doit s'assurer que l'UUID fourni est suffisamment unique et différent pour chaque instance démarrée de la VM. Cette étape est ignorée si --root= est spécifié ou si l'on exécute dans un environnement chroot.
5.De même, si exécuté à l'intérieur d'un environnement de conteneur Linux et qu'un UUID est configuré pour le conteneur, celui-ci est utilisé pour initialiser l'ID machine. Pour plus de détails, voir la documentation de l'Interface Conteneur[1]. Cette étape est ignorée si --root= est spécifié ou si l'on exécute dans un environnement chroot.
6.Sinon, un nouvel ID est généré aléatoirement.

Le commutateur --commit peut être utilisé pour valider un ID machine transitoire sur disque, le rendant persistant. Pour plus de détails, voir ci-dessous.

Utilisez systemd-firstboot(1) pour initialiser l'ID machine sur des images système montées (mais non démarrées).

OPTIONS

Les options suivantes sont comprises :

--root=chemin

Prend un chemin de répertoire comme argument. Tous les chemins traités seront préfixés par le chemin racine alternatif donné, y compris le chemin pour /etc/machine-id.

Ajouté dans la version 212.

--image=chemin

Prend un chemin vers un nœud de périphérique ou un fichier régulier comme argument. Ceci est similaire à --root= comme décrit ci-dessus, mais opère sur une image disque au lieu d'une arborescence de répertoires.

Ajouté dans la version 249.

--image-policy=politique

Prend une chaîne de politique d'image comme argument, selon systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si elle n'est pas spécifiée, la politique par défaut est "*", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--commit

Valide un ID machine transitoire sur disque. Cette commande peut être utilisée pour convertir un ID machine transitoire en un ID persistant. Un fichier d'ID machine transitoire est un fichier qui a été monté par liaison depuis un système de fichiers en mémoire (généralement "tmpfs") vers /etc/machine-id pendant la phase précoce du processus de démarrage. Cela peut se produire car /etc/ est initialement en lecture seule et manquait d'un fichier d'ID machine valide à ce moment-là.

Cette commande n'exécutera aucune opération si /etc/machine-id n'est pas monté depuis un système de fichiers en mémoire, ou si /etc/ est en lecture seule. La commande écrira l'ID machine transitoire actuel sur disque et démontera le point de montage /etc/machine-id de manière sans course pour s'assurer que ce fichier est toujours valide et accessible pour les autres processus.

Cette commande est principalement utilisée par le service de démarrage anticipé systemd-machine-id-commit.service(8).

Ajouté dans la version 227.

--print

Imprime l'ID machine généré ou validé après la fin de l'opération.

Ajouté dans la version 231.

-h, --help

Imprime un court message d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

CODES DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
