NOM

systemd-pstore.service, systemd-pstore - Un service pour archiver le contenu de pstore

SYNTAXE

/usr/lib/systemd/systemd-pstore

systemd-pstore.service

DESCRIPTION

systemd-pstore.service est un service système qui archive le contenu du système de fichiers de stockage persistant Linux, pstore, vers d'autres emplacements de stockage, préservant ainsi les informations existantes contenues dans le pstore et vidant le stockage pstore pour de futurs événements d'erreur.

Linux fournit un système de fichiers de stockage persistant, pstore, qui peut stocker des enregistrements d'erreurs lorsque le noyau plante (ou redémarre ou s'éteint). Ces enregistrements peuvent ensuite être utilisés pour déboguer des problèmes du noyau (actuellement, le noyau stocke la fin du journal du noyau, qui contient également une trace de pile, dans pstore).

Le système de fichiers pstore prend en charge une variété de backends qui correspondent à un stockage persistant, tels que l'ACPI ERST et les variables UEFI. Les backends pstore offrent généralement une quantité de stockage persistant relativement faible, par exemple 64 Ko, qui peut se remplir rapidement et ainsi empêcher les futurs plantages du noyau d'enregistrer des erreurs. Il est donc nécessaire de surveiller et d'extraire le contenu de pstore afin que les futurs problèmes du noyau puissent également enregistrer des informations dans le pstore.

Le service pstore est indépendant du service kdump. Dans les environnements cloud en particulier, les systèmes de fichiers hôtes et invités sont sur des systèmes de fichiers distants (par exemple, iSCSI ou NFS), donc kdump repose (implicitement et/ou explicitement) sur le bon fonctionnement du logiciel *et* du matériel *et* de l'infrastructure réseau. Il peut donc ne pas être possible de capturer un core dump du noyau dans un fichier, car les écritures sur le réseau peuvent ne pas être possibles.

Le backend pstore, en revanche, est complètement local et fournit un moyen de stocker des enregistrements d'erreurs qui survivront à un redémarrage et aideront au débogage post-mortem.

L'exécutable systemd-pstore effectue le travail réel. Lors du démarrage, le fichier pstore.conf est lu et le contenu du répertoire /sys/fs/pstore/ est traité selon les options. Les fichiers pstore sont écrits dans le journal, et éventuellement sauvegardés dans /var/lib/systemd/pstore/.

CONFIGURATION

Le comportement de systemd-pstore est configuré via le fichier de configuration /etc/systemd/pstore.conf et les snippets correspondants /etc/systemd/pstore.conf.d/*.conf, voir pstore.conf(5).

Désactivation du traitement de pstore

Pour désactiver le traitement de pstore par systemd-pstore, définissez

Storage=none

dans pstore.conf(5).

Paramètres du noyau

Le noyau dispose de deux paramètres, /sys/module/kernel/parameters/crash_kexec_post_notifiers et /sys/module/printk/parameters/always_kmsg_dump, qui contrôlent les écritures dans pstore. Le premier permet le stockage du journal du noyau (y compris la trace de pile) dans pstore lors d'une panique ou d'un crash, et le second permet le stockage du journal du noyau lors d'un arrêt normal (arrêt, redémarrage, halt). Ces paramètres peuvent être gérés via le mécanisme tmpfiles.d(5), spécifiquement le fichier /usr/lib/tmpfiles/systemd-pstore.conf.

UTILISATION

Les données stockées dans le journal peuvent être consultées avec journalctl(1) comme d'habitude.
