NOM

systemd-pcrlock, systemd-pcrlock-file-system.service, systemd-pcrlock-firmware-code.service, systemd-pcrlock-firmware-config.service, systemd-pcrlock-machine-id.service, systemd-pcrlock-make-policy.service, systemd-pcrlock-secureboot-authority.service, systemd-pcrlock-secureboot-policy.service - Analyser et prédire les états PCR de TPM2 et générer une politique d'accès à partir de la prédiction

SYNTAXE

/usr/lib/systemd/systemd-pcrlock [OPTIONS...]

DESCRIPTION

Note : cette commande est expérimentale pour l'instant. Bien qu'elle devienne probablement un composant régulier de systemd, son comportement et son interface peuvent encore changer.

systemd-pcrlock est un outil qui peut être utilisé pour analyser et prédire les mesures PCR de TPM2, et générer des politiques d'accès TPM2 à partir de la prédiction, qu'il stocke dans un index NV de TPM2 (c'est-à-dire dans la mémoire non volatile de TPM2). Ceci peut ensuite être utilisé pour restreindre l'accès aux objets TPM2 (tels que les clés de chiffrement de disque) aux démarrages système pour lesquels seuls des composants spécifiques et approuvés sont utilisés.

systemd-pcrlock utilise comme entrées pour son analyse et sa prédiction :

•Le journal des événements TPM2 du firmware UEFI (c'est-à-dire /sys/kernel/security/tpm0/binary_bios_measurements) du démarrage actuel.
•Le journal des événements TPM2 de l'espace utilisateur (c'est-à-dire /run/log/systemd/tpm2-measure.log) du démarrage actuel.
•L'état actuel des PCR de la puce TPM2.
•Des fichiers de définition de composants de démarrage (*.pcrlock et *.pcrlock.d/*.pcrlock, voir systemd.pcrlock(5)) qui définissent chacun les mesures attendues pour un composant du processus de démarrage, autorisant des variantes alternatives pour chacun. (Les variantes peuvent être utilisées pour bénir plusieurs versions de noyau ou de chargeur de démarrage en même temps.)

Il utilise ces entrées pour générer un journal d'événements combiné, le validant par rapport aux états des PCR. Il tente ensuite de reconnaître les enregistrements du journal d'événements et les associe aux composants définis. Pour chaque PCR pour laquelle cela peut être fait de manière exhaustive (c'est-à-dire où tous les enregistrements listés et tous les composants définis ont été associés), cela peut alors être utilisé pour prédire les futures mesures PCR, en tenant compte des variantes alternatives définies pour chaque composant. Cette prédiction peut ensuite être convertie en une politique d'accès TPM2 (composée d'éléments TPM2 PolicyPCR et PolicyOR), qui est ensuite stockée dans un index NV du TPM2. Ceci peut être utilisé pour verrouiller des secrets (tels que des clés de chiffrement de disque) à ces politiques (via une politique TPM2 PolicyAuthorizeNV).

Utilisez des outils tels que systemd-cryptenroll(1) ou systemd-repart(8) pour lier le chiffrement de disque à une telle politique TPM2 de systemd-pcrlock. Spécifiquement, voir les options --tpm2-pcrlock= de ces outils.

La logique de politique d'accès nécessite un appareil TPM2 qui implémente la commande "PolicyAuthorizeNV", c'est-à-dire qui implémente TPM 2.0 version 1.38 ou plus récente.

COMMANDES

Les commandes suivantes sont comprises :

log

Lit le journal d'événements TPM2 combiné, le valide, l'associe aux valeurs PCR actuelles, et affiche les deux sous forme de tableau. Combinez avec --json= pour générer une sortie au format JSON.

Ajouté en version 255.

cel

Lit le journal d'événements TPM2 combiné et l'écrit sur STDOUT au format TCG Canonical Event Log Format (CEL-JSON)[1].

Ajouté en version 255.

list-components

Affiche une liste des définitions de composants et de leurs variantes, c'est-à-dire les fichiers *.pcrlock découverts dans /var/lib/pcrlock.d/, /usr/lib/pcrlock.d/, et les autres répertoires pris en charge. Voir systemd.pcrlock(5) pour les détails sur ces fichiers et la liste complète des répertoires recherchés.

Ajouté en version 255.

predict

Prédit l'état des PCR lors des futurs démarrages. Ceci analysera le journal d'événements TPM2 comme décrit ci-dessus, reconnaîtra les composants, et générera ensuite toutes les valeurs PCR résultantes possibles pour toutes les combinaisons de variantes de composants. Notez qu'aucune prédiction n'est faite pour les PCR dont la valeur ne correspond pas aux enregistrements du journal d'événements, pour lesquels des mesures non reconnues sont découvertes, ou pour lesquels des composants sont définis mais ne peuvent pas être trouvés dans le journal d'événements. C'est une mesure de sécurité pour garantir qu'une politique d'accès générée puisse être correctement satisfaite lors des démarrages actuels et futurs.

Ajouté en version 255.

make-policy

Prédit l'état des PCR pour les futurs démarrages, tout comme la commande predict ci-dessus. Elle utilise ensuite ces données pour générer une politique d'accès TPM2 qu'elle stocke dans un index NV de TPM2. La prédiction et les informations sur le TPM2 utilisé et son index NV sont écrites dans /var/lib/systemd/pcrlock.json.

L'index NV est alloué lors de la première invocation, et mis à jour lors des invocations ultérieures.

Le contenu de l'index NV peut être modifié (et donc la politique qui y est stockée mise à jour) en fournissant un code PIN d'accès. Ce code PIN est normalement généré automatiquement et stocké sous forme chiffrée (avec une politique d'accès le liant à l'index NV lui-même) dans le fichier de politique JSON susmentionné. Ce code PIN peut être choisi par l'utilisateur, via le commutateur --recovery-pin=. S'il est spécifié, il peut être utilisé comme chemin d'accès alternatif pour mettre à jour la politique.

Si la nouvelle prédiction correspond à l'ancienne, cette commande se termine rapidement et n'exécute aucune autre opération. (Sauf si --force est spécifié, voir ci-dessous.)

À partir de la v256, une copie du fichier de politique /var/lib/systemd/pcrlock.json est encodée dans un identifiant (voir systemd-creds(1) pour les détails) et écrite sur la partition système EFI ou la partition XBOOTLDR, dans le sous-répertoire /loader/credentials/. Là, elle est récupérée au démarrage par systemd-stub(7) et transmise à l'initrd invité, où elle peut être utilisée pour déverrouiller le système de fichiers racine (qui contient généralement /var/, où se trouve la copie principale de la politique, qui ne peut donc pas être utilisée pour déverrouiller le système de fichiers racine). Le fichier d'identifiant est nommé d'après le jeton d'entrée de démarrage de l'installation (voir bootctl(1)), qui est configurable via le commutateur --entry-token=, voir ci-dessous.

Ajouté en version 255.

remove-policy

Supprime une politique générée précédemment. Supprime le fichier /var/lib/systemd/pcrlock.json et désalloue l'index NV.

Ajouté en version 255.

is-supported

Vérifie si le TPM2 local prend en charge toutes les fonctionnalités pour que systemd-pcrlock fonctionne correctement. Ceci effectue des tests similaires à systemd-analyze has-tpm2, mais vérifie également la prise en charge des opérations TPM2 requises par systemd-pcrlock. Affiche l'une des valeurs : "no", "partial" (si certaines parties du support TPM2 sont disponibles matériellement, via le firmware ou l'OS, mais pas complètement), "obsolete" (si le support TPM2 est disponible matériellement, via le firmware et l'OS, mais que les opérations requises pour systemd-pcrlock sont manquantes), "yes". Retourne un code de sortie de zéro si un support complet est disponible, sinon un code non nul.

Si combiné avec --quiet, supprime l'affichage de la chaîne.

Actuellement, ceci vérifie la prise en charge de la commande TPM2 PolicyAuthorizeNV, ainsi que la prise en charge de l'algorithme de hachage SHA-256.

Ajouté en version 258.

Ceci est similaire à lock-firmware-code/unlock-firmware-code mais verrouille la configuration du micrologiciel, c'est-à-dire les PCR 1 (« platform-config ») et 3 (« external-config »).

--pcr=

Spécifie le numéro de PCR à utiliser. Peut être spécifié plusieurs fois pour sélectionner plusieurs PCR.

Ceci est utilisé par lock-raw et lock-pe pour sélectionner le PCR à verrouiller.

Si utilisé avec predict et make-policy, cela remplacera les PCR à inclure dans la prédiction et la politique. S'il n'est pas spécifié, la valeur par défaut est les PCR 0-5, 7, 11-15. Notez que ces commandes n'incluront aucun PCR dans la prédiction/politique (même s'ils sont spécifiés explicitement) s'il existe des mesures dans le journal des événements qui ne correspondent pas à la valeur actuelle du PCR, ou s'il existe des mesures non reconnues dans le journal des événements, ou si des composants définissent des mesures non vues dans le journal des événements.

Ajouté dans la version 255.

--nv-index=

Spécifie l'index NV où stocker la politique. Pris en compte par make-policy. S'il n'est pas spécifié, la commande choisira automatiquement un index NV libre.

Ajouté dans la version 255.

--components=

Prend un chemin pour lire les fichiers *.pcrlock et *.pcrlock.d/*.pcrlock. Peut être utilisé plusieurs fois pour spécifier plusieurs répertoires. S'il n'est pas spécifié, la valeur par défaut est /etc/pcrlock.d/, /run/pcrlock.d/, /var/lib/pcrlock.d/, /usr/local/lib/pcrlock.d/, /usr/lib/pcrlock.d/.

Ajouté dans la version 255.

--location=

Prend soit une chaîne, soit une paire de chaînes séparées par des deux-points. Configure jusqu'à quel point dans la liste triée des composants définis analyser/prédire les PCR. Typiquement, l'outil systemd-pcrlock est invoqué à partir d'un système entièrement démarré après le démarrage et avant l'arrêt. Cela signifie que divers composants définis pour l'arrêt n'ont pas encore été mesurés et ne doivent pas être recherchés. Cette option permet de restreindre les composants à considérer pour l'analyse (en ne prenant en compte que les composants avant un certain point, en ignorant ceux après). La chaîne attendue est ordonnée par rapport aux noms de fichiers des composants définis. Tous les composants dont le nom est lexicographiquement postérieur sont ignorés. Cette logique s'applique aux verbes log, predict et make-policy. Si une paire de chaînes séparées par des deux-points est spécifiée, elle sélectionne les phases de démarrage à inclure dans la prédiction/politique. La première chaîne définit le point de départ de la première prédiction, et la seconde chaîne définit le point de fin de la dernière prédiction. Toutes ces prédictions sont ensuite combinées en un seul ensemble.

Si utilisé avec list-components, la plage de localisation sélectionnée sera mise en évidence dans la liste des composants.

Par défaut, la valeur est « 760-:940- », ce qui signifie que les politiques générées par défaut couvriront essentiellement toute la durée de vie de l'espace utilisateur du système d'exploitation, de l'initrd (car « 760- » suit de près 750-enter-initrd.pcrlock) jusqu'à (et y compris) l'exécution principale du système (car « 940- » est suivi de près par 950-shutdown.pcrlock). Voir systemd.pcrlock(5) pour une liste complète des composants bien connus, qui illustrent où cette plage est placée par défaut.

Ajouté dans la version 255.

NAME

systemd-pcrlock-firmware-config.service - integrate PCR values into firmware configuration

SYNOPSIS

systemd-pcrlock-firmware-config.service

DESCRIPTION

This service is intended to be used by system firmware (like UEFI or Coreboot) to record measurements of boot components (like the firmware itself, bootloader, kernel, initrd) into PCRs (Platform Configuration Registers) of a TPM (Trusted Platform Module). These measurements are cryptographically bound to the PCR values.

The service is invoked by the firmware before it proceeds with the boot process.

It reads the configuration from /etc/systemd/pcrlock.d/ and/or /usr/lib/systemd/pcrlock.d/. For each file ending in .conf, it parses the configuration and invokes systemd-pcrlock(1) to extend the PCRs with the specified measurements.

The PCR values are then stored in the TPM's Non-Volatile (NV) memory. These values may be used later by systemd-cryptenroll(1) or systemd-pcrmachine.service(8) to unlock sensitive data.

For more details on how the measurements are defined and how the PCRs are extended, refer to systemd.pcrlock(5).

COMMANDS

The following commands are understood:

systemd-pcrlock(1)
Commands to manage PCRs and TPM NV indices.

OPTIONS

The following options are understood:

--pcr-value=

Takes a file system path as argument. The content of the file is used as the PCR value to extend. The file is read only once, so it should contain the final PCR value. If this option is not specified, the content of the file specified by --data= is used.

--data=

Takes a file system path as argument. The content of the file is used as the data to extend the PCR with. This option is only relevant if --pcr-value= is not used. If neither is specified, the command attempts to read the data from standard input.

--pcr-index=

Specifies the PCR index (0-23) to extend. If not specified, defaults to 10.

--tpm-device=

Specifies the TPM device node. Defaults to /dev/tpmrm0.
