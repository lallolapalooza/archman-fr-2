NOM

strelaysrv - Serveur de relais Syncthing

SYNTAXE

OPTIONS

-debug
Activer la sortie de débogage.
-ext-address=<adresse>
Une adresse optionnelle à annoncer comme étant disponible. Permet d'écouter sur un port non privilégié avec redirection de port depuis, par exemple, 443, et d'être connecté sur le port 443.
-global-rate=<octets/s>
Limitation globale du débit, en octets/s.
-keys=<rép>
Répertoire où sont stockés cert.pem et key.pem (par défaut “.”).
-listen=<addr d'écoute>
Adresse d'écoute du protocole (par défaut “:22067”).
-message-timeout=<durée>
Temps maximum d'attente des messages pertinents (par défaut 1m0s).
-nat
Utiliser UPnP/NAT-PMP pour acquérir une cartographie de port externe
-nat-lease=<durée>
Durée du bail NAT en minutes (par défaut 60)
-nat-renewal=<durée>
Fréquence de renouvellement NAT en minutes (par défaut 30)
-nat-timeout=<durée>
Délai de découverte NAT en secondes (par défaut 10)
-network-timeout=<durée>
Délai d'attente pour les opérations réseau entre le client et le relais. Si aucune donnée n'est reçue entre le client et le relais pendant cette période, la connexion est terminée. De plus, si aucune donnée n'est envoyée entre les clients relayés pendant cette période, la session est également terminée. (par défaut 2m0s)
-per-session-rate=<octets/s>
Limitation du débit par session, en octets/s.
-ping-interval=<durée>
Fréquence d'envoi des pings (par défaut 1m0s).
-pools=<adresses de pools>
Liste séparée par des virgules des adresses des pools de relais à rejoindre (par défaut “https://relays.syncthing.net/endpoint”). Vide pour désactiver l'annonce à un pool, restant ainsi un relais privé.
-pprof
Activer le profilage intégré sur le serveur de statut
-protocol=<chaîne>
Protocole utilisé pour l'écoute. ‘tcp’ pour IPv4 et IPv6, ‘tcp4’ pour IPv4, ‘tcp6’ pour IPv6 (par défaut “tcp”).
-provided-by=<chaîne>
Une description optionnelle de qui fournit le relais.
-status-srv=<addr d'écoute>
Adresse d'écoute pour le service de statut (vide pour désactiver) (par défaut “:22070”). Le service de statut est utilisé par l'interface utilisateur du serveur de pool de relais pour afficher les statistiques (données transférées, nombre de clients, etc.)
-token=<chaîne>
Jeton pour restreindre l'accès au relais (facultatif). Désactive la jointure à n'importe quel pool.
-version
Afficher la version

Installation

MISE EN PLACE

Principalement, vous devez décider d'un répertoire pour stocker la clé TLS et le certificat, ainsi qu'un port d'écoute. Le port d'écoute par défaut de 22067 convient, mais pour une compatibilité optimale, un port bien connu pour le trafic chiffré comme 443 est recommandé. Cela peut nécessiter une configuration supplémentaire pour fonctionner sans s'exécuter en tant que root ou utilisateur privilégié, voir Exécution sur le port 443 en tant qu'utilisateur non privilégié ci-dessous. En principe, quelque chose de similaire à ceci devrait fonctionner sur un système Linux/Unix :

$ sudo useradd strelaysrv
$ sudo mkdir /etc/strelaysrv
$ sudo chown strelaysrv /etc/strelaysrv
$ sudo -u strelaysrv /usr/local/bin/strelaysrv -keys /etc/strelaysrv

Ceci crée un utilisateur strelaysrv et un répertoire /etc/strelaysrv pour stocker les clés. Les clés sont générées au premier démarrage. Le relais rejoindra le pool de relais global, à moins qu'un argument -pools="" ne soit donné.

Pour que le serveur de relais démarre automatiquement au démarrage, utilisez la procédure recommandée pour votre système d'exploitation.

Configuration du client

Syncthing peut être configuré pour utiliser des serveurs de relais spécifiques (exclusivement du pool public) en ajoutant les serveurs requis au champ Adresse d'écoute du protocole Sync, sous Actions et Paramètres. Le format est le suivant :

relay://<nom d'hôte|IP>[:port]/?id=<ID du périphérique relais>

Par exemple :

relay://private-relay-1.exam

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ple.com:443/?id=ITZRNXE-YNROGBZ-HXTH5P7-VK5NYE5-QHRQGE2-7JQ6VNJ-KZUEDIU-5PPR5AM

L'ID de l'appareil du relais est affiché au démarrage.

Exécution sur le port 443 en tant qu'utilisateur non privilégié

Il est recommandé d'exécuter le relais sur le port 443 (ou un autre port couramment autorisé par les pare-feux d'entreprise), afin de maximiser les chances de connexion. Cependant, la liaison aux ports inférieurs à 1024 nécessite des privilèges root, et l'exécution d'un relais en tant que root n'est pas recommandée. Heureusement, plusieurs approches s'offrent à vous.

Une option consiste à exécuter le relais sur le port 22067 et à utiliser une règle iptables pour transférer le trafic du port 443 vers le port 22067, par exemple :

iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 22067

Ou, si vous utilisez ufw, ajoutez ce qui suit à /etc/ufw/before.rules :

*nat
:PREROUTING ACCEPT [0:0]
:POSTROUTING ACCEPT [0:0]
-A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 22067
COMMIT

Vous devrez démarrer strelaysrv avec -ext-address "":443"". Cela indique à strelaysrv qu'il peut être contacté sur le port 443, même s'il écoute sur le port 22067. Vous devrez également autoriser les ports 443 et 22067 à travers votre pare-feu.

CONSIDÉRATIONS SUR LE PARE-FEU

  • Port de données : 22067/tcp surchargé avec -listen et annoncé avec -ext-address
  • Port de statut : 22070/tcp surchargé avec -status-srv

Règles iptables d'exécution pour autoriser l'accès aux ports par défaut :

iptables -I INPUT -p tcp --dport 22067 -j ACCEPT
iptables -I INPUT -p tcp --dport 22070 -j ACCEPT

Veuillez consulter la documentation de votre distribution Linux pour rendre les règles de pare-feu persistantes.

CONTRÔLE D'ACCÈS POUR LES RELAIS PRIVÉS

Ajouté dans la version 1.22.1.

Les relais privés peuvent être configurés pour n'accepter que les connexions des pairs en possession d'un secret partagé. Pour configurer cela, utilisez l'option -token :

$ strelaysrv -token=monSecretPartagé

Configurez ensuite vos appareils Syncthing pour envoyer le jeton lors de la connexion au relais :

relay://<nom d'hôte|IP>[:port]/?id=<ID de l'appareil relais>&token=monSecretPartagé
