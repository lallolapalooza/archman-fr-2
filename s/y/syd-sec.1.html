SYD-SEC(1) Manuel des commandes générales SYD-SEC(1)

NOM

syd-sec - Affiche les bits de sécurité ou exécute une commande avec les bits de sécurité définis

SYNOPIS

syd-sec [-ahikprsxAIKPRSX] {commande [arguments...]}

DESCRIPTION

Sans arguments, affiche des informations sur les bits de sécurité du processus au format JSON compact.

Sans commande, une ou plusieurs des options de bits de sécurité [-aikprsx] peuvent être utilisées pour tester les bits de sécurité. Utilisez les options en lettres capitales, [-AIKPRSX], pour tester les versions verrouillées des bits de sécurité respectifs.

Avec une commande et des arguments, et au moins une des options de bits de sécurité [-aikprsxAIKRSX] définie, définit les bits de sécurité spécifiés, exécute la commande et quitte avec le même statut.

OPTIONS

-h Affiche l'aide et quitte.
-p, -P Définit/teste l'attribut no_new_privs du processus.
-r, -R Définit/teste le bit de sécurité SECBIT_NOROOT.
-s, -S Définit/teste le bit de sécurité SECBIT_NO_SETUID_FIXUP.
-k, -K Définit/teste le bit de sécurité SECBIT_KEEP_CAPS.
-a, -A Définit/teste le bit de sécurité SECBIT_NO_CAP_AMBIENT_RAISE.
-x, -X Définit/teste le bit de sécurité SECBIT_EXEC_RESTRICT_FILE.
-i, -I Définit/teste le bit de sécurité SECBIT_EXEC_DENY_INTERACTIVE.

BITS DE SÉCURITÉ

Bit de sécurité Description CAP_SETPCAP requis ?
NO_NEW_PRIVS Lorsqu'il est défini, execve(2) n'accordera pas de nouveaux privilèges (par exemple, les bits de mode set-user-ID/set-group-ID et les capacités de fichier sont ignorés). Hérité via fork(2), clone(2) et execve(2) ; une fois défini, ne peut pas être désactivé. Non
NOROOT Désactive le traitement spécial de l'UID 0 pour obtenir des capacités lors de l'exécution/setuid. NOROOT_LOCKED est un verrou pour NOROOT (empêche les changements supplémentaires ; irréversible). Oui
NO_SETUID_FIXUP Arrête les ajustements du noyau sur les ensembles de capacités autorisées/effectives/ambiantes lorsque les UID effectifs/du système de fichiers basculent entre 0 et non nul. NO_SETUID_FIXUP_LOCKED est un verrou pour NO_SETUID_FIXUP (empêche les changements supplémentaires ; irréversible). Oui
KEEP_CAPS Permet de conserver les capacités autorisées lors du passage de tous les UID de 0 à non nuls ; toujours effacé lors de execve(2). KEEP_CAPS_LOCKED est un verrou pour KEEP_CAPS (empêche les changements supplémentaires ; irréversible). Oui
NO_CAP_AMBIENT_RAISE Interdit l'augmentation des capacités ambiantes via prctl(PR_CAP_AMBIENT_RAISE). NO_CAP_AMBIENT_RAISE_LOCKED est un verrou pour NO_CAP_AMBIENT_RAISE (empêche les changements supplémentaires ; irréversible). Oui
EXEC_RESTRICT_FILE L'interpréteur/lieur dynamique ne doit exécuter un fichier que si execveat(2) avec AT_EXECVE_CHECK sur le descripteur de fichier associé réussit. EXEC_RESTRICT_FILE_LOCKED est un verrou pour EXEC_RESTRICT_FILE (empêche les changements supplémentaires ; irréversible). Non
EXEC_DENY_INTERACTIVE L'interpréteur ne doit pas accepter les commandes interactives de l'utilisateur ; le contenu via un descripteur de fichier n'est autorisé que si execveat(2) avec AT_EXECVE_CHECK réussit. EXEC_DENY_INTERACTIVE_LOCKED est un verrou pour EXEC_DENY_INTERACTIVE (empêche les changements supplémentaires ; irréversible). Non

STATUT DE SORTIE

Lors de l'interrogation des bits de sécurité, syd-sec se termine avec succès si tous les bits de sécurité spécifiés sont définis dans les bits de sécurité du processus. Lors de l'exécution d'une commande, syd-sec se termine avec le même code que le processus enfant. Si l'opération PR_SET_SECUREBITS(2const) prctl(2) échoue avant l'exécution de la commande, syd-sec se termine avec errno(3).
