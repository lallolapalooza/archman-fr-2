SYSTEMD-FIRSTBOOT(1) systemd-firstboot SYSTEMD-FIRSTBOOT(1)

NOM

systemd-firstboot, systemd-firstboot.service - Initialise les paramètres système de base lors du premier démarrage ou avant celui-ci.

SYNTAXE

systemd-firstboot [OPTIONS...]

systemd-firstboot.service

DESCRIPTION

L'unité systemd-firstboot.service fait partie des unités utilisées pour initialiser la configuration de la machine lors du « Premier Démarrage », c'est-à-dire lorsqu'un système est fraîchement installé ou après une réinitialisation d'usine. Le gestionnaire systemd(1) lui-même initialise le machine-id(5) et préconfigure toutes les unités, en les activant ou désactivant selon les paramètres de systemd.preset(5). systemd-firstboot.service est démarré plus tard pour initialiser interactivement la configuration système de base. Il n'est démarré que si ConditionFirstBoot=yes est remplie, ce qui signifie essentiellement que /etc/ est vide, voir systemd.unit(5) pour plus de détails. Les identifiants système peuvent être utilisés pour injecter la configuration ; ces paramètres ne sont pas interrogés interactivement.

La commande systemd-firstboot peut également être utilisée pour initialiser de manière non interactive une image système hors ligne.

Les paramètres suivants peuvent être configurés :

•L'ID machine du système
•La locale du système, plus spécifiquement les deux variables de locale LANG= et LC_MESSAGES
•Le mappage clavier du système
•Le fuseau horaire du système
•Le nom d'hôte du système
•La ligne de commande du noyau utilisée lors de l'installation des images de noyau
•Le mot de passe et le shell de l'utilisateur root

Chacun des champs peut être interrogé interactivement par les utilisateurs, défini de manière non interactive sur la ligne de commande de l'outil, ou copié à partir d'un système hôte utilisé pour configurer l'image système.

Si un paramètre est déjà initialisé, il ne sera pas écrasé et l'utilisateur ne sera pas invité à le définir.

Notez que cet outil opère directement sur le système de fichiers et n'implique aucun service système en cours d'exécution, contrairement à localectl(1), timedatectl(1) ou hostnamectl(1). Cela permet à systemd-firstboot d'opérer sur des images disque montées mais non démarrées et lors des premières étapes du démarrage. Il est déconseillé d'utiliser systemd-firstboot sur le système en cours d'exécution une fois qu'il a été configuré.

OPTIONS

Les options suivantes sont comprises :

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés par le chemin racine alternatif donné, y compris les chemins de recherche de configuration. Ceci est utile pour opérer sur une image système montée dans le répertoire spécifié au lieu du système hôte lui-même.

Ajouté dans la version 216.

--image=chemin

Prend un chemin vers un fichier d'image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur des systèmes de fichiers stockés dans des images disque ou des périphériques bloc. L'image disque doit contenir uniquement un système de fichiers ou un ensemble de systèmes de fichiers au sein d'une table de partitions GPT, suivant la Spécification des partitions découvrables[1]. Pour plus d'informations sur les images disque supportées, voir le commutateur du même nom dans systemd-nspawn(1).

Ajouté dans la version 246.

--locale=LOCALE, --locale-messages=LOCALE

Définit la locale du système, plus spécifiquement les paramètres LANG= et LC_MESSAGES. L'argument doit être un identifiant de locale valide, tel que « de_DE.UTF-8 ». Ceci contrôle le fichier de configuration locale.conf(5).

Ajouté dans la version 216.

--keymap=KEYMAP

Définit la disposition du clavier du système. L'argument doit être une carte de clavier valide, telle que « de-latin1 ». Ceci contrôle l'entrée « KEYMAP » dans le fichier de configuration vconsole.conf(5).

Ajouté dans la version 236.

--timezone=TIMEZONE

Définit le fuseau horaire du système. L'argument doit être un identifiant de fuseau horaire valide, tel que « Europe/Berlin ». Ceci contrôle le lien symbolique localtime(5).

Ajouté dans la version 216.

--hostname=HOSTNAME

Définit le nom d'hôte du système. L'argument doit être un nom d'hôte compatible avec le DNS. Ceci contrôle le fichier de configuration hostname(5).

Ajouté dans la version 216.

--setup-machine-id

Initialise l'ID machine du système à un ID aléatoire. Ceci contrôle le fichier machine-id(5).

Cette option ne fonctionne qu'en combinaison avec --root= ou --image=. Sur un système en cours d'exécution, machine-id est écrit par le gestionnaire avec l'aide de systemd-machine-id-commit.service(8).

Ajouté dans la version 216.

--machine-id=ID

Définit l'ID machine du système à la valeur spécifiée. Les mêmes restrictions s'appliquent qu'à --setup-machine-id.

Ajouté dans la version 216.

--root-password=PASSWORD, --root-password-file=CHEMIN, --root-password-hashed=HASHED_PASSWORD

Définit le mot de passe de l'utilisateur root du système. Ceci crée/modifie les fichiers passwd(5) et shadow(5). Ce paramètre existe sous trois formes : --root-password= accepte le mot de passe à définir directement sur la ligne de commande, --root-password-file= le lit à partir d'un fichier et --root-password-hashed= accepte un mot de passe déjà haché sur la ligne de commande. Voir shadow(5) pour plus d'informations sur le format du mot de passe haché. Notez qu'il n'est pas recommandé de spécifier des mots de passe en clair sur la ligne de commande, car d'autres utilisateurs pourraient les voir en invoquant simplement ps(1).

Ajouté dans la version 216.

--root-shell=SHELL

Définit le shell de l'utilisateur root du système. Ceci crée/modifie le fichier passwd(5).

Ajouté dans la version 246.

--kernel-command-line=CMDLINE

Définit la ligne de commande du noyau du système. Ceci contrôle le fichier /etc/kernel/cmdline utilisé par kernel-install(8).

Ajouté dans la version 246.

--prompt-locale, --prompt-keymap, --prompt-timezone, --prompt-hostname, --prompt-root-password, --prompt-root-shell

Demande interactivement à l'utilisateur un réglage de base spécifique. Notez que tous les réglages de configuration explicites spécifiés sur la ligne de commande ont la priorité, et que l'utilisateur n'est pas invité pour ceux-ci.

Ajouté dans la version 216.

--prompt

Interroge l'utilisateur pour la locale, le mappage clavier, le fuseau horaire, le nom d'hôte, le mot de passe root et le shell root. Ceci équivaut à spécifier --prompt-locale, --prompt-keymap, --prompt-timezone, --prompt-hostname, --prompt-root-password, --prompt-root-shell en combinaison.

Ajouté dans la version 216.

--copy-locale, --copy-keymap, --copy-timezone, --copy-root-password, --copy-root-shell

Copie un réglage de base spécifique de l'hôte. Ceci ne fonctionne qu'en combinaison avec --root= ou --image=.

Ajouté dans la version 216.

--copy

Copie la locale, le mappage clavier, le fuseau horaire, le mot de passe root et le shell de l'hôte. Ceci équivaut à spécifier --copy-locale, --copy-keymap, --copy-timezone, --copy-root-password, --copy-root-shell en combinaison.

Ajouté dans la version 216.

--force

Écrire la configuration même si les fichiers pertinents existent déjà. Sans cette option, systemd-firstboot ne modifie ni ne remplace les fichiers existants. Notez que lors de la configuration du compte root, même avec cette option, systemd-firstboot ne modifie que l'entrée de l'utilisateur « root », laissant les autres entrées dans /etc/passwd et /etc/shadow intactes.

Ajouté dans la version 246.

--reset

Si spécifié, tous les fichiers existants configurés par systemd-firstboot sont supprimés. Notez que les fichiers sont supprimés indépendamment de la configuration d'une nouvelle valeur ou non. Cette opération garantit que le prochain démarrage de l'image sera considéré comme un premier démarrage, et systemd-firstboot demandera à nouveau la configuration de chacun des fichiers supprimés.

Ajouté dans la version 254.

--delete-root-password

Supprime le mot de passe de l'utilisateur root du système, permettant de se connecter en tant que root sans mot de passe, sauf si le compte root est verrouillé. Notez que ceci est extrêmement peu sûr et que cette option ne doit donc pas être utilisée à la légère.

Ajouté dans la version 246.

--welcome=

Accepte un argument booléen. Par défaut, lorsque l'on demande à l'utilisateur des options de configuration, un bref texte de bienvenue est affiché avant la première question. Passez false à cette option pour désactiver le texte de bienvenue.

Ajouté dans la version 246.

-h, --help

Affiche un bref message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

IDENTIFIANTS

systemd-firstboot prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour plus de détails). Les identifiants suivants sont utilisés lorsqu'ils sont transmis :

passwd.hashed-password.root, passwd.plaintext-password.root

Une version hachée ou en texte brut du mot de passe root à utiliser, à la place de la demande à l'utilisateur. Ces identifiants sont équivalents à ceux définis pour le service systemd-sysusers.service(8).

Ajouté dans la version 249.

passwd.shell.root

Spécifie le binaire de shell à utiliser pour le compte spécifié. Équivalent à l'identifiant du même nom défini pour le service systemd-sysusers.service(8).

Ajouté dans la version 249.

firstboot.locale, firstboot.locale-messages

Ces identifiants spécifient les paramètres régionaux à définir lors du premier démarrage, à la place de la demande à l'utilisateur.

Ajouté dans la version 249.

firstboot.keymap

Cet identifiant spécifie le paramètre du clavier à définir lors du premier démarrage, à la place de la demande à l'utilisateur.

Notez la relation avec l'identifiant vconsole.keymap compris par systemd-vconsole-setup.service(8) : les deux affectent finalement le même paramètre, mais firstboot.keymap est écrit dans /etc/vconsole.conf lors du premier démarrage (s'il n'est pas déjà configuré), puis lu à partir de là par systemd-vconsole-setup, tandis que vconsole.keymap est lu à chaque démarrage, et n'est pas persistant sur le disque (mais toute configuration dans vconsole.conf aura la priorité si elle est présente).

Ajouté dans la version 249.

firstboot.timezone

Cet identifiant spécifie le paramètre du fuseau horaire du système à définir lors du premier démarrage, à la place de la demande à l'utilisateur.

Ajouté dans la version 249.

Notez que par défaut, le fichier unit systemd-firstboot.service est configuré pour hériter des identifiants listés du gestionnaire de service. Ainsi, lors de l'invocation d'un conteneur avec un /etc/ non peuplé pour la première fois, il est possible de configurer le mot de passe de l'utilisateur root à « systemd » comme suit :

# systemd-nspawn --image=... --set-credential=firstboot.locale:de_DE.UTF-8 ...

Notez que ces identifiants ne sont lus et appliqués que lors du premier démarrage. Une fois appliqués, ils restent en vigueur pour les démarrages suivants, et les identifiants ne sont plus pris en compte.

CODE DE RETOUR

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

LIGNE DE COMMANDE DU NOYAU

systemd.firstboot=

Accepte un argument booléen, par défaut activé. Si désactivé, systemd-firstboot.service n'interrogera pas interactivement l'utilisateur pour les paramètres de base lors du premier démarrage, même si ces paramètres ne sont pas encore initialisés.

Ajouté dans la version 233.
