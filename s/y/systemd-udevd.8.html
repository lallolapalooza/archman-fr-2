SYSTEMD-UDEVD.SERVICE(8) systemd-udevd.service SYSTEMD-UDEVD.SERVICE(8)

NOM

systemd-udevd.service, systemd-udevd-control.socket, systemd-udevd-kernel.socket, systemd-udevd-varlink.socket, systemd-udevd - Démon de gestion des événements de périphériques

SYNOPIS

systemd-udevd.service

systemd-udevd-control.socket

systemd-udevd-kernel.socket

systemd-udevd-varlink.socket

/usr/lib/systemd/systemd-udevd [--daemon] [--debug] [--children-max=] [--exec-delay=] [--event-timeout=] [--resolve-names=early|late|never] [--version] [--help]

DESCRIPTION

systemd-udevd écoute les événements uevent du noyau. Pour chaque événement, systemd-udevd exécute les instructions correspondantes spécifiées dans les règles udev. Voir udev(7).

Le comportement du démon peut être configuré à l'aide de udev.conf(5), de ses options de ligne de commande, des variables d'environnement, et sur la ligne de commande du noyau, ou modifié dynamiquement avec udevadm control.

OPTIONS

-d, --daemon

Se détacher et s'exécuter en arrière-plan.

Ajouté dans la version 186.

-D, --debug

Afficher les messages de débogage sur la sortie d'erreur standard.

Ajouté dans la version 186.

-c, --children-max=

Limiter le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

-e, --exec-delay=

Retarder l'exécution de chaque paramètre RUN{{program}} du nombre de secondes donné. Cette option peut être utile lors du débogage des pannes système pendant le coldplug causées par le chargement de modules du noyau non fonctionnels.

Ajouté dans la version 186.

-t, --event-timeout=

Définir le nombre de secondes à attendre pour que les événements se terminent. Après ce délai, l'événement sera terminé. La valeur par défaut est 180 secondes.

Ajouté dans la version 216.

-s, --timeout-signal=

Définir le signal que systemd-udevd enverra aux processus créés après avoir atteint le délai d'événement. Le réglage peut être remplacé au démarrage avec l'option de ligne de commande du noyau udev.timeout_signal=. Définir sur SIGABRT peut être utile pour déboguer les timeouts des workers. La valeur par défaut est SIGKILL. Notez que la définition de l'option sur la ligne de commande remplace le réglage du fichier de configuration.

Ajouté dans la version 246.

-N, --resolve-names=

Spécifier quand systemd-udevd doit résoudre les noms des utilisateurs et des groupes. Lorsqu'il est réglé sur early (la valeur par défaut), les noms seront résolus lors de l'analyse des règles. Lorsqu'il est réglé sur late, les noms seront résolus pour chaque événement. Lorsqu'il est réglé sur never, les noms ne seront jamais résolus et tous les périphériques appartiendront à root.

Ajouté dans la version 186.

-h, --help

Afficher un court texte d'aide et quitter.

--version

Afficher une courte chaîne de version et quitter.

LIGNE DE COMMANDE DU NOYAU

Les paramètres préfixés par « rd. » seront lus lorsque systemd-udevd est utilisé dans un initrd, ceux sans préfixe seront traités à la fois dans l'initrd et sur l'hôte.

udev.log_level=, rd.udev.log_level=

Définir le niveau de journalisation.

Ajouté dans la version 247.

udev.trace[=BOOL], rd.udev.trace[=BOOL]

Activer/désactiver la journalisation des traces. Lorsqu'elle est activée, udev.log_level= sera ignoré, et le niveau « debug » sera supposé.

Ajouté dans la version 258.

udev.children_max=, rd.udev.children_max=

Limiter le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

udev.exec_delay=, rd.udev.exec_delay=

Retarder l'exécution de chaque paramètre RUN{{program}} du nombre de secondes donné. Cette option peut être utile lors du débogage des pannes système pendant le coldplug causées par le chargement de modules du noyau non fonctionnels.

Ajouté dans la version 186.

udev.event_timeout=, rd.udev.event_timeout=

Attendre que les événements se terminent jusqu'au nombre de secondes donné. Cette option peut être utile si des événements sont terminés parce que les pilotes du noyau mettent trop de temps à s'initialiser.

Ajouté dans la version 216.

udev.timeout_signal=, rd.udev.timeout_signal=

Spécifie un signal que systemd-udevd enverra aux workers lors du timeout. Notez que l'option de ligne de commande du noyau remplace à la fois le réglage dans le fichier de configuration et celui sur la ligne de commande du programme.

Ajouté dans la version 246.

udev.blockdev_read_only, rd.udev.blockdev_read_only

Si spécifié, marquer tous les périphériques de blocage physiques en lecture seule dès leur apparition. Les périphériques de blocage synthétiques (tels que les périphériques de blocage de boucle ou les périphériques de mappage de périphériques) sont laissés tels quels. Ceci est utile pour garantir que le contenu des périphériques de blocage physiques reste inchangé pendant l'exécution, par exemple pour implémenter des systèmes entièrement sans état, pour des tests ou pour des situations de récupération où des systèmes de fichiers corrompus ne doivent pas être davantage corrompus par une modification accidentelle.

Un périphérique de blocage peut être marqué à nouveau comme inscriptible en exécutant la commande blockdev --setrw, voir blockdev(8) pour plus de détails.

Ajouté dans la version 246.

net.ifnames=

Les interfaces réseau sont renommées pour leur donner des noms prévisibles lorsque c'est possible. Elle est activée par défaut ; spécifier 0 la désactive.

Ajouté dans la version 199.

net.naming_scheme=

Les interfaces réseau sont renommées pour leur donner des noms prévisibles lorsque c'est possible (sauf si net.ifnames=0 est spécifié, voir ci-dessus). Avec cette option de ligne de commande du noyau, il est possible de choisir une version spécifique de cet algorithme et de remplacer celle par défaut choisie au moment de la compilation. Attend l'un des identifiants de schéma de nommage listés dans systemd.net-naming-scheme(7), ou « latest » pour sélectionner le schéma le plus récent connu (par cette version particulière de systemd-udevd.service).

Notez que la sélection d'un schéma spécifique n'est pas suffisante pour stabiliser complètement le nommage des interfaces : le nommage est généralement dérivé des attributs du pilote exposés par le noyau. Lorsque le noyau est mis à jour, des attributs précédemment manquants que systemd-udevd.service vérifie peuvent apparaître, ce qui affecte également les anciens algorithmes de dérivation de noms.

Ajouté dans la version 240.

net.ifname_policy=policy1[,policy2,...][,MAC]

Spécifie les politiques de nommage appliquées lors du renommage des interfaces réseau. Prend une liste de politiques et une adresse MAC optionnelle séparées par des virgules. Chaque valeur de politique doit être l'une des politiques comprises par le réglage NamePolicy= dans les fichiers .link, par exemple « onboard » ou « path ». Voir systemd.link(5) pour plus de détails. Lorsque l'adresse MAC est spécifiée, les politiques sont appliquées à l'interface qui possède cette adresse. Lorsque aucune adresse MAC n'est spécifiée, les politiques sont appliquées à toutes les interfaces. Cet argument de ligne de commande du noyau peut être spécifié plusieurs fois.

Cet argument n'est pas directement lu par systemd-udevd, mais est plutôt converti en un fichier .link par systemd-network-generator.service(8). Pour que cet argument prenne effet, systemd-network-generator.service doit être activé.

Exemple:

net.ifname_policy=keep,kernel,path,slot,onboard,01:23:45:67:89:ab
net.ifname_policy=keep,kernel,path,slot,onboard,mac

Ceci est principalement équivalent à la création des fichiers .link suivants :

# 91-name-policy-with-mac.link
[Match]
MACAddress=01:23:45:67:89:ab
[Link]
NamePolicy=keep kernel path slot onboard
AlternativeNamePolicy=path slot onboard

et

# 92-name-policy-for-all.link
[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel path slot onboard mac
AlternativeNamePolicy=path slot onboard mac

Ajouté dans la version 250.

systemd-udevd.8.en

NAME

systemd-udevd — device event managing daemon

SYNOPSIS

systemd-udevd [ -d ]

DESCRIPTION

The systemd-udevd daemon is the device event manager for the Linux kernel. It listens to kernel uevents, processes them, and dispatches device-specific task. It manages device nodes in /dev/, and symbolic links that define more convenient names for devices.

systemd-udevd uses a set of rules files, read from /etc/udev/rules.d/, /run/udev/rules.d/, and /usr/lib/udev/rules.d/. The rules are evaluated in alphanumerical order.

It handles device events such as hot-plugging and un-plugging of devices. For each event, systemd-udevd determines which rules match the event and executes the corresponding actions. These actions might include creating device nodes, setting permissions, running external programs, and more.

The daemon can be run in the foreground using the -d option, which is useful for debugging.

OPTIONS

systemd-udevd recognizes the following options:

-d
Run in the foreground. In this mode, systemd-udevd will not fork into the background and will print all log messages to the standard error stream.

KERNEL COMMAND LINE

When systemd-udevd is started during the boot process, it may be influenced by kernel command line parameters. For example, setting root=/dev/sdX will cause systemd-udevd to wait for the specified device to appear before proceeding with the boot process. This behaviour is usually handled by systemd-fstab-generator and other systemd generators, which interact with systemd-udevd.

SEE ALSO

udev.conf(5), udev(7), udevadm(8)
