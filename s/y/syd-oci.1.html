NOM

syd-oci - Environnement d'exécution de conteneur OCI

SYNTAXE

syd-oci [OPTIONS] [COMMANDE]

DESCRIPTION

syd-oci est une implémentation d'environnement d'exécution de conteneur OCI pour syd(1).

Toutes les sous-commandes courantes sont prises en charge : create, start, state, kill, delete, pause, resume, exec, run, list, ps, spec, events, features, update. La prise en charge du checkpoint/restore est prévue dans un avenir proche. Voir le problème youki correspondant, https://github.com/youki-dev/youki/issues/142, pour plus d'informations.

INTÉGRATION

syd-oci est un wrapper léger autour de youki(1) qui intègre le sandbox syd(1) dans les conteneurs. Il est compatible avec docker(1) et podman(1). Pour obtenir syd-oci, vous devez compiler syd(1) avec la fonctionnalité oci. Pour utiliser syd-oci avec docker(1), vous avez deux options : Soit démarrer dockerd(8) manuellement avec l'option --add-runtime=syd-oci=/bin/syd-oci, et faire par exemple docker run -it --runtime=syd-oci alpine lors du démarrage des conteneurs, soit ajouter le fragment suivant à votre fichier /etc/docker/daemon.json :

{
"runtimes": { "syd-oci": { "path": "/bin/syd-oci" } },
"default-runtime": "syd-oci"
}

Vous devrez peut-être adapter le chemin vers syd-oci en fonction de votre installation. Pour utiliser avec podman(1), c'est similaire, il suffit de passer --runtime=/bin/syd-oci comme option à podman run.

CONFIGURATION

Le répertoire de configuration de syd-oci est l'un des suivants :

  • Pour les conteneurs à l'échelle du système : /etc/syd/oci
  • Pour les conteneurs sans privilèges (rootless), l'un des suivants :
    - ${XDG_CONFIG_HOME}/syd/oci où XDG_CONFIG_HOME est généralement ~/.config.
    - ${HOME}/.syd/oci si XDG_CONFIG_HOME n'est pas défini.

syd-oci tente de configurer le sandbox syd(1) dans l'ordre suivant, et analyse le premier fichier ou profil qu'il localise et arrête le traitement. La variable d'environnement SYD_OCI_NO_CONFIG peut être définie pour passer directement à l'étape finale :

  • Si le nom d'hôte et le nom de domaine sont définis pour le conteneur, essayez de charger ${SYD_CONFIG_DIR}/${hostname}.${domainname}.syd-3.
  • Si le nom de domaine est défini pour le conteneur, essayez de charger ${SYD_CONFIG_DIR}/${domainname}.syd-3.
  • Si le nom d'hôte est défini pour le conteneur, essayez de charger ${SYD_CONFIG_DIR}/${hostname}.syd-3.
  • Essayez de charger ${SYD_CONFIG_DIR}/default.syd-3
  • Chargez le profil intégré oci. Ce profil est conçu pour être combiné avec pandora(1) et le mode d'apprentissage. Voir syd-cat -p oci pour la liste des règles.

SYD_CONFIG_DIR dans les éléments ci-dessus fait référence au répertoire de configuration. Référez-vous à syd(5) pour la syntaxe des fichiers de configuration syd(1) et à syd(2) pour une liste des éléments de configuration que syd(1) comprend. Un fichier de coloration syntaxique pour vim(1) est également fourni pour éditer facilement les fichiers de configuration syd(1). Utilisez syd-cat file.syd-3 pour vérifier la syntaxe d'un fichier de configuration syd(1).

Enfin, notez que les directives include dans les fichiers de configuration sont recherchées dans l'image du conteneur. Cela vous permet de fournir une configuration de sandbox supplémentaire basée sur l'image. Une utilisation possible pourrait être de stocker des sommes de contrôle cryptographiques de tous les exécutables et de leurs bibliothèques dynamiques dépendantes dans un fichier d'inclusion dans l'image, puis d'utiliser ceci avec le mode Sandbox Forcé pour la vérification des binaires, voir syd(7) pour plus d'informations sur le mode Sandbox Forcé.
