syncthing-networking - Configuration du pare-feu

CONFIGURATION DU ROUTEUR

Redirections de ports

Si vous avez un routeur NAT qui prend en charge l'UPnP, la manière la plus simple d'obtenir une redirection de port fonctionnelle est de vous assurer que le paramètre UPnP est activé sur Syncthing et sur le routeur – Syncthing essaiera de gérer le reste. S'il réussit, vous verrez un message dans la console indiquant :

Created UPnP port mapping for external port XXXXX on UPnP device YYYYY.

Si cela n'est pas possible ou souhaitable, vous devez configurer une redirection de port pour les ports 22000/TCP et 22000/UDP (ou le port configuré dans le paramètre Adresse d'écoute du protocole Sync). Les ports externes redirigés et les ports de destination internes doivent être identiques (par exemple, 22000/TCP).

La communication dans Syncthing fonctionne dans les deux sens. Par conséquent, si vous configurez des redirections de port pour un appareil, les autres appareils pourront s'y connecter même s'ils sont derrière un réseau NAT ou un pare-feu.

En l'absence de redirection de port, le Relais peut fonctionner suffisamment bien pour connecter et synchroniser les appareils, mais ses performances seront inférieures à celles d'une connexion directe.

Découverte locale

Le routeur doit autoriser/rediriger les diffusions/multidiffusions pour que la découverte locale fonctionne. Celles-ci sont généralement autorisées par défaut sur un seul sous-réseau local, mais peuvent être bloquées entre différents sous-réseaux, voire entre un Wi-Fi ponté et le LAN.

Si vous ne parvenez pas à configurer votre routeur ainsi ou votre pare-feu comme indiqué ci-dessous, et que vos appareils ont des adresses IP statiques, vous pouvez les spécifier directement en modifiant le paramètre par défaut dynamic pour Adresses en quelque chose comme : tcp://192.168.1.xxx:22000, dynamic.

PARE FEU LOCAL

Si votre PC dispose d'un pare-feu local, vous devrez ouvrir les ports suivants pour le trafic entrant et sortant :

  • Port 22000/TCP : trafic du protocole de synchronisation basé sur TCP
  • Port 22000/UDP : trafic du protocole de synchronisation basé sur QUIC
  • Port 21027/UDP : pour les diffusions de découverte sur IPv4 et les multidiffusions sur IPv6

Si vous avez configuré un port personnalisé dans le paramètre Adresse d'écoute du protocole Sync, vous devez adapter les règles du pare-feu en conséquence.

Uncomplicated Firewall (ufw)

sudo ufw allow syncthing

Si vous souhaitez également autoriser l'accès externe à l'interface graphique web de Syncthing, exécutez :

sudo ufw allow syncthing-gui

Autoriser l'accès externe n'est pas nécessaire pour une installation typique.

Vous pouvez ensuite vérifier que les ports mentionnés ci-dessus sont autorisés :

Firewalld

sudo firewall-cmd --zone=public --add-service=syncthing --permanent
sudo firewall-cmd --reload

De même, il existe également un service syncthing-gui.

INTERFACE WEB À DISTANCE

Pour pouvoir accéder à l'interface graphique web depuis d'autres ordinateurs, vous devez changer le paramètre Adresse d'écoute de l'interface graphique de la valeur par défaut 127.0.0.1:8384 à 0.0.0.0:8384. Vous devez également ouvrir le port dans votre pare-feu local si vous en avez un.

Tunnelisation via SSH

Si vous avez un accès SSH à la machine exécutant Syncthing mais que vous préférez ne pas ouvrir le port de l'interface graphique web au monde extérieur, vous pouvez y accéder via un tunnel SSH à la place. Vous pouvez démarrer un tunnel avec une commande comme celle-ci :

ssh -L 9999:localhost:8384 machine

Cela se liera à votre port local 9999 et transférera toutes les connexions à partir de là vers le port 8384 sur la machine cible. Cela fonctionne même si Syncthing est configuré pour écouter uniquement sur localhost.

VIA UN PROXY

Syncthing peut utiliser un proxy SOCKS5 pour les connexions sortantes. Veuillez consulter Utilisation des proxys.
