NOM

systemd-debug-generator - Générateur pour activer un shell de débogage à l'exécution et masquer des unités spécifiques au démarrage

SYNTAXE

/usr/lib/systemd/system-generators/systemd-debug-generator

DESCRIPTION

systemd-debug-generator est un générateur qui fournit certaines fonctionnalités de débogage.

systemd-debug-generator implémente systemd.generator(7).

LIGNE DE COMMANDE DU NOYAU

systemd-debug-generator comprend les paramètres de ligne de commande du noyau suivants :

systemd.mask=, rd.systemd.mask=

Ces options prennent le nom d'une unité en argument. L'unité spécifiée est masquée pour l'exécution (c'est-à-dire pour cette session — du démarrage à l'arrêt), de manière similaire à l'effet de la commande mask de systemctl(1). Ceci est utile pour démarrer avec certaines unités retirées de la transaction de démarrage initiale pour le débogage du démarrage du système. Peut être spécifié plusieurs fois. L'option préfixée par « rd. » n'est prise en compte que dans l'initrd, tandis que celle sans préfixe n'est prise en compte que sur l'hôte.

Ajouté dans la version 215.

systemd.wants=, rd.systemd.wants=

Ces options prennent le nom d'une unité en argument. Un travail de démarrage pour cette unité est ajouté à la transaction initiale. Ceci est utile pour démarrer une ou plusieurs unités supplémentaires au démarrage. Peut être spécifié plusieurs fois. L'option préfixée par « rd. » n'est prise en compte que dans l'initrd, tandis que celle non préfixée n'est prise en compte que sur l'hôte.

Ajouté dans la version 215.

systemd.debug_shell, rd.systemd.debug_shell, systemd.default_debug_tty=, rd.systemd.default_debug_tty=

Si l'option systemd.debug_shell ou rd.systemd.debug_shell est spécifiée, le service de shell de débogage « debug-shell.service » est inclus dans la transaction de démarrage et un shell de débogage sera lancé au début du processus de démarrage. Par défaut, /dev/tty9 est utilisé, mais un tty spécifique peut également être spécifié, avec ou sans le préfixe /dev/. Pour définir le tty à utiliser sans activer le shell de débogage, l'option systemd.default_debug_tty= peut être utilisée, qui accepte également un tty avec ou sans le préfixe /dev/. Notez que le shell peut également être activé de manière persistante en l'activant avec la commande enable de systemctl(1). Les options préfixées par « rd. » ne sont prises en compte que dans l'initrd, tandis que celles sans préfixe ne le sont que sur l'hôte.

Ajouté dans la version 215.

systemd.break=, rd.systemd.break=

Prend l'une des valeurs pre-udev, pre-basic, pre-mount, ou pre-switch-root (la valeur par défaut pour l'option « rd. »). Accepte également plusieurs valeurs séparées par une virgule (« , »). Ces options permettent de suspendre le processus de démarrage à un certain point et de lancer un shell de débogage. Après avoir quitté ce shell, le système reprendra son démarrage. L'option préfixée par « rd. » n'est prise en compte que dans l'initrd, tandis que celle sans préfixe ne l'est que sur l'hôte.

Tableau 1. Points d'arrêt disponibles

Points d'arrêt Description Peut être utilisé dans l'initrd Peut être utilisé sur l'hôte
pre-udev Avant de commencer à traiter les uevents du noyau, c'est-à-dire avant le démarrage de systemd-udevd.service. ✓ ✓
pre-basic Avant de quitter le début du démarrage et que les services réguliers ne démarrent, c'est-à-dire avant d'atteindre basic.target. ✓ ✓
pre-mount Avant le montage du système de fichiers racine, c'est-à-dire avant le démarrage de sysroot.mount. ✓ ✗
pre-switch-root Avant de basculer de l'initrd à la racine réelle. ✓ ✗

Ajouté dans la version 258.

IDENTIFIANTS DU SYSTEME

systemd.extra-unit.*

Les identifiants préfixés par « systemd.extra-unit. » spécifient des unités supplémentaires à ajouter au système final. Notez que ces unités supplémentaires sont ajoutées à la fois à l'initrd et au système final. ConditionPathExists=!/etc/initrd-release peut être utilisé pour s'assurer que l'unité est conditionnellement ignorée dans l'initrd. Notez que cela peut également être utilisé pour masquer des unités, en spécifiant simplement une valeur vide.

Ajouté dans la version 256.

systemd.unit-dropin.*

Les identifiants préfixés par « systemd.unit-dropin. » ajoutent des fichiers de remplacement pour les unités correspondantes dans le système final. Chaque identifiant doit être suffixé par le nom complet de l'unité, y compris l'extension de l'unité. Son contenu doit être un fichier de remplacement d'unité valide. Optionnellement, le nom de l'unité peut être suivi de « ~ », suivi du nom du fichier de remplacement sans le suffixe « .conf ». S'il n'est pas spécifié, le nom du fichier de remplacement généré sera « 50-credential.conf ». Notez que ces fichiers de remplacement supplémentaires sont ajoutés à la fois à l'initrd et au système final.

Ajouté dans la version 256.
