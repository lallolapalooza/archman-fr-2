NOM

systemd-ask-password - Interroger l'utilisateur pour obtenir un mot de passe système

SYNOPSIS

systemd-ask-password [OPTIONS...] [MESSAGE]

DESCRIPTION

systemd-ask-password peut être utilisé pour interroger interactivement l'utilisateur pour obtenir un mot de passe ou une phrase secrète, en utilisant une invite de message spécifiée en ligne de commande. Lorsqu'il est exécuté depuis un TTY, il demandera un mot de passe sur le TTY et l'affichera sur la sortie standard. Lorsqu'il est exécuté sans TTY ou avec --no-tty, il utilisera un mécanisme de requête basé sur un agent, au niveau du système ou par utilisateur, qui permet aux utilisateurs actifs de répondre via plusieurs agents, listés ci-dessous.

Le but de cet outil est d'interroger les mots de passe système ou par utilisateur — les premiers incluent des mots de passe qui ne sont potentiellement pas associés à un compte utilisateur spécifique. Exemples : déverrouiller des disques durs chiffrés lorsqu'ils sont branchés ou au démarrage, entrer une phrase secrète de certificat SSL pour les serveurs web et VPN.

Les agents de mots de passe système existants sont :

•Un agent de mot de passe au démarrage demandant à l'utilisateur des mots de passe en utilisant plymouth(8),
•Un agent de mot de passe au démarrage interrogeant l'utilisateur directement sur la console — systemd-ask-password-console.service(8),
•Un agent demandant la saisie du mot de passe via un message de wall(1) — systemd-ask-password-wall.service(8),
•Un agent TTY qui est temporairement lancé lors des invocations de systemctl(1),
•Un agent en ligne de commande qui peut être lancé temporairement pour traiter les requêtes de mots de passe mises en file d'attente — systemd-tty-ask-password-agent --query.

Répondre aux requêtes de mots de passe système est une opération privilégiée, donc tous les agents listés ci-dessus (sauf le dernier) s'exécutent en tant que services système privilégiés. Le dernier nécessite également des privilèges élevés, il doit donc être exécuté via run0(1) ou similaire.

Des agents de mots de passe supplémentaires peuvent être implémentés selon la Spécification des agents de mots de passe systemd[1].

Si un mot de passe est interrogé sur un TTY, l'utilisateur peut appuyer sur TAB pour masquer les astérisques normalement affichés pour chaque caractère tapé. Appuyer sur Retour arrière comme première touche obtient le même effet.

OPTIONS

Les options suivantes sont comprises :

--icon=

Spécifiez un nom d'icône à côté de la requête de mot de passe, qui peut être utilisé dans tous les agents prenant en charge l'affichage graphique. Le nom de l'icône doit suivre la XDG Icon Naming Specification[2].

--id=

Spécifiez un identifiant pour cette requête de mot de passe. Cet identifiant est librement choisissable et permet la reconnaissance des requêtes par les agents impliqués. Il doit inclure le sous-système effectuant la requête et l'objet spécifique pour lequel la requête est faite. Exemple : "--id=cryptsetup:/dev/sda5".

Ajouté dans la version 227.

--keyname=

Configurez un nom de clé du keyring du noyau à utiliser comme cache pour le mot de passe. S'il est défini, l'outil essaiera de pousser tous les mots de passe collectés dans le keyring du noyau de l'utilisateur root, sous une clé du nom spécifié. Combiné avec --accept-cached, il essaiera également de récupérer ces mots de passe mis en cache depuis la clé du keyring du noyau au lieu d'interroger immédiatement l'utilisateur. En utilisant cette option, le keyring du noyau peut être utilisé comme cache efficace pour éviter de demander plusieurs fois des mots de passe, s'il existe plusieurs objets qui peuvent être déverrouillés avec le même mot de passe. La clé mise en cache aura un délai d'expiration de 2,5 minutes, après quoi elle sera purgée du keyring du noyau. Notez qu'il est possible de mettre en cache plusieurs mots de passe sous le même nom de clé, auquel cas ils seront stockés sous forme de liste de mots de passe séparés par NUL. Utilisez keyctl(1) pour accéder directement à la clé mise en cache via le keyring du noyau. Exemple : "--keyname=cryptsetup"

Ajouté dans la version 227.

--credential=

Configurez un identifiant à partir duquel lire le mot de passe — s'il existe. Ceci peut être utilisé en conjonction avec les paramètres ImportCredential=, LoadCredential= et SetCredential= dans les fichiers d'unité. Voir systemd.exec(5) pour les détails. S'il n'est pas spécifié, utilise par défaut "password". Cette option n'a aucun effet si aucun répertoire d'identifiants n'est passé au programme (c.-à-d. si $CREDENTIALS_DIRECTORY n'est pas défini) ou si aucun identifiant du nom spécifié n'existe.

Ajouté dans la version 249.

--timeout=

Spécifiez le délai d'attente de la requête en secondes. Par défaut 90s. Une valeur de 0 attend indéfiniment.

--echo=yes|no|masked

Contrôle si l'entrée de l'utilisateur doit être échoée. Prend une valeur booléenne ou la chaîne spéciale "masked", la valeur par défaut étant cette dernière. Si activé, les caractères tapés sont échoés littéralement, ce qui est utile pour demander des noms d'utilisateur et d'autres données non protégées. Si désactivé, les caractères tapés ne sont échoés sous aucune forme, l'utilisateur n'aura aucun retour sur son entrée. S'il est défini sur "masked", une astérisque ("*") est échoée pour chaque caractère tapé. Dans ce mode, si l'utilisateur appuie sur la touche tabulation ("↹"), l'écho est désactivé. (Alternativement, si l'utilisateur appuie sur la touche retour arrière ("⌫") alors qu'aucune donnée n'a été entrée autrement, l'écho est également désactivé).

Ajouté dans la version 249.

--echo, -e

Équivalent à --echo=yes, voir ci-dessus.

Ajouté dans la version 217.

--emoji=yes|no|auto

Contrôle si la requête doit être préfixée ou non par un emoji de cadenas et de clé (🔐), si les paramètres du TTY le permettent. Par défaut "auto", qui utilise par défaut "yes", sauf si --echo=yes est donné.

Ajouté dans la version 249.

--no-tty

Ne jamais demander le mot de passe sur le TTY courant même si un est disponible. Utiliser toujours le système d'agent.

--accept-cached

Si passé, accepte les mots de passe mis en cache, c'est-à-dire les mots de passe entrés précédemment.

--multiple

Lorsqu'il est utilisé en conjonction avec --accept-cached, accepte plusieurs mots de passe. Cela produira un mot de passe par ligne.

--no-output

N'affiche pas les mots de passe sur la sortie standard. Ceci est utile si vous voulez stocker un mot de passe dans le keyring du noyau avec --keyname= mais ne voulez pas qu'il apparaisse à l'écran ou dans les logs.

Ajouté dans la version 230.

-n

Par défaut, lorsque le mot de passe acquis est écrit sur la sortie standard, il est suffixé par un caractère de nouvelle ligne. Ceci peut être désactivé avec le commutateur -n, de manière similaire au commutateur du même nom de la commande echo(1).

Ajouté dans la version 249.

--user, --system

Contrôle s'il faut interroger les agents de mots de passe système ou par utilisateur. Par défaut, si invoqué avec des privilèges, ce sont les agents système qui sont interrogés, sinon ceux par utilisateur. Ces options permettent de remplacer ce comportement automatique.

Ajouté dans la version 257.

-h, --help

Affiche un bref texte d'aide et quitte.

ETAT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
