NOM

systemd-cat - Connecte un pipeline ou la sortie d'un programme au journal

SYNTAXE

systemd-cat [OPTIONS...] [COMMANDE] [ARGUMENTS...]

systemd-cat [OPTIONS...]

DESCRIPTION

systemd-cat peut être utilisé pour connecter l'entrée standard et la sortie d'un processus au journal, ou comme un outil de filtrage dans un pipeline shell pour transmettre la sortie générée par l'élément précédent du pipeline au journal.

Si aucun paramètre n'est passé, systemd-cat écrira tout ce qu'il lit de l'entrée standard (stdin) dans le journal.

Si des paramètres sont passés, ils sont exécutés en tant que ligne de commande avec la sortie standard (stdout) et la sortie d'erreur standard (stderr) connectées au journal, de sorte que tout ce qu'ils écrivent soit stocké dans le journal.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

-t, --identifier=

Spécifie une courte chaîne qui est utilisée pour identifier l'outil de journalisation. Si elle n'est pas spécifiée, aucune chaîne d'identification n'est définie pour l'entrée du journal, et le nom de l'exécutable (ou "cat" si l'entrée est lue depuis un pipe) sera utilisé pour décrire la source du journal à la place.

-p, --priority=

Spécifie le niveau de priorité par défaut pour les messages journalisés. Passez l'une des valeurs suivantes : "emerg", "alert", "crit", "err", "warning", "notice", "info", "debug", ou une valeur comprise entre 0 et 7 (correspondant aux mêmes niveaux nommés). Ces valeurs de priorité sont les mêmes que celles définies par syslog(3). Par défaut, la valeur est "info". Notez que cela contrôle simplement la valeur par défaut ; les lignes individuelles peuvent être journalisées avec des niveaux différents si elles sont préfixées en conséquence. Pour plus de détails, voir --level-prefix= ci-dessous.

--stderr-priority=

Spécifie le niveau de priorité par défaut pour les messages provenant de la sortie d'erreur standard (stderr) du processus. L'utilisation de cette option est la même que celle de l'option --priority=, ci-dessus, et les deux peuvent être utilisées simultanément. Lorsque les deux sont utilisées, --priority= spécifiera la priorité par défaut pour la sortie standard (stdout).

Si --stderr-priority= n'est pas spécifié, les messages provenant de stderr seront toujours journalisés, avec le même niveau de priorité par défaut que stdout.

De plus, notez que lorsque stdout et stderr utilisent la même priorité par défaut, les messages seront strictement ordonnés, car un seul canal est utilisé pour les deux. Lorsque la priorité par défaut diffère, deux canaux sont utilisés, et donc les messages stdout ne seront pas strictement ordonnés par rapport aux messages stderr - bien qu'ils auront tendance à être approximativement ordonnés.

Ajouté dans la version 241.

--level-prefix=

Contrôle si les lignes lues sont analysées pour les préfixes de niveau de priorité syslog. Si activé (par défaut), une ligne préfixée par un préfixe de priorité tel que "<5>" est journalisée avec la priorité 5 ("notice"), et de même pour les autres niveaux de priorité. Prend un argument booléen.

--namespace=

Spécifie l'espace de noms du journal auquel les E/S standard doivent être connectées. Pour plus de détails sur les espaces de noms du journal, voir systemd-journald.service(8).

Ajouté dans la version 256.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

EXEMPLES

Exemple 1. Appeler un programme

Ceci appelle /bin/ls avec la sortie standard et les erreurs connectées au journal :

# systemd-cat ls

Exemple 2. Utilisation dans un pipeline shell

Ceci construit un pipeline shell appelant également /bin/ls et écrit la sortie qu'il génère dans le journal :

# ls | systemd-cat

Bien que les deux exemples aient des effets très similaires, le premier est préférable, car un seul processus s'exécute à la fois et stdout et stderr sont capturés, tandis que dans le second exemple, seul stdout est capturé.
