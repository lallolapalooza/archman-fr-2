sysexits.h(3head) sysexits.h(3head)

NOM

sysexits.h - codes de sortie pour les programmes

BIBLIOTHÈQUE

Bibliothèque C standard (libc)

SYNTAXE

#include <sysexits.h>
#define EX_OK 0 /* terminaison réussie */
#define EX__BASE 64 /* valeur de base pour les messages d'erreur */
#define EX_USAGE 64 /* erreur d'utilisation de la ligne de commande */
#define EX_DATAERR 65 /* erreur de format de données */
#define EX_NOINPUT 66 /* impossible d'ouvrir l'entrée */
#define EX_NOUSER 67 /* destinataire inconnu */
#define EX_NOHOST 68 /* nom d'hôte inconnu */
#define EX_UNAVAILABLE 69 /* service indisponible */
#define EX_SOFTWARE 70 /* erreur logicielle interne */
#define EX_OSERR 71 /* erreur système (par ex. impossible de fork) */
#define EX_OSFILE 72 /* fichier système critique manquant */
#define EX_CANTCREAT 73 /* impossible de créer (fichier de sortie utilisateur) */
#define EX_IOERR 74 /* erreur d'entrée/sortie */
#define EX_TEMPFAIL 75 /* échec temporaire ; l'utilisateur est invité à réessayer */
#define EX_PROTOCOL 76 /* erreur distante dans le protocole */
#define EX_NOPERM 77 /* permission refusée */
#define EX_CONFIG 78 /* erreur de configuration */
#define EX__MAX ... /* valeur maximale répertoriée */

DESCRIPTION

Quelques programmes se terminent avec les codes d'erreur suivants.

La terminaison réussie est toujours indiquée par un statut de 0, ou EX_OK (équivalent à EXIT_SUCCESS de <stdlib.h>). Les numéros d'erreur commencent à EX__BASE pour réduire la possibilité de conflits avec d'autres statuts de sortie que des programmes aléatoires pourraient déjà retourner. La signification du code est approximativement la suivante :

EX_USAGE
La commande a été utilisée incorrectement, par exemple avec un nombre incorrect d'arguments, un drapeau invalide, une syntaxe erronée dans un paramètre, ou autre.
EX_DATAERR
Les données d'entrée étaient incorrectes d'une manière ou d'une autre. Ceci ne devrait être utilisé que pour les données de l'utilisateur et non pour les fichiers système.
EX_NOINPUT
Un fichier d'entrée (pas un fichier système) n'existait pas ou n'était pas lisible. Cela pourrait également inclure des erreurs comme "Pas de message" à un agent de messagerie (s'il s'en souciait).
EX_NOUSER
L'utilisateur spécifié n'existait pas. Cela pourrait être utilisé pour les adresses e-mail ou les connexions à distance.
EX_NOHOST
L'hôte spécifié n'existait pas. Ceci est utilisé dans les adresses e-mail ou les requêtes réseau.
EX_UNAVAILABLE
Un service est indisponible. Cela peut se produire si un programme ou un fichier de support n'existe pas. Cela peut également être utilisé comme message fourre-tout lorsque quelque chose que vous vouliez faire ne fonctionne pas, mais que vous ne savez pas pourquoi.
EX_SOFTWARE
Une erreur logicielle interne a été détectée. Cela devrait être limité aux erreurs non liées au système d'exploitation si possible.
EX_OSERR
Une erreur du système d'exploitation a été détectée. Ceci est destiné à être utilisé pour des choses comme "impossible de fork", "impossible de créer un tube", ou similaire. Cela inclut des choses comme getuid(2) retournant un utilisateur qui n'existe pas dans le fichier passwd(5).
EX_OSFILE
Certains fichiers système (par ex. /etc/passwd, /etc/utmp, etc.) n'existent pas, ne peuvent pas être ouverts ou présentent une sorte d'erreur (par ex. erreur de syntaxe).
EX_CANTCREAT
Un fichier de sortie (spécifié par l'utilisateur) ne peut pas être créé.
EX_IOERR
Une erreur s'est produite lors de l'opération d'E/S sur un fichier.
EX_TEMPFAIL
Échec temporaire, indiquant quelque chose qui n'est pas vraiment une erreur. Par exemple, qu'un agent de messagerie n'a pas pu établir de connexion et que la demande doit être retentée plus tard.
EX_PROTOCOL
Le système distant a renvoyé quelque chose qui était "impossible" lors d'un échange de protocole.
EX_NOPERM
Vous n'aviez pas les permissions suffisantes pour effectuer l'opération. Ceci n'est pas destiné aux problèmes de système de fichiers, qui devraient utiliser EX_NOINPUT ou EX_CANTCREAT, mais plutôt aux permissions de niveau supérieur.
EX_CONFIG
Quelque chose a été trouvé dans un état non configuré ou mal configuré.

Les valeurs numériques correspondant aux symboliques sont données entre parenthèses pour référence facile.

NORMES

BSD.

HISTORIQUE

Le fichier <sysexits.h> est apparu dans 4.0BSD pour être utilisé par l'utilitaire deliverymail, renommé plus tard en sendmail(8).

LIMITATIONS

Le choix d'une valeur de sortie appropriée est souvent ambigu.

VOIR AUSSI

err(3), error(3), exit(3)
