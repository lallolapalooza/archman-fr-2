NOM

systemd.target - Configuration d'une unité de cible

SYNOPSIS

cible.target

DESCRIPTION

Un fichier de configuration d'unité dont le nom se termine par ".target" encode des informations sur une unité de cible de systemd. Les unités de cible sont utilisées pour regrouper des unités et pour définir des points de synchronisation pour l'ordre des dépendances avec d'autres fichiers d'unité.

Ce type d'unité n'a pas d'options spécifiques. Voir systemd.unit(5) pour les options communes à tous les fichiers de configuration d'unité. Les éléments de configuration communs sont configurés dans les sections génériques [Unit] et [Install]. Une section [Target] séparée n'existe pas, car aucune option spécifique aux cibles ne peut être configurée.

Les unités de cible n'offrent aucune fonctionnalité supplémentaire par rapport aux fonctionnalités génériques fournies par les unités. Elles regroupent simplement des unités, permettant d'utiliser un seul nom de cible dans les paramètres Wants= et Requires= pour établir une dépendance envers un ensemble d'unités défini par la cible, et dans les paramètres Before= et After= pour établir un ordre. Les cibles établissent des noms standardisés pour les points de synchronisation pendant le démarrage et l'arrêt. Il est important de consulter systemd.special(7) pour des exemples et des descriptions des cibles systemd standard.

Les unités de cible offrent un remplacement plus flexible pour les niveaux d'exécution SysV dans le système d'init SysV classique.

Notez qu'un fichier d'unité de cible ne doit pas être vide, sinon il sera considéré comme une unité masquée. Il est recommandé de fournir une section [Unit] incluant des options informatives Description= et Documentation=.

DEPENDANCES AUTOMATIQUES

Dépendances implicites

Il n'y a pas de dépendances implicites pour les unités de cible.

Dépendances par défaut

Les dépendances suivantes sont ajoutées, sauf si DefaultDependencies=no est défini :

•Les unités de cible complèteront automatiquement toutes les dépendances configurées de type Wants= ou Requires= avec des dépendances de type After=, sauf si DefaultDependencies=no est défini dans les unités spécifiées.

Notez que l'inverse n'est pas vrai. Par exemple, définir Wants=that.target dans some.service n'ajoutera pas automatiquement la dépendance d'ordre After=that.target pour some.service. Au lieu de cela, some.service devrait utiliser la fonction de synchronisation principale des unités de type cible, en définissant une dépendance d'ordre spécifique After=that.target ou Before=that.target dans son fichier d'unité .service.

•Les unités de cible obtiennent automatiquement des dépendances Conflicts= et Before= vis-à-vis de shutdown.target.

OPTIONS

Les fichiers d'unité de cible peuvent inclure les sections [Unit] et [Install], qui sont décrites dans systemd.unit(5). Aucune option spécifique à ce type de fichier n'est prise en charge.

EXEMPLE

Exemple 1. Cible autonome simple

# emergency-net.target
[Unit]
Description=Emergency Mode with Networking
Requires=emergency.target systemd-networkd.service
After=emergency.target systemd-networkd.service
AllowIsolate=yes

Lors de l'ajout de dépendances à d'autres unités, il est important de vérifier si elles définissent DefaultDependencies=. Les unités de service, sauf si elles définissent DefaultDependencies=no, obtiennent automatiquement une dépendance vis-à-vis de sysinit.target. Dans ce cas, emergency.target et systemd-networkd.service ont tous deux DefaultDependencies=no, ils sont donc appropriés pour être utilisés dans cette cible, et n'entraînent pas sysinit.target.

Vous pouvez maintenant passer en mode urgence en exécutant systemctl isolate emergency-net.target ou en passant l'option systemd.unit=emergency-net.target sur la ligne de commande du noyau.

D'autres unités peuvent avoir WantedBy=emergency-net.target dans la section [Install]. Une fois qu'elles sont activées à l'aide de systemctl enable, elles seront démarrées avant le démarrage de emergency-net.target. Il est également possible d'ajouter des unités arbitraires comme dépendances d'emergency.target sans les modifier en utilisant systemctl add-wants.
