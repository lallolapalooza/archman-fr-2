NOM

systemd.link - Configuration des périphériques réseau

SYNTAXE

link.link

DESCRIPTION

Un fichier texte simple au format ini qui encode la configuration des périphériques réseau correspondants, utilisé par systemd-udevd(8) et en particulier par sa fonction intégrée net_setup_link. Voir systemd.syntax(7) pour une description générale de la syntaxe.

Notez que certaines distributions peuvent intégrer des fichiers .link dans leurs facilités de démarrage précoce (par exemple, en incluant des copies des fichiers .link dans l'initramfs). Il peut donc être nécessaire de prendre des mesures manuelles pour s'assurer que les modifications locales sont cohérentes avec les installations de stockage de démarrage précoce. La documentation spécifique à la distribution concernée doit être consultée.

Les fichiers .link sont lus à partir des fichiers situés dans le répertoire réseau système /usr/lib/systemd/network et /usr/local/lib/systemd/network [1], le répertoire réseau d'exécution temporaire /run/systemd/network, et le répertoire réseau d'administration locale /etc/systemd/network. Tous les fichiers de configuration sont triés collectivement et traités dans l'ordre alphabétique, quels que soient les répertoires dans lesquels ils se trouvent. Cependant, les fichiers portant des noms identiques se remplacent mutuellement. Il est recommandé que chaque nom de fichier soit précédé d'un nombre inférieur à "70" (par exemple, 10-eth0.link). Sinon, les fichiers .link par défaut ou ceux générés par systemd-network-generator.service(8) peuvent prendre la priorité sur les fichiers configurés par l'utilisateur. Les fichiers dans /etc/ ont la priorité la plus élevée, les fichiers dans /run/ prennent la priorité sur les fichiers portant le même nom dans /usr/lib/. Ceci peut être utilisé pour remplacer un fichier de lien fourni par le système par un fichier local si nécessaire. À titre de cas spécial, un fichier vide (taille 0) ou un lien symbolique portant le même nom pointant vers /dev/null désactive entièrement le fichier de configuration (il est "masqué").

En plus du fichier de lien foo.link, un répertoire de "drop-in" foo.link.d/ peut exister. Tous les fichiers se terminant par ".conf" provenant de ce répertoire seront fusionnés dans l'ordre alphabétique et analysés après le fichier principal lui-même. Ceci est utile pour modifier ou ajouter des paramètres de configuration, sans avoir à modifier le fichier de configuration principal. Chaque fichier de drop-in doit avoir des en-têtes de section appropriés.

En plus de /etc/systemd/network, des répertoires de drop-in ".d" peuvent être placés dans les répertoires /usr/lib/systemd/network ou /run/systemd/network. Les fichiers de drop-in dans /etc/ ont la priorité sur ceux dans /run/, qui à leur tour ont la priorité sur ceux dans /usr/lib/. Les fichiers de drop-in sous l'un de ces répertoires ont la priorité sur le fichier de lien principal, où qu'il soit situé.

Le fichier de lien contient une section [Match], qui détermine si un fichier de lien donné peut être appliqué à un périphérique donné, ainsi qu'une section [Link] spécifiant comment le périphérique doit être configuré. Le premier (par ordre lexical) des fichiers de lien qui correspond à un périphérique donné est appliqué. Notez qu'un fichier par défaut 99-default.link est fourni par le système. Tout .link fourni par l'utilisateur doit donc avoir un nom lexicalement antérieur pour être pris en compte.

Voir udevadm(8) pour diagnostiquer les problèmes avec les fichiers .link.

OPTIONS DE LA SECTION [MATCH]

Un fichier de lien est dit correspondre à une interface si toutes les correspondances spécifiées par la section [Match] sont satisfaites. Lorsqu'un fichier de lien ne contient pas de paramètres valides dans la section [Match], le fichier correspond à toutes les interfaces et systemd-udevd émet un avertissement à ce sujet. Astuce : pour éviter l'avertissement et indiquer clairement que toutes les interfaces doivent être mises en correspondance, ajoutez ce qui suit :

OriginalName=*

Le premier (par ordre alphabétique) des fichiers de lien qui correspond à une interface donnée est appliqué, tous les fichiers suivants sont ignorés, même s'ils correspondent également. Les clés suivantes sont acceptées :

MACAddress=

Une liste d'adresses matérielles séparées par des espaces. Les formats acceptables sont :

hexadécimal séparé par des deux-points

Chaque champ doit être un octet. Par exemple, "12:34:56:78:90:ab" ou "AA:BB:CC:DD:EE:FF".

Ajouté en version 250.

hexadécimal séparé par des tirets

Chaque champ doit être un octet. Par exemple, "12-34-56-78-90-ab" ou "AA-BB-CC-DD-EE-FF".

Ajouté en version 250.

hexadécimal séparé par des points

Chaque champ doit être deux octets. Par exemple, "1234.5678.90ab" ou "AABB.CCDD.EEFF".

Ajouté en version 250.

format d'adresse IPv4

Par exemple, "127.0.0.1" ou "192.168.0.1".

Ajouté en version 250.

format d'adresse IPv6

Par exemple, "2001:0db8:85a3::8a2e:0370:7334" ou "::1".

Ajouté en version 250.

La longueur totale de chaque adresse MAC doit être de 4 (pour un tunnel IPv4), 6 (pour Ethernet), 16 (pour un tunnel IPv6) ou 20 (pour InfiniBand). Cette option peut apparaître plusieurs fois, auquel cas les listes sont fusionnées. Si la chaîne vide est assignée à cette option, la liste des adresses matérielles définies précédemment est réinitialisée. Valeur par défaut : non définie.

Ajouté en version 211.

PermanentMACAddress=

Une liste d'adresses matérielles permanentes séparées par des espaces. Alors que MACAddress= correspond à l'adresse MAC actuelle du périphérique, ceci correspond à l'adresse MAC permanente du périphérique, qui peut être différente de l'actuelle. Utilisez le format hexadécimal complet séparé par des deux-points, des tirets ou des points, ou le format d'adresse IPv4 ou IPv6. Cette option peut apparaître plusieurs fois, auquel cas les listes sont fusionnées. Si la chaîne vide est assignée à cette option, la liste des adresses matérielles définies précédemment est réinitialisée. Valeur par défaut : non définie.

Ajouté en version 245.

Path=

Une liste de globs de style shell séparés par des espaces correspondant au chemin persistant, tel qu'exposé par la propriété udev ID_PATH.

Ajouté en version 211.

Driver=

Une liste de globs de style shell séparés par des espaces correspondant au pilote actuellement lié au périphérique, tel qu'exposé par la propriété udev ID_NET_DRIVER de son périphérique parent, ou si celle-ci n'est pas définie, le pilote tel qu'exposé par ethtool -i du périphérique lui-même. Si la liste est précédée de "!", le test est inversé.

Ajouté en version 211.

Type=

Une liste de globs de style shell séparés par des espaces correspondant au type de périphérique, tel qu'exposé par networkctl list. Si la liste est précédée de "!", le test est inversé. Certaines valeurs valides sont "ether", "loopback", "wlan", "wwan". Les types valides sont nommés soit à partir de l'attribut udev "DEVTYPE", soit des macros "ARPHRD_" dans linux/if_arp.h, donc ceci n'est pas exhaustif.

Ajouté en version 211.

Kind=

Une liste de globs de style shell séparés par des espaces correspondant au type de périphérique, tel qu'exposé par networkctl status INTERFACE ou ip -d link show INTERFACE. Si la liste est précédée de "!", le test est inversé. Certaines valeurs valides sont "bond", "bridge", "gre", "tun", "veth". Les types valides sont donnés par l'attribut netlink "IFLA_INFO_KIND", donc ceci n'est pas exhaustif.

Ajouté en version 251.

Property=

Une liste de noms de propriétés udev séparés par des espaces avec leurs valeurs après le signe égal ("="). Si plusieurs propriétés sont spécifiées, les résultats des tests sont combinés par un ET logique. Si la liste est précédée de "!", le test est inversé. Si une valeur contient des espaces blancs, alors citez la paire clé-valeur entière. Si une valeur contient des guillemets, alors échappez le guillemet avec "\".

Exemple : si un fichier .link contient ce qui suit :

Property=ID_MODEL_ID=9999 "ID_VENDOR_FROM_DATABASE=nom du vendeur" "CLE=avec \"guillemets\""

alors, le fichier .link ne correspond que lorsqu'une interface possède les trois propriétés ci-dessus.

Ajouté en version 243.

OriginalName=

Une liste de globs de style shell séparés par des espaces correspondant au nom du périphérique, tel qu'exposé par la propriété udev "INTERFACE". Ceci ne peut pas être utilisé pour correspondre à des noms qui ont déjà été modifiés depuis l'espace utilisateur. Attention

on est avisé lors de la correspondance avec des noms attribués par le noyau, car ils sont connus pour être instables entre les redémarrages.

Ajouté dans la version 218.

Host=

Correspond aux noms d'hôte ou aux identifiants de machine de l'hôte. Voir ConditionHost= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 211.

Virtualization=

Vérifie si le système est exécuté dans un environnement virtualisé et teste éventuellement s'il s'agit d'une implémentation spécifique. Voir ConditionVirtualization= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 211.

KernelCommandLine=

Vérifie si une option spécifique de la ligne de commande du noyau est définie. Voir ConditionKernelCommandLine= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 211.

KernelVersion=

Vérifie si la version du noyau (telle que rapportée par uname -r) correspond à une certaine expression. Voir ConditionKernelVersion= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 237.

Version=

Vérifie si une version logicielle correspond à une certaine expression. Voir ConditionVersion= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 258.

Credential=

Vérifie si le credential spécifié a été passé au service systemd-udevd.service. Voir Credentials système et service[2] pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 252.

Architecture=

Vérifie si le système fonctionne sur une architecture spécifique. Voir ConditionArchitecture= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 211.

Firmware=

Vérifie si le système fonctionne sur une machine avec le firmware spécifié. Voir ConditionFirmware= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est assignée, la valeur précédemment assignée est effacée.

Ajouté dans la version 249.

[LIEN] OPTIONS DE SECTION

La section [Link] accepte les clés suivantes :

Description=

Une description de l'appareil.

Ajouté dans la version 211.

Property=

Définit les propriétés udev spécifiées. Cela prend une liste d'éléments séparés par des espaces, des paires clé-valeur concaténées avec un signe égal ("="). Exemple : 
Property=HOGE=foo BAR=baz

Cette option prend en charge l'expansion de spécificateurs simples, voir la section Spécificateurs ci-dessous. Cette option peut être spécifiée plusieurs fois. Si une chaîne vide est assignée, alors toutes les assignations précédentes sont effacées.

Ce paramètre est utile pour configurer la propriété "ID_NET_MANAGED_BY=" qui déclare quel service de gestion réseau doit gérer l'interface, ce qui est respecté par systemd-networkd(8) et d'autres. Utilisez

Property=ID_NET_MANAGED_BY=io.systemd.Network

pour déclarer explicitement que systemd-networkd doit gérer l'interface, ou définissez la propriété sur autre chose pour déclarer explicitement qu'elle ne doit pas le faire. Voir systemd.network(5) pour les détails sur la façon dont cette propriété est utilisée pour faire correspondre les noms d'interface.

Ajouté dans la version 256.

ImportProperty=

Importe les propriétés udev spécifiées à partir de la base de données sauvegardée. Cela prend une liste de noms de propriétés séparés par des espaces. Exemple : 
ImportProperty=HOGE BAR

Cette option prend en charge l'expansion de spécificateurs simples, voir la section Spécificateurs ci-dessous. Cette option peut être spécifiée plusieurs fois. Si une chaîne vide est assignée, alors toutes les assignations précédentes sont effacées.

Si la même propriété est également définie dans Property= ci-dessus, alors la valeur de la propriété importée sera remplacée par la valeur spécifiée dans Property=.

Ajouté dans la version 256.

UnsetProperty=

Annule les propriétés udev spécifiées. Cela prend une liste de noms de propriétés séparés par des espaces. Exemple : 
UnsetProperty=HOGE BAR

Cette option prend en charge l'expansion de spécificateurs simples, voir la section Spécificateurs ci-dessous. Cette option peut être spécifiée plusieurs fois. Si une chaîne vide est assignée, alors toutes les assignations précédentes sont effacées.

Ce paramètre est appliqué après l'application de ImportProperty= et Property=. Par conséquent, si la même propriété est spécifiée dans ImportProperty= ou Property=, alors la valeur de la propriété importée ou spécifiée sera ignorée, et la propriété sera annulée.

Ajouté dans la version 256.

Alias=

La propriété d'interface ifalias est définie à cette valeur.

Ajouté dans la version 211.

MACAddressPolicy=

La politique selon laquelle l'adresse MAC doit être définie. Les politiques disponibles sont :

persistent

Si le matériel possède une adresse MAC persistante, comme la plupart du matériel devrait en avoir, et si elle est utilisée par le noyau, rien n'est fait. Sinon, une nouvelle adresse MAC est générée et sera garantie d'être la même à chaque démarrage pour la machine donnée et l'appareil donné, mais elle sera par ailleurs aléatoire. Cette fonctionnalité dépend de l'existence des propriétés ID_NET_NAME_* pour le lien. Sur le matériel où ces propriétés ne sont pas définies, la génération d'une adresse MAC persistante échouera.

Ajouté dans la version 211.

random

Si le noyau utilise une adresse MAC aléatoire, rien n'est fait. Sinon, une nouvelle adresse est générée aléatoirement chaque fois que l'appareil apparaît, généralement au démarrage. Quoi qu'il en soit, l'adresse aléatoire aura les bits "unicast" et "localement administré" définis.

Ajouté dans la version 211.

none

Conserve l'adresse MAC attribuée par le noyau. Ou utilise l'adresse MAC spécifiée dans MACAddress=.

Ajouté dans la version 227.

Une assignation de chaîne vide équivaut à définir "none".

Ajouté dans la version 211.

MACAddress=

L'adresse MAC de l'interface à utiliser. Pour que ce paramètre prenne effet, MACAddressPolicy= doit être soit non défini, vide, soit "none".

Ajouté dans la version 211.

NamePolicy=

Une liste ordonnée et séparée par des espaces de politiques selon lesquelles le nom de l'interface doit être défini. NamePolicy= peut être désactivé en spécifiant net.ifnames=0 sur la ligne de commande du noyau. Chacune des politiques peut échouer, et la première qui réussit est utilisée. Le nom n'est pas défini directement, mais est exporté vers udev en tant que propriété ID_NET_NAME, qui est, par défaut, utilisée par une règle udev(7) pour définir NAME. Les politiques disponibles sont :

kernel

Si le noyau prétend que le nom qu'il a défini pour un appareil est prévisible, alors aucun renommage n'est effectué.

Ajouté dans la version 216.

database

Le nom est défini en fonction des entrées de la base de données matérielle d'udev avec la clé ID_NET_NAME_FROM_DATABASE.

Ajouté dans la version 211.

onboard

Le nom est défini en fonction des informations fournies par le firmware pour les appareils intégrés, telles qu'exportées par la propriété udev ID_NET_NAME_ONBOARD. Voir systemd.net-naming-scheme(7).

Ajouté dans la version 211.

slot

Le nom est défini en fonction des informations fournies par le firmware pour les appareils remplaçables à chaud, telles qu'exportées par la propriété udev ID_NET_NAME_SLOT. Voir systemd.net-naming-scheme(7).

Ajouté dans la version 211.

path

Le nom est défini en fonction de l'emplacement physique de l'appareil, tel qu'exporté par la propriété udev ID_NET_NAME_PATH. Voir systemd.net-naming-scheme(7).

Ajouté dans la version 211.

mac

Le nom est défini en fonction de l'adresse MAC persistante de l'appareil, telle qu'exportée par la propriété udev ID_NET_NAME_MAC. Voir systemd.net-naming-scheme(7).

Ajouté dans la version 211.

keep

Si l'appareil avait déjà un nom attribué par l'espace utilisateur (dans le cadre de la création de l'appareil ou d'un renommage), conservez-le.

Ajouté dans la version 241.

Ajouté dans la version 211.

Name=

Le nom de l'interface à utiliser. Cette option a une priorité inférieure à NamePolicy=, donc pour que ce paramètre prenne effet, NamePolicy= doit être soit non défini, vide, désactivé, soit toutes les politiques configurées doivent échouer. Voir également l'exemple ci-dessous avec "Name=dmz0".

Notez qu'attribuer un nom que le noyau pourrait utiliser pour une autre interface (par exemple "eth0") est dangereux car l'attribution du nom par udev entrera en concurrence avec l'attribution effectuée par le noyau, et une seule interface peut utiliser le nom. Selon l'ordre des opérations, soit udev soit le noyau gagnera, rendant le nommage imprévisible. Il est préférable d'utiliser un préfixe différent, par exemple "internal0"/"external0" ou "lan0"/"lan1&qu

Les noms d'interface doivent avoir une longueur minimale de 1 caractère et une longueur maximale de 15 caractères, et peuvent contenir n'importe quel caractère ASCII 7 bits, à l'exception des caractères de contrôle, des caractères « : », « / » et « % ». Bien que « . » soit un caractère autorisé, il est recommandé d'éviter de l'utiliser lors de la nomination d'interfaces, car divers outils (tels que resolvconf(1)) l'utilisent comme caractère séparateur. De plus, les noms d'interface entièrement numériques ne sont pas autorisés (afin d'éviter toute ambiguïté avec la spécification d'interface par index numérique), pas plus que les chaînes spéciales « . », « .. », « all » et « default ».

Ajouté dans la version 211.

AlternativeNamesPolicy=

Une liste séparée par des espaces de politiques selon lesquelles les noms alternatifs de l'interface doivent être définis. Chacune des politiques peut échouer, et toutes les politiques réussies sont utilisées. Les politiques disponibles sont « database », « onboard », « slot », « path » et « mac ». Si le noyau ne prend pas en charge les noms alternatifs, ce paramètre sera ignoré.

Ajouté dans la version 245.

AlternativeName=

Le nom d'interface alternatif à utiliser. Cette option peut être spécifiée plusieurs fois. Si la chaîne vide est assignée à cette option, la liste est réinitialisée et toutes les affectations précédentes n'ont aucun effet. Si le noyau ne prend pas en charge les noms alternatifs, ce paramètre sera ignoré.

Les noms d'interface alternatifs peuvent être utilisés pour identifier les interfaces dans divers outils. Contrairement au nom primaire (tel que configuré avec Name= ci-dessus), il peut y avoir plusieurs noms alternatifs faisant référence à la même interface. Les noms alternatifs peuvent avoir une longueur maximale de 127 caractères, contrairement aux 15 autorisés pour le nom d'interface primaire, mais sont par ailleurs soumis aux mêmes contraintes de nommage.

Ajouté dans la version 245.

TransmitQueues=

Spécifie le nombre de files d'attente de transmission de l'appareil. Un entier dans la plage 1...4096. Lorsqu'il n'est pas défini, la valeur par défaut du noyau sera utilisée.

Ajouté dans la version 248.

ReceiveQueues=

Spécifie le nombre de files d'attente de réception de l'appareil. Un entier dans la plage 1...4096. Lorsqu'il n'est pas défini, la valeur par défaut du noyau sera utilisée.

Ajouté dans la version 248.

TransmitQueueLength=

Spécifie la longueur de la file d'attente de transmission de l'appareil en nombre de paquets. Un entier non signé dans la plage 0...4294967294. Lorsqu'il n'est pas défini, la valeur par défaut du noyau sera utilisée.

Ajouté dans la version 248.

MTUBytes=

L'unité de transmission maximale en octets à définir pour l'appareil. Les suffixes habituels K, M, G sont pris en charge et sont compris dans la base de 1024.

Ajouté dans la version 211.

BitsPerSecond=

La vitesse à définir pour l'appareil, la valeur est arrondie à la baisse au Mbps le plus proche. Les suffixes habituels K, M, G sont pris en charge et sont compris dans la base de 1000.

Ajouté dans la version 211.

Duplex=

Le mode duplex à définir pour l'appareil. Les valeurs acceptées sont half et full.

Ajouté dans la version 211.

AutoNegotiation=

Prend une valeur booléenne. Si défini sur oui, la négociation automatique des paramètres de transmission est activée. L'autonégociation est une procédure par laquelle deux appareils Ethernet connectés choisissent des paramètres de transmission communs, tels que la vitesse, le mode duplex et le contrôle de flux. Lorsqu'il n'est pas défini, la valeur par défaut du noyau sera utilisée.

Notez que si l'autonégociation est activée, les paramètres de vitesse et de duplex sont en lecture seule. Si l'autonégociation est désactivée, les paramètres de vitesse et de duplex sont accessibles en écriture si le pilote prend en charge plusieurs modes de liaison.

Ajouté dans la version 233.

WakeOnLan=

La politique Wake-on-LAN à définir pour l'appareil. Prend la valeur spéciale « off » qui désactive le Wake-on-LAN, ou une liste séparée par des espaces des mots suivants :

phy

Réveil sur activité PHY.

Ajouté dans la version 211.

unicast

Réveil sur messages unicast.

Ajouté dans la version 235.

multicast

Réveil sur messages multicast.

Ajouté dans la version 235.

broadcast

Réveil sur messages broadcast.

Ajouté dans la version 235.

arp

Réveil sur ARP.

Ajouté dans la version 235.

magic

Réveil à la réception d'un paquet magique.

Ajouté dans la version 211.

secureon

Active le mot de passe SecureOn pour MagicPacket. Implicite lorsque WakeOnLanPassword= est spécifié. Si spécifié sans l'option WakeOnLanPassword=, le mot de passe est lu depuis l'identifiant « LINK.link.wol.password » (par exemple, « 60-foo.link.wol.password »), et si l'identifiant n'est pas trouvé, alors il est lu depuis « wol.password ». Voir ImportCredential=/LoadCredential=/SetCredential= dans systemd.exec(5) pour plus de détails. Le mot de passe dans l'identifiant doit être de 6 octets au format hexadécimal, chaque octet étant séparé par deux-points (« : ») comme une adresse MAC Ethernet, par exemple « aa:bb:cc:dd:ee:ff ».

Ajouté dans la version 235.

Par défaut non défini, et la valeur par défaut de l'appareil sera utilisée. Ce paramètre peut être spécifié plusieurs fois. Si une chaîne vide est assignée, alors toutes les affectations précédentes sont effacées.

Ajouté dans la version 211.

WakeOnLanPassword=

Spécifie le mot de passe SecureOn pour MagicPacket. Prend un chemin d'accès absolu vers un fichier régulier ou une socket de flux AF_UNIX, ou le mot de passe brut. Lorsqu'un chemin d'accès vers un fichier régulier est spécifié, le mot de passe est lu à partir de celui-ci. Lorsqu'une socket de flux AF_UNIX est spécifiée, une connexion est établie et le mot de passe est lu à partir de celle-ci. Le mot de passe doit être de 6 octets au format hexadécimal, chaque octet étant séparé par deux-points (« : ») comme une adresse MAC Ethernet, par exemple « aa:bb:cc:dd:ee:ff ». Cela implique WakeOnLan=secureon. Par défaut non défini, et la valeur actuelle ne sera pas modifiée.

Ajouté dans la version 250.

Port=

L'option Port est utilisée pour sélectionner le port de l'appareil. Les valeurs prises en charge sont :

[SR-IOV] OPTIONS DE SECTION

SR-IOV offre la possibilité de partitionner une seule ressource PCI physique en fonctions PCI virtuelles qui peuvent ensuite être, par exemple, injectées dans une VM. Dans le cas des VFs réseau, SR-IOV réduit la latence et l'utilisation du processeur pour le trafic réseau nord-sud (c'est-à-dire le trafic avec des points de terminaison externes à la machine hôte), en permettant au trafic de contourner la pile réseau de la machine hôte.

La présence d'une section [SR-IOV] dans un fichier .link entraînera la création et la configuration de la fonction virtuelle spécifiée. Dans un fichier .network, la fonction virtuelle spécifiée sera configurée, mais doit déjà exister. Spécifiez plusieurs sections [SR-IOV] pour configurer plusieurs SR-IOV.

La section [SR-IOV] accepte les clés suivantes.

VirtualFunction=

Spécifie une Fonction Virtuelle (VF), une fonction PCIe légère conçue uniquement pour déplacer des données. Accepte un entier dans la plage 0...2147483646. Cette option est obligatoire.

Ajouté dans la version 251.

VLANId=

Spécifie l'ID VLAN de la fonction virtuelle. Accepte un entier dans la plage 1...4095.

Ajouté dans la version 251.

QualityOfService=

Spécifie la qualité de service de la fonction virtuelle. Accepte un entier dans la plage 1...4294967294.

Ajouté dans la version 251.

VLANProtocol=

Spécifie le protocole VLAN de la fonction virtuelle. Accepte "802.1Q" ou "802.1ad".

Ajouté dans la version 251.

MACSpoofCheck=

Accepte une valeur booléenne. Contrôle la vérification de l'usurpation MAC. Lorsqu'elle n'est pas définie, le comportement par défaut du noyau sera utilisé.

Ajouté dans la version 251.

QueryReceiveSideScaling=

Accepte une valeur booléenne. Active/désactive la capacité de requête de la configuration de mise à l'échelle côté réception (RSS) de la fonction virtuelle (VF). Les informations RSS de la VF, comme la clé de hachage RSS, peuvent être considérées comme sensibles sur certains périphériques où ces informations sont partagées entre la VF et la fonction physique (PF). Lorsqu'elle n'est pas définie, le comportement par défaut du noyau sera utilisé.

Ajouté dans la version 251.

Trust=

Accepte une valeur booléenne. Permet de définir le mode de confiance de la fonction virtuelle (VF). Lorsqu'elle est définie, les utilisateurs de VF peuvent définir une fonctionnalité spécifique qui peut avoir un impact sur la sécurité et/ou les performances. Lorsqu'elle n'est pas définie, le comportement par défaut du noyau sera utilisé.

Ajouté dans la version 251.

LinkState=

Permet de définir l'état de la liaison de la fonction virtuelle (VF). Accepte une valeur booléenne ou une valeur spéciale "auto". Définir sur "auto" signifie une réflexion de l'état de la liaison de la fonction physique (PF), "yes" permet à la VF de communiquer avec d'autres VFs sur cet hôte même si l'état de la liaison PF est arrêté, "no" fait que le matériel abandonne tous les paquets envoyés par la VF. Lorsqu'elle n'est pas définie, le comportement par défaut du noyau sera utilisé.

Ajouté dans la version 251.

MACAddress=

Spécifie l'adresse MAC pour la fonction virtuelle.

Ajouté dans la version 251.

[ENERGYEFFICIENTETHERNET] OPTIONS DE SECTION

OPTIONS

La section [EnergyEfficientEthernet] contrôle la fonctionnalité Energy Efficient Ethernet (EEE) de l'interface et accepte les clés suivantes.

Enable=

Prend un argument booléen. Si vrai, la fonctionnalité Energy Efficient Ethernet (EEE) sera activée sur l'interface. La valeur par défaut est non définie, et l'activation de l'EEE ne sera pas modifiée.

Ajouté dans la version 258.

TxLowPowerIdle=

Prend un argument booléen. Si vrai, le mode de transmission Low Power Idle (Tx-LPI) de la fonctionnalité Energy Efficient Ethernet sera activé sur l'interface. La valeur par défaut est non définie, et l'activation du mode ne sera pas modifiée.

Ajouté dans la version 258.

TxLowPowerIdleSec=

Prend une durée. Ceci configure combien de temps l'interface ne doit pas entrer en mode Low Power Idle après la transmission. Si elle est trop courte, cela peut diminuer les performances. Si elle est trop longue, cela peut ne pas permettre de réaliser des économies d'énergie. La valeur par défaut est non définie, et la durée ne sera pas modifiée.

Ajouté dans la version 258.

LinkMode=

Prend une liste de modes de liaison, par ex. "1000baset-full". Voir le tableau pour le réglage Advertise= dans la section [Link] ci-dessus pour les valeurs possibles. Ceci configure les modes de connexion compatibles Energy Efficient Ethernet à annoncer. La valeur par défaut est non définie, et les modes annoncés ne seront pas modifiés.

Ajouté dans la version 258.

"%v" Version du noyau (Kernel release) Identique à la sortie de uname -r.
"%V" Répertoire pour les fichiers temporaires plus grands et persistants Il s'agit soit de /var/tmp, soit du chemin défini par "$TMPDIR", "$TEMP" ou "$TMP". (Notez que le répertoire peut être spécifié sans barre oblique finale.)
"%w" Identifiant de la version du système d'exploitation L'identifiant de la version du système d'exploitation du système en cours d'exécution, tel que lu dans le champ VERSION_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%W" Identifiant de la variante du système d'exploitation L'identifiant de la variante du système d'exploitation du système en cours d'exécution, tel que lu dans le champ VARIANT_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.

EXEMPLES

Exemple 1. /usr/lib/systemd/network/99-default.link

Le fichier de liaison 99-default.link fourni avec systemd définit les stratégies par défaut pour le nom de l'interface, les noms alternatifs et l'adresse MAC des liaisons.

[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel database onboard slot path
AlternativeNamesPolicy=database onboard slot path
MACAddressPolicy=persistent

Exemple 2. /etc/systemd/network/10-dmz.link

Cet exemple attribue le nom fixe "dmz0" à l'interface ayant l'adresse MAC 00:a0:de:63:7a:e6 :

[Match]
MACAddress=00:a0:de:63:7a:e6
[Link]
Name=dmz0

NamePolicy= n'est pas défini, donc Name= prend effet. Nous utilisons le préfixe "10-" pour classer ce fichier tôt dans la liste. Notez qu'il doit être placé avant 99-default.link, c'est-à-dire qu'il doit avoir un préfixe numérique, pour avoir un quelconque effet.

Exemple 3. (Ré)appliquer un fichier .link à une interface

Après la création d'un nouveau fichier .link ou la modification d'un fichier .link existant, les nouveaux réglages peuvent être appliqués à l'interface correspondante avec les commandes suivantes :

$ sudo udevadm control --reload
$ sudo ip link set eth0 down
$ sudo udevadm trigger --verbose --settle --action add /sys/class/net/eth0

Vous pourriez également avoir besoin d'arrêter le service qui gère l'interface réseau, par ex. systemd-networkd.service(8) ou NetworkManager.service avant l'opération ci-dessus, puis redémarrer le service après. Pour plus de détails sur la commande udevadm, voir udevadm(8).

Exemple 4. Débogage des affectations NamePolicy=

$ sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/hub0
...

ID_NET_DRIVER=cdc_ether

La configuration explicite Name= l'emporte dans ce cas.

sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/enp0s31f6
...
Parsed configuration file /usr/lib/systemd/network/99-default.link
Parsed configuration file /etc/systemd/network/10-eth0.link
Created link configuration context.
ID_NET_DRIVER=e1000e
Config file /usr/lib/systemd/network/99-default.link applies to device enp0s31f6
link_config: autonegotiation is unset or enabled, the speed and duplex are not writable.
enp0s31f6: Device has name_assign_type=4
Using default interface naming scheme 'v240'.
enp0s31f6: Policy *keep*: keeping existing userspace name
enp0s31f6: Device has addr_assign_type=0
enp0s31f6: MAC on the device already matches policy *persistent*
ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
...

Dans ce cas, l'interface a déjà été renommée, donc la politique keep spécifiée comme première option dans 99-default.link signifie que le nom existant est préservé. Si keep était supprimé, ou si cela se produisait avant le renommage, nous pourrions obtenir ce qui suit à la place :

enp0s31f6: Policy *path* yields "enp0s31f6".
enp0s31f6: Device has addr_assign_type=0
enp0s31f6: MAC on the device already matches policy *persistent*
ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
ID_NET_NAME=enp0s31f6
...

Veuillez noter que les détails de la sortie sont sujets à modification.

Exemple 5. /etc/systemd/network/10-internet.link

Cet exemple attribue le nom fixe "internet0" à l'interface avec le chemin de périphérique "pci-0000:00:1a.0-*" :

[Match]
Path=pci-0000:00:1a.0-*
[Link]
Name=internet0

Exemple 6. /etc/systemd/network/25-wireless.link

Voici un exemple trop complexe qui montre l'utilisation d'un grand nombre de réglages [Match] et [Link].

[Link]
