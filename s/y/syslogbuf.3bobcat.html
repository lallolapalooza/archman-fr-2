FBB::SyslogBuf(3bobcat) Tampon de flux pour Syslog FBB::SyslogBuf(3bobcat)

NOM

FBB::SyslogBuf - Un objet streambuf insérant des messages syslog

SYNOPIS

#include <bobcat/syslogbuf>
Option de liaison : -lbobcat

DESCRIPTION

Les adresses des objets FBB::SyslogBuf peuvent être passées comme adresses std::streambuf à des objets std::ostream pour écrire des messages au démon syslog en utilisant les facilités de flux.

Des insertions multiples et séparées peuvent être utilisées pour créer un seul message syslog : le message n'est envoyé au démon syslog qu'après avoir reçu une commande flush (par exemple, après avoir inséré std::flush ou std::endl). Les caractères non imprimables (comme ’\n’) apparaissent dans le message syslog sous forme de valeurs octales, précédées de # (par exemple, #012 pour ’\n’). Le retour à la ligne normalement inséré par std::endl est ignoré : les objets SyslogStream interprètent std::endl comme std::flush.

Une série d'insertions peut contenir plusieurs manipulateurs std::endl ou std::flush. À chacun de ces manipulateurs, un nouveau message est envoyé au démon syslog, contenant toutes les informations qui ont été mises en tampon jusqu'à présent. Après avoir envoyé un message au démon syslog, le tampon interne du SyslogStream est vidé.

ESPACE DE NOMMAGE

CONSTRUCTEUR

o
SyslogBuf(string const &ident = "", FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0) :
Le paramètre ident est généralement le nom du programme. Son contenu est préfixé aux messages syslog.
Le paramètre priority détermine l'importance par défaut du message envoyé au démon syslog. Par défaut, les messages sont envoyés au démon syslog avec la priorité FBB::NOTICE. Les messages syslog peuvent recevoir une priorité différente en insérant un manipulateur SyslogStream(3bobcat). La priorité définie lors de la construction peut également être modifiée en utilisant les membres setPriority et setDefaultPriority.
Les messages qui apparaissent effectivement dans les facilités de journalisation ne sont pas déterminés par les priorités des messages, mais par le masque de journalisation de syslog. Le masque de journalisation peut être défini par le membre statique setMask (voir ci-dessous).
Le paramètre facility détermine le type de programme qui enregistre les messages. Par défaut, FBB::USER est utilisé.
Le paramètre option peut être utilisé pour spécifier diverses options (utilisez l'opérateur binaire `bitor` (`|`) pour combiner les options) :
LOG_CONS : écrire directement sur la console système en cas d'erreur lors de l'envoi au journal système
LOG_NDELAY : ouvrir la connexion immédiatement (normalement, la connexion est ouverte lors du premier message enregistré)
LOG_PERROR : imprimer également sur stderr
LOG__PID : inclure le PID avec chaque message
Par défaut, aucune option n'est utilisée.

Les constructeurs de copie et de déplacement (et les opérateurs d'affectation) ne sont pas disponibles.

FONCTIONS MEMBRES

Tous les membres de std::streambuf sont disponibles, car FBB::SyslogBuf hérite de cette classe.

o
Priority defaultPriority() const :
Retourne la priorité par défaut actuelle. C'est-à-dire la priorité qui sera utilisée pour les messages après l'insertion de endl ou flush.
o
void eoi() :
Si le tampon interne du SyslogStream n'est pas vide, il est vidé vers le démon syslog. Ensuite, closelog(3) est appelé. Au lieu d'utiliser ce membre, le manipulateur eoi peut également être utilisé.
o
Priority priority() const :
Retourne la priorité suivante. C'est-à-dire la priorité qui sera utilisée pour le prochain message envoyé au démon syslog.
o
void reset(string const &ident, FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0) :
Redéfinit l'identifiant, la priorité, la facilité et les options actuelles utilisées lors de l'envoi de messages au démon syslog. Si le tampon interne du SyslogStream n'est pas vide, il est d'abord vidé vers le démon syslog.

DESCRIPTION

The SyslogBuf class is a stream-buffer that redirects its output to the syslog daemon.

When SyslogBuf is used to construct an std::ostream object, the output sent to that stream object will be forwarded to the syslog daemon. The default priority and facility values can be controlled by the constructor parameters.

The open() member function may be used to re-initialise the stream-buffer, and the close() member function closes the stream-buffer and forces any buffered data to be written to the syslog daemon.

The setFacility() and setOption() member functions allow the caller to modify the facility and option values used by the syslog daemon.

The setPriority() member function allows the caller to set the priority of the next message to be written. This priority setting is only valid for the next message, and is reset to the default priority afterwards.

The setDefaultPriority() member function allows the caller to set the default priority for subsequent messages.

The FBB::eoi manipulator can be inserted into the stream object to close the stream-buffer. It behaves identically to the close() member function.

EXAMPLE

#include <iostream>
#include <bobcat/syslogbuf>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    // Create a syslog stream buffer, using the program name as the identifier
    SyslogBuf ssb(argv[0]);
    // Create an ostream using the syslog stream buffer
    ostream sls(&ssb);
    // Send a debug message to the syslog daemon
    sls << SyslogStream::debug << "Hello world" << flush;
    // Send an error message with the current error code
    sls << SyslogStream::errcode << "An error occurred" << endl;
    // Close the syslog stream buffer
    sls << FBB::eoi;
    return 0;
}

BUGS

The open() and constructor functions that take `option` and `facility` arguments take them as `int` rather than the appropriate enumeration types. This means that it is the responsibility of the programmer to ensure that valid enumeration values are passed.
