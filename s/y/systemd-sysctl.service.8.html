NOM

systemd-sysctl.service, systemd-sysctl - Configurer les paramètres du noyau au démarrage

SYNTAXE

/usr/lib/systemd/systemd-sysctl [OPTIONS...] [FICHIER_CONFIG...]

systemd-sysctl.service

DESCRIPTION

systemd-sysctl.service est un service de démarrage précoce qui configure les paramètres du noyau sysctl(8) en invoquant /usr/lib/systemd/systemd-sysctl.

Lorsqu'il est invoqué sans arguments, /usr/lib/systemd/systemd-sysctl applique toutes les directives des fichiers de configuration listés dans sysctl.d(5). Si un ou plusieurs noms de fichiers sont passés en ligne de commande, seules les directives de ces fichiers sont appliquées.

De plus, l'option --prefix= peut être utilisée pour limiter les paramètres sysctl appliqués.

Voir sysctl.d(5) pour des informations sur la configuration des paramètres sysctl. Après la modification de la configuration sysctl sur le disque, elle doit être écrite dans les fichiers de /proc/sys/ avant de prendre effet. Il est possible de mettre à jour des paramètres spécifiques, ou simplement de recharger toute la configuration, voir les Exemples ci-dessous.

OPTIONS

--prefix=

Applique uniquement les règles avec le préfixe spécifié.

Ajouté dans la version 230.

--strict=

Retourne toujours un code de sortie non nul en cas d'échec (y compris un nom de variable sysctl invalide et des autorisations insuffisantes), sauf si le nom de la variable sysctl est préfixé par un caractère "-".

Ajouté dans la version 252.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé en commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties « intéressantes » des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé en commentaire.

--no-pager

Ne redirige pas la sortie vers un paginateur.

-h, --help

Imprime un court message d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

IDENTIFIANTS

systemd-sysctl prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour plus de détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

sysctl.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier de configuration sysctl.d/. Si cet identifiant est passé, il est traité après tous les fichiers drop-in lus à partir du système de fichiers. Les paramètres configurés dans l'identifiant prennent donc la priorité sur ceux du système de fichiers.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-sysctl.service est configuré pour hériter de l'identifiant « sysctl.extra » du gestionnaire de service.

EXEMPLES

Exemple 1. Réinitialiser tous les paramètres sysctl

systemctl restart systemd-sysctl

Exemple 2. Afficher la configuration du gestionnaire de coredump

# sysctl kernel.core_pattern
kernel.core_pattern = |/usr/libexec/abrt-hook-ccpp %s %c %p %u %g %t %P %I

Exemple 3. Mettre à jour la configuration du gestionnaire de coredump

# /usr/lib/systemd/systemd-sysctl --prefix kernel.core_pattern

Cela recherche dans tous les répertoires listés dans sysctl.d(5) les fichiers de configuration et écrit /proc/sys/kernel/core_pattern.

Exemple 4. Mettre à jour la configuration du gestionnaire de coredump selon un fichier spécifique

# /usr/lib/systemd/systemd-sysctl 50-coredump.conf

Cela applique tous les paramètres trouvés dans 50-coredump.conf. Soit /etc/sysctl.d/50-coredump.conf, soit /run/sysctl.d/50-coredump.conf, soit /usr/lib/sysctl.d/50-coredump.conf sera utilisé, dans l'ordre de préférence.

Voir sysctl(8) pour diverses manières d'appliquer directement les paramètres sysctl.
