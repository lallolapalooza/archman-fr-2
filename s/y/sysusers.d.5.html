SYSUSERS.D(5) sysusers.d SYSUSERS.D(5)

NOM

sysusers.d - Allocation déclarative des utilisateurs et groupes système

SYNTAXE

/etc/sysusers.d/*.conf
/run/sysusers.d/*.conf
/usr/local/lib/sysusers.d/*.conf
/usr/lib/sysusers.d/*.conf
#Type Nom       ID                  GECOS              Répertoire personnel Shell
u     nom_utilisateur  uid                 "Description utilisateur" /home/dir      /chemin/vers/shell
u     nom_utilisateur  uid:gid             "Description utilisateur" /home/dir      /chemin/vers/shell
u     nom_utilisateur  /chemin/appartient/utilisateur "Description utilisateur" /home/dir      /chemin/vers/shell
g     nom_groupe  gid
g     nom_groupe  /chemin/appartient/groupe
m     nom_utilisateur  nom_groupe
r     -          plus-bas-plus-haut

DESCRIPTION

systemd-sysusers utilise les fichiers du répertoire sysusers.d pour créer des utilisateurs et groupes système et pour ajouter des utilisateurs à des groupes, lors de l'installation d'un paquet ou au démarrage. Cet outil peut être utilisé pour allouer uniquement des utilisateurs et groupes système, il n'est pas utile pour créer des utilisateurs et groupes non système (c'est-à-dire normaux, "humains"), car il accède directement à /etc/passwd et /etc/group, contournant ainsi toute base de données utilisateur plus complexe, par exemple toute base de données impliquant NIS ou LDAP.

RÉPERTOIRES DE CONFIGURATION ET PRIORITÉ

Chaque fichier de configuration doit être nommé dans le style paquet.conf ou paquet-partie.conf. La seconde variante devrait être utilisée lorsqu'il est souhaitable de faciliter la substitution d'une partie spécifique de la configuration.

Les fichiers dans /etc/sysusers.d remplacent les fichiers portant le même nom dans /usr/lib/sysusers.d et /run/sysusers.d. Les fichiers dans /run/sysusers.d remplacent les fichiers portant le même nom dans /usr/lib/sysusers.d. Les paquets doivent installer leurs fichiers de configuration dans /usr/lib/sysusers.d. Les fichiers dans /etc/sysusers.d sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du vendeur. Tous les fichiers de configuration sont triés par leur nom de fichier dans l'ordre lexicographique, quelle que soit la répertoire dans lequel ils se trouvent. Si plusieurs fichiers spécifient le même chemin, l'entrée du fichier portant le nom le plus ancien lexicographiquement sera appliquée. Toutes les entrées ultérieures pour les mêmes noms d'utilisateur et de groupe seront signalées comme des avertissements.

Si l'administrateur souhaite désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans /etc/sysusers.d/ portant le même nom de fichier.

FORMAT DES FICHIERS DE CONFIGURATION

Le format du fichier est une ligne par utilisateur ou groupe contenant le nom, l'ID, la description du champ GECOS, le répertoire personnel et le shell de connexion :

#Type Nom     ID             GECOS                 Répertoire personnel Shell
u!    httpd    404            "Utilisateur HTTP"
u!    _authd   /usr/bin/authd "Utilisateur d'autorisation"
u!    postgres -              "Base de données Postgreql" /var/lib/pgsql /usr/libexec/postgresdb
g     input    -              -
m     _authd   input
u     root     0              "Superutilisateur"           /root          /bin/zsh
r     -        500-900

Les lignes vides et les lignes commençant par le caractère "#" sont ignorées et peuvent être utilisées pour les commentaires.

Type

Le type se compose d'une seule lettre. Les types de ligne suivants sont compris :

u

Crée un utilisateur et un groupe système du nom spécifié s'ils n'existent pas encore. Le groupe primaire de l'utilisateur sera défini comme le groupe portant le même nom, sauf si le champ ID le spécifie. Le compte sera créé désactivé, de sorte que les connexions ne soient pas autorisées.

Le type u peut être suffixé d'un point d'exclamation ("u!") pour créer un compte entièrement verrouillé. Ceci est recommandé, car les connexions ne devraient généralement pas être autorisées pour les utilisateurs système. Avec ou sans point d'exclamation, un mot de passe invalide est défini. Pour "u!", le compte est également verrouillé, ce qui fait une différence pour les formes d'authentification sans mot de passe, comme SSH ou similaire.

Ajouté dans la version 215.

g

Crée un groupe système du nom spécifié s'il n'existe pas encore. Notez que u crée implicitement un groupe correspondant. Le groupe sera créé sans mot de passe.

Ajouté dans la version 215.

m

Ajoute un utilisateur à un groupe. Si l'utilisateur ou le groupe n'existent pas encore, ils seront créés implicitement.

Ajouté dans la version 215.

r

Ajoute une plage d'UIDs/GIDs numériques au pool pour allouer de nouveaux UIDs et GIDs. Si aucune ligne de ce type n'est spécifiée, la plage d'UIDs/GIDs est définie sur une valeur par défaut compilée. Notez que les UIDs et GIDs sont alloués à partir du même pool, afin de garantir que les utilisateurs et les groupes portant le même nom portent probablement le même UID et GID numérique.

Ajouté dans la version 216.

Nom

Le champ nom spécifie le nom de l'utilisateur ou du groupe. Le nom spécifié doit uniquement contenir les caractères a-z, A-Z, 0-9, "_" et "-", à l'exception du premier caractère qui doit être l'un des a-z, A-Z ou "_" (c'est-à-dire que les chiffres et "-" ne sont pas autorisés comme premier caractère). Le nom d'utilisateur/groupe doit avoir au moins un caractère, et au plus 31.

Pour plus de détails sur la syntaxe des noms d'utilisateur/groupe, voir Syntaxe des noms d'utilisateur/groupe[1].

Il est fortement recommandé de choisir des noms d'utilisateur et de groupe qui ont peu de chances d'entrer en conflit avec les utilisateurs normaux créés par l'administrateur. Un bon schéma pour garantir cela est de préfixer tous les noms système et groupe avec un tiret bas, et d'éviter les noms trop génériques.

Pour les lignes m, ce champ doit contenir le nom d'utilisateur à ajouter à un groupe.

Pour les lignes de type r, ce champ doit être défini sur "-".

ID

Pour u et g, l'UID ou GID numérique 32 bits de l'utilisateur/groupe. N'utilisez pas les ID 65535 ou 4294967295, car ils ont des significations spéciales de substitution. Spécifiez "-" pour une allocation automatique d'UID/GID pour l'utilisateur ou le groupe (ceci est fortement recommandé sauf s'il est strictement nécessaire d'utiliser un UID ou GID spécifique). Alternativement, spécifiez un chemin absolu dans le système de fichiers. Dans ce cas, l'UID/GID est lu à partir du propriétaire/groupe du chemin. Ceci est utile pour créer des utilisateurs dont l'UID/GID correspond aux propriétaires de fichiers préexistants (tels que les binaires SUID ou SGID). Les syntaxes "uid:gid" et "uid:nom_groupe" sont prises en charge pour permettre la création d'utilisateurs avec des groupes primaires spécifiques. Le groupe donné doit être créé explicitement, ou il doit déjà exister. Spécifier "-" pour l'UID dans ces syntaxes est également pris en charge.

Pour les lignes m, ce champ doit contenir le nom du groupe auquel ajouter l'utilisateur.

Pour les lignes de type r, ce champ doit être défini sur une plage d'UID/GID au format "DE-À", où les deux valeurs sont formatées comme des nombres ASCII décimaux. Alternativement, un seul UID/GID peut être spécifié au format décimal ASCII.

GECOS

Une chaîne courte et descriptive pour les utilisateurs à créer, entourée de guillemets. Notez que ce champ ne doit pas contenir de deux-points.

S'applique uniquement aux lignes de type u et doit sinon être laissé non défini (ou "-").

Répertoire personnel

Le répertoire personnel d'un nouvel utilisateur système. S'il est omis, la valeur par défaut est le répertoire racine.

S'applique uniquement aux lignes de type u et doit sinon être laissé non défini (ou "-"). Il est recommandé de l'omettre, sauf si le logiciel exige strictement qu'un répertoire personnel soit défini.

systemd-sysusers ne définit que l'entrée du répertoire personnel dans la base de données utilisateur. Pour créer réellement le répertoire, envisagez d'ajouter un fragment tmpfiles.d(5) correspondant.

Ne s'applique qu'aux lignes de type u et doit sinon être laissé non défini (ou "-"). Il est recommandé d'omettre ceci, à moins qu'un shell différent de /usr/sbin/nologin ne doive être utilisé.

SPÉCIFICATEURS

Les spécificateurs peuvent être utilisés dans les champs "Nom", "ID", "GECOS", "Répertoire personnel" et "Shell". Un spécificateur inconnu ou non résoluble est traité comme une configuration invalide. Les expansions suivantes sont comprises :

Tableau 1. Spécificateurs disponibles

Spécificateur Signification Détails
"%a" Architecture Une chaîne courte identifiant l'architecture du système local. Une chaîne telle que x86, x86-64 ou arm64. Voir les architectures définies pour ConditionArchitecture= dans systemd.unit(5) pour une liste complète.
"%A" Version de l'image du système d'exploitation L'identifiant de version de l'image du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ IMAGE_VERSION= de /etc/os-release. S'il n'est pas défini, il est résolu en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%b" ID de démarrage L'ID de démarrage du système en cours d'exécution, formaté en chaîne. Voir random(4) pour plus d'informations.
"%B" ID de construction du système d'exploitation L'identifiant de construction du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ BUILD_ID= de /etc/os-release. S'il n'est pas défini, il est résolu en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%H" Nom d'hôte Le nom d'hôte du système en cours d'exécution.
"%l" Nom d'hôte court Le nom d'hôte du système en cours d'exécution, tronqué au premier point pour supprimer tout composant de domaine.
"%m" ID de machine L'ID de machine du système en cours d'exécution, formaté en chaîne. Voir machine-id(5) pour plus d'informations.
"%M" Identifiant de l'image du système d'exploitation L'identifiant de l'image du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ IMAGE_ID= de /etc/os-release. S'il n'est pas défini, il est résolu en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%o" ID du système d'exploitation L'identifiant du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ ID= de /etc/os-release. Voir os-release(5) pour plus d'informations.
"%q" Nom d'hôte joliment formaté Le nom d'hôte joliment formaté du système en cours d'exécution, tel que lu à partir du champ PRETTY_HOSTNAME= de /etc/machine-info. S'il n'est pas défini, il est résolu en le nom d'hôte court. Voir machine-info(5) pour plus d'informations.
"%T" Répertoire pour les fichiers temporaires Il s'agit soit de /tmp, soit du chemin défini par "$TMPDIR", "$TEMP" ou "$TMP". (Notez que le répertoire peut être spécifié sans barre oblique finale.)
"%v" Version du noyau Identique à la sortie de uname -r.
"%V" Répertoire pour les fichiers temporaires plus volumineux et persistants Il s'agit soit de /var/tmp, soit du chemin défini par "$TMPDIR", "$TEMP" ou "$TMP". (Notez que le répertoire peut être spécifié sans barre oblique finale.)
"%w" ID de version du système d'exploitation L'identifiant de version du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ VERSION_ID= de /etc/os-release. S'il n'est pas défini, il est résolu en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%W" ID de variante du système d'exploitation L'identifiant de variante du système d'exploitation du système en cours d'exécution, tel que lu à partir du champ VARIANT_ID= de /etc/os-release. S'il n'est pas défini, il est résolu en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%%" Un seul signe de pourcentage Utilisez "%%" au lieu de "%" pour spécifier un seul signe de pourcentage.

IDEMPOTENCE

Notez que
systemd-sysusers ne fera rien si les utilisateurs ou groupes spécifiés existent déjà ou si les utilisateurs sont membres des groupes spécifiés, il n'y a donc normalement aucune raison de outrepasser la configuration du fournisseur sysusers.d, sauf pour bloquer la création de certains utilisateurs ou groupes.
