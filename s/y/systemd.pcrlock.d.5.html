NOM

systemd.pcrlock, systemd.pcrlock.d - Fichiers de prédiction de mesures PCR

SYNOPIS

/etc/pcrlock.d/*.pcrlock
/etc/pcrlock.d/*.pcrlock.d/*.pcrlock
/run/pcrlock.d/*.pcrlock
/run/pcrlock.d/*.pcrlock.d/*.pcrlock
/var/lib/pcrlock.d/*.pcrlock
/var/lib/pcrlock.d/*.pcrlock.d/*.pcrlock
/usr/local/lib/pcrlock.d/*.pcrlock
/usr/local/lib/pcrlock.d/*.pcrlock.d/*.pcrlock
/usr/lib/pcrlock.d/*.pcrlock
/usr/lib/pcrlock.d/*.pcrlock.d/*.pcrlock

DESCRIPTION

Les fichiers *.pcrlock définissent les mesures attendues des PCR TPM2 des composants impliqués dans le processus de démarrage. systemd-pcrlock(8) utilise ces fichiers pcrlock pour analyser et prédire les mesures des PCR TPM2. Les fichiers pcrlock sont des tableaux JSON qui suivent un sous-ensemble de la spécification du Format du Journal d'Événements Canonique TCG (CEL-JSON)[1]. Spécifiquement, les champs d'enregistrement "recnum", "content" et "content_type" ne sont pas utilisés et sont ignorés s'ils sont présents. Chaque fichier pcrlock définit un ensemble de mesures PCR attendues et ordonnées d'un composant spécifique du démarrage.

Les fichiers *.pcrlock peuvent être placés dans divers répertoires de type .d/ (voir ci-dessus pour une liste complète). Tous les fichiers correspondants découverts dans ces répertoires sont triés par ordre alphabétique de leur nom de fichier (sans tenir compte du répertoire réel dans lequel ils ont été trouvés) : les fichiers pcrlock avec des noms alphabétiquement plus petits sont censés couvrir des mesures effectuées avant ceux avec des noms alphabétiquement plus grands. Afin de rendre le positionnement des fichiers pcrlock pratique dans le processus de démarrage, les fichiers sont attendus (par convention, ce n'est pas imposé) d'être nommés "NNN-composant.pcrlock" (où NNN est un nombre décimal à trois chiffres), par exemple 750-enter-initrd.pcrlock.

Pour divers composants du processus de démarrage, plus d'un fichier pcrlock alternatif sera supporté (c'est-à-dire des "variantes"). Par exemple, pour couvrir plusieurs noyaux installés en parallèle dans la politique d'accès, ou plusieurs versions du chargeur de démarrage. Ceci peut être fait en plaçant *.pcrlock.d/*.pcrlock dans les répertoires de type drop-in, c'est-à-dire un répertoire commun pour un composant spécifique, qui contient un ou plusieurs fichiers pcrlock couvrant chacun une variante du composant. Exemple : 650-kernel.pcrlock.d/6.5.5-200.fc38.x86_64.pcrlock et 650-kernel.pcrlock.d/6.5.7-100.fc38.x86_64.pcrlock

Utilisez systemd-pcrlock list-components pour lister tous les fichiers pcrlock actuellement installés.

Utilisez les différentes commandes lock-* de systemd-pcrlock pour générer automatiquement des fichiers pcrlock adéquats pour divers types de ressources.

COMPOSANTS BIEN CONNUS

Les composants du processus de démarrage peuvent être définis librement par l'administrateur ou le fournisseur du système d'exploitation. Les composants suivants sont cependant bien connus et définis par systemd. La liste ci-dessous est utile pour ordonner correctement les fichiers pcrlock locaux par rapport à ces composants du démarrage.

240-secureboot-policy.pcrlock

La politique SecureBoot, telle qu'enregistrée dans le PCR 7. Peut être généré via systemd-pcrlock lock-secureboot-policy.

Ajouté dans la version 255.

250-firmware-code-early.pcrlock

Les mesures du code du firmware, enregistrées dans les PCR 0 et 2, jusqu'à la mesure du séparateur (voir 400-secureboot-separator.pcrlock ci-dessous). Peut être généré via systemd-pcrlock lock-firmware-code.

Ajouté dans la version 255.

250-firmware-config-early.pcrlock

Les mesures de configuration du firmware, enregistrées dans les PCR 1 et 3, jusqu'à la mesure du séparateur (voir 400-secureboot-separator.pcrlock ci-dessous). Peut être généré via systemd-pcrlock lock-firmware-config.

Ajouté dans la version 255.

350-action-efi-application.pcrlock

La mesure EFI "Application" effectuée une fois par le firmware. Définie statiquement.

Ajouté dans la version 255.

400-secureboot-separator.pcrlock

La mesure EFI "separator" sur le PCR 7 effectuée une fois par le firmware pour indiquer où le contrôle du firmware passe au contrôle du chargeur de démarrage/système d'exploitation. Définie statiquement.

Ajouté dans la version 255.

500-separator.pcrlock

Les mesures EFI "separator" sur les PCR 0-6 effectuées une fois par le firmware pour indiquer où le contrôle du firmware passe au contrôle du chargeur de démarrage/système d'exploitation. Définie statiquement.

Ajouté dans la version 255.

550-firmware-code-late.pcrlock

Les mesures du code du firmware, enregistrées dans les PCR 0 et 2, après la mesure du séparateur (voir 400-secureboot-separator.pcrlock ci-dessus). Peut être généré via systemd-pcrlock lock-firmware-code.

Ajouté dans la version 255.

550-firmware-config-late.pcrlock

Les mesures de configuration du firmware, enregistrées dans les PCR 1 et 3, après la mesure du séparateur (voir 400-secureboot-separator.pcrlock ci-dessus). Peut être généré via systemd-pcrlock lock-firmware-config.

Ajouté dans la version 255.

600-gpt.pcrlock

La table de partitions GPT du média amorcé, enregistrée dans le PCR 5 par le firmware. Peut être généré via systemd-pcrlock lock-gpt.

Ajouté dans la version 255.

620-secureboot-authority.pcrlock

L'autorité SecureBoot, enregistrée dans le PCR 7. Peut être généré via systemd-pcrlock lock-secureboot-authority.

Ajouté dans la version 255.

700-action-efi-exit-boot-services.pcrlock

L'action EFI générée lorsque ExitBootServices() est généré, c'est-à-dire lorsque l'environnement UEFI est quitté et que le système d'exploitation prend le relais. Couvre la mesure du PCR 5. Définie statiquement.

Ajouté dans la version 255.

710-kernel-cmdline.pcrlock

La ligne de commande du noyau, mesurée par le noyau Linux dans le PCR 9. Peut être généré via systemd-pcrlock lock-kernel-cmdline.

Ajouté dans la version 255.

720-kernel-initrd.pcrlock

L'initrd du noyau, mesuré par le noyau Linux dans le PCR 9. Peut être généré via systemd-pcrlock lock-kernel-initrd.

Ajouté dans la version 255.

750-enter-initrd.pcrlock

La mesure que systemd-pcrphase-initrd.service(8) fait dans le PCR 11 lorsque l'initrd s'initialise. Définie statiquement.

Ajouté dans la version 255.

800-leave-initrd.pcrlock

La mesure que systemd-pcrphase-initrd.service(8) fait dans le PCR 11 lorsque l'initrd se termine. Définie statiquement.

Ajouté dans la version 255.

820-machine-id.pcrlock

La mesure que systemd-pcrmachine.service(8) fait au démarrage, couvrant le contenu de /etc/machine-id. Peut être généré via systemd-pcrlock lock-machine-id.

Ajouté dans la version 255.

830-root-file-system.pcrlock

La mesure que systemd-pcrfs-root.service(8) fait au démarrage, couvrant l'identité du système de fichiers racine. Peut être généré via systemd-pcrlock lock-file-system.

Ajouté dans la version 255.

850-sysinit.pcrlock

La mesure que systemd-pcrphase-sysinit.service(8) fait lorsque l'espace utilisateur principal a effectué une initialisation de base et procédera maintenant au démarrage des services système réguliers. Définie statiquement.

Ajouté dans la version 255.

900-ready.pcrlock

La mesure que systemd-pcrphase.service(8) fait lorsque le système a entièrement démarré. Définie statiquement.

Ajouté dans la version 255.

950-shutdown.pcrlock

La mesure que systemd-pcrphase.service(8) fait lorsque le système commence son arrêt. Définie statiquement.

Ajouté dans la version 255.

990-final.pcrlock

La mesure que systemd-pcrphase-sysinit.service(8) fait lorsque le système est sur le point de terminer son arrêt. Définie statiquemest défini.

Ajouté dans la version 255.
