NOM

systemd.automount - Configuration des unités d'automontage

SYNTAXE

automount.automount

DESCRIPTION

Un fichier de configuration d'unité dont le nom se termine par ".automount" encode des informations sur un point de montage de système de fichiers à monter automatiquement et à superviser par systemd. Les unités d'automontage peuvent être utilisées pour implémenter le montage à la demande ainsi que le montage parallèle de systèmes de fichiers.

Cette page de manuel liste les options de configuration spécifiques à ce type d'unité. Voir systemd.unit(5) pour les options communes à tous les fichiers de configuration d'unité. Les éléments de configuration communs sont configurés dans les sections génériques [Unit] et [Install]. Les options de configuration spécifiques à l'automontage sont configurées dans la section [Automount].

Les unités d'automontage doivent être nommées d'après les répertoires d'automontage qu'elles contrôlent. Exemple : le point d'automontage /home/lennart doit être configuré dans un fichier d'unité home-lennart.automount. Pour plus de détails sur la logique d'échappement utilisée pour convertir un chemin de système de fichiers en nom d'unité, voir systemd.unit(5). Notez que les unités d'automontage ne peuvent pas être utilisées comme modèles, et il n'est pas possible d'ajouter plusieurs noms à une unité d'automontage en créant des liens symboliques vers son fichier d'unité.

Pour chaque fichier d'unité d'automontage, un fichier d'unité de montage correspondant (voir systemd.mount(5) pour les détails) doit exister et être activé lorsque le chemin d'automontage est accédé. Exemple : si une unité d'automontage home-lennart.automount est active et que l'utilisateur accède à /home/lennart, l'unité de montage home-lennart.mount sera activée.

Notez que les unités d'automontage sont distinctes du montage lui-même, vous ne devriez donc pas définir After= ou Requires= pour les dépendances de montage ici. Par exemple, vous ne devriez pas définir After=network-online.target ou similaire pour les systèmes de fichiers réseau. Faire ainsi peut entraîner un cycle d'ordonnancement.

Notez que la prise en charge de l'automontage sous Linux est privilégiée. Les unités d'automontage ne sont donc disponibles que dans le gestionnaire de services système (et le gestionnaire de services utilisateur de root), mais pas dans les gestionnaires de services des utilisateurs non privilégiés.

Notez que les unités d'automontage ne doivent pas être imbriquées. (L'établissement du point d'automontage intérieur épinglerait de manière inconditionnelle le point de montage extérieur, annulant son objectif.)

DÉPENDANCES AUTOMATIQUES

Dépendances implicites

Les dépendances suivantes sont ajoutées implicitement :

•Si une unité d'automontage se trouve sous une autre unité de montage dans la hiérarchie du système de fichiers, des dépendances de nécessité et d'ordonnancement sont créées vers l'unité supérieure dans la hiérarchie.
•Une dépendance implicite Before= est créée entre une unité d'automontage et l'unité de montage qu'elle active.

Dépendances par défaut

Les dépendances suivantes sont ajoutées sauf si DefaultDependencies=no est défini :

•Les unités d'automontage acquièrent des dépendances automatiques Before= et Conflicts= sur umount.target afin d'être arrêtées lors de l'extinction.
•Les unités d'automontage acquièrent automatiquement une dépendance After= sur local-fs-pre.target, et une dépendance Before= sur local-fs.target.

FSTAB

Les unités d'automontage peuvent être configurées soit via des fichiers d'unité, soit via /etc/fstab (voir fstab(5) pour les détails).

Pour plus de détails sur la façon dont systemd analyse /etc/fstab, voir systemd.mount(5).

Si un point d'automontage est configuré à la fois dans /etc/fstab et dans un fichier d'unité, la configuration de ce dernier a la priorité.

OPTIONS

Les fichiers d'unité d'automontage peuvent inclure les sections [Unit] et [Install], qui sont décrites dans systemd.unit(5).

Les fichiers d'unité d'automontage doivent inclure une section [Automount], qui contient des informations sur les points d'automontage de système de fichiers qu'elle supervise. Les options spécifiques à la section [Automount] des unités d'automontage sont les suivantes :

Where=

Prend un chemin absolu d'un répertoire du point d'automontage. Si le point d'automontage n'existe pas au moment où le point d'automontage est installé, il est créé. Cette chaîne doit être reflétée dans le nom du fichier d'unité. (Voir ci-dessus.) Cette option est obligatoire.

ExtraOptions=

Options de montage supplémentaires à utiliser lors de la création du point de montage autofs. Prend une liste d'options séparées par des virgules. Ce paramètre est facultatif. Notez que l'expansion habituelle des spécificateurs est appliquée à ce paramètre. Les caractères de pourcentage littéraux doivent donc être écrits comme "%%".

Ajouté dans la version 250.

DirectoryMode=

Les répertoires des points d'automontage (et tout répertoire parent) sont automatiquement créés si nécessaire. Cette option spécifie le mode d'accès au système de fichiers utilisé lors de la création de ces répertoires. Prend un mode d'accès en notation octale. Par défaut 0755.

TimeoutIdleSec=

Configure un délai d'inactivité. Une fois que le montage est inactif pendant le temps spécifié, systemd tentera de le démonter. Prend une valeur sans unité en secondes, ou une durée telle que "5min 20s". Passer 0 désactive la logique de temporisation. La temporisation est désactivée par défaut.

Ajouté dans la version 220.

Consultez systemd.unit(5), systemd.exec(5), et systemd.kill(5) pour plus de paramètres.
