SYSTEMD-SYSUSERS(8) systemd-sysusers SYSTEMD-SYSUSERS(8)

NOM

systemd-sysusers, systemd-sysusers.service - Allouer des utilisateurs et groupes système

SYNTAXE

systemd-sysusers [OPTIONS...] [FICHIER_CONFIG...]

systemd-sysusers.service

DESCRIPTION

systemd-sysusers crée des utilisateurs et groupes système, basé sur des fichiers dont le format est décrit dans sysusers.d(5).

S'il est appelé sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par sysusers.d(5) sont exécutées. Lorsqu'il est appelé avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments fournis sur la ligne de commande sont utilisés à la place du fichier de configuration CHEMIN. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée à la place d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans aucune barre oblique), tous les répertoires de configuration sont recherchés pour trouver un fichier correspondant et le fichier trouvé ayant la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration d'autres fichiers correspondants.

OPTIONS

Les options suivantes sont comprises :

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés par le chemin racine alternatif donné, y compris les chemins de recherche de configuration.

Ajouté dans la version 215.

--image=image

Prend un chemin vers un fichier d'image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur les systèmes de fichiers stockés dans des images disque ou des périphériques bloc. L'image disque doit contenir soit un système de fichiers, soit un ensemble de systèmes de fichiers dans une table de partitions GPT, suivant la Spécification des Partitions Découvrables[1]. Pour plus d'informations sur les images disque prises en charge, voir le commutateur du même nom dans systemd-nspawn(1).

Ajouté dans la version 247.

--image-policy=politique

Prend une chaîne de politique d'image comme argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si elle n'est pas spécifiée, la politique par défaut est "*", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=CHEMIN

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans sysusers.d(5) seront lus, et la configuration donnée sur la ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration CHEMIN.

Cette option est destinée à être utilisée lors de l'exécution de scripts d'installation de paquets et que les fichiers appartenant à ce paquet ne sont pas encore disponibles sur le disque, de sorte que leur contenu doit être donné sur la ligne de commande, mais la configuration de l'administrateur pourrait déjà exister et devrait recevoir une priorité plus élevée.

Exemple 1. Script d'installation RPM pour radvd

echo 'u radvd - "radvd daemon"' | \
          systemd-sysusers --replace=/usr/lib/sysusers.d/radvd.conf -

Cela créera l'utilisateur radvd comme si /usr/lib/sysusers.d/radvd.conf était déjà sur le disque. Un administrateur pourrait remplacer la configuration spécifiée sur la ligne de commande en plaçant /etc/sysusers.d/radvd.conf ou même /etc/sysusers.d/00-overrides.conf.

Notez qu'il s'agit de la forme développée, et lorsqu'elle est utilisée dans un paquet, cela serait écrit à l'aide d'une macro avec "radvd" et un fichier contenant la ligne de configuration comme arguments.

Ajouté dans la version 238.

--dry-run

Traite la configuration et détermine quelles entrées seraient créées, mais n'écrit rien en réalité.

Ajouté dans la version 250.

--inline

Traite chaque argument positionnel comme une ligne de configuration séparée au lieu d'un nom de fichier.

Ajouté dans la version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties "intéressantes" des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne pas rediriger la sortie vers un paginator.

-h, --help

Imprime un court message d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

IDENTIFIANTS

systemd-sysusers prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour plus de détails). Les identifiants suivants sont utilisés lorsqu'ils sont transmis :

passwd.hashed-password.utilisateur

Une chaîne de mot de passe haché UNIX à utiliser pour l'utilisateur spécifié, lors de la création d'une entrée pour celui-ci. Ceci est particulièrement utile pour l'utilisateur "root" car il permet de provisionner le mot de passe root par défaut à utiliser via un fichier de configuration drop-in ou depuis un gestionnaire de conteneurs transmettant cet identifiant. Notez que la définition de cet identifiant n'a aucun effet si le compte utilisateur spécifié existe déjà. Cet identifiant est donc principalement utile dans les scénarios de premier démarrage ou pour les systèmes entièrement sans état qui démarrent avec un /etc/ vide à chaque démarrage.

Ajouté dans la version 249.

passwd.plaintext-password.utilisateur

Similaire à "passwd.hashed-password.utilisateur" mais attend un mot de passe littéral en clair, qui est ensuite automatiquement haché avant d'être utilisé pour le compte utilisateur. Si les identifiants haché et en clair sont spécifiés pour le même utilisateur, le premier a la priorité. Il est généralement recommandé de spécifier la version hachée ; cependant, dans les environnements de test avec des exigences de sécurité moindres, il peut être plus facile de transmettre les mots de passe en clair à la place.

Ajouté dans la version 249.

passwd.shell.utilisateur

Spécifie le binaire du shell à utiliser pour le compte spécifié lors de sa création.

Ajouté dans la version 249.

sysusers.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre drop-in sysusers.d/. Si cet identifiant est transmis, il est traité après tous les fichiers drop-in lus depuis le système de fichiers.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-sysusers.service est configuré pour hériter des identifiants "passwd.hashed-password.root", "passwd.plaintext-password.root", "passwd.shell.root" et "sysusers.extra" du gestionnaire de service. Ainsi, lors de l'invocation d'un conteneur avec un /etc/ non rempli pour la première fois, il est possible de configurer le mot de passe de l'utilisateur root à "systemd" comme ceci :

# systemd-nspawn --image=... --set-credential=passwd.hashed-password.root:'$y$j9T$yAuRJu1o5HioZAGDYPU5d.$F64ni6J2y2nNQve90M/p0ZP0ECP/qqzipNyaY9fjGpC' ...

Notez encore que les données spécifiées dans cet identifiant sont consultées uniquement lors de la création d'un compte pour la première fois, elles ne peuvent pas être utilisées pour changer le mot de passe ou le shell d'un compte qui existe déjà.

Utilisez mkpasswd(1) pour générer des hachages de mots de passe UNIX depuis la ligne de commande.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

VOIR AUSSI

systemd(1), sysusers.d(5), Utilisateurs, Groupes, UID et GID sur les systèmes systemd[2], systemd.exec(5), mkpasswd(1)

systemd.directives(7) — systemd manual

NAME

systemd.directives — List of basic configuration directives in systemd

DESCRIPTION

systemd uses a variety of configuration files to control its behavior. The files are typically located in subdirectories of /etc/systemd/, /run/systemd/, and /usr/lib/systemd/. Each file is a simple INI-style text file, consisting of sections enclosed in square brackets, and directives within these sections.

This page lists the most common directives used in configuration files. For a full list of directives, refer to the man pages for the specific unit types (e.g., systemd.unit(5), systemd.service(5), systemd.socket(5), etc.).

SECTION TYPES

Configuration files are divided into sections, each identified by a name enclosed in square brackets. The following section types are common:

[Unit]
Contains general information about the unit, dependencies, and ordering.
[Service]
Contains configuration specific to service units.
[Socket]
Contains configuration specific to socket units.
[Mount]
Contains configuration specific to mount units.
[Timer]
Contains configuration specific to timer units.
[Install]
Contains information about how the unit should be enabled or disabled.

COMMON DIRECTIVES

The following directives are frequently encountered across various section types:

Description=
A human-readable description of the unit.
Documentation=
A space-separated list of URIs or file paths pointing to documentation for the unit.
Requires=
A space-separated list of unit names. If this unit is started, these units will also be started. If any of these units fail, this unit will be stopped.
Wants=
A space-separated list of unit names. If this unit is started, these units will also be started. However, if these units fail, this unit will continue running.
BindsTo=
Similar to Requires=, but if any of the specified units stops, this unit will also be stopped.
PartOf=
A space-separated list of unit names. If any of the specified units is stopped, this unit will also be stopped, and vice versa.
Conflicts=
A space-separated list of unit names. If this unit is started, the specified units will be stopped, and vice versa.
After=
A space-separated list of unit names. This unit will be started only after the specified units have finished starting.
Before=
A space-separated list of unit names. This unit will be started before the specified units start.
OnFailure=
A space-separated list of unit names. If this unit enters a failed state, the specified units will be started.
User=
The user name or UID to run the process as.
Group=
The group name or GID to run the process as.
Environment=
Sets environment variables for the service process.
Type=
Specifies the process startup type of a service.
ExecStart=
The command to execute when the service is started.
ExecStop=
The command to execute when the service is stopped.
ExecReload=
The command to execute when the service is reloaded.
RemainAfterExit=
Specifies whether the service should be considered active after the main process exits.
WantedBy=
Specifies the target unit that should include this unit when enabled.
Alias=
Specifies alternative names for the unit.
ConditionPathExists=
A condition that must be met (path exists) for the unit to be activated.
ConditionPathExists=!
A condition that must be met (path does not exist) for the unit to be activated.
ConditionDirectoryNotEmpty=
A condition that must be met (directory is not empty) for the unit to be activated.
ConditionFileNotEmpty=
A condition that must be met (file is not empty) for the unit to be activated.

UNIT DIRECTIVES

These directives are part of the [Unit] section and control the unit's metadata and dependencies.

Description=
A human-readable name for the unit.
Documentation=
Space-separated URIs or paths to documentation.
Requires=, Wants=, BindsTo=, PartOf=
Define dependency relationships with other units.
Conflicts=
Define units that cannot be active simultaneously.
Before=, After=
Define ordering constraints between units.
OnFailure=
Units to start if this unit fails.
OnSuccess=
Units to start if this unit succeeds.
OnAborted=
Units to start if this unit is aborted.
OnFailureJobMode=, OnSuccessJobMode=, OnAbortedJobMode=
Job mode for units triggered by state changes.
RefuseManualStart=, RefuseManualStop=
Prevent manual activation/deactivation.
AllowIsolate=
Allow the unit to be isolated.

SERVICE DIRECTIVES

These directives are part of the [Service] section and control the execution of services.

Type=
The service type (e.g., simple, forking, oneshot, dbus, notify, idle).
ExecStart=
Command to execute to start the service.
ExecStartPre=, ExecStartPost=
Commands to execute before/after ExecStart=.
ExecStop=
Command to execute to stop the service.
ExecStopPost=
Command to execute after the service has been stopped.
ExecReload=
Command to execute to reload the service configuration.
Restart=
When to restart the service (e.g., no, on-success, on-failure, on-abnormal, on-abort, always).
RestartSec=
Time to wait before restarting.
TimeoutSec=
Timeout for start, stop, and reload operations.
GuessMainPID=
Try to guess the main PID.
PIDFile=
Path to the PID file.
BusName=
The D-Bus name the service acquires.
WatchdogSec=
Watchdog interval.
SyslogIdentifier=
Identifier for syslog messages.
User=, Group=
User and group to run the service as.
SupplementaryGroups=
Supplementary groups for the service process.
Nice=, IOSchedulingClass=, IOSchedulingPriority=
Scheduling parameters.
CPUSchedulingPolicy=, CPUSchedulingPriority=
CPU scheduling parameters.
UMask=
File mode creation mask.
Environment=, EnvironmentFile=
Set environment variables.
WorkingDirectory=
Set the working directory.
RootDirectory=
Chroot into a directory.
SecureBits=
Set secure bits for the process.
ProtectSystem=, ProtectHome=, ProtectKernelTunables=, ProtectKernelModules=, ProtectKernelLogs=, ProtectClock=, ProtectControlGroups=
Security hardening options.
CapabilityBoundingSet=, AmbientCapabilities=, SecureAmbientProcesses=
Capability management.
NoNewPrivileges=
Prevent privilege escalation.
PrivateTmp=, PrivateDevices=, PrivateNetwork=, PrivateUsers=, PrivateXXX=
Namespace isolation options.
JoinsNamespaceOf=
Join existing namespaces.
KillMode=, KillSignal=, RezendKillSignal=
Signals used for stopping the service.
RestartKillSignal=, PreStopHook=, PostStopHook=
Signals and hooks related to stopping.

TIMER DIRECTIVES

These directives are part of the [Timer] section and control timer units.

OnCalendar=
Specifies a calendar event time.
OnBootSec=, OnStartupSec=, OnUnitActiveSec=, OnUnitInactiveSec=
Specifies time relative to boot, startup, or unit activation.
AccuracySec=
The desired accuracy of the timer.
RandomizedDelaySec=
Adds a random delay to the timer activation.
RootDirectory=
Chroot into a directory before activating the timer.
Persistent=
Whether to activate the timer if it was missed.
Unit=
The unit to activate when the timer elapses.
ApplyTimezone=
Whether to use the system's timezone for OnCalendar=.

INSTALL DIRECTIVES

These directives are part of the [Install] section and control how a unit is enabled or disabled.

WantedBy=
Specifies the target unit that should include this unit when enabled. For example, multi-user.target.
RequiredBy=
Specifies the target unit that requires this unit when enabled.
Also=
Specifies other units that should be enabled or disabled along with this unit.

FILESYSTEM DIRECTIVES

These directives are part of the [Mount] and [Automount] sections and control filesystem mounting and automounting.

What=
The device or filesystem to mount.
Where=
The mount point.
Type=
The filesystem type.
Options=
Mount options.
Directory=
The directory for the automount point.
TimeoutSec=
Timeout for automount activation.

SOCKET DIRECTIVES

These directives are part of the [Socket] section and control socket units.

ListenStream=, ListenDatagram=, ListenSequentialPacket=
Specifies the address and port to listen on for stream, datagram, or sequential packet sockets.
ListenFIFO=
Specifies the path for a FIFO special file.
ListenSpecial=
Specifies a Unix device node.
BindToDevice=
Bind the socket to a specific network device.
Accept=
Whether to accept incoming connections.
ReuseAddress=, ReusePort=
Socket option for address/port reuse.
Service=
The service unit to start when a connection is received.
Freebind=
Allow binding to non-local addresses.

SEE ALSO

systemd.unit(5), systemd.service(5), systemd.socket(5), systemd.mount(5), systemd.automount(5), systemd.timer(5), systemd.directives(7), mkpasswd(1)
