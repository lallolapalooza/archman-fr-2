SYSTEMD-MOUNT(1) systemd-mount SYSTEMD-MOUNT(1)

NOM

systemd-mount, systemd-umount - Établir et détruire des points de montage ou de montage automatique transitoires

SYNTAXE

systemd-mount [OPTIONS...] QUOI [OÙ]

systemd-mount [OPTIONS...] --tmpfs [NOM] OÙ

systemd-mount [OPTIONS...] --list

systemd-mount [OPTIONS...] --umount QUOI|OÙ...

DESCRIPTION

systemd-mount peut être utilisé pour créer et démarrer une unité .mount ou .automount transitoire pour le système de fichiers QUOI sur le point de montage OÙ.

À bien des égards, systemd-mount est similaire à la commande de bas niveau mount(8). Cependant, au lieu d'exécuter l'opération de montage directement et immédiatement, systemd-mount la planifie via la file d'attente des tâches du gestionnaire de services, de sorte qu'elle puisse entraîner d'autres dépendances (comme les points de montage parents, ou un vérificateur de système de fichiers à exécuter préalablement) et peut utiliser la logique de montage automatique.

La commande prend un ou deux arguments. Si un seul argument est spécifié, il doit faire référence à un périphérique bloc ou un fichier régulier contenant un système de fichiers (par exemple, "/dev/sdb1" ou "/chemin/vers/disk.img"). Le périphérique bloc ou le fichier image est alors sondé pour trouver une étiquette de système de fichiers et d'autres métadonnées, et est monté sur un répertoire sous /run/media/system/ dont le nom est généré à partir de l'étiquette du système de fichiers. Dans ce mode, le périphérique bloc ou le fichier image doit exister au moment de l'invocation de la commande, afin qu'il puisse être sondé. Si le périphérique est détecté comme étant un périphérique bloc amovible (par exemple, une clé USB), un point de montage automatique est créé à la place d'un point de montage régulier (c'est-à-dire que l'option --automount= est implicite, voir ci-dessous). Si l'option --tmpfs est spécifiée, alors l'argument est interprété comme le chemin où le nouveau système de fichiers temporaire doit être monté.

Si deux arguments sont spécifiés, le premier indique la source du montage (le QUOI) et le second indique le chemin sur lequel le monter (le OÙ). Dans ce mode, aucune sonde de la source n'est tentée et un nœud de périphérique sous-jacent n'a pas besoin d'exister. Cependant, si ce mode est combiné avec --discover, la sonde du nœud de périphérique pour des métadonnées supplémentaires est activée et – tout comme dans le cas à un seul argument discuté ci-dessus – le périphérique spécifié doit exister au moment de l'invocation de la commande.

Utilisez la commande --list pour afficher un tableau concis de tous les périphériques blocs locaux connus avec des systèmes de fichiers pouvant être montés avec cette commande.

systemd-umount peut être utilisé pour démonter un point de montage ou un point de montage automatique. C'est la même chose que systemd-mount --umount.

OPTIONS

Les options suivantes sont comprises :

--no-block

Ne pas attendre de manière synchrone que l'opération demandée se termine. Si cela n'est pas spécifié, la tâche sera vérifiée, mise en file d'attente et systemd-mount attendra que le démarrage de l'unité de montage ou de montage automatique soit terminé. En passant cet argument, elle est seulement vérifiée et mise en file d'attente.

Ajouté dans la version 232.

-l, --full

Ne pas élider la sortie lorsque --list est spécifié.

Ajouté dans la version 245.

--no-pager

Ne pas utiliser de pagineur pour la sortie.

--no-legend

Ne pas imprimer la légende, c'est-à-dire les en-têtes de colonne et le pied de page avec des indices.

--no-ask-password

Ne pas interroger l'utilisateur pour l'authentification des opérations privilégiées.

--json=MODE

Affiche la sortie formatée en JSON. Attend l'une des valeurs suivantes : "short" (pour une sortie la plus courte possible sans espaces superflus ni sauts de ligne), "pretty" (pour une version soignée de celle-ci, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

--quiet, -q

Supprime les informations supplémentaires pendant l'exécution.

Ajouté dans la version 232.

--discover

Active la sonde de la source de montage. Ce commutateur est implicite si un seul argument est spécifié sur la ligne de commande. S'il est passé, des métadonnées supplémentaires sont lues depuis le périphérique pour améliorer l'unité à créer. Par exemple, une chaîne descriptive pour les unités transitoires est générée à partir de l'étiquette du système de fichiers et du modèle de périphérique. De plus, si un périphérique bloc amovible (par exemple, une clé USB) est détecté, une unité de montage automatique est créée à la place d'une unité de montage régulière, avec un court délai d'inactivité, afin d'assurer que le système de fichiers est placé dans un état propre rapidement après chaque accès.

Ajouté dans la version 232.

--type=, -t

Spécifie le type de système de fichiers à monter (par exemple, "vfat" ou "ext4"). Si omis ou défini sur "auto", le type de système de fichiers est déterminé automatiquement.

Ajouté dans la version 232.

--options=, -o

Options de montage supplémentaires pour le point de montage.

Ajouté dans la version 232.

--owner=UTILISATEUR

Laisse l'utilisateur spécifié UTILISATEUR posséder le système de fichiers monté. Ceci est fait en ajoutant les options uid= et gid= à la liste des options de montage. Seuls certains systèmes de fichiers prennent en charge cette option.

Ajouté dans la version 237.

--fsck=

Prend un argument booléen, par défaut activé. Contrôle si une vérification du système de fichiers doit être effectuée immédiatement avant l'opération de montage. Dans le cas du montage automatique (voir --automount= ci-dessous), la vérification sera effectuée dès le premier accès au périphérique, ce qui pourrait légèrement retarder l'accès.

Ajouté dans la version 232.

--description=

Fournit une description pour l'unité de montage ou de montage automatique. Voir Description= dans systemd.unit(5).

Ajouté dans la version 232.

--property=, -p

Définit une propriété d'unité pour l'unité de montage créée. Ceci prend une assignation dans le même format que la commande set-property de systemctl(1).

Ajouté dans la version 232.

--automount=

Prend un argument booléen. Contrôle s'il faut créer un point de montage automatique ou un point de montage régulier. Si vrai, un point de montage automatique est créé, dont le backend est le système de fichiers réel au moment du premier accès. Si faux, un simple point de montage est créé, dont le backend est le système de fichiers réel immédiatement. Les points de montage automatique ont l'avantage que le système de fichiers reste démonté et donc dans un état propre jusqu'à ce qu'il soit accédé pour la première fois. En mode montage automatique, le commutateur --timeout-idle-sec= (voir ci-dessous) peut être utilisé pour s'assurer que le point de montage est démonté automatiquement après le dernier accès et que le délai d'inactivité est passé.

Si ce commutateur n'est pas spécifié, il est défini sur faux par défaut. S'il n'est pas spécifié et que --discover est utilisé (ou qu'un seul argument est passé, ce qui implique --discover, voir ci-dessus), et que le périphérique bloc du système de fichiers est détecté comme amovible, il est défini sur vrai, afin d'augmenter la probabilité que le système de fichiers soit dans un état complètement propre si le périphérique est débranché brusquement.

Ajouté dans la version 232.

-A

Équivalent à --automount=yes.

Ajouté dans la version 232.

--timeout-idle-sec=

Prend une valeur temporelle qui contrôle le délai d'inactivité en mode montage automatique. S'il est défini sur "infinity" (par défaut), aucun démontage automatique n'est effectué. Sinon, le système de fichiers sous-jacent au point de montage automatique est détaché après le dernier accès et une fois le délai d'inactivité écoulé. Voir systemd.time(7) pour les détails sur la syntaxe temporelle prise en charge. Cette option n'a aucun effet si seul un montage régulier est établi et que le montage automatique n'est pas utilisé.

Notez que si --discover est utilisé (ou qu'un seul argument est passé, ce qui implique --discover, voir ci-dessus), et que le périphérique bloc du système de fichiers est détecté comme amovible, --timeout-idle-sec=1s est implicite.

Ajouté dans la version 232.

--automount-property=

Similaire à --property=, mais applique des propriétés supplémentaires à l'unité de montage automatique créée, au lieu de l'unité de montage.

Ajouté dans la version 232.

--bind-device

Contrôle si l'unité de montage/montage automatique générée doit être

S'il est activé, les unités seront arrêtées automatiquement lorsque le périphérique de stockage disparaît. Par défaut, l'unité de montage automatique reste active, et les accès ultérieurs seront bloqués jusqu'à ce que le périphérique de stockage soit rebranché. Cette option n'a aucun effet pour les montages qui ne concernent pas des périphériques, tels que les montages de systèmes de fichiers réseau ou virtuels.

Si --discover est utilisé (ou si un seul argument est passé, ce qui implique --discover, voir ci-dessus), et que le périphérique bloc du système de fichiers est détecté comme amovible, cette option est implicite.

Ce comportement peut être contrôlé via l'option de montage x-systemd.device-bound=, voir systemd.mount(5) pour plus de détails. En particulier, x-systemd.device-bound=no prend la priorité sur cette option, ce qui supprime les dépendances de périphérique à la fois dans les unités de montage générées et ce qui est implicite par le gestionnaire de services.

Ajouté dans la version 232.

--list

Au lieu d'établir un point de montage ou de montage automatique, affiche une liste concise des périphériques blocs contenant des systèmes de fichiers qui peuvent être montés avec "systemd-mount", ainsi que des métadonnées utiles telles que les étiquettes, etc.

Ajouté dans la version 232.

-u, --umount

Arrête les unités de montage et de montage automatique correspondant aux points de montage spécifiés WHERE ou aux périphériques WHAT. systemd-mount avec cette option ou systemd-umount peut prendre plusieurs arguments qui peuvent être des points de montage, des périphériques, des noms de nœuds de style /etc/fstab, ou des fichiers de stockage correspondant à des périphériques loop, comme systemd-mount --umount /chemin/vers/demontage /dev/sda1 UUID=xxxxxx-xxxx LABEL=xxxxx /chemin/vers/disque.img. Notez que lorsque -H ou -M est spécifié, seuls les chemins absolus vers les points de montage sont supportés.

Ajouté dans la version 233.

-G, --collect

Décharge l'unité transitoire une fois qu'elle est terminée, même si elle a échoué. Normalement, sans cette option, toutes les unités de montage qui ont été montées et qui ont échoué sont conservées en mémoire jusqu'à ce que l'utilisateur réinitialise explicitement leur état d'échec avec systemctl reset-failed ou une commande équivalente. D'autre part, les unités qui se sont arrêtées avec succès sont déchargées immédiatement. Si cette option est activée, le "nettoyage" des unités est plus agressif, et décharge les unités qu'elles aient réussi ou échoué à se terminer. Cette option est un raccourci pour --property=CollectMode=inactive-or-failed, voir l'explication de CollectMode= dans systemd.unit(5) pour plus d'informations.

Ajouté dans la version 236.

-T, --tmpfs

Crée et monte un nouveau système de fichiers tmpfs sur WHERE, avec un nom optionnel NAME qui vaut par défaut "tmpfs".

Le système de fichiers est monté avec le mode du répertoire de niveau supérieur déterminé par le paramètre umask(2) de l'appelant, c'est-à-dire rwxrwxrwx masqué par l'umask de l'appelant. Cela correspond à ce que fait mkdir(1), mais diffère du défaut du noyau "rwxrwxrwxt", c'est-à-dire un répertoire accessible en écriture par tout le monde avec le bit collant activé.

Ajouté dans la version 255.

--canonicalize=

Contrôle si le chemin spécifié doit être canonisé côté client avant de demander l'opération ou non. Prend un paramètre booléen, vaut par défaut true. Notez que pour une opération non locale (c'est-à-dire lorsque --machine= ou ----host= sont utilisés), la canonisation est implicitement désactivée.

La canonisation du chemin implique la résolution des liens symboliques, des éléments de chemin ".." et de l'expansion des nœuds de périphérique de style LABEL=/UUID=. Si la canonisation est désactivée et que le chemin contient un lien symbolique, "..", ou une expansion LABEL=/UUID=/..., l'opération échouera.

Ajouté dans la version 258.

--user

Communique avec le gestionnaire de services de l'utilisateur appelant, plutôt qu'avec le gestionnaire de services du système.

--system

Communique avec le gestionnaire de services du système. C'est le défaut implicite.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par "@", pour se connecter. Le nom d'hôte peut éventuellement être suivi d'un port sur lequel ssh écoute, séparé par ":", puis d'un nom de conteneur, séparé par "/", ce qui se connecte directement à un conteneur spécifique sur l'hôte spécifié. Cela utilisera SSH pour communiquer avec l'instance du gestionnaire de machine distante. Les noms de conteneurs peuvent être énumérés avec machinectl -H HOST. Mettez les adresses IPv6 entre crochets.

-M, --machine=

Exécute l'opération sur un conteneur local. Spécifiez un nom de conteneur pour se connecter, éventuellement préfixé par un nom d'utilisateur pour se connecter et un caractère séparateur "@". Si la chaîne spéciale ".host" est utilisée à la place du nom de conteneur, une connexion au système local est établie (ce qui est utile pour se connecter au bus d'un utilisateur spécifique : "--user --machine=lennart@.host"). Si la syntaxe "@" n'est pas utilisée, la connexion est établie en tant qu'utilisateur root. Si la syntaxe "@" est utilisée, le côté gauche ou le côté droit peut être omis (mais pas les deux) auquel cas le nom d'utilisateur local et ".host" sont implicites.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

LA BASE DE DONNÉES UDEV

Si --discover est utilisé, systemd-mount respecte quelques propriétés udev supplémentaires des périphériques blocs :

SYSTEMD_MOUNT_OPTIONS=

Les options de montage à utiliser, si --options= n'est pas utilisé.

Ajouté dans la version 232.

SYSTEMD_MOUNT_WHERE=

Le chemin du système de fichiers où placer le point de montage, au lieu de celui généré automatiquement.

Ajouté dans la version 232.

EXEMPLE

Utilisez une règle udev comme la suivante pour monter automatiquement tous les périphériques de stockage USB branchés :

ACTION=="add", SUBSYSTEMS=="usb", SUBSYSTEM=="block", ENV{ID_FS_USAGE}=="filesystem", \
        RUN{program}+="/usr/bin/systemd-mount --no-block --automount=yes --collect $devnode"
