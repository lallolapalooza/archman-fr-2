SYSTEMD-UDEVD.SERVICE(8) systemd-udevd.service SYSTEMD-UDEVD.SERVICE(8)

NOM

systemd-udevd.service, systemd-udevd-control.socket, systemd-udevd-kernel.socket, systemd-udevd-varlink.socket, systemd-udevd - Démon de gestion des événements de périphériques

SYNOPIS

systemd-udevd.service

systemd-udevd-control.socket

systemd-udevd-kernel.socket

systemd-udevd-varlink.socket

/usr/lib/systemd/systemd-udevd [--daemon] [--debug] [--children-max=] [--exec-delay=] [--event-timeout=] [--resolve-names=early|late|never] [--version] [--help]

DESCRIPTION

systemd-udevd écoute les uevents du noyau. Pour chaque événement, systemd-udevd exécute les instructions correspondantes spécifiées dans les règles udev. Voir udev(7).

Le comportement du démon peut être configuré en utilisant udev.conf(5), ses options en ligne de commande, les variables d'environnement, et sur la ligne de commande du noyau, ou modifié dynamiquement avec udevadm control.

OPTIONS

-d, --daemon

Se détache et s'exécute en arrière-plan.

Ajouté dans la version 186.

-D, --debug

Affiche les messages de débogage sur la sortie d'erreur standard.

Ajouté dans la version 186.

-c, --children-max=

Limite le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

-e, --exec-delay=

Retarde l'exécution de chaque paramètre RUN{programme} du nombre de secondes donné. Cette option peut être utile lors du débogage de plantages système pendant le coldplug causés par le chargement de modules du noyau non fonctionnels.

Ajouté dans la version 186.

-t, --event-timeout=

Définit le nombre de secondes à attendre pour que les événements se terminent. Après ce délai, l'événement sera terminé. La valeur par défaut est 180 secondes.

Ajouté dans la version 216.

-s, --timeout-signal=

Définit le signal que systemd-udevd enverra aux processus enfants après avoir atteint le délai d'expiration de l'événement. Le réglage peut être remplacé au démarrage avec l'option de ligne de commande du noyau udev.timeout_signal=. Le réglage sur SIGABRT peut être utile pour déboguer les timeouts des workers. Par défaut, il vaut SIGKILL. Notez que le réglage de l'option en ligne de commande remplace le réglage du fichier de configuration.

Ajouté dans la version 246.

-N, --resolve-names=

Spécifie quand systemd-udevd doit résoudre les noms d'utilisateurs et de groupes. Lorsque réglé sur early (la valeur par défaut), les noms seront résolus lors de l'analyse des règles. Lorsqu'il est réglé sur late, les noms seront résolus pour chaque événement. Lorsqu'il est réglé sur never, les noms ne seront jamais résolus et tous les périphériques appartiendront à root.

Ajouté dans la version 186.

-h, --help

Affiche un court texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

LIGNE DE COMMANDE DU NOYAU

Les paramètres préfixés par "rd." seront lus lorsque systemd-udevd est utilisé dans un initrd, ceux sans préfixe seront traités à la fois dans l'initrd et sur l'hôte.

udev.log_level=, rd.udev.log_level=

Définit le niveau de journalisation.

Ajouté dans la version 247.

udev.trace[=BOOL], rd.udev.trace[=BOOL]

Active/désactive la journalisation de traçage. Lorsqu'elle est activée, udev.log_level= sera ignoré, et le niveau "debug" sera supposé.

Ajouté dans la version 258.

udev.children_max=, rd.udev.children_max=

Limite le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

udev.exec_delay=, rd.udev.exec_delay=

Retarde l'exécution de chaque paramètre RUN{programme} du nombre de secondes donné. Cette option peut être utile lors du débogage de plantages système pendant le coldplug causés par le chargement de modules du noyau non fonctionnels.

Ajouté dans la version 186.

udev.event_timeout=, rd.udev.event_timeout=

Attend la fin des événements pendant le nombre de secondes donné. Cette option peut être utile si les événements sont terminés parce que les pilotes du noyau prennent trop de temps à s'initialiser.

Ajouté dans la version 216.

udev.timeout_signal=, rd.udev.timeout_signal=

Spécifie un signal que systemd-udevd enverra aux workers lors d'un timeout. Notez que l'option de ligne de commande du noyau remplace à la fois le réglage dans le fichier de configuration et celui de la ligne de commande du programme.

Ajouté dans la version 246.

udev.blockdev_read_only, rd.udev.blockdev_read_only

Si spécifié, marque tous les périphériques de bloc physiques en lecture seule à leur apparition. Les périphériques de bloc synthétiques (tels que les périphériques de bloc de boucle ou les périphériques de mappage de périphériques) restent tels quels. Ceci est utile pour garantir que le contenu des périphériques de bloc physiques reste inchangé pendant l'exécution, par exemple pour implémenter des systèmes entièrement sans état, pour des tests ou pour des situations de récupération où les systèmes de fichiers corrompus ne doivent pas être davantage corrompus par une modification accidentelle.

Un périphérique de bloc peut être marqué à nouveau en écriture en lançant la commande blockdev --setrw, voir blockdev(8) pour plus de détails.

Ajouté dans la version 246.

net.ifnames=

Les interfaces réseau sont renommées pour leur donner des noms prévisibles lorsque cela est possible. C'est activé par défaut ; spécifier 0 le désactive.

Ajouté dans la version 199.

net.naming_scheme=

Les interfaces réseau sont renommées pour leur donner des noms prévisibles lorsque cela est possible (sauf si net.ifnames=0 est spécifié, voir ci-dessus). Avec cette option de ligne de commande du noyau, il est possible de choisir une version spécifique de cet algorithme et de remplacer celui par défaut choisi au moment de la compilation. Attend l'un des identifiants de schéma de nommage listés dans systemd.net-naming-scheme(7), ou "latest" pour sélectionner le schéma le plus récent connu (par cette version particulière de systemd-udevd.service).

Notez que le choix d'un schéma spécifique n'est pas suffisant pour stabiliser complètement le nommage des interfaces : le nommage est généralement dérivé des attributs du pilote exposés par le noyau. Lorsque le noyau est mis à jour, des attributs précédemment manquants que systemd-udevd.service vérifie pourraient apparaître, ce qui affecte également les anciens algorithmes de dérivation de nom.

Ajouté dans la version 240.

net.ifname_policy=policy1[,policy2,...][,MAC]

Spécifie les politiques de nommage appliquées lors du renommage des interfaces réseau. Prend une liste de politiques et une adresse MAC optionnelle séparées par une virgule. Chaque valeur de politique doit être l'une des politiques comprises par le réglage NamePolicy= dans les fichiers .link, par exemple "onboard" ou "path". Voir systemd.link(5) pour plus de détails. Lorsque l'adresse MAC est spécifiée, les politiques sont appliquées à l'interface qui possède cette adresse. Lorsqu'aucune adresse MAC n'est spécifiée, les politiques sont appliquées à toutes les interfaces. Cet argument de ligne de commande du noyau peut être spécifié plusieurs fois.

Cet argument n'est pas lu directement par systemd-udevd, mais est plutôt converti en un fichier .link par systemd-network-generator.service(8). Pour que cet argument prenne effet, systemd-network-generator.service doit être activé.

Exemple :

net.ifname_policy=keep,kernel,path,slot,onboard,01:23:45:67:89:ab
net.ifname_policy=keep,kernel,path,slot,onboard,mac

Ceci est essentiellement équivalent à la création des fichiers .link suivants :

# 91-name-policy-with-mac.link
[Match]
MACAddress=01:23:45:67:89:ab
[Link]
NamePolicy=keep kernel path slot onboard
AlternativeNamePolicy=path slot onboard

et

# 92-name-policy-for-all.link
[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel path slot o

systemd-udevd.service(8) — Arch Linux

NAME

systemd-udevd.service — event driven device node manager

SYNOPSIS

/lib/systemd/systemd-udevd
systemd-udevd.service

DESCRIPTION

systemd-udevd is the event driven device node manager. It listens to kernel uevents, processes them, and dispatches device-related events to various mechanisms to manage device nodes, permissions, and properties.

It implements the udev API, described in udev(7). It provides a runtime device information database, and a generic interface for querying this database.

The daemon runs in the background and handles device events like device discovery, device renaming, and device permissions.

For more detailed information, refer to the general udev.conf(5) and udev(7) man pages.

OPTIONS

systemd-udevd supports the following options:

--daemon
Run in daemon mode. This is the default when started by systemd.service(5).
--debug
Enable debug output. Useful for debugging udev rules.
--test
Run in test mode. This option is ignored.
--foreground
Run in foreground mode. This is typically used for debugging.
--pipe-size=bytes
Set the size of the internal event pipe. Defaults to 16 MiB.
--log-level=priority
Set the logging priority. Defaults to info.
--resolve-aliases
Resolve symbolic links in device paths.
--block-timeout=seconds
Set the timeout for blocking device events. Defaults to 5 minutes.
--children-max=max
Set the maximum number of child processes systemd-udevd may create. Defaults to 1024.
--timeout=seconds
Set the general timeout for device event processing. Defaults to 5 minutes.
--uid-file=file
Read UID from file. Used for assigning ownership of device nodes.
--gid-file=file
Read GID from file. Used for assigning ownership of device nodes.
--watch
Watch for changes in udev rules files and reload them.
--rename-device=old new
Rename device old to new. This is primarily for internal use or specific testing scenarios.
--remove-already-present-device
Remove device nodes for devices that are already present.
--add-already-present-device
Add device nodes for devices that are already present.
--use-syslog
Send output to syslog instead of the console.
--log-target=target
Set the log target. Can be console, syslog, or a file path.

KERNEL COMMAND LINE

systemd-udevd also accepts kernel command line parameters to control its behavior. These include:

udev.log-priority=priority
Sets the initial logging priority. For available values, see syslog(3).
udev.debug
Enables debug logging.
udev.children-max=max
Sets the maximum number of child processes.
udev.timeout=seconds
Sets the general timeout for device event processing.
udev.block-timeout=seconds
Sets the timeout for blocking device events.
udev.extra-log-level=level
Sets an additional logging level. This is a bitmask that enables specific logging categories.
udev.log-syslog
Enable logging to syslog.
udev.auto-mode=mode
Sets the automatic device naming mode. Valid values are on, off, and name.
udev.default-permissions=permissions
Sets the default permissions for device nodes.
udev.default-owner-group=group
Sets the default owner group for device nodes.
udev.net-rule-name=rule
Specifies the rule for naming network interfaces. For example, mac, path, slot, onboard mac.

For a full list of kernel command line parameters, see systemd(1).

udev.net-rule-name=onboard mac was added in version 250.

NOM

systemd-udevd.service — gestionnaire d'événements de périphériques dirigé par les événements

SYNOPSIS

/lib/systemd/systemd-udevd
systemd-udevd.service

DESCRIPTION

systemd-udevd est le gestionnaire d'événements de périphériques dirigé par les événements. Il écoute les uevents du noyau, les traite et distribue les événements liés aux périphériques à divers mécanismes pour gérer les nœuds de périphériques, les permissions et les propriétés.

Il implémente l'API udev, décrite dans udev(7). Il fournit une base de données d'informations sur les périphériques en temps réel et une interface générique pour interroger cette base de données.

Le démon s'exécute en arrière-plan et gère les événements de périphériques tels que la découverte de périphériques, le renommage de périphériques et les permissions de périphériques.

Pour plus d'informations, reportez-vous aux pages de manuel générales udev.conf(5) et udev(7).

OPTIONS

systemd-udevd prend en charge les options suivantes :

--daemon
Exécute en mode démon. C'est le comportement par défaut lorsqu'il est démarré par systemd.service(5).
--debug
Active la sortie de débogage. Utile pour le débogage des règles udev.
--test
Exécute en mode test. Cette option est ignorée.
--foreground
Exécute en mode premier plan. Ceci est généralement utilisé pour le débogage.
--pipe-size=octets
Définit la taille du tube d'événements interne. Par défaut 16 Mio.
--log-level=priorité
Définit la priorité de journalisation. Par défaut info.
--resolve-aliases
Résout les liens symboliques dans les chemins des périphériques.
--block-timeout=secondes
Définit le délai d'attente pour les événements de périphériques bloquants. Par défaut 5 minutes.
--children-max=max
Définit le nombre maximum de processus enfants que systemd-udevd peut créer. Par défaut 1024.
--timeout=secondes
Définit le délai d'attente général pour le traitement des événements de périphériques. Par défaut 5 minutes.
--uid-file=fichier
Lit l'UID depuis le fichier. Utilisé pour attribuer la propriété des nœuds de périphériques.
--gid-file=fichier
Lit le GID depuis le fichier. Utilisé pour attribuer la propriété des nœuds de périphériques.
--watch
Surveille les changements dans les fichiers de règles udev et les recharge.
--rename-device=ancien nouveau
Renomme le périphérique ancien en nouveau. Ceci est principalement destiné à un usage interne ou à des scénarios de test spécifiques.
--remove-already-present-device
Supprime les nœuds de périphériques pour les périphériques qui sont déjà présents.
--add-already-present-device
Ajoute les nœuds de périphériques pour les périphériques qui sont déjà présents.
--use-syslog
Envoie la sortie à syslog au lieu de la console.
--log-target=cible
Définit la cible de journalisation. Peut être console, syslog, ou un chemin de fichier.

LIGNE DE COMMANDE DU NOYAU

systemd-udevd accepte également des paramètres de ligne de commande du noyau pour contrôler son comportement. Ceux-ci incluent :

udev.log-priority=priorité
Définit la priorité de journalisation initiale. Pour les valeurs disponibles, voir syslog(3).
udev.debug
Active la journalisation de débogage.
udev.children-max=max
Définit le nombre maximum de processus enfants.
udev.timeout=secondes
Définit le délai d'attente général pour le traitement des événements de périphériques.
udev.block-timeout=secondes
Définit le délai d'attente pour les événements de périphériques bloquants.
udev.extra-log-level=niveau
Définit un niveau de journalisation supplémentaire. Il s'agit d'un masque de bits qui active des catégories de journalisation spécifiques.
udev.log-syslog
Active la journalisation vers syslog.
udev.auto-mode=mode
Définit le mode de nommage automatique des périphériques. Les valeurs valides sont on, off, et name.
udev.default-permissions=permissions
Définit les permissions par défaut pour les nœuds de périphériques.
udev.default-owner-group=groupe
Définit le groupe propriétaire par défaut pour les nœuds de périphériques.
udev.net-rule-name=règle
Spécifie la règle pour nommer les interfaces réseau. Par exemple, mac, path, slot, onboard mac.

Pour une liste complète des paramètres de ligne de commande du noyau, voir systemd(1).
