NOM

syslog-ng - application de journalisation système syslog-ng

SYNTAXE

syslog-ng [options]

DESCRIPTION

Cette page de manuel est seulement un résumé.

L'application syslog-ng OSE est une application de journalisation système flexible et hautement évolutive. Typiquement, syslog-ng OSE est utilisée pour gérer les messages de log et implémenter une journalisation centralisée, où le but est de collecter les messages de log de plusieurs périphériques sur un seul serveur de log central. Les différents périphériques - appelés clients syslog-ng OSE - exécutent tous syslog-ng OSE, et collectent les messages de log des différentes applications, fichiers et autres sources. Les clients envoient tous les messages de log importants au serveur syslog-ng OSE distant, où le serveur les trie et les stocke.

OPTIONS

--caps
Exécute le processus syslog-ng OSE avec les indicateurs de capacité POSIX spécifiés.

  • Si l'option --no-caps n'est pas définie, syslog-ng OSE a été compilé avec l'option de compilation --enable-linux-caps, et l'hôte supporte CAPSYSLOG, syslog-ng OSE utilise les capacités suivantes : "capnetbindservice, capnetbroadcast, capnetraw, capdacreadsearch, capdacoverride, capchown, capfowner=p capsyslog=ep"
  • Si l'option --no-caps n'est pas définie, et que l'hôte ne supporte pas CAPSYSLOG, syslog-ng OSE utilise les capacités suivantes : "capnetbindservice, apnetbroadcast, capnetraw, capdacreadsearch, capdacoverride, capchown, capfowner=p capsys_admin=ep"

Par exemple :

    /usr/sbin/syslog-ng -Fv --caps cap_sys_admin,cap_chown,cap_dac_override,cap_net_bind_service,cap_fowner=pi

NOTE : Les capacités ne sont pas sensibles à la casse, la commande suivante est également valide :

    /usr/sbin/syslog-ng -Fv --caps CAP_SYS_ADMIN,CAP_CHOWN,CAP_DAC_OVERRIDE,CAP_NET_BIND_SERVICE,CAP_FOWNER=pi

Pour plus de détails sur les indicateurs de capacité, consultez les pages de manuel suivantes : cap_from_text(3) et capabilities(7)

--cfgfile <fichier> ou -f <fichier>
Utilise le fichier de configuration spécifié.

--chroot <répertoire> ou -C <répertoire>
Change la racine vers le répertoire spécifié. Le fichier de configuration est lu après le chroot, donc le fichier de configuration doit être disponible dans le chroot. De cette façon, il est également possible de recharger la configuration de syslog-ng OSE après le chroot. Cependant, notez que les options --user et --group sont résolues avant le chroot.

--check-startup
Disponible dans les versions 4.5 et ultérieures de syslog-ng OSE.
Cette option peut être utilisée pour effectuer une initialisation complète de la configuration avec syslog-ng OSE, puis quitter avec le code de sortie indiquant le résultat. Cette option peut également être utilisée pour vérifier si la configuration est sémantiquement valide et si syslog-ng OSE peut effectivement démarrer. (L'option --syntax-only ne détecte que les erreurs syntaxiques.)
De plus, --check-startup peut également être utilisé dans un environnement Kubernetes, pour l'exécuter en tant que conteneur dédié à la vérification de configuration.

NOTE : Cette option échouera très probablement si une autre instance de syslog-ng OSE est en cours d'exécution en arrière-plan, car elle initialise plusieurs processus, tels que les écouteurs réseau. Dans un tel cas, l'adresse réseau serait déjà utilisée.

--control <fichier> ou -c <fichier>
Définit l'emplacement du socket de contrôle de syslog-ng OSE. Valeur par défaut : /var/run/syslog-ng.ctl

--debug ou -d
Démarre syslog-ng OSE en mode débogage.

--default-modules
Une liste séparée par des virgules des modules qui sont chargés automatiquement. Les modules non chargés automatiquement peuvent être chargés en incluant l'instruction @module <nom_module> dans le fichier de configuration de syslog-ng OSE. Disponible uniquement dans la version 4.1 et ultérieures de syslog-ng OSE.

--enable-core
Permet à syslog-ng OSE d'écrire des fichiers core en cas de crash pour aider au support et au débogage.

--fd-limit <nombre>
Définit le nombre minimum de descripteurs de fichiers (fd) requis. Ceci définit combien de fichiers syslog-ng OSE peut garder ouverts simultanément.
Valeur par défaut : 4096.

NOTE : Ceci ne remplace pas le réglage ulimit global de l'hôte.

--foreground ou -F
Ne pas daemoniser, exécuter en premier plan. Lors de l'exécution en premier plan, syslog-ng OSE démarre à partir du répertoire courant (${CWD}) afin qu'il puisse créer des fichiers core (normalement, syslog-ng OSE démarre à partir de ${PREFIX}/var).

--group <groupe> ou -g <groupe>
Passe au groupe spécifié après initialisation du fichier de configuration.

--help ou -h
Affiche un bref message d'aide.

--module-registry
Affiche la liste et la description des modules disponibles.

NOTE : Tous ces modules ne sont pas chargés automatiquement, seulement ceux spécifiés dans l'option --default-modules. Disponible uniquement dans la version 4.0 et ultérieures de syslog-ng OSE.

--no-caps
Exécute syslog-ng OSE en tant que root, sans support de capacités. C'est le comportement par défaut. Sous Linux, il est possible d'exécuter syslog-ng OSE en tant que non-root avec le support de capacités si syslog-ng OSE a été compilé avec l'option --enable-linux-caps activée. (Exécutez syslog-ng --version pour afficher la liste des paramètres de compilation activés.)
Pour exécuter syslog-ng OSE avec des capacités spécifiques, utilisez l'option --caps.

--persist-file <fichier-persistance> ou -R <fichier-persistance>
Définit le chemin et le nom du fichier syslog-ng.persist où les options et données persistantes sont stockées.

--pidfile <fichier-pid> ou -p <fichier-pid>
Définit le chemin vers le fichier PID où le pid du processus principal est stocké.

--preprocess-into <fichier-sortie>
Après avoir traité le fichier de configuration et résolu les fichiers inclus et les variables, écrit la configuration résultante dans le fichier de sortie spécifié. Disponible uniquement dans la version 4.0 et ultérieures de syslog-ng OSE.

--process-mode <mode>
Définit comment exécuter syslog-ng OSE : en premier plan (principalement utilisé pour le débogage), en arrière-plan en tant que démon, ou en mode arrière-plan sécurisé. Par défaut, syslog-ng OSE s'exécute en mode arrière-plan sécurisé. Ce mode crée un processus superviseur appelé syslog-ng OSE supervisé, qui redémarre syslog-ng OSE s'il plante.

--stderr ou -e
Journalise les messages internes de syslog-ng OSE sur stderr. Principalement utilisé à des fins de débogage en conjonction avec l'option --foreground. Si non spécifié, syslog-ng OSE journalisera ces messages sur sa source interne.

--syntax-only ou -s
Vérifie que le fichier de configuration est syntaxiquement correct et quitte.

--user <utilisateur> ou -u <utilisateur>
Passe à l'utilisateur spécifié après initialisation du fichier de configuration (et éventuellement après chroot).

NOTE : Il n'est pas possible de recharger la configuration de syslog-ng OSE si l'utilisateur spécifié n'a pas le privilège de créer le fichier /dev/log.

--verbose ou -v
Active la journalisation verbale utilisée pour le dépannage de syslog-ng OSE.

--version ou -V
Affiche le numéro de version et les informations de compilation, ainsi que la liste et la courte description des modules disponibles. Pour une description détaillée des modules disponibles, voir l'option --module-registry.

NOTE : Tous ces modules ne sont pas chargés automatiquement, seulement ceux spécifiés dans l'option --default-modules.

--worker-threads
Définit le nombre de threads de travail que syslog-ng OSE peut utiliser, y compris le thread principal de syslog-ng OSE.
Voir le Guide d'administration de syslog-ng OSE[1] pour plus de détails.

NOTE : Certaines opérations dans syslog-ng OSE peuvent utiliser des threads qui ne sont pas limités par cette option. Ce réglage n'a d'effet que lorsque syslog-ng OSE est exécuté en mode multithread. Disponible uniquement dans les versions 4.0 et ultérieures de syslog-ng OSE.
