NOM

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Créer, supprimer et nettoyer les fichiers et répertoires

SYNTAXE

systemd-tmpfiles [OPTIONS...] [FICHIER_CONFIG...]

Unités système :

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unités utilisateur :

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPTION

systemd-tmpfiles crée, supprime et nettoie les fichiers et répertoires, en utilisant le format et l'emplacement des fichiers de configuration spécifiés dans tmpfiles.d(5). Historiquement, il était conçu pour gérer les fichiers volatils et temporaires, comme son nom l'indique, mais il fournit des fonctionnalités génériques de gestion de fichiers et peut être utilisé pour gérer tout type de fichiers. Il doit être invoqué avec au moins une des commandes --create, --remove et --clean, pour sélectionner le sous-ensemble d'opérations respectif.

S'il est invoqué sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par tmpfiles.d(5) sont exécutées. Lorsqu'il est invoqué avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments donnés en ligne de commande sont utilisés à la place du chemin du fichier de configuration CHEMIN. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée au lieu d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans slashs), tous les répertoires de configuration sont recherchés pour un fichier correspondant, et le fichier trouvé ayant la plus haute priorité est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration d'autres fichiers correspondants.

Les services système (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invoquent systemd-tmpfiles pour créer des fichiers système et effectuer un nettoyage global du système. Ces services lisent les fichiers de configuration contrôlés par l'administrateur dans les répertoires tmpfiles.d/. Les services utilisateur (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) invoquent également systemd-tmpfiles, mais celui-ci lit un ensemble distinct de fichiers, qui inclut les fichiers contrôlés par l'utilisateur sous ~/.config/user-tmpfiles.d/ et ~/.local/share/user-tmpfiles.d/, et les fichiers contrôlés par l'administrateur sous /usr/share/user-tmpfiles.d/. Les utilisateurs peuvent l'utiliser pour créer et nettoyer des fichiers sous leur contrôle, mais l'instance système effectue le nettoyage global et n'est pas influencée par la configuration utilisateur. Notez qu'un nettoyage basé sur le temps configuré dans l'instance système, comme celui typiquement configuré pour /tmp/, affectera ainsi également les fichiers créés par l'instance utilisateur s'ils sont placés dans /tmp/, même si le nettoyage basé sur le temps de l'instance utilisateur est désactivé.

Pour réappliquer les paramètres après que la configuration ait été modifiée, redémarrez simplement systemd-tmpfiles-clean.service, ce qui appliquera tous les paramètres qui peuvent être exécutés en toute sécurité pendant l'exécution. Pour déboguer systemd-tmpfiles, il peut être utile de l'invoquer directement depuis la ligne de commande avec un niveau de journalisation augmenté (voir $SYSTEMD_LOG_LEVEL ci-dessous).

COMMANDES ET OPTIONS

Les commandes suivantes sont comprises :

--create

Si cette commande est passée, tous les fichiers et répertoires marqués avec f, F, w, d, D, v, p, L, c, b, m dans les fichiers de configuration sont créés ou écrits. Les fichiers et répertoires marqués avec z, Z, t, T, a, et A ont leur propriétaire, leur mode d'accès et leurs étiquettes de sécurité définis.

--clean

Si cette commande est passée, tous les fichiers et répertoires ayant un paramètre d'âge configuré seront nettoyés.

--remove

Si cette commande est passée, le contenu des répertoires marqués avec D ou R, et les fichiers ou répertoires eux-mêmes marqués avec r ou R sont supprimés à moins qu'un verrou exclusif ou partagé BSD ne soit pris sur eux (voir flock(2)).

--purge

Si cette option est passée, tous les fichiers et répertoires déclarés pour création et marqués du caractère "$" par les fichiers tmpfiles.d/ spécifiés sur la ligne de commande seront supprimés. Spécifiquement, cela agit sur tous les fichiers et répertoires marqués avec f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si ce commutateur est utilisé, au moins un fichier tmpfiles.d/ (ou - pour l'entrée standard) doit être spécifié sur la ligne de commande, sinon l'invocation sera refusée, par mesure de sécurité (car sinon une grande partie des fichiers système installés pourrait être supprimée).

L'usage principal de cette option est de supprimer automatiquement les fichiers et répertoires qui ont été initialement créés pour un paquet installé, lors de la désinstallation du paquet.

Il est recommandé d'exécuter d'abord cette commande en combinaison avec --dry-run (voir ci-dessous) pour vérifier quels fichiers et répertoires seront supprimés.

Attention ! Ce n'est généralement pas la commande que vous voulez ! Dans la plupart des cas, --remove est ce que vous recherchez.

Ajouté dans la version 256.

--user

Exécute la configuration "utilisateur", c'est-à-dire les fichiers tmpfiles.d/ dans les répertoires de configuration utilisateur.

Ajouté dans la version 236.

--boot

Exécute également les lignes avec un point d'exclamation. Les lignes qui ne sont pas sûres à exécuter sur un système en cours d'exécution peuvent être marquées de cette manière. systemd-tmpfiles est exécuté au démarrage avec l'option --boot spécifiée et exécutera ces lignes. Lorsqu'il est invoqué à nouveau plus tard, il doit être appelé sans --boot.

Ajouté dans la version 209.

--graceful

Ignore les lignes de configuration relatives à des utilisateurs ou des groupes inconnus. Cette option est destinée à être utilisée au début du démarrage, avant que tous les utilisateurs ou groupes n'aient été créés.

Ajouté dans la version 254.

--dry-run

Traite la configuration et affiche les opérations qui seraient effectuées, mais ne modifie rien dans le système de fichiers.

Ajouté dans la version 256.

--prefix=chemin

Applique uniquement les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 212.

--exclude-prefix=chemin

Ignore les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 207.

-E

Raccourci pour "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", c'est-à-dire exclure les hiérarchies généralement sauvegardées par des systèmes de fichiers virtuels ou en mémoire. Ceci est utile en combinaison avec --root=, si l'arbre de répertoires spécifié contient un arbre d'OS sans ces systèmes de fichiers virtuels/en mémoire montés, car il n'est généralement pas souhaitable de créer des fichiers et répertoires sous ces sous-répertoires s'ils doivent être recouvertes en cours d'exécution.

Ajouté dans la version 247.

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés par le chemin root alternatif donné, y compris les chemins de recherche de configuration.

Lorsque cette option est utilisée, le service de noms (NSS) de la libc est contourné pour résoudre les utilisateurs et les groupes. Au lieu de cela, les fichiers /etc/passwd et /etc/group dans le root alternatif sont lus directement. Cela signifie que les utilisateurs/groupes non listés dans ces fichiers ne seront pas résolus, c'est-à-dire que LDAP, NIS et d'autres bases de données complexes ne seront pas pris en compte.

Envisagez de combiner ceci avec -E pour vous assurer que l'invocation ne crée pas de fichiers ou de répertoires sous des points de montage dans l'image de l'OS sur laquelle vous opérez qui sont généralement recouverts pendant l'exécution.

OPTIONS

Options can be specified on the command line or via configuration files in tmpfiles.d(5) format. Command line options take precedence over configuration files, and configuration files are read in the order of the $SYSTEMD_CONFIG_DIR directory (if set), followed by /etc/tmpfiles.d/, /usr/lib/tmpfiles.d/, and /run/tmpfiles.d/. Command line options specified later take precedence over earlier ones.

The following options are understood:

--create, -c
Create the directories and files listed in the configuration. If a directory is created, it is created with the specified mode, owner, and group. If a file is created, its content is written, and it is created with the specified mode, owner, and group. If the file already exists, it is truncated and overwritten.
--clean, -q
Remove files and directories that are not listed in the configuration. This is useful for cleaning up temporary directories. For each listed path, if it is older than the specified time, it is removed. For directories, the removal is recursive.
--remove, -r
Remove files and directories that are listed in the configuration. This is useful for cleaning up temporary files and directories that are no longer needed. If a directory is removed, the removal is recursive.
--purge, -p
Remove files and directories that are listed in the configuration and are older than the specified time. This is similar to --clean but only applies to entries explicitly listed in the configuration.
--root=root
Run systemd-tmpfiles in a different directory, specified by root. This is useful for operating on a different system image. All paths are then interpreted relative to this directory.
--image=image
Takes a path to a disk image file or block device node. If specified all operations are applied to file system in the indicated disk image. This is similar to --root= but operates on file systems stored in disk images or block devices. The disk image should either contain just a file system or a set of file systems within a GPT partition table, following the Discoverable Partitions Specification[1]. For further information on supported disk images, see systemd-nspawn(1)'s switch of the same name.

Implies -E.

Added in version 247.

--image-policy=policy
Takes an image policy string as argument, as per systemd.image-policy(7). The policy is enforced when operating on the disk image specified via --image=, see above. If not specified, defaults to the "*" policy, i.e. all recognized file systems in the image are used.
--replace=PATH
When this option is given, one or more positional arguments must be specified. All configuration files found in the directories listed in tmpfiles.d(5) will be read, and the configuration given on the command line will be handled instead of and with the same priority as the configuration file PATH.

This option is intended to be used when package installation scripts are running and files belonging to that package are not yet available on disk, so their contents must be given on the command line, but the admin configuration might already exist and should be given higher priority.

Added in version 238.

--cat-config
Copy the contents of config files to standard output. Before each file, the filename is printed as a comment.
--tldr
Copy the contents of config files to standard output. Only the "interesting" parts of the configuration files are printed, comments and empty lines are skipped. Before each file, the filename is printed as a comment.
--no-pager
Do not pipe output into a pager.
-h, --help
Print a short help text and exit.
--version
Print a short version string and exit.

It is possible to combine --create, --clean, and --remove in one invocation (in which case removal and cleanup are executed before creation of new files). For example, during boot the following command line is executed to ensure that all temporary and volatile directories are removed and created according to the configuration file:

systemd-tmpfiles --remove --create

CREDENTIALS

systemd-tmpfiles supports the service credentials logic as implemented by ImportCredential=/LoadCredential=/SetCredential= (see systemd.exec(5) for details). The following credentials are used when passed in:

tmpfiles.extra

The contents of this credential may contain additional lines to operate on. The credential contents should follow the same format as any other tmpfiles.d/ drop-in configuration file. If this credential is passed it is processed after all of the drop-in files read from the file system. The lines in the credential can hence augment existing lines of the OS, but not override them.

Added in version 252.

Note that by default the systemd-tmpfiles-setup.service unit file (and related unit files) is set up to inherit the "tmpfiles.extra" credential from the service manager.

ENVIRONMENT

$SYSTEMD_LOG_LEVEL

The maximum log level of emitted messages (messages with a higher log level, i.e. less important ones, will be suppressed). Takes a comma-separated list of values. A value may be either one of (in order of decreasing importance) emerg, alert, crit, err, warning, notice, info, debug, or an integer in the range 0...7. See syslog(3) for more information. Each value may optionally be prefixed with one of console, syslog, kmsg or journal followed by a colon to set the maximum log level for that specific log target (e.g. SYSTEMD_LOG_LEVEL=debug,console:info specifies to log at debug level except when logging to the console which should be at info level). Note that the global maximum log level takes priority over any per target maximum log levels.

$SYSTEMD_LOG_COLOR

A boolean. If true, messages written to the tty will be colored according to priority.

This setting is only useful when messages are written directly to the terminal, because journalctl(1) and other tools that display logs will color messages based on the log level on their own.

$SYSTEMD_LOG_TIME

A boolean. If true, console log messages will be prefixed with a timestamp.

This setting is only useful when messages are written directly to the terminal or a file, because journalctl(1) and other tools that display logs will attach timestamps based on the entry metadata on their own.

$SYSTEMD_LOG_LOCATION

A boolean. If true, messages will be prefixed with a filename and line number in the source code where the message originates.

Note that the log location is often attached as metadata to journal entries anyway. Including it directly in the message text can nevertheless be convenient when debugging programs.

$SYSTEMD_LOG_TARGET

The destination for log messages. One of console (log to the attached tty), console-prefixed (log to the attached tty but with prefixes encoding the log level and "facility", see syslog(3), kmsg (log to the kernel circular log buffer), journal (log to the journal), journal-or-kmsg (log to the journal if available, and to kmsg otherwise), auto (determine the appropriate log target automatically, the default), null (disable log output).

$SYSTEMD_PAGER, $PAGER

Pager to use when --no-pager is not given. $SYSTEMD_PAGER is used if set; otherwise $PAGER is used. If neither $SYSTEMD_PAGER nor $PAGER are set, a set of well-known pager implementations is tried in turn, including less(1) and more(1), until one is found. If no pager implementation is discovered, no pager is invoked. Setting those environment variables to an empty string or the value "cat" is equivalent to passing --no-pager.

Note: if $SYSTEMD_PAGERSECURE is not set, $SYSTEMD_PAGER and $PAGER can only be used to disable the pager (with "cat" or ""), and are otherwise ignored.

$SYSTEMD_LESS

Override the options passed to less (by default "FRSXMK").

Users might want to change two options in particular:

K

This option instructs the pager to exit immediately when Ctrl+C is pressed. To allow less to handle Ctrl+C itself to switch back to the pager command prompt, unset this option.

If the value of $SYSTEMD_LESS does not include "K", and the pager that is invoked is less, Ctrl+C will be ignored by the executable, and needs to be handled by the pager.

X

This option instructs the pager to not send termcap initialization and deinitialization strings to the terminal. It is set by default to allow command output to remain visible in the terminal even after the pager exits. Nevertheless, this prevents some pager functionality from working, in particular paged output cannot be scrolled with the mouse.

Note that setting the regular $LESS environment variable has no effect for less invocations by systemd tools.

See less(1) for more discussion.

$SYSTEMD_LESSCHARSET

Override the charset passed to less (by default "utf-8", if the invoking terminal is determined to be UTF-8 compatible).

Note that setting the regular $LESSCHARSET environment variable has no effect for less invocations by systemd tools.

$SYSTEMD_PAGERSECURE

Common pager commands like less(1), in addition to "paging", i.e. scrolling through the output, support opening of or writing to other files and running arbitrary shell commands. When commands are invoked with elevated privileges, for example under sudo(8) or pkexec(1), the pager becomes a security boundary. Care must be taken that only programs with strictly limited functionality are used as pagers, and unintended interactive features like opening or creation of new files or starting of subprocesses are not allowed. "Secure mode" for the pager may be enabled as described below, if the pager supports that (most pagers are not written in a way that takes this into consideration). It is recommended to either explicitly enable "secure mode" or to completely disable the pager using --no-pager or PAGER=cat when allowing untrusted users to execute commands with elevated privileges.

This option takes a boolean argument. When set to true, the "secure mode" of the pager is enabled. In "secure mode", LESSSECURE=1 will be set when invoking the pager, which instructs the pager to disable commands that open or create new files or start new subprocesses. Currently only less(1) is known to understand this variable and implement "secure mode".

When set to false, no limitation is placed on the pager. Setting SYSTEMD_PAGERSECURE=0 or not removing it from the inherited environment may allow the user to invoke arbitrary commands.

When $SYSTEMD_PAGERSECURE is not set, systemd tools attempt to automatically figure out if "secure mode" should be enabled and whether the pager supports it. "Secure mode" is enabled if the effective UID is not the same as the owner of the login session, see geteuid(2) and sd_pid_get_owne

r_uid.3.fr'>sd_pid_get_owner_uid(3), ou lors de l'exécution sous sudo(8) ou des outils similaires ($SUDO_UID est défini [2]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagers qui ne sont pas connus pour implémenter le « mode sécurisé » ne seront pas du tout utilisés. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à la commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pager.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être respectées, à l'exception de la désactivation du pager, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Prend un argument booléen. Si vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : « 16 », « 256 » pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256, respectivement. Ceci peut être spécifié pour outrepasser la décision automatique basée sur $TERM et ce à quoi la console est connectée.

$SYSTEMD_URLIFY

La valeur doit être un booléen. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminaux qui le prennent en charge. Ceci peut être spécifié pour outrepasser la décision que systemd prend en fonction de $TERM et d'autres conditions.

OPERATION DE NETTOYAGE NON PRIVILÉGIÉE

systemd-tmpfiles essaie d'éviter de modifier les heures d'accès et de modification des répertoires qu'il accède, ce qui nécessite les privilèges CAP_FOWNER. Lorsqu'il s'exécute en tant qu'utilisateur non root, les répertoires qui sont vérifiés pour les fichiers à nettoyer auront leur heure d'accès augmentée, ce qui pourrait empêcher leur nettoyage.

STATUT DE SORTIE

En cas de succès, 0 est retourné. Si la configuration était syntaxiquement invalide (erreurs de syntaxe, arguments manquants, ...), de sorte que certaines lignes ont dû être ignorées, mais qu'aucune autre erreur ne s'est produite, 65 est retourné (EX_DATAERR de /usr/include/sysexits.h). Si la configuration était syntaxiquement valide, mais n'a pas pu être exécutée (manque de permissions, création de fichiers dans des répertoires manquants, contenu invalide lors de l'écriture dans des valeurs /sys/, ...), 73 est retourné (EX_CANTCREAT de /usr/include/sysexits.h). Sinon, 1 est retourné (EXIT_FAILURE de /usr/include/stdlib.h).

Note : lors de la création d'éléments, si la cible existe déjà, mais est du mauvais type ou ne correspond pas autrement à l'état demandé, et que l'opération forcée n'a pas été demandée avec « + », un message est émis, mais l'échec est autrement ignoré.
