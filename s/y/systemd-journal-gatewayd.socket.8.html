SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8) systemd-journal-gatewayd.service SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8)

NOM

systemd-journal-gatewayd.service, systemd-journal-gatewayd.socket, systemd-journal-gatewayd - Serveur HTTP pour les événements du journal

SYNOPSIS

systemd-journal-gatewayd.service

systemd-journal-gatewayd.socket

/usr/lib/systemd/systemd-journal-gatewayd [OPTIONS...]

DESCRIPTION

systemd-journal-gatewayd sert les événements du journal sur le réseau. Les clients doivent se connecter via HTTP. Le serveur écoute par défaut sur le port 19531. Si --cert= est spécifié, le serveur attend des connexions HTTPS.

Le programme est lancé par systemd(1) et s'attend à recevoir un unique socket. Utilisez systemctl start systemd-journal-gatewayd.socket pour démarrer le service, et systemctl enable systemd-journal-gatewayd.socket pour qu'il démarre au démarrage.

OPTIONS

Les options suivantes sont comprises :

--cert=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire le certificat du serveur. Le certificat doit être au format PEM. Cette option bascule systemd-journal-gatewayd en mode HTTPS et doit être utilisée conjointement avec --key=.

Ajouté dans la version 198.

--key=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire la clé secrète du serveur correspondant au certificat spécifié avec --cert=. La clé doit être au format PEM.

Ajouté dans la version 198.

--trust=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire un certificat CA. Le certificat doit être au format PEM.

Ajouté dans la version 236.

--system, --user

Limite les entrées servies aux entrées des services système et du noyau, ou aux entrées des services de l'utilisateur actuel. Ceci a la même signification que les options --system et --user pour journalctl(1). Si aucune n'est spécifiée, toutes les entrées accessibles sont servies.

Ajouté dans la version 249.

-m, --merge

Sert les entrées entrelacées de tous les journaux disponibles, y compris ceux des autres machines. Ceci a la même signification que l'option --merge pour journalctl(1).

Ajouté dans la version 249.

-D DIR, --directory=DIR

Prend un chemin de répertoire en argument. Si spécifié, systemd-journal-gatewayd servira le répertoire de journal spécifié DIR au lieu des chemins par défaut du journal d'exécution et du journal système.

Ajouté dans la version 232.

--file=GLOB

Prend un glob de fichiers en argument. Sert les entrées des fichiers journaux spécifiés correspondant à GLOB au lieu des chemins par défaut du journal d'exécution et du journal système. Peut être spécifié plusieurs fois, auquel cas les fichiers seront correctement entrelacés. Ceci a la même signification que l'option --file= pour journalctl(1).

Ajouté dans la version 249.

-h, --help

Affiche un bref texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

URL SUPPORTÉES

Les URL suivantes sont reconnues :

/boots

Retourne une réponse json-seq (RFC 7464) contenant des objets JSON, chacun contenant le numéro de démarrage, son ID et les horodatages du premier et du dernier message. Les démarrages sont retournés en commençant par le dernier démarrage et utilisent le même schéma que journalctl --list-boots --output json.

Ajouté dans la version 258.

/browse

Navigation interactive.

Ajouté dans la version 197.

/entries[?option1&option2=value...]

Récupération des événements dans divers formats.

La partie Accept: de l'en-tête HTTP détermine le format. Les valeurs supportées sont décrites ci-dessous.

La partie Range: de l'en-tête HTTP détermine la plage d'événements retournés. Les valeurs supportées sont décrites ci-dessous.

Les paramètres GET peuvent être utilisés pour modifier les événements retournés. Les paramètres supportés sont décrits ci-dessous.

Ajouté dans la version 197.

/machine

Retourne une structure JSON décrivant la machine.

Exemple :

{ "machine_id" : "8cf7ed9d451ea194b77a9f118f3dc446",
  "boot_id" : "3d3c9efaf556496a9b04259ee35df7f7",
  "hostname" : "fedora",
  "os_pretty_name" : "Fedora 19 (Rawhide)",
  "virtualization" : "kvm",
  ...}

Ajouté dans la version 197.

/fields/NOM_CHAMP

Retourne une liste des valeurs de ce champ présentes dans les journaux.

Ajouté dans la version 197.

EN-TÊTE ACCEPT

Accept: format

Formats reconnus :

text/plain

Par défaut. Sortie en texte brut de type syslog, une ligne par entrée de journal (comme journalctl --output short).

Ajouté dans la version 197.

application/json

Les entrées sont formatées en structures de données JSON, une par ligne (comme journalctl --output json). Voir Journal JSON Format[1] pour plus d'informations.

Ajouté dans la version 197.

text/event-stream

Les entrées sont formatées en structures de données JSON, encapsulées dans un format adapté aux Server-Sent Events[2] (comme journalctl --output json-sse).

Ajouté dans la version 229.

application/vnd.fdo.journal

Les entrées sont sérialisées dans un flux binaire (mais principalement textuel) adapté aux sauvegardes et au transfert réseau (comme journalctl --output export). Voir Journal Export Format[3] pour plus d'informations.

Ajouté dans la version 197.

EN-TÊTE RANGE

Range: entries=[curseur][[:nb_saut]:[nb_entrées]]

Range: realtime=[depuis]:[jusqu'à][[:nb_saut]:nb_entrées]

où curseur est une chaîne de curseur, par défaut la première entrée, depuis et jusqu'à sont des horodatages (secondes depuis le 01/01/1970 00:00:00 UTC), nb_saut est un entier, nb_entrées est un entier non signé.

La plage par défaut correspond à tous les événements disponibles.

Si nb_saut est négatif et qu'aucun curseur n'est donné, la dernière entrée sera le point de référence.

PARAMÈTRES GET DE L'URL

Les paramètres suivants peuvent être utilisés dans l'URL :

follow

attend les nouveaux événements (comme journalctl --follow, le nombre d'événements retournés n'est pas limité, sauf si nb_entrées est spécifié dans l'en-tête Range).

Ajouté dans la version 197.

discrete

Vérifie que le curseur spécifié fait référence à une entrée dans le journal. Retourne uniquement cette entrée.

Ajouté dans la version 197.

boot

Limite les événements au démarrage actuel du système (comme journalctl -b).

Ajouté dans la version 197.

CLÉ=correspondance

Correspond aux champs du journal. Voir systemd.journal-fields(7).

Ajouté dans la version 197.

EXEMPLES

Récupérer les événements de ce démarrage depuis le journal local au format Journal Export Format[3] :

curl --silent -H'Accept: application/vnd.fdo.journal' \
       'http://localhost:19531/entries?boot'

Écouter les dumps de noyau :

curl 'http://localhost:19531/entries?follow&MESSAGE_ID=fc2e22bc6ee6

Voir la référence [1] pour le format JSON du journal.

Voir la référence [2] pour les Server-Sent Events.

Voir la référence [3] pour le format d'exportation du journal.
