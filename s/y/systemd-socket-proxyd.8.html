NOM

systemd-socket-proxyd - Proxy de socket réseau bidirectionnel pour un autre socket (potentiellement distant)

SYNTAXE

systemd-socket-proxyd [OPTIONS...] HÔTE:PORT

systemd-socket-proxyd [OPTIONS...] CHEMIN-SOCKET-UNIX

DESCRIPTION

systemd-socket-proxyd est un proxy de redirection générique de sockets réseau activé par socket pour les sockets de flux IPv4, IPv6 et UNIX. Il peut être utilisé pour rediriger bidirectionnellement le trafic d'un socket d'écoute local vers un socket de destination local ou distant.

Une utilisation de cet outil est de fournir une prise en charge de l'activation par socket pour les services qui ne prennent pas en charge l'activation par socket nativement. Au nom du service à activer, le proxy hérite du socket de systemd, accepte chaque connexion client, ouvre une connexion à un serveur configuré pour chaque client, puis transfère bidirectionnellement les données entre les deux.

Le comportement de cet utilitaire est similaire à socat(1). Les principales différences pour systemd-socket-proxyd sont la prise en charge de l'activation par socket avec "Accept=no" et une conception événementielle qui évolue mieux avec le nombre de connexions.

Notez que systemd-socket-proxyd ne redirigera pas les informations du canal secondaire du socket, c'est-à-dire qu'il ne redirigera pas SCM_RIGHTS, SCM_CREDENTIALS, SCM_SECURITY, SO_PEERCRED, SO_PEERPIDFD, SO_PEERSEC, SO_PEERGROUPS et similaires.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche un court texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

--connections-max=, -c

Définit le nombre maximum de connexions simultanées, par défaut 256. Si la limite de connexions concurrentes est atteinte, les connexions supplémentaires seront refusées.

Ajouté dans la version 233.

--exit-idle-time=

Définit le temps avant de quitter lorsqu'il n'y a pas de connexions, par défaut infini. Prend une valeur sans unité en secondes, ou une valeur de durée telle que "5min 20s".

Ajouté dans la version 246.

ÉTAT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

EXEMPLES

Exemple Simple

Utilise deux services avec une dépendance et sans isolation d'espace de noms.

Exemple 1. proxy-to-nginx.socket

[Socket]
ListenStream=80
[Install]
WantedBy=sockets.target

Exemple 2. proxy-to-nginx.service

[Unit]
Requires=nginx.service
After=nginx.service
Requires=proxy-to-nginx.socket
After=proxy-to-nginx.socket
[Service]
Type=notify
ExecStart=/usr/lib/systemd/systemd-socket-proxyd /run/nginx/socket
PrivateTmp=yes
PrivateNetwork=yes

Exemple 3. nginx.conf

[...]
server {
    listen       unix:/run/nginx/socket;
    [...]

Exemple 4. Activation du proxy

# systemctl enable --now proxy-to-nginx.socket
$ curl http://localhost:80/

Si nginx.service a StopWhenUnneeded= défini, alors passer --exit-idle-time= à systemd-socket-proxyd permet aux deux services de s'arrêter pendant les périodes d'inactivité.

Exemple d'Espace de Noms

Similaire à ci-dessus, mais exécute le proxy de socket et le service principal dans le même espace de noms privé, en supposant que nginx.service a également PrivateTmp= et PrivateNetwork= définis.

Exemple 5. proxy-to-nginx.socket

[Socket]
ListenStream=80
[Install]
WantedBy=sockets.target

Exemple 6. proxy-to-nginx.service

[Unit]
Requires=nginx.service
After=nginx.service
Requires=proxy-to-nginx.socket
After=proxy-to-nginx.socket
JoinsNamespaceOf=nginx.service
[Service]
Type=notify
ExecStart=/usr/lib/systemd/systemd-socket-proxyd 127.0.0.1:8080
PrivateTmp=yes
PrivateNetwork=yes

Exemple 7. nginx.conf

[...]
server {
    listen       8080;
    [...]

Exemple 8. Activation du proxy

# systemctl enable --now proxy-to-nginx.socket
$ curl http://localhost:80/
