NOM

systemd-import-generator - Générateur pour télécharger automatiquement des images disque au démarrage

SYNTAXE

/usr/lib/systemd/system-generators/systemd-import-generator

DESCRIPTION

systemd-import-generator peut être utilisé pour télécharger automatiquement des images disque (archives tar ou DDI) via systemd-importd.service(8) au démarrage, en fonction des paramètres de la ligne de commande du noyau ou des identifiants système. Ceci est utile pour déployer automatiquement une image systemd-confext(8), systemd-sysext(8), systemd-nspawn(1) / systemd-vmspawn(1) ou systemd-portabled.service(8) au démarrage. Ceci fournit une fonctionnalité équivalente à importctl(1), mais accessible via la ligne de commande du noyau et les identifiants système.

systemd-import-generator implémente systemd.generator(7).

LIGNE DE COMMANDE DU NOYAU

systemd-import-generator comprend les paramètres de kernel-command-line(7) suivants :

systemd.pull=

Cette option prend un triplet séparé par des deux-points : chaîne d'options, nom d'image cible locale et URL distante. Le nom d'image cible locale peut être spécifié comme une chaîne vide, auquel cas le nom est dérivé de l'URL distante spécifiée. L'URL distante doit utiliser les schémas "http://", "https://", "file://". La chaîne d'options elle-même est une liste d'options séparées par des virgules :

rw, ro

Contrôle si l'image locale doit être marquée comme lecture seule. Si non spécifié, la lecture seule est désactivée par défaut.

Ajouté dans la version 257.

verify=

Contrôle si le téléchargement doit être validé cryptographiquement avant d'être installé. Prend l'une des valeurs "no", "checksum", ou "signature" (par défaut si non spécifié). Pour les détails, voir le paramètre --verify= de importctl(1).

Ajouté dans la version 257.

sysext, confext, machine, portable

Contrôle la classe de l'image à télécharger, et donc finalement le répertoire de destination de l'image, en fonction de ce choix, le répertoire de destination /var/lib/extensions/, /var/lib/confexts/, /var/lib/machines/ ou /var/lib/portables/ est sélectionné.

La spécification d'exactement une de ces options est obligatoire.

Ajouté dans la version 257.

tar, raw

Contrôle le type de ressource à télécharger, c'est-à-dire une archive tar (éventuellement compressée) qui doit être décompressée dans une arborescence de fichiers, ou une image disque brute (DDI) (éventuellement compressée).

La spécification d'exactement une de ces options est obligatoire.

Ajouté dans la version 257.

blockdev

Si cette option est spécifiée, l'image téléchargée est attachée à un périphérique bloc en boucle (via systemd-loop@.service) une fois terminée. Cela permet de démarrer à partir d'images disque téléchargées. Ceci n'est supporté que pour les images disque "raw".

Note : lorsque cette option est utilisée dans le but de monter une image disque conforme à la Discoverable Disk Image Specification[1] en tant que système de fichiers racine, et que la logique de découverte automatique de partitions GPT telle qu'implémentée par systemd-gpt-auto-generator(8) doit la traiter, il est essentiel de spécifier "rootdisk" comme nom local pour l'importation. De plus, "root=gpt-auto" doit être spécifié explicitement sur la ligne de commande du noyau. Également, préfixez l'option de ligne de commande "systemd.pull=" avec "rd." pour garantir qu'elle soit exécutée dans le disque RAM initial (initrd) déjà, voir aussi ci-dessous.

Ajouté dans la version 258.

bootorigin

Si cette option est spécifiée, à la place de l'URL, un simple nom de fichier peut être spécifié. Si le système démarre via le démarrage réseau HTTP UEFI, le dernier composant de l'URL d'origine du démarrage réseau est remplacé par ce nom de fichier et utilisé comme source de téléchargement. Ceci permet donc de construire automatiquement les URL des images disque à partir de l'URL de démarrage d'origine utilisée pour invoquer le noyau ou le chargeur de démarrage.

Si cette option est utilisée et que le système ne démarre pas effectivement via le démarrage réseau HTTP UEFI, le téléchargement est gracieusement ignoré. Ou en d'autres termes, sans autres modifications, il est possible de construire une image initrd qui démarrera à partir d'un disque local si disponible, ou à partir d'une image disque téléchargée si utilisée via le démarrage réseau.

Ajouté dans la version 258.

runtime=

Prend un argument booléen. Si défini sur true, l'image est téléchargée sous la hiérarchie /run/, si défini sur false sous la hiérarchie /var/lib/. Si non spécifié, la valeur par défaut est true dans le disque RAM initial (initrd) et false sur le système hôte.

Ajouté dans la version 258.

Ajouté dans la version 257.

systemd.pull.success_action=, systemd.pull.failure_action=

Contrôle si une action telle que redémarrer, éteindre, et similaire doit être exécutée après avoir terminé le téléchargement avec succès, ou sans succès. Voir SuccessAction=/FailureAction= sur systemd.unit(5) pour les détails sur les actions disponibles. Si non spécifié, aucune action n'est effectuée et le système continuera à démarrer normalement.

Ajouté dans la version 257.

Ces options de ligne de commande du noyau sont interprétées uniquement par le système hôte. Si ces options sont préfixées par "rd.", elles sont interprétées par le disque RAM initial (initrd) à la place.

IDENTIFIANTS

systemd-import-generator supporte la logique des identifiants système. Les identifiants suivants sont utilisés lorsqu'ils sont passés :

import.pull

Cet identifiant doit être un fichier texte, avec chaque ligne faisant référence à une opération de téléchargement. Chaque ligne doit suivre le même format que la valeur de l'option de ligne de commande du noyau systemd.pull= décrite ci-dessus.

Ajouté dans la version 257.

EXEMPLES

Exemple 1. Téléchargement d'une extension de configuration 

systemd.pull=raw,confext::https://example.com/myconfext.raw.gz

Avec une option de ligne de commande du noyau comme celle ci-dessus, une DDI d'extension de configuration est téléchargée automatiquement au démarrage depuis l'URL spécifiée, validée cryptographiquement, décompressée et installée.

Exemple 2. Téléchargement d'une extension système (sans validation)

systemd.pull=tar,sysext,verify=no::https://example.com/mysysext.tar.gz

Avec une option de ligne de commande du noyau comme celle ci-dessus, une archive tar d'extension système est téléchargée automatiquement au démarrage depuis l'URL spécifiée, décompressée et installée – sans aucune validation cryptographique. Ceci est utile à des fins de développement dans des machines virtuelles et des conteneurs. Attention : ne déployez pas un système avec la validation désactivée de cette façon !

Exemple 3. Téléchargement d'une image de disque racine (raw) dans la mémoire, pour démarrer dessus

rd.systemd.pull=raw,machine,verify=no,blockdev:image:https://example.com/image.raw.xz root=/dev/disk/by-loop-ref/image.raw-part2

Ceci télécharge l'image disque spécifiée, l'enregistre localement sous le nom "image", et l'attache à un périphérique bloc en boucle une fois terminé. Il démarre ensuite à partir de la 2ème partition de l'image.

Exemple 4. Démarrage sur une image disque (raw), avec URL dérivée du démarrage réseau HTTP UEFI

rd.systemd.pull=raw,machine,verify=no,blockdev,bootorigin:rootdisk:image.raw.xz root=gpt-auto

Ceci est similaire à l'exemple précédent, mais cette fois l'URL source est dérivée automatiquement de l'URL de démarrage réseau HTTP UEFI. Par exemple, si une UKI démarre à partir d'une URL "http://example.com/image.efi", cela entraînera le téléchargement d'un disque racine depuis "http://example.com/image.raw.xz". De plus, ceci utilise le générateur systemd-gpt-auto-gen

systemd-import-generator.8.en — systemd, version 258.2

NAME

systemd-import-generator, systemd-importd.service, systemd-importctl — import disk images and mount them

SYNOPSIS

systemd-import-generator [DEVICE]

DESCRIPTION

The systemd-import-generator is a systemd generator that may mount disk images specified via kernel command line parameters. It primarily handles the parameters described in systemd.exec(5) under the heading "Disk Image Mount Options", but specifically supports the root= and rootfstype= parameters too. It is usually invoked very early in the boot process by systemd(1) itself.

The primary goal is to allow importing a root file system from a disk image file or an existing block device, and then mounting it read-write under /run/machines/root.

The generator is invoked with the kernel command line arguments as its input. It inspects these arguments for parameters that specify a disk image to mount.

If a suitable parameter is found, the generator will usually start the systemd-importd.service service, which is responsible for the actual import and mount operation. It makes use of systemd-library(3) to perform the import. After the import is complete, the generator may start a systemd-import-mount unit, which is a transient unit that mounts the imported root file system.

If the root= kernel command line parameter is used to specify the imported image (e.g. root=import:/path/to/image.raw), the generator will automatically set up the appropriate mount unit to make this the actual root file system for the remainder of the boot process.

KERNEL COMMAND LINE

The following kernel command line parameters are relevant:

rd.systemd.machine_owner=UNIT
Specifies the owner unit for the imported machine. Defaults to systemd-importd.service. This is useful if you are managing the import process with a custom unit.
rd.systemd.pull=LIST
A comma-separated list of machine images to import. Each element in the list may be prefixed with a key word like root: or var: to specify the target mount point. The list supports the syntax described in systemd.exec(5) under "Disk Image Mount Options".
root=import:PATH
Specifies that the root file system should be imported from the disk image at the given path. The path can be a local file path or a URL. This parameter implies rd.systemd.pull=root:PATH.
rootfstype=TYPE
Specifies the file system type of the imported root image. This is passed to the mount command.

CREDENTIALS

If the imported image requires credentials (e.g., for accessing a network URL), these may be provided via systemd system credentials, as described in systemd.system-credentials(7).

EXAMPLES

Example 1. Boot into a raw disk image (loop device)

root=/dev/disk/by-label/my-root-image

This is the traditional way of booting from a disk image. The generator will detect the root= parameter and use the standard systemd-importd service to mount the specified block device as the root file system.

Example 2. Boot into a raw disk image (URL)

root=import:https://example.com/images/my-root.raw

This example boots into a raw disk image available at a URL. The generator will download the image using systemd-importd.service and then mount it as the root file system.

Example 3. Boot into a tarball

rd.systemd.pull=root:tar,image.tar.xz

This example boots into a tarball. The tar keyword indicates that the image is a tar archive. The systemd-importd service will extract the tarball and mount it as the root file system.

Example 4. Importing multiple images

rd.systemd.pull=root:image.raw,var:data.tar.gz

This command imports two images: image.raw as the root file system and data.tar.gz as /run/machines/var.

Example 5. Boot into disk image (tar), with URL derived from UEFI HTTP network booting

rd.systemd.pull=tar,machine,verify=no,bootorigin:root:image.tar.xz root=bind:/run/machines/root

This is similar to the previous example, but instead of a raw (i.e. block device based) disk image the system boots into a tarball that is downloaded from the originating UEFI network server.
