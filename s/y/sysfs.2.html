sysfs(2) Manuel des appels système sysfs(2)

NOM

sysfs - obtenir des informations sur le type de système de fichiers

SYNOPSIS

[[obsolète]] int sysfs(int option, const char *fsname);
[[obsolète]] int sysfs(int option, unsigned int fs_index, char *buf);
[[obsolète]] int sysfs(int option);

DESCRIPTION

Note: si vous recherchez des informations sur le système de fichiers sysfs normalement monté sur /sys, consultez sysfs(5).

L'appel système sysfs() (obsolète) retourne des informations sur les types de systèmes de fichiers actuellement présents dans le noyau. La forme spécifique de l'appel sysfs() et les informations retournées dépendent de l'option en cours :

1
Traduit la chaîne d'identifiant de système de fichiers fsname en un indice de type de système de fichiers.
2
Traduit l'indice de type de système de fichiers fs_index en une chaîne d'identifiant de système de fichiers terminée par un caractère nul. Cette chaîne sera écrite dans le tampon pointé par buf. Assurez-vous que buf a suffisamment d'espace pour accepter la chaîne.
3
Retourne le nombre total de types de systèmes de fichiers actuellement présents dans le noyau.

La numérotation des indices de type de système de fichiers commence à zéro.

VALEUR DE RETOUR

En cas de succès, sysfs() retourne l'indice du système de fichiers pour l'option 1, zéro pour l'option 2, et le nombre de systèmes de fichiers configurés actuellement pour l'option 3. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Soit fsname, soit buf est en dehors de votre espace d'adressage accessible.
EINVAL
fsname n'est pas un identifiant de type de système de fichiers valide ; fs_index est hors limites ; option est invalide.

NORMES

Aucune.

HISTORIQUE

SVr4.

Cet appel système dérivé de System-V est obsolète ; ne l'utilisez pas. Sur les systèmes avec /proc, les mêmes informations peuvent être obtenues via /proc ; utilisez cette interface à la place.

BOGUES

Il n'y a pas de support libc ou glibc. Il n'y a aucun moyen de deviner la taille que buf devrait avoir.

VOIR AUSSI

proc(5), sysfs(5)
