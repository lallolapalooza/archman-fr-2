NOM

systemd-storagetm.service, systemd-storagetm - Expose tous les périphériques de blocage locaux comme périphériques de stockage de masse NVMe-TCP

SYNOPSIS

systemd-storagetm.service

/usr/lib/systemd/systemd-storagetm [OPTIONS...] [PÉRIPHÉRIQUE]

DESCRIPTION

systemd-storagetm.service est un service qui expose tous les périphériques de blocage locaux comme périphériques de stockage de masse NVMe-TCP. Son cas d'utilisation principal est d'être invoqué par l'unité storage-target-mode.target dans laquelle on peut démarrer.


Avertissement

Les disques NVMe sont actuellement exposés sans authentification ni chiffrement, en mode lecture/écriture. Cela signifie que les pairs du réseau peuvent lire et écrire sur le périphérique sans aucune restriction. Cette fonctionnalité ne doit donc être utilisée que dans une configuration locale.

Notez que pour fonctionner correctement, le réseau doit également être configuré. Le mécanisme recommandé pour démarrer en mode cible de stockage est d'ajouter "rd.systemd.unit=storage-target-mode.target ip=link-local" sur la ligne de commande du noyau. Notez que "ip=link-local" ne configure que des adresses IP locales (link-local), c'est-à-dire IPv4LL et IPv6LL, ce qui signifie des adresses non routables. Ceci est fait pour des raisons de sécurité, de sorte que seuls les systèmes sur le lien local puissent accéder aux périphériques. Utilisez "ip=dhcp" pour attribuer également des adresses routables. Pour plus de détails, consultez systemd-network-generator.service(8).

Sauf si l'option --all est utilisée, le programme attend un ou plusieurs périphériques de blocage ou fichiers réguliers à exposer via NVMe-TCP comme arguments.

OPTIONS

Les options suivantes sont comprises :

--nqn=

Prend une chaîne de caractères. Si spécifié, configure le nom qualifié NVMe (NVMe Qualified Name) à utiliser pour les périphériques de stockage de masse NVMe-TCP exposés. Le NQN doit suivre la syntaxe décrite dans la spécification NVM Express Base Specification 2.0c[1], section 4.5 "NVMe Qualified Names". Notez que le NQN spécifié ici sera suffixé par un point et le nom du périphérique de blocage avant d'être exposé sur la cible NVMe. S'il n'est pas spécifié, la valeur par défaut est "nqn.2023-10.io.systemd:storagetm.ID", où ID est remplacé par un identifiant de 128 bits dérivé de machine-id(5).

Ajouté dans la version 255.

--all, -a

Si spécifié, expose tous les périphériques de blocage locaux via NVMe-TCP, actuels et futurs (c'est-à-dire qu'il surveille l'arrivée et le départ des périphériques de blocage et met à jour la liste NVMe-TCP si nécessaire). Notez que par défaut, les périphériques de blocage qui proviennent du même périphérique de blocage que le périphérique de blocage sous-jacent du système de fichiers racine actuel sont exclus. Si l'option est spécifiée deux fois, ce mécanisme de sécurité est désactivé.

Ajouté dans la version 255.

--list-devices

Affiche une liste des périphériques de blocage candidats sur lesquels cette commande peut opérer. Spécifiquement, cela énumère les périphériques de blocage actuellement présents et affiche leurs chemins de nœuds de périphérique ainsi que leurs liens symboliques.

Ajouté dans la version 257.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.
