NOM

systemd-sbsign - Signer des binaires PE pour le démarrage sécurisé EFI

SYNTAXE

systemd-sbsign [OPTIONS...] {COMMANDE}

DESCRIPTION

systemd-sbsign peut être utilisé pour signer des binaires PE pour le démarrage sécurisé EFI.

COMMANDES

sign

Signe le binaire PE donné pour le démarrage sécurisé EFI. Prend un chemin vers un binaire PE comme argument. Si le binaire PE a déjà une table de certificats, la nouvelle signature y sera ajoutée. Sinon, une nouvelle table de certificats sera créée. Le binaire PE signé sera écrit au chemin spécifié avec --output=.

Ajouté dans la version 257.

OPTIONS

Les options suivantes sont comprises :

--output=CHEMIN

Spécifie le chemin où écrire le binaire PE signé ou les données à signer hors ligne lors de l'utilisation de l'option --prepare-offline-signing.

Ajouté dans la version 257.

--private-key=CHEMIN/URI, --private-key-source=TYPE[:NOM], --certificate=CHEMIN, --certificate-source=TYPE[:NOM]

Définit la clé privée et le certificat de démarrage sécurisé à utiliser avec le verbe sign. L'option --certificate= prend un chemin vers un certificat X.509 encodé en PEM ou une URI qui est passée au fournisseur OpenSSL configuré avec --certificate-source. L'option --certificate-source prend l'une des valeurs "file" ou "provider", cette dernière étant suivie d'un identifiant de fournisseur spécifique, séparé par un deux-points, par exemple "provider:pkcs11". L'option --private-key= prend un chemin ou une URI qui sera passée au moteur ou au fournisseur OpenSSL, tel que spécifié par --private-key-source= sous forme de tuple "type:nom", tel que "engine:pkcs11". Le moteur de signature ou le fournisseur OpenSSL spécifié sera utilisé pour signer le binaire PE.

Ajouté dans la version 257.

--prepare-offline-signing

Lorsque cette option est spécifiée, la commande sign écrit les données qui doivent être signées au chemin spécifié avec --output= au lieu d'écrire le binaire PE signé. Ces données peuvent ensuite être signées hors bande, après quoi la signature peut être attachée au binaire PE en utilisant les options --signed-data= et --signed-data-signature=.

Ajouté dans la version 258.

--signed-data=CHEMIN, --signed-data-signature=CHEMIN

Configure les données signées (telles qu'écrites au chemin spécifié avec --output= lors de l'utilisation de l'option --prepare-offline-signing) et la signature correspondante pour la commande sign.

Ajouté dans la version 258.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

EXEMPLES

Exemple 1. Signature hors bande du démarrage EFI sécurisé d'un binaire PE

Ce qui suit effectue une signature hors bande du démarrage sécurisé de systemd-boot :

SD_BOOT="$(find /usr/lib/systemd/boot/efi/ -name "systemd-boot*.efi" | head -n1)"
# Extrait les données qui doivent être signées hors bande.
/usr/lib/systemd/systemd-sbsign \
    sign \
    --certificate=secure-boot-certificate.pem \
    --output=signed-data.bin \
    --prepare-offline-signing \
    "$SD_BOOT"
# Signe les données hors bande. Cette étape se produit généralement hors bande sur un système séparé.
openssl dgst -sha256 -sign secure-boot-private-key.pem -out signed-data.sig signed-data.bin
# Attache les données signées et leur signature au binaire PE de systemd-boot.
/usr/lib/systemd/systemd-sbsign \
    sign \
    --certificate=secure-boot-certificate.pem \
    --output="$SD_BOOT.signed" \
    --signed-data=signed-data.bin \
    --signed-data-signature=signed-data.sig \
    "$SD_BOOT"
