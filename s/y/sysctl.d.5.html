SYSCTL.D(5) sysctl.d SYSCTL.D(5)

NOM

sysctl.d - Configurer les paramètres du noyau au démarrage

SYNTAXE

/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/local/lib/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
clé.nom.sous.proc.sys = valeur
clé/nom/sous/proc/sys = valeur
clé/partie.milieu.avec.points/foo = 123
clé.partie/milieu/avec/points.foo = 123
-clé.qui.ne.échouera.pas = valeur
clé.motif.*.avec.glob = quoi que ce soit
-clé.motif.exclu.avec.glob
clé.motif.remplacé.avec.glob = personnalisé

DESCRIPTION

Au démarrage, systemd-sysctl.service(8) lit les fichiers de configuration des répertoires ci-dessus pour configurer les paramètres du noyau sysctl(8).

FORMAT DE CONFIGURATION

Les fichiers de configuration contiennent une liste d'assignations de variables, séparées par des sauts de ligne. Les lignes vides et les lignes dont le premier caractère non blanc est un "#" ou un ";" sont ignorées.

Notez que "/" ou "." peuvent être utilisés comme séparateurs dans les noms de variables sysctl. Si le premier séparateur est une barre oblique, les barres obliques et les points restants sont laissés intacts. Si le premier séparateur est un point, les points et les barres obliques sont échangés. "kernel.domainname=foo" et "kernel/domainname=foo" sont équivalents et provoqueront l'écriture de "foo" dans /proc/sys/kernel/domainname. Soit "net.ipv4.conf.enp3s0/200.forwarding", soit "net/ipv4/conf/enp3s0.200/forwarding" peuvent être utilisés pour faire référence à /proc/sys/net/ipv4/conf/enp3s0.200/forwarding. Un motif glob(7) peut être utilisé pour écrire la même valeur à toutes les clés correspondantes. Les clés pour lesquelles un motif explicite existe seront exclues de toute correspondance glob. De plus, une clé peut être explicitement exclue de la configuration par des motifs glob correspondants en préfixant le nom de la clé avec un caractère "-" et sans le faire suivre de "=", voir SYNTAXE.

Toutes les erreurs d'autorisation d'accès et les tentatives d'écriture de variables absentes du système local sont enregistrées au niveau de débogage et ne provoquent pas l'échec du service. D'autres types d'erreurs lors de la configuration des variables sont enregistrés avec une priorité plus élevée et provoquent un échec du service à la fin (après le traitement des autres variables). À titre d'exception, si une assignation de variable est préfixée par un seul caractère "-", l'échec de la configuration de la variable pour quelque raison que ce soit sera enregistré au niveau de débogage et ne provoquera pas l'échec du service.

Les paramètres configurés avec les fichiers sysctl.d seront appliqués tôt au démarrage. Les options spécifiques aux interfaces réseau seront également appliquées individuellement pour chaque interface réseau à mesure qu'elle apparaît dans le système. (Plus précisément, net.ipv4.conf.*, net.ipv6.conf.*, net.ipv4.neigh.* et net.ipv6.neigh.*).

De nombreux paramètres sysctl ne deviennent disponibles que lorsque certains modules du noyau sont chargés. Les modules sont généralement chargés à la demande, par exemple lorsqu'un matériel spécifique est branché ou que le réseau est activé. Cela signifie que systemd-sysctl.service(8), qui s'exécute au début du démarrage, ne configurera pas ces paramètres s'ils deviennent disponibles après son exécution. Pour configurer de tels paramètres, il est recommandé d'ajouter une règle udev(7) pour les définir lorsqu'ils deviennent disponibles. Alternativement, une option légèrement plus simple et moins efficace consiste à ajouter le module à modules-load.d(5), ce qui le fera charger statiquement avant l'application des paramètres sysctl (voir l'exemple ci-dessous).

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

Les fichiers de configuration sont lus à partir des répertoires /etc/, /run/, /usr/local/lib/ et /usr/lib/, dans l'ordre de priorité, comme indiqué dans la section SYNTAXE ci-dessus. Les fichiers doivent avoir l'extension ".conf". Les fichiers dans /etc/ remplacent les fichiers du même nom dans /run/, /usr/local/lib/ et /usr/lib/. Les fichiers dans /run/ remplacent les fichiers du même nom sous /usr/.

Tous les fichiers de configuration sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du répertoire dans lequel ils se trouvent. Si plusieurs fichiers spécifient la même option, l'entrée du fichier ayant le nom lexicographiquement le plus récent aura la priorité. Ainsi, la configuration d'un fichier donné peut soit être complètement remplacée (en plaçant un fichier du même nom dans un répertoire de priorité plus élevée), soit les paramètres individuels peuvent être modifiés (en spécifiant des paramètres supplémentaires dans un fichier portant un nom différent, classé plus tard).

Les paquets doivent installer leurs fichiers de configuration dans /usr/lib/ (paquets de distribution) ou /usr/local/lib/ (installations locales) [1]. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration fournis par les paquets du fournisseur.

Il est recommandé de préfixer tous les noms de fichiers par un nombre à deux chiffres et un trait d'union pour simplifier le tri. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de configuration dans /usr/ et la plage 60-90 pour les fichiers de configuration dans /etc/ et /run/, afin de s'assurer que les fichiers de configuration locaux et transitoires auront toujours la priorité sur les fichiers de configuration fournis par le vendeur du système d'exploitation.

Si l'administrateur souhaite désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du vendeur. Si le fichier de configuration du vendeur est inclus dans l'image initrd, l'image doit être régénérée.

EXEMPLES

Exemple 1. Définir le nom de domaine YP du noyau

/etc/sysctl.d/nom-domaine.conf :

kernel.domainname=exemple.com

Exemple 2. Appliquer des paramètres disponibles uniquement lorsqu'un certain module est chargé (méthode un)

/etc/udev/rules.d/99-bridge.rules :

ACTION=="add", SUBSYSTEM=="module", KERNEL=="br_netfilter", \
      RUN+="/usr/lib/systemd/systemd-sysctl --prefix=/net/bridge"

/etc/sysctl.d/bridge.conf :

net.bridge.bridge-nf-call-ip6tables = 0
net.bridge.bridge-nf-call-iptables = 0
net.bridge.bridge-nf-call-arptables = 0

Cette méthode applique les paramètres lorsque le module est chargé. Veuillez noter que, sauf si le module br_netfilter est chargé, les paquets pontés ne seront pas filtrés par Netfilter (à partir du noyau 3.18), donc ne pas charger le module suffit à éviter le filtrage.

Exemple 3. Appliquer des paramètres disponibles uniquement lorsqu'un certain module est chargé (méthode deux)

/etc/modules-load.d/bridge.conf :

br_netfilter

/etc/sysctl.d/bridge.conf :

net.bridge.bridge-nf-call-ip6tables = 0
net.bridge.bridge-nf-call-iptables = 0
net.bridge.bridge-nf-call-arptables = 0

Cette méthode force le module à être toujours chargé. Veuillez noter que, sauf si le module br_netfilter est chargé, les paquets pontés ne seront pas filtrés par Netfilter (à partir du noyau 3.18), donc ne pas charger le module suffit à éviter le filtrage.

Exemple 4. Définir les propriétés de routage réseau pour toutes les interfaces

/etc/sysctl.d/20-rp_filter.conf :

net.ipv4.conf.default.rp_filter = 2
net.ipv4.conf.*.rp_filter = 2
-net.ipv4.conf.all.rp_filter
net.ipv4.conf.hub0.rp_filter = 1

La clé rp_filter sera définie sur "2" pour toutes les interfaces, à l'exception de "hub0". Nous définissons d'abord net.ipv4.conf.default.rp_filter, de sorte que toutes les interfaces ajoutées *plus tard* recevront cette valeur (cela couvre également toutes les interfaces détectées pendant notre exécution). Le glob correspond à toutes les interfaces qui ont été détectées *auparavant*. Le glob correspondra également à net.ipv4.conf.all.rp_filter, que nous ne voulons pas définir du tout, il est donc explicitement exclu. Et "hub0" est exclu du glob car il a un réglage explicite.
