NOM

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Créer, supprimer et nettoyer les fichiers et répertoires

SYNTAXE

systemd-tmpfiles [OPTIONS...] [FICHIER_CONFIG...]

Unités système :

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unités utilisateur :

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPTION

systemd-tmpfiles crée, supprime et nettoie les fichiers et répertoires, en utilisant le format de fichier de configuration et l'emplacement spécifiés dans tmpfiles.d(5). Historiquement, il était conçu pour gérer les fichiers volatils et temporaires, comme son nom l'indique, mais il fournit des fonctionnalités génériques de gestion de fichiers et peut être utilisé pour gérer n'importe quel type de fichier. Il doit être appelé avec une ou plusieurs commandes --create, --remove, et --clean, pour sélectionner le sous-ensemble d'opérations respectif.

S'il est appelé sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par tmpfiles.d(5) sont exécutées. Lorsqu'il est appelé avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments donnés en ligne de commande sont utilisés à la place du CHEMIN du fichier de configuration. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée au lieu d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans aucun slash), tous les répertoires de configuration sont parcourus pour trouver un fichier correspondant et le fichier trouvé qui a la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration d'autres fichiers correspondants.

Les services système (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) appellent systemd-tmpfiles pour créer des fichiers système et effectuer un nettoyage à l'échelle du système. Ces services lisent les fichiers de configuration contrôlés par l'administrateur dans les répertoires tmpfiles.d/. Les services utilisateur (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) appellent également systemd-tmpfiles, mais il lit un ensemble séparé de fichiers, qui comprend des fichiers contrôlés par l'utilisateur sous ~/.config/user-tmpfiles.d/ et ~/.local/share/user-tmpfiles.d/, et des fichiers contrôlés par l'administrateur sous /usr/share/user-tmpfiles.d/. Les utilisateurs peuvent l'utiliser pour créer et nettoyer des fichiers sous leur contrôle, mais l'instance système effectue un nettoyage global et n'est pas influencée par la configuration utilisateur. Notez que cela signifie qu'un nettoyage basé sur le temps configuré dans l'instance système, comme celui généralement configuré pour /tmp/, affectera également les fichiers créés par l'instance utilisateur s'ils sont placés dans /tmp/, même si le nettoyage basé sur le temps de l'instance utilisateur est désactivé.

Pour réappliquer les paramètres après modification de la configuration, redémarrez simplement systemd-tmpfiles-clean.service, ce qui appliquera tous les paramètres qui peuvent être exécutés en toute sécurité à l'exécution. Pour déboguer systemd-tmpfiles, il peut être utile de l'appeler directement depuis la ligne de commande avec un niveau de journalisation accru (voir $SYSTEMD_LOG_LEVEL ci-dessous).

COMMANDES ET OPTIONS

Les commandes suivantes sont comprises :

--create

Si cette commande est passée, tous les fichiers et répertoires marqués avec f, F, w, d, D, v, p, L, c, b, m dans les fichiers de configuration sont créés ou écrits. Les fichiers et répertoires marqués avec z, Z, t, T, a, et A ont leur propriété, leur mode d'accès et leurs étiquettes de sécurité définis.

--clean

Si cette commande est passée, tous les fichiers et répertoires avec un paramètre d'âge configuré seront nettoyés.

--remove

Si cette commande est passée, le contenu des répertoires marqués avec D ou R, et les fichiers ou répertoires eux-mêmes marqués avec r ou R sont supprimés à moins qu'un verrou exclusif ou partagé BSD ne soit pris sur eux (voir flock(2)).

--purge

Si cette option est passée, tous les fichiers et répertoires déclarés pour création et marqués avec le caractère "$" par les fichiers tmpfiles.d/ spécifiés sur la ligne de commande seront supprimés. Plus précisément, cela s'applique à tous les fichiers et répertoires marqués avec f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si ce commutateur est utilisé, au moins un fichier tmpfiles.d/ (ou - pour l'entrée standard) doit être spécifié sur la ligne de commande, sinon l'invocation sera refusée, par mesure de sécurité (car autrement une grande partie des fichiers système installés pourrait être supprimée).

L'utilisation principale de cette option est de supprimer automatiquement les fichiers et répertoires qui ont été initialement créés au nom d'un paquet installé lors de la désinstallation du paquet.

Il est recommandé d'exécuter d'abord cette commande en combinaison avec --dry-run (voir ci-dessous) pour vérifier quels fichiers et répertoires seront supprimés.

Attention ! Ce n'est généralement pas la commande que vous voulez ! Dans la plupart des cas, --remove est ce que vous recherchez.

Ajouté dans la version 256.

--user

Exécute la configuration "utilisateur", c'est-à-dire les fichiers tmpfiles.d/ dans les répertoires de configuration utilisateur.

Ajouté dans la version 236.

--boot

Exécute également les lignes avec un point d'exclamation. Les lignes qui ne sont pas sûres à exécuter sur un système en cours d'exécution peuvent être marquées de cette façon. systemd-tmpfiles est exécuté au démarrage précoce avec --boot spécifié et exécutera ces lignes. Lorsqu'il est appelé à nouveau plus tard, il doit être appelé sans --boot.

Ajouté dans la version 209.

--graceful

Ignore les lignes de configuration concernant des utilisateurs ou des groupes inconnus. Cette option est destinée à être utilisée au démarrage précoce avant que tous les utilisateurs ou groupes n'aient été créés.

Ajouté dans la version 254.

--dry-run

Traite la configuration et affiche les opérations qui seraient effectuées, mais ne modifie rien dans le système de fichiers.

Ajouté dans la version 256.

--prefix=chemin

Applique uniquement les règles avec des chemins qui commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 212.

--exclude-prefix=chemin

Ignore les règles avec des chemins qui commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 207.

-E

Un raccourci pour "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", c'est-à-dire exclure les hiérarchies typiquement sauvegardées par des systèmes de fichiers virtuels ou en mémoire. Ceci est utile en combinaison avec --root=, si l'arborescence spécifiée contient une arborescence de système d'exploitation sans ces systèmes de fichiers virtuels/en mémoire montés, car il n'est généralement pas souhaitable de créer des fichiers et répertoires sous ces sous-répertoires s'ils sont censés être surmontés pendant l'exécution.

Ajouté dans la version 247.

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront précédés du chemin racine alternatif root donné, y compris les chemins de recherche de configuration.

Lorsque cette option est utilisée, le Name Service Switch (NSS) de libc est contourné pour la résolution des utilisateurs et des groupes. Au lieu de cela, les fichiers /etc/passwd et /etc/group dans la racine alternative sont lus directement. Cela signifie que les utilisateurs/groupes non listés dans ces fichiers ne seront pas résolus, c'est-à-dire que les bases de données complexes comme LDAP, NIS, etc. ne sont pas prises en compte.

Envisagez de combiner cela avec -E pour vous assurer que l'invocation ne crée pas de fichiers ou de répertoires sous les points de montage de l'image du système d'exploitation sur lesquels elle opère, qui sont typiquement surmontés pendant l'exécution.

Ajouté dans la version 212.

--image=image

Prend un chemin vers un fichier image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur les systèmes de fichiers stockés dans des images disque ou des périphériques blocs. L'image disque doit soit contenir uniquement un système de fichiers, soit un ensemble de systèmes de fichiers au sein d'une table de partitions GPT, conformément à la Discoverable Partitions Specification[1]. Pour plus d'informations sur les images disque prises en charge, voir le commutateur du même nom dans systemd-nspawn(1).

Implique -E.

Ajouté dans la version 247.

--image-policy=policy

Prend une chaîne de politique d'image en argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si non spécifiée, elle prend par défaut la politique « * », c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=PATH

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans tmpfiles.d(5) seront lus, et la configuration donnée sur la ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration PATH.

Cette option est destinée à être utilisée lors de l'exécution de scripts d'installation de paquets et lorsque les fichiers appartenant à ce paquet ne sont pas encore disponibles sur le disque, de sorte que leur contenu doit être fourni sur la ligne de commande, mais la configuration de l'administrateur peut déjà exister et devrait avoir une priorité plus élevée.

Ajouté dans la version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties « intéressantes » des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne redirige pas la sortie vers un pagineur.

-h, --help

Imprime un court message d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

Il est possible de combiner --create, --clean et --remove en une seule invocation (auquel cas la suppression et le nettoyage sont exécutés avant la création de nouveaux fichiers). Par exemple, au démarrage, la ligne de commande suivante est exécutée pour garantir que tous les répertoires temporaires et volatiles sont supprimés et créés conformément au fichier de configuration :

systemd-tmpfiles --remove --create

IDENTIFIANTS

systemd-tmpfiles prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

tmpfiles.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier de configuration de type drop-in pour tmpfiles.d/. Si cet identifiant est passé, il est traité après tous les fichiers drop-in lus depuis le système de fichiers. Les lignes de l'identifiant peuvent donc compléter les lignes existantes du système d'exploitation, mais ne pas les remplacer.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-tmpfiles-setup.service (et les fichiers d'unité associés) est configuré pour hériter de l'identifiant "tmpfiles.extra" du gestionnaire de services.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximum des messages émis (les messages avec un niveau de journalisation plus élevé, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, ou un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'une des valeurs suivantes : console, syslog, kmsg ou journal, suivie d'un deux-points, pour définir le niveau de journalisation maximum pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug, sauf lorsqu'il s'agit de journaliser sur la console, qui devrait être au niveau info). Notez que le niveau de journalisation maximum global a la priorité sur tous les niveaux de journalisation maximum par cible.

$SYSTEMD_LOG_COLOR

Un booléen. S'il est vrai, les messages écrits sur le tty seront colorés en fonction de leur priorité.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. S'il est vrai, les messages du journal de la console seront préfixés par un horodatage.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux ajouteront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. S'il est vrai, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent joint en tant que métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages du journal. L'une des valeurs suivantes : console (journaliser sur le tty attaché), console-prefixed (journaliser sur le tty attaché mais avec des préfixes codant le niveau de journalisation et la « facilité », voir syslog(3), kmsg (journaliser dans le tampon circulaire du journal du noyau), journal (journaliser dans le journal), journal-or-kmsg (journaliser dans le journal si disponible, et dans kmsg sinon), auto (déterminer automatiquement la cible de journal appropriée, par défaut), null (désactiver la sortie du journal).

$SYSTEMD_PAGER, $PAGER

Pagineur à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de pagineurs bien connues est essayé tour à tour, y compris less(1) et more(1), jusqu'à ce qu'un soit trouvé. Si aucune implémentation de pagineur n'est découverte, aucun pagineur n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur « cat » est équivalent à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le pagineur (avec « cat » ou « »), et sont par ailleurs ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut « FRSXMK »).

Les utilisateurs pourraient vouloir changer deux options en particulier :

K

Cette option demande au pagineur de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même afin de revenir à l'invite de commande du pagineur, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas « K », et que le pagineur invoqué est less, Ctrl+C sera ignoré par l'exécutable et devra être géré par le pagineur.

X

Cette option demande au pagineur de ne pas envoyer les chaînes d'initialisation et de désinitialisation de termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du pagineur. Néanmoins, cela empêche certaines fonctionnalités du pagineur de fonctionner, en particulier la sortie paginée ne peut pas être défilée avec la souris.

Notez que la définition de la variable d'environnement $LESS normale n'a aucun effet pour les invocations de less par les outils systemd.

Voir less(1) pour plus de discussion.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut « utf-8 », si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET normale n'a aucun effet pour les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pagineur courantes comme less(1), en plus de la « pagination », c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque des commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pagineur devient une limite de sécurité. Des précautions doivent être prises pour que seuls des programmes avec des fonctionnalités strictement limitées soient utilisés comme pagineurs, et que les fonctionnalités interactives indésirables comme l'ouverture ou la création de nouveaux fichiers ou le démarrage de sous-processus ne soient pas autorisées. Le « mode sécurisé » pour le pagineur peut être activé comme décrit ci-dessous, si le pagineur le prend en charge (la plupart des pagineurs ne sont pas écrits de manière à en tenir compte). Il est recommandé d'activer explicitement le « mode sécurisé » ou de désactiver complètement le pagineur en utilisant --no-pager ou PAGER=cat lorsque des utilisateurs non fiables sont autorisés à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'il est défini sur vrai, le « mode sécurisé » du pagineur est activé. En « mode sécurisé », LESSSECURE=1 sera défini lors de l'invocation du pagineur, ce qui demande au pagineur de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou démarrent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le « mode sécurisé ».

Lorsqu'il est défini sur faux, aucune limitation n'est placée sur le pagineur. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le « mode sécurisé » doit être activé et si le pagineur le prend en charge. Le « mode sécurisé » est activé si l'UID effectif n'est pas le même que celui du propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous systemd-tmpfiles-setup.service(8) — systemd v258.2

NAME

systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer, systemd-tmpfiles — create, remove and clean up temporary files and directories

SYNOPSIS

systemd-tmpfiles [--boot] [--create] [--remove] [--clean] [--prefix /path] [--exclude /path] [--directory /path] [--file /path] [--truncate /path] [--verify] [--cat-only] [--all-families] [--no-pager] [--user] [--quiet]

DESCRIPTION

The systemd-tmpfiles utility may be used to manage the lifetime of files and directories in /tmp and /var/tmp and other locations. It reads configuration files from /usr/lib/tmpfiles.d/*.conf, /etc/tmpfiles.d/*.conf, and /run/tmpfiles.d/*.conf.

The configuration files define which files and directories should be created, removed, or cleaned up.

systemd-tmpfiles-setup.service runs during boot to create directories and files defined in the configuration files.

systemd-tmpfiles-clean.service runs periodically (via systemd-tmpfiles-clean.timer) to clean up old files and directories.

COMMANDS AND OPTIONS

--boot
This option is implied by systemd-tmpfiles-setup.service and should not be used directly. It means that only files and directories owned by the boot process should be created, removed or cleaned up. This affects the interpretation of the Age column in the tmpfiles.d configuration files: a value of inf implies that the file/directory should be kept indefinitely, while a numeric value is interpreted as days since boot. This is the default mode for systemd-tmpfiles-setup.service.
--create
Create files and directories that are defined in the configuration files but do not exist. This option is implied by systemd-tmpfiles-setup.service and systemd-tmpfiles when no command is given. It does not affect existing files. It will not remove files or directories.
--remove
Remove files and directories that are defined in the configuration files but exist and should not be there anymore. This option is implied by systemd-tmpfiles-setup.service and systemd-tmpfiles when no command is given. It does not affect files that are not mentioned in the configuration files.
--clean
Remove old files and directories that are defined in the configuration files. This option is implied by systemd-tmpfiles-clean.service. It only affects files and directories matching the age criteria specified in the configuration files. It will not remove files that are not mentioned in the configuration files. It does not affect files or directories that should be created or removed unconditionally.
--prefix=/path
Only process lines in the configuration files that refer to paths prefixed by /path. This option may be specified multiple times.
--exclude=/path
Do not process lines in the configuration files that refer to paths prefixed by /path. This option may be specified multiple times.
--directory=/path
Process only lines in the configuration files that refer to the specific directory /path. This is useful for testing specific configuration files. This option may be specified multiple times.
--file=/path
Process only lines in the configuration files that refer to the specific file /path. This is useful for testing specific configuration files. This option may be specified multiple times.
--truncate=/path
Truncate the file /path to zero size if it exists. This option is useful for clearing log files or other files that should be kept but emptied regularly.
--verify
Verify the current state of the temporary files against the configuration. This option does not change anything, but prints messages about files that are not in the desired state. This is useful for debugging and testing.
--cat-only
Only output the contents of files that would be created or modified. Do not create or modify any files. This option is useful for seeing what changes would be made.
--all-families
When creating directories, create them with default permissions for all known filesystem families (e.g. POSIX, SELinux, ...). This is normally not needed as the default behaviour is to create directories with permissions suitable for the running system.
--no-pager
Do not pipe command output into a pager. This is useful when scripting or when the output is large and needs to be redirected.
--user
This option is used by systemd-tmpfiles when run as a user service. It allows the user to manage temporary files in their home directory.
--quiet
Suppress informational messages. Only errors and warnings will be printed.

CREDENTIALS

On systems that employ PortableServices, systemd-tmpfiles may be invoked with specific user and group credentials. In this case, it will operate on behalf of the specified user and group, respecting their permissions. If no specific credentials are provided, it operates as the user it is invoked as.

ENVIRONMENT

The behavior of systemd-tmpfiles and related utilities is affected by the following environment variables:

$SYSTEMD_PAGERSECURE
This variable controls whether the pager is invoked securely. If set to 1, the pager is invoked with options that prevent it from executing arbitrary commands. This is the default when systemd-tmpfiles is run via sudo(8) or similar tools ($SUDO_UID is set [2]). In those cases, SYSTEMD_PAGERSECURE=1 will be set and pagers which are not known to implement "secure mode" will not be used at all. Note that this autodetection only covers the most common mechanisms to elevate privileges and is intended as convenience. It is recommended to explicitly set $SYSTEMD_PAGERSECURE or disable the pager.
$SYSTEMD_PAGER
Determines the pager program to be used for displaying output. If this variable is set, systemd-tmpfiles will use the specified pager unless $SYSTEMD_PAGERSECURE is not set to 1.
$PAGER
This variable serves as a fallback for the pager program if $SYSTEMD_PAGER is not set. Similar to $SYSTEMD_PAGER, its use is subject to $SYSTEMD_PAGERSECURE.
$SYSTEMD_COLORS
Takes a boolean argument. When true, systemd and related utilities will use colors in their output, otherwise the output will be monochrome. Additionally, the variable can take one of the following special values: "16", "256" to restrict the use of colors to the base 16 or 256 ANSI colors, respectively. This can be specified to override the automatic decision based on $TERM and what the console is connected to.
$SYSTEMD_URLIFY
The value must be a boolean. Controls whether clickable links should be generated in the output for terminal emulators supporting this. This can be specified to override the decision that systemd makes based on $TERM and other conditions.

Note that if the $SYSTEMD_PAGER or $PAGER variables are to be honoured, other than to disable the pager, $SYSTEMD_PAGERSECURE must be set too.

UNPRIVILEGED --CLEANUP OPERATION

systemd-tmpfiles tries to avoid changing the access and modification times on the directories it accesses, which requires CAP_FOWNER privileges. When running as non-root, directories which are checked for files to clean up will have their access time bumped, which might prevent their cleanup.

EXIT STATUS

On success, 0 is returned. If the configuration was syntactically invalid (syntax errors, missing arguments, ...), so some lines had to be ignored, but no other errors occurred, 65 is returned (EX_DATAERR from /usr/include/sysexits.h). If the configuration was syntactically valid, but could not be executed (lack of permissions, creation of files in missing directories, invalid contents when writing to /sys/ values, ...), 73 is returned (EX_CANTCREAT from /usr/include/sysexits.h). Otherwise, 1 is returned (EXIT_FAILURE from /usr/include/stdlib.h).

Note: when creating items, if the target already exists, but is of the wrong type or otherwise does not match the requested state, and forced operation has not been requested with "+", a message is emitted, but the failure is otherwise ignored.
