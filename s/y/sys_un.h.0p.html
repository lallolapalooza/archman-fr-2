PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sys/un.h — définitions pour les sockets de domaine UNIX

SYNOPIS

#include <sys/un.h>

DESCRIPTION

L'en-tête <sys/un.h> définira la structure sockaddr_un, qui inclura au moins les membres suivants :

sa_family_t  sun_family  Famille d'adresses.
char         sun_path[]  Chemin d'accès du socket.

La structure sockaddr_un est utilisée pour stocker les adresses des sockets de domaine UNIX. Les pointeurs vers ce type seront convertis par les applications en struct sockaddr * pour être utilisés avec les fonctions de socket.

L'en-tête <sys/un.h> définira le type sa_family_t tel que décrit dans <sys/socket.h>.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

La taille de sun_path a été intentionnellement laissée indéfinie. Ceci est dû au fait que différentes implémentations utilisent différentes tailles. Par exemple, 4.3 BSD utilise une taille de 108 et 4.4 BSD une taille de 104. Étant donné que la plupart des implémentations proviennent de versions BSD, la taille est généralement comprise entre 92 et 108.

Les applications ne doivent pas supposer une longueur particulière pour sun_path ni supposer qu'elle peut contenir {_POSIX_PATH_MAX} octets (256).

Bien que les applications soient tenues d'initialiser tous les membres (y compris ceux qui ne sont pas standard) d'une structure sockaddr_in6 (voir <netinet_in.h>), il n'en est pas de même pour la structure sockaddr_un, car historiquement de nombreuses applications n'initialisaient que les membres standard. Malgré cela, il est conseillé aux applications d'initialiser les structures sockaddr_un d'une manière similaire à l'initialisation requise des structures sockaddr_in6.
