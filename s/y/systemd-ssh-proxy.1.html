NOM

systemd-ssh-proxy - Plugin client SSH pour se connecter aux sockets AF_VSOCK et AF_UNIX

SYNOPIS

Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
    ProxyUseFdpass yes

/usr/lib/systemd/systemd-ssh-proxy [ADRESSE] [PORT]

DESCRIPTION

systemd-ssh-proxy est un petit plugin "proxy" pour l'outil ssh(1) qui permet de se connecter aux sockets AF_UNIX et AF_VSOCK. Il implémente l'interface définie par l'option de configuration ProxyCommand de ssh. Il est destiné à être utilisé avec un fragment de configuration ssh_config(5) comme suit :

Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
    ProxyUseFdpass yes
    CheckHostIP no
Host .host
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy unix/run/ssh-unix-local/socket %p
    ProxyUseFdpass yes
    CheckHostIP no

Un fragment de configuration dans ce sens est installé par défaut dans /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf.

Avec cela en place, les connexions SSH à la chaîne hôte "unix/" suivie d'un chemin absolu dans le système de fichiers AF_UNIX vers un socket seront dirigées vers le socket spécifié, qui doit être de type SOCK_STREAM. De même, les connexions SSH à "vsock/" suivies d'un CID AF_VSOCK entraîneront une connexion SSH établie vers ce CID. "vsock-mux/" suivi d'un chemin absolu dans le système de fichiers AF_UNIX vers un socket est similaire mais pour cloud-hypervisor/firecracker qui n'autorisent pas la communication AF_VSOCK directe entre l'hôte et les invités, et fournissent leur propre multiplexeur sur les sockets AF_UNIX. Voir cloud-hypervisor VSOCK support[1] et Using the Firecracker Virtio-vsock Device[2]. Notez que "%" peut être utilisé comme séparateur au lieu de "/" pour être compatible avec des outils comme "scp" et "rsync".

De plus, se connecter à ".host" établira une connexion à l'hôte local via SSH, sans impliquer le réseau.

Cet outil est destiné à être utilisé conjointement avec systemd-ssh-generator(8) qui, lorsqu'il est exécuté dans une VM ou un conteneur, liera SSH aux adresses appropriées. systemd-ssh-generator est censé s'exécuter dans le conteneur ou l'invité de la VM, et systemd-ssh-proxy est exécuté sur l'hôte, afin de se connecter au conteneur ou à l'invité de la VM.

ÉTAT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

EXEMPLES

Exemple 1. Communiquer avec une VM locale avec CID 4711

ssh vsock/4711

Exemple 2. Communiquer avec un invité de VM hébergé avec cloud-hypervisor/firecracker

ssh vsock-mux/run/vm-1234.sock

Exemple 3. Communiquer avec l'hôte local via ssh

ssh .host

ou l'équivalent :

ssh unix/run/ssh-unix-local/socket

Exemple 4. Copier le fichier local 'foo' vers une VM locale avec CID 1348

scp foo vsock%1348:
