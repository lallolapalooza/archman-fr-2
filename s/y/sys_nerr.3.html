perror(3) Manuel des fonctions de bibliothèque perror(3)

NOM

perror - imprimer un message d'erreur système

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <stdio.h>
void perror(const char *s);
#include <errno.h>
int errno;  /* Pas vraiment déclaré ainsi ; voir errno(3) */
[[deprecated]] const char *const sys_errlist[];
[[deprecated]] int sys_nerr;
Exigences pour le macro de test de fonctionnalités glibc (voir feature_test_macros(7)) :

sys_errlist, sys_nerr :

    De glibc 2.19 à glibc 2.31 :
        _DEFAULT_SOURCE
    glibc 2.19 et antérieur :
        _BSD_SOURCE

DESCRIPTION

La fonction perror() produit un message sur la sortie d'erreur standard décrivant la dernière erreur rencontrée lors d'un appel à une fonction système ou bibliothèque.

D'abord (si s n'est pas NULL et que *s n'est pas un octet nul ('\0')), la chaîne d'argument s est imprimée, suivie d'un deux-points et d'un espace. Ensuite, un message d'erreur correspondant à la valeur actuelle de errno et une nouvelle ligne sont imprimés.

Pour être la plus utile, la chaîne d'argument devrait inclure le nom de la fonction qui a rencontré l'erreur.

La liste d'erreurs globale sys_errlist[], qui peut être indexée par errno, peut être utilisée pour obtenir le message d'erreur sans la nouvelle ligne. Le plus grand numéro d'erreur fourni dans le tableau est sys_nerr-1. Faites attention lorsque vous accédez directement à cette liste, car de nouvelles valeurs d'erreur pourraient ne pas avoir été ajoutées à sys_errlist[]. L'utilisation de sys_errlist[] est maintenant obsolète ; utilisez strerror(3) à la place.

Lorsqu'un appel système échoue, il retourne généralement -1 et définit la variable errno à une valeur décrivant ce qui s'est mal passé. (Ces valeurs peuvent être trouvées dans <errno.h>.) De nombreuses fonctions de bibliothèque font de même. La fonction perror() sert à traduire ce code d'erreur en une forme lisible par l'homme. Notez que errno n'est pas défini après un appel système ou une fonction de bibliothèque réussi : cet appel pourrait bien modifier cette variable, même s'il réussit, par exemple parce qu'il a utilisé en interne une autre fonction de bibliothèque qui a échoué. Ainsi, si un appel défaillant n'est pas suivi immédiatement d'un appel à perror(), la valeur de errno devrait être sauvegardée.
