NOM

syncthing-stignore - Empêcher la synchronisation des fichiers avec d'autres nœuds

SYNTAXE

.stignore

DESCRIPTION

Si certains fichiers ne doivent pas être synchronisés vers (ou depuis) d'autres appareils, un fichier nommé .stignore peut être créé contenant des motifs de fichiers à ignorer. Le fichier .stignore doit être placé à la racine du dossier synchronisé (les fichiers situés à d'autres emplacements ne sont pas appliqués). Le fichier .stignore lui-même ne sera jamais synchronisé vers d'autres appareils, bien qu'il puisse #include des fichiers qui sont synchronisés entre appareils. Tous les motifs sont relatifs à la racine du dossier synchronisé. Le contenu du fichier .stignore doit être encodé en UTF-8.

NOTE :

Notez que les fichiers ignorés peuvent empêcher la suppression d'un répertoire autrement vide. Voir ci-dessous le préfixe (?d) pour autoriser la suppression des fichiers ignorés.

MOTIFS

Le fichier .stignore contient une liste de motifs de fichiers ou de chemins. Le premier motif correspondant décidera du sort d'un fichier donné.

  • Les noms de fichiers réguliers correspondent à eux-mêmes, c'est-à-dire que le motif foo correspond aux fichiers foo, subdir/foo ainsi qu'à tout répertoire nommé foo. Les espaces sont traités comme des caractères ordinaires, à l'exception des espaces en début et fin de ligne, qui sont automatiquement supprimés.
  • L'astérisque (*) correspond à zéro ou plusieurs caractères dans un nom de fichier, mais ne correspond pas au séparateur de répertoire. te*ne correspond à telephone, subdir/telephone mais pas à tele/phone.
  • Le double astérisque (**) correspond comme ci-dessus, mais aussi aux séparateurs de répertoire. te**ne correspond à telephone, subdir/telephone et tele/sub/dir/phone.
  • Le point d'interrogation (?) correspond à un seul caractère qui n'est pas le séparateur de répertoire. te??st correspond à tebest mais pas à teb/st ou test.
  • Les crochets ([]) dénotent une plage de caractères : [a-z] correspond à toute lettre minuscule.
  • Les accolades ({}) dénotent un ensemble d'alternatives séparées par des virgules : {banana,pineapple} correspond soit à banana, soit à pineapple.
  • Le backslash (\) « échappe » un caractère spécial afin qu'il perde sa signification spéciale. Par exemple, \{banana\} correspond exactement à {banana} et ne dénote pas un ensemble d'alternatives comme ci-dessus.

    NOTE :

Sous Windows, \ est le séparateur de chemin, utilisez donc | pour échapper les caractères spéciaux. Par exemple, |{banana|} correspond à {banana}.

Pour utiliser \ pour échapper les caractères spéciaux (et utiliser / comme séparateur de chemin), insérez un #escape=\ en haut du fichier. Voici un court exemple :

#escape=\
/foo
/path/bar/\{banana\}
/path/baz\[2\]/ex\[3\].txt

#escape=\ doit être placé en haut du fichier, avant tout motif, mais les commentaires en début de fichier et les lignes vides sont acceptés.

Tout fichier inclus à l'aide de #include (voir ci-dessous) nécessitera son propre #escape=\.

L'utilisation de #escape=\ permet d'utiliser le même fichier pour la synchronisation et l'utilisation sur n'importe quel système d'exploitation.

  • Un motif commençant par / ne correspond qu'à la racine du dossier synchronisé. /foo correspond à foo mais pas à subdir/foo.
  • Un motif commençant par #include entraîne le chargement des motifs du fichier nommé. Il est une erreur si un fichier n'existe pas ou est inclus plusieurs fois. Notez que bien que cela puisse être utilisé pour inclure des motifs d'un fichier dans un sous-répertoire, les motifs eux-mêmes sont toujours relatifs à la racine du dossier synchronisé. Exemple : #include more-patterns.txt.

    Toute directive #include à l'intérieur d'un fichier chargé par #include nécessite que les chemins spécifiés soient relatifs au répertoire contenant le fichier chargé, plutôt qu'au répertoire racine synchronisé.

  • Un motif commençant par un préfixe ! annule le motif : les fichiers correspondants sont inclus (c'est-à-dire non ignorés). Cela peut être utilisé pour remplacer des motifs plus généraux qui suivent.

    NOTE :

Les motifs inversés qui peuvent correspondre à des éléments en dessous de la racine du dossier entraîneront Syncthing à parcourir des répertoires autrement ignorés. Si le surveillant est activé, ces répertoires seront également surveillés. Cependant, les répertoires ignorés avant le premier motif inversé peuvent être ignorés en toute sécurité, car le premier motif correspondant l'emporte. Par exemple : 
/foo
/bar
!baz
*

Les répertoires foo et bar seront entièrement ignorés. Cependant, tous les autres répertoires présents doivent être entièrement analysés pour trouver tout élément nommé baz, malgré le fait qu'ils seront ignorés en raison du *. À titre de cas spécial, les motifs racines de premier niveau (par ex., !/foo) ne provoquent pas ce comportement :

!/baz
*

Dans ce cas, seul le répertoire baz sera analysé, car tout le reste est ignoré par le motif *.

  • Un motif commençant par un préfixe (?i) active la correspondance de motif insensible à la casse. (?i)test correspond à test, TEST et tEsT. Le préfixe (?i) peut être combiné avec d'autres motifs, par exemple le motif (?i)!picture*.png indique que Picture1.PNG doit être synchronisé. Sur Mac OS et Windows, les motifs sont toujours insensibles à la casse.
  • Un motif commençant par un préfixe (?d) active la suppression de ces fichiers s'ils empêchent la suppression d'un répertoire. Ce préfixe doit être utilisé par les fichiers générés par le système d'exploitation dont vous acceptez la suppression.

    NOTE :

Les préfixes peuvent être spécifiés dans n'importe quel ordre (par ex., (?d)(?i)), mais ne peuvent pas être combinés dans une seule paire de parenthèses comme (?di).
•
Une ligne commençant par // est un commentaire et n'a aucun effet. Les mêmes doubles barres obliques à tout autre endroit sont interprétées littéralement, par ex., essayer de faire file // comment amènera Syncthing à chercher un fichier nommé file // comment.

EXEMPLE

Étant donné une structure de répertoire commençant à la racine du dossier synchronisé :

.DS_Store
.stignore
foo
foofoo
bar/
    baz
    quux
    quuz
bar2/
    baz
    frobble
My Pictures/
    Img15.PNG

et un fichier .stignore avec le contenu :

(?d).DS_Store
!frobble
!quuz
foo
*2
qu*
(?i)my pictures

tous les fichiers et répertoires nommés « foo », se terminant par un « 2 » ou commençant par « qu » seront ignorés. Le résultat final devient :

.DS_Store     # ignoré, sera supprimé s'il gêne la suppression du répertoire parent
foo           # ignoré, correspond à "foo"
foofoo        # synchronisé, ne correspond pas à "foo" mais correspondrait à "foo*" ou "*foo"
bar/          # synchronisé
    baz       # synchronisé
    quux      # ignoré, correspond à "qu*"
    quuz      # synchronisé, correspond à "qu*" mais est exclu par le "!quuz" précédent
bar2/         # synchronisé, malgré la correspondance avec "*2" grâce à l'enfant frobble
    baz       # ignoré, en raison de l'ignorance du parent
    frobble   # synchronisé, grâce à "!frobble"
My Pictures/  # ignoré, correspond de manière insensible à la casse au motif "(?i)my pictures"
    Img15.PNG # ignoré, en raison de l'ignorance du parent

NOTE :

Veuillez noter que les motifs de répertoire se terminant par une barre oblique some/directory/ correspondent au contenu du répertoire, mais pas au répertoire lui-même. Si vous souhaitez que le motif corresponde au répertoire et à son contenu, assurez-vous qu'il n'y ait pas de / à la fin du motif.

Ajouté dans la version 1.19.0 : Des motifs par défaut peuvent être configurés et prendront effet lors de l'acceptation automatique d'un dossier d'un appareil distant. NAME

syncthing-stignore ― ignore patterns for Syncthing

SYNOPSIS

The file .stignore is used to specify patterns of files and directories that should be ignored by Syncthing. It is placed in the root directory of a Syncthing folder.

DESCRIPTION

Patterns are processed in the order they appear in the file. The first matching pattern determines if a file is ignored or not. If no pattern matches, the file is not ignored.

A leading ! negates the pattern, meaning that files matching the negated pattern will be explicitly included.

If a pattern matches a directory, the directory and all its contents are ignored. If a pattern matches a file, only that file is ignored.

Patterns are relative to the directory containing the .stignore file.

PATTERNS

  • *: Matches any sequence of characters, except for path separators.
  • ?: Matches any single character, except for path separators.
  • **: Matches any sequence of characters, including path separators.
  • [abc]: Matches any single character specified in the brackets.
  • [^abc]: Matches any single character not specified in the brackets.
  • /: Path separator.
  • #: If the character # appears at the beginning of a line, the entire line is treated as a comment.
  • !: If the character ! appears at the beginning of a line, the pattern is negated.

EXAMPLE

To ignore all files ending with .bak and all directories named tmp:

*.bak
tmp/

To ignore all files and directories in the node_modules directory, except for those starting with .:

node_modules/*
!node_modules/.*

Added in version 2.0.0: Windows users can now use the pipe character (|) to escape metacharacters in the .stignore file. Additionally, adding #escape=X to the top of the file, allows users to define X as the escape character for that particular file.
