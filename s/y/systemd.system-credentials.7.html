NOM

systemd.system-credentials - Identifiants système

DESCRIPTION

Les identifiants système et de service[1] sont des objets de données qui peuvent être transmis aux systèmes démarrés ou aux services système lors de leur invocation. Ils peuvent être obtenus à partir de diverses sources externes et propagés dans le système, puis dans les services système. Les identifiants peuvent éventuellement être chiffrés avec une clé spécifique à la machine et/ou verrouillés sur le périphérique TPM2 local, et ne sont déchiffrés que lorsque le service consommateur est invoqué.

Les identifiants système peuvent être utilisés pour le provisionnement et la configuration de divers aspects du système. Selon le composant consommateur, les identifiants sont utilisés uniquement lors des invocations initiales ou sont nécessaires pour toutes les invocations.

Les identifiants peuvent être utilisés pour tout type de données, binaires ou textuelles, et peuvent contenir des mots de passe, des secrets, des certificats, du matériel de clé cryptographique, des informations d'identité, des configurations, et plus encore.

IDENTIFIANTS SYSTÈME BIEN CONNUS

firstboot.keymap

Le mappage de touches de la console à définir (par exemple, "de"). Lu par systemd-firstboot(1), et uniquement respecté si aucun mappage de touches de console n'a été configuré auparavant.

Ajouté dans la version 252.

firstboot.locale, firstboot.locale-messages

La locale système à définir (par exemple, "de_DE.UTF-8"). Lu par systemd-firstboot(1), et uniquement respecté si aucune locale n'a été configurée auparavant. firstboot.locale définit "LANG", tandis que firstboot.locale-message définit "LC_MESSAGES".

Ajouté dans la version 252.

firstboot.timezone

Le fuseau horaire système à définir (par exemple, "Europe/Berlin"). Lu par systemd-firstboot(1), et uniquement respecté si aucun fuseau horaire système n'a été configuré auparavant.

Ajouté dans la version 252.

login.issue

Les données de cet identifiant sont écrites dans /etc/issue.d/50-provision.conf, si le fichier n'existe pas encore. agetty(8) lit ce fichier et affiche son contenu à l'invite de connexion des connexions terminales. Voir issue(5) pour les détails.

Consommé par /usr/lib/tmpfiles.d/provision.conf, voir tmpfiles.d(5).

Ajouté dans la version 252.

login.motd

Les données de cet identifiant sont écrites dans /etc/motd.d/50-provision.conf, si le fichier n'existe pas encore. pam_motd(8) lit ce fichier et affiche son contenu comme "message du jour" lors des connexions terminales. Voir motd(5) pour les détails.

Consommé par /usr/lib/tmpfiles.d/provision.conf, voir tmpfiles.d(5).

Ajouté dans la version 252.

network.hosts

Les données de cet identifiant sont écrites dans /etc/hosts, si le fichier n'existe pas encore. Voir hosts(5) pour les détails.

Consommé par /usr/lib/tmpfiles.d/provision.conf, voir tmpfiles.d(5).

Ajouté dans la version 252.

network.dns, network.search_domains

Informations sur les serveurs DNS et les domaines de recherche. Lu par systemd-resolved.service(8).

Ajouté dans la version 253.

network.conf.*, network.link.*, network.netdev.*, network.network.*

Configure les périphériques réseau. Lu par systemd-network-generator.service(8). Ces identifiants doivent contenir des données de configuration valides pour networkd.conf(5), systemd.link(5), systemd.netdev(5), systemd.network(5). Chaque identifiant correspondant génère un fichier séparé. Exemple : le contenu d'un identifiant network.link.50-foobar sera copié dans un fichier 50-foobar.link.

Notez que les fichiers résultants sont créés en lecture seule pour tous les utilisateurs, il est donc recommandé de ne pas inclure de secrets dans ces identifiants, mais de les fournir via des identifiants séparés directement à systemd-networkd.service, par exemple network.wireguard.* comme décrit ci-dessous.

Ajouté dans la version 256.

network.wireguard.*

Configure les secrets pour les périphériques netdev WireGuard. Lu par systemd-networkd.service(8). Pour plus d'informations, référez-vous à la section [WireGuard] de systemd.netdev(5).

Ajouté dans la version 256.

passwd.hashed-password.root, passwd.plaintext-password.root

Peut contenir le mot de passe (au format haché UNIX ou en texte brut) de l'utilisateur root. Lu par systemd-firstboot(1) et systemd-sysusers(8), et uniquement respecté si aucun mot de passe root n'a été configuré auparavant.

Ajouté dans la version 252.

passwd.shell.root

Le chemin vers le programme shell (par exemple, "/bin/bash") pour l'utilisateur root. Lu par systemd-firstboot(1) et systemd-sysusers(8), et uniquement respecté si aucun shell root n'a été configuré auparavant.

Ajouté dans la version 252.

ssh.ephemeral-authorized_keys-all

Fournit des clés publiques supplémentaires, au format habituel de authorized_keys, pour tous les utilisateurs, pour les connexions entrantes via les unités de socket AF_VSOCK et AF_UNIX générées.

L'utilisation prévue est pour un système hôte (dans des configurations de VM ou de conteneur) de générer une paire de clés et d'injecter la clé publique dans l'invité, en utilisant la clé privée pour se connecter à n'importe quel compte utilisateur sur l'invité via ssh, sans authentification supplémentaire.

Consommé par systemd-ssh-generator(8).

Ajouté dans la version 256.

ssh.authorized_keys.root

Les données de cet identifiant sont écrites dans /root/.ssh/authorized_keys, si le fichier n'existe pas encore. Cela permet de provisionner l'accès SSH pour l'utilisateur root du système.

Consommé par /usr/lib/tmpfiles.d/provision.conf, voir tmpfiles.d(5).

Ajouté dans la version 252.

ssh.listen

Peut être utilisé pour configurer les sockets SSH sur lesquels le système doit être accessible. Voir systemd-ssh-generator(8) pour les détails.

Ajouté dans la version 256.

sysusers.extra

Lignes supplémentaires sysusers.d(5) à traiter lors du démarrage.

Ajouté dans la version 252.

sysctl.extra

Lignes supplémentaires sysctl.d(5) à traiter lors du démarrage.

Ajouté dans la version 252.

tmpfiles.extra

Lignes supplémentaires tmpfiles.d(5) à traiter lors du démarrage.

Ajouté dans la version 252.

fstab.extra

Montages supplémentaires à établir au démarrage. Pour les détails, voir systemd-fstab-generator(8).

Ajouté dans la version 254.

vconsole.keymap, vconsole.keymap_toggle, vconsole.font, vconsole.font_map, vconsole.font_unimap

Paramètres de console à appliquer, voir systemd-vconsole-setup.service(8) pour les détails.

Ajouté dans la version 253.

getty.auto

Utilisé pour contrôler le mode d'exécution de systemd-getty-generator. Voir systemd-getty-generator(8) pour les détails.

Ajouté dans la version 258.

getty.ttys.serial, getty.ttys.container

Utilisé pour lancer des invites de connexion supplémentaires, voir systemd-getty-generator(8) pour les détails.

Ajouté dans la version 254.

journal.forward_to_socket

Utilisé par systemd-journald.8

systemd.system-credentials.7.fr - systemd.system-credentials

NOM

systemd.system-credentials - Informations sur les identifiants système

DESCRIPTION

Les identifiants système sont des fichiers spéciaux qui peuvent être utilisés pour configurer des services système, y compris le gestionnaire de système lui-même (PID 1) et les services qui s'exécutent tôt dans le processus de démarrage.

Ils sont principalement utilisés par systemd-fstab-generator(8), systemd-udev-rules.service(8), et d'autres services similaires qui doivent être configurés avant que les services normaux ne soient démarrés.

Les identifiants système sont généralement placés dans des répertoires dans /etc/systemd/system/, tels que /etc/systemd/system/systemd-fstab-generator.service.d/, /etc/systemd/system/systemd-udev-rules.service.d/, etc.

Ils peuvent également être fournis via des images de disque de démarrage, comme décrit dans systemd-boot(7) et systemd-repart(8).

Le nom des identifiants système suit un schéma général de type.suffix. Le type indique le service ou le composant qui doit consommer l'identifiant, et le suffix est une chaîne arbitraire qui aide à identifier l'identifiant.

IDENTIFIANTS SYSTÈME CONNUS

Voici une liste des identifiants système connus, avec leur type et leur utilisation :

journal.forwardTo

Utilisé par systemd-journald(8) pour déterminer où transférer les messages de journal pour le transfert via socket. Voir journald.conf(5) pour plus de détails.

Ajouté en version 256.

journal.storage

Utilisé par systemd-journald(8) pour déterminer où stocker les fichiers de journal. Voir journald.conf(5) pour plus de détails.

Ajouté en version 256.

vmm.notify_socket

Configure une socket sd_notify(3) compatible AF_VSOCK sur laquelle le gestionnaire de services rapportera les informations de statut, la notification de prêt et le statut de sortie. Pour plus de détails, voir systemd(1).

Ajouté en version 253.

shell.prompt.prefix, shell.prompt.suffix

Définit les chaînes à préfixer et suffixer à toute invite de shell UNIX interactive. Pour plus de détails, voir pam_systemd(8).

Ajouté en version 257.

shell.welcome

Définit une chaîne à imprimer lorsqu'un shell UNIX interactif est initialisé. Pour plus de détails, voir pam_systemd(8).

Ajouté en version 257.

system.machine-id

Prend un ID de 128 bits pour initialiser l'ID de la machine (s'il n'est pas déjà défini). Interprété par le gestionnaire de services (PID 1). Pour plus de détails, voir systemd(1).

Ajouté en version 254.

system.hostname

Accepte un nom d'hôte (transitoire) à configurer tôt au démarrage. Le nom d'hôte statique spécifié dans /etc/hostname, s'il est configuré, a la priorité sur ce réglage. Interprété par le gestionnaire de services (PID 1). Pour plus de détails, voir systemd(1).

Ajouté en version 254.

home.add-signing-key.*

Ajoute une nouvelle clé de signature pour les enregistrements d'utilisateurs au système. Le contenu de l'identifiant doit contenir une clé de signature d'utilisateur, par exemple telle que rapportée par homectl get-signing-key. Plusieurs clés peuvent être spécifiées, et elles seront placées sous le nom du suffixe du nom de l'identifiant (qui doit lui-même porter le suffixe .public). Pour plus de détails, voir homectl(1).

Ajouté en version 258.

home.create.*

Crée un nouvel espace personnel pour l'utilisateur spécifié avec les données d'enregistrement d'utilisateur fournies. Pour plus de détails, voir homectl(1).

Ajouté en version 256.

home.register.*

Enregistre un espace personnel existant pour l'utilisateur spécifié avec les données d'enregistrement d'utilisateur fournies. Pour plus de détails, voir homectl(1).

Ajouté en version 258.

cryptsetup.passphrase, cryptsetup.tpm2-pin, cryptsetup.fido2-pin, cryptsetup.pkcs11-pin, cryptsetup.luks2-pin

Spécifie la phrase secrète/les codes PIN à utiliser pour déverrouiller les volumes de stockage chiffrés. Pour plus de détails, voir systemd-cryptsetup(8).

Ajouté en version 256.

systemd.extra-unit.*, systemd.unit-dropin.*

Ces identifiants spécifient des unités supplémentaires et des fichiers drop-in à ajouter au système. Pour plus de détails, voir systemd-debug-generator(8).

Ajouté en version 256.

udev.conf.*, udev.rules.*

Configure le fichier de configuration udev et les règles udev. Lu par systemd-udev-load-credentials.service, qui invoque udevadm control --load-credentials. Ces identifiants se traduisent directement par un fichier udev.conf(5) ou udev(7) correspondant. Exemple : le contenu d'un identifiant udev.conf.50-foobar sera copié dans un fichier /run/udev/udev.conf.d/50-foobar.conf, et udev.rules.50-foobar sera copié dans un fichier /run/udev/rules.d/50-foobar.rules. Voir udev(7), udev.conf(5), et udevadm(8) pour plus de détails.

Ajouté en version 256.

import.pull

Spécifie les images disque (archives tar et DDI) à télécharger et installer automatiquement au démarrage. Pour plus de détails, voir systemd-import-generator(8).

Ajouté en version 257.

userdb.user.*, userdb.group.*, userdb.transient.user.*, userdb.transient.group.*

Configure les enregistrements d'utilisateurs et de groupes JSON. Lu par systemd-userdb-load-credentials.service, qui invoque userdbctl load-credentials. Ces identifiants se traduisent directement par des enregistrements JSON User[2] et JSON Group[3] correspondants. Exemple : le contenu d'un identifiant userdb.user.foobar sera copié dans un fichier /etc/userdb/foobar.user, et userdb.group.foobar sera copié dans un fichier /etc/userdb/foobar.group. Des liens symboliques pour uid/gid seront également créés dans /etc/userdb/, ainsi que les fichiers correspondants de membres. Voir systemd-userdbd.service(7), nss-systemd(8), et userdbctl(1) pour plus de détails.

Tous les enregistrements d'utilisateurs fournis doivent contenir les champs uid et gid. Tous les enregistrements de groupe fournis doivent contenir un champ gid. Pour les enregistrements d'utilisateurs et de groupes, le suffixe de l'identifiant (pour "userdb.user.foobar", le suffixe est "foobar") doit correspondre au nom d'utilisateur ou de groupe du champ nom d'utilisateur ou de groupe de l'enregistrement utilisateur ou groupe.

fsck.*

Lu par systemd-fsck@.service, systemd-fsck-root.service, et systemd-fsck-usr.service. Voir systemd-fsck@.service(8) pour plus de détails.

Ajouté en version 258.

quotacheck.*

Lu par systemd-quotacheck@.service et systemd-quotacheck-root.service. Voir systemd-quotacheck(8) pour plus de détails.

Ajouté en version 258.
