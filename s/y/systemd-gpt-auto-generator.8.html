SYSTEMD-GPT-AUTO-GENERATOR(8) systemd-gpt-auto-generator SYSTEMD-GPT-AUTO-GENERATOR(8)

NOM

systemd-gpt-auto-generator - Générateur pour la découverte et le montage automatiques des partitions root, /home/, /srv/, /var/ et /var/tmp/, ainsi que la découverte et l'activation des partitions swap, basé sur les GUID de type de partition GPT

SYNOPSIS

/usr/lib/systemd/system-generators/systemd-gpt-auto-generator

DESCRIPTION

systemd-gpt-auto-generator est un générateur d'unités qui découvre automatiquement la partition racine, les partitions /home/, /srv/, /var/, /var/tmp/, la partition système EFI (ESP) et la partition de démarrage étendue (XBOOTLDR), ainsi que les partitions swap, et crée des unités de montage et de swap pour celles-ci, en se basant sur les GUID de type de partition des tables de partitions GPT. Voir la Spécification UEFI[1], chapitre 5 pour plus de détails. Il implémente la Spécification des Partitions Découvrables[2].

Notez que ce générateur n'a aucun effet sur les systèmes non-GPT. Il ne créera pas non plus de configuration de point de montage pour les répertoires qui contiennent déjà des fichiers ou si le point de montage est explicitement configuré dans fstab(5). De plus, aucune unité ne sera créée pour l'ESP ou la partition XBOOTLDR si des entrées de montage sont trouvées dans les hiérarchies /boot/ ou /efi/ dans fstab(5).

Si les unités que ce générateur crée sont remplacées, par exemple par des unités dans des répertoires ayant une priorité plus élevée, les fichiers drop-in et les dépendances supplémentaires créés par ce générateur pourront toujours être utilisés.

Lorsqu'il est exécuté dans le disque RAM initial (initrd), ce générateur peut rechercher automatiquement le système de fichiers racine. Spécifiquement :

•Il recherchera la partition racine sur le même disque physique où se trouve la partition système EFI (ESP). Notez que le support du chargeur de démarrage est requis pour que cela fonctionne : la variable EFI LoaderDevicePartUUID de l'UUID de fournisseur 4a67b082-0a4c-41cf-b6c7-440b29bb8c4f est utilisée pour déterminer à partir de quelle partition (et donc quel disque) le système a démarré. Si le chargeur de démarrage ne définit pas cette variable, ce générateur ne pourra pas détecter la partition racine. Voir l'Interface du chargeur de démarrage[3] pour les détails.

•Alternativement, il recherchera le système de fichiers racine sur un périphérique bloc en boucle dont le champ ".lo_name" est défini sur l'une des chaînes littérales "rootdisk" ou "rootdisk.raw". Ce champ peut être défini via la chaîne --loop-ref= de losetup. Pour les images téléchargées via systemd-import-generator(8), assurez-vous de définir l'option "blockdev" et de définir la chaîne de nom local sur "rootdisk" pour obtenir cet effet. Notez que la découverte du système de fichiers racine sur les périphériques blocs en boucle comme celui-ci n'est effectuée que si "root=gpt-auto" ou "root=dissect" est explicitement spécifié sur la ligne de commande du noyau, contrairement à la découverte basée sur l'ESP rapportée par le chargeur de démarrage qui est également activée si aucun paramètre "root=" n'est spécifié du tout. (Ce dernier repose sur la génération du lien symbolique de bloc /dev/gpt-auto-root par systemd-udevd.service).

Lorsqu'il est exécuté sur le système hôte (c'est-à-dire après être sorti avec succès de l'initrd vers le système de fichiers racine), ce générateur recherchera toutes les autres partitions sur le même disque physique que la partition racine. Pour cette découverte, le support du chargeur de démarrage n'est pas requis. De plus, il n'est pas nécessaire que la partition racine ait été découverte automatiquement par l'initrd (comme décrit ci-dessus) pour que la découverte des partitions de fichiers non-racine ait lieu. Autrement dit : la découverte automatique du système de fichiers racine et des systèmes de fichiers non-racine sont des opérations indépendantes, qui ne dépendent pas l'une de l'autre, et sont effectuées pendant deux phases distinctes du processus de démarrage (une dans l'initrd, l'autre après). Ces partitions ne seront pas recherchées sur les systèmes où le système de fichiers racine est distribué sur plusieurs disques, par exemple via un RAID btrfs.

La partition racine peut être configurée explicitement en créant un lien symbolique /run/systemd/volatile-root vers /dev/block/$major:$minor. Ceci est particulièrement utile si le montage racine a été remplacé par une forme de système de fichiers volatile (overlayfs).

systemd-gpt-auto-generator est utile pour centraliser la configuration du système de fichiers dans la table de partitions et rendre inutile la configuration dans /etc/fstab ou sur la ligne de commande du noyau.

Les partitions
/home/, /srv/, /var/, /var/tmp/ et swap peuvent être chiffrées au format LUKS. Dans ce cas, un périphérique de mappage de périphérique est configuré sous les noms /dev/mapper/home, /dev/mapper/srv, /dev/mapper/var, /dev/mapper/tmp ou /dev/mapper/swap. Notez que cela peut créer des conflits si la même partition est listée dans /etc/crypttab avec un nom de périphérique de mappage de périphérique différent.

Lorsque systemd s'exécute dans l'initrd, la partition / peut également être chiffrée avec LUKS. Dans ce cas, un périphérique de mappage de périphérique est configuré sous le nom /dev/mapper/root, et un sysroot.mount est configuré qui monte le périphérique sous /sysroot. Pour plus d'informations, voir bootup(7).

Les unités de montage et d'automontage pour la partition système EFI (ESP) et la partition de chargeur de démarrage étendue (XBOOTLDR) sont générées sur les systèmes EFI. Si le disque contient une partition XBOOTLDR, telle que définie dans la Spécification du chargeur de démarrage[4], elle est mise à disposition sur /boot/. Ce générateur crée une unité d'automontage ; le montage ne sera activé à la demande que lorsqu'il sera accédé. Le point de montage sera créé si nécessaire.

L'ESP est montée sur /boot/ si ce répertoire existe et n'est pas utilisé pour XBOOTLDR, et sinon sur /efi/. Comme pour /boot/, une unité d'automontage est utilisée. Le point de montage sera créé si nécessaire.

Aucune configuration n'est créée pour les points de montage qui sont configurés dans fstab(5) ou lorsque le répertoire cible contient des fichiers.

Lors de l'utilisation de ce générateur conjointement avec des systèmes de fichiers btrfs, assurez-vous de définir les sous-volumes par défaut corrects sur ceux-ci, en utilisant btrfs subvolume set-default.

Si le système a démarré via systemd-stub(7) et que le stub a indiqué à l'espace utilisateur que l'image du noyau a été mesurée dans un TPM2 PCR, alors tous les identifiants de volume racine et /var/ découverts (et la clé de chiffrement de volume si elle est chiffrée) seront automatiquement mesurés dans le PCR 15 à l'activation, via systemd-pcrfs@.service(8).

Les métadonnées de contrainte de montage contenues dans les systèmes de fichiers sont validées en tirant systemd-validatefs@.service(8) pour les montages générés.

systemd-gpt-auto-generator implémente systemd.generator(7).

LIGNE DE COMMANDE DU NOYAU

systemd-gpt-auto-generator comprend les paramètres de ligne de commande du noyau suivants :

systemd.gpt_auto, rd.systemd.gpt_auto

Ces options prennent un argument booléen optionnel et par défaut à oui. Le générateur est activé par défaut, et une valeur fausse peut être utilisée pour le désactiver (par exemple, "systemd.gpt_auto=0").

Ajouté dans la version 242.

systemd.image_policy=

Prend une chaîne de politique de dissection d'image comme argument (conformément à systemd.image-policy(7)), et permet d'appliquer une politique sur la dissection et l'utilisation des entrées de table de partition GPT découvertes automatiquement.

Notez que la politique d'image spécifiée n'est pas prise en compte pour la découverte automatique des systèmes de fichiers racine ou /usr/ à moins que root=dissect/mount.usr=dissect (ou root=dissect-force) ne soient spécifiés. (La politique sera toujours appliquée aux autres types de partitions auto-découvrables.)

Ajouté dans la version 254.

systemd.image_filter=

Prend une chaîne de filtre de dissection d'image comme argument (conformément à systemd.image-filter(7)), et permet d'appliquer un ensemble de motifs globaux sur la correspondance des partitions des entrées de table de partition GPT découvertes automatiquement.

Notez que le filtre d'image spécifié n'est pas pris en compte pour la découverte automatique des systèmes de fichiers racine ou /usr/ à moins que root=dissect/mount.usr=dissect (ou root=dissect-force) ne soient spécifiés. (Le filtre sera toujours appliqué aux autres types de partitions auto-découvrables.)

Ajouté dans la version 258.

root=, rootfstype=, rootflags=

Lorsque root= est utilisé avec la valeur spéciale "gpt-auto", la découverte automatique de base de la partition racine basée sur le type de partition GPT est activée. L'utilisation de la partition racine est retardée jusqu'à ce que le mode de réinitialisation d'usine soit quitté, au cas où elle serait activée lors du démarrage actuel. Voir Réinitialisation d'usine[5] pour plus d'informations à ce sujet. Si "gpt-auto-force" est spécifié, la découverte automatique de la partition racine est activée, ignorant tout mode de réinitialisation d'usine.

Si root= est défini sur la valeur spéciale "dissect", la découverte automatique complète de la partition racine basée sur les informations de partition GPT est activée. Ceci est un sur-ensemble de root=gpt-auto, car il configure automatiquement les partitions Verity (y compris la configuration basée sur la signature) en suivant la logique définie pour cela dans la Spécification des partitions découvrables[6]. De plus, il prend en compte la politique d'image et le filtre d'image configurés pour tous les types de partitions, y compris le système de fichiers racine. "root=dissect" attendra que la phase de réinitialisation d'usine soit terminée si elle est en vigueur avant d'activer le système de fichiers racine. Utilisez "root=dissect-force" pour ignorer la phase de réinitialisation d'usine et activer le système de fichiers racine immédiatement.

Toute autre valeur (c'est-à-dire autre que "gpt-auto", "gpt-auto-force", "dissect", "dissect-force") désactive la découverte automatique du système de fichiers racine.

Si root= n'est pas spécifié du tout sur la ligne de commande du noyau, la découverte automatique de la partition racine via l'ESP rapportée par le chargeur de démarrage est également activée (en tenant compte de l'état de réinitialisation d'usine, c'est-à-dire équivalent à "root=gpt-auto"), cependant dans ce cas la découverte basée sur le champ ".lo_name" du périphérique bloc de boucle n'est pas activée.

Les options rootfstype= et rootflags= sont utilisées pour sélectionner le type de système de fichiers et les options lors de la découverte automatique du système de fichiers racine.

Ajouté dans la version 242.

mount.usr=, mount.usrfstype=, mount.usrflags=

Similaire à root=, rootfstype=, rootflags= (voir ci-dessus), mais s'applique à la partition /usr/ à la place. Notez que les paramètres "gpt-auto", "gpt-auto-force", "dissect-force" que root= comprend ne sont pas pris en charge par mount.usr= (cependant "dissect" l'est).

Notez également que la découverte automatique de partitions pour /usr/ doit être activée explicitement, contrairement à la découverte pour le système de fichiers racine, qui est activée si aucun paramètre root= n'est passé du tout.

Ajouté dans la version 258.

rw, ro

Monte la partition racine en lecture-écriture ou en lecture seule initialement.

Notez que contrairement à la plupart des options de ligne de commande du noyau, ces paramètres ne remplacent pas la configuration dans le système de fichiers, et le système de fichiers peut être remonté ultérieurement. Voir systemd-remount-fs.service(8).

Ajouté dans la version 242.

systemd.swap=

Prend un argument booléen ou active l'option si elle est spécifiée sans argument. Si elle est désactivée, la découverte automatique des partitions swap basée sur le type de partition GPT est désactivée. Par défaut, elle est activée.

Ajouté dans la version 254.

NOM

systemd-gpt-auto-generator - Générateur automatique de partitions GPT

SYNOPIS

systemd-gpt-auto-generator

DESCRIPTION

systemd-gpt-auto-generator est un générateur automatique qui analyse la table de partitions GUID (GPT) du disque d'amorçage du système et crée des unités de montage dynamiques correspondantes pour les partitions qui ont un type de partition de Linux filesystem ({72576157-3234-47f4-8369-289578222934}) et qui ne sont pas déjà reconnues par d'autres générateurs automatiques de systemd.

Ce générateur automatique est particulièrement utile pour automatiser le montage de partitions de données, de partitions de swap ou d'autres partitions de système de fichiers dont le type est inconnu du système ou qui n'ont pas été explicitement configurées dans /etc/fstab. Il permet une découverte et un montage automatiques des partitions basés sur leur type GPT et le système de fichiers qu'elles contiennent.

LIGNE DE COMMANDE DU NOYAU

Ce programme n'interprète pas directement les paramètres de la ligne de commande du noyau. Son comportement est déterminé par la configuration du système et la table de partitions GPT.

VOIR AUSSI

systemd(1), systemd.mount(5), fstab(5)

NOTES

Le générateur systemd-gpt-auto-generator est activé par défaut. Pour le désactiver, il suffit de supprimer le fichier /usr/lib/systemd/system-generators/systemd-gpt-auto-generator ou de le rendre non exécutable.

Ce générateur automatique fonctionne en tandem avec d'autres générateurs automatiques, tels que systemd-fstab-generator. Il n'interférera pas avec les montages définis dans /etc/fstab ou gérés par d'autres mécanismes.
