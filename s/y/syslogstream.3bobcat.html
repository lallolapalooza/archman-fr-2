FBB::SyslogStream(3bobcat) Flux de sortie pour Syslog FBB::SyslogStream(3bobcat)

NOM

FBB::SyslogStream - Un flux de sortie insérant des messages syslog

SYNTAXE

#include <bobcat/syslogstream>
Option de liaison : -lbobcat

DESCRIPTION

Les objets FBB::SyslogStream peuvent être utilisés comme un std::ostream pour écrire des messages syslog en utilisant les facilités de flux.

Des insertions multiples et distinctes peuvent être utilisées pour créer un seul message syslog : le message n'est envoyé au démon syslog qu'après avoir reçu une commande de flush (par exemple, après avoir inséré std::flush ou std::endl). Les caractères non imprimables (comme ’\n’) apparaissent dans le message syslog sous forme de valeurs octales, précédées de # (par exemple, #012 pour ’\n’). Le saut de ligne normalement inséré par std::endl est ignoré : les objets SyslogStream interprètent std::endl comme std::flush.

Une série d'insertions peut contenir plusieurs manipulateurs std::endl ou std::flush. À chacun de ces manipulateurs, un nouveau message est envoyé au démon syslog, contenant toutes les informations qui ont été mises en tampon jusqu'à présent. Après l'envoi d'un message au démon syslog, le tampon interne du SyslogStream est effacé.

ESPACE DE NOMMAGE

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de nommage FBB.

HERITE DE

std::ostream

ENUMERATIONS

Les énumérations suivantes sont définies dans l'espace de nommage FBB:

Priority:

Les valeurs de cette énumération correspondent aux valeurs de priorité LOG_xxx correspondantes utilisées avec syslog(3):

o
EMERG:
le système est inutilisable;
o
ALERT:
une action doit être entreprise immédiatement;
o
CRIT:
conditions critiques;
o
ERR:
conditions d'erreur;
o
WARNING:
conditions d'avertissement;
o
NOTICE:
condition normale, mais significative;
o
INFO:
message d'information;
o
DEBUG:
message de niveau débogage ; Le membre setMask (voir ci-dessous) peut être utilisé pour sélectionner quels types de messages seront effectivement traités par le démon syslog.

PriorityType:

Cette énumération a deux valeurs qui affinent le type de messages effectivement traités par le démon syslog:

o
SINGLE:
Seuls les messages de la priorité spécifiée lors de l'appel à setMask sont traités par le démon syslog ;
o
UPTO:
Les messages de priorité EMERG jusqu'à la priorité spécifiée lors de l'appel à setMask sont traités par le démon syslog ; Par défaut, le démon syslog traite tous les messages qu'il reçoit.

Facility:

Les valeurs de cette énumération correspondent aux valeurs de facility LOG_xxx correspondantes utilisées avec syslog(3):

o
AUTHPRIV:
messages de sécurité/autorisation (privés)
o
CRON:
démon d'horloge (cron et at)
o
DAEMON:
autres démons système
o
KERN:
messages du noyau
o
LOCAL0:
réservé à un usage local. LOCAL1 à LOCAL7 sont également disponibles.
o
LPR:
sous-système d'imprimante ligne
o
MAIL:
sous-système de messagerie
o
NEWS:
sous-système de news USENET
o
SYSLOGBUF:
messages générés en interne par syslogbufd
o
USER:
messages génériques au niveau utilisateur
o
UUCP:
sous-système UUCP

CONSTRUCTEURS

o
SyslogStream(string const &ident = "", FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
Ce constructeur initialise un objet SyslogStream. Le paramètre ident est généralement le nom du programme. Son contenu est ajouté en préfixe aux messages syslog.
Le paramètre priority détermine l'importance par défaut du message envoyé au démon syslog. Par défaut, les messages sont envoyés au démon syslog avec la priorité FBB::NOTICE. Les messages syslog peuvent recevoir une priorité différente en insérant un manipulateur SyslogStream (voir ci-dessous). La priorité définie lors de la construction peut également être modifiée à l'aide des membres setPriority et setDefaultPriority.
Les messages qui apparaissent réellement dans les facilities de journalisation ne sont pas déterminés par les priorités des messages, mais par le masque de journalisation de syslog. Le masque de journalisation peut être défini par le membre statique setMask (voir ci-dessous).
Le paramètre facility détermine le type de programme effectuant la journalisation. Par défaut, FBB::USER est utilisé.
Le paramètre option peut être utilisé pour spécifier diverses options (utilisez l'opérateur binaire `bitor` (`|`) pour combiner les options) :
LOG_CONS: écrire directement sur la console système en cas d'erreur lors de l'envoi au journaliste système
LOG_NDELAY: ouvrir la connexion immédiatement (normalement, la connexion est ouverte lorsque le premier message est journalisé)
LOG_PERROR: imprimer également sur stderr
LOG__PID: inclure le PID avec chaque message
Par défaut, aucune option n'est utilisée.

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) ne sont pas disponibles.

FONCTIONS MEMBRES

Tous les membres de std::ostream sont disponibles, car FBB::SyslogStream en hérite.

o
void close():
Si le tampon interne du SyslogStream n'est pas vide, il est vidé vers le démon syslog. Ensuite, closelog(3) est appelé.
o
Priority defaultPriority() const:
Retourne la priorité par défaut actuelle. C'est-à-dire la priorité qui sera utilisée pour les messages après l'insertion de endl ou flush.
o
void open(string const &ident, FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
Redéfinit l'identifiant, la priorité, la facility et les options actuels utilisés lors de l'envoi de messages au démon syslog. Si le tampon interne du SyslogStream n'est pas vide, il est d'abord vidé vers le démon syslog en utilisant l'identifiant, la priorité et les options qui étaient actifs juste avant l'appel à open.
o
Priority priority() co

MEMBER FUNCTIONS

o
Priority defaultPriority():
Returns the default priority.
o
Priority nextnst():
Retourne la priorité suivante. C'est-à-dire la priorité qui sera utilisée pour le prochain message envoyé au démon syslog.
o
Priority priority():
Retourne la priorité courante.
o
Priority setDefaultPriority(Priority priority):
Change la priorité par défaut du prochain message envoyé au démon syslog après l'insertion de std::eoln ou std::flush. La priorité par défaut précédemment active est retournée.
o
Priority setPriority(Priority priority):
Change la priorité pour le prochain message envoyé au démon syslog après l'insertion de std::eoln ou std::flush. Les messages subséquents utiliseront à nouveau la priorité par défaut. La priorité précédemment active est retournée.

FONCTIONS MEMBRES STATIQUES

o
Priority setMask(Priority priority, PriorityMask upTo):
Les messages syslog de (si upTo est égal à SINGLE) ou jusqu'à (si upTo est égal à UPTO) la priorité indiquée sont traités par le démon syslog.
o
Priority setMask(Priority priority, Priority ...priorities):
Les messages syslog des priorités passées à setMask sont traités par le démon syslog. Au moins une priorité doit être spécifiée.
o
Facility stoF(std::string const &name, Facility facility = USER):
Retourne la facilité correspondant au nom de la facilité fourni par name. La correspondance des facilités est effectuée sans tenir compte de la casse. Par exemple, si name contient daemon, la facilité FBB::DAEMON est retournée. Si name ne correspond à aucun nom de facilité, la valeur du second argument de cette fonction est retournée. Le nom de la fonction (stoF) a été utilisé par analogie avec les diverses fonctions de conversion sto... qui ont été rendues disponibles par la norme C++11.
o
Priority stoP(std::string const &name, Priority priority = NOTICE):
Retourne la priorité correspondant au nom de la priorité fourni par name. La correspondance des priorités est effectuée sans tenir compte de la casse. Par exemple, si name contient emerg, la priorité FBB::EMERG est retournée. Si name ne correspond à aucun nom de priorité, la valeur du second argument de cette fonction est retournée. Le nom de la fonction (stoP) a été utilisé par analogie avec les diverses fonctions de conversion sto... qui ont été rendues disponibles par la norme C++11.

MANIPULATEURS

L'ensemble suivant de manipulateurs sont tous définis comme membres (statiques). Ils peuvent être insérés dans un objet FBB::SyslogStream. Sauf pour le dernier manipulateur (strerrno), ils ont les caractéristiques suivantes en commun :

o
Ils changent la priorité des messages qui sont ensuite insérés par l'objet FBB::SyslogStream, agissant ainsi comme un appel setPriority distinct.
o
Lors de l'insertion de plusieurs manipulateurs avant que le message inséré ne soit vidé (par exemple, en utilisant les manipulateurs std::flush ou std::endl), le dernier manipulateur FBB::SyslogStream inséré sera utilisé.
o
Si les manipulateurs ne sont pas insérés dans un objet FBB::SyslogStream (mais dans un autre objet de type std::ostream), alors ils n'effectuent aucune action.

Voici les manipulateurs disponibles :

o
SyslogStream::alert:
Les messages sont insérés avec la priorité FBB::ALERT.
o
SyslogStream::crit:
Les messages sont insérés avec la priorité FBB::CRIT.
o
SyslogStream::debug:
Les messages sont insérés avec la priorité FBB::DEBUG.
o
SyslogStream::emerg:
Les messages sont insérés avec la priorité FBB::EMERG.
o
SyslogStream::err:
Les messages sont insérés avec la priorité FBB::ERR.
o
SyslogStream::info:
Les messages sont insérés avec la priorité FBB::INFO.
o
SyslogStream::notice:
Les messages sont insérés avec la priorité FBB::NOTICE.
o
SyslogStream::strerrno:
Ce manipulateur insère l'interprétation textuelle de la valeur actuelle de std::errno dans un std::ostream. Notez que, contrairement aux autres manipulateurs, l'objet dans lequel ce manipulateur est inséré ne doit pas nécessairement être un objet FBB::SyslogStream.
o
SyslogStream::warning:
Les messages sont insérés avec la priorité FBB::WARNING.

EXEMPLE

#include <bobcat/syslogstream>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    SyslogStream sls(argv[0]);
    sls << SyslogStream::debug << "Hello world" << flush <<
           SyslogStream::strerrno << endl;
}
