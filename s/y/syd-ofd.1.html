SYD-OFD(1) Manuel des commandes générales SYD-OFD(1)

NOM

syd-ofd - Verrouille un fichier, puis exécute un autre programme

SYNOPSIS

syd-ofd [-n | -N] [-t timeout] [-d fd] [-s=-r | -x=-w] fichier {commande [arg...]}

DESCRIPTION

syd-ofd verrouille un fichier, puis exécute un autre programme. Il est fonctionnellement identique à l'utilitaire s6-setlock(1), sauf qu'il utilise des verrous OFD qui sont nouveaux dans POSIX 2024. Ce type de verrou est également connu sous le nom de "verrous privés au fichier" et est basé sur la description de fichier ouverte, plutôt que sur le processus comme les anciens verrous POSIX que s6-setlock(1) utilise. Cela permet à syd(1) de passer le descripteur de fichier au processus sandbox et de fermer sa propre copie tout en maintenant le verrou, ce qui n'est pas possible avec les anciens verrous et s6-setlock(1).

OPTIONS

-h Affiche l'aide.
-n Verrou non bloquant. Si syd-ofd ne parvient pas à acquérir le verrou, il se terminera avec le code 11 ("EAGAIN": Réessayer) immédiatement.
-N Verrou bloquant. syd-ofd attendra jusqu'à ce qu'il puisse acquérir le verrou. C'est le comportement par défaut.
-t timeout Verrou temporisé. Si syd-ofd ne parvient pas à acquérir le verrou après un délai de timeout millisecondes, il se terminera avec le code 4 ("EINTR": Appel système interrompu).
-s=-r Verrou partagé. D'autres verrous partagés sur le même fichier n'empêcheront pas l'acquisition du verrou (mais un verrou exclusif le fera).
L'option -r est conservée pour la compatibilité avec l'utilitaire s6-setlock(1).
-x=-w Verrou exclusif. C'est le comportement par défaut.
L'option -w est conservée pour la compatibilité avec l'utilitaire s6-setlock(1).
-d fd Rend le verrou visible dans programme sur le descripteur de fichier fd.

STATUT DE SORTIE

En cas de sortie propre, syd-ofd se termine avec le même code que le processus enfant. En cas de terminaison anormale, le code de sortie est défini à 128 plus le numéro du signal. Si l'exécution du processus enfant échoue, syd-ofd se termine avec le numéro d'errno(3).

SÉCURITÉ

syd-ofd utilise openat(2) avec les drapeaux de résolution RESOLVE_NO_MAGICLINKS et RESOLVE_NO_SYMLINKS lors de l'ouverture ou de la création du fichier de verrou. Par conséquent, si un composant du chemin spécifié est un lien symbolique, l'appel échoue et renvoie le code d'erreur 40 (ELOOP : "Trop de liens symboliques rencontrés"). De même, la présence de tout composant .. (point-point) dans le chemin du fichier de verrou entraîne l'échec de l'appel et le renvoi du code d'erreur 13 (EACCES : "Permission refusée"). Cette restriction est destinée à atténuer les vulnérabilités de type "confused deputy" lors de la création du fichier de verrou et des opérations de fichier associées, en empêchant un acteur intermédiaire ou moins privilégié de rediriger l'opération via des liens symboliques ou des composants de répertoire parent (..) vers un emplacement inattendu du système de fichiers.
