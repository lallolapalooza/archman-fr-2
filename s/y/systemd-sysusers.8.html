NAME

systemd-sysusers, systemd-sysusers.service - Allouer des utilisateurs et des groupes système

SYNOPSIS

systemd-sysusers [OPTIONS...] [FICHIER_CONFIG...]

systemd-sysusers.service

DESCRIPTION

systemd-sysusers crée des utilisateurs et des groupes système, en se basant sur des fichiers au format décrit dans sysusers.d(5).

S'il est appelé sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par sysusers.d(5) sont exécutées. S'il est appelé avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments donnés en ligne de commande sont utilisés à la place du fichier de configuration CHEMIN. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée au lieu d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans slash), tous les répertoires de configuration sont parcourus pour trouver un fichier correspondant et le fichier trouvé ayant la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans parcourir les répertoires de configuration pour tout autre fichier correspondant.

OPTIONS

Les options suivantes sont comprises :

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés par le chemin racine alternatif donné, y compris les chemins de recherche de configuration.

Ajouté en version 215.

--image=image

Prend un chemin vers un fichier d'image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur des systèmes de fichiers stockés dans des images disque ou des périphériques bloc. L'image disque doit contenir soit un système de fichiers, soit un ensemble de systèmes de fichiers dans une table de partitions GPT, suivant la Spécification des partitions détectables[1]. Pour plus d'informations sur les images disque prises en charge, voir le commuteur du même nom dans systemd-nspawn(1).

Ajouté en version 247.

--image-policy=politique

Prend une chaîne de politique d'image comme argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si elle n'est pas spécifiée, la politique par défaut est "*", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=CHEMIN

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans sysusers.d(5) seront lus, et la configuration donnée en ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration CHEMIN.

Cette option est destinée à être utilisée lorsque les scripts d'installation de paquets s'exécutent et que les fichiers appartenant à ce paquet ne sont pas encore disponibles sur le disque, de sorte que leur contenu doit être donné en ligne de commande, mais que la configuration administrative peut déjà exister et devrait avoir une priorité plus élevée.

Exemple 1. Script d'installation RPM pour radvd

echo 'u radvd - "radvd daemon"' | \
          systemd-sysusers --replace=/usr/lib/sysusers.d/radvd.conf -

Ceci créera l'utilisateur radvd comme si /usr/lib/sysusers.d/radvd.conf était déjà sur le disque. Un administrateur pourrait remplacer la configuration spécifiée en ligne de commande en plaçant /etc/sysusers.d/radvd.conf ou même /etc/sysusers.d/00-overrides.conf.

Notez qu'il s'agit de la forme étendue, et lorsqu'elle est utilisée dans un paquet, cela serait écrit en utilisant une macro avec "radvd" et un fichier contenant la ligne de configuration comme arguments.

Ajouté en version 238.

--dry-run

Traite la configuration et détermine quelles entrées seraient créées, mais n'écrit rien en réalité.

Ajouté en version 250.

--inline

Traite chaque argument positionnel comme une ligne de configuration distincte au lieu d'un nom de fichier.

Ajouté en version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties "intéressantes" des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne redirige pas la sortie vers un pager.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

IDENTIFIANTS

systemd-sysusers supporte la logique des identifiants du service implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont transmis :

passwd.hashed-password.utilisateur

Une chaîne de mot de passe UNIX haché à utiliser pour l'utilisateur spécifié, lors de la création d'une entrée pour celui-ci. Ceci est particulièrement utile pour l'utilisateur "root" car il permet de provisionner le mot de passe root par défaut à utiliser via un drop-in de fichier d'unité ou à partir d'un gestionnaire de conteneur transmettant cet identifiant. Notez que la définition de cet identifiant n'a aucun effet si le compte utilisateur spécifié existe déjà. Cet identifiant est donc principalement utile dans les scénarios de premier démarrage ou les systèmes complètement sans état qui démarrent avec un /etc/ vide à chaque démarrage.

Ajouté en version 249.

passwd.plaintext-password.utilisateur

Similaire à "passwd.hashed-password.utilisateur" mais attend un mot de passe littéral en clair, qui est ensuite automatiquement haché avant d'être utilisé pour le compte utilisateur. Si l'identifiant haché et l'identifiant en clair sont spécifiés pour le même utilisateur, le premier a la priorité. Il est généralement recommandé de spécifier la version hachée ; cependant, dans les environnements de test avec des exigences de sécurité moindres, il peut être plus facile de transmettre les mots de passe en clair.

Ajouté en version 249.

passwd.shell.utilisateur

Spécifie le binaire du shell à utiliser pour le compte spécifié lors de sa création.

Ajouté en version 249.

sysusers.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier drop-in sysusers.d/. Si cet identifiant est transmis, il est traité après tous les fichiers drop-in lus depuis le système de fichiers.

Ajouté en version 252.

Notez que par défaut, le fichier d'unité systemd-sysusers.service est configuré pour hériter des identifiants "passwd.hashed-password.root", "passwd.plaintext-password.root", "passwd.shell.root" et "sysusers.extra" du gestionnaire de service. Ainsi, lors de l'invocation d'un conteneur avec un /etc/ non peuplé pour la première fois, il est possible de configurer le mot de passe de l'utilisateur root à "systemd" comme ceci :

# systemd-nspawn --image=... --set-credential=passwd.hashed-password.root:'$y$j9T$yAuRJu1o5HioZAGDYPU5d.$F64ni6J2y2nNQve90M/p0ZP0ECP/qqzipNyaY9fjGpC' ...

Notez encore que les données spécifiées dans cet identifiant ne sont consultées que lors de la création d'un compte pour la première fois, elles ne peuvent pas être utilisées pour changer le mot de passe ou le shell d'un compte qui existe déjà.

Utilisez mkpasswd(1) pour générer des hachages de mot de passe UNIX depuis la ligne de commande.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
