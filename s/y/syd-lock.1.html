SYD-LOCK(1) Manuel des commandes générales SYD-LOCK(1)

NOM

syd-lock - Exécuter un programme sous landlock(7)

SYNTAXE

syd-lock [-bchrvwASUV] [-C niveau] [-E errata] [-F drapeau]... [-l catégorie[,catégorie...]{+|-}chemin|port[-port]]... {commande [arguments...]}

DESCRIPTION

L'utilitaire syd-lock exécute un programme sous landlock(7). Le programme est confiné par les catégories landlock(7) données. Les catégories prises en charge sont read, write, exec, ioctl, create, delete, rename, symlink, truncate, readdir, mkdir, rmdir, mkbdev, mkcdev, mkfifo, bind et connect. Les catégories autres que bind et connect doivent spécifier des chemins à confiner. Les chemins absolus et relatifs sont autorisés. Les catégories bind et connect doivent spécifier un port réseau ou une plage de ports fermés séparés par un trait d'union. Zéro est un numéro de port valide pour confiner les liaisons et les connexions aux ports éphémères. La catégorie bind prend également en charge les chemins absolus de sockets UNIX pour confiner leur création via mknod(2). Pour plus de détails et le comportement spécifique de chaque catégorie landlock(7), consultez les sections Sandboxing et Verrouillage Sandboxing de la page de manuel syd(7).

OPTIONS

-h Afficher l'aide.
-v Être verbeux. Afficher l'état de landlock(7) sur stderr(3) avant d'exécuter le programme.
-V Afficher la version de l'ABI de landlock(7) sur stdout(3).
-A Afficher la version de l'ABI de landlock(7) sur stdout(3) et quitter avec celle-ci comme code de sortie. Utiliser pour le scripting.
-l cat[,cat...]{+|-}chemin|port[-port] Ajouter ou supprimer une règle de landlock(7) avec des catégories et une ressource associée (chemin ou port), peut être répété.
Joindre les catégories et la ressource par un "+" (plus) pour ajouter ou un "-" (moins) pour supprimer.
La ressource doit être un chemin pour toutes les catégories sauf bind et connect.
La ressource doit être un port ou une plage de ports fermés délimitée par des traits d'union pour bind et connect.
La ressource peut également être un chemin de socket UNIX pour bind afin de confiner mknod(2) avec S_IFSOCK.
Les chemins absolus et relatifs sont autorisés pour toutes les catégories sauf bind qui nécessite un chemin absolu.
Les chemins sont stockés sous forme d'ensembles de hachage et les ports sous forme d'ensembles de bits fixes pour permettre un empilement simple et prévisible des options.
-C niveau Définir le niveau de compatibilité de landlock(7). Doit être l'un de hard-requirement, soft-requirement et best-effort.
La valeur par défaut est hard-requirement pour adhérer au principe des valeurs par défaut sécurisées.
Le niveau peut être donné brièvement comme hard (ou h), soft (ou s) et best (ou b).
-E errata Interroger les corrections d'errata landlock(7) prises en charge. Utiliser -E list pour afficher la liste des erratas connues.
L'argument peut être un nom ou un numéro. Utiliser un numéro pour interroger les erratas indéfinis.
Plusieurs erratas peuvent être spécifiés, séparés par des virgules.
-F drapeaux Définir les drapeaux de landlock_restrict_self(2). Utiliser -F list pour afficher une liste de drapeaux.
Voir la section FLAGS pour des informations sur les drapeaux et leur fonctionnalité.
-S Activer les signaux groupés introduits avec l'ABI 6 de landlock(7).
-U Activer les sockets abstraits UNIX groupés introduits avec l'ABI 6 de landlock(7).
-r chemin Spécifier un chemin en lecture seule, peut être répété. Équivalent à -l read,readdir,exec,ioctl+chemin.
-w chemin Spécifier un chemin en lecture-écriture, peut être répété. Équivalent à -l all+chemin.
-b port[-port] Spécifier un port pour bind(2), peut être répété. Équivalent à -l bind+port.
-c port[-port] Spécifier un port pour connect(2), peut être répété. Équivalent à -l connect+port.

CONFIGURATION

Les catégories landlock(7) et leurs ressources associées (chemins ou ports) sont spécifiées avec l'option -l. Cette option accepte une liste de catégories séparées par des virgules, suivie d'un symbole "+" (plus) ou "-" (moins) indiquant d'ajouter ou de supprimer la règle donnée. Les ensembles de règles stockent les chemins sous forme d'ensembles de hachage et les ports sous forme d'ensembles de bits fixes pour permettre un empilement simple et prévisible de plusieurs options -l. Utilisez l'option -V pour vérifier la prise en charge de landlock(7) dans le noyau Linux. Le niveau de prise en charge spécifique peut être déterminé par le code de sortie. Utilisez l'option -A pour vérifier la version de l'ABI de landlock(7).

ABI

La gestion des versions de l'ABI de landlock(7) permet d'ajuster la politique de sécurité en fonction des capacités du noyau. syd-lock prend en charge l'ABI 7 de landlock(7), nouveau dans Linux-6.15. Consultez la section HISTORIQUE pour savoir quand chaque ABI de landlock(7) a été introduit dans le noyau Linux.

ENSEMBLES

Depuis la version 3.38.0, plusieurs catégories peuvent être spécifiées, séparées par des virgules, et les ensembles suivants sont définis pour rationaliser la composition des profils de sandbox. Les noms sont intentionnellement choisis pour être cohérents avec pledge(2) d'OpenBSD :

all Tous les droits d'accès au système de fichiers
rpath read, readdir
wpath write, truncate
cpath create, delete, rename
dpath mkbdev, mkcdev
spath mkfifo, symlink
tpath mkdir, rmdir
inet bind, connect

NIVEAUX DE COMPATIBILITÉ

Depuis la version 3.35.0, le niveau de compatibilité de landlock(7) peut être défini à l'aide de l'option -C sur l'un des niveaux suivants : hard-requirement, ou simplement hard ou h, soft-requirement, ou simplement short ou s, et best-effort, ou simplement best ou b. La valeur par défaut est hard-requirement pour adhérer au principe des valeurs par défaut sécurisées. Dans ce niveau, les restrictions landlock(7) demandées ne sont prises en compte que si elles sont prises en charge par le système en cours d'exécution ; si une fonctionnalité demandée n'est pas prise en charge, l'opération renvoie une erreur de compatibilité et le sandbox n'est pas activé. Les erreurs open(2) de fichiers lors de la configuration du sandbox, y compris l'erreur errno(3) ENOENT ("Aucun fichier ou répertoire de ce type"), renvoient une erreur fatale dans ce niveau. Dans le niveau soft-requirement, les restrictions demandées sont prises en compte si elles sont prises en charge par le système en cours d'exécution, ou la demande de sandbox entière est silencieusement

FLAGS

As of version 3.38.0, landlock(7) flags may be set using the -F option. Flags may be specified using their names or numerical values. Multiple flags may be set at once by specifying them as a comma-separated list. Flags are supported beginning with landlock(7) ABI 7 which is new in Linux-6.15. List of supported flags are given below. Setting a flag on an unsupported ABI is a NO-OP unless otherwise noted.

log_same_exec_off 1: Disables logging of denied accesses originating from the thread creating the landlock(7) domain, as well as its children, as long as they continue running the same executable code (i.e., without an intervening execve(2) call). This is intended for programs that execute unknown code without invoking execve(2), such as script interpreters. Programs that only sandbox themselves should not set this flag, so users can be notified of unauthorized access attempts via system logs. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.
log_new_exec_on 2: Enables logging of denied accesses after an execve(2) call, providing visibility into unauthorized access attempts by newly executed programs within the created landlock(7) domain. This flag is recommended only when all potential executables in the domain are expected to comply with the access restrictions, as excessive audit log entries could make it more difficult to identify critical events. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.
log_subdomains_off 4: Disables logging of denied accesses originating from nested landlock(7) domains created by the caller or its descendants. This flag should be set according to runtime configuration, not hardcoded, to avoid suppressing important security events. It is useful for container runtimes or sandboxing tools that may launch programs which themselves create landlock(7) domains and could otherwise generate excessive logs. Unlike log_same_exec_off, this flag only affects future nested domains, not the one being created. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.

SECURITY

As of version 3.35.0, the default landlock(7) compatibility level has been changed from best-effort to hard-requirement, and ENOENT (No such file or directory) errors are made fatal unless level is set to best-effort. This adheres to the principle of secure defaults and above all avoids the silent and dangerous trap where a non-existing file or directory which had been denied access (and skipped) at startup is created after and landlock(7) ends up allowing access to the newly created file or directory. For more information, see: https://landlock.io/rust-landlock/landlock/trait.Compatible.html

Consider combining syd-lock(1) use with syd-mdwe(1) to get W^X memory protections. See syd-mdwe(1) manual page for more information.

EXIT STATUS

syd-lock exits with the same code as the child process on clean exit. On unclean termination, exit code is set to 128 plus signal number. In case executing the child process fails syd-lock(1) exits with the errno(3) number. syd-lock -A exits with the landlock(7) ABI version as exit code.

syd-lock -E exits with one of the following exit codes:

0 All erratas are available.
1 Some erratas are not available.
2 No erratas are available.

syd-lock -V exits with one of the following exit codes based on support for the latest landlock(7) ABI:

0 Fully enforced
1 Partially enforced
2 Not enforced
127 Not supported

syd-lock exits with 22 (EINVAL) for invalid CLI arguments.

syd-lock(1)

NOM

syd-lock - Verrouiller un répertoire

SYNTAXE

syd-lock [OPTION]... RÉPERTOIRE

DESCRIPTION

syd-lock verrouille un répertoire donné. Le répertoire verrouillé ne peut être ni lu, ni modifié, ni supprimé, ni renommé par des utilisateurs non autorisés.

OPTIONS

-h, --help
Afficher un message d'aide et quitter.
-v, --version
Afficher des informations sur la version et quitter.

CONFIGURATION

Aucune configuration n'est requise pour utiliser syd-lock. Le répertoire à verrouiller est spécifié comme argument de ligne de commande.

SÉCURITÉ

syd-lock utilise les mécanismes de verrouillage du système de fichiers pour restreindre l'accès aux répertoires. Assurez-vous que le système de fichiers prend en charge ces mécanismes.

HISTORIQUE

La première version de syd-lock a été introduite dans la version 1.0 du paquet syd.

STATUT DE SORTIE

0
Succès.
1
Erreur lors du verrouillage du répertoire.
2
Argument invalide.

EXEMPLES

Verrouiller le répertoire /data/secret :

$ syd-lock /data/secret
