NOM

systemd-ssh-generator - Générateur pour lier un serveur SSH activé par socket à des sockets AF_VSOCK et AF_UNIX locaux

SYNTAXE

/usr/lib/systemd/system-generators/systemd-ssh-generator

DESCRIPTION

systemd-ssh-generator lie un serveur SSH activé par socket à des sockets AF_VSOCK et AF_UNIX locaux sous certaines conditions. Il n'a d'effet que si le binaire sshd(8) est installé. Plus spécifiquement, il fait ce qui suit :

•Si invoqué dans une VM avec prise en charge d'AF_VSOCK, un service SSH activé par socket pour chaque connexion est lié au port AF_VSOCK 22.
•Si invoqué dans un environnement conteneurisé avec un répertoire accessible en écriture /run/host/unix-export/ pré-monté, il lie SSH à un socket AF_UNIX /run/host/unix-export/ssh. L'hypothèse est que ce répertoire est également monté en tant que bind sur le côté hôte, et peut être utilisé pour se connecter au conteneur à partir de là. Voir Interface de conteneur[1] pour plus d'informations sur cette interface.
•Un socket AF_UNIX local /run/ssh-unix-local/socket est également lié, inconditionnellement. Ceci peut être utilisé pour la communication SSH de l'hôte avec lui-même, sans impliquer le réseau, par exemple pour traverser des frontières de sécurité en toute sécurité et avec une authentification sécurisée.
•Des sockets AF_UNIX et AF_VSOCK supplémentaires sont liés optionnellement, en fonction de l'option de ligne de commande du noyau systemd.ssh_listen= ou du credential système ssh.listen (voir ci-dessous).

Voir systemd-ssh-proxy(1) pour les détails sur la façon de se connecter à ces sockets via le client ssh.

Le credential ssh.authorized_keys.root peut être utilisé pour autoriser des clés publiques spécifiques à se connecter via SSH. Voir systemd.system-credentials(7) pour plus d'informations.

Le générateur utilisera un fichier modèle de service sshd@.service empaqueté s'il en existe un, sinon il générera un fichier modèle de service approprié.

systemd-ssh-generator implémente systemd.generator(7).

LIGNE DE COMMANDE DU NOYAU

systemd-ssh-generator comprend les paramètres de kernel-command-line(7) suivants :

systemd.ssh_auto=

Cette option prend un argument booléen optionnel, et vaut par défaut yes. Si activée, la liaison automatique aux sockets AF_VSOCK et AF_UNIX listés ci-dessus est effectuée. Si désactivée, cela n'est pas fait, sauf pour ceux explicitement demandés via systemd.ssh_listen= sur la ligne de commande du noyau ou via le credential système ssh.listen.

Ajouté dans la version 256.

systemd.ssh_listen=

Cette option configure un socket supplémentaire pour lier SSH. Elle peut être utilisée plusieurs fois pour lier plusieurs sockets. La syntaxe doit suivre celle de ListenStream=, voir systemd.socket(5) pour les détails. Cette fonctionnalité prend en charge toutes les familles de sockets supportées par systemd(1), y compris AF_INET et AF_INET6.

Ajouté dans la version 256.

IDENTIFIANTS

systemd-ssh-generator prend en charge la logique des identifiants système. Les identifiants suivants sont utilisés lorsqu'ils sont passés :

ssh.listen

Cet identifiant doit être un fichier texte, chaque ligne faisant référence à un socket supplémentaire pour lier SSH. La syntaxe doit suivre celle de ListenStream=, voir systemd.socket(5) pour les détails. Cette fonctionnalité prend en charge toutes les familles de sockets supportées par systemd, y compris AF_INET et AF_INET6.

Ajouté dans la version 256.

ssh.ephemeral-authorized_keys-all

Fournit des clés publiques supplémentaires, au format habituel de authorized_keys, pour tous les utilisateurs, pour les connexions entrantes via les unités de sockets AF_VSOCK et AF_UNIX générées.

L'usage prévu est pour un système hôte (dans des configurations VM ou conteneur) de générer une paire de clés et d'injecter la clé publique dans l'invité, en utilisant la clé privée pour se connecter à n'importe quel compte utilisateur sur l'invité via ssh, sans authentification supplémentaire.

Ajouté dans la version 256.
