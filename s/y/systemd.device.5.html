NOM

systemd.device - Configuration d'unité de périphérique

SYNTAXE

périphérique.device

DESCRIPTION

Un fichier de configuration d'unité dont le nom se termine par ".device" encode des informations sur une unité de périphérique telles qu'exposées dans l'arborescence des périphériques sysfs/udev(7). Ceci peut être utilisé pour définir des dépendances entre les périphériques et d'autres unités.

Ce type d'unité n'a pas d'options spécifiques. Voir systemd.unit(5) pour les options communes à tous les fichiers de configuration d'unité. Les éléments de configuration communs sont configurés dans les sections génériques [Unit] et [Install]. Une section [Device] séparée n'existe pas, car aucune option spécifique au périphérique ne peut être configurée.

systemd créera dynamiquement des unités de périphérique pour tous les périphériques du noyau qui sont marqués avec la balise udev "systemd" (par défaut, tous les périphériques de bloc et réseau, et quelques autres). Notez que si systemd-udevd.service ne tourne pas, aucune unité de périphérique ne sera disponible (par exemple dans un conteneur typique).

Les unités de périphérique sont nommées d'après les chemins /sys/ et /dev/ qu'elles contrôlent. Exemple : le périphérique /dev/sda5 est exposé dans systemd en tant que dev-sda5.device. Pour les détails sur la logique d'échappement utilisée pour convertir un chemin de système de fichiers en nom d'unité, voir systemd.unit(5).

Pour baliser un périphérique udev, utilisez "TAG+="systemd"" dans le fichier de règles udev, voir udev(7) pour les détails.

Les unités de périphérique seront rechargées par systemd chaque fois que le périphérique correspondant génère un événement "changé". D'autres unités peuvent utiliser ReloadPropagatedFrom= pour réagir à cet événement.

DÉPENDANCES AUTOMATIQUES

Dépendances implicites

De nombreux types d'unités acquièrent automatiquement des dépendances sur les unités de périphérique des périphériques dont ils ont besoin. Par exemple, les unités .socket acquièrent des dépendances sur les unités de périphérique de l'interface réseau spécifiée dans BindToDevice=. De même, les unités swap et mount acquièrent des dépendances sur les unités qui encapsulent leurs périphériques de bloc sous-jacents.

Dépendances par défaut

Il n'y a pas de dépendances par défaut pour les unités de périphérique.

LA BASE DE DONNÉES UDEV

Les paramètres d'unité des unités de périphérique peuvent être configurés soit via des fichiers d'unité, soit directement depuis la base de données udev. Les propriétés de périphérique udev suivantes sont comprises par le gestionnaire de service :

SYSTEMD_WANTS=, SYSTEMD_USER_WANTS=

Ajoute des dépendances de type Wants= de l'unité de périphérique aux unités spécifiées. SYSTEMD_WANTS= est lu par le gestionnaire de service système, SYSTEMD_USER_WANTS= par les instances du gestionnaire de service utilisateur. Ces propriétés peuvent être utilisées pour activer des unités arbitraires lorsqu'un périphérique spécifique devient disponible.

Notez que ceci et les autres propriétés de périphérique udev ne sont pas pris en compte à moins que le périphérique ne soit balisé avec la balise "systemd" dans la base de données udev, car sinon le périphérique n'est pas exposé en tant qu'unité systemd (voir ci-dessus).

Notez que systemd n'agira sur les dépendances Wants= que lorsqu'un périphérique devient actif pour la première fois. Il n'agira pas sur elles si elles sont ajoutées à des périphériques déjà actifs. Utilisez SYSTEMD_READY= (voir ci-dessous) pour configurer quand un périphérique udev doit être considéré comme actif, et donc quand déclencher les dépendances.

La valeur de propriété spécifiée doit être une liste d'unités valides séparées par des espaces. Si un nom de modèle d'unité est spécifié (c'est-à-dire un nom d'unité contenant un caractère "@" indiquant un nom d'unité à utiliser pour l'instanciation multiple, mais avec un nom d'instance vide suivant le "@"), il sera automatiquement instancié par le chemin "sysfs" du périphérique (c'est-à-dire : le chemin est échappé et inséré comme nom d'instance dans le nom du modèle d'unité). Ceci est utile afin d'instancier une unité modèle spécifique une fois pour chaque périphérique qui apparaît et correspond à des propriétés spécifiques.

SYSTEMD_ALIAS=

Ajoute un alias supplémentaire à l'unité de périphérique. Ce doit être un chemin absolu qui est automatiquement transformé en nom d'unité. (Voir ci-dessus.)

SYSTEMD_READY=

Si défini à 0, systemd considérera ce périphérique comme débranché même s'il apparaît dans l'arborescence udev. Si cette propriété est non définie ou définie à 1, le périphérique sera considéré comme branché s'il est visible dans l'arborescence udev.

Cette option est utile pour les périphériques qui apparaissent initialement dans un état non initialisé dans l'arborescence, et pour lesquels un événement "changé" est généré au moment où ils sont pleinement configurés. Notez que SYSTEMD_WANTS= (voir ci-dessus) n'est pas pris en compte tant que SYSTEMD_READY=0 est défini pour un périphérique.

ID_MODEL_FROM_DATABASE=, ID_MODEL=

Si défini, cette propriété est utilisée comme chaîne de description pour l'unité de périphérique.

OPTIONS

Les fichiers d'unité de périphérique peuvent inclure les sections [Unit] et [Install], qui sont décrites dans systemd.unit(5). Aucune option spécifique à ce type de fichier n'est prise en charge.
