SYSTEMD-JOURNAL-UPLOAD.SERVICE(8) systemd-journal-upload.service SYSTEMD-JOURNAL-UPLOAD.SERVICE(8)

NOM

systemd-journal-upload.service, systemd-journal-upload - Envoyer des messages de journal sur le réseau

SYNTAXE

systemd-journal-upload.service

/usr/lib/systemd/systemd-journal-upload [OPTIONS...] [-u/--url=URL] [SOURCES...]

DESCRIPTION

systemd-journal-upload téléversera les entrées du journal vers l'URL spécifiée avec --url=. Ce programme lit les entrées du journal à partir d'un ou plusieurs fichiers de journal, de manière similaire à journalctl(1). Sauf limitation par l'une des options spécifiées ci-dessous, toutes les entrées du journal accessibles à l'utilisateur exécutant le programme seront téléversées, puis le programme attendra et enverra les nouvelles entrées au fur et à mesure qu'elles deviennent disponibles.

systemd-journal-upload transfère le contenu brut du fichier de journal et utilise HTTP comme protocole de transport.

systemd-journal-upload.service est un service système qui utilise systemd-journal-upload pour téléverser les entrées du journal vers un serveur. Il utilise la configuration de journal-upload.conf(5). Au moins l'option URL= doit être spécifiée.

OPTIONS

-u, --url=[https://]URL[:PORT], --url=[http://]URL[:PORT]

Téléverse vers l'adresse spécifiée. URL peut spécifier soit juste le nom d'hôte, soit le protocole et le nom d'hôte. https est la valeur par défaut. Le numéro de port peut être spécifié après deux-points (":"), sinon 19532 sera utilisé par défaut.

Ajouté en version 239.

--system, --user

Limite les entrées téléversées aux entrées des services système et du noyau, ou aux entrées des services de l'utilisateur courant. Cela a le même sens que les options --system et --user pour journalctl(1). Si aucune des deux n'est spécifiée, toutes les entrées accessibles sont téléversées.

Ajouté en version 239.

-m, --merge

Téléverse les entrées entrelacées depuis tous les journaux disponibles, y compris ceux d'autres machines. Cela a le même sens que l'option --merge pour journalctl(1).

Ajouté en version 239.

--namespace=NAMESPACE

Prend un identifiant de namespace de journal sous forme de chaîne de caractères en argument. Téléverse les entrées du namespace de journal spécifié NAMESPACE au lieu du namespace par défaut. Cela a le même sens que l'option --namespace= pour journalctl(1).

Ajouté en version 254.

-D, --directory=DIR

Prend un chemin de répertoire en argument. Téléverse les entrées du répertoire de journal spécifié DIR au lieu des chemins de journal système et d'exécution par défaut. Cela a le même sens que l'option --directory= pour journalctl(1).

Ajouté en version 239.

--file=GLOB

Prend un glob de fichiers en argument. Téléverse les entrées des fichiers de journal spécifiés correspondant à GLOB au lieu des chemins de journal système et d'exécution par défaut. Peut être spécifié plusieurs fois, auquel cas les fichiers seront correctement entrelacés. Cela a le même sens que l'option --file= pour journalctl(1).

Ajouté en version 239.

--cursor=

Téléverse les entrées à partir de l'emplacement dans le journal spécifié par le curseur passé. Cela a le même sens que l'option --cursor= pour journalctl(1).

Ajouté en version 239.

--after-cursor=

Téléverse les entrées à partir de l'emplacement dans le journal après l'emplacement spécifié par ce curseur. Cela a le même sens que l'option --after-cursor= pour journalctl(1).

Ajouté en version 239.

--save-state[=PATH]

Téléverse les entrées à partir de l'emplacement dans le journal après l'emplacement spécifié par le curseur sauvegardé dans le fichier à PATH (/var/lib/systemd/journal-upload/state par défaut). Après qu'une entrée a été téléversée avec succès, met à jour ce fichier avec le curseur de cette entrée.

Ajouté en version 239.

--follow[=BOOL]

Si défini sur oui, alors systemd-journal-upload attend une entrée.

Ajouté en version 239.

--key=

Prend un chemin vers un fichier de clé SSL au format PEM, ou -. Si - est défini, alors la vérification de l'authentification du certificat client sera désactivée. Par défaut, /etc/ssl/private/journal-upload.pem.

Ajouté en version 239.

--cert=

Prend un chemin vers un fichier de certificat SSL au format PEM, ou -. Si - est défini, alors la vérification de l'authentification du certificat client sera désactivée. Par défaut, /etc/ssl/certs/journal-upload.pem.

Ajouté en version 239.

--trust=

Prend un chemin vers un fichier de certificat CA SSL au format PEM, ou -/all. Si -/all est défini, alors la vérification du certificat sera désactivée. Par défaut, /etc/ssl/ca/trusted.pem.

Ajouté en version 239.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

CODE DE RETOUR

En cas de succès, 0 est retourné ; sinon, un code d'échec non nul est retourné.

EXEMPLES

Exemple 1. Configuration des certificats pour l'authentification

Des certificats signés par une autorité de confiance sont utilisés pour vérifier que le serveur auquel les messages sont téléversés est légitime, et vice-versa, que le client est approuvé.

Un ensemble approprié de certificats peut être généré avec openssl. Notez que 2048 bits de longueur de clé sont minimalement recommandés pour des raisons de sécurité :

openssl req -newkey rsa:2048 -days 3650 -x509 -nodes \
      -out ca.pem -keyout ca.key -subj '/CN=Certificate authority/'
cat >ca.conf <<EOF
[ ca ]
default_ca = this
[ this ]
new_certs_dir = .
certificate = ca.pem
database = ./index
private_key = ca.key
serial = ./serial
default_days = 3650
default_md = default
policy = policy_anything
[ policy_anything ]
countryName             = optional
stateOrProvinceName     = optional
localityName            = optional
organizationName        = optional
organizationalUnitName  = optional
commonName              = supplied
emailAddress            = optional
EOF
touch index
echo 0001 >serial
SERVER=server
CLIENT=client
openssl req -newkey rsa:2048 -nodes -out $SERVER.csr -keyout $SERVER.key -subj "/CN=$SERVER/"
openssl ca -batch -config ca.conf -notext -in $SERVER.csr -out $SERVER.pem
openssl req -newkey rsa:2048 -nodes -out $CLIENT.csr -keyout $CLIENT.key -subj "/CN=$CLIENT/"
openssl ca -batch -config ca.conf -notext -in $CLIENT.csr -out $CLIENT.pem

Les fichiers générés ca.pem, server.pem, et server.key doivent être installés sur le serveur, et ca.pem, client.pem, et client.key sur le client. L'emplacement de ces fichiers peut être spécifié en utilisant TrustedCertificateFile=, ServerCertificateFile=, et ServerKeyFile= dans /etc/systemd/journal-remote.conf et /etc/systemd/journal-upload.conf, respectivement. Les emplacements par défaut peuvent être interrogés en utilisant systemd-journal-remote --help et systemd-journal-upload --help.
