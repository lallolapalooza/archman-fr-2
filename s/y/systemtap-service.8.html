NOM

systemtap-service - script d'initialisation et service systemd pour SystemTap

SYNOPIS

systemtap-service COMMANDE [OPTIONS] [SCRIPT...]

service systemtap COMMANDE [OPTIONS] [SCRIPT...]

DESCRIPTION

Le script d'initialisation SystemTap vise à fournir un moyen d'exécuter des scripts en tant que service et de les contrôler facilement individuellement. Les scripts peuvent être configurés pour démarrer sur demande manuelle, ou pendant le démarrage du système. Sur les systèmes basés sur dracut, il est également possible d'intégrer des scripts dans l'initramfs et de les faire démarrer pendant le début du processus de démarrage.

Le script d'initialisation SystemTap peut être appelé manuellement en utilisant la commande systemtap-service. Sur les systèmes basés sur systemd, le script d'initialisation est contrôlé par systemctl avec le fichier de service systemtap.service.

Il existe divers paramètres et options disponibles pour modifier le comportement global, ainsi que le comportement des scripts. Des dépendances entre scripts peuvent être établies de sorte que le démarrage d'un script démarre d'autres.

Le fichier de configuration du script d'initialisation se trouve dans /etc/systemtap/config. Les paramètres acceptables sont détaillés dans la section PARAMÈTRES GLOBAUX.

Les scripts doivent être placés dans le répertoire /etc/systemtap/script.d et doivent avoir une extension .stp. Cependant, lors de leur référence dans la ligne de commande, il n'est pas nécessaire d'inclure l'extension .stp. Les noms de scripts ne peuvent contenir que des caractères alphanumériques (et '_') et ne doivent pas commencer par un chiffre. Le répertoire des scripts peut être modifié en définissant le paramètre SCRIPT_PATH dans le fichier de configuration.

COMMANDES

Une des commandes ci-dessous doit être spécifiée :

démarrer
Démarre les SCRIPTs. Si aucun script n'est spécifié, démarre les scripts spécifiés par la configuration DEFAULT_START. Si DEFAULT_START n'est pas défini, démarre tous les scripts du répertoire de scripts. Pour les scripts déjà démarrés, la commande est ignorée. La commande échouera si les scripts ne parviennent pas à démarrer (voir aussi la configuration PASSALL).

Si la configuration AUTOCOMPILE est activée, la commande tentera de compiler ou de mettre à jour les scripts spécifiés lorsque l'une des conditions ci-dessous est vraie :

-
Le fichier cache compilé n'existe pas.
-
Le mtime (horodatage de modification) du fichier script original est plus récent que le temps du cache script compilé.
-
Le résultat des options stap spécifiées utilisées pour compiler le script a été modifié (voir aussi la section PARAMÈTRES DE SCRIPT).
-
Le résultat de `uname -a` a été modifié.
arrêter
Arrête les SCRIPTs. Si aucun script n'est spécifié, arrête tous les scripts en cours d'exécution. Pour les scripts déjà arrêtés, la commande est ignorée. La commande échouera si les scripts ne parviennent pas à s'arrêter (voir aussi la configuration PASSALL).
redémarrer
Arrête et démarre les SCRIPTs.
état
Affiche l'état des SCRIPTs et de leurs dépendances.
compiler
Compile les SCRIPTs mais ne les démarre pas. Si les scripts ont déjà été compilés, demande confirmation avant d'écraser le cache. Compile pour le noyau actuel, ou pour la version du noyau spécifiée par l'option -r.
onboot
Incorpore les SCRIPTs à l'initramfs afin qu'ils soient démarrés plus tôt pendant le processus de démarrage. Cette commande n'est disponible que sur les systèmes basés sur dracut. Si aucun script n'est spécifié, crée une initramfs normale sans aucun fichier SystemTap.

L'initramfs est créée pour le noyau actuel, ou pour la version du noyau spécifiée par l'option -r. Le chemin du fichier initramfs créé est par défaut /boot/initramfs-KVER.img, où KVER est le résultat de `uname -r`. Le chargeur de démarrage est également mis à jour (en utilisant new-kernel-pkg(8)) pour que l'entrée du noyau utilise le nouveau fichier initramfs. Utilisez l'option -o pour spécifier un chemin différent (le chargeur de démarrage ne sera pas mis à jour).

Si le fichier de sortie existe déjà, il est écrasé, sauf si le commutateur -b est donné, auquel cas le fichier est sauvegardé avec l'extension .bak plutôt qu'écrasé. Cependant, s'il existe déjà une version .bak du fichier, la sauvegarde ne sera pas écrasée.

ATTENTION : n'utilisez pas l'option -o de stap(1) avec les scripts onboot car le script est démarré avant même que le système de fichiers racine ne soit monté. Augmentez la taille du tampon si plus d'espace est nécessaire.

nettoyer
Supprime les SCRIPTs compilés du cache. Si aucun script n'est spécifié, tous les scripts compilés sont supprimés. Seul le cache du noyau actuel est supprimé, ou la version du noyau spécifiée par l'option -r. Demande confirmation avant de supprimer.

OPTIONS

Beaucoup des commandes peuvent également prendre des options. Cependant, comme les utilisateurs ne peuvent pas passer ces options au démarrage, elles sont uniquement destinées à la gestion des scripts après le démarrage et aux tests. Les options disponibles sont :

-c FICHIER_CONFIG
Spécifie un fichier de configuration différent à la place du fichier par défaut.
-R
Lors de l'utilisation des commandes démarrer et arrêter, inclut également les dépendances des scripts (récursivement).
-r VERSION_NOYAU
Lors de l'utilisation des commandes compiler, onboot et nettoyer, spécifie la version cible du noyau au lieu d'utiliser la version actuelle. Doit être dans le même format que `uname -r`.
-y
Répond oui à toutes les demandes.
-o CHEMIN.IMG
Lors de l'utilisation de la commande onboot, spécifie le chemin de sortie de l'initramfs créée. Lorsque spécifié, la configuration du chargeur de démarrage n'est pas mise à jour.
-b
Lors de l'utilisation de la commande onboot, sauvegarde une image initramfs existante en ajoutant l'extension .bak au lieu de l'écraser. Sans cette option, l'initramfs est écrasée.

PARAMÈTRES GLOBAUX

Ces paramètres affectent le comportement général du service d'initialisation SystemTap. Ils peuvent être spécifiés dans le fichier de configuration.

CHEMIN_SCRIPTS
Spécifie le chemin absolu du répertoire des scripts. Ce sont les scripts sur lesquels le script d'initialisation peut opérer. Les scripts doivent avoir l'extension .stp. Le chemin par défaut est /etc/systemtap/script.d.
CHEMIN_CONFIG
Spécifie le chemin absolu du répertoire de configuration des scripts. Ces fichiers de configuration contiennent des options pour des scripts spécifiques. Ils doivent avoir l'extension .conf. Le chemin par défaut est /etc/systemtap/conf.d.
CHEMIN_CACHE
Spécifie le chemin absolu du répertoire de cache. Le chemin par défaut est /var/cache/systemtap.
CHEMIN_TEMPORAIRE
Spécifie le chemin absolu du répertoire temporaire dans lequel SystemTap crée des répertoires temporaires pour compiler des scripts. Le chemin par défaut est /tmp.
CHEMIN_STAT
Spécifie le chemin absolu du répertoire contenant les fichiers PID utilisés pour suivre l'état des scripts SystemTap. Le chemin par défaut est /var/run/systemtap.
FICHIER_LOG
Spécifie le chemin absolu du fichier journal. Tous les messages sont envoyés à ce fichier, y compris les erreurs de compilation et d'exécution. Le chemin par défaut est /var/log/sy
systemtap.log.
PASSALL
Si cette option est définie sur yes, les commandes de script d'initialisation qui opèrent sur plusieurs scripts seront signalées comme échouées lorsque l'action n'a pas pu être effectuée sur au moins un script. Si elle est définie sur no, seul un avertissement sera émis. La valeur par défaut est yes.
RECURSIVE
Si cette option est définie sur yes, le script d'initialisation suivra toujours récursivement les dépendances de scripts. Cela signifie qu'il n'est pas nécessaire de spécifier l'option -R. Ce drapeau n'est effectif que si vous spécifiez des scripts depuis la ligne de commande. La valeur par défaut est no.
AUTOCOMPILE
Si cette option est définie sur yes, le script d'initialisation tentera automatiquement de compiler les scripts spécifiés lorsque nécessaire s'il n'y a pas de cache valide. Sinon, la commande associée échouera simplement. La valeur par défaut est yes.
DEFAULT_START
Spécifie les scripts qui seront démarrés par défaut. S'il est omis (ou vide), tous les scripts du répertoire de scripts seront démarrés. La valeur par défaut est "".
ALLOW_CACHEONLY
Si cette option est définie sur yes, le script d'initialisation permettra également d'opérer sur des scripts qui se trouvent dans le répertoire de cache, mais pas dans le répertoire de scripts. La valeur par défaut est no.

AVERTISSEMENT : le script d'initialisation peut charger des caches obsolètes inattendus avec cette option. Le répertoire de cache doit être vérifié avant d'activer cette option.

LOG_BOOT_ERR
Comme les scripts de démarrage sont exécutés avant que le système de fichiers racine ne soit monté, la sortie d'erreur standard de staprun ne peut pas être enregistrée dans LOG_FILE comme d'habitude. Cependant, le log peut être redirigé vers /run/systemtap/$script.log en définissant LOG_BOOT_ERR sur yes. Si STAT_PATH est différent de la valeur par défaut, les fichiers journaux seront déplacés vers cet emplacement lors de l'exécution de l'une des commandes du script d'initialisation. La valeur par défaut est no.

Voici un exemple de fichier de configuration globale :

SCRIPT_PATH=/var/systemtap/script.d/
PASSALL=yes
RECURSIVE=no

PARAMÈTRES DES SCRIPTS

Ces paramètres affectent la compilation ou le comportement à l'exécution de scripts SystemTap spécifiques. Ils doivent être placés dans des fichiers de configuration situés dans le répertoire CONFIG_PATH.

<SCRIPT>_OPT
Spécifie les options passées à la commande stap(1) pour SCRIPT. Ici, SCRIPT est le nom du fichier script sans l'extension .stp. Notez que l'option -F est toujours ajoutée.

Les options suivantes sont ignorées lors de la compilation des scripts : -p, -m, -r, -c, -x, -e, -s, -o, -h, -V, -k.

Les options suivantes sont ignorées lors de l'exécution des scripts de démarrage : -h, -V, -v, -t, -p, -I, -e, -R, -r, -m, -k, -g, -P, -D, -b, -u, -q, -w, -l, -d, -L, -F, et toutes les options longues.

<SCRIPT>_REQ
Spécifie les dépendances du script (c'est-à-dire, quel script ce script nécessite). Par exemple, si foo.stp nécessite (ou doit s'exécuter après) bar.stp, définissez 
foo_REQ="bar"

Spécifiez plusieurs scripts en séparant leurs noms par des espaces.

Voici un exemple de fichier de configuration de script :

script1_OPT="-o /var/log/script1.out"
script2_OPT="-o /var/log/script2.out"
script2_REQ="script1"

EXEMPLES

INSTALLATION DES SCRIPTS
Nous copions d'abord un script SystemTap (par exemple, "script1.stp") dans le répertoire de scripts : 
# cp script1.stp /etc/systemtap/script.d/

Nous pouvons ensuite définir toutes les options de script, par exemple :

# vi /etc/systemtap/conf.d/group1.conf
script1_OPT="-o /var/log/group1.out"

Nous installons ensuite un script (par exemple, "script2.stp") qui nécessite de s'exécuter après script1. Dans ce cas, nous pouvons faire ce qui suit :

# cp script2.stp /etc/systemtap/script.d/
# vi /etc/systemtap/conf.d/group1.conf
script2_OPT="-o /var/log/script2.out"
script2_REQ="script1"

De cette façon, si stap(1) échoue à exécuter script1, le script d'initialisation n'essaiera même pas d'exécuter script2.

TEST
Après avoir installé les scripts, nous pouvons tester leur fonctionnement en faisant simplement : 
# systemtap-service start
# systemtap-service stop

Nous pourrions aussi être plus spécifiques, par exemple :

# systemtap-service start script1
# systemtap-service stop script1

S'il n'y a eu aucune erreur, nous sommes prêts à l'utiliser.

ACTIVATION DU SERVICE
Une fois que nous sommes satisfaits des scripts et de leurs tests, nous pouvons activer le service d'initialisation SystemTap : 
# chkconfig systemtap on
SUPPRESSION DES SCRIPTS
Les scripts sont supprimés en les retirant simplement du répertoire de scripts et en supprimant toute ligne de configuration qui leur est spécifique : 
# rm /etc/systemtap/script.d/script2.stp
# vi /etc/systemtap/conf.d/group1.conf

Si le script est toujours en cours d'exécution, nous devons également l'arrêter :

# systemtap-service stop script2

Nous pouvons ensuite également supprimer le cache associé au script :

# systemtap-service cleanup script2
PRÉPARATION POUR LES MISES À JOUR DU NOYAU
Généralement, il n'y a rien à faire lors du démarrage sur un nouveau noyau. Le script d'initialisation constatera que la version du noyau est différente et compilera les scripts. La compilation peut également être effectuée à l'avance pour éviter d'avoir à compiler lors du démarrage en utilisant l'option -r : 
# systemtap-service compile myscript -r <NOUVELLE_VERSION_DU_NOYAU>
IMPORTATION DES SCRIPTS COMPILÉS
Pour les environnements qui manquent d'infrastructure de compilation (par exemple, pas de compilateurs ou de débogage), comme un système de production, les scripts peuvent être compilés sur une autre machine (de développement) puis transférés sur le système de production : 
# systemtap-service compile myscript -r \
>   <VERSION_DU_NOYAU_DE_LA_MACHINE_CIBLE>
# tar czf stap-scripts-<version-noyau>.tar.gz \
>   /var/cache/systemtap/<version-noyau> \
>   /etc/systemtap/conf.d/<fichier_de_configuration>

Et ensuite, copiez ce paquet sur la machine cible et extrayez-le.

DÉMARRAGE DES SCRIPTS PENDANT LE DÉMARRAGE PRÉCOCE
Le script d'initialisation permet également de démarrer les scripts plus tôt pendant le processus de démarrage en créant un initramfs contenant le module du script. Le système doit être basé sur dracut pour que cela fonctionne. Démarrer un script à ce stade donne accès à des informations difficiles à obtenir autrement.

Nous installons d'abord le script en le copiant dans le répertoire de scripts comme d'habitude et en définissant les options souhaitées :

# cp myscript.stp /etc/systemtap/script.d
# vi /etc/systemtap/conf.d/myscript.conf

Pour ajouter le script à l'initramfs, nous utilisons la commande onboot :

# systemtap-service onboot myscript

Si le script n'est pas déjà compilé et mis en cache, cela sera fait à ce moment-là. Un nouvel initramfs sera alors créé à l'emplacement par défaut. Nous pouvons utiliser l'option -b pour nous assurer que l'initramfs existant est sauvegardé. Nous pouvons ensuite redémarrer le système.

UTILISATION D'UN INITRAMFS DIFFÉRENT
Si nous préférons démarrer le script uniquement pour un démarrage et pas pour les autres, il peut être plus simple d'utiliser l'option -o pour spécifier un fichier initramfs de sortie différent : 
# systemtap-service onboot myscript \
>   -o /boot/special_initramfs.img

Une fois l'initramfs créé, il suffit de modifier les options de la ligne de commande au démarrage pour que la nouvelle image soit utilisée plutôt que celle habituelle.

CRÉATION D'UN INITRAMFS POUR UN AUTRE NOYAU
Tout comme la commande de compilation, nous pouvons utiliser l'option -r pour spécifier le noyau pour lequel nous voulons créer l'initramfs. Ceci est utile lorsque nous sommes sur le point de mettre à niveau et que nous voulons nous préparer à l'avance. Par exemple : 
# systemtap-service onboot myscript \
>   -r 3.12.6-200.fc19.x86_64
SUPPRESSION DES SCRIPTS DE L'INITRAMFS
Enfin, pour supprimer tous les scripts de l'initramfs, nous exécutons simplement la commande onboot sans spécifier de scripts : 
# systemtap-service onboot

Ceci créera simplement un initramfs standard sans aucun module SystemTap inséré.

RÉSOLUTION DES PROBLÈMES DE DÉMARRAGE PRÉCOCE
Il peut y avoir de nombreuses raisons pour lesquelles le module n'a pas été inséré ou n'a pas fonctionné comme prévu. Il peut être utile d'activer le débogage dracut en ajoutant 'rdinitdebug' à la ligne de commande du noyau et en vérifiant dmesg/journalctl -ae. De plus, la sortie d'erreur standard de staprun peut être capturée en définissant l'option LOG_BOOT_ERR sur yes.
