sysconf(3) Manuel des fonctions de bibliothèque sysconf(3)

NOM

sysconf - obtenir des informations de configuration à l'exécution

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
long sysconf(int name);

DESCRIPTION

POSIX permet à une application de tester à la compilation ou à l'exécution si certaines options sont prises en charge, ou quelle est la valeur de certaines constantes ou limites configurables.

À la compilation, cela se fait en incluant <unistd.h> et/ou <limits.h> et en testant la valeur de certaines macros.

À l'exécution, on peut demander des valeurs numériques en utilisant la fonction présente sysconf(). On peut demander des valeurs numériques qui peuvent dépendre du système de fichiers dans lequel réside un fichier en utilisant fpathconf(3) et pathconf(3). On peut demander des valeurs de chaînes de caractères en utilisant confstr(3).

Les valeurs obtenues de ces fonctions sont des constantes de configuration système. Elles ne changent pas pendant la durée de vie d'un processus.

Pour les options, typiquement, il existe une constante _POSIX_FOO qui peut être définie dans <unistd.h>. Si elle est indéfinie, il faut demander à l'exécution. Si elle est définie à -1, alors l'option n'est pas prise en charge. Si elle est définie à 0, alors les fonctions et en-têtes pertinents existent, mais il faut demander à l'exécution quel degré de support est disponible. Si elle est définie à une valeur autre que -1 ou 0, alors l'option est prise en charge. Généralement, la valeur (comme 200112L) indique l'année et le mois de la révision POSIX décrivant l'option. glibc utilise la valeur 1 pour indiquer le support tant que la révision POSIX n'a pas été publiée. L'argument sysconf() sera _SC_FOO. Pour une liste d'options, voir posixoptions(7).

Pour les variables ou les limites, typiquement, il existe une constante _FOO, peut-être définie dans <limits.h>, ou _POSIX_FOO, peut-être définie dans <unistd.h>. La constante ne sera pas définie si la limite n'est pas spécifiée. Si la constante est définie, elle donne une valeur garantie, et une valeur plus grande pourrait être effectivement prise en charge. Si une application veut tirer parti de valeurs qui peuvent changer entre les systèmes, un appel à sysconf() peut être effectué. L'argument sysconf() sera _SC_FOO.

variables POSIX.1

Nous donnons le nom de la variable, le nom de l'argument sysconf() utilisé pour s'enquérir de sa valeur, et une courte description.

Premièrement, les valeurs compatibles POSIX.1.

ARG_MAX - _SC_ARG_MAX
La longueur maximale des arguments pour la famille de fonctions exec(3). Ne doit pas être inférieure à _POSIX_ARG_MAX (4096).
CHILD_MAX - _SC_CHILD_MAX
Le nombre maximum de processus simultanés par ID utilisateur. Ne doit pas être inférieur à _POSIX_CHILD_MAX (25).
HOST_NAME_MAX - _SC_HOST_NAME_MAX
Longueur maximale d'un nom d'hôte, sans inclure le octet nul de terminaison, tel que renvoyé par gethostname(2). Ne doit pas être inférieure à _POSIX_HOST_NAME_MAX (255).
LOGIN_NAME_MAX - _SC_LOGIN_NAME_MAX
Longueur maximale d'un nom de connexion, y compris l'octet nul de terminaison. Ne doit pas être inférieure à _POSIX_LOGIN_NAME_MAX (9).
NGROUPS_MAX - _SC_NGROUPS_MAX
Nombre maximum d'identifiants de groupe supplémentaires.
ticks d'horloge - _SC_CLK_TCK
Le nombre de ticks d'horloge par seconde. La variable correspondante est obsolète. Elle était bien sûr appelée CLK_TCK. (Note : la macro CLOCKS_PER_SEC ne donne pas d'information : elle doit être égale à 1000000.)
OPEN_MAX - _SC_OPEN_MAX
Le nombre maximum de fichiers qu'un processus peut avoir ouverts à un moment donné. Ne doit pas être inférieur à _POSIX_OPEN_MAX (20).
PAGESIZE - _SC_PAGESIZE
Taille d'une page en octets. Ne doit pas être inférieure à 1.
PAGE_SIZE - _SC_PAGE_SIZE
Un synonyme pour PAGESIZE/_SC_PAGESIZE. (PAGESIZE et PAGE_SIZE sont spécifiés dans POSIX.)
RE_DUP_MAX - _SC_RE_DUP_MAX
Le nombre d'occurrences répétées d'un BRE autorisées par regexec(3) et regcomp(3). Ne doit pas être inférieur à _POSIX2_RE_DUP_MAX (255).
STREAM_MAX - _SC_STREAM_MAX
Le nombre maximum de flux qu'un processus peut avoir ouverts à un moment donné. Si elle est définie, elle a la même valeur que la macro C standard FOPEN_MAX. Ne doit pas être inférieure à _POSIX_STREAM_MAX (8).
SYMLOOP_MAX - _SC_SYMLOOP_MAX
Le nombre maximum de liens symboliques rencontrés dans un chemin avant que la résolution ne renvoie ELOOP. Ne doit pas être inférieur à _POSIX_SYMLOOP_MAX (8).
TTY_NAME_MAX - _SC_TTY_NAME_MAX
La longueur maximale d'un nom de périphérique terminal, y compris l'octet nul de terminaison. Ne doit pas être inférieure à _POSIX_TTY_NAME_MAX (9).
TZNAME_MAX - _SC_TZNAME_MAX
Le nombre maximum d'octets dans un nom de fuseau horaire. Ne doit pas être inférieur à _POSIX_TZNAME_MAX (6).
_POSIX_VERSION - _SC_VERSION
indique l'année et le mois de l'approbation de la norme POSIX.1 au format AAAAAA ; la valeur 199009L indique la révision de septembre 1990.

variables POSIX.2

Ensuite, les valeurs POSIX.2, donnant les limites pour les utilitaires.

BC_BASE_MAX - _SC_BC_BASE_MAX
indique la valeur maximale d'obase acceptée par l'utilitaire bc(1).
BC_DIM_MAX - _SC_BC_DIM_MAX
indique la valeur maximale d'éléments autorisée dans un tableau par bc(1).
BC_SCALE_MAX - _SC_BC_SCALE_MAX
indique la valeur maximale d'échelle autorisée par bc(1).
BC_STRING_MAX - _SC_BC_STRING_MAX
indique la longueur maximale d'une chaîne acceptée par bc(1).
COLL_WEIGHTS_MAX - _SC_COLL_WEIGHTS_MAX
indique le nombre maximum de poids qui peuvent être attribués à une entrée du mot-clé LC_COLLATE order dans le fichier de définition de locale.
EXPR_NEST_MAX - _SC_EXPR_NEST_MAX
est le nombre maximum d'expressions qui peuvent être imbriquées entre parenthèses par expr(1).
LINE_MAX - _SC_LINE_MAX
La longueur maximale d'une ligne d'entrée d'un utilitaire, soit depuis l'entrée standard, soit depuis un fichier. Ceci inclut l'espace pour un saut de ligne final.

sysconf(3) — man pages

NAME

sysconf — get configurable system variables

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <unistd.h>

long sysconf(int name);

DESCRIPTION

The sysconf() function returns a value related to the configurable system limit or option indicated by name. The value returned is of type long.

If name corresponds to a limit that is indeterminate, -1 is returned and errno is unchanged. If name corresponds to an option, a positive value indicates that the option is supported, and -1 indicates that it is not.

The constants used for name are defined in <unistd.h>.

The standard POSIX.1-2001 and POSIX.1-2008 options are:

_SC_ARG_MAX
The maximum number of bytes that can be occupied by an argument list, including environment specifications.
_SC_CHILD_MAX
The maximum number of simultaneous processes that may be created by a user.
_SC_CLK_TCK
The number of clock ticks per second. (The value of this constant is required to be CLOCKS_PER_SEC from <time.h>.)
_SC_COLL_WEIGHTS_MAX
The maximum number of weights that can be assigned to an equivalent character with the collation (table definitions).
_SC_EMAIL_MAX
The maximum length of an email address.
_SC_EQUIV_CLASS_MAX
The maximum number of characters in a POSIX.1 equivalence class name.
_SC_EXINIT_MAX
The maximum number of lines supported by the ex editor.
_SC_EXTENDED_MASS_STORAGE
Indicates support for the USB Extended Mass Storage Class.
_SC_HOST_NAME_MAX
The maximum length of a hostname, including the terminating null character.
_SC_IOV_MAX
The maximum number of iov_t structures that can be passed to a single readv or writev system call.
_SC_JOB_CONTROL
Indicates whether job control is supported.
_SC_LINK_MAX
The maximum number of links that can be created to a regular file.
_SC_LOGIN_NAME_MAX
The maximum length of the login name, including the terminating null character.
_SC_MAX_CANON
The maximum length in bytes of the canonical input queue.
_SC_MAX_INPUT
The maximum length in bytes of the terminal input buffer.
_SC_MB_LEN_MAX
The maximum number of bytes in a character that is represented by a multibyte character sequence.
_SC_MEN_MAX
The maximum number of messages that can be sent to a message queue.
_SC_MEMBER_MAX
The maximum number of members that can be specified in a structure definition.
_SC_MSG_MAX
The maximum number of bytes that can be sent in a single message.
_SC_M_PAGESIZE
The size of a page.
_SC_M_PAGERS_MAX
The number of pages of physical memory.
_SC_NGROUPS_MAX
The maximum number of groups that can be created by a user.
_SC_NL_ARGMAX
The maximum length in bytes of the command line argument list.
_SC_NL_LANGMAX
The maximum length in bytes of a language string.
_SC_NL_MSGMAX
The maximum length in bytes of a message.
_SC_NL_SETMAX
The maximum number of message sets that can be created.
_SC_NL_TEXTMAX
The maximum length in bytes of a text string.
_SC_OPEN_MAX
The maximum number of files that a process may have open at any time.
_SC_PAGE_SIZE
The size of a page.
_SC_PASS_MAX
The maximum length of a password.
_SC_PAGESIZE
The size of a page in bytes.
_SC_RE_DUP_MAX
The maximum number of repeated occurrences of a regular expression when the interval notation \{m,n\} is used.
POSIX2_VERSION - _SC_2_VERSION
indicates the version of the POSIX.2 standard in the format of YYYYMML.
POSIX2_C_DEV - _SC_2_C_DEV
indicates whether the POSIX.2 C language development facilities are supported.
POSIX2_FORT_DEV - _SC_2_FORT_DEV
indicates whether the POSIX.2 FORTRAN development utilities are supported.
POSIX2_FORT_RUN - _SC_2_FORT_RUN
indicates whether the POSIX.2 FORTRAN run-time utilities are supported.
_POSIX2_LOCALEDEF - _SC_2_LOCALEDEF
indicates whether the POSIX.2 creation of locales via localedef(1) is supported.
POSIX2_SW_DEV - _SC_2_SW_DEV
indicates whether the POSIX.2 software development utilities option is supported.

These values also exist, but may not be standard.

- _SC_PHYS_PAGES
The number of pages of physical memory. Note that it is possible for the product of this value and the value of _SC_PAGESIZE to overflow.
- _SC_AVPHYS_PAGES
The number of currently available pages of physical memory.
- _SC_NPROCESSORS_CONF
The number of processors configured. See also get_nprocs_conf(3).
- _SC_NPROCESSORS_ONLN
The number of processors currently online (available). See also get_nprocs_conf(3).

RETURN VALUE

The return value of sysconf() is one of the following:

•
On error, -1 is returned and errno is set to indicate the error (for example, EINVAL, indicating that name is invalid).
•
If name corresponds to a maximum or minimum limit, and that limit is indeterminate, -1 is returned and errno is not changed. (To distinguish an indeterminate limit from an error, set errno to zero before the call, and then check whether errno is nonzero when -1 is returned.)
•
If name corresponds to an option, a positive value is returned if the option is supported, and -1 is returned if the option is not supported.
•
Otherwise, the current value of the option or limit is returned. This value will not be more restrictive than the corresponding value that was described to the application in <unistd.h> or <limits.h> when the application was compiled.

ERRORS

EINVAL
name is invalid.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute Value
sysconf () Thread safety MT-Safe env

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

BUGS

It is difficult to use ARG_MAX because it is not specified how much of the argument space for exec(3) is consumed by the user's environment variables.

Some returned values may be huge; they are not suitable for allocating memory.

SEE ALSO

bc(1), expr(1), getconf(1), locale(1), confstr(3), fpathconf(3), pathconf(3), posixoptions(7)
