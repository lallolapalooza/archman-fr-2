NOM

systemd.nspawn - Paramètres de conteneur

SYNTAXE

/etc/systemd/nspawn/machine.nspawn
/run/systemd/nspawn/machine.nspawn
/var/lib/machines/machine.nspawn

DESCRIPTION

Un fichier de configuration de conteneur nspawn (suffixe .nspawn) contient la configuration d'exécution pour un conteneur local et est utilisé par systemd-nspawn(1). Les fichiers de ce type sont nommés d'après les conteneurs pour lesquels ils définissent des paramètres. Ils sont optionnels et ne sont requis que pour les conteneurs dont l'environnement d'exécution doit différer des valeurs par défaut. Les fichiers de ce type contiennent principalement des paramètres qui peuvent également être définis sur la ligne de commande de systemd-nspawn, et facilitent l'association persistante de paramètres spécifiques à des conteneurs spécifiques. La syntaxe de ces fichiers est inspirée des fichiers .desktop, de manière similaire aux autres fichiers de configuration pris en charge par le projet systemd. Voir systemd.syntax(7) pour un aperçu.

DÉCOUVERTE DE FICHIER .NSPAWN

Les fichiers sont recherchés en ajoutant le suffixe .nspawn au nom de la machine du conteneur, tel que spécifié avec l'option --machine= de systemd-nspawn, ou dérivé du nom du répertoire ou du fichier image. Ce fichier est d'abord recherché dans /etc/systemd/nspawn/ et /run/systemd/nspawn/. S'il est trouvé là, les paramètres sont lus et tous prennent pleinement effet (mais peuvent toujours être remplacés par des arguments de ligne de commande correspondants). Sinon, le fichier sera ensuite recherché à côté du fichier image ou dans le parent immédiat du répertoire racine du conteneur. S'il est trouvé là, seul un sous-ensemble des paramètres prendra effet cependant. Tous les paramètres qui élèvent éventuellement les privilèges ou accordent un accès supplémentaire aux ressources de l'hôte (tels que des fichiers ou des répertoires) sont ignorés. À quelles options cela s'applique est documenté ci-dessous.

Les fichiers de paramètres persistants créés et maintenus par l'administrateur (et donc fiables) doivent être placés dans /etc/systemd/nspawn/, tandis que les fichiers de paramètres téléchargés automatiquement (et donc potentiellement non fiables) sont placés dans /var/lib/machines/ (à côté des images de conteneur), où leur impact sur la sécurité est limité. Afin d'ajouter des paramètres privilégiés aux fichiers .nspawn obtenus auprès du fournisseur d'images, il est recommandé de copier les fichiers de paramètres dans /etc/systemd/nspawn/ et de les modifier là, afin que les options privilégiées deviennent disponibles. L'algorithme précis de la manière dont les fichiers sont recherchés et interprétés peut être configuré avec le commutateur --settings= de systemd-nspawn, voir systemd-nspawn(1) pour plus de détails.

OPTIONS DE LA SECTION [EXEC]

Les fichiers de paramètres peuvent inclure une section [Exec], qui contient divers paramètres d'exécution :

Boot=

Prend un argument booléen, qui est désactivé par défaut. S'il est activé, systemd-nspawn recherchera automatiquement un exécutable d'init et l'invoquera. Dans ce cas, les paramètres spécifiés à l'aide de Parameters= sont passés comme arguments supplémentaires au processus d'init. Ce paramètre correspond au commutateur --boot sur la ligne de commande de systemd-nspawn. Ce paramètre ne peut pas être combiné avec ProcessTwo=yes. Ce paramètre est spécifié par défaut dans l'unité modèle systemd-nspawn@.service.

Ajouté dans la version 226.

Ephemeral=

Prend un argument booléen, qui est désactivé par défaut. S'il est activé, le conteneur est exécuté avec un instantané temporaire de son système de fichiers qui est supprimé immédiatement lorsque le conteneur se termine. Ceci est équivalent au commutateur de ligne de commande --ephemeral. Voir systemd-nspawn(1) pour les détails sur les options spécifiques prises en charge.

Ajouté dans la version 240.

ProcessTwo=

Prend un argument booléen, qui est désactivé par défaut. S'il est activé, le programme spécifié est exécuté comme PID 2. Un processus d'init factice est exécuté comme PID 1. Ce paramètre correspond au commutateur --as-pid2 sur la ligne de commande de systemd-nspawn. Ce paramètre ne peut pas être combiné avec Boot=yes.

Ajouté dans la version 229.

Parameters=

Prend une liste d'arguments séparés par des espaces. Des guillemets simples ("'") et doubles (""") peuvent être utilisés autour des arguments contenant des espaces. Il s'agit soit d'une ligne de commande, commençant par le nom du binaire à exécuter, soit – si Boot= est activé – des arguments à passer au processus d'init. Ce paramètre correspond aux paramètres de la ligne de commande passés sur la ligne de commande de systemd-nspawn.

Note : Boot=no, Parameters=a b "c c" est identique à systemd-nspawn a b "c c", et Boot=yes, Parameters=b 'c c' est identique à systemd-nspawn --boot b 'c c'.

Ajouté dans la version 226.

Environment=

Prend une affectation de variable d'environnement composée d'une clé et d'une valeur, séparées par "=". Définit une variable d'environnement pour le processus principal invoqué dans le conteneur. Ce paramètre peut être utilisé plusieurs fois pour définir plusieurs variables d'environnement. Il correspond au commutateur de ligne de commande --setenv=.

Ajouté dans la version 226.

User=

Prend un nom d'utilisateur UNIX. Spécifie le nom d'utilisateur sous lequel invoquer le processus principal du conteneur. Cet utilisateur doit être connu dans la base de données des utilisateurs du conteneur. Ceci correspond au commutateur de ligne de commande --user=.

Ajouté dans la version 226.

WorkingDirectory=

Sélectionne le répertoire de travail pour le processus invoqué dans le conteneur. Attend un chemin absolu dans l'espace de noms du système de fichiers du conteneur. Ceci correspond au commutateur de ligne de commande --chdir=.

Ajouté dans la version 229.

PivotRoot=

Sélectionne un répertoire vers lequel pivoter / à l'intérieur du conteneur au démarrage. Prend un seul chemin, ou une paire de deux chemins séparés par un deux-points. Les deux chemins doivent être absolus et sont résolus dans l'espace de noms du système de fichiers du conteneur. Ceci correspond au commutateur de ligne de commande --pivot-root=.

Ajouté dans la version 233.

Capability=, DropCapability=

Prend une liste de capacités de processus Linux séparées par des espaces (voir capabilities(7) pour les détails). Le paramètre Capability= spécifie des capacités supplémentaires à passer en plus de l'ensemble par défaut de capacités. Le paramètre DropCapability= spécifie les capacités à supprimer de l'ensemble par défaut. Ces paramètres correspondent aux commutateurs de ligne de commande --capability= et --drop-capability=. Notez que Capability= est un paramètre privilégié et ne prend effet que dans les fichiers .nspawn dans /etc/systemd/nspawn/ et /run/system/nspawn/ (voir ci-dessus). D'autre part, DropCapability= prend effet dans tous les cas. Si la valeur spéciale "all" est passée, toutes les capacités sont conservées (ou supprimées).

Ces paramètres modifient l'ensemble des capacités limitées qui limite également les capacités ambiantes telles que définies par AmbientCapability=.

Ajouté dans la version 226.

AmbientCapability=

Prend une liste de capacités de processus Linux séparées par des espaces (voir capabilities(7) pour les détails). Le paramètre AmbientCapability= spécifie les capacités qui seront transmises au programme démarré dans les ensembles de capacités héritables et ambiantes. Ceci accordera ces capacités à ce processus. Ce paramètre correspond au commutateur de ligne de commande --ambient-capability=.

La valeur "all" n'est pas prise en charge pour ce paramètre.

Le réglage de AmbientCapability= doit être couvert par les réglages de l'ensemble de limitation qui ont été établis par Capability= et DropCapability=.

Notez que AmbientCapability= est un paramètre privilégié (voir ci-dessus).

Ajouté dans la version 248.

NoNewPrivileges=

Prend un argument booléen qui contrôle le drapeau PR_SET_NO_NEW_PRIVS pour la charge utile du conteneur. Ceci est équivalent au commutateur de ligne de commande --no-new-privileges=. Voir systemd-nspawn(1) pour les détails.

Ajouté dans la version 239.

KillSignal=

Spécifiez le signal du processus t
o envoyer au PID du conteneur 1 lorsque nspawn reçoit lui-même SIGTERM, afin de déclencher un arrêt ordonné du conteneur. Par défaut SIGRTMIN+3 si Boot= est utilisé (sur les systèmes d'initialisation compatibles systemd, SIGRTMIN+3 déclenche un arrêt ordonné). Pour une liste des signaux valides, voir signal(7).

Ajouté dans la version 230.

Personality=

Configure la personnalité du noyau pour le conteneur. Ceci est équivalent à l'option --personality=.

Ajouté dans la version 226.

MachineID=

Configure l'ID machine 128 bits (UUID) à passer au conteneur. Ceci est équivalent à l'option de ligne de commande --uuid=. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 226.

PrivateUsers=

Configure la prise en charge de l'espace de noms d'utilisateurs. Ceci est équivalent à l'option de ligne de commande --private-users=, et prend les mêmes options. Cette option est privilégiée (voir ci-dessus). Cette option est la valeur par défaut si le fichier d'unité modèle systemd-nspawn@.service est utilisé.

Ajouté dans la version 230.

NotifyReady=

Configure la prise en charge des notifications du processus d'initialisation du conteneur. Ceci est équivalent à l'option de ligne de commande --notify-ready=, et prend les mêmes paramètres. Voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge.

Ajouté dans la version 231.

SystemCallFilter=

Configure le filtre des appels système appliqué aux conteneurs. Ceci est équivalent à l'option de ligne de commande --system-call-filter=, et prend le même paramètre de liste. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 235.

LimitCPU=, LimitFSIZE=, LimitDATA=, LimitSTACK=, LimitCORE=, LimitRSS=, LimitNOFILE=, LimitAS=, LimitNPROC=, LimitMEMLOCK=, LimitLOCKS=, LimitSIGPENDING=, LimitMSGQUEUE=, LimitNICE=, LimitRTPRIO=, LimitRTTIME=

Configure divers types de limites de ressources appliquées aux conteneurs. Ceci est équivalent à l'option de ligne de commande --rlimit=, et prend les mêmes arguments. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

OOMScoreAdjust=

Configure la valeur d'ajustement du score OOM. Ceci est équivalent à l'option de ligne de commande --oom-score-adjust=, et prend le même argument. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

CPUAffinity=

Configure l'affinité CPU. Ceci est équivalent à l'option de ligne de commande --cpu-affinity=, et prend le même argument. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

Hostname=

Configure le nom d'hôte du noyau défini pour le conteneur. Ceci est équivalent à l'option de ligne de commande --hostname=, et prend le même argument. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

ResolvConf=

Configure la manière dont /etc/resolv.conf dans le conteneur doit être géré. Ceci est équivalent à l'option de ligne de commande --resolv-conf=, et prend le même argument. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

Timezone=

Configure la manière dont /etc/localtime dans le conteneur doit être géré. Ceci est équivalent à l'option de ligne de commande --timezone=, et prend le même argument. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

LinkJournal=

Configure la manière de lier les journaux de l'hôte et du conteneur. Ceci est équivalent à l'option de ligne de commande --link-journal=, et prend le même paramètre. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 239.

SuppressSync=

Configure s'il faut supprimer la synchronisation sur disque pour la charge utile du conteneur. Ceci est équivalent à l'option de ligne de commande --suppress-sync=, et prend le même paramètre. Voir systemd-nspawn(1) pour plus de détails.

Ajouté dans la version 250.

[FICHIERS] OPTIONS DE SECTION

Les fichiers de configuration peuvent inclure une section [Files], qui contient divers paramètres configurant le système de fichiers du conteneur :

ReadOnly=

Prend un argument booléen, qui est désactivé par défaut. S'il est spécifié, le conteneur sera exécuté avec un système de fichiers en lecture seule. Ce paramètre correspond à l'option de ligne de commande --read-only.

Ajouté dans la version 226.

Volatile=

Prend un argument booléen, ou la valeur spéciale "state". Ceci configure si le conteneur doit être exécuté avec un état et/ou une configuration volatile. Cette option est équivalente à --volatile=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge.

Ajouté dans la version 226.

Bind=, BindReadOnly=

Ajoute un montage par liaison (bind mount) de l'hôte dans le conteneur. Prend un chemin unique, une paire de deux chemins séparés par un deux-points, ou un triplet de deux chemins plus une chaîne d'options séparés par des deux-points. Cette option peut être utilisée plusieurs fois pour configurer plusieurs montages par liaison. Cette option est équivalente aux options de ligne de commande --bind= et --bind-ro=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 226.

BindUser=

Lie un utilisateur de l'hôte dans le conteneur. Cette option est équivalente à l'option de ligne de commande --bind-user=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 249.

BindUserShell=

Lorsqu'elle est utilisée avec BindUser, spécifie le shell qui est inclus dans l'enregistrement utilisateur des utilisateurs liés depuis l'hôte vers le conteneur. Cette option est équivalente à l'option de ligne de commande --bind-user-shell=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 258.

TemporaryFileSystem=

Ajoute un montage "tmpfs" au conteneur. Prend un chemin ou une paire de chemin et chaîne d'options, séparés par un deux-points. Cette option peut être utilisée plusieurs fois pour configurer plusieurs montages "tmpfs". Cette option est équivalente à l'option de ligne de commande --tmpfs=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 226.

Inaccessible=

Masque le fichier ou répertoire spécifié dans le conteneur, en le superposant avec un fichier vide du même type avec le mode d'accès le plus restrictif. Prend un chemin de système de fichiers comme argument. Cette option peut être utilisée plusieurs fois pour masquer plusieurs fichiers ou répertoires. Cette option est équivalente à l'option de ligne de commande --inaccessible=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 242.

Overlay=, OverlayReadOnly=

Ajoute un point de montage de superposition (overlay mount). Prend une liste de chemins séparés par des deux-points. Cette option peut être utilisée plusieurs fois pour configurer plusieurs montages de superposition. Cette option est équivalente aux options de ligne de commande --overlay= et --overlay-ro=, voir systemd-nspawn(1) pour plus de détails sur les options spécifiques prises en charge. Ce paramètre est privilégié (voir ci-dessus).

Ajouté dans la version 233.

PrivateUsersOwnership=

Configure si la propriété des fichiers et répertoires de l'arborescence du conteneur doit être ajustée à la plage UID/GID utilisée, si nécessaire et si l'espace de noms d'utilisateurs est activé. Ceci est équivalent à l'option de ligne de commande --private-users-ownership=. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 249.

[RESEAU] OPTIONS DE SECTION

Les fichiers de configuration peuvent inclure une section [Network], qui contient divers paramètres configurant la connectivité réseau du conteneur :

Private=

Prend un argument booléen, qui est désactivé par défaut. S'il est activé, le conteneur s'exécutera dans son propre espace de noms réseau et ne partagera pas les interfaces réseau et la configuration avec l'hôte. Ce paramètre correspond à l'option de ligne de commande --private-network.

Ajouté dans la version 226.

VirtualEthernet=

Prend un argument booléen. Configure s'il faut créer une connexion Ethernet virtuelle ("veth") entre l'hôte et le conteneur. Ce paramètre implique Private=yes. Ce paramètre correspond à l'option de ligne de commande --network-veth. Cette option est la valeur par défaut si le fichier d'unité modèle systemd-nspawn@.service est utilisé.

Ajouté dans la version 226.

VirtualEthernetExtra=

Prend une paire de noms d'interface séparés par un deux-points. Configure une connexion Ethernet virtuelle supplémentaire ("veth") entre l'hôte et le conteneur. Le premier nom spécifié est le nom de l'interface sur l'hôte, le second le nom de l'interface dans le conteneur. Ce dernier peut être omis, auquel cas il sera défini sur le même nom que l'interface côté hôte. Ce paramètre implique Private=yes. Ce paramètre correspond à l'option de ligne de commande --network-veth-extra=, et peut être utilisé plusieurs fois. Il est indépendant de VirtualEthernet=. Notez que cette option est sans rapport avec le paramètre Bridge= ci-dessous, et donc toute connexion créée de cette manière n'est pas automatiquement ajoutée à un périphérique de pont côté hôte. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 228.

Interface=

Prend une liste d'interfaces séparées par des espaces à ajouter au conteneur. L'objet d'interface est défini soit par un seul nom d'interface, référençant le nom sur l'hôte, soit par une paire séparée par des deux-points of interfaces, auquel cas la première fait référence au nom sur l'hôte et la seconde au nom dans le conteneur. Cette option correspond à l'option de ligne de commande --network-interface= et implique Private=yes. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 226.

MACVLAN=, IPVLAN=

Prend une liste d'interfaces séparées par des espaces pour ajouter des interfaces MACLVAN ou IPVLAN, qui sont ensuite ajoutées au conteneur. L'objet d'interface est défini soit par un seul nom d'interface, faisant référence au nom sur l'hôte, soit par une paire d'interfaces séparées par des deux-points, auquel cas la première fait référence au nom sur l'hôte et la seconde au nom dans le conteneur. Ces options correspondent aux options de ligne de commande --network-macvlan= et --network-ipvlan= et impliquent Private=yes. Ces options sont privilégiées (voir ci-dessus).

Ajouté dans la version 226.

Bridge=

Prend un nom d'interface. Ce réglage implique VirtualEthernet=yes et Private=yes et a pour effet que le côté hôte du lien Ethernet virtuel créé est connecté à l'interface de pont spécifiée. Cette option correspond à l'option de ligne de commande --network-bridge=. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 226.

Zone=

Prend un nom de zone réseau. Ce réglage implique VirtualEthernet=yes et Private=yes et a pour effet que le côté hôte du lien Ethernet virtuel créé est connecté à une interface de pont gérée automatiquement nommée d'après l'argument passé, préfixée par "vz-". Cette option correspond à l'option de ligne de commande --network-zone=. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 230.

Port=

Expose un port TCP ou UDP du conteneur sur l'hôte. Cette option correspond à l'option de ligne de commande --port=, voir systemd-nspawn(1) pour la syntaxe précise de l'argument que cette option prend. Cette option est privilégiée (voir ci-dessus).

Ajouté dans la version 226.
