NOM

systemd.swap - Configuration des unités de swap

SYNOPSIS

swap.swap

DESCRIPTION

Un fichier de configuration d'unité dont le nom se termine par ".swap" encode des informations sur un périphérique ou un fichier de swap pour la pagination de la mémoire contrôlée et supervisée par systemd.

Cette page de manuel liste les options de configuration spécifiques à ce type d'unité. Voir systemd.unit(5) pour les options communes de tous les fichiers de configuration d'unité. Les éléments de configuration communs sont configurés dans les sections génériques [Unit] et [Install]. Les options de configuration spécifiques au swap sont configurées dans la section [Swap].

Des options supplémentaires sont listées dans systemd.exec(5), qui définissent l'environnement d'exécution dans lequel le programme swapon(8) est exécuté, dans systemd.kill(5), qui définissent la manière dont ces processus sont terminés, et dans systemd.resource-control(5), qui configurent les paramètres de contrôle des ressources pour ces processus de l'unité.

Les unités de swap doivent être nommées d'après les périphériques ou fichiers qu'elles contrôlent. Exemple : le périphérique de swap /dev/sda5 doit être configuré dans un fichier d'unité dev-sda5.swap. Pour les détails sur la logique d'échappement utilisée pour convertir un chemin de système de fichiers en nom d'unité, voir systemd.unit(5). Notez que les unités de swap ne peuvent pas être des modèles, ni il est possible d'ajouter plusieurs noms à une unité de swap en créant des liens symboliques supplémentaires vers elle.

Notez que la prise en charge du swap sous Linux est privilégiée, les unités de swap ne sont donc disponibles que dans le gestionnaire de services système (et le gestionnaire de services de l'utilisateur root), mais pas dans le gestionnaire de services des utilisateurs non privilégiés.

DÉPENDANCES AUTOMATIQUES

Dépendances implicites

Les dépendances suivantes sont ajoutées implicitement :

•Toutes les unités de swap obtiennent automatiquement les dépendances Requires= et After= sur les unités de périphériques ou les unités de montage des fichiers à partir desquels elles sont activées.

Des dépendances implicites supplémentaires peuvent être ajoutées en résultat des paramètres d'exécution et de contrôle des ressources, tels que documentés dans systemd.exec(5) et systemd.resource-control(5).

Dépendances par défaut

Les dépendances suivantes sont ajoutées sauf si DefaultDependencies=no est défini :

•Les unités de swap acquièrent automatiquement une dépendance Conflicts= et une dépendance Before= sur umount.target, de sorte qu'elles soient désactivées à l'arrêt, ainsi qu'une dépendance Before=swap.target.

FSTAB

Les unités de swap peuvent être configurées via des fichiers d'unité ou via /etc/fstab (voir fstab(5) pour les détails). Les swaps listés dans /etc/fstab seront convertis dynamiquement en unités natives au démarrage et lors du rechargement de la configuration du gestionnaire système. Voir systemd-fstab-generator(8) pour les détails de la conversion.

Si un périphérique ou fichier de swap est configuré à la fois dans /etc/fstab et dans un fichier d'unité, la configuration de ce dernier a priorité.

Lors de la lecture de /etc/fstab, quelques options spéciales sont comprises par systemd qui influencent la manière dont les dépendances sont créées pour les unités de swap.

noauto, auto

Avec noauto, l'unité de swap ne sera pas ajoutée comme dépendance de swap.target. Cela signifie qu'elle ne sera pas activée automatiquement au démarrage, à moins qu'elle ne soit déclenchée par une autre unité. L'option auto a le sens opposé et est le défaut.

Ajouté dans la version 218.

nofail

Avec nofail, l'unité de swap sera uniquement désirée, pas requise par swap.target. Cela signifie que le démarrage se poursuivra même si ce périphérique de swap n'est pas activé avec succès.

Ajouté dans la version 218.

x-systemd.device-timeout=

Configure le temps pendant lequel systemd attendra qu'un périphérique apparaisse avant d'abandonner une entrée de /etc/fstab. Spécifiez un temps en secondes ou ajoutez explicitement une unité comme "s", "min", "h", "ms".

Notez que cette option ne peut être utilisée que dans /etc/fstab, et sera ignorée lorsqu'elle fait partie du réglage Options= dans un fichier d'unité.

Ajouté dans la version 215.

x-systemd.makefs

La structure de swap sera initialisée sur le périphérique. Si le périphérique n'est pas "vide", c'est-à-dire qu'il contient une signature, l'opération sera ignorée. Il est donc attendu que cette option reste définie même après que le périphérique a été initialisé.

Notez que cette option ne peut être utilisée que dans /etc/fstab, et sera ignorée lorsqu'elle fait partie du réglage Options= dans un fichier d'unité.

Voir systemd-mkswap@.service(8) et la discussion de wipefs(8) dans systemd.mount(5).

Ajouté dans la version 240.

OPTIONS

Les fichiers d'unité de swap peuvent inclure les sections [Unit] et [Install], qui sont décrites dans systemd.unit(5).

Les fichiers d'unité de swap doivent inclure une section [Swap], qui contient des informations sur le périphérique de swap qu'elle supervise. Un certain nombre d'options qui peuvent être utilisées dans cette section sont partagées avec d'autres types d'unités. Ces options sont documentées dans systemd.exec(5), systemd.kill(5) et systemd.resource-control(5). Les options spécifiques à la section [Swap] des unités de swap sont les suivantes :

What=

Prend un chemin absolu ou un identifiant de style fstab d'un nœud de périphérique ou d'un fichier à utiliser pour la pagination. Voir swapon(8) pour les détails. S'il fait référence à un nœud de périphérique, une dépendance sur l'unité de périphérique respective est créée automatiquement. (Voir systemd.device(5) pour plus d'informations.) S'il fait référence à un fichier, une dépendance sur l'unité de montage respective est créée automatiquement. (Voir systemd.mount(5) pour plus d'informations.) Cette option est obligatoire. Notez que l'expansion habituelle des spécificateurs est appliquée à ce paramètre, les caractères pour cent littéraux doivent donc être écrits comme "%%".

Priority=

Priorité de swap à utiliser lors de l'activation du périphérique ou du fichier de swap. Prend un entier. Ce paramètre est optionnel et ignoré lorsque la priorité est définie par pri= dans la clé Options=.

Options=

Peut contenir une chaîne d'options pour le périphérique de swap. Ceci peut être utilisé pour contrôler les options de décharge (discard) entre autres fonctionnalités, si le périphérique de support de swap prend en charge l'opération de décharge ou trim. (Voir swapon(8) pour plus d'informations.) Notez que l'expansion habituelle des spécificateurs est appliquée à ce paramètre, les caractères pour cent littéraux doivent donc être écrits comme "%%".

Ajouté dans la version 217.

TimeoutSec=

Configure le temps d'attente pour que la commande swapon se termine. Si une commande ne se termine pas dans le temps configuré, le swap sera considéré comme défaillant et sera à nouveau arrêté. Toutes les commandes encore en cours seront terminées de force via SIGTERM, et après un autre délai de ce temps avec SIGKILL. (Voir KillMode= dans systemd.kill(5).) Prend une valeur sans unité en secondes, ou une valeur de durée comme "5min 20s". Passez "0" pour désactiver la logique de délai d'attente. Par défaut, il utilise DefaultTimeoutStartSec= du fichier de configuration du gestionnaire (voir systemd-system.conf(5)).

Consultez systemd.unit(5), systemd.exec(5), et systemd.kill(5) pour plus de réglages.
