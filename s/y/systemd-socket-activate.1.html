NOM

systemd-socket-activate - Tester l'activation de socket pour les démons

SYNTAXE

systemd-socket-activate [OPTIONS...] COMMANDE [ARGUMENTS...]

DESCRIPTION

systemd-socket-activate peut être utilisé pour lancer un programme de service activé par socket depuis la ligne de commande à des fins de test. Il peut également être utilisé pour lancer des instances individuelles du programme de service par connexion.

Le démon à lancer et ses options doivent être spécifiés après les options destinées à systemd-socket-activate.

Si l'option --inetd est donnée, le descripteur de fichier de socket sera utilisé comme entrée et sortie standard du processus lancé. Sinon, l'entrée et la sortie standard seront héritées, et les sockets seront passés via les descripteurs de fichiers 3 et supérieurs. Les sockets passés via $LISTEN_FDS à systemd-socket-activate seront transmis au démon, dans leurs positions d'origine. Les autres sockets spécifiés avec --listen= utiliseront des descripteurs consécutifs. Par défaut, systemd-socket-activate écoute sur un socket de flux, utilisez --datagram et --seqpacket pour écouter sur des sockets de datagramme ou de paquet séquentiel à la place (voir ci-dessous).

OPTIONS

-l adresse, --listen=adresse

Écoute sur cette adresse. Prend une chaîne comme "2000" ou "127.0.0.1:2001".

Ajouté dans la version 230.

-a, --accept

Lance une instance du programme de service pour chaque connexion et passe le socket de connexion. Ne peut pas être combiné avec --now.

Ajouté dans la version 230.

-d, --datagram

Écoute sur un socket de datagramme (SOCK_DGRAM), au lieu d'un socket de flux (SOCK_STREAM). Ne peut pas être combiné avec --seqpacket.

Ajouté dans la version 230.

--seqpacket

Écoute sur un socket de paquet séquentiel (SOCK_SEQPACKET), au lieu d'un socket de flux (SOCK_STREAM). Ne peut pas être combiné avec --datagram.

Ajouté dans la version 230.

--inetd

Utilise le protocole inetd pour passer les descripteurs de fichiers, c'est-à-dire comme entrée et sortie standard, au lieu du protocole de nouveau style pour passer les descripteurs de fichiers en utilisant $LISTEN_FDS (voir ci-dessus).

Ajouté dans la version 230.

-E VAR[=VALEUR], --setenv=VAR[=VALEUR]

Ajoute cette variable à l'environnement du processus lancé. Si VAR est suivi de "=", suppose qu'il s'agit d'une paire variable–valeur. Sinon, la valeur est obtenue à partir de l'environnement de systemd-socket-activate lui-même.

Ajouté dans la version 230.

--fdname=NOM[:NOM...]

Spécifie des noms pour les descripteurs de fichiers passés. Ceci est équivalent à définir FileDescriptorName= dans les fichiers d'unité de socket, et permet l'utilisation de sd_listen_fds_with_names(3). Plusieurs entrées peuvent être spécifiées en utilisant des options séparées ou en séparant les noms par des deux-points (":") dans une seule option. Si plus de noms sont donnés que de descripteurs, les noms superflus seront ignorés. Si moins de noms sont donnés que de descripteurs, les descripteurs de fichiers restants seront sans nom.

Ajouté dans la version 230.

--now

Démarre le programme de service instantanément, au lieu d'attendre une connexion sur le(s) socket(s). Ne peut pas être combiné avec --accept.

Ajouté dans la version 258.

-h, --help

Affiche un court texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

VARIABLES D'ENVIRONNEMENT

$LISTEN_FDS, $LISTEN_PID, $LISTEN_FDNAMES

Voir sd_listen_fds(3).

Ajouté dans la version 230.

$SYSTEMD_LOG_TARGET, $SYSTEMD_LOG_LEVEL, $SYSTEMD_LOG_TIME, $SYSTEMD_LOG_COLOR, $SYSTEMD_LOG_LOCATION

Identique à celles de systemd(1).

Ajouté dans la version 230.

EXEMPLES

Exemple 1. Lancer un serveur echo sur le port 2000

$ systemd-socket-activate -l 2000 --inetd -a cat

Exemple 2. Lancer une instance activée par socket de systemd-journal-gatewayd(8)

$ systemd-socket-activate -l 19531 /usr/lib/systemd/systemd-journal-gatewayd
