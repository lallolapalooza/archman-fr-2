SYSTEMD-FACTORY-RESET(8) systemd-factory-reset SYSTEMD-FACTORY-RESET(8)

NOM

systemd-factory-reset, systemd-factory-reset-request.service, systemd-factory-reset-complete.service, systemd-factory-reset.socket, systemd-factory-reset@.service - Demander ou compléter une opération de réinitialisation d'usine, ou interroger le mode de réinitialisation d'usine actuel

SYNOPSIS

/usr/lib/systemd/systemd-factory-reset

systemd-factory-reset-request.service

systemd-factory-reset-complete.service

systemd-factory-reset.socket

systemd-factory-reset@.service

DESCRIPTION

systemd-factory-reset est un outil qui peut interroger l'état actuel de la réinitialisation d'usine, demander des opérations de réinitialisation d'usine ou les compléter.

Certaines fonctionnalités sont également disponibles via le service Varlink /run/systemd/io.systemd.FactoryReset (implémenté via les unités systemd-factory-reset.socket/systemd-factory-reset@.service).

Voir Factory Reset[1] pour un aperçu de la logique de réinitialisation d'usine.

COMMANDES

L'exécutable /usr/lib/systemd/systemd-factory-reset peut également être invoqué depuis la ligne de commande, en prenant l'un des arguments de commande suivants :

status

Rapporte l'état actuel de la réinitialisation d'usine. Rapporte l'un des états suivants : "unsupported" (si le système d'exploitation ne prend pas en charge la logique de réinitialisation d'usine), "unspecified" (si aucune réinitialisation d'usine n'a été demandée, mais qu'elle n'a pas non plus été désactivée explicitement), "off" (si la logique de réinitialisation d'usine a été explicitement désactivée via l'option de ligne de commande du noyau), "on" (si la réinitialisation d'usine est actuellement activée et exécutée), "complete" (si la logique de réinitialisation d'usine s'est exécutée pendant le démarrage actuel mais est terminée maintenant), "pending" (si une réinitialisation d'usine a été demandée pour le prochain démarrage).

Retourne avec un code de sortie de 0 si le mécanisme de réinitialisation d'usine n'est actuellement pas actif, 10 si une réinitialisation d'usine est en cours d'exécution, ou 11 si elle est en attente pour le prochain démarrage.

Ajouté dans la version 258.

request

Demande l'exécution d'une opération de réinitialisation d'usine au prochain démarrage.

Notez qu'il s'agit d'une opération relativement bas niveau. L'interface principale pour demander une opération de réinitialisation d'usine est de démarrer l'unité factory-reset.target.

Ceci définit la variable EFI FactoryResetRequest, voir ci-dessous.

Cette opération est exécutée lorsque l'unité systemd-factory-reset-request.service est démarrée (ce qui est généralement l'un des services accrochés et ordonnancés avant factory-reset.target).

Ajouté dans la version 258.

cancel

Annule toute opération de réinitialisation d'usine précédemment demandée (mais non encore exécutée).

Ajouté dans la version 258.

complete

Marque une opération de réinitialisation d'usine en cours comme terminée.

Cette opération est exécutée lorsque l'unité systemd-factory-reset-complete.service est démarrée (ce qui est généralement l'un des services accrochés et ordonnancés après factory-reset-now.target).

Ajouté dans la version 258.

OPTIONS

Les options suivantes sont comprises :

--retrigger

Lorsqu'utilisé avec la commande complete, re-déclenche tous les périphériques blocs, ce qui pourrait permettre l'utilisation de périphériques découverts automatiquement qui n'étaient pas utilisables auparavant parce que la logique de réinitialisation d'usine était en place.

Ajouté dans la version 258.

--quiet, -q

Supprime la sortie de l'état de status, mais définit toujours le code de sortie comme documenté.

Ajouté dans la version 258.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

VARIABLES EFI

La variable EFI suivante est définie et lue par systemd-factory-reset, sous l'UUID du vendeur "8cf2644b-4b0b-428f-9387-6d876050dc67", pour la communication entre ce démarrage et le prochain.

FactoryResetRequest

Défini chaque fois qu'une réinitialisation d'usine est demandée pour le prochain démarrage, supprimé une fois la réinitialisation d'usine terminée. Contient des données JSON décrivant le système d'exploitation demandeur, afin d'éviter toute confusion dans les systèmes multi-amorçages.

Ajouté dans la version 258.
