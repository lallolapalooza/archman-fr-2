NOM

systemd-keyutil - Effectue diverses opérations sur les clés privées et les certificats X.509

SYNTAXE

systemd-keyutil [OPTIONS...] {COMMANDE}

DESCRIPTION

systemd-keyutil peut être utilisé pour effectuer diverses opérations sur les clés privées et les certificats X.509.

COMMANDES

validate

Vérifie que nous pouvons charger la clé privée et le certificat spécifiés respectivement avec --private-key= et --certificate=.

En tant qu'effet secondaire, si la clé privée est chargée à partir d'un jeton matériel protégé par code PIN, cette commande peut être utilisée pour mettre en cache le code PIN dans la keyring du noyau. Les variables d'environnement $SYSTEMD_ASK_PASSWORD_KEYRING_TIMEOUT_SEC et $SYSTEMD_ASK_PASSWORD_KEYRING_TYPE peuvent être utilisées pour contrôler combien de temps et dans quelle keyring du noyau le code PIN est mis en cache.

Ajouté dans la version 257.

public

Cette commande imprime la clé publique au format PEM extraite soit du certificat fourni avec --certificate=, soit de la clé privée fournie avec --private-key=.

Ajouté dans la version 257.

pkcs7

Cette commande intègre la signature PKCS#1 (RSA) fournie avec --signature= dans une signature PKCS#7 en utilisant le certificat fourni avec --certificate= et l'écrit dans le fichier spécifié avec --output= au format PKCS#7 (p7s). Si --content= est fourni, il est inclus dans le p7s, sinon une signature « détachée » est créée. L'option --hash-algorithm=, qui par défaut est "SHA256", spécifie quel algorithme de hachage a été utilisé pour générer la signature.

Ajouté dans la version 258.

OPTIONS

Les options suivantes sont comprises :

--private-key=CHEMIN/URI, --private-key-source=TYPE[:NOM], --certificate=CHEMIN, --certificate-source=TYPE[:NOM]

Définit la clé privée et le certificat à utiliser. L'option --certificate= prend un chemin vers un certificat X.509 encodé en PEM ou une URI qui est passée au fournisseur OpenSSL configuré avec --certificate-source. --certificate-source prend l'une des valeurs « file » ou « provider », cette dernière étant suivie d'un identifiant de fournisseur spécifique, séparé par deux-points, par exemple « provider:pkcs11 ». L'option --private-key= peut prendre un chemin ou une URI qui sera passée au moteur ou fournisseur OpenSSL, tel que spécifié par --private-key-source= comme un tuple « type:nom », tel que « engine:pkcs11 ».

Ajouté dans la version 257.

--signature=CHEMIN

Signature PKCS#1 en entrée pour la commande pkcs7.

Ajouté dans la version 258.

--content=CHEMIN

Données en entrée correspondant à la signature PKCS#1 pour la commande pkcs7, utilisées pour générer des signatures PKCS#7 en ligne (c'est-à-dire non « détachées »).

Ajouté dans la version 258.

--hash-algorithm=ALGORITHME

Algorithme de hachage utilisé pour générer la signature PKCS#1 pour la commande pkcs7. Il doit s'agir d'un algorithme de digest OpenSSL valide ; utilisez « openssl list -digest-algorithms » pour voir une liste des algorithmes valides sur votre système. Par défaut : "SHA256".

Ajouté dans la version 258.

--output=CHEMIN

Signature PKCS#7 en sortie pour la commande pkcs7.

Ajouté dans la version 258.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.
