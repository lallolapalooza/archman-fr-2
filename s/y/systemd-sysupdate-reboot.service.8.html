NOM

systemd-sysupdate, systemd-sysupdate.service, systemd-sysupdate.timer, systemd-sysupdate-reboot.service, systemd-sysupdate-reboot.timer - Mise à jour automatique de l'OS ou d'autres ressources

SYNTAXE

systemd-sysupdate [OPTIONS...]

systemd-sysupdate.service

DESCRIPTION

systemd-sysupdate met à jour de manière atomique le système d'exploitation de l'hôte, les images de conteneurs, les images de services portables ou d'autres sources, en se basant sur les fichiers de configuration de transfert décrits dans sysupdate.d(5).

Cet outil implémente des schémas de mise à jour basés sur des fichiers, des répertoires ou des partitions, prenant en charge plusieurs versions installées simultanément de ressources spécifiques dans un style A/B (ou même A/B/C, A/B/C/D/...). La mise à jour A/B signifie que lorsqu'une version d'une ressource est actuellement utilisée, la version suivante peut être téléchargée, décompressée et préparée dans un emplacement entièrement séparé, indépendamment de la première, et — une fois terminée — être activée, échangeant les rôles de sorte qu'elle devienne celle utilisée et que celle précédemment utilisée devienne celle qui sera remplacée par la prochaine mise à jour, et ainsi de suite. Les ressources à mettre à jour sont définies dans des fichiers de transfert, un pour chaque ressource à mettre à jour. Par exemple, les ressources qui peuvent être mises à jour avec cet outil pourraient être : une partition du système de fichiers racine, une partition Verity correspondante plus une image de noyau. La combinaison des trois serait considérée comme une mise à jour complète du système d'exploitation.

L'outil met à jour les partitions, les fichiers ou les arborescences de répertoires toujours dans leur intégralité, et fonctionne avec au moins deux versions de chacune de ces ressources : la version *actuelle*, plus la version *suivante* : celle vers laquelle la mise à jour est en cours, et qui est initialement incomplète car les données téléchargées y sont écrites ; plus éventuellement d'autres versions. Une fois le téléchargement d'une nouvelle version terminé, elle devient la version actuelle, libérant la version précédemment considérée comme actuelle pour suppression/remplacement/mise à jour.

Lors de l'installation de nouvelles versions, l'outil téléchargera, décompressera et écrira directement la nouvelle version dans la destination. Ceci est fait de manière robuste de sorte qu'un téléchargement incomplet puisse être reconnu lors de la prochaine invocation, et évacué avant qu'une nouvelle tentative ne soit initiée.

Notez que lors de l'écriture des mises à jour sur une partition, la partition doit déjà exister, car systemd-sysupdate ne créera pas automatiquement de nouvelles partitions. Utilisez un outil tel que systemd-repart(8) pour créer automatiquement des partitions supplémentaires à utiliser avec systemd-sysupdate au démarrage.

L'outil peut être utilisé sur le système d'exploitation en cours d'exécution, pour mettre à jour le système d'exploitation dans un état "en ligne" à partir de lui-même, et sur des images disque "hors ligne", pour les mettre à jour de l'extérieur en se basant sur les fichiers de transfert intégrés aux images disque. Pour ces derniers, voir --image= ci-dessous. Ces derniers sont particulièrement intéressants pour mettre à jour des images de conteneurs ou des images de services portables.

Le service système systemd-sysupdate.service mettra automatiquement à jour le système d'exploitation de l'hôte en se basant sur les fichiers de transfert installés. Il est déclenché à intervalles réguliers via systemd-sysupdate.timer. Le systemd-sysupdate-reboot.service redémarrera automatiquement le système après l'installation d'une nouvelle version. Il est déclenché via systemd-sysupdate-reboot.timer. Les deux services sont séparés l'un de l'autre car il est généralement conseillé de télécharger les mises à jour régulièrement pendant que le système est en fonctionnement, mais de retarder les redémarrages jusqu'au moment approprié (c'est-à-dire généralement la nuit). Les deux ensembles d'unités de service/minuterie peuvent être activés séparément.

Pour plus de détails sur les fichiers de transfert et les exemples, voir sysupdate.d(5).

COMMANDE

Les commandes suivantes sont comprises :

list [VERSION]

Si invoquée sans argument, énumère les versions téléchargeables et installées, et affiche un tableau récapitulatif avec les versions découvertes et leurs propriétés, y compris s'il existe une version candidate plus récente à mettre à jour. Si un argument de version est spécifié, affiche des détails sur la version spécifique, y compris les fichiers individuels qui doivent être transférés pour acquérir la version.

Si aucune commande n'est explicitement spécifiée, cette commande est implicite.

Ajouté dans la version 251.

features [FEATURE]

Si invoquée sans argument, énumère les fonctionnalités optionnelles et affiche un tableau récapitulatif, indiquant quelles fonctionnalités sont activées ou désactivées. Si un argument de fonctionnalité est spécifié, affiche des détails sur la fonctionnalité spécifique, y compris les transferts contrôlés par la fonctionnalité.

Ajouté dans la version 257.

check-new

Vérifie si une nouvelle version est disponible. Ceci énumère en interne les versions téléchargeables et installées et renvoie le code de sortie 0 s'il existe une nouvelle version à mettre à jour, un code non nul sinon. S'il existe une nouvelle version à mettre à jour, son identifiant de version est écrit sur la sortie standard.

Ajouté dans la version 251.

update [VERSION]

Installe (met à jour vers) la version spécifiée, ou si aucune n'est spécifiée, met à jour vers la version la plus récente disponible. Si la version est déjà installée ou si aucune version plus récente n'est disponible, aucune opération n'est exécutée.

Si une nouvelle version à installer/mettre à jour est trouvée, les anciennes versions installées sont supprimées jusqu'à ce qu'au moins une nouvelle version puisse être installée, conformément à la configuration via InstanceMax= dans sysupdate.d(5), ou via les emplacements de partition disponibles du bon type. Cette opération implicite peut également être invoquée explicitement via la commande vacuum décrite ci-dessous.

Ajouté dans la version 251.

vacuum

Supprime les anciennes versions installées jusqu'à ce que les limites configurées via InstanceMax= dans sysupdate.d(5) soient à nouveau atteintes. Normalement, il ne devrait pas être nécessaire d'invoquer cette commande explicitement, car elle est invoquée implicitement chaque fois qu'une nouvelle mise à jour est initiée.

Ajouté dans la version 251.

pending

Vérifie si une version plus récente de l'OS est installée que celle actuellement en cours d'exécution. Renvoie zéro si c'est le cas, un code non nul sinon. Ceci compare l'identifiant de la version installée la plus récente avec la version de l'image du système d'exploitation telle que rapportée par le champ IMAGE_VERSION= dans /etc/os-release. Si le premier est plus récent que le second, une mise à jour a apparemment été terminée mais pas encore activée (c'est-à-dire redémarrée).

Ajouté dans la version 251.

reboot

Similaire à la commande pending mais redémarre immédiatement si une version plus récente de l'OS a été installée que celle actuellement en cours d'exécution. Cette opération peut être effectuée implicitement avec la commande update, après une mise à jour terminée via le commutateur --reboot, voir ci-dessous. Cette commande n'exécutera aucune opération (et retournera succès) si aucune mise à jour n'a été installée, et donc si le système n'a pas redémarré.

Ajouté dans la version 251.

components

Liste les composants qui peuvent être mis à jour. Ceci énumère les répertoires /etc/sysupdate.*.d/, /run/sysupdate.*.d/ et /usr/lib/sysupdate.*.d/ qui contiennent des fichiers de transfert. Cette commande est utile pour lister les paramètres possibles pour --component= (voir ci-dessous).

Ajouté dans la version 251.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

OPTIONS

Les options suivantes sont comprises :

--component=, -C

Sélectionne le composant à mettre à jour. Prend un nom de composant comme argument. Cela a pour effet de modifier légèrement la logique de recherche des fichiers de transfert. Si ce commutateur n'est pas utilisé, les fichiers de transfert sont chargés à partir de /etc/sysupdate.d/*.conf, /run/sysupdate.d/*.conf et /usr/lib/sysupdate.d/*.conf. Si ce commutateur est utilisé, le nom du composant spécifié est utilisé pour modifier les répertoires à rechercher pour être /etc/sysupdate.component.d/*.conf, /run/sysupdate.component.d/*.conf et /usr/lib/sysupdate.component.d/*.conf, chaque fois avec la chaîne component remplacée par le nom du composant spécifié.

Utilisez la commande components pour lister les composants disponibles à mettre à jour. Ceci énumère les répertoires correspondant à cette règle de nommage.

Les composants peuvent être utilisés pour définir un ensemble séparé de fichiers de transfert pour différents composants du système d'exploitation qui doivent être mis à jour séparément. N'utilisez pas ce concept pour les ressources qui doivent toujours être mises à jour conjointement

ther dans un synchrones. Définissez simplement plusieurs fichiers de transfert dans le même répertoire sysupdate.d/ pour ces cas.

Cette option ne peut pas être combinée avec --definitions=.

Ajouté dans la version 251.

--definitions=

Un chemin vers un répertoire. Si spécifié, les fichiers de transfert *.conf sont lus depuis ce répertoire au lieu de /usr/lib/sysupdate.d/*.conf, /etc/sysupdate.d/*.conf et /run/sysupdate.d/*.conf.

Cette option ne peut pas être combinée avec --component=.

Ajouté dans la version 251.

--root=

Prend un chemin vers un répertoire à utiliser comme système de fichiers racine lors de la recherche des fichiers sysupdate.d/*.conf.

Ajouté dans la version 251.

--image=

Prend un chemin vers un fichier image disque ou un périphérique à monter et à utiliser de manière similaire à --root=, voir ci-dessus. Si ceci est utilisé et que les ressources de partition sont mises à jour, cela se fait à l'intérieur de l'image disque spécifiée.

Ajouté dans la version 251.

--image-policy=politique

Prend une chaîne de politique d'image comme argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si non spécifié, utilise par défaut la politique "*", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--instances-max=, -m

Prend un entier décimal supérieur ou égal à 2 lors de la mise à jour ou à 1 lors du nettoyage. Contrôle combien de versions garder à tout moment. Cette option peut également être configurée dans les fichiers de transfert, via le paramètre InstancesMax=, voir sysupdate.d(5) pour les détails.

Ajouté dans la version 251.

--sync=

Prend un argument booléen, par défaut oui. Ceci peut être utilisé pour spécifier si les nouvelles versions de ressources mises à jour doivent être synchronisées sur le disque lorsque approprié (c'est-à-dire après la fin du téléchargement, avant sa finalisation, et à nouveau après la finalisation). Ceci ne devrait pas être désactivé, sauf pour améliorer les performances d'exécution dans des environnements de test.

Ajouté dans la version 251.

--verify=

Prend un argument booléen, par défaut oui. Contrôle si les téléchargements doivent être vérifiés cryptographiquement. Ne désactivez pas cette option, sauf dans les environnements de test.

Ajouté dans la version 251.

--reboot

Lorsqu'il est utilisé en combinaison avec la commande update et qu'une nouvelle version est installée, redémarre automatiquement le système immédiatement après.

Ajouté dans la version 251.

--offline

Empêche la récupération des métadonnées depuis le réseau (c'est-à-dire SHA256SUMS). Ceci est particulièrement utile lorsqu'il est utilisé en combinaison avec la commande list, pour interroger les versions installées localement.

Ajouté dans la version 257.

--transfer-source=

Prend un chemin comme argument. Lorsqu'il est spécifié, toutes les sources de transfert configurées avec PathRelativeTo=explicit seront interprétées relativement au chemin spécifié.

Ajouté dans la version 257.

--no-pager

Ne pas rediriger la sortie vers un paginator.

--no-legend

Ne pas imprimer la légende, c'est-à-dire les en-têtes de colonne et le pied de page avec des indices.

--json=MODE

Affiche la sortie au format JSON. Attend l'une des valeurs "short" (pour une sortie la plus courte possible sans espaces blancs redondants ni sauts de ligne), "pretty" (pour une version joliment formatée de la même sortie, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
