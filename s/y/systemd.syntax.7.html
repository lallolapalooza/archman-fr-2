NOM

systemd.syntax - Syntaxe générale des fichiers de configuration systemd

INTRODUCTION

Cette page décrit les principes de base des fichiers de configuration utilisés par systemd(1) et les programmes associés pour :

•les fichiers d'unité systemd, voir systemd.unit(5), systemd.service(5), systemd.socket(5), systemd.device(5), systemd.mount(5), systemd.automount(5), systemd.swap(5), systemd.target(5), systemd.path(5), systemd.timer(5), systemd.slice(5), systemd.scope(5)
•les fichiers link, voir systemd.link(5)
•les fichiers netdev et network, voir systemd.netdev(5), systemd.network(5)
•les fichiers de configuration du démon, voir systemd-system.conf(5), systemd-user.conf(5), logind.conf(5), journald.conf(5), journal-remote.conf(5), journal-upload.conf(5), systemd-sleep.conf(5), timesyncd.conf(5)
•les fichiers nspawn, voir systemd.nspawn(5)

La syntaxe s'inspire des fichiers .desktop de la XDG Desktop Entry Specification[1] , qui sont eux-mêmes inspirés par les fichiers .ini de Microsoft Windows.

Chaque fichier est un fichier texte brut divisé en sections, avec des entrées de configuration du style clé=valeur. Les espaces immédiatement avant ou après le "=" sont ignorés. Les lignes vides et les lignes commençant par "#" ou ";" sont ignorées, ce qui peut être utilisé pour les commentaires.

Les lignes se terminant par une barre oblique inverse sont concaténées avec la ligne suivante lors de la lecture et la barre oblique inverse est remplacée par un espace. Ceci peut être utilisé pour envelopper de longues lignes. La limite de longueur de ligne est très grande (actuellement 1 Mo), mais il est recommandé d'éviter de telles lignes longues et d'utiliser plusieurs directives, la substitution de variables ou d'autres mécanismes appropriés pour le type de fichier donné. Lorsqu'une ligne de commentaire ou des lignes suivent une ligne se terminant par une barre oblique inverse, le bloc de commentaires est ignoré, de sorte que la ligne continuée est concaténée avec ce qui suit le bloc de commentaires.

[Section A]
CleUn=valeur 1
CleDeux=valeur 2
# un commentaire
[Section B]
Parametre="quelque chose" "quelque chose" "..."
CleDeux=valeur 2 \
       valeur 2 continuée
[Section C]
CleTrois=valeur 3\
# cette ligne est ignorée
; cette ligne est ignorée aussi
       valeur 3 continuée

Les arguments booléens utilisés dans les fichiers de configuration peuvent être écrits dans divers formats. Pour les paramètres positifs, les chaînes 1, yes, true et on sont équivalentes. Pour les paramètres négatifs, les chaînes 0, no, false et off sont équivalentes.

Les valeurs de durée codées dans les fichiers de configuration peuvent être écrites dans divers formats. Un nombre autonome spécifie un temps en secondes. S'il est suffixé par une unité de temps, l'unité est respectée. Une concaténation de plusieurs valeurs avec des unités est supportée, auquel cas les valeurs sont additionnées. Exemple : "50" fait référence à 50 secondes ; "2min 200ms" fait référence à 2 minutes et 200 millisecondes, soit 120200 ms. Les unités de temps suivantes sont comprises : "s", "min", "h", "d", "w", "ms", "us". Pour plus de détails, voir systemd.time(7).

Divers paramètres sont autorisés à être spécifiés plusieurs fois, auquel cas l'interprétation dépend du paramètre. Souvent, plusieurs paramètres forment une liste, et la définition à une valeur vide "réinitialise", ce qui signifie que les affectations précédentes sont ignorées. Lorsque cela est autorisé, c'est mentionné dans la description du paramètre. Notez que l'utilisation de plusieurs affectations à la même valeur rend le fichier incompatible avec les analyseurs du format de fichier .desktop XDG.

GUILLEMETS

Pour les paramètres où les guillemets sont autorisés, les règles générales suivantes s'appliquent : les guillemets doubles ("...") et les guillemets simples ('...') peuvent être utilisés pour encapsuler un élément entier (le guillemet ouvrant ne peut apparaître qu'au début ou après un espace qui n'est pas cité, et le guillemet fermant doit être suivi d'un espace ou de la fin de ligne), auquel cas tout jusqu'au prochain guillemet correspondant fait partie du même élément. Les guillemets eux-mêmes sont supprimés. Les échappements de style C sont supportés. Le tableau ci-dessous contient la liste des séquences d'échappement connues. Seules les séquences d'échappement qui correspondent à la syntaxe du tableau sont autorisées ; d'autres modèles peuvent être ajoutés à l'avenir et les modèles inconnus entraîneront un avertissement. En particulier, toute barre oblique inverse devrait être doublée. Enfin, une barre oblique inverse finale ("\") peut être utilisée pour fusionner les lignes, comme décrit ci-dessus. L'UTF-8 est accepté, et donc les caractères unicode typiques n'ont pas besoin d'être échappés.

Tableau 1. Échappements supportés

Littéral Valeur réelle
"\a" bell (sonnerie)
"\b" backspace (retour arrière)
"\f" form feed (saute-page)
"\n" newline (nouvelle ligne)
"\r" carriage return (retour chariot)
"\t" tab (tabulation)
"\v" vertical tab (tabulation verticale)
"\\" backslash (barre oblique inverse)
"\"" double quotation mark (guillemet double)
"\'" single quotation mark (guillemet simple)
"\s" space (espace)
"\xxx" caractère numéro xx en encodage hexadécimal
"\nnn" caractère numéro nnn en encodage octal
"\unnnn" point de code unicode nnnn en encodage hexadécimal
"\Unnnnnnnn" point de code unicode nnnnnnnn en encodage hexadécimal
