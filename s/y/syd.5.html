NOM

syd - Format de document pour écrire des profils Syd

API

La version actuelle de l'API de commande Syd est la 3. Cette version est stable.

CONFIGURATION

Syd est configuré via des commandes de bac à sable. Pour plusieurs règles correspondantes (par exemple, deux règles correspondant au même chemin), la dernière règle correspondante l'emporte. Il existe deux façons de fournir des commandes de bac à sable. Premièrement, Syd peut être configuré à l'aide d'un fichier de configuration. Le chemin vers le fichier de configuration est spécifié à l'aide du commutateur de ligne de commande -P. Plus d'un fichier de configuration peut être spécifié de cette manière. Des commandes individuelles peuvent également être transmises via le commutateur de ligne de commande -m. Les profils de configuration peuvent être appliqués en utilisant le commutateur de ligne de commande -p. Voir la section PROFILES pour plus d'informations. Deuxièmement, Syd peut être configuré en utilisant des appels magiques stat(2) pendant l'exécution. Ceci est réalisé en appelant l'appel système stat(2) sur le chemin spécial /dev/syd suivi de la commande de bac à sable. La configuration d'exécution n'est possible que si le verrouillage du bac à sable est désactivé. L'appel système stat(2) a été choisi car il est pratique à invoquer en utilisant des commandes shell intégrées comme :

; test -c /dev/syd/sandbox/read:on

ce qui active le bac à sable en lecture pour un shell s'exécutant sous Syd. Il est également possible de demander certaines valeurs en utilisant la valeur de retour de l'appel stat(2) :

test -c /dev/syd/sandbox/read? && echo read sandboxing on || echo read sandboxing off

Certains de ces intégrés shell peuvent en fait appeler d'autres appels système tels que fstat(2), lstat(2), newfstatat(2), ou statx(2). Syd prend en charge la même interface à travers tous ces appels système de manière transparente. Vérifiez la page man syd(2) pour une description de l'interface stat(2).

NOMMAGE

La nomenclature des fichiers de configuration de Syd suit un schéma qui permet d'extraire la version de l'API de commande du nom de fichier. Un fichier de configuration Syd doit avoir l'extension syd- suivie de la version de l'API (par exemple, "syd-3" pour la version de l'API 3).

SYNTAXE

Les fichiers d'entrée doivent utiliser l'encodage UTF-8. Le format de configuration est orienté ligne. Les commentaires commencent par "#". Les commentaires en ligne ne sont pas supportés. Les lignes vides sont ignorées. Toutes les autres lignes sont traitées comme si elles étaient fournies à Syd via le commutateur de ligne de commande -m. Pour une liste des commandes de bac à sable disponibles, consultez syd(2). Pour un fichier de syntaxe VIM pour les profils Syd, consultez ici : https://gitlab.exherbo.org/sydbox/sydbox/-/tree/main/vim

Depuis la version 3.15.1, Syd ajoute deux fonctionnalités supplémentaires au parsing des fichiers de configuration :

  • L'expansion des variables d'environnement est effectuée sur les arguments. Par défaut, le crate shellexpand est utilisé pour effectuer l'expansion et un délai d'attente peut être défini en utilisant config/expand pour effectuer l'expansion en utilisant wordexp(3) à la place. Notamment, les variables d'environnement non définies ne sont pas développées en chaînes vides. En cas d'erreurs de recherche de variables d'environnement et d'erreurs de décodage UTF-8, Syd arrête le parsing et se termine avec une erreur. Ceci est fait pour la sécurité car une expansion involontaire en chaîne vide peut potentiellement entraîner une règle de bac à sable autorisant des chemins involontaires sans que l'utilisateur ne s'en aperçoive facilement. Il est recommandé à l'utilisateur de définir des valeurs par défaut pour les variables d'environnement en utilisant la notation familière ${HOME:-/var/empty}. Si vous voulez vraiment une expansion en chaîne vide pour les variables d'environnement non définies, vous pouvez obtenir cet effet en utilisant la notation ${HOME:-} mais ce n'est pas recommandé et doit être utilisé avec précaution.
  • Les directives include peuvent être utilisées pour demander l'inclusion d'un autre fichier de configuration. Lors de la lecture d'une ligne d'inclusion, Syd arrête de parser le fichier actuel, valide le chemin d'inclusion donné et commence à parser le nouveau fichier de configuration. Le fichier ne doit pas être accessible en écriture par le groupe ou par d'autres pour des raisons de sécurité. Pour les fichiers d'inclusion avec des chemins relatifs, Syd recherche le fichier sous le répertoire du fichier de configuration précédent plutôt que sous le répertoire de travail actuel pour la sécurité et la facilité de configuration. Les boucles dans les directives d'inclusion sont détectées en mettant en cache l'identifiant du périphérique et l'inode des fichiers de configuration. Notez que cette directive n'est pas autorisée lors du chargement de la configuration à partir d'un descripteur de fichier en utilisant la commande load.

Depuis la version 3.17.6, Syd ajoute la directive include_profile qui peut être utilisée pour inclure un profil Syd. Voir syd-cat -plist pour la liste des profils.

PROFILES

Syd a un certain nombre de profils prédéfinis pour faciliter la configuration. Ces profils peuvent être utilisés seuls ou empilés avec d'autres profils et configurations personnalisées pour créer divers niveaux d'isolation et de confinement. Pour voir la liste complète des profils, utilisez syd-cat -plist. Pour lister les règles d'un profil, utilisez syd-cat -p<nom-du-profil>. Vous trouverez ci-dessous une brève liste des profils courants et leur fonctionnalité :

Empilage des profils

Il est possible d'empiler plusieurs profils pour configurer une sandbox plus restreinte. N'oubliez pas que l'ordre d'empilage des profils est important, la dernière règle correspondante l'emporte. Voici quelques exemples :

  • syd -puser -pimmutable -mroot:/mnt/gnu ...
  • syd -ppaludis -plandlock -mallow/lock/write+/var/tmp ...

Il est également possible de combiner les raccourcis d'un seul caractère des profils d'aide, afin de les empiler ensemble. Voici quelques exemples :

  • syd -pMPX ... # Désactive les restrictions MDWE, PIE et exec.
  • syd -puiq ... # Analyse le profil utilisateur, crée un conteneur immuable et silencie les violations d'accès.

Shell de connexion et profil utilisateur

Lorsqu'il est invoqué sans arguments, /bin/sh est exécuté sous Syd avec le profil user comme shell de connexion. Utilisez la variable d'environnement SYD_SH pour remplacer le shell à exécuter.

SÉCURITÉ

À partir de la version 3.30.0, Syd se termine avec une erreur si le chemin d'un fichier de configuration spécifié contient un lien symbolique dans n'importe lequel de ses composants de chemin.

Par conséquent, l'utilisateur doit fournir des chemins canonicalisés comme arguments de fichier de configuration.

EXEMPLE

# Profil Syd pour OpenNTPD
# Sandbox Seccomp
sandbox/read,stat,write,exec,net:on
# Landlock
sandbox/lock:on
# Fournir une isolation à l'aide des namespaces.
unshare/mount,uts,pid,ipc,cgroup:1
# Autoriser adjtimex et conserver CAP_SYS_TIME.
trace/allow_unsafe_time:1
# Monter tout en ro sauf /var
bind+tmpfs:/dev/shm:nodev,nosuid,noexec
bind+tmpfs:/tmp:nodev,nosuid
bind+/etc:/etc:ro,nodev,noexec,nosuid,noatime
bind+/home:/home:ro,nodev,noexec,nosuid,noatime
bind+/media:/media:ro,nodev,noexec,nosuid,noatime
bind+/mnt:/mnt:ro,nodev,noexec,nosuid,noatime
bind+/opt:/opt:ro,nodev,nosuid,noatime
bind+/srv:/srv:ro,nodev,noexec,nosuid,noatime
bind+/usr:/usr:ro,nodev,noatime
# Cacher Syd
deny/read,stat,write+/proc/1/***
# Autoriser l'écoute sur le port ntp sur la boucle locale.
allow/net/bind+loopback!123
# Autoriser les connexions aux serveurs NTP.
allow/net/connect+any!53
allow/net/connect+any!123
allow/net/connect+any!65535
# Autoriser la journalisation vers syslog.
allow/net/connect+/dev/log
# Autoriser `listen wildcard`
allow/net/bind+0.0.0.0!0
allow/net/connect+0.0.0.0!0
# Autoriser l'écoute sur le socket ntpd.
allow/net/bind+/run/ntpd.sock
allow/net/bind+/var/run/ntpd.sock
allow/write+/run/ntpd.sock
allow/write+/var/run/ntpd.sock
# Autoriser l'accès aux chemins système
allow/read,stat+/dev/urandom
allow/lock/read+/dev/urandom
allow/read,stat+/etc/hosts
allow/lock/read+/etc/hosts
allow/read,stat+/etc/ntpd.conf
allow/lock/read+/etc/ntpd.conf
allow/read,stat+/etc/passwd
allow/lock/read+/etc/passwd
allow/read,stat+/etc/resolv.conf
allow/lock/read+/etc/resolv.conf
allow/read,stat+/etc/services
allow/lock/read+/etc/services
allow/read,stat+/usr/share/zoneinfo-posix/UTC
# chroot /var/empty && cd /
allow/stat+/
allow/stat+/var/empty
allow/write+/dev/null
allow/lock/write+/dev/null
# Autoriser l'exécution du binaire ntp.
allow/lock/read+/proc
allow/lock/read+/usr
allow/lock/write+/run
allow/lock/write+/var/run
allow/exec+/usr/**/bin/openntpd*
# Autoriser l'écriture du fichier de dérive.
allow/write+/var/db/ntpd.drift
allow/lock/write+/var/db/ntpd.drift
# Verrouillage de la configuration
lock:on
