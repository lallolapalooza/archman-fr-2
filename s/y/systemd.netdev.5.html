NOM

systemd.netdev - Configuration de périphérique réseau virtuel

SYNTAXE

netdev.netdev

DESCRIPTION

Un fichier texte simple de style ini qui encode la configuration d'un périphérique réseau virtuel, utilisé par systemd-networkd(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

Le fichier principal du périphérique réseau virtuel doit avoir l'extension .netdev ; les autres extensions sont ignorées. Les périphériques réseau virtuels sont créés dès que systemd-networkd est démarré si possible. Si un périphérique réseau avec le nom spécifié existe déjà, systemd-networkd tentera de mettre à jour la configuration si le type du périphérique réseau existant est équivalent à celui demandé, sinon (par exemple, lorsqu'un périphérique de pont foo existe mais qu'un périphérique de liaison portant le même nom est configuré dans un fichier .netdev) il utilisera le périphérique réseau existant tel quel plutôt que de le remplacer par le périphérique réseau demandé. Notez que plusieurs paramètres (par exemple, l'ID VLAN) ne peuvent pas être modifiés une fois le périphérique réseau créé. Pour modifier ces paramètres, il est nécessaire de d'abord supprimer le périphérique réseau existant, puis d'exécuter la commande networkctl reload ou de redémarrer systemd-networkd. Voir aussi networkctl(1).

Les fichiers .netdev sont lus à partir des fichiers situés dans le répertoire réseau système /usr/lib/systemd/network et /usr/local/lib/systemd/network, le répertoire réseau d'exécution volatile /run/systemd/network et le répertoire réseau d'administration locale /etc/systemd/network. Tous les fichiers de configuration sont triés collectivement et traités dans l'ordre alphanumérique, indépendamment des répertoires dans lesquels ils se trouvent. Cependant, les fichiers portant des noms identiques se remplacent mutuellement. Il est recommandé que chaque nom de fichier soit préfixé par un nombre inférieur à "70" (par exemple, 10-vlan.netdev). Sinon, les fichiers .netdev générés par systemd-network-generator.service(8) peuvent avoir la priorité sur les fichiers configurés par l'utilisateur. Les fichiers dans /etc/ ont la priorité la plus élevée, les fichiers dans /run/ prennent la priorité sur les fichiers du même nom dans /usr/lib/. Ceci peut être utilisé pour remplacer un fichier de configuration fourni par le système par un fichier local si besoin. Dans un cas spécial, un fichier vide (taille de fichier 0) ou un lien symbolique portant le même nom pointant vers /dev/null désactive complètement le fichier de configuration (il est "masqué").

Parallèlement au fichier netdev foo.netdev, un répertoire "drop-in" foo.netdev.d/ peut exister. Tous les fichiers portant le suffixe ".conf" de ce répertoire seront fusionnés dans l'ordre alphanumérique et analysés après que le fichier principal lui-même ait été analysé. Ceci est utile pour modifier ou ajouter des paramètres de configuration, sans avoir à modifier le fichier de configuration principal. Chaque fichier drop-in doit avoir les sections appropriées en-têtes.

En plus de /etc/systemd/network, des répertoires ".d" "drop-in" peuvent être placés dans les répertoires /usr/lib/systemd/network ou /run/systemd/network. Les fichiers drop-in dans /etc/ ont la priorité sur ceux dans /run/ qui à leur tour ont la priorité sur ceux dans /usr/lib/. Les fichiers drop-in dans l'un quelconque de ces répertoires ont la priorité sur le fichier netdev principal, où qu'il soit situé. (Bien sûr, comme /run/ est temporaire et /usr/lib/ est pour les fournisseurs, il est peu probable que des drop-ins soient utilisés dans l'un ou l'autre de ces endroits.)

[MATCH] OPTIONS DE SECTION

Un périphérique réseau virtuel n'est créé que si la section [Match] correspond à l'environnement actuel, ou si la section est vide. Les clés suivantes sont acceptées :

Host=

Correspondance avec le nom d'hôte ou l'identifiant de la machine. Voir ConditionHost= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 211.

Virtualization=

Vérifie si le système est exécuté dans un environnement virtualisé et teste éventuellement s'il s'agit d'une implémentation spécifique. Voir ConditionVirtualization= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 211.

KernelCommandLine=

Vérifie si une option de ligne de commande du noyau spécifique est définie. Voir ConditionKernelCommandLine= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 211.

KernelVersion=

Vérifie si la version du noyau (telle que rapportée par uname -r) correspond à une expression donnée. Voir ConditionKernelVersion= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 237.

Version=

Vérifie si une version logicielle correspond à une expression donnée. Voir ConditionVersion= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 258.

Credential=

Vérifie si l'identifiant spécifié a été transmis au service systemd-udevd.service. Voir **Identifiants système et de service**[6] pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 252.

Architecture=

Vérifie si le système tourne sur une architecture spécifique. Voir ConditionArchitecture= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 211.

Firmware=

Vérifie si le système tourne sur une machine avec le firmware spécifié. Voir ConditionFirmware= dans systemd.unit(5) pour plus de détails. Lorsqu'il est préfixé par un point d'exclamation ("!"), le résultat est nié. Si une chaîne vide est attribuée, la valeur précédemment attribuée est effacée.

Ajouté dans la version 249.

[NETDEV] OPTIONS DE SECTION

La section [NetDev] accepte les clés suivantes :

Description=

Une description libre du netdev.

Ajouté dans la version 215.

Name=

Le nom de l'interface utilisé lors de la création du netdev. Ce paramètre est obligatoire.

Ajouté dans la version 211.

Kind=

Le type de netdev. Ce paramètre est obligatoire. Voir la section "Types de netdev pris en charge" pour les clés valides.

Ajouté dans la version 211.

MTUBytes=

L'unité de transmission maximale en octets à définir pour le périphérique. Les suffixes usuels K, M, G sont pris en charge et sont compris sur la base de 1024. Pour les périphériques "tun" ou "tap", le paramètre MTUBytes= n'est actuellement pas pris en charge dans la section [NetDev]. Veuillez le spécifier dans la section [Link] des fichiers systemd.network(5) correspondants.

Ajouté dans la version 215.

MACAddress=

Spécifie l'adresse MAC à utiliser pour le périphérique, ou prend la valeur spéciale "none". Lorsque "none" est spécifié, systemd-networkd ne demande pas l'adresse MAC pour le périphérique, et le noyau attribuera une adresse MAC aléatoire. Pour les périphériques "tun", "tap" ou "l2tp", le paramètre MACAddress= dans la section [NetDev] n'est pas pris en charge et sera ignoré. Veuillez le spécifier dans la section [Link] du fichier systemd.network(5) correspondant. Si cette option n'est pas définie, le périphérique "vlan" hérite de l'adresse MAC de l'interface maître. Pour les autres types de netdevs, si cette option n'est pas définie, alors l'adresse MAC est générée en fonction du nom de l'interface et de l'machine-id(5).

Notez que même si "none" est spécifié, systemd-udevd attribuera l'adresse MAC persistante pour le périphérique, car 99-default.link a MACAddressPolicy=persistent. Il est donc également nécessaire de créer un fichier .link personnalisé pour le périphérique, si l'attribution de l'adresse MAC n'est pas souhaitée.

Ajouté dans la version 215.

[BRIDGE] OPTIONS DE SECTION

La section [Bridge] s'applique uniquement aux netdevs de type "bridge" et accepte les clés suivantes :

HelloTimeSec=

HelloTimeSec spécifie le nombre de secondes entre deux paquets de "hello" envoyés par le pont racine et les ponts désignés. Les paquets "hello" sont utilisés pour communiquer des informations sur la topologie sur l'ensemble du réseau local ponté.

Ajouté dans la version 227.

MaxAgeSec=

MaxAgeSec spécifie le nombre de secondes d'âge maximum du message. Si le dernier paquet "hello" vu (reçu) est plus ancien que ce nombre de secondes, le pont concerné commencera la procédure de prise de contrôle pour tenter de devenir lui-même le pont racine.

Ajouté dans la version 227.

ForwardDelaySec=

ForwardDelaySec spécifie le nombre de secondes passées dans chacun des états d'écoute (Listening) et d'apprentissage (Learning) avant que l'état de transfert (Forwarding) ne soit atteint.

Ajouté dans la version 227.

AgeingTimeSec=

Ceci spécifie le nombre de secondes pendant lesquelles une adresse MAC sera conservée dans la base de données de transfert après avoir reçu un paquet de cette adresse MAC.

Ajouté dans la version 232.

Priority=

La priorité du pont. Un entier compris entre 0 et 65535. Une valeur plus basse signifie une priorité plus élevée. Le pont ayant la priorité la plus basse sera élu pont racine.

Ajouté dans la version 232.

GroupForwardMask=

Un masque de bits de 16 bits représenté sous forme d'entier qui permet le transfert des trames de liaison locale avec les adresses réservées 802.1D (01:80:C2:00:00:0X). Une opération ET logique est effectuée entre le masque spécifié et l'exponentiation de 2^X, le nibble inférieur du dernier octet de l'adresse MAC. Par exemple, une valeur de 8 permettrait le transfert des trames adressées à 01:80:C2:00:00:03 (802.1X PAE).

Ajouté dans la version 235.

DefaultPVID=

Ceci spécifie l'ID VLAN par défaut du port pour un port de pont nouvellement attaché. Définissez ceci sur un entier dans la plage 1...4094 ou "none" pour désactiver le PVID.

Ajouté dans la version 232.

MulticastQuerier=

Prend une valeur booléenne. Ce paramètre contrôle l'option IFLA_BR_MCAST_QUERIER du noyau. Si activé, le noyau enverra des requêtes ICMP générales à partir d'une adresse source nulle. Cette fonctionnalité devrait permettre une convergence plus rapide au démarrage, mais elle provoque un mauvais fonctionnement de certains commutateurs conscients du multidiffusion et perturbe le transfert des paquets multidiffusion. Lorsqu'il n'est pas défini, le défaut du noyau sera utilisé.

Ajouté dans la version 230.

MulticastSnooping=

Prend une valeur booléenne. Ce paramètre contrôle l'option IFLA_BR_MCAST_SNOOPING du noyau. Si activé, IGMP snooping surveille le trafic IGMP (Internet Group Management Protocol) entre les hôtes et les routeurs de multidiffusion. Lorsqu'il n'est pas défini, le défaut du noyau sera utilisé.

Ajouté dans la version 230.

VLANFiltering=

Prend une valeur booléenne. Ce paramètre contrôle l'option IFLA_BR_VLAN_FILTERING du noyau. Si activé, le pont démarrera en mode filtrage VLAN. Lorsqu'il n'est pas défini, le défaut du noyau sera utilisé.

Ajouté dans la version 231.

VLANProtocol=

Permet de définir le protocole utilisé pour le filtrage VLAN. Accepte 802.1q ou 802.1ad, et par défaut il est non défini et le défaut du noyau est utilisé.

Ajouté dans la version 246.

STP=

Prend une valeur booléenne. Ceci active le protocole Spanning Tree (STP) du pont. Lorsqu'il n'est pas défini, le défaut du noyau sera utilisé.

[HSR] OPTIONS DE SECTION

La section [HSR] s'applique uniquement aux périphériques réseau de type "hsr" et accepte les clés suivantes :

Ports=

Spécifie les interfaces sous-jacentes. Ce champ est obligatoire et doit contenir exactement deux noms d'interface séparés par un espace. Cette option peut être spécifiée plusieurs fois, donc les deux cas ci-dessous ont le même résultat : 
Ports=eth1 eth2
Ports=eth1
Ports=eth2

Toutes les assignations précédentes sont effacées lorsqu'une chaîne vide est spécifiée.

Ajouté dans la version 258.

Protocol=

Spécifie le protocole utilisé par l'interface. Prend l'une des valeurs "hsr" ou "prp". Par défaut, "hsr".

Les deux protocoles fonctionnent en envoyant deux copies de chaque trame sortante, une pour chacun des deux ports. Le nœud de destination reçoit les deux trames et ne conserve que la première. Si une liaison échoue, seule l'une des deux trames est reçue. HSR utilise une topologie en anneau où les deux trames sortantes sont envoyées dans des directions opposées dans l'anneau. PRP n'a pas besoin d'une topologie spécifique, mais il nécessite deux réseaux complètement redondants connectés aux deux ports.

Ajouté dans la version 258.

Supervision=

Spécifie le dernier octet de l'adresse MAC de destination des trames de supervision. Prend un nombre compris entre 0 et 255. Par défaut, 0. Les trames de supervision sont utilisées par les protocoles HSR et PRP pour surveiller l'intégrité du réseau et la présence des nœuds. Les 5 premiers octets de l'adresse MAC de destination sont toujours 01:15:4E:00:01 tandis que le dernier octet est configurable.

Elle est utilisée comme marque de configuration d'une entrée SAD/SPD dans le cadre de la clé de recherche (dans le chemin des données et de contrôle) dans IP XFRM (framework utilisé pour implémenter le protocole IPsec). Voir ip-xfrm — configuration de transformation[14] pour plus de détails. Elle n'est utilisée que pour les tunnels VTI/VTI6, GRE, GRETAP et ERSPAN.

Ajouté dans la version 231.

Le paramètre InputKey= spécifie la clé à utiliser pour l'entrée. Le format est le même que Key=. Il n'est utilisé que pour les tunnels VTI/VTI6, GRE, GRETAP et ERSPAN.

Le paramètre OutputKey= spécifie la clé à utiliser pour la sortie. Le format est le même que Key=. Il n'est utilisé que pour les tunnels VTI/VTI6, GRE, GRETAP et ERSPAN.

AllSlavesActive=

Prend une valeur booléenne. Spécifie si les trames dupliquées (reçues sur des ports inactifs) doivent être ignorées lorsqu'elle est fausse, ou livrées lorsqu'elle est vraie. Normalement, la liaison ignorera les trames dupliquées (reçues sur des ports inactifs), ce qui est souhaitable pour la plupart des utilisateurs. Mais il y a certains cas où il est utile de permettre la livraison des trames dupliquées. La valeur par défaut est fausse (ignorer les trames dupliquées reçues sur des ports inactifs).

Ajouté dans la version 220.

DynamicTransmitLoadBalancing=

Prend une valeur booléenne. Spécifie si le mélange dynamique des flux est activé. S'applique uniquement au mode balance-tlb. Par défaut, non défini.

Ajouté dans la version 240.

MinLinks=

Spécifie le nombre minimum de liaisons qui doivent être actives avant d'assertir le signal de port. La valeur par défaut est 0.

Ajouté dans la version 220.

ARPMissedMax=

Spécifiez le nombre maximum de cycles d'intervalle de surveillance ARP pour les réponses ARP manquées. Si ce nombre est dépassé, la liaison est signalée comme étant inactive. Par défaut, non défini.

Ajouté dans la version 256.

Pour plus d'informations, consultez le Linux Ethernet Bonding Driver HOWTO[1]

[BATMANADVANCED] OPTIONS DE SECTION

La section [BatmanAdvanced] s'applique uniquement aux périphériques réseau de type "batadv" et accepte les clés suivantes :

GatewayMode=

Prend l'une des valeurs "off", "server" ou "client". Un nœud batman-adv peut fonctionner en mode serveur (partageant sa connexion Internet avec le mesh) ou en mode client (recherchant la connexion Internet la plus appropriée dans le mesh) ou en désactivant complètement la prise en charge de la passerelle (ce qui est le paramètre par défaut).

Ajouté dans la version 248.

Aggregation=

Prend une valeur booléenne. Active ou désactive l'agrégation des messages d'origine. Par défaut, vrai.

Ajouté dans la version 248.

BridgeLoopAvoidance=

Prend une valeur booléenne. Active ou désactive l'évitement des boucles sur les ponts. Par défaut, vrai.

Ajouté dans la version 248.

DistributedArpTable=

Prend une valeur booléenne. Active ou désactive la table ARP distribuée. Par défaut, vrai.

Ajouté dans la version 248.

Fragmentation=

Prend une valeur booléenne. Active ou désactive la fragmentation. Par défaut, vrai.

Ajouté dans la version 248.

HopPenalty=

Le paramètre de pénalité de saut permet de modifier la préférence de batctl(8) pour les routes multi-sauts par rapport aux routes courtes. Cette valeur entière est appliquée à la qualité de transmission (TQ) de chaque OGM (message d'origine) transféré, propageant ainsi le coût d'un saut supplémentaire (le paquet doit être reçu et retransmis, ce qui coûte du temps d'antenne). Une pénalité de saut plus élevée rend moins probable que d'autres nœuds choisissent ce nœud comme saut intermédiaire vers une destination donnée. La pénalité de saut par défaut de '15' est une valeur raisonnable pour la plupart des configurations et ne nécessite probablement pas d'être modifiée. Cependant, les nœuds mobiles pourraient choisir une valeur de 255 (valeur maximale) pour éviter d'être choisis comme routeur par d'autres nœuds. La valeur minimale est 0.

Ajouté dans la version 248.

OriginatorIntervalSec=

La valeur spécifie l'intervalle en secondes, à moins qu'une autre unité de temps ne soit spécifiée, pendant lequel batman-adv inonde le réseau avec ses informations de protocole. Voir systemd.time(7) pour plus d'informations.

Ajouté dans la version 248.

GatewayBandwidthDown=

Si le nœud est un serveur, ce paramètre est utilisé pour informer les autres nœuds du réseau de la bande passante de téléchargement de la connexion Internet de ce nœud en bits par seconde. Entrez simplement un nombre suffixé par K, M, G ou T (base 1000) et le module batman-adv propagera la valeur entrée dans le mesh.

Ajouté dans la version 248.

GatewayBandwidthUp=

Si le nœud est un serveur, ce paramètre est utilisé pour informer les autres nœuds du réseau de la bande passante de téléchargement de la connexion Internet de ce nœud en bits par seconde. Entrez simplement un nombre suffixé par K, M, G ou T (base 1000) et le module batman-adv propagera la valeur entrée dans le mesh.

Ajouté dans la version 248.

RoutingAlgorithm=

Peut être "batman-v" ou "batman-iv" et décrit quel algorithme de routage de batctl(8) utiliser. L'algorithme ne peut pas être modifié après la création de l'interface. Par défaut, "batman-v".

Ajouté dans la version 248.

[IPOIB] OPTIONS DE SECTION

La section [IPoIB] s'applique uniquement aux périphériques réseau de type "ipoib" et accepte les clés suivantes :

PartitionKey=

Prend un entier dans la plage 1...0xffff, à l'exception de 0x8000. Par défaut, non défini, et le défaut du noyau est utilisé.

Ajouté dans la version 250.

Mode=

Prend l'une des valeurs spéciales "datagram" ou "connected". Par défaut, non défini, et le défaut du noyau est utilisé.

Lorsqu'il est défini sur "datagram", le transport de datagrammes non fiables (UD) d'Infiniband est utilisé, et donc le MTU de l'interface est égal au MTU L2 IB moins l'en-tête d'encapsulation IPoIB (4 octets). Par exemple, dans un tissu IB typique avec un MTU de 2K, le IPoIB

IB MTU sera de 2048 - 4 = 2044 octets.

Lorsque « connecté », le transport fiable connecté (RC) d'Infiniband est utilisé. Le mode connecté tire parti de la nature connectée du transport IB et autorise une MTU jusqu'à la taille maximale du paquet IP de 64 Ko, ce qui réduit le nombre de paquets IP nécessaires pour gérer de gros datagrammes UDP, segments TCP, etc. et augmente les performances pour les gros messages.

Ajouté dans la version 250.

IgnoreUserspaceMulticastGroups=

Prend une valeur booléenne. Lorsque vrai, le noyau ignore les groupes de multidiffusion gérés par l'espace utilisateur. Par défaut, il n'est pas défini et le défaut du noyau est utilisé.

Ajouté dans la version 250.

[WLAN] OPTIONS DE SECTION

La section [WLAN] s'applique uniquement aux interfaces WLAN et accepte les clés suivantes :

PhysicalDevice=

Spécifie le nom ou l'index du périphérique WLAN physique (par exemple, « 0 » ou « phy0 »). La liste des périphériques WLAN physiques existants sur l'hôte peut être obtenue par la commande iw phy. Cette option est obligatoire.

Ajouté dans la version 251.

Type=

Spécifie le type de l'interface. Prend l'une des valeurs « ad-hoc », « station », « ap », « ap-vlan », « wds », « monitor », « mesh-point », « p2p-client », « p2p-go », « p2p-device », « ocb », et « nan ». Cette option est obligatoire.

Ajouté dans la version 251.

WDS=

Active le mode Wireless Distribution System (WDS) sur l'interface. Le mode est également connu sous le nom de « mode 4 adresses ». Prend une valeur booléenne. Par défaut, il n'est pas défini et le défaut du noyau sera utilisé.

Ajouté dans la version 251.
