NOM

sysdig - l'outil ultime de dépannage système et de processus

SYNTAXE

sysdig [option]... [filtre]

DESCRIPTION

Note : si vous êtes intéressé par une interface plus facile à utiliser pour les fonctionnalités de sysdig, utilisez l'utilitaire en ligne de commande csysdig.

sysdig est un outil pour le dépannage, l'analyse et l'exploration systèmes. Il peut être utilisé pour capturer, filtrer et décoder les appels système et autres événements OS. sysdig peut être utilisé à la fois pour inspecter des systèmes vivants, ou pour générer des fichiers de trace qui peuvent être analysés ultérieurement.

sysdig inclut un langage de filtrage puissant, a une sortie personnalisable, et peut être étendu par des scripts Lua, appelés chisels.

Format de sortie

Par défaut, sysdig imprime les informations pour chaque événement capturé sur une seule ligne, avec le format suivant :

*%evt.num %evt.time %evt.cpu %proc.name (%thread.tid) %evt.dir %evt.type %evt.info

où :

•
evt.num est le numéro d'événement incrémental
•
evt.time est l'horodatage de l'événement
•
evt.cpu est le numéro du CPU où l'événement a été capturé
•
proc.name est le nom du processus qui a généré l'événement
•
thread.tid est l'ID du thread qui a généré l'événement, qui correspond au PID pour les processus à thread unique
•
evt.dir est la direction de l'événement, > pour les événements d'entrée et < pour les événements de sortie
•
evt.type est le nom de l'événement, par exemple 'open' ou 'read'
•
evt.args est la liste des arguments de l'événement.

Le format de sortie peut être personnalisé avec l'option -p, en utilisant l'un des champs listés par 'sysdig -l'.

En utilisant -pc ou -pcontainer, le format par défaut sera modifié pour un format adapté aux conteneurs :

*%evt.num %evt.time %evt.cpu %container.name (%container.id) %proc.name (%thread.tid:%thread.vtid) %evt.dir %evt.type %evt.info

Fichiers de trace

Un fichier de trace peut être créé en utilisant l'option -w :

$ sysdig -w trace.scap

L'option -s peut être utilisée pour spécifier combien d'octets de chaque tampon de données doivent être sauvegardés sur le disque. Et les filtres peuvent être utilisés pour sauvegarder uniquement certains événements sur le disque :

$ sysdig -s 2000 -w trace.scap proc.name=cat

Les fichiers de trace peuvent être lus en utilisant l'option -r :

$ sysdig -r trace.scap

Filtrage

Les filtres sysdig sont spécifiés à la fin de la ligne de commande. Le filtre le plus simple est une vérification basique champ-valeur :

$ sysdig proc.name=cat

La liste des champs disponibles peut être obtenue avec 'sysdig -l'. Les expressions de filtre peuvent utiliser l'un des opérateurs de comparaison suivants : =, !=, <, <=, >, >=, contains, icontains, in et exists. par exemple :

$ sysdig fd.name contains /etc $ sysdig "evt.type in ( 'select', 'poll' )" $ sysdig proc.name exists

Plusieurs vérifications peuvent être combinées par des parenthèses et les opérateurs booléens suivants : and, or, not. par exemple :

$ sysdig "not (fd.name contains /proc or fd.name contains /dev)"

Chisels

Les chisels de sysdig sont de petits scripts qui analysent le flux d'événements de sysdig pour effectuer des actions utiles. Pour obtenir la liste des chisels disponibles, tapez

$ sysdig -cl

Pour obtenir des détails sur un chisel spécifique, tapez

$ sysdig -i spy_ip

Pour exécuter l'un des chisels, vous utilisez le flag -c, par exemple :

$ sysdig -c topfiles_bytes

Si un chisel nécessite des arguments, vous les spécifiez après le nom du chisel :

$ sysdig -c spy_ip 192.168.1.157

Si un chisel a plus d'un argument, spécifiez-les après le nom du chisel, entre guillemets :

$ sysdig -c chisel_name "arg1 arg2 arg3"

Les chisels peuvent être combinés avec des filtres :

$ sysdig -c topfiles_bytes "not fd.name contains /dev"

OPTIONS

-A, --print-ascii N'imprime que la portion texte des tampons de données, et écho les fins de ligne. Ceci est utile pour n'afficher que des données lisibles par l'homme.

-b, --print-base64 Imprime les tampons de données en base64. Ceci est utile pour encoder des données binaires qui doivent être utilisées sur des médias conçus pour gérer des données textuelles (c'est-à-dire terminal ou json).

-c nom_chisel args_chisel, --chisel=nom_chisel args_chisel exécute le chisel spécifié. Si le chisel nécessite des arguments, ils doivent être spécifiés dans la ligne de commande après le nom.

-C taille_fichier Casse une capture en fichiers séparés, et limite la taille de chaque fichier en fonction du nombre de mégaoctets spécifié. Les unités de taille_fichier sont des millions d'octets (10^6, pas 2^20). À utiliser conjointement avec -W pour activer la rotation automatique des fichiers. Sinon, de nouveaux fichiers continueront d'être créés jusqu'à ce que la capture soit arrêtée manuellement.

Les fichiers auront le nom spécifié par -w avec un compteur ajouté commençant à 0.

-cl, --list-chisels liste les chisels disponibles. Sysdig recherche les chisels dans les répertoires suivants : ./chisels, ~/.chisels et /usr/share/sysdig/chisels.

-d, --displayflt Fait du filtre donné un filtre d'affichage. Le réglage de cette option fait que les événements sont filtrés après avoir été analysés par le système d'état. Les événements sont normalement filtrés avant d'être analysés, ce qui est plus efficace, mais peut entraîner la perte d'état (par exemple, noms FD).

-D, --debug Capture des événements concernant sysdig lui-même, affiche les événements internes en plus des événements système, et imprime des logs supplémentaires sur la sortie d'erreur standard.

-E, --exclude-users Ne crée pas les tables utilisateur/groupe en interrogeant l'OS au démarrage de sysdig. Cela signifie également qu'aucune information utilisateur ou groupe ne sera écrite dans le fichier de trace par l'option -w. Les tables utilisateur/groupe sont nécessaires pour utiliser des champs de filtre comme user.name ou group.name. Cependant, leur création peut augmenter le temps de démarrage de sysdig. De plus, elles contiennent des informations qui pourraient être sensibles en termes de vie privée.

-e nb_evenements Casse une capture en fichiers séparés, et limite la taille de chaque fichier en fonction du nombre d'événements spécifié. À utiliser conjointement avec -W pour activer la rotation automatique des fichiers. Sinon, de nouveaux fichiers continueront d'être créés jusqu'à ce que la capture soit arrêtée manuellement.

Les fichiers auront le nom spécifié par -w avec un compteur ajouté commençant à 0.

-F, --fatfile Active le mode fatfile. En écrivant en mode fatfile, le fichier de sortie contiendra des événements qui seront invisibles lors de la lecture du fichier, mais qui sont nécessaires pour reconstruire complètement l'état. Le mode fatfile est utile lors de la sauvegarde d'événements sur disque avec un filtre agressif. Le filtre pourrait supprimer des événements qui mettraient à jour l'état (par exemple, clone() ou open()). Avec le mode fatfile, ces événements sont toujours sauvegardés dans le fichier, mais 'cachés' afin qu'ils n'apparaissent pas lors de la lecture du fichier. Soyez conscient que l'utilisation de ce flag peut générer des fichiers de trace considérablement plus gros.

--filter-proclist Applique le filtre à la table des processus. Un dump complet de /proc est généralement inclus dans tout fichier de trace pour s'assurer que tout l'état nécessaire au décodage des événements est dans le fichier. Cela pourrait causer des informations non désirées ou sensibles dans le fichier. L'utilisation de ce flag fait que le filtre en ligne de commande s'applique également au dump /proc.

-G nbsecondes Casse une capture en fichiers séparés, et limite la taille de chaque fichier en fonction du nombre de secondes spécifié. À utiliser conjointement avec -W pour activer la rotation automatique des fichiers. Sinon, de nouveaux fichiers continueront d'être créés jusqu'à ce que la capture soit arrêtée manuellement.

Les fichiers auront le nom spécifié par -w qui devrait inclure un format de temps tel que défini par strftime(3). Si aucun format de temps n'est spécifié, un compteur sera utilisé.

-h, --help Imprime cette page

-H nom_plugin[:config_init], --plugin nom_plugin[:config_init] Enregistre un plugin, en utilisant la configuration d'initialisation passée si présente.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Un chemin peut également être utilisé comme nom de plugin. Le format de initconf est contrôlé par le plugin, référez-vous à la documentation de chaque plugin pour en savoir plus.

-I nom_plugin[:param_ouverture], --input nom_plugin[:param_ouverture] Capture les événements en utilisant le plugin du nom nom_plugin, en passant la chaîne param_ouverture comme paramètres au plugin. Le format des inputargs est contrôlé par le plugin, référez-vous à la documentation de chaque plugin pour en savoir plus. Les sources d'événements disponibles pour la capture varient en fonction des plugins installés. Vous pouvez lister les plugins chargés en utilisant l'indicateur -Il.

-Il, --list-inputs Liste les plugins chargés. Sysdig recherche les plugins dans les répertoires suivants : ./plugins, ~/.plugins, /usr/share/sysdig/plugins.

--plugin-config-file Charge la configuration du plugin à partir d'un fichier de configuration yaml compatible Falco. Mélanger cette option avec '-H' ou '-I' n'est pas supporté. Voir la section plugin dans https://falco.org/docs/configuration/ pour des informations supplémentaires.

-i nom_chisel, --chisel-info=_nom_chisel_ Obtient une description plus longue et les arguments associés à un chisel trouvé dans la liste de l'option -cl.

-j, --json Émet la sortie au format JSON, le codage du buffer de données dépendra du format d'impression sélectionné.

-k, --k8s-api Active le support Kubernetes en se connectant au serveur API spécifié comme argument. Ex: "http://admin:password@127.0.0.1:8080". Le serveur API peut également être spécifié via la variable d'environnement SYSDIG_K8S_API.

-K fichier_bt | fichier_cert:fichier_clé[#mot_de_passe][:fichier_ca_cert], --k8s-api-cert=_fichier_bt | fichier_cert:fichier_clé[#mot_de_passe][:fichier_ca_cert]_ Utilise les noms de fichiers fournis pour authentifier l'utilisateur et (facultativement) vérifier l'identité du serveur API K8S. Chaque entrée doit spécifier le chemin complet (absolu ou relatif au répertoire courant) vers le fichier respectif. Le mot de passe de la clé privée est facultatif (requis uniquement si la clé est protégée par mot de passe). Le certificat CA est facultatif. Seul le format de fichier PEM est supporté pour tous les fichiers. Spécifier uniquement le certificat CA est obsolète - lorsqu'une seule entrée est fournie pour cette option, elle sera interprétée comme le nom d'un fichier contenant un jeton porteur. Notez que le format de cette option de ligne de commande interdit l'utilisation de fichiers dont les noms contiennent les caractères ':' ou '#' dans le nom du fichier. L'option peut également être fournie via la variable d'environnement SYSDIG_K8S_API_CERT.

-L, --list-events Liste les événements supportés par le moteur.

-l, --list Liste les champs qui peuvent être utilisés pour le filtrage et le formatage de la sortie. Utilisez -lv pour obtenir des informations supplémentaires pour chaque champ.

--list-markdown Similaire à -l, mais produit une sortie au format markdown.

-m url[,url_marathon], --mesos-api=_url[,url_marathon]_ Active le support Mesos en se connectant au serveur API spécifié comme argument (ex: http://admin:password@127.0.0.1:5050). L'URL Mesos est requise. L'URL Marathon est facultative, par défaut elle essaie de suivre automatiquement - si le serveur API Marathon n'est pas fourni, sysdig tentera de récupérer (et de suivre ensuite, s'il migre) l'emplacement du serveur API Marathon à partir du maître Mesos. Notez qu'avec le suivi automatique, sysdig recevra probablement une adresse IP interne au cluster pour le serveur API Marathon, donc exécuter sysdig avec le suivi automatique Marathon à partir d'un nœud qui ne fait pas partie du cluster Mesos peut ne pas fonctionner. De plus, exécuter sysdig avec le support Mesos sur un nœud qui n'a pas de conteneurs gérés par Mesos est d'une utilité limitée car, bien que les métadonnées du cluster seront collectées, il n'y aura pas de capacité de filtrage Mesos/Marathon. Les serveurs API peuvent également être spécifiés via la variable d'environnement SYSDIG_MESOS_API.

-M num_secondes Arrête la capture après avoir atteint

-n num, --numevents=num

Arrête la capture après num événements.

--page-faults Capture les défauts de page majeurs/mineurs utilisateur/noyau.

-P, --progress

Affiche la progression sur stderr pendant le traitement des fichiers de trace.

-p format_sortie, --print=format_sortie

Spécifie le format à utiliser lors de l'affichage des événements. Avec -pc ou -pcontainer, utilisera un format adapté aux conteneurs. Avec -pk ou -pkubernetes, utilisera un format adapté à Kubernetes. Avec -pm ou -pmesos, utilisera un format adapté à Mesos. Spécifier -pp sur la ligne de commande provoquera l'affichage du format de ligne de commande par défaut et la sortie de sysdig.

-q, --quiet

Ne pas afficher les événements à l'écran. Utile lors de l'écriture sur disque.

-r fichier_lecture, --read=fichier_lecture

Lit les événements depuis fichier_lecture.

-R, --resolve-ports Résout les numéros de ports en noms.

-S, --summary

Affiche le résumé des événements (c'est-à-dire la liste des événements les plus fréquents) à la fin de la capture.

-s longueur, --snaplen=longueur

Capture les longueur premiers octets de chaque buffer d'E/S. Par défaut, les 80 premiers octets sont capturés. Utilisez cette option avec précaution, elle peut générer des fichiers de trace énormes.

-t type_heure, --timetype=type_heure

Change la façon dont l'heure de l'événement est affichée. Les valeurs acceptées sont h pour une chaîne lisible par l'homme, a pour un timestamp absolu depuis l'époque, r pour un temps relatif depuis le premier événement affiché, d pour la différence entre l'entrée et la sortie de l'événement, et D pour la différence par rapport à l'événement précédent.

-T, --force-tracers-capture

Indique au driver de s'assurer que les buffers complets sont capturés à partir de /dev/null, pour s'assurer que les traceurs sont complètement capturés. Notez que sysdig activera la capture étendue de /dev/null par lui-même après avoir détecté que des traceurs y sont écrits, mais cela pourrait entraîner la troncature de certains traceurs au début de la capture. Cette option permet d'éviter cela.

--unbuffered

Désactive la mise en mémoire tampon de la sortie. Cela provoque la vidange de chaque ligne émise par sysdig, ce qui génère une utilisation CPU plus élevée mais est utile lors du piping de la sortie de sysdig vers un autre processus ou un script.

-v, --verbose

Sortie verbeuse. Cet indicateur provoquera l'affichage du contenu complet des buffers texte et binaire à l'écran, au lieu d'être tronqué à 40 caractères. Notez que la longueur des buffers de données est toujours limitée par le snaplen (voir la documentation du drapeau -s) -v provoquera également l'affichage d'informations récapitulatives à la fin de la capture.

--version

Affiche le numéro de version.

-w fichier_ecriture, --write=fichier_ecriture

Écrit les événements capturés dans fichier_ecriture.

-W num

Active la rotation des fichiers pour la capture continue et limite le nombre de fichiers créés au nombre spécifié. Une fois le plafond atteint, les fichiers plus anciens seront écrasés (buffer circulaire). À utiliser conjointement avec les options -C / -G / -e pour limiter la taille de chaque fichier en fonction du nombre de mégaoctets, de secondes et/ou d'événements (respectivement).

-x, --print-hex

Affiche les buffers de données en hexadécimal.

-X, --print-hex-ascii

Affiche les buffers de données en hexadécimal et ASCII.

-z, --compress

Utilisé avec -w, active la compression pour les fichiers de trace.

EXEMPLES

Capture tous les événements du système en direct et les affiche à l'écran.

$ sysdig

Capture tous les événements du système en direct et les enregistre sur disque.

$ sysdig -w dumpfile.scap

Capture tous les événements des dernières 24 heures et les enregistre sur disque, organisés en fichiers contenant 1 heure d'activité système chacun.

$ sysdig -G 3600 -W 24 -w dumpfile.scap

Lit les événements à partir d'un fichier et les affiche à l'écran.

$ sysdig -r dumpfile.scap

Prépare une version nettoyée d'une capture système.

$ sysdig -r dumpfile.scap 'not evt.buffer contains foo' -w cleandump.scap

Affiche tous les appels système open invoqués par cat.

$ sysdig proc.name=cat and evt.type=open

Affiche le nom des fichiers ouverts par cat.

$ sysdig -p"%evt.arg.name" proc.name=cat and evt.type=open

Liste les chisels disponibles.

$ sysdig -cl

Utilise le chisel spy_ip pour examiner les données échangées avec 192.168.1.157 :

$ sysdig -c spy_ip 192.168.1.157

FICHIERS

/usr/share/sysdig/chisels

Le répertoire global des chisels.

~/.chisels

Le répertoire personnel des chisels.

BOGUES

•
sysdig et ses chisels sont conçus pour être utilisés avec LuaJIT en mode Lua 5.1. Bien qu'il soit possible d'utiliser sysdig avec LuaJIT en mode Lua 5.2 ou Lua standard, certains chisels peuvent ne pas fonctionner comme prévu.
