NOM

systemd-validatefs@.service - Valider les données de contrainte de montage de système de fichiers

SYNTAXE

systemd-validatefs@.service

/usr/lib/systemd/systemd-validatefs [PÉRIPHÉRIQUE]

DESCRIPTION

systemd-validatefs@.service est un service système modèle qui peut être instancié pour les points de montage nouvellement établis. Il lit les données de contrainte de montage du système de fichiers à partir du système de fichiers et s'assure que la configuration d'exécution du montage correspond à ces données. Si ce n'est pas le cas, le service échoue, ce qui entraîne un redémarrage immédiat.

Cette fonctionnalité est censée garantir que les systèmes de fichiers de confiance ne peuvent pas être utilisés dans un contexte différent de celui pour lequel ils étaient destinés. Plus précisément : dans un environnement basé sur systemd-gpt-auto-generator(8), les systèmes de fichiers à monter sont largement auto-découverts sur la base de données de tables de partition GPT (non protégées). Les informations de contrainte de montage peuvent être utilisées pour valider les données de partition GPT, sur la base du contenu du système de fichiers (protégé).

Plus précisément, les contraintes de montage sont codées dans les attributs étendus suivants sur l'inode racine des systèmes de fichiers :

1.user.validatefs.mount_point : cet attribut étendu doit contenir un ou plusieurs chemins absolus et normalisés, séparés par des octets NUL. S'il est défini et que le système de fichiers spécifié est monté à un emplacement ne correspondant à aucun des chemins listés, la vérification de validation échouera.
2.user.validatefs.gpt_label : cet attribut étendu peut contenir une ou plusieurs chaînes de caractères libres, séparées par des octets NUL. S'il est défini, toutes les partitions sous-jacentes du système de fichiers sont vérifiées par rapport à cette liste, et si une étiquette de partition sous-jacente n'est pas listée, la validation échouera. Notez qu'il peut y avoir plusieurs partitions sous-jacentes dans le cas de configurations Verity, qui combinent une partition de données et une partition de hachage.
3.user.validatefs.gpt_type_uuid : cet attribut étendu peut contenir un ou plusieurs UUID de type de partition GPT, formatés sous forme de chaînes de caractères, séparés par des octets NUL. Comme ci-dessus, toutes les partitions sous-jacentes du système de fichiers sont vérifiées par rapport à cette liste, et si aucune ne correspond, la validation échouera.

L'unité systemd-validatefs@.service est automatiquement tirée dans la transaction initiale par systemd-gpt-auto-generator(8) pour tous les systèmes de fichiers qu'elle découvre et pour lesquels elle génère des montages. systemd-fstab-generator(8) fera cela pour tous les montages avec l'option de montage x-systemd.validatefs dans /etc/fstab.

L'outil systemd-repart(8) génère automatiquement ces attributs étendus pour les systèmes de fichiers qu'il assemble, ce qui peut être contrôlé avec l'option de configuration AddValidateFS=.

OPTIONS

L'exécutable /usr/lib/systemd/system-validatefs peut également être appelé depuis la ligne de commande, où il attend un chemin vers un montage et les options suivantes :

--root=

Prend un chemin absolu ou la chaîne spéciale "auto". Le chemin spécifié est supprimé en tant que préfixe de l'argument du point de montage spécifié avant la validation. S'il est défini sur "auto", il est indéfini sur l'hôte et /sysroot/ lorsqu'il est exécuté dans le contexte initrd, afin de valider les données de contrainte de montage par rapport à la future racine du système de fichiers.

-h, --help

Affiche un bref message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.
