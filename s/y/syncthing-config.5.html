NOM

syncthing-config - Configuration de Syncthing

APERÇU

Cette page décrit comment configurer Syncthing pour la synchronisation de fichiers, y compris la configuration des appareils, la configuration des dossiers, les paramètres de connexion et diverses méthodes de configuration via l'interface graphique web, la ligne de commande ou l'édition directe du fichier.

EMPLACEMENTS DES FICHIERS DE CONFIGURATION

Les emplacements par défaut pour le répertoire de configuration et de base de données sont :

$XDG_STATE_HOME/syncthing
$HOME/.local/state/syncthing
$HOME/Library/Application Support/Syncthing
%LOCALAPPDATA%\Syncthing

DESCRIPTION

Modifié dans la version 1.27.0 : L'emplacement par défaut du répertoire de configuration et de base de données sur les systèmes de type Unix a été modifié pour devenir $XDG_STATE_HOME/syncthing ou $HOME/.local/state/syncthing. Auparavant, l'emplacement par défaut de la configuration était $XDG_CONFIG_HOME/syncthing ou $HOME/.config/syncthing. Le répertoire de base de données était précédemment $HOME/.config/syncthing ou, si la variable d'environnement était définie, $XDG_DATA_HOME/syncthing. Les installations existantes peuvent encore utiliser ces répertoires au lieu des nouveaux paramètres par défaut.

Ajouté dans la version 1.5.0 : La base de données et la configuration peuvent maintenant être définies séparément. Auparavant, la base de données était toujours située dans le même répertoire que la configuration.

Syncthing utilise un seul répertoire pour stocker la configuration et les clés cryptographiques. Syncthing conserve également une base de données d'index avec les métadonnées des fichiers qui est, par défaut, stockée dans le même répertoire, bien que cela puisse être remplacé.

L'emplacement par défaut est $XDG_STATE_HOME/syncthing ou $HOME/.local/state/syncthing (Unix-like), $HOME/Library/Application Support/Syncthing (Mac), ou %LOCALAPPDATA%\Syncthing (Windows). Il peut être modifié à l'exécution en utilisant les options --config ou --home, ou les variables d'environnement correspondantes ($STCONFDIR ou STHOMEDIR). Les fichiers suivants se trouvent dans ce répertoire :

config.xml
Le fichier de configuration, au format XML.
cert.pem, key.pem
La clé publique et privée de l'appareil. Elles constituent la base de l'ID de l'appareil. La clé doit rester privée.
https-cert.pem, https-key.pem
Le certificat et la clé pour les connexions GUI HTTPS. Ils peuvent être remplacés par un certificat personnalisé pour HTTPS selon les besoins.

La base de données est, par défaut, stockée dans le même répertoire que la configuration, mais son emplacement peut être remplacé par les options --data ou --home, ou les variables d'environnement correspondantes ($STDATADIR ou STHOMEDIR).

Le répertoire de la base de données contient, entre autres, les fichiers suivants :

index-*
La base de données contenant les métadonnées et les sommes de contrôle des fichiers actuellement sur le disque et disponibles auprès des pairs.
syncthing.log
La sortie du journal, sur certains systèmes.
audit-*.log
Données du journal d'audit, lorsque celui-ci est activé.
panic-*.log
Données du journal de plantage, lorsque cela est requis.

# ÉLÉMENT FOLDER Un ou plusieurs éléments folder doivent être présents dans le fichier. Chaque élément décrit un dossier. Les attributs suivants peuvent être définis sur l'élément folder :
id (obligatoire)
L'ID du dossier, qui doit être unique.
label
L'étiquette d'un dossier est un nom local lisible par l'homme et descriptif. Peut être différent sur chaque périphérique, vide et/ou identique à d'autres étiquettes de dossier. (facultatif)
filesystemType
L'implémentation du système de fichiers interne utilisée pour accéder à ce dossier, détaillée dans un chapitre séparé.
path (obligatoire)
Le chemin d'accès au répertoire où le dossier est stocké sur ce périphérique ; non envoyé aux autres périphériques.
type
Contrôle la manière dont le dossier est géré par Syncthing. Les valeurs possibles sont :
sendreceive
Le dossier est en mode par défaut. Envoi des modifications locales et acceptation des modifications distantes. Notez que ce type était précédemment appelé "readwrite", qui est déprécié mais toujours accepté dans les configurations entrantes.
sendonly
Le dossier est en mode "send only" – il ne sera pas modifié par Syncthing sur ce périphérique. Notez que ce type était précédemment appelé "readonly", qui est déprécié mais toujours accepté dans les configurations entrantes.
receiveonly
Le dossier est en mode "receive only" – il ne propagera pas les modifications aux autres périphériques.
receiveencrypted
Doit être utilisé sur des périphériques non fiables, où les données ne peuvent pas être déchiffrées car aucun mot de passe de dossier n'a été saisi. Voir Périphériques non fiables (chiffrés).
rescanIntervalS
L'intervalle de réanalyse, en secondes. Peut être défini sur 0 pour désactiver lorsque des plugins externes sont utilisés pour déclencher les réanalyses.
fsWatcherEnabled
S'il est défini sur true, cela détecte les modifications apportées aux fichiers dans le dossier et les analyse.
fsWatcherDelayS
La durée pendant laquelle les modifications détectées sont accumulées, avant qu'une analyse ne soit planifiée (prend effet uniquement si fsWatcherEnabled est défini sur true).
fsWatcherTimeoutS
fsWatcherTimeoutS
Le délai maximum avant le déclenchement d'une analyse lorsqu'un fichier change continuellement. Si non défini ou zéro, une valeur par défaut est calculée en fonction de fsWatcherDelayS.
ignorePerms
Si vrai, les fichiers provenant de ce dossier seront annoncés aux appareils distants avec le drapeau « pas de bits de permission ». Les appareils distants utiliseront leur propre paramètre de permission par défaut lors de la création des fichiers. Le cas d'utilisation principal est pour les systèmes de fichiers qui ne prennent pas en charge les permissions, tels que FAT, ou les environnements où la modification des permissions est impossible.
autoNormalize
Correction automatique des erreurs de normalisation UTF-8 trouvées dans les noms de fichiers. Le mécanisme et comment le configurer sont décrits dans un chapitre séparé.

Les éléments enfants suivants peuvent exister :

device
Ceux-ci doivent avoir l'attribut id et peuvent avoir un attribut introducedBy, identifiant l'appareil qui nous a fait partager ce dossier avec l'appareil donné. Si l'introducteur d'origine cesse de partager ce dossier avec cet appareil, notre appareil suivra et cessera de partager le dossier (sous réserve que skipIntroductionRemovals soit faux sur l'appareil introducteur).

Tous les appareils mentionnés sont ceux qui partageront le dossier en question. Chaque appareil mentionné doit avoir un élément device distinct plus loin dans le fichier. Il est d'usage que l'ID de l'appareil local soit inclus dans tous les dossiers. Syncthing l'ajoutera actuellement automatiquement s'il n'est pas présent dans le fichier de configuration.

L'élément enfant encryptionPassword contient le secret nécessaire pour déchiffrer les données de ce dossier sur l'appareil distant. S'il est laissé vide, les données sont accessibles en clair (mais toujours protégées par le chiffrement du transport). Le mécanisme et comment le configurer sont décrits dans un chapitre séparé.

minDiskFree
L'espace libre minimum requis qui devrait être disponible sur le disque où réside ce dossier. Le dossier s'arrêtera lorsque la valeur tombera en dessous du seuil. Le contenu de l'élément est interprété selon l'attribut unit donné. Les valeurs acceptées pour unit sont % (pour cent de la taille du disque / volume), kB, MB, GB et TB. Définir à zéro désactive cette fonctionnalité.
versioning
Spécifie une configuration de versionnage.

Versionnage de fichiers

hashers
Le nombre de routines de copie et de hachage à utiliser, ou 0 pour les optimaux déterminés par le système. Ce sont des options de performance de bas niveau réservées aux utilisateurs avancés ; ne modifiez pas ces valeurs à moins d'y être invité ou si vous avez réellement lu et compris le code vous-même. :)
pullerMaxPendingKiB
Contrôle quand nous arrêtons d'envoyer des requêtes à d'autres appareils une fois que nous avons cette quantité de requêtes non servies. Le nombre de téléchargeurs est ajusté automatiquement en fonction de cette quantité souhaitée de données de requêtes en suspens.
order
L'ordre dans lequel les fichiers nécessaires doivent être téléchargés depuis le cluster. Cela n'a aucun effet lorsque le type de dossier est « envoyer uniquement ». Les valeurs possibles sont :
random (par défaut)
Télécharge les fichiers dans un ordre aléatoire. Cela optimise l'équilibrage des ressources entre les appareils d'un cluster.
alphabetic
Télécharge les fichiers dans l'ordre alphabétique des noms de fichiers.
smallestFirst, largestFirst
Télécharge les fichiers dans l'ordre de taille de fichier ; le plus petit et le plus grand d'abord respectivement.
oldestFirst, newestFirst
Télécharge les fichiers dans l'ordre de date de modification ; le plus ancien et le plus récent d'abord respectivement.

Notez que les fichiers analysés sont envoyés par lots et le tri ne s'applique qu'aux fichiers déjà découverts. Cela signifie que la synchronisation peut commencer par un fichier de 1 Go même s'il existe un fichier de 1 Ko disponible sur l'appareil source jusqu'à ce que le fichier de 1 Ko soit connu de l'appareil de téléchargement.

ignoreDelete
AVERTISSEMENT :
L'activation de cette option est fortement déconseillée - utilisez-la à vos propres risques. Vous avez été prévenu.

Lorsqu'il est défini sur vrai, cet appareil prétendra ne pas voir les instructions de suppression de fichiers provenant d'autres appareils. Le mécanisme est décrit dans un chapitre séparé.

scanProgressIntervalS
L'intervalle en secondes auquel les informations de progression de l'analyse sont envoyées à l'interface graphique. Définir à 0 fera utiliser à Syncthing la valeur par défaut de deux. Si vous n'avez pas besoin de voir la progression de l'analyse, définissez-le à -1 pour la désactiver.
pullerPauseS
Ajustement pour limiter le débit du téléchargeur lors de la nouvelle tentative de téléchargement de fichiers. Ne modifiez pas cette valeur à moins de savoir ce que vous faites.
maxConflicts
Le nombre maximum de copies de conflit à conserver pour un fichier donné. La valeur par défaut est 10. -1 signifie un nombre illimité. La définir à 0 désactive complètement les copies de conflit.
disableSparseFiles
Par défaut, les blocs contenant uniquement des zéros ne sont pas écrits, ce qui rend les fichiers éparpillés sur les systèmes de fichiers qui prennent en charge cette fonctionnalité. Lorsqu'il est défini sur vrai, les fichiers éparpillés ne seront pas créés.
paused
Vrai si ce dossier est (temporairement) suspendu.
markerName
Nom d'un répertoire ou d'un fichier dans la racine du dossier à utiliser comme marqueur - voir la FAQ sur les marqueurs pour son utilité. Un répertoire marqueur n'est créé par Syncthing que pour le .stfolder par défaut, pas autrement.
copyOwnershipFromParent
Sur les systèmes Unix, essaie de copier la propriété du fichier/dossier du répertoire parent (le répertoire dans lequel il se trouve). Nécessite l'exécution de Syncthing en tant qu'utilisateur privilégié, ou l'octroi de capacités supplémentaires (par exemple, CAP_CHOWN sous Linux).
modTimeWindowS
Différence autorisée de l'horodatage de modification lors de la comparaison des fichiers pour l'équivalence. À utiliser sur les systèmes de fichiers dont les horodatages de modification sont instables et peuvent changer après avoir été enregistrés lors de la dernière opération d'écriture. La valeur par défaut est 2 sur Android lorsque le dossier est situé sur une partition FAT, et 0 sinon.
maxConcurrentWrites
Nombre maximum d'opérations d'écriture simultanées lors de la synchronisation. L'augmentation de cette valeur peut améliorer ou dégrader les performances du disque, en fonction du stockage sous-jacent. La valeur par défaut est 16.
disableFsync
AVERTISSEMENT :
Ceci est une option connue pour être non sécurisée - utilisez-la à vos propres risques.

Désactive la validation des opérations sur fichier sur le disque avant de les enregistrer dans la base de données. La désactivation de fsync peut entraîner une corruption des données. Le mécanisme est décrit dans un chapitre séparé.

blockPullOrder
Ordre dans lequel les blocs d'un fichier sont téléchargés. Cette option contrôle la rapidité avec laquelle différentes parties du fichier se propagent entre les appareils connectés, au détriment d'une contrainte sur le stockage.

Options disponibles :

standard (par défaut)
Les blocs d'un fichier sont divisés en N séquences continues égales, où N est le nombre d'appareils connectés. Chaque appareil commence à télécharger sa propre séquence, après quoi il choisit aléatoirement les séquences des autres appareils. Offre une distribution de données acceptable et une contrainte minimale sur les disques rotatifs.
random
Les blocs d'un fichier sont téléchargés dans un ordre aléatoire. Offre une excellente distribution des données, mais est très exigeant pour les disques rotatifs.
inOrder
Les blocs d'un fichier sont téléchargés séquentiellement, du début à la fin. Convivial pour les disques rotatifs, mais n'apporte aucune amélioration à la distribution des données.
copyRangeMethod
Propose un choix de méthode pour copier des données entre fichiers. Cela peut être utilisé pour optimiser les copies sur les systèmes de fichiers réseau, améliorer la vitesse des copies volumineuses ou cloner les données en utilisant la fonctionnalité de copie sur écriture si le
que le système de fichiers sous-jacent le prenne en charge. Le mécanisme est décrit dans un chapitre séparé.
caseSensitiveFS
Affecte les performances en désactivant les vérifications de sécurité supplémentaires pour les systèmes de fichiers insensibles à la casse. Le mécanisme et la manière de le configurer sont décrits dans un chapitre séparé.
junctionsAsDirs
Les jonctions de répertoires NTFS sont traitées comme des répertoires ordinaires, si ce paramètre est défini sur true.
syncOwnership
La propriété des fichiers et des répertoires est synchronisée lorsque ce paramètre est défini sur true. Voir syncOwnership pour plus d'informations.
sendOwnership
Les informations de propriété des fichiers et des répertoires sont analysées lorsque ce paramètre est défini sur true. Voir sendOwnership pour plus d'informations.
syncXattrs
Les attributs étendus des fichiers et des répertoires sont synchronisés lorsque ce paramètre est défini sur true. Voir syncXattrs pour plus d'informations.
sendXattrs
Les attributs étendus des fichiers et des répertoires sont analysés et envoyés à d'autres appareils lorsque ce paramètre est défini sur true. Voir sendXattrs pour plus d'informations.

L'ID de l'appareil.
name
Un nom convivial pour l'appareil. (optionnel)
compression
Indique s'il faut utiliser la compression du protocole lors de l'envoi de messages à cet appareil. Les valeurs possibles sont :
metadata
Compresse les paquets de métadonnées, tels que les informations d'index. Les métadonnées sont généralement très propices à la compression, c'est donc un bon réglage par défaut.
always
Compresse tous les paquets, y compris les données de fichiers. Ceci est recommandé si le contenu des dossiers est principalement constitué de données compressibles telles que des documents ou des fichiers texte.

Défini sur vrai si cet appareil doit être considéré comme un introducteur, c'est-à-dire si nous devons copier sa liste d'appareils par dossier lors de la connexion.

VOIR AUSSI :

Configuration de l'introducteur
skipIntroductionRemovals
Défini sur vrai si vous souhaitez suivre uniquement les introductions et non les désintroductions. Par exemple, si cela est défini, nous ne supprimerions pas un appareil auquel nous avons été introduits, même si l'introducteur d'origine ne liste plus l'appareil distant comme connu.
introducedBy
Définit quel appareil nous a présenté à cet appareil. Utilisé uniquement pour suivre les désintroductions.
certName
Le nom commun du certificat de l'appareil, s'il ne s'agit pas du nom par défaut “syncthing”.

Parmi les éléments enfants suivants, au moins un enfant address doit exister.

address (obligatoire : Au moins un doit être présent.)
Contient une adresse ou un nom d'hôte à utiliser lors de la tentative de connexion à cet appareil. Les entrées autres que dynamic nécessitent un préfixe spécifique au protocole. Pour le protocole TCP, les préfixes tcp:// (double pile), tcp4:// (IPv4 uniquement) ou tcp6:// (IPv6 uniquement) peuvent être utilisés. Les préfixes pour le protocole QUIC sont analogues : quic://, quic4:// et quic6:// Notez que les adresses IP n'ont pas besoin d'utiliser de préfixes IPv4 ou IPv6 ; ceux-ci sont facultatifs. Les formats acceptés sont :
Adresse IPv4 (tcp://192.0.2.42)
Le port par défaut (22000) est utilisé.
Adresse IPv4 et port (tcp://192.0.2.42:12345)
L'adresse et le port sont utilisés tels quels.
Adresse IPv6 (tcp://[2001:db8::23:42])
Le port par défaut (22000) est utilisé. L'adresse doit être entourée de crochets.
Adresse IPv6 et port (tcp://[2001:db8::23:42]:12345)
L'adresse et le port sont utilisés tels quels. L'adresse doit être entourée de crochets.
Nom d'hôte (tcp6://fileserver)
Le nom d'hôte sera utilisé sur le port par défaut (22000) et les connexions ne seront tentées qu'en IPv6.
Nom d'hôte et port (tcp://fileserver:12345)
Le nom d'hôte sera utilisé sur le port donné et les connexions seront tentées en IPv4 et IPv6, en fonction de la résolution du nom.
dynamic
Le mot dynamic (sans préfixe) signifie utiliser la découverte locale et globale pour trouver l'appareil.

Syncthing Configuration Options

This document describes the configuration options for Syncthing. The configuration is stored in the file named config.xml in the Syncthing configuration directory. It is an XML file and should not be edited manually unless you know what you are doing.

The main element in the configuration file is <configuration>, which contains two child elements: <nodes> and <options>.

Nodes

The nodes element contains the configuration for all the remote devices that Syncthing is aware of. It has no attributes and contains zero or more <node> elements.

Node

The node element describes a single remote device. It has the following attributes:

id
The unique device ID of the remote device. This is mandatory.
name
A human readable name for the remote device. Optional.
addresses
A comma separated list of addresses to connect to the remote device. The syntax is the same as for Listen Addresses. If omitted, Syncthing will rely on discovery and global announce.
introducer
If set to true, this device will be announced to its introducer, and will not announce itself. This is used to establish a chain of trust, where the introducer is trusted to announce its peers. This is useful in environments where devices may not be directly discoverable, but the introducer is.
skipIntroShortID
If set to true, this device will not announce itself to its introducer using its short ID. This is useful when you want to prevent devices from being announced to the introducer, but still want to be able to connect to them.
noProxy
If set to true, Syncthing will not try to connect to this device via a relay. This is useful for devices that are directly reachable.
insecureSkipTLSVerify
If set to true, Syncthing will not verify the TLS certificate of this device. This is insecure and should only be used if you know what you are doing.

The node element may contain zero or more <folder> elements.

Folder

The folder element describes a single folder to be shared. It has the following attributes:

id
The unique ID of the folder. This is mandatory.
label
A human readable label for the folder. Optional.
path
The local path to the folder. Mandatory.
type
The type of folder. May be one of:
  • sendreceive (default): Send and receive files.
  • sendonly: Only send files to other devices.
  • receiveonly: Only receive files from other devices.
  • freeze: Receive files but do not send.
ignorePermissions
If set to true, Syncthing will not attempt to preserve file permissions when syncing. This is useful on systems where permissions are not important or cannot be preserved.
ignoreDeletePermissions
If set to true, Syncthing will not attempt to preserve delete permissions when syncing. This is useful on systems where delete permissions are not important or cannot be preserved.
copyTimestamps
If set to true, Syncthing will attempt to preserve the modification time of files when syncing. This is generally desirable.
hashOrderStrategy
The strategy used to determine the order in which files are hashed. May be one of:
  • LEAST_BLOCKS (default): Hash files with the fewest blocks first.
  • MOST_BLOCKS: Hash files with the most blocks first.
  • NAME: Hash files in alphabetical order.
  • RANDOM: Hash files in random order.
pullOrderStrategy
The strategy used to determine the order in which files are pulled. May be one of:
  • RANDOM (default): Pull files in random order.
  • LEAST_BLOCKS: Pull files with the fewest blocks first.
  • MOST_BLOCKS: Pull files with the most blocks first.
  • NAME: Pull files in alphabetical order.
invalidIgnorePatterns
A comma-separated list of ignore patterns that are invalid. This is used internally by Syncthing to track invalid ignore patterns.
disableSparseFiles
If set to true, Syncthing will not use sparse files when writing files. This can be useful on filesystems that do not support sparse files or when performance is critical.
versioningType
The versioning strategy to use for this folder. May be one of:
  • none (default): No versioning.
  • keepRevisions: Keep a specified number of old revisions.
  • versionsUntilOlderThan: Keep revisions until they are older than a specified duration.
versioningParams
Parameters for the versioning strategy. This is a comma-separated list of key=value pairs. The keys and values depend on the versioningType. See the Syncthing documentation for details.
maxEntriesInRecycleBin
The maximum number of entries to keep in the recycle bin for versioned folders. Set to 0 to disable the recycle bin.
rotationsInRecycleBin
The number of rotations to keep in the recycle bin for versioned folders. A rotation is a set of files that were changed in a single operation. Set to 0 to disable the recycle bin.
fsWatcherEnabled
Whether to enable filesystem watcher for this folder. If enabled, Syncthing will be notified of changes in the folder by the operating system, rather than polling the directory.
fsWatcherDelayS
The delay in seconds after a filesystem event before Syncthing processes it. This is useful to avoid multiple events for the same change.
fsWatcherPollIntervalS
The interval in seconds for polling the directory if the filesystem watcher is disabled or not available. Defaults to 60.
disablePermissions
If set to true, Syncthing will not attempt to preserve file permissions when syncing. This is equivalent to setting ignorePermissions to true.

The listen address for incoming sync connections. See Listen Addresses for the allowed syntax. To configure multiple addresses, you can either: repeat <listenAddress> tags in the configuration file or enter several addresses separated by commas in the GUI.

The syntax for non-default entries is that of an HTTP or HTTPS URL. The device ID to use is printed by the discovery server on startup. To configure multiple servers, you can either: repeat <globalAnnounceServer> tags in the configuration file or enter several servers separated by commas in the GUI.

Whether to send announcements to the local LAN, also use such announcements to find other devices.

Outgoing data rate limit, in kibibytes per second.

Incoming data rate limits, in kibibytes per second.

NOM

syncthing-config - Fichier de configuration de Syncthing

APERÇU

Le fichier de configuration principal de Syncthing, config/config.xml, décrit la façon dont Syncthing est configuré pour fonctionner.

EMPLACEMENTS DU FICHIER DE CONFIGURATION

Le fichier de configuration est stocké à:

Linux:
~/.config/syncthing/config.xml
FreeBSD:
~/.config/syncthing/config.xml
macOS:
~/Library/Application Support/Syncthing/config.xml
Windows:
%LOCALAPPDATA%\Syncthing\config.xml
Android:
Internal storage/Syncthing/config.xml
OpenBSD:
~/.config/syncthing/config.xml

Il peut également être spécifié via l'argument de ligne de commande --config=path.

DESCRIPTION

Le fichier de configuration est un fichier XML décrivant tous les paramètres globaux, les éléments partagés, les appareils distants et leurs propriétés.

FORMAT DU FICHIER DE CONFIGURATION

Le fichier de configuration est un fichier XML valide. Il doit contenir un élément racine unique, <configuration>, qui peut contenir plusieurs éléments enfants.

ÉLÉMENT DE CONFIGURATION

L'élément racine du fichier de configuration.

version
Entier. Indique la version du schéma de configuration. Doit être 2.

ÉLÉMENT DOSSIER

Chaque dossier synchronisé est représenté par un élément <folder>. Les éléments enfants suivants sont acceptés:

id
Chaîne. Identifiant unique du dossier. Il est généré et ne doit jamais être modifié manuellement.
label
Chaîne. Un nom convivial pour le dossier, utilisé dans l'interface graphique.
path
Chaîne. Le chemin d'accès au dossier sur le système de fichiers local.
type
Chaîne. Indique si le dossier est partagé avec d'autres appareils. Les valeurs possibles sont sendreceive (par défaut), sendonly et readonly.
rescanIntervalS
Entier. L'intervalle de temps en secondes entre les vérifications des modifications dans le dossier. La valeur 0 désactive la recherche automatique.
ignorePerms
Booléen. Si défini à true, les permissions des fichiers ne seront pas synchronisées.
isDeleted
Booléen. Si défini à true, le dossier est marqué comme supprimé et ne sera plus synchronisé. Utilisé pour la suppression propre.
versioningEnabled
Booléen. Si défini à true, la gestion des versions est activée pour ce dossier.
versioningKeepNum
Entier. Nombre de versions de fichiers à conserver. S'applique uniquement si versioningEnabled est défini à true.
versioningKeepTime
Entier. Durée pendant laquelle conserver les versions de fichiers en secondes. S'applique uniquement si versioningEnabled est défini à true.
versioningType
Chaîne. Type de gestion des versions. Les valeurs possibles sont versions (par défaut) et trash.
hashers
Chaîne. Algorithmes de hachage à utiliser pour la détection des doublons. Les valeurs possibles sont ahu (par défaut) et blockchain.
fsWatcherDelayS
Entier. Délai en secondes avant de traiter les modifications du système de fichiers. La valeur 0 désactive le watcher.
maxConflicts
Entier. Nombre maximal de conflits à conserver pour chaque fichier. La valeur 0 désactive la conservation des conflits.

ÉLÉMENT APPAREIL

Chaque appareil distant auquel Syncthing se connecte est représenté par un élément <device>. Cet élément peut apparaître à la fois dans l'élément <device> racine et à l'intérieur d'un élément <folder>.

id
Chaîne. L'ID de l'appareil distant. Obligatoire.
name
Chaîne. Un nom convivial pour l'appareil, utilisé dans l'interface graphique.
addresses
Liste d'adresses séparées par des virgules. Indique les adresses où l'appareil peut être contacté. Si vide, Syncthing essaiera de découvrir l'adresse via le protocole de découverte.
introducer
Booléen. Si défini à true, cet appareil est un introducteur. Les nouveaux appareils tenteront de se connecter via cet appareil.
skipIntroductionSummary
Booléen. Si défini à true, Syncthing n'enverra pas de résumé d'introduction à cet appareil.
paused
Booléen. Si défini à true, la synchronisation avec cet appareil est mise en pause.
compression
Chaîne. Niveau de compression à utiliser pour la communication avec cet appareil. Les valeurs possibles sont disabled, local, metadata, standard (par défaut), max.

ÉLÉMENT GUI

Définit les paramètres de l'interface graphique.

theme
Chaîne. Thème de l'interface graphique. Les valeurs possibles sont auto (par défaut), light et dark.
userLogin
Booléen. Si défini à true, l'authentification utilisateur est activée pour l'accès à l'interface graphique.
theme-variant
Chaîne. Variante de thème. Les valeurs possibles sont default, darker, lightest.
title
Chaîne. Titre personnalisé affiché dans la barre d'en-tête.

ÉLÉMENT LDAP

Configure la connexion au service d'annuaire LDAP.

server
Chaîne. L'URL du serveur LDAP (par exemple, ldap://ldap.example.com).
user
Chaîne. Le nom d'utilisateur à utiliser pour la connexion.
password
Chaîne. Le mot de passe à utiliser pour la connexion.
baseDN
Chaîne. Le DN de base pour la recherche d'utilisateurs.
userFilter
Chaîne. Un filtre LDAP pour trouver les utilisateurs.
attributeMap
Chaîne. Mappage des attributs LDAP aux attributs Syncthing.

ÉLÉMENT OPTIONS

Définit les options globales de Syncthing.

listenAddress
Liste d'adresses séparées par des virgules. Les adresses où Syncthing écoutera les connexions entrantes.
globalAnnounceServer
Chaîne. L'URL du serveur d'annonce globale.
localAnnounceServers
Liste d'adresses séparées par des virgules. Serveurs d'annonce locale.
announceServer
Chaîne. Serveur d'annonce à utiliser.
tcpTimeoutS
Entier. Délai d'attente TCP en secondes.
tcpConnectTimeoutS
Entier. Délai d'attente de connexion TCP en secondes.
tcpKeepAliveS
Entier. Intervalle de keep-alive TCP en secondes.
udpTimeoutS
Entier. Délai d'attente UDP en secondes.
udpMessageTimeoutS
Entier. Délai d'attente des messages UDP en secondes.
tlsKexTimeoutS
Entier. Délai d'attente d'échange de clés TLS en secondes.
tlsInsecureSkipCertVerify
Booléen. Si défini à true, la vérification des certificats TLS est ignorée.
tlsMaxVersion
Entier. Version maximale de TLS autorisée.
tlsMinVersion
Entier. Version minimale de TLS autorisée.
natEnabled
Booléen. Si défini à true, la découverte et le traversage de NAT sont activés.
natRateLimit
Entier. Limite de débit pour le traversage de NAT.
bindAddresses
Liste d'adresses séparées par des virgules. Adresses sur lesquelles Syncthing écoutera les connexions locales (par exemple, pour l'API).
diskUsageEnabled
Booléen. Si défini à true, l'utilisation du disque est activée.
urandomRSS
Entier. Taille du tampon de lecture du fichier système /dev/urandom en octets.
parallelRequests
Entier. Nombre de requêtes parallèles à envoyer aux appareils distants.
defaultFolderPermissions
Chaîne. Permissions par défaut pour les nouveaux dossiers créés.
defaultFolderType
Chaîne. Type par défaut pour les nouveaux dossiers.
defaultFolderRescanIntervalS
Entier. Intervalle de re-scan par défaut pour les nouveaux dossiers.
defaultFolderVersioningEnabled
Booléen. Si défini à true, la gestion des versions est activée par défaut pour les nouveaux dossiers.
defaultFolderVersioningKeepNum
Entier. Nombre de versions par défaut à conserver.
defaultFolderVersioningKeepTime
Entier. Durée par défaut de conservation des versions en secondes.
defaultFolderVersioningType
Chaîne. Type de gestion des versions par défaut.
defaultFolderHashers
Chaîne. Algorithmes de hachage par défaut.
defaultFolderFsWatcherDelayS
Entier. Délai du watcher du système de fichiers par défaut en secondes.
defaultFolderMaxConflicts
Entier. Nombre maximal de conflits par défaut.
disableClientTLSAuth
Booléen. Si défini à true, l'authentification TLS client est désactivée.
devMode
Booléen. Si défini à true, active le mode développeur.
batchMode
Booléen. Si défini à true, Syncthing s'exécute en mode batch (sans interface graphique).
noPauseOnRemoteNetworkChanges
Booléen. Si défini à true, Syncthing ne met pas en pause les synchronisations lorsque les modifications du réseau distant sont détectées.

ÉLÉMENT DEFAULTS

Définit les valeurs par défaut pour les nouveaux dossiers et appareils. Les éléments contenus ici sont des modèles pour les nouveaux éléments ajoutés. Toute modification apportée ici sera appliquée aux nouveaux éléments créés par la suite.

folder
Modèle pour un élément folder, avec la même structure interne. Tous les champs ici seront utilisés pour un nouveau dossier partagé. L'attribut id n'a aucun sens dans ce contexte.

L'interface graphique proposera de créer de nouveaux dossiers au chemin indiqué dans l'attribut path (anciennement defaultFolderPath sous options). Cela s'applique également aux dossiers automatiquement acceptés d'un appareil distant.

Même le partage avec d'autres appareils distants peut être effectué dans le modèle en incluant l'élément approprié folder.device en dessous.

ignores
Ajouté dans la version 1.19.0.

Modèle pour les modèles d'exclusion appliqués aux nouveaux dossiers. Ceux-ci sont copiés dans le fichier .stignore lorsqu'un dossier est automatiquement accepté d'un appareil distant. L'interface graphique les utilise également pour pré-remplir le champ respectif lors de l'ajout d'un nouveau dossier. En XML, chaque ligne de modèle est représentée par un élément <line>.

Adresses d’écoute

Les types d'adresses suivants sont acceptés dans les adresses d'écoute du protocole de synchronisation. Si vous souhaitez que Syncthing écoute sur plusieurs adresses, vous pouvez soit : répéter les balises <listenAddress> dans le fichier de configuration, soit entrer plusieurs adresses séparées par des virgules dans l'interface graphique.

Adresses d'écoute par défaut (default)
Ceci est équivalent à tcp://0.0.0.0:22000, quic://0.0.0.0:22000 et dynamic+https://relays.syncthing.net/endpoint.
Adresse générique et port TCP (tcp://0.0.0.0:22000, tcp://:22000)
Ceci est équivalent et entraînera l'écoute de Syncthing sur toutes les interfaces, IPv4 et IPv6, sur le port spécifié.
Adresse générique IPv4 et port TCP (tcp4://0.0.0.0:22000, tcp4://:22000)
Ceci est équivalent et entraînera l'écoute de Syncthing sur toutes les interfaces via IPv4 uniquement.
Adresse et port IPv4 TCP (tcp4://192.0.2.1:22000)
Ceci entraîne l'écoute de Syncthing sur l'adresse et le port spécifiés, IPv4 uniquement.
Adresse générique IPv6 et port TCP (tcp6://[::]:22000, tcp6://:22000)
Ceci est équivalent et entraînera l'écoute de Syncthing sur toutes les interfaces via IPv6 uniquement.
Adresse et port IPv6 TCP (tcp6://[2001:db8::42]:22000)
Ceci entraîne l'écoute de Syncthing sur l'adresse et le port spécifiés, IPv6 uniquement.
Adresse et port QUIC (par ex. quic://0.0.0.0:22000)
La syntaxe est la même que pour TCP, quic4 et quic6 peuvent également être utilisés.
Adresse de relais statique (relay://192.0.2.42:22067?id=abcd123...)
Syncthing se connectera et écoutera les connexions entrantes via l'adresse de relais spécifiée.

SYNCHRONISATION DES FICHIERS DE CONFIGURATION

La synchronisation des fichiers de configuration entre appareils (de telle sorte que plusieurs appareils utilisent les mêmes fichiers de configuration) peut causer des problèmes. Ceci est facile à faire accidentellement si vous synchronisez votre dossier personnel entre appareils. Un symptôme courant de la synchronisation des fichiers de configuration est que deux appareils se retrouvent avec le même ID d'appareil.

Si vous souhaitez utiliser Syncthing pour sauvegarder vos fichiers de configuration, il est recommandé que les fichiers que vous sauvegardez soient dans un Dossier en lecture seule pour empêcher d'autres appareils d'écraser la configuration spécifique à chaque appareil. Le dossier sur l'appareil (les) distant (s) ne doit pas être utilisé comme configuration pour les appareils distants.

Si vous souhaitez synchroniser votre dossier personnel en mode autre qu'en lecture seule, vous pouvez ajouter le dossier qui stocke les fichiers de configuration à la liste d'exclusion. Si vous souhaitez également sauvegarder vos fichiers de configuration, ajoutez un autre dossier en mode lecture seule pour le dossier de configuration uniquement.
