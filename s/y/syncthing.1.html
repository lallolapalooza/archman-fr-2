NOM

syncthing - Syncthing

SYNTAXE

DESCRIPTION

Syncthing permet de synchroniser vos fichiers de manière bidirectionnelle sur plusieurs appareils. Cela signifie que la création, la modification ou la suppression de fichiers sur une machine sera automatiquement répliquée sur vos autres appareils. Nous pensons que vos données vous appartiennent uniquement et que vous méritez de choisir où elles sont stockées. Par conséquent, Syncthing ne télécharge pas vos données dans le cloud mais les échange entre vos machines dès qu'elles sont en ligne en même temps.

L'application principale syncthing est un programme en ligne de commande qui s'exécute généralement en arrière-plan et gère la synchronisation. Elle fournit une interface utilisateur intégrée basée sur HTML et JavaScript pour être contrôlée depuis un navigateur web. Ce frontend communique avec l'application principale via des APIs HTTP, que d'autres applications comme des assistants d'intégration graphique du système peuvent également utiliser, pour une flexibilité maximale. Un lien pour accéder à l'interface graphique et aux APIs est imprimé parmi les premiers messages de journalisation.

OPTIONS COMMUNES

--home=<dir>, -H <dir> ($STHOMEDIR)
Définit le répertoire commun de configuration et de données. Le répertoire de configuration par défaut est $XDG_STATE_HOME/syncthing ou $HOME/.local/state/syncthing (systèmes Unix-like), $HOME/Library/Application Support/Syncthing (Mac) et %LOCALAPPDATA%\Syncthing (Windows).
--config=<dir>, -C <dir> ($STCONFDIR)
Définit le répertoire de configuration. Alternative à --home et doit être utilisé conjointement avec --data.
--data=<dir>, -D <dir> ($STDATADIR)
Définit le répertoire de données (par exemple, la base de données). Alternative à --home et doit être utilisé conjointement avec --config.
--help, -h
Affiche le texte d'aide sur l'utilisation de la ligne de commande. Contexte sensible en fonction de la sous-commande donnée.

OPTIONS SERVEUR

--allow-newer-config ($STALLOWNEWERCONFIG)
Tente de charger un fichier de configuration écrit par une version plus récente du programme, au lieu d'échouer immédiatement.
--audit ($STAUDIT)
Écrit les événements dans un fichier horodaté audit-AAAA-MMJJ-HHMMSS.log.
--auditfile=<file|-|--> ($STAUDITFILE)
Utilise le fichier spécifié ou le flux ("-" pour stdout, "--" pour stderr) pour les événements d'audit, au lieu du nom de fichier par défaut horodaté.
--db-maintenance-interval=<interval> ($STDBMAINTENANCEINTERVAL)
Intervalle de maintenance de la base de données – les routines de maintenance internes de la base de données s'exécutent aussi souvent. Le format est celui d'une chaîne de durée Go (voir https://pkg.go.dev/time#ParseDuration).
--db-delete-retention-interval=<interval> ($STDBDELETERETENTIONINTERVAL)
Intervalle de rétention des éléments supprimés dans la base de données – les éléments supprimés sont oubliés de la base de données après cet intervalle. Le format est celui d'une chaîne de durée Go (voir https://pkg.go.dev/time#ParseDuration).
--gui-address=<address> ($STGUIADDRESS)
Remplace l'adresse d'écoute de l'interface graphique. Définissez-la sur une adresse (0.0.0.0:8384) ou une URL (http://0.0.0.0:8384). Les schémas supportés sont http pour HTTP simple, https pour HTTP sur TLS, unix pour des sockets Unix simples ou unixs pour TLS sur sockets Unix. Un socket Unix pourrait ressembler à ceci : unix:///run/syncthing/syncthing.socket (notez les trois barres obliques : deux faisant partie de la structure de l'URL, une pour spécifier un chemin absolu).
--gui-apikey=<string> ($STGUIAPIKEY)
Remplace la clé API nécessaire pour accéder à l'interface graphique / API REST.
--log-file=<filename> ($STLOGFILE)
Définit le nom du fichier de destination pour la journalisation (utilisez "-" pour stdout, ce qui est l'option par défaut).
--log-level=<level> ($STLOGLEVEL)
Définit le niveau de journalisation pour tous les paquets. Les niveaux valides sont DEBUG, INFO, WARN et ERROR.
--log-max-old-files=<num> ($STLOGMAXOLDFILES)
Nombre de fichiers anciens à conserver (zéro pour ne conserver que le courant). S'applique uniquement lorsque la rotation des journaux est activée via --log-max-size.
--log-max-size=<num> ($STLOGMAXSIZE)
Taille maximale en octets de chaque fichier journal (zéro pour désactiver la rotation des journaux).
--log-format-timestamp=<format> ($STLOGFORMATTIMESTAMP)
Format de l'horodatage, défini sur vide pour désactiver les horodatages. Le format est celui du formateur de temps Go (voir https://pkg.go.dev/time#Layout).
--[no-]log-format-level-string ($STLOGFORMATLEVELSTRING
--log-format-level-syslog ($STLOGFORMATLEVELSYSLOG)
Utilise le formatage de niveau syslog. Cela désactive --log-format-level-string.
--no-browser ($STNOBROWSER)
Désactive le démarrage automatique du navigateur web lors du lancement de l'interface graphique.
--no-console ($STNOCONSOLE)
Désactive la sortie sur la console lors du lancement de l'interface graphique.
--no-port-probing ($STNOPORTPROBING)
Désactive le sondage des ports UPnP et WAN.
--no-restart ($STNORESTART)
Ne pas redémarrer automatiquement en cas de mise à jour.
--no-upgrade ($STNOUPGRADE)
Ne pas proposer de mises à jour automatiques.
--paused ($STPAUSED)
Démarrer Syncthing en mode pause (toutes les synchronisations sont suspendues).
--unpaused ($STUNPAUSED)
Démarrer Syncthing en mode débloqué (synchronisations actives).
--version
Affiche la version du programme et quitte.
--debug-*
Active les options de débogage supplémentaires. Utilisez --debug-help pour une liste.

SOUS-COMMANDES

Syncthing est une application polyvalente qui peut être utilisée de différentes manières. Les sous-commandes suivantes sont disponibles :

serve
Lance le serveur Syncthing. C'est le comportement par défaut si aucune sous-commande n'est spécifiée.
cli
Lance Syncthing en mode CLI (interface en ligne de commande). Permet d'interagir avec le serveur Syncthing en cours d'exécution via des commandes textuelles.
browser
Lance le navigateur web par défaut sur l'interface utilisateur de Syncthing. Ne fonctionne que si un serveur Syncthing est déjà en cours d'exécution.
decrypt
Déchiffre les fichiers chiffrés par Syncthing. Nécessite le chemin du fichier à déchiffrer et potentiellement un mot de passe ou un jeton.
device-id
Affiche l'identifiant de l'appareil Syncthing.
generate
Génère un certificat et une clé privés pour Syncthing. Utilisé lors de la configuration initiale.
paths
Affiche les chemins utilisés par Syncthing pour la configuration et les données.
upgrade
Tente de mettre à jour Syncthing vers la dernière version. Peut être utilisé avec l'option --check-only pour vérifier les mises à jour sans lancer la mise à jour.
version
Affiche la version actuelle de Syncthing et quitte.
debug
Exécute une commande de débogage spécifique. Utilisez --help pour voir les commandes de débogage disponibles.

EXEMPLES

Lancer Syncthing en arrière-plan, en utilisant les chemins par défaut pour la configuration et les données, et en ouvrant l'interface graphique dans le navigateur par défaut :

$ syncthing

Lancer Syncthing avec un répertoire de configuration et de données spécifique :

$ syncthing --home=/etc/syncthing --data=/var/syncthing/data

Démarrer Syncthing en mode pause et désactiver le démarrage automatique du navigateur :

$ syncthing --paused --no-browser

Vérifier les mises à jour de Syncthing sans les installer :

$ syncthing upgrade --check-only

Déchiffrer un fichier à l'aide d'un mot de passe :

$ syncthing decrypt --password="mypassword" /path/to/encrypted/file.syncthing-enc

Obtenir l'identifiant de l'appareil actuel :

$ syncthing device-id

Démarrer le serveur avec une adresse GUI spécifique et sans ouvrir automatiquement un navigateur :

$ syncthing --gui-address="http://127.0.0.1:8384" --no-browser

OPTIONS DE DÉCHIFFREMENT

--to=<répertoire>
Répertoire de destination où les fichiers doivent être stockés après le déchiffrement.
--verify-only
Ne pas écrire les fichiers déchiffrés sur le disque (mais vérifier les hachages en clair).
--password=<mdp> ($FOLDER_PASSWORD)
Mot de passe du dossier pour le déchiffrement / la vérification. Peut être passé via la variable d'environnement FOLDER_PASSWORD pour éviter l'enregistrement dans le tampon d'historique d'un shell ou l'espionnage depuis la liste des processus en cours d'exécution.
--folder-id=<id>
ID du dossier du dossier chiffré, s'il ne peut pas être déterminé automatiquement.
--token-path=<fichier>
Chemin d'accès au fichier de jeton dans le dossier (utilisé pour déterminer l'ID du dossier).
--continue
Continuer le traitement du fichier suivant en cas d'erreur, au lieu d'avorter.

OPTIONS DE GÉNÉRATION

--gui-password=<mot de passe|->
Spécifier un nouveau mot de passe d'authentification de l'interface graphique, pour mettre à jour le fichier de configuration. Lu depuis le flux d'entrée standard si seul un tiret (-) est fourni. Un mot de passe en clair est haché avant d'être écrit dans le fichier de configuration, mais une entrée déjà hachée bcrypt est stockée telle quelle. À titre de cas spécial, fournir le hachage du mot de passe existant comme mot de passe le laissera inchangé.
--gui-user=<nom d'utilisateur>
Spécifier un nouveau nom d'utilisateur d'authentification de l'interface graphique, pour mettre à jour le fichier de configuration.

OPTIONS DE MISE À NIVEAU

--check-only
Ne pas mettre à niveau, seulement indiquer si une mise à niveau est disponible.
--from=<url>
Mettre à niveau vers la version Syncthing disponible en chargeant le paquet à l'URL donnée.

CODES DE SORTIE

0
Succès / Arrêt
1
Erreur
2
Mise à niveau non disponible
3
Redémarrage
4
Mise à niveau en cours

Les codes de sortie supérieurs à 125 sont généralement retournés par le shell/le chargeur binaire/le gestionnaire de signaux par défaut. Les codes de sortie supérieurs à 128+N sur Unix représentent généralement le signal qui a provoqué la sortie du processus. Par exemple, 128 + 9 (SIGKILL) = 137.

SOUS-COMMANDES

La syntaxe de la ligne de commande prend en charge différents modes de fonctionnement via plusieurs sous-commandes, spécifiées comme premier argument. Si omise, la sous-commande par défaut serve est supposée.

La configuration initiale d'un ID d'appareil et de la configuration par défaut peut être appelée explicitement avec la sous-commande generate. Elle peut également mettre à jour les informations d'identification d'authentification de l'interface graphique configurées, sans passer par l'API REST. Un certificat d'appareil existant est laissé intact. Si le fichier de configuration existe déjà, il est validé et mis à jour vers le dernier schéma de configuration, y compris l'ajout de valeurs par défaut pour les nouvelles options.

La sous-commande decrypt est utilisée en conjonction avec les appareils non fiables (chiffrés), voir la section pertinente sur le déchiffrement pour plus de détails. Elle ne dépend pas de Syncthing en cours d'exécution, mais fonctionne sur des données hors ligne.

Pour travailler avec l'API REST pour le débogage ou l'automatisation de choses dans Syncthing, la sous-commande cli offre un accès facile aux fonctionnalités individuelles. Elle évite essentiellement les tracas liés à la gestion des connexions HTTP et à l'authentification API.

Les sous-commandes disponibles sont regroupées en plusieurs hiérarchies imbriquées et certaines parties sont générées dynamiquement à partir de l'instance Syncthing en cours d'exécution. À chaque niveau, l'option --help liste les propriétés, actions et commandes disponibles que l'utilisateur peut découvrir interactivement. Les groupes de premier niveau sont :

config
Accéder à la configuration en direct dans une instance en cours d'exécution via l'API REST pour récupérer (get) ou mettre à jour (set) des valeurs de manière granulaire. La hiérarchie est basée sur la même structure que celle utilisée dans les représentations JSON / XML.
show
Afficher les propriétés système et l'état d'une instance en cours d'exécution. La sortie est transmise directement depuis la réponse de l'API REST et nécessite donc l'analyse du format JSON.
operations
Contrôler le fonctionnement général du programme tel que le redémarrage ou la gestion des mises à niveau, ainsi que le déclenchement de certaines actions par dossier. Peut également configurer les motifs d'ignorance par défaut à partir d'un fichier d'ignorance en texte brut.
errors
Examiner les conditions d'erreur en attente qui nécessitent l'attention de l'utilisateur, ou les accuser (effacer).
debug
Divers outils pour aider au diagnostic des problèmes ou à la collecte d'informations pour les rapports de bug. Certaines de ces commandes accèdent directement à la base de données et ne peuvent donc fonctionner que lorsque Syncthing n'est pas en cours d'exécution.
- (un seul tiret)
Lit les commandes suivantes depuis le flux d'entrée standard, sans avoir besoin d'appeler la commande syncthing cli de manière répétée. Se termine sur toute commande invalide ou lors de la réception de EOF (fin de fichier).

PROCURATIONS

Syncthing peut utiliser une procuration SOCKS, HTTP ou HTTPS pour communiquer avec le monde extérieur. La procuration est utilisée uniquement pour les connexions sortantes - il n'est pas possible d'accepter des connexions entrantes via la procuration. La procuration est configurée via la variable d'environnement all_proxy. De manière quelque peu inhabituelle, cette variable doit être nommée en minuscules - ce n'est pas « ALL_PROXY ». Par exemple :

$ export all_proxy=socks://192.0.2.42:8081

PARAMÈTRES DE DÉVELOPPEMENT

Les variables d'environnement suivantes modifient le comportement de Syncthing de manière principalement utile pour les développeurs. À utiliser avec précaution. Si vous démarrez Syncthing à partir de gestionnaires de service comme systemd ou supervisor, l'expansion de chemin peut ne pas être prise en charge.

STTRACE
Utilisé pour augmenter la verbosité du débogage dans des installations spécifiques, correspondant généralement à un package Go. Entrez une chaîne de facilities séparées par des virgules à tracer : api,beacon. Facultativement, un niveau de journalisation peut être donné par facility pour spécifier autre chose que DEBUG : api:WARN,beacon:ERROR, pouvant remplacer un ajustement global de --log-level.

Utilisé pour le débogage des interblocages internes ; définit la sensibilité du débogage. À utiliser uniquement sur instruction d'un développeur.
STVERSIONEXTRA
Ajoute des informations supplémentaires à la chaîne de version dans les journaux et à la ligne de version dans l'interface graphique. Peut être défini sur le nom d'un wrapper ou d'un outil contrôlant syncthing pour le communiquer à l'utilisateur final.
GOMAXPROCS
Définit le nombre maximum de cœurs de processeur à utiliser. Par défaut, tous les cœurs de processeur disponibles.

Pourcentage de croissance du tas auquel déclencher le GC. Par défaut, 100. Des nombres plus bas réduisent l'utilisation maximale de la mémoire, au détriment de l'utilisation du processeur (c'est-à-dire la performance).
LOGGER_DISCARD
Astuce pour désactiver complètement la journalisation, par exemple lors de l'exécution de benchmarks. Définir sur toute valeur non vide pour l'utiliser.
