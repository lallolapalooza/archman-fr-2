NOM

systemd-network-generator.service, systemd-network-generator - Générer la configuration réseau à partir de la ligne de commande du noyau

SYNTAXE

systemd-network-generator.service

/usr/lib/systemd/systemd-network-generator

DESCRIPTION

systemd-network-generator.service est un service système qui traduit les paramètres ip= et similaires sur la ligne de commande du noyau (voir ci-dessous) en fichiers de configuration systemd.network(5), systemd.netdev(5), et systemd.link(5) compris par systemd-networkd.service(8) et systemd-udevd.service(8).

Les fichiers sont générés dans /run/systemd/network/.

Note : malgré son nom, ce générateur s'exécute en tant que service systemd normal et n'est pas une implémentation du concept de systemd.generator(7).

OPTIONS DE LA LIGNE DE COMMANDE DU NOYAU

Cet outil comprend les options suivantes :

ip=, nameserver=, rd.route=, rd.peerdns=

Traduit en fichiers systemd.network(5).

En plus des paramètres définis par dracut.cmdline(7), l'option ip= accepte la valeur spéciale "link-local". Si elle est sélectionnée, les interfaces réseau seront configurées uniquement pour une adressage de lien local (IPv4LL, IPv6LL), DHCP ou IPv6RA ne seront pas activés.

Ajouté dans la version 245.

ifname=, net.ifname_policy=

Traduit en fichiers systemd.link(5).

Ajouté dans la version 245.

vlan=, bond=, bridge=, bootdev=

Traduit en fichiers systemd.netdev(5).

Ajouté dans la version 245.

Voir dracut.cmdline(7) et systemd-udevd.service(8) pour la syntaxe et les détails des options.

IDENTIFIANTS

systemd-network-generator prend en charge la logique des identifiants de service implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

network.conf.*, network.link.*, network.netdev.*, network.network.*

Ces identifiants doivent contenir des données de configuration networkd.conf(5), systemd.link(5), systemd.netdev(5), systemd.network(5) valides. De chaque identifiant correspondant, un fichier séparé est créé. Exemple : un identifiant passé network.link.50-foobar sera copié dans un fichier de configuration 50-foobar.link.

Notez que les fichiers résultants sont créés avec une lecture publique, il est donc recommandé de ne pas inclure de secrets dans ces identifiants, mais de les fournir via des identifiants séparés directement à systemd-networkd.service(8).

Ajouté dans la version 256.

Notez que par défaut, le service systemd-networkd.service(8) est configuré pour hériter de ces identifiants du gestionnaire de service.
