SYSSTAT(5) Manuel de l'utilisateur Linux SYSSTAT(5)

NOM

sysstat - fichier de configuration de sysstat.

DESCRIPTION

Ce fichier est lu par les scripts shell sa1(8) et sa2(8) de la suite d'outils de sysstat. Il se compose d'une séquence d'assignments de variables shell utilisés pour configurer la journalisation de sysstat. Les variables et leur signification sont les suivantes :

COMPRESSAFTER
Nombre de jours après lequel les fichiers de données quotidiens doivent être compressés. Le programme de compression est indiqué dans la variable ZIP.
DELAY_RANGE
Indique au script sa2 d'attendre un délai aléatoire dans la plage indiquée avant de s'exécuter. Ce délai est exprimé en secondes et vise à éviter un pic d'E/S massif en même temps sur des VM partageant la même zone de stockage. Une valeur de 0 signifie que le script sa2 générera ses fichiers de rapports immédiatement.
HISTORY
Le nombre de jours pendant lesquels un fichier de données quotidien ou un rapport doit être conservé. Les fichiers de données ou les rapports plus anciens que ce nombre de jours seront supprimés par le script shell sa2(8). Les fichiers de données et les rapports sont normalement sauvegardés dans le répertoire /var/log/sa, sous le nom saDD (pour les fichiers de données) ou sarDD (pour les rapports), où le paramètre DD indique le jour actuel.

Le nombre de fichiers effectivement conservés dans le répertoire /var/log/sa peut être légèrement supérieur à la valeur HISTORY en raison de la façon dont le script sa2(8) détermine quels fichiers supprimer (voir ci-dessous "Comment le script sa2(8) applique la valeur HISTORY"). Utiliser une valeur de 28 conserve les données d'un mois entier. Si vous définissez HISTORY à une valeur supérieure à 28, vous devriez envisager d'utiliser l'option -D de sadc pour éviter que les anciens fichiers de données ne soient écrasés (voir la page de manuel de sadc(8)). Dans ce dernier cas, les fichiers de données sont nommés saYYYYMMDD et les rapports sarYYYYMMDD, où YYYY représente l'année en cours, MM le mois en cours et DD le jour en cours.

Comment le script sa2(8) applique la valeur HISTORY

Le script sa2 utilise la commande find avec l'option -mtime pour déterminer quels fichiers supprimer. La commande find interprète cette valeur comme "N périodes de 24 heures", ignorant toute partie fractionnaire. Cela signifie que l'heure de dernière modification d'un fichier de données ou de rapport sa[r]DD donné, avec une HISTORY de 1, doit avoir été modifiée au moins deux jours auparavant avant d'être supprimée. Et pour une HISTORY de 28, cela signifierait 29 jours auparavant.

Pour déterminer comment une HISTORY de 28 est appliquée en pratique, nous devons considérer que le script sa2 qui exécute la commande find pour supprimer les anciens fichiers s'exécute généralement juste avant minuit sur un système donné, et comme le premier enregistrement de sadc peut également être écrit dans le fichier de données du jour précédent (déplaçant ainsi légèrement son heure de modification), le script sa2 laissera 30 fichiers intacts. Donc, pour un réglage de 28, et en comptant le fichier de données du jour actuel, il y aura toujours 31 fichiers (ou 30 fichiers, selon le nombre de jours dans un mois) dans le répertoire /var/log/sa pendant la majeure partie d'une journée donnée. Par exemple :

30 avril : 31 fichiers (30 avril-1er avril, 31 mars)
1er mai : 30 fichiers (1er mai, 30 avril-2 avril)

Cependant, nous pouvons noter les exceptions suivantes (telles qu'inspectées à midi le jour donné) :

28 février : 31 fichiers (28 fév-1er fév, 31 jan, 30 jan & 29 jan)
1er mars : 30 fichiers (1er mars, 28 fév-2 mars, 31 jan & 30 jan)
2 mars : 29 fichiers (1er et 2 mars, 28 fév-3 mars, 31 jan)
3 mars : 28 fichiers (1er-3 mars, 28 fév-4 mars)
29 mars au 28 avril : 28 fichiers
29 mars : 29 fichiers
30 mars : 30 fichiers
31 mars : 31 fichiers

(Déterminer le nombre de fichiers en mars lors d'une année bissextile est laissé en exercice au lecteur).

Les choses sont plus simples si vous utilisez le format de nom sa[r]YYYYMMDD. Appliquez la même logique que ci-dessus dans ce cas et vous constaterez qu'il y a toujours HISTORY + 3 fichiers dans le répertoire /var/log/sa pendant la majeure partie d'une journée donnée.

REPEAT_HEADER
Nombre maximum de lignes après lesquelles un en-tête sera inséré dans le rapport généré par le script sa2. Par défaut, il n'y a qu'un en-tête au début de chaque rapport et il n'est pas répété par la suite.
REPORTS
Définissez cette variable à false pour empêcher le script sa2 de générer des rapports (les fichiers sarDD).
SA_DIR
Répertoire où sont sauvegardés les fichiers de données quotidiens et les fichiers de rapports d'activité système standard. Sa valeur par défaut est /var/log/sa.
SADC_OPTIONS
Options qui doivent être passées à sadc(8). Avec ces options (voir la page de manuel de sadc(8)), vous pouvez sélectionner des données supplémentaires qui seront sauvegardées dans les fichiers de données quotidiens. Ces options ne sont utilisées que lorsqu'un nouveau fichier de données est créé. Elles seront ignorées avec un fichier déjà existant.
UMASK
Les scripts sa1 et sa2 génèrent des fichiers de données d'activité système et des rapports dans le répertoire /var/log/sa. Par défaut, les fichiers sont créés avec un umask de 0022 et sont donc lisibles par tous les utilisateurs. Modifiez cette variable pour restreindre les permissions sur les fichiers (par exemple, utilisez 0027 pour adhérer à des normes de sécurité plus strictes).
YESTERDAY
Par défaut, le script sa2 génère le résumé de la veille, car le job cron s'exécute généralement juste après minuit. Si vous souhaitez que sa2 génère le résumé du même jour (par exemple, lorsque le job cron s'exécute à 23:53), définissez cette variable sur no.
ZIP
Programme utilisé pour compresser les fichiers de données et de rapports.
