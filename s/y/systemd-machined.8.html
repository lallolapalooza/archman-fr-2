SYSTEMD-MACHINED.SERVICE(8) systemd-machined.service SYSTEMD-MACHINED.SERVICE(8)

NOM

systemd-machined.service, systemd-machined - Gestionnaire d'enregistrement de machines virtuelles et de conteneurs

SYNTAXE

systemd-machined.service

/usr/lib/systemd/systemd-machined

DESCRIPTION

systemd-machined est un service système qui permet de suivre les machines virtuelles et les conteneurs s'exécutant localement.

systemd-machined est utile pour enregistrer et suivre à la fois les conteneurs OS (conteneurs qui partagent le noyau hôte mais exécutent un système d'initialisation complet propre et se comportent à bien des égards comme un système d'exploitation virtuel complet plutôt que comme une simple application virtualisée) et les machines virtuelles complètes (matériel virtualisé exécutant des systèmes d'exploitation normaux et potentiellement des noyaux différents).

systemd-machined ne doit pas être utilisé pour enregistrer/suivre des conteneurs sandbox d'application. Une machine dans le contexte de systemd-machined est censée être un terme abstrait couvrant à la fois les conteneurs OS et les machines virtuelles complètes, mais pas les sandboxes d'application.

Les machines enregistrées auprès de machined sont exposées de diverses manières dans le système. Par exemple :

•Des outils comme ps(1) montreront à quelle machine un processus spécifique appartient dans une colonne dédiée, tout comme le fera gnome-system-monitor[1] ou systemd-cgls(1).
•Les divers outils de systemd (systemctl(1), journalctl(1), loginctl(1), hostnamectl(1), timedatectl(1), localectl(1), machinectl(1), ...) prennent en charge le commutateur -M pour opérer sur les conteneurs locaux au lieu du système hôte.
•systemctl list-machines affichera l'état du système de tous les conteneurs locaux, se connectant au système d'initialisation du conteneur pour cela.
•Le commutateur --recursive de systemctl aura pour effet non seulement d'afficher les services locaux en cours d'exécution, mais aussi d'afficher récursivement les services de tous les conteneurs enregistrés.
•La commande machinectl donne accès à un certain nombre d'opérations utiles sur les conteneurs enregistrés, telles que l'introspection, le redémarrage, l'arrêt et l'obtention d'une invite de connexion.
•La bibliothèque sd-bus(3) expose l'appel sd_bus_open_system_machine(3) pour se connecter au bus système de n'importe quel conteneur enregistré.
•Le module nss-mymachines(8) garantit que tous les conteneurs enregistrés peuvent être résolus via les appels normaux de glibc gethostbyname(3) ou getaddrinfo(3).

Voir systemd-nspawn(1) pour quelques exemples sur la façon d'exécuter des conteneurs avec des outils OS.

Si vous souhaitez écrire un gestionnaire de VM ou de conteneurs qui utilise machined, veuillez consulter Écrire des gestionnaires de machines virtuelles ou de conteneurs[2]. Voir également les Nouvelles Interfaces de Groupes de Contrôle[3].

Le démon fournit à la fois une interface de bibliothèque C (partagée avec systemd-logind.service(8)) ainsi qu'une interface D-Bus et une interface Varlink. L'interface de bibliothèque peut être utilisée pour introspecter et surveiller l'état des machines virtuelles/conteneurs. L'interface de bus fournit la même chose mais peut en plus être utilisée pour enregistrer ou terminer des machines. L'interface Varlink peut être utilisée pour enregistrer des machines avec des extensions optionnelles, par exemple avec une clé/adresse SSH ; elle peut être interrogée avec varlinkctl introspect /run/systemd/machine/io.systemd.Machine io.systemd.Machine. Pour plus d'informations, veuillez consulter sd-login(3) et org.freedesktop.machine1(5) et org.freedesktop.LogControl1(5).

Un petit démon compagnon systemd-importd.service(8) est également disponible, qui implémente l'importation, l'exportation et le téléchargement d'images de conteneurs et de VM.

Pour chaque conteneur enregistré auprès de systemd-machined.service qui utilise l'espace de noms utilisateur, les utilisateurs/groupes sont synthétisés pour les UID/GIDs utilisés. Ceux-ci sont mis à disposition du système via l'API de recherche d'enregistrements utilisateur/groupe via Varlink[4], et peuvent donc être résolus avec userdbctl(1) ou les appels NSS habituels de glibc.
