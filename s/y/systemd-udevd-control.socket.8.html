SYSTEMD-UDEVD.SERVICE(8) systemd-udevd.service SYSTEMD-UDEVD.SERVICE(8)

NOM

systemd-udevd.service, systemd-udevd-control.socket, systemd-udevd-kernel.socket, systemd-udevd-varlink.socket, systemd-udevd - Démon de gestion des événements de périphériques

SYNTAXE

systemd-udevd.service

systemd-udevd-control.socket

systemd-udevd-kernel.socket

systemd-udevd-varlink.socket

/usr/lib/systemd/systemd-udevd [--daemon] [--debug] [--children-max=] [--exec-delay=] [--event-timeout=] [--resolve-names=early|late|never] [--version] [--help]

DESCRIPTION

systemd-udevd écoute les uevents du noyau. Pour chaque événement, systemd-udevd exécute les instructions correspondantes spécifiées dans les règles udev. Voir udev(7).

Le comportement du démon peut être configuré via udev.conf(5), ses options de ligne de commande, les variables d'environnement et sur la ligne de commande du noyau, ou modifié dynamiquement avec udevadm control.

OPTIONS

-d, --daemon

Détache et exécute en arrière-plan.

Ajouté dans la version 186.

-D, --debug

Affiche les messages de débogage sur la sortie standard d'erreur.

Ajouté dans la version 186.

-c, --children-max=

Limite le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

-e, --exec-delay=

Retarde l'exécution de chaque paramètre RUN{{programme}} du nombre de secondes spécifié. Cette option peut être utile pour déboguer des plantages système pendant le coldplug causés par le chargement de modules du noyau défectueux.

Ajouté dans la version 186.

-t, --event-timeout=

Définit le nombre de secondes à attendre que les événements se terminent. Après ce délai, l'événement sera terminé. La valeur par défaut est 180 secondes.

Ajouté dans la version 216.

-s, --timeout-signal=

Définit le signal que systemd-udevd enverra aux processus lancés après avoir atteint le délai d'attente de l'événement. Le paramètre peut être remplacé au démarrage avec l'option de ligne de commande du noyau udev.timeout_signal=. Définir sur SIGABRT peut être utile pour déboguer les timeouts des workers. Par défaut, il s'agit de SIGKILL. Notez que la définition de l'option sur la ligne de commande remplace le paramètre du fichier de configuration.

Ajouté dans la version 246.

-N, --resolve-names=

Spécifie quand systemd-udevd doit résoudre les noms des utilisateurs et des groupes. Lorsque défini sur early (par défaut), les noms seront résolus lors de l'analyse des règles. Lorsqu'il est défini sur late, les noms seront résolus pour chaque événement. Lorsqu'il est défini sur never, les noms ne seront jamais résolus et tous les périphériques appartiendront à root.

Ajouté dans la version 186.

-h, --help

Affiche un bref message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

LIGNE DE COMMANDE DU NOYAU

Les paramètres préfixés par "rd." seront lus lorsque systemd-udevd est utilisé dans un initrd, ceux sans préfixe seront traités à la fois dans l'initrd et sur l'hôte.

udev.log_level=, rd.udev.log_level=

Définit le niveau de journalisation.

Ajouté dans la version 247.

udev.trace[=BOOL], rd.udev.trace[=BOOL]

Active/désactive la journalisation des traces. Lorsque activée, udev.log_level= sera ignoré, et le niveau "debug" sera supposé.

Ajouté dans la version 258.

udev.children_max=, rd.udev.children_max=

Limite le nombre d'événements exécutés en parallèle.

Ajouté dans la version 186.

udev.exec_delay=, rd.udev.exec_delay=

Retarde l'exécution de chaque paramètre RUN{{programme}} du nombre de secondes spécifié. Cette option peut être utile pour déboguer des plantages système pendant le coldplug causés par le chargement de modules du noyau défectueux.

Ajouté dans la version 186.

udev.event_timeout=, rd.udev.event_timeout=

Attend la fin des événements jusqu'au nombre de secondes spécifié. Cette option peut être utile si les événements sont terminés car les pilotes du noyau mettent trop de temps à s'initialiser.

Ajouté dans la version 216.

udev.timeout_signal=, rd.udev.timeout_signal=

Spécifie un signal que systemd-udevd enverra aux workers en cas de timeout. Notez que l'option de ligne de commande du noyau remplace à la fois le paramètre dans le fichier de configuration et celui sur la ligne de commande du programme.

Ajouté dans la version 246.

udev.blockdev_read_only, rd.udev.blockdev_read_only

Si spécifié, marque tous les périphériques de bloc physiques en lecture seule dès leur apparition. Les périphériques de bloc synthétiques (tels que les périphériques de bloc de boucle ou les périphériques device-mapper) sont laissés tels quels. Ceci est utile pour garantir que le contenu des périphériques de bloc physiques reste inchangé pendant l'exécution, par exemple pour implémenter des systèmes entièrement sans état, pour des tests ou pour des situations de récupération où les systèmes de fichiers corrompus ne doivent pas être davantage corrompus par une modification accidentelle.

Un périphérique de bloc peut être marqué à nouveau en écriture en exécutant la commande blockdev --setrw, voir blockdev(8) pour plus de détails.

Ajouté dans la version 246.

net.ifnames=

Les interfaces réseau sont renommées pour leur donner des noms prédictibles lorsque cela est possible. C'est activé par défaut ; spécifier 0 le désactive.

Ajouté dans la version 199.

net.naming_scheme=

Les interfaces réseau sont renommées pour leur donner des noms prédictibles lorsque cela est possible (sauf si net.ifnames=0 est spécifié, voir ci-dessus). Avec cette option de ligne de commande du noyau, il est possible de choisir une version spécifique de cet algorithme et de remplacer celui choisi par défaut à la compilation. Attend l'un des identifiants de schéma de nommage listés dans systemd.net-naming-scheme(7), ou "latest" pour sélectionner le schéma le plus récent connu (de cette version particulière de systemd-udevd.service).

Notez que la sélection d'un schéma spécifique n'est pas suffisante pour stabiliser complètement le nommage des interfaces : le nommage est généralement dérivé des attributs du pilote exposés par le noyau. Lorsque le noyau est mis à jour, des attributs précédemment manquants que systemd-udevd.service vérifie pourraient apparaître, ce qui affecte également les anciens algorithmes de dérivation de noms.

Ajouté dans la version 240.

net.ifname_policy=policy1[,policy2,...][,MAC]

Spécifie les politiques de nommage appliquées lors du renommage des interfaces réseau. Prend une liste de politiques et une adresse MAC optionnelle séparées par des virgules. Chaque valeur de politique doit être l'une des politiques comprises par le réglage NamePolicy= dans les fichiers .link, par exemple "onboard" ou "path". Voir systemd.link(5) pour plus de détails. Lorsque l'adresse MAC est spécifiée, les politiques sont appliquées à l'interface qui possède cette adresse. Lorsqu'aucune adresse MAC n'est spécifiée, les politiques sont appliquées à toutes les interfaces. Cet argument de ligne de commande du noyau peut être spécifié plusieurs fois.

Cet argument n'est pas directement lu par systemd-udevd, mais est plutôt converti en un fichier .link par systemd-network-generator.service(8). Pour que cet argument prenne effet, systemd-network-generator.service doit être activé.

Exemple :

net.ifname_policy=keep,kernel,path,slot,onboard,01:23:45:67:89:ab
net.ifname_policy=keep,kernel,path,slot,onboard,mac

Ceci est globalement équivalent à la création des fichiers .link suivants :

# 91-name-policy-with-mac.link
[Match]
MACAddress=01:23:45:67:89:ab
[Link]
NamePolicy=keep kernel path slot onboard
AlternativeNamePolicy=path slot onboard

et

# 92-name-policy-for-all.link
[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel path slot onboard mac
AlternativeNamePolicy=path slot onboard mac

Ajouté dans la version 250.
