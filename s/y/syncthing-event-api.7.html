SYNCTHING-EVENT-API(7) Syncthing SYNCTHING-EVENT-API(7)

NOM

syncthing-event-api - API d'événements

DESCRIPTION

Syncthing fournit une interface simple de 'long polling' pour exposer les événements de l'utilitaire principal vers une interface graphique. Pour recevoir des événements, consultez GET /rest/events.

STRUCTURE DES ÉVÉNEMENTS

Chaque événement est représenté par un objet similaire à ce qui suit :

{
    "id": 2,
    "globalID": 3,
    "type": "DeviceConnected",
    "time": "2014-07-13T21:04:33.687836696+02:00",
    "data": {
        "addr": "172.16.32.25:22000",
        "id": "NFGKEKE-7Z6RTH7-I3PRZXS-DEJF3UJ-FRWJBFO-VBBTDND-4SGNGVZ-QUQHJAG"
    }
}

Les clés de niveau supérieur id, globalID, time, type et data sont toujours présentes, bien que data puisse être null.

id
Un identifiant unique pour cet événement sur l'API d'événements. Il augmente toujours de 1 : le premier événement généré a l'id 1, le suivant a l'id 2, etc. Si cet identifiant augmente de plus de 1, alors un ou plusieurs événements ont été ignorés par l'API d'événements.
globalID
Un identifiant global pour cet événement, à travers l'API d'événements, le journal d'audit et toute autre source. Il peut augmenter de plus de 1, mais il sera toujours supérieur ou égal à l'id.
time
L'heure à laquelle l'événement a été généré.
type
Indique le type (c'est-à-dire la raison) de l'événement et est l'un des types d'événements ci-dessous.
data
Un objet contenant des informations supplémentaires optionnelles ; la structure exacte est déterminée par le type d'événement.

TYPES D'ÉVÉNEMENTS

ClusterConfigReceived

Ajouté dans la version 1.20.0.

L'événement ClusterConfigReceived est émis après le traitement d'un tel message de protocole reçu d'un appareil distant. Il est principalement utilisé à des fins internes.

{

    "globalID": 84,
    "type": "ClusterConfigReceived",
    "time": "2022-04-27T14:14:27.043576583+09:00",
    "data": {
        "device": "I6KAH76-66SLLLB-5PFXSOA-UFJCDZC-YAOMLEK-CP2GB32-BV5RQST-3PSROAU"
    }
}

DeviceDisconnected

Généré chaque fois qu'une connexion à un appareil a été terminée.

{
    "id": 48,
    "globalID": 48,
    "type": "DeviceDisconnected",
    "time": "2014-07-13T21:18:52.859929215+02:00",
    "data": {
        "error": "unexpected EOF",
        "id": "NFGKEKE-7Z6RTH7-I3PRZXS-DEJF3UJ-FRWJBFO-VBBTDND-4SGNGVZ-QUQHJAG"
    }
}

NOTE :

La clé d'erreur contient la cause de la déconnexion, qui peut ne pas être nécessairement une erreur en soi. En particulier, “EOF” et “unexpected EOF” signifient tous deux la fin de la connexion TCP, soit parce que l'autre appareil a redémarré ou s'est déconnecté, soit en raison d'un changement de réseau.

DownloadProgress

Émis pendant le téléchargement de fichiers pour chaque dossier et pour chaque fichier. Par défaut, un seul fichier dans un dossier est traité à la fois, mais une configuration personnalisée peut entraîner l'affichage de plusieurs fichiers.

{
    "id": 221,
    "globalID": 221,
    "type": "DownloadProgress",
    "time": "2014-12-13T00:26:12.9876937Z",
    "data": {
        "folder1": {
            "file1": {
                "total": 800,
                "pulling": 2,
                "copiedFromOrigin": 0,
                "reuse"
```

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

{ "id": 69, "globalID": 69, "type": "FileRenamed", "time": "2022-04-27T13:39:47.733414258+09:00", "data": { "from": "folder1/file1", "to": "folder1/file_renamed" } } ```

FileProgress events are emitted for individual files. The data field contains the following fields:

  • total - total number of blocks in the file
  • pulling - number of blocks currently being downloaded
  • copiedFromOrigin - number of blocks copied from the file we are about to replace
  • reused - number of blocks reused from a previous temporary file
  • copiedFromElsewhere - number of blocks copied from other files or potentially other folders
  • pulled - number of blocks actually downloaded so far
  • bytesTotal - approximate total file size
  • bytesDone - approximate number of bytes already handled (already reused, copied or pulled)

Where block size is 128KB.

Files/folders appearing in the event data imply that the download has been started for that file/folder, where disappearing implies that the downloads have been finished or failed for that file/folder. There is always a last event emitted with no data, which implies all downloads have finished/failed.

Failure

Generated for specific errors that will also be sent to the usage reporting server, if enabled in the configuration. These are usually of special interest to the developers to troubleshoot complex errors. The data field contains a textual error message.

{
  "id": 93,
  "globalID": 93,
  "type": "Failure",
  "time": "2021-06-07T21:22:03.414609034+02:00",
  "data": "index handler got paused while already paused"
}

FolderCompletion

The FolderCompletion event is emitted when the local or remote contents for a folder changes. It contains the completion percentage for a given remote device and is emitted once per currently connected remote device.

Added in version 1.20.0: Indication whether the remote device has accepted the folder (shares it with us) as well, and whether it is paused. The remoteState field is unknown when the remote device is not connected. Otherwise it can be either paused, notSharing, or valid if the remote is sharing back.

{
    "id": 84,
    "globalID": 84,
    "type": "FolderCompletion",
    "time": "2022-04-27T14:14:27.043576583+09:00",
    "data": {
        "completion": 100,
        "device": "I6KAH76-66SLLLB-5PFXSOA-UFJCDZC-YAOMLEK-CP2GB32-BV5RQST-3PSROAU",
        "folder": "default",
        "globalBytes": 17,
        "globalItems": 4,
        "needBytes": 0,
        "needDeletes": 0,
        "needItems": 0,
        "remoteState": "valid",
        "sequence": 12
    }
}

FolderErrors

The FolderErrors event is emitted when a folder cannot be successfully synchronized. The event contains the ID of the affected folder and a list of errors for files or directories therein. This list of errors is obsolete once the folder changes state to syncing - if errors remain after the next synchronization attempt, a new FolderErrors event is emitted.

{
    "id": 132,
    "type": "FolderErrors",
    "time": "2015-06-26T13:39:24.697401384+02:00",
    "data": {
        "errors": [
            {
                "error": "open /Users/jb/src/github.com/syncthing/syncthing/test/s2/h2j/.syncthing.aslkjd.tmp: permission denied",
                "path": "h2j/aslkjd"
            }
        ],
        "folder": "default"
    }
}

Added in version 0.11.12.

                "folderLabel": "Documents",

                    "IJKL789-MNOP012-..."
                ]
            }

    }
}

Added in version v1.13.0.

StateChanged

This event is emitted whenever the state of a folder changes. This includes transitions to and from "scanning", "syncing", "idle", and "disconnected". It also includes reasons for state changes, such as "PausedByUser", "PausedByVirusScanner", "DisconnectedByPeer", etc.

{
    "id": 15,
    "type": "StateChanged",
    "time": "2024-01-31T08:27:24.777875+01:00",
    "data": {
        "folder": "default",
        "oldState": "scanning",
        "newState": "idle",
        "reason": "ScanCompleted"
    }
}

Généré lorsque Syncthing termine la synchronisation d'un fichier avec une version plus récente. Une opération réussie :

    "globalID": 93,
    "type": "ItemFinished",

    "id": 44,
    "globalID": 44,
    "type": "ItemFinished",

LocalChangeDetected

Généré lors du scan, chaque fois que le disque local a découvert un fichier mis à jour par rapport au scan précédent. Cela n'inclut *pas* les événements découverts et copiés depuis d'autres appareils (RemoteChangeDetected), seulement les fichiers qui ont été modifiés sur le système de fichiers local.

NOTE :

Cet événement n'est pas inclus dans le point de terminaison GET /rest/events sans masque spécifié, mais doit être sélectionné explicitement.
{
  "id": 7,
  "globalID": 59,
  "time": "2016-09-26T22:07:10.7189141-04:00",
  "type": "LocalChangeDetected",
  "data": {
    "action": "deleted",
    "folder": "vitwy-zjxqt",
    "folderID": "vitwy-zjxqt",
    "label": "TestSync",
    "path": "test file.rtf",
    "type": "file"
  }
}

Déprécié depuis la version v1.1.2 : Le champ folderID est un nom hérité conservé uniquement pour des raisons de compatibilité. Utilisez le champ folder avec un contenu identique à la place.

Déprécié depuis la version v1.10.0 : Le champ version est un nom hérité conservé uniquement pour des raisons de compatibilité. Utilisez le champ sequence avec un contenu identique à la place.

LoginAttempt

Lorsque l'authentification est activée pour l'interface graphique, cet événement est émis à chaque tentative de connexion. Si le nom d'utilisateur ou le mot de passe sont incorrects, success est faux et dans tous les cas, le nom d'utilisateur donné est retourné.

{
   "id" : 187,
   "time" : "2017-03-07T00:19:24.420386143+01:00",
   "data" : {
      "remoteAddress" : "127.0.0.1",
      "username" : "somename",
      "success" : false
   },
   "type" : "LoginAttempt",
   "globalID" : 195
}

Si l'en-tête X-Forwared-For est présent et que l'hôte de connexion est soit sur localhost soit sur le même LAN, il sera traité comme un proxy inverse. Dans ce cas, le champ remoteAddress sera rempli avec l'adresse IP la plus à gauche de l'en-tête, et le champ supplémentaire proxy conservera l'IP d'origine de l'hôte de connexion.

{
   "id" : 187,
   "time" : "2017-03-07T00:19:24.420386143+01:00",
   "data" : {
      "proxy" : "127.0.0.1",
      "remoteAddress" : "192.168.178.10",
      "username" : "somename",
      "success" : false
   },
   "type" : "LoginAttempt",
   "globalID" : 195
}

Ajouté dans la version 1.14.0.

        "name": "Mon ordinateur poussiéreux"

  }

PendingFoldersChanged

Ajouté dans la version 1.14.0.

Émis lorsque les dossiers en attente ont été ajoutés / mis à jour (proposé par un appareil, mais non partagé avec lui) ou supprimés (dossier ignoré, rejeté ou ajouté, ou ne lui est plus proposé par l'appareil distant). Une entrée supprimée sans attribut deviceID signifie que le dossier n'est plus en attente pour aucun appareil.

  "data": {

        "folderLabel": "Mes Photos"

        "remoteEncrypted": "false"

Détection de changement à distance

Généré lors de l'analyse chaque fois qu'un fichier est mis à jour localement en raison d'un changement à distance. Les fichiers mis à jour localement produisent un événement LocalChangeDetected.

NOTE :

Cet événement n'est pas inclus dans le point de terminaison GET /rest/events sans masque spécifié, mais doit être sélectionné explicitement.
{
   "time" : "2017-03-06T23:58:21.844739891+01:00",
   "globalID" : 123,
   "data" : {
      "type" : "file",
      "action" : "deleted",
      "folder": "Dokumente",
      "folderID" : "Dokumente",
      "path" : "testfile",
      "label" : "Dokumente",
      "modifiedBy" : "BPDFDTU"
   },
   "type" : "RemoteChangeDetected",
   "id" : 2
}

Obsolète depuis la version v1.1.2 : Le champ folderID est un nom hérité conservé uniquement pour des raisons de compatibilité. Utilisez le champ folder avec un contenu identique à la place.

Progression du téléchargement à distance

Cet événement est émis lorsqu'un message DownloadProgress est reçu. Il renvoie une carte data des noms de fichiers avec un décompte des blocs téléchargés. Les fichiers en question sont en cours de téléchargement sur le périphérique distant et appartiennent au dossier.

{
   "time" : "2017-03-07T00:11:37.65838955+01:00",
   "globalID" : 170,
   "data" : {
      "state" : {
         "tahr64-6.0.5.iso" : 1784
      },
      "device" : "F4HSJVO-CP2C3IL-YLQYLSU-XTYODAG-PPU4LGV-PH3MU4N-G6K56DV-IPN47A",
      "folder" : "Dokumente"
   },
   "type" : "RemoteDownloadProgress",
   "id" : 163
}

Démarrage

Émis exactement une fois, au démarrage de Syncthing, avant l'analyse de la configuration, etc.

{
    "id": 1,
    "globalID": 1,
    "type": "Starting",
    "time": "2014-07-17T13:13:32.044470055+02:00",
    "data": {
        "home": "/home/jb/.config/syncthing"
    }
}

Démarrage terminé

Émis exactement une fois, une fois l'initialisation terminée et Syncthing prêt à commencer à échanger des données avec d'autres périphériques.

{
    "id": 1,
    "globalID": 1,
    "type": "StartupComplete",
    "time": "2014-07-13T21:03:18.383239179+02:00",
    "data": null
}

Changement d'état

Émis lorsqu'un dossier change d'état. Les états possibles sont idle, scanning, syncing et error. Le champ duration représente le nombre de secondes pendant lesquelles le dossier est resté dans l'état from. Dans l'exemple ci-dessous, le dossier default était dans l'état scanning pendant 0,198 seconde et est maintenant dans l'état idle.

{
    "id": 8,
    "globalID": 8,
    "type": "StateChanged",
    "time": "2014-07-17T13:14:28.697493016+02:00",
    "data": {
        "folder": "default",
        "from": "scanning",
        "duration": 0.19782869900000002,
        "to": "idle"
    }
}
