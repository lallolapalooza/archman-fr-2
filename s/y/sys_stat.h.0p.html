NOM

sys/stat.h — données retournées par la fonction stat()

SYNTAXE

#include <sys/stat.h>

DESCRIPTION

L'en-tête <sys/stat.h> définit la structure des données retournées par les fonctions fstat(), lstat() et stat().

L'en-tête <sys/stat.h> définit la structure stat, qui contient au minimum les membres suivants :

dev_t st_dev            ID du périphérique contenant le fichier.
ino_t st_ino            Numéro de série du fichier.
mode_t st_mode          Mode du fichier (voir ci-dessous).
nlink_t st_nlink        Nombre de liens physiques vers le fichier.
uid_t st_uid            ID utilisateur du fichier.
gid_t st_gid            ID du groupe du fichier.
dev_t st_rdev           ID du périphérique (si le fichier est spécial caractère ou bloc).
off_t st_size           Pour les fichiers réguliers, la taille du fichier en octets.
                        Pour les liens symboliques, la longueur en octets du
                        chemin contenu dans le lien symbolique.
                        Pour un objet de mémoire partagée, la longueur en octets.
                        Pour un objet de mémoire typée, la longueur en octets.
                        Pour d'autres types de fichiers, l'utilisation de ce champ est
                        non spécifiée.
struct timespec st_atim Horodatage du dernier accès aux données.
struct timespec st_mtim Horodatage de la dernière modification des données.
struct timespec st_ctim Horodatage du dernier changement d'état du fichier.
blksize_t st_blksize    Une taille de bloc d'E/S préférée spécifique au système de fichiers
                        pour cet objet. Dans certains types de systèmes de fichiers, cela
                        peut varier d'un fichier à l'autre.
blkcnt_t st_blocks      Nombre de blocs alloués pour cet objet.

Les champs st_ino et st_dev, pris ensemble, identifient de manière unique le fichier dans le système.

L'en-tête <sys/stat.h> définit les types blkcnt_t, blksize_t, dev_t, ino_t, mode_t, nlink_t, uid_t, gid_t, off_t et time_t tels que décrits dans <sys/types.h>.

L'en-tête <sys/stat.h> définit la structure timespec telle que décrite dans <time.h>. Les temps seront donnés en secondes depuis l'Époque.

Les membres de la structure dont les valeurs ont un sens dépendent du type de fichier. Pour plus d'informations, voir les descriptions de fstat(), lstat() et stat() dans le volume Interfaces Système de POSIX.1-2017.

Pour la compatibilité avec les versions antérieures de cette norme, la macro st_atime sera définie avec la valeur st_atim.tv_sec. De même, st_ctime et st_mtime seront définies comme des macros avec les valeurs st_ctim.tv_sec et st_mtim.tv_sec, respectivement.

L'en-tête <sys/stat.h> définit les constantes symboliques suivantes pour les types de fichiers encodés dans le type mode_t. Les valeurs seront appropriées pour une utilisation dans les directives de préprocesseur #if :

S_IFMT
Type de fichier.
S_IFBLK
Spécial bloc.
S_IFCHR
Spécial caractère.
S_IFIFO
Spécial FIFO.
S_IFREG
Régulier.
S_IFDIR
Répertoire.
S_IFLNK
Lien symbolique.
S_IFSOCK
Socket.

L'en-tête <sys/stat.h> définit les constantes symboliques suivantes pour les bits de mode de fichier encodés dans le type mode_t, avec les valeurs numériques indiquées. Ces macros se développeront en une expression qui a un type permettant de les utiliser, seules ou ORées ensemble, comme troisième argument de open() sans avoir besoin d'un cast mode_t. Les valeurs seront appropriées pour une utilisation dans les directives de préprocesseur #if :

NOM

sys_stat.h - informations sur les fichiers

SYNOPSIS

#include <sys/stat.h>

DESCRIPTION

Le fichier d'en-tête <sys/stat.h> définit des structures et des constantes utilisées pour obtenir des informations sur les fichiers, créer des fichiers et modifier leurs autorisations. Les types de fichiers ci-dessous peuvent être implémentés comme des types de fichiers distincts. Les macros suivantes doivent être fournies pour tester si un fichier est du type spécifié. La valeur de l'argument buf fourni aux macros est un pointeur vers une structure stat. La macro doit retourner une valeur non nulle si l'objet spécifié est implémenté comme un type de fichier distinct et que le type de fichier spécifié est contenu dans la structure stat référencée par buf. Sinon, la macro doit retourner zéro.

S_TYPEISMQ(buf)
Tester pour une file de messages.
S_TYPEISSEM(buf)
Tester pour un sémaphore.
S_TYPEISSHM(buf)
Tester pour un objet de mémoire partagée.

L'implémentation peut implémenter des objets de mémoire typés comme des types de fichiers distincts, et la macro suivante doit tester si un fichier est du type spécifié. La valeur de l'argument buf fourni aux macros est un pointeur vers une structure stat. La macro doit retourner une valeur non nulle si l'objet spécifié est implémenté comme un type de fichier distinct et que le type de fichier spécifié est contenu dans la structure stat référencée par buf. Sinon, la macro doit retourner zéro.

S_TYPEISTMO(buf)
Macro de test pour un objet de mémoire typé.

Le fichier d'en-tête <sys/stat.h> doit définir les constantes symboliques suivantes comme des valeurs entières distinctes en dehors de la plage [0,999999999], pour être utilisées avec les fonctions futimens() et utimensat(): UTIME_NOW UTIME_OMIT

Les éléments suivants doivent être déclarés comme fonctions et peuvent également être définis comme des macros. Les prototypes de fonctions doivent être fournis.

int    chmod(const char *, mode_t);
int    fchmod(int, mode_t);
int    fchmodat(int, const char *, mode_t, int);
int    fstat(int, struct stat *);
int    fstatat(int, const char *restrict, struct stat *restrict, int);
int    futimens(int, const struct timespec [2]);
int    lstat(const char *restrict, struct stat *restrict);
int    mkdir(const char *, mode_t);
int    mkdirat(int, const char *, mode_t);
int    mkfifo(const char *, mode_t);
int    mkfifoat(int, const char *, mode_t);
int    mknod(const char *, mode_t, dev_t);
int    mknodat(int, const char *, mode_t, dev_t);
int    stat(const char *restrict, struct stat *restrict);
mode_t umask(mode_t);
int    utimensat(int, const char *, const struct timespec [2], int);

L'inclusion du fichier d'en-tête <sys/stat.h> peut rendre visibles tous les symboles du fichier d'en-tête <time.h>.

Les sections suivantes sont informatives.

USAGE APPLICATIF

L'utilisation des macros est recommandée pour déterminer le type d'un fichier.

RATIONALE

Une application conforme en langage C doit inclure <sys/stat.h> pour les fonctions qui ont des arguments ou des valeurs de retour de type mode_t, afin que les valeurs symboliques pour ce type puissent être utilisées. Une alternative serait d'exiger que ces constantes soient également définies en incluant <sys/types.h>.

Les bits S_ISUID et S_ISGID peuvent être effacés lors de toute écriture, pas seulement lors de open(), comme le font certaines implémentations historiques.

Les appels système qui mettent à jour les champs d'entrée de temps dans la structure stat doivent être documentés par les implémenteurs. Les systèmes conformes à POSIX ne doivent pas mettre à jour les champs d'entrée de temps pour les fonctions listées dans le volume Interfaces Système de POSIX.1‐2017 à moins que la norme ne l'exige, sauf dans le cas d'extensions documentées à la norme.

Lors de l'assignation, les horodatages des fichiers sont immédiatement convertis à la résolution du système de fichiers par troncature (c'est-à-dire que l'heure enregistrée peut être antérieure à l'heure réelle). Par exemple, si la résolution du système de fichiers est de 1 microseconde, alors un stat() conforme doit toujours retourner un st_mtim.tv_nsec qui est un multiple de 1000. Certaines anciennes implémentations retournaient des horodatages à plus haute résolution pendant que les informations de l'inode étaient mises en cache, puis tronquaient spontanément les champs tv_nsec lors de leur stockage et récupération du disque, mais ce comportement n'est pas conforme.

Notez que st_dev doit être unique au sein d'un réseau local (LAN) dans un « système » composé des systèmes de fichiers de plusieurs ordinateurs connectés par un LAN.

Les implémentations réseau d'un système conforme à POSIX doivent garantir que tous les fichiers visibles dans l'arborescence des fichiers (y compris les parties de l'arborescence qui peuvent être montées à distance depuis d'autres machines sur le réseau) sur chaque processeur individuel sont identifiés de manière unique par la combinaison des champs st_ino et st_dev.

L'unité du membre st_blocks de la structure stat n'est pas définie dans POSIX.1‐2008. Dans certaines implémentations, elle est de 512 octets. Elle peut différer selon le système de fichiers. Il n'y a aucune corrélation entre les valeurs de st_blocks et st_blksize, et les membres de la structure f_bsize (de <sys/statvfs.h>).

Traditionnellement, certaines implémentations définissaient le multiplicateur de st_blocks dans <sys/param.h> comme le symbole DEV_BSIZE.

Certaines versions antérieures de cette norme ne spécifiaient pas de valeurs pour les macros des bits de mode de fichier. L'attente était que certains implémenteurs choisiraient d'utiliser un encodage différent pour ces bits que celui traditionnel, et que les nouvelles applications utiliseraient des modes de fichier symboliques au lieu de numériques. Cette version de la norme spécifie l'encodage traditionnel, en reconnaissance qu'environ 20 ans après la première publication de cette norme, les modes de fichier numériques sont toujours largement utilisés par les développeurs d'applications, et que toutes les implémentations conformes utilisent toujours l'encodage traditionnel.

FUTURES DIRECTIONS

Aucun nouveau nom symbolique S_IFMT pour les valeurs de type de fichier de mode_t ne sera défini par POSIX.1‐2008 ; si de nouveaux types de fichiers sont requis, ils ne pourront être testés qu'à travers les macros S_ISxx() ou S_TYPEISxxx() à la place.
