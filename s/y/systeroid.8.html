SYSTEROID(8) Administration système SYSTEROID(8)

NOM

systeroid - configurer les paramètres du noyau à l'exécution

SYNTAXE

systeroid [options] [variable[=valeur] ...] --load[=<fichier>]

DESCRIPTION

systeroid est utilisé pour modifier les paramètres du noyau à l'exécution. Les paramètres disponibles sont ceux listés sous /proc/sys/. Procfs est requis pour le support de systeroid sous Linux. Vous pouvez utiliser systeroid pour lire et écrire des données sysctl.

PARAMETRES

variable
Le nom d'une clé à lire. Un exemple est kernel.ostype. Le séparateur '/' est également accepté à la place d'un '.'.
variable=valeur
Pour définir une clé, utilisez la forme variable=valeur où variable est la clé et valeur est la valeur à définir. Si la valeur contient des guillemets ou des caractères analysés par le shell, vous pourrez avoir besoin de mettre la valeur entre guillemets doubles.
-a, --all
Afficher toutes les variables actuellement disponibles. (-A,-X)
-T, --tree
Afficher les variables dans un format arborescent.
-J, --json
Afficher les variables au format JSON.
--deprecated
Inclure les paramètres obsolètes dans la liste des valeurs --all.
-e, --ignore
Utilisez cette option pour ignorer les erreurs concernant les clés inconnues.
-N, --names
Utilisez cette option pour n'afficher que les noms. Cela peut être utile avec les shells qui ont une complétion programmable.
-n, --values
Utilisez cette option pour désactiver l'affichage du nom de la clé lors de l'affichage des valeurs.
-b, --binary
Afficher uniquement les valeurs des variables sans nouvelle ligne.
-p[FICHIER], --load[=FICHIER]
Charger les paramètres sysctl à partir du fichier spécifié ou de /etc/sysctl.conf si aucun n'est donné. Spécifier - comme nom de fichier signifie lire les données depuis l'entrée standard.
-S, --system
Charger les paramètres à partir de tous les fichiers de configuration du système. Voir la section CONFIGURATION ci-dessous.
-r, --pattern <expr>
Appliquer uniquement les paramètres qui correspondent à pattern. Le pattern utilise la syntaxe des expressions régulières étendues.
-q, --quiet
Utilisez cette option pour ne pas afficher les valeurs définies sur la sortie standard.
-w, --write
Utilisez cette option lorsque tous les arguments prescrivent une clé à définir.
-E, --explain
Utilisez cette option pour afficher une explication détaillée d'une variable.
-D, --docs <chemin>
Utilisez cette option pour définir un chemin personnalisé pour la documentation du noyau.
-P, --no-pager
Utilisez cette option pour désactiver le passage de la sortie dans un pagineur.
-v, --verbose
Utilisez cette option pour activer la journalisation détaillée.
--tui
Utilisez cette option pour afficher l'interface utilisateur du terminal. Le binaire systeroid-tui doit être présent dans $PATH. Voir systeroid-tui(8) pour plus d'informations.
-h, --help
Afficher le texte d'aide et quitter. (-d)
-V, --version
Afficher les informations de version et quitter.

EXEMPLES

systeroid -a
systeroid -t
systeroid vm user
systeroid -n kernel.hostname
systeroid kernel.domainname="example.com"
systeroid dmesg_restrict=0
systeroid -p /etc/sysctl.conf
systeroid -r 'net.ipv4.conf.(eth|wlan)0.arp'
systeroid --names --tree --pattern 'kernel.*_max$'
systeroid --explain oom_dump_tasks
systeroid -E user.max_user_namespaces --docs /usr/share/doc/linux
systeroid --no-pager -E kernel.ctrl-alt-del
systeroid --tui

PARAMETRES OBSOLETES

Les paramètres base_reachable_time et retrans_time sont obsolètes. La commande systeroid ne permet pas de modifier les valeurs de ces paramètres. Les utilisateurs qui insistent pour utiliser les interfaces obsolètes du noyau devraient pousser des valeurs dans le système de fichiers /proc par d'autres moyens. Par exemple :

echo 256 > /proc/sys/net/ipv6/neigh/eth0/base_reachable_time

CONFIGURATION

sysctl.conf est un fichier simple contenant les valeurs sysctl à lire et à définir par systeroid. La syntaxe est simplement la suivante :

# commentaire
; commentaire
jeton = valeur

Notez que les lignes vides sont ignorées, et les espaces avant et après un jeton ou une valeur sont ignorés, bien qu'une valeur puisse contenir des espaces en son sein. Les lignes commençant par un # ou un ; sont considérées comme des commentaires et ignorées.

Si une ligne commence par un tiret simple -, toute tentative de définir la valeur qui échoue sera ignorée.

EXEMPLE

# Exemple sysctl.conf
#
  kernel.domainname = example.com
; celui-ci a un espace qui sera écrit dans le sysctl !
  kernel.modprobe = /sbin/mod probe

FICHIERS

Lors de l'utilisation de l'option --system, systeroid lira les fichiers des répertoires dans la liste suivante.

/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/local/lib/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
/lib/sysctl.d/*.conf
/etc/sysctl.conf

NOM

systeroid — Outil de gestion des services d'un systèmed.

SYNOPSIS

systeroid [-h] [-v] [-H HOSTNAME] [-p PORT] [-u UTILISATEUR] [-P MOT_DE_PASSE] [-k CLE_SSH] [-t TEMPS_D_ACTION] [-T TEMPS_DE_VENTILATION] [-i ITERATIONS] [-I INTERVALLE] [-l FICHIER_LOG] [-d] [--no-pager] [commande]

DESCRIPTION

systeroid est un utilitaire en ligne de commande conçu pour gérer les services systemd sur une ou plusieurs machines distantes via SSH. Il offre une manière pratique d'interagir avec les services systemd, similaire à systemctl, mais avec des fonctionnalités supplémentaires pour la gestion à distance et le contrôle des actions.

PARAMETRES

  • -h, --help : Affiche un message d'aide et quitte.
  • -v, --version : Affiche les informations sur la version et quitte.
  • -H HOSTNAME, --host HOSTNAME : Spécifie le nom d'hôte ou l'adresse IP de la machine distante. Peut être spécifié plusieurs fois pour plusieurs hôtes.
  • -p PORT, --port PORT : Spécifie le port SSH sur la machine distante. Par défaut, 22.
  • -u UTILISATEUR, --user UTILISATEUR : Spécifie le nom d'utilisateur pour la connexion SSH.
  • -P MOT_DE_PASSE, --password MOT_DE_PASSE : Spécifie le mot de passe pour l'authentification SSH. Attention : l'utilisation de mots de passe en ligne de commande est déconseillée pour des raisons de sécurité.
  • -k CLE_SSH, --key CLE_SSH : Spécifie le chemin vers la clé privée SSH pour l'authentification.
  • -t TEMPS_D_ACTION, --action-timeout TEMPS_D_ACTION : Définit le délai d'attente pour les actions sur les services (en secondes).
  • -T TEMPS_DE_VENTILATION, --throttle-time TEMPS_DE_VENTILATION : Définit le temps de "ventilation" (en secondes) entre les actions sur les services lorsqu'une liste d'hôtes est fournie.
  • -i ITERATIONS, --iterations ITERATIONS : Nombre d'itérations pour les opérations répétées (par exemple, surveiller l'état d'un service).
  • -I INTERVALLE, --interval INTERVALLE : Intervalle (en secondes) entre les itérations pour les opérations répétées.
  • -l FICHIER_LOG, --log-file FICHIER_LOG : Spécifie un fichier pour enregistrer les opérations.
  • -d, --daemon : Exécute systeroid en tant que démon en arrière-plan.
  • --no-pager : Désactive l'utilisation d'un pager pour l'affichage des résultats.

EXEMPLES

Démarrer un service sur une machine distante :

systeroid --host server1.example.com --user admin --key ~/.ssh/id_rsa start myapp.service

Arrêter un service sur plusieurs machines avec un délai entre elles :

systeroid --host server1.example.com --host server2.example.com --user admin --throttle-time 5 stop myapp.service

Vérifier l'état d'un service sur une machine distante et répéter la vérification toutes les 10 secondes :

systeroid --host server1.example.com --user admin --interval 10 status myapp.service

PARAMETRES OBSOLÈTES

  • -l : Alias pour --log-file.

CONFIGURATION

systeroid peut également être configuré via un fichier de configuration. Le fichier par défaut est ~/.config/systeroid/config.yaml. Les paramètres du fichier de configuration peuvent être outrepassés par des arguments de ligne de commande.

Exemple de fichier de configuration :

hosts:
  - hostname: server1.example.com
    user: admin
    port: 22
    key: ~/.ssh/id_rsa
  - hostname: server2.example.com
    user: deploy
    password: "your_password" # Déconseillé

ssh_timeout: 30
action_timeout: 60
throttle_time: 10
log_file: /var/log/systeroid.log
