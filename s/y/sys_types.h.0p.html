PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

sys/types.h — types de données

SYNTAXE

#include <sys/types.h>

DESCRIPTION

L'en-tête <sys/types.h> définit au moins les types suivants :

blkcnt_t
Utilisé pour les décomptes de blocs de fichiers.
blksize_t
Utilisé pour les tailles de blocs.
clock_t
Utilisé pour les temps système en ticks d'horloge ou CLOCKS_PER_SEC ; voir <time.h>.
clockid_t
Utilisé pour le type d'ID d'horloge dans les fonctions d'horloge et de minuteur.
dev_t
Utilisé pour les identifiants de périphériques.
fsblkcnt_t
Utilisé pour les décomptes de blocs de systèmes de fichiers.
fsfilcnt_t
Utilisé pour les décomptes de fichiers de systèmes de fichiers.
gid_t
Utilisé pour les identifiants de groupe.
id_t
Utilisé comme identifiant général ; peut contenir au moins un pid_t, uid_t ou gid_t.
ino_t
Utilisé pour les numéros de série de fichiers.
key_t
Utilisé pour la communication inter-processus XSI.
mode_t
Utilisé pour certains attributs de fichier.
nlink_t
Utilisé pour les décomptes de liens.
off_t
Utilisé pour les tailles de fichiers.
pid_t
Utilisé pour les identifiants de processus et les identifiants de groupe de processus.
pthread_attr_t
Utilisé pour identifier un objet d'attributs de thread.
pthread_barrier_t
Utilisé pour identifier une barrière.
pthread_barrierattr_t
Utilisé pour définir un objet d'attributs de barrière.
pthread_cond_t
Utilisé pour les variables de condition.
pthread_condattr_t
Utilisé pour identifier un objet d'attributs de condition.
pthread_key_t
Utilisé pour les clés de données spécifiques aux threads.
pthread_mutex_t
Utilisé pour les mutex.
pthread_mutexattr_t
Utilisé pour identifier un objet d'attributs de mutex.
pthread_once_t
Utilisé pour l'initialisation dynamique de packages.
pthread_rwlock_t
Utilisé pour les verrous de lecture-écriture.
pthread_rwlockattr_t
Utilisé pour les attributs de verrous de lecture-écriture.
pthread_spinlock_t
Utilisé pour identifier un verrou tournant.
pthread_t
Utilisé pour identifier un thread.
size_t
Utilisé pour les tailles d'objets.
ssize_t
Utilisé pour un décompte d'octets ou une indication d'erreur.
suseconds_t
Utilisé pour le temps en microsecondes.
time_t
Utilisé pour le temps en secondes.
timer_t
Utilisé pour l'ID de minuteur retourné par timer_create().
trace_attr_t
Utilisé pour identifier un objet d'attributs de flux de trace
trace_event_id_t
Utilisé pour identifier un type d'événement de trace.
trace_event_set_t
Utilisé pour identifier un ensemble de types d'événements de trace.
trace_id_t
Utilisé pour identifier un flux de trace.
uid_t
Utilisé pour les identifiants d'utilisateur.

Tous les types seront définis comme des types arithmétiques de longueur appropriée, à l'exception des suivants :

pthread_attr_t
pthread_barrier_t
pthread_barrierattr_t
pthread_cond_t
pthread_condattr_t
pthread_key_t
pthread_mutex_t
pthread_mutexattr_t
pthread_once_t
pthread_rwlock_t
pthread_rwlockattr_t
pthread_spinlock_t
pthread_t
timer_t
trace_attr_t
trace_event_id_t
trace_event_set_t
trace_id_t

De plus :

*
mode_t sera un type entier.
*
dev_t sera un type entier.
*
nlink_t, uid_t, gid_t et id_t seront des types entiers.
*
blkcnt_t et off_t seront des types entiers signés.
*
fsblkcnt_t, fsfilcnt_t et ino_t seront définis comme des types entiers non signés.
*
size_t sera un type entier non signé.
*
blksize_t, pid_t et ssize_t seront des types entiers signés.
*
clock_t sera un type entier ou à virgule flottante réel. time_t sera un type entier.

Le type ssize_t sera capable de stocker des valeurs au moins dans la plage [-1, {SSIZE_MAX}].

Le type suseconds_t sera un type entier signé capable de stocker des valeurs au moins dans la plage [-1, 1000000].

L'implémentation supportera un ou plusieurs environnements de programmation dans lesquels les largeurs de blksize_t, pid_t, size_t, ssize_t et suseconds_t ne seront pas supérieures à la largeur du type long. Les noms de ces environnements de programmation peuvent être obtenus en utilisant la fonction confstr() ou l'utilitaire getconf.

Il n'y a pas d'opérateurs de comparaison ou d'assignation définis pour les types suivants :

pthread_attr_t
pthread_barrier_t
pthread_barrierattr_t
pthread_cond_t
pthread_condattr_t
pthread_mutex_t
pthread_mutexattr_t
pthread_rwlock_t
pthread_rwlockattr_t
pthread_spinlock_t
timer_t
trace_attr_t

PROLOG

This document is the POSIX.1-2018 standard for the `<sys/types.h>` header file. It is part of the IEEE Std 1003.1-2018 (“POSIX.1”) standard.

NAME

sys_types.h

— basic system data types

SYNOPSIS

#include <sys/types.h>

DESCRIPTION

The <sys/types.h> header shall define basic system data types that are used throughout the system. Some of these types are required to be defined with specific integrity properties or sizes by the POSIX.1-2018 standard. The following data types shall be defined:

  • blkcnt_t: Type for file system block counts.

  • blksize_t: Type for block sizes.

  • clock_t: Type for system clock ticks.

  • clockid_t: Type for clock IDs.

  • cpuwhich_t: Type for CPU set identifiers.

  • dev_t: Type for device IDs.

  • fsid_t: Type for file system IDs.

  • gid_t: Type for group IDs.

  • id_t: Type for general IDs.

  • ino_t: Type for file serial numbers.

  • key_t: Type for interprocess communication keys.

  • mode_t: Type for file mode information.

  • nlink_t: Type for link counts.

  • off_t: Type for file sizes.

  • pid_t: Type for process IDs.

  • rlim64_t: Type for resource limits (64-bit).

  • rlim_t: Type for resource limits.

  • suseconds_t: Type for microseconds.

  • ssize_t: Type for a signed size.

  • time_t: Type for time in seconds.

  • timer_t: Type for timer IDs.

  • uid_t: Type for user IDs.

The following symbolic constants shall be defined:

  • _POSIX_VERSION: Expands to the version of the POSIX standard implemented.

The definitions of these types and constants may vary across different systems and architectures. However, their basic integrity and usage are defined by the POSIX standard.

APPLICATION USAGE

Applications should include <sys/types.h> whenever they need to use these basic system data types. It is often included implicitly by other POSIX headers, but it is good practice to include it explicitly when its types are used.

RATIONALE

The <sys/types.h> header file is a fundamental part of the POSIX operating system interface. It defines the basic building blocks for data structures and types used in system calls and other system-level operations. By standardizing these types, POSIX ensures a greater degree of portability for applications across different UNIX-like systems.

The types defined in this header are crucial for operations involving files, processes, users, groups, time, and resource management. The specific sizes and ranges of these types are often implementation-defined, but the POSIX standard mandates their existence and general purpose.

FUTURE DIRECTIONS

Future versions of POSIX may introduce new data types or modify existing ones to accommodate new system functionalities and evolving hardware capabilities. Developers should stay informed about the latest POSIX standards and best practices.
