SYSLINUX(1) Manuel des commandes générales SYSLINUX(1)

NOM

syslinux - installe le chargeur d'amorçage SYSLINUX sur un système de fichiers FAT

SYNTAXE

syslinux [OPTIONS] périphérique

DESCRIPTION

Syslinux est un chargeur d'amorçage pour le système d'exploitation Linux qui fonctionne à partir d'un système de fichiers MS-DOS/Windows FAT. Il est destiné à simplifier la première installation de Linux et à la création de disquettes de secours et autres disquettes d'amorçage spéciales.

Pour créer une disquette Linux amorçable à l'aide de Syslinux, préparez une disquette formatée MS-DOS normale. Copiez-y un ou plusieurs fichiers de noyau Linux, puis exécutez la commande :

syslinux --install /dev/fd0

Cela modifiera le secteur d'amorçage du disque et copiera un fichier nommé ldlinux.sys dans son répertoire racine.

Au démarrage, par défaut, le noyau sera chargé à partir de l'image nommée LINUX sur la disquette d'amorçage. Cette valeur par défaut peut être modifiée, voir la section sur le fichier de configuration de syslinux.

Si les touches Maj ou Alt sont maintenues enfoncées pendant le démarrage, ou si les verrouillages Verr Maj ou Verr Défil sont activés, syslinux affichera une invite de type "boot:" de lilo(8). L'utilisateur peut alors taper le nom d'un fichier de noyau suivi de tout paramètre du noyau. Le chargeur d'amorçage SYSLINUX n'a pas besoin de connaître le fichier du noyau à l'avance ; il suffit qu'il s'agisse d'un fichier situé dans le répertoire racine du disque.

Syslinux prend en charge le chargement des disques RAM initiaux (initrd) et du format de noyau bzImage.

OPTIONS

-i, --install
Installe SYSLINUX sur un nouveau support, en écrasant tout chargeur d'amorçage précédemment installé.
-U, --update
Installe SYSLINUX sur un nouveau support si et seulement si une version de SYSLINUX est déjà installée.
-s, --stupid
Installe une version "sûre, lente et stupide" de SYSLINUX. Cette version peut fonctionner sur certains BIOS très bogués sur lesquels SYSLINUX échouerait autrement. Si vous trouvez une machine pour laquelle l'option -s est requise pour qu'elle démarre de manière fiable, veuillez envoyer autant d'informations que possible sur votre machine, et inclure le mode de défaillance.
-f, --force
Force l'installation même si cela semble dangereux.
-r, --raid
Mode RAID. Si le démarrage échoue, demandez au BIOS de démarrer le périphérique suivant dans la séquence de démarrage (généralement le disque dur suivant) au lieu de s'arrêter avec un message d'erreur. Ceci est utile pour le démarrage RAID-1.
-d, --directory sous-répertoire
Installe les fichiers de contrôle SYSLINUX dans un sous-répertoire portant le nom spécifié (par rapport au répertoire racine sur le périphérique).
-t, --offset décalage
Indique que le système de fichiers se trouve à un décalage par rapport à la base du périphérique ou du fichier.
--once commande
Déclare une commande de démarrage à essayer uniquement lors du premier démarrage.
-O, --clear-once
Efface la commande de démarrage unique.
-H, --heads nombre-de-têtes
Remplace le nombre détecté de têtes pour la géométrie.
-S, --sectors nombre-de-secteurs
Remplace le nombre détecté de secteurs pour la géométrie.
-z, --zipdrive
Suppose une géométrie de lecteur zip (--heads 64 --sectors 32).

FICHIERS

Fichier de configuration

Tous les paramètres configurables de SYSLINUX peuvent être modifiés en plaçant un fichier nommé syslinux.cfg dans le répertoire d'installation du disque de démarrage. Il s'agit d'un fichier texte au format UNIX ou DOS, contenant un ou plusieurs des éléments suivants (la casse est insensible pour les mots-clés).

Cette liste est obsolète.

Dans le fichier de configuration, les lignes vides et les lignes de commentaire commençant par un dièse (#) sont ignorées.

default noyau [ options ... ]
Définit la ligne de commande par défaut. Si syslinux démarre automatiquement, il agira comme si les entrées après "default" avaient été tapées à l'invite "boot:".
Si aucune instruction DEFAULT ou UI n'est trouvée, ou si le fichier de configuration est complètement manquant, SYSLINUX bascule sur l'invite boot: avec un message d'erreur (si NOESCAPE est défini, il s'arrête avec un message "boot failed" ; c'est également le cas pour PXELINUX si le fichier de configuration n'est pas trouvé.)
NOTE : Jusqu'à SYSLINUX 3.85, si aucun fichier de configuration n'est présent, ou si aucune
entrée "default" n'est présente dans le fichier de configuration, la valeur par défaut est "linux auto".
Même les versions antérieures de SYSLINUX avaient l'habitude d'ajouter automatiquement
la chaîne "auto" à tout ce que l'utilisateur spécifiait avec la commande DEFAULT. Depuis la version 1.54, ce n'est plus le cas, car cela causait des problèmes lors de l'utilisation d'un shell en remplacement de "init". Vous voudrez peut-être inclure cette option manuellement.
append options ...
Ajoute une ou plusieurs options à la ligne de commande du noyau. Celles-ci sont ajoutées à la fois pour les démarrages automatiques et manuels. Les options sont ajoutées tout au début de la ligne de commande du noyau, permettant généralement aux options du noyau explicitement saisies de les remplacer. Ceci est l'équivalent de l'option lilo(8)
"append".
label étiquette
kernel image
append options ...
Indique que si étiquette est entrée comme noyau à démarrer, syslinux démarrera plutôt image, et les options "append" spécifiées seront utilisées à la place de celles spécifiées dans la section globale du fichier (avant la première commande "label".) La valeur par défaut pour image est la même que pour étiquette, et s'il n'y a pas d'"append", la valeur par défaut est d'utiliser l'entrée globale (s'il y en a une). Utilisez "append -" pour n'utiliser aucune option. Jusqu'à 128 entrées "label" sont autorisées.
L'"image" n'a pas besoin d'être un noyau Linux ; cela peut être un secteur de démarrage (voir ci-dessous.)
implicit valeur_indic
Si valeur_indic est 0, ne charge aucune image de noyau à moins qu'elle n'ait été explicitement nommée dans une instruction "label". La valeur par défaut est 1.
timeout délai
Indique combien de temps attendre à l'invite "boot:" avant de démarrer automatiquement, en unités de 1/10 s. Le délai est annulé dès que l'utilisateur tape quelque chose sur le clavier, en supposant que l'utilisateur terminera la ligne de commande déjà commencée. Un délai de zéro désactivera complètement le délai, c'est également la valeur par défaut. La valeur maximale possible du délai est 35996 ; correspondant à juste moins d'une heure.
serial port [ débit_en_bauds ]
Active un port série pour agir comme console. "port" est un nombre (0 = /dev/ttyS0 = COM1, etc.) ; si "débit_en_bauds" est omis, le débit par défaut est de 9600 bps. Les paramètres série sont codés en dur pour être 8 bits, pas de parité, 1 bit d'arrêt.
Pour que cette directive fonctionne correctement, elle doit être la première directive dans le fichier de configuration.
font nom_fichier
Charge une police au format .psf avant d'afficher toute sortie (à l'exception de la ligne de copyright, qui est affichée lors du chargement de ldlinux.sys lui-même.) syslinux charge uniquement la police sur la carte vidéo ; si le fichier .psf contient
s a table Unicode, elle est ignorée. Ceci ne fonctionne que sur les cartes EGA et VGA ; espérons que cela ne fera rien sur les autres.
kbdmap keymap
Installe une carte de clavier simple. Le remappeur de clavier utilisé est *très* simpliste (il remappe simplement les codes de touches reçus du BIOS, ce qui signifie que seules les combinaisons de touches pertinentes dans la disposition par défaut - généralement l'anglais américain - peuvent être mappées) mais devrait au moins aider les personnes ayant une disposition de clavier AZERTY et les emplacements de = et , (deux caractères spéciaux utilisés intensivement sur la ligne de commande du noyau Linux).
Le programme inclus keytab-lilo.pl(8) de la distribution lilo(8)
peut être utilisé pour créer de telles cartes de clavier.
display nom_fichier
Affiche le fichier indiqué à l'écran au moment du démarrage (avant l'invite boot :, si elle est affichée). Veuillez consulter la section ci-dessous sur les fichiers DISPLAY. Si le fichier est manquant, cette option est simplement ignorée.
prompt val_indicateur
Si val_indicateur est 0, affiche l'invite "boot :" uniquement si la touche Maj ou Alt est enfoncée, ou si Verr Maj ou Arrêt Défil est activé (c'est le comportement par défaut). Si val_indicateur est 1, affiche toujours l'invite "boot :".
f1 nom_fichier
f2 nom_fichier
...
f9 nom_fichier
f10 nom_fichier
f11 nom_fichier
f12 nom_fichier
Affiche le fichier indiqué à l'écran lorsqu'une touche de fonction est enfoncée à l'invite "boot :". Ceci peut être utilisé pour implémenter une aide en ligne avant le démarrage (vraisemblablement pour les options de la ligne de commande du noyau.)
Lors de l'utilisation de la console série, appuyez sur <Ctrl-F><chiffre> pour accéder aux écrans d'aide, par exemple <Ctrl-F>2 pour accéder à l'écran f2. Pour f10-f12, appuyez sur <Ctrl-F>A, <Ctrl-F>B, <Ctrl-F>C. Pour la compatibilité avec les versions antérieures, f10 peut également être saisi comme <Ctrl-F>0.

Format des fichiers DISPLAY

Les fichiers d'aide DISPLAY et de touches de fonction sont des fichiers texte au format DOS ou UNIX (avec ou sans <CR>). De plus, les codes spéciaux suivants sont interprétés :

<FF> = <Ctrl-L> = ASCII 12
Efface l'écran, ramène le curseur au début. Notez que l'écran est rempli avec la couleur d'affichage actuelle.
<SI><bg><fg>, <SI> = <Ctrl-O> = ASCII 15
Définit les couleurs d'affichage aux couleurs d'arrière-plan et de premier plan spécifiées, où <bg> et <fg> sont des chiffres hexadécimaux, correspondant aux attributs d'affichage standard du PC :
0 = noir	8 = gris foncé
1 = bleu foncé	9 = bleu vif
2 = vert foncé	a = vert vif
3 = cyan foncé	b = cyan vif
4 = rouge foncé	c = rouge vif
5 = violet foncé	d = violet vif
6 = marron	e = jaune
7 = gris clair	f = blanc
Choisir une couleur vive (8-f) pour l'arrière-plan entraîne la couleur sombre correspondante (0-7), avec le premier plan clignotant.
les couleurs ne sont pas visibles sur la console série.
<CAN>nom_fichier<nouvelle_ligne>, <CAN> = <Ctrl-X> = ASCII 24
Si un affichage VGA est présent, passe en mode graphique et affiche le graphique inclus dans le fichier spécifié. Le format de fichier est un format ad hoc appelé LSS16 ; le programme Perl inclus "ppmtolss16" peut être utilisé pour produire ces images. Ce programme Perl inclut également la spécification du format de fichier.
L'image est affichée en mode 640x480 16 couleurs. Une fois en mode graphique, les attributs d'affichage (définis par des séquences de codes <SI>) fonctionnent légèrement différemment : la couleur d'arrière-plan est ignorée, et les couleurs de premier plan sont les 16 couleurs spécifiées dans le fichier image. Pour cette raison, ppmtolss16 vous permet de spécifier que certaines couleurs doivent être attribuées à des indices de couleur spécifiques.
Les indices de couleur 0 et 7, en particulier, doivent être choisis avec soin : 0 est la couleur d'arrière-plan, et 7 est la couleur utilisée pour le texte imprimé par SYSLINUX lui-même.
<EM>, <EM> = <Ctrl-U> = ASCII 25
Si nous sommes actuellement en mode graphique, revient en mode texte.
<DLE>..<ETB>, <Ctrl-P>..<Ctrl-W> = ASCII 16-23
Ces codes peuvent être utilisés pour sélectionner les modes dans lesquels imprimer une partie du fichier message. Chacun de ces caractères de contrôle sélectionne un ensemble spécifique de modes (écran texte, écran graphique, port série) pour lesquels la sortie est effectivement affichée :
Caractère                       Texte    Graph.   Série
------------------------------------------------------
<DLE> = <Ctrl-P> = ASCII 16     Non      Non      Non
<DC1> = <Ctrl-Q> = ASCII 17     Oui      Non      Non
<DC2> = <Ctrl-R> = ASCII 18     Non      Oui      Non
<DC3> = <Ctrl-S> = ASCII 19     Oui      Oui      Non
<DC4> = <Ctrl-T> = ASCII 20     Non      Non      Oui
<NAK> = <Ctrl-U> = ASCII 21     Oui      Non      Oui
<SYN> = <Ctrl-V> = ASCII 22     Non      Oui      Oui
<ETB> = <Ctrl-W> = ASCII 23     Oui      Oui      Oui
Par exemple : 
<DC1>Mode texte<DC2>Mode graphique<DC4>Port série<ETB>

... affichera en fait dans quel mode se trouve la console !
<SUB> = <Ctrl-Z> = ASCII 26
Fin de fichier (convention DOS).

Autres systèmes d'exploitation

Cette version de syslinux prend en charge le chaînage d'autres systèmes d'exploitation (tels que MS-DOS et ses dérivés, y compris Windows 95/98).

Le chaînage nécessite que le secteur de démarrage du système d'exploitation étranger soit stocké dans un fichier dans le répertoire racine du système de fichiers. Étant donné que ni les noyaux Linux, ni les images de secteur de démarrage n'ont de nombres magiques fiables, syslinux examine l'extension du fichier. Les extensions suivantes sont reconnues :

aucun ou autre	Image du noyau Linux
BSS	Secteur de démarrage (superbloc DOS sera patché)
BS	Secteur de démarrage

Pour les noms de fichiers donnés sur la ligne de commande, syslinux recherchera le fichier en ajoutant les extensions dans l'ordre indiqué ci-dessus si le nom de fichier simple n'est pas trouvé. Les noms de fichiers dans les instructions KERNEL doivent être entièrement qualifiés.

Protection des novices

Syslinux tentera de détecter si l'utilisateur essaie de démarrer sur une machine de classe 286 ou inférieure, ou une machine avec moins de 608 Ko de RAM basse ("DOS") (ce qui signifie que la séquence de démarrage Linux ne peut pas se terminer). Si c'est le cas, un message est affiché et la séquence de démarrage est abandonnée. Maintenir la touche Ctrl enfoncée pendant le démarrage désactive cette fonctionnalité.

L'heure et la date de compilation d'une version spécifique de syslinux peuvent être obtenues par la commande DOS "type ldlinux.sys". Ceci est également utilisé comme signature pour le fichier LDLINUX.SYS, qui doit correspondre au secteur de démarrage.

Tout fichier que syslinux utilise peut être marqué comme caché, système ou en lecture seule si cela est pratique ; syslinux ignore tous les attributs de fichier. SYSLINUX installé définit automatiquement l'attribut en lecture seule sur LDLINUX.SYS.

CD-ROMs amorçables

SYSLINUX peut être utilisé pour créer des images de disquettes de démarrage pour des CD-ROMs amorçables compatibles El Torito. Cependant, il semble que de nombreux BIOS soient très bogués lorsqu'il s'agit de démarrer des CD-ROMs. Certains utilisateurs ont signalé que les étapes suivantes sont utiles pour créer un CD-ROM qui démarre sur le plus grand nombre possible de machines :

  • Utilisez l'option -s (sûr, lent et stupide) pour SYSLINUX
  • Placez l'image de démarrage aussi près que possible du début du système de fichiers ISO 9660.

Un CD-ROM est tellement plus rapide qu'une disquette que l'option -s ne devrait pas avoir d'importance du point de vue de la vitesse.

Bien sûr, vous voudrez probablement utiliser ISOLINUX à la place. Voir le fichier de documentation isolinux.doc.

Démarrage depuis une partition FAT sur un disque dur

SYSLINUX peut démarrer depuis une partition de système de fichiers FAT sur un disque dur (y compris FAT32). La procédure d'installation est identique à la procédure pour l'installer sur une disquette, et devrait fonctionner sous DOS ou Linux. Pour démarrer depuis une partition, SYSLINUX doit être lancé depuis un Master Boot Record ou un autre chargeur de démarrage, tout comme le ferait DOS lui-même. Un exemple de secteur de démarrage maître (mbr.bin) est inclus avec SYSLINUX.

BOGUES

Je serais heureux d'entendre parler de tout problème que vous pourriez rencontrer avec SYSLINUX. J'aimerais également avoir de vos nouvelles si vous avez utilisé SYSLINUX avec succès, surtout si vous l'utilisez pour une distribution.

Si vous signalez des problèmes, veuillez inclure toutes les informations possibles sur votre système et votre BIOS ; la grande majorité de tous les problèmes signalés s'avèrent être des bogues de BIOS ou de matériel, et j'ai besoin d'autant d'informations que possible pour diagnostiquer les problèmes.

Il existe une liste de diffusion pour les discussions entre utilisateurs SYSLINUX et pour les annonces de nouvelles versions et de versions de test. Pour vous y inscrire, envoyez un message à majordomo@linux.kernel.org avec la ligne :

subscribe syslinux

dans le corps du message. L'adresse de soumission est syslinux@linux.kernel.org.
