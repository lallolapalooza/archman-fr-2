NOM

systemd-getty-generator - Générateur pour activer des instances getty sur la console

SYNTAXE

/usr/lib/systemd/system-generators/systemd-getty-generator

DESCRIPTION

systemd-getty-generator est un générateur qui instancie automatiquement serial-getty@.service sur les consoles du noyau, si elles peuvent fonctionner comme des ttys et ne sont pas fournies par le sous-système de console virtuelle. Il instanciera également des instances de serial-getty@.service pour les consoles de virtualiseurs, si une exécution dans un environnement virtualisé est détectée. Si une exécution dans un environnement conteneurisé est détectée, il activera à la place console-getty.service pour /dev/console, et des instances de container-getty@.service pour des pseudo TTYs de conteneur supplémentaires comme demandé par le gestionnaire de conteneur (voir Interface de conteneur[1]). Cela devrait garantir que l'utilisateur voit une invite de connexion au bon endroit, quel que soit l'environnement dans lequel le système est démarré. Par exemple, il suffit de rediriger la console du noyau avec un argument de ligne de commande du noyau tel que console= pour obtenir à la fois les messages du noyau et une invite getty sur un TTY série. Voir Les paramètres de ligne de commande du noyau[2] pour plus d'informations sur le paramètre du noyau console=.

systemd-getty-generator implémente systemd.generator(7).

Des informations supplémentaires sur la configuration des gettys peuvent être trouvées dans systemd pour Administrateurs, Partie XVI : Gettys sur les Consoles Série (et Ailleurs)[3].

LIGNE DE COMMANDE DU NOYAU

systemd-getty-generator comprend les paramètres suivants de kernel-command-line(7) :

systemd.getty_auto=

Cette option de ligne de commande du noyau peut être utilisée pour contrôler le mode d'exécution du générateur. Prend un argument booléen optionnel. Depuis la v258, cela prend également une liste séparée par des virgules de valeurs spéciales : "credential", "container", "console", et "builtin".

Lorsque "credential" est spécifié, les deux identifiants getty.ttys.serial et getty.ttys.container seront analysés. Voir la section Identifiants système ci-dessous pour plus de détails.

Lorsque "container" est spécifié, console-getty.service et container-getty@.service seront activés lorsque le système s'exécute dans un conteneur. Cette option sera ignorée lorsque le système ne s'exécute pas dans un conteneur.

Lorsque "console" est spécifié, serial-getty@.service pour les consoles du noyau actives sera activé. Cette option sera ignorée lorsque le système s'exécute dans un conteneur.

Lorsque "builtins" est spécifié, serial-getty@.service pour les consoles de virtualiseur disponibles sera activé. Cette option sera ignorée lorsque le système s'exécute dans un conteneur.

Lorsque oui, les quatre options ci-dessus seront activées. Lorsque non, toutes les options sont désactivées et aucun service ne sera activé. Lorsque l'option de ligne de commande du noyau est spécifiée sans argument, elle vaut par défaut oui. Le générateur est activé par défaut, et une valeur fausse peut être utilisée pour le désactiver.

Ajouté dans la version 250.

ENVIRONNEMENT

$SYSTEMD_GETTY_AUTO

Cette variable d'environnement peut être utilisée pour contrôler le mode d'exécution du générateur. Prend la même valeur que l'option de ligne de commande du noyau systemd.getty_auto=.

Ajouté dans la version 250.

IDENTIFIANTS SYSTÈME

getty.auto

L'identifiant système peut être utilisé pour contrôler le mode d'exécution du générateur. Prend la même valeur que l'option de ligne de commande du noyau systemd.getty_auto=.

Ajouté dans la version 258.

getty.ttys.serial, getty.ttys.container

Ces identifiants système peuvent être utilisés pour lancer des invites de connexion supplémentaires sur des TTYs sélectionnés. Les deux identifiants doivent contenir une liste de noms de TTY séparés par des sauts de ligne pour lancer des instances de serial-getty@.service (dans le cas de getty.ttys.serial) et de container-getty@.service (dans le cas de getty.ttys.container) sur ceux-ci. Toutes les lignes commençant par un "#" seront ignorées.

Ajouté dans la version 254.
