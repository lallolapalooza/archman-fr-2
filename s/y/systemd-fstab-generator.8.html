NOM

systemd-fstab-generator - Générateur d'unité pour /etc/fstab

SYNTAXE

/usr/lib/systemd/system-generators/systemd-fstab-generator

DESCRIPTION

systemd-fstab-generator est un générateur qui traduit /etc/fstab (voir fstab(5) pour les détails) en unités systemd natives tôt au démarrage et lors du rechargement de la configuration du gestionnaire système. Cela instanciera des unités de montage et de swap selon les besoins.

Le champ passno est traité comme un simple booléen, et les informations d'ordonnancement sont ignorées. Cependant, si le système de fichiers racine est vérifié, il est vérifié avant tous les autres systèmes de fichiers.

Consultez systemd.mount(5) et systemd.swap(5) pour plus d'informations sur les options spéciales de montage /etc/fstab que ce générateur comprend.

Un sujet spécial est la gestion des liens symboliques. Les implémentations d'init historiques prenaient en charge les liens symboliques dans /etc/fstab. Comme les unités de montage refusent les montages où la cible est un lien symbolique, ce générateur résoudra les liens symboliques autant que possible lors du traitement de /etc/fstab afin d'améliorer la compatibilité descendante. Si la cible d'un lien symbolique n'existe pas au moment où ce générateur s'exécute, on suppose que la cible du lien symbolique est la cible finale du montage.

systemd-fstab-generator implémente systemd.generator(7).

LIGNE DE COMMANDE DU NOYAU

systemd-fstab-generator comprend les paramètres suivants de la ligne de commande du noyau :

fstab=, rd.fstab=

Prend un argument booléen. Par défaut, "yes". Si "no", le générateur ignore tous les montages ou périphériques de swap configurés dans /etc/fstab. rd.fstab= n'est honoré que dans l'initrd, tandis que fstab= est honoré par le système principal et l'initrd.

Ajouté dans la version 186.

root=

Configure le système de fichiers racine du système d'exploitation à monter lors de l'exécution dans l'initrd. Cela accepte un chemin de nœud de périphérique (généralement /dev/disk/by-uuid/... ou /dev/disk/by-label/... ou similaire), ou les valeurs spéciales "gpt-auto", "gpt-auto-force", "dissect", "dissect-force", "fstab", "fstab", et "off".

Défini sur "gpt-auto", "gpt-auto-force", "dissect", "dissect-force" pour demander explicitement la découverte automatique du système de fichiers racine, implémentée dans systemd-gpt-auto-generator(8).

Utilisez "fstab" pour demander explicitement la découverte automatique du système de fichiers racine via l'initrd /etc/fstab plutôt que via la ligne de commande du noyau.

Utilisez "tmpfs" pour monter un système de fichiers tmpfs(5) comme système de fichiers racine du système d'exploitation. Ceci est utile en combinaison avec mount.usr= (voir ci-dessous) pour combiner un système de fichiers racine volatil avec un système de fichiers /usr/ séparé et immuable. Voir également systemd.volatile= ci-dessous.

Utilisez "bind:..." pour effectuer un montage par liaison d'un autre répertoire comme système de fichiers racine du système d'exploitation (ajouté en v258). Attend un nom de chemin absolu faisant référence à un répertoire existant dans la hiérarchie de fichiers de l'initrd pour démarrer.

Défini sur "off" pour désactiver le montage d'un système de fichiers racine.

Notez que d'autres valeurs root= peuvent être prises en charge, implémentées dans des paquets supplémentaires.

Ajouté dans la version 217.

rootfstype=

Prend le type de système de fichiers racine qui sera passé à la commande mount. rootfstype= est honoré par l'initrd.

Ajouté dans la version 217.

rootflags=

Prend les options de montage du système de fichiers racine à utiliser. rootflags= est honoré par l'initrd.

Notez que contrairement à la plupart des options de ligne de commande du noyau, ce paramètre ne remplace pas les paramètres définis dans les fichiers de configuration (spécifiquement : la chaîne d'options de montage dans /etc/fstab). Voir systemd-remount-fs.service(8).

Ajouté dans la version 217.

mount.usr=

Prend le système de fichiers /usr/ à monter par l'initrd. Si mount.usrfstype= ou mount.usrflags= est défini, alors le montage configuré via mount.usr= utilisera par défaut la même valeur que celle définie dans root=.

Défini sur "dissect" pour demander explicitement la découverte automatique du système de fichiers /usr/, implémentée dans systemd-gpt-auto-generator(8).

Défini sur "off" pour désactiver le montage d'un système de fichiers /usr/ séparé.

mount.usr= est honoré par l'initrd.

Ajouté dans la version 217.

mount.usrfstype=

Prend le type de système de fichiers /usr/ qui sera passé à la commande mount. Si mount.usr= ou mount.usrflags= est défini, alors mount.usrfstype= utilisera par défaut la valeur définie dans rootfstype=.

Sinon, cette valeur sera lue à partir de l'entrée /usr/ dans /etc/fstab sur le système de fichiers racine.

mount.usrfstype= est honoré par l'initrd.

Ajouté dans la version 217.

mount.usrflags=

Prend les options de montage du système de fichiers /usr/ à utiliser. Si mount.usr= ou mount.usrfstype= est défini, alors mount.usrflags= utilisera par défaut la valeur définie dans rootflags=.

Sinon, cette valeur sera lue à partir de l'entrée /usr/ dans /etc/fstab sur le système de fichiers racine.

mount.usrflags= est honoré par l'initrd.

Ajouté dans la version 217.

roothash=, usrhash=

Ces options sont principalement lues par systemd-veritysetup-generator(8). Lorsqu'elles sont définies, cela indique que le système de fichiers racine (ou /usr/) doit être monté à partir de volumes Verity avec les hachages spécifiés. Si ces options de ligne de commande du noyau sont définies, le système de fichiers racine (ou /usr/) est ainsi monté à partir d'un volume de mappage de périphériques /dev/mapper/root (ou /dev/mapper/usr).

Ajouté dans la version 251.

systemd.volatile=

Contrôle si le système doit démarrer en mode volatil. Prend un argument booléen ou la valeur spéciale state.

Si faux (par défaut), ce générateur n'apporte aucune modification à l'arborescence des montages et le système démarre en mode normal.

Si vrai, le générateur s'assure que systemd-volatile-root.service(8) est exécuté dans l'initrd. Ce service modifie la table des montages avant de passer au système hôte, de sorte qu'un système de fichiers en mémoire vive volatile ("tmpfs") est utilisé comme répertoire racine, avec uniquement /usr/ monté à partir du système de fichiers racine configuré, en mode lecture seule. De cette façon, le système fonctionne en mode entièrement sans état, toutes les configurations et l'état étant réinitialisés au démarrage et perdus à l'arrêt, car /etc/ et /var/ seront servis à partir du système de fichiers en mémoire vive volatile (initialement vide).

Si défini sur state, le générateur laissera le point de montage du répertoire racine inchangé, mais montera un système de fichiers "tmpfs" sur /var/. Dans ce mode, la configuration normale du système (c'est-à-dire le contenu de "/etc/") est effective (et peut être modifiée pendant l'exécution du système), mais l'état du système (c'est-à-dire le contenu de "/var/") est réinitialisé au démarrage et perdu à l'arrêt.

Si ce paramètre est défini sur "overlay", le système de fichiers racine est configuré comme un montage "overlayfs" combinant le répertoire racine en lecture seule avec un "tmpfs" inscriptible, de sorte qu'aucune modification n'est apportée au disque, mais le système de fichiers peut néanmoins être modifié, toutes les modifications étant perdues au redémarrage.

Notez que dans aucun de ces modes les ressources stockées dans le système de fichiers racine, telles que le répertoire racine, /etc/, /var/ ou d'autres, ne sont physiquement supprimées. Il est donc sûr de démarrer un système normalement exploité en mode non volatil temporairement en mode volatil, sans perdre de données.

Notez qu'à l'exception du mode "overlay", l'activation de ce paramètre ne fonctionnera correctement que sur les systèmes d'exploitation pouvant démarrer avec uniquement /usr/ monté, et capables de peupler automatiquement /etc/, et également /var/ dans le cas de "systemd.volatile=yes".

Ajouté dans la version 233.

systemd.swap=

Prend un argument booléen ou active l'option si spécifiée sans argument. Si désactivé, fait en sorte que le générateur ignore tous les périphériques de swap configurés dans /etc/fstab. Par défaut, il est activé.

Ajouté dans la version 246.

systemd.mount-extra=WHAT:WHERE[:FSTYPE[:OPTIONS]], rd.systemd.mount-extra=WHAT:WHERE[:FSTYPE[:OPTIONS]]

Spécifie l'unité de montage. Prend au moins deux et au plus quatre champs séparés par deux points (":"). Chaque champ est traité comme le champ fstab correspondant. Cette option peut être spécifiée plusieurs fois. rd.systemd.mount-extra= n'est honoré que dans l'initrd, tandis que systemd.mount-extra= est honoré par le système principal et par l'initrd. Dans l'initrd, le point de montage (et aussi le chemin source si le montage est un montage par liaison) spécifié dans systemd.mount-extra= est préfixé par /sysroot/.

Exemple :

systemd.mount-extra=/dev/sda1:/mount-point:ext4:rw,noatime

Ajouté dans la version 254.

systemd.swap-extra=WHAT[:OPTIONS], rd.systemd.swap-extra=WHAT[:OPTIONS]

Spécifie l'unité de swap. Prend le périphérique bloc à utiliser comme périphérique de swap, et prend éventuellement des options de montage suivies d'un deux points (":"). Cette option peut être spécifiée plusieurs fois. rd.systemd.swap-extra= n'est honoré que dans l'initrd, tandis que systemd.swap-extra= est honoré par le système principal et par l'initrd.

Exemple :

systemd.swap-extra=/dev/sda2:x-systemd.makefs

Ajouté dans la version 254.

IDENTIFIANTS SYSTÈME

fstab.extra

Cet identifiant peut contenir des montages supplémentaires à établir, dans le même format que fstab(5), avec un montage par ligne. Il est lu en plus de /etc/fstab.

Ajouté dans la version 254.
