NOM

systemd.environment-generator - générateurs de fichiers d'environnement systemd

SYNTAXE

/usr/lib/systemd/system-environment-generators/quelque-generateur

/usr/lib/systemd/user-environment-generators/quelque-generateur

/run/systemd/system-environment-generators/*
/etc/systemd/system-environment-generators/*
/usr/local/lib/systemd/system-environment-generators/*
/usr/lib/systemd/system-environment-generators/*
/run/systemd/user-environment-generators/*
/etc/systemd/user-environment-generators/*
/usr/local/lib/systemd/user-environment-generators/*
/usr/lib/systemd/user-environment-generators/*

DESCRIPTION

Les générateurs sont de petits exécutables situés dans /usr/lib/systemd/system-environment-generators/ et d'autres répertoires listés ci-dessus. systemd(1) exécutera ces binaires très tôt au démarrage de chaque gestionnaire et lors du rechargement de la configuration, avant d'exécuter les générateurs décrits dans systemd.generator(7) et avant de démarrer toute unité. Les générateurs d'environnement peuvent remplacer l'environnement que le gestionnaire exporte vers les services et autres processus.

Les générateurs sont chargés à partir d'un ensemble de chemins déterminés lors de la compilation, comme listé ci-dessus. Les générateurs d'environnement système et utilisateur sont chargés depuis des répertoires dont les noms se terminent par system-environment-generators/ et user-environment-generators/, respectivement. Les générateurs trouvés dans les répertoires listés précédemment remplacent ceux portant le même nom dans les répertoires situés plus bas dans la liste [1]. Un lien symbolique vers /dev/null ou un fichier vide peut être utilisé pour masquer un générateur, l'empêchant ainsi de s'exécuter. Veuillez noter que l'ordre des deux répertoires ayant la priorité la plus élevée est inversé par rapport au chemin de chargement des unités, et les générateurs dans /run/ remplacent ceux dans /etc/.

Après avoir installé de nouveaux générateurs ou mis à jour la configuration, systemctl daemon-reload peut être exécuté. Cela re-exécutera tous les générateurs, mettant à jour la configuration de l'environnement. Elle sera utilisée pour tous les services démarrés ultérieurement.

Les générateurs de fichiers d'environnement sont exécutés de manière similaire aux générateurs de fichiers d'unités décrits dans systemd.generator(7), avec les différences suivantes :

•Les générateurs sont exécutés séquentiellement dans l'ordre alphanumérique du dernier composant de leur nom. La sortie de chaque générateur est immédiatement analysée et utilisée pour mettre à jour l'environnement des générateurs qui s'exécutent après. Ainsi, les générateurs ultérieurs peuvent utiliser et/ou modifier la sortie des générateurs précédents.
•Les générateurs sont exécutés par chaque instance de gestionnaire, leur sortie peut être différente pour chaque utilisateur.

Il est recommandé d'utiliser des préfixes numériques pour les noms des générateurs afin de simplifier leur ordonnancement.

EXEMPLES

Exemple 1. Un générateur simple qui étend une variable d'environnement si un répertoire existe dans le système de fichiers

# 50-xdg-data-dirs.sh
#!/bin/sh
# SPDX-License-Identifier: MIT-0
# définit la valeur par défaut
XDG_DATA_DIRS="${XDG_DATA_DIRS:-/usr/local/share/:/usr/share}"
# ajoute un répertoire s'il existe
if [ -d /opt/foo/share ]; then
    XDG_DATA_DIRS="/opt/foo/share:${XDG_DATA_DIRS}"
fi
# écrit notre sortie
echo "XDG_DATA_DIRS=${XDG_DATA_DIRS}"

Exemple 2. Un générateur plus compliqué qui lit la configuration existante et modifie une variable

# 90-rearrange-path.py
#!/usr/bin/python
# SPDX-License-Identifier: MIT-0
"""
Générateur d'environnement systemd proof-of-concept qui s'assure que les
répertoires bin sont toujours après les répertoires sbin correspondants
dans le path.
(Change /sbin:/bin:/foo/bar en /bin:/sbin:/foo/bar.)
Ce générateur montre comment remplacer la configuration éventuellement créée
par des générateurs précédents. Il serait plus facile de l'écrire en bash,
mais utilisons-le en Python juste pour prouver que nous le pouvons, et pour
servir de modèle pour des générateurs plus intéressants.
"""
import os
import pathlib
def rearrange_bin_sbin(path):
    """Assure que toute paire de répertoires .../bin, .../sbin est dans cet ordre
    >>> rearrange_bin_sbin('/bin:/sbin:/usr/sbin:/usr/bin')
    '/bin:/sbin:/usr/bin:/usr/sbin'
    """
    items = [pathlib.Path(p) for p in path.split(':')]
    for i in range(len(items)):
        if 'sbin' in items[i].parts:
            ind = items[i].parts.index('sbin')
            bin = pathlib.Path(*items[i].parts[:ind], 'bin', *items[i].parts[ind+1:])
            if bin in items[i+1:]:
                j = i + 1 + items[i+1:].index(bin)
                items[i], items[j] = items[j], items[i]
    return ':'.join(p.as_posix() for p in items)
if __name__ == '__main__':
    path = os.environ['PATH'] # Ceci doit toujours être défini.
                              # S'il ne l'est pas, nous allons simplement planter, ce qui est aussi OK.
    new = rearrange_bin_sbin(path)
    if new != path:
        print('PATH={}'.format(new))
