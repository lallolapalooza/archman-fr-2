SYSTEM.ROOTDAEMONRC(1) Manuel des commandes générales SYSTEM.ROOTDAEMONRC(1)

NOTA BENE

L'utilisation de ce fichier est dépréciée et sera supprimée dans les futures versions de ROOT.

Veuillez contacter l'équipe ROOT à http://root.cern dans le cas peu probable où ce changement perturberait votre flux de travail.

NOM

system.rootdaemonrc, .rootdaemonrc - directives de contrôle d'accès pour les démons ROOT

EMPLACEMENTS

ROOTDAEMORC, $HOME/.rootdaemonrc
/etc/root/system.rootdaemonrc, $ROOTSYS/etc/system.rootdaemonrc

DESCRIPTION

Cette page de manuel documente le format des directives spécifiant les directives de contrôle d'accès pour les démons ROOT. Ces directives sont lues à partir d'un fichier texte dont le chemin complet est tiré de la variable d'environnement ROOTDAEMONRC. Si une telle variable est indéfinie, le démon recherche un fichier nommé .rootdaemonrc dans le répertoire $HOME de l'utilisateur qui démarre le démon ; si ce fichier n'existe pas non plus, le fichier system.rootdaemonrc, situé sous /etc/root ou $ROOTSYS/etc, est utilisé. Si aucun de ces fichiers n'existe (ou n'est lisible), le démon utilise une directive intégrée par défaut dérivée des options de configuration de l'installation.

FORMAT

*
les lignes commençant par '#' sont des lignes de commentaire.
*
les hôtes peuvent être spécifiés soit par leur nom (par exemple, pcepsft43), leur FQDN (par exemple, pcepsft43.cern.ch) ou leur adresse IP (par exemple, 137.138.99.73).
*
les directives s'appliquant à tous les hôtes peuvent être spécifiées par 'default' ou '*'
*
le caractère '*' peut être utilisé dans n'importe quel champ du nom pour indiquer un ensemble de machines ou de domaines, par exemple, pcepsft*.cern.ch s'applique à toutes les machines 'pcepsft' du domaine 'cern.ch'. (pour indiquer toutes les machines 'lxplus', vous devriez utiliser 'lxplus*.cern.ch' car en interne, la machine générique lxplus a un nom réel de la forme lxplusnnn.cern.ch ; vous pouvez également utiliser 'lxplus' si vous ne vous souciez pas de la vérification du nom de domaine).
*
un domaine entier peut être indiqué par son nom, par exemple, 'cern.ch', 'cnaf.infn.it' ou '.ch'
*
les adresses IP tronquées peuvent également être utilisées pour indiquer un ensemble de machines ; elles sont interprétées comme la toute première ou la toute dernière partie de l'adresse ; par exemple, pour sélectionner 137.138.99.73, l'un des éléments suivants est valide : '137.138.99', '137.138', '137`, '99.73' ; ou avec des jokers : '137.13*' ou '*.99.73' ; cependant, '138.99' est invalide car ambigu.
*
les informations suivant le nom ou l'adresse IP indiquent, par ordre de préférence, les noms courts ou les codes internes des méthodes d'authentification acceptées pour les requêtes provenant des hôtes spécifiés ; celles implémentées jusqu'à présent sont :


Surnom de la méthode code


UsrPwd usrpwd 0

Les méthodes non spécifiées explicitement ne sont pas acceptées.

*
les lignes se terminant par '´ sont suivies d'informations supplémentaires pour l'hôte sur la ligne suivante ; le nom de l'hôte ne doit pas être répété.

EXEMPLES

Exemples valides :

défaut aucun
Toutes les requêtes sont refusées sauf indication contraire par des directives dédiées.
défaut 0
Les mécanismes d'authentification autorisés par défaut sont 'usrpwd' (code 0)
137.138. 0
Les mécanismes d'authentification autorisés depuis les hôtes du domaine 137.138. (cern.ch) sont 'usrpwd' (code 0)
lxplus*.cern.ch 0:qwerty:uytre
Les requêtes du cluster lxplus des utilisateurs 'qwerty' et 'uytre' peuvent s'authentifier en utilisant 'usrpwd'.
pcep*.cern.ch 0:-qwerty
Les requêtes des nœuds pcep*.cern.ch peuvent s'authentifier en utilisant 'usrpwd' lors de l'accès au démon 'rootd' ; l'utilisateur 'qwerty' ne peut pas utiliser 'usrpwd'.

Pour plus d'informations sur le système ROOT, veuillez consulter http://root.cern/ .
