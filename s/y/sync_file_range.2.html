sync_file_range(2) Manuel des appels système sync_file_range(2)

NOM

sync_file_range - synchronise un segment de fichier avec le disque

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#define _FILE_OFFSET_BITS 64
#include <fcntl.h>
int sync_file_range(int fd, off_t offset, off_t nbytes,
                    unsigned int flags);

DESCRIPTION

sync_file_range() permet un contrôle fin lors de la synchronisation du fichier ouvert référencé par le descripteur de fichier fd avec le disque.

offset est le début en octets de la plage de fichier à synchroniser. nbytes spécifie la longueur de la plage à synchroniser, en octets ; si nbytes est zéro, alors tous les octets de offset jusqu'à la fin du fichier sont synchronisés. La synchronisation s'effectue par unités de la taille de page du système : offset est arrondi à la borne inférieure d'une page ; (offset+nbytes-1) est arrondi à la borne supérieure d'une page.

L'argument masqué de bits flags peut inclure n'importe laquelle des valeurs suivantes :

SYNC_FILE_RANGE_WAIT_BEFORE
Attend la sortie des écritures de toutes les pages de la plage spécifiée qui ont déjà été soumises au pilote de périphérique pour écriture avant d'effectuer toute écriture.
SYNC_FILE_RANGE_WRITE
Lance l'écriture de toutes les pages sales de la plage spécifiée qui ne sont pas actuellement soumises à l'écriture. Notez que même cela peut bloquer si vous tentez d'écrire plus que la taille de la file d'attente des requêtes.
SYNC_FILE_RANGE_WAIT_AFTER
Attend la sortie des écritures de toutes les pages de la plage après avoir effectué toute écriture.

Spécifier flags à 0 est autorisé, cela ne fait rien.

Avertissement

Cet appel système est extrêmement dangereux et ne doit pas être utilisé dans des programmes portables. Aucune de ces opérations n'écrit les métadonnées du fichier. Par conséquent, à moins que l'application ne se contente de réécrire des blocs de disque déjà existants, il n'y a aucune garantie que les données seront disponibles après un crash. Il n'y a pas d'interface utilisateur pour savoir si une écriture est purement une réécriture. Sur les systèmes de fichiers utilisant la sémantique de copie sur écriture (par exemple, btrfs), une réécriture de blocs alloués existants est impossible. Lors de l'écriture dans un espace pré-alloué, de nombreux systèmes de fichiers nécessitent également des appels à l'allocateur de blocs, que cet appel système ne synchronise pas sur le disque. Cet appel système ne vide pas les caches d'écriture sur disque et ne garantit donc pas l'intégrité des données sur les systèmes avec des caches d'écriture de disque volatils.

Quelques détails

SYNC_FILE_RANGE_WAIT_BEFORE et SYNC_FILE_RANGE_WAIT_AFTER détecteront toute erreur d'E/S ou condition ENOSPC et les renverront à l'appelant.

Des combinaisons utiles des bits de flags sont :

SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE
Assure que toutes les pages de la plage spécifiée qui étaient sales lorsque sync_file_range() a été appelé sont soumises à l'écriture. Ceci est une opération de démarrage d'écriture pour l'intégrité des données.
SYNC_FILE_RANGE_WRITE
Lance l'écriture de toutes les pages sales de la plage spécifiée qui ne sont pas actuellement sous contrôle d'écriture. Ceci est une opération de vidage asynchrone sur disque. Ceci ne convient pas aux opérations d'intégrité des données.
SYNC_FILE_RANGE_WAIT_BEFORE (ou SYNC_FILE_RANGE_WAIT_AFTER)
Attend l'achèvement de l'écriture de toutes les pages de la plage spécifiée. Ceci peut être utilisé après une opération précédente SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE pour attendre l'achèvement de cette opération et obtenir son résultat.
SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE | SYNC_FILE_RANGE_WAIT_AFTER
Ceci est une opération d'écriture pour l'intégrité des données qui assurera que toutes les pages de la plage spécifiée qui étaient sales lorsque sync_file_range() a été appelé sont validées sur le disque.

VALEUR DE RETOUR

En cas de succès, sync_file_range() renvoie 0 ; en cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide.
EINVAL
flags spécifie un bit invalide ; ou offset ou nbytes est invalide.
EIO
Erreur d'E/S.
ENOMEM
Pas assez de mémoire.
ENOSPC
Plus d'espace disque.
ESPIPE
fd fait référence à quelque chose d'autre qu'un fichier ordinaire, un périphérique bloc, ou un répertoire.

VERSIONS

sync_file_range2()

Certaines architectures (par exemple, PowerPC, ARM) nécessitent que les arguments 64 bits soient alignés dans une paire de registres appropriée. Sur de telles architectures, la signature d'appel de sync_file_range() montrée dans la SYNTAXE gaspillerait un registre en remplissage entre les arguments fd et offset. (Voir syscall(2) pour les détails.) Par conséquent, ces architectures définissent un appel système différent qui ordonne les arguments de manière appropriée :


int sync_file_range2(int fd, unsigned int flags,
                     off_t offset, off_t nbytes);

Le comportement de cet appel système est par ailleurs exactement le même que sync_file_range().

NORMES

Linux.

HISTORIQUE

Linux 2.6.17.

sync_file_range2()

Un appel système avec cette signature est apparu pour la première fois sur l'architecture ARM sous Linux 2.6.20, avec le nom arm_sync_file_range(). Il a été renommé sous Linux 2.6.22, lorsque l'appel système analogue a été ajouté pour PowerPC. Sur les architectures où la prise en charge par glibc est fournie, glibc encapsule de manière transparente sync_file_range2() sous le nom sync_file_range().

NOTES

_FILE_OFFSET_BITS doit être défini à 64 dans le code qui prend l'adresse de sync_file_range, si le code est destiné à être portable vers les plateformes traditionnelles x86 32 bits et ARM où la largeur de off_t est par défaut de 32 bits.
