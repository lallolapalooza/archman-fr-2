DESCRIPTION

Cette page man est seulement un résumé.

L'application syslog-ng OSE est une application de journalisation système flexible et hautement évolutive. Typiquement, syslog-ng OSE est utilisé pour gérer les messages de log et implémenter une journalisation centralisée, dont le but est de collecter les messages de log de plusieurs appareils sur un serveur de log unique et central. Les différents appareils - appelés clients syslog-ng OSE - exécutent tous syslog-ng OSE, et collectent les messages de log des différentes applications, fichiers et autres sources. Les clients envoient tous les messages de log importants au serveur syslog-ng OSE PE distant, où le serveur les trie et les stocke.

Concepts de base de syslog-ng OSE

L'application syslog-ng OSE lit les messages entrants et les transmet aux destinations sélectionnées. L'application syslog-ng OSE peut recevoir des messages à partir de fichiers, d'hôtes distants et d'autres sources.

Les messages de log entrent dans syslog-ng OSE dans l'une des sources définies, et sont envoyés à une ou plusieurs destinations.

Les sources et les destinations sont des objets indépendants, les chemins de log définissent ce que syslog-ng OSE fait avec un message, connectant les sources aux destinations. Un chemin de log se compose d'une ou plusieurs sources et d'une ou plusieurs destinations : les messages arrivant d'une source sont envoyés à toutes les destinations listées dans le chemin de log. Un chemin de log défini dans syslog-ng OSE est appelé une instruction de log.

Optionnellement, les chemins de log peuvent inclure des filtres. Les filtres sont des règles qui sélectionnent seulement certains messages, par exemple, en sélectionnant seulement les messages envoyés par une application spécifique. Si un chemin de log inclut des filtres, syslog-ng OSE n'envoie que les messages satisfaisant les règles de filtre aux destinations définies dans le chemin de log.

D'autres éléments optionnels qui peuvent apparaître dans les instructions de log sont les analyseurs (parsers) et les règles de réécriture. Les analyseurs segmentent les messages en différents champs pour aider au traitement des messages, tandis que les règles de réécriture modifient les messages en ajoutant, remplaçant ou supprimant des parties des messages.

Configuration de syslog-ng OSE

•
Le corps principal du fichier de configuration se compose de définitions d'objets : les sources, destinations, et chemins de log définissent quels messages de log sont reçus et où ils sont envoyés. Tous les identifiants, noms d'options et attributs, et toute autre chaîne de caractères utilisée dans le fichier de configuration syslog-ng OSE sont sensibles à la casse. Les définitions d'objets (aussi appelées instructions) ont la syntaxe suivante :
type-de-l-objet identifiant-de-l-objet {<paramètres>};
  • Type de l'objet : L'un parmi source, destination, log, filter, parser, rewrite rule, ou template.
  • Identifiant de l'objet : Un nom unique identifiant l'objet. Lorsque vous utilisez un mot réservé comme identifiant, entourez l'identifiant de guillemets (\"\").

Tous les identifiants, attributs et autres chaînes utilisés dans le fichier de configuration syslog-ng OSE sont sensibles à la casse.

ASTUCE : Utilisez des identifiants qui font référence au type de l'objet qu'ils identifient. Par exemple, préfixez les objets source avec s_, les destinations avec d_, etc.

NOTE : Répéter la définition d'un objet (c'est-à-dire définir le même objet avec le même id plus d'une fois) n'est pas autorisé, sauf si vous utilisez la définition @define allow-config-dups 1 dans le fichier de configuration. - Paramètres : Les paramètres de l'objet, entourés d'accolades
{paramètres}. - Point-virgule : Les définitions d'objets se terminent par un point-virgule (;).

Par exemple, la ligne suivante définit une source et l'appelle s_internal.

source s_internal { internal(); };

L'objet peut être référencé plus tard dans d'autres instructions en utilisant son ID, par exemple, la source précédente est utilisée comme paramètre de l'instruction de log suivante :

log { source(s_internal); destination(d_file); };
•
Les paramètres et options au sein d'une instruction sont similaires aux appels de fonction du langage de programmation C : le nom de l'option suivi d'une liste de ses paramètres entourée d'accolades et terminée par un point-virgule.
option(paramètre1, paramètre2); option2(paramètre1, paramètre2);

Par exemple, le pilote file() dans l'instruction source suivante a trois options : le nom de fichier (/var/log/apache/access.log), follow-freq(), et flags(). L'option follow-freq() a aussi un paramètre, tandis que l'option flags() a deux paramètres.

source s_tail { file("/var/log/apache/access.log"
follow-freq(1) flags(no-parse, validate-utf8)); };

Les objets peuvent avoir des paramètres requis et optionnels. Les paramètres requis sont positionnels, ce qui signifie qu'ils doivent être spécifiés dans un ordre défini. Les paramètres optionnels peuvent être spécifiés dans n'importe quel ordre en utilisant le format option(valeur). Si un paramètre (optionnel ou requis) n'est pas spécifié, sa valeur par défaut est utilisée. Les paramètres et leurs valeurs par défaut sont listés dans la section de référence de l'objet particulier.

Exemple : Utilisation de paramètres requis et optionnels

Le pilote source unix-stream() a un seul argument requis : le nom du socket sur lequel écouter. Les paramètres optionnels suivent le nom du socket dans n'importe quel ordre, donc les définitions source suivantes ont le même effet :

source s_demo_stream1 {
    unix-stream("<chemin-vers-socket>" 
    max-connections(10) group(log)); 
};
source s_demo_stream2 {
    unix-stream("<chemin-vers-socket>" 
    group(log) max-connections(10)); 
};
•
Certaines options sont des options globales, ou peuvent être définies globalement, par exemple, si syslog-ng OSE doit utiliser la résolution DNS pour résoudre les adresses IP.
options { use-dns(no); };
  • Les objets peuvent être utilisés avant leur définition.
  • Les objets peuvent également être définis en ligne. Ceci est utile si vous utilisez l'objet une seule fois (par exemple, un filtre).
  • Pour ajouter des commentaires au fichier de configuration, commencez une ligne par # et écrivez vos commentaires. Ces lignes sont ignorées par syslog-ng OSE.
# Commentaire : ceci est une source de flux
source s_demo_stream {
unix-stream("<chemin-vers-socket>" max-connections(10) group(log)); };

La syntaxe des instructions de log est la suivante :

log {
    source(s1); source(s2); ...
    optional_element(filter1|parser1|rewrite1);
    optional_element(filter2|parser2|rewrite2);
    ...
    destination(d1); destination(d2); ...
    flags(flag1[, flag2...]);
};

L'instruction de log suivante envoie tous les messages arrivant sur localhost à un serveur distant.

source s_localhost { network(ip(127.0.0.1) port(1999)); };
destination d_tcp { network("10.1.2.3" port(1999) localport(999)); };
log { source(s_localhost); destination(d_tcp); };

L'application syslog-ng OSE dispose d'un certain nombre d'options globales régissant l'utilisation du DNS, le format de l'horodatage utilisé et d'autres points généraux. Chaque option peut avoir des paramètres, de manière similaire aux spécifications des pilotes. Pour définir les options globales, ajoutez une instruction d'options au fichier de configuration syslog-ng OSE en utilisant la syntaxe suivante :

options { option1(params); option2(params); ... };

Exemple : Utilisation d'options globales

Pour désactiver la résolution des noms de domaine, ajoutez la ligne suivante au fichier de configuration syslog-ng OSE :

options { use-dns(no); };
