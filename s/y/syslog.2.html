syslog(2) Manuel des appels système syslog(2)

NOM

syslog, klogctl - lire et/ou effacer le tampon circulaire des messages du noyau ; régler le niveau de journalisation de la console

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_syslog, int type, char *bufp, int size);
/* L'interface glibc */
#include <sys/klog.h>
int klogctl(int type, char *bufp, int size);

DESCRIPTION

Note : Vous cherchez probablement la fonction de bibliothèque C syslog(), qui communique avec syslogd(8) ; consultez syslog(3) pour plus de détails.

Cette page décrit l'appel système syslog() du noyau, qui est utilisé pour contrôler le tampon printk() du noyau ; la fonction d'encapsulation glibc pour l'appel système s'appelle klogctl().

Le tampon de journalisation du noyau

Le noyau dispose d'un tampon circulaire de taille LOG_BUF_LEN dans lequel les messages passés en arguments à la fonction noyau printk() sont stockés (quelle que soit leur niveau de journalisation). Dans les anciens noyaux, LOG_BUF_LEN avait la valeur 4096 ; à partir de Linux 1.3.54, c'était 8192 ; à partir de Linux 2.1.113, c'était 16384 ; depuis Linux 2.4.23/2.6, la valeur est une option de configuration du noyau (CONFIG_LOG_BUF_SHIFT, valeur par défaut dépendante de l'architecture). Depuis Linux 2.6.6, la taille peut être interrogée avec le type de commande 10 (voir ci-dessous).

Commandes

L'argument type détermine l'action effectuée par cette fonction. La liste ci-dessous spécifie les valeurs pour type. Les noms symboliques sont définis dans le code source du noyau, mais ne sont pas exportés à l'espace utilisateur ; vous devrez soit utiliser les numéros, soit définir vous-même les noms.

SYSLOG_ACTION_CLOSE (0)
Fermer le journal. Actuellement une NOP (No Operation).
SYSLOG_ACTION_OPEN (1)
Ouvrir le journal. Actuellement une NOP.
SYSLOG_ACTION_READ (2)
Lire depuis le journal. L'appel attend jusqu'à ce que le tampon de journalisation du noyau ne soit plus vide, puis lit au maximum len octets dans le tampon pointé par bufp. L'appel renvoie le nombre d'octets lus. Les octets lus depuis le journal disparaissent du tampon de journalisation : l'information ne peut être lue qu'une seule fois. C'est la fonction exécutée par le noyau lorsqu'un programme utilisateur lit /proc/kmsg.
SYSLOG_ACTION_READ_ALL (3)
Lire tous les messages restants dans le tampon circulaire, en les plaçant dans le tampon pointé par bufp. L'appel lit les derniers len octets du tampon de journalisation (de manière non destructive), mais ne lit pas plus que ce qui a été écrit dans le tampon depuis la dernière commande "effacer le tampon circulaire" (voir commande 5 ci-dessous)). L'appel renvoie le nombre d'octets lus.
SYSLOG_ACTION_READ_CLEAR (4)
Lire et effacer tous les messages restants dans le tampon circulaire. L'appel fait précisément la même chose que pour un type de 3, mais exécute également la commande "effacer le tampon circulaire".
SYSLOG_ACTION_CLEAR (5)
L'appel exécute uniquement la commande "effacer le tampon circulaire". Les arguments bufp et size sont ignorés.
Cette commande n'efface pas réellement le tampon circulaire. Plutôt, elle définit une variable de comptabilité du noyau qui détermine les résultats renvoyés par les commandes 3 (SYSLOG_ACTION_READ_ALL) et 4 (SYSLOG_ACTION_READ_CLEAR). Cette commande n'a aucun effet sur les commandes 2 (SYSLOG_ACTION_READ) et 9 (SYSLOG_ACTION_SIZE_UNREAD).
SYSLOG_ACTION_CONSOLE_OFF (6)
La commande sauvegarde la valeur actuelle de console_loglevel puis définit console_loglevel à minimum_console_loglevel, de sorte qu'aucun message ne soit imprimé sur la console. Avant Linux 2.6.32, la commande définissait simplement console_loglevel à minimum_console_loglevel. Voir la discussion sur /proc/sys/kernel/printk, ci-dessous.
Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_CONSOLE_ON (7)
Si une commande SYSLOG_ACTION_CONSOLE_OFF précédente a été effectuée, cette commande restaure console_loglevel à la valeur qui a été sauvegardée par cette commande. Avant Linux 2.6.32, cette commande définissait simplement console_loglevel à default_console_loglevel. Voir la discussion sur /proc/sys/kernel/printk, ci-dessous.
Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_CONSOLE_LEVEL (8)
L'appel définit console_loglevel à la valeur donnée dans size, qui doit être un entier compris entre 1 et 8 (inclus). Le noyau impose silencieusement une valeur minimale de minimum_console_loglevel pour size. Voir la section niveau de journalisation pour les détails. L'argument bufp est ignoré.
SYSLOG_ACTION_SIZE_UNREAD (9) (depuis Linux 2.4.10)
L'appel renvoie le nombre d'octets actuellement disponibles en lecture dans le tampon de journalisation du noyau via la commande 2 (SYSLOG_ACTION_READ). Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_SIZE_BUFFER (10) (depuis Linux 2.6.6)
Cette commande renvoie la taille totale du tampon de journalisation du noyau. Les arguments bufp et size sont ignorés.

Toutes les commandes sauf 3 et 10 nécessitent des privilèges. Dans les noyaux Linux avant Linux 2.6.37, les types de commande 3 et 10 sont autorisés pour les processus non privilégiés ; depuis Linux 2.6.37, ces commandes ne sont autorisées pour les processus non privilégiés que si /proc/sys/kernel/dmesg_restrict a la valeur 0. Avant Linux 2.6.37, "privilégié" signifie que l'appelant possède la capacité CAP_SYS_ADMIN. Depuis Linux 2.6.37, "privilégié" signifie que l'appelant possède soit la capacité CAP_SYS_ADMIN (maintenant obsolète pour cet usage), soit la (nouvelle) capacité CAP_SYSLOG.

/proc/sys/kernel/printk

/proc/sys/kernel/printk est un fichier accessible en écriture contenant quatre valeurs entières qui influencent le comportement de printk() du noyau lors de l'impression ou de la journalisation des messages d'erreur. Les quatre valeurs sont :

console_loglevel
Seuls les messages dont le niveau de journalisation est inférieur à cette valeur seront imprimés sur la console. La valeur par défaut pour ce champ est DEFAULT_CONSOLE_LOGLEVEL (7), mais elle est définie à 4 si la ligne de commande du noyau contient le mot "quiet", à 10 si la ligne de commande du noyau contient le mot "debug", et à 15 en cas de faute du noyau (les 10 et 15 sont juste stupides et équivalents à 8). La valeur de console_loglevel peut être définie (à une valeur comprise entre 1 et 8) par un appel syslog() avec un type de 8.
default_message_loglevel

syslog(2) — man.free.dev

NAME

syslog() — read/write the kernel message log

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/syslog.h>

int syslog(int type, char *buf, int len);

DESCRIPTION

The syslog() system call is used to read messages from the kernel message buffer or to change the kernel message logging parameters.

The type argument specifies the operation to perform. The available operations are defined in the <sys/syslog.h> header file:

LOG_MASK(priority)
This macro is used to manipulate the mask argument used by some of the syslog(3) library routine functions.
LOG_UPTO(priority)
This macro is used to manipulate the mask argument used by some of the syslog(3) library routine functions.
OLD_SYSLOG_NAMES
Some older systems defined symbolic names for the log levels. For backward compatibility, these are still supported if OLD_SYSLOG_NAMES is defined before including <sys/syslog.h>.
SYSLOG_ACTION_CLOSE
Close the log.
SYSLOG_ACTION_OPEN
Open the log.
SYSLOG_ACTION_READ
Read from the log.
SYSLOG_ACTION_READ_ALL
Read all messages from the log, including those not yet read.
SYSLOG_ACTION_READ_CLEAR
Read all messages from the log and clear the log.
SYSLOG_ACTION_CLEAR
Clear the log.
SYSLOG_ACTION_CONSOLE_COLOR
Set the console logging color.
SYSLOG_ACTION_CONSOLE_LEVEL
Set the console log level.
SYSLOG_ACTION_CONSOLE_LOG
Set the console log flag.
SYSLOG_ACTION_SIZE_BUFFER
Get the size of the kernel log buffer.
SYSLOG_ACTION_SIZE_UNREAD
Get the number of unread messages in the kernel log buffer.
SYSLOG_ACTION_SETDEFAULTCuáles
Set the default message log level.
SYSLOG_ACTION_SETLOWCuáles
Set the minimum console log level.

The following variables control the behavior of the kernel logging:

default_message_loglevel
The default log level for all kernel messages. This value is controlled by the kernel configuration option CONFIG_DEFAULT_MESSAGE_LOGLEVEL, which defaults to 4.
minimum_console_loglevel
The value in this field is the minimum value to which console_loglevel can be set.
default_console_loglevel
This is the default value for console_loglevel.

The log level

Every printk() message has its own log level. If the log level is not explicitly specified as part of the message, it defaults to default_message_loglevel. The conventional meaning of the log level is as follows:

Kernel constant Level value Meaning
KERN_EMERG 0 System is unusable
KERN_ALERT 1 Action must be taken immediately
KERN_CRIT 2 Critical conditions
KERN_ERR 3 Error conditions
KERN_WARNING 4 Warning conditions
KERN_NOTICE 5 Normal but significant condition
KERN_INFO 6 Informational
KERN_DEBUG 7 Debug-level messages

The kernel printk() routine will print a message on the console only if it has a log level less than the value of console_loglevel.

RETURN VALUE

For type equal to 2, 3, or 4, a successful call to syslog() returns the number of bytes read. For type 9, syslog() returns the number of bytes currently available to be read on the kernel log buffer. For type 10, syslog() returns the total size of the kernel log buffer. For other values of type, 0 is returned on success.

In case of error, -1 is returned, and errno is set to indicate the error.

ERRORS

EINVAL
Bad arguments (e.g., bad type; or for type 2, 3, or 4, buf is NULL, or size is less than zero; or for type 8, the level is outside the range 1 to 8).
ENOSYS
This syslog() system call is not available, because the kernel was compiled with the CONFIG_PRINTK kernel-configuration option disabled.
EPERM
An attempt was made to change console_loglevel or clear the kernel message ring buffer by a process without sufficient privilege (more precisely: without the CAP_SYS_ADMIN or CAP_SYSLOG capability).
ERESTARTSYS
System call was interrupted by a signal; nothing was read. (This can be seen only during a trace.)

STANDARDS

Linux.

HISTORY

From the very start, people noted that it is unfortunate that a system call and a library routine of the same name are entirely different animals.
