SYSTEMD-FACTORY-RESET(8) systemd-factory-reset SYSTEMD-FACTORY-RESET(8)

NOM

systemd-factory-reset, systemd-factory-reset-request.service, systemd-factory-reset-complete.service, systemd-factory-reset.socket, systemd-factory-reset@.service - Demande ou achèvement d'une opération de réinitialisation d'usine, ou requête du mode de réinitialisation d'usine actuel

SYNOPIS

/usr/lib/systemd/systemd-factory-reset

systemd-factory-reset-request.service

systemd-factory-reset-complete.service

systemd-factory-reset.socket

systemd-factory-reset@.service

DESCRIPTION

systemd-factory-reset est un outil qui permet de demander l'état actuel de réinitialisation d'usine, de demander des opérations de réinitialisation d'usine ou de les terminer.

Certaines fonctionnalités sont également disponibles via le service Varlink /run/systemd/io.systemd.FactoryReset (implémenté via les unités systemd-factory-reset.socket/systemd-factory-reset@.service).

Voir Factory Reset[1] pour un aperçu de la logique de réinitialisation d'usine.

COMMANDES

L'exécutable /usr/lib/systemd/systemd-factory-reset peut également être appelé depuis la ligne de commande, en prenant l'un des arguments de commande suivants :

status

Rapporte l'état actuel de réinitialisation d'usine. Rapporte l'un des états suivants : "unsupported" (si le système d'exploitation ne prend pas en charge la logique de réinitialisation d'usine), "unspecified" (si aucune réinitialisation d'usine n'a été demandée, mais qu'elle n'a pas non plus été désactivée explicitement), "off" (si la logique de réinitialisation d'usine a été explicitement désactivée via l'option de ligne de commande du noyau), "on" (si la réinitialisation d'usine est actuellement activée et exécutée), "complete" (si la logique de réinitialisation d'usine a été exécutée lors du démarrage actuel mais est terminée), "pending" (si une réinitialisation d'usine a été demandée pour le prochain démarrage).

Retourne avec un code de sortie de 0 si le mécanisme de réinitialisation d'usine n'est pas actuellement en vigueur, 10 si une réinitialisation d'usine est actuellement en cours d'exécution, ou 11 si elle est en attente pour le prochain démarrage.

Ajouté dans la version 258.

request

Demande l'exécution d'une opération de réinitialisation d'usine au prochain démarrage.

Notez qu'il s'agit d'une opération relativement bas niveau. L'interface principale pour demander une opération de réinitialisation d'usine est de démarrer l'unité factory-reset.target.

Cela définit la variable EFI FactoryResetRequest, voir ci-dessous.

Cette opération est exécutée lorsque l'unité systemd-factory-reset-request.service est démarrée (ce qui fait généralement partie des services connectés et ordonnancés avant factory-reset.target).

Ajouté dans la version 258.

cancel

Annule toute opération de réinitialisation d'usine précédemment demandée (mais pas encore exécutée).

Ajouté dans la version 258.

complete

Marque une opération de réinitialisation d'usine en cours comme terminée.

Cette opération est exécutée lorsque l'unité systemd-factory-reset-complete.service est démarrée (ce qui fait généralement partie des services connectés et ordonnancés après factory-reset-now.target).

Ajouté dans la version 258.

OPTIONS

Les options suivantes sont comprises :

--retrigger

Lorsqu'elle est utilisée avec la commande complete, retraite tous les périphériques de blocage, ce qui peut entraîner la disponibilité de périphériques découverts automatiquement qui ne l'étaient auparavant pas car la logique de réinitialisation d'usine était en place.

Ajouté dans la version 258.

--quiet, -q

Supprime la sortie de l'état de status, mais définit toujours le statut de sortie comme documenté.

Ajouté dans la version 258.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

VARIABLES EFI

La variable EFI suivante est définie et lue par systemd-factory-reset, sous l'UUID du fournisseur "8cf2644b-4b0b-428f-9387-6d876050dc67", pour la communication entre ce démarrage et le suivant.

FactoryResetRequest

Définie chaque fois qu'une réinitialisation d'usine est demandée pour le prochain démarrage, supprimée une fois la réinitialisation d'usine terminée. Contient des données JSON décrivant le système d'exploitation demandeur, afin d'éviter toute confusion sur les systèmes multi-démarrages.

Ajouté dans la version 258.
