NOM

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Créer, supprimer et nettoyer des fichiers et répertoires

SYNTAXE

systemd-tmpfiles [OPTIONS...] [FICHIERCONFIG...]

Unités système :

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unités utilisateur :

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPTION

systemd-tmpfiles crée, supprime et nettoie des fichiers et répertoires, en utilisant le format de fichier de configuration et l'emplacement spécifiés dans tmpfiles.d(5). Historiquement, il était conçu pour gérer les fichiers volatils et temporaires, comme son nom l'indique, mais il fournit une fonctionnalité générique de gestion de fichiers et peut être utilisé pour gérer n'importe quel type de fichier. Il doit être appelé avec une ou plusieurs commandes --create, --remove et --clean pour sélectionner le sous-ensemble d'opérations respectif.

S'il est appelé sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par tmpfiles.d(5) sont exécutées. Lorsqu'il est appelé avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments fournis sur la ligne de commande remplacent le fichier de configuration CHEMIN. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée à la place d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans slash), tous les répertoires de configuration sont recherchés pour un fichier correspondant et le fichier trouvé qui a la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration d'autres fichiers correspondants.

Les services système (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invoquent systemd-tmpfiles pour créer des fichiers système et effectuer un nettoyage à l'échelle du système. Ces services lisent les fichiers de configuration contrôlés par l'administrateur dans les répertoires tmpfiles.d/. Les services utilisateur (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) invoquent également systemd-tmpfiles, mais celui-ci lit un ensemble distinct de fichiers, qui inclut les fichiers contrôlés par l'utilisateur sous ~/.config/user-tmpfiles.d/ et ~/.local/share/user-tmpfiles.d/, et les fichiers contrôlés par l'administrateur sous /usr/share/user-tmpfiles.d/. Les utilisateurs peuvent l'utiliser pour créer et nettoyer des fichiers sous leur contrôle, mais l'instance système effectue un nettoyage global et n'est pas influencée par la configuration utilisateur. Notez qu'un nettoyage basé sur le temps configuré dans l'instance système, comme celui généralement configuré pour /tmp/, affectera également les fichiers créés par l'instance utilisateur s'ils sont placés dans /tmp/, même si le nettoyage basé sur le temps de l'instance utilisateur est désactivé.

Pour réappliquer les paramètres après la modification de la configuration, redémarrez simplement systemd-tmpfiles-clean.service, ce qui appliquera tous les paramètres qui peuvent être exécutés en toute sécurité à l'exécution. Pour déboguer systemd-tmpfiles, il peut être utile de l'invoquer directement depuis la ligne de commande avec un niveau de journalisation augmenté (voir $SYSTEMD_LOG_LEVEL ci-dessous).

COMMANDES ET OPTIONS

Les commandes suivantes sont comprises :

--create

Si cette commande est passée, tous les fichiers et répertoires marqués avec f, F, w, d, D, v, p, L, c, b, m dans les fichiers de configuration sont créés ou écrits. Les fichiers et répertoires marqués avec z, Z, t, T, a et A ont leur propriété, leur mode d'accès et leurs étiquettes de sécurité définis.

--clean

Si cette commande est passée, tous les fichiers et répertoires avec un paramètre d'âge configuré seront nettoyés.

--remove

Si cette commande est passée, le contenu des répertoires marqués avec D ou R, et les fichiers ou répertoires eux-mêmes marqués avec r ou R sont supprimés à moins qu'un verrou exclusif ou partagé BSD ne soit pris sur eux (voir flock(2)).

--purge

Si cette option est passée, tous les fichiers et répertoires déclarés pour création et marqués avec le caractère "$" par les fichiers tmpfiles.d/ spécifiés sur la ligne de commande seront supprimés. Spécifiquement, cela agit sur tous les fichiers et répertoires marqués avec f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si ce commutateur est utilisé, au moins un fichier tmpfiles.d/ (ou - pour l'entrée standard) doit être spécifié sur la ligne de commande, sinon l'invocation sera refusée, pour des raisons de sécurité (car autrement, de nombreux fichiers système installés pourraient être supprimés).

L'utilisation principale de cette option est de supprimer automatiquement les fichiers et répertoires qui ont été initialement créés pour le compte d'un paquet installé lors de la suppression du paquet.

Il est recommandé d'exécuter d'abord cette commande en combinaison avec --dry-run (voir ci-dessous) pour vérifier quels fichiers et répertoires seront supprimés.

Attention ! Ce n'est généralement pas la commande que vous recherchez ! Dans la plupart des cas, --remove est ce que vous cherchez.

Ajouté dans la version 256.

--user

Exécute la configuration "utilisateur", c'est-à-dire les fichiers tmpfiles.d/ dans les répertoires de configuration utilisateur.

Ajouté dans la version 236.

--boot

Exécute également les lignes avec un point d'exclamation. Les lignes qui ne sont pas sûres à exécuter sur un système en cours d'exécution peuvent être marquées de cette façon. systemd-tmpfiles est exécuté au démarrage précoce avec --boot spécifié et exécutera ces lignes. Lorsqu'il est invoqué à nouveau plus tard, il doit être appelé sans --boot.

Ajouté dans la version 209.

--graceful

Ignore les lignes de configuration relatives à des utilisateurs ou groupes inconnus. Cette option est destinée à être utilisée au début du démarrage avant que tous les utilisateurs ou groupes n'aient été créés.

Ajouté dans la version 254.

--dry-run

Traite la configuration et affiche les opérations qui seraient effectuées, mais ne modifie rien dans le système de fichiers.

Ajouté dans la version 256.

--prefix=chemin

Applique uniquement les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 212.

--exclude-prefix=chemin

Ignore les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 207.

-E

Un raccourci pour "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", c'est-à-dire exclut les hiérarchies généralement sauvegardées par des systèmes de fichiers virtuels ou en mémoire. Ceci est utile en combinaison avec --root=, si l'arborescence spécifiée contient une arborescence d'OS sans ces systèmes de fichiers virtuels/en mémoire montés, car il n'est généralement pas souhaitable de créer des fichiers et des répertoires sous ces sous-répertoires s'ils sont censés être surmontés pendant l'exécution.

Ajouté dans la version 247.

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés avec le chemin root alternatif donné, y compris les chemins de recherche de configuration.

Lorsque cette option est utilisée, le Name Service Switch (NSS) de libc est contourné pour la résolution des utilisateurs et des groupes. Au lieu de cela, les fichiers /etc/passwd et /etc/group de l'autre racine sont lus directement. Cela signifie que les utilisateurs/groupes non listés dans ces fichiers ne seront pas résolus, c'est-à-dire que LDAP, NIS et d'autres bases de données complexes ne sont pas pris en compte.

Envisagez de combiner ceci avec -E pour vous assurer que l'invocation ne crée pas de fichiers ou de répertoires sous les points de montage de l'image système opérée qui sont généralement surmontés pendant l'exécution.

Ajouté dans la version 212.

--image=

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

image

Prend un chemin vers un fichier d'image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur les systèmes de fichiers stockés dans des images disque ou des périphériques bloc. L'image disque doit soit contenir uniquement un système de fichiers, soit un ensemble de systèmes de fichiers dans une table de partitions GPT, suivant la Discoverable Partitions Specification[1]. Pour plus d'informations sur les images disque prises en charge, voir le commutateur du même nom dans systemd-nspawn(1).

Implique -E.

Ajouté dans la version 247.

--image-policy=politique

Prend une chaîne de politique d'image en argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si non spécifié, utilise par défaut la politique « * », c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=CHEMIN

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans tmpfiles.d(5) seront lus, et la configuration donnée sur la ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration CHEMIN.

Cette option est destinée à être utilisée lors de l'exécution de scripts d'installation de paquets lorsque les fichiers appartenant à ce paquet ne sont pas encore disponibles sur disque, de sorte que leur contenu doive être donné sur la ligne de commande, mais que la configuration de l'administrateur puisse déjà exister et doive avoir une priorité plus élevée.

Ajouté dans la version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties « intéressantes » des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne pas rediriger la sortie vers un pager.

-h, --help

Imprime un court texte d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

Il est possible de combiner --create, --clean et --remove en une seule invocation (auquel cas la suppression et le nettoyage sont exécutés avant la création de nouveaux fichiers). Par exemple, lors du démarrage, la ligne de commande suivante est exécutée pour s'assurer que tous les répertoires temporaires et volatils sont supprimés et créés conformément au fichier de configuration :

systemd-tmpfiles --remove --create

IDENTIFIANTS

systemd-tmpfiles prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

tmpfiles.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier de configuration drop-in tmpfiles.d/. Si cet identifiant est passé, il est traité après tous les fichiers drop-in lus à partir du système de fichiers. Les lignes de l'identifiant peuvent donc augmenter les lignes existantes du système d'exploitation, mais pas les remplacer.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-tmpfiles-setup.service (et les fichiers d'unité associés) est configuré pour hériter de l'identifiant « tmpfiles.extra » du gestionnaire de service.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages avec un niveau de journalisation plus élevé, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être précédée de console, syslog, kmsg ou journal suivi de deux points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lors de la journalisation vers la console qui doit être au niveau info). Notez que le niveau de journalisation maximal global a la priorité sur tous les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Un booléen. Si vrai, les messages écrits sur le tty seront colorés en fonction de la priorité.

Ce réglage n'est utile que lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux colorient les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. Si vrai, les messages de journalisation de la console seront préfixés par un horodatage.

Ce réglage n'est utile que lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux attachent des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. Si vrai, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent joint comme métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des valeurs suivantes : console (journaliser vers le tty attaché), console-prefixed (journaliser vers le tty attaché mais avec des préfixes codant le niveau de journalisation et la « facilité », voir syslog(3), kmsg (journaliser vers le tampon circulaire du noyau), journal (journaliser vers le journal), journal-or-kmsg (journaliser vers le journal si disponible, et vers kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie de journal).

$SYSTEMD_PAGER, $PAGER

Pager à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de pager connues est essayé successivement, y compris less(1) et more(1), jusqu'à ce qu'un soit trouvé. Si aucune implémentation de pager n'est découverte, aucun pager n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur « cat » équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le pager (avec « cat » ou « »), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut « FRSXMK »).

Les utilisateurs pourraient vouloir modifier deux options en particulier :

K

Cette option indique au pager de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même afin de revenir à l'invite de commande du pager, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas « K », et que le pager invoqué est less, Ctrl+C sera ignoré par l'exécutable et devra être géré par le pager.

X

Cette option indique au pager de ne pas envoyer les chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du pager. Néanmoins, cela empêche certaines fonctionnalités du pager de fonctionner, en particulier la sortie paginée ne peut pas être parcourue avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet pour les invocations de less par les outils systemd.

Voir less(1) pour plus de détails.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut « utf-8 », si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet pour les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pager courantes comme less(1), en plus du « pagination », c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture dans d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque des commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pager devient une frontière de sécurité. Il faut veiller à ce que seules des programmes avec des fonctionnalités strictement limitées soient utilisés comme pagers, et que les fonctionnalités interactives non souhaitées comme l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le « mode sécurisé » pour le pager peut être activé comme décrit ci-dessous, si le pager le supporte (la plupart des pagers ne sont pas écrits d'une manière qui en tient compte). Il est recommandé d'activer explicitement le « mode sécurisé » ou de désactiver complètement le pager en utilisant --no-pager ou PAGER=cat lors de l'autorisation d'utilisateurs non fiables à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur vrai, le « mode sécurisé » du pager est activé. En « mode sécurisé », LESSSECURE=1 sera défini lors de l'invocation du pager, ce qui indique au pager de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou démarrent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le « mode sécurisé ».

Lorsqu'elle est définie sur faux, aucune limitation n'est placée sur le pager. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le « mode sécurisé » doit être activé et si le pager le supporte. Le « mode sécurisé » est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous

NOM

systemd-tmpfiles ‐ crée, supprime et nettoie les fichiers temporaires

SYNTAXE

systemd-tmpfiles [--purge] [--cleanup] [--remove] [--prefix PATH] [--directory DIR...] [--exclude PATH...] [--user USER...] [--group GROUP...] [--remove-tmpfiles-unsafe] [--mkonly] [--now] [--quiet]

DESCRIPTION

Le démon systemd-tmpfiles est utilisé pour gérer les fichiers et répertoires dans des emplacements comme /tmp, /var/tmp, et /run. Il s'assure que les fichiers et répertoires spécifiés dans les fichiers de configuration ont les permissions correctes, sont créés ou supprimés selon les besoins, et que le contenu est approprié pour les systèmes qui démarrent à partir d'une image initramfs ou d'un système de fichiers racine temporaire.

systemd-tmpfiles peut être exécuté périodiquement via systemd-tmpfiles-clean.timer, ou directement pour des opérations spécifiques.

Il lit les fichiers de configuration dans le répertoire /usr/lib/tmpfiles.d/, /run/tmpfiles.d/ et /etc/tmpfiles.d/. Ces fichiers contiennent des directives pour la création, la suppression et la gestion des fichiers et répertoires.

COMMANDES ET OPTIONS

Les options suivantes contrôlent le comportement de systemd-tmpfiles :

--purge
Supprime les fichiers et répertoires qui ne sont plus définis dans les fichiers de configuration. Cela inclut également les fichiers créés par des directives w, W, et e.
--cleanup
Supprime les fichiers et répertoires qui sont plus anciens qu'un certain âge, tel que spécifié par la colonne de temps dans les fichiers de configuration. Les fichiers et répertoires créés par des directives f, F, d, D, a, A, c, C, z, Z, l, et L sont éligibles.
--remove
Supprime les fichiers et répertoires spécifiés dans les fichiers de configuration qui sont plus anciens qu'un certain âge. Ceci est similaire à --cleanup, mais ne concerne que les fichiers et répertoires créés par des directives f, F, d, D, a, A, c, C, z, Z, l, et L.
--prefix
Se concentre sur les fichiers et répertoires situés sous le chemin spécifié par PATH. Tous les autres chemins sont ignorés.
--directory
Traite uniquement les directives d et D pour les répertoires spécifiés par DIR...
--exclude
Exclut les fichiers et répertoires qui correspondent au motif spécifié par PATH...
--user
Ne traiter que les fichiers et répertoires qui appartiennent à l'utilisateur spécifié par USER...
--group
Ne traiter que les fichiers et répertoires qui appartiennent au groupe spécifié par GROUP...
--remove-tmpfiles-unsafe
Permet la suppression de fichiers et répertoires considérés comme potentiellement dangereux pour la suppression automatique, même s'ils ne sont pas explicitement marqués comme temporaires.
--mkonly
Crée uniquement les fichiers et répertoires spécifiés, sans effectuer d'autres opérations comme la suppression ou la modification des permissions.
--now
Applique immédiatement les modifications sans attendre le délai spécifié dans la configuration.
--quiet
Réduit la verbosité de la sortie. Les messages d'erreur sont toujours affichés.

IDENTIFIANTS

Les directives de tmpfiles.d peuvent spécifier un propriétaire et un groupe pour les fichiers et répertoires créés. Si non spécifiés, les valeurs par défaut sont utilisées.

Les identifiants peuvent être spécifiés par nom d'utilisateur/groupe ou par ID numérique.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent affecter le comportement de systemd-tmpfiles :

$SYSTEMD_PAGER, $SYSTEMD_PAGERSECURE, $PAGER

Contrôle le choix du pagineur pour l'affichage des messages. Si $SYSTEMD_PAGER est défini, il est utilisé. Sinon, $PAGER est utilisé. Si $SYSTEMD_PAGERSECURE est défini à 1, les pages qui ne sont pas connues pour implémenter un mode sécurisé ne seront pas utilisées. Ceci est particulièrement pertinent lorsque systemd-tmpfiles est exécuté via des outils comme sudo(8) (où $SUDO_UID est défini [2]). Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à la commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pagineur.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être respectées, autre que pour désactiver le pagineur, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Argument booléen. S'il est vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : « 16 », « 256 » pour restreindre l'utilisation des couleurs aux 16 ou 256 couleurs ANSI de base, respectivement. Ceci peut être spécifié pour outrepasser la décision automatique basée sur $TERM et sur ce à quoi la console est connectée.

$SYSTEMD_URLIFY

La valeur doit être booléenne. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminaux qui le prennent en charge. Ceci peut être spécifié pour outrepasser la décision que systemd prend en fonction de $TERM et d'autres conditions.

OPÉRATION DE NETTOYAGE NON PRIVILÉGIÉE

systemd-tmpfiles essaie d'éviter de modifier les heures d'accès et de modification des répertoires qu'il parcourt, ce qui nécessite des privilèges CAP_FOWNER. Lorsqu'il s'exécute en tant que non-root, les répertoires qui sont vérifiés pour les fichiers à nettoyer verront leur heure d'accès incrémentée, ce qui pourrait empêcher leur nettoyage.

STATUT DE SORTIE

En cas de succès, 0 est retourné. Si la configuration était syntaxiquement invalide (erreurs de syntaxe, arguments manquants, ...), de sorte que certaines lignes ont dû être ignorées, mais aucune autre erreur ne s'est produite, 65 est retourné (EX_DATAERR de /usr/include/sysexits.h). Si la configuration était syntaxiquement valide, mais n'a pas pu être exécutée (manque de permissions, création de fichiers dans des répertoires manquants, contenu invalide lors de l'écriture dans /sys/ valeurs, ...), 73 est retourné (EX_CANTCREAT de /usr/include/sysexits.h). Sinon, 1 est retourné (EXIT_FAILURE de /usr/include/stdlib.h).

Note : lors de la création d'éléments, si la cible existe déjà, mais est du mauvais type ou ne correspond autrement pas à l'état demandé, et que l'opération forcée n'a pas été demandée avec « + », un message est émis, mais l'échec est sinon ignoré.
