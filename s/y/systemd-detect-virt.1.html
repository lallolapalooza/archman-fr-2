NOM

systemd-detect-virt - Détecter l'exécution dans un environnement virtualisé

SYNTAXE

systemd-detect-virt [OPTIONS...]

DESCRIPTION

systemd-detect-virt détecte l'exécution dans un environnement virtualisé. Il identifie la technologie de virtualisation et peut distinguer la virtualisation complète de machine de la virtualisation par conteneur. systemd-detect-virt se termine avec un code de retour de 0 (succès) si une technologie de virtualisation est détectée, et une valeur non nulle (erreur) sinon. Par défaut, tout type de virtualisation est détecté, et les options --container et --vm peuvent être utilisées pour limiter les types de virtualisation détectés.

Lorsqu'il est exécuté sans --quiet, il affiche un identifiant court pour la technologie de virtualisation détectée. Les technologies suivantes sont actuellement identifiées :

Tableau 1. Technologies de virtualisation connues (à la fois VM, c'est-à-dire virtualisation matérielle complète, et conteneur, c'est-à-dire virtualisation avec noyau partagé)

Type ID Produit
VM qemu Virtualisation logicielle QEMU, sans KVM
kvm Machine virtuelle noyau KVM Linux, en combinaison avec QEMU. Non utilisé pour d'autres virtualiseurs utilisant les interfaces KVM, tels qu'Oracle VirtualBox ou Amazon EC2 Nitro, voir ci-dessous.
amazon Amazon EC2 Nitro utilisant KVM Linux
zvm z/VM s390
vmware VMware Workstation ou Server, et produits associés
microsoft Hyper-V, également connu sous le nom de Viridian ou Virtualisation de serveur Windows
oracle Oracle VM VirtualBox (historiquement commercialisé par innotek et Sun Microsystems), pour hyperviseur hérité et KVM
powervm Hyperviseur IBM PowerVM — livré sous forme de micrologiciel avec certains serveurs IBM POWER
xen Hyperviseur Xen (uniquement domU, pas dom0)
bochs Émulateur Bochs
uml User-mode Linux
parallels Parallels Desktop, Parallels Server
bhyve bhyve, hyperviseur FreeBSD
qnx Hyperviseur QNX
acrn Hyperviseur ACRN[1]
apple Framework de virtualisation Apple[2]
sre Hyperviseur LMHS SRE[3]
google Google Compute Engine[4]
Conteneur openvz OpenVZ/Virtuozzo
lxc Implémentation de conteneur Linux par LXC
lxc-libvirt Implémentation de conteneur Linux par libvirt
systemd-nspawn Implémentation minimale de conteneur de systemd, voir systemd-nspawn(1)
docker Gestionnaire de conteneurs Docker
podman Gestionnaire de conteneurs **Podman**[5]
rkt Runtime de conteneurs d'applications rkt
wsl **Windows Subsystem for Linux**[6]
proot Émulation d'environnement chroot/bind mount en espace utilisateur **proot**[7]
pouch Moteur de conteneurs **Pouch**[8]

Si plusieurs solutions de virtualisation sont utilisées, seule la solution la plus "interne" est détectée et identifiée. Cela signifie que si la virtualisation machine et la virtualisation par conteneur sont utilisées en conjonction, seule cette dernière sera identifiée (sauf si
--vm est passé).

Windows Subsystem for Linux n'est pas un conteneur Linux, mais un environnement pour exécuter des applications utilisateurs Linux par-dessus le noyau Windows à l'aide d'une interface compatible Linux. WSL est classé comme un conteneur à des fins pratiques. Plusieurs environnements WSL partagent le même noyau et les services devraient généralement se comporter comme lorsqu'ils sont exécutés dans un conteneur.

Lorsqu'il est exécuté avec --cvm, au lieu d'afficher la technologie de virtualisation, il affiche la technologie de machine virtuelle confidentialisée, le cas échéant. Les technologies suivantes sont actuellement identifiées :

Tableau 2. Technologies de virtualisation confidentialisée connues

Architecture ID Technologie
x86_64 sev AMD Secure Encrypted Virtualization
sev-es AMD Secure Encrypted Virtualization - Encrypted State
sev-snp AMD Secure Encrypted Virtualization - Secure Nested Paging
tdx Intel Trust Domain Extensions
s390x protvirt IBM Protected Virtualization (Secure Execution)
arm64 cca Arm Confidential Compute Architecture

OPTIONS

Les options suivantes sont comprises :

-c, --container

Ne détecte que la virtualisation par conteneur (c'est-à-dire la virtualisation avec noyau partagé).

-v, --vm

Ne détecte que la virtualisation matérielle.

-r, --chroot

Détecte si l'appel a été effectué dans un environnement chroot(2). Dans ce mode, aucune sortie n'est écrite, mais la valeur de retour indique si le processus a été appelé dans un environnement chroot() ou non.

Ajouté dans la version 228.

--private-users

Détecte si l'appel a été effectué dans un espace utilisateur (user namespace). Dans ce mode, aucune sortie n'est écrite, mais la valeur de retour indique si le processus a été appelé à l'intérieur d'un espace utilisateur ou non. Voir user_namespaces(7) pour plus d'informations.

Ajouté dans la version 232.

--cvm

Détecte si l'appel a été effectué dans une machine virtuelle confidentialisée. Le résultat de cette détection peut être utilisé pour désactiver des fonctionnalités qui ne devraient pas être utilisées dans les VMs confidentialisées. Il ne doit pas être utilisé pour divulguer des informations sensibles pour la sécurité. Ces dernières ne doivent être divulguées qu'après attestation de l'environnement confidentiel.

Ajouté dans la version 254.

-q, --quiet

Supprime l'affichage de l'identifiant de la technologie de virtualisation.

--list

Affiche tous les environnements de conteneurs et de VM actuellement connus et détectables.

Ajouté dans la version 239.

--list-cvm

Affiche toutes les technologies de virtualisation confidentialisée actuellement connues et détectables.

Ajouté dans la version 254.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

STATUT DE SORTIE

Si une technologie de virtualisation est détectée, 0 est retourné, un code non nul sinon.
