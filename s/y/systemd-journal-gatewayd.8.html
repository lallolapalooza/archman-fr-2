SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8) systemd-journal-gatewayd.service SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8)

NOM

systemd-journal-gatewayd.service, systemd-journal-gatewayd.socket, systemd-journal-gatewayd - Serveur HTTP pour les événements du journal

SYNTAXE

systemd-journal-gatewayd.service

systemd-journal-gatewayd.socket

/usr/lib/systemd/systemd-journal-gatewayd [OPTIONS...]

DESCRIPTION

systemd-journal-gatewayd sert les événements du journal sur le réseau. Les clients doivent se connecter en utilisant HTTP. Le serveur écoute sur le port 19531 par défaut. Si --cert= est spécifié, le serveur attend des connexions HTTPS.

Le programme est démarré par systemd(1) et s'attend à recevoir un unique socket. Utilisez systemctl start systemd-journal-gatewayd.socket pour démarrer le service, et systemctl enable systemd-journal-gatewayd.socket pour qu'il démarre au démarrage.

OPTIONS

Les options suivantes sont comprises :

--cert=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire le certificat serveur. Le certificat doit être au format PEM. Cette option fait passer systemd-journal-gatewayd en mode HTTPS et doit être utilisée conjointement avec --key=.

Ajouté dans la version 198.

--key=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire la clé secrète serveur correspondante au certificat spécifié avec --cert=. La clé doit être au format PEM.

Ajouté dans la version 198.

--trust=

Spécifie le chemin vers un fichier ou un socket de flux AF_UNIX pour lire un certificat d'autorité de certification (CA). Le certificat doit être au format PEM.

Ajouté dans la version 236.

--system, --user

Limite les entrées servies aux entrées provenant des services système et du noyau, ou aux entrées provenant des services de l'utilisateur actuel. Ceci a la même signification que les options --system et --user pour journalctl(1). Si aucune n'est spécifiée, toutes les entrées accessibles sont servies.

Ajouté dans la version 249.

-m, --merge

Sert les entrées entrelacées de tous les journaux disponibles, y compris ceux des autres machines. Ceci a la même signification que l'option --merge pour journalctl(1).

Ajouté dans la version 249.

-D DIR, --directory=DIR

Prend un chemin de répertoire comme argument. Si spécifié, systemd-journal-gatewayd servira le répertoire de journal spécifié DIR au lieu des chemins par défaut du runtime et du journal système.

Ajouté dans la version 232.

--file=GLOB

Prend un glob de fichier comme argument. Sert les entrées des fichiers journaux spécifiés correspondant à GLOB au lieu des chemins par défaut du runtime et du journal système. Peut être spécifié plusieurs fois, auquel cas les fichiers seront convenablement entrelacés. Ceci a la même signification que l'option --file= pour journalctl(1).

Ajouté dans la version 249.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

URLS SUPPORTÉES

Les URL suivantes sont reconnues :

/boots

Retourne une réponse au format json-seq (RFC 7464) contenant des objets JSON, chacun contenant le numéro de démarrage, son ID et les horodatages du premier et du dernier message. Les démarrages sont retournés en commençant par le démarrage le plus récent et utilisent le même schéma que journalctl --list-boots --output json.

Ajouté dans la version 258.

/browse

Navigation interactive.

Ajouté dans la version 197.

/entries[?option1&option2=valeur...]

Récupération d'événements dans divers formats.

La partie Accept: de l'en-tête HTTP détermine le format. Les valeurs supportées sont décrites ci-dessous.

La partie Range: de l'en-tête HTTP détermine la plage d'événements retournés. Les valeurs supportées sont décrites ci-dessous.

Les paramètres GET peuvent être utilisés pour modifier les événements retournés. Les paramètres supportés sont décrits ci-dessous.

Ajouté dans la version 197.

/machine

Retourne une structure JSON décrivant la machine.

Exemple :

{ "machine_id" : "8cf7ed9d451ea194b77a9f118f3dc446",
  "boot_id" : "3d3c9efaf556496a9b04259ee35df7f7",
  "hostname" : "fedora",
  "os_pretty_name" : "Fedora 19 (Rawhide)",
  "virtualization" : "kvm",
  ...}

Ajouté dans la version 197.

/fields/NOM_CHAMP

Retourne une liste des valeurs de ce champ présentes dans les logs.

Ajouté dans la version 197.

EN TETE ACCEPT

Accept: format

Formats reconnus :

text/plain

Par défaut. Sortie texte de type syslog, une ligne par entrée de journal (comme journalctl --output short).

Ajouté dans la version 197.

application/json

Les entrées sont formatées comme des structures de données JSON, une par ligne (comme journalctl --output json). Voir Format JSON du journal[1] pour plus d'informations.

Ajouté dans la version 197.

text/event-stream

Les entrées sont formatées comme des structures de données JSON, encapsulées dans un format adapté aux Server-Sent Events[2] (comme journalctl --output json-sse).

Ajouté dans la version 229.

application/vnd.fdo.journal

Les entrées sont sérialisées dans un flux binaire (mais principalement textuel) adapté aux sauvegardes et aux transferts réseau (comme journalctl --output export). Voir Format d'exportation du journal[3] pour plus d'informations.

Ajouté dans la version 197.

EN TETE RANGE

Range: entries=[curseur][[:nb_saut]:[nb_entrées]]

Range: realtime=[depuis]:[jusqu’à][[:nb_saut]:nb_entrées]

où curseur est une chaîne de curseur, par défaut la première entrée, depuis et jusqu’à sont des horodatages (secondes depuis le 1970-01-01 00:00:00 UTC), nb_saut est un entier, nb_entrées est un entier non signé.

La plage est par défaut tous les événements disponibles.

Si nb_saut est négatif et qu'aucun curseur n'est donné, la dernière entrée sera le point de référence.

PARAMETRES GET URL

Les paramètres suivants peuvent être utilisés dans l'URL :

follow

attend de nouveaux événements (comme journalctl --follow, le nombre d'événements retournés n'est pas limité, sauf si nb_entrées est spécifié dans l'en-tête Range).

Ajouté dans la version 197.

discrete

Teste si le curseur spécifié fait référence à une entrée dans le journal. Retourne uniquement cette entrée.

Ajouté dans la version 197.

boot

Limite les événements au démarrage actuel du système (comme journalctl -b).

Ajouté dans la version 197.

CLE=correspondance

Fait correspondre les champs du journal. Voir systemd.journal-fields(7).

Ajouté dans la version 197.

EXEMPLES

Récupérer les événements de ce démarrage du journal local au format Exportation du journal[3] :

curl --silent -H'Accept: application/vnd.fdo.journal' \
       'http://localhost:19531/entries?boot'

Écouter les vidages mémoire (core dumps) :

curl 'http://localhost:19531/entries?follow&MESSAGE_ID=fc2e22bc6ee647b6b90

systemd.journal-gatewayd.8.en

NAME

systemd-journal-gatewayd.service, systemd-journal-gatewayd - Gateway to the system journal

SYNOPSIS

systemd-journal-gatewayd.service

DESCRIPTION

The systemd-journal-gatewayd service provides a network gateway to the system journal. It listens for journal export requests via HTTP/S and forwards them to the local systemd-journald instance. This allows remote clients to query the system journal over the network.

It supports the journal export formats JSON and a custom format based on Server-Sent Events (SSE).

OPTIONS

The following options are available:

--listen-http=, --listen-https=
Configures listening addresses for the HTTP or HTTPS server. Takes a space-separated list of addresses in the format host:port or port. If only a port is given, it is bound to all IPv4 and IPv6 interfaces. Defaults to *:80 and *:443. For HTTPS, TLS certificates and keys must be configured in journald.conf(5).
--gateway=
Sets the gateway URL path. Defaults to /journal/.
--token-file=
Path to a file containing an API token for authentication. If this is set, only requests with a matching token are accepted. Defaults to no token authentication.
--max-body-size=
Maximum size of the request body in bytes. Defaults to 1M.
--max-connections=
Maximum number of concurrent connections. Defaults to 100.
--max-journal-entry-size=
Maximum size of a single journal entry in bytes. Defaults to 128K.
--max-log-file-size=
Maximum size of the log file in bytes. Defaults to 1G.

SUPPORTED URLS

The following URL paths are supported relative to the gateway path:

/journal/[format]
Retrieves journal entries in the specified format. Supported formats are json and sse. If no format is specified, it defaults to sse.
/journal/[format]/[field]=[value]
Filters journal entries by the specified field and value.
/journal/[format]/[field]=[value]&[field]=[value]
Filters journal entries by multiple fields and values.

See journalctl(1) for a list of supported fields.

ACCEPT HEADER

The server also honors the Accept HTTP header to determine the desired output format. Supported media types are application/json and text/event-stream.

RANGE HEADER

The server supports the Range HTTP header for pagination of journal entries.

URL GET PARAMETERS

The following URL GET parameters can be used to control the output:

since=, until=
Filter entries by time.
boot=
Filter entries by boot ID.
limit=
Limit the number of entries returned.
output=
Specify the output format (json or sse).

EXAMPLES

To retrieve all journal entries in JSON format:

$ curl http://localhost:80/journal/json

To retrieve journal entries from the current boot in SSE format:

$ curl http://localhost:80/journal/sse

To retrieve journal entries from a specific boot ID:

$ curl http://localhost:80/journal/json/boot=BOOT_ID

To retrieve journal entries with priority error or higher:

$ curl http://localhost:80/journal/sse/priority=4

To retrieve the last 100 entries:

$ curl -H "Range: items=-100" http://localhost:80/journal/sse

A client using the SSE format can be implemented using the Server-Sent Events API in web browsers.
