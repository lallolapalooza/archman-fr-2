NOM

systemd.dnssd - configuration DNS-SD

SYNOPSIS

service_réseau.dnssd

DESCRIPTION

La configuration DNS-SD est effectuée par systemd-resolved(8).

Le fichier de service réseau principal doit avoir l'extension .dnssd ; les autres extensions sont ignorées.

Les fichiers .dnssd sont lus à partir des fichiers situés dans les répertoires réseau système /usr/lib/systemd/dnssd et /usr/local/lib/systemd/dnssd, le répertoire réseau de runtime volatil /run/systemd/dnssd et le répertoire réseau d'administration locale /etc/systemd/dnssd. Tous les fichiers de configuration sont triés collectivement et traités dans l'ordre lexical, indépendamment des répertoires dans lesquels ils se trouvent. Cependant, les fichiers portant des noms identiques se remplacent mutuellement. Les fichiers dans /etc/ ont la priorité la plus élevée, les fichiers dans /run/ priment sur les fichiers portant le même nom dans /usr/lib/. Ceci peut être utilisé pour remplacer un fichier de configuration fourni par le système par un fichier local si nécessaire.

En plus du fichier de service réseau foo.dnssd, un répertoire de "drop-in" foo.dnssd.d/ peut exister. Tous les fichiers avec le suffixe ".conf" de ce répertoire seront analysés après l'analyse du fichier lui-même. Ceci est utile pour modifier ou ajouter des paramètres de configuration, sans avoir à modifier le fichier de configuration principal. Chaque fichier de drop-in doit avoir des en-têtes de section appropriés.

En plus de /etc/systemd/dnssd, des répertoires ".d" de drop-in peuvent être placés dans les répertoires /usr/lib/systemd/dnssd ou /run/systemd/dnssd. Les fichiers de drop-in dans /etc/ priment sur ceux dans /run/ qui priment à leur tour sur ceux dans /usr/lib/ ou /usr/local/lib. Les fichiers de drop-in sous l'un de ces répertoires priment sur le fichier de service réseau principal où qu'il soit situé.

OPTIONS DE LA SECTION [SERVICE]

Le fichier de service réseau contient une section [Service], qui spécifie un service réseau découvrable annoncé sur un réseau local avec des diffusions Multicast DNS.

Nom=

Un nom d'instance du service réseau tel que défini dans la section 4.1.1 de RFC 6763[1], par exemple "webserver".

L'option prend en charge l'expansion de spécificateurs simples. Les expansions suivantes sont comprises :

Tableau 1. Spécificateurs disponibles

Spécificateur Signification Détails
"%a" Architecture Une courte chaîne identifiant l'architecture du système local. Une chaîne telle que x86, x86-64 ou arm64. Voir les architectures définies pour ConditionArchitecture= dans systemd.unit(5) pour une liste complète.
"%A" Version de l'image du système d'exploitation L'identifiant de la version de l'image du système d'exploitation du système en cours d'exécution, tel que lu dans le champ IMAGE_VERSION= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%b" ID de démarrage L'ID de démarrage du système en cours d'exécution, formaté en chaîne. Voir random(4) pour plus d'informations.
"%B" ID de build du système d'exploitation L'identifiant de build du système d'exploitation du système en cours d'exécution, tel que lu dans le champ BUILD_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%H" Nom d'hôte Le nom d'hôte du système en cours d'exécution.
"%m" ID de la machine L'ID de la machine du système en cours d'exécution, formaté en chaîne. Voir machine-id(5) pour plus d'informations.
"%M" Identifiant de l'image du système d'exploitation L'identifiant de l'image du système d'exploitation du système en cours d'exécution, tel que lu dans le champ IMAGE_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%o" ID du système d'exploitation L'identifiant du système d'exploitation du système en cours d'exécution, tel que lu dans le champ ID= de /etc/os-release. Voir os-release(5) pour plus d'informations.
"%v" Version du noyau Identique à la sortie de uname -r.
"%w" ID de version du système d'exploitation L'identifiant de la version du système d'exploitation du système en cours d'exécution, tel que lu dans le champ VERSION_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%W" ID de variante du système d'exploitation L'identifiant de la variante du système d'exploitation du système en cours d'exécution, tel que lu dans le champ VARIANT_ID= de /etc/os-release. S'il n'est pas défini, il se résout en une chaîne vide. Voir os-release(5) pour plus d'informations.
"%%" Signe de pourcentage simple Utilisez "%%" à la place de "%" pour spécifier un signe de pourcentage simple.

Ajouté dans la version 236.

Type=

Un type de service réseau tel que défini dans la section 4.1.2 de RFC 6763[1], par exemple "_http._tcp".

Ajouté dans la version 236.

SubType=

Un sous-type du service réseau tel que défini dans la section 7.1 de RFC 6763[1], par exemple "_printer".

Ajouté dans la version 256.

Port=

Un numéro de port IP du service réseau.

Ajouté dans la version 236.

Priority=

Un numéro de priorité défini dans les enregistrements de ressource SRV correspondant au service réseau.

Ajouté dans la version 236.

Weight=

Un numéro de poids défini dans les enregistrements de ressource SRV correspondant au service réseau.

Ajouté dans la version 236.

TxtText=

Une liste d'éléments clé/valeur séparés par des espaces blancs transmettant des informations supplémentaires sur le service nommé dans l'enregistrement de ressource TXT correspondant, par exemple "path=/portal/index.html". Les clés et les valeurs peuvent contenir des séquences d'échappement de style C qui sont traduites lors de la lecture des fichiers de configuration.

Cette option ainsi que TxtData= peuvent être spécifiées plusieurs fois, auquel cas plusieurs enregistrements de ressources TXT seront créés pour le service. Si la chaîne vide est assignée à cette option, la liste est réinitialisée et toutes les affectations précédentes n'auront aucun effet.

Ajouté dans la version 236.

TxtData=

Une liste d'éléments clé/valeur séparés par des espaces blancs transmettant des informations supplémentaires sur le service nommé dans l'enregistrement de ressource TXT correspondant où les valeurs sont des chaînes encodées en base64 représentant des données binaires, par exemple "data=YW55IGJpbmFyeSBkYXRhCg==". Les clés peuvent contenir des séquences d'échappement de style C qui sont traduites lors de la lecture des fichiers de configuration.

Cette option ainsi que TxtText= peuvent être spécifiées plusieurs fois, auquel cas plusieurs enregistrements de ressources TXT seront créés pour le service. Si la chaîne vide est assignée à cette option, la liste est réinitialisée et toutes les affectations précédentes n'auront aucun effet.

Ajouté dans la version 236.

EXEMPLES

Exemple 1. Service HTTP

# /etc/systemd/dnssd/http.dnssd
[Service]
Name=%H
Type=_http._tcp
Port=80
TxtText=path=/stats/index.html t=temperature_sensor

Ceci rend le serveur http fonctionnant sur l'hôte découvrable sur le réseau local étant donné que MulticastDNS est activé sur l'interface réseau.

Maintenant, l'utilitaire "resolvectl" devrait pouvoir résoudre le service au nom de l'hôte :

$ resolvectl service meteo._http._tcp.local
meteo._http._tcp.local: meteo.local:80 [priorité=0, poids=0]
                        169.254.208.106%senp0s21f0u2u4
                        fe80::213:3bff:fe49:8aa%senp0s21f0u2u4
