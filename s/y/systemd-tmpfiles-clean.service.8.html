NOM

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Créer, supprimer et nettoyer des fichiers et répertoires

SYNTAXE

systemd-tmpfiles [OPTIONS...] [FICHIER_CONFIG...]

Unités système :

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unités utilisateur :

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPTION

systemd-tmpfiles crée, supprime et nettoie des fichiers et des répertoires, en utilisant le format et l'emplacement des fichiers de configuration spécifiés dans tmpfiles.d(5). Historiquement, il était conçu pour gérer les fichiers volatils et temporaires, comme son nom l'indique, mais il fournit une fonctionnalité générique de gestion de fichiers et peut être utilisé pour gérer tout type de fichiers. Il doit être invoqué avec une ou plusieurs commandes --create, --remove, et --clean, pour sélectionner le sous-ensemble respectif d'opérations.

S'il est invoqué sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par tmpfiles.d(5) sont exécutées. Lorsqu'il est invoqué avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments fournis en ligne de commande sont utilisés à la place du fichier de configuration CHEMIN. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne "-" est spécifiée à la place d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans barres obliques), tous les répertoires de configuration sont recherchés pour un fichier correspondant et le fichier trouvé ayant la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration d'autres fichiers correspondants.

Les services système (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invoquent systemd-tmpfiles pour créer des fichiers système et effectuer un nettoyage à l'échelle du système. Ces services lisent les fichiers de configuration contrôlés par l'administrateur dans les répertoires tmpfiles.d/. Les services utilisateur (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) invoquent également systemd-tmpfiles, mais il lit un ensemble distinct de fichiers, qui comprend des fichiers contrôlés par l'utilisateur sous ~/.config/user-tmpfiles.d/ et ~/.local/share/user-tmpfiles.d/, et des fichiers contrôlés par l'administrateur sous /usr/share/user-tmpfiles.d/. Les utilisateurs peuvent l'utiliser pour créer et nettoyer des fichiers sous leur contrôle, mais l'instance système effectue le nettoyage global et n'est pas influencée par la configuration utilisateur. Notez que cela signifie qu'un nettoyage basé sur le temps configuré dans l'instance système, comme celui généralement configuré pour /tmp/, affectera également les fichiers créés par l'instance utilisateur s'ils sont placés dans /tmp/, même si le nettoyage basé sur le temps de l'instance utilisateur est désactivé.

Pour réappliquer les paramètres après la modification de la configuration, redémarrez simplement systemd-tmpfiles-clean.service, ce qui appliquera tous les paramètres qui peuvent être exécutés en toute sécurité à l'exécution. Pour déboguer systemd-tmpfiles, il peut être utile de l'invoquer directement depuis la ligne de commande avec un niveau de journalisation accru (voir $SYSTEMD_LOG_LEVEL ci-dessous).

COMMANDES ET OPTIONS

Les commandes suivantes sont comprises :

--create

Si cette commande est passée, tous les fichiers et répertoires marqués avec f, F, w, d, D, v, p, L, c, b, m dans les fichiers de configuration sont créés ou écrits. Les fichiers et répertoires marqués avec z, Z, t, T, a, et A ont leur propriétaire, leur mode d'accès et leurs étiquettes de sécurité définis.

--clean

Si cette commande est passée, tous les fichiers et répertoires avec un paramètre d'âge configuré seront nettoyés.

--remove

Si cette commande est passée, le contenu des répertoires marqués avec D ou R, et les fichiers ou répertoires eux-mêmes marqués avec r ou R sont supprimés à moins qu'un verrou BSD exclusif ou partagé ne soit pris dessus (voir flock(2)).

--purge

Si cette option est passée, tous les fichiers et répertoires déclarés pour création et marqués avec le caractère "$" par les fichiers tmpfiles.d/ spécifiés en ligne de commande seront supprimés. Plus précisément, cela agit sur tous les fichiers et répertoires marqués avec f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si ce commutateur est utilisé, au moins un fichier tmpfiles.d/ (ou - pour l'entrée standard) doit être spécifié en ligne de commande ou l'invocation sera refusée, pour des raisons de sécurité (car autrement, une grande partie des fichiers du système installés pourrait être supprimée).

L'utilisation principale de cette option est de supprimer automatiquement les fichiers et répertoires qui ont été initialement créés pour un paquet installé, lors de la désinstallation du paquet.

Il est recommandé d'exécuter d'abord cette commande en combinaison avec --dry-run (voir ci-dessous) pour vérifier quels fichiers et répertoires seront supprimés.

Attention ! Ce n'est généralement pas la commande que vous recherchez ! Dans la plupart des cas, --remove est ce que vous cherchez.

Ajouté dans la version 256.

--user

Exécute la configuration "utilisateur", c'est-à-dire les fichiers tmpfiles.d/ dans les répertoires de configuration utilisateur.

Ajouté dans la version 236.

--boot

Exécute également les lignes avec un point d'exclamation. Les lignes qui ne sont pas sûres à exécuter sur un système en cours d'exécution peuvent être marquées de cette façon. systemd-tmpfiles est exécuté au démarrage avec --boot spécifié et exécutera ces lignes. Lorsqu'il est invoqué à nouveau plus tard, il doit être appelé sans --boot.

Ajouté dans la version 209.

--graceful

Ignore les lignes de configuration concernant des utilisateurs ou des groupes inconnus. Cette option est destinée à être utilisée au démarrage, avant que tous les utilisateurs ou groupes n'aient été créés.

Ajouté dans la version 254.

--dry-run

Traite la configuration et affiche les opérations qui seraient effectuées, mais ne modifie rien dans le système de fichiers.

Ajouté dans la version 256.

--prefix=chemin

Applique uniquement les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 212.

--exclude-prefix=chemin

Ignore les règles dont les chemins commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 207.

-E

Raccourci pour "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", c'est-à-dire exclure les hiérarchies généralement supportées par les systèmes de fichiers virtuels ou en mémoire. Ceci est utile en combinaison avec --root=, si l'arborescence de répertoires spécifiée contient une arborescence d'OS sans ces systèmes de fichiers virtuels/en mémoire montés, car il n'est généralement pas souhaitable de créer des fichiers et des répertoires sous ces sous-répertoires s'ils doivent être surmontés pendant l'exécution.

Ajouté dans la version 247.

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront préfixés avec le chemin root alternatif donné, y compris les chemins de recherche de configuration.

Lorsque cette option est utilisée, le service de noms (NSS) de la libc est contourné pour la résolution des utilisateurs et des groupes. Au lieu de cela, les fichiers /etc/passwd et /etc/group dans le root alternatif sont lus directement. Cela signifie que les utilisateurs/groupes non listés dans ces fichiers ne seront pas résolus, c'est-à-dire que les bases de données complexes comme LDAP, NIS, etc. ne sont pas prises en compte.

Envisagez de combiner cela avec -E pour garantir que l'invocation ne crée pas de fichiers ou de répertoires sous des points de montage dans l'image de l'OS opérée qui sont généralement surmontés pendant l'exécution.

Ajouté dans la version 212.

--image=

b>image

Prend un chemin vers un fichier image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers dans l'image disque indiquée. Ceci est similaire à --root= mais opère sur les systèmes de fichiers stockés dans des images disque ou des périphériques blocs. L'image disque doit soit contenir uniquement un système de fichiers, soit un ensemble de systèmes de fichiers au sein d'une table de partitions GPT, conformément à la Discoverable Partitions Specification[1]. Pour plus d'informations sur les images disque prises en charge, consultez le commutateur du même nom dans systemd-nspawn(1).

Implique -E.

Ajouté dans la version 247.

--image-policy=policy

Prend une chaîne de politique d'image en argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si elle n'est pas spécifiée, elle prend par défaut la politique "*", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=PATH

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans tmpfiles.d(5) seront lus, et la configuration donnée sur la ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration PATH.

Cette option est destinée à être utilisée lorsque des scripts d'installation de paquets s'exécutent et que les fichiers appartenant à ce paquet ne sont pas encore disponibles sur le disque, de sorte que leur contenu doit être donné sur la ligne de commande, mais que la configuration de l'administrateur peut déjà exister et devrait se voir attribuer une priorité plus élevée.

Ajouté dans la version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties "intéressantes" des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne pas rediriger la sortie vers un paginator.

-h, --help

Affiche un bref texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

Il est possible de combiner --create, --clean et --remove en une seule invocation (auquel cas la suppression et le nettoyage sont exécutés avant la création de nouveaux fichiers). Par exemple, lors du démarrage, la ligne de commande suivante est exécutée pour s'assurer que tous les répertoires temporaires et volatiles sont supprimés et créés conformément au fichier de configuration :

systemd-tmpfiles --remove --create

IDENTIFIANTS

systemd-tmpfiles prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

tmpfiles.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier de configuration drop-in tmpfiles.d/. Si cet identifiant est passé, il est traité après tous les fichiers drop-in lus à partir du système de fichiers. Les lignes de l'identifiant peuvent donc augmenter les lignes existantes du système d'exploitation, mais ne pas les remplacer.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-tmpfiles-setup.service (et les fichiers d'unité associés) est configuré pour hériter de l'identifiant "tmpfiles.extra" du gestionnaire de service.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages d'un niveau de journalisation supérieur, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'un des mots suivants : console, syslog, kmsg ou journal suivi d'un deux-points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lors de la journalisation vers la console, qui devrait être au niveau info). Notez que le niveau de journalisation maximal global prime sur tous les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Un booléen. S'il est vrai, les messages écrits sur le tty seront colorés en fonction de la priorité.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. S'il est vrai, les messages du journal de la console seront préfixés par un horodatage.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux attacheront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. S'il est vrai, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent joint comme métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages du journal. L'un des éléments suivants : console (journaliser vers le tty attaché), console-prefixed (journaliser vers le tty attaché mais avec des préfixes codant le niveau de journalisation et la "facility", voir syslog(3), kmsg (journaliser vers le tampon circulaire du journal du noyau), journal (journaliser vers le journal), journal-or-kmsg (journaliser vers le journal si disponible, et vers kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie du journal).

$SYSTEMD_PAGER, $PAGER

Paginator à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de paginators bien connues sont essayées successivement, y compris less(1) et more(1), jusqu'à ce qu'une soit trouvée. Si aucune implémentation de paginator n'est découverte, aucun paginator n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur "cat" équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le paginator (avec "cat" ou ""), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs peuvent vouloir modifier deux options en particulier :

K

Cette option indique au paginator de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même afin de revenir à l'invite de commande du paginator, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas "K", et que le paginator invoqué est less, Ctrl+C sera ignoré par l'exécutable, et devra être géré par le paginator.

X

Cette option indique au paginator de ne pas envoyer les chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du paginator. Néanmoins, cela empêche certaines fonctionnalités du paginator de fonctionner, en particulier la sortie paginée ne peut pas être défilée avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet sur les invocations de less par les outils systemd.

Voir less(1) pour plus de détails.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut "utf-8", si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet sur les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes paginator courantes comme less(1), en plus de la "pagination", c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque les commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le paginator devient une limite de sécurité. Des précautions doivent être prises pour que seuls les programmes aux fonctionnalités strictement limitées soient utilisés comme paginators, et que les fonctionnalités interactives indésirables telles que l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le "mode sécurisé" pour le paginator peut être activé comme décrit ci-dessous, si le paginator le prend en charge (la plupart des paginators ne sont pas écrits de manière à en tenir compte). Il est recommandé soit d'activer explicitement le "mode sécurisé", soit de désactiver complètement le paginator en utilisant --no-pager ou PAGER=cat lorsque des utilisateurs non fiables sont autorisés à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur vrai, le "mode sécurisé" du paginator est activé. En "mode sécurisé", LESSSECURE=1 sera défini lors de l'invocation du paginator, ce qui demande au paginator de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou qui lancent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le "mode sécurisé".

Lorsqu'elle est définie sur faux, aucune limitation n'est imposée au paginator. Définir SYSTEMD_PAGERSECURE=0 ou ne pas la supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le "mode sécurisé" doit être activé et si le paginator le prend en charge. Le "mode sécurisé" est activé si l'UID effectif n'est pas le même que celui du propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lorsqu'il s'exécute sous systemd-tmpfiles(8) — systemd v258.2

NAME

systemd-tmpfiles - Creates, removes and cleans up volatile and temporary files and directories

SYNOPSIS

systemd-tmpfiles [--clean|--remove|--create] [--prefix=PATH] [--directory] [--all]

DESCRIPTION

systemd-tmpfiles is used to manage volatile and temporary files and directories. It parses files in /usr/lib/tmpfiles.d/, /run/tmpfiles.d/ and /etc/tmpfiles.d/ (see tmpfiles.d(5) for details) and creates, removes or cleans up files and directories based on the rules specified therein. This is typically used to manage directories like /tmp, /var/tmp, or /run.

The primary purpose is to manage files that should not persist across reboots, or files that are created automatically and might grow indefinitely if not cleaned up. It is intended to be used once during early boot by the systemd instance. For cleaning up runtime directories, systemd-tmpfiles-clean.service(8) is typically used.

If no options are given, systemd-tmpfiles will execute all three operations: create, remove, and clean.

COMMANDS AND OPTIONS

The following operations may be selected:

--create
Create the files and directories specified in the configuration files that do not exist. This operation is normally executed during early boot.
--remove
Remove files and directories specified in the configuration files that exist and are listed. This operation is normally executed during early boot.
--clean
Remove files and directories that exist and are older than the time specified in the configuration files. This operation is normally run periodically via systemd-tmpfiles-clean.timer(8). If --prefix= is given, only entries within that prefix are cleaned.
--all
Perform all three operations: --create, --remove, and --clean. This is the default behavior if no operation is specified.

The following options modify the behavior of the operations:

--prefix=PATH
Only process rules that apply to the specified directory path. If not specified, all rules are processed. This option is particularly useful for the --clean operation.
--directory
When creating files or directories, the target path must be a directory. This is useful to ensure that a directory exists before it is used by other processes.

CREDENTIALS

When run with the --clean operation, systemd-tmpfiles requires the CAP_FOWNER capability to change file ownership and permissions. If run without sufficient privileges, it might fail to clean up certain files or directories.

ENVIRONMENT

The behavior of systemd-tmpfiles is affected by the following environment variables:

$SYSTEMD_PAGER, $PAGER

Controls which pager program is used for displaying output. If neither is set, a built-in pager is used. If set to an empty string or if the value is not a program name, output is not paged.

$SYSTEMD_PAGERSECURE

Controls whether a pager is invoked with security enhancements. If this is set to the string "1", or if the user is not logged in as root and is invoking a tool like sudo(8) or similar tools ($SUDO_UID is set [2]). In those cases, SYSTEMD_PAGERSECURE=1 will be set and pagers which are not known to implement "secure mode" will not be used at all. Note that this autodetection only covers the most common mechanisms to elevate privileges and is intended as convenience. It is recommended to explicitly set $SYSTEMD_PAGERSECURE or disable the pager.

Note that if the $SYSTEMD_PAGER or $PAGER variables are to be honoured, other than to disable the pager, $SYSTEMD_PAGERSECURE must be set too.

$SYSTEMD_COLORS

Takes a boolean argument. When true, systemd and related utilities will use colors in their output, otherwise the output will be monochrome. Additionally, the variable can take one of the following special values: "16", "256" to restrict the use of colors to the base 16 or 256 ANSI colors, respectively. This can be specified to override the automatic decision based on $TERM and what the console is connected to.

$SYSTEMD_URLIFY

The value must be a boolean. Controls whether clickable links should be generated in the output for terminal emulators supporting this. This can be specified to override the decision that systemd makes based on $TERM and other conditions.

UNPRIVILEGED --CLEANUP OPERATION

systemd-tmpfiles tries to avoid changing the access and modification times on the directories it accesses, which requires CAP_FOWNER privileges. When running as non-root, directories which are checked for files to clean up will have their access time bumped, which might prevent their cleanup.

EXIT STATUS

On success, 0 is returned. If the configuration was syntactically invalid (syntax errors, missing arguments, ...), so some lines had to be ignored, but no other errors occurred, 65 is returned (EX_DATAERR from /usr/include/sysexits.h). If the configuration was syntactically valid, but could not be executed (lack of permissions, creation of files in missing directories, invalid contents when writing to /sys/ values, ...), 73 is returned (EX_CANTCREAT from /usr/include/sysexits.h). Otherwise, 1 is returned (EXIT_FAILURE from /usr/include/stdlib.h).

Note: when creating items, if the target already exists, but is of the wrong type or otherwise does not match the requested state, and forced operation has not been requested with "+", a message is emitted, but the failure is otherwise ignored.
