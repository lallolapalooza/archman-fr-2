SYD(1) Manuel des commandes générales SYD(1)

NOM

syd - Noyau d'application solide comme le roc

SYNTAXE

syd [-acefhlmpqxEPV] [--] {commande [arg...]}

syd [-acefhlmpqxEPV] [--] {bibliothèque.so}

syd --api

syd --check

syd --el

syd --sh

DESCRIPTION

Syd est un utilitaire exploitant l'appel système seccomp(2) pour isoler des processus sous Linux versions 5.19 ou ultérieures. Il permet un contrôle précis de l'accès au système de fichiers et au réseau d'un processus sans nécessiter de privilèges root. Syd est conçu pour être facile à utiliser sur une large gamme d'architectures, y compris x86, x86_64, x32, armv7, aarch64, loongarch64, mips, mips64, mips64el, ppc, ppc64, ppc64le, riscv64 et s390x, incarnant le principe de fournir un contrôle d'accès simple, flexible et robuste aux utilisateurs Linux.

La fonctionnalité principale de Syd tourne autour de la restriction de l'accès aux ressources d'un processus via plusieurs mécanismes :

  • Montages liés (Bind Mounts) : Utilisés dans un espace de noms de montage pour appliquer des restrictions au niveau du Système de fichiers virtuel (VFS), telles que lecture seule, nodev, noexec, nosuid et nosymfollow.
  • Landlock : Emploie des restrictions de chemins en lecture seule et en lecture-écriture au niveau du noyau.
  • seccomp-bpf : Applique des filtres utilisateur Secure Computing pour l'isolation dans l'espace noyau.
  • seccomp-notify : Permet l'isolation dans l'espace noyau avec un relais vers l'espace utilisateur pour désadresser des arguments pointeurs dans les appels système, y compris les noms de chemins et les adresses réseau. Les vérifications d'accès utilisent des motifs de style shell UNIX et la notation CIDR, refusant par défaut les appels système avec EACCES tout en tentant d'émuler les appels réussis pour atténuer les vecteurs d'attaque Time-of-Check to Time-of-Use (TOCTOU).

Les prérequis pour Syd incluent un noyau Linux supportant les appels système pidfd_getfd(2) et pidfd_send_signal(2), l'opération SECCOMP_USER_NOTIF_FLAG_CONTINUE dans le mécanisme Secure Computing, et de préférence l'option noyau CONFIG_CROSS_MEMORY_ATTACH. Pour l'émulation des appels système, Syd utilise l'opération seccomp SECCOMP_IOCTL_NOTIF_ADDFD. De plus, Syd définit le drapeau SECCOMP_FILTER_FLAG_WAIT_KILLABLE_RECV pour gérer correctement les interruptions pendant le traçage. Bien que la version de Linux 5.19 ou ultérieure soit requise, pour le support de Landlock, Syd nécessite un noyau configuré avec l'option CONFIG_LSM_LANDLOCK supportant la version 3 de l'ABI Landlock, avec syd-lock(1) disponible comme programme d'aide pour vérifier le support du noyau. Les options du noyau Linux CONFIG_KCMP et CONFIG_UNIX_DIAG sont recommandées.

Syd s'engage à maintenir des normes de sécurité rigoureuses en délimitant strictement l'espace de ressources accessibles aux processus isolés. Dans la section SECURITE de la page de manuel syd(7), une énumération détaillée des mesures de renforcement de la sécurité implémentées par Syd est fournie, ainsi que des configurations optionnelles pour assouplir certaines restrictions. Cette flexibilité permet l'accueil d'une grande variété de processus au sein de l'environnement d'isolation.

L'approche de la sécurité au sein de Syd est méticuleusement conçue pour équilibrer une protection robuste avec la flexibilité opérationnelle, garantissant que les utilisateurs ont la possibilité d'affiner les mécanismes d'isolation pour répondre à des exigences spécifiques. En offrant un aperçu des techniques de renforcement et des options de personnalisation, Syd permet aux utilisateurs de naviguer efficacement entre les compromis sécurité et fonctionnalité.

OPTIONS

Les options suivantes sont comprises :

-h, --help Affiche l'aide et quitte.
-V, --version Affiche la version et quitte.
-C, --check Affiche les informations de support d'isolation du système actuel et quitte.
-v, --verbose Être verbeux, équivalent à la commande log/verbose:true.
-c Compatibilité avec les shells de connexion
Déclenche l'exécution de la commande sous un shell avec le profil utilisateur.
Le shell à exécuter est /bin/sh par défaut.
Utiliser la variable d'environnement SYD_SHELL pour remplacer.
-f Compatibilité avec les shells de connexion.
Déclenche l'analyse du profil utilisateur par Syd au démarrage.
-l, --login Compatibilité avec les shells de connexion
Déclenche l'analyse du profil utilisateur par Syd au démarrage.
-q Active le mode de démarrage rapide pour des temps de lancement plus courts.
Ceci doit être passé comme première option, sinon il sera ignoré.
Voir l'explication de la variable d'environnement SYD_QUICK_BOOT pour la sécurité de cette option.
-x Active le mode trace alias « exécution à blanc ».
Dans ce mode, Syd autorisera les appels système même s'ils entraînent des violations d'accès.
Ce mode avec une journalisation étendue peut être utilisé pour construire des profils d'isolation de manière automatisée.
Voir pandora(1) qui est un outil utilisant le mode trace de Syd pour générer automatiquement des profils d'isolation.
-m config Configure le bac à sable pendant l'initialisation, peut être répété.
-p name Utilise un profil d'isolation pendant l'initialisation, peut être répété.
-P path Exécute un fichier de configuration pendant l'initialisation, peut être répété.
-a alias Définit un alias de la commande. Passé comme argv[0] au programme.
-e Utilisez -e var=val pour placer var=val dans l'environnement de la commande, peut être répété.
Utilisez -e var pour supprimer var de l'environnement de la commande, peut être répété.
Utilisez -e var= pour transmettre une variable d'environnement non sécurisée, peut être répété.
-E mode Exportez les règles de calcul sécurisé avec le format donné vers la sortie standard et quittez.
Le mode doit être l'un des suivants : bpf ou pfc :
bpf, alias Berkeley Packet Filter est un format binaire lisible par machine, tandis que
pfc, alias Pseudo Filter Code est un format textuel lisible par l'homme.
--api Affiche la spécification de l'API syd(2) au format JSON.
Cette spécification est destinée à faciliter la génération de liaisons de langage.
Cette spécification est également disponible via le chemin magique /dev/syd.
--el Affiche syd.el, qui est l'implémentation Emacs Lisp de l'interface stat(2) de Syd.
Ce fichier est également disponible via le chemin magique /dev/syd.el.
--sh Affiche un script shell qui définit la fonction d'aide esyd.
Ce fichier est également disponible via le chemin magique /dev/syd.sh.
Fonctionne avec POSIX sh, bash et zsh.
Vous pouvez utiliser eval "$(syd --sh)" dans votre fichier d'initialisation shell.

Syd peut soit exécuter une commande avec les arguments spécifiés, soit charger une bibliothèque dynamique et exécuter la fonction syd_main() de celle-ci. Si le premier argument non optionnel se termine par le suffixe .so, il est attendu que ce soit le chemin d'une bibliothèque dynamique à charger. La bibliothèque dynamique est chargée tôt au démarrage dans le processus Syd de telle sorte que même le système de fichiers qui la possède puisse être monté en noexec, en utilisant par exemple bind+/:/:noexec. Cela permet de créer un environnement très restreint.

ENVIRONNEMENT

SYD_ID Spécifie l'ID du sandbox sous forme de 128 caractères hexadécimaux minuscules.
Les 32 premiers caractères ne peuvent pas être tous des zéros.
Si cette variable n'est pas définie par l'utilisateur au démarrage,
Syd la génère en hachant des octets AT_RANDOM avec SHA3-512.
Syd panique si l'utilisateur passe la valeur dans un format incorrect.
SYD_IPC Spécifie l'adresse du socket UNIX pour la configuration d'exécution.
Équivalent à la commande ipc, voir la page man syd(2).
La commande ipc a la priorité sur cette variable d'environnement.
SYD_LOG Définit le niveau de journalisation sur emerg, alert, crit, error, warn, notice, info ou debug.
SYD_LOG_BUF_LEN Définit la capacité du tampon circulaire de syslog(2).
Par défaut, le tampon circulaire est alloué sur la pile avec une taille dépendante de l'architecture.
La définition de cette variable amène Syd à allouer le tampon circulaire sur le tas avec la taille spécifiée par l'utilisateur.
Notez que la valeur est analysée à l'aide de la crate parse-size.
Consultez leur documentation pour des informations sur le formatage.
SYD_LOG_FD Définit le descripteur de fichier de journalisation, par défaut stderr(3).
Les valeurs négatives sont autorisées comme raccourci pour désactiver la journalisation.
Les valeurs positives doivent être des descripteurs de fichier valides ou Syd se terminera avec EBADF.
SYD_PDS Définit le signal de décès du parent en utilisant le nom ou le numéro du signal.
SYD_PID_FN Définit le nom du fichier PID, ce qui amène Syd à écrire son identifiant de processus dans ce fichier au démarrage.
Le fichier ne doit pas exister et sera créé avec des permissions de lecture réservées à l'utilisateur.
SYD_NPROC Définit le nombre de threads de gestionnaire d'appels système de base, par défaut le nombre de CPUs.
Le nombre doit être au moins de 1.
SYD_NPROC_MAX Définit le nombre maximal de threads de gestionnaire d'appels système, par défaut usize::MAX.
Le nombre doit être supérieur à SYD_NPROC.
SYD_SHELL Choisit le shell à lancer lorsqu'il est invoqué comme shell de connexion, par défaut /bin/sh.
SYD_DUMP_SCMP Exporte les règles de calcul sécurisé avec le format donné, équivalent à l'option -E.
SYD_SKIP_SCMP Ignore le confinement seccomp(2) des threads par Syd.
Ceci est dangereux et ne doit être utilisé que pour le profilage.
SYD_FORCE_NO_SYMLINKS Force le drapeau de résolution RESOLVE_NO_SYMLINKS à la limite de open(2).
Équivalent à trace/force_no_symlinks:1.
SYD_FORCE_NO_MAGICLINKS Force le drapeau de résolution RESOLVE_NO_MAGICLINKS à la limite de open(2).
Équivalent à trace/force_no_magiclinks:1.
SYD_FORCE_NO_XDEV Force le drapeau de résolution RESOLVE_NO_XDEV à la limite de open(2).
Équivalent à trace/force_no_xdev:1.
SYD_FORCE_CLOEXEC Force la fermeture lors de l'exécution pour les descripteurs de fichier.
Équivalent à trace/force_cloexec:1.
SYD_FORCE_RAND_FD Utilise des descripteurs de fichier aléatoires pour renforcer la sécurité contre la réutilisation des descripteurs de fichier.
Équivalent à trace/force_rand_fd:1.
SYD_FORCE_RO_OPEN Rejette la création et l'écriture des appels open(2).
Équivalent à trace/force_ro_open:1.
SYD_FORCE_TTY Force la sortie TTY qui est du JSON joliment formaté.
SYD_QUIET_TTY Force la sortie TTY silencieuse qui est du JSON orienté ligne.
SYD_PROXY_HOST Remplace la valeur par défaut de proxy/ext/host,
Si la valeur est un nom d'hôte et non une adresse IP,
Syd résout ce nom d'hôte au démarrage et sélectionne une adresse IP de réponse de manière aléatoire.
SYD_PROXY_PORT Remplace la valeur par défaut de proxy/ext/port.
SYD_PROXY_UNIX Définit la valeur par défaut pour proxy/ext/unix qui remplace proxy/ext/host.
SYD_QUICK_BOOT Active le mode de démarrage rapide, ce qui rend le démarrage de Syd notablement plus rapide :
Cependant, le démarrage rapide supprime une couche de défense contre certaines brèches de conteneur !
Utilisez ceci si vous réexécutez fréquemment syd(1) ou syd-oci(1),
comme le fait Exherbo Linux lors de cave-generate-metadata(1).
SYD_NO_CROSS_MEMORY_ATTACH Désactive l'attachement mémoire croisé et utilise proc_pid_mem(5) inconditionnellement.
SYD_PROC_PID_MEM_FALLBACK Par défaut, Syd utilise l'attachement mémoire croisé inconditionnellement.
La définition de cette variable amène Syd à se rabattre automatiquement sur proc_pid_mem(5),
si process_vm_readv(2) ou process_vm_writev(2) échoue avec ENOSYS,
ce qui indique une absence de prise en charge du noyau pour ces appels système.
La variable SYD_NO_CROSS_MEMORY_ATTACH a la priorité sur cette variable.
SYD_ASSUME_KERNEL Remplace uname(2) pour obtenir la version du noyau Linux hôte utilisée pour la détection des fonctionnalités.
Syd rapporte la version majeure et mineure du noyau à la limite de uname(2) au sein du sandbox.
La version micro est randomisée par exécution de Syd pour éviter les fuites d'informations.
SYD_PALUDIS_LPATH Remplace l'option sandbox/lpath pour le profil paludis, par défaut désactivé.
SYD_PALUDIS_IOCTL Remplace l'option sandbox/ioctl pour le profil paludis, par défaut désactivé.
SYD_USER_LPATH Remplace l'option sandbox/lpath pour le profil user, par défaut activé.
CARGO_BIN_EXE_syd-pty Chemin vers l'utilitaire syd-pty(1). Par défaut, recherche dans PATH.
CARGO_BIN_EXE_syd-tor Chemin vers l'utilitaire syd-tor(1). Par défaut, recherche dans PATH.

JOURNALISATION

Il existe huit niveaux de journalisation : emerg, alert, crit, error, warn, notice, info et debug. Le niveau de journalisation peut être défini avec la variable d'environnement SYD_LOG. Les journaux vont sur l'erreur standard sauf si un descripteur de fichier est spécifié avec la variable d'environnement SYD_LOG_FD. Les messages de gravité warn et supérieure sont également envoyés à syslog(3) sauf si la variable d'environnement SYD_NO_SYSLOG est définie.

Syd journalise en lignes JSON. Ci-dessous une liste de quelques clés couramment utilisées et leur signification :

CLÉ DESCRIPTION
ctx Contexte de l'entrée de journal, par exemple access, safesetid, segvguard etc.
cap Capacité du sandbox
act Action du sandbox : Allow, Warn, Deny, Panic, Stop, Abort, Kill ou Exit
pid Identifiant du processus
path Argument de chemin de l'appel système
addr Argument d'adresse réseau de l'appel système, par exemple 127.0.0.1!22
unix Argument d'adresse de socket UNIX de l'appel système
ipv Version IP de l'adresse réseau dans le champ addr (4 ou 6)
abs Vrai si l'adresse de socket dans le champ unix est un socket UNIX abstrait
sys Nom de l'appel système
arch Architecture de l'appel système
args Arguments de l'appel système
src Origine de l'appel système au format path+offset
Utilisez, par exemple, objdump -D path | grep offset pour afficher l'instruction d'appel système
cmd Nom du processus, ou ligne de commande si la sortie du journal est un TTY ou si la fonctionnalité log est activée
cwd Répertoire de travail actuel du processus
uid Identifiant utilisateur
time Horodatage au format compatible ISO8601, actuellement YYYYMMDDThhmmssZ
Le format de l'heure peut changer mais il restera toujours compatible ISO8601.
Les erreurs de formatage se rabattent sur l'affichage de l'horodatage sous forme d'entier.
err Erreur syd(1) — sydbox — exherbo documentation

LOGGING

Syd provides several logging levels for different types of messages:

error Error messages. These are critical and usually indicate a failure that prevents the sandbox from functioning correctly.
warn Warning messages. These indicate potential issues that may not immediately cause failure but could lead to problems later on.
info General information. Used for significant events or status updates.
debug Debug messages. Verbose output intended for developers to diagnose issues.
trace Trace messages. Extremely verbose output, often showing the flow of execution down to the finest detail.
msg Miscellaneous informational messages, mostly used with the info log level
tip Informational messages on how to configure the sandbox

CODES DE SORTIE

Syd sort avec le même code de sortie que le processus sandbox lui-même. Si le processus sandbox se termine avec un signal, Syd sort avec 128 plus la valeur du signal. En cas d'erreur lors du lancement ou de l'attente du processus sandbox, Syd sort avec errno indiquant la condition d'erreur. Par exemple, syd true renvoie 0, syd false renvoie 1, et syd -- syd true renvoie 16 qui représente EBUSY signifiant Périphérique ou ressource occupée, indiquant qu'un filtre de calcul sécurisé est déjà chargé.
