NOM

syncthing-rest-api - API REST

Syncthing expose une interface REST via HTTP sur le port de l'interface graphique. Celle-ci est utilisée par l'interface graphique (depuis Javascript) et peut être utilisée par d'autres processus souhaitant contrôler Syncthing. Dans la plupart des cas, les données d'entrée et de sortie sont au format JSON. L'interface est susceptible d'être modifiée.

CLÉ API

Pour utiliser l'API REST, une clé API doit être définie et utilisée. La clé API peut être générée dans l'interface graphique, ou définie dans l'élément configuration/gui/apikey du fichier de configuration. Pour utiliser une clé API, définissez l'en-tête de requête X-API-Key à la valeur de la clé API, ou définissez-la comme un jeton Bearer dans l'en-tête Authorization. Par exemple, curl -X POST -H "X-API-Key: abc123" http://localhost:8384/rest/... ou curl -X POST -H "Authorization: Bearer abc123" http://localhost:8384/rest/... peut être utilisé pour invoquer avec curl (ajoutez le flag -k lors de l'utilisation de HTTPS avec un certificat généré par Syncthing ou auto-signé).

Une exception à cette exigence est /rest/noauth, vous n'avez pas besoin de clé API pour utiliser ces points d'accès. De cette façon, les périphériques et services tiers peuvent effectuer des appels simples qui n'exposent pas d'informations sensibles sans avoir à exposer votre clé API.

PAGINATION DES RÉSULTATS

Certains points d'accès GET acceptent des arguments optionnels page et perpage pour la pagination. Pas plus de perpage (par défaut 65536 si non spécifié) entrées de résultats sont retournées dans un tableau. Pour accéder à d'autres entrées, passer le paramètre page avancera dans les résultats de ce nombre de pages. Les paramètres réellement utilisés sont toujours retournés comme attributs dans l'objet de réponse.

GET /rest/system/config/insync (DÉPRÉCIÉ)


Déprécié depuis la version v1.12.0: Cet endpoint fonctionne toujours comme avant mais est déprécié. Utilisez /rest/config/restart-required à la place.


Retourne si la configuration est synchronisée, c'est-à-dire si la configuration en cours d'exécution est identique à celle sur le disque.






{
  "configInSync": true
}










POST /rest/system/config (DÉPRÉCIÉ)


Déprécié depuis la version v1.12.0: Cet endpoint fonctionne toujours comme avant mais est déprécié. Utilisez les Endpoints de configuration à la place.


Envoie le contenu complet de la configuration, dans le même format que celui retourné par la requête GET correspondante. Lorsque l'envoi de la configuration réussit, la configuration envoyée est immédiatement appliquée, à l'exception des modifications qui nécessitent un redémarrage. Interrogez /rest/config/restart-required pour vérifier si un redémarrage est nécessaire.


Cet endpoint est le point principal pour contrôler Syncthing, même si la modification ne concerne qu'une très petite partie de la configuration : Le flux de travail habituel consiste à obtenir la configuration, à modifier les parties nécessaires et à la renvoyer.

POST   /rest/system/pause


Met en pause le périphérique donné ou tous les périphériques.


Prend le paramètre optionnel device (ID de périphérique). Lorsqu'il est omis, met en pause tous les périphériques. Retourne le statut 200 et aucun contenu en cas de succès, ou le statut 500 et une erreur en texte brut en cas d'échec.

{
  "ping": "pong"
}










POST   /rest/system/ping


Retourne un objet {"ping": "pong"}.






POST   /rest/system/reset


Envoie avec un corps vide pour effacer la base de données d'index actuelle et redémarrer Syncthing. Sans paramètres de requête, toute la base de données est effacée du disque. En spécifiant le paramètre folder avec un ID de dossier valide, seules les informations de ce dossier seront effacées :






curl -X POST -H "X-API-Key: abc123" http://localhost:8384/rest/system/reset?folder=ab1c2-def3g






Attention : Voir --reset-database pour l'effet secondaire de création de .stfolder et la mise en garde concernant les points de montage.






POST   /rest/system/restart


Envoie avec un corps vide pour redémarrer immédiatement Syncthing.






POST   /rest/system/resume


Reprend le périphérique donné ou tous les périphériques.


Prend le paramètre optionnel device (ID de périphérique). Lorsqu'il est omis, reprend tous les périphériques. Retourne le statut 200 et aucun contenu en cas de succès, ou le statut 500 et une erreur en texte brut en cas d'échec.






POST   /rest/system/shutdown


Envoie avec un corps vide pour faire quitter Syncthing et ne pas redémarrer.

CONFIG ENDPOINTS

Config Endpoints

Ajouté dans la version 1.12.0.

Ces points de terminaison facilitent l'accès et la modification de la configuration de manière granulaire. La configuration envoyée aux points de terminaison doit être dans le même format que celui retourné par la requête GET correspondante. Lorsque la soumission de la configuration réussit, la configuration envoyée est appliquée immédiatement, à l'exception des changements qui nécessitent un redémarrage. Interrogez /rest/config/restart-required pour vérifier si un redémarrage est nécessaire.

Pour tous les points de terminaison prenant en charge PATCH, il prend la configuration existante et désérialise l'objet JSON donné par-dessus. Cela signifie que tous les objets enfants remplaceront les objets existants, sans les étendre. Par exemple, pour RawListenAddresses dans les options, qui est un tableau de chaînes de caractères, l'envoi de {RawListenAddresses: ["tcp://10.0.0.2"]} remplacera toutes les adresses d'écoute existantes.

/rest/config

GET renvoie toute la configuration et PUT la remplace.

/rest/config/restart-required

GET indique si un redémarrage de Syncthing est nécessaire pour que la configuration actuelle prenne effet.

/rest/config/folders, /rest/config/devices

GET renvoie tous les dossiers respectivement les appareils sous forme de tableau. PUT prend un tableau et POST un objet unique. Dans les deux cas, si un dossier/appareil donné existe déjà, il est remplacé, sinon un nouveau est ajouté.

/rest/config/folders/*id*, /rest/config/devices/*id*

Remplacez *id* par l'ID du dossier ou de l'appareil souhaité. GET renvoie le dossier/appareil pour l'ID donné, PUT remplace toute la configuration, PATCH remplace uniquement les objets enfants donnés et DELETE supprime le dossier/appareil.

/rest/config/defaults/folder, /rest/config/defaults/device

GET renvoie un objet de configuration de dossier/appareil modèle avec toutes les valeurs par défaut, qui n'a besoin que d'un ID unique pour être appliqué. PUT remplace la configuration par défaut (les valeurs omises sont réinitialisées aux valeurs par défaut codées en dur), PATCH remplace uniquement les objets enfants donnés.

/rest/config/defaults/ignores

Ajouté dans la version 1.19.0.

GET renvoie un objet avec un seul attribut lines listant les modèles d'exclusion à utiliser par défaut sur les dossiers, sous forme de tableau de chaînes de caractères sur une seule ligne. PUT remplace les modèles d'exclusion par défaut à partir d'un objet du même format.

/rest/config/options, /rest/config/ldap, /rest/config/gui

GET renvoie l'objet respectif, PUT remplace l'objet entier et PATCH remplace uniquement les objets enfants donnés.

REMARQUE :

L'option de configuration gui.password a un traitement spécial pour accepter des mots de passe déjà hachés. Tout hachage bcrypt valide est stocké tel quel, tandis qu'un mot de passe en clair est d'abord haché.

GET /rest/db/completion

Retourne le pourcentage d'achèvement (0 à 100) ainsi que les comptages d'octets / d'éléments. Prend les paramètres optionnels device et folder :

/rest/db/completion?folder=abcd-1234

Statut d'achèvement agrégé pour tous les dossiers sur l'appareil local :

/rest/db/completion

Prend un paramètre, folder, et retourne le contenu du .stignore comme champ ignore. POST /rest/db/revert

Ajouté dans la version 0.14.50.

Demande l'annulation d'un dossier en lecture seule. Annuler un dossier signifie annuler toutes les modifications locales. Cet appel d'API ne fait rien si le dossier n'est pas un dossier en lecture seule.

Prend le paramètre obligatoire folder (ID du dossier).

curl -X POST -H X-API-Key:... http://127.0.0.1:8384/rest/db/revert?folder=default

POST /rest/db/scan

Demande un scan immédiat. Prend les paramètres optionnels folder (ID du dossier), sub (chemin relatif à la racine du dossier) et next (temps en secondes). Si folder est omis ou vide, tous les dossiers sont scannés. Si sub est donné, seul ce chemin (et ses enfants, s'il s'agit d'un répertoire) est scanné. L'argument next retarde l'intervalle de rescan automatique de Syncthing pendant un nombre donné de secondes.

Demander le scan d'un chemin qui n'existe plus, mais qui existait auparavant, est valide et entraînera la détection par Syncthing de la suppression du chemin en question.

Renvoie le statut 200 et aucun contenu en cas de succès, ou le statut 500 et une erreur en texte brut si une erreur s'est produite pendant le scan.

curl -X POST http://127.0.0.1:8384/rest/db/scan?folder=default&sub=foo/bar

POINTS DE TERMINAISON D'ÉVÉNEMENT

GET /rest/events

Pour recevoir des événements, effectuez une requête HTTP GET sur /rest/events.

Pour filtrer la liste des événements, créant ainsi un abonnement spécifique pour les types d'événements souhaités uniquement, ajoutez un paramètre events=EventTypeA,EventTypeB,... où les types d'événements sont parmi les Types d'événements. Si aucun filtre n'est spécifié, tous les événements sauf LocalChangeDetected et RemoteChangeDetected sont inclus.

Le paramètre optionnel since=<lastSeenID> définit l'ID du dernier événement que vous avez déjà vu. Syncthing renvoie un tableau d'objets événement codé en JSON, commençant juste après l'événement avec cet ID vu en dernier. La valeur par défaut est 0, ce qui renvoie tous les événements. Il y a une limite au nombre d'événements mis en mémoire tampon, donc si le taux d'événements est élevé ou si le temps entre les appels de sondage est long, certains événements peuvent être manqués. Cela peut être détecté en notant une discontinuité dans les ID d'événements.

Si aucun nouvel événement n'est produit depuis <lastSeenID>, l'appel HTTP se bloque et attend que de nouveaux événements se produisent avant de renvoyer. Si <lastSeenID> est un ID futur, l'appel HTTP se bloque jusqu'à ce que cet ID soit atteint ou qu'il expire. Par défaut, il expire après 60 secondes en renvoyant un tableau vide. La durée d'expiration peut être personnalisée avec le paramètre optionnel timeout=<secondes>.

Pour recevoir un nombre limité d'événements, ajoutez le paramètre limit=<n> avec une valeur appropriée pour n et seuls les derniers n événements seront renvoyés. Cela peut être utilisé pour rattraper l'ID de l'événement le plus récent après une déconnexion, par exemple : /rest/events?since=0&limit=1.

GET /rest/events/disk

Ce point de terminaison pratique fournit le même flux d'événements, mais pré-filtré pour n'afficher que les types d'événements LocalChangeDetected et RemoteChangeDetected. Le paramètre events n'est pas utilisé.

POINTS DE TERMINAISON SERVICES DIVERS

GET /rest/svc/deviceid

Vérifie et formate un ID d'appareil. Accepte tous les formats actuellement valides (52 ou 56 caractères avec ou sans séparateurs, majuscules ou minuscules, avec des substitutions triviales). Prend un paramètre, id, et renvoie soit un ID d'appareil valide au format moderne, soit une erreur.

$ curl -s http://localhost:8384/rest/svc/deviceid?id=1234 | json
{
  "error": "device ID invalid: incorrect length"
}

{
  "id": "P56IOI7-MZJNU2Y-IQGDREY-DM2MGTI-MGL3BXN-PQ6W5BM-TBBZ4TJ-XZWICQ2"
}

Renvoie une liste de codes de localisation canonisés, tels qu'ils sont récupérés de l'en-tête Accept-Language envoyé par le navigateur.

POINTS DE TERMINAISON DÉPANNAGE

Points de terminaison de débogage

GET /rest/debug/cpuprof

Utilisé pour capturer un profil de ce que Syncthing fait sur le CPU. Voir Profiling.

GET /rest/debug/heapprof

Utilisé pour capturer un profil de ce que Syncthing fait avec la mémoire du tas. Voir Profiling.

GET /rest/debug/support

Collecte des informations sur l'instance en cours d'exécution à des fins de dépannage. Renvoie un « bundle de support » sous forme d'archive zippée, qui doit être envoyé aux développeurs après vérification qu'il ne contient aucune information personnelle sensible. Les identifiants pour l'interface graphique Web et la clé API sont automatiquement expurgés.

GET /rest/debug/file

Affiche les diagnostics concernant un fichier spécifique dans un dossier partagé. Prend les paramètres folder (ID du dossier) et file (chemin relatif au dossier).

$ curl -H X-API-Key:... "http://localhost:8384/rest/debug/file?folder=default&file=foo/bar"

L'objet renvoyé contient les mêmes informations que GET /rest/db/file, plus un résumé de globalVersions.
