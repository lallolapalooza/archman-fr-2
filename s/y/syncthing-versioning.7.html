NOM

syncthing-versioning - Conserve des sauvegardes automatiques des fichiers supprimés par d'autres nœuds

Syncthing prend en charge l'archivage de l'ancienne version d'un fichier lorsqu'il est supprimé ou remplacé par une version plus récente du cluster. C'est ce qu'on appelle la «gestion des versions de fichiers» et elle utilise l'une des stratégies de gestion des versions décrites ci-dessous. La gestion des versions de fichiers est configurée par dossier, par appareil, et par défaut, elle est définie sur «aucune gestion de version de fichier», c'est-à-dire qu'aucune copie ancienne des fichiers n'est conservée.

REMARQUE :

La gestion des versions s'applique aux modifications reçues d'autres appareils. Autrement dit, si Alice a activé la gestion des versions et que Bob modifie un fichier, l'ancienne version sera archivée sur l'ordinateur d'Alice lorsque cette modification sera synchronisée depuis Bob. Si Alice modifie un fichier localement sur son propre ordinateur, Syncthing n'archivera pas et ne pourra pas archiver l'ancienne version.

Les options de configuration applicables pour chaque stratégie de gestion des versions sont décrites ci-dessous. Pour la plupart d'entre elles, il est possible de spécifier où les versions sont stockées, le chemin par défaut étant le dossier .stversions à l'intérieur du chemin du dossier partagé. Si vous définissez un chemin de version personnalisé, assurez-vous qu'il se trouve sur la même partition ou le même système de fichiers que le chemin du dossier régulier, car le déplacement de fichiers vers celui-ci peut échouer autrement.

GESTION DES VERSIONS DE FICHIERS PANNIER

Cette stratégie de gestion des versions émule l'approche courante du «panier». Lorsqu'un fichier est supprimé ou remplacé en raison d'une modification sur un appareil distant, il est déplacé vers le panier dans le dossier .stversions. Si un fichier portant le même nom était déjà dans le panier, il est remplacé.

Une option de configuration est disponible pour nettoyer le panier des fichiers plus anciens qu'un nombre spécifié de jours. Si cette valeur est définie sur un nombre positif de jours, les fichiers seront supprimés lorsqu'ils auront été dans le panier pendant cette durée. Définir cette valeur à zéro empêche la suppression automatique de tout fichier du panier.

GESTION DES VERSIONS DE FICHIERS SIMPLE

Avec la «Gestion des versions de fichiers Simple», les fichiers sont déplacés vers le dossier .stversions lorsqu'ils sont remplacés ou supprimés sur un appareil distant. En plus de l'option cleanoutDays, cette stratégie prend également une valeur dans un champ intitulé «Conserver les versions» qui indique à Syncthing combien d'anciennes versions du fichier il doit conserver. Par exemple, si vous définissez cette valeur à 5, si un fichier est remplacé 5 fois sur un appareil distant, vous verrez 5 versions horodatées de ce fichier dans le dossier .stversions sur les autres appareils partageant le même dossier.

GESTION DES VERSIONS DE FICHIERS ALTERNEE

Avec la «Gestion des versions de fichiers Alternée», les fichiers sont également déplacés vers le dossier .stversions lorsqu'ils sont remplacés ou supprimés sur un appareil distant (tout comme la «Gestion des versions de fichiers Simple»), cependant, les versions sont automatiquement supprimées si elles sont plus anciennes que l'âge maximum ou dépassent le nombre de fichiers autorisés dans un intervalle.

Les intervalles suivants sont utilisés et chacun d'eux a un nombre maximum de fichiers qui seront conservés pour chacun.

1 Heure
Pendant la première heure, la version la plus ancienne de chaque intervalle de 30 secondes est conservée.
1 Jour
Pendant le premier jour, la version la plus ancienne de chaque heure est conservée.
30 Jours
Pendant les 30 premiers jours, la version la plus ancienne de chaque jour est conservée.
Jusqu'à l'âge maximum
Jusqu'à l'âge maximum, la version la plus ancienne de chaque semaine est conservée.
Âge maximum
Le temps maximum de conservation d'une version en jours. Par exemple, pour conserver les fichiers remplacés ou supprimés dans le dossier .stversions pendant une année entière, utilisez 365. Si ce n'est que pour 10 jours, utilisez 10. Correspond à l'option maxAge. Remarque : Définissez à 0 pour conserver les versions indéfiniment.

Cela signifie qu'il n'y a qu'une seule version dans chaque intervalle et que, lorsque les fichiers vieillissent, ils sont supprimés, sauf lorsque l'intervalle qu'ils rejoignent est vide. En conservant les versions les plus anciennes, ce schéma de gestion des versions préserve le fichier s'il est écrasé.

GESTION DES VERSIONS DE FICHIERS EXTERNE

Cette stratégie de gestion des versions délègue la décision sur ce qu'il faut faire à une commande externe (par exemple, un programme ou un script en ligne de commande). Juste avant qu'un fichier ne soit remplacé, la commande sera exécutée. Le fichier doit être supprimé du dossier dans ce processus, sinon Syncthing signalera une erreur. La commande peut utiliser les arguments de modèle suivants :

%FOLDER_PATH%
Chemin du dossier
%FILE_PATH%
Chemin du fichier dans le dossier

Notez que le premier représente le chemin du dossier Syncthing réel, et le second le chemin à l'intérieur de ce dossier. Par exemple, si vous utilisez le dossier Sync par défaut sous Windows, et que le chemin complet du fichier est C:\Users\User\Sync\Photos de famille\IMG_2021-03-01.jpg, alors %FOLDER_PATH% sera C:\Users\User\Sync, et %FILE_PATH% sera Photos de famille\IMG_2021-03-01.jpg.

Exemple pour les systèmes Unix

Disons que je veux conserver la dernière version de chaque fichier lorsqu'ils sont remplacés ou supprimés ; en gros, je veux un comportement similaire à un «panier». Pour cela, je crée le script suivant et je le stocke sous le nom /Users/jb/bin/onlylatest.sh (c'est-à-dire le répertoire bin dans mon répertoire personnel) :

#!/bin/sh
set -eu
# Où je veux que mes versions soient stockées
versionspath=~/.trashcan
# Les paramètres que nous recevons de Syncthing
folderpath="$1"
filepath="$2"
# Assurez d'abord que le répertoire où nous devons stocker le fichier existe
outpath=$(dirname "$versionspath/$filepath")
mkdir -p "$outpath"
# Ensuite, déplacez le fichier là-bas
mv -f "$folderpath/$filepath" "$versionspath/$filepath"

Je dois m'assurer que le script a les permissions d'exécution (chmod 755 onlylatest.sh), puis configurer Syncthing avec la commande /Users/jb/bin/onlylatest.sh %FOLDER_PATH% %FILE_PATH%

Supposons que j'aie un dossier «default» dans ~/Sync, et qu'à l'intérieur de ce dossier se trouve un fichier docs/letter.txt qui est remplacé ou supprimé. Le script sera appelé comme si je l'exécutais depuis la ligne de commande :

$ /Users/jb/bin/onlylatest.sh /Users/jb/Sync docs/letter.txt

Le script déplacera alors le fichier en question vers ~/.trashcan/docs/letter.txt, remplaçant toute version précédente de cette lettre qui aurait déjà pu s'y trouver.

Exemples pour Windows

Déplacer vers un dossier donné en utilisant l'invite de commande (CMD)

Sous Windows, nous pouvons utiliser un script batch pour effectuer le même comportement de type «panier» que mentionné ci-dessus. J'ai créé le script suivant et je l'ai enregistré sous le nom C:\Users\mfrnd\Scripts\onlylatest.bat.

@echo off
rem Activer l'encodage UTF-8 pour gérer les noms de dossiers et de fichiers multilingues
chcp 65001
rem Nous avons besoin d'extensions de commande pour que md crée des dossiers intermédiaires en une seule fois
setlocal enableextensions
rem Où je veux que mes versions soient stockées
set "versions_path=%USERPROFILE%\.trashcan"
rem Les paramètres que nous recevons de Syncthing, '~' supprime les guillemets s'il y en a
set "folder_path=%~1"
set "file_path=%~2"
rem Assurez d'abord que le répertoire où nous devons stocker le fichier existe
for %%f in ("%versions_path%\%file_path%") do set "output_path=%%~dpf"
if not exist "%output_path%" md "%output_path%" || exit /b
rem Enfin, déplacez le fichier, écrasez le fichier existant s'il y en a un
move /y "%folder_path%\%file_path%" "%versions_path%\%file_

syncthing - gestionnaire de fichiers en versionnage Syncthing

VERSIONNAGE DE FICHIERS PAR LA CORBEILLE

Cette méthode permet de désigner un répertoire où les anciens fichiers seront stockés, une fois qu'ils sont remplacés par de nouvelles versions. La corbeille de Syncthing se compose des sous-répertoires suivants :

corbeille/
  ├── 2019-01-01_12-00-00/
  │   └── fichier.txt
  ├── 2019-01-01_12-05-00/
  │   └── fichier.txt
  ├── 2019-01-01_12-10-00/
  │   └── fichier.txt
  └── VERSION

Le répertoire est créé en utilisant le temps de la dernière modification comme nom de sous-répertoire. Si un fichier est modifié plusieurs fois en l'espace de quelques secondes, il est possible qu’une seule version soit sauvegardée.

Les paramètres cleanoutDays et keep sont utilisés pour nettoyer la corbeille. Les fichiers plus anciens que la date spécifiée par cleanoutDays sont supprimés. S’il y a plus de versions que celles spécifiées par keep, les plus anciennes sont supprimées.

Il est également possible de configurer Syncthing pour envoyer des fichiers supprimés à la corbeille du système d’exploitation. Ceci peut être fait en configurant un script à lancer une fois qu’un fichier est supprimé.

Le script suivant est un exemple de script de lot Windows qui peut être utilisé pour déplacer un fichier vers la corbeille :

@echo off
REM Move to Recycle Bin using the RecycleBin utility.
REM You can download it from: https://github.com/andralex/RecycleBin
REM
REM Usage: onlylatest.bat <folder_path> <file_path>
REM Example: C:\Users\mfrnd\Scripts\onlylatest.bat "C:\Users\mfrnd\Documents" "Documents\New Text Document.txt"
REM
REM This will move the specified file to the recycle bin.
REM Be aware that if the recycle bin is disabled or if the folder is on a removable
REM drive, the file will be permanently deleted.

REM Check if recycle bin utility exists
if not exist "%~dp0RecycleBin.exe" (
    echo RecycleBin.exe not found in %~dp0. Please download it from https://github.com/andralex/RecycleBin
    exit /b 1
)

REM Construct the full path to the file
set "FULL_FILE_PATH=%~1\%~2"

REM Check if the file exists
if not exist "%FULL_FILE_PATH%" (
    echo File not found: %FULL_FILE_PATH%
    exit /b 1
)

REM Move the file to the recycle bin
"%~dp0RecycleBin.exe" -d "%FULL_FILE_PATH%"

REM Check if the move was successful
if %errorlevel% equ 0 (
    echo Moved "%FULL_FILE_PATH%" to Recycle Bin.
) else (
    echo Failed to move "%FULL_FILE_PATH%" to Recycle Bin. Error code: %errorlevel%
)
exit /b %errorlevel%

Enfin, j'ai défini "C:\Users\mfrnd\Scripts\onlylatest.bat" "%FOLDER_PATH%" "%FILE_PATH%" comme nom de commande dans Syncthing.

Déplacer vers la corbeille en utilisant PowerShell

Nous pouvons utiliser PowerShell pour envoyer des fichiers directement à la corbeille, ce qui imite le comportement de suppression à l'aide de l'Explorateur Windows. Tout d'abord, créez le script suivant et enregistrez-le à l'emplacement de votre choix, par exemple C:\Users\User\Scripts\SendToRecycleBin.ps1.

# PowerShell n'a pas de méthode native pour recycler les fichiers, nous utilisons donc
# Visual Basic pour effectuer l'opération. En cas de succès, nous incluons également
# le fichier recyclé dans la sortie DEBUG de Syncthing.
Add-Type -AssemblyName Microsoft.VisualBasic
[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','SendToRecycleBin')
if ($?) {
  Write-Output ("Recyclé " + $args + ".")
}

Alternativement, le script peut être étendu pour envoyer uniquement les fichiers supprimés à la corbeille, et supprimer définitivement les fichiers modifiés, ce qui le rend plus cohérent avec le fonctionnement de l'Explorateur.

# PowerShell n'a pas de méthode native pour recycler les fichiers, nous utilisons donc
# Visual Basic pour effectuer l'opération.
Add-Type -AssemblyName Microsoft.VisualBasic
# Nous devons tester si un fichier temporaire .tmp de Syncthing existe. Si c'est le cas, nous supposons
# une modification et supprimons le fichier existant. S'il n'existe pas, nous supposons
# une suppression et recyclons le fichier actuel. En cas de succès, nous incluons également
# le fichier supprimé/recyclé dans la sortie DEBUG de Syncthing.
if (Test-Path -LiteralPath ((Split-Path -Path $args) + "\~syncthing~" + (Split-Path -Path $args -Leaf) + ".tmp")) {
  [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','DeletePermanently')
  if ($?) {
    Write-Output ("Supprimé " + $args + ".")
  }
} else {
  [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','SendToRecycleBin')
  if ($?) {
    Write-Output ("Recyclé " + $args + ".")
  }
}

Enfin, nous définissons le nom de la commande dans Syncthing sur powershell.exe -ExecutionPolicy Bypass -File "C:\Users\User\Scripts\SendToRecycleBin.ps1" "%FOLDER_PATH%\%FILE_PATH%".

La seule mise en garde dont vous devriez être conscient est que si votre dossier Syncthing est situé sur un support de stockage portable, tel qu'une clé USB, ou si vous avez désactivé la corbeille, le script finira par supprimer tous les fichiers de manière permanente.

RÉFÉRENCE DES PARAMÈTRES DE CONFIGURATION

Les paramètres de versionnage sont regroupés dans leur propre section de chaque dossier dans le fichier de configuration. L'exemple suivant montre une telle section en XML :

<folder id="...">
    <versioning type="simple">
        <cleanupIntervalS>3600</cleanupIntervalS>
        <fsPath></fsPath>
        <fsType>basic</fsType>
        <param key="cleanoutDays" val="0"></param>
        <param key="keep" val="5"></param>
    </versioning>
</folder>
versioning.type
Sélectionne l'une des stratégies de versionnage : trashcan, simple, staggered, external ou laisse vide pour désactiver complètement le versionnage.
versioning.fsPath
Remplace le chemin où les anciennes versions des fichiers sont stockées et prend par défaut .stversions si laissé vide. Un chemin absolu ou relatif peut être spécifié. Ce dernier est interprété par rapport au chemin du dossier partagé, si fsType est configuré sur basic. Ignoré pour la stratégie de versionnage external.

Cette option était auparavant stockée sous les clés fsPath ou versionsPath dans l'élément params.

versioning.fsType
L'implémentation du système de fichiers interne utilisée pour accéder à ce dossier de versions. S'applique uniquement si fsPath est également défini comme non vide, sinon le filesystemType de l'élément folder est utilisé à la place. Se référer à la description de cette option pour les valeurs possibles. Ignoré pour la stratégie de versionnage external.

Cette option était auparavant stockée sous la clé fsType dans l'élément params.

versioning.cleanupIntervalS
L'intervalle, en secondes, pour le nettoyage dans le dossier des versions. Zéro pour désactiver le nettoyage périodique. Limité à un an (31536000 secondes). Ignoré pour la stratégie de versionnage external.

Cette option était auparavant stockée sous la clé cleanInterval dans l'élément params.

versioning.params
Chaque stratégie de versionnage peut avoir des paramètres de configuration spécifiques à son implémentation sous cet élément.
versioning.params.cleanoutDays
Le nombre de jours pendant lesquels garder les fichiers dans le dossier des versions. Zéro signifie garder indéfiniment. Les éléments plus anciens rencontrés lors du nettoyage sont supprimés.
versioning.params.keep
Le nombre d'anciennes versions à conserver, par fichier.
versioning.params.maxAge
Le temps maximum pendant lequel conserver une version, en secondes. Zéro signifie conserver indéfiniment.
versioning.params.command
Commande externe à exécuter pour stocker un fichier versionné sur le point d'être remplacé ou supprimé. Si le chemin vers l'application contient des espaces, il doit être mis entre guillemets.
