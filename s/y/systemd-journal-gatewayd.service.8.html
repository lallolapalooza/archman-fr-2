SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8) systemd-journal-gatewayd.service SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8)

NOM

systemd-journal-gatewayd.service, systemd-journal-gatewayd.socket, systemd-journal-gatewayd - Serveur HTTP pour les événements du journal

SYNOPIS

systemd-journal-gatewayd.service

systemd-journal-gatewayd.socket

/usr/lib/systemd/systemd-journal-gatewayd [OPTIONS...]

DESCRIPTION

systemd-journal-gatewayd sert les événements du journal sur le réseau. Les clients doivent se connecter via HTTP. Le serveur écoute sur le port 19531 par défaut. Si --cert= est spécifié, le serveur attend des connexions HTTPS.

Le programme est démarré par systemd(1) et attend de recevoir un seul socket. Utilisez systemctl start systemd-journal-gatewayd.socket pour démarrer le service, et systemctl enable systemd-journal-gatewayd.socket pour qu'il démarre au démarrage.

OPTIONS

Les options suivantes sont comprises :

--cert=

Spécifiez le chemin vers un fichier ou un socket de flux AF_UNIX pour lire le certificat du serveur. Le certificat doit être au format PEM. Cette option bascule systemd-journal-gatewayd en mode HTTPS et doit être utilisée avec --key=.

Ajouté en version 198.

--key=

Spécifiez le chemin vers un fichier ou un socket de flux AF_UNIX pour lire la clé secrète du serveur correspondant au certificat spécifié avec --cert=. La clé doit être au format PEM.

Ajouté en version 198.

--trust=

Spécifiez le chemin vers un fichier ou un socket de flux AF_UNIX pour lire un certificat d'autorité de certification (CA). Le certificat doit être au format PEM.

Ajouté en version 236.

--system, --user

Limiter les entrées servies aux entrées des services système et du noyau, ou aux entrées des services de l'utilisateur courant. Ceci a la même signification que les options --system et --user de journalctl(1). Si aucune des deux n'est spécifiée, toutes les entrées accessibles sont servies.

Ajouté en version 249.

-m, --merge

Servir les entrées entrelacées de tous les journaux disponibles, y compris ceux des autres machines. Ceci a la même signification que l'option --merge de journalctl(1).

Ajouté en version 249.

-D DIR, --directory=DIR

Prend un chemin de répertoire comme argument. Si spécifié, systemd-journal-gatewayd servira le répertoire de journal spécifié DIR au lieu des chemins par défaut du journal runtime et système.

Ajouté en version 232.

--file=GLOB

Prend un motif de fichier (glob) comme argument. Sert les entrées des fichiers de journal spécifiés correspondant à GLOB au lieu des chemins par défaut du journal runtime et système. Peut être spécifié plusieurs fois, auquel cas les fichiers seront entrelacés de manière appropriée. Ceci a la même signification que l'option --file= de journalctl(1).

Ajouté en version 249.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

URL SUPPORTÉES

Les URL suivantes sont reconnues :

/boots

Retourne une réponse json-seq (RFC 7464) contenant des objets JSON, chacun contenant le numéro de démarrage, son ID, et les horodatages du premier et du dernier message. Les démarrages sont retournés en commençant par le dernier démarrage et utilisent le même schéma que journalctl --list-boots --output json.

Ajouté en version 258.

/browse

Navigation interactive.

Ajouté en version 197.

/entries[?option1&option2=valeur...]

Récupération des événements dans divers formats.

La partie Accept: de l'en-tête HTTP détermine le format. Les valeurs prises en charge sont décrites ci-dessous.

La partie Range: de l'en-tête HTTP détermine la plage d'événements retournés. Les valeurs prises en charge sont décrites ci-dessous.

Les paramètres GET peuvent être utilisés pour modifier les événements renvoyés. Les paramètres pris en charge sont décrits ci-dessous.

Ajouté en version 197.

/machine

Retourne une structure JSON décrivant la machine.

Exemple :

{ "machine_id" : "8cf7ed9d451ea194b77a9f118f3dc446",
  "boot_id" : "3d3c9efaf556496a9b04259ee35df7f7",
  "hostname" : "fedora",
  "os_pretty_name" : "Fedora 19 (Rawhide)",
  "virtualization" : "kvm",
  ...}

Ajouté en version 197.

/fields/NOM_DU_CHAMP

Retourne une liste des valeurs de ce champ présentes dans les journaux.

Ajouté en version 197.

EN-TÊTE ACCEPT

Accept: format

Formats reconnus :

text/plain

Par défaut. Sortie texte de type syslog, une ligne par entrée du journal (comme journalctl --output short).

Ajouté en version 197.

application/json

Les entrées sont formatées comme des structures de données JSON, une par ligne (comme journalctl --output json). Voir Format JSON du journal[1] pour plus d'informations.

Ajouté en version 197.

text/event-stream

Les entrées sont formatées comme des structures de données JSON, encapsulées dans un format adapté aux Server-Sent Events[2] (comme journalctl --output json-sse).

Ajouté en version 229.

application/vnd.fdo.journal

Les entrées sont sérialisées dans un flux binaire (mais majoritairement textuel) adapté aux sauvegardes et au transfert réseau (comme journalctl --output export). Voir Format d'exportation du journal[3] pour plus d'informations.

Ajouté en version 197.

EN-TÊTE RANGE

Range: entries=[curseur][[:num_skip]:[num_entries]]

Range: realtime=[depuis]:[jusqu'à][[:num_skip]:num_entries]

où curseur est une chaîne de curseur, par défaut la première entrée, depuis et jusqu'à sont des horodatages (secondes depuis le 01/01/1970 00:00:00 UTC), num_skip est un entier, num_entries est un entier non signé.

La plage par défaut est tous les événements disponibles.

Si num_skip est négatif et qu'aucun curseur n'est donné, la dernière entrée sera le point de référence.

PARAMÈTRES GET DE L'URL

Les paramètres suivants peuvent être utilisés dans l'URL :

follow

attend les nouveaux événements (comme journalctl --follow, le nombre d'événements retournés n'est pas limité, sauf si num_entries est spécifié dans l'en-tête Range).

Ajouté en version 197.

discrete

Vérifie que le curseur spécifié fait référence à une entrée dans le journal. Retourne uniquement cette entrée.

Ajouté en version 197.

boot

Limite les événements au démarrage actuel du système (comme journalctl -b).

Ajouté en version 197.

CLE=correspondance

Fait correspondre les champs du journal. Voir systemd.journal-fields(7).

Ajouté en version 197.

EXEMPLES

Récupérer les événements de ce démarrage depuis le journal local au format Format d'exportation du journal[3] :

curl --silent -H'Accept: application/vnd.fdo.journal' \
       'http://localhost:19531/entries?boot'

Écouter les vidages de cœur (core dumps) :

curl 'http://localhost:19531/entries?follow&MESSAGE_ID=fc2e22bc6ee647b6b90729ab34a250b1'
