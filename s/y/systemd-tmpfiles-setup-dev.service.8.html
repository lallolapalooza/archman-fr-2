NOM

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer — Créer, supprimer et nettoyer des fichiers et répertoires

SYNTAXE

systemd-tmpfiles [OPTIONS...] [FICHIER_CONFIG...]

Unités système :

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unités utilisateur :

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPTION

systemd-tmpfiles crée, supprime et nettoie des fichiers et répertoires, en utilisant le format de fichier de configuration et l'emplacement spécifiés dans tmpfiles.d(5). Historiquement, il était conçu pour gérer les fichiers volatils et temporaires, comme son nom l'indique, mais il fournit des fonctionnalités génériques de gestion de fichiers et peut être utilisé pour gérer tout type de fichiers. Il doit être appelé avec une ou plusieurs commandes --create, --remove, et --clean, pour sélectionner le sous-ensemble d'opérations respectif.

S'il est appelé sans arguments, les directives des fichiers de configuration trouvés dans les répertoires spécifiés par tmpfiles.d(5) sont exécutées. Lorsqu'il est appelé avec des arguments positionnels, si l'option --replace=CHEMIN est spécifiée, les arguments spécifiés sur la ligne de commande remplacent le CHEMIN du fichier de configuration. Sinon, seule la configuration spécifiée par les arguments de la ligne de commande est exécutée. Si la chaîne de caractères "-" est spécifiée à la place d'un nom de fichier, la configuration est lue depuis l'entrée standard. Si l'argument est un nom de fichier (sans aucune barre oblique), tous les répertoires de configuration sont recherchés pour un fichier correspondant et le fichier trouvé qui a la priorité la plus élevée est exécuté. Si l'argument est un chemin, ce fichier est utilisé directement sans rechercher dans les répertoires de configuration un autre fichier correspondant.

Les services système (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invoquent systemd-tmpfiles pour créer des fichiers système et effectuer un nettoyage à l'échelle du système. Ces services lisent les fichiers de configuration contrôlés par l'administrateur dans les répertoires tmpfiles.d/. Les services utilisateur (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) invoquent également systemd-tmpfiles, mais celui-ci lit un ensemble distinct de fichiers, qui comprend les fichiers contrôlés par l'utilisateur sous ~/.config/user-tmpfiles.d/ et ~/.local/share/user-tmpfiles.d/, et les fichiers contrôlés par l'administrateur sous /usr/share/user-tmpfiles.d/. Les utilisateurs peuvent l'utiliser pour créer et nettoyer des fichiers sous leur contrôle, mais l'instance système effectue un nettoyage global et n'est pas influencée par la configuration utilisateur. Notez qu'une nettoyage basé sur le temps configuré dans l'instance système, comme celui typiquement configuré pour /tmp/, affectera ainsi aussi les fichiers créés par l'instance utilisateur s'ils sont placés dans /tmp/, même si le nettoyage basé sur le temps de l'instance utilisateur est désactivé.

Pour réappliquer les paramètres après que la configuration a été modifiée, redémarrez simplement systemd-tmpfiles-clean.service, ce qui appliquera tous les paramètres qui peuvent être exécutés en toute sécurité pendant l'exécution. Pour déboguer systemd-tmpfiles, il peut être utile de l'invoquer directement depuis la ligne de commande avec un niveau de journalisation augmenté (voir $SYSTEMD_LOG_LEVEL ci-dessous).

COMMANDES ET OPTIONS

Les commandes suivantes sont comprises :

--create

Si cette commande est passée, tous les fichiers et répertoires marqués avec f, F, w, d, D, v, p, L, c, b, m dans les fichiers de configuration sont créés ou écrits. Les fichiers et répertoires marqués avec z, Z, t, T, a, et A ont leur propriétaire, leur mode d'accès et leurs étiquettes de sécurité définis.

--clean

Si cette commande est passée, tous les fichiers et répertoires dont l'âge est configuré seront nettoyés.

--remove

Si cette commande est passée, le contenu des répertoires marqués avec D ou R, et les fichiers ou répertoires eux-mêmes marqués avec r ou R sont supprimés à moins qu'un verrou exclusif ou partagé BSD ne soit pris sur eux (voir flock(2)).

--purge

Si cette option est passée, tous les fichiers et répertoires déclarés pour création et marqués avec le caractère "$" par les fichiers tmpfiles.d/ spécifiés sur la ligne de commande seront supprimés. Plus précisément, cela agit sur tous les fichiers et répertoires marqués avec f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si ce commutateur est utilisé, au moins un fichier tmpfiles.d/ (ou - pour l'entrée standard) doit être spécifié sur la ligne de commande, sinon l'invocation sera refusée, pour des raisons de sécurité (car sinon une grande partie des fichiers système installés pourraient être supprimés).

L'objectif principal de cette option est de supprimer automatiquement les fichiers et répertoires qui ont été initialement créés au nom d'un paquet installé lors de la désinstallation du paquet.

Il est recommandé d'exécuter d'abord cette commande en combinaison avec --dry-run (voir ci-dessous) pour vérifier quels fichiers et répertoires seront supprimés.

Attention ! Ce n'est généralement pas la commande que vous recherchez ! Dans la plupart des cas, --remove est ce que vous recherchez.

Ajouté dans la version 256.

--user

Exécute la configuration "utilisateur", c'est-à-dire les fichiers tmpfiles.d/ dans les répertoires de configuration utilisateur.

Ajouté dans la version 236.

--boot

Exécute également les lignes avec un point d'exclamation. Les lignes qui ne sont pas sûres à exécuter sur un système en cours d'exécution peuvent être marquées de cette façon. systemd-tmpfiles est exécuté au début du démarrage avec --boot spécifié et exécutera ces lignes. Lorsqu'il est appelé à nouveau plus tard, il doit être appelé sans --boot.

Ajouté dans la version 209.

--graceful

Ignore les lignes de configuration relatives aux utilisateurs ou groupes inconnus. Cette option est destinée à être utilisée au début du démarrage avant que tous les utilisateurs ou groupes n'aient été créés.

Ajouté dans la version 254.

--dry-run

Traite la configuration et affiche les opérations qui seraient effectuées, mais ne modifie rien dans le système de fichiers.

Ajouté dans la version 256.

--prefix=chemin

Applique uniquement les règles avec des chemins qui commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 212.

--exclude-prefix=chemin

Ignore les règles avec des chemins qui commencent par le préfixe spécifié. Cette option peut être spécifiée plusieurs fois.

Ajouté dans la version 207.

-E

Raccourci pour "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", c'est-à-dire exclut les hiérarchies généralement soutenues par des systèmes de fichiers virtuels ou en mémoire. Ceci est utile en combinaison avec --root=, si l'arborescence spécifiée contient une arborescence de système d'exploitation sans ces systèmes de fichiers virtuels/en mémoire montés, car il n'est généralement pas souhaitable de créer des fichiers et des répertoires sous ces sous-répertoires s'ils sont censés être surimprimés pendant l'exécution.

Ajouté dans la version 247.

--root=root

Prend un chemin de répertoire comme argument. Tous les chemins seront précédés du chemin root alternatif donné, y compris les chemins de recherche de configuration.

Lorsque cette option est utilisée, le Name Service Switch (NSS) de libc est contourné pour la résolution des utilisateurs et des groupes. Au lieu de cela, les fichiers /etc/passwd et /etc/group dans le root alternatif sont lus directement. Cela signifie que les utilisateurs/groupes non listés dans ces fichiers ne seront pas résolus, c'est-à-dire que les bases de données LDAP NIS et autres bases de données complexes ne sont pas prises en compte.

Envisagez de combiner cela avec -E pour garantir que l'invocation ne crée pas de fichiers ou de répertoires sous des points de montage dans l'image du système d'exploitation sur lesquels on opère qui sont généralement surimprimés pendant l'exécution.

Ajouté dans la version 212.

--imag

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

e=image

Prend un chemin vers un fichier d'image disque ou un nœud de périphérique bloc. Si spécifié, toutes les opérations sont appliquées au système de fichiers de l'image disque indiquée. Ceci est similaire à --root= mais opère sur les systèmes de fichiers stockés dans des images disque ou des périphériques bloc. L'image disque doit soit contenir uniquement un système de fichiers, soit un ensemble de systèmes de fichiers au sein d'une table de partitions GPT, suivant la Discoverable Partitions Specification[1]. Pour plus d'informations sur les images disque prises en charge, voir le commutateur du même nom dans systemd-nspawn(1).

Implique -E.

Ajouté dans la version 247.

--image-policy=politique

Prend une chaîne de politique d'image comme argument, conformément à systemd.image-policy(7). La politique est appliquée lors de l'opération sur l'image disque spécifiée via --image=, voir ci-dessus. Si non spécifié, la politique par défaut est la politique ""*"", c'est-à-dire que tous les systèmes de fichiers reconnus dans l'image sont utilisés.

--replace=CHEMIN

Lorsque cette option est donnée, un ou plusieurs arguments positionnels doivent être spécifiés. Tous les fichiers de configuration trouvés dans les répertoires listés dans tmpfiles.d(5) seront lus, et la configuration donnée sur la ligne de commande sera traitée à la place et avec la même priorité que le fichier de configuration CHEMIN.

Cette option est destinée à être utilisée lorsque les scripts d'installation de paquets sont en cours d'exécution et que les fichiers appartenant à ce paquet ne sont pas encore disponibles sur disque, de sorte que leur contenu doit être donné sur la ligne de commande, mais la configuration de l'administrateur peut déjà exister et devrait recevoir une priorité plus élevée.

Ajouté dans la version 238.

--cat-config

Copie le contenu des fichiers de configuration sur la sortie standard. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--tldr

Copie le contenu des fichiers de configuration sur la sortie standard. Seules les parties "intéressantes" des fichiers de configuration sont imprimées, les commentaires et les lignes vides sont ignorés. Avant chaque fichier, le nom du fichier est imprimé sous forme de commentaire.

--no-pager

Ne pas rediriger la sortie vers un pagineur.

-h, --help

Affiche un court texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

Il est possible de combiner --create, --clean et --remove en une seule invocation (auquel cas la suppression et le nettoyage sont exécutés avant la création de nouveaux fichiers). Par exemple, au démarrage, la ligne de commande suivante est exécutée pour s'assurer que tous les répertoires temporaires et volatils sont supprimés et créés selon le fichier de configuration :

systemd-tmpfiles --remove --create

IDENTIFIANTS

systemd-tmpfiles prend en charge la logique des identifiants de service telle qu'implémentée par ImportCredential=/LoadCredential=/SetCredential= (voir systemd.exec(5) pour les détails). Les identifiants suivants sont utilisés lorsqu'ils sont passés :

tmpfiles.extra

Le contenu de cet identifiant peut contenir des lignes supplémentaires à traiter. Le contenu de l'identifiant doit suivre le même format que tout autre fichier de configuration drop-in tmpfiles.d/. Si cet identifiant est passé, il est traité après tous les fichiers drop-in lus à partir du système de fichiers. Les lignes de l'identifiant peuvent donc augmenter les lignes existantes du système d'exploitation, mais ne pas les remplacer.

Ajouté dans la version 252.

Notez que par défaut, le fichier d'unité systemd-tmpfiles-setup.service (et les fichiers d'unité associés) est configuré pour hériter de l'identifiant "tmpfiles.extra" du gestionnaire de service.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximum des messages émis (les messages avec un niveau de journalisation plus élevé, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'un des éléments suivants : console, syslog, kmsg ou journal suivi d'un deux-points pour définir le niveau de journalisation maximum pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug, sauf lors de la journalisation sur la console qui devrait être au niveau info). Notez que le niveau de journalisation maximum global a la priorité sur tous les niveaux de journalisation maximum par cible.

$SYSTEMD_LOG_COLOR

Un booléen. Si vrai, les messages écrits sur le tty seront colorés en fonction de la priorité.

Ce paramètre n'est utile que lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. Si vrai, les messages de journalisation de la console seront préfixés par un horodatage.

Ce paramètre n'est utile que lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux ajouteront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. Si vrai, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent attaché en tant que métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des valeurs suivantes : console (journaliser sur le tty connecté), console-prefixed (journaliser sur le tty connecté mais avec des préfixes codant le niveau de journalisation et la "facilité", voir syslog(3), kmsg (journaliser dans le tampon de journal circulaire du noyau), journal (journaliser dans le journal), journal-or-kmsg (journaliser dans le journal si disponible, et dans kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie de journalisation).

$SYSTEMD_PAGER, $PAGER

Pagineur à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de pagineurs bien connues est essayé en séquence, y compris less(1) et more(1), jusqu'à ce qu'un soit trouvé. Si aucune implémentation de pagineur n'est découverte, aucun pagineur n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur "cat" est équivalent à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le pagineur (avec "cat" ou "") et sont par ailleurs ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs pourraient vouloir changer deux options en particulier :

K

Cette option demande au pagineur de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même pour revenir à l'invite de commande du pagineur, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas "K", et que le pagineur invoqué est less, Ctrl+C sera ignoré par l'exécutable et devra être géré par le pagineur.

X

Cette option demande au pagineur de ne pas envoyer les chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du pagineur. Néanmoins, cela empêche certaines fonctionnalités du pagineur de fonctionner, en particulier la sortie paginée ne peut pas être défilée avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet pour les invocations de less par les outils systemd.

Voir less(1) pour plus de discussions.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut "utf-8", si le terminal appelant est déterminé comme compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet pour les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pagineur courantes comme less(1), en plus de la "pagination", c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque les commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pagineur devient une frontière de sécurité. Des précautions doivent être prises pour que seuls des programmes aux fonctionnalités strictement limitées soient utilisés comme pagineurs, et que les fonctionnalités interactives indésirables comme l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le "mode sécurisé" pour le pagineur peut être activé comme décrit ci-dessous, si le pagineur le prend en charge (la plupart des pagineurs ne sont pas écrits de manière à en tenir compte). Il est recommandé soit d'activer explicitement le "mode sécurisé", soit de désactiver complètement le pagineur en utilisant --no-pager ou PAGER=cat lors de l'autorisation d'utilisateurs non fiables à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur vrai, le "mode sécurisé" du pagineur est activé. En "mode sécurisé", LESSSECURE=1 sera défini lors de l'invocation du pagineur, ce qui demande au pagineur de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou lancent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le "mode sécurisé".

Lorsqu'elle est définie sur faux, aucune limitation n'est imposée au pagineur. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le "mode sécurisé" doit être activé et si le pagineur le prend en charge. Le "mode sécurisé" est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution soussudo(8) ou des outils similaires ($SUDO_UID est défini [2]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagers qui ne sont pas connus pour implémenter un « mode sécurisé » ne seront pas du tout utilisés. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à des fins de commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pager.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être respectées, autre que pour désactiver le pager, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Accepte un argument booléen. Si vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : « 16 », « 256 » pour restreindre l'utilisation des couleurs aux 16 ou 256 couleurs ANSI de base, respectivement. Ceci peut être spécifié pour outrepasser la décision automatique basée sur $TERM et ce à quoi la console est connectée.

$SYSTEMD_URLIFY

La valeur doit être un booléen. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminaux qui le prennent en charge. Ceci peut être spécifié pour outrepasser la décision que systemd prend en fonction de $TERM et d'autres conditions.

OPÉRATION DE NETTOYAGE NON PRIVILÉGIÉE

systemd-tmpfiles essaie d'éviter de modifier les heures d'accès et de modification des répertoires qu'il parcourt, ce qui nécessite les privilèges CAP_FOWNER. Lorsqu'il s'exécute en tant qu'utilisateur non -root, les répertoires qui sont vérifiés pour trouver des fichiers à nettoyer verront leur heure d'accès incrémentée, ce qui pourrait empêcher leur nettoyage.

STATUT DE SORTIE

En cas de succès, 0 est retourné. Si la configuration était syntaxiquement invalide (erreurs de syntaxe, arguments manquants, ...), de sorte que certaines lignes ont dû être ignorées, mais qu'aucune autre erreur ne s'est produite, 65 est retourné (EX_DATAERR de /usr/include/sysexits.h). Si la configuration était syntaxiquement valide, mais n'a pas pu être exécutée (manque de permissions, création de fichiers dans des répertoires manquants, contenus invalides lors de l'écriture dans les valeurs /sys/, ...), 73 est retourné (EX_CANTCREAT de /usr/include/sysexits.h). Sinon, 1 est retourné (EXIT_FAILURE de /usr/include/stdlib.h).

Note : lors de la création d'éléments, si la cible existe déjà, mais est du mauvais type ou ne correspond pas autrement à l'état demandé, et que l'opération forcée n'a pas été demandée avec « + », un message est émis, mais l'échec est autrement ignoré.
