syslog-ng-ctl(1) Manuel de l'outil de contrôle syslog-ng OSE syslog-ng-ctl(1)

NOM

syslog-ng-ctl --- Affiche les statistiques de messages et active les modes verbeux, de débogage et de trace dans {{ site.product.short_name }}

Synopsis

syslog-ng-ctl [commande] [options]

Description

NOTE : L'application syslog-ng-ctl est distribuée avec l'application de journalisation système syslog-ng OSE et fait généralement partie du paquet syslog-ng OSE. La dernière version de l'application syslog-ng OSE est disponible sur la page syslog-ng OSE.

Cette page de manuel est seulement un résumé.

L'application syslog-ng-ctl est un utilitaire qui peut être utilisé pour :

  • activer/désactiver divers messages de syslog-ng OSE pour le dépannage
  • afficher les statistiques sur les messages traités
  • gérer les clés privées protégées par mot de passe
  • afficher la configuration en cours d'exécution de syslog-ng OSE
  • recharger la configuration de syslog-ng OSE.

Activation des messages de dépannage

commande [options]

Utilisez la commande syslog-ng-ctl <commande> --set=on pour afficher les messages verbeux, de trace ou de débogage. Si vous essayez de résoudre des problèmes de configuration, les messages verbeux (et occasionnellement les messages de trace) sont généralement suffisants. Les messages de débogage sont principalement nécessaires pour trouver des erreurs logicielles. Après avoir résolu le problème, n'oubliez pas de désactiver ces messages en utilisant syslog-ng-ctl <commande> --set=off. Notez que l'activation des messages de débogage n'active pas les messages verbeux et de trace.

Utilisez syslog-ng-ctl <commande> sans aucun paramètre pour afficher si le type de messages particulier est activé ou non.

Si vous avez besoin d'utiliser un socket de contrôle non standard pour accéder à syslog-ng OSE, utilisez la commande syslog-ng-ctl <commande> --set=on --control=<socket> pour spécifier le socket à utiliser.

•
verbose

Affiche les messages verbeux. Si syslog-ng OSE a été démarré avec l'option --stderr ou -e, les messages seront envoyés à stderr. Si non spécifié, syslog-ng OSE enregistrera ces messages dans sa source interne.

•
trace

Affiche les messages de trace sur la manière dont les messages sont traités. Si syslog-ng OSE a été démarré avec l'option --stderr ou -e, les messages seront envoyés à stderr. Si non spécifié, syslog-ng OSE enregistrera ces messages dans sa source interne.

•
debug

Affiche les messages de débogage. Si syslog-ng OSE a été démarré avec l'option --stderr ou -e, les messages seront envoyés à stderr. Si non spécifié, syslog-ng OSE enregistrera ces messages dans sa source interne.

Exemple

syslog-ng-ctl verbose --set=on

syslog-ng-ctl query

L'application syslog-ng OSE stocke diverses données, métriques et statistiques dans une table de hachage. Chaque propriété a un nom et une valeur. Par exemple :

[syslog-ng]
|              
|_[destinations]-[network]-[tcp]->[stats]->{received=12;dropped=2}
|
|_[sources]-[sql]-[stats]->{received=501;dropped=0}

Vous pouvez interroger les nœuds de cet arbre, et également utiliser des filtres pour sélectionner les informations dont vous avez besoin. Une requête est en réalité un chemin dans l'arbre. Vous pouvez également utiliser les caractères génériques ? et *. Par exemple :

  • Sélectionne toutes les propriétés : *
  • Sélectionne toutes les valeurs 'dropped' de tous les nœuds 'stats' : *.stats.dropped

Les nœuds et propriétés disponibles dans l'arbre dépendent de votre configuration syslog-ng OSE (c'est-à-dire les sources, les destinations et les autres objets que vous avez configurés), ainsi que de vos paramètres stats-level().

La commande list

syslog-ng-ctl query list

Utilisez la commande syslog-ng-ctl query list pour afficher la liste des métriques que syslog-ng OSE collecte sur les messages traités.

La commande syslog-ng-ctl query list a les options suivantes :

•
--reset

Utilisez --reset pour mettre les compteurs sélectionnés à 0 après l'exécution de la requête.

Affichage des métriques et des statistiques

syslog-ng-ctl query get [options]

La commande syslog-ng-ctl query get <requête> liste les nœuds qui correspondent à la requête, et leurs valeurs.

Par exemple, la requête 'destination' liste les destinations configurées, et les métriques associées à chaque destination. Un exemple de sortie :

destination.d_elastic.stats.processed=0

La commande syslog-ng-ctl query get a les options suivantes :

•
--sum

Additionne le résultat de chaque nœud correspondant et renvoie un seul nombre.

Par exemple, la commande syslog-ng-ctl query get --sum \"destination*.dropped\" affiche le nombre de messages abandonnés par l'instance syslog-ng OSE.

•
--reset

Utilisez --reset pour mettre les compteurs sélectionnés à 0 après l'exécution de la requête.

La commande stats

stats [options]

Utilisez la commande stats pour afficher les statistiques sur les messages traités. Pour plus de détails sur les statistiques affichées, voir le Guide d'Administration de syslog-ng OSE. La commande stats a les options suivantes :

•
--control=<socket> ou -c

Spécifie le socket à utiliser pour accéder à syslog-ng PE. Nécessaire uniquement lorsque vous utilisez un socket non standard.

•
--reset=<socket> ou -r

Réinitialise toutes les statistiques à zéro, à l'exception des compteurs de mise en file d'attente. (Les compteurs de mise en file d'attente indiquent le nombre de messages dans la file d'attente de messages du pilote de destination, en attente d'être envoyés à la destination.)

•
--remove-orphans

Supprime en toute sécurité tous les compteurs qui ne sont référencés par aucun objet producteur de statistiques syslog-ng.

Le drapeau peut être utilisé pour élaguer manuellement les compteurs dynamiques et statiques. Ceci est utile, par exemple, lorsqu'une destination de fichier avec modèle produit beaucoup de statistiques :

dst.file;#anon-destination0#0;/tmp/2021-08-16.log;o;processed;253592 dst.file;#anon-destination0#0;/tmp/2021-08-17.log;o;processed;156 dst.file;#anon-destination0#0;/tmp/2021-08-18.log;a;processed;961

NOTE : stats(lifetime()) peut être utilisé pour faire la même chose automatiquement et périodiquement, mais actuellement stats(lifetime()) ne supprime que les compteurs dynamiques qui

n’a pas de champ d’horodatage défini.

Gestion des clés privées protégées par mot de passe

syslog-ng-ctl credentials [options]

La commande syslog-ng-ctl credentials status permet d’interroger l’état des clés privées utilisées par syslog-ng OSE dans les pilotes network() et syslog(). Vous pouvez également fournir la phrase secrète pour les clés privées protégées par mot de passe en utilisant la commande syslog-ng-ctl credentials add. Pour plus de détails sur l’utilisation des clés protégées par mot de passe, consultez le Guide d’administration de syslog-ng OSE.

Affichage de l’état des clés privées

syslog-ng-ctl credentials status [options]

La commande syslog-ng-ctl credentials status permet d’interroger l’état des clés privées utilisées par syslog-ng OSE dans les pilotes network() et syslog(). La commande renvoie la liste des clés privées utilisées et leur état. Par exemple :

syslog-ng-ctl credentials status
État du magasin secret : /home/user/ssl_test/client-1/client-encrypted.key SUCCÈS

Si l’état d’une clé est PENDING, vous devez fournir la phrase secrète de la clé, sinon syslog-ng OSE ne pourra pas l’utiliser. Les sources et les destinations qui utilisent ces clés ne fonctionneront pas tant que vous n’aurez pas fourni les mots de passe. Les autres parties de la configuration de syslog-ng OSE ne seront pas affectées. Vous devez fournir la phrase secrète des clés protégées par mot de passe à chaque redémarrage de syslog-ng OSE.

Le message de journal suivant vous informe également des phrases secrètes PENDING :

Attente du mot de passe ; keyfile='private.key'
•
--control=<socket> ou -c

Spécifie le socket à utiliser pour accéder à syslog-ng OSE. Uniquement nécessaire lors de l’utilisation d’un socket non standard.

Ouverture des clés privées protégées par mot de passe

syslog-ng-ctl credentials add [options]

Vous pouvez ajouter la phrase secrète à un fichier de clé privée protégé par mot de passe en utilisant la commande suivante. syslog-ng OSE vous demandera d’entrer la phrase secrète. Nous vous recommandons d’utiliser cette méthode.

syslog-ng-ctl credentials add --id=<chemin-vers-la-clé>

Alternativement, vous pouvez inclure la phrase secrète dans le paramètre --secret :

syslog-ng-ctl credentials add --id=<chemin-vers-la-clé> --secret=<phrase-secrète-de-la-clé>

Ou vous pouvez rediriger la phrase secrète vers la commande syslog-ng-ctl, par exemple :

echo "<phrase-secrète-de-la-clé>" | syslog-ng-ctl credentials add --id=<chemin-vers-la-clé>
•
--control=<socket> ou -c

Spécifie le socket à utiliser pour accéder à syslog-ng PE. Uniquement nécessaire lors de l’utilisation d’un socket non standard.

•
--id=<chemin-vers-la-clé> ou -i

Le chemin d’accès au fichier de clé privée protégé par mot de passe. C’est le même chemin que celui que vous utilisez dans l’option key-file() du fichier de configuration de syslog-ng OSE.

•
--secret=<phrase-secrète-de-la-clé> ou -s

Le mot de passe ou la phrase secrète de la clé privée.

Affichage de la configuration

syslog-ng-ctl config [options]

Utilisez la commande syslog-ng-ctl config pour afficher la configuration avec laquelle syslog-ng OSE s’exécute actuellement. Notez que par défaut, seul le contenu du fichier de configuration principal est affiché, les fichiers inclus ne sont pas résolus. Pour résoudre les fichiers inclus et afficher la configuration complète, utilisez la commande syslog-ng-ctl config --preprocessed.

Rechargement de la configuration

syslog-ng-ctl reload [options]

Utilisez la commande syslog-ng-ctl reload pour recharger le fichier de configuration de syslog-ng OSE sans avoir à redémarrer l’application syslog-ng OSE. La commande syslog-ng-ctl reload fonctionne comme un SIGHUP.

La commande syslog-ng-ctl reload retourne 0 si l’opération a réussi, 1 sinon.
