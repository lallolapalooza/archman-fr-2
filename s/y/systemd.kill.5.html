NOM

systemd.kill - Configuration de la procédure d'arrêt des processus

SYNTAXE

service.service, socket.socket, mount.mount, swap.swap, scope.scope

DESCRIPTION

Les fichiers de configuration d'unités pour les services, sockets, points de montage, périphériques swap et scopes partagent un sous-ensemble d'options de configuration qui définissent la procédure d'arrêt des processus appartenant à l'unité.

Cette page de manuel liste les options de configuration partagées par ces cinq types d'unités. Voir systemd.unit(5) pour les options communes partagées par tous les fichiers de configuration d'unités, et systemd.service(5), systemd.socket(5), systemd.swap(5), systemd.mount(5) et systemd.scope(5) pour plus d'informations sur les options de configuration spécifiques à chaque type d'unité.

Les options de configuration de la procédure d'arrêt sont configurées dans la section [Service], [Socket], [Mount] ou [Swap], en fonction du type d'unité.

OPTIONS

KillMode=

Spécifie comment les processus de cette unité doivent être arrêtés. L'une des valeurs suivantes : control-group, mixed, process, none.

Si réglé sur control-group, tous les processus restants dans le groupe de contrôle de cette unité seront arrêtés lors de l'arrêt de l'unité (pour les services : après l'exécution de la commande d'arrêt, configurée avec ExecStop=). Si réglé sur mixed, le signal SIGTERM (voir ci-dessous) est envoyé au processus principal, tandis que le signal SIGKILL ultérieur (voir ci-dessous) est envoyé à tous les processus restants du groupe de contrôle de l'unité. Si réglé sur process, seul le processus principal lui-même est arrêté (non recommandé !). Si réglé sur none, aucun processus n'est arrêté (fortement déconseillé !). Dans ce cas, seule la commande d'arrêt sera exécutée lors de l'arrêt de l'unité, mais aucun processus ne sera arrêté par ailleurs. Les processus restant actifs après l'arrêt sont laissés dans leur groupe de contrôle et le groupe de contrôle continue d'exister après l'arrêt s'il n'est pas vide.

Il est déconseillé de régler KillMode= sur process ou même none, car cela permet aux processus d'échapper à la gestion du cycle de vie et des ressources du gestionnaire de services, et de rester en cours d'exécution même lorsque leur service est considéré comme arrêté et qu'il est supposé ne consommer aucune ressource.

Les processus seront d'abord terminés via SIGTERM (sauf si le signal à envoyer est modifié via KillSignal= ou RestartKillSignal=). Optionnellement, ceci est immédiatement suivi d'un SIGHUP (si activé avec SendSIGHUP=). Si des processus subsistent après :

•que le processus principal d'une unité a terminé (s'applique à KillMode= : mixed)
•que le délai configuré via TimeoutStopSec= a expiré (s'applique à KillMode= : control-group, mixed, process)

la demande de terminaison est répétée avec le signal SIGKILL ou le signal spécifié via FinalKillSignal= (sauf si cela est désactivé via l'option SendSIGKILL=). Voir kill(2) pour plus d'informations.

Par défaut : control-group.

Ajouté dans la version 187.

KillSignal=

Spécifie quel signal utiliser lors de l'arrêt d'un service. Cela contrôle le signal envoyé comme première étape de l'arrêt d'une unité (voir ci-dessus), et il est généralement suivi de SIGKILL (voir ci-dessus et ci-dessous). Pour une liste des signaux valides, voir signal(7). Par défaut : SIGTERM.

Notez que, juste après l'envoi du signal spécifié dans ce réglage, systemd enverra toujours SIGCONT, afin de s'assurer que même les tâches suspendues puissent être terminées proprement.

Ajouté dans la version 187.

RestartKillSignal=

Spécifie quel signal utiliser lors du redémarrage d'un service. Identique à KillSignal= décrit ci-dessus, à l'exception de ce réglage qui est utilisé dans une tâche de redémarrage. Non défini par défaut, et la valeur de KillSignal= est utilisée.

Ajouté dans la version 244.

SendSIGHUP=

Spécifie s'il faut envoyer SIGHUP aux processus restants immédiatement après l'envoi du signal configuré avec KillSignal=. Ceci est utile pour indiquer aux shells et aux programmes de type shell que leur connexion a été coupée. Prend une valeur booléenne. Par défaut : "no".

Ajouté dans la version 207.

SendSIGKILL=

Spécifie s'il faut envoyer SIGKILL (ou le signal spécifié par FinalKillSignal=) aux processus restants après un délai d'attente, si la procédure d'arrêt normale a laissé des processus du service actifs. Lorsqu'il est désactivé, un KillMode= de control-group ou mixed ne redémarrera pas si des processus des services précédents existent dans le groupe de contrôle. Prend une valeur booléenne. Par défaut : "yes".

Ajouté dans la version 187.

FinalKillSignal=

Spécifie quel signal envoyer aux processus restants après un délai d'attente si SendSIGKILL= est activé. Le signal configuré ici doit être l'un de ceux qui ne sont généralement pas interceptés et traités par les services (SIGTERM n'est pas adapté). Les développeurs peuvent trouver utile de l'utiliser pour générer un core dump afin de diagnostiquer pourquoi un service n'a pas terminé sa tâche après avoir reçu le signal initial SIGTERM. Ceci peut être réalisé en configurant LimitCORE= et en réglant FinalKillSignal= sur SIGQUIT ou SIGABRT. Par défaut : SIGKILL.

Ajouté dans la version 240.

WatchdogSignal=

Spécifie quel signal utiliser pour terminer le service lorsque le délai d'attente du chien de garde expire (activé via WatchdogSec=). Par défaut : SIGABRT.

Ajouté dans la version 240.
