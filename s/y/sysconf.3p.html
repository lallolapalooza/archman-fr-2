NOM

sysconf — obtenir les variables système configurables

SYNOPIS

#include <unistd.h>
long sysconf(int name);

VALEUR DE RETOUR

Si name est une valeur invalide, sysconf() retournera -1 et définira errno pour indiquer l'erreur. Si la variable correspondant à name est décrite dans <limits.h> comme une valeur maximum ou minimum et que la variable n'a pas de limite, sysconf() retournera -1 sans modifier la valeur de errno. Notez que les limites indéfinies n'impliquent pas de limites infinies ; voir <limits.h>.

Sinon, sysconf() retournera la valeur actuelle de la variable sur le système. La valeur retournée ne sera pas plus restrictive que la valeur correspondante décrite à l'application lorsqu'elle a été compilée avec <limits.h> ou <unistd.h> de l'implémentation. La valeur ne changera pas pendant la durée de vie du processus appelant, sauf que sysconf(_SC_OPEN_MAX) peut retourner des valeurs différentes avant et après un appel à setrlimit() qui modifie la limite douce de RLIMIT_NOFILE.

Si la variable correspondant à name dépend d'une option non prise en charge, les résultats ne sont pas spécifiés.

ERREURS

La fonction sysconf() échouera si :

EINVAL
La valeur de l'argument name est invalide.

EXEMPLES

Aucun.

UTILISATION PAR LES APPLICATIONS

Comme -1 est une valeur de retour permissible dans une situation de succès, une application souhaitant vérifier des situations d'erreur devrait initialiser errno à 0, puis appeler sysconf(), et, si elle retourne -1, vérifier si errno est non nul.

Les développeurs d'applications devraient vérifier si une option, telle que _POSIX_TRACE, est prise en charge avant d'obtenir et d'utiliser les valeurs des variables associées, telles que _POSIX_TRACE_NAME_MAX.

RATIONALE

Cette fonctionnalité a été ajoutée en réponse aux exigences des développeurs d'applications et des fournisseurs de systèmes qui traitent de nombreuses configurations système internationales. Elle est étroitement liée à pathconf() et fpathconf().

Bien qu'une application conforme puisse s'exécuter sur tous les systèmes en ne demandant jamais plus de ressources que les valeurs minimales publiées dans ce volume de POSIX.1‐2017, il est utile pour cette application de pouvoir utiliser la valeur réelle de la quantité de ressource disponible sur un système donné. Pour ce faire, l'application utilise la valeur d'une constante symbolique dans <limits.h> ou <unistd.h>.

Cependant, une fois compilée, l'application doit toujours être capable de gérer l'augmentation de la quantité de ressource disponible. À cette fin, une application peut avoir besoin d'un moyen de déterminer la quantité d'une ressource, ou la présence d'une option, au moment de l'exécution.

Deux exemples sont proposés :

1.
Les applications peuvent souhaiter agir différemment sur les systèmes avec ou sans contrôle de travaux. Les fournisseurs d'applications qui souhaitent distribuer un seul paquet binaire à toutes les instances d'une architecture informatique seraient obligés de supposer que le contrôle de travaux n'est jamais disponible s'ils se contentaient de la valeur <unistd.h> publiée dans ce volume de POSIX.1‐2017.
2.
Les fournisseurs d'applications internationales ont parfois besoin de connaître le nombre de cycles d'horloge par seconde. Sans ces facilités, ils seraient obligés soit de distribuer leurs applications partiellement sous forme source, soit d'avoir des versions 50 Hz et 60 Hz pour les différents pays où ils opèrent.

C'est la connaissance que de nombreuses applications sont effectivement distribuées largement sous forme exécutable qui conduit à cette fonctionnalité. Si l'on se limite aux valeurs les plus restrictives dans les en-têtes, de telles applications devraient être préparées à accepter les environnements les plus limités offerts par les plus petits micro-ordinateurs. Bien que cela soit entièrement portable, il y a eu un consensus sur le fait qu'elles devraient pouvoir tirer parti des fonctionnalités offertes par les grands systèmes, sans les restrictions associées aux distributions sources et objets.

Lors des discussions sur cette fonctionnalité, il a été souligné qu'il est presque toujours possible pour une application de déterminer quelle peut être une valeur au moment de l'exécution en testant convenablement les diverses fonctions elles-mêmes. NAME

sysconf - get system configuration information

SYNOPSIS

     #include <unistd.h>

     long sysconf(int name);

DESCRIPTION

The sysconf() function shall return the value of the system configuration variable specified by name. If the value is indeterminate, or if the implementation does not support the configuration variable, it shall return -1 and set errno to indicate the error. Implementations shall not return -1 for any of the system configuration variables defined by POSIX.1-2017.

The following are the valid values for the name argument:

_SC_ARG_MAX
The maximum length, in bytes, of the argument list to be executed by the exec family of functions, including environment data. On systems that support it, the minimum value of this constant shall be 4096.
The minimum value for {ARG_MAX} shall be 4096.
_SC_CHILD_MAX
The maximum number of child processes that may be created by a single user with the current login session. On systems that support it, the minimum value of this constant shall be 25.
The minimum value for {CHILD_MAX} shall be 25.
_SC_CLK_TCK
The number of clock ticks per second.
The minimum value for {CLK_TCK} shall be 1.
_SC_NGROUPS_MAX
The maximum number of groups that can be passed to setgroups(). On systems that support it, the minimum value of this constant shall be 0.
The minimum value for {NGROUPS_MAX} shall be 16.
_SC_OPEN_MAX
The maximum number of files that a process may have open at any time. On systems that support it, the minimum value of this constant shall be 16.
The minimum value for {OPEN_MAX} shall be 16.
_SC_PASS_MAX
The maximum length, in bytes, of the password, size of the password in bytes, including the terminating null byte. If this value is not positive, the password length is indeterminate.
The minimum value for {PASS_MAX} shall be 128.
_SC_TZNAME_MAX
The maximum number of bytes in the name of a timezone, including the final NUL character. On systems that support it, the minimum value of this constant shall be 3.
The minimum value for {TZNAME_MAX} shall be 3.
_SC_JOB_COREDUMP
A boolean value indicating whether a system limit on the size of core files is imposed per process. This is a boolean value. If the value is non-zero, a system limit is imposed. If the value is zero, no system limit is imposed.
_SC_SAVED_CURSES_MAX
The maximum number of screens that can be saved using the curses(3x) library. If this value is not positive, the number of screens that can be saved is indeterminate.
The minimum value for {SAVED_CURSES_MAX} shall be 16.
_SC_VERSION
The version of the POSIX standard that the system conforms to. The value returned shall be POSIX.1-2017.
_SC_BC_BASE_MAX
The maximum value the bc(1) utility, or an equivalent, will support for the value of the constants BC_BASE_MAX.
The minimum value for {BC_BASE_MAX} shall be 99.
_SC_BC_DIM_MAX
The maximum number of operands allowed in an expression in the bc(1) utility, or an equivalent.
The minimum value for {BC_DIM_MAX} shall be 2048.
_SC_BC_SCALE_MAX
The maximum number of digits supported by the bc(1) utility, or an equivalent, for the scale factor.
The minimum value for {BC_SCALE_MAX} shall be 2048.
_SC_BC_STRING_MAX
The maximum length, in bytes, of a string supported by the bc(1) utility, or an equivalent.
The minimum value for {BC_STRING_MAX} shall be 1000.
_SC_COLL_WEIGHTS_MAX

The minimum value for {COLL_WEIGHTS_MAX} shall be 2.
_SC_EQUIV_CLASS_MAX

The minimum value for {EQUIV_CLASS_MAX} shall be 2.
_SC_EXINIT_MAX
The maximum number of lines that can be saved in the ex(1) editor's pattern space.
The minimum value for {EXINIT_MAX} shall be 128.
_SC_EXPNAMES
A boolean value indicating whether the vi(1) editor supports the use of shell expansion for filenames. If the value is non-zero, shell expansion is supported. If the value is zero, shell expansion is not supported.
_SC_HOST_NAME_MAX

The minimum value for {HOST_NAME_MAX} shall be 255.
_SC_LINE_MAX

_SC_MAC_AFFINE_MAX

A boolean value indicating whether the system supports the X/Open Portability Guide, Issue 4, Extended Specification. If the value is non-zero, it is supported. If the value is zero, it is not.

RETURN VALUE

If name is a valid configuration variable, sysconf() shall return the value of that variable. If the value of the configuration variable is indeterminate, sysconf() shall return -1 and set errno to EINVAL.

If name is not a recognised system configuration variable, sysconf() shall return -1 and set errno to EINVAL.

ERRORS

EINVAL
The value of name is not recognised or is indeterminate.

EXAMPLES

None.

APPLICATION USAGE

None.

RATIONALE

The sysconf(3p) function was introduced to provide a standard way to query system configuration values. Previously, applications often relied on implementation-specific header files or constants that were not guaranteed to be portable.

The values returned by sysconf() are generally static for a given system. They are not expected to change during the lifetime of a running process. Changes to system configuration typically require a system reboot or the intervention of a system administrator.

Some system configuration values may vary depending on the context (e.g., file system mount options). For such values, the fpathconf(3p) function should be used instead.

The decision to restrict return values to integers simplifies implementation and usage. While some configuration values could conceptually be represented as strings, this would introduce additional complexity for both the system implementers and application developers.

For constants like {PATH_MAX}, which may be extremely large, sysconf() returns a negative value to indicate that the constant is not defined or is effectively unlimited in the current context. This prevents applications from attempting to allocate excessively large memory buffers based on potentially unbounded values.

The behavior of returning -1 and setting errno to EINVAL is consistent with other POSIX functions that query system information.
