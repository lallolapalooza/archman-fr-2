NOM

upterm-host - Héberger une session de terminal

SYNTAXE

upterm host [options]

DESCRIPTION

Héberge une session de terminal via un tunnel SSH inversé vers le serveur Upterm.

La session relie l'entrée/sortie de l'hôte et du client à l'entrée/sortie d'une commande. L'authentification auprès du serveur Upterm utilise les clés privées dans cet ordre :
1. Fichiers de clé privée : ~/.ssh/id_dsa, ~/.ssh/id_ecdsa, ~/.ssh/id_ed25519, ~/.ssh/id_rsa
2. Clés de l'agent SSH
3. Clé éphémère générée automatiquement (si aucune clé n'est trouvée)

Pour autoriser les connexions clientes, utilisez --authorized-keys pour spécifier un fichier authorized_keys contenant les clés publiques des clients.

OPTIONS

--accept[=false] Accepte automatiquement les connexions clientes sans demande.

--authorized-keys="" Spécifie un fichier authorized_keys listant les clés publiques autorisées pour la connexion.

--codeberg-user=[] Autorise les utilisateurs Codeberg spécifiés en permettant à leurs clés publiques de se connecter.

-f, --force-command="" Force une commande spécifiée pour que les clients puissent s'y connecter, et relie l'entrée/sortie de la commande au terminal du client.

--github-user=[] Autorise les utilisateurs GitHub spécifiés en permettant à leurs clés publiques de se connecter. Configurez les variables d'environnement de la CLI GitHub au besoin ; voir https://cli.github.com/manual/gh_help_environment pour les détails.

--gitlab-user=[] Autorise les utilisateurs GitLab spécifiés en permettant à leurs clés publiques de se connecter.

-h, --help[=false] aide pour host

--hide-client-ip[=false] Masque les adresses IP des clients dans la sortie (activé automatiquement dans les environnements CI).

--known-hosts="/build/.ssh/known_hosts" Spécifie un fichier contenant les clés connues pour les hôtes distants (requis).

-i, --private-key=[] Spécifie les fichiers de clé privée pour l'authentification par clé publique auprès du serveur upterm (requis).

-r, --read-only[=false] Héberge une session en lecture seule, empêchant l'interaction du client.

--server="ssh://uptermd.upterm.dev:22" Spécifie l'adresse du serveur upterm (requis). Protocoles supportés : ssh, ws, wss.

--skip-host-key-check[=false] Accepte automatiquement les clés d'hôte serveur inconnues et les ajoute à known_hosts (similaire à StrictHostKeyChecking=accept-new de SSH). Cela contourne la vérification de la clé d'hôte pour les nouvelles connexions.

--srht-user=[] Autorise les utilisateurs SourceHut spécifiés en permettant à leurs clés publiques de se connecter.

OPTIONS INHERITÉES DES COMMANDES PARENTES

--debug[=false] active la journalisation au niveau de débogage (fichier journal : /build/.upterm/upterm.log).

EXEMPLE

  # Héberge une session de terminal exécutant $SHELL, en attachant l'entrée/sortie du client à celle de l'hôte :
  upterm host
  # Accepte automatiquement les connexions clientes sans demande :
  upterm host --accept
  # Héberge une session de terminal n'autorisant que la ou les clés publiques spécifiées à se connecter :
  upterm host --authorized-keys CHEMIN_VERS_FICHIER_AUTHORIZED_KEY
  # Héberge une session exécutant une commande personnalisée :
  upterm host -- docker run --rm -ti ubuntu bash
  # Héberge une session 'tmux new -t pair-programming', forçant les clients à s'y joindre avec 'tmux attach -t pair-programming' :
  upterm host --force-command 'tmux attach -t pair-programming' -- tmux new -t pair-programming
  # Utilise un serveur Uptermd différent, hébergeant une session via WebSocket :
  upterm host --server wss://VOTRE_SERVEUR_UPTERMD -- VOTRE_COMMANDE
