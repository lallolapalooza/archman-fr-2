NOM

uucico - démon de transfert de fichiers UUCP

SYNTAXE

uucico [ options ]

DESCRIPTION

Le démon uucico traite les requêtes de transfert de fichiers mises en file d'attente par uucp (1) et uux (1). Il est lancé lorsque uucp ou uux est exécuté (sauf s'ils reçoivent l'option -r). Il est également généralement lancé périodiquement à l'aide d'entrées dans la ou les tables crontab.

Lorsqu'il est invoqué avec -r1, --master, -s, --system, ou -S, le démon établira un appel vers un système distant, fonctionnant en mode maître. Sinon, le démon démarrera en mode esclave, acceptant un appel d'un système distant. Typiquement, un nom de connexion spécial sera configuré pour UUCP, qui invoquera automatiquement uucico lorsqu'un appel sera effectué.

Lorsque uucico se termine, il invoque le démon uuxqt (8), à moins que l'option -q ou --nouuxqt ne soit fournie ; uuxqt (8) exécute les ordres de travail créés par uux (1) sur un système distant, et tous les ordres de travail créés localement qui ont reçu des fichiers distants pour lesquels ils attendaient.

Si un appel échoue, uucico refusera normalement de réessayer l'appel avant qu'un certain délai (configurable) ne se soit écoulé. Cela peut être outrepassé par les options -f, --force, ou -S.

Les options -l, --prompt, -e, ou --loop peuvent être utilisées pour forcer uucico à produire ses propres invites de connexion et de mot de passe : "login: " et "Password:". Lorsqu'un autre démon appelle, il verra ces invites et se connectera comme d'habitude. Le nom de connexion et le mot de passe seront normalement vérifiés par rapport à une liste séparée conservée spécialement pour uucico plutôt qu'au fichier /etc/passwd ; il est possible sur certains systèmes de diriger uucico pour utiliser le fichier /etc/passwd. L'option -l ou --prompt demandera une fois puis se terminera ; dans ce mode, l'administrateur UUCP ou le superutilisateur peut utiliser l'option -u ou --login pour forcer un nom de connexion, auquel cas uucico ne demandera pas de nom de connexion. L'option -e ou --loop demandera à nouveau après la fin de la première session ; dans ce mode, uucico contrôlera un port de manière permanente.

Si uucico reçoit un signal SIGQUIT, SIGTERM ou SIGPIPE, il abandonnera proprement toute conversation en cours avec un système distant et se terminera. S'il reçoit un signal SIGHUP, il abandonnera toute conversation en cours, mais continuera à appeler (s'il est invoqué avec -r1 ou --master) et à accepter les appels (s'il est invoqué avec -e ou --loop) d'autres systèmes. S'il reçoit un signal SIGINT, il terminera la conversation en cours, mais ne passera ou n'acceptera plus d'appels.

OPTIONS

Les options suivantes peuvent être fournies à uucico.

-r1, --master
Démarrer en mode maître (appeler un système) ; implicite par -s, --system, ou -S. Si aucun système n'est spécifié, appeler tout système pour lequel il y a du travail en attente.
-r0, --slave
Démarrer en mode esclave. C'est le comportement par défaut.
-s system, --system system
Appeler le système nommé.
-S system
Appeler le système nommé, en ignorant tout délai requis. Ceci est équivalent à -s system -f.
-f, --force
Ignorer tout délai requis pour les systèmes à appeler.
-l, --prompt
Demander le nom de connexion et le mot de passe en utilisant "login: " et "Password:". Cela permet à uucico d'être facilement lancé depuis inetd (8). Le nom de connexion et le mot de passe sont vérifiés par rapport au fichier de mots de passe UUCP, qui n'a probablement aucun lien avec le fichier /etc/passwd. L'option --login peut être utilisée pour forcer un nom de connexion, auquel cas uucico ne demandera qu'un mot de passe.
-p port, --port port
Spécifier un port à appeler ou à écouter.
-e, --loop
Entrer dans une boucle infinie de demandes de connexion/mot de passe et d'exécution du démon en mode esclave. Le programme ne s'arrêtera pas tout seul ; vous devrez utiliser kill (1) pour l'arrêter.
-w, --wait
Après avoir appelé (un système spécifique lorsque -s, --system, ou -S est spécifié, ou tous les systèmes qui ont du travail lorsque juste -r1 ou --master est spécifié), démarrer une boucle infinie comme avec --loop.
-q, --nouuxqt
Ne pas démarrer le démon uuxqt (8) une fois terminé.
-c, --quiet
Si aucun appel n'est autorisé à ce moment-là, alors ne pas passer l'appel, mais ne pas non plus écrire de message d'erreur dans le fichier journal et ne pas mettre à jour l'état du système (tel que rapporté par uustat (1)). Ceci peut être pratique pour les scripts d'interrogation automatisés, qui peuvent simplement vouloir tenter d'appeler chaque système sans se soucier des systèmes particuliers qui peuvent être appelés à l'instant T. Cette option supprime également le message du journal indiquant qu'il n'y a pas de travail à faire.
-C, --ifwork
Appeler uniquement le système nommé par -s, --system ou -S s'il y a du travail pour ce système.
-D, --nodetach
Ne pas se détacher du terminal de contrôle. Normalement, uucico se détache du terminal avant chaque appel sortant vers un autre système et avant d'invoquer uuxqt. Cette option empêche cela.
-u name, --login name
Définir le nom de connexion à utiliser au lieu de celui de l'utilisateur appelant. Cette option ne peut être utilisée que par l'administrateur UUCP ou le superutilisateur. Si elle est utilisée avec --prompt, cela amènera uucico à ne demander que le mot de passe, pas le nom de connexion.
-z, --try-next
Si un appel échoue après que le système distant a été atteint, essayer le prochain système alternatif plutôt que de simplement sortir.
-i type, --stdin type
Définir le type de port à utiliser lors de l'utilisation de l'entrée standard. Le seul type de port pris en charge est TLI, et il n'est disponible que sur les machines qui prennent en charge l'interface réseau TLI. Spécifier -iTLI amène uucico à utiliser les appels TLI pour effectuer les E/S.
-x type, -X type, --debug type
Activer des types de débogage spécifiques. Les types suivants sont reconnus : abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing.

Plusieurs types peuvent être donnés, séparés par des virgules, et l'option --debug peut apparaître plusieurs fois. Un nombre peut également être donné, qui activera ce nombre de types de la liste précédente ; par exemple, --debug 2 est équivalent à --debug abnormal,chat.

La sortie de débogage est envoyée au fichier de débogage, qui peut être imprimé en utilisant uulog -D.

-I file, --config file
Définir le fichier de configuration à utiliser. Cette option peut ne pas être disponible, selon la façon dont uucico a été compilé.
-v, --version
Afficher les informations de version et quitter.
--help
Afficher un message d'aide et quitter.
