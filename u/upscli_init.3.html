NOM

upscli_init - Initialise le module upsclient en spécifiant les propriétés de sécurité.

SYNOPSIS

        #include <upsclient.h>
        int upscli_init(
                int certverify,
                const char *certpath,
                const char *certname,
                const char *certpasswd);

DESCRIPTION

La fonction upscli_init() initialise le module upsclient et définit plusieurs propriétés liées à TLS/SSL : certverify à 1 rend la vérification des certificats requise pour toutes les connexions SSL, et certpath est l'emplacement de la base de données des certificats.

•Si compilé avec OpenSSL, certpath fait référence au répertoire contenant les certificats où les certificats doivent être nommés selon leurs valeurs de hachage se terminant par une extension ".0". Si deux certificats aboutissent à la même valeur de hachage (donc nom de fichier), le ".0" peut être incrémenté à ".1" et ainsi de suite, selon les besoins. La commande shell pour créer des liens de cette manière serait : 
:; ln -s ca.pem ./$(openssl x509 -hash -noout -in ca.pem).0

Alternativement, l'utilitaire c_rehash (fourni par exemple par le paquet openssl-perl) peut prendre un répertoire et l'itérer pour lier tous les certificats trouvés dans ce répertoire, de la manière décrite ci-dessus.

•Si compilé avec NSS, certpath fait référence à un répertoire contenant ses fichiers de base de données.

Si compilé avec NSS et en utilisant SSL, vous pouvez spécifier certname avec le nom du certificat à envoyer à upsd, et certpasswd avec le mot de passe utilisé pour décrypter la clé privée du certificat.

Si compilé avec NSS, il enregistrerait normalement le message bien connu "Init SSL without certificate database" si aucun certpath n'était fourni, ou "Init SSL with certificate database located at %s" sinon. Comme certains consommateurs programmatiques deviennent confus par ce texte supplémentaire sur la sortie d'erreur des outils qu'ils appellent (tels que les systèmes de surveillance effectuant des requêtes upsc), vous pouvez exporter une variable d'environnement NUT_QUIET_INIT_SSL avec les valeurs de chaîne "true", "TRUE" ou "1", pour éviter d'enregistrer ces messages et simplement les émettre comme flux de débogage (à la verbosité 1 ou plus).

Dans le cadre de l'initialisation générale, la fonction upscli_init() peut appeler la méthode upscli_init_default_connect_timeout(3) (si elle n'a jamais été utilisée auparavant) : cela permet aux clients NUT non modifiés (hérités) de bénéficier de manière cohérente de la présence de la variable d'environnement NUT_DEFAULT_CONNECT_TIMEOUT pour les tentatives de upscli_connect(3) afin de ne pas bloquer (comme par défaut).

Vous pouvez appeler upscli_add_host_cert(3) pour enregistrer une politique de sécurité spécifique à l'hôte avant d'initialiser les connexions à ceux-ci.

Vous devez appeler upscli_cleanup(3) en quittant l'application.

VALEUR DE RETOUR

La fonction upscli_init() retourne 1 en cas de succès, ou -1 si une erreur se produit.
