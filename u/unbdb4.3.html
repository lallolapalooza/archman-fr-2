CUNBDB4

But :

!>
!> CUNBDB4 bidiagonalise simultanément les blocs d'une matrice X grande et mince
!> avec des colonnes orthonormales :
!>
!>                            [ B11 ]
!>      [ X11 ]   [ P1 |    ] [  0  ]
!>      [-----] = [---------] [-----] Q1**T .
!>      [ X21 ]   [    | P2 ] [ B21 ]
!>                            [  0  ]
!>
!> X11 est P par Q, et X21 est (M-P) par Q. M-Q doit être inférieur ou égal à P,
!> M-P, ou Q. Les routines CUNBDB1, CUNBDB2 et CUNBDB3 gèrent les cas où
!> M-Q n'est pas la dimension minimale.
!>
!> Les matrices unitaires P1, P2 et Q1 sont respectivement P par P, (M-P) par (M-P)
!> et (M-Q) par (M-Q). Elles sont représentées implicitement par
!> des vecteurs de Householder.
!>
!> B11 et B12 sont des matrices bidiagonales (M-Q) par (M-Q) représentées
!> implicitement par les angles THETA, PHI.
!>
!>

Paramètres

M 
!>          M est ENTIER
!>           Le nombre de lignes de X11 plus le nombre de lignes de X21.
!>

P

!>          P est ENTIER
!>           Le nombre de lignes de X11. 0 <= P <= M.
!>

Q

!>          Q est ENTIER
!>           Le nombre de colonnes de X11 et X21. 0 <= Q <= M et
!>           M-Q <= min(P,M-P,Q).
!>

X11

!>          X11 est un tableau COMPLÈXE, dimension (LDX11,Q)
!>           À l'entrée, le bloc supérieur de la matrice X à réduire. À
!>           la sortie, les colonnes de tril(X11) spécifient les réflecteurs
!>           pour P1 et les lignes de triu(X11,1) spécifient les réflecteurs
!>           pour Q1.
!>

LDX11

!>          LDX11 est ENTIER
!>           La dimension principale de X11. LDX11 >= P.
!>

X21

!>          X21 est un tableau COMPLÈXE, dimension (LDX21,Q)
!>           À l'entrée, le bloc inférieur de la matrice X à réduire. À
!>           la sortie, les colonnes de tril(X21) spécifient les réflecteurs
!>           pour P2.
!>

LDX21

!>          LDX21 est ENTIER
!>           La dimension principale de X21. LDX21 >= M-P.
!>

THETA

!>          THETA est un tableau RÉEL, dimension (Q)
!>           Les entrées des blocs bidiagonaux B11, B21 sont définies par
!>           THETA et PHI. Voir Détails supplémentaires.
!>

PHI

!>          PHI est un tableau RÉEL, dimension (Q-1)
!>           Les entrées des blocs bidiagonaux B11, B21 sont définies par
!>           THETA et PHI. Voir Détails supplémentaires.
!>

TAUP1

!>          TAUP1 est un tableau COMPLÈXE, dimension (M-Q)
!>           Les facteurs scalaires des réflecteurs élémentaires qui définissent
!>           P1.
!>

TAUP2

!>          TAUP2 est un tableau COMPLÈXE, dimension (M-Q)
!>           Les facteurs scalaires des réflecteurs élémentaires qui définissent
!>           P2.
!>

TAUQ1

!>          TAUQ1 est un tableau COMPLÈXE, dimension (Q)
!>           Les facteurs scalaires des réflecteurs élémentaires qui définissent
!>           Q1.
!>

PHANTOM

!>          PHANTOM est un tableau COMPLÈXE, dimension (M)
!>           La routine calcule un vecteur colonne Y de taille M par 1 qui est
!>           orthogonal aux colonnes de [ X11; X21 ]. PHANTOM(1:P) et
!>           PHANTOM(P+1:M) contiennent des vecteurs de Householder pour Y(1:P) et
!>           Y(P+1:M), respectivement.
!>

WORK

!>          WORK est un tableau COMPLÈXE, dimension (LWORK)
!>

LWORK

!>          LWORK est ENTIER
!>           La dimension du tableau WORK. LWORK >= M-Q.
!>
!>           Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>           calcule uniquement la taille optimale du tableau WORK, renvoie
!>           cette valeur comme première entrée du tableau WORK, et aucun message d'erreur
!>           lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est ENTIER
!>           = 0 : sortie réussie.
!>           < 0 : si INFO = -i, le i-ème argument avait une valeur illégale.
!>

Univ. de Californie Berkeley

Détails supplémentaires :

!>
!>  Les blocs supérieurs bidiagonaux B11, B21 sont représentés implicitement par
!>  les angles THETA(1), ..., THETA(Q) et PHI(1), ..., PHI(Q-1). Chaque entrée
!>  de chaque bande bidiagonale est un produit d'un sinus ou d'un cosinus d'un THETA
!>  avec un sinus ou un cosinus d'un PHI. Voir [1] ou CUNCSD pour les détails.
!>
!>  P1, P2 et Q1 sont représentés comme des produits de réflecteurs élémentaires.
!>  Voir CUNCSD2BY1 pour les détails sur la génération de P1, P2 et Q1 à l'aide de CUNGQR
!>  et CUNGLQ.
!>

Références :

[1] Brian D. Sutton. Computing the complete CS decomposition. Numer. Algorithms, 50(1):33-65, 2009.

NAME

zunbdb4 - ZUNBDB4 bidiagonalise simultanément les blocs d'une matrice X élancée et étroite avec des colonnes orthonormales.

SYNOPSIS

subroutine zunbdb4(m, p, q, x11, ldx11, x21, ldx21, theta, phi, taup1, taup2, tauq1, phantom, work, lwork, info)

complex*16 :: x11(ldx11,*)
complex*16 :: x21(ldx21,*)
complex*16 :: taup1(*)
complex*16 :: taup2(*)
complex*16 :: tauq1(*)
complex*16 :: phantom(*)
complex*16 :: work(*)
integer :: m, p, q, ldx11, ldx21, lwork, info
real*8 :: theta(*)
real*8 :: phi(*)

Detailed Description

Purpose:

!>
!> ZUNBDB4 bidiagonalise simultanément les blocs d'une matrice X élancée et
!> étroite avec des colonnes orthonormales :
!>
!>                            [ B11 ]
!>      [ X11 ]   [ P1 |    ] [  0  ]
!>      [-----] = [---------] [-----] Q1**T .
!>      [ X21 ]   [    | P2 ] [ B21 ]
!>                            [  0  ]
!>
!> X11 est de taille P-par-Q, et X21 est de taille (M-P)-par-Q. M-Q doit être
!> inférieur ou égal à P, M-P, ou Q. Les routines ZUNBDB1, ZUNBDB2 et ZUNBDB3
!> gèrent les cas où M-Q n'est pas la dimension minimale.
!>
!> Les matrices unitaires P1, P2 et Q1 sont respectivement de taille P-par-P,
!> (M-P)-par-(M-P) et (M-Q)-par-(M-Q). Elles sont représentées implicitement
!> par des vecteurs de Householder.
!>
!> B11 et B12 sont des matrices bidiagonales de taille (M-Q)-par-(M-Q)
!> représentées implicitement par les angles THETA et PHI.
!>
!>

!>           La routine calcule un vecteur colonne Y de taille M-par-1 qui est
!>           orthogonal aux colonnes de [ X11; X21 ]. PHANTOM(1:P) et
!>           PHANTOM(P+1:M) contiennent des vecteurs de Householder pour Y(1:P)
!>           et Y(P+1:M), respectivement.
!>

WORK

!>          WORK est un tableau COMPLEX*16, dimension (LWORK)
!>

LWORK

!>          LWORK est INTEGER
!>           La dimension du tableau WORK. LWORK >= M-Q.
!>
!>           Si LWORK = -1, alors une requête d'espace de travail est supposée ;
!>           la routine calcule uniquement la taille optimale du tableau WORK,
!>           retourne cette valeur comme première entrée du tableau WORK, et
!>           aucun message d'erreur lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est INTEGER
!>           = 0 : succès.
