UMASK(1P) Manuel du programmeur POSIX UMASK(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

umask — obtenir ou définir le masque de création de mode de fichier

SYNTAXE

umask [-S] [masque]

DESCRIPTION

L'utilitaire umask doit définir le masque de création de mode de fichier de l'environnement d'exécution du shell courant (voir Section 2.12, Environnement d'exécution du shell) à la valeur spécifiée par l'opérande masque. Ce masque doit affecter la valeur initiale des bits de permission de fichier des fichiers créés par la suite. Si umask est appelé dans un sous-shell ou un environnement d'exécution d'utilitaire séparé, tel qu'un des éléments suivants :

(umask 002)
nohup umask ...
find . -exec umask ... \;

cela ne doit pas affecter le masque de création de mode de fichier de l'environnement de l'appelant.

Si l'opérande masque n'est pas spécifié, l'utilitaire umask doit écrire sur la sortie standard la valeur du masque de création de mode de fichier du processus appelant.

OPTIONS

L'utilitaire umask doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

L'option suivante doit être prise en charge :

-S
Produire une sortie symbolique.

Le style de sortie par défaut n'est pas spécifié, mais doit être reconnu lors d'une invocation ultérieure de umask sur le même système comme un opérande masque pour restaurer le masque de création de mode de fichier précédent.

OPÉRANDES

L'opérande suivant doit être pris en charge :

masque
Une chaîne spécifiant le nouveau masque de création de mode de fichier. La chaîne est traitée de la même manière que l'opérande mode décrit dans la section DESCRIPTION ÉTENDUE pour chmod.

Pour une valeur mode_symbolique, la nouvelle valeur du masque de création de mode de fichier doit être le complément logique de la partie bits de permission du mode de fichier spécifié par la chaîne mode_symbolique.

Dans une valeur mode_symbolique, les caractères op de permission '+' et '-' doivent être interprétés par rapport au masque de création de mode de fichier actuel ; '+' doit effacer les bits pour les permissions indiquées dans le masque ; '-' doit définir les bits pour les permissions indiquées dans le masque.

L'interprétation des valeurs mode qui spécifient des bits de mode de fichier autres que les bits de permission de fichier n'est pas spécifiée.

Dans la forme d'entier octal de mode, les bits spécifiés sont définis dans le masque de création de mode de fichier.

Le masque de création de mode de fichier doit être défini à la valeur numérique résultante.

La sortie par défaut d'une invocation précédente de umask sur le même système sans opérande doit également être reconnue comme un opérande masque.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de umask :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, elle remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Déterminer la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Lorsque l'opérande masque n'est pas spécifié, l'utilitaire umask doit écrire un message sur la sortie standard qui pourra être utilisé ultérieurement comme opérande masque de umask.

Si -S est spécifié, le message doit avoir le format suivant :

"u=%s,g=%s,o=%s\n", <permissions propriétaire>, <permissions groupe>,
    <permissions autres>

où les trois valeurs doivent être des combinaisons de lettres de l'ensemble {r, w, x} ; la présence d'une lettre doit indiquer que le bit correspondant est effacé dans le masque de création de mode de fichier.

Si un opérande masque est spécifié, aucun message ne doit être écrit sur la sortie standard.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard ne doit être utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucun.

VALEUR DE RETOUR

Les valeurs de sortie suivantes doivent être retournées :

 0
Le masque de création de mode de fichier a été modifié avec succès, ou aucun opérande masque n'a été fourni.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Étant donné que umask affecte l'environnement d'exécution du shell courant, il est généralement fourni en tant que commande interne du shell.

Contrairement à la logique des permissions négatives fournie par le masque de création de mode de fichier et la forme de nombre octal de l'argument masque, la forme symbolique de l'argument masque spécifie les permissions qui sont laissées telles quelles.

EXEMPLES

L'une des commandes suivantes :

umask a=rx,ug+w
umask 002

définit le masque de mode de sorte que les fichiers créés par la suite aient leur bit S_IWOTH effacé.

Après avoir défini le masque de mode avec l'une des commandes ci-dessus, la commande umask peut être utilisée pour afficher la valeur actuelle du masque de mode :

$ umask
0002

(Le format de sortie n'est pas spécifié, mais les implémentations historiques utilisent le format de mode entier octal.)

$ umask -S
u=rwx,g=rwx,o=rx

L'une de ces sorties peut être utilisée comme opérande masque pour une invocation ultérieure de l'utilitaire umask.

umask(1p) - Linux manual page

PROLOG

This page is a manual page for `umask' under Linux. It is part of the POSIX Standard, which is part of the Linux man-pages project. The POSIX Standard is available online at the Open Group.

NAME

umask

SYNOPSIS

sh

umask [-p] [-S] [umask]

DESCRIPTION

The umask utility shall set the file mode creation mask of the current shell execution environment. The file mode creation mask is used by the system to determine the default permissions for newly created files and directories. The umask utility shall set the mask to the value specified by the umask argument. If the umask argument is omitted, the current file mode creation mask shall be written to standard output.

The exact behavior of masking is described in umask(3p). The standard utilities document that the permissions are masked from the default permissions that would be assigned if the user did not specify a mode. The description of the file mode creation mask is as follows: the mask is a set of bits that is ANDed with the desired mode when a file is created. If a bit is set in the mask, the corresponding permission bit shall not be set in the file's mode. This means that if a bit is set in the mask, the application cannot grant that permission.

OPTIONS

The following options shall be supported:

-p
Output shall be in the form of future commands to re-create the current mode. This option is intended to allow the output to be reused as input to the shell. When -p is specified, the output format is implementation-defined, but it shall be valid input to the shell. The default output format when -p is not specified is implementation-defined, but it shall be valid input to the shell.
-S
Output the current file mode creation mask in symbolic notation. The format shall be u=rwx,g=rwx,o=rwx, where each group is omitted if all permissions are denied. For example, u=rwx,g=rx,o= means that user write, read, and execute are allowed, group read and execute are allowed, and others have no permissions.

OPERANDS

The following operand shall be supported:

umask
A symbolic or octal string representing the new file mode creation mask. If the umask argument is omitted, the current file mode creation mask shall be written to standard output.

Symbolic modes are described in chmod(1). The symbolic modes used by umask are restrictions on the default permissions; they specify the bits to be cleared from the default permissions. For example, g-w removes write permission for the group. Default permissions are normally 0666 for files and 0777 for directories. The effective mode is the default mode ANDed with the complement of the mask.

Octal modes are a three-digit number in base 8. The first digit specifies the permissions for the user, the second for the group, and the third for others. The permissions are represented as follows: 4 for read, 2 for write, and 1 for execute. Permissions are added together; for example, 6 means read and write (4+2), and 7 means read, write, and execute (4+2+1).

It is an error for the umask argument to begin with a <hyphen-minus> unless it is preceded by "--".

STDIN

None.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

Default.

STDOUT

When the umask argument is omitted, the current file mode creation mask shall be written to standard output. The format is implementation-defined, but shall be valid input to the shell.

When the -S option is specified, the current file mode creation mask shall be written to standard output in symbolic notation.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The umask utility shall exit with a value greater than 0 if an attempt to change the file mode creation mask fails. Otherwise, the umask utility shall exit with a value of 0.

CONSEQUENCES OF ERRORS

None.

APPLICATION USAGE

The umask utility is a shell built-in utility. If it is invoked in a subshell or in a separate utility execution environment, such as with `nohup' or `find -exec ... \;', its effects on the file mode creation mask are local to that subshell or execution environment and will not affect the file mode creation mask of the invoking environment.

When using the symbolic mode form of the umask argument, it is important to precede any mask operand that begins with a <hyphen-minus> with the -- argument to prevent it from being interpreted as an option.

EXAMPLES

To display the current file mode creation mask:

umask

To display the current file mode creation mask in symbolic notation:

umask -S

To set the file mode creation mask so that subsequently created files have their group and other write bits cleared:

umask -- -w

The command:

umask -- -w

sets the mode mask so that subsequently created files have all their write bits cleared. Note that mask operands -r, -w, -x or anything beginning with a <hyphen-minus>, must be preceded by "--" to keep it from being interpreted as an option.

RATIONALE

Since umask affects the current shell execution environment, it is generally provided as a shell regular built-in. If it is called in a subshell or separate utility execution environment, such as one of the following:

(umask 002)
nohup umask ...
find . -exec umask ... \;

it does not affect the file mode creation mask of the environment of the caller.

The description of the historical utility was modified to allow it to use the symbolic modes of chmod. The -s option used in early proposals was changed to -S because -s could be confused with a symbolic_mode form of mask referring to the S_ISUID and S_ISGID bits.

The default output style is unspecified to permit implementors to provide migration to the new symbolic style at the time most appropriate to their users. A -o flag to force octal mode output was omitted because the octal mode may not be sufficient to specify all of the information that may be present in the file mode creation mask when more secure file access permission checks are implemented.

It has been suggested that trusted systems developers might appreciate ameliorating the requirement that the mode mask ``affects'' the file access permissions, since it seems access control lists might replace the mode mask to some degree. The wording has been changed to say that it affects the file permission bits, and it leaves the details of the behavior of how they affect the file access permissions to the description in the System Interfaces volume of POSIX.1‐2017.
