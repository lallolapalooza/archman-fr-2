uustat(1) Manuel des commandes générales uustat(1)

NOM

uustat - Interrogation et contrôle du statut UUCP

SYNOPIS

uustat -a

uustat --all

uustat [ -eKRiMNQ ] [ -sS système ] [ -uU utilisateur ] [ -cC commande ] [ -oy heures ] [ -B lignes ] [ --executions ] [ --kill-all ] [ --rejuvenate-all ] [ --prompt ] [ --mail ] [ --notify ] [ --no-list ] [ --system système ] [ --not-system système ] [ --user utilisateur ] [ --not-user utilisateur ] [ --command commande ] [ --not-command commande ] [ --older-than heures ] [ --younger-than heures ] [ --mail-lines lignes ]

uustat [ -kr jobid ] [ --kill jobid ] [ --rejuvenate jobid ]

uustat -q [ -sS système ] [ -oy heures ] [ --system système ] [ --not-system système ] [ --older-than heures ] [ --younger-than heures ]

uustat --list [ -sS système ] [ -oy heures ] [ --system système ] [ --not-system système ] [ --older-than heures ] [ --younger-than heures ]

uustat -m

uustat --status

uustat -p

uustat --ps

DESCRIPTION

La commande uustat peut afficher divers types d'informations sur le statut du système UUCP. Elle peut également être utilisée pour annuler ou rajeunir des requêtes faites par uucp (1) ou uux (1).

Par défaut, uustat affiche tous les travaux mis en file d'attente pour l'utilisateur appelant, comme si l'option --user avait été donnée avec l'argument approprié.

Si l'une des options -a, --all, -e, --executions, -s, --system, -S, --not-system, -u, --user, -U, --not-user, -c, --command, -C, --not-command, -o, --older-than, -y, --younger-than est donnée, alors tous les travaux correspondant aux spécifications combinées sont affichés.

L'option -K ou --kill-all peut être utilisée pour annuler un groupe de travaux sélectionnés, tels que tous les travaux datant de plus de 7 jours.

OPTIONS

Les options suivantes peuvent être données à uustat.

-a, --all
Lister toutes les requêtes de transfert de fichiers en file d'attente.
-e, --executions
Lister les requêtes d'exécution en file d'attente plutôt que les requêtes de transfert de fichiers. Les requêtes d'exécution en file d'attente sont traitées par uuxqt (8) plutôt que par uucico (8). Les requêtes d'exécution en file d'attente peuvent attendre le transfert de certains fichiers depuis un système distant. Elles sont créées par une invocation de uux (1).
-s système, --system système
Lister tous les travaux mis en file d'attente pour le système nommé. Ces options peuvent être spécifiées plusieurs fois, auquel cas tous les travaux de tous les systèmes seront listés. Si utilisé avec --list seuls les systèmes nommés seront listés.
-S système, --not-system système
Lister tous les travaux mis en file d'attente pour des systèmes autres que celui nommé. Ces options peuvent être spécifiées plusieurs fois, auquel cas aucun travail provenant d'aucun des systèmes spécifiés ne sera listé. Si utilisé avec --list seuls les systèmes non nommés seront listés. Ces options ne peuvent pas être utilisées avec -s ou --system.
-u utilisateur, --user utilisateur
Lister tous les travaux mis en file d'attente pour l'utilisateur nommé. Ces options peuvent être spécifiées plusieurs fois, auquel cas tous les travaux de tous les utilisateurs seront listés.
-U utilisateur, --not-user utilisateur
Lister tous les travaux mis en file d'attente pour des utilisateurs autres que celui nommé. Ces options peuvent être spécifiées plusieurs fois, auquel cas aucun travail provenant d'aucun des utilisateurs spécifiés ne sera listé. Ces options ne peuvent pas être utilisées avec -u ou --user.
-c commande, --command commande
Lister tous les travaux demandant l'exécution de la commande nommée. Si commande est ALL cela listera tous les travaux demandant l'exécution d'une commande (par opposition à une simple demande de transfert de fichier). Ces options peuvent être spécifiées plusieurs fois, auquel cas tous les travaux demandant une des commandes seront listés.
-C commande, --not-command commande
Lister tous les travaux demandant l'exécution d'une commande autre que la commande nommée, ou, si commande est ALL, lister tous les travaux qui demandent simplement un transfert de fichier (par opposition à la demande d'exécution d'une commande). Ces options peuvent être spécifiées plusieurs fois, auquel cas aucun travail demandant une des commandes spécifiées ne sera listé. Ces options ne peuvent pas être utilisées avec -c ou --command.
-o heures, --older-than heures
Lister tous les travaux mis en file d'attente plus vieux que le nombre d'heures donné. Si utilisé avec --list seuls les systèmes dont le plus vieux travail est plus âgé que le nombre d'heures donné seront listés.
-y heures, --younger-than heures
Lister tous les travaux mis en file d'attente plus jeunes que le nombre d'heures donné. Si utilisé avec --list seuls les systèmes dont le plus vieux travail est plus jeune que le nombre d'heures donné seront listés.
-k jobid, --kill jobid
Annuler le travail nommé. L'identifiant du travail est affiché par le format de sortie par défaut, ainsi que par l'option -j ou --jobid de uucp (1) ou uux (1). Un travail ne peut être annulé que par l'utilisateur qui l'a créé, ou par l'administrateur UUCP ou le superutilisateur. Les options -k ou --kill peuvent être utilisées plusieurs fois sur la ligne de commande pour annuler plusieurs travaux.
-r jobid, --rejuvenate jobid
Rajeunir le travail nommé. Cela le marquera comme ayant été invoqué au moment actuel, affectant la sortie des options -o, --older-than, -y, ou --younger-than et le préservant de tout démon de nettoyage automatique. L'identifiant du travail est affiché par le format de sortie par défaut, ainsi que par les options -j ou --jobid de uucp (1) ou uux (1). Un travail ne peut être rajeuni que par l'utilisateur qui l'a créé, ou par l'administrateur UUCP ou le superutilisateur. Les options -r ou --rejuvenate peuvent être utilisées plusieurs fois sur la ligne de commande pour rajeunir plusieurs travaux.
-q, --list
Afficher le statut des commandes, exécutions et conversations pour tous les systèmes distants pour lesquels des commandes ou des exécutions sont en file d'attente. Les options -s, --system, -S, --not-system, -o, --older-than, -y, et --younger-than peuvent être utilisées pour restreindre les systèmes qui sont listés. Les systèmes pour lesquels aucune commande ou exécution n'est en file d'attente ne seront jamais listés.
-m, --status
Afficher le statut des conversations pour tous les systèmes distants.
-p, --ps
Afficher le statut de tous les processus détenant des verrous UUCP sur les systèmes ou les ports.
-i, --prompt
Pour chaque travail listé, demander s'il faut annuler le travail ou non. Si le premier caractère de la ligne d'entrée est y ou Y le travail sera annulé.
-K, --kill-all
Annuler automatiquement chaque travail listé. Ceci peut être utile pour les scripts de nettoyage automatique, en conjonction avec les options --mail et --notify.
-R, --rejuvenate-all
Rajeunir automatiquement chaque travail listé. Ceci ne peut pas être utilisé avec --kill-all.
-M, --mail
Pour chaque travail listé, envoyer un courrier à l'administrateur UUCP. Si le travail est annulé (en raison de --kill-all ou --prompt avec une réponse affirmative) le courrier l'indiquera. Un commentaire spécifié par l'option --comment peut être inclus. Si le travail est une exécution, la portion initiale de son entrée standard sera incluse dans le message de courrier ; le nombre de lignes à inclure peut être défini avec l'option --mail-lines (la valeur par défaut est 100). Si l'entrée standard contient des caractères nuls, elle est supposée être un fichier binaire

uustat(1) - Arch Linux man pages

NAME

uustat - display UUCP job status

SYNOPSIS

uustat [-a | --all] [-e | --executions] [-l | --list] [-s | --status] [-p | --ps] [-K | --kill-all] [-r | --rejuvenate] [-c jobid | --kill jobid] [-j jobid | --rejuvenate-job jobid] [-m mail-address | --mail mail-address] [-M mail-address | --mail-from mail-address] [-N | --notify] [-W comment | --comment comment] [-B lines | --mail-lines lines] [-Q | --no-list] [-x type | --debug type] [-I file | --config file] [-v | --version] [--help] [other-options ...]

DESCRIPTION

The uustat utility provides information about UUCP (Unix-to-Unix Copy Program) jobs. It can display the status of all queued jobs, specific jobs, or various other information about the state of the UUCP subsystem.

The following options are available:

OPTIONS

-a, --all
Display status of all jobs.
-e, --executions
Display status of queued execution requests.
-l, --list
Display status for all systems with queued up commands.
-s, --status
Display conversation status for all remote systems.
-p, --ps
Display the status of all processes holding UUCP locks.
-K, --kill-all
Kill all jobs. This option is used in conjunction with other options such as --command or --user to specify which jobs to kill.
-r, --rejuvenate
Rejuvenate all jobs. This option is used in conjunction with other options such as --command or --user to specify which jobs to rejuvenate.
-c jobid, --kill jobid
Kill the specified jobid.
-j jobid, --rejuvenate-job jobid
Rejuvenate the specified jobid.
-m address, --mail address
Send mail to the specified address when a job is completed. The mail message will contain the jobid, the user, and the command.
-M address, --mail-from address
Send mail to the specified address when a job is completed. The mail message will contain the jobid, the user, the command, and a sample of the standard input.
-N, --notify
For each listed job, send mail to the user who requested the job. The mail is identical to that sent by the -M or --mail options.
-W comment, --comment comment
Specify a comment to be included in mail sent with the -M, --mail, -N, or --notify options.
-B lines, --mail-lines lines
When the -M, --mail, -N, or --notify options are used to send mail about an execution with standard input, this option controls the number of lines of standard input to include in the message. The default is 100.
-Q, --no-list
Do not actually list the job, but only take any actions indicated by the -i, --prompt, -K, --kill-all, -M, --mail, -N or --notify options.
-x type, --debug type
Turn on particular debugging types. The following types are recognized: abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Only abnormal, config, spooldir and execute are meaningful for uustat.

Multiple types may be given, separated by commas, and the --debug option may appear multiple times. A number may also be given, which will turn on that many types from the foregoing list; for example, --debug 2 is equivalent to --debug abnormal,chat.

-I file, --config file
Set configuration file to use. This option may not be available, depending upon how uustat was compiled.
-v, --version
Report version information and exit.
--help
Print a help message and exit.

EXAMPLES

uustat --all

Display status of all jobs. A sample output line is as follows: 

bugsA027h bugs ian 04-01 13:50 Executing rmail ian@airs.com (sending 1283 bytes)

The format is 

jobid system user queue-date command (size)

The jobid may be passed to the --kill or --rejuvenate options. The size indicates how much data is to be transferred to the remote system, and is absent for a file receive request. The --system, --not-system, --user, --not-user, --command, --not-command, --older-than, and --younger-than options may be used to control which jobs are listed.

uustat --executions
Display status of queued up execution requests. A sample output line is as follows: 

bugs bugs!ian 05-20 12:51 rmail ian

The format is 

system requestor queue-date command

The --system, --not-system, --user, --not-user, --command, --not-command, --older-than, and --younger-than options may be used to control which requests are listed.

uustat --list
Display status for all systems with queued up commands. A sample output line is as follows: 

bugs            4C (1 hour)   0X (0 secs) 04-01 14:45 Dial failed

This indicates the system, the number of queued commands, the age of the oldest queued command, the number of queued local executions, the age of the oldest queued execution, the date of the last conversation, and the status of that conversation.

uustat --status
Display conversation status for all remote systems. A sample output line is as follows: 

bugs           04-01 15:51 Conversation complete

This indicates the system, the date of the last conversation, and the status of that conversation. If the last conversation failed, uustat will indicate how many attempts have been made to call the system. If the retry period is currently preventing calls to that system, uustat also displays the time when the next call will be permitted.

uustat --ps
Display the status of all processes holding UUCP locks. The output format is system dependent, as uustat simply invokes ps (1) on each process holding a lock. 


uustat --command rmail --older-than 168 --kill-all --no-list --mail --notify --comment "Queued for over 1 week"
This will kill all rmail commands that have been queued up waiting for delivery for over 1 week (168 hours). For each such command, mail will be sent both to the UUCP administrator and to the user who requested the rmail execution. The mail message sent will include the string given by the --comment option. The --no-list option prevents any of the jobs from being listed on the terminal, so any output from the program will be error messages.
