UUDECODE(1P) Manuel du programmeur POSIX UUDECODE(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uudecode — décoder un fichier binaire

SYNOPIS

uudecode [-o fichier_sortie] [fichier]

DESCRIPTION

L'utilitaire uudecode lit un fichier, ou l'entrée standard si aucun fichier n'est spécifié, qui contient des données créées par l'utilitaire uuencode. L'utilitaire uudecode parcourt le fichier d'entrée, recherchant des données compatibles avec l'un des formats spécifiés dans uuencode, et tente de créer ou d'écraser le fichier décrit par les données (ou substitué par l'option -o). Le chemin du fichier est contenu dans les données ou spécifié par l'option -o. Les bits de permissions d'accès au fichier et le contenu du fichier à produire sont contenus dans ces données. Les bits de mode du fichier créé (autre que la sortie standard) sont définis à partir des bits de permissions d'accès au fichier contenus dans les données ; c'est-à-dire que les autres attributs du mode, y compris le masque de création du mode de fichier (voir umask), n'affectent pas le fichier produit. Si l'un des caractères op '+' et '-' (voir chmod) est spécifié en mode symbolique, le mode initial sur lequel ces opérations sont basées est indéterminé.

Si le chemin du fichier résout en un fichier existant et que l'utilisateur n'a pas la permission d'écriture sur ce fichier, uudecode se terminera avec une erreur. Si le chemin du fichier résout en un fichier existant et que l'utilisateur a la permission d'écriture sur ce fichier, le fichier existant sera écrasé et, si possible, les bits de mode du fichier (autre que la sortie standard) seront définis comme décrit ci-dessus ; si les bits de mode ne peuvent pas être définis, uudecode ne traitera pas cela comme une erreur.

Si les données d'entrée ont été produites par uuencode sur un système avec un nombre de bits par octet différent de celui du système cible, les résultats de uudecode sont indéterminés.

OPTIONS

L'utilitaire uudecode doit être conforme aux directives de syntaxe utilitaire du volume Définitions de base de POSIX.1‐2017, Section 12.2.

L'implémentation doit supporter l'option suivante :

-o fichier_sortie
Le chemin d'un fichier qui sera utilisé à la place de tout chemin contenu dans les données d'entrée. Spécifier un argument d'option fichier_sortie de /dev/stdout indiquera la sortie standard.

OPÉRANDES

L'opérande suivant doit être supporté :

fichier
Le chemin d'un fichier contenant la sortie de uuencode.

STDIN

Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers contenant la sortie de uuencode.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de uudecode :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Si l'en-tête de données du fichier encodé par uuencode est - ou /dev/stdout, ou si l'option -o /dev/stdout remplace les données du fichier, la sortie standard sera dans le même format que le fichier initialement encodé par uuencode. Sinon, la sortie standard ne sera pas utilisée.

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Le fichier de sortie sera dans le même format que le fichier initialement encodé par uuencode.

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE APPLICATIF

L'utilisateur qui invoque uudecode doit avoir la permission d'écriture sur tout fichier créé.

La sortie de uuencode est essentiellement un flux de bits codé qui n'est pas conscient des frontières d'octets. Il est possible qu'une machine cible à 9 bits par octet puisse traiter une entrée provenant d'une source à 8 bits, si elle est consciente de cette exigence, mais l'inverse est peu susceptible d'être satisfaisant. Bien sûr, seules les données généralement utiles pour un tel transfert entre architectures sont des données caractères.

EXEMPLES

Aucun.

RATIONNELLE

Les fichiers d'entrée ne sont pas nécessairement des fichiers texte, comme indiqué par une proposition antérieure. Bien que la sortie de uuencode soit un fichier texte, cette sortie aurait pu être encapsulée dans un autre fichier ou un message électronique qui n'est pas un fichier texte.

L'option -o n'est pas une pratique historique, mais a été ajoutée à la demande de WG15 afin que l'utilisateur puisse remplacer le chemin cible sans avoir à éditer les données d'entrée elles-mêmes.

Dans les premières ébauches, l'argument d'option [-o fichier_sortie] autorisait l'utilisation de - pour signifier la sortie standard. Le symbole - n'a été utilisé auparavant dans POSIX.1‐2008 qu'en tant qu'indicateur d'entrée standard. Les développeurs du standard ne souhaitaient pas surcharger le sens de - de cette manière. Le concept /dev/stdout existe sur la plupart des systèmes modernes. La syntaxe /dev/stdout ne fait pas référence à un nouveau fichier spécial. C'est juste un cookie magique pour spécifier la sortie standard.
