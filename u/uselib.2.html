uselib(2) Manuel des appels système uselib(2)

NOM

uselib - charger une bibliothèque partagée

SYNTAXE

#include <unistd.h>
[[deprecated]] int uselib(const char *library);

DESCRIPTION

L'appel système uselib() sert à charger une bibliothèque partagée à utiliser par le processus appelant. Il reçoit un nom de chemin. L'adresse de chargement est trouvée dans la bibliothèque elle-même. La bibliothèque peut avoir n'importe quel format binaire reconnu.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

En plus de tous les codes d'erreur retournés par open(2) et mmap(2), les erreurs suivantes peuvent également être retournées :

EACCES
La bibliothèque spécifiée par library n'a pas les permissions de lecture ou d'exécution, ou l'appelant n'a pas la permission de recherche pour l'un des répertoires du préfixe du chemin. (Voir aussi path_resolution(7).)
ENFILE
La limite du système sur le nombre total de fichiers ouverts a été atteinte.
ENOEXEC
Le fichier spécifié par library n'est pas un exécutable d'un type connu ; par exemple, il n'a pas les nombres magiques corrects.

NORMES

Linux.

HISTORIQUE

Cet appel système obsolète n'est pas supporté par glibc. Aucune déclaration n'est fournie dans les en-têtes glibc, mais, par une bizarrerie historique, glibc avant glibc 2.23 exportait une ABI pour cet appel système. Par conséquent, afin d'employer cet appel système, il suffisait de déclarer manuellement l'interface dans votre code ; alternativement, vous pouviez invoquer l'appel système en utilisant syscall(2).

Dans les anciennes versions de libc (avant glibc 2.0), uselib() était utilisé pour charger les bibliothèques partagées dont les noms étaient trouvés dans un tableau de noms dans le binaire.

Depuis Linux 3.15, cet appel système n'est disponible que lorsque le noyau est configuré avec l'option CONFIG_USELIB.

VOIR AUSSI

ar(1), gcc(1), ld(1), ldd(1), mmap(2), open(2), dlopen(3), capabilities(7), ld.so(8)
