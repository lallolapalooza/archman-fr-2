uux(1) Manuel des commandes générales uux(1)

NOM

uux - Exécution de commandes à distance via UUCP

SYNTAXE

uux [ options ] commande

DESCRIPTION

La commande uux est utilisée pour exécuter une commande sur un système distant, ou pour exécuter une commande sur le système local en utilisant des fichiers de systèmes distants. La commande n'est pas exécutée immédiatement ; la requête est mise en file d'attente jusqu'à ce que le démon uucico (8) contacte le système et l'exécute. Le démon est démarré automatiquement à moins que l'une des options -r ou --nouucico ne soit spécifiée.

L'exécution réelle de la commande est effectuée par le démon uuxqt (8).

Les arguments de fichier peuvent être récupérés à partir de systèmes distants vers le système d'exécution, tout comme l'entrée standard. La sortie standard peut être dirigée vers un fichier sur un système distant.

Le nom de la commande peut être précédé d'un nom de système suivi d'un point d'exclamation s'il doit être exécuté sur un système distant. Un nom de système vide est considéré comme le système local.

Chaque argument contenant un point d'exclamation est traité comme le nom d'un fichier. Le système sur lequel se trouve le fichier est avant le point d'exclamation, et le chemin d'accès sur ce système suit. Un nom de système vide est considéré comme le système local ; cela doit être utilisé pour transférer un fichier vers une commande exécutée sur un système distant. Si le chemin n'est pas absolu, il sera ajouté au répertoire de travail actuel sur le système local ; le résultat peut ne pas être significatif sur le système distant. Un chemin peut commencer par ~/, auquel cas il est relatif au répertoire public UUCP (généralement /usr/spool/uucppublic ou /var/spool/uucppublic) sur le système approprié. Un chemin peut commencer par ~nom/, auquel cas il est relatif au répertoire personnel de l'utilisateur nommé sur le système approprié.

L'entrée et la sortie standard peuvent être redirigées comme d'habitude ; les chemins utilisés peuvent contenir des points d'exclamation pour indiquer qu'ils sont sur des systèmes distants. Notez que les caractères de redirection doivent être mis entre guillemets afin qu'ils soient transmis à uux plutôt qu'interprétés par le shell. La redirection d'ajout (>>) ne fonctionne pas.

Tous les fichiers spécifiés sont rassemblés dans un seul répertoire avant le début de l'exécution de la commande. Cela signifie que chaque fichier doit avoir un nom de base distinct. Par exemple, 

uux 'sys1!diff sys2!~user1/foo sys3!~user2/foo >!foo.diff'
échouera car les deux fichiers seront copiés sur sys1 et stockés sous le nom foo.

Les arguments peuvent être mis entre guillemets par des parenthèses pour éviter l'interprétation des points d'exclamation. Ceci est utile lors de l'exécution de la commande uucp sur un système distant.

Une requête pour exécuter une commande vide (par exemple, uux sys!) créera un fichier de sondage pour le système spécifié.

Le code de sortie de uux est l'un des codes trouvés dans le fichier d'en-tête sysexits.h. En particulier, EX_OK ( 0 ) indique un succès, et EX_TEMPFAIL ( 75 ) indique un échec temporaire.

OPTIONS

Les options suivantes peuvent être données à uux.

-, -p, --stdin
Lire l'entrée standard et l'utiliser comme entrée standard pour la commande à exécuter.
-c, --nocopy
Ne pas copier les fichiers locaux dans le répertoire de spool. C'est le comportement par défaut. S'ils sont supprimés avant d'être traités par le démon uucico (8), la copie échouera. Les fichiers doivent être lisibles par le démon uucico (8), ainsi que par l'appelant de uux.
-C, --copy
Copier les fichiers locaux dans le répertoire de spool.
-l, --link
Lier les fichiers locaux dans le répertoire de spool. Si un fichier ne peut pas être lié parce qu'il se trouve sur un périphérique différent, il sera copié à moins que l'une des options -c ou --nocopy n'apparaisse également (en d'autres termes, l'utilisation de --link change le comportement par défaut de --nocopy à --copy). Si les fichiers sont modifiés avant d'être traités par le démon uucico (8), les versions modifiées seront utilisées. Les fichiers doivent être lisibles par le démon uucico (8), ainsi que par l'appelant de uux.
-g grade, --grade grade
Définir la priorité du transfert de fichier. Les travaux de priorité supérieure sont exécutés en premier. Les priorités vont de 0 ... 9 A ... Z a ... z, de la plus haute à la plus basse.
-n, --notification=no
Ne pas envoyer d'e-mail sur le statut du travail, même en cas d'échec.
-z, --notification=error
Envoyer un e-mail sur le statut du travail en cas d'erreur. Pour de nombreux démons uuxqt, y compris celui de Taylor UUCP, c'est le comportement par défaut ; pour ceux-là, --notification=error n'aura aucun effet. Cependant, certains démons uuxqt enverront un e-mail si le travail réussit à moins que l'option --notification=error ne soit utilisée, et certains autres démons uuxqt n'enverront pas d'e-mail si le travail échoue à moins que l'option --notification=error ne soit utilisée.
-r, --nouucico
Ne pas démarrer le démon uucico (8) immédiatement ; simplement mettre en file d'attente la requête d'exécution pour traitement ultérieur.
-j, --jobid
Afficher les identifiants de travail sur la sortie standard. Un identifiant de travail sera généré pour chaque opération de copie de fichier requise pour effectuer l'opération. Ces copies de fichiers peuvent être annulées en passant l'identifiant de travail à l'option --kill de uustat (1), ce qui rendra l'exécution impossible à terminer.
-a address, --requestor address
Signaler le statut du travail à l'adresse e-mail spécifiée.
-x type, --debug type
Activer des types de débogage particuliers. Les types suivants sont reconnus : abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Seuls abnormal, config, spooldir et execute sont pertinents pour uux.

Plusieurs types peuvent être donnés, séparés par des virgules, et l'option --debug peut apparaître plusieurs fois. Un nombre peut également être donné, ce qui activera ce nombre de types de la liste précédente ; par exemple, --debug 2 équivaut à --debug abnormal,chat.

-I file, --config file
Définir le fichier de configuration à utiliser. Cette option peut ne pas être disponible, en fonction de la manière dont uux a été compilé.
-v, --version
Afficher les informations de version et quitter.
--help
Afficher un message d'aide et quitter.

EXEMPLES

uux -z - sys1!rmail user1

Exécute la commande ``rmail user1'' sur le système sys1, en lui fournissant comme entrée standard ce qui est fourni à uux en entrée standard. En cas d'échec, envoyer un message en utilisant mail (1).

uux 'diff -c sys1!~user1/file1 sys2!~user2/file2 >!file.diff'
Récupère les deux fichiers nommés du système sys1 et du système sys2 et exécute diff en plaçant le résultat dans file.diff dans le répertoire courant. Le répertoire courant doit être inscriptible par le démon uuxqt (8) pour que cela fonctionne. 
uux 'sys1!uucp ~user1/file1 (sys2!~user2/file2)'
Exécute uucp sur le système sys1 en copiant file1 (sur le système sys1) vers sys2. Ceci illustre l'utilisation des parenthèses pour les guillemets.

RESTRICTIONS

Le système distant peut ne pas vous autoriser à exécuter certaines commandes. De nombreux systèmes distants n'autorisent que l'exécution de rmail et rnews.

Certaines options dépendent des capacités du démon uuxqt (8) sur le système distant.

VOIR AUSSI

mail(1), uustat(1), uucp(1), uucico(8), uuxqt(8)

BOGUES

Les fichiers ne peuvent pas être référencés sur plusieurs systèmes.

Trop d'identifiants de travail sont générés par --jobid, et il n'y a pas de bon moyen d'annuler une exécution locale nécessitant des fichiers distants.
