UWSM-APP(1) Manuel des commandes générales UWSM-APP(1)

NOM

uwsm-app - Lanceur d'applications vers des unités utilisant le démon d'application de UWSM.

SYNTAXE

uwsm-app [-h] [-s {a,b,s,custom.slice}] [-t {scope,service}] [-a nom_app] [-u nom_unité] [-d description_unité] [-S ] [-T] -- application [args ...]

DESCRIPTION

Lanceur d'applications vers des unités avec prise en charge des entrées de bureau. Analogue à la commande uwsm app et utilise les mêmes arguments, car l'analyse des arguments est effectuée du côté du démon d'application avec le même analyseur.

OPTIONS

-s {a,b,s,custom.slice} Sélecteur de slice (par défaut : a) :
a - app-graphical.slice
b - background-graphical.slice
s - session-graphical.slice
n'importe quelle slice par nom complet
-t {scope,service} Type d'unité à lancer (par défaut : scope, peut être pré-défini par la variable d'environnement UWSM_APP_UNIT_TYPE).
-a nom_app Remplace le nom de l'application (une sous-chaîne dans le nom de l'unité).
-u nom_unité Remplace le nom d'unité autogénéré entier.
-d description_unité Description de l'unité.
-S {out,err,both} Silencie la sortie standard, la sortie d'erreur, ou les deux.
-T Lance l'application dans un terminal. Permet à la commande d'être vide pour simplement lancer un terminal.

L'application peut être fournie sous forme de commande avec des arguments optionnels, ou un identifiant d'entrée de bureau, éventuellement suffixé par un identifiant d'action délimité par des ":". Si une entrée de bureau est lancée, les arguments doivent lui être compatibles.

Utilisez toujours "--" pour distinguer les arguments commençant par un tiret qui sont destinés à l'application elle-même.

Arguments spéciaux qui sont transmis au démon d'application :

  • ping vérifie le démon d'application, il doit retourner "pong"
  • stop arrête le démon d'application

OPÉRATION

Le client uwsm-app envoie les arguments au démon d'application de uwsm via un pipe. Après réception des arguments, le démon d'application renvoie du code shell à uwsm-app qu'il exécute nativement. Les commandes uniques sont préfixées par exec, les commandes itérées sont assemblées avec un & final pour chacune, suivi de wait.

Le but de tout cela est d'éviter les routines coûteuses de démarrage et d'importation de Python qui ralentissent tout appel à "uwsm app". Au lieu de cela, le démon le fait une fois puis écoute les requêtes, tandis qu'un script shell simple peut envoyer les arguments dans un pipe et exécuter le code reçu d'un autre via eval, ce qui est beaucoup plus rapide.
