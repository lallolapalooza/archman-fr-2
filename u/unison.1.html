NOM

unison — outil de synchronisation de fichiers bidirectionnelle multiplateforme

SYNTAXE

unison [options]

unison racine1 racine2 [options]

unison nom_profil [options]

DESCRIPTION

Unison est un outil de synchronisation de fichiers pour les systèmes compatibles POSIX (par exemple, *BSD et GNU/Linux, macOS) et Windows. Il permet à deux répliques d'une collection de fichiers et de répertoires d'être stockées sur des machines différentes (ou des disques différents sur la même machine), modifiées séparément, puis mises à jour en propageant les modifications de chaque réplique à l'autre.

Unison est utilisé depuis plus de 20 ans et de nombreuses personnes l'utilisent pour synchroniser des données qui leur sont importantes.

Unison partage un certain nombre de fonctionnalités avec d'autres outils. Certaines de ses caractéristiques distinctives sont :

  • Contrairement aux utilitaires simples de mise en miroir ou de sauvegarde, Unison peut gérer les mises à jour des deux répliques d'une structure de répertoire distribuée.
  • Unison fonctionne sur différentes plateformes, vous permettant de synchroniser, par exemple, un ordinateur portable Windows avec un serveur Unix.
  • Contrairement à la plupart des systèmes de fichiers distribués, Unison est un programme au niveau utilisateur qui utilise simplement des appels système normaux : il n'est pas nécessaire de modifier le noyau, d'avoir des privilèges superutilisateur sur l'une ou l'autre machine, ou d'avoir une implémentation FUSE.
  • Unison fonctionne entre deux machines quelconques connectées à Internet, communiquant typiquement via ssh(1), mais aussi directement via TCP. Il est attentif à la bande passante réseau et fonctionne bien sur des liaisons lentes. Les transferts de petites mises à jour vers de gros fichiers sont optimisés en utilisant un protocole de compression similaire à rsync(1).
  • Unison est résistant aux pannes. Il veille à laisser les répliques et ses propres structures privées dans un état cohérent à tout moment, même en cas d'arrêt anormal ou de défaillance de communication.

batch
Lorsque cette option est activée sur true, l'interface utilisateur ne posera aucune question. Les modifications non conflictuelles seront propagées ; les conflits seront ignorés.
clientHostName xxx
Lorsqu'il est spécifié, le nom d'hôte du client ne sera pas deviné et le nom d'hôte fourni sera utilisé pour trouver l'archive.
color xxx
Lorsqu'elle est définie sur true, ce drapeau active la sortie couleur dans l'interface utilisateur en mode texte. Lorsqu'elle est définie sur false, toute sortie couleur est désactivée. La valeur par défaut est d'activer la couleur si la variable d'environnement NO_COLOR n'est pas définie.
confirmbigdel
Lorsque cette option est activée sur true, Unison demandera une confirmation supplémentaire s'il semble que toute la réplique a été supprimée, avant de propager la modification. Si le drapeau batch est également activé, la synchronisation sera interrompue. Lorsque la préférence path est utilisée, la même confirmation sera demandée pour les chemins de premier niveau. (Actuellement, ce drapeau n'affecte que l'interface utilisateur textuelle.) Voir également la préférence mountpoint.
confirmmerge
Définir cette préférence oblige les interfaces textuelles et graphiques à demander à l'utilisateur si les résultats d'une commande de fusion peuvent être validés dans la réplique ou non. La commande de fusion fonctionnant sur des fichiers temporaires, l'utilisateur peut alors annuler tous les effets de l'application de la fusion si le résultat s'avère insatisfaisant. En mode batch, cette préférence n'a aucun effet. La valeur par défaut est false.
contactquietly
Si ce drapeau est activé, Unison sautera l'affichage du message « Contacting server » (que certains utilisateurs trouvent agaçant) au démarrage.
copymax n
(Obsolète) Un nombre indiquant combien d'instances de l'utilitaire de copie externe Unison est autorisé à exécuter simultanément (par défaut 1).
copyonconflict
Lorsque ce drapeau est activé, Unison créera une copie des fichiers qui seraient autrement écrasés ou supprimés en cas de conflits de modification, et plus généralement lorsque le comportement par défaut est remplacé. Cela permet de résoudre automatiquement les conflits de manière assez sûre lors de la synchronisation continue, en combinaison avec les préférences -repeat watch et -prefer newer.
copyprog xxx
(Obsolète) Une chaîne de caractères donnant le nom d'un programme externe pouvant être utilisé pour copier efficacement de gros fichiers (plus les options de ligne de commande lui indiquant de copier les fichiers en place). Le paramètre par défaut invoque rsync avec les options appropriées — la plupart des utilisateurs ne devraient pas avoir besoin de le modifier.
copyprogrest xxx
(Obsolète) Une variante de copyprog qui nomme un programme externe devant être utilisé pour continuer le transfert d'un gros fichier déjà partiellement transféré. Typiquement, copyprogrest sera simplement copyprog avec une option supplémentaire (par exemple, --partial, pour rsync). Le paramètre par défaut invoque rsync avec les options appropriées — la plupart des utilisateurs ne devraient pas avoir besoin de le modifier.
copythreshold n
(Obsolète) Un nombre indiquant au-dessus de quelle taille de fichier (en kilo-octets) Unison doit utiliser l'utilitaire de copie externe spécifié par copyprog. Spécifier 0 fera en sorte que toutes les copies utilisent le programme externe ; un nombre négatif empêchera tout fichier de l'utiliser. La valeur par défaut est -1. Voir la section “Rendre Unison plus rapide sur les gros fichiers” dans le manuel pour plus d'informations.
debug xxx
Cette préférence est utilisée pour que Unison affiche diverses informations sur ce qu'il fait en interne sur le flux d'erreurs standard. Elle peut être utilisée plusieurs fois, chaque fois avec le nom d'un module pour lequel des informations de débogage doivent être affichées. Les arguments possibles pour debug peuvent être trouvés en recherchant les appels à Util.debug dans les sources (en utilisant, par exemple, grep). Définir -debug all provoque l'affichage d'informations provenant de tous les modules (ce mode d'utilisation est le premier à essayer si vous essayez de comprendre quelque chose que Unison semble faire de travers) ; -debug verbose active des informations de débogage supplémentaires de certains modules (par exemple, il montrera exactement quels octets sont envoyés sur le réseau).
diff xxx
Cette préférence peut être utilisée pour contrôler le nom et les arguments de ligne de commande de l'utilitaire système utilisé pour générer les affichages de différences de fichiers. La valeur par défaut est `diff -u OLDER NEWER'. Si la valeur de cette préférence contient les sous-chaînes CURRENT1 et CURRENT2, elles seront remplacées par les noms des fichiers à comparer. Si la valeur de cette préférence contient les sous-chaînes NEWER et OLDER, elles seront remplacées par les noms des fichiers à comparer, NEWER étant le fichier le plus récemment modifié des deux. Sans aucune de ces sous-chaînes, les deux noms de fichiers seront ajoutés à la commande. Dans tous les cas, les noms de fichiers sont correctement cités.
doc xxx
L'argument de ligne de commande -doc secname demande à unison d'afficher la section secname du manuel sur la sortie standard puis de se terminer. Utilisez -doc all pour afficher l'intégralité du manuel, qui contient exactement les mêmes informations que les manuels imprimé et HTML, à la mise en forme près. Utilisez -doc topics pour obtenir une liste des noms des différentes sections qui peuvent être imprimées.
dontchmod
Par défaut, Unison utilise l'appel système « chmod » pour définir les bits d'autorisation des fichiers après les avoir copiés. Mais dans certaines circonstances (et sous certains systèmes d'exploitation), l'appel chmod échoue toujours. La définition de cette préférence empêche complètement Unison d'appeler chmod.
dumbtty
Lorsqu'il est réglé sur true, ce drapeau évite à l'interface utilisateur en mode texte d'essayer de modifier les paramètres du terminal. (Normalement, Unison met le terminal en « mode brut », afin de pouvoir faire des choses comme écraser la ligne courante.) Ceci est utile, par exemple, lorsque Unison s'exécute dans un shell à l'intérieur d'Emacs. Lorsque dumbtty est activé, les commandes de l'interface utilisateur doivent être suivies d'un retour chariot avant qu'Unison ne les exécute. (Lorsqu'il est désactivé, Unison reconnaît les frappes dès qu'elles sont tapées.) Cette préférence n'a aucun effet sur l'interface utilisateur graphique.
dumparchives
Lorsque cette préférence est activée, Unison créera un fichier unison.dump sur chaque hôte, contenant un résumé textuel de l'archive, immédiatement après l'avoir chargée.
fastcheck xxx
Lorsque cette préférence est réglée sur true, Unison utilisera l'heure de modification et la longueur d'un fichier comme « pseudo numéro d'inode » lors de l'analyse des répliques pour les mises à jour, au lieu de lire le contenu complet de chaque fichier. (Cela ne s'applique pas à la toute première exécution, où Unison analysera toujours tous les fichiers, quel que soit leur
ess de ce commutateur). Sous Windows, cela peut amener Unison à manquer la propagation d'une mise à jour si l'heure de modification et la longueur du fichier ne sont pas modifiées par la mise à jour. Cependant, Unison ne écrasera jamais une telle mise à jour avec un changement provenant de l'autre réplique, car il effectue toujours une vérification de sécurité des mises à jour juste avant de propager un changement. Ainsi, il est raisonnable d'utiliser ce commutateur sous Windows la plupart du temps et d'exécuter occasionnellement Unison une fois avec fastcheck défini sur false, si vous craignez qu'Unison n'ait négligé une mise à jour. Pour la compatibilité ascendante, yes, no, et default peuvent être utilisés à la place de true, false, et auto. Voir la section « Détection rapide des mises à jour » du manuel pour plus d'informations.
fastercheckUNSAFE
CETTE FONCTIONNALITÉ EST ENCORE EXPÉRIMENTALE ET DOIT ÊTRE UTILISÉE AVEC UNE EXTRÊME PRUDENCE. Lorsque ce drapeau est défini sur true, Unison calculera une « empreinte pseudo » la première fois qu'il verra un fichier (soit parce que le fichier est nouveau, soit parce qu'Unison s'exécute pour la première fois). Cela accélère énormément la détection des mises à jour, mais elle doit être utilisée avec précaution, car elle peut amener Unison à manquer des conflits : si un chemin donné dans le système de fichiers contient des fichiers des deux côtés que Unison n'a pas encore vus, et si ces fichiers ont la même longueur mais un contenu différent, alors Unison ne remarquera pas la présence d'un conflit. Si, plus tard, l'un des fichiers est modifié, le fichier modifié sera propagé, écrasant l'autre. De plus, même lorsque les fichiers sont initialement identiques, la définition de ce drapeau peut entraîner un comportement potentiellement déroutant : si un fichier nouvellement créé est ensuite touché sans être modifié, Unison le traitera conservativement comme un changement potentiel (car il n'a aucun enregistrement du contenu précédent) et l'affichera comme nécessitant d'être propagé à l'autre réplique. La plupart des utilisateurs devraient laisser ce drapeau désactivé – le petit gain de temps lié au fait de ne pas calculer l'empreinte des nouveaux fichiers ne vaut pas le coût en termes de sécurité. Cependant, cela peut être très utile pour les utilisateurs expérimentés disposant d'énormes répliques dont on sait qu'elles sont déjà synchronisées (par exemple, parce qu'une réplique est une copie nouvellement créée de l'autre, ou parce qu'elles ont déjà été synchronisées avec Unison mais que les archives d'Unison doivent être reconstruites). Dans de telles situations, il est recommandé de définir ce drapeau uniquement pour la première exécution d'Unison, afin que les nouvelles archives puissent être créées rapidement, puis de le désactiver pour une utilisation normale.
fat
Lorsque ceci est défini sur true, Unison utilisera les options appropriées pour synchroniser efficacement et sans erreur une réplique située sur un système de fichiers FAT sur une machine non Windows : ne pas synchroniser les permissions (perms = 0) ; ne jamais utiliser chmod (dontchmod = true) ; traiter les noms de fichiers comme non sensibles à la casse (ignorecase = true) ; ne pas tenter de synchroniser les liens symboliques (links = false) ; ignorer les changements d'identifiants d'inœuds lors de la détection des mises à jour (ignoreinodenumbers = true). Chacun de ces changements peut être outrepassé en définissant explicitement la préférence correspondante dans le profil.
follow xxx
L'inclusion de la préférence -follow pathspec fait que Unison traite les liens symboliques correspondant à pathspec comme « invisibles » et se comporte comme si l'objet pointé par le lien était apparu littéralement à cet endroit dans la réplique. Voir la section « Liens symboliques » du manuel pour plus de détails. La syntaxe de pathspec est décrite dans la section « Spécification de chemin » du manuel.
force xxx
L'inclusion de la préférence -force root fait que Unison résout toutes les différences (même les changements non conflictuels) en faveur de root. Cela transforme efficacement Unison d'un synchroniseur en un utilitaire de mise en miroir. Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Vous pouvez également spécifier -force newer (ou -force older) pour forcer Unison à choisir le fichier avec le modtime le plus récent (le plus ancien). Dans ce cas, la préférence -times doit également être activée. Si les modtimes sont égaux dans les deux répliques lors de l'utilisation de newer ou older, cette préférence n'aura aucun effet (les changements seront synchronisés comme s'il n'y avait pas cette préférence ou resteront non synchronisés en cas de conflit). Cette préférence est outrepassée par la préférence forcepartial. Cette préférence ne doit être utilisée que si vous êtes sûr de savoir ce que vous faites !
forcepartial xxx
L'inclusion de la préférence forcepartial = PATHSPEC -> root fait que Unison résout toutes les différences (même les changements non conflictuels) en faveur de root pour les fichiers dans PATHSPEC (voir la section « Spécification de chemin » du manuel pour plus d'informations). Cela transforme efficacement Unison d'un synchroniseur en un utilitaire de mise en miroir. Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Vous pouvez également spécifier forcepartial PATHSPEC -> newer (ou forcepartial PATHSPEC -> older) pour forcer Unison à choisir le fichier avec le modtime le plus récent (le plus ancien). Dans ce cas, la préférence -times doit également être activée. Si les modtimes sont égaux dans les deux répliques lors de l'utilisation de newer ou older, cette préférence n'aura aucun effet (les changements seront synchronisés comme s'il n'y avait pas cette préférence ou resteront non synchronisés en cas de conflit). Cette préférence ne doit être utilisée que si vous êtes sûr de savoir ce que vous faites !
group
Lorsque ce drapeau est défini sur true, les attributs de groupe des fichiers sont synchronisés. Si les noms de groupe ou les identifiants de groupe sont synchronisés dépend de la préférence numerids.
halfduplex
(Obsolète) Lorsque ce drapeau est défini sur true, la communication réseau d'Unison est forcée d'être en semi-duplex (le client et le serveur n'émettent jamais de données simultanément). Si vous rencontrez des instabilités avec votre connexion réseau, cela peut aider.
height n
Utilisé pour définir la hauteur (en lignes) de la fenêtre principale dans l'interface graphique.
i
Fournit cette préférence dans les arguments de la ligne de commande pour activer le gestionnaire de profils interactif dans l'interface utilisateur textuelle. Actuellement, seuls le listage des profils et la sélection interactive sont disponibles. Les préférences telles que batch et silent restent applicables aux fonctionnalités de synchronisation.
ignore xxx
L'inclusion de la préférence -ignore pathspec fait que Unison ignore complètement les chemins qui correspondent à pathspec (ainsi que leurs enfants). Ceci est utile pour éviter de synchroniser des fichiers temporaires, des fichiers objets, etc. La syntaxe de pathspec est décrite dans la section « Spécification de chemin » du manuel, et des détails supplémentaires sur l'ignorance des chemins se trouvent dans la section « Ignorer les chemins » du manuel.
ignorearchives
Lorsque cette préférence est définie, Unison ignorera tous les fichiers d'archives existants et se comportera comme s'il était exécuté pour la première fois sur ces rplicas. Il n'est pas conseillé de définir cette option dans un profil : elle est prévue pour une utilisation en ligne de commande.
ignorecase xxx
Lorsqu'elle est définie sur true, cette option fait en sorte qu'Unison traite les noms de fichiers comme insensibles à la casse, c'est-à-dire que les fichiers des deux répliques dont les noms diffèrent par l'orthographe (majuscules et minuscules) sont traités comme le même fichier. Lorsque l'option est définie sur false, Unison traitera tous les noms de fichiers comme sensibles à la casse. Normalement, lorsque l'option est définie sur default, les noms de fichiers sont automatiquement considérés comme insensibles à la casse si l'un des hôtes exécute Windows ou OSX. Dans de rares cas, il peut être utile de définir l'option manuellement.
ignoreinodenumbers
Lorsqu'elle est définie sur true, cette préférence indique à Unison de ne pas utiliser les numéros d'inode lors de la détection rapide des mises à jour. Cette option doit être utilisée avec précaution, car elle est moins sûre que la méthode standard de détection des mises à jour, mais elle peut être utile avec les systèmes de fichiers qui ne prennent pas en charge les numéros d'inode.
ignorelocks
Lorsque cette préférence est définie, Unison ignorera tous les fichiers de verrouillage qui pourraient avoir été laissés par une exécution précédente d'Unison qui a été interrompue lors de la lecture ou de l'écriture de fichiers d'archives ; par défaut, lorsqu'Unison voit ces fichiers de verrouillage, il s'arrête et demande une intervention manuelle. Cette option ne doit être définie que si vous êtes certain qu'aucune autre instance d'Unison n'accède simultanément aux mêmes fichiers d'archives (par exemple, parce qu'il n'y avait qu'une seule instance d'Unison en cours d'exécution et qu'elle vient de planter ou que vous venez de la tuer). Il n'est probablement pas conseillé de définir cette option dans un profil : elle est prévue pour une utilisation en ligne de commande.
ignorenot xxx
Cette préférence remplace la préférence ignore. Elle donne une liste de motifs (dans le même format que ignore) pour les chemins qui ne doivent absolument pas être ignorés, même s'ils correspondent à l'un des motifs ignore. Notez que la sémantique de ignore et ignorenot est un peu contre-intuitive. Lors de la détection des mises à jour, Unison examine les chemins dans l'ordre de parcours en profondeur, en partant des racines des répliques et en descendant. Avant d'examiner chaque chemin, il vérifie s'il correspond à ignore et ne correspond pas ignorenot ; dans ce cas, il saute ce chemin et tous ses descendants. Cela signifie que, si un parent d'un chemin donné correspond à un motif ignore, il sera ignoré même si le chemin lui-même correspond à un motif ignorenot. En particulier, mettre ignore = Chemin * dans votre profil et utiliser ensuite ignorenot pour sélectionner des chemins spécifiques à synchroniser ne fonctionnera pas. Au lieu de cela, vous devriez utiliser la préférence path pour choisir les chemins spécifiques à synchroniser.
immutable xxx
Cette préférence spécifie les chemins des répertoires dont les enfants immédiats sont tous des fichiers immuables, c'est-à-dire qu'une fois qu'un fichier a été créé, son contenu ne change jamais. Lors de l'analyse des mises à jour, Unison ne vérifie pas si ces fichiers ont été modifiés ; cela peut considérablement accélérer la détection des mises à jour (en particulier pour les répertoires de courrier).
immutablenot xxx
Cette préférence remplace immutable.
include xxx
Inclut les préférences d'un profil. include nom lit le profil “nom” (ou le fichier “nom” dans le répertoire .unison si le profil “nom” n'existe pas) et inclut son contenu comme s'il faisait partie d'un profil ou était donné directement en ligne de commande.
key xxx
Utilisé dans un profil pour définir une clé numérique (0-9) qui peut être utilisée dans l'interface utilisateur pour passer immédiatement à ce profil.
killserver
Lorsqu'elle est définie sur true, cette option fait en sorte qu'Unison tue le processus serveur distant une fois la synchronisation terminée. Ce comportement est le défaut pour les connexions ssh, donc cette préférence n'est normalement pas nécessaire lorsqu'on utilise ssh ; elle est fournie pour que les serveurs en mode socket puissent être tués après une seule exécution d'Unison, plutôt que d'attendre de futures connexions. (Certains utilisateurs préfèrent lancer un serveur socket distant pour chaque exécution d'Unison, plutôt que d'en laisser un tourner en permanence.)
label xxx
Utilisé dans un profil pour fournir une chaîne descriptive documentant ses paramètres. (Ceci est utile pour les utilisateurs qui basculent entre plusieurs profils, en particulier en utilisant la fonction de 'commutation rapide' de l'interface utilisateur graphique.)
links xxx
Lorsqu'elle est définie sur true, cette option fait en sorte qu'Unison synchronise les liens symboliques. Lorsque l'option est définie sur false, les liens symboliques seront ignorés lors de la détection des mises à jour. Normalement, lorsque l'option est définie sur default, les liens symboliques sont synchronisés sauf lorsqu'un des hôtes exécute Windows. Sur un client Windows, Unison tente de détecter si les liens symboliques sont pris en charge et autorisés par les privilèges de l'utilisateur. Vous pourriez avoir besoin de privilèges élevés pour créer des liens symboliques. Lorsque l'option est définie sur default et que les liens symboliques ne peuvent pas être synchronisés, une erreur est générée lors de la détection des mises à jour.
listen xxx
Lorsqu'il agit en tant que serveur sur un socket TCP, Unison écoutera par défaut sur l'adresse "any" (0.0.0.0 et [::]). Cet argument de ligne de commande permet de spécifier une adresse d'écoute différente et peut être répété pour écouter sur plusieurs adresses. L'adresse d'écoute peut être spécifiée comme un nom d'hôte ou une adresse IP.
log
Lorsque cette option est définie, Unison enregistrera toutes les modifications apportées aux systèmes de fichiers dans un fichier.
logfile xxx
Par défaut, les messages de journalisation seront ajoutés au fichier unison.log dans votre répertoire .unison. Définissez cette préférence si vous préférez un autre fichier. Il peut s'agir d'un chemin relatif à votre répertoire .unison. L'envoi de SIGUSR1 fermera le fichier journal ; le fichier journal sera rouvert (et créé, si nécessaire) automatiquement, pour permettre la rotation des journaux.
maxbackups n
Cette préférence spécifie le nombre de versions de sauvegarde qui seront conservées par Unison, pour chaque chemin qui correspond au prédicat backup. La valeur par défaut est 2.
maxerrors n
Cette préférence contrôle le nombre d'erreurs après lequel Unison interrompt le transfert d'un répertoire. La définir sur un grand nombre permet à Unison de transférer la plupart d'un répertoire même lorsque certains fichiers ne parviennent pas à être copiés. La valeur par défaut est 1. Si la préférence est définie trop haut, Unison peut prendre beaucoup de temps pour s'interrompre en cas d'échecs répétés (par exemple, lorsque le disque est plein).
maxsizethreshold n
Un nombre indiquant au-dessus de quelle taille de fichier (en kilo-octets) Unison signalera un conflit au lieu de transférer le fichier. Ce conflit subsiste même en présence des options force ou prefer. Un nombre négatif autorisera tout transfert indépendamment de la taille. La valeur par défaut est -1.
maxthreads n
Cette préférence contrôle le niveau de concurrence autorisé pendant la phase de transport. Normalement, elle devrait être réglée à une valeur raisonnablement élevée pour maximiser les performances, mais lorsque Unison est utilisé sur une liaison à faible bande passante, il peut être utile de la régler plus bas (par exemple à 1) afin qu'Unison n'absorbe pas toute la bande passante disponible. La valeur par défaut est la valeur spéciale 0, qui signifie 20 threads lorsque le streaming du contenu des fichiers est désactivé et 1000 threads lorsqu'il est activé.
merge xxx
Cette préférence peut être utilisée pour exécuter un programme de fusion qui créera une nouvelle version pour chacun des fichiers et la sauvegarde, avec la dernière sauvegarde et les deux répliques. La syntaxe de pathspec -> cmd est décrite dans la Section « Spécification de chemin » du manuel, et plus de détails sur les fonctions de fusion sont présents dans la Section « Fusion des versions conflictuelles » du manuel.
mountpoint xxx
L'inclusion de la préférence -mountpoint PATH amène Unison à vérifier, à la fin de la détection des mises à jour, que PATH existe dans chaque racine, et à abandonner si ce n'est pas le cas. Cela peut éviter de synchroniser lorsque le média amovible n'est pas monté. Cette préférence peut être donnée plus d'une fois. Voir la Section « Points de montage et médias amovibles » du manuel.
moves-experimental
Lorsque cette préférence est définie, Unison tentera d'éviter de transférer le contenu des fichiers sur le réseau, ou de faire une copie locale, en reconnaissant quand un fichier ou un répertoire a été renommé ou déplacé vers un nouvel emplacement. Cela permet généralement de ne propager que le renommage, sans transférer ni copier de données. La valeur par défaut est false. Cette fonctionnalité est actuellement expérimentale et peut changer de manière incompatible dans les futures versions.
nocreation xxx
L'inclusion de la préférence -nocreation root empêche Unison d'effectuer toute création de fichier sur la racine root. Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Cette préférence peut être incluse deux fois, une fois pour chaque racine, si vous souhaitez empêcher toute création.
nocreationpartial xxx
L'inclusion de la préférence nocreationpartial = PATHSPEC -> root empêche Unison d'effectuer toute création de fichier dans PATHSPEC sur la racine root (voir la Section « Spécification de chemin » du manuel pour plus d'informations). Il est recommandé d'utiliser des motifs BelowPath lors de la sélection d'un répertoire et de tout son contenu.
nodeletion xxx
L'inclusion de la préférence -nodeletion root empêche Unison d'effectuer toute suppression de fichier sur la racine root. Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Cette préférence peut être incluse deux fois, une fois pour chaque racine, si vous souhaitez empêcher toute suppression.
nodeletionpartial xxx
L'inclusion de la préférence nodeletionpartial = PATHSPEC -> root empêche Unison d'effectuer toute suppression de fichier dans PATHSPEC sur la racine root (voir la Section « Spécification de chemin » du manuel pour plus d'informations). Il est recommandé d'utiliser des motifs BelowPath lors de la sélection d'un répertoire et de tout son contenu.
noupdate xxx
L'inclusion de la préférence -noupdate root empêche Unison d'effectuer toute mise à jour ou suppression de fichier sur la racine root. Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Cette préférence peut être incluse deux fois, une fois pour chaque racine, si vous souhaitez empêcher toute mise à jour.
noupdatepartial xxx
L'inclusion de la préférence noupdatepartial = PATHSPEC -> root empêche Unison d'effectuer toute mise à jour ou suppression de fichier dans PATHSPEC sur la racine root (voir la Section « Spécification de chemin » du manuel pour plus d'informations). Il est recommandé d'utiliser des motifs BelowPath lors de la sélection d'un répertoire et de tout son contenu.
numericids
Lorsque ce drapeau est défini sur true, les groupes et les utilisateurs sont synchronisés numériquement, plutôt que par nom. Le uid spécial 0 et le groupe spécial 0 ne sont jamais mappés via les noms d'utilisateur/groupe même si cette préférence n'est pas définie.
owner
Lorsque ce drapeau est défini sur true, les attributs du propriétaire des fichiers sont synchronisés. Le fait que les noms de propriétaire ou les identifiants de propriétaire soient synchronisés dépend de la préférence numerids.
path xxx
Lorsqu'aucune préférence path n'est donnée, Unison synchronisera simplement les deux répliques entières, en commençant par la paire de racines donnée. Si une ou plusieurs préférences path sont données, alors Unison synchronisera uniquement ces chemins et leurs enfants. (Ceci est utile pour effectuer une synchronisation rapide d'un seul répertoire, par exemple.) Notez que les préférences path sont interprétées littéralement — ce ne sont pas des expressions régulières.
perms n
La valeur entière de cette préférence est un masque indiquant quels bits de permission doivent être synchronisés. Elle est définie par défaut à $0o1777$ : tous les bits sauf les bits set-uid et set-gid sont synchronisés (la synchronisation de ces derniers bits peut présenter un risque de sécurité). Si vous souhaitez synchroniser tous les bits, vous pouvez définir la valeur de cette préférence à $-1$. Si l'une des répliques se trouve sur un système de fichiers FAT [Windows], vous devriez envisager d'utiliser la préférence fat au lieu de cette préférence. Si vous avez besoin qu'Unison ne définisse pas du tout les permissions, définissez la valeur de cette préférence à $0$ et la préférence dontchmod à true.
prefer xxx
L'inclusion de la préférence -prefer root amène Unison à résoudre systématiquement les conflits en faveur de root, plutôt que de demander des instructions à l'utilisateur, sauf pour les chemins marqués par la préférence merge. (La syntaxe de root est la même que pour la préférence root, plus les valeurs spéciales newer et older.) Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin de l'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Cette préférence est outrepassée par la préférence preferpartial
preferpartial xxx
Inclure la préférence preferpartial = PATHSPEC -> root cause Unison à résoudre toujours les conflits en faveur de root, plutôt que de demander des conseils à l'utilisateur, pour les fichiers dans PATHSPEC (voir la Section “Spécification de chemin” dans le manuel pour plus d'informations). (La syntaxe de root est la même que pour la préférence root, plus les valeurs spéciales newer et older.) Vous pouvez également spécifier un préfixe ou un suffixe unique du chemin d'une des racines ou un préfixe unique du nom d'hôte d'une racine distante. Cette préférence ne doit être utilisée que si vous êtes sûr de savoir ce que vous faites !
repeat xxx
Définir cette préférence amène l'interface en mode texte à se synchroniser de manière répétée, plutôt que de le faire une seule fois et de s'arrêter. Si l'argument est un nombre, Unison fera une pause pendant ce nombre de secondes avant de recommencer. Lorsque l'argument est watch, Unison s'appuie sur un processus externe de surveillance de fichiers pour se synchroniser chaque fois qu'un changement se produit. Vous pouvez combiner les deux avec un caractère + pour utiliser la surveillance de fichiers et également effectuer un scan complet toutes les secondes spécifiées. Par exemple, watch+3600 réagira aux changements immédiatement et effectuera en outre un scan complet toutes les heures.
retry n
Définir cette préférence amène l'interface en mode texte à réessayer de synchroniser les chemins mis à jour dont la synchronisation échoue. Chaque chemin sera essayé N fois.
root xxx
Chaque utilisation de cette préférence nomme la racine de l'une des répliques pour que Unison se synchronise. Exactement deux racines sont nécessaires, donc les modes d'usage normaux consistent soit à donner deux valeurs pour root dans le profil, soit à ne donner aucune valeur dans le profil et à en fournir deux sur la ligne de commande. Les détails de la syntaxe des racines se trouvent dans la Section “Racines” dans le manuel. Les deux racines peuvent être données dans n'importe quel ordre ; Unison les triera dans un ordre canonique avant de faire quoi que ce soit d'autre. Il essaie également de « canoniser » les noms de machines et les chemins qui apparaissent dans les racines, de sorte que, si Unison est invoqué plus tard avec un nom légèrement différent pour la même racine, il sera capable de retrouver les bonnes archives.
rootalias xxx
Lors du calcul du nom des fichiers d'archive pour une paire de racines donnée, Unison remplace toute racine correspondant au côté gauche de toute règle de rootalias par le côté droit correspondant.
rsrc xxx
Lorsqu'il est défini sur true, ce drapeau amène Unison à synchroniser les forks de ressources et les métadonnées HFS. Sur les systèmes de fichiers qui ne prennent pas en charge nativement les forks de ressources, ces données sont stockées dans des fichiers ._AppleDouble compatibles Carbon. Lorsque le drapeau est défini sur false, Unison ne synchronisera pas ces données. Normalement, le drapeau est défini sur default, et ces données sont automatiquement synchronisées si l'un des hôtes exécute OSX. Dans de rares circonstances, il est utile de définir le drapeau manuellement.
rsync
Unison utilise l'« algorithme rsync » pour le transfert des mises à jour de gros fichiers « uniquement par différence ». Définir ce drapeau sur false amène Unison à utiliser des transferts de fichiers entiers à la place. Dans des circonstances normales, il n'y a aucune raison de le faire, mais si vous rencontrez des problèmes répétés d'erreurs de « rsync failure », le définir sur false devrait vous permettre de synchroniser les fichiers incriminés.
selftest
Exécute les tests internes et quitte. Cette option est principalement destinée aux développeurs et doit être utilisée avec prudence : en particulier, elle supprimera le contenu des deux racines, afin de pouvoir installer ses propres fichiers pour les tests. Ce drapeau n'a de sens que sur la ligne de commande. Lorsqu'il est fourni, aucun fichier de préférences n'est lu : toutes les préférences doivent être spécifiées sur la ligne de commande. De plus, étant donné que la procédure d'auto-test implique l'écrasement des racines et du répertoire de sauvegarde, les noms des racines et de la préférence backupdir doivent inclure la chaîne « test » sous peine d'interruption des tests. (Si ceux-ci ne sont pas fournis sur la ligne de commande, des sous-répertoires factices dans le répertoire courant seront créés automatiquement.)
servercmd xxx
Cette préférence peut être utilisée pour définir explicitement le nom de l'exécutable Unison sur le serveur distant (par exemple, en donnant un chemin complet), si nécessaire.
showarchive
Lorsque cette préférence est définie, Unison affichera les « vrais noms » des racines, sous la même forme que celle attendue par la préférence rootalias.
silent
Lorsque cette préférence est définie sur true, l'interface utilisateur textuelle ne rien afficher du tout, sauf en cas d'erreurs. Définir silent sur true définit automatiquement la préférence batch sur true.
socket xxx
Démarre unison en tant que serveur écoutant sur un socket TCP (avec le numéro de port TCP comme argument) ou un socket local (alias socket Unix) (avec le chemin du socket comme argument).
sortbysize
Lorsque ce drapeau est défini, l'interface utilisateur listera les fichiers modifiés par taille (du plus petit au plus grand) plutôt que par nom. Ceci est utile, par exemple, pour la synchronisation sur des liaisons lentes, car cela place les très gros fichiers à la fin de la liste où ils n'empêcheront pas les petits fichiers d'être transférés rapidement. Cette préférence (ainsi que les autres drapeaux de tri, mais pas les préférences de tri qui nécessitent des motifs comme arguments) peut être définie interactivement et temporairement en utilisant le menu 'Sort' dans les interfaces utilisateur graphiques et textuelles.
sortfirst xxx
Chaque argument de sortfirst est un motif pathspec, qui décrit un ensemble de chemins. Les fichiers correspondant à l'un de ces motifs seront listés en premier dans l'interface utilisateur. La syntaxe de pathspec est décrite dans la Section “Spécification de chemin” dans le manuel.
sortlast xxx
Similaire à sortfirst, sauf que les fichiers correspondant à l'un de ces motifs seront listés à la toute fin.
sortnewfirst
Lorsque ce drapeau est défini, l'interface utilisateur listera les nouveaux fichiers créés avant tous les autres. Ceci est utile, par exemple, pour vérifier que les nouveaux fichiers créés ne sont pas du « junk », c'est-à-dire ceux qui devraient être ignorés ou supprimés plutôt que synchronisés.
source xxx
Inclure les préférences d'un fichier. source name lit le fichier “name” dans le répertoire .unison et inclut son contenu comme s'il faisait partie d'un profil ou était donné directement sur la ligne de commande.
sshargs xxx
La chaîne de caractères de cette préférence sera passée comme arguments supplémentaires (outre le nom d'hôte et le nom de l'exécutable Unison sur le système distant) à la commande ssh utilisée pour invoquer le serveur distant. Le caractère antislash est un caractère d'échappement.
sshcmd">sshcmd xxx
Cette préférence peut être utilisée pour définir explicitement le nom de l'exécutable ssh (par exemple, en donnant un nom de chemin complet), si nécessaire.
stream
(Obsolète) Lorsque cette préférence est définie, Unison utilisera un protocole de streaming expérimental pour transférer le contenu des fichiers plus efficacement. La valeur par défaut est true.
terse
Lorsque cette préférence est définie sur true, l'interface utilisateur n'affichera pas de messages de statut.
testserver
Définir ce drapeau sur la ligne de commande amène Unison à tenter de se connecter au serveur distant et, si la connexion réussit, à afficher un message et à quitter immédiatement. Utile pour le débogage des problèmes d'installation. Ne doit pas être défini dans les fichiers de préférences.
times
Lorsque ce drapeau est défini sur true, les heures de modification des fichiers (mais pas les heures de modification des répertoires) sont propagées.
ui xxx
Cette préférence sélectionne soit l'interface utilisateur graphique, soit l'interface utilisateur textuelle. Les valeurs autorisées sont graphic ou text. Comme cette option est traitée spécialement pendant la séquence de démarrage d'Unison, elle ne peut que être utilisée sur la ligne de commande. Dans les fichiers de préférences, elle n'a aucun effet. Si l'exécutable Unison a été compilé avec seulement une interface textuelle, cette option n'a aucun effet. (Les binaires précompilés sont tous compilés avec les deux interfaces disponibles.)
unicode xxx
Lorsqu'il est défini sur true, ce drapeau amène Unison à effectuer des comparaisons de fichiers insensibles à la casse en supposant un encodage Unicode. C'est la valeur par défaut. Lorsque le drapeau est défini sur false, l'encodage Latin 1 est supposé (cela signifie que tous les octets qui ne sont pas des lettres dans l'encodage Latin 1 seront comparés octet par octet, même s'ils peuvent être des caractères valides dans un autre encodage). Lorsque Unison s'exécute en mode sensible à la casse, ce drapeau ne fait une différence que si un hôte exécute Mac OS X. Sous Mac OS X, il détermine s'il faut comparer les noms de fichiers jusqu'à la décomposition, ou octet par octet.
version
Affiche le numéro de version actuel et quitte. (Cette option n'a de sens que sur la ligne de commande.)
watch
Unison utilise un processus de surveillance de fichiers, lorsque disponible, pour détecter les changements du système de fichiers ; ceci est utilisé pour accélérer la détection des mises à jour. Définir ce drapeau sur false désactive l'utilisation de ce processus.
xattrignore xxx
Préférence -xattrignore namespec amène Unison à ignorer les attributs étendus dont les noms correspondent à namespec. Ceci peut être utilisé pour exclure les attributs étendus qui échoueraient à la synchronisation en raison d'un manque de permissions ou de différences techniques entre les répliques. La syntaxe de namespec est la même que celle utilisée pour la spécification de chemin (décrite dans la Section “Spécification de Chemin” du manuel) ; préférez les formes Path et Regex à la forme Name. Le motif s'applique au nom de l'attribut étendu, pas au chemin. Sous Linux, les attributs dans les espaces de noms security et trusted sont ignorés par défaut (ceci est réalisé par le motif Regex !security[.].*); également les attributs utilisés pour stocker les ACL POSIX sont ignorés par défaut (ceci est réalisé par le motif Path !system.posix_acl_*). Pour synchroniser les attributs dans un ou deux de ces espaces de noms, voir la préférence xattrignorenot. Notez que le nom de l'espace de noms doit être préfixé par un "!" (s'applique uniquement sous Linux). Tous les noms non préfixés par un "!" sont considérés comme appartenant strictement à l'espace de noms utilisateur et donc le préfixe "!user." n'est jamais utilisé.
xattrignorenot xxx
Cette préférence remplace la préférence xattrignore. Elle donne une liste de motifs (dans le même format que xattrignore) pour les attributs étendus qui ne devraient pas être ignorés, qu'ils correspondent ou non à l'un des motifs xattrignore. Il est possible de synchroniser uniquement les attributs souhaités en ignorant tous les attributs (par exemple, en définissant xattrignore sur Path * puis en ajoutant xattrignorenot pour les attributs étendus qui devraient être synchronisés. Sous Linux, les attributs dans les espaces de noms security et trusted sont ignorés par défaut. Pour synchroniser les attributs dans un ou deux de ces espaces de noms, vous pouvez ajouter un motif xattrignorenot comme Path !security.* pour synchroniser tous les attributs de l'espace de noms security, ou Path !security.selinux pour synchroniser un attribut spécifique dans un espace de noms autrement ignoré. Un motif comme Path !system.posix_acl_* peut être utilisé pour synchroniser les ACL POSIX sous Linux. Notez que le nom de l'espace de noms doit être préfixé par un "!" (s'applique uniquement sous Linux). Tous les noms non préfixés par un "!" sont considérés comme appartenant strictement à l'espace de noms utilisateur et donc le préfixe "!user." n'est jamais utilisé.
xattrs
Lorsque ce drapeau est défini sur true, les attributs étendus des fichiers et répertoires sont synchronisés. Les attributs étendus système ne sont pas synchronisés.
xferbycopying
Lorsque cette préférence est définie, Unison essaie d'éviter de transférer le contenu des fichiers sur le réseau en reconnaissant quand un fichier avec le contenu requis existe déjà dans la réplique cible. Ceci permet généralement de propager très rapidement les déplacements de fichiers. La valeur par défaut est true.

ROOTS

La racine d'une réplique indique à Unison où trouver un ensemble de fichiers à synchroniser, soit sur la machine locale, soit sur un hôte distant. Par exemple,

chemin/relatif/de/la/racine

spécifie une racine locale relative au répertoire où Unison est lancé, tandis que

/chemin/absolu/de/la/racine

spécifie une racine relative au sommet du système de fichiers local, indépendamment de l'endroit où Unison s'exécute. Les racines distantes peuvent commencer par ssh:// pour indiquer que le serveur distant doit être démarré avec ssh(1):

ssh://hote_distant//chemin/absolu/de/la/racine
ssh://utilisateur@hote_distant/chemin/relatif/de/la/racine

Si le serveur distant est déjà en cours d'exécution (en mode socket), alors la syntaxe

socket://hote_distant:num_port//chemin/absolu/de/la/racine
socket://hote_distant:num_port/chemin/relatif/de/la/racine
socket://[adresse_ipv6]:num_port/chemin

est utilisée pour spécifier le nom d'hôte et le port que le client Unison doit utiliser pour le contacter. La syntaxe

socket://{chemin/du/socket}//chemin/absolu/de/la/racine
socket://{chemin/du/socket}/chemin/relatif/de/la/racine

est utilisée pour spécifier le socket de domaine Unix que le client Unison doit utiliser pour contacter le serveur.

La syntaxe des racines est basée sur celle des URI (décrite dans la RFC 2396). La grammaire complète est :

réplique ::= [protocole:]//[utilisateur@][hôte][:port][/chemin]
         |  chemin

protocole ::= file
          |  socket
          |  ssh

utilisateur ::= [-_a-zA-Z0-9%@]+

hôte ::= [-_a-zA-Z0-9.]+
      |  \[ [a-f0-9:.]+ zone? \]     Littéraux IPv6 (aucun format futur).
      |  { [^}]+ }                   Pour les sockets de domaine Unix uniquement.

zone ::= %[-_a-zA-Z0-9~%.]+

port ::= [0-9]+
Lorsque le chemin est donné sans aucun préfixe de protocole, le protocole est supposé être file:. Sous Windows, il est possible de synchroniser avec un répertoire distant en utilisant le protocole file: via le réseau Windows (Network Neighborhood). Par exemple,
unison foo //hôte/disque/bar

synchronise le répertoire local foo avec le répertoire drive:\bar sur la machine hôte, à condition que l'hôte soit accessible via le voisinage réseau. Lorsque le protocole file: est utilisé de cette manière, il n'est pas nécessaire qu'un serveur Unison soit en cours d'exécution sur l'hôte distant. Cependant, exécuter Unison de cette manière n'est une bonne idée que si l'hôte distant est atteint par une connexion réseau très rapide, car le contenu intégral de chaque fichier de la réplique distante devra être transféré vers la machine locale pour détecter les mises à jour.

CHEMINS

Un chemin fait référence à un point dans un ensemble de fichiers synchronisés ; il est spécifié par rapport à la racine de la réplique. Formellement, un chemin est simplement une séquence de noms, séparés par /. Notez que le caractère séparateur de chemin est toujours une barre oblique, quel que soit le système d'exploitation sur lequel Unison est exécuté. Le chemin vide (c'est-à-dire la séquence vide de noms) désigne la réplique entière.

SPÉCIFICATION DE CHEMIN

Plusieurs préférences Unison (par exemple, ignore/ignorenot, follow, sortfirst/sortlast, backup, merge, etc.) spécifient des chemins individuels ou des ensembles de chemins. Ces préférences partagent une syntaxe commune basée sur des expressions régulières. Chaque préférence est associée à une liste de modèles de chemin ; les chemins spécifiés sont ceux qui correspondent à l'un des modèles de chemin.

Chaque modèle peut avoir l'une des trois formes. La forme la plus générale est une expression régulière étendue Posix introduite par le mot-clé Regex. (Les séquences de tri et les classes de caractères des expressions régulières Posix complètes ne sont pas actuellement prises en charge.)

Regex regexp

Par souci de commodité, trois autres styles de modèles sont également reconnus :

Name nom

correspond à tout chemin dont le dernier composant correspond à nom,

Path chemin

correspond exactement au chemin chemin, et

BelowPath chemin

correspond au chemin chemin et à tout chemin en dessous. Les arguments nom et chemin des dernières formes de modèles ne sont *pas* des expressions régulières. Au lieu de cela, les conventions standard de « globbing » peuvent être utilisées dans nom et chemin :

  • un * correspond à toute séquence de caractères n'incluant pas / (et ne commençant pas par ., lorsqu'il est utilisé au début d'un nom)
  • un ? correspond à tout caractère unique sauf / (et le point de départ .)
  • [xyz] correspond à tout caractère de l'ensemble {x, y, z}
  • {a,bb,ccc} correspond à l'un des a, bb ou ccc. (Faites attention à ne pas mettre d'espaces supplémentaires après les virgules : ceux-ci seront interprétés littéralement comme faisant partie des chaînes à faire correspondre !)

Le séparateur de chemin dans les modèles de chemin est toujours le caractère barre oblique « / » — même lorsque le client ou le serveur fonctionne sous Windows, où le caractère séparateur normal est une barre oblique inversée. Cela permet d'utiliser le même ensemble de modèles de chemin pour les systèmes de fichiers Unix et Windows.

Une spécification de chemin peut être suivie du séparateur « -> » lui-même suivi d'une chaîne qui sera associée aux chemins correspondants :

Path chemin -> chaîne associée

Toutes les préférences de spécification de chemin n'utilisent pas ces chaînes associées, mais toutes les préférences de spécification de chemin sont analysées de manière identique et les chaînes peuvent être ignorées. Seule la dernière correspondance de la chaîne du séparateur sur la ligne est utilisée comme délimiteur. Ainsi, pour permettre à une spécification de chemin de contenir la chaîne du séparateur, ajoutez-lui une chaîne associée, même si elle n'est pas utilisée. La chaîne associée ne peut pas contenir la chaîne du séparateur.

PROFILS

Un profil est un fichier texte qui spécifie les paramètres permanents pour les racines, les chemins, les modèles d'ignorance et d'autres préférences, afin qu'ils n'aient pas besoin d'être tapés à la ligne de commande à chaque fois qu'Unison est exécuté. Les profils doivent résider dans le répertoire .unison sur la machine cliente. Si Unison est démarré avec un seul argument nom sur la ligne de commande, il recherche un profil appelé nom.prf dans le répertoire .unison. S'il est démarré sans argument, il analyse le répertoire .unison à la recherche de fichiers dont le nom se termine par .prf et propose un menu (lors de l'utilisation de l'interface utilisateur graphique ; pour l'interface texte, vous devez utiliser l'option -i). Si un fichier nommé default.prf est trouvé, ses paramètres seront utilisés comme préférences par défaut.

Pour définir la valeur d'une préférence p de manière permanente, ajoutez au profil approprié une ligne de la forme

p = true

pour un indicateur booléen ou

p = <valeur>

pour une préférence de tout autre type. Les espaces autour de p et de la valeur sont ignorés. Un profil peut également inclure des lignes vides et des lignes commençant par # ; les deux sont ignorés.

Lorsque Unison démarre, il lit d'abord le profil, puis la ligne de commande, de sorte que les options de la ligne de commande remplacent les paramètres du profil.

TERMINAISON

Lorsqu'il ne synchronise pas en continu, l'interface texte se termine lorsque la synchronisation est terminée normalement ou en raison d'une erreur fatale.

Dans l'interface texte, pour interrompre la synchronisation avant qu'elle ne soit terminée, appuyez sur Ctrl-C (ou envoyez le signal SIGINT ou SIGTERM). Cela interrompra la propagation des mises à jour aussi rapidement que possible mais terminera quand même le nettoyage approprié. Si le processus ne s'arrête pas même après avoir appuyé sur Ctrl-C, continuez à le faire de manière répétée. Cela contournera les procédures de nettoyage et terminera le processus de force (similaire à SIGKILL). Cela peut laisser les archives ou les répliques dans un état incohérent ou verrouillé.

Lors de la synchronisation continue (répétition d'intervalle de temps ou avec surveillance du système de fichiers), l'interruption avec Ctrl-C ou avec le signal SIGINT ou SIGTERM fonctionne de la même manière que décrit ci-dessus et arrêtera en plus le processus continu. Pour arrêter uniquement le processus continu et laisser la dernière synchronisation se terminer normalement, envoyez le signal SIGUSR2 à la place.

ENVIRONNEMENT

UNISON
Unison stocke diverses informations dans un répertoire privé sur chaque hôte. Si la variable d'environnement UNISON est définie, sa valeur sera utilisée comme chemin pour ce répertoire. Il peut s'agir simplement d'un nom ou d'un chemin. Si UNISON n'est pas définie, le répertoire dépend du système d'exploitation utilisé. Sous Unix, la valeur par défaut est $HOME/.unison. Sous Windows, si la variable d'environnement USERPROFILE est définie, le répertoire sera $USERPROFILE\.unison ; sinon, ce sera c:\.unison. Sur macOS, $HOME/.unison sera utilisé s'il est présent, mais $HOME/Library/Application Support/Unison sera créé et utilisé par défaut.
UNISONLOCALHOSTNAME
La fonction qui trouve le nom d'hôte canonique de l'hôte local (qui est utilisé, par exemple, pour calculer le nom du fichier d'archive utilisé pour se souvenir des fichiers qui ont été synchronisés) utilise normalement l'appel système gethostname. Cependant, si la variable d'environnement UNISONLOCALHOSTNAME est définie, sa valeur sera utilisée à la place. Cela facilite l'utilisation d'Unison dans des situations où le nom d'une machine change fréquemment (par exemple, parce qu'il s'agit d'un ordinateur portable et qu'il est déplacé fréquemment).
UNISONBACKUPDIR
Lorsque les sauvegardes sont stockées de manière centralisée, le répertoire utilisé pour les contenir est contrôlé par la préférence backupdir et la variable d'environnement UNISONBACKUPDIR. Si les deux sont spécifiés, la variable d'environnement remplace la préférence. Si aucun des deux n'est défini, le répertoire $UNISON/backup est utilisé (voir la variable d'environnement UNISON ci-dessus).
PAGER
Utilisé par l'interface texte comme afficheur lors de l'affichage des différences entre les fichiers modifiés.
NO_COLOR
Si la variable d'environnement NO_COLOR est définie, l'interface texte d'Unison ne produira aucune sortie couleur par défaut. La préférence color remplace cette variable d'environnement.

EXEMPLES

Synchroniser deux répertoires locaux
unison chemin/vers/rep1 /rep2

Cette commande synchronise deux répertoires locaux en utilisant les options par défaut. Les options par défaut sont définies par Unison et peuvent être remplacées par l'utilisateur dans un profil appelé « default », qui est par défaut stocké dans le fichier ~/.unison/default.prf.

Synchroniser un répertoire local et un répertoire distant
unison rep_local/ ssh://utilisateur@hote//chemin/absolu

Cette commande synchronise un répertoire local (ici spécifié par un chemin relatif) et un répertoire distant (ici spécifié par un chemin absolu) en utilisant ssh(1) et les options par défaut (voir l'exemple ci-dessus).

Synchroniser avec toutes les options spécifiées dans un profil
unison nom_profil

Cette commande lit toutes les options du profil nommé « nom_profil » et synchronise selon ces options.

Synchroniser avec les options spécifiées dans un profil et les racines sur la ligne de commande
unison nom_profil /chemin/vers/rep ssh://hote/chemin/sur/serveur

Cette commande lit toutes les options du profil nommé « nom_profil » avec seulement les racines spécifiées sur la ligne de commande. Les racines ne doivent pas être spécifiées dans le profil, car les racines de la ligne de commande ne remplaceront pas les racines du profil, mais ajouteront plutôt à la liste des racines.

Synchroniser automatiquement
unison -batch /chemin/vers/rep ssh://hote/chemin/sur/serveur

Cette commande synchronise automatiquement tous les changements non conflictuels, une seule fois.

Synchroniser en continu
unison -repeat watch /chemin/vers/rep ssh://hote/chemin/sur/serveur

Cette commande synchronise d'abord entièrement les racines, puis reste inactive, attendant tout changement de fichier dans l'une ou l'autre racine, puis synchronise automatiquement ces changements. Cela fonctionne également dans un profil (repeat = watch). Si le programme d'assistance à la surveillance du système de fichiers n'est pas disponible ou n'est pas souhaité pour d'autres raisons, il est possible de faire en sorte qu'Unison synchronise de manière répétée à intervalles de temps définis :

unison -repeat 60 /chemin/vers/rep ssh://hote/chemin/sur/serveur

Cette commande synchronise toutes les 60 secondes. L'utilisation de -repeat implique -batch.

Actuellement, la synchronisation continue n'est pas possible lors de l'utilisation de l'interface graphique.

DIAGNOSTICS

Lors de l'exécution en mode textuel, Unison renvoie un code de sortie, qui décrit si la synchronisation a réussi et à quel niveau. Le code de sortie peut être utile lorsque Unison est appelé à partir d'un script. Actuellement, il existe quatre valeurs possibles pour le code de sortie :

0
synchronisation réussie ; tout est à jour maintenant.
1
certains fichiers ont été ignorés, mais tous les transferts de fichiers ont été réussis.
2
des échecs non fatals se sont produits lors du transfert de fichiers.
3
une erreur fatale s'est produite ou l'exécution a été interrompue.

L'interface graphique ne renvoie aucune information utile via le code de sortie.

COMPATIBILITÉ

Si vous utilisez les versions d'Unison ≥ 2.52 sur toutes les machines, vous n'avez rien de plus à faire pour la compatibilité.

Historiquement (versions < 2.52), les versions d'Unison devaient être relativement exactes pour fonctionner ensemble. De plus, la version du compilateur utilisée pour construire Unison avait une importance significative pour la compatibilité.

À partir de la version 2.52, Unison a un certain degré de compatibilité ascendante et descendante. Cela signifie trois choses. Premièrement, il est possible que les machines locales et distantes exécutent une version différente d'Unison. Deuxièmement, il est possible que les machines locales et distantes exécutent une version (identique ou différente) d'Unison construite avec une version différente du compilateur. Troisièmement, il est possible de mettre à niveau Unison sur la machine locale et de conserver les archives existantes.

Pour plus d'informations sur la coexistence des versions < 2.52 et ≥ 2.52, consultez https://github.com/bcpierce00/unison/wiki/2.52-Migration-Guide
