NOM

umoci insert - insérer du contenu dans une image OCI

SYNTAXE

umoci insert --image=image[:tag] [--tag=nouveau-tag] [--opaque] [--rootless] [--uid-map=valeur] [--uid-map=valeur] [--no-history] [--history.comment=commentaire] [--history.created_by=créé_par] [--history.author=auteur] [--history-created=date] source cible

umoci insert [options] --whiteout cible

DESCRIPTION

Dans la première forme, insère le contenu de source dans l'image OCI donnée par --image -- l'écrasant sauf si vous spécifiez --tag. Ceci est fait en créant une nouvelle couche contenant uniquement le contenu de source avec le nom de cible. source peut être un fichier ou un répertoire, et dans ce dernier cas, il sera parcouru récursivement. Si --opaque est spécifié, alors tous les chemins sous cible dans les couches d'image précédentes (en supposant que cible est un répertoire) seront supprimés.

Dans la seconde forme, insère une "entrée de suppression" dans l'image OCI pour cible à l'intérieur de l'image. Ceci est fait en insérant une couche contenant uniquement une entrée de whiteout pour le chemin donné.

Notez que cette commande fonctionne en créant une nouvelle couche, donc elle ne devrait pas être utilisée pour supprimer (ou remplacer) des secrets d'une image déjà construite. Voir umoci-config(1) et --config.volume pour savoir comment y parvenir correctement en ne créant pas de couches d'image contenant des secrets dès le départ.

Si --no-history n'a pas été spécifié, une entrée d'historique est ajoutée à l'image OCI marquée pour ce changement (avec les différents drapeaux --history. contrôlant les valeurs utilisées). Pour voir l'historique, voir umoci-stat(1).

OPTIONS

Les options globales sont définies dans umoci(1).

--image=image[:tag]
La source et le tag de destination pour l'insertion de fichier à
chemin à l'intérieur de l'image du conteneur. image doit être un chemin vers une image OCI valide et tag
doit être un tag valide dans l'image. Si tag n'est pas fourni, il prend par défaut
"latest".

--tag=nouveau-tag
Nom du tag pour l'image modifiée, si non spécifié, le tag original
fourni à --image sera écrasé.

--opaque
(En supposant que cible est un répertoire.) Ajouter une entrée de whiteout opaque pour cible
de sorte que tout chemin enfant de cible dans les couches précédentes soit masqué par la nouvelle
entrée pour cible, qui contiendra uniquement le contenu de source. Cela
permet le remplacement complet d'un répertoire, par opposition à la fusion
des entrées de répertoire.

--whiteout
Ajouter une entrée de suppression pour cible, afin qu'elle ne soit pas présente lors des
extractions futures de l'image.

--rootless
Activer le support d'insertion sans privilèges root. Cela permet à umoci-insert(1) d'être
utilisé par un utilisateur non privilégié. L'utilisation de ce drapeau implique
--uid-map=0:$(id -u):1 et --gid-map=0:$(id -g):1, ainsi que l'activation de plusieurs fonctionnalités
pour simuler des parties du processus de récursion afin de générer un
clone du système de fichiers aussi proche que possible pour l'insertion.

--uid-map=valeur
Spécifie un mappage UID à utiliser lors de l'insertion de fichiers. Ceci est utilisé de manière
similaire à user_namespaces(7), et est de la forme
conteneur:hôte[:taille].

--gid-map=valeur
Spécifie un mappage GID à utiliser lors de l'insertion de fichiers. Ceci est utilisé de manière
similaire à user_namespaces(7), et est de la forme
conteneur:hôte[:taille].

--no-history
Aucune entrée d'historique n'est ajoutée pour cette opération. Il n'est pas
recommandé d'utiliser ceci avec umoci-insert(1), car cela a pour conséquence que l'historique n'inclut pas
toutes les couches de l'image -- et provoquera donc une confusion avec les outils
qui examinent l'historique de l'image.

--history.comment=commentaire
Commentaire pour l'entrée d'historique correspondant à cette modification de l'image.
Si non spécifié, umoci(1) générera une valeur dépendante de l'implémentation.

--history.created_by=créé_par
Entrée CreatedBy pour l'entrée d'historique correspondant à cette modification de
l'image. Si non spécifié, umoci(1) générera une
valeur dépendante de l'implémentation.

--history.author=auteur
Valeur Auteur pour l'entrée d'historique correspondant à cette modification de
l'image. Si non spécifiée, cette valeur sera la valeur d'auteur de l'image après
toutes les modifications apportées par cet appel à umoci-config(1).

--history-created=date
Date de création pour l'entrée d'historique correspondant à ces modifications de
l'image. Ce doit être un horodatage formaté ISO8601 (voir date(1)). Si
non spécifié, l'heure actuelle est utilisée.

EXEMPLE

Ce qui suit insère un fichier mybinary dans le chemin /usr/bin/mybinary et un répertoire myconfigdir dans le chemin /etc/myconfigdir. Il convient de noter que si /etc/myconfigdir existe déjà dans l'image, le contenu des deux répertoires est fusionné (la couche la plus récente ayant la priorité).

% umoci insert --image oci:foo mybinary /usr/bin/mybinary
% umoci insert --image oci:foo myconfigdir /etc/myconfigdir

Et dans ces exemples, nous supprimons /usr/bin/mybinary et remplaçons la totalité de /etc par myetcdir (de sorte qu'aucune des anciennes entrées /etc ne soit présente lors de umoci-unpack(1)).

% umoci insert --image oci:foo --whiteout /usr/bin/mybinary
% umoci insert --image oci:foo --opaque myetcdir /etc
