NOM

upsclient - Bibliothèque d'accès client Network UPS Tools

DESCRIPTION

La bibliothèque upsclient de Network UPS Tools (NUT) fournit un certain nombre de fonctions utiles aux programmes clients pour communiquer avec upsd(8). La plupart des détails bas niveau des sockets et du protocole sont gérés automatiquement lors de l'utilisation de cette interface, également connue sous le nom d'API "upscli".

L'état est maintenu entre les appels dans une structure opaque appelée UPSCONN_t. Les appelants sont censés en créer une par connexion. Celles-ci seront fournies à la plupart des fonctions upsclient. Le format de cette structure est sujet à modification, et les programmes clients ne doivent pas y accéder directement.

INITIALISATION ET NETTOYAGE

Avant de créer toute connexion, et en général avant d'utiliser toute fonction upscli, vous devez appeler upscli_init(3) avec les paramètres appropriés pour initialiser le module upscli.

Pour enregistrer une politique de sécurité spécifique pour l'hôte, vous devez appeler upscli_add_host_cert(3) avant d'initialiser une connexion à celui-ci.

De la même manière, juste avant de quitter, et après toute utilisation d'upscli, vous devez appeler upscli_cleanup(3) pour vider les fichiers cache et effectuer d'autres nettoyages.

FONCTIONS RESEAU

Pour créer une nouvelle connexion, utilisez upscli_connect(3). Cela initialisera également la structure UPSCONN_t. Pour vérifier plus tard qu'une connexion a été établie, upscli_fd(3) peut être utilisée pour retourner le descripteur de fichier. Les clients souhaitant vérifier la présence et le fonctionnement de SSL sur une connexion peuvent appeler upscli_ssl(3).

La majorité des clients utiliseront upscli_get(3) pour récupérer des éléments uniques du serveur. Pour récupérer une liste, utilisez upscli_list_start(3) pour la démarrer, puis appelez upscli_list_next(3) pour chaque élément.

Les lignes de texte brutes peuvent être envoyées à upsd(8) avec upscli_sendline(3). La lecture de lignes brutes est possible avec upscli_readline(3). Les programmes clients sont censés formater ces lignes conformément au protocole, car aucune vérification ne sera effectuée avant la transmission.

À la fin d'une connexion, vous devez appeler upsclient_disconnect(3) pour vous déconnecter de upsd et libérer toute mémoire dynamique associée à la structure UPSCONN_t. Le non-respect de cet appel entraînera des fuites de mémoire et de descripteurs de fichiers dans votre programme.

FONCTIONS CHAÎNE

Pour analyser les valeurs ups.status (vérifier si un jeton particulier est présent), il est conseillé d'utiliser la méthode upscli_str_contains_token(3).

Pour collecter des jetons uniques dans une chaîne, de la même manière qu'un pilote NUT le fait, upscli_str_add_unique_token(3) peut être utile.

Vous êtes invité à consulter la base de code source de NUT pour l'utilisation de méthodes équivalentes afin d'implémenter des fonctionnalités telles que les méthodes status_init(), status_get(), status_set() et status_commit() dans ses boucles de traitement de données.

GESTION DES ERREURS

En cas d'erreur, upscli_strerror(3) fournira des détails lisibles par l'homme sur ce qui s'est passé. upscli_upserror(3) peut également être utilisé pour récupérer le numéro d'erreur. Ces numéros sont définis dans upsclient.h comme UPSCLI_ERR_*.
