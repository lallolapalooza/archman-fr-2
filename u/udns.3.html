NOM

udns - bibliothèque de résolution DNS stub

DESCRIPTION

La bibliothèque DNS, udns, implémente des fonctionnalités de résolution DNS stub thread-safe, qui peuvent être utilisées de manière traditionnelle et synchrone, ainsi qu'asynchrone, avec une boucle d'événements fournie par l'application.

Bien que DNS fonctionne avec TCP et UDP, en effectuant d'abord une requête UDP et si le résultat ne rentre pas dans le tampon UDP (512 octets maximum pour le protocole DNS original), en répétant la requête sur TCP, la bibliothèque n'utilise que UDP, mais utilise les extensions EDNS0 (RFC2671) qui permettent des tampons UDP plus grands.

La bibliothèque utilise un seul socket UDP pour effectuer toutes les opérations, même lors de la consultation de plusieurs serveurs DNS. De cette manière, il est très simple d'utiliser la bibliothèque dans des applications à boucle d'événements asynchrone : une application ne devrait ajouter qu'un seul socket à l'ensemble des descripteurs de fichiers qu'elle surveille pour les E/S.

La bibliothèque utilise deux objets principaux, le *contexte du résolveur* de type struct dns_ctx, et la *structure de requête* de type struct dns_query, tous deux opaques pour une application. Le contexte du résolveur contient des informations globales sur le résolveur, telles que la liste des serveurs DNS à utiliser, la liste des requêtes actives, etc. Les objets de requête contiennent des informations sur une seule requête DNS en cours et sont alloués/traités/libérés par la bibliothèque. Un pointeur vers la structure de requête peut être traité comme un identifiant d'une requête en cours et peut être utilisé pour annuler la requête asynchrone ou attendre qu'elle se termine.

L'interface asynchrone fonctionne comme suit. Une application initialise un contexte de résolveur, soumet un nombre quelconque de requêtes pour celui-ci en utilisant l'une des routines dns_submit_XXX() fournies (chacune renvoyant l'identifiant de la requête sous forme de pointeur vers la structure de requête), attend des entrées sur le socket UDP utilisé par la bibliothèque, et donne un certain contrôle à la bibliothèque en appelant les routines dns_ioevent() et dns_timeouts() le cas échéant. La bibliothèque effectue tous les traitements nécessaires et exécute la routine de rappel fournie par l'application lorsqu'une requête est terminée (succès ou échec), en lui donnant le résultat le cas échéant, un pointeur vers le contexte du résolveur (à partir duquel le statut d'achèvement peut être obtenu) et le pointeur de données fourni par une application lors de la soumission de la requête. Lors de la soumission d'une requête, une application demande comment traiter la réponse -- soit renvoyer le paquet de réponse DNS brut pour son propre traitement de bas niveau, soit fournir l'adresse d'une *routine d'analyse* de type dns_parse_fn pour effectuer la conversion du format réseau en une structure de données facile à utiliser (la bibliothèque fournit des routines d'analyse pour plusieurs types d'enregistrements de ressources couramment utilisés, ainsi qu'une interface de haut niveau type-safe qui demande l'analyse automatiquement). La surveillance des E/S et la gestion des délais d'attente peuvent être basées sur select() ou poll() traditionnels, ou toute technique basée sur des rappels peut être utilisée.

De plus, la bibliothèque fournit une interface synchrone traditionnelle, qui peut être mélangée avec des appels asynchrones (pendant le traitement des requêtes synchrones, d'autres requêtes asynchrones pour le même contexte de résolveur continuent d'être traitées normalement). Une application utilise l'une des nombreuses routines dns_resolve_XXX() fournies par la bibliothèque pour effectuer une requête. Comme avec l'interface asynchrone, une application peut demander à renvoyer le paquet DNS brut ou une structure de données spécifique au type en fournissant la routine d'analyse pour traiter la réponse. Chaque routine de la série dns_resolve_XXX() renvoie un pointeur vers le résultat ou NULL en cas d'erreur. Le statut d'achèvement de la requête (ou la longueur du paquet DNS brut) est disponible à partir du contexte du résolveur en utilisant la routine dns_status(), de la même manière que pour l'interface asynchrone.

En interne, la bibliothèque utilise le format réseau des noms de domaine, appelé *format DN* dans cette page de manuel. Il s'agit d'une série de *libellés* de domaine précédés d'un octet de longueur, se terminant par un libellé de longueur nulle qui fait partie intégrante du format DN. Plusieurs routines sont fournies pour convertir des chaînes asciiz traditionnelles en DN et vice versa. L'interface de requête de haut niveau spécifique au type masque le format DN à l'application.

DÉFINITIONS COMMUNES

Chaque enregistrement de ressource (RR) DNS a un *type* et une *classe*. La bibliothèque définit plusieurs constantes entières, DNS_C_XXX et DNS_T_XXX, pour servir de noms symboliques aux classes et types de RR, tels que DNS_C_IN pour la classe Internet, DNS_T_A pour le type d'enregistrement d'adresse IPv4, etc. Voir le fichier d'en-tête udns.h pour la liste complète de toutes ces constantes.

Les constantes suivantes sont définies dans le fichier d'en-tête udns.h :

DNS_MAXDN (255 octets)
Longueur maximale d'un nom de domaine dans le format interne (réseau) DN.
DNS_MAXLABEL (63 octets)
Longueur maximale d'un seul libellé au format DN.
DNS_MAXNAME (1024 octets)
Longueur maximale d'un nom de domaine au format asciiz.
DNS_HSIZE (12 octets)
Taille de l'en-tête dans un paquet DNS.
DNS_PORT (53)
Port par défaut à utiliser lors de la contactation d'un serveur DNS.
DNS_MAXSERV (6 serveurs)
Nombre maximum de serveurs DNS à utiliser.
DNS_MAXPACKET (512 octets)
Longueur maximale d'un paquet DNS UDP telle que spécifiée par le protocole DNS original.
DNS_EDNS0PACKET (4096 octets)
Longueur par défaut d'un paquet DNS UDP (avec extensions EDNS0) que la bibliothèque utilise. Notez que les serveurs DNS récursifs résident généralement près du client qui leur demande de résoudre des noms, par exemple sur le même segment LAN ou même sur la même machine, de sorte que la fragmentation des paquets UDP n'est pas un problème dans la plupart des cas. Notez également que la taille des paquets réels sera de la taille de la réponse réelle requise, ce qui est plus petit que cette valeur dans presque tous les cas.

De plus, plusieurs constantes sont définies pour simplifier le travail avec les paquets DNS bruts, telles que les codes de réponse DNS (DNS_R_XXX), la disposition de l'en-tête DNS (DNS_H_XXX) et d'autres. Encore une fois, voir udns.h pour la liste complète. Les codes d'erreur de la bibliothèque (DNS_E_XXX) sont décrits plus loin dans cette page de manuel.

CONTEXTE DU RÉSOLVEUR

Le contexte du résolveur, de type struct dns_ctx, est un objet opaque pour une application. Plusieurs routines fournies par la bibliothèque permettent d'initialiser, de copier et de libérer les contextes de résolveur. La plupart des autres routines de haut niveau de cette bibliothèque attendent un pointeur vers un contexte de résolveur, *ctx*, comme premier argument. Il existe un contexte de résolveur par défaut, nommé dns_defctx. Lorsque le pointeur de contexte *ctx* passé à une routine est NULL, dns_defctx est utilisé. Plusieurs contextes de résolveur peuvent être actifs en même temps, par exemple, lorsqu'une application est multithreadée et que chaque thread utilise le résolveur.

Pour utiliser la bibliothèque, une application doit initialiser et ouvrir un ou plusieurs objets de contexte de résolveur. Ce sont deux actions distinctes, effectuées par dns_init() (ou dns_reset()), et dns_open(). Entre ces deux appels, une application est libre d'effectuer une initialisation supplémentaire, telle que la définition de serveurs DNS personnalisés, d'options ou de listes de recherche de domaines. Optionnellement, si aucune initialisation personnalisée supplémentaire n'est requise, dns_init() peut ouvrir le contexte si l'argument *do_open* (voir ci-dessous) est non nul.

Lors de l'initialisation du contexte du résolveur, la bibliothèque utilise les informations du fichier système /etc/resolv.conf (voir resolv.conf(5)), consulte les variables d'environnement $LOCALDOMAIN, $NSCACHEIP, $NAMESERVERS et $RES_OPTIONS, ainsi que le nom d'hôte local pour obtenir la liste des serveurs DNS locaux, la liste de recherche de domaines et diverses options de résolveur.

Traite tous les timeouts en attente et renvoie le nombre de secondes depuis l'heure actuelle (now s'il n'est pas 0) jusqu'à l'heure à laquelle la bibliothèque souhaite que l'application lui cède le contrôle pour traiter davantage de requêtes en file d'attente. typedef void dns_utm_fn(ctx, int timeout, void *data)

Une application peut utiliser un mécanisme de multiplexage d'E/S basé sur des rappels personnalisés. Généralement, un tel mécanisme a le concept d'un timer, et la capacité d'enregistrer un événement de timer sous la forme d'une routine de rappel qui sera exécutée après un certain temps. Pour utiliser un tel mécanisme d'événement, udns offre la possibilité d'enregistrer et de désenregistrer des événements de timer nécessaires au traitement interne à l'aide du mécanisme d'événement que l'application utilise. Pour que cela fonctionne, il est possible d'associer un pointeur vers une routine qui effectuera le travail nécessaire pour (dés)enregistrer les événements de timer avec un contexte de résolution donné, et udns appellera cette routine aux moments appropriés. Le prototype d'une telle routine est montré par le typedef dns_utm_fn ci-dessus. Libudns associe un seul timer au contexte de résolution. La routine utmfn fournie par l'utilisateur sera appelée par la bibliothèque avec les arguments suivants :
ctx == NULL
supprimer le timer utilisateur, lors de la libération du contexte ou lorsqu'une application change la routine de demande de timer utilisateur en utilisant dns_set_tmcbck();
ctx != NULL, timeout < 0
ne plus déclencher le timer, lorsqu'il n'y a pas de requêtes actives;
ctx != NULL, timeout == 0
déclencher le timer à la prochaine possibilité, mais pas immédiatement;
ctx != NULL, timeout > 0
déclencher le timer après timeout secondes à partir de maintenant.

L'argument data passé à la routine sera le même que celui passé à dns_set_tmcbck().

Lorsqu'un timer expire, une application doit appeler la routine dns_timeouts() (voir ci-dessous). L'utilisation de timers non basés sur des rappels est également fournie.

INTERFACE DE REQUÊTE

Il existe deux façons d'effectuer des requêtes DNS : la manière synchrone traditionnelle, où udns effectue tout le traitement nécessaire et ne rend le contrôle à l'application que lorsque la requête est terminée, et la manière asynchrone, où une application soumet une ou plusieurs requêtes à la bibliothèque à l'aide d'un contexte de résolution donné et attend la fin du traitement en surveillant le descripteur de fichier utilisé par la bibliothèque et en appelant les routines de la bibliothèque pour traiter les entrées sur ce descripteur de fichier. Le mode asynchrone fonctionne avec des routines de rappel : une application fournit l'adresse d'une routine à exécuter lorsque la requête est terminée, et un pointeur de données, qui est passé à la routine de rappel.

Les requêtes sont soumises à la bibliothèque sous la forme de struct dns_query. Pour effectuer une requête asynchrone, une application appelle l'une des routines dns_submit_XXX() et fournit les informations nécessaires pour un rappel, ainsi que tous les paramètres de la requête. Lorsque la requête est terminée, la bibliothèque appellera la routine de rappel fournie par l'application, en lui donnant le contexte de résolution (qui détient l'état d'achèvement de la requête), le résultat alloué dynamiquement (qui sera soit un paquet DNS brut, soit, si l'application a demandé l'analyse du résultat en spécifiant une routine d'analyse non NULL, une structure prête à l'emploi spécifique au type), et un pointeur de données fourni par une application lorsqu'elle a soumis la requête. C'est à l'application qu'incombe la responsabilité de libérer la mémoire du résultat.

Une routine de rappel de requête générique ressemble à ceci :

typedef void
dns_query_fn(ctx, void *result, void *data)
Le type de routine de rappel pour l'interface de requête spécifique à un type attend une forme similaire, la seule différence étant le type de l'argument result, qui sera un pointeur vers une structure de données spécifique (réponse décodée) au lieu de ce pointeur void vers les données brutes du paquet DNS.

Une routine d'analyse de résultat ressemble à ceci :

typedef int
dns_parse_fn(const unsigned char *qdn,
      const unsigned char *pkt,
      const unsigned char *cur,
      const unsigned char *end,
      void **resultp);
Lorsqu'elle est appelée par la bibliothèque, les arguments sont les suivants : pkt pointe vers le début du paquet reçu ; end pointe après la fin du paquet reçu ; cur pointe après le DN de requête dans la section de requête du paquet ; qdn pointe vers le DN de requête d'origine. La routine doit allouer un seul tampon pour contenir le résultat, analyser la réponse en remplissant le tampon et renvoyer le tampon via l'argument resultp. Elle renvoie 0 en cas d'erreur, ou un code d'erreur udns (constantes DNS_E_XXX) en cas d'erreur. Notez qu'au moment où la routine d'analyse est appelée par la bibliothèque, le paquet a déjà été vérifié comme étant une réponse à la requête d'origine, en faisant correspondre le DN de requête, la classe de requête et le type de requête.

L'interface de requête spécifique à un type fournit automatiquement les routines d'analyse nécessaires.

La bibliothèque fournit deux séries de routines qui utilisent une interface similaire -- une pour les requêtes asynchrones et une autre pour les requêtes synchrones. Il existe deux routines générales de bas niveau dans chaque série pour soumettre (interface asynchrone) et résoudre (interface synchrone) les requêtes, ainsi que plusieurs routines spécifiques au type avec des interfaces plus faciles à utiliser. Pour soumettre une requête asynchrone, utilisez l'une des routines dns_submit_XXX(), chacune acceptant les paramètres de requête, des pointeurs vers la routine de rappel et vers les données de rappel, et un indice de temps actuel optionnel. Notez que les routines dns_submit_XXX() spécifiques au type attendent également un type spécifique de routine de rappel, qui accepte la réponse comme un pointeur vers la structure correspondante, et non comme un pointeur void). Chaque routine dns_submit_XXX() retourne un pointeur vers la structure de requête interne de type struct dns_query, utilisée comme identifiant de la requête donnée.

Pour résoudre une requête de manière synchrone, utilisez l'une des routines dns_resolve_XXX(), qui accepte les mêmes paramètres de requête (mais pas les pointeurs de rappel) que les routines dns_submit_XXX() correspondantes, et retourne le résultat de la requête, qui est le même que celui passé à la routine de rappel dans le cas de l'interface asynchrone.

Dans les deux cas, la mémoire du résultat (si la requête s'est terminée avec succès) est allouée dynamiquement et doit être libérée par une application. Si la requête a échoué pour une raison quelconque, le résultat sera NULL, et l'état d'erreur sera disponible à partir de la routine dns_status(ctx) comme montré ci-dessus.

interface synchrone. Les routines effectuent toutes les étapes nécessaires pour résoudre la requête donnée et retournent le résultat. S'il n'y a pas de résultat positif pour une raison quelconque, toutes les routines retournent NULL, et définissent l'état d'erreur du contexte (disponible via la routine dns_status()) pour indiquer le code d'erreur. Si la requête a réussi, le code d'état du contexte contiendra soit la longueur du paquet DNS brut si l'argument parse était NULL (auquel cas la valeur de retour est un pointeur vers le paquet DNS de réponse), soit 0 (auquel cas la valeur de retour est le résultat de la routine parse). Si la requête a réussi (la valeur de retour n'est pas NULL), la mémoire retournée a été allouée dynamiquement par la bibliothèque et doit être libérée par l'application après utilisation.
void *dns_resolve(ctx, struct dns_query *q)
attend que la requête donnée q, telle que retournée par l'une des routines dns_submit_XXX(), soit terminée, et retourne le résultat. La routine de rappel ne sera pas appelée pour cette requête. Après achèvement, l'identifiant de requête q n'est plus valide. Les deux routines dns_resolve_dn() et dns_resolve_p() ne sont que des wrappers autour des routines de soumission correspondantes et de cette routine dns_resolve().
void dns_cancel(ctx, struct dns_query *q)
annule une requête active q, sans appeler de routine de rappel. Après achèvement, l'identifiant de requête q n'est plus valide.

REQUÊTES SPÉCIFIQUES AU TYPE

En plus de l'interface de requête générique de bas niveau, la bibliothèque fournit un ensemble de routines pour effectuer des requêtes spécifiques de manière type-safe, ainsi que des analyseurs pour plusieurs types d'enregistrements de ressources bien connus. La bibliothèque implémente une interface de haut niveau pour les enregistrements A, AAAA, PTR, MX et TXT, ainsi que pour les fonctionnalités DNSBL et RHSBL. Ces routines retournent des types spécifiques comme résultat d'une requête, au lieu de paquets DNS bruts. Les types et routines suivants sont disponibles.

INTERFACE BAS-NIVEAU

Noms de domaine (DNs)

Un DN est une série d'étiquettes de noms de domaine, chacune commençant par un octet de longueur, suivie d'une étiquette vide (étiquette de longueur nulle). Les routines suivantes pour travailler avec les DN sont fournies.

unsigned dns_dnlen(const unsigned char *dn)
renvoie la longueur du nom de domaine dn, y compris l'étiquette de terminaison.
unsigned dns_dnlabels(const unsigned char *dn)
renvoie le nombre d'étiquettes non nulles dans le nom de domaine dn.
unsigned dns_dnequal(dn1, dn2)
  const unsigned char *dn1, *dn2;
teste si les deux noms de domaine, dn1 et dn2, sont égaux (insensible à la casse). Renvoie la longueur du nom de domaine si égal ou 0 si non.
unsigned dns_dntodn(sdn, ddn, dnsiz)
  const unsigned char *sdn;
  unsigned char *ddn;
  unsigned dnsiz;
copie le nom de domaine source sdn dans le tampon de destination ddn de taille dnsiz. Renvoie la longueur du nom de domaine ou 0 si ddn est trop petit.
int dns_ptodn(name, namelen, dn, dnsiz, isabs)
int dns_sptodn(name, dn, dnsiz)
  const char *name; unsigned namelen;
  unsigned char *dn; unsigned dnsiz;
  int *isabs;
convertit le nom asciiz name de longueur namelen en format DN, plaçant le résultat dans le tampon dn de taille dnsiz. Renvoie la longueur du DN en cas de succès, 0 si le tampon dn fourni est trop petit, ou une valeur négative si name est invalide. Si isabs n'est pas NULL et que la conversion a réussi, *isabs sera défini sur 1 ou 0 selon que name était absolu (c'est-à-dire se terminant par un point) ou non. La longueur du nom, namelength, peut être zéro, auquel cas strlen(name) sera utilisée. La deuxième forme, dns_sptodn(), est une forme simplifiée de dns_ptodn(), équivalente à 
dns_ptodn(name, 0, dn, dnlen, 0).

      unsigned char *dn, unsigned dnsiz)

      unsigned char *dn, unsigned dnsiz)

Si tdn (ou tname) est NULL, dns_inaddr_arpa_dn (ou dns_ip6_arpa_dn) sera utilisé. Les routines peuvent être utilisées pour construire un DN pour une recherche DNSBL par exemple. convertit le nom de domaine dn au format DN en une chaîne asciiz, plaçant le résultat dans le tampon name de taille namesiz. La longueur maximale de la représentation asciiz d'un nom de domaine est de DNS_MAXNAME (1024) octets. Le domaine racine est représenté par une chaîne vide. Renvoie la longueur du nom résultant (y compris le caractère de terminaison, c'est-à-dire strlen(name)+1) en cas de succès, 0 si le tampon name est trop petit, ou une valeur négative si dn est invalide (ce dernier cas ne devrait jamais se produire car toutes les routines de cette bibliothèque qui produisent des noms de domaine garantissent que les DN générés sont valides).

Travail avec les paquets DNS

Les routines suivantes sont fournies pour encoder et décoder les paquets DNS sur le réseau. C'est une interface bas niveau.

Les codes de réponse DNS (renvoyés par la routine dns_rcode()) sont définis comme des constantes préfixées par DNS_R_. Voir le fichier d'en-tête udns.h pour la liste complète. En particulier, les constantes DNS_R_NOERROR (0), DNS_R_SERVFAIL, DNS_R_NXDOMAIN peuvent intéresser une application.

dns_getdn() extrait un DN du paquet DNS pkt qui se termine avant pkte à partir de la position *curp dans le tampon pointé par dn de taille dnsiz. Après une exécution réussie, *curp pointera vers le prochain octet dans le paquet après le nom de domaine extrait. Il renvoie un nombre positif (longueur du DN si dn) en cas de succès, une valeur négative en cas d'erreur (lorsque le paquet contient des données invalides), ou zéro si dnsiz est trop petit (la longueur maximale d'un nom de domaine est DNS_MAXDN). dns_skipdn() renvoie un pointeur vers le prochain octet dans le paquet DNS qui se termine avant pkte après un nom de domaine qui commence à l'octet cur, ou NULL si le paquet est invalide. dns_skipdn() est plus ou moins équivalent à ce que fait dns_getdn(), sauf qu'il n'extrait pas réellement le nom de domaine en question et utilise une interface plus simple.

  const unsigned char *dnsp_pkt; /* pointeur vers le paquet en cours d'analyse */
  const unsigned char *dnsp_end; /* pointeur de fin du paquet */

La structure dns_parse est utilisée pour analyser le paquet de réponse DNS. Elle contient des informations sur le paquet en cours d'analyse (champs dnsp_pkt, dnsp_end et dnsp_cur), le nombre de RR restants dans la section actuelle, et les informations sur le RR spécifique que nous recherchons (champs dnsp_qdn, dnsp_qcls et dnsp_qtyp).
int dns_initparse(struct dns_parse *p,
  const unsigned char *qdn,
  const unsigned char *pkt,
  const unsigned char *cur,
  const unsigned char *end)
initialise la structure d'analyse de RR p. Les arguments pkt, cur et end doivent décrire le paquet reçu : pkt est le début du paquet, end pointe vers l'octet suivant la fin du paquet, et cur pointe après le DN de la requête dans la section de requête (vers les informations de classe+type de la requête). Et qdn pointe vers le DN de la requête. Ce sont les arguments passés à la routine dns_parse_fn(). dns_initparse() initialise les champs dnsp_pkt, dnsp_end et dnsp_qdn aux arguments correspondants, extrait et initialise les champs dnsp_qcls et dnsp_qtyp aux valeurs trouvées au pointeur cur, initialise les champs dnsp_cur et dnsp_ans à cur+4 (au début de la section de réponse), et initialise le champ dnsp_rrl au nombre d'entrées dans la section de réponse. dnsp_ttl sera défini à la valeur TTL maximale, 0xffffffff, et dnsp_nrr à 0.
int dns_nextrr(struct dns_parse *p, struct dns_rr *rr);
recherche le prochain RR dans le paquet en fonction des critères fournis dans la structure p, en remplissant la structure rr et en avançant p->dnsp_cur vers le prochain RR dans le paquet. La sélection du RR est basée sur les champs dnsp_qdn, dnsp_qcls et dnsp_qtyp dans la structure dns_parse. N'importe lequel (ou tous) des 3 champs peut être 0, ce qui signifie que toute valeur réelle du paquet est acceptable. Dans le cas où le champ n'est pas 0 (ou NULL pour dnsp_qdn), seuls les RR ayant les caractéristiques correspondantes sont acceptables. De plus, lorsque dnsp_qdn n'est pas NULL, dns_nextrr() effectue une expansion automatique de CNAME. La routine renverra une valeur positive en cas de succès, 0 si elle a atteint la fin de la section actuelle dans le paquet (p->dnsp_rrl est zéro), ou une valeur négative si le prochain RR ne peut pas être décodé (le format du paquet est invalide). La routine met à jour p->dnsp_qdn automatiquement lorsque ce champ n'est pas NULL et qu'elle rencontre des RR CNAME appropriés (en sauvegardant la cible du CNAME dans p->dnsp_dnbuf), de sorte qu'après la fin du processus, p->dnsp_qdn pointera vers le nom canonique du domaine en question. La routine met à jour la valeur p->dnsp_ttl pour qu'elle soit le TTL minimum de tous les RR trouvés.
void dns_rewind(struct dns_parse *p, const unsigned char *qdn)
cette routine "rembobine" la structure d'état d'analyse du paquet pour qu'elle soit dans le même état qu'après un appel à dns_initparse(), c'est-à-dire repositionne la structure d'analyse p au début de la section de réponse et initialise p->dnsp_rrl au nombre d'entrées dans la section de réponse.
int dns_stdrr_size(const struct dns_parse *p);
renvoie la taille nécessaire pour contenir les informations de la structure RR standard, comme indiqué dans la structure dns_rr_null (pour les noms de requête et canoniques). Utilisé pour calculer la quantité de mémoire à allouer pour la partie commune des structures RR spécifiques au type dans les routines d'analyse.
void *dns_stdrr_finish(struct dns_rr_null *ret, char *cp,
  const struct dns_parse *p);
initialise les champs RR standard dans la structure ret en utilisant le tampon pointé par cp, qui doit avoir au moins autant d'octets que dns_stdrr_size(p) l'a retourné. Utilisé pour finaliser la partie commune des structures RR spécifiques au type dans les routines d'analyse.

Routines auxiliaires

int dns_pton(int af, const char *src, void *dst);
fournit des fonctionnalités similaires à la routine standard inet_pton(), pour convertir la représentation imprimable d'une adresse IP de famille af (soit AF_INET, soit AF_INET6) pointée par src en forme binaire adaptée aux adresses de socket et à la transmission sur le réseau, dans le tampon pointé par dst. Le tampon de destination doit être de taille 4 pour la famille AF_INET ou 16 pour AF_INET6. La valeur de retour est positive en cas de succès, 0 si src n'est pas une représentation textuelle valide d'une adresse de famille af, ou négative si la famille d'adresses donnée n'est pas prise en charge.
const char *dns_ntop(int af, const void *src,
    char *dst, int dstsize)
fournit des fonctionnalités similaires à la routine standard inet_ntop(), pour convertir la représentation binaire d'une adresse IP de famille af (soit AF_INET, soit AF_INET6) pointée par src (soit 4, soit 16 octets) en forme imprimable dans le tampon pointé par dst de taille dstsize. Le tampon de destination doit être d'au moins 16 octets pour la famille AF_INET ou 46 octets pour AF_INET6. La valeur de retour est soit dst, soit un pointeur NULL si dstsize est trop petit pour contenir cette adresse ou si la famille d'adresses donnée n'est pas prise en charge.
