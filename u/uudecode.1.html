uudecode(1) Commandes utilisateur uudecode(1)

NOM

uudecode - décoder un fichier encodé

SYNTAXE

uudecode [-flags] [-flag [valeur]] [--nom-option[[=| ]valeur]] [<fichier>...]

Si aucun fichier n'est fourni, l'entrée standard est décodée.

DESCRIPTION

uudecode transforme les fichiers encodés uu en leur forme originale.

Les fichiers encodés peuvent être spécifiés sur la ligne de commande, ou lus depuis l'entrée standard. Le nom du fichier de sortie est spécifié dans le fichier encodé, mais peut être remplacé avec l'option -o. Il aura le mode du fichier original, à l'exception des bits setuid et d'exécution qui ne sont pas conservés. Si le fichier de sortie est spécifié comme étant /dev/stdout ou -, le résultat sera écrit sur la sortie standard. S'il y a plusieurs fichiers d'entrée et que le second ou les fichiers suivants spécifient la sortie standard, les données décodées seront écrites dans le même fichier que la sortie précédente. Ne faites pas cela.

uudecode ignore toute ligne de début et de fin. Il recherche une ligne commençant par "begin" et continue jusqu'à ce que le marqueur de fin d'encodage soit trouvé. Le programme détermine à partir de la ligne d'en-tête du fichier encodé quel schéma d'encodage parmi les deux pris en charge a été utilisé et si le nom du fichier de sortie a été encodé avec un encodage base64. Voir uuencode(5).

OPTIONS

-o fichier, --fichier-sortie=fichier

dirige la sortie vers fichier.

Si spécifié, les données décodées sont écrites dans ce fichier. Lorsque plusieurs entrées sont spécifiées sur la ligne de commande, cette option ne peut pas être spécifiée. Toutes les données décodées doivent être écrites dans le nom de fichier encodé dans les données.

-c, --ignorer-chmod

ignore les erreurs de fchmod(3P).

Par défaut, si les permissions du fichier de sortie ne peuvent pas être modifiées pour correspondre aux permissions spécifiées dans les données encodées, le fichier ne sera pas écrit et l'exécution s'arrêtera. Cette option entraînera l'ignorance de cette erreur. Le fichier résultant contiendra toutes les données, mais avec des paramètres de mode incorrects.

Les erreurs de fchmod() sont également ignorées si POSIXLY_CORRECT est défini dans l'environnement. RE : http://austingroupbugs.net/view.php?id=635

Un avertissement est toujours émis lorsque fchmod() échoue.

-h, --aide

Affiche les informations d'utilisation et quitte.
-!, --plus-aide

Passe les informations d'utilisation étendues à un paginateur.
-R [fichiercfg], --sauvegarder-options [=fichiercfg]

Sauvegarde l'état des options dans fichiercfg. Le défaut est le dernier fichier de configuration listé dans la section PRÉGLAGES D'OPTIONS, ci-dessous. La commande quittera après avoir mis à jour le fichier de configuration.
-r fichiercfg, --charger-options=fichiercfg, --pas-charger-options

Charge les options depuis fichiercfg. La forme pas-charger-options désactivera le chargement des fichiers de configuration/rc/ini précédents. --pas-charger-options est géré tôt, hors séquence.
-v [{v|c|n --version [{v|c|n}]}]

Affiche la version du programme et quitte. Le mode par défaut est `v', une version simple. Le mode `c' affichera les informations de copyright et `n' affichera l'avis de copyright complet.

PRÉGLAGES D'OPTIONS

Toute option non marquée comme non présélectionnable peut être présélectionnée en chargeant les valeurs à partir de fichiers de configuration ("RC" ou ".INI"). Le fichier "$HOME/.sharrc" sera utilisé, s'il existe.

NORMES

Cette implémentation est conforme à P1003.2b/D11.

FICHIERS

Voir PRÉGLAGES D'OPTIONS pour les fichiers de configuration.

STATUT DE SORTIE

L'une des valeurs de sortie suivantes sera retournée :

0 (EXIT_SUCCESS)

Exécution réussie du programme.
1 (EXIT_OPTION_ERROR)

Les options de la commande étaient mal configurées.
2 (EXIT_INVALID)

(avertissement) Un ou plusieurs fichiers d'entrée ne contenaient aucune donnée valide
4 (EXIT_NO_INPUT)

(avertissement) Le fichier d'entrée spécifié n'a pas été trouvé
8 (EXIT_NO_OUTPUT)

Le fichier de sortie spécifié n'a pas pu être créé (erreur) ; ou bien l'un des fichiers de sortie n'a pas pu être écrit ou son mode d'accès n'a pas pu être modifié (avertissements). Les messages accompagnant l'erreur distingueront.
9 (EXIT_NO_MEM)

Pas de mémoire de processus disponible
66 (EX_NOINPUT)

Un fichier de configuration spécifié n'a pas pu être chargé.
70 (EX_SOFTWARE)

libopts a eu une erreur opérationnelle interne. Veuillez la signaler à autogen-users@lists.sourceforge.net. Merci.

Les codes de statut de sortie sont (principalement) des codes d'avertissement. En tant que tels, chaque code est "mis en OR" dans le code de sortie final au fur et à mesure du traitement des fichiers d'entrée. Par exemple, un code de sortie de '6' n'est pas listé ci-dessus. C'est la somme de EXIT_INVALID et EXIT_NO_INPUT. Cela signifierait qu'au moins un fichier d'entrée contenait des données invalides et qu'au moins un fichier d'entrée n'a pas pu être trouvé.

BOGUES

Veuillez mettre sharutils dans la ligne d'objet des rapports de bogues par e-mail. Cela aide à repérer le message.

Si plus d'un nom dans les fichiers encodés sont identiques, ou si le deuxième ou les fichiers suivants spécifient la sortie standard pour le fichier de sortie, le résultat n'est probablement pas celui attendu. Plus précisément, la sortie standard sera ajoutée et les fichiers de sortie nommés seront remplacés.

Veuillez envoyer les rapports de bogues à : bug-gnu-utils@gnu.org
