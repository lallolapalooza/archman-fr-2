NOM

udpxy - un démon de relais de trafic multicast UDP vers HTTP.

SYNOPSIS

udpxy [-vTS] [-a <adresse_ecoute>] [-m <adresse_ifc_mcast>] [-c <clients>] [-l <fichier_log>] [-B <tailleK>] [-R <msg>] [-H <sec>] [-n <incr_nice>] [-M <sec>] -p <port>

DESCRIPTION

udpxy est un démon de relais de trafic multicast UDP vers HTTP : il transfère le trafic UDP d'un abonnement multicast donné vers le client HTTP demandeur.

udpxy écoute (sur une adresse/port dédié) les requêtes HTTP émises par les clients. Une requête client doit être structurée comme suit :

http://{adresse}:{port}/{cmd}/{adresse_groupe_mcast}[SEP]{port_groupe_mcast}

[SEP]
:|%|~|+|-|^
{cmd}
udp|rtp

où adresse et port correspondent à la combinaison adresse/port d'écoute de udpxy, et adresse_groupe_mcast:port_groupe_mcast identifient le groupe/canal multicast auquel s'abonner.

udp
la commande udp fera en sorte que udpxy recherche les types de payload connus (tels que MPEG-TS et RTP sur MPEG-TS) ;
rtp
la commande rtp fait supposer à udpxy un payload RTP sur MPEG-TS, sautant ainsi les sondages.

udpxy démarrera un processus client séparé pour chaque nouvelle demande de relais (dans la limite spécifiée de clients actifs). Le processus client relaira/transférera tout le trafic réseau reçu (via un socket UDP) du groupe multicast spécifié vers la connexion HTTP demandée.

udpxy prend également en charge quelques requêtes administratives :

status
http://adresse:port/status/ pour renvoyer une page HTML avec l'état du démon et les statistiques des clients.
restart
http://adresse:port/restart/ pour fermer toutes les connexions actives et redémarrer.

EXEMPLES

http://192.168.0.12:5056/udp/224.0.2.26:24012

http://192.168.0.12:5056/rtp/224.0.2.26:24012

http://192.168.0.15:5056/rtp/224.0.2.26^24055

http://192.168.0.15:5056/status/

OPTIONS

udpxy accepte les options suivantes :

-v
Activer la sortie détaillée [défaut = désactivé].
-S
Activer les statistiques clients [défaut = désactivé].
-T
Ne PAS exécuter en tant que démon [défaut = démon si root].
-a <adresse_ecoute>
Adresse/interface IPv4 sur laquelle écouter [défaut = 0.0.0.0].
-m <adresse_ifc_mcast>
Adresse/interface IPv4 de la source (multicast) [défaut = 0.0.0.0].
-c <clients>
Nombre maximum de clients à accepter [défaut = 3, max = 5000].
-l <fichier_log>
Journaliser la sortie dans un fichier [défaut = stderr].
-B <tailleK>
Taille du tampon (65536, 32Ko, 1Mo) pour les données entrantes (multicast) [défaut = 2048 octets].
-R <msg>
Nombre maximum de messages à mettre en tampon (-1 = tout) [défaut = 1].
-H <sec>
Temps maximum (en secondes) pour conserver les données dans un tampon (-1 = illimité) [défaut = 1].
-n <incr_nice>
Incrément de la valeur nice [défaut = 0].
-M <sec>
Renouveler l'abonnement multicast toutes les M secondes (ignorer si 0) [défaut = 0].
-p <port>
Port d'écoute.

TYPES DE PAYLOAD ET GESTION

udpxy reconnaît les payloads MPEG-TS et RTP sur MPEG-TS dans les paquets relaiés ; si udpxy rencontre un payload RTP, il le 'traduit' automatiquement en MPEG-TS (en retirant les en-têtes RTP) de sorte que les lecteurs multimédias qui ne reconnaissent pas RTP puissent tout de même lire le flux.

Jusqu'à présent, aucune traduction n'est effectuée pour les autres types de payload.

ENREGISTREMENT DU TRAFIC MPEG

udpxy inclut une fonctionnalité pour enregistrer le trafic capturé sous forme de flux MPEG-TS brut dans un fichier. Cette fonctionnalité est activée via udpxrec : une application groupée et liée avec udpxy (en un seul exécutable).

udpxrec est appelé via un lien symbolique (nommé udpxrec) vers l'exécutable udpxy (c'est-à-dire ne renommez pas l'exécutable udpxy).

udpxrec crée des fichiers MPEG encapsulant des segments MPEG-TS ; certains lecteurs multimédias ne liront PAS de tels fichiers ; afin de les rendre lisibles, le flux doit être transcodé en MPEG-PS ; vlc 'sait' comment faire un tel transcodage, voici un exemple de ligne de commande :

vlc input-ts.mpg --sout="#std{access=file,mux=ps,dst=out-ps.mpg}"

Le fichier MPEG-PS résultant peut être lu par la plupart des lecteurs multimédias.

ENVIRONNEMENT

udpxy utilise les variables d'environnement suivantes pour compléter ses options en ligne de commande ; les variables sont prises en compte pour les options que la plupart des gens n'auront pas besoin de changer trop souvent (ou simplement qu'il est peu pratique d'utiliser en ligne de commande).

NB : S'il existe un commutateur en ligne de commande qui intersects fonctionnellement avec une variable d'environnement, le commutateur a toujours une priorité plus élevée.

UDPXY_RCV_TMOUT
délai (sec) sur le flux de données entrant (multicast), défaut=5 ;
UDPXY_DHOLD_TMOUT
délai (sec) pour conserver les données tamponnées avant de les envoyer/vider aux clients, défaut=1 ;
UDPXY_SREAD_TMOUT
délai (sec) pour lire depuis le socket d'écoute (gestion des requêtes HTTP), défaut=1 ;
UDPXY_SWRITE_TMOUT
délai (sec) pour écrire dans le socket d'écoute (gestion des requêtes HTTP), défaut=1 ;
UDPXY_SSEL_TMOUT
délai (sec) pour select(2) dans la boucle serveur (inutilisé si pselect(2) est utilisé), défaut=30 ;
UDPXY_LQ_BACKLOG
taille de la file d'attente du socket d'écoute, défaut=16 ;
UDPXY_SRV_RLWMARK
marque basse d'eau sur le socket de réception (m-cast), défaut=0 ( non définie) ;
UDPXY_SSOCKBUF_NOSYNC
ne pas synchroniser la taille du tampon du socket entrant (UDP) (avec la valeur définie par -B), défaut=1 ( synchroniser) ;
UDPXY_DSOCKBUF_NOSYNC
ne pas synchroniser la taille du tampon du socket sortant (TCP) avec la valeur définie par -B), par défaut=1 (sync) ;
UDPXY_TCP_NODELAY
désactiver l'algorithme de Nagle sur le socket nouvellement accepté (commutation de canal plus rapide), par défaut=1 ;
UDPXY_HTTP200_FTR_FILE
ajouter le contenu du fichier texte donné à la réponse HTTP 200, par défaut=aucun ;
UDPXY_HTTP200_FTR_LN
ajouter le texte (ligne) à la réponse HTTP 200, par défaut=aucun ;
UDPXY_ALLOW_PAUSES
si bloqué sur une write(2), continuer à lire les données jusqu'à ce que le tampon (-B <tailleK>) soit plein, par défaut=désactivé ;
UDPXY_PAUSE_MSEC
autoriser seulement N millisecondes de lecture de données lors d'un blocage sur une write(2).
UDPXY_CONTENT_TYPE
spécifier un Content-Type personnalisé dans les réponses HTTP.
