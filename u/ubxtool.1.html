UBXTOOL(1) Documentation GPSD UBXTOOL(1)

NOM

ubxtool - outil u-blox

SYNTAXE

ubxtool [OPTIONS} [serveur[:port[:périphérique]]]

ubxtool -h

ubxtool -V

DESCRIPTION

ubxtool est un outil pour GPS u-blox. Si vous n'avez pas de GPS u-blox, vous pouvez arrêter de lire maintenant.

Cet outil fonctionne avec votre GPS u-blox à un niveau très bas. Pour comprendre ubxtool, vous devez d'abord être familier avec votre GPS u-blox et la documentation du protocole binaire u-blox. Le protocole u-blox varie considérablement en fonction du modèle de GPS et de la révision du firmware. Utilisez la documentation u-blox pour votre modèle et votre firmware.

ubxtool peut décoder les messages binaires courants de u-blox, interroger l'état du GPS, activer et désactiver les fonctionnalités du GPS, et envoyer des commandes générées par l'utilisateur au GPS. Il peut lire des messages binaires à partir d'un fichier. Il peut lire et écrire directement via un périphérique série, ou via une instance gpsd en cours d'exécution.

ubxtool ne nécessite pas de privilèges root, sauf peut-être pour accéder au port série en mode d'accès direct (-f FICHIER). Il fonctionnera correctement en tant que root. L'exécution sous sudo entraînera une perte de fonctionnalités.

OPTIONS

Le programme accepte les options suivantes :

-?, -h, --help

Fait afficher à ubxtool un message d'utilisation et quitte. Utilisez avec -v 2 pour voir toutes les valeurs d'activation/désactivation et prédéfinies. Utilisez avec -v 3 pour voir également tous les éléments de configuration (long).

-c COMMANDE, --command COMMANDE

Envoie une commande au GPS. Accepte un paramètre, COMMANDE, une liste d'octets hexadécimaux séparés par des virgules, spécifiant la classe, l'identifiant et toute charge utile nécessaire. L'en-tête, la longueur et la somme de contrôle sont ajoutés automatiquement.

--device PÉRIPHÉRIQUE

Le PÉRIPHÉRIQUE sur gpsd auquel se connecter. Par défaut, tous.

-d OPTION, --disable OPTION

Désactive une option dans le GPS. Accepte un paramètre, OPTION, l'option à désactiver. Exécutez "ubxtool -h -v 2" pour voir toutes les OPTIONS possibles. Quelques OPTIONS possibles sont :

BEIDOU

Désactive l'utilisation de la constellation BeiDou (COMPASS).

BINARY

Désactive l'envoi des messages binaires de base.

ECEF

Désactive l'envoi des messages binaires ECEF.

GALILEO

Désactive l'utilisation de la constellation GALILEO.

GLONASS

Désactive l'utilisation de la constellation GLONASS.

GPS

Désactive l'utilisation des constellations GPS et QZSS.

NED

Désactive l'envoi des messages binaires NED. UBX-NAV-VELNED et UBX-NAV-RELPOSNED.

NMEA

Désactive l'envoi des messages NMEA de base. Les messages sont GBS, GGA, GSA, GGL, GST, GSV, RMC, VTG, et ZDA.

PPS

Désactive TIMEPULSE 0.

RAWX

Désactive l'envoi des messages UBX-RXM-RAWX.

SBAS

Désactive l'utilisation de la constellation SBAS.

SFRBX

Désactive l'utilisation des messages SFRBX.

SURVEYIN

Désactive le mode survey-in avec TMODE2.

TP

Désactive l'envoi de UBX-TIM-TP.

-e OPTION, --enable OPTION

Active une option dans le GPS. Accepte un paramètre, OPTION, l'option à activer. -e accepte les mêmes OPTIONS que -d, sauf que l'action est d'activer l'option.

-f FICHIER, --file FICHIER

Se connecte directement à un fichier ou un périphérique. Accepte un paramètre, FICHIER, le fichier ou le périphérique à ouvrir. Les fichiers sont ouverts en lecture seule. Les périphériques caractères sont ouverts en lecture/écriture, sauf si le paramètre -r est donné. Nécessite le module pyserial.

-g OBJET,COUCHE,POSITION,FIN, --getitem OBJET,COUCHE,POSITION,FIN

Obtient la valeur de OBJET de COUCHE, en commençant à POSITION, jusqu'à END paires clé/valeur (UBX-CFG-VALGET). Tous les paramètres après OBJET sont optionnels et décimaux. Si COUCHE est absent, alors les couches 0, 1, 2 et 7 sont toutes demandées. Voir la section sur les OBJETS DE CONFIGURATION

--host HOTE

Se connecte au gpsd sur HOTE (serveur). Par défaut, localhost.

-i port, --portid port

Spécifie l'identifiant de port # (interface) pour les commandes liées aux ports telles que UBX_CFG-PRT.

-p PRÉDÉFINI, --preset PRÉDÉFINI

Envoie une commande prédéfinie au GPS. Accepte généralement un paramètre, PRÉDÉFINI, le nom de la commande à envoyer. Quelques PRÉDÉFINIS, comme LOG-FINDTIME, acceptent des paramètres supplémentaires séparés par des virgules. Plus d'un -p peuvent être utilisés.

Seuls les PRÉDÉFINIS courants sont montrés ici. Pour voir la liste complète, y compris les paramètres optionnels, exécutez "ubxtool -h -v 2".

COLDBOOT

Redémarre à froid le GPS (UBX-CFG-RST).

HOTBOOT

Redémarre à chaud le GPS (UBX-CFG-RST).

MODEL,modèle

Configure le Modèle de Plateforme Dynamique sur modèle. (UBX-CFG-NAV5). Le modèle est le numéro décimal du mode désiré.

PMS

Définit les paramètres de gestion d'alimentation (UBX-CFG-PMS). "PMS,pow" où pow est la valeur de configuration de l'alimentation.

RATE

Définit le taux de mesure et de navigation (UBX-CFG-RATE). "RATE,mes,nav" mes est le taux de mesure en millisecondes. L'argument nav est le taux de navigation en cycles et vaut 1 par défaut.

RESET

Réinitialise la configuration par défaut (UBX-CFG-CFG).

SAVE

Sauvegarde la configuration actuelle (UBX-CFG-CFG).

MON-RESETODO

Réinitialise l'odomètre (UBX-MON-RESETODO).

MON-VER

Interroge la version du GPS (UBX-MON-VER).

WARMBOOT

Redémarre le GPS à chaud (UBX-CFG-RST).

La plupart des paramètres PRÉDÉFINIS sont de simples commandes d'interrogation. Ils interrogent simplement le GPS pour qu'il réponde avec le message associé. Par exemple "ubxtool -p CFG-GNSS" demande au GPS de répondre avec un message UBX-CFG-GNSS décrivant la configuration GNSS actuelle. Augmentez la verbosité de la sortie en ajoutant les options "-v 2" ou "-v 3".

--port PORT

Utilise le PORT pour se connecter à gpsd. Par défaut, 2947.

-P protver, --protver protver

Définit la version du protocole à utiliser pour envoyer des commandes. Minimum 6 (Antaris 4). Utilisez "ubxtool -p MON-VER" pour voir la version supportée par votre récepteur. De nombreux récepteurs u-blox plus récents échoueront silencieusement ou étrangement si cela n'est pas correctement défini. Par défaut 10 (u-blox 5).

-r, --readonly

Lecture seule. N'envoie rien au GPS.

-R BRUT, --rawfile BRUT

Sauvegarde toutes les données série brutes reçues du GPS dans le fichier BRUT.

-s VITESSE, --inspeed VITESSE

Définit la vitesse du port série local à VITESSE bps. Par défaut 9 600 bps.

-S VITESSE, --setspeed VITESSE

Définit la vitesse du port série du GPS à VITESSE bps.

-t, --timestamp

Horodate les messages décodés avec les secondes depuis l'époque. Utilisez-le deux fois et obtenez également l'heure UTC.

-v VERBOSITE, --verbosity VERBOSITE

Définit le niveau de verbosité à VERBOSITE. La verbosité peut aller de 0 (très silencieux), 2 (décoder les messages), à 4 (très bavard). Par défaut 1.

-V, --version

Affiche la version de ubxtool et quitte.

-w ATTENTE, --wait ATTENTE

Attend ATTENTE secondes avant de quitter. Utilisez 0 pour attendre indéfiniment. Par défaut 2 secondes.

-x OBJET,COUCHES, --delitem OBJET,COUCHES

Supprime la valeur du nom OBJET des COUCHES. Le masque de bits COUCHES est optionnel. Par défaut, supprime dans les couches BBR et FLASH du récepteur (UBX_CFG-VALDEL). Retourne à la valeur par défaut du récepteur pour cet objet. Voir la section sur les OBJETS DE CONFIGURATION

-z OBJET,VAL,COUCHES, --setitem OBJET,VAL,COUCHES

Définit la valeur du nom OBJET à VAL dans COUCHES dans le GPS (UBX-CFG-VALSET). VAL et le masque de bits COUCHES sont décimaux. ",COUCHES" est optionnel. Les COUCHES par défaut sont RAM et FLASH. Voir la section sur les OBJETS DE CONFIGURATION

ubxtool(1) - Man page

NAME

ubxtool - U-blox binary protocol tool

SYNOPSIS

ubxtool [OPTIONS] [server[:port[:device]]]

DESCRIPTION

The ubxtool utility is a command-line tool for interacting with u-blox GPS receivers using the u-blox binary protocol.

OPTIONS

The following options are supported:

-a, --ascii
Dump message data in ASCII format.
-b baudrate, --baudrate baudrate
Set serial port baudrate. This option is ignored when interacting with a remote server.
-c CLASS, --class CLASS
Message class.
-d device, --device device
Use the specified serial device.
-f file, --file file
Read from file instead of a serial device or network socket.
-g ITEM, --get ITEM
Get the value of configuration ITEM.
-h, --help
Show program help.
-i interface, --interface interface
Use the specified network interface.
-l, --list
List available messages.
-m ID, --message-id ID
Message ID.
-p CMD, --poll CMD
Poll for message CMD. See the u-blox protocol specification for a list of available commands.
-P version, --protocol-version version
Set the protocol version. Default is 18.
-r, --raw
Dump message data in raw format.
-s seconds, --timeout seconds
Set timeout in seconds.
-S speed, --speed speed
Set serial port speed.
-t, --timestamp
Prepend a timestamp to each line of output.
-u, --unlog
Unlog messages.
-v level, --verbose level
Set verbose level (0-4).
-w seconds, --wait seconds
Wait additional seconds for operations to complete.
-x ITEM, --delete ITEM
Reset configuration ITEM to its default value.
-z ITEM,VAL[,LAYER], --set ITEM,VAL[,LAYER]
Set configuration ITEM to VAL. Optionally specify LAYER (e.g., RAM, BBR, FLASH).

ARGUMENTS

By default, clients collect data from the local gpsd daemon running on localhost, using the default GPSD port 2947. The optional argument to any client may override this behavior: [server[:port[:device]]]

For further explanation, and examples, see the ARGUMENTS section in the gps(1) man page

CONFIGURATION ITEMS

Configuring u-blox GPS with the traditional configuration messages is fraught with problems. Many configuration messages interact in odd ways. Something as simple as changing the serial port speed requires you to read the current configuration using UBX-CFG-PRT for the proper port, merging in the change, the writing back the changed UBX-CFG-PRT message. Or just guessing at the current configuration and overwriting it all.

The u-blox 9 series, protocol version 27+, tries, but does not completely succeed, to solve the problem with Configuration Items. If your GPS does not support protocol version 27+, then this section does not apply to you.

Most of the configuration variables in the GPS have been assigned a 32-bit Key ID. Each Key references one specific value. A typical receiver may have over 1,100 Key IDs. Each Key ID has been assigned a Key Name. Most of the Key Names are documented by u-blox and supported by ubxtool. To see all the Key Name understood by ubxtool run: "ubxtool -h -v 3".

To get the value related to an item, use "-g ITEM".

To reset the value related to an item to it default value, use "-x ITEM".

To set an ITEM name to a value, use "-z ITEM,VAL".

If you only want to set an ITEM in one layer, use "-z ITEM,VAL,LAYER".

See the EXAMPLES section for concrete examples.

EXAMPLES

All examples assume that UBXOPTS is set with the protocol version of your receiver. Be sure to replace the "-P 18" with your correct prototype version.

export UBXOPTS="-P 18"

Dump configuration and status of the GNSS recceiver. The "-w 4" is to provide extra time for the operations to complete.

ubxtool -p CONFIG -p STATUS -w 4 -v 2

Decode raw log file:

ubxtool -r -f ublox-neo-m8n.log

Change GPS port speed of device on /dev/ttyAMA0 to 230,400 bps:

ubxtool -S 230400 -f /dev/ttyAMA0

Watch entire GPS reset cycle, include $GPTXT messages:

ubxtool -p COLDBOOT -w 20 -v 2

Poll Enabled Constellations:

ubxtool -p CFG-GNSS

Dump gpsd data from a remote server named x.example.com:

ubxtool -w 5 x.example.com

CFG-TP5

Some of the "-p" and "--preset" commands can take multiple options. One of these is "--preset CFG-TP5".

Synopsis:

-p CFG-TP5,[tpIdx = 0],[antCableDelay = 2],[rfGroupDelay = 0],[freqPeriod = 1000000],[freqPeriodLock = 1000000],[pulseLenRatio = 0],[pulseLenRatioLock = 100000],[userConfigDelay = 0],[flags = 0x77]

Leave a positional parameter empty for it to take the default value.

To set the pulse period to 0.25 s and its length to 0.1 s:

$ ubxtool -p CFG-TP5,,,,250000,250000,100000,100000

To set the pulse period to 0.1 s and length to 0.1 s in the presence of lock:

$ ubxtool -p CFG-TP5,,,,,100000,,50000

Version 27+ examples

The following examples require a GPS supporting protocol 27 or greater. Be sure to set your protocol version first:

    export UBXOPTS="-P 32"

To check the current dynamic model, change it to 6 (AIR1, Airborne with <1g acceleration), revert to the default setting, and verify the faults was restored.

$ ubxtool -g CFG-NAVSPG-DYNMODEL
[...]
UBX-CFG-VALGET:
 version 1 layer 0 reserved 0,0
  layers (ram)
    item CFG-NAVSPG-DYNMODEL/0x20110021 val 2
[...]
$ ubxtool -z CFG-NAVSPG-DYNMODEL,6
[...]
UBX-ACK-ACK:
 ACK to Class x6 (CFG) ID x8a (VALSET)
[...]
$ ubxtool -g CFG-NAVSPG-DYNMODEL
[...]
UBX-CFG-VALGET:
 version 1 layer 0 reserved 0,0
  layers (ram)
    item CFG-NAVSPG-DYNMODEL/0x20110021 val 6
[...]
$ ubxtool -x CFG-NAVSPG-DYNMODEL
[...]
UBX-ACK-ACK:
 ACK to Class x6 (CFG) ID x8c (VALDEL)
[...]
$ ubxtool -g CFG-NAVSPG-DYNMODEL
[...]
UBX-CFG-VALGET:
 version 1 layer 0 reserved 0,0
  layers (ram)
    item CFG-NAVSPG-DYNMODEL/0x20110021 val 6

Notice that the current DYNMODEL stayed at 6 (AIR1). The "-x" only affects the saved setting, not the current setting. To change the current setting you must set it with "-z".

Getting all the Configuration Items in a group one by one could be very tedious. VAL-GET allows you to wild card the item number and dump all the items in a group. To get all the CFG-TP items in ram, the currently active ones, you can do this:

$ ubxtool -g CFG-TP,0
[...]
UBX-CFG-VALGET:
 version 1 layer 0 position 0
  layers (ram)
    item CFG-TP-TP1_ENA/0x10050007 val 1
    item CFG-TP-SYNC_GNSS_TP1/0x10050008 val 1
    item CFG-TP-USE_LOCKED_TP1/0x10050009 val 1
[...]

The truly masochistic can dump all the Configuration Items by wildcarding the group. Dumping all 1,000+ of them, 64 at a time, could still be tedious. The -g parameter optionally allows you to specify the starting position to get from, as well as the ending position. To get all the known, and unknown, items supported by the receiver that are currently in ram:

$ ubxtool -g CFG,0,0,1200 | fgrep "item CFG-"
    item CFG-1-1/0x10010001 val 0
    item CFG-1-1/0x10010101 val 0
    item CFG-4-1/0x10040001 val 1
    item CFG-4-2/0x10040002 val 0
    item CFG-4-3/0x10040003 val 0
    item CFG-4-4/0x10040004 val 0
    item CFG-4-9/0x10040009 val 0
    item CFG-TP-TP1_ENA/0x10050007 val 1
    item CFG-TP-SYNC_GNSS_TP1/0x10050008 val 1
[...]

Changing CFG,0,0,1200 to CFG,7,0,1200 would instead dump all the configuration defaults, from the Default layer (7).

ENVIRONMENT

Options can be placed in the UBXOPTS environment variable. UBXOPTS is processed before the CLI options.

RETURN VALUES

0

on success.

1

on failure
