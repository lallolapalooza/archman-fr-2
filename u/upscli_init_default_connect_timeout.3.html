upscli_init_default_connect_timeout(3)

Paquet: nut

Licences: GPL-2.0-or-later AND GPL-3.0-or-later

UPSCLI_INIT_DEFAULT_(3) Manuel NUT UPSCLI_INIT_DEFAULT_(3)

NOM

upscli_init_default_connect_timeout - Initialise l'aspect du module upsclient du délai de connexion par défaut.

SYNTAXE

        #include <upsclient.h>
        int upscli_init_default_connect_timeout(
                const char *cli_secs,
                const char *config_secs,
                const char *default_secs);

DESCRIPTION

La fonction upscli_init_default_connect_timeout() initialise l'aspect du module upsclient du délai de connexion par défaut pour upscli_connect(3), ce qui peut être important lorsque par exemple le scripting de upsc(8) ou la configuration de upsmon(8) font référence à des hôtes non réactifs, ou lorsque la résolution de noms d'hôtes est lente, etc. Par défaut, upscli_connect(3) bloque indéfiniment dans ses tentatives de connexion (ou jusqu'à ce que la couche de transport système interrompe une telle tentative).

Elle remplit la valeur à partir de différentes sources, principalement des chaînes de caractères C qui représentent un nombre flottant non négatif (une analyse invalide est enregistrée et peut affecter la valeur de retour), l'une ou toutes pouvant être NULL pour être ignorées, et dans un ordre spécifique (la dernière correspondance valide l'emporte) :

•0 intégré signifiant un blocage indéfini (défaut NUT pour cette méthode depuis au moins 20 ans) ;
•le nombre de default_secs comme préférence intégrée (basse priorité) d'un programme client NUT ou tiers particulier ;
•le nombre de la variable d'environnement NUT_DEFAULT_CONNECT_TIMEOUT comme préférence locale au site (généralement pré-configurée dans nut.conf(5)) ;
•le nombre de config_secs comme défaut du fichier de configuration d'un programme client NUT ou tiers particulier ;
•le nombre de cli_secs comme réglage depuis la ligne de commande d'un programme client NUT ou tiers particulier (priorité la plus élevée).

En interne, appelle upscli_set_default_connect_timeout(3) pour la plupart du traitement lié aux chaînes de caractères.

Le module upsclient suit si la fonction upscli_init_default_connect_timeout() a été appelée et a réussi, afin de l'appeler une fois (si jamais elle n'a pas été utilisée) depuis les méthodes upscli_connect(3) ou upscli_init(3). Cela permet aux clients NUT non modifiés (hérités) de bénéficier de manière cohérente de la présence de la variable d'environnement NUT_DEFAULT_CONNECT_TIMEOUT.

Ce suivi n'empêche pas les programmes d'appeler explicitement la méthode autant de fois que nécessaire.

VALEUR DE RETOUR

La fonction upscli_init_default_connect_timeout() retourne 0 en cas de succès (soit si toutes les chaînes étaient NULL donc le défaut intégré est appliqué, soit si au moins une de ces chaînes qui étaient définies était valide et sa valeur a été appliquée), soit -1 si une erreur se produit (au moins une chaîne n'était pas NULL, et aucune des chaînes n'était valide).

VOIR AUSSI

upscli_connect(3), upscli_tryconnect(3), upscli_set_default_connect_timeout(3), upscli_get_default_connect_timeout(3), upscli_init(3)
