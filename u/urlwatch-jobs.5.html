NOM

urlwatch-jobs - Types de jobs et configuration pour urlwatch

SYNOPSIS

urlwatch --edit

DESCRIPTION

Les jobs sont les types de choses que urlwatch(1) peut surveiller.

La liste des jobs à exécuter se trouve dans le fichier de configuration urls.yaml, accessible avec la commande urlwatch --edit, chacun séparé par une ligne ne contenant que ---. La commande urlwatch --list affiche le nom de chaque job, ainsi que son numéro d'index (1, 2, 3, ...) qui lui est attribué automatiquement selon sa position dans le fichier de configuration.

Bien qu'optionnelle, il est recommandé que chaque job commence par une entrée name :

name: "Ceci est un nom/label lisible par l'homme pour le job"

Les types de jobs suivants sont disponibles :

URL

C'est le type de job principal -- il récupère un document à partir d'un serveur web :

name: "page d'accueil urlwatch"
url: "https://thp.io/2008/urlwatch/"

Clés requises :

•
url : L'URL du document à surveiller pour les changements

Clés optionnelles spécifiques au job :

  • cookies : Cookies à envoyer avec la requête (voir Sujets avancés)
  • method : Méthode HTTP à utiliser (par défaut : GET)
  • data : Données HTTP POST/PUT
  • ssl_no_verify : Ne pas vérifier les certificats SSL (vrai/faux)
  • ignore_cached : Ne pas utiliser les valeurs de contrôle de cache (ETag/Last-Modified) (vrai/faux)
  • http_proxy : Serveur proxy à utiliser pour les requêtes HTTP (peut être http:// ou socks5://)
  • https_proxy : Serveur proxy à utiliser pour les requêtes HTTPS (peut être http:// ou socks5://)
  • headers : En-tête HTTP à envoyer avec la requête
  • encoding : Ignorer le codage de caractères du serveur (voir Sujets avancés)
  • timeout : Ignorer le délai d'attente par défaut du socket (voir Sujets avancés)
  • ignore_connection_errors : Ignorer les erreurs de connexion (temporaires) (voir Sujets avancés)
  • ignore_http_error_codes : Liste des erreurs HTTP à ignorer (voir Sujets avancés)
  • ignore_timeout_errors : Ne pas signaler les erreurs lorsque le délai d'attente est atteint
  • ignore_too_many_redirects : Ignorer les boucles de redirection (voir Sujets avancés)
  • ignore_incomplete_reads : Ignorer les réponses HTTP incomplètes (voir Sujets avancés)

(Note : url implique kind: url)

BROWSER

Ce type de job est une variante gourmande en ressources de "URL" pour gérer les pages Web qui nécessitent JavaScript pour rendre le contenu surveillé.

Le paquet optionnel playwright doit être installé pour exécuter des jobs de type Browser (voir Dépendances). Vous devrez également installer les navigateurs en utilisant playwright install (voir Installation de Playwright https://playwright.dev/python/docs/intro pour les détails).

name: "Une page avec JavaScript"
navigate: "https://example.org/"

Clés requises :

•
navigate : URL à naviguer avec le navigateur

Clés optionnelles spécifiques au job :

  • wait_until : Soit load, domcontentloaded, networkidle, ou commit (voir Sujets avancés)
  • wait_for : Un sélecteur CSS ou XPath basé sur la spécification : https://playwright.dev/python/docs/locators#locate-by-css-or-xpath. Le job attendra le délai par défaut de 30 secondes.
  • useragent : En-tête User-Agent utilisé pour les requêtes (sinon, le défaut du navigateur est utilisé)
  • browser : Soit chromium, chrome, chrome-beta, msedge, msedge-beta, msedge-dev, firefox, webkit (doit être installé avec playwright install)

Étant donné que ce job utilise Playwright https://playwright.dev/python/ pour rendre la page dans une instance de navigateur sans tête (headless), il utilise massivement plus de ressources qu'un job "URL". Utilisez-le uniquement sur les pages où url ne renvoie pas les résultats corrects. Dans de nombreux cas, au lieu d'utiliser un job "Browser", vous pouvez utiliser la sortie d'une API appelée par la page lors du chargement, qui contient les informations que vous recherchez en utilisant le type de job "URL" beaucoup plus rapide.

(Note : navigate implique kind: browser)

SHELL

Ce type de job permet de surveiller la sortie de commandes shell arbitraires, ce qui est utile par exemple pour surveiller un dossier d'upload FTP, la sortie de scripts qui interrogent des périphériques externes (GPIO RPi), etc...

name: "Que contient mon répertoire personnel ?"
command: "ls -al ~"

Clés requises :

•
command : La commande shell à exécuter

Clés optionnelles spécifiques au job :

•
stderr : Modifier la façon dont la sortie d'erreur standard est traitée, voir ci-dessous

(Note : command implique kind: shell)

Configuration du comportement de stderr pour les jobs shell

Par défaut, urlwatch capture stderr pour le signalement d'erreurs (code de sortie non nul), mais ignore la sortie lorsque le job shell se termine avec le code de sortie 0.

Ce comportement peut être personnalisé en utilisant la clé stderr :

  • ignore : Capturer stderr, signaler en cas de code de sortie non nul, ignorer sinon (par défaut)
  • urlwatch : stderr du job shell est envoyé à stderr du processus urlwatch ; tout message d'erreur sur stderr ne sera pas visible dans le message d'erreur du rapporteur (comportement par défaut hérité de urlwatch 2.24 et versions antérieures)
  • fail : Traiter le job comme échoué s'il y a *une quelconque* sortie sur stderr, même avec un code de sortie 0
  • stdout : Fusionner la sortie de stderr dans stdout, ce qui signifie que la sortie de stderr est également prise en compte pour la détection de changement/diff de urlwatch (similaire à 2>&1 dans un shell)

Par exemple, cette définition de job fera apparaître le job comme échoué, même si le script se termine avec le code de sortie 0 :

command: |
  echo "Sortie standard normale."
  echo "Quelque chose va vers stderr, ce qui fait échouer ce job." 1>&2
  exit 0
stderr: fail

En revanche, si vous souhaitez comparer à la fois stdout et stderr du job, utilisez ceci :

command: |
  echo "Une ligne importante sur stdout."
  echo "Une autre ligne importante sur stderr." 1>&2
stderr: stdout

CLÉS OPTIONNELLES POUR TOUS LES TYPES DE JOBS

  • name : Nom/label lisible par l'homme du job
  • tags : Tableau d'étiquettes (tags), ou une seule étiquette sous forme de chaîne
  • filter : Filtres (le cas échéant) à appliquer à la sortie (peut être testé avec --test-filter)
  • max_tries : Après ce nombre d'exécutions échouées séquentielles, l'erreur sera signalée plutôt qu'ignorée
  • diff_tool : Commande d'un outil personnalisé pour générer du texte de différence
  • diff_filter : Filtres (le cas échéant) à appliquer au résultat de la différence (peut être testé avec --test-diff-filter)
  • treat_new_as_changed : Traitera les jobs n'ayant aucune donnée historique comme CHANGÉ au lieu de NOUVEAU (et créera une différence pour le nouveau job)
