NOM

upssched - Aide à la planification pour l'exécution d'événements à partir d'upsmon

SYNTAXE

upssched


Note

upssched doit être lancé par upsmon(8) via le NOTIFYCMD. Vous ne devriez jamais le lancer directement pendant les opérations normales.

DESCRIPTION

upssched a été créé pour permettre aux utilisateurs d'exécuter des programmes à des moments relatifs aux événements surveillés par upsmon(8). Le but initial était de permettre un arrêt après une période fixe sur batterie, mais d'autres usages sont possibles.

INTÉGRATION

upssched doit être appelé comme NOTIFYCMD dans votre upsmon.conf(5). Il détermine ce qui se passe en fonction des variables d'environnement UPSNAME et NOTIFYTYPE. Vous ne devriez jamais avoir à les gérer directement.

Définissez le drapeau EXEC sur les événements que vous souhaitez voir dans upssched. Par exemple, pour vous assurer qu'upssched entend les événements ONLINE, ONBATT et LOWBATT, les drapeaux ressembleraient à ceci :

NOTIFYFLAG ONLINE EXEC
NOTIFYFLAG ONBATT EXEC
NOTIFYFLAG LOWBATT EXEC

Si vous souhaitez également continuer à écrire dans le syslog, ajoutez-le simplement :

NOTIFYFLAG ONLINE SYSLOG+EXEC
NOTIFYFLAG ONBATT SYSLOG+EXEC
NOTIFYFLAG LOWBATT SYSLOG+EXEC

Pour une liste complète des drapeaux de notification, consultez la documentation de upsmon(8).

CONFIGURATION

Consultez upssched.conf(5) pour des informations sur la configuration de ce programme.

ARRÊTS ANTICIPÉS

Pour arrêter le système plus tôt, définissez une minuterie qui démarre en raison d'une condition ONBATT. Lorsqu'elle se déclenche, faites en sorte que votre CMDSCRIPT appelle votre routine d'arrêt. Elle devrait se terminer en appelant upsmon -c fsd afin qu'upsmon puisse arrêter les esclaves de manière contrôlée.

Assurez-vous d'annuler la minuterie si l'alimentation revient (ONLINE).

DÉBOUTAGE DES ÉVÉNEMENTS

Si votre UPS passe fréquemment sur batterie et en sort, vous pouvez utiliser ce programme pour réduire le nombre de messages de pager envoyés. Plutôt que d'envoyer des pages directement depuis upsmon(8), utilisez une courte minuterie ici. Si la minuterie se déclenche avec l'onduleur toujours sur batterie, envoyez la page. Si l'alimentation revient avant cela, la minuterie peut être annulée et aucune page n'est nécessaire.

ARRIÈRE-PLAN

Ce programme a été écrit principalement pour répondre aux demandes des utilisateurs concernant le scénario d'arrêt anticipé. La conception "externe" du programme (par rapport à upsmon) visait à réduire la charge sur le système moyen. La plupart des gens n'ont pas besoin d'arrêter le système après N secondes sur batterie, car les tests OB+LB habituels sont suffisants.

Ce programme a été créé séparément afin que ces personnes n'aient pas à dépenser de temps CPU et de RAM pour quelque chose qui ne sera jamais utilisé dans leur environnement.

La conception du gestionnaire de minuterie vise également à minimiser l'impact. Il entrera et sortira de la liste des processus si nécessaire. Lorsqu'une nouvelle minuterie est démarrée, un processus sera créé pour surveiller l'horloge et éventuellement démarrer le CMDSCRIPT. Lorsqu'une minuterie se déclenche, elle est retirée de la file d'attente. L'annulation d'une minuterie la retire également de la file d'attente. Lorsqu'aucune minuterie n'est présente dans la file d'attente, le processus d'arrière-plan se termine.

Cela signifie que vous ne verrez upssched s'exécuter que si l'une des deux choses suivantes se produit :

•Il y a actuellement une minuterie de quelque sorte en cours d'exécution
•upsmon vient de l'appeler, et vous avez réussi à attraper cette brève instant

L'optimisation finale gère la possibilité d'essayer d'annuler une minuterie alors qu'il n'y en a aucune en cours d'exécution. Si le démon de minuterie n'est pas en cours d'exécution, il n'y a pas de minuteries à annuler, et de plus, il n'est pas nécessaire de démarrer un moniteur d'horloge. Il saute donc cette étape et se termine plus rapidement.

VARIABLES D'ENVIRONNEMENT

NUT_DEBUG_LEVEL définit le niveau de débogage par défaut si aucun argument -D n'a été fourni sur la ligne de commande, mais ne demande pas que le démon s'exécute en mode avant-plan.


Note

Contrairement à d'autres démons NUT, upssched avec le débogage activé n'arrête pas de signaler sur stderr ! Il crée un processus d'arrière-plan avec le premier appel comme gestionnaire d'événements, qui se termine peu après l'expiration de toutes les minuteries suivies (si nécessaire).

UPSNAME et NOTIFYTYPE sont requis, comme détaillé ci-dessus. Ils sont définis par upsmon lorsqu'il appelle upssched comme choix de NOTIFYCMD.

NUT_CONFPATH est le nom du chemin du répertoire qui contient upssched.conf et d'autres fichiers de configuration. Si cette variable n'est pas définie, upssched utilise une valeur par défaut intégrée, qui est souvent /usr/local/ups/etc.
