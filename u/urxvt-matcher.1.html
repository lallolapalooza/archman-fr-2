NOM

matcher - fait correspondre des chaînes dans la sortie du terminal et modifie leur rendu

DESCRIPTION

Utilise le filtrage d'affichage par ligne ("on_line_update") pour souligner le texte correspondant à un certain motif et le rendre cliquable. Lorsqu'il est cliqué avec le bouton de la souris spécifié dans la ressource "matcher.button" (par défaut 2, ou milieu), le programme spécifié dans la ressource "matcher.launcher" (par défaut, la ressource "url-launcher", "sensible-browser") sera démarré avec le texte correspondant comme premier argument. La configuration par défaut convient pour faire correspondre des URL et lancer un navigateur Web, comme l'ancienne extension "mark-urls".

Le motif par défaut pour faire correspondre les URL peut être remplacé par la ressource "matcher.pattern.0", et des motifs supplémentaires peuvent être spécifiés avec des motifs numérotés, d'une manière similaire à l'extension "selection". Le lanceur peut également être remplacé par motif.

Il est possible d'activer la correspondance la plus récemment vue ou une liste de correspondances depuis le clavier. Liez simplement une touche à "matcher:last" ou "matcher:list" comme vu dans l'exemple ci-dessous.

L'action "matcher:select" active un mode dans lequel il est possible d'itérer sur les correspondances en utilisant le clavier et soit de les activer, soit de les copier dans le presse-papiers. Tant que le mode est actif, l'entrée/sortie normale du terminal est suspendue et les liaisons suivantes sont reconnues :

"Up"
Recherche une correspondance vers le haut.
"Down"
Recherche une correspondance vers le bas.
"Home"
Se déplace vers la première correspondance en haut.
"End"
Se déplace vers la dernière correspondance en bas.
"Escape"
Quitte le mode et retourne au point où la recherche a commencé.
"Enter"
Active la correspondance actuelle.
"y"
Copie la correspondance actuelle dans le presse-papiers.

Il est également possible de parcourir les correspondances en utilisant une combinaison de touches liée à l'action "matcher:select".

Exemple : charge et utilise l'extension matcher avec les paramètres par défaut.

URxvt.perl-ext:           default,matcher

Exemple : utilise une configuration personnalisée.

URxvt.url-launcher:       sensible-browser
URxvt.keysym.C-Delete:    matcher:last
URxvt.keysym.M-Delete:    matcher:list
URxvt.matcher.button:     1
URxvt.matcher.pattern.1:  \\bwww\\.[\\w-]+\\.[\\w./?&@#-]*[\\w/-]
URxvt.matcher.pattern.2:  \\B(/\\S+?):(\\d+)(?=:|$)
URxvt.matcher.launcher.2: gvim +$2 $1

Encodage des expressions régulières / correspondance de caractères larges

Urxvt stocke tout le texte en unicode, dans un encodage spécial qui utilise un caractère/point de code par colonne. Pour diverses raisons, les expressions régulières sont mises en correspondance directement avec cet encodage, ce qui signifie qu'il y a quelques éléments à garder à l'esprit :

Les ressources X / arguments de ligne de commande sont encodés localement
Les expressions régulières provenant de la ligne de commande ou des ressources seront converties de l'encodage local vers l'unicode. Cela peut modifier le nombre de points de code par caractère.
Les caractères larges sont remplis avec $urxvt::NOCHAR
Les caractères larges (tels que le kanji et parfois les tabulations) sont remplis avec une valeur de caractère spéciale ($urxvt::NOCHAR). Cela signifie que des constructions telles que "\w" ou "." ne correspondront qu'à une partie d'un caractère, car $urxvt::NOCHAR n'est pas correspondant par "\w" et les deux ne correspondent qu'à la première « colonne » d'un caractère large.

Cela signifie que vous devez incorporer $urxvt::NOCHAR dans les parties des expressions régulières qui peuvent correspondre à des caractères larges. Par exemple, pour correspondre à "\w+", vous pourriez utiliser "[\w$urxvt::NOCHAR]+" à la place, et pour correspondre à un seul caractère (".") vous pourriez utiliser ".$urxvt::NOCHAR*" à la place.
