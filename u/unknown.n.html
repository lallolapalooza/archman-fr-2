unknown(n) Commandes intégrées Tcl unknown(n)

NOM

unknown - Gère les tentatives d'utilisation de commandes inexistantes

SYNTAXE

unknown nomCmd ?arg arg ...?

DESCRIPTION

Cette commande est appelée par l'interpréteur Tcl chaque fois qu'un script tente d'invoquer une commande qui n'existe pas. L'implémentation par défaut de unknown est une procédure de bibliothèque définie lors de l'initialisation d'un interpréteur par Tcl. Vous pouvez remplacer le unknown par défaut pour modifier sa fonctionnalité, ou vous pouvez enregistrer un nouveau gestionnaire pour les espaces de noms individuels en utilisant la commande namespace unknown. Notez qu'il n'y a pas d'implémentation par défaut de unknown dans un interpréteur sécurisé.

Si l'interpréteur Tcl rencontre un nom de commande pour lequel aucune commande n'est définie (ni dans l'espace de noms actuel, ni dans l'espace de noms global), Tcl recherche l'existence d'un gestionnaire inconnu pour l'espace de noms actuel. Par défaut, ce gestionnaire est une commande nommée ::unknown. S'il n'existe pas de telle commande, l'interpréteur retourne une erreur. Si la commande unknown existe (ou si un nouveau gestionnaire a été enregistré pour l'espace de noms actuel), elle est appelée avec des arguments constitués du nom complètement substitué et des arguments de la commande originale inexistante. La commande unknown fait généralement des choses comme rechercher dans les répertoires de bibliothèques une procédure de commande nommée nomCmd, ou développer des noms de commandes abrégés en longueur complète, ou exécuter automatiquement les commandes inconnues en tant que sous-processus. Dans certains cas (comme l'expansion d'abréviations), unknown modifiera légèrement la commande originale puis la (ré)exécutera. Le résultat de la commande unknown est utilisé comme résultat de la commande originale inexistante.

L'implémentation par défaut de unknown se comporte comme suit. Elle appelle d'abord la procédure de bibliothèque auto_load pour charger la commande. Si cela réussit, elle exécute la commande originale avec ses arguments originaux. Si le chargement automatique échoue et que Tcl est exécuté interactivement, alors unknown appelle auto_execok pour voir s'il existe un fichier exécutable nommé cmd. Si c'est le cas, elle invoque la commande Tcl exec avec cmd et tous les args comme arguments. Si cmd ne peut pas être auto-exécuté, unknown vérifie si la commande a été appelée au niveau supérieur et en dehors de tout script. Si c'est le cas, alors unknown effectue deux étapes supplémentaires. Premièrement, elle vérifie si cmd a l'une des trois formes suivantes : !!, !événement, ou ^ancien^nouveau?^?. Si c'est le cas, alors unknown effectue la substitution d'historique de la même manière que csh pour ces constructions. Enfin, unknown vérifie si cmd est une abréviation unique pour une commande Tcl existante. Si c'est le cas, elle développe le nom de la commande et exécute la commande avec les arguments originaux. Si aucune des tentatives ci-dessus n'a pu exécuter la commande, unknown génère un retour d'erreur. Si la variable globale auto_noload est définie, alors l'étape de chargement automatique est sautée. Si la variable globale auto_noexec est définie, alors l'étape d'exécution automatique est sautée. Dans des circonstances normales, la valeur de retour de unknown est la valeur de retour de la commande qui a été finalement exécutée.

EXEMPLE

Faire en sorte que la commande unknown ait son comportement standard, sauf qu'elle enregistre d'abord le fait qu'une commande n'a pas été trouvée :

# Sauvegarder l'original pour pouvoir le chaîner
rename unknown _original_unknown
# Fournir notre propre implémentation
proc unknown args {
    puts stderr "ATTENTION : commande inconnue : $args"
    uplevel 1 [list _original_unknown {*}$args]
}
