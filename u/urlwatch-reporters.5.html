URLWATCH-REPORTERS(5) Documentation urlwatch URLWATCH-REPORTERS(5)

NOM

urlwatch-reporters - Rapporteurs pour les notifications de changement

SYNTAXE

urlwatch --edit-config

DESCRIPTION

Par défaut, urlwatch(1) imprime les informations sur les changements sur la sortie standard, qui est votre terminal si vous l'exécutez de manière interactive. Si vous l'exécutez via cron(8) ou un autre service de planification, cela dépend de la configuration du planificateur.

Vous pouvez activer un ou plusieurs rapporteurs supplémentaires qui sont utilisés pour envoyer des notifications de changement. Veuillez noter que la plupart des rapporteurs nécessitent des dépendances supplémentaires installées.

Voir urlwatch-config(5) pour les paramètres de configuration généraux.

Pour envoyer une notification de test, utilisez l'option de ligne de commande --test-reporter avec le nom du rapporteur :

urlwatch --test-reporter stdout

Cela créera un rapport de test avec des notifications nouveau, changé, inchangé et erreur (seules celles configurées dans display dans la Configuration seront affichées dans le rapport) et l'enverra via le rapporteur stdout (s'il est activé).

Pour tester si votre rapporteur d'e-mail est correctement configuré, vous pouvez utiliser :

urlwatch --test-reporter email

Tout rapporteur configuré et activé peut être testé.

Si la notification ne fonctionne pas, vérifiez votre configuration et/ou ajoutez l'option de ligne de commande --verbose pour afficher des journaux de débogage détaillés.

RAPPORTEURS INTÉGRÉS

La liste des rapporteurs intégrés peut être récupérée en utilisant :

urlwatch --features

À l'heure actuelle, les rapporteurs suivants sont intégrés :

  • discord: Envoyer un message à un canal Discord
  • email: Envoyer un résumé par e-mail / SMTP / sendmail
  • gotify: Envoyer un message à un serveur Gotify
  • ifttt: Envoyer un résumé via IFTTT
  • mailgun: Envoyer un e-mail via le service Mailgun
  • matrix: Envoyer un message à une salle en utilisant le protocole Matrix
  • mattermost: Envoyer un message à un canal Mattermost
  • prowl: Envoyer une notification détaillée via prowlapp.com
  • pushbullet: Envoyer un résumé via pushbullet.com
  • pushover: Envoyer un résumé via pushover.net
  • shell: Envoyer un message à une commande shell via un pipe
  • slack: Envoyer un message à un canal Slack
  • stdout: Imprimer le résumé sur stdout (la console)
  • telegram: Envoyer un message en utilisant Telegram
  • xmpp: Envoyer un message en utilisant le protocole XMPP

PUSHOVER

Vous pouvez configurer urlwatch pour envoyer des notifications en temps réel sur les changements via Pushover https://pushover.net/. Pour activer cela, assurez-vous d'avoir le paquet Python chump installé (voir Dépendances). Ensuite, modifiez votre configuration (urlwatch --edit-config) et activez pushover. Vous devrez également ajouter à la configuration votre clé utilisateur Pushover et une clé d'application unique (générée en enregistrant urlwatch comme une application sur votre compte Pushover https://pushover.net/apps/build.

Vous pouvez envoyer à un appareil spécifique en utilisant le nom de l'appareil, comme indiqué lorsque vous ajoutez ou affichez votre liste d'appareils dans la console Pushover. Par exemple device: 'MonTéléphone', ou device: 'MonOrdinateurPortable'. Pour envoyer à tous vos appareils, définissez device: null dans votre configuration (urlwatch --edit-config) ou omettez complètement la configuration de l'appareil.

La définition de la priorité est possible via l'option de configuration priority, qui peut être lowest, low, normal, high ou emergency. Tout autre réglage (y compris laisser l'option non définie) correspond à normal.

PUSHBULLET

Les notifications Pushbullet sont configurées de manière similaire à Pushover (voir ci-dessus). Vous devrez ajouter à la configuration votre jeton d'accès Pushbullet, que vous pouvez générer sur https://www.pushbullet.com/#settings

TELEGRAM

Les notifications Telegram sont configurées en utilisant l'API Bot Telegram. Pour cela, vous aurez besoin d'un jeton d'API Bot et d'un identifiant de chat (voir https://core.telegram.org/bots). Exemple de configuration :

telegram:
  bot_token: '999999999:3tOhy2CuZE0pTaCtszRfKpnagOG8IQbP5gf' # votre jeton d'api bot
  chat_id: '88888888' # l'identifiant du chat où les messages doivent être envoyés
  enabled: true

Les messages peuvent être envoyés silencieusement (silent) si vous préférez des notifications sans son, et formatés en mono-espacé (monospace). Par défaut, les notifications ne sont pas silencieuses et aucun formatage n'est effectué.

telegram:
  # ...
  silent: true # le message est envoyé silencieusement
  monospace: true # affiche le message comme un bloc de code pré-formaté

Pour configurer Telegram, depuis votre application Telegram, discutez avec BotFather (Nouveau Message, Recherche, « BotFather »), puis dites /newbot et suivez les instructions. Finalement, il vous indiquera le jeton du bot (sous la forme vue ci-dessus, <nombre>:<chaîne aléatoire>) - ajoutez-le à votre fichier de configuration.

Vous pouvez ensuite cliquer sur le lien de votre bot, ce qui enverra le message /start. À ce stade, vous pouvez utiliser la commande urlwatch --telegram-chats pour lister les conversations privées auxquelles le bot participe. C'est l'identifiant de chat que vous devez mettre dans le fichier de configuration en tant que chat_id. Vous pouvez ajouter plusieurs identifiants de chat sous forme de liste YAML :

telegram:
  bot_token: '999999999:3tOhy2CuZE0pTaCtszRfKpnagOG8IQbP5gf' # votre jeton d'api bot
  chat_id:
    - '11111111'
    - '22222222'
  enabled: true

N'oubliez pas d'activer également le rapporteur.

SLACK

Les notifications Slack sont configurées en utilisant les « Webhooks entrants Slack ». Voici un exemple de configuration :

slack:
  webhook_url: 'https://hooks.slack.com/services/T50TXXXXXU/BDVYYYYYYY/PWTqwyFM7CcCfGnNzdyDYZ'
  enabled: true

Pour configurer Slack, depuis votre équipe Slack, créez une nouvelle application et activez les « Webhooks entrants » sur un canal, vous obtiendrez une URL de webhook, copiez-la dans la configuration comme indiqué ci-dessus.

MATTERMOST

Les notifications Mattermost sont configurées de la même manière que les notifications Slack, l'URL du webhook est différente :

mattermost:
  webhook_url: 'http://{votre-site-mattermost}/hooks/XXXXXXXXXXXXXXXXXXXXXX'
  enabled: true

Voir Webhooks entrants https://developers.mattermost.com/integrate/incoming-webhooks/ dans la documentation Mattermost pour plus de détails.

DISCORD

Les notifications Discord sont configurées en utilisant les « Webhooks entrants Discord ». Voici un exemple de configuration :

discord:
   webhook_url: 'https://discordapp.com/api/webhooks/11111XXXXXXXXXXX/BBBBYYYYYYYYYYYYYYYYYYYYYYYyyyYYYYYYYYYYYYYY'
   enabled: true
   embed: true
   colored: true
   subject: '{count} changements: {jobs}'

Pour configurer Discord, à partir des paramètres de votre serveur Discord, sélectionnez Intégration, puis créez un « Nouveau Webhook », donnez un nom au webhook pour qu'il publie sous ce nom, sélectionnez un canal, appuyez sur « Copier l'URL du Webhook » et collez-la dans la configuration comme indiqué ci-dessus.

Le contenu intégré peut être plus facile à lire et à identifier les rapports individuels. Le sujet précède le rapport intégré et n'est utilisé que lorsque embed est vrai.

Lorsque colored est vrai, les rapports seront intégrés dans une section de code (avec la syntaxe diff) pour activer les couleurs.

GOTIFY

[Gotify](https://gotify.net/) est un serveur pour envoyer et recevoir des messages en temps réel via WebSockets.

Pour envoyer des notifications à un serveur Gotify, vous avez besoin d'un jeton d'application.

Vous pouvez en créer un pour urlwatch comme suit :

1.
Connectez-vous à l'interface Web de votre serveur Gotify.
2.
Accédez à l'onglet "APPS".
3.
Cliquez sur le bouton "CREATE APPLICATION".

4. Remplissez les champs et appuyez sur "CREATE". 6. Cliquez sur l'icône en forme d'œil de la nouvelle entrée créée et copiez le jeton.

Voici une configuration d'exemple :

gotify:
  enabled: true
  priority: 4
  server_url: "http://127.0.0.1:8090"
  title: null
  token: "Aa1yyikLFjEm35A"

IFTTT

Pour configurer les événements IFTTT, vous devez récupérer votre clé ici :

https://ifttt.com/maker_webhooks/settings

L'URL affichée dans "Account Info" a le format suivant :

https://maker.ifttt.com/use/{key}

Dans cette URL, {key} est votre clé d'API. La configuration devrait ressembler à ceci (vous pouvez choisir le nom d'événement que vous souhaitez) :

ifttt:
  enabled: true
  key: aA12abC3D456efgHIjkl7m
  event: nom_de_l_evenement_souhaite

L'événement contiendra trois valeurs dans le JSON envoyé :

  • value1 : Le type de changement (new, changed, unchanged ou error)
  • value2 : Le nom du job (clé name dans jobs.yaml)
  • value3 : L'emplacement du job (clé url, command ou navigate dans jobs.yaml)

Ces valeurs seront transmises à l'action dans votre recette.

MATRIX

Vous pouvez recevoir des notifications via le protocole Matrix https://matrix.org.

Pour ce faire, vous devez d'abord enregistrer un compte Matrix pour le bot sur n'importe quel serveur d'accueil.

Vous devrez ensuite acquérir un jeton d'accès et un identifiant de salle, en utilisant les instructions suivantes, adaptées de ce guide https://t2bot.io/docs/access_tokens/ :

1.
Ouvrez Riot.im https://riot.im/app/ dans une fenêtre de navigation privée.
2.
Enregistrez-vous/Connectez-vous en tant que votre bot, en utilisant son identifiant utilisateur et son mot de passe.
3.
Définissez le nom d'affichage et l'avatar, si désiré.
4.
Sur la page des paramètres, sélectionnez l'onglet "Aide & À propos", faites défiler jusqu'en bas et cliquez sur Jeton d'accès : <cliquez pour révéler>.
5.
Copiez le texte mis en surbrillance dans votre configuration.
6.
Rejoignez la salle dans laquelle vous souhaitez envoyer des notifications.
7.
Accédez aux Paramètres de la salle (icône en forme d'engrenage) et copiez l'ID de salle interne en bas.
8.
Fermez la fenêtre de navigation privée mais ne vous déconnectez pas, car cela invalide le jeton d'accès.

Voici une configuration d'exemple :

matrix:
  homeserver: https://matrix.org
  access_token: "VOTRE_JETON_ICI"
  room_id: "!roomroomroom:matrix.org"
  enabled: true

Vous voudrez probablement utiliser la configuration suivante pour le reporter markdown, si vous avez l'intention de publier les notifications de changement dans une salle Matrix publique, car les messages deviennent rapidement bruyants :

markdown:
  details: false
  footer: false
  minimal: true
  enabled: true

E-MAIL VIA SENDMAIL

Vous pouvez envoyer des e-mails via la commande système sendmail fournie par le MTA. Vous devez définir method: sendmail dans le fichier de configuration :

report:
  email:
    enabled: true
    from: 'postmaster@example.com'
    to: 'recipient@bar.com'
    method: sendmail

E-MAIL VIA GMAIL SMTP

Vous devez configurer votre compte GMail pour autoriser les applications « moins sécurisées » (basées sur mot de passe) à se connecter :

1.
Accédez à https://myaccount.google.com/
2.
Cliquez sur « Connexion et sécurité »
3.
Faites défiler tout en bas jusqu'à « Autoriser les applications moins sécurisées » et activez-la.

Vous ne devriez pas faire cela avec votre compte GMail principal, mais plutôt avec un compte séparé que vous créez uniquement pour envoyer des e-mails via urlwatch. Autoriser les applications moins sécurisées et stocker le mot de passe (même s'il est dans le trousseau) n'est pas une bonne pratique de sécurité pour votre compte principal.

Maintenant, lancez l'éditeur de configuration :

urlwatch --edit-config

Voici les clés que vous devez configurer :

report:
  email:
    enabled: true
    from: votre.nom_utilisateur@gmail.com
    to: votre.destination.email@example.com
    method: smtp
    smtp:
      host: smtp.gmail.com
      auth: true
      port: 587
      starttls: true

Il est préférable de stocker le mot de passe dans votre trousseau, et non dans le fichier de configuration. Pour stocker le mot de passe, exécutez :

urlwatch --smtp-login

Cela vous demandera votre mot de passe, vérifiera la connexion et le stockera dans votre trousseau. Les exécutions ultérieures utiliseront ce mot de passe pour la connexion.

E-MAIL VIA AMAZON SIMPLE E-MAIL SERVICE (SES)

Identique à la configuration GMail ci-dessus, mais utilisez par exemple email-smtp.us-west-2.amazonaws.com comme hôte SMTP, et les paramètres de nom d'utilisateur et de port selon la page de connexion de SES.

CONNEXION SMTP SANS TROUSSEAU

Si, pour une raison quelconque, vous ne pouvez pas utiliser un trousseau pour stocker votre mot de passe (par exemple, lors de son utilisation depuis une tâche cron), vous pouvez également définir l'option insecure_password dans la configuration SMTP :

report:
  email:
    smtp:
      auth: true
      insecure_password: motsecret123

La clé insecure_password sera préférée aux données stockées dans le trousseau. Veuillez noter que, comme son nom l'indique, stocker le mot de passe en clair dans la configuration est une pratique non sécurisée et mauvaise, mais pour un compte e-mail dédié uniquement à l'envoi d'e-mails, cela peut être une solution. N'utilisez jamais cela avec votre compte e-mail principal ! Sérieusement ! Créez un compte GMail (ou autre) jetable juste pour envoyer ces e-mails ou utilisez le sendmail local avec un serveur de messagerie configuré au lieu de vous fier à SMTP et à l'authentification par mot de passe.

Notez que cela rend très facile pour votre mot de passe d'être récupéré par des logiciels fonctionnant sur votre machine, par d'autres utilisateurs connectés au système et/ou pour que le mot de passe apparaisse accidentellement dans les fichiers journaux.

XMPP

Vous pouvez recevoir des notifications via le protocole XMPP.

Pour ce faire, vous devriez enregistrer un nouveau compte XMPP qui est uniquement utilisé pour urlwatch.

Voici une configuration d'exemple :

xmpp:
  enabled: true
  sender: "NOM_DU_COMPTE_BOT"
  recipient: "VOTRE_NOM_DE_COMPTE"

Le mot de passe n'est pas stocké dans le fichier de configuration, mais dans votre trousseau. Pour stocker le mot de passe, exécutez : urlwatch --xmpp-login et entrez votre mot de passe.

Si, pour une raison quelconque, vous ne pouvez pas utiliser un trousseau pour stocker votre mot de passe, vous pouvez également définir l'option insecure_password dans la configuration XMPP. Pour plus d'informations sur les implications de sécurité, voir Connexion SMTP sans trousseau.

PROWL

Vous pouvez recevoir des notifications via le service de notification push Prowl, pour recevoir la notification sur iOS.

Pour ce faire, vous devriez enregistrer un nouveau compte Prowl et avoir l'application Prowl installée sur votre appareil iOS.

Pour créer une clé d'API pour urlwatch :

1.
Connectez-vous au site Web Prowl sur https://prowlapp.com/
2.
Accédez à l'onglet « API Keys ».
3.
Faites défiler jusqu'à la section « Generate a new API key ».
4.
Donnez à la clé une note qui vous rappellera que vous l'avez utilisée pour urlwatch.
5.
Appuyez sur « Generate Key »
6.
Copiez la clé résultante.

Voici une configuration d'exemple :

prowl:
  enabled: true
  api_key: '<votre clé d'api ici>'
  priority: 2
  application: 'urlwatch example'
  subject: '{count} changements : {jobs}'

Le champ « subject » est similaire au champ sujet de l'e-mail, et sera utilisé comme nom de l'événement Prowl. L'application est ajoutée au début de l'événement et affichée comme source de l'événement dans l'application Prowl.

SHELL

Ceci est un reporter simple qui envoie la notification texte du rapport à une commande de votre choix. La commande est exécutée à l'aide de subprocess.Popen() de Python https://docs.python.org/3/library/subprocess.html#popen-constructor avec shell=False (pour éviter une expansion shell potentiellement indésirable). Bien sûr, vous pouvez créer votre propre script shell qui effectue une expansion shell et d'autres actions, et l'appeler à partir de la command.

La clé ignore_stdout (par défaut true) peut être utilisée pour ignorer tout

urlwatch-reporters(5) — urlwatch manual

SHELL

This reporter executes a shell command, piping the report to its stdin. The command is invoked for each report. If the command exits with a non-zero exit code, urlwatch will log an error message in its log file.

It is possible to send the output of the command to stdout or stderr. If stdout/stderr are not ignored, urlwatch will log any possible output in its --verbose log.

The report written to stdin of the process is based on the output of the text reporter, configuring the text reporter will adjust the data sent to the shell reporter.

For example, to simply append reports to a file, configure it like this:

shell:
  enabled: true
  command: ['tee', '-a', '/path/to/log.txt']
  ignore_stdout: true
