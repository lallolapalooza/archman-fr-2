UUX(1P) Manuel du programmeur POSIX UUX(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uux — exécution de commandes distantes

SYNTAXE

uux [-jnp] chaîne-commande

DESCRIPTION

L'utilitaire uux rassemblera zéro ou plusieurs fichiers de divers systèmes, exécutera un pipeline de shell (voir Section 2.9, Commandes Shell) sur un système spécifié, puis enverra la sortie standard de la commande vers un fichier sur un système spécifié. Seule la première commande d'un pipeline peut avoir un préfixe nom-système!. Toutes les autres commandes du pipeline seront exécutées sur le système de la première commande.

Les restrictions suivantes s'appliquent au pipeline de shell traité par uux :

*
Lors du rassemblement de fichiers provenant de différents systèmes, l'expansion des noms de chemin ne sera pas effectuée par uux. Ainsi, une requête telle que :
uux "c99 remsys!~/*.c"

tenterait de copier le fichier nommé littéralement *.c vers le système local.

*
Les opérateurs de redirection ">>", "<<", ">|", et ">&" ne seront pas acceptés. Toute utilisation de ces opérateurs de redirection provoquera l'affichage d'un message d'erreur décrivant le problème et la sortie avec un statut de sortie non nul.
*
Le mot réservé ! ne peut pas être utilisé en tête du pipeline pour modifier le statut de sortie. (Voir la description de l'opérande chaîne-commande ci-dessous.)
*
La substitution d'alias ne sera pas effectuée.

Un nom de fichier peut être spécifié comme pour uucp ; il peut s'agir d'un chemin absolu, d'un chemin précédé de ~nom (qui est remplacé par le répertoire de connexion correspondant), d'un chemin spécifié comme ~/dest (dest est précédé par le répertoire public appelé PUBDIR ; l'emplacement réel de PUBDIR est défini par l'implémentation), ou d'un nom de fichier simple (qui est précédé par uux du répertoire courant). Voir uucp pour les détails.

L'exécution des commandes sur des systèmes distants aura lieu dans un répertoire d'exécution connu du système uucp. Tous les fichiers requis pour l'exécution seront placés dans ce répertoire, sauf s'ils résident déjà sur cette machine. Par conséquent, l'application doit s'assurer que les noms de fichiers non locaux (sans référence de chemin ou de machine) sont uniques dans la requête uux.

L'utilitaire uux tentera de transférer tous les fichiers vers le système d'exécution. Pour les fichiers qui sont des fichiers de sortie, l'application doit s'assurer que le nom de fichier est échappé à l'aide de parenthèses.

Le système distant notifiera l'utilisateur par courrier si la commande demandée sur le système distant était interdite ou si les fichiers n'étaient pas accessibles. Cette notification peut être désactivée par l'option -n.

Les implémentations typiques de cet utilitaire nécessitent une ligne de communication configurée pour utiliser le volume des Définitions de Base de POSIX.1‐2017, Chapitre 11, Interface de Terminal Générale, mais d'autres moyens de communication peuvent être utilisés. Sur les systèmes où il n'y a pas de moyens de communication disponibles (temporairement ou de manière permanente), cet utilitaire écrira un message d'erreur décrivant le problème et se terminera avec un statut de sortie non nul.

uux ne peut pas garantir la prise en charge de tous les encodages de caractères dans toutes les circonstances. Par exemple, les données de transmission peuvent être limitées à 7 bits par le réseau sous-jacent, les fichiers nommés avec 8 bits et les noms de fichiers ne sont pas nécessairement portables vers des systèmes non internationalisés, etc. Dans ces circonstances, il est recommandé de n'utiliser que les caractères définis dans la version internationale de référence de la norme ISO/IEC 646:1991 (équivalente à ASCII) dans la plage de 7 bits et de n'utiliser que les caractères définis dans l'ensemble de caractères de nom de fichier portable pour nommer les fichiers.

OPTIONS

L'utilitaire uux doit être conforme aux Directives de syntaxe des utilitaires du volume des Définitions de Base de POSIX.1‐2017, Section 12.2.

Les options suivantes doivent être prises en charge :

-j
Écrit la chaîne d'identification de tâche sur la sortie standard. Cette identification de tâche peut être utilisée par uustat pour obtenir le statut ou terminer une tâche.
-n
Ne pas notifier l'utilisateur si la commande échoue.
-p
Faire de l'entrée standard de uux l'entrée standard de la chaîne-commande.

OPÉRANDES

L'opérande suivant doit être pris en charge :

chaîne-commande

Une chaîne composée d'un ou plusieurs arguments similaires aux arguments de commande normaux, sauf que la commande et tous les noms de fichiers peuvent être préfixés par nom-système!. Un nom-système vide sera interprété comme le système local.

STDIN

L'entrée standard ne sera pas utilisée à moins que l'option '-' ou -p ne soit spécifiée ; dans ces cas, l'entrée standard sera la même que l'entrée standard de la chaîne-commande.

FICHIERS D'ENTRÉE

Les fichiers d'entrée seront sélectionnés conformément au contenu de chaîne-commande.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de uux :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de Base de POSIX.1‐2017, Section 8.2, Variables d'Internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de valeur non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard ne sera pas utilisée à moins que l'option -j ne soit spécifiée ; dans ce cas, la chaîne d'identification de tâche sera écrite sur la sortie standard dans le format suivant :

"%s\n", <jobid>

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Les fichiers de sortie seront créés ou écrits, ou les deux, conformément au contenu de chaîne-commande.

Si -n n'est pas utilisé, les fichiers de courrier seront modifiés suite à des échecs de commande ou d'accès aux fichiers sur le système distant.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0

UTILISATION PAR L'APPLICATION

Cet utilitaire fait partie de l'option UUCP Utilities et n'a pas besoin d'être pris en charge par toutes les implémentations.

Notez que, pour des raisons de sécurité, de nombreuses installations limitent la liste des commandes exécutables pour une requête entrante de uux. De nombreux sites ne permettent que la réception de courrier via uux.

Tous les caractères spéciaux pour l'interpréteur de commandes doivent être mis entre guillemets, soit en mettant entre guillemets la chaîne-de-commande entière, soit en mettant les caractères spéciaux entre guillemets en tant qu'arguments individuels.

Comme indiqué dans uucp, les caractères de la notation de mise en correspondance de motifs du shell apparaissant dans les noms de chemin sont développés sur le système local approprié. Ceci est fait sous le contrôle des paramètres locaux de LC_COLLATE et LC_CTYPE. Ainsi, il convient d'être prudent lors de l'utilisation de motifs de noms de fichiers entre crochets, car les règles de collation et de typage peuvent varier d'un système à l'autre. Soyez également conscient que certains types d'expressions (c'est-à-dire les classes d'équivalence, les classes de caractères et les symboles de collation) n'ont pas besoin d'être pris en charge sur les systèmes non internationalisés.

EXEMPLES

1.
La commande suivante récupère file1 du système a et file2 du système b, exécute diff sur le système local, et place les résultats dans file.diff dans le répertoire local PUBDIR. (PUBDIR est le répertoire public uucp sur le système local.)
uux "!diff a!/usr/file1 b!/a4/file2 >!~/file.diff"
2.
La commande suivante échoue car uux place tous les fichiers copiés sur un système dans le même répertoire de travail. Bien que les fichiers xyz proviennent de deux systèmes différents, leurs noms de fichiers sont identiques et entrent en conflit.
uux "!diff a!/usr1/xyz b!/usr2/xyz >!~/xyz.diff"
3.
La commande suivante réussit (en supposant que diff est autorisé sur le système a) car le fichier local au système a n'est pas copié dans le répertoire de travail, et n'entre donc pas en conflit avec le fichier du système c.
uux "a!diff a!/usr/xyz c!/usr/xyz >!~/xyz.diff"
