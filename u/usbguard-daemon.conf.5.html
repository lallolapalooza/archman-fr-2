NOM

usbguard-daemon.conf - Fichier de configuration du démon USBGuard

DESCRIPTION

Le fichier usbguard-daemon.conf est chargé par le démon USBGuard après l'analyse de ses options en ligne de commande. Il est utilisé pour configurer les paramètres d'exécution du démon. Le chemin de recherche par défaut est /etc/usbguard/usbguard-daemon.conf. Il peut être remplacé en utilisant l'option de commande -c, voir usbguard-daemon(8) pour plus de détails.

OPTIONS

RuleFile=chemin

Le démon USBGuard utilisera ce fichier pour charger l'ensemble de règles de stratégie à partir de celui-ci et pour écrire les nouvelles règles reçues via l'interface IPC. Par défaut : %sysconfdir%/usbguard/rules.conf

RuleFolder=chemin

Le démon USBGuard utilisera ce dossier pour charger l'ensemble de règles de stratégie à partir de celui-ci et pour écrire les nouvelles règles reçues via l'interface IPC. Habituellement, nous définissons l'option sur /etc/usbguard/rules.d/. Le démon USBGuard est censé se comporter comme n'importe quel démon Linux standard, par conséquent, il charge les fichiers de règles dans l'ordre alphanumérique. Les noms de fichiers à l'intérieur du répertoire RuleFolder doivent commencer par un préfixe de deux chiffres indiquant la position dans laquelle les règles sont analysées par le démon. L'utilisation simultanée de RuleFile et RuleFolder est autorisée. Cependant, la modification de la stratégie permanente n'est pas possible si l'une des conditions suivantes est remplie :
•Ni RuleFile ni RuleFolder ne sont spécifiés.
•RuleFile n'est pas spécifié, RuleFolder l'est mais il ne contient aucun fichier où nous pourrions enregistrer les règles permanentes.

ImplicitPolicyTarget=cible

Comment traiter les périphériques USB qui ne correspondent à aucune règle de la stratégie. La cible doit être l'une des valeurs suivantes : allow, block ou reject (supprimer logiquement le nœud du périphérique du système). Par défaut : block

PresentDevicePolicy=stratégie

Comment traiter les périphériques USB déjà connectés lorsque le démon démarre. La stratégie doit être l'une des valeurs suivantes : allow, block, reject, keep (conserver quel que soit l'état actuel du périphérique) ou apply-policy (évaluer l'ensemble de règles pour chaque périphérique présent). Par défaut : apply-policy

PresentControllerPolicy=stratégie

Comment traiter les périphériques contrôleur USB déjà connectés lorsque le démon démarre. L'une des valeurs suivantes : allow, block, reject, keep ou apply-policy. Par défaut : keep

InsertedDevicePolicy=stratégie

Comment traiter les périphériques USB déjà connectés après le démarrage du démon. L'une des valeurs suivantes : block, reject, apply-policy. Par défaut : apply-policy

AuthorizedDefault=authorizedDefault

Le démon USBGuard modifie certains attributs d'autorisation par défaut des périphériques contrôleurs. Ce réglage vous permet de définir la valeur de l'autorisation par défaut. Authorized default doit être l'une des valeurs suivantes : keep (ne pas modifier l'état d'autorisation), none (chaque nouveau périphérique commence désautorisé), all (chaque nouveau périphérique commence autorisé) ou internal (les périphériques internes commencent autorisés, les externes ne le sont pas). Par défaut : none

RestoreControllerDeviceState=booléen

Le démon USBGuard modifie certains attributs des périphériques contrôleurs, comme l'état d'autorisation par défaut des nouvelles instances de périphériques enfants. En utilisant ce réglage, vous pouvez contrôler si le démon tentera de restaurer les valeurs des attributs à l'état d'avant la modification lors de l'arrêt. Par défaut : false

DeviceManagerBackend=backend

Quelle implémentation de backend de gestionnaire de périphériques utiliser. Le backend doit être l'une des valeurs suivantes : uevent (par défaut) ou umockdev (utile pour les tests). Le backend UEvent est une implémentation basée sur netlink qui utilise sysfs pour scanner les périphériques présents et un socket uevent pour recevoir les événements liés aux périphériques USB. Le gestionnaire de périphériques basé sur UMockDev est capable de simuler des périphériques basés sur des fichiers d'enregistrement umockdev. Par défaut : uevent

IPCAllowedUsers=nomutilisateur [nomutilisateur ...]

Une liste d'utilisateurs séparés par des espaces à partir desquels le démon acceptera les connexions IPC. Par défaut : root

IPCAllowedGroups=nomgroupe [nomgroupe ...]

Une liste de noms de groupes séparés par des espaces à partir desquels le démon acceptera les connexions IPC.

IPCAccessControlFiles=chemin

Les fichiers à cet emplacement seront interprétés par le démon comme des fichiers de définition de contrôle d'accès IPC. Voir la section CONTRÔLE D'ACCÈS IPC pour plus de détails.

DeviceRulesWithPort=booléen

Générer des règles spécifiques aux périphériques incluant l'attribut "via-port". Par défaut : false

AuditBackend=backend

Backend d'enregistrement des événements d'audit USBGuard. La valeur backend doit être l'une des suivantes : FileAudit ou LinuxAudit. Par défaut : FileAudit

AuditFilePath=cheminfichier

Chemin du fichier d'enregistrement des événements d'audit USBGuard. Requis si AuditBackend est défini sur FileAudit. Par défaut : %localstatedir%/log/usbguard/usbguard-audit.log

HidePII=booléen

Masque les informations personnellement identifiables, telles que les numéros de série des périphériques et les hachages des descripteurs (qui incluent le numéro de série), des entrées d'audit. Par défaut : false

CONSIDÉRATIONS DE SÉCURITÉ

IPC

Le démon fournit l'interface IPC publique d'USBGuard. Selon les paramètres par défaut de votre distribution, l'accès à cette interface est limité à un groupe spécifique ou à un utilisateur spécifique uniquement. Veuillez définir les options IPCAllowedUsers, IPCAllowedGroups ou IPCAccessControlFiles pour limiter l'accès à l'interface IPC. Ne laissez pas la liste de contrôle d'accès (ACL) non configurée, car cela exposera l'interface IPC à tous les utilisateurs locaux et leur permettra de manipuler l'état d'autorisation des périphériques USB et de modifier la stratégie USBGuard.

L'option de configuration RestoreControllerDeviceState

Si définie sur true, la stratégie d'autorisation USB pourrait être contournée en effectuant une sorte d'attaque sur le démon (via une exploitation locale ou via un périphérique USB) pour le faire s'arrêter et revenir à l'état par défaut du système d'exploitation (connu pour être permissif).

CONTRÔLE D'ACCÈS IPC

L'accès à l'interface IPC d'USBGuard peut être limité par utilisateur ou par groupe. De plus, en utilisant les fichiers de contrôle d'accès IPC, il est possible de limiter l'accès jusqu'au niveau des Sections et des Privilèges, comme expliqué ci-dessous.

Recommandé : IPCAccessControlFiles

Lorsque vous définissez l'option IPCAccessControlFiles, le démon recherche les fichiers de contrôle d'accès IPC dans le répertoire spécifié par la valeur définie. Chaque fichier dans le répertoire est traité comme suit :

1.Le nom de base du fichier est interprété comme un nom d'utilisateur, un UID, un nom de groupe ou un GID. Si le nom commence par : (deux-points), il est supposé que le reste du nom représente un identifiant de groupe (nom de groupe ou GID dans le cas d'une chaîne uniquement numérique). Sinon, il est interprété comme un identifiant utilisateur (nom d'utilisateur ou UID dans le cas d'une chaîne uniquement numérique).
2.Le contenu du fichier est analysé sous forme de lignes formatées Section=[privilege1][,privilege2] ... qui spécifient les privilèges de la section. Si une section est omise, il est supposé qu'aucun privilège n'est donné pour cette section.

Sections et privilèges disponibles :

•Devices
•modify: Modifier l'état d'autorisation des périphériques, y compris les modifications permanentes (c'est-à-dire la modification des règles spécifiques aux périphériques dans la stratégie).
•list: Possibilité d'obtenir une liste des périphériques reconnus et de leurs attributs.
•listen: Écouter la présence des périphériques et les changements de stratégie des périphériques.
•Policy
•modify: Ajouter des règles à la stratégie ou en retirer n'importe laquelle.
•list: Possibilité de visualiser la stratégie actuellement appliquée.
•Exceptions
•listen: Recevoir des messages d'exception.
•Parameters

Voici un exemple de fichier de contrôle d'accès utilisable de manière générale et raisonnablement sûr. Il permet de modifier l'état d'autorisation des périphériques USB (Devices=modify), de lister les périphériques USB (Devices=list), d'écouter les événements liés aux périphériques USB (Devices=listen), de lister les règles de politique d'autorisation USB (Policy=list) et d'écouter les événements d'exception (Exceptions=listen) :

Devices=modify,list,listen
Policy=list
Exceptions=listen

Vous pouvez créer ou supprimer les fichiers de contrôle d'accès IPC à l'aide des commandes CLI usbguard add-user et usbguard remove-user. Voir usbguard(1) pour plus de détails. Si vous souhaitez créer les fichiers de contrôle d'accès IPC manuellement, vous devez définir les permissions des fichiers sur 0600.

Héritage : IPCAllowedUsers et IPCAllowedGroups

Exemple de configuration autorisant l'accès IPC complet aux utilisateurs root, joe et aux membres du groupe wheel :

IPCAllowedUsers=root joe
IPCAllowedGroups=wheel
