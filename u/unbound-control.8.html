NOM

unbound-control - Utilitaire de contrôle à distance du serveur Unbound 1.24.2.

SYNTAXE

unbound-control [-hq] [-c fichier_config] [-s serveur] commande

DESCRIPTION

unbound-control effectue l'administration à distance du serveur DNS unbound(8). Il lit le fichier de configuration, contacte le serveur Unbound via TLS, envoie la commande et affiche le résultat.

Les options disponibles sont :

-h
Affiche la version et l'aide des options de ligne de commande.
-c <fichier_config>
Le fichier de configuration à lire avec les paramètres. S'il n'est pas donné, le fichier de configuration par défaut /etc/unbound/unbound.conf est utilisé.
-s <serveur[@port]>
Adresse IPv4 ou IPv6 du serveur à contacter. Si elle n'est pas donnée, l'adresse est lue dans le fichier de configuration.
-q
Silencieux, si l'option est donnée, rien ne sera affiché en cas de succès.

COMMANDES

Il existe plusieurs commandes que le serveur comprend.

start
Démarre le serveur. Exécute simplement unbound(8). L'exécutable unbound est recherché dans le PATH défini dans l'environnement. Il est lancé avec le fichier de configuration spécifié via -c ou le fichier de configuration par défaut.
stop
Arrête le serveur. Le démon du serveur se termine.
reload
Recharge le serveur. Cela vide le cache et relit le fichier de configuration.
reload_keep_cache
Recharge le serveur mais essaie de conserver le cache des RRset et des messages si la (re)configuration le permet. Cela signifie que les tailles de cache et le nombre de threads ne doivent pas changer entre les rechargements.
fast_reload [+dpv]
Recharge le serveur, mais minimise le temps d'arrêt afin que les requêtes des utilisateurs continuent d'être desservies. Cela nécessite que le code soit compilé avec des threads. La configuration est chargée dans un thread, préparée, puis le serveur existant est brièvement interrompu et les options de configuration sont mises à jour. L'intention est que la pause n'affecte pas le service des requêtes utilisateur. Le cache est conservé. Les requêtes utilisateur en cours sont également conservées et continuent, mais avec les nouvelles options de configuration.

NOTE :

Cette commande est expérimentale pour le moment.

La quantité de mémoire temporaire nécessaire lors d'un fast_reload est le double de la quantité nécessaire à la configuration. En effet, Unbound a temporairement besoin de stocker à la fois les valeurs de configuration actuelles et les nouvelles pendant la tentative de fast_reload. Les zones chargées depuis le disque (zones d'autorité et zones RPZ) sont incluses dans ces besoins en mémoire.

Les options qui peuvent être modifiées sont : forwards, stubs, views, authority zones, RPZ zones et local zones.

Également access-control et options similaires, interface-action et options similaires, et tcp-connection-limit. Elle peut recharger certains changements de define-tag, plus d'informations ci-dessous. D'autres options incluent : insecure-lan-zones, domain-insecure, trust-anchor-file, trust-anchor, trusted-keys-file, auto-trust-anchor-file, edns-client-string, ipset, log-identity, infra-cache-numhosts, msg-cache-size, rrset-cache-size, key-cache-size, ratelimit-size, neg-cache-size, num-queries-per-thread, jostle-timeout, use-caps-for-id, unwanted-reply-threshold, tls-use-sni, outgoing-tcp-mss, ip-dscp, max-reuse-tcp-queries, tcp-reuse-timeout, tcp-auth-query-timeout, delay-close. iter-scrub-promiscuous.

Elle ne fonctionne pas avec les modifications de interface et outgoing-interface, ni avec remote control, outgoing-port-permit, outgoing-port-avoid, msg-buffer-size, aucune option *-slabs et les changements de statistics-interval.

Pour dnstap, ces options peuvent être modifiées : dnstap-log-resolver-query-messages, dnstap-log-resolver-response-messages, dnstap-log-client-query-messages, dnstap-log-client-response-messages, dnstap-log-forwarder-query-messages et dnstap-log-forwarder-response-messages.

Elle ne fonctionne pas avec ces options : dnstap-enable, dnstap-bidirectional, dnstap-socket-path, dnstap-ip, dnstap-tls, dnstap-tls-server-name, dnstap-tls-cert-bundle, dnstap-tls-client-key-file et dnstap-tls-client-cert-file.

Les options dnstap-send-identity, dnstap-send-version, dnstap-identity et dnstap-version peuvent être chargées lorsque +p n'est pas utilisé.

L'option +v rend la sortie détaillée, incluant le temps nécessaire pour effectuer le rechargement. Avec +vv, elle est plus détaillée, incluant la quantité de mémoire temporairement allouée pour effectuer le rechargement ; cette quantité de mémoire peut être importante si la configuration est volumineuse. Dans la sortie temporelle, le temps de 'reload' est le temps pendant lequel le serveur a été mis en pause.

L'option +p (nopause) empêche la mise en pause des threads pendant le rechargement ; ils continuent de fonctionner. Des verrous sont acquis, mais les éléments sont mis à jour séquentiellement. Il est donc possible que les threads voient un état incohérent avec certaines options de l'ancienne configuration et d'autres de la nouvelle, comme les paramètres TTL du cache de l'ancienne configuration et les forwards de la nouvelle. Les stubs et les forwards sont mis à jour simultanément, de sorte qu'ils sont vus de manière cohérente, soit avec les anciennes, soit avec les nouvelles valeurs ensemble. L'option fait en sorte que le temps de rechargement soit, par exemple, de 3 microsecondes au lieu de 0.3 millisecondes pendant lesquels les threads de travail sont interrompus. Ainsi, l'interruption est beaucoup plus courte, au détriment d'une certaine incohérence. Après le rechargement lui-même, chaque thread de travail est brièvement contacté pour qu'il libère ses ressources, ce qui allonge légèrement le temps de suppression et prend du temps au thread de travail servant le contrôle à distance.

Avec l'option nopause (+p), le rechargement ne fonctionne pas pour recharger certaines options, que le rechargement rapide fonctionne sans l'option nopause : val-bogus-ttl, val-override-date, val-sig-skew-min, val-sig-skew-max, val-max-restart, val-nsec3-keysize-iterations, target-fetch-policy, outbound-msg-retry, max-sent-count, max-query-restarts, do-not-query-address, do-not-query-localhost, private-address, private-domain, caps-exempt, nat64-prefix, do-nat64, infra-host-ttl, infra-keep-probing, ratelimit, ip-ratelimit, ip-ratelimit-cookie, wait-limit-netblock, wait-limit-cookie-netblock, ratelimit-below-domain, ratelimit-for-domain.

L'option +d fait en sorte que le rechargement abandonne les requêtes sur lesquelles les threads de travail sont en train de traiter. C'est comme flush_requestlist. Sans elle, les requêtes sont conservées afin que les utilisateurs continuent de recevoir des réponses pour ces requêtes en cours de traitement. L'abandon fait en sorte que les requêtes pendant la durée du traitement ne voient que les anciennes ou que les nouvelles options de configuration.

Lorsqu'il y a des changements dans les balises de configuration, provenant de l'option define-tag, alors l'option +d est implicitement activée avec un message d'avertissement, et les requêtes sont abandonnées. Ceci afin d'empêcher les références aux anciennes informations de balise par les anciennes requêtes. Si le nombre de balises est augmenté dans la configuration nouvellement chargée, en ajoutant des balises à la fin, alors l'option +d implicite n'est pas nécessaire.

Pour les adresses IP de réponse, c'est-à-dire les actions associées aux adresses IP, et peut-être recoupées avec des informations de balise et d'action de contrôle d'accès, ces paramètres sont stockés avec une requête lorsqu'elle arrive en fonction de son adresse IP source. L'ancien in

verbosity nombre
Change la valeur de verbosité pour la journalisation. Identiques valeurs que la clé verbosity: dans unbound.conf(5). Ce nouveau réglage dure jusqu'à ce que le serveur soit relancé (recharge les valeurs du fichier de configuration), ou jusqu'à la prochaine commande de contrôle de verbosité.
log_reopen
Rouvre le fichier journal, le ferme et le rouvre. Utile pour la rotation des journaux afin que le démon libère le fichier auquel il écrit. Si vous utilisez syslog, il tentera de fermer et rouvrir syslog (ce qui peut ne pas fonctionner s'il est chrooté).
stats
Affiche les statistiques. Réinitialise les compteurs internes à zéro, ceci peut être contrôlé via l'instruction de configuration statistics-cumulative:. Les statistiques sont affichées avec une ligne [nom]: [valeur] par ligne.
stats_noreset
Examine les statistiques. Les affiche comme le fait la commande stats, mais ne réinitialise pas les compteurs internes à zéro.
status
Affiche l'état du serveur. Code de sortie 3 s'il n'est pas en cours d'exécution (la connexion au port est refusée), 1 en cas d'erreur, 0 s'il est en cours d'exécution.
local_zone nom type
Ajoute une nouvelle zone locale avec le nom et le type donnés. Similaire à l'instruction de configuration local-zone. Si la zone existe déjà, son type est modifié pour correspondre à l'argument donné.
local_zone_remove nom
Supprime la zone locale du nom donné. Supprime toutes les données locales qu'elle contient. Si la zone n'existe pas, la commande réussit.
local_data RR données...
Ajoute de nouvelles données locales, l'enregistrement de ressources donné. Similaire à la clé local-data:, sauf que si aucune zone couvrante n'existe. Dans ce cas, cette commande de contrôle à distance crée une zone transparente portant le même nom que cet enregistrement.
local_data_remove nom
Supprime tous les enregistrements de ressources du nom local. Si le nom n'a déjà aucun élément, rien ne se passe. Souvent, cela résulte en un NXDOMAIN pour le nom (dans une zone statique), mais si le nom est devenu un non-terminal vide (il y a toujours des données dans les noms de domaine en dessous du nom supprimé), des réponses NOERROR nodata sont le résultat pour ce nom.
local_zones
Ajoute des zones locales lues depuis stdin de unbound-control. Les entrées sont lues ligne par ligne, avec nom espace type sur une ligne. Pour des ajouts en masse.
local_zones_remove
Supprime des zones locales lues depuis stdin de unbound-control. L'entrée est un nom par ligne. Pour des suppressions en masse.
local_datas
Ajoute des enregistrements de ressources de données locales lus depuis stdin de unbound-control. L'entrée est un enregistrement de ressource par ligne. Pour des ajouts en masse.
local_datas_remove
Supprime des enregistrements de ressources de données locales lus depuis stdin de unbound-control. L'entrée est un nom par ligne. Pour des suppressions en masse.
dump_cache
Le contenu du cache est imprimé dans un format texte sur la sortie standard. Vous pouvez le rediriger vers un fichier pour stocker le cache. Non supporté dans les Unbounds distants en opération multi-processus.
load_cache
Le contenu du cache est chargé depuis stdin. Utilise le même format que dump_cache. Charger le cache avec des données anciennes ou incorrectes peut entraîner la fourniture de données anciennes ou incorrectes aux clients. Le chargement de données dans le cache de cette manière est supporté pour faciliter le débogage. Non supporté dans les Unbounds distants en opération multi-processus.
cache_lookup [+t] noms
Affiche sur la sortie standard les RRsets et messages présents dans le cache. Pour chaque nom listé, le contenu à ou sous le nom est affiché. Plusieurs noms séparés par des espaces peuvent être donnés, chacun est affiché. Lorsque subnetcache est activé, les entrées correspondantes du cache de sous-réseaux sont également affichées.

L'option +t permet les noms de domaine de premier niveau (TLD) et racines. Avec elle, des noms comme 'com' et '.' peuvent être utilisés, mais cela demande beaucoup d'efforts pour chercher dans le cache.

lookup nom
Affiche sur la sortie standard les serveurs de noms qui seraient utilisés pour rechercher le nom spécifié.
flush [+c] nom
Supprime le nom du cache. Supprime les types A, AAAA, NS, SOA, CNAME, DNAME, MX, PTR, SRV, NAPTR, SVCB et HTTPS. Car c'est rapide à faire. D'autres types d'enregistrements peuvent être supprimés en utilisant flush_type ou flush_zone.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_type [+c] nom type
Supprime le nom et le type d'information du cache.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_zone [+c] nom
Supprime toutes les informations présentes à ou sous le nom spécifié du cache. Les RRsets et les entrées de clés sont supprimés afin que de nouvelles recherches soient effectuées. Cela nécessite de parcourir et d'inspecter l'intégralité du cache, et constitue une opération lente. Les entrées sont marquées comme expirées dans l'implémentation de cette commande (ainsi, avec serve-expired activé, il servira cette information mais planifiera un pré-fetch pour de nouvelles informations).

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_bogus [+c]
Supprime toutes les données invalides (bogus) du cache.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_negative [+c]
Supprime toutes les données négatives du cache. Il s'agit des réponses nxdomain, nodata et servfail. Supprime également les entrées de clés incorrectes (qui pourraient résulter d'échecs de recherche) du cache de clés dnssec, et les échecs de recherche de dernier recours des itérateurs du cache rrset.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_stats
Réinitialise les statistiques à zéro.
flush_requestlist
Supprime les requêtes en cours de traitement. Arrête le traitement des requêtes sur lesquelles le serveur travaille actuellement. Le cache n'est pas affecté. Aucune réponse n'est envoyée pour ces requêtes, ce qui incite probablement les utilisateurs à réessayer plus tard. Utile pour que le serveur recommence à traiter les requêtes avec de nouveaux paramètres, tels qu'un niveau de verbosité plus élevé.
dump_requestlist
Affiche ce qui est en cours de traitement. Affiche toutes les requêtes sur lesquelles le serveur travaille actuellement. Affiche le temps d'attente des utilisateurs. Pour les requêtes internes, aucun temps n'est affiché. Ensuite, affiche l'état des modules. Ceci affiche les requêtes du premier thread, et non les requêtes servies par d'autres threads.
flush_infra all|IP
Si 'all', l'intégralité du cache d'infrastructure est vidé. Si une adresse IP spécifique est fournie, l'entrée correspondant à cette adresse est supprimée du cache. Il contient des données EDNS, ping et lameness.
dump_infra
Affiche le contenu du cache d'infrastructure.
set_option opt: val
Définit l'option à la valeur donnée sans rechargement. Le cache n'est donc pas vidé. L'option doit se terminer par un : et un espace doit séparer l'option et la valeur. Certaines valeurs peuvent ne pas avoir d'effet lorsqu'elles sont définies de cette manière, les nouvelles valeurs ne sont pas écrites dans le fichier de configuration, et toutes les options ne sont pas prises en charge. Ceci est différent de l'appel set_option dans libunbound, où toutes les valeurs fonctionnent car Unbound n'a pas été initialisé.

Les valeurs qui fonctionnent sont : statistics-interval, statistics-cumulative, do-not-query-localhost, harden-short-bufsize, harden-large-queries, harden-glue, harden-dnssec-stripped, harden-below-nxdomain, harden-referral-path, prefetch, prefetch-key, log-queries, hide-identity, hide-version, identity, version, val-log-level, val-log-squelch, ignore-cd-flag, add-holddown, del-holddown, keep-missing, tcp-upstream, ssl-upstream, max-udp-size, ratelimit, ip-ratelimit, cache-max-ttl, cache-min-ttl

, cache-max-negative-ttl.

get_option opt
Obtenir la valeur de l'option. Donnez le nom de l'option sans le ':' final. La valeur est imprimée. Si la valeur est "", rien n'est imprimé et la connexion est fermée. En cas d'erreur, 'error ...' est imprimé (il donne une erreur de syntaxe pour une option inconnue). Pour certaines options, une liste de valeurs, une par ligne, est imprimée. Les options sont affichées à partir du fichier de configuration tel que modifié avec set_option. Pour certaines options, un remplacement peut avoir été effectué et ne pas apparaître avec cette commande, ni les résultats de commandes comme verbosity et forward control. Toutes les options ne fonctionnent pas, voir list_stubs, list_forwards, list_local_zones et list_local_data pour celles qui le font.
list_stubs
Lister les zones stub en cours d'utilisation. Elles sont imprimées une par une sur la sortie. Cela inclut les racines d'indices en cours d'utilisation.
list_forwards
Lister les zones de transfert en cours d'utilisation. Elles sont imprimées zone par zone sur la sortie.
list_insecure
Lister les zones avec domain-insecure.
list_local_zones
Lister les zones locales en cours d'utilisation. Elles sont imprimées une par ligne avec le type de zone.
list_local_data
Lister les enregistrements de données locaux en cours d'utilisation. Les enregistrements de ressources sont imprimés.
insecure_add zone
Ajouter un domain-insecure pour la zone donnée, comme la déclaration dans unbound.conf. S'ajoute au Unbound en cours sans affecter le contenu du cache (qui peut encore être invalide, utilisez flush_zone pour le supprimer), n'affecte pas le fichier de configuration.
insecure_remove zone
Supprime domain-insecure pour la zone donnée.
forward_add [+it] zone addr ...
Ajouter une nouvelle zone de transfert à Unbound en cours d'exécution. Avec l'option +i, ajoute également un domain-insecure pour la zone (afin qu'elle puisse résoudre de manière non sécurisée si vous avez une ancre de confiance DNSSEC racine configurée pour d'autres noms). L'addr peut être une IP4, une IP6 ou des noms de serveurs de noms, comme la configuration forward-zone dans unbound.conf. L'option +t la configure pour utiliser TLS en amont, comme forward-tls-upstream: yes.
forward_remove [+i] zone
Supprimer une zone de transfert d'Unbound en cours d'exécution. Le +i supprime également un domain-insecure pour la zone.
stub_add [+ipt] zone addr ...
Ajouter une nouvelle zone stub à Unbound en cours d'exécution. Avec l'option +i, ajoute également un domain-insecure pour la zone. Avec +p, la zone stub est configurée sur prime, sans cela elle est configurée sur notprime. L'addr peut être une IP4, une IP6 ou des noms de serveurs de noms, comme la configuration stub-zone: dans unbound.conf. L'option +t la configure pour utiliser TLS en amont, comme stub-tls-upstream: yes.
stub_remove [+i] zone
Supprimer une zone stub d'Unbound en cours d'exécution. Le +i supprime également un domain-insecure pour la zone.
forward [off | addr ... ]
Configurer le mode de transfert. Détermine si le serveur doit interroger d'autres serveurs de noms en amont, doit aller lui-même aux serveurs de noms racines d'Internet, ou afficher la configuration actuelle. Vous pouvez passer les serveurs de noms après une mise à jour DHCP.

Sans arguments, la liste actuelle des adresses utilisées pour transférer toutes les requêtes est imprimée. Au démarrage, cela provient de la configuration forward-zone ".". Ensuite, cela affiche l'état. Cela imprime off lorsqu'aucun transfert n'est utilisé.

Si off est passé, le transfert est désactivé et les serveurs de noms racines sont utilisés. Cela peut être utilisé pour éviter les serveurs de noms défectueux ou ne prenant pas en charge DNSSEC retournés par DHCP. Mais cela peut ne pas fonctionner dans les hôtels ou les points d'accès.

Si une ou plusieurs adresses IPv4 ou IPv6 sont données, elles sont ensuite utilisées pour transférer les requêtes. Les adresses doivent être séparées par des espaces. Avec '@port', le numéro de port peut être défini explicitement (le port par défaut est 53 (DNS)).

Par défaut, les informations de transfert du fichier de configuration pour la racine "." sont utilisées. Le fichier de configuration n'est pas modifié, donc après un rechargement, ces modifications disparaissent. Les autres zones de transfert du fichier de configuration ne sont pas affectées par cette commande.

ratelimit_list [+a]
Lister les domaines qui sont limités en débit. Imprimés un par ligne avec le qps estimé actuel et la limite de qps de la configuration. Avec +a, il imprime tous les domaines, pas seulement les domaines limités en débit, avec leur qps estimé. Les domaines limités en débit renvoient une erreur pour les requêtes non mises en cache (nouvelles), mais les requêtes mises en cache fonctionnent normalement.
ip_ratelimit_list [+a]
Lister les adresses IP qui sont limitées en débit. Imprimées une par ligne avec le qps estimé actuel et la limite de qps de la configuration. Avec +a, il imprime toutes les IP, pas seulement les IP limitées en débit, avec leur qps estimé. Les IP limitées en débit sont rejetées avant la vérification du cache.
list_auth_zones
Lister les zones d'autorisation configurées. Imprimées une par ligne avec un statut indiquant si la zone a expiré et le numéro de série actuel. Les zones RPZ configurées sont incluses.
auth_zone_reload zone
Recharger la zone d'autorisation (ou zone RPZ) à partir du fichier de zone. Le fichier de zone est lu en écrasant le contenu actuel de la zone en mémoire. Cela modifie le contenu de la zone d'autorisation elle-même, pas le contenu du cache. Un tel contenu de cache existe si vous avez configuré Unbound pour valider avec for-upstream: yes et cela peut être effacé avec flush_zone zone.
auth_zone_transfer zone
Transférer la zone d'autorisation (ou zone RPZ) du maître. La séquence de sondage de la zone d'autorisation est démarrée, où les maîtres sont sondés pour voir s'ils ont une zone mise à jour (avec la vérification du numéro de série SOA). Puis la zone est transférée pour une version de zone plus récente.
rpz_enable zone
Activer la zone RPZ si elle avait été précédemment désactivée.
rpz_disable zone
Désactiver la zone RPZ.
view_list_local_zones view
list_local_zones pour la vue donnée.
view_local_zone view name type
local_zone pour la vue donnée.
view_local_zone_remove view name
local_zone_remove pour la vue donnée.
view_list_local_data view
list_local_data pour la vue donnée.
view_local_data view RR data...
local_data pour la vue donnée.
view_local_data_remove view name
local_data_remove pour la vue donnée.
view_local_datas_remove view
Supprimer une liste de local_data pour la vue donnée depuis stdin. Comme local_datas_remove.
view_local_datas view
Ajouter une liste de local_data pour la vue donnée depuis stdin. Comme local_datas.
add_cookie_secret secret
Ajouter ou remplacer un secret de cookie de manière persistante. secret doit être une chaîne hexadécimale de 128 bits.

Les secrets de cookie peuvent être soit actifs, soit en staging. Les secrets de cookie actifs sont utilisés pour créer des cookies DNS, mais la vérification d'un cookie DNS réussit avec l'un des secrets de cookie actifs ou en staging. L'état des secrets de cookie actuels peut être affiché avec la commande print_cookie_secrets.

Lorsqu'aucun secret de cookie n'est encore configuré, le secret est ajouté comme actif. S'il existe déjà un secret de cookie actif, le secret est ajouté comme en staging ou remplace un secret en staging existant.

STATISTIQUES EXTENDUES

mem.cache.rrset
Mémoire en octets utilisée par le cache RRset.
mem.cache.message
Mémoire en octets utilisée par le cache de messages.
mem.cache.dnscrypt_shared_secret
Mémoire en octets utilisée par le cache de secrets partagés dnscrypt.
mem.cache.dnscrypt_nonce
Mémoire en octets utilisée par le cache de nonces dnscrypt.
mem.mod.iterator
Mémoire en octets utilisée par le module itérateur.
mem.mod.validator
Mémoire en octets utilisée par le module validateur. Comprend le cache de clés et le cache négatif.
mem.streamwait
Mémoire en octets utilisée par les tampons d'attente de flux TCP et TLS. Ce sont les réponses en attente d'être renvoyées aux clients.
mem.http.query_buffer
Mémoire en octets utilisée par les tampons de requête HTTP/2. Contenant des requêtes DNS (partielles) en attente d'achèvement du flux de requête.
mem.http.response_buffer
Mémoire en octets utilisée par les tampons de réponse HTTP/2. Contenant des réponses DNS en attente d'être renvoyées aux clients.
mem.quic
Mémoire en octets utilisée par QUIC. Contenant des informations de connexion, des informations de flux, des requêtes lues et des réponses renvoyées aux clients.
histogram.<sec>.<usec>.to.<sec>.<usec>
Affiche un histogramme, sommé sur tous les threads. Chaque élément compte les requêtes récursives dont le temps de réponse se situe entre la limite inférieure et la limite supérieure. Les temps supérieurs ou égaux à la limite inférieure, et inférieurs à la limite supérieure. Il y a 40 intervalles, avec des tailles d'intervalles doublées.
num.query.type.A
Le nombre total de requêtes sur tous les threads avec le type de requête A. Imprimé pour les autres types de requêtes également, mais uniquement pour les types pour lesquels des requêtes ont été reçues, donc les entrées =0 sont omises par souci de brièveté.
num.query.type.other
Nombre de requêtes avec les types de requêtes 256-65535.
num.query.class.IN
Le nombre total de requêtes sur tous les threads avec la classe de requête IN (internet). Également imprimé pour les autres classes (telles que CH (CHAOS) parfois utilisées pour le débogage), ou NONE, ANY, utilisées pour les mises à jour dynamiques. `num.query.class.other` est imprimé pour les classes 256-65535.
num.query.opcode.QUERY
Le nombre total de requêtes sur tous les threads avec l'opcode de requête QUERY. Également imprimé pour les autres opcodes, UPDATE, ...
num.query.tcp
Nombre de requêtes qui ont été effectuées en utilisant TCP vers le serveur Unbound.
num.query.tcpout
Nombre de requêtes que le serveur Unbound a effectuées en utilisant TCP sortant vers d'autres serveurs.
num.query.udpout
Nombre de requêtes que le serveur Unbound a effectuées en UDP sortant vers d'autres serveurs.
num.query.tls
Nombre de requêtes effectuées en TLS vers le serveur Unbound. Celles-ci sont également comptées dans num.query.tcp, car TLS utilise TCP.
num.query.tls.resume
Nombre de reprises de session TLS, ce sont des requêtes sur TLS vers le serveur Unbound où le client a négocié une clé de reprise de session TLS.
num.query.https
Nombre de requêtes effectuées en HTTPS vers le serveur Unbound. Celles-ci sont également comptées dans num.query.tcp et num.query.tls, car HTTPS utilise TLS et TCP.
num.query.quic
Nombre de requêtes effectuées en QUIC vers le serveur Unbound. Celles-ci sont également comptées dans num.query.tls, car TLS est utilisé pour ces requêtes.
num.query.ipv6
Nombre de requêtes effectuées en IPv6 vers le serveur Unbound.
num.query.flags.RD
Le nombre de requêtes qui avaient le drapeau RD défini dans l'en-tête. Également imprimé pour les drapeaux QR, AA, TC, RA, Z, AD, CD. Notez que les requêtes avec les drapeaux QR, AA ou TC peuvent avoir été rejetées à cause de cela.
num.query.edns.present
nombre de requêtes qui avaient un enregistrement OPT EDNS présent.
num.query.edns.DO
nombre de requêtes qui avaient un enregistrement OPT EDNS avec le bit DO (DNSSEC OK) défini. Ces requêtes sont également incluses dans le nombre num.query.edns.present.
num.query.ratelimited
Le nombre de requêtes qui sont refusées à l'envoi vers les serveurs de noms en raison de la limitation du débit.
num.query.dnscrypt.shared_secret.cachemiss
Le nombre de requêtes dnscrypt qui n'ont pas trouvé de secret partagé dans le cache. Ceci peut être utilisé pour calculer le taux de succès du secret partagé.
num.query.dnscrypt.replay
Le nombre de requêtes dnscrypt qui ont trouvé un nonce dans le cache de nonces et sont donc considérées comme une relecture de requête.
num.answer.rcode.NXDOMAIN
Le nombre de réponses aux requêtes, provenant du cache ou de la récursion, qui avaient le code de retour NXDOMAIN. Également imprimé pour les autres codes de retour.
num.answer.rcode.nodata
Le nombre de réponses aux requêtes qui avaient le pseudo-code de retour nodata. Cela signifie que le code de retour réel était NOERROR, mais qu'en plus, aucune donnée n'était transportée dans la réponse (ce qui en fait une réponse dite NOERROR/NODATA). Ces requêtes sont également incluses dans le nombre num.answer.rcode.NOERROR. Courant pour les recherches AAAA lorsqu'un enregistrement A existe, et aucun AAAA.
num.answer.secure
Nombre de réponses qui étaient sécurisées. La réponse a été correctement validée. Le bit AD a peut-être été défini dans certaines de ces réponses, où le client a signalé (avec le bit DO ou AD dans la requête) qu'il était prêt à accepter le bit AD dans la réponse.
num.answer.bogus
Nombre de réponses qui étaient invalides. Ces réponses ont entraîné un SERVFAIL pour le client car la réponse n'a pas pu être validée.
num.rrset.bogus
Le nombre d'ensembles d'enregistrements (rrsets) marqués comme invalides par le validateur. Augmenté pour chaque inspection d'rrset qui échoue.
num.valops
Le nombre d'opérations de validation effectuées par le validateur. Augmenté pour chaque opération de vérification d'RRSIG, quel que soit le résultat de la validation. La combinaison RRSIG et clé doit d'abord passer certains contrôles de sanity avant qu'Unbound n'effectue la vérification, par exemple, des vérifications de longueur/protocole.
unwanted.queries
Nombre de requêtes qui ont été refusées ou ignorées car elles ne respectaient pas les paramètres de contrôle d'accès.
unwanted.replies
Réponses qui étaient indésirables ou non sollicitées. Il pourrait s'agir de trafic aléatoire, de doublons retardés, de réponses très tardives, ou de tentatives d'usurpation. Un faible niveau de réponses tardives et de doublons retardés est à prévoir avec le protocole UDP. Des valeurs très élevées pourraient indiquer une menace (usurpation).
msg.cache.count
Le nombre d'éléments (réponses DNS) dans le cache de messages.
rrset.cache.count
Le nombre d'ensembles d'enregistrements (RRsets) dans le cache d'RRsets. Cela inclut les RRsets utilisés par les messages dans le cache de messages, mais aussi les informations de délégation.
infra.cache.count
Le nombre d'éléments dans le cache d'infrastructure. Ce sont des adresses IP avec leurs informations de temporisation et de support de protocole.
key.cache.count
Le nombre d'éléments dans le cache de clés. Ce sont des clés DNSSEC, un élément par point de délégation, et leur statut de validation.
msg.cache.max_collisions
Le nombre maximum de collisions dans la table de hachage du cache de messages. C'est le nombre de hachages qui sont identiques lorsqu'un nouvel élément est inséré dans la table de hachage. Si la valeur est très grande, comme des centaines, quelque chose ne va pas avec les performances de la table de hachage, les valeurs de hachage sont incorrectes ou malveillantes.
rrset.cache.max_collisions
Le nombre maximum de collisions dans la table de hachage du cache d'rrsets. C'est le nombre de hachages qui sont identiques lorsqu'un nouvel élément est inséré dans la table de hachage. Si la valeur est très grande, comme des centaines, quelque chose ne va pas avec les performances de la table de hachage, les valeurs de hachage sont incorrectes ou malveillantes.
dnscrypt_shared_secret.cache.count
Le nombre d'éléments dans le cache de secrets partagés. Ce sont des secrets partagés précalculés pour une paire clé publique client/clé secrète serveur donnée. Les secrets partagés sont intensifs en CPU et ce cache permet à Unbound d'éviter de recalculer le secret partagé lorsque plusieurs requêtes dnscrypt sont envoyées par le même client.
dnscrypt_nonce.cache.count
Le nombre d'éléments dans le cache de nonces client. Ce cache est utilisé pour empêcher la relecture des requêtes dnscrypt. Le nonce client doit être unique pour chaque paire clé publique client/clé secrète serveur. Ce cache devrait pouvoir héberger QPS * fenêtre de relecture clés d'intervalle pour empêcher la relecture d'une requête pendant fenêtre de relecture secondes.
num.query.authzone.up
Le nombre de requêtes répondues à partir des données de zone d'autorité, requêtes ascendantes. Ces requêtes auraient autrement été envoyées (avec le repli activé) vers l'internet, mais sont maintenant répondues à partir de la zone d'autorité.
num.query.authzone.down
Le nombre de requêtes descendantes répondues à partir des données de zone d'autorité. Ces requêtes proviennent de clients descendants et ont reçu une réponse à partir des données de la zone d'autorité.
num.query.aggressive.NOERROR
Le nombre de requêtes répondues en utilisant des enregistrements NSEC mis en cache avec RCODE NODATA. Ces requêtes auraient autrement été envoyées à l'internet, mais sont maintenant répondues en utilisant des données mises en cache.
num.query.aggressive.NXDOMAIN
Le nombre de requêtes répondues en utilisant des enregistrements NSEC mis en cache avec RCODE NXDOMAIN. Ces requêtes auraient autrement été envoyées à l'internet, mais sont maintenant répondues en utilisant des données mises en cache.
num.query.subnet
Nombre de requêtes quigot an answer that contained EDNS client subnet data.
num.query.subnet_cache
Nombre de requêtes répondant à partir du cache de sous-réseau client EDNS. Celles-ci sont comptées comme des échecs de cache par les compteurs principaux, mais correspondent au cache spécifique au sous-réseau client après avoir été traitées par le module de sous-réseau client EDNS.
num.query.cachedb
Nombre de requêtes répondant à partir du cache externe de cachedb. Celles-ci sont comptées comme des échecs de cache par les compteurs principaux, mais correspondent au cache externe de cachedb après avoir été traitées par le module cachedb.
num.rpz.action.<rpz_action>
Nombre de requêtes répondant en utilisant une politique RPZ configurée, par type d'action RPZ. Les actions possibles sont : nxdomain, nodata, passthru, drop, tcp-only, local-data, disabled, et cname-override.
