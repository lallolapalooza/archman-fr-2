uudoc(1) Manuel des commandes générales uudoc(1)

NOM

uudoc - Affiche la sortie en fonction de la chaîne de format et des arguments qui la suivent.

SYNTAXE

uudoc [--aide] [--version] [FORMAT] [ARGUMENT]

DESCRIPTION

Affiche la sortie en fonction de la chaîne de format et des arguments qui la suivent.

OPTIONS

--aide
Affiche les informations d'aide
--version
Affiche les informations de version
[FORMAT]
[ARGUMENT]

SUPPLÉMENTAIRE

Système de gabarits de chaînes anonymes basique :

Affiche la chaîne de format au moins une fois, en la répétant tant qu'il reste des arguments. La sortie affiche les littéraux échappés dans la chaîne de format sous forme de littéraux de caractères. La sortie remplace les champs anonymes par l'argument non utilisé suivant, formaté selon le champ.

Affiche la chaîne, en remplaçant les séquences de caractères échappées par des littéraux de caractères et les séquences de substitution par les arguments passés.

Littéralement, à l'exception des séquences de caractères échappés ci-dessous, et des séquences de substitution décrites plus loin.

### SÉQUENCES D'ÉCHAPPEMENT

Les séquences d'échappement suivantes, organisées ici par ordre alphabétique, afficheront le littéral de caractère correspondant :

- \" guillemet double

- \\ antislash

- \\a alerte (BEL)

- \\b retour arrière

- \\c Fin d'entrée

- \\e échappement

- \\f saut de formulaire

- \\n nouvelle ligne

- \\r retour chariot

- \\t tabulation horizontale

- \\v tabulation verticale

- \\NNN octet avec la valeur exprimée en valeur octale NNN (1 à 3 chiffres)
les valeurs supérieures à 256 seront traitées

- \\xHH octet avec la valeur exprimée en valeur hexadécimale NN (1 à 2 chiffres)

- \\uHHHH caractère Unicode (IEC 10646) avec la valeur exprimée en valeur hexadécimale HHHH (4 chiffres)
(note : la documentation originale semble avoir une erreur ici, la seconde occurrence de \\uHHHH est probablement une erreur de frappe ou une spécification non standard, typiquement, on trouverait \\U pour les caractères de plus de 16 bits, ou simplement \\uHHHH pour les 16 bits)

- %% un seul %

### SUBSTITUTIONS

#### RÉFÉRENCE RAPIDE DES SUBSTITUTIONS

Champs

- %s : chaîne - %b : chaîne analysée pour les littéraux, le second paramètre est la longueur maximale

- %c : caractère, aucun second paramètre

- %i ou %d : entier 64 bits - %u : entier non signé 64 bits - %x ou %X : entier non signé 64 bits en hexadécimal - %o : entier non signé 64 bits en octal
le second paramètre est la largeur minimale ; la sortie inférieure à cette largeur est complétée avec des zéros de tête

- %q : l'ARGUMENT est affiché dans un format qui peut être réutilisé comme entrée du shell, en échappant les caractères non imprimables
avec la syntaxe $'' proposée par POSIX.

- %f ou %F : valeur flottante décimale - %e ou %E : valeur flottante en notation scientifique - %g ou %G : la plus courte des valeurs décimales ou scientifiques interprétées de manière spéciale.
le second paramètre est
- le nombre maximal de chiffres après la virgule pour la sortie flottante
- le nombre maximal de chiffres significatifs pour la sortie en notation scientifique

paramétrage des champs

exemples :

printf '%4.3i' 7

Il a un premier paramètre de 4 et un second paramètre de 3 et résultera en ' 007'

printf '%.1s' abcde

Il n'a pas de premier paramètre et un second paramètre de 1 et résultera en 'a'

printf '%4c' q

Il a un premier paramètre de 4 et aucun second paramètre et résultera en ' q'

Le premier paramètre d'un champ est la largeur minimale pour compléter la sortie si la sortie est inférieure à la valeur absolue de cette largeur ; elle sera complétée avec des espaces en tête, ou, si l'argument est négatif, avec des espaces en queue. la valeur par défaut est zéro.

Le second paramètre d'un champ est particulier au type du champ de sortie. les valeurs par défaut se trouvent dans l'aide complète sur les substitutions ci-dessous.

préfixes spéciaux pour les arguments numériques

- 0 : (par ex. 010) interpréter l'argument comme octal (champs de sortie entiers uniquement) - 0x : (par ex. 0xABC) interpréter l'argument comme hexadécimal (champs de sortie numériques uniquement) - \': (par ex. \'a) interpréter l'argument comme une constante caractère

#### COMMENT UTILISER LES SUBSTITUTIONS

Les substitutions sont utilisées pour passer un ou plusieurs arguments supplémentaires dans la chaîne de FORMAT, pour qu'ils soient formatés d'une manière particulière. Par exemple :

printf 'la lettre %X précède la lettre %X' 10 11

affichera

la lettre A précède la lettre B

car le champ de substitution %X signifie 'prendre un argument entier et l'écrire en nombre hexadécimal'

Passer plus d'arguments qu'il n'y en a dans la chaîne de format provoquera la répétition de la chaîne de format pour les substitutions restantes.

printf 'il fait %i F à %s \n' 22 Portland 25 Boston 27 New York

affichera

il fait 22 F à Portland il fait 25 F à Boston il fait 27 F à Boston

Si une chaîne de format est affichée mais qu'il reste moins d'arguments qu'il n'y a de champs de substitution, les champs de substitution sans argument seront par défaut des chaînes vides, ou pour les champs numériques la valeur 0

#### SUBSTITUTIONS DISPONIBLES

Ce programme, comme printf de GNU coreutils, interprète un sous-ensemble modifié du spécificateur C printf de POSIX. Une référence rapide des substitutions est ci-dessous.

#### SUBSTITUTIONS DE CHAÎNE

Tous les champs de chaîne ont un paramètre de 'largeur maximale'. %.3s signifie 'ne pas afficher plus de trois caractères de l'entrée d'origine'

- %s : chaîne

- %b : chaîne échappée - la chaîne sera vérifiée pour tous les littéraux échappés de
la liste des littéraux échappés ci-dessus, et traduira ceux-ci en caractères littéraux.
Par exemple, \\n sera transformé en un caractère de nouvelle ligne.
Une règle spéciale concernant le mode %b est que les littéraux octaux sont interprétés différemment.
Dans les arguments passés par %b, les littéraux interprétés en octal doivent être sous la forme de \\0NNN
au lieu de \\NNN. (Bien que, pour des raisons d'héritage, les littéraux octaux sous la forme \\NNN
seront toujours interprétés et ne déclencheront pas d'avertissement, vous aurez des problèmes si vous utilisez cela pour un
littéral dont le code commence par zéro, car il sera considéré comme sous la forme \\0NNN.)

- %q : chaîne échappée - la chaîne dans un format qui peut être réutilisé comme entrée par la plupart des shells.
Les caractères non imprimables sont échappés avec la syntaxe ‘$''’ proposée par POSIX,
et les méta-caractères du shell sont mis entre guillemets de manière appropriée.
Ceci est un format équivalent à la sortie de ls --quoting=shell-escape.

#### SUBSTITUTIONS DE CARACTÈRE

Le champ de caractère n'a pas de paramètre secondaire.

- %c : un seul caractère

#### SUBSTITUTIONS D'ENTIER

Tous les champs d'entier ont un paramètre de 'compléter avec des zéros'. %.4i signifie un entier qui, s'il a moins de 4 chiffres, est complété avec des zéros de tête jusqu'à ce qu'il ait 4 chiffres.

- %d ou %i : entier 64 bits

- %u : entier non signé 64 bits

- %x ou %X : entier non signé 64 bits affiché en hexadécimal (base 16)
%X au lieu de %x signifie utiliser des lettres majuscules pour 'a' à 'f'

- %o : entier non signé 64 bits affiché en octal (base 8)

#### SUBSTITUTIONS FLOTTANTES

Tous les champs flottants ont un paramètre de 'nombre maximal de décimales / nombre maximal de chiffres significatifs'. %.10f signifie un flottant décimal avec 7 décimales après 0. %.10e signifie un nombre en notation scientifique avec 10 chiffres significatifs. %.10g signifie le même comportement pour décimal et scientifique, respectivement, et fournit la plus courte sortie de chacun.

Comme avec GNU coreutils, la valeur après le point décimal de ces sorties est d'abord analysée comme un double avant d'être rendue en texte. Pour les deux implémentations, n'attendez pas une précision significative au-delà de la 18ème décimale. Lors de l'utilisation d'un nombre de décimales de 18 ou plus, vous pouvez vous attendre à des variations de sortie entre printf de GNU coreutils et ce printf à la 18ème décimale de +/- 1

- %f : valeur flottante présentée en décimal, tronquée et affichée avec 6 décimales par
défaut. Il n'y a pas de parité de comportement post-double avec Coreutils printf, les valeurs ne sont pas
estimées ou ajustées au-delà des valeurs d'entrée.

- %e ou %E : valeur flottante présentée en notation scientifique
7 chiffres significatifs par défaut
%E signifie utiliser un E majuscule pour

printf - man page

NAME

printf

format and print data

SYNOPSIS

printf FORMAT [ARGUMENT]...

DESCRIPTION

Write formatted output to standard output.

The printf utility performs one of the actions in FORMAT, then for each remaining ARGUMENT, performs the remaining actions in FORMAT.

The FORMAT string can contain:

  • a literal character: will be outputted as is.
  • an escape sequence: \ followed by an alphanumeric character represents a special character, which depends on the sequence.
  • \a: alert (BEL)
  • \b: backspace
  • \c: Suppress any further output.
  • \e: escape character (ASCII 27)
  • \f: form-feed
  • \n: new line
  • \r: carriage return
  • \t: horizontal tab
  • \v: vertical tab
  • \0NNN: the character whose ASCII code is NNN (octal)
  • \\: backslash
  • %[flags][width][.precision]specifier: a specification, which converts an argument to an appropriate format.

The specifier is one of the following letters:

%d, %i
Signed decimal integer.
%u
Unsigned decimal integer.
%o
Unsigned octal integer.
%x, %X
Unsigned hexadecimal integer.
%c
Single character.
%s
String. The string is terminated by the first encountered null byte or when the specified precision has been reached.
%f, %F
Decimal floating point, in conventional notation
%e, %E
Decimal floating point, in scientific notation (e.g. -1.234567e+07).
%g, %G
Floating point value presented in the shortest of decimal and scientific notation
behaves differently from %f and %E, please see posix printf spec for full details,
some examples of different behavior:
Sci Note has 6 significant digits by default
Trailing zeroes are removed
Instead of being truncated, digit after last is rounded

Like other behavior in this utility, the design choices of floating point behavior in this utility is selected to reproduce in exact the behavior of GNU coreutils' printf from an inputs and outputs standpoint.

USING PARAMETERS

Most substitution fields can be parameterized using up to 2 numbers that can be passed to the field, between the % sign and the field letter.

The 1st parameter always indicates the minimum width of output, it is useful for creating columnar output. Any output that would be less than this minimum width is padded with leading spaces The 2nd parameter is proceeded by a dot. You do not have to use parameters

SPECIAL FORMS OF INPUT

For numeric input, the following additional forms of input are accepted besides decimal:

Octal (only with integer): if the argument begins with a 0 the proceeding characters will be interpreted as octal (base 8) for integer fields

Hexadecimal: if the argument begins with 0x the proceeding characters will be interpreted will be interpreted as hex (base 16) for any numeric fields for float fields, hexadecimal input results in a precision limit (in converting input past the decimal point) of 10^-15

Character Constant: if the argument begins with a single quote character, the first byte of the next character will be interpreted as an 8-bit unsigned integer. If there are additional bytes, they will throw an error (unless the environment variable POSIXLY_CORRECT is set)
