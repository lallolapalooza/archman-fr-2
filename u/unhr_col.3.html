sous-routine cunhr_col (entier m, entier n, entier nb, complexe, dimension( lda, * ) a, entier lda, complexe, dimension( ldt, * ) t, entier ldt, complexe, dimension( * ) d, entier info)

CUNHR_COL

Objectif:

!>
!>  CUNHR_COL prend en entrée une matrice complexe M par N, Q_in, ayant des colonnes
!>  orthonormales, stockée dans A, et effectue une Reconstruction de Householder (HR),
!>  c'est-à-dire qu'elle reconstruit les vecteurs de Householder V(i) représentant
!>  implicitement une autre matrice M par N, Q_out, avec la propriété que
!>  Q_in = Q_out*S, où S est une matrice diagonale N par N avec des entrées
!>  diagonales égales à +1 ou -1. Les vecteurs de Householder (colonnes V(i) de V)
!>  sont stockés dans A en sortie, et les entrées diagonales de S sont stockées
!>  dans D. Des réflecteurs par blocs sont également retournés dans T
!>  (même format de sortie que CGEQRT).
!>

Paramètres

M 
!>          M est un ENTIER
!>          Le nombre de lignes de la matrice A. M >= 0.
!>

N

!>          N est un ENTIER
!>          Le nombre de colonnes de la matrice A. M >= N >= 0.
!>

NB

!>          NB est un ENTIER
!>          La taille du bloc de colonnes à utiliser dans la reconstruction
!>          des blocs de vecteurs de colonnes de Householder dans le tableau A
!>          et les réflecteurs de blocs correspondants dans le tableau T. NB >= 1.
!>          (Notez que si NB > N, alors N est utilisé à la place de NB
!>          comme taille du bloc de colonnes.)
!>

A

!>          A est un tableau COMPLEXE, dimension (LDA,N)
!>
!>          En entrée :
!>
!>             Le tableau A contient une matrice orthonormée M par N, Q_in,
!>             c'est-à-dire que les colonnes de A sont des vecteurs unitaires orthogonaux.
!>
!>          En sortie :
!>
!>             Les éléments sous la diagonale de A représentent la matrice
!>             unit-inférieure trapézoïdale V des vecteurs de colonnes de Householder
!>             V(i). Les entrées diagonales unitaires de V ne sont pas stockées
!>             (même format que la sortie sous la diagonale dans A de
!>             CGEQRT). La matrice T et la matrice V stockées en sortie
!>             dans A définissent implicitement Q_out.
!>
!>             Les éléments au-dessus de la diagonale contiennent le facteur U
!>             de la décomposition LU :
!>                Q_in - ( S ) = V * U
!>                       ( 0 )
!>             où 0 est une matrice nulle (M-N)-par-(M-N).
!>

LDA

!>          LDA est un ENTIER
!>          La dimension principale du tableau A. LDA >= max(1,M).
!>

T

!>          T est un tableau COMPLEXE,
!>          dimension (LDT, N)
!>
!>          Soit NOCB = Nombre_de_blocs_de_colonnes_de_sortie
!>                   = CEIL(N/NB)
!>
!>          En sortie, T(1:NB, 1:N) contient NOCB réflecteurs de blocs
!>          triangulaires supérieurs utilisés pour définir Q_out stockés
!>          sous forme compacte comme une séquence de blocs de colonnes
!>          NB par NB triangulaires supérieurs (même format que la sortie T
!>          dans CGEQRT). La matrice T et la matrice V stockées en sortie
!>          dans A définissent implicitement Q_out. REMARQUE : Les triangles
!>          inférieurs sous les blocs triangulaires supérieurs seront remplis
!>          de zéros. Voir Détails supplémentaires.
!>

LDT

!>          LDT est un ENTIER
!>          La dimension principale du tableau T.
!>          LDT >= max(1,min(NB,N)).
!>

D

!>          D est un tableau COMPLEXE, dimension min(M,N).
!>          Les éléments ne peuvent être que plus ou moins un.
!>
!>          D(i) est construit comme D(i) = -SIGN(Q_in_i(i,i)), où
!>          1 <= i <= min(M,N), et Q_in_i est Q_in après avoir effectué
!>          i-1 étapes d'élimination gaussienne "modifiée".
!>          Voir Détails supplémentaires.
!>

INFO

!>          INFO est un ENTIER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>

Détails supplémentaires:

!>
!> Le facteur unitaire M-par-M calculé Q_out est défini implicitement comme
!> un produit de matrices unitaires Q_out(i). Chaque Q_out(i) est stocké
!> dans le format de représentation WY compact en blocs correspondants
!> des matrices V (stockée dans A) et T.
!>
!> La matrice unitaire-inférieure trapézoïdale M-par-N V stockée dans la
!> matrice M-par-N A contient les vecteurs de colonnes V(i) en blocs de
!> colonnes de taille NB, VB(j). Par exemple, VB(1) contient les colonnes
!> V(1), V(2), ... V(NB). REMARQUE : Les entrées unitaires sur
!> la diagonale de V ne sont pas stockées dans A.
!>
!> Le nombre de blocs de colonnes est
!>
!>     NOCB = Nombre_de_blocs_de_colonnes_de_sortie = CEIL(N/NB)
!>
!> où chaque bloc est d'ordre NB sauf le dernier bloc, qui
!> est d'ordre LAST_NB = N - (NOCB-1)*NB.
!>
!> Par exemple, si M=6, N=5 et NB=2, la matrice V est
!>
!>
!>     V = (    VB(1),   VB(2), VB(3) ) =
!>
!>       = (    1                      )
!>         ( v21    1                 )
!>         ( v31  v32    1            )
!>         ( v41  v42  v43   1        )
!>         ( v51  v52  v53  v54    1  )
!>         ( v61  v62  v63  v54   v65 )
!>
!>
!> Pour chacun des blocs de colonnes VB(i), un réflecteur de bloc
!> triangulaire supérieur TB(i) est calculé. Ces blocs sont stockés
!> comme une séquence de blocs de colonnes triangulaires supérieurs dans
!> la matrice T de taille NB-par-N. La taille de chaque bloc TB(i) est NB-par-NB,
!> sauf pour le dernier bloc, dont la taille est LAST_NB-par-LAST_NB.
!>
!> Par exemple, si M=6, N=5 et NB=2, la matrice T est
!>
!>     T  = (    TB(1),    TB(2), TB(3) ) =
!>
!>        = ( t11  t12  t13  t14   t15  )
!>          (      t22       t24        )
!>
!>
!> Le facteur M-par-M Q_out est donné comme un produit de NOCB
!> matrices unitaires M-par-M, Q_out(i).
!>
!>     Q_out = Q_out(1) * Q_out(2) * ... * Q_out(NOCB),
!>
!> où chaque matrice Q_out(i) est donnée par la représentation WY
!> en utilisant les blocs correspondants des matrices V et T :
!>
!>     Q_out(i) = I - VB(i) * TB(i) * (VB(i))**T,
!>
!> où I est la matrice identité. Voici la formule avec les dimensions matricielles :
!>
!>  Q(i){M-par-M} = I{M-par-M} -
!>    VB(i){M-par-INB} * TB(i){INB-par-INB} * (VB(i))**T {INB-par-M},
!>
!> où INB = NB, sauf pour le dernier bloc NOCB
!> pour lequel INB=LAST_NB.
!>
!> =====
!> REMARQUE :
!> =====
!>
!> Si Q_in est le résultat d'une factorisation QR
!> B = Q_in * R_in, alors :
!>
!> B = (Q_out*S) * R_in = Q_out * (S * R_in) = Q_out * R_out.
!>
!> Donc, si l'on veut interpréter Q_out comme le résultat
!> de la factorisation QR de B, alors le R_out correspondant
!> doit être égal à R_out = S * R_in, c'est-à-dire que certaines lignes
!> de R_in doivent être multipliées par -1.
!>
!> Pour les détails de l'algorithme, voir [1].
!>
!> [1] ,
!>     G. Ballard, J. Demmel, L. Grigori, M. Jacquelin, H.D. Nguyen,
!>     E. Solomonik, J. Parallel Distrib. Comput.,
!>     vol. 85, pp. 3-31, 2015.
!>

!> triangulaire supérieur TB(i) est calculé. Ces blocs sont stockés comme
!> une séquence de blocs de colonnes triangulaires supérieurs dans la matrice T,
!> de taille NB-par-N. La taille de chaque bloc TB(i) est NB-par-NB, sauf

Objectif :

!>
!>  ZUNHR_COL prend une matrice complexe Q_in de taille M-par-N avec des colonnes orthonormées
!>  en entrée, stockée dans A, et effectue une Reconstruction de Householder (HR),
!>  c'est-à-dire qu'elle reconstruit les vecteurs de Householder V(i) représentant implicitement
!>  une autre matrice complexe Q_out de taille M-par-N, telle que Q_in = Q_out*S,
!>  où S est une matrice diagonale N-par-N avec des entrées diagonales
!>  égales à +1 ou -1. Les vecteurs de Householder (colonnes V(i) de V) sont
!>  stockés dans A en sortie, et les entrées diagonales de S sont stockées dans D.
!>  Les réflecteurs de blocs sont également retournés dans T
!>  (même format de sortie que ZGEQRT).
!>

Paramètres

M 
!>          M est un entier (INTEGER)
!>          Le nombre de lignes de la matrice A. M >= 0.
!>

N

!>          N est un entier (INTEGER)
!>          Le nombre de colonnes de la matrice A. M >= N >= 0.
!>

NB

!>          NB est un entier (INTEGER)
!>          La taille des blocs de colonnes à utiliser pour la reconstruction
!>          des blocs de vecteurs de colonnes de Householder dans le tableau A et
!>          les réflecteurs de blocs correspondants dans le tableau T. NB >= 1.
!>          (Notez que si NB > N, alors N est utilisé à la place de NB
!>          comme taille de bloc de colonnes.)
!>

A

!>          A est un tableau COMPLEX*16, de dimension (LDA,N)
!>
!>          En entrée :
!>
!>             Le tableau A contient une matrice orthonormée Q_in de taille M-par-N,
!>             c'est-à-dire que les colonnes de A sont des vecteurs unitaires orthogonaux.
!>
!>          En sortie :
!>
!>             Les éléments sous la diagonale de A représentent la matrice V,
!>             unitaire et triangulaire inférieure, des vecteurs de colonnes de Householder
!>             V(i). Les entrées diagonales unitaires de V ne sont pas stockées
!>             (même format que la sortie sous la diagonale de A provenant de
!>             ZGEQRT). La matrice T et la matrice V stockées en sortie
!>             dans A définissent implicitement Q_out.
!>
!>             Les éléments au-dessus de la diagonale contiennent le facteur U
!>             de la décomposition LU :
!>                Q_in - ( S ) = V * U
!>                       ( 0 )
!>             où 0 est une matrice nulle de taille (M-N)-par-(M-N).
!>

LDA

!>          LDA est un entier (INTEGER)
!>          La dimension principale du tableau A. LDA >= max(1,M).
!>

T

!>          T est un tableau COMPLEX*16,
!>          de dimension (LDT, N)
!>
!>          Soit NOCB = Nombre_de_blocs_de_colonnes_de_sortie
!>                   = CEIL(N/NB)
!>
!>          En sortie, T(1:NB, 1:N) contient les NOCB blocs réflecteurs
!>          triangulaires supérieurs utilisés pour définir Q_out stockés sous forme compacte
!>          comme une séquence de blocs de colonnes NB-par-NB triangulaires supérieurs
!>          (même format que la sortie T de ZGEQRT).
!>          La matrice T et la matrice V stockées en sortie dans A
!>          définissent implicitement Q_out. REMARQUE : Les parties triangulaires inférieures
!>          sous les blocs triangulaires supérieurs seront remplies de
!>          zéros. Voir Détails Supplémentaires.
!>

LDT

!>          LDT est un entier (INTEGER)
!>          La dimension principale du tableau T.
!>          LDT >= max(1,min(NB,N)).
!>

D

!>          D est un tableau COMPLEX*16, de dimension min(M,N).
!>          Les éléments ne peuvent être que plus ou moins un.
!>
!>          D(i) est construit comme D(i) = -SIGN(Q_in_i(i,i)), où
!>          1 <= i <= min(M,N), et Q_in_i est Q_in après avoir effectué
!>          i-1 étapes d'élimination Gaussienne "modifiée".
!>          Voir Détails Supplémentaires.

!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale

NOM

unhr_col - la UNIQR et la UNHQR: les sous-programmes pour la factorisation QR de matrice des matrices générales.

SYNTAXIS

Fortran

CALL CUNHR_COL( N, K, A, LDA, TAU, WORK, LWORK, INFO )
CALL ZUNHR_COL( N, K, A, LDA, TAU, WORK, LWORK, INFO )

Fonctionnalités

Cette page décrit les sous-programmes CUNHR_COL et ZUNHR_COL.

Ces sous-programmes utilisent les facteurs de Householder générés par CGEQRF ou ZGEQRF pour reconstruire la matrice Q de la factorisation QR, qui est une matrice unitaire.

Les sous-programmes appliquent la transformation unitaire
Q = Q1Q2...Qk
à une matrice donnée.

Pour les détails de l'algorithme, voir [1].

[1] ,
G. Ballard, J. Demmel, L. Grigori, M. Jacquelin, H.D. Nguyen,
E. Solomonik, J. Parallel Distrib. Comput.,
vol. 85, pp. 3-31, 2015.

Description détaillée

La routine CUNHR_COL et ZUNHR_COL sont utilisées pour reconstruire la matrice unitaire Q à partir des facteurs de Householder générés par la routine CGEQRF et ZGEQRF.

Supposons que la factorisation QR de la matrice A est donnée par:

A = Q * R

où Q est une matrice unitaire et R est une matrice triangulaire supérieure.

Les routines CUNHR_COL et ZUNHR_COL reconstruisent la matrice Q à partir des vecteurs de Householder stockés dans la matrice A et dans le tableau TAU.

La matrice Q résultante est de dimension N x K.

L'argument INFO indique le statut de sortie:

INFO = 0 : succès
INFO < 0 : le i-ème argument, où i = abs(INFO), est invalide

La signification des autres arguments est la suivante:

N
La dimension de la matrice. N est de type Integer.
K
Le nombre de vecteurs de Householder. K est de type Integer.
A
La matrice d'entrée. La partie supérieure de A contient les vecteurs de Householder. A est de type Character*1 ou Double Precision.
LDA
Le pas de la matrice A. LDA est de type Integer.
TAU
Le tableau des scalaires tau des transformations de Householder. TAU est de type Complex ou Double Precision Complex.
WORK
Un tableau de travail. WORK est de type Complex ou Double Precision Complex.
LWORK
La taille du tableau WORK. LWORK est de type Integer.
INFO
Le statut de sortie. INFO est de type Integer.

Exemple d'utilisation:

      PROGRAM TEST_UNHR_COL
      IMPLICIT NONE
      INTEGER N, K, LDA, LWORK, INFO
      COMPLEX*16 A(10,10), TAU(10), WORK(100)
      INTEGER I, J

      N = 4
      K = 2
      LDA = 10
      LWORK = 100

      ! Initialiser la matrice A avec des vecteurs de Householder
      A(1,1) = (0.0D0, 0.0D0)
      A(2,1) = (1.0D0, 0.0D0)
      A(3,1) = (0.0D0, 0.0D0)
      A(4,1) = (0.0D0, 0.0D0)
      A(1,2) = (0.0D0, 0.0D0)
      A(2,2) = (0.0D0, 0.0D0)
      A(3,2) = (1.0D0, 0.0D0)
      A(4,2) = (0.0D0, 0.0D0)
      A(1,3) = (2.0D0, 0.0D0)
      A(2,3) = (3.0D0, 0.0D0)
      A(3,3) = (4.0D0, 0.0D0)
      A(4,3) = (5.0D0, 0.0D0)
      A(1,4) = (6.0D0, 0.0D0)
      A(2,4) = (7.0D0, 0.0D0)
      A(3,4) = (8.0D0, 0.0D0)
      A(4,4) = (9.0D0, 0.0D0)

      ! Initialiser le tableau TAU
      TAU(1) = (-1.0D0, 0.0D0)
      TAU(2) = (-0.5D0, 0.0D0)

      ! Appeler la routine ZUNHR_COL
      CALL ZUNHR_COL( N, K, A, LDA, TAU, WORK, LWORK, INFO )

      ! Vérifier le statut de sortie
      IF (INFO .NE. 0) THEN
         PRINT *, 'Erreur: INFO = ', INFO
      ELSE
         PRINT *, 'Matrice Q résultante:'
         DO I = 1, N
            DO J = 1, K
               PRINT '(F10.5,2X)', REAL(A(I,J)), AIMAG(A(I,J))
            END DO
            PRINT *
         END DO
      END IF

      END PROGRAM TEST_UNHR_COL
