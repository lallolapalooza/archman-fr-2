NOM

urxvtd - démon urxvt

SYNOPSIS

urxvtd [-q|--quiet] [-o|--opendisplay] [-f|--fork] [-m|--mlock] [-e|--eval chaîneperl]

urxvtd -q -o -f # pour une utilisation dans .xsession

DESCRIPTION

Cette page de manuel décrit le démon urxvtd, qui est le même émulateur de terminal vt102 que urxvt, mais fonctionne comme un démon capable d'ouvrir plusieurs fenêtres de terminal au sein du même processus.

Vous pouvez l'exécuter à partir de vos scripts de démarrage X, par exemple, bien qu'il ne dépende pas d'un affichage X fonctionnel et puisse même ouvrir des fenêtres sur plusieurs écrans X simultanément.

Les avantages de l'exécution d'un démon urxvt incluent un temps de création plus rapide pour les fenêtres de terminal et une économie de mémoire considérable.

Le désavantage est un impact potentiel sur la stabilité : si le programme principal plante, tous les processus dans les fenêtres du terminal sont terminés. Par exemple, comme il n'y a aucun moyen de réagir proprement aux fermetures de connexion anormales, "xkill" et les réinitialisations/redémarrages du serveur tueront l'instance urxvtd, y compris toutes les fenêtres qu'elle a ouvertes.

OPTIONS

urxvtd ne comprend actuellement que quelques options. Le regroupement des options n'est pas encore pris en charge.

-q, --quiet
Normalement, urxvtd affiche le message "rxvt-unicode daemon listening on <path>" après s'être lié à son socket de contrôle. Cette option supprime ce message (les erreurs et les avertissements seront toujours enregistrés).
-o, --opendisplay
Force urxvtd à ouvrir une connexion au $DISPLAY actuel et à la maintenir ouverte.

Ceci est utile si vous souhaitez lier une instance de urxvtd à la durée de vie d'un serveur/affichage spécifique. Si le serveur effectue une réinitialisation, urxvtd sera tué automatiquement.

-f, --fork
Fait en sorte que urxvtd se détache (fork) après s'être lié à son socket de contrôle.
-m, --mlock
Fait en sorte que urxvtd appelle mlockall(2) sur lui-même. Cela verrouille urxvtd en RAM et l'empêche d'être échangé sur le disque, au prix d'une consommation de mémoire beaucoup plus importante sur la plupart des systèmes d'exploitation.

Note : Pour utiliser cette fonctionnalité, votre administrateur système doit avoir défini la RLIMIT_MEMLOCK de votre utilisateur à une taille supérieure ou égale à la taille du binaire urxvtd (ou à illimité). Voir /etc/security/limits.conf.

Note 2 : Il existe un bug connu dans glibc (potentiellement corrigé dans les versions 2.8 et ultérieures) où calloc retourne de la mémoire non initialisée lorsque mlockall est actif. Si vous rencontrez des plantages ou d'autres comportements étranges lors de l'utilisation de --mlock, essayez sans cette option.

-e, --eval chaîneperl
Évalue le code perl donné après l'initialisation de base (nécessite que le support perl soit activé lors de la compilation de urxvtd).

Ceci peut être utilisé, par exemple, pour configurer l'interpréteur perl interne, qui est partagé entre toutes les instances de terminal, ou créer des sockets d'écoute supplémentaires pour des protocoles additionnels.

Le code est actuellement exécuté *avant* la création des sockets d'écoute normaux : cela pourrait changer dans les futures versions.

EXEMPLES

Voici une invocation utile de urxvtd dans un script de type .xsession :

urxvtd -q -f -o

Ceci attend que le socket de contrôle soit disponible, ouvre l'affichage actuel et se détache en arrière-plan. Lorsque vous vous déconnectez, le serveur est réinitialisé et urxvtd est tué.

ENVIRONNEMENT

RXVT_SOCKET
urxvtc et urxvtd utilisent tous deux la variable d'environnement RXVT_SOCKET pour créer un socket d'écoute et pour contacter urxvtd, respectivement. Si la variable est manquante, alors $HOME/.urxvt/urxvtd-<nomdunoeud> est utilisé.
LISTEN_PID, LISTEN_FDS, LISTEN_FDNAMES
Si ces variables d'environnement sont définies, urxvtd recherche un descripteur de fichier passé par le gestionnaire de service via l'interface native de systemd. Si un est fourni, urxvtd l'utilise comme socket d'écoute au lieu d'en créer un comme spécifié ci-dessus.
DISPLAY
Utilisé uniquement lorsque l'option "--opendisplay" est spécifiée. Doit contenir un nom d'affichage X valide.
