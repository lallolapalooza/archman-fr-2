NOM

unbound-host - Utilitaire de requête DNS Unbound 1.24.2.

SYNTAXE

unbound-host [-C fichier_config] [-vdhr46D] [-c classe] [-t type] [-y clé] [-f fichier_clé] [-F fichier_clé_nommée] nom_hôte

DESCRIPTION

unbound-host utilise le résolveur validant Unbound pour interroger le nom d'hôte et afficher les résultats. Avec l'option -v, il affiche le statut de validation : sécurisé, non sécurisé, faux (échec de sécurité).

Par défaut, il ne lit aucun fichier de configuration. Il tente de contacter les serveurs racine d'Internet. Avec -C, un fichier de configuration unbound et avec -r, resolv.conf peut être lu.

Les options disponibles sont :

nom_hôte
Ce nom est résolu (interrogé dans le DNS). Si une adresse IPv4 ou IPv6 est fournie, une requête inverse est effectuée.
-h
Affiche l'aide sur la version et les options de la ligne de commande.
-v
Active la sortie verbeuse et affiche les résultats de validation, sur chaque ligne. Sécurisé signifie que la réponse NXDOMAIN (aucun nom de domaine existant), nodata (aucune donnée existante) ou donnée positive a été validée correctement avec l'une des clés. Non sécurisé signifie qu'aucun mécanisme de sécurité n'est configuré pour ce nom de domaine. Faux (échec de sécurité) signifie que la réponse a échoué à une ou plusieurs vérifications, elle est probablement erronée, obsolète, falsifiée ou corrompue.
-d
Active la sortie de débogage vers stderr. Une seule option -d montre ce que font le résolveur et le validateur et peut vous dire ce qui se passe. Plusieurs options -d -d génèrent beaucoup de sortie, avec chaque paquet envoyé et reçu.
-c <classe>
Spécifie la classe à rechercher, la classe par défaut est IN (Internet).
-t <type>
Spécifie le type de données à rechercher. Par défaut, recherche les données IPv4, IPv6 et les gestionnaires de courrier, ou les pointeurs de nom de domaine pour les requêtes inverses.
-y <clé>
Spécifie une clé publique à utiliser comme ancre de confiance. C'est la base d'une chaîne de confiance qui est construite à partir de l'ancre de confiance jusqu'à la réponse, afin de valider le message de réponse. Peut être fournie sous forme d'enregistrement DS ou DNSKEY. Par exemple :
-y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD"
-D
Active la validation DNSSEC. Lit l'ancre racine à partir de l'ancre racine par défaut configurée, à l'emplacement par défaut : /etc/trusted-key.key.
-f <fichier_clé>
Lit les clés à partir d'un fichier. Chaque ligne contient un enregistrement DS ou DNSKEY, dans le format indiqué pour -y. Le format du fichier de zone, le même que celui produit par dig et drill.
-F <fichier_clé_nommée>
Lit les clés à partir d'un fichier named.conf de style BIND. Seules les entrées trusted-key {}; sont lues.
-C <fichier_config>
Utilise le fichier unbound.conf spécifié pour initialiser libunbound(3). Passez-le comme premier argument si vous souhaitez remplacer certaines options du fichier de configuration par d'autres arguments sur la ligne de commande.
-r
Lit /etc/resolv.conf et utilise les serveurs DNS de redirection qui s'y trouvent (ceux qui auraient pu être définis par DHCP). Plus d'informations dans resolv.conf(5). Casse la validation si ces serveurs ne prennent pas en charge DNSSEC.
-4
Utilise uniquement le réseau IPv4 pour envoyer des paquets.
-6
Utilise uniquement le réseau IPv6 pour envoyer des paquets.

EXEMPLES

Quelques exemples d'utilisation. Les clés affichées ci-dessous sont fausses, donc un échec de sécurité sera rencontré.

$ unbound-host www.example.com
$ unbound-host -v -y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD" www.example.com
$ unbound-host -v -y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD" 192.0.2.153

CODE DE SORTIE

Le programme unbound-host se termine avec le code de statut 1 en cas d'erreur, 0 en cas de succès. Les données peuvent ne pas être disponibles avec le code de sortie 0, le code de sortie 1 signifie que la recherche a rencontré une erreur fatale.
