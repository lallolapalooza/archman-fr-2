unshare(2) Manuel des appels système unshare(2)

NOM

unshare - dissocier des parties du contexte d'exécution du processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE
#include <sched.h>
int unshare(int flags);

DESCRIPTION

unshare() permet à un processus (ou un thread) de dissocier des parties de son contexte d'exécution qui sont actuellement partagées avec d'autres processus (ou threads). Une partie du contexte d'exécution, comme l'espace de noms de montage, est partagée implicitement lorsqu'un nouveau processus est créé en utilisant fork(2) ou vfork(2), tandis que d'autres parties, comme la mémoire virtuelle, peuvent être partagées sur demande explicite lors de la création d'un processus ou d'un thread en utilisant clone(2).

L'utilisation principale de unshare() est de permettre à un processus de contrôler son contexte d'exécution partagé sans créer de nouveau processus.

L'argument flags est un masque de bits qui spécifie quelles parties du contexte d'exécution doivent être dissociées. Cet argument est spécifié en combinant par OR zéro ou plusieurs des constantes suivantes :

CLONE_FILES
Inverse l'effet du drapeau clone(2) CLONE_FILES. Dissocie la table des descripteurs de fichiers, de sorte que le processus appelant ne partage plus ses descripteurs de fichiers avec aucun autre processus.
CLONE_FS
Inverse l'effet du drapeau clone(2) CLONE_FS. Dissocie les attributs du système de fichiers, de sorte que le processus appelant ne partage plus son répertoire racine (chroot(2)), son répertoire courant (chdir(2)) ou ses attributs umask (umask(2)) avec aucun autre processus.
CLONE_NEWCGROUP (depuis Linux 4.6)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWCGROUP. Dissocie l'espace de noms cgroup. L'utilisation de CLONE_NEWCGROUP nécessite la capacité CAP_SYS_ADMIN.
CLONE_NEWIPC (depuis Linux 2.6.19)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWIPC. Dissocie l'espace de noms IPC, de sorte que le processus appelant possède une copie privée de l'espace de noms IPC qui n'est pas partagée avec tout autre processus. La spécification de ce drapeau implique automatiquement CLONE_SYSVSEM également. L'utilisation de CLONE_NEWIPC nécessite la capacité CAP_SYS_ADMIN.
CLONE_NEWNET (depuis Linux 2.6.24)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWNET. Dissocie l'espace de noms réseau, de sorte que le processus appelant est déplacé dans un nouvel espace de noms réseau qui n'est pas partagé avec tout processus existant précédemment. L'utilisation de CLONE_NEWNET nécessite la capacité CAP_SYS_ADMIN.
CLONE_NEWNS
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWNS. Dissocie l'espace de noms de montage, de sorte que le processus appelant possède une copie privée de son espace de noms qui n'est pas partagée avec tout autre processus. La spécification de ce drapeau implique automatiquement CLONE_FS également. L'utilisation de CLONE_NEWNS nécessite la capacité CAP_SYS_ADMIN. Pour plus d'informations, voir mount_namespaces(7).
CLONE_NEWPID (depuis Linux 3.8)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWPID. Dissocie l'espace de noms PID, de sorte que le processus appelant possède un nouvel espace de noms PID pour ses enfants qui n'est pas partagé avec tout processus existant précédemment. Le processus appelant n'est *pas* déplacé dans le nouvel espace de noms. Le premier enfant créé par le processus appelant aura l'identifiant de processus 1 et assumera le rôle d'init(1) dans le nouvel espace de noms. CLONE_NEWPID implique automatiquement CLONE_THREAD également. L'utilisation de CLONE_NEWPID nécessite la capacité CAP_SYS_ADMIN. Pour plus d'informations, voir pid_namespaces(7).
CLONE_NEWTIME (depuis Linux 5.6)
Dissocie l'espace de noms de temps, de sorte que le processus appelant possède un nouvel espace de noms de temps pour ses enfants qui n'est pas partagé avec tout processus existant précédemment. Le processus appelant n'est *pas* déplacé dans le nouvel espace de noms. L'utilisation de CLONE_NEWTIME nécessite la capacité CAP_SYS_ADMIN. Pour plus d'informations, voir time_namespaces(7).
CLONE_NEWUSER (depuis Linux 3.8)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWUSER. Dissocie l'espace de noms utilisateur, de sorte que le processus appelant est déplacé dans un nouvel espace de noms utilisateur qui n'est pas partagé avec tout processus existant précédemment. Comme avec le processus enfant créé par clone(2) avec le drapeau CLONE_NEWUSER, l'appelant obtient un ensemble complet de capacités dans le nouvel espace de noms.
CLONE_NEWUSER nécessite que le processus appelant ne soit pas threadé ; la spécification de CLONE_NEWUSER implique automatiquement CLONE_THREAD. Depuis Linux 3.9, CLONE_NEWUSER implique également automatiquement CLONE_FS. CLONE_NEWUSER nécessite que l'identifiant utilisateur et l'identifiant de groupe du processus appelant soient mappés aux identifiants utilisateur et de groupe dans l'espace de noms utilisateur du processus appelant au moment de l'appel.
Pour plus d'informations sur les espaces de noms utilisateur, voir user_namespaces(7).
CLONE_NEWUTS (depuis Linux 2.6.19)
Ce drapeau a le même effet que le drapeau clone(2) CLONE_NEWUTS. Dissocie l'espace de noms IPC UTS, de sorte que le processus appelant possède une copie privée de l'espace de noms UTS qui n'est pas partagée avec tout autre processus. L'utilisation de CLONE_NEWUTS nécessite la capacité CAP_SYS_ADMIN.
CLONE_SYSVSEM (depuis Linux 2.6.26)
Ce drapeau inverse l'effet du drapeau clone(2) CLONE_SYSVSEM. Dissocie les valeurs d'ajustement des sémaphores System V (semadj), de sorte que le processus appelant possède une nouvelle liste semadj vide qui n'est partagée avec aucun autre processus. Si c'est le dernier processus qui a une référence à la liste semadj actuelle du processus, alors les ajustements de cette liste sont appliqués aux sémaphores correspondants, comme décrit dans semop(2).

De plus, CLONE_THREAD, CLONE_SIGHAND et CLONE_VM peuvent être spécifiés dans flags si l'appelant est monothreadé (c'est-à-dire qu'il ne partage pas son espace d'adressage avec un autre processus ou thread). Dans ce cas, ces drapeaux n'ont aucun effet. (Notez également que la spécification de CLONE_THREAD implique automatiquement CLONE_VM, et la spécification de CLONE_VM implique automatiquement CLONE_SIGHAND.) Si le processus est multithreadé, l'utilisation de ces drapeaux entraîne une erreur.

Si flags est spécifié comme zéro, alors unshare() est une opération nulle ; aucune modification n'est apportée au contexte d'exécution du processus appelant.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
Un bit invalide a été spécifié dans flags.
EINVAL
CLONE_THREAD, CLONE_SIGHAND ou CLONE_VM a été spécifié dans flags, et l'appelant est multithreadé.
EPERM
Une des opérations de création d'espace de noms (par exemple, CLONE_NEWNET, CLONE_NEWPID, CLONE_NEWUSER, CLONE_NEWIPC, CLONE_NEWUTS, CLONE_NEWCGROUP, CLONE_NEWNS) a été demandée, mais le processus appelant n'a pas la capacité CAP_SYS_ADMIN requise.
EPERM
CLONE_NEWUSER a été spécifié, mais l'utilisateur et le groupe du processus appelant ne sont pas mappés dans l'espace de noms utilisateur actuel.
ENOMEM
Impossible d'allouer suffisamment de mémoire pour créer un nouvel espace de noms.

CONFORMITÉ

L'appel système unshare() existe depuis Linux 2.6.19. Sa disponibilité et son comportement peuvent varier sur d'autres systèmes d'exploitation.

ERRORS

EINVAL
CLONE_NEWIPC était spécifié dans flags, mais le noyau n'a pas été configuré avec les options CONFIG_SYSVIPC et CONFIG_IPC_NS.
EINVAL
CLONE_NEWNET était spécifié dans flags, mais le noyau n'a pas été configuré avec l'option CONFIG_NET_NS.
EINVAL
CLONE_NEWPID était spécifié dans flags, mais le noyau n'a pas été configuré avec l'option CONFIG_PID_NS.
EINVAL
CLONE_NEWUSER était spécifié dans flags, mais le noyau n'a pas été configuré avec l'option CONFIG_USER_NS.
EINVAL
CLONE_NEWUTS était spécifié dans flags, mais le noyau n'a pas été configuré avec l'option CONFIG_UTS_NS.
EINVAL
CLONE_NEWPID était spécifié dans flags, mais le processus a précédemment appelé unshare() avec le drapeau CLONE_NEWPID.
ENOMEM
Impossible d'allouer suffisamment de mémoire pour copier les parties du contexte de l'appelant qui doivent être dissociées.
ENOSPC (depuis Linux 3.7)
CLONE_NEWPID était spécifié dans flags, mais la limite sur la profondeur de imbrication des espaces de noms PID aurait été dépassée ; voir pid_namespaces(7).
ENOSPC (depuis Linux 4.9 ; auparavant EUSERS)
CLONE_NEWUSER était spécifié dans flags, et l'appel causerait le dépassement de la limite sur le nombre d'espaces de noms utilisateur imbriqués. Voir user_namespaces(7).
De Linux 3.11 à Linux 4.8, l'erreur diagnostiquée dans ce cas était EUSERS.
ENOSPC (depuis Linux 4.9)
Une des valeurs dans flags spécifiait la création d'un nouvel espace de noms utilisateur, mais cela aurait causé le dépassement de la limite définie par le fichier correspondant dans /proc/sys/user. Pour plus de détails, voir namespaces(7).
EPERM
Le processus appelant n'avait pas les privilèges requis pour cette opération.
EPERM
CLONE_NEWUSER était spécifié dans flags, mais soit l' identifiant utilisateur effectif, soit l'identifiant groupe effectif de l'appelant n'a pas de mappage dans l'espace de noms parent (voir user_namespaces(7)).
EPERM (depuis Linux 3.9)
CLONE_NEWUSER était spécifié dans flags et l'appelant est dans un environnement chroot (c'est-à-dire que le répertoire racine de l'appelant ne correspond pas au répertoire racine de l'espace de noms de montage dans lequel il réside).
EUSERS (de Linux 3.11 à Linux 4.8)
CLONE_NEWUSER était spécifié dans flags, et la limite sur le nombre d'espaces de noms utilisateur imbriqués serait dépassée. Voir la discussion sur l'erreur ENOSPC ci-dessus.

STANDARDS

Linux.

HISTORY

Linux 2.6.16.

NOTES

Tous les attributs de processus qui peuvent être partagés lors de la création d'un nouveau processus en utilisant clone(2) ne peuvent pas être dissociés en utilisant unshare(). En particulier, en version noyau 3.8, unshare() n'implémente pas de drapeaux qui inversent les effets de CLONE_SIGHAND, CLONE_THREAD, ou CLONE_VM. Une telle fonctionnalité pourrait être ajoutée à l'avenir, si nécessaire.

La création de tous types d'espaces de noms, sauf les espaces de noms utilisateur, nécessite la capacité CAP_SYS_ADMIN. Cependant, étant donné que la création d'un espace de noms utilisateur confère automatiquement un ensemble complet de capacités, la création simultanée d'un espace de noms utilisateur et de tout autre type d'espace de noms dans un seul appel unshare() ne nécessite pas la capacité CAP_SYS_ADMIN dans l'espace de noms d'origine.

EXAMPLES

Le programme ci-dessous fournit une implémentation simple de la commande unshare(1), qui dissocie un ou plusieurs espaces de noms et exécute la commande fournie dans ses arguments de ligne de commande. Voici un exemple d'utilisation de ce programme, exécutant un shell dans un nouvel espace de noms de montage, et vérifiant que le shell d'origine et le nouveau shell sont dans des espaces de noms de montage distincts :


$ readlink /proc/$$/ns/mnt;
mnt:[4026531840]
$ sudo ./unshare -m /bin/bash;
# readlink /proc/$$/ns/mnt;
mnt:[4026532325]

La sortie différente des deux commandes readlink(1) montre que les deux shells sont dans des espaces de noms de montage différents.

Source du programme

/* unshare.c
   Une implémentation simple de la commande unshare(1) : dissocie
   les espaces de noms et exécute une commande.
*/
#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
static void
usage(char *pname)
{
    fprintf(stderr, "Usage: %s [options] program [arg...]\n", pname);
    fprintf(stderr, "Les options peuvent être :\n");
    fprintf(stderr, "    -C   dissocier l'espace de noms cgroup\n");
    fprintf(stderr, "    -i   dissocier l'espace de noms IPC\n");
    fprintf(stderr, "    -m   dissocier l'espace de noms de montage\n");
    fprintf(stderr, "    -n   dissocier l'espace de noms réseau\n");
    fprintf(stderr, "    -p   dissocier l'espace de noms PID\n");
    fprintf(stderr, "    -t   dissocier l'espace de noms temporel\n");
    fprintf(stderr, "    -u   dissocier l'espace de noms UTS\n");
    fprintf(stderr, "    -U   dissocier l'espace de noms utilisateur\n");
    exit(EXIT_FAILURE);
}
int
main(int argc, char *argv[])
{
    int flags, opt;
    flags = 0;
    while ((opt = getopt(argc, argv, "CimnptuU")) != -1) {
        switch (opt) {
        case 'C': flags |= CLONE_NEWCGROUP;     break;
        case 'i': flags |= CLONE_NEWIPC;        break;
        case 'm': flags |= CLONE_NEWNS;         break;
        case 'n': flags |= CLONE_NEWNET;        break;
        case 'p': flags |= CLONE_NEWPID;        break;
        case 't': flags |= CLONE_NEWTIME;       break;
        case 'u': flags |= CLONE_NEWUTS;        break;
        case 'U': flags |= CLONE_NEWUSER;       break;
        default:  usage(argv[0]);
        }
    }
    if (optind >= argc)
        usage(argv[0]);
    if (unshare(flags) == -1)
        err(EXIT_FAILURE, "unshare");
    execvp(argv[optind], &argv[optind]);
    err(EXIT_FAILURE, "execvp");
}
