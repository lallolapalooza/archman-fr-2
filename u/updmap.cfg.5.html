NOM

updmap.cfg - configuration du mappage/inclusion des polices pour dvips et ses semblables.

DESCRIPTION

Le fichier updmap.cfg est le fichier de configuration central des polices d'un système teTeX et est lu par updmap(1). Il décrit si et comment les polices doivent être incluses (ou non) dans les fichiers PS/PDF. Cela fonctionne principalement pour les polices de contour (Type 1 Postscript) et les polices bitmap (Type 3 Postscript) provenant de MetaFont.

updmap est un utilitaire qui crée des fichiers de configuration de polices pour dvips(1), pdftex(1), xdvi(1), ps2pk(1), gsftopk(1), et dvipdfmx(1). Dans un monde idéal, updmap serait inutile — chacun de ces programmes lirait le même fichier de configuration pour savoir quelles polices sont disponibles et comment elles doivent être traitées. Cependant, dans l'état actuel des choses, chacun de ces outils a des exigences subtilement différentes et a donc besoin de son propre fichier de configuration de polices. updmap crée des fichiers de configuration de polices pour tous ces programmes à partir de plusieurs sources, à savoir tous les updmap.cfg, vous permettant de garder facilement tous les différents fichiers de configuration synchronisés.

Exécuter "updmap --help" affichera la documentation principale pour l'utilisation de updmap.

dvipsPreferOutline
Configure si dvips doit (par défaut) préférer les polices bitmap ou les polices de contour si les deux sont disponibles ? Indépendamment de ce réglage, les contours peuvent être forcés en plaçant "p psfonts_t1.map" dans un fichier de configuration que dvips lit. Les bitmaps peuvent être forcés en plaçant "p psfonts_pk.map" dans un fichier de configuration. Nous fournissons de tels fichiers de configuration qui peuvent être activés via dvips -Poutline (resp. dvips -Ppk).

Les paramètres valides pour dvipsPreferOutline sont true / false.

LW35
Quelles polices des "Basic 35 Laserwriter Fonts" souhaitez-vous utiliser et comment les noms de fichiers sont-ils choisis ? Paramètres valides :
URW : Polices URW avec des noms de fichiers "vendor" (par ex. n019064l.pfb)
URWkb : Polices URW avec des noms de fichiers "berry" (par ex. uhvbo8ac.pfb)
ADOBE : Polices Adobe avec des noms de fichiers "vendor" (par ex. hvnbo___.pfb)
ADOBEkb : Polices Adobe avec des noms de fichiers "berry" (par ex. phvbo8an.pfb)

dvipsDownloadBase35
Configure si dvips doit (par défaut) télécharger les 35 polices PostScript de base dans le document (paramètre true) ou si ces polices doivent être utilisées à partir de l'interpréteur ps / de l'imprimante (paramètre false).
L'utilisateur peut outrepasser la valeur par défaut en spécifiant dvips -Pdownload35 (resp. dvips -Pbuiltin35) pour télécharger les polices LW35 (resp. utiliser les polices intégrées).
Les paramètres valides sont true / false.

pdftexDownloadBase14
pdftex doit-il télécharger les 14 polices PDF de base ? Comme certaines configurations (outils ps / pdf / imprimantes) utilisent de mauvaises polices par défaut, il est plus sûr de télécharger les polices. Les fichiers pdf deviennent plus volumineux, mais c'est le coût.
Les paramètres valides sont true (télécharger les polices) ou false (ne pas télécharger les polices). Adobe recommande d'incorporer toutes les polices.

pxdviUse
Faut-il créer des fichiers de mappage spéciaux pour pxdvi ? pxdvi est une adaptation de xdvi avec la prise en charge de la lecture et de l'affichage des fichiers générés par la famille d'engines ptex.
Les paramètres valides sont true (générer la configuration) ou false. Voir http://www.tug.org/texlive/updmap-kanji.html pour une discussion détaillée.

kanjiEmbed
kanjiVariant
Les options kanjiEmbed et kanjiVariant spécifient des remplacements spéciaux dans les lignes de mappage. Dans un mappage, la chaîne "@kanjiEmbed@" sera remplacée par la valeur de cette option ; de même pour kanjiVariant. De cette façon, les utilisateurs de TeX japonais peuvent sélectionner différentes polices à inclure dans la sortie finale.

Map
Pointe vers un fichier de mappage, qui décrit un mappage d'une police (appelée dans le document TeX) vers le fichier pfb contenant le code Postscript.
Utilisation : Map nom_fichier.map

La syntaxe des fichiers de mappage est la même que celle utilisée par dvips(1), voir la section "psfonts.map" du manuel de dvips(1).

MixedMap
Similaire à Map. Il doit être utilisé lorsqu'il existe une implémentation Type1 et une implémentation bitmap de la police (cette dernière provenant principalement de MetaFont). Ces entrées ne seront pas utilisées dans le mappage par défaut de dvips si dvipsPreferOutline est réglé sur false.
Utilisation : MixedMap nom_fichier.map

KanjiMap
Similaire à Map. Il doit être utilisé pour les polices kanji.
Utilisation : KanjiMap nom_fichier.map

Le signe # précède un commentaire.

Les fichiers de mappage à ne pas utiliser doivent être commentés à l'aide de la chaîne #! au début de la ligne. Ces entrées peuvent être (dés)activées en utilisant updmap avec les options --enable et --disable, respectivement.
