NOM

urxvtperl - interpréteur perl embarqué de rxvt-unicode

SYNOPIS

# créer un fichier grab_test dans un répertoire quelconque :
sub on_sel_grab {
   warn "vous avez sélectionné ", $_[0]->selection;
   ()
}
# démarrer une instance urxvt en l'utilisant :
urxvt --perl-lib chemin/vers/ledossier -pe grab_test

DESCRIPTION

Chaque fois qu'un objet terminal est créé, les scripts d'extension spécifiés via la ressource "perl" sont chargés et associés à celui-ci.

Les scripts sont compilés dans un environnement 'use strict qw(vars subs)' et 'use utf8', et doivent donc être encodés en UTF-8.

Chaque script ne sera chargé qu'une seule fois, même dans urxvtd, où les scripts seront partagés (mais pas activés) pour tous les terminaux.

Vous pouvez désactiver l'interpréteur perl embarqué en définissant les ressources "perl-ext" et "perl-ext-common" sur une chaîne vide.

EXTENSIONS PRÉ-EMPAQUETÉES

Un certain nombre d'extensions sont livrées avec cette version. Vous pouvez les trouver dans <libdir>/urxvt/perl/, et la documentation peut être consultée en utilisant man urxvt-<NOMDELEXTENSION>.

Vous pouvez les activer ainsi :

urxvt -pe <nomdelextension>

Ou en les ajoutant à la ressource pour les extensions chargées par défaut :

URxvt.perl-ext-common: default,selection-autotransform

Les extensions peuvent ajouter des ressources supplémentaires et des "actions", c'est-à-dire des méthodes qui peuvent être liées à une touche et invoquées par l'utilisateur. Une extension peut définir les ressources qu'elle supporte en utilisant des commentaires dits META, décrits ci-dessous. De manière similaire aux ressources intégrées, les ressources d'extension peuvent également être spécifiées sur la ligne de commande comme options longues (avec "." remplacé par "-"), auquel cas l'extension correspondante est chargée automatiquement. Pour que cela fonctionne, l'extension **doit** définir des commentaires META pour ses ressources.

DOCUMENTATION DE L'API

Considérations Générales sur l'API

Tous les objets (tels que les terminaux, les observateurs de temps, etc.) sont typiquement des objets référence-vers-hash. Le hash peut être utilisé pour stocker tout ce que vous voulez. Tous les membres commençant par un underscore (tel que "_ptr" ou "_hook") sont réservés à des usages internes et ne **doivent pas** être accédés ou modifiés).

Lorsque les objets sont détruits du côté C++, les hashes des objets perl sont vidés, il est donc préférable de stocker des objets liés tels que les observateurs de temps et autres à l'intérieur de l'objet terminal afin qu'ils soient détruits dès que le terminal est détruit.

Les noms des arguments indiquent souvent également le type d'un paramètre. Voici quelques indices sur ce qu'ils signifient :

$text
La manière spéciale de rxvt-unicode d'encoder le texte, où un caractère « unicode » représente toujours une cellule d'écran. Voir ROW_t pour une discussion de ce format.
$string
Une chaîne de texte perl, en mettant l'accent sur le mot *texte*. Elle peut stocker tous les caractères unicode et doit être distinguée du texte encodé dans un encodage spécifique (souvent spécifique à la locale) et des données binaires.
$octets
Soit des données binaires, soit — plus couramment — une chaîne de texte encodée d'une manière spécifique à la locale.
$keysym
un entier qui est un code X11 keysym valide. Vous pouvez convertir une chaîne en keysym et vice versa en utilisant "XStringToKeysym" et "XKeysymToString".

Objets d'extension

Chaque extension perl est une classe perl. Un objet perl distinct est créé pour chaque terminal, et chaque terminal a son propre ensemble d'objets d'extension, qui sont passés comme premier paramètre aux hooks. Ainsi, les extensions peuvent utiliser leur objet $self sans avoir à penser aux conflits avec d'autres extensions ou d'autres terminaux, à l'exception des méthodes et des membres qui commencent par un caractère underscore "_" : ceux-ci sont réservés à un usage interne.

Bien que ce ne soit pas un objet "urxvt::term", vous pouvez appeler toutes les méthodes de la classe "urxvt::term" sur cet objet.

Des méthodes supplémentaires uniquement supportées pour les objets d'extension sont décrites dans la section "urxvt::extension" ci-dessous.

Commentaires META

Rxvt-unicode reconnaît des commentaires méta spéciaux dans les extensions qui définissent différents types de métadonnées. Ces commentaires sont analysés chaque fois qu'un terminal est créé et sont généralement utilisés pour charger automatiquement les extensions lorsque leurs ressources ou leurs paramètres de ligne de commande sont utilisés.

Actuellement, il reconnaît les commentaires ci-dessous. Les composants individuels sont séparés par des deux-points (":"), et ne doivent pas contenir de deux-points eux-mêmes — il n'y a actuellement aucun mécanisme d'échappement prévu pour cela.

#:META:RESOURCE:nom:type:desc
Le commentaire RESOURCE définit une ressource utilisée par l'extension, où "nom" est le nom de la ressource, "type" est le type de la ressource, "boolean" ou "string", et "desc" est la description de la ressource.

L'extension sera chargée automatiquement lorsque cette ressource est spécifiée ou utilisée comme paramètre de ligne de commande.

Exemple : matcher fournit la ressource "matcher.launcher" en ayant ce commentaire :

#:META:RESOURCE:%.launcher:string:commande de lancement par défaut

Exemple : charger cette extension lorsque l'option de ligne de commande ou le nom de ressource "-tr" est utilisé.

#:META:RESOURCE:tr:boolean:définir l'image racine comme arrière-plan
#:META:OSC:nombre:desc
Le commentaire OSC spécifie une séquence OSC, où "nombre" est le code OSC numérique et "desc" est une courte description qui est actuellement inutilisée.

Cela entraînera le chargement automatique de l'extension lorsque la séquence OSC est utilisée pour la première fois.

Notez que le chargement automatique entraîne certaines responsabilités supplémentaires : bien que le terminal ne puisse pas vraiment se protéger contre des sources malveillantes de séquences de commandes, faisant ainsi confiance aux programmes qui s'exécutent *à l'intérieur* pour assainir les données qu'ils émettent, il est très courant que des programmes émettent des séquences de commandes provenant de sources non fiables.

Bien que cela signifie que les extensions devraient, comme mécanisme de défense en profondeur, toujours considérer si les séquences OSC sont sûres, le chargement automatique expose automatiquement toute extension chargée automatiquement dans toutes les fenêtres du terminal, donc une attention particulière doit être portée.

Exemple : l'extension background enregistre l'OSC 20 comme ceci :

#:META:OSC:20:changer/interroger l'image d'arrière-plan
#:META:OSC_PERL:préfixe:desc
Identique au commentaire OSC, mais pour la séquence OSC Perl (777). Le "préfixe" doit être unique parmi les extensions, bien sûr, ce qui est plus facilement organisé en utilisant le nom de l'extension, bien que ce ne soit pas obligatoire.

Exemple : l'extension overlay-osc enregistre son OSC Perl comme ceci :

#:META:OSC_PERL:overlay:man overlay-osc

Hooks (Crochets)

Les sous-routines suivantes peuvent être déclarées dans les fichiers d'extension, et seront appelées chaque fois que l'événement pertinent se produit.

Le premier argument qui leur est passé est un objet d'extension tel que décrit dans la section "Objets d'extension".

**Toutes** ces hooks doivent retourner une valeur booléenne. Si l'une des hooks appelées retourne vrai, alors l'événement est considéré comme *consommé*, et l'action pertinente pourrait ne pas être effectuée par le code C++.

En cas de doute, retournez une valeur fausse (de préférence "()" - l'équivalent perl de null).

on_attach $term
Appelé lorsqu'un paquet d'extension est attaché à une instance de terminal en cours d'exécution. Doit retourner vrai dans tous les cas et s'exécute avec les mêmes limitations que "on_init".

Contrairement à "on_init" ou "on_start", ceci est appelé lorsque l'extension est attachée à un terminal, que l'extension soit chargée avant ou après le démarrage du terminal. Les extensions qui ont besoin de faire quelque chose avant de fonctionner peuvent le faire dans ce callback, par opposition à par exemple "on_init", qui pourrait ne pas être appelé.

on_init $term
Appelé après qu'un nouvel objet de terminal a été initialisé, mais avant que les fenêtres ne soient créées ou que la commande ne soit exécutée. La plupart des méthodes sont dangereuses à appeler ou fournissent des données insensées, car la taille du terminal et d'autres caractéristiques n'ont pas encore été déterminées. Vous pouvez cependant interroger et modifier en toute sécurité les ressources et les options. Pour de nombreux usages, le hook "on_start" est un meilleur endroit.
on_start $term
Appelé à la toute fin de l'initialisation d'un nouveau terminal, juste avant d'essayer de mapper (afficher) le toplevel et de retourner à la boucle principale.
on_destroy $term
Appelé chaque fois que quelque chose essaie de détruire le terminal, lorsque le terminal est encore entièrement fonctionnel (mais pas pour longtemps).
on_reset $term
Appelé après que l'écran est « réinitialisé » pour quelque raison que ce soit, telle qu'un redimensionnement ou des séquences de contrôle. C'est ici que vous pouvez réagir aux changements des variables liées à la taille.
on_child_start $term, $pid
Appelé juste après que le processus fils a été « forké ».
on_child_exit $term, $status
Appelé juste après que le processus fils est sorti. $status est le statut de "waitpid".
on_sel_make $term, $eventtime
Appelé chaque fois qu'une sélection est faite par l'utilisateur, mais avant que le texte de la sélection ne soit copié, de sorte que les modifications au début, à la fin ou au type de la sélection seront prises en compte.

Retourner une valeur vraie annule la création de la sélection par urxvt, auquel cas vous devez faire une sélection vous-même en appelant "$term->selection_grab".

on_sel_grab $term, $eventtime
Appelé chaque fois qu'une sélection est copiée, mais avant que la sélection ne soit demandée au serveur. Le texte de la sélection peut être interrogé et modifié en appelant "$term->selection".

Retourner une valeur vraie annule la capture de la sélection. Elle sera toujours mise en surbrillance.

on_sel_extend $term
Appelé chaque fois que l'utilisateur tente d'étendre la sélection (par exemple, avec un double clic) et est censé retourner faux (opération normale), ou doit étendre la sélection lui-même et retourner vrai pour supprimer le traitement intégré. Cela peut se produire plusieurs fois, tant que le callback retourne vrai, il sera appelé à chaque clic ultérieur de l'utilisateur et est censé agrandir la sélection de plus en plus, si possible.

Voir l'extension d'exemple selection.

on_view_change $term, $offset
Appelé chaque fois que l'offset de vue change, c'est-à-dire lorsque l'utilisateur ou le programme fait défiler. L'offset 0 signifie afficher le terminal normal, les valeurs positives montrent ce nombre de lignes de défilement.
on_scroll_back $term, $lines, $saved
Appelé chaque fois que des lignes défilent hors de la zone du terminal vers le tampon de défilement. $lines est le nombre de lignes sorties et peut être supérieur au tampon de défilement ou au terminal.

Il est appelé avant que les lignes ne soient sorties (donc les lignes 0 à min($lines - 1, $nrow - 1) représentent les lignes qui seront sorties). $saved est le nombre total de lignes qui seront dans le tampon de défilement.

on_osc_seq $term, $op, $args, $resp
Appelé sur chaque séquence OSC et peut être utilisé pour la supprimer ou modifier son comportement. Le comportement par défaut devrait être de retourner une liste vide. Une valeur vraie supprime complètement l'exécution de la requête. Assurez-vous de ne pas vous laisser confondre par des invocations récursives lorsque vous sortez une séquence OSC dans ce callback.

"on_osc_seq_perl" devrait être utilisé pour le nouveau comportement.

on_osc_seq_perl $term, $args, $resp
Appelé chaque fois que la séquence de commande ESC ] 777 ; préfixe ; chaîne ST (OSC = commande système d'exploitation) est traitée. La position du curseur et d'autres informations d'état sont à jour lorsque cela se produit. Pour l'interopérabilité, l'argument doit commencer par le nom de l'extension (sans -osc) ou un autre préfixe approprié, et un point-virgule, pour le distinguer des commandes destinées à d'autres extensions.

Par exemple, "overlay-osc" l'utilise :

sub on_osc_seq_perl {
   my ($self, $osc, $resp) = @_;
   return unless $osc =~ s/^overlay;//;
   ... traiter le reste de la chaîne $osc
}

Faites attention à ne jamais faire confiance (en termes de sécurité) aux données que vous recevez, car leur source ne peut pas être facilement contrôlée (contenu d'e-mail, messages d'autres utilisateurs sur le même système, etc.).

Pour les réponses, $resp contient le séparateur de fin d'arguments utilisé par l'expéditeur.

on_add_lines $term, $string
Appelé chaque fois que du texte est sur le point d'être affiché, avec le texte comme argument. Vous pouvez filtrer/modifier et afficher le texte vous-même en retournant une valeur vraie et en appelant "$term->scr_add_lines" vous-même. Veuillez noter que cela peut être très lent, car votre hook est appelé pour tout le texte affiché.
on_tt_write $term, $octets
Appelé chaque fois que des données sont écrites sur le tty/pty et peut être utilisé pour supprimer ou filtrer l'entrée tty.
on_tt_paste $term, $octets
Appelé chaque fois que du texte est sur le point d'être collé, avec le texte comme argument. Vous pouvez filtrer/modifier et coller le texte vous-même en retournant une valeur vraie et en appelant "$term->tt_paste" vous-même. $octets est encodé en locale.
on_line_update $term, $row
Appelé chaque fois qu'une ligne a été mise à jour ou modifiée. Peut être utilisé pour filtrer la sortie de l'écran (par exemple, souligner les URL ou d'autres éléments inutiles). Seules les lignes affichées seront filtrées et, pour des raisons de performance, pas toujours immédiatement.

Le numéro de ligne est toujours la ligne la plus haute si la ligne s'étend sur plusieurs lignes.

Veuillez noter que, si vous modifiez la ligne, le hook pourrait être appelé plus tard avec la ligne déjà modifiée (par exemple, si des parties non liées changent), vous ne pouvez donc pas simplement basculer les bits de rendu, mais seulement les définir.

on_refresh_begin $term
Appelé juste avant que l'écran ne soit redessiné. Peut être utilisé pour des effets de superposition ou similaires en modifiant le contenu du terminal dans refresh_begin, et en le restaurant dans refresh_end. Le code intégré de superposition et d'affichage de sélection est exécuté après ce hook, et a la priorité.
on_refresh_end $term
Appelé juste après que l'écran a été redessiné. Voir "on_refresh_begin".
on_action $term, $string
Appelé chaque fois qu'une action est invoquée pour l'extension correspondante (par exemple, via une action intégrée "extension:string" liée à une touche, voir la description de la ressource keysym dans la page de manuel urxvt(1)). L'événement est simplement la chaîne d'action. Notez qu'un événement d'action est toujours associé à une seule extension.
on_user_command $term, $string *DÉPRÉCIÉ*
Appelé chaque fois qu'un événement configuré par l'utilisateur est activé (par exemple, via une action "perl:string" liée à une touche, voir la description de la ressource keysym dans la page de manuel urxvt(1)).

L'événement est simplement la chaîne d'action. Cette interface va disparaître au profit du hook "on_action".

on_resize_all_windows $term, $new_width, $new_height
Appelé juste après que la nouvelle taille de fenêtre a été calculée, mais avant que les fenêtres ne soient réellement redimensionnées ou que les indices ne soient définis. Si ce hook retourne une valeur vraie, la définition des indices de fenêtre est ignorée.
on_x_event $term, $event
Appelé sur chaque événement X reçu sur la fenêtre vt (et potentiellement d'autres fenêtres). Ne devrait être utilisé qu'en dernier recours. La plupart des membres de la structure d'événement ne sont pas passés.
on_root_event $term, $event
Comme "on_x_event", mais appelé pour les événements sur la fenêtre racine.
on_focus_in $term
Appelé chaque fois que la fenêtre obtient le focus du clavier, avant que rxvt-unicode ne traite le focus entrant.
on_focus_out $term
Appelé chaque fois que la fenêtre perd le focus du clavier, avant que rxvt-unicode ne traite le focus sortant.
on_configure_notify $term, $event
on_property_notify $term, $event
on_key_press $term, $event, $keysym, $octets
on_key_release $term, $event, $keysym
on_button_press $term, $event
on_button_release $term, $event
on_motion_notify $term, $event
on_map_notify $term, $event
on_unmap_notify $term, $event
Appelé chaque fois que l'événement X correspondant est reçu pour le terminal. Si le hook retourne vrai, alors l'événement sera ignoré par rxvt-unicode.

L'événement est une table de hachage dont la plupart des valeurs sont nommées par Xlib (voir la page de manuel XEvent), avec les membres supplémentaires "row" et "col", qui sont la ligne et la colonne (réelles, pas basées sur l'écran) sous le curseur de la souris.

"on_key_press" reçoit en plus la chaîne que rxvt-unicode générerait, le cas échéant, dans un encodage spécifique à la locale.

on_client_message $term, $event
on_wm_protocols $term, $event
on_wm_delete_window $term, $event
Appelé lors de la réception de divers types d'événements ClientMessage (tous avec format=32, WM_PROTOCOLS ou WM_PROTOCOLS:WM_DELETE_WINDOW).
on_bell $term
Appelé à la réception d'un caractère de sonnerie.

Variables dans le package "urxvt"

$urxvt::LIBDIR
Le répertoire de la bibliothèque rxvt-unicode, où, entre autres choses, les modules et scripts perl sont stockés.
$urxvt::RESCLASS, $urxvt::RESNAME
La classe de ressource et le nom que rxvt-unicode utilise pour rechercher les ressources X.
$urxvt::RXVTNAME
Le nom de base des binaires installés, généralement "urxvt".
$urxvt::TERM
Le terminal courant. Cette variable stocke l'objet "urxvt::term" courant, chaque fois qu'un callback/hook est en cours d'exécution.
@urxvt::TERM_INIT
Toutes les références de code dans ce tableau seront appelées comme des méthodes du prochain objet "urxvt::term" nouvellement créé (pendant la phase "on_init"). Le tableau est effacé avant que les références de code qu'il contenait ne soient exécutées, de sorte que les références peuvent se pousser à nouveau si elles le souhaitent.

Ceci complète l'option de ligne de commande perl-eval, mais est exécuté en premier.

@urxvt::TERM_EXT
Fonctionne de manière similaire à @TERM_INIT, mais contient des noms de packages/classes perl, qui sont enregistrés comme extensions normales après avoir appelé les hooks dans @TERM_INIT mais avant les autres extensions. Est effacé juste comme @TERM_INIT.

Fonctions dans le package "urxvt"

urxvt::fatal $errormessage
Arrête fatalement l'exécution avec le message d'erreur donné (qui doit inclure une nouvelle ligne à la fin). À éviter à tout prix ! Le seul moment où cela est acceptable (et utile) est dans le hook d'initialisation, où cela empêche le terminal de démarrer.
urxvt::warn $string
Appelle "rxvt_warn" avec la chaîne donnée qui devrait inclure une nouvelle ligne à la fin. Le module remplace également le builtin "warn" par une fonction qui appelle cette fonction.

L'utilisation de cette fonction présente l'avantage que sa sortie se retrouve au bon endroit, par exemple sur la sortie d'erreur du client urxvtc connecté.

Les messages ont actuellement une limite de taille de 1023 octets.

@terms = urxvt::termlist
Retourne tous les objets urxvt::term qui existent dans ce processus, qu'ils soient démarrés, en cours de destruction, etc., alors soyez prudent. Seuls les objets de terminal auxquels des extensions perl sont attachées seront retournés (car il n'y a pas d'objet urxvt::term associé aux autres).
$time = urxvt::NOW
Retourne l'heure "courante" (selon la boucle d'événements).

RENDITION

Les jeux de bits de rendition contiennent des informations sur la couleur, la police, les styles de police et des informations similaires pour chaque cellule de l'écran.

Les "macros" suivantes traitent des changements dans les ensembles de rendition. Vous ne devriez jamais créer un jeu de bits directement, vous devriez toujours modifier un jeu existant, car ils contiennent des informations importantes requises pour le bon fonctionnement de rxvt-unicode.

$rend = urxvt::DEFAULT_RSTYLE
Retourne la rendition par défaut, telle qu'utilisée au démarrage ou à la réinitialisation du terminal. Utile comme base pour commencer lors de la création de renditions.
$rend = urxvt::OVERLAY_RSTYLE
Retourne le masque de rendition utilisé pour les superpositions par défaut.
$rendbit = urxvt::RS_Bold, urxvt::RS_Italic, urxvt::RS_Blink, urxvt::RS_RVid, urxvt::RS_Uline
Retourne le bit qui active respectivement le gras, l'italique, le clignotement, la vidéo inversée et le soulignement. Pour activer un tel style, il suffit de le combiner logiquement (OR) avec le jeu de bits.
$foreground = urxvt::GET_BASEFG $rend
$background = urxvt::GET_BASEBG $rend
Retourne respectivement l'indice de la couleur de premier plan/arrière-plan.
$rend = urxvt::SET_FGCOLOR $rend, $new_colour
$rend = urxvt::SET_BGCOLOR $rend, $new_colour
$rend = urxvt::SET_COLOR $rend, $new_fg, $new_bg
Remplace la couleur de premier plan/arrière-plan dans le masque de rendition par celle spécifiée.
$value = urxvt::GET_CUSTOM $rend
Retourne la valeur "personnalisée" : Chaque rendition a 5 bits à utiliser par les extensions. Ils peuvent être définis et modifiés à volonté et sont initialement à zéro.
$rend = urxvt::SET_CUSTOM $rend, $new_value
Modifie la valeur personnalisée.

La classe "urxvt::term::extension"

Chaque extension attachée à un objet terminal est représentée par un objet "urxvt::term::extension".

Vous pouvez utiliser ces objets, qui sont passés à tous les callbacks pour stocker tout état lié à l'instance du terminal et de l'extension.

Les méthodes (et membres de données) documentées ci-dessous peuvent être appelées sur les objets d'extension, en plus des méthodes appelées documentées pour la classe <urxvt::term>.

$urxvt_term = $self->{term}
Retourne l'objet "urxvt::term" associé à cette instance de l'extension. Ce membre ne doit pas être modifié de quelque manière que ce soit.
$self->enable ($hook_name => $cb[, $hook_name => $cb..])
Active dynamiquement les hooks donnés (nommés sans le préfixe "on_") pour cette extension, remplaçant tout hook précédemment installé via "enable" dans cette extension.

C'est utile lorsque vous voulez remplacer des hooks critiques en temps pour des durées limitées.

Pour installer des callbacks supplémentaires pour le même hook, vous pouvez utiliser la méthode "on" de la classe "urxvt::term".

$self->disable ($hook_name[, $hook_name..])
Désactive dynamiquement les hooks donnés.
$guard = $self->on ($hook_name => $cb[, $hook_name => $cb..])

Ces méthodes prennent en charge un préfixe supplémentaire "%" pour $action ou $pattern lorsqu'elles sont appelées sur un objet d'extension, par rapport aux méthodes "urxvt::term" du même nom - voir la description de ces méthodes dans la classe "urxvt::term" pour plus de détails.

La classe "urxvt::anyevent"

Le seul but de cette classe est de fournir une interface au module "AnyEvent" - tout module l'utilisant fonctionnera à l'intérieur d'urxvt sans programmation supplémentaire. La seule exception est que vous ne pouvez pas attendre sur des variables de condition, mais une utilisation non bloquante de condvar est acceptable.

En termes pratiques, cela signifie que vous ne pouvez pas utiliser d'API bloquantes, mais la variante non bloquante devrait fonctionner.

La classe "urxvt::term"

$term = new urxvt::term $envhashref, $rxvtname, [arg...]
Crée un nouveau terminal, très similaire à comme si vous l'aviez démarré avec la commande système "$rxvtname, arg...". $envhashref doit être une référence à une table de hachage de type %ENV qui définit l'environnement du nouveau terminal.

Croaks (et affiche probablement un message d'erreur) si la nouvelle instance n'a pas pu être créée. Retourne "undef" si la nouvelle instance n'a pas initialisé perl, et l'objet terminal sinon. Les crochets "init" et "start" seront appelés avant le retour de cet appel, et sont libres de référencer des données globales (ce qui est sans concurrence).

$term->destroy
Détruit l'objet terminal (ferme la fenêtre, libère les ressources, etc.). Veuillez noter qu'urxvt ne se terminera pas tant que des observateurs d'événements (timers, observateurs io) seront actifs.
$term->exec_async ($cmd[, @args])
Fonctionne comme la combinaison des utilitaires intégrés "fork"/"exec", qui exécute ("démarre") des programmes en arrière-plan. Cette fonction prend en charge la configuration de l'environnement utilisateur avant d'exécuter la commande (par exemple, "PATH") et devrait être préférée aux appels explicites à "exec" ou "system".

Elle définit également la variable d'environnement "URXVT_EXT_WINDOWID" avec l'ID de la fenêtre du terminal ("$self->parent"), similaire à la variable "WINDOWID" définie pour le processus lancé à l'intérieur du terminal.

Retourne le pid du sous-processus ou "undef" en cas d'erreur.

Retourne la ressource X pour le motif donné, excluant le nom du programme ou de la classe, c'est-à-dire que "$term->x_resource ("boldFont")" devrait retourner la même valeur que celle utilisée par cette instance d'rxvt-unicode. Retourne "undef" si aucune ressource avec ce motif n'existe.

Les extensions qui définissent des ressources supplémentaires doivent également appeler cette méthode pour accéder à leurs valeurs.

Ajoute un bouton cliquable au popup. $cb est appelé chaque fois qu'il est sélectionné.
$popup->add_toggle ($text, $initial_value, $cb)
Ajoute un élément à bascule/case à cocher au popup. La fonction de rappel est appelée chaque fois qu'elle est basculée, avec une valeur booléenne indiquant sa nouvelle valeur comme premier argument.
$popup->show
Affiche le popup (qui est initialement caché).

La classe "urxvt::timer"

Cette classe implémente des observateurs/événements de minuteur. Le temps est représenté comme un nombre fractionnaire de secondes depuis l'époque. Exemple :

$term->{overlay} = $term->overlay (-1, 0, 8, 1, urxvt::OVERLAY_RSTYLE, 0);
$term->{timer} = urxvt::timer
                 ->new
                 ->interval (1)
                 ->cb (sub {
                    $term->{overlay}->set (0, 0,
                       sprintf "%2d:%02d:%02d", (localtime urxvt::NOW)[2,1,0]);
                 });
$timer = new urxvt::timer
Crée un nouvel objet minuteur en état démarré. Il est programmé pour se déclencher immédiatement.
$timer = $timer->cb (sub { my ($timer) = @_; ... })
Définit la fonction de rappel à appeler lorsque le minuteur se déclenche.
$timer = $timer->set ($tstamp[, $interval])
Définit le moment de génération de l'événement à $tstamp (et spécifie éventuellement un nouvel $interval).
$timer = $timer->interval ($interval)
Par défaut (et lorsque $interval est 0), le minuteur s'arrêtera automatiquement après s'être déclenché une fois. Si $interval est non nul, le minuteur est automatiquement replanifié aux intervalles donnés.
$timer = $timer->start
Démarre le minuteur.
$timer = $timer->start ($tstamp[, $interval])
Définit le moment de déclenchement de l'événement à $tstamp et démarre le minuteur. Remplace éventuellement également l'intervalle.
$timer = $timer->after ($delay[, $interval])
Comme "start", mais définit le minuteur d'expiration à c<urxvt::NOW + $delay>.
$timer = $timer->stop
Arrête le minuteur.

La classe "urxvt::iow"

Cette classe implémente des observateurs d'E/S/événements. Exemple :

$term->{socket} = ...
$term->{iow} = urxvt::iow
               ->new
               ->fd (fileno $term->{socket})
               ->events (urxvt::EV_READ)
               ->start
               ->cb (sub {
                 my ($iow, $revents) = @_;
                 # $revents doit être 1 ici, pas besoin de vérifier
                 sysread $term->{socket}, my $buf, 8192
                    or end-of-file;
               });
$iow = new urxvt::iow
Crée un nouvel objet observateur d'E/S en état arrêté.
$iow = $iow->cb (sub { my ($iow, $reventmask) = @_; ... })
Définit la fonction de rappel à appeler lorsque des événements d'E/S sont déclenchés. $reventmask est un tableau de bits tel que décrit dans la méthode "events".
$iow = $iow->fd ($fd)
Définit le descripteur de fichier (pas le handle) à observer.
$iow = $iow->events ($eventmask)
Définit le masque d'événements à observer. Les seules valeurs autorisées sont "urxvt::EV_READ" et "urxvt::EV_WRITE", qui peuvent être combinées par un OU bit à bit, ou "urxvt::EV_NONE".
$iow = $iow->start
Commence à observer les événements demandés sur le handle donné.
$iow = $iow->stop
Arrête d'observer les événements sur le handle de fichier donné.

La classe "urxvt::iw"

Cette classe implémente des observateurs d'inactivité, qui sont appelés automatiquement lorsque le processus est inactif. Ils doivent retourner aussi rapidement que possible, après avoir effectué un travail utile.

$iw = new urxvt::iw
Crée un nouvel objet observateur d'inactivité en état arrêté.
$iw = $iw->cb (sub { my ($iw) = @_; ... })
Définit la fonction de rappel à appeler lorsque l'observateur se déclenche.
$timer = $timer->start
Démarre l'observateur.
$timer = $timer->stop
Arrête l'observateur.

La classe "urxvt::pw"

Cette classe implémente des surveillants de processus. Ils créent un événement chaque fois qu'un processus se termine, après quoi ils s'arrêtent automatiquement.

mon $pid = fork;
...
$term->{pw} = urxvt::pw
                 ->nouveau
                 ->démarre ($pid)
                 ->cb (sous {
                    mon ($pw, $exit_status) = @_;
                    ...
                 });
$pw = nouveau urxvt::pw
Crée un nouveau surveillant de processus dans un état arrêté.
$pw = $pw->cb (sous { mon ($pw, $exit_status) = @_; ... })
Définit la fonction de rappel à appeler lorsque le minuteur se déclenche.
$pw = $timer->démarre ($pid)
Indique au surveillant de commencer à surveiller le processus $pid.
$pw = $pw->arrête
Arrête le surveillant.

ENVIRONNEMENT

URXVT_PERL_VERBOSITY

Cette variable contrôle le niveau de verbosité de l'extension perl. Des nombres plus élevés indiquent une sortie plus détaillée.

== 0 - messages fatals uniquement
>= 2 - avertissements généraux (niveau par défaut)
>= 3 - chargement et gestion des scripts
>=10 - tous les hooks appelés
>=11 - valeurs de retour des hooks
