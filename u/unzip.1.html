NOM

unzip - lister, tester et extraire des fichiers compressés dans une archive ZIP

SYNTAXE

unzip [-Z] [-cflptTuvz[abjnoqsCDKLMUVWX$/:^]] fichier[.zip] [fichier(s) ...] [-x fichiers_exclus ...] [-d rép_extractions]

DESCRIPTION

unzip listera, testera ou extraira des fichiers d'une archive ZIP, couramment trouvée sur les systèmes MS-DOS. Le comportement par défaut (sans options) est d'extraire dans le répertoire courant (et les sous-répertoires en dessous) tous les fichiers de l'archive ZIP spécifiée. Un programme compagnon, zip(1L), crée des archives ZIP ; les deux programmes sont compatibles avec les archives créées par PKZIP et PKUNZIP de PKWARE pour MS-DOS, mais dans de nombreux cas, les options du programme ou les comportements par défaut diffèrent.

ARGUMENTS

fichier[.zip]
Chemin d'accès de l'archive ZIP ou des archives. Si la spécification de fichier est un caractère générique, chaque fichier correspondant est traité dans un ordre déterminé par le système d'exploitation (ou le système de fichiers). Seul le nom de fichier peut être un caractère générique ; le chemin lui-même ne le peut pas. Les expressions de caractères génériques sont similaires à celles prises en charge dans les shells Unix couramment utilisés (sh, ksh, csh) et peuvent contenir :
*
correspond à une séquence de 0 ou plusieurs caractères
?
correspond à exactement 1 caractère
[...]
correspond à n'importe quel caractère unique trouvé entre crochets ; les plages sont spécifiées par un caractère de début, un trait d'union et un caractère de fin. Si un point d'exclamation ou un accent circonflexe (`!' ou `^') suit la parenthèse gauche, alors la plage de caractères entre parenthèses est inversée (c'est-à-dire que tout sauf les caractères entre parenthèses est considéré comme une correspondance). Pour spécifier une parenthèse gauche littérale, la séquence de trois caractères ``[[]'' doit être utilisée.
(Assurez-vous de mettre entre guillemets tout caractère qui pourrait autrement être interprété ou modifié par le système d'exploitation, en particulier sous Unix et VMS.) Si aucune correspondance n'est trouvée, la spécification est supposée être un nom de fichier littéral ; et si cela échoue également, le suffixe .zip est ajouté. Notez que les fichiers ZIP auto-extractibles sont pris en charge, comme toute autre archive ZIP ; spécifiez simplement le suffixe .exe (le cas échéant) explicitement.
[fichier(s)]
Une liste facultative de membres de l'archive à traiter, séparés par des espaces. (Les versions VMS compilées avec VMSCLI défini doivent délimiter les fichiers par des virgules à la place. Voir -v dans OPTIONS ci-dessous.) Des expressions régulières (caractères génériques) peuvent être utilisées pour faire correspondre plusieurs membres ; voir ci-dessus. Encore une fois, assurez-vous de mettre entre guillemets les expressions qui seraient autrement développées ou modifiées par le système d'exploitation.
[-x fichiers_exclus]
Une liste facultative de membres de l'archive à exclure du traitement. Comme les caractères génériques correspondent normalement aux séparateurs de répertoire (`/') (pour les exceptions voir l'option -W), cette option peut être utilisée pour exclure tous les fichiers qui se trouvent dans des sous-répertoires. Par exemple, ``unzip foo *.[ch] -x */*'' extrairait tous les fichiers source C dans le répertoire principal, mais aucun dans aucun sous-répertoire. Sans l'option -x, tous les fichiers source C dans tous les répertoires à l'intérieur du zipfile seraient extraits.
[-d rép_extractions]
Un répertoire facultatif vers lequel extraire les fichiers. Par défaut, tous les fichiers et sous-répertoires sont recréés dans le répertoire courant ; l'option -d permet l'extraction dans un répertoire arbitraire (en supposant toujours que l'on a la permission d'écrire dans le répertoire). Cette option n'a pas besoin d'apparaître à la fin de la ligne de commande ; elle est également acceptée avant la spécification du zipfile (avec les options normales), immédiatement après la spécification du zipfile, ou entre les fichiers et l'option -x. L'option et le répertoire peuvent être concaténés sans espace blanc entre eux, mais notez que cela peut supprimer le comportement normal du shell. En particulier, ``-d ~'' est développé par les shells C Unix en le nom du répertoire personnel de l'utilisateur, mais ``-d~'' est traité comme un sous-répertoire littéral ``~'' du répertoire courant.

OPTIONS

Notez qu'afin de prendre en charge le matériel obsolète, l'écran d'utilisation d'unzip(1L) est limité à 22 ou 23 lignes et doit donc être considéré uniquement comme un rappel de la syntaxe de base d'unzip(1L) plutôt qu'une liste exhaustive de tous les indicateurs possibles. La liste exhaustive suit :

-Z
Mode zipinfo(1L). Si la première option sur la ligne de commande est -Z, les options restantes sont considérées comme des options de zipinfo(1L). Voir la page de manuel appropriée pour une description de ces options.
-A
[OS/2, Unix DLL] affiche l'aide étendue pour l'interface de programmation (API) de la DLL.
-c
extrait les fichiers vers stdout/écran (``CRT''). Cette option est similaire à l'option -p sauf que le nom de chaque fichier est imprimé lors de son extraction, l'option -a est autorisée, et la conversion ASCII-EBCDIC est effectuée automatiquement si approprié. Cette option n'est pas listée dans l'écran d'utilisation d'unzip(1L).
-f
actualise les fichiers existants, c'est-à-dire extrait uniquement les fichiers qui existent déjà sur le disque et qui sont plus récents que les copies sur disque. Par défaut, unzip demande avant d'écraser, mais l'option -o peut être utilisée pour supprimer les requêtes. Notez que sous de nombreux systèmes d'exploitation, la variable d'environnement TZ (fuseau horaire) doit être correctement définie pour que -f et -u fonctionnent correctement (sous Unix, la variable est généralement définie automatiquement). Les raisons en sont quelque peu subtiles mais liées aux différences entre les heures de fichiers au format DOS (toujours heure locale) et les heures au format Unix (toujours en GMT/UTC) et à la nécessité de comparer les deux. Une valeur TZ typique est ``PST8PDT'' (heure du Pacifique US avec ajustement automatique pour l'heure d'été ou l'heure d'été).
-l
liste les fichiers de l'archive (format court). Les noms, les tailles non compressées et les dates et heures de modification des fichiers spécifiés sont imprimés, ainsi que les totaux pour tous les fichiers spécifiés. Si UnZip a été compilé avec OS2_EAS défini, l'option -l liste également les colonnes pour les tailles des attributs étendus OS/2 (EA) et des listes de contrôle d'accès OS/2 (ACL) stockés. De plus, le commentaire du zipfile et les commentaires de fichiers individuels (le cas échéant) sont affichés. Si un fichier a été archivé à partir d'un système de fichiers à casse unique (par exemple, l'ancien système de fichiers FAT MS-DOS) et que l'option -L a été donnée, le nom de fichier est converti en minuscules et précédé d'un accent circonflexe (^).
-p
extrait les fichiers vers un tube (stdout). Rien d'autre que les données du fichier n'est envoyé à stdout, et les fichiers sont toujours extraits en format binaire, tels qu'ils sont stockés (aucune conversion).
-t
teste les fichiers de l'archive. Cette option extrait chaque fichier spécifié en mémoire et compare le CRC (contrôle de redondance cyclique, une somme de contrôle améliorée) du fichier développé avec la valeur CRC stockée du fichier d'origine.
-T
[la plupart des OS] définit l'horodatage sur l'archive ou les archives à celui du fichier le plus récent dans chacune d'elles. Ceci correspond à l'option -go de zip, sauf qu'elle peut être utilisée sur des zipfiles génériques (par exemple, ``unzip -T \*.zip'') et est beaucoup plus rapide.
-u
met à jour les fichiers existants et crée de nouveaux fichiers si nécessaire. Cette option effectue la même fonction que l'option -f, en extrayant (avec requête) les fichiers qui sont plus récents que ceux portant le même nom sur le disque, et en plus, elle extrait les fichiers qui n'existent pas encore sur le disque. Voir -f ci-dessus pour des informations sur la définition correcte du fuseau horaire.
-v
liste les fichiers de l'archive (format détaillé) ou affiche les informations de version de diagnostic. Cette option a évolué et se comporte maintenant à la fois comme une option et un modificateur. En tant qu'option, elle a deux objectifs : lorsqu'un zipfile est spécifié sans autre option, -v liste les fichiers de l'archive de manière détaillée, ajoutant aux informations de base de -l la méthode de compression, la taille compressée, le taux de compression et le CRC 32 bits. MODIFICATEURS

-a
convertit les fichiers texte. Normalement, tous les fichiers sont extraits exactement tels qu'ils sont stockés (comme des fichiers ``binaires''). L'option -a fait que les fichiers identifiés par `zip` comme fichiers texte (ceux avec le label `t` dans les listes `zipinfo`, plutôt que `b`) soient automatiquement extraits comme tels, en convertissant les fins de ligne, les caractères de fin de fichier et le jeu de caractères lui-même si nécessaire. (Par exemple, les fichiers Unix utilisent des sauts de ligne (LF) pour la fin de ligne (EOL) et n'ont pas de marqueur de fin de fichier (EOF) ; les Macintosh utilisent des retours chariot (CR) pour les EOL ; et la plupart des systèmes d'exploitation PC utilisent CR+LF pour les EOL et le contrôle-Z pour EOF. De plus, les mainframes IBM et le Michigan Terminal System utilisent EBCDIC plutôt que le jeu de caractères ASCII plus courant, et NT prend en charge Unicode.) Notez que l'identification des fichiers texte par `zip` n'est en aucun cas parfaite ; certains fichiers ``texte'' peuvent en réalité être binaires et vice versa. `unzip` affiche donc ``[texte]'' ou ``[binaire]'' comme vérification visuelle pour chaque fichier qu'il extrait lors de l'utilisation de l'option -a. L'option -aa force l'extraction de tous les fichiers en tant que texte, indépendamment du type de fichier supposé. Sur VMS, voir aussi -S.
-b
[général] traite tous les fichiers comme binaires (pas de conversions de texte). Ceci est un raccourci pour ---a.
-b
[Tandem] force la création de fichiers avec le type de code fichier 180 ('C') lors de l'extraction d'entrées Zip marquées comme "texte". (Sur Tandem, -a est activé par défaut, voir ci-dessus).
-b
[VMS] convertit automatiquement les fichiers binaires (voir -a ci-dessus) en format d'enregistrement à longueur fixe de 512 octets. Doubler l'option (-bb) force l'extraction de tous les fichiers dans ce format. Lors de l'extraction vers la sortie standard (option -c ou -p en vigueur), la conversion par défaut des délimiteurs d'enregistrement texte est désactivée pour les fichiers binaires (-b) respectivement tous (-bb) les fichiers.
-B
[lorsque compilé avec UNIXBACKUP défini] sauvegarde une copie de sauvegarde de chaque fichier écrasé. Le fichier de sauvegarde reçoit le nom du fichier cible avec une tilde et éventuellement une séquence numérique unique (jusqu'à 5 chiffres) ajoutée. La séquence numérique est appliquée chaque fois qu'un autre fichier avec le nom d'origine plus la tilde existe déjà. Lorsqu'elle est utilisée conjointement avec l'option "tout écraser" -o, les fichiers de sauvegarde numérotés ne sont jamais créés. Dans ce cas, tous les fichiers de sauvegarde sont nommés comme le fichier d'origine avec une tilde ajoutée, les fichiers de sauvegarde existants sont supprimés sans préavis. Cette fonctionnalité fonctionne de manière similaire au comportement par défaut de emacs(1) dans de nombreux endroits.
Exemple : l'ancienne copie de ``foo'' est renommée en ``foo~''.
Avertissement : les utilisateurs doivent être conscients que l'option -B n'empêche pas la perte de données existantes dans toutes les circonstances. Par exemple, lorsque `unzip` est exécuté en mode "tout écraser", un fichier ``foo~'' existant est supprimé avant que `unzip` ne tente de renommer ``foo'' en ``foo~''. Lorsque cette tentative de renommage échoue (en raison d'un verrouillage de fichier, de privilèges insuffisants, ou ...), l'extraction de ``foo~'' est annulée, mais le fichier de sauvegarde existant est déjà perdu. Un scénario similaire se produit lorsque la plage de numéros de séquence pour les fichiers de sauvegarde numérotés est épuisée (99999, ou 65535 pour les systèmes 16 bits). Dans ce cas, le fichier de sauvegarde avec le numéro de séquence maximum est supprimé et remplacé par la nouvelle version de sauvegarde sans préavis.
-C
utilise une correspondance insensible à la casse pour la sélection des entrées d'archive à partir de la liste des modèles de sélection d'extraction en ligne de commande. La philosophie d'`unzip` est "vous obtenez ce que vous demandez" (ce qui est également responsable du changement -L/-U ; voir les options pertinentes ci-dessous). Comme certains systèmes de fichiers sont entièrement sensibles à la casse (notamment ceux sous le système d'exploitation Unix) et que les archives ZIP et `unzip` lui-même sont portables sur différentes plateformes, le comportement par défaut d'`unzip` est de faire correspondre les noms de fichiers littéraux et les caractères génériques de manière sensible à la casse. C'est-à-dire, spécifier ``makefile'' en ligne de commande correspondra *uniquement* à ``makefile'' dans l'archive, pas à ``Makefile'' ou ``MAKEFILE'' (et de même pour les spécifications de caractères génériques). Comme cela ne correspond pas au comportement de nombreux autres systèmes d'exploitation/fichiers (par exemple, OS/2 HPFS, qui préserve la casse mixte mais n'y est pas sensible), l'option -C peut être utilisée pour forcer toutes les correspondances de noms de fichiers à être insensibles à la casse. Dans l'exemple ci-dessus, les trois fichiers correspondraient alors à ``makefile'' (ou ``make*'', ou similaire). L'option -C affecte les spécifications de fichiers dans la liste normale des fichiers et dans la liste des fichiers exclus (xlist).
Veuillez noter que l'option -C n'affecte ni la recherche des fichiers zip ni la correspondance des entrées d'archive avec les fichiers existants sur le chemin d'extraction. Sur un système de fichiers sensible à la casse, `unzip` n'essaiera jamais d'écraser un fichier ``FOO'' lors de l'extraction d'une entrée ``foo'' !
-D
ignore la restauration des horodatages pour les éléments extraits. Normalement, `unzip` essaie de restaurer toutes les métadonnées pour les éléments extraits qui sont fournis dans l'archive Zip (et ne nécessitent pas de privilèges ou n'imposent pas de risque de sécurité). En spécifiant -D, `unzip` est informé de supprimer la restauration des horodatages pour les répertoires explicitement créés à partir des entrées de l'archive Zip. Cette option ne s'applique qu'aux ports qui prennent en charge la définition des horodatages pour les répertoires (actuellement ATheOS, BeOS, MacOS, OS/2, Unix, VMS, Win32, pour les autres ports `unzip`, -D n'a aucun effet). L'option dupliquée -DD force la suppression de la restauration des horodatages pour toutes les entrées extraites (fichiers et répertoires). Cette option entraîne la définition des horodatages pour toutes les entrées extraites à l'heure actuelle.
Sur VMS, le réglage par défaut pour cette option est -D pour la cohérence avec le comportement de BACKUP : les horodatages des fichiers sont restaurés, les horodatages des répertoires extraits sont laissés à l'heure actuelle. Pour activer la restauration des horodatages de répertoire, l'option niée --D doit être spécifiée. Sur VMS, l'option -D désactive la restauration des horodatages pour tous les éléments de l'archive Zip extraits. (Ici, un seul -D sur la ligne de commande se combine avec le -D par défaut pour faire ce que fait un -DD explicite sur d'autres systèmes.)
-E
[MacOS uniquement] affiche le contenu du champ supplémentaire MacOS pendant l'opération de restauration.
-F
[Acorn uniquement] supprime la suppression de l'extension de type de fichier NFS des noms de fichiers stockés.
-F
[systèmes non-Acorn prenant en charge les noms de fichiers longs avec des virgules intégrées, et seulement si compilé avec ACORN_FTYPE_NFS défini] traduit les informations de type de fichier des blocs de champ supplémentaire ACORN RISC OS et les ajoute aux noms des fichiers extraits. (Lorsque le nom de fichier stocké semble déjà avoir une extension de type de fichier NFS ajoutée, elle est remplacée par les informations du champ supplémentaire.)
-i
[MacOS uniquement] ignore les noms de fichiers stockés dans les champs supplémentaires MacOS. À la place, le nom de fichier le plus compatible stocké dans la partie générique de l'en-tête de l'entrée est utilisé.
-j
supprime les chemins. La structure de répertoire de l'archive n'est pas recréée ; tous les fichiers sont déposés dans le répertoire d'extraction (par défaut, le répertoire courant).
-J
[BeOS uniquement] supprime les attributs de fichier. Les attributs de fichier BeOS du fichier ne sont pas restaurés, seulement les données du fichier.
-J
[MacOS uniquement] ignore les champs supplémentaires MacOS. Toutes les informations spécifiques à Macintosh sont ignorées. Les fourches de données et de ressources sont restaurées en tant que fichiers séparés.
-K
[AtheOS, BeOS, Unix uniquement] conserve les attributs de fichier SUID/SGID/Tacky. Sans ce drapeau, ces bits d'attributs sont effacés pour des raisons de sécurité.
-L
convertit en minuscules tout nom de fichier provenant d'un système d'exploitation ou d'un système de fichiers uniquement en majuscules. (C'était le comportement par défaut d'`unzip` dans les versions antérieures à 5.11 ; le nouveau comportement par défaut est identique à l'ancien comportement avec l'option -U, qui est maintenant obsolète et sera supprimée dans une future version.) Selon l'archiveur, les fichiers archivés sous des systèmes de fichiers à casse unique (VMS, anciens MS-DOS FAT, etc.) peuvent être stockés sous forme de noms tout en majuscules ; cela peut être laid ou gênant lors de l'extraction vers un système de fichiers préservant la casse comme OS/2 HPFS ou un système sensible à la casse comme sous Unix. Par défaut, `unzip` liste et extrait ces noms de fichiers exactement tels qu'ils sont stockés (à l'exception de la troncature, de la conversion des caractères non pris en charge, etc.) ; cette option force la conversion en minuscules des noms de tous les fichiers provenant de certains systèmes. L'option -LL force la conversion de tous les noms de fichiers en minuscules, quel que soit le système d'exploitation d'origine.
-M
redirige toute la sortie via un afficheur interne similaire à la commande Unix more(1). À la fin d'un écran de sortie, unzip s'arrête avec l'invite ``--More--'' ; l'écran suivant peut être affiché en appuyant sur la touche Entrée (Retour) ou la barre d'espace. unzip peut être terminé en appuyant sur la touche ``q'' et, sur certains systèmes, sur la touche Entrée/Retour. Contrairement à more(1) d'Unix, il n'y a pas de fonction de recherche avant ni de capacité d'édition. De plus, unzip ne remarque pas si les longues lignes passent le bord de l'écran, ce qui entraîne effectivement l'impression de deux lignes ou plus et la probabilité que certains textes défilent hors du haut de l'écran avant d'être vus. Sur certains systèmes, le nombre de lignes disponibles sur l'écran n'est pas détecté, auquel cas unzip suppose que la hauteur est de 24 lignes.
-n
ne jamais écraser les fichiers existants. Si un fichier existe déjà, ignorer l'extraction de ce fichier sans demander. Par défaut, unzip demande avant d'extraire tout fichier existant ; l'utilisateur peut choisir d'écraser uniquement le fichier actuel, d'écraser tous les fichiers, d'ignorer l'extraction du fichier actuel, d'ignorer l'extraction de tous les fichiers existants, ou de renommer le fichier actuel.
-N
[Amiga] extrait les commentaires de fichiers sous forme de notes de fichier Amiga. Les commentaires de fichiers sont créés avec l'option -c de zip(1L), ou avec l'option -N du port Amiga de zip(1L), qui stocke les notes de fichier comme commentaires.
-o
écrase les fichiers existants sans demander. C'est une option dangereuse, alors utilisez-la avec précaution. (Elle est souvent utilisée avec -f, cependant, et c'est la seule façon d'écraser les EAs de répertoire sous OS/2.)
-P motdepasse
utilise le motdepasse pour décrypter les entrées de fichier zip cryptées (le cas échéant). C'EST NON SÉCURISÉ ! De nombreux systèmes d'exploitation multi-utilisateurs permettent à n'importe quel utilisateur de voir la ligne de commande actuelle de tout autre utilisateur ; même sur des systèmes autonomes, il existe toujours la menace d'être observé par-dessus l'épaule. Stocker le mot de passe en texte clair dans le cadre d'une ligne de commande dans un script automatisé est encore pire. Dans la mesure du possible, utilisez l'invite interactive sans écho pour entrer les mots de passe. (Et lorsque la sécurité est vraiment importante, utilisez un chiffrement fort tel que Pretty Good Privacy au lieu du chiffrement relativement faible fourni par les utilitaires zipfile standard.)
-q
effectue les opérations silencieusement (-qq = encore plus silencieux). Normalement unzip affiche les noms des fichiers qu'il extrait ou teste, les méthodes d'extraction, les commentaires de fichiers ou de zip qui peuvent être stockés dans l'archive, et éventuellement un résumé une fois terminé avec chaque archive. Les options -q[q] suppriment l'affichage de certains ou de tous ces messages.
-s
[OS/2, NT, MS-DOS] convertit les espaces dans les noms de fichiers en underscores. Comme tous les systèmes d'exploitation PC autorisent les espaces dans les noms de fichiers, unzip par défaut extrait les noms de fichiers avec des espaces intacts (par exemple, ``EA DATA. SF''). Cela peut cependant être gênant, car MS-DOS en particulier ne gère pas bien les espaces dans les noms de fichiers. La conversion des espaces en underscores peut dans certains cas éliminer la gêne.
-S
[VMS] convertit les fichiers texte (-a, -aa) au format d'enregistrement Stream_LF au lieu du format d'enregistrement à longueur variable par défaut pour les fichiers texte. (Stream_LF est le format d'enregistrement par défaut de unzip sous VMS. Il est appliqué sauf si une conversion (-a, -aa et/ou -b, -bb) est demandée ou si une entrée spécifique à VMS est traitée.)
-U
[UNICODE_SUPPORT uniquement] modifie ou désactive la gestion de UTF-8. Lorsque UNICODE_SUPPORT est disponible, l'option -U force unzip à échapper tous les caractères non-ASCII des noms de fichiers codés UTF-8 en tant que ``#Uxxxx'' (pour les caractères UCS-2, ou ``#Lxxxxxx'' pour les points de code Unicode nécessitant 3 octets). Cette option est principalement fournie à des fins de débogage lorsque le support UTF-8, relativement nouveau, est suspecté de corrompre les noms de fichiers extraits.
L'option -UU permet de désactiver entièrement la reconnaissance des noms de fichiers codés UTF-8. La gestion des codages de noms de fichiers dans unzip revient au comportement des versions précédentes.
[utilisation ancienne et obsolète] laisse les noms de fichiers en majuscules s'ils ont été créés sous MS-DOS, VMS, etc. Voir -L ci-dessus.
-V
conserve les numéros de version de fichiers (VMS). Les fichiers VMS peuvent être stockés avec un numéro de version, au format fichier.ext;##. Par défaut, les numéros de version ``;##'' sont supprimés, mais cette option permet de les conserver. (Sur les systèmes de fichiers qui limitent les noms de fichiers à des longueurs particulièrement courtes, les numéros de version peuvent être tronqués ou supprimés indépendamment de cette option.)
-W
[uniquement lorsque l'option de compilation WILD_STOP_AT_DIR est activée] modifie la routine de correspondance de motifs de manière à ce que ni `?' (caractère joker d'un seul caractère) ni `*' (caractère joker de plusieurs caractères) ne correspondent au séparateur de répertoire `/'. (La séquence de deux caractères ``**'' agit comme un caractère joker de plusieurs caractères qui inclut le séparateur de répertoire dans les caractères correspondants.) Exemples :
    "*.c" correspond à "foo.c" mais pas à "mydir/foo.c"
    "**.c" correspond à la fois à "foo.c" et à "mydir/foo.c"
    "*/*.c" correspond à "bar/foo.c" mais pas à "baz/bar/foo.c"
    "??*/*" correspond à "ab/foo" et "abc/foo"
            mais pas à "a/foo" ou "a/b/foo"
Ce comportement modifié est équivalent au style de correspondance de motifs utilisé par les shells de certains des systèmes d'exploitation cibles pris en charge par UnZip (un exemple est Acorn RISC OS). Cette option peut ne pas être disponible sur les systèmes où le caractère séparateur de répertoire `/' de l'archive Zip est autorisé comme caractère régulier dans les noms de fichiers du système d'exploitation natif. (Actuellement, UnZip utilise les mêmes règles de correspondance de motifs pour les spécifications de fichiers zip génériques et les motifs de sélection d'entrées zip dans la plupart des ports. Pour les systèmes autorisant `/' comme caractère de nom de fichier régulier, l'option -W ne fonctionnerait pas comme prévu sur une spécification de fichier zip générique.)
-X
[VMS, Unix, OS/2, NT, Tandem] restaure les informations de propriétaire/protection (UICs et entrées ACL) sous VMS, ou les informations d'utilisateur et de groupe (UID/GID) sous Unix, ou les listes de contrôle d'accès (ACLs) sous certaines versions réseau d'OS/2 (Warp Server avec IBM LAN Server/Requester 3.0 à 5.0 ; Warp Connect avec IBM Peer 1.0), ou les ACLs de sécurité sous Windows NT. Dans la plupart des cas, cela nécessitera des privilèges système spéciaux, et doubler l'option (-XX) sous NT indique à unzip d'utiliser les privilèges pour l'extraction ; mais sous Unix, par exemple, un utilisateur appartenant à plusieurs groupes peut restaurer des fichiers appartenant à n'importe lequel de ces groupes, tant que les identifiants d'utilisateur correspondent aux siens. Notez que les attributs de fichier ordinaires sont toujours restaurés ; cette option ne s'applique qu'aux informations de propriété optionnelles et supplémentaires disponibles sur certains systèmes d'exploitation. [Les listes de contrôle d'accès de NT ne semblent pas être particulièrement compatibles avec celles d'OS/2, donc aucune tentative n'est faite pour la portabilité interplateforme des privilèges d'accès. Il n'est pas clair dans quelles conditions cela pourrait jamais être utile.]
-Y
[VMS] traite les terminaisons de noms de fichiers archivés de type ``.nnn'' (où ``nnn'' est un nombre décimal) comme s'il s'agissait de numéros de version VMS (``;nnn''). (Par défaut, ils sont traités comme des types de fichiers.) Exemple : 
     "a.b.3" -> "a.b;3".
-$
[MS-DOS, OS/2, NT] restaure le libellé du volume si le support d'extraction est amovible (par exemple, une disquette). Doubler l'option (-$$) permet également de libeller les supports fixes (disques durs). Par défaut, les libellés de volume sont ignorés.
-/ extensions
[Acorn uniquement] remplace la liste des extensions fournie par la variable d'environnement Unzip$Ext. Lors de l'extraction, les extensions de noms de fichiers qui correspondent à l'un des éléments de cette liste d'extensions sont échangées devant le nom de base du fichier extrait.
-:
[tous sauf Acorn, VM/CMS, MVS, Tandem] permet d'extraire les membres de l'archive dans des emplacements en dehors du « dossier racine d'extraction » actuel. Pour des raisons de sécurité, unzip supprime normalement les composants de chemin « répertoire parent » (``../'') des noms de fichiers extraits. Cette fonction de sécurité (nouvelle depuis la version 5.50) empêche unzip d'écrire accidentellement des fichiers dans des zones « sensibles » en dehors de l'arborescence de dossiers active. L'option -: permet à unzip de revenir à son comportement précédent, plus libéral, pour permettre l'extraction exacte d'archives (plus anciennes) qui utilisaient des composants ``../'' pour créer plusieurs arborescences de répertoires au niveau du dossier d'extraction actuel. Cette option ne permet pas d'écrire explicitement dans le répertoire racine (``/''). Pour y parvenir, il est nécessaire de définir le dossier cible d'extraction sur la racine (par exemple, -d / ). Cependant, lorsque l'option -: est spécifiée, il est toujours possible d'écrire implicitement dans le répertoire racine en spécifiant suffisamment de composants de chemin ``../'' dans l'archive zip. Utilisez cette option avec une extrême prudence.
-^
[Unix uniquement] autorise les caractères de contrôle dans les noms des entrées d'archive ZIP extraites. Sous Unix, un nom de fichier peut contenir n'importe quel code de caractère (8 bits) à l'exception de '/' (délimiteur de répertoire) et de NUL (0x00, indicateur de fin de chaîne C), à moins que le système de fichiers spécifique n'ait des conventions plus restrictives. Généralement, cela permet d'intégrer des caractères de contrôle ASCII (ou même des séquences de contrôle sophistiquées) dans les noms de fichiers, au moins sur les systèmes de fichiers Unix « natifs ». Cependant, il peut être très suspect d'utiliser cette « fonctionnalité » Unix. Les caractères de contrôle intégrés dans les noms de fichiers peuvent avoir des effets secondaires désagréables lorsqu'ils sont affichés à l'écran par certains codes d'affichage sans filtrage suffisant. Et, pour les utilisateurs ordinaires, il peut être difficile de gérer de tels noms de fichiers (par exemple, lorsqu'on essaie de les spécifier pour des opérations d'ouverture, de copie, de déplacement ou de suppression). Par conséquent, unzip applique par défaut un filtre qui supprime les caractères de contrôle potentiellement dangereux des noms de fichiers extraits. L'option -^ permet de remplacer ce filtre dans le cas rare où les caractères de contrôle intégrés aux noms de fichiers doivent être intentionnellement restaurés.
-2
[VMS] force inconditionnellement la conversion des noms de fichiers en noms compatibles ODS2. Par défaut, il exploite le système de fichiers de destination,
préservation de la casse et des caractères de noms de fichiers étendus sur un système de fichiers de destination ODS5 ; et application du filtrage des noms de fichiers de compatibilité ODS2 sur un système de fichiers de destination ODS2.

OPTIONS D'ENVIRONNEMENT

Le comportement par défaut de unzip peut être modifié via des options placées dans une variable d'environnement. Cela peut être fait avec n'importe quelle option, mais c'est probablement le plus utile avec les modificateurs -a, -L, -C, -q, -o ou -n : faire que unzip convertisse automatiquement les fichiers texte par défaut, qu'il convertisse les noms de fichiers des systèmes en majuscules vers minuscules, qu'il corresponde aux noms sans tenir compte de la casse, qu'il soit plus silencieux, ou qu'il écrase toujours ou n'écrase jamais les fichiers lorsqu'il les extrait. Par exemple, pour rendre unzip aussi silencieux que possible, ne signalant que les erreurs, on utiliserait l'une des commandes suivantes :


Shell Bourne Unix :
UNZIP=-qq; export UNZIP

Shell C Unix :
setenv UNZIP -qq

OS/2 ou MS-DOS :
set UNZIP=-qq

VMS (guillemets pour minuscules) :
define UNZIP_OPTS "-qq"

Les options d'environnement sont, en fait, considérées comme toutes les autres options de ligne de commande, sauf qu'elles sont effectivement les premières options sur la ligne de commande. Pour outrepasser une option d'environnement, on peut utiliser l'opérateur « moins » pour la supprimer. Par exemple, pour outrepasser l'un des indicateurs de silence dans l'exemple ci-dessus, utilisez la commande

unzip --q[autres options] fichier.zip

Le premier tiret est le caractère de commutateur normal, et le second est un signe moins, agissant sur l'option q. Ainsi, l'effet ici est d'annuler un quantum de silence. Pour annuler les deux indicateurs de silence, on peut utiliser deux tirets (ou plus) :

unzip -t--q fichier.zip
unzip ---qt fichier.zip

(les deux sont équivalents). Cela peut sembler maladroit ou confus, mais c'est raisonnablement intuitif : ignorez simplement le premier tiret et continuez à partir de là. C'est aussi cohérent avec le comportement de nice(1) sous Unix.

Comme suggéré par les exemples ci-dessus, les noms de variables par défaut sont UNZIP_OPTS pour VMS (où le symbole utilisé pour installer unzip en tant que commande étrangère serait autrement confondu avec la variable d'environnement), et UNZIP pour tous les autres systèmes d'exploitation. Pour la compatibilité avec zip(1L), UNZIPOPT est également accepté (ne demandez pas). Si UNZIP et UNZIPOPT sont tous deux définis, cependant, UNZIP a la priorité. L'option de diagnostic d'unzip (-v sans nom de fichier zip) peut être utilisée pour vérifier les valeurs des quatre variables d'environnement possibles pour unzip et zipinfo.

La variable de fuseau horaire (TZ) doit être définie selon le fuseau horaire local afin que -f et -u fonctionnent correctement. Voir la description de -f ci-dessus pour les détails. Cette variable peut également être nécessaire pour que les horodatages des fichiers extraits soient correctement définis. Le port WIN32 (Win9x/ME/NT4/2K/XP/2K3) d'unzip obtient la configuration du fuseau horaire du registre, en supposant qu'elle est correctement définie dans le Panneau de configuration. La variable TZ est ignorée pour ce port.

DÉCRYPTION

Les archives chiffrées sont entièrement prises en charge par le logiciel Info-ZIP, mais en raison des restrictions d'exportation des États-Unis, la prise en charge de la dé-/chiffrement pourrait être désactivée dans votre binaire compilé. Cependant, depuis le printemps 2000, les restrictions d'exportation américaines ont été assouplies, et nos archives sources incluent maintenant un code de chiffrement complet. Si vous avez besoin de distributions binaires avec la prise en charge du chiffrement activée, consultez le fichier « WHERE » dans toute distribution source ou binaire d'Info-ZIP pour connaître les emplacements aux États-Unis et à l'extérieur.

Certaines versions compilées d'unzip peuvent ne pas prendre en charge le chiffrement. Pour vérifier si une version prend en charge le chiffrement, tentez de tester ou d'extraire une archive chiffrée, ou vérifiez l'écran de diagnostic d'unzip (voir l'option -v ci-dessus) pour voir « [decryption] » parmi les options de compilation spéciales.

Comme indiqué ci-dessus, l'option -P peut être utilisée pour fournir un mot de passe sur la ligne de commande, mais au détriment de la sécurité. La méthode de déchiffrement préférée consiste simplement à extraire normalement ; si un membre du fichier zip est chiffré, unzip demandera le mot de passe sans afficher ce qui est tapé. unzip continue à utiliser le même mot de passe tant qu'il semble valide, en testant un en-tête de 12 octets sur chaque fichier. Le mot de passe correct passera toujours le test de l'en-tête, mais il y a une chance sur 256 qu'un mot de passe incorrect le passe également. (C'est une fonctionnalité de sécurité du format de fichier zip PKWARE ; cela aide à prévenir les attaques par force brute qui pourraient sinon gagner un avantage de vitesse important en ne testant que l'en-tête.) Dans le cas où un mot de passe incorrect est donné mais qu'il passe le test de l'en-tête de toute façon, soit un CRC incorrect sera généré pour les données extraites, soit unzip échouera lors de l'extraction car les octets « déchiffrés » ne constituent pas un flux de données compressées valide.

Si le premier mot de passe échoue au test de l'en-tête sur un fichier, unzip demandera un autre mot de passe, et ainsi de suite jusqu'à ce que tous les fichiers soient extraits. Si un mot de passe n'est pas connu, entrer un mot de passe vide (c'est-à-dire, juste un retour chariot ou « Entrée ») est considéré comme un signal pour ignorer toutes les demandes ultérieures. Seuls les fichiers non chiffrés dans l'archive(s) seront alors extraits. (En fait, ce n'est pas tout à fait vrai ; les anciennes versions de zip(1L) et zipcloak(1L) autorisaient les mots de passe vides, donc unzip vérifie chaque fichier chiffré pour voir si le mot de passe vide fonctionne. Cela peut entraîner des « faux positifs » et des erreurs d'extraction, comme noté ci-dessus.)

Les archives chiffrées avec des mots de passe 8 bits (par exemple, des mots de passe avec des caractères européens accentués) peuvent ne pas être portables entre les systèmes et/ou d'autres archiveurs. Ce problème découle de l'utilisation de plusieurs méthodes d'encodage pour de tels caractères, y compris Latin-1 (ISO 8859-1) et le jeu de codes OEM 850. PKZIP 2.04g pour DOS utilise le jeu de codes OEM ; PKZIP 2.50 pour Windows utilise Latin-1 (et est donc incompatible avec PKZIP pour DOS) ; Info-ZIP utilise le jeu de codes OEM sur les ports DOS, OS/2 et Win3.x mais le codage ISO (Latin-1 etc.) partout ailleurs ; et WinZip 6.x de Nico Mak n'autorise pas du tout les mots de passe 8 bits. UnZip 5.3 (ou plus récent) tente d'abord d'utiliser le jeu de caractères par défaut (par exemple, Latin-1), suivi de l'ensemble de caractères alternatif (par exemple, jeu de codes OEM) pour tester les mots de passe. Sur les systèmes EBCDIC, si ces deux échouent, l'encodage EBCDIC sera testé en dernier recours. (L'EBCDIC n'est pas testé sur les systèmes non-EBCDIC, car il n'existe aucun archiveur connu qui chiffre en utilisant l'encodage EBCDIC.) Les encodages de caractères ISO autres que Latin-1 ne sont pas pris en charge. Le nouvel ajout de la prise en charge (partielle) Unicode (resp. UTF-8) dans UnZip 6.0 n'a pas encore été adapté à la gestion des mots de passe de chiffrement dans unzip. Sur les systèmes qui utilisent UTF-8 comme encodage de caractères natif, unzip tente simplement le déchiffrement avec le mot de passe encodé en UTF-8 natif ; les tentatives intégrées pour tester le mot de passe dans un encodage traduit n'ont pas encore été adaptées à la prise en charge UTF-8 et échoueront par conséquent.

EXEMPLES

Pour utiliser unzip afin d'extraire tous les membres de l'archive lettres.zip dans le répertoire courant et les sous-répertoires en dessous, en créant les sous-répertoires si nécessaire :

unzip lettres

Pour extraire tous les membres de lettres.zip dans le répertoire courant uniquement :

unzip -j lettres

Pour tester lettres.zip, en affichant uniquement un message résumé indiquant si l'archive est OK ou non :

unzip -tq lettres

Pour tester tous les fichiers zip du répertoire courant, en affichant uniquement les résumés :

unzip -tq \*.zip

(Le backslash avant l'astérisque n'est requis que si le shell étend les jokers, comme sous Unix ; des guillemets doubles auraient pu être utilisés à la place, comme dans les exemples sources ci-dessous.) Pour extraire vers la sortie standard tous les membres de lettres.zip dont les noms se terminent par .tex, en convertissant automatiquement en convention de fin de ligne locale et en redirigeant la sortie vers more(1) :

unzip -ca lettres \*.tex | more

Pour extraire le fichier binaire paper1.dvi vers la sortie standard et le rediriger vers un programme d'impression :

unzip -p articles paper1.dvi | dvips

Pour extraire tous les fichiers source FORTRAN et C -- *.f, *.c, *.h, et Makefile -- dans le répertoire /tmp :

unzip source.zip "*.[fch]" Makefile -d /tmp

(les guillemets doubles ne sont nécessaires que sous Unix et seulement si le globbing est activé). Pour extraire tous les fichiers source FORTRAN et C, quelle que soit la casse (par exemple, *.c et *.C, et tout makefile, Makefile, MAKEFILE ou similaire) :

unzip -C source.zip "*.[fch]" makefile -d /tmp

Pour extraire de tels fichiers mais convertir tous les noms MS-DOS ou VMS en majuscules en minuscules et convertir les fins de ligne de tous les fichiers à la norme locale (sans tenir compte des fichiers marqués comme « binaire ») :

unzip -aaCL source.zip "*.[fch]" makefile -d /tmp

Pour extraire uniquement les versions plus récentes des fichiers déjà présents dans le répertoire courant, sans confirmation (NOTE : faites attention lors de l'extraction dans un fuseau horaire différent d'un fichier zip créé dans un autre -- les archives ZIP autres que celles créées par Zip 2.1 ou plus récent ne contiennent aucune information de fuseau horaire, et un fichier « plus récent » d'un fuseau horaire oriental peut, en fait, être plus ancien) :

unzip -fo sources

Pour extraire les versions plus récentes des fichiers déjà présents dans le répertoire courant et créer les fichiers qui n'y sont pas encore (même avertissement que l'exemple précédent) :

unzip -uo sources

Pour afficher un écran de diagnostic montrant quelles options unzip et zipinfo sont stockées dans les variables d'environnement, si la prise en charge du déchiffrement a été compilée, le compilateur avec lequel unzip a été compilé, etc. :

unzip -v

Dans les cinq derniers exemples, supposez que UNZIP ou UNZIP_OPTS est défini sur -q. Pour faire une liste simplement silencieuse :

unzip -l fichier.zip

Pour faire une liste doublement silencieuse :

unzip -ql fichier.zip

(Notez que « .zip » n'est généralement pas nécessaire.) Pour faire une liste standard :

unzip --ql fichier.zip
ou 
unzip -l-q fichier.zip
ou 
unzip -l--q fichier.zip
(Les tirets supplémentaires dans les options ne nuisent pas.)

CONSEILS

Le mainteneur actuel, étant paresseux, trouve très utile de définir une paire d'alias : tt pour « unzip -tq » et ii pour « unzip -Z » (ou « zipinfo »). On peut alors simplement taper « tt nom_fichier.zip » pour tester une archive, ce qui vaut la peine d'en faire une habitude.

ENVOI

Avec un peu de chance, unzip affichera « No errors detected in compressed data of zipfile.zip », après quoi l'on pourra pousser un soupir de soulagement.

Le mainteneur trouve également utile de définir la variable d'environnement UNZIP à « -aL » et est tenté d'ajouter « -C » également. Sa variable ZIPINFO est définie à « -z ».

DIAGNOSTICS

Le statut de sortie (ou niveau d'erreur) approxime les codes de sortie définis par PKWARE et prend les valeurs suivantes, sauf sous VMS :

0
normal ; aucune erreur ou avertissement détecté.
1
une ou plusieurs erreurs d'avertissement ont été rencontrées, mais le traitement s'est terminé avec succès. Cela inclut les zipfiles où un ou plusieurs fichiers ont été ignorés en raison d'une méthode de compression non prise en charge ou d'un chiffrement avec un mot de passe inconnu.
2
une erreur générique dans le format du zipfile a été détectée. Le traitement peut s'être terminé avec succès ; certains zipfiles corrompus créés par d'autres archiveurs ont des solutions de contournement simples.
3
une erreur grave dans le format du zipfile a été détectée. Le traitement a probablement échoué immédiatement.
4
unzip n'a pas pu allouer de mémoire pour un ou plusieurs tampons lors de l'initialisation du programme.
5
unzip n'a pas pu allouer de mémoire ou obtenir un tty pour lire le(s) mot(s) de passe de déchiffrement.
6
unzip n'a pas pu allouer de mémoire lors de la décompression sur disque.
7
unzip n'a pas pu allouer de mémoire lors de la décompression en mémoire.
8
[actuellement non utilisé]
9
les zipfiles spécifiés n'ont pas été trouvés.
10
des options invalides ont été spécifiées sur la ligne de commande.
11
aucun fichier correspondant n'a été trouvé.
12
zipfile invalide avec des composants superposés (possible zip-bomb). Les vérifications de zip-bomb peuvent être désactivées en utilisant la variable d'environnement UNZIP_DISABLE_ZIPBOMB_DETECTION=TRUE.
50
le disque est (ou était) plein lors de l'extraction.
51
la fin de l'archive ZIP a été rencontrée prématurément.
80
l'utilisateur a interrompu unzip prématurément avec control-C (ou similaire)
81
le test ou l'extraction d'un ou plusieurs fichiers a échoué en raison de méthodes de compression non prises en charge ou de déchiffrement non pris en charge.
82
aucun fichier n'a été trouvé en raison d'un (des) mauvais mot(s) de passe de déchiffrement. (Si même un fichier est traité avec succès, le statut de sortie est 1.)

VMS interprète les valeurs de retour Unix (ou PC) standard comme d'autres choses, plus effrayantes, donc unzip les mappe plutôt en codes de statut de style VMS. Le mappage actuel est le suivant : 1 (succès) pour une sortie normale, 0x7fff0001 pour les erreurs d'avertissement, et (0x7fff000? + 16*statut_de_sortie_unzip_normal) pour toutes les autres erreurs, où le `?' est 2 (erreur) pour les valeurs 2, 9-11 et 80-82 d'unzip, et 4 (erreur fatale) pour les restantes (3-8, 50, 51). De plus, il existe une option de compilation pour étendre ce comportement : définir RETURN_CODES produit une explication lisible par l'homme de ce que signifie le statut d'erreur.

BUGS

Les archives multi-parties ne sont pas encore prises en charge, sauf en conjonction avec zip. (Toutes les parties doivent être concaténées dans l'ordre, puis « zip -F » (pour zip 2.x) ou « zip -FF » (pour zip 3.x) doit être effectué sur l'archive concaténée afin de la « réparer ». De plus, zip 3.0 et versions ultérieures peuvent combiner des archives multi-parties (divisées) en une archive unique combinée en utilisant « zip -s- inarchive -O outarchive ». Voir la page de manuel de zip 3 pour plus d'informations.) Ceci sera définitivement corrigé dans la prochaine version majeure.

Les archives lues depuis l'entrée standard ne sont pas encore prises en charge, sauf avec funzip (et alors seul le premier membre de l'archive peut être extrait).

Les archives chiffrées avec des mots de passe 8 bits (par exemple, des mots de passe avec des caractères européens accentués) peuvent ne pas être portables entre les systèmes et/ou d'autres archiveurs. Voir la discussion dans DECRYPTION ci-dessus.

L'option -M (« more ») d'unzip essaie de prendre en compte le retour automatique des lignes longues. Cependant, le code peut ne pas détecter les bons emplacements de retour. Premièrement, les caractères TAB (et séquences de contrôle similaires) ne sont pas pris en compte, ils sont traités comme des caractères imprimables ordinaires. Deuxièmement, en fonction du système / port OS réel, unzip peut ne pas détecter la véritable géométrie de l'écran mais plutôt s'appuyer sur des dimensions par défaut « couramment utilisées ». La gestion correcte des tabulations nécessiterait l'implémentation d'une requête pour la configuration réelle du tabulateur sur la console de sortie.

Les dates, heures et permissions des répertoires stockés ne sont pas restaurés sauf sous Unix. (Sous Windows NT et successeurs, les horodatages sont maintenant restaurés.)

[MS-DOS] Lors de l'extraction ou du test de fichiers d'une archive sur une disquette défectueuse, si l'option « Fail » est choisie dans le message « Abort, Retry, Fail? » de DOS, les anciennes versions d'unzip peuvent bloquer le système, nécessitant un redémarrage. Ce problème semble résolu, mais control-C (ou control-Break) peut toujours être utilisé pour terminer unzip.

Sous DEC Ultrix, unzip échouait parfois sur de longs zipfiles (CRC incorrect, pas toujours reproductible). C'était apparemment dû soit à un bug matériel (mémoire cache), soit à un bug du système d'exploitation (mauvaise gestion des fautes de page?). Comme Ultrix a été abandonné au profit de Digital Unix (OSF/1), ce n'est peut-être plus un problème.

[Unix] Les fichiers spéciaux Unix tels que les tampons FIFO (tubes nommés), les périphériques de bloc et les périphériques de caractères ne sont pas restaurés même s'ils sont représentés d'une manière ou d'une autre dans le zipfile, ni les fichiers liés en dur ne sont relinkés. Essentiellement, les seuls types de fichiers restaurés par unzip sont les fichiers réguliers, les répertoires et les liens symboliques (soft links).

[OS/2] Les attributs étendus pour les répertoires existants ne sont mis à jour que si l'option -o (« tout écraser ») est donnée. C'est une limitation du système d'exploitation ; comme les répertoires n'ont qu'une date de création associée, unzip n'a aucun moyen de déterminer si les attributs stockés sont plus récents ou plus anciens que ceux sur le disque. En pratique, cela peut signifier qu'une approche en deux passes est nécessaire : d'abord décompresser l'archive normalement (avec ou sans actualisation/mise à jour des fichiers existants), puis écraser uniquement les entrées de répertoire (par exemple, « unzip -o foo */' »).

[VMS] Lors de l'extraction vers un autre répertoire, seule la syntaxe [.foo] est acceptée pour l'option -d ; la syntaxe Unix simple foo est silencieusement ignorée (tout comme la syntaxe VMS moins courante foo.dir).

[VMS] Lorsque le fichier en cours d'extraction existe déjà, la requête d'unzip n'autorise que le saut, l'écrasement ou le renommage ; il devrait en plus y avoir un choix pour créer une nouvelle version du fichier. En fait, le choix « écraser » crée une nouvelle version ; l'ancienne version n'est pas écrasée ni supprimée.
