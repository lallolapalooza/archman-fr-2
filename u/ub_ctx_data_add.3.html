DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui effectue la mise en cache et la validation DNSSEC. Ceci est l'API de la bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et vice versa, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour maintenir le contexte entre les appels. L'utilisateur doit la maintenir, la créant avec ub_ctx_create et la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La recréer efface toute configuration précédente (comme les clés de confiance) et tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement multi-threadé (ainsi que dans un environnement non-multi-threadé). La résolution (et la validation) peuvent également être effectuées de manière bloquante et non-bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement de l'appel, de sorte que le traitement puisse continuer, tandis que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec les valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez lib openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou plus récent utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les callbacks ne sont pas appelés pour celles-ci.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère la valeur d'une option. Certaines options ne peuvent pas être récupérées, et d'autres retournent une liste séparée par des sauts de ligne. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée (free(2)) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine à laquelle les requêtes DNS seront transmises, le résolveur de cache à utiliser. Adresse IP4 ou IP6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas compatible DNSSEC, la validation peut échouer. Peut être appelé plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. Il n'est possible à ce stade de définir la configuration qu'avant la première résolution.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Réglez isprime à true si vous configurez des indications de racine avec. Sinon, similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelé plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. Il n'est possible à ce stade de définir la configuration qu'avant la première résolution.
ub_ctx_set_tls
Active le DNS sur TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. Il n'est possible à ce stade de définir la configuration qu'avant la première résolution.
ub_ctx_resolvconf
Par défaut, les serveurs racines sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser depuis le nom de fichier donné. Habituellement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxies de cache. S'ils ne supportent pas DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont pris en compte, le domaine de recherche, ndots et d'autres paramètres de resolv.conf(5) sont ignorés. Si fname est NULL, "/etc/resolv.conf" est utilisé (sur Windows, le serveur de noms configuré globalement est choisi à la place). Il n'est possible à ce stade de définir la configuration qu'avant la première résolution.
ub_ctx_hosts
Lit la liste des hôtes depuis le nom de fichier donné. Habituellement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname est NULL, "/etc/hosts" est utilisé (sur Windows, le fichier etc/hosts de WINDIR est choisi à la place). Il n'est possible à ce stade de définir la configuration qu'avant la première résolution.

ub_ctx_add_ta
Ajoute un point d'ancrage de confiance au contexte donné. À l'heure actuelle, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée. Le format est une chaîne de caractères, similaire au format de fichier de zone, [nom de domaine] [type] [contenu rdata]. Les enregistrements DS et DNSKEY sont acceptés.
ub_ctx_add_ta_autr
Ajoute un nom de fichier avec un point d'ancrage de confiance suivi automatiquement au contexte donné. Passez le nom d'un fichier avec le point d'ancrage de confiance géré. Vous pouvez créer ce fichier avec unbound-anchor(8) pour le point d'ancrage racine. Vous pouvez également le créer avec un fichier initial contenant une seule ligne avec un enregistrement DNSKEY ou DS. Si le fichier est inscriptible, il est mis à jour lorsque le point d'ancrage de confiance change. À l'heure actuelle, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_add_ta_file
Ajoute des points d'ancrage de confiance au contexte donné. Passez le nom d'un fichier contenant des enregistrements DS et DNSKEY au format de fichier de zone. À l'heure actuelle, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_trustedkeys
Ajoute des points d'ancrage de confiance au contexte donné. Passez le nom d'un fichier de configuration de style bind avec trusted-keys{}. À l'heure actuelle, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_debugout
Définit la sortie des journaux de débogage et d'erreur sur le flux donné. Passez NULL pour désactiver la sortie. Par défaut, c'est stderr. Les noms de fichiers ou l'utilisation de syslog peuvent être activés via les options de configuration, cette routine est destinée à l'utilisation de votre propre flux.
ub_ctx_debuglevel
Définit la verbosité du débogage pour le contexte. La sortie est dirigée vers stderr. Un niveau de débogage plus élevé génère plus de sortie.
ub_ctx_async
Définit le comportement d'un contexte pour une action asynchrone. Si défini sur true, il active le multithreading et un appel à ub_resolve_async crée un thread pour gérer le travail en arrière-plan. Si défini sur false, un processus est dédoublé pour gérer le travail en arrière-plan. Les modifications apportées à ce paramètre après des appels à ub_resolve_async n'ont aucun effet (supprimez et recréez le contexte pour le modifier).
ub_poll
Sonde un contexte pour voir s'il a de nouveaux résultats. Ne sonde pas en boucle, extraire plutôt le fd ci-dessous pour sonder sa disponibilité, puis vérifier, ou attendre en utilisant la routine d'attente. Retourne 0 s'il n'y a rien à lire, ou une valeur non nulle si un résultat est disponible. Si non nulle, appelez ub_process pour effectuer les rappels.
ub_wait
Attend qu'un contexte termine avec des résultats. Appelle ub_process après l'attente pour vous. Après l'attente, il n'y a plus de requêtes asynchrones en cours.
ub_fd
Obtient le descripteur de fichier. Attendez qu'il devienne lisible, à ce moment-là, les réponses sont retournées par le résolveur de validation asynchrone. Appelez ensuite ub_process pour continuer le traitement.
ub_process
Appelez cette routine pour continuer le traitement des résultats du résolveur de validation (lorsque le fd devient lisible). Effectuera les rappels nécessaires.
ub_resolve
Effectue la résolution et la validation du nom cible. Le nom est un nom de domaine sous forme de chaîne de caractères terminée par un zéro. Les types et classes rrtype et rrclass sont des codes de type et de classe DNS. La structure de résultat est nouvellement allouée avec les données résultantes.
ub_resolve_async
Effectue la résolution et la validation asynchrones du nom cible. Les arguments ont la même signification que pour ub_resolve, sauf qu'aucune donnée n'est retournée immédiatement, un rappel est plutôt appelé plus tard. Le rappel reçoit une copie du pointeur mydata, que vous pouvez utiliser pour passer des informations au rappel. Le type de rappel est un pointeur de fonction vers une fonction déclarée comme suit :
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

L'async_id est retourné afin que vous puissiez (à votre discrétion) le suivre et annuler la requête si nécessaire. Si vous passez un pointeur NULL, l'async_id n'est pas retourné.

ub_cancel
Annule une requête asynchrone en cours. Cela peut retourner une erreur si la requête n'existe pas, ou si la requête est déjà en cours de livraison, auquel cas vous pourriez encore recevoir un rappel pour la requête.
ub_resolve_free
Libère le contenu de la structure ub_result après utilisation.
ub_strerror
Convertit une valeur d'erreur d'une des fonctions de la bibliothèque unbound en une chaîne de caractères lisible par l'homme.
ub_ctx_print_local_zones
Imprime les informations d'autorité locale dans la sortie de débogage.
ub_ctx_zone_add
Ajoute une nouvelle zone aux informations d'autorité locale, comme l'instruction local-zone de unbound.conf(5).
ub_ctx_zone_remove
Supprime une zone des informations d'autorité locale.
ub_ctx_data_add
Ajoute des données d'enregistrement de ressources aux informations d'autorité locale, comme l'instruction local-data de unbound.conf(5).
ub_ctx_data_remove
Supprime les données d'autorité locale du nom donné.

STRUCTURE DES DONNÉES DE RÉSULTAT

Le résultat de la résolution et de la validation DNS est retourné sous forme de struct ub_result. La structure de résultat contient les entrées suivantes :

struct ub_result {
     char* qname;         /* chaîne de caractères, question originale */
     int qtype;           /* code de type demandé */
     int qclass;          /* code de classe demandé */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas de données manquantes */
     void* answer_packet; /* paquet de réponse complet au format réseau */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai si nodata car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si une défaillance de sécurité s'est produite */
     char* why_bogus;     /* chaîne avec l'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée en débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

Si secure et bogus sont tous deux faux, la sécurité n'était pas activée pour le domaine de la requête. Sinon, ils ne sont pas tous deux vrais, l'un d'eux est vrai.

VALEURS DE RETOUR

De nombreuses routines retournent un code d'erreur. La valeur 0 (zéro) signifie qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror retourne une chaîne terminée par un zéro. ub_ctx_create retourne NULL en cas d'erreur (un échec d'allocation mémoire). ub_poll retourne vrai si des informations peuvent être disponibles, faux sinon. ub_fd retourne un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif en cas de retour de fonction avec échec de lecture de fichier.
