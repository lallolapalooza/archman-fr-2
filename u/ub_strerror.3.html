DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui gère la mise en cache et la validation DNSSEC. Ceci est l'API de bibliothèque, pour l'utilisation de la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution, et peut être utilisée pour convertir des noms d'hôte en adresses IP, et vice-versa, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour maintenir le contexte entre les appels. L'utilisateur doit la gérer, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La créer à nouveau supprime toute configuration précédente (comme les clés de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement multi-threadé (ainsi que dans un environnement mono-threadé). La résolution (et la validation) peuvent également être effectuées de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement de l'appel, de sorte que le traitement puisse continuer, pendant que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées une par une ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec les valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez lib openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou supérieur utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les callbacks ne sont pas appelés pour elles.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier l'une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère la valeur d'une option. Certaines options ne peuvent pas être récupérées, et d'autres renvoient une liste séparée par des sauts de ligne. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée (free(2)) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction n'est thread-safe que si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine vers laquelle les requêtes DNS doivent être transmises, le résolveur de mise en cache à utiliser. Adresse IPv4 ou IPv6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas compatible DNSSEC, la validation peut échouer. Peut être appelée plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. À ce stade, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS autoritaires à utiliser pour une zone particulière. Adresse IPv4 ou IPv6. Si l'adresse est NULL, l'entrée stub est supprimée. Mettez isprime à vrai si vous configurez des indices racine avec. Sinon, c'est similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelée plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. À ce stade, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_set_tls
Active le DNS sur TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. À ce stade, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_resolvconf
Par défaut, les serveurs racine sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser à partir du nom de fichier donné. Habituellement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxys de mise en cache. S'ils ne prennent pas en charge DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont récupérés, le domaine de recherche, ndots et les autres paramètres de resolv.conf(5) sont ignorés. Si fname est NULL, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré globalement est sélectionné à la place). À ce stade, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Habituellement "/etc/hosts". Lors de l'interrogation, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname est NULL, "/etc/hosts" est utilisé (si sous Windows, etc/hosts depuis WINDIR est sélectionné à la place). À ce stade, il n'est possible de définir la configuration qu'avant la première réso

NOM

ub_strerror - convertir la valeur d'erreur des fonctions de la bibliothèque unbound en une chaîne de caractères lisible.

SYNOPSIS

char* ub_strerror(int errnum);

DESCRIPTION

La fonction ub_strerror prend un entier errnum représentant un code d'erreur retourné par une fonction de la bibliothèque unbound. Elle retourne une chaîne de caractères terminée par un caractère nul qui décrit l'erreur. Si errnum est 0, une chaîne vide est retournée. Si l'erreur est inconnue, une chaîne décrivant un nombre inconnu est retournée.

Cette fonction est utile pour convertir les codes d'erreur numériques retournés par les fonctions unbound en messages d'erreur lisibles par l'utilisateur, facilitant ainsi le débogage et la gestion des erreurs dans les applications qui utilisent la bibliothèque unbound.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte unbound. Le contexte contient l'état et les configurations pour les opérations de résolution DNS. Les opérations peuvent être effectuées sur ce contexte. Le nouveau contexte est renvoyé. En cas d'erreur (par exemple, échec d'allocation mémoire), NULL est retourné. Le contexte créé doit être libéré par un appel à ub_ctx_destroy.
ub_ctx_destroy
Détruit le contexte unbound et libère toutes les ressources associées. Après cet appel, le contexte ne peut plus être utilisé.
ub_ctx_set_fwd_addr
Définit l'adresse du serveur DNS forwarder à utiliser pour le contexte. L'adresse est fournie sous forme de chaîne de caractères, qui peut inclure un nom d'hôte ou une adresse IP, ainsi que le numéro de port. La fonction prend également en charge la spécification d'adresses IPv6. Si plusieurs forwarders sont spécifiés, ils seront utilisés dans l'ordre. Les anciens forwarders sont effacés avant d'ajouter les nouveaux. Retourne 0 en cas de succès, une valeur négative en cas d'erreur. Un appel à cette fonction avant le premier appel à ub_resolve ou ub_resolve_async est nécessaire pour configurer le forwarder.
ub_ctx_set_fwd_zone
Définit le serveur DNS forwarder pour une zone spécifique. La fonction prend le nom de la zone, le type de classe (généralement 1 pour IN), et l'adresse du forwarder. Ceci permet de spécifier des serveurs DNS différents pour des zones particulières, par exemple, pour gérer des zones privées. Les anciens forwarders pour la zone spécifiée sont effacés. Retourne 0 en cas de succès, une valeur négative en cas d'erreur. Les spécifications de forwarders de zone doivent être faites avant le premier appel à ub_resolve ou ub_resolve_async.
ub_ctx_add_ta
Ajoute une ancre de confiance au contexte donné. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée. Le format est une chaîne de caractères, similaire au format de fichier de zone, [nom de domaine] [type] [contenu rdata]. Les enregistrements DS et DNSKEY sont acceptés.
ub_ctx_add_ta_autr
Ajoute un nom de fichier contenant une ancre de confiance suivie automatiquement au contexte donné. Passez le nom d'un fichier contenant l'ancre de confiance gérée. Vous pouvez créer ce fichier avec unbound-anchor(8) pour l'ancre racine. Vous pouvez également le créer avec un fichier initial contenant une ligne avec un enregistrement DNSKEY ou DS. Si le fichier est inscriptible, il est mis à jour lorsque l'ancre de confiance change. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_add_ta_file
Ajoute des ancres de confiance au contexte donné. Passez le nom d'un fichier contenant des enregistrements DS et DNSKEY au format de fichier de zone. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_trustedkeys
Ajoute des ancres de confiance au contexte donné. Passez le nom d'un fichier de configuration de style bind avec trusted-keys{}. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_debugout
Définit la sortie des logs de débogage et d'erreur vers le flux donné. Passez NULL pour désactiver la sortie. La valeur par défaut est stderr. Les noms de fichiers ou l'utilisation de syslog peuvent être activés via les options de configuration, cette routine sert à utiliser votre propre flux.
ub_ctx_debuglevel
Définit la verbosité du débogage pour le contexte. La sortie est dirigée vers stderr. Un niveau de débogage plus élevé produit plus de sortie.
ub_ctx_async
Définit le comportement du contexte pour les actions asynchrones. Si défini sur vrai, cela active le multithreading et un appel à ub_resolve_async crée un thread pour gérer le travail en arrière-plan. Si faux, un processus est bifurqué pour gérer le travail en arrière-plan. Les modifications apportées à ce paramètre après que des appels à ub_resolve_async aient été effectués n'ont aucun effet (supprimez et recréez le contexte pour changer).
ub_poll
Interroge un contexte pour voir s'il y a de nouveaux résultats. N'interrogez pas en boucle, mais extrayez le fd ci-dessous pour interroger la disponibilité, puis vérifiez, ou attendez en utilisant la routine d'attente. Retourne 0 s'il n'y a rien à lire, ou une valeur non nulle s'il y a un résultat disponible. Si non nulle, appelez ub_process pour effectuer les rappels.
ub_wait
Attend qu'un contexte termine avec des résultats. Appelle ub_process après l'attente pour vous. Après l'attente, il n'y a plus de requêtes asynchrones en cours.
ub_fd
Obtient le descripteur de fichier. Attendez qu'il devienne lisible, à ce moment-là les réponses sont retournées par le résolveur de validation asynchrone. Appelez ensuite ub_process pour continuer le traitement.
ub_process
Appelez cette routine pour continuer le traitement des résultats du résolveur de validation (lorsque le fd devient lisible). Effectuera les rappels nécessaires.
ub_resolve
Effectue la résolution et la validation du nom cible. Le nom est un nom de domaine sous forme de chaîne de texte terminée par un caractère nul. Le type de rr et la classe de rr sont les codes de type et de classe DNS. La structure de résultat est nouvellement allouée avec les données résultantes.
ub_resolve_async
Effectue la résolution et la validation asynchrones du nom cible. Les arguments signifient la même chose que pour ub_resolve, sauf qu'aucune donnée n'est retournée immédiatement, mais un rappel est appelé plus tard. Le rappel reçoit une copie du pointeur mydata, que vous pouvez utiliser pour passer des informations au rappel. Le type de rappel est un pointeur de fonction vers une fonction déclarée comme suit :
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

L' async_id est retourné afin que vous puissiez (à votre discrétion) décider de le suivre et d'annuler la requête si nécessaire. Si vous passez un pointeur NULL, l' async_id n'est pas retourné.

ub_cancel
Annule une requête asynchrone en cours. Cela peut retourner une erreur si la requête n'existe pas, ou si la requête est déjà en cours de livraison, auquel cas vous pourriez toujours recevoir un rappel pour la requête.
ub_resolve_free
Libère le contenu de la structure ub_result après utilisation.
ub_strerror
Convertit une valeur d'erreur de l'une des fonctions de la bibliothèque unbound en une chaîne de caractères lisible par l'homme.
ub_ctx_print_local_zones
Affiche les informations d'autorité locale dans la sortie de débogage.
ub_ctx_zone_add
Ajoute une nouvelle zone aux informations d'autorité locale, comme l'instruction local-zone de unbound.conf(5).
ub_ctx_zone_remove
Supprime une zone des informations d'autorité locale.
ub_ctx_data_add
Ajoute des données d'enregistrement de ressources aux informations d'autorité locale, comme l'instruction local-data de unbound.conf(5).
ub_ctx_data_remove
Supprime les données d'autorité locale du nom donné.

STRUCTURE DE DONNÉES DE RÉSULTAT

Le résultat de la résolution et de la validation DNS est retourné sous forme de struct ub_result. La structure de résultat contient les entrées suivantes :

struct ub_result {
     char* qname;         /* chaîne de texte, question originale */
     int qtype;           /* type demandé */
     int qclass;          /* classe demandée */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas de absence de données */
     void* answer_packet; /* paquet réseau complet de la réponse */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai si nodata car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si une défaillance de sécurité s'est produite */
     char* why_bogus;     /* chaîne avec l'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée en débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

Si à la fois secure et bogus sont faux, la sécurité n'a pas été activée pour le domaine de la requête. Sinon, ils ne sont pas tous les deux vrais, l'un d'eux est vrai.

VALEURS DE RETOUR

De nombreuses routines retournent un code d'erreur. La valeur 0 (zéro) signifie qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror retourne une chaîne terminée par un zéro. ub_ctx_create retourne NULL en cas d'erreur (échec de malloc). ub_poll retourne vrai si des informations peuvent être disponibles, faux sinon. ub_fd retourne un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif en cas de retour de fonction avec échec de lecture de fichier.
