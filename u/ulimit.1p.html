ULIMIT(1P) Manuel du programmeur POSIX ULIMIT(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ulimit — définir ou signaler la limite de taille de fichier

SYNOPSIS

ulimit [-f] [blocs]

DESCRIPTION

L'utilitaire ulimit définit ou signale la limite de taille de fichier imposée aux fichiers écrits par le shell et ses processus enfants (les fichiers de toute taille peuvent être lus). Seul un processus ayant les privilèges appropriés peut augmenter la limite.

OPTIONS

L'utilitaire ulimit est conforme au volume Bases Définitions de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

L'option suivante doit être prise en charge :

-f
Définit (ou signale, s'il n'y a pas d'opérande blocs) la limite de taille de fichier en blocs. L'option -f est également le cas par défaut.

OPÉRANDES

L'opérande suivant doit être pris en charge :

blocs
Le nombre de blocs de 512 octets à utiliser comme nouvelle limite de taille de fichier.

STDIN

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de ulimit :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Bases Définitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard est utilisée lorsqu'aucun opérande blocs n'est présent. Si le nombre actuel de blocs est limité, le nombre de blocs de la limite actuelle sera écrit dans le format suivant :

"%d\n", <nombre de blocs de 512 octets>

S'il n'y a pas de limite actuelle sur le nombre de blocs, dans la locale POSIX, le format suivant sera utilisé :

"unlimited\n"

STDERR

La sortie d'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une demande d'augmentation de limite a été rejetée ou une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Étant donné que ulimit affecte l'environnement d'exécution du shell courant, il est toujours fourni en tant qu'interne régulier du shell. S'il est appelé dans un environnement d'exécution utilitaire séparé, tel que l'un des éléments suivants :

nohup ulimit -f 10000
env ulimit 10000

il n'affecte pas la limite de taille de fichier de l'environnement de l'appelant.

Une fois qu'une limite a été réduite par un processus, elle ne peut pas être augmentée (sauf si des privilèges appropriés sont impliqués), même pour revenir à la limite système d'origine.

EXEMPLES

Définir la limite de taille de fichier à 51200 octets :

ulimit -f 100
