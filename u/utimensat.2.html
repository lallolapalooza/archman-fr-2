utimensat(2) Manuel des appels système utimensat(2)

NOM

utimensat, futimens - modifier les horodatages de fichiers avec une précision nanoseconde

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>            /* Définition des constantes AT_* */
#include <sys/stat.h>
int utimensat(int dirfd, const char *path,
              const struct timespec times[_Nullable 2], int flags);
int futimens(int fd, const struct timespec times[_Nullable 2]);
Exigences pour les macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _ATFILE_SOURCE

futimens():

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _GNU_SOURCE

DESCRIPTION

utimensat() et futimens() mettent à jour les horodatages d'un fichier avec une précision nanoseconde. Ceci contraste avec les anciens appels utime(2) et utimes(2), qui permettent respectivement une précision à la seconde et à la microseconde lors de la définition des horodatages de fichiers.

Avec utimensat(), le fichier est spécifié via le chemin donné dans path. Avec futimens(), le fichier dont les horodatages doivent être mis à jour est spécifié via un descripteur de fichier ouvert, fd.

Pour les deux appels, les nouveaux horodatages de fichiers sont spécifiés dans le tableau times : times[0] spécifie le nouvel "heure de dernier accès" (atime) ; times[1] spécifie la nouvelle "heure de dernière modification" (mtime). Chacun des éléments de times spécifie une heure comme le nombre de secondes et de nanosecondes depuis l'Époque, 1970-01-01 00:00:00 +0000 (UTC). Ces informations sont transmises dans une structure timespec(3).

Les horodatages de fichiers mis à jour sont définis à la plus grande valeur supportée par le système de fichiers qui n'est pas supérieure à l'heure spécifiée.

Si le champ tv_nsec de l'une des structures timespec a la valeur spéciale UTIME_NOW, alors l'horodatage de fichier correspondant est défini à l'heure actuelle. Si le champ tv_nsec de l'une des structures timespec a la valeur spéciale UTIME_OMIT, alors l'horodatage de fichier correspondant reste inchangé. Dans les deux cas, la valeur du champ tv_sec correspondant est ignorée.

Si times est NULL, alors les deux horodatages sont définis à l'heure actuelle.

L'heure de changement d'état (ctime) sera définie à l'heure actuelle, même si les autres horodatages ne changent pas réellement.

Exigences de permissions

Pour définir les deux horodatages de fichiers à l'heure actuelle (c'est-à-dire times est NULL, ou les deux champs tv_nsec spécifient UTIME_NOW), soit :

•
l'appelant doit avoir un accès en écriture au fichier ;
•
l'ID utilisateur effectif de l'appelant doit correspondre au propriétaire du fichier ; ou
•
l'appelant doit avoir les privilèges appropriés.

Pour effectuer toute modification autre que la définition des deux horodatages à l'heure actuelle (c'est-à-dire times n'est pas NULL, et aucun champ tv_nsec n'est UTIME_NOW et aucun champ tv_nsec n'est UTIME_OMIT), l'une des conditions 2 ou 3 doit s'appliquer.

Si les deux champs tv_nsec sont spécifiés comme UTIME_OMIT, alors aucune vérification de propriété de fichier ou de permission n'est effectuée, et les horodatages de fichiers ne sont pas modifiés, mais d'autres conditions d'erreur peuvent toujours être détectées.

Spécificités de utimensat()

Si path est relatif, alors par défaut il est interprété par rapport au répertoire référencé par le descripteur de fichier ouvert, dirfd (plutôt que par rapport au répertoire de travail courant du processus appelant, comme le fait utimes(2) pour un nom de chemin relatif). Voir openat(2) pour une explication de l'utilité de ceci.

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail courant du processus appelant (comme utimes(2)).

Si path est absolu, alors dirfd est ignoré.

L'argument flags est un masque de bits créé en combinant zéro ou plus des valeurs suivantes définies dans <fcntl.h> :

AT_EMPTY_PATH (depuis Linux 5.8)
Si path est une chaîne vide, opérez sur le fichier référencé par dirfd (qui peut avoir été obtenu en utilisant le flag open(2) O_PATH). Dans ce cas, dirfd peut faire référence à tout type de fichier, pas seulement un répertoire. Si dirfd est AT_FDCWD, l'appel opère sur le répertoire de travail courant. Ce flag est spécifique à Linux ; définissez _GNU_SOURCE pour obtenir sa définition.
AT_SYMLINK_NOFOLLOW
Si path spécifie un lien symbolique, alors mettez à jour les horodatages du lien, plutôt que ceux du fichier auquel il fait référence.

VALEUR DE RETOUR

En cas de succès, utimensat() et futimens() retournent 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
(futimens()) fd n'est pas un descripteur de fichier valide.
EBADF
(utimensat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
times pointait vers une adresse invalide ; ou, dirfd était AT_FDCWD, et path est NULL ou une adresse invalide.
EINVAL
Valeur invalide dans flags.
EINVAL
Valeur invalide dans l'un des champs tv_nsec (valeur hors plage [0, 999 999 999], et ni UTIME_NOW ni UTIME_OMIT) ; ou une valeur invalide dans l'un des champs tv_sec.
EINVAL
path est NULL, dirfd n'est pas AT_FDCWD, et flags contient AT_SYMLINK_NOFOLLOW.

VERSIONS

Différences ABI bibliothèque C / noyau

Sur Linux, futimens() est une fonction de bibliothèque implémentée au-dessus de l'appel système utimensat(). Pour cela, l'appel système utimensat() de Linux implémente une fonctionnalité non standard : si path est NULL, alors l'appel modifie les horodatages du fichier référencé par le descripteur de fichier dirfd (qui peut référencer tout type de fichier). En utilisant cette fonctionnalité, l'appel futimens(fd, times) est implémenté comme suit :


utimensat(fd, NULL, times, 0);

Notez cependant que l'enveloppe glibc pour utimensat() interdit de passer NULL comme valeur pour path : la fonction enveloppe renvoie l'erreur EINVAL dans ce cas.

NOTES

utimensat() rend obsolète futimesat(2).

Sur Linux, les horodatages ne peuvent pas être modifiés pour un fichier marqué comme immuable, et la seule modification permise pour les fichiers marqués comme uniquement accessible en ajout est de définir les horodatages à l'heure actuelle. (Ceci est cohérent avec le comportement historique de utime(2) et utimes(2) sur Linux.)

Si les deux champs tv_nsec sont spécifiés comme UTIME_OMIT, alors l'implémentation Linux de utimensat() réussit même si le fichier référencé par dirfd et path n'existe pas.

BOGUES

Plusieurs bogues affectent utimensat() et futimens() avant Linux 2.6.26. Ces bogues sont soit des non-conformités avec la spécification du brouillon POSIX.1, soit des incohérences avec le comportement historique de Linux.

•
POSIX.1 spécifie que si l'un des champs tv_nsec a la valeur UTIME_NOW ou UTIME_OMIT, alors la valeur du champ tv_sec correspondant doit être ignorée. Au lieu de cela, la valeur du champ tv_sec doit être 0 (ou l'erreur EINVAL en résulte).
•
Divers bogues signifient que, aux fins de vérification des permissions, le cas où les deux champs tv_nsec sont définis sur UTIME_NOW n'est pas toujours traité de la même manière que la spécification de times comme NULL, et le cas où une valeur tv_nsec est UTIME_NOW et l'autre est UTIME_OMIT n'est pas traité de la même manière que la spécification de times comme un pointeur vers un tableau de structures contenant des valeurs de temps arbitraires. En conséquence, dans certains cas : a) les horodatages des fichiers peuvent être mis à jour par un processus qui ne devrait pas avoir la permission d'effectuer des mises à jour ; b) les horodatages des fichiers ne peuvent pas être mis à jour par un processus qui devrait avoir la permission d'effectuer des mises à jour ; et c) le mauvais code errno est renvoyé en cas d'erreur.
•
POSIX.1 indique qu'un processus ayant un accès en écriture au fichier peut effectuer un appel avec times comme NULL, ou avec times pointant vers un tableau de structures où les deux champs tv_nsec sont UTIME_NOW, afin de mettre à jour les deux horodatages à l'heure actuelle. Cependant, futimens() vérifie au lieu de cela si le mode d'accès du descripteur de fichier autorise l'écriture.
