UDEVADM(8) udevadm UDEVADM(8)

NOM

udevadm - outil de gestion de udev

SYNTAXE

udevadm [--debug] [--version] [--help]

udevadm info [options...] [devpath|syspath|id|unit...]

udevadm trigger [options...] [devpath|syspath|id|unit...]

udevadm settle [options...]

udevadm control options...

udevadm monitor [options...]

udevadm test [options...] devpath|syspath|id|unit

udevadm test-builtin [options...] commande devpath|syspath|id|unit

udevadm verify [options...] [fichiers...]

udevadm cat [options...] [fichiers...]

udevadm wait [options...] devpath|syspath...

udevadm lock [options...] commande...

DESCRIPTION

udevadm attend une commande et des options spécifiques à la commande. Il contrôle le comportement d'exécution de systemd-udevd, demande des événements du noyau, gère la file d'attente des événements et fournit des mécanismes de débogage simples.

OPTIONS

-d, --debug

Affiche les messages de débogage sur la sortie d'erreur standard. Cette option est implicite dans les commandes udevadm test et udevadm test-builtin.

-V, --version

Affiche une courte chaîne de version et quitte.

-h, --help

Affiche un court texte d'aide et quitte.

udevadm info [options...] [devpath|syspath|id|unit...]

Interroge la base de données udev pour obtenir des informations sur les périphériques.

Les arguments positionnels doivent être utilisés pour spécifier un ou plusieurs périphériques. Chacun peut être un nom de périphérique (auquel cas il doit commencer par /dev/), un chemin sys (auquel cas il doit commencer par /sys/), un ID de périphérique (tel que "n1", "c5:1", ou "b259:1", voir sd_device_get_device_id(3)). ou un nom d'unité de périphérique systemd (auquel cas il doit se terminer par ".device", voir systemd.device(5)).

-q, --query=TYPE

Interroge la base de données pour le type de données de périphérique spécifié. Les TYPEs valides sont : name, symlink, path, property, all.

--property=NOM

Lors de l'affichage des propriétés du périphérique à l'aide de l'option --query=property, limite l'affichage aux propriétés spécifiées dans l'argument. L'argument doit être une liste de noms de propriétés séparés par des virgules. Si non spécifié, toutes les propriétés connues sont affichées.

Ajouté dans la version 250.

--value

Lors de l'affichage des propriétés du périphérique à l'aide de l'option --query=property, affiche uniquement leurs valeurs et ignore le nom de la propriété et le signe "=".

Ne peut pas être utilisé avec -x/--export ou -P/--export-prefix.

Ajouté dans la version 250.

-p, --path=DEVPATH

Le chemin /sys/ du périphérique à interroger, par exemple [/sys/]/class/block/sda. Cette option est une alternative à l'argument positionnel avec un préfixe /sys/. udevadm info --path=/class/block/sda est équivalent à udevadm info /sys/class/block/sda.

-n, --name=FICHIER

Le nom du nœud du périphérique ou un lien symbolique à interroger, par exemple [/dev/]/sda. Cette option est une alternative à l'argument positionnel avec un préfixe /dev/. udevadm info --name=sda est équivalent à udevadm info /dev/sda.

-r, --root

Affiche les chemins absolus dans la requête name ou symlink.

-a, --attribute-walk

Affiche toutes les propriétés sysfs du périphérique spécifié qui peuvent être utilisées dans les règles udev pour faire correspondre le périphérique spécifié. Il affiche tous les périphériques le long de la chaîne, jusqu'à la racine de sysfs qui peut être utilisée dans les règles udev.

Ce commutateur prend en charge le mode de sortie JSON (voir --json= ci-dessous). Notez que comme ce commutateur génère plusieurs objets JSON, le mode JSON-SEQ est automatiquement activé (RFC7464). (Note : les outils tels que jq[1] prennent en charge nativement JSON-SEQ via le commutateur --seq.)

-t, --tree

Affiche un arbre sysfs. Ceci itère récursivement sur la hiérarchie sysfs et l'affiche dans une structure arborescente. Si un chemin est spécifié, seul le sous-arbre en dessous et les répertoires parents sont affichés. Ceci affichera à la fois les périphériques et les éléments du sous-système.

Ajouté dans la version 251.

-x, --export

Affiche la sortie sous forme de paires clé/valeur. Les valeurs sont entourées d'apostrophes simples. Ceci ne prend effet que lorsque --query=property ou --device-id-of-file=FICHIER est spécifié.

-P, --export-prefix=NOM

Ajoute un préfixe au nom de clé des valeurs exportées. Ceci implique --export.

-d, --device-id-of-file=FICHIER

Affiche les numéros majeur/mineur du périphérique sous-jacent, où se trouve le fichier. Si ceci est spécifié, tous les arguments positionnels sont ignorés.

-e, --export-db

Exporte le contenu de la base de données udev.

-c, --cleanup-db

Nettoie la base de données udev.

-w[SECONDES], --wait-for-initialization[=SECONDES]

Attend que le périphérique soit initialisé. Si l'argument SECONDES n'est pas spécifié, la valeur par défaut est d'attendre indéfiniment.

Ajouté dans la version 243.

--subsystem-match[=SUBSYSTEM], --subsystem-nomatch[=SUBSYSTEM]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques du sous-système donné ou non du sous-système donné respectivement.

Ajouté dans la version 255.

--attr-match[=FICHIER[=VALEUR]], --attr-nomatch[=FICHIER[=VALEUR]]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques correspondant ou ne correspondant pas à l'attribut donné respectivement.

Ajouté dans la version 255.

--property-match[=CLE=VALEUR]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques correspondant à la propriété et à la valeur données.

Ajouté dans la version 255.

--tag-match[=TAG]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques avec le tag donné.

Ajouté dans la version 255.

--sysname-match[=NOM]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques avec le chemin "/sys" donné.

Ajouté dans la version 255.

--name-match[=NOM]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques avec le nom donné dans "/dev".

Ajouté dans la version 255.

--parent-match[=NOM]

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques avec le périphérique parent donné.

Ajouté dans la version 255.

--initialized-match, --initialized-nomatch

Lorsqu'il est utilisé avec --export-db, affiche uniquement les périphériques qui sont initialisés ou non initialisés respectivement.

Ajouté dans la version 255.

--json=MODE

Affiche la sortie au format JSON. Attend l'une des valeurs suivantes : "short" (pour la sortie la plus courte possible sans espaces superflus ni sauts de ligne), "pretty" (pour une version lisible de la même chose, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

--no-pager

Ne pas utiliser de pagineur pour la sortie.

La sortie générée montre la base de données actuelle des périphériques en

essayez en format concis. Chaque ligne affichée est précédée de l'un des caractères suivants :

Tableau 1. Préfixes de sortie de udevadm info

Préfixe Signification
"P:" Chemin d'accès de l'appareil dans /sys/
"M:" Nom de l'appareil dans /sys/ (c'est-à-dire le dernier composant de "P:")
"R:" Numéro de l'appareil dans /sys/ (c'est-à-dire le suffixe numérique du dernier composant de "P:")
"J:" ID de l'appareil
"U:" Sous-système du noyau
"B:" Sous-système du pilote
"T:" Type d'appareil du noyau dans le sous-système
"D:" Nœud de périphérique du noyau majeur/mineur
"I:" Index de l'interface réseau
"N:" Nom du nœud de périphérique du noyau
"L:" Priorité du lien symbolique du nœud de périphérique
"S:" Lien symbolique du nœud de périphérique
"Q:" Numéro de séquence du périphérique de bloc (DISKSEQ)
"V:" Pilote attaché
"E:" Propriété de l'appareil

udevadm trigger [options...] [devpath|syspath|id|unit...]

Demande des événements de périphériques au noyau. Principalement utilisé pour rejouer des événements au moment du plug à froid du système.

Prend des spécifications d'appareils comme arguments positionnels. Voir la description de udevadm info ci-dessus.

-v, --verbose

Affiche la liste des périphériques qui seront déclenchés.

-n, --dry-run

Ne déclenche pas réellement l'événement.

-q, --quiet

Supprime la journalisation des erreurs lors du déclenchement des événements.

Ajouté dans la version 248.

-t, --type=TYPE

Déclenche un type spécifique d'appareils. Les types valides sont "all", "devices" et "subsystems". La valeur par défaut est "devices".

-c, --action=ACTION

Type d'événement à déclencher. Les actions possibles sont "add", "remove", "change", "move", "online", "offline", "bind" et "unbind". De plus, la valeur spéciale "help" peut être utilisée pour lister les actions possibles. La valeur par défaut est "change".

--prioritized-subsystem=SUBSYSTEM[,SUBSYSTEM...]

Prend une liste de sous-systèmes séparés par des virgules. Lors du déclenchement d'événements pour des appareils, les appareils des sous-systèmes spécifiés et leurs parents sont déclenchés en premier. Par exemple, si --prioritized-subsystem=block,net, alors d'abord tous les appareils de bloc et leurs parents sont déclenchés, ensuite tous les appareils réseau et leurs parents sont déclenchés, et enfin les autres appareils sont déclenchés. Cette option peut être spécifiée plusieurs fois, et dans ce cas les listes de sous-systèmes seront fusionnées. C'est-à-dire, --prioritized-subsystem=block --prioritized-subsystem=net est équivalent à --prioritized-subsystem=block,net.

Ajouté dans la version 251.

-s, --subsystem-match=SUBSYSTEM

Déclenche des événements pour les appareils appartenant à un sous-système correspondant. Cette option prend en charge la correspondance de motifs de style shell. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par OU, c'est-à-dire que tous les appareils de chaque sous-système sont déclenchés.

-S, --subsystem-nomatch=SUBSYSTEM

Ne déclenche pas d'événements pour les appareils appartenant à un sous-système correspondant. Cette option prend en charge la correspondance de motifs de style shell. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par ET, c'est-à-dire que les appareils qui ne correspondent à aucun des sous-systèmes spécifiés sont déclenchés.

-a, --attr-match=ATTRIBUTE=VALUE

Déclenche des événements pour les appareils dont un attribut sysfs correspond. Si une valeur est spécifiée avec le nom de l'attribut, le contenu de l'attribut est comparé à la valeur donnée en utilisant la correspondance de motifs de style shell. Si aucune valeur n'est spécifiée, l'existence de l'attribut sysfs est vérifiée. Lorsque cette option est spécifiée plusieurs fois, chaque résultat correspondant est combiné par ET, c'est-à-dire que seuls les appareils possédant tous les attributs spécifiés sont déclenchés.

-A, --attr-nomatch=ATTRIBUTE=VALUE

Ne déclenche pas d'événements pour les appareils dont un attribut sysfs correspond. Si une valeur est spécifiée avec le nom de l'attribut, le contenu de l'attribut est comparé à la valeur donnée en utilisant la correspondance de motifs de style shell. Si aucune valeur n'est spécifiée, l'existence de l'attribut sysfs est vérifiée. Lorsque cette option est spécifiée plusieurs fois, chaque résultat correspondant est combiné par ET, c'est-à-dire que seuls les appareils qui ne possèdent aucun des attributs spécifiés sont déclenchés.

-p, --property-match=PROPERTY=VALUE

Déclenche des événements pour les appareils ayant une valeur de propriété correspondante. Cette option prend en charge la correspondance de motifs de style shell. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par OU, c'est-à-dire que les appareils qui possèdent l'une des propriétés spécifiées sont déclenchés.

-g, --tag-match=TAG

Déclenche des événements pour les appareils ayant une balise correspondante. Lorsque cette option est spécifiée plusieurs fois, chaque résultat correspondant est combiné par ET, c'est-à-dire que les appareils qui possèdent toutes les balises spécifiées sont déclenchés.

-y, --sysname-match=NAME

Déclenche des événements pour les appareils pour lesquels le dernier composant (c'est-à-dire le nom de fichier) du chemin /sys/ correspond au PATH spécifié. Cette option prend en charge la correspondance de motifs de style shell. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par OU, c'est-à-dire que tous les appareils possédant l'un des NAME spécifiés sont déclenchés.

--name-match=NAME

Déclenche des événements pour les appareils dont le chemin d'accès de l'appareil correspond. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par OU, c'est-à-dire que tous les appareils spécifiés sont déclenchés.

Ajouté dans la version 218.

-b, --parent-match=SYSPATH

Déclenche des événements pour tous les enfants d'un appareil donné. Lorsque cette option est spécifiée plus d'une fois, chaque résultat correspondant est combiné par OU, c'est-à-dire que tous les enfants de chaque appareil spécifié sont déclenchés.

--initialized-match, --initialized-nomatch

Lorsque --initialized-match est spécifié, déclenche des événements pour les appareils qui sont déjà initialisés par systemd-udevd, et saute les appareils qui ne sont pas encore initialisés.

Lorsque --initialized-nomatch est spécifié, déclenche des événements pour les appareils qui ne sont pas encore initialisés par systemd-udevd, et saute les appareils qui sont déjà initialisés.

En général, il est essentiel que les applications qui ont l'intention d'utiliser une telle correspondance s'assurent qu'une règle udev appropriée est installée et qui définit au moins une propriété sur les appareils qui doivent correspondre. Voir également la section Appareils Initialisés ci-dessous pour plus de détails.


Attention
--initialized-nomatch peut potentiellement faire gagner un temps considérable par rapport au redéclenchement de tous les appareils du système et peut, par exemple, être utilisé pour optimiser le temps de démarrage. Cependant, son utilisation n'est généralement pas sûre dans une séquence de démarrage. En particulier, lorsque les règles udev pour un appareil dépendent de ses appareils parents (par exemple, les clés "ATTRS" ou "IMPORT{parent}", voir udev(7) pour plus de détails), l'état final de l'appareil devient facilement instable avec cette option.
Ajouté dans la version 251.

--include-parents

Déclenche les appareils parents des appareils trouvés même si les parents ne correspondent pas à la condition de filtre. Ceci est utile si nous souhaitons limiter les activités de coldplug à certains appareils ou sous-systèmes.

Ajouté dans la version 258.

-w, --settle

En plus de déclencher des événements, attend également que ces événements soient terminés. Notez que cela est différent de l'appel à udevadm settle. udevadm settle attend que tous les événements soient terminés. Cette option attend uniquement que les événements déclenchés par la même commande soient terminés.

Ajouté dans la version 238.

--uuid

Déclenche les événements de périphériques synthétiques et leur associe un UUID randomisé. Ces UUID sont imprimés sur la sortie standard, une ligne pour chaque événement. Ces UUID sont inclus dans le bloc d'environnement uevent (dans la propriété "SYNTH_UUID=") et peuvent être utilisés pour suivre la livraison des événements générés.

Ajouté dans la version 249.

--wait-daemon[=SECONDS]

Avant de déclencher les uevents, attend que le démon systemd-udevd soit initialisé. Peut éventuellement prendre une valeur de délai d'attente. Le délai d'attente par défaut est de 5 secondes. Ceci équivaut à appeler udevadm control --ping avant udevadm trigger.

Ajouté dans la version 241.

De plus, des arguments positionnels optionnels peuvent être utilisés pour spécifier des noms d'appareils ou des chemins sys. Ils doivent commencer respectivement par /dev/ ou /sys/.

udevadm settle [options...]

Surveille la file d'attente des événements udev et se termine si tous les événements actuels sont traités.

-t, --timeout=SECONDS

Nombre maximum de secondes à attendre que la file d'attente des événements devienne vide. La valeur par défaut est de 120 secondes. Une valeur de 0 vérifiera si la file est vide et renverra toujours immédiatement. Une valeur non nulle renverra un code de sortie de 0 si la file est devenue vide avant l'expiration du délai, sinon une valeur non nulle.

-E, --exit-if-exists=FILE

Arrête d'attendre si le fichier existe.

Voir systemd-udev-settle.service(8) pour plus d'informations.

udevadm control options...

Modifie l'état interne du démon udev en cours d'exécution.

-e, --exit

Signale et attend la sortie de systemd-udevd. Aucune option sauf --timeout ne peut être spécifiée après cette option. Notez que systemd-udevd.service contient Restart=always et, par conséquent, cette option redémarre systemd-udevd. Si vous souhaitez arrêter systemd-udevd.service, veuillez utiliser la commande suivante : 
systemctl stop systemd-udevd-control.socket systemd-udevd-kernel.socket systemd-udevd-varlink.socket systemd-udevd.service

-l, --log-level=valeur

Définit le niveau de journalisation interne de systemd-udevd. Les valeurs valides sont les priorités syslog numériques ou leurs représentations textuelles : emerg, alert, crit, err, warning, notice, info et debug.

-s, --stop-exec-queue

Signale à systemd-udevd d'arrêter l'exécution des nouveaux événements. Les événements entrants seront mis en file d'attente.

-S, --start-exec-queue

Signale à systemd-udevd d'activer l'exécution des événements.

-R, --reload

Signale à systemd-udevd de recharger les fichiers de règles et d'autres bases de données comme l'index des modules du noyau. Le rechargement des règles et des bases de données n'applique aucune modification aux appareils existants ; la nouvelle configuration ne sera appliquée qu'aux nouveaux événements.

-p, --property=CLE=valeur

Définit une propriété globale pour tous les événements.

-m, --children-max=valeur

Définit le nombre maximum d'événements que systemd-udevd traitera simultanément. Lorsqu'il est spécifié 0, le maximum est déterminé en fonction des ressources système.

--ping

Envoie un message ping à systemd-udevd et attend la réponse. Ceci peut être utile pour vérifier que le démon systemd-udevd est en cours d'exécution.

Ajouté dans la version 241.

--trace=BOOL

Active/désactive la journalisation de trace dans systemd-udevd.

Ajouté dans la version 258.

--revert

Annule les paramètres précédemment définis avec la commande udevadm control. Lorsqu'il est spécifié, les paramètres définis avec -l/--log-level=, --trace, -m/--children-max= et -p/--property= seront effacés.

Ajouté dans la version 258.

-t, --timeout=secondes

Le temps maximum en secondes à attendre une réponse de systemd-udevd.

--load-credentials

Lorsqu'il est spécifié, les identifiants suivants sont utilisés lorsqu'ils sont passés :

udev.conf.*

Ces identifiants doivent contenir des données de configuration valides de udev.conf(5). Pour chaque identifiant correspondant, un fichier séparé est créé. Exemple : un identifiant passé udev.conf.50-foobar sera copié dans un fichier de configuration /run/udev/udev.conf.d/50-foobar.conf.

Ajouté dans la version 256.

udev.rules.*

Ces identifiants doivent contenir des règles valides de udev(7). Pour chaque identifiant correspondant, un fichier séparé est créé. Exemple : un identifiant passé udev.rules.50-foobar sera copié dans un fichier de configuration /run/udev/rules.d/50-foobar.rules.

Ajouté dans la version 256.

Notez que cela n'implique *pas* l'option --reload. Donc, si systemd-udevd est déjà en cours d'exécution, veuillez envisager de spécifier également -reload pour que les fichiers de règles udev copiés soient utilisés par systemd-udevd.

Ajouté dans la version 256.

udevadm monitor [options...]

Écoute les uevents du noyau et les événements envoyés par une règle udev et affiche le devpath de l'événement sur la console. Il peut être utilisé pour analyser le timing des événements, en comparant les horodatages du uevent du noyau et de l'événement udev.

-k, --kernel

Affiche les uevents du noyau.

-u, --udev

Affiche l'événement udev après le traitement des règles.

-p, --property

Affiche également les propriétés de l'événement.

-s, --subsystem-match=chaîne[/chaîne]

Filtre les uevents du noyau et les événements udev par sous-système[/type-dev]. Seuls les événements avec une valeur de sous-système correspondante passeront. Lorsque cette option est spécifiée plusieurs fois, chaque résultat correspondant est combiné par un OU logique, c'est-à-dire que tous les appareils dans les sous-systèmes spécifiés sont surveillés.

-t, --tag-match=chaîne

Filtre les événements udev par tag. Seuls les événements udev avec un tag donné attaché passeront. Lorsque cette option est spécifiée plusieurs fois, chaque résultat correspondant est combiné par un OU logique, c'est-à-dire que les appareils qui ont l'un des tags spécifiés sont surveillés.

udevadm test [options...] devpath|syspath|id|unit

Simule une exécution d'événement udev pour l'appareil donné et affiche la sortie de débogage. L'option --json= peut être utile pour analyser le résultat final. Voir aussi la section Exemple.

-a, --action=ACTION

Type d'événement à simuler. Les actions possibles sont "add", "remove", "change", "move", "online", "offline", "bind" et "unbind". De plus, la valeur spéciale "help" peut être utilisée pour lister les actions possibles. La valeur par défaut est "add".

-N, --resolve-names=early|late|never

Spécifie quand udevadm doit résoudre les noms d'utilisateurs et de groupes spécifiés dans les règles udev. Lorsqu'il est réglé sur early (par défaut), les noms seront résolus lors de l'analyse des règles. Lorsqu'il est réglé sur late, les noms seront résolus pendant le traitement de l'événement. Lorsqu'il est réglé sur never, les noms ne seront jamais résolus et les règles udev pertinentes seront ignorées.

Ajouté dans la version 209.

-D DIR, --extra-rules-dir=DIR

Charge également les fichiers de règles udev du répertoire spécifié. Cette option peut être spécifiée plusieurs fois. Elle peut être utile pour déboguer les règles udev en copiant certains fichiers de règles udev dans un répertoire temporaire, en les modifiant et en spécifiant le répertoire avec cette option. Les fichiers trouvés dans les répertoires spécifiés ont une priorité plus élevée que les fichiers de règles dans les répertoires udev/rules.d par défaut utilisés par systemd-udevd. Voir udev(7) pour plus de détails sur les chemins de recherche.

Ajouté dans la version 258.

-v, --verbose

Affiche les journaux détaillés lors du traitement des règles udev.

Ajouté dans la version 258.

--json=MODE

Affiche la sortie formatée en JSON. Attend l'une des valeurs suivantes : "short" (pour une sortie aussi courte que possible sans espaces blancs superflus ni sauts de ligne), "pretty" (pour une version esthétique de celle-ci, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

udevadm test-builtin [options...] command devpath|file|unit

Exécute une commande intégrée COMMAND pour l'appareil DEVPATH et affiche la sortie de débogage.

-a, --action=ACTION

Type d'événement à simuler. Les actions possibles sont "add", "remove", "change", "move", "online", "offline", "bind" et "unbind". De plus, la valeur spéciale "help" peut être utilisée pour lister les actions possibles. La valeur par défaut est "add".

Ajouté dans la version 250.

udevadm verify [options...] [fichiers...]

Vérifie la correction syntaxique, sémantique et stylistique des fichiers de règles udev.

Les arguments positionnels peuvent être utilisés pour spécifier un ou plusieurs fichiers à vérifier. Chaque argument doit être un chemin absolu vers un fichier de règles udev ou un répertoire contenant des fichiers de règles, ou un nom de fichier de règles udev (par exemple, 99-systemd.rules). Si un nom de fichier est spécifié, le fichier sera recherché dans les répertoires udev/rules.d qui sont traités par systemd-udevd, et recherché dans le répertoire de travail courant s'il n'est pas trouvé. Si aucun fichier n'est spécifié, les règles udev sont lues à partir des fichiers situés dans les mêmes répertoires udev/rules.d qui sont traités par systemd-udevd. Voir udev(7) pour plus de détails sur les chemins de recherche.

Le code de sortie est 0 si tous les fichiers de règles udev spécifiés sont syntaxiquement, sémantiquement et stylistiquement corrects, et un code d'erreur non nul sinon.

-N, --resolve-names=early|late|never

Spécifie quand udevadm doit résoudre les noms d'utilisateurs et de groupes spécifiés dans les règles udev. Lorsqu'il est réglé sur early (par défaut), les noms seront résolus lors de l'analyse des règles. Lorsqu'il est réglé sur late, les noms ne seront pas vérifiés, car systemd-udevd résout les noms lors de chaque événement traité. Lorsqu'il est réglé sur never, les noms ne seront jamais résolus et les règles pertinentes seront ignorées.

udevadm lock [options...] commande...

udevadm lock prend un verrou exclusif (arbitraire) sur un périphérique bloc (ou tous les périphériques spécifiés), conformément à la section Verrouillage de l'accès aux périphériques bloc[2] et invoque un programme avec les verrous pris. Lorsque le programme invoqué se termine, les verrous sont automatiquement libérés et sa valeur de retour est propagée comme code de sortie de udevadm lock.

Cet outil est particulièrement utile pour s'assurer que systemd-udevd.service(8) ne sonde pas un périphérique bloc pendant que des modifications y sont apportées, par exemple lors de la création de partitions ou du formatage de systèmes de fichiers. Notez que de nombreux outils qui interagissent avec les périphériques blocs prennent nativement en charge la prise de verrous pertinents, voir par exemple le commutateur --lock de sfdisk(8).

La commande attend au moins un périphérique bloc spécifié via --device= ou --backing=, et une ligne de commande à exécuter comme arguments.

--device=PÉRIPHÉRIQUE, -d PÉRIPHÉRIQUE

Prend un chemin vers un nœud de périphérique du périphérique à verrouiller. Ce commutateur peut être utilisé plusieurs fois (et en combinaison avec --backing=) afin de verrouiller plusieurs périphériques. Si un nœud de périphérique de partition bloc est spécifié, le périphérique bloc «  complet  » contenant est automatiquement déterminé et utilisé pour le verrouillage, conformément à la spécification. Si plusieurs périphériques sont spécifiés, ils sont dédupliqués, triés par le majeur/mineur de leurs nœuds de périphérique, puis verrouillés dans l'ordre.

Ce commutateur doit être utilisé au moins une fois pour spécifier au moins un périphérique à verrouiller. (Alternativement, utilisez --backing=, voir ci-dessous.)

Ajouté dans la version 251.

--backing=CHEMIN, -b CHEMIN

Si un chemin vers un nœud de périphérique est spécifié, identique à --device=. Cependant, ce commutateur accepte alternativement un chemin vers un fichier ordinaire ou un répertoire, auquel cas le périphérique bloc du système de fichiers sur lequel le fichier/répertoire réside est automatiquement déterminé et utilisé comme s'il avait été spécifié avec --device=.

Ajouté dans la version 251.

--timeout=SECS, -t SECS

Spécifie combien de temps attendre au maximum avant que tous les verrous ne puissent être pris. Prend une valeur en secondes, ou dans les unités de temps habituelles prises en charge, voir systemd.time(7). Si spécifié à zéro, la tentative de verrouillage est effectuée et si elle échoue, l'invocation échoue immédiatement. Si elle est passée comme «  infinity  » (la valeur par défaut), l'invocation attendra indéfiniment jusqu'à ce que le verrou puisse être acquis. Si le verrou ne peut pas être pris dans le temps spécifié, la commande spécifiée ne sera pas exécutée et l'invocation échouera.

Ajouté dans la version 251.

--print, -p

Au lieu de verrouiller les périphériques spécifiés et d'exécuter une commande, affiche simplement les chemins des périphériques qui seraient verrouillés, et n'exécute aucune commande. Cette commande est utile pour déterminer le périphérique bloc «  complet  » dans le cas où un nœud de périphérique de partition est spécifié. Les périphériques seront triés par leur numéro majeur de nœud de périphérique comme clé d'ordre primaire et le numéro mineur comme clé d'ordre secondaire (c'est-à-dire qu'ils seront affichés dans l'ordre dans lequel ils seraient verrouillés). Notez que le nombre de lignes imprimées ici peut être inférieur au nombre de commutateurs --device= et --backing= spécifiés au cas où ceux-ci résolvent les mêmes périphériques «  complets  ».

Ajouté dans la version 251.

PÉRIPHÉRIQUES INITIALISÉS

Les périphériques initialisés sont ceux pour lesquels au moins une règle udev a déjà terminé son exécution – pour toute action autre que « remove » – qui a défini une propriété ou un autre paramètre de périphérique (et qui a donc une entrée dans la base de données des périphériques udev). Les périphériques ne sont plus considérés comme initialisés si une action « remove » est vue pour eux (ce qui supprime leur entrée dans la base de données des périphériques udev). Notez que les périphériques qui n'ont aucune règle udev ne sont jamais considérés comme initialisés, mais peuvent toujours être annoncés via l'API sd-device (ou similaire).

EXEMPLE

Exemple 1. Formatage d'un système de fichiers

Prend un verrou sur le périphérique bloc sous-jacent lors de la création d'un système de fichiers, pour s'assurer que systemd-udevd ne sonde ni n'annonce le nouveau superbloc avant qu'il ne soit complètement écrit :

# udevadm lock --device=/dev/sda1 mkfs.ext4 /dev/sda1

Exemple 2. Formatage d'un système de fichiers RAID

Similaire, mais prend des verrous sur plusieurs périphériques à la fois :

# udevadm lock --device=/dev/sda1 --device=/dev/sdb1 mkfs.btrfs /dev/sda1 /dev/sdb1

Exemple 3. Copie d'un système de fichiers

Prend un verrou sur le périphérique bloc sous-jacent lors de la copie d'une image de système de fichiers préparée, pour s'assurer que systemd-udevd ne sonde ni n'annonce le nouveau superbloc avant qu'il ne soit entièrement écrit :

# udevadm lock -d /dev/sda1 dd if=fs.raw of=/dev/sda1

Exemple 4. Prédiction du renommage d'une interface réseau

Pour prédire un nom d'interface réseau, udevadm test peut être utilisé :

$ udevadm test /sys/class/net/wlan0 --json=pretty 2>/dev/null | jq .networkInterface.name
"wlp59s0"

Exemple 5. Prédiction des liens symboliques d'un nœud de périphérique

Pour prédire les liens symboliques vers un nœud de périphérique, udevadm test peut être utilisé :

$ udevadm test /dev/nvme0n1p1 --json=pretty 2>/dev/null | jq .node.symlinks
[
  "/dev/disk/by-diskseq/1-part1",
  "/dev/disk/by-id/nvme-WDC_PC_SN720_SDAQNTW-512G-1001_192290802247-part1",
  "/dev/disk/by-id/nvme-WDC_PC_SN720_SDAQNTW-512G-1001_192290802247_1-part1",
  "/dev/disk/by-id/nvme-eui.1922908022470001001b448b44ccb9d6-part1",
  "/dev/disk/by-path/pci-0000:3c:00.0-nvme-1-part/by-partnum/1",
  "/dev/disk/by-path/pci-0000:3c:00.0-nvme-1-part1"
]
$ udevadm test /dev/input/event3 --json=pretty 2>/dev/null | jq .node.symlinks
[
  "/dev/input/by-path/platform-i8042-serio-0-event-kbd"
]
