NOM

uconv - convertir des données d'un encodage à un autre

SYNTAXE

uconv [ -h, -?, --help ] [ -V, --version ] [ -s, --silent ] [ -v, --verbose ] [ -l, --list | -l, --list-code code | --default-code | -L, --list-transliterators ] [ --canon ] [ -x translitération ] [ --to-callback callback | -c ] [ --from-callback callback | -i ] [ --callback callback ] [ --fallback | --no-fallback ] [ -b, --block-size taille ] [ -f, --from-code encodage ] [ -t, --to-code encodage ] [ --add-signature ] [ --remove-signature ] [ -o, --output fichier ] [ fichier... ]

DESCRIPTION

uconv convertit, ou transcode, chaque fichier donné (ou son entrée standard si aucun fichier n'est spécifié) d'un encodage à un autre. La transcodage est effectué en utilisant Unicode comme encodage pivot (c'est-à-dire que les données sont d'abord transcodées de leur encodage d'origine vers Unicode, puis d'Unicode vers l'encodage de destination).

Si un encodage n'est pas spécifié ou est -, l'encodage par défaut est utilisé. Ainsi, appeler uconv sans encodage offre un moyen facile de valider et de nettoyer les fichiers de données pour une consommation ultérieure par des outils nécessitant des données dans l'encodage par défaut.

Lors de l'appel de uconv, il est possible de spécifier des callbacks qui sont utilisés pour gérer les caractères invalides dans l'entrée, ou les caractères qui ne peuvent pas être transcodés vers l'encodage de destination. Certains encodages, par exemple, offrent un caractère de substitution par défaut qui peut être utilisé pour représenter l'occurrence de tels caractères dans l'entrée. D'autres callbacks offrent une représentation visuelle utile des données invalides.

uconv peut également appliquer la transitération spécifiée aux données transcodées, auquel cas la translitération se produira comme une étape intermédiaire, après que les données aient été transcodées en Unicode. La transitération peut être soit une liste de noms de translitérateurs séparés par des points-virgules, soit un ensemble arbitrairement complexe de règles au format des règles de translitération ICU.

Pour les besoins de transcodage, les options de uconv sont compatibles avec celles de iconv(1), ce qui rend facile son remplacement dans les scripts. Il n'est cependant pas nécessairement le cas que les noms d'encodage utilisés par uconv et ICU soient les mêmes que ceux utilisés par iconv(1). De plus, les options qui fournissent des données informatives, telles que le -l, --list offert par certaines variantes de iconv(1) telles que celles de GNU, produisent des données dans un format légèrement différent et plus facile à analyser.

OPTIONS

-h, -?, --help
Affiche l'aide sur l'utilisation et quitte.
-V, --version
Affiche la version de uconv et quitte.
-s, --silent
Supprime les messages pendant l'exécution.
-v, --verbose
Affiche des messages informatifs supplémentaires pendant l'exécution.
-l, --list
Liste tous les encodages disponibles et quitte.
-l, --list-code code
Liste uniquement l'encodage code et quitte. Si code n'est pas un encodage valide, quitte avec une erreur.
--default-code
Liste uniquement le nom de l'encodage par défaut et quitte.
-L, --list-transliterators
Liste tous les translitérateurs disponibles et quitte.
--canon
Si utilisé avec -l, --list ou --default-code, la liste des encodages est produite dans un format compatible avec convrtrs.txt(5). Si utilisé avec -L, --list-transliterators, affiche un seul nom de translitérateur par ligne.
-x transitération
Exécute la transitération donnée sur les données Unicode transcodées, et utilise les données translatées comme entrée pour le transcodage vers l'encodage de destination.
--to-callback callback
Utilise le callback pour gérer les caractères qui ne peuvent pas être transcodés vers l'encodage de destination. Voir la section CALLBACKS pour les détails sur les callbacks valides.
-c
Omets les caractères invalides de la sortie. Identique à --to-callback skip.
--from-callback callback
Utilise le callback pour gérer les caractères qui ne peuvent pas être transcodés depuis l'encodage d'origine. Voir la section CALLBACKS pour les détails sur les callbacks valides.
-i
Ignore les séquences invalides dans l'entrée. Identique à --from-callback skip.
--callback callback
Utilise le callback pour gérer à la fois les caractères qui ne peuvent pas être transcodés depuis l'encodage d'origine et les caractères qui ne peuvent pas être transcodés vers l'encodage de destination. Voir la section CALLBACKS pour les détails sur les callbacks valides.
--fallback
Utilise le mappage de repli lors du transcodage d'Unicode vers l'encodage de destination.
--no-fallback
N'utilise pas le mappage de repli lors du transcodage d'Unicode vers l'encodage de destination. C'est le comportement par défaut.
-b, --block-size taille
Lit l'entrée par blocs de taille octets à la fois. La taille de bloc par défaut est de 4096.
-f, --from-code encodage
Définit l'encodage d'origine des données à encodage.
-t, --to-code encodage
Transcode les données vers encodage.
--add-signature
Ajoute un caractère de signature Unicode U+FEFF (BOM) si le jeu de caractères de sortie le supporte et n'en ajoute pas déjà un.
--remove-signature
Supprime un caractère de signature Unicode U+FEFF (BOM).
-o, --output fichier
Écrit les données transcodées dans fichier.

CALLBACKS

uconv supporte la spécification de callbacks pour gérer les données invalides. Les callbacks peuvent être définis pour les deux directions de transcodage : de l'encodage d'origine vers Unicode, avec l'option --from-callback, et d'Unicode vers l'encodage de destination, avec l'option --to-callback.

Voici une liste des noms de callback valides, accompagnés d'une description de leur comportement. La liste des callbacks actuellement supportés par uconv est affichée lorsqu'il est appelé avec -h, --help.

substitute
Écrit la séquence de substitution de l'encodage, ou le caractère de remplacement Unicode U+FFFD lors du transcodage vers Unicode.
skip
Ignore les données invalides.
stop
Arrête avec une erreur lors de la rencontre de données invalides. C'est le callback par défaut.
escape
Identique à escape-icu.
escape-icu
Représente les données invalides en utilisant la notation d'échappement ICU. Par exemple, U+FFFE est représenté par `\uFFFE`.

CALLBACKS

escape-icu
Remplace les caractères manquants par une chaîne du format %Uhhhh pour les caractères du plan 0, et %Uhhhh%Uhhhh pour les caractères des plans 1 et supérieurs, où hhhh est la valeur hexadécimale de l'une des unités de code UTF-16 représentant le caractère. Les caractères des plans 1 et supérieurs sont écrits comme une paire d'unités de code substituts UTF-16.
escape-java
Remplace les caractères manquants par une chaîne du format \uhhhh pour les caractères du plan 0, et \uhhhh\uhhhh pour les caractères des plans 1 et supérieurs, où hhhh est la valeur hexadécimale de l'une des unités de code UTF-16 représentant le caractère. Les caractères des plans 1 et supérieurs sont écrits comme une paire d'unités de code substituts UTF-16.
escape-c
Remplace les caractères manquants par une chaîne du format \uhhhh pour les caractères du plan 0, et \Uhhhhhhhh pour les caractères des plans 1 et supérieurs, où hhhh et hhhhhhhh sont les valeurs hexadécimales du point de code Unicode.
escape-xml
Identique à escape-xml-hex.
escape-xml-hex
Remplace les caractères manquants par une chaîne du format &#xhhhh;, où hhhh est la valeur hexadécimale du point de code Unicode.
escape-xml-dec
Remplace les caractères manquants par une chaîne du format &#nnnn;, où nnnn est la valeur décimale du point de code Unicode.
escape-unicode
Remplace les caractères manquants par une chaîne du format {U+hhhh}, où hhhh est la valeur hexadécimale du point de code Unicode. Cette chaîne hexadécimale est de longueur variable et peut utiliser de 4 à 6 chiffres. C'est le format universellement utilisé pour désigner un point de code Unicode dans la littérature, délimité par des accolades pour une reconnaissance facile de ces substitutions dans la sortie.

EXEMPLES

Convertir des données d'un encodage donné vers l'encodage de la plateforme :

$ uconv -f encodage

Vérifier si un fichier contient des données valides pour un encodage donné :

$ uconv -f encodage -c fichier >/dev/null

Convertir un fichier UTF-8 vers un encodage donné et s'assurer que le texte résultant est adapté à n'importe quelle version de HTML :

$ uconv -f utf-8 -t encodage \
--callback escape-xml-dec fichier

Afficher les noms des points de code Unicode dans un fichier UTF :

$ uconv -f utf-8 -x any-name fichier

Afficher le nom d'un point de code Unicode dont la valeur est connue (U+30AB dans cet exemple) :

$ echo '\u30ab' | uconv -x 'hex-any; any-name'; echo
{KATAKANA LETTER KA}{LINE FEED}
$

(Les noms sont délimités par des accolades. De plus, le nom du terminateur de ligne est également affiché.)

Normaliser les données UTF-8 en utilisant Unicode NFKC, supprimer tous les caractères de contrôle et mapper les Katakana en Hiragana :

$ uconv -f utf-8 -t utf-8 \
-x '::nfkc; [:Cc:] >; ::katakana-hiragana;'

AVERTISSEMENTS ET BUGS

uconv signale les erreurs comme survenant au premier octet invalide rencontré. Cela peut être déroutant pour les utilisateurs de GNU iconv(1), qui signale les erreurs comme survenant au premier octet d'une séquence invalide. Pour les jeux de caractères ou les encodages multi-octets, cela signifie que les positions d'erreur de uconv peuvent être à un décalage ultérieur dans le flux d'entrée par rapport à ce qui serait le cas avec GNU iconv(1).

Le rapport des positions d'erreur lorsqu'un translittérateur est utilisé peut être inexact ou indisponible. Dans ce cas, uconv signalera le décalage dans le flux de sortie auquel l'erreur s'est produite.
