uplevel(n) Commandes intégrées Tcl uplevel(n)

NOM

uplevel - Exécuter un script dans une autre frame de pile

SYNOPSIS

uplevel ?niveau? arg ?arg ...?

DESCRIPTION

Tous les arguments arg sont concaténés comme s'ils avaient été passés à concat ; le résultat est ensuite évalué dans le contexte de variables indiqué par niveau. Uplevel retourne le résultat de cette évaluation.

Si niveau est un entier, il indique une distance (vers le haut dans la pile d'appels de procédure) à parcourir avant d'exécuter la commande. Si niveau consiste en # suivi d'un nombre, alors le nombre indique un numéro de niveau absolu. Si niveau est omis, il prend la valeur par défaut 1. Niveau ne peut pas être omis si le premier argument commande commence par un chiffre ou #.

Par exemple, supposons que la procédure a a été appelée depuis le niveau supérieur, et qu'elle a appelé b, et que b a appelé c. Supposons que c invoque la commande uplevel. Si niveau est 1 ou #2 ou omis, alors la commande sera exécutée dans le contexte des variables de b. Si niveau est 2 ou #1, alors la commande sera exécutée dans le contexte des variables de a. Si niveau est 3 ou #0, alors la commande sera exécutée au niveau supérieur (seules les variables globales seront visibles).

La commande uplevel fait disparaître la procédure appelante de la pile d'appels de procédure pendant l'exécution de la commande. Dans l'exemple ci-dessus, supposons que c invoque la commande

uplevel 1 {set x 43; d}

où d est une autre procédure Tcl. La commande set modifiera la variable x dans le contexte de b, et d sera exécutée au niveau 3, comme si elle était appelée depuis b. Si elle exécute à son tour la commande

uplevel {set x 42}

alors la commande set modifiera la même variable x dans le contexte de b : la procédure c n'apparaît pas sur la pile d'appel lorsque d est en cours d'exécution. La commande info level peut être utilisée pour obtenir le niveau de la procédure actuelle.

Uplevel permet d'implémenter de nouveaux construits de contrôle en tant que procédures Tcl (par exemple, uplevel pourrait être utilisé pour implémenter le construit while en tant que procédure Tcl).

Les commandes namespace eval et apply offrent d'autres moyens (outre les appels de procédure) par lesquels le contexte de nommage Tcl peut changer. Elles ajoutent une frame d'appel à la pile pour représenter le contexte de l'espace de noms. Cela signifie que chaque commande namespace eval compte comme un niveau d'appel supplémentaire pour les commandes uplevel et upvar. Par exemple, info level 1 retournera une liste décrivant une commande qui est soit l'appel de procédure le plus externe, soit la commande namespace eval la plus externe. De plus, uplevel #0 évalue un script au niveau supérieur dans l'espace de noms le plus externe (l'espace de noms global).

EXEMPLE

Comme indiqué ci-dessus, la commande uplevel est utile pour créer de nouveaux construits de contrôle. Cet exemple montre comment (sans gestion des erreurs) elle peut être utilisée pour créer une commande do qui est l'équivalent de while, sauf qu'elle effectue toujours le test après avoir exécuté le corps de la boucle :

proc do {body while condition} {
    if {$while ne "while"} {
        error "mot requis manquant"
    }
    set conditionCmd [list expr $condition]
    while {1} {
        uplevel 1 $body
        if {![uplevel 1 $conditionCmd]} {
            break
        }
    }
}
