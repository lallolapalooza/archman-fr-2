uu-shred(1) Manuel des commandes générales uu-shred(1)

NOM

uu-shred - Écrase le(s) FICHIER(s) spécifié(s) de manière répétée, afin de rendre la récupération des données plus difficile, même avec des sondes matérielles très coûteuses.

SYNTAXE

uu-shred [-f|--force] [-n|--iterations] [-s|--size] [-u] [--remove] [-v|--verbose] [-x|--exact] [-z|--zero] [--random-source] [-h|--help] [-V|--version] [fichier]

DESCRIPTION

Écrase le(s) FICHIER(s) spécifié(s) de manière répétée, afin de rendre la récupération des données plus difficile, même avec des sondes matérielles très coûteuses.

OPTIONS

-f, --force
change les permissions pour permettre l'écriture si nécessaire
-n, --iterations <NOMBRE> [défaut : 3]
écrase N fois au lieu du défaut (3)
-s, --size <N>
écrase N octets (suffixes comme K, M, G acceptés)
-u
désalloue et supprime le fichier après l'écrasement
--remove[=<COMMENT>]
comme -u mais donne le contrôle sur COMMENT supprimer ; Voir ci-dessous

[valeurs possibles : unlink, wipe, wipesync]

-v, --verbose
affiche la progression
-x, --exact
n'arrondit pas les tailles de fichier au bloc complet supérieur ; c'est le défaut pour les fichiers non réguliers
-z, --zero
ajoute un dernier écrasement avec des zéros pour masquer l'écrasement
--random-source
prend des octets aléatoires de FICHIER
-h, --help
Affiche l'aide
-V, --version
Affiche la version
[fichier]

EXTRA

Supprime le(s) FICHIER(s) si --remove (-u) est spécifié. Par défaut, les fichiers ne sont pas supprimés car il est courant d'opérer sur des fichiers de périphériques comme /dev/hda, et ces fichiers ne doivent généralement pas être supprimés.

ATTENTION : Notez que shred repose sur une hypothèse très importante : que le système de fichiers écrase les données sur place. C'est la manière traditionnelle de faire les choses, mais de nombreuses conceptions modernes de systèmes de fichiers ne satisfont pas cette hypothèse. Voici des exemples de systèmes de fichiers sur lesquels shred n'est pas efficace, ou n'est pas garanti d'être efficace dans tous les modes du système de fichiers :


- systèmes de fichiers log-structurés ou journalisés, tels que ceux fournis avec
AIX et Solaris (et JFS, ReiserFS, XFS, Ext3, etc.)


- systèmes de fichiers qui écrivent des données redondantes et continuent même si certaines écritures échouent, tels que les systèmes de fichiers basés sur RAID


- systèmes de fichiers qui créent des instantanés, tels que le serveur NFS de Network Appliance


- systèmes de fichiers qui mettent en cache dans des emplacements temporaires, tels que les clients NFS
version 3


- systèmes de fichiers compressés

Dans le cas des systèmes de fichiers ext3, l'avertissement ci-dessus s'applique (et shred est donc d'efficacité limitée) uniquement en mode data=journal, qui journalise les données du fichier en plus des métadonnées. Dans les modes data=ordered (par défaut) et data=writeback, shred fonctionne comme d'habitude. Les modes de journalisation d'Ext3 peuvent être modifiés en ajoutant l'option data=quelquechose aux options de montage pour un système de fichiers particulier dans le fichier /etc/fstab, comme documenté dans la page man de mount (`man mount`).

De plus, les sauvegardes de systèmes de fichiers et les miroirs distants peuvent contenir des copies du fichier qui ne peuvent pas être supprimées, et qui permettront de récupérer un fichier écrasé ultérieurement.
