update(n) Commandes intégrées Tcl update(n)

NOM

update - Traite les événements en attente et les rappels inactifs

SYNOPIS

update ?idletasks?

DESCRIPTION

Cette commande est utilisée pour mettre l'application “à jour” en entrant dans la boucle d'événements de manière répétée jusqu'à ce que tous les événements en attente (y compris les rappels inactifs) aient été traités.

Si le mot-clé idletasks est spécifié comme argument de la commande, alors aucun nouvel événement ou erreur n'est traité ; seuls les rappels inactifs sont appelés. Cela provoque l'exécution immédiate des opérations normalement différées, telles que les mises à jour de l'affichage et les calculs de disposition des fenêtres.

La commande update idletasks est utile dans les scripts où des modifications ont été apportées à l'état de l'application et où vous souhaitez que ces modifications apparaissent immédiatement à l'écran, plutôt que d'attendre la fin du script. La plupart des mises à jour d'affichage sont effectuées en tant que rappels inactifs, donc update idletasks les exécutera. Cependant, certains types de mises à jour ne se produisent qu'en réponse à des événements, tels que ceux déclenchés par des changements de taille de fenêtre ; ces mises à jour ne se produiront pas avec update idletasks.

La commande update sans options est utile dans les scripts où vous effectuez un calcul de longue durée mais souhaitez que l'application réponde aux événements tels que les interactions de l'utilisateur ; si vous appelez update occasionnellement, les entrées utilisateur seront traitées lors du prochain appel à update.

EXEMPLE

Exécutez des calculs pendant environ une seconde, puis terminez :

set x 1000
set done 0
after 1000 set done 1
while {!$done} {
    # Un exemple très idiot !
    set x [expr {log($x) ** 2.8}]
    # Vérifier si notre limite de temps a été atteinte. Ceci donnerait
    # également une chance de servir les sockets réseau et, si
    # le paquet Tk est chargé, de mettre à jour une interface utilisateur.
    update
}
