getutent(3) Manuel des fonctions de bibliothèque getutent(3)

NOM

getutent, getutid, getutline, pututline, setutent, endutent, utmpname — accéder aux entrées du fichier utmp

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPTION

Les nouvelles applications doivent utiliser les fonctions « utmpx » spécifiées par POSIX.1 ; voir NORMES.

utmpname() définit le chemin du fichier au format utmp pour que les autres fonctions utmp y accèdent. Si utmpname() n'est pas utilisé pour définir le chemin avant que les autres fonctions ne soient utilisées, elles supposent _PATH_UTMP, tel que défini dans <paths.h>.

setutent() rembobine le pointeur de fichier au début du fichier utmp. Il est généralement conseillé de l'appeler avant toute autre fonction.

endutent() ferme le fichier utmp. Il doit être appelé lorsque le code utilisateur a fini d'accéder au fichier avec les autres fonctions.

getutent() lit une ligne à partir de la position actuelle du fichier dans le fichier utmp. Il renvoie un pointeur vers une structure contenant les champs de la ligne. La définition de cette structure est montrée dans utmp(5).

getutid() recherche vers l'avant à partir de la position actuelle du fichier dans le fichier utmp en fonction de ut. Si ut->ut_type est l'un de RUN_LVL, BOOT_TIME, NEW_TIME ou OLD_TIME, getutid() trouvera la première entrée dont le champ ut_type correspond à ut->ut_type. Si ut->ut_type est l'un de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS ou DEAD_PROCESS, getutid() trouvera la première entrée dont le champ ut_id correspond à ut->ut_id.

getutline() recherche vers l'avant à partir de la position actuelle du fichier dans le fichier utmp. Il analyse les entrées dont ut_type est USER_PROCESS ou LOGIN_PROCESS et renvoie la première dont le champ ut_line correspond à ut->ut_line.

pututline() écrit la structure utmp ut dans le fichier utmp. Il utilise getutid() pour rechercher l'endroit approprié dans le fichier pour insérer la nouvelle entrée. S'il ne trouve pas d'emplacement approprié pour ut, pututline() ajoutera la nouvelle entrée à la fin du fichier.

VALEUR DE RETOUR

getutent(), getutid() et getutline() renvoient un pointeur vers une struct utmp en cas de succès, et NULL en cas d'échec (ce qui inclut le cas « enregistrement non trouvé »). Cette struct utmp est allouée dans un stockage statique et peut être écrasée par des appels ultérieurs.

En cas de succès, pututline() renvoie ut ; en cas d'échec, il renvoie NULL.

utmpname() renvoie 0 si le nouveau nom a été stocké avec succès, ou -1 en cas d'échec.

En cas d'échec, ces fonctions définissent errno pour indiquer l'erreur.

ERREURS

ENOMEM
Pas assez de mémoire.
ESRCH
Enregistrement non trouvé.

setutent(), pututline() et les fonctions getut*() peuvent également échouer pour les raisons décrites dans open(2).

FICHIERS

/var/run/utmp
base de données des utilisateurs actuellement connectés
/var/log/wtmp
base de données des connexions utilisateur passées

NORMES

Aucune.

HISTORIQUE

XPG2, SVr4.

Dans XPG2 et SVID 2, la fonction pututline() est documentée comme retournant void, et c'est ce qu'elle fait sur de nombreux systèmes (AIX, HP-UX). HP-UX introduit une nouvelle fonction _pututline() avec le prototype donné ci-dessus pour pututline().

Toutes ces fonctions sont maintenant obsolètes sur les systèmes non-Linux. POSIX.1-2001 et POSIX.1-2008, suivant SUSv1, n'ont aucune de ces fonctions, mais utilisent à la place

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Ces fonctions sont fournies par glibc, et effectuent la même tâche que leurs équivalents sans le « x », mais utilisent struct utmpx, définie sous Linux comme étant identique à struct utmp. Pour être complet, glibc fournit également utmpxname(), bien que cette fonction ne soit pas spécifiée par POSIX.1.

Sur certains autres systèmes, la structure utmpx est un sur-ensemble de la structure utmp, avec des champs supplémentaires, et des versions plus grandes des champs existants, et des fichiers parallèles sont maintenus, souvent /var/*/utmpx et /var/*/wtmpx.

Linux glibc, en revanche, n'utilise pas de fichier utmpx parallèle car sa structure utmp est déjà suffisamment grande. Les fonctions « x » listées ci-dessus ne sont que des alias pour leurs homologues sans le « x » (par exemple, getutxent() est un alias pour getutent()).

NOTES

Notes glibc

Les fonctions ci-dessus ne sont pas sûres pour les threads. glibc ajoute des versions réentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Conditions de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getutent_r(), getutid_r(), getutline_r() :

    _GNU_SOURCE
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */    _SVID_SOURCE || _BSD_SOURCE

Ce sont des extensions GNU, analogues aux fonctions du même nom sans le suffixe _r. L'argument ubuf donne à ces fonctions un emplacement pour stocker leur résultat. En cas de succès, elles renvoient 0, et un pointeur vers le résultat est écrit dans *ubufp. En cas d'erreur, ces fonctions renvoient -1. Il n'y a pas d'équivalents utmpx des fonctions ci-dessus. (POSIX.1 ne spécifie pas de telles fonctions.)

utmpname(3) — archlinux man pages

NAME

utmpname, getutmp, pututline, setutent, endutent, updwtmp, updwtmp-type — utmp file access

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <utmp.h>
void setutent(void);
void endutent(void);
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *id);
struct utmp *getutline(const struct utmp *line);
int pututline(const struct utmp *entry);
void updwtmp(const char *wtmp_file, const struct utmp *entry);
void updwtmp-type(const char *wtmp_file, const struct utmp *entry, int type);
char *getutmp(const struct utmp *utmp, struct utmp *utmpx);
char *getutmpx(const struct utmp *utmpx, struct utmp *utmp);

DESCRIPTION

The utmpname(), getutmp(), pututline(), setutent(), endutent(), getutent(), getutid(), getutline(), updwtmp(), and updwtmp-type() functions provide an interface to the user accounting file utmp.

The utmp file is a database of currently logged-in users. Its format is described in utmp(5).

The functions getutent(), setutent(), and endutent() are used to read the utmp file sequentially. setutent() opens the utmp file and rewinds it to the beginning. getutent() reads the next entry from the file and returns a pointer to it. The data is stored in a static area and the pointer is valid only until the next call to getutent() or setutent(). endutent() closes the file.

The functions getutid() and getutline() search the utmp file for an entry matching either a specific ID (given in id->ut_id) or a specific terminal line (given in line->ut_line), respectively. They return a pointer to the found entry, or NULL if no match is found. Note that getutline() requires the `ut_line` field to be set, and getutid() requires the `ut_id` field to be set.

The function pututline() writes the structure pointed to by entry to the utmp file. If an entry with the same ut_id or ut_line already exists, it is overwritten. If no such entry exists, it is appended to the file. This function may require special privileges.

The functions updwtmp() and updwtmp-type() append the entry specified by entry to the specified wtmp_file (usually /var/log/wtmp). The updwtmp-type() function allows to specify the entry type using the type argument. If type is UT_UNKNOWN, the type from the entry is used. These functions are often used to record login and logout information.

The functions getutmp() and getutmpx() are used to convert between the older utmp structure and the newer utmpx structure (see utmp(5)). getutmp() converts from utmp to utmpx, and getutmpx() converts from utmpx to utmp.

A program should typically use setutent(), pututline(), and endutent() to modify the utmp file.

For adding a new user entry, the ut_type should be USER_PROCESS. The ut_pid should be the process ID, ut_line the terminal name (e.g., 'tty1'), ut_time the current time, and ut_user the username.

To remove an entry, its ut_type should be set to DEAD_PROCESS or USER_PROCESS with all other fields cleared, and then written using pututline().

RETURN VALUE

getutent(), getutid(), and getutline() return a pointer to a struct utmp on success, and NULL on failure or end-of-file. The returned pointer points to static data, and may be overwritten by subsequent calls to these functions.

pututline() returns a pointer to the modified utmp entry on success, and NULL on failure.

updwtmp() and updwtmp-type() do not return a value.

getutmp() and getutmpx() return a pointer to the destination structure (utmpx or utmp, respectively) on success, and NULL on failure.

ERRORS

The functions getutent(), getutid(), getutline(), and pututline() may fail if the utmp file cannot be opened, read, or written. The specific error is indicated by the global variable errno.

FILES

/var/run/utmp (or /var/log/utmp on some systems)

/var/log/wtmp

STANDARDS

The functions getutent(), setutent(), endutent(), getutid(), getutline(), and pututline() are part of the SVr4 ABI. The updwtmp() function is also part of SVr4.

The utmpname() function is not specified by any standard.

The getutmp() and getutmpx() functions are part of X/Open Portability Guide Issue 4.

The updwtmp-type() function is not specified by any standard.

HISTORY

The utmpname(), getutmp(), pututline(), setutent(), endutent(), getutent(), getutid(), getutline(), updwtmp(), and updwtmp-type() functions first appeared in FreeBSD 2.0.

NOTES

The utmpname() function is not used by the standard library functions. It is provided for backward compatibility and user convenience.

The functions getutent(), getutid(), getutline(), and pututline() operate on the utmp file directly. On systems that use the utmpx file (see utmp(5)), these functions may internally use getutmp() and getutmpx() to perform the necessary conversions.

The pututline() function may require root privileges to write to the utmp file.

The ut_id field is used to uniquely identify a session. It is usually derived from the terminal device name.

EXAMPLES

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
