NOM

user-session-keyring - trousseau de clés par défaut de la session utilisateur

DESCRIPTION

Le trousseau de clés de session utilisateur est un trousseau de clés utilisé pour ancrer des clés pour le compte d'un utilisateur. Chaque UID traité par le noyau possède son propre trousseau de clés de session utilisateur qui est partagé par tous les processus ayant cet UID. Le trousseau de clés de session utilisateur a un nom (description) de la forme _uid_ses.<UID> où <UID> est l'identifiant utilisateur de l'utilisateur correspondant.

Le trousseau de clés de session utilisateur est associé à l'enregistrement que le noyau maintient pour l'UID. Il est créé lors de la première tentative d'accès soit au trousseau de clés de session utilisateur, soit au user-keyring(7), soit au session-keyring(7). Le trousseau de clés reste épinglé en existence tant qu'il y a des processus en cours d'exécution avec cet UID réel ou des fichiers ouverts par ces processus restent ouverts. (Le trousseau de clés peut également être épinglé indéfiniment en le liant à un autre trousseau de clés.)

Le trousseau de clés de session utilisateur est créé à la demande lorsqu'un thread le demande ou lorsqu'un thread demande son session-keyring(7) et que ce trousseau de clés n'existe pas. Dans ce dernier cas, un trousseau de clés de session utilisateur sera créé et, si le trousseau de clés de session n'était pas créé, le trousseau de clés de session utilisateur sera défini comme le trousseau de clés réel du processus.

Le trousseau de clés de session utilisateur est recherché par request_key(2) si le trousseau de clés de session réel n'existe pas et est ignoré sinon.

Une valeur spéciale de numéro de série, KEY_SPEC_USER_SESSION_KEYRING, est définie et peut être utilisée à la place du numéro de série réel du trousseau de clés de session utilisateur du processus appelant.

Depuis l'utilitaire keyctl(1), '@us' peut être utilisé à la place d'un identifiant de clé numérique de la même manière.

Les trousseaux de clés de session utilisateur sont indépendants de clone(2), fork(2), vfork(2), execve(2), et _exit(2) sauf que le trousseau de clés est détruit lorsque l'enregistrement de l'UID est détruit lorsque le dernier processus qui l'épingle se termine.

Si un trousseau de clés de session utilisateur n'existe pas lorsqu'il est accédé, il sera créé.

Plutôt que de s'appuyer sur le trousseau de clés de session utilisateur, il est fortement recommandé—en particulier si le processus s'exécute en tant que root—qu'un session-keyring(7) soit explicitement défini, par exemple par pam_keyinit(8).

NOTES

Le trousseau de clés de session utilisateur a été ajouté pour prendre en charge les situations où un processus n'a pas de trousseau de clés de session, peut-être parce qu'il a été créé via un chemin qui n'impliquait pas PAM (par exemple, peut-être était-ce un démon démarré par inetd(8)). Dans un tel scénario, le trousseau de clés de session utilisateur sert de substitut au session-keyring(7).
