NOM

update-ca-trust - gérer la configuration consolidée et dynamique des certificats d'autorité de certification (CA) et la confiance associée

SYNTAXE

update-ca-trust [extract] [-o DIR|--output=DIR]

DESCRIPTION

update-ca-trust(8) est utilisé pour gérer une fonctionnalité de configuration consolidée et dynamique des certificats d'autorité de certification (CA) et de la confiance associée.

Cette fonctionnalité est disponible pour les nouvelles applications qui lisent les fichiers de configuration consolidés trouvés dans le répertoire /etc/ca-certificates/extracted ou qui chargent le module PKCS#11 p11-kit-trust.so

Des parties de la nouvelle fonctionnalité sont également fournies de manière à la rendre utile pour les applications existantes.

De nombreuses applications existantes s'attendent à trouver les certificats CA et la configuration de confiance à un emplacement fixe, contenus dans des fichiers avec un chemin et un nom particuliers, ou en se référant à un module de confiance PKCS#11 classique fourni par la bibliothèque cryptographique NSS.

La fonctionnalité de configuration dynamique fournit des remplacements fonctionnellement compatibles pour les fichiers de configuration classiques et pour le module de confiance PKCS#11 classique nommé libnssckbi.

Afin de permettre aux applications existantes, qui lisent les fichiers classiques ou accèdent au module classique, d'utiliser la nouvelle fonctionnalité de configuration consolidée et dynamique, les noms de fichiers classiques ont été convertis en liens symboliques. Ces liens symboliques pointent vers une sortie consolidée et créée dynamiquement stockée dans la hiérarchie du répertoire /etc/ca-certificates/extracted.

La sortie est produite en utilisant la commande update-ca-trust (sans paramètres), ou en utilisant la commande update-ca-trust extract. Afin de produire la sortie, un ensemble flexible de configurations sources est lu, comme décrit dans la section CONFIGURATION SOURCE.

En outre, le module PKCS#11 classique est remplacé par un nouveau module PKCS#11 (p11-kit-trust.so) qui lit dynamiquement la même configuration source.

CONFIGURATION SOURCE

La fonctionnalité de configuration dynamique utilise plusieurs répertoires sources qui seront parcourus pour trouver n'importe quel nombre de fichiers sources. Il est important de sélectionner le sous-répertoire correct pour ajouter les fichiers, car le sous-répertoire définit comment les certificats contenus seront approuvés ou désapprouvés, et quels formats de fichiers sont lus.

Les fichiers dans les sous-répertoires de la hiérarchie de répertoires /usr/share/ca-certificates/trust-source/ contiennent des certificats CA et des paramètres de confiance au format de fichier PEM. Les paramètres de confiance trouvés ici seront interprétés avec une faible priorité.

Les fichiers dans les sous-répertoires de la hiérarchie de répertoires /etc/ca-certificates/trust-source/ contiennent des certificats CA et des paramètres de confiance au format de fichier PEM. Les paramètres de confiance trouvés ici seront interprétés avec une haute priorité.

Vous pouvez utiliser les règles suivantes pour décider si vos fichiers de configuration doivent être ajoutés au répertoire /etc ou plutôt à la hiérarchie du répertoire /usr :

•Si vous ajoutez manuellement un fichier de configuration à un système, vous voudrez probablement qu'il remplace toute autre configuration par défaut, et vous devriez très probablement l'ajouter au sous-répertoire correspondant dans la hiérarchie /etc.
•Si vous créez un paquet qui fournit des certificats CA racine supplémentaires, destiné à être distribué à plusieurs systèmes informatiques, mais que vous souhaitez toujours permettre à l'administrateur de remplacer votre liste, alors votre paquet devrait ajouter vos fichiers au sous-répertoire correspondant dans la hiérarchie /usr.
•Si vous créez un paquet censé remplacer les paramètres de confiance système par défaut, destiné à être distribué à plusieurs systèmes informatiques, alors votre paquet devrait installer les fichiers dans le sous-répertoire correspondant de la hiérarchie /etc.

AIDE RAPIDE 1: Pour ajouter un certificat aux formats de fichier PEM ou DER simples à la liste des CA approuvées sur le système :

•ajoutez-le en tant que nouveau fichier dans le répertoire /etc/ca-certificates/trust-source/anchors/
•exécutez update-ca-trust extract

AIDE RAPIDE 2: Si votre certificat est au format étendu BEGIN TRUSTED (qui peut contenir des indicateurs de confiance de désapprobation/blocage, ou des indicateurs de confiance pour des usages autres que TLS), alors :

•ajoutez-le en tant que nouveau fichier dans le répertoire /etc/ca-certificates/trust-source/
•exécutez update-ca-trust extract

Afin d'offrir simplicité et flexibilité, la manière dont les fichiers de certificat sont traités dépend du sous-répertoire dans lequel ils sont installés.

•sous-répertoire des points d'ancrage de confiance simples : /usr/share/ca-certificates/trust-source/anchors/ ou /etc/ca-certificates/trust-source/anchors/
•sous-répertoire de liste de blocage (désapprobation) simple : /usr/share/ca-certificates/trust-source/blocklist/ ou /etc/ca-certificates/trust-source/blocklist/
•répertoire de format étendu : /usr/share/ca-certificates/trust-source/ ou /etc/ca-certificates/trust-source/

Dans les répertoires principaux /usr/share/ca-certificates/trust-source/ ou /etc/ca-certificates/trust-source/, vous pouvez installer un ou plusieurs fichiers dans les formats de fichiers suivants :

•fichiers de certificats qui incluent des indicateurs de confiance, au format de fichier BEGIN/END TRUSTED CERTIFICATE (n'importe quel nom de fichier), qui ont été créés à l'aide de l'outil openssl x509 et des options -addreject -addtrust. Les fichiers bundles avec plusieurs certificats sont pris en charge.
•fichiers au format de fichier p11-kit utilisant l'extension de nom de fichier .p11-kit, qui peuvent (par exemple) être utilisés pour désapprouver des certificats basés sur le numéro de série et le nom de l'émetteur, sans avoir le certificat complet disponible. (Il s'agit actuellement d'un format non documenté, qui sera étendu ultérieurement. Pour des exemples des formats pris en charge, voir les fichiers fournis avec le paquet ca-certificates-mozilla.)
•fichiers de certificats sans indicateurs de confiance, soit au format de fichier DER, soit au format de fichier PEM (BEGIN/END CERTIFICATE) (n'importe quel nom de fichier). Ces fichiers seront ajoutés avec une confiance neutre, ni approuvés ni désapprouvés. Ils seront simplement connus du système, ce qui peut être utile pour aider les logiciels cryptographiques à construire des chaînes de certificats. (Si vous souhaitez qu'un certificat CA dans ces formats de fichiers soit approuvé, vous devez le supprimer de ce répertoire et le déplacer dans le sous-répertoire ./anchors à la place.)

Dans les sous-répertoires anchors /usr/share/ca-certificates/trust-source/anchors/ ou /etc/ca-certificates/trust-source/anchors/, vous pouvez installer un ou plusieurs certificats aux formats de fichier DER ou PEM (BEGIN/END CERTIFICATE). Chaque certificat sera traité comme approuvé à toutes fins.

Dans les sous-répertoires blocklist /usr/share/ca-certificates/trust-source/blocklist/ ou /etc/ca-certificates/trust-source/blocklist/, vous pouvez installer un ou plusieurs certificats aux formats de fichier DER ou PEM (BEGIN/END CERTIFICATE). Chaque certificat sera traité comme désapprouvé à toutes fins.

Veuillez vous référer à la page de manuel x509(1) pour la documentation des formats de fichiers BEGIN/END CERTIFICATE et BEGIN/END TRUSTED CERTIFICATE.

Les applications qui dépendent d'un fichier statique pour une liste de CA approuvées peuvent charger l'un des fichiers trouvés dans le répertoire /etc/ca-certificates/extracted/. Après avoir modifié un fichier dans les répertoires /usr/share/ca-certificates/trust-source/ ou /etc/ca-certificates/trust-source/ ou dans l'un de leurs sous-répertoires, ou après avoir ajouté un fichier, il est nécessaire d'exécuter la commande update-ca-trust extract, afin de mettre à jour les fichiers consolidés dans /etc/ca-certificates/extracted/.

Les applications qui chargent le module PKCS#11 classique en utilisant le nom de fichier libnssckbi.so (qui a été converti en un lien symbolique pointant vers le nouveau module) et toute application capable de charger des modules PKCS#11 et de charger p11-kit-trust.so, bénéficieront de l'ensemble combiné dynamiquement de certificats et d'informations de confiance stockés dans les répertoires /usr/share/ca-certificates/trust-source/ et /etc/ca-certificates/trust-source/.

CONFIGURATION EXTRAITE

Le répertoire /etc/ca-certificates/extracted/ contient des fichiers de paquets de certificats CA générés qui sont créés et mis à jour, en se basant sur la CONFIGURATION SOURCE, en exécutant la commande update-ca-trust extract.

Si votre application n'est pas capable de charger le module PKCS#11 p11-kit-trust.so, alors vous pouvez utiliser ces fichiers dans votre application pour charger une liste

update-ca-trust(8) — Arch manual pages

NAME

update-ca-trust — manage the set of trusted CA certificates

SYNOPSIS

update-ca-trust command [options]

DESCRIPTION

The update-ca-trust utility manages the set of CA certificates that are trusted by the system. It can be used to add, remove, and manage certificates, and to generate consistent trust store files in various formats.

The primary goal is to provide a central mechanism for managing trusted CA certificates, rather than having individual applications manage their own lists of trusted CAs.

The trust information is stored in a set of configuration files, which are then processed by the update-ca-trust extract command to generate consolidated trust store files used by applications.

SOURCE CONFIGURATION

The source configuration files are located in two directories: /usr/share/ca-certificates/trust-source/ and /etc/ca-certificates/trust-source/. The latter has higher priority.

Each file in these directories must be named using the pattern [0-9][0-9]*-*.crt. The leading digits determine the order in which the certificates are processed. Files with lower numbers are processed first.

Each file contains a list of CA certificates in the PEM format. Additionally, each file may be accompanied by a .flags file, which specifies trust attributes for the certificates in the corresponding .crt file. The .flags file contains trust flags on separate lines, for example:

    # Flags for /usr/share/ca-certificates/trust-source/01-example.com.crt
    # This is a comment.
    KRA: KRA = Key Recovery Agent
    SCTLR: SLOTS = 1, TYPE = OCSP, USAGE = TLS_SERVER_AUTH
    default = TLS_SERVER_AUTH,EMAIL

The available trust flags are:

  • TLS_SERVER_AUTH: Trust for TLS server authentication.
  • TLS_CLIENT_AUTH: Trust for TLS client authentication.
  • EMAIL: Trust for E-Mail protection (S/MIME).
  • CODE_SIGNING: Trust for code signing.
  • OBJ_SIGN: Trust for object signing.
  • KRA: Trust for key recovery agent.
  • OCSP_SIGN: Trust for OCSP signing.
  • TIME_STAMP: Trust for time stamping.
  • SECURITY_UPDATE: Trust for security updates.
  • REMOTE_UPDATE: Trust for remote updates.
  • DEFAULT: Default trust attributes.

Trust attributes can be specified with optional parameters, e.g., SLOTS=1,TYPE=OCSP,USAGE=TLS_SERVER_AUTH.

Certificates can also be distrusted by prefixing the trust flag with an exclamation mark (!), e.g., !TLS_SERVER_AUTH.

EXTRACTED CONFIGURATION

The /etc/ca-certificates/extracted/ directory contains the consolidated and automatically generated trust store files, which are used by applications. These files are generated by the update-ca-trust extract command.

Please never manually edit the files stored in this directory, because your changes will be lost and the files automatically overwritten, each time the update-ca-trust extract command gets executed.

In order to install new trusted or distrusted certificates, please rather install them in the respective subdirectory below the /usr/share/ca-certificates/trust-source/ or /etc/ca-certificates/trust-source/ directories, as described in the SOURCE CONFIGURATION section.

The directory /etc/ca-certificates/extracted/ contains a CA certificate bundle in the java keystore file format. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File java-cacerts.jks contains CA certificates trusted for TLS server authentication.

It also contains CA certificate bundle files in the extended BEGIN/END TRUSTED CERTIFICATE file format, as described in the x509(1) manual page. File ca-bundle.trust.crt contains the full set of all trusted or distrusted certificates, including the associated trust flags.

It also contains CA certificate bundle files in the simple BEGIN/END CERTIFICATE file format, as described in the x509(1) manual page. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File tls-ca-bundle.pem contains CA certificates trusted for TLS server authentication. File email-ca-bundle.pem contains CA certificates trusted for E-Mail protection. File objsign-ca-bundle.pem contains CA certificates trusted for code signing.

It also contains a CA certificate bundle ("edk2-cacerts.bin") in the "sequence of EFI_SIGNATURE_LISTs" format, defined in the UEFI-2.7 specification, sections "31.4.1 Signature Database" and "EFI_CERT_X509_GUID". Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File "edk2-cacerts.bin" contains CA certificates trusted for TLS server authentication.

COMMANDS

(absent/empty command)

Same as the extract command described below. (However, the command may print fewer warnings, as this command is being run during rpm package installation, where non-fatal status output is undesired.)

extract

Instruct update-ca-trust to scan the SOURCE CONFIGURATION and produce updated versions of the consolidated configuration files stored below the /etc/ca-certificates/extracted directory hierarchy.

EXTRACT OPTIONS

-o DIR, --output=DIR

Write the extracted trust store into the given directory instead of updating /etc/ca-certificates/extracted.

FILES

/etc/ssl/cert.pem

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/

Classic directory, contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. The files are symbolic links that refer to the output created by the update-ca-trust command.

/etc/ssl/certs/ca-bundle.crt

Classic filename for compatibility with RHEL/Fedora, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/ca-certificates.crt

Classic filename for compatibility with Debian, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/java/cacerts

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/usr/share/ca-certificates/trust-source

Contains multiple, low priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/trust-source

Contains multiple, high priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/extracted

Contains consolidated and automatically generated configuration files for consumption by applications, which are created using the update-ca-trust extract command. Don’t edit files in this directory, because they will be overwritten. See section EXTRACTED CONFIGURATION for additional details.

/etc/ca-certificates/extracted/ca-bundle.trust.crt

File contains a list of CA certificates in the extended BEGIN/END TRUSTED CERTIFICATE file format, which includes trust (and/or distrust) flags specific to certificate usage. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/email-ca-bundle.pem

File contains a list of CA certificates trusted for E-Mail protection, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/objsign-ca-bundle.pem

File contains a list of CA certificates trusted for code signing, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/tls-ca-bundle.pem

File contains a list of CA certificates trusted for TLS server authentication, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/cadir/

Contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. These files are maintained by the update-ca-trust command.

/etc/ca-certificates/extracted/edk2-cacerts.bin

File contains a list of CA certificates trusted for TLS server authentication usage, in the UEFI signature database format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/java-cacerts.jks

File contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is consolidated output created by the update-ca-trust command.
