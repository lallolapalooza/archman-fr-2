getutent(3) Manuel des fonctions de bibliothèque getutent(3)

NOM

getutent, getutid, getutline, pututline, setutent, endutent, utmpname - accéder aux entrées du fichier utmp

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPTION

Les nouvelles applications devraient utiliser les versions « utmpx » de ces fonctions spécifiées par POSIX.1 ; voir NORMES.

utmpname() définit le nom du chemin du fichier au format utmp pour que les autres fonctions utmp puissent y accéder. Si utmpname() n'est pas utilisé pour définir le nom du chemin avant l'utilisation des autres fonctions, elles supposent _PATH_UTMP, tel que défini dans <paths.h>.

setutent() rembobine le pointeur de fichier au début du fichier utmp. Il est généralement conseillé de l'appeler avant toute autre fonction.

endutent() ferme le fichier utmp. Il doit être appelé lorsque le code utilisateur a terminé l'accès au fichier avec les autres fonctions.

getutent() lit une ligne à partir de la position actuelle du fichier dans le fichier utmp. Il retourne un pointeur vers une structure contenant les champs de la ligne. La définition de cette structure est montrée dans utmp(5).

getutid() recherche vers l'avant à partir de la position actuelle du fichier dans le fichier utmp en se basant sur ut. Si ut->ut_type est l'une de RUN_LVL, BOOT_TIME, NEW_TIME ou OLD_TIME, getutid() trouvera la première entrée dont le champ ut_type correspond à ut->ut_type. Si ut->ut_type est l'une de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS ou DEAD_PROCESS, getutid() trouvera la première entrée dont le champ ut_id correspond à ut->ut_id.

getutline() recherche vers l'avant à partir de la position actuelle du fichier dans le fichier utmp. Il analyse les entrées dont ut_type est USER_PROCESS ou LOGIN_PROCESS et retourne la première dont le champ ut_line correspond à ut->ut_line.

pututline() écrit la structure utmp ut dans le fichier utmp. Elle utilise getutid() pour rechercher l'endroit approprié dans le fichier pour insérer la nouvelle entrée. Si elle ne parvient pas à trouver une place appropriée pour ut, pututline() ajoutera la nouvelle entrée à la fin du fichier.

VALEUR DE RETOUR

getutent(), getutid() et getutline() retournent un pointeur vers une struct utmp en cas de succès, et NULL en cas d'échec (ce qui inclut le cas « enregistrement non trouvé »). Cette struct utmp est allouée dans un stockage statique et peut être écrasée par des appels ultérieurs.

En cas de succès, pututline() retourne ut ; en cas d'échec, elle retourne NULL.

utmpname() retourne 0 si le nouveau nom a été stocké avec succès, ou -1 en cas d'échec.

En cas d'échec, ces fonctions définissent errno pour indiquer l'erreur.

ERREURS

ENOMEM
Pas assez de mémoire.
ESRCH
Enregistrement non trouvé.

setutent(), pututline() et les fonctions getut*() peuvent également échouer pour les raisons décrites dans open(2).

FICHIERS

/var/run/utmp
base de données des utilisateurs actuellement connectés
/var/log/wtmp
base de données des connexions d'utilisateurs passées

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
getutent () Sécurité des threads MT-Unsafe init race:utent race:utentbuf sig:ALRM timer
getutid (), getutline () Sécurité des threads MT-Unsafe init race:utent sig:ALRM timer
pututline () Sécurité des threads MT-Unsafe race:utent sig:ALRM timer
setutent (), endutent (), utmpname () Sécurité des threads MT-Unsafe race:utent

Dans le tableau ci-dessus, utent dans race:utent signifie que si l'une des fonctions setutent(), getutent(), getutid(), getutline(), pututline(), utmpname() ou endutent() est utilisée en parallèle dans différents threads d'un programme, des courses de données pourraient se produire.

NORMES

Aucune.

HISTORIQUE

XPG2, SVr4.

Dans XPG2 et SVID 2, la fonction pututline() est documentée comme retournant void, et c'est ce qu'elle fait sur de nombreux systèmes (AIX, HP-UX). HP-UX introduit une nouvelle fonction _pututline() avec le prototype donné ci-dessus pour pututline().

Toutes ces fonctions sont maintenant obsolètes sur les systèmes non-Linux. POSIX.1-2001 et POSIX.1-2008, suivant SUSv1, n'ont aucune de ces fonctions, mais utilisent à la place

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Ces fonctions sont fournies par glibc, et effectuent la même tâche que leurs équivalents sans le « x », mais utilisent struct utmpx, définie sous Linux pour être identique à struct utmp. Pour des raisons de complétude, glibc fournit également utmpxname(), bien que cette fonction ne soit pas spécifiée par POSIX.1.

Sur certains autres systèmes, la structure utmpx est un sur-ensemble de la structure utmp, avec des champs supplémentaires, et des versions plus grandes des champs existants, et des fichiers parallèles sont maintenus, souvent /var/*/utmpx et /var/*/wtmpx.

Linux glibc, en revanche, n'utilise pas de fichier utmpx parallèle car sa structure utmp est déjà suffisamment grande. Les fonctions « x » listées ci-dessus ne sont que des alias pour leurs homologues sans le « x » (par exemple, getutxent() est un alias pour getutent()).

NOTES

notes glibc

Les fonctions ci-dessus ne sont pas thread-safe. glibc ajoute des versions réentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Conditions requises pour les macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getutent_r(), getutid_r(), getutline_r() :

    _GNU_SOURCE
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */    _SVID_SOURCE || _BSD_SOURCE

Ce sont des extensions GNU, analogues aux fonctions du même nom sans le suffixe _r. L'argument ubuf donne à ces fonctions un endroit pour stocker leur résultat. En cas de succès, elles retournent 0, et un pointeur vers le résultat est écrit dans *ubufp. En cas d'erreur, ces fonctions retournent -1. Il n'y a pas d'équivalents utmpx des fonctions ci-dessus. (POSIX.1 ne spécifie pas de telles fonctions.)

pututline(3) - Linux man pages

NAME

pututline, getutent, getutid, getutline, setutent, endutent, utmpxname - examine utmp entries

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <utmp.h>
int pututline(const struct utmp *utmp);
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *id);
struct utmp *getutline(const struct utmp *line);
void setutent(void);
void endutent(void);
int utmpxname(const char *file);

DESCRIPTION

These functions provide an interface to the user accounting database, whose format is described in utmp(5). The database is a set of records, each describing a current login session. The utmpxname() function specifies the file to be used instead of the default /var/run/utmp. Only the superuser can change the utmpxname() file.

The setutent() function opens the database file and rewinds it to the beginning. The getutent() function reads the next entry from the database. Successive calls return successive entries. The endutent() function closes the database file.

The getutid() function finds and returns a pointer to the record in the database whose ut_id field matches the ut_id field of the structure pointed to by id. The getutline() function is similar, but searches for a matching ut_line field.

The pututline() function writes the utmp structure pointed to by utmp to the database. If the record is a new entry, it is appended to the end of the file. If the record overwrites an existing entry, the original entry is replaced.

The functions getutent(), getutid(), and getutline() all return a pointer to a static structure. Subsequent calls to any of these functions, or to setutent(), may overwrite the pointer. Calls to pututline() may also overwrite the pointer.

RETURN VALUE

On success, pututline() returns a pointer to the written entry. Otherwise, it returns NULL.

The functions getutent(), getutid(), and getutline() return a pointer to a struct utmp on success, and NULL on failure or end-of-file.

The utmpxname() function returns 0 on success, and -1 on failure.

ERRORS

The pututline() function may fail if the database file cannot be opened for writing, or if a write operation fails. The specific error is set in the global variable errno.

The utmpxname() function fails if file is not a regular file, or if the current user is not the superuser and attempts to change the utmpxname() file.

FILES

/var/run/utmp
Default user accounting database.
/var/log/wtmp
Login record file, used by last(1).
/var/run/utmp.pid
Process ID file for the login process.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

+--------------------+---------------------+----------------------------+
| Interface          | Attribute           | Value                      |
+--------------------+---------------------+----------------------------+
| setutent(),        | Thread safety       | MT-Unsafe                  |
| endutent(),        |                     |                            |
| getutent(),        |                     |                            |
| getutid(),         |                     |                            |
| getutline(),       |                     |                            |
| pututline(),       |                     |                            |
| utmpxname()        |                     |                            |
+--------------------+---------------------+----------------------------+

STANDARDS

POSIX.1-2001, POSIX.1-2008.

HISTORY

These functions first appeared in AT&T System V UNIX.

NOTES

The getutent(), getutid(), getutline(), and pututline() functions are not thread-safe because they use static variables to store the current position in the database and the last retrieved record. In multithreaded applications, use the _r variants (e.g., getutent_r()) instead.

The pututline() function is used to add and remove entries from the utmp database. To remove an entry, set the ut_type field to DEAD_PROCESS or USER_PROCESS with a zeroed-out ut_line field. This will mark the entry as removed.

EXAMPLES

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
