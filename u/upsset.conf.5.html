UPSSET.CONF(5) Manuel NUT UPSSET.CONF(5)

NOM

upsset.conf - Configuration pour Network UPS Tools upsset.cgi

DESCRIPTION

Ce fichier ne fait qu'une seule chose : il permet de convaincre upsset.cgi(8) que le répertoire CGI de votre système est sécurisé. Le programme ne s'exécutera pas tant que ce fichier n'aura pas été correctement défini.

NOTES IMPORTANTES

• Le contenu de ce fichier doit être en ASCII pur (les codes de caractères hors plage seront ignorés avec un message d'avertissement).

EXIGENCES DE SÉCURITÉ

upsset.cgi(8) vous permet de tester des combinaisons de noms d'utilisateur et de mots de passe. Il n'y a pas de limitation de débit, car le programme s'arrête entre chaque requête. Telle est la nature des programmes CGI.

Les identifiants sont fournis à upsset.cgi dans le cadre de votre session de navigation, il est donc fortement recommandé de configurer HTTPS sur le serveur Web ; les méthodes pour le faire sont hors de la portée de ce document.

Normalement, les attaquants ne seraient pas en mesure d'accéder directement à votre serveur upsd(8), car il serait protégé par les directives LISTEN de votre fichier upsd.conf(5), tcp-wrappers (si disponible lors de la compilation de NUT), et espérons-le, par des paramètres de pare-feu locaux dans votre système d'exploitation.

upsset s'exécute sur votre serveur Web, donc upsd le verra comme une connexion provenant d'un hôte d'un réseau interne. Il ne saura pas que la connexion est réellement initiée par quelqu'un de plus extérieur. C'est pourquoi vous devez le sécuriser.

Sur Apache, vous pouvez utiliser le fichier .htaccess ou placer les directives dans votre httpd.conf. Cela ressemble à ceci, en supposant la méthode .htaccess pour les anciennes versions d'Apache :

<Files upsset.cgi>
        deny from all
        allow from vos.adresses.reseau
</Files>

Vous devrez probablement définir AllowOverride Limit pour ce répertoire dans le fichier de configuration de niveau serveur également.

Apache moderne bénéficie d'une syntaxe plus détaillée, comme ceci :

ScriptAlias /upsstats.cgi /usr/share/nut/cgi/upsstats.cgi
ScriptAlias /upsset.cgi /usr/share/nut/cgi/upsset.cgi
<Directory "/usr/share/nut/cgi">
      Options +Includes +ExecCGI
      AllowOverride Limit
      <RequireAny>
          Require local
          Require ip aa.bb.cc.dd/nn
      </RequireAny>
</Directory>

Si cela n'a pas de sens pour vous, arrêtez de lire et laissez ce programme tranquille. Ce n'est pas quelque chose dont vous avez absolument besoin de toute façon.

En supposant que vous ayez tout cela fait, et que cela fonctionne réellement (testez-le !), alors vous pouvez ajouter la directive suivante à ce fichier :

I_HAVE_SECURED_MY_CGI_DIRECTORY

Si vous mentez au programme et que quelqu'un attaque votre upsd via votre serveur Web, ne m'en blâmez pas.
