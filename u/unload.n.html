unload(n) Commandes intégrées Tcl unload(n)

NOM

unload - Décharger le code machine

SYNOPSIS

unload ?options? nomFichier
unload ?options? nomFichier préfixe
unload ?options? nomFichier préfixe interpréteur

DESCRIPTION

Cette commande tente de décharger les bibliothèques partagées précédemment chargées avec load de l'espace d'adressage de l'application. nomFichier est le nom du fichier contenant le fichier de bibliothèque à décharger ; il doit être le même que le nom de fichier fourni à load pour charger la bibliothèque. L'argument préfixe est le préfixe (tel que déterminé ou passé à load) et est utilisé pour calculer le nom de la procédure de déchargement ; s'il n'est pas fourni, il est calculé à partir de nomFichier de la même manière que load. L'argument interpréteur est le nom du chemin de l'interpréteur à partir duquel décharger le paquet (voir la page de manuel interp pour plus de détails) ; si interpréteur est omis, il prend par défaut l'interpréteur dans lequel la commande unload a été invoquée.

Si les arguments initiaux de unload commencent par -, ils sont traités comme des options. Les options suivantes sont actuellement prises en charge :

-nocomplain
Supprime tous les messages d'erreur. Si cette option est donnée, unload ne rapportera jamais d'erreur.
-keeplibrary
Cette option empêchera unload d'émettre l'appel système qui déchargera la bibliothèque du processus.
--
Marque la fin des options. L'argument suivant sera traité comme un nomFichier même s'il commence par un -.

OPÉRATION DE DÉCHARGEMENT

Lorsqu'un fichier contenant une bibliothèque partagée est chargé via la commande load, Tcl associe deux compteurs de référence au fichier de bibliothèque. Le premier compteur indique combien de fois la bibliothèque a été chargée dans des interpréteurs normaux (de confiance), tandis que le second décrit combien de fois la bibliothèque a été chargée dans des interpréteurs sûrs. Comme un fichier contenant une bibliothèque partagée ne peut être chargé qu'une seule fois par Tcl (avec le premier appel load sur le fichier), ces compteurs indiquent combien d'interpréteurs utilisent la bibliothèque. Chaque appel ultérieur à load après le premier incrémente simplement le compteur de référence approprié.

unload fonctionne en sens inverse. Comme première étape, unload vérifiera si la bibliothèque est déchargeable : une bibliothèque déchargeable exporte une procédure de déchargement spéciale. Le nom de la procédure de déchargement est déterminé par préfixe et si l'interpréteur cible est sûr ou non. Pour les interpréteurs normaux, le nom de la procédure d'initialisation sera de la forme pfx_Unload, où pfx est le même que préfixe, à l'exception de la conversion de la première lettre en majuscule et de toutes les autres lettres en minuscule. Par exemple, si préfixe est foo ou FOo, le nom de la procédure d'initialisation sera Foo_Unload. Si l'interpréteur cible est un interpréteur sûr, alors le nom de la procédure d'initialisation sera pkg_SafeUnload au lieu de pkg_Unload.

Si unload détermine qu'une bibliothèque n'est pas déchargeable (ou que la fonctionnalité de déchargement a été désactivée lors de la compilation), une erreur sera retournée. Si la bibliothèque est déchargeable, alors unload appellera la procédure de déchargement. Si la procédure de déchargement renvoie TCL_OK, unload continuera et diminuera le compteur de référence approprié (en fonction du type d'interpréteur cible). Lorsque les deux compteurs de référence atteignent 0, la bibliothèque sera détachée du processus.

PROTOTYPE DU CROCHET DE DÉCHARGEMENT

La procédure de déchargement doit correspondre au prototype suivant :

typedef int Tcl_PackageUnloadProc(
        Tcl_Interp *interp,
        int flags);

L'argument interp identifie l'interpréteur à partir duquel la bibliothèque doit être déchargée. La procédure de déchargement doit retourner TCL_OK ou TCL_ERROR pour indiquer si elle s'est terminée avec succès ou non ; en cas d'erreur, elle doit définir le résultat de l'interpréteur pour qu'il pointe vers un message d'erreur. Dans ce cas, le résultat de la commande unload sera le résultat retourné par la procédure de déchargement.

L'argument flags peut être soit TCL_UNLOAD_DETACH_FROM_INTERPRETER soit TCL_UNLOAD_DETACH_FROM_PROCESS. Dans le cas où la bibliothèque restera attachée au processus après le retour de la procédure de déchargement (c'est-à-dire parce que la bibliothèque est utilisée par d'autres interpréteurs), TCL_UNLOAD_DETACH_FROM_INTERPRETER sera défini. Cependant, si la bibliothèque n'est utilisée que par l'interpréteur cible et que la bibliothèque sera détachée de l'application dès que la procédure de déchargement retournera, l'argument flags sera défini à TCL_UNLOAD_DETACH_FROM_PROCESS.

NOTES

La commande unload ne peut pas décharger les bibliothèques qui sont liées statiquement à l'application. Si nomFichier est une chaîne vide, alors l'argument préfixe doit être spécifié.

Si préfixe est omis ou spécifié comme une chaîne vide, Tcl essaie de deviner le préfixe. Cela peut être fait différemment selon les plateformes. L'estimation par défaut, utilisée sur la plupart des plateformes UNIX, consiste à prendre le dernier élément de nomFichier, à supprimer les trois premiers caractères s'il s'agit de lib, et à utiliser les caractères alphabétiques et de soulignement suivants, convertis en casse de titre, comme préfixe. Par exemple, la commande unload libxyz4.2.so utilise le préfixe Xyz et la commande unload bin/last.so {} utilise le préfixe Last.

PROBLÈMES DE PORTABILITÉ

Unix     
Tous les systèmes d'exploitation Unix ne prennent pas en charge le déchargement de bibliothèques. Sur un tel système d'exploitation, unload retourne une erreur (sauf si -nocomplain a été spécifié).

BOGUES

Si le même fichier est chargé par différentes invocations de load avec différents nomFichier, il sera chargé plusieurs fois dans l'espace d'adressage du processus. Le comportement de ceci varie d'un système à l'autre (certains systèmes peuvent détecter les chargements redondants, d'autres non). Dans le cas où une bibliothèque a été silencieusement détachée par le système d'exploitation (et qu'en conséquence Tcl pense que la bibliothèque est toujours chargée), il peut être dangereux d'utiliser unload sur une telle bibliothèque (car la bibliothèque sera complètement détachée de l'application tandis que certains interpréteurs continueront à l'utiliser).

EXEMPLE

Si un module déchargeable dans le fichier foobar.dll avait été chargé en utilisant la commande load comme suit (sous Windows) :

load c:/some/dir/foobar.dll

alors il serait déchargé comme suit :

unload c:/some/dir/foobar.dll

Cela permet à un module de code C d'être temporairement installé dans un programme Tcl de longue durée, puis d'être retiré (soit parce qu'il n'est plus nécessaire, soit parce qu'il est mis à jour avec une nouvelle version) sans avoir à arrêter le processus Tcl global.
