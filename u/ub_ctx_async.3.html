DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui fait de la mise en cache et de la validation DNSSEC. C'est l'API de bibliothèque pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution, et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et vice-versa, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour maintenir le contexte entre les appels. L'utilisateur doit la maintenir, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. Sa recréation supprime toute configuration précédente (comme les clés de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement threadé (ainsi que dans un environnement non threadé). La résolution (et la validation) peut également être effectuée de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement à l'appel, de sorte que le traitement puisse continuer, tandis que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec des valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez lib openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou plus récent utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en attente sont annulées et les rappels ne sont pas appelés pour elles.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le : final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère la valeur d'une option. Certaines options ne peuvent pas être récupérées, et d'autres renvoient une liste séparée par des sauts de ligne. Passez le nom de l'option sans le : final. La valeur renvoyée doit être libérée par l'appelant avec free(2).
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine à laquelle les requêtes DNS doivent être transmises, le résolveur de mise en cache à utiliser. Adresse IP4 ou IP6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas capable de DNSSEC, la validation peut échouer. Peut être appelée plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. Pour le moment, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Définissez isprime à vrai si vous configurez des root hints avec. Sinon, similaire à l'élément zone stub du fichier de configuration d'Unbound. Peut être appelée plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. Pour le moment, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_set_tls
Active DNS over TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. Pour le moment, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_resolvconf
Par défaut, les serveurs racines sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser à partir du nom de fichier donné. Habituellement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxys de mise en cache. S'ils ne prennent pas en charge DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont pris en compte, le searchdomain, ndots et d'autres paramètres de resolv.conf(5) sont ignorés. Si fname est NULL, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré globalement est utilisé à la place). Pour le moment, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Habituellement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname est NULL, "/etc/hosts" est utilisé (si sous Windows, etc/hosts de WINDIR est utilisé à la place). Pour le moment, il n'est possible de définir la configuration qu'avant la première résolution.

DESCRIPTION

These functions provide an interface to the unbound validating, recursive, caching DNS resolver library.

The libunbound library allows applications to query DNS names, validate the answers using DNSSEC, and use the unbound resolver core. You must first create a context with ub_ctx_create.

Contexts can be configured using ub_ctx_set_option.

The following options are supported:

unbound_server
sets the server name (default localhost).
root_hints
sets the root hints file (default uses internal hints).
domain_insecure
makes the specified domain name and subdomains insecure.
private_domain
makes the specified domain name and subdomains private.
access_control
restricts access based on IP address.
chroot
changes root directory.
username
changes user.
pidfile
sets the PID file.
logfile
sets the log file.
verbosity
sets verbosity level.
log_queries
enables query logging.
log_replies
enables reply logging.
log_dnscrypt_conn
enables logging of dnscrypt connections.
do_ip4
enables IPv4.
do_ip6
enables IPv6.
do_udp
enables UDP.
do_tcp
enables TCP.
do_notickle
disables tickling the server.
harden_short_buf
enables harden short buffer.
harden_dnssec_stripped
enables harden DNSSEC stripped.
use_caps_for_id
enables caps for id.
edns_buffer_size
sets the EDNS buffer size.
max_udp_size
sets the maximum UDP payload size.
max_tcp_size
sets the maximum TCP payload size.
use_syslog
enables syslog logging.
log_time_ascii
enables ASCII time logging.
log_time_iso
enables ISO time logging.
log_suffix
appends a suffix to log messages.
zone_search
sets search list for zones.
so_rcvbuf
sets the socket receive buffer size.
so_sndbuf
sets the socket send buffer size.
sndbuf_size
sets the send buffer size.
rcvbuf_size
sets the receive buffer size.
trust_anchor_file
sets the trust anchor file.
auto_trust_anchor_file
sets the auto trust anchor file.
keyfile
sets the key file.
load-cache
loads the cache from disk.
save-cache
saves the cache to disk.
cache_min_ttl
sets the minimum TTL for cached entries.
cache_max_ttl
sets the maximum TTL for cached entries.
infra-cache-minimum
sets the minimum infra cache size.
infra-cache-maximum
sets the maximum infra cache size.
rrset-cache-size
sets the RRSET cache size.
ip-ratelimit
enables IP rate limiting.
ip-ratelimit-only-known-to-be-bad
only rate limits known bad IPs.
num-threads
sets the number of threads.
module-config
sets the module configuration.
id-prefix
sets the ID prefix.
outgoing-interface
sets the outgoing interface.

The function ub_ctx_get_option can be used to retrieve option values. The caller is responsible for freeing the returned string val.

Trust anchors can be added using ub_ctx_add_ta, ub_ctx_add_ta_file, or ub_ctx_trustedkeys. ub_ctx_add_ta adds a trust anchor from a string. ub_ctx_add_ta_file adds trust anchors from a file containing DS and DNSKEY records in zone file format. ub_ctx_trustedkeys adds trust anchors from a bind-style configuration file with trusted-keys{}.

ub_ctx_add_ta_autr adds a filename containing an automatically tracked trust anchor. This file can be created using unbound-anchor(8). If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.

Debug and error output can be directed to a specified stream using ub_ctx_debugout. Pass NULL to disable output. The default is stderr. Debug verbosity can be set using ub_ctx_debuglevel.

ub_ctx_async sets the behavior for asynchronous operations. If true, threading is enabled, and ub_resolve_async creates a thread. If false, a process is forked. Changes to this setting after ub_resolve_async calls have been made have no effect.

ub_poll checks if there are any new results for the context. Do not poll in a loop; instead, use the file descriptor obtained from ub_fd to poll for readiness, and then check. It returns non-zero if a result is available, and zero otherwise. If non-zero, call ub_process to perform callbacks.

ub_wait waits for a context to finish with results and calls ub_process afterwards. After the wait, there are no more outstanding asynchronous queries.

ub_fd returns a file descriptor that can be used with poll(2) or select(2). Wait for it to become readable, at which point answers are returned from the asynchronous validating resolver. Then call ub_process to continue processing.

ub_process should be called when the file descriptor returned by ub_fd becomes readable. It performs necessary callbacks.

ub_resolve performs synchronous resolution and validation of the target name. The name is a zero-terminated string. rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.

ub_resolve_async performs asynchronous resolution and validation. Arguments are the same as for ub_resolve, except that no data is returned immediately. Instead, a callback function is called later. The callback receives a copy of the mydata pointer. The callback function is declared as:

void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can optionally track it and cancel the request if needed. If you pass a NULL pointer, the async_id is not returned.

ub_cancel cancels an in-progress asynchronous query. It may return an error if the query does not exist or is already being delivered, in which case you may still get a callback for the query.

ub_resolve_free frees the contents of a struct ub_result after use.

ub_strerror converts an error code returned by libunbound functions into a human-readable string.

ub_ctx_print_local_zones debug-prints the local authority information to the debug output.

ub_ctx_zone_add adds a new zone to the local authority info, similar to the local-zone statement in unbound.conf(5).

ub_ctx_zone_remove deletes a zone from the local authority info.

ub_ctx_data_add adds resource record data to the local authority info, similar to the local-data statement in unbound.conf(5).

ub_ctx_data_remove deletes local authority data from the given name.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Otherwise, they are not both true; one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero-terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_set_option, ub_ctx_add_ta, ub_ctx_add_ta_autr, ub_ctx_add_ta_file, ub_ctx_trustedkeys, ub_ctx_zone_add, ub_ctx_zone_remove, ub_ctx_data_add, ub_ctx_data_remove, ub_resolve and ub_resolve_async return 0 on success and an error code on failure. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
