umount(2) Manuel des appels système umount(2)

NOM

umount, umount2 - démonter un système de fichiers

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mount.h>
int umount(const char *cible);
int umount2(const char *cible, int flags);

DESCRIPTION

umount() et umount2() retirent l'attachement du système de fichiers (le plus haut) monté sur cible.

Des privilèges appropriés (Linux : la capacité CAP_SYS_ADMIN) sont requis pour démonter des systèmes de fichiers.

Linux 2.1.116 a ajouté l'appel système umount2(), qui, comme umount(), démonte une cible, mais autorise des flags supplémentaires contrôlant le comportement de l'opération :

MNT_FORCE (depuis Linux 2.1.116)
Demande au système de fichiers d'annuler les requêtes en attente avant de tenter le démontage. Cela peut permettre au démontage de se terminer sans attendre un serveur inaccessible, mais peut entraîner une perte de données. Si, après l'annulation des requêtes, certains processus ont encore des références actives au système de fichiers, le démontage échouera toujours. En date de Linux 4.12, MNT_FORCE n'est pris en charge que sur les systèmes de fichiers suivants : 9p (depuis Linux 2.6.16), ceph (depuis Linux 2.6.34), cifs (depuis Linux 2.6.12), fuse (depuis Linux 2.6.16), lustre (depuis Linux 3.11) et NFS (depuis Linux 2.1.116).
MNT_DETACH (depuis Linux 2.4.11)
Effectue un démontage paresseux : rend le montage indisponible pour de nouvelles tentatives d'accès, déconnecte immédiatement le système de fichiers et tous les systèmes de fichiers montés en dessous les uns des autres et de la table de montage, et effectue réellement le démontage quand le montage cesse d'être occupé.
MNT_EXPIRE (depuis Linux 2.6.8)
Marque le montage comme expiré. Si un montage n'est pas actuellement en cours d'utilisation, un premier appel à umount2() avec ce drapeau échoue avec l'erreur EAGAIN, mais marque le montage comme expiré. Le montage reste expiré tant qu'il n'est accédé par aucun processus. Un second appel à umount2() spécifiant MNT_EXPIRE démonte un montage expiré. Ce drapeau ne peut pas être spécifié avec MNT_FORCE ou MNT_DETACH.
UMOUNT_NOFOLLOW (depuis Linux 2.6.34)
Ne pas résoudre cible s'il s'agit d'un lien symbolique. Ce drapeau permet d'éviter les problèmes de sécurité dans les programmes set-user-ID en mode root qui autorisent les utilisateurs non privilégiés à démonter des systèmes de fichiers.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

Les valeurs d'erreur ci-dessous résultent d'erreurs indépendantes du type de système de fichiers. Chaque type de système de fichiers peut avoir ses propres erreurs spéciales et son propre comportement spécial. Voir le code source du noyau Linux pour plus de détails.

EAGAIN
Un appel à umount2() spécifiant MNT_EXPIRE a marqué correctement un système de fichiers non occupé comme expiré.
EBUSY
cible n'a pas pu être démonté car elle est occupée.
EFAULT
cible pointe en dehors de l'espace d'adressage utilisateur.
EINVAL
cible n'est pas un point de montage.
EINVAL
cible est verrouillé ; voir mount_namespaces(7).
EINVAL
umount2() a été appelé avec MNT_EXPIRE et soit MNT_DETACH, soit MNT_FORCE.
EINVAL (depuis Linux 2.6.34)
umount2() a été appelé avec une valeur de drapeau invalide dans flags.
ENAMETOOLONG
Un nom de chemin était plus long que MAXPATHLEN.
ENOENT
Un nom de chemin était vide ou avait un composant inexistant.
ENOMEM
Le noyau n'a pas pu allouer une page libre pour copier des noms de fichiers ou des données.
EPERM
L'appelant n'a pas les privilèges requis.

NORMES

Linux.

HISTORIQUE

MNT_DETACH et MNT_EXPIRE sont disponibles depuis glibc 2.11.

La fonction originale umount() était appelée comme umount(device) et retournait ENOTBLK lorsqu'elle était appelée avec autre chose qu'un périphérique bloc. Dans Linux 0.98p4, un appel umount(dir) a été ajouté, afin de supporter les périphériques anonymes. Dans Linux 2.3.99-pre7, l'appel umount(device) a été retiré, ne laissant que umount(dir) (car les périphériques peuvent maintenant être montés à plus d'un endroit, donc spécifier le périphérique ne suffisait plus).

NOTES

umount() et les montages partagés

Les montages partagés provoquent la transmission de toute activité de montage, y compris les opérations umount(), à chaque montage partagé du groupe de pairs et à chaque montage esclave de ce groupe de pairs. Cela signifie que umount() de n'importe quel pair dans un ensemble de montages partagés provoquera le démontage de tous ses pairs et le démontage de tous leurs esclaves.

Cette propagation de l'activité de démontage peut être particulièrement surprenante sur les systèmes où chaque montage est partagé par défaut. Sur de tels systèmes, le montage récursif de la racine du système de fichiers sur un sous-répertoire, puis le démontage ultérieur de ce sous-répertoire avec MNT_DETACH provoquera le démontage paresseux de chaque montage dans l'espace de noms de montage.

Pour garantir que umount() ne se propage pas de cette manière, le montage peut être remonté en utilisant un appel mount(2) avec un argument mount_flags qui inclut à la fois MS_REC et MS_PRIVATE avant que umount() ne soit appelé.

VOIR AUSSI

mount(2), mount_namespaces(7), path_resolution(7), mount(8), umount(8)

umount(2)

NOM

umount - démonter un système de fichiers

BIBLIOTHÈQUE

Bibliothèque standard C (libc)

SYNTAXE

#include <sys/mount.h> int umount(const char *target); int umount2(const char *target, int flags);

DESCRIPTION

La fonction umount démonte le système de fichiers spécifié par target. target est soit le point de montage, soit le périphérique de bloc qui a été monté.

La fonction umount2 est similaire à umount, mais accepte un argument supplémentaire flags qui peut être utilisé pour spécifier différentes options de démontage.

Les drapeaux suivants peuvent être utilisés pour umount2:

  • MNT_FORCE: Force le démontage. Cela peut être utilisé pour démonter des systèmes de fichiers qui sont occupés.
  • MNT_DETACH: Détache le système de fichiers. Le système de fichiers sera détaché immédiatement, mais il ne sera pas vraiment démonté tant que tous les processus qui l'utilisent ne se seront pas terminés.
  • MNT_EXPIRE: Marque le système de fichiers comme expiré. Le système de fichiers sera réellement démonté lorsque tous les processus qui l'utilisent se seront terminés.

Les utilisateurs non privilégiés peuvent démonter des systèmes de fichiers qui ont été montés par eux-mêmes. Pour démonter des systèmes de fichiers montés par d'autres utilisateurs ou par le système, l'utilisateur doit avoir les privilèges de superutilisateur (root).

VALEUR DE RETOUR

En cas de succès, umount et umount2 renvoient 0. En cas d'erreur, elles renvoient -1 et définissent $errno pour indiquer l'erreur.

ERREURS

EBUSY
Le système de fichiers est occupé. Il y a un processus qui utilise le système de fichiers.
EINVAL
Le point de montage n'est pas valide.
ENOTDIR
Le point de montage n'est pas un répertoire.
ENOENT
Le point de montage n'existe pas.
EPERM
L'utilisateur n'a pas les privilèges nécessaires pour démonter le système de fichiers.

ÉTATS

Les systèmes de fichiers sont démontés en utilisant des appels système.

HISTORIQUE

La fonction umount est apparue dans la première version d'UNIX. umount2 a été ajoutée dans le noyau Linux 2.3.10.

NOTES

La fonction umount est un appel système de bas niveau. Pour la plupart des utilisations, il est préférable d'utiliser la commande umount (voir umount(8)).

VOIR AUSSI

mount(2), umount(8)
