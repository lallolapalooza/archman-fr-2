NOM

urlwatch-filters - Filtrage de la sortie et des données de différences des tâches urlwatch

SYNTAXE

urlwatch --edit

DESCRIPTION

Chaque tâche peut avoir deux étapes de filtrage configurées, avec un ou plusieurs filtres traités les uns après les autres :

  • Appliqué à la page téléchargée avant de comparer les changements (filter)
  • Appliqué au résultat de la comparaison avant de signaler les changements (diff_filter)

Lors de la création de votre pipeline de filtres, vous pourriez vouloir prévisualiser à quoi ressemble la sortie filtrée. Vous pouvez le faire en configurant d'abord votre tâche, puis en exécutant urlwatch avec la commande --test-filter, en passant l'index (provenant de --list) ou l'URL/l'emplacement de la tâche à tester :

urlwatch --test-filter 1   # Teste la première tâche de la liste
urlwatch --test-filter https://example.net/  # Teste la tâche avec l'URL donnée

La sortie de cette commande sera le texte brut filtré de la tâche, c'est la sortie qui sera (dans une vraie exécution de urlwatch) l'entrée de l'algorithme de comparaison.

Le filter n'est appliqué qu'au nouveau contenu, l'ancien contenu a déjà été filtré lorsqu'il a été récupéré. Cela signifie que les changements apportés à filter ne sont pas visibles lorsque le contenu inchangé est signalé (voir Display pour plus de détails), et que la sortie de la comparaison sera entre (l'ancien contenu avec le filtre au moment où l'ancien contenu a été récupéré) et (le nouveau contenu avec le filtre actuel).

Une fois qu'urlwatch a collecté au moins 2 clichés historiques d'une tâche (deux états différents d'une page Web), vous pouvez utiliser l'option de ligne de commande --test-diff-filter pour tester vos paramètres diff_filter ; cela utilisera les données historiques mises en cache localement.

FILTRES INTÉGRÉS

La liste des filtres intégrés peut être récupérée en utilisant :

urlwatch --features

À l'heure actuelle, les filtres suivants sont intégrés :

  • beautify : Améliore l'apparence du HTML
  • css : Filtre XML/HTML en utilisant des sélecteurs CSS
  • csv2text : Convertit CSV en texte brut
  • element-by-class : Obtient tous les éléments HTML par classe
  • element-by-id : Obtient un élément HTML par son ID
  • element-by-style : Obtient tous les éléments HTML par style
  • element-by-tag : Obtient un élément HTML par sa balise
  • format-json : Convertit en JSON formaté
  • grep : Filtre uniquement les lignes correspondant à une expression régulière
  • grepi : Supprime les lignes correspondant à une expression régulière
  • hexdump : Convertit les données binaires au format hex dump
  • html2text : Convertit le HTML en texte brut
  • pdf2text : Convertit le PDF en texte brut
  • pretty-xml : Améliore l'apparence du XML
  • ical2text : Convertit iCalendar https://fr.wikipedia.org/wiki/ICalendar en texte brut
  • ocr : Convertit le texte dans les images en texte brut à l'aide de Tesseract OCR
  • re.sub : Remplace le texte par des expressions régulières en utilisant re.sub de Python
  • re.findall : Trouve toutes les correspondances non chevauchantes en utilisant re.findall de Python
  • reverse : Inverse les éléments d'entrée
  • sha1sum : Calcule la somme de contrôle SHA-1 du contenu
  • shellpipe : Filtre à l'aide d'une commande shell
  • sort : Trie les éléments d'entrée
  • remove-duplicate-lines : Supprime les lignes en double (sensible à la casse)
  • strip : Supprime les espaces blancs en début et fin de texte
  • striplines : Supprime les espaces blancs en début et fin de chaque ligne
  • xpath : Filtre XML/HTML en utilisant des expressions XPath
  • jq : Filtre, transforme et extrait des valeurs de JSON

SÉLECTIONNER DES ÉLÉMENTS DE PAGE WEB

Vous pouvez sélectionner uniquement un élément HTML donné avec le filtre intégré, par exemple pour extraire <div id="quelque-chose">.../<div> d'une page, vous pouvez utiliser ce qui suit dans votre urls.yaml :

url: http://example.org/idtest.html
filter:
  - element-by-id: quelque-chose

De plus, vous pouvez chaîner les filtres, vous pouvez donc exécuter html2text sur le résultat :

url: http://example.net/id2text.html
filter:
  - element-by-id: quelque-chose
  - html2text

CHAÎNER PLUSIEURS FILTRES

Le fichier d'exemple urls.yaml démontre également l'utilisation des filtres intégrés, ici 3 filtres sont utilisés : html2text, line-grep et suppression des espaces blancs pour obtenir juste un champ d'information spécifique d'une page Web :

url: https://example.net/version.html
filter:
  - html2text
  - grep: "Current.*version"
  - strip

EXTRAIRE UNIQUEMENT LA BALISE <BODY> D'UNE PAGE

Si vous souhaitez extraire uniquement la balise body, vous pouvez utiliser ce filtre :

url: https://example.org/bodytag.html
filter:
  - element-by-tag: body

FILTRAGE BASÉ SUR UNE EXPRESSION XPATH

Pour filtrer basé sur une expression XPath https://www.w3.org/TR/1999/REC-xpath-19991116/, vous pouvez utiliser le filtre xpath comme ceci :

url: https://example.net/xpath.html
filter:
  - xpath: /html/body/marquee

Ceci filtre uniquement les éléments <marquee> directement sous l'élément <body>, qui à son tour doit être sous l'élément <html> du document, supprimant tout le reste.

Consultez la page Exemples XPath de Microsoft https://docs.microsoft.com/en-us/previous-versions/dotnet/netframework-4.0/ms256086(v%3dvs.100) pour d'autres exemples. Vous pouvez également trouver un XPath d'un nœud <html> dans les outils de développement Chromium/Google Chrome en cliquant avec le bouton droit sur le nœud et en sélectionnant copier XPath.

FILTRAGE BASÉ SUR DES SÉLECTEURS CSS

Pour filtrer basé sur un sélecteur CSS https://www.w3.org/TR/2011/REC-css3-selectors-20110929/, vous pouvez utiliser le filtre css comme ceci :

url: https://example.net/css.html
filter:
  - css: ul#groceries > li.unchecked

Ceci filtrerait uniquement les balises <li class="unchecked"> directement sous les éléments <ul id="groceries">.

Certaines limitations et extensions existent comme expliqué dans la documentation de cssselect https://cssselect.readthedocs.io/en/latest/#supported-selectors.

UTILISATION DES FILTRES XPATH ET CSS AVEC XML ET EXCLUSIONS

Par défaut, les filtres XPath et CSS sont configurés pour les documents HTML. Cependant, il est possible de les utiliser également pour les documents XML (ces exemples analysent un flux RSS et filtrent uniquement les titres et les dates de publication) :

url: https://example.com/blog/xpath-index.rss
filter:
  - xpath:
      path: '//item/title/text()|//item/pubDate/text()'
      method: xml
url: http://example.com/blog/css-index.rss
filter:
  - css:
      selector: 'item > title, item > pubDate'
      method: xml
  - html2text: re

Pour faire correspondre un élément dans un espace de noms XML https://www.w3.org/TR/xml-names/, utilisez un préfixe d'espace de noms avant le nom de la balise. Utilisez un : pour séparer

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

te le préfixe d'espace de noms et le nom de balise dans une expression XPath, et utilisez un | dans un sélecteur CSS.

url: https://example.net/feed/xpath-namespace.xml
filter:
  - xpath:
      path: '//item/media:keywords/text()'
      method: xml
      namespaces:
        media: http://search.yahoo.com/mrss/
url: http://example.org/feed/css-namespace.xml
filter:
  - css:
      selector: 'item > media|keywords'
      method: xml
      namespaces:
        media: http://search.yahoo.com/mrss/
  - html2text

Alternativement, utilisez l'expression XPath //*[name()='<nom_de_balise>'] pour contourner complètement l'espace de noms.

Une autre option utile avec les filtres XPath et CSS est exclude. Les éléments sélectionnés par cette expression exclude sont supprimés du résultat final. Par exemple, le travail suivant n'aura aucune balise <a> dans ses résultats :

url: https://example.org/css-exclude.html
filter:
  - css:
      selector: body
      exclude: a

LIMITER LES ÉLÉMENTS RENVOYÉS PAR UN SÉLECTEUR CSS OU XPATH

Si vous ne souhaitez renvoyer qu'un sous-ensemble des éléments renvoyés par un sélecteur CSS ou un filtre XPath, vous pouvez utiliser deux sous-filtres supplémentaires :

  • skip : Nombre d'éléments à ignorer depuis le début (par défaut : 0).
  • maxitems : Nombre maximum d'éléments à renvoyer (par défaut : pas de limite).

Par exemple, si la page contient plusieurs éléments, mais que vous ne souhaitez sélectionner que le deuxième et le troisième élément correspondant (ignorer le premier, et renvoyer au plus deux éléments), vous pouvez utiliser ce filtre :

url: https://example.net/css-skip-maxitems.html
filter:
  - css:
      selector: div.cpu
      skip: 1
      maxitems: 2

GÉRER LES RÉSULTATS DUPLIQUÉS

Si vous obtenez plusieurs résultats sur une page, mais que vous n'en attendiez qu'un (par exemple, parce que la page contient à la fois une version mobile et une version de bureau dans le même document HTML, et affiche/masque l'une via CSS en fonction de la taille de la fenêtre d'affichage), vous pouvez utiliser maxitems: 1 pour ne renvoyer que le premier élément.

CORRIGER LES RENVOIS DES LISTES AVEC LES FILTRES DE SÉLECTEUR CSS OU XPATH

Dans certains cas, l'ordre des éléments sur une page web peut changer régulièrement sans que le contenu réel ne change. Par défaut, cela apparaîtrait dans la sortie de différence comme un élément étant retiré d'une partie de la page et inséré dans une autre partie de la page.

Dans les cas où l'ordre des éléments n'a pas d'importance, il est possible de trier les éléments correspondants lexicographiquement pour éviter des rapports fantaisistes lorsque seul l'ordre des éléments change sur la page.

Le sous-filtre pour les filtres css et xpath est sort, et peut être true ou false (la valeur par défaut) :

url: https://example.org/items-random-order.html
filter:
  - css:
      selector: span.item
      sort: true

FILTRAGE DES DOCUMENTS PDF

Pour surveiller le texte d'un fichier PDF, utilisez le filtre pdf2text. Il nécessite l'installation de la bibliothèque pdftotext https://github.com/jalan/pdftotext/blob/master/README.md#pdftotext et de ses dépendances spécifiques au système d'exploitation https://github.com/jalan/pdftotext/blob/master/README.md#os-dependencies.

Ce filtre doit être le premier filtre d'une chaîne de filtres, car il consomme des données binaires et génère des données textuelles.

url: https://example.net/pdf-test.pdf
filter:
  - pdf2text
  - strip

Si le fichier PDF est protégé par mot de passe, vous pouvez spécifier son mot de passe :

url: https://example.net/pdf-test-password.pdf
filter:
  - pdf2text:
      password: urlwatchsecret
  - strip

GESTION DES ENTRÉES CSV

Le filtre csv2text peut être utilisé pour transformer des données CSV en une représentation textuelle plus propre. Ceci est fait en fournissant une format_string qui est une chaîne de formatage python https://docs.python.org/3/library/string.html#format-string-syntax.

Si le CSV a un en-tête, la chaîne de formatage doit utiliser les noms d'en-tête en minuscules. Par exemple, supposons que nous ayons un fichier CSV contenant des données comme celles-ci :

Name;Company
Smith;Initech
Doe;Initech

Une chaîne de formatage possible pour le CSV ci-dessus (notez les clés en minuscules) :

Mr {name} works at {company}

S'il n'y a pas de ligne d'en-tête, vous devrez utiliser la notation de tableau numérique :

Mr {0} works at {1}

Vous pouvez forcer l'utilisation des indices numériques avec le drapeau ignore_header.

La clé has_header peut être utilisée pour forcer l'utilisation de la première ligne ou ignorer la première ligne en tant qu'en-tête, sinon csv.Sniffer https://docs.python.org/3/library/csv.html#csv.Sniffer sera utilisé.

TRI DU CONTENU DE PAGE WEB

Parfois, une page web peut avoir les mêmes données entre les comparaisons mais elles apparaissent dans un ordre aléatoire. Si cela se produit, vous pouvez choisir de trier avant la comparaison.

url: https://example.net/sorting.txt
filter:
  - sort

Le filtre de tri prend un paramètre facultatif separator qui définit le séparateur d'éléments (par défaut, le tri est basé sur les lignes), par exemple pour trier des paragraphes de texte (texte séparé par une ligne vide) :

url: http://example.org/paragraphs.txt
filter:
  - sort:
      separator: "\n\n"

Cela peut être combiné avec une option booléenne reverse, qui est utile pour trier et inverser avec le même séparateur (en utilisant % comme séparateur, cela transformerait 3%2%4%1 en 4%3%2%1) :

url: http://example.org/sort-reverse-percent.txt
filter:
  - sort:
      separator: '%'
      reverse: true

INVERSER LES LIGNES OU LES ÉLÉMENTS SÉPARÉS

Pour inverser l'ordre des éléments sans trier, le filtre reverse peut être utilisé. Par défaut, il inverse les lignes :

url: http://example.com/reverse-lines.txt
filter:
  - reverse

Ce comportement peut être modifié en utilisant un argument de chaîne de séparateur facultatif (par exemple, des éléments séparés par un symbole pipe (|), comme dans 1|4|2|3, qui serait inversé en 3|2|4|1) :

url: http://example.net/reverse-separator.txt
filter:
  - reverse: '|'

Alternativement, le filtre peut être spécifié de manière plus verbeuse avec un dict. Dans cet exemple, "\n\n" est utilisé pour séparer les paragraphes (éléments séparés par une ligne vide) :

url: http://example.org/reverse-paragraphs.txt
filter:
  - reverse:
      separator: "\n\n"

SURVEILLER LES VERSIONS GITHUB ET LES TAGS GITLAB

Voici un exemple de la façon de surveiller la page “releases” de GitHub pour un projet donné afin d'obtenir la dernière version, pour être notifié des nouvelles versions :

url: https://github.com/tulir/gomuks/releases
filter:
  - xpath:
      path: //*[@class="Link--primary Link"]
      maxitems: 1
  - html2text:

Ceci est la version correspondante pour les tags GitHub :

url: https://github.com/thp/urlwatch/tags
filter:
  - xpath:
      path: //*[@class="Link--primary Link"]
      maxitems: 1
  - html2text:

et pour les tags Gitlab :

url: https://gitlab.com/chinstrap/gammastep/-/tags
filter:
  - xpath: (//a[contains(@class,"item-title ref-name")])[1]
  - html2text

Alternativement, jq peut être utilisé pour le filtrage :

url: https://api.github.com/repos/voxpupuli/puppet-rundeck/tags
filter:
  - jq: '.[0].name'

TROUVER, SUPPRIMER OU REMPLACER DU TEXTE AVEC DES EXPRESSIONS RÉGULIÈRES

Vous pouvez utiliser re.sub et re.findall pour appliquer des expressions régulières.

re.sub peut être utilisé pour supprimer ou remplacer toutes les instances non chevauchantes de texte correspondant. L'exemple suivant applique le filtre 3 fois :

1.
Spécifier simplement une chaîne comme valeur remplacera les correspondances par la chaîne vide.
2.
Les modèles simples peuvent être remplacés par une autre chaîne en utilisant “pattern” comme expression et “repl” comme remplacement.
3.
Vous pouvez utiliser des groupes (()) et les référencer avec \1 (etc.) pour insérer des groupes dans la chaîne de remplacement.

repl est par défaut la chaîne vide, ce qui supprimera les chaînes correspondantes.

url: https://example.com/regex-substitute.html
filter:
    - re.sub: '\s*href="[^"]*"'
    - re.sub:
        pattern: '<h1>'

EXPRESSIONS

Les filtres re.sub et re.findall vous permettent de traiter le texte à l'aide d'expressions régulières.

L'exemple suivant utilise re.sub pour modifier la façon dont les balises HTML sont affichées dans le texte :

url: https://example.com/regex-sub.html
filter:
    - re.sub:
        pattern: '<h1>(.*?)</h1>'
        repl: 'HEADING 1: \1'
    - re.sub:
        pattern: '</([^>]*)>'
        repl: '<END OF TAG \1>'

re.findall peut être utilisé pour trouver toutes les correspondances non chevauchantes d'une expression régulière. Chaque correspondance est affichée sur sa propre ligne. L'exemple suivant applique le filtre deux fois :

1.
Il utilise un groupe (()) et une référence arrière (\1) pour extraire une date de la chaîne d'entrée.
2.
Il sépare les nombres de la date sur des lignes distinctes.

Si repl n'est pas spécifié, la correspondance complète sera incluse dans la sortie.

url: https://example.com/regex-findall.html
filter:
    - re.findall:
        pattern: 'The next draw is on (\d{4}-\d{2}-\d{2}).'
        repl: '\1'
    - re.findall: '\d+'

Remarque : lors de l'utilisation de HTML ou XML, il est généralement préférable d'utiliser des sélecteurs CSS ou des expressions XPATH. HTML et XML *ne peuvent pas être analysés* https://stackoverflow.com/a/1732454/1047040 correctement à l'aide d'expressions régulières. Si le sélecteur CSS ou XPATH ne permet pas la sélection ciblée requise, l'utilisation d'un filtre html2text en premier, puis de re.findall peut être un bon schéma.

Si vous souhaitez activer des indicateurs (par exemple, re.MULTILINE) dans les filtres re.sub ou re.findall, utilisez un « indicateur en ligne », voici quelques exemples :

  • re.MULTILINE : (?m) (fait correspondre ^ au début de la ligne et $ à la fin de la ligne)
  • re.DOTALL : (?s) (fait correspondre . également à une nouvelle ligne)
  • re.IGNORECASE : (?i) (Effectue une recherche insensible à la casse)

Cela vous permet, par exemple, de supprimer tous les espaces de début (caractère d'espace et tabulation uniquement) :

url: http://example.com/leading-spaces.txt
filter:
  - re.sub: '(?m)^[ \t]*'

UTILISATION D'UN SCRIPT SHELL COMME FILTRE

Bien que les filtres intégrés soient puissants pour traiter le balisage tel que HTML et XML, dans certains cas, vous savez peut-être déjà comment vous filtreriez votre contenu à l'aide d'une commande shell ou d'un script shell. Le filtre shellpipe vous permet de démarrer un shell et d'exécuter des commandes personnalisées pour filtrer le contenu.

Les données textuelles à filtrer seront écrites dans l'entrée standard (stdin) du processus shell et la sortie du filtre sera prise de la sortie standard (stdout) du shell.

Par exemple, si vous souhaitez utiliser l'outil grep avec l'option de correspondance insensible à la casse (-i) et afficher uniquement la partie correspondante de la ligne (-o), vous pouvez le spécifier comme filtre shellpipe :

url: https://example.net/shellpipe-grep.txt
filter:
  - shellpipe: "grep -i -o 'price: <span>.*</span>'"

Cette fonctionnalité vous permet également d'utiliser des sed(1), awk(1) et des perl(1) en une seule ligne pour le traitement du texte (bien sûr, tout outil de texte fonctionnant dans un shell peut être utilisé). Par exemple, cette ligne unique awk(1) prépende le numéro de ligne à chaque ligne :

url: https://example.net/shellpipe-awk-oneliner.txt
filter:
  - shellpipe: awk '{ print FNR " " $0 }'

Vous pouvez également utiliser une commande multi-lignes pour un script shell plus sophistiqué (| dans YAML indique le début d'un bloc de texte) :

url: https://example.org/shellpipe-multiline.txt
filter:
  - shellpipe: |
      FILENAME=`mktemp`
      # Copie l'entrée dans un fichier temporaire, puis la redirige via awk
      tee $FILENAME | awk '/The numbers for (.*) are:/,/The next draw is on (.*)./'
      # Analyse le fichier d'entrée d'une autre manière
      echo "Input lines: $(wc -l $FILENAME | awk '{ print $1 }')"
      rm -f $FILENAME

Dans le script shellpipe, deux variables d'environnement seront définies pour une personnalisation supplémentaire (cela peut être utile si vous avez un fichier de script shell externe utilisé comme filtre pour plusieurs travaux, mais qui doit traiter chaque travail d'une manière légèrement différente) :

Variable d'environnement Contenu
$URLWATCH_JOB_NAME Le nom du travail (clé name dans le YAML des travaux)
$URLWATCH_JOB_LOCATION L'URL du travail, ou la ligne de commande (pour les travaux shell)

CONVERTIR LE TEXTE DES IMAGES EN TEXTE BRUT

Le filtre ocr utilise le *moteur OCR Tesseract* https://github.com/tesseract-ocr pour convertir le texte des images en texte brut. Il nécessite l'installation de deux modules Python : pytesseract https://github.com/madmaze/pytesseract et Pillow https://python-pillow.org. Tous les formats de fichiers pris en charge par Pillow (PIL) sont pris en charge.

Ce filtre *doit* être le premier filtre d'une chaîne de filtres, car il consomme des données binaires et produit des données textuelles.

url: https://example.net/ocr-test.png
filter:
  - ocr:
      timeout: 5
      language: eng
  - strip

Les sous-filtres timeout et language sont facultatifs :

  • timeout : Délai d'attente pour la reconnaissance, en secondes (défaut : 10 secondes)
  • language : Langue du texte (par exemple, fra ou eng+fra, par défaut : eng)

FILTRAGE DES DONNÉES DE RÉPONSE JSON À L'AIDE DES SÉLECTEURS JQ

Le filtre jq utilise les liaisons Python pour *jq* https://stedolan.github.io/jq/, un processeur JSON léger. L'utilisation de ce filtre nécessite l'installation du module Python optionnel *jq* https://github.com/mwilliamson/jq.py.

url: https://example.net/jobs.json
filter:
   - jq:
      query: '.[].title'

Le sous-filtre query est facultatif :

•
query : Une chaîne de filtre jq valide.

Prend en charge les agrégations, les sélections et les opérateurs intégrés tels que length. Pour plus d'informations sur les opérations autorisées, voir le *Manuel jq* https://stedolan.github.io/jq/manual/.

urlwatch-filters - Description des filtres disponibles pour urlwatch

NAME

urlwatch-filters - Description des filtres disponibles pour urlwatch

SYNOPSIS

Les filtres sont utilisés pour traiter le contenu des URL surveillées avant de comparer la version actuelle avec la version précédente.

DESCRIPTION

urlwatch supporte l'utilisation de divers filtres pour le traitement du contenu web. Ces filtres peuvent être des programmes externes, des scripts Python, des scripts shell, ou des outils spécifiques comme jq pour le JSON. L'objectif est de normaliser le contenu pour une comparaison plus pertinente, par exemple en supprimant les publicités, en convertissant le HTML en texte brut, ou en extrayant des informations spécifiques.

Les filtres sont configurés dans le fichier de configuration de urlwatch, généralement sous la section [filters] ou via des options en ligne de commande. Chaque filtre reçoit le contenu brut de l'URL en entrée standard et doit produire le contenu filtré en sortie standard.

AVAILABLE FILTERS

USING EXTERNAL PROGRAMS AS FILTERS

Vous pouvez utiliser n'importe quel programme exécutable comme filtre. urlwatch appellera ce programme avec le contenu de l'URL en entrée standard et utilisera sa sortie standard comme contenu filtré.

Exemple de configuration :

[filters]
my_filter = /usr/bin/mon_programme_filtre

USING PYTHON SESSIONS

Pour des traitements plus complexes, vous pouvez écrire des scripts Python. urlwatch peut exécuter ces scripts et passer le contenu de l'URL comme argument.

Exemple de configuration :

[filters]
python_filter = python /chemin/vers/mon_script.py

Le script Python doit lire depuis sys.stdin et écrire sur sys.stdout.

USING A SHELL SCRIPT AS A FILTER

Similaire aux programmes externes, vous pouvez utiliser des scripts shell. Assurez-vous que le script est exécutable.

Exemple de configuration :

[filters]
shell_script_filter = /bin/bash /chemin/vers/mon_script.sh

CONVERTING TEXT IN IMAGES TO PLAINTEXT

urlwatch peut utiliser des outils comme tesseract pour extraire du texte des images (par exemple, si une page web contient des images avec du texte).

Exemple de configuration (nécessite l'installation de tesseract) :

[filters]
image_to_text = tesseract stdin stdout --psm 6

L'option --psm 6 suppose une page de texte unique. Ajustez selon vos besoins.

FILTERING JSON RESPONSE DATA USING JQ SELECTORS

Pour les réponses JSON, l'outil jq est extrêmement utile pour sélectionner et reformater des parties spécifiques des données.

Exemple de configuration pour extraire une clé spécifique :

[filters]
json_data = jq .ma_cle_specifique

Vous pouvez utiliser n'importe quel sélecteur jq valide.

FILES

~/.config/urlwatch/urlwatch.yml : Fichier de configuration utilisateur principal.

/etc/urlwatch/urlwatch.yml : Fichier de configuration système.
