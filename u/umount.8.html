UMOUNT(8) Administration système UMOUNT(8)

NOM

umount - démonter des systèmes de fichiers

SYNTAXE

umount -a [-dflnrv] [-t type_fs] [-O option...]

umount [-dflnrv] {répertoire|périphérique}

umount -h|-V

DESCRIPTION

La commande umount détache le(s) système(s) de fichiers mentionné(s) de la hiérarchie des fichiers. Un système de fichiers est spécifié en donnant le répertoire où il a été monté. Donner le périphérique spécial sur lequel le système de fichiers vit peut aussi fonctionner, mais est obsolète, principalement parce que cela échouera dans le cas où ce périphérique a été monté sur plus d'un répertoire.

Notez qu'un système de fichiers ne peut pas être démonté lorsqu'il est 'occupé' - par exemple, lorsqu'il y a des fichiers ouverts dessus, ou lorsqu'un processus a son répertoire de travail là, ou lorsqu'un fichier d'échange dessus est en cours d'utilisation. Le processus fautif pourrait même être umount lui-même - il ouvre libc, et libc à son tour peut ouvrir par exemple des fichiers de localisation. Un démontage paresseux évite ce problème, mais peut introduire d'autres soucis. Voir la description de --lazy ci-dessous.

OPTIONS

-a, --all

Tous les systèmes de fichiers décrits dans /proc/self/mountinfo (ou dans le déprécié /etc/mtab) sont démontés, sauf les systèmes de fichiers proc, devfs, devpts, sysfs, rpc_pipefs et nfsd. Cette liste de systèmes de fichiers peut être remplacée par l'option --types de umount.

-A, --all-targets

Démonte tous les points de montage dans l'espace de noms de montage actuel pour le système de fichiers spécifié. Le système de fichiers peut être spécifié par l'un des points de montage ou par le nom du périphérique (ou UUID, etc.). Lorsque cette option est utilisée avec --recursive, tous les montages imbriqués dans le système de fichiers sont démontés récursivement. Cette option n'est prise en charge que sur les systèmes où /etc/mtab est un lien symbolique vers /proc/mounts.

-c, --no-canonicalize

Ne pas canoniser les chemins. La canonisation des chemins est basée sur les appels système stat(2) et readlink(2). Ces appels système peuvent bloquer dans certains cas (par exemple sur NFS si le serveur n'est pas disponible). L'option doit être utilisée avec le chemin canonisé du point de montage.

Cette option est ignorée silencieusement par umount pour les utilisateurs non root.

Pour plus de détails sur cette option, consultez la page de manuel mount(8). Notez que umount ne passe pas cette option aux utilitaires /sbin/umount.type.

-d, --detach-loop

Lorsque le périphérique démonté était un périphérique de boucle, libérez également ce périphérique de boucle. Cette option est inutile pour les périphériques initialisés par mount(8), dans ce cas la fonctionnalité "autoclear" est activée par défaut.

--fake

Fait tout sauf l'appel système réel ou l'exécution de l'utilitaire de démontage ; cela 'simule' le démontage du système de fichiers. Il peut être utilisé pour supprimer des entrées de /etc/mtab déprécié qui ont été démontées précédemment avec l'option -n.

-f, --force

Forcer un démontage (en cas de système NFS inaccessible).

Notez que cette option ne garantit pas que la commande umount ne bloquera pas. Il est fortement recommandé d'utiliser des chemins absolus sans liens symboliques pour éviter les appels système readlink(2) et stat(2) non désirés sur NFS inaccessible dans umount.

-i, --internal-only

N'appelle pas l'utilitaire /sbin/umount.filesystem même s'il existe. Par défaut, un tel programme utilitaire est appelé s'il existe.

-l, --lazy

Démontage paresseux. Détache le système de fichiers de la hiérarchie des fichiers maintenant, et nettoie toutes les références à ce système de fichiers dès qu'il n'est plus occupé.

Un redémarrage du système serait attendu dans un avenir proche si vous allez utiliser cette option pour un système de fichiers réseau ou un système de fichiers local avec des sous-montages. L'utilisation recommandée de umount -l est d'éviter les blocages à l'arrêt dus à un partage réseau inaccessible où un umount normal bloquera en raison d'un serveur en panne ou d'une partition réseau. Les remontages du partage ne seront pas possibles.

-N, --namespace ns

Effectue umount dans l'espace de noms de montage spécifié par ns. ns est soit le PID d'un processus s'exécutant dans cet espace de noms, soit un fichier spécial représentant cet espace de noms.

umount bascule dans l'espace de noms lors de la lecture de /etc/fstab, de l'écriture de /etc/mtab (ou de l'écriture dans /run/mount) et de l'appel à l'appel système umount(2), sinon il s'exécute dans l'espace de noms d'origine. Cela signifie que l'espace de noms de montage cible n'a pas besoin de contenir de bibliothèques ou d'autres exigences nécessaires pour exécuter la commande umount(2).

Voir mount_namespaces(7) pour plus d'informations.

-n, --no-mtab

Démonte sans écrire dans /etc/mtab.

-O, --test-opts option...

Démonte uniquement les systèmes de fichiers qui ont l'option spécifiée définie dans /etc/fstab. Plusieurs options peuvent être spécifiées dans une liste séparée par des virgules. Chaque option peut être préfixée par no pour indiquer qu'aucune action ne doit être effectuée pour cette option.

-q, --quiet

Supprimer les messages d'erreur "non monté".

-R, --recursive

Démonte récursivement chaque répertoire spécifié. La récursion pour chaque répertoire s'arrêtera si une opération de démontage dans la chaîne échoue pour quelque raison que ce soit. La relation entre les points de montage est déterminée par les entrées de /proc/self/mountinfo. Le système de fichiers doit être spécifié par le chemin du point de montage ; un démontage récursif par nom de périphérique (ou UUID) n'est pas pris en charge. Depuis la version 2.37, il démonte également tous les systèmes de fichiers sur-montés (plusieurs systèmes de fichiers sur le même point de montage).

-r, --read-only

En cas d'échec du démontage, essayer de remonter le système de fichiers en lecture seule.

-t, --types type...

Indique que les actions ne doivent être effectuées que sur les systèmes de fichiers du type spécifié. Plusieurs types peuvent être spécifiés dans une liste séparée par des virgules. La liste des types de systèmes de fichiers peut être préfixée par no pour indiquer qu'aucune action ne doit être effectuée pour tous les types mentionnés. Notez que umount lit les informations sur les systèmes de fichiers montés à partir du noyau (/proc/mounts) et que les noms de systèmes de fichiers peuvent être différents des noms de systèmes de fichiers utilisés dans /etc/fstab (par exemple, "nfs4" vs "nfs").

-v, --verbose

Mode verbeux.

-h, --help

Afficher le texte d'aide et quitter.

-V, --version

Afficher la version et quitter.

DEMONTAGE PAR NON-SUPERUTILISATEUR

Normalement, seul le superutilisateur peut démonter des systèmes de fichiers. Cependant, lorsque fstab contient l'option user sur une ligne, n'importe qui peut démonter le système de fichiers correspondant. Pour plus de détails, voir la page de manuel mount(8).

Depuis la version 2.34, la commande umount peut être utilisée pour effectuer l'opération de démontage également pour les systèmes de fichiers fuse si la table de montage du noyau contient l'ID de l'utilisateur. Dans ce cas, l'option de montage fstab user= n'est pas requise.

Depuis la version 2.35, la commande umount ne se termine pas lorsque les permissions utilisateur sont inadéquates selon les règles de sécurité internes de libmount. Elle abandonne les permissions suid et continue en tant qu'utilisateur régulier non root. Cela peut être utilisé pour prendre en charge les cas d'utilisation où les permissions root ne sont pas nécessaires (par exemple, les systèmes de fichiers fuse, les espaces de noms utilisateur, etc.).

LOOP DEVICE

The umount command will automatically detach loop device previously initialized by mount(8) command independently of /etc/mtab.

In this case the device is initialized with "autoclear" flag (see losetup(8) output for more details), otherwise it’s necessary to use the option --detach-loop or call losetup -d device. The autoclear feature is supported since Linux 2.6.25.

Note that since Linux v3.7 kernel uses "lazy device destruction". The system just marks the loop device by autoclear flag and destroys it later. If you need to wait for a complete removal of the loop device, call udevadm settle after umount.

STATUT DE SORTIE

umount a les valeurs de statut de sortie suivantes (les bits peuvent être combinés par OU) :

0

succès

1

invocation incorrecte ou permissions

2

erreur système (pas assez de mémoire, impossible de forker, pas de périphériques de boucle disponibles)

4

bug interne de mount

8

interruption utilisateur

16

problèmes d'écriture ou de verrouillage de /etc/mtab

32

échec du montage

64

certains démontages ont réussi

La commande umount -a retourne 0 (tout a réussi), 32 (tout a échoué), ou 64 (certains ont échoué, d'autres ont réussi).

126

échec de l'exécution de l'aide externe /sbin/umount.<type> (depuis util-linux v2.41)

AIDES EXTERNES

La syntaxe des aides de démontage externes est :

umount.suffixe {répertoire|périphérique} [-flnrv] [-N espace de noms] [-t type.sous-type]

où suffixe est le type de système de fichiers (ou la valeur d'un marqueur uhelper= ou helper= dans le fichier mtab). L'option -t peut être utilisée pour les systèmes de fichiers qui prennent en charge les sous-types. Par exemple :

umount.fuse -t fuse.sshfs

Un marqueur uhelper=quelque chose (aide non privilégiée) peut apparaître dans le fichier /etc/mtab lorsque les utilisateurs ordinaires doivent pouvoir démonter un point de montage qui n'est pas défini dans /etc/fstab (par exemple pour un périphérique qui a été monté par udisks(1)).

Un marqueur helper=type dans le fichier mtab redirigera toutes les demandes de démontage vers l'aide /sbin/umount.type indépendamment de l'UID.

Notez que /etc/mtab est actuellement obsolète et que les options de montage helper= et autres options de l'espace utilisateur sont gérées par libmount.

La valeur du statut de sortie de l'aide est retournée comme statut de sortie de umount(8). La valeur 126 est utilisée si le programme d'aide au montage est trouvé, mais que l'appel execl() a échoué.

ENVIRONNEMENT

LIBMOUNT_FSTAB=<chemin>

remplace l'emplacement par défaut du fichier fstab (ignoré pour suid)

LIBMOUNT_DEBUG=all

active la sortie de débogage de libmount

FICHIERS

/etc/mtab

tableau des systèmes de fichiers montés (obsolète et généralement remplacé par un lien symbolique vers /proc/mounts)

/etc/fstab

tableau des systèmes de fichiers connus

/proc/self/mountinfo

tableau des systèmes de fichiers montés généré par le noyau.

HISTORIQUE

Une commande umount est apparue dans la Version 6 d'AT&T UNIX.
