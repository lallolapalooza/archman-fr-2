utmp(5) Manual des formats de fichiers utmp(5)

NOM

utmp, wtmp - enregistrements de connexion

SYNOPSIS

#include <utmp.h>

DESCRIPTION

Le fichier utmp permet de découvrir des informations sur qui utilise actuellement le système. Il peut y avoir plus d'utilisateurs utilisant actuellement le système, car tous les programmes n'utilisent pas l'enregistrement utmp.

Attention : utmp ne doit pas être accessible en écriture par la classe d'utilisateurs "other", car de nombreux programmes système (bêtement) dépendent de son intégrité. Vous risquez des fichiers journaux système falsifiés et des modifications de fichiers système si vous laissez utmp accessible en écriture à tout utilisateur autre que le propriétaire et le groupe propriétaire du fichier.

Le fichier est une séquence de structures utmp, déclarées comme suit dans <utmp.h> (notez que ce n'est qu'une des plusieurs définitions existantes ; les détails dépendent de la version de libc) :


/* Valeurs pour le champ ut_type, ci-dessous */
#define EMPTY         0 /* L'enregistrement ne contient pas d'informations valides
                           (anciennement connu sous le nom de UT_UNKNOWN sous Linux) */
#define RUN_LVL       1 /* Changement du niveau d'exécution du système (voir
init(1)) 
*/
#define BOOT_TIME     2 /* Heure de démarrage du système (dans ut_tv) */
#define NEW_TIME      3 /* Heure après changement de l'horloge système
                           (dans ut_tv) */
#define OLD_TIME      4 /* Heure avant changement de l'horloge système
                           (dans ut_tv) */
#define INIT_PROCESS  5 /* Processus lancé par
init(1) 
*/
#define LOGIN_PROCESS 6 /* Processus chef de session pour la connexion utilisateur */
#define USER_PROCESS  7 /* Processus normal */
#define DEAD_PROCESS  8 /* Processus terminé */
#define ACCOUNTING    9 /* Non implémenté */
#define UT_LINESIZE      32
#define UT_NAMESIZE      32
#define UT_HOSTSIZE     256
struct exit_status {              /* Type pour ut_exit, ci-dessous */
    short e_termination;          /* Statut de terminaison du processus */
    short e_exit;                 /* Statut de sortie du processus */
};
struct utmp {
    short   ut_type;              /* Type d'enregistrement */
    pid_t   ut_pid;               /* PID du processus de connexion */
    char    ut_line[UT_LINESIZE]; /* Nom du périphérique de tty - "/dev/" */
    char    ut_id[4];             /* Suffixe du nom du terminal,
                                     ou ID d'inittab(5) */
    char    ut_user[UT_NAMESIZE]; /* Nom d'utilisateur */
    char    ut_host[UT_HOSTSIZE]; /* Nom d'hôte pour la connexion distante, ou
                                     version du noyau pour les messages de niveau d'exécution */
    struct  exit_status ut_exit;  /* Statut de sortie d'un processus
                                     marqué comme DEAD_PROCESS ; non
                                     utilisé par init(1) sous Linux 
*/
    /* Les champs ut_session et ut_tv doivent avoir la même taille lors
       de la compilation en 32 et 64 bits. Cela permet de partager les fichiers
       de données et la mémoire partagée entre les applications 32 et 64 bits.  */
#if __WORDSIZE == 64 && defined __WORDSIZE_COMPAT32
    int32_t ut_session;           /* ID de session (
getsid(2)),
                                     utilisé pour le fenêtrage */
    struct {
        int32_t tv_sec;           /* Secondes */
        int32_t tv_usec;          /* Microsecondes */
    } ut_tv;                      /* Heure à laquelle l'enregistrement a été créé */
#else
     long   ut_session;           /* ID de session */
     struct timeval ut_tv;        /* Heure à laquelle l'enregistrement a été créé */
#endif
    int32_t ut_addr_v6[4];        /* Adresse Internet de l'hôte distant ;
                                     l'adresse IPv4 utilise uniquement
                                     ut_addr_v6[0] */
    char __unused[20];            /* Réservé pour usage futur */
};
/* Hacks de compatibilité ascendante */
#define ut_name ut_user
#ifndef _NO_UT_TIME
#define ut_time ut_tv.tv_sec
#endif
#define ut_xtime ut_tv.tv_sec
#define ut_addr ut_addr_v6[0]

Cette structure donne le nom du fichier spécial associé au terminal de l'utilisateur, le nom de connexion de l'utilisateur, et l'heure de connexion sous la forme de time(2). Les champs de type chaîne se terminent par un octet nul ('\0') s'ils sont plus courts que la taille du champ.

Les premières entrées créées résultent du traitement de inittab(5) par init(1). Avant qu'un enregistrement ne soit traité, cependant, init(1) nettoie utmp en mettant ut_type à DEAD_PROCESS, en effaçant ut_user, ut_host, et ut_time avec des octets nuls pour chaque enregistrement dont ut_type n'est pas DEAD_PROCESS ou RUN_LVL et où aucun processus avec le PID ut_pid n'existe. Si aucun enregistrement vide avec le ut_id requis n'est trouvé, init(1) en crée un nouveau. Il définit ut_id à partir d'inittab, ut_pid et ut_time aux valeurs actuelles, et ut_type à INIT_PROCESS.

mingetty(8) (ou agetty(8)) localise l'enregistrement par le PID, change ut_type en LOGIN_PROCESS, change ut_time, définit ut_line, et attend que la connexion soit établie. login(1), après qu'un utilisateur a été authentifié, change ut_type en USER_PROCESS, change ut_time, et définit ut_host et ut_addr. Selon mingetty(8) (ou agetty(8)) et login(1), les enregistrements peuvent être localisés par ut_line au lieu de préférer ut_pid.

Lorsque init(1) constate qu'un processus s'est terminé, il localise son enregistrement utmp par ut_pid, définit ut_type en DEAD_PROCESS, et efface ut_user, ut_host, et ut_time avec des octets nuls.

xterm(1) et d'autres émulateurs de terminaux créent directement un enregistrement USER_PROCESS et génèrent le ut_id en utilisant la chaîne qui est le suffixe du nom du terminal (les caractères suivant /dev/[pt]ty). S'ils trouvent un DEAD_PROCESS pour cet ID, ils le recyclent, sinon ils créent un nouvel enregistrement. S'ils le peuvent, ils le marqueront comme DEAD_PROCESS à la sortie et il est conseillé qu'ils mettent également à zéro ut_line, ut_time, ut_user, et ut_host.

telnetd(8) configure un enregistrement LOGIN_PROCESS et laisse le reste à login(1) comme d'habitude. Une fois la session telnet terminée, telnetd(8) nettoie utmp de la manière décrite.

Le fichier wtmp enregistre toutes les connexions et déconnexions. Son format est exactement le même que utmp, sauf qu'un nom d'utilisateur nul indique une déconnexion sur le terminal associé. De plus, le nom de terminal ~ avec le nom d'utilisateur shutdown ou reboot indique un arrêt ou un redémarrage du système, et la paire de noms de terminaux |/} enregistre l'ancienne/nouvelle heure système lorsque date(1) la modifie. wtmp est maintenu par login(1), init(1), et certaines versions de getty(8) (par ex. mingetty(8) ou agetty(8)). Aucun de ces programmes ne crée le fichier, donc s'il est supprimé, l'enregistrement est désactivé.

FICHIERS

/var/run/utmp
/var/log/wtmp

VERSIONS

POSIX.1 ne spécifie pas de structure utmp, mais plutôt une nommée utmpx (dans le cadre de l'extension XSI), avec des spécifications pour les champs ut_type, ut_pid, ut_line, ut_id, ut_user et ut_tv. POSIX.1 ne spécifie pas les longueurs des champs ut_line et ut_user.

Linux définit la structure utmpx comme étant identique à la structure utmp.

NORMES

Linux.

HISTORIQUE

Les enregistrements utmp de Linux ne sont conformes ni à v7/BSD ni à System V ; ils sont un mélange des deux.

v7/BSD a moins de champs ; plus important encore, il manque ut_type, ce qui fait que les programmes de type v7/BSD natifs affichent (par exemple) des entrées mortes ou de connexion. De plus, il n'y a pas de fichier de configuration qui alloue des emplacements aux sessions. BSD le fait car il manque des champs ut_id.

Sous Linux (comme sous System V), le champ ut_id d'un enregistrement ne changera jamais une fois qu'il aura été défini, ce qui réserve cet emplacement sans avoir besoin d'un fichier de configuration. Effacer ut_id peut entraîner des conditions de concurrence conduisant à des entrées utmp corrompues et des trous de sécurité potentiels. Effacer les champs mentionnés ci-dessus par remplissage

utmpx(5) — man pages

NAME

utmpx, utmpx.h - utmp file structure

SYNOPSIS

#include <utmpx.h>

DESCRIPTION

The structure defined in <utmpx.h> is used to record information about user logins and logouts. This file is often named utmp. The structure contains at least the following members:

  • char ut_user[sizeof(ut_name)];
  • char ut_id[4];
  • char ut_type;
  • char ut_pid[4];
  • char ut_line[sizeof(ut_name)];
  • char ut_host[MAXHOSTNAMELEN];
  • struct exit_status ut_exit;
  • time_t ut_tv;
  • int32_t ut_session;
  • int32_t ut_addr_v6[4];

The fields are named and used as follows:

ut_user
The login name of the user.
ut_id
The identifier for the current run-level.
ut_type
Indicates the type of the entry. Possible values are:
  • EMPTY
  • RUN_LVL
  • BOOT_TIME
  • OLD_TIME
  • NEW_TIME
  • INIT_PROCESS
  • LOGIN_PROCESS
  • USER_PROCESS
  • DEAD_PROCESS
  • ACCOUNTING
ut_pid
The process ID associated with the entry.
ut_line
The terminal device name (e.g., tty0).
ut_host
The name of the host from which the user logged in (if remote).
ut_exit
The exit status of the dead process.
ut_tv
The time of the event.
ut_session
The session ID.
ut_addr_v6
The IPv6 address of the remote host.

The ut_type field is set to one of the UT_* constants defined in <utmpx.h>. The EMPTY entry is used to mark unused slots in the file.

The ut_host field is present for remote logins. The ut_addr_v6 field contains the IPv6 address of the remote host. Filling these with null bytes is not required by System V semantics, but makes it possible to run many programs which assume BSD semantics and which do not modify utmp. Linux uses the BSD conventions for line contents, as documented above.

System V has no ut_host or ut_addr_v6 fields.

NOTES

Unlike various other systems, where utmp logging can be disabled by removing the file, utmp must always exist on Linux. If you want to disable who(1), then do not make utmp world readable.

The file format is machine-dependent, so it is recommended that it be processed only on the machine architecture where it was created.

Note that on biarch platforms, that is, systems which can run both 32-bit and 64-bit applications (x86-64, ppc64, s390x, etc.), ut_tv is the same size in 32-bit mode as in 64-bit mode. The same goes for ut_session and ut_time if they are present. This allows data files and shared memory to be shared between 32-bit and 64-bit applications. This is achieved by changing the type of ut_session to int32_t, and that of ut_tv to a struct with two int32_t fields tv_sec and tv_usec. Since ut_tv may not be the same as struct timeval, then instead of the call:


gettimeofday((struct timeval *) &ut.ut_tv, NULL);

the following method of setting this field is recommended:


struct utmp ut;
struct timeval tv;
gettimeofday(&tv, NULL);
ut.ut_tv.tv_sec = tv.tv_sec;
ut.ut_tv.tv_usec = tv.tv_usec;
