NOM

upsd - Serveur de données Network UPS Tools

SYNTAXE

upsd -h

upsd [OPTIONS]

DESCRIPTION

upsd est responsable de la diffusion des données des pilotes aux clients. Il se connecte à chaque pilote et maintient un cache local de l'état actuel. Les requêtes des clients sont servies à partir de ce cache, de sorte que les délais sont minimes.

Il transmet également les messages administratifs des clients aux pilotes, tels que le lancement de tests ou la modification de valeurs.

La communication entre upsd et les clients est gérée sur un port TCP. Les détails de configuration de ce port sont décrits dans upsd.conf(5).

Ce programme est essentiel et doit être exécuté en permanence pour réellement utiliser les pilotes et les clients (à l'exception des commandes finales d'extinction de l'onduleur juste avant que votre serveur ne s'arrête, que les programmes pilotes NUT peuvent effectuer seuls lorsqu'ils sont appelés en tant que nompilote -k dans un hook de démarrage ou un script d'initialisation SysV ordonné tardivement).

Les contrôles dans les fichiers de configuration vous permettent de limiter l'accès au serveur, mais vous devriez également utiliser un pare-feu pour une protection supplémentaire. Les processus clients tels que upsmon(8) font confiance à upsd pour les informations de statut sur le matériel de l'onduleur, alors gardez-le sécurisé.

OPTIONS

-c commande

Envoie la commande au processus d'arrière-plan sous forme de signal. Les commandes valides sont :

reload

recharge les fichiers de configuration

stop

arrête le processus et quitte

-P pid

Envoie le signal de commande ci-dessus en utilisant le numéro de PID spécifié, plutôt que de consulter le fichier PID. Cela peut aider à définir des unités de service qui démarrent upsd en tant que processus de premier plan afin qu'il ne crée pas de fichier PID. Voir également l'option -FF comme alternative.

-D

Augmente le niveau de débogage. upsd s'exécutera en premier plan par défaut et affichera des informations sur stdout concernant le processus de surveillance. Utilisez cette option plusieurs fois pour plus de détails.

-F

upsd s'exécutera en premier plan, indépendamment des paramètres de débogage. Spécifiez deux fois (-FF ou -F -F) pour enregistrer le fichier PID même dans ce mode.

-B

upsd s'exécutera en arrière-plan, indépendamment des paramètres de débogage.

-h

Affiche le texte d'aide.

-r répertoire

upsd effectuera un chroot(2) vers le répertoire peu de temps après le démarrage et avant d'analyser les fichiers de configuration avec cette option définie. Vous pouvez l'utiliser pour créer une « jail » pour une sécurité accrue.

Vous devez coordonner cela avec vos pilotes, car upsd doit pouvoir trouver le chemin d'état dans le répertoire. Voir upsdrvctl(8) et nutupsdrv(8).

-u utilisateur

Commute vers l'utilisateur utilisateur après le démarrage si démarré en tant que root. Cela remplace tout ce que vous pourriez avoir compilé avec configure --with-user.

-V

Affiche la version du programme.

RECHARGEMENT

upsd peut recharger ses fichiers de configuration sans arrêter le processus si vous lui envoyez un SIGHUP ou si vous le démarrez à nouveau avec -c reload. Cela ne fonctionne que si le processus d'arrière-plan est capable de lire ces fichiers (permissions, jail chroot), et si le démon a sauvegardé un fichier PID lors de son démarrage (pour que la commande de rechargement trouve l'instance précédente).


Note

Les instances de service encapsulées par systemd ou SMF peuvent ne pas les enregistrer par défaut — utilisez plutôt les actions de rechargement/rafraîchissement respectives du framework), par exemple systemctl reload nut-server

Les versions de NUT après 2.8.0 définissent des alias pour ces unités, donc si votre distribution Linux utilise les définitions d'unités fournies par NUT, systemctl reload upsd peut également fonctionner.

Si vous pensez qu'upsd ne peut pas recharger, vérifiez votre syslog pour des messages d'erreur. S'il se plaint de ne pas pouvoir lire les fichiers, vous devez ajuster votre système pour le rendre possible. Changez les permissions des fichiers, ou exécutez upsd en tant qu'autre utilisateur qui pourra les lire, ou redémarrez-le complètement (peut être nécessaire par exemple si vous exécutez dans une jail chroot).

NE rendez PAS vos fichiers upsd.conf(5) ou upsd.users(5) lisibles par tous, car ils contiennent des informations d'authentification importantes. Entre de mauvaises mains, ils pourraient être utilisés par une personne malveillante pour usurper votre upsmon principal et commander l'arrêt de vos systèmes, par exemple.

DIAGNOSTICS

upsd s'attend à ce que les pilotes mettent à jour leur statut régulièrement ou au moins répondent aux requêtes périodiques, appelées pings. Si un pilote ne répond pas, upsd le déclarera « périmé » et aucune autre information ne sera fournie aux clients.

Si upsd se plaint de périmé au démarrage, alors soit votre pilote, soit vos fichiers de configuration sont probablement défectueux. Assurez-vous que le pilote est réellement en cours d'exécution et que la définition de l'onduleur dans ups.conf(5) est correcte. Assurez-vous également que vous démarrez vos pilotes avant de démarrer upsd.

Les données peuvent également être marquées comme périmées si le pilote ne peut plus communiquer avec l'onduleur. Dans ce cas, le pilote devrait également fournir des informations de diagnostic dans le syslog. Si cela se produit, vérifiez les câblages série ou USB, ou inspectez le chemin réseau dans le cas d'un onduleur SNMP.

CONTROLE D'ACCES

Si le serveur est construit avec le support tcp-wrappers activé, il vérifiera si le nom d'utilisateur NUT est autorisé à se connecter depuis l'adresse du client via les fichiers /etc/hosts.allow et /etc/hosts.deny. Notez que cela ne sera fait que pour les commandes qui nécessitent d'être connectées au serveur. De plus amples détails sont décrits dans hosts_access(5).

FICHIERS

Le fichier de configuration général de upsd est upsd.conf(5).

Les fonctions administratives comme SET et INSTCMD pour les utilisateurs, et divers rôles upsmon, sont définies et contrôlées dans upsd.users(5).

Les définitions d'onduleurs se trouvent dans ups.conf(5) (partagé avec les pilotes réels).

VARIABLES ENVIRONNEMENT

NUT_DEBUG_LEVEL définit la verbosité de débogage par défaut si aucun argument -D n'a été fourni sur la ligne de commande, mais ne demande pas que le démon s'exécute en mode premier plan.

NUT_CONFPATH est le nom de chemin du répertoire qui contient upsd.conf et d'autres fichiers de configuration. Si cette variable n'est pas définie, upsd utilise une valeur par défaut intégrée, qui est souvent /usr/local/ups/etc.

NUT_STATEPATH est le nom de chemin du répertoire dans lequel upsd conserve les informations d'état. Si cette variable n'est pas définie, upsd utilise une valeur par défaut intégrée, qui est souvent /var/state/ups. La directive STATEPATH dans upsd.conf(5) remplace cette variable.

NUT_ALTPIDPATH est le nom de chemin du répertoire dans lequel upsd et les pilotes stockent les fichiers .pid. Si cette variable n'est pas définie, upsd et les pilotes utilisent soit NUT_STATEPATH s'il est défini, soit ALTPIDPATH s'il est défini, soit sinon la valeur par défaut intégrée STATEPATH.

NUT_QUIET_INIT_UPSNOTIFY=true peut être utilisé pour empêcher les démons qui peuvent notifier les frameworks de gestion de services (tels que systemd) de passer leurs étapes de cycle de vie d'émettre de telles notifications (y compris celles concernant le manque de support système pour de telles fonctionnalités modernes, une fois par exécution).

NUT_QUIET_INIT_BANNER=true peut être utilisé pour supprimer la bannière du nom et de la version de l'outil NUT. NON recommandé pour les services en raison d'un impact négatif sur le dépannage, mais peut être utile dans les profils de shell ou les scripts qui traitent les sorties des outils NUT.
