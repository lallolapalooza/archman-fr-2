NOM

urlwatch-config - Configuration du comportement de urlwatch

SYNOPSIS

urlwatch --edit-config

DESCRIPTION

La configuration globale de urlwatch contient les paramètres de base pour le comportement générique de urlwatch ainsi que pour les Rapporteurs.

AFFICHAGE

En plus de toujours signaler les changements (ce qui est le but même de urlwatch), urlwatch signale par défaut les pages nouvellement ajoutées (nouvelle) et les erreurs (erreur). Vous pouvez modifier ce comportement dans la section affichage de la configuration :

affichage:
  nouvelle: true
  erreur: true
  inchangé: false
  diff-vide: true

Si vous définissez inchangé à true, urlwatch signalera toujours toutes les pages vérifiées mais qui n'ont pas changé.

Le paramètre diff-vide contrôle ce qui se passe si une page est modifiée, mais qu'en raison, par exemple, d'un filtre_diff, la différence est réduite à une chaîne vide. Si défini à true, urlwatch signalera un changement (vide). Si défini à false, le changement ne sera pas inclus dans le rapport.

Les changements filtrés ne sont pas appliqués pour inchangé

En raison de la manière dont la sortie filtrée est stockée, inchangé rapportera toujours le contenu ancien avec les filtres au moment de la récupération, ce qui signifie que tout changement que vous apportez au filtre d'un travail ne sera pas visible dans le rapport inchangé. Lorsque la page change, le nouveau filtre sera appliqué.

Pour cette raison, inchangé ne peut pas être utilisé pour tester les filtres, vous devez utiliser l'option de ligne de commande --test-filter pour appliquer votre filtre actuel au contenu de page actuel.

RAPPORTEURS

"Rapporteurs" sont les modules qui délivrent des notifications par leur moyen respectif lorsqu'ils sont activés via le fichier de configuration.

Voir urlwatch-reporters(5) pour les options spécifiques aux rapporteurs.

En plus des options spécifiques aux rapporteurs, tous les rapporteurs prennent en charge ces options :

  • activé : [bool] Active le rapporteur. (défaut : Faux)
  • séparé : [bool] Envoie un rapport pour chaque travail plutôt qu'un rapport combiné pour tous les travaux. (défaut : Faux)

Les rapporteurs sont implémentés dans une hiérarchie, de sorte que ces paramètres de configuration courants s'appliqueront à tous les rapporteurs descendants :

html
texte
├───stdout
├───email
├───ifttt
├───webservice
│   ├───pushover
│   └───pushbullet
├───mailgun
├───telegram
├───slack
│   └───mattermost
├───discord
├───xmpp
├───prowl
└───shell
markdown
├───matrix
└───gotify

NOTE :

Définir l'option html du rapporteur email sur true provoquera son héritage de la configuration html.

Voici un exemple de configuration qui rapporte sur la sortie standard en couleur, ainsi qu'un e-mail HTML utilisant sendmail :

rapport:
  texte:
    details: true
    pied-de-page: true
    longueur-ligne: 75
  html:
    diff: unifié
    séparé: true
  email:
    activé: true
    méthode: sendmail
    sendmail:
        chemin: /usr/sbin/sendmail
    de: 'urlwatch@example.org'
    à: 'you@example.org'
    html: true
    sujet: '{count} changements : {jobs}'
  stdout:
    couleur: true
    activé: true

Toute configuration spécifique à un rapporteur doit se trouver sous la clé rapport dans la configuration.

PAR DÉFAUT DES TRAVAUX

Si vous souhaitez modifier certains paramètres pour tous vos travaux, modifiez la section job_defaults dans votre fichier de configuration :

job_defaults:
  tous:
    outil_diff: wdiff
  url:
    ignorer_erreurs_connexion: true

Le fichier de configuration ci-dessus définit tous les travaux pour utiliser wdiff comme outil de différence, et tous les travaux de type url pour ignorer les erreurs de connexion.

Les sous-clés possibles pour job_defaults sont :

  • tous : S'applique à tous vos travaux, indépendamment de leur type
  • shell : S'applique uniquement aux travaux de type shell (avec la clé commande)
  • url : S'applique uniquement aux travaux de type url (avec la clé url)
  • browser : S'applique uniquement aux travaux de type browser (avec la clé navigate)

Voir Travaux pour connaître les différents types de travaux et les clés possibles.
