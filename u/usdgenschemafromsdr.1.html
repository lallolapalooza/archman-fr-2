USDGENSCHEMAFROMSDR(1) Commandes utilisateur USDGENSCHEMAFROMSDR(1)

NOM

usdgenschemafromsdr - page de manuel pour usdgenschemafromsdr 25.11

DESCRIPTION

utilisation : usdgenschemafromsdr [-h] [--noreadme] [-v]

[schemaConfig] [schemaGenerationPath]
Ce script génère schema.usda dynamique, generatedSchema.usda et plugInfo.json. Le schema.usda est généré en analysant les sdrNodes appropriés fournis dans un fichier de configuration. En plus de fournir les types et identifiants de sdrNodes, le fichier de configuration fournit également une liste de sous-couches (subLayers) qui doivent être sous-couchées par le schema.usda auto-populé. La génération de code peut également être activée en option via la configuration json, notez que la génération de code est désactivée par défaut.
Le script prend 3 arguments :
- une configuration json, fournissant les sdrNodes via sourceType, sdrNodeIdentifiers
ou une liste explicite de chemins de fichiers d'actifs absolus (sourceAssetNodes) et une liste de sous-couches. Les chemins de fichiers d'actifs peuvent également contenir des variables d'environnement, les utilisateurs doivent donc les définir avant d'exécuter le script.
- un répertoire de destination. Notez qu'un schema.usda avec GLOBAL prim approprié fournissant un nom de bibliothèque (libraryName) dans ses données personnalisées (customData), doit être présent à cet emplacement. C'est aussi l'emplacement où generatedSchema.usda, plugInfo.json seront exportés. Dans le cas où la génération de code est explicitement activée dans la configuration, libraryPath doit également être fourni avec libraryName dans customData, sinon usdGenSchema échouera.
- un noreadme optionnel pour ignorer la génération d'un README.md fournissant une brève
explication du contenu du répertoire.
Ce script exécutera usdGenSchema sur le schema.usda auto-populé.
Si vous régénérez des schémas, il est recommandé de définir la variable d'environnement USD_DISABLE_AUTO_APPLY_API_SCHEMAS à true afin d'éviter que des schémas d'application automatique (auto-apply API schemas) précédemment générés ne soient appliqués aux bases de schémas spécifiées, ce qui pourrait entraîner la suppression de propriétés supplémentaires.
Les spécifications du schema.usda peuplées à partir des sdrNodes fournis à l'aide de UsdUtils.UpdateSchemaWithSdrNode et le métadonnées skipCodeGeneration seront définies à true, sauf indication contraire explicite dans la configuration pour ce schema.usda.
UsdUtils.UpdateSchemaWithSdrNode est responsable de :

Met à jour le schemaLayer donné avec les spécifications de prim (primSpec) et de propriétés (propertySpecs) à partir des métadonnées sdrNode.

Un contexte de rendu (renderContext) peut être fourni, qui est utilisé pour déterminer l'espace de noms du shaderId, suivant le modèle : "<renderContext>:<SdrShaderNodeContext>:shaderId". Notez que nous utilisons le contexte d'un nœud (SDR_NODE_CONTEXT_TOKENS) ici pour construire l'espace de noms du shaderId, les analyseurs de shaders doivent donc s'assurer d'utiliser les SDR_NODE_CONTEXT_TOKENS appropriés dans les définitions de nœuds.

Le paramètre overrideIdentifier est l'identifiant qui doit être utilisé lorsque l'identifiant du nœud en cours de traitement diffère de celui que Sdr découvrira à l'exécution, par exemple lorsque cette fonction définit un nœud construit à partir d'un chemin d'actif explicite. Ceci ne doit être utilisé que lorsque les clients savent que l'identifiant passé est le véritable identifiant que sdr Runtime fournira lors des requêtes avec GetShaderNodeByIdentifierAndType, etc.

Il consomme les attributs suivants (qui se manifestent comme métadonnées Sdr) en plus de nombreuses métadonnées Sdr standard spécifiées et analysées (via son plugin d'analyse).

Métadonnées au niveau du nœud :

- "schemaName" : Nom du nouveau schéma peuplé à partir du sdrNode donné
(Obligatoire)
- "schemaKind" : Spécifie le UsdSchemaKind pour le schéma en cours de
peuplement à partir du sdrNode. (Notez que cela ne prend pas en charge plusieurs schémas d'application).
- "schemaBase" : Schéma de base dont le nouveau schéma doit hériter
de. Notez que cela vaut par défaut "APISchemaBase" pour un schéma d'API ou "Typed" pour un schéma concret.
- "apiSchemasForAttrPruning" : Une liste de schémas d'API principaux qui seront composés ensemble et toute propriété de shader partagée de cette définition de prim sera supprimée du schéma résultant.
- "typedSchemaForAttrPruning" : Un schéma typé principal qui sera composé ensemble avec les apiSchemasForAttrPruning et toute propriété de shader partagée de cette définition de prim sera supprimée du schéma résultant. Si aucun typedSchemaForAttrPruning n'est fourni, seuls les apiSchemasForAttrPruning sont composés pour créer une définition de prim. Ceci ne sera utilisé que lors de la création d'un APISchema.
- "apiSchemaAutoApplyTo" : Les schémas auxquels le schéma d'API peuplé par le sdrNode
sera appliqué automatiquement.
- "apiSchemaCanOnlyApplyTo" : Si spécifié, le schéma d'API généré à partir du sdrNode ne pourra être appliqué valablement qu'à cet ensemble de schémas.
- "providesUsdShadeConnectableAPIBehavior" : Utilisé pour activer un comportement de connectivité pour un schéma d'API.
- "isUsdShadeContainer" : Utilisé uniquement lorsque providesUsdShadeConnectableAPIBehavior est défini sur true. Marque le prim connectable comme un type de conteneur UsdShade.
- "requiresUsdShadeEncapsulation" : Utilisé uniquement lorsque providesUsdShadeConnectableAPIBehavior est défini sur true. Configure les règles d'encapsulation UsdShade régissant son connectableBehavior.
- "tfTypeNameSuffix" : Nom de classe qui sera enregistré auprès du système TfType. Ceci est ajouté au nom de domaine pour l'enregistrement auprès de TfType.
- "schemaPropertyNSPrefixOverride" : Métadonnées au niveau du nœud qui peuvent contrôler le préfixe de l'espace de noms de toutes les propriétés des nœuds. Ceci peut être utile pour les nœuds non connectables qui ne devraient pas avoir de préfixe d'espace de noms d'entrées et sorties UsdShade.

Métadonnées au niveau de la propriété :

- "usdVariability" : Métadonnées au niveau de la propriété qui spécifie qu'une propriété de sdrNode spécifique doit avoir sa variabilité USD définie sur Uniform ou Varying.
- "usdSuppressProperty" : Métadonnées au niveau de la propriété qui détermine si la propriété doit être supprimée de la traduction des arguments en spécifications de propriété.
- "propertyNSPrefixOverride" : Fournit un moyen de remplacer l'espace de noms d'une propriété par rapport au défaut (inputs:/outputs:) ou par rapport aux métadonnées schemaPropertyNSPrefixOverride d'un nœud.

Traductions des métadonnées Sdr Property vers SdfPropertySpec

- Une valeur "null" pour les métadonnées Widget SdrShaderProperty se traduit par 'hidden' dans le dictionnaire de métadonnées uiHints de SdfPropertySpec.
- Les métadonnées Help de SdrShaderProperty (métadonnées Label si les métadonnées Help ne sont pas fournies) se traduisent par les chaînes de métadonnées personnalisées userDocBrief et userDoc de SdfPropertySpec.
- Les métadonnées Page de SdrShaderProperty se traduisent par 'displayGroup' dans le dictionnaire de métadonnées uiHints de SdfPropertySpec.
- Les métadonnées Label de SdrShaderProperty se traduisent par 'displayName' dans le dictionnaire de métadonnées uiHints de SdfPropertySpec.
- Les Options de SdrShaderProperty se traduisent par soit 'allowedTokens' (lorsque des étiquettes ou des valeurs sont fournies) soit 'valueLabels' (lorsque des étiquettes et des valeurs sont fournies) dans le dictionnaire de métadonnées uiHints de SdfPropertySpec. Pour la compatibilité descendante, définissez USD_POPULATE_LEGACY_ALLOWED_TOKENS pour écrire allowedTokens en plus de valueLabels pour les attributs de type chaîne et de type token qui fournissent à la fois des étiquettes et des valeurs.
- La valeur par défaut de SdrShaderProperty se traduit par la valeur par défaut de SdfPropertySpec.
- Les entrées connectables se traduisent par la connectivité InterfaceOnly de SdfPropertySpec.

arguments positionnels :

schemaConfig
Une configuration json fournissant les sdrNodes via sourceType, sdrNodeIdentifiers ou explicite

usdgenschemafromsdr - Converts UsdShadeDataReference (SDR) files into USD schema files.

NAME

usdgenschemafromsdr — Converts UsdShadeDataReference (SDR) files into USD schema files.

SYNOPSIS

usdgenschemafromsdr [ -h | --help ] [ --noreadme ] [ -v | --validate ] <config.json>

DESCRIPTION

This tool takes an SDR JSON configuration file as input, and generates USD schema files. The JSON file specifies how to discover SDR assets and how to organize the generated USD schema.

config.json
Path to the JSON configuration file. This file dictates the behavior of the script.

The configuration file is a JSON object with the following keys:

sdrNodes
A dictionary specifying how to discover and process SDR nodes.
renderContext
The render context to associate with the generated SDR nodes. This is a string value.
sourceType
A list of strings representing the source types of the SDR nodes. These are typically identifiers for different types of shading nodes (e.g., "UsdPreviewSurface").
sourceAssetNodes
A list of absolute asset file paths (sourceAssetNodes). Note that for nodes specified under sourceAssetNodes we will use the basename stripped of extension as the shaderId for nodes we create. If node paths specified in sourceAssetNodes contain any environment variables, user is required to set these prior to running the script. And also optionally providing a list of sublayers which the schema.usda will sublayer. Code generation can also be optionally enabled via the json config, note that code generation is disabled by default. [Default: ./schemaConfig.json]'. Example json config file:
{
"sdrNodes": {
"renderContext": "myRenderContext",
"sourceType": [
"sdrIdentifier1",
"sdrIdentifier2", "sdrIdentifier3"
],
"sourceAssetNodes": [
"/absolutepath/to/sdrNodeIdentifyingAsset1.extension,
"/absolutepath/to/sdrNodeIdentifyingAsset1.extension,
],
}, "sublayers": [
"usd/schema.usda",
"usdGeom/schema.usda", "usdLux/schema.usda" ],
"skipCodeGeneration": True
}
schemaGenerationPath
The target directory where the code should be generated. The script assumes a basic schema.usda is defined at this location with a GLOBAL prim configured with appropriate libraryName. [Default: .]

options:

-h, --help
show this help message and exit
--noreadme
When specified a README.md will not be created in the schemaGenerationPath explaining the source of the contents of this directory.
-v, --validate
This is passed to usdGenSchem to verify that the source files are unchanged.
