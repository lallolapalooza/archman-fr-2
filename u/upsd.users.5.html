NOM

upsd.users - Définitions des utilisateurs administratifs pour le serveur de données upsd de NUT

DESCRIPTION

Les commandes administratives telles que la définition de variables et les commandes instantanées sont puissantes, et l'accès à celles-ci doit être restreint. Ce fichier définit qui peut y accéder et ce qui est disponible.

NOTES IMPORTANTES

•Le contenu de ce fichier doit être en ASCII pur (les codes de caractères hors plage seraient ignorés avec un message d'avertissement).
•Équilibrez les permissions d'exécution de l'utilisateur pour accéder au fichier (et peut-être au répertoire qu'il contient) afin que seul upsd puisse le lire ; un accès en écriture n'est pas nécessaire. Il est courant d'utiliser chown root:nut et chmod 640 pour définir des permissions de fichier acceptables.
•Les paquets (et leurs recettes de compilation) préparent généralement un ensemble de comptes utilisateurs et de groupes pour NUT. Des compilations personnalisées avec une configuration minimale peuvent même utiliser nobody:nogroup ou similaire, ce qui est intrinsèquement non sécurisé.
•Sur les systèmes avec des préoccupations de sécurité supplémentaires, les pilotes NUT et le serveur de données devraient s'exécuter en tant que comptes utilisateurs distincts qui seraient membres d'un même groupe pour un accès partagé aux fichiers de socket Unix locaux et au répertoire qui les contient, mais de groupes différents pour l'accès aux fichiers de configuration. Cela nécessiterait que certains démons utilisent des paramètres personnalisés user, group, RUN_AS_USER et/ou RUN_AS_GROUP pour remplacer la seule valeur intégrée.
•Notez que les clients de surveillance, de journalisation, etc. sont uniquement réseau. Ils n'ont pas besoin d'accéder à ces fichiers et répertoires, et peuvent s'exécuter dans un groupe et un utilisateur complètement indépendants.
•Gardez à l'esprit la sécurité de toute copie de sauvegarde de ce fichier, par exemple les fichiers d'archive dans lesquels il pourrait se retrouver.

SECTIONS

Chaque utilisateur obtient sa propre section. Les champs de cette section définissent les paramètres associés aux privilèges de cet utilisateur. La section commence par le nom de l'utilisateur entre crochets, et se poursuit jusqu'au nom de l'utilisateur suivant entre crochets ou jusqu'à la fin du fichier (EOF). Ces utilisateurs sont indépendants de /etc/passwd ou d'autres bases de données de comptes OS.

Voici quelques exemples pour vous lancer :

[admin]
        password = monmotdepasse
        actions = set
        actions = fsd
        instcmds = all
[pfy]
        password = duh
        instcmds = test.panel.start
        instcmds = test.panel.stop
[upswired]
        password = blah
        upsmon primary
[observer]
        password = abcd
        upsmon secondary

CHAMPS

password

Définit le mot de passe pour cet utilisateur.

actions

Permet à l'utilisateur d'effectuer certaines actions avec upsd. Pour spécifier plusieurs actions, utilisez plusieurs instances du champ actions. Les actions valides sont :

SET

modifier la valeur de certaines variables dans l'UPS

FSD

définir le drapeau d'arrêt forcé dans l'UPS. Ceci est équivalent à une situation "sur batterie + batterie faible" aux fins de surveillance.

La liste des actions devrait s'allonger à l'avenir.

instcmds

Permet à un utilisateur d'initier des commandes instantanées spécifiques. Utilisez "ALL" pour accorder automatiquement toutes les commandes. Pour spécifier plusieurs commandes, utilisez plusieurs instances du champ instcmds. Pour la liste complète de ce que votre UPS prend en charge, utilisez upscmd -l.

Le fichier cmdvartab fourni avec la distribution NUT contient une liste de la plupart des noms de commandes généralement connus.

upsmon

Ajoute les actions nécessaires pour un processus upsmon, et peut être considéré comme un rôle d'une instance cliente particulière pour travailler avec cette instance de serveur de données. Ceci est défini sur primary (peut demander FSD) ou secondary (suit les situations critiques pour s'arrêter lorsque nécessaire).

N'essayez pas d'attribuer des actions à upsmon manuellement, car vous pourriez manquer quelque chose d'important. Cette méthode de désignation d'un "utilisateur upsmon" a été créée afin que les capacités internes puissent être modifiées ultérieurement sans casser les installations existantes (utilisant potentiellement des actions qui ne sont pas exposées pour une attribution directe).
