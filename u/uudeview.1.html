UUDEVIEW(1) Manuel des commandes générales UUDEVIEW(1)

NOM

UUDeview - un décodeur puissant pour fichiers binaires

SYNTAXE

uudeview [options] [@fichier] fichier(s)

DESCRIPTION

UUDeview est un décodeur intelligent pour les pièces jointes que vous avez reçues sous forme codée via le courrier électronique ou les newsgroups. Il est similaire à la commande standard uudecode(1), mais avec plus de confort et de flexibilité. UUDeview prend en charge les méthodes de codage uuencoding, xxencoding, Base64, yEncoding et BinHex, et est capable de gérer les fichiers divisés (qui ont été envoyés en plusieurs parties) ainsi que plusieurs fichiers à la fois, simplifiant ainsi grandement le processus de décodage. Habituellement, vous n'aurez pas à modifier manuellement les fichiers pour les préparer au décodage.

Après avoir lancé uudeview, il analysera tous les fichiers donnés à la recherche de données codées, les triera ainsi que leurs parties, puis vous présentera la liste des fichiers qui semblent pouvoir être décodés correctement. Vous pourrez alors choisir les fichiers individuellement pour le décodage.

OPTIONS

COMPORTEMENT

-i
Désactive l'interactivité. Après avoir analysé les fichiers et trié le tout, le programme ne vous demandera pas si un fichier doit être décodé ou non, mais décodera en lot tous les fichiers disponibles. C'est le comportement par défaut lors de la lecture depuis l'entrée standard.
-a
Option de renommage automatique. Si un fichier cible existe déjà, et que cette option est donnée, un point et une séquence numérique unique sont ajoutés au nom du fichier. Par exemple, foo.gif devient foo.gif.1 s'il est décodé une seconde fois.
+a
Une autre variante de renommage automatique. Si un fichier cible existe déjà, un trait de soulignement et une séquence numérique unique sont insérés dans le nom du fichier avant le premier point, c'est-à-dire que foo.gif devient foo_1.gif.
-o
Donne l'autorisation d'écraser les fichiers existants lors du décodage. En mode interactif, le défaut est de demander à l'utilisateur s'il faut écraser, renommer ou ignorer le fichier. Cette option a priorité sur -a. En mode non interactif (en utilisant -f), le défaut est d'écraser les fichiers sans demander.
+o
Indique qu'il n'est pas autorisé d'écraser les fichiers. Ceci est utile en mode non interactif, afin que les fichiers existants ne soient pas modifiés. Ceci a moins de priorité que -a.
-c
Nettoyage automatique. Supprime tous les fichiers d'entrée qui ont été décodés avec succès. À utiliser avec prudence ! UUDeview vérifie uniquement si des données ont été décodées à partir d'un fichier d'entrée, mais ne tient pas compte du reste du contenu de ce fichier, ni du fait qu'un fichier puisse contenir une pièce jointe incomplète.
-p chemin
Définit le chemin où les fichiers décodés doivent être écrits. Cela doit être un chemin d'accès valide, sinon vous obtiendrez des erreurs en essayant de décoder quoi que ce soit. Par défaut, c'est le répertoire de travail actuel.
-m
Ignorer les permissions du fichier. Les fichiers encodés en uuencode et xxencode ont les permissions d'origine stockées sur la ligne de début. À moins que cette option ne soit donnée, UUDeview les restaurera sans vérifier si elles sont raisonnables. Avec cette option, les permissions sont rétablies par défaut à 0666.

AJUSTEMENT

-z
Force une conformité MIME plus stricte. Normalement, le programme essaie de trouver des données codées même dans les parties de texte brut "text/plain" des messages MIME. Avec cette option, UUDeview limitera cette capacité et n'acceptera pas les messages codés apparemment incomplets (par exemple, des données apparemment encodées en uuencode sans lignes de début ou de fin). Vous pouvez renforcer davantage cette option en l'utilisant deux fois, ou en utilisant -z2. Alors, UUDeview ne vérifiera pas les sections de texte brut des messages MIME pour les données codées du tout et se comportera de manière entièrement conforme à la norme MIME. Aucune de ces options n'affecte le comportement sur les fichiers d'entrée non-MIME. Cette option mériterait un meilleur nom, mais je manque lentement de lettres d'options.
-f
Utilise le mode rapide pour l'analyse des fichiers. Le programme suppose que chaque fichier d'entrée contient au plus une partie, ce qui est généralement vrai pour les fichiers dans un répertoire de spool de news. Cette option casse le décodage des fichiers d'entrée avec plusieurs articles. De plus, certaines vérifications de cohérence sont désactivées, ce qui peut probablement présenter des fichiers erronés pour le décodage. Parfois, vous obtiendrez des messages d'erreur lors du décodage, parfois vous recevrez simplement des fichiers invalides. N'utilisez pas -f si vous ne pouvez pas vivre avec ces problèmes.
-r
Ignore les messages de réponse, c'est-à-dire tous les messages dont l'objet commence par Re:
-t
Utilise les messages texte. Habituellement, UUDeview ne présente que des données codées pour le décodage. Les messages texte ne sont affichés que s'ils ont un nom de fichier associé. Avec cette option activée, les parties texte sans nom des messages MIME et les messages non codés sont également proposés. Les messages sans nom reçoivent un nom unique sous la forme d'un nombre séquentiel à quatre chiffres.
-d
Met le programme en mode désespéré. Il vous proposera alors de décoder des fichiers incomplets. Ceci est utile si vous manquez la dernière partie d'un post en 50 parties, mais dans la plupart des cas, les fichiers décodés désespérément seront simplement corrompus et inutilisables. Le degré d'utilité d'un fichier incomplet dépend du type de fichier.
-b
Ceci change la "politique d'accolades" de UUDeview. UUDeview regarde la ligne d'objet d'un message et interprète les nombres entre parenthèses comme le numéro de partie, comme dans (3/7), qui est lu comme le troisième message d'une série de sept. Par défaut, les nombres entre parenthèses () sont préférés aux nombres entre crochets []. Vous pouvez changer cela en utilisant soit -b, soit, pour plus de clarté, -b[].
-s
Lecture "moins intelligente". Cette option désactive la détection automatique du numéro de partie à partir de la ligne d'objet. Essayez cette option si UUDeview échoue à analyser correctement la ligne d'objet et fait des erreurs en devinant les numéros de partie, ce qui entraîne un classement incorrect des parties. Avec cette option, les parties sont toujours assemblées séquentiellement (les parties doivent donc être correctement ordonnées dans le fichier d'entrée). De plus, avec cette option, le programme ne peut pas détecter que des parties sont manquantes. Note : Le numéro de partie correct trouvé dans les fichiers MIME appropriés est toujours évalué. Si cette option est donnée deux fois, l'objet lui-même est également ignoré et ne sera pas utilisé pour regrouper les parties. Utilisez-la si les messages dans lesquels les parties sont livrées ont des lignes d'objet différentes.

AUTRES OPTIONS

-q
(Silencieux) Désactive la verbosité. Normalement, le programme affiche quelques messages d'état lors de la lecture des fichiers d'entrée, ce qui peut être très utile si quelque chose tourne mal. Utilisez-la si ces messages vous dérangent. Désactive les barres de progression. Voir l'option -n.
-v
(désactive la Verbosity) Désactive les messages détaillés, c'est-à-dire que les notes ne sont pas affichées, mais cela ne supprime pas les avertissements et les erreurs. N'est pas aussi silencieux que l'option -q (Silencieux).
-n
Pas de barres de progression. Normalement, UUDeview affiche des barres ASCII qui avancent jusqu'à 100 %, mais il ne vérifie pas si votre terminal est capable de les afficher. Utilisez ce commutateur si votre terminal ne l'est pas, ou si vous trouvez les barres ennuyeuses.
+e ext
Sélectionne uniquement les fichiers avec les extensions données pour le décodage, les autres seront ignorés. +e .gif.jpg décoderait tous les fichiers gif et jpeg, mais pas les fichiers tif ou autres. La liste des extensions ne tient pas compte de la casse.
-e ext
L'inverse de ce qui précède.

Vous obtiendrez des résultats indésirables si vous essayez de mélanger les options +e et -e sur la ligne de commande.

OPTIONS D'ENTRÉE

fichier(s)
Les fichiers

Vous pouvez aussi spécifier des fichiers d'entrée sous la forme @fichier, où fichier est un fichier contenant une liste de fichiers à décoder. Ce format est utile pour les longs noms de fichiers ou si vous voulez garder votre ligne de commande propre.

Si aucun nom de fichier n'est donné, UUDeview essaiera de lire depuis l'entrée standard.

EXEMPLES

uudeview *

 Analyse et décode tous les fichiers du répertoire courant qui semblent être des données codées.

uudeview -i -a *

 Décode automatiquement tous les fichiers du répertoire courant, en renommant les fichiers existants si nécessaire.

uudeview +e .jpg -r

 Décode uniquement les fichiers JPG dans le répertoire courant, en ignorant les messages de réponse.

uudeview -p /home/user/decoded_files my_encoded_file.txt

 Décode le fichier my_encoded_file.txt et place le fichier résultant dans /home/user/decoded_files.

cat * | uudecode -p /tmp/decoded

 Pipe tous les fichiers du répertoire courant dans uudecode et place les fichiers décodés dans /tmp/decoded.

uudeview -z2 -d files*

 Mode désespéré, strictement conforme à la norme MIME, décode les fichiers commençant par "files".

VOIR AUSSI

uudecode(1), base64(1), munpack(1)

UUDEVIEW(1) - Manuel de l'utilisateur Linux

NOM

uudeview - décodeur intelligent pour fichiers uuencode, xxencode, base64 et binhex

SYNTAXE

uudeview [-h] [-V] [-v] [-q] [-z] [-p path] [-m mode] [-e file] [-o] [-d] [-f file] [-i file] [-l file] [-a] [-r file] [-t file] [@file]... [file]...

DESCRIPTION

uudeview est un programme qui décode les fichiers encodés au format uuencode, xxencode, base64 et binhex. Il est conçu pour gérer les fichiers qui sont envoyés comme pièces jointes par courrier électronique, en particulier ceux qui sont divisés en plusieurs parties, qui sont envoyés comme des messages MIME distincts ou qui sont envoyés sans respect strict des normes.

Le programme est interrogeable, c'est-à-dire qu'il vous demande ce qu'il faut faire de chaque fichier trouvé. Si vous ne connaissez pas la commande, tapez simplement ? pour obtenir de l'aide.

OPTIONS

-h
Affiche un bref résumé des options.
-V
Affiche la version du programme et quitte.
-v
Active le mode verbeux. Des messages de progression sont imprimés.
-q
Désactive le mode verbeux. En mode verbeux par défaut, le programme imprime beaucoup d'informations utiles.
-z
Mode strict de conformité RFC2045. Par défaut, uudeview tente de décoder les données même si elles ne sont pas strictement conformes aux normes MIME.
-p path
Définit le chemin où les fichiers décodés doivent être écrits. Si cette option n'est pas fournie, les fichiers sont écrits dans le répertoire courant.
-m mode
Définit le mode des fichiers créés. Le mode doit être un nombre octal valide (par exemple, 0644).
-e file
Exécute une commande. Vous pouvez entrer une commande arbitraire, en utilisant potentiellement le fichier courant comme argument. Tous les signes dollar ($) dans cette ligne de commande sont remplacés par le nom du fichier courant (pour être précis, le nom d'un fichier temporaire). Vous ne devriez pas exécuter de processus en arrière-plan en utilisant ce fichier temporaire, car les programmes pourraient être déroutés si leur fichier d'entrée disparaît soudainement.
-o
Écrase les fichiers existants sans demander.
-d
Décode tous les fichiers sans demander.
-f file
Traite le fichier spécifié comme une liste de fichiers à décoder. Chaque ligne du fichier doit contenir un nom de fichier.
-i file
Traite le fichier spécifié comme une liste de fichiers à ignorer.
-l file
Traite le fichier spécifié comme une liste de fichiers à lister.
-a
Traite tous les fichiers sans demander.
-r file
Renomme le fichier spécifié.
-t file
Traite le fichier spécifié comme une liste de fichiers à utiliser comme modèles pour renommer les fichiers décodés.
-
Lit depuis l'entrée standard. Peut être utilisé avec un seul trait d'union seul pour lire depuis l'entrée standard.
´-´
Lit depuis l'entrée standard. Vous pouvez également donner un seul trait d'union pour lire depuis l'entrée standard. N'importe quel nombre de fichiers peut être donné, mais il y a généralement une limitation de 128 options imposée par le shell. Si vous composez la liste des fichiers avec des caractères génériques, assurez-vous de ne pas fournir accidentellement des fichiers binaires au programme. Cela entraînera un comportement indéfini.
@file
Fait lire à UUDeview d'autres options depuis le fichier. Chaque ligne du fichier doit contenir exactement une option. Le fichier est effacé après que le programme a terminé. Cette fonctionnalité peut être utilisée pour spécifier un nombre illimité de fichiers à analyser. Combiné avec la puissance de find(1), des arborescences de répertoires entières (comme le répertoire de la file d'attente des nouvelles) peuvent être traitées.

Les options peuvent également être définies dans la variable d'environnement $UUDEVIEW, qui est lue avant le traitement des options sur la ligne de commande.

DECODAGE

Après que tous les fichiers d'entrée ont été analysés, il vous est demandé pour chaque fichier quoi en faire. Bien sûr, la réponse habituelle est de le décoder, mais il existe d'autres possibilités. Vous pouvez utiliser les commandes suivantes (chaque commande est une seule lettre) :

d
(D)écode le fichier et écrit le fichier décodé sur le disque, avec le nom donné.
y
(Y)es fait la même chose que (d).
x
E(x)tract décode également le fichier.
a
Décode tous les fichiers restants sans demander.
n
Ignore ce fichier sans le décoder.
b
Revient au fichier précédent.
r
Renommer. Vous pouvez choisir un nom différent pour le fichier afin de l'enregistrer sous ce nouveau nom.
p
Définit le chemin où les fichiers décodés doivent être écrits. Ce chemin peut également être défini avec l'option de ligne de commande -p.
i
Affiche des informations sur le fichier, si elles sont présentes. Si un message multipartite avait une partie zéro, elle est imprimée, sinon la première partie jusqu'aux données encodées est imprimée.
e
Exécute une commande. Vous pouvez entrer une commande arbitraire, en utilisant potentiellement le fichier courant comme argument. Tous les signes dollar '$' dans cette ligne de commande sont remplacés par le nom du fichier courant (pour être précis, le nom d'un fichier temporaire). Vous ne devriez pas exécuter de processus en arrière-plan en utilisant ce fichier temporaire, car les programmes pourraient être déroutés si leur fichier d'entrée disparaît soudainement.
l
Liste un fichier. Utilisez cette commande uniquement si vous savez que le fichier en question est un fichier texte, sinon, vous obtiendrez un tas d'ordures.
q
Quitte le programme immédiatement.
?
Imprime une brève description de toutes ces commandes.

Si vous ne tapez pas de commande et appuyez simplement sur retour à l'invite, la commande par défaut, le décodage du fichier, est utilisée.

MESSAGES A L'EXECUTION

En mode verbeux (c'est-à-dire si vous n'avez pas désactivé la verbosité avec l'option -v), des messages de progression apparaîtront. Ils sont extrêmement utiles pour suivre ce que fait le programme, et peuvent être utilisés pour comprendre pourquoi les fichiers ne peuvent pas être décodés, si vous les comprenez. Cette section explique comment les interpréter. La compréhension de cette section n'est pas essentielle pour utiliser le programme.

Tout d'abord, il y a des messages "Chargement", qui commencent par la chaîne "Chargé". Chaque ligne devrait comporter les éléments suivants :

Fichier Source
Le premier élément est le fichier source à partir duquel une partie a été chargée. Plusieurs parties peuvent être détectées dans un seul fichier.
Ligne Sujet
Le sujet complet est reproduit entre apostrophes.
Identifiant
Le programme dérive une identification unique pour ce fil de discussion à partir de la ligne sujet, pour regrouper les articles qui semblent appartenir au même fichier. Le résultat de cet algorithme est présenté entre accolades.
Nom de fichier
Si un nom de fichier a été détecté sur la ligne sujet ou dans les données (par exemple, sur une ligne begin, ou dans le cadre des informations Content-Type).
Numéro de partie
Le numéro de partie dérivé de la ligne sujet, ou, dans le cas de messages correctement formatés MIME, des informations "partie".
Début/Fin
Si un jeton "begin" ou "end" a été détecté, il est imprimé ici.
Type d'encodage
Si des données encodées ont été détectées dans cette partie, "UUdata", "Base64", "XXdata" ou "Binhex" est imprimé ici.

D'autres messages sont imprimés après la fin de l'analyse. Une seule ligne sera imprimée pour chaque groupe d'articles. Le contenu de cette ligne est mieux compris en regardant un exemple. Voici un exemple :

Trouvé 'mailfile.gz' État 16 Parties UUData début 1 2 3 4 5 fin 6 OK

Cela indique que le fichier mailfile.gz a été trouvé. Le fichier était encodé en uuencode ("UUData") et se compose de 6 parties. Le jeton "begin" a été trouvé dans la première partie, et le jeton "end" dans la sixième partie. Parce qu'il semble que tout est là, ce fichier est marqué comme "OK". L'État est un ensemble de bits, où les valeurs suivantes peuvent être combinées par OU :

1
Partie manquante
2
Pas de début
4
Pas de fin
8
Aucune donnée encodée trouvée.
16
Le fichier semble OK
32
Une erreur s'est produite lors du décodage du fichier.
64
Le fichier a été décodé avec succès.

NOTES

Comme le programme ne peut pas recevoir d'entrée de terminal lorsqu'un fichier est lu depuis l'entrée standard, l'interactivité est automatiquement désactivée dans ce cas.

UUDeview est conscient des messages MIME, mais ignore normalement la stricte conformité MIME en faveur de la recherche de données mal encodées à l'intérieur, par exemple pour réussir lorsque des parties individuelles d'un fichier uuencodé ont été envoyées avec un agent de messagerie MIME comme messages MIME. Pour cela, il soumet toutes les parties "text/plain" d'un message à la détection d'encodage. Vous pouvez utiliser l'option -z (voir ci-dessus) pour une conformité RFC2045 plus stricte.

Le scanner a tendance à ignorer les courtes données Base64 (moins de quatre lignes) en dehors des messages MIME. Certaines vérifications pour cette condition sont utilisées en mode désespéré, mais elles peuvent entraîner une mauvaise détection des données encodées, résultant en des fichiers invalides.

Les fichiers sont toujours décodés dans un fichier temporaire d'abord, puis ce fichier est copié à l'emplacement final. Ceci est pour éviter d'écraser accidentellement des fichiers existants avec des données qui s'avèrent trop tard pour être indéchiffrables. Ainsi, veillez à avoir deux fois l'espace nécessaire disponible. De plus, lors de la lecture depuis l'entrée standard, toutes les données sont déversées dans un fichier temporaire avant de commencer le processus d'analyse habituel sur ce fichier.

uudeview essaie de dériver toutes les informations nécessaires de la ligne Subject : si elle est présente. Si elle contient des déchets, ou si le programme ne parvient pas à trouver une identification unique et le numéro de partie là, uudeview pourrait toujours être capable de décoder le fichier en utilisant d'autres heuristiques, mais vous aurez alors beaucoup de chance.

Cependant, cela n'est pertinent que pour les fichiers divisés. Si tous les fichiers encodés ne consistent qu'en des parties uniques, ne vous inquiétez pas.

Si vous renommez, copiez ou liez le programme à uudecode, il peut agir comme un remplacement intelligent pour la norme, acceptant les mêmes options de ligne de commande. Cela n'a pas encore été bien testé.

BOGUES

Pour lire un fichier dont le nom commence par un trait d'union '-', préfixez-le avec un nom de chemin, par exemple './'.

Les sommes de contrôle trouvées dans les données BinHex sont ignorées.

Le programme ne peut pas gérer entièrement les messages multipartites partiels (messages multipartites de style MIME divisés sur plusieurs messages électroniques). Les parties individuelles sont reconnues et concaténées, et le message multipartite intégré est "décodé" dans un fichier texte brut, qui doit ensuite être à nouveau soumis à uudeview. Ne vous inquiétez pas, ces types de messages sont rares.

UUDeview ne peut pas déchiffrer les en-têtes RFC 1522.

NAME

uudeview - Display UUE, XXT, BINHEX, ASC files

SYNOPSIS

uudeview [OPTION]... [FILE]...

DESCRIPTION

uudeview is a program that decodes UUE, XXT, BINHEX, and ASC files. These are common file encoding formats used in early internet communications.

OPTIONS

-h, --help
Display a help message and exit.
-V, --version
Display version information and exit.
-v, --verbose
Enable verbose output.
-f, --force
Force decoding even if some checks fail.
-o, --output-dir DIR
Specify the output directory for decoded files.
-d, --delete
Delete the original encoded file after successful decoding.

DECODING

uudeview automatically detects the encoding type of the input files. It attempts to decode them into their original binary or text forms. If multiple encoded files are found in a single input (e.g., multiple parts of a split file), uudeview will try to reassemble them correctly.

RUNTIME MESSGAGES

uudeview may display messages during its operation, indicating the progress of decoding, any errors encountered, or information about the files being processed.

NOTES

This program is useful for retrieving files that were distributed using older encoding methods. Ensure that you have the necessary permissions to write to the output directory.

SEE ALSO

uuencode(1), uudecode(1)
