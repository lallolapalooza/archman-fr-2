NAME

unbound-control - utilitaire de contrôle de serveur Unbound 1.24.2 à distance.

SYNOPSIS

unbound-control [-hq] [-c fichier_config] [-s serveur] commande

DESCRIPTION

unbound-control effectue l'administration à distance du serveur DNS unbound(8). Il lit le fichier de configuration, contacte le serveur Unbound via TLS, envoie la commande et affiche le résultat.

Les options disponibles sont :

-h
Affiche la version et l'aide des options de la ligne de commande.
-c <fichier_config>
Le fichier de configuration à lire avec les paramètres. S'il n'est pas fourni, le fichier de configuration par défaut /etc/unbound/unbound.conf est utilisé.
-s <serveur[@port]>
Adresse IPv4 ou IPv6 du serveur à contacter. S'il n'est pas fourni, l'adresse est lue dans le fichier de configuration.
-q
Silencieux, si l'option est donnée, rien n'est affiché si cela fonctionne correctement.

COMMANDS

Il existe plusieurs commandes que le serveur comprend.

start
Démarre le serveur. Exécute simplement unbound(8). L'exécutable unbound est recherché dans le PATH défini dans l'environnement. Il est démarré avec le fichier de configuration spécifié via -c ou le fichier de configuration par défaut.
stop
Arrête le serveur. Le démon serveur se termine.
reload
Recharge le serveur. Cela vide le cache et relit le fichier de configuration.
reload_keep_cache
Recharge le serveur mais essaie de conserver le cache RRset et message si la (re)configuration le permet. Cela signifie que les tailles de cache et le nombre de threads ne doivent pas changer entre les rechargements.
fast_reload [+dpv]
Recharge le serveur, mais minimise le temps d'arrêt, afin que les requêtes des utilisateurs continuent d'être servies. Cela nécessite que le code soit compilé avec des threads. La configuration est chargée dans un thread et préparée, puis elle interrompt brièvement le serveur existant et met à jour les options de configuration. L'intention est que la pause n'affecte pas le service des requêtes des utilisateurs. Le cache est conservé. Les requêtes des utilisateurs en cours sont également conservées et continuent, mais avec les nouvelles options de configuration.

NOTE :

Cette commande est actuellement expérimentale.

La quantité de mémoire temporaire nécessaire lors d'un fast_reload est le double de la quantité nécessaire pour la configuration. En effet, Unbound a temporairement besoin de stocker à la fois les valeurs de configuration actuelles et les nouvelles tout en essayant de réaliser un fast_reload. Les zones chargées depuis le disque (zones d'autorité et zones RPZ) sont incluses dans ces besoins en mémoire.

Les options qui peuvent être modifiées sont : forwards, stubs, views, authority zones, RPZ zones et local zones.

Également access-control et options similaires, interface-action et options similaires et tcp-connection-limit. Il peut recharger certains changements define-tag, plus d'informations ci-dessous. D'autres options incluent insecure-lan-zones, domain-insecure, trust-anchor-file, trust-anchor, trusted-keys-file, auto-trust-anchor-file, edns-client-string, ipset, log-identity, infra-cache-numhosts, msg-cache-size, rrset-cache-size, key-cache-size, ratelimit-size, neg-cache-size, num-queries-per-thread, jostle-timeout, use-caps-for-id, unwanted-reply-threshold, tls-use-sni, outgoing-tcp-mss, ip-dscp, max-reuse-tcp-queries, tcp-reuse-timeout, tcp-auth-query-timeout, delay-close. iter-scrub-promiscuous.

Cela ne fonctionne pas avec les changements interface et outgoing-interface, ni avec le remote control, outgoing-port-permit, outgoing-port-avoid, msg-buffer-size, aucune option *-slabs et les changements de statistics-interval.

Pour dnstap, ces options peuvent être modifiées : dnstap-log-resolver-query-messages, dnstap-log-resolver-response-messages, dnstap-log-client-query-messages, dnstap-log-client-response-messages, dnstap-log-forwarder-query-messages et dnstap-log-forwarder-response-messages.

Cela ne fonctionne pas avec les options suivantes : dnstap-enable, dnstap-bidirectional, dnstap-socket-path, dnstap-ip, dnstap-tls, dnstap-tls-server-name, dnstap-tls-cert-bundle, dnstap-tls-client-key-file et dnstap-tls-client-cert-file.

Les options dnstap-send-identity, dnstap-send-version, dnstap-identity et dnstap-version peuvent être chargées lorsque +p n'est pas utilisé.

L'option +v rend la sortie verbeuse, incluant le temps nécessaire pour effectuer le rechargement. Avec +vv, elle est plus verbeuse, incluant la quantité de mémoire temporairement allouée pour effectuer le rechargement ; cette quantité de mémoire peut être importante si la configuration a un contenu volumineux. Dans la sortie du chronométrage, le temps de 'reload' est le temps pendant lequel le serveur a été mis en pause.

L'option +p fait que le rechargement ne met pas en pause les threads, ils continuent de fonctionner. Les verrous sont acquis, mais les éléments sont mis à jour séquentiellement, il est donc possible que les threads voient un état incohérent avec certaines options de l'ancienne et certaines options de la nouvelle configuration, comme les paramètres TTL du cache de l'ancienne configuration et les forwards de la nouvelle configuration. Les stubs et les forwards sont mis à jour simultanément, de sorte qu'ils sont vus de manière cohérente, soit avec des valeurs anciennes, soit avec des valeurs nouvelles ensemble. L'option rend le temps de rechargement de, par exemple, 3 microsecondes au lieu de 0,3 milliseconde pendant lequel les threads de travail sont interrompus. L'interruption est donc beaucoup plus courte, au détriment d'une certaine incohérence. Après le rechargement lui-même, chaque thread de travail est brièvement contacté pour qu'il libère les ressources, ce qui rend le temps de suppression un peu plus long, et prend du temps au thread de travail de service du contrôle à distance.

Avec l'option nopause (+p), le rechargement ne permet pas de recharger certaines options, que le rechargement rapide effectue sans l'option nopause : val-bogus-ttl, val-override-date, val-sig-skew-min, val-sig-skew-max, val-max-restart, val-nsec3-keysize-iterations, target-fetch-policy, outbound-msg-retry, max-sent-count, max-query-restarts, do-not-query-address, do-not-query-localhost, private-address, private-domain, caps-exempt, nat64-prefix, do-nat64, infra-host-ttl, infra-keep-probing, ratelimit, ip-ratelimit, ip-ratelimit-cookie, wait-limit-netblock, wait-limit-cookie-netblock, ratelimit-below-domain, ratelimit-for-domain.

L'option +d fait que le rechargement abandonne les requêtes sur lesquelles les threads de travail sont en train de travailler. C'est comme flush_requestlist. Sans elle, les requêtes sont conservées afin que les utilisateurs continuent de recevoir des réponses pour les requêtes en cours de traitement. L'abandon fait que les requêtes pendant la durée de vie du traitement des requêtes ne voient que les anciennes ou uniquement les nouvelles options de configuration.

Lorsqu'il y a des modifications apportées aux balises de configuration, à partir de l'option define-tag, alors l'option +d est implicitement activée avec un avertissement, et les requêtes sont abandonnées. Ceci afin d'arrêter les références aux anciennes informations de balises par les anciennes requêtes. Si le nombre de balises est augmenté dans la configuration nouvellement chargée, en ajoutant des balises à la fin, alors l'option +d implicite n'est pas nécessaire.

Pour les réponses IP, c'est-à-dire les actions associées aux adresses IP, et peut-être intersectées avec les informations de balise et d'action de contrôle d'accès, ces paramètres sont stockés avec une requête lorsqu'elle arrive en fonction de son adresse IP source. Le

verbosity nombre
Change la valeur de verbosité pour la journalisation. Les mêmes valeurs que la clé verbosity: dans unbound.conf(5). Ce nouveau paramètre dure jusqu'à ce que le serveur reçoive un rechargement (reprend les paramètres du fichier de configuration) ou jusqu'à la prochaine commande de contrôle de verbosité.
log_reopen
Rouvre le fichier journal, le ferme et le rouvre. Utile pour la rotation des journaux afin que le démon libère le fichier sur lequel il journalise. Si vous utilisez syslog, il tentera de fermer et rouvrir syslog (ce qui peut ne pas fonctionner s'il est chrooté).
stats
Affiche les statistiques. Réinitialise les compteurs internes à zéro, cela peut être contrôlé à l'aide de l'instruction de configuration statistics-cumulative:. Les statistiques sont affichées avec une ligne [nom]: [valeur] par ligne.
stats_noreset
Consulte les statistiques. Les affiche comme la commande stats, mais ne réinitialise pas les compteurs internes à zéro.
status
Affiche l'état du serveur. Code de sortie 3 si non démarré (la connexion au port est refusée), 1 en cas d'erreur, 0 si démarré.
local_zone nom type
Ajoute une nouvelle zone locale avec son nom et son type. Similaire à l'instruction de configuration local-zone. Si la zone existe déjà, son type est modifié pour celui donné en argument.
local_zone_remove nom
Supprime la zone locale portant le nom donné. Supprime toutes les données locales qu'elle contient. Si la zone n'existe pas, la commande réussit.
local_data RR données...
Ajoute de nouvelles données locales, le enregistrement de ressource donné. Similaire à la clé local-data:, sauf lorsqu'aucune zone couvrante n'existe. Dans ce cas, cette commande de contrôle à distance crée une zone transparente portant le même nom que cet enregistrement.
local_data_remove nom
Supprime toutes les données RR du nom local. Si le nom n'a déjà aucun élément, rien ne se passe. Souvent, cela résulte en NXDOMAIN pour le nom (dans une zone statique), mais si le nom est devenu un non-terminal vide (il reste des données dans les noms de domaine sous le nom supprimé), des réponses NOERROR nodata sont renvoyées pour ce nom.
local_zones
Ajoute des zones locales lues depuis stdin de unbound-control. Les entrées sont lues ligne par ligne, avec nom espace type sur une ligne. Pour les additions en masse.
local_zones_remove
Supprime les zones locales lues depuis stdin de unbound-control. Les entrées sont un nom par ligne. Pour les suppressions en masse.
local_datas
Ajoute des enregistrements RR de données locales lus depuis stdin de unbound-control. Les entrées sont un enregistrement RR par ligne. Pour les additions en masse.
local_datas_remove
Supprime les enregistrements RR de données locales lus depuis stdin de unbound-control. Les entrées sont un nom par ligne. Pour les suppressions en masse.
dump_cache
Le contenu du cache est affiché dans un format texte sur la sortie standard. Vous pouvez le rediriger vers un fichier pour stocker le cache dans un fichier. Non pris en charge dans les Unbound distants en fonctionnement multi-processus.
load_cache
Le contenu du cache est chargé depuis la sortie standard. Utilise le même format que dump_cache. Charger le cache avec des données anciennes ou incorrectes peut entraîner le renvoi de données anciennes ou incorrectes aux clients. Le chargement de données dans le cache de cette manière est pris en charge pour faciliter le débogage. Non pris en charge dans les Unbound distants en fonctionnement multi-processus.
cache_lookup [+t] noms
Affiche sur la sortie standard les jeux d'enregistrements et les messages qui se trouvent dans le cache. Pour chaque nom listé, le contenu à ce nom ou en dessous est affiché. Plusieurs noms séparés par des espaces peuvent être donnés, chacun est affiché. Lorsque le cache de sous-réseaux est activé, les entrées correspondantes du cache de sous-réseaux sont également affichées.

L'option +t permet les noms de domaine de premier niveau (TLD) et de racine. Avec elle, des noms comme 'com' et '.' peuvent être utilisés, mais cela demande beaucoup d'efforts pour la recherche dans le cache.

lookup nom
Affiche sur la sortie standard les serveurs de noms qui seraient utilisés pour rechercher le nom spécifié.
flush [+c] nom
Supprime le nom du cache. Supprime les types A, AAAA, NS, SOA, CNAME, DNAME, MX, PTR, SRV, NAPTR, SVCB et HTTPS. Parce que c'est rapide à faire. D'autres types d'enregistrements peuvent être supprimés en utilisant flush_type ou flush_zone.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_type [+c] nom type
Supprime les informations de nom et de type du cache.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_zone [+c] nom
Supprime toutes les informations à ce nom ou en dessous du nom du cache. Les jeux d'enregistrements RR et les entrées de clés sont supprimés afin que de nouvelles recherches soient effectuées. Cela nécessite de parcourir et d'inspecter l'intégralité du cache, et est une opération lente. Les entrées sont définies comme expirées dans l'implémentation de cette commande (ainsi, avec serve-expired activé, elles seront servies mais une pré-récupération sera planifiée pour de nouvelles informations).

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_bogus [+c]
Supprime toutes les données invalides (bogus) du cache.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_negative [+c]
Supprime toutes les données négatives du cache. Ce sont les réponses nxdomain, nodata et servfail. Supprime également les entrées de clés invalides (qui pourraient résulter d'échecs de recherche) du cache de clés dnssec, et les échecs de recherche de dernier recours de l'itérateur du cache d'enregistrements RR.

L'option +c supprime également les éléments du cache cachedb. Si cachedb est utilisé.

flush_stats
Réinitialise les statistiques à zéro.
flush_requestlist
Supprime les requêtes en cours de traitement. Arrête le traitement des requêtes sur lesquelles le serveur travaille actuellement. Le cache n'est pas affecté. Aucune réponse n'est envoyée pour ces requêtes, ce qui amènera probablement les utilisateurs à redemander plus tard. Utile pour que le serveur recommence à traiter les requêtes avec de nouveaux paramètres, tels qu'un niveau de verbosité plus élevé.
dump_requestlist
Affiche ce qui est en cours de traitement. Affiche toutes les requêtes sur lesquelles le serveur travaille actuellement. Affiche le temps pendant lequel les utilisateurs ont attendu. Pour les requêtes internes, aucun temps n'est affiché. Puis affiche l'état du module. Ceci affiche les requêtes du premier thread, et non les requêtes servies par d'autres threads.
flush_infra all|IP
Si 'all', l'ensemble du cache d'infrastructure est vidé. Si une adresse IP spécifique est fournie, l'entrée pour cette adresse est supprimée du cache. Il contient des données EDNS, de ping et de latence (lameness).
dump_infra
Affiche le contenu du cache d'infrastructure.
set_option opt: valeur
Définit l'option à la valeur donnée sans rechargement. Le cache n'est donc pas vidé. L'option doit se terminer par un ':' et un espace doit séparer l'option et la valeur. Certaines valeurs peuvent ne pas avoir d'effet si elles sont définies de cette manière, les nouvelles valeurs ne sont pas écrites dans le fichier de configuration, toutes les options ne sont pas prises en charge. Ceci est différent de l'appel set_option dans libunbound, où toutes les valeurs fonctionnent car Unbound n'a pas été initialisé.

Les valeurs qui fonctionnent sont : statistics-interval, statistics-cumulative, do-not-query-localhost, harden-short-bufsize, harden-large-queries, harden-glue, harden-dnssec-stripped, harden-below-nxdomain, harden-referral-path, prefetch, prefetch-key, log-queries, hide-identity, hide-version, identity, version, val-log-level, val-log-squelch, ignore-cd-flag, add-holddown, del-holddown, keep-missing, tcp-upstream, ssl-upstream, max-udp-size, ratelimit, ip-ratelimit, cache-max-ttl, cache-m

in-ttl, cache-max-negative-ttl.

get_option opt
Récupère la valeur de l'option. Donnez le nom de l'option sans le caractère ':' final. La valeur est affichée. Si la valeur est "", rien n'est affiché et la connexion est fermée. En cas d'erreur, 'error ...' est affiché (cela donne une erreur de syntaxe si l'option est inconnue). Pour certaines options, une liste de valeurs, une par ligne, est affichée. Les options sont celles du fichier de configuration modifiées avec set_option. Pour certaines options, un remplacement peut avoir été pris en compte qui n'apparaît pas avec cette commande, ni les résultats de commandes comme la verbosité et le contrôle des forwards. Toutes les options ne fonctionnent pas, voir list_stubs, list_forwards, list_local_zones et list_local_data pour celles qui le font.
list_stubs
Liste les zones stub utilisées. Elles sont affichées une par une dans la sortie. Cela inclut les root hints utilisés.
list_forwards
Liste les zones forward utilisées. Elles sont affichées zone par zone dans la sortie.
list_insecure
Liste les zones avec domain-insecure.
list_local_zones
Liste les zones locales utilisées. Elles sont affichées une par ligne avec leur type.
list_local_data
Liste les enregistrements RR locaux utilisés. Les enregistrements de ressources sont affichés.
insecure_add zone
Ajoute un domaine-insecure pour la zone donnée, comme l'instruction dans unbound.conf. Ajoute au Unbound en cours d'exécution sans affecter le contenu du cache (qui pourrait encore être invalide, utilisez flush_zone pour le supprimer), n'affecte pas le fichier de configuration.
insecure_remove zone
Supprime le domaine-insecure pour la zone donnée.
forward_add [+it] zone addr ...
Ajoute une nouvelle zone forward à Unbound en cours d'exécution. Avec l'option +i, ajoute également un domaine-insecure pour la zone (afin qu'elle puisse résoudre de manière non sécurisée si vous avez une ancre de confiance racine DNSSEC configurée pour d'autres noms). Les addr peuvent être des adresses IP4, IP6 ou des noms de serveurs de noms, comme la configuration forward-zone dans unbound.conf. L'option +t la configure pour utiliser TLS en amont, comme forward-tls-upstream: yes.
forward_remove [+i] zone
Supprime une zone forward d'Unbound en cours d'exécution. Le +i supprime également un domaine-insecure pour la zone.
stub_add [+ipt] zone addr ...
Ajoute une nouvelle zone stub à Unbound en cours d'exécution. Avec l'option +i, ajoute également un domaine-insecure pour la zone. Avec +p, la zone stub est définie sur prime, sinon elle est définie sur notprime. Les addr peuvent être des adresses IP4, IP6 ou des noms de serveurs de noms, comme la configuration stub-zone: dans unbound.conf. L'option +t la configure pour utiliser TLS en amont, comme stub-tls-upstream: yes.
stub_remove [+i] zone
Supprime une zone stub d'Unbound en cours d'exécution. Le +i supprime également un domaine-insecure pour la zone.
forward [off | addr ... ]
Configure le mode de transfert. Configure si le serveur doit interroger d'autres serveurs de noms en amont, s'il doit utiliser les serveurs de noms racines d'Internet, ou afficher la configuration actuelle. Vous pouvez passer les serveurs de noms après une mise à jour DHCP.

Sans arguments, la liste actuelle des adresses utilisées pour transférer toutes les requêtes est affichée. Au démarrage, cela provient de la configuration de la zone "." de type forward-zone. Ensuite, cela affiche l'état. Cela affiche 'off' lorsqu'aucun transfert n'est utilisé.

Si 'off' est passé, le transfert est désactivé et les serveurs de noms racines sont utilisés. Cela peut être utilisé pour éviter les serveurs de noms défectueux ou ne prenant pas en charge DNSSEC retournés par DHCP. Mais cela peut ne pas fonctionner dans les hôtels ou les points d'accès.

Si une ou plusieurs adresses IPv4 ou IPv6 sont fournies, elles sont alors utilisées pour transférer les requêtes. Les adresses doivent être séparées par des espaces. Avec '@port', le numéro de port peut être défini explicitement (le port par défaut est 53 (DNS)).

Par défaut, les informations du forwarder du fichier de configuration pour la racine "." sont utilisées. Le fichier de configuration n'est pas modifié, donc après un rechargement, ces modifications disparaîtront. Les autres zones de transfert du fichier de configuration ne sont pas affectées par cette commande.

ratelimit_list [+a]
Liste les domaines qui sont limités en débit. Affichés un par ligne avec le qps estimé actuel et la limite de qps de la configuration. Avec +a, il affiche tous les domaines, pas seulement les domaines limités, avec leur qps estimé. Les domaines limités renvoient une erreur pour les requêtes non mises en cache (nouvelles), mais les requêtes mises en cache fonctionnent normalement.
ip_ratelimit_list [+a]
Liste les adresses IP qui sont limitées en débit. Affichées une par ligne avec le qps estimé actuel et la limite de qps de la configuration. Avec +a, il affiche toutes les IP, pas seulement les IP limitées, avec leur qps estimé. Les IP limitées sont supprimées avant la vérification du cache.
list_auth_zones
Liste les zones d'autorisation configurées. Affichées une par ligne avec un état, indiquant si la zone est expirée et son numéro de série actuel. Les zones RPZ configurées sont incluses.
auth_zone_reload zone
Recharge la zone d'autorisation (ou zone RPZ) depuis le fichier de zone. Le fichier de zone est lu en écrasant le contenu actuel de la zone en mémoire. Cela modifie le contenu de la zone d'autorisation elle-même, pas le contenu du cache. Un tel contenu de cache existe si vous avez configuré Unbound pour valider avec for-upstream: yes et cela peut être effacé avec flush_zone zone.
auth_zone_transfer zone
Transfère la zone d'autorisation (ou zone RPZ) du maître. La séquence de sondage de zone d'autorisation est démarrée, où les maîtres sont sondés pour voir s'ils ont une zone mise à jour (avec la vérification du numéro de série SOA). Et ensuite, la zone est transférée pour une version de zone plus récente.
rpz_enable zone
Active la zone RPZ si elle avait été précédemment désactivée.
rpz_disable zone
Désactive la zone RPZ.
view_list_local_zones view
list_local_zones pour la vue donnée.
view_local_zone view name type
local_zone pour la vue donnée.
view_local_zone_remove view name
local_zone_remove pour la vue donnée.
view_list_local_data view
list_local_data pour la vue donnée.
view_local_data view RR data...
local_data pour la vue donnée.
view_local_data_remove view name
local_data_remove pour la vue donnée.
view_local_datas_remove view
Supprime une liste de local_data pour la vue donnée depuis stdin. Comme local_datas_remove.
view_local_datas view
Ajoute une liste de local_data pour la vue donnée depuis stdin. Comme local_datas.
add_cookie_secret secret
Ajoute ou remplace un secret de cookie de manière persistante. secret doit être une chaîne hexadécimale de 128 bits.

Les secrets de cookie peuvent être soit actifs, soit en attente. Les secrets de cookie actifs sont utilisés pour créer des DNS Cookies, mais la vérification d'un DNS Cookie réussit avec l'un des secrets de cookie actifs ou en attente. L'état des secrets de cookie actuels peut être affiché avec la commande print_cookie_secrets.

Lorsqu'aucun secret de cookie n'est encore configuré, le secret est ajouté comme actif. S'il existe déjà un secret de cookie actif, le secret est ajouté comme en attente ou remplace un secret en attente existant.

Pour « faire pivoter » un cookie secret utilisé dans un ensemble anycast. Le nouveau secret doit être ajouté en tant que secret staging à tous les nœuds de l'ensemble anycast. Lorsque tous les nœuds peuvent vérifier les DNS Cookies avec le nouveau secret, le nouveau secret peut être activé avec la commande activate_cookie_secret. Après que tous les nœuds aient le nouveau secret actif pendant au moins une heure, le secret précédent peut être supprimé avec la commande drop_cookie_secret.

La persistance est assurée par l'écriture dans un fichier configuré avec l'option cookie-secret-file dans la section server du fichier de configuration. Ceci est désactivé par défaut, et est une chaîne vide.

drop_cookie_secret
Supprime le secret cookie staging.
activate_cookie_secret
Rend le secret cookie staging courant actif, et le secret cookie actif courant staging.
print_cookie_secrets
Affiche les secrets cookies configurés actuels avec leur statut.

CODE DE SORTIE

Le programme unbound-control se termine avec le code de statut 1 en cas d'erreur, 0 en cas de succès.

MISE EN PLACE

La mise en place nécessite un certificat auto-signé et des clés privées pour le serveur et le client. Le script unbound-control-setup génère ces éléments dans le répertoire d'exécution par défaut, ou avec -d dans un autre répertoire. Si vous modifiez les permissions d'accès sur les fichiers de clés, vous pouvez décider qui peut utiliser unbound-control ; par défaut, le propriétaire et le groupe, mais pas tous les utilisateurs. Exécutez le script sous le même nom d'utilisateur que celui configuré dans unbound.conf ou en tant que root, afin que le démon soit autorisé à lire les fichiers, par exemple avec :

sudo -u unbound unbound-control-setup

Si vous n'avez pas configuré de nom d'utilisateur dans unbound.conf, les clés doivent avoir des permissions de lecture pour l'utilisateur sous lequel le démon est démarré. Le script préserve les clés privées présentes dans le répertoire. Après avoir exécuté le script en tant que root, activez control-enable dans unbound.conf.

Nombre de réponses qui étaient invalides (bogus). Ces réponses ont abouti à SERVFAIL pour le client car la réponse n'a pas pu être validée.
num.rrset.bogus
Le nombre d'ensembles d'enregistrements (rrsets) marqués comme invalides par le validateur. Augmenté pour chaque inspection d'RRset qui échoue.
num.valops
Le nombre d'opérations de validation effectuées par le validateur. Augmenté pour chaque opération de vérification d'RRSIG, quel que soit le résultat de la validation. La combinaison RRSIG et clé doit d'abord passer par quelques vérifications de bon sens avant qu'Unbound n'effectue la vérification, par exemple, des vérifications de longueur/protocole.
unwanted.queries
Nombre de requêtes qui ont été refusées ou abandonnées parce qu'elles ne respectaient pas les paramètres de contrôle d'accès.
unwanted.replies
Réponses qui étaient indésirables ou non sollicitées. Il pouvait s'agir de trafic aléatoire, de doublons tardifs, de réponses très tardives, ou de tentatives d'usurpation d'identité. Un faible niveau de réponses tardives et de doublons tardifs est à prévoir avec le protocole UDP. Des valeurs très élevées pourraient indiquer une menace (usurpation).
msg.cache.count
Le nombre d'éléments (réponses DNS) dans le cache de messages.
rrset.cache.count
Le nombre d'ensembles d'enregistrements (RRsets) dans le cache d'RRsets. Cela inclut les RRsets utilisés par les messages dans le cache de messages, mais aussi les informations de délégation.
infra.cache.count
Le nombre d'éléments dans le cache d'infrastructure. Ce sont des adresses IP avec leurs informations de timing et de support de protocole.
key.cache.count
Le nombre d'éléments dans le cache de clés. Ce sont des clés DNSSEC, un élément par point de délégation, et leur statut de validation.
msg.cache.max_collisions
Le nombre maximum de collisions dans la table de hachage du cache de messages. C'est le nombre de hachages qui sont identiques lors de l'insertion d'un nouvel élément dans la table de hachage. Si la valeur est très grande, comme des centaines, quelque chose ne va pas avec les performances de la table de hachage, les valeurs de hachage sont incorrectes ou malveillantes.
rrset.cache.max_collisions
Le nombre maximum de collisions dans la table de hachage du cache d'RRsets. C'est le nombre de hachages qui sont identiques lors de l'insertion d'un nouvel élément dans la table de hachage. Si la valeur est très grande, comme des centaines, quelque chose ne va pas avec les performances de la table de hachage, les valeurs de hachage sont incorrectes ou malveillantes.
dnscrypt_shared_secret.cache.count
Le nombre d'éléments dans le cache de secrets partagés. Ce sont des secrets partagés précalculés pour une paire clé publique client/clé secrète serveur donnée. Les secrets partagés sont coûteux en CPU et ce cache permet à Unbound d'éviter de recalculer le secret partagé lorsque plusieurs requêtes dnscrypt sont envoyées par le même client.
dnscrypt_nonce.cache.count
Le nombre d'éléments dans le cache de nonces client. Ce cache est utilisé pour empêcher la relecture des requêtes dnscrypt. Le nonce client doit être unique pour chaque paire clé publique client/clé secrète serveur. Ce cache devrait pouvoir héberger QPS * fenêtre de relecture clés d'intervalle pour empêcher la relecture d'une requête pendant fenêtre de relecture secondes.
num.query.authzone.up
Le nombre de requêtes répondues à partir de données de zone autoritaire, requêtes ascendantes. Ces requêtes auraient autrement été envoyées (avec le fallback activé) sur l'internet, mais sont maintenant répondues à partir de la zone autoritaire.
num.query.authzone.down
Le nombre de requêtes pour les clients descendants répondues à partir de données de zone autoritaire. Ces requêtes proviennent de clients descendants, et ont reçu une réponse des données de la zone autoritaire.
num.query.aggressive.NOERROR
Le nombre de requêtes répondues en utilisant des enregistrements NSEC en cache avec un RCODE NODATA. Ces requêtes auraient autrement été envoyées sur l'internet, mais sont maintenant répondues en utilisant des données mises en cache.
num.query.aggressive.NXDOMAIN
Le nombre de requêtes répondues en utilisant des enregistrements NSEC en cache avec un RCODE NXDOMAIN. Ces requêtes auraient autrement été envoyées sur l'internet, mais sont maintenant répondues en utilisant des données mises en cache.
num.query.subnet
Nombre de requêtes
que contenait des données EDNS client subnet.
num.query.subnet_cache
Nombre de requêtes répondues depuis le cache de sous-réseau client edns. Celles-ci sont comptées comme des échecs de cache par les compteurs principaux, mais elles atteignent le cache spécifique au sous-réseau client après avoir été traitées par le module de sous-réseau client edns.
num.query.cachedb
Nombre de requêtes répondues depuis le cache externe de cachedb. Celles-ci sont comptées comme des échecs de cache par les compteurs principaux, mais elles atteignent le cache externe de cachedb après avoir été traitées par le module cachedb.
num.rpz.action.<rpz_action>
Nombre de requêtes répondues en utilisant la politique RPZ configurée, par type d'action RPZ. Les actions possibles sont : nxdomain, nodata, passthru, drop, tcp-only, local-data, disabled, et cname-override.
