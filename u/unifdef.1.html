NOM

unifdef, unifdefall — supprimer les conditions du préprocesseur du code

SYNTAXE

unifdef [-bBcdehKkmnsStV] [-Ichemin] [-[i]Dsym[=val]] [-[i]Usym] ... [-f fichierdef] [-x {012}] [-M extarr] [-o fichierout] [fichierentree ...]

unifdefall [-Ichemin] ... fichier

DESCRIPTION

L'utilitaire unifdef traite sélectivement les directives conditionnelles de cpp(1). Il supprime d'un fichier à la fois les directives et tout texte supplémentaire qu'elles spécifient comme devant être supprimé, tout en laissant le fichier intact par ailleurs.

unifdef opère sur les lignes #if, #ifdef, #ifndef, #elif, #else et #endif, en utilisant les macros spécifiées dans les options de ligne de commande -D et -U ou dans les fichiers de définitions -f. Une directive est traitée si les spécifications de macros sont suffisantes pour fournir une valeur définie pour son expression de contrôle. Si le résultat est faux, la directive et les lignes suivantes sous son contrôle sont supprimées. Si le résultat est vrai, seule la directive est supprimée. Une directive #ifdef ou #ifndef est transmise inchangée si sa macro de contrôle n'est pas spécifiée. Toute expression de contrôle #if ou #elif ayant une valeur inconnue ou que unifdef ne peut pas analyser est transmise inchangée. Par défaut, unifdef ignore les lignes #if et #elif avec des expressions constantes ; il peut être instruit de les traiter en spécifiant l'indicateur -k sur la ligne de commande.

Il comprend un sous-ensemble couramment utilisé de la syntaxe d'expression pour les lignes #if et #elif : constantes entières, valeurs entières des macros définies sur la ligne de commande, l'opérateur defined(), les opérateurs !, ~, - (unaire), *, /, %, +, -, <, <=, >, >=, ==, !=, &, ^, |, &&, ||, et les expressions entre parenthèses. La division par zéro est traitée comme une valeur inconnue. Une forme d'évaluation « court-circuit » est utilisée pour l'opérateur && : si l'un des opérandes est définitivement faux, le résultat est faux, même si la valeur de l'autre opérande est inconnue. De même, si l'un des opérandes de || est définitivement vrai, le résultat est vrai.

Lors de l'évaluation d'une expression, unifdef n'étend pas les macros au préalable. La valeur d'une macro doit être un nombre simple, pas une expression. Une forme limitée d'indirection est autorisée, où la valeur d'une macro est le nom d'une autre.

Dans la plupart des cas, unifdef ne fait pas de distinction entre les macros de type objet (sans arguments) et les macros de type fonction (avec arguments). L'invocation d'une macro de type fonction peut apparaître dans les expressions de contrôle #if et #elif. Si la macro n'est pas explicitement définie, ou est définie avec l'indicateur -D sur la ligne de commande, ou avec #define dans un fichier de définitions -f, ses arguments sont ignorés. Si une macro est explicitement dé-définie sur la ligne de commande avec l'indicateur -U, ou avec #undef dans un fichier de définitions -f, elle ne peut pas avoir d'arguments car cela conduit à une erreur de syntaxe.

unifdef comprend juste assez de C pour savoir quand une des directives est inactive parce qu'elle est à l'intérieur d'un commentaire, ou ne peut pas être évaluée parce qu'elle est divisée par une ligne continuée par une barre oblique inverse. Il détecte les directives du préprocesseur de format inhabituel et les transmet inchangées lorsque la mise en page est trop étrange pour qu'il puisse les gérer. (Voir la section ERREURS ci-dessous.)

Un script appelé unifdefall peut être utilisé pour supprimer toutes les directives conditionnelles de cpp(1) d'un fichier. Il utilise unifdef -s et cpp -dM pour obtenir des listes de toutes les macros de contrôle et de leurs définitions (ou leur absence), puis invoque unifdef avec des arguments appropriés pour traiter le fichier.

OPTIONS

-Dsym=val
Spécifie qu'une macro est définie avec une valeur donnée.
-Dsym
Spécifie qu'une macro est définie avec la valeur 1.
-Usym
Spécifie qu'une macro est dé-définie.

Si la même macro apparaît dans plusieurs arguments, la dernière occurrence domine.

-iDsym[=val]
 
-iUsym
Les chaînes C, les commentaires et les continuations de ligne sont ignorés dans les blocs #ifdef et #ifndef contrôlés par les macros spécifiées avec ces options.
-f fichierdef
Le fichier fichierdef contient des directives de préprocesseur #define et #undef, qui ont le même effet que les arguments de ligne de commande -D et -U correspondants. Vous pouvez avoir plusieurs arguments -f et les mélanger avec des arguments -D et -U ; les options ultérieures remplacent les précédentes.

Chaque directive doit être sur une seule ligne. Les définitions de macro de type objet (sans arguments) sont définies à la valeur donnée. Les définitions de macro de type fonction (avec arguments) sont traitées comme si elles étaient définies à 1.

Attention: les littéraux de chaînes et les constantes de caractères ne sont pas analysés correctement dans les fichiers -f.

-b

-B
Compresse les lignes vides autour d'une section supprimée. Mutuellement exclusif avec l'option -b.
-c
Complémentaire, c'est-à-dire que les lignes qui auraient été supprimées ou mises en blanc sont conservées et vice versa.
-d
Active l'affichage des messages de débogage.

NAME

unifdef — remove the specified preprocessor conditionals from C source files.

SYNOPSIS

unifdef [-abBdehi] [-ccomment] [-ffile] [-kn] [-mbackext] [-ooutfile] [-xmode] [file…]

DESCRIPTION

The unifdef utility processes C source files, removing sections of code that are controlled by the specified preprocessor directives. This can be used to strip out debugging code, or code specific to a certain operating system or hardware architecture. The directives that can be stripped are:

#ifdef, #ifndef, #if, #elif, #else, and #endif

#define and #undef directives.

When a directive is removed, the associated lines are deleted from the output. If the directive is defined, the lines are passed through unchanged. The behaviour for undefined directives can be altered by the -D and -U options.

The unifdef utility is similar to cpp(1), but it does not perform any macro substitution or file inclusion itself. It only parses the conditional compilation directives.

The options are as follows:

OPTIONS

-a
Keep #ifdef and #ifndef blocks that are normally removed. This option is not compatible with the -e option.
-A sym
Keep #ifdef and #ifndef blocks controlled by sym, even if sym is not defined. This option is not compatible with the -e option.
-b
A blank line is added before each line that is deleted.
-B
A blank line is added after each line that is deleted.
-ccomment
Wrap deleted lines in comments. The comment argument is used to specify the comment delimiters. For example, -c"/* */" will wrap deleted lines in C-style comments. If comment is omitted, -c behaves like the -b option.
-Dsym
Define sym. This is equivalent to adding #define sym at the beginning of the file. This option can be repeated to define multiple symbols.
-d
Remove #define and #undef directives. By default, these directives are passed through unchanged.
-e
Ignore lines that contain preprocessor directives that span more than one line, for example, if it has a multi-line comment hanging off its right hand end. The -e flag makes it ignore the line instead.
-h
Print help.
-Ipath
Specifies to unifdefall an additional place to look for #include files. This option is ignored by unifdef for compatibility with cpp(1) and to simplify the implementation of unifdefall.
-K
Always treat the result of && and || operators as unknown if either operand is unknown, instead of short-circuiting when unknown operands can't affect the result. This option is for compatibility with older versions of unifdef.
-k
Process #if and #elif lines with constant expressions. By default, sections controlled by such lines are passed through unchanged because they typically start “#if 0” and are used as a kind of comment to sketch out future or past development. It would be rude to strip them out, just as it would be for normal comments.
-m
Modify one or more input files in place. If an input file is not modified, the original is preserved instead of being overwritten with an identical copy.
-M backext
Modify input files in place, and keep backups of the original files by appending the backext to the input filenames. A zero length backext behaves the same as the -m option.
-n
Add #line directives to the output following any deleted lines, so that errors produced when compiling the output file correspond to line numbers in the input file.
-o outfile
Write output to the file outfile instead of the standard output when processing a single file.
-s
Instead of processing an input file as usual, this option causes unifdef to produce a list of macros that are used in preprocessor directive controlling expressions.
-S
Like the -s option, but the nesting depth of each macro is also printed. This is useful for working out the number of possible combinations of interdependent defined/undefined macros.
-t
Disables parsing for C strings, comments, and line continuations, which is useful for plain text. This is a blanket version of the -iD and -iU flags.
-Usym
Undefine sym. This is equivalent to adding #undef sym at the beginning of the file. This option can be repeated to undefine multiple symbols.
-V
Print version details.
-x {012}
Set exit status mode to zero, one, or two. See the EXIT STATUS section below for details.

The unifdef utility takes its input from stdin if there are no file arguments. You must use the -m or -M options if there are multiple input files. You can specify inut from stdin or output to stdout with ‘-’.

The unifdef utility works nicely with the -Dsym option of diff(1).

EXIT STATUS

In normal usage the unifdef utility's exit status depends on the mode set using the -x option.

If the exit mode is zero (the default) then unifdef exits with status 0 if the output is an exact copy of the input, or with status 1 if the output differs.

If the exit mode is one, unifdef exits with status 1 if the output is unmodified or 0 if it differs.

If the exit mode is two, unifdef exits with status zero in both cases.

In all exit modes, unifdef exits with status 2 if there is an error.

The exit status is 0 if the -h or -V command line options are given.

DIAGNOSTICS

  • EOF dans un commentaire
  • #elif, #else ou #endif inapproprié
  • Nom de macro manquant dans #define ou #undef
  • Ligne de contrôle du préprocesseur obfusquée
  • EOF prématuré (avec le numéro de ligne du #if le plus récent non terminé)
  • Trop de niveaux d'imbrication
  • Directive de préprocesseur non reconnue
  • Littéral de caractère ou de chaîne non terminé

HISTORY

La commande unifdef est apparue dans 2.9BSD. Le support ANSI C a été ajouté dans FreeBSD 4.7.

AUTHORS

L'implémentation originale a été écrite par Dave Yost <Dave@Yost.com>. Tony Finch <dot@dotat.at> l'a réécrite pour supporter ANSI C.

BUGS

  • L'évaluation des expressions est très limitée.
  • Les constantes de caractères ne sont pas évaluées. Les littéraux de chaînes et les constantes de caractères dans les fichiers de définition -f sont ignorés plutôt que parsés comme faisant partie des jetons de remplacement d'une macro.
  • Seule la forme de base des littéraux de chaînes brutes C++ est reconnue, comme R"(string)" sans délimiteurs comme dans R"delimiter(string)delimiter".
  • Les fichiers source sont traités ligne par ligne, de sorte que les directives du préprocesseur divisées sur plus d'une ligne physique (à cause des commentaires ou des barres obliques inverses suivies d'un saut de ligne) ne peuvent pas être gérées dans tous les cas.
  • Les trigraphes ne sont pas reconnus.
  • Il n'y a pas de support pour les macros avec des définitions différentes à différents points du fichier source.
  • Les fonctionnalités de mode texte et d'ignorance ne correspondent pas au comportement de cpp(1) moderne.

Veuillez envoyer les rapports de bogues par e-mail à <dot@dotat.at>.
