UNHIDE(8) Manuel de l'administrateur système UNHIDE(8)

NOM

unhide — outil d'investigation pour trouver les processus cachés

SYNTAXE

unhide [OPTIONS] LISTE_TESTS
unhide-posix proc | sys

DESCRIPTION

unhide est un outil d'investigation conçu pour détecter les processus cachés par des rootkits, des modules du noyau Linux ou par d'autres techniques. Il détecte les processus cachés en utilisant six techniques.

OPTIONS

Les options ne sont disponibles que pour unhide-linux, pas pour unhide-posix.

-d
Effectue une double vérification dans le test par force brute afin d'éviter les faux positifs.
-f
Écrit un fichier journal (unhide-linux.log) dans le répertoire courant.
-h
Affiche l'aide.
-m
Effectue des vérifications supplémentaires. À la date du 2012-03-17, cette option n'a d'effet que pour les tests procfs, procall, checkopendir et checkchdir.
Implique -v.
-r
Utilise une version alternative de la vérification sysinfo dans les tests standards.
-V
Affiche la version et quitte.
-v
Mode verbeux, affiche les messages d'avertissement (par défaut : ne pas afficher). Cette option peut être répétée plusieurs fois.
-u
Effectue une écriture non bufferisée sur la sortie standard. Cette option peut être utile lorsque unhide est lancé par un autre processus (par exemple, il est utilisé par unhideGui).
-H
Fournit une sortie légèrement plus conviviale. Cette option ajoute des messages de fin aux tests et indique lorsqu'aucun processus caché n'est trouvé.

LISTE_TESTS

Les vérifications à effectuer consistent en un ou plusieurs des tests suivants.
Les tests standards sont l'agrégation d'un ou plusieurs tests élémentaires.

Tests standards :

La technique brute consiste à tester par force brute tous les identifiants de processus.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique proc consiste à comparer /proc avec la sortie de /bin/ps.

La technique procall combine les tests proc et procfs.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique procfs consiste à comparer les informations recueillies à partir de /bin/ps avec les informations recueillies en parcourant le procfs.
Avec l'option -m, ce test effectue des vérifications supplémentaires, voir le test checkchdir.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique quick combine les techniques proc, procfs et sys de manière rapide. Elle est environ 20 fois plus rapide mais peut donner plus de faux positifs.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique reverse consiste à vérifier que tous les threads vus par ps sont également vus dans le procfs et par les appels système. Elle vise à vérifier qu'un rootkit n'a pas tué un outil de sécurité (IDS ou autre) et fait en sorte que ps affiche un faux processus à la place.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique sys consiste à comparer les informations recueillies à partir de /bin/ps avec les informations recueillies à partir des appels système.

Tests élémentaires :

La technique checkbrute consiste à tester par force brute tous les identifiants de processus.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkchdir consiste à comparer les informations recueillies à partir de /bin/ps avec les informations recueillies en faisant un chdir() dans le procfs.
Avec l'option -m, elle vérifie également que le thread apparaît dans la liste des threads de son "processus leader".
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetaffinity consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système sched_getaffinity().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetparam consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système sched_getparam().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetpgid consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système getpgid().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetprio consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système getpriority().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkRRgetinterval consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système sched_rr_get_interval().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetsched consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système sched_getscheduler().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkgetsid consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système getsid().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkkill consiste à comparer les informations recueillies à partir de /bin/ps avec le résultat de l'appel à la fonction système kill().
Note : aucun processus n'est réellement tué par ce test.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checknoprocps consiste à comparer le résultat de l'appel à chaque fonction système. Aucune comparaison n'est effectuée avec /proc ou la sortie de ps.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkopendir consiste à comparer les informations recueillies à partir de /bin/ps avec les informations recueillies en faisant un opendir() dans le procfs.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkproc consiste à comparer /proc avec la sortie de /bin/ps.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkquick combine les techniques proc, procfs et sys de manière rapide. Elle est environ 20 fois plus rapide mais peut donner plus de faux positifs.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkreaddir consiste à comparer les informations recueillies à partir de /bin/ps avec les informations recueillies en faisant un readdir() dans /proc et /proc/pid/task.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checkreverse consiste à vérifier que tous les threads vus par ps sont également vus dans le procfs et par les appels système. Elle vise à vérifier qu'un rootkit n'a pas tué un outil de sécurité (IDS ou autre) et fait en sorte que ps affiche un faux processus à la place.
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checksysinfo consiste à comparer le nombre de processus vus par /bin/ps avec les informations obtenues par l'appel système sysinfo().
Cette technique n'est disponible qu'avec la version unhide-linux.

La technique checksysinfo2 est une version alternative du test checksysinfo. Elle peut (ou pas) mieux fonctionner sur des noyaux patchés pour RT, preempt ou latence et avec des noyaux qui n'utilisent pas le planificateur standard.
Elle est également appelée par les tests standards lorsque l'option -r est utilisée.
Cette technique n'est disponible qu'avec la version unhide-linux.

Statut de sortie:

0
si OK,
1
si un thread caché ou faux est trouvé.

EXEMPLES

Test plus rapide :
unhide quick
Test rapide :
unhide quick reverse
Test standard :

unhide(8) — unhide — Arch Linux

DESCRIPTION

unhide is a tool designed to help users detect the presence of rootkits and other maliciously installed programs on their systems. It works by performing a series of tests that can reveal the presence of hidden processes, files, and network connections.

The tool can perform various tests, including checking for hidden processes in the process list, verifying file integrity, and examining network sockets for suspicious activity.

SYNOPSIS

unhide [-h|-V] [-c|-n|-p|-a] [-o OUTPUT] [-L LOG] [-l MODULE] [-f FILE] [TEST...]

OPTIONS

-h
Display help message and exit.
-V
Display version information and exit.
-c
Check for rootkit characteristics.
-n
Check for network rootkits.
-p
Check for process rootkits.
-a
Check for all rootkit types.
-o OUTPUT
Specify output file. Default is stdout.
-L LOG
Specify log file. Default is no log file.
-l MODULE
Load a specific module.
-f FILE
Use a specific configuration file.

TEST_LIST

The following tests can be performed:

all
Run all available tests.
proc
Check for hidden processes in /proc.
sys
Check system information for anomalies.
kmod
Check loaded kernel modules.
tcp
Check for hidden TCP sockets.
udp
Check for hidden UDP sockets.
file
Check for hidden files.
dmesg
Check dmesg buffer for anomalies.
iptables
Check iptables rules.
arp
Check ARP table.
login
Check user login information.
mount
Check mounted filesystems.

EXAMPLES

Run all tests and save output to unhide.log:

unhide -a -o unhide.log all
Check for hidden processes only:

unhide -p proc
Check for hidden files and TCP sockets:

unhide file tcp
Unhide sys proc
Deeper test:
unhide -m -d sys procall brute reverse

BUGS

Report unhide bugs on the bug tracker on GitHub (https://github.com/YJesus/Unhide/issues)
With recent versions of Linux kernel (> 2.6.33), the sysinfo test may report false positives. It may be due to optimization in the scheduler, the use of cgroup or even the use of systemd. The use of the PREEMPT-RT patch amplifies the occurrence of the problem. This is currently under investigation.
