UPSCLI_GET(3) Manuel NUT UPSCLI_GET(3)

NOM

upscli_get - Récupérer des données d'un UPS

SYNTAXE

        #include <upsclient.h>
        int upscli_get(
                UPSCONN_t *ups,
                size_t numq,
                const char **query,
                size_t *numa,
                char ***answer)

DESCRIPTION

La fonction upscli_get() prend le pointeur ups vers une structure d'état UPSCONN_t, et le pointeur query vers un tableau de numq éléments de requête. Elle construit une requête formatée à partir de ces éléments et la transmet à upsd(8).

En cas de succès, la réponse sera divisée en composants distincts. Un pointeur vers ces composants sera renvoyé dans answer. Le nombre de composants de réponse utilisables sera renvoyé dans numa.

UTILISATIONS

Cette fonction implémente la commande "GET" du protocole NUT. Par conséquent, vous pouvez l'utiliser pour demander de nombreuses choses différentes au serveur.

Quelques exemples sont :

•GET NUMLOGINS <ups>
•GET UPSDESC <ups>
•GET VAR <ups> <var>
•GET TYPE <ups> <var>
•GET DESC <ups> <var>
•GET CMDDESC <ups> <cmd>

FORMATAGE DE LA REQUÊTE

Pour générer une requête pour GET NUMLOGINS su700, vous rempliriez query et numq comme suit :

        size_t numq;
        const char *query[2];
        query[0] = "NUMLOGINS";
        query[1] = "su700";
        numq = 2;

L'échappement des caractères spéciaux et la mise entre guillemets des éléments contenant des espaces sont gérés pour vous à l'intérieur de cette fonction.

FORMATAGE DE LA RÉPONSE

La réponse brute de upsd à la requête ci-dessus serait NUMLOGINS su700 1.

Comme celle-ci est divisée pour vous, les valeurs se présentent comme suit :

        size_t numa;
        numa = 3;
        answer[0] = "NUMLOGINS"
        answer[1] = "su700"
        answer[2] = "1"

Notez que la valeur que vous recherchez commence généralement à answer[numq].

VÉRIFICATION DES ERREURS

Cette fonction vérifiera votre requête par rapport à la réponse du serveur de données upsd(8).

Par exemple, si vous envoyez "VAR" "su700" "ups.status", elle s'attendra à voir ces éléments au début de la réponse.

Si les résultats de upsd ne réussissent pas ce test insensible à la casse par rapport à votre requête, cette fonction renverra une erreur. Lorsque cela se produit, upscli_upserror(3) renverra UPSCLI_ERR_PROTOCOL.

DURÉE DE VIE DU TABLEAU DE RÉPONSE

Les pointeurs contenus dans le tableau answer ne sont valides que jusqu'au prochain appel à une fonction upsclient qui les référence. Si vous avez besoin d'utiliser des données de plusieurs appels, vous devez d'abord les copier ailleurs.

Le tableau answer et ses éléments peuvent changer d'emplacement, vous ne devez donc pas vous fier aux adresses précédentes. Vous devez uniquement utiliser les adresses qui ont été renvoyées par l'appel le plus récent. Vous ne devez pas non plus essayer d'utiliser plus de numa éléments dans answer. Un tel comportement est indéfini et peut produire des données erronées ou un crash.

Le tableau sera supprimé après l'appel à upscli_disconnect(3). Toute tentative d'accès après ce point est également indéfinie.

VALEUR DE RETOUR

La fonction upscli_get() renvoie 0 en cas de succès, ou -1 si une erreur se produit.

Si upsd se déconnecte, vous devrez peut-être gérer ou ignorer SIGPIPE pour éviter que votre programme ne se termine la prochaine fois que la bibliothèque écrira sur le socket déconnecté.

Le code suivant dans votre fonction d'initialisation permettra à l'appel upscli_get() de renvoyer une erreur dans ce cas :

        #include <signal.h>
        ...
        signal (SIGPIPE, SIG_IGN);
        ...

VOIR AUSSI
