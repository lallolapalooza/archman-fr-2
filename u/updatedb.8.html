updatedb(8) Manuel du gestionnaire système updatedb(8)

NOM

updatedb - met à jour une base de données pour plocate

SYNTAXE

updatedb [OPTION]...

DESCRIPTION

updatedb crée ou met à jour une base de données utilisée par locate(1). Si la base de données existe déjà, ses données sont réutilisées pour éviter de relire des répertoires qui n'ont pas changé.

updatedb est généralement exécuté quotidiennement à partir d'un systemd.timer(8) pour mettre à jour la base de données par défaut.

STATUT DE SORTIE

updatedb retourne avec le statut de sortie 0 en cas de succès, 1 en cas d'erreur.

OPTIONS

Les variables PRUNE_BIND_MOUNTS, PRUNEFS, PRUNENAMES et PRUNEPATHS, qui sont modifiées par certaines des options, sont documentées en détail dans updatedb.conf(5).

-f, --add-prunefs FS
Ajoute des entrées dans la liste séparée par des espaces blancs FS à PRUNEFS.
-n, --add-prunenames NOMS
Ajoute des entrées dans la liste séparée par des espaces blancs NOMS à PRUNENAMES.
-e, --add-prunepaths CHEMINS
Ajoute des entrées dans la liste séparée par des espaces blancs CHEMINS à PRUNEPATHS.
--add-single-prunepath CHEMIN
Ajoute CHEMIN à PRUNEPATHS. Notez que c'est actuellement la seule façon d'ajouter un chemin contenant un espace.
-U, --database-root CHEMIN
Stocke uniquement les résultats de l'analyse du sous-arbre du système de fichiers raciné à CHEMIN dans la base de données générée. Le système de fichiers entier est analysé par défaut.

locate(1) affiche les entrées sous forme de noms de chemin absolus qui ne contiennent pas de liens symboliques, quelle que soit la forme de CHEMIN.

--debug-pruning
Écrit les informations de débogage sur les décisions d'élagage dans la sortie d'erreur standard.
-h, --help
Écrit un résumé des options disponibles sur la sortie standard et quitte avec succès.
-o, --output FICHIER
Écrit la base de données dans FICHIER au lieu d'utiliser la base de données par défaut.
--prune-bind-mounts INDICATEUR
Définit PRUNE_BIND_MOUNTS à INDICATEUR, en remplaçant le fichier de configuration.
--prunefs FS
Définit PRUNEFS à FS, en remplaçant le fichier de configuration.
--prunenames NOMS
Définit PRUNENAMES à NOMS, en remplaçant le fichier de configuration.
--prunepaths CHEMINS
Définit PRUNEPATHS à CHEMINS, en remplaçant le fichier de configuration.
-l, --require-visibility INDICATEUR
Définit l'indicateur « exiger la visibilité du fichier avant de le signaler » dans la base de données générée à INDICATEUR.

Si INDICATEUR est 0 ou no, ou si le fichier de base de données est lisible par les « autres » ou n'appartient pas à locate, locate(1) affiche les entrées de la base de données même si l'utilisateur exécutant locate(1) n'aurait pas pu lire le répertoire nécessaire pour trouver le fichier décrit par l'entrée de la base de données.

Si INDICATEUR est 1 ou yes (par défaut), locate(1) vérifie les permissions des répertoires parents de chaque entrée avant de la signaler à l'utilisateur appelant. Pour que l'existence du fichier soit réellement cachée aux autres utilisateurs, le groupe de la base de données est défini sur locate et les permissions de la base de données interdisent la lecture de la base de données par les utilisateurs par d'autres moyens que locate(1), qui est défini comme set-gid locate.

Notez que l'indicateur de visibilité n'est vérifié que si la base de données appartient à locate et n'est pas lisible par les « autres ».

-v, --verbose
Écrit les noms de chemin des fichiers sur la sortie standard, dès qu'ils sont trouvés.
-V, --version
Écrit des informations sur la version et la licence de locate sur la sortie standard et quitte avec succès.

EXEMPLES

Pour créer une base de données plocate privée en tant qu'utilisateur autre que root, exécutez

updatedb -l 0 -o fichier_db -U repertoire_source
Notez que tous les utilisateurs qui peuvent lire fichier_db peuvent obtenir la liste complète des fichiers dans le sous-répertoire de repertoire_source.

FICHIERS

/etc/updatedb.conf
Un fichier de configuration. Voir updatedb.conf(5). Utilise exactement le même format que celui utilisé par updatedb de mlocate(1), donc ils peuvent être partagés.
/var/lib/plocate/plocate.db
La base de données mise à jour par défaut.

SÉCURITÉ

Les bases de données construites avec --require-visibility no permettent aux utilisateurs de trouver les noms de fichiers et de répertoires d'autres utilisateurs, ce qu'ils ne pourraient pas faire autrement.
