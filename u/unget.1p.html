UNGET(1P) Manuel du programmeur POSIX UNGET(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

unget — annuler un get précédent d'un fichier SCCS (DÉVELOPPEMENT)

SYNTAXE

unget [-ns] [-r SID] fichier...

DESCRIPTION

L'utilitaire unget inverse l'effet d'un get -e effectué avant la création du nouveau delta prévu.

OPTIONS

L'utilitaire unget doit être conforme aux directives de syntaxe des utilitaires du volume Définitions de base de POSIX.1-2017, Section 12.2.

Les options suivantes doivent être prises en charge :

-r SID
Identifie de manière unique quel delta n'est plus prévu. (Ceci aurait été spécifié par get comme le nouveau delta.) L'utilisation de cette option n'est nécessaire que si deux commandes get ou plus, en attente d'édition sur le même fichier SCCS, ont été effectuées par la même personne (nom de connexion).
-s
Supprime l'écriture du SID du delta prévu sur la sortie standard.
-n
Conserve le fichier qui a été obtenu par get, qui serait normalement supprimé du répertoire courant.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier
Un chemin d'accès à un fichier SCCS existant ou à un répertoire. Si fichier est un répertoire, l'utilitaire unget se comportera comme si chaque fichier du répertoire était spécifié comme un fichier nommé, à l'exception des fichiers non-SCCS (le dernier composant du chemin ne commence pas par s.) et des fichiers illisibles qui seront ignorés silencieusement.

Si exactement un opérande fichier apparaît, et qu'il s'agit de '-', l'entrée standard sera lue ; chaque ligne de l'entrée standard sera considérée comme le nom d'un fichier SCCS à traiter. Les fichiers non-SCCS et les fichiers illisibles seront ignorés silencieusement.

STDIN

L'entrée standard sera un fichier texte utilisé uniquement lorsque l'opérande fichier est spécifié comme '-'. Chaque ligne du fichier texte sera interprétée comme un chemin d'accès SCCS.

FICHIERS D'ENTRÉE

Tous les fichiers SCCS traités seront des fichiers de format non spécifié.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de unget :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard consistera en une ligne pour chaque fichier, au format suivant :

"%s\n", <SID retiré du fichier>

S'il y a plus d'un fichier nommé ou si un répertoire ou l'entrée standard est nommé, chaque chemin sera écrit avant chacune des lignes précédentes :

"\n%s:\n", <chemin>

STDERR

La sortie d'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Tous les fichiers SCCS mis à jour seront des fichiers de format non spécifié. Pendant le traitement d'un fichier, un fichier de verrouillage z-file, tel que décrit dans get, et un fichier q-file (une copie de travail du p-file), peuvent être créés et supprimés. Le p-file et le g-file, tels que décrits dans get, seront supprimés.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.
