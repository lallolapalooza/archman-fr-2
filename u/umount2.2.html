umount(2) Manuel des appels système umount(2)

NOM

umount, umount2 - démonter un système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mount.h>
int umount(const char *cible);
int umount2(const char *cible, int drapeaux);

DESCRIPTION

umount() et umount2() suppriment l'attachement du système de fichiers (le plus haut dans la pile) monté sur cible.

Un privilège approprié (sous Linux : la capacité CAP_SYS_ADMIN) est nécessaire pour démonter les systèmes de fichiers.

Linux 2.1.116 a ajouté l'appel système umount2(), qui, comme umount(), démonte une cible, mais autorise des drapeaux supplémentaires contrôlant le comportement de l'opération :

MNT_FORCE (depuis Linux 2.1.116)
Demande au système de fichiers d'interrompre les requêtes en attente avant de tenter le démontage. Cela peut permettre au démontage de se terminer sans attendre un serveur inaccessible, mais peut entraîner une perte de données. Si, après l'interruption des requêtes, des processus ont encore des références actives au système de fichiers, le démontage échouera quand même. Depuis Linux 4.12, MNT_FORCE n'est pris en charge que sur les systèmes de fichiers suivants : 9p (depuis Linux 2.6.16), ceph (depuis Linux 2.6.34), cifs (depuis Linux 2.6.12), fuse (depuis Linux 2.6.16), lustre (depuis Linux 3.11) et NFS (depuis Linux 2.1.116).
MNT_DETACH (depuis Linux 2.4.11)
Effectue un démontage "paresseux" : rend le montage indisponible pour de nouvelles accès, déconnecte immédiatement le système de fichiers et tous les systèmes de fichiers montés en dessous les uns des autres et de la table des montages, et effectue réellement le démontage lorsque le montage cesse d'être utilisé.
MNT_EXPIRE (depuis Linux 2.6.8)
Marque le montage comme expiré. Si un montage n'est pas actuellement utilisé, un premier appel à umount2() avec ce drapeau échoue avec l'erreur EAGAIN, mais marque le montage comme expiré. Le montage reste expiré tant qu'il n'est pas accédé par un processus. Un deuxième appel umount2() spécifiant MNT_EXPIRE démonte un montage expiré. Ce drapeau ne peut pas être spécifié avec MNT_FORCE ou MNT_DETACH.
UMOUNT_NOFOLLOW (depuis Linux 2.6.34)
Ne pas suivre le lien symbolique cible s'il s'agit d'un lien symbolique. Ce drapeau permet d'éviter des problèmes de sécurité dans les programmes définis avec le bit setuid en root qui autorisent les utilisateurs non privilégiés à démonter des systèmes de fichiers.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

Les valeurs d'erreur ci-dessous résultent d'erreurs indépendantes du type de système de fichiers. Chaque type de système de fichiers peut avoir ses propres erreurs spéciales et son propre comportement spécial. Voir le code source du noyau Linux pour plus de détails.

EAGAIN
Un appel à umount2() spécifiant MNT_EXPIRE a marqué avec succès un système de fichiers non utilisé comme expiré.
EBUSY
cible n'a pas pu être démonté car il est utilisé.
EFAULT
cible pointe en dehors de l'espace d'adressage utilisateur.
EINVAL
cible n'est pas un point de montage.
EINVAL
cible est verrouillé ; voir mount_namespaces(7).
EINVAL
umount2() a été appelé avec MNT_EXPIRE et soit MNT_DETACH, soit MNT_FORCE.
EINVAL (depuis Linux 2.6.34)
umount2() a été appelé avec une valeur de drapeau invalide dans drapeaux.
ENAMETOOLONG
Un nom de chemin était plus long que MAXPATHLEN.
ENOENT
Un nom de chemin était vide ou contenait un composant inexistant.
ENOMEM
Le noyau n'a pas pu allouer une page libre pour copier des noms de fichiers ou des données.
EPERM
L'appelant n'a pas les privilèges requis.

NORMES

Linux.

HISTORIQUE

MNT_DETACH et MNT_EXPIRE sont disponibles depuis glibc 2.11.

La fonction umount() originale était appelée comme umount(périphérique) et renvoyait ENOTBLK lorsqu'elle était appelée avec autre chose qu'un périphérique bloc. Dans Linux 0.98p4, un appel umount(dir) a été ajouté, pour prendre en charge les périphériques anonymes. Dans Linux 2.3.99-pre7, l'appel umount(périphérique) a été supprimé, ne laissant que umount(dir) (car les périphériques peuvent maintenant être montés à plusieurs endroits, spécifier le périphérique ne suffit plus).

NOTES

umount() et montages partagés

Les montages partagés provoquent la transmission de toute activité de montage, y compris les opérations umount(), à chaque montage partagé du groupe pair et à chaque montage esclave de ce groupe pair. Cela signifie que le umount() de n'importe quel pair dans un ensemble de montages partagés provoquera le démontage de tous ses pairs et le démontage de tous leurs esclaves.

Cette propagation de l'activité de démontage peut être particulièrement surprenante sur les systèmes où chaque montage est partagé par défaut. Sur de tels systèmes, le montage récursif de l'arborescence racine du système de fichiers sur un sous-répertoire, puis plus tard le démontage de ce sous-répertoire avec MNT_DETACH, entraînera le démontage paresseux de tous les montages dans l'espace de noms de montage.

Pour s'assurer que umount() ne se propage pas de cette manière, le montage peut être remonté en utilisant un appel mount(2) avec un argument drapeaux_montage qui inclut à la fois MS_REC et MS_PRIVATE avant que umount() ne soit appelé.

VOIR AUSSI

mount(2), mount_namespaces(7), path_resolution(7), mount(8), umount(8)

umount2(2) — DÉMONTAGE DE SYSTÈMES DE FICHIERS

BIBLIOTHÈQUE

Support des bibliothèques C (libc), utilise directement l’appel système.

SYNTAXE

#include <sys/mount.h>

int umount2(const char *target, int flags);

DESCRIPTION

L’appel système umount2 démonte un système de fichiers situé au point de montage target.

Le paramètre target est un pointeur vers une chaîne de caractères qui spécifie le point de montage du système de fichiers à démonter.

Le paramètre flags spécifie les options de démontage. Les valeurs possibles sont zéro ou une combinaison des drapeaux suivants :

MNT_FORCE
Forcer le démontage. Cela est utile pour les systèmes de fichiers distants où le serveur ne répond pas.
MNT_DETACH
Démonter le système de fichiers de manière asynchrone. L’opération de démontage ne sera terminée que lorsque le système de fichiers n’est plus utilisé. Cela permet d’utiliser des opérations coûteuses à l’avance, mais de les terminer plus tard.
MNT_EXPIRE
Marquer le système de fichiers comme expiré. Cela est utile pour les systèmes de fichiers virtuels comme procfs qui peuvent être réutilisés après démontage.

Il est généralement recommandé de ne pas utiliser MNT_FORCE, car cela peut entraîner une perte de données.

VALEUR RENVOYÉE

En cas de succès, umount2 renvoie 0. En cas d’erreur, il renvoie -1 et errno est défini en conséquence.

ERREURS

Les erreurs suivantes peuvent être renvoyées :

EBUSY
Le système de fichiers est occupé (par exemple, un processus utilise un fichier sur le système de fichiers).
EINVAL
target n’est pas un point de montage valide ou les drapeaux spécifiés ne sont pas valides.
EPERM
L’appelant n’a pas les privilèges nécessaires pour démonter le système de fichiers (nécessite CAP_SYS_ADMIN).
ENOENT
Le système de fichiers spécifié par target n’existe pas.

NORMES

L’appel système umount2 est spécifique à Linux.

HISTORIQUE

Le système d’exploitation Linux. Les premières versions du noyau avaient une fonction umount, qui a été remplacée par umount2 pour permettre l’ajout d’options.

NOTES

La fonction umount de la bibliothèque C est généralement un wrapper autour de l’appel système umount2. La fonction umount ne prend qu’un seul argument, le point de montage, et utilise implicitement les drapeaux 0.

Il est important de noter que démonter un système de fichiers peut entraîner une perte de données si des données n’ont pas encore été écrites sur le support de stockage. Assurez-vous que toutes les opérations d’écriture sont terminées avant de démonter un système de fichiers.

VOIR AUSSI

mount(2), umount(8)
