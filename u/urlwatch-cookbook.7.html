NOM

urlwatch-cookbook - Sujets avancés et recettes pour urlwatch

AJOUT D'URLS DEPUIS LA LIGNE DE COMMANDE

Ajout rapide de nouvelles URLS à la liste des tâches depuis la ligne de commande :

urlwatch --add url=http://example.org,name=Example

UTILISATION DES DIFFÉRENCES PAR MOTS

Vous pouvez également spécifier un outil externe de type diff (un outil qui prend deux noms de fichiers (ancien, nouveau) en paramètre et renvoie la différence des fichiers sur sa sortie standard), par exemple pour utiliser wdiff(1) pour obtenir des différences par mots au lieu de différences par lignes, ou pandiff https://github.com/davidar/pandiff pour obtenir des différences en markdown :

url: https://example.com/
diff_tool: wdiff

Notez que diff_tool spécifie un outil en ligne de commande externe, donc cet outil doit être installé séparément (par ex. apt install wdiff sur Debian ou brew install wdiff sur macOS). La coloration syntaxique est prise en charge pour la sortie de type wdiff, mais potentiellement pas pour d'autres outils de comparaison.

IGNORER LES CHANGEMENTS D'ESPACES BLANCS

Si vous souhaitez ignorer les changements d'espaces blancs afin de ne pas recevoir de notifications pour des différences triviales, vous pouvez utiliser diff_tool pour cela. Par exemple :

diff_tool: "diff --ignore-all-space --unified"

Lorsque vous utilisez un autre outil externe de type diff, assurez-vous qu'il renvoie le format de sortie unifié pour conserver la coloration syntaxique.

AFFICHER UNIQUEMENT LES LIGNES AJOUTÉES OU SUPPRIMÉES

La fonctionnalité diff_filter peut être utilisée pour filtrer le texte de sortie de la comparaison avec les mêmes outils (voir Filtres) que ceux utilisés pour filtrer les pages web.

Afin de n'afficher que les lignes de comparaison avec des lignes ajoutées, utilisez :

url: http://example.com/things-get-added.html
diff_filter:
  - grep: '^[@+]'

Ceci ne conservera que les lignes de comparaison commençant par @ ou +. De même, pour ne conserver que les lignes supprimées :

url: http://example.com/things-get-removed.html
diff_filter:
  - grep: '^[@-]'

Un filtrage de comparaison plus sophistiqué est possible en combinant les filtres existants, en écrivant un nouveau filtre ou en utilisant shellpipe pour déléguer le filtrage/traitement de la sortie de comparaison à un outil externe.

Lisez la section suivante si vous souhaitez désactiver les notifications vides.

DÉSACTIVER LES NOTIFICATIONS VIDES

En extension de l'exemple précédent, disons que vous souhaitez uniquement être notifié de toutes les lignes ajoutées, mais ne recevoir aucune notification si des lignes sont supprimées.

Une comparaison ressemble généralement à ceci :

--- @       Ven, 04 Mar 2022 19:58:14 +0100
+++ @       Ven, 04 Mar 2022 19:58:22 +0100
@@ -1,3 +1,3 @@
 someline
-someotherlines
+someotherline
 anotherline

Nous voulons filtrer uniquement les lignes commençant par « + », mais à cause des en-têtes, nous voulons également filtrer les lignes commençant par « +++ », ce qui peut être réalisé comme suit :

url: http://example.com/only-added.html
diff_filter:
  - grep: '^[+]'      # Inclure toutes les lignes commençant par « + »
  - grepi: '^[+]{3}'  # Exclure la ligne commençant par « +++ »

Cela gère maintenant toutes les lignes de comparaison, mais comme urlwatch signale des pages « modifiées » même lorsque diff_filter renvoie une chaîne vide (ce qui peut être utile dans certains cas), vous devez explicitement désactiver cela en utilisant urlwatch --edit-config et en réglant l'option empty-diff sur false dans la catégorie display :

display:
  empty-diff: false

TRANSMETTRE LA SORTIE DE COMPARAISON À UN SCRIPT PERSONNALISÉ

Dans certaines situations, il peut être utile d'exécuter un script avec la comparaison comme entrée lorsque des changements sont détectés (par exemple, pour démarrer une mise à jour ou traiter quelque chose). Cela peut être fait en combinant diff_filter avec le filtre shellpipe, qui peut être n'importe quel script personnalisé.

La sortie du script personnalisé sera alors le résultat de la comparaison tel que rapporté par urlwatch, donc s'il produit un statut, la notification CHANGED que urlwatch génère contiendra la sortie du script personnalisé, pas la comparaison d'origine. Cela peut même avoir un filtre « normal » attaché pour ne surveiller que les liens (la partie css: a des définitions de filtre) :

url: http://example.org/downloadlist.html
filter:
  - css: a
diff_filter:
  - shellpipe: /usr/local/bin/process_new_links.sh

COMPARAISON VISUELLE DES PAGES WEB

Pour comparer visuellement le contenu des pages web, Nicolai a écrit pyvisualcompare https://github.com/nspo/pyvisualcompare comme interface (avec GUI) à urlwatch. L'outil peut être utilisé pour sélectionner une région d'une page web. Il génère ensuite une configuration pour urlwatch afin d'exécuter pyvisualcompare et de générer un hachage pour le contenu de l'écran.

IGNORER LES ERREURS DE CONNEXION

Dans certains cas, il peut être utile d'ignorer les erreurs de réseau (temporaires) pour éviter l'envoi de notifications. Bien qu'il existe une option de configuration display.error (par défaut à true) pour contrôler globalement le signalement des erreurs, pour ignorer les erreurs réseau pour des tâches spécifiques uniquement, vous pouvez utiliser la clé ignore_connection_errors dans le fichier de configuration de la liste des tâches :

url: https://example.com/
ignore_connection_errors: true

De même, vous pourriez vouloir ignorer certaines erreurs HTTP (temporaires) côté serveur :

url: https://example.com/
ignore_http_error_codes: 408, 429, 500, 502, 503, 504

ou ignorer toutes les erreurs HTTP si vous le souhaitez :

url: https://example.com/
ignore_http_error_codes: 4xx, 5xx

Vous pouvez également ignorer les lectures incomplètes :

url: "https://example.com/"
ignore_incomplete_reads: true

SUBSTITUER LE GROUPAGE DE CONTENU

Pour les pages web avec des en-têtes HTTP mal configurés ou des encodages rares, il peut être utile de spécifier explicitement un encodage parmi les Encodages standard de Python https://docs.python.org/3/library/codecs.html#standard-encodings.

url: https://example.com/
encoding: utf-8

MODIFIER LE DÉLAI PAR DÉFAUT

Par défaut, les tâches url expirent après 60 secondes. Si vous souhaitez une période de délai différente, utilisez la clé timeout pour la spécifier en nombre de secondes, ou réglez-la sur 0 pour ne jamais expirer.

url: https://example.com/
timeout: 300

FOURNIR DES DONNÉES DE COOKIES

Il est possible d'ajouter des cookies aux requêtes HTTP pour les pages qui en ont besoin, la syntaxe YAML pour cela est :

url: http://example.com/
cookies:
    Key: ValueForKey
    OtherKey: OtherValue

COMPARER AVEC PLUSIEURS DERNIERS INSTANTANÉS

Si une page Web change fréquemment entre plusieurs états stables connus, il peut être souhaitable que les changements ne soient signalés que si la page Web change pour un nouvel état inconnu. Vous pouvez utiliser compared_versions pour cela.

url: https://example.com/
compared_versions: 3

Dans cet exemple, les changements ne sont signalés que si la page Web devient différente des trois derniers états distincts. Les différences sont affichées par rapport à la correspondance la plus proche.

RECEVOIR UN RAPPORT CHAQUE FOIS QUE URLWATCH S'EXÉCUTE

Si vous surveillez des pages qui changent rarement, mais que vous souhaitez tout de même être informé quotidiennement si urlwatch fonctionne toujours, vous pouvez surveiller la sortie de la commande date, par exemple :

name: "urlwatch watchdog"
command: "date"

Étant donné que la sortie de date change chaque seconde, ce travail devrait produire un rapport chaque fois que urlwatch est exécuté.

UTILISER REDIS COMME BACKEND DE MISE EN CACHE

Si vous souhaitez utiliser Redis comme backend de mise en cache au lieu du fichier SQLite3 par défaut :

urlwatch --cache=redis://localhost:6379/

Il n'y a pas de chemin de migration depuis le format SQLite3, le cache sera vide la première fois que Redis sera utilisé.

SURVEILLER LES CHANGEMENTS SUR LES PAGES .ONION (TOR)

Comme les pages du Réseau Tor https://www.torproject.org ne sont pas accessibles via le DNS public et TCP, vous devez soit configurer un client Tor comme proxy HTTP/HTTPS, soit utiliser l'outil torify(1) du package tor (apt install tor sur Debian, brew install tor sur macOS). La configuration de Tor est hors de portée de ce document. Sur une installation Tor correctement configurée, on peut simplement préfixer la commande urlwatch avec le wrapper torify pour accéder aux pages .onion :

torify urlwatch

SURVEILLER LES ÉVÉNEMENTS DE PAGE FACEBOOK

Si vous souhaitez être informé des nouveaux événements sur une page publique Facebook, vous pouvez utiliser le modèle de travail suivant, remplacez PAGE par le nom de la page (trouvable en naviguant vers la page des événements dans votre navigateur) :

url: http://m.facebook.com/PAGE/pages/permalink/?view_type=tab_events
filter:
  - css:
      selector: div#objects_container
      exclude: 'div.x, #m_more_friends_who_like_this, img'
  - re.sub:
      pattern: '(/events/\d*)[^"]*'
      repl: '\1'
  - html2text: pyhtml2text

DÉFINIR LA LARGEUR DU CONTENU POUR HTML2TEXT (MÉTHODE LYNX)

Lors de l'utilisation de la méthode lynx dans le filtre html2text, elle utilise une largeur par défaut qui provoquera l'insertion de sauts de ligne supplémentaires.

Pour définir la largeur de sortie de lynx à 400 caractères, utilisez cette configuration de filtre :

url: http://example.com/longlines.html
filter:
  - html2text:
      method: lynx
      width: 400

CONFIGURER COMBIEN DE TEMPS LES TRAVAUX DE NAVIGATION ATTENDENT LE CHARGEMENT DES PAGES

Pour les travaux de navigation, vous pouvez configurer le temps pendant lequel le navigateur sans interface graphique attendra avant qu'une page ne soit considérée comme chargée en utilisant l'option wait_until.

Elle peut prendre l'une des quatre valeurs (voir la documentation de wait_until https://playwright.dev/python/docs/api/class-page#page-goto-option-wait-until de Playwright) :

  • load - considérer l'opération comme terminée lorsque l'événement load est déclenché
  • domcontentloaded - considérer l'opération comme terminée lorsque l'événement DOMContentLoaded est déclenché
  • networkidle - déconseillé considérer l'opération comme terminée lorsqu'il n'y a aucune connexion réseau pendant au moins 500 ms. N'utilisez pas cette méthode pour les tests, appuyez-vous plutôt sur des assertions Web pour évaluer la préparation.
  • commit - considérer l'opération comme terminée lorsque la réponse réseau est reçue et que le document a commencé à charger

TRAITER LES NOUVEAUX TRAVAUX COMME MODIFIÉS

Dans certains cas (par exemple, lorsque le diff_tool ou le diff_filter exécute une commande externe comme effet secondaire qui devrait également s'exécuter pour l'état initial de la page), vous pouvez définir treat_new_as_changed sur true, ce qui fera que le travail sera signalé comme CHANGED au lieu de NEW la première fois qu'il sera récupéré (et la différence sera également signalée).

url: http://example.com/initialpage.html
treat_new_as_changed: true

Cette option modifiera également le comportement de --test-diff-filter et permettra de tester le filtre de différence si une seule version de la page a été récupérée.

SURVEILLER LA MÊME URL DANS PLUSIEURS TRAVAUX

Étant donné que urlwatch utilise la clé url/navigate (pour les travaux URL/Navigateur) et/ou la clé command (pour les travaux Shell) comme identifiant unique, chaque URL ne peut apparaître que dans un seul travail. Si vous souhaitez surveiller la même URL plusieurs fois, vous pouvez ajouter #1, #2, ... (ou tout ce qui les rend uniques) aux URLs, comme ceci :

name: "Recherche de la Chose A"
url: http://example.com/#1
filter:
  - grep: "Chose A"
---
name: "Recherche de la Chose B"
url: http://example.com/#2
filter:
  - grep: "Chose B"

METTRE À JOUR UNE URL ET CONSERVER L'HISTORIQUE PASSÉ

L'historique des travaux est stocké en fonction de la valeur du paramètre url, donc la mise à jour de l'URL d'un travail dans le fichier de configuration urls.yaml créera un nouveau travail sans historique. Conservez l'historique en utilisant --change-location :

urlwatch --change-location http://example.org#old http://example.org#new

La commande fonctionne également avec les travaux Navigateur et Shell, en changeant respectivement navigate et command.

EXÉCUTER UN SOUS-ENSEMBLE DE TRAVAUX

Pour exécuter un ou plusieurs travaux spécifiques au lieu de tous les travaux connus, fournissez les numéros d'index des travaux à la commande urlwatch. Par exemple, pour exécuter les travaux d'index 2, 4 et 7 :

urlwatch 2 4 7

ENVOYER DES DONNÉES DE FORMULAIRE HTML UTILISANT POST

Pour simuler la soumission d'un formulaire HTML en utilisant la méthode POST, vous pouvez passer les champs du formulaire dans le champ data de la description du travail :

name: "Mon Travail POST"
url: http://example.com/foo
data:
  username: "foo"
  password: "bar"
  submit: "Envoyer la requête"

Par défaut, la requête utilisera la méthode HTTP POST, et le Content-type sera défini sur application/x-www-form-urlencoded.

ENVOYER DES DONNÉES ARBITRAIRES UTILISANT HTTP PUT

Il est possible de personnaliser la méthode HTTP et l'en-tête Content-type, vous permettant d'envoyer des requêtes arbitraires au serveur :

name: "Ma Requête PUT"
url: http://example.com/item/new
method: PUT
headers:
  Content-type: application/json
data: '{"foo": true}'

SUPPORT UTF-8 SOUS WINDOWS

Sous Windows, le codage de fichier par défaut peut être spécifique à la locale et ne pas fonctionner correctement si les fichiers sont enregistrés en utilisant le codage UTF-8 (recommandé).

Si vous rencontrez des problèmes pour charger des fichiers codés en UTF-8 sous Windows, vous pourriez voir un problème comme celui-ci lorsque urlwatch analyse vos fichiers de configuration :

UnicodeDecodeError: 'charmap' codec can't decode byte 0x9d in position 214: character maps to <undefined>

Pour contourner ce problème, Python 3.7 et versions ultérieures disposent d'un nouveau mode UTF-8 https://peps.python.org/pep-0540/ qui peut être activé en définissant la variable d'environnement PYTHONUTF8 sur 1 :

set PYTHONUTF8=1
urlwatch

Vous pouvez également ajouter cette variable d'environnement à votre environnement utilisateur ou à votre environnement système pour appliquer le mode UTF-8 à tous les programmes Python sur votre machine.
