user_caps(5) Formats de fichiers user_caps(5)

NOM

user_caps - format des capacités terminfo définies par l'utilisateur

SYNTAXE

infocmp -x

tic -x

DESCRIPTION

Contexte

Avant ncurses version 5.0, les bases de données terminfo utilisaient un répertoire fixe de capacités de terminaux conçu pour la base de données de terminaux SVr2 en 1984, et étendu par étapes jusqu'à SVr4 (1989), et standardisé dans la spécification Single Unix à partir de 1995.

La plupart des extensions de ce répertoire fixe étaient des ajouts aux tables de capacités booléennes, numériques et de chaînes. Plutôt que de modifier la signification d'une capacité existante, un nouveau nom était ajouté. La base de données terminfo utilise un format binaire ; la compatibilité binaire a été assurée en utilisant un en-tête indiquant le nombre d'éléments dans les tables pour chaque type de capacité. La standardisation était incomplète :

•
Le format binaire lui-même n'est pas décrit dans la documentation X/Open Curses. Seul le format source est décrit.
Les développeurs de bibliothèques s'appuient sur la documentation SVr4 et sur l'ingénierie inverse des fichiers terminfo compilés pour correspondre au format binaire.
•
En l'absence de standard pour le format binaire, la plupart des implémentations copient le format binaire SVr2, qui utilise des entiers signés de 16 bits et est limité à des entrées de 4096 octets.
Le format ne peut pas représenter de capacités numériques très grandes, ni un grand nombre de définitions de touches spéciales.
•
Les tables de noms de capacités diffèrent entre les implémentations.
Bien qu'elles puissent fournir tous les noms de capacités standards, la position dans les tables diffère car certaines fonctionnalités ont été ajoutées au besoin, tandis que d'autres ont été ajoutées (hors séquence) pour se conformer à X/Open Curses.
Bien que le répertoire de capacités prédéfinies de ncurses soit le plus proche de Solaris, la base de données terminfo de Solaris présente quelques différences par rapport à la liste publiée par X/Open Curses. Par exemple, ncurses peut être configuré avec des tables qui correspondent aux bases de données de terminaux pour AIX, HP-UX ou OSF/1, plutôt qu'à la configuration par défaut de type Solaris.
•
Dans SVr4 curses et ncurses, la base de données de terminaux est définie au moment de la compilation à l'aide d'un fichier texte qui liste les différentes capacités du terminal.
En principe, le fichier texte peut être étendu, mais cela nécessite de recompiler et de réinstaller la bibliothèque. Le fichier texte utilisé dans ncurses pour les capacités de terminaux inclut des détails pour divers systèmes au-delà des fonctionnalités documentées de X/Open Curses. Par exemple, ncurses prend en charge ces capacités dans chaque configuration :
memory_lock
(meml) verrouiller la mémoire au-dessus du curseur
memory_unlock
(memu) déverrouiller la mémoire
box_chars_1
(box1) jeu primaire de caractères pour les boîtes
Les capacités de verrouillage/déverrouillage de la mémoire ont été incluses car elles étaient utilisées dans la description du terminal X11R6 pour xterm(1). La capacité box1 est utilisée dans tic pour aider avec les descriptions de terminaux écrites pour AIX.

Au cours des années 1990, certains utilisateurs étaient réticents à utiliser terminfo malgré ses avantages en termes de performances par rapport à termcap :

  • Le répertoire fixe empêchait les utilisateurs d'ajouter des fonctionnalités pour les améliorations de terminaux imprévues (ou leur demandait de réutiliser des capacités existantes comme solution de contournement).
  • La limitation aux entiers signés de 16 bits a également été mentionnée. Comme termcap stocke tout sous forme de chaîne, il pouvait représenter des nombres plus grands.

Bien que l'extensibilité de termcap ait été rarement utilisée (ce n'était jamais le locuteur qui avait effectivement utilisé la fonctionnalité), la critique était pertinente. ncurses 5.0 a fourni un moyen de détecter les capacités non standard, de déterminer leur type et éventuellement de les stocker et de les récupérer d'une manière qui n'interférait pas avec d'autres applications. Celles-ci sont appelées capacités définies par l'utilisateur car aucune modification des noms de capacités prédéfinis de la boîte à outils n'est nécessaire.

Les utilitaires ncurses tic et infocmp ont une option de ligne de commande “-x” pour contrôler si les capacités non standard sont stockées ou récupérées. Une fonction de bibliothèque use_extended_names est fournie dans le même but.

Lors de la compilation d'une base de données de terminaux, si “-x” est défini, tic stockera une capacité définie par l'utilisateur si le nom de la capacité n'est pas l'un des noms prédéfinis.

Étant donné que ncurses fournit une interface de bibliothèque termcap, ces capacités définies par l'utilisateur peuvent être visibles par les applications termcap :

•
L'interface termcap (comme toutes les implémentations de termcap) exige que les noms des capacités soient de 2 caractères.
Lorsque la capacité est suffisamment simple pour être utilisée dans une application termcap, elle est fournie sous forme de nom de 2 caractères.
  • Il existe d'autres capacités définies par l'utilisateur qui font référence à des fonctionnalités inutilisables dans termcap, par exemple, des chaînes paramétrées qui utilisent plus de deux paramètres ou qui utilisent plus que le support d'expression trivial fourni par termcap. Pour celles-ci, la base de données terminfo ne devrait avoir que des noms de capacités de 3 caractères ou plus.
  • Certains terminaux peuvent envoyer des chaînes distinctes pour les touches spéciales (touches curseur, pavé numérique ou fonction) en fonction des touches modificatrices (maj, ctrl, etc.). Bien que terminfo et termcap disposent d'un ensemble de 60 noms de touches fonction prédéfinies, auxquelles une série de touches peut être assignée, cela est insuffisant pour plus d'une douzaine de touches multipliées par plus de quelques combinaisons de modificateurs. La base de données ncurses utilise une convention basée sur xterm(1) pour fournir des noms de touches spéciales étendus.
Adapter cela à la limitation de 2 caractères de termcap serait inutile. Ces touches étendues ne sont disponibles qu'avec terminfo.

Capacités reconnues

La bibliothèque ncurses utilise les capacités définissables par l'utilisateur. Bien que la base de données terminfo puisse avoir d'autres extensions, ncurses effectue des vérifications explicites pour celles-ci :

AX
Booléen, affirme que le terminal interprète SGR 39 et SGR 49 en réinitialisant respectivement la couleur de premier plan et d'arrière-plan aux valeurs par défaut.
C'est également une fonctionnalité reconnue par le programme screen.
E3
Chaîne, indique comment effacer le tampon de défilement du terminal. Lorsqu'elle est présente, le programme clear(1) l'envoie avant d'effacer le terminal.
La commande “tput clear” fait la même chose.
NQ
Booléen, utilisé pour supprimer une vérification de cohérence dans tic pour les capacités ncurses user6 à user9 (u6, u7, u8 et u9) qui indiquent comment interroger la position du curseur du terminal et ses attributs de périphérique.
RGB
Booléen, nombre ou chaîne, utilisé pour affirmer que les capacités set_a_foreground et set_a_background correspondent à des couleurs directes, en utilisant une convention RVB (rouge/vert/bleu). Cette capacité permet à la fonction color_content de retourner les valeurs appropriées sans nécessiter que l'application initialise les couleurs à l'aide de init_color.
Le type de capacité détermine les valeurs que ncurses voit :
Booléen

Comme il existe plusieurs encodages RGB en usage, les applications qui font des suppositions sur le nombre de bits par couleur ne fonctionneront probablement pas de manière fiable. Comme cas trivial, par exemple, on pourrait définir RGB#1 pour représenter les huit couleurs ANSI standard, c'est-à-dire un bit par couleur.
U8
number, affirme que ncurses doit utiliser les valeurs Unicode pour les caractères de dessin de ligne, et qu'il doit ignorer les capacités de jeu de caractères alternatif lorsque la locale utilise l'encodage UTF-8. Pour plus d'informations, voir la discussion de NCURSES_NO_UTF8_ACS dans ncurses(3X).
Définissez cette capacité à une valeur non nulle pour l'activer.
XM
string, remplace la chaîne intégrée de ncurses qui active/désactive le mode souris de xterm(1).
ncurses envoie une séquence de caractères au terminal pour initialiser le mode souris, et lorsque l'utilisateur clique sur les boutons de la souris ou (dans certains modes) déplace la souris, gère les caractères renvoyés par le terminal pour lui indiquer ce qui a été fait avec la souris.
Le protocole souris est activé lorsque le masque passé dans la fonction mousemask n'est pas nul. Par défaut, ncurses gère les réponses pour le protocole souris xterm X11. Il connaît également le protocole souris xterm SGR 1006, mais doit en être informé pour le rechercher spécifiquement. Il ne pourra pas deviner quel mode est utilisé, car les réponses sont suffisamment similaires pour ne causer que de la confusion.
La capacité XM a un seul paramètre. S'il est non nul, le protocole souris doit être activé. S'il est nul, le protocole souris doit être désactivé. ncurses inspecte cette capacité si elle est présente, pour voir si le protocole 1006 est utilisé. Si c'est le cas, il s'attend à ce que les réponses utilisent le protocole souris xterm SGR 1006.
Le protocole souris xterm est utilisé par d'autres émulateurs de terminaux. La base de données des terminaux utilise des blocs de construction pour les différents protocoles souris xterm qui peuvent être utilisés dans des descriptions de terminaux personnalisées.
Les blocs de construction de la base de données des terminaux pour cette fonctionnalité souris ont également une capacité expérimentale xm. La capacité “xm” décrit la réponse de la souris. Actuellement, il n'y a pas d'interpréteur qui utiliserait ces informations pour rendre la prise en charge de la souris complètement pilotée par les données.
xm montre le format des réponses de la souris. Dans cette capacité expérimentale, les paramètres sont

Définitions de touches étendues

Plusieurs terminaux offrent la possibilité d'envoyer des chaînes distinctes pour des combinaisons de touches spéciales modifiées. Il n'y a pas de norme pour ce que ces touches peuvent envoyer.

Depuis 1999, xterm(1) prend en charge les modificateurs shift, control, alt et meta qui produisent des chaînes de touches spéciales distinctes. Dans une description de terminal, ncurses n'a aucune connaissance spéciale des modificateurs utilisés. Les applications peuvent utiliser la convention de nommage établie pour xterm pour trouver ces touches spéciales dans la description du terminal.

En partant de la convention curses selon laquelle les codes de capacité décrivant l'entrée générée par les touches d'un terminal commencent par “k”, et que les touches spéciales modifiées utilisent des lettres majuscules dans leurs noms, la base de données des terminaux de ncurses définit les noms et codes suivants auxquels un suffixe est ajouté.

Code Description
kDC kdch1 déplacé (supprimer le caractère)
kDN kcud1 déplacé (curseur vers le bas)
kEND kend déplacé (fin)
kHOM khome déplacé (début)
kLFT kcub1 déplacé (curseur vers l'arrière)
kNXT knext déplacé (page suivante)
kPRV kprev déplacé (page précédente)
kRIT kcuf1 déplacé (curseur vers l'avant)
kUP kcuu1 déplacé (curseur vers le haut)

La nomenclature des touches sur les systèmes Unix pour lesquels curses a été développé diffère de celle des descendants omniprésents de la disposition du clavier IBM PC/AT aujourd'hui. Dans ce qui précède, interprétez “backward” comme “left”, “forward” comme “right”, “next” comme “page down”, et “prev(ious)” comme “page up”.

Ce sont les suffixes utilisés pour désigner les modificateurs :

Valeur Description
2 Shift
3 Alt
4 Shift + Alt
5 Control
6 Shift + Control
7 Alt + Control
8 Shift + Alt + Control
9 Meta
10 Meta + Shift
11 Meta + Alt
12 Meta + Alt + Shift
13 Meta + Ctrl
14 Meta + Ctrl + Shift
15 Meta + Ctrl + Alt
16 Meta + Ctrl + Alt + Shift

Aucune de ces options n'est prédéfinie ; les descriptions de terminaux peuvent faire référence à des noms que ncurses allouera à l'exécution pour des codes de touche. Pour utiliser ces touches dans un programme ncurses, une application pourrait faire ceci :

  • en utilisant une liste de noms de touches étendues, demander à tigetstr(3X) leurs valeurs, et
  • étant donné la liste des valeurs, demander à key_defined(3X) le code de touche qui serait retourné pour ces touches par wgetch(3X).

PORTABILITÉ

L'extension “-x” de tic et infocmp a été adoptée dans NetBSD curses. Cette implémentation stocke les capacités définies par l'utilisateur, mais n'utilise aucune de ces capacités elle-même.

    DESCRIPTION

    Le fichier /etc/security/caps.d/*.conf est utilisé pour configurer les capacités de Linux. Chaque fichier de ce répertoire peut contenir une ou plusieurs directives qui modifient le comportement des capacités.

    Les directives supportées sont :

    • ignorecaps : Liste des capacités à ignorer. Ces capacités seront supprimées de tous les processus.
    • execcaps : Liste des capacités à définir pour les exécutables. Ces capacités seront définies pour les exécutables lors de leur exécution.
    • setuid : Liste des utilisateurs pour lesquels les capacités SETUID sont autorisées.
    • setgid : Liste des utilisateurs pour lesquels les capacités SETGID sont autorisées.

    Les capacités sont spécifiées par leur nom, sans le préfixe CAP_. Par exemple, CHOWN au lieu de CAP_CHOWN.

    Les fichiers sont traités dans l'ordre alphabétique. Les directives définies dans les fichiers ultérieurs écraseront celles définies dans les fichiers précédents.

    PORTABILITÉ

    Cette fonctionnalité est spécifique à Linux.
