UWSM-PLUGINS(3) Manuel des fonctions de bibliothèque UWSM-PLUGINS(3)

NOM

UWSM-plugins - Plugins pour le gestionnaire de session Wayland universel.

DESCRIPTION

Les plugins shell fournissent des fonctions spécifiques au compositeur lors de la préparation de l'environnement.

Situés dans ${PREFIX}/share/uwsm/plugins/ et nommés ${__WM_BIN_ID__}.sh, ils ne devraient contenir que des fonctions nommées spécifiquement.

${__WM_BIN_ID__} est dérivé du premier élément de la ligne de commande du compositeur en appliquant s/(^[^a-zA-Z]|[^a-zA-Z0-9_])+/_/ et en le convertissant en minuscules.

Il est utilisé comme identifiant de plugin et suffixe dans les noms de fonction.

Variables disponibles pour les plugins

__WM_ID__

identifiant du compositeur, premier argument effectif de start.
__WM_ID_UNIT_STRING__
identifiant du compositeur échappé pour le nom d'unité systemd.
__WM_BIN_ID__
premier élément traité de l'argv du compositeur.
__WM_DESKTOP_NAMES__
noms de bureau séparés par : provenant de DesktopNames= de l'entrée et de l'argument CLI -D.
__WM_FIRST_DESKTOP_NAME__
le premier des éléments ci-dessus.
__WM_DESKTOP_NAMES_LOWERCASE__
identique à __WM_DESKTOP_NAMES__, mais en minuscules.
__WM_FIRST_DESKTOP_NAME_LOWERCASE__
le premier des éléments ci-dessus.
__WM_DESKTOP_NAMES_EXCLUSIVE__
(true|false) indique que __WM_DESKTOP_NAMES__ provient d'un argument CLI et est marqué comme exclusif.
__OIFS__
contient le séparateur de champs par défaut du shell (espace, tabulation, nouvelle ligne) pour une restauration pratique.

Fonctions standard

load_wm_env

fonction standard pour charger les fichiers d'environnement
process_config_dirs
itère sur la hiérarchie XDG Config et la partie système de la hiérarchie XDG Data (priorité décroissante)
process_config_dirs_reversed
(appelée par load_wm_env), identique à process_config_dirs mais en sens inverse (priorité croissante)
in_each_config_dir_reversed
appelée par process_config_dirs_reversed pour chaque répertoire de configuration comme $1, charge les fichiers uwsm/env, uwsm/env-${desktop}
in_each_config_dir
appelée par process_config_dirs pour chaque répertoire de configuration comme $1, ne fait rien pour le moment
source_file
charge le fichier $1 s'il existe, en fournissant des messages pour le journal.

Voir le code dans uwsm/main.py pour plus de fonctions auxiliaires.

Fonctions qui peuvent être ajoutées par les plugins

quirks__${__WM_BIN_ID__}
appelée avant le chargement de l'environnement.

Ces fonctions seront appelées à la place des fonctions standard si elles sont définies :

load_wm_env__${__WM_BIN_ID__}
process_config_dirs_reversed__${__WM_BIN_ID__}
in_each_config_dir_reversed__${__WM_BIN_ID__}
process_config_dirs__${__WM_BIN_ID__}
in_each_config_dir__${__WM_BIN_ID__}

Les fonctions originales sont toujours disponibles pour être appelées explicitement si un effet combiné est nécessaire.

Exemple :

#!/bin/false
# fonction pour effectuer des actions arbitraires avant le chargement de l'environnement
quirks__my_cool_wm() {
  # ici des variables supplémentaires peuvent être définies ou supprimées
  export I_WANT_THIS_IN_SESSION=yes
  unset I_DO_NOT_WANT_THAT
  # ou préparer une configuration pour le compositeur
  # ou définir une variable pour modifier ce que le sourcing de uwsm/env, uwsm/env-${__WM_ID__}
  # fera à l'étape suivante
  ...
}
in_each_config_dir_reversed__my_cool_wm() {
  # mécanisme personnalisé pour le chargement des fichiers d'environnement (ou un stub)
  # remplace la fonction standard, mais nous la voulons aussi
  # donc appelons-la explicitement
  in_each_config_dir_reversed "$1"
  # et chargeons en plus notre fichier
  source_file "${1}/${__WM_ID__}/env"
}
