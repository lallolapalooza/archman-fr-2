UNCOMPRESS(1P) Manuel du programmeur POSIX UNCOMPRESS(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uncompress — développer des données compressées

SYNTAXE

uncompress [-cfv] [fichier...]

DESCRIPTION

L'utilitaire uncompress restaure les fichiers à leur état d'origine après qu'ils aient été compressés à l'aide de l'utilitaire compress. Si aucun fichier n'est spécifié, l'entrée standard est décompressée vers la sortie standard. Si le processus appelant dispose des privilèges appropriés, la propriété, les permissions, l'heure d'accès et l'heure de modification du fichier d'origine sont conservées.

Cet utilitaire doit prendre en charge la décompression de tous les fichiers produits par l'utilitaire compress sur la même implémentation. Pour les fichiers produits par compress sur d'autres systèmes, uncompress prend en charge la compression de 9 à 14 bits (voir compress, -b) ; il est défini par l'implémentation si les valeurs de -b supérieures à 14 sont prises en charge.

OPTIONS

L'utilitaire uncompress doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires, à l'exception de la convention 1 qui s'applique car le nom de l'utilitaire a dix lettres.

Les options suivantes doivent être prises en charge :

-c
Écrit vers la sortie standard ; aucun fichier n'est modifié.
-f
Ne pas demander la confirmation pour l'écrasement des fichiers. Sauf lorsque exécuté en arrière-plan, si -f n'est pas donné, l'utilisateur sera invité à confirmer si un fichier existant doit être écrasé. Si l'entrée standard n'est pas un terminal et que -f n'est pas donné, uncompress écrira un message de diagnostic sur la sortie d'erreur standard et quittera avec un statut supérieur à zéro.
-v
Écrit des messages sur la sortie d'erreur standard concernant le développement de chaque fichier.

OPÉRANDES

L'opérande suivant doit être pris en charge :

fichier
Un chemin d'accès à un fichier. Si fichier a déjà le suffixe .Z spécifié, il sera utilisé comme fichier d'entrée et le fichier de sortie sera nommé fichier avec le suffixe .Z supprimé. Sinon, fichier sera utilisé comme nom du fichier de sortie et fichier avec le suffixe .Z ajouté sera utilisé comme fichier d'entrée.

ENTRÉE STANDARD

L'entrée standard sera utilisée uniquement si aucun opérande fichier n'est spécifié, ou si un opérande fichier est '-'.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être dans le format produit par l'utilitaire compress.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de uncompress :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

En l'absence d'opérandes fichier ou lorsque l'option -c est spécifiée, la sortie décompressée est écrite sur la sortie standard.

ERREUR STANDARD

Les invites sont écrites sur la sortie d'erreur standard dans les conditions spécifiées dans les sections DESCRIPTION et OPTIONS. Les invites contiennent le chemin du fichier, mais leur format n'est pas spécifié autrement. Sinon, la sortie d'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Les fichiers de sortie sont les mêmes que les fichiers d'entrée respectifs de compress.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Le fichier d'entrée reste inchangé.

Les sections suivantes sont informatives.

USAGE DES APPLICATIONS

La limite de 14 pour l'argument bits de compress -b est destinée à assurer la portabilité sur tous les systèmes (dans les limites imposées par l'absence d'un format de fichier explicite publié). Certaines implémentations basées sur des architectures 16 bits ne peuvent pas supporter la décompression 15 ou 16 bits.

Aucun.

OPTIONS

-c
Écrit la sortie sur la sortie standard. Tous les fichiers compressés sont lus en séquence et leur contenu décompressé est écrit sur la sortie standard. Le fichier d'entrée d'origine est laissé inchangé.
-f
Force la décompression. Si le fichier de sortie existe, il sera écrasé sans demande. Si le fichier d'entrée n'est pas un fichier compressé par compress, et si le fichier de sortie n'existe pas, il sera créé avec le nom de fichier d'entrée et sans extension.
-v
Mode verbeux. Affiche le nom de chaque fichier avant de le traiter, ainsi que le pourcentage de réduction.
-F
Désactive la vérification du nom de fichier. La commande tentera toujours de décompresser le fichier, même s'il est indiqué qu'il s'agit d'un fichier corrompu.

OPERANDS

Les opérandes sont les noms de fichiers à décompresser. S'il n'y a pas d'opérandes, uncompress lit l'entrée standard.

STDIN

Si aucun fichier n'est spécifié, l'entrée standard est lue. Le contenu décompressé est écrit sur la sortie standard, sauf si l'option -c est utilisée.

INPUT FILES

Les fichiers d'entrée sont les fichiers spécifiés en tant qu'opérandes. Ils doivent avoir été compressés à l'aide de la commande compress.

ENVIRONMENT VARIABLES

Aucune variable d'environnement n'affecte l'exécution de cette commande.

ASYNCHRONOUS EVENTS

Aucun événement asynchrone n'est géré par cette commande.

STDOUT

Par défaut, le contenu décompressé des fichiers est écrit dans des fichiers portant le même nom que les fichiers d'origine mais sans l'extension .Z. Si l'option -c est utilisée, la sortie décompressée est écrite sur la sortie standard.

STDERR

Les messages d'erreur sont écrits sur la sortie d'erreur standard.

OUTPUT FILES

Les fichiers de sortie sont les versions décompressées des fichiers d'entrée. Le nom du fichier de sortie est le nom du fichier d'entrée sans l'extension .Z.

EXTENDED DESCRIPTION

Aucune description étendue.

EXIT STATUS

La commande uncompress retourne 0 si la décompression a réussi, et une valeur supérieure à 0 en cas d'erreur.

CONSEQUENCES OF ERRORS

En cas d'erreur, les fichiers de sortie peuvent être incomplets ou corrompus. Les messages d'erreur sur la sortie d'erreur standard indiquent la nature du problème.

APPLICATION USAGE

Utilisez uncompress pour récupérer des fichiers compressés à l'aide de compress. Par exemple :

uncompress mon_fichier.Z

Pour décompresser plusieurs fichiers, ou pour rediriger la sortie vers un autre fichier :

uncompress *.Z

uncompress -c fichier1.Z fichier2.Z > fichiers_decompresses.txt

EXAMPLES

Décompresser archive.Z et le remplacer par archive :

$ uncompress archive.Z

Décompresser rapport.Z et afficher la progression :

$ uncompress -v rapport.Z

Décompresser data.Z et écrire le résultat sur la sortie standard :

$ uncompress -c data.Z > data.txt

RATIONALE

La commande uncompress fait partie de l'utilitaire de compression historique compress. Elle est fournie pour la compatibilité avec les fichiers compressés par cette méthode. D'autres méthodes de compression plus modernes et plus efficaces, comme gzip, sont généralement préférées.
