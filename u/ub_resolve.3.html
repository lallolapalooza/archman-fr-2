DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui fait de la mise en cache et de la validation DNSSEC. Ceci est l'API de la bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et vice versa, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour maintenir le contexte entre les appels. L'utilisateur doit la gérer, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La créer à nouveau supprime toute configuration précédente (telle que les clés de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe et un contexte peut être utilisé dans un environnement threadé (ainsi que dans un environnement non threadé). La résolution (et la validation) peut également être effectuée de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement à l'appel, de sorte que le traitement puisse continuer, pendant que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec des valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez la bibliothèque openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou plus récent utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les rappels ne sont pas appelés pour celles-ci.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier l'une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère une valeur d'option. Certaines options ne peuvent pas être récupérées, et d'autres retournent une liste séparée par des nouvelles lignes. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée par l'appelant avec free(2).
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelé en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine à laquelle les requêtes DNS doivent être transmises, le résolveur de mise en cache à utiliser. Adresse IP4 ou IP6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas capable de DNSSEC, la validation peut échouer. Peut être appelé plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. Il n'est possible à ce stade de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Définissez isprime à vrai si vous configurez des hints racine avec. Sinon, similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelé plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. Il n'est possible à ce stade de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_set_tls
Active le DNS via TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. Il n'est possible à ce stade de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_resolvconf
Par défaut, les serveurs racines sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser à partir du nom de fichier donné. Généralement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxys de mise en cache. S'ils ne prennent pas en charge DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont pris en compte, le domaine de recherche, ndots et les autres paramètres de resolv.conf(5) sont ignorés. Si fname est NULL, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré globalement est choisi à la place). Il n'est possible à ce stade de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Généralement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname est NULL, "/etc/hosts" est utilisé (si sous Windows, etc/hosts depuis WINDIR est choisi à la place). Il n'est possible à ce stade de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_add_ta
Ajoute un domaine d'ancre de confiance (trust anchor) pour la validation DNSSEC. Le format est le même que celui utilisé dans le fichier de configuration unbound. L'option est : domain: key-type: key. La clé est en base64. Plus spécifiquement, vous pouvez utiliser ub_ctx_add_ta_autr pour charger un fichier de clés publiques pour un domaine.
ub_ctx_add_ta_autr
Charge les ancres de confiance à partir d'un fichier nommé. Le fichier est lu comme un fichier de configuration unbound, les lignes contenant des ancres de confiance sont chargées. Plus spécifiquement, les lignes commençant par auto-trust-anchor-file: sont utilisées.
ub_ctx_add_ta_file
Charge les ancres de confiance à partir d'un fichier nommé. Le fichier est lu comme un fichier de configuration unbound, les lignes contenant des ancres de confiance sont chargées. Plus spécifiquement, les lignes commençant par trust-anchor-file: sont utilisées.
ub_ctx_trustedkeys
Charge les clés de confiance (trust anchors) à partir du fichier nommé. Le fichier est lu comme unbound le fait pour le paramètre trust-keys-file dans son fichier de configuration. Ce paramètre est obsolète, utilisez plutôt ub_ctx_add_ta_file.
ub_ctx_debugout
Définit le fichier où les messages de débogage doivent être envoyés. Par défaut, ils sont envoyés sur stderr. Les messages de débogage sont activés par ub_ctx_debuglevel.
ub_ctx_debuglevel
Définit le niveau de débogage. Par défaut, le niveau est 0 (aucun message de débogage). Plus le niveau est élevé, plus les messages sont verbeux. Les niveaux de débogage possibles sont définis dans unbound.conf(5).
ub_ctx_async
Active le mode asynchrone, qui permet de faire plusieurs requêtes sans attendre la réponse de chacune. Lorsque dothread est vrai, la bibliothèque tente d'utiliser un thread séparé pour les requêtes DNS, afin de ne pas bloquer le thread appelant. Quand dothread est faux, la bibliothèque utilise les appels système non bloquants, et le programme appelant doit explicitement utiliser ub_poll et ub_process pour gérer les événements réseau. Le mode asynchrone est le mode de fonctionnement par défaut pour les fonctions de résolution asynchrones.
ub_poll
Attend qu'un événement réseau se produise sur les sockets utilisés par unbound. Cette fonction doit être appelée régulièrement lorsque le mode asynchrone sans thread est activé. Elle retourne le nombre de descripteurs de fichiers prêts à être lus ou écrits. Une valeur de 0 signifie qu'un timeout s'est produit. La fonction retourne -1 en cas d'erreur. Utilisez ub_fd pour obtenir les descripteurs de fichiers.
ub_wait
Attend qu'une réponse soit disponible pour une requête asynchrone. Cette fonction est une simplification pour le mode asynchrone sans thread. Elle attend qu'un descripteur de fichier soit prêt, puis appelle ub_process pour traiter les données. Elle retourne 0 en cas de succès, et -1 en cas d'erreur.
ub_fd
Obtient le descripteur de fichier utilisé par unbound pour la communication réseau. Peut être appelé plusieurs fois pour obtenir tous les descripteurs de fichiers actifs. Retourne -1 si aucun descripteur de fichier n'est disponible. Utile lorsque le mode asynchrone sans thread est activé, pour savoir sur quel descripteur de fichier appeler select(2) ou poll(2).
ub_process
Traite les données réseau disponibles sur les descripteurs de fichiers retournés par ub_poll. Cette fonction doit être appelée lorsque des données sont disponibles, ou après un appel à ub_wait. Elle traite les réponses DNS et déclenche les rappels pour les requêtes asynchrones terminées. Elle retourne 0 en cas de succès, et -1 en cas d'erreur.
ub_resolve
Effectue une requête DNS synchrone (bloquante). Elle recherche le nom d'hôte donné, pour le type d'enregistrement (rrtype) et la classe (rrclass) spécifiés. Les types et classes courants sont définis dans <arpa/nameser.h>. Par exemple, pour une requête A (IPv4), utilisez 1 pour rrtype et 1 pour rrclass. Le résultat est stocké dans le pointeur result. La mémoire allouée pour result doit être libérée par ub_resolve_free. Retourne 0 en cas de succès, et un code d'erreur unbound en cas d'échec. Le nom d'hôte doit être une chaîne ASCII.
ub_resolve_async
Effectue une requête DNS asynchrone (non bloquante). Le nom d'hôte, le type d'enregistrement (rrtype) et la classe (rrclass) sont spécifiés comme pour ub_resolve. Le paramètre mydata est un pointeur vers des données définies par l'utilisateur qui seront passées au rappel. Le paramètre callback est un pointeur vers la fonction de rappel qui sera appelée lorsque le résultat sera disponible. Le paramètre async_id reçoit un identifiant unique pour cette requête asynchrone, qui peut être utilisé pour l'annuler avec ub_cancel. La fonction retourne 0 en cas de succès, et un code d'erreur unbound en cas d'échec.
ub_cancel
Annule une requête DNS asynchrone précédemment initiée avec ub_resolve_async. Le async_id est l'identifiant retourné par ub_resolve_async. La fonction de rappel ne sera pas appelée pour cette requête.
ub_resolve_free
Libère la mémoire allouée pour la structure ub_result retournée par ub_resolve.
ub_strerror
Retourne une chaîne de caractères décrivant le code d'erreur unbound donné.
ub_ctx_print_local_zones
Imprime les zones locales configurées dans le contexte unbound.
ub_ctx_zone_add
Ajoute une zone locale au contexte unbound. zone_name est le nom de la zone (par exemple, "example.com"), et zone_type est le type de zone (par exemple, "local" ou "static").
ub_ctx_zone_remove
Supprime une zone locale du contexte unbound.
ub_ctx_data_add
Ajoute des données brutes au contexte unbound. Celles-ci peuvent être utilisées pour des tests ou des configurations spécifiques.
ub_ctx_data_remove
Supprime des données brutes du contexte unbound.

RETURN CODE

La plupart des fonctions de la bibliothèque retournent 0 en cas de succès, et un code d'erreur différent de zéro en cas d'échec. Les codes d'erreur sont des entiers définis dans la bibliothèque libunbound.

ub_ctx_add_ta
Ajoute un point d'ancrage de confiance au contexte donné. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée. Le format est une chaîne de caractères, similaire au format de fichier de zone, [nom de domaine] [type] [contenu rdata]. Les enregistrements DS et DNSKEY sont acceptés.
ub_ctx_add_ta_autr
Ajoute un nom de fichier avec un point d'ancrage de confiance suivi automatiquement au contexte donné. Passe le nom d'un fichier contenant le point d'ancrage de confiance géré. Vous pouvez créer ce fichier avec unbound-anchor(8) pour le point d'ancrage racine. Vous pouvez également le créer avec un fichier initial contenant une seule ligne avec un enregistrement DNSKEY ou DS. Si le fichier est accessible en écriture, il est mis à jour lorsque le point d'ancrage de confiance change. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_add_ta_file
Ajoute des points d'ancrage de confiance au contexte donné. Passe le nom d'un fichier contenant des enregistrements DS et DNSKEY au format de fichier de zone. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_trustedkeys
Ajoute des points d'ancrage de confiance au contexte donné. Passe le nom d'un fichier de configuration de style bind contenant trusted-keys{}. Pour le moment, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_debugout
Définit la sortie des logs de débogage et d'erreur vers le flux donné. Passe NULL pour désactiver la sortie. Par défaut, stderr. Les noms de fichiers ou l'utilisation de syslog peuvent être activés à l'aide des options de configuration, cette routine est destinée à l'utilisation de votre propre flux.
ub_ctx_debuglevel
Définit la verbosité du débogage pour le contexte. La sortie est dirigée vers stderr. Un niveau de débogage plus élevé donne plus de sortie.
ub_ctx_async
Définit un comportement de contexte pour l'action asynchrone. Si défini à vrai, active le multithreading et un appel à ub_resolve_async crée un thread pour gérer le travail en arrière-plan. Si faux, un processus est "forké" pour gérer le travail en arrière-plan. Les modifications apportées à ce paramètre après des appels à ub_resolve_async n'ont aucun effet (supprimez et recréez le contexte pour changer).
ub_poll
Sonde un contexte pour voir s'il a de nouveaux résultats. Ne pas sonder en boucle, extraire plutôt le fd ci-dessous pour sonder la disponibilité, puis vérifier, ou attendre en utilisant la routine d'attente. Renvoie 0 si rien à lire, ou une valeur non nulle si un résultat est disponible. Si non nulle, appelez ub_process pour effectuer les rappels.
ub_wait
Attend qu'un contexte termine avec des résultats. Appelle ub_process après l'attente pour vous. Après l'attente, il n'y a plus de requêtes asynchrones en suspens.
ub_fd
Obtient le descripteur de fichier. Attend qu'il devienne lisible, à ce moment-là les réponses sont renvoyées par le résolveur de validation asynchrone. Appelez ensuite ub_process pour continuer le traitement.
ub_process
Appelez cette routine pour continuer le traitement des résultats du résolveur de validation (lorsque le fd devient lisible). Effectuera les rappels nécessaires.
ub_resolve
Effectue la résolution et la validation du nom cible. Le nom est un nom de domaine dans une chaîne de caractères terminée par zéro. Les types et classes rrtype et rrclass sont des codes de type et de classe DNS. La structure de résultat est nouvellement allouée avec les données résultantes.
ub_resolve_async
Effectue la résolution et la validation asynchrones du nom cible. Les arguments signifient la même chose que pour ub_resolve, sauf qu'aucune donnée n'est retournée immédiatement, un rappel est appelé plus tard. Le rappel reçoit une copie du pointeur mydata, que vous pouvez utiliser pour passer des informations au rappel. Le type de rappel est un pointeur de fonction vers une fonction déclarée comme suit :
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

L'identifiant async_id est retourné afin que vous puissiez (facultativement) décider de le suivre et d'annuler la requête si nécessaire. Si vous passez un pointeur NULL, l'identifiant async_id n'est pas retourné.

ub_cancel
Annule une requête asynchrone en cours. Cela peut retourner une erreur si la requête n'existe pas, ou si la requête est déjà en cours de livraison, auquel cas vous pourriez encore recevoir un rappel pour cette requête.
ub_resolve_free
Libère le contenu de la structure ub_result après utilisation.
ub_strerror
Convertit une valeur d'erreur d'une des fonctions de la bibliothèque unbound en une chaîne lisible par l'homme.
ub_ctx_print_local_zones
Imprime les informations d'autorité locale pour le débogage.
ub_ctx_zone_add
Ajoute une nouvelle zone aux informations d'autorité locale, similaire à l'instruction local-zone de unbound.conf(5).
ub_ctx_zone_remove
Supprime une zone des informations d'autorité locale.
ub_ctx_data_add
Ajoute des données d'enregistrement de ressources aux informations d'autorité locale, similaire à l'instruction local-data de unbound.conf(5).
ub_ctx_data_remove
Supprime les données d'autorité locale du nom donné.

STRUCTURE DE DONNEES DE RESULTAT

Le résultat de la résolution et de la validation DNS est renvoyé sous la forme d'une structure ub_result. La structure de résultat contient les entrées suivantes :

struct ub_result {
     char* qname;         /* chaîne de caractères, question originale */
     int qtype;           /* type demandé */
     int qclass;          /* classe demandée */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas de données manquantes */
     void* answer_packet; /* paquet complet au format réseau */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai si nodata car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si une défaillance de sécurité s'est produite */
     char* why_bogus;     /* chaîne d'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée par débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

Si secure et bogus sont tous deux faux, la sécurité n'était pas activée pour le domaine de la requête. Sinon, ils ne sont pas tous les deux vrais, l'un d'eux est vrai.

VALEURS DE RETOUR

De nombreuses routines renvoient un code d'erreur. La valeur 0 (zéro) signifie qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror renvoie une chaîne terminée par zéro. ub_ctx_create renvoie NULL en cas d'erreur (échec d'allocation malloc). ub_poll renvoie vrai si des informations peuvent être disponibles, faux sinon. ub_fd renvoie un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif lors d'un retour de fonction en cas d'échec de lecture de fichier.
