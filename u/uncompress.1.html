COMPRESS(1) Manuel des commandes générales COMPRESS(1)

NOM

compress, uncompress, zcat - compresser et décompresser des données

SYNTAXE

compress [ -f ] [ -k ] [ -v ] [ -c ] [ -V ] [ -r ] [ -b bits ] [ -- ] [ nom ... ]
uncompress [ -f ] [ -k ] [ -v ] [ -c ] [ -V ] [ -- ] [ nom ... ]
zcat [ -V ] [ -- ] [ nom ... ]

DESCRIPTION

Compress réduit la taille des fichiers nommés en utilisant le codage adaptatif Lempel-Ziv. Chaque fois que possible, le fichier est remplacé par un fichier avec l'extension .Z, tout en conservant les mêmes permissions, temps d'accès et de modification. Si aucun fichier n'est spécifié, l'entrée standard est compressée vers la sortie standard. Compress tente uniquement de compresser les fichiers réguliers. Il ignore notamment les liens symboliques. Si un fichier possède plusieurs liens physiques, compress refusera de le compresser, sauf si l'option -f est donnée.

Si -f n'est pas donné et que compress est exécuté au premier plan, l'utilisateur est interrogé pour savoir si le fichier existant doit être écrasé.

Les fichiers compressés peuvent être restaurés dans leur forme d'origine en utilisant uncompress ou zcat.

uncompress prend une liste de fichiers sur sa ligne de commande et remplace chaque fichier dont le nom se termine par .Z et qui commence par le bon nombre magique par un fichier décompressé sans le .Z. Le fichier décompressé aura les mêmes permissions, propriété et horodatages que le fichier compressé.

L'option -k fait en sorte que compress/uncompress conserve les fichiers d'entrée au lieu de les supprimer automatiquement.

L'option -c fait en sorte que compress/uncompress écrive sur la sortie standard ; aucun fichier n'est modifié.

zcat est identique à uncompress -c. zcat décompresse soit une liste de fichiers sur la ligne de commande, soit son entrée standard, et écrit les données décompressées sur la sortie standard. zcat décompressera les fichiers qui ont le bon nombre magique, qu'ils aient ou non le suffixe .Z.

Si l'option -r est spécifiée, compress opère récursivement. Si l'un des noms de fichiers spécifiés sur la ligne de commande est un répertoire, compress descendra dans le répertoire et compressera tous les fichiers qu'il y trouve. Lors de la compression, tous les fichiers déjà compressés seront ignorés, et lors de la décompression, tous les fichiers déjà décompressés seront ignorés.

L'option -V indique à chacun de ces programmes d'afficher sa version et son niveau de correctif, ainsi que tous les indicateurs de préprocesseur spécifiés lors de la compilation, sur stderr avant de procéder à toute compression ou décompression.

Compress utilise l'algorithme Lempel-Ziv modifié popularisé dans « A Technique for High Performance Data Compression », Terry A. Welch, IEEE Computer, vol. 17, no. 6 (juin 1984), pp. 8-19. Les sous-chaînes communes dans le fichier sont d'abord remplacées par des codes de 9 bits à partir de 257. Lorsque le code 512 est atteint, l'algorithme passe à des codes de 10 bits et continue d'utiliser plus de bits jusqu'à la limite spécifiée par l'option -b (par défaut 16). Bits doit être compris entre 9 et 16. La valeur par défaut peut être modifiée dans le code source pour permettre à compress d'être exécuté sur une machine plus petite.

Une fois la limite de bits atteinte, compress vérifie périodiquement le taux de compression. S'il augmente, compress continue d'utiliser le dictionnaire de codes existant. Cependant, si le taux de compression diminue, compress abandonne la table des sous-chaînes et la reconstruit à partir de zéro. Cela permet à l'algorithme de s'adapter au bloc suivant du fichier.

Notez que l'option -b est omise pour uncompress, car le paramètre bits spécifié lors de la compression est encodé dans la sortie, ainsi qu'un nombre magique pour garantir que ni la décompression de données aléatoires ni la recompression de données compressées ne soient tentées.

La quantité de compression obtenue dépend de la taille de l'entrée, du nombre de bits par code et de la distribution des sous-chaînes communes. Typiquement, le texte tel que le code source ou l'anglais est réduit de 50 à 60 %. La compression est généralement bien meilleure que celle obtenue par codage de Huffman (utilisé dans pack) ou par codage de Huffman adaptatif (compact), et elle prend moins de temps à calculer.

Sous l'option -v, un message est affiché indiquant le pourcentage de réduction pour chaque fichier compressé.

-- peut être utilisé pour arrêter l'analyse des options et forcer tous les arguments restants à être traités comme des chemins.

DIAGNOSTICS

Le statut de sortie est normalement 0 ; si le dernier fichier est plus grand après compression (tentée), le statut est 2 ; si une erreur survient, le statut de sortie est 1.

Usage: compress [-dfvcVr] [-b maxbits] [fichier ...]
Des options invalides ont été spécifiées sur la ligne de commande.
maxbits manquant
Maxbits doit suivre -b.
fichier: pas au format compressé
Le fichier spécifié à uncompress n'a pas été compressé.
fichier: compressé avec xx bits, ne peut gérer que yy bits
Fichier a été compressé par un programme qui pouvait gérer plus de bits que le code de compression sur cette machine. Recompressez le fichier avec moins de bits.
fichier: a déjà le suffixe .Z -- aucun changement
Le fichier est supposé être déjà compressé. Renommez le fichier et réessayez.
fichier: nom de fichier trop long pour ajouter .Z
Le fichier ne peut pas être compressé car son nom est plus long que 12 caractères. Renommez et réessayez. Ce message n'apparaît pas sur les systèmes BSD.
fichier existe déjà ; souhaitez-vous écraser (o ou n) ?
Répondez "o" si vous souhaitez que le fichier de sortie soit remplacé ; "n" sinon.
uncompress: entrée corrompue
Une violation de SIGSEGV a été détectée, ce qui signifie généralement que le fichier d'entrée a été corrompu.
Compression : xx.xx%
Pourcentage de l'entrée économisé par la compression. (Pertinent uniquement pour -v.)
-- pas un fichier régulier ou un répertoire : ignoré
Lorsque le fichier d'entrée n'est pas un fichier régulier ou un répertoire (par exemple, un lien symbolique, une socket, un FIFO, un fichier de périphérique), il est laissé inchangé.
-- a xx autres liens : inchangé
Le fichier d'entrée a des liens ; il est laissé inchangé. Voir ln(1) pour plus d'informations. Utilisez l'option -f pour forcer la compression des fichiers ayant plusieurs liens.
-- fichier inchangé
Aucune économie n'est réalisée par la compression. L'entrée reste vierge.

BOGUES

Bien que les fichiers compressés soient compatibles entre machines disposant de beaucoup de mémoire, -b12 devrait être utilisé pour le transfert de fichiers vers des architectures disposant d'un petit espace de données de processus (64 Ko ou moins, comme celles des séries DEC PDP, de l'Intel 80286, etc.)
