NOM

umoci unpack - Décompresse une image OCI taggée pour créer un bundle runtime

SYNOPSIS

umoci unpack --image=image[:tag] [--rootless] [--uid-map=valeur] [--uid-map=valeur] [--keep-dirlinks] bundle

DESCRIPTION

Extrait toutes les couches (de manière déterministe) dans un bundle runtime OCI au chemin spécifié par bundle, tout en générant une configuration de runtime OCI qui correspond à la configuration de l'image. De plus, une spécification mtree(8) est générée au moment de la décompression pour permettre la génération de deltas de système de fichiers par umoci-repack(1), autorisant ainsi la création d'images OCI en couches.

OPTIONS

Les options globales sont définies dans umoci(1).

--image=image[:tag]
Le tag de l'image OCI qui sera extrait dans le bundle. image doit être un
chemin vers une image OCI valide et tag doit être un tag valide dans l'image. Si
tag n'est pas fourni, il est par défaut "latest".

--rootless
Active la prise en charge de la décompression sans privilèges root. Cela permet
d'utiliser umoci-unpack(1) et umoci-repack(1) en tant qu'utilisateur non privilégié. L'utilisation de cette option
implique --uid-map=0:$(id -u):1 et --gid-map=0:$(id -g):1, ainsi que
l'activation de plusieurs fonctionnalités pour simuler certaines parties de la
décompression afin de tenter de générer une extraction du système de fichiers
aussi proche que possible. Notez qu'il est presque toujours impossible d'extraire
parfaitement une image OCI avec --rootless, mais le résultat sera aussi
proche que possible.

--uid-map=valeur
Spécifie un mappage UID à utiliser pendant la décompression (et la recom-
pression) des couches. Ceci est utilisé de manière similaire à user_namespaces(7), et est de la forme
container:host[:taille].

--gid-map=valeur
Spécifie un mappage GID à utiliser pendant la décompression (et la recom-
pression) des couches. Ceci est utilisé de manière similaire à user_namespaces(7), et est de la forme
container:host[:taille].

--keep-dirlinks
Au lieu d'écraser les répertoires qui sont des liens vers d'autres répertoires
lorsque les couches supérieures ont un répertoire explicite, écrire simplement à
travers le lien symbolique. Cette option est inspirée de l'option de rsync(1) portant le même nom.

EXEMPLE

Ce qui suit télécharge une image d'un registre docker(1) en utilisant skopeo(1), décompresse ladite image puis crée un nouveau conteneur en utilisant le bundle runtime OCI extrait avec runc(8). Ensuite, l'image est recomprimée avec umoci-repack(1).

% skopeo copy docker://opensuse/amd64:42.2 oci:image:latest
# umoci unpack --image image bundle
# runc run -b bundle ctr
[ session de conteneur ]
# umoci repack --image image bundle

Avec --rootless, il est également possible de réaliser l'exemple ci-dessus sans privilèges root. umoci générera une configuration qui fonctionne avec les conteneurs sans privilèges root dans runc(8).

% skopeo copy docker://opensuse/amd64:42.2 oci:image:latest
% umoci unpack --image image --rootless bundle
% runc --root $HOME/runc run -b bundle ctr
[ session de conteneur sans privilèges root ]
% umoci repack --image image --rootless bundle
