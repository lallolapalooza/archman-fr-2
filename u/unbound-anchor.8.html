NOM

unbound-anchor - Utilitaire d'ancre Unbound 1.24.2.

SYNTAXE

unbound-anchor [options]

DESCRIPTION

unbound-anchor effectue la configuration ou la mise à jour de l'ancre de confiance racine pour la validation DNSSEC. Le programme récupère l'ancre de confiance avec la méthode de la RFC 7958 lorsque la mise à jour régulière de la RFC 5011 échoue à la maintenir à jour. Il peut être exécuté (en tant que root) depuis la ligne de commande, ou dans le cadre des scripts de démarrage. Avant de démarrer le serveur DNS unbound(8).

Utilisation suggérée :

# dans les scripts d'init.
# fournir ou mettre à jour l'ancre racine (si nécessaire)
unbound-anchor -a "/etc/trusted-key.key"
# Veuillez noter que l'utilisation de cette ancre racine se fait à vos propres risques
# et selon les termes de notre LICENCE (voir source).
#
# démarrer le résolveur de validation
# unbound.conf contient:
# auto-trust-anchor-file: "/etc/trusted-key.key"
unbound -c unbound.conf

Cet outil fournit un contenu par défaut intégré pour les fichiers d'ancre racine et de certificat de mise à jour racine.

Il teste si le fichier d'ancre racine fonctionne, et sinon, et si une mise à jour est possible, il tente de mettre à jour l'ancre racine en utilisant le certificat de mise à jour racine. Il effectue une requête HTTPS pour root-anchors.xml et vérifie les résultats (RFC 7958) ; si toutes les vérifications sont réussies, il met à jour le fichier d'ancre racine. Sinon, le fichier d'ancre racine reste inchangé. Il effectue le suivi de la RFC 5011 si les informations DNSSEC disponibles via le DNS le permettent.

Il n'effectue pas de mise à jour si le certificat est expiré, si le réseau est en panne ou si d'autres erreurs surviennent.

Les options disponibles sont :

-a <fichier>
Le fichier clé d'ancre racine, qui est lu et écrit. Par défaut, c'est /etc/trusted-key.key. Si le fichier n'existe pas, ou s'il est vide, une clé racine intégrée y est écrite.
-c <fichier>
Le fichier de certificat de mise à jour racine, qui est lu. Par défaut, c'est /etc/unbound/icannbundle.pem. Si le fichier n'existe pas, ou s'il est vide, un certificat intégré est utilisé.
-l
Liste la clé racine intégrée et le certificat de mise à jour racine intégré sur la sortie standard.
-u <nom>
Le nom du serveur, il se connecte à https://name. Spécifier sans le préfixe https://. Par défaut, c'est "data.iana.org". Il se connecte au port spécifié avec -P. Vous pouvez passer une adresse IPv4 ou IPv6 (sans crochets) si vous le souhaitez.
-S
N'utilise pas SNI pour la connexion HTTPS. Par défaut, il utilise SNI.
-b <adresse>
L'adresse source à lier pour la résolution de domaine et le contact du serveur sur https. Peut être une adresse IPv4 ou IPv6 (sans crochets).
-x <chemin>
Le nom du chemin vers le fichier root-anchors.xml sur le serveur. (forme l'URL avec -u). Par défaut, c'est /root-anchors/root-anchors.xml.
-s <chemin>
Le nom du chemin vers le fichier root-anchors.p7s sur le serveur. (forme l'URL avec -u). Par défaut, c'est /root-anchors/root-anchors.p7s. Ce fichier doit être une signature PKCS7 sur le fichier xml, en utilisant le fichier pem (-c) comme ancre de confiance.
-n <nom>
L'adresse e-mail pour le sujet du certificat du signataire du fichier p7s. Seules les signatures de ce nom sont autorisées. Par défaut, c'est dnssec@iana.org. Si vous passez "", l'adresse e-mail n'est pas vérifiée.
-4
Utilise IPv4 pour la résolution de domaine et le contact du serveur sur https. Par défaut, utilise IPv4 et IPv6 le cas échéant.
-6
Utilise IPv6 pour la résolution de domaine et le contact du serveur sur https. Par défaut, utilise IPv4 et IPv6 le cas échéant.
-f <resolv.conf>
Utilise le fichier resolv.conf donné. Non activé par défaut, mais vous pourriez essayer de passer /etc/resolv.conf sur certains systèmes. Il contient les adresses IP des serveurs de noms récursifs à utiliser. Cependant, comme cet outil pourrait être utilisé pour amorcer ce serveur de noms récursifs, il ne serait pas utile (car ce serveur n'est pas encore démarré, puisque nous l'amorçons). Il pourrait être utile dans une situation où vous savez qu'un cache en amont est déployé (et en cours d'exécution) et dans des situations de portail captif.
-r <root.hints>
Utilise le fichier root.hints donné (même syntaxe que le fichier root hints de BIND et Unbound) pour amorcer la résolution de domaine. Par défaut, une liste d'amorces racines intégrées est utilisée. unbound-anchor va sur le réseau lui-même pour ces racines, afin de résoudre le serveur (option -u) et de vérifier les enregistrements DNSKEY racine. Il le fait car l'outil, lorsqu'il est utilisé pour amorcer le résolveur récursif, ne peut pas utiliser ce résolveur récursif lui-même car il est en train de l'amorcer.
-R
Permet le repli depuis le fichier -f <resolv.conf> vers une requête directe des serveurs racines. Il vous permet de préférer les résolveurs locaux, mais de revenir automatiquement à une requête racine directe s'ils ne répondent pas ou ne prennent pas en charge DNSSEC.
-v
Plus verbeux. Une fois imprime des messages informatifs, plusieurs fois peu activer de grandes quantités de débogage (comme des certificats complets ou des dumps d'octets de fichiers téléchargés). Par défaut, il n'imprime presque rien. Il n'imprime rien non plus en cas d'erreur par défaut ; dans ce cas, le fichier d'ancre racine d'origine est simplement laissé intact, afin qu'un serveur récursif puisse démarrer juste après.
-C <unbound.conf>
Option de débogage pour lire <unbound.conf> dans le processus résolveur utilisé.
-P <port>
Définit le numéro de port à utiliser pour la connexion https. Par défaut, c'est 443.
-F
Option de débogage pour forcer la mise à jour de l'ancre racine en téléchargeant le fichier xml et en le vérifiant avec le certificat. Par défaut, il essaie d'abord de mettre à jour en contactant le DNS, ce qui utilise beaucoup moins de bande passante, est beaucoup plus rapide (200 ms au lieu de 2 secondes), et est plus respectueux de l'infrastructure déployée. Avec cette option, il essaie toujours de le faire (et peut vous le dire de manière verbeuse), mais ignore ensuite le résultat et utilise la méthode de repli xml.
-h
Affiche la version et l'aide des options de la ligne de commande.

CODE DE RET OUR

Cet outil renvoie la valeur 1 si l'ancre racine a été mise à jour en utilisant le certificat ou si l'ancre racine intégrée a été utilisée. Il renvoie le code 0 si aucune mise à jour n'était nécessaire, si la mise à jour était possible avec le suivi RFC 5011, ou si une erreur s'est produite.

Vous pouvez vérifier la valeur de retour de cette manière :

unbound-anchor -a "root.key" || logger "Veuillez vérifier root.key"

Ou quelque chose de plus adapté à votre environnement opérationnel.

NAME

unbound-anchor

get and install the root trust anchor for validating DNSSEC data

SYNOPSIS

unbound-anchor[-l] [-v] [-a anchorfile] [-c certfile] [-d] [-f rootfile] [-h] [-H host] [-i] [-I interface] [-p port] [-r] [-s server] [-S domain] [-u] [-U rootkeyfile]

DESCRIPTION

The DNSSEC root trust anchor is needed to validate DNSSEC data up to the root zone. This trust anchor consists of the public key of the root zone's DNSKEY record. Without it, DNSSEC validation cannot be performed.

This tool downloads and installs the root trust anchor for use by unbound(8).

The tool fetches the root key from the IANA (Internet Assigned Numbers Authority) and stores it in /etc/trusted-key.key. It can also download a trusted certificate, icannbundle.pem, to verify the authenticity of the downloaded key.

The program prints its progress to stderr and may print the updated key information to stdout.

To enable DNSSEC validation, you need to configure unbound.conf(5) with dnssec-enable: yes.

EXIT CODE

0 on success, 1 on failure.

TRUST

The certificate included in this tool are provided for convenience and under the terms of our license (see the LICENSE file in the source distribution or https://github.com/NLnetLabs/unbound/blob/master/LICENSE and might be stale or not suitable to your purpose.

By running unbound-anchor -l the keys and certificate that are configured in the code are printed for your convenience.

The built-in configuration can be overridden by providing a root-cert file and a rootkey file.

FILES

/etc/trusted-key.key
The root anchor file, updated with 5011 tracking, and read and written to. The file is created if it does not exist.
/etc/unbound/icannbundle.pem
The trusted self-signed certificate that is used to verify the downloaded DNSSEC root trust anchor. You can update it by fetching it from https://data.iana.org/root-anchors/icannbundle.pem (and validate it). If the file does not exist or is empty, a builtin version is used.
https://data.iana.org/root-anchors/root-anchors.xml
Source for the root key information.
https://data.iana.org/root-anchors/root-anchors.p7s
Signature on the root key information.
