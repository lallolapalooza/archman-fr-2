ULIMIT(3P) Manuel du programmeur POSIX ULIMIT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ulimit — obtenir et définir les limites du processus

SYNTAXE

#include <ulimit.h>
long ulimit(int cmd, ...);

DESCRIPTION

La fonction ulimit() contrôle les limites du processus. Les limites de processus qui peuvent être contrôlées par cette fonction incluent la taille maximale d'un seul fichier qui peut être écrit (ceci est équivalent à l'utilisation de setrlimit() avec RLIMIT_FSIZE). Les valeurs de cmd, définies dans <ulimit.h>, incluent :

UL_GETFSIZE
Retourne la limite de taille de fichier (RLIMIT_FSIZE) du processus. La limite est en unités de blocs de 512 octets et est héritée par les processus enfants. Les fichiers de toute taille peuvent être lus. La valeur de retour est la partie entière de la limite de taille de fichier souple divisée par 512. Si le résultat ne peut pas être représenté par un long, le résultat est indéfini.
UL_SETFSIZE
Définit la limite de taille de fichier pour les opérations de sortie du processus à la valeur du deuxième argument, prise comme un long, multipliée par 512. Si le résultat déborde un rlim_t, la valeur réelle définie est indéfinie. Tout processus peut diminuer sa propre limite, mais seul un processus ayant les privilèges appropriés peut augmenter la limite. La valeur de retour est la partie entière de la nouvelle limite de taille de fichier divisée par 512.

La fonction ulimit() ne modifie pas le réglage de errno en cas de succès.

Comme toutes les valeurs de retour sont permises dans une situation de succès, une application souhaitant vérifier les situations d'erreur doit définir errno à 0, appeler ensuite ulimit(), et, si elle retourne -1, vérifier si errno est non nul.

VALEUR DE RETOUR

En cas de succès, ulimit() retourne la valeur de la limite demandée. Sinon, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

La fonction ulimit() échoue et la limite n'est pas modifiée si :

EINVAL
L'argument cmd n'est pas valide.
EPERM
Un processus n'ayant pas les privilèges appropriés tente d'augmenter sa limite de taille de fichier.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

Étant donné que la fonction ulimit() utilise le type long plutôt que rlim_t, cette fonction n'est pas suffisante pour les tailles de fichiers sur de nombreux systèmes actuels. Les applications devraient utiliser les fonctions getrlimit() ou setrlimit() à la place de la fonction obsolète ulimit().

RATIONALE

Aucun.

ORIENTATIONS FUTURES

La fonction ulimit() pourrait être supprimée dans une future version.
