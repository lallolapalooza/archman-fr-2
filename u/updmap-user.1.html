UPDMAP(1) Commandes utilisateur UPDMAP(1)

NOM

updmap - gérer les cartes de polices TeX
updmap-sys - gérer les cartes de polices TeX, au niveau du système
updmap-user - gérer les cartes de polices TeX, par utilisateur

SYNTAXE

updmap [-user|-sys] [OPTION] ... [COMMANDE]
updmap-user [OPTION] ... [COMMANDE]
updmap-sys [OPTION] ... [COMMANDE]

DESCRIPTION

updmap version r65932 (2023-02-19 21:49:48 +0100)

Met à jour les fichiers de cartes de polices par défaut utilisés par pdftex et dvipdfm(x) (pdftex.map), dvips (psfonts.map), et optionnellement pxdvi, tels que déterminés par tous les fichiers de configuration updmap.cfg (généralement ceux renvoyés par l'exécution de "kpsewhich --all updmap.cfg", mais voir ci-dessous).

Entre autres choses, ces fichiers de cartes sont utilisés pour déterminer quelles polices doivent être utilisées comme bitmaps et lesquelles comme contours, et pour déterminer quels fichiers de polices sont inclus, typiquement sous-segmentés, dans la sortie PDF ou PostScript.

updmap-sys (ou updmap -sys) est destiné à affecter la configuration globale du système, tandis que updmap-user (ou updmap -user) affecte uniquement les fichiers de configuration personnels, remplaçant les fichiers système.

En conséquence, une fois qu'updmap-user a été exécuté, même une seule fois, l'exécution d'updmap-sys n'a plus d'effet. updmap-sys émet un avertissement à ce sujet, car c'est rarement souhaitable. Voir https://tug.org/texlive/scripts-sys-user.html pour plus de détails.

Par défaut, la base de données des noms de fichiers TeX (ls-R) est également mise à jour.

Le système updmap est malheureusement compliqué, pour des raisons inhérentes et historiques. Aperçu général :

- Les fichiers updmap.cfg concernent principalement la liste d'autres fichiers, à savoir les

cartes spécifiques aux polices .maps, dans lesquelles chaque ligne donne des informations sur une police TeX (.tfm) différente.

- updmap lit les fichiers updmap.cfg et concatène ensuite les

contenus de ces fichiers .map dans les fichiers de sortie principaux : psfonts.map pour dvips et pdftex.map pour pdftex et dvipdfmx.

- Les fichiers updmap.cfg eux-mêmes sont créés et mis à jour lors de l'installation des paquets

par l'installateur système, le gestionnaire de paquets ou manuellement, et non (par défaut) par updmap.

La sortie principale :

La sortie principale d'updmap est constituée des fichiers contenant les lignes individuelles des cartes de polices que les pilotes (dvips, pdftex, etc.) lisent pour gérer les polices.
Les fichiers de cartes pour dvips (psfonts.map) et pdftex et dvipdfmx (pdftex.map) sont écrits dans TEXMFVAR/fonts/map/updmap/{dvips,pdftex}/.
De plus, les informations sur les polices Kanji sont écrites dans TEXMFVAR/fonts/map/updmap/dvipdfmx/kanjix.map, et optionnellement dans TEXMFVAR/fonts/map/updmap/pxdvi/xdvi-ptex.map. Celles-ci concernent les polices Kanji uniquement et ne sont pas comme les autres fichiers de cartes. dvipdfmx lit pdftex.map pour les entrées de carte des polices non Kanji.
Si aucune option n'est donnée, donc l'invocation est juste "updmap-user" ou "updmap-sys", ces fichiers de sortie sont toujours recréés.
Sinon, si une option comme --enable ou --disable est donnée, les fichiers de sortie sont recréés si la liste des cartes activées (depuis updmap.cfg) a changé. L'option --force outrepasser cela, recréant toujours les fichiers de sortie.

Explication des types de cartes :

Le type normal est Map.
La seule différence entre Map et MixedMap est que les entrées MixedMap ne sont pas ajoutées à psfonts_pk.map. Le but est d'aider les utilisateurs dont les périphériques rendent les polices de contours Type 1 moins bien que les polices bitmaps Type 3 réglées selon le mode. Ainsi, MixedMap est utilisé pour les polices disponibles à la fois en Type 1 et Metafont.
Les entrées KanjiMap sont ajoutées à psfonts_t1.map et kanjix.map.

Ces options ne sont lues et traitées que par updmap ; dvips, pdftex, etc., ne les connaissent pas. Elles fonctionnent en changeant le fichier de mappage par défaut que les programmes lisent, elles peuvent donc être remplacées en spécifiant des options en ligne de commande ou des fichiers de configuration aux programmes, comme expliqué au début de updmap.cfg.
Les options jaEmbed et jaVariant (anciennement kanjiEmbed et kanjiVariant) spécifient des remplacements spéciaux dans les lignes de mappage. Si un mappage contient la chaîne @jaEmbed@, celle-ci sera remplacée par la valeur de cette option ; de même pour jaVariant. Ainsi, les utilisateurs de TeX japonais peuvent sélectionner différentes polices à inclure dans la sortie finale. Les équivalents pour les polices simplifiées chinoises, traditionnelles chinoises et coréennes sont respectivement scEmbed, tcEmbed et koEmbed.

ENVIRONNEMENT

Explication des arbres et fichiers normalement utilisés :

Si --cnffile est spécifié sur la ligne de commande (peut être donné plusieurs fois), sa(ses) valeur(s) est(sont) utilisée(s). Sinon, updmap lit tous les fichiers updmap.cfg trouvés en exécutant `kpsewhich -all updmap.cfg', dans l'ordre retourné par kpsewhich (qui est l'ordre des arbres définis dans texmf.cnf).
Dans les deux cas, si plusieurs fichiers updmap.cfg sont trouvés, toutes les cartes mentionnées dans tous les fichiers updmap.cfg sont fusionnées.
Ainsi, si des fichiers updmap.cfg sont présents dans tous les arbres, et que la disposition par défaut est utilisée telle qu'expédiée avec TeX Live, les fichiers suivants sont lus, dans l'ordre donné.
Pour updmap-sys :
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
Pour updmap-user :
TEXMFCONFIG    $HOME/.texliveYYYY/texmf-config/web2c/updmap.cfg
TEXMFVAR       $HOME/.texliveYYYY/texmf-var/web2c/updmap.cfg
TEXMFHOME      $HOME/texmf/web2c/updmap.cfg
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
(où YYYY est la version de la distribution TeX Live).
Selon les actions, updmap peut écrire dans l'un des fichiers donnés ou créer un nouveau updmap.cfg, décrit plus loin.

Où et quelles modifications de updmap.cfg sont sauvegardées :

Quand aucune option n'est donnée, les fichiers updmap.cfg sont seulement lus, pas écrits. C'est lorsqu'une option --setoption, --enable ou --disable est spécifiée qu'un updmap.cfg doit être mis à jour. Dans ce cas :
1) Si des fichiers de configuration sont donnés sur la ligne de commande, alors le premier donné est utilisé pour sauvegarder de telles modifications.
2) Si les fichiers de configuration sont extraits de la sortie de kpsewhich, alors l'algorithme est plus complexe :
2a) Si $TEXMFCONFIG/web2c/updmap.cfg ou $TEXMFHOME/web2c/updmap.cfg apparaît dans la liste des fichiers utilisés, alors celui listé en premier par kpsewhich --all (équivalent à celui retourné par kpsewhich updmap.cfg), est utilisé.
2b) Si ni l'un ni l'autre des deux ci-dessus ne sont présents et que des modifications sont apportées, un nouveau fichier de configuration est créé dans $TEXMFCONFIG/web2c/updmap.cfg.
En général, l'idée est que si l'utilisateur ne peut pas écrire dans un fichier de configuration donné, un fichier de niveau supérieur peut être utilisé. Ainsi, les paramètres de la distribution peuvent être remplacés globalement en utilisant TEXMFLOCAL, et les paramètres système peuvent être remplacés à nouveau dans TEXMFHOME ou TEXMFCONFIG d'un utilisateur particulier.

Résolution des définitions multiples d'une police :

Si une police est définie dans plus d'un fichier de mappage, alors la définition provenant du premier fichier updmap.cfg listé est utilisée. Si une police est définie plusieurs fois dans le même fichier de mappage, une est choisie arbitrairement. Dans les deux cas, un avertissement est émis.

Désactivation des mappages :

Les fichiers updmap.cfg avec une priorité plus élevée (listés plus tôt) peuvent désactiver les mappages mentionnés dans les fichiers updmap.cfg de priorité inférieure (listés plus tard) en écrivant, par exemple,
#! Map nom_mappage.map
ou
#! MixedMap nom_mappage.map
dans le fichier updmap.cfg de priorité plus élevée.
(Le #! doit être au
début de la ligne, avec au moins un espace ou une tabulation après, et des espaces entre chaque mot de la liste.)
Par exemple, supposons que vous ayez une copie des polices MathTime Pro et que vous souhaitiez désactiver la version Belleek des polices ; c'est-à-dire, désactiver le mappage belleek.map. Vous pouvez créer le fichier $TEXMFCONFIG/web2c/updmap.cfg avec le contenu
#! Map belleek.map Map mt-plus.map Map mt-yy.map
et appeler updmap.

Liste des mappages :

Les deux options --listmaps et --listavailablemaps listent toutes les cartes définies dans n'importe lequel des fichiers updmap.cfg (pour --listmaps), et seulement celles effectivement trouvées sur le système (pour --listavailablemaps). La sortie est une ligne par carte de polices, avec les champs suivants séparés par des tabulations : mappage, type (Map, MixedMap, KanjiMap), statut (activé, désactivé), origine (le fichier updmap.cfg où il est mentionné, ou 'builtin' pour les trois cartes de base).
Dans le cas de --listmaps, il peut y avoir un champ supplémentaire (également séparé par une tabulation) contenant '(non disponible)' pour les fichiers de mappage qui ne peuvent pas être trouvés.

updmap-user vs. updmap-sys :

Lorsque updmap-sys est exécuté, TEXMFSYSCONFIG et TEXMFSYSVAR sont utilisés à la place de TEXMFCONFIG et TEXMFVAR, respectivement. C'est la principale différence entre updmap-sys et updmap-user.
D'autres emplacements peuvent être utilisés si vous les spécifiez sur la ligne de commande, ou si ces arbres n'existent pas, ou si vous n'utilisez pas la distribution TeX Live d'origine.

Pour voir les emplacements précis des divers fichiers qui seront lus et écrits, donnez l'option -n (ou lisez la source).

NAME

updmap-user - make map files for use with TeX fonts (user-specific configuration)

SYNOPSIS

updmap-user [ --help | --version ] [ --verbose ] [ --showconfig ] [ --enable-feature FEATURE | --disable-feature FEATURE ] [ --force ] [ --sync-file FILE ] [ --remove FILE ] [ --list-files ] [ --admin-only ]

DESCRIPTION

The updmap-user script is a front-end to the TeX font map file generation system. This version is for user-specific configuration. It is intended to be run by the user, not as root.

The primary purpose of updmap-user is to set up font map files for use with various TeX engines, specifically for fonts that are not part of the standard TeX distribution, and to enable or disable support for specific font features.

When updmap-user is run, it takes the user's configuration settings and uses them to generate or update font map files (e.g., `psfonts.map`, `pdftex.map`) in the user's personal TeX directory tree. These map files tell TeX how to find and use specific fonts.

Supported features can be listed using `--showconfig`.

A list of standard configuration files and the map files they include can be found in the output of `updmap-user --showconfig`.

OPTIONS

--help
Print a short help message and exit.
--version
Print version information and exit.
--verbose
Print detailed information about the operations being performed.
--showconfig
Print the current configuration settings, including enabled/disabled features and the map files that are included by default. This is useful for understanding how updmap is configured and what options are available.
--enable-feature FEATURE
Enable a specific font feature. This might involve activating a particular set of fonts or a specific font encoding. The available features can be seen with `--showconfig`.
--disable-feature FEATURE
Disable a specific font feature.
--force
Forces regeneration of all map files, even if no changes are detected.
--sync-file FILE
Specifies a file to be synchronized. This is typically a font map file that updmap needs to process or update.
--remove FILE
Removes the specified font map file from the user's TeX directory tree.
--list-files
Lists all the font map files that are currently in use or generated by updmap-user.
--admin-only
This option is typically used by the system administrator (`updmap.conf`) and is not generally intended for user use.

ENVIRONMENT

Information about relevant environment variables can be found in the documentation for `texmf.cnf` and related TeX configuration files.

EXAMPLES

To see the current configuration:

$ updmap-user --showconfig

To enable the `pdftex` feature (which usually ensures standard 14 PDF fonts are available):

$ updmap-user --enable-feature pdftex

To regenerate all user map files:

$ updmap-user --force

FILES

The following are some of the font map files that might be generated or manipulated by updmap-user:

psfonts.map
The default map file for PostScript fonts. This file is usually generated by default and contains mappings for standard PostScript fonts.
download35.map
A map file that instructs TeX to download the 35 standard PostScript fonts if they are not found locally. This is often used when creating PostScript output.
builtin35.map
Similar to download35.map, but might use built-in versions of the standard 35 fonts if available.
psfonts_t1.map
A map file specifically for Type 1 PostScript fonts, often used for high-quality output and PDF generation.
psfonts_pk.map
A map file for PK (packed) fonts, typically used with older versions of TeX or for specific purposes.
pdftex_dl14.map
For pdftex(1). Always downloads the standard 14 fonts.
pdftex_ndl14.map
For pdftex(1). Never downloads the standard 14 fonts.
ps2pk.map
Similar to psfonts.map file, but forces all fonts to be downloaded, so this map file can be used with xdvi(1) and ps2pk(1).

Configuration files for dvips(1):

config.builtin35
Loads builtin35.map instead of psfonts.map.
config.download35
Loads download35.map instead of psfonts.map.
config.outline
Loads psfonts_t1.map instead of psfonts.map.
config.pdf
Loads psfonts_t1.map instead of psfonts.map and has additional settings for PDF generation.
config.pk
Loads psfonts_pk.map instead of psfonts.map.
config.www
Loads psfonts_t1.map instead of psfonts.map. (For compatibility with old versions.)
config.gstopk
Loads psfonts_t1.map instead of psfonts.map.
