NOM

usbguard - Interface en ligne de commande de USBGuard

SYNTAXE

usbguard [OPTIONS] <sous-commande> [OPTIONS-DE-SOUS-COMMANDE] ...

usbguard get-parameter nom

usbguard set-parameter nom valeur

usbguard list-devices

usbguard allow-device id | règle | règle-partielle

usbguard block-device id | règle | règle-partielle

usbguard reject-device id | règle | règle-partielle

usbguard list-rules

usbguard append-rule règle

usbguard remove-rule id

usbguard generate-policy

usbguard watch

usbguard read-descriptor fichier

usbguard add-user nom

usbguard remove-user nom

DESCRIPTION

La commande usbguard fournit une interface en ligne de commande (CLI) à une instance en cours d'exécution de usbguard-daemon(8). Elle fournit également un outil pour générer des politiques USBGuard initiales basées sur les périphériques USB connectés au système.

SOUS-COMMANDES

get-parameter [OPTIONS] nom

Obtenir la valeur d'un paramètre d'exécution. Le paramètre nom est soit InsertedDevicePolicy, soit ImplicitPolicyTarget.

Options disponibles :

-h, --help

Afficher l'aide.

set-parameter [OPTIONS] nom valeur

Définir la valeur d'un paramètre d'exécution. Le paramètre nom est soit InsertedDevicePolicy, soit ImplicitPolicyTarget.

Options disponibles :

-v, --verbose

Afficher la valeur précédente et la nouvelle valeur de l'attribut.

-h, --help

Afficher l'aide.

list-devices [OPTIONS]

Lister tous les périphériques USB reconnus par le démon USBGuard.

Options disponibles :

-a, --allowed

Lister les périphériques autorisés.

-b, --blocked

Lister les périphériques bloqués.

-t, --tree

Lister les périphériques au format arborescent.

-h, --help

Afficher l'aide.

allow-device [OPTIONS] < id | règle | règle-partielle >

Autoriser un périphérique à interagir avec le système. Le périphérique peut être identifié par un id de périphérique, une règle ou une règle-partielle (règle sans cible). Les règles et règles-partielles peuvent être utilisées pour autoriser plusieurs périphériques à la fois. Notez que id fait référence à l'ID interne de la règle du périphérique (le tout premier numéro de la sortie de la commande list-devices) plutôt qu'à l'attribut ID du périphérique.

Options disponibles :

-p, --permanent

Rendre la décision permanente. Une règle d'autorisation spécifique au périphérique sera ajoutée à la politique actuelle.

-h, --help

Afficher l'aide.

block-device [OPTIONS] < id | règle | règle-partielle >

Désautoriser un périphérique. Le périphérique peut être identifié par un id de périphérique, une règle ou une règle-partielle (règle sans cible). Les règles et règles-partielles peuvent être utilisées pour bloquer plusieurs périphériques à la fois. Notez que id fait référence à l'ID interne de la règle du périphérique (le tout premier numéro de la sortie de la commande list-devices) plutôt qu'à l'attribut ID du périphérique.

Options disponibles :

-p, --permanent

Rendre la décision permanente. Une règle de blocage spécifique au périphérique sera ajoutée à la politique actuelle.

-h, --help

Afficher l'aide.

reject-device [OPTIONS] < id | règle | règle-partielle >

Désautoriser et supprimer un périphérique. Le périphérique peut être identifié par un id de périphérique, une règle ou une règle-partielle (règle sans cible). Les règles et règles-partielles peuvent être utilisées pour rejeter plusieurs périphériques à la fois. Notez que id fait référence à l'ID interne de la règle du périphérique (le tout premier numéro de la sortie de la commande list-devices) plutôt qu'à l'attribut ID du périphérique.

Options disponibles :

-p, --permanent

Rendre la décision permanente. Une règle de rejet spécifique au périphérique sera ajoutée à la politique actuelle.

-h, --help

Afficher l'aide.

list-rules [OPTIONS]

Lister l'ensemble des règles (politique) utilisé par le démon USBGuard.

Options disponibles :

-d, --show-devices

Afficher tous les périphériques affectés par la règle spécifique.

-l, --label étiquette

N'afficher que les règles ayant une étiquette spécifique.

-h, --help

Afficher l'aide.

append-rule [OPTIONS] règle

Ajouter la règle à l'ensemble de règles actuel.

Options disponibles :

-a, --after id

Ajouter la nouvelle règle après une règle avec l'id de règle spécifié.

-t, --temporary

Rendre la décision temporaire. Le fichier de politique de règle ne sera pas mis à jour.

-h, --help

Afficher l'aide.

remove-rule [OPTIONS] id

Supprimer une règle identifiée par son id de l'ensemble de règles.

Options disponibles :

-h, --help

Afficher l'aide.

generate-policy [OPTIONS]

Générer un ensemble de règles (politique) qui autorise les périphériques USB actuellement connectés.

Options disponibles :

-p, --with-ports

Générer des règles spécifiques aux ports pour tous les périphériques. Par défaut, des règles spécifiques aux ports ne sont générées que pour les périphériques qui n'exportent pas de valeur iSerial.

-P, --no-ports-sn

Ne pas générer de règles spécifiques aux ports pour les périphériques sans valeur iSerial. Sans cette option, l'outil ajoutera un attribut via-port à tout périphérique qui ne fournit pas de numéro de série. Ceci est une mesure de sécurité pour limiter les périphériques qui ne peuvent pas être identifiés de manière unique à ne se connecter que via un port spécifique. Cela rend plus difficile de contourner la politique car le périphérique réel occupera le port USB autorisé la plupart du temps.

-d, --devpath devpath

Générer une règle uniquement pour le périphérique situé au sous-chemin spécifié de

NOM

usbguard - outil en ligne de commande pour configurer et contrôler le démon USBGuard.

SYNOPSIS

usbguard SUBCOMMAND [OPTIONS]

DESCRIPTION

Cet outil permet aux utilisateurs d'interagir avec le démon usbguard(8) et d'ajuster la politique de sécurité USB. Il peut être utilisé pour :

  • Générer des règles de politique
  • Autoriser, bloquer ou rejeter des périphériques USB
  • Surveiller les événements de l'interface IPC
  • Lire des descripteurs USB
  • Gérer les autorisations d'accès IPC pour les utilisateurs/groupes

SOUS-COMMANDES

générer-politique [OPTIONS]

Générer un ensemble de règles de politique initiales. Par défaut, il est généré pour tous les périphériques USB connectés.

Options disponibles :

-c, --connection connection

Générer une politique pour la connexion spécifiée. Les valeurs possibles sont : usb, sys.

-t, --cible cible

Générer une règle explicite "catch all" avec la cible spécifiée. La cible peut être l'une des valeurs suivantes : autoriser, bloquer, rejeter

-X, --sans-hash

Ne pas générer d'attribut hash pour chaque périphérique.

-H, --hash-seulement

Générer une politique uniquement basée sur les hashes.

-L, --ldif

Générer une politique ldif pour LDAP.

-b, --base-usbguard base

Générer une politique ldif pour LDAP avec cette base. Cette option est requise lorsque --ldif a été spécifié.

-o, --objetclasse classeObjet

Générer une politique ldif pour LDAP avec cette classe d'objet.

-n, --préfixe-nom préfixe

Générer une politique ldif pour LDAP avec ce préfixe de nom.

-h, --aide

Afficher l'aide.

surveiller [OPTIONS]

Surveiller les événements de l'interface IPC et les imprimer sur stdout.

Options disponibles :

-w, --attendre

Attendre que la connexion IPC soit disponible.

-o, --une-fois

Attendre uniquement au démarrage, si nécessaire. Quitter lorsque la connexion est perdue.

-e, --exécuter chemin

Exécuter un fichier exécutable situé à chemin pour chaque événement. Passer les données de l'événement au processus via les variables d'environnement.

-h, --aide

Afficher l'aide.

lire-descripteur [OPTIONS] fichier

Lire un descripteur USB à partir d'un fichier et l'afficher sous une forme lisible par l'homme.

Options disponibles :

-h, --aide

Afficher l'aide.

ajouter-utilisateur nom [OPTIONS]

Créer un fichier de contrôle d'accès IPC autorisant l'utilisateur/groupe identifié par nom à utiliser le bus IPC d'USBGuard. Le changement prend effet uniquement après le redémarrage de l'instance de usbguard-daemon(8).

Options disponibles :

-u, --utilisateur

Le nom spécifié représente un nom d'utilisateur ou un UID (par défaut).

-g, --groupe

Le nom spécifié représente un nom de groupe ou un GID.

-p, --politique privilèges

Privilèges liés à la politique.

-d, --périphériques privilèges

Privilèges liés aux périphériques.

-e, --exceptions privilèges

Privilèges liés aux exceptions.

-P, --paramètres privilèges

Privilèges liés aux paramètres d'exécution.

-h, --aide

Afficher l'aide.

Privilèges :

Les privilèges sont attendus sous la forme d'une liste séparée par deux-points :

    $ sudo usbguard add-user joe --devices=listen,modify

Consultez la page de manuel de usbguard-daemon.conf(5) pour une liste détaillée des privilèges disponibles dans chaque section. Vous pouvez également utiliser ALL à la place de privilèges pour attribuer automatiquement tous les privilèges pertinents à une section donnée.

supprimer-utilisateur nom [OPTIONS]

Supprimer un fichier de contrôle d'accès IPC associé à l'utilisateur/groupe identifié par nom. Le changement prend effet uniquement après le redémarrage de l'instance de usbguard-daemon(8).

Options disponibles :

-u, --utilisateur

Le nom spécifié représente un nom d'utilisateur ou un UID (par défaut).

-g, --groupe

Le nom spécifié représente un nom de groupe ou un GID.

-h, --aide

Afficher l'aide.

EXEMPLES

Génération d'une politique initiale :

    $ sudo usbguard générer-politique > rules.conf
    $ vi rules.conf
    (revoir/modifier l'ensemble des règles)
    $ sudo install -m 0600 -o root -g root rules.conf /etc/usbguard/rules.conf
    $ sudo systemctl restart usbguard

Autoriser un ou plusieurs périphériques :

    # Autoriser un périphérique par ID (c'est le tout premier numéro issu de la sortie de la commande list-devices)
    $ sudo usbguard autoriser-périphérique 10
    # Autoriser tous les périphériques nommés "Dell Wired Multimedia Keyboard"
    $ sudo usbguard autoriser-périphérique nom \"Dell Wired Multimedia Keyboard\"
