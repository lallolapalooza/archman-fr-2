NOM

unicharambigs - Ambiguïtés d'unicharset de Tesseract

DESCRIPTION

Le fichier unicharambigs (un composant de traineddata, voir combine_tessdata(1) ) est utilisé par Tesseract pour représenter les ambiguïtés possibles entre caractères, ou groupes de caractères.

Le fichier contient un certain nombre de lignes, disposées comme suit :

[nombre] <TAB> [caractère(s)] <TAB> [nombre] <TAB> [caractère(s)] <TAB> [nombre]
Champ un le nombre de caractères contenus dans le champ deux
Champ deux la séquence de caractères à remplacer
Champ trois le nombre de caractères contenus dans le champ quatre
Champ quatre la séquence de caractères utilisée pour remplacer le champ deux
Champ cinq contient soit 1, soit 0. 1 indique un remplacement obligatoire, 0 indique un remplacement optionnel.

Les caractères apparaissant dans les champs deux et quatre doivent apparaître dans l'unicharset. Les nombres dans les champs un et trois font référence au nombre d'unichars (pas d'octets).

EXEMPLE

v1
2       ' '     1       "     1
1       m       2       r n   0
3       i i i   1       m     0

La première ligne est un identifiant de version. Dans cet exemple, toutes les instances de la séquence de 2 caractères '' seront toujours remplacées par la séquence de 1 caractère "; une séquence de 1 caractère m peut être remplacée par la séquence de 2 caractères rn, et la séquence de 3 caractères peut être remplacée par la séquence de 1 caractère m.

La version 3.03 et ultérieures prend en charge un nouveau format plus simple pour le fichier unicharambigs :

v2
'' " 1
m rn 0
iii m 0

Dans ce format, les "erreurs" et "corrections" sont des chaînes UTF-8 simples séparées par un espace, et, après un autre espace, le même spécificateur de type que dans v1 (0 pour substitution optionnelle et 1 pour obligatoire). Notez que le revers de ce format plus simple est que Tesseract doit encoder les chaînes UTF-8 dans les composants de l'unicharset. Dans les scripts complexes, cet encodage peut être ambigu. Dans ce cas, l'encodage est choisi de manière à utiliser le moins de caractères UTF-8 possible pour chaque composant, c'est-à-dire que les composants d'unicharset les plus courts constitueront l'encodage.

HISTORIQUE

Le fichier unicharambigs est apparu pour la première fois dans Tesseract 3.00 ; avant cela, un format similaire, appelé DangAmbigs (dangerous ambiguities), était utilisé : le format était presque identique, sauf que seuls les remplacements obligatoires pouvaient être spécifiés, et le champ 5 était absent.

BOGUES

Ceci est un "boguedoc" de documentation : il n'est actuellement pas clair quoi faire en cas de ligatures (comme fi) qui peuvent également apparaître comme des lettres ordinaires dans l'unicharset.
