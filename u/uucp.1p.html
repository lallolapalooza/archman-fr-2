UUCP(1P) Manuel du programmeur POSIX UUCP(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uucp — copie entre systèmes

SYNOPIS

uucp [-cCdfjmr] [-n utilisateur] fichier-source... fichier-destination

DESCRIPTION

L'utilitaire uucp copie les fichiers nommés par l'argument fichier-source vers l'argument fichier-destination. Les fichiers nommés peuvent se trouver sur des systèmes locaux ou distants.

L'utilitaire uucp ne peut garantir la prise en charge de toutes les encodages de caractères dans toutes les circonstances. Par exemple, les données de transmission peuvent être limitées à 7 bits par le réseau sous-jacent, les données et les noms de fichiers sur 8 bits ne sont pas nécessairement portables vers des systèmes non internationalisés, etc. Dans ces circonstances, il est recommandé de n'utiliser que les caractères définis dans la plage de caractères 7 bits de la version de référence internationale (équivalente à l'ASCII) de la norme ISO/IEC 646:1991, et de n'utiliser que les caractères définis dans l'ensemble de caractères de nom de fichier portable pour nommer les fichiers. Le protocole de transfert de fichiers n'est pas spécifié par POSIX.1‐2008.

Les implémentations typiques de cet utilitaire nécessitent une ligne de communication configurée pour utiliser le volume Définitions de base de POSIX.1‐2017, Chapitre 11, Interface de terminal générale, mais d'autres moyens de communication peuvent être utilisés. Sur les systèmes où aucun moyen de communication n'est disponible (temporairement ou définitivement), cet utilitaire écrira un message d'erreur décrivant le problème et se terminera avec un statut de sortie non nul.

OPTIONS

L'utilitaire uucp doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-c
Ne pas copier le fichier local dans le répertoire spool pour le transfert vers la machine distante (par défaut).
-C
Forcer la copie des fichiers locaux dans le répertoire spool pour le transfert.
-d
Créer tous les répertoires nécessaires pour la copie de fichier (par défaut).
-f
Ne pas créer de répertoires intermédiaires pour la copie de fichier.
-j
Écrire la chaîne d'identification du travail sur la sortie standard. Cette identification du travail peut être utilisée par uustat pour obtenir le statut ou terminer un travail.
-m
Envoyer un courrier à l'appelant une fois la copie terminée.
-n utilisateur
Notifier utilisateur sur le système distant qu'un fichier a été envoyé.
-r
Ne pas démarrer le transfert de fichier ; mettre seulement le travail en file d'attente.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier-destination, fichier-source

Un nom de chemin d'un fichier à copier vers, ou depuis, respectivement. L'un ou l'autre nom peut être un nom de chemin sur la machine locale, ou peut avoir la forme :
nom-système!nom-chemin

où nom-système est tiré d'une liste de noms de systèmes que uucp connaît. Le nom-système de destination peut également être une liste de noms telle que :

nom-système!nom-système!...!nom-système!nom-chemin

auquel cas, une tentative est faite pour envoyer le fichier via la route spécifiée vers la destination. Il faut veiller à s'assurer que les nœuds intermédiaires de la route acceptent de transférer des informations.

Les caractères de notation de correspondance de motif du shell '?', '*', et "[...]" apparaissant dans nom-chemin doivent être développés sur le système approprié.

Les noms de chemin peuvent être :

1.
Un nom de chemin absolu.
2.
Un nom de chemin précédé de ~utilisateur où utilisateur est un nom de connexion sur le système spécifié et est remplacé par le répertoire de connexion de cet utilisateur. Noter que si un login invalide est spécifié, le défaut est le répertoire public (appelé PUBDIR ; l'emplacement réel de PUBDIR est défini par l'implémentation).
3.
Un nom de chemin précédé de ~/destination où destination est ajouté à PUBDIR.
Note :
Cette destination est traitée comme un nom de fichier sauf si plus d'un fichier est transféré par cette requête ou si la destination est déjà un répertoire. Pour s'assurer qu'il s'agit d'un répertoire, faire suivre la destination d'un '/'. Par exemple, ~/dan/ comme destination crée le répertoire PUBDIR/dan s'il n'existe pas et y place les fichiers demandés.
4.
Tout le reste sera préfixé par le répertoire courant.

Si le résultat est un nom de chemin erroné pour le système distant, la copie échouera. Si le fichier-destination est un répertoire, la dernière partie du nom du fichier-source sera utilisée.

Les permissions de lecture, écriture et exécution données par uucp sont définies par l'implémentation.

STDIN

Non utilisé.

FICHIERS ENTRÉE

Les fichiers à copier sont des fichiers réguliers.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de uucp :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la prédominance des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une chaîne de caractères non vide, outrepasser les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Déterminer la locale pour le comportement des plages, des classes d'équivalence et des éléments de tri multi-caractères dans les motifs de noms de fichiers entre crochets.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octet dans les arguments et les fichiers d'entrée) et le comportement des classes de caractères dans les motifs de noms de fichiers entre crochets (par exemple, "'[[:lower:]]*'").
LC_MESSAGES

Déterminer la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur l'erreur standard, et les messages informatifs écrits sur la sortie standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

STDERR

L'erreur standard ne sera utilisée que pour les messages de diagnostic.

UTILISATION APPLICATIVE

Cet utilitaire fait partie de l'option UUCP Utilities et peut ne pas être pris en charge par toutes les implémentations.

Le domaine des fichiers accessibles à distance peut (et pour des raisons de sécurité évidentes, le devrait généralement) être sévèrement restreint.

Notez que le caractère '!' dans les adresses doit être échappé lors de l'utilisation de csh comme interpréteur de commandes en raison de sa syntaxe de substitution d'historique. Pour ksh et sh, l'échappement n'est pas nécessaire, mais peut être utilisé.

Comme indiqué ci-dessus, les métacaractères du shell apparaissant dans les noms de chemin sont développés sur le système approprié. Sur un système internationalisé, cela est fait sous le contrôle des paramètres locaux de LC_COLLATE et LC_CTYPE. Par conséquent, il convient de faire attention lors de l'utilisation de motifs de noms de fichiers entre crochets, car les règles de tri et de typage peuvent varier d'un système à l'autre. Soyez également conscient que certains types d'expressions (à savoir, les classes d'équivalence, les classes de caractères et les symboles de tri) ne sont pas nécessairement pris en charge sur les systèmes non internationalisés.
