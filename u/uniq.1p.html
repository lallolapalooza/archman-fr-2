UNIQ(1P) Manuel du programmeur POSIX UNIQ(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uniq — signaler ou filtrer les lignes répétées dans un fichier

SYNTAXE

uniq [-c|-d|-u] [-f champs] [-s caractères] [fichier_entree [fichier_sortie]]

DESCRIPTION

L'utilitaire uniq lit un fichier d'entrée en comparant les lignes adjacentes, et écrit une copie de chaque ligne d'entrée en sortie. Les deuxièmes copies et les suivantes des lignes d'entrée répétées adjacentes ne sont pas écrites. Le caractère de fin de ligne (<newline>) de chaque ligne d'entrée est ignoré lors des comparaisons.

Les lignes répétées dans l'entrée ne seront pas détectées si elles ne sont pas adjacentes.

OPTIONS

L'utilitaire uniq doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception près que '+' peut être reconnu comme délimiteur d'option ainsi que '-'.

Les options suivantes doivent être prises en charge :

-c
Précède chaque ligne de sortie d'un compteur indiquant le nombre de fois où la ligne est apparue dans l'entrée.
-d
Supprime l'écriture des lignes qui ne sont pas répétées dans l'entrée.
-f champs
Ignore les champs premiers champs de chaque ligne d'entrée lors des comparaisons, où champs est un entier décimal positif. Un champ est la chaîne maximale correspondant à l'expression régulière de base :
[[:blanc:]]*[^[:blanc:]]*

Si l'argument de l'option champs spécifie plus de champs qu'il n'en apparaît sur une ligne d'entrée, une chaîne nulle sera utilisée pour la comparaison.

-s caractères
Ignore les caractères premiers caractères lors des comparaisons, où caractères est un entier décimal positif. Si spécifié en conjonction avec l'option -f, les caractères premiers après les champs premiers champs seront ignorés. Si l'argument de l'option caractères spécifie plus de caractères qu'il n'en reste sur une ligne d'entrée, une chaîne nulle sera utilisée pour la comparaison.
-u
Supprime l'écriture des lignes qui sont répétées dans l'entrée.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier_entree
Un chemin d'accès vers le fichier d'entrée. Si l'opérande fichier_entree n'est pas spécifié, ou si fichier_entree est '-', l'entrée standard sera utilisée.
fichier_sortie
Un chemin d'accès vers le fichier de sortie. Si l'opérande fichier_sortie n'est pas spécifié, la sortie standard sera utilisée. Les résultats sont indéterminés si le fichier nommé par fichier_sortie est le même que le fichier nommé par fichier_entree.

ENTRÉE STANDARD

L'entrée standard ne sera utilisée que si aucun opérande fichier_entree n'est spécifié ou si fichier_entree est '-'. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Le fichier d'entrée doit être un fichier texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de uniq :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en tant que caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée) et quels caractères constituent un <blanc> dans la locale courante.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard sera utilisée si aucun opérande fichier_sortie n'est spécifié, et sera utilisée si l'opérande fichier_sortie est '-' et que l'implémentation traite '-' comme signifiant la sortie standard. Sinon, la sortie standard ne sera pas utilisée. Voir la section FICHIERS DE SORTIE.

ERREUR STANDARD

La sortie standard d'erreur ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Si l'option -c est spécifiée, le fichier de sortie sera vide ou chaque ligne sera de la forme :

"%d %s", <nombre de doublons>, <ligne>

sinon, le fichier de sortie sera vide ou chaque ligne sera de la forme :

"%s", <ligne>

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
L'utilitaire s'est exécuté avec succès.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Si la séquence de tri de la locale courante a un ordre total de tous les caractères, l'utilitaire sort peut être utilisé pour rendre les lignes répétées adjacentes dans le fichier d'entrée. Si la séquence de tri n'a pas d'ordre total de tous les caractères, l'utilitaire sort devrait quand même le faire mais pourrait ne pas y parvenir. Pour garantir que toutes les lignes dupliquées sont éliminées, et que la sortie est triée selon la séquence de tri de la locale courante, les applications devraient utiliser :

LC_ALL=C sort -u | sort

au lieu de :

sort | uniq

Pour supprimer les lignes dupliquées en fonction de leur égalité de tri plutôt que de leur identité, les applications devraient utiliser :

sort -u

au lieu de :

sort | uniq

Lors de l'utilisation de uniq pour traiter des chemins d'accès, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les chemins d'accès peuvent contenir des séquences d'octets qui ne forment pas de c valides

PROLOG

Ce document décrit la syntaxe et le comportement de la commande uniq tels qu'ils sont implémentés dans les versions futures de POSIX, conformément aux directives de la norme.

NOM

uniq - rapportez ou omettez les lignes identiques adjacentes

SYNOPSIS

uniq [-c|-d|-u] [-f fields] [-s characters] [input_file [output_file]]

DESCRIPTION

La commande uniq lit les lignes d'un fichier d'entrée spécifié par input_file, ou de l'entrée standard si aucun fichier d'entrée n'est spécifié. Les lignes d'entrée doivent être triées. La commande compare chaque ligne avec la ligne précédente. Par défaut, uniq écrit chaque ligne unique sur la sortie standard. Si des lignes identiques adjacentes sont trouvées, seule la première occurrence est écrite.

Les options suivantes sont disponibles :

  • -c : Précède chaque ligne de sortie du nombre de fois où la ligne est apparue dans le fichier d'entrée.
  • -d : N'écrit qu'une seule occurrence de chaque ligne qui apparaît deux fois ou plus dans le fichier d'entrée. Ces lignes sont appelées lignes répétées.
  • -u : N'écrit qu'une seule occurrence de chaque ligne qui n'apparaît qu'une seule fois dans le fichier d'entrée. Ces lignes sont appelées lignes uniques.

Les options -f et -s peuvent être utilisées pour modifier le comportement de comparaison de uniq. Elles permettent d'ignorer un certain nombre de champs ou de caractères au début de chaque ligne lors de la comparaison.

OPTIONS

Voir la section DESCRIPTION ci-dessus.

OPERANDS

input_file
Le fichier dont les lignes sont lues. S'il est omis, l'entrée standard est utilisée.
output_file
Le fichier dans lequel les lignes sont écrites. S'il est omis, la sortie standard est utilisée.

STDIN

L'entrée standard est utilisée si input_file est omis.

INPUT FILES

Les lignes d'entrée doivent être triées pour que la commande uniq fonctionne correctement. L'utilitaire uniq traite les lignes comme des chaînes de caractères délimitées par le caractère de nouvelle ligne (‘\n’).

ENVIRONMENT VARIABLES

Voir les pages de manuel appropriées pour les variables d'environnement pertinentes.

ASYNCHRONOUS EVENTS

Voir les pages de manuel appropriées pour les événements asynchrones pertinents.

STDOUT

Par défaut, uniq écrit chaque ligne unique sur la sortie standard. Les lignes sont délimitées par le caractère de nouvelle ligne.

STDERR

Les erreurs sont écrites sur la sortie d'erreur standard.

OUTPUT FILES

Voir la description de output_file dans la section OPERANDS.

EXTENDED DESCRIPTION

La commande uniq compare les lignes adjacentes dans le fichier d'entrée. Le comportement de la comparaison peut être modifié par les options -f et -s.

-f fields : Ignorer les fields premiers champs de chaque ligne lors de la comparaison. Les champs sont délimités par des espaces blancs. Si fields est 0, aucun champ n'est ignoré. Les valeurs de fields doivent être des entiers positifs ou nuls.

-s characters : Ignorer les characters premiers caractères de chaque ligne lors de la comparaison. Si characters est 0, aucun caractère n'est ignoré. Les valeurs de characters doivent être des entiers positifs ou nuls.

Dans la locale POSIX, chaque octet est un caractère valide à un seul octet, ce qui évite les problèmes potentiels liés aux caractères multi-octets dans d'autres locales.

EXEMPLES

Les données de fichier d'entrée suivantes (mais alignées à gauche) ont été utilisées pour une série de tests sur uniq :

#01 foo0 bar0 foo1 bar1
#02 bar0 foo1 bar1 foo1
#03 foo0 bar0 foo1 bar1
#04
#05 foo0 bar0 foo1 bar1
#06 foo0 bar0 foo1 bar1
#07 bar0 foo1 bar1 foo0

Ce qui suit est une série d'invocations de test de l'utilitaire uniq qui utilisent un mélange d'options uniq contre les données du fichier d'entrée. Ces tests vérifient la signification de adjacentes. L'utilitaire uniq considère les données d'entrée comme une séquence de chaînes délimitées par ‘\n’. En conséquence, pour le fields-ième membre de la séquence, uniq interprète les lignes uniques ou répétées adjacentes strictement par rapport au fields+1-ième membre.

1.
Ce premier exemple teste l'option de comptage de lignes, en comparant chaque ligne des données du fichier d'entrée à partir du deuxième champ :
uniq -c -f 1 uniq_0I.t
    1 #01 foo0 bar0 foo1 bar1
    1 #02 bar0 foo1 bar1 foo1
    1 #03 foo0 bar0 foo1 bar1
    1 #04
    2 #05 foo0 bar0 foo1 bar1
    1 #07 bar0 foo1 bar1 foo0

Le nombre '2', préfixant la cinquième ligne de sortie, signifie que l'utilitaire uniq a détecté une paire de lignes répétées. Compte tenu des données d'entrée, cela ne peut être vrai que lorsque uniq est exécuté avec l'option -f 1 (qui fait que uniq ignore le premier champ de chaque ligne d'entrée).

2.
Le deuxième exemple teste l'option pour supprimer les lignes uniques, en comparant chaque ligne des données du fichier d'entrée à partir du deuxième champ :
uniq -d -f 1 uniq_0I.t
#05 foo0 bar0 foo1 bar1
3.
Ce test supprime les lignes répétées, en comparant chaque ligne des données du fichier d'entrée à partir du deuxième champ :
uniq -u -f 1 uniq_0I.t
#01 foo0 bar0 foo1 bar1
#02 bar0 foo1 bar1 foo1
#03 foo0 bar0 foo1 bar1
#04
#07 bar0 foo1 bar1 foo0
4.
Ceci supprime les lignes uniques, en comparant chaque ligne des données du fichier d'entrée à partir du troisième caractère :
uniq -d -s 2 uniq_0I.t

Dans le dernier exemple, l'utilitaire uniq n'a trouvé aucune entrée correspondant aux critères ci-dessus.

RATIONALE

Certaines implémentations historiques ont limité les lignes à 1080 octets, ce qui ne respecte pas la limite {LINE_MAX} implicite.

Les versions antérieures de cette norme autorisaient les options -nombre et +nombre. Ces options ne sont plus spécifiées par POSIX.1-2008 mais peuvent être présentes dans certaines implémentations.
