UMASK(3P) Manuel du programmeur POSIX UMASK(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

umask — définir et obtenir le masque de création de mode de fichier

SYNTAXE

#include <sys/stat.h>
mode_t umask(mode_t cmask);

DESCRIPTION

La fonction umask() définit le masque de création de mode de fichier du processus sur cmask et retourne la valeur précédente du masque. Seuls les bits de permission de fichier de cmask (voir <sys/stat.h>) sont utilisés ; la signification des autres bits est définie par l'implémentation.

Le masque de création de mode de fichier du processus est utilisé pour désactiver les bits de permission dans l'argument mode fourni lors des appels aux fonctions suivantes :

*
open(), openat(), creat(), mkdir(), mkdirat(), mkfifo(), et mkfifoat()
*
mknod(), mknodat()
*
mq_open()
*
sem_open()

Les positions de bits qui sont définies dans cmask sont effacées dans le mode du fichier créé.

VALEUR DE RETOUR

Les bits de permission de fichier dans la valeur retournée par umask() sont la valeur précédente du masque de création de mode de fichier. L'état de tout autre bit dans cette valeur n'est pas spécifié, sauf qu'un appel ultérieur à umask() avec la valeur retournée comme cmask laissera l'état du masque inchangé par rapport à son état avant le premier appel, y compris toute utilisation non spécifiée de ces bits.

ERREURS

Aucune erreur n'est définie.

RATIONALE

Des types d'arguments et de retour non signés pour umask() ont été proposés. Le type de retour et l'argument ont tous deux été changés en mode_t.

Les implémentations historiques ont utilisé des bits supplémentaires dans cmask pour leurs objectifs définis par l'implémentation. L'ajout du texte indiquant que la signification des autres bits du champ est définie par l'implémentation permet à ces implémentations d'être conformes à ce volume de POSIX.1‐2017.
