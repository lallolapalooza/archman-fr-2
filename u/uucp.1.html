uucp(1) Manuel des commandes générales uucp(1)

NOM

uucp - copie Unix vers Unix

SYNTAXE

uucp [ options ] fichier-source fichier-destination

uucp [ options ] fichier-source... répertoire-destination

DESCRIPTION

La commande uucp copie des fichiers entre systèmes. Chaque argument fichier est soit un chemin d'accès sur la machine locale, soit de la forme

système!chemin

ce qui est interprété comme étant sur un système distant. Dans la première forme, le contenu du premier fichier est copié vers le second. Dans la seconde forme, chaque fichier source est copié dans le répertoire de destination.

Un fichier peut être transféré vers ou depuis système2 via système1 en utilisant

système1!système2!chemin.

Tout chemin d'accès qui ne commence pas par / ou ~ sera ajouté au répertoire courant (sauf si l'option -W ou --noexpand est utilisée) ; ce chemin résultant n'existera pas nécessairement sur un système distant. Un chemin d'accès commençant par un simple ~ commence dans le répertoire public UUCP ; un chemin d'accès commençant par ~nom commence dans le répertoire personnel de l'utilisateur nommé. Le ~ est interprété sur le système approprié. Notez que certains shells interpréteront un simple ~ vers le répertoire personnel local avant que uucp ne le voie ; pour éviter cela, le ~ doit être mis entre guillemets.

Les métacaractères de shell ? * [ ] sont interprétés sur le système approprié, à condition qu'ils soient mis entre guillemets pour empêcher le shell de les interpréter en premier.

La copie n'a pas lieu immédiatement, mais est mise en file d'attente pour le démon uucico (8) ; le démon est démarré immédiatement, sauf si le commutateur -r ou --nouucico est donné. Dans tous les cas, lors de la prochaine connexion au système distant, le(s) fichier(s) sera copié(s).

OPTIONS

Les options suivantes peuvent être données à uucp.

-c, --nocopy
Ne pas copier les fichiers sources locaux dans le répertoire de spool. S'ils sont supprimés avant d'être traités par le démon uucico (8), la copie échouera. Les fichiers doivent être lisibles par le démon uucico (8) et par l'utilisateur appelant.
-C, --copy
Copier les fichiers sources locaux dans le répertoire de spool. C'est le comportement par défaut.
-d, --directories
Créer tous les répertoires nécessaires lors de la copie. C'est le comportement par défaut.
-f, --nodirectories
Si des répertoires nécessaires n'existent pas pour le chemin de destination, interrompre la copie.
-R, --recursive
Si l'un des noms de fichiers sources est un répertoire, copiez son contenu récursivement vers la destination (qui doit elle-même être un répertoire).
-g niveau, --grade niveau
Définir le niveau de la commande de transfert de fichiers. Les tâches de niveau supérieur sont exécutées en premier. Les niveaux vont de 0...9 A...Z a...z du plus haut au plus bas.
-m, --mail
Signaler l'achèvement ou l'échec du transfert de fichiers par mail (1).
-n utilisateur, --notify utilisateur
Signaler l'achèvement ou l'échec du transfert de fichiers par mail (1) à l'utilisateur nommé sur le système distant.
-r, --nouucico
Ne pas démarrer le démon uucico (8) immédiatement ; simplement mettre en file d'attente le transfert de fichier pour exécution ultérieure.
-j, --jobid
Afficher l'identifiant de tâche (jobid) sur la sortie standard. La tâche peut être ultérieurement annulée en passant l'identifiant de tâche à l'option -k de uustat (1). Il est possible que certaines opérations complexes produisent plus d'un identifiant de tâche, auquel cas chacun sera affiché sur une ligne séparée. Par exemple 

uucp sys1!~utilisateur1/fichier1 sys2!~utilisateur2/fichier2 ~utilisateur3

générera deux tâches distinctes, une pour le système sys1 et une pour le système sys2.
-W, --noexpand
Ne pas préfixer les noms de chemins relatifs distants avec le répertoire courant.
-t, --uuto
Cette option est utilisée par le script shell uuto. Elle amène uucp à interpréter le dernier argument comme système!utilisateur. Le(s) fichier(s) sont envoyés à ~/receive/UTILISATEUR/LOCAL sur le système distant, où UTILISATEUR provient du dernier argument et LOCAL est le nom du système UUCP local. De plus, uucp agira comme si --notify utilisateur avait été spécifié.
-x type, --debug type
Activer des types de débogage spécifiques. Les types suivants sont reconnus : abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Seuls abnormal, config, spooldir et execute sont significatifs pour uucp.

Plusieurs types peuvent être donnés, séparés par des virgules, et l'option --debug peut apparaître plusieurs fois. Un nombre peut également être donné, qui activera autant de types de la liste ci-dessus ; par exemple, --debug 2 équivaut à --debug abnormal,chat.

-I fichier, --config fichier
Définir le fichier de configuration à utiliser. Cette option peut ne pas être disponible, en fonction de la façon dont uucp a été compilé.
-v, --version
Afficher les informations de version et quitter.
--help
Afficher un message d'aide et quitter.

VOIR AUSSI

mail(1), uux(1), uustat(1), uucico(8)

BOGUES

Certaines des options dépendent des capacités du démon uucico (8) sur le système distant.

Les commutateurs -n et -m ne fonctionnent pas lors du transfert d'un fichier d'un système distant à un autre.

Les modes de fichiers ne sont pas conservés, à l'exception du bit d'exécution. Le fichier résultant appartient à l'utilisateur uucp.
