DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui effectue la mise en cache et la validation DNSSEC. Ceci est l'API de la bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et inversement, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour conserver le contexte entre les appels. L'utilisateur doit la maintenir, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. Sa création efface toute configuration précédente (comme les clés de confiance) et tous les résultats mis en cache.

Les fonctions sont thread-safe et un contexte peut être utilisé dans un environnement multithread (ainsi que dans un environnement non-multithread). La résolution (et la validation) peuvent également être effectuées de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement à partir de l'appel, de sorte que le traitement puisse continuer, tandis que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec des valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez la bibliothèque openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou plus récent utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les callbacks ne sont pas appelés pour celles-ci.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier l'une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère une valeur d'option. Certaines options ne peuvent pas être récupérées, et d'autres retournent une liste séparée par des nouvelles lignes. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée par free(2) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine vers laquelle les requêtes DNS seront transmises, le résolveur de cache à utiliser. Adresse IP4 ou IP6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas compatible DNSSEC, la validation peut échouer. Peut être appelée plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. À ce stade, il n'est possible de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. isprime est défini à vrai si vous configurez des hints racine avec. Sinon, similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelé plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. À ce stade, il n'est possible de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_set_tls
Active le DNS sur TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. À ce stade, il n'est possible de définir la configuration qu'avant que la première résolution ne soit effectuée.
ub_ctx_resolvconf
Par défaut, les serveurs racine sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser à partir du nom de fichier donné. Généralement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxies de cache. S'ils ne supportent pas DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont pris en compte, le domaine de recherche (searchdomain), ndots et d'autres paramètres de resolv.conf(5) sont ignorés. Si fname NULL est passé, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré globalement est choisi à la place). À ce stade, il n'est possible de définir la configuration qu'avant la première résolution.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Généralement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname NULL est passé, "/etc/hosts" est utilisé (si sous Windows, etc/hosts à partir de WINDIR est sélectionné à la place). DESCRIPTION

These functions provide an API to the unbound validating, recursive, caching DNS resolver library. The library can be used to perform DNS lookups and perform DNSSEC validation.

To use the library you must first create a context by calling ub_ctx_create. This context holds the configuration and state for the resolver. When finished with the context, it must be freed using ub_ctx_delete.

Configuration can be done by setting options using ub_ctx_set_option, or by reading a configuration file using ub_ctx_config. For resolver specific configuration, such as DNS servers to use, ub_ctx_resolvconf can be used.

Local zones and data can be added and removed using ub_ctx_zone_add, ub_ctx_zone_remove, ub_ctx_data_add, and ub_ctx_data_remove.

DNSSEC trust anchors can be added using the functions described below.

The library can be used synchronously using ub_resolve, or asynchronously using ub_resolve_async. For asynchronous operation, you need to use ub_poll, ub_fd, and ub_process to manage the event loop.

FUNCTIONS

ub_ctx_create
Create a context for the unbound library. Returns a pointer to the context, or NULL on error.
ub_ctx_delete
Delete the context and free all associated resources.
ub_ctx_set_option
Set an option for the context. Options are given as string pairs, for example: ub_ctx_set_option(ctx, "verbosity", "2"). Returns 0 on success, or an error code.
ub_ctx_get_option
Get the value of an option for the context. The value is returned in *val. The caller must free the returned string with free(). Returns 0 on success, or an error code.
ub_ctx_set_option_int
Set an integer option for the context.
ub_ctx_get_option_int
Get an integer option for the context.
ub_ctx_set_option_list
Set a list option for the context. The list is a NULL terminated array of strings.
ub_ctx_get_option_list
Get a list option for the context. The list is a NULL terminated array of strings. The caller must free the returned list with ub_ctx_free_list.
ub_ctx_free_list
Frees a list allocated by ub_ctx_get_option_list.
ub_ctx_config
Read configuration from the specified file into the context. Returns 0 on success, or an error code.
ub_ctx_resolvconf
Read resolver configuration (like nameservers) from the specified file into the context. On Unix-like systems, this is typically /etc/resolv.conf. Returns 0 on success, or an error code.
ub_ctx_add_dns_server
Add a DNS server to use for DNS queries. The address can be an IP address or a hostname. The port defaults to 53 if not specified. If the server is already present, this function does nothing.
ub_ctx_remove_dns_server
Remove a DNS server from the list of servers to use. If the server is not present, this function does nothing.
ub_ctx_add_ip_range
Add an IP range for local data. The name is the domain name, and the range is a CIDR notation string, e.g. "192.168.1.0/24".
ub_ctx_remove_ip_range
Remove an IP range for local data.
ub_ctx_add_local_zone
Add a local zone to the context. The type can be UB_LOCALZONE_POSITIVE, UB_LOCALZONE_NEGATIVE, UB_LOCALZONE_REDIRECT, UB_LOCALZONE_NODATA, or UB_LOCALZONE_EMPTY. Corresponds to the local-zone directive in unbound.conf(5).
ub_ctx_remove_local_zone
Remove a local zone from the context.
ub_ctx_add_local_data
Add local data to the context. The data is a string in standard DNS zone file format. Corresponds to the local-data directive in unbound.conf(5).
ub_ctx_remove_local_data
Remove local data from the context for the given zone.
ub_ctx_add_ta
Ajouter une ancre de confiance au contexte donné. Actuellement, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée. Le format est une chaîne de caractères, similaire au format de fichier de zone, [nom de domaine] [type] [contenu rdata]. Les enregistrements DS et DNSKEY sont acceptés.
ub_ctx_add_ta_autr
Ajouter un nom de fichier avec une ancre de confiance suivie automatiquement au contexte donné. Passer le nom d'un fichier avec l'ancre de confiance gérée. Vous pouvez créer ce fichier avec unbound-anchor(8) pour l'ancre racine. Vous pouvez également le créer avec un fichier initial contenant une ligne avec un enregistrement DNSKEY ou DS. Si le fichier est accessible en écriture, il est mis à jour lorsque l'ancre de confiance change. Actuellement, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_add_ta_file
Ajouter des ancres de confiance au contexte donné. Passer le nom d'un fichier contenant des enregistrements DS et DNSKEY au format de fichier de zone. Actuellement, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_trustedkeys
Ajouter des ancres de confiance au contexte donné. Passer le nom d'un fichier de configuration de style bind avec trusted-keys{}. Actuellement, il est seulement possible d'ajouter des clés de confiance avant que la première résolution ne soit effectuée.
ub_ctx_debugout
Définir la sortie des logs de débogage et d'erreur vers le flux donné. Passer NULL pour désactiver la sortie. La sortie par défaut est stderr. Les noms de fichiers ou l'utilisation de syslog peuvent être activés en utilisant les options de configuration, cette routine est pour utiliser votre propre flux.
ub_ctx_debuglevel
Définir la verbosité du débogage pour le contexte. La sortie est dirigée vers stderr. Un niveau de débogage plus élevé donne plus de sortie.
ub_ctx_async
Définir le comportement du contexte pour une action asynchrone. Si défini à vrai, cela active les threads et un appel à ub_resolve_async crée un thread pour gérer le travail en arrière-plan. Si défini à faux, un processus est bifurqué pour gérer le travail en arrière-plan. Les changements à ce paramètre après que des appels à ub_resolve_async ont été effectués n'ont aucun effet (supprimez et recréez le contexte pour le changer).
ub_poll
Interroger un contexte pour voir s'il a de nouveaux résultats. N'interrogez pas en boucle, extrayez plutôt le fd ci-dessous pour interroger la disponibilité, puis vérifiez, ou attendez en utilisant la routine d'attente. Retourne 0 si rien à lire, ou une valeur non nulle si un résultat est disponible. Si non nulle, appelez ub_process pour effectuer les rappels.
ub_wait
Attendre qu'un contexte finisse avec des résultats. Appelle ub_process après l'attente pour vous. Après l'attente, il n'y a plus de requêtes asynchrones en cours.
ub_fd
Obtenir un descripteur de fichier. Attendre qu'il devienne lisible, à ce moment-là les réponses sont retournées par le résolveur de validation asynchrone. Ensuite, appelez ub_process pour continuer le traitement.
ub_process
Appelez cette routine pour continuer le traitement des résultats du résolveur de validation (lorsque le fd devient lisible). Effectuera les rappels nécessaires.
ub_resolve
Effectuer la résolution et la validation du nom cible. Le nom est un nom de domaine sous forme de chaîne de caractères terminée par un zéro. Le type rrtype et la classe rrclass sont les codes de type et de classe DNS. La structure de résultat est nouvellement allouée avec les données résultantes.
ub_resolve_async
Effectuer la résolution et la validation asynchrones du nom cible. Les arguments signifient la même chose que pour ub_resolve, sauf qu'aucune donnée n'est retournée immédiatement, un rappel est plutôt appelé plus tard. Le rappel reçoit une copie du pointeur mydata, que vous pouvez utiliser pour passer des informations au rappel. Le type de rappel est un pointeur de fonction vers une fonction déclarée comme :
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

L' async_id est retourné afin que vous puissiez (à votre discrétion) décider de le suivre et d'annuler la requête si nécessaire. Si vous passez un pointeur NULL, l' async_id n'est pas retourné.

ub_cancel
Annuler une requête asynchrone en cours. Cela peut retourner une erreur si la requête n'existe pas, ou si la requête est déjà en cours de livraison, auquel cas vous pourriez toujours recevoir un rappel pour la requête.
ub_resolve_free
Libérer le contenu de la structure ub_result après utilisation.
ub_strerror
Convertir une valeur d'erreur d'une des fonctions de la bibliothèque unbound en une chaîne de caractères lisible par l'homme.
ub_ctx_print_local_zones
Impression de débogage des informations d'autorité locale dans la sortie de débogage.
ub_ctx_zone_add
Ajouter une nouvelle zone aux informations d'autorité locale, comme l'énoncé local-zone de unbound.conf(5).
ub_ctx_zone_remove
Supprimer une zone des informations d'autorité locale.
ub_ctx_data_add
Ajouter des données d'enregistrement de ressources aux informations d'autorité locale, comme l'énoncé local-data de unbound.conf(5).
ub_ctx_data_remove
Supprimer les données d'autorité locale du nom donné.

RESULT DATA STRUCTURE

Le résultat de la résolution et de la validation DNS est retourné sous forme de struct ub_result. La structure de résultat contient les entrées suivantes :

struct ub_result {
     char* qname;         /* chaîne de caractères, question originale */
     int qtype;           /* code de type demandé */
     int qclass;          /* code de classe demandé */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas de absence de données */
     void* answer_packet; /* paquet complet en format réseau de la réponse */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai si pas de données car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si une défaillance de sécurité s'est produite */
     char* why_bogus;     /* chaîne avec l'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée par le débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

Si secure et bogus sont tous deux faux, la sécurité n'a pas été activée pour le domaine de la requête. Sinon, ils ne sont pas tous les deux vrais, l'un d'eux est vrai.

RETURN VALUES

De nombreuses routines retournent un code d'erreur. La valeur 0 (zéro) indique qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror retourne une chaîne terminée par un zéro. ub_ctx_create retourne NULL en cas d'erreur (échec d'allocation malloc). ub_poll retourne vrai si certaines informations peuvent être disponibles, faux sinon. ub_fd retourne un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif en cas de retour de fonction avec échec de lecture de fichier.
