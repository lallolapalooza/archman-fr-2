unibi_format(3)

Paquet: unibilium

Licences: LGPL3

doc::unibi_format(3) unibilium doc::unibi_format(3)

NOM

unibi_format, unibi_run - interpréter une chaîne de formatage terminfo

SYNTAXE

#include <unibilium.h>

void unibi_format(
    unibi_var_t var_dyn[26],
    unibi_var_t var_static[26],
    const char *fmt,
    unibi_var_t param[9],
    void (*out)(void *, const char *, size_t),
    void *ctx1,
    void (*pad)(void *, size_t, int, int),
    void *ctx2
);

size_t unibi_run(const char *fmt, unibi_var_t param[9], char *p, size_t n);

DESCRIPTION

"unibi_format" prend une chaîne de formatage fmt et l'exécute. Toute la sortie est effectuée par des appels (éventuellement répétés) à out. Dans les appels à out, le premier argument est toujours ctx1, le second argument est un pointeur vers un morceau de données, et le troisième argument est un compteur spécifiant la taille du morceau en octets.

pad est utilisé lorsque la chaîne de formatage contient des instructions de remplissage "$<...>". Dans les appels à pad, le premier argument est toujours ctx2, le second argument est le délai en dixièmes de millisecondes, le troisième argument est un indicateur booléen indiquant si "*" (délai proportionnel) a été spécifié dans la chaîne de formatage, et le quatrième argument est un indicateur booléen indiquant si "/" (remplissage forcé) a été spécifié dans la chaîne de formatage. Ainsi, une chaîne de formatage de "$<5/>" se traduirait par "pad(ctx2, 50, 0, 1)". Vous pouvez passer un pointeur nul pour pad ; dans ce cas, les instructions de remplissage sont ignorées silencieusement.

Les valeurs de param sont utilisées pour les codes de format %p1 .. %p9 ; les valeurs de var_dyn et var_static sont utilisées pour les variables dites dynamiques/statiques %Pa .. %Pz et %PA .. %PZ, respectivement.

"unibi_run" est une enveloppe autour de "unibi_format". Elle passe deux tableaux (chacun initialisé à 26 zéros) comme var_dyn et var_static. fmt et param sont transmis tels quels. Elle ignore le remplissage et place toute la sortie normale dans le tampon pointé par p. n est la taille du tampon ; au plus n octets seront écrits dans p.

VALEUR DE RETOUR

"unibi_run" retourne le nombre d'octets qui auraient été écrits si le tampon était assez grand. Ainsi, le nombre d'octets valides dans p après un appel à "unibi_run" est le minimum de n et de la valeur de retour de "unibi_run".
