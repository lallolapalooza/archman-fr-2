UWSM(1) Manuel des commandes générales UWSM(1)

NOM

UWSM - Gestionnaire de session Wayland universel.

SYNTAXE

uwsm [-h|-v] {sous-commande} [options ...]

DESCRIPTION

Lance un compositeur Wayland arbitraire via un ensemble d'unités utilisateur systemd pour fournir une session utilisateur graphique avec gestion de l'environnement, prise en charge du démarrage automatique XDG, arrêt propre. Fournit des utilitaires pour lancer des applications en tant que scopes ou services.

SOUS-COMMANDES

select Sélectionne l'Entrée du compositeur par défaut.
start Démarre le compositeur et la session graphique.
finalize Envoie les variables définies par le compositeur et la notification de démarrage de l'unité au gestionnaire utilisateur systemd.
stop Arrête la session graphique et le compositeur.
app Lancement d'unité d'application (avec prise en charge des entrées de bureau).
check Effectue des vérifications d'état (pour les scripts et les informations).
aux Fonctions techniques à utiliser dans les unités.

Consultez les sous-sections correspondantes de SOUS-COMMANDES ci-dessous pour plus d'informations.

L'aide pour chaque sous-commande est accessible en exécutant "uwsm {sous-commande} -h".

CONFIGURATION

Fichiers

Dans la hiérarchie de configuration XDG :

uwsm/env
uwsm/env-${compositeur} Environnement (shell) à sourcer pour la session graphique. Sourcé depuis des répertoires de priorité croissante, dans chaque répertoire, le fichier commun est sourcé en premier, puis les fichiers suffixés dans l'ordre des éléments listés dans la variable XDG_CURRENT_SESSION (en minuscules).
uwsm/default-id Stocke l'ID de l'entrée de bureau du compositeur par défaut.

Le fallback est également étendu à la partie système de la hiérarchie des données XDG, cela peut être utilisé pour les valeurs par défaut au niveau de la distribution.

Variables d'environnement

UWSM_UNIT_RUNG (run|home)
Quel niveau de la hiérarchie systemd/user/ gérer pour les fichiers d'unité et de remplacement générés : $XDG_RUNTIME_DIR ou $XDG_CONFIG_HOME.
UWSM_NO_TWEAKS (valeur booléenne)
Supprime et ne génère pas de remplacements de configuration pour d'autres logiciels.
UWSM_FINALIZE_VARNAMES (noms des variables d'environnement séparés par des espaces)
Variables supplémentaires pour "uwsm finalize".
UWSM_WAIT_VARNAMES (noms des variables d'environnement séparés par des espaces)
Variables à attendre dans l'environnement d'activation avant de passer à la session graphique (en plus de WAYLAND_DISPLAY).
UWSM_WAIT_VARNAMES_TIMEOUT (valeur entière)
Secondes d'attente pour l'apparition des variables dans l'environnement d'activation. Essentiellement, délai de démarrage (par défaut : 10).
UWSM_WAIT_VARNAMES_SETTLETIME (valeur flottante)
Secondes de pause après que toutes les variables attendues aient été trouvées dans l'environnement d'activation (par défaut : 0.2).
UWSM_APP_UNIT_TYPE (scope|service)
Type d'unité par défaut pour le lancement des applications (par défaut : scope).
UWSM_SILENT_START (valeur entière ou booléenne)
True ou 1 pour inhiber les messages de sortie standard de uwsm start. 2 pour inhiber également les avertissements.
DEBUG (valeur entière ou booléenne)
True ou un nombre positif pour afficher les informations de débogage sur stderr.

APERÇU DU FONCTIONNEMENT

Intégration de la séquence de connexion

uwsm peut être lancé en utilisant un exec conditionnel dans le profil du shell pour remplacer le shell de connexion (voir la section Intégration du profil shell).

Alternativement, la commande "uwsm start ..." peut être placée dans une entrée de bureau de session Wayland pour être lancée par un gestionnaire d'affichage (voir la section Utilisation dans une entrée de bureau).

Sélection du compositeur

uwsm peut exécuter une ligne de commande de compositeur arbitraire ou une entrée de bureau par son ID (la spécification d'un ID d'action est également prise en charge).

L'entrée de bureau peut également être sélectionnée via un menu whiptail (voir la section de la sous-commande select).

Démarrage

Voir la section de la sous-commande start pour la syntaxe de la commande.

UWSM utilise un ensemble d'unités liées aux cibles de session utilisateur standard :

•
wayland-session-pre@.target (liée à graphical-session-pre.target)
•
wayland-wm-env@.service (service de préchargement d'environnement)
•
wayland-session@.target (liée à graphical-session.target)
•
wayland-wm@.service (service pour le compositeur sélectionné)
  • wayland-session-xdg-autostart@.target (liée à xdg-desktop-autostart.target)
  • wayland-session-shutdown.target (entre en conflit avec les cibles ci-dessus pour l'arrêt)
  • wayland-session-bindpid@.service (interrupteur de session suivant le PID)
  • wayland-session-waitenv.service (retarde la session graphique jusqu'à ce que les variables apparaissent)

L'ID du compositeur (ID de l'entrée de bureau ou nom de l'exécutable) devient le spécificateur pour toutes les unités à modèle.

Au stade de graphical-session-pre.target, l'environnement sauvegardé du contexte "uwsm start" est chargé (ou le profil du shell POSIX est sourcé), les fichiers d'environnement uwsm sont sourcés. Le delta est exporté vers les environnements d'activation systemd et D-Bus par le service de préchargement d'environnement et est marqué pour nettoyage au stade de l'arrêt. Le contexte shell du préchargeur a, pour des raisons pratiques, la variable IN_UWSM_ENV_PRELOADER définie à true.

Au stade de graphical-session.target (avant cela), l'unité principale du compositeur wayland-wm@${ID}.service et le service wayland-session-waitenv.service sont démarrés.

Le compositeur devrait au minimum placer la variable WAYLAND_DISPLAY dans l'environnement d'activation systemd. Cela déclenchera la logique de finalisation automatique d'uwsm. Sans WAYLAND_DISPLAY dans l'environnement d'activation, le démarrage échouera par délai d'attente en 10 secondes.

La finalisation manuelle est possible en exécutant "uwsm finalize" (voir la section de la sous-commande finalize), également en combinaison avec le réglage des variables UWSM_WAIT_VARNAMES et UWSM_WAIT_VARNAMES_SETTLETIME (voir la section Variables d'environnement).

L'activation réussie de l'unité du compositeur et l'existence de WAYLAND_DISPLAY dans l'environnement d'activation permettront à graphical-session.target d'être déclaré atteint.

Enfin, xdg-desktop-autostart.target est activé.

Dans la session

Il est fortement recommandé de configurer le compositeur ou le lanceur d'applications pour lancer les applications en tant que scopes ou services dans des slices de session utilisateur spéciales (app.slice, background.slice, session.slice). uwsm fournit des slices imbriqués personnalisés pour que les applications résident et soient terminées à la fin de la session :

  • app-graphical.slice
  • background-graphical.slice
  • session-graphical.slice

Un utilitaire de sous-commande app est fourni pour gérer

Toutes les invocations de **systemd-run** pour vous (voir la section de la sous-commande *app*). APP DAEMON

Fourni sous le nom wayland-wm-app-daemon.service pour être démarré à la demande.

Le daemon reçoit les arguments d'application du tube ${XDG_RUNTIME_DIR}/uwsm-app-daemon-in. Les arguments résultants sont formatés en code shell et écrits dans le tube ${XDG_RUNTIME_DIR}/uwsm-app-daemon-out.

Les arguments sont censés être délimités par \0, le \0 initial est supprimé. Une commande est reçue par écriture+fermeture.

Le premier argument détermine le comportement :

  • app le reste est traité de la même manière que dans "uwsm app"
  • ping juste "pong" est retourné
  • stop le daemon est arrêté

Les commandes uniques sont précédées de exec, les commandes itérées sont assemblées avec un & final pour chacune, suivi de wait.

Le but de tout cela est de sauter toutes les routines coûteuses de démarrage et d'importation de Python qui ralentissent les choses à chaque fois que "uwsm app" est appelé. Au lieu de cela, le daemon le fait une fois, puis écoute les requêtes, tandis qu'un simple script shell peut envoyer des arguments vers un tube et exécuter le code reçu d'un autre via eval, ce qui est beaucoup plus rapide.

Le script le plus simple est :

#!/bin/sh
printf '0%s' app "$@" > "${XDG_RUNTIME_DIR}/uwsm-app-daemon-in"
IFS='' read -r cmd < "${XDG_RUNTIME_DIR}/uwsm-app-daemon-out"
eval "$cmd"

Le client script uwsm-app fourni est un peu plus intelligent : il peut démarrer le daemon, appliquer des délais d'attente et prendre en charge les sauts de ligne dans les arguments retournés.

INTÉGRATION DU PROFIL SHELL

Pour lancer uwsm automatiquement à la connexion, ajoutez une des constructions ci-dessous (ou similaire) à votre profil shell.

Ceci demande de sélectionner un compositeur (ou de refuser et de continuer avec le shell de connexion) lors de la connexion sur le VT 1 :

if uwsm may-start && uwsm select; then
	exec systemd-cat -t uwsm_start uwsm start default
fi

Ceci démarre simplement un compositeur spécifique en fonction du VT actif :

if uwsm may-start 1; then
	exec systemd-cat -t uwsm_start uwsm start sway.desktop
elif uwsm may-start 2; then
	exec systemd-cat -t uwsm_start uwsm start labwc.desktop
fi

Utiliser "uwsm check may-start" comme condition est essentiel, non seulement pour empêcher les tentatives de démarrage accidentelles là où elles ne sont pas attendues, mais aussi parce que le démarrage peut impliquer le sourcing du profil shell, ce qui pourrait entraîner des boucles désagréables.

Voir la section sur la sous-commande check pour des informations sur le vérificateur may-start.

exec permet à uwsm de remplacer le shell de connexion afin de se lier correctement à la session utilisateur et de gérer la terminaison de session.

"systemd-cat -t uwsm_start" (facultatif) exécute la commande qui lui est donnée (uwsm) avec son stdout et son stderr connectés au journal systemd, étiquetés avec l'identifiant "uwsm_start". Voir systemd-cat(1) pour plus d'options.

UTILISATION DANS UNE ENTRÉE DE BUREAU

Pour lancer uwsm à partir d'un gestionnaire d'affichage/connexion, "uwsm start" peut être utilisé à l'intérieur des entrées de bureau. Exemple /usr/local/share/wayland-sessions/my-compositor.desktop :

[Desktop Entry]
Name=Mon compositeur (avec UWSM)
Comment=Mon compositeur cool
Exec=uwsm start -N "Mon compositeur" -D mycompositor -C "Mon compositeur cool" mywm
DesktopNames=mycompositor
Type=Application

Points à garder à l'esprit :

  • Pour la cohérence, les arguments de ligne de commande doivent refléter les clés de l'entrée
  • La commande dans Exec= doit commencer par "uwsm start"
  • Elle ne doit pas pointer vers elle-même (en tant que combinaison de l'ID de l'entrée de bureau et de l'ID de l'action)
  • Elle ne doit pas pointer vers un ID d'entrée de bureau et un ID d'action qui utilisent également `uwsm`

Potentiellement, de telles entrées peuvent être trouvées et utilisées par uwsm lui-même, c'est-à-dire dans une situation d'intégration de profil shell, ou lorsqu'elles sont lancées manuellement. Le respect des principes ci-dessus garantit que uwsm se reconnaîtra correctement et analysera les arguments demandés à l'intérieur de l'entrée sans aucun effet secondaire.
