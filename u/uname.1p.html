UNAME(1P) Manuel du programmeur POSIX UNAME(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

uname — renvoyer le nom du système

SYNTAXE

uname [-amnrsv]

DESCRIPTION

Par défaut, l'utilitaire uname écrit le nom du système d'exploitation sur la sortie standard. Lorsque des options sont spécifiées, des symboles représentant une ou plusieurs caractéristiques du système sont écrits sur la sortie standard. Le format et le contenu des symboles sont définis par l'implémentation. Sur les systèmes conformes au volume Interfaces Système de POSIX.1‐2017, les symboles écrits sont ceux pris en charge par la fonction uname() telle que définie dans le volume Interfaces Système de POSIX.1‐2017.

OPTIONS

L'utilitaire uname doit se conformer au volume Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-a
Se comporte comme si toutes les options -mnrsv avaient été spécifiées.
-m
Écrit le nom du type de matériel sur lequel le système s'exécute sur la sortie standard.
-n
Écrit le nom de ce nœud dans un réseau de communication défini par l'implémentation.
-r
Écrit le niveau de version actuel de l'implémentation du système d'exploitation.
-s
Écrit le nom de l'implémentation du système d'exploitation.
-v
Écrit le niveau de version actuel de cette version de l'implémentation du système d'exploitation.

Si aucune option n'est spécifiée, l'utilitaire uname écrit le nom du système d'exploitation, comme si l'option -s avait été spécifiée.

OPÉRANDES

Aucun.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de uname :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Par défaut, la sortie est une seule ligne du format suivant :

"%s\n", <sysname>

Si l'option -a est spécifiée, la sortie est une seule ligne du format suivant :

"%s %s %s %s %s\n", <sysname>, <nodename>, <release>,
    <version>, <machine>

Des symboles supplémentaires définis par l'implémentation peuvent être écrits ; tous ces symboles seront écrits à la fin de la ligne de sortie avant le <newline>.

Si des options sont spécifiées pour sélectionner différentes combinaisons de symboles, seuls ces symboles seront écrits, dans l'ordre indiqué ci-dessus pour l'option -a. Si un symbole n'est pas sélectionné pour l'écriture, les caractères d'espacement suivants correspondants ne seront pas non plus écrits.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard est utilisée uniquement pour les messages diagnostiques.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront renvoyées :

 0
Les informations demandées ont été correctement écrites.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Notez que les symboles peuvent contenir des caractères d'<espace> embarqués, ce qui peut affecter les algorithmes d'analyse si plusieurs options sont sélectionnées pour la sortie.

Le nom du nœud est généralement un nom que le système utilise pour s'identifier pour l'adressage de la communication inter-systèmes.

EXEMPLES

La commande suivante :

uname -sr

écrit le nom du système d'exploitation et le niveau de version, séparés par un ou plusieurs caractères d'<espace>.

JUSTIFICATION

Il a été suggéré que cet utilitaire ne peut pas être utilisé de manière portable car le format des symboles est défini par l'implémentation. Le groupe de travail POSIX.1 n'a pas pu parvenir à un consensus sur la définition de ces formats dans la fonction sous-jacente uname(), et il n'y avait aucune attente que ce volume de POSIX.1‐2017 réussisse davantage. Certaines applications peuvent encore trouver cet utilitaire historique utile. Par exemple, les symboles pourraient être utilisés pour les entrées de journal du système ou pour la comparaison avec des entrées de l'opérateur ou de l'utilisateur.
