UTF-8(7) Manuel d'informations diverses UTF-8(7)

NOM

UTF-8 - un encodage Unicode multibyte compatible ASCII

DESCRIPTION

La table de caractères Unicode 3.0 occupe un espace de code de 16 bits. L'encodage Unicode le plus évident (connu sous le nom de UCS-2) consiste en une séquence de mots de 16 bits. De telles chaînes peuvent contenir — dans le cadre de nombreux caractères de 16 bits — des octets tels que '\0' ou '/', qui ont une signification spéciale dans les noms de fichiers et autres arguments de fonctions de la bibliothèque C. De plus, la majorité des outils UNIX s'attendent à des fichiers ASCII et ne peuvent pas lire des mots de 16 bits comme des caractères sans modifications majeures. Pour ces raisons, UCS-2 n'est pas un encodage externe approprié pour Unicode dans les noms de fichiers, les fichiers texte, les variables d'environnement, etc. L'ensemble de caractères universel ISO/IEC 10646 (UCS), un sur-ensemble d'Unicode, occupe un espace de code encore plus grand — 31 bits — et l'encodage UCS-4 évident pour celui-ci (une séquence de mots de 32 bits) présente les mêmes problèmes.

L'encodage UTF-8 d'Unicode et d'UCS n'a pas ces problèmes et est la manière courante dont Unicode est utilisé sur les systèmes d'exploitation de type UNIX.

Propriétés

L'encodage UTF-8 a les propriétés intéressantes suivantes :

•
Les caractères UCS de 0x00000000 à 0x0000007f (les caractères US-ASCII classiques) sont encodés simplement comme les octets 0x00 à 0x7f (compatibilité ASCII). Cela signifie que les fichiers et les chaînes contenant uniquement des caractères ASCII 7 bits ont le même encodage en ASCII et en UTF-8.
•
Tous les caractères UCS supérieurs à 0x7f sont encodés comme une séquence multibyte ne contenant que des octets dans la plage 0x80 à 0xfd, de sorte qu'aucun octet ASCII ne peut apparaître comme faisant partie d'un autre caractère et il n'y a pas de problèmes avec, par exemple, '\0' ou '/'.
•
L'ordre de tri lexicographique des chaînes UCS-4 est préservé.
•
Tous les codes UCS possibles de 2^31 peuvent être encodés en utilisant UTF-8.
•
Les octets 0xc0, 0xc1, 0xfe et 0xff ne sont jamais utilisés dans l'encodage UTF-8.
•
Le premier octet d'une séquence multibyte représentant un seul caractère UCS non-ASCII est toujours dans la plage 0xc2 à 0xfd et indique la longueur de cette séquence multibyte. Tous les octets suivants d'une séquence multibyte sont dans la plage 0x80 à 0xbf. Cela permet une resynchronisation facile et rend l'encodage sans état et robuste contre les octets manquants.
•
Les caractères UCS encodés en UTF-8 peuvent avoir jusqu'à six octets de longueur, cependant la norme Unicode ne spécifie aucun caractère au-dessus de 0x10ffff, donc les caractères Unicode ne peuvent avoir que jusqu'à quatre octets de long en UTF-8.

Encodage

Les séquences d'octets suivantes sont utilisées pour représenter un caractère. La séquence à utiliser dépend du numéro de code UCS du caractère :

0x00000000 - 0x0000007F :
0xxxxxxx
0x00000080 - 0x000007FF :
110xxxxx 10xxxxxx
0x00000800 - 0x0000FFFF :
1110xxxx 10xxxxxx 10xxxxxx
0x00010000 - 0x001FFFFF :
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
0x00200000 - 0x03FFFFFF :
111110xx 10xxxxxx 10xxxxxx 10xxxxxx 10xxxxxx
0x04000000 - 0x7FFFFFFF :
1111110x 10xxxxxx 10xxxxxx 10xxxxxx 10xxxxxx 10xxxxxx

Les positions de bits xxx sont remplies avec les bits du numéro de code de caractère dans sa représentation binaire, bit de poids fort en premier (big-endian). Seule la séquence multibyte la plus courte possible pouvant représenter le numéro de code du caractère peut être utilisée.

Les valeurs de code UCS 0xd800–0xdfff (substituts UTF-16) ainsi que 0xfffe et 0xffff (non-caractères UCS) ne doivent pas apparaître dans les flux UTF-8 conformes. Conformément à la RFC 3629, aucun point au-dessus de U+10FFFF ne doit être utilisé, ce qui limite les caractères à quatre octets.

Exemple

Le caractère Unicode 0xa9 = 1010 1001 (le symbole de copyright) est encodé en UTF-8 comme

11000010 10101001 = 0xc2 0xa9

et le caractère 0x2260 = 0010 0010 0110 0000 (le symbole « non égal ») est encodé comme :

11100010 10001001 10100000 = 0xe2 0x89 0xa0

Notes d'application

Les utilisateurs doivent sélectionner une locale UTF-8, par exemple avec

export LANG=fr_FR.UTF-8

afin d'activer le support UTF-8 dans les applications.

Les logiciels qui doivent être conscients de l'encodage de caractères utilisé doivent toujours définir la locale avec par exemple

setlocale(LC_CTYPE, "")

et les programmeurs peuvent alors tester l'expression

strcmp(nl_langinfo(CODESET), "UTF-8") == 0

pour déterminer si une locale UTF-8 a été sélectionnée et si, par conséquent, toutes les entrées/sorties standard en texte brut, la communication avec le terminal, le contenu des fichiers texte, les noms de fichiers et les variables d'environnement sont encodés en UTF-8.

Les programmeurs habitués aux encodages à octet unique tels que US-ASCII ou ISO/IEC 8859 doivent savoir que deux hypothèses faites jusqu'alors ne sont plus valides dans les locales UTF-8. Premièrement, un octet unique ne correspond plus nécessairement à un caractère unique. Deuxièmement, étant donné que les émulateurs de terminaux modernes en mode UTF-8 prennent également en charge les caractères double largeur chinois, japonais et coréens ainsi que les caractères combinants non espacés, l'affichage d'un caractère unique ne fait pas nécessairement avancer le curseur d'une position comme c'était le cas en ASCII. Les fonctions de bibliothèque telles que mbsrtowcs(3) et wcswidth(3) doivent être utilisées aujourd'hui pour compter les caractères et les positions du curseur.

La séquence ESC officielle pour passer d'un schéma d'encodage ISO/IEC 2022 (tel qu'utilisé par exemple par les terminaux VT100) à UTF-8 est ESC % G (« \x1b%G »). La séquence de retour correspondante d'UTF-8 à ISO/IEC 2022 est ESC % @ (« \x1b%@ »). Les autres séquences ISO/IEC 2022 (telles que celles pour changer les ensembles G0 et G1) ne sont pas applicables en mode UTF-8.

Sécurité

Les normes Unicode et UCS exigent que les producteurs d'UTF-8 utilisent la forme la plus courte possible, par exemple, produire une séquence à deux octets avec le premier octet 0xc0 est non conforme. Unicode 3.1 a ajouté l'exigence que les programmes conformes ne doivent pas accepter les formes non les plus courtes dans leur entrée. C'est pour des raisons de sécurité : si l'entrée de l'utilisateur est vérifiée pour d'éventuelles violations de sécurité, un programme pourrait ne vérifier que la version ASCII de « /../ » ou « ; » ou NUL et ignorer qu'il existe de nombreuses façons non-ASCII de représenter ces choses dans un encodage UTF-8 non le plus court.

Normes

ISO/IEC 10646-1:2000, Unicode 3.1, RFC 3629, Plan 9.

VOIR AUSSI

NOM

utf8 — Encodage de caractères Unicode (UTF-8)

DESCRIPTION

L'encodage de caractères Unicode, UTF-8, est un jeu de caractères qui peut représenter tous les caractères Unicode. Il est devenu le jeu de caractères standard sur la plupart des systèmes d'exploitation Unix-like, y compris Linux.

UTF-8 est un encodage à longueur variable, ce qui signifie que les caractères peuvent être représentés par un nombre variable d'octets. Les caractères ASCII de base sont représentés par un seul octet, tandis que les caractères plus complexes sont représentés par plusieurs octets. Cette conception permet la rétrocompatibilité avec ASCII, car tous les caractères ASCII valides sont également des séquences UTF-8 valides d'un seul octet.

Les principaux avantages d'UTF-8 sont sa capacité à représenter tous les caractères Unicode, sa rétrocompatibilité avec ASCII et son utilisation efficace de l'espace de stockage pour la plupart des textes couramment utilisés (qui sont souvent dominés par des caractères ASCII ou latins).

Les commandes et utilitaires GNU courants, tels que ls, grep, sed, awk, bash, perl, etc., prennent tous en charge UTF-8. Il est fortement recommandé d'utiliser UTF-8 pour les nouveaux projets et pour la configuration du système.

Pour configurer votre système pour utiliser UTF-8, vous devrez généralement modifier les paramètres régionaux de votre système. Cela implique généralement de modifier le fichier /etc/locale.gen pour décommenter les lignes appropriées (par exemple, en_US.UTF-8 UTF-8) et d'exécuter la commande locale-gen. Ensuite, vous pouvez définir la variable d'environnement LANG ou LC_ALL sur la valeur appropriée (par exemple, LANG=en_US.UTF-8).
