UPDMAP(1) Commandes utilisateur UPDMAP(1)

NOM

updmap - gérer les cartes de polices TeX
updmap-sys - gérer les cartes de polices TeX, au niveau système
updmap-user - gérer les cartes de polices TeX, par utilisateur

SYNTAXE

updmap [-user|-sys] [OPTION] ... [COMMANDE]
updmap-user [OPTION] ... [COMMANDE]
updmap-sys [OPTION] ... [COMMANDE]

DESCRIPTION

updmap version r65932 (2023-02-19 21:49:48 +0100)

Met à jour les fichiers de carte de polices par défaut utilisés par pdftex et dvipdfm(x) (pdftex.map), dvips (psfonts.map), et optionnellement pxdvi, tels que déterminés par tous les fichiers de configuration updmap.cfg (généralement ceux retournés par l'exécution de "kpsewhich --all updmap.cfg", mais voir ci-dessous).

Entre autres choses, ces fichiers de carte sont utilisés pour déterminer quelles polices doivent être utilisées comme bitmaps et lesquelles comme contours, et pour déterminer quels fichiers de polices sont inclus, généralement sous forme de sous-ensembles, dans la sortie PDF ou PostScript.

updmap-sys (ou updmap -sys) est destiné à affecter la configuration globale du système, tandis que updmap-user (ou updmap -user) affecte uniquement les fichiers de configuration personnels, remplaçant ainsi les fichiers système.

Par conséquent, une fois qu'updmap-user a été exécuté, même une seule fois, l'exécution d'updmap-sys n'a plus aucun effet. updmap-sys émet un avertissement à ce sujet, car c'est rarement souhaitable. Voir https://tug.org/texlive/scripts-sys-user.html pour plus de détails.

Par défaut, la base de données des noms de fichiers TeX (ls-R) est également mise à jour.

Le système updmap est malheureusement compliqué, pour des raisons inhérentes et historiques. Un aperçu général :

- Les fichiers updmap.cfg concernent principalement la liste d'autres fichiers, à savoir les

.maps spécifiques aux polices, dans lesquels chaque ligne donne des informations sur une police TeX (.tfm) différente.

- updmap lit les fichiers updmap.cfg puis concatène les

contenus de ces fichiers .map dans les fichiers de sortie principaux : psfonts.map pour dvips et pdftex.map pour pdftex et dvipdfmx.

- Les fichiers updmap.cfg eux-mêmes sont créés et mis à jour lors de l'installation

des paquets, par l'installeur système, le gestionnaire de paquets, ou manuellement, et non (par défaut) par updmap.

La sortie principale :

La sortie principale d'updmap est constituée des fichiers contenant les lignes de carte de polices individuelles que les pilotes (dvips, pdftex, etc.) lisent pour gérer les polices.
Les fichiers de carte pour dvips (psfonts.map) et pdftex et dvipdfmx (pdftex.map) sont écrits dans TEXMFVAR/fonts/map/updmap/{dvips,pdftex}/.
En outre, des informations sur les polices Kanji sont écrites dans TEXMFVAR/fonts/map/updmap/dvipdfmx/kanjix.map, et optionnellement dans TEXMFVAR/fonts/map/updmap/pxdvi/xdvi-ptex.map. Ceux-ci sont réservés aux Kanji et ne sont pas comme les autres fichiers de carte. dvipdfmx lit pdftex.map pour les entrées de carte des polices non-Kanji.
Si aucune option n'est donnée, donc que l'invocation est simplement "updmap-user" ou "updmap-sys", ces fichiers de sortie sont toujours recréés.
Sinon, si une option telle que --enable ou --disable est donnée, les fichiers de sortie sont recréés si la liste des fichiers de carte activés (provenant de updmap.cfg) a changé. L'option --force outrepasse ce comportement, recréant toujours les fichiers de sortie.

Explication des types de carte :

Le type normal est Map.
La seule différence entre Map et MixedMap est que les entrées MixedMap ne sont pas ajoutées à psfonts_pk.map. Le but est d'aider les utilisateurs ayant des appareils qui rendent les polices vectorielles Type 1 moins bien que les polices bitmaps Type 3 réglées au mode. Ainsi, MixedMap est utilisé pour les polices disponibles à la fois en Type 1 et Metafont.
Les entrées KanjiMap sont ajoutées à psfonts_t1.map et kanjix.map.

EXEMPLES

Pour voir quels paquets de polices sont actuellement activés (globalement et personnellement) :

updmap --listmaps

Pour activer une police spécifique (par exemple, une police de type 1) :

updmap-user --enable t1fonts

Pour désactiver une police (par exemple, une police de type 1) :

updmap-user --disable t1fonts

Pour voir toutes les polices disponibles qui peuvent être activées :

updmap --listavailablemaps

Pour activer une police spécifique et mettre à jour les fichiers de carte nécessaires :

updmap-sys --enable t1fonts
updmap-sys --enable pfblogo

Pour désactiver les polices de type 1 et mettre à jour les fichiers de carte :

updmap-user --disable t1fonts

Pour activer toutes les polices disponibles (cela peut être beaucoup !) :

updmap-user --syncwithtrees

Pour désactiver les cartes non disponibles (par exemple, si vous avez supprimé un paquet de polices) :

updmap-user --syncwithtrees

Pour modifier la configuration globale afin que dvips utilise les polices vectorielles (plutôt que les bitmaps) par défaut :

updmap-sys --setoption dvipsPreferOutline true

Pour désactiver l'intégration des 14 polices PostScript de base dans les fichiers PDF générés par pdftex :

updmap-user --setoption pdftexDownloadBase14 false

NOTE

Le comportement exact d'updmap et les emplacements des fichiers de configuration peuvent varier légèrement en fonction de la distribution TeX installée.

Elles fonctionnent en modifiant le fichier de cartes par défaut que les programmes lisent, elles peuvent donc être substituées en spécifiant des options en ligne de commande ou des fichiers de configuration aux programmes, comme expliqué au début d'updmap.cfg.

Les correspondants pour les polices chinoises simplifiées, chinoises traditionnelles et coréennes sont scEmbed, tcEmbed et koEmbed respectivement.

ENVIRONNEMENT

Explication des arbres et des fichiers normalement utilisés :

Si --cnffile est spécifié en ligne de commande (peut être donné plusieurs fois), sa(ses) valeur(s) est(sont) utilisée(s). Sinon, updmap lit tous les fichiers updmap.cfg trouvés en exécutant `kpsewhich -all updmap.cfg', dans l'ordre retourné par kpsewhich (qui est l'ordre des arbres définis dans texmf.cnf).
Dans les deux cas, si plusieurs fichiers updmap.cfg sont trouvés, toutes les cartes mentionnées dans tous les fichiers updmap.cfg sont fusionnées.
Ainsi, si des fichiers updmap.cfg sont présents dans tous les arbres, et que la disposition par défaut est utilisée telle qu'expédiée avec TeX Live, les fichiers suivants sont lus, dans l'ordre donné.
Pour updmap-sys :
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
Pour updmap-user :
TEXMFCONFIG    $HOME/.texliveYYYY/texmf-config/web2c/updmap.cfg
TEXMFVAR       $HOME/.texliveYYYY/texmf-var/web2c/updmap.cfg
TEXMFHOME      $HOME/texmf/web2c/updmap.cfg
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
(où YYYY est la version de la distribution TeX Live).
Selon les actions, updmap peut écrire dans l'un des fichiers donnés ou créer un nouveau updmap.cfg, décrit plus loin.

Où et quelles modifications d'updmap.cfg sont sauvegardées :

Lorsqu'aucune option n'est donnée, les fichiers updmap.cfg sont seulement lus, pas écrits. C'est lorsqu'une option --setoption, --enable ou --disable est spécifiée qu'un updmap.cfg doit être mis à jour. Dans ce cas :
1) Si des fichiers de configuration sont donnés en ligne de commande, alors le premier donné est utilisé pour sauvegarder toutes les modifications.
2) Si les fichiers de configuration sont pris de la sortie de kpsewhich, alors l'algorithme est plus complexe :
2a) Si $TEXMFCONFIG/web2c/updmap.cfg ou $TEXMFHOME/web2c/updmap.cfg apparaît dans la liste des fichiers utilisés, alors celui listé en premier par kpsewhich --all (équivalent- ment, celui retourné par kpsewhich updmap.cfg) est utilisé.
2b) Si aucun des deux ci-dessus n'est présent et que des modifications sont apportées, un nouveau fichier de configuration est créé dans $TEXMFCONFIG/web2c/updmap.cfg.
En général, l'idée est que si l'utilisateur ne peut pas écrire dans un fichier de configuration donné, un fichier de niveau supérieur peut être utilisé. Ainsi, les paramètres de la distribution peuvent être outrepassés à l'échelle du système en utilisant TEXMFLOCAL, et les paramètres système peuvent être outrepassés à nouveau dans le TEXMFHOME ou le TEXMFCONFIG d'un utilisateur particulier.

Résolution des définitions multiples d'une police :

Si une police est définie dans plusieurs fichiers de cartes, la définition provenant du premier fichier updmap.cfg listé est utilisée. Si une police est définie plusieurs fois dans le même fichier de cartes, une est choisie arbitrairement. Dans les deux cas, un avertissement est émis.

Désactivation des cartes :

Les fichiers updmap.cfg avec une priorité plus élevée (listés plus tôt) peuvent désactiver les cartes mentionnées dans les fichiers updmap.cfg de priorité inférieure (listés plus tard) en écrivant, par exemple,
#! Map mapname.map
ou
#! MixedMap mapname.map
dans le fichier updmap.cfg de priorité supérieure.
(Le #! doit être au
début de la ligne, avec au moins un espace ou une tabulation ensuite, et des espaces blancs entre chaque mot de la liste.)
À titre d'exemple, supposons que vous ayez une copie des polices MathTime Pro et que vous souhaitiez désactiver la version Belleek des polices ; c'est-à-dire, désactiver la carte belleek.map. Vous pouvez créer le fichier $TEXMFCONFIG/web2c/updmap.cfg avec le contenu
#! Map belleek.map Map mt-plus.map Map mt-yy.map
et appeler updmap.

Liste des cartes :

Les deux options --listmaps et --listavailablemaps listent toutes les cartes définies dans n'importe lequel des fichiers updmap.cfg (pour --listmaps), et seulement celles réellement trouvées sur le système (pour --listavailablemaps). Le format de sortie est une ligne par carte de polices, avec les champs suivants séparés par des tabulations : carte, type (Map, MixedMap, KanjiMap), statut (activé, désactivé), origine (le fichier updmap.cfg où elle est mentionnée, ou 'builtin' pour les trois cartes de base).
Dans le cas de --listmaps, il peut y avoir un champ supplémentaire (séparé par une tabulation) contenant '(not available)' pour les fichiers de cartes qui ne peuvent pas être trouvés.

updmap-user vs. updmap-sys :

Lorsque updmap-sys est exécuté, TEXMFSYSCONFIG et TEXMFSYSVAR sont utilisés à la place de TEXMFCONFIG et TEXMFVAR, respectivement. C'est la principale différence entre updmap-sys et updmap-user.
D'autres emplacements peuvent être utilisés si vous les spécifiez en ligne de commande, si ces arbres n'existent pas, ou si vous n'utilisez pas la distribution TeX Live d'origine.

Pour voir les emplacements précis des divers fichiers qui seront lus et écrits, donnez l'option -n (ou lisez le code source).

Configuration files for updmap(1):

The default configuration file. It is read by updmap(1) and updmap-sys(1). If this file is not found, the system default is used.

The system-wide configuration file. This file is only read by updmap-sys(1). If this file is not found, the system default is used.
