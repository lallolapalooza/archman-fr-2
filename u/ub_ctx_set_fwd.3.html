DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui fait de la mise en cache et de la validation DNSSEC. Ceci est l'API de la bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et inversement, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour maintenir le contexte entre les appels. L'utilisateur doit la maintenir, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La créer à nouveau supprime toute configuration précédente (tels que les clés de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement threadé (ainsi que dans un environnement non threadé). De plus, la résolution (et la validation) peuvent être effectuées de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne de l'appel immédiatement, de sorte que le traitement puisse continuer, tandis que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec des valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer l'opération asynchrone si vous utilisez la bibliothèque openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou ultérieur utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les rappels ne sont pas appelés pour elles.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier l'une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui récupère une valeur d'option. Certaines options ne peuvent pas être récupérées, et d'autres retournent une liste séparée par des sauts de ligne. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée (free(2)) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine à laquelle les requêtes DNS doivent être transmises, le résolveur de cache à utiliser. Adresse IP4 ou IP6. Transmet toutes les requêtes DNS à cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas capable de DNSSEC, la validation peut échouer. Peut être appelée plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. Pour le moment, il est uniquement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Définissez isprime à vrai si vous configurez des indices racines avec. Sinon, similaire à l'élément zone stub du fichier de configuration d'unbound. Peut être appelée plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. Pour le moment, il est uniquement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_set_tls
Active le DNS sur TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. Pour le moment, il est uniquement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_resolvconf
Par défaut, les serveurs racines sont interrogés et le mode de résolution complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des serveurs de noms à utiliser à partir du nom de fichier donné. Habituellement "/etc/resolv.conf". Utilise ces serveurs de noms comme proxies de cache. S'ils ne supportent pas DNSSEC, la validation peut échouer. Seuls les serveurs de noms sont pris en compte, le domaine de recherche, ndots et d'autres paramètres de resolv.conf(5) sont ignorés. Si fname est NULL, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré au niveau du système est choisi à la place). Pour le moment, il est uniquement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Habituellement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname est NULL, "/etc/hosts" est utilisé (si sous Windows, etc/hosts de WINDIR est choisi à la place). Pour le moment, il est uniquement possible de définir la configuration avant la première résolution.

Le format est une chaîne de caractères, similaire au format de fichier de zone, [nom de domaine] [type] [contenu rdata]. Les enregistrements DS et DNSKEY sont acceptés.
    ub_ctx_add_ta_autr
    Ajoute un fichier contenant un point d'ancrage de confiance suivi automatiquement au contexte donné. Passez le nom d'un fichier contenant le point d'ancrage de confiance géré. Vous pouvez créer ce fichier avec unbound-anchor(8) pour le point d'ancrage racine. Vous pouvez également créer un fichier initial avec une ligne contenant un enregistrement DNSKEY ou DS. Si le fichier est accessible en écriture, il est mis à jour lorsque le point d'ancrage de confiance change. À l'heure actuelle, il n'est possible d'ajouter des clés de confiance qu'avant que la première résolution ne soit effectuée.
    ub_ctx_add_ta_file
    Ajoute des points d'ancrage de confiance au contexte donné. Passez le nom d'un fichier contenant des enregistrements DS et DNSKEY au format fichier de zone. À l'heure actuelle, il n'est possible d'ajouter des clés de confiance qu'avant que la première résolution ne soit effectuée.
    ub_ctx_trustedkeys
    Ajoute des points d'ancrage de confiance au contexte donné. Passez le nom d'un fichier de configuration de style bind contenant trusted-keys{}. À l'heure actuelle, il n'est possible d'ajouter des clés de confiance qu'avant que la première résolution ne soit effectuée.
    ub_ctx_debugout
    Définit la sortie des journaux de débogage et d'erreur sur le flux donné. Passez NULL pour désactiver la sortie. La valeur par défaut est stderr. Les noms de fichiers ou l'utilisation de syslog peuvent être activés à l'aide des options de configuration, cette routine sert à utiliser votre propre flux.
    ub_ctx_debuglevel
    Définit la verbosité du débogage pour le contexte. La sortie est dirigée vers stderr. Un niveau de débogage plus élevé donne plus de sortie.
    ub_ctx_async
    Définit un comportement de contexte pour l'action asynchrone. Si réglé sur vrai, active le threading et un appel à ub_resolve_async crée un thread pour gérer le travail en arrière-plan. Si faux, un processus est forké pour gérer le travail en arrière-plan. Les modifications apportées à ce paramètre après des appels à ub_resolve_async n'ont aucun effet (supprimez et recréez le contexte pour changer).
    ub_poll
    Interroge un contexte pour voir s'il y a de nouveaux résultats. Ne pas interroger en boucle, mais extraire le fd ci-dessous pour interroger la disponibilité, puis vérifier, ou attendre en utilisant la routine d'attente. Renvoie 0 s'il n'y a rien à lire, ou une valeur non nulle si un résultat est disponible. Si non nulle, appelez ub_process pour effectuer les rappels.
    ub_wait
    Attend qu'un contexte termine avec des résultats. Appelle ub_process après l'attente pour vous. Après l'attente, il n'y a plus de requêtes asynchrones en suspens.
    ub_fd
    Obtient le descripteur de fichier. Attend qu'il devienne lisible, à ce moment-là les réponses sont retournées par le résolveur de validation asynchrone. Ensuite, appelez ub_process pour continuer le traitement.
    ub_process
    Appelez cette routine pour continuer le traitement des résultats du résolveur de validation (lorsque le fd devient lisible). Effectuera les rappels nécessaires.
    ub_resolve
    Effectue la résolution et la validation du nom cible. Le nom est un nom de domaine sous forme de chaîne de caractères texte terminée par un zéro. Les types et classes rrtype et rrclass sont des codes de type et de classe DNS. La structure de résultat est nouvellement allouée avec les données résultantes.
    ub_resolve_async
    Effectue la résolution et la validation asynchrones du nom cible. Les arguments signifient la même chose que pour ub_resolve, sauf qu'aucune donnée n'est retournée immédiatement, mais un rappel est appelé plus tard. Le rappel reçoit une copie du pointeur mydata, que vous pouvez utiliser pour passer des informations au rappel. Le type de rappel est un pointeur de fonction vers une fonction déclarée comme suit :
    void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

    L'async_id est retourné afin que vous puissiez (à votre discrétion) décider de le suivre et d'annuler la requête si nécessaire. Si vous passez un pointeur NULL, l'async_id n'est pas retourné.

    ub_cancel
    Annule une requête asynchrone en cours. Cela peut renvoyer une erreur si la requête n'existe pas, ou si la requête est déjà en cours de livraison, auquel cas vous pourriez quand même recevoir un rappel pour la requête.
    ub_resolve_free
    Libère le contenu de la structure ub_result après utilisation.
    ub_strerror
    Convertit la valeur d'erreur d'une des fonctions de la bibliothèque unbound en une chaîne de caractères lisible par l'homme.
    ub_ctx_print_local_zones
    Affiche les informations d'autorité locale pour le débogage.
    ub_ctx_zone_add
    Ajoute une nouvelle zone aux informations d'autorité locale, comme l'instruction local-zone de unbound.conf(5).
    ub_ctx_zone_remove
    Supprime une zone des informations d'autorité locale.
    ub_ctx_data_add
    Ajoute des données d'enregistrement de ressources aux informations d'autorité locale, comme l'instruction local-data de unbound.conf(5).
    ub_ctx_data_remove
    Supprime les données d'autorité locale du nom donné.

    STRUCTURE DES DONNÉES DE RÉSULTAT

    Le résultat de la résolution et de la validation DNS est renvoyé sous forme de struct ub_result. La structure de résultat contient les entrées suivantes :

    struct ub_result {
     char* qname;         /* chaîne de caractères, question originale */
     int qtype;           /* code de type demandé */
     int qclass;          /* code de classe demandé */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas de absence de données */
     void* answer_packet; /* paquet réseau complet de réponse */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai si pas de données car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si un échec de sécurité s'est produit */
     char* why_bogus;     /* chaîne avec l'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée en débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

    Si secure et bogus sont tous deux faux, la sécurité n'était pas activée pour le domaine de la requête. Sinon, ils ne sont pas tous les deux vrais, l'un d'eux est vrai.

    VALEURS DE RETOUR

    De nombreuses routines renvoient un code d'erreur. La valeur 0 (zéro) indique qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror renvoie une chaîne terminée par un zéro. ub_ctx_create renvoie NULL en cas d'erreur (un échec malloc). ub_poll renvoie vrai si des informations peuvent être disponibles, faux sinon. ub_fd renvoie un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif en cas de retour de fonction avec échec de lecture de fichier.
