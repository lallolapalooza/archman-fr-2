USB_MODESWITCH(1) Manuel des commandes générales USB_MODESWITCH(1)

NOM

usb_modeswitch - contrôler le mode des périphériques USB « multi-états »

SYNTAXE

usb_modeswitch [-heWQDIvpVPmM23rwKdHSOBGTNALnsRiuagft] [-c nom_fichier]

DESCRIPTION

Plusieurs nouveaux périphériques USB ont leurs pilotes propriétaires pour Windows intégrés, la plupart étant des dongles WWAN et WLAN. Lorsqu'ils sont branchés pour la première fois, ils agissent comme un stockage flash et commencent à installer le pilote Windows à partir de là. Si le pilote est installé, le périphérique de stockage disparaît et un nouveau périphérique, principalement composite (par exemple, avec des ports modem), apparaît.

Sous Linux, dans la plupart des cas, les pilotes sont disponibles sous forme de modules du noyau, tels que « usbserial » ou « option ». Cependant, le périphérique se lie initialement à « usb-storage » par défaut. usb_modeswitch peut alors envoyer un message groupé fourni (très probablement une commande de stockage de masse) au périphérique ; ce message doit être déterminé en analysant les actions du pilote Windows.

Dans certains cas, des commandes de contrôle USB sont utilisées pour la commutation. Ces cas sont gérés par des fonctions personnalisées, et aucun message groupé n'a besoin d'être fourni.

Habituellement, le programme est distribué avec un ensemble de configurations pour de nombreux périphériques connus, ce qui permet une gestion entièrement automatique d'un périphérique lors de son insertion, rendue possible en combinant usb_modeswitch avec le script wrapper usb_modeswitch_dispatcher qui est lancé par le démon udev. Cela nécessite cependant un système de type Linux.

Notez que usb_modeswitch lui-même n'a pas de dépendances spécifiques à Linux.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU, avec les options longues commençant par deux tirets (« -- »). Un résumé des options est inclus ci-dessous.

-h --help
Afficher le résumé des options.
-e --version
Afficher les informations de version et quitter.
-v --default-vendor NUM
ID du vendeur à rechercher (obligatoire), généralement donné sous forme de nombre hexadécimal (exemple : 0x12d1). Chaque périphérique USB est identifié par un numéro officiellement attribué au vendeur par l'association USB et un numéro pour le modèle respectif (ID produit) choisi par le vendeur.
-p --default-product NUM
ID produit à rechercher (obligatoire).
-V --target-vendor NUM
ID du vendeur cible. S'il est fourni, il sera recherché et détecté initialement à des fins d'information. Si la vérification de succès (option -s) est active, il est recommandé de fournir des ID cibles (vendeur/produit) ou une classe cible.
-j --find-mbim
Retourner le numéro de configuration avec l'interface MBIM et quitter.
-P --target-product NUM
ID produit cible.
-b --bus-num NUM
-g --device-num NUM
Si le numéro de bus et de périphérique sont fournis, le traitement d'un périphérique spécifique sur un port USB spécifique est garanti, contrairement à l'utilisation uniquement de l'ID USB. Ceci est important s'il y a plusieurs périphériques similaires sur un système.
-C --target-class NUM
Classe de périphérique cible selon la spécification USB. Certains périphériques conservent leur ID vendeur/produit d'origine après une commutation réussie. Pour éviter qu'ils ne soient traités à nouveau, la classe du périphérique peut être vérifiée. Pour les périphériques non commutés, elle est toujours de 8 (classe de stockage), pour les modems commutés, elle est souvent de 0xff (spécifique au vendeur). En mode composite, la classe de la première interface est surveillée.
-m --message-endpoint NUM
Un point de terminaison spécifique à utiliser pour les transferts de données. À des fins de test uniquement ; les points de terminaison sont généralement déterminés à partir des attributs du périphérique.
-M --message-content CHAINE
Un message groupé à envoyer comme commande de commutation. Fourni sous forme de chaîne hexadécimale.
-2 --message-content2 CHAINE
-3 --message-content3 CHAINE
Messages groupés supplémentaires à envoyer comme commandes de commutation. Fournis sous forme de chaînes hexadécimales. Lorsqu'ils sont utilisés avec des commandes de stockage de masse, il est fortement conseillé de définir --need-response pour se conformer aux spécifications et éviter des erreurs probables.
-w --release-delay <millisecondes>
Après avoir émis tous les messages groupés, attendez le temps donné avant de libérer l'interface. Requis pour certains modems sur les anciens systèmes (surtout après un message EJECT).
-n --need-response
Obsolète. Le CSW est toujours tenté d'être lu après les transferts de stockage de masse. Pas d'inconvénient.
-r --response-endpoint NUM
Essayer de lire la réponse à une commande de stockage à partir de là. À des fins de test uniquement ; les points de terminaison sont généralement déterminés à partir des attributs du périphérique.
-K --std-eject
Appliquer la séquence standard SCSI de « Autoriser le retrait du média » et « Éjecter ». Implique -n. Un 'Message' peut être ajouté avec -M qui sera transmis après la séquence d'éjection. Utilisé par de nombreux modems.
-d --detach-only
Simplement détacher le pilote actuel. Ceci est suffisant pour que certains périphériques précoces basculent avec succès. Sinon, cette fonctionnalité peut être utilisée comme un « scalpel » pour des cas spéciaux, comme séparer le pilote des interfaces individuelles.
-H --huawei-mode
Envoyer un message de contrôle spécial utilisé par les anciens périphériques Huawei.
-J --huawei-new-mode
Envoyer un message groupé spécifique utilisé par tous les périphériques Huawei plus récents.
-X --huawei-alt-mode
Envoyer un message groupé alternatif aux périphériques Huawei.
-S --sierra-mode
Envoyer un message de contrôle spécial utilisé par les périphériques Sierra.
-G --gct-mode
Envoyer un message de contrôle spécial utilisé par les chipsets GCT.
-T --kobil-mode
Envoyer un message de contrôle spécial utilisé par les périphériques Kobil.
-N --sequans-mode
Envoyer un message de contrôle spécial utilisé par le chipset Sequans.
-A --mobileaction-mode
Envoyer un message de contrôle spécial utilisé par le périphérique MobileAction.
-B --qisda-mode
Envoyer un message de contrôle spécial utilisé par les périphériques Qisda.
-E --quanta-mode
Envoyer un message de contrôle spécial utilisé par les périphériques Quanta.
-F --pantech-mode NUM
Envoyer un message de contrôle spécial utilisé par les périphériques Pantech. La valeur NUM sera utilisée dans le message de contrôle comme 'wValue'.
-Z --blackberry-mode
Envoyer un message de contrôle spécial utilisé par certains périphériques Blackberry plus récents.
-S --option-mode
Envoyer un message de contrôle spécial utilisé par tous les périphériques Option.
-O --sony-mode
Appliquer une séquence spéciale utilisée par les périphériques Sony Ericsson. Implique l'option --check-success.
-L --cisco-mode
Envoyer une séquence de messages groupés utilisée par les périphériques Cisco.
-R --reset-usb
Envoyer une commande de réinitialisation USB au périphérique. Peut être combiné avec n'importe quelle méthode de commutation ou utilisé seul. Il est toujours effectué comme dernière étape de toutes les interactions avec le périphérique. Peu de périphériques en ont besoin pour compléter la commutation ; en dehors de cela, cela peut être utile pendant les tests.
-c --config-file NOM_FICHIER
usb_modeswitch(8)

NAME

usb_modeswitch - utility to switch USB 3G/4G modems to standard storage or serial mode

SYNOPSIS

usb_modeswitch [-h|--help] [-v|--version] [-d|--debug] [-w|--verbose] [-q|--quiet] [-c CONFIGFILE|--config CONFIGFILE] [-f STRING|--long-config STRING] [-t|--stdinput] [-D|--sysmode] [-s <seconds>|--check-success <seconds>] [-I|--inquire] [-i NUM|--interface NUM] [-u NUM|--configuration NUM] [-a NUM|--altsetting NUM] [-H ID|--new-heartbeat ID] [-K ID|--reset-disconnect ID] [-W ID|--quirk-reset-disconnect ID] [-e ID|--quirk-quirk-usb-driver ID] [-2 ID|--quirk-lenny-kernel-bug ID] [-3 ID|--quirk-killing-the-kernel ID] [-4 ID|--quirk-kobil-wfs ID] [-5 ID|--quirk-dell-y560-laptop ID] [-6 ID|--quirk-samsung-nc10-laptop ID] [-7 ID|--quirk-option-legacysubdriver ID] [-8 ID|--quirk-zte-backend-driver ID] [-9 ID|--quirk-huawei-lg-firmware-lock ID] [-A ID|--quirk-telia-com-opera-mini-apple ID] [-B ID|--quirk-apple-os-x-10-6-plus ID] [-C ID|--quirk-legacy-sierra-chipset ID] [-E ID|--quirk-no-terminal-server ID] [-F ID|--quirk-reset-after-close ID] [-G ID|--quirk-reset-device ID] [-J ID|--quirk-acer-netbook-a110 ID] [-L ID|--quirk-long-warranty-id ID] [-M ID|--quirk-no-common-rmnet ID] [-N ID|--quirk-no-sync-submit ID] [-P ID|--quirk-option-mfstring-not-supported ID] [-R ID|--quirk-option-not-locked ID] [-S ID|--quirk-no-auto-bcd ID] [-T ID|--quirk-zyxel-evdo-prepaid ID] [-U ID|--quirk-sierra-network-controller ID] [-V ID|--quirk-unusual-init-length ID] [-X ID|--quirk-new-huawei-init-always ID] [-Y ID|--quirk-remove-driver ID] [-Z ID|--quirk-ztemt-is-really-ztedc ID] [BUS:DEVICE]

DESCRIPTION

The usb_modeswitch utility switches USB UMTS/LTE modems from their default "storage mode" (which often makes them appear as a CD-ROM drive) to "modem mode" (which makes them appear as a serial device). This is required on some Linux systems to use the modem with standard connection managers.

The tool works by sending specific USB control messages to the device. The correct sequence of messages is stored in a configuration file, usually located in /etc/usb_modeswitch.d/. The correct configuration is selected based on the vendor and product ID of the USB device.

If no specific device ID is given, usb_modeswitch tries to find an appropriate configuration file based on the currently attached USB devices.

OPTIONS

-h, --help
Show help message and exit.
-v, --version
Show version and exit.
-d, --debug
Enable debug messages. Use multiple times for more output.
-W, --verbose
Print all settings before running and show libusb debug messages.
-q, --quiet
Don't show progress or error messages.
-c CONFIGFILE, --config CONFIGFILE
Use the specified configuration file instead of the default ones in /etc/usb_modeswitch.d/. If the specified file is a directory, it is scanned for configuration files. Use a specific config file. If any ID or switching options are given as command line parameters, this option is ignored. In that case all mandatory parameters have to be provided on the command line
-f STRING, --long-config STRING
Provide device details in config file syntax as a multiline string on the command line
-t, --stdinput
Read the device details in config file syntax from standard input, e.g. redirected from a command pipe (multiline text)
-D, --sysmode
Changes the behaviour of the program slightly. A success message including the effective target device ID is put out and a syslog notice is issued. Mainly for integration with a wrapper script
-s <seconds>, --check-success <seconds>
After switching, keep checking for the result up to the given time. If target IDs or target class were provided, their appearance indicates certain success. Otherwise the disconnection of the original device is rated as likely proof
-I, --inquire
Obsolete. Formerly obtained SCSI attributes, now ignored
-i NUM, --interface NUM
Select initial USB interface (default: 0). Only for testing purposes
-u NUM, --configuration NUM
Select USB configuration (applied after any other possible switching actions)
-a NUM, --altsetting NUM
Select alternative USB interface setting (applied after switching). Mainly for testing
-H ID, --new-heartbeat ID
Set a new device ID that is used for checking the device status after switching.
-K ID, --reset-disconnect ID
Disconnect the device by sending a reset command. The device ID is given as a 4-digit hex number.
-W ID, --quirk-reset-disconnect ID
Workaround for a specific device that requires a disconnect reset. The device ID is given as a 4-digit hex number.
-e ID, --quirk-quirk-usb-driver ID
Workaround for a device that uses a specific USB driver. The device ID is given as a 4-digit hex number.
-2 ID, --quirk-lenny-kernel-bug ID
Workaround for a bug in the Linux kernel 2.6.29. The device ID is given as a 4-digit hex number.
-3 ID, --quirk-killing-the-kernel ID
Workaround for a kernel bug that can cause a system crash. The device ID is given as a 4-digit hex number.
-4 ID, --quirk-kobil-wfs ID
Workaround for Kobil USB devices. The device ID is given as a 4-digit hex number.
-5 ID, --quirk-dell-y560-laptop ID
Workaround for Dell Y560 laptop. The device ID is given as a 4-digit hex number.
-6 ID, --quirk-samsung-nc10-laptop ID
Workaround for Samsung NC10 laptop. The device ID is given as a 4-digit hex number.
-7 ID, --quirk-option-legacysubdriver ID
Workaround for Option modem legacy subdriver. The device ID is given as a 4-digit hex number.
-8 ID, --quirk-zte-backend-driver ID
Workaround for ZTE modem backend driver. The device ID is given as a 4-digit hex number.
-9 ID, --quirk-huawei-lg-firmware-lock ID
Workaround for Huawei and LG modems with firmware lock. The device ID is given as a 4-digit hex number.
-A ID, --quirk-telia-com-opera-mini-apple ID
Workaround for Telia/Com/Opera/Mini/Apple. The device ID is given as a 4-digit hex number.
-B ID, --quirk-apple-os-x-10-6-plus ID
Workaround for Apple OS X 10.6+. The device ID is given as a 4-digit hex number.
-C ID, --quirk-legacy-sierra-chipset ID
Workaround for legacy Sierra chipset. The device ID is given as a 4-digit hex number.
-E ID, --quirk-no-terminal-server ID
Workaround for devices that do not support terminal server mode. The device ID is given as a 4-digit hex number.
-F ID, --quirk-reset-after-close ID
Workaround for devices that require a reset after closing the connection. The device ID is given as a 4-digit hex number.
-G ID, --quirk-reset-device ID
Workaround for devices that require a device reset. The device ID is given as a 4-digit hex number.
-J ID, --quirk-acer-netbook-a110 ID
Workaround for Acer Netbook A110. The device ID is given as a 4-digit hex number.
-L ID, --quirk-long-warranty-id ID
Workaround for devices with a long warranty ID. The device ID is given as a 4-digit hex number.
-M ID, --quirk-no-common-rmnet ID
Workaround for devices that do not use the common rmnet driver. The device ID is given as a 4-digit hex number.
-N ID, --quirk-no-sync-submit ID
Workaround for devices that do not support synchronous submission. The device ID is given as a 4-digit hex number.
-P ID, --quirk-option-mfstring-not-supported ID
Workaround for Option modems where the MFSTRING command is not supported. The device ID is given as a 4-digit hex number.
-R ID, --quirk-option-not-locked ID
Workaround for Option modems that are not locked. The device ID is given as a 4-digit hex number.
-S ID, --quirk-no-auto-bcd ID
Workaround for devices that do not support automatic BCD (Binary Coded Decimal) conversion. The device ID is given as a 4-digit hex number.
-T ID, --quirk-zyxel-evdo-prepaid ID
Workaround for Zyxel EVDO prepaid modems. The device ID is given as a 4-digit hex number.
-U ID, --quirk-sierra-network-controller ID
Workaround for Sierra Wireless network controller. The device ID is given as a 4-digit hex number.
-V ID, --quirk-unusual-init-length ID
Workaround for devices with an unusual initialization length. The device ID is given as a 4-digit hex number.
-X ID, --quirk-new-huawei-init-always ID
Workaround for new Huawei modems that always require initialization. The device ID is given as a 4-digit hex number.
-Y ID, --quirk-remove-driver ID
Workaround for devices where the driver needs to be removed before switching. The device ID is given as a 4-digit hex number.
-Z ID, --quirk-ztemt-is-really-ztedc ID
Workaround for ZTE MT devices that are actually ZTE DC devices. The device ID is given as a 4-digit hex number.
BUS:DEVICE
Specify the USB device to operate on using its bus and device number (e.g., 001:002).
