upvar(n) Commandes intégrées Tcl upvar(n)

NOM

upvar - Crée un lien vers une variable dans une autre frame de pile

SYNOPSIS

upvar ?niveau? autreVar maVar ?autreVar maVar ...?

DESCRIPTION

Cette commande organise pour qu'une ou plusieurs variables locales dans la procédure actuelle fassent référence à des variables dans un appel de procédure englobant ou à des variables globales. Niveau peut avoir l'une des formes permises pour la commande uplevel, et peut être omis (il vaut par défaut 1). Pour chaque argument autreVar, upvar rend la variable portant ce nom dans la frame de procédure donnée par niveau (ou au niveau global, si niveau est #0) accessible dans la procédure actuelle par le nom donné dans l'argument maVar correspondant. La variable nommée autreVar n'a pas besoin d'exister au moment de l'appel; elle sera créée la première fois que maVar sera référencée, tout comme une variable ordinaire. Il ne doit pas exister de variable portant le nom maVar au moment où upvar est invoquée. MaVar est toujours traitée comme le nom d'une variable, et non comme un élément de tableau. Une erreur est retournée si le nom ressemble à un élément de tableau, tel que a(b). AutreVar peut faire référence à une variable scalaire, un tableau, ou un élément de tableau. Upvar retourne une chaîne vide.

La commande upvar simplifie l'implémentation de l'appel par nom des procédures et facilite également la création de nouveaux construits de contrôle sous forme de procédures Tcl. Par exemple, considérons la procédure suivante :

proc add2 nom {
    upvar $nom x
    set x [expr {$x + 2}]
}

Si add2 est invoquée avec un argument donnant le nom d'une variable, elle ajoute deux à la valeur de cette variable. Bien que add2 ait pu être implémentée en utilisant uplevel au lieu de upvar, upvar rend plus simple pour add2 d'accéder à la variable dans la frame de procédure de l'appelant.

namespace eval est une autre façon (en dehors des appels de procédure) dont le contexte de nommage Tcl peut changer. Elle ajoute une frame d'appel à la pile pour représenter le contexte de l'espace de noms. Cela signifie que chaque commande namespace eval compte comme un niveau d'appel supplémentaire pour les commandes uplevel et upvar. Par exemple, info level 1 retournera une liste décrivant une commande qui est soit l'appel de procédure le plus externe, soit la commande namespace eval la plus externe. De plus, uplevel #0 évalue un script au niveau supérieur dans l'espace de noms le plus externe (l'espace de noms global).

Si une variable upvar est désaffectée (par exemple, x dans add2 ci-dessus), l'opération unset affecte la variable à laquelle elle est liée, et non la variable upvar. Il n'y a aucun moyen de désaffecter une variable upvar sauf en quittant la procédure dans laquelle elle est définie. Cependant, il est possible de rediriger une variable upvar en exécutant une autre commande upvar.

TRACES ET UPVAR

Upvar interagit avec les traces de manière simple mais potentiellement inattendue. Si une trace de variable est définie sur autreVar, cette trace sera déclenchée par des actions impliquant maVar. Cependant, la procédure de trace recevra le nom de maVar, plutôt que le nom de autreVar. Ainsi, la sortie du code suivant sera “localVar” plutôt que “originalVar” :

proc traceproc { nom index op } {
    puts $nom
}
proc setByUpvar { nom valeur } {
    upvar $nom localVar
    set localVar $valeur
}
set originalVar 1
trace variable originalVar w traceproc
setByUpvar originalVar 2

Si autreVar fait référence à un élément d'un tableau, alors les traces de variables définies pour l'ensemble du tableau ne seront pas appelées lorsque maVar est accédé (mais les traces sur l'élément particulier seront toujours appelées). En particulier, si le tableau est env, alors les modifications apportées à maVar ne seront pas correctement transmises aux sous-processus.

EXEMPLE

Une commande decr qui fonctionne comme incr sauf qu'elle soustrait la valeur de la variable au lieu de l'ajouter :

proc decr {varName {decrement 1}} {
    upvar 1 $varName var
    incr var [expr {-$decrement}]
}
