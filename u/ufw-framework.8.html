NOM

ufw-framework - utilisation du framework ufw

DESCRIPTION

ufw fournit à la fois une interface en ligne de commande et un framework pour gérer un pare-feu netfilter. Alors que la commande ufw offre une interface facile à utiliser pour gérer un pare-feu, le framework ufw offre à l'administrateur des méthodes pour personnaliser le comportement par défaut et ajouter des règles non supportées par l'outil en ligne de commande. De cette manière, ufw peut tirer pleinement parti de la puissance et de la flexibilité de netfilter sous Linux.

APERÇU

Le framework fournit une initialisation au démarrage, des fichiers de règles pour ajouter des règles personnalisées, une méthode pour charger les modules netfilter, la configuration des paramètres du noyau et la configuration d'IPv6. Le framework se compose des fichiers suivants :

/usr/lib/ufw/ufw-init
script d'initialisation
/etc/ufw/before.init
script de personnalisation de l'initialisation exécuté avant l'initialisation de ufw
/etc/ufw/after.init
script de personnalisation de l'initialisation exécuté après l'initialisation de ufw
/etc/ufw/before[6].rules
fichier de règles contenant les règles évaluées avant les règles ajoutées par l'interface utilisateur
/etc/ufw/user[6].rules
fichier de règles contenant les règles ajoutées par l'interface utilisateur (gérées avec la commande ufw)
/etc/ufw/after[6].rules
fichier de règles contenant les règles évaluées après les règles ajoutées par l'interface utilisateur
/etc/default/ufw
configuration de haut niveau
/etc/ufw/sysctl.conf
paramètres réseau du noyau
/etc/ufw/ufw.conf
configuration de haut niveau supplémentaire

INITIALISATION AU DÉMARRAGE

ufw est démarré au démarrage avec /usr/lib/ufw/ufw-init. Ce script est un script d'initialisation standard de style SysV utilisé par la commande ufw et ne doit pas être modifié. Les scripts /etc/before.init et /etc/after.init peuvent être utilisés pour effectuer toute configuration de pare-feu supplémentaire qui n'est pas encore prise en charge par ufw lui-même et s'ils existent et sont exécutables, ufw-init exécutera ces scripts. ufw-init se terminera avec une erreur si l'un de ces scripts se termine avec une erreur. ufw-init prend en charge les arguments suivants :

start:
charge le pare-feu
stop:
décharge le pare-feu
restart:
recharge le pare-feu
force-reload:
identique à restart
status:
état de base du pare-feu
force-stop:
identique à stop, sauf qu'il ne vérifie pas si le pare-feu est déjà chargé
flush-all:
vide les chaînes intégrées, supprime toutes les chaînes non intégrées et réinitialise la politique à ACCEPT

ufw-init appellera before.init et after.init avec start, stop, status et flush-all, mais généralement, s'ils sont utilisés, ces scripts n'ont besoin d'implémenter que start et stop.

ufw utilise de nombreuses chaînes définies par l'utilisateur en plus des chaînes iptables intégrées. Si MANAGE_BUILTINS dans /etc/default/ufw est défini sur 'yes', lors de l'arrêt et du rechargement, les chaînes intégrées sont vidées. Si elle est définie sur 'no', lors de l'arrêt et du rechargement, les chaînes secondaires ufw sont supprimées et les chaînes primaires ufw sont vidées. En plus de vider les chaînes spécifiques à ufw, il maintient les chaînes primaires dans le même ordre par rapport à toute autre chaîne définie par l'utilisateur qui aurait pu être ajoutée. Cela permet à ufw d'interopérer avec d'autres logiciels qui peuvent gérer leurs propres règles de pare-feu.

Pour vous assurer que votre pare-feu se charge au démarrage, vous devez intégrer ce script au processus de démarrage. Consultez la documentation de votre distribution pour connaître la manière appropriée de modifier votre processus de démarrage si ufw n'est pas déjà intégré.

FICHIERS DE RÈGLES

ufw est en partie un frontal pour iptables-restore, avec ses règles enregistrées dans /etc/ufw/before.rules, /etc/ufw/after.rules et /etc/ufw/user.rules. Les administrateurs peuvent personnaliser before.rules et after.rules selon leurs besoins en utilisant la syntaxe standard iptables-restore. Les règles sont évaluées comme suit : before.rules d'abord, user.rules ensuite, et after.rules en dernier. Les règles IPv6 sont évaluées de la même manière, avec les fichiers de règles nommés before6.rules, user6.rules et after6.rules. Veuillez noter que ufw status n'affiche que les règles ajoutées avec ufw et non les règles trouvées dans les fichiers de règles /etc/ufw.

Important : ufw n'utilise que la table *filter par défaut. Vous pouvez ajouter d'autres tables comme *nat, *raw et *mangle selon vos besoins. Pour chaque table, une instruction COMMIT correspondante est requise.

Après avoir modifié l'un de ces fichiers, vous devez recharger ufw pour que les règles prennent effet. Voir la section EXEMPLES pour les utilisations courantes de ces fichiers de règles.

MODULES

Netfilter possède de nombreux modules de suivi de connexion différents. Ces modules connaissent le protocole sous-jacent et permettent à l'administrateur de simplifier ses ensembles de règles. Vous pouvez ajuster quels modules netfilter charger en ajustant IPT_MODULES dans /etc/default/ufw. Certains modules populaires à charger sont :


nf_conntrack_ftp
nf_nat_ftp
nf_conntrack_irc
nf_nat_irc
nf_conntrack_netbios_ns
nf_conntrack_pptp
nf_conntrack_tftp
nf_nat_tftp
nf_conntrack_sane

Le chargement inconditionnel des modules de suivi de connexion (nf_conntrack_*) de cette manière est déconseillé. ufw continue à prendre en charge cette fonctionnalité mais la nouvelle configuration ne devrait contenir que les modules spécifiques requis pour le site. Pour plus d'informations, voir CONNECTION HELPERS.

PARAMÈTRES DU NOYAU

ufw lira /etc/ufw/sysctl.conf au démarrage lorsqu'il est activé. Veuillez noter que /etc/ufw/sysctl.conf remplace les valeurs dans le fichier systcl.conf du système (généralement /etc/sysctl.conf). Les administrateurs peuvent modifier le fichier utilisé en modifiant /etc/default/ufw.

IPV6

IPv6 est activé par défaut. Lorsqu'il est désactivé, tous les paquets entrants, sortants et routés sont abandonnés, à l'exception du trafic sur l'interface de boucle locale. Pour ajuster ce comportement, définissez IPV6 sur 'yes' dans /etc/default/ufw. Voir la page de manuel ufw pour plus de détails.

EXEMPLES

Comme mentionné, ufw charge ses fichiers de règles dans le noyau en utilisant les commandes iptables-restore et ip6tables-restore. Les utilisateurs souhaitant ajouter manuellement des règles aux fichiers de règles de ufw doivent être familiarisés avec ceux-ci ainsi qu'avec les commandes iptables et ip6tables. Ci- dessous quelques exemples courants d'utilisation des fichiers de règles ufw. Tous les exemples supposent IPv4 uniquement et que DEFAULT_FORWARD_POLICY dans /etc/default/ufw est défini sur DROP.

Masquerade IP

Pour autoriser le masquerade IP pour que les ordinateurs du réseau 10.0.0.0/8 sur eth1 partagent l'adresse IP unique sur eth0 :

Modifier /etc/ufw/sysctl.conf pour avoir :

net.ipv4.ip_forward=1
Ajouter à la fin de /etc/ufw/before.rules, après la section *filter :

*nat
:POSTROUTING ACCEPT [0:0]
-A POSTROUTING -s 10.0.0.0/8 -o eth0 -j MASQUERADE
COMMIT
Si votre pare-feu utilise des tunnels IPv6 ou 6to4 et effectue également du NAT, alors vous ne devriez généralement pas masquer les paquets du protocole '41' (ipv6). Par exemple, au lieu de ce qui précède, /etc/ufw/before.rules peut être ajusté pour avoir :

*nat
:POSTROUTING ACCEPT [0:0]
-A POSTROUTING -s 10.0.0.0/8 ! --protocol 41 -o eth0 -j MASQUERADE
COMMIT
Ajouter la commande ufw route pour autoriser le trafic :

ufw route allow in on eth1 out on eth0 from 10.0.0.0/8

Redirections de port

Pour rediriger le trafic entrant sur le port 80 vers le port 8080 sur la même machine :

Ajouter à la fin de /etc/ufw/before.rules, après la section *filter :

*nat
:PREROUTING ACCEPT [0:0]
-A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
COMMIT
Ajouter le trafic à la table de filtre :

ufw allow 8080/tcp

Redirections de port

Pour rediriger le trafic entrant sur le port 80 de la machine 1.2.3.4 vers le port 8080 sur la machine 5.6.7.8 :

Ajouter à la fin de /etc/ufw/before.rules, après la section *filter :

*nat
:PREROUTING ACCEPT [0:0]
-A PREROUTING -p tcp -s 1.2.3.4 --dport 80 -j DNAT --to-destination 5.6.7.8:8080
COMMIT
Ajouter le trafic à la table de filtre :

ufw allow proto tcp from 1.2.3.4 to 5.6.7.8 port 8080

Blocage de certains protocoles

Pour bloquer toutes les connexions UDP entrants :

Ajouter à la fin de /etc/ufw/before.rules :

-A ufw-before-input -p udp -j DROP

Début des règles de filtrage IPv6

Par défaut, le paquetage ufw inclut un fichier de règles par défaut qui ne filtre que le trafic IPv6. Ce fichier est /etc/ufw/before6.rules et il est chargé avant les règles définies par l'utilisateur. Si vous souhaitez les personnaliser, vous pouvez ajouter les règles suivantes à la fin de /etc/ufw/before6.rules.

Pour autoriser le trafic SSH entrant sur toutes les interfaces :

Ajouter à la fin de /etc/ufw/before6.rules :

-A ufw6-before-input -p tcp --dport 22 -j ACCEPT

ufw-framework(8) — ufw framework

NAME

ufw-framework - Framework for configuring netfilter firewall

DESCRIPTION

The ufw command is a frontend for managing a netfilter firewall. It is designed to provide an easy to use interface for a user to manage the firewall. This man page details the framework for configuring the firewall rules and settings and is intended for advanced users wanting to customize their firewall configuration. It is not needed for basic firewall management.

OVERVIEW

The ufw firewall is configured by editing configuration files and setting kernel parameters. Configuration can be done manually by editing the rules files and then reloading the firewall rules, or it can be done by setting the kernel parameters using sysctl.

The ufw framework uses the following files:

/etc/default/ufw
This file contains framework default settings. It is sourced by the ufw script and should be modified to set framework defaults.
/etc/ufw/sysctl.conf
This file contains kernel parameters that are set using sysctl when ufw is enabled. See sysctl.conf(5) for more information.
/etc/ufw/before.rules
This file contains rules that are inserted into the raw, mangle, and nat tables before ufw management rules. Rules in this file are inserted before the filter table rules.
/etc/ufw/after.rules
This file contains rules that are inserted into the raw, mangle, and nat tables after ufw management rules. Rules in this file are inserted after the filter table rules.
/etc/ufw/before6.rules
This file contains rules that are inserted into the raw, mangle, and nat tables before ufw management rules for IPv6. Rules in this file are inserted before the filter table rules.
/etc/ufw/after6.rules
This file contains rules that are inserted into the raw, mangle, and nat tables after ufw management rules for IPv6. Rules in this file are inserted after the filter table rules.
/etc/ufw/uf.rules
This file contains the rules that are managed by the ufw command. Users should not edit this file directly. Use the ufw command instead.

BOOT INITIALIZATION

When ufw is enabled, it loads the rules from the rules files and sets the kernel parameters in /etc/ufw/sysctl.conf. The rules are loaded in the following order:

  1. Rules in /etc/ufw/before.rules
  2. Rules in /etc/ufw/uf.rules (managed by ufw command)
  3. Rules in /etc/ufw/after.rules

For IPv6, the order is:

  1. Rules in /etc/ufw/before6.rules
  2. Rules in /etc/ufw/uf.rules (managed by ufw command)
  3. Rules in /etc/ufw/after6.rules

The kernel parameters in /etc/ufw/sysctl.conf are loaded using sysctl.

RULES FILES

The rules files contain standard iptables(8) rules. The following sections are recognized:

`*filter`
Rules for the filter table. This is the default table if no table is specified.
`*nat`
Rules for the nat table.
`*mangle`
Rules for the mangle table.
`*raw`
Rules for the raw table.
`:PREROUTING`
Default chain for PREROUTING.
`:POSTROUTING`
Default chain for POSTROUTING.
`:INPUT`
Default chain for INPUT.
`:OUTPUT`
Default chain for OUTPUT.
`:FORWARD`
Default chain for FORWARD.
`COMMIT`
Indicates the end of rules for a table.

Rules in these files are added to the corresponding iptables chains. The ufw command manages the rules in the filter table's ufw-user-input, ufw-user-output, and ufw-user-forward chains.

Any rules that are not part of the filter table or do not belong in the ufw-user-* chains should be added to the /etc/ufw/before.rules or /etc/ufw/after.rules files, depending on whether they should be applied before or after the ufw-managed rules.

For example, to enable port forwarding, you would add rules to the nat table in /etc/ufw/before.rules.

MODULES

The following modules are used by ufw:

nf_conntrack_ftp
Tracks FTP connections.
nf_conntrack_sip
Tracks SIP connections.

These modules can be loaded by adding them to the IPT_MODULES variable in /etc/default/ufw.

KERNEL PARAMETERS

The following kernel parameters can be set in /etc/ufw/sysctl.conf:

net.ipv4.ip_forward
Enables IP forwarding. Required for routing.
net.ipv4.conf.all.accept_redirects
Accept ICMP router advertisements. Defaults to 1 (accept).
net.ipv4.conf.all.send_redirects
Send ICMP router advertisements. Defaults to 1 (send).
net.ipv6.conf.all.accept_redirects
Accept ICMPv6 router advertisements. Defaults to 1 (accept).
net.ipv6.conf.all.send_redirects
Send ICMPv6 router advertisements. Defaults to 1 (send).
net.bridge.bridge-nf-call-iptables
Process bridged packets with iptables. Defaults to 0 (disabled).
net.bridge.bridge-nf-call-ip6tables
Process bridged packets with ip6tables. Defaults to 0 (disabled).
net.bridge.bridge-nf-call-arptables
Process bridged packets with arptables. Defaults to 0 (disabled).

IPV6

The framework supports IPv6. Rules for IPv6 can be placed in /etc/ufw/before6.rules and /etc/ufw/after6.rules. The ufw command applies the same rules to IPv6 as it does to IPv4, unless otherwise specified.

EXAMPLES

Port Redirections

To forward tcp port 80 on eth0 to go to the webserver at 10.0.0.2:

Edit /etc/ufw/sysctl.conf to have:

net.ipv4.ip_forward=1
Add to the end of /etc/ufw/before.rules, after the *filter section:

*nat
:PREROUTING ACCEPT [0:0]
-A PREROUTING -p tcp -i eth0 --dport 80 -j DNAT \
--to-destination 10.0.0.2:80
COMMIT
Add the ufw route rule to allow the traffic:

ufw route allow in on eth0 to 10.0.0.2 port 80 proto tcp

Egress filtering

To block RFC1918 addresses going out of eth0:

Add the ufw route rules to reject the traffic:

ufw route reject out on eth0 to 10.0.0.0/8
ufw route reject out on eth0 to 172.16.0.0/12
ufw route reject out on eth0 to 192.168.0.0/16

Full example

This example combines the other examples and demonstrates a simple routing firewall. Warning: this setup is only an example to demonstrate the functionality of the ufw framework in a concise and simple manner and should not be used in production without understanding what each part does and does not do. Your firewall will undoubtedly want to be less open.

This router/firewall has two interfaces: eth0 (Internet facing) and eth1 (internal LAN). Internal clients have addresses on the 10.0.0.0/8 network and should be able to connect to anywhere on the Internet. Connections to port 80 from the Internet should be forwarded to 10.0.0.2. Access to ssh port 22 from the administrative workstation (10.0.0.100) to this machine should be allowed. Also make sure no internal traffic goes to the Internet.

Edit /etc/ufw/sysctl.conf to have:

net.ipv4.ip_forward=1
Add to the end of /etc/ufw/before.rules, after the *filter section:

*nat
:PREROUTING ACCEPT [0:0]
:POSTROUTING ACCEPT [0:0]
-A PREROUTING -p tcp -i eth0 --dport 80 -j DNAT \
--to-destination 10.0.0.2:80
-A POSTROUTING -s 10.0.0.0/8 -o eth0 -j MASQUERADE
COMMIT
Add the necessary ufw rules:

ufw route reject out on eth0 to 10.0.0.0/8
ufw route reject out on eth0 to 172.16.0.0/12
ufw route reject out on eth0 to 192.168.0.0/16
ufw route allow in on eth1 out on eth0 from 10.0.0.0/8
ufw route allow in on eth0 to 10.0.0.2 port 80 proto tcp
ufw allow in on eth1 from 10.0.0.100 to any port 22 proto tcp

CONNECTION HELPERS

Various protocols require the use of netfilter connection tracking helpers to group related packets into RELATED flows to make rulesets clearer and more precise. For example, with a couple of kernel modules and a couple of rules, a ruleset could simply allow a connection to FTP port 21, then the kernel would examine the traffic and mark the other FTP data packets as RELATED to the initial connection.

When the helpers were first introduced, one could only configure the modules as part of module load (eg, if your FTP server listened on a different port than 21, you'd have to load the nf_conntrack_ftp module specifying the correct port). Over time it was understood that unconditionally using connection helpers could lead to abuse, in part because some protocols allow user specified data that would allow traversing the firewall in undesired ways. As of kernel 4.7, automatic conntrack helper assignment (ie, handling packets for a given port and all IP addresses) is disabled (the old behavior can be restored by setting net/netfilter/nf_conntrack_helper=1 in /etc/ufw/sysctl.conf). Firewalls should now instead use the CT target to associate traffic with a particular helper and then set RELATED rules to use the helper. This allows sites to tailor the use of helpers and help avoid abuse.

In general, to use helpers securely, the following needs to happen:

1.
net/netfilter/nf_conntrack_helper should be set to 0 (default)
2.
create a rule for the start of a connection (eg for FTP, port 21)
3.
create a helper rule to associate the helper with this connection
4.
create a helper rule to associate a RELATED flow with this connection
5.
if needed, add the corresponding nf_conntrack_* module to IPT_MODULES
6.
optionally add the corresponding nf_nat_* module to IPT_MODULES

In general it is desirable to make connection helper rules as specific as possible and ensure anti-spoofing is correctly setup for your site to avoid security issues in your ruleset. For more information, see ANTI-SPOOFING, above, and https://home.regit.org/netfilter-en/secure-use-of-helpers/.

Currently helper rules must be managed in via the RULES FILES. A future version of ufw will introduce syntax for working with helper rules.

NOTES

When using ufw with libvirt and bridging, packets may be blocked. The libvirt team recommends that the following sysctl's be set to disable netfilter on the bridge:


net.bridge.bridge-nf-call-ip6tables = 0
net.bridge.bridge-nf-call-iptables = 0
net.bridge.bridge-nf-call-arptables = 0

Note that the bridge module must be loaded in to the kernel before these values are set. One way to ensure this works properly with ufw is to add 'bridge' to IPT_MODULES in /etc/default/ufw, and then add the above rules to /etc/ufw/sysctl.conf.

Alternatively to disabling netfilter on the bridge, you can configure iptables to allow all traffic to be forwarded across the bridge. Eg, add to /etc/ufw/before.rules within the *filter section:


-I FORWARD -m physdev --physdev-is-bridged -j ACCEPT
