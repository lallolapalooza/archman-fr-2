ualarm(3) Manuel des fonctions de bibliothèque ualarm(3)

NOM

ualarm - planifier l'envoi d'un signal après un certain nombre de microsecondes

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
useconds_t ualarm(useconds_t usecs, useconds_t interval);
Macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

ualarm():

    Depuis glibc 2.12:
        (_XOPEN_SOURCE >= 500) && ! (_POSIX_C_SOURCE >= 200809L)
            || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
            || /* glibc <= 2.19 : */ _BSD_SOURCE
    Avant glibc 2.12:
        _BSD_SOURCE || _XOPEN_SOURCE >= 500

DESCRIPTION

La fonction ualarm() provoque l'envoi du signal SIGALRM au processus appelant après (et pas moins de) usecs microsecondes. Le délai peut être légèrement allongé par toute activité système ou par le temps passé à traiter l'appel ou par la granularité des minuteries système.

Sauf s'il est intercepté ou ignoré, le signal SIGALRM terminera le processus.

Si l'argument interval est non nul, des signaux SIGALRM supplémentaires seront envoyés toutes les interval microsecondes après le premier.

VALEUR DE RETOUR

Cette fonction retourne le nombre de microsecondes restantes pour toute alarme qui était précédemment définie, ou 0 si aucune alarme n'était en attente.

ERREURS

EINTR
Interrompu par un signal ; voir signal(7).
EINVAL
usecs ou interval n'est pas inférieur à 1000000. (Sur les systèmes où cela est considéré comme une erreur.)

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
ualarm () Thread safety MT-Safe

NORMES

Aucune.

HISTORIQUE

4.3BSD, POSIX.1-2001. POSIX.1-2001 la marque comme obsolète. Supprimée dans POSIX.1-2008.

4.3BSD, SUSv2 et POSIX ne définissent aucune erreur.

POSIX.1-2001 ne spécifie pas ce qui se passe si l'argument usecs est égal à 0. Sous Linux (et probablement la plupart des autres systèmes), l'effet est d'annuler toute alarme en attente.

Le type useconds_t est un type entier non signé capable de contenir des entiers dans la plage [0,1000000]. Sur l'implémentation BSD d'origine, et dans glibc avant glibc 2.1, les arguments de ualarm() étaient typés comme unsigned int. Les programmes seront plus portables s'ils ne mentionnent jamais explicitement useconds_t.

L'interaction de cette fonction avec d'autres fonctions de temporisation telles que alarm(2), sleep(3), nanosleep(2), setitimer(2), timer_create(2), timer_delete(2), timer_getoverrun(2), timer_gettime(2), timer_settime(2), usleep(3) n'est pas spécifiée.

Cette fonction est obsolète. Utilisez plutôt setitimer(2) ou les minuteries d'intervalle POSIX (timer_create(2), etc.).

VOIR AUSSI

alarm(2), getitimer(2), nanosleep(2), select(2), setitimer(2), usleep(3), time(7)
