NOM

upsdrvsvcctl - Contrôleur d'instances de service de pilotes Network UPS Tools

SYNOPSIS

upsdrvsvcctl -h

upsdrvsvcctl [OPTIONS] {start | stop | status} [ups]

DESCRIPTION

upsdrvsvcctl fournit une interface uniforme pour contrôler vos pilotes UPS encapsulés dans des instances de service sur les plateformes qui le supportent (actuellement, cela couvre les distributions Linux avec systemd et les systèmes dérivés de la base de code Solaris 10, y compris les distributions propriétaires Sun/Oracle Solaris et de nombreuses distributions illumos open-source avec SMF). Il peut ne pas être installé dans les paquets pour d'autres systèmes d'exploitation.

Utilisé correctement, upsdrvsvcctl vous permet de maintenir des scripts de démarrage identiques sur plusieurs systèmes avec différentes configurations UPS.

L'objectif de cette solution est de permettre aux services du serveur de données upsd(8) de démarrer même si certains des appareils d'alimentation ne sont pas accessibles, et pour que les pilotes NUT soient redémarrés automatiquement par le système en cas de problèmes (bug du pilote, échec de démarrage). Il permet également un démarrage plus rapide des systèmes qui surveillent plusieurs appareils, en laissant chaque pilote démarrer en parallèle avec les autres et dès que le sous-système requis pour le support spécifique du pilote est disponible, c'est-à-dire sans boucle séquentielle comme c'était fait précédemment.

Des instances de service indépendantes pour chaque pilote NUT permettent également de configurer des dépendances supplémentaires, telles que la disponibilité du réseau pour les pilotes SNMP et similaires (mais ce n'est pas nécessaire pour les pilotes à support local comme série ou USB).

L'ancienne solution monolithique « tout ou rien » exigeant que tous les pilotes soient en cours d'exécution, qui suffisait pour les déploiements avec quelques onduleurs, ne fonctionnait pas vraiment bien pour la surveillance de déploiements plus importants. Il n'était pas non plus facile d'établir un équilibre pré-packagé entre la protection UPS précoce pour les configurations domestiques USB/série et l'attente du réseau pour les configurations plus importantes.

upsdrvsvcctl est un script qui imite le fonctionnement du programme upsdrvctl(8) (dans la mesure du possible) pour fournir une expérience utilisateur similaire lors de la manipulation de pilotes encapsulés dans des instances de service plutôt que comme démons directement exécutés. Il s'appuie en grande partie sur nut-driver-enumerator(8) pour les opérations réelles.

Vous devriez utiliser upsdrvsvcctl au lieu d'appels directs aux pilotes et de gestion basée sur des démons avec upsdrvctl(8) chaque fois que possible (c'est-à-dire pour une utilisation « en production » sur des systèmes compatibles). Sinon (pour les tests, d'autres systèmes), upsdrvctl est une option recommandée.

OPTIONS

-h

Affiche le texte d'aide, y compris la version intégrée du script.

-V

Affiche la version des binaires NUT (appelant upsdrvctl -V), qui ne devrait normalement pas différer beaucoup de la version intégrée du script affichée dans l'aide. Mais avec des compilations personnalisées, tout est possible, donc cela peut être utile à savoir.

-t

Active le mode test. Le mode test fait en sorte que upsdrvsvcctl affiche les actions qu'il exécuterait sans les réaliser réellement.

--timeout-cmd <prog> et --timeout-args <arg>

Les appels de gestion de service seront limités dans le temps en appelant le programme spécifié avec ses arguments. Par défaut, si timeout de coreutils est trouvé, il sera utilisé pour limiter les appels de service à 90 secondes, afin d'éviter/contourner certains blocages qui se produisent dans certaines versions de systemd sous stress.

OPTIONS DE UPSDRVCTL NON (ACTUELLEMENT) APPLICABLES À UPSDRVSVCCTL

Des options comme -r, -u ou -D pourraient être gérées par les propriétés des instances de service elles-mêmes, avec ce script aidant à les configurer (en supposant les privilèges appropriés de l'utilisateur qui l'a appelé). Ce n'est cependant pas un cas d'utilisation « en production » pour modifier de telles options sur un système configuré — donc pour les expériences et le dépannage, il peut être préférable d'arrêter l'instance de service et de jouer directement avec upsdrvctl.

-r directory

Si vous démarrez un pilote, cette valeur l'incitera à faire un chroot(2) dans directory. Cela peut être utile lors de la sécurisation des systèmes.

Cela peut être défini dans le fichier ups.conf(5) avec la directive chroot dans la section globale.

-u username

Si vous démarrez un pilote, cette valeur l'incitera à faire un setuid(2) à l'identifiant utilisateur associé à username.

Si le pilote est démarré en tant que root sans spécifier cette valeur, il utilisera le nom d'utilisateur qui a été compilé dans le binaire. Cela vaut par défaut pour nobody (si non configuré autrement), ce qui est loin d'être idéal.

Cela peut être défini dans le fichier ups.conf(5) avec la directive user dans la section globale.

-D

Augmente le niveau de débogage du pilote. Utilisez ceci plusieurs fois pour plus de détails.

COMMANDES

upsdrvsvcctl prend en charge trois des commandes traitées par upsdrvctl — start, stop et shutdown. Elles prennent un argument optionnel qui est un nom d'UPS du fichier ups.conf(5). Sans cet argument, elles opèrent sur chaque UPS actuellement configuré.

Note : shutdown est actuellement pris en charge en arrêtant les instances de service du pilote pour libérer les ports potentiellement détenus, etc., en appelant upsdrvctl directement pour émettre la commande de shutdown, et en redémarrant les instances de service du pilote pour se reconnecter lorsque l'appareil revient en ligne.

start

Démarre le ou les pilotes UPS. En cas d'échec, des tentatives supplémentaires peuvent être exécutées en utilisant les options maxretry et retrydelay — voir ups.conf(5).

stop

Arrête le ou les pilotes UPS.

status

Interroge l'état d'exécution de tous les appareils configurés (ou d'un appareil spécifié). Déléguera actuellement le travail à upsdrvctl(8), pour lister les configurations de périphériques connues et les détails de leur démon pilote (PID, réactivité, ups.status) et à nut-driver-enumerator(8) pour mapper les noms de périphériques aux instances d'unité de service afin de signaler leurs noms et états dans le framework de gestion de service.

upsdrvsvcctl prend également en charge des opérations supplémentaires pour le dépannage du mappage des noms de sections de pilotes NUT aux noms d'instances de service (qui peuvent différer en raison des limitations de divers systèmes).

list

Liste le mappage actuellement actif des instances de service aux sections de périphériques.

resync

Met à jour le mappage des instances de service pour les pilotes NUT aux noms de sections de périphériques utilisés dans ups.conf (enregistre les nouvelles instances, supprime celles obsolètes).

COMMANDES DE UPSDRVCTL NON (ACTUELLEMENT) APPLICABLES À UPSDRVSVCCTL

shutdown

Commande aux pilotes UPS d'exécuter leur séquence d'arrêt. Les pilotes sont arrêtés selon leur valeur sdorder — voir ups.conf(5).

Attention

cela coupera probablement l'alimentation de vos ordinateurs, alors ne jouez pas avec cette option. Utilisez-la uniquement lorsque vos systèmes sont préparés à perdre l'alimentation.


Note

référez-vous à ups.conf(5) pour utiliser le paramètre nowait. Il peut être remplacé par la variable d'environnement NUT_IGNORE_NOWAIT (par exemple, utilisé pour contourner certains problèmes avec systemd autrement).

VARIABLES D'ENVIRONNEMENT

NUT_CONFPATH est le nom du chemin du répertoire qui contient upsd.conf et d'autres fichiers de configuration. Si cette variable n'est pas définie, upsdrvsvcctl (ou plutôt nut-driver-enumerator.sh) utiliserait une valeur par défaut intégrée, qui est souvent /usr

/local/ups/etc.

DIAGNOSTICS

upsdrvsvcctl retournera un code de sortie non nul s'il rencontre une erreur lors de l'exécution de l'opération souhaitée. Cela se produira également si un pilote met plus de temps que la période maxstartdelay pour passer en arrière-plan.

Tous les messages émis par le programme upsdrvctl utilisé pour démarrer les pilotes NUT dans le cadre des implémentations des instances de service, ou par les pilotes eux-mêmes, seront journalisés par les installations du framework de gestion des services et n'apparaîtront pas dans votre terminal interactif utilisé pour gérer le pilote.

Utilisez upsdrvsvcctl list ou upsdrvsvcctl list NUT-device pour trouver le nom de l'instance de service pour le pilote NUT (nom de section) qui vous intéresse. Ensuite, consultez les journaux du service (où sont stockées les sorties du programme d'implémentation du service ainsi que les messages du framework concernant ce service), comme suggéré ci-dessous :

Linux systemd

Les messages seront normalement conservés dans le journal du service, donc : 
journalctl -lu nut-driver@instance-name

Notez que la configuration de votre système local peut être affectée par des nuances telles que le transfert des données du journal vers un serveur syslog standard, et/ou par la présence d'un petit cache pour les messages de journal stockés localement (de sorte que les anciennes entrées disparaissent). Il se peut également qu'une copie des journaux soit stockée ou non dans le système de fichiers persistant.

Solaris SMF

Recherchez le fichier /var/svc/log/system-power-nut-driver:instance-name.log.
