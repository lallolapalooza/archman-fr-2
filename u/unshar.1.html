unshar(1) Commandes utilisateur unshar(1)

NOM

unshar - décompresser une archive shar

SYNOPIS

unshar [-flags] [-flag [valeur]] [--nom-option[[=| ]valeur]] [<fichier>...]

Les opérandes sur lesquels ce programme opère peuvent être spécifiés soit sur la ligne de commande, soit lus depuis l'entrée standard, un par ligne. Dans cette entrée, les espaces blancs en début et en fin de ligne sont supprimés, les lignes vides sont ignorées. L'entrée standard ne peut pas être un terminal.

DESCRIPTION

Unshar scanne les fichiers d'entrée (typiquement des messages électroniques) à la recherche du début d'une archive shell. Si aucun fichier n'est donné, l'entrée standard est alors traitée. Il passe ensuite chaque archive découverte à une invocation du programme shell pour la décompresser.

Ce programme effectuera sa fonction pour chaque fichier nommé sur la ligne de commande ou pour chaque fichier nommé dans une liste lue depuis stdin. Les arguments ou noms d'entrée doivent être des fichiers préexistants. La liste d'entrée peut contenir des commentaires, qui sont des lignes vides ou des lignes commençant par un caractère '#' .

OPTIONS

-d rép, --directory=rép

décompresser dans le répertoire rép.

Les noms de fichiers d'entrée sont relatifs au répertoire courant lors du démarrage du programme. Cette option indique à unshar d'insérer une commande cd <rép> au début du texte shar écrit dans le shell.

-c, --overwrite

écraser les fichiers préexistants.

Cette option est transmise en tant qu'option au fichier shar. De nombreux scripts d'archives shell acceptent un argument -c pour indiquer que les fichiers existants doivent être écrasés.

-f, --force

Ceci est un alias pour l'option --overwrite.
-E marque-coupure, --split-at=marque-coupure

diviser l'entrée sur les lignes marque-coupure. Le marque-coupure par défaut pour cette option est :
exit 0

Avec cette option, unshar isole chaque archive shell différente des autres qui ont été placées dans le même fichier, les décompressant une par une, du début du fichier à la fin. Son fonctionnement correct repose sur le fait que de nombreux fichiers shar sont terminés par une chaîne facilement identifiable au début de la dernière ligne.

Par exemple, remarquant que la plupart des `.signatures' ont des tirets doubles ("--") sur une ligne juste avant eux, on peut alors parfois utiliser --split-at=--. La signature sera alors ignorée, ainsi que les en-têtes du message suivant.

-e, --exit-0

diviser l'entrée sur les lignes "exit 0". Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : split-at.

La plupart des archives shell se terminent par une ligne composée simplement de "exit 0". Cette option est équivalente à (et entre en conflit avec) --split-at="exit 0".

-D, --debug

déboguer le code shell.

"set -x" sera émis dans le code que le shell interprète.

-h, --help

Afficher les informations d'utilisation et quitter.
-!, --more-help

Transmettre les informations d'utilisation étendues via un paginateur.
-R [fichier-cfg], --save-opts [=fichier-cfg]

Sauvegarder l'état des options dans fichier-cfg. Le défaut est le dernier fichier de configuration listé dans la section PRÉGLAGES D'OPTIONS, ci-dessous. La commande quittera après avoir mis à jour le fichier de configuration.
-r fichier-cfg, --load-opts=fichier-cfg, --no-load-opts

Charger les options depuis fichier-cfg. La forme no-load-opts désactivera le chargement des fichiers de configuration/rc/ini antérieurs. --no-load-opts est traité tôt, hors séquence.
-v [{v|c|n --version [{v|c|n}]}]

Afficher la version du programme et quitter. Le mode par défaut est `v', une version simple. Le mode `c' affichera les informations de copyright et `n' affichera l'avis de copyright complet.

PRÉGLAGES D'OPTIONS

Toute option qui n'est pas marquée comme non préséglable peut être préséglée en chargeant les valeurs depuis des fichiers de configuration ("RC" ou ".INI"). Le fichier "$HOME/.sharrc" sera utilisé, s'il est présent.

Voir PRÉGLAGES D'OPTIONS pour les fichiers de configuration.

STATUT DE SORTIE

L'une des valeurs de sortie suivantes sera retournée :

0 (EXIT_SUCCESS)

Exécution réussie du programme.
1 (EXIT_FAILURE)

Il y a eu une erreur dans l'utilisation de la commande.
2 (EXIT_POPEN_PROBLEM)

impossible de lancer ou d'écrire dans un processus shell
3 (EXIT_CANNOT_CREATE)

impossible de créer le fichier de sortie
4 (EXIT_BAD_DIRECTORY)

la structure du répertoire de travail est invalide
5 (EXIT_NOMEM)

échec d'allocation mémoire
6 (EXIT_INVALID)

entrée invalide, ne contient pas de fichier shar
66 (EX_NOINPUT)

Un fichier de configuration spécifié n'a pas pu être chargé.
70 (EX_SOFTWARE)

libopts a eu une erreur opérationnelle interne. Veuillez la signaler à autogen-users@lists.sourceforge.net. Merci.
