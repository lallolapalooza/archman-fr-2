DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui effectue de la mise en cache et de la validation DNSSEC. Ceci est l'API de bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution, et peut être utilisée pour convertir des noms d'hôtes en adresses IP, et vice versa, et obtenir d'autres informations du DNS. La bibliothèque effectue la validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour conserver le contexte entre les appels. L'utilisateur doit la maintenir, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La créer à nouveau supprime toute configuration précédente (telles que les clés de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement threadé (ainsi que dans un environnement non threadé). La résolution (et la validation) peut également être effectuée de manière bloquante et non bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement de l'appel, de sorte que le traitement puisse continuer, tandis que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées une par une ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec les valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone si vous utilisez la bibliothèque openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou version ultérieure utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les rappels ne sont pas appelés pour celles-ci.
ub_ctx_set_option
Une interface pour utilisateurs avancés qui permet de spécifier l'une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs avancés qui obtient la valeur d'une option. Certaines options ne peuvent pas être obtenues, et d'autres retournent une liste séparée par des sauts de ligne. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée avec free(2) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs avancés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, telles que l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelé en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine à laquelle les requêtes DNS seront transférées, le résolveur de mise en cache à utiliser. Adresse IP4 ou IP6. Transfère toutes les requêtes DNS vers cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas compatible DNSSEC, la validation peut échouer. Peut être appelé plusieurs fois, dans ce cas les adresses sont utilisées comme serveurs de secours. À ce stade, il est seulement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS faisant autorité à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Définir isprime à vrai si vous configurez des hints racine avec cela. Sinon, similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelé plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. À ce stade, il est seulement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_set_tls
Active le DNS sur TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. À ce stade, il est seulement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_resolvconf
Par défaut, les serveurs racine sont interrogés et le mode résolveur complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des noms de serveurs à utiliser à partir du nom de fichier donné. Habituellement "/etc/resolv.conf". Utilise ces noms de serveurs comme proxys de mise en cache. S'ils ne supportent pas DNSSEC, la validation peut échouer. Seuls les noms de serveurs sont récupérés, le domaine de recherche, ndots et autres paramètres de resolv.conf(5) sont ignorés. Si NULL est passé comme fname, "/etc/resolv.conf" est utilisé (si sous Windows, le nom de serveur configuré au niveau du système est sélectionné à la place). À ce stade, il est seulement possible de définir la configuration avant que la première résolution ne soit effectuée.
ub_ctx_hosts
Lit la liste des hôtes à partir du nom de fichier donné. Habituellement "/etc/hosts". Lors de l'interrogation, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si NULL est passé comme fname, "/etc/hosts" est utilisé (si sous Windows, etc/hosts depuis WINDIR est sélectionné à la place). À ce stade, il est seulement possible de définir la configuration avant que la première résolution

FUNCTIONS

ub_ctx_create
Create a context for the unbound library. Return a context pointer or NULL on error. The context is used to hold state for operations.
ub_ctx_destroy
Destroy the context and free all associated memory. All asynchronous queries are cancelled.
ub_ctx_resolvconf
Read system nameservers from system configuration file (e.g. /etc/resolv.conf). If you use this, you do not need to specify servers with ub_ctx_server. This function can be called multiple times, it adds to the list of servers.
ub_ctx_server
Add a server to the list of servers to use. It takes a server IP address (string format) and port number. If you use this, you do not need to use ub_ctx_resolvconf. This function can be called multiple times, it adds to the list of servers.
ub_ctx_config
Read configuration file. This is equivalent to reading a config file with unbound.conf. Setups like interface, port, and DNSSEC settings can be configured here. See unbound.conf(5) for details.
ub_ctx_hosts
Load hosts file. This allows the creation of local data, like DNSSEC unsigned data. Format is the standard hosts file format. All data is inserted with a TTL of 0. The file is read in once. Use with care, it is not dynamic. This function can be called multiple times to load multiple host files.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
