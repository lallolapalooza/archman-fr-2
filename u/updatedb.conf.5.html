updatedb.conf(5) Manuel des formats de fichiers updatedb.conf(5)

NOM

/etc/updatedb.conf - fichier de configuration pour updatedb(8)

DESCRIPTION

/etc/updatedb.conf est un fichier texte. Les lignes vides sont ignorées. Un caractère # en dehors d'une chaîne entre guillemets commence un commentaire qui s'étend jusqu'à la fin de la ligne.

Les autres lignes doivent avoir la forme suivante :

VARIABLE = "VALEUR"

Les espaces entre les jetons sont ignorés. VARIABLE est une chaîne alphanumérique qui ne commence pas par un chiffre. VALEUR peut contenir n'importe quel caractère à l'exception de ". Aucun mécanisme d'échappement n'est pris en charge dans VALEUR et il n'y a aucun moyen d'écrire une VALEUR s'étendant sur plusieurs lignes.

Les VARIABLEs inconnues sont considérées comme une erreur. Les variables définies sont :

PRUNEFS
Une liste d'espaces séparant les types de systèmes de fichiers (tels qu'utilisés dans /etc/mtab) qui ne doivent pas être analysés par updatedb(8). La correspondance des types de systèmes de fichiers est insensible à la casse. Par défaut, aucun type de système de fichiers n'est ignoré.

Lorsqu'un système de fichiers est ignoré, tous les systèmes de fichiers montés dans le sous-arbre sont également ignorés, même si leur type ne correspond à aucune entrée dans PRUNEFS.

PRUNENAMES
Une liste d'espaces séparant les noms de répertoires (sans chemins) qui ne doivent pas être analysés par updatedb(8). Par défaut, aucun nom de répertoire n'est ignoré.

Notez que seuls les répertoires peuvent être spécifiés, et aucun mécanisme de modèle (par exemple, globbing) n'est utilisé.

PRUNEPATHS
Une liste d'espaces séparant les noms de chemins de répertoires qui ne doivent pas être analysés par updatedb(8). Chaque nom de chemin doit être exactement dans la forme dans laquelle le répertoire serait rapporté par locate(1).

Par défaut, aucun chemin n'est ignoré.

PRUNE_BIND_MOUNTS
L'une des chaînes 0, no, 1 ou yes. Si PRUNE_BIND_MOUNTS est 1 ou yes, les montages par liaison (bind mounts) ne sont pas analysés par updatedb(8). Tous les systèmes de fichiers montés dans le sous-arbre d'un montage par liaison sont également ignorés, même s'ils ne sont pas des montages par liaison. À titre d'exception, les montages par liaison d'un répertoire sur lui-même ne sont pas ignorés. Notez que les montages de sous-volumes Btrfs sont gérés en interne par le noyau comme des montages par liaison (voir btrfs-subvolume(8)), et par conséquent, peuvent être ignorés si vous avez également monté le répertoire racine lui-même. Pour contrer cela, faites de votre répertoire racine un sous-volume Btrfs également.

Par défaut, les montages par liaison ne sont pas ignorés.

NOTES

Lorsqu'un répertoire est trouvé par PRUNEFS, PRUNENAMES ou PRUNEPATHS, updatedb(8) n'analyse pas le contenu du répertoire. Le chemin du répertoire lui-même est, cependant, entré dans la base de données créée. Par exemple, si /tmp est dans PRUNEPATHS, locate(1) n'affichera aucun fichier stocké dans /tmp, mais il peut afficher le répertoire /tmp. Ce comportement diffère des implémentations locate traditionnelles.

Dans certaines implémentations de updatedb(8), PRUNEPATHS peut être utilisé pour exclure des fichiers non-répertoires. Ce n'est pas le cas dans cette implémentation.

/etc/updatedb.conf est un script shell dans certaines implémentations, ce qui permet beaucoup plus de flexibilité dans la définition des variables. Une fonctionnalité équivalente peut être obtenue en utilisant les options de ligne de commande pour updatedb(8).
