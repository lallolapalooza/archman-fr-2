USERMOD(8) Commandes de gestion du système USERMOD(8)

NOM

usermod - modifier un compte utilisateur

SYNTAXE

usermod [options] LOGIN

DESCRIPTION

La commande usermod modifie les fichiers de compte système.

OPTIONS

Les options qui s'appliquent à la commande usermod sont :

-a, --append

Ajoute l'utilisateur aux groupes supplémentaires. À utiliser uniquement avec l'option -G.

-b, --badname

Autorise les noms qui ne respectent pas les normes.

-c, --comment COMMENTAIRE

Met à jour le champ commentaire de l'utilisateur dans /etc/passwd, qui est normalement modifié à l'aide de l'utilitaire chfn(1).

-d, --home DIR_ACCUEIL

Nouveau répertoire de connexion de l'utilisateur.

Si l'option -m est fournie, le contenu du répertoire personnel actuel sera déplacé vers le nouveau répertoire personnel, qui sera créé s'il n'existe pas déjà. Si le répertoire personnel actuel n'existe pas, le nouveau répertoire personnel ne sera pas créé.

-e, --expiredate DATE_EXPIRATION

Spécifie la date à laquelle le compte utilisateur sera désactivé. La valeur peut être spécifiée sous forme de date au format AAAA-MM-JJ ou sous forme d'un nombre de jours depuis le 1970-01-01. La date est interprétée en utilisant le fuseau horaire UTC.

Une valeur de -1 ou une chaîne vide effacera le champ d'expiration du compte dans le fichier shadow des mots de passe. Le compte restera disponible sans date d'expiration.

Cette option nécessite le fichier /etc/shadow. S'il n'y a pas d'entrée dans le fichier /etc/shadow, le système en créera automatiquement une.

-f, --inactive INACTIF

Définit le nombre de jours après que le mot de passe ait dépassé son âge maximum pendant lequel l'utilisateur peut encore se connecter en changeant immédiatement son mot de passe. Si l'utilisateur ne change pas son mot de passe pendant cette période, son compte devient inactif. Cette valeur est stockée dans le fichier shadow des mots de passe.

Une valeur de 0 désactive le compte lorsque le mot de passe expire, sans délai.

Une valeur de -1 vide le champ respectif dans le fichier shadow des mots de passe, ce qui signifie que la période d'inactivité n'est pas appliquée.

Cette option nécessite le fichier /etc/shadow. S'il n'y a pas d'entrée dans le fichier /etc/shadow, le système en créera automatiquement une.

-g, --gid GROUPE

Le nom ou l'identifiant numérique du nouveau groupe principal de l'utilisateur. Le groupe doit exister.

Tous les fichiers du répertoire personnel de l'utilisateur appartenant à l'ancien groupe principal de l'utilisateur appartiendront à ce nouveau groupe.

La propriété des fichiers en dehors du répertoire personnel de l'utilisateur doit être corrigée manuellement.

La modification de la propriété des fichiers à l'intérieur du répertoire personnel de l'utilisateur n'est pas non plus effectuée si l'UID du propriétaire du répertoire personnel est différent de l'UID actuel ou nouvel utilisateur. Il s'agit d'une mesure de sécurité pour les répertoires personnels spéciaux tels que /.

-G, --groups GROUPE1[,GROUPE2[,...[,GROUPN]]]

Une liste de groupes supplémentaires dont l'utilisateur est également membre. Chaque groupe est séparé du suivant par une virgule, sans espace intermédiaire. Les groupes doivent exister.

Si l'utilisateur est actuellement membre d'un groupe qui ne figure pas dans la liste, l'utilisateur sera supprimé de ce groupe. Ce comportement peut être modifié via l'option -a, qui ajoute l'utilisateur à la liste actuelle des groupes supplémentaires.

-l, --login NOUVEAU_LOGIN

Le nom de l'utilisateur sera modifié de LOGIN à NOUVEAU_LOGIN. Rien d'autre n'est modifié. En particulier, le répertoire personnel ou la boîte aux lettres de l'utilisateur devraient probablement être renommés manuellement pour refléter le nouveau nom de connexion.

-L, --lock

Verrouille le mot de passe d'un utilisateur. Cela place un '!' devant le mot de passe chiffré, désactivant ainsi le mot de passe. Vous ne pouvez pas utiliser cette option avec -p ou -U.

Note : si vous souhaitez verrouiller le compte (pas seulement l'accès avec un mot de passe), vous devriez également définir DATE_EXPIRATION à 1.

-m, --move-home

déplace le contenu du répertoire personnel de l'utilisateur vers le nouvel emplacement. Si le répertoire personnel actuel n'existe pas, le nouveau répertoire personnel ne sera pas créé.

Cette option n'est valide qu'en combinaison avec l'option -d (ou --home).

usermod tentera d'adapter la propriété des fichiers et de copier les modes, ACL et attributs étendus, mais des modifications manuelles pourraient être nécessaires par la suite.

-o, --non-unique

permet de changer l'ID utilisateur pour une valeur non unique.

Cette option n'est valide qu'en combinaison avec l'option -u. Comme une identité utilisateur sert de clé pour faire le lien entre les utilisateurs d'une part, et les permissions, la propriété des fichiers et d'autres aspects qui déterminent le comportement du système d'autre part, plus d'un nom de connexion accéderont au compte de l'UID donné.

-p, --password MOT_DE_PASSE

définit un nouveau mot de passe pour l'utilisateur. Le MOT_DE_PASSE est censé être chiffré, tel que retourné par crypt (3).

Note : Évitez cette option dans la ligne de commande car le mot de passe (ou le mot de passe chiffré) sera visible par les utilisateurs qui listent les processus.

Le mot de passe sera écrit dans le fichier local /etc/passwd ou /etc/shadow. Cela peut différer de la base de données des mots de passe configurée dans votre configuration PAM.

Vous devez vous assurer que le mot de passe respecte la politique de mot de passe du système.

-r, --remove

Supprime l'utilisateur des groupes supplémentaires nommés. À utiliser uniquement avec l'option -G.

-R, --root DIR_CHROOT

Applique les modifications dans le répertoire DIR_CHROOT et utilise les fichiers de configuration du répertoire DIR_CHROOT. Seuls les chemins absolus sont pris en charge.

-P, --prefix PREFIX_DIR

Applique les modifications dans l'arborescence des répertoires commençant par PREFIX_DIR et utilise également les fichiers de configuration situés là. Cette option ne fait pas de chroot et est destinée à la préparation d'une cible de compilation croisée. Certaines limitations : les utilisateurs/groupes NIS et LDAP ne sont pas vérifiés. L'authentification PAM utilise les fichiers de l'hôte. Pas de support SELINUX.

-s, --shell SHELL

change le shell de connexion de l'utilisateur. Une chaîne vide pour SHELL efface le champ dans /etc/passwd et connecte l'utilisateur au shell par défaut du système.

-u, --uid UID

La nouvelle valeur de l'ID de l'utilisateur.

Cette valeur doit être unique, sauf si l'option -o est utilisée. La valeur doit être non négative.

La boîte aux lettres de l'utilisateur, et tous les fichiers appartenant à l'utilisateur et situés dans son répertoire personnel, auront automatiquement leur UID modifié.

La propriété des fichiers en dehors du répertoire personnel de l'utilisateur doit être corrigée manuellement.

La modification de la propriété des fichiers à l'intérieur du répertoire personnel de l'utilisateur n'est pas non plus effectuée si l'UID du propriétaire du répertoire personnel est différent de l'UID actuel ou nouvel utilisateur. Il s'agit d'une mesure de sécurité pour les répertoires personnels spéciaux tels que /.

Aucune vérification ne sera effectuée concernant UID_MIN, UID_MAX, SYS_UID_MIN ou SYS_UID_MAX de /etc/login.defs.

-U, --unlock

Déverrouille le mot de passe d'un utilisateur. Cela supprime le '!' devant le mot de passe chiffré. Vous ne pouvez pas utiliser cette option avec -p ou -L.

-v, --add-subuids FIRST-LAST

Ajoute une plage d'UID subordonnés au compte de l'utilisateur.

Cette option peut être spécifiée plusieurs fois pour ajouter plusieurs plages au compte d'un utilisateur.

Aucune vérification ne sera effectuée concernant SUB_UID_MIN, SUB_UID_MAX ou SUB_UID_COUNT de /etc/login.defs.

-V, --del-subuids FIRST-LAST

Supprime une plage d'UID subordonnés du compte de l'utilisateur.

Cette option peut être spécifiée plusieurs fois pour supprimer plusieurs plages du compte d'un utilisateur. Lorsque --del-subuids et --add-subuids sont spécifiés, la suppression de toutes les plages d'UID subordonnés se produit avant l'ajout de toute plage d'UID subordonné.

Aucune vérification ne sera effectuée concernant SUB_UID_MIN, SUB_UID_MAX ou SUB_UID_COUNT de /etc/login.defs.

-w, --add-subgids FIRST-LAST

Ajoute une plage de GID subordonnés au compte de l'utilisateur.

Cette option peut être spécifiée plusieurs fois pour ajouter plusieurs plages au compte d'un utilisateur.

Aucune vérification ne sera effectuée concernant SUB_GID_MIN, SUB_GID_MAX ou SUB_GID_COUNT de /etc/login.defs.

-W, --del-subgids FIRST-LAST

Supprime une plage de GID subordonnés du compte de l'utilisateur.

Cette option peut être spécifiée plusieurs fois pour supprimer plusieurs plages du compte d'un utilisateur. Lorsque --del-subgids et --add-subgids sont spécifiés, la suppression de toutes les plages de GID subordonnés se produit avant l'ajout de toute plage de GID subordonné.

Aucune vérification ne sera effectuée concernant SUB_GID_MIN, SUB_GID_MAX ou SUB_GID_COUNT de /etc/login.defs.

-Z, --selinux-user SEUSER

définit l'utilisateur SELinux à mapper avec LOGIN. Une chaîne vide ("") supprimera l'entrée correspondante (le cas échéant). Notez que le système shadow ne stocke pas l'utilisateur selinux, il utilise semanage(8) pour cela.

--selinux-range SERANGE

définit la plage MLS SELinux pour le nouveau compte. Notez que le système shadow ne stocke pas la plage selinux, il utilise semanage(8) pour cela.

Cette option n'est valide que si l'option -Z (ou --selinux-user) est spécifiée.

CAVEATS

Vous devez vous assurer que l'utilisateur nommé n'exécute aucun processus lorsque cette commande est exécutée si l'ID utilisateur numérique, le nom d'utilisateur ou le répertoire personnel de l'utilisateur est modifié. usermod vérifie cela sous Linux. Sur d'autres systèmes d'exploitation, il utilise uniquement utmp pour vérifier si l'utilisateur est connecté.

Vous devez modifier manuellement le propriétaire de tous les fichiers crontab ou les tâches at.

Vous devez apporter toutes les modifications impliquant NIS sur le serveur NIS.

CONFIGURATION

Les variables de configuration suivantes dans /etc/login.defs modifient le comportement de cet outil :

LASTLOG_UID_MAX (nombre)

ID utilisateur le plus élevé pour lequel les entrées lastlog doivent être mises à jour. Comme les IDs utilisateur plus élevés sont généralement suivis par des services d'authentification et d'identité d'utilisateur distants, il n'est pas nécessaire de créer un fichier lastlog sparse énorme pour eux.

L'absence de l'option LASTLOG_UID_MAX dans la configuration signifie qu'il n'y a pas de limite d'ID utilisateur pour écrire les entrées lastlog.

MAIL_DIR (chaîne)

Le répertoire des spools de messagerie. Ceci est nécessaire pour manipuler la boîte aux lettres lorsque son compte utilisateur correspondant est modifié ou supprimé. Si non spécifié, une valeur par défaut au moment de la compilation est utilisée. Le paramètre CREATE_MAIL_SPOOL dans /etc/default/useradd détermine si le spool de messagerie doit être créé.

MAIL_FILE (chaîne)

Définit l'emplacement des fichiers de spool de messagerie des utilisateurs par rapport à leur répertoire personnel.

Les variables MAIL_DIR et MAIL_FILE sont utilisées par useradd, usermod et userdel pour créer, déplacer ou supprimer le spool de messagerie de l'utilisateur.

MAX_MEMBERS_PER_GROUP (nombre)

Nombre maximum de membres par entrée de groupe. Lorsque le maximum est atteint, une nouvelle entrée de groupe (ligne) est commencée dans /etc/group (avec le même nom, le même mot de passe et le même GID).

La valeur par défaut est 0, ce qui signifie qu'il n'y a pas de limite au nombre de membres dans un groupe.

Cette fonctionnalité (groupe divisé) permet de limiter la longueur des lignes dans le fichier de groupe. Ceci est utile pour s'assurer que les lignes des groupes NIS ne dépassent pas 1024 caractères.

Si vous avez besoin d'appliquer une telle limite, vous pouvez utiliser 25.

Remarque : les groupes divisés peuvent ne pas être pris en charge par tous les outils (même dans la suite d'outils Shadow). Vous ne devriez pas utiliser cette variable à moins que vous n'en ayez vraiment besoin.

SUB_GID_MIN (nombre), SUB_GID_MAX (nombre), SUB_GID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur a déjà des IDs de groupe subordonnés) allouent SUB_GID_COUNT IDs de groupe inutilisés de la plage SUB_GID_MIN à SUB_GID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT sont respectivement 100000, 600100000 et 65536.

SUB_UID_MIN (nombre), SUB_UID_MAX (nombre), SUB_UID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur a déjà des IDs utilisateur subordonnés) allouent SUB_UID_COUNT IDs utilisateur inutilisés de la plage SUB_UID_MIN à SUB_UID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT sont respectivement 100000, 600100000 et 65536.
