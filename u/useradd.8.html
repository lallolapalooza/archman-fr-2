USERADD(8) Commandes de gestion du système USERADD(8)

NOM

useradd - créer un nouvel utilisateur ou mettre à jour les informations par défaut du nouvel utilisateur

SYNTAXE

useradd [options] LOGIN

useradd -D

useradd -D [options]

DESCRIPTION

Lorsqu'il est appelé sans l'option -D, la commande useradd crée un nouveau compte utilisateur en utilisant les valeurs spécifiées sur la ligne de commande plus les valeurs par défaut du système. Selon les options de la ligne de commande, la commande useradd mettra à jour les fichiers système et pourra également créer le répertoire personnel du nouvel utilisateur et copier les fichiers initiaux.

Par défaut, un groupe sera également créé pour le nouvel utilisateur (voir -g, -N, -U, et USERGROUPS_ENAB).

OPTIONS

Les options qui s'appliquent à la commande useradd sont :

--badname 

Autorise les noms qui ne respectent pas les normes.

-b, --base-dir BASE_DIR

Le répertoire de base par défaut pour le système si -d HOME_DIR n'est pas spécifié. BASE_DIR est concaténé avec le nom du compte pour définir le répertoire personnel.

Si cette option n'est pas spécifiée, useradd utilisera le répertoire de base spécifié par la variable HOME dans /etc/default/useradd, ou /home par défaut.

-c, --comment COMMENT

Toute chaîne de caractères. Il s'agit généralement d'une brève description du compte, et elle est actuellement utilisée comme champ pour le nom complet de l'utilisateur.

-d, --home-dir HOME_DIR

Le nouvel utilisateur sera créé en utilisant HOME_DIR comme valeur pour le répertoire de connexion de l'utilisateur. Par défaut, le nom LOGIN est ajouté à BASE_DIR et utilisé comme nom de répertoire de connexion. Le répertoire HOME_DIR n'est pas créé par défaut. Cependant, il sera créé pour les utilisateurs non système si l'option -m est spécifiée ou si CREATE_HOME dans login.defs est défini à true. Cependant, il ne sera jamais créé si l'option -M est spécifiée.

-D, --defaults

Voir ci-dessous, la sous-section « Modification des valeurs par défaut ».

-e, --expiredate EXPIRE_DATE

Définit la date à laquelle le compte utilisateur sera désactivé. La valeur peut être spécifiée sous forme de date au format AAAA-MM-JJ ou sous forme de nombre de jours depuis le 1970-01-01. La date est interprétée en utilisant le fuseau horaire UTC.

Si elle n'est pas spécifiée, useradd utilise la date d'expiration par défaut spécifiée par la variable EXPIRE dans /etc/default/useradd, ou une chaîne vide (pas d'expiration) par défaut.

-f, --inactive INACTIVE

Définit le nombre de jours après que le mot de passe a dépassé son âge maximal avant que le compte utilisateur ne soit verrouillé. Si l'utilisateur ne change pas son mot de passe pendant cette période, son compte devient inactif. Cette valeur est stockée dans le fichier des mots de passe shadow. Pour plus d'informations, voir shadow(5).

Une valeur de 0 désactive le compte lorsque le mot de passe expire, sans délai.

Une valeur de -1 vide le champ respectif dans le fichier des mots de passe shadow, ce qui signifie que la période d'inactivité n'est pas appliquée.

Si elle n'est pas spécifiée, useradd utilise la période d'inactivité par défaut spécifiée par la variable INACTIVE dans /etc/default/useradd, ou -1 par défaut si aucune valeur n'est spécifiée.

-F, --add-subids-for-system

Met à jour /etc/subuid et /etc/subgid même lors de la création d'un compte système avec l'option -r.

-g, --gid GROUPE

Le nom ou le numéro du groupe primaire de l'utilisateur. Le nom du groupe doit exister. Un numéro de groupe doit faire référence à un groupe déjà existant.

Si elle n'est pas spécifiée, le comportement de useradd dépendra de la variable USERGROUPS_ENAB dans /etc/login.defs. Si cette variable est définie à yes (ou si -U/--user-group est spécifié sur la ligne de commande), un groupe sera créé pour l'utilisateur, portant le même nom que le login. Si la variable est définie à no (ou si -N/--no-user-group est spécifié sur la ligne de commande), useradd définira le groupe primaire du nouvel utilisateur sur la valeur spécifiée par la variable GROUP dans /etc/default/useradd, ou 1000 par défaut.

-G, --groups GROUPE1[,GROUPE2,...[,GROUPN]]]

Une liste de groupes supplémentaires dont l'utilisateur est également membre. Chaque groupe est séparé du suivant par une virgule, sans espace blanc intermédiaire. Les groupes sont soumis aux mêmes restrictions que le groupe donné avec l'option -g. Par défaut, l'utilisateur n'appartient qu'au groupe initial. En plus de passer le drapeau -G, vous pouvez ajouter l'option GROUPS au fichier /etc/default/useradd, qui ajoutera ensuite tous les utilisateurs à ces groupes supplémentaires.

-h, --help

Affiche le message d'aide et quitte.

-k, --skel SKEL_DIR

Le répertoire squelette, qui contient les fichiers et répertoires à copier dans le répertoire personnel de l'utilisateur, lorsque le répertoire personnel est créé par useradd.

Cette option n'est valide que si l'option -m (ou --create-home) est spécifiée.

Si cette option n'est pas définie, le répertoire squelette est défini par la variable SKEL dans /etc/default/useradd ou, par défaut, par /etc/skel.

Les liens symboliques absolus qui renvoient au répertoire squelette auront le préfixe /etc/skel remplacé par le répertoire personnel de l'utilisateur.

Si possible, les ACL et les attributs étendus sont copiés.

-K, --key KEY=VALUE

Remplace les valeurs par défaut de /etc/login.defs (UID_MIN, UID_MAX, UMASK, PASS_MAX_DAYS et autres).

Exemple : -K PASS_MAX_DAYS =-1 peut être utilisé lors de la création d'un compte pour désactiver le vieillissement des mots de passe. Plusieurs options -K peuvent être spécifiées, par exemple : -K UID_MIN =100 -K UID_MAX=499

-l, --no-log-init

N'ajoute pas l'utilisateur aux bases de données lastlog et faillog.

Par défaut, les entrées de l'utilisateur dans les bases de données lastlog et faillog sont réinitialisées pour éviter de réutiliser l'entrée d'un utilisateur précédemment supprimé.

Si cette option n'est pas spécifiée, useradd consultera également la variable LOG_INIT dans /etc/default/useradd ; si elle est définie à no, l'utilisateur ne sera pas ajouté aux bases de données lastlog et faillog.

-m, --create-home

Crée le répertoire personnel de l'utilisateur s'il n'existe pas. Les fichiers et répertoires contenus dans le répertoire squelette (qui peut être défini avec l'option -k) seront copiés dans le répertoire personnel.

Par défaut, si cette option n'est pas spécifiée et que CREATE_HOME n'est pas activé, aucun répertoire personnel n'est créé.

Le répertoire où le répertoire personnel de l'utilisateur est créé doit exister et avoir un contexte SELinux et des permissions appropriés. Sinon, le répertoire personnel de l'utilisateur ne pourra pas être créé ni accédé.

-M, --no-create-home

Ne crée pas le répertoire personnel de l'utilisateur, même si le paramètre global du système défini dans /etc/login.defs (CREATE_HOME) est défini à yes.

-N, --no-user-group

Ne crée pas de groupe portant le même nom que l'utilisateur, mais ajoute l'utilisateur au groupe spécifié par l'option -g ou par la variable GROUP dans /etc/default/useradd.

Le comportement par défaut (si les options -g, -N et -U ne sont pas spécifiées) est défini par la variable USERGROUPS_ENAB dans /etc/login.defs.

-o, --non-

unique

permet la création d'un compte avec un UID déjà existant.

Cette option n'est valide qu'en combinaison avec l'option -u. Comme une identité utilisateur sert de clé pour faire le lien entre les utilisateurs d'une part, et les permissions, les propriétaires de fichiers et d'autres aspects qui déterminent le comportement du système d'autre part, plus d'un nom de connexion accèderont au compte de l'UID donné.

-p, --password MOTDEPASSE

définit un mot de passe initial pour le compte. MOTDEPASSE est censé être chiffré, tel que retourné par crypt (3). Dans un script shell, cette option permet de créer efficacement des lots d'utilisateurs.

Sans cette option, le nouveau compte sera verrouillé et sans mot de passe défini, c'est-à-dire un point d'exclamation unique dans le champ respectif de /etc/shadow. C'est une situation où l'utilisateur ne pourra pas accéder au compte ni définir lui-même un mot de passe.

Note : Évitez cette option sur la ligne de commande car le mot de passe (ou le mot de passe chiffré) sera visible par les utilisateurs qui listeront les processus.

Vous devez vous assurer que le mot de passe respecte la politique de mot de passe du système.

-r, --system

Crée un compte système.

Les utilisateurs système seront créés sans informations d'expiration dans /etc/shadow, et leurs identifiants numériques seront choisis dans la plage SYS_UID_MIN-SYS_UID_MAX, définie dans /etc/login.defs, au lieu de UID_MIN-UID_MAX (et leurs homologues GID pour la création de groupes).

Notez que useradd ne créera pas de répertoire personnel pour un tel utilisateur, quelle que soit la valeur par défaut définie dans /etc/login.defs (CREATE_HOME). Vous devez spécifier l'option -m si vous souhaitez qu'un répertoire personnel soit créé pour un compte système.

Notez que cette option ne mettra pas à jour /etc/subuid et /etc/subgid. Vous devez spécifier l'option -F si vous souhaitez que les fichiers soient mis à jour pour la création d'un compte système.

-R, --root DIR_CHROOT

Applique les modifications dans le répertoire DIR_CHROOT et utilise les fichiers de configuration du répertoire DIR_CHROOT. Seuls les chemins absolus sont pris en charge.

-P, --prefix DIR_PREFIX

Applique les modifications aux fichiers de configuration sous le racine du système de fichiers trouvée dans le répertoire DIR_PREFIX. Cette option ne fait pas de chroot et est destinée à la préparation d'une cible de compilation croisée. Certaines limitations : les utilisateurs/groupes NIS et LDAP ne sont pas vérifiés. L'authentification PAM utilise les fichiers de l'hôte. Pas de support SELINUX.

-s, --shell SHELL

définit le chemin vers le shell de connexion de l'utilisateur. Sans cette option, le système utilisera la variable SHELL spécifiée dans /etc/default/useradd, ou, si celle-ci n'est pas non plus définie, le champ du shell de connexion dans /etc/passwd restera vide.

-u, --uid UID

La valeur numérique de l'identifiant de l'utilisateur. Cette valeur doit être unique, sauf si l'option -o est utilisée. La valeur doit être non négative. La valeur par défaut est la plus petite valeur d'ID supérieure ou égale à UID_MIN et supérieure à celle de tous les autres utilisateurs.

Voir également l'option -r et la description de UID_MAX.

-U, --user-group

Crée un groupe portant le même nom que l'utilisateur, et ajoute l'utilisateur à ce groupe.

Le comportement par défaut (si les options -g, -N et -U ne sont pas spécifiées) est défini par la variable USERGROUPS_ENAB dans /etc/login.defs.

-Z, --selinux-user SEUSER

définit l'utilisateur SELinux pour le nouveau compte. Sans cette option, SELinux utilise l'utilisateur par défaut. Notez que le système shadow ne stocke pas le selinux-user, il utilise semanage(8) pour cela.

--selinux-range SERANGE

définit la plage MLS SELinux pour le nouveau compte. Sans cette option, SELinux utilise la plage par défaut. Notez que le système shadow ne stocke pas le selinux-range, il utilise semanage(8) pour cela.

Cette option n'est valide que si l'option -Z (ou --selinux-user) est spécifiée.

Changement des valeurs par défaut

Lorsqu'il est appelé avec uniquement l'option -D, useradd affiche les valeurs par défaut actuelles. Lorsqu'il est appelé avec -D suivi d'autres options, useradd met à jour les valeurs par défaut pour les options spécifiées. Les options valides pour modifier les valeurs par défaut sont :

-b, --base-dir DIR_BASE

définit le chemin préfixe pour le répertoire personnel d'un nouvel utilisateur. Le nom de l'utilisateur sera ajouté à la fin de DIR_BASE pour former le nom du répertoire personnel du nouvel utilisateur, si l'option -d n'est pas utilisée lors de la création d'un nouveau compte.

Cette option définit la variable HOME dans /etc/default/useradd.

-e, --expiredate DATE_EXPIRATION

définit la date à laquelle les comptes utilisateurs nouvellement créés seront désactivés.

Cette option définit la variable EXPIRE dans /etc/default/useradd.

-f, --inactive INACTIF

spécifie le nombre de jours après l'expiration d'un mot de passe pendant lequel l'utilisateur peut toujours se connecter. Après cette période, le compte est verrouillé.

Cette option définit la variable INACTIVE dans /etc/default/useradd.

-g, --gid GROUPE

définit le groupe primaire par défaut pour les nouveaux utilisateurs, acceptant les noms de groupe ou un identifiant numérique de groupe. Le groupe nommé doit exister, et le GID doit avoir une entrée existante.

Cette option définit la variable GROUP dans /etc/default/useradd.

-s, --shell SHELL

définit le shell de connexion par défaut pour les nouveaux utilisateurs.

Cette option définit la variable SHELL dans /etc/default/useradd.

NOTES

L'administrateur système est responsable du placement des fichiers utilisateurs par défaut dans le répertoire /etc/skel/ (ou tout autre répertoire squelette spécifié dans /etc/default/useradd ou sur la ligne de commande).

ATTENTION

Vous ne pouvez pas ajouter un utilisateur à un groupe NIS ou LDAP. Cela doit être effectué sur le serveur correspondant.

De même, si le nom d'utilisateur existe déjà dans une base de données d'utilisateurs externe telle que NIS ou LDAP, useradd rejettera la demande de création de compte utilisateur.

Les noms d'utilisateur ne peuvent contenir que des lettres minuscules et majuscules, des chiffres, des underscores ou des tirets. Ils peuvent se terminer par un signe dollar. Les tirets ne sont pas autorisés au début du nom d'utilisateur. Les noms d'utilisateur entièrement numériques et les noms d'utilisateur . ou .. sont également interdits. Il n'est pas recommandé d'utiliser des noms d'utilisateur commençant par un point car leurs répertoires personnels seront cachés dans la sortie de ls.

Les noms d'utilisateur ne peuvent pas dépasser 256 caractères.

CONFIGURATION

Les variables de configuration suivantes dans /etc/login.defs modifient le comportement de cet outil :

CREATE_HOME (booléen)

Indique si un répertoire personnel doit être créé par défaut pour les nouveaux utilisateurs.

Ce paramètre ne s'applique pas aux utilisateurs système et peut être remplacé sur la ligne de commande.

GID_MAX (nombre), GID_MIN (nombre)

Plage des identifiants de groupe utilisés pour la création de groupes réguliers par useradd, groupadd ou newusers.

La valeur par défaut pour GID_MIN (resp. GID_MAX) est 1000 (resp. 60000).

HOME_MODE (nombre)

Le mode pour les nouveaux répertoires personnels. Si non spécifié, l' UMASK est utilisé pour créer le mode.

useradd et newusers utilisent cela pour définir le mode du répertoire personnel qu'ils créent.

LASTLOG_UID_MAX (nombre)

Le plus grand numéro d'identifiant utilisateur pour lequel les entrées lastlog doivent être mises à jour. Comme les identifiants utilisateur plus élevés sont généralement suivis par des services d'authentification et d'identité utilisateur à distance, il n'est pas nécessaire de créer un fichier lastlog sparse très grand pour eux.

L'absence de l'option LASTLOG_UID_MAX dans la configuration signifie qu'il n'y a pas de limite d'identifiant utilisateur pour l'écriture des entrées lastlog.

MAIL_DIR (chaîne)

Le répertoire de la boîte aux lettres. Ceci est nécessaire pour manipuler la boîte aux lettres lorsque son compte utilisateur correspondant est modifié ou supprimé. Si non spécifié, une valeur par défaut au moment de la compilation est utilisée. Le paramètre CREATE_MAIL_SPOOL dans /etc/default/useradd détermine si la boîte aux lettres doit être créée.

MAIL_FILE (chaîne)

Définit l'emplacement des fichiers de boîte aux lettres des utilisateurs par rapport à leur répertoire personnel.

Les variables MAIL_DIR et MAIL_FILE sont utilisées par useradd, usermod et userdel pour créer, déplacer ou supprimer la boîte aux lettres de l'utilisateur.

MAX_MEMBERS_PER_GROUP (nombre)

Nombre maximum de membres par entrée de groupe. Lorsque le maximum est atteint, une nouvelle entrée de groupe (ligne) est créée dans /etc/group (avec le même nom, le même mot de passe et le même GID).

La valeur par défaut est 0, ce qui signifie qu'il n'y a pas de limite au nombre de membres dans un groupe.

Cette fonctionnalité (groupe divisé) permet de limiter la longueur des lignes dans le fichier de groupe. Ceci est utile pour s'assurer que les lignes pour les groupes NIS ne dépassent pas 1024 caractères.

Si vous devez appliquer une telle limite, vous pouvez utiliser 25.

Remarque : les groupes divisés peuvent ne pas être pris en charge par tous les outils (même dans la suite d'outils Shadow). Vous ne devriez pas utiliser cette variable à moins d'en avoir réellement besoin.

PASS_MAX_DAYS (nombre)

Nombre maximum de jours pendant lesquels un mot de passe peut être utilisé. Si le mot de passe est plus ancien que cela, un changement de mot de passe sera forcé. S'il n'est pas spécifié, -1 sera supposé (ce qui désactive la restriction).

PASS_MIN_DAYS (nombre)

Nombre minimum de jours autorisés entre deux changements de mot de passe. Tout essai de changement de mot de passe avant ce délai sera rejeté. S'il n'est pas spécifié, 0 sera supposé (ce qui désactive la restriction).

PASS_WARN_AGE (nombre)

Nombre de jours d'avertissement donnés avant l'expiration d'un mot de passe. Zéro signifie que l'avertissement n'est donné que le jour de l'expiration, une valeur de -1 signifie qu'aucun avertissement n'est donné. S'il n'est pas spécifié, aucun avertissement ne sera fourni.

useradd(8) - Man pages

NOM

useradd — ajouter un nouvel utilisateur ou modifier des informations d'utilisateur

SYNOPIS

useradd [options] LOGIN

useradd [options] -u UID [-G groupe...] [-g groupe] LOGIN

DESCRIPTION

La commande useradd est une commande de bas niveau pour ajouter des utilisateurs à un système. Les administrateurs système peuvent l'utiliser pour créer un nouveau compte utilisateur. Notez que la plupart des sites ont des utilitaires de plus haut niveau, comme adduser(8), qui peuvent être plus faciles à utiliser.

Après avoir exécuté la commande useradd pour créer un nouvel utilisateur, vous devrez peut-être créer le répertoire personnel de l'utilisateur et définir le mot de passe de celui-ci. Le mot de passe peut être défini à l'aide de la commande passwd(1).

Le programme useradd crée l'utilisateur, alloue des ID de groupe et d'utilisateur, et, en option, ajoute l'utilisateur à des groupes supplémentaires, crée le répertoire personnel de l'utilisateur, et copie les fichiers du répertoire /etc/skel dans le répertoire personnel de l'utilisateur.

OPTIONS

Les options disponibles sont les suivantes :

-b, --base-dir DIR
Le répertoire de base dans lequel le répertoire personnel de l'utilisateur sera créé. Par défaut, il s'agit du répertoire spécifié par la variable d'environnement HOME ou USERGROUPS_ENAB est défini sur yes.
-c, --comment COMMENTAIRE
La chaîne de commentaires du nouveau compte utilisateur. La chaîne habituelle est le nom complet de l'utilisateur.
-d, --home-dir DIR
Le répertoire personnel du nouvel utilisateur. Par défaut, il est créé sous le répertoire de base spécifié par HOME, et possède le même nom que le nom d'utilisateur (LOGIN).
-e, --expire DATE
La date à laquelle le compte de l'utilisateur expirera. La date est au format AAAAMMJJ.
-f, --inactive NOMBRE
Le nombre de jours après l'expiration du mot de passe pendant lequel le compte reste désactivé. Une valeur de 0 signifie que le compte est désactivé immédiatement après l'expiration du mot de passe. Une valeur de -1 désactive la fonction de désactivation des comptes.
-g, --gid GROUPE
Le GID (Group ID) du nouveau compte utilisateur. Ce doit être un entier valide. Si ce paramètre n'est pas spécifié, le GID sera soit le prochain GID disponible du groupe USERGROUPS_ENAB, soit un GID unique.
-G, --groups GROUPE
Une liste de groupes supplémentaires dont le nouvel utilisateur sera membre. Chaque groupe est séparé par une virgule, sans espace.
-m, --create-home
Crée le répertoire personnel de l'utilisateur s'il n'existe pas. Les fichiers du répertoire /etc/skel sont copiés dans le répertoire personnel.
-M, --no-create-home
Ne crée pas le répertoire personnel, même si l'option -m est spécifiée.
-n, --sn
Ne prend pas en compte les noms courts.
-o, --non-unique
Autorise la création d'un utilisateur avec un UID déjà utilisé.
-r, --system
Crée un compte système. Les comptes système sont généralement utilisés pour les démons et les services. Ils ont des UID et des GID dans la plage des UID et GID système définie dans /etc/login.defs.
-s, --shell SHELL
Le nom du shell de connexion de l'utilisateur. La valeur par défaut est le shell spécifié dans le fichier /etc/default/useradd, sinon /bin/sh.
-u, --uid UID
L'UID (User ID) du nouvel utilisateur. Ce doit être un entier unique, sauf si l'option -o est utilisée.
-U, --user-group
Crée un groupe portant le nom de l'utilisateur et l'ajoute à ce groupe. Ceci est le comportement par défaut si USERGROUPS_ENAB est défini sur yes dans /etc/login.defs.

NOTES

La commande useradd peut être utilisée pour créer des utilisateurs dans différents formats de stockage des mots de passe (par exemple, NIS, LDAP). Cela dépend de la configuration du système.

Le comportement par défaut de useradd est contrôlé par les valeurs dans le fichier /etc/default/useradd.

Les fichiers /etc/subuid et /etc/subgid sont utilisés pour allouer des ID d'utilisateur et de groupe subordonnés aux utilisateurs.

CAVEATS

Les changements apportés à /etc/default/useradd ne prennent effet qu'après le redémarrage.

CONFIGURATION

Les paramètres suivants peuvent être configurés dans /etc/login.defs :

GID_MAX (nombre), GID_MIN (nombre)

Plage des GID utilisés pour la création de groupes par groupadd.

LOGIN_RETRIES (nombre)

Nombre de tentatives de connexion avant de refuser la demande.

LOGIN_TIMEOUT (nombre)

Délai d'attente avant de refuser la demande de connexion.

MAX_CLASS (chaîne)

La classe maximale d'une classe d'utilisateurs.

PASS_MAX_DAYS (nombre)

Nombre maximal de jours pendant lesquels un mot de passe est valide.

PASS_MIN_DAYS (nombre)

Nombre minimal de jours entre les changements de mot de passe.

PASS_WARN_AGE (nombre)

Nombre de jours avant l'expiration d'un mot de passe pendant lequel l'utilisateur sera averti.

SUB_GID_COUNT (nombre), SUB_GID_MAX (nombre), SUB_GID_MIN (nombre)

Si /etc/subgid existe, les commandes useradd et newusers (sauf si l'utilisateur a déjà des ID de groupe subordonnés) allouent SUB_GID_COUNT ID de groupe inutilisés dans la plage de SUB_GID_MIN à SUB_GID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT sont respectivement 100000, 600100000 et 65536.

SUB_UID_COUNT (nombre), SUB_UID_MAX (nombre), SUB_UID_MIN (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur a déjà des ID d'utilisateur subordonnés) allouent SUB_UID_COUNT ID d'utilisateur inutilisés dans la plage de SUB_UID_MIN à SUB_UID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT sont respectivement 100000, 600100000 et 65536.

SYS_GID_MAX (nombre), SYS_GID_MIN (nombre)

Plage des GID utilisés pour la création de groupes système par useradd, groupadd, ou newusers.

La valeur par défaut pour SYS_GID_MIN (resp. SYS_GID_MAX) est 101 (resp. GID_MIN-1).

SYS_UID_MAX (nombre), SYS_UID_MIN (nombre)

Plage des UID utilisés pour la création d'utilisateurs système par useradd ou newusers.

La valeur par défaut pour SYS_UID_MIN (resp. SYS_UID_MAX) est 101 (resp. UID_MIN-1).

UID_MAX (nombre), UID_MIN (nombre)

Plage des UID utilisés pour la création d'utilisateurs réguliers par useradd ou newusers.

La valeur par défaut pour UID_MIN (resp. UID_MAX) est 1000 (resp. 60000).

UMASK (nombre)

Le masque de création de fichiers est initialisé à cette valeur. Si non spécifié, le masque sera initialisé à 022.

useradd et newusers utilisent ce masque pour définir le mode du répertoire personnel qu'ils créent si HOME_MODE n'est pas défini.

Il est également utilisé par pam_umask comme valeur umask par défaut.

USERGROUPS_ENAB (booléen)

Si défini sur oui, userdel supprimera le groupe de l'utilisateur s'il ne contient plus de membres, et useradd créera par défaut un groupe portant le nom de l'utilisateur.

Valeurs par défaut pour la création de compte.

/etc/shadow-maint/useradd-pre.d/*, /etc/shadow-maint/useradd-post.d/*

Fichiers run-part à exécuter lors de l'ajout d'un utilisateur. La variable d'environnement ACTION sera remplie avec useradd et SUBJECT avec le nom d'utilisateur. useradd-pre.d sera exécuté avant tout ajout d'utilisateur. useradd-post.d s'exécutera après l'ajout d'utilisateur. Si un script se termine avec une valeur non nulle, l'exécution sera interrompue.

Configuration de la suite de mots de passe shadow.
