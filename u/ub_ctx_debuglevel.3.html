DESCRIPTION

Unbound est une implémentation d'un résolveur DNS, qui fait de la mise en cache et de la validation DNSSEC. Ceci est l'API de la bibliothèque, pour utiliser la bibliothèque -lunbound. Le démon serveur est décrit dans unbound(8). La bibliothèque fonctionne indépendamment d'un serveur unbound en cours d'exécution et peut être utilisée pour convertir des noms d'hôtes en adresses IP et vice versa, et obtenir d'autres informations du DNS. La bibliothèque effectue une validation par clé publique des résultats avec DNSSEC.

La bibliothèque utilise une variable de type struct ub_ctx pour conserver le contexte entre les appels. L'utilisateur doit la maintenir, en la créant avec ub_ctx_create et en la supprimant avec ub_ctx_delete. Elle peut être créée et supprimée à tout moment. La recréer supprime toute configuration précédente (telle que les ancres de confiance) et efface tous les résultats mis en cache.

Les fonctions sont thread-safe, et un contexte peut être utilisé dans un environnement threadé (ainsi que dans un environnement non-threadé). La résolution (et la validation) peut également être effectuée de manière bloquante et non-bloquante (également appelée asynchrone). La méthode asynchrone retourne immédiatement après l'appel, de sorte que le traitement peut continuer pendant que les résultats deviennent disponibles plus tard.

Les fonctions sont discutées tour à tour ci-dessous.

FONCTIONS

ub_ctx_create
Crée un nouveau contexte, initialisé avec des valeurs par défaut. Les informations de /etc/resolv.conf et /etc/hosts ne sont pas utilisées par défaut. Utilisez ub_ctx_resolvconf et ub_ctx_hosts pour les lire. Avant d'appeler cette fonction, utilisez les fonctions openssl CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer une opération asynchrone si vous utilisez la bibliothèque openssl (l'application appelle ces fonctions une fois pour l'initialisation). Openssl 1.0.0 ou ultérieur utilise la fonction CRYPTO_THREADID_set_callback.
ub_ctx_delete
Supprime le contexte de validation et libère les ressources associées. Les requêtes asynchrones en cours sont annulées et les callbacks ne sont pas appelés pour elles.
ub_ctx_set_option
Une interface pour utilisateurs expérimentés qui permet de spécifier une des options du format de fichier de configuration, voir unbound.conf(5). Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Passez le nom de l'option avec le ':' final.
ub_ctx_get_option
Une interface pour utilisateurs expérimentés qui récupère la valeur d'une option. Certaines options ne peuvent pas être récupérées, et d'autres retournent une liste séparée par des nouvelles lignes. Passez le nom de l'option sans le ':' final. La valeur retournée doit être libérée (free(2)) par l'appelant.
ub_ctx_config
Une interface pour utilisateurs expérimentés qui permet de spécifier un fichier de configuration unbound, voir unbound.conf(5), qui est lu pour la configuration. Toutes les options ne sont pas pertinentes. Pour certaines options spécifiques, comme l'ajout d'ancres de confiance, des routines spéciales existent. Cette fonction est thread-safe uniquement si une seule instance de ub_ctx* existe dans l'application. Si plusieurs instances existent, l'application doit s'assurer que ub_ctx_config n'est pas appelée en parallèle par les différentes instances.
ub_ctx_set_fwd
Définit la machine vers laquelle transférer les requêtes DNS, le résolveur de mise en cache à utiliser. Adresse IP4 ou IP6. Transfère toutes les requêtes DNS vers cette machine, qui est censée exécuter un résolveur récursif. Si le proxy n'est pas compatible DNSSEC, la validation peut échouer. Peut être appelée plusieurs fois, dans ce cas, les adresses sont utilisées comme serveurs de secours. Il n'est possible à l'heure actuelle de définir la configuration qu'avant la première résolution.
ub_ctx_set_stub
Définit une zone stub, des serveurs DNS autoritaires à utiliser pour une zone particulière. Adresse IP4 ou IP6. Si l'adresse est NULL, l'entrée stub est supprimée. Réglez isprime à vrai si vous configurez des hints racine avec. Sinon, similaire à l'élément de zone stub du fichier de configuration d'unbound. Peut être appelée plusieurs fois, pour différentes zones, ou pour ajouter plusieurs adresses pour une zone particulière. Il n'est possible à l'heure actuelle de définir la configuration qu'avant la première résolution.
ub_ctx_set_tls
Active le DNS via TLS (DoT) pour les machines définies avec ub_ctx_set_fwd. Il n'est possible à l'heure actuelle de définir la configuration qu'avant la première résolution.
ub_ctx_resolvconf
Par défaut, les serveurs racine sont interrogés et le mode de résolution complet est utilisé, mais vous pouvez utiliser cet appel pour lire la liste des noms de serveurs à utiliser à partir du nom de fichier donné. Généralement "/etc/resolv.conf". Utilise ces noms de serveurs comme proxies de mise en cache. S'ils ne supportent pas DNSSEC, la validation peut échouer. Seuls les noms de serveurs sont récupérés, le domain de recherche, ndots et les autres paramètres de resolv.conf(5) sont ignorés. Si fname NULL est passé, "/etc/resolv.conf" est utilisé (si sous Windows, le serveur de noms configuré au niveau du système est choisi à la place). Il n'est possible à l'heure actuelle de définir la configuration qu'avant la première résolution.
ub_ctx_hosts
Lit la liste des hôtes depuis le nom de fichier donné. Généralement "/etc/hosts". Lorsqu'elles sont interrogées, ces adresses ne sont pas marquées comme sécurisées par DNSSEC. Si fname NULL est passé, "/etc/hosts" est utilisé (si sous Windows, etc/hosts depuis WINDIR est choisi à la place). Il n'est possible à l'heure actuelle de définir la configuration qu'avant la première résolution.

DESCRIPTION

The unbound library is a high-level API to the unbound(8) validating, recursive, caching DNS resolver. It allows applications to perform DNS lookups from within the application, and get back validated results.

The library supports:

  • DNS resolution and validation.
  • DNSSEC support for validation.
  • Asynchronous operation, for non-blocking lookups.
  • Threaded operation, for multiple lookups in parallel.
  • Local data and zone overrides.

The library is designed to be used by applications that require validated DNS data. For example, applications that need to ensure they are talking to the correct server, or that the data they receive is authentic.

FUNCTIONS

ub_ctx_create
Create a context for the unbound library. This context is used for all further communication with the library. Multiple contexts can be created, each operating independently. A context needs to be created before any other unbound library function can be called. Returns a pointer to the new context, or NULL on error.
ub_ctx_delete
Delete a context created by ub_ctx_create. This frees all memory associated with the context and cleans up any resources held by it. All outstanding lookups associated with the context are cancelled.
ub_ctx_resolvconf
Read the system's resolver configuration file (e.g. /etc/resolv.conf) into the context. This configures the stub resolvers for the unbound library. On success, returns 0, otherwise returns an error code.
ub_ctx_config
Read unbound configuration options from the specified file into the context. This allows applications to control the behavior of unbound without needing to run a separate unbound process. On success, returns 0, otherwise returns an error code.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

STRUCTURE DE DONNEES DE RESULTAT

Le résultat de la résolution et de la validation DNS est retourné sous forme de *struct* *ub_result*. La structure de résultat contient les entrées suivantes :

struct ub_result {
     char* qname;         /* chaîne de caractères, question originale */
     int qtype;           /* code de type demandé */
     int qclass;          /* code de classe demandé */
     char** data;         /* tableau d'éléments rdata, terminé par NULL */
     int* len;            /* tableau avec les longueurs des éléments rdata */
     char* canonname;     /* nom canonique du résultat */
     int rcode;           /* code d'erreur supplémentaire en cas d'absence de données */
     void* answer_packet; /* paquet complet au format réseau */
     int answer_len;      /* longueur du paquet en octets */
     int havedata;        /* vrai s'il y a des données */
     int nxdomain;        /* vrai s'il n'y a pas de données car le nom n'existe pas */
     int secure;          /* vrai si le résultat est sécurisé */
     int bogus;           /* vrai si une défaillance de sécurité s'est produite */
     char* why_bogus;     /* chaîne avec l'erreur si bogus */
     int was_ratelimited; /* vrai si la requête a été limitée par le débit (SERVFAIL) par unbound */
     int ttl;             /* nombre de secondes pendant lesquelles le résultat est valide */
};

Si secure et bogus sont tous deux faux, la sécurité n'était pas activée pour le domaine de la requête. Sinon, ils ne sont pas tous deux vrais, l'un d'eux est vrai.

VALEURS DE RETOUR

De nombreuses routines retournent un code d'erreur. La valeur 0 (zéro) indique qu'aucune erreur ne s'est produite. D'autres valeurs peuvent être passées à ub_strerror pour obtenir une chaîne d'erreur lisible. ub_strerror retourne une chaîne terminée par un zéro. ub_ctx_create retourne NULL en cas d'erreur (échec d'allocation mémoire). ub_poll retourne vrai si des informations peuvent être disponibles, faux sinon. ub_fd retourne un descripteur de fichier ou -1 en cas d'erreur. ub_ctx_config et ub_ctx_resolvconf tentent de laisser errno informatif lors d'un retour de fonction avec échec de lecture de fichier.

NOM

ls - lister les fichiers

SYNTAXE

ls [OPTION]... [FICHIER]...

DESCRIPTION

Lister les informations sur les fichiers (par défaut, le répertoire courant). Trier et afficher les informations des fichiers.

Les options courantes incluent :

  • -l : Utiliser un format de liste long.
  • -a : Afficher tous les fichiers, y compris ceux commençant par un point (.).
  • -h : Avec -l, afficher les tailles dans un format lisible par l'homme (par exemple, 1K, 234M, 2G).
  • -t : Trier par date de modification, du plus récent au plus ancien.

EXEMPLES

ls -l : Lister les fichiers du répertoire courant dans un format long.

ls -a /home/user : Lister tous les fichiers (y compris les cachés) du répertoire /home/user.

ls -lh : Lister les fichiers dans un format long et lisible par l'homme.
