NOM

udplite — Protocole léger de datagrammes utilisateur

SYNTAXE

#include <sys/socket.h>
sockfd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDPLITE);

DESCRIPTION

Ceci est une implémentation du Protocole Léger de Datagrammes Utilisateur (UDP-Lite), tel que décrit dans la RFC 3828.

UDP-Lite est une extension de UDP (RFC 768) pour supporter des sommes de contrôle de longueur variable. Cela présente des avantages pour certains types de transport multimédia qui peuvent être capables d'utiliser des datagrammes légèrement endommagés, plutôt que de les faire rejeter par les protocoles de couche inférieure.

La couverture de somme de contrôle de longueur variable est définie via une option de setsockopt(2). Si cette option n'est pas définie, la seule différence avec UDP réside dans l'utilisation d'un identifiant de protocole IP différent (numéro IANA 136).

L'implémentation UDP-Lite est une extension complète de udp(7) — c'est-à-dire qu'elle partage la même API et le même comportement d'API, et offre en plus deux options de socket pour contrôler la couverture de somme de contrôle.

Format d'adresse

UDP-Litev4 utilise le format d'adresse sockaddr_in décrit dans ip(7). UDP-Litev6 utilise le format d'adresse sockaddr_in6 décrit dans ipv6(7).

Options de socket

Pour définir ou obtenir une option de socket UDP-Lite, appelez getsockopt(2) pour lire ou setsockopt(2) pour écrire l'option avec l'argument de niveau d'option défini sur IPPROTO_UDPLITE. De plus, toutes les options de socket IPPROTO_UDP sont valides sur un socket UDP-Lite. Voir udp(7) pour plus d'informations.

Les deux options suivantes sont spécifiques à UDP-Lite.

UDPLITE_SEND_CSCOV
Cette option définit la couverture de somme de contrôle de l'expéditeur et prend un entier int comme argument, avec une valeur de couverture de somme de contrôle dans la plage 0..2^16-1.
Une valeur de 0 signifie que le datagramme entier est toujours couvert. Les valeurs de 1 à 7 sont illégales (RFC 3828, 3.1) et sont arrondies à la couverture minimale de 8.
Concernant les jumbogrammes IPv6 (RFC 2675), la couverture de somme de contrôle UDP-Litev6 est limitée aux 2^16-1 premiers octets, conformément à la RFC 3828, 3.5. Les valeurs plus élevées sont donc silencieusement tronquées à 2^16-1. En cas de doute, la valeur de couverture actuelle peut toujours être interrogée à l'aide de getsockopt(2).
UDPLITE_RECV_CSCOV
C'est l'analogue côté récepteur et utilise le même format d'argument et la même plage de valeurs que UDPLITE_SEND_CSCOV. Cette option n'est pas nécessaire pour activer le trafic avec une couverture de somme de contrôle partielle. Sa fonction est celle d'un filtre de trafic : lorsqu'elle est activée, elle demande au noyau de rejeter tous les paquets dont la couverture est inférieure à la valeur spécifiée.
Lorsque la valeur de UDPLITE_RECV_CSCOV dépasse la couverture réelle du paquet, les paquets entrants sont silencieusement rejetés, mais peuvent générer un message d'avertissement dans le journal système.

ERREURS

Toutes les erreurs documentées pour udp(7) peuvent être retournées. UDP-Lite n'ajoute pas d'erreurs supplémentaires.

VERSIONS

UDP-Litev4/v6 est apparu pour la première fois dans Linux 2.6.20.

BOGUES

Là où le support de glibc manque, les définitions suivantes sont nécessaires :


#define IPPROTO_UDPLITE     136
#define UDPLITE_SEND_CSCOV  10
#define UDPLITE_RECV_CSCOV  11
