YASM_ARCH(7) Architectures cibles prises en charge par Yasm YASM_ARCH(7)

NOM

yasm_arch - Architectures cibles prises en charge par Yasm

SYNTAXE

yasm -a arch [-m machine] ...

DESCRIPTION

La distribution standard de Yasm comprend un certain nombre de modules pour différentes architectures cibles. Chaque architecture cible peut prendre en charge une ou plusieurs architectures machine.

L'architecture et la machine sont sélectionnées sur la ligne de commande yasm(1) à l'aide des options de ligne de commande -a arch et -m machine, respectivement.

L'architecture machine peut également être sélectionnée automatiquement par certains formats d'objets. Par exemple, le format d'objet « elf32 » sélectionne l'architecture machine « x86 » par défaut, tandis que le format d'objet « elf64 » sélectionne l'architecture machine « amd64 » par défaut.

ARCHITECTURE X86

L'architecture « x86 » prend en charge l'ensemble d'instructions IA-32 et ses dérivés, ainsi que l'ensemble d'instructions AMD64. Elle se compose de deux machines : « x86 » (pour IA-32 et ses dérivés) et « amd64 » (pour AMD64 et ses dérivés). La machine par défaut pour l'architecture « x86 » est la machine « x86 ».

Réglage BITS

Le réglage BITS de l'architecture x86 spécifie à Yasm le mode processeur dans lequel le code généré est censé s'exécuter. Les processeurs x86 peuvent fonctionner dans trois modes d'exécution majeurs différents : 16 bits, 32 bits et, sur les processeurs prenant en charge AMD64, 64 bits. Comme l'ensemble d'instructions x86 contient des parties dont la fonction dépend du mode d'exécution (telles que les préfixes de dépassement de taille d'opérande et de taille d'adresse), Yasm ne peut pas assembler correctement les instructions x86 à moins que l'utilisateur ne lui indique dans quel mode processeur le code s'exécutera.

Le réglage BITS peut être modifié de diverses manières. Lors de l'utilisation de l'analyseur compatible NASM, le réglage BITS peut être modifié directement via l'utilisation de la directive d'assembleur BITS xx. Le réglage BITS par défaut est déterminé par le format d'objet utilisé.

Extensions BITS 64

L'architecture AMD64 est une nouvelle architecture 64 bits développée par AMD, basée sur l'architecture x86 32 bits. Elle étend l'architecture x86 d'origine en doublant le nombre de registres à usage général et SIMD, en étendant les opérations arithmétiques et l'espace d'adressage à 64 bits, ainsi que d'autres fonctionnalités.

Récemment, Intel a introduit une version essentiellement identique d'AMD64 appelée EM64T.

Lorsqu'un processeur prenant en charge AMD64 s'exécute en mode 64 bits, un certain nombre d'extensions supplémentaires sont disponibles, notamment des registres supplémentaires à usage général, des registres SSE2 supplémentaires et l'adressage relatif RIP.

Yasm étend la syntaxe de base NASM pour prendre en charge AMD64 comme suit. Pour activer l'assemblage d'instructions pour le mode 64 bits des processeurs AMD64, utilisez la directive BITS 64. Comme avec la directive BITS de NASM, cela ne modifie pas le format du fichier objet de sortie en 64 bits ; cela modifie uniquement le mode de l'assembleur pour supposer que les instructions assemblées seront exécutées en mode 64 bits. Pour spécifier un fichier objet AMD64, utilisez -m amd64 sur la ligne de commande Yasm, ou ciblez explicitement un format d'objet 64 bits tel que -f win64 ou -f elf64. -f elfx32 peut être utilisé pour sélectionner le format d'objet ELF 32 bits pour les processeurs AMD64.

Changements de Registres

Les registres supplémentaires à usage général 64 bits sont nommés r8-r15. Il existe également des sous-registres de 8 bits (rXb), 16 bits (rXw) et 32 bits (rXd) qui correspondent aux 8, 16 ou 32 bits les moins significatifs du registre 64 bits. Les 8 registres à usage général d'origine ont également été étendus à 64 bits : eax, edx, ecx, ebx, esi, edi, esp et ebp ont de nouvelles versions 64 bits appelées rax, rdx, rcx, rbx, rsi, rdi, rsp et rbp respectivement. Les anciens registres 32 bits correspondent aux bits de poids faible des nouveaux registres 64 bits.

De nouveaux registres 8 bits sont également disponibles qui correspondent aux 8 bits de poids faible de rsi, rdi, rsp et rbp. Ceux-ci sont appelés sil, dil, spl et bpl respectivement. Malheureusement, en raison de la façon dont les instructions sont encodées, ces nouveaux registres 8 bits sont encodés de la même manière que les anciens registres 8 bits ah, dh, ch et bh. Le processeur indique lequel est utilisé par la présence du nouveau préfixe REX qui est utilisé pour spécifier les autres registres étendus. Cela signifie qu'il est illégal de mélanger l'utilisation de ah, dh, ch et bh avec une instruction qui nécessite le préfixe REX pour d'autres raisons. Par exemple :

add ah, [r10]

(Syntaxe NASM) n'est pas une instruction légale car l'utilisation de r10 nécessite un préfixe REX, rendant impossible l'utilisation de ah.

En mode 64 bits, 8 registres SSE2 supplémentaires sont également disponibles. Ceux-ci sont nommés xmm8-xmm15.

Instructions 64 bits

Par défaut, la plupart des opérations en mode 64 bits restent à 32 bits ; les opérations 64 bits nécessitent généralement un préfixe REX (un bit du préfixe REX détermine si une opération est 64 bits ou 32 bits). Ainsi, la quasi-totalité des instructions 32 bits ont une version 64 bits, et les versions 64 bits des instructions peuvent utiliser des registres étendus « gratuitement » (car le préfixe REX est déjà présent). Exemples en syntaxe NASM :

mov eax, 1  ; instruction 32 bits
mov rcx, 1  ; instruction 64 bits

Les instructions qui modifient la pile (push, pop, call, ret, enter et leave) sont implicitement 64 bits. Leurs homologues 32 bits ne sont pas disponibles, mais leurs homologues 16 bits le sont. Exemples en syntaxe NASM :

push eax  ; instruction illégale
push rbx  ; instruction de 1 octet
push r11  ; instruction de 2 octets avec préfixe REX

Extension par zéro implicite

Les résultats des opérations 32 bits sont implicitement étendus par zéro vers les 32 bits supérieurs du registre 64 bits correspondant. Les opérations 16 et 8 bits, en revanche, n'affectent pas les bits supérieurs du registre (tout comme en mode 32 bits et 16 bits). Cela peut être utilisé pour générer un code plus court dans certains cas. Exemples en syntaxe NASM :

mov ecx, 1  ; 1 octet plus court que mov rcx, 1
and edx, 3  ; équivalent à and rdx, 3

Valeurs Immédiates

Pour la plupart des instructions en mode 64 bits, les valeurs immédiates restent à 32 bits ; leur valeur est étendue par signe vers les 32 bits supérieurs du registre cible avant d'être utilisée. L'exception est l'instruction mov, qui peut prendre une valeur immédiate 64 bits lorsque la destination est un registre 64 bits. Exemples en syntaxe NASM :

add rax, 1           ; optimisé en 8 bits avec signe
add rax, dword 1     ; forcer la taille à 32 bits
add rax, 0xffffffff  ; 32 bits étendus par signe
add rax, -1          ; identique à ci-dessus
add rax, 0xffffffffffffffff ; tronqué à 32 bits (avertissement)
mov eax, 1           ; 5 octets
mov rax, 1           ; 5 octets (optimisé en 32 bits avec signe)
mov rax, qword 1     ; 10 octets (forcé 64 bits)
mov rbx, 0x1234567890abcdef ; 10 octets
mov rcx, 0xffffffff  ; 10 octets (ne rentre pas dans 32 bits avec signe)
mov ecx, -1          ; 5 octets, équivalent à ci-dessus
mov rcx, sym         ; 5 octets, taille 32 bits par défaut pour les symboles
mov rcx, qword sym   ; 10 octets, remplacer la taille par défaut

La gestion de mov reg64, valeur immédiate non dimensionnée est différente entre YASM et NASM 2.x ; YASM suit le comportement ci-dessus, tandis que NASM 2.x fait ce qui suit :

add rax, 0xffffffff  ; valeur immédiate 32 bits étendue par signe
add rax, -1          ; identique à ci-dessus
add rax, 0xffffffffffffffff ; valeur immédiate 32 bits tronquée (avertissement)
add rax, sym         ; valeur immédiate 32 bits étendue par signe

X86 ARCHITECTURE

The x86 architecture provides support for both 32-bit (IA-32) and 64-bit (AMD64) modes. By default, yasm will assemble in 32-bit mode. To assemble in 64-bit mode, use the BITS 64 directive.

In 32-bit mode, immediates are generally 32 bits in size. In 64-bit mode, immediates are generally 64 bits in size. The exception to this is the mov instruction.

Immediates

For the mov instruction, immediates are restricted to 32 bits in size, regardless of whether you are in 32-bit or 64-bit mode. This means that if you are in 64-bit mode, attempting to move a 64-bit immediate into a register will result in the immediate being truncated to 32 bits. The instruction will still be 64 bits in size, however. The exception is when moving into the 64-bit registers rax, rbx, rcx, rdx, rsi, rdi, r8-r15. In this case, the immediate will be sign-extended to 64 bits. The instruction size remains 10 bytes.

mov eax, 1           ; 5 octets (immédiat 32-bit)
mov rax, 1           ; 10 octets (immédiat 64-bit)
mov rbx, 0x1234567890abcdef ; instruction 10 octets
mov rcx, 0xffffffff  ; instruction 10 octets
mov ecx, -1          ; 5 octets, équivalent à ci-dessus
mov ecx, sym         ; 5 octets (immédiat 32-bit)
mov rcx, sym         ; instruction 10 octets
mov rcx, qword sym   ; 10 octets (immédiat 64-bit)

Déplacements

Tout comme les immédiats, les déplacements restent, pour la plupart, de 32 bits et sont étendus en signe avant utilisation. Encore une fois, l'exception est une forme restreinte de l'instruction mov : entre le registre al/ax/eax/rax et une adresse absolue de 64 bits (aucun registre autorisé dans l'adresse effective). En syntaxe NASM, l'utilisation de la forme absolue 64 bits nécessite [qword]. Exemples en syntaxe NASM :

mov eax, [1]    ; 32 bits, avec extension de signe
mov al, [rax-1] ; 32 bits, avec extension de signe
mov al, [qword 0x1122334455667788] ; Absolu 64 bits
mov al, [0x1122334455667788] ; Tronqué à 32 bits (avertissement)

Adresses relatives RIP

En mode 64 bits, une nouvelle forme d'adressage effectif est disponible pour faciliter l'écriture de code indépendant de la position. Toute référence mémoire peut être rendue relative à RIP (RIP est le registre pointeur d'instruction, qui contient l'adresse de l'emplacement immédiatement suivant l'instruction actuelle).

En syntaxe NASM, il y a deux façons de spécifier l'adressage relatif à RIP :

mov dword [rip+10], 1

stocke la valeur 1 dix octets après la fin de l'instruction. 10 peut également être une constante symbolique, et sera traité de la même manière. D'un autre côté,

mov dword [sym wrt rip], 1

stocke la valeur 1 à l'adresse du symbole symb. Ceci est clairement différent du comportement de :

mov dword [symb+rip], 1

qui prend l'adresse de la fin de l'instruction, y ajoute l'adresse de symb, puis y stocke la valeur 1. Si symb est une variable, cela ne stockera *pas* la valeur 1 dans la variable symb !

Yasm prend également en charge la syntaxe suivante pour l'adressage relatif à RIP :

mov [rel sym], rax  ; Relatif à RIP
mov [abs sym], rax  ; Pas relatif à RIP

Le comportement de :

mov [sym], rax

Dépend d'un mode défini par la directive DEFAULT, comme suit. Le mode par défaut est toujours "abs", et en mode "rel", l'utilisation de registres, un dépassement de segment fs ou gs, ou un override explicite "abs" entraînera une adresse effective non relative à RIP.

default rel
mov [sym], rbx      ; Relatif à RIP
mov [abs sym], rbx  ; Pas relatif à RIP (override explicite)
mov [rbx+1], rbx    ; Pas relatif à RIP (utilisation de registre)
mov [fs:sym], rbx   ; Pas relatif à RIP (utilisation de fs ou gs)
mov [ds:sym], rbx   ; Relatif à RIP (segment, mais pas fs ou gs)
mov [rel sym], rbx  ; Relatif à RIP (override redondant)
default abs
mov [sym], rbx      ; Pas relatif à RIP
mov [abs sym], rbx  ; Pas relatif à RIP
mov [rbx+1], rbx    ; Pas relatif à RIP
mov [fs:sym], rbx   ; Pas relatif à RIP
mov [ds:sym], rbx   ; Pas relatif à RIP
mov [rel sym], rbx  ; Relatif à RIP (override explicite)

Références mémoire

Généralement, la taille d'une référence mémoire peut être déduite des registres que vous utilisez pour le déplacement - par exemple, "mov [rax],ecx" est un déplacement de 32 bits, car ecx est de 32 bits. YASM donne actuellement l'erreur non évidente "combinaison invalide d'opcode et d'opérandes" s'il ne peut pas déterminer la quantité de mémoire que vous déplacez. La solution dans ce cas est d'ajouter un spécificateur de taille mémoire : qword, dword, word, ou byte.

Voici un déplacement mémoire de 64 bits, qui définit 8 octets à partir de rax :

mov qword [rax], 1

Voici un déplacement mémoire de 32 bits, qui définit 4 octets :

mov dword [rax], 1

Voici un déplacement mémoire de 16 bits, qui définit 2 octets :

mov word [rax], 1

Voici un déplacement mémoire de 8 bits, qui définit 1 octet :

mov byte [rax], 1

LC3B ARCHITECTURE

L'architecture "lc3b" prend en charge l'ISA LC-3b telle qu'utilisée dans le cours ECE 312 (maintenant ECE 411) de l'Université de l'Illinois, Urbana-Champaign, ainsi que dans d'autres cours universitaires. Voir http://courses.ece.uiuc.edu/ece411/ pour plus de détails et des exemples de code. L'architecture "lc3b" ne comprend qu'une seule machine : "lc3b".

VOIR AUSSI

yasm(1)

BOGUES

Lors de l'utilisation de l'architecture "x86", il est trop facile de générer du code AMD64 (en utilisant la directive BITS 64) et de générer un fichier objet 32 bits (en omettant de spécifier -m amd64 sur la ligne de commande ou en sélectionnant un format d'objet 64 bits). De même, spécifier -m amd64 ne définit pas par défaut BITS à 64. Un moyen simple d'éviter cela est de spécifier directement un format d'objet 64 bits tel que -f elf64.
