yodl(1) Langage de Document Personnalisé yodl(1)

NOM

yodl - convertisseur principal de Yodl

SYNTAXE

yodl [OPTION]... [FICHIER]...

DESCRIPTION

Yodl est un ensemble d'outils qui implémente un langage de pré-traitement de documents et des outils pour le traiter. L'idée de Yodl est que vous écrivez un document dans un pré-langage, puis utilisez les outils (par exemple, yodl2html(1)) pour le convertir vers un langage de document final. Les convertisseurs actuels sont pour HTML, man, LaTeX, texte et un convertisseur XML expérimental. Les principaux types de documents sont "article", "report", "book", "manpage" et "letter". Le langage de document Yodl est conçu pour être facile à utiliser et extensible.

OPTIONS

o
`-D, --define=NOM[=VALEUR]’: Définit nom comme un symbole. Cette option agit comme `DEFINESYMBOL(NOM)()’. Si `=VALEUR’ est ajouté, `NOM’ est initialisé à `VALEUR’ (identiquement à `DEFINESYMBOL(NOM)(VALEUR)’).
o
`-d, --definemacro=NOM=EXPANSION’: Définit `NOM’ comme une macro s'étendant en `EXPANSION’
o
`-h, --help’: Les informations d'utilisation sont écrites dans le flux de sortie d'erreur standard, décrivant toutes les options de Yodl.
o
`-i, --index[=fichier]’: `fichier’ est le nom du fichier d'index. Par défaut, `.idx` est utilisé. Pas de défaut lorsque la sortie est envoyée sur stdout. Le fichier d'index est traité par le post-processeur de Yodl, `yodlpost`.
o
`-I, --include=REP’: Définit le répertoire d'inclusion système où YODL recherche ses fichiers d'entrée. Par exemple, une instruction pour inclure un fichier donné, comme : 
INCLUDEFILE(latex)
Yodl recherche alors le fichier `latex’ dans le répertoire courant, et en cas d'échec, dans le répertoire d'inclusion système. Le répertoire d'inclusion système est généralement l'endroit où le mainteneur d'un système stocke les fichiers de macros pour Yodl. Ce processus de recherche s'applique aux fichiers inclus dans un document, mais aussi aux noms de fichiers sur la ligne de commande lors de l'invocation du programme YODL.
Le nom du fichier inclus (`latex’ dans l'exemple ci-dessus) est le nom seul, YODL fournit une extension par défaut (`.yo’), si nécessaire.
L'option `-I’ remplace le nom système intégré de Yodl pour le répertoire d'inclusion système. Le nom intégré est défini lors de la compilation de Yodl, et est, par exemple, `/usr/share/yodl’. De plus, la définition peut contenir $HOME, qui est remplacé par le répertoire personnel de l'utilisateur si la variable d'environnement `home’ ou `HOME’ est définie. Elle peut également contenir $STD_INCLUDE, qui est remplacé par le chemin d'inclusion standard défini à la compilation. Le chemin d'inclusion standard peut être remplacé par soit (dans cet ordre) le commutateur de ligne de commande `-I’ soit la variable d'environnement `YODL_INCLUDE_PATH’. Par défaut, le répertoire courant est ajouté au chemin d'inclusion standard. Cependant, lorsque `-I’ ou `YODL_INCLUDE_PATH’ est utilisé, le répertoire courant doit être mentionné explicitement. Les répertoires individuels n'ont pas besoin d'être terminés par un caractère /. Dans les archives `.deb’ distribuées, le répertoire standard est défini comme `/usr/share/yodl’ (précédé du répertoire de travail courant).
o
`-k, --keep-ws’: Depuis la version 2.00 de YODL, les espaces au début et à la fin des lignes sont ignorés, même sans '\' final, lorsque le "niveau d'espaces blancs" est non nul. Les versions antérieures conservaient ces espaces. Le comportement hérité de la gestion des espaces blancs en fin de ligne peut être obtenu en utilisant l'indicateur `-k’. Notez que les espaces blancs sont toujours conservés lors de l'utilisation de la copie verbatim, et lorsque le niveau d'espaces blancs est à zéro.
o
`-m, --messages=ENSEMBLE’: Définit le soi-disant "niveau de messages" à une combinaison de l'ENSEMBLE `acdeinw’. Les lettres de cet ensemble ont les significations suivantes :
o
`a’: alerte. Lorsqu'une erreur d'alerte se produit, Yodl se termine. Ici, Yodl demande quelque chose au système (comme un `get_cwd()`), mais le système échoue.
o
`c’: critique. Lorsqu'une erreur critique se produit, Yodl se termine. Le message lui-même peut être supprimé, mais la sortie ne le peut pas. Une condition critique est, par exemple, l'omission d'une parenthèse ouvrante à un endroit où un argument entre parenthèses devrait apparaître, ou un fichier inexistant dans une spécification `INCLUDEFILE` (car ce fichier devrait être analysé). Un fichier inexistant avec une spécification `NOEXPANDINCLUDE` est une erreur simple (non critique).
o
`d’: débogage. Probablement trop d'informations, comme des informations sur chaque caractère lu par Yodl.
o
`e’: erreur. Une erreur (comme des symboles définis en double). Une fois qu'une erreur a été rencontrée, le reste de l'entrée est toujours analysé (jusqu'à un nombre maximum d'erreurs), mais aucune sortie n'est générée.
o
`i’: information. Pas aussi détaillé que "débogage", mais toujours beaucoup d'informations, comme des informations sur les changements de média.
o
`n’: notification. Informations sur, par exemple, les appels aux fonctions intégrées.
o
`w’: avertissement. Quelque chose que vous devriez savoir, mais qui n'affecte probablement pas le bon fonctionnement de Yodl. La gestion d'un message d' *urgence* n'est pas configurable. Ces messages ne peuvent pas être supprimés, mais ne devraient pas se produire, car ils indiquent une erreur interne. Il serait apprécié de recevoir des informations sur ces messages s'ils se produisent jamais.
o
`-n, --max-nested-files=NR’: Cette option fait avorter Yodl lorsque le nombre de fichiers d'entrée imbriqués dépasse `NR`, qui est de 20 par défaut. Dépasser ce nombre signifie généralement une définition circulaire quelque part dans le document. C'est le cas lorsque, un fichier `a.yo` inclut `b.yo`, tandis que `b.yo` inclut `a.yo`, etc. Cela n'empêche pas les remplacements récursifs de macros ou subst. Pour cela, l'option `-r` (`--max-replacements`) est disponible.
o
`-o, --output=FICHIER’: Cette option fait que Yodl écrit sa sortie dans `FICHIER`. Par défaut, la sortie va vers le flux de sortie standard. Par exemple, vous pouvez utiliser YODL pour lire un fichier `input` et écrire dans `output` avec les deux commandes suivantes : 
        yodl input > output
        yodl -ooutput input
La différence est que dans le dernier cas, un fichier d'index est généré, mais pas dans le premier cas. Notez qu'écrire un fichier d'index peut être forcé lorsque l'option `--index` est spécifiée.
o
`-p, --preload=CMD’: Cette option "pré-charge" la chaîne `cmd`. Elle agit comme si `cmd` était la première commande dans le premier fichier d'entrée traité par YODL.
Plusieurs options `--preload=CMD` peuvent être présentes sur la ligne de commande. Chacune des commandes est alors traitée dans l'ordre, avant la lecture de tout fichier.
o
`-r, --max-replacements=NR’: Cette option fait avorter Yodl lorsque le nombre d'appels de macros ou de remplacements subst dépasse `NR * 10 000`. Par défaut, `NR` est égal à 1. Définir `--max-replacements=0` implique qu'aucune vérification de remplacement de macro ou de subst n'est effectuée.
o
`-t, --trace’: Cette option active le traçage : lors de l'analyse, Yodl écrit sa sortie dans le flux d'erreur standard. Comme pour l'option `-k`, cette option est définie uniquement à des fins de débogage.
o
`-V, --version’. Cette option affiche la version actuelle de YODL.
o
`-v, --verbose’: Cette option augmente le "niveau de verbosité" de Yodl et peut être répétée. Par défaut, yodl affiche les alertes, les messages critiques,

yodl(1) - YODL Manual

NAME

yodl - Convert document to another format.

SYNOPSIS

yodl [-b] [-c] [-d] [-e] [-f] [-g] [-h] [-i] [-I] [-l] [-n] [-o] [-p] [-q] [-r] [-s] [-t] [-u] [-v] [-w] [-W] [-V] [--help] [--version] [inputfile...] [outputfile]

DESCRIPTION

The yodl program is a front-end to the YODL compiler. It uses converters to convert the input document into the desired output format.

The default behaviour is to convert the input file(s) into a single output file in plain text format. If only one input file is given, then the output file is named after the input file, otherwise the output file is named `stdout’. If no output file is given then the output is directed to stdout.

OPTIONS

-b, --batch
Run in batch mode. This means that no questions will be asked, and that error messages are only printed to stderr. This option is useful for scripts.
-c, --catalog
Generate a catalog file. This catalog file contains a list of all input files used to generate the document. It is named after the output file, but with extension `.cat’.
-d, --debug
Turn on debugging messages. This option can be given up to 4 times. With each occurrence, the messages become more verbose. See also the `VERBOSITY’ built-in.
-e, --errors
This option suppresses the messages that are generated by the converters. Only serious errors that prevent the generation of the output file will be reported. See also the `VERBOSITY’ built-in.
-f, --force
This option causes yodl to overwrite existing output files. Without this option, yodl will refuse to overwrite any file.
-g, --graphic
Generate a graphic representation of the document. This representation is stored into a file named after the output file, but with extension `.ps’.
-h, --help
Show a list of options.
-i, --info
This option makes yodl print some information messages during the generation of the output file. See also the `VERBOSITY’ built-in.
-I, --include
Add the directory specified by the following argument to the list of directories that are searched for input files.
-l, --lint
This option forces Yodl to run the lint program on the generated output file. Note that this only works for some converters, e.g. for `tex’.
-n, --notice
This option makes yodl print notice messages during the generation of the output file. See also the `VERBOSITY’ built-in.
-o, --output
Specify the output file. If this option is not given, then the output is directed to stdout.
-p, --postprocessor
Specify a postprocessor to be used to process the generated output file. This is useful to e.g. automatically run `tex’ on the generated `.tex’ file.
-q, --quiet
Suppress all messages. See also the `VERBOSITY’ built-in.
-r, --remove
Remove the intermediate files that are generated during the conversion. This is the default behaviour.
-s, --silent
Suppress warning and error messages. See also the `VERBOSITY’ built-in.
-t, --test
Test the generated output. This option implies `-f’ and `-r’. It is useful to test a document without polluting the directory with intermediate files.
-u, --update
Update the output file only if the input file is newer. This option can also be used to update the catalog file.
-v, --verbose
Increase the verbosity of the messages. This option can be given up to 4 times. The default verbosity is `notice’. Each `--verbose’ option adds a next message level. In order, warning, notice, info and debug messages are added to this set. It is also possible to suppress messages. The `VERBOSITY’ builtin can be used for that.
-W, --warranty
This option shows a warranty disclaimer and a copyright notice.
-w, --warn
The presence of this option caused Yodl to warn when, e.g., symbols are redefined.

FILES

The yodl program requires no files, but `normal’ usage of the Yodl package requires macro files, by default installed in `tmp/wip/macros’. The files in this directory are included by the converters yodl2txt(1) etc..
