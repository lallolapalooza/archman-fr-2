NOM

yt-dlp - Téléchargeur audio/vidéo riche en fonctionnalités en ligne de commande

SYNOPSIS

yt-dlp [OPTIONS] URL [URL...]

DESCRIPTION

yt-dlp est un téléchargeur audio/vidéo riche en fonctionnalités en ligne de commande, prenant en charge des milliers de sites. Le projet est un fork de youtube-dl (https://github.com/ytdl-org/youtube-dl) basé sur le youtube-dlc désormais inactif (https://github.com/blackjack4494/yt-dlc).

OPTIONS

Options Générales :

-h, --help
Affiche ce texte d'aide et quitte
--version
Affiche la version du programme et quitte
-U, --update
Met à jour ce programme vers la dernière version
--no-update
Ne pas vérifier les mises à jour (par défaut)
--update-to [CHANNEL]@[TAG]
Mise à niveau/rétrogradation vers une version spécifique. CHANNEL peut également être un dépôt. CHANNEL et TAG valent par défaut "stable" et "latest" s'ils sont omis ; voir "UPDATE" pour plus de détails. Canaux pris en charge : stable, nightly, master
-i, --ignore-errors
Ignore les erreurs de téléchargement et de post-traitement. Le téléchargement sera considéré comme réussi même si le post-traitement échoue
--no-abort-on-error
Continue avec la vidéo suivante en cas d'erreurs de téléchargement ; par exemple, pour ignorer les vidéos indisponibles dans une playlist (par défaut)
--abort-on-error
Arrête le téléchargement des vidéos ultérieures en cas d'erreur (Alias : --no-ignore-errors)
--list-extractors
Liste tous les extracteurs pris en charge et quitte
--extractor-descriptions
Affiche les descriptions de tous les extracteurs pris en charge et quitte
--use-extractors NOMS
Noms des extracteurs à utiliser, séparés par des virgules. Vous pouvez également utiliser des expressions régulières, "all", "default" et "end" (correspondance de l'URL finale) ; par exemple, --ies "holodex.*,end,youtube". Préfixez le nom par un "-" pour l'exclure, par exemple, --ies default,-generic. Utilisez --list-extractors pour une liste de noms d'extracteurs. (Alias : --ies)
--default-search PREFIX
Utilise ce préfixe pour les URL non qualifiées. Par exemple, "gvsearch2:python" télécharge deux vidéos depuis Google Vidéos pour le terme de recherche "python". Utilisez la valeur "auto" pour laisser yt-dlp deviner ("auto_warning" pour émettre un avertissement lors de la devinette). "error" génère simplement une erreur. La valeur par défaut "fixup_error" répare les URL cassées, mais génère une erreur si ce n'est pas possible au lieu de rechercher.
--ignore-config
Ne charge aucun autre fichier de configuration à l'exception de ceux fournis à --config-locations. Pour la compatibilité descendante, si cette option est trouvée dans le fichier de configuration système, la configuration utilisateur n'est pas chargée. (Alias : --no-config)
--no-config-locations
Ne charge aucun fichier de configuration personnalisé (par défaut). Lorsqu'elle est utilisée dans un fichier de configuration, ignore tous les --config-locations définis précédemment dans le fichier actuel.
--config-locations CHEMIN
Emplacement du fichier de configuration principal ; soit le chemin d'accès au fichier de configuration, soit son répertoire parent ("-" pour stdin). Peut être utilisé plusieurs fois et à l'intérieur d'autres fichiers de configuration.
--plugin-dirs REP
Chemin d'accès à un répertoire supplémentaire pour rechercher des plugins. Cette option peut être utilisée plusieurs fois pour ajouter plusieurs répertoires. Utilisez "default" pour rechercher les répertoires de plugins par défaut (par défaut).
--no-plugin-dirs
Efface les répertoires de plugins à rechercher, y compris les répertoires par défaut et ceux fournis par les --plugin-dirs précédents.
--js-runtimes RUNTIME[:CHEMIN]
Runtime JavaScript supplémentaire à activer, avec un emplacement optionnel pour le runtime (soit le chemin d'accès au binaire, soit son répertoire contenant). Cette option peut être utilisée plusieurs fois pour activer plusieurs runtimes. Les runtimes pris en charge sont (par ordre de priorité, du plus élevé au plus bas) : deno, node, quickjs, bun. Seul "deno" est activé par défaut. Le runtime de priorité la plus élevée qui est à la fois activé et disponible sera utilisé. Afin d'utiliser un runtime de priorité inférieure lorsque "deno" est disponible, --no-js-runtimes doit être passé avant d'activer d'autres runtimes.
--no-js-runtimes
Efface les runtimes JavaScript à activer, y compris les valeurs par défaut et ceux fournis par les --js-runtimes précédents.
--remote-components COMPOSANT
Composants distants que yt-dlp est autorisé à récupérer lorsqu'ils sont requis. Cette option n'est actuellement pas nécessaire si vous utilisez un exécutable officiel ou si vous avez la version requise du package yt-dlp-ejs installée. Vous pouvez utiliser cette option plusieurs fois pour autoriser plusieurs composants. Valeurs prises en charge : ejs:npm (composants JavaScript externes depuis npm), ejs:github (composants JavaScript externes depuis yt-dlp-ejs GitHub). Par défaut, aucun composant distant n'est autorisé.
--no-remote-components
Interdit la récupération de tous les composants distants, y compris ceux précédemment autorisés par --remote-components ou les valeurs par défaut.
--flat-playlist
N'extrait pas les entrées de résultats d'une URL de playlist ; certaines métadonnées d'entrée peuvent être manquantes et le téléchargement peut être contourné.
--no-flat-playlist
Extrait entièrement les vidéos d'une playlist (par défaut)
--live-from-start
Télécharge les flux en direct depuis le début. Actuellement expérimental et pris en charge uniquement pour YouTube et Twitch.
--no-live-from-start
Télécharge les flux en direct depuis l'heure actuelle (par défaut)
--wait-for-video MIN[-MAX]
Attend que les flux programmés deviennent disponibles. Fournit le nombre minimum de secondes (ou une plage) à attendre entre les tentatives.
--no-wait-for-video
Ne pas attendre les flux programmés (par défaut)
--mark-watched
Marque les vidéos comme vues (même avec --simulate)
--no-mark-watched
Ne pas marquer les vidéos comme vues (par défaut)
--color [STREAM:]POLITIQUE
Indique si des codes couleur doivent être émis dans la sortie, éventuellement préfixés par le FLUX (stdout ou stderr) pour appliquer le réglage. Peut être l'une des valeurs suivantes : "always", "auto" (par défaut), "never", ou "no_color" (utiliser des séquences de terminal sans couleur). Utilisez "auto-tty" ou "no_color-tty" pour décider en fonction de la prise en charge du terminal uniquement. Peut être utilisé plusieurs fois.
--compat-options OPTS
Options qui peuvent aider à maintenir la compatibilité avec les configurations de youtube-dl ou youtube-dlc en annulant certaines des modifications apportées dans yt-dlp. Voir "Différences dans le comportement par défaut" pour plus de détails.

-6, --force-ipv6
Effectue toutes les connexions via IPv6.
--enable-file-urls
Active les URL file://. Ceci est désactivé par défaut pour des raisons de sécurité.

Géo-restriction :

--geo-verification-proxy URL
Utilise ce proxy pour vérifier l'adresse IP pour certains sites géo-restreints. Le proxy par défaut spécifié par --proxy (ou aucun, si l'option n'est pas présente) est utilisé pour le téléchargement réel.
--xff VALEUR
Comment falsifier l'en-tête HTTP X-Forwarded-For pour tenter de contourner la restriction géographique. L'une des valeurs suivantes : "default" (seulement lorsqu'il est utile), "never", un bloc IP en notation CIDR, ou un code pays ISO 3166-2 à deux lettres.

Sélection Vidéo :

-I, --playlist-items ITEM_SPEC
Index de liste de lecture séparés par des virgules des éléments à télécharger. Vous pouvez spécifier une plage en utilisant "[DÉBUT]:[FIN][:PAS]". Pour la compatibilité descendante, START-STOP est également pris en charge. Utilisez des indices négatifs pour compter à partir de la fin et un PAS négatif pour télécharger en ordre inverse. Par exemple, "-I 1:3,7,-5::2" utilisé sur une liste de lecture de taille 15 téléchargera les éléments aux indices 1,2,3,7,11,13,15.
--min-filesize TAILLE
Arrête le téléchargement si la taille du fichier est inférieure à TAILLE, par exemple 50k ou 44.6M.
--max-filesize TAILLE
Arrête le téléchargement si la taille du fichier est supérieure à TAILLE, par exemple 50k ou 44.6M.
--date DATE
Télécharge uniquement les vidéos mises en ligne à cette date. La date peut être au format "AAAAJJMM" ou au format [now|today|yesterday][-N[day|week|month|year]]. Par exemple, "--date today-2weeks" télécharge uniquement les vidéos mises en ligne le même jour il y a deux semaines.
--datebefore DATE
Télécharge uniquement les vidéos mises en ligne à cette date ou avant. Les formats de date acceptés sont les mêmes que pour --date.
--dateafter DATE
Télécharge uniquement les vidéos mises en ligne à cette date ou après. Les formats de date acceptés sont les mêmes que pour --date.
--match-filters FILTRE
Filtre vidéo générique. N'importe quel champ de "TEMPLATE DE SORTIE" peut être comparé à un nombre ou une chaîne à l'aide des opérateurs définis dans "Formats de Filtrage". Vous pouvez également simplement spécifier un champ à faire correspondre si le champ est présent, utilisez "!champ" pour vérifier si le champ n'est pas présent, et "&" pour vérifier plusieurs conditions. Utilisez une chaîne vide "" pour échapper "&" ou les guillemets si nécessaire. Si utilisé plusieurs fois, le filtre correspond si au moins une des conditions est remplie. Par exemple, --match-filters !is_live --match-filters "like_count>?100 & description~='(?i)& dogs'" correspond uniquement aux vidéos qui ne sont pas en direct OU celles qui ont un nombre de "like" supérieur à 100 (ou le champ "like" n'est pas disponible) et ont également une description qui contient la phrase "chats & chiens" (insensible à la casse). Utilisez "--match-filters -" pour demander interactivement si le téléchargement de chaque vidéo doit avoir lieu.
--no-match-filters
N'utilise aucun --match-filters (par défaut).
--break-match-filters FILTRE
Identique à "--match-filters" mais arrête le processus de téléchargement lorsqu'une vidéo est rejetée.
--no-break-match-filters
N'utilise aucun --break-match-filters (par défaut).
--no-playlist
Télécharge uniquement la vidéo, si l'URL fait référence à une vidéo et une liste de lecture.
--yes-playlist
Télécharge la liste de lecture, si l'URL fait référence à une vidéo et une liste de lecture.
--age-limit ANNÉES
Télécharge uniquement les vidéos adaptées à l'âge donné.
--download-archive FICHIER
Télécharge uniquement les vidéos non listées dans le fichier archive. Enregistre les identifiants de toutes les vidéos téléchargées dans ce fichier.
--no-download-archive
N'utilise pas de fichier archive (par défaut).
--max-downloads NOMBRE
Arrête après le téléchargement de NOMBRE fichiers.
--break-on-existing
Arrête le processus de téléchargement lors de la rencontre d'un fichier qui se trouve dans l'archive fournie avec l'option --download-archive.
--no-break-on-existing
N'arrête pas le processus de téléchargement lors de la rencontre d'un fichier qui se trouve dans l'archive (par défaut).
--break-per-input
Modifie --max-downloads, --break-on-existing, --break-match-filters, et autonumber pour réinitialiser par URL d'entrée.
--no-break-per-input
Les options --break-on-existing et similaires terminent toute la file d'attente de téléchargement.
--skip-playlist-after-errors N
Nombre d'échecs autorisés avant que le reste de la liste de lecture ne soit ignoré.

Options de Téléchargement :

-N, --concurrent-fragments N
Nombre de fragments d'une vidéo dash/hlsnative qui doivent être téléchargés simultanément (par défaut est 1).
-r, --limit-rate TAUX
Taux de téléchargement maximum en octets par seconde, par exemple 50K ou 4.2M.
--throttled-rate TAUX
Taux de téléchargement minimum en octets par seconde en dessous duquel une limitation est supposée et les données vidéo sont ré-extraites, par exemple 100K.
-R, --retries RETRIES
Nombre de tentatives (par défaut est 10), ou "infinite".
--file-access-retries RETRIES
Nombre de tentatives en cas d'erreur d'accès au fichier (par défaut est 3), ou "infinite".
--fragment-retries RETRIES
Nombre de tentatives pour un fragment (par défaut est 10), ou "infinite" (DASH, hlsnative et ISM).
--retry-sleep [TYPE:]EXPR
Temps d'attente entre les tentatives en secondes (facultatif) préfixé par le type de tentative (http (par défaut), fragment, file_access, extractor) pour appliquer le temps d'attente. EXPR peut être un nombre, linear=START[:END[:STEP=1]] ou exp=START[:END[:BASE=2]]. Cette option peut être utilisée plusieurs fois pour définir le temps d'attente pour les différents types de tentatives, par exemple --retry-sleep linear=1::2 --retry-sleep fragment:exp=1:20.
--skip-unavailable-fragments
Ignore les fragments indisponibles pour les téléchargements DASH, hlsnative et ISM (par défaut) (Alias : --no-abort-on-unavailable-fragments).
--abort-on-unavailable-fragments
Arrête le téléchargement si un fragment est indisponible (Alias : --no-skip-unavailable-fragments).
--keep-fragments
Conserve les fragments téléchargés sur le disque après la fin du téléchargement.
--no-keep-fragments
Supprime les fragments téléchargés après la fin du téléchargement (par défaut).
--buffer-size TAILLE
Taille du tampon de téléchargement, par exemple 1024 ou 16K (par défaut 1024)
--resize-buffer
La taille du tampon est automatiquement ajustée à partir de la valeur initiale de --buffer-size (par défaut)
--no-resize-buffer
Ne pas ajuster automatiquement la taille du tampon
--http-chunk-size TAILLE
Taille d'un morceau pour le téléchargement HTTP par morceaux, par exemple 10485760 ou 10M (par défaut désactivé). Peut être utile pour contourner la limitation de bande passante imposée par un serveur web (expérimental)
--playlist-random
Télécharger les vidéos de la playlist dans un ordre aléatoire
--lazy-playlist
Traiter les entrées de la playlist au fur et à mesure de leur réception. Cela désactive n_entries, --playlist-random et --playlist-reverse
--no-lazy-playlist
Traiter les vidéos de la playlist uniquement après l'analyse complète de la playlist (par défaut)
--hls-use-mpegts
Utiliser le conteneur mpegts pour les vidéos HLS; permettant à certains lecteurs de lire la vidéo pendant le téléchargement, et réduisant le risque de corruption de fichier si le téléchargement est interrompu. Ceci est activé par défaut pour les flux en direct
--no-hls-use-mpegts
Ne pas utiliser le conteneur mpegts pour les vidéos HLS. C'est le comportement par défaut lorsque le téléchargement n'est pas en direct
--download-sections REGEX
Télécharger uniquement les chapitres qui correspondent à l'expression régulière. Un préfixe "*" dénote une plage horaire au lieu d'un chapitre. Les horodatages négatifs sont calculés à partir de la fin. "*from-url" peut être utilisé pour télécharger entre "start_time" et "end_time" extraits de l'URL. Nécessite ffmpeg. Cette option peut être utilisée plusieurs fois pour télécharger plusieurs sections, par exemple --download-sections "*10:15-inf" --download-sections "intro"
--downloader [PROTO:]NOM
Nom ou chemin du téléchargeur externe à utiliser (facultativement) préfixé par les protocoles (http, ftp, m3u8, dash, rstp, rtmp, mms) pour l'utiliser. Prend actuellement en charge native, aria2c, axel, curl, ffmpeg, httpie, wget. Vous pouvez utiliser cette option plusieurs fois pour définir différents téléchargeurs pour différents protocoles. Par exemple, --downloader aria2c --downloader "dash,m3u8:native" utilisera aria2c pour les téléchargements http/ftp, et le téléchargeur natif pour les téléchargements dash/m3u8 (Alias: --external-downloader)
--downloader-args NOM:ARGUMENTS
Donner ces arguments au téléchargeur externe. Spécifiez le nom du téléchargeur et les arguments séparés par deux points ":". Pour ffmpeg, les arguments peuvent être passés à différentes positions en utilisant la même syntaxe que --postprocessor-args. Vous pouvez utiliser cette option plusieurs fois pour donner différents arguments à différents téléchargeurs (Alias: --external-downloader-args)

Options du système de fichiers :

-a, --batch-file FICHIER
Fichier contenant les URLs à télécharger ("-" pour stdin), une URL par ligne. Les lignes commençant par "#", ";" ou "]" sont considérées comme des commentaires et ignorées
--no-batch-file
Ne pas lire les URLs à partir du fichier batch (par défaut)
-P, --paths [TYPES:]CHEMIN
Les chemins où les fichiers doivent être téléchargés. Spécifiez le type de fichier et le chemin séparés par deux points ":". Tous les TYPES identiques à --output sont pris en charge. De plus, vous pouvez également fournir les chemins "home" (par défaut) et "temp". Tous les fichiers intermédiaires sont d'abord téléchargés dans le chemin temp, puis les fichiers finaux sont déplacés vers le chemin home une fois le téléchargement terminé. Cette option est ignorée si --output est un chemin absolu
-o, --output [TYPES:]MODÈLE
Modèle de nom de fichier de sortie ; voir "MODÈLE DE SORTIE" pour les détails
--output-na-placeholder TEXTE
Placeholder pour les champs indisponibles dans --output (par défaut : "NA")
--restrict-filenames
Restreindre les noms de fichiers aux caractères ASCII uniquement, et éviter les "&" et les espaces dans les noms de fichiers
--no-restrict-filenames
Autoriser les caractères Unicode, les "&" et les espaces dans les noms de fichiers (par défaut)
--windows-filenames
Forcer les noms de fichiers à être compatibles avec Windows
--no-windows-filenames
Nettoyer les noms de fichiers uniquement de manière minimale
--trim-filenames LONGUEUR
Limiter la longueur du nom de fichier (hors extension) au nombre spécifié de caractères
-w, --no-overwrites
Ne pas écraser les fichiers
--force-overwrites
Écraser tous les fichiers vidéo et de métadonnées. Cette option inclut --no-continue
--no-force-overwrites
Ne pas écraser la vidéo, mais écraser les fichiers associés (par défaut)
-c, --continue
Reprendre les fichiers/fragments partiellement téléchargés (par défaut)
--no-continue
Ne pas reprendre les fragments partiellement téléchargés. Si le fichier n'est pas fragmenté, redémarrer le téléchargement du fichier entier
--part
Utiliser des fichiers .part au lieu d'écrire directement dans le fichier de sortie (par défaut)
--no-part
Ne pas utiliser de fichiers .part - écrire directement dans le fichier de sortie
--mtime
Utiliser l'en-tête Last-modified pour définir l'heure de modification du fichier
--no-mtime
Ne pas utiliser l'en-tête Last-modified pour définir l'heure de modification du fichier (par défaut)
--write-description
Écrire la description de la vidéo dans un fichier .description
--no-write-description
Ne pas écrire la description de la vidéo (par défaut)
--write-info-json
Écrire les métadonnées de la vidéo dans un fichier .info.json (cela peut contenir des informations personnelles)
--no-write-info-json
Ne pas écrire les métadonnées de la vidéo (par défaut)
--write-playlist-metafiles
Écrire les métadonnées de la playlist en plus des métadonnées vidéo lors de l'utilisation de --write-info-json, --write-description, etc. (par défaut)
--no-write-playlist-metafiles
Ne pas écrire les métadonnées de la playlist lors de l'utilisation de --write-info-json, --write-description, etc.
--clean-info-json
Supprimer certaines métadonnées internes comme les noms de fichiers de l'infojson (par défaut)
--no-clean-info-json
Écrire tous les champs dans l'infojson
--write-comments
Récupérer les commentaires de la vidéo pour les placer dans l'infojson. Les commentaires sont récupérés même sans cette option si l'extraction est connue pour être rapide (Alias: --get-comments)
--no-write-comments
Ne pas récupérer les commentaires vidéo sauf si l'extraction est connue pour être rapide (Alias: --no-get-comments)
--load-info-json FICHIER
Fichier JSON contenant les informations vidéo (créé avec l'option "--write-info-json")
--cookies FICHIER
Fichier au format Netscape pour lire les cookies et y écrire le cookie jar
--no-cookies
Ne pas lire/écrire les cookies depuis/vers le fichier (par défaut)
--cookies-from-browser NAVIGATEUR[+CLE_SECRET]:PROFIL[::CONTENEUR]
Nom du navigateur à partir duquel charger les cookies. Les navigateurs actuellement pris en charge sont : brave, chrome, chromium, edge, firefox, opera, safari, vivaldi, whale. Facultativement, le KEYRING utilisé pour déchiffrer les cookies Chromium sous Linux, le nom/chemin du PROFIL à partir duquel charger les cookies, et le nom du CONTENEUR (pour Firefox) ("none" pour aucun conteneur) peuvent être indiqués avec leurs séparateurs respectifs. Par défaut, tous les conteneurs du profil accédé le plus récemment sont utilisés. Les keyrings actuellement pris en charge sont : basictext, gnomekeyring, kwallet, kwallet5, kwallet6
--no-cookies-from-browser
Ne pas charger les cookies du navigateur (par défaut)
--cache-dir DIR
Emplacement dans le système de fichiers où yt-dlp peut stocker de manière permanente certaines informations téléchargées (telles que les IDs clients et les signatures). Par défaut ${XDG_CACHE_HOME}/yt-dlp
--no-cache-dir
Désactiver la mise en cache du système de fichiers
--rm-cache-dir
Supprimer tous les fichiers de cache du système de fichiers

CONFIGURATION

Vous pouvez configurer yt-dlp en plaçant toute option de ligne de commande prise en charge dans un fichier de configuration. La configuration est chargée depuis les emplacements suivants :

1.

•
Le fichier donné à --config-locations
2.
Configuration portable : (Recommandé pour les installations portables)

•
Si vous exécutez à partir de la source, yt-dlp.conf dans le répertoire parent de yt_dlp
3.
Configuration du répertoire personnel :
•
yt-dlp.conf dans le chemin du répertoire personnel donné par -P
•
Si -P n'est pas donné, le répertoire courant est recherché
4.

•
${XDG_CONFIG_HOME}/yt-dlp.conf
•

•
${XDG_CONFIG_HOME}/yt-dlp/config.txt

•
${APPDATA}/yt-dlp/config (recommandé sous Windows)
•
${APPDATA}/yt-dlp/config.txt
•
~/yt-dlp.conf
•
~/yt-dlp.conf.txt
•
~/.yt-dlp/config
•
~/.yt-dlp/config.txt Voir aussi : Notes sur les variables d'environnement

Configuration système :
•
/etc/yt-dlp.conf
•
/etc/yt-dlp/config
•
/etc/yt-dlp/config.txt

Par exemple, avec le fichier de configuration suivant, yt-dlp extraira toujours l'audio, copiera le mtime, utilisera un proxy et enregistrera toutes les vidéos sous le répertoire YouTube de votre répertoire personnel :

# Les lignes commençant par # sont des commentaires
# Extraire toujours l'audio
-x
# Copier le mtime
--mtime
# Utiliser ce proxy
--proxy 127.0.0.1:3128
# Enregistrer toutes les vidéos sous le répertoire YouTube de votre répertoire personnel
-o ~/YouTube/%(title)s.%(ext)s

Note : Les options dans un fichier de configuration sont

e le même options aka switches utilisés dans les appels de ligne de commande réguliers ; ainsi il doit y avoir aucun espace après - ou --, par exemple -o ou --proxy mais pas - o ou -- proxy. Ils doivent également être mis entre guillemets lorsque nécessaire, comme dans un shell UNIX.

Vous pouvez utiliser --ignore-config si vous souhaitez désactiver tous les fichiers de configuration pour une exécution particulière de yt-dlp. Si --ignore-config est trouvé dans un fichier de configuration, aucune configuration supplémentaire ne sera chargée. Par exemple, avoir l'option dans le fichier de configuration portable empêche le chargement des configurations de l'utilisateur, du système et du répertoire personnel. De plus, (pour la compatibilité ascendante) si --ignore-config est trouvé dans le fichier de configuration système, la configuration utilisateur n'est pas chargée.

Encodage du fichier de configuration

Les fichiers de configuration sont décodés selon le BOM UTF s'il est présent, et sinon dans l'encodage de la locale système.

Si vous souhaitez que votre fichier soit décodé différemment, ajoutez # coding: ENCODAGE au début du fichier (par exemple, # coding: shift-jis). Il ne doit y avoir aucun caractère avant cela, même des espaces ou un BOM.

Authentification avec netrc

Vous pourriez également vouloir configurer le stockage automatique des identifiants pour les extracteurs qui supportent l'authentification (en fournissant login et mot de passe avec --username et --password) afin de ne pas passer les identifiants en arguments de ligne de commande à chaque exécution de yt-dlp et d'éviter le suivi des mots de passe en texte clair dans l'historique des commandes du shell. Vous pouvez y parvenir en utilisant un fichier .netrc (https://stackoverflow.com/tags/.netrc/info) par extracteur. Pour ce faire, vous devrez créer un fichier .netrc dans --netrc-location et restreindre ses permissions à la lecture/écriture par vous seul :

touch ${HOME}/.netrc
chmod a-rwx,u+rw ${HOME}/.netrc

Après cela, vous pouvez ajouter les identifiants pour un extracteur dans le format suivant, où extracteur est le nom de l'extracteur en minuscules :

machine <extracteur> login <nom_utilisateur> password <mot_de_passe>

Par exemple :

machine youtube login moncompte@gmail.com password mon_mot_de_passe_youtube
machine twitch login monnom_compte_twitch password mon_mot_de_passe_twitch

Pour activer l'authentification avec le fichier .netrc, vous devez passer --netrc à yt-dlp ou le placer dans le fichier de configuration.

L'emplacement par défaut du fichier .netrc est ~ (voir ci-dessous).

En alternative à l'utilisation du fichier .netrc, qui a le désavantage de garder vos mots de passe dans un fichier en texte brut, vous pouvez configurer une commande shell personnalisée pour fournir les identifiants pour un extracteur. Ceci est fait en fournissant le paramètre --netrc-cmd, qui doit produire les identifiants au format netrc et retourner 0 en cas de succès, d'autres valeurs seront traitées comme une erreur. {} dans la commande sera remplacé par le nom de l'extracteur pour permettre la sélection des identifiants du bon extracteur.

Par exemple, pour utiliser un fichier .netrc crypté stocké sous .authinfo.gpg

yt-dlp --netrc-cmd 'gpg --decrypt ~/.authinfo.gpg' 'https://www.youtube.com/watch?v=BaW_jenozKc'

Notes sur les variables d'environnement

•
Les variables d'environnement sont normalement spécifiées comme ${VARIABLE}/$VARIABLE sous UNIX et %VARIABLE% sous Windows ; mais sont toujours affichées comme ${VARIABLE} dans cette documentation
•
yt-dlp permet également d'utiliser des variables de style UNIX sous Windows pour les options de type chemin ; par exemple, --output, --config-locations
•
Si non définies, ${XDG_CONFIG_HOME} prend par défaut la valeur ~/.config et ${XDG_CACHE_HOME} la valeur ~/.cache
•
Sous Windows, ~ pointe vers ${HOME} si présent ; ou, ${USERPROFILE} ou ${HOMEDRIVE}${HOMEPATH} sinon
•
Sous Windows, ${USERPROFILE} pointe généralement vers C:\Users\<nom_utilisateur> et ${APPDATA} vers ${USERPROFILE}\AppData\Roaming

MODÈLE DE SORTIE

L'option -o est utilisée pour indiquer un modèle pour les noms de fichiers de sortie tandis que l'option -P est utilisée pour spécifier le chemin où chaque type de fichier doit être enregistré.

L'utilisation la plus simple de -o est de ne pas définir d'arguments de modèle lors du téléchargement d'un seul fichier, comme dans yt-dlp -o video_drôle.flv "<https://quelque.video>" (coder en dur l'extension de fichier comme cela n'est pas recommandé et pourrait casser certains post-traitements).

Il peut cependant également contenir des séquences spéciales qui seront remplacées lors du téléchargement de chaque vidéo. Les séquences spéciales peuvent être formatées selon les opérations de formatage de chaînes Python (https://docs.python.org/3/library/stdtypes.html#printf-style-string-formatting), par exemple %(NOM)s ou %(NOM)05d. Pour être clair, il s'agit d'un symbole de pourcentage suivi d'un nom entre parenthèses, suivi d'opérations de formatage.

Les noms de champs eux-mêmes (la partie entre parenthèses) peuvent également avoir une mise en forme spéciale :

1.
Parcours d'objet : Les dictionnaires et listes disponibles dans les métadonnées peuvent être parcourus en utilisant un point . comme séparateur ; par exemple, %(tags.0)s, %(subtitles.en.-1.ext)s. Vous pouvez faire du découpage Python avec deux-points : ; par exemple, %(id.3:7)s, %(id.6:2:-1)s, %(formats.:.format_id)s. Les accolades {} peuvent être utilisées pour construire des dictionnaires avec seulement des clés spécifiques ; par exemple, %(formats.:.{format_id,height})#j. Un nom de champ vide %()s fait référence à l'ensemble du dictionnaire d'informations ; par exemple, %(.{id,title})s. Notez que tous les champs disponibles par cette méthode ne sont pas listés ci-dessous. Utilisez -j pour voir ces champs.
2.
Arithmétique : Une arithmétique simple peut être effectuée sur les champs numériques en utilisant +, - et *. Par exemple, %(playlist_index+10)03d, %(n_entries+1-playlist_index)d
3.
Formatage Date/Heure : Les champs date/heure peuvent être formatés selon le formatage strftime (https://docs.python.org/3/library/datetime.html#strftime-and-strptime-format-codes) en le spécifiant séparé du nom du champ par un >. Par exemple, %(duration>%H-%M-%S)s, %(upload_date>%Y-%m-%d)s, %(epoch-3600>%H-%M-%S)s
4.
Alternatifs : Des champs alternatifs peuvent être spécifiés séparés par une virgule ,. Par exemple, %(release_date>%Y,upload_date>%Y|Inconnu)s
5.
Remplacement : Une valeur de remplacement peut être spécifiée en utilisant un séparateur & selon le mini-langage de formatage str.format (https://docs.python.org/3/library/string.html#format-specification-mini-language). Si le champ est vide, cette valeur de remplacement sera utilisée à la place du contenu réel du champ. Ceci est fait après que les champs alternatifs aient été considérés ; ainsi le remplacement est utilisé si l'un quelconque des champs alternatifs n'est pas vide. Par exemple, %(chapters&contient des chapitres|pas de chapitres)s, %(title&TITRE={:>20}|PAS DE TITRE)s
6.
Défaut : Une valeur de remplacement littérale peut être spécifiée pour les cas où le champ est vide en utilisant un séparateur |. Ceci remplace --output-na-placeholder. Par exemple, %(uploader|Inconnu)s
7.
Plus de conversions : En plus des types de format normaux diouxXeEfFgGcrs, yt-dlp supporte en plus la conversion en B = Bytes, j = json (flag # pour l'impression formatée, + pour Unicode), h = échappement HTML, l = une liste séparée par des virgules (flag # pour séparé par des sauts de ligne \n), q = une chaîne quootée pour le terminal (flag # pour diviser une liste en arguments différents), D = ajouter des suffixes en Décimales (par exemple 10M) (flag # pour utiliser 1024 comme facteur), et S = Sanitiser comme nom de fichier (flag # pour restreint)
8.
Normalisation Unicode : Le type de format U peut être utilisé pour la normalisation Unicode NFC (https://docs.python.org/3/library/unicodedata.html#unicodedata.normalize). La forme alternative (#) change la normalisation en NFD et le flag de conversion + peut être utilisé pour la normalisation d'équivalence de compatibilité NFKC/NFKD. Par exemple, %(title)+.100U est NFKC

Pour résumer, la syntaxe générale pour un champ est :

%(nom[.clés][addition][>strf][,alternatif][&remplacement][|défaut])[flags][largeur][.précision][longueur]type

De plus, vous pouvez définir différents modèles de sortie pour les divers fichiers de métadonnées séparément du modèle de sortie général en spécifiant le type de fichier suivi du modèle séparé par deux-points :. Les différents types de fichiers supportés sont subtitle, thumbnail, description, annotation (obsolète), infojson, link, pl_thumbnail, pl_description, pl_infojson, chapter, pl_video. Par exemple -o ""%(title)s.%(ext)s"" -o ""thumbnail:%(title)s\%(title)s.%(ext)s"" placera les miniatures dans un dossier du même nom que la vidéo. Si l'un des modèles est vide, ce type de fichier ne sera pas écrit. Par exemple, --write-thumbnail -o ""thumbnail:"" n'écrira les miniatures que pour les playlists et pas pour les vidéos.

Note : En raison du post-traitement (c'est-à-dire la fusion, etc.), le nom de fichier de sortie réel pourrait différer. Utilisez --print after_move:filepath pour obtenir le nom après que tout le post-traitement soit terminé.

Les modèles de sortie peuvent également contenir des chemins hiérarchiques arbitraires, par exemple -o ""%(playlist)s/%(playlist_index)s - %(title)s.%(ext)s"" qui téléchargera chaque vidéo dans un répertoire correspondant à ce modèle de chemin. Pour utiliser des littéraux de pourcentage dans un modèle de sortie, utilisez %%. Pour envoyer la sortie vers stdout, utilisez -o -.

Le modèle par défaut actuel est %(title)s [%(id)s].%(ext)s.

Dans ces cas, ajoutez le drapeau --restrict-filenames pour obtenir un titre plus court.

youtube-dl vidéo test ''_ä↭𝕐.webm    # Tous types de caractères étranges

SÉLECTION DU FORMAT

Par défaut, yt-dlp essaie de télécharger la meilleure qualité disponible si vous ne fournissez pas d'options. Ceci est généralement équivalent à utiliser -f bestvideo*+bestaudio/best. Cependant, si plusieurs flux audio sont activés (--audio-multistreams), le format par défaut change pour -f bestvideo+bestaudio/best. De même, si ffmpeg n'est pas disponible, ou si vous utilisez yt-dlp pour diffuser vers stdout (-o -), le défaut devient -f best/bestvideo+bestaudio.

Avertissement de dépréciation : Les dernières versions de yt-dlp peuvent diffuser plusieurs formats vers stdout simultanément en utilisant ffmpeg. Ainsi, dans les versions futures, le défaut sera défini sur -f bv*+ba/b similaire aux téléchargements normaux. Si vous souhaitez conserver le réglage -f b/bv+ba, il est recommandé de le spécifier explicitement dans les options de configuration.

La syntaxe générale pour la sélection de format est -f FORMAT (ou --format FORMAT) où FORMAT est une expression de sélecteur, c'est-à-dire une expression décrivant le ou les formats que vous souhaitez télécharger.

Le cas le plus simple est de demander un format spécifique ; par exemple, avec -f 22 vous pouvez télécharger le format ayant le code de format égal à 22. Vous pouvez obtenir la liste des codes de format disponibles pour une vidéo particulière en utilisant --list-formats ou -F. Notez que ces codes de format sont spécifiques à l'extracteur.

Vous pouvez également utiliser une extension de fichier (actuellement 3gp, aac, flv, m4a, mp3, mp4, ogg, wav, webm sont pris en charge) pour télécharger le format de meilleure qualité d'une extension de fichier particulière servi sous forme de fichier unique, par exemple -f webm téléchargera le format de meilleure qualité avec l'extension webm servi sous forme de fichier unique.

Vous pouvez utiliser -f - pour fournir interactivement le sélecteur de format pour chaque vidéo

Vous pouvez également utiliser des noms spéciaux pour sélectionner des formats de cas limites particuliers :

•
all : Sélectionne tous les formats séparément
•
mergeall : Sélectionne et fusionne tous les formats (Doit être utilisé avec --audio-multistreams, --video-multistreams ou les deux)
•
b*, best* : Sélectionne le format de meilleure qualité qui contient soit une vidéo, soit un audio, soit les deux (c'est-à-dire vcodec!=none ou acodec!=none)
•
b, best : Sélectionne le format de meilleure qualité qui contient à la fois une vidéo et un audio. Équivalent à best*[vcodec!=none][acodec!=none]
•
bv, bestvideo : Sélectionne le format de meilleure qualité vidéo seule. Équivalent à best*[acodec=none]
•
bv*, bestvideo* : Sélectionne le format de meilleure qualité qui contient une vidéo. Il peut également contenir de l'audio. Équivalent à best*[vcodec!=none]
•
ba, bestaudio : Sélectionne le format de meilleure qualité audio seul. Équivalent à best*[vcodec=none]
•
ba*, bestaudio* : Sélectionne le format de meilleure qualité qui contient de l'audio. Il peut également contenir une vidéo. Équivalent à best*[acodec!=none] (À ne pas utiliser ! (https://github.com/yt-dlp/yt-dlp/issues/979#issuecomment-919629354))
•
w*, worst* : Sélectionne le format de moindre qualité qui contient une vidéo ou un audio
•
w, worst : Sélectionne le format de moindre qualité qui contient à la fois une vidéo et un audio. Équivalent à worst*[vcodec!=none][acodec!=none]
•
wv, worstvideo : Sélectionne le format vidéo seul de moindre qualité. Équivalent à worst*[acodec=none]
•
wv*, worstvideo* : Sélectionne le format de moindre qualité qui contient une vidéo. Il peut également contenir de l'audio. Équivalent à worst*[vcodec!=none]
•
wa, worstaudio : Sélectionne le format audio seul de moindre qualité. Équivalent à worst*[vcodec=none]
•
wa*, worstaudio* : Sélectionne le format de moindre qualité qui contient de l'audio. Il peut également contenir une vidéo. Équivalent à worst*[acodec!=none]

Par exemple, pour télécharger le format vidéo seul de moindre qualité, vous pouvez utiliser -f worstvideo. Il est cependant recommandé de ne pas utiliser worst et les options associées. Lorsque votre sélecteur de format est worst, le format qui est le pire à tous égards est sélectionné. La plupart du temps, ce que vous voulez vraiment, c'est la vidéo avec la plus petite taille de fichier. Il est donc généralement préférable d'utiliser -S +size ou plus rigoureusement, -S +size,+br,+res,+fps au lieu de -f worst. Voir Tri des formats pour plus de détails.

Vous pouvez sélectionner le n-ième meilleur format d'un type en utilisant best<type>.<n>. Par exemple, best.2 sélectionnera le 2ème meilleur format combiné. De même, bv*.3 sélectionnera le 3ème meilleur format contenant un flux vidéo.

Si vous souhaitez télécharger plusieurs vidéos, et qu'elles n'ont pas les mêmes formats disponibles, vous pouvez spécifier l'ordre de préférence en utilisant des barres obliques. Notez que les formats à gauche sont préférés ; par exemple, -f 22/17/18 téléchargera le format 22 s'il est disponible, sinon il téléchargera le format 17 s'il est disponible, sinon il téléchargera le format 18 s'il est disponible, sinon il se plaindra qu'aucun format approprié n'est disponible pour le téléchargement.

Si vous souhaitez télécharger plusieurs formats d'une même vidéo, utilisez une virgule comme séparateur, par exemple -f 22,17,18 téléchargera ces trois formats, bien sûr s'ils sont disponibles. Ou un exemple plus sophistiqué combiné avec la fonctionnalité de précédence : -f 136/137/mp4/bestvideo,140/m4a/bestaudio.

Vous pouvez fusionner la vidéo et l'audio de plusieurs formats en un seul fichier en utilisant -f <format1>+<format2>+... (nécessite ffmpeg installé) ; par exemple, -f bestvideo+bestaudio téléchargera le meilleur format vidéo seul, le meilleur format audio seul et les multiplexera ensemble avec ffmpeg.

Avertissement de dépréciation : Comme le comportement décrit ci-dessous est complexe et contre-intuitif, il sera supprimé et les flux multiples seront activés par défaut à l'avenir. Un nouvel opérateur sera plutôt ajouté pour limiter les formats à un seul audio/vidéo

À moins que --video-multistreams ne soit utilisé, tous les formats avec un flux vidéo sauf le premier sont ignorés. De même, à moins que --audio-multistreams ne soit utilisé, tous les formats avec un flux audio sauf le premier sont ignorés. Par exemple, -f bestvideo+best+bestaudio --video-multistreams --audio-multistreams téléchargera et fusionnera les 3 formats donnés. Le fichier résultant aura 2 flux vidéo et 2 flux audio. Mais -f bestvideo+best+bestaudio --no-video-multistreams téléchargera et fusionnera seulement bestvideo et bestaudio. best est ignoré car un autre format contenant un flux vidéo (bestvideo) a déjà été sélectionné. L'ordre des formats est donc important. -f best+bestaudio --no-audio-multistreams ne téléchargera que best tandis que -f bestaudio+best --no-audio-multistreams ignorera best et ne téléchargera que bestaudio.

Filtrage des Formats

Vous pouvez également filtrer les formats vidéo en mettant une condition entre crochets, comme dans -f "best[heig

ht=720]" (ou -f "[filesize>10M]" puisque les filtres sans sélecteur sont interprétés comme étant les meilleurs).

Les champs de métadonnées numériques suivants peuvent être utilisés avec les comparaisons <, <=, >, >=, = (égal à), != (différent de) :

•
filesize : Le nombre d'octets, si connu à l'avance
•
filesize_approx : Une estimation du nombre d'octets
•
width : Largeur de la vidéo, si connue
•
height : Hauteur de la vidéo, si connue
•
aspect_ratio : Ratio d'aspect de la vidéo, si connu
•
tbr : Débit moyen de l'audio et de la vidéo en kbps
•
abr : Débit moyen de l'audio en kbps
•
vbr : Débit moyen de la vidéo en kbps
•
asr : Fréquence d'échantillonnage audio en Hertz
•
fps : Fréquence d'images
•
audio_channels : Le nombre de canaux audio
•
stretched_ratio : largeur:hauteur des pixels de la vidéo, si non carrés

Le filtrage fonctionne également pour les comparaisons = (égal à), ^= (commence par), $= (finit par), *= (contient), ~= (correspond à une expression régulière) et les champs de métadonnées de chaîne de caractères suivants :

•
url : URL de la vidéo
•
ext : Extension du fichier
•
acodec : Nom du codec audio utilisé
•
vcodec : Nom du codec vidéo utilisé
•
container : Nom du format de conteneur
•
protocol : Le protocole qui sera utilisé pour le téléchargement réel, en minuscules (http, https, rtsp, rtmp, rtmpe, mms, f4m, ism, http_dash_segments, m3u8, ou m3u8_native)
•
language : Code de langue
•
dynamic_range : La plage dynamique de la vidéo
•
format_id : Une courte description du format
•
format : Une description lisible par l'homme du format
•
format_note : Informations supplémentaires sur le format
•
resolution : Description textuelle de la largeur et de la hauteur

Toute comparaison de chaîne de caractères peut être précédée de la négation ! afin de produire une comparaison opposée, par ex. !*= (ne contient pas). Le comparand d'une comparaison de chaîne de caractères doit être mis entre guillemets doubles ou simples s'il contient des espaces ou des caractères spéciaux autres que ._-.

Note : Aucun des champs de métadonnées mentionnés ci-dessus n'est garanti d'être présent, car cela dépend uniquement des métadonnées obtenues par l'extracteur particulier, c'est-à-dire les métadonnées offertes par le site web. Tout autre champ rendu disponible par l'extracteur peut également être utilisé pour le filtrage.

Les formats dont la valeur est inconnue sont exclus à moins que vous ne mettiez un point d'interrogation (?) après l'opérateur. Vous pouvez combiner les filtres de format, ainsi -f "bv[height<=?720][tbr>500]" sélectionne des vidéos jusqu'à 720p (ou des vidéos dont la hauteur est inconnue) avec un débit de 500 kbps minimum. Vous pouvez également utiliser les filtres avec all pour télécharger tous les formats qui satisfont le filtre, par ex. -f "all[vcodec=none]" sélectionne tous les formats audio uniquement.

Les sélecteurs de format peuvent également être regroupés à l'aide de parenthèses ; par ex. -f "(mp4,webm)[height<480]" téléchargera les meilleurs formats mp4 et webm pré-fusionnés avec une hauteur inférieure à 480.

Tri des formats

Vous pouvez modifier les critères de sélection du meilleur format en utilisant -S (--format-sort). Le format général est --format-sort champ1,champ2....

Les champs disponibles sont :

•
hasvid : Donne la priorité aux formats qui ont un flux vidéo
•
hasaud : Donne la priorité aux formats qui ont un flux audio
•
ie_pref : La préférence du format
•
lang : La préférence linguistique telle que déterminée par l'extracteur (par ex. langue originale préférée à la description audio)
•
quality : La qualité du format
•
source : La préférence de la source
•
proto : Protocole utilisé pour le téléchargement (https/ftps > http/ftp > m3u8_native/m3u8 > http_dash_segments> websocket_frag > mms/rtsp > f4f/f4m)
•
vcodec : Codec vidéo (av01 > vp9.2 > vp9 > h265 > h264 > vp8 > h263 > theora > autre)
•
acodec : Codec audio (flac/alac > wav/aiff > opus > vorbis > aac > mp4a > mp3 > ac4 > eac3 > ac3 > dts > autre)
•
codec : Équivalent à vcodec,acodec
•
vext : Extension vidéo (mp4 > mov > webm > flv > autre). Si --prefer-free-formats est utilisé, webm est préféré.
•
aext : Extension audio (m4a > aac > mp3 > ogg > opus > webm > autre). Si --prefer-free-formats est utilisé, l'ordre change en ogg > opus > webm > mp3 > m4a > aac
•
ext : Équivalent à vext,aext
•
filesize : Taille exacte du fichier, si connue à l'avance
•
fs_approx : Taille approximative du fichier
•
size : Taille exacte du fichier si disponible, sinon taille approximative du fichier
•
height : Hauteur de la vidéo
•
width : Largeur de la vidéo
•
res : Résolution vidéo, calculée comme la plus petite dimension.
•
fps : Fréquence d'images de la vidéo
•
hdr : La plage dynamique de la vidéo (DV > HDR12 > HDR10+ > HDR10 > HLG > SDR)
•
channels : Le nombre de canaux audio
•
tbr : Débit moyen total en kbps
•
vbr : Débit moyen de la vidéo en kbps
•
abr : Débit moyen de l'audio en kbps
•
br : Débit moyen en kbps, tbr/vbr/abr
•
asr : Fréquence d'échantillonnage audio en Hz

Avertissement de dépréciation : Beaucoup de ces champs ont des alias (actuellement non documentés) qui pourraient être supprimés dans une future version. Il est recommandé d'utiliser uniquement les noms de champs documentés.

Tous les champs, sauf indication contraire, sont triés par ordre décroissant. Pour inverser cela, préfixez le champ par un +. Par ex. +res préfère les formats avec la plus petite résolution. De plus, vous pouvez suffixer une valeur préférée pour les champs, séparée par un :. Par ex. res:720 préfère les vidéos plus grandes, mais pas plus grandes que 720p et la plus petite vidéo s'il n'y a pas de vidéos inférieures à 720p. Pour les codecs et extensions, vous pouvez fournir deux valeurs préférées, la première pour la vidéo et la seconde pour l'audio. Par ex. +codec:avc:m4a (équivalent à +vcodec:avc,+acodec:m4a) définit la préférence du codec vidéo sur h264 > h265 > vp9 > vp9.2 > av01 > vp8 > h263 > theora et la préférence du codec audio sur mp4a > aac > vorbis > opus > mp3 > ac3 > dts. Vous pouvez également faire en sorte que le tri préfère les valeurs les plus proches de celles fournies en utilisant ~ comme délimiteur. Par ex. filesize~1G préfère le format dont la taille de fichier est la plus proche de 1 Gio.

Les champs hasvid et ie_pref reçoivent toujours la priorité la plus élevée dans le tri, indépendamment de l'ordre défini par l'utilisateur. Ce comportement peut être modifié en utilisant --format-sort-force. En dehors de ceux-ci, l'ordre par défaut utilisé est : lang,quality,res,fps,hdr:12,vcodec,channels,acodec,size,br,asr,proto,ext,hasaud,source,id. Les extracteurs peuvent outrepasser cet ordre par défaut, mais ils ne peuvent pas outrepasser l'ordre fourni par l'utilisateur.

Notez que la valeur par défaut pour hdr est hdr:12 ; c'est-à-dire que Dolby Vision n'est pas privilégié. Ce choix a été fait car les formats DV ne sont pas encore entièrement compatibles avec la plupart des appareils. Cela pourrait changer à l'avenir.

Si votre sélecteur de format est worst, le dernier élément est sélectionné après le tri. Cela signifie qu'il sélectionnera le format le plus mauvais à tous égards. La plupart du temps, ce que vous voulez réellement, c'est la vidéo avec la plus petite taille de fichier. Il est donc généralement préférable d'utiliser -f best -S +size,+br,+res,+fps.

Astuce : Vous pouvez utiliser -v -F pour voir comment les formats ont été triés (du pire au meilleur).

Exemples de sélection de format

# Télécharger et fusionner le meilleur format vidéo uniquement et le meilleur format audio uniquement,
# ou télécharger le meilleur format combiné si le format vidéo uniquement n'est pas disponible
$ yt-dlp -f "bv+ba/b"
# Télécharger le meilleur format contenant une vidéo,
# et s'il n'a pas déjà de flux audio, le fusionner avec le meilleur format audio uniquement
$ yt-dlp -f "bv*+ba/b"
# Identique à ci-dessus
$ yt-dlp
# Télécharger le meilleur format vidéo uniquement et le meilleur format audio uniquement sans les fusionner
# Dans ce cas, un modèle de sortie doit être utilisé car
# par défaut, bestvideo et bestaudio auront le même nom de fichier.
$ yt-dlp -f "bv,ba" -o "%(title)s.f%(format_id)s.%(ext)s"
# Télécharger et fusionner le meilleur format contenant un flux vidéo,
# et tous les formats audio uniquement dans un seul fichier
$ yt-dlp -f "bv*+mergeall[vcodec=none]" --audio-multistreams
# Télécharger et fusionner le meilleur format contenant un flux vidéo,
# et les 2 meilleurs formats audio uniquement dans un seul fichier
$ yt-dlp -f "bv*+ba+ba.2" --audio-multistreams
# Les exemples suivants montrent l'ancienne méthode (sans -S) de sélection de format
# et comment utiliser -S pour obtenir un résultat similaire mais (généralement) meilleur
# Télécharger la pire vidéo disponible (ancienne méthode)
$ yt-dlp -f "wv*+wa/w"
# Télécharger la meilleure vidéo disponible mais avec la plus petite résolution
$ yt-dlp -S "+res"
# Télécharger la plus petite vidéo disponible
$ yt-dlp -S "+size,+br"
# Télécharger la meilleure vidéo mp4 disponible, ou la meilleure vidéo s'il n'y a pas de mp4 disponible
$ yt-dlp -f "bv*[ext=mp4]+ba[ext=m4a]/b[ext=mp4] / bv*+ba/b"
# Télécharger la meilleure vidéo avec la meilleure extension
# (Pour la vidéo, mp4 > mov > webm > flv. Pour l'audio, m4a > aac > mp3 ...)
$ yt-dlp -S "ext"
# Télécharger la meilleure vidéo disponible mais pas mieux que 480p,
# ou la pire vidéo s'il n'y a pas de vidéo de moins de 480p
$ yt-dlp -f "bv*[height<=480]+ba/b[height<=480] / wv*+ba/w"
# Télécharger la meilleure vidéo disponible avec la plus grande hauteur mais pas mieux que 480p,
# ou la meilleure vidéo avec la plus petite résolution s'il n'y a pas de vidéo de moins de 480p
$ yt-dlp -S "height:480"
# Télécharger la meilleure vidéo disponible avec la plus grande résolution mais pas mieux que 480p,
# ou la meilleure vidéo avec la plus petite résolution s'il n'y a pas de vidéo de moins de 480p
# La résolution est déterminée en utilisant la plus petite dimension.
# Donc cela fonctionne correctement aussi pour les vidéos verticales
$ yt-dlp -S "res:480"
# Télécharger la meilleure vidéo (qui a aussi de l'audio) mais pas plus de 50 Mo,
# ou la pire vidéo (qui a aussi de l'audio) s'il n'y a pas de vidéo de moins de 50 Mo
$ yt-dlp -f "b[filesize<50M] / w"
# Télécharger la plus grande vidéo (qui a aussi de l'audio) mais pas plus de 50 Mo,
# ou la plus petite vidéo (qui a aussi de l'audio) s'il n'y a pas de vidéo de moins de 50 Mo
$ yt-dlp -f "b" -S "filesize:50M"
# Télécharger la meilleu
t vidéo (qui a aussi de l'audio) qui est la plus proche de 50 Mo
$ yt-dlp -f "b" -S "filesize~50M"
# Télécharger la meilleure vidéo disponible via un lien direct sur le protocole HTTP/HTTPS,
# ou la meilleure vidéo disponible via n'importe quel protocole s'il n'y a pas de telle vidéo
$ yt-dlp -f "(bv*+ba/b)[protocol^=http][protocol!*=dash] / (bv*+ba/b)"
# Télécharger la meilleure vidéo disponible via le meilleur protocole
# (https/ftps > http/ftp > m3u8_native > m3u8 > http_dash_segments ...)
$ yt-dlp -S "proto"
# Télécharger la meilleure vidéo avec le codec h264 ou h265,
# ou la meilleure vidéo s'il n'y a pas de telle vidéo
$ yt-dlp -f "(bv*[vcodec~='^((he|a)vc|h26[45])']+ba) / (bv*+ba/b)"
# Télécharger la meilleure vidéo avec le meilleur codec pas meilleur que h264,
# ou la meilleure vidéo avec le pire codec s'il n'y a pas de telle vidéo
$ yt-dlp -S "codec:h264"
# Télécharger la meilleure vidéo avec le pire codec pas pire que h264,
# ou la meilleure vidéo avec le meilleur codec s'il n'y a pas de telle vidéo
$ yt-dlp -S "+codec:h264"
# Exemples plus complexes
# Télécharger la meilleure vidéo pas meilleure que 720p en préférant une fréquence d'images supérieure à 30,
# ou la pire vidéo (préférant toujours une fréquence d'images supérieure à 30) s'il n'y a pas de telle vidéo
$ yt-dlp -f "((bv*[fps>30]/bv*)[height<=720]/(wv*[fps>30]/wv*)) + ba / (b[fps>30]/b)[height<=720]/(w[fps>30]/w)"
# Télécharger la vidéo avec la plus grande résolution pas meilleure que 720p,
# ou la vidéo avec la plus petite résolution disponible s'il n'y a pas de telle vidéo,
# en préférant une fréquence d'images plus élevée pour les formats de même résolution
$ yt-dlp -S "res:720,fps"
# Télécharger la vidéo avec la plus petite résolution pas pire que 480p,
# ou la vidéo avec la plus grande résolution disponible s'il n'y a pas de telle vidéo,
# en préférant un meilleur codec puis un débit binaire total plus élevé pour la même résolution
$ yt-dlp -S "+res:480,codec,br"

MODIFIER LES METADONNEES

Les métadonnées obtenues par les extracteurs peuvent être modifiées en utilisant --parse-metadata et --replace-in-metadata

--replace-in-metadata CHAMPS REGEX REMPLACER est utilisé pour remplacer du texte dans n'importe quel champ de métadonnées en utilisant une expression régulière Python (https://docs.python.org/3/library/re.html#regular-expression-syntax). Des références arrières (https://docs.python.org/3/library/re.html?highlight=backreferences#re.sub) peuvent être utilisées dans la chaîne de remplacement pour une utilisation avancée.

La syntaxe générale de --parse-metadata FROM:TO consiste à donner le nom d'un champ ou un modèle de sortie à partir duquel extraire des données, et le format pour l'interpréter, séparés par un deux-points :. Soit une expression régulière Python (https://docs.python.org/3/library/re.html#regular-expression-syntax) avec des groupes de capture nommés, un seul nom de champ, ou une syntaxe similaire au modèle de sortie (seul le formatage %(field)s est supporté) peut être utilisé pour TO. L'option peut être utilisée plusieurs fois pour analyser et modifier divers champs.

Notez que ces options conservent leur ordre relatif, permettant des remplacements dans les champs analysés et vice versa. De plus, tout champ ainsi créé peut être utilisé dans le modèle de sortie et affectera également les métadonnées du fichier multimédia ajoutées lors de l'utilisation de --embed-metadata.

Cette option a également quelques utilisations spéciales :

•
Vous pouvez télécharger une URL supplémentaire basée sur les métadonnées de la vidéo actuellement téléchargée. Pour ce faire, définissez le champ additional_urls à l'URL que vous souhaitez télécharger. Par exemple, --parse-metadata "description:(?P<additional_urls>https?://www\.vimeo\.com/\d+)" téléchargera la première vidéo Vimeo trouvée dans la description
•
Vous pouvez utiliser ceci pour changer les métadonnées qui sont intégrées dans le fichier multimédia. Pour ce faire, définissez la valeur du champ correspondant avec un préfixe meta_. Par exemple, toute valeur que vous définissez pour le champ meta_description sera ajoutée au champ description du fichier - vous pouvez utiliser ceci pour définir une "description" et un "synopsis" différents. Pour modifier les métadonnées des flux individuels, utilisez le préfixe meta<n>_ (par exemple, meta1_language). Toute valeur définie pour le champ meta_ écrasera toutes les valeurs par défaut.

Note : La modification des métadonnées se produit avant la sélection du format, l'extraction post-traitement et d'autres opérations de post-traitement. Certains champs peuvent être ajoutés ou modifiés pendant ces étapes, remplaçant vos modifications.

MISE À JOUR

Vous pouvez utiliser yt-dlp -U pour mettre à jour si vous utilisez les binaires de sortie

Si vous avez installé avec pip (https://github.com/yt-dlp/yt-dlp/wiki/Installation#with-pip), réexécutez simplement la même commande qui a été utilisée pour installer le programme

Pour les autres gestionnaires de paquets tiers, consultez le wiki (https://github.com/yt-dlp/yt-dlp/wiki/Installation#third-party-package-managers) ou référez-vous à leur documentation

Il existe actuellement trois canaux de sortie pour les binaires : stable, nightly et master.

•
stable est le canal par défaut, et bon nombre de ses changements ont été testés par les utilisateurs des canaux nightly et master.
•
Le canal nightly a des sorties prévues pour être compilées tous les jours vers minuit UTC, pour un instantané des nouveaux correctifs et changements du projet. C'est le canal recommandé pour les utilisateurs réguliers de yt-dlp. Les sorties nightly sont disponibles à partir de yt-dlp/yt-dlp-nightly-builds (https://github.com/yt-dlp/yt-dlp-nightly-builds/releases) ou en tant que sorties de développement du paquet PyPI yt-dlp (qui peut être installé avec le flag --pre de pip).
•
Le canal master contient des sorties compilées après chaque push sur la branche principale, et celles-ci auront les correctifs et ajouts les plus récents, mais peuvent également être plus sujettes aux régressions. Elles sont disponibles à partir de yt-dlp/yt-dlp-master-builds (https://github.com/yt-dlp/yt-dlp-master-builds/releases).

Lors de l'utilisation de --update/-U, un binaire de sortie ne mettra à jour que vers son canal actuel. --update-to CHANNEL peut être utilisé pour passer à un canal différent lorsqu'une version plus récente est disponible. --update-to [CHANNEL@]TAG peut également être utilisé pour mettre à niveau ou rétrograder vers des tags spécifiques d'un canal.

Vous pouvez également utiliser --update-to <repository> (<owner>/<repository>) pour mettre à jour vers un canal sur un dépôt complètement différent. Faites cependant attention au dépôt vers lequel vous mettez à jour, car aucune vérification n'est effectuée pour les binaires provenant de dépôts différents.

Exemples d'utilisation :

•
yt-dlp --update-to master pour passer au canal master et mettre à jour vers sa dernière sortie
•
yt-dlp --update-to stable@2023.07.06 pour mettre à niveau/rétrograder vers le tag de sortie stable 2023.07.06
•
yt-dlp --update-to 2023.10.07 pour mettre à niveau/rétrograder vers le tag 2023.10.07 s'il existe sur le canal actuel
•
yt-dlp --update-to example/yt-dlp@2023.09.24 pour mettre à niveau/rétrograder vers la sortie du dépôt example/yt-dlp, tag 2023.09.24

Important : Tout utilisateur rencontrant un problème avec la sortie stable doit installer ou mettre à jour vers la sortie nightly avant de soumettre un rapport de bug :

# Pour mettre à jour vers nightly depuis un exécutable/binaire stable :
yt-dlp --update-to nightly
# Pour installer nightly avec pip :
python -m pip install -U --pre "yt-dlp[default]"

Lorsque vous exécutez une version de yt-dlp antérieure à 90 jours, vous verrez un message d'avertissement suggérant de mettre à jour vers la dernière version. Vous pouvez supprimer cet avertissement en ajoutant --no-update à votre commande ou fichier de configuration.

PLUGINS

Notez que tous les plugins sont importés même s'ils ne sont pas appelés, et qu'aucune vérification n'est effectuée sur le code des plugins. Utilisez les plugins à vos propres risques et uniquement si vous faites confiance au code !

Les plugins peuvent être de type <type> extracteur ou postprocesseur. - Les plugins extracteurs n'ont pas besoin d'être activés depuis la ligne de commande et sont automatiquement appelés lorsque l'URL d'entrée le permet. - Les plugins extracteurs ont la priorité sur les extracteurs intégrés. - Les plugins postprocesseurs peuvent être appelés à l'aide de --use-postprocessor NOM.

Les plugins sont chargés depuis les packages d'espace de noms yt_dlp_plugins.extractor et yt_dlp_plugins.postprocessor.

En d'autres termes, la structure des fichiers sur le disque ressemble à ceci :

    yt_dlp_plugins/
        extractor/
            monplugin.py
        postprocessor/
            monplugin.py

yt-dlp recherche ces dossiers d'espace de noms yt_dlp_plugins dans de nombreux emplacements (voir ci-dessous) et charge les plugins de tous ces dossiers. Définissez la variable d'environnement YTDLP_NO_PLUGINS à quelque chose de non vide pour désactiver complètement le chargement des plugins.

Consultez le wiki pour connaître certains plugins connus (https://github.com/yt-dlp/yt-dlp/wiki/Plugins)

Toutes les classes publiques dont le nom se termine par IE/PP sont importées de chaque fichier pour les extracteurs et les postprocesseurs respectivement. INTEGRATION DE YT-DLP

yt-dlp fait de son mieux pour être un bon programme en ligne de commande, et devrait donc être appelable depuis n'importe quel langage de programmation.

Votre programme doit éviter d'analyser la sortie standard normale car elle pourrait changer dans les versions futures. Au lieu de cela, il devrait utiliser des options telles que -J, --print, --progress-template, --exec, etc. pour créer une sortie console que vous pouvez reproduire et analyser de manière fiable.

Depuis un programme Python, vous pouvez intégrer yt-dlp de manière plus puissante, comme ceci :

from yt_dlp import YoutubeDL
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
with YoutubeDL() as ydl:
    ydl.download(URLS)

Très probablement, vous voudrez utiliser diverses options. Pour une liste des options disponibles, consultez yt_dlp/YoutubeDL.py ou help(yt_dlp.YoutubeDL) dans un shell Python. Si vous êtes déjà familier avec la ligne de commande, vous pouvez utiliser devscripts/cli_to_api.py (https://github.com/yt-dlp/yt-dlp/blob/master/devscripts/cli_to_api.py) pour traduire n'importe quel commutateur CLI en paramètres YoutubeDL.

Astuce : Si vous portez votre code de youtube-dl vers yt-dlp, un point important à surveiller est que nous ne garantissons pas que la valeur de retour de YoutubeDL.extract_info soit sérialisable en JSON, ni même qu'elle soit un dictionnaire. Elle sera de type dictionnaire, mais si vous voulez vous assurer qu'il s'agit d'un dictionnaire sérialisable, passez-le par YoutubeDL.sanitize_info comme montré dans l'exemple ci-dessous

Utiliser un sélecteur de format personnalisé








import yt_dlp
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
def format_selector(ctx):
    """ Sélectionne la meilleure vidéo et le meilleur audio qui ne résultent pas en mkv.
    NOTE : Ceci n'est qu'un exemple et ne gère pas tous les cas """
    # les formats sont déjà triés du pire au meilleur
    formats = ctx.get('formats')[::-1]
    # acodec='none' signifie qu'il n'y a pas d'audio
    best_video = next(f for f in formats
                      if f['vcodec'] != 'none' and f['acodec'] == 'none')
    # trouve l'extension audio compatible
    audio_ext = {'mp4': 'm4a', 'webm': 'webm'}[best_video['ext']]
    # vcodec='none' signifie qu'il n'y a pas de vidéo
    best_audio = next(f for f in formats if (
        f['acodec'] != 'none' and f['vcodec'] == 'none' and f['ext'] == audio_ext))
    # Ce sont les champs minimum requis pour un format fusionné
    yield {
        'format_id': f'{best_video["format_id"]}+{best_audio["format_id"]}',
        'ext': best_video['ext'],
        'requested_formats': [best_video, best_audio],
        # Doit être une liste de protocoles séparés par +
        'protocol': f'{best_video["protocol"]}+{best_audio["protocol"]}'
    }
ydl_opts = {
    'format': format_selector,
}
with yt_dlp.YoutubeDL(ydl_opts) as ydl:
    ydl.download(URLS)

Différences dans le comportement par défaut


Certaines des options par défaut de yt-dlp diffèrent de celles de
youtube-dl et youtube-dlc :




•


yt-dlp ne prend en charge que Python 3.10+ et supprimera la prise en charge de plus
de versions à mesure qu'elles atteignent la fin de vie (EOL)
(https://devguide.python.org/versions/#python-release-cycle) ; tandis que
youtube-dl prend toujours en charge Python 2.6+ et 3.2+
(https://github.com/ytdl-org/youtube-dl/issues/30568#issue-1118238743)


•


Les options --auto-number (-A), --title (-t) et --literal (-l) ne fonctionnent plus. Voir options supprimées pour plus de détails


•


avconv n'est pas pris en charge comme alternative à ffmpeg


•


yt-dlp stocke les fichiers de configuration dans des emplacements légèrement différents de ceux de youtube-dl.
Voir CONFIGURATION pour une liste des emplacements corrects


•


Le modèle de sortie par défaut est %(title)s [%(id)s].%(ext)s. Il n'y a pas de
vraie raison à ce changement. Il a été modifié avant même que yt-dlp ne soit rendu public et il n'est plus prévu de le ramener à
%(title)s-%(id)s.%(ext)s. Au lieu de cela, vous pouvez utiliser --compat-options
filename


•


Le tri des formats par défaut est différent de celui de youtube-dl et privilégie les résolutions plus élevées et les meilleurs codecs plutôt que les débits binaires plus élevés. Vous pouvez utiliser
l'option --format-sort pour la changer dans n'importe quel ordre de préférence, ou utiliser
--compat-options format-sort pour utiliser l'ordre de tri de youtube-dl. Les anciennes
versions de yt-dlp privilégiaient VP9 en raison de sa compatibilité plus large ; vous pouvez
utiliser --compat-options prefer-vp9-sort pour revenir à cette préférence de tri de format.
Ces deux options de compatibilité ne peuvent pas être utilisées ensemble


•


Le sélecteur de format par défaut est bv*+ba/b. Cela signifie que si un format combiné
vidéo + audio meilleur que le meilleur format vidéo seul est trouvé, le premier sera préféré. Utilisez -f bv+ba/b ou --compat-options
format-spec pour revenir à cela


•


Contrairement à youtube-dlc, yt-dlp ne permet pas de fusionner plusieurs flux audio/vidéo en un seul fichier par défaut (car cela entre en conflit avec l'utilisation de -f
bv*+ba). Si nécessaire, cette fonctionnalité doit être activée







 using
      --audio-multistreams et --video-multistreams. Vous pouvez également utiliser
      --compat-options multistreams pour activer les deux.
•
--no-abort-on-error est activé par défaut. Utilisez --abort-on-error ou --compat-options abort-on-error pour abandonner en cas d'erreur à la place.
•
Lors de l'écriture de fichiers de métadonnées tels que les miniatures, la description ou infojson, les mêmes informations (si disponibles) sont également écrites pour les playlists. Utilisez --no-write-playlist-metafiles ou --compat-options no-playlist-metafiles pour ne pas écrire ces fichiers.
•
--add-metadata joint l'infojson aux fichiers mkv en plus d'écrire les métadonnées lorsqu'il est utilisé avec --write-info-json. Utilisez --no-embed-info-json ou --compat-options no-attach-info-json pour annuler ce comportement.
•
Certaines métadonnées sont intégrées dans des champs différents lors de l'utilisation de --add-metadata par rapport à youtube-dl. Notamment, le champ comment contient l'URL de la page web (webpage_url) et le champ synopsis contient la description. Vous pouvez utiliser --parse-metadata pour modifier cela à votre convenance ou utiliser --compat-options embed-metadata pour annuler ce comportement.
•
playlist_index se comporte différemment lorsqu'il est utilisé avec des options telles que --playlist-reverse et --playlist-items. Voir #302 (https://github.com/yt-dlp/yt-dlp/issues/302) pour plus de détails. Vous pouvez utiliser --compat-options playlist-index pour conserver le comportement précédent.
•
La sortie de -F est listée dans un nouveau format. Utilisez --compat-options list-formats pour annuler ce comportement.
•
Les discussions en direct (si disponibles) sont considérées comme des sous-titres. Utilisez --sub-langs all,-live_chat pour télécharger tous les sous-titres à l'exception des discussions en direct. Vous pouvez également utiliser --compat-options no-live-chat pour empêcher le téléchargement de toute discussion en direct/danmaku.
•
Les URL de chaînes YouTube téléchargent toutes les vidéos de la chaîne. Pour télécharger uniquement les vidéos d'un onglet spécifique, fournissez l'URL de l'onglet. Si la chaîne n'affiche pas l'onglet demandé, une erreur sera levée. De plus, les URL /live lèvent une erreur s'il n'y a pas de vidéos en direct au lieu de télécharger silencieusement toute la chaîne. Vous pouvez utiliser --compat-options no-youtube-channel-redirect pour annuler toutes ces redirections.
•
Les vidéos indisponibles sont également listées pour les playlists YouTube. Utilisez --compat-options no-youtube-unavailable-videos pour supprimer cela.
•
Les dates de mise en ligne extraites de YouTube sont en UTC.
•
Si ffmpeg est utilisé comme téléchargeur, le téléchargement et la fusion des formats se font en une seule étape lorsque c'est possible. Utilisez --compat-options no-direct-merge pour annuler ce comportement.
•
L'intégration des miniatures dans les mp4 se fait avec mutagen si possible. Utilisez --compat-options embed-thumbnail-atomicparsley pour forcer l'utilisation d'AtomicParsley à la place.
•
Certaines métadonnées internes telles que les noms de fichiers sont supprimées par défaut de l'infojson. Utilisez --no-clean-infojson ou --compat-options no-clean-infojson pour annuler ce comportement.
•
Lorsque --embed-subs et --write-subs sont utilisés ensemble, les sous-titres sont écrits sur le disque et également intégrés dans le fichier multimédia. Vous pouvez utiliser uniquement --embed-subs pour intégrer les sous-titres et supprimer automatiquement le fichier séparé. Voir #630 (comment) (https://github.com/yt-dlp/yt-dlp/issues/630#issuecomment-893659460) pour plus d'informations. --compat-options no-keep-subs peut être utilisé pour annuler ce comportement.
•
certifi sera utilisé pour les certificats racine SSL, s'il est installé. Si vous souhaitez utiliser les certificats système (par exemple, auto-signés), utilisez --compat-options no-certifi.
•
La désinfection par yt-dlp des caractères invalides dans les noms de fichiers est différente/plus intelligente que dans youtube-dl. Vous pouvez utiliser --compat-options filename-sanitization pour revenir au comportement de youtube-dl.
•
[BARRÉ: yt-dlp essaie d'analyser les sorties des téléchargeurs externes dans la sortie de progression standard si possible (Actuellement implémenté : aria2c (https://github.com/yt-dlp/yt-dlp/issues/5931)). Vous pouvez utiliser --compat-options no-external-downloader-progress pour obtenir la sortie du téléchargeur telle quelle.]
•
Les versions de yt-dlp entre 2021.09.01 et 2023.01.02 appliquent --match-filters aux playlists imbriquées. C'était un effet secondaire involontaire de 8f18ac (https://github.com/yt-dlp/yt-dlp/commit/8f18aca8717bb0dd49054555af8d386e5eda3a88) et a été corrigé dans d7b460 (https://github.com/yt-dlp/yt-dlp/commit/d7b460d0e5fc710950582baed2e3fc616ed98a80). Utilisez --compat-options playlist-match-filter pour annuler ce comportement.
•
Les versions de yt-dlp entre 2021.11.10 et 2023.06.21 ont estimé les valeurs filesize_approx pour les formats fragmentés/manifestes. Cela a été ajouté pour la commodité dans f2fe69 (https://github.com/yt-dlp/yt-dlp/commit/f2fe69c7b0d208bdb1f6292b4ae92bc1e1a7444a), mais a été annulé dans 0dff8e (https://github.com/yt-dlp/yt-dlp/commit/0dff8e4d1e6e9fb938f4256ea9af7d81f42fd54f) en raison de l'inexactitude potentiellement extrême des valeurs estimées. Utilisez --compat-options manifest-filesize-approx pour continuer à extraire les valeurs estimées.
•
yt-dlp utilise des backends de client http modernes tels que requests. Utilisez --compat-options prefer-legacy-http-handler pour préférer l'utilisation du gestionnaire http hérité (urllib) pour les requêtes http standard.
•
Les sous-modules swfinterp, casefold sont supprimés.
•
Passer --simulate (ou appeler extract_info avec download=False) ne modifie plus la sélection de format par défaut. Voir #9843 (https://github.com/yt-dlp/yt-dlp/issues/9843) pour les détails.
•
yt-dlp n'applique plus le temps modifié par le serveur aux fichiers téléchargés par défaut. Utilisez --mtime ou --compat-options mtime-by-default pour annuler ce comportement.

Pour plus de facilité d'utilisation, quelques options de compatibilité supplémentaires sont disponibles :

•
--compat-options all : Utilise toutes les options de compatibilité (NE PAS UTILISER ceci !)
•
--compat-options youtube-dl : Identique à --compat-options all,-multistreams,-playlist-match-filter,-manifest-filesize-approx,-allow-unsafe-ext,-prefer-vp9-sort
•
--compat-options youtube-dlc : Identique à --compat-options all,-no-live-chat,-no-youtube-channel-redirect,-playlist-match-filter,-manifest-filesize-approx,-allow-unsafe-ext,-prefer-vp9-sort
•
--compat-options 2021 : Identique à --compat-options 2022,no-certifi,filename-sanitization
•
--compat-options 2022 : Identique à --compat-options 2023,playlist-match-filter,no-external-downloader-progress,prefer-legacy-http-handler,manifest-filesize-approx
•
--compat-options 2023 : Identique à --compat-options 2024,prefer-vp9-sort
•
--compat-options 2024 : Identique à --compat-options mtime-by-default. Utilisez ceci pour activer toutes les futures options de compatibilité.

Les options de compatibilité suivantes restaurent un comportement vulnérable d'avant les correctifs de sécurité :

•
--compat-options allow-unsafe-ext : Permet de télécharger des fichiers avec n'importe quelle extension (y compris les extensions non sécurisées) (GHSA-79w7-vh3h-8g4j (https://github.com/yt-dlp/yt-dlp/security/advisories/GHSA-79w7-vh3h-8g4j))

:warning: N'utilisez que si un téléchargement de fichier valide est rejeté parce que son extension est détectée comme peu courante.

Cette option peut permettre l'exécution de code à distance ! Envisagez d'ouvrir plutôt un ticket (https://github.com/yt-dlp/yt-dlp/issues/new/choose) !
