NOM

yadm - Yet Another Dotfiles Manager (Autre gestionnaire de fichiers de configuration)

SYNTAXE

yadm commande [options]

yadm commande-git-ou-alias [options]

yadm init [-f] [-w rép]

yadm clone url [-f] [-w rép] [-b branche] [--bootstrap] [--no-bootstrap]

yadm config nom [valeur]

yadm config [-e]

yadm list [-a]

yadm bootstrap

yadm encrypt

yadm decrypt [-l]

yadm alt

yadm perms

yadm enter [commande]

yadm git-crypt [options]

yadm transcrypt [options]

yadm upgrade [-f]

yadm introspect catégorie

DESCRIPTION

yadm est un outil pour gérer une collection de fichiers sur plusieurs ordinateurs, en utilisant un dépôt Git partagé. De plus, yadm offre une fonctionnalité pour sélectionner des versions alternatives de fichiers pour des systèmes particuliers. Enfin, yadm fournit la capacité de gérer un sous-ensemble de fichiers sécurisés, qui sont cryptés avant d'être inclus dans le dépôt.

COMMANDES

commande-git ou alias-git
Toute commande non gérée en interne par yadm est transmise à git(1). Les commandes ou alias Git sont invoqués avec le dépôt géré par yadm. Le répertoire de travail pour les commandes Git sera le répertoire de travail configuré work-tree (généralement $HOME).

Les fichiers de configuration sont gérés en utilisant les commandes git standard ; add, commit, push, pull, etc.

La commande config n'est pas transmise directement. Utilisez plutôt la commande gitconfig (voir ci-dessous).

alt
Crée des liens symboliques et traite les modèles pour tous les fichiers gérés correspondant aux règles de nommage décrites dans les sections ALTERNATES et TEMPLATES. Il est généralement inutile d'exécuter cette commande, car yadm traite automatiquement les alternatives par défaut. Ce comportement automatique peut être désactivé en définissant la configuration yadm.auto-alt sur "false".
bootstrap
Exécute $HOME/.config/yadm/bootstrap s'il existe.
clone url
Clone un dépôt distant pour suivre les fichiers de configuration. Après que le contenu du dépôt distant a été récupéré, une tentative de "checkout" de la branche HEAD distante est effectuée. S'il existe déjà des fichiers en conflit dans le work-tree, la version locale ne sera pas modifiée et vous devrez examiner et résoudre la différence.

Le dépôt est stocké dans $HOME/.local/share/yadm/repo.git. Par défaut, $HOME sera utilisé comme work-tree, mais cela peut être remplacé avec l'option -w . yadm peut forcer l'écrasement d'un dépôt existant en fournissant l'option -f . Si vous souhaitez utiliser une branche autre que la branche HEAD distante, vous pouvez la spécifier en utilisant l'option -b . Par défaut, yadm demandera à l'utilisateur si le programme de bootstrap doit être exécuté (s'il existe). Les options --bootstrap ou --no-bootstrap forceront l'exécution du bootstrap ou l'empêcheront, sans demander à l'utilisateur.

config
Cette commande gère les configurations pour yadm. Elle fonctionne exactement comme git-config(1). Voir la section CONFIGURATION pour plus de détails.
decrypt
Décrypte tous les fichiers stockés dans $HOME/.local/share/yadm/archive. Les fichiers décryptés seront relatifs au work-tree configuré (généralement $HOME). L'utilisation de l'option -l listera les fichiers stockés sans les extraire.
encrypt
Crypte tous les fichiers correspondant aux motifs trouvés dans $HOME/.config/yadm/encrypt. Voir la section CRYPTAGE pour plus de détails.
enter
Exécute un sous-shell avec toutes les variables Git définies. Quittez le sous-shell de la même manière que vous quittez votre shell normal (généralement avec la commande "exit"). Ce sous-shell peut être utilisé pour interagir facilement avec votre dépôt yadm en utilisant les commandes "git". Cela pourrait être utile si vous utilisez un outil qui utilise Git directement, tel que tig, vim-fugitive, git-cola, etc.

Optionnellement, vous pouvez fournir une commande après "enter", et au lieu d'invoquer votre shell, cette commande sera exécutée avec toutes les variables Git exposées à l'environnement de la commande.

Emacs Tramp et Magit peuvent gérer les fichiers en utilisant cette configuration :


(add-to-list 'tramp-methods
'("yadm"
(tramp-login-program "yadm")
(tramp-login-args (("enter")))
(tramp-login-env (("SHELL") ("/bin/sh")))
(tramp-remote-shell "/bin/sh")
(tramp-remote-shell-args ("-c"))))
Avec cette configuration, utilisez (magit-status "/yadm::").
git-crypt options
Si git-crypt est installé, cette commande vous permet de passer des options directement à git-crypt, avec l'environnement configuré pour utiliser le dépôt yadm.

git-crypt permet le chiffrement et le déchiffrement transparents des fichiers dans un dépôt git. Vous pouvez lire https://github.com/AGWA/git-crypt pour plus de détails.

gitconfig
Passe des options à la commande git config. Comme yadm utilise déjà la commande config pour gérer ses propres configurations, cette commande est fournie comme moyen de modifier les configurations du dépôt géré par yadm. Un cas utile pourrait être de configurer le dépôt afin que les fichiers non suivis soient affichés dans les commandes de statut. yadm configure initialement son dépôt de manière à ce que les fichiers non suivis ne soient pas affichés. Si vous souhaitez utiliser le comportement par défaut de Git (pour afficher les fichiers et répertoires non suivis), vous pouvez supprimer cette configuration.
yadm gitconfig --unset status.showUntrackedFiles
help
Affiche un résumé des commandes yadm.
init
Initialise un nouveau dépôt vide pour le suivi des fichiers de configuration. Le dépôt est stocké dans $HOME/.local/share/yadm/repo.git. Par défaut, $HOME sera utilisé comme work-tree, mais cela peut être remplacé avec l'option -w . yadm peut forcer l'écrasement d'un dépôt existant en fournissant l'option -f .
list
Affiche une liste des fichiers gérés par yadm. L'option -a provoquera l'affichage de tous les fichiers gérés. Sinon, la liste n'inclura que les fichiers du répertoire courant ou en dessous.
introspect catégorie
Rapporte les données internes de yadm. Les catégories supportées sont commands, configs, repo, et switches. Le but de l'introspection est de supporter la complétion en ligne de commande.
perms
Met à jour les permissions comme décrit dans la section PERMISSIONS. Il est généralement inutile d'exécuter cette commande, car yadm traite automatiquement les permissions par défaut. Ce comportement automatique peut être désactivé en définissant la configuration yadm.auto-perms sur "false".
transcrypt options
Si transcrypt est installé, cette commande vous permet de passer des options directement à transcrypt, avec l'environnement configuré pour utiliser le dépôt yadm.

transcrypt permet le chiffrement et le déchiffrement transparents des fichiers dans un dépôt git.

upgrade
Met à niveau le dépôt yadm vers la dernière version. L'option -f forcer la mise à niveau, même si elle n'est pas strictement nécessaire.

La mise à niveau est généralement nécessaire après une mise à niveau de yadm, car le format des fichiers de configuration et/ou la structure du dépôt peuvent avoir changé.

CONFIGURATION

yadm utilise le système de configuration de Git. Les configurations peuvent être définies en utilisant la commande yadm config ou en éditant le fichier $HOME/.config/yadm/config. Les configurations suivantes sont spécifiques à yadm:

yadm.bootstrap
Si défini sur "true", le programme $HOME/.config/yadm/bootstrap sera exécuté après un yadm clone. Par défaut, yadm demandera à l'utilisateur.
yadm.auto-alt
Si défini sur "false", les fichiers alternatifs et les modèles ne seront pas traités automatiquement. La commande yadm alt devra être exécutée manuellement.
yadm.auto-perms
Si défini sur "false", les permissions ne seront pas mises à jour automatiquement. La commande yadm perms devra être exécutée manuellement.
yadm.work-tree
Définit le répertoire de travail pour yadm. Par défaut, il s'agit de $HOME.

FICHIERS SPÉCIAUX

$HOME/.config/yadm/bootstrap
Script exécuté après un yadm clone si yadm.bootstrap est défini sur "true" ou si l'utilisateur le confirme.
$HOME/.config/yadm/encrypt
Fichier contenant des motifs glob pour les fichiers à crypter avec yadm encrypt.
$HOME/.local/share/yadm/archive
Répertoire contenant les fichiers cryptés.
$HOME/.local/share/yadm/repo.git
Dépôt Git géré par yadm.

upgrade
La version 3 de yadm utilise un répertoire différent pour stocker les données. Lorsque vous commencez à utiliser la version 3 pour la première fois, vous pourriez voir des avertissements concernant le déplacement de vos données vers ce nouveau répertoire. La manière la plus simple d'y parvenir est d'exécuter "yadm upgrade". Cette commande commencera par déplacer votre dépôt yadm vers le nouveau chemin. Ensuite, elle déplacera toutes les données d'archive. Si l'archive est suivie dans votre dépôt yadm, cette commande effectuera la "mise en staging" du renommage de ce fichier dans l'index du dépôt.

La mise à niveau tentera de désinitialiser et de réinitialiser vos sous-modules. Si vos sous-modules ne peuvent pas être désinitialisés, la mise à niveau échouera. La raison la plus courante pour laquelle les sous-modules échouent à la désinitialisation est qu'ils ont des modifications locales. Si vous êtes prêt à perdre les modifications locales de ces sous-modules, vous pouvez utiliser l'option -f avec la commande "upgrade" pour forcer la désinitialisation.

Après avoir exécuté "yadm upgrade", vous devriez exécuter "yadm status" pour examiner les modifications qui ont été mises en staging, et les commiter dans votre dépôt.

Vous pouvez lire https://yadm.io/docs/upgrade_from_2 pour plus d'informations.

version
Affiche la version de yadm.

OPTIONS

yadm prend en charge un ensemble d'options universelles qui modifient les chemins qu'il utilise. Les chemins par défaut sont documentés dans la section FICHIERS. Tout chemin spécifié par ces options doit être complètement qualifié. Si vous souhaitez toujours remplacer un ou plusieurs de ces chemins, il peut être utile de créer un alias pour la commande yadm. Par exemple, l'alias suivant pourrait être utilisé pour remplacer le répertoire du dépôt.

alias yadm='yadm --yadm-repo /chemin/alternatif/vers/repo'

Voici la liste complète des options universelles. Chaque option doit être suivie d'un chemin.

-Y, --yadm-dir
Remplace le répertoire yadm. yadm stocke ses configurations relatives à ce répertoire.
--yadm-data
Remplace le répertoire de données yadm. yadm stocke ses données relatives à ce répertoire.
--yadm-repo
Remplace l'emplacement du dépôt yadm.
--yadm-config
Remplace l'emplacement du fichier de configuration yadm.
--yadm-encrypt
Remplace l'emplacement de la configuration de chiffrement yadm.
--yadm-archive
Remplace l'emplacement de l'archive des fichiers chiffrés yadm.
--yadm-bootstrap
Remplace l'emplacement du programme de démarrage yadm.

CONFIGURATION

yadm utilise un fichier de configuration nommé $HOME/.config/yadm/config. Ce fichier utilise le même format que git-config(1). De plus, vous pouvez contrôler le contenu du fichier de configuration via la commande yadm config (qui fonctionne exactement comme git-config). Par exemple, pour désactiver les alternatives, vous pouvez exécuter la commande :

yadm config yadm.auto-alt false

Voici la liste complète des configurations prises en charge :

yadm.alt-copy
Si défini sur "true", les fichiers alternatifs seront des copies au lieu de liens symboliques. Cela peut être souhaitable, car certains systèmes pourraient ne pas prendre en charge correctement les symlinks.
yadm.auto-alt
Désactive la création automatique de liens décrite dans la section ALTERNATIVES. Si désactivée, vous pouvez toujours exécuter "yadm alt" manuellement pour créer les liens alternatifs. Cette fonctionnalité est activée par défaut.
yadm.auto-exclude
Désactive l'exclusion automatique des liens alternatifs créés, des fichiers de modèle et des motifs définis dans $HOME/.config/yadm/encrypt. Cette fonctionnalité est activée par défaut.
yadm.auto-perms
Désactive les modifications automatiques des permissions décrites dans la section PERMISSIONS. Si désactivée, vous pouvez toujours exécuter yadm perms manuellement pour mettre à jour les permissions. Cette fonctionnalité est activée par défaut.
yadm.auto-private-dirs
Désactive la création automatique de répertoires privés décrite dans la section PERMISSIONS.
yadm.cipher
Configure le système de chiffrement utilisé par les commandes encrypt/decrypt. Les options valides sont "gpg" et "openssl". La valeur par défaut est "gpg". Des informations détaillées peuvent être trouvées dans la section CHIFFREMENT.
yadm.git-program
Spécifie un programme alternatif à utiliser à la place de "git". Par défaut, le premier "git" trouvé dans $PATH est utilisé.
yadm.gpg-perms
Désactive les modifications de permissions sur $HOME/.gnupg/*. Cette fonctionnalité est activée par défaut.
yadm.gpg-program
Spécifie un programme alternatif à utiliser à la place de "gpg". Par défaut, le premier "gpg" trouvé dans $PATH est utilisé.
yadm.gpg-recipient
Chiffre de manière asymétrique les fichiers avec une paire de clés publique/privée gpg. Fournissez un "ID de clé" pour spécifier quelle clé publique utiliser pour le chiffrement. La clé doit exister dans vos trousseaux de clés publiques. Plusieurs destinataires peuvent être spécifiés (séparés par des espaces). Si laissé vide ou non fourni, le chiffrement symétrique est utilisé à la place. Si défini sur "ASK", gpg demandera interactivement les destinataires. Voir la section CHIFFREMENT pour plus de détails. Cette fonctionnalité est désactivée par défaut.
yadm.openssl-ciphername
Spécifie quel chiffrement doit être utilisé par openssl. "aes-256-cbc" est utilisé par défaut.
yadm.openssl-old
Les versions plus récentes d'openssl prennent en charge la fonction de dérivation de clé pbkdf2. Ceci est utilisé par défaut. Si cette configuration est définie sur "true", les opérations openssl utiliseront des options compatibles avec les anciennes versions d'openssl. Si vous modifiez cette option, vous devrez recréer votre archive chiffrée.
yadm.openssl-program
Spécifie un programme alternatif à utiliser à la place de "openssl". Par défaut, le premier "openssl" trouvé dans $PATH est utilisé.
yadm.ssh-perms
Désactive les modifications de permissions sur $HOME/.ssh/*. Cette fonctionnalité est activée par défaut.

Les configurations "locales" suivantes ne sont pas stockées dans $HOME/.config/yadm/config, elles sont stockées dans le dépôt local.

local.class
Spécifie une classe dans le but de créer des liens symboliques de fichiers alternatifs. Par défaut, aucune classe ne sera mise en correspondance. L'hôte local peut être assigné à plusieurs classes en utilisant la commande :
yadm config --add local.class <classe-additionnelle>
local.arch
Remplace l'architecture dans le but de créer des liens symboliques de fichiers alternatifs.
local.hostname
Remplace le nom d'hôte dans le but de créer des liens symboliques de fichiers alternatifs.
local.os
Remplace le système d'exploitation dans le but de créer des liens symboliques de fichiers alternatifs.
local.user
Remplace l'utilisateur dans le but de créer des liens symboliques de fichiers alternatifs.
local.distro
Remplace la distribution dans le but de créer des liens symboliques de fichiers alternatifs.
local.distro-family
Remplace la famille de distributions dans le but de créer des liens symboliques de fichiers alternatifs.

ALTERNATIVES

Lors de la gestion d'un ensemble de fichiers sur différents systèmes, il peut être utile d'avoir un moyen automatisé de choisir une version alternative d'un fichier pour un système d'exploitation, un hôte, un utilisateur, etc. différent.

yadm créera automatiquement un lien symbolique vers la version appropriée d'un fichier, lorsqu'un suffixe valide est ajouté au nom du fichier. Le suffixe contient les conditions qui doivent être remplies pour que ce fichier soit utilisé.

Le suffixe commence par "##", suivi d'un nombre quelconque de conditions séparées par des virgules.


##<condition>[,<condition>,...]

Chaque condition est une paire attribut/valeur, séparée par un point. Certaines conditions ne nécessitent pas de "valeur", et dans ce cas, le point et la valeur peuvent être omis. La plupart des attributs peuvent être abrégés en une seule lettre. Préfixer un attribut avec "~" nie la condition, ce qui signifie que la condition n'est évaluée que si la paire attribut/valeur est fausse.


[~]<attribut>[.<valeur>]

NOTE : La valeur est comparée sans tenir compte de la casse.

Voici les attributs pris en charge, dans l'ordre de priorité pondérée :

template, t
Valide lorsque la valeur correspond à un processeur de modèle pris en charge. Voir la section MODÈLES pour plus de détails.
user, u
Valide si la valeur correspond à l'utilisateur actuel. Utilisateur actuel

ALTERNATIVES

Les fichiers gérés par yadm peuvent avoir plusieurs versions. Par exemple, vous pouvez gérer à la fois la configuration pour Linux et macOS pour le même fichier. Lorsque yadm place un fichier (ou un lien symbolique vers celui-ci), il sélectionne la version la plus appropriée.

Les versions sont choisies en fonction des conditions spécifiées dans le suffixe du nom de fichier, séparées par des ##. Les conditions sont évaluées dans l'ordre suivant.

user, u
Valide si la valeur correspond au nom d'utilisateur actuel. Le nom d'utilisateur est calculé en exécutant id -u -n.
hostname, h
Valide si la valeur correspond au nom d'hôte court. Le nom d'hôte est calculé en exécutant uname -n et en supprimant tout domaine.
class, c
Valide si la valeur correspond à la configuration local.class. La classe doit être définie manuellement à l'aide de yadm config local.class <classe>. Consultez la section CONFIGURATION pour plus de détails sur la définition de local.class.
distro_family, f
Valide si la valeur correspond à la famille de distribution. La famille de distribution est calculée en inspectant la ligne ID_LIKE de /etc/os-release (ou ID si aucune ligne ID_LIKE n'est trouvée).
distro, d
Valide si la valeur correspond à la distribution. La distribution est calculée en exécutant lsb_release -si ou en inspectant l'ID de /etc/os-release.
os, o
Valide si la valeur correspond au système d'exploitation. Le système d'exploitation est calculé en exécutant uname -s.
arch, a
Valide si la valeur correspond à l'architecture. L'architecture est calculée en exécutant uname -m.
default
Valide lorsqu'aucune autre alternative n'est valide.
extension, e
Une "condition" spéciale qui n'affecte pas le processus de sélection. Son but est plutôt de permettre au fichier alternatif de se terminer par une certaine extension afin, par exemple, de faire en sorte que les éditeurs mettent correctement en évidence le contenu.

NOTE: Le système d'exploitation pour "Windows Subsystem for Linux" est rapporté comme "WSL", même si uname s'identifie comme "Linux".

Vous pouvez utiliser n'importe quel nombre de conditions, dans n'importe quel ordre. Une alternative ne sera utilisée que si TOUTES les conditions sont valides. Pour tous les fichiers gérés par le dépôt de yadm ou listés dans $HOME/.config/yadm/encrypt, s'ils correspondent à cette convention de nommage, des liens symboliques seront créés pour la version la plus appropriée.

La version "la plus appropriée" est déterminée en calculant un score pour chaque version d'un fichier. Un modèle est toujours mieux classé qu'une condition de lien symbolique. Le nombre de conditions est le facteur suivant en importance pour le classement ; les fichiers avec plus de conditions seront toujours favorisés. Les conditions négatives (précédées de "~") ne sont classées que par rapport au nombre de conditions non niées. Toute condition invalide disqualifiera complètement ce fichier.

Si vous ne souhaitez pas que toutes les versions des alternatives soient stockées dans le même répertoire que le lien symbolique généré, vous pouvez les placer dans le répertoire $HOME/.config/yadm/alt. Le lien symbolique généré ou le modèle traité sera créé en utilisant le même chemin relatif.

La liaison d'alternatives peut être mieux illustrée par un exemple. Supposons que les fichiers suivants sont gérés par le dépôt de yadm :


- $HOME/path/example.txt##default
- $HOME/path/example.txt##class.Work
- $HOME/path/example.txt##class.Work,~os.Darwin
- $HOME/path/example.txt##os.Darwin
- $HOME/path/example.txt##os.Darwin,hostname.host1
- $HOME/path/example.txt##os.Darwin,hostname.host2
- $HOME/path/example.txt##os.Linux
- $HOME/path/example.txt##os.Linux,hostname.host1
- $HOME/path/example.txt##os.Linux,hostname.host2

Si vous exécutez sur un Macbook nommé "host2", yadm créera un lien symbolique qui ressemble à ceci :

$HOME/path/example.txt -> $HOME/path/example.txt##os.Darwin,hostname.host2

Cependant, sur un autre Macbook nommé "host3", yadm créera un lien symbolique qui ressemble à ceci :

$HOME/path/example.txt -> $HOME/path/example.txt##os.Darwin

Comme le nom d'hôte ne correspond à aucun des fichiers gérés, la version plus générique est choisie.

Si vous exécutez sur un serveur Linux nommé "host4", le lien sera :

$HOME/path/example.txt -> $HOME/path/example.txt##os.Linux

Si vous exécutez sur un serveur Solaris, le lien utilisera la version par défaut :

$HOME/path/example.txt -> $HOME/path/example.txt##default

Si vous exécutez sur un Macbook avec la classe définie sur "Work", le lien sera :

$HOME/path/example.txt -> $HOME/path/example.txt##class.Work

Comme la classe a une priorité plus élevée que le système d'exploitation, cette version est choisie.

Si vous exécutez sur un système avec la classe définie sur "Work", mais dans Windows Subsystem for Linux, où le système d'exploitation est rapporté comme WSL, le lien sera :

$HOME/path/example.txt -> $HOME/path/example.txt##class.Work,~os.Darwin

Si aucune version "##default" n'existe et qu'aucun fichier n'a de conditions valides, aucun lien ne sera créé.

Des liens sont également créés pour les répertoires nommés de cette manière, tant qu'ils contiennent au moins un fichier géré par yadm.

yadm créera automatiquement ces liens par défaut. Cela peut être désactivé à l'aide de la configuration yadm.auto-alt. Même si cela est désactivé, les liens peuvent être créés manuellement en exécutant yadm alt.

Les liens créés sont automatiquement ajoutés au fichier info/exclude du dépôt. Cela peut être désactivé à l'aide de la configuration yadm.auto-exclude.

La classe est une valeur spéciale qui est stockée localement sur chaque hôte (dans le dépôt local). Pour utiliser des liens symboliques alternatifs basés sur la classe, vous devez définir la valeur de la classe à l'aide de la configuration local.class. Ceci est défini comme toute autre configuration yadm avec la commande yadm config. Ce qui suit définit la classe sur "Work".


yadm config local.class Work

De même, les valeurs d'architecture, de système d'exploitation, de nom d'hôte, d'utilisateur, de distribution et de famille de distribution peuvent être remplacées manuellement à l'aide des options de configuration local.arch, local.os, local.hostname, local.user, local.distro et local.distro-family.

MODÈLES

Si une condition de modèle est définie dans le suffixe "##" d'un fichier alternatif, et que les dépendances nécessaires pour le modèle sont disponibles, alors le fichier sera traité pour créer ou écraser des fichiers.

Processeurs de modèles pris en charge :

default
C'est le processeur de modèles intégré de yadm. Ce processeur est très basique, avec une syntaxe de type Jinja. L'avantage de ce processeur est qu'il ne dépend que de awk, qui est disponible sur la plupart des systèmes *nix. Pour utiliser ce processeur, spécifiez la valeur "default" ou laissez simplement la valeur (par exemple, "##template").

NOTE: Ce processeur de modèles effectue des comparaisons insensibles à la casse dans les instructions if.

ESH
ESH est un processeur de modèles écrit en shell conforme POSIX. Il permet d'exécuter des commandes shell dans les modèles. Cela peut être utilisé pour faire référence à vos propres configurations dans les modèles, par exemple :


<% yadm config mysection.myconfig %>

Pour utiliser le processeur de modèles ESH, spécifiez la valeur "esh".

j2cli
Pour utiliser le processeur de modèles Jinja j2cli, spécifiez la valeur "j2" ou "j2cli".
envtpl
Pour utiliser le processeur de modèles Jinja envtpl, spécifiez la valeur "j2" ou "envtpl".

NOTE: La spécification de "j2" comme processeur tentera d'utiliser j2cli ou envtpl, selon celui qui est disponible.

Si le processeur de modèles spécifié est disponible, les modèles seront traités pour créer ou écraser des fichiers.

Lors du traitement, les variables suivantes sont disponibles dans le modèle :


Jinja par défaut ou Description ESH
------------- ------------- ----------------------------
yadm.arch YADM_ARCH uname -m
yadm.class YADM_CLASS Dernière classe définie localement
yadm.classes YADM_CLASSES Toutes les classes
yadm.distro YADM_DISTRO lsb_release -si
yadm.distro_family YADM_DISTRO_FAMILY ID_LIKE de /etc/os-release
yadm.filename Nom de fichier pour le fichier actuel
yadm.hostname YADM_HOSTNAME uname -n (sans domaine)
yadm.os YADM_OS uname -s
yadm.source YADM_SOURCE Nom du fichier modèle

NOTE: Le système d'exploitation pour "Windows Subsystem for Linux" est rapporté comme "WSL", même si uname s'identifie comme "Linux".

NOTE: Si lsb_release n'est pas disponible, DISTRO sera l'ID spécifié dans /etc/os-release.

Exemples :

whatever##template avec le contenu suivant


{% if yadm.user == "harvey" %}
config={{yadm.class}}-{{yadm.os}}
{% else %}

{% endif %}

produirait un fichier nommé whatever avec le contenu suivant si l'utilisateur est "harvey" :


config=work-Linux

et le suivant sinon (si whatever.extra contient admin=false) :


config=dev-whatever
admin=false

Un modèle ESH équivalent nommé whatever##template.esh ressemblerait à ceci :

Les fichiers créés sont automatiquement ajoutés au fichier info/exclude du dépôt. Cela peut être désactivé à l'aide de la configuration yadm.auto-exclude.

CHIFFREMENT

Il peut être utile de gérer des informations confidentielles

CHIFFREMENT ET DÉCHIFFREMENT

Il est courant d'utiliser des fichiers sensibles, comme des clés SSH ou GPG, sur plusieurs systèmes. Cependant, cela impliquerait de placer des données en texte clair dans un dépôt Git, qui réside souvent sur un système public. yadm peut faciliter le chiffrement et le déchiffrement d'un ensemble de fichiers afin que la version chiffrée puisse être maintenue dans le dépôt Git. Cette fonctionnalité ne fonctionnera que si un outil pris en charge est disponible. gpg(1) et openssl(1) sont pris en charge. gpg est utilisé par défaut, mais openssl peut être configuré avec la configuration yadm.cipher.

Pour utiliser cette fonctionnalité, une liste de motifs (un par ligne) doit être créée et enregistrée sous le nom $HOME/.config/yadm/encrypt. Cette liste de motifs doit être relative au work-tree configuré (généralement $HOME). Par exemple :


.ssh/*.key
.gnupg/*.gpg

Les expansions de noms de fichiers standards (*, ?, [) sont prises en charge. Deux astérisques consécutifs "**" peuvent être utilisés pour faire correspondre tous les sous-répertoires. Les autres expansions de shell comme les accolades et le tilde ne sont pas prises en charge. Les espaces dans les chemins sont pris en charge et ne doivent pas être mis entre guillemets. Si un répertoire est spécifié, son contenu sera inclus. Les chemins commençant par "!" seront exclus.

La commande yadm encrypt trouvera tous les fichiers correspondant aux motifs et demandera un mot de passe. Une fois le mot de passe confirmé, les fichiers correspondants seront chiffrés et enregistrés sous le nom $HOME/.local/share/yadm/archive. Les fichiers "encrypt" et "archive" doivent être ajoutés au dépôt yadm afin qu'ils soient disponibles sur plusieurs systèmes.

Pour déchiffrer ces fichiers ultérieurement, ou sur un autre système, exécutez yadm decrypt et fournissez le mot de passe correct. Une fois les fichiers déchiffrés, les permissions sont automatiquement mises à jour comme décrit dans la section PERMISSIONS.

Le chiffrement symétrique est utilisé par défaut, mais le chiffrement asymétrique peut être activé en utilisant la configuration yadm.gpg-recipient.

NOTE : Il est recommandé d'utiliser un dépôt privé lors de la conservation de fichiers confidentiels, même s'ils sont chiffrés.

Les motifs trouvés dans $HOME/.config/yadm/encrypt sont automatiquement ajoutés au fichier info/exclude du dépôt à chaque exécution de yadm encrypt. Ceci afin d'empêcher l'ajout accidentel de données sensibles au dépôt. Ceci peut être désactivé en utilisant la configuration yadm.auto-exclude.

Utilisation de transcrypt ou git-crypt

Une option complètement distincte pour le chiffrement de données consiste à installer et utiliser transcrypt ou git-crypt. Une fois installés, vous pouvez utiliser ces outils en exécutant yadm transcrypt ou yadm git-crypt. Ces outils permettent le chiffrement et le déchiffrement transparent des fichiers dans un dépôt Git. Voir les sites web suivants pour plus d'informations :

- https://github.com/elasticdog/transcrypt

- https://github.com/AGWA/git-crypt

PERMISSIONS

Lorsque les fichiers sont extraits d'un dépôt Git, leurs permissions initiales dépendent de l'umask de l'utilisateur. En raison de cela, yadm mettra automatiquement à jour les permissions de certains chemins de fichiers. Les permissions "groupe" et "autres" seront supprimées des fichiers suivants :

- $HOME/.local/share/yadm/archive

- Tous les fichiers correspondant aux motifs dans $HOME/.config/yadm/encrypt

- Le répertoire et les fichiers SSH, .ssh/*

- Le répertoire et les fichiers GPG, .gnupg/*

yadm met automatiquement à jour les permissions par défaut. Cela peut être désactivé en utilisant la configuration yadm.auto-perms. Même si désactivé, les permissions peuvent être mises à jour manuellement en exécutant yadm perms. Le traitement du répertoire .ssh peut être désactivé en utilisant la configuration yadm.ssh-perms. Le traitement du répertoire .gnupg peut être désactivé en utilisant la configuration yadm.gpg-perms.

Lors du clonage d'un dépôt qui contient des données dans un répertoire .ssh ou .gnupg, si ces répertoires n'existent pas au moment du clonage, yadm créera les répertoires avec le masque 0700 avant de fusionner les données récupérées dans le work-tree.

Lors de l'exécution d'une commande Git et que les répertoires .ssh ou .gnupg n'existent pas, yadm créera ces répertoires avec le masque 0700 avant d'exécuter la commande Git. Cela peut être désactivé en utilisant la configuration yadm.auto-private-dirs.

HOOKS

Pour chaque commande prise en charge par yadm, un programme peut être fourni pour s'exécuter avant ou après cette commande. On les appelle des "hooks". yadm recherche les hooks dans le répertoire $HOME/.config/yadm/hooks. Chaque hook est nommé en utilisant un préfixe de pre_ ou post_, suivi de la commande qui doit déclencher le hook. Par exemple, pour créer un hook qui s'exécute après chaque commande yadm pull, créez un hook nommé post_pull. Les hooks doivent avoir la permission de fichier exécutable définie.

Si un hook pre_ est défini et que le hook se termine avec un statut de sortie non nul, yadm refusera d'exécuter la commande yadm. Par exemple, si un hook pre_commit est défini, mais que cette commande se termine avec un statut de sortie non nul, le yadm commit ne sera jamais exécuté. Cela permet de "court-circuiter" toute opération à l'aide d'un hook pre_.

Les hooks disposent des variables d'environnement suivantes à leur disposition lors de l'exécution :

YADM_HOOK_COMMAND
La commande qui a déclenché le hook
YADM_HOOK_DATA
Le chemin vers le répertoire de données yadm
YADM_HOOK_DIR
Le chemin vers le répertoire yadm
YADM_HOOK_EXIT
Le statut de sortie de la commande yadm
YADM_HOOK_FULL_COMMAND
La commande yadm avec tous les arguments de ligne de commande (les paramètres sont séparés par des espaces, et tout espace, tabulation ou barre oblique inverse sera échappé par une barre oblique inverse)
YADM_HOOK_REPO
Le chemin vers le dépôt yadm
YADM_HOOK_WORK
Le chemin vers le work-tree

FICHIERS

Toutes les configurations de yadm sont relatives au "répertoire yadm". yadm utilise la "XDG Base Directory Specification" pour déterminer ce répertoire. Si la variable d'environnement $XDG_CONFIG_HOME est définie comme un chemin complet, ce répertoire sera $XDG_CONFIG_HOME/yadm. Sinon, ce sera $HOME/.config/yadm.

De même, les fichiers de données de yadm sont relatifs au "répertoire de données yadm". yadm utilise la "XDG Base Directory Specification" pour déterminer ce répertoire. Si la variable d'environnement $XDG_DATA_HOME est définie comme un chemin complet, ce répertoire sera $XDG_DATA_HOME/yadm. Sinon, ce sera $HOME/.local/share/yadm.

Voici les chemins par défaut utilisés par yadm pour ses propres données. La plupart de ces chemins peuvent être modifiés à l'aide d'options universelles. Voir la section OPTIONS pour plus de détails.

$HOME/.config/yadm
Le répertoire yadm. Par défaut, toutes les configurations que yadm stocke sont relatives à ce répertoire.
$HOME/.local/share/yadm
Le répertoire de données yadm. Par défaut, toutes les données que yadm stocke sont relatives à ce répertoire.
$YADM_DIR/config
Fichier de configuration pour yadm.
$YADM_DIR/alt
C'est un répertoire pour conserver les "fichiers alternatifs" sans les avoir côte à côte avec le lien symbolique résultant ou le modèle traité. Les fichiers alternatifs placés dans ce répertoire seront créés par rapport à $HOME.
$YADM_DATA/repo.git
Dépôt Git utilisé par yadm.
$YADM_DIR/encrypt
Liste des globs utilisés pour le chiffrement/déchiffrement
$YADM_DATA/archive
Tous les fichiers chiffrés avec yadm encrypt sont stockés dans ce fichier.

EXEMPLES

yadm init
Créer un dépôt vide pour gérer les fichiers
yadm add .bash_profile ; yadm commit
Ajouter .bash_profile à l'index Git et créer un nouveau commit
yadm remote add origin <url>
Ajouter un dépôt distant d'origine à un dépôt existant
yadm push -u origin master
Première poussée de master vers origin
echo .ssh/*.key >> $HOME/.config/yadm/encrypt
Ajouter un nouveau motif à la liste des fichiers chiffrés
yadm encrypt ; yadm add ~/.local/share/yadm/archive ; yadm commit
Valider un nouvel ensemble de fichiers chiffrés
