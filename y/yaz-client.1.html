NOM

yaz-client - Client Z39.50/SRU pour les implémenteurs

SYNTAXE

yaz-client [-a apdulog] [-b berdump] [-c cclfile] [-d dump] [-f cmdfile] [-k taille] [-m marclog] [-p proxy-addr] [-q cqlfile] [-t dispcharset] [-u auth] [-v loglevel] [-V] [-x] [server-addr]

DESCRIPTION

yaz-client est un client Z39.50[1]/SRU[2] (origine) avec une interface en ligne de commande simple qui vous permet de tester le comportement et les performances des cibles Z39.50 et des serveurs SRU.

À partir de la version 4.1.0 de YAZ, yaz-client peut également fonctionner comme un client de service web Solr[3].

Si server-addr est spécifié, le client établit une connexion à la cible Z39.50/SRU à l'adresse donnée.

Lorsque yaz-client est démarré, il essaie de lire les commandes à partir de l'un des fichiers suivants :

•Fichier de commandes s'il est donné par l'option -f.
•.yazclientrc dans le répertoire de travail courant.
•.yazclientrc dans le répertoire personnel de l'utilisateur. La valeur de la variable d'environnement $HOME est utilisée pour déterminer le répertoire personnel. Normalement, $HOME n'est défini que sur les systèmes POSIX tels que Linux, FreeBSD, Solaris.

OPTIONS

-a nomfichier

S'il est spécifié, la journalisation des paquets du protocole sera ajoutée au fichier donné. Si nomfichier est spécifié comme -, la sortie est écrite sur stdout.

-b nomfichier

S'il est spécifié, YAZ exportera les données BER dans une notation lisible vers le fichier spécifié. Si nomfichier est spécifié comme - la sortie est écrite sur stdout.

-c nomfichier

S'il est spécifié, la configuration CCL sera lue à partir du fichier donné.

-d dump

S'il est spécifié, YAZ exportera les données BER pour tous les PDU envoyés et reçus dans des fichiers individuels, nommés dump.DDD.raw, où DDD est 001, 002, 003, ...

-f fichiercmd

Lit les commandes à partir de fichiercmd. Lorsque cette option est utilisée, le client YAZ ne lit pas .yazclientrc du répertoire courant ou du répertoire personnel.

-k taille

Définit les messages préférés et la taille maximale d'enregistrement pour la requête d'initialisation en kilooctets. La valeur par défaut est 65536 (64 Mo).

-m nomfichier

S'il est spécifié, les enregistrements récupérés seront ajoutés au fichier donné.

-p proxy-addr

S'il est spécifié, le client utilisera le proxy à l'adresse donnée. Le client YAZ se connectera à un proxy à l'adresse et au port donnés. La cible réelle sera spécifiée dans le cadre de la requête InitRequest pour informer le proxy de la cible réelle.

-q nomfichier

S'il est spécifié, la configuration CQL sera lue à partir du fichier donné.

-t charsetaffichage

Si charsetaffichage est donné, il spécifie le nom du jeu de caractères de la sortie (sur le terminal sur lequel YAZ client est en cours d'exécution).

-u auth

S'il est spécifié, la chaîne auth sera utilisée pour l'authentification.

-v niveau

Définit le niveau de LOG à niveau. Le niveau est une séquence de jetons séparés par des virgules. Chaque jeton est un entier ou un élément LOG nommé - l'un de fatal, debug, warn, log, malloc, all, none.

-V

Imprime la version de YAZ.

-x

Permet au client YAZ d'afficher des vidages hexadécimaux des paquets envoyés et reçus sur la sortie standard.

COMMANDES

Le client YAZ accepte les commandes suivantes.

open zurl

Ouvre une connexion à un serveur. La syntaxe pour zurl est la même que celle décrite ci-dessus pour la connexion depuis la ligne de commande.

Syntaxe :

[(tcp|ssl|unix|http)':']hôte [:port][/base]

quit

Quitte le client YAZ

find requête

Envoie une requête de recherche en utilisant la requête donnée. Par défaut, la requête est supposée être PQF. Voir la commande querytype pour plus d'informations.

delete nomset

Supprime le jeu de résultats nommé nomset sur le serveur.

base base1 base2 ...

Définit le(s) nom(s) de la (des) base(s) de données à interroger. Une ou plusieurs bases de données peuvent être spécifiées, séparées par des espaces. Cette commande remplace la base de données donnée dans zurl.

show [début[+nombre [+setresult]]]

Récupère des enregistrements en envoyant une requête Present à partir de la position de départ donnée par début et un nombre d'enregistrements donné par nombre, à partir du jeu de résultats setresult. Si début n'est pas donné, alors le client récupère à partir de la position du dernier enregistrement récupéré plus 1. Si nombre n'est pas donné, alors un enregistrement est récupéré à la fois. Si setresult n'est pas donné, le jeu de résultats le plus récemment récupéré est utilisé.

scan terme

Analyse l'index de la base de données pour un terme. La syntaxe ressemble à la syntaxe de find. Si vous souhaitez rechercher le mot eau, vous pouvez écrire 
      scan water

mais si vous souhaitez rechercher uniquement dans, par exemple, le champ titre, vous écririez

      scan @attr 1=4 water

setscan set terme

Analyse l'index de la base de données pour un terme dans un jeu de résultats. Ceci est similaire à la commande scan mais a un jeu de résultats comme premier argument.

scanpos pos

Définit la position préférée pour le scan. Cette valeur est utilisée lors du prochain scan. Par défaut, la position est 1.

scansize taille

Définit le nombre d'entrées à retourner par le scan. Le nombre d'entrées par défaut est 20.

scanstep step

Définit la taille du pas pour le scan. Cette valeur est utilisée lors du prochain scan envoyé à la cible. Par défaut, la taille du pas est 0.

sort specsdeTri

Trie un jeu de résultats. La commande sort prend une séquence de spécifications de tri séparées par des espaces, chaque spécification de tri consistant en deux mots séparés par des espaces (de sorte que la liste de spécifications entière soit composée d'un nombre pair de mots). Le premier mot de chaque spécification représente un champ (critère de tri) et le second représente des indicateurs. Si le critère de tri contient =, il est supposé que la clé de tri est de type SortAttributes utilisant Bib-1 : dans ce cas, l'entier avant = est le type d'attribut et l'entier suivant = est la valeur de l'attribut. Si aucun caractère = n'est dans le critère, il est traité comme un champ de tri de type InternationalString. Le mot des indicateurs de chaque spécification de tri doit être constitué de s pour sensible à la casse ou i pour insensible à la casse, et < pour l'ordre croissant ou > pour l'ordre décroissant.

Exemple utilisant un critère de tri avec les attributs d'utilisation =local-number et structure = numeric et un indicateur croissant : 1=12,4=109 <

Autre exemple avec le champ de tri "Title" et un indicateur décroissant : Title >

sort+

Identique à sort mais stocke le jeu de résultats trié dans un nouveau jeu de résultats.

authentication [auth1 [auth2 [auth3]]]

Configure les chaînes d'authentification à envoyer au serveur. Zéro, 1, 2 ou 3 arguments peuvent suivre la commande auth.

Si aucun (0) argument n'est donné, aucune chaîne d'authentification n'est envoyée.

Si un argument est donné, l'authentification Z39.50 v2 OpenStyle est utilisée. Une convention courante pour la chaîne auth1 est que le nom d'utilisateur et le mot de passe sont séparés par une barre oblique, par exemple monutilisateur/monmotdepasse.

Si deux arguments ou plus sont donnés, l'authentification Z39.50 v3 est utilisée, dans ce cas le premier argument est utilisé, le deuxième argument est le groupe et le troisième argument est le mot de passe. Si seulement deux arguments sont donnés, le groupe est supposé être vide.

Comme pour les autres commandes de yaz-client, les arguments sont séparés par des espaces. Un caractère barre oblique inverse peut être utilisé pour inclure un caractère littéralement. Par exemple, auth monuser a\ b est une commande auth à deux arguments où l'utilisateur est monuser et le mot de passe est a b.

Pp">La chaîne d'authentification est d'abord envoyée au serveur lorsque la commande open est émise et que la requête Z39.50 Initialize Request est envoyée, donc cette commande doit être utilisée avant open afin d'être efficace.

sru méthode version

Sélectionne la méthode et la version du service Web. Doit être l'un de post, get, soap (par défaut) ou solr. La version doit être 1.1, 1.2 ou 2.0 pour SRU. D'autres versions sont autorisées - à des fins de test (négociation de version avec le serveur SRU). La version n'est actuellement pas utilisée pour les services Web Solr.

list_all

Cette commande affiche l'état et les valeurs de nombreux paramètres.

lslb n

Définit la limite à partir de laquelle aucun enregistrement ne doit être retourné avec le résultat de la recherche. Voir la norme Z39.50 sur les bornes de définition[4] pour plus de détails.

ssub n

Définit la limite jusqu'à laquelle tous les enregistrements doivent être retournés avec le résultat de la recherche. Voir la norme Z39.50 sur les bornes de définition[4] pour plus de détails.

mspn n

Définit le nombre d'enregistrements qui doivent être retournés si le nombre d'enregistrements dans l'ensemble de résultats se situe entre les valeurs de lslb et ssub. Voir la norme Z39.50 sur les bornes de définition[4] pour plus de détails.

status

Affiche les valeurs de lslb, ssub et mspn.

setname

Active ou désactive les jeux de résultats nommés. Par défaut, ils sont activés.

cancel

Envoie une requête de contrôle de ressource déclenchée (Trigger Resource Control Request) à la cible.

facets spécification

Spécifie les facettes demandées à utiliser dans la recherche. La notation est spécifiée dans ???.

format oid

Définit la syntaxe de transfert préférée pour les enregistrements récupérés. yaz-client prend en charge toutes les syntaxes d'enregistrement actuellement enregistrées. Voir Identificateurs de syntaxe d'enregistrement Z39.50[5] pour plus de détails. Les syntaxes d'enregistrement couramment utilisées incluent usmarc, sutrs et xml.

elements e

Définit le nom de l'ensemble d'éléments pour les enregistrements. De nombreuses cibles prennent en charge les ensembles d'éléments B (pour bref) et F (pour complet).

close

Envoie une APDU de fermeture Z39.50 et ferme la connexion avec le pair.

querytype type

Définit le type de requête tel qu'utilisé par la commande find. Les suivants sont pris en charge : prefix pour la notation de requête préfixe (requête de type 1) ; ccl pour la recherche CCL (requête de type 2), cql pour CQL (recherche de type 104 avec OID CQL), ccl2rpn pour la conversion CCL vers RPN (requête de type 1), cql2rpn pour la conversion CQL vers RPN (requête de type 1).

attributeset set

Définit l'OID de l'ensemble d'attributs pour les requêtes préfixes (RPN, Type-1).

refid id

Définit l'identifiant de référence pour la ou les requêtes Z39.50.

itemorder type no

Envoie une requête de commande d'article (Item Order Request) en utilisant ILL External. type est soit 1 soit 2, correspondant respectivement aux profils ILL 1 et 2. Le no est la position dans l'ensemble de résultats de l'enregistrement à commander.

update action recid doc

Envoie une requête de mise à jour d'article (Item Update Request). L'argument action doit être le type d'action : l'un de insert, replace, delete et update. Le deuxième argument, recid, est l'identifiant de l'enregistrement (chaîne quelconque). Le troisième argument, qui est facultatif, est le document d'enregistrement pour la requête. Si doc est précédé de « < », les caractères suivants sont traités comme un nom de fichier contenant les enregistrements à mettre à jour. Sinon, doc est traité comme un document lui-même. Le doc peut également être cité entre guillemets doubles. Si doc est omis, le dernier enregistrement reçu (dans le cadre d'une réponse present ou d'une réponse de recherche en parallèle) est utilisé pour la mise à jour.

source nomdefichier

Exécute une liste de commandes du fichier nomdefichier, tout comme 'source' sur la plupart des shells UNIX. Un point unique (.) peut être utilisé comme alternative.

! args

Exécute la commande args dans un sous-shell à l'aide de l'appel système.

push_command commande

La commande push_command prend une autre commande comme argument. Cette commande est alors ajoutée aux informations de l'historique (vous pouvez donc la récupérer plus tard). La commande elle-même n'est pas exécutée. Cette commande ne fonctionne que si vous avez activé GNU readline/history.

set_apdufile nomdefichier

Spécifie que les APDU doivent être enregistrées dans le fichier nomdefichier. Une autre façon d'obtenir un journal APDU est d'utiliser l'option de ligne de commande -a.

set_auto_reconnect indicateur

Spécifie si le client YAZ se reconnecte automatiquement si la cible ferme la connexion (uniquement Z39.50).

indicateur doit être on ou off.

set_auto_wait indicateur

Spécifie si le client YAZ doit attendre les paquets de protocole de réponse après une requête. Par défaut, le client YAZ attend (on) les paquets de réponse immédiatement après qu'une commande (find, show) a été émise. Si off est utilisé, le client YAZ ne tente pas de recevoir les paquets automatiquement. Ils devront être reçus manuellement lorsque la commande wait_response est utilisée.

indicateur doit être on ou off.

set_marcdump nomdefichier

Spécifie que tous les enregistrements récupérés doivent être ajoutés au fichier nomdefichier. Cette commande fait la même chose que l'option -m.

schema schemaid

Spécifie le schéma pour la récupération. Le schéma peut être spécifié comme un OID pour Z39.50. Pour SRU, le schéma est une simple URI de chaîne.

charset jeu_de_caracteres_negociation [jeu_de_caracteres_affichage] [[jeu_de_caracteres_marc]]

Spécifie le jeu de caractères (encodage) pour la négociation Z39.50 / l'encodage SRU et/ou le jeu de caractères pour la sortie (terminal).

jeu_de_caracteres_negociation est le nom du jeu de caractères à négocier par le serveur. Le nom spécial - pour jeu_de_caracteres_negociation spécifie qu'aucun jeu de caractères ne doit être négocié.

Si jeu_de_caracteres_affichage est donné, il spécifie le nom du jeu de caractères de la sortie (sur le terminal où le client YAZ est en cours d'exécution). Pour désactiver la conversion des caractères vers l'encodage de sortie, le nom spécial - (tiret) peut être utilisé. Si le nom spécial auto est donné, YAZ client convertira les chaînes dans l'encodage du terminal tel que retourné par l'appel nl_langinfo.

Si jeu_de_caracteres_marc est donné, il spécifie le nom du jeu de caractères des enregistrements MARC récupérés du serveur. Voir également la commande marccharset.


Note
Étant donné que la négociation du jeu de caractères prend effet dans la requête Z39.50 Initialize Request, vous devez exécuter cette commande avant la commande open.

Note
Les enregistrements MARC ne sont pas couverts par la négociation du jeu de caractères Z39.50, c'est pourquoi il existe un caractère séparé qui doit être connu pour effectuer des conversions significatives.

negcharset jeu_de_caracteres

Spécifie le jeu de caractères pour la négociation (Z39.50). L'argument est le même que le deuxième argument de la commande charset.

displaycharset jeu_de_caracteres

Spécifie le jeu de caractères pour la sortie (affichage). L'argument est le même que le deuxième argument de la commande charset.

marccharset jeu_de_caracteres

Spécifie le jeu de caractères pour les enregistrements MARC récupérés afin que YAZ client puisse les afficher dans un caractère adapté à votre écran. Voir la commande charset. Si auto est donné, YAZ supposera que MARC21/USMARC utilise MARC8/UTF8 et ISO-8859-1 pour toutes les autres variantes MARC. L'argument charset est le même que le troisième argument de la commande charset.

querycharset jeu_de_caracteres

Spécifie le jeu de caractères pour les termes de requête pour les requêtes RPN Z39.50 et les requêtes de scan Z39.50 (termListAndStartPoint). Il s'agit d'une conversion pure côté client qui convertit de displayCharset vers queryCharset.

set_cclfile nomdefichier

Spécifie que les champs CCL doivent être lus à partir du fichier nomdefichier. Cette commande fait la même chose que l'option -c.

set_cqlfile nomdefichier

Spécifie que les champs CQL doivent être lus à partir du fichier nomdefichier. Cette commande fait la même chose que l'option -q.

register_oid nom classe OID

Cette commande vous permet d'enregistrer votre propre identifiant d'objet - de sorte qu'au lieu de saisir une longue notation pointée, vous pouvez utiliser un nom court à la place. Le nom est votre nom pour l'OID, la classe est la classe, et l'OID est l'OID brut en notation pointée. La classe est l'une des suivantes : appctx, absyn, attet, transyn, diagset, recsyn, resform, accform, extserv, userinfo, elemspec, varset, schema, tagset, general. En cas de doute, utilisez la classe general.

register_tab commande chaîne

Cette commande enregistre une chaîne de complétion par tabulation pour la commande donnée.

sleep secondes

Cette commande fait dormir (rester inactive) le client YAZ pendant le nombre de secondes donné.

wait_response [ nombre]

Cette commande fait attendre au client YAZ un nombre de paquets de réponse de la cible. Si nombre est omis, 1 est supposé.

Cette commande est rarement utilisée et n'est utile que si la commande set_auto_wait est définie sur off.

xmles OID doc

Envoie une requête de services étendus XML en utilisant l'OID et le doc donnés.

zversion ver

Cette commande définit la version Z39.50 pour la négociation. Doit être utilisée avant open. Par défaut, 3 (version 3) est utilisée.

options op1 op2..

Cette commande définit les options Z39.50 pour la négociation. Doit être utilisée avant open.

Les options suivantes sont prises en charge : search, present, delSet, resourceReport, triggerResourceCtrl, resourceCtrl, accessCtrl, scan, sort, extendedServices, level_1Segmentation, level_2Segmentation, concurrentOperations, namedResultSets, encapsulation, resultCount, negotiationModel, duplicationDetection, queryType104, pQESCorrection, stringSchema.

EXEMPLE

L'exemple le plus simple de requête préfixe serait quelque chose comme

    f knuth

ou

    f "donald knuth"

Dans ces requêtes, aucun attribut n'a été spécifié. Cela laisse au serveur le soin de choisir les champs à rechercher, mais la plupart des serveurs rechercheront dans tous les champs. Certains serveurs ne prennent pas en charge cette fonctionnalité et exigent que certains attributs soient définis. Pour en ajouter un, vous pourriez faire :

    f @attr 1=4 computer

où nous recherchons dans le champ titre, puisque l'usage (1) est titre (4). Si nous voulons rechercher dans le champ auteur *et* dans le champ titre, et dans le champ titre en utilisant la troncature droite, cela pourrait ressembler à ce qui suit

g comme ceci :

    f @and @attr 1=1003 knuth @attr 1=4 @attr 5=1 computer

Enfin, l'utilisation d'un mélange d'attributs Bib-1 et GILS pourrait ressembler à ceci :

    f @attrset Bib-1 @and @attr GILS 1=2008 Washington @attr 1=21 weather
