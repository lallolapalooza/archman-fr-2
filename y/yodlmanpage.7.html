yodlmanpage(7) Langage de document Your Own Document Language yodlmanpage(7)

NOM

yodlmanpage - Type de document `manpage’ de Yodl

SYNTAXE

Le type de document manpage a été spécifiquement implémenté pour écrire des pages de manuel de style Unix. D'autres formats de document Yodl, tels que article, report et book, sont documentés dans le guide Yodl et dans la page de manuel de yodlmacros.

DESCRIPTION

Cette page de manuel décrit brièvement le type de document manpage du langage de document Yodl. Ce type de document est suffisamment spécifique pour justifier une page de manuel distincte.

Les documents Yodl de type manpage peuvent être convertis en documents `groff’ (en utilisant `yodl2man’), en documents `html’ (en utilisant `yodl2html’), ou en documents texte brut ASCII (en utilisant `yodl2txt’).

Les documents manpage n'utilisent pas les commandes de sectionnement `standard’ (par exemple, sect() et subsect()), mais disposent de macros spécifiques manpage...(). Vous pouvez cependant utiliser (et il est même conseillé de le faire) d'autres macros `normales’, telles que description(...) ou itemization(...) pour les listes, ou bf() pour le gras et em() pour l'emphase. En ce qui concerne les polices, voici ce qui est suggéré :

o
Utilisez em(texte) lorsque texte est une variable, un espace réservé, etc..
o
Utilisez bf(texte) lorsque texte est littéral, tel qu'une commande, un nom de fichier, un répertoire. Chaque document manpage dans Yodl doit être organisé comme suit :
o
manpage(nom) (section) (date) (paquet) (source) : C'est le préambule du document. Il indique ce que la page décrit, la section à laquelle elle appartient, la date de publication, le paquet auquel elle appartient et la source du paquet. Le numéro de section doit être (selon la page de manuel Linux sur man) : 1 pour les commandes, 2 pour les appels système, 3 pour les appels de bibliothèque, 4 pour les fichiers spéciaux, 5 pour les formats de fichiers, 6 pour les jeux, 7 pour les paquets de macros et les conventions, 8 pour les commandes de gestion système, et 9 pour les autres sujets spéciaux (par exemple, les commandes du noyau).
o
manpagename(nom) (description courte) : Le nom est à nouveau ce qui est décrit, la description courte est ce que, par exemple, la base de données whatis utilise pour les descriptions.
o
manpagesynopsis() : des informations très courtes sur l'`utilisation’ ou similaires. Gardez cette section courte, par exemple, une ligne avec toutes les options du programme est acceptable mais sans descriptions (celles-ci viennent plus tard).
o
manpagedescription() : le but du programme et autres. C'est aussi l'endroit pour documenter le fonctionnement.
o
manpageoptions() : C'est l'endroit pour documenter, par exemple, les indicateurs qui sont indiqués dans le manpagesynopsis(). Cette section est optionnelle, mais si elle est présente, elle doit se trouver à cet endroit.
o
manpagefiles() : les fichiers pertinents sont décrits dans cette section.
o
manpageseealso() : cette section liste les pages de manuel associées.
o
manpagediagnostics() : Conditions d'erreur, messages d'erreur, etc..
o
manpagebugs() : C'est ici que les bogues connus sont décrits. Cette section est optionnelle.
o
manpageauthor() : indiquant l'auteur et/ou le mainteneur.
o
manpagesection(NOM) : Cette macro démarre une section générique, non requise. Par exemple, vous pourriez vouloir une manpagesection(EXEMPLES) dans votre document. Comme suggestion typographique, utilisez des majuscules pour l'argument NOM pour des raisons de cohérence.
