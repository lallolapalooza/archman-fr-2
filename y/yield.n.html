coroutine(n) Commandes intégrées Tcl coroutine(n)

NOM

coroutine, yield, yieldto - Créer et produire des valeurs à partir de coroutines

SYNOPSIS

coroutine nom commande ?arg...?
yield ?valeur?
yieldto commande ?arg...?
nom ?valeur...?

DESCRIPTION

La commande coroutine crée un nouveau contexte de coroutine (avec la commande associée) nommé nom et exécute ce contexte en appelant commande, en lui passant les autres arguments restants sans interprétation supplémentaire. Une fois que commande retourne normalement ou avec une exception (par exemple, une erreur), le contexte de coroutine nom est supprimé.

Dans le contexte, des valeurs peuvent être générées comme résultats en utilisant la commande yield ; si aucun valeur n'est fourni, la chaîne vide est utilisée. Lorsque cela est appelé, le contexte suspend son exécution et la commande coroutine retourne l'argument de yield. L'exécution du contexte peut ensuite être reprise en appelant la commande de contexte, en transmettant éventuellement la seule valeur à utiliser comme résultat de l'appel yield qui a provoqué la suspension du contexte. Si le contexte de coroutine ne yield jamais et retourne conventionnellement, le résultat de la commande coroutine sera le résultat de l'évaluation du contexte.

La coroutine peut également suspendre son exécution en utilisant la commande yieldto, qui au lieu de retourner, cède l'exécution à une commande appelée commande (résolue dans le contexte de la coroutine) et à laquelle n'importe quel nombre d'arguments peut être passé. Comme chaque coroutine a une commande de contexte, yieldto peut être utilisé pour transférer le contrôle directement d'une coroutine à une autre (ceci n'est conseillé que si les deux coroutines s'attendent à cela), mais n'importe quelle commande peut être la cible. Si une coroutine est suspendue par ce mécanisme, le traitement de la coroutine peut être repris en appelant la commande de contexte en transmettant éventuellement un nombre arbitraire d'arguments. La valeur de retour de l'appel yieldto sera la liste des arguments passés à la commande de contexte ; il appartient à l'appelant de décider quoi faire de ces valeurs.

La manière recommandée d'écrire une version de yield qui permet la reprise avec plusieurs arguments est d'utiliser yieldto et la commande return, comme ceci :

proc yieldm {valeur} {
    yieldto return -level 0 $valeur
}

La coroutine peut également être supprimée en détruisant la commande nom, et le nom de la coroutine actuelle peut être récupéré en utilisant info coroutine. S'il y a des traces de suppression sur les variables dans l'implémentation de la coroutine, elles se déclencheront au moment où la coroutine est explicitement supprimée (ou, naturellement, si la commande retourne conventionnellement).

Au moment où commande est appelée, le namespace courant sera le namespace global et il n'y aura pas de frames de pile au-dessus (dans le sens de upvar et uplevel). Cependant, quelle commande appeler sera déterminé dans le namespace à partir duquel la commande coroutine a été appelée.

EXEMPLES

Cet exemple montre une coroutine qui produira une séquence infinie de valeurs paires, et une boucle qui consomme les dix premières.

proc allNumbers {} {
    yield
    set i 0
    while 1 {
        yield $i
        incr i 2
    }
}
coroutine nextNumber allNumbers
for {set i 0} {$i < 10} {incr i} {
    puts "reçu [nextNumber]"
}
rename nextNumber {}

Dans cet exemple, la coroutine sert à additionner les arguments qui lui sont passés.

coroutine accumulator apply {{} {
    set x 0
    while 1 {
        incr x [yield $x]
    }
}}
for {set i 0} {$i < 10} {incr i} {
    puts "$i -> [accumulator $i]"
}

Cet exemple démontre l'utilisation des coroutines pour implémenter l'algorithme classique du crible d'Ératosthène pour trouver les nombres premiers. Notez la création de coroutines à l'intérieur d'une coroutine.

proc filterByFactor {source n} {
    yield [info coroutine]
    while 1 {
        set x [$source]
        if {$x % $n} {
            yield $x
        }
    }
}
coroutine allNumbers apply {{} {while 1 {yield [incr x]}}}
coroutine eratosthenes apply {c {
    yield
    while 1 {
        set n [$c]
        yield $n
        set c [coroutine prime$n filterByFactor $c $n]
    }
}} allNumbers
for {set i 1} {$i <= 20} {incr i} {
    puts "premier#$i = [eratosthenes]"
}

Cet exemple montre comment une valeur peut être transmise entre un groupe de trois coroutines qui se font des yield mutuellement :

proc juggler {nom cible {valeur ""}} {
    if {$valeur eq ""} {
        set valeur [yield [info coroutine]]
    }
    while {$valeur ne ""} {
        puts "$nom : $valeur"
        set valeur [string range $valeur 0 end-1]
        lassign [yieldto $cible $valeur] valeur
    }
}
coroutine j1 juggler Larry [
    coroutine j2 juggler Curly [
        coroutine j3 juggler Moe j1]] "Nyuck!Nyuck!Nyuck!"

SEMANTIQUE DETAILEE

Cet exemple démontre que les coroutines commencent dans le namespace global, et que la résolution de commande se produit avant que la pile de la coroutine ne soit créée.

proc report {où niveau} {
    # D'où venait l'appelant ?
    set ns [uplevel 2 {namespace current}]
    yield "créé $où $niveau contexte=$ns nom=[info coroutine]"
}
proc example {} {
    report outer [info level]
}
namespace eval demo {
    proc example {} {
        report inner [info level]
    }
    proc makeExample {} {
        puts "création depuis [info level]"
        puts [coroutine coroEg example]
    }
    makeExample
}

En particulier, nous pouvons voir que la manipulation de la pile a eu lieu (en comparant les niveaux de la première et de la deuxième ligne) et que le niveau parent dans la coroutine est le namespace global. Nous pouvons également voir que les noms de coroutines sont locaux au namespace courant s'ils ne sont pas qualifiés, et que les coroutines peuvent yield en profondeur (par exemple, dans des procédures appelées).
