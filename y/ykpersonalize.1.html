YKPERSONALIZE(1) Outil de personnalisation YubiKey M YKPERSONALIZE(1)

NOM

ykpersonalize - personnalise les jetons OTP YubiKey

SYNTAXE

ykpersonalize [-Nclé] [-1 | -2] [-sfichier] [-ifichier] [-fformat] [-axxx] [-cxxx] [-ooption] [-y] [-v] [-d] [-h] [-n] [-t] [-u] [-x] [-z] [-m] [-S] [-V] [-Dxxx_]

DESCRIPTION

Configure la clé AES, l'identifiant utilisateur et d'autres paramètres dans une YubiKey. Pour une explication complète de la signification de tous les paramètres, consultez le manuel de référence : Manuel YubiKey (https://www.yubico.com/wp-content/uploads/2015/03/YubiKeyManual_v3.4.pdf)

OPTIONS

-Nclé

utilise la nième YubiKey trouvée.

-1

modifie la première configuration. C'est la configuration par défaut et elle est normalement utilisée pour la génération d'OTP réelle. Dans cette configuration, l'option -oappend-cr est activée par défaut.

-2

modifie la deuxième configuration. Ceci est pour YubiKey II uniquement et est alors normalement utilisé pour la génération de clé statique. Dans cette configuration, les options -oappend-cr, -ostatic-ticket, -ostrong-pw1, -ostrong-pw2 et -oman-update sont activées par défaut.

-z

supprime la configuration dans l'emplacement sélectionné.

-sfichier

enregistre la configuration dans un fichier au lieu de la clé (si le fichier est -, envoie vers la sortie standard).

-ifichier

lit la configuration depuis un fichier (si le fichier est -, lit depuis l'entrée standard). L'importation de configuration n'est valide que pour le format ycfg.

-fformat

format à utiliser avec -s et -i. Les options valides sont ycfg et legacy.

-a[xxx]

la clé secrète AES sous forme de chaîne hexadécimale de 32 (ou 40 pour OATH-HOTP/HMAC CHAL-RESP) caractères (pas modhex) (vide pour demander la clé sur stdin). Si -a n'est pas utilisé, une clé aléatoire sera générée.

-c[xxx]

une chaîne hexadécimale de 12 caractères (pas modhex) à utiliser comme code d'accès pour la programmation. NOTE : ceci ne CONFIGURATION PAS le code d'accès. Cela se fait avec -oaccess=. Si aucun argument n'est fourni, le code est demandé via stdin.

-ooption

modifie une option de configuration. Les arguments d'option possibles sont :

fixed=fffffffffff

L'identité publique modhex de la YubiKey, de 0 à 32 caractères (encodant jusqu'à 16 octets). Il est possible de fournir l'identité en hexadécimal, il suffit de préfixer la valeur avec 'h:'. La partie fixe est émise avant l'OTP lorsque le bouton de la YubiKey est pressé. Elle peut être utilisée comme identifiant pour l'utilisateur, par exemple.

uid[=uuuuuu]

La partie uid de l'OTP généré, également appelée identité privée, en hexadécimal. Doit faire 12 caractères de long. L'uid est 6 octets de données statiques qui sont inclus (chiffrés) dans chaque OTP, et sont utilisés pour valider qu'un OTP a bien été chiffré avec la clé AES partagée entre la YubiKey et le service de validation. Il ne peut pas être utilisé pour identifier la YubiKey car il n'est lisible que par ceux qui connaissent la clé AES. Si aucun argument n'est fourni, l'uid est demandé via stdin.

access[=fffffffffff]

Nouveau code d'accès hexadécimal à définir. Doit faire 12 caractères de long. Si un code d'accès est défini, il sera requis pour toute reprogrammation ultérieure de la YubiKey. Si aucun argument n'est fourni, le code est demandé via stdin.

oath-imf=xxx

Définit le facteur de déplacement initial OATH. C'est la valeur du compteur initial pour la YubiKey. Il doit s'agir d'une valeur comprise entre 0 et 1048560, divisible par 16.

ticket-flag

Active/désactive le drapeau de ticket, voir la section Drapeaux de ticket.

configuration-flag

Active/désactive le drapeau de configuration, voir la section Drapeaux de configuration.

-y

valide toujours sans demander confirmation.

-d

simulation (dry-run), exécute sans écrire sur une YubiKey.

-v

plus verbeux.

-h

affiche l'aide.

-V

affiche la version.

YubiKey Neo uniquement

-n URI

programme l'URI NDEF NFC.

-t texte

programme le texte NDEF NFC.

YubiKey 3 et 4 uniquement

-m mode

définit la configuration du périphérique pour la YubiKey. Elle est analysée sous la forme mode:delai_cr:delai_eject_auto où mode est :

0

Périphérique OTP uniquement.

1

Périphérique CCID uniquement.

2

Périphérique composite OTP/CCID.

3

Périphérique U2F uniquement.

4

Périphérique composite OTP/U2F.

5

Périphérique composite U2F/CCID.

6

Périphérique composite OTP/U2F/CCID. Ajoutez 80 pour définir MODE_FLAG_EJECT, par exemple : 81

delai_cr est le délai en secondes pendant lequel la YubiKey attend une pression sur le bouton pour la réponse au défi (par défaut 15)

delai_eject_auto est le délai en secondes avant que la carte ne soit éjectée automatiquement en mode 81

La suppression du mode OTP désactive également la communication entre ykpersonalize et la YubiKey. D'autres modifications de mode devront être effectuées avec ykneomgr (pour le mode CCID) ou u2f-host (pour le mode U2F).

YubiKey 3 et supérieur

-S0605...

définit la table de scan à utiliser avec la YubiKey. Elle doit être composée de 45 octets uniques sous forme de 90 caractères. Laissez l'argument vide pour réinitialiser à la valeur par défaut de la YubiKey. La table de scan doit être envoyée dans l'ordre : 
cbdefghijklnrtuvCBDEFGHIJKLNRTUV0123456789!\t\r

La table de scan par défaut dans la YubiKey est :

06050708090a0b0c0d0e0f111517181986858788898a8b8c8d8e8f9195979899271e1f202122232425269e2b28

Un exemple pour un Dvorak américain simplifié serait :

0c110b071c180d0a0619130f120e09378c918b879c988d8a8699938f928e89b7271e1f202122232425269e2b28

Ou pour un clavier français azerty (les chiffres sont décalés) :

06050708090a0b0c0d0e0f111517181986858788898a8b8c8d8e8f9195979899a79e9fa0a1a2a3a4a5a6382b28

Ou pour un clavier français BÉPO (Dvorak français) :

0b140c0938363707130512330f0d16188b948c89b8b6b787938592b38f8d9698a79e9fa0a1a2a3a4a5a69c2b28

Et un exemple turc (a un i sans point au lieu du i habituel) :

06050708090a0b340d0e0f111517181986858788898a8b8c8d8e8f9195979899271e1f202122232425269e2b28

Notez que vous devez supprimer tout espace blanc présent dans ces exemples avant d'utiliser les valeurs.

YubiKey 5 et supérieur

-D0403...

définit les informations du périphérique à utiliser avec cette YubiKey.

YubiKey 2.3 et supérieur

-u

Met à jour la configuration existante, plutôt que de la remplacer. Possible uniquement si l'emplacement est configuré comme mettable à jour.

-x

Échange les emplacements de configuration 1 et 2 à l'intérieur de la YubiKey. Possible uniquement si les deux emplacements sont configurés comme mettables à jour.

DRAPEAUX DE TICKET

tab-first

Envoie un caractère de tabulation comme premier caractère. Ceci est généralement utilisé pour passer au champ de saisie suivant.

append-tab1

Envoie un caractère de tabulation entre la partie fixe et la partie mot de passe unique. Ceci est utile si vous avez la partie fixe égale à t

YKPERSONALIZE

The ykpersonalize program allows you to reprogram a YubiKey. It can be used to change configuration, reprogram the OTP or change the configuration flags.

The YubiKey has two configurations, numbered 1 and 2. Configurations can be programmed independently. When ykpersonalize is run, it operates on configuration 1 unless the -2 option is given.

OPTIONS

The following options may be given on the command line:

-1
Operate on configuration 1.
-2
Operate on configuration 2.
-a
The argument to -a is interpreted as a password and is used to unlock the YubiKey. YubiKeys are password protected by default. If the password is not supplied, then the YubiKey is not programmed.
-n
No password is required. This will disable the password protection on the YubiKey. Use with caution!
-o
The argument to -o is interpreted as a YubiKey configuration flag. See the Configuration flags section.
-c
The argument to -c is interpreted as the fixed part of the YubiKey. This is a 12 character string in Modhex. See the Modhex section.
-i
The argument to -i is interpreted as the UID of the YubiKey. This is a 6 byte value. A UID can be specified in hex (eg. -i=0x123456789abc) or in modhex (eg. -i=h:abcde). If the UID is specified in modhex, it must be preceded by h:.
-H
The argument to -H is interpreted as the AES key. The key must be 16 bytes long. The key can be specified in hex (eg. -H=0x123456789abcdef0123456789abcdef0) or in modhex (eg. -H=h:bbbbbbbbbbbbbbbbbbbb). If the key is specified in modhex, it must be preceded by h:.
-C
The argument to -C is interpreted as the configuration token. This is a 16 character string in Modhex.
-l
The argument to -l is interpreted as the secret key. The secret key must be 32 bytes long. The key can be specified in hex (eg. -l=0x123456789abcdef0123456789abcdef0123456789abcdef0) or in modhex (eg. -l=h:bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb). If the secret key is specified in modhex, it must be preceded by h:.
-q
Quiet mode. Suppress all output except for errors.
-v
Verbose mode. Print extra debug information.
-s
This option is for programming YubiKey Neo only. It will program the YubiKey in scan-code mode. The output will differ between keyboard layouts.

CONFIGURATION FLAGS 1.x firmware only

append-tab

Send a tab character after the one-time password.

append-usbhid

Send the one-time password as a USB HID report.

append-newline

Send a newline character after the one-time password.

append-tab2

Send a tab character as the last character.

append-delay1

Add a half-second delay before sending the one-time password part. This option is only valid for firmware 1.x and 2.x.

append-delay2

Add a half-second delay after sending the one-time password part. This option is only valid for firmware 1.x and 2.x.

append-cr

Add a carriage return after sending the one-time password part.

YubiKey 2.0 firmware and above

protect-cfg2

When written to configuration 1, block later updates to configuration 2. When written to configuration 2, prevent configuration 1 from having the lock bit set.

YubiKey 2.1 firmware and above

oath-hotp

Set OATH-HOTP mode rather than YubiKey mode. In this mode, the token functions according to the OATH-HOTP standard.

YubiKey 2.2 firmware and above

chal-resp

Set challenge-response mode.

CONFIGURATION FLAGS

send-ref

Send a reference string of all 16 modhex characters before the fixed part. When combined with -ostrong-pw2 this sends a ! before the rest of the string.

pacing-10ms

Add a 10ms delay between key presses.

pacing-20ms

Add a 20ms delay between key presses.

static-ticket

Output a fixed string rather than a one-time password. The password is still based on the AES key and should be hard to guess and impossible to remember.

YubiKey 1.x firmware only

ticket-first

Send the one-time password rather than the fixed part first.

allow-hidtrig

Allow trigger through HID/keyboard by pressing caps-, num or scroll-lock twice. Not recommended for security reasons.

YubiKey 2.0 firmware and above

short-ticket

Limit the length of the static string to max 16 digits. This flag only makes sense with the -ostatic-ticket option. When -oshort-ticket is used without -ostatic-ticket it will program the YubiKey in "scan-code mode", in this mode the key sends the contents of fixed, uid and key as raw keyboard scancodes. For example, by using the fixed string h:8b080f0f122c9a12150f079e in this mode it will send Hello World! on a qwerty keyboard. This mode sends raw scan codes, so output will differ between keyboard layouts.

strong-pw1

Upper-case the two first letters of the output string. This is for compatibility with legacy systems that enforce both uppercase and lowercase characters in a password and does not add any security.

strong-pw2

Replace the first eight characters of the modhex alphabet with the numbers 0 to 7. Like -ostrong-pw1, this is intended to support legacy systems.

man-update

Enable user-initiated update of the static password. Only makes sense with the -ostatic-ticket option. This is only valid for firmware 2.x.

YubiKey 2.1 firmware and above

oath-hotp8

Generate an 8-digit HOTP rather than a 6-digit one.

oath-fixed-modhex1

Send the first byte of the fixed part as modhex.

oath-fixed-modhex2

Send the first two bytes of the fixed part as modhex.

oath-fixed-modhex

Send the fixed part is as modhex.

oath-id=m:OOTTUUUUUUUU

Configure OATH token id with a provided value. See description of this option under the 2.2 section for details, but note that a YubiKey 2.1 key can’t report its serial number and thus a token identifier value must be specified.

YubiKey 2.2 firmware and above

chal-yubico

Yubico OTP challenge-response mode.

chal-hmac

Generate HMAC-SHA1 challenge responses.

hmac-lt64

Calculate HMAC on less than 64 bytes input. Whatever is in the last byte of the challenge is used as end of input marker (backtracking from end of payload).

chal-btn-trig

The YubiKey will wait for the user to press the key (within 15 seconds) before answering the challenge.

serial-btn-visible

The YubiKey will emit its serial number if the button is pressed during power-up. This option is only valid for the 2.x firmware line.

serial-usb-visible

The YubiKey will indicate its serial number in the USB iSerial field. This option is not available in the 3.0 and 3.1 firmwares.

serial-api-visible

The YubiKey will allow its serial number to be read using an API call.

oath-id[=m:OOTTUUUUUUUU]

Configure OATH token id with a provided value, or if used without a value use the standard YubiKey token identifier.

The standard OATH token id for a Yubico YubiKey is (modhex) OO=ub, TT=he, (decimal) UUUUUUUU=serial number.

The reason for the decimal serial number is to make it easy for humans to correlate the serial number on the back of the YubiKey to an entry in a list of associated tokens for example. Other encodings can be accomplished using the appropriate oath-fixed-modhex options.

Note that the YubiKey must be programmed to allow reading its serial number, otherwise automatic token id creation is not possible.

See section "5.3.4 - OATH-HOTP Token Identifier" of the YubiKey manual http://yubico.com/files/YubiKey_manual-2.0.pdf for further details.

YubiKey 2.3 firmware and above

use-numeric-keypad

Send scancodes for numeric keypad keypresses when sending digits - helps with some keyboard layouts. This option is only valid for the 2.x firmware line.

fast-trig

Faster triggering when only configuration 1 is available. This option is always in effect on firmware versions 3.0 and above.

allow-update

Allow updating (or swapping) of certain parameters in a configuration at a later time.

dormant

Hides/unhides a configuration stored in a YubiKey.

YubiKey 2.4/3.1 firmware and above

led-inv

Inverts the behaviour of the led on the YubiKey.

OATH-HOTP Mode

When using OATH-HOTP mode, a HMAC key of 160 bits (20 bytes, 40 chars of hex) can be supplied with -a.

Challenge-response Mode

In CHAL-RESP mode, the token will NOT generate any keypresses when the button is pressed (although it is perfectly possible to have one slot with a keypress-generating configuration, and the other in challenge-response mode). Instead, a program capable of sending USB HID feature reports to the token must be used to send it a challenge, and read the response.

Modhex

Modhex is a way of writing hex digits where the “digits” are chosen for being in the same place on most keyboard layouts. To convert from hex to modhex, you can use:

tr "[0123456789abcdef]" "[cbdefghijklnrtuv]"

To convert the other way, use:

tr "[cbdefghijklnrtuv]" "[0123456789abcdef]"

EXAMPLES

Programming for YubiCloud:

ouid=`dd if=/dev/urandom 2>/dev/null | tr -d '[:upper:]' | tr -cd '[:xdigit:]' | fold -w12 | head -1`
ofixed=ff`dd if=/dev/urandom 2>/dev/null | tr -d '[:upper:]' | tr -cd '[:xdigit:]' | fold -w10 | head -1`
ykpersonalize -1 -ouid=h:$ouid -ofixed=h:$ofixed

This will program a key with a random 6 byte uid and a 12 character fixed string starting with vv. This is suitable for upload to YubiCloud at https://upload.yubico.com/
