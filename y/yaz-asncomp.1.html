NOM

yaz-asncomp - Compilateur ASN.1 de YAZ

SYNOPSIS

yaz-asncomp [-v] [-c fichier_c] [-h fichier_h] [-p fichier_p] [-d config] [-I output_include] [-i includedir] [-m module] [nom_fichier]

DESCRIPTION

yaz-asncomp est un compilateur ASN.1 qui lit une spécification ASN.1 dans nom_fichier et produit des définitions C/C++ et des encodeurs/décodeurs BER pour celle-ci.

Le code C/C++ et les fichiers d'en-tête produits utilisent le module ODR de YAZ, qui est une bibliothèque permettant d'encoder/décoder/imprimer des paquets BER. yaz-asncomp vous permet de spécifier le nom du fichier source résultant via des options. Alternativement, vous pouvez spécifier un fichier de DEFINITIONS, qui fournit une sortie personnalisée à de nombreux fichiers de sortie – si le fichier de spécification ASN.1 est constitué de plusieurs modules.

Cet utilitaire est écrit en Tcl. Toute version de Tcl devrait fonctionner.

OPTIONS

-v

Fait en sorte que le compilateur ASN.1 affiche plus de détails sur les différentes étapes des opérations.

-c fichier_c

Spécifie le nom du fichier C/C++ contenant les encodeurs/décodeurs.

-h fichier_h

Spécifie le nom du fichier d'en-tête contenant les définitions.

-p fichier_p

Spécifie le nom d'un fichier d'en-tête privé contenant les définitions. Par défaut, toutes les définitions sont placées dans le fichier d'en-tête (option -h).

-d fichier_d

Spécifie le nom d'un fichier de définitions.

-I output_include

Spécifie la première partie du répertoire où les fichiers d'en-tête sont écrits.

-i includedir

Spécifie la deuxième partie du répertoire où les fichiers d'en-tête sont écrits.

-m module

Spécifie que le compilateur ASN.1 ne doit traiter que le module donné. Si cette option n'est pas spécifiée, tous les modules du fichier ASN.1 sont traités.

FICHIER DE DÉFINITIONS

Le fichier de définitions est en réalité un script Tcl, mais il suit les règles traditionnelles des fichiers de configuration de type Shell. C'est-à-dire que # dénote le début d'un commentaire. Les définitions sont orientées ligne. Les fichiers de définitions consistent généralement en une série d'affectations de variables de la forme :

set nom valeur

Les variables disponibles sont :

default-prefix

Définit le préfixe pour les noms dans la sortie produite. La valeur consiste en trois jetons : préfixe de fonction C, préfixe de typedef C et préfixe de préprocesseur respectivement.

prefix(module)

Cette valeur définit les valeurs de préfixe pour le module module. La valeur a la même forme que default-prefix.

filename(module)

Spécifie le nom du fichier C/d'en-tête pour le module module.

init(module,h)

Fragment de code à placer dans la première partie de l'en-tête public pour le module module.

body(module,h)

Fragment de code à placer dans la dernière partie de l'en-tête public pour le module module (pied de page).

init(module,c)

Fragment de code à placer dans la première partie de l'encodeur/décodeur basé sur C pour le module module.

body(module,c)

Fragment de code à placer dans la dernière partie de l'encodeur/décodeur basé sur C pour le module module (pied de page).

map(module,nom)

Mappe le type ASN.1 dans le module module de nom à une valeur.

membermap(module,nom,membre)

Mappe le membre membre dans la SEQUENCE/CHOICE de nom dans le module module à une valeur. La valeur consiste en un ou deux jetons. Le premier jeton est le nom de la partie préprocesseur C. Le second jeton est le nom du membre C. Si le second jeton est omis, la valeur (un seul jeton) sert à la fois pour le préprocesseur et le membre de la structure/union C.

unionmap(module,nom,membre)

Mappe le membre membre dans la CHOICE de nom dans le module module à une valeur. La valeur consiste en deux ou trois jetons. Le premier jeton est le nom de l'entier dans l'union qui sert de sélecteur pour l'union elle-même. Le second jeton est le nom de l'union. Le troisième jeton remplace le nom du membre de la CHOICE; s'il est omis, le nom du membre est utilisé.
