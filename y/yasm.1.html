YASM(1) L'assembleur modulaire Yasm YASM(1)

NOM

yasm - L'assembleur modulaire Yasm

SYNTAXE

yasm [-f format] [-o fichier_sortie] [autres options...] {fichier_entree}

yasm -h

DESCRIPTION

L'assembleur modulaire Yasm est un assembleur portable et retargetable écrit sous la licence BSD « nouvelle » (2 ou 3 clauses). Yasm prend actuellement en charge les jeux d'instructions x86 et AMD64, accepte les syntaxes d'assembleur NASM et GAS, produit des formats d'objet binaires, ELF32, ELF64, COFF, Win32 et Win64, et génère des informations de débogage source dans les formats STABS, DWARF 2 et CodeView 8.

YASM est composé de la commande yasm, de libyasm, la bibliothèque backend principale, et d'un grand nombre de modules. Actuellement, libyasm et les modules chargeables sont intégrés statiquement dans l'exécutable yasm.

La commande yasm assemble le fichier fichier_entree et dirige la sortie vers le fichier fichier_sortie s'il est spécifié. Si fichier_sortie n'est pas spécifié, yasm dérivera un nom de fichier de sortie par défaut à partir du nom de son fichier d'entrée, généralement en ajoutant .o ou .obj, ou en supprimant toutes les extensions pour un fichier binaire brut. À défaut, le nom du fichier de sortie sera yasm.out.

Si appelée avec un fichier_entree de « - », yasm assemble l'entrée standard et dirige la sortie vers le fichier fichier_sortie, ou yasm.out si aucun fichier_sortie n'est spécifié.

OPTIONS

De nombreuses options peuvent être données sous l'une des deux formes : soit un tiret suivi d'une seule lettre, soit deux tirets suivis d'un nom d'option long. Les options sont listées par ordre alphabétique.

Options Générales

-a arch ou --arch=arch: Sélectionner l'architecture cible

Sélectionne l'architecture cible. L'architecture par défaut est « x86 », qui prend en charge à la fois les jeux d'instructions IA-32 et dérivés ainsi que AMD64. Pour afficher une liste des architectures disponibles sur la sortie standard, utilisez « help » comme arch. Voir yasm_arch(7) pour une liste des architectures prises en charge.

-f format ou --oformat=format: Sélectionner le format objet

Sélectionne le format de l'objet de sortie. Le format objet par défaut est « bin », qui est un binaire de format plat sans relocations. Pour afficher une liste des formats objets disponibles sur la sortie standard, utilisez « help » comme format. Voir yasm_objfmts(7) pour une liste des formats objets pris en charge.

-g debug ou --dformat=debug: Sélectionner le format de débogage

Sélectionne le format de débogage pour les informations de débogage. Les informations de débogage peuvent être utilisées par un débogueur pour associer le code exécutable au fichier source ou obtenir des informations sur les structures de données et les types. Les formats de débogage disponibles varient selon les formats objets ; yasm générera une erreur lorsqu'une combinaison invalide est sélectionnée. Le format objet par défaut est sélectionné par le format objet. Pour afficher une liste des formats de débogage disponibles sur la sortie standard, utilisez « help » comme debug. Voir yasm_dbgfmts(7) pour une liste des formats de débogage pris en charge.

-L liste ou --lformat=liste: Sélectionner le format du fichier liste

Sélectionne le format/style du fichier liste de sortie. Les fichiers liste mélangent généralement la source originale avec le code machine généré par l'assembleur. Le format de liste par défaut est « nasm », qui imite le format du fichier liste de NASM. Pour afficher une liste des formats de fichiers liste disponibles sur la sortie standard, utilisez « help » comme liste.

-l fichier_liste ou --list=fichier_liste: Spécifier le nom du fichier liste

Spécifie le nom du fichier liste de sortie. Si cette option n'est pas utilisée, aucun fichier liste n'est généré.

-m machine ou --machine=machine: Sélectionner l'architecture machine cible

Sélectionne l'architecture machine cible. Essentiellement un sous-type de l'architecture sélectionnée, le type de machine sélectionne entre les principaux sous-ensembles d'une architecture. Par exemple, pour l'architecture « x86 », les deux machines disponibles sont « x86 », qui est utilisée pour le jeu d'instructions 32 bits IA-32 et dérivés, et « amd64 », qui est utilisée pour le jeu d'instructions 64 bits. Cette différenciation est nécessaire pour générer le fichier objet correct pour les formats objets relocables tels que COFF et ELF. Pour afficher une liste des machines disponibles pour une architecture donnée sur la sortie standard, utilisez « help » comme machine et l'architecture donnée en utilisant -a arch. Voir yasm_arch(7) pour plus de détails.

-o nom_fichier ou --objfile=nom_fichier: Spécifier le nom du fichier objet

Spécifie le nom du fichier de sortie, en remplaçant tout nom par défaut généré par Yasm.

-p parseur ou --parser=parseur: Sélectionner le parseur

Sélectionne le parseur (la syntaxe de l'assembleur). Le parseur par défaut est « nasm », qui émule la syntaxe de NASM, le Netwide Assembler. Un autre parseur disponible est « gas », qui émule la syntaxe de GNU AS. Pour afficher une liste des parseurs disponibles sur la sortie standard, utilisez « help » comme parseur. Voir yasm_parsers(7) pour une liste des parseurs pris en charge.

-r preproc ou --preproc=preproc: Sélectionner le préprocesseur

Sélectionne le préprocesseur à utiliser sur le fichier d'entrée avant de le transmettre au parseur. Les préprocesseurs fournissent souvent des fonctionnalités de macros qui ne sont pas incluses dans le parseur principal. Le préprocesseur par défaut est « nasm », qui est une version importée du préprocesseur NASM réel. Un préprocesseur « raw » est également disponible, qui ignore simplement l'étape de préprocessing, transmettant le fichier d'entrée directement au parseur. Pour afficher une liste des préprocesseurs disponibles sur la sortie standard, utilisez « help » comme preproc.

-h ou --help: Afficher un résumé des options

Affiche un résumé des options d'invocation. Toutes les autres options sont ignorées et aucun fichier de sortie n'est généré.

--version: Obtenir la version de Yasm

Cette option fait que Yasm affiche le numéro de version de Yasm ainsi qu'un résumé de la licence sur la sortie standard. Toutes les autres options sont ignorées et aucun fichier de sortie n'est généré.

Options d'Avertissement

Les options -W ont deux formes contraires : -Wnom et -Wno-nom. Seules les formes non-par défaut sont montrées ici.

Les options d'avertissement sont traitées dans l'ordre où elles apparaissent sur la ligne de commande, donc si -w est suivi de -Worphan-labels, tous les avertissements sont désactivés *sauf* les étiquettes orphelines.

-w: Inhiber tous les messages d'avertissement

Cette option fait que Yasm inhibe tous les messages d'avertissement. Comme discuté ci-dessus, cette option peut être suivie d'autres options pour réactiver certains avertissements spécifiés.

-Werror: Traiter les avertissements comme des erreurs

Cette option fait que Yasm traite tous les avertissements comme des erreurs. Normalement, les avertissements n'empêchent pas la génération d'un fichier objet et ne résultent pas en un statut de sortie d'échec de yasm, contrairement aux erreurs. Cette option rend les avertissements équivalents aux erreurs en termes de ce comportement.

-Wno-unrecognized-char: Ne pas avertir sur les caractères d'entrée non reconnus

Fait en sorte que Yasm n'émette pas d'avertissement sur les caractères non reconnus trouvés dans l'entrée. Normalement, Yasm générera un avertissement pour tout caractère non ASCII trouvé dans le fichier d'entrée.

-Worphan-labels: Avertir sur les étiquettes sans option de fin

Lors de l'utilisation du parseur compatible NASM, fait que Yasm avertisse sur les étiquettes trouvées seules sur une ligne sans deux-points en fin. Bien que ce soient des étiquettes légales en syntaxe NASM, elles peuvent être involontaires, en raison de fautes de frappe ou d'un ordre de définition de macro.

Options du préprocesseur

Bien que ces options de préprocesseur affectent théoriquement tout préprocesseur, le seul préprocesseur actuellement dans Yasm est le préprocesseur “nasm”.

-D macro[=valeur] : Prédéfinit une macro

Prédéfinit une macro sur une seule ligne. La valeur est facultative (si aucune valeur n'est donnée, la macro est quand même définie, mais à une valeur vide).

-e ou --preproc-only : Préprocesse uniquement

Arrête l'assemblage après l'étape de préprocesseur; la sortie préprocessée est envoyée au nom de sortie spécifié ou, si aucun nom de sortie n'est spécifié, à la sortie standard. Aucun fichier objet n'est produit.

-I chemin : Ajouter un chemin de fichier include

Ajoute le répertoire chemin au chemin de recherche pour les fichiers include. Le chemin de recherche ne comprend par défaut que le répertoire dans lequel réside le fichier source.

-P nom_fichier : Pré-inclure un fichier

Pré-inclut le fichier nom_fichier, donnant l'impression que nom_fichier a été ajouté au début de l'entrée. Peut être utile pour ajouter des macros multi-lignes que -D ne peut pas prendre en charge.

-U macro : Annuler la définition d'une macro

Annule la définition d'une macro sur une seule ligne (peut être une macro intégrée ou une macro définie précédemment dans la ligne de commande avec -D.

EXEMPLES

Pour assembler la syntaxe NASM, source x86 32 bits source.asm dans un fichier ELF source.o, en avertissant sur les étiquettes orphelines :

yasm -f elf32 -Worphan-labels source.asm

Pour assembler la syntaxe NASM AMD64 source x.asm dans un fichier Win64 object.obj :

yasm -f win64 -o object.obj x.asm

Pour assembler la syntaxe NASM déjà préprocessée source x86 y.asm dans un fichier binaire plat y.com :

yasm -f bin -r raw -o y.com y.asm

DIAGNOSTICS

La commande yasm se termine avec 0 en cas de succès, et une valeur non nulle en cas d'erreur.

COMPATIBILITÉ

L'analyseur et le préprocesseur NASM de Yasm, bien qu'ils s'efforcent d'être aussi compatibles que possible avec NASM, présentent quelques incompatibilités en raison de la structure interne différente de YASM.

L'analyseur et le préprocesseur GAS de Yasm manquent un certain nombre de fonctionnalités présentes dans GNU AS.

RESTRICTIONS

Comme les fichiers objets dépendent souvent de l'architecture et de la machine, toutes les combinaisons de formats d'objets, d'architectures et de machines ne sont pas légales ; tenter d'utiliser une combinaison illégale entraînera une erreur.

Il n'y a pas de support pour les cartes de symboles.

VOIR AUSSI

yasm_arch(7), yasm_dbgfmts(7), yasm_objfmts(7), yasm_parsers(7)

Outils associés : as(1), ld(1), nasm(1)

BOGUES

Lorsque vous utilisez l'architecture « x86 », il est très facile de générer du code AMD64 (en utilisant la directive BITS 64) et de générer un fichier objet 32 bits (en omettant de spécifier -m amd64 ou en sélectionnant un format d'objet 64 bits tel que ELF64 sur la ligne de commande).
