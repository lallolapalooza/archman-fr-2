NOM

yaz-log - Gestion des logs dans tous les programmes basés sur YAZ

SYNOPSIS

yaz-XXXX [-v niveau_log,...] [-l fichier_log]

DESCRIPTION

Tous les programmes basés sur YAZ utilisent un sous-système de journalisation commun et devraient prendre en charge des options de ligne de commande communes pour le contrôler. Cette page man les documente.

OPTIONS

-l fichier_log

Spécifie le fichier où le log doit être écrit. Si aucun n'est spécifié, stderr est utilisé. Le log est ajouté à ce fichier. Si le fichier devient trop volumineux, il est silencieusement rotationné : il est renommé en fichier_log.1, fichier_log.2, .., 9 (l'ancien fichier est supprimé), et un nouveau fichier est ouvert. La limite est de 1 Go par défaut, mais peut être définie par le programme. La limite de rotation peut être spécifiée avec l'option -r pour le serveur frontal YAZ (yaz-ztest).

La rotation peut également être implicitement activée en utilisant un nom de fichier qui change pour une date donnée, grâce aux substitutions comme celles données par la fonction strftime(3).

-v niveau_log

Spécifie le niveau de journalisation. L'argument est un ensemble de noms de niveaux de log, séparés par des virgules (sans espace !), éventuellement précédé d'un '-' pour nier ce niveau. La plupart des programmes ont leur propre valeur par défaut, contenant souvent fatal, warn, log, et quelques valeurs spécifiques à l'application. La liste par défaut peut être effacée avec le mot none, ou des bits individuels peuvent être supprimés en les préfixant avec un tiret '-'.

NIVEAUX DE LOG POUR CONTROLER LA JOURNALISATION

Certains niveaux de log contrôlent la façon dont le log est écrit.

flush force le log à être vidé après chaque écriture. Cela peut avoir des implications sérieuses sur les performances et ne doit pas être utilisé en production. D'un autre côté, lors du débogage d'un crash de programme, cela peut être extrêmement utile. L'option debug implique également flush.

notime empêche l'écriture des horodatages. Ceci est destiné aux scripts de test automatiques, qui devraient produire des fichiers de log prévisibles et faciles à comparer.

NIVEAUX DE LOG GENERAUX DANS YAZ MEME

YAZ lui-même utilise les niveaux de log suivants :

fatal pour les erreurs fatales, qui empêchent l'exécution ultérieure du programme.

warn pour les avertissements concernant des choses qui devraient être corrigées.

debug pour le débogage. Ce drapeau peut être utilisé temporairement lors du développement ou du débogage de yaz, ou d'un programme qui utilise yaz. Il est pratiquement obsolète, vous devriez définir et utiliser vos propres niveaux de log (voir ci-dessous).

all active presque tous les niveaux de log codés en dur.

loglevel journalise les informations sur les niveaux de log utilisés par le programme. Chaque fois que le niveau de log est modifié, il liste tous les bits actifs. Chaque fois qu'un module demande ses bits de log, cela est enregistré. Cela peut être utilisé pour avoir une idée des niveaux de log disponibles dans n'importe quel programme qui utilise yaz-log. Lancez le programme avec -v none,loglevel, et effectuez quelques opérations courantes. Une autre façon est de chercher yaz_log_module_level dans le code source, comme ceci :

      find . -name '*.[ch]' -print |
         xargs grep yaz_log_module_level |
         grep '"' |
         cut -d'"' -f2 |
         sort -u

eventl, malloc, nmem, odr sont utilisés en interne pour le débogage de yaz.

NIVEAUX DE LOG POUR LES CLIENTS

zoom journalise les appels à l'API zoom, ce qui peut être utile pour le débogage des applications clientes.

NIVEAUX DE LOG POUR LES SERVEURS

server journalise les fonctions du serveur à un niveau élevé, démarrage, écoute sur un port, etc.

session journalise les sessions individuelles (connexions).

request journalise une ligne pour chaque requête (init, search, etc.).

requestdetail journalise les détails de chaque requête, avant qu'elle ne soit passée au backend, et les résultats reçus de celui-ci.

Chaque programme serveur (zebra, etc.) est censé définir ses propres niveaux de log en plus de ceux-ci. Comme ils dépendent du serveur en question, ils ne peuvent pas être décrits ici. Voir ci-dessus comment les découvrir.

EXEMPLES DE NOM DE FICHIER DE LOG

Un fichier avec le format my_YYYYMMDD.log (où Y, M, D sont les chiffres de l'année, du mois et du jour) est donné comme suit : -l my_%Y%m%d.log . Et comme le nom de fichier dépend du jour, la rotation se produira à minuit.

Un log hebdomadaire peut être spécifié comme -l my_%Y%U.log.
