NOM

YUV4MPEG2 - format de flux vidéo utilisé par les MJPEGtools basés sur les pipes

DESCRIPTION

Beaucoup des MJPEGtools communiquent via des pipes et agissent comme des filtres (ou sources, ou puits). Le format des données vidéo utilisé dans les pipes est appelé "YUV4MPEG", ou plus précisément "YUV4MPEG2". (Le format a été étendu et codifié lors des versions v1.5.x des outils.)

La structure de base est un en-tête de flux suivi d'un nombre illimité d'images. Chaque image elle-même consiste en un en-tête suivi de données vidéo. Les en-têtes sont vaguement lisibles par l'homme en ASCII, mais les données vidéo sont de simples données binaires de taille d'octet.

La distribution MJPEGtools possède une bibliothèque C (libmjpegutils) qui contient des fonctions pour manipuler les flux YUV4MPEG2. Nous vous recommandons d'utiliser cette bibliothèque plutôt que d'écrire votre propre code si possible. Voir le fichier d'en-tête "yuv4mpeg.h" pour une description de ces fonctions.

Objectifs de conception :

o
Facile à analyser à la fois via C ou sh.
o
Extensible ; facile à ajouter de nouveaux paramètres tout en maintenant la compatibilité ascendante.
o
Mise à niveau simple par rapport au format original "YUV4MPEG".

Inconvénients :

o
Les en-têtes d'image n'ont pas de taille constante, donc les flux ne sont pas cherchables.

GRAMMAIRE

La description précise du format de flux YUV4MPEG2 est la suivante :

FLUX se compose de

-
un EN-TETE-FLUX
-
un nombre illimité de IMAGES

EN-TETE-FLUX se compose de

-
chaîne magique "YUV4MPEG2"
-
un nombre illimité de CHAMPS-IDENTIFIES, chacun précédé d'un séparateur ' ' (espace simple)
-
terminateur de ligne '\n' unique

IMAGE se compose de

-
un EN-TETE-IMAGE
-
"longueur" octets de données d'image YCbCr 4:2:0 planaire (Si le flux est entrelacé, alors les deux champs par image sont entrelacés, avec un ordonnancement spatial approprié.)

EN-TETE-IMAGE se compose de

-
chaîne magique "FRAME"
-
un nombre illimité de CHAMPS-IDENTIFIES, chacun précédé d'un séparateur ' ' (espace simple)
-
terminateur de ligne '\n' unique

CHAMP-IDENTIFIE se compose de

-
étiquette de caractère ASCII unique
-
VALEUR (qui ne contient pas d'espaces blancs)

VALEUR se compose de

-
RATIO, ou
-
entier (représentation ASCII base 10), ou
-
caractère ASCII unique, ou
-
chaîne (caractères ASCII multiples)

RATIO se compose de

-
numérateur (entier ASCII base 10)
-
':' (un deux-points)
-
dénominateur (entier ASCII base 10)

Les étiquettes d'en-tête entrent dans trois catégories : optionnelles, requises et avec-valeur-par-défaut. Les étiquettes optionnelles sont complètement optionnelles et peuvent être omises d'un en-tête. Les étiquettes requises doivent être présentes dans un en-tête. Les étiquettes avec-valeur-par-défaut ont une valeur par défaut qui est implicite si l'étiquette n'est pas présente. Indépendamment de ces catégories, certaines étiquettes autorisent une valeur "inconnue" et d'autres non.

Les étiquettes prises en charge pour l'EN-TETE-FLUX :

L[entier] - largeur de l'image en pixels, doit être > 0 (requise)

H[entier] - hauteur de l'image en pixels, doit être > 0 (requise)

C[chaîne] - sous-échantillonnage de la chroma, format des données d'image (avec valeur par défaut)


420jpeg - 4:2:0 avec positionnement JPEG/MPEG-1 (par défaut)
420mpeg2 - 4:2:0 avec positionnement MPEG-2
420paldv - 4:2:0 avec positionnement PAL-DV
411  - 4:1:1, co-situé
422  - 4:2:2, co-situé
444  - 4:4:4 (pas de sous-échantillonnage)
444alpha - 4:4:4 avec un canal alpha
mono  - plan de luminance (Y') uniquement

I[caractère] - spécification d'entrelacement : (avec valeur par défaut)


? - inconnu (par défaut)
p - progressif/aucun
t - champ supérieur d'abord
b - champ inférieur d'abord
m - mode mixte : se référer à l'étiquette 'I' dans l'en-tête de l'image

F[ratio] - fréquence d'images (avec valeur par défaut de 0:0 == inconnu)

A[ratio] - rapport d'aspect d'échantillonnage (avec valeur par défaut de 0:0 == inconnu)

X[chaîne] - 'métadonnées' (optionnel ; non analysé, mais transmis)

Les étiquettes actuellement prises en charge pour l'EN-TETE-IMAGE :

I[chaîne] - structuration et échantillonnage (requis si et seulement si Im est présent dans l'en-tête du flux). La valeur est une chaîne de trois caractères "xyz" qui ont les significations suivantes :


x : présentation de l'image
t - champ supérieur d'abord
T - champ supérieur d'abord et répétition
b - champ inférieur d'abord
B - champ inférieur d'abord et répétition
1 - image progressive unique
2 - image progressive double (répétition)
3 - image progressive triple (répétition)
y : échantillonnage temporel de l'image
p - progressif (champs échantillonnés au même moment)
i - entrelacé (champs échantillonnés à des moments différents)
z : sous-échantillonnage chroma de l'image
p - progressif (sous-échantillonnage sur l'image entière)
i - entrelacé (chaque champ sous-échantillonné indépendamment)
? - inconnu (autorisé uniquement pour le sous-échantillonnage non 4:2:0)

X[chaîne] - 'métadonnées' (optionnel ; non analysé, mais transmis)

Notez qu'une application de filtre doit transmettre fidèlement toutes les étiquettes "X" du pipe d'entrée au pipe de sortie (sauf si elle utilise l'une de ces étiquettes, bien sûr). La bibliothèque fournie fera cela automatiquement si les fonctions y4m_copy_stream_info() et y4m_copy_frame_info() sont utilisées de manière appropriée.

NOTES SUR LES DONNÉES D'IMAGE

Toutes les données d'image sont dans l'espace colorimétrique Y'CbCr CCIR-601, présentées plan par plan dans l'ordre ligne-majeur. Chaque échantillon dans chaque plan a une taille d'octet (8 bits). Lorsque tous les plans sont présents, ils sont transmis dans l'ordre Y', Cb, Cr, potentiellement suivis d'un plan alpha/transparence (pour le format chroma 444alpha). Les données du canal alpha suivent la même plage que le canal de luminance Y' : la transparence totale est à 16 et l'opacité totale est à 235.

Tous les plans Y' et alpha sont constitués de (hauteur X largeur) octets. La taille des plans chroma dépend du mode de sous-échantillonnage :

-
4:4:4 - (hauteur X largeur) octets
-
4:2:2 - (hauteur X largeur) / 2 octets
-
4:1:1 - (hauteur X largeur) / 4 octets
-
4:2:0 - (hauteur X largeur) / 4 octets

NOTES SUR LA STRUCTURATION

Pour plus de détails sur la lecture et l'écriture des fichiers yuv4mpeg, lisez les sources - il existe de nombreux programmes utilitaires, certains simples, d'autres complexes, qui peuvent servir de guides.
