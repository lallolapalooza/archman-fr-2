NOM

tpm2_print(1) - Imprime les structures de données TPM

SYNTAXE

tpm2_print [OPTIONS] [ARGUMENT ou STDIN]

DESCRIPTION

tpm2_print(1) - Décode une structure de données TPM et imprime les éléments contenus dans stdout au format YAML. Un chemin de fichier contenant un objet TPM ou une clé privée TSS2 au format PEM peut être spécifié comme argument de chemin. Lit depuis stdin si non spécifié.

OPTIONS

•
-t, --type:

Requis. Type de structure de données. L'option supporte les arguments suivants :

•
TPMS_ATTEST
•
TPMS_CONTEXT
•
TPM2B_PUBLIC
•
TPMT_PUBLIC
•
TSSPRIVKEY_OBJ
•
ESYS_TR
•
ARGUMENT L'argument de ligne de commande spécifie le chemin des données TPM.
•
-f, --format:

Sélection du format pour le fichier de sortie de la clé publique. `tss' (par défaut) produira un blob binaire conforme à la spécification TPM 2.0. `pem' produira une clé publique encodée PEM compatible avec OpenSSL. `der' produira une clé publique encodée DER compatible avec OpenSSL. `tpmt' produira un blob binaire de la structure TPMT_PUBLIC référencée par les spécifications TPM 2.0.

Format de la clé publique. Ceci ne fonctionne que si l'option --type/-t est définie sur TPM2B_PUBLIC ou TPMT_PUBLIC.

Références

Format des objets de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, *par ordre* :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet temporaire TPM restauré.
•
Si l'argument est une correspondance *préfixe* sur l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par ex. 0x81010013 et utilisé directement.

Formatage de l'Autorisation

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : "Les autorisations utilisent le mot de passe **VIDE** par défaut lorsqu'elles ne sont pas spécifiées".

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe "str:" ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe "hex:", est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou difficiles à utiliser dans un terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe "file:", doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un "-" pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en tant qu'options pouvant être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/mot_de_passe
# pour afficher un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé *session*. Indiquez ensuite le chemin d'un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de politique), ajoutez un "+" suivi d'une chaîne comme décrit dans la section **Mots de passe**.

Exemples

Pour utiliser un fichier de contexte de session appelé *session.ctx*.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé *session.ctx* **ET** envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé *session.ctx* **ET** envoyer la valeur d'authentification *HEX* 0x11223344.

session:session.ctx+hex:11223344

Autorisations de PCR

Vous pouvez satisfaire une politique de PCR en utilisant le préfixe "pcr:" et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur de PCR est documenté dans la section "Spécificateurs de banque PCR".

Le fichier-pcr-brut est un argument **optionnel** qui contient la sortie des contenus bruts des PCR tels que retournés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant *AUTH*.

Configuration du TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour parler directement à un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils autorisent les options hors TPM et prennent donc en charge l'absence d'utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté sous la forme exacte du texte « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou la <configuration-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est par défaut.

TCTI personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et chaque chaîne de valeur sont séparées par un caractère '='.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

tpm2_print(1) — tpm2-tools

NOM

tpm2_print — imprimer des données du TPM.

SYNTAX

tpm2_print [options] [fichier]

DESCRIPTION

tpm2_print est utilisé pour imprimer le contenu des fichiers et des données relatives au TPM. Il est capable de comprendre différents types de structures de données du TPM et de les présenter dans un format lisible.

OPTIONS

•
-S, --session fichier

Spécifie le fichier de session à utiliser.

•
-c, --context fichier

Spécifie le fichier de contexte à utiliser.

•
-u, --usage

Affiche un message d'aide et quitte.

•
-v, --version

Affiche les informations de version et quitte.

•
-t, --type type_donnee

Spécifie le type de données à imprimer. Les types valides sont : TPMS_ATTEST, TPM2B_PUBLIC, TPMT_PUBLIC, ESYS_TR, TSSPRIVKEY_OBJ.

•
-f, --format format_sortie

Spécifie le format de sortie. Les formats valides sont : text (par défaut), pem.

•
-g, --grammar fichier_grammaire

Spécifie un fichier de grammaire pour analyser les données.

•
-e, --encoding encodage

Spécifie l'encodage des données d'entrée. Les encodages valides sont : hex, base64.

•
--tcti tcti

Spécifie le module TCTI (Tabernacle Common Target Interface) à utiliser. Le format de la chaîne de configuration dépend du module TCTI.

•
mssim: Le format est host=...[,port=...]. Exemple: --tcti=mssim:host=localhost,port=2321
•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé=valeur simples séparées par une virgule ,. Chaque clé et chaîne de valeur sont séparées par un signe égal =.
•
Le TCTI abrmd prend en charge deux clés :
1.
bus_name : Le nom du service tabrmd sur le bus (une chaîne).
2.
bus_type : Le type de l'instance dbus (une chaîne) limité à session et system.

Spécifiez le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Imprimer une citation TPM

Configurer une clé pour générer une citation

tpm2_createprimary -C e -c primary.ctx
tpm2_create -C primary.ctx -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx
tpm2_quote -c key.ctx -l 0x0004:16,17,18+0x000b:16,17,18 -g sha256 -m msg.dat

Imprimer une citation

tpm2_print -t TPMS_ATTEST msg.dat

Imprimer un fichier public

tpm2_print -t TPM2B_PUBLIC key.pub

Imprimer un fichier public tpmt

tpm2_readpublic -c key.ctx -f tpmt -o key.tpmt
tpm2_print -t TPMT_PUBLIC key.tpmt

Imprimer un fichier TPM2B_PUBLIC et convertir au format PEM

tpm2 print -t TPM2B_PUBLIC -f pem key.pub

Imprimer la portion publique d'un fichier PEM TSSPRIVKEY et convertir au format PEM

tpm2 print -t TSSPRIVKEY_OBJ tssprivkey.pem
tpm2 print -t TSSPRIVKEY_OBJ tssprivkey.pem -f pem > publickey.pem

Imprimer le nom d'un handle ESYS_TR sérialisé.

Les handles ESYS_TR sérialisés sont retournés par des outils tels que tpm2_evictcontrol avec les options -o et tpm2_readpublic avec l'option -t.

tpm2_createprimary -c primary.ctx
tpm2_evictcontrol -c primary.ctx -o primary.tr
tpm2 print -t ESYS_TR primary.tr

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
