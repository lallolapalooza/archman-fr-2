NOM

tpm2_selftest(1) - Exécute les routines internes d'auto-test du TPM

SYNOPSIS

tpm2_selftest [OPTIONS]

DESCRIPTION

tpm2_selftest(1) - Demande au TPM d'exécuter un auto-test de ses capacités.

L'auto-test peut être exécuté dans deux modes :

•
Test simple - Le TPM testera les fonctions qui nécessitent un test.
•
Test complet - Le TPM testera toutes les fonctions, indépendamment de ce qui a déjà été testé.

Une fois que le TPM reçoit cette requête, il renverra TPM_RC_TESTING pour toute commande nécessitant un test. Si un test échoue, le TPM renverra TPM_RC_FAILURE pour toute commande autre que TPM2_GetTestResult() et TPM2_GetCapability() pendant cette période. Le TPM restera en mode échec jusqu'à la prochaine initialisation du TPM.

OPTIONS

•
-f, --fulltest : Exécute l'auto-test en mode complet.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le pager de manuel pour l'outil, cependant, en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument de l'option “man” est spécifié, cependant, si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pager de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, celles-ci doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les TCTI pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le numéro de fichier et de ligne est imprimé.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration du TCTI

Le TCTI, ou “Transmission Interface”, est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge le fait de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché à l'aide de la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI implémentant l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et chaîne de valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Effectuer un auto-test simple du TPM

tpm2_selftest

Effectuer un auto-test complet du TPM

tpm2_selftest -f

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
