tpm2_getcommandauditdigest(1) Manuel des commandes générales tpm2_getcommandauditdigest(1)

NOM

tpm2_getcommandauditdigest(1) - Récupérer les données d'attestation d'audit de commande du TPM.

SYNTAXE

tpm2_getcommandauditdigest [OPTIONS]

DESCRIPTION

tpm2_getcommandauditdigest(1) - Récupérer les données d'attestation d'audit de commande du TPM. Les données d'attestation incluent le digest d'audit des commandes de l'ensemble définies à l'aide de la commande tpm2_setcommandauditstatus. Les données d'attestation incluent également le digest de la liste des commandes configurées pour l'audit. L'algorithme de digest d'audit est configuré dans tpm2_setcommandauditstatus.

OPTIONS

•
-P, --hierarchy-auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie d'endossement.

•
-c, --key-context=OBJET:

Objet de contexte pour la clé de signature qui signe les données d'attestation.

•
-p, --auth=AUTH:

Spécifie la valeur d'autorisation pour la clé spécifiée par l'option -c.

•
-q, --qualification=CHAINE_HEX_OU_FICHIER:

Données fournies sous forme de chaîne hexadécimale ou de fichier binaire pour qualifier la citation, facultatif. Ceci est généralement utilisé pour ajouter un nonce contre les attaques par rejeu.

•
-s, --signature=FICHIER:

Fichier de sortie de signature, enregistre la signature dans le format spécifié via l'option -f.

•
-m, --message=FICHIER:

Fichier de sortie du message, enregistre le message de citation qui constitue les données signées par le TPM. Ce sont les données d'attestation de digest d'audit de commande.

•
-f, --format=FORMAT:

Sélection du format pour le fichier de sortie de signature.

•
-g, --hash-algorithm:

Algorithme de hachage pour la signature. Par défaut, sha256.

•
--scheme=ALGORITHME:

Le schéma de signature utilisé pour signer le message. Facultatif. Les schémas de signature doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Schémas de signature pris en charge » pour une liste des schémas de signature pris en charge. S'il est spécifié, le schéma de signature doit correspondre au type de clé. S'il est laissé non spécifié, un schéma de signature par défaut pour le type de clé sera utilisé.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement._OBJET_.

Formatage des autorisations

L'autorisation d'utiliser un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations sont par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi des mots de passe avec des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en option peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via stdin:
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'autorisation à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pager de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pager de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des manuels, il faut que les manuels soient installés ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le numéro de fichier et de ligne est affiché.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également effacé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou "Transmission Interface" est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté comme le texte exact de "none".

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<tcti-name>:<tcti-option-config>

Spécifier une chaîne vide pour <tcti-name> ou <tcti-option-config> utilise la valeur par défaut pour cette partie respectivement.

Valeurs par défaut TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et valeur chaîne sont séparées par un caractère '='.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

tpm2_getcommandauditdigest -P ekpass -c key.ctx -p keypass -m att.data -s att.sig

Retours

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
