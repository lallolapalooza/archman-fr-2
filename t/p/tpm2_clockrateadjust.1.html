tpm2_clockrateadjust(1) Manuel des commandes générales tpm2_clockrateadjust(1)

NOM

tpm2_clockrateadjust(1) - Définit la période de cadence de l'horloge sur le TPM.

SYNTAXE

tpm2_clockrateadjust [OPTIONS] ADJUSTEUR

DESCRIPTION

tpm2_clockrateadjust(1) - Ajuste la vitesse à laquelle l'horloge et le temps sont mis à jour sur le TPM afin de mieux correspondre au temps réel. Sans argument, la commande est appelée mais la cadence de l'horloge n'est pas modifiée. Avec un argument, l'outil ajustera la période de l'horloge et du temps. La commande peut soit augmenter, soit diminuer la période de l'horloge via 3 granularités distinctes : grossière, moyenne et fine. Pour spécifier cela, l'argument peut être une chaîne de 1 à 3 caractères composés uniquement de 's' ou de 'f'.

Arguments valides pour l'adjusteur

•
s - ralentit la période de l'horloge d'un cran fin.
•
ss - ralentit la période de l'horloge d'un cran moyen.
•
sss - ralentit la période de l'horloge d'un cran grossier.
•
f - accélère la période de l'horloge d'un cran fin.
•
ff - accélère la période de l'horloge d'un cran moyen.
•
fff - accélère la période de l'horloge d'un cran grossier.

OPTIONS

•
-c, --hierarchy=OBJET:

La hiérarchie à utiliser pour l'autorisation, soit plateforme, soit propriétaire. Par défaut, utilise la hiérarchie propriétaire si non spécifiée.

•
-p, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie spécifiée par l'option -c.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé en tant qu'objet transitoire TPM restauré.
•
Si l'argument correspond en préfixe à l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement. _OBJECT_.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou non amicaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de la session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banques PCR ».

Le fichier-pcr-brut est un argument optionnel contenant la sortie du contenu PCR brut tel que retourné par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR sur sha256 pour les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

spécifiant AUTH.

NOM

tpm2_clockrateadjust — Ajuster le taux d'horloge du TPM

SYNPOSIS

tpm2_clockrateadjust [-h | --help] [-v | --version] [-d | --debug] [-Q | --quiet] [-T TCTI | --tcti TCTI] [-c context-file | --context-file context-file] [-p password | --password password] [-u password | --password-hex password-hex] [-C parent-context | --parent-context parent-context] [-i increment | --increment increment] [-s slowdown | --slowdown slowdown] [-f frequency | --frequency frequency]

DESCRIPTION

La commande tpm2_clockrateadjust ajuste le taux d'horloge du TPM. La commande peut être utilisée pour ralentir ou accélérer le taux d'horloge du TPM. Cette commande est utile pour tester la résilience des applications au niveau des performances du TPM.

Le TPM a deux horloges principales : l'horloge de performance et l'horloge de durée. Le taux d'horloge de ces horloges peut être ajusté. Les ajustements sont effectués par incréments et peuvent être lents ou rapides.

Les outils TPM2 sont des wrappers autour d'une bibliothèque de bas niveau qui permet la communication avec un module de plateforme de confiance (TPM). La bibliothèque elle-même est une interface vers une variété de TCTI (Transmission Interface) qui permettent la communication avec les TPM via différents supports.

En l'absence d'une option -T ou --tcti, le comportement par défaut est d'utiliser le premier TCTI qui est détecté dans la liste suivante : tabrmd, device, mssim. Voir la section TCTI.

En l'absence d'option d'aide, l'aide est générée et renvoyée au stdout.

Pour une utilisation réussie de la fonctionnalité des pages de manuel, les pages de manuel doivent être installées ou sur MANPATH. Voir man(1) pour plus de détails.

OPTIONS

•
-h, --help: Affiche l'aide pour la commande et quitte.
•
-v, --version: Affiche les informations de version pour cet outil, les TCTI pris en charge et quitte.
•
-d, --debug: Active la journalisation de débogage.
•
-Q, --quiet: Supprime la sortie normale de l'outil vers stdout.
•
-T TCTI, --tcti TCTI: La transmission interface TCTI à utiliser. Voir la section TCTI pour plus de détails.
•
-c context-file, --context-file context-file: Les objets de contexte TPM à charger à partir d'un fichier. Cela inclut les autorisations, les handles, les polices, etc. Pour plus d'informations sur le format du fichier de contexte, voir la section « Format de l'objet de contexte » ci-dessous.
•
-p password, --password password: Le mot de passe utilisé pour s'authentifier auprès du TPM. Ce mot de passe est appliqué aux autorisations spécifiées par les options -c, -C ou les options de mot de passe par défaut de l'outil.
•
-u password-hex, --password-hex password-hex: Le mot de passe en représentation hexadécimale utilisé pour s'authentifier auprès du TPM. Ce mot de passe est appliqué aux autorisations spécifiées par les options -c, -C ou les options de mot de passe par défaut de l'outil.
•
-C parent-context, --parent-context parent-context: L'objet de contexte parent du nouveau handle de politique. Ce peut être un handle sous la forme de handle ou context-file. Pour plus d'informations sur le format du fichier de contexte, voir la section « Format de l'objet de contexte » ci-dessous.
•
-i increment, --increment increment: L'incrément spécifié pour les horloges. L'incrément peut être positif ou négatif.
•
-s slowdown, --slowdown slowdown: Les horloges sont ralenties par cette valeur. La valeur peut être comprise entre 0 et 100. Une valeur de 0 désactive le ralentissement.
•
-f frequency, --frequency frequency: Le taux d'horloge est augmenté par cette valeur. La valeur peut être comprise entre 0 et 100. Une valeur de 0 désactive l'accélération.

L'utilisation des options -s et -f est mutuellement exclusive. Vous ne pouvez pas utiliser les deux en même temps.

Le format d'authentification peut être spécifié en tant que chaîne ou en utilisant l'indicateur -u pour utiliser une chaîne hexadécimale. Les mots de passe sont appliqués aux autorisations spécifiées par les options -c, -C ou les options de mot de passe par défaut de l'outil.

Format de l'objet de contexte

Les outils TPM2 peuvent lire et écrire des objets de contexte dans des fichiers. Le format de ces fichiers est une structure JSON qui contient des informations sur les handles, les autorisations, les polices et d'autres métadonnées relatives aux objets TPM.

Voici un exemple de fichier de contexte :

{
  "commandCode" : "0x123",
  "handles" : [
    {
      "handle": "0x81000001",
      "type": "owner"
    }
  ],
  "permissions": {
    "0x81000001": [
      "ownerAuth"
    ]
  },
  "policies": {
    "0x81000001": [
      "policyAuth"
    ]
  }
}

L'utilisation de fichiers de contexte permet de persister l'état des objets TPM entre les exécutions des commandes, ce qui facilite la gestion des sessions et des autorisations.

Formatage de l'autorisation

Les autorisations peuvent être spécifiées dans la ligne de commande ou via un fichier de contexte. Les formats d'autorisation courants incluent les mots de passe de propriétaire, de plateforme et d'éditeur, ainsi que les politiques personnalisées.

Exemples de formatage d'autorisation :

•
Mots de passe : ownerpw, platformpw, endorsementpw.
•
Politiques : Les politiques sont spécifiées sous forme de chaînes de caractères qui décrivent les conditions d'accès à un objet TPM.

Configuration du TCTI

Le TCTI ou « Transmission Interface » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lorsque l'on parle directement à un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et utiliseront le PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et chaîne de valeur sont séparées par un caractère '='.
•
abrmd TCTI prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Régler l'horloge

Ralentir l'horloge d'un incrément moyen en utilisant le mot de passe propriétaire.

tpm2_clockrateadjust -p ownerpw ss

Accélérer l'horloge d'un incrément rapide en utilisant le mot de passe plateforme.

tpm2_clockrateadjust -c p -p platformpw fff

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
