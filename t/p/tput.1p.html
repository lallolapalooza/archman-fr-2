TPUT(1P) Manuel du programmeur POSIX TPUT(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

tput — modifier les caractéristiques du terminal

SYNTAXE

tput [-T type] opérande...

DESCRIPTION

L'utilitaire tput affiche des informations dépendantes du terminal. La manière dont ces informations sont récupérées n'est pas spécifiée. Les informations affichées effacent l'écran du terminal, initialisent le terminal de l'utilisateur ou réinitialisent le terminal de l'utilisateur, en fonction de l'opérande donné. Les conséquences exactes de l'affichage de ces informations ne sont pas spécifiées.

OPTIONS

L'utilitaire tput doit être conforme aux directives de syntaxe des utilitaires du volume Des définitions de base de POSIX.1‐2017, Section 12.2.

L'option suivante doit être prise en charge :

-T type
Indique le type de terminal. Si cette option n'est pas fournie et que la variable TERM n'est pas définie ou est nulle, un type de terminal par défaut non spécifié sera utilisé. Le réglage de type aura la priorité sur la valeur dans TERM.

OPERANDES

Les chaînes suivantes doivent être prises en charge comme opérandes par l'implémentation dans la locale POSIX :

clear
Affiche la séquence d'effacement de l'écran.
init
Affiche la séquence qui initialise le terminal de l'utilisateur d'une manière définie par l'implémentation.
reset
Affiche la séquence qui réinitialise le terminal de l'utilisateur d'une manière définie par l'implémentation.

Si un terminal ne prend pas en charge l'une des opérations décrites par ces opérandes, cela ne sera pas considéré comme une condition d'erreur.

ENTRÉE STANDARD

Non utilisée.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de tput :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou sont nulles. (Voir le volume Des définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si elle est définie sur une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en tant que caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TERM
Détermine le type de terminal. Si cette variable n'est pas définie ou est nulle, et si l'option -T n'est pas spécifiée, un type de terminal par défaut non spécifié sera utilisé.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Si la sortie standard est un périphérique terminal, elle peut être utilisée pour écrire la séquence appropriée pour effacer l'écran ou réinitialiser/initialiser le terminal. Si la sortie standard n'est pas un périphérique terminal, des résultats indéfinis se produisent.

ERREUR STANDARD

La sortie d'erreur standard ne doit être utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
La chaîne demandée a été écrite avec succès.
 1
Non spécifié.
 2
Erreur d'utilisation.
 3
Aucune information n'est disponible sur le type de terminal spécifié.
 4
L'opérande spécifié est invalide.
>4
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Si l'un des opérandes n'est pas disponible pour le terminal, tput continue le traitement des opérandes restants.

Les sections suivantes sont informatives.

USAGE APPLICATIF

La différence entre réinitialiser et initialiser un terminal est laissée non spécifiée, car elle varie considérablement selon les types de matériel. En général, la réinitialisation est une action plus sévère.

Certains terminaux utilisent des caractères de contrôle pour effectuer les fonctions indiquées, et sur de tels terminaux, il peut être judicieux d'utiliser tput pour stocker les chaînes d'initialisation dans un fichier ou une variable d'environnement pour une utilisation ultérieure. Cependant, comme d'autres terminaux peuvent s'appuyer sur des appels système pour effectuer ce travail, la sortie standard ne peut pas être utilisée de manière portable, comme les constructions non portables suivantes :

ClearVar=`tput clear`
tput reset | mailx -s "Wake Up" ddg

EXEMPLES

1.
Initialise le terminal en fonction du type de terminal dans la variable d'environnement TERM. Cette commande peut être incluse dans un fichier .profile.
tput init
2.
Réinitialise un terminal 450.
tput -T 450 reset

RATIONALE

La liste des opérandes a été réduite à un minimum pour les raisons suivantes :

*
Les seules fonctionnalités choisies étaient celles susceptibles d'être utilisées par des utilisateurs humains interagissant avec un terminal.
*
La spécification de l'ensemble complet de terminfo n'était pas considérée comme souhaitable, mais les développeurs du standard n'ont pas voulu sélectionner parmi les opérandes.
*
Ce volume de POSIX.1‐2017 ne tente pas de fournir aux applications des capacités de manipulation de terminal sophistiquées, car cela sort de son champ d'application assigné et recoupe les responsabilités d'autres organismes de normalisation.

La différence entre la réinitialisation et l'initialisation d'un terminal est laissée non spécifiée, car cela varie considérablement selon les types de matériel. En général, la réinitialisation est une action plus sévère.

Le statut de sortie de 1 est historiquement réservé pour savoir si un opérande booléen n'est pas défini. Bien que les opérandes aient été réduits au minimum, le statut de sortie de 1 devrait toujours être réservé aux opérandes booléens, pour les sites qui souhaitent les prendre en charge.
