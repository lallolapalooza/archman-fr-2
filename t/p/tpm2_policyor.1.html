tpm2_policyor(1) Manuel des commandes générales tpm2_policyor(1)

NOM

tpm2_policyor(1) - fusionne logiquement deux politiques.

SYNTAXE

tpm2_policyor [OPTIONS]

DESCRIPTION

tpm2_policyor(1) - Génère un événement policy_or avec le TPM. Il s'attend à ce qu'une session soit déjà établie via tpm2_startauthsession(1). Si la session d'entrée est une session d'essai cet outil génère un résumé de politique qui compose deux ou plusieurs résumés de politique d'entrée de sorte que le résumé de politique résultant nécessite qu'au moins un des événements de politique soit vrai. Si la session d'entrée est une vraie session de politique tpm2_policyor(1) authentifie l'objet avec succès si au moins un des événements de politique est vrai.

OPTIONS

•
-L, --policy=FICHIER:

Fichier pour sauvegarder le résumé de politique composé.

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
ARGUMENT L'argument de ligne de commande spécifie la liste des fichiers pour les résumés de politique qui doivent être composés, résultant en des politiques individuelles ajoutées au résumé de politique final qui peut authentifier l'objet. La liste commence par l'algorithme de hachage du résumé de politique. Exemple sha256:policy1,policy2
•
-l, --policy-list=LISTE_FICHIERS_POLITIQUE:

Cette option est DÉPRÉCIÉE mais conservée pour la compatibilité ascendante. Utilisez plutôt la méthode des arguments. NOTE: Lorsque -l et un argument sont spécifiés, cela équivaut à tout spécifier en une seule fois. Par exemple : tpm2_policyor -l sha256:file1 sha256:file2 est identique à tpm2_policyor sha256:file1,file2.

Références

OPTIONS COMMUNES

C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Configuration TCTI

Le TCTI ou “Interface de Transmission” est le mécanisme de communication avec le TPM. Les TCTIs peuvent être changés pour la communication avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour communiquer directement avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou <configuration-options-tcti> résulte en l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur de chaîne sont séparées par un caractère `=`.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

tpm2_policyor(1) — tpm2-tools documentation

NAME

tpm2_policyor — Creates a policy OR authorization policy

SYNOPSIS

tpm2_policyor [OPTIONS] [POLICY_FILES]

DESCRIPTION

The tpm2_policyor command allows the user to create a policy session that is satisfied if any of the specified policies are satisfied. The policies are specified as a comma separated list of policy digest hashes. The policy digest hashes are obtained from previous policy command invocations. The command itself does not take any policy digest hashes as input.

The command expects the policy session to be already established via tpm2_startauthsession(1).

The command requires one of the following:

  • Direct device access
  • Extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.

OPTIONS

•
-S session
The path to the session context file. This session context is created by tpm2_startauthsession(1).

The following options are applicable to sessions created with tpm2_startauthsession using the --policy-session option:

•
-L policy
The path to the policy digest file. This file will contain the policy digest computed by this command. The policy digest can be used in subsequent calls to tpm2_policyor, tpm2_policyand, tpm2_policysecret, etc. The policy digest file is created using the digest algorithm specified in the policy session context.

COMMON OPTIONS

••
-h, --help
Print the help information.
••
-v, --verbose
Enables verbosity.
••
-z, --hex
Policy session is in hex format.

TCTI Configuration

The TPM communication is configured using the generic TCTI options. This is a global option and can be specified at any point in the command line.

The default TCTI is tabrmd.

--tcti=cmdline

The following TCTIs are available:

cmdline
The TCTI is specified as a command line argument.
socket
The TCTI is specified as a command line argument in the following format:
--tcti=socket:host=HOSTNAME,port=PORT
Where HOSTNAME is the hostname or IP address of the TPM device, and PORT is the port number on which the TPM device is listening.
லாம்d
The TCTI is specified as a command line argument.
--tcti=லாம்d:host=HOSTNAME,port=PORT
Where HOSTNAME is the hostname or IP address of the TPM device, and PORT is the port number on which the TPM device is listening.
For லாம்d TCTI, the default port is 2321.
tabrmd
The TCTI is specified as a command line argument.
--tcti=tabrmd:host=HOSTNAME,port=PORT
Where HOSTNAME is the hostname or IP address of the TPM device, and PORT is the port number on which the TPM device is listening.
For tabrmd TCTI, the default port is 2321.
--tcti=tabrmd:bus_name=com.example.FooBar
--tcti=tabrmd:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create an authorization policy for a sealing object that compounds a pcr policy and a policypassword in an OR fashion and show satisfying either policies could unseal the secret.

Create policypcr as first truth value for compounding the policies

tpm2_startauthsession -S session.ctx
tpm2_policypcr -S session.ctx -L policy.pcr -l sha256:0,1,2,3
tpm2_flushcontext session.ctx

Create policypassword as second truth value for compounding the policies

tpm2_startauthsession -S session.ctx
tpm2_policypassword -S session.ctx -L policy.pass
tpm2_flushcontext session.ctx

Compound the two policies in an OR fashion with tpm2_policyor command

tpm2_startauthsession -S session.ctx
tpm2_policyor -S session.ctx -L policy.or sha256:policy.pass,policy.pcr
tpm2_flushcontext session.ctx

Create a sealing object and attach the auth policy from tpm2_policyor command

tpm2_createprimary -c prim.ctx -Q
echo "secret" | tpm2_create -C prim.ctx -c key.ctx -u key.pub -r key.priv \
-L policy.or -i-

Satisfy auth policy using password and unseal the secret

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypassword -S session.ctx
tpm2_policyor -S session.ctx sha256:policy.pass,policy.pcr
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Satisfy auth policy using pcr and unseal the secret

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypcr -S session.ctx -l sha256:0,1,2,3
tpm2_policyor -S session.ctx sha256:policy.pass,policy.pcr
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
