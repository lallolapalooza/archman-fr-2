tpm2_nvcertify(1) Manuel des commandes générales tpm2_nvcertify(1)

NOM

tpm2_nvcertify(1) - Fournit une attestation du contenu d'un index NV.

SYNOPSIS

tpm2_nvcertify [OPTIONS] [ARGUMENTS]

DESCRIPTION

tpm2_nvcertify(1) - Fournit une attestation du contenu d'un index NV. NOTE : Dans le cadre de la sortie d'attestation, le contenu de l'index NV est révélé.

OPTIONS

Ces options contrôlent la certification :

•
-C, --signingkey-context=OBJET:

L'objet clé qui signe la structure d'attestation.

•
-P, --signingkey-auth=AUTH:

La valeur d'autorisation fournie pour l'objet spécifié avec -C.

•
-c, --nvauthobj-context=OBJET:

L'objet qui est le handle d'autorisation pour l'objet NV. C'est soit le handle de l'index NV lui-même, soit le handle de la hiérarchie de plateforme/propriétaire. S'il n'est pas spécifié, il prend par défaut le handle de l'index NV.

•
-p, --nvauthobj-auth=AUTH:

La valeur d'autorisation fournie pour l'objet spécifié avec -c.

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage à utiliser pour la génération de signature.

•
-s, --scheme=ALGORITHME:

Le schéma de signature utilisé pour signer les données d'attestation.

•
-f, --format=FORMAT:

Sélection du format pour le fichier de sortie de signature.

•
-o, --signature=FICHIER:

Nom du fichier de sortie pour les données de signature.

•
-q, --qualification=FICHIER_OU_CHAINE_HEX:

Optionnel, les données de qualificatif de politique que le signataire peut choisir d'inclure dans la signature. Peut être une chaîne hexadécimale ou un chemin.

•
--size=NOMBRE_NATUREL:

Spécifie la taille des données à lire en octets, en commençant à 0 si le décalage n'est pas spécifié. Si non spécifié, la taille des données telle que rapportée par la partie publique de l'index sera utilisée.

•
--offset=NOMBRE_NATUREL:

Le décalage dans l'index NV à partir duquel commencer la lecture.

•
–attestation=FICHIER:

Les données d'attestation du type TPM2_CREATION_INFO signées avec la clé de signature.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash à moins qu'un rphash ne soit également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. C'est communément appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Peut être utilisée pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
-n, --name=FICHIER:

Le nom de l'index NV qui doit être fourni lors du calcul du cpHash sans réellement envoyer la commande au TPM.

•
-signer-name=FICHIER:

Le nom de la clé de signature qui doit être fourni lors du calcul du cpHash sans réellement envoyer la commande au TPM.

•
ARGUMENT l'argument de ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'objet contexte

Le type d'un objet contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument est une correspondance de *préfixe* avec l'un des éléments suivants :
•
owner: la hiérarchie du propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle du lockout
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par ex. 0x81010013 et utilisé directement._OBJET_.

Formatage des autorisations

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations prennent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi des mots de passe avec des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser l'entrée standard. Stocker les mots de passe dans des fichiers évite les fuites d'informations ; les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour afficher un mot de passe via stdin :
echo mdp | tpm2_tool -p file:-
# pour utiliser une chaîne here de bash via stdin :
tpm2_tool -p file:- <<< mdp

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session requ

ira une valeur d'authentification à envoyer avec le descripteur de session (par exemple, mot de passe de politique), puis ajoutez un '+' et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session nommé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le minilangage PCR. Le minilangage PCR est le suivant : <pcr-spec>=<fichier-pcr-brut>

La spécification PCR est documentée dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à remplir dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Ci-dessous se trouve le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de Type

Cette partie du spécificateur d'algorithme complexe est requise. Le schéma et les détails symétriques restants seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe Elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de Schéma

Ensuite, il y a un champ facultatif, il peut être ignoré.

Les schémas sont généralement des Schémas de Signature ou des Schémas de Chiffrement Asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il prend par défaut sha256. Certains ne prennent aucun argument, et certains en prennent plusieurs.

OPTIONS

The specific options that are available for the tools vary based on the tool. However, there are a set of common options that are available for most of the tools that are listed below.

To see the full list of options available for a specific tool, you can use the -h or --help option when invoking the tool. For example, to see the options for tpm2_nvread, you would type:

tpm2_nvread -h

Context Object Format

Many tools will operate on objects that are stored in TPM context files. These files are typically generated by other tools and contain the necessary information for the TPM to locate and utilize the object. The format of these context objects are not standardized and may vary between different TPM software stacks. Therefore, it is recommended to only use context files generated by the same software stack that you are using to consume them.

Authorization Formatting

Authorization for TPM objects can be specified in several ways:

•
-P, --auth=Password: Specifies the authorization value for the object. This is typically a hex string or a plain text password. For example, to specify the password `password`, you would use -P password.
•
-L, --policy=PolicyDigest: Specifies a policy digest that will be used for authorization. This is a hex string representing the policy digest.
•
-s, --password-file=File: Specifies a file that contains the authorization value. This is useful for storing sensitive authorization values securely.

Algorithm Specifiers

Many tools that operate on cryptographic algorithms will accept algorithm specifiers. These specifiers can be in the form of:

•
A case-insensitive string representing the algorithm name (e.g., `sha256`, `rsa`, `ecc`).
•
A hex string representing the algorithm identifier (e.g., `0x0004` for `sha256`).

The list of supported algorithms and their corresponding identifiers can be found in the TPM specifications or by using the tool's help option.

Signature Format Specifiers

When dealing with signatures, the format of the signature can be specified using the following options:

•
-f, --format=Format: Specifies the output format for the signature. Common formats include:
•
binary: Raw binary signature.
•
pem: PEM encoded signature.
•
plain: Plain text representation of the signature.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
