tpm2_loadexternal(1) Manuel des commandes générales tpm2_loadexternal(1)

NOM

tpm2_loadexternal(1) - Charge un objet externe dans le TPM.

SYNOPSIS

tpm2_loadexternal [OPTIONS]

DESCRIPTION

tpm2_loadexternal(1) - Cette commande charge un objet externe dans le TPM, en renonçant aux protections du TPM. C'est-à-dire que le matériel de la clé n'est pas protégé par la graine de l'objet parent. Elle peut également être utilisée pour charger des clés privées TSS2 au format pem. La commande permet de charger seulement la partie publique d'un objet ou les parties publique et privée d'un objet. Pour les clés privées TSS2, seule la partie publique de la clé est chargée.

L'outil affiche le nom de l'objet chargé dans un format de dictionnaire YAML avec la clé name, où la valeur de cette clé est le nom de l'objet au format hexadécimal, par exemple :

name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

Elle enregistre également un fichier de contexte pour les interactions futures avec l'objet.

OPTIONS

•
-C, --hierarchy=OBJET:

Hiérarchie à utiliser pour le ticket, facultatif. Par défaut n, null. Les options supportées sont :

•
o pour la hiérarchie owner.
•
p pour la hiérarchie platform.
•
e pour la hiérarchie endorsement.
•
n pour la hiérarchie null.
•
-G, --key-algorithm=ALGORITHME:

L'algorithme utilisé par la clé à importer. Supporte :

•
aes - Clé AES 128, 192 ou 256.
•
rsa - Clé RSA 1024 ou 2048.
•
ecc - Clé publique et privée ECC NIST P192, P224, P256, P384 ou P521.
•
-u, --public=FICHIER:

La partie publique de l'objet, cela peut être l'un des formats de fichier suivants :

•
TSS - Le format TSS/TPM. Par exemple, issu de l'option -u de la commande tpm2_create(1).
•
RSA - Formats OSSL PEM. Par exemple, public.pem provenant de la commande openssl rsa -in private.pem -out public.pem -pubout
•
ECC - Formats OSSL PEM. Par exemple, public.pem provenant de la commande openssl ec -in private.ecc.pem -out public.ecc.pem -pubout
•
-r, --private=FICHIER:

La partie sensible de l'objet, facultatif. Si vous souhaitez utiliser la partie privée d'une clé, elle doit être spécifiée. Comme l'option -u, cette commande accepte des fichiers dans le format suivant :

•
RSA - Formats OSSL PEM. Par exemple, private.pem provenant de la commande openssl genrsa -out private.pem 2048 Puisqu'une clé publique RSA peut être dérivée du fichier PEM privé, il n'est pas nécessaire de spécifier -u pour la partie publique.
•
Formats PEM de clé privée TSS2.

Note : La partie privée ne respecte pas les formats TSS car il est impossible d'obtenir une sortie TPM2B_SENSITIVE d'une commande précédente. Ce sont toujours des blobs TPM2B_PRIVATE protégés par le TPM.

•
-p, --auth=AUTH:

La valeur d'autorisation pour la clé, facultatif.

•
-L, --policy=FICHIER ou CHAÎNE_HEX:

Le fichier de politique d'entrée ou la chaîne hexadécimale, facultatif. Un fichier ou une chaîne hexadécimale contenant le hachage d'une politique dérivée de tpm2_createpolicy ou d'une autre source générant un digest de politique.

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage pour générer le nom des objets. Ceci est facultatif et utilise sha256 par défaut lorsqu'il n'est pas spécifié. Cependant, load external supporte un algorithme de nom null. Dans ce cas, aucune vérification de liaison cryptographique entre les parties publique et privée n'est effectuée.

•
-a, --attributes=ATTRIBUTS:

Les attributs de l'objet, facultatif. La valeur par défaut pour les objets créés est : TPMA_OBJECT_SIGN_ENCRYPT|TPMA_OBJECT_DECRYPT. Facultativement, si -p est spécifié ou si ni -p ni -L n'est spécifié, alors TPMA_OBJECT_USERWITHAUTH est ajouté à l'ensemble d'attributs par défaut.

Note : Si vous spécifiez des attributs, le TPM rejettera certains attributs comme TPMA_OBJECT_FIXEDTPM, car ces garanties ne peuvent pas être faites.

•
-c, --key-context=FICHIER

Le nom du fichier pour enregistrer le contexte de l'objet, requis.

•
-n, --name=FICHIER:

Un fichier facultatif pour enregistrer le nom de l'objet, qui est au format binaire de hachage. La taille du hachage est basée sur l'algorithme de nom ou l'option -g.

•
--passin=OSSL_PEM_FILE_PASSWORD

Un mot de passe facultatif pour un fichier d'entrée fourni par Open SSL (OSSL). Il reflète l'option -passin d'OSSL et est connu pour supporter les formats pass, file, env, fd et plain password d'openssl. (voir man(1) openssl) pour plus d'informations.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner : la hiérarchie owner
•
platform : la hiérarchie platform
•
endorsement : la hiérarchie endorsement
•
lockout : l'objet persistant de contrôle lockout
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013, et utilisé directement.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées. »

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Passwords

The password argument supports different password sources. The default mechanism is to interpret the argument as a hex-encoded string. This converts a hexidecimal form into a byte array form, thus allowing passwords with non-printable and/or terminal un-friendly characters.

Example

hex:1122334455667788

File

A file based password, specified be prefix “file:” should be the path of a file containing the password to be read by the tool or a “-” to use stdin. Storing passwords in files prevents information leakage, passwords passed as options can be read from the process list or common shell history features.

Examples

# to use stdin and be prompted
file:-
# to use a file from a path
file:path/to/password/file
# to echo a password via stdin:
echo foobar | tpm2_tool -p file:-
# to use a bash here-string via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

When using a policy session to authorize the use of an object, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Complex Specifiers

Objects, when specified for creation by the TPM, have numerous algorithms to populate in the public data. Things like type, scheme and asymmetric details, key size, etc. Below is the general format for specifying this data: <type>:<scheme>:<symmetric-details>

Type Specifiers

This portion of the complex algorithm specifier is required. The remaining scheme and symmetric details will default based on the type specified and the type of the object being created.

•
aes - Default AES: aes128
•
aes128<mode> - 128 bit AES with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
aes192<mode> - Same as aes128<mode>, except for a 192 bit key size.
•
aes256<mode> - Same as aes128<mode>, except for a 256 bit key size.
•
sm4 - Default SM4: sm4128
•
sm4128 or sm4_128 <mode> - 128 bit SM4 with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
ecc - Elliptical Curve, defaults to ecc256.
•
ecc192 or ecc_nist_p192 - 192 bit ECC NIST curve
•
ecc224 or ecc_nist_p224 - 224 bit ECC NIST curve
•
ecc256 or ecc_nist_p256 - 256 bit ECC NIST curve
•
ecc384 or ecc_nist_p384 - 384 bit ECC NIST curve
•
ecc521 or ecc_nist_p521 - 521 bit ECC NIST curve
•
ecc_sm2 or ecc_sm2_p256 - 256 bit SM2 curve
•
rsa - Default RSA: rsa2048
•
rsa1024 - RSA with 1024 bit keysize.
•
rsa2048 - RSA with 2048 bit keysize.
•
rsa3072 - RSA with 3072 bit keysize.
•
rsa4096 - RSA with 4096 bit keysize.

Scheme Specifiers

Next, is an optional field, it can be skipped.

Schemes are usually Signing Schemes or Asymmetric Encryption Schemes. Most signing schemes take a hash algorithm directly following the signing scheme. If the hash algorithm is missing, it defaults to sha256. Some take no arguments, and some take multiple arguments.

Hash Optional Scheme Specifiers

These scheme specifiers are followed by a dash and a valid hash algorithm, For example: oaep-sha256.

•
oaep
•
ecdh
•

•
rsapss
•
ecdsa

ecschnorr

Multiple Option Scheme Specifiers

This scheme specifier is followed by a count (max size UINT16) then followed by a dash(-) and a valid hash algorithm. * ecdaa For example, ecdaa4-sha256. If no count is specified, it defaults to 4.

No Option Scheme Specifiers

This scheme specifier takes NO arguments. * rsaes

Symmetric Details Specifiers

This field is optional, and defaults based on the type of object being created and it’s attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compte de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHM.

Attributs d’objet

Les attributs d'objet sont utilisés pour contrôler diverses propriétés des objets créés. Lorsqu'ils sont spécifiés comme une option, le masque de bits bruts ou les « noms conviviaux » peuvent être utilisés. Les valeurs se trouvent dans le tableau 31, partie 2, de la spécification TPM2.0, qui peut être consultée ici :

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Les noms conviviaux sont calculés en prenant le champ nom du tableau 31 et en supprimant le préfixe TPMA_OBJECT_ et en mettant le résultat en minuscules. Ainsi, TPMA_OBJECT_FIXEDTPM devient fixedtpm. Les noms conviviaux peuvent être joints en utilisant l'opérateur OU binaire « | ».

Par exemple, pour définir les champs TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA et TPMA_OBJECT_SIGN_ENCRYPT, l'argument serait :

fixedtpm|noda|sign spécifiant les attributs d'objet ATTRIBUTES.

OPTIONS COMMUNES

Cet ensemble d'options est commun à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le pagineur man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument de l'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pagineur man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité de pages de manuel, il faut que les pages de manuel soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tcti pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque vous utilisez cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active le déchargement automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également déchargé. Le déchargement automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils autorisent les options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur utilisation sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<tcti-name>:<tcti-option-config>

Spécifier une chaîne vide pour <tcti-name> ou <tcti-option-config> entraîne l'utilisation de la valeur par défaut pour cette partie respective.

Valeurs par défaut TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

TCTI personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cet ensemble d'options est utilisé pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI= « device:/dev/tpm0 »

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI= « mssim:host=localhost,port=2321 »

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

NOTES

•
Si la hiérarchie est null ou si l'algorithme de hachage du nom est null, les tickets produits à l'aide de l'objet seront NUL.
•
Si la partie privée d'un objet est spécifiée, la hiérarchie doit être null ou le TPM refusera de la charger.

EXEMPLES

Charger une clé publique générée par TPM dans la hiérarchie owner

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -u pub.dat -r priv.dat
tpm2_loadexternal -C o -u pub.dat -c pub.ctx
name: 000b9be4d7c6193a57e1bfc86a42a6b03856a91d2f9e77c6cbdb796a783d52d4b3b9

Charger une clé publique RSA dans la hiérarchie owner

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -out public.pem -outform PEM -pubout
tpm2_loadexternal -C o -Grsa -u public.pem -c key.ctx
name: 000b7b91d304d16995d42792b57d0fb25df7abe5fdd8afe9950730e00dc5b934ddbc

Charger une paire de clés RSA dans la hiérarchie null

openssl genrsa -out private.pem 2048
tpm2_loadexternal -C n -Grsa -r private.pem -c key.ctx
name: 000b635ea220b6c62ec1d02343859dd203c8ac5dad82ebc5b124e407d2502f88691f

Charger une clé AES dans la hiérarchie null

dd if=/dev/urandom of=sym.key bs=1 count=16
tpm2_loadexternal -C n -Gaes -r sym.key -c key.ctx
name: 000bfc4d8dd7e4f921bcc9dca4b04f49564243cd9def129a3740002bfd4b9e966d34

Charger une clé privée TSS2 dans la hiérarchie null

tpm2_loadexternal -r tss_privkey.pem -c tss_privkey.ctx
name: 000bc5a216702aca9ba226af1214c50dc4dc33ce6269677aa581ea6d9eec7f27000d

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
