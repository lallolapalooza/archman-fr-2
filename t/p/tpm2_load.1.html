tpm2_load(1) Manuel des commandes générales tpm2_load(1)

NOM

tpm2_load(1) - Charger un objet dans le TPM.

SYNTAXE

tpm2_load [OPTIONS]

DESCRIPTION

tpm2_load(1) - Charge les parties privée et publique d'un objet dans le TPM ou charge l'objet au format PEM TSS2-Private-Key. Cela peut être fait en spécifiant la partie privée ainsi que la partie publique ou via un fichier pem en utilisant l'option -r.

L'outil affiche le nom de l'objet chargé dans un dictionnaire YAML avec la clé name, où la valeur pour cette clé est le nom de l'objet au format hexadécimal, par exemple :

name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

Il sauvegarde également un fichier de contexte pour les interactions futures avec l'objet.

NOTE : Les parties privée et publique de la clé TPM doivent être spécifiées. L'exception est si un objet PEM au format TSS2-Private-Key doit être chargé, auquel cas le public n'a pas besoin d'être spécifié.

OPTIONS

•
-C, --parent-context=OBJET:

L'objet parent.

•
-P, --auth=AUTH:

La valeur d'autorisation de l'objet parent spécifié par -C.

•
-u, --public=FICHIER:

Un fichier contenant la partie publique de l'objet.

•
-r, --private=FICHIER:

Un fichier contenant la partie sensible de l'objet.

•
-n, --name=FICHIER:

Un fichier optionnel pour sauvegarder la structure de nom de l'objet.

•
-c, --key-context=FICHIER:

Le nom du fichier du contexte d'objet sauvegardé, requis.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas la commande, il renverra simplement un cpHash.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe parmi :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie plateforme
•
endorsement : la hiérarchie d'approbation
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage des autorisations

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes suivantes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: » est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations ; les mots de passe passés comme options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour écho un mot de passe via stdin:
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Ensuite, indiquez un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADECIMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel contenant la sortie du contenu PCR brut tel que retourné par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Configuration TCTI

Le TCTI ou "Interface de Transmission" est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec les TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de "none".

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTI susmentionnés est le défaut.

TCTI Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne de clé et de valeur est séparée par un caractère `=´.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Configuration

Pour charger un objet, vous devez d'abord créer un objet sous un objet primaire. La première étape consiste donc à créer l'objet primaire.

tpm2_createprimary -c primary.ctx

L'étape 2 consiste à créer un objet sous l'objet primaire.

tpm2_create -C primary.ctx -u key.pub -r key.priv

Ceci crée les parties privée et publique de l'objet TPM. Avec ces parties d'objet, il est maintenant possible de charger cet objet dans le TPM pour une utilisation ultérieure.

Chargement d'un Objet dans le TPM

La dernière étape consiste à charger les parties publique et privée de l'objet dans le TPM.

tpm2_load  -C primary.ctx -u key.pub -r key.priv -c key.ctx
name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

Retours

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
