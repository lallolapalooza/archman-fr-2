tpm2_policyrestart(1) Manuel des commandes générales tpm2_policyrestart(1)

NOM

tpm2_policyrestart(1) - Redémarre une session existante avec le TPM.

SYNTAXE

tpm2_policyrestart [OPTIONS]

DESCRIPTION

tpm2_policyrestart(1) - Redémarre une session avec le TPM pour la ramener à son état initial. Ceci est utile lorsque le TPM renvoie le code d'erreur TPM_RC_PCR_CHANGED (0x00000128) lors de l'utilisation d'une session de politique PCR.

Ceci sera renvoyé si un état PCR affectant la politique est modifié pendant la session. On pourrait redémarrer la session et réessayer, cependant, l'état PCR devrait toujours satisfaire la politique.

OPTIONS

•
-S, --session=FICHIER:

Optionnel, Un fichier de session provenant de l'option -S de tpm2_startauthsession(1). Cette session est utilisée à la place du démarrage d'une session et de l'utilisation des options de politique PCR.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents médias.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge le fait de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou <config-options-tcti> aboutit à l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs personnalisés

Tout TCTI implémentant l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=.
•
TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Démarrer une session de policy et la redémarrer, déverrouiller certaines données.

# créer une politique et la lier à un objet
tpm2_startauthsession -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3" -L policy.dat
tpm2_createprimary -c primary.ctx
tpm2_create -Cprimary.ctx -u key.pub -r key.priv -L policy.dat -i- <<< "secret"
tpm2_load -C primary.ctx -c key.ctx -u key.pub -r key.priv
tpm2_flushcontext session.dat
# satisfaire la politique et utiliser l'objet
tpm2_startauthsession --policy -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3"
# l'événement PCR se produit ici, provoquant l'échec de l'unseal
tpm2_pcrevent 0 <<< "event data"
tpm2_unseal -psession:session.dat -c key.ct
ERREUR : Esys_Unseal(0x128) - tpm:error(2.0) : Les PCR ont changé depuis la vérification
# Effacer le résumé de la politique à l'état initial, noter que l'accès à l'objet n'est plus autorisé par
# la politique, donc policyor serait utile ici.
tpm2_policyrestart -S session.dat

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.

Limitations

Il attend qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des conditions suivantes :

•
accès direct au périphérique
•
prise en charge de sessions étendues avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commandes.
