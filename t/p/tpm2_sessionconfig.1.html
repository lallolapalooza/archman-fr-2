NOM

tpm2_sessionconfig(1) - Configure les attributs de session et affiche les informations de session à partir d'un fichier de session.

SYNTAXE

tpm2_sessionconfig [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_sessionconfig(1) - Configure les attributs de session et affiche les informations de session à partir d'un fichier de session.

L'outil fonctionne dans l'un des deux modes : 1. Configurer/modifier les attributs de session. 2. Afficher les informations de session. C'est le comportement par défaut.

OPTIONS

•
--enable-continuesession:

Active continueSession dans les attributs de session.

•
--disable-continuesession

Désactive continuesession dans les attributs de session.

•
--enable-auditexclusive

Active auditexclusive dans les attributs de session.

•
--disable-auditexclusive

Désactive auditexclusive dans les attributs de session.

•
--enable-auditreset

Active auditreset dans les attributs de session.

•
--disable-auditreset

Désactive auditreset dans les attributs de session.

•
--enable-decrypt

Active decrypt dans les attributs de session.

•
--disable-decrypt

Désactive decrypt dans les attributs de session.

•
--enable-encrypt

Active encrypt dans les attributs de session.

•
--disable-encrypt

Désactive encrypt dans les attributs de session.

•
--enable-audit

Active audit dans les attributs de session.

•
--disable-audit

Désactive audit dans les attributs de session.

•
ARGUMENT le fichier de contexte de session.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le programme de pagination man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » explicite est demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le programme de pagination man échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité des pages de manuel, celles-ci doivent être installées ou se trouver dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tcti pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le numéro de fichier et de ligne sont affichés.
•
-Q, --quiet: Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de l'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush: Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autovidage peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. des informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique du TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas produiront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier caractère du périphérique TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

NAME

tpm2_sessionconfig() — configure a session

SYNOPSIS

General Options

tpm2_sessionconfig [General Options] [SESSION-OPTIONS]

Session Options
-S, --session=SESSION
TPM session context blob SESSION
-P, --auth=AUTH
authorization policy digest AUTH
--disable-continueSession
--enable-continueSession
--disable-session-limits
--enable-session-limits

DESCRIPTION

The tpm2_sessionconfig command is used to configure various session attributes. It supports modifying session attributes, such as enabling or disabling session continuity or limits.

OPTIONS

General Options

-h, --help
Help message.
-v, --version
Return TPM information.
-d, --debug
Enable debug messages.
-V, --verbose
Enable verbose messages.
-t, --tcti=TCTI
The Tagged Command Transmission Interface (TCTI) to use. Specifies the interface to the TPM. The format is: NAME:OPTION1=VALUE1:OPTION2=VALUE2. For example, tabrmd:bus_name=com.example.FooBar.

Session Options

-S, --session=SESSION
TPM session context blob SESSION. This option is mandatory and specifies the session to be configured.
-P, --auth=AUTH
Authorization policy digest AUTH. This option is used to authorize operations on the session.
--disable-continueSession
Disable the continue session attribute. If set, the session cannot be resumed after being closed.
--enable-continueSession
Enable the continue session attribute. If set, the session can be resumed after being closed.
--disable-session-limits
Disable session limits. This affects the maximum duration and number of commands that can be executed within a session.
--enable-session-limits
Enable session limits. This affects the maximum duration and number of commands that can be executed within a session.

COMMON OPTIONS

These options are common to all tpm2-tools.

-?, -h, --help
Print the help message and exit.
-v, --version
Print version information and exit.
-d, --debug
Enable debug messages. This will print out verbose debug information about the tool's operation.
-V, --verbose
Enable verbose output. This will print out more detailed information about the tool's operation than usual.
-t, --tcti=<TCTI>
The Tagged Command Transmission Interface (TCTI) to use. This specifies the interface to the TPM. The format is: NAME:OPTION1=VALUE1:OPTION2=VALUE2.

TCTI Configuration

The TCTI configuration string is a comma-separated list of key-value pairs, where keys and values are separated by an equals sign.

•
The abrmd TCTI supports two keys:
1.
bus_name : The name of the tabrmd service on the bus (a string).
2.
bus_type : The type of the dbus instance (a string) limited to session and system.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

TCTI OPTIONS

For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,` character. Each key and value string are separated by an `=` character.

•
abrmd TCTI supports two keys:
1.
bus_name : The name of the tabrmd service on the bus (a string).
2.
bus_type : The type of the dbus instance (a string) limited to session and system.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Start a bounded & salted session, disable continuesession and display session

tpm2 createprimary -c prim.ctx
tpm2 startauthsession -S session.ctx --policy-session -c prim.ctx
### Session info before changing attributes
tpm2 sessionconfig session.ctx
### Session info after changing attributes
tpm2 sessionconfig --disable-continuesession
tpm2 sessionconfig session.ctx

•

•
