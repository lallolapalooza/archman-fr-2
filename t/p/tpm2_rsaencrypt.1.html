tpm2_rsaencrypt(1) Manuel des commandes générales tpm2_rsaencrypt(1)

NOM

tpm2_rsaencrypt(1) - Effectue une opération de chiffrement RSA à l'aide du TPM.

SYNTAXE

tpm2_rsaencrypt [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_rsaencrypt(1) - Effectue le chiffrement RSA sur le contenu du fichier de données à l'aide du schéma de remplissage indiqué conformément à la RFC 3447 de l'IETF (PKCS#1). L'entrée est par défaut STDIN si elle n'est pas spécifiée.

La clé référencée par le contexte de clé doit être :

1.
Une clé RSA
2.
Avoir l'attribut encrypt DEFINI dans ses attributs.

OPTIONS

•
-c, --key-context=OBJET:

Objet de contexte pointant vers la partie publique de la clé RSA à utiliser pour le chiffrement.

•
-o, --output=FICHIER:

Chemin optionnel du fichier de sortie pour enregistrer les données chiffrées. Par défaut, les données binaires chiffrées sont imprimées sur stdout.

•
-s, --scheme=FORMAT:

Optionnel, définit le schéma de remplissage (par défaut rsaes).

•
null - TPM_ALG_NULL utilise le schéma de la clé s'il est défini.
•
rsaes - TPM_ALG_RSAES qui est RSAES_PKCSV1.5.
•
oaep - TPM_ALG_OAEP qui est RSAES_OAEP.
•
-l, --label=FICHIER ou CHAINE:

Optionnel, définit les données de l'étiquette. Peut être une chaîne de caractères ou un chemin de fichier. Le TPM exige que le dernier octet de l'étiquette soit zéro, cela est géré en interne par l'outil. Aucun autre octet nul intégré ne peut exister sous peine de troncature de votre étiquette par le TPM.

•
ARGUMENT l'argument de la ligne de commande spécifie le chemin du fichier contenant les données à chiffrer.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet temporaire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement._OBJET_.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous en utilisant des identifiants de préfixes.

Remarque : Par défaut, les mots de passe sont supposés être sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu adaptés au terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour faire un écho d'un mot de passe via stdin :
echo mdp | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin :
tpm2_tool -p file:- <<< mdp

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de politique), ajoutez un + et une chaîne de caractères comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations de PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banques PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Remarque : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lorsque l'on parle directement à un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge l'absence de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <configuration-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS DU TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

REMARQUE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Créer une clé RSA et la charger

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Grsa2048 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Chiffrer en utilisant RSA

echo "mon message" > msg.dat
tpm2_rsaencrypt -c key.ctx -o msg.enc msg.dat

Déchiffrer en utilisant RSA

tpm2_rsadecrypt -c key.ctx -o msg.ptext msg.enc
cat msg.ptext
mon message

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
