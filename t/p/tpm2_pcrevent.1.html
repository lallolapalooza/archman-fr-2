tpm2_pcrevent(1) Manuel des commandes générales tpm2_pcrevent(1)

NOM

tpm2_pcrevent(1) - Hache un fichier et étend optionnellement un pcr.

SYNTAXE

tpm2_pcrevent [OPTIONS] FICHIER INDEX_PCR

DESCRIPTION

tpm2_pcrevent(1) - Hache le FICHIER s'il est spécifié ou l'entrée standard. Il utilise tous les algorithmes de hachage supportés par le TPM.

Optionnellement, si un index de PCR est spécifié, il étend ce PCR pour tous les algorithmes supportés avec le digest du hachage. Les arguments FICHIER et INDEX_PCR n'ont pas besoin d'être dans un ordre particulier.

Dans les deux cas, il affiche sur la sortie standard l'algorithme de hachage utilisé et la valeur du digest, une par ligne :

alg:digest

Où alg est l'algorithme utilisé (comme sha1) et digest est le digest résultant du calcul de hachage de alg sur les données.

Voir les sections 23.1 et les sections 17 de la https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-3-Commands-01.38.pdf Spécification TPM2.0

OPTIONS

Ces options contrôlent l'extension du pcr :

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour le PCR.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le paginator de manuel pour l'outil, cependant, en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le paginator de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou dans le MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Silence la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option en ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option en ligne de commande remplace toujours la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne supporte **AUCUNE** option et **DOIT** être présenté comme le texte exact de « none ».

Les arguments, que ce soit pour l'option en ligne de commande ou la variable d'environnement, sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant les sémantiques de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'interprété par les sémantiques de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaîne de valeur sont séparées par un caractère `=.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

Formatage de l'autorisation

L'autorisation d'utiliser un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSEVIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes décrites ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou en son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi l'utilisation de mots de passe contenant des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en options pouvant être lus à partir de la liste des processus ou des fonctions communes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de stratégie pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de stratégie), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification hexadécimale 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spec-pcr>=<fichier-pcr-brut>

Le spécificateur de PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

EXEMPLES

Hacher un fichier

echo "foo" > data
tpm2_pcrevent data

Hacher un fichier et étendre le PCR 8

echo "foo" > data
tpm2_pcrevent 8 data

Retours

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
