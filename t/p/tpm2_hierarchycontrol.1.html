tpm2_hierarchycontrol(1) Manuel des commandes générales tpm2_hierarchycontrol(1)

NOM

tpm2_hierarchycontrol(1) - Active et désactive l'utilisation d'une hiérarchie et de son stockage NV associé.

SYNTAXE

tpm2_hierarchycontrol [OPTIONS] VARIABLE OPERATION

DESCRIPTION

tpm2_hierarchycontrol(1) - Permet à l'utilisateur de modifier phEnable, phEnableNV, shEnable et ehEnable lorsque l'autorisation appropriée est fournie. L'autorisation doit être l'une des autorisations de la hiérarchie propriétaire, l'autorisation de la hiérarchie de fin et l'autorisation de la hiérarchie de plateforme. L'outil prend comme argument la VARIABLE comme bit TPMA_STARTUP_CLEAR et l'_OPERATION_ comme chaîne de caractères clear|set pour effacer ou définir le bit VARIABLE.

Note : Si l'option de mot de passe est manquante, NULL est supposé.

OPTIONS

•
-C, --hierarchy=OBJECT:

Spécifie le descripteur utilisé pour autoriser. Par défaut, il s'agit de la hiérarchie “plateforme”. Les options prises en charge sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<nombre> où un nombre brut peut être utilisé.
•
-P, --hierarchy-auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment le cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Références

Format objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un descripteur ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à une correspondance de préfixe sur l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie de fin
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un descripteur, par exemple 0x81010013, et utilisé directement._OBJECT_.

Formatage de lAutorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut se présenter sous 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations par défaut sont le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaine de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaine hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:”, est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:”, doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un “-” pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, car les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour transmettre un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne de caractères comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session nommé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que renvoyés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

spécifiant AUTH.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page man de l'outil. Par défaut, il tente d'appeler le programme de pagination man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le programme de pagination man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages man, il faut que les pages man soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tcti pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Supprime la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application des correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush: Active le vidage automatique pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. information que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou "Interface de transmission" est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils autorisent les options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté comme le texte exact de "none".

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <configuration-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur de chaîne sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Définir phEnableNV avec la hiérarchie plateforme et son autorisation

tpm2_hierarchycontrol -C p phEnableNV set -P pass

clear phEnableNV avec la hiérarchie plateforme

tpm2_hierarchycontrol -C p phEnableNV clear

Définir shEnable avec la hiérarchie plateforme

tpm2_hierarchycontrol -C p shEnable set

Définir shEnable avec la hiérarchie propriétaire

tpm2_hierarchycontrol -C o shEnable set

Vérifier les bits actuels de TPMA_STARTUP_CLEAR

tpm2_getcap properties-variable

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
