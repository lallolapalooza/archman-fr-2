NOM

tpm2_nvsetbits(1) - Applique un ET bit à bit à un Non-Volatil (NV).

SYNTAXE

tpm2_nvsetbits [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvsetbits(1) - Applique un ET bit à bit à un Non-Volatil (NV). L'index NV doit être de type « bits », spécifié via le champ « nt » lors de la création de l'espace NV avec tpm2_nvdefine(1). L'index peut être spécifié comme un handle brut ou une valeur de décalage par rapport à la plage de handles NV « TPM2_HR_NV_INDEX ».

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie la hiérarchie utilisée pour l'autorisation. Les options prises en charge sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un handle de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, le handle de l'index sera utilisé pour autoriser l'index. La valeur d'autorisation de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
-i, --bits=BITS:

Spécifie la valeur de bits sous forme numérique à appliquer par un ET bit à bit à la valeur actuelle de l'index NV.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash, sauf si rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est couramment appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
-n, --name=FICHIER:

Le nom de l'index NV qui doit être fourni lors du calcul uniquement du cpHash sans réellement envoyer la commande au TPM.

•
ARGUMENT l'argument de ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe sur l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche la fuite d'informations ; les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou via les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier d'un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).
