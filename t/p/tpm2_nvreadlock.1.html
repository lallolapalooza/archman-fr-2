tpm2_nvreadlock(1) Manuel des commandes générales tpm2_nvreadlock(1)

NOM

tpm2_nvreadlock(1) - Verrouille l'index Non-Volatile (NV) pour les lectures ultérieures.

SYNOPSIS

tpm2_nvreadlock [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvreadlock(1) - Verrouille l'index Non-Volatile (NV) pour les lectures ultérieures. Le verrou sur l'index NV est déverrouillé lors du redémarrage du TPM et l'index NV devient à nouveau lisible. L'index peut être spécifié sous forme de handle brut ou de valeur de décalage de la plage de handles nv “TPM2_HR_NV_INDEX”.

OPTIONS

•
-C, --hierarchy=OBJECT:

Spécifie la hiérarchie utilisée pour l'autorisation. Options supportées :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un handle de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, le handle de l'index sera utilisé pour s'autoriser contre l'index. La valeur d'authentification de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
--cphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash à moins que rphash ne soit également requis.

•
--rphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. C'est ce qu'on appelle couramment rpHash.

•
-S, --session=FILE:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
-n, --name=FILE:

Le nom de l'index NV qui doit être fourni lors du calcul du cpHash sans réellement envoyer la commande au TPM.

•
ARGUMENT l'argument de la ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé en tant qu'objet transitoire TPM restauré.
•
Si l'argument est une correspondance *par préfixe* sur l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.*_OBJECT_*.

Format de l'autorisation

L'autorisation pour l'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:”, est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:” doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un “-” pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en option peuvent être lus à partir de la liste des processus ou des fonctionnalités d'historique courant du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Ensuite, indiquez un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session nommé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banques PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

OPTIONS COMMUNES

Cette collection d'options sont communes à de nombreux programmes et fournissent des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le paginator de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le paginator de manuel échoue, les options courtes seront envoyées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, celles-ci doivent être installées ou se trouver dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le numéro de fichier et de ligne sont imprimés.
•
-Q, --quiet : Silence la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active le nettoyage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également nettoyé. Le nettoyage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Transmission Interface » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour la communication avec les TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lorsque l'on communique directement avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-option-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne de clé et de valeur est séparée par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXEMPLES

Verrouiller un index

tpm2_nvdefine -Q   1 -C o -s 32 \
-a "ownerread|policywrite|ownerwrite|read_stclear"
echo "foobar" > nv.readlock
tpm2_nvwrite -Q   0x01000001 -C o -i nv.readlock
tpm2_nvread -Q   1 -C o -s 6 -o 0
tpm2_nvreadlock -Q   1 -C o

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
