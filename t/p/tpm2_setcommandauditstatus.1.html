tpm2_setcommandauditstatus(1) Manuel des commandes générales tpm2_setcommandauditstatus(1)

NOM

tpm2_setcommandauditstatus(1) - Ajoute ou retire des commandes TPM2 de la liste des commandes auditées.

SYNTAXE

tpm2_setcommandauditstatus [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_setcommandauditstatus(1) - Ajoute ou retire des commandes TPM2 de la liste des commandes auditées.

Prend en argument la commande sous forme d'entier ou de chaîne de caractères conviviale. Le mappage entre la chaîne conviviale et le CODE DE COMMANDE se trouve dans la section MAPPAGE DES CODES DE COMMANDE.

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie la hiérarchie propriétaire ou la hiérarchie plateforme. Par défaut, TPM_RH_OWNER est utilisé si aucune valeur n'est spécifiée. Les options supportées sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
-P, --hierarchy-auth=AUTH: Spécifie la valeur d'autorisation pour la hiérarchie. Les valeurs d'autorisation doivent suivre les “normes de formatage d'autorisation”, voir la section “Formatage d'autorisation”.
•
-c, --clear-list: Indique que la commande TPM spécifiée doit être retirée de la liste d'audit. Si cette option n'est pas spécifiée, le comportement par défaut est d'ajouter la commande TPM à la liste d'audit.
•
-g, --hash-algorithm=ALGORITHME:

Configure l'algorithme de hachage pour le digest d'audit. Si non spécifié, l'algorithme de digest d'audit par défaut est SHA256.

•
ARGUMENT l'argument de ligne de commande spécifie le code de commande TPM2.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche le manuel de l'outil. Par défaut, il tente d'invoquer le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” explicite est demandé, l'outil affichera les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pagineur de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité de manuel, les pages de manuel doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose: Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet: Silencie la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de l'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush: Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Configuration TCTI

Le TCTI ou “Transmission Interface” est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas produiront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou les <config-options-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et valeur sont séparées par un caractère '='.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limité à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.
FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Ajouter TPM2_CC_Unseal à la liste des commandes auditées.

tpm2_setcommandauditstatus TPM2_CC_Unseal

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

Limitations

Il s'attend à ce qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des actions suivantes :

•
accès direct au périphérique
•
support de session étendue avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commande.
