tpm2_policynvwritten(1) Manuel des commandes générales tpm2_policynvwritten(1)

NOM

tpm2_policynvwritten(1) - Restreint l'autorisation d'objet TPM à l'état écrit d'un index NV.

SYNTAXE

tpm2_policynvwritten [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_policynvwritten(1) - Restreint l'autorisation d'objet TPM à l'état écrit d'un index NV. Utile lors de la création d'index NV inscriptibles une seule fois.

En tant qu'[ARGUMENT], il prend l'état écrit attendu de l'index NV. Il peut être spécifié comme s|c|0|1.

OPTIONS

•
-S, --session=FICHIER:

Un fichier de session provenant de l'option -S de tpm2_startauthsession(1).

•
-L, --policy=FICHIER:

Fichier pour enregistrer le digest de politique.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le man page de l'outil. Par défaut, il tente d'appeler le pagineur de man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. Ceci est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pagineur de man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des man pages, il faut que les man pages soient installées ou présentes dans MANPATH, voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Silence la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata : Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également purgé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou "Transmission Interface" est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=’.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limité à `session' et `system'.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

tpm2_policynvwritten(1) — tpm2-tools

NAME

tpm2_policynvwritten — Set the policy that NV index was not written

SYNOPSIS

tpm2_policynvwritten [options] [policy file]

DESCRIPTION

The tpm2_policynvwritten tool is intended to be used in conjunction with a session and is used to define a policy session that will check if a specific NV index has NOT been written to. This command is used when you want to ensure that a certain NV index is in an unwritten state before proceeding with a TPM operation.

OPTIONS

•
-S session session.dat : This option specifies the session file previously created by tpm2_startauthsession(1). It is mandatory to have a valid session.
•
-L policy file nvwrite.policy : This option specifies the output file where the policy digest will be stored. This policy digest is then used by other TPM commands to check against the policy requirements.
•
-c c : This flag indicates that the policy condition is that the NV index has NOT been written. If this flag is omitted, the default behavior is to check if the NV index HAS been written.

COMMON OPTIONS

See tpm2.common(7) for common options that can be used with this command.

TCTI Configuration

The TPM Communication Transport Interface (TCTI) can be configured using environment variables or specific options. Refer to tpm2.common(7) for details on TCTI configuration.

TCTI OPTIONS

See tpm2.common(7) for TCTI specific options.

EXAMPLES

This example demonstrates how to create a policy that requires an NV index to be in an unwritten state before allowing a write operation.

Define the NV index write policy

tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat -L nvwrite.policy c
tpm2_flushcontext session.dat

Define the NV index with the policy

 tpm2_nvdefine -s 1 -a "authread|policywrite" -p nvrdpass -L nvwrite.policy

Write the NV index by satisfying the policy

tpm2_startauthsession -S session.dat --policy-session
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat c
echo 0xAA | xxd -r -p | tpm2_nvwrite 0x01000000 -i- -P session:session.dat
tpm2_flushcontext session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
