tpm2_ecdhzgen(1) Manuel des commandes générales tpm2_ecdhzgen(1)

NOM

tpm2_ecdhzgen(1) - Récupère la valeur du secret partagé (Z) à partir d'un point public et d'une clé privée spécifiée.

SYNOPIS

tpm2_ecdhzgen [OPTIONS]

DESCRIPTION

tpm2_ecdhzgen(1) - Récupère la valeur du secret partagé (Z) à partir d'un point public et d'une clé privée spécifiée. Il effectuera la multiplication du point d'entrée (inPoint, QB) avec la clé privée (ds) et retournera les coordonnées du point résultant (Z = (xZ , yZ) ≔ [hds]QB ; où h est le cofacteur de la courbe).

OPTIONS

•
-c, --key-context=FICHIER:

Objet de contexte pointant vers une clé ECC. Soit un fichier, soit un numéro de handle. Voir la section « Format de l'objet de contexte ».

•
-p, --key-auth=AUTH:

La valeur d'autorisation pour l'objet de clé ECC.

•
-u, --public=FICHIER:

Point ECC d'entrée Q.

•
-k, --public-key=FICHIER:

Clé publique ECC d'entrée avec le point Q.

•
-o, --output=FICHIER

Spécifiez le chemin du fichier pour sauvegarder le secret ecdh calculé ou le point Z.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il retournera simplement un cpHash.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Des choses comme le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les détails restants du schéma et du mode symétrique seront pris par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il est par défaut à null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il est par défaut à null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ optionnel, il peut être sauté.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétriques. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il est par défaut à sha256. Certains ne prennent aucun argument, et certains en prennent plusieurs.

SYNOPSIS

tpm2_create [OPTIONS] [ARGUMENTS]

DESCRIPTION

The tpm2_create command is used to create a primary key or a regular key. A primary key is created when the parent context is the empty primary seed (defined as NULL or the default of NULL). A regular key is created when the parent context is an existing primary key or other key. The created key will be created under the parent context specified.

The tpm2_create command will create a TPM object.

OPTIONS

These options control the behavior of the tpm2_create command.

Basic Configuration

Options that control the creation of the key.

-C CONTEXT, --parent-context=CONTEXT
Specifies the parent object context. This can be a TPM2B_CONTEXT_DATA structure, a file path to a context file, or a numeric handle.
-u FILE, --public=FILE
Specifies the output file path for the public key. This will be a TPM2B_PUBLIC structure. This option is mandatory.
-r FILE, --private=FILE
Specifies the output file path for the private key. This will be a TPM2B_PRIVATE structure. This option is mandatory.
-I FILE, --input-public=FILE
Specifies the input TPM2B_PUBLIC structure to be used as the public portion of the key. If this option is not specified, then the public key structure will be generated using the default attributes.
-i FILE, --input-private=FILE
Specifies the input TPM2B_PRIVATE structure to be used as the private portion of the key. If this option is not specified, then the private key structure will be generated using the default attributes.

Key Creation Options

Options that control the type and attributes of the key being created.

-G ALG[:ALG...], --key-algorithm=ALG[:ALG...]
Specifies the algorithms to be used for the key. The format for the algorithm string is described in the section Algorithm Specifiers. Multiple algorithms can be specified, separated by a colon. The last algorithm specified will be the primary algorithm used for the key.
-L FILE, --policy=FILE
Specifies the policy file that will be used to create the policy digest associated with the key. This option can be specified multiple times to create a policy tree.
-P PASSWD, --parent-password=PASSWD
Specifies the password for the parent context. This is only needed if the parent context is password protected.
-p PASSWD, --key-password=PASSWD
Specifies the password for the key being created. This is only needed if the key is created with a password authorization policy.
-a ATTRIBUTES, --attributes=ATTRIBUTES
Specifies the attributes for the key. The attributes are specified as a comma separated list of flags. See section Attributes for a list of attributes.
-e FILE, --extension=FILE
Specifies a file containing a TPM2B_NAME structure. This will be used to extend the name of the created object.
-t TYPE, --type=TYPE
Specifies the type of object being created. The default is OBJECT. Valid options are:
OBJECT
KEYEDHASH
SYMCIPHER

Algorithm Specifiers

The -G and --key-algorithm options take a list of algorithms that define the key to be created. The general format is:

<KeyAlg>[:<HashAlg>][:<SymAlg>]

Where:

<KeyAlg>
Specifies the primary key algorithm. This can be:
rsaXXX
: RSA key with a key size of XXX bits (e.g., rsa2048, rsa3072, rsa4096).
eccXXX
: Elliptic curve key with a curve size of XXX bits (e.g., ecc256, ecc384, ecc521).
keyedhash
: Keyed hash object (e.g., HMAC, CMAC).
symcipher
: Symmetric cipher object.
<HashAlg>
Specifies the hash algorithm to be used with the key. This is only applicable to signing keys. This can be:
shaXXX
: SHA hash with a digest size of XXX bits (e.g., sha1, sha256, sha384, sha512).
sm3
: SM3 hash.
mgf1shaXXX
: MGF1 hash (e.g., mgf1sha1, mgf1sha256).
<SymAlg>
Specifies the symmetric cipher algorithm to be used with the key. This is only applicable to symmetric cipher objects. This can be:
aesXXX
: AES cipher with a key size of XXX bits (e.g., aes128, aes192, aes256).
sm4
: SM4 cipher.
camelliaXXX
: Camellia cipher with a key size of XXX bits.

If no hash algorithm is specified, it defaults to sha256.

If no symmetric cipher algorithm is specified, it defaults to aes128cfb.

Signatures

For signing keys, the algorithm specifier can include a signing scheme. The format is:

<KeyAlg>-<SignScheme>

Where:

<SignScheme>
Specifies the signing scheme. This can be:
rsassa:pkcs1-shaXXX
: RSASSA PKCS1v15 signature scheme with SHA hash.
rsassa:pss-shaXXX
: RSASSA PSS signature scheme with SHA hash.
ecdsa:shaXXX
: ECDSA signature scheme with SHA hash.
ecdaa:XXX
: ECDAA signature scheme with SHA hash.

The ecdaa scheme also takes an optional count (max size UINT16) which defaults to 4 if not specified. For example, ecdaa4-sha256.

If no signing scheme is specified, it defaults to the most appropriate scheme for the key type.

Algorithm Specifier Examples

rsa2048:sha256
An RSA 2048-bit key that will be used for signing with SHA256.
ecc384:ecdsa:sha384
An ECC 384-bit key that will be used for signing with ECDSA and SHA384.
rsa3072:rsassa:pss-sha256
An RSA 3072-bit key that will be used for signing with RSASSA-PSS and SHA256.
symcipher:aes256
A symmetric cipher key with AES 256-bit encryption.
keyedhash:hmac
A keyed hash object that will be used for HMAC.

Asymmetric Details Specifiers

This scheme specifier is followed by a count (max size UINT16) then followed by a dash(-) and a valid hash algorithm. * ecdaa For example, ecdaa4-sha256. If no count is specified, it defaults to 4.

No Option Scheme Specifiers

This scheme specifier takes NO arguments. * rsaes

Symmetric Details Specifiers

This field is optional, and defaults based on the type of object being created and it’s attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
