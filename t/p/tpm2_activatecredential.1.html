tpm2_activatecredential(1)

tpm2_activatecredential(1) Manuel des commandes générales tpm2_activatecredential(1)

NOM

tpm2_activatecredential(1) - Permet l'accès au qualificateur d'identifiants pour récupérer le secret de l'identifiant.

SYNTAXE

tpm2_activatecredential [OPTIONS]

DESCRIPTION

tpm2_activatecredential(1) - Permet l'association d'un identifiant à un objet de manière à garantir que le TPM a validé les paramètres de l'objet identifié. Dans un schéma d'attestation, cela garantit au registraire que la clé d'attestation appartient au TPM avec une clé parente qualifiée dans le TPM.

OPTIONS

•
-c, --credentialedkey-context=OBJET:

Objet associé au certificat créé par l'AC.

•
-C, --credentialkey-context=OBJET:

L'objet chargé utilisé pour déchiffrer la graine aléatoire.

•
-p, --credentialedkey-auth=AUTH:

La valeur d'authentification de l'objet identifié spécifié avec -c.

•
-P, --credentialkey-auth=AUTH:

La valeur d'authentification de l'objet d'identifiant spécifié avec -C.

•
-i, --credential-blob=FICHIER:

Le chemin du fichier d'entrée contenant le blob d'identifiant et le secret créés avec l'outil tpm2_makecredential(1).

•
-o, --certinfo-data=FICHIER:

Le chemin du fichier de sortie pour enregistrer les informations du secret d'identifiant déchiffré.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE: Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash, à moins que rphash ne soit également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un descripteur ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire du TPM restauré.
•
Si l'argument correspond à une correspondance préfixée de l'un des éléments suivants :
•
owner: la hiérarchie du propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un descripteur, par exemple 0x81010013 et utilisé directement.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations sont par défaut le mot de passe VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi l'utilisation de mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers évite les fuites d'informations ; les mots de passe transmis comme options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour écho d'un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, un mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banques PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que renvoyés par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

OPTIONS

Many of the tools take common options that are not covered here, instead see tpm2_tool(1) for common options.

Context Object Format

For options that take a context object, the options are specified in the following format:

[-c | --context] contextfile:filename

or

[-C | --parent-context] parentcontext:filename

where filename is the path to the file containing the context data.

Authorization Formatting

For options that take authorization data, the options are specified in the following format:

--password password

or

--authval password

or

--authfile filename

or

--policy session:filename

or

--policy-hmac session:filename

or

--policy-authorize session:filename

or

--policy-counter session:filename

or

--policy-locality session:filename

or

--policy-or session:filename

or

--policy-stclear session:filename

or

--policy-commandcode session:filename

or

--policy-nv written:filename

or

--policy-signed session:filename

or

--policy-ticket session:filename

or

--policy-tpm2_actions session:filename

or

--policy-physical-presence session:filename

where session is a previously created session context, and filename is the path to the file containing the policy data or credential.

The password and filename are substituted for the corresponding placeholder.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

echo "12345678" > secret.data
tpm2_createek -Q -c 0x81010001 -G rsa -u ek.pub
tpm2_createak -C 0x81010001 -c ak.ctx -G rsa -g sha256 -s rsassa -u ak.pub \
-n ak.name -p akpass> ak.out
file_size=`stat --printf="%s" ak.name`
loaded_key_name=`cat ak.name | xxd -p -c $file_size`
tpm2_makecredential -Q -e ek.pub  -s secret.data -n $loaded_key_name \
-o mkcred.out
tpm2_startauthsession --policy-session -S session.ctx
tpm2_policysecret -S session.ctx -c e
tpm2_activatecredential -Q -c ak.ctx -C 0x81010001 -i mkcred.out \
-o actcred.out -p akpass -P"session:session.ctx"
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
