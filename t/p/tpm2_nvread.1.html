tpm2_nvread(1) Manuel des commandes générales tpm2_nvread(1)

NOM

tpm2_nvread(1) - Lire les données stockées dans un index Non Volatil (NV).

SYNOPIS

tpm2_nvread [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvread(1) - Lire les données stockées dans un index Non Volatil (NV). L'index peut être spécifié comme une poignée brute ou une valeur de décalage de la plage de poignées nv “TPM2_HR_NV_INDEX”.

OPTIONS

•
-C, --hierarchy=OBJECT:

Spécifie la hiérarchie utilisée pour l'autorisation. Options prises en charge :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où une poignée de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, la poignée de l'index sera utilisée pour autoriser contre l'index. La valeur d'autorisation de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-o, --output=FILE:

Fichier où écrire les données

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
-s, --size=NATURAL_NUMBER:

Spécifie la taille des données à lire en octets, en commençant par 0 si le décalage n'est pas spécifié. Si non spécifié, la taille des données telle que rapportée par la partie publique de l'index sera utilisée.

•
--offset=NATURAL_NUMBER:

Le décalage dans l'index NV à partir duquel commencer la lecture.

•
--cphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash, sauf si rphash est également requis.

•
--rphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-n, --name=FILE:

Le nom de l'index NV qui doit être fourni lors du calcul uniquement du cpHash sans réellement envoyer la commande au TPM.

•
-S, --session=FILE:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
--print-yaml:

Afficher le contenu de l'index NV dans un format lisible par l'homme, utile pour afficher le contenu des index de compteur, bits et étendue et épingle. Lorsque cet argument est fourni, la taille et le décalage sont ignorés.

•
ARGUMENT l'argument de ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'une poignée ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à une préfixe sur l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme une poignée, par exemple 0x81010013 et utilisé directement. _OBJECT_.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations par défaut utilisent le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixes.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:” doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un “-” pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en option peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour écho un mot de passe via stdin:
echo mdp | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin:
tpm2_tool -p file:- <<< mdp

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec la poignée de session (par exemple, un mot de passe de politique), ajoutez un + et une chaîne telle que décrite dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant :

DESCRIPTION

The PCR specifiers are used to indicate which PCRs are to be tested. The PCR specifiers are formatted as:

<pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.d)
