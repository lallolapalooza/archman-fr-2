tpm2_import(1) Manuel des commandes générales tpm2_import(1)

NOM

tpm2_import(1) - Importe une clé externe dans le tpm comme un objet clé géré par le TPM.

SYNTAXE

tpm2_import [OPTIONS]

DESCRIPTION

tpm2_import(1) - Importe une clé générée extérieurement en tant qu'objet clé géré par le TPM. Il nécessite que l'objet clé parent soit une clé RSA. Peut également importer un objet clé géré par le TPM créé par l'outil tpm2_duplicate.

OPTIONS

Ces options contrôlent le processus d'importation de clé :

•
-G, --key-algorithm=ALGORITHME:

L'algorithme utilisé par la clé à importer. Prend en charge :

•
aes - Clé AES 128, 192 ou 256.
•
rsa - Clé RSA 1024, 2048, 3072 ou 4096.
•
ecc - Clé publique et privée ECC NIST P192, P224, P256, P384 ou P521.
•
hmac - Clé HMAC.
•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage pour générer le nom de l'objet. Ceci est facultatif et par défaut sha256 lorsqu'il n'est pas spécifié. Les algorithmes doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Algorithmes de hachage pris en charge » pour une liste des algorithmes de hachage pris en charge.

•
-i, --input=FICHIER:

Spécifie le nom du fichier de la clé à importer. Pour les clés AES, ce fichier contient les octets bruts de la clé. Pour les clés asymétriques au format PEM ou DER. Un fichier typique est généré avec openssl genrsa.

•
-C, --parent-context=OBJET:

L'objet clé parent.

•
-U, --parent-public=FICHIER:

Facultatif. Spécifie l'entrée du fichier de données publiques de la clé parent. Ceci peut être lu avec l'outil tpm2_readpublic(1). Si non spécifié, l'outil invoque un tpm2_readpublic sur l'objet parent.

•
-k, --encryption-key=FICHIER:

Facultatif. Spécifie le fichier contenant la clé de l'algorithme symétrique qui a été utilisée pour l'enveloppe intérieure. Si le fichier est spécifié, l'outil suppose que l'algorithme est AES 128 en mode CFB, sinon aucun.

•
-r, --private=FICHIER:

Spécifie le chemin du fichier requis pour enregistrer la partie privée chiffrée de l'objet importé en tant que clé.

Lors de l'importation d'un objet dupliqué, cette option spécifie le fichier contenant la partie privée de l'objet à importer. # Détails de la protection

Les objets qui peuvent sortir du TPM doivent être protégés (confidentialité et intégrité). Par exemple, les objets transitoires nécessitent que les données protégées par le TPM (clé ou matériel de scellement) soient stockées à l'extérieur du TPM. Ceci est visible dans des outils comme tpm2_create(1), où l'option -r produit ces données protégées. Ce blob contient les parties sensibles de l'objet. Les parties sensibles de l'objet sont protégées par l'objet parent, en utilisant les détails de chiffrement symétrique du parent pour chiffrer les données sensibles et les HMACer.

Des détails approfondis peuvent être trouvés dans la section 23 de :

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

Notamment la Figure 20 est pertinente, même si elle fait spécifiquement référence aux blobs de duplication, le processus est identique.

Si la sortie provient de tpm2_duplicate(1), la sortie sera légèrement différente, comme décrit intégralement dans la section 23.

•
-u, --public=FICHIER:

Spécifie le chemin du fichier requis pour enregistrer la partie publique de l'objet importé en tant que clé.

Lors de l'importation d'un objet dupliqué, cette option spécifie le fichier contenant la partie publique de l'objet à importer.

•
-a, --attributes=ATTRIBUTS:

Les attributs de l'objet, facultatif.

•
-P, --parent-auth=AUTH:

La valeur d'autorisation pour utiliser la clé parent spécifiée avec -C.

•
-p, --key-auth=AUTH:

La valeur d'autorisation pour la clé importée, facultatif.

•
-L, --policy=POLITIQUE ou CHAINE_HEX:

Le fichier de politique ou la chaîne hexadécimale de politique utilisée pour l'autorisation de l'objet.

•
-s, --seed=FICHIER:

Spécifie le fichier contenant la graine chiffrée de l'objet dupliqué.

Pour effectuer une « importation non chiffrée », un fichier de graine avec le contenu 0x0000 doit être fourni (par exemple, printf "0000" | xxd -r -p >seed.file).

•
--passin=OSSL_PEM_FILE_PASSWORD

Un mot de passe facultatif pour un fichier d'entrée fourni par Open SSL (OSSL). Il reflète l'option -passin d'OSSL et est connu pour prendre en charge les formats pass, file, env, fd et le mot de passe brut d'openssl. (voir man(1) openssl pour plus de détails).

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

Références

Format de l'objet contexte

Le type d'un objet contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un *préfixe* de l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement._OBJET_.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations sont par défaut sur le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous en utilisant des identifiants de préfixe.

Remarque : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples
>foobar str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:”, est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi l'utilisation de mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:”, doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un “-” pour utiliser l'entrée standard. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, car les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou via les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour afficher un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADÉCIMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant: <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section “Spécificateurs de banques PCR”.

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des contenus PCR bruts tels que renvoyés par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez le spécificateur :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, comportent de nombreux algorithmes à renseigner dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Vous trouverez ci-dessous le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est obligatoire. Les spécifications de schéma et de détails symétriques restantes seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ optionnel, il peut être omis.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est absent, la valeur par défaut est sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

Attributs d'objet

Les attributs d'objet sont utilisés pour contrôler diverses propriétés des objets créés. Lorsqu'ils sont spécifiés en option, le masque de champs de bits bruts ou les « noms conviviaux » peuvent être utilisés. Les valeurs peuvent être trouvées dans le Tableau 31, partie 2 de la spécification TPM2.0, qui peut être trouvée ici :

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Les noms conviviaux sont calculés en prenant le champ de nom du tableau 31 et en supprimant le préfixe TPMA_OBJECT_ et en mettant le résultat en minuscules. Ainsi, TPMA_OBJECT_FIXEDTPM devient fixedtpm. Les noms conviviaux peuvent être joints à l'aide de l'opérateur OU binaire « | ».

Par exemple, pour définir les champs TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA et TPMA_OBJECT_SIGN_ENCRYPT, l'argument serait :

fixedtpm|noda|sign spécifiant les attributs d'objet ATTRIBUTES.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé pour communiquer directement avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils autorisent les options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute du nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier périphérique TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère « , ». Chaque chaîne de clé et de valeur est séparée par un caractère « = ».
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Pour importer une clé, il faut avoir une clé parente

tpm2_createprimary -Grsa2048:aes128cfb -C o -c parent.ctx

Créez votre clé et importez-la. Si vous avez déjà une clé, utilisez-la simplement et sautez sa création.

Importer une clé AES 128

dd if=/dev/urandom of=sym.key bs=1 count=16
tpm2_import -C parent.ctx -G aes -i sym.key -u key.pub -r key.priv

Importer une clé RSA

openssl genrsa -out private.pem 2048
tpm2_import -C parent.ctx -G rsa -i private.pem -u key.pub -r key.priv

Importer une clé ECC

openssl ecparam -name prime256v1 -genkey -noout -out private.ecc.pem
tpm2_import -C parent.ctx -G ecc -i private.ecc.pem -u key.pub -r key.priv

Importer une clé dupliquée

tpm2_import -C parent.ctx -i key.dup -u key.pub -r key.priv -L policy.dat

NOM

tpm2_import — importer une clé dans le TPM.

SYNONYPSIS

tpm2_import [OPTIONS] [ARGUMENTS]

DESCRIPTION

La commande tpm2_import est utilisée pour importer une clé dans le TPM. Le format de l'objet du contexte est le suivant :

L'objet parent du nouveau handle sera recherché par son handle. Le handle est le premier argument et est un entier, par défaut il est au format hexadécimal. Les handles peuvent être préfixés par 0x.
Les attributs de l'objet sont représentés par une chaîne de caractères. Par défaut, l'attribut 0x20000 (TPMA_OBJECT_USERWITHAUTH) est utilisé. Les attributs peuvent être spécifiés par leur valeur hexadécimale ou par une chaîne de caractères reconnue.
L'algorithme de politique du nouvel objet est spécifié par le nom de l'algorithme.
Les informations du certificat de signature sont fournies par l'option -c.

Les options de manipulation d'autorisations sont les suivantes :

La méthode d'autorisation peut être spécifiée en utilisant l'option --auth. Par défaut, c'est policy-session.
La clé de saisie de l'autorisation peut être fournie avec l'option --key. La valeur par défaut est un identifiant de saisie vide.
La méthode de politique peut être spécifiée en utilisant l'option --policy. Par défaut, c'est policy-nv-read.

OPTIONS

Les options suivantes sont disponibles :

-i, --input-file
Le chemin du fichier contenant l'objet à importer. Ce fichier est généralement un fichier PEM.
-r, --parent-auth
L'autorisation du parent. La valeur par défaut est un identifiant de saisie vide.
-p, --parent-hierarchy
La hiérarchie parente. Les valeurs possibles sont owner, endorsement, ou null.
-a, --auth-policy
La politique d'autorisation pour le nouvel objet. La valeur par défaut est un identifiant de saisie vide.
-u, --attributes
Les attributs de l'objet. La valeur par défaut est 0x20000 (TPMA_OBJECT_USERWITHAUTH).
-n, --name-alg
L'algorithme de nommage de l'objet. La valeur par défaut est rsa.
-o, --output-file
Le chemin du fichier où le handle du nouvel objet sera écrit. Par défaut, il est écrit sur la sortie standard.
-t, --type
Le type de l'objet. Les valeurs possibles sont secret, nv, ou data.
-c, --context-file
Le fichier contenant l'objet du contexte.
-l, --policy-file
Le fichier contenant la politique.
-e, --evict
Permet au nouvel objet d'être expulsé.
-P, --parent-public
Le fichier contenant la clé publique du parent.
-s, --policy-session
Le handle de la session de politique.
-f, --force
Forcer l'importation même si un objet du même nom existe déjà.
--help
Afficher un message d'aide et quitter.
--version
Afficher les informations de version et quitter.

Context Object Format

Le format de l'objet du contexte est le suivant :

L'objet parent du nouveau handle sera recherché par son handle. Le handle est le premier argument et est un entier, par défaut il est au format hexadécimal. Les handles peuvent être préfixés par 0x.
Les attributs de l'objet sont représentés par une chaîne de caractères. Par défaut, l'attribut 0x20000 (TPMA_OBJECT_USERWITHAUTH) est utilisé. Les attributs peuvent être spécifiés par leur valeur hexadécimale ou par une chaîne de caractères reconnue.
L'algorithme de politique du nouvel objet est spécifié par le nom de l'algorithme.
Les informations du certificat de signature sont fournies par l'option -c.

Authorization Formatting

Les options de manipulation d'autorisations sont les suivantes :

La méthode d'autorisation peut être spécifiée en utilisant l'option --auth. Par défaut, c'est policy-session.
La clé de saisie de l'autorisation peut être fournie avec l'option --key. La valeur par défaut est un identifiant de saisie vide.
La méthode de politique peut être spécifiée en utilisant l'option --policy. Par défaut, c'est policy-nv-read.

Algorithm Specifiers

Les algorithmes sont spécifiés par leur nom. Les algorithmes reconnus sont :

rsa
ecc
hmac
sha1
sha256
sha384
sha512

Object Attributes

Les attributs de l'objet sont spécifiés par leur nom ou leur valeur hexadécimale. Les attributs reconnus sont :

userwithauth (0x20000)

sensitivedataorigin (0x100000)
useronly (0x10000)

fixedtpm (0x4000)
stclear (0x2000)
sensitive (0x1000)
adminonly (0x800)
no_DA (0x400)
userdefined (0x200)
restricted (0x100)
decrypt (0x80)
sign (0x40)
fixed (0x20)

COMMON OPTIONS

Les options courantes suivantes sont également disponibles :

-h, --help
Affiche un message d'aide et quitte.
-v, --version
Affiche les informations de version et quitte.
-X, --debug
Active la sortie de débogage.

TCTI Configuration

Le protocole de transport TCTI peut être configuré à l'aide des options suivantes :

-z, --tcti-name
Nom du TCTI. Les valeurs possibles sont device, socket, ou none.
-C, --tcti-config
Configuration du TCTI. Le format dépend du TCTI choisi.

TCTI OPTIONS

Les options suivantes sont spécifiques à certains TCTI :

device

Utilise le périphérique TCTI.

-d, --device
Le chemin du périphérique TCTI. La valeur par défaut est /dev/tpm0.
socket

Utilise le socket TCTI.

-s, --socket
Le chemin du socket TCTI. La valeur par défaut est /var/run/tpm/tpmd_socket.

EXAMPLES

Importer une clé RSA dans la hiérarchie propriétaire :

tpm2_import -i mykey.pem -r parent_auth -p owner -n rsa -o importedkey.bin

Importer une clé ECC avec des attributs spécifiques :

tpm2_import -i myecckey.pem -r parent_auth -p owner -u userwithauth+restricted -n ecc -o importedeccekey.bin

LIMITATIONS

Le TPM exige que le nom de l'algorithme de l'enfant soit plus petit que celui du parent.

Returns

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
