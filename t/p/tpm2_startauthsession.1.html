tpm2_startauthsession(1) Manuel des commandes générales tpm2_startauthsession(1)

NOM

tpm2_startauthsession(1) - Démarre une session avec le TPM.

SYNOPSIS

tpm2_startauthsession [OPTIONS]

DESCRIPTION

tpm2_startauthsession(1) - Démarre une session avec le TPM. Par défaut, il s'agit d'une session test, sauf si l'option -a est spécifiée. Sauvegarde les données de la session de politique dans un fichier. Ce fichier peut ensuite être utilisé par des outils ultérieurs qui peuvent utiliser un fichier de politique pour l'autorisation ou les événements de politique.

Cela ne fonctionnera pas avec les gestionnaires de ressources (RM) en dehors de tpm2-abrmd, car la plupart des RM effaceront les identifiants de session lorsqu'un client se déconnecte du canal IPC. Cependant, lors de l'utilisation d'un RM sans la fonctionnalité de mise en file d'attente des sessions, on peut utiliser la commande TCTI pour maintenir la connexion ouverte.

La première étape consiste à créer un écouteur de socket qui utilise tpm2_send :

mknod "$HOME/backpipe" p
while [ 1 ]; do tpm2_send 0<"$HOME/backpipe" | nc -lU "$HOME/sock" 1>"$HOME/backpipe"; done;

L'étape suivante consiste à utiliser la commande TCTI et netcat (nc) pour envoyer des données au socket.

tpm2_startauthsession --tcti="cmd:nc -q 0 -U $HOME/sock" <options>

Lors de la fin, assurez-vous de tuer l'écouteur. Pour les commandes exécutées avec la commande tcti contre l'écouteur, vous devrez gérer les identifiants transitoires. Le moyen le plus simple est d'ajouter un flush après chaque commande : tpm2_flushcontext --tcti="cmd:nc -q 0 -U $HOME/sock" -t

Remarque : Cet exemple utilise des sockets UNIX, car le socket est contrôlé par les contrôles d'accès Linux. L'utilisation d'un port n'est pas recommandée car il est soit ouvert à tout utilisateur du système (localhost), soit lié à une carte réseau et exposé au réseau.

Cela fonctionnera avec un accès TPM direct, mais notez que cela appelle en interne un ContextSave et un ContextLoad sur l'identifiant de session, donc la session ne peut pas être sauvegardée/chargée à nouveau.

OPTIONS

•
--policy-session:

Démarre une session de politique de type TPM_SE_POLICY. Par défaut, sans cette option, c'est TPM_SE_TRIAL.

NOTE : Une session test est utilisée lors de la construction d'une politique et une session politique est utilisée lors de l'authentification avec une politique.

•
--audit-session:

Démarre une session HMAC à utiliser comme session d'audit. Par défaut, sans cette option, c'est TPM2_SE_TRIAL.

•
--hmac-session:

Démarre une session HMAC de type TPM_SE_HMAC. Par défaut, sans cette option, c'est TPM2_SE_TRIAL.

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage utilisé dans le calcul du résumé de la politique.

•
-G, --key-algorithm=ALGORITHME:

L'algorithme symétrique utilisé dans le chiffrement/déchiffrement des paramètres.

•
-c, --key-context=OBJET:

Définit l'objet tpmkey et les objets de liaison pour qu'ils soient identiques. Le chiffrement des paramètres de session est activé. Le déchiffrement des paramètres de session est activé. La clé symétrique de chiffrement/déchiffrement des paramètres est définie sur AES-CFB.

•
-S, --session=FICHIER:

Le nom du fichier de session de politique, requis.

•
--bind-context=FICHIER:

Définit l'objet de liaison. Le chiffrement des paramètres de session est désactivé. Utilisez tpm2_sessionconfig pour l'activer. Le déchiffrement des paramètres de session est désactivé. Utilisez tpm2_sessionconfig pour l'activer. La clé symétrique de chiffrement/déchiffrement des paramètres est définie sur AES-CFB.

•
--bind-auth=AUTH:

Définit la valeur d'autorisation pour l'objet de liaison.

•
--tpmkey-context=FICHIER:

Définit l'objet tpmkey. Le chiffrement des paramètres de session est désactivé. Utilisez tpm2_sessionconfig pour l'activer. Le déchiffrement des paramètres de session est désactivé. Utilisez tpm2_sessionconfig pour l'activer. La clé symétrique de chiffrement/déchiffrement des paramètres est définie sur AES-CFB.

•
-n, --name=FICHIER

Un fichier de nom en sortie d'un outil comme tpm2_readpublic(1) avec l'option -n. Le fichier de nom peut être utilisé pour vérifier un identifiant persistant d'entrée pour les options --tpmkey-context, -c et --key-context. La vérification que l'objet référencé par un identifiant persistant, par exemple 0x81000000, est la clé attendue empêche les attaquants d'effectuer une attaque de l'homme du milieu sur le trafic de session.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un identifiant ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe d'une des options suivantes :
•
owner: la hiérarchie du propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle du verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un identifiant, par exemple 0x81010013, et utilisé directement.

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut se présenter sous 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Remarque : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne Hex

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou de l'historique commun des shells.

ory features.

Exemples

# pour utiliser l'entrée standard et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/de/motdepasse
# pour échoer un mot de passe via l'entrée standard :
echo foobar | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via l'entrée standard :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, précédez l'argument de l'option du mot-clé session. Indiquez ensuite un chemin vers un fichier de session créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADECIMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <pcr-spec>=<fichier-pcr-brut>

La spécification PCR est documentée dans la section “Spécificateurs de banque PCR”.

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Pour utiliser correctement la fonctionnalité de manuel, il faut que les manuels soient installés ou sur MANPATH, voir man(1) pour plus de détails.

•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Réduit au silence la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.

Configuration TCTI

Le TCTI ou “Interface de transmission” est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge l'absence de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne de clé et de valeur est séparée par un caractère `= '.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus. # EXEMPLES

Démarrer une session d'essai et enregistrer les données de session dans un fichier

tpm2_startauthsession -S mysession.ctx

Démarrer une session de politique et enregistrer les données de session dans un fichier

tpm2_startauthsession --policy-session -S mysession.ctx

Démarrer une session de politique chiffrée et liée et enregistrer les données de session dans un fichier

tpm2_createprimary -c primary.ctx
tpm2_startauthsession --policy-session -c primary.ctx -S mysession.ctx

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
