tpm2_nvdefine(1) Manuel des commandes générales tpm2_nvdefine(1)

NOM

tpm2_nvdefine(1) - Définit un index Non-Volatile (NV) du TPM.

SYNOPSIS

tpm2_nvdefine [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvdefine(1) - Définit un index NV avec une valeur d'authentification donnée. L'index est spécifié comme argument. Il peut être spécifié comme un handle brut ou une valeur de décalage de la plage de handles nv “TPM2_HR_NV_INDEX”. Si aucun index n'est spécifié, l'outil utilise le premier index libre. L'outil affiche l'index nv défini en cas de succès.

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie le handle utilisé pour autoriser. Par défaut, o, TPM_RH_OWNER, lorsqu'aucune valeur n'a été spécifiée. Options supportées :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un handle de hiérarchie ou un index nv peut être utilisé.
•
-s, --size=NOMBRE_NATUREL:

Spécifie la taille de la zone de données en octets. Par défaut, MAX_NV_INDEX_SIZE qui est généralement de 2048.

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage utilisé pour calculer le nom de l'Index et utilisé pour la politique d'autorisation. Si l'index est un index d'extension, l'algorithme de hachage est utilisé pour l'extension.

•
-a, --attributes=ATTRIBUTS

Spécifie les valeurs d'attributs pour la région nv utilisée lors de la création de l'entité. Le masque de champ de bits brut ou des "noms conviviaux" peuvent être utilisés. Voir la section "Attributs NV" pour plus de détails. Si non spécifié, les attributs utilisent par défaut diverses sélections basées sur la hiérarchie dans laquelle l'index est défini.

Pour la hiérarchie propriétaire, les valeurs par défaut sont :

•
TPMA_NV_OWNERWRITE
•
TPMA_NV_OWNERREAD

Pour la hiérarchie de la plateforme, les valeurs par défaut sont :

•
TPMA_NV_PPWRITE
•
TPMA_NV_PPREAD

Si un fichier de politique est spécifié, les attributs par défaut choisis de la hiérarchie sont combinés par un OU binaire avec :

•
TPMA_NV_POLICYWRITE
•
TPMA_NV_POLICYREAD

Si un fichier de politique n'est PAS spécifié, les attributs par défaut choisis de la hiérarchie sont combinés par un OU binaire avec :

•
TPMA_NV_AUTHWRITE
•
TPMA_NV_AUTHREAD
•
-P, --hierarchy-auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie. Les valeurs d'autorisation doivent suivre les "normes de formatage des autorisations", voir la section "Formatage des autorisations".

•
-p, --index-auth=AUTH:

Spécifie le mot de passe de l'Index NV lors de sa création. Les valeurs d'autorisation HMAC et Mot de passe doivent suivre les "normes de formatage des autorisations", voir la section "Formatage des autorisations".

•
-L, --policy=FICHIER:

Spécifie le fichier de digest de politique pour les autorisations basées sur la politique.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash, sauf si rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est couramment appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Plusieurs de ceux-ci peuvent être spécifiés. Par exemple, vous pouvez avoir une session pour l'audit et une autre pour le chiffrement/déchiffrement des paramètres.

•
ARGUMENT l'argument de ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'Objet de Contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme objet transitoire TPM restauré.
•
Si l'argument correspond *par préfixe* à l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie d'approbation
•
lockout : l'objet persistant de contrôle de blocage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage des Autorisations

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations prennent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous en utilisant des identifiants de préfixe.

Remarque : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti de sa forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non amicaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:” doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un “-” pour utiliser stdin. Stocker les mots de passe dans des fichiers évite les fuites d'informations, les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une "here-string" bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Authentifications PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe "pcr:" et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section "Spécificateurs de banques PCR".

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que retourné par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

spécifiant AUTH.

Attributs des objets

Les attributs des objets sont utilisés pour contrôler diverses propriétés des objets créés. Lorsqu'ils sont spécifiés comme une option, le masque de champ de bits brut ou les "noms sympas" peuvent être utilisés. Les valeurs se trouvent dans le tableau 31, partie 2 de la spécification TPM2.0, qui peut être consultée ici :

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Les noms sympas sont calculés en prenant le champ nom du tableau 31 et en supprimant le préfixe TPMA_OBJECT_ et en mettant le résultat en minuscules. Ainsi, TPMA_OBJECT_FIXEDTPM devient fixedtpm. Les noms sympas peuvent être joints en utilisant le symbole OU bit à bit " | ".

Par exemple, pour définir les champs TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA et TPMA_OBJECT_SIGN_ENCRYPT, l'argument serait :

fixedtpm|noda|sign spécifiant les attributs nv ATTRIBUTES.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pager de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option "man" est spécifié, cependant si le "man" explicite est demandé, l'outil fournira les erreurs de man sur stderr. Si l'option "no-man" est spécifiée, ou si le pager de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité des pages de manuel, celles-ci doivent être installées ou se trouver dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de l'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou "Interface de Transmission" est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté comme le texte exact de "none".

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et utiliseront LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque chaîne de clé et de valeur est séparée par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

tpm2_nvdefine   0x1500016 -C o -s 32 -a 0x2000A
tpm2_nvdefine   0x1500016 -C o -s 32 -a ownerread|ownerwrite|policywrite -p 1a1b

Retours

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
