tpm2_policyduplicationselect(1) Manuel des commandes générales tpm2_policyduplicationselect(1)

NOM

tpm2_policyduplicationselect(1) - Restreint la duplication à un nouveau parent spécifique.

SYNOPSIS

tpm2_policyduplicationselect [OPTIONS]

DESCRIPTION

tpm2_policyduplicationselect(1) - Restreint la duplication à un nouveau parent spécifique.

OPTIONS

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
-n, --object-name=FICHIER:

Fichier du nom d'entrée de l'objet à dupliquer.

•
-N, --parent-name=FICHIER:

Fichier du nom d'entrée du nouveau parent.

•
-L, --policy=FICHIER:

Fichier où sauvegarder la valeur de hachage de politique.

•
--include-object:

Si présent, le nom de l'objet sera inclus dans la valeur de la valeur de hachage de politique.

Références

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lorsque l'on communique directement avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-TPM et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend pas en charge AUCUN argument et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

La spécification d'une chaîne vide pour <nom-tcti> ou <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant les sémantiques de dlopen(3). Les outils rechercheront tabrmd, device et mssim comme TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par les sémantiques de dlopen(3).

OPTIONS TCTI

Cet ensemble d'options est utilisé pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifier le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Configuration d'une politique de rôle de duplication restreinte

Ceci montre comment configurer une politique de duplication qui limite la duplication à un nouveau parent spécifié. Les objets à dupliquer sont associés à l'identifiant du nouveau parent lors de la création de l'objet parent.

# Créez une session d'authentification et enregistrez la valeur de hachage de politique
tpm2_startauthsession -S session.ctx
tpm2_policyduplicationselect -S session.ctx -L policy_duplication.bin

# Créez un objet parent pour l'objet à dupliquer
tpm2_createprimary -c primary.ctx -L policy_duplication.bin -u obj.pub -r obj.priv
tpm2_evictcontrol -c 0x80000001

# Créez un objet parent pour le nouveau parent
tpm2_createprimary -c newparent.ctx
tpm2_evictcontrol -c 0x80000002

# Dupliquez l'objet vers le nouveau parent
tpm2_duplicate -C newparent.ctx -u obj.pub -r obj.priv -L policy_duplication.bin -o duplicated.bin

NOM

tpm2_policyduplicationselect — permet de configurer une politique de session pour le rôle de duplication des objets TPM.

SYNOPIS

tpm2_policyduplicationselect [OPTIONS] [POLICY_OPTIONS] [SESSION_OPTIONS]

DESCRIPTION

Le programme tpm2_policyduplicationselect est utilisé pour configurer une politique de session TPM. Cette politique est spécifiquement conçue pour autoriser le rôle de duplication des objets. Cela signifie que lorsqu'une politique définie avec cet outil est satisfaite, l'objet protégé par cette politique peut être dupliqué par une commande telle que tpm2_duplicate.

En substance, cette commande enregistre le nom du parent de destination auprès du TPM, préparant ainsi le terrain pour une opération de duplication future. Elle est souvent utilisée dans des scénarios où des secrets ou des clés doivent être transférés en toute sécurité d'un TPM à un autre, en utilisant le rôle de duplication du TPM.

OPTIONS

Aucune option spécifique à tpm2_policyduplicationselect n'est documentée ici.

OPTIONS COMMUNES

Voir tpm2_policycommand(1) pour les options communes.

CONFIGURATION TCTI

Voir tpm2_tool(1) pour la configuration TCTI.

OPTIONS TCTI

Voir tpm2_tool(1) pour les options TCTI.

EXEMPLES

Mettre en place une politique de rôle de duplication vers un nouveau parent restreint

Créer le parent source et le parent de destination (ou nouveau) parent

tpm2_createprimary -C n -g sha256 -G rsa -c dst_n.ctx -Q
tpm2_createprimary -C o -g sha256 -G rsa -c src_o.ctx -Q

Créer la politique du parent restreint

tpm2_readpublic -c dst_n.ctx -n dst_n.name -Q
tpm2_startauthsession -S session.ctx
tpm2_policyduplicationselect -S session.ctx  -N dst_n.name \
-L policydupselect.dat -Q
tpm2_flushcontext session.ctx
rm session.ctx

Créer l'objet à dupliquer en utilisant la politique

tpm2_create -C src_o.ctx -g sha256 -G rsa -r dupkey.priv -u dupkey.pub \
-L policydupselect.dat  -a "sensitivedataorigin|sign|decrypt" -c dupkey.ctx -Q
tpm2_readpublic -c dupkey.ctx -n dupkey.name -Q

Satisfaire la politique et dupliquer l'objet

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policyduplicationselect -S session.ctx  -N dst_n.name -n dupkey.name -Q
tpm2_duplicate -C dst_n.ctx -c dupkey.ctx -G null -p session:session.ctx \
-r new_dupkey.priv -s dupseed.dat
tpm2_flushcontext  session.ctx
rm session.ctx

NOTES

•
Cette commande coopère généralement avec tpm2_duplicate(1), il est donc recommandé de consulter la page de manuel de tpm2_duplicate(1).
•
Cette commande définira le code de commande de la session politique sur TPM_CC_Duplicate, ce qui active le rôle de duplication de la politique.

RETOUR

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

LIMITATIONS

Elle attend qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des conditions suivantes :

•
accès direct au périphérique
•
support de session étendue avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commandes.
