CTPRFB applique un réflecteur de bloc complexe "triangulaire-pentagonal" à une matrice complexe, composée de deux blocs.

Objectif :

!>
!> CTPRFB applique un réflecteur de bloc complexe H ou son
!> conjugué transposé H**H à une matrice complexe C, composée de deux
!> blocs A et B, soit à gauche soit à droite.
!>
!>

Paramètres

SIDE 
!>          SIDE est CHARACTER*1
!>          = 'L' : applique H ou H**H à Gauche
!>          = 'R' : applique H ou H**H à Droite
!>

TRANS

!>          TRANS est CHARACTER*1
!>          = 'N' : applique H (Pas de transposée)
!>          = 'C' : applique H**H (Transposée conjuguée)
!>

DIRECT

!>          DIRECT est CHARACTER*1
!>          Indique comment H est formé à partir d'un produit de réflecteurs
!>          élémentaires
!>          = 'F' : H = H(1) H(2) . . . H(k) (Avant)
!>          = 'B' : H = H(k) . . . H(2) H(1) (Arrière)
!>

STOREV

!>          STOREV est CHARACTER*1
!>          Indique comment les vecteurs définissant les réflecteurs élémentaires
!>          sont stockés :
!>          = 'C' : Colonnes
!>          = 'R' : Lignes
!>

M

!>          M est INTEGER
!>          Le nombre de lignes de la matrice B.
!>          M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes de la matrice B.
!>          N >= 0.
!>

K

!>          K est INTEGER
!>          L'ordre de la matrice T, c'est-à-dire le nombre de réflecteurs
!>          élémentaires dont le produit définit le réflecteur de bloc.
!>          K >= 0.
!>

L

!>          L est INTEGER
!>          L'ordre de la partie trapézoïdale de V.
!>          K >= L >= 0. Voir Détails supplémentaires.
!>

V

!>          V est un tableau COMPLEX, dimension
!>                                (LDV,K) si STOREV = 'C'
!>                                (LDV,M) si STOREV = 'R' et SIDE = 'L'
!>                                (LDV,N) si STOREV = 'R' et SIDE = 'R'
!>          La matrice pentagonale V, qui contient les réflecteurs élémentaires
!>          H(1), H(2), ..., H(K). Voir Détails supplémentaires.
!>

LDV

!>          LDV est INTEGER
!>          La dimension principale du tableau V.
!>          Si STOREV = 'C' et SIDE = 'L', LDV >= max(1,M);
!>          si STOREV = 'C' et SIDE = 'R', LDV >= max(1,N);
!>          si STOREV = 'R', LDV >= K.
!>

T

!>          T est un tableau COMPLEX, dimension (LDT,K)
!>          La matrice triangulaire K-par-K T dans la représentation du
!>          réflecteur de bloc.
!>

LDT

!>          LDT est INTEGER
!>          La dimension principale du tableau T.
!>          LDT >= K.
!>

A

!>          A est un tableau COMPLEX, dimension
!>          (LDA,N) si SIDE = 'L' ou (LDA,K) si SIDE = 'R'
!>          À l'entrée, la matrice A de taille KxN ou MxK.
!>          À la sortie, A est écrasée par le bloc correspondant de
!>          H*C ou H**H*C ou C*H ou C*H**H. Voir Détails supplémentaires.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.
!>          Si SIDE = 'L', LDA >= max(1,K);
!>          Si SIDE = 'R', LDA >= max(1,M).
!>

B

!>          B est un tableau COMPLEX, dimension (LDB,N)
!>          À l'entrée, la matrice B de taille MxN.
!>          À la sortie, B est écrasée par le bloc correspondant de
!>          H*C ou H**H*C ou C*H ou C*H**H. Voir Détails supplémentaires.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B.
!>          LDB >= max(1,M).
!>

WORK

!>          WORK est un tableau COMPLEX, dimension
!>          (LDWORK,N) si SIDE = 'L',
!>          (LDWORK,K) si SIDE = 'R'.
!>

LDWORK

!>          LDWORK est INTEGER
!>          La dimension principale du tableau WORK.
!>          Si SIDE = 'L', LDWORK >= K;
!>          si SIDE = 'R', LDWORK >= M.
!>

Auteur

NAG Ltd.

!>
!>  Si DIRECT = 'B' et STOREV = 'C' : V = [V2]
!>                                         [V1]

!>       inférieure KxK)
!>
!>  Si DIRECT = 'B' et STOREV = 'R' : V = [V2 V1]
!>
!>     - V2 est upper trapézoïdal (les L dernières colonnes de la matrice triangulaire

subroutine ztprfb (character side, character trans, character direct, character storev, integer m, integer n, integer k, integer l, complex*16, dimension( ldv, * ) v, integer ldv, complex*16, dimension( ldt, * ) t, integer ldt, complex*16, dimension( lda, * ) a, integer lda, complex*16, dimension( ldb, * ) b, integer ldb, complex*16, dimension( ldwork, * ) work, integer ldwork)

ZTPRFB applies a complex "triangular-pentagonal" block reflector to a complex matrix, which is composed of two blocks.

Purpose:

!>
!> ZTPRFB applies a complex  block reflector H or its
!> conjugate transpose H**H to a complex matrix C, which is composed of two
!> blocks A and B, either from the left or right.
!>
!>

Parameters

SIDE 
!>          SIDE is CHARACTER*1
!>          = 'L': apply H or H**H from the Left
!>          = 'R': apply H or H**H from the Right
!>

TRANS

Detailed Description

    
tprfb applies a triangular block factorization
    to a general rectangular matrix.

    
Let C be an m-by-n matrix. In the following descriptions,
    the operation is applied to C.

    
The factorization is of the form

    
 C :=  T * C,  or  C := C * T,
 

    
where T is an upper or lower triangular k-by-k matrix.

    
T is formed from a block reflector H = I - V * T * V', where
    V is an m-by-k matrix (if direct = 'L') or k-by-m (if
    direct = 'R') and T is a k-by-k triangular block matrix.

    
The elements of the matrix V are assumed to be stored contiguously
    row-wise or column-wise, determined by the storev parameter.

    
For example, if direct = 'L', then T is applied
    to the left of C. If trans = 'N', T is lower triangular; if
    trans = 'T', T is upper triangular. If storev =
    'C', then V is m-by-k, and the j-th column of V contains the elementary
    vector associated with the j-th diagonal block of T.

    
If direct = 'L' and trans = 'N',
    then

    
 C := T * C
 

    
If direct = 'R' and trans = 'N',
    then

    
 C := C * T
 

    
If direct = 'L' and trans = 'T',
    then

    
 C := T' * C
 

    
If direct = 'R' and trans = 'T',
    then

    
 C := C * T'
 

    
The parameter storev determines how V and V2 are
    stored:

    
 If STOREV = 'C', V is N-by-K with V2 L-by-K.
 If STOREV = 'R', V is K-by-N with V2 K-by-L.
 

    
And the dimensions of C and T depend on side and
    direct:

    
 If SIDE = 'L' and DIRECT = 'F', then C is M-by-N, V is M-by-K, V2 is L-by-K, T is K-by-K.
 If SIDE = 'L' and DIRECT = 'B', then C is M-by-N, V is M-by-K, V2 is L-by-K, T is K-by-K.
 If SIDE = 'R' and DIRECT = 'F', then C is M-by-N, V is N-by-K, V2 is L-by-K, T is K-by-K.
 If SIDE = 'R' and DIRECT = 'B', then C is M-by-N, V is N-by-K, V2 is L-by-K, T is K-by-K.
 

    
And the dimensions of V and V2 also depend on storev:

    
 If STOREV = 'C', V is M-by-K (if SIDE = 'L') or N-by-K (if SIDE = 'R'). V2 is L-by-K.
 If STOREV = 'R', V is K-by-M (if SIDE = 'L') or K-by-N (if SIDE = 'R'). V2 is K-by-L.

  • If `storev` = 'R', V is K-by-N.

The parameter `direct` influences the order of operations when
    multiple blocks are involved but does not change the fundamental dimensions
    of V relative to `side` and `storev` in this context.

    
The documentation for V2 seems to be less directly tied to the
    `direct` parameter in the provided snippet, and its dimensions (L-by-K or

    implemented (e.g., if V2 is related to a different part of the factorization
