tpm2_encodeobject(1) Manuel des commandes générales tpm2_encodeobject(1)

NOM

tpm2_encodeobject(1) - Encode un objet dans un format PEM combiné.

SYNTAXE

tpm2_encodeobject [OPTIONS]

DESCRIPTION

tpm2_encodeobject(1) - Encode les parties privée et publique d'un objet dans un format PEM combiné utilisé par tpm2-tss-engine.

L'outil lit les parties privée et publique d'un objet et les encode dans un format PEM combiné utilisé par tpm2-tss-engine et d'autres applications.

NOTE : Les parties privée et publique de la clé TPM doivent être spécifiées.

OPTIONS

•
-C, --parent-context=OBJET:

L'objet parent.

•
-P, --auth=AUTH:

La valeur d'autorisation de l'objet parent spécifié par -C.

•
-u, --public=FICHIER:

Un fichier contenant la partie publique de l'objet.

•
-r, --private=FICHIER:

Un fichier contenant la partie sensible de l'objet.

•
-p, --key-auth:

Indique si une valeur d'autorisation est nécessaire pour l'objet spécifié par -r et -u.

•
-o, --output=FICHIER:

Le chemin du fichier de sortie, enregistrant la partie publique de l'objet.

Références

Format des objets de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé en tant qu'objet transitoire TPM restauré.
•
Si l'argument correspond *par préfixe* à l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'endorsement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage des autorisations

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche la fuite d'informations ; les mots de passe passés en options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADÉCIAMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des PCR brutes telles que retournées par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

spécifiant une AUTORISATION.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le programme de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument de l'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le programme de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité de manuel, il est nécessaire que les manuels soient installés ou présents sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version

tpm2_encodeobject(1) — tpm2-tools — Documentation Arch Linux

NAME

tpm2_encodeobject

encode an object into a combined PEM format

SYNOPSIS

tpm2_encodeobject [OPTIONS] [-u input-public-key] [-r input-private-key] [-o output-pem-file]

DESCRIPTION

The tpm2_encodeobject tool takes the raw public and private key blobs for a TPM object and encodes them into a combined PEM format file.

The TPM object is first created using tpm2_create(1) or tpm2_createak(1). These commands generate the private and public key blobs in separate files. The tpm2_encodeobject command takes these blobs and creates a single PEM file that contains both the public and private key material. This is useful for exporting TPM objects in a format that can be easily shared and used by other applications.

The tool supports various options for specifying input and output files, as well as handling authorization and context information.

OPTIONS

Common Options:

-h, --help
Display help information.
-V, --version
Display version information.
-C, --context context-handle
The context object to use for the session. The context object handle can be a file path to a context file, or a handle value. If a file path is provided, it will be loaded from the specified file.
-u, --input-public input-public-key
The file path to the public key blob. This is a raw binary file that contains the public key information for the TPM object.
-r, --input-private input-private-key
The file path to the private key blob. This is a raw binary file that contains the private key information for the TPM object.
-o, --output output-pem-file
The file path to the output PEM file. This file will contain the combined public and private key material in PEM format.
-f, --format format
Specify the output format. The default is 'pem'. Other supported formats include 'raw'.
-c, --policy-file policy-file
The policy file to use for authorization. This option is used when the TPM object requires a policy authorization.
-t, --ticket-file ticket-file
The ticket file to use for authorization. This option is used when the TPM object requires a ticket authorization.

Context Object Format

The context object can be specified as a file path or a handle. If a file path is provided, the tool will attempt to load the context from that file. The context file is typically created by commands such as tpm2_createprimary(1) or tpm2_load(1).

Authorization Formatting

If the TPM object requires authorization (e.g., password, policy, or ticket), the necessary authorization data must be provided. This can be done via command-line options or by specifying files containing the authorization data.

Supported authorization methods include:

•
Password authorization using the -p or --password option.
•
Policy authorization using the -c or --policy-file option.
•
Ticket authorization using the -t or --ticket-file option.

COMMON OPTIONS

•
-T, --tcti name:conf: Specify the TCTI (Transmission Control and Interface) used to communicate with the TPM. This option can be used to override the default TCTI or to specify a different TCTI. The format is name:conf where name is the TCTI name (e.g., 'device', 'mssim', 'tabrmd') and conf is the TCTI-specific configuration string. If conf is omitted, the default configuration for the specified TCTI is used. See TCTI Configuration section for more details.
•
-q, --quiet: Suppress normal output to stdout. Only warnings and errors will be printed.
•
-v, --version: Print version information and exit.
•
-?, --help: Display help information and exit.
•
-X, --debug: Print verbose debug information to stderr. This option is useful for troubleshooting issues with the tool, supported tctis and exit.
•
-V, --verbose: Increase the information that the tool prints to the console during its execution. When using this option the file and line number are printed.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Setup

To load an object you first must create an object under a primary object. So the first step is to create the primary object.

tpm2_createprimary -c primary.ctx

Step 2 is to create an object under the primary object.

tpm2_create -C primary.ctx -u key.pub -r key.priv -f pem -o pub.pem

This creates the private and public portions of the TPM object. With these object portions, it is now possible to load that object into the TPM for subsequent use.

Encoding an Object into a combined PEM format

The final step, is encoding the public and private portions of the object into a PEM format.

tpm2_encodeobject -C primary.ctx -u key.pub -r key.priv -o priv.pem

The generated priv.pem can be used together with pub.pem created in the step 2 of Setup section.

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
