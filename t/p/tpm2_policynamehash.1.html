tpm2_policynamehash(1) Manuel des commandes générales tpm2_policynamehash(1)

NOM

tpm2_policynamehash(1) - Couple une politique avec les noms d'objets spécifiques.

SYNTAXE

tpm2_policynamehash [OPTIONS]

DESCRIPTION

tpm2_policynamehash(1) - Couple une politique avec les noms d'objets spécifiques. Il s'agit d'une assertion différée où le hachage des noms de tous les descripteurs d'objet dans une commande TPM est vérifié par rapport à celui spécifié dans la politique.

OPTIONS

•
-L, --policy=FICHIER:

Fichier où enregistrer le résumé du digest de politique.

•
-S, --session=FICHIER:

Fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
-n, --name=FICHIER:

Fichier contenant le hachage du nom des objets référencés.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page man de l'outil. Par défaut, il tente d'appeler le paginator man pour l'outil, cependant, en cas d'échec, il affichera un court résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option en ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option en ligne de commande remplace toujours la variable d'environnement.

Les TCTI connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que noms de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté sous la forme exacte de “none”.

Les arguments de l'option en ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou pour le <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

TCTI Personnalisés

Tout TCTI implémentant l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de simples paires clé-valeur séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=´.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

tpm2_policynamehash(1) — tpm2-tools documentation

NAME

tpm2_policynamehash

Create a policy session to enforce the name hash of a TPM object

SYNOPSIS

tpm2_policynamehash [-h] [-v] [-c session_handle] [-L policy_file] [-n name_hash_file] [-S session.ctx]

DESCRIPTION

The tpm2_policynamehash command is used to create a policy session that requires the name hash of a TPM object to be met. This is often used in conjunction with other policy commands to restrict access to objects based on their names.

OPTIONS

-h
Help information.
-v
Verbose output.
-c, --session=session_handle
The policy session handle. If not provided, a session will be created using tpm2_startauthsession.
-L, --policy=policy_file
The file to store the policy digest in.
-n, --name=name_hash_file
The file containing the name hash of the object. This can be generated using tpm2_readpublic and piped to a file.
-S, --session-context=session.ctx
The file path to the session context. This is used to load and save the session state.

COMMON OPTIONS

These options are common to many tpm2_tools commands and are used for TCTI selection and session management.

TCTI Configuration

The TPM communication is done via a Tabernacle Communication Interface (TCTI). The default TCTI is the socket TCTI. This can be overridden with environment variables or the -T option.

TCTI OPTIONS

-T, --tcti=tcti-string
Overrides the default TCTI. For example, -T "mstcloud:host=127.0.0.1:port=2321".

EXAMPLES

The following example demonstrates how to use tpm2_policynamehash to set up a policy that requires the name hash of a duplicable key to be met. This is a prerequisite for duplicating the key.

Generate a duplicable object

openssl rsa -in signing_key_private.pem -inform pem -outform pem -pubout -out signing_key_public.pem
tpm2_loadexternal -G rsa -C o -u signing_key_public.pem -c signing_key.ctx \
-n signing_key.name
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policyauthorize -S session.ctx -L authorized.policy -n signing_key.name
tpm2_policycommandcode -S session.ctx -L policy.dat TPM2_CC_Duplicate
tpm2_flushcontext session.ctx
## The duplicable key
tpm2_create -Q -C primary.ctx -g sha256 -G rsa -r key.prv -u key.pub \
-L policy.dat -a "sensitivedataorigin|sign|decrypt"
tpm2_load -Q -C primary.ctx -r key.prv -u key.pub -c key.ctx

Create the new parent

tpm2_create -Q -C primary.ctx -g sha256 -G rsa -r new_parent.prv \
-u new_parent.pub \
-a "decrypt|fixedparent|fixedtpm|restricted|sensitivedataorigin"
tpm2_loadexternal -Q -C o -u new_parent.pub -c new_parent.ctx

Modify the duplicable key policy to namehash policy to restrict parent and key

tpm2_readpublic -Q -c new_parent.ctx -n new_parent.name
tpm2_readpublic -Q -c key.ctx -n key.name
cat key.name new_parent.name | openssl dgst -sha256 -binary > name.hash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policynamehash -L policy.namehash -S session.ctx -n name.hash
tpm2_flushcontext session.ctx
openssl dgst -sha256 -sign signing_key_private.pem \
-out policynamehash.signature policy.namehash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policyauthorize -S session.ctx -L authorized.policy -i policy.namehash \
-n signing_key.name
tpm2_policycommandcode -S session.ctx -L policy.dat TPM2_CC_Duplicate
tpm2_flushcontext session.ctx

Satisfy the policy and attempt key duplication

tpm2_verifysignature -c signing_key.ctx -g sha256 -m policy.namehash \
-s policynamehash.signature -t verification.tkt -f rsassa
tpm2_startauthsession -S session.ctx --policy-session -g sha256
tpm2_policynamehash -S session.ctx -n name.hash
tpm2_policyauthorize -S session.ctx -i policy.namehash -n signing_key.name \
-t verification.tkt
tpm2_policycommandcode -S session.ctx TPM2_CC_Duplicate
tpm2_duplicate -C new_parent.ctx -c key.ctx -G null -p "session:session.ctx" \
-r dupprv.bin -s dupseed.dat
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
